open_tree(2) Manual de llamadas al sistema open_tree(2)

NOMBRE

open_tree - abrir ruta o crear objeto de montaje separado y adjuntar a fd

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <fcntl.h>          /* Definición de constantes AT_* */
#include <sys/mount.h>
int open_tree(int dirfd, const char *path, unsigned int flags);
#include <sys/syscall.h>    /* Definición de constantes SYS_* */
int syscall(SYS_open_tree_attr,
            int dirfd, const char *path, unsigned int flags,
            struct mount_attr *_Nullable attr, size_t size);

Nota: glibc no proporciona un envoltorio para open_tree_attr(), lo que requiere el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema open_tree() forma parte del conjunto de instalaciones de montaje basadas en descriptores de archivo en Linux.

•
Si flags contiene OPEN_TREE_CLONE, open_tree() crea un objeto de montaje separado que consiste en un montaje bind de la ruta especificada por path. Luego se devuelve un nuevo descriptor de archivo asociado al objeto de montaje separado. El objeto de montaje es equivalente a un montaje bind que sería creado por mount(2) llamado con MS_BIND, excepto que está ligado a un descriptor de archivo y no está montado en el sistema de archivos.
Al igual que con los descriptores de archivo devueltos por fsmount(2), el descriptor de archivo resultante puede usarse con move_mount(2), mount_setattr(2), u otras llamadas al sistema similares para realizar más operaciones de montaje.
Este objeto de montaje será desmontado y destruido cuando se cierre el descriptor de archivo si no se adjuntó de otra manera a un punto de montaje llamando a move_mount(2). Esta operación de desmontaje implícita es perezosa — similar a llamar a umount2(2) con MNT_DETACH; por lo tanto, cualquier referencia abierta existente a archivos del objeto de montaje continuará funcionando, y el objeto de montaje solo se destruirá por completo una vez que deje de estar ocupado.
•
Si flags no contiene OPEN_TREE_CLONE, open_tree() devuelve un descriptor de archivo que es exactamente equivalente a uno producido por openat(2) cuando se llama con el mismo dirfd y path.

En ambos casos, el descriptor de archivo resultante se comporta igual que uno producido por open(2) con O_PATH, lo que significa que también se puede usar como argumento dirfd para las llamadas al sistema "*at()". Sin embargo, a diferencia de open(2) llamado con O_PATH, los automontajes se activarán por defecto con open_tree() a menos que AT_NO_AUTOMOUNT se incluya en flags.

Al igual que con las llamadas al sistema "*at()", open_tree() utiliza el argumento dirfd junto con el argumento path para determinar la ruta sobre la que operar, de la siguiente manera:

•
Si la ruta de nombre dada en path es absoluta, entonces se ignora dirfd.
•
Si la ruta de nombre dada en path es relativa y dirfd es el valor especial AT_FDCWD, entonces path se interpreta relativamente al directorio de trabajo actual del proceso de llamada (como open(2)).
•
Si la ruta de nombre dada en path es relativa, entonces se interpreta relativamente al directorio al que se refiere el descriptor de archivo dirfd (en lugar de relativamente al directorio de trabajo actual del proceso de llamada, como hace open(2) para una ruta de nombre relativa). En este caso, dirfd debe ser un directorio abierto para lectura (O_RDONLY) o usando la bandera O_PATH.
•
Si path es una cadena vacía y flags contiene AT_EMPTY_PATH, entonces el descriptor de archivo dirfd se opera directamente. En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio.

Consulte openat(2) para obtener una explicación de por qué es útil el argumento dirfd.

flags se puede usar para controlar aspectos de la búsqueda de rutas y las propiedades del descriptor de archivo devuelto. Un valor para flags se construye combinando bit a bit cero o más de las siguientes constantes:

AT_EMPTY_PATH
Si path es una cadena vacía, opera en el archivo al que se refiere dirfd (que puede haberse obtenido de open(2), fsmount(2), o de otra llamada open_tree()). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio. Si dirfd es AT_FDCWD, open_tree() operará en el directorio de trabajo actual del proceso de llamada. Esta bandera es específica de Linux; defina _GNU_SOURCE para obtener su definición.
AT_NO_AUTOMOUNT
No montar automáticamente el componente terminal ("nombre base") de path si es un directorio que es un punto de automontaje. Esto le permite crear un manejador para el propio punto de automontaje, en lugar de la ubicación que montaría. Esta bandera no tiene efecto si el punto de montaje ya se ha montado encima. Esta bandera es específica de Linux; defina _GNU_SOURCE para obtener su definición.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo resuelva; en su lugar, cree un manejador para el enlace en sí o un montaje bind del mismo. El descriptor de archivo resultante es indistinguible de uno producido por openat(2) con O_PATH|O_NOFOLLOW.
OPEN_TREE_CLOEXEC
Establezca la bandera de cierre al ejecutar (FD_CLOEXEC) en el nuevo descriptor de archivo. Consulte la descripción de la bandera O_CLOEXEC en open(2) para conocer las razones por las que esto puede ser útil.
OPEN_TREE_CLONE
En lugar de crear un descriptor de archivo O_PATH estilo openat(2), cree un montaje bind de path (similar a mount --bind) como un objeto de montaje separado. Para realizar esta operación, el proceso de llamada debe tener la capacidad CAP_SYS_ADMIN.
AT_RECURSIVE
Cree un montaje bind recursivo de la ruta (similar a mount --rbind) como un objeto de montaje separado. Esta bandera solo está permitida en conjunción con OPEN_TREE_CLONE.

open_tree_attr()

La llamada al sistema open_tree_attr() opera exactamente de la misma manera que open_tree(), excepto por las diferencias que se describen aquí.

Después de realizar la misma operación que con open_tree(), open_tree_attr() aplicará los cambios de atributo de montaje descritos en attr al descriptor de archivo antes de que sea devuelto. (Consulte mount_attr(2type) para obtener una descripción de la estructura mount_attr. Como se describe en mount_setattr(2), size debe establecerse en sizeof(struct mount_attr) para soportar extensiones futuras). Si attr es NULL, o tiene attr.attr_clr, attr.attr_set, y attr.propagation todos establecidos en cero, entonces open_tree_attr() tiene un comportamiento idéntico a open_tree().

La aplicación de attr al descriptor de archivo resultante tiene semántica idéntica a mount_setattr(2), excepto por las siguientes extensiones y advertencias generales:

•
A diferencia de mount_setattr(2) llamado con un objeto de montaje separado OPEN_TREE_CLONE regular de open_tree(), open_tree_attr() puede especificar una configuración diferente para MOUNT_ATTR_IDMAP al objeto de montaje original clonado con

OPEN_TREE_CLONE.
Agregar MOUNT_ATTR_IDMAP a attr.attr_clr deshabilitará el mapeo de ID para el nuevo objeto de montaje; agregar MOUNT_ATTR_IDMAP a attr.attr_set configurará el objeto de montaje para tener el mapeo de ID definido por el espacio de nombres de usuario al que se hace referencia por el descriptor de archivo attr.userns_fd. (La semántica de esto es idéntica a cuando se usa mount_setattr(2) para configurar MOUNT_ATTR_IDMAP).
Cambiar o eliminar el mapeo de un montaje mapeado por ID solo está permitido si se está creando un nuevo montaje desconectado con flags que incluyen OPEN_TREE_CLONE.
•
Si flags contiene AT_RECURSIVE, entonces los atributos descritos en attr se aplican recursivamente (al igual que cuando se llama a mount_setattr(2) con AT_RECURSIVE). Sin embargo, esto se aplica además del comportamiento específico de open_tree() con respecto a AT_RECURSIVE, y por lo tanto, flags también debe contener OPEN_TREE_CLONE.

Tenga en cuenta que si flags no contiene OPEN_TREE_CLONE, open_tree_attr() intentará modificar los atributos de montaje del objeto de montaje adjunto en la ruta descrita por dirfd y path. Al igual que con mount_setattr(2), si dicha ruta no es un punto de montaje, open_tree_attr() devolverá un error.

VALOR DE RETORNO

En caso de éxito, se devuelve un nuevo descriptor de archivo. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EACCES
Se deniega el permiso de búsqueda para uno de los directorios en el prefijo de ruta de path. (Ver también path_resolution(7)).
EBADF
path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
path es NULL o un puntero a una ubicación fuera del espacio de direcciones accesible del proceso que llama.
EINVAL
Se especificó una bandera inválida en flags.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver path.
EMFILE
El proceso que llama tiene demasiados archivos abiertos para crear más.
ENAMETOOLONG
path es más largo que PATH_MAX.
ENFILE
El sistema tiene demasiados archivos abiertos para crear más.
ENOENT
Un componente de path no existe, o es un enlace simbólico colgante.
ENOENT
path es una cadena vacía, pero AT_EMPTY_PATH no está especificado en flags.
ENOTDIR
Un componente del prefijo de ruta de path no es un directorio, o path es relativo y dirfd es un descriptor de archivo que hace referencia a un archivo que no es un directorio.
ENOSPC
El espacio de nombres de montaje "anónimo" necesario para contener el objeto de montaje de montaje vinculado desconectado OPEN_TREE_CLONE no se pudo asignar, ya que hacerlo excedería el límite configurado por usuario en la cantidad de espacios de nombres de montaje en el espacio de nombres de usuario actual. (Ver también namespaces(7)).
ENOMEM
El kernel no pudo asignar memoria suficiente para completar la operación.
EPERM
flags contiene OPEN_TREE_CLONE pero el proceso que llama no tiene la capacidad CAP_SYS_ADMIN requerida.

NOTAS

Propagación de montaje

Los objetos de montaje vinculados creados por open_tree() con OPEN_TREE_CLONE no están asociados con el espacio de nombres de montaje del proceso que llama. En su lugar, cada objeto de montaje se coloca en un espacio de nombres de montaje "anónimo" recién asignado asociado con el proceso que llama.

Uno de los efectos secundarios de esto es que (a diferencia de los montajes vinculados creados con mount(2)), la propagación de montaje (como se describe en mount_namespaces(7)) no se aplicará a los montajes vinculados creados por open_tree() hasta que el montaje vinculado se adjunte con move_mount(2), momento en el cual el objeto de montaje se asociará con el espacio de nombres de montaje donde se adjuntó y la propagación de montaje se reanudará. Tenga en cuenta que cualquier evento de propagación de montaje que ocurrió antes de que se adjuntara el objeto de montaje NO se propagará al objeto de montaje, incluso después de que se adjunte.

EJEMPLOS

Los siguientes ejemplos muestran cómo open_tree() puede usarse en lugar de llamadas más tradicionales a mount(2) con MS_BIND.


int srcfd = open_tree(AT_FDCWD, "/var", OPEN_TREE_CLONE);
move_mount(srcfd, "", AT_FDCWD, "/mnt", MOVE_MOUNT_F_EMPTY_PATH);

Primero, se crea un objeto de montaje vinculado desconectado de /var y se asocia con el descriptor de archivo srcfd. Luego, el objeto de montaje se adjunta a /mnt usando move_mount(2) con MOVE_MOUNT_F_EMPTY_PATH para solicitar que el objeto de montaje desconectado asociado con el descriptor de archivo srcfd se mueva (y por lo tanto se adjunte) a /mnt.

El procedimiento anterior es funcionalmente equivalente a la siguiente operación de montaje usando mount(2):


mount("/var", "/mnt", NULL, MS_BIND, NULL);

OPEN_TREE_CLONE se puede combinar con AT_RECURSIVE para crear objetos de montaje vinculados desconectados recursivos, que a su vez se pueden adjuntar a puntos de montaje para crear montajes vinculados recursivos.


int srcfd = open_tree(AT_FDCWD, "/var",
                      OPEN_TREE_CLONE | AT_RECURSIVE);
move_mount(srcfd, "", AT_FDCWD, "/mnt", MOVE_MOUNT_F_EMPTY_PATH);

El procedimiento anterior es funcionalmente equivalente a la siguiente operación de montaje usando mount(2):


mount("/var", "/mnt", NULL, MS_BIND | MS_REC, NULL);

Uno de los beneficios principales de usar open_tree() y move_mount(2) sobre el tradicional mount(2) es que operar con descriptores de archivo de estilo dirfd es mucho más fácil e intuitivo.


int srcfd = open_tree(100, "", AT_EMPTY_PATH | OPEN_TREE_CLONE);
move_mount(srcfd, "", 200, "foo", MOVE_MOUNT_F_EMPTY_PATH);

El procedimiento anterior es aproximadamente equivalente a la siguiente operación de montaje usando mount(2):


mount("/proc/self/fd/100",
      "/proc/self/fd/200/foo",
      NULL, MS_BIND, NULL);

Además, puede usar el descriptor de archivo devuelto por open_tree() como argumento dirfd para cualquier llamada al sistema de tipo "*at()":


int dirfd, fd;
dirfd = open_tree(AT_FDCWD, "/etc", OPEN_TREE_CLONE);
fd = openat(dirfd, "passwd", O_RDONLY);
fchmodat(dirfd, "shadow", 0000, 0);
close(dirfd);
close(fd);
/* El montaje vinculado ahora está destruido */

open_tree_attr()

El siguiente es un ejemplo de cómo open_tree_attr() puede usarse para tomar un montaje existente mapeado por ID y construir un nuevo objeto de montaje vinculado con un atributo MOUNT_ATTR_IDMAP diferente. El objeto de montaje desconectado resultante puede usarse como cualquier otro objeto de montaje devuelto por open_tree().


int nsfd1, nsfd2;
int mntfd1, mntfd2, mntfd3;
struct mount_attr attr;
mntfd1 = open_tree(AT_FDCWD, "/foo", OPEN_TREE_CLONE);
/* Configurar el mapeo de ID de mntfd1 */
nsfd1 = open("/proc/1234/ns/user", O_RDONLY);
memset(&attr, 0, sizeof(attr));
attr.attr_set = MOUNT_ATTR_IDMAP;
attr.userns_fd = nsfd1;
mount_setattr(mntfd1, "", AT_EMPTY_PATH, &attr, sizeof(attr));
/* Crear una nueva copia con un mapeo de ID diferente */
nsfd2 = open("/proc/5678/ns/user", O_RDONLY);
memset(&attr, 0, sizeof(attr));
attr.attr_clr = MOUNT_ATTR_IDMAP;
attr.attr_set = MOUNT_ATTR_IDMAP;
attr.userns_fd = nsfd2;
mntfd2 = open_tree_attr(mntfd1, "", OPEN_TREE_CLONE,
                        &attr, sizeof(attr));
/* Crear una nueva copia con el mapeo de ID borrado */
memset(&attr, 0, sizeof(attr));
attr.attr_clr = MOUNT_ATTR_IDMAP;
mntfd3 = open_tree_attr(mntfd1, "", OPEN_TREE_CLONE,
                        &attr, sizeof(attr));

open_tree_attr() también puede usarse con objetos de montaje adjuntos; el ejemplo anterior solo pretende ser ilustrativo.

OPEN_TREE(2) Linux Programmer's Manual OPEN_TREE(2)

NAME

open_tree, move_mount, umount_tree - manipulate mount trees

LIBRARY

Library Direct system calls

SYNOPSIS

int open_tree(const char *pathname, int flags);
int move_mount(int from_dfd, const char *from_pathname, int to_dfd, const char *to_pathname, unsigned int move_flags);
int umount_tree(int dfd, const char *pathname);

DESCRIPTION

The open_tree() system call is used to open a new mount tree, which is a representation of a subtree of the mount table. This is typically used for manipulating mount points and their contents in a safe and controlled manner.

The pathname argument specifies the path to the mount point or directory from which to open the new mount tree. The flags argument controls how the tree is opened. Some common flags include:

  • OPEN_TREE_CLONE: Clones the existing mount tree.
  • OPEN_TREE_READONLY: Opens the tree in read-only mode.
  • OPEN_TREE_SYMLINK_FOLLOW: Follows symbolic links.

The move_mount() system call is used to move a mount point from one location to another within the mount tree. This allows for reorganizing the filesystem hierarchy.

The from_dfd and from_pathname arguments specify the source mount point, and the to_dfd and to_pathname arguments specify the destination. The move_flags argument controls the behavior of the move operation.

The umount_tree() system call is used to unmount a mount tree. This detaches a subtree from the main mount table.

The dfd argument specifies a file descriptor referring to the root of the mount namespace, and pathname specifies the path within that namespace to the mount point to be unmounted.

RETURN VALUE

On success, open_tree(), move_mount(), and umount_tree() return a file descriptor referring to the root of the opened or manipulated mount tree. On error, they return -1, and errno is set to indicate the error.

ERRORS

See the manual pages for open_tree(2), move_mount(2), and umount_tree(2) for a detailed list of possible errors. Common errors include EACCES, EBUSY, EFAULT, EINVAL, EISDIR, ENOENT, ENOMEM, ENOTDIR, EPERM, and EROFS.

STANDARDS

These are Linux-specific system calls and are not part of any standard.

HISTORY

The open_tree(), move_mount(), and umount_tree() system calls were introduced in Linux kernel version 5.8.

NOTES

These system calls are powerful and should be used with caution, as incorrect usage can lead to filesystem corruption or instability. They are primarily intended for use by system administrators and developers working with advanced filesystem and containerization technologies.

EXAMPLES

Opening a mount tree:

int dfd = open_tree("/", AT_FDCWD, OPEN_TREE_CLONE | OPEN_TREE_READONLY);
if (dfd == -1) {
    perror("open_tree");
    // handle error
}

Moving a mount:

// Assuming dfd is a file descriptor for the root directory
int ret = move_mount(dfd, "/mnt/old_mount", dfd, "/mnt/new_location", MOVE_MOUNT_SHAKE);
if (ret == -1) {
    perror("move_mount");
    // handle error
}

Unmounting a tree:

// Assuming dfd is a file descriptor for the root directory
int ret = umount_tree(dfd, "/mnt/mountpoint");
if (ret == -1) {
    perror("umount_tree");
    // handle error
}
