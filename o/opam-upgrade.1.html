OPAM-UPGRADE(1) Opam Manual OPAM-UPGRADE(1)

NOMBRE

opam-upgrade - Actualiza el paquete instalado a la última versión.

SINOPSIS

opam upgrade [OPCIÓN]… [PAQUETES]…

DESCRIPCIÓN

Este comando actualiza los paquetes instalados a sus últimas versiones disponibles. Más precisamente, este comando llama al solucionador de dependencias para encontrar un estado consistente donde la *mayoría* de los paquetes instalados se actualizan a sus últimas versiones.

Si se especifica un directorio como argumento, todo lo que esté anclado a ese directorio se selecciona para la actualización.

ARGUMENTOS

PAQUETES
Lista de nombres de paquetes, con una versión opcional o restricción, por ejemplo `pkg', `pkg.1.0' o `pkg>=0.5'; o nombres de directorios que contienen la descripción del paquete, con directorio explícito (por ej. `./srcdir' o `.')

OPCIONES

-a, --all
Ejecuta una actualización de todos los paquetes instalados. Este es el valor predeterminado si no se especificó PAQUETES, y puede ser útil con PAQUETES para actualizar asegurando que algunos paquetes se instalen o permanezcan instalados.
--check
No ejecutes la actualización: solo verifica si algo puede actualizarse. Retorna 0 si es así, 1 si no hay nada que pueda actualizarse.
--fixup
Recuperarse de un estado roto (por ejemplo, dependencias faltantes, dos paquetes conflictivos instalados juntos...).
--formula=FORMULA (ausente=[])
Experimental. Especifica una fórmula de dependencia a ser verificada por la solución, además del invariante del switch. El formato es el mismo que para expresar dependencias en archivos de definición de paquetes, por ejemplo `"foo" {>= "1.1"}'
--installed
Cuando se proporciona un directorio como argumento, no instales paquetes anclados que aún no estén instalados.
--recursive
Permite búsquedas recursivas de archivos *.opam. Cf. también --subpath.
--subpath=PATH
Los archivos *.opam se recuperan del subdirectorio dado en lugar del directorio principal. Las fuentes se toman entonces del subdirectorio dirigido, internamente solo este subdirectorio se copia/descarga. Puede combinarse con --recursive para tener una búsqueda recursiva en el subdirectorio.

OPCIONES DE COMPILACIÓN DE PAQUETES

--assume-depexts
Omite el paso de instalación para cualquier paquete del sistema faltante, y trata de proceder de todos modos con la compilación de los paquetes opam. Si la instalación es exitosa, opam no volverá a preguntar sobre estos paquetes del sistema. Solo tiene sentido si el manejo de dependencias externas está habilitado.
-b, --keep-build-dir
Mantiene los directorios de compilación después de compilar los paquetes. Esto es equivalente a establecer $OPAMKEEPBUILDDIR a "true".
--build-doc
Eliminado en la versión 2.1, usa --with-doc en su lugar.
--build-test
Eliminado en la versión 2.1, usa --with-test en su lugar.
-d, --with-doc
Compila la documentación del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Es equivalente a establecer $OPAMWITHDOC (o el obsoleto $OPAMBUILDDOC) a "true".
--dry-run
Simula el comando, pero no realiza ningún cambio real. Esto también se puede configurar con la variable de entorno $OPAMDEBUG.
--fake
Esta opción registra las acciones en la base de datos de opam, sin realizarlas realmente. ADVERTENCIA: Esta opción es peligrosa y probablemente rompa tu entorno opam. Probablemente quieras usar --dry-run. Has sido advertido.
--ignore-constraints-on[=PAQUETES] (predeterminado=)
Fuerza a opam a ignorar las restricciones de versión en todas las dependencias de los paquetes listados. Esto se puede usar para probar la compatibilidad, pero se esperan fallos en la compilación al usar esto. Ten en cuenta que la disponibilidad de los paquetes, así como las restricciones de versión en dependencias opcionales y conflictos, no se ven afectadas. Esto es equivalente a establecer $OPAMIGNORECONSTRAINTS.
--inplace-build
Al compilar un paquete cuya fuente está enlazada a un directorio local, procesa las acciones de compilación e instalación directamente en ese directorio, en lugar de en una copia limpia manejada por opam. Esto solo afecta a los paquetes que se listan explícitamente en la línea de comandos. Es equivalente a establecer $OPAMINPLACEBUILD a "true".
-j JOBS, --jobs=JOBS
Establece el número máximo de trabajos concurrentes a usar. El valor predeterminado se calcula a partir del número de núcleos. También puedes establecerlo usando la variable de entorno $OPAMJOBS.
--lock-suffix=SUFIJO (predeterminado=locked)
Establece el sufijo de los archivos de bloqueo a SUFIJO.
--locked
En los comandos que usan archivos opam encontrados en fuentes ancladas, si se encuentra una variante del archivo con una extensión .locked añadida (por ejemplo, foo.opam.locked junto a foo.opam), se utilizará esa en su lugar. Esto es típicamente útil para ofrecer un conjunto más específico de dependencias y reproducir contextos de compilación similares, de ahí el nombre. La opción lock se puede usar para generar dichos archivos, basándose en las versiones de las dependencias actualmente instaladas en el host. Es equivalente a establecer la variable de entorno $OPAMLOCKED. Ten en cuenta que esta opción generalmente no afecta a los paquetes ya anclados.
-m MAKE, --make=MAKE
Eliminado en la versión 2.1, usa opam config set[-global] make MAKE en su lugar.
--no-checksums
No verifica la suma de verificación (checksum) de los archivos descargados. Esto es equivalente a establecer $OPAMNOCHECKSUMS a "true".
--no-depexts
Deshabilita temporalmente el manejo de dependencias externas. Esto puede usarse si un paquete no está disponible en el gestor de paquetes de tu sistema, pero instalaste la dependencia requerida manualmente. Implica --assume-depexts, y almacena las excepciones tras el éxito también.
--require-checksums
Rechaza la instalación de paquetes que no proporcionan una suma de verificación (checksum) para los archivos de origen. Esto es equivalente a establecer $OPAMREQUIRECHECKSUMS a "true".
--reuse-build-dir
Reutiliza los directorios de compilación existentes (mantenidos usando --keep-build-dir), en lugar de compilar desde una copia nueva de la fuente. Esto puede ser más rápido, pero también puede llevar a fallos si los sistemas de compilación de los paquetes no manejan bien las actualizaciones de dependencias. Es equivalente a establecer $OPAMREUSEBUILDDIR a "true".
--show-actions
Llama al solucionador y muestra las acciones. No realiza ningún cambio. Esto es equivalente a establecer $OPAMSHOW.
--skip-updates
Al ejecutar una instalación, actualización o reinstalación en paquetes anclados desde la fuente, normalmente se actualizan primero desde su origen. Esta bandera deshabilita ese comportamiento y los mantendrá en su versión en caché. Esto es equivalente a establecer $OPAMSKIPUPDATE.
-t, --with-test
Compila y ejecuta las pruebas unitarias del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Es equivalente a establecer $OPAMWITHTEST (o el obsoleto $OPAMBUILDTEST) a "true".
--unlock-base
Eliminado en la versión 2.1, usa --update-invariant en su lugar.
--update-invariant
Permite cambios en los paquetes establecidos como base del switch (típicamente, el compilador principal). Úsese con precaución. Es equivalente a establecer la variable de entorno $OPAMUNLOCKBASE
--verbose-on=PAQUETES
Sé más verboso en paquetes específicos. Esto es equivalente a establecer $OPAMVERBOSE.
--with-dev-setup
Incluye dependencias solo de herramientas de desarrollo.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No falles si no se pueden instalar todos los paquetes solicitados: intenta instalar tantos como sea posible. Ten en cuenta que no todos los solucionadores externos pueden soportar esta opción (versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.

NAME

opam-bin - wrapper scripts and opam configuration variables

SYNOPSIS

opam [OTHER OPTIONS]

DESCRIPTION

This document describes the environment variables that control opam's behaviour. Some of these are also available as command-line options.

The available variables are:

OPAM_BASE
The base directory of the opam installation. This is automatically set.
OPAM_CONFIG_DIR
The directory containing opam's configuration files. This is $OPAM_BASE/config.
OPAM_DATADIR
The directory containing opam's data files. This is $OPAM_BASE/share.
OPAM_LOCK_DIR
The directory for lock files. Defaults to /var/lock/opam or $HOME/.opam/lock.
OPAM_ROOT
The root directory of the opam installation. This is automatically set by `opam env --root=DIR --set-root'. See also option `--root'.
OPAM_SHARE_DIR
The directory containing opam's shared data files. This is $OPAM_BASE/share.
OPAM_SWITCH_PREFIX
The prefix for the current switch's environment variables. This is automatically set by `opam env --switch=SWITCH --set-switch'. See also option `--switch'.
OPAM_USER_CONFIG_DIR
The user-specific configuration directory. Defaults to $HOME/.config/opam.
OPAM_USER_DATA_DIR
The user-specific data directory. Defaults to $HOME/.local/share/opam.
OPAM_USER_STATE_DIR
The user-specific state directory. Defaults to $HOME/.local/state/opam.

The following variables are meant for internal use or advanced users:

OPAM_API_LEVEL
Requests a specific version of the opam API. Do not set this unless you know what you're doing.
OPAM_CHECK_REQUESTS
If set, checks that all requests are valid. This is slow and should only be used for debugging.
OPAM_CHECK_SUMS
If set, skips checksum verification for downloaded files. Use with caution.
OPAM_CONFIRM_LEVEL
Sets the confirmation level for operations. Can be `low', `medium', or `high'.
OPAM_DEBIAN
Internal.
OPAM_DEPEXT_RETRY
Number of retries for fetching system dependencies.
OPAM_DIR
The current opam root directory. This is automatically set by `opam env'.
OPAM_DOWNLOAD_CMD
Command used for downloading files. Defaults to `curl -fL' or `wget'.
OPAM_DOWNLOAD_DIR
Directory for storing downloaded files. Defaults to $HOME/.opam/.download-cache.
OPAM_FETCH_CMD
Command used for fetching files from version control systems. Defaults to `git' or `hg'.
OPAM_FIND_ONLY
If set, opam will only try to find existing packages and not attempt to install or update anything.
OPAM_FORCE_REINSTALL
Force reinstallation of packages even if they are already installed.
OPAM_GLOBAL_OPTIONS
Internal.
OPAM_KEEP_BUILD_DIR
If set, the build directory for packages will be kept after installation.
OPAM_KEEP_OLD_PACKAGES
If set, old versions of packages will not be removed when upgrading.
OPAM_KEEP_OLD_SWITCHES
If set, old switches will not be removed when creating a new one.
OPAM_KIND_PIN
Internal.
OPAM_KIND_UNPIN
Internal.
OPAM_LIST_CHOICES
If set, `opam list' will show all available versions of packages, not just installed ones.
OPAM_LOCAL_PATH
Path to local opam files.
OPAM_NO_ANALYZE
If set, opam will not analyze the package dependencies.
OPAM_NO_ARCHIVE
If set, opam will not use archives for package downloads.
OPAM_NO_AUTO_UPGRADE
Disables automatic internal upgrade of repositories in an earlier format to the current one, on 'update' or 'init'.
OPAM_NO_CHECKSUMS
Enables option --no-checksums when available.
OPAM_NO_DEPE
Disables system dependencies handling, see option `--no-depexts'.
OPAM_NO_ENV_NOTICE
Internal.
OPAM_NO_REMOTE_CACHE
Disables the remote cache for repositories.
OPAM_NO_SELF_UPGRADE
See option `--no-self-upgrade'.
OPAM_PIN_KINDA_AUTO
Sets whether version control systems should be detected when pinning to a local path. Enabled by default since 1.3.0.
OPAM_PRECISE_TRACKING
Fine grain tracking of directories.
OPAM_PREPRO
Set this to false to disable CUDF preprocessing. Less efficient, but might help debugging solver issue.
OPAM_REPOSITORY_TARRING
Internally store the repositories as tar.gz files. This can be much faster on filesystems that don't cope well with scanning large trees but have good caching in /tmp. However this is slower in the general case.
OPAM_REQUIRE_CHECKSUMS
Enables option `--require-checksums' when available (e.g. for `opam install').
OPAM_RETRIES
Sets the number of tries before failing downloads.
OPAM_REUSE_BUILD_DIR
See option `--reuse-build-dir'.
OPAM_ROOT
See option `--root'. This is automatically set by `opam env --root=DIR --set-root'.
OPAM_ROOT_IS_OK
Don't complain when running as root.
OPAM_SAFE
See option `--safe'.
OPAM_SHOW
See option `--show'.
OPAM_SKIP_UPDATE
See option `--skip-updates'.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
