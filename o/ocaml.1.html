OCAML(1) Manual de comandos generales OCAML(1)

NOMBRE

ocaml - El intérprete interactivo de OCaml

SINOPSIS

ocaml [ opciones ] [ archivos-objeto ] [ archivo-script ]

DESCRIPCIÓN

El comando ocaml(1) es el sistema de intérprete para OCaml, que permite el uso interactivo del sistema OCaml a través de un bucle de lectura-evaluación-impresión. En este modo, el sistema lee repetidamente frases de OCaml desde la entrada estándar, luego las verifica tipográficamente, compila y evalúa, y finalmente imprime el tipo inferido y el valor resultante, si los hay. El fin de archivo en la entrada estándar termina ocaml(1).

La entrada al intérprete puede abarcar varias líneas. Comienza después del indicador # (almohadilla) impreso por el sistema y termina con ;; (un punto y coma doble) seguido de espacios en blanco opcionales y un final de línea. La entrada del intérprete consiste en una o varias frases de intérprete.

Si se proporcionan uno o más archivos-objeto (que terminan en .cmo o .cma) en la línea de comandos, se cargan silenciosamente antes de iniciar el intérprete.

Si se proporciona un archivo-script, las frases se leen silenciosamente del archivo, y los errores se imprimen en la salida de error estándar. ocaml(1) sale después de la ejecución de la última frase.

OPCIONES

Las siguientes opciones de línea de comandos son reconocidas por ocaml(1).

-absname
Muestra nombres de archivo absolutos en mensajes de error.
-no-absname
No intentes mostrar nombres de archivo absolutos en mensajes de error.
-I directorio
Añade el directorio dado a la lista de directorios buscados para archivos fuente y compilados. Por defecto, se busca primero el directorio actual, luego el directorio de la biblioteca estándar. Los directorios añadidos con -I se buscan después del directorio actual, en el orden en que se proporcionaron en la línea de comandos, pero antes del directorio de la biblioteca estándar.
Si el directorio dado comienza con +, se toma relativo al directorio de la biblioteca estándar. Por ejemplo, -I +compiler-libs añade el subdirectorio compiler-libs de la biblioteca estándar a la ruta de búsqueda.
Los directorios también se pueden añadir a la ruta de búsqueda una vez que el intérprete está en ejecución con la directiva #directory.
-init archivo
Carga el archivo dado en lugar del archivo de inicialización predeterminado. Ver la sección "Archivo de inicialización" a continuación.
-labels
Las etiquetas no se ignoran en los tipos, las etiquetas pueden usarse en aplicaciones, y los parámetros etiquetados se pueden dar en cualquier orden. Este es el valor predeterminado.
-no-app-funct
Desactiva el comportamiento aplicativo de los functores. Con esta opción, cada aplicación de functor genera nuevos tipos en su resultado y aplicar el mismo functor dos veces al mismo argumento produce dos estructuras incompatibles.
-noassert
No compila las comprobaciones de aserción. Ten en cuenta que la forma especial assert false siempre se compila porque se tipifica especialmente.
-noinit
No carga ningún archivo de inicialización. Ver la sección "Archivo de inicialización" a continuación.
-nolabels
Ignora las etiquetas no opcionales en los tipos. Las etiquetas no se pueden usar en aplicaciones, y el orden de los parámetros se vuelve estricto.
-noprompt
No muestra ningún indicador cuando espera entrada.
-nopromptcont
No muestra el indicador secundario cuando espera líneas continuas en entradas multilínea. Esto debe usarse, por ejemplo, al ejecutar ocaml(1) en una ventana de emacs(1).
-nostdlib
No incluye el directorio de la biblioteca estándar en la lista de directorios buscados para archivos fuente y compilados.
-open módulo
Abre el módulo dado antes de iniciar el intérprete. Si se proporcionan varias opciones -open, se procesan en orden, como si se introdujeran las sentencias open! módulo1;; ... open! móduloN;;.
-ppx comando
Después de analizar, canaliza el árbol de sintaxis abstracta a través del preprocesador comando. El módulo Ast_mapper(3) implementa la interfaz externa de un preprocesador.
-principal
Verifica la ruta de información durante la verificación de tipos, para asegurar que todos los tipos se derivan de forma principal. Al usar argumentos etiquetados y/o métodos polimórficos, esta bandera es necesaria para garantizar que las versiones futuras del compilador puedan inferir tipos correctamente, incluso si los algoritmos internos cambian. Todos los programas aceptados en modo -principal también se aceptan en el modo predeterminado con tipos equivalentes, pero con firmas binarias diferentes, y esto puede ralentizar la verificación de tipos; sin embargo, es una buena idea usarlo una vez antes de publicar código fuente.
-no-principal
No verifica la principalidad de la inferencia de tipos. Este es el valor predeterminado.
-rectypes
Permite tipos recursivos arbitrarios durante la verificación de tipos. Por defecto, solo se admiten tipos recursivos donde la recursión pasa a través de un tipo de objeto.
-no-rectypes
No permite tipos recursivos arbitrarios durante la verificación de tipos. Este es el valor predeterminado.
-safe-string
Refuerza la separación entre los tipos string y bytes, haciendo que las cadenas sean de solo lectura. Este es el valor predeterminado.
-safer-matching
No utiliza información de tipos para optimizar la coincidencia de patrones. Esto permite detectar fallos de coincidencia incluso si se asumió erróneamente que una coincidencia de patrones era exhaustiva. Esto solo afecta a la compilación de GADT y variantes polimórficas.
-short-paths
Cuando un tipo es visible bajo varias rutas de módulo, usa la más corta al imprimir el nombre del tipo en las interfaces inferidas y en los mensajes de error y advertencia.
-stdin
Lee la entrada estándar como un archivo script en lugar de iniciar una sesión interactiva.
-strict-sequence
Fuerza que la parte izquierda de cada secuencia tenga el tipo unit.
-no-strict-sequence
La parte izquierda de una secuencia no necesita tener el tipo unit. Este es el valor predeterminado.
-unboxed-types
Cuando un tipo es "unboxable" (es decir, un registro con un solo argumento o un tipo de dato concreto con un solo constructor de un argumento) será "unboxed" a menos que se anote con [@@ocaml.boxed].
-no-unboxed-types
Cuando un tipo es "unboxable" será "boxed" a menos que se anote con [@@ocaml.unboxed]. Este es el valor predeterminado.
-unsafe
Desactiva la comprobación de límites en accesos a arrays y cadenas (las construcciones v.(i) y s.[i]). Los programas compilados con -unsafe son por lo tanto ligeramente más rápidos, pero inseguros: cualquier cosa puede suceder si el programa accede a un array o cadena fuera de sus límites.
-unsafe-string
Identifica los tipos string y bytes, haciendo así que las cadenas sean modificables. Esto está destinado a la compatibilidad con código fuente antiguo y no debe usarse con software nuevo.
-version
Imprime la cadena de versión y sale.
-vnum
Imprime el número de versión corto y sale.
-no-version
No imprime la cadena de versión.
-w [+|-]warnings
Habilita o deshabilita advertencias específicas. Las advertencias se agrupan en conjuntos, y se puede habilitar o deshabilitar un conjunto de advertencias proporcionando su código numérico (que se muestra entre corchetes en el mensaje de advertencia). Por ejemplo, -w +a-4 habilita las advertencias del conjunto 'a' y deshabilita las advertencias del conjunto '4'. El conjunto de advertencias 'a' se refiere a todas las advertencias de tipo.
-warn-error [+|-]warnings
Trata las advertencias especificadas como errores. Por ejemplo, -warn-error +a trata todas las advertencias de tipo como errores.

ARCHIVO DE INICIALIZACIÓN

Cuando se inicia ocaml(1), busca un archivo de inicialización en el directorio actual. Si existe, se ejecuta como si fuera una entrada del intérprete. El nombre del archivo predeterminado es .ocamlinit. Si el archivo de inicialización predeterminado no existe, se busca el archivo .ocamlinit en el directorio home del usuario (si este está definido).

Si se proporciona el nombre de un archivo con la opción -init, ese archivo se carga en lugar del archivo predeterminado. La opción -noinit impide la carga de cualquier archivo de inicialización.

Los archivos de inicialización se utilizan para configurar el intérprete interactivo, por ejemplo, para precargar módulos o definir atajos de teclado.

EJEMPLOS

Para iniciar una sesión interactiva:

$ ocaml

Para cargar archivos de objeto y luego iniciar una sesión interactiva:

$ ocaml foo.cmo bar.cmo

Para ejecutar un script de OCaml:

$ ocaml myscript.ml

Para ejecutar un script y agregar directorios de búsqueda:

$ ocaml -I /path/to/my/libs myscript.ml

ocaml(1) - Arch manual pages

NAME

ocaml - ocaml interactive toplevel

SYNOPSIS

ocaml [option ...] [file ...]

DESCRIPTION

The ocaml program is the OCaml bytecode interpreter and toplevel. It can be used to interactively type OCaml phrases, which are then compiled and executed immediately. If one or more file names are given on the command line, these files are loaded and executed before the interactive session starts.

The toplevel can also be used to link and run programs in memory. See the ocamlc(1) manual page for a description of the linking options.

OPTIONS

-no-version
Do not print the version banner at startup.
-wwarning-list
Enable or disable warnings according to the argument warning-list. See ocamlc(1) for the syntax of the warning-list argument.
-warn-error warning-list
Mark as fatal the warnings described by the argument warning-list. Note that a warning is not triggered (and does not trigger an error) if it is disabled by the -w option. See ocamlc(1) for the syntax of the warning-list argument.
-color mode
Enable or disable colors in compiler messages (especially warnings and errors). The following modes are supported:

auto use heuristics to enable colors only if the output supports them (an ANSI-compatible tty terminal);

always enable colors unconditionally;

never disable color output.

The environment variable "OCAML_COLOR" is considered if -color is not provided. Its values are auto/always/never as above.

If -color is not provided, "OCAML_COLOR" is not set and the environment variable "NO_COLOR" is set, then color output is disabled. Otherwise, the default setting is auto, and the current heuristic checks that the "TERM" environment variable exists and is not empty or "dumb", and that isatty(stderr) holds.

-error-style mode
Control the way error messages and warnings are printed. The following modes are supported:

short only print the error and its location;

contextual like "short", but also display the source code snippet corresponding to the location of the error.

The default setting is contextual.

The environment variable "OCAML_ERROR_STYLE" is considered if -error-style is not provided. Its values are short/contextual as above.

-warn-help
Show the description of all available warning numbers.
- file
Use file as a script file name, even when it starts with a hyphen (-).
-help or --help
Display a short usage summary and exit.

INITIALIZATION FILE

When ocaml(1) is invoked, it will read phrases from an initialization file before giving control to the user. The file read is the first found of:

1.
.ocamlinit in the current directory;
2.
XDG_CONFIG_HOME/ocaml/init.ml, if XDG_CONFIG_HOME is an absolute path;
3.
otherwise, on Unix, HOME/ocaml/init.ml or, on Windows, ocaml\init.ml under LocalAppData (e.g. C:\Users\Bactrian\AppData\Local\ocaml\init.ml);
4.
ocaml/init.ml under any of the absolute paths in XDG_CONFIG_DIRS. Paths in XDG_CONFIG_DIRS are colon-delimited on Unix, and semicolon-delimited on Windows;
5.
if XDG_CONFIG_DIRS contained no absolute paths, /usr/xdg/ocaml/init.ml on Unix or, ocaml\init.ml under any of LocalAppData (e.g. C:\Users\Bactrian\AppData\Local), RoamingAppData (e.g. C:\Users\Bactrian\AppData\Roaming), or ProgramData (e.g. C:\ProgramData) on Windows;
6.
HOME/.ocamlinit, if HOME is non-empty;

You can specify a different initialization file by using the -init file option, and disable initialization files by using the -noinit option.

Note that you can also use the #use directive to read phrases from a file.

ENVIRONMENT VARIABLES

OCAMLTOP_UTF_8
When printing string values, non-ascii bytes (>0x7E) are printed as decimal escape sequence if OCAMLTOP_UTF_8 is set to false. Otherwise they are printed unescaped.
TERM
When printing error messages, the toplevel system attempts to underline visually the location of the error. It consults the TERM variable to determines the type of output terminal and look up its capabilities in the terminal database.
XDG_CONFIG_HOME HOME XDG_CONFIG_DIRS
See INITIALIZATION FILE above.
