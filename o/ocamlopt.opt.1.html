Paquete: ocaml

OCAMLOPT(1) Manual de comandos generales OCAMLOPT(1)

NOMBRE

ocamlopt - El compilador de código nativo de OCaml

SINOPSIS

ocamlopt [ opciones ] nombrearchivo ...

ocamlopt.opt (mismas opciones)

DESCRIPCIÓN

El compilador de código nativo de alto rendimiento de OCaml ocamlopt(1) compila archivos fuente de OCaml a archivos objeto de código nativo y enlaza estos archivos objeto para producir ejecutables independientes.

El comando ocamlopt(1) tiene una interfaz de línea de comandos muy similar a la de ocamlc(1). Acepta los mismos tipos de argumentos y los procesa secuencialmente, después de que todas las opciones han sido procesadas:

Los argumentos que terminan en .mli se toman como archivos fuente para las interfaces de unidades de compilación. Las interfaces especifican los nombres exportados por las unidades de compilación: declaran nombres de valor con sus tipos, definen tipos de datos públicos, declaran tipos de datos abstractos y así sucesivamente. Del archivo x.mli, el compilador ocamlopt(1) produce una interfaz compilada en el archivo x.cmi. La interfaz producida es idéntica a la producida por el compilador de bytecode ocamlc(1).

Los argumentos que terminan en .ml se toman como archivos fuente para las implementaciones de unidades de compilación. Las implementaciones proporcionan definiciones para los nombres exportados por la unidad, y también contienen expresiones que se evaluarán por sus efectos secundarios. Del archivo x.ml, el compilador ocamlopt(1) produce dos archivos: x.o, que contiene código objeto nativo, y x.cmx, que contiene información adicional para el enlace y la optimización de los clientes de la unidad. La implementación compilada debe referirse siempre bajo el nombre x.cmx (cuando se le da un archivo .o, ocamlopt(1) asume que contiene código compilado de C, no de OCaml).

La implementación se verifica contra el archivo de interfaz x.mli (si existe) como se describe en el manual de ocamlc(1).

Los argumentos que terminan en .cmx se toman como código objeto compilado. Estos archivos se enlazan juntos, junto con los archivos objeto obtenidos al compilar argumentos .ml (si los hay), y la biblioteca estándar de OCaml, para producir un programa ejecutable de código nativo. El orden en que los argumentos .cmx y .ml se presentan en la línea de comandos es relevante: las unidades de compilación se inicializan en ese orden en tiempo de ejecución, y es un error de enlace usar un componente de una unidad antes de haberlo inicializado. Por lo tanto, un archivo x.cmx dado debe venir antes que todos los archivos .cmx que se refieren a la unidad x.

Los argumentos que terminan en .cmxa se toman como bibliotecas de código objeto. Tal biblioteca empaqueta en dos archivos lib.cmxa y lib.a un conjunto de archivos objeto (.cmx/.o). Las bibliotecas se construyen con ocamlopt -a (ver la descripción de la opción -a más abajo). Los archivos objeto contenidos en la biblioteca se enlazan como archivos .cmx normales (ver arriba), en el orden especificado cuando se construyó la biblioteca. La única diferencia es que si un archivo objeto contenido en una biblioteca no se referencia en ningún lugar del programa, entonces no se enlaza.

Los argumentos que terminan en .c se pasan al compilador C, que genera un archivo objeto .o. Este archivo objeto se enlaza con el programa.

Los argumentos que terminan en .o o .a se asumen como archivos objeto C y bibliotecas. Se enlazan con el programa.

La salida de la fase de enlace es un archivo ejecutable Unix regular. No necesita ocamlrun(1) para ejecutarse.

ocamlopt.opt es el mismo compilador que ocamlopt, pero compilado consigo mismo en lugar de con el compilador de bytecode ocamlc(1). Por lo tanto, se comporta exactamente como ocamlopt, pero compila más rápido. ocamlopt.opt no está disponible en todas las instalaciones de OCaml.

OPCIONES

Las siguientes opciones de línea de comandos son reconocidas por ocamlopt(1).

-a
Construye una biblioteca (.cmxa/.a) con los archivos objeto (.cmx/.o) proporcionados en la línea de comandos, en lugar de enlazarlos en un archivo ejecutable. El nombre de la biblioteca debe establecerse con la opción -o.

Si se pasan opciones -cclib o -ccopt en la línea de comandos, estas opciones se almacenan en la biblioteca .cmxa resultante. Luego, el enlace con esta biblioteca agrega automáticamente las opciones -cclib y -ccopt como si hubieran sido proporcionadas en la línea de comandos, a menos que se proporcione la opción -no-autolink. Adicionalmente, una subcadena $CAMLORIGIN dentro de una opción -ccopt será reemplazada por la ruta completa a la biblioteca .cma, excluyendo el nombre del archivo.

-absname
Muestra nombres de archivo absolutos en mensajes de error.
-no-absname
No intentes mostrar nombres de archivo absolutos en mensajes de error.
-annot
Obsoleto desde OCaml 4.11. Por favor, usa -bin-annot en su lugar.
-bin-annot
Descarga información detallada sobre la compilación (tipos, enlaces, llamadas en cola, etc.) en formato binario. La información para el archivo src.ml se coloca en el archivo src.cmt. En caso de error de tipo, descarga toda la información inferida por el verificador de tipos antes del error. Los archivos de anotación producidos por -bin-annot contienen más información y son mucho más compactos que los archivos producidos por -annot.
-c
Solo compila. Suprime la fase de enlace de la compilación. Los archivos de código fuente se convierten en archivos compilados, pero no se produce ningún archivo ejecutable. Esta opción es útil para compilar módulos por separado.
-cc ccomp
Usa ccomp como el enlazador C llamado para construir el ejecutable final y como el compilador C para compilar archivos fuente .c.
-cclib -lnombrelib
Pasa la opción -lnombrelib al enlazador. Esto hace que la biblioteca C dada se enlace con el programa.
-ccopt opción
Pasa la opción dada al compilador C y al enlazador. Por ejemplo, -ccopt -Ldir hace que el enlazador C busque bibliotecas C en el directorio dir.
-color modo
Habilita o deshabilita los colores en los mensajes del compilador (especialmente advertencias y errores). Los siguientes modos son compatibles:

auto usa heurísticas para habilitar colores solo si la salida los soporta (una terminal tty compatible con ANSI);

always habilita colores incondicionalmente;

never deshabilita la salida de color.

La variable de entorno "OCAML_COLOR" se considera si -color no se proporciona. Sus valores son auto/always/never como arriba.

Si -color no se proporciona, "OCAML_COLOR" no está configurado y la variable de entorno "NO_COLOR" está configurada, entonces la salida de color se deshabilita. De lo contrario, la configuración predeterminada es auto, y la heurística actual verifica que la variable de entorno "TERM" exista y no esté vacía o sea "dumb", y que isatty(stderr) sea verdadero.

-error-style modo
Controla la forma en que se imprimen los mensajes de error y las advertencias. Los siguientes modos son compatibles:

short solo imprime el error y su ubicación;

contextual como "short", pero también muestra el fragmento de código fuente correspondiente a la ubicación del error.

La configuración predeterminada es contextual.

La variable de entorno "OCAML_ERROR_STYLE" se considera si -error-style no se proporciona. Sus valores son short/contextual como arriba.

-compact
Optimiza el código producido para espacio en lugar de tiempo. Esto resulta en programas más pequeños pero ligeramente más lentos. El valor predeterminado es optimizar para velocidad.
-config
Imprime el número de versión de ocamlopt(1) y un resumen detallado de su configuración, luego sale.

ocamlopt.opt(1)

ocamlopt.opt - Compilador nativo de OCaml para la arquitectura AMD64

NOMBRE

ocamlopt.opt - Compilador nativo de OCaml para la arquitectura AMD64

SINOPSIS

ocamlopt.opt [opciones] [archivos.ml] ...

DESCRIPCIÓN

El comando ocamlopt.opt invoca el compilador nativo de OCaml para la arquitectura AMD64. Genera código máquina para la plataforma de destino. Es el compilador optimizado, que puede ser más lento para compilar pero produce ejecutables más rápidos.

OPCIONES

El compilador ocamlopt.opt acepta una amplia gama de opciones. Algunas de las más comunes incluyen:

  • -o archivo: Especifica el nombre del archivo de salida.
  • -c: Compila solo los archivos fuente, sin enlazarlos.
  • -I dir: Añade un directorio a la ruta de búsqueda de módulos.
  • -linkall módulo: Enlaza forzosamente un módulo.
  • -principal módulo: Especifica el módulo principal para la compilación.
  • -annot archivo: Genera un archivo de anotaciones.
  • -bin-annot: Habilita las anotaciones binarias.
  • -w lista-advertencias: Controla las advertencias del compilador.
  • -help: Muestra la ayuda del compilador.
  • -version: Muestra la versión del compilador.

OPCIONES PARA EL MIDDLE-END FLAMBDA

Estas opciones afectan al proceso de optimización intermedio:

  • -Olevel: Establece el nivel de optimización (0 a 3).
  • -inline n: Establece el tamaño máximo de las funciones para ser sustituidas en línea.
  • -unbox-small-structs: Habilita la desestratificación de estructuras pequeñas.

OPCIONES PARA LA ARQUITECTURA AMD64

Estas opciones son específicas de la generación de código para la arquitectura AMD64:

  • -flambda: Habilita el front-end Flambda para la optimización.
  • -noassert: Deshabilita la comprobación de aserciones.
  • -nodynlink: Deshabilita el enlace dinámico.
  • -runtime-variant variant: Especifica una variante del runtime.
