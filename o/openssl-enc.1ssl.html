NOMBRE

openssl-enc - rutinas de cifrado simétrico

SINOPSIS

openssl enc|cifrado [-cifrado] [-help] [-list] [-ciphers] [-in archivo] [-out archivo] [-pass arg] [-e] [-d] [-a] [-base64] [-A] [-k contraseña] [-kfile archivo] [-K clave] [-iv IV] [-S sal] [-salt] [-nosalt] [-z] [-md resumen] [-iter contador] [-pbkdf2] [-saltlen tamaño] [-p] [-P] [-bufsize número] [-nopad] [-v] [-debug] [-none] [-skeymgmt skeymgmt] [-skeyopt opt:valor] [-engine id] [-rand archivos] [-writerand archivo] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq]

openssl cifrado [...]

DESCRIPCIÓN

Los comandos de cifrado simétrico permiten cifrar o descifrar datos utilizando varios cifrados de bloque y de flujo utilizando claves basadas en contraseñas o proporcionadas explícitamente. La codificación o decodificación Base64 también se puede realizar por sí sola o además del cifrado o descifrado.

OPCIONES

-cifrado
El cifrado a utilizar.
-help
Muestra un mensaje de uso.
-list
Lista todos los cifrados compatibles.
-ciphers
Alias de -list para mostrar todos los cifrados compatibles.
-in archivo
El nombre del archivo de entrada, la entrada estándar por defecto.
-out archivo
El nombre del archivo de salida, la salida estándar por defecto.
-pass arg
El origen de la contraseña. Para más información sobre el formato de arg consulte openssl-passphrase-options(1).
-e
Cifra los datos de entrada: este es el valor predeterminado.
-d
Descifra los datos de entrada.
-a
Procesa los datos con Base64. Esto significa que si se está cifrando, los datos se codifican en Base64 después del cifrado. Si se establece la descifración, los datos de entrada se decodifican en Base64 antes de ser descifrados.

Cuando la opción -A no se proporciona, en la codificación se inserta una nueva línea después de cada 64 caracteres, y en la decodificación se espera una nueva línea entre los primeros 1024 bytes de entrada.

-base64
Igual que -a
-A
Si la opción -a está activada, la codificación Base64 produce salida sin ningún carácter de nueva línea, y la decodificación Base64 no requiere ninguna nueva línea. Por lo tanto, puede ser útil usar la opción -A al decodificar entrada desconocida.
-k contraseña
La contraseña para derivar la clave. Esto es para compatibilidad con versiones anteriores de OpenSSL. Sustituido por el argumento -pass.
-kfile archivo
Lee la contraseña para derivar la clave de la primera línea del archivo. Esto es para compatibilidad con versiones anteriores de OpenSSL. Sustituido por el argumento -pass.
-md resumen
Utiliza el resumen especificado para crear la clave a partir de la contraseña. El algoritmo predeterminado es sha-256.
-iter contador
Utiliza un número dado de iteraciones en la contraseña al derivar la clave de cifrado. Los valores altos aumentan el tiempo requerido para realizar fuerza bruta sobre el archivo resultante. Esta opción habilita el uso del algoritmo PBKDF2 para derivar la clave.
-pbkdf2
Utiliza el algoritmo PBKDF2 con un recuento de iteraciones predeterminado de 10000, a menos que se especifique lo contrario mediante la opción de línea de comandos -iter.
-saltlen
Establece la longitud de la sal a utilizar al usar la opción -pbkdf2. Por razones de compatibilidad, el valor predeterminado es 8 bytes. El valor máximo es actualmente de 16 bytes. Si la opción -pbkdf2 no se utiliza, esta opción se ignora y se utiliza una longitud de sal fija de 8 bytes. La longitud de sal utilizada al cifrar debe ser la misma que se utiliza al descifrar.
-nosalt
No utilizar sal (generada aleatoriamente o proporcionada con la opción -S) en las rutinas de derivación de clave. Esta opción NO DEBERÍA usarse excepto para propósitos de prueba o compatibilidad con versiones antiguas de OpenSSL.
-salt
Utiliza sal (generada aleatoriamente o proporcionada con la opción -S) al cifrar, este es el valor predeterminado.
-S sal
La sal real a utilizar: debe representarse como una cadena de dígitos hexadecimales. Si se utiliza esta opción al cifrar, se necesitará el mismo valor exacto de nuevo durante el descifrado. Esta sal puede ser truncada o rellenada con ceros para que coincida con la longitud de la sal (ver -saltlen).
-K clave
La clave real a utilizar: debe representarse como una cadena compuesta únicamente por dígitos hexadecimales. Si solo se especifica la clave, además se debe especificar el IV utilizando la opción -iv. Cuando se especifican tanto una clave como una contraseña, se utilizará la clave proporcionada con la opción -K y se tomará el IV generado a partir de la contraseña. No tiene mucho sentido especificar tanto la clave como la contraseña.
-iv IV
El IV real a utilizar: debe representarse como una cadena compuesta únicamente por dígitos hexadecimales. Cuando solo se especifica la clave usando la opción -K, el IV debe definirse explícitamente. Cuando se especifica una contraseña usando una de las otras opciones, el IV se genera a partir de esta contraseña.
-p
Muestra la clave y el IV utilizados.
-P
Muestra la clave y el IV utilizados y sale inmediatamente: no realiza ningún cifrado ni descifrado.
-bufsize número
Establece el tamaño del búfer para E/S.
-nopad
Deshabilita el relleno de bloque estándar.
-v
Impresión detallada; muestra algunas estadísticas sobre E/S y tamaños de búfer.
-debug
Depura los BIO utilizados para E/S.
-z
Comprime o descomprime los datos cifrados utilizando zlib después del cifrado o antes del descifrado. Esta opción solo existe si OpenSSL se compiló con la opción zlib o zlib-dynamic.
-none
Utiliza el cifrado NULL (sin cifrado ni descifrado de entrada).
-skeymgmt skeymgmt
Algunos proveedores pueden admitir objetos de claves simétricas opacas. Para utilizarlos, necesitamos conocer el nombre del EVP_SKEYMGMT a utilizar. Si no se especifica, se utilizará el nombre del cifrado.

Para averiguar el nombre de la gestión de claves simétricas adecuada, consulte la salida del comando "openssl list -skey-managers".

-skeyopt opt:valor
Para obtener una clave simétrica opaca existente o generar una nueva, las opciones de clave se especifican como opt:valor. Estas opciones no se pueden utilizar junto con ninguna opción que implique una clave en bruto directa o indirectamente.
-rand archivos, -writerand archivo
Consulte "Opciones de Estado Aleatorio" en openssl(1) para obtener detalles.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

-provider nombre
-provider-path ruta
-provparam [nombre:]clave=valor
-propquery consulta_prop
Ver "Opciones del proveedor" en openssl(1), provider(7) y property(7).
-engine id
Ver "Opciones del motor" en openssl(1). Esta opción está obsoleta.

NOTAS

El programa puede llamarse como "openssl cifrado" o "openssl enc -cifrado". La primera forma no funciona con cifrados proporcionados por motores, ya que esta forma se procesa antes de leer el archivo de configuración y cargar cualquier MOTOR. Utilice el comando openssl-list(1) para obtener una lista de cifrados compatibles.

Los motores que proporcionan algoritmos de cifrado completamente nuevos (como el motor ccgost que proporciona el algoritmo gost89) deben configurarse en el archivo de configuración. Los motores especificados en la línea de comandos usando la opción -engine solo se pueden usar para implementaciones asistidas por hardware de cifrados que son compatibles con el núcleo de OpenSSL o con otro motor especificado en el archivo de configuración.

Cuando el comando enc enumera los cifrados compatibles, también se enumeran los cifrados proporcionados por motores, especificados en los archivos de configuración.

Se le pedirá una contraseña para derivar la clave y el IV si es necesario.

La opción -salt debe usarse SIEMPRE si la clave se deriva de una contraseña, a menos que desee compatibilidad con versiones anteriores de OpenSSL.

Sin la opción -salt, es posible realizar ataques de diccionario eficientes contra la contraseña y atacar datos cifrados con cifrado de flujo. La razón de esto es que sin la sal, la misma contraseña siempre genera la misma clave de cifrado.

Cuando la sal se genera aleatoriamente (es decir, al cifrar usando una contraseña sin una sal explícita dada con la opción -S), los primeros bytes de los datos cifrados se reservan para almacenar la sal para su posterior descifrado.

Algunos de los cifrados no tienen claves grandes y otros tienen implicaciones de seguridad si no se usan correctamente. Se recomienda a los principiantes que utilicen solo un cifrado de bloque seguro, como AES, en modo CBC.

Todos los cifrados de bloque normalmente utilizan relleno PKCS#7, también conocido como relleno de bloque estándar. Esto permite realizar una comprobación rudimentaria de integridad o contraseña. Sin embargo, dado que la probabilidad de que datos aleatorios pasen la prueba es superior a 1 entre 256, no es una prueba muy buena.

Si el relleno está deshabilitado, los datos de entrada deben ser un múltiplo de la longitud del bloque del cifrado.

Todos los cifrados RC2 tienen la misma clave y longitud de clave efectiva.

Los algoritmos Blowfish y RC5 utilizan una clave de 128 bits.

Tenga en cuenta que OpenSSL 3.0 cambió el efecto de la opción -S. Cualquier valor de sal explícito especificado a través de esta opción ya no se antepone al texto cifrado al cifrar, y debe proporcionarse nuevamente explícitamente al descifrar. Por el contrario, cuando se utiliza la opción -S durante el descifrado, se espera que el texto cifrado no tenga un valor de sal antepuesto.

Al utilizar OpenSSL 3.0 o posterior para descifrar datos que fueron cifrados con una sal explícita bajo OpenSSL 1.1.1, no utilice la opción -S; la sal se leerá del texto cifrado. Para generar texto cifrado que pueda ser descifrado con OpenSSL 1.1.1, no utilice la opción -S; la sal se generará aleatoriamente y se antepondrá a la salida.

CIFRADOS COMPATIBLES

Tenga en cuenta que algunos de estos cifrados pueden estar deshabilitados en tiempo de compilación y algunos solo están disponibles si se configura un motor apropiado en el archivo de configuración. La salida al invocar este comando con la opción -list (es decir, "openssl enc -list") es una lista de cifrados, compatibles con su versión de OpenSSL, incluidos los proporcionados por los motores configurados.

Este comando no admite modos de cifrado autenticado como CCM y GCM, y no admitirá tales modos en el futuro. Esto se debe a que es necesario comenzar a transmitir la salida (por ejemplo, a la salida estándar cuando no se usa -out) antes de que se pueda validar la etiqueta de autenticación. Cuando este comando se utiliza en un pipeline, el extremo receptor no podrá revertir ante un fallo de autenticación. Los modos AEAD de uso común actualmente también sufren un fallo catastrófico de confidencialidad y/o integridad ante la reutilización de clave/IV/nonce, y dado que openssl enc traslada toda la carga de la gestión de clave/IV/nonce al usuario, el riesgo de exponer los modos AEAD es demasiado grande para permitirlo. Estos problemas de gestión de clave/IV/nonce también afectan a otros modos expuestos actualmente en este comando, pero los modos de fallo son menos extremos en estos casos, y la funcionalidad no se puede eliminar en una rama de lanzamiento estable. Para el cifrado masivo de datos, ya sea utilizando modos de cifrado autenticado u otros modos, se recomienda openssl-cms(1), ya que proporciona un formato de datos estándar y realiza la gestión necesaria de clave/IV/nonce.

Cuando se utiliza enc con modos de envoltura de claves, los datos de entrada no se pueden transmitir en flujo, lo que significa que deben procesarse en una sola pasada. En consecuencia, el tamaño de los datos de entrada debe ser menor que el tamaño del búfer (argumento -bufsize, por defecto 8*1024 bytes). Los cifrados '*-wrap' requieren que la entrada sea múltiplo de 8 bytes, ya que no se utiliza relleno. Los cifrados '*-wrap-pad' permiten cualquier longitud de entrada. En ambos casos, no se necesita IV. Ver ejemplo a continuación.

EJEMPLOS

Simplemente codifique un archivo binario en Base64:

openssl base64 -in archivo.bin -out archivo.b64

Decodifique el mismo archivo

openssl base64 -d -in archivo.b64 -out archivo.bin

Cifre un archivo usando AES-128 con una contraseña solicitada y derivación de clave PBKDF2:

openssl enc -aes128 -pbkdf2 -in archivo.txt -out archivo.aes128

Descifre un archivo usando una contraseña proporcionada:

openssl enc -aes128 -pbkdf2 -d -in archivo.aes128 -out archivo.txt \
   -pass pass:<contraseña>

Cifre un archivo y luego codifíquelo en Base64 (para que pueda ser enviado por correo, por ejemplo) usando AES-256 en modo CTR y derivación de clave PBKDF2:

openssl enc -aes-256-ctr -pbkdf2 -a -in archivo.txt -out archivo.aes256

Decodifique un archivo en Base64 y luego descifre usando una contraseña proporcionada en un archivo:

openssl enc -aes-256-ctr -pbkdf2 -d -a -in archivo.aes256 -out archivo.txt \

NAME

openssl-enc — encrypt or decrypt data using a set of ciphers

SYNOPSIS

 openssl enc [-cipher] [-variant] [-a | -base64] [-A] [-d] [-e] [-in file] [-out file] [-pass arg] [-pbkdf2] [-iter n] [-md digest] [-p] [-P] [-nolock] [-null] [-z] [-rand file(s)] [-engine id] [-provider name] [-provider-ctx ctx] [-ciphers | -list] [-engine_impl] [-skeymgmt alg] [-skeyopt opt]

DESCRIPTION

The enc command is a generic interface to various symmetric cipher algorithms. It can be used to encrypt and decrypt files. Note that this command is only intended for basic encryption and decryption tasks. For more advanced features like authenticated encryption, or for integrating with key derivation functions, consider using the dgst, cms, or pkcs7 commands.

The default operation is encryption. The -d option can be used to decrypt.

A cipher can be specified on the command line. If no cipher is specified, the default cipher is used (currently AES-256-CBC). The available ciphers can be listed using the -list option.

For password-based encryption, if the -pass option is not provided, the user will be prompted for a password. If the -in and -out options are not provided, stdin and stdout will be used.

The -e option explicitly selects encryption (this is the default), and the -d option selects decryption.

The -a or -base64 option performs base64 encoding on the output, and base64 decoding on the input if decrypting. This is useful for transmitting binary data over text-only channels.

The -A option enables 64-bit alignment for large files. It is only used when the -a or -base64 option is also specified.

The -pass argument can take several forms:

  • arg: The password is provided directly as arg.
  • env:VAR: The password is read from the environment variable VAR.
  • file:FILE: The password is read from the first line of the file FILE.
  • fd:FD: The password is read from the file descriptor FD.

The -pbkdf2 option uses the PBKDF2 key derivation function instead of the default EVP-based key derivation. The -iter option specifies the number of iterations for PBKDF2. The -md option specifies the digest to use with PBKDF2.

The -p option prints the salt and the key generated from the password.

The -P option prints the salt and the key generated from the password without encrypting or decrypting anything.

The -z option compresses the input before encrypting, and decompresses after decrypting.

The -rand file:s option can be used to obtain seed bytes from a file or files.

The -engine id option is deprecated. Use the -provider option instead.

The -provider name and -provider-ctx ctx options load providers and their contexts.

The -ciphers and -list options (deprecated in OpenSSL 3.0) list the available ciphers.

The -engine_impl option can be used to select an engine implementation.

The -skeymgmt and -skeyopt options allow specifying secret key management algorithms and their options.

OPTIONS

See openssl-ciphers(1) for a full list of supported ciphers.

NOTES

The -a option performs RFC 1521 base64 encoding. If the -A option is also specified, then the output is aligned to 64-bit boundaries. This is not standard base64 encoding, but it can be useful for some protocols.

The default digest for password derivation is MD5 (for compatibility with older versions). It is recommended to use a stronger digest like SHA256 or SHA512 by specifying -md sha256 or -md sha512.

When using a password-based encryption method, the salt is automatically generated and prepended to the ciphertext. When decrypting, the salt is automatically extracted from the ciphertext.

For password-based encryption, OpenSSL uses a default key derivation function (KDF). For newer versions of OpenSSL (3.0+), it's recommended to use PBKDF2 with a sufficient number of iterations (e.g., -pbkdf2 -iter 100000) and a strong digest (e.g., -md sha256).

SUPPORTED CIPHERS

See openssl-ciphers(1) for a list of supported ciphers.

EXAMPLES

Encrypt a file using AES-256-CBC and a password:

 openssl enc -aes-256-cbc -salt -in file.txt -out file.enc

Decrypt a file encrypted with AES-256-CBC:

 openssl enc -d -aes-256-cbc -in file.enc -out file.txt

Encrypt a file using AES-256-CBC with a password read from an environment variable:

 export MYPASS="mysecretpassword"
 openssl enc -aes-256-cbc -salt -in file.txt -out file.enc -pass env:MYPASS

Encrypt a file using AES-256-CBC with a password read from a file:

 openssl enc -aes-256-cbc -salt -in file.txt -out file.enc -pass file:pass.txt

Encrypt a file using AES-256-CBC and base64 encoding:

 openssl enc -aes-256-cbc -salt -a -in file.txt -out file.enc.b64

Decrypt a base64 encoded file:

 openssl enc -d -aes-256-cbc -a -in file.enc.b64 -out file.txt

Encrypt a file using AES-256-CBC with PBKDF2 and SHA256:

 openssl enc -aes-256-cbc -pbkdf2 -iter 100000 -md sha256 -salt -in file.txt -out file.enc

AES key wrapping:

 openssl enc -e -a -id-aes128-wrap-pad -K 000102030405060708090A0B0C0D0E0F -in file.bin
 or
 openssl aes128-wrap-pad -e -a -K 000102030405060708090A0B0C0D0E0F -in file.bin

BUGS

The -A option when used with large files doesn't work properly. On the other hand, when base64 decoding without the -A option, if the first 1024 bytes of input do not include a newline character the first two lines of input are ignored.

The openssl enc command only supports a fixed number of algorithms with certain parameters. So if, for example, you want to use RC2 with a 76 bit key or RC4 with an 84 bit key you can't use this program.

openssl-list(1ssl), EVP_SKEY(3ssl)

HISTORY

The default digest was changed from MD5 to SHA256 in OpenSSL 1.1.0.

The -list option was added in OpenSSL 1.1.1e.

The -ciphers and -engine options were deprecated in OpenSSL 3.0.

The -saltlen option was added in OpenSSL 3.2.

The -skeymgmt and -skeyopt options were added in OpenSSL 3.5.
