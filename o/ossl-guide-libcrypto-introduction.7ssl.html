NOMBRE

ossl-guide-libcrypto-introduction, crypto - Guía de OpenSSL: Una introducción a libcrypto

INTRODUCCIÓN

La biblioteca de criptografía de OpenSSL ("libcrypto") permite acceder a una amplia gama de algoritmos criptográficos utilizados en varios estándares de Internet. Los servicios proporcionados por esta biblioteca son utilizados por las implementaciones de TLS y CMS de OpenSSL, y también se han utilizado para implementar muchos otros productos y protocolos de terceros.

La funcionalidad incluye cifrado simétrico, criptografía de clave pública, acuerdo de claves, manejo de certificados, funciones hash criptográficas, generadores de números pseudoaleatorios criptográficos, códigos de autenticación de mensajes (MACs), funciones de derivación de claves (KDFs) y varias utilidades.

Algoritmos

Las primitivas criptográficas como el hash SHA256, o el cifrado AES se denominan "algoritmos" en OpenSSL. Cada algoritmo puede tener múltiples implementaciones disponibles para su uso. Por ejemplo, el algoritmo RSA está disponible como una implementación "predeterminada" adecuada para uso general, y una implementación "fips" que ha sido validada según los estándares FIPS 140 para situaciones donde esto es importante. También es posible que un tercero añada implementaciones adicionales, como en un módulo de seguridad de hardware (HSM).

Los algoritmos se implementan en proveedores. Consulte ossl-guide-libraries-introduction(7) para obtener información sobre los proveedores.

Operaciones

Los diferentes algoritmos se pueden agrupar por su propósito. Por ejemplo, hay algoritmos para cifrado y diferentes algoritmos para resumir datos. Estos diferentes grupos se conocen como "operaciones" en OpenSSL. Cada operación tiene un conjunto diferente de funciones asociadas. Por ejemplo, para realizar una operación de cifrado utilizando AES (o cualquier otro algoritmo de cifrado), utilizaría las funciones de cifrado detalladas en la página EVP_EncryptInit(3). O para realizar una operación de resumen utilizando SHA256, utilizaría las funciones de resumen en la página EVP_DigestInit(3).

OBTENCIÓN DE ALGORITMOS

Para utilizar un algoritmo, primero se debe "obtener" una implementación del mismo. La obtención es el proceso de buscar entre las implementaciones disponibles, aplicar criterios de selección (a través de una cadena de consulta de propiedades) y, finalmente, elegir la implementación que se utilizará.

OpenSSL admite dos tipos de obtención: "obtención explícita" y "obtención implícita".

Obtención explícita

La obtención explícita implica llamar directamente a una API específica para obtener una implementación de algoritmo de un proveedor. Este objeto obtenido se puede pasar a otras API. Estas funciones de obtención explícita suelen tener el nombre "NOMBRE_API_fetch", donde "NOMBRE_API" es el nombre de la operación. Por ejemplo, EVP_MD_fetch(3) se puede usar para obtener explícitamente una implementación de algoritmo de resumen. El usuario es responsable de liberar el objeto devuelto por la función "NOMBRE_API_fetch" utilizando "NOMBRE_API_free" cuando ya no sea necesario.

Estas funciones de obtención siguen un patrón bastante común, donde se pasan tres argumentos:

El contexto de la biblioteca
Consulte OSSL_LIB_CTX(3) para obtener una descripción más detallada. Puede ser NULL para indicar el contexto de biblioteca predeterminado (global) o un contexto creado por el usuario. Solo los proveedores cargados en este contexto de biblioteca (ver OSSL_PROVIDER_load(3)) serán considerados por la función de obtención. En caso de que no se haya cargado ningún proveedor en este contexto de biblioteca, se cargará el proveedor predeterminado como reserva (ver OSSL_PROVIDER-default(7)).
Un identificador
Para todas las funciones de obtención actualmente implementadas, este es el nombre del algoritmo. Cada proveedor admite una lista de implementaciones de algoritmos. Consulte la documentación específica del proveedor para obtener información sobre las implementaciones de algoritmos disponibles en cada proveedor: "OPERACIONES Y ALGORITMOS" en OSSL_PROVIDER-default(7), "OPERACIONES Y ALGORITMOS" en OSSL_PROVIDER-FIPS(7), "OPERACIONES Y ALGORITMOS" en OSSL_PROVIDER-legacy(7) y "OPERACIONES Y ALGORITMOS" en OSSL_PROVIDER-base(7).

Tenga en cuenta que, aunque los proveedores pueden registrar algoritmos contra una lista de nombres usando una cadena con una lista de nombres separados por dos puntos, la obtención de algoritmos utilizando ese formato no es compatible actualmente.

Una cadena de consulta de propiedades
La cadena de consulta de propiedades utilizada para guiar la selección de la implementación del algoritmo. Consulte "CADENAS DE CONSULTA DE PROPIEDADES" en ossl-guide-libraries-introduction(7).

La implementación del algoritmo que se obtiene se puede utilizar luego con otras funciones diversas que las utilizan. Por ejemplo, la función EVP_DigestInit_ex(3) toma como parámetro un objeto EVP_MD que puede haber sido devuelto por una llamada anterior a EVP_MD_fetch(3).

Obtención implícita

OpenSSL tiene una serie de funciones que devuelven un objeto de algoritmo sin una implementación asociada, como EVP_sha256(3), EVP_aes_128_cbc(3), EVP_get_cipherbyname(3) o EVP_get_digestbyname(3). Estos están presentes por compatibilidad con OpenSSL anterior a la versión 3.0, donde la obtención explícita no estaba disponible.

Cuando se utilizan con funciones como EVP_DigestInit_ex(3) o EVP_CipherInit_ex(3), la implementación real a utilizar se obtiene implícitamente utilizando criterios de búsqueda predeterminados (que usan NULL para el contexto de la biblioteca y la cadena de consulta de propiedades).

En algunos casos, la obtención implícita también puede ocurrir cuando se proporciona un parámetro de algoritmo NULL. En este caso, se obtiene implícitamente una implementación de algoritmo utilizando criterios de búsqueda predeterminados y un nombre de algoritmo que sea coherente con el contexto en el que se está utilizando.

Las funciones que utilizan un EVP_PKEY_CTX o un EVP_PKEY(3), como EVP_DigestSignInit(3), obtienen todas las implementaciones implícitamente. Normalmente, el algoritmo a obtener se determina en función del tipo de clave que se está utilizando y la función que se ha llamado.

Rendimiento

Si realiza la misma operación muchas veces con el mismo algoritmo, se recomienda realizar una única obtención explícita del algoritmo y luego reutilizar el algoritmo obtenido explícitamente cada vez subsiguiente. Esto será típicamente más rápido que obtener implícitamente el algoritmo cada vez que lo use. Vea un ejemplo de obtención explícita en "USO DE ALGORITMOS EN APLICACIONES".

Antes de OpenSSL 3.0, se utilizaron funciones como EVP_sha256(), que devuelven un objeto "const", directamente para indicar el algoritmo a utilizar en varias llamadas a funciones. Si pasa el valor devuelto de una de estas funciones de conveniencia a una operación, está utilizando la obtención implícita. Si está convirtiendo una aplicación que funcionaba con una versión de OpenSSL anterior a OpenSSL 3.0, considere cambiar las instancias de obtención implícita por obtención explícita.

Si no se pasa un objeto obtenido explícitamente a una operación, cualquier obtención implícita utilizará un objeto preobtenido almacenado en caché internamente, pero seguirá siendo más lento que pasar directamente el objeto obtenido explícitamente.
