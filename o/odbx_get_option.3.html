odbx_get_option(3)

Paquete: opendbx

Licencias: LGPL

odbx_get_option(3) OpenDBX odbx_get_option(3)

NOMBRE

odbx_get_option - Consultar al backend por opciones implementadas

SINOPSIS

#include <opendbx/api.h>


int odbx_get_option
(odbx_t* handle, unsigned int option, void* value);

DESCRIPCIÓN

odbx_get_option() solicita al módulo backend asociado a handle por odbx_init() las opciones implementadas y sus valores actuales. Esta función se puede utilizar en cualquier etapa siempre que handle apunte a un objeto de conexión válido. Su uso principal es averiguar las características compatibles del módulo backend y habilitarlas con odbx_set_option() antes de que la conexión con el servidor de base de datos se establezca llamando a odbx_bind().

El primer parámetro, handle, es el objeto de conexión creado y devuelto por odbx_init(), que deja de ser válido tan pronto como se suministra a odbx_finish().

Hay varios valores de opción definidos como constantes con nombre en el archivo de cabecera odbx.h. Algunos de ellos son solo para fines informativos, mientras que la mayoría de las opciones también se pueden establecer en diferentes valores de opción mediante odbx_set_option() para cambiar el comportamiento del módulo backend. Las opciones disponibles son:

ODBX_OPT_API_VERSION
La versión de la API implementada por el backend. Actualmente, solo devuelve cero y está reservada para el futuro.
ODBX_OPT_THREAD_SAFE
Si es seguro usar este backend y especialmente la biblioteca cliente de base de datos nativa en una aplicación que utiliza hilos, donde más de un hilo abre conexiones de base de datos a través de la biblioteca OpenDBX.
ODBX_OPT_TLS
La biblioteca cliente de base de datos puede admitir la transmisión segura de todos los datos mediante el cifrado del tráfico de red a través de SSL o TLS.
ODBX_OPT_MULTI_STATEMENTS
El servidor de base de datos puede admitir múltiples sentencias SQL en una cadena de consulta enviada a través de odbx_query().
ODBX_OPT_PAGED_RESULTS
Todos los servidores de base de datos y bibliotecas cliente pueden transferir los registros fila por fila. Algunos de ellos también pueden transferir múltiples filas o incluso todas a la vez para minimizar la carga del servidor, el tráfico de red y la latencia. La desventaja de esto es un mayor consumo de memoria.
ODBX_OPT_COMPRESS
Soporte para tráfico de red comprimido entre el cliente y el servidor de base de datos. Esto puede conducir a un mayor rendimiento si la red es el cuello de botella.
ODBX_OPT_MODE
Algunos servidores de base de datos admiten diferentes modos de operación, por ejemplo, modos para cumplir con otras implementaciones SQL o lenguajes de consulta completamente diferentes. Esta opción está disponible desde OpenDBX 1.1.4.

value debe ser un puntero a una variable entera donde el módulo backend almacenará el resultado de la opción suministrada. Si no se indica lo contrario, el valor asignado al parámetro value por odbx_get_option() será de naturaleza booleana y, por lo tanto, será ODBX_ENABLE para una opción compatible u ODBX_DISABLE para una opción que no sea compatible.

VALOR DE RETORNO

odbx_get_option() devuelve ODBX_ERR_SUCCESS, o un código de error cuyo valor es menor que cero si alguna de las operaciones no se pudo completar con éxito. Los códigos de error posibles se enumeran en la sección de errores y se pueden alimentar a odbx_error() y odbx_error_type() para obtener más detalles.

ERRORES

-ODBX_ERR_PARAM
Uno de los parámetros suministrados es inválido o es NULL y esto no está permitido en el módulo backend utilizado o en la biblioteca cliente de base de datos nativa.
-ODBX_ERR_OPTION
El valor pasado al parámetro option no es uno de los valores enumerados en este manual. El contenido de value permanece sin cambios si ocurre este error.

VER TAMBIÉN

odbx_bind(), odbx_error(), odbx_error_type(), odbx_init(), odbx_set_option()
