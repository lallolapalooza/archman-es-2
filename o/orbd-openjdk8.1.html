orbd(1) Java IDL y herramientas RMI-IIOP orbd(1)

NOMBRE

orbd - Permite a los clientes localizar y llamar a objetos persistentes en servidores en el entorno CORBA.

SINOPSIS

orbd [ opciones ]
opciones
Opciones de línea de comandos. Ver Opciones.

DESCRIPCIÓN

El comando orbd permite a los clientes localizar y llamar de forma transparente a objetos persistentes en servidores en el entorno CORBA. El Administrador de Servidores incluido con la herramienta orbd se utiliza para permitir a los clientes localizar y llamar de forma transparente a objetos persistentes en servidores en el entorno CORBA. Los servidores persistentes, al publicar las referencias de objetos persistentes en el servicio de nombres, incluyen el número de puerto del ORBD en la referencia del objeto en lugar del número de puerto del servidor. La inclusión de un número de puerto ORBD en la referencia del objeto para las referencias de objetos persistentes tiene las siguientes ventajas:

•
La referencia del objeto en el servicio de nombres permanece independiente del ciclo de vida del servidor. Por ejemplo, la referencia del objeto podría ser publicada por el servidor en el Servicio de Nombres cuando se instala por primera vez, y luego, independientemente de cuántas veces el servidor se inicie o se detenga, el ORBD devuelve la referencia del objeto correcta al cliente que llama.
•
El cliente necesita buscar la referencia del objeto en el servicio de nombres solo una vez, y puede seguir reutilizando esta referencia independientemente de los cambios introducidos debido al ciclo de vida del servidor.

Para acceder al Administrador de Servidores de ORBD, el servidor debe iniciarse usando servertool, que es una interfaz de línea de comandos para que los programadores de aplicaciones registren, anulen el registro, inicien y detengan un servidor persistente. Para más información sobre el Administrador de Servidores, ver Administrador de Servidores.

Cuando orbd se inicia, también inicia un servicio de nombres. Para más información sobre el servicio de nombres. Ver Inicio y Detención del Servicio de Nombres.

OPCIONES

-ORBInitialPort puertodenombre

Requerido. Especifica el puerto en el que se debe iniciar el servidor de nombres. Después de iniciarse, orbd escucha las solicitudes entrantes en este puerto. En el software Oracle Solaris, debe convertirse en el usuario root para iniciar un proceso en un puerto inferior a 1024. Por esta razón, Oracle recomienda que utilice un número de puerto superior o igual a 1024.

OPCIONES NO&#x00A0;REQUERIDAS

-puerto puerto

Especifica el puerto de activación donde se iniciará ORBD, y donde ORBD aceptará solicitudes para objetos persistentes. El valor predeterminado para este puerto es 1049. Este número de puerto se añade al campo de puerto de las Referencias de Objeto Interoperables (IOR) persistentes.
-defaultdb directorio

Especifica la base donde se creará el directorio de almacenamiento persistente de ORBD, orb.db. Si esta opción no se especifica, el valor predeterminado es ./orb.db.
-serverPollingTime milisegundos

Especifica con qué frecuencia ORBD comprueba la salud de los servidores persistentes registrados a través de servertool. El valor predeterminado es 1000 ms. El valor especificado para milisegundos debe ser un entero positivo válido.
-serverStartupDelay milisegundos

Especifica cuánto tiempo espera ORBD antes de enviar una excepción de reenvío de ubicación después de que un servidor persistente registrado a través de servertool se reinicia. El valor predeterminado es 1000 ms. El valor especificado para milisegundos debe ser un entero positivo válido.
-Jopción

Pasa opción a la Máquina Virtual Java, donde opción es una de las opciones descritas en la página de referencia para el lanzador de aplicaciones Java. Por ejemplo, -J-Xms48m establece la memoria de inicio en 48 MB. Ver java(1).

INICIO Y DETENCIÓN DEL SERVICIO DE NOMBRES

Un servicio de nombres es un servicio CORBA que permite nombrar objetos CORBA mediante la vinculación de un nombre a una referencia de objeto. La vinculación de nombres puede almacenarse en el servicio de nombres, y un cliente puede proporcionar el nombre para obtener la referencia de objeto deseada.

Antes de ejecutar un cliente o un servidor, iniciará ORBD. ORBD incluye un servicio de nombres persistente y un servicio de nombres transitorio, ambos son una implementación del Servicio de Nombres COS.

El Servicio de Nombres Persistente proporciona persistencia para los contextos de nombres. Esto significa que esta información es persistente entre las detenciones e inicios del servicio, y es recuperable en caso de fallo del servicio. Si se reinicia ORBD, el Servicio de Nombres Persistente restaura el grafo de contextos de nombres, de modo que la vinculación de los nombres de todos los clientes y servidores permanece intacta (persistente).

Por compatibilidad con versiones anteriores, tnameserv, un Servicio de Nombres Transitorio que se incluyó con versiones anteriores de JDK, también se incluye en esta versión de Java SE. Un servicio de nombres transitorio retiene los contextos de nombres mientras se está ejecutando. Si hay una interrupción del servicio, el grafo de contextos de nombres se pierde.

El argumento -ORBInitialPort es un argumento de línea de comandos requerido para orbd, y se utiliza para establecer el número de puerto en el que se ejecuta el servicio de nombres. Las siguientes instrucciones asumen que puede usar el puerto 1050 para el Daemon del Objeto de Solicitud de Corbroker de Java IDL. Al usar software Oracle Solaris, debe convertirse en usuario root para iniciar un proceso en un puerto inferior a 1024. Por esta razón, se recomienda usar un número de puerto superior o igual a 1024. Puede sustituir un puerto diferente si es necesario.

Para iniciar orbd desde una shell de comandos de UNIX, introduzca:

orbd -ORBInitialPort 1050&

Desde un símbolo del sistema de MS-DOS (Windows), introduzca:

start orbd -ORBInitialPort 1050

Ahora que ORBD está en ejecución, puede ejecutar sus aplicaciones cliente y servidor. Al ejecutar las aplicaciones cliente y servidor, deben ser conscientes del número de puerto (y el nombre de la máquina, cuando sea aplicable) donde se está ejecutando el Servicio de Nombres. Una forma de hacerlo es añadir el siguiente código a su aplicación:

Properties props = new Properties();
props.put("org.omg.CORBA.ORBInitialPort", "1050");
props.put("org.omg.CORBA.ORBInitialHost", "MiHost");
ORB orb = ORB.init(args, props);

En este ejemplo, el servicio de nombres se está ejecutando en el puerto 1050 en el host MiHost. Otra forma es especificar el número de puerto y/o el nombre de la máquina al ejecutar la aplicación servidor o cliente desde la línea de comandos. Por ejemplo, iniciaría su HelloApplication con la siguiente línea de comandos:

java HelloApplication -ORBInitialPort 1050 -ORBInitialHost MiHost

Para detener el servicio de nombres, utilice el comando del sistema operativo relevante, como pkillorbd en Oracle Solaris, o Ctrl+C en la ventana de DOS en la que se está ejecutando orbd. Tenga en cuenta que los nombres registrados en el servicio de nombres pueden desaparecer cuando el servicio se termina debido a un servicio de nombres transitorio. El servicio de nombres de Java IDL se ejecutará hasta que se detenga explícitamente.

Para más información sobre el servicio de nombres incluido con ORBD, ver Servicio de Nombres en http://docs.oracle.com/javase/8/docs/technotes/guides/idl/jidlNaming.html

orbd(8) - Arch Linux Manual Pages

NAME

orbd - Java(TM) Object Request Broker Daemon

SYNOPSIS

orbd [options]

DESCRIPTION

The orbd command starts the ORBD Naming Service. This service allows CORBA Java clients and servers to locate each other. The service maintains a database of object references keyed by object name. It supports the standard CORBA Naming Service interface and also provides a simple mechanism for registering and looking up local objects.

The orbd command can be used to start a name server that supports the Persistent and Transient naming services. The default is to start only the persistent naming service.

Use the -help option to display the full list of command-line options.

OPTIONS

-ORBInitialPort port
Specifies the port number on which the name server will listen for requests. This option is required if the name server is to be started and run. If this option is not specified, the name server will be started on the default port 1050.
-ORBInitialHost host
Specifies the host name on which the name server will run. This option is used by clients to find the name server.
-JSSenabling
Enables the Java Server (JS) Secure Socket Layer (SSL) support for the name server.
-sslport port
Specifies the port number for SSL connections. This option is only valid when -JSSenabling is specified.
-properties filename
Specifies the property file to be used to initialize the ORB. The property file contains a list of properties and their values.
-v
Verbose mode. Prints additional information about the name server's startup and operation.
-help
Displays all available command-line options.

SERVER MANAGER

The servertool utility is used to manage servers that are registered with the ORBD Naming Service. You can use servertool to register, start, stop, and query servers.

To start the servertool, use the command: servertool -ORBInitialPort 1050.

The port number specified with -ORBInitialPort must match the port number used to start orbd. If the ports do not match, the servertool will not be able to connect to the name server.

To shut down a persistent server. When a server is started using servertool, it must be started on the same host and port on which orbd is executing. If the server is run on a different port, then the information stored in the database for local contexts will be invalid and the service will not work properly.

See Java IDL: The "Hello World" Example at http://docs.oracle.com/javase/8/docs/technotes/guides/idl/jidlExample.html

In this example, you run the idlj compiler and javac compiler as shown in the tutorial. To run the ORBD Server Manager, follow these steps for running the application:

Start orbd.

UNIX command shell, enter: orbd -ORBInitialPort 1050.

MS-DOS system prompt (Windows), enter: start orbd -ORBInitialPort 1050.

Port 1050 is the port on which you want the name server to run. The -ORBInitialPort option is a required command-line argument. When using Oracle Solaris software, you must become a root user to start a process on a port below 1024. For this reason, it is recommended that you use a port number above or equal to 1024.

Start the servertool: servertool -ORBInitialPort 1050.

Make sure the name server (orbd) port is the same as in the previous step, for example, -ORBInitialPort 1050. The servertool must be started on the same port as the name server.

In the servertool command line interface, start the Hello server from the servertool prompt:

servertool > register -server HelloServer -classpath . -applicationName
                                    HelloServerApName

The servertool registers the server, assigns it the name HelloServerApName, and displays its server ID with a listing of all registered servers.Run the client application from another terminal window or prompt:

java HelloClient -ORBInitialPort 1050 -ORBInitialHost localhost

For this example, you can omit -ORBInitialHost localhost because the name server is running on the same host as the Hello client. If the name server is running on a different host, then use the -ORBInitialHost nameserverhost option to specify the host on which the IDL name server is running.Specify the name server (orbd) port as done in the previous step, for example, -ORBInitialPort 1050. When you finish experimenting with the ORBD Server Manager, be sure to shut down or terminate the name server (orbd) and servertool. To shut down orbd from am MS-DOS prompt, select the window that is running the server and enter Ctrl+C to shut it down.

To shut down orbd from an Oracle Solaris shell, find the process, and terminate with the kill command. The server continues to wait for invocations until it is explicitly stopped. To shut down the servertool, type quit and press the Enter key.
