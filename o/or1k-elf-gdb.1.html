GDB(1) Herramientas de Desarrollo GNU GDB(1)

NOMBRE

gdb - El Depurador GNU

SINOPSIS

gdb [OPCIONES] [programa|programa ID_proceso|programa core]

DESCRIPCION

El propósito de un depurador como GDB es permitirte ver lo que está sucediendo "dentro" de otro programa mientras se ejecuta — o lo que estaba haciendo otro programa en el momento en que falló.

GDB puede hacer cuatro tipos principales de cosas (más otras cosas en apoyo de estas) para ayudarte a detectar errores en el acto:

  • Iniciar tu programa, especificando cualquier cosa que pueda afectar su comportamiento.
  • Hacer que tu programa se detenga bajo condiciones específicas.
  • Examinar lo que ha sucedido, cuando tu programa se ha detenido.
  • Cambiar cosas en tu programa, para que puedas experimentar corrigiendo los efectos de un error y continuar aprendiendo sobre otro.

Puedes usar GDB para depurar programas escritos en C, C++, Fortran y Modula-2.

GDB se invoca con el comando de la shell "gdb". Una vez iniciado, lee comandos del terminal hasta que le dices que salga con el comando GDB "quit" o "exit". Puedes obtener ayuda en línea desde GDB mismo usando el comando "help".

Puedes ejecutar "gdb" sin argumentos ni opciones; pero la forma más habitual de iniciar GDB es con un argumento o dos, especificando un archivo ejecutable como argumento:

gdb programa

También puedes iniciar con un archivo ejecutable y un archivo core especificados:

gdb programa core

Alternativamente, puedes especificar un ID de proceso como segundo argumento o usar la opción "-p", si deseas depurar un proceso en ejecución:

gdb programa 1234
gdb -p 1234

esto adjuntaría GDB al proceso 1234. Con la opción -p puedes omitir el nombre de archivo del programa.

Aquí están algunos de los comandos GDB más frecuentemente necesarios:

break [archivo:][función|línea]
Establece un punto de interrupción en función o línea (en archivo).
run [lista_argumentos]
Inicia tu programa (con lista_argumentos, si se especifica).
bt
Backtrace (rastreo inverso): muestra la pila del programa.
print expresión
Muestra el valor de una expresión.
c
Continúa ejecutando tu programa (después de detenerse, por ejemplo, en un punto de interrupción).
next
Ejecuta la siguiente línea del programa (después de detenerse); avanza *sobre* cualquier llamada a función en la línea.
edit [archivo:]función
examina la línea del programa donde está detenido actualmente.
list [archivo:]función
muestra el texto del programa en la vecindad de donde está detenido actualmente.
step
Ejecuta la siguiente línea del programa (después de detenerse); avanza *dentro* de cualquier llamada a función en la línea.
help [nombre]
Muestra información sobre el comando GDB nombre, o información general sobre el uso de GDB.
quit
exit
Sale de GDB.

Para obtener detalles completos sobre GDB, consulta Using GDB: A Guide to the GNU Source-Level Debugger, de Richard M. Stallman y Roland H. Pesch. El mismo texto está disponible en línea como la entrada "gdb" en el programa "info".

OPCIONES

Cualquier argumento que no sean opciones especifica un archivo ejecutable y un archivo core (o ID de proceso); es decir, el primer argumento encontrado sin una bandera de opción asociada es equivalente a una opción --se, y el segundo, si existe, es equivalente a una opción -c si es el nombre de un archivo. Muchas opciones tienen formas largas y abreviadas; ambas se muestran aquí. Las formas largas también se reconocen si las truncas, siempre que sea suficiente parte de la opción para que sea inequívoca.

Las formas abreviadas se muestran aquí con - y las formas largas se muestran con -- para reflejar cómo se muestran en --help. Sin embargo, GDB reconoce todas las siguientes convenciones para la mayoría de las opciones:

"--opción=valor"
"--opción valor"
"-opción=valor"
"-opción valor"
"--o=valor"
"--o valor"
"-o=valor"
"-o valor"

Todas las opciones y argumentos de línea de comandos que proporciones se procesan en orden secuencial. El orden marca la diferencia cuando se usa la opción -x.

--help
-h
Lista todas las opciones, con explicaciones breves.
--symbols=archivo
-s archivo
Lee la tabla de símbolos del archivo.
--write
Habilita la escritura en archivos ejecutables y core.
--exec=archivo
-e archivo
Usa archivo como el archivo ejecutable a ejecutar cuando sea apropiado, y para examinar datos puros junto con un volcado de core.
--se=archivo
Lee la tabla de símbolos del archivo y úsala como el archivo ejecutable.
--core=archivo
-c archivo
Usa archivo como un volcado de core para examinar.
--command=archivo
-x archivo
Ejecuta comandos de GDB desde archivo.
--eval-command=comando
-ex comando
Ejecuta el comando GDB dado.
--init-eval-command=comando
-iex
Ejecuta el comando GDB antes de cargar el inferior.
--directory=directorio
-d directorio
Añade directorio a la ruta de búsqueda de archivos fuente.
--nh
No ejecutes comandos desde ~/.config/gdb/gdbinit, ~/.gdbinit, ~/.config/gdb/gdbearlyinit, o ~/.gdbearlyinit
--nx
-n
No ejecutes comandos desde ningún archivo de inicialización .gdbinit o .gdbearlyinit.
--quiet
--silent
-q
«Silencioso». No imprimas los mensajes introductorios y de copyright. Estos mensajes también se suprimen en modo batch.
--batch
Ejecuta en modo batch. Sal con estado 0 después de procesar todos los archivos de comandos especificados con -x (y .gdbinit, si no se inhibe). Sal con estado distinto de cero si ocurre un error al ejecutar los comandos GDB en los archivos de comandos.

--batch-silent
Ejecutar en modo batch, igual que --batch, pero totalmente silencioso. Toda la salida de GDB se suprime (stderr no se ve afectado). Esto es mucho más silencioso que --silent y sería inútil para una sesión interactiva.

Esto es particularmente útil cuando se usan objetivos que muestran mensajes de Loading section, por ejemplo.

Tenga en cuenta que los objetivos que emiten su salida a través de GDB, en contraposición a escribir directamente en "stdout", también se volverán silenciosos.

--args programa [lista_argumentos]
Cambiar la interpretación de la línea de comandos para que los argumentos que siguen a esta opción se pasen como argumentos al inferior. Como ejemplo, tome el siguiente comando: 
gdb ./a.out -q

Iniciaría GDB con -q, sin imprimir el mensaje introductorio. Por otro lado, usando:

gdb --args ./a.out -q

inicia GDB con el mensaje introductorio y pasa la opción al inferior.

--pid=pid
Adjuntar GDB a un programa ya en ejecución, con el PID pid.
--tui
Abrir la interfaz de usuario de terminal.
--readnow
Leer todos los símbolos del symfile dado en el primer acceso.
--readnever
No leer archivos de símbolos.
--return-child-result
El código de salida de GDB será el mismo que el código de salida del hijo.
--configuration
Imprimir detalles sobre la configuración de GDB y luego salir.
--version
Imprimir información de la versión y luego salir.
--cd=directorio
Ejecutar GDB usando directorio como su directorio de trabajo, en lugar del directorio actual.
--data-directory=directorio
-D
Ejecutar GDB usando directorio como su directorio de datos. El directorio de datos es donde GDB busca sus archivos auxiliares.
--fullname
-f
Emacs establece esta opción cuando ejecuta GDB como un subproceso. Le dice a GDB que emita el nombre de archivo completo y el número de línea de una manera estándar y reconocible cada vez que se muestra un marco de pila (lo que incluye cada vez que el programa se detiene). Este formato reconocible se ve como dos caracteres \032, seguidos del nombre del archivo, el número de línea y la posición del carácter separados por dos puntos, y una nueva línea. El programa de interfaz Emacs-a-GDB utiliza los dos caracteres \032 como una señal para mostrar el código fuente del marco.
-b velocidad_baudios
Establecer la velocidad de línea (velocidad en baudios o bits por segundo) de cualquier interfaz serie utilizada por GDB para depuración remota.
-l tiempo_espera
Establecer el tiempo de espera, en segundos, para la depuración remota.
--tty=dispositivo
Ejecutar usando dispositivo para la entrada y salida estándar de su programa.
