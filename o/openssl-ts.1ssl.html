NOMBRE

openssl-ts - Comando de Autoridad de Sellado de Tiempo

SINOPSIS

openssl ts -help

openssl ts -query [-config archivo_config] [-data archivo_a_hashear] [-digest bytes_digest] [-digest] [-tspolicy oid] [-no_nonce] [-cert] [-in request.tsq] [-out request.tsq] [-text] [-rand archivos] [-writerand archivo] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq]

openssl ts -reply [-config archivo_config] [-section seccion_tsa] [-queryfile request.tsq] [-passin fuente_contraseña] [-signer tsa_cert.pem] [-inkey nombre_archivo|uri] [-digest] [-chain certs_file.pem] [-tspolicy oid] [-in response.tsr] [-token_in] [-out response.tsr] [-token_out] [-text] [-engine id] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq]

openssl ts -verify [-data archivo_a_hashear] [-digest bytes_digest] [-queryfile request.tsq] [-in response.tsr] [-token_in] [-untrusted archivos|uris] [-CAfile archivo] [-CApath dir] [-CAstore uri] [-allow_proxy_certs] [-attime timestamp] [-no_check_time] [-check_ss_sig] [-crl_check] [-crl_check_all] [-explicit_policy] [-extended_crl] [-ignore_critical] [-inhibit_any] [-inhibit_map] [-partial_chain] [-policy arg] [-policy_check] [-policy_print] [-purpose propósito] [-suiteB_128] [-suiteB_128_only] [-suiteB_192] [-trusted_first] [-no_alt_chains] [-use_deltas] [-auth_level num] [-verify_depth num] [-verify_email email] [-verify_hostname hostname] [-verify_ip ip] [-verify_name nombre] [-x509_strict] [-issuer_checks] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq]

DESCRIPCIÓN

Este comando es una aplicación básica de cliente y servidor de Autoridad de Sellado de Tiempo (TSA) según se especifica en RFC 3161 (Time-Stamp Protocol, TSP). Una TSA puede ser parte de un despliegue PKI y su función es proporcionar prueba a largo plazo de la existencia de un determinado dato antes de un tiempo particular. Aquí hay una breve descripción del protocolo:

1.
El cliente TSA calcula un valor hash unidireccional para un archivo de datos y envía el hash a la TSA.
2.
La TSA adjunta la fecha y hora actuales al valor hash recibido, las firma y envía el token de sello de tiempo de vuelta al cliente. Al crear este token, la TSA certifica la existencia del archivo de datos original en el momento de la generación de la respuesta.
3.
El cliente TSA recibe el token de sello de tiempo y verifica la firma sobre él. También comprueba si el token contiene el mismo valor hash que había enviado a la TSA.

Hay una unidad de datos de protocolo codificada en DER definida para transportar una solicitud de sello de tiempo a la TSA y otra para enviar la respuesta de sello de tiempo de vuelta al cliente. Este comando tiene tres funciones principales: crear una solicitud de sello de tiempo basada en un archivo de datos, crear una respuesta de sello de tiempo basada en una solicitud, y verificar si una respuesta corresponde a una solicitud particular o a un archivo de datos.

Todavía no hay soporte para enviar las solicitudes/respuestas automáticamente a través de HTTP o TCP como se sugiere en RFC 3161. Los usuarios deben enviar las solicitudes por ftp o correo electrónico.

OPCIONES

-help
Imprime un mensaje de uso.
-query
Genera una consulta TS. Para más detalles ver "Generación de Solicitud de Sello de Tiempo".
-reply
Genera una respuesta TS. Para más detalles ver "Generación de Respuesta de Sello de Tiempo".
-verify
Verifica una respuesta TS. Para más detalles ver "Verificación de Respuesta de Sello de Tiempo".

Generación de Solicitud de Sello de Tiempo

El comando -query se puede usar para crear e imprimir una solicitud de sello de tiempo con las siguientes opciones:

-config archivo_config
El archivo de configuración a utilizar. Opcional; para una descripción del valor por defecto, ver "RESUMEN DE COMANDOS" en openssl(1).
-data archivo_a_hashear
El archivo de datos para el cual se necesita crear la solicitud de sello de tiempo. stdin es el valor por defecto si no se especifica el parámetro -data ni -digest. (Opcional)
-digest bytes_digest
Es posible especificar la huella del mensaje explícitamente sin el archivo de datos. La huella debe especificarse en formato hexadecimal, dos caracteres por byte, los bytes opcionalmente separados por dos puntos (ej. 1A:F6:01:... o 1AF601...). El número de bytes debe coincidir con el algoritmo de resumen de mensajes en uso. (Opcional)
-digest
El resumen de mensajes a aplicar al archivo de datos. Cualquier resumen soportado por el comando openssl-dgst(1) puede ser utilizado. El valor por defecto es SHA-256. (Opcional)
-tspolicy oid
La política que el cliente espera que la TSA utilice para crear el token de sello de tiempo. Se pueden usar tanto la notación OID punteada como los nombres OID definidos en el archivo de configuración. Si no se solicita ninguna política, la TSA utilizará su propia política por defecto. (Opcional)
-no_nonce
No se especifica ningún nonce en la solicitud si se da esta opción. De lo contrario, se incluye un nonce pseudoaleatorio de 64 bits en la solicitud. Se recomienda el uso de un nonce para proteger contra ataques de repetición. (Opcional)
-cert
Se espera que la TSA incluya su certificado de firma en la respuesta. (Opcional)
-in request.tsq
Esta opción especifica una solicitud de sello de tiempo previamente creada en formato DER que se imprimirá en el archivo de salida. Útil cuando se necesita examinar el contenido de una solicitud en formato legible por humanos. (Opcional)
-out request.tsq
Nombre del archivo de salida al que se escribirá la solicitud. El valor por defecto es stdout. (Opcional)
-text
Si se especifica esta opción, la salida estará en formato de texto legible por humanos en lugar de DER. (Opcional)
-rand archivos, -writerand archivo
Ver "Opciones de Estado Aleatorio" en openssl(1) para detalles.

Generación de Respuesta de Sello de Tiempo

Una respuesta de sello de tiempo (TimeStampResp) consiste en un estado de respuesta y el propio token de sello de tiempo (ContentInfo), si la generación del token fue exitosa. El comando -reply es para crear una respuesta de sello de tiempo o un token de sello de tiempo basado en una solicitud e imprimir la respuesta/token en formato legible por humanos. Si no se especifica -token_out, la salida es siempre una respuesta de sello de tiempo (TimeStampResp), de lo contrario, es un token de sello de tiempo (ContentInfo).

-config archivo_config
El archivo de configuración a utilizar. Opcional; para una descripción del valor por defecto, ver "RESUMEN DE COMANDOS" en openssl(1).
-section seccion_tsa
La sección en el archivo de configuración que contiene los parámetros de la TSA, por ejemplo, la política de sellado de tiempo y el certificado de firma. (Opcional)
-queryfile request.tsq
Este parámetro especifica el archivo que contiene la solicitud de sello de tiempo (en formato DER) que debe ser procesada.
-passin fuente_contraseña
La fuente de la contraseña para el archivo de clave privada. Ver "PASSWORD SOURCES" en openssl(1) para más detalles. (Opcional)
-signer tsa_cert.pem
El certificado del firmante TSA. Si no se especifica, se intentará buscar en el archivo de configuración. (Opcional)
-inkey nombre_archivo|uri
La clave privada del firmante TSA. Si no se especifica, se intentará buscar en el archivo de configuración. (Opcional)
-digest
El resumen de mensajes a aplicar al archivo de datos. Cualquier resumen soportado por el comando openssl-dgst(1) puede ser utilizado. El valor por defecto es SHA-256. (Opcional)
-chain certs_file.pem
Un archivo que contiene certificados adicionales de la cadena de confianza del certificado TSA. (Opcional)
-tspolicy oid
La política de sellado de tiempo a usar. Si no se especifica, se utilizará la política por defecto en la configuración de la TSA. (Opcional)
-in response.tsr
Lee la respuesta de sello de tiempo del archivo especificado. Si no se especifica, se lee de stdin. (Opcional)
-token_in
Lee un token de sello de tiempo (ContentInfo) en lugar de una respuesta completa (TimeStampResp). (Opcional)
-out response.tsr
Escribe la respuesta de sello de tiempo en el archivo especificado. Si no se especifica, se escribe en stdout. (Opcional)
-token_out
Escribe solo el token de sello de tiempo (ContentInfo) en el archivo de salida, en lugar de la respuesta completa (TimeStampResp). (Opcional)
-text
Si se especifica esta opción, la salida estará en formato de texto legible por humanos en lugar de DER. (Opcional)
-engine id
Ver "Engines" en openssl(1).

Verificación de Respuesta de Sello de Tiempo

El comando -verify verifica una respuesta de sello de tiempo (TimeStampResp) contra una solicitud de sello de tiempo (TimeStampReq) o un archivo de datos y un archivo de certificados de confianza.

-data archivo_a_hashear
El archivo de datos original que se supone que se ha sellado. Si no se especifica, el hash se lee de la solicitud (si está presente).
-digest bytes_digest
La huella del mensaje explícita (en formato hexadecimal) que se supone que se ha sellado. Si no se especifica, el hash se lee de la solicitud (si está presente).
-queryfile request.tsq
Lee la solicitud de sello de tiempo (en formato DER) del archivo especificado. Se utiliza para verificar que el hash de la respuesta coincide con el hash de la solicitud y que la respuesta contiene todos los campos esperados.
-in response.tsr
Lee la respuesta de sello de tiempo del archivo especificado. Si no se especifica, se lee de stdin.
-token_in
Lee un token de sello de tiempo (ContentInfo) en lugar de una respuesta completa (TimeStampResp).
-untrusted archivos|uris
Uno o más archivos o URIs que contienen certificados de confianza (por ejemplo, el certificado de la TSA y los certificados intermedios). Se utilizan para verificar la cadena de certificados de la TSA.
-CAfile archivo
Un archivo que contiene certificados de Autoridad de Certificación (CA) de confianza.
-CApath dir
Un directorio que contiene certificados de Autoridad de Certificación (CA) de confianza, organizados en un formato específico.
-CAstore uri
Un URI que apunta a un almacén de certificados de confianza.
-attime timestamp
Verifica que el sello de tiempo sea posterior a la marca de tiempo dada. El formato de la marca de tiempo es YYYYMMDDHHMMSS[Z|+-hhmm].
-no_check_time
No comprueba la validez de la marca de tiempo del sello de tiempo (si se proporciona).
-check_ss_sig
Verifica las firmas de los certificados de los sellos de tiempo de la cadena de servidores de seguridad.
-crl_check
Verifica las listas de revocación de certificados (CRL).
-crl_check_all
Verifica las listas de revocación de certificados (CRL) para todos los certificados de la cadena.
-explicit_policy
Requiere que el certificado de la TSA contenga una política explícita.
-extended_crl
Permite el uso de extensiones de CRL.
-ignore_critical
Ignora las extensiones críticas en el certificado de la TSA.
-inhibit_any
Permite la presencia de extensiones de inhabilitación de políticas.
-inhibit_map
Mapea las extensiones de inhabilitación de políticas.
-partial_chain
Permite cadenas de certificados parciales.
-policy arg
Comprueba la presencia de una política específica.
-policy_check
Habilita la comprobación de políticas.
-policy_print
Imprime las políticas del certificado.
-purpose propósito
Verifica que el certificado de la TSA tenga el propósito especificado.
-suiteB_128
Verifica según los requisitos de Suite B de 128 bits.
-suiteB_128_only
Verifica según los requisitos de Suite B de 128 bits exclusivamente.
-suiteB_192
Verifica según los requisitos de Suite B de 192 bits.
-trusted_first
Prioriza la verificación de certificados de confianza.
-no_alt_chains
No permite cadenas de certificados alternativas.
-use_deltas
Permite el uso de CRLs delta.
-auth_level num
Establece el nivel de autenticación para la verificación.
-verify_depth num
Establece la profundidad máxima de la cadena de certificados para la verificación.
-verify_email email
Verifica que el nombre del firmante del certificado coincida con la dirección de correo electrónico proporcionada.
-verify_hostname hostname
Verifica que el nombre del firmante del certificado coincida con el nombre de host proporcionado.
-verify_ip ip
Verifica que el nombre del firmante del certificado coincida con la dirección IP proporcionada.
-verify_name nombre
Verifica que el nombre del firmante del certificado coincida con el nombre proporcionado.
-x509_strict
Habilita la verificación estricta de X.509.
-issuer_checks
Realiza comprobaciones sobre el emisor del certificado.

EJEMPLOS

Generar una solicitud de sello de tiempo para el archivo `myfile.dat` utilizando el algoritmo SHA-256 y guardarla en `request.tsq`:

openssl ts -query -data myfile.dat -sha256 -out request.tsq

Generar una respuesta de sello de tiempo para la solicitud en `request.tsq` utilizando el certificado TSA `tsa_cert.pem` y la clave privada `tsa_key.pem`, y guardar la respuesta en `response.tsr`:

openssl ts -reply -queryfile request.tsq -signer tsa_cert.pem -inkey
tsa_key.pem -out response.tsr

Verificar la respuesta de sello de tiempo en `response.tsr` para el archivo `myfile.dat` utilizando el certificado TSA y los certificados intermedios en `chain.pem`:

openssl ts -verify -data myfile.dat -in response.tsr -untrusted
chain.pem

Verificar la respuesta de sello de tiempo en `response.tsr` contra la solicitud en `request.tsq`:

openssl ts -verify -queryfile request.tsq -in response.tsr

VER

openssl(1), openssl-dgst(1)

HISTORIA

La funcionalidad de TS se añadió en OpenSSL 0.9.7.

La lista de algoritmos de digestión de mensajes que la TSA acepta. Se debe especificar al menos un algoritmo. (Obligatorio)
accuracy
La precisión de la fuente de tiempo de la TSA en segundos, milisegundos y microsegundos. Por ejemplo: secs:1, millisecs:500, microsecs:100. Si falta algún componente, se asume cero para ese campo. (Opcional)
clock_precision_digits
Especifica el número máximo de dígitos que representan la fracción de segundos y que deben incluirse en el campo de tiempo. Los ceros finales deben eliminarse del tiempo, por lo que puede haber menos dígitos o ninguna fracción de segundos. Solo compatible en plataformas UNIX. El valor máximo es 6, el predeterminado es 0. (Opcional)
ordering
Si esta opción es sí, las respuestas generadas por esta TSA siempre pueden ordenarse, incluso si la diferencia de tiempo entre dos respuestas es inferior a la suma de sus precisiones. El valor predeterminado es no. (Opcional)
tsa_name
Establezca esta opción en sí si el nombre del sujeto de la TSA debe incluirse en el campo del nombre de la TSA de la respuesta. El valor predeterminado es no. (Opcional)
ess_cert_id_chain
Los objetos SignedData creados por la TSA siempre contienen el identificador del certificado de firma en un atributo firmado (ver RFC 2634, Enhanced Security Services). Si esta variable se establece en no, solo se incluye el identificador de este certificado de firma en el atributo firmado SigningCertificate. Si esta variable se establece en sí y se especifica la variable certs o la opción -chain, entonces también se incluirán los identificadores de los certificados de la cadena, donde la opción -chain anula la variable certs. El valor predeterminado es no. (Opcional)
ess_cert_id_alg
Esta opción especifica la función hash que se utilizará para calcular el identificador del certificado público de la TSA. El valor predeterminado es sha256. (Opcional)

EJEMPLOS

Todos los ejemplos siguientes presuponen que OPENSSL_CONF está configurado en un archivo de configuración adecuado, por ejemplo, el archivo de configuración de ejemplo openssl/apps/openssl.cnf servirá.

Solicitud de marca de tiempo

Para crear una solicitud de marca de tiempo para design1.txt con digest SHA-256, sin nonce ni política, y sin requisito de certificado en la respuesta:

openssl ts -query -data design1.txt -no_nonce \
      -out design1.tsq

Para crear una solicitud de marca de tiempo similar especificando explícitamente la impresión del mensaje:

openssl ts -query -digest b7e5d3f93198b38379852f2c04e78d73abdd0f4b \
       -no_nonce -out design1.tsq

Para mostrar el contenido de la solicitud anterior en formato legible por humanos:

openssl ts -query -in design1.tsq -text

Para crear una solicitud de marca de tiempo que incluya el digest SHA-512 de design2.txt, solicite el certificado del firmante y el nonce, y especifique un ID de política (asumiendo que el nombre tsa_policy1 está definido en la sección OID del archivo de configuración):

openssl ts -query -data design2.txt -sha512 \
      -tspolicy tsa_policy1 -cert -out design2.tsq

Respuesta de marca de tiempo

Antes de generar una respuesta, se debe crear un certificado de firma para la TSA que contenga la extensión de uso de clave extendido timeStamping crítica sin ninguna otra extensión de uso de clave. Puede agregar esta línea a la sección de certificados de usuario del archivo de configuración para generar un certificado adecuado;

extendedKeyUsage = critical,timeStamping

Consulte openssl-req(1), openssl-ca(1), y openssl-x509(1) para obtener instrucciones. Los ejemplos a continuación asumen que cacert.pem contiene el certificado de la CA, tsacert.pem es el certificado de firma emitido por cacert.pem y tsakey.pem es la clave privada de la TSA.

Para crear una respuesta de marca de tiempo para una solicitud:

openssl ts -reply -queryfile design1.tsq -inkey tsakey.pem \
      -signer tsacert.pem -out design1.tsr

Si desea utilizar la configuración del archivo de configuración, podría simplemente escribir:

openssl ts -reply -queryfile design1.tsq -out design1.tsr

Para mostrar una respuesta de marca de tiempo en la salida estándar en formato legible por humanos:

openssl ts -reply -in design1.tsr -text

Para crear un token de marca de tiempo en lugar de una respuesta de marca de tiempo:

openssl ts -reply -queryfile design1.tsq -out design1_token.der -token_out

Para mostrar un token de marca de tiempo en la salida estándar en formato legible por humanos:

openssl ts -reply -in design1_token.der -token_in -text -token_out

Para extraer el token de marca de tiempo de una respuesta:

openssl ts -reply -in design1.tsr -out design1_token.der -token_out

Para agregar información de estado 'concedido' a un token de marca de tiempo, creando así una respuesta válida:

openssl ts -reply -in design1_token.der -token_in -out design1.tsr

Verificación de marca de tiempo

Para verificar una respuesta de marca de tiempo contra una solicitud:

openssl ts -verify -queryfile design1.tsq -in design1.tsr \
      -CAfile cacert.pem -untrusted tsacert.pem

Para verificar una respuesta de marca de tiempo que incluye la cadena de certificados:

openssl ts -verify -queryfile design2.tsq -in design2.tsr \
      -CAfile cacert.pem

Para verificar un token de marca de tiempo contra el archivo de datos original:

openssl ts -verify -data design2.txt -in design2.tsr \
      -CAfile cacert.pem

Para verificar un token de marca de tiempo contra una impresión de mensaje:

openssl ts -verify -digest b7e5d3f93198b38379852f2c04e78d73abdd0f4b \
       -in design2.tsr -CAfile cacert.pem

También puede consultar el directorio 'test' para ver más ejemplos.

ERRORES

  • No hay soporte para marcas de tiempo sobre SMTP, aunque es bastante fácil implementar una TSA automática basada en correo electrónico con procmail(1) y perl(1). El soporte del servidor HTTP se proporciona en forma de un módulo de Apache separado. El soporte del cliente HTTP se proporciona mediante tsget(1). El protocolo TCP/IP puro no es compatible.
  • El archivo que contiene el último número de serie de la TSA no está bloqueado al leerlo o escribirlo. Esto es un problema si más de una instancia de openssl(1) intenta crear una respuesta de marca de tiempo al mismo tiempo. Esto no es un problema cuando se utiliza el módulo del servidor apache, ya que realiza el bloqueo adecuado.
  • Busque la palabra FIXME en los archivos fuente.
  • El código fuente realmente debería ser revisado por otra persona también.
  • Se necesita más pruebas, solo he realizado algunas pruebas básicas (ver test/testtsa).

HISTORIA

OpenSSL 1.1.1 introdujo un nuevo generador aleatorio (CSPRNG) con un mecanismo de siembra mejorado. El nuevo mecanismo de siembra hace innecesario definir un RANDFILE para guardar y restaurar la aleatoriedad. Esta opción se conserva principalmente por motivos de compatibilidad.

La opción -engine fue obsoleta en OpenSSL 3.0.
