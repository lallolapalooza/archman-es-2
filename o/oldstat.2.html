stat(2) Manual de Llamadas al Sistema stat(2)

NOMBRE

stat, fstat, lstat, fstatat - obtener estado del archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

lstat():

    /* Desde glibc 2.20 */ _DEFAULT_SOURCE
        || _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.10: */ _POSIX_C_SOURCE >= 200112L
        || /* glibc 2.19 y anteriores */ _BSD_SOURCE

fstatat():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _ATFILE_SOURCE

DESCRIPCIÓN

Estas funciones devuelven información sobre un archivo, en el búfer apuntado por statbuf. No se requieren permisos sobre el archivo en sí, pero —en el caso de stat(), fstatat() y lstat()— se requiere permiso de ejecución (búsqueda) en todos los directorios de path que conducen al archivo.

stat() y fstatat() obtienen información sobre el archivo apuntado por path; las diferencias para fstatat() se describen a continuación.

lstat() es idéntica a stat(), excepto que si path es un enlace simbólico, devuelve información sobre el propio enlace, no sobre el archivo al que se refiere el enlace.

fstat() es idéntica a stat(), excepto que el archivo sobre el cual se va a obtener información se especifica mediante el descriptor de archivo fd.

La estructura stat

Todas estas llamadas al sistema devuelven una estructura stat (ver stat(3type)).

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura stat pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si st_mode o st_uid son cambiados por otro proceso llamando a chmod(2) o chown(2), stat() podría devolver el st_mode antiguo junto con el st_uid nuevo, o el st_uid antiguo junto con el st_mode nuevo.

fstatat()

La llamada al sistema fstatat() es una interfaz más general para acceder a la información del archivo que aún puede proporcionar exactamente el comportamiento de cada una de stat(), lstat() y fstat().

Si path es relativo, se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como hacen stat() y lstat() para una ruta relativa).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso que llama (como stat() y lstat()).

Si path es absoluto, dirfd se ignora.

flags puede ser 0, o incluir una o más de las siguientes banderas ORed:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si path es una cadena vacía (o NULL, desde Linux 6.11) opere sobre el archivo al que se refiere dirfd (que pudo haber sido obtenido usando la bandera O_PATH de open(2)). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio, y el comportamiento de fstatat() es similar al de fstat(). Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; defina _GNU_SOURCE para obtener su definición.
AT_NO_AUTOMOUNT (desde Linux 2.6.38)
No montar automáticamente el componente terminal ("nombre base") de path. Desde Linux 3.1 esta bandera se ignora. Desde Linux 4.11 esta bandera está implícita.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo resuelva: en su lugar, devuelva información sobre el propio enlace, como lstat(). (Por defecto, fstatat() resuelve enlaces simbólicos, como stat().)

Ver openat(2) para una explicación de la necesidad de fstatat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se deniega el permiso de búsqueda en uno de los directorios del prefijo de ruta de path. (Ver también path_resolution(7).)
EBADF
fd no es un descriptor de archivo abierto válido.
EBADF
(fstatat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
Dirección inválida.
EINVAL
(fstatat()) Bandera inválida especificada en flags.
ELOOP
Se encontraron demasiados enlaces simbólicos al recorrer la ruta.
ENAMETOOLONG
path es demasiado largo.
ENOENT
Un componente de path no existe o es un enlace simbólico colgante.
ENOENT
path es una cadena vacía y no se especificó AT_EMPTY_PATH en flags.
ENOMEM
Sin memoria (es decir, memoria del kernel).
ENOTDIR
Un componente del prefijo de ruta de path no es un directorio.
ENOTDIR
(fstatat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EOVERFLOW
path o fd se refieren a un archivo cuyo tamaño, número de inodo o número de bloques no se pueden representar en los tipos off_t, ino_t o blkcnt_t, respectivamente. Este error puede ocurrir cuando, por ejemplo, una aplicación compilada en una plataforma de 32 bits sin -D_FILE_OFFSET_BITS=64 llama a stat() en un archivo cuyo tamaño excede (1<<31)-1 bytes.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

stat()
fstat()
lstat()
SVr4, 4.3BSD, POSIX.1-2001.
fstatat()
POSIX.1-2008. Linux 2.6.16, glibc 2.4.

Según POSIX.1-2001, lstat() en un enlace simbólico solo necesita devolver información válida en el campo st_size y el tipo de archivo

oldstat(2) — oldstat system call

NAME

oldstat, fstat, lstat — get file status (obsolete)

LIBRARY

Standard C library (libc, −lc)

SYNOPSIS

#include <sys/stat.h>

int oldstat(const char *pathname, struct stat *statbuf);

int fstat(int fd, struct stat *statbuf);

int lstat(const char *pathname, struct stat *statbuf);

DESCRIPTION

These functions retrieve information about the file pointed to by pathname (for oldstat and lstat) or described by the file descriptor fd (for fstat). The information is stored in the structure pointed to by statbuf.

The struct stat structure contains at least the following fields:

struct stat {
    dev_t     st_dev;     /* ID of the device containing the file */
    ino_t     st_ino;     /* Node number */
    mode_t    st_mode;    /* Protection bits */
    nlink_t   st_nlink;   /* Number of hard links */
    uid_t     st_uid;     /* User ID of owner */
    gid_t     st_gid;     /* Group ID of owner */
    dev_t     st_rdev;    /* Device ID (if special file) */
    off_t     st_size;    /* Total size, in bytes */
    time_t    st_atime;   /* Time of last access */
    time_t    st_mtime;   /* Time of last modification */
    time_t    st_ctime;   /* Time of last status change */
    blksize_t st_blksize; /* Block size for I/O */
    blkcnt_t  st_blocks;  /* Number of 512B blocks allocated */
};

The interpretation of the st_mode field is system-dependent, but the following bits are defined by POSIX:

S_IFMT
Mask to extract the file type field.
S_IFSOCK
Socket.
S_IFLNK
Symbolic link.
S_IFREG
Regular file.
S_IFBLK
Block device.
S_IFDIR
Directory.
S_IFCHR
Character device.
S_IFIFO
FIFO (named pipe).
S_ISUID
Set-user-ID bit.
S_ISGID
Set-group-ID bit.
S_ISVTX
Sticky bit.
S_IRUSR
Read permission for owner.
S_IWUSR
Write permission for owner.
S_IXUSR
Execute permission for owner.
S_IRWXU
Read, write, execute for owner.
S_IRGRP
Read permission for group.
S_IWGRP
Write permission for group.
S_IXGRP
Execute permission for group.
S_IRWXG
Read, write, execute for group.
S_IROTH
Read permission for others.
S_IWOTH
Write permission for others.
S_IXOTH
Execute permission for others.
S_IRWXOTH
Read, write, execute for others.

fstat() is identical to stat() except that the file to be examined is specified by the file descriptor fd rather than by a pathname.

lstat() is like stat() but if pathname is a symbolic link, then it returns information about the link itself rather than the file the link points to.

oldstat() is an older version of stat(). On Linux, the stat() library function is a wrapper that calls the most recent version of the stat() system call, and may perform the necessary repacking for older applications.

The st_atime, st_mtime, and st_ctime fields are stored as seconds since the Epoch. The interpretation of these times may differ between systems. On some systems, accesses to files on certain file systems (e.g., NFS) may not update st_atime.

The st_blocks and st_blksize fields are intended to indicate the number of blocks allocated for the file and the preferred block size for I/O, respectively. Their interpretation can vary significantly between systems. POSIX.1-2008 requires that st_blksize be returned if the file system supports it; otherwise, 0 may be returned. The st_blocks field is measured in 512-byte units, regardless of the actual block size of the file system.

POSIX.1-2008 requires that lstat() return valid information in all fields except the mode bits in st_mode.

C library/kernel differences

Over time, increases in the size of the stat structure have led to three successive versions of stat(): sys_stat() (slot __NR_oldstat), sys_newstat() (slot __NR_stat), and sys_stat64() (slot __NR_stat64) on 32-bit platforms such as i386. The first two versions were already present in Linux 1.0 (albeit with different names); the last was added in Linux 2.4. Similar remarks apply for fstat() and lstat().

The kernel-internal versions of the stat structure dealt with by the different versions are, respectively:

__old_kernel_stat
The original structure, with rather narrow fields, and no padding.
stat
Larger st_ino field and padding added to various parts of the structure to allow for future expansion.
stat64
Even larger st_ino field, larger st_uid and st_gid fields to accommodate the Linux-2.4 expansion of UIDs and GIDs to 32 bits, and various other enlarged fields and further padding in the structure. (Various padding bytes were eventually consumed in Linux 2.6, with the advent of 32-bit device IDs and nanosecond components for the timestamp fields.)

The glibc stat() wrapper function hides these details from applications, invoking the most recent version of the system call provided by the kernel, and repacking the returned information if required for old binaries.

On modern 64-bit systems, life is simpler: there is a single stat() system call and the kernel deals with a stat structure that contains fields of a sufficient size.

The underlying system call employed by the glibc fstatat() wrapper function is actually called fstatat64() or, on some architectures, newfstatat().

RETURN VALUE

On success, zero is returned. On error, −1 is returned, and errno is set appropriately.

ERRORS

The following errno values may be set for stat() and lstat():

EACCES
Search permission denied for any component of the required path prefix, or read permission denied for the file itself.
EBADF
fd is not a valid file descriptor for fstat().
EFAULT

statbuf points outside the accessible address space.

pathname points outside the accessible address space.

EINTR
A signal was caught during the execution of the system call.
EIO
An I/O error occurred while reading from or writing to the file system.
ELOOP
Too many symbolic links were encountered in resolving pathname.
ENAMETOOLONG
pathname is too long.
ENOENT
A component of pathname does not exist or is a dangling symbolic link (for stat() and fstat(), but not for lstat()).
ENOMEM
Out of kernel memory.
ENOTDIR
A component of pathname is not a directory.
ENXIO
The file does not exist and is a character or block special file. (This error is defined in POSIX.1 but may not be returned by all implementations.)
EOVERFLOW
The file is too large to be represented in the object returned by statbuf.
EROFS
A read-only file system was encountered.
ETXTBSY
The file is a regular file that is being executed.

The following errno values may be set for fstat():

EINVAL

fd is a pipe or FIFO.

fd refers to a file that has been opened with the O_TMPFILE flag but without the O_RDWR flag.

STANDARDS

fstat() and lstat() conform to POSIX.1-2008.

oldstat() is obsolete; it is provided for compatibility with older systems. Its behavior is undefined on Linux.

HISTORY

The stat() and fstat() system calls appeared in Version 1 AT&T UNIX. The lstat() system call appeared in Version 7 AT&T UNIX.

The structure members st_atime, st_mtime, and st_ctime were originally stored as members of struct stat. In some older systems, these were arrays of structures, and had to be accessed via offsets. The stat() system call, as described in the POSIX standard, returns time values as time_t. However, on some systems (like Linux and BSD), the st_atime, st_mtime, and st_ctime fields returned by the kernel may contain more precise timestamps (e.g., nanoseconds) than the standard time_t type can represent. The glibc wrapper function might provide these higher-resolution timestamps if available, either by using a larger structure for the return value or by returning pointers to structures containing these fields.

The st_blocks and st_blksize fields were introduced in BSD. The interpretation differs between systems, and possibly on a single system when NFS mounts are involved.

The st_rdev field was originally 16 bits. On Linux, it is 32 bits. The interpretation of the bits in the st_mode field of the stat structure is system-dependent. POSIX.1-2008 tightens the specification, requiring lstat() to return valid information in all fields except the mode bits in st_mode.

C library/kernel differences

Over time, increases in the size of the stat structure have led to three successive versions of stat(): sys_stat() (slot __NR_oldstat), sys_newstat() (slot __NR_stat), and sys_stat64() (slot __NR_stat64) on 32-bit platforms such as i386. The first two versions were already present in Linux 1.0 (albeit with different names); the last was added in Linux 2.4. Similar remarks apply for fstat() and lstat().

EXAMPLES

The following program calls lstat() and displays selected fields in the returned stat structure.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID of containing device:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("File type:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("block device\n");            break;
    case S_IFCHR:  printf("character device\n");        break;
    case S_IFDIR:  printf("directory\n");               break;
    case S_IFIFO:  printf("FIFO/pipe\n");               break;
    case S_IFLNK:  printf("symlink\n");                 break;
    case S_IFREG:  printf("regular file\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("unknown?\n");                break;
    }
    printf("I-node number:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Mode:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Link count:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Ownership:                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Preferred I/O block size: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("File size:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Blocks allocated:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Last status change:       %s", ctime(&sb.st_ctime));
    printf("Last file access:         %s", ctime(&sb.st_atime));
    printf("Last file modification:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
