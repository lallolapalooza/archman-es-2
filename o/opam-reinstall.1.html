NOMBRE

opam-reinstall - Reinstalar una lista de paquetes.

SINOPSIS

opam reinstall [OPCIÓN]… [PAQUETES]…

DESCRIPCIÓN

Este comando elimina los paquetes dados y los que dependen de ellos, y reinstala las mismas versiones. Sin argumentos, asume --pending y reinstala cualquier paquete con cambios externos.

Si se especifica un directorio como argumento, se seleccionan para reinstalar todos los elementos anclados a ese directorio.

ARGUMENTOS

PAQUETES
Lista de nombres de paquetes, con una versión o restricción opcional, p. ej. `pkg', `pkg.1.0' o `pkg>=0.5'; o nombres de directorios que contienen la descripción del paquete, con directorio explícito (p. ej. `./srcdir' o `.')

OPCIONES

--assume-built
Para uso en paquetes anclados localmente: asume que ya han sido compilados correctamente, y solo ejecuta sus instrucciones de instalación, directamente desde su directorio fuente. Esto omite las instrucciones de compilación y puede ser útil para instalar paquetes en los que se está trabajando. Implica --inplace-build. Ningún paquete anclado localmente será omitido.
--forget-pending
Olvida las reinstalaciones pendientes de los paquetes listados. Esto implica hacer que opam asuma que tus paquetes fueron instalados con una versión más reciente de sus metadatos, así que usa esto solo si sabes lo que estás haciendo, y los cambios reales que estás sobrescribiendo. Puede ser más seguro usar opam pin --current en los paquetes con reinstalaciones pendientes, bloqueándolos explícitamente en su estado actual.
--list-pending
Lista los paquetes que han sido cambiados desde su instalación y están marcados para reinstalación
--pending
Realiza reinstalaciones pendientes, es decir, reinstalaciones de paquetes que han cambiado desde su instalación
--recursive
Permite búsquedas recursivas de archivos *.opam. Cf. también --subpath.
--subpath=RUTA
Los archivos *.opam se obtienen del subdirectorio dado en lugar del directorio principal. Las fuentes se toman entonces del subdirectorio objetivo, internamente solo se copia/descarga este subdirectorio. Puede combinarse con --recursive para tener una búsqueda recursiva en la subruta.

OPCIONES DE COMPILACIÓN DE PAQUETES

--assume-depexts
Omite el paso de instalación para cualquier paquete de sistema faltante, e intenta continuar con la compilación de los paquetes opam de todos modos. Si la instalación tiene éxito, opam no volverá a preguntar sobre estos paquetes de sistema. Solo tiene sentido si el manejo de dependencias externas está habilitado.
-b, --keep-build-dir
Conserva los directorios de compilación después de compilar los paquetes. Esto es equivalente a establecer $OPAMKEEPBUILDDIR a "true".
--build-doc
Eliminado en 2.1, usa --with-doc en su lugar.
--build-test
Eliminado en 2.1, usa --with-test en su lugar.
-d, --with-doc
Compila la documentación del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Esto es equivalente a establecer $OPAMWITHDOC (o el obsoleto $OPAMBUILDDOC) a "true".
--dry-run
Simula el comando, pero no realiza ningún cambio real. Esto también se puede establecer con la variable de entorno $OPAMDEBUG.
--fake
Esta opción registra las acciones en la base de datos de opam, sin realizarlas realmente. ADVERTENCIA: Esta opción es peligrosa y es probable que rompa tu entorno de opam. Probablemente quieras --dry-run. Has sido advertido.
--ignore-constraints-on[=PAQUETES] (por defecto=)
Fuerza a opam a ignorar las restricciones de versión en todas las dependencias de los paquetes listados. Esto se puede usar para probar la compatibilidad, pero se esperan fallos en la compilación al usarlo. Ten en cuenta que la disponibilidad de los paquetes, así como las restricciones de versión en dependencias opcionales y conflictos, no se ven afectados. Esto es equivalente a establecer $OPAMIGNORECONSTRAINTS.
--inplace-build
Al compilar un paquete cuya fuente está vinculada a un directorio local, procesa las acciones de compilación e instalación directamente en ese directorio, en lugar de hacerlo en una copia limpia gestionada por opam. Esto solo afecta a los paquetes que se listan explícitamente en la línea de comandos. Esto es equivalente a establecer $OPAMINPLACEBUILD a "true".
-j TRABAJOS, --jobs=TRABAJOS
Establece el número máximo de trabajos concurrentes a utilizar. El valor por defecto se calcula a partir del número de núcleos. También puedes establecerlo usando la variable de entorno $OPAMJOBS.
--lock-suffix=SUFIJO (ausente=locked)
Establece el sufijo de los archivos de bloqueo a SUFIJO.
--locked
En comandos que usan archivos opam encontrados a partir de fuentes ancladas, si se encuentra una variante del archivo con una extensión .locked añadida (por ejemplo, foo.opam.locked junto a foo.opam), se usará esa en su lugar. Esto es típicamente útil para ofrecer un conjunto más específico de dependencias y reproducir contextos de compilación similares, de ahí el nombre. La opción lock se puede usar para generar tales archivos, basándose en las versiones de las dependencias actualmente instaladas en el host. Esto es equivalente a establecer la variable de entorno $OPAMLOCKED. Ten en cuenta que esta opción generalmente no afecta a los paquetes ya anclados.
-m MAKE, --make=MAKE
Eliminado en 2.1, usa opam config set[-global] make MAKE en su lugar.
--no-checksums
No verificar la suma de comprobación de los archivos descargados. Esto es equivalente a establecer $OPAMNOCHECKSUMS a "true".
--no-depexts
Deshabilita temporalmente el manejo de dependencias externas. Esto se puede usar si un paquete no está disponible en el gestor de paquetes de tu sistema, pero has instalado la dependencia requerida manualmente. Implica --assume-depexts, y también almacena las excepciones al tener éxito.
--require-checksums
Rechaza la instalación de paquetes que no proporcionan una suma de comprobación para los archivos externos. Esto es equivalente a establecer $OPAMREQUIRECHECKSUMS a "true".
--reuse-build-dir
Reutiliza los directorios de compilación existentes (conservados usando --keep-build-dir), en lugar de compilar desde una copia nueva de la fuente. Esto puede ser más rápido, pero también puede llevar a fallos si los sistemas de compilación de los paquetes no manejan bien las actualizaciones de dependencias. Esto es equivalente a establecer $OPAMREUSEBUILDDIR a "true".
--show-actions
Llama al solucionador y muestra las acciones. No realiza ningún cambio. Esto es equivalente a establecer $OPAMSHOW.
--skip-updates
Al ejecutar una instalación, actualización o reinstalación en paquetes anclados a fuente, normalmente se actualizan primero desde su origen. Esta bandera deshabilita ese comportamiento y los mantiene a su versión en caché. Esto es equivalente a establecer $OPAMSKIPUPDATE.
-t, --with-test
Compila y **ejecuta** las pruebas unitarias del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Esto es equivalente a establecer $OPAMWITHTEST (o el obsoleto $OPAMBUILDTEST) a "true".
--unlock-base
Eliminado en 2.1, usa --update-invariant en su lugar.
--update-invariant
Permite cambios en los paquetes establecidos como base del switch (típicamente, el compilador principal). Usar con precaución. Esto es equivalente a establecer la variable de entorno $OPAMUNLOCKBASE
--verbose-on=PAQUETES
Sé más verboso en paquetes específicos. Esto es equivalente a establecer $OPAMVERBOSE.
--with-dev-setup
Incluye dependencias solo de herramientas de desarrollo.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no todos los paquetes solicitados pueden ser instalados: intentar instalar tantos como sea posible. Ten en cuenta que no todos los solucionadores externos pueden soportar esta opción (versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

--cli=MAYOR.MENOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Previsto para cualquier uso persistente de opam (scripts, posts de blog, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. La bandera no estaba disponible en opam 2.0, por lo que para seleccionar la CLI de 2.0, establece la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o unsafe-yes. Se puede especificar más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIA
Especifica las preferencias del usuario para la resolución de dependencias en esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para detalles sobre el lenguaje soportado y los solucionadores externos disponibles, ver http://opam.ocaml.org/doc/External_solvers.html. Una guía general para el uso de preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBRE_ARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en NOMBRE_ARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Igual que --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está configurada (es decir, si estás usando una versión de desarrollo), y sale.
--help[=FMT] (por defecto=auto)
Muestra esta ayuda en el formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBRE_ARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre de archivo contiene el carácter `%', será reemplazado por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en la versión 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto desactiva este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato más antiguo. En cualquier caso, es preferible actualizar manualmente los repositorios usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Desactiva --verbose.
--root=ROOT
Utiliza ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegura que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de completado, por ejemplo. Fallará siempre que se necesite tal operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el solucionador CUDF a usar para resolver problemas de instalación de paquetes. Este es un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. Por defecto, continúa silenciosamente si es posible.
--switch=SWITCH
Utiliza SWITCH como el switch del compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Desactiva cualquier solucionador externo y usa el incorporado (esto requiere que opam haya sido compilado con un solucionador incorporado). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más verboso. Una opción -v muestra todos los comandos de paquetes, repetir para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.). Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra información de la versión.
-w, --working-dir
Siempre que se actualicen paquetes vinculados a un directorio local controlado por versiones, actualiza al estado de trabajo actual de su código fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio de origen se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede configurar con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

OPAMBUILDDOC Eliminado en la versión 2.1.

OPAMBUILDTEST Eliminado en la versión 2.1.

OPAMCLI ver opción `--cli'.

OPAMCRITERIA especifica las preferencias del usuario para la resolución de dependencias. El valor por defecto depende de la versión del solucionador, usa `config report' para conocer la configuración actual. Ver también la opción --criteria.

OPAMDIGDEPTH define cuán agresiva es la búsqueda de conflictos durante el preprocesamiento CUDF.

OPAMDOWNLOADJOBS establece el número máximo de descargas simultáneas.

OPAMDROPWORKINGDIR anula los paquetes previamente actualizados con --working-dir en la actualización. Sin esta variable establecida, opam los mantendría sin cambios a menos que se nombren explícitamente en la línea de comandos.

OPAMEDITOR establece el editor a usar para editar archivos de opam, anula $EDITOR y $VISUAL.

OPAMERRLOGLEN establece el número de líneas de log impresas cuando falla un subproceso. 0 para imprimir todas.

OPAMEXTERNALSOLVER ver opción `--solver'.

OPAMFAKE ver opción `--fake'.

OPAMFETCH especifica cómo descargar archivos: `wget', `curl' o un comando personalizado donde las variables %{url}%, %{out}%, %{retry}%, %{compress}% y %{checksum}% serán reemplazadas. Anula el valor de 'download-command' del archivo de configuración principal.

OPAMFIXUPCRITERIA igual que OPAMUPGRADECRITERIA, pero específico para fixup y reinstalación.

OPAMIGNORECONSTRAINTS ver opción de instalación `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS ver opción `--ignore-pin-depends'.

OPAMINPLACEBUILD ver opción `--inplace-build'.

OPAMJOBS establece el número máximo de trabajadores paralelos a ejecutar.

OPAMJSON registra la salida json en el archivo dado (usa el carácter `%` para indexar los archivos).

OPAMKEEPBUILDDIR ver opción de instalación `--keep-build-dir'.

OPAMKEEPLOGS indica a opam que no elimine algunos logs de comandos temporales y algunas copias de seguridad. Esto omite algunos finalizadores y también puede ayudar a obtener rastreos de pila más fiables.

OPAMLOCKED combinación de las opciones `--locked' y `--lock-suffix'.

OPAMLOGS logdir establece el directorio de logs, el valor por defecto es un directorio temporal en /tmp

OPAMMAKECMD establece el comando make del sistema a usar.

OPAMMERGEOUT fusiona las salidas de los procesos, stderr en stdout.

OPAMNO responde no a cualquier pregunta, ver opciones `--no' y `--confirm-level`. OPAMNO se ignora si OPAMCONFIRMLEVEL o OPAMYES está establecido.

DESCRIPTION

This section details the environment variables that can be used to configure the behaviour of opam.

Most of these settings can also be controlled via command-line options, which usually take precedence over environment variables. For example, `opam install --no-checksums pkg' is equivalent to setting the OPAMNOCHECKSUMS environment variable to true.

The variables are typically set in the shell before running opam, for example:

$ export OPAMROOT=~/.opam-test
$ opam install some-package

or directly in the invocation:

$ OPAMROOT=~/.opam-test opam install some-package

Some variables are only used internally by opam.

OPAMCLI
See section CLI VERSION.

OPAMCLIENTVERSION
This variable is set by opam when it invokes a script, and can be used by scripts to check the opam client version.

OPAMCOLUMNS
Set the width of the terminal. Defaults to the terminal width.

OPAMCONFIRMLEVEL
This variable specifies the default confirmation level. It can be set to `safe', `medium', or `low'. This is equivalent to the `--confirm-level' command-line option.

OPAMCRITERIA
Specifies user preferences for dependency solving. See option `--criteria'.

OPAMDEBUG
If set, opam enters debugging mode and prints debugging information to stderr.

Sets the diff backend used for showing differences, e.g. `git diff' or `diff -u`. Defaults to `diff -u`.

Disables host system checks.

Disables running tests for packages. Equivalent to `--disable-tests'.

OPAMDOWNLOADERS
