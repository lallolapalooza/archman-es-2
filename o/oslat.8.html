NOMBRE

oslat - Detector de latencia del sistema operativo

SINOPSIS

oslat [ -shvz ] [ -b tamaño-cubeta ] [ -B sesgo ] [ -c lista-cpu ] [ -C hilo-principal-cpu ] [ -f prioridad-rt ] [ --json archivo ] [ -m memoria-carga-trabajo ] [-t tiempo-ejecucion ] [ -T umbral-trazado ] [ -w carga-trabajo ] [ -W ancho-cubeta ]

DESCRIPCIÓN

oslat es un programa de estrés en modo de sondeo de espacio de usuario de código abierto para detectar latencia a nivel del sistema operativo. El programa ejecuta un bucle ocupado sin carga de trabajo o con varias cargas de trabajo, recopilando información TSC y midiendo el tiempo con frecuencia durante el proceso.

OPCIONES

-b, --tamaño-cubeta=N
Especifica el número de cubetas (4-1024).
-B, --sesgo
Agrega un sesgo a todas las cubetas utilizando el mínimo estimado.
-c, --lista-cpu=LISTA_CPUS
Especifica las CPU en las que ejecutarse. Por ejemplo, '1,3,5,7-15'.
-C, --hilo-principal-cpu=NÚCLEO
Especifica en qué CPU se ejecuta el hilo principal. Por defecto es cpu0.
-f, --prioridad-rt=PRIORIDAD
Usando una prioridad SCHED_FIFO específica (1-99). De lo contrario, usa la prioridad predeterminada, normalmente será SCHED_OTHER.
--json=ARCHIVO
Escribe los resultados finales en ARCHIVO, con formato JSON.
-m, --carga-trabajo-memoria=TAMAÑO
Tamaño de la memoria a utilizar para la carga de trabajo (por ejemplo, 4K, 1M). El uso total de memoria será este valor multiplicado por 2*N, ya que habrá búferes de origen/destino para cada hilo, y N es el número de procesadores para la prueba.
-D, --duración=TIEMPO
Especifica la duración de la prueba, por ejemplo, 60, 20m, 2H (m/M: minutos, h/H: horas, d/D: días). Por defecto, la unidad es s/segundo.
-T, --umbral-trazado=UMBRAL
Detiene la prueba cuando se activa el umbral (en USEC). Al mismo tiempo, imprime un marcador en ftrace y también detiene ftrace.
-w, --carga-trabajo=CARGA_TRABAJO
Especifica un tipo de carga de trabajo, el valor predeterminado es sin carga de trabajo. Opciones: "no", "memmove".
-s, --precalentamiento-unico
Utiliza un solo hilo al medir la latencia en la etapa de precalentamiento. NOTA: Asegúrese de que la frecuencia de la CPU en todos los núcleos de prueba esté bloqueada antes de usar este parámetro. Si no sabe cómo bloquear la frecuencia, no utilice este parámetro.
-W, --ancho-cubeta
Intervalo entre cubetas en nanosegundos

NOTA: Los anchos que no son múltiplos de 1000 causan salida de precisión ns. Usted es responsable de considerar el impacto de la sobrecarga de medición a escala de nanosegundos.

-h, --ayuda
Muestra el mensaje de ayuda.
-v, --versión
Muestra la versión del programa.
-z, --omitir-cero
No muestre las cubetas en el histograma de salida si todas son cero.
