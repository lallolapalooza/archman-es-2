OPENFORTIVPN(1) Manual de Comandos Generales OPENFORTIVPN(1)

NOMBRE

openfortivpn - Cliente para servicios de túnel VPN PPP+TLS

SINOPSIS

openfortivpn [<host>[:<puerto>]] [-u <usuario>] [-p <contraseña>] [--cookie=<cookie>] [--cookie-on-stdin] [--saml-login[=<puerto>]] [--pinentry=<nombre>] [--otp=<otp>] [--otp-prompt=<mensaje>] [--otp-delay=<retraso>] [--no-ftm-push] [--realm=<realm>] [--ifname=<interfaz>] [--set-routes=<booleano>] [--no-routes] [--set-dns=<booleano>] [--no-dns] [--half-internet-routes=<booleano>] [--ca-file=<archivo>] [--user-cert=<archivo>] [--user-cert=pkcs11:] [--user-key=<archivo>] [--use-syslog] [--trusted-cert=<resumen>] [--insecure-ssl] [--cipher-list=<cifrados>] [--min-tls=<version>] [--seclevel-1] [--pppd-use-peerdns=<booleano>] [--pppd-no-peerdns] [--pppd-log=<archivo>] [--pppd-plugin=<archivo>] [--pppd-ipparam=<cadena>] [--pppd-ifname=<cadena>] [--pppd-call=<nombre>] [--pppd-accept-remote=<booleano>] [--ppp-system=<cadena>] [--use-resolvconf=<booleano>] [--persistent=<intervalo>] [-c <archivo>] [-v|-q]
openfortivpn --help
openfortivpn --version

DESCRIPCIÓN

openfortivpn se conecta a una VPN configurando un túnel al gateway en <host>:<puerto>.

OPCIONES

--help
Muestra el mensaje de ayuda y sale.
--version
Muestra la versión y sale.
-c <archivo>, --config=<archivo>
Especifica un archivo de configuración personalizado (por defecto: /etc/openfortivpn/config).
-u <usuario>, --username=<usuario>
Nombre de usuario de la cuenta VPN.
-p <contraseña>, --password=<contraseña>
Contraseña de la cuenta VPN en texto plano. Para una alternativa segura, usa pinentry o deja que openfortivpn la solicite.
--cookie=<cookie>
Una cookie válida (SVPNCOOKIE) para usar en lugar del nombre de usuario y contraseña.
--cookie-on-stdin
Lee la cookie (SVPNCOOKIE) de la entrada estándar.
--saml-login[=<puerto>]
Crea un servidor web temporal para recibir una operación de redirección SAML local. Para iniciar sesión con SAML solo tienes que abrir `<tu-dominio-vpn>/remote/saml/start?redirect=1' y seguir los pasos de inicio de sesión. Al final del proceso de inicio de sesión, la página se redirigirá a `http://127.0.0.1:8020/?id=<id-sesion>'. La URL real a usar para el inicio de sesión, incluido el realm opcional, se imprime en la terminal cuando se inicia el servidor web.
--pinentry=<nombre>
El programa pinentry a usar. Permite proporcionar la contraseña de forma segura. Por ejemplo: pinentry-gnome3 en Linux o pinentry-mac en macOS.
-o <otp>, --otp=<otp>
Contraseña de un solo uso (One-Time-Password).
--otp-prompt=<mensaje>
Busca el mensaje de solicitud de contraseña OTP comenzando con la cadena <mensaje>.
--otp-delay=<retraso>
Establece el tiempo de espera antes de enviar la contraseña de un solo uso. El tiempo de espera debe especificarse en segundos, donde 0 significa no esperar (este es el valor por defecto).
--no-ftm-push
No usar FTM push si el servidor proporciona la opción. El servidor puede estar configurado para permitir autenticación de dos factores a través de una notificación push a la aplicación móvil. Si se proporciona esta opción, se utilizará en su lugar la autenticación basada en OTP.
--realm=<realm>
Conecta al realm de autenticación especificado. Por defecto está vacío, que suele ser lo que quieres.
--ifname=<interfaz>
Vincula la conexión a la interfaz de red especificada.
--set-routes=<booleano>, --no-routes
Establece si openfortivpn debe intentar configurar rutas IP a través de la VPN cuando el túnel esté activo. Si se usa varias veces, la última prioriza.

--no-routes es lo mismo que --set-routes=0.

--half-internet-routes=<booleano>
Establece si openfortivpn debe añadir dos rutas 0.0.0.0/1 y 128.0.0.0/1 con mayor prioridad en lugar de reemplazar la ruta por defecto.
--set-dns=<booleano>, --no-dns
Establece si openfortivpn debe añadir servidores de nombres DNS en /etc/resolv.conf cuando el túnel esté activo. También se puede recibir un sufijo DNS del peer y añadirlo a /etc/resolv.conf al añadir los servidores de nombres. Se instruirá a resolvconf para que actualice el archivo resolv.conf si está instalado y se activa --use-resolvconf, de lo contrario, openfortivpn antepone sus cambios al contenido existente del archivo resolv.conf. Ten en cuenta que puede haber otros mecanismos para actualizar /etc/resolv.conf, por ejemplo, --pppd-use-peerdns en conjunción con un script ip-up, lo que puede requerir que openfortivpn se llame con --no-dns. --no-dns es lo mismo que --set-dns=0.
--use-resolvconf=<booleano>
Establece si openfortivpn debe usar resolvconf para añadir servidores de nombres DNS en /etc/resolv.conf. Si se establece en falso, se utiliza el mecanismo de respaldo integrado incluso si resolvconf está disponible.
--ca-file=<archivo>
Usa el paquete de certificados especificado en formato PEM en lugar de la tienda del sistema para verificar el certificado del gateway.
--user-cert=<archivo>
Usa el certificado especificado en formato PEM si el servidor requiere autenticación con un certificado.
--user-cert=pkcs11:
Usa al menos la cadena pkcs11: para usar una tarjeta inteligente. Toma la URI PKCS11 completa o parcial (p11tool --list-token-urls)


--user-cert = pkcs11:


--user-cert = pkcs11:token=algunusuario


--user-cert = pkcs11:model=PKCS%2315%20emulated;manufacturer=piv_II;serial=012345678;token=algunusuario

¡Esta función requiere el motor PKCS de OpenSSL!

--user-key=<archivo>
Usa la clave especificada en formato PEM si el servidor requiere autenticación con un certificado.
--pem-passphrase=<contraseña>
Frase de contraseña para la clave PEM.
--use-syslog
Registrar en syslog en lugar de la terminal.
--trusted-cert=<resumen>
Confía en un gateway dado. Si la validación del certificado TLS clásico falla, el certificado del gateway se comparará con este valor. <resumen> es la suma sha256 del certificado X509. El certificado debe estar codificado en formato DER. Esta opción se puede usar varias veces para confiar en varios certificados.
