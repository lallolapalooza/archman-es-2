OPAM-UPDATE(1) Manual de Opam OPAM-UPDATE(1)

NOMBRE

opam-update - Actualizar la lista de paquetes disponibles.

SINOPSIS

opam update [OPCIÓN]… [NOMBRES]…

DESCRIPCIÓN

Actualiza las definiciones de paquetes. Esto obtiene la versión más reciente de los repositorios configurados a través de opam repository, y las fuentes de los paquetes de desarrollo instalados y los paquetes fijados en el switch actual. Para usar las fuentes y definiciones actualizadas, usa opam upgrade.

ARGUMENTOS

NOMBRES
Lista de nombres de repositorios o paquetes de desarrollo para actualizar.

OPCIONES

-a, --all
Actualiza todos los repositorios configurados, no solo lo que está establecido en el switch actual.
--check
Realiza la actualización, luego regresa con el código 0 si hubo cambios externos, 1 si no hubo ninguno. Los repositorios o paquetes de desarrollo que fallaron al actualizar se consideran sin cambios. Con --upgrade, se aplica al paso de actualización: es decir, opam update --upgrade --check se comporta como opam update && opam upgrade --check, regresando 0 si hay actualizaciones disponibles, en lugar de actualizaciones externas.
--depexts
Solicita al gestor de paquetes del sistema que actualice sus bases de datos (saltándose todos los paquetes opam, a menos que también se especifiquen --development o --repositories). Esto generalmente requiere derechos de sudo.
--development
Actualiza paquetes de desarrollo (saltándose repositorios a menos que también se especifique --repositories).
-j JOBS, --jobs=JOBS
Establece el número máximo de trabajos concurrentes a utilizar. El valor predeterminado se calcula a partir del número de núcleos. También puedes establecerlo usando la variable de entorno $OPAMJOBS.
-R, --repositories
Actualiza repositorios (saltándose paquetes de desarrollo a menos que también se especifique --development).
-u, --upgrade
Ejecuta automáticamente opam upgrade después de la actualización.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intenta instalar tantos como sea posible. Ten en cuenta que no todos los resolutores externos pueden soportar esta opción (versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAJOR.MINOR. Previsto para cualquier uso persistente de opam (scripts, publicaciones de blogs, etc.), cualquier versión de opam en la misma serie MAJOR se comportará como para la versión MINOR especificada. El flag no estaba disponible en opam 2.0, así que para seleccionar la CLI 2.0, establece la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o unsafe-yes. Puede especificarse más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIA
Especifica las preferencias del usuario para la resolución de dependencias para esta ejecución. Sobrescribe $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para detalles sobre el lenguaje soportado, y los resolutores externos disponibles, véase http://opam.ocaml.org/doc/External_solvers.html. Una guía general para usar preferencias del resolutor se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBRE_ARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al resolutor en NOMBRE_ARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al resolutor durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Como --debug, pero permite especificar el nivel de depuración (--debug lo establece a 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está establecida (es decir, estás usando una versión de desarrollo), y sale.
--help[=FMT] (predeterminado=auto)
Muestra esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o no esté definida.
--ignore-pin-depends
Ignora los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBRE_ARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%`, será reemplazado por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio que está escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Ten en cuenta que los repositorios deberían definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Usa ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegúrate de que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de completado, por ejemplo. Fallará siempre que se necesite tal operación; también evita esperar bloqueos, omite preguntas interactivas y sobrescribe la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el resolutor CUDF a utilizar para resolver problemas de instalación de paquetes. Este es un resolutor predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentre un error en la definición de un paquete o un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.
--switch=SWITCH
Usa SWITCH como el switch de compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier resolutor externo, y usa el interno (esto requiere que opam se haya compilado con un resolutor interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más verboso. Una -v muestra todos los comandos de paquetes, repite para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra información de la versión.
-w, --working-dir
Siempre que se actualizan paquetes que están vinculados a un directorio local, controlado por versión

NAME

opam-update

SYNOPSIS

opam update [-args…]

DESCRIPTION

This subcommand is a frontend to opam’s repositories sync mechanism.

It uses opam’s internal mechanisms to fetch the latest changes from all configured repositories.

The list of repositories to update can be restricted using arguments.

ARGUMENTS

If arguments are provided, they are interpreted as repository names (or glob patterns), and only the matching repositories are updated.

Example: opam update will update all repositories, while opam update will update only the repository named core.

OPTIONS

See COMMON OPTIONS below.

Additional options:

--all
Update all repositories, even those not currently configured with a repository name, but discovered via git submodules.
--verbose
-v
Show more details about the update process.
--freeze
Update all repositories and then generate opam.freeze files for all installed packages.

COMMON OPTIONS

--help
-h
Show this help message and exit.
--version
-V
Print Opam version and exit.
--color [auto|always|never]
Enable or disable colored output. Default is auto.
--debug
Enable debug logging.
--dev-build
Use debug builds of opam and core libraries.
--dot-conf DIR
Use configuration directory DIR (default: ~/.opam).
--logs-dir DIR
Use directory DIR for logs (default: $OPAM_USER_LOGS_DIR or ~/.opam/log).
--no-source-filter
Don't filter out package sources based on --enabled-sources (opam-filter). Default behaviour is to filter.
--one-core
Only perform operation on the core repositories.
--parallel [N]
Run operations in parallel using N jobs (default: number of CPUs).
--root DIR
Use DIR as the root directory for the opam state.
--solver NAME
Use NAME as the solver (e.g. "builtin-dune", "mccs").
--strict
Activate strict mode, making opam fail on warnings.
--sync
Sync all repositories before proceeding.
--test-build
Use test builds of opam and core libraries.
--user-message
Print user-facing messages only.
--yes
-y
Assume "yes" to all confirmation prompts.

ENVIRONMENT

See CLI VERSION below.

CLI VERSION

The opam command can be invoked in two ways:

  • By calling the command directly, e.g. opam install. This is the default behaviour.
  • By calling it via the opam-bin script, e.g. opam-bin --cli=opam install.

The opam-bin script can be configured to always use a specific opam binary by setting the OPAMCLI environment variable.

For example:

  • export OPAMCLI=/path/to/opam
  • opam-bin --cli=opam-bin --install base

This behaviour can also be controlled via the --cli' option or the OPAMCLI environment variable. --cli' may be specified more than once, where the last instance takes precedence. OPAMCLI is only inspected if --cli' is not given.

EXIT STATUS

As an exception to the following, the exec command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
