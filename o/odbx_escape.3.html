odbx_escape(3)

Paquete: opendbx

Licencias: LGPL

odbx_escape(3) OpenDBX odbx_escape(3)

NOMBRE

odbx_escape - Prepara cadenas para su inclusión en sentencias

SINOPSIS

#include <opendbx/api.h>


int odbx_escape
(odbx_t* handle, const char* from, unsigned long fromlen, char* to, unsigned long* tolen);

DESCRIPCIÓN

odbx_escape() neutraliza caracteres potencialmente peligrosos de la cadena para que pueda ser utilizada como parte de una sentencia. ¡Por razones de seguridad, toda entrada del usuario debe pasar por odbx_escape() para evitar ataques de inyección SQL que pueden tener consecuencias fatales! También es una buena idea escapar nuevamente las cadenas devueltas de campos de la base de datos si desea utilizarlas en una consulta, ya que no permanecen escapadas una vez que se devuelven como parte de un registro.

La mayoría de los backends requieren que el búfer sea más del doble de largo que la cadena de entrada. Para ser precisos, el búfer de salida debe tener un tamaño de 2 * tamaño de entrada + 1 bytes. Después de escapar exitosamente los caracteres en from, se escriben en la memoria proporcionada a través de to y el parámetro de valor/resultado tolen se actualiza a la nueva longitud de to al final.

El primer parámetro, handle, es el objeto de conexión creado y devuelto por odbx_init() que se vuelve inválido tan pronto como se proporciona a odbx_finish().

from debe apuntar a una cadena de caracteres que contenga la cadena que se utilizará como parte de una sentencia. No tiene que ser terminada en nulo, ya que su longitud también se proporciona a través de fromlen. Los backends pueden admitir conjuntos de caracteres de ancho variable como UTF-8, pero esta función no admite el tipo de caracteres anchos (wchar_t), donde cada carácter tiene un tamaño fijo de dos o cuatro bytes.

El valor del parámetro fromlen debe ser la longitud en bytes de la cadena a la que apunta from. Esto también es cierto para conjuntos de caracteres de ancho variable como UTF-8, pero el tipo de caracteres anchos (wchar_t) no es compatible. El carácter de terminación \0 no debe formar parte de fromlen.

La función que llama proporciona un búfer para almacenar la cadena escapada a través de to. En general, la longitud del búfer debe ser más del doble de la longitud de la cadena pasada a través de from para poder almacenar la cadena escapada, incluso si cada carácter tiene que ser escapado.

tolen es un parámetro de valor-resultado que apunta a una variable entera en la función que llama. Debe contener la longitud original del búfer proporcionado a través de to y, si el escape de la cadena en from tuvo éxito, odbx_escape() almacenará la nueva longitud de la cadena escapada en esta variable.

VALOR DE RETORNO

odbx_escape() devuelve ODBX_ERR_SUCCESS, o un código de error cuyo valor es menor que cero si alguna de las operaciones no se pudo completar con éxito. Los códigos de error posibles se enumeran en la sección de errores y se pueden alimentar a odbx_error() y odbx_error_type() para obtener más detalles.

ERRORES

-ODBX_ERR_BACKEND
La biblioteca de base de datos nativa devolvió un error porque no pudo escapar la cadena dada para que fuera adecuada para una sentencia
-ODBX_ERR_PARAM
Uno de los parámetros proporcionados es inválido o es NULL y esto no está permitido en el módulo backend utilizado o en la biblioteca cliente nativa de la base de datos
-ODBX_ERR_SIZE
La longitud de la cadena escapada excede o es probable que exceda el búfer disponible (antes de la versión 1.1.4, el nombre de la etiqueta era ODBX_ERR_TOOLONG, pero el valor sigue siendo el mismo)
