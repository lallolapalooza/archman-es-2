NOMBRE

openstackdocstheme - openstackdocstheme 3.5.0

openstackdocstheme es una extensión de documentación de Sphinx que incluye soporte de temas para proyectos de Open Infrastructure Foundation.

USO DEL TEMA

NOTA:

Antes de usar este tema, asegúrese de que su proyecto puede usar la marca de OpenStack consultando las directrices de marca en https://www.openstack.org/brand.

NOTA:

Algunas de las configuraciones a continuación se incluyen en el archivo generado por Sphinx al inicializar un proyecto, por lo que pueden tener valores que necesiten ser cambiados.
1.
Actualice la lista de requisitos de su proyecto para incluir openstackdocstheme (generalmente en test-requirements.txt).
2.
Si su proyecto utilizó previamente el tema oslosphinx (sin modificar la navegación del encabezado), elimine oslosphinx de su lista de requisitos y luego, en su conf.py, puede eliminar la declaración de importación y la lista de extensiones para oslosphinx.
3.
Una vez hecho esto, debería añadir 'openstackdocstheme' a la lista de extensiones que Sphinx necesita inicializar y configurar el tema:
extensions = [
    # ...
    'openstackdocstheme',
    # ...
]
html_theme = 'openstackdocs'
4.
Establezca las opciones para enlazar con el repositorio git en https://opendev.org y el rastreador de errores.
openstackdocs_repo_name
El prefijo y el nombre del repositorio. Por ejemplo, 'openstack/python-glanceclient'.
openstackdocs_use_storyboard
Establecer en True si se utiliza StoryBoard.

NOTA:

Si utiliza StoryBoard, no establezca las opciones bug_project y bug_tag.
openstackdocs_bug_project
El nombre o ID del proyecto. Para Launchpad, es una cadena como python-glanceclient. Si no se especifica, los enlaces "Report a bug" no se muestran. Esta opción se puede eliminar si se utiliza StoryBoard.
openstackdocs_bug_tag
Etiqueta de error de Launchpad. Si no se especifica, no se establece ninguna etiqueta. El valor predeterminado es vacío. Esta opción se puede eliminar si se utiliza StoryBoard.

Un ejemplo para un proyecto que utiliza Launchpad:

# Opciones de openstackdocstheme
openstackdocs_repo_name = 'openstack/python-glanceclient'
openstackdocs_bug_project = 'python-glanceclient'
openstackdocs_bug_tag = ''

Un ejemplo para un proyecto que utiliza StoryBoard:

# Opciones de openstackdocstheme
openstackdocs_repo_name = 'openstack/infra-manual'
openstackdocs_use_storyboard = true
5.
Elimine las opciones que serán configuradas automáticamente por el tema.
  • project
  • html_last_updated_fmt
6.
Configure las opciones relacionadas con la versión.

Para todo excepto la documentación en las rutas api-guide, api-ref y releasenotes, el tema establecerá automáticamente la versión de su documentación. Este comportamiento se puede configurar manualmente estableciendo la opción openstackdocs_auto_version a True o False.

Si su documentación tiene versión automática, debería eliminar las opciones relacionadas con el versionado, ya que serán reemplazadas.

  • version
  • release
7.
(Opcional) Configure manualmente el nombre del proyecto.

El tema establecerá automáticamente el nombre del proyecto utilizado en su documentación. Puede deshabilitar este comportamiento estableciendo la opción openstackdocs_auto_name a false y configurando la opción project con el nombre que desee utilizar.

8.
(Opcional) Enlace al archivo PDF.

Si también genera un archivo PDF, el tema puede crear un enlace a él. Establezca openstack_pdf_link a True para generar el enlace. Se espera que el archivo se llame doc-<nombrecorto>.pdf y se coloque en el directorio de nivel superior donde <nombre corto> es el openstackdocs_repo_name. Por ejemplo, con:

openstackdocs_repo_name = "openstack/python-glanceclient"

el nombre corto es python-glanceclient y el nombre del archivo será doc-python-glanceclient.pdf. Utilice la variable openstackdocs_pdf_filename para anular el nombre del archivo generado.

Cambiado en la versión 2.2.0: Se introdujeron las opciones de configuración openstack_pdf_link y openstackdocs_pdf_filename.

Cambiado en la versión 2.1.0: Las opciones de configuración repository_name, bug_project, bug_tag y use_storyboard se renombraron a openstackdocs_repo_name, openstackdocs_bug_project, openstackdocs_bug_tag y openstackdocs_use_storyboard, respectivamente. Se proporcionan alias, pero se eliminarán en una futura versión.

Cambiado en la versión 2.1.0: Se añadieron las opciones de configuración openstackdocs_auto_version y openstackdocs_auto_name.

Cambiado en la versión 1.20: En versiones anteriores de openstackdocstheme, era necesario configurar manualmente la opción html_last_updated_fmt para la salida HTML y las opciones latex_engine y latex_elements si se requería salida PDF. Ya no es así, ya que estos atributos ahora se configuran automáticamente.

CONFIGURACIÓN ADICIONAL

Si está utilizando este tema para la documentación de referencia de la API, establezca la navegación de la barra lateral en html_theme_options en el archivo conf.py:

# Para usar el menú desplegable de la barra lateral de Referencia de API,
# descomente el parámetro html_theme_options. La variable del tema,
# sidebar_dropdown, debe establecerse en `api_ref`.
# De lo contrario, la lista de enlaces para la documentación de Usuario y Ops
# aparece en el menú desplegable de la barra lateral.
html_theme_options = {
    # ...
    "sidebar_dropdown": "api_ref",
    "sidebar_mode": "toc",
    # ...
}

Si está utilizando este tema para documentación que desea lanzar basándose en etiquetas git en su repositorio, establezca la opción del menú desplegable de versiones en html_theme_options en el archivo conf.py. Por defecto está establecido en False:

html_theme_options = {
    # ...
    "show_other_versions": "True",
    # ...
}

Si está utilizando este tema para un proyecto con documentación publicada que precede al ciclo de lanzamiento de Mitaka, establezca la versión publicada más antigua en html_theme_options en el archivo conf.py con el nombre de la primera serie con documentación disponible. Por defecto está establecido en None:

html_theme_options = {
    # ...
    "earliest_published_series": "grizzly",
    # ...
}

ADVERTENCIA:

No utilice esto para notas de lanzamiento (release-notes) ya que siempre se publican como un único documento con int

PRETTY-PRINT EXAMPLE

The pretty_print HTML theme option can be used to enable or disable the automatic pretty-printing of the documentation pages. When enabled, it will format the JSON and YAML data on the pages so that it is easier to read. This feature is disabled by default. The theme handles detecting the correct format for you. So far, it handles JSON and YAML. It will also automatically detect and pretty-print the openstack_spec file. This file is expected to be in /etc/openstack/. This works well with external versioning.

DISPLAY BADGE

A badge pointing out the support status of a document is shown now for repositories that have stable/ branches. The badge is not displayed for api-ref, api-guide and releasenotes documents. It can be disabled with the display_badge html theme option:

html_theme_options = { # ... "display_badge": False, # ... }

The TOC on the left contains a global section (to navigate between pages) and a local section (showing page contents). If the TOC is displayed in the text, you might want to disable the global section of the TOC:

html_theme_options = { # ... "display_global_toc_section": False, # ... }

If you are using this theme for something other than docs.openstack.org, you can customize the root title ("OpenStack Docs") that appears in the page title and the left arrow tooltip:

html_theme_options = { # ... "root_title": "OpenStack Governance", # ... }

EXTERNAL LINK HELPER

The configuration option openstack_projects can be used to define custom roles that build links that update automatically when branches are created for each release series. Builds on the master branch link to the latest documentation.

In the conf.py for the source documentation, add:

openstack_projects = ['horizon']

Then in the documentation source, link to a target using syntax like:

:horizon-doc:`Launching Instances with Horizon <user/launch-instances.html>`

NOTE:

Do not use this feature to reference projects that have a different branching policy, for example, only have a master branch.

Here's another example that's python code:

def builder_inited(app):
    theme_dir = os.path.join(os.path.dirname(__file__), 'theme')
    LOG.info('Using openstack theme from %s' % theme_dir)
    # Insert our theme directory at the front of the search path and
    # force the theme setting to use the one in the package. This is
    # done here, instead of in setup(), because conf.py is read after
    # setup() runs, so if the conf contains these values the user
    # values overwrite these. That's not bad for the theme, but it
    # breaks the search path.
    app.config.html_theme_path.insert(0, theme_dir)
    # Set the theme name
    app.config.html_theme = 'openstack'
    # Re-initialize the builder, if it has the method for setting up
    # the templates and theme.
    if hasattr(app.builder, 'init_templates'):
        app.builder.init_templates()

Configure access and security for instances

Before you launch an instance, you should add security group rules to enable users to ping and use SSH to connect to the instance. Security groups are sets of IP filter rules that define networking access and are applied to all instances within a project. To do so, you either add rules to the default security group or add a new security group with rules.

Key pairs are SSH credentials that are injected into an instance when it is launched. To use key pair injection, the image that the instance is based on must contain the cloud-init package. Each project should have at least one key pair. For more information, see import a key pair.

Introduction

OpenStack Compute enables users to launch and manage virtual servers, called instances. An instance is a virtual machine that runs an operating system and applications. You can launch as many instances as you need, with the virtual hardware that you choose, and then connect to them from your computer.

You can also manage Compute resources, such as instances, images, and key pairs.

The dashboard is a web application that enables end users to provision and manage cloud resources. The dashboard is available on the node with the nova-dashboard server role.

For more information about Compute, see OpenStack Compute Administration Guide.

When an instance is created in OpenStack, it is automatically assigned a fixed IP address in the network to which the instance is assigned. This IP address is permanently associated with the instance until the instance is terminated. However, in addition to the fixed IP address, a floating IP address can also be attached to an instance. Unlike fixed IP addresses, floating IP addresses are able to have their associations modified at any time, regardless of the state of the instances involved.

Add a rule to the default security group

This procedure enables SSH and ICMP (ping) access to instances. The rules apply to all instances within a given project, and should be set for every project unless there is a reason to prohibit SSH or ICMP access to the instances.

This procedure can be adjusted as necessary to add additional security group rules to a project, if your cloud requires them.

NOTE:

When adding a rule, you must specify the protocol used with the destination port or source port.
1.
Log in to the dashboard, choose a project, and click Access & Security. The Security Groups tab shows the security groups that are available for this project.
2.
Select the default security group and click Edit Rules.
3.
To allow SSH access, click Add Rule.
4.
In the Add Rule dialog box, enter the following values:
Rule SSH
Remote CIDR
CIDR 0.0.0.0/0

NOTE:

To accept requests from a particular range of IP addresses, specify the IP address block in the CIDR box.
5.
Click Add.

Instances will now have SSH port 22 open for requests from any IP address.

6.
To add an ICMP rule, click Add Rule.
7.
In the Add Rule dialog box, enter the following values:
Rule All ICMP
Direction Ingress
Remote CIDR
CIDR 0.0.0.0/0
8.
Click Add.

Instances will now accept all incoming ICMP packets.

Add a key pair

Create at least one key pair for each project.

1.
Log in to the dashboard, choose a project, and click Access & Security.
2.
Click the Keypairs tab, which shows the key pairs that are available for this project.
3.
Click Create Keypair.
4.
In the Create Keypair dialog box, enter a name for your key pair, and click Create Keypair.
5.
Respond to the prompt to download the key pair.

Import a key pair

1.
Log in to the dashboard, choose a project, and click Access & Security.
2.
Click the Keypairs tab, which shows the key pairs that are available for this project.
3.
Click Import Keypair.
4.
In the Import Keypair dialog box, enter the name of your key pair, copy the public key into the Public Key box, and then click Import Keypair.
5.
Save the *.pem file locally.
6.
To change its permissions so that only you can read and write to the file, run the following command:
$ chmod 0600 yourPrivateKey.pem

NOTE:

If you are using the dashboard from a Windows computer, use PuTTYgen to load the *.pem file and convert and save it as *.ppk. For more information see the WinSCP web page for PuTTYgen.
7.
To make the key pair known to SSH, run the ssh-add command:
$ ssh-add yourPrivateKey.pem

The Compute database registers the public key of the key pair.

The dashboard lists the key pair on the Access & Security tab.

Allocate a floating IP address to an instance

When an instance is created in OpenStack, it is automatically assigned a fixed IP address in the network to which the instance is assigned. This IP address is permanently associated with the instance until the instance is terminated.

However, in addition to the fixed IP address, a floating IP address can also be attached to an instance. Unlike fixed IP addresses, floating IP addresses can have their associations modified at any time, regardless of the state of the instances involved. This procedure details the reservation of a floating IP address from an existing pool of addresses and the association of that address with a specific instance.

1.
Log in to the dashboard, choose a project, and click Access & Security.
2.
Click the Floating IPs tab, which shows the floating IP addresses allocated to instances.
3.
Click Allocate IP to Project.
4.
Choose the pool from which to pick the IP address.
5.
Click Allocate IP.
6.
In the Floating IPs list, click Associate.
7.
In the Manage Floating IP Associations dialog box, choose the following options:
  • The IP Address field is filled automatically, but you can add a new IP address by clicking the + button.
  • In the Ports to be associated field, select a port from the list. The list shows all the instances with their fixed IP addresses.
8.
Click Associate.

NOTE:

To disassociate an IP address from an instance, click the Disassociate button.

To release the floating IP address back into the pool of addresses, click the More button and select the Release Floating IP option.

Configurar el acceso y la seguridad para las instancias

Antes de lanzar una instancia, debe agregar reglas de grupo de seguridad para permitir que los usuarios hagan ping y utilicen SSH para conectarse a la instancia. Los grupos de seguridad son conjuntos de reglas de filtro de IP que definen el acceso de red y se aplican a todas las instancias dentro de un proyecto. Para hacerlo, agrega reglas al grupo de seguridad predeterminado Agregar una regla al grupo de seguridad predeterminado o agrega un nuevo grupo de seguridad con reglas.

Los pares de claves son credenciales SSH que se inyectan en una instancia cuando se lanza. Para usar la inyección de pares de claves, la imagen en la que se basa la instancia debe contener el paquete cloud-init. Cada proyecto debe tener al menos un par de claves. Para obtener más información, consulte la sección Agregar un par de claves.

Si ha generado un par de claves con una herramienta externa, puede importarlo a OpenStack. El par de claves se puede utilizar para múltiples instancias que pertenecen a un proyecto. Para obtener más información, consulte la sección Importar un par de claves.

Cuando se crea una instancia en OpenStack, se le asigna automáticamente una dirección IP fija en la red a la que se asigna la instancia. Esta dirección IP está asociada permanentemente con la instancia hasta que la instancia se termina. Sin embargo, además de la dirección IP fija, también se puede adjuntar una dirección IP flotante a una instancia. A diferencia de las direcciones IP fijas, las direcciones IP flotantes pueden tener sus asociaciones modificadas en cualquier momento, independientemente del estado de las instancias involucradas.

Agregar una regla al grupo de seguridad predeterminado

Este procedimiento permite el acceso SSH e ICMP (ping) a las instancias. Las reglas se aplican a todas las instancias dentro de un proyecto determinado y deben configurarse para cada proyecto, a menos que exista una razón para prohibir el acceso SSH o ICMP a las instancias.

Este procedimiento se puede ajustar según sea necesario para agregar reglas adicionales de grupo de seguridad a un proyecto, si su nube las requiere.

NOTA:

Al agregar una regla, debe especificar el protocolo utilizado con el puerto de destino o el puerto de origen.
1.
Inicie sesión en el panel, seleccione un proyecto y haga clic en Acceso y seguridad. La pestaña Grupos de seguridad muestra los grupos de seguridad que están disponibles para este proyecto.
2.
Seleccione el grupo de seguridad predeterminado y haga clic en Editar reglas.
3.
Para permitir el acceso SSH, haga clic en Agregar regla.
4.
En el cuadro de diálogo Agregar regla, introduzca los siguientes valores:
Regla Remoto

Asignar una dirección IP flotante a una instancia

Cuando se crea una instancia en OpenStack, se le asigna automáticamente una dirección IP fija en la red a la que se asigna la instancia. Esta dirección IP está asociada permanentemente con la instancia hasta que la instancia se termina.

Sin embargo, además de la dirección IP fija, también se puede adjuntar una dirección IP flotante a una instancia. A diferencia de las direcciones IP fijas, las direcciones IP flotantes pueden tener sus asociaciones modificadas en cualquier momento, independientemente del estado de las instancias involucradas. Este procedimiento detalla la reserva de una dirección IP flotante de un grupo existente de direcciones y la asociación de esa dirección con una instancia específica.

1.
Inicie sesión en el panel, seleccione un proyecto y haga clic en Acceso y seguridad.
2.
Haga clic en la pestaña IP flotantes, que muestra las direcciones IP flotantes asignadas a las instancias.
3.
Haga clic en Asignar IP al proyecto.
4.
Elija el grupo del que desea seleccionar la dirección IP.
5.
Haga clic en Asignar IP.
6.
En la lista de IP flotantes, haga clic en Asociar.
7.
En el cuadro de diálogo Gestionar asociaciones de IP flotantes

Configurar direcciones IP flotantes

Una dirección IP flotante es una dirección IP externa que puede asignar a una instancia de cómputo. Esto permite a los usuarios acceder a las instancias de forma remota y que estas se conecten a Internet.

Utilice el procedimiento siguiente para configurar una dirección IP flotante:

El campo Dirección IP se rellena automáticamente, pero puede añadir una nueva dirección IP haciendo clic en el botón +.
2.
En el campo Puertos a asociar, seleccione un puerto de la lista.

La lista muestra todas las instancias con sus direcciones IP fijas.

8.
Haga clic en Asociar.

NOTA:

Crear y gestionar bases de datos

El servicio de Bases de Datos proporciona funcionalidad de aprovisionamiento en la nube escalable y fiable para motores de bases de datos relacionales y no relacionales. Los usuarios pueden utilizar rápida y fácilmente las características de bases de datos sin la carga de realizar tareas administrativas complejas.

Crear una instancia de base de datos

Requisitos previos. Antes de crear una instancia de base de datos, debe configurar un almacén de datos predeterminado y asegurarse de que tiene un tipo (flavor) apropiado para el tipo de instancia de base de datos que desea.

1.
Configurar un almacén de datos predeterminado.

Dado que el panel de control no le permite elegir un almacén de datos específico para usar con una instancia, debe configurar un almacén de datos predeterminado. El panel de control utilizará entonces el almacén de datos predeterminado para crear la instancia.

1.
Añada la siguiente línea a /etc/trove/trove.conf: 
default_datastore = NOMBRE_ALMACEN_DATOS

Reemplace ``NOMBRE_ALMACEN_DATOS`` con el nombre que el usuario administrador estableció al emitir el comando trove-manage para crear el almacén de datos. Puede utilizar el comando trove datastore-list para mostrar los almacenes de datos disponibles en su entorno.

Por ejemplo, si el nombre de su almacén de datos MySQL está configurado como mysql, su entrada se vería así:

default_datastore = mysql
2.
Reinicie los servicios de Bases de Datos en el nodo controlador: 
# service trove-api restart
# service trove-taskmanager restart
# service trove-conductor restart
2.
Verificar tipo (flavor).

Asegúrese de que existe un tipo (flavor) apropiado para el tipo de instancia de base de datos que desea.

Crear instancia de base de datos. Una vez que haya configurado un almacén de datos predeterminado y haya verificado que tiene un tipo (flavor) apropiado, puede crear una instancia de base de datos.

1.
Inicie sesión en el panel de control, elija un proyecto y haga clic en Bases de datos.
2.
Haga clic en Instancias de bases de datos. Esto lista las instancias que ya existen en su entorno.
3.
Haga clic en Lanzar Instancia.
4.
En el cuadro de diálogo Lanzar Base de Datos, especifique los siguientes valores.

Detalles

Nombre de la base de datos: Especifique un nombre para la instancia de base de datos.

Tipo (Flavor): Seleccione un tipo (flavor) apropiado para la instancia.

Tamaño del Volumen: Seleccione un tamaño de volumen. El tamaño del volumen se expresa en GB.

Inicializar Bases de Datos: Base de Datos Inicial

Opcionalmente, proporcione una lista separada por comas de bases de datos para crear, por ejemplo:

basedatos1, basedatos2, basedatos3

Usuario Administrador Inicial: Cree un usuario administrador inicial. Este usuario tendrá acceso a todas las bases de datos que cree.

Contraseña: Especifique una contraseña asociada al usuario administrador inicial que acaba de nombrar.

Host: Opcionalmente, permita que el usuario se conecte solo desde este host. Si no especifica un host, este usuario podrá conectarse desde cualquier lugar.

5.
Haga clic en el botón Lanzar. La nueva instancia de base de datos aparece en la lista de bases de datos.

Hacer copia de seguridad y restaurar una base de datos

Puede utilizar los servicios de Bases de Datos para hacer una copia de seguridad de una base de datos y almacenar el artefacto de copia de seguridad en el módulo de Almacenamiento de Objetos. Más tarde, si la base de datos original está dañada, puede utilizar el artefacto de copia de seguridad para restaurar la base de datos. El proceso de restauración crea una instancia de base de datos.

Este ejemplo le muestra cómo hacer una copia de seguridad y restaurar una base de datos MySQL.

Para hacer copia de seguridad de la instancia de base de datos

1.
Inicie sesión en el panel de control, elija un proyecto y haga clic en Bases de datos.
2.
Haga clic en Instancias de bases de datos. Esto muestra las instancias existentes en su sistema.
3.
Haga clic en Crear Copia de Seguridad.
4.
En el cuadro de diálogo Copia de Seguridad de Base de Datos, especifique los siguientes valores:

Nombre

Especifique un nombre para la copia de seguridad.

Instancia de Base de Datos

Seleccione la instancia de la que desea hacer copia de seguridad.

5.
Haga clic en Copia de Seguridad. La nueva copia de seguridad aparece en la lista de copias de seguridad.

Para restaurar una instancia de base de datos

Ahora suponga que su instancia de base de datos original está dañada y necesita restaurarla. Realiza la restauración utilizando su copia de seguridad para crear una nueva instancia de base de datos.

1.
Inicie sesión en el panel de control, elija un proyecto y haga clic en Bases de datos.
2.
Haga clic en Copias de Seguridad de Bases de Datos. Esto lista las copias de seguridad disponibles.
3.
Marque la copia de seguridad que desea utilizar y haga clic en Restaurar Copia de Seguridad.
4.
En el cuadro de diálogo Lanzar Base de Datos, especifique los valores que desea para la nueva instancia de base de datos.
5.
Haga clic en la pestaña Restaurar Desde Base de Datos y asegúrese de que esta nueva instancia se basa en la copia de seguridad correcta.
6.
Haga clic en Lanzar.

La nueva instancia aparece en la lista de instancias de bases de datos.

Crear y gestionar redes

El servicio de Redes de OpenStack proporciona un sistema escalable para gestionar la conectividad de red dentro de una implementación de nube de OpenStack. Puede reaccionar fácil y rápidamente a las necesidades cambiantes de la red (por ejemplo, crear y asignar nuevas direcciones IP).

La gestión de redes en OpenStack es compleja. Esta sección proporciona las instrucciones básicas para crear una red y un router. Para obtener información detallada sobre la gestión de redes, consulte la Guía del Administrador de OpenStack.

Crear una red

1.
Inicie sesión en el panel de control, elija un proyecto y haga clic en Redes.
2.
Haga clic en Crear Red.
3.
En el cuadro de diálogo Crear Red, especifique los siguientes valores.

Pestaña Red

Nombre de la Red: Especifique un nombre para identificar la red.

Pestaña Subred

Crear Subred: Seleccione esta casilla para crear una subred

No tiene que especificar una subred al crear una red, pero si no especifica una subred, cualquier instancia adjunta recibe un estado de Error.

Nombre de la Subred: Especifique un nombre para la subred.

Dirección de Red: Especifique la dirección IP para la subred.

Versión IP: Seleccione IPv4 o IPv6.

IP de Puerta de Enlace: Especifique una dirección IP para una puerta de enlace específica. Este parámetro es opcional.

Desactivar Puerta de Enlace: Seleccione esta casilla para desactivar una dirección IP de puerta de enlace.

Pestaña Detalle de Subred

Activar DHCP: Seleccione esta casilla para activar DHCP.

Pools de Asignación Especifique pools de direcciones IP.

Servidores DNS: Especifique un nombre para el servidor DNS.

Rutas de Host: Especifique la dirección IP de las rutas de host.

4.
Haga clic en Crear.

El panel de control muestra la red en la pestaña Redes.

Crear un router

1.
Inicie sesión en el panel de control, elija un proyecto y haga clic en Routers.
2.
Haga clic en Crear Router.
3.
En el cuadro de diálogo Crear Router, especifique un nombre para el router y haga clic en Crear Router.

El nuevo router se muestra ahora en la pestaña Routers.

4.
Haga clic en el botón Establecer Puerta de Enlace del nuevo router.
5.
En el campo Red Externa, especifique la red a la que se conectará el router y, a continuación, haga clic en Establecer Puerta de Enlace.

Conectar un router

1.
Para conectar una red privada al router recién creado, en la pestaña Routers, haga clic en el nombre del router.
2.
En la página Detalles del Router, haga clic en Añadir Interfaz.
3.
En el cuadro de diálogo Añadir Interfaz, seleccione una Subred.
4.
Opcionalmente, en el cuadro de diálogo Añadir Interfaz, establezca una Dirección IP para la interfaz del router para la subred seleccionada.

Si elige no establecer el valor de la Dirección IP, por defecto OpenStack Networking utilizará la primera dirección IP del host en la subred.

Los campos Nombre del Router e ID del Router se actualizan automáticamente.

5.
Haga clic en Añadir Interfaz.

Ha creado el router con éxito. Puede ver la nueva topología desde la pestaña Topología de Red.
