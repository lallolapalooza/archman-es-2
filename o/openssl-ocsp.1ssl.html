DESCRIPCIÓN

El Protocolo de Estado de Certificado en Línea (OCSP) permite a las aplicaciones determinar el estado (de revocación) de un certificado identificado (RFC 2560).

Este comando realiza muchas tareas comunes de OCSP. Se puede utilizar para imprimir solicitudes y respuestas, crear solicitudes y enviar consultas a un responder OCSP, y comportarse como un mini servidor OCSP en sí mismo.

OPCIONES

Este comando opera como cliente o servidor. Las opciones se describen a continuación, divididas en esos dos modos.

Opciones del Cliente OCSP

-help
Imprime un mensaje de uso.
-out nombrearchivo
especifica el nombre del archivo de salida, por defecto es la salida estándar.
-issuer archivo
Este especifica el certificado del emisor actual. La entrada puede estar en formato PEM, DER o PKCS#12.

Esta opción se puede usar varias veces. Esta opción DEBE aparecer antes que cualquier opción -cert.

-cert archivo
Agrega el certificado archivo a la solicitud. La entrada puede estar en formato PEM, DER o PKCS#12.

Esta opción se puede usar varias veces. El certificado del emisor se toma de la opción -issuer anterior, o se produce un error si no se especifica ningún certificado emisor.

-no_certs
No incluir ningún certificado en la solicitud firmada.
-serial num
Igual que la opción -cert excepto que el certificado con el número de serie num se agrega a la solicitud. El número de serie se interpreta como un entero decimal a menos que esté precedido por "0x". También se pueden especificar enteros negativos anteponiendo el valor un signo "-".
-signer archivo, -signkey archivo
Firma la solicitud OCSP utilizando el certificado especificado en la opción -signer y la clave privada especificada por la opción -signkey. La entrada puede estar en formato PEM, DER o PKCS#12.

Si la opción -signkey no está presente, la clave privada se lee del mismo archivo que el certificado. Si no se especifica ninguna de las opciones, la solicitud OCSP no se firma.

-sign_other archivo
Certificados adicionales para incluir en la solicitud firmada. La entrada puede estar en formato PEM, DER o PKCS#12.
-nonce, -no_nonce
Agrega una extensión nonce OCSP a una solicitud o deshabilita la adición de nonce OCSP. Normalmente, si se ingresa una solicitud OCSP usando la opción -reqin, no se agrega ningún nonce: usar la opción -nonce forzará la adición de un nonce. Si se está creando una solicitud OCSP (usando las opciones -cert y -serial), se agrega automáticamente un nonce; especificar -no_nonce anula esto.
-req_text, -resp_text, -text
Imprime la forma de texto de la solicitud OCSP, la respuesta o ambas, respectivamente.
-reqout archivo, -respout nombrearchivo
Escribe la solicitud OCSP o la respuesta codificada en DER en nombrearchivo. El nombre del archivo de salida puede ser el mismo que el nombre del archivo de entrada, lo que lleva a reemplazar el contenido del archivo. Tenga en cuenta que la E/S de archivos no es atómica. El archivo de salida se trunca y luego se escribe.
-reqin archivo, -respin nombrearchivo
Lee el archivo de solicitud o respuesta OCSP de archivo. Estas opciones se ignoran si la creación de la solicitud o respuesta OCSP está implícita por otras opciones (por ejemplo, con las opciones -serial, -cert y -host).
-url url_del_responder
Especifica el host del responder y opcionalmente el puerto y la ruta a través de una URL. Se pueden especificar URL HTTP y HTTPS (SSL/TLS). Los componentes opcionales de userinfo y fragmento se ignoran. Cualquier componente de consulta dado se maneja como parte del componente de ruta. Para obtener detalles, consulte las opciones -host y -path descritas a continuación.
-host host:puerto, -path rutaarchivo
Si la opción -host está presente, la solicitud OCSP se envía al host host en el puerto puerto. El host puede ser un nombre de dominio o una dirección IP (v4 o v6), como 127.0.0.1 o "[::1]" para localhost. Si es una dirección IPv6, debe estar encerrada entre "[" y "]".

La opción -path especifica la ruta del archivo HTTP a usar o "/" por defecto. Esto es equivalente a especificar -url con el esquema http:// y el host, puerto y rutaarchivo opcionales dados.

-proxy [http[s]://][userinfo@]host[:port][/path][?query][#fragment]

Opciones del Servidor OCSP

-index archivo
El archivo de índice del certificado. Contiene el estado de revocación de los certificados. Este archivo se utiliza para responder solicitudes OCSP.
-CA archivo
El certificado de la Autoridad de Certificación (CA) para firmar las respuestas OCSP. Este debe ser un certificado de emisor válido.
-rsigner archivo
El certificado utilizado para firmar las respuestas OCSP. Por defecto, se utiliza el certificado especificado por la opción -CA.
-rkey archivo
La clave privada para firmar las respuestas OCSP. Por defecto, se utiliza la clave privada asociada con el certificado especificado por la opción -rsigner.
-passin arg
El método para obtener la contraseña de la clave privada. Consulte la sección PASS PHRASE ARGUMENTS en openssl(1) para obtener más detalles.
-rother archivo
Certificados adicionales para incluir en la respuesta OCSP firmada. Esto puede ser necesario si el certificado firmante no está incluido en la ruta de confianza del solicitante.
-rsigopt nm:v
Opciones de firma para la respuesta OCSP. El formato es nombre:valor. Por ejemplo, para añadir un nonce, se usaría -rsigopt nonce:-nonce.
-rmd resumen
El algoritmo de resumen a utilizar para firmar la respuesta OCSP. Los valores comunes incluyen md5, sha1, sha256, etc.
-badsig
Genera una respuesta OCSP con una firma inválida. Útil para pruebas.
-resp_no_certs
No incluir certificados en la respuesta OCSP.
-nmin n
El número de minutos que la respuesta OCSP es válida a partir de la hora de emisión. El valor por defecto es 0.
-ndays n
El número de días que la respuesta OCSP es válida a partir de la hora de emisión. El valor por defecto es 30.
-resp_key_id
Utiliza el ID de clave del emisor para identificar el certificado firmante en la respuesta OCSP.
-nrequest n
El número máximo de solicitudes OCSP que se procesarán antes de que el servidor se detenga.
-multi conteo-procesos
Inicia el servidor OCSP con el número especificado de procesos hijos para manejar las solicitudes concurrentes.
-rcid resumen
Especifica el algoritmo de resumen para generar el ID de clave del emisor.
-resumen
Especifica el algoritmo de resumen que se utilizará para firmar las respuestas OCSP. Los algoritmos comunes son: md5, sha1, sha256, sha384, sha512.
-CAfile archivo
Un archivo que contiene certificados de CA de confianza. Se utiliza para verificar las cadenas de certificados.
-no-CAfile
No utilizar ningún archivo de certificados de CA.
-CApath dir
Un directorio que contiene certificados de CA de confianza, indexados por hash de asunto.
-no-CApath
No utilizar ningún directorio de certificados de CA.
-CAstore uri
Una URI que apunta a un almacén de certificados de confianza.
-no-CAstore
No utilizar ningún almacén de certificados de confianza.
-allow_proxy_certs
Permitir el uso de certificados de proxy en las respuestas OCSP.
-attime marca de tiempo
Verifica el estado del certificado en la marca de tiempo dada. La marca de tiempo debe estar en formato de cadena que pueda ser interpretada por la función X509_cmp_time.
-no_check_time
No verificar las marcas de tiempo de validez de los certificados.
-check_ss_sig
Comprobar la firma del certificado del servidor OCSP.
-crl_check
Comprobar la CRL (Lista de Revocación de Certificados) del certificado del servidor OCSP.
-crl_check_all
Comprobar todas las CRL de la cadena de certificados del servidor OCSP.
-explicit_policy
Requiere que la política explícita esté presente en la cadena de certificados.
-extended_crl
Utilizar CRL extendidas si están disponibles.
-ignore_critical
Ignorar las extensiones críticas en los certificados y CRL.
-inhibit_any
Inhibir el uso de políticas Any-Policy.
-inhibit_map
Inhibir el mapeo de políticas.
-partial_chain
Permitir cadenas de certificados parciales.
-policy arg
Especifica una política de certificación permitida. El formato es OID[:*]
-policy_check
Habilitar la verificación de políticas.
-policy_print
Imprimir las políticas de certificación encontradas.
-purpose propósito
Especifica el propósito del certificado que se está verificando (por ejemplo, sslCA, sslServer, etc.).
-suiteB_128
Restringe el uso a Suite B de 128 bits.
-suiteB_128_only
Restringe el uso exclusivamente a Suite B de 128 bits.
-suiteB_192
Restringe el uso a Suite B de 192 bits.
-trusted_first
Intenta usar primero certificados de confianza al construir la cadena.
-no_alt_chains
No permite cadenas alternativas.
-use_deltas
Utiliza CRL delta si están disponibles.
-auth_level num
Establece el nivel de autenticación para las respuestas OCSP.
-verify_depth num
Establece la profundidad máxima de verificación de la cadena de certificados.
-verify_email email
Verifica que la dirección de correo electrónico del sujeto del certificado coincida con la proporcionada.
-verify_hostname nombrehost
Verifica que el nombre de host del certificado coincida con el proporcionado.
-verify_ip ip
Verifica que la dirección IP del certificado coincida con la proporcionada.
-verify_name nombre
Verifica que el nombre del certificado coincida con el proporcionado.
-x509_strict
Realiza verificaciones X509 más estrictas.
-issuer_checks
Realiza comprobaciones adicionales sobre el certificado emisor.
-provider nombre
Especifica un proveedor de FIPS o de otro tipo para utilizar.
-provider-path ruta
Especifica una ruta de búsqueda para los proveedores.
-provparam [nombre:]key=valor
Parámetros para pasar a un proveedor.
-propquery propq
Consulta de propiedades para seleccionar certificados o claves.

DESCRIPCIÓN

El comando openssl ocsp puede actuar como cliente OCSP o como servidor OCSP.

Opciones de Cliente OCSP

-host host:port
Nombre de host y puerto del servidor OCSP. Si el puerto no se especifica, se utiliza el puerto 80 por defecto. Si el esquema es "https", se utiliza el puerto 443 por defecto. Si la dirección IP es una dirección IPv6, debe ir entre corchetes "[" y "]". El puerto del proxy toma el valor por defecto de 80 o 443 si el esquema es "https"; aparte de eso, se ignoran el prefijo opcional "http://" o "https://", así como cualquier componente de userinfo, ruta, consulta y fragmento. Por defecto, se utiliza la variable de entorno "http_proxy" si está definida, de lo contrario "HTTP_PROXY" si no se utiliza TLS, de lo contrario "https_proxy" si está definida, de lo contrario "HTTPS_PROXY".
-paccept
Acepta cualquier certificado de firmante OCSP. Esto desactiva la verificación del certificado del firmante.
-reqin file
Lee las solicitudes OCSP del archivo especificado. Si el archivo contiene varias solicitudes, se envían todas en un único mensaje OCSP. Si el valor es "FD", se leen de la entrada estándar.
-sign_hash alg
El algoritmo de hash a utilizar para las solicitudes OCSP. El valor por defecto es SHA1.
-out file
Escribe la respuesta OCSP en el archivo especificado. Si no se especifica, la salida se escribe en la salida estándar.
-text
Imprime la respuesta OCSP en formato de texto.
-header nombre=valor
Añade la cabecera nombre con el valor especificado a la solicitud OCSP que se envía al respondedor. Esto se puede repetir.
-timeout segundos
Tiempo de espera de conexión al respondedor OCSP en segundos. En sistemas POSIX, cuando se ejecuta como respondedor OCSP, esta opción también limita el tiempo que el respondedor está dispuesto a esperar la solicitud del cliente. Este tiempo se mide desde el momento en que el respondedor acepta la conexión hasta que se recibe la solicitud completa.
-verify_other archivo
Archivo o URI que contiene certificados adicionales para buscar al intentar localizar el certificado del firmante de la respuesta OCSP. Algunos respondedores omiten el certificado real del firmante de la respuesta: esta opción se puede utilizar para proporcionar el certificado necesario en dichos casos. La entrada puede estar en formato PEM, DER o PKCS#12.
-trust_other
Los certificados especificados por la opción -verify_other deben ser explícitamente confiables y no se realizarán comprobaciones adicionales sobre ellos. Esto es útil cuando la cadena completa de certificados del respondedor no está disponible o cuando confiar en una CA raíz no es apropiado.
-VAfile archivo
Archivo o URI que contiene certificados de respondedor explícitamente confiables. Equivalente a las opciones -verify_other y -trust_other. La entrada puede estar en formato PEM, DER o PKCS#12.
-noverify
No intente verificar la firma de la respuesta OCSP ni los valores nonce. Normalmente, esta opción solo se utilizará para depuración, ya que deshabilita toda la verificación del certificado del respondedor.
-no_intern
Ignore los certificados contenidos en la respuesta OCSP al buscar el certificado del firmante. Con esta opción, el certificado del firmante debe ser especificado con las opciones -verify_other o -VAfile.
-no_signature_verify
No verifique la firma de la respuesta OCSP. Dado que esta opción tolera firmas inválidas en las respuestas OCSP, normalmente solo se utilizará con fines de prueba.
-no_cert_verify
No verifique en absoluto el certificado del firmante de la respuesta OCSP. Dado que esta opción permite que la respuesta OCSP sea firmada por cualquier certificado, solo debe usarse con fines de prueba.
-no_chain
No utilice certificados en la respuesta como certificados de CA adicionales no confiables.
-no_explicit
No confíe explícitamente en la CA raíz si está configurada para ser confiable para la firma OCSP.
-no_cert_checks
No realice ninguna comprobación adicional en el certificado del firmante de la respuesta OCSP. Es decir, no realice ninguna comprobación para ver si el certificado del firmante está autorizado para proporcionar la información de estado necesaria: como resultado, esta opción solo debe usarse con fines de prueba.
-validity_period nsec, -status_age age
Estas opciones especifican el rango de tiempos, en segundos, que se tolerarán en una respuesta OCSP. Cada respuesta de estado de certificado incluye un tiempo notBefore y un tiempo opcional notAfter. El tiempo actual debe caer entre estos dos valores, pero el intervalo entre los dos tiempos puede ser de solo unos pocos segundos. En la práctica, los relojes del respondedor OCSP y de los clientes pueden no estar sincronizados con precisión, por lo que dicha comprobación podría fallar. Para evitar esto, la opción -validity_period se puede utilizar para especificar un rango de error aceptable en segundos; el valor por defecto es de 5 minutos.

Si el tiempo notAfter se omite de una respuesta, esto significa que la nueva información de estado está disponible inmediatamente. En este caso, se comprueba la antigüedad del campo notBefore para ver si no es mayor que age segundos. Por defecto, esta comprobación adicional no se realiza.

-rcid digest
Esta opción establece el algoritmo de digest que se utilizará para la identificación del certificado en la respuesta OCSP. Se puede utilizar cualquier digest compatible con el comando openssl-dgst(1). El valor por defecto es el mismo algoritmo de digest que se utiliza en la solicitud.
-digest
Esta opción establece el algoritmo de digest que se utilizará para la identificación del certificado en la solicitud OCSP. Se puede utilizar cualquier digest compatible con el comando dgst de OpenSSL. El valor por defecto es SHA-1. Esta opción puede usarse varias veces para especificar el digest utilizado por los identificadores de certificados subsiguientes.

openssl-ocsp - OCSP client and server

DESCRIPTION

The OCSP utility is a tool for sending and receiving OCSP (Online Certificate Status Protocol) requests. It can act as either an OCSP client or an OCSP responder.

When acting as an OCSP client, it sends a request for the status of a certificate, and verifies the response received. It can also be used to send OCSP requests to a specified URL, or to an OCSP responder service specified in a certificate's Authority Information Access (AIA) extension.

When acting as an OCSP responder, it listens for incoming OCSP requests (usually via HTTP), looks up certificate status information, signs and returns an OCSP response.

The command can also be used to generate OCSP requests and responses.

Most options are intended for use with specific modes of operation (client or responder). If an option is used in the wrong mode, it will be ignored, or an error will be reported.

OCSP CLIENT OPTIONS

-cert cert_file
The certificate to query the status of. This option can be repeated to query multiple certificates.
-issuer issuer_file
The issuer certificate of the certificate being queried. This option is required if the issuer certificate is not present in the certificate being queried. This option can be repeated.
-serial number
The serial number of the certificate to query. This is an alternative to the -cert option. This option can be repeated.

OCSP RESPONSE VERIFICATION

OCSP Response follows the rules specified in RFC2560.

Initially the OCSP responder certificate is located and the signature on the OCSP request checked using the responder certificate's public key.

Then a normal certificate verify is performed on the OCSP responder certificate building up a certificate chain in the process. The locations of the trusted certificates used to build the chain can be specified by the -CAfile, -CApath or -CAstore options or they will be looked for in the standard OpenSSL certificates directory.

If the initial verify fails then the OCSP verify process halts with an error.

Otherwise the issuing CA certificate in the request is compared to the OCSP responder certificate: if there is a match then the OCSP verify succeeds.

Otherwise the OCSP responder certificate's CA is checked against the issuing CA certificate in the request. If there is a match and the OCSPSigning extended key usage is present in the OCSP responder certificate then the OCSP verify succeeds.

Otherwise, if -no_explicit is not set the root CA of the OCSP responders CA is checked to see if it is trusted for OCSP signing. If it is the OCSP verify succeeds.

If none of these checks is successful then the OCSP verify fails.

What this effectively means if that if the OCSP responder certificate is authorised directly by the CA it is issuing revocation information about (and it is correctly configured) then verification will succeed.

If the OCSP responder is a "global responder" which can give details about multiple CAs and has its own separate certificate chain then its root CA can be trusted for OCSP signing. For example:

openssl x509 -in ocspCA.pem -addtrust OCSPSigning -out trustedCA.pem

Alternatively the responder certificate itself can be explicitly trusted with the -VAfile option.

NOTES

As noted, most of the verify options are for testing or debugging purposes. Normally only the -CApath, -CAfile, -CAstore and (if the responder is a 'global VA') -VAfile options need to be used.

The OCSP server is only useful for test and demonstration purposes: it is not really usable as a full OCSP responder. It contains only a very simple HTTP request handling and can only handle the POST form of OCSP queries. It also handles requests serially meaning it cannot respond to new requests until it has processed the current one. The text index file format of revocation is also inefficient for large quantities of revocation data.

It is possible to run this command in responder mode via a CGI script using the -reqin and -respout options.

EXAMPLES

Create an OCSP request and write it to a file:

openssl ocsp -issuer issuer.pem -cert c1.pem -cert c2.pem -reqout req.der

Send a query to an OCSP responder with URL http://ocsp.myhost.com/ save the response to a file, print it out in text form, and verify the response:

openssl ocsp -issuer issuer.pem -cert c1.pem -cert c2.pem \
    -url http://ocsp.myhost.com/ -resp_text -respout resp.der

Read in an OCSP response and print out text form:

openssl ocsp -respin resp.der -text -noverify

OCSP server on port 8888 using a standard ca configuration, and a separate responder certificate. All requests and responses are printed to a file.

openssl ocsp -index demoCA/index.txt -port 8888 -rsigner rcert.pem -CA demoCA/cacert.pem
       -text -out log.txt

As above but exit after processing one request:

openssl ocsp -index demoCA/index.txt -port 8888 -rsigner rcert.pem -CA demoCA/cacert.pem
    -nrequest 1

Query status information using an internally generated request:

openssl ocsp -index demoCA/index.txt -rsigner rcert.pem -CA demoCA/cacert.pem
    -issuer demoCA/cacert.pem -serial 1

Query status information using request read from a file, and write the response to a second file.

openssl ocsp -index demoCA/index.txt -rsigner rcert.pem -CA demoCA/cacert.pem
    -reqin req.der -respout resp.der
