opendmarc(8) Manual del Administrador del Sistema opendmarc(8)

NOMBRE

opendmarc - Filtro de política DMARC para MTAs

SINOPSIS

opendmarc [-A] [-c archivo_config] [-f] [-l] [-n] [-p espec_socket] [-P archivo_pid] [-t archivo[,archivo[,...]]] [-u usuario[:grupo]] [-v] [-V]

DESCRIPCIÓN

opendmarc implementa la especificación propuesta de DMARC para la autenticación de mensajes y el informe del tráfico observado.

opendmarc utiliza la interfaz milter, distribuida originalmente como parte de la versión 8.11 de sendmail(8), para proporcionar un servicio de procesamiento DMARC para el correo que transita por un MTA compatible con milter.

La mayoría, si no todas, de las opciones de línea de comandos que se enumeran a continuación también se pueden configurar mediante un archivo de configuración. Consulte la opción -c para obtener más detalles.

opendmarc se basa en la adición de campos Authentication-Results por parte de filtros anteriores en hosts de confianza para recopilar información para el algoritmo DMARC. No realiza evaluaciones DKIM o SPF por sí mismo.

OPCIONES

-A
Reiniciar automáticamente en caso de fallos. Úselo con precaución; si el filtro falla instantáneamente después de iniciarse, esto puede causar un bucle fork(2) estrecho. Esto puede mitigarse utilizando algunos valores en el archivo de configuración para limitar el reinicio. Consulte opendmarc.conf(5).
-c archivo_config
Lee el archivo de configuración especificado. Consulte la página del manual de opendmarc.conf(5) para obtener más detalles. Los valores en el archivo de configuración se anulan cuando sus equivalentes se proporcionan en la línea de comandos hasta que ocurra una recarga de configuración. La sección OPERACIÓN describe cómo se activan las recargas. El valor predeterminado es leer un archivo de configuración de /etc/opendmarc/opendmarc.conf si existe, o de lo contrario, aplicar valores predeterminados a todos los valores.
-f
Normalmente, opendmarc crea un proceso hijo y sale inmediatamente, dejando el servicio ejecutándose en segundo plano. Esta bandera suprime este comportamiento para que se ejecute en primer plano.
-l
Registra cualquier actividad interesante a través de llamadas a syslog(3).
-n
Analiza el archivo de configuración y los argumentos de la línea de comandos, informando de cualquier error encontrado, y luego sale. El valor de salida será 0 si el filtro se iniciara sin problemas, o no cero en caso contrario.
-p espec_socket
Especifica el socket que debe establecer el filtro para recibir conexiones de sendmail(8) para proporcionar servicio. espec_socket tiene una de las dos formas: local:ruta que crea un socket de dominio UNIX en la ruta especificada, o inet:puerto[@host] o inet6:puerto[@host] que crea un socket TCP en el puerto especificado dentro de la familia de protocolos especificada. Si el host no se proporciona como un nombre de host o una dirección IP, el socket escuchará en todas las interfaces. Si no se especifica ningún tipo de socket, se asume local, lo que significa que el parámetro se interpreta como una ruta en la que se debe crear el socket. Si se utiliza una dirección IP, debe estar entre corchetes. Este parámetro es obligatorio.
-P archivo_pid
Especifica un archivo en el que el filtro debe escribir su ID de proceso al arrancar.
-t archivo[,archivo[,...]]
Lee mensajes de correo electrónico de los archivos especificados y los procesa como si hubieran sido recibidos por el filtro. El servicio no se inicia y las acciones que normalmente se envían de vuelta al MTA se imprimirán en la salida estándar.
-u usuario[:grupo]
Intenta convertirse en el usuario especificado antes de comenzar las operaciones. El proceso recibirá todos los grupos y el ID de grupo primario del usuario nombrado a menos que se especifique un grupo alternativo. Consulte la sección PERMISOS DE ARCHIVO para obtener más información.
-v
Aumenta la salida detallada durante el modo de prueba (consulte -t anterior). Puede especificarse varias veces para solicitar cantidades crecientes de salida.
-V
Imprime el número de versión y los algoritmos de canonización y firma admitidos, y luego sale sin hacer nada más.

SEÑALES

Al recibir SIGUSR1, si el filtro se inició con un archivo de configuración, este se volverá a leer y se utilizarán los nuevos valores. Tenga en cuenta que las anulaciones de línea de comandos proporcionadas al inicio se perderán cuando esto suceda. Además, los siguientes valores del archivo de configuración (y sus elementos correspondientes en la línea de comandos, si los hay) no se recargan a través de este proceso: AutoRestart (-A), AutoRestartCount, AutoRestartRate, Background, MilterDebug, PidFile (-P), Socket (-p), UMask, UserID (-u). El filtro no comprueba automáticamente los cambios en el archivo de configuración ni los recarga.
