NOMBRE

stat, fstat, lstat, fstatat - obtener estado del archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);

DESCRIPCIÓN

Estas funciones devuelven información sobre un archivo, en el búfer apuntado por statbuf. No se requieren permisos sobre el archivo en sí, pero —en el caso de stat(), fstatat() y lstat()— se requiere permiso de ejecución (búsqueda) en todos los directorios de path que conducen al archivo.

stat() y fstatat() recuperan información sobre el archivo apuntado por path; las diferencias para fstatat() se describen a continuación.

lstat() es idéntico a stat(), excepto que si path es un enlace simbólico, devuelve información sobre el propio enlace, no sobre el archivo al que se refiere el enlace.

fstat() es idéntico a stat(), excepto que el archivo sobre el que se debe recuperar información se especifica mediante el descriptor de archivo fd.

La estructura stat

Todas estas llamadas al sistema devuelven una estructura stat (ver stat(3type)).

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura stat pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si st_mode o st_uid son modificados por otro proceso llamando a chmod(2) o chown(2), stat() podría devolver el st_mode antiguo junto con el nuevo st_uid, o el st_uid antiguo junto con el nuevo st_mode.

fstatat()

La llamada al sistema fstatat() es una interfaz más general para acceder a la información del archivo que aún puede proporcionar exactamente el comportamiento de cada una de stat(), lstat() y fstat().

Si path es relativo, se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como hacen stat() y lstat() para un nombre de ruta relativo).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso que llama (como stat() y lstat()).

Si path es absoluto, dirfd se ignora.

flags puede ser 0, o incluir una o más de las siguientes banderas ORed:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si path es una cadena vacía (o NULL, desde Linux 6.11), opera sobre el archivo al que se refiere dirfd (que podría haberse obtenido usando la bandera O_PATH de open(2)). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio, y el comportamiento de fstatat() es similar al de fstat(). Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; define _GNU_SOURCE para obtener su definición.
AT_NO_AUTOMOUNT (desde Linux 2.6.38)
No montar automáticamente el componente final ("basename") de path. Desde Linux 3.1 esta bandera se ignora. Desde Linux 4.11 esta bandera está implícita.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo desreferencies: en su lugar, devuelve información sobre el propio enlace, como lstat(). (Por defecto, fstatat() desreferencia los enlaces simbólicos, como stat().)

Ver openat(2) para una explicación de la necesidad de fstatat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece la variable errno para indicar el error.

ERRORES

EACCES
Se niega el permiso de búsqueda en uno de los directorios del prefijo de ruta de path. (Ver también path_resolution(7).)
EBADF
fd no es un descriptor de archivo abierto válido.
EBADF
(fstatat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
Dirección incorrecta.
EINVAL
(fstatat()) Se especificó una bandera inválida en flags.
ELOOP
Se encontraron demasiados enlaces simbólicos al recorrer la ruta.
ENAMETOOLONG
path es demasiado larga.
ENOENT
Un componente de path no existe o es un enlace simbólico desconectado.
ENOENT
path es una cadena vacía y AT_EMPTY_PATH no se especificó en flags.
ENOMEM
Memoria agotada (es decir, memoria del kernel).
ENOTDIR
Un componente del prefijo de ruta de path no es un directorio.
ENOTDIR
(fstatat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EOVERFLOW
path o fd se refieren a un archivo cuyo tamaño, número de inodo o número de bloques no pueden representarse en los tipos off_t, ino_t o blkcnt_t, respectivamente. Este error puede ocurrir cuando, por ejemplo, una aplicación compilada en una plataforma de 32 bits sin -D_FILE_OFFSET_BITS=64 llama a stat() en un archivo cuyo tamaño excede (1<<31)-1 bytes.

NOMBRE

lstat, stat, fstat - obtener información sobre un archivo

BIBLIOTECA

Standard C library (libc, -lc)

SINOPSIS

#include <sys/stat.h>

int stat(const char *pathname, struct stat *statbuf);
int lstat(const char *pathname, struct stat *statbuf);
int fstat(int fd, struct stat *statbuf);

#define _ATFILE_SOURCE
#include <fcntl.h>
int fstatat(int dirfd, const char *pathname, struct stat *statbuf, int flags);

DESCRIPCIÓN

Estas funciones devuelven información sobre el archivo al que se refiere el pathname (para stat y lstat) o el descriptor de archivo fd (para fstat). La información se almacena en la estructura en la que apunta statbuf. La estructura stat tiene al menos los siguientes campos:

st_size
Tamaño del archivo en bytes.
st_mode
Modo de archivo y bits de tipo de archivo. Ver stat(2).
st_nlink
Número de enlaces.
st_uid
ID del usuario propietario.
st_gid
ID del grupo propietario.
st_atime
Hora del último acceso.
st_mtime
Hora de la última modificación.
st_ctime
Hora de la última modificación del estado.
st_blksize
Tamaño de bloque preferido para E/S de E/S eficiente. Por ejemplo, para lecturas o escrituras en disco.
st_blocks
Número de bloques de 512 bytes asignados al archivo. Tenga en cuenta que esto puede ser diferente de st_size / 512 si el archivo tiene huecos o si se utilizan tamaños de bloque no estándar.
st_dev
ID del dispositivo en el que se encuentra este archivo.
st_ino
Número de inodo.

stat sigue los enlaces simbólicos. lstat no sigue los enlaces simbólicos; devuelve información sobre el enlace simbólico en sí.

fstat es similar a stat, pero opera en un descriptor de archivo abierto en lugar de un nombre de ruta.

fstatat es similar a stat, pero con el comportamiento adicional descrito a continuación. Si pathname es relativo, se interpreta en relación con el directorio cuyo descriptor de archivo se proporciona en dirfd. Si pathname es absoluto, dirfd se ignora. Si pathname termina en una barra inclinada, se aplica la misma regla que para open(2) y link(2). Si pathname es ., .., o ., se hace referencia al directorio especificado por dirfd.

fstatat se puede usar para obtener información sobre un archivo sin abrirlo previamente (lo que podría ser una ventaja de seguridad en algunos casos). Si pathname es un enlace simbólico, fstatat opera en el enlace simbólico (de forma similar a lstat).

Los flags son cero o una o más de las siguientes constantes ORed juntas:

AT_SYMLINK_NOFOLLOW
Igual que lstat: si pathname es un enlace simbólico, devuelva información sobre el enlace en sí en lugar de lo que hay en el enlace. Esto se aplica solo si pathname es relativo a dirfd. Si pathname es absoluto, se ignora dirfd y esta bandera tiene el mismo efecto que lstat.
AT_REMOVEDIR
Si pathname hace referencia a un directorio vacío, se eliminará el directorio. Esta operación es atómica. Ver openat(2).

Los campos de tiempo (st_atime, st_mtime, st_ctime) son estructuras struct timespec que contienen los segundos y los nanosegundos. El campo st_mode es una máscara de bits que incluye el tipo de archivo y los permisos. Consulte stat(2) para obtener una descripción detallada de los campos stat.

La especificación POSIX.1-2008 obliga a que lstat() devuelva información válida en todos los campos, excepto en los bits de modo del campo st_mode.

El uso de los campos st_blocks y st_blksize puede ser menos portable. (Fueron introducidos en BSD. La interpretación difiere entre sistemas, y posiblemente en un solo sistema cuando hay montajes NFS involucrados).

Diferencias entre la biblioteca C y el kernel

Con el tiempo, los aumentos en el tamaño de la estructura stat han llevado a tres versiones sucesivas de **stat**(): sys_stat() (slot __NR_oldstat), sys_newstat() (slot __NR_stat), y sys_stat64() (slot __NR_stat64) en plataformas de 32 bits como i386. Las dos primeras versiones ya estaban presentes en Linux 1.0 (aunque con nombres diferentes); la última se añadió en Linux 2.4. Observaciones similares se aplican a **fstat**() y **lstat**().

Las versiones internas del kernel de la estructura stat gestionadas por las diferentes versiones son, respectivamente:

__old_kernel_stat
La estructura original, con campos bastante estrechos y sin relleno.
stat
Campo st_ino más grande y relleno añadido a varias partes de la estructura para permitir la expansión futura.
stat64
Campo st_ino aún más grande, campos st_uid y st_gid más grandes para acomodar la expansión de UIDs y GIDs a 32 bits en Linux 2.4, y varios otros campos ampliados y relleno adicional en la estructura. (Varios bytes de relleno finalmente se consumieron en Linux 2.6, con la llegada de IDs de dispositivo de 32 bits y componentes de nanosegundos para los campos de marca de tiempo).

La función envoltorio stat() de glibc oculta estos detalles a las aplicaciones, invocando la versión más reciente de la llamada al sistema proporcionada por el kernel y reempaquetando la información devuelta si es necesario para binarios antiguos.

En los sistemas modernos de 64 bits, la vida es más simple: hay una única llamada al sistema stat() y el kernel maneja una estructura stat que contiene campos de tamaño suficiente.

La llamada al sistema subyacente empleada por la función envoltorio fstatat() de glibc se llama en realidad fstatat64() o, en algunas arquitecturas, newfstatat().

EJEMPLOS

El siguiente programa llama a lstat() y muestra campos seleccionados en la estructura stat devuelta.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID del dispositivo contenedor:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("Tipo de archivo:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("dispositivo de bloque\n");            break;
    case S_IFCHR:  printf("dispositivo de caracter\n");        break;
    case S_IFDIR:  printf("directorio\n");               break;
    case S_IFIFO:  printf("FIFO/pipe\n");               break;
    case S_IFLNK:  printf("enlace simbólico\n");                 break;
    case S_IFREG:  printf("archivo regular\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("desconocido?\n");                break;
    }
    printf("Número de inodo:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Modo:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Número de enlaces:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Propiedad:               UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Tamaño de bloque preferido para E/S: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("Tamaño del archivo:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Bloques asignados:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Último cambio de estado:       %s", ctime(&sb.st_ctime));
    printf("Último acceso al archivo:         %s", ctime(&sb.st_atime));
    printf("Última modificación del archivo:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
