NOMBRE

opam-remove - Eliminar una lista de paquetes.

SINOPSIS

opam remove [OPCIÓN]… [PAQUETES]…

DESCRIPCIÓN

Este comando desinstala uno o más paquetes actualmente instalados en el entorno seleccionado actualmente. Para eliminar paquetes instalados en otro entorno, necesitas cambiar de entorno usando opam switch o usar la opción --switch. Este comando es el inverso de opam-install.

Si se especifica un nombre de directorio como paquete, los paquetes anclados a ese directorio serán desanclados y eliminados.

ARGUMENTOS

PAQUETES
Lista de nombres de paquetes, con una versión o restricción opcional, por ejemplo `pkg', `pkg.1.0' o `pkg>=0.5' ; o nombres de directorios que contienen la descripción del paquete, con un directorio explícito (por ejemplo `./srcdir' o `.')

OPCIONES

-a, --auto-remove
Eliminar todos los paquetes que no han sido instalados explícitamente y que ya no son necesarios. Es posible evitar la eliminación de un paquete ya instalado ejecutando opam install <paquete> --set-root. Esta opción también se puede establecer mediante la variable de configuración $OPAMAUTOREMOVE.
--destdir=DIR
En lugar de desinstalar los paquetes, revierte la acción de opam install --destdir: elimina los archivos correspondientes a lo que los paquetes listados instalaron en el entorno actual desde el directorio DIR especificado. Ten en cuenta que el paquete debe seguir instalado con la misma versión que se utilizó para install --destdir para que esto funcione de manera fiable. Los paquetes no se eliminan del entorno opam actual cuando se especifica esto.
--force
Ejecutar directamente los comandos de eliminación de los paquetes dados, incluso si no son considerados instalados por opam.
--formula=FORMULA (ausente=[])
Experimental. Especifica una fórmula de dependencia a ser verificada por la solución, además del invariante del entorno. El formato es el mismo que para expresar dependencias en archivos de definición de paquetes, por ejemplo '"foo" {>= "1.1"}'
--recursive
Permite búsquedas recursivas de archivos *.opam. Cf. también --subpath.
--subpath=PATH
Los archivos *.opam se obtienen del subdirectorio dado en lugar del directorio principal. Las fuentes se toman del subdirectorio objetivo, internamente solo se copia/descarga este subdirectorio. Puede combinarse con --recursive para tener una búsqueda recursiva en el subpath.

OPCIONES DE COMPILACIÓN DE PAQUETES

--assume-depexts
Omitir el paso de instalación de cualquier paquete del sistema faltante e intentar continuar de todos modos con la compilación de los paquetes opam. Si la instalación es exitosa, opam no volverá a preguntar sobre estos paquetes del sistema. Solo tiene sentido si la gestión de dependencias externas está habilitada.
-b, --keep-build-dir
Mantener los directorios de compilación después de compilar los paquetes. Esto es equivalente a establecer $OPAMKEEPBUILDDIR a "true".
--build-doc
Eliminado en la versión 2.1, usar --with-doc en su lugar.
--build-test
Eliminado en la versión 2.1, usar --with-test en su lugar.
-d, --with-doc
Compilar la documentación del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Es equivalente a establecer $OPAMWITHDOC (o el obsoleto $OPAMBUILDDOC) a "true".
--dry-run
Simular el comando, pero sin realizar ningún cambio real. Esto también se puede configurar con la variable de entorno $OPAMDEBUG.
--fake
Esta opción registra las acciones en la base de datos de opam, sin realizarlas realmente. ADVERTENCIA: Esta opción es peligrosa y probablemente rompa tu entorno opam. Probablemente quieras usar --dry-run. Has sido advertido.
--ignore-constraints-on[=PAQUETES] (por defecto=)
Obliga a opam a ignorar las restricciones de versión en todas las dependencias de los paquetes listados. Esto se puede usar para probar la compatibilidad, pero se esperan fallos de compilación al usarlo. Ten en cuenta que la disponibilidad de los paquetes, así como las restricciones de versión en dependencias opcionales y conflictos, no se ven afectadas. Es equivalente a establecer $OPAMIGNORECONSTRAINTS.
--inplace-build
Al compilar un paquete cuya fuente está vinculada a un directorio local, procesar las acciones de compilación e instalación directamente en ese directorio, en lugar de en una copia limpia gestionada por opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. Es equivalente a establecer $OPAMINPLACEBUILD a "true".
-j JOBS, --jobs=JOBS
Establecer el número máximo de trabajos concurrentes a utilizar. El valor por defecto se calcula a partir del número de núcleos. También puedes establecerlo usando la variable de entorno $OPAMJOBS.
--lock-suffix=SUFFIX (ausente=locked)
Establece el sufijo de los archivos de bloqueo a SUFFIX.
--locked
En comandos que utilizan archivos opam encontrados en fuentes ancladas, si se encuentra una variante del archivo con una extensión .locked añadida (por ejemplo, foo.opam.locked junto a foo.opam), se utilizará esa en su lugar. Esto es típicamente útil para ofrecer un conjunto de dependencias más específico y reproducir contextos de compilación similares, de ahí el nombre. La opción lock se puede usar para generar dichos archivos, basándose en las versiones de las dependencias actualmente instaladas en el host. Es equivalente a establecer la variable de entorno $OPAMLOCKED. Ten en cuenta que esta opción generalmente no afecta a los paquetes ya anclados.
-m MAKE, --make=MAKE
Eliminado en la versión 2.1, usar opam config set[-global] make MAKE en su lugar.
--no-checksums
No verificar la suma de comprobación de los archivos descargados. Es equivalente a establecer $OPAMNOCHECKSUMS a "true".
--no-depexts
Deshabilita temporalmente la gestión de dependencias externas. Esto puede ser útil si un paquete no está disponible en el gestor de paquetes de tu sistema, pero has instalado la dependencia requerida manualmente. Implica --assume-depexts, y también almacena las excepciones en caso de éxito.
--require-checksums
Rechazar la instalación de paquetes que no proporcionen una suma de comprobación para los archivos originales. Es equivalente a establecer $OPAMREQUIRECHECKSUMS a "true".
--reuse-build-dir
Reutilizar los directorios de compilación existentes (mantenidos usando --keep-build-dir), en lugar de compilar desde una copia nueva de la fuente. Esto puede ser más rápido, pero también puede llevar a fallos si los sistemas de compilación de los paquetes no manejan bien las actualizaciones de dependencias. Es equivalente a establecer $OPAMREUSEBUILDDIR a "true".
--show-actions
Llamar al solucionador y mostrar las acciones. No realizar ningún cambio. Es equivalente a establecer $OPAMSHOW.
--skip-updates
Al ejecutar una instalación, actualización o reinstalación en paquetes anclados por fuente, normalmente se actualizan primero desde su origen. Esta opción deshabilita ese comportamiento y los mantendrá en su versión en caché. Es equivalente a establecer $OPAMSKIPUPDATE.
-t, --with-test
Compilar y ejecutar las pruebas unitarias del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Es equivalente a establecer $OPAMWITHTEST (o el obsoleto $OPAMBUILDTEST) a "true".
--unlock-base
Eliminado en la versión 2.1, usar --update-invariant en su lugar.
--update-invariant
Permitir cambios en los paquetes establecidos como base del entorno (típicamente, el compilador principal). Usar con precaución. Es equivalente a establecer la variable de entorno $OPAMUNLOCKBASE
--verbose-on=PAQUETES
Ser más verboso en paquetes específicos. Es equivalente a establecer $OPAMVERBOSE.
--with-dev-setup
Incluir dependencias solo de herramientas de desarrollo.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

>
No fallar si no se pueden instalar todos los paquetes solicitados: intente instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAJOR.MINOR. Previsto para cualquier uso persistente de opam (scripts, entradas de blog, etc.), cualquier versión de opam en la misma serie MAJOR se comportará como para la versión MINOR especificada. La bandera no estaba disponible en opam 2.0, por lo que para seleccionar la CLI 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o sí-inseguro. Se puede especificar más de una vez. Si también se proporcionan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especifique las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje soportado y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre el uso de preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBRE_ARCHIVO
Opción de depuración: guarda las solicitudes CUDF enviadas al solucionador en NOMBRE_ARCHIVO-<n>.cudf, donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está configurada (es decir, si está usando una versión de desarrollo), y sale.
--help[=FMT] (predeterminado=auto)
Muestra esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable de entorno TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBRE_ARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%', será reemplazado por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en la versión 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato más antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Usa ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegúrese de que nada se actualice o reescriba automáticamente. Útil para llamar desde scripts de finalización, por ejemplo. Fallará siempre que se necesite una operación de este tipo; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifique el solucionador CUDF a utilizar para resolver problemas de instalación de paquetes. Puede ser un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentre un error en la definición de un paquete o un archivo de configuración. La configuración predeterminada es continuar silenciosamente si es posible.
--switch=SWITCH
Usa SWITCH como el cambio de compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier solucionador externo y utiliza el interno (esto requiere que opam haya sido compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sea más verboso. Un -v muestra todos los comandos de paquetes, repetir para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.). Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra información de la versión.
-w, --working-dir
Siempre que actualice paquetes vinculados a un directorio local controlado por versiones, actualice al estado de trabajo actual de su fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio fuente se copia tal cual, si no está limpio, puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede configurar con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.
