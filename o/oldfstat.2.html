NOMBRE

stat, fstat, lstat, fstatat - obtener información de archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);

        || /* glibc 2.19 y anteriores */ _BSD_SOURCE

fstatat():

    Antes de glibc 2.10:

DESCRIPCIÓN

Estas funciones devuelven información sobre un archivo, en el búfer al que apunta statbuf. No se requieren permisos en el archivo en sí, pero—en el caso de stat(), fstatat() y lstat()—se requiere permiso de ejecución (búsqueda) en todos los directorios en path que conducen al archivo.

stat() y fstatat() recuperan información sobre el archivo al que apunta path; las diferencias para fstatat() se describen a continuación.

lstat() es idéntica a stat(), excepto que si path es un enlace simbólico, devuelve información sobre el propio enlace, no sobre el archivo al que se refiere el enlace.

fstat() es idéntica a stat(), excepto que el archivo sobre el cual se debe recuperar la información se especifica mediante el descriptor de archivo fd.

La estructura stat

Todas estas llamadas al sistema devuelven una estructura stat (ver stat(3type)).

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura stat pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si st_mode o st_uid son modificados por otro proceso llamando a chmod(2) o chown(2), stat() podría devolver el st_mode antiguo junto con el nuevo st_uid, o el st_uid antiguo junto con el nuevo st_mode.

fstatat()

La llamada al sistema fstatat() es una interfaz más general para acceder a la información del archivo que aún puede proporcionar exactamente el comportamiento de cada una de stat(), lstat() y fstat().

Si path es relativo, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como hacen stat() y lstat() para un nombre de ruta relativo).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso que llama (como stat() y lstat()).

Si path es absoluto, entonces dirfd se ignora.

flags puede ser 0, o incluir una o más de las siguientes banderas OR-ed:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si path es una cadena vacía (o NULL, desde Linux 6.11), opera sobre el archivo al que se refiere dirfd (que podría haber sido obtenido usando la bandera O_PATH de open(2)). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio, y el comportamiento de fstatat() es similar al de fstat(). Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; define _GNU_SOURCE para obtener su definición.
AT_NO_AUTOMOUNT (desde Linux 2.6.38)
No montar automáticamente el componente final ("basename") de path. Desde Linux 3.1 esta bandera se ignora. Desde Linux 4.11 esta bandera está implícita.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo desreferencie: en su lugar, devuelva información sobre el propio enlace, como lstat(). (Por defecto, fstatat() desreferencia enlaces simbólicos, como stat().)

Ver openat(2) para una explicación de la necesidad de fstatat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EACCES
Se niega el permiso de búsqueda en uno de los directorios en el prefijo de ruta de path. (Ver también path_resolution(7).)
EBADF
fd no es un descriptor de archivo abierto válido.
EBADF
(fstatat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
Dirección incorrecta.
EINVAL
(fstatat()) Se especificó una bandera inválida en flags.
ELOOP
Se encontraron demasiados enlaces simbólicos al recorrer la ruta.
ENAMETOOLONG
path es demasiado largo.
ENOENT
Un componente de path no existe o es un enlace simbólico colgante.
ENOENT
path es una cadena vacía y no se especificó AT_EMPTY_PATH en flags.
ENOMEM
Sin memoria (es decir, memoria del kernel).
ENOTDIR
Un componente del prefijo de ruta de path no es un directorio.
ENOTDIR
(fstatat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EOVERFLOW
path o fd se refieren a un archivo cuyo tamaño, número de inodo o número de bloques no se puede representar en los tipos, respectivamente, off_t, ino_t o blkcnt_t. Este error puede ocurrir cuando, por ejemplo, una aplicación compilada en una plataforma de 32 bits sin -D_FILE_OFFSET_BITS=64 llama a stat() sobre un archivo cuyo tamaño excede los (1<<31)-1 bytes.

NOMBRE

oldfstat - obtener información de un archivo (obsoleto)

BIBLIOTECA

Función de la biblioteca C, también proporcionada por el núcleo.

SINOPSIS

#include <sys/stat.h>
int oldfstat(int fd, struct old_stat *buf);

DESCRIPCIÓN

La llamada al sistema oldfstat es un predecesor de fstat(2). Devuelve información sobre un archivo abierto especificado por el descriptor de archivo fd. La información se devuelve en la estructura que apunta buf, que es una versión antigua y más pequeña de la estructura stat.

Los detalles sobre la estructura old_stat son específicos de la implementación y se omiten aquí. La estructura stat definida en <sys/stat.h> en los sistemas Linux modernos es significativamente más grande y contiene campos adicionales. La estructura old_stat contendrá al menos los siguientes campos, que coinciden con los campos más importantes de la estructura stat moderna:

st_dev
Dispositivo en el que se encuentra este archivo.
st_ino
Número de inodo de este archivo.
st_mode
Modo de protección de los bits de archivo.
st_nlink
Número de enlaces duros a este archivo.
st_uid
ID del propietario de este archivo.
st_gid
ID del grupo propietario de este archivo.
st_size
Tamaño total de los datos del archivo en bytes.
st_atime
Hora del último acceso.
st_mtime
Hora de la última modificación de contenido.
st_ctime
Hora del último cambio de estado.

Para obtener una descripción completa de los campos de la estructura stat, consulta stat(2). La principal diferencia es el tamaño y la disposición de la estructura, y que oldfstat puede no devolver información válida en todos los campos que están presentes en la estructura stat moderna.

En la práctica, oldfstat es una versión obsoleta de la llamada al sistema fstat(2). La versión del núcleo que implementa esta llamada al sistema tiene el número de trazado __NR_oldstat en sistemas de 32 bits. En sistemas modernos, esta llamada al sistema es principalmente de interés histórico; se debería utilizar fstat(2).

La llamada al sistema fstat(2) se introduce para superar las limitaciones de tamaño de la estructura stat que existían en los primeros kernels de Linux. En los sistemas de 32 bits, había tres versiones de la llamada al sistema: sys_stat() (número de trazado __NR_oldstat), sys_newstat() (número de trazado __NR_stat) y sys_stat64() (número de trazado __NR_stat64). oldfstat se corresponde con sys_oldstat().

POSIX.1-2001 y posteriores requieren que fstat devuelva información válida en todos los campos, excepto en los bits de modo del campo st_mode. lstat (y por lo tanto oldlstat) está sujeto a las mismas restricciones de POSIX.1-2008 que fstat con respecto a los campos de la estructura stat.

El uso de los campos st_blocks y st_blksize puede ser menos portable. (Fueron introducidos en BSD. La interpretación difiere entre sistemas y, posiblemente, en un mismo sistema cuando hay montajes NFS involucrados).

Diferencias C biblioteca/núcleo

Con el tiempo, el aumento del tamaño de la estructura stat ha llevado a tres versiones sucesivas de stat(): sys_stat() (ranura __NR_oldstat), sys_newstat() (ranura __NR_stat), y sys_stat64() (ranura __NR_stat64) en plataformas de 32 bits como i386. Las dos primeras versiones ya estaban presentes en Linux 1.0 (aunque con nombres diferentes); la última se añadió en Linux 2.4. Observaciones similares se aplican a fstat() y lstat().

Las versiones internas del núcleo de la estructura stat manejadas por las diferentes versiones son, respectivamente:

__old_kernel_stat
La estructura original, con campos bastante estrechos y sin relleno.
stat
Campo st_ino más grande y relleno añadido a varias partes de la estructura para permitir una expansión futura.
stat64
Campo st_ino aún más grande, campos st_uid y st_gid más grandes para acomodar la expansión de UID y GID de Linux 2.4 a 32 bits, y varios otros campos ampliados y relleno adicional en la estructura. (Varios bytes de relleno fueron finalmente consumidos en Linux 2.6, con la llegada de IDs de dispositivo de 32 bits y componentes de nanosegundos para los campos de marca de tiempo).

La función envoltorio stat() de glibc oculta estos detalles a las aplicaciones, invocando la versión más reciente de la llamada al sistema proporcionada por el núcleo y reempaquetando la información devuelta si es necesario para binarios antiguos.

En los sistemas modernos de 64 bits, la vida es más sencilla: hay una única llamada al sistema stat() y el núcleo maneja una estructura stat que contiene campos de tamaño suficiente.

La llamada al sistema subyacente empleada por la función envoltorio fstatat() de glibc se llama en realidad fstatat64() o, en algunas arquitecturas, newfstatat().

EJEMPLOS

El siguiente programa llama a lstat() y muestra campos seleccionados en la estructura stat devuelta.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID del dispositivo contenedor:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("Tipo de archivo:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("dispositivo de bloques\n");            break;
    case S_IFCHR:  printf("dispositivo de caracteres\n");        break;
    case S_IFDIR:  printf("directorio\n");               break;
    case S_IFIFO:  printf("FIFO/tubería\n");               break;
    case S_IFLNK:  printf("enlace simbólico\n");                 break;
    case S_IFREG:  printf("archivo regular\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("desconocido?\n");                break;
    }
    printf("Número de inodo:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Modo:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Número de enlaces:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Propiedad:                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Tamaño de I/O preferido: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("Tamaño de archivo:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Bloques asignados:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Último cambio de estado:       %s", ctime(&sb.st_ctime));
    printf("Último acceso al archivo:         %s", ctime(&sb.st_atime));
    printf("Última modificación de archivo:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
