NOMBRE

overload - Paquete para sobrecargar operaciones de Perl

SINOPSIS

package SomeThing;
use overload
    '+' => \&myadd,
    '-' => \&mysub;
    # etc
...
package main;
$a = SomeThing->new( 57 );
$b = 5 + $a;
...
if (overload::Overloaded $b) {...}
...
$strval = overload::StrVal $b;

DESCRIPCIÓN

Este pragma permite sobrecargar los operadores de Perl para una clase. Para sobrecargar funciones integradas, consulte en su lugar "Overriding Built-in Functions" en perlsub.

Fundamentos

Declaración

Los argumentos de la directiva "use overload" son pares (clave, valor). Para ver el conjunto completo de claves legales, consulte "Operaciones Sobrecargables" más abajo.

Las implementaciones de operadores (los valores) pueden ser subrutinas, referencias a subrutinas o subrutinas anónimas, en otras palabras, cualquier cosa legal dentro de una llamada "&{ ... }". Los valores especificados como cadenas se interpretan como nombres de métodos. Por lo tanto,

package Number;
use overload
    "-" => "minus",
    "*=" => \&muas,
    '""' => sub { ...; };

declara que la resta será implementada por el método minus() en la clase "Number" (o una de sus clases base), y que la función Number::muas() se utilizará para la forma de asignación de la multiplicación, "*=". También define una subrutina anónima para implementar la conversión a cadena: esta se llama cada vez que un objeto bendecido en el paquete "Number" se utiliza en un contexto de cadena (esta subrutina podría, por ejemplo, devolver el número como un número romano).

Convenciones de llamada y autogeneración mágica

El siguiente ejemplo de implementación de minus() (que asume que los objetos "Number" son simplemente referencias bendecidas a escalares) ilustra las convenciones de llamada:

package Number;
sub minus {
    my ($self, $other, $swap) = @_;
    my $result = $$self - $other;         # *
    $result = -$result if $swap;
    ref $result ? $result : bless \$result;
}
# * puede recursar una vez - ver tabla abajo

Se pasan tres argumentos a todas las subrutinas especificadas en la directiva "use overload" (con excepciones - ver más abajo, particularmente "nomethod").

El primero de ellos es el operando que proporciona la implementación del operador sobrecargado; en este caso, el objeto cuyo método minus() se está llamando.

El segundo argumento es el otro operando, o "undef" en el caso de un operador unario.

El tercer argumento se establece en TRUE si (y solo si) los dos operandos han sido intercambiados. Perl puede hacer esto para asegurar que el primer argumento ($self) sea un objeto que implemente la operación sobrecargada, en línea con las convenciones generales de llamada a objetos. Por ejemplo, si $x y $y son "Number"s:

operación   |   genera una llamada a
============|======================
$x - $y     |   minus($x, $y, '')
$x - 7      |   minus($x, 7, '')
7 - $x      |   minus($x, 7, 1)

Perl también puede usar minus() para implementar otros operadores que no han sido especificados en la directiva "use overload", según las reglas para "Autogeneración mágica" descritas más adelante. Por ejemplo, el "use overload" anterior no declaró ninguna subrutina para ninguno de los operadores "--", "neg" (la clave de sobrecarga para el menos unario), o "-=". Por lo tanto

operación   |   genera una llamada a
============|======================
-$x         |   minus($x, 0, 1)
$x--        |   minus($x, 1, undef)
$x -= 3     |   minus($x, 3, undef)

Tenga en cuenta los "undef"s: donde la autogeneración da como resultado que el método para un operador estándar que no cambia ninguno de sus operandos, como "-", se utilice para implementar un operador que cambia el operando (mutadores: aquí, "--" y "-="), Perl pasa undef como tercer argumento. Esto todavía se evalúa como FALSE, consistente con el hecho de que los operandos no han sido intercambiados, pero da a la subrutina la oportunidad de alterar su comportamiento en estos casos.

En todos los ejemplos anteriores, minus() solo debe devolver el resultado de la resta: Perl se encarga de la asignación a $x. De hecho, tales métodos no deben modificar sus operandos, incluso si se pasa "undef" como tercer argumento (ver "Operaciones Sobrecargables").

Lo mismo no se aplica a las implementaciones de "++" y "--": se espera que estas modifiquen su operando. Una implementación apropiada de "--" podría parecer

use overload '--' => "decr",
    # ...
sub decr { --${$_[0]}; }

Si la característica "bitwise" está habilitada (ver feature), se pasa un quinto argumento TRUE a las subrutinas que manejan "&", "|", "^" y "~". Esto indica que el llamador espera un comportamiento numérico. El cuarto argumento será "undef", ya que esa posición ($_[3]) está reservada para su uso por "nomethod".

Matemáticas mágicas, Mutadores y Constructores de Copias

El término 'matemágica' describe la implementación sobrecargada de operadores matemáticos. Las operaciones mathemágicas plantean un problema. Considere el código:

$a = $b;
--$a;

Si $a y $b son escalares, entonces después de estas sentencias

$a == $b - 1

Sin embargo, un objeto es una referencia a datos bendecidos, por lo que si $a y $b son objetos, la asignación "$a = $b" solo copia la referencia, dejando $a y $b apuntando a los mismos datos del objeto. Por lo tanto, uno podría esperar que la operación "--$a" decremente $b además de $a. Sin embargo, esto no sería consistente con la forma en que esperamos que funcionen los operadores matemáticos.

Perl resuelve este dilema llamando transparentemente a un constructor de copias antes de llamar a un método definido para implementar un mutador ("--", "+=", y así sucesivamente). En el ejemplo anterior, cuando Perl llega a la sentencia de decremento, hace una copia de los datos del objeto en $a y asigna a $a una referencia a los datos copiados. Solo entonces llama a decr(), que altera los datos copiados, dejando $b sin cambios. De esta manera, la metáfora del objeto se preserva tanto como sea posible, mientras que las operaciones mathemágicas siguen funcionando de acuerdo con la metáfora aritmética.

Nota: el párrafo anterior describe lo que sucede cuando Perl autogenera el constructor de copias para un objeto basado en un escalar. Para otros casos, consulte "Constructor de Copias".

Se emite una advertencia si se intenta registrar un operador no encontrado anteriormente.

  • "not"

    El operador "not" no es una clave válida para "use overload". Sin embargo, si el operador "!" está sobrecargado, la misma implementación se utilizará para "not" (ya que los dos operadores difieren solo en precedencia).

  • "neg"

    La clave "neg" se utiliza para el signo menos unario para distinguirlo del signo menos binario.

  • "++", "--"

    Suponiendo que se comportarán de manera análoga a los "++" y "--" de Perl, las implementaciones sobrecargadas de estos operadores deben mutar sus operandos.

    No se hace distinción entre las formas prefija y postfija de los operadores de incremento y decremento: estos solo difieren en el punto en que Perl llama a la subrutina asociada al evaluar una expresión.

  • Asignaciones 
    +=  -=  *=  /=  %=  **=  <<=  >>=  x=  .=
&=  |=  ^=  &.=  |.=  ^.=

    La asignación simple no es sobrecargable (la clave '=' se utiliza para el "Constructor de Copia"). Perl tiene una forma de hacer que las asignaciones a un objeto hagan lo que quieras, pero esto implica usar tie(), no overload. Consulta "tie" en perlfunc y los ejemplos del "COOKBOOK" a continuación.

    La subrutina para la variante de asignación de un operador solo debe devolver el resultado de la operación. Se permite cambiar el valor de su operando (esto es seguro porque Perl llama primero al constructor de copia), pero es opcional ya que Perl asigna el valor devuelto al operando de la izquierda de todos modos.

    Un objeto que sobrecarga un operador de asignación lo hace solo con respecto a las asignaciones a ese objeto. En otras palabras, Perl nunca llama a los métodos correspondientes con el tercer argumento (el argumento "swap") establecido en TRUE. Por ejemplo, la operación

    $a *= $b

    no puede provocar que se llame a la implementación de $b para "*=", incluso si $a es un escalar. (Sin embargo, puede generar una llamada al método de $b para "*").

  • No mutadores con variante mutadora 
    +  -  *  /  %  **  <<  >>  x  .
&  |  ^  &.  |.  ^.

    Como se describió anteriormente, Perl puede llamar a métodos para operadores como "+" y "&" en el curso de la implementación de operaciones faltantes como "++", "+=" y "&=". Si bien estos métodos pueden detectar este uso probando la definción del tercer argumento, en todos los casos deben evitar cambiar sus operandos. Esto se debe a que Perl no llama al constructor de copia antes de invocar estos métodos.

  • "int"

    Tradicionalmente, la función Perl "int" redondea a 0 (ver "int" en perlfunc), y por lo tanto, para tipos similares a punto flotante, se debe seguir la misma semántica.

  • Conversiones de cadena, numéricas, booleanas y de expresiones regulares 
    ""  0+  bool

    Estas conversiones se invocan según el contexto, según sea necesario. Por ejemplo, la subrutina para '""' (convertir a cadena) puede usarse cuando el objeto sobrecargado se pasa como argumento a "print", y la de 'bool' cuando se prueba en la condición de una declaración de flujo de control (como "while") o la operación ternaria "?:".

    Por supuesto, en contextos como, por ejemplo, "$obj + 1", Perl invocará la implementación de $obj de "+" en lugar de (en este ejemplo) convertir $obj a un número usando el método de numerificación '0+' (una excepción a esto es cuando no se ha proporcionado ningún método para '+' y "fallback" está establecido en TRUE).

    Las subrutinas para '""', '0+' y 'bool' pueden devolver cualquier valor Perl arbitrario. Si la operación correspondiente para este valor también está sobrecargada, la operación se llamará nuevamente con este valor.

    Como caso especial, si la sobrecarga devuelve el objeto mismo, se utilizará directamente. Una conversión sobrecargada que devuelve el objeto es probablemente un error, ya que es probable que obtenga algo que se parezca a "YourPackage=HASH(0x8172b34)".

    qr

    La subrutina para 'qr' se utiliza dondequiera que el objeto se interpola o se utiliza como una expresión regular, incluido cuando aparece en el lado derecho de un operador "=~" o "!~".

    "qr" debe devolver una expresión regular compilada, o una referencia a una expresión regular compilada (como devuelve "qr//"), y cualquier sobrecarga adicional en el valor de retorno será ignorada.

  • Iteración

    Si "<>" está sobrecargado, la misma implementación se utiliza tanto para la sintaxis de lectura de archivo "<$var>" como para la sintaxis de globbing "<${var}>".

  • Pruebas de archivo

    La clave '-X' se utiliza para especificar una subrutina para manejar todos los operadores de prueba de archivo ("-f", "-x", etc.; ver "-X" en perlfunc para la lista completa); no es posible sobrecargar ningún operador de prueba de archivo individualmente. Para distinguirlos, la letra que sigue al '-' se pasa como segundo argumento (es decir, en la ranura que para los operadores binarios se utiliza para pasar el segundo operando).

    Llamar a un operador de prueba de archivo sobrecargado no afecta el valor stat asociado con el manejador de archivos especial "_". Todavía se refiere al resultado de la última "stat", "lstat" o prueba de archivo no sobrecargada.

    Esta sobrecarga se introdujo en Perl 5.12.

  • Coincidencia

    La clave "~~" te permite anular la lógica de coincidencia inteligente utilizada por el operador "~~" y la construcción de switch ("given"/"when"). Consulta "Switch Statements" en perlsyn y feature.

    De forma inusual, la implementación sobrecargada del operador de coincidencia inteligente no obtiene control total del comportamiento de coincidencia inteligente. En particular, en el siguiente código:

    package Foo;
use overload '~~' => 'match';
my $obj =  Foo->new();
$obj ~~ [ 1,2,3 ];

    la coincidencia inteligente *no* invoca la llamada al método de esta manera:

    $obj->match([1,2,3],0);

    en cambio, la regla distributiva de coincidencia inteligente tiene precedencia, por lo que $obj se compara inteligentemente con cada elemento de la matriz en orden hasta que se encuentra una coincidencia, por lo que puede ver entre una y tres de estas llamadas en su lugar:

    $obj->match(1,0);
$obj->match(2,0);
$obj->match(3,0);

    Consulta la tabla de coincidencias en "Smartmatch Operator" en perlop para obtener detalles sobre cuándo se invoca la sobrecarga.

  • Desreferenciación 
    ${}  @{}  %{}  &{}  *{}

    Si estos operadores no se sobrecargan explícitamente, funcionan de la manera normal, produciendo el escalar subyacente, la matriz o lo que sea que almacene los datos del objeto (o el mensaje de error apropiado si el operador de desreferenciación no coincide con él). Definir un 'nomethod' general (ver más abajo) no hace ninguna diferencia en esto, ya que la función general no se llamará para implementar un operador de desreferenciación faltante.

    Si se sobrecarga un operador de desreferenciación, debe devolver una *referencia* del tipo apropiado (por ejemplo, la subrutina para la clave '${}' debe devolver una referencia a un escalar, no un escalar), u otro objeto que sobrecargue el operador: es decir, la subrutina solo determina qué se desreferencia y la desreferenciación real se deja a Perl. Como caso especial, si la subrutina devuelve el objeto mismo, no se volverá a llamar, evitando la recursión infinita.

  • Especial 
    nomethod  fallback  =

    Consulta "Special Keys for "use overload"".

Si no se encuentra un método para una operación, Perl intenta autogenerar una implementación sustituta a partir de las operaciones que se han definido.

Por ejemplo, la tabla a continuación indica que, si no se ha definido ninguna implementación para '!', Perl la implementará usando 'bool' (es decir, invirtiendo el valor devuelto por el método para 'bool'); si la conversión booleana también no está implementada, Perl usará '0+' o, en su defecto, '""'.



NAME


overload - Perl pragma for operator overloading






SYNOPSIS


  use overload
      '+' => \&add,
      '-' => \&subtract,
      '""' => \&stringify,
      '0+' => \&tonumber,
      'bool' => \&toboolean,
      ...
  use overload; # Reset to defaults
  no overload; # Disable overloading






DESCRIPTION


The use overload pragma allows you to
    specify how operators should behave when applied to objects of a particular
    class. It's a form of operator overloading, similar to what's available in
    other object-oriented languages, but with some Perl-specific twists.


When use overload is encountered, Perl
    maintains a table of overloaded operators for the current package. This table
    maps operator symbols (like '+',
    '""', etc.) to subroutines (or code references)
    that should be called when that operator is used with an object of a class
    that has declared this pragma.


The basic syntax is:


  use overload KEY => VALUE, ...


where KEY is the operator symbol (as a string) and VALUE is the
    subroutine or code reference to call. For example:


  use overload '+' => \&my_add;


This means that whenever Perl sees an operation like
    obj + 5 or 5 + obj (where obj
    is an object of the current package), it will call the subroutine
    my_add.


The subroutine called will receive the operands of the operator
    as arguments. The order of arguments depends on the operator and which operand
    triggered the overload lookup (see "How Perl Chooses an Operator
    Implementation" below).


If you want to turn off overloading for the current package, use
    no overload.


  no overload;


If you want to reset overloading to the default behaviour (i.e., no
    overloading specified), you can use use overload
    without any arguments.


  use overload;


The default behaviour for most operators is to delegate to the
    built-in Perl operators. For conversions like stringification or numeric
    conversion, the default behaviour is to call the object's
    overload::StrVal or
    overload::NumVal subs, respectively, if they exist.

    minimal set is:

<=> cmp
& | ^ ~ &. |. ^. ~.

~~


Of the conversions, only one of string, boolean or numeric is
    needed because each can be generated from either of the other two.

"nomethod"


The 'nomethod' key is used to specify a
    catch-all function to be called for any operator that is not individually
    overloaded. The specified function will be passed four parameters. The first
    three arguments coincide with those that would have been passed to the
    corresponding method if it had been defined. The fourth argument is the
    "use overload" key for that missing
    method. If the "bitwise" feature is enabled (see feature), a fifth
    TRUE argument is passed to subroutines handling
    "&",
    "|", "^"
    and "~" to indicate that the caller is
    expecting numeric behaviour.


For example, if $a is an object blessed
    into a package declaring


use overload 'nomethod' => 'catch_all', # ...


then the operation


3 + $a


could (unless a method is specifically declared for the key
    '+') result in a call


catch_all($a, 3, 1, '+')


See "How Perl Chooses an Operator Implementation".

would be executed in a manner equivalent to

# ...
$b = $b->clone(undef, "");
$b->incr(undef, "");

  • The subroutine for '=' does not overload the Perl
      assignment operator: it is used only to allow mutators to work as
      described here. (See "Assignments" above.)
    • 
  
  • As for other operations, the subroutine implementing '=' is passed three
      arguments, though the last two are always
      "undef" and
    ''.
    • 
  
  • The copy constructor is called only before a call to a function declared
      to implement a mutator, for example, if
      "++$b;" in the code above is effected
      via a method declared for key '++' (or 'nomethod',
      passed '++' as the fourth argument) or, by
      autogeneration, '+='. It is not called if the
      increment operation is effected by a call to the method for
      '+' since, in the equivalent code,
        
    $a = $b;
$b = $b + 1;

    
    
    the data referred to by $a is
        unchanged by the assignment to $b of a reference
        to new object data.
    
  
    • 
  
  • The copy constructor is not called if Perl determines that it is
      unnecessary because there is no other reference to the data being
      modified.
    • 
  
  • If 'fallback' is undefined or TRUE then a copy
      constructor can be autogenerated, but only for objects based on scalars.
      In other cases it needs to be defined explicitly. Where an object's data
      is stored as, for example, an array of scalars, the following might be
      appropriate:
        
    use overload '=' => sub { bless [ @{$_[0]} ] },  # ...

    
  
    • 
  
  • If 'fallback' is TRUE and no copy constructor is
      defined then, for objects not based on scalars, Perl may silently fall
      back on simple assignment - that is, assignment of the object reference.
      In effect, this disables the copy constructor mechanism since no new copy
      of the object data is created. This is almost certainly not what you want.
      (It is, however, consistent: for example, Perl's fallback for the
      "++" operator is to increment the
      reference itself.)

How Perl Chooses an Operator Implementation


Which is checked first,
    "nomethod" or
    "fallback"? If the two operands of an
    operator are of different types and both overload the operator, which
    implementation is used? The following are the precedence rules:



  
1.

  
If the first operand has declared a subroutine to overload the operator
      then use that implementation.

  
2.

  
Otherwise, if fallback is TRUE or undefined for the first operand then see
      if the rules for autogeneration allows another of its operators to be used
      instead.

  
3.

  
Unless the operator is an assignment
      ("+=",
      "-=", etc.), repeat step (1) in respect
      of the second operand.

  
4.

  
Repeat Step (2) in respect of the second operand.

  
5.

  
If the first operand has a "nomethod" method then use that.

  
6.

  
If the second operand has a "nomethod" method then use
    that.

  
7.

  
If "fallback" is TRUE for both operands
      then perform the usual operation for the operator, treating the operands
      as numbers, strings, or booleans as appropriate for the operator (see
      note).

  
8.

  
Nothing worked - die.




Where there is only one operand (or only one operand with
    overloading) the checks in respect of the other operand above are
  skipped.


There are exceptions to the above rules for dereference operations
    (which, if Step 1 fails, always fall back to the normal, built-in
    implementations - see Dereferencing), and for
    "~~" (which has its own set of rules - see
    "Matching" under "Overloadable
    Operations" above).


Note on Step 7: some operators have a different semantic depending
    on the type of their operands. As there is no way to instruct Perl to treat
    the operands as, e.g., numbers instead of strings, the result here may not
    be what you expect. See "BUGS AND PITFALLS".

Herencia y Sobrecarga


La sobrecarga respeta la herencia a través de la jerarquía de
    @ISA. La herencia interactúa con la sobrecarga de dos
    maneras.



  
Nombres de métodos en la
    directiva "use overload"

  
Si "valor" en
        
use overload key => value;


    
es una cadena, se interpreta como un nombre de método, el cual
        puede (de la manera habitual) ser heredado de otra clase.

  

  
La sobrecarga de
    una operación es heredada por las clases derivadas

  
Cualquier clase derivada de una clase sobrecargada también está sobrecargada
      y hereda sus implementaciones de operador. Si el mismo operador está
      sobrecargado en más de un antecesor, la implementación se determina según
      las reglas habituales de herencia.
    
Por ejemplo, si "A" hereda de
        "B" y
        "C" (en ese orden),
        "B" sobrecarga
        "+" con
        "\&D::plus_sub", y
        "C" sobrecarga
        "+" con
        "plus_meth", entonces la subrutina
        "D::plus_sub" será llamada para
        implementar la operación "+" para un
        objeto en el paquete "A".

  




Tenga en cuenta que en versiones de Perl anteriores a la 5.18, la
    herencia de la clave "fallback" no se regía
    por las reglas anteriores. Se utilizaba el valor de
    "fallback" en el primer antecesor sobrecargado.
    Esto se corrigió en la versión 5.18 para seguir las reglas habituales de
    herencia.






Sobrecarga en Tiempo de Ejecución


Dado que todas las directivas "use"
    se ejecutan en tiempo de compilación, la única forma de cambiar la sobrecarga
    durante el tiempo de ejecución es mediante:


eval 'use overload "+" => \&addmethod';


También puede usar:


eval 'no overload "+", "--", "<="';


aunque el uso de estas construcciones en tiempo de ejecución es
    cuestionable.

Sobrecarga de Constantes


Para algunas aplicaciones, el intérprete de Perl modifica demasiado
    las constantes. Es posible engancharse a este proceso a través de las
    funciones overload::constant() y
    overload::remove_constant().


Estas funciones toman un hash como argumento. Las claves reconocidas
    de este hash son:



  
integer

  
para sobrecargar constantes enteras,

  
float

  
para sobrecargar constantes de punto flotante,

  
binary

  
para sobrecargar constantes octales y hexadecimales,

  
q

  
para sobrecargar cadenas entre comillas "q",
      trozos constantes de cadenas entre comillas "qq"
      y "qx" y here-documents,

  
qr

  
para sobrecargar trozos constantes de expresiones regulares.




Los valores correspondientes son referencias a funciones que toman
    tres argumentos: el primero es la forma de cadena *inicial* de la constante,
    el segundo es cómo Perl interpreta esta constante, el tercero es cómo se usa
    la constante. Tenga en cuenta que la forma de cadena inicial no contiene
    delimitadores de cadena, y tiene las barras invertidas en combinaciones de
    barras invertidas y delimitadores eliminadas (por lo tanto, el valor del
    delimitador no es relevante para el procesamiento de esta cadena). El valor
    de retorno de esta función es cómo esta constante será interpretada por
    Perl. El tercer argumento es indefinido, excepto para constantes
    "q" y "qr"
    sobrecargadas, es "q" en contexto de comillas
    simples (proviene de cadenas, expresiones regulares y documentos HERE de
    comillas simples), es "tr" para argumentos de
    los operadores "tr"/"y",
    es "s" para el lado derecho del operador
    "s", y es "qq" en
    otros casos.


Dado que una expresión "ab$cd,," es
    simplemente un atajo para 'ab' . $cd . ',,', se espera
    que las cadenas constantes sobrecargadas estén equipadas con un operador de
    concatenación sobrecargado razonable, de lo contrario se obtendrán resultados
    absurdos. De manera similar, los números negativos se consideran negaciones de
    constantes positivas.


Tenga en cuenta que probablemente no tenga sentido llamar a las
    funciones overload::constant() y
    overload::remove_constant() desde ningún otro lugar que no sean los
    métodos import() y unimport(). Desde estos métodos pueden ser
    llamadas como


sub import {
    shift;
    return unless @_;
    die "unknown import: @_" unless @_ == 1 and $_[0] eq ':constant';
    overload::constant integer => sub {Math::BigInt->new(shift)};
}

Lo siguiente está sujeto a cambios PRONTO.


La tabla de métodos para todas las operaciones se almacena en caché
    en magia para el hash de la tabla de símbolos del paquete. La caché se
    invalida durante el procesamiento de "use overload",
    "no overload", definiciones de nuevas funciones
    y cambios en @ISA.


(Cada cosa tipo SV tiene una cola mágica, y la magia es una entrada en
    esa cola. Así es como una sola variable puede participar simultáneamente en
    múltiples formas de magia. Por ejemplo, las variables de entorno suelen tener
    dos formas a la vez: su magia de %ENV y su magia de
    taint. Sin embargo, la magia que implementa la sobrecarga se aplica a los
    stashes, que rara vez se usan directamente, por lo que no debería ralentizar
    Perl.)


Si un paquete utiliza sobrecarga, lleva una bandera especial. Esta
    bandera también se activa cuando se definen nuevas funciones o se modifica
    @ISA. Habrá una ligera penalización de velocidad en la
    primera operación posterior que admita sobrecarga, mientras se actualizan las
    tablas de sobrecarga. Si no hay sobrecarga presente, la bandera se desactiva.
    Por lo tanto, la única penalización de velocidad posterior es la comprobación
    de esta bandera.


Se espera que los argumentos de los métodos que no están explícitamente
    destinados a ser cambiados sean constantes (pero esto no se aplica).
