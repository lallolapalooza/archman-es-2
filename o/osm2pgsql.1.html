NOMBRE

osm2pgsql - conversor de datos de OpenStreetMap a PostgreSQL

SINOPSIS

osm2pgsql [OPCIONES] OSM-ARCHIVO...

DESCRIPCIÓN

osm2pgsql importa datos de OpenStreetMap a una base de datos PostgreSQL/PostGIS. Es una parte esencial de muchas cadenas de procesamiento de renderizado, el geocodificador Nominatim y otras aplicaciones que procesan datos de OSM.

osm2pgsql puede ejecutarse en modo “crear” (el predeterminado) o en modo “añadir” (opción -a, --append).

En modo “crear”, osm2pgsql creará las tablas de la base de datos requeridas por la configuración e importará los archivos OSM especificados en la línea de comandos a esas tablas. Tenga en cuenta que también debe usar la opción -s, --slim si desea que su base de datos sea actualizable.

En modo “añadir”, osm2pgsql actualizará las tablas de la base de datos con los datos de los archivos de cambio de OSM especificados en la línea de comandos.

Esta página del manual solo puede cubrir algunos de los aspectos básicos y describir las opciones de la línea de comandos. Consulte el Manual de Osm2pgsql (https://osm2pgsql.org/doc/manual.html) para obtener más información.

OPCIONES

Este programa sigue la sintaxis habitual de línea de comandos de GNU, con opciones largas que comienzan con dos guiones (--). Los argumentos obligatorios para las opciones largas son obligatorios también para las opciones cortas.

OPCIONES PRINCIPALES

-a, --append
Ejecutar en modo de añadir. Añade el archivo de cambio de OSM a la base de datos sin eliminar los datos existentes.
-c, --create
Ejecutar en modo de creación. Este es el predeterminado si no se especifica -a, --append. ¡Elimina los datos existentes de las tablas de la base de datos!

OPCIONES DE AYUDA/VERSIÓN

-h, --help
Imprime la ayuda. Añada -v, --verbose para mostrar una ayuda más detallada.
-V, --version
Imprime la versión de osm2pgsql.

OPCIONES DE REGISTRO

--log-level=NIVEL
Establece el nivel de registro (`debug', `info' (predeterminado), `warn', o `error').
--log-progress=VALOR
Habilita (true) o deshabilita (false) el registro de progreso. Establecer esto en `auto` habilitará el registro de progreso en la consola y lo deshabilitará si la salida se redirige a un archivo. Predeterminado: true.
--log-sql
Habilita el registro de comandos SQL para depuración.
--log-sql-data
Habilita el registro de todos los datos añadidos a la base de datos. ¡Esto escribirá una gran cantidad de datos! Para depuración.
-v, --verbose
Igual que --log-level=debug.

OPCIONES DE BASE DE DATOS

-d, --database=NOMBRE
El nombre de la base de datos PostgreSQL a la que conectarse. Si este parámetro contiene un signo = o comienza con un prefijo de URI válido (postgresql:// o postgres://), se trata como una cadena de conninfo. Consulte el manual de PostgreSQL para obtener detalles.
-U, --username=NOMBRE
Nombre de usuario de PostgreSQL.
-W, --password
Forzar solicitud de contraseña.
-H, --host=NOMBRE_HOST
Nombre de host del servidor de base de datos o ubicación del socket de dominio Unix.
-P, --port=PUERTO
Puerto del servidor de base de datos.
--schema=ESQUEMA
Predeterminado para varias configuraciones de esquema en osm2pgsql (predeterminado: public). El esquema debe existir en la base de datos y ser escribible por el usuario de la base de datos.

OPCIONES DE ENTRADA

-r, --input-reader=FORMATO
Selecciona el formato del archivo de entrada. Las opciones disponibles son auto (predeterminado) para autodetectar el formato, xml para archivos en formato OSM XML, o5m para archivos con formato o5m y pbf para formato binario OSM PBF.
-b, --bbox=MINLON,MINLAT,MAXLON,MAXLAT
Aplica un filtro de cuadro delimitador a los datos importados. Ejemplo: --bbox -0.5,51.25,0.5,51.75

OPCIONES INTERMEDIAS

-i, --tablespace-index=TABLESPC
Almacena todos los índices en el tablespace de PostgreSQL TABLESPC. Esta opción también afecta a las tablas creadas por la salida pgsql. Esta opción está obsoleta. Utilice las opciones --tablespace-slim-index y/o --tablespace-main-index en su lugar.
--tablespace-slim-data=TABLESPC
Almacena las tablas en modo slim en el tablespace especificado.
--tablespace-slim-index=TABLESPC
Almacena los índices de las tablas en modo slim en el tablespace especificado.
-p, --prefix=PREFIJO
Prefijo para los nombres de tabla (predeterminado: planet_osm).
-s, --slim
Almacena datos temporales en la base de datos. Sin este modo, todos los datos temporales se almacenan en RAM y si no tiene suficiente, la importación no se realizará con éxito. Con el modo slim, debería poder importar los datos incluso en un sistema con RAM limitada, aunque si no tiene suficiente RAM para almacenar en caché al menos todos los nodos, es probable que el tiempo de importación de los datos aumente considerablemente.
--drop
Elimina las tablas en modo slim de la base de datos y el archivo plano de nodos una vez que se completa la importación. Esto puede reducir significativamente el tamaño de la base de datos, ya que las tablas en modo slim suelen tener el mismo tamaño, si no un poco más grandes, que las tablas principales. Sin embargo, no reduce el pico máximo de uso de disco durante la importación. Además, puede aumentar la velocidad de importación, ya que no es necesario crear índices para las tablas en modo slim, lo que (dependiendo del hardware) puede casi duplicar el tiempo de importación. Sin embargo, las tablas en modo slim deben ser persistentes si desea poder actualizar su base de datos, ya que estas tablas son necesarias para el procesamiento de diff.
-C, --cache=NUM
Solo para el modo slim: Utiliza hasta NUM MB de RAM para almacenar en caché los nodos. Proporcionar a osm2pgsql suficiente caché para almacenar todos los nodos importados suele aumentar considerablemente la velocidad de importación. Cada nodo en caché requiere 8 bytes de caché, más aproximadamente un 10% - 30% de sobrecarga. Como regla general, proporcione un poco más del tamaño del archivo de importación en formato PBF. Si la RAM no es suficiente, utilice aproximadamente el 75% de la memoria. Asegúrese de dejar suficiente RAM para PostgreSQL. Necesita al menos la cantidad de shared_buffers especificada en su configuración. Predeterminado: 800.
-x, --extra-attributes
Incluye atributos de cada objeto en las tablas intermedias y los hace disponibles para las salidas. Los atributos son: nombre de usuario, ID de usuario, ID de changeset, marca de tiempo y versión.
-F, --flat-nodes=NOMBRE_ARCHIVO
Utiliza un archivo en disco para almacenar las ubicaciones de los nodos en lugar de almacenarlos en memoria (en modo no slim) o en la base de datos (en modo slim). Esto es mucho más eficiente que almacenar los datos en la base de datos. Almacenar la información de los nodos para el planeta completo requiere más de 500 GB en PostgreSQL; los mismos datos se almacenan en “solo” 90 GB utilizando el modo flat-nodes. Esto también puede aumentar la velocidad de aplicación de los archivos diff. Este modo activa el modo flat-nodes y especifica la ubicación del archivo de base de datos. Es un único archivo grande. OPCIONES DEL MEDIO

--middle-drop
Elimina las tablas y funciones de la base de datos después de que el script haya terminado. Por defecto, las tablas y funciones se quedan en la base de datos. No funciona bien con importaciones pequeñas. El valor por defecto está desactivado. El archivo permanecerá en disco después de la importación, usa --drop para eliminarlo (pero no podrás hacer actualizaciones entonces).
--middle-schema=SCHEMA
Usa el esquema de PostgreSQL SCHEMA para todas las tablas, índices y funciones en el medio. El esquema debe existir en la base de datos y ser escribible por el usuario de la base de datos. Por defecto, se usa el esquema establecido con --schema, o public si no está configurado.
--middle-with-nodes
Cuando se usa un archivo de nodos plano, los nodos no se almacenan en la base de datos. Usa esta opción para forzar el almacenamiento de nodos con etiquetas en la base de datos también.

OPCIONES DE SALIDA

-O, --output=OUTPUT
Especifica la salida a usar. Actualmente osm2pgsql soporta pgsql, flex y null. pgsql es la salida por defecto aún disponible por compatibilidad hacia atrás. Las nuevas configuraciones deben usar la salida flex, que permite una configuración mucho más flexible. La salida null no escribe nada y solo es útil para pruebas o con --slim para crear tablas slim.
-S, --style=FILE
El archivo de estilo. Este especifica cómo se importan los datos en la base de datos, su formato depende de la salida. (Para la salida pgsql, el valor por defecto es /usr/share/osm2pgsql/default.style, para otras salidas no hay valor por defecto.)

OPCIONES DE SALIDA PGSQL

--tablespace-main-data=TABLESPC
Almacena las tablas de datos en el tablespace de PostgreSQL TABLESPC.
--tablespace-main-index=TABLESPC
Almacena los índices en el tablespace de PostgreSQL TABLESPC.
--latlong
Almacena las coordenadas en grados de latitud y longitud.
-m, --merc
Almacena las coordenadas en Mercator Esférico (Mercator Web, EPSG:3857) (el valor por defecto).
-E, --proj=SRID
Usa la proyección EPSG:SRID.
-p, --prefix=PREFIX
Prefijo para los nombres de tabla (por defecto: planet_osm). Esta opción afecta a los nombres de tabla del medio y de la salida pgsql.
--tag-transform-script=SCRIPT
Especifica un script de Lua para manejar el filtrado y normalización de etiquetas. El script contiene funciones de devolución de llamada para nodos, vías y relaciones, que cada una toma un conjunto de etiquetas y devuelve un conjunto transformado y filtrado de etiquetas que luego se escriben en la base de datos.
-x, --extra-attributes
Incluye atributos (nombre de usuario, id de usuario, id de changeset, timestamp y versión). Esto también requiere entradas adicionales en tu archivo de estilo.
-k, --hstore
Añade etiquetas sin columna a una columna adicional hstore (clave/valor) en las tablas de la base de datos.
-j, --hstore-all
Añade todas las etiquetas a una columna adicional hstore (clave/valor) en las tablas de la base de datos.
-z, --hstore-column=PREFIX
Añade una columna adicional hstore (clave/valor) llamada PREFIX que contiene todas las etiquetas cuya clave comienza con PREFIX, por ejemplo \--hstore-column "name:" producirá una columna hstore extra que contiene todas las etiquetas name:xx.
--hstore-match-only
Solo conserva los objetos que tienen un valor en al menos una de las columnas no-hstore.
--hstore-add-index
Crea índices para todas las columnas hstore después de la importación.
-G, --multi-geometry
Normalmente osm2pgsql divide las geometrías multiparte en filas de base de datos separadas por parte. Por lo tanto, un solo objeto OSM puede usar varias filas en las tablas de salida. Con esta opción, osm2pgsql genera en su lugar características de multi-geometría en las tablas de PostgreSQL.
-K, --keep-coastlines
Conserva los datos de las líneas costeras en lugar de filtrarlos. Por defecto, los objetos etiquetados como natural=coastline serán descartados basándose en la suposición de que se usarán Shapefiles generados por OSMCostline (https://osmdata.openstreetmap.de/) para los datos de las líneas costeras.
--reproject-area
Calcula la columna de área usando coordenadas de mercator esférico incluso si se usa una proyección diferente para las geometrías.
--output-pgsql-schema=SCHEMA
Usa el esquema de PostgreSQL SCHEMA para todas las tablas, índices y funciones en la salida pgsql. El esquema debe existir en la base de datos y ser escribible por el usuario de la base de datos. Por defecto, se usa el esquema establecido con --schema, o public si no está configurado.

OPCIONES DE CADUCIDAD

-e, --expire-tiles=[MIN_ZOOM-]MAX-ZOOM
Crea una lista de caducidad de teselas.
-o, --expire-output=FILENAME
Nombre del archivo de salida para la lista de teselas caducadas.
--expire-bbox-size=SIZE
Tamaño máximo para un polígono para caducar el polígono completo, no solo el borde.

OPCIONES AVANZADAS

-I, --disable-parallel-indexing
Deshabilita la agrupación y construcción de índices paralela en todas las tablas, construye un índice tras otro.
--number-processes=THREADS
Especifica el número de hilos paralelos utilizados para ciertas operaciones.
