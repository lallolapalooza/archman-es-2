NOMBRE

org.freedesktop.hostname1 - La interfaz D-Bus de systemd-hostnamed

INTRODUCCIÓN

systemd-hostnamed.service(8) es un servicio del sistema que puede ser utilizado por programas de usuario para controlar el nombre de host y metadatos relacionados de la máquina. Esta página describe la semántica del nombre de host y la interfaz D-Bus.

LA API DE D-BUS

El servicio expone las siguientes interfaces en el bus:

nodo /org/freedesktop/hostname1 {
  interfaz org.freedesktop.hostname1 {
    métodos:
      SetHostname(in  s hostname,
                  in  b interactive);
      SetStaticHostname(in  s hostname,
                        in  b interactive);
      SetPrettyHostname(in  s hostname,
                        in  b interactive);
      SetIconName(in  s icon,
                  in  b interactive);
      SetChassis(in  s chassis,
                 in  b interactive);
      SetDeployment(in  s deployment,
                    in  b interactive);
      SetLocation(in  s location,
                  in  b interactive);
      GetProductUUID(in  b interactive,
                     out ay uuid);
      GetHardwareSerial(out s serial);
      Describe(out s json);
    propiedades:
      readonly s Hostname = '...';
      readonly s StaticHostname = '...';
      readonly s PrettyHostname = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s DefaultHostname = '...';
      readonly s HostnameSource = '...';
      readonly s IconName = '...';
      readonly s Chassis = '...';
      readonly s Deployment = '...';
      readonly s Location = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s KernelName = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s KernelRelease = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s KernelVersion = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s OperatingSystemPrettyName = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s OperatingSystemCPEName = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly t OperatingSystemSupportEnd = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s HomeURL = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s OperatingSystemImageID = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s OperatingSystemImageVersion = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s HardwareVendor = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")

Cada vez que el demonio cambia el nombre de host u otros metadatos a través de la interfaz, se envían señales PropertyChanged a los clientes suscritos. Cambiar un nombre de host utilizando esta interfaz se autentica a través de polkit[1].

SEMÁNTICA

La propiedad StaticHostname expone el nombre de host "estático" configurado en /etc/hostname. No siempre está sincronizado con el nombre de host actual tal como lo devuelve la llamada al sistema gethostname(3). Si no hay un nombre de host estático configurado, esta propiedad será una cadena vacía.

Cuando systemd(1) o systemd-hostnamed.service(8) establecen el nombre de host, este nombre de host estático tiene la máxima prioridad.

La propiedad Hostname expone el nombre de host real configurado en el kernel a través de sethostname(2). Puede ser diferente del nombre de host estático. Esta propiedad nunca está vacía.

La propiedad PrettyHostname expone el nombre de host bonito (pretty hostname), que es un nombre de host en formato libre UTF-8 para presentarlo al usuario. Las interfaces de usuario deben asegurarse de que el nombre de host bonito y el nombre de host estático se mantengan sincronizados. Por ejemplo, cuando el primero es "Ordenador de Lennart", el segundo debería ser "ordenador-de-lennart". Si no se establece un nombre de host bonito, esta configuración será una cadena vacía. Las aplicaciones deberían entonces encontrar una alternativa adecuada, como el nombre de host dinámico.

La propiedad DefaultHostname expone el nombre de host predeterminado (configurado a través de os-release(5), o una alternativa establecida en tiempo de compilación).

La propiedad HostnameSource expone el origen del nombre de host configurado actualmente. Uno de "static" (establecido desde /etc/hostname), "transient" (un nombre de host no permanente de una fuente externa), "default" (el valor de os-release o la alternativa compilada en el código).

La propiedad IconName expone el nombre del icono siguiendo la especificación de nombres de iconos XDG. Si no está establecido, se utiliza información como el tipo de chasis (ver más abajo) para encontrar un nombre de icono alternativo adecuado (por ejemplo, se elige "computer-laptop" en lugar de "computer-desktop" basándose en la información del chasis). Si no hay datos disponibles, se devuelve una cadena vacía. En ese caso, una aplicación debería recurrir a un icono de reemplazo, como por ejemplo "computer". Si esta propiedad se establece en una cadena vacía, se vuelve a habilitar la selección automática del nombre de icono alternativo.

La propiedad Chassis expone el tipo de chasis, uno de los tipos de chasis definidos actualmente: "desktop", "laptop", "server", "tablet", "handset", así como los tipos de chasis especiales "vm" y "container" para sistemas virtualizados. Tenga en cuenta que en la mayoría de los casos, el tipo de chasis se determinará automáticamente a partir de la información del firmware DMI/SMBIOS/ACPI. Por lo tanto, escribir en esta configuración solo es útil para anular tipos de chasis detectados erróneamente, o para configurar el tipo de chasis si no se pudo detectar automáticamente. Establezca esta propiedad en una cadena vacía para volver a habilitar la detección automática del tipo de chasis a partir de la información del firmware.

Tenga en cuenta que systemd-hostnamed solo se inicia bajo petición y termina después de un corto período de inactividad. Esto significa efectivamente que los mensajes PropertyChanged no se envían para los cambios realizados directamente en los archivos (es decir: el administrador edita los archivos con vi). Este es el comportamiento previsto: los cambios de configuración manuales deberían requerir una recarga manual.

El nombre de host transitorio (dinámico) expuesto por la propiedad Hostname se corresponde directamente con el nombre de host del kernel. Se debe asumir que este nombre de host es muy dinámico, y por lo tanto debe ser monitorizado directamente, sin depender de los mensajes PropertyChanged de systemd-hostnamed. Para lograr esto, abra /proc/sys/kernel/hostname y utilice poll(3) para recibir SIGHUP, que es activado por el kernel cada vez que cambia el nombre de host. De nuevo: esto es especial para el nombre de host transitorio (dinámico) y no se aplica al nombre de host configurado (fijo).

Las aplicaciones pueden leer los datos del nombre de host directamente si las notificaciones de cambio de nombre de host no son necesarias. Utilice gethostname(2), /etc/hostname (posiblemente con alternativas por distribución) y machine-info(5) para ello. Para más información sobre estos archivos y llamadas al sistema, consulte las páginas man correspondientes.

KernelName, KernelRelease y KernelVersion exponen el nombre del kernel (por ejemplo, "Linux"), la versión (por ejemplo, "5.0.0-11") y el número de compilación (es decir, el número de compilación, por ejemplo, "#11") según lo informado por uname(2). Operati

ngSystemPrettyName, OperatingSystemCPEName y HomeURL exponen los campos PRETTY_NAME=, CPE_NAME= y HOME_URL= de os-release(5). El propósito de estas propiedades es permitir a los clientes remotos acceder a esta información a través de D-Bus. Los clientes locales pueden acceder a la información directamente.

MachineID expone la ID de máquina de 128 bits, ver machine-id(5) para más detalles.

BootID expone la ID de arranque de 128 bits, según /proc/sys/kernel/random/boot_id.

VSockCID expone el CID local (Identificador de Contexto, es decir, dirección) de AF_VSOCK del sistema, si está disponible en el entorno de la máquina virtual. Se establece en UINT32_MAX en caso contrario. Ver vsock(7) para más detalles.

OperatingSystemSupportEnd expone cuándo finaliza el soporte del proveedor del SO, si esta información es conocida. Es un valor sin signo de 64 bits, en µs desde la época UNIX, UTC. Si esta información no se conoce, contiene el valor 2^64-1, es decir, UINT64_MAX.

OperatingSystemImageID y OperatingSystemImageVersion exponen el nombre y la versión de la imagen del SO si están disponibles, o contienen cadenas vacías en caso contrario. Esto corresponde principalmente a los campos IMAGE_ID= y IMAGE_VERSION= del archivo os-release.

HardwareVendor, HardwareModel, HardwareSKU y HardwareVersion exponen información del proveedor sobre el hardware del sistema. La unidad de mantenimiento de stock (SKU) describe un tipo distinto de hardware para la venta, compra o gestión de inventario. La SKU y la versión solo están disponibles si se desvían del modelo y entre sí. Por lo tanto, la versión es más específica y solo está disponible si difiere del modelo y la SKU. Si no se puede determinar dicha información, estas propiedades se establecen en cadenas vacías.

FirmwareVersion y FirmwareVendor exponen información sobre el firmware del sistema, es decir, una cadena de versión y un nombre de proveedor. Si no se puede determinar dicha información, estas propiedades se establecen en cadenas vacías.

FirmwareDate expone la fecha de compilación del firmware, si esa información se conoce. Es un valor sin signo de 64 bits, en µs desde la época UNIX, UTC. Si no se conoce, UNIT64_MAX.

ChassisAssetTag expone un identificador único del chasis del sistema. Si esta información no se conoce, esta propiedad se establece en una cadena vacía.

Métodos

SetHostname() establece el nombre de host transitorio (dinámico), que se utiliza si no se ha establecido un nombre de host estático. Este valor debe ser un nombre de host de estilo de Internet, ASCII en minúsculas de 7 bits, sin caracteres especiales/espacios. Una cadena vacía anulará el nombre de host transitorio.

SetStaticHostname() establece el nombre de host estático que expone la propiedad StaticHostname. Cuando se llama con un argumento vacío, se elimina la configuración estática en /etc/hostname. Dado que el nombre de host estático tiene la máxima prioridad, llamar a esta función generalmente también afecta a la propiedad Hostname y al nombre de host efectivo configurado en el kernel.

SetPrettyHostname() establece el nombre de host "bonito" que expone la propiedad PrettyHostname.

SetIconName(), SetChassis(), SetDeployment() y SetLocation() establecen las propiedades IconName (el nombre del icono que representa a la máquina), Chassis (el factor de forma de la máquina), Deployment (el entorno de implementación del sistema) y Location (la ubicación física del sistema), respectivamente.

PrettyHostname, IconName, Chassis, Deployment y Location se almacenan en /etc/machine-info. Ver machine-info(5) para la semántica de esta configuración.

GetProductUUID() devuelve el "UUID del producto" tal como lo expone el kernel basándose en la información DMI en /sys/class/dmi/id/product_uuid. La lectura directa del archivo requiere privilegios de root, y este método permite el acceso a clientes no privilegiados a través del framework polkit.

GetHardwareSerial() devuelve el "número de serie del hardware" tal como lo expone el kernel basándose en la información DMI. La lectura directa del archivo requiere privilegios de root, y este método permite el acceso a clientes no privilegiados a través del framework polkit.

Describe() devuelve una representación JSON de todas las propiedades en una sola.

Seguridad

Los parámetros booleanos interactive se pueden utilizar para controlar si polkit debe solicitar interactivamente al usuario credenciales de autenticación si son necesarios.

La acción de polkit para SetHostname() es org.freedesktop.hostname1.set-hostname. Para SetStaticHostname() y SetPrettyHostname() es org.freedesktop.hostname1.set-static-hostname. Para SetIconName(), SetChassis(), SetDeployment() y SetLocation() es org.freedesktop.hostname1.set-machine-info.

RECOMENDACIONES

Aquí hay tres ejemplos que muestran cómo se deben utilizar el nombre de host "bonito" y el nombre del icono:

•Al registrar servicios DNS-SD: use el nombre de host "bonito" en el nombre del servicio y pase el nombre del icono en los datos TXT, si existe un nombre de icono. Los clientes de exploración pueden mostrar el icono del servidor en cada servicio. Esto es especialmente útil para aplicaciones WebDAV o para compartir medios UPnP.
•Establezca el nombre de Bluetooth en el nombre de host "bonito".
•Cuando su explorador de archivos tenga un icono de "Ordenador", reemplace el nombre con el nombre de host "bonito" si está establecido, y el icono con el nombre del icono, si está establecido.

Para manejar correctamente las búsquedas de nombres con nombres de host locales cambiantes sin tener que editar /etc/hosts, recomendamos usar systemd-hostnamed en combinación con nss-myhostname(8).

Aquí hay algunas recomendaciones a seguir al generar un nombre de host estático (de Internet) a partir de un nombre "bonito":

•Genere solo una etiqueta DNS, no un FQDN. Eso significa que no se permiten puntos. Elimínelos o reemplácelos con "-".
•Probablemente sea más seguro no usar caracteres que no sean ASCII, incluso si DNS lo permite de alguna manera hoy en día. De hecho, restrinja su conjunto de caracteres a "a-zA-Z0-9" y "-". Elimine otros caracteres o intente reemplazarlos de manera inteligente con caracteres de este conjunto, por ejemplo, "ä" → "ae", y use "-" como reemplazo para todos los caracteres de puntuación y espacios en blanco.
•Intente evitar crear "-" repetidos, así como "-" como primer o último carácter.
•Limite el nombre de host a 63 caracteres, que es la longitud de una etiqueta DNS.
•Si después de eliminar los caracteres especiales el resultado es la cadena vacía, puede pasarla tal cual a systemd-hostnamed, en cuyo caso utilizará automáticamente un respaldo adecuado.
•Los caracteres en mayúsculas deben reemplazarse por sus equivalentes en minúsculas.

Tenga en cuenta que aunque systemd-hostnamed aplica algunas verificaciones al nombre de host que usted pasa, estas son mucho más flexibles que las recomendaciones anteriores. Por ejemplo, systemd-hostnamed también aceptará "_" en el nombre de host, pero recomendamos no usarlo para evitar conflictos con los tipos de servicio DNS-SD. Además, systemd-hostnamed permite nombres de host más largos, pero debido a las limitaciones de las etiquetas DNS, recomendamos no hacer uso de esto.

Aquí hay un par de ejemplos de conversiones:

•"El PC de Lennart" → "el-pc-de-lennart"
•"Ordenador de Müller" → "ordenador-de-muellers"
•"¡Adelante!" → "adelante"
•"Érase una vez un hombrecito" → "erase-un-hombrecito"
•"¡Claro que sí! ¡Es verdad!" → "claro-que-si-es-verdad"
•"localhost" → "localhost"
•"...¡zas!!! ¡zas!..." → "zas-zas"

Por supuesto, una etiqueta de nombre de host de Internet válida que ingrese y pase por esta conversión debe permanecer sin modificaciones, para que los usuarios tengan control directo sobre ella, si lo desean — simplemente ignorando el hecho de que el nombre de host "bonito" es bonito y editándolo como si fuera el nombre normal de Internet.
