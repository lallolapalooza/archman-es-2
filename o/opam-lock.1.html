NOMBRE

opam-lock - Crear archivos opam bloqueados para compartir entornos de compilación entre hosts.

SINOPSIS

opam lock [--direct-only] [--keep-local] [--lock-suffix=SUFIJO] [OPCIÓN]… [PAQUETES]…

DESCRIPCIÓN

Genera un archivo de bloqueo de un paquete: comprueba el estado actual de sus dependencias instaladas y genera versiones modificadas del archivo opam con un sufijo .locked, donde todas las dependencias (transitivas) y fijaciones se han limitado estrictamente a la versión actualmente instalada.

Al utilizar estos archivos opam bloqueados, es posible recuperar el entorno de compilación preciso que se configuró cuando se generaron.

Si se proporcionan rutas (nombre de archivo o directorio), se bloquearán esos archivos opam. Si se proporciona un paquete, se bloqueará el instalado, de lo contrario, su última versión. Si se proporciona un paquete fijado localmente, se bloqueará su archivo opam local actual, incluso si no está versionado o tiene cambios no confirmados.

Falla si todas las dependencias obligatorias no están instaladas en el switch.

CAMPOS CAMBIADOS DEL ARCHIVO DE BLOQUEO

- depends se fijan a sus versiones específicas, con todos los filtros eliminados (excepto las excepciones a continuación).

- depopts que están instalados en el switch actual se convierten en depends, con su versión establecida. Otros se establecen en el campo conflict.

- Los filtros `{dev}`, `{with-test}` y `{with-doc}` se conservan si todos los paquetes de un filtro específico están instalados en el switch. Las versiones se fijan y el mismo filtro se aplica a todas las dependencias que se añaden a partir de ellos.

- pin-depends se conservan y se añaden nuevos si en las dependencias algunos paquetes están fijados.

- Las fijaciones se resuelven: si un paquete está fijado localmente, opam intenta obtener su URL remota y rama, y la establece como URL de destino; de lo contrario, las ignora. Puede usar --keep-local para conservar las URL locales.

ARGUMENTOS

PAQUETES
Lista de nombres de paquetes, con una versión o restricción opcional, por ejemplo `pkg', `pkg.1.0' o `pkg>=0.5' ; o nombres de archivos o directorios que contienen la descripción del paquete, con un directorio explícito (por ejemplo, `./foo.opam' o `.')

OPCIONES

-d, --direct-only
Solo bloquea dependencias directas, en lugar de todo el árbol de dependencias.
--keep-local
Conserva las rutas de fijación locales en el campo 'pin-depends:'.
--lock-suffix=SUFIJO (ausente=locked)
Establece el sufijo de los archivos bloqueados en SUFIJO.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No falla si no se pueden instalar todos los paquetes solicitados: intenta instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (versiones recientes de aspcud o mccs deberían poder hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Diseñado para cualquier uso persistente de opam (scripts, publicaciones de blog, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. El flag no estaba disponible en opam 2.0, por lo que para seleccionar la CLI 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de utilizar este parámetro.

Colorea la salida. CUÁNDO debe ser uno de always, never o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de ask, no, yes o unsafe-yes. Se puede especificar varias veces. Si --yes o --no también se dan, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL`.
--criteria=CRITERIA
Especifica las preferencias del usuario para la resolución de dependencias en esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. --debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Igual que --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.

--json=NOMBRE_ARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por ordenador. Si el nombre del archivo contiene el carácter `%`, se reemplazará por un índice que no sobrescribirá un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.

Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.

Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet

--root=ROOT
Usa ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegura que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de finalización, por ejemplo. Fallará cada vez que se necesite dicha operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.

Falla siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.

OPAMSOLVERALLOWSUBOPTIMAL (predeterminado `true') permite que algunos solucionadores devuelvan una solución cuando alcanzan el tiempo límite; si bien se asegura que la solución sea consistente, en este caso no hay garantía de que cumpla los criterios de optimización esperados. Si es `true', opam continuará con una advertencia, si es `false' un tiempo límite es un error. Actualmente, solo el backend builtin-z3 maneja este caso degradado.

OPAMSOLVERTIMEOUT cambia el tiempo de asignación del solucionador. El valor predeterminado es 60.0, establecido en 0 para ilimitado. Tenga en cuenta que es posible que no todos los solucionadores admitan esta opción.

Los valores típicos van de 0.0 (la mejor solución conocida por el solucionador) a 1.0 (solución no optimizada). El valor predeterminado es 0.0. Esta opción es útil en caso de que el solucionador no pueda encontrar una solución en un tiempo razonable (ver $OPAMSOLVERTIMEOUT). Tenga en cuenta que es posible que no todos los solucionadores admitan esta opción.

CLI VERSION

This section details the CLI version of opam, and is generally of interest only to developers wishing to integrate opam into their workflow, or for the opam system itself.

This feature prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
