NOMBRE

org.freedesktop.timedate1 - La interfaz D-Bus de systemd-timedated

INTRODUCCIÓN

systemd-timedated.service(8) es un servicio del sistema que se puede utilizar para controlar la hora del sistema y la configuración relacionada. Esta página describe la interfaz D-Bus.

LA API DE D-BUS

El servicio expone las siguientes interfaces en el bus:

nodo /org/freedesktop/timedate1 {
  interfaz org.freedesktop.timedate1 {
    métodos:
      SetTime(in  x usec_utc,
              in  b relative,
              in  b interactive);
      SetTimezone(in  s timezone,
                  in  b interactive);
      SetLocalRTC(in  b local_rtc,
                  in  b fix_system,
                  in  b interactive);
      SetNTP(in  b use_ntp,
             in  b interactive);
      ListTimezones(out as timezones);
    propiedades:
      readonly s Timezone = '...';
      readonly b LocalRTC = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("false")
      readonly b CanNTP = ...;
      readonly b NTP = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("false")
      readonly b NTPSynchronized = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("false")
      readonly t TimeUSec = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("false")
      readonly t RTCTimeUSec = ...;
  };
  interfaz org.freedesktop.DBus.Peer { ... };
  interfaz org.freedesktop.DBus.Introspectable { ... };
  interfaz org.freedesktop.DBus.Properties { ... };
};

Métodos

Utiliza SetTime() para cambiar el reloj del sistema. Pasa un valor de microsegundos desde la época UNIX (1 de enero de 1970 UTC). Si relative es verdadero, el valor de usec pasado se añadirá a la hora actual del sistema. Si es falso, la hora actual del sistema se establecerá al valor de usec pasado. Si la hora del sistema se establece con este método, la RTC (Reloj de Tiempo Real) también se actualizará.

Utiliza SetTimezone() para establecer la zona horaria del sistema. Pasa un valor como "Europe/Berlin" para establecer la zona horaria. Las zonas horarias válidas se enumeran en /usr/share/zoneinfo/zone.tab. Si la RTC está configurada para mantenerse en hora local, se actualizará en consecuencia.

Utiliza SetLocalRTC() para controlar si la RTC está en hora local o UTC. Se recomienda encarecidamente mantener la RTC en UTC. Sin embargo, algunos sistemas operativos (Windows) mantienen la RTC en hora local, lo que puede hacer necesario habilitar esta función. Ten en cuenta que esto podría crear varios problemas, ya que los cambios de horario de verano podrían pasarse por alto. Si fix_system es "true", se vuelve a leer la hora de la RTC y el reloj del sistema se ajusta según la nueva configuración. Si fix_system es "false", la hora del sistema se escribe en la RTC teniendo en cuenta la nueva configuración. Utiliza fix_system=true en instaladores y livecds donde la RTC es probablemente más fiable que la hora del sistema. Utiliza fix_system=false en interfaces de configuración que se ejecutan durante la operación normal y donde el reloj del sistema es probablemente más fiable que la RTC.

Utiliza SetNTP() para controlar si el reloj del sistema se sincroniza con la red utilizando systemd-timesyncd. Esto habilitará e iniciará o deshabilitará y detendrá el servicio de sincronización horaria elegido.

ListTimezones() devuelve una lista de zonas horarias conocidas en el sistema local como un array de nombres ("["Africa/Abidjan", "Africa/Accra", ..., "UTC"]").

Propiedades

Timezone muestra la zona horaria configurada actualmente. LocalRTC muestra si la RTC está configurada para usar UTC (falso) o la zona horaria local (verdadero). CanNTP muestra si hay disponible un servicio para realizar la sincronización horaria a través de la red, y NTP muestra si dicho servicio está habilitado.

NTPSynchronized muestra si el kernel informa de que la hora está sincronizada (véase adjtimex(3)). TimeUSec y RTCTimeUSec muestran la hora actual en el sistema y en la RTC. El propósito de estas tres propiedades es permitir que los clientes remotos accedan a esta información a través de D-Bus. Los clientes locales pueden acceder a la información directamente.

Siempre que la configuración de Timezone y LocalRTC se cambie a través del demonio, se enviarán señales PropertyChanged a los clientes que se hayan suscrito.

Ten en cuenta que este servicio no te informará sobre los cambios en la hora del sistema. Utiliza timerfd(3) con CLOCK_REALTIME y TFD_TIMER_CANCEL_ON_SET para ello.

Seguridad

Los parámetros booleanos interactive se pueden utilizar para controlar si polkit[1] debe solicitar interactivamente las credenciales de autenticación al usuario si son necesarias.

La acción de polkit para SetTimezone() es org.freedesktop.timedate1.set-timezone. Para SetLocalRTC() es org.freedesktop.timedate1.set-local-rtc, para SetTime() es org.freedesktop.timedate1.set-time y para SetNTP() es org.freedesktop.timedate1.set-ntp. ListTimezones() no requiere ningún privilegio.
