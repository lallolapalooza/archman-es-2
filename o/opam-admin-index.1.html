OPAM ADMIN-INDEX(1) Manual de administración de Opam OPAM ADMIN-INDEX(1)

NOMBRE

opam admin index - Genera un archivo de índice inclusivo para servir a través de HTTP.

SINOPSIS

opam admin index [--full-urls-txt] [--minimal-urls-txt] [--no-urls-txt] [OPCIÓN]…

DESCRIPCIÓN

Un repositorio de opam puede ser servido a través de HTTP o HTTPS usando cualquier servidor web. Para ese propósito, primero se necesita generar un índice inclusivo: este comando genera los archivos que el cliente opam esperará al descargar desde un remoto HTTP, y debería ejecutarse después de cualquier cambio realizado en el contenido del repositorio.

OPCIONES

--full-urls-txt
Genera un 'urls.txt' inclusivo, para un repositorio que será utilizado por versiones de opam anteriores a la 2.0.
--minimal-urls-txt
Genera un archivo 'urls.txt' mínimo, que solo incluye el archivo 'repo'. Esto permite que las versiones de opam anteriores a la 2.0 lean ese archivo, y sean redirigidas correctamente a un repositorio dedicado a su versión, asumiendo que se define un campo 'redirect:' adecuado, en lugar de fallar. Este es el comportamiento predeterminado.
--no-urls-txt
No genera un archivo 'urls.txt'. Ese archivo de índice ya no es necesario a partir de opam 2.0, pero todavía es utilizado por versiones más antiguas.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intenta instalar tantos como sea posible. Ten en cuenta que no todos los solucionadores externos pueden soportar esta opción (versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Previsto para cualquier uso persistente de opam (scripts, posts de blog, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. La bandera no estaba disponible en opam 2.0, por lo que para seleccionar la interfaz de línea de comandos 2.0, establece la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o unsafe-yes. Se puede especificar más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL`.
--criteria=CRITERIOS
Especifica las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para detalles sobre el lenguaje soportado, y los solucionadores externos disponibles, consulta http://opam.ocaml.org/doc/External_solvers.html. Una guía general para usar las preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBREARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en NOMBREARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece a 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está configurada (es decir, si estás usando una versión de desarrollo), y sale.
--help[=FMT] (predeterminado=auto)
Muestra esta ayuda en el formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora pines adicionales requeridos por paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBREARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%', se reemplazará por un índice que no sobrescribirá un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio que está escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Ten en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato anterior. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Usa ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegura que nada será actualizado o reescrito automáticamente. Útil para llamar desde scripts de completado, por ejemplo. Fallará siempre que se necesite tal operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el solucionador CUDF a usar para resolver problemas de instalación de paquetes. Esto es un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentre un error en la definición de un paquete o un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.
--switch=SWITCH
Usa SWITCH como el switch del compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier solucionador externo, y usa el interno (esto requiere que opam haya sido compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más verboso. Una -v muestra todos los comandos de paquetes, repetir para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra información de la versión.
-w, --working-dir
Siempre que se actualicen paquetes que estén vinculados a un directorio local controlado por versión, actualiza al estado de trabajo actual de su fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio fuente se copia tal cual, si no está limpio, puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

All options that are not flags can be set using an environment variable of the same name, in uppercase. For example, setting OPAMJOBS to 4 is equivalent to running `opam --jobs=4'.

OPAM_USER_DIR is the directory that opam uses to store its configuration and packages, defaults to ~/.opam.

OPAM_CONFIG_DIR is the directory that opam uses to store its configuration files, defaults to $OPAM_USER_DIR/config.

OPAM_PACKAGE_DIR is the directory that opam uses to store the downloaded sources and build directories, defaults to $OPAM_USER_DIR/download.

OPAM_CACHE_DIR is the directory that opam uses to store the build cache, defaults to $OPAM_USER_DIR/cache.

OPAM_ROOT is the directory that opam uses as the root of its package database. This is often set by `opam env` and is normally set to $OPAM_USER_DIR/system.

OPAM_SWITCH_PREFIX is the directory that opam uses as the prefix for the current switch. This is often set by `opam env` and is normally set to $OPAM_ROOT/switches/$OPAM_SWITCH_NAME.

If `true', opam willcontinue with a warning, if `false' a timeout is an error. Currently only the builtin-z3 backend handles this degraded case.

OPAMSOLVERTIMEOUT change the time allowance of the solver. Default is 60.0, set to 0 for unlimited. Note that all solvers may not support this option.

OPAMSOLVERTOLERANCE changes the tolerance towards the solver choosing an unoptimized solution (i.e. might pull outdated packages). This option is useful in case the solver can't find a solution in a reasonable time (see $OPAMSOLVERTIMEOUT). Note that all solvers may not support this option.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
10
No se pudieron adquirir los bloqueos necesarios para la operación.
20
No existe una solución para la solicitud del usuario. Esto puede ser causado por solicitar la instalación de dos paquetes incompatibles, por ejemplo.
30
Error en la definición del paquete o en otros archivos de metadatos. El uso de --strict aumenta la frecuencia de este error.
31
Error en el script del paquete. Algunas operaciones del paquete no se realizaron correctamente. Puede ser un error en los paquetes o una incompatibilidad con su sistema. Puede ser un error parcial.
40
Error de sincronización. No se pudieron obtener algunos remotos de la red. Puede ser un error parcial.
50
Error de configuración. La configuración de Opam o del sistema no permite la operación y necesita ser corregida.
60
Fallo del solucionador. El solucionador no pudo devolver una respuesta sólida. Puede ser debido a un solucionador externo defectuoso o a un error en la configuración del solucionador.
99
Error interno. Algo salió mal, probablemente debido a un error en el propio opam.
130
Interrupción del usuario. Se recibió SIGINT, generalmente debido a que el usuario presionó Ctrl-C.
0
en caso de éxito.
123
en errores indiscriminados reportados en la salida estándar.
124
en errores de análisis de línea de comandos.
125
en errores internos inesperados (bugs).
