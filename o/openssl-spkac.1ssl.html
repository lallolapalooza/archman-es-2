NOMBRE

openssl-spkac - Comando para imprimir y generar SPKAC

SINOPSIS

openssl spkac [-help] [-in archivo] [-out archivo] [-digest digest] [-key archivo|uri] [-keyform DER|PEM|P12|ENGINE] [-passin arg] [-challenge cadena] [-pubkey] [-spkac nombre_spkac] [-spksect seccion] [-noout] [-verify] [-engine id] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq]

DESCRIPCIÓN

Este comando procesa archivos de clave pública firmada y desafío (SPKAC) de Netscape. Puede imprimir su contenido, verificar la firma y producir sus propios SPKAC a partir de una clave privada proporcionada.

OPCIONES

-help
Imprime un mensaje de uso.
-in archivo
Este especifica el nombre del archivo de entrada a leer o la entrada estándar si no se especifica esta opción. Ignorado si se usa la opción -key.
-out archivo
Especifica el nombre del archivo de salida al que escribir o la salida estándar por defecto.
-digest digest
Utiliza el digest especificado para firmar un archivo SPKAC creado. El algoritmo de digest por defecto es MD5.
-key archivo|uri
Crea un archivo SPKAC usando la clave privada especificada por archivo o uri. Las opciones -in, -noout, -spksect y -verify se ignoran si están presentes.
-keyform DER|PEM|P12|ENGINE
El formato de la clave; no especificado por defecto. Vea openssl-format-options(1) para más detalles.
-passin arg
La fuente de la contraseña del archivo de entrada. Para más información sobre el formato de arg, vea openssl-passphrase-options(1).
-challenge cadena
Especifica la cadena de desafío si se está creando un SPKAC.
-spkac nombre_spkac
Permite un nombre alternativo para la variable que contiene el SPKAC. El valor por defecto es "SPKAC". Esta opción afecta tanto a los SPKAC generados como a los de entrada.
-spksect seccion
Permite un nombre alternativo para la sección que contiene el SPKAC. El valor por defecto es la sección por defecto.
-noout
No imprimir la versión en texto del SPKAC (no se usa si se está creando un SPKAC).
-pubkey
Imprime la clave pública de un SPKAC (no se usa si se está creando un SPKAC).
-verify
Verifica la firma digital en el SPKAC proporcionado.
-engine id
Vea "Opciones de motor" en openssl(1). Esta opción está obsoleta.
-provider nombre
-provider-path ruta
-provparam [nombre:]clave=valor
-propquery propq
Vea "Opciones de proveedor" en openssl(1), provider(7) y property(7).

EJEMPLOS

Imprimir el contenido de un SPKAC:

openssl spkac -in spkac.cnf

Verificar la firma de un SPKAC:

openssl spkac -in spkac.cnf -noout -verify

Crear un SPKAC usando la cadena de desafío "hola":

openssl spkac -key key.pem -challenge hola -out spkac.cnf

Ejemplo de un SPKAC, (líneas largas divididas para mayor claridad):

SPKAC=MIG5MGUwXDANBgkqhkiG9w0BAQEFAANLADBIAkEA\
1cCoq2Wa3Ixs47uI7FPVwHVIPDx5yso105Y6zpozam135a\
8R0CpoRvkkigIyXfcCjiVi5oWk+6FfPaD03uPFoQIDAQAB\
FgVoZWxsbzANBgkqhkiG9w0BAQQFAANBAFpQtY/FojdwkJ\
h1bEIYuc2EeM2KHTWPEepWYeawvHD0gQ3DngSC75YCWnnD\
dq+NQ3F+X4deMx9AaEglZtULwV4=

NOTAS

Un SPKAC creado con los componentes DN adecuados añadidos puede ser introducido a openssl-ca(1).

Los SPKAC son generados típicamente por Netscape cuando se envía un formulario que contiene la etiqueta KEYGEN como parte del proceso de inscripción del certificado.

La cadena de desafío permite una forma primitiva de prueba de posesión de la clave privada. Al verificar la firma del SPKAC y una cadena de desafío aleatoria, se da una cierta garantía de que el usuario conoce la clave privada correspondiente a la clave pública que se está certificando. Esto es importante en algunas aplicaciones. Sin esto, es posible que se utilice un SPKAC anterior en un "ataque de repetición".
