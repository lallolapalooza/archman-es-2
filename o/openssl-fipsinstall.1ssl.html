NOMBRE

openssl-fipsinstall - realiza la instalación de la configuración FIPS

SINOPSIS

openssl fipsinstall [-help] [-in nombre_archivo_config] [-out nombre_archivo_config] [-module nombre_archivo_modulo] [-provider_name nombre_proveedor] [-section_name nombre_seccion] [-verify] [-mac_name nombre_mac] [-macopt nm:v] [-noout] [-quiet] [-pedantic] [-no_conditional_errors] [-no_security_checks] [-hmac_key_check] [-kmac_key_check] [-ems_check] [-no_drbg_truncated_digests] [-signature_digest_check] [-hkdf_digest_check] [-tls13_kdf_digest_check] [-tls1_prf_digest_check] [-sshkdf_digest_check] [-sskdf_digest_check] [-x963kdf_digest_check] [-dsa_sign_disabled] [-no_pbkdf2_lower_bound_check] [-no_short_mac] [-tdes_encrypt_disabled] [-rsa_pkcs15_padding_disabled] [-rsa_pss_saltlen_check] [-rsa_sign_x931_disabled] [-hkdf_key_check] [-kbkdf_key_check] [-tls13_kdf_key_check] [-tls1_prf_key_check] [-sshkdf_key_check] [-sskdf_key_check] [-x963kdf_key_check] [-x942kdf_key_check] [-ecdh_cofactor_check] [-self_test_onload] [-self_test_oninstall] [-corrupt_desc descripcion_autoeval] [-corrupt_type tipo_autoeval] [-config config_padre]

DESCRIPCIÓN

Este comando se utiliza para generar un archivo de configuración del módulo FIPS. Este archivo de configuración se puede utilizar cada vez que se carga un módulo FIPS para pasar datos a las auto-pruebas del módulo FIPS. El módulo FIPS siempre verifica su MAC, pero opcionalmente solo necesita ejecutar los KAT una vez, en la instalación.

El archivo de configuración generado consta de:

- Un MAC del archivo del módulo FIPS.
- Un indicador de estado de prueba.
Esto indica si las Auto-Pruebas de Respuesta Conocida (KATs) se han ejecutado correctamente.
- Un MAC del indicador de estado.
- Un control para errores de auto-prueba condicionales.
Por defecto, si falla una prueba continua (por ejemplo, una prueba de par de claves), el módulo FIPS entrará en un estado de error, y no se podrá acceder a ningún servicio o algoritmo criptográfico a partir de ese momento. El valor por defecto de '1' provocará la entrada en el estado de error del módulo FIPS. Si el valor es '0', no se entrará en el estado de error del módulo. Independientemente de si se entra o no en el estado de error, la operación actual (por ejemplo, la generación de claves) devolverá un error. El usuario es responsable de reintentar la operación si no se entra en el estado de error del módulo.
- Un control para indicar si se realizan comprobaciones de seguridad en tiempo de ejecución.
Esto indica si se utilizan comprobaciones en tiempo de ejecución relacionadas con la aplicación de parámetros de seguridad, como la fuerza mínima de las claves y los nombres de curvas aprobados. El valor por defecto de '1' realizará las comprobaciones. Si el valor es '0', no se realizarán las comprobaciones y el cumplimiento de FIPS debe hacerse mediante los procedimientos documentados en la Política de Seguridad relevante.

Este archivo se describe en fips_config(5).

OPCIONES

-help
Imprime un mensaje de uso.
-module nombre_archivo
Nombre del archivo del módulo FIPS al que realizar una comprobación de integridad. La ruta proporcionada en el nombre del archivo se utiliza para cargar el módulo cuando se activa, y esto anula la variable de entorno OPENSSL_MODULES.
-out nombre_archivo_config
Nombre del archivo donde se volcarán los datos de configuración; el valor por defecto es la salida estándar.
-in nombre_archivo_config
Nombre del archivo de entrada desde el que cargar los datos de configuración. Debe usarse si se especifica la opción -verify.
-verify
Verifica que el archivo de configuración de entrada contiene la información correcta.
-provider_name nombre_proveedor
Nombre del proveedor dentro del archivo de configuración. El valor por defecto es "fips".
-section_name nombre_seccion
Nombre de la sección dentro del archivo de configuración. El valor por defecto es "fips_sect".
-mac_name nombre
Especifica el nombre de un algoritmo MAC compatible que se utilizará. Los mecanismos MAC disponibles dependerán de las opciones utilizadas al compilar OpenSSL. Para ver la lista de MACs compatibles, usa el comando "openssl list -mac-algorithms". El valor por defecto es HMAC.
-macopt nm:v
Pasa opciones al algoritmo MAC. Se puede encontrar una lista completa de controles en la documentación de implementación de EVP_MAC. Las cadenas de control comunes utilizadas para este comando son:
key:cadena
Especifica la clave MAC como una cadena alfanumérica (usar si la clave contiene solo caracteres imprimibles). La longitud de la cadena debe cumplir cualquier restricción del algoritmo MAC. Se debe especificar una clave para cada algoritmo MAC. Si no se proporciona ninguna clave, se utiliza la clave por defecto especificada al configurar OpenSSL.
hexkey:cadena
Especifica la clave MAC en formato hexadecimal (dos dígitos hexadecimales por byte). La longitud de la clave debe cumplir cualquier restricción del algoritmo MAC. Se debe especificar una clave para cada algoritmo MAC. Si no se proporciona ninguna clave, se utiliza la clave por defecto especificada al configurar OpenSSL.
digest:cadena
Utilizado por HMAC como una cadena alfanumérica (usar si la clave contiene solo caracteres imprimibles). La longitud de la cadena debe cumplir cualquier restricción del algoritmo MAC. Para ver la lista de resúmenes compatibles, usa el comando "openssl list -digest-commands". El resumen por defecto es SHA-256.
-noout
Deshabilita el registro de las auto-pruebas.
-pedantic
Configura el módulo para que sea estrictamente compatible con FIPS en lugar de ser compatible con versiones anteriores. Esto habilita errores condicionales, comprobaciones de seguridad, etc. Ten en cuenta que cualquier opción de configuración anterior se sobrescribirá y cualquier opción de configuración subsiguiente que viole la conformidad FIPS resultará en un error.
-no_conditional_errors
Configura el módulo para que no entre en estado de error si falla una auto-prueba condicional, como se describe anteriormente.
-no_security_checks
Configura el módulo para que no realice comprobaciones de seguridad en tiempo de ejecución, como se describe anteriormente.

Habilitar la opción de configuración "no-fips-securitychecks" proporciona otra forma de desactivar la comprobación en tiempo de compilación.

-ems_check
Configura el módulo para habilitar una comprobación en tiempo de ejecución del Secreto Maestro Extendido (EMS) al usar el algoritmo KDF TLS1_PRF. Esta comprobación está deshabilitada por defecto. Consulta RFC 7627 para obtener información sobre EMS.
-no_short_mac
Configura el módulo para no permitir salidas MAC cortas. Consulta SP 800-185 8.4.2 y FIPS 140-3 ID C.D para obtener detalles.
-hmac_key_check
Configura el módulo para no permitir tamaños de clave pequeños al usar HMAC. Consulta SP 800-131Ar2 para obtener detalles.
-kmac_key_check

OPTIONS

-kmac_key_check
Configure the module to not allow small key sizes when using KMAC. See SP 800-131Ar2 for details.
-no_drbg_truncated_digests
Configure the module to not allow truncated digests to be used with Hash and HMAC DRBGs. See FIPS 140-3 IG D.R for details.
-signature_digest_check
Configure the module to enforce signature algorithms to use digests that are explicitly permitted by the various standards.
-hkdf_digest_check
This option is deprecated.
-tls13_kdf_digest_check
Configure the module to enable a run-time digest check when deriving a key by TLS13 KDF. See RFC 8446 for details.
-tls1_prf_digest_check
Configure the module to enable a run-time digest check when deriving a key by TLS_PRF. See NIST SP 800-135r1 for details.
-sshkdf_digest_check
Configure the module to enable a run-time digest check when deriving a key by SSHKDF. See NIST SP 800-135r1 for details.
-sskdf_digest_check
This option is deprecated.
-x963kdf_digest_check
Configure the module to enable a run-time digest check when deriving a key by X963KDF. See NIST SP 800-131Ar2 for details.
-dsa_sign_disabled
Configure the module to not allow DSA signing (DSA signature verification is still allowed). See FIPS 140-3 IG C.K for details.
-tdes_encrypt_disabled
Configure the module to not allow Triple-DES encryption. Triple-DES decryption is still allowed for legacy purposes. See SP800-131Ar2 for details.
-rsa_pkcs15_padding_disabled
Configure the module to not allow PKCS#1 version 1.5 padding to be used with RSA for key transport and key agreement. See NIST's SP 800-131A Revision 2 for details.
-rsa_pss_saltlen_check
Configure the module to enable a run-time salt length check when generating or verifying a RSA-PSS signature. See FIPS 186-5 5.4 (g) for details.
-rsa_sign_x931_disabled
Configure the module to not allow X9.31 padding to be used when signing with RSA. See FIPS 140-3 IG C.K for details.
-hkdf_key_check
Configure the module to enable a run-time short key-derivation key check when deriving a key by HKDF. See NIST SP 800-131Ar2 for details.
-kbkdf_key_check
Configure the module to enable a run-time short key-derivation key check when deriving a key by KBKDF. See NIST SP 800-131Ar2 for details.
-tls13_kdf_key_check
Configure the module to enable a run-time short key-derivation key check when deriving a key by TLS13 KDF. See NIST SP 800-131Ar2 for details.
-tls1_prf_key_check
Configure the module to enable a run-time short key-derivation key check when deriving a key by TLS_PRF. See NIST SP 800-131Ar2 for details.
-sshkdf_key_check
Configure the module to enable a run-time short key-derivation key check when deriving a key by SSHKDF. See NIST SP 800-131Ar2 for details.
-sskdf_key_check
Configure the module to enable a run-time short key-derivation key check when deriving a key by SSKDF. See NIST SP 800-131Ar2 for details.
-x963kdf_key_check
Configure the module to enable a run-time short key-derivation key check when deriving a key by X963KDF. See NIST SP 800-131Ar2 for details.
-x942kdf_key_check
Configure the module to enable a run-time short key-derivation key check when deriving a key by X942KDF. See NIST SP 800-131Ar2 for details.
-no_pbkdf2_lower_bound_check
Configure the module to not perform run-time lower bound check for PBKDF2. See NIST SP 800-132 for details.
-ecdh_cofactor_check
Configure the module to enable a run-time check that ECDH uses the EC curves cofactor value when deriving a key. This only affects the 'B' and 'K' curves. See SP 800-56A r3 Section 5.7.1.2 for details.
-self_test_onload
Do not write the two fields related to the "test status indicator" and "MAC status indicator" to the output configuration file. Without these fields the self tests KATS will run each time the module is loaded. This option could be used for cross compiling, since the self tests need to run at least once on each target machine. Once the self tests have run on the target machine the user could possibly then add the 2 fields into the configuration using some other mechanism. This option defaults to 0 for any OpenSSL FIPS 140-2 provider (OpenSSL 3.0.X). and is not relevant for an OpenSSL FIPS 140-3 provider, since this is no longer allowed.
-self_test_oninstall
The converse of -self_test_oninstall. The two fields related to the "test status indicator" and "MAC status indicator" are written to the output configuration file. This field is not relevant for an OpenSSL FIPS 140-3 provider, since this is no longer allowed.
-quiet
Do not output pass/fail messages. Implies -noout.
-corrupt_desc selftest_description, -corrupt_type selftest_type
The corrupt options can be used to test failure of one or more self tests by name. Either option or both may be used to select the tests to corrupt. Refer to the entries for st-desc and st-type in OSSL_PROVIDER-FIPS(7) for values that can be used.
-config parent_config
Test that a FIPS provider can be loaded from the specified configuration file. A previous call to this application needs to generate the extra configuration data that is included by the base "parent_config" configuration file. See config(5) for further information on how to set up a provider section. All other options are ignored if '-config' is used.

NOTES

Self tests results are logged by default if the options -quiet and -noout are not specified, or if either of the options -corrupt_desc or -corrupt_type are used. If the base configuration file is set up to autoload the fips module, then the fips module will be loaded and self tested BEFORE the fipsinstall application has a chance to set up its own self test callback. As a result of this the self test output and the options -corrupt_desc and -corrupt_type will be ignored. For normal usage the base configuration file should use the default provider when generating the fips configuration file.

The -self_test_oninstall option was added and the -self_test_onload option was made the default in OpenSSL 3.1.

The command and all remaining options were added in OpenSSL 3.0.

EXAMPLES

Calculate the mac of a FIPS module fips.so and run a FIPS self test for the module, and save the fips.cnf configuration file:

openssl fipsinstall -module ./fips.so -out fips.cnf -provider_name fips

Verify that the configuration file fips.cnf contains the correct info:

openssl fipsinstall -module ./fips.so -in fips.cnf  -provider_name fips -verify

Corrupt any self tests which have the description "SHA1":

openssl fipsinstall -module ./fips.so -out fips.cnf -provider_name fips \
        -corrupt_desc 'SHA1'

Validate that the fips module can be loaded from a base configuration file:

export OPENSSL_CONF_INCLUDE=<path of configuration files>
export OPENSSL_MODULES=<provider-path>
openssl fipsinstall -config' 'default.cnf'

DESCRIPTION

The openssl command can be used to perform various operations related to FIPS mode. These operations include installing, loading, updating, checking, and performing cryptographic tests within FIPS mode. Each of the commands listed in the SYNOPSIS section corresponds to a specific FIPS-related operation.

The commands generally operate by interacting with the FIPS provider or FIPS-capable cryptographic modules. They may require specific inputs such as keys, certificates, or configuration files, and may produce output files or status messages indicating the success or failure of the operation.

Detailed descriptions of each command and their respective options are beyond the scope of this overview. Users should consult the specific man pages for each command (e.g., man openssl-fipsinstall) for detailed usage instructions, options, and examples.

OPTIONS

The available options vary significantly depending on the specific FIPS command being used. Common options may include:

  • Options for specifying input and output files.
  • Options for selecting cryptographic algorithms or modes.
  • Options for providing passwords or passphrases.
  • Options for setting configuration parameters.
  • Options for controlling verbosity or debugging output.

Refer to the individual man pages for each command for a complete list of supported options.

EXAMPLES

The examples below illustrate the general usage pattern. Specific commands will have their own unique examples.

openssl -fipsinstall -config fips.cnf

openssl -fipsload -module fipsmodule.cnf

openssl -fipscheck

openssl -fipskeycheck -key private.key -in public.pem

HISTORY

All commands were added in OpenSSL 3.0.

The following commands are new in OpenSSL 3.2:

-hkdf_key_check, -kbkdf_key_check, -tls13_kdf_key_check, -tls1_prf_key_check, -sshkdf_key_check, -sskdf_key_check, -x963kdf_key_check, -x942kdf_key_check, -ecdh_cofactor_check
