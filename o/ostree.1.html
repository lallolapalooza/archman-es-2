NOMBRE

ostree - Gestiona múltiples árboles de sistemas de archivos versionados y arrancables

SINOPSIS

ostree {COMANDO} [OPCIONES...]

DESCRIPCIÓN

OSTree es una herramienta para gestionar múltiples árboles de sistemas de archivos versionados y arrancables, o simplemente "árboles" para abreviar. En el modelo de OSTree, los sistemas operativos ya no residen en el directorio raíz físico "/". En su lugar, se instalan en paralelo en el nuevo directorio de nivel superior /ostree. Cada sistema instalado obtiene su propio directorio /ostree/deploy/stateroot. (stateroot es el término más reciente para osname).

A diferencia de rpm o dpkg, OSTree solo es consciente de árboles de sistemas de archivos completos. No tiene conocimiento incorporado de qué componentes se utilizaron para crear el árbol del sistema de archivos.

Es posible utilizar OSTree en varios modos; la forma más básica es replicar árboles precompilados desde un servidor de compilación. Por lo general, estos árboles precompilados se derivan de paquetes. También puede estar utilizando OSTree debajo de una herramienta de nivel superior que calcula árboles de sistemas de archivos localmente.

Se debe enfatizar que OSTree solo soporta árboles de solo lectura. Para cambiar a un árbol diferente (actualizar, degradar, instalar software), se verifica un nuevo árbol y se realiza una fusión de 3 vías de la configuración. El árbol que se está ejecutando actualmente nunca se modifica; el nuevo árbol se activará en el próximo reinicio del sistema.

Para ver la página del manual de un comando, ejecute man ostree COMANDO o man ostree-admin COMANDO

OPCIONES

Las siguientes opciones son reconocidas:

--repo

Para la mayoría de los comandos, se requiere un repositorio. Si no se especifica, se utiliza el directorio actual si parece ser un repositorio OSTree. Si no lo es, se utiliza la variable de entorno OSTREE_REPO o el repositorio del sistema ubicado en /sysroot/ostree/repo.

-v, --verbose

Produce salida a nivel de depuración.

--version

Imprime información de la versión, incluidas las funciones habilitadas en el momento de la compilación, y sale.

VERIFICACIÓN GPG

OSTree admite la firma de commits con GPG. Las operaciones en el repositorio del sistema utilizan por defecto archivos de llavero en /usr/share/ostree/trusted.gpg.d. Cualquier clave pública en un archivo de llavero en ese directorio será confiable para el cliente. No deben haber claves privadas en este directorio.

Además del repositorio del sistema, OSTree admite dos rutas más. Primero, hay una opción gpgkeypath para remotos, que debe apuntar al nombre del archivo de una clave GPG en formato ASCII o a un directorio que contenga claves GPG en formato ASCII para importar. Se pueden especificar varias rutas de archivos y directorios para importar, como una lista separada por comas de rutas. Esta opción se puede especificar usando --set en ostree remote add.

Segundo, hay soporte para un archivo remotename.trustedkeys.gpg por remoto almacenado en el nivel superior del repositorio (junto a objects/ y similares). Esto es particularmente útil cuando se descargan contenidos que pueden no ser completamente confiables (por ejemplo, desea inspeccionarlos pero no implementarlos como un sistema operativo, o usarlos para contenedores. Este archivo se escribe a través de ostree remote add --gpg-import.

TERMINOLOGÍA

Los siguientes términos se usan comúnmente en todas las páginas del manual. Los términos en mayúsculas son literales utilizados en los argumentos de la línea de comandos.

TERMINOLOGY

BRANCH

Nombre de rama. Parte de un REF.

CHECKSUM

Un hash SHA256 de un objeto almacenado en el repositorio OSTree. Este puede ser un objeto de contenido, un árbol de directorios (dirtree), metadatos de directorio (dirmeta) o un objeto de confirmación (commit). Si se pretende el hash SHA256 de un objeto de confirmación, se usa el término COMMIT.

COMMIT

Un hash SHA256 de un objeto de confirmación.

REF

Una referencia a una confirmación particular. Las referencias son archivos de texto almacenados en refs/ que nombran (se refieren a) una confirmación particular. Una referencia solo puede ser la parte del nombre de rama, en cuyo caso se utiliza una referencia local (ej. mybranch/stable). Si se hace referencia a una rama remota, se debe usar el nombre del remoto seguido de dos puntos y el nombre de la rama (ej. myremote:mybranch/stable).

REV, REFSPEC

Una revisión específica, una confirmación. Esto puede ser cualquier cosa que se pueda resolver a una confirmación, por ejemplo, un REF o un COMMIT.

SHA256

Una función hash criptográfica utilizada para almacenar objetos en el repositorio OSTree. Los hashes tienen una longitud de 256 bits y típicamente se muestran y se pasan a ostree en su representación hexadecimal de 64 caracteres ASCII (ej. 0fc70ed33cfd7d26fe99ae29afb7682ddd0e2157a4898bd8cfcdc8a03565b870).
