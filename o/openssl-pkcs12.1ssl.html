NOMBRE

openssl-pkcs12 - comando de archivo PKCS#12

SINOPSIS

openssl pkcs12 [-help] [-passin arg] [-passout arg] [-password arg] [-twopass] [-in nombre_archivo|uri] [-out nombre_archivo] [-nokeys] [-nocerts] [-noout] [-legacy] [-engine id] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq] [-rand archivos] [-writerand archivo]

Opciones de entrada PKCS#12 (análisis): [-info] [-nomacver] [-clcerts] [-cacerts]

[-aes128] [-aes192] [-aes256] [-aria128] [-aria192] [-aria256] [-camellia128] [-camellia192] [-camellia256] [-des] [-des3] [-idea] [-noenc] [-nodes]

Opciones de salida PKCS#12 (exportación):

[-export] [-inkey nombre_archivo|uri] [-certfile nombre_archivo] [-passcerts arg] [-chain] [-untrusted nombre_archivo] [-CAfile archivo] [-no-CAfile] [-CApath dir] [-no-CApath] [-CAstore uri] [-no-CAstore] [-name nombre] [-caname nombre] [-CSP nombre] [-LMK] [-keyex] [-keysig] [-keypbe cifrado] [-certpbe cifrado] [-descert] [-macalg resumen] [-pbmac1_pbkdf2] [-pbmac1_pbkdf2_md resumen] [-iter contador] [-noiter] [-nomaciter] [-maciter] [-macsaltlen] [-nomac] [-jdktrust uso]

DESCRIPCIÓN

Este comando permite crear y analizar archivos PKCS#12 (a veces denominados archivos PFX). Los archivos PKCS#12 son utilizados por varios programas, incluyendo Netscape, MSIE y MS Outlook.

OPCIONES

Hay muchas opciones, el significado de algunas depende de si se está creando o analizando un archivo PKCS#12. Por defecto, se analiza un archivo PKCS#12. Se puede crear un archivo PKCS#12 usando la opción -export (ver más abajo). Las opciones de cifrado y MAC de exportación PKCS#12 como -certpbe y -iter, y muchas opciones adicionales como -chain, solo son relevantes con -export. Por el contrario, las opciones relativas al cifrado de claves privadas al exportar la entrada PKCS#12 solo son relevantes cuando la opción -export no se proporciona.

El algoritmo de cifrado por defecto es AES-256-CBC con PBKDF2 para la derivación de claves.

Al encontrar problemas al cargar archivos PKCS#12 antiguos que involucran, por ejemplo, RC2-40-CBC, intente usar la opción -legacy y, si es necesario, la opción -provider-path.

-help
Muestra un mensaje de uso.
-passin arg
Fuente de la contraseña para la entrada, y para cifrar cualquier clave privada que se exporte. Para más información sobre el formato de arg, véase openssl-passphrase-options(1).
-passout arg
Fuente de la contraseña para los archivos de salida.
-password arg
Con -export, -password es equivalente a -passout, de lo contrario es equivalente a -passin.
-twopass
Solicitar contraseñas separadas para integridad y cifrado: la mayoría del software siempre asume que son las mismas, por lo que esta opción hará que dichos archivos PKCS#12 sean ilegibles. No se puede usar en combinación con las opciones -password, -passin si se importa desde PKCS#12, o -passout si se exporta.
-nokeys
No se exportarán claves privadas.
-nocerts
No se exportarán certificados.
-noout
Esta opción inhibe toda la exportación de credenciales, por lo que la entrada solo se verifica.
-legacy
Utiliza el modo de operación heredado y carga automáticamente el proveedor heredado. Si OpenSSL no está instalado en todo el sistema, es necesario usar también, por ejemplo, "-provider-path ./providers" o establecer la variable de entorno OPENSSL_MODULES para que apunte al directorio donde se pueden encontrar los proveedores.

En el modo heredado, el algoritmo por defecto para el cifrado de certificados es RC2_CBC o 3DES_CBC dependiendo de si el cifrado RC2 está habilitado en la compilación. El algoritmo por defecto para el cifrado de claves privadas es 3DES_CBC. Si la opción legacy no se especifica, entonces el proveedor legacy no se carga y el algoritmo de cifrado por defecto tanto para certificados como para claves privadas es AES_256_CBC con PBKDF2 para la derivación de claves.

-engine id
Véase "Opciones de motor" en openssl(1). Esta opción está obsoleta.
-provider nombre
-provider-path ruta
-provparam [nombre:]clave=valor
-propquery propq
Véase "Opciones de Proveedor" en openssl(1), provider(7), y property(7).
-rand archivos, -writerand archivo
Véase "Opciones de Estado Aleatorio" en openssl(1) para detalles.

Opciones de entrada PKCS#12 (análisis)

-in nombre_archivo|uri
Esto especifica el nombre de archivo o URI de entrada. La entrada estándar se utiliza por defecto. Sin la opción -export, este debe ser un archivo PKCS#12 para analizar. Para usar con la opción -export véase la sección "Opciones de salida PKCS#12 (exportación)".
-out nombre_archivo
El nombre de archivo donde escribir los certificados y claves privadas, salida estándar por defecto. Todos se escriben en formato PEM.
-info
Muestra información adicional sobre la estructura del archivo PKCS#12, los algoritmos utilizados y los recuentos de iteración.
-nomacver
No intentes verificar el MAC de integridad.
-clcerts
Solo exporta certificados de cliente (no certificados CA).
-cacerts
Solo exporta certificados CA (no certificados de cliente).
-aes128, -aes192, -aes256
Usa AES para cifrar claves privadas antes de exportarlas.
-aria128, -aria192, -aria256
Usa ARIA para cifrar claves privadas antes de exportarlas.
-camellia128, -camellia192, -camellia256
Usa Camellia para cifrar claves privadas antes de exportarlas.
-des
Usa DES para cifrar claves privadas antes de exportarlas.
-des3
Usa triple DES para cifrar claves privadas antes de exportarlas.
-idea
Usa IDEA para cifrar claves privadas antes de exportarlas.
-noenc
No cifres las claves privadas en absoluto.
-nodes
Esta opción está obsoleta desde OpenSSL 3.0; usa -noenc en su lugar.

NAME

openssl-pkcs12

manage PKCS#12 keystore files

SYNOPSIS

openssl pkcs12 [-export] [-inkey file] [-in file] [-out file] [-name friendly name] [-certfile file] [-chain] [-caname friendly name] [-password pass arg] [-passin pass arg] [-passout pass arg] [-macalg digest] [-keypbe alg] [-certpbe alg] [-keyex|-keysig] [-iter count] [-noiter] [-nomaciter] [-mac] [-nomac] [-certorder] [-twopass] [-legacy] [-bom] [-CSP name] [-LMK] [-descert] [-nokeys] [-nocerts] [-clcerts] [-cacerts] [-noout] [-multidump] [-*import_certopt*] [-*export_certopt*]

DESCRIPTION

The openssl pkcs12 utility is used to read and write PKCS#12 files. It can be used to convert PKCS#12 files to other formats, or to create PKCS#12 files from other formats.

A PKCS#12 file is a binary format used to store a private key and its corresponding public key certificate, along with any intermediate CA certificates.

By default, openssl pkcs12 reads a PKCS#12 file, prompts for a password, and then writes the contents of the PKCS#12 file to the standard output.

If the -export option is given, then openssl pkcs12 creates a PKCS#12 file from input certificates and a private key. It prompts for an export password and optionally an import password.

IMPORT OPTIONS

-WINCERT
Also load certificates from the Windows Certificate Store.
-WINROOT
Also load certificates from the Windows Root Certificate Store.
-in filename
The filename to read the PKCS#12 structure from. Standard input is used by default.
-atexit
Does not prompt for a password when reading password protected files, but instead uses the password specified with the -passin option. On exit, it prompts for a password to be used to encrypt the output file, rather than using the password specified with the -passout option.
-password pass arg
The password source for the PKCS#12 file. See openssl-passphrase-options(1) for details.
-passin pass arg
The password source for reading the PKCS#12 file. See openssl-passphrase-options(1) for details.
-passout pass arg
The password source for writing the PKCS#12 file. See openssl-passphrase-options(1) for details.
-nocerts
Do not output the certificates.
-noykeys
Do not output the private keys.
-noout
Do not output anything other than what is specified by other options.
-clcerts
Only output the client certificates (non-CA certificates).
-cacerts
Only output the CA certificates.
-certorder
Output certificates in the order they appear in the PKCS#12 file rather than sorted by trust.
-multidump
Output keys and certificates in a multi-PEM format.
-chainfile filename
Write CA certificates to filename.
-edit
Edit the PKCS#12 file in place. This option is highly experimental and should not be used unless you know what you are doing. It requires the file to be readable and writable.
-twopass
Produce a PKCS#12 file which is encrypted with two passwords: one for the MAC and one for the encryption of the private keys and certificates. This is the standard behaviour for older versions of OpenSSL and is still supported for compatibility reasons.
-legacy
Produce a PKCS#12 file which is compatible with older versions of OpenSSL (pre-1.0.0). This means that it will use Triple DES for encrypting private keys and certificates, and SHA1 for the MAC.
-bom
Prepend a UTF-8 BOM (Byte Order Mark) to the output. This is useful for Windows compatibility.
-aeskeys
Use AES-256-CBC to encrypt the private keys. This is the default unless the -legacy option is used.
-aes128
Use AES-128-CBC to encrypt the private keys.
-aes192
Use AES-192-CBC to encrypt the private keys.
-aes256
Use AES-256-CBC to encrypt the private keys.
-des
Use DES-CBC to encrypt the private keys.
-3des
Use Triple DES (DES-EDE3-CBC) to encrypt the private keys.

PKCS#12 output (export) options

-export
This option specifies that a PKCS#12 file will be created rather than parsed.
-out filename
This specifies filename to write the PKCS#12 file to. Standard output is used by default.
-in filename|uri
This specifies the input filename or URI. Standard input is used by default. With the -export option this is a file with certificates and a key, or a URI that refers to a key accessed via an engine. The order of credentials in a file doesn't matter but one private key and its corresponding certificate should be present. If additional certificates are present they will also be included in the PKCS#12 output file.
-inkey filename|uri
The private key input for PKCS12 output. If this option is not specified then the input file (-in argument) must contain a private key. If no engine is used, the argument is taken as a file. If the -engine option is used or the URI has prefix "org.openssl.engine:" then the rest of the URI is taken as key identifier for the given engine.
-certfile filename
An input file with extra certificates to be added to the PKCS#12 output if the -export option is given.
-passcerts arg
The password source for certificate input such as -certfile and -untrusted. For more information about the format of arg see openssl-passphrase-options(1).
-chain
If this option is present then the certificate chain of the end entity certificate is built and included in the PKCS#12 output file. The end entity certificate is the first one read from the -in file if no key is given, else the first certificate matching the given key. The standard CA trust store is used for chain building, as well as any untrusted CA certificates given with the -untrusted option.
-untrusted filename
An input file of untrusted certificates that may be used for chain building, which is relevant only when a PKCS#12 file is created with the -export option and the -chain option is given as well. Any certificates that are actually part of the chain are added to the output.
-CAfile file, -no-CAfile, -CApath dir, -no-CApath, -CAstore uri, -no-CAstore
See "Trusted Certificate Options" in openssl-verification-options(1) for details.
-name friendlyname
This specifies the "friendly name" for the certificates and private key. This name is typically displayed in list boxes by software importing the file.
-caname friendlyname
This specifies the "friendly name" for other certificates. This option may be used multiple times to specify names for all certificates in the order they appear. Netscape ignores friendly names on other certificates whereas MSIE displays them.
-CSP name
Write name as a Microsoft CSP name. The password source for the input, and for encrypting any private keys that are output. For more information about the format of arg see openssl-passphrase-options(1).
-LMK
Add the "Local Key Set" identifier to the attributes.
-keyex|-keysig
Specifies that the private key is to be used for key exchange or just signing. This option is only interpreted by MSIE and similar MS software. Normally "export grade" software will only allow 512 bit RSA keys to be used for encryption purposes but arbitrary length keys for signing. The -keysig option marks the key for signing only. Signing only keys can be used for S/MIME signing, authenticode (ActiveX control signing) and SSL client authentication, however, due to a bug only MSIE 5.0 and later support the use of signing only keys for SSL client authentication.
-keypbe alg, -certpbe alg
These options allow the algorithm used to encrypt the private key and certificates to be selected. Any PKCS#5 v1.5 or PKCS#12 PBE algorithm name can be used (see "NOTES" section for more information). If a cipher name (as output by "openssl list -cipher-algorithms") is specified then it is used with PKCS#5 v2.0. For interoperability reasons it is advisable to only use PKCS#12 algorithms.

Special value "NONE" disables encryption of the private key and certificates.

-descert
Encrypt the certificates using triple DES. By default the private key and the certificates are encrypted using AES-256-CBC unless the '-legacy' option is used. If '-descert' is used with the '-legacy' then both, the private key and the certificates are encrypted using triple DES.
-macalg digest
Specify the MAC digest algorithm. If not included SHA256 will be used.
-pbmac1_pbkdf2
Use PBMAC1 with PBKDF2 for MAC protection of the PKCS#12 file.
-pbmac1_pbkdf2_md digest
Specify the PBKDF2 KDF digest algorithm. If not specified, SHA256 will be used. Unless "-pbmac1_pbkdf2" is specified, this parameter is ignored.
-iter count
This option specifies the iteration count for the encryption key and MAC. The default value is 2048.

To discourage attacks by using large dictionaries of common passwords the algorithm that derives keys from passwords can have an iteration count applied to it: this causes a certain part of the algorithm to be repeated and slows it down. The MAC is used to check the file integrity but since it will normally have the same password as the keys and certificates it could also be attacked.

-noiter, -nomaciter
By default both encryption and MAC iteration counts are set to 2048, using these options the MAC and encryption iteration counts can be set to 1, since this reduces the file security you should not use these options unless you really have to. Most software supports both MAC and encryption iteration counts. MSIE 4.0 doesn't support MAC iteration counts so it needs the -nomaciter option.
-maciter
This option is included for compatibility with previous versions, it used to be needed to use MAC iterations counts but they are now used by default.
-macsaltlen
This option specifies the salt length in bytes for the MAC. The salt length should be at least 16 bytes as per NIST SP 800-132, which is the default value.
-nomac
Do not attempt to provide the MAC integrity. This can be useful with the FIPS provider as the PKCS12 MAC requires PKCS12KDF which is not an approved FIPS algorithm and cannot be supported by the FIPS provider.
-jdktrust
Export pkcs12 file in a format compatible with Java keystore usage. This option accepts a string parameter indicating the trust oid name to be granted to the certificate it is associated with. Currently only "anyExtendedKeyUsage" is defined. Note that, as Java keystores do not accept PKCS12 files with both trusted certificates and keypairs, use of this option implies the setting of the -nokeys option

NOTES

Although there are a large number of options most of them are very rarely used. For PKCS#12 file parsing only -in and -out need to be used for PKCS#12 file creation -export and -name are also used.

If none of the -clcerts, -cacerts or -nocerts options are present then all certificates will be output in the order they appear in the input PKCS#12 files. There is no guarantee that the first certificate present is the one corresponding to the private key. Certain software which tries to get a private key and the corresponding certificate might assume that the first certificate in the file is the one corresponding to the private key, but that may not always be the case. Using the -clcerts option will solve this problem by only outputting the certificate corresponding to the private key. If the CA certificates are required then they can be output to a separate file using the -nokeys -cacerts options to just output CA certificates.

The -keypbe and -certpbe algorithms allow the precise encryption algorithms for private keys and certificates to be specified. Normally the defaults are fine but occasionally software can't handle triple DES encrypted private keys, then the option -keypbe PBE-SHA1-RC2-40 can be used to reduce the private key encryption to 40 bit RC2. A complete description of all algorithms is contained in openssl-pkcs8(1).

Prior 1.1 release passwords containing non-ASCII characters were encoded in non-compliant manner, which limited interoperability, in first hand with Windows. But switching to standard-compliant password encoding poses problem accessing old data protected with broken encoding. For this reason even legacy encodings is attempted when reading the data. If you use PKCS#12 files in production application

se le aconseja convertir los datos, porque el enfoque heurístico implementado no es seguro para subprocesos (MT-safe), su único objetivo es facilitar la actualización de datos con este comando.

EJEMPLOS

Analizar un archivo PKCS#12 y enviarlo a un archivo PEM:

openssl pkcs12 -in file.p12 -out file.pem

Enviar solo certificados de cliente a un archivo:

openssl pkcs12 -in file.p12 -clcerts -out file.pem

No cifrar la clave privada:

openssl pkcs12 -in file.p12 -out file.pem -noenc

Mostrar información sobre un archivo PKCS#12:

openssl pkcs12 -in file.p12 -info -noout

Mostrar información sobre un archivo PKCS#12 en modo heredado:

openssl pkcs12 -in file.p12 -info -noout -legacy

Crear un archivo PKCS#12 a partir de un archivo PEM que puede contener una clave y certificados:

openssl pkcs12 -export -in file.pem -out file.p12 -name "Mi PSE"

Incluir certificados adicionales:

openssl pkcs12 -export -in file.pem -out file.p12 -name "Mi PSE" \
 -certfile othercerts.pem

Exportar un archivo PKCS#12 con datos de un archivo PEM de certificado y de un archivo PEM adicional que contiene una clave, con algoritmos predeterminados como en el proveedor heredado:

openssl pkcs12 -export -in cert.pem -inkey key.pem -out file.p12 -legacy

HISTORIAL

La opción -engine fue deprecada en OpenSSL 3.0. La opción -nodes también fue deprecada en OpenSSL 3.0; use -noenc en su lugar. El valor predeterminado de la opción -macsaltlen cambió de 8 a 16 bytes en OpenSSL 3.6.
