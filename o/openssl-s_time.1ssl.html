openssl-s_time(1ssl)

Paquete: openssl

Licencias: Apache-2.0

OPENSSL-S_TIME(1ssl) OpenSSL OPENSSL-S_TIME(1ssl)

NOMBRE

openssl-s_time - Programa de temporización de rendimiento de SSL/TLS

SINOPSIS

openssl s_time [-help] [-connect host:puerto] [-www página] [-cert archivo] [-key archivo] [-reuse] [-new] [-verify profundidad] [-time segundos] [-ssl3] [-tls1] [-tls1_1] [-tls1_2] [-tls1_3] [-bugs] [-cipher lista_cifrados] [-ciphersuites val] [-nameopt opción] [-cafile archivo] [-CAfile archivo] [-no-CAfile] [-CApath directorio] [-no-CApath] [-CAstore uri] [-no-CAstore] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq]

DESCRIPCIÓN

Este comando implementa un cliente SSL/TLS genérico que se conecta a un host remoto usando SSL/TLS. Puede solicitar una página del servidor e incluye el tiempo de transferencia de los datos de carga útil en sus mediciones de tiempo. Mide el número de conexiones dentro de un período de tiempo dado, la cantidad de datos transferidos (si los hay) y calcula el tiempo promedio dedicado a una conexión.

OPCIONES

-help
Imprime un mensaje de uso.
-connect host:puerto
Esto especifica el host y el puerto opcional al que conectarse. Si la cadena del host es una dirección IPv6, debe encerrarse entre "[" y "]".
-www página
Esto especifica la página a obtener del servidor. Un valor de '/' obtiene la página index.html. Si este parámetro no se especifica, entonces este comando solo realizará el handshake para establecer conexiones SSL, pero no transferirá ningún dato de carga útil.
-cert nombre_cert
El certificado a usar, si es solicitado por el servidor. Por defecto no se usa un certificado. El archivo está en formato PEM.
-key archivo_clave
La clave privada a usar. Si no se especifica, se usará el archivo del certificado. El archivo está en formato PEM.
-verify profundidad
La profundidad de verificación a usar. Esto especifica la longitud máxima de la cadena de certificados del servidor y activa la verificación del certificado del servidor. Actualmente la operación de verificación continúa después de los errores, por lo que se pueden ver todos los problemas con una cadena de certificados. Como efecto secundario, la conexión nunca fallará debido a un fallo de verificación del certificado del servidor.
-new
Realiza la prueba de temporización usando un ID de sesión nuevo para cada conexión. Si no se especifican ni -new ni -reuse, ambos están activados por defecto y se ejecutan en secuencia.
-reuse
Realiza la prueba de temporización usando el mismo ID de sesión; esto puede usarse como una prueba de que el almacenamiento en caché de sesiones está funcionando. Si no se especifican ni -new ni -reuse, ambos están activados por defecto y se ejecutan en secuencia.
-bugs
Existen varios errores conocidos en las implementaciones SSL y TLS. Añadir esta opción habilita varias soluciones alternativas.
-cipher lista_cifrados
Esto permite modificar la lista de cifrados TLSv1.2 y anteriores enviada por el cliente. Esta lista se combinará con cualquier conjunto de cifrados TLSv1.3 que se haya configurado. Aunque el servidor determina qué conjunto de cifrados se utiliza, debe tomar el primer cifrado compatible en la lista enviada por el cliente. Consulte openssl-ciphers(1) para más información.
-ciphersuites val
Esto permite modificar los conjuntos de cifrados TLSv1.3 enviados por el cliente. Esta lista se combinará con cualquier conjunto de cifrados TLSv1.2 y anteriores que se hayan configurado. Aunque el servidor determina qué conjunto de cifrados se utiliza, debe tomar el primer cifrado compatible en la lista enviada por el cliente. Consulte openssl-ciphers(1) para más información. El formato para esta lista es una lista simple separada por dos puntos (":") de nombres de conjuntos de cifrados TLSv1.3.
-time longitud
Especifica durante cuánto tiempo (en segundos) este comando debe establecer conexiones y opcionalmente transferir datos de carga útil desde un servidor. El rendimiento del servidor y del cliente, y la velocidad del enlace determinan cuántas conexiones puede establecer.
-nameopt opción
Esto especifica cómo se muestran los nombres del sujeto o del emisor. Consulte openssl-namedisplay-options(1) para más detalles.
-CAfile archivo, -no-CAfile, -CApath directorio, -no-CApath, -CAstore uri, -no-CAstore
Consulte "Opciones de Certificado de Confianza" en openssl-verification-options(1) para más detalles.
-provider nombre
-provider-path ruta
-provparam [nombre:]clave=valor
-propquery propq
Consulte "Opciones del Proveedor" en openssl(1), provider(7) y property(7).
-cafile archivo
Este es un sinónimo obsoleto de -CAfile.
-ssl3, -tls1, -tls1_1, -tls1_2, -tls1_3
Consulte "Opciones de Versión TLS" en openssl(1).

MEDIO AMBIENTE

SSL_CIPHER
Si no se especifica la opción -cipher, el contenido de esta variable de entorno se utiliza para modificar la lista de cifrados TLSv1.2 y anteriores enviada por el cliente de la misma manera que lo hace la opción mencionada anteriormente.

NOTAS

Este comando se puede utilizar para medir el rendimiento de una conexión SSL. Para conectarse a un servidor HTTP SSL y obtener la página predeterminada, el comando

openssl s_time -connect nombre_servidor:443 -www / -CApath tu_directorio -CAfile tu_archivo.pem -cipher cifrado_comun [-ssl3]

normalmente se usaría (https usa el puerto 443). cifrado_comun es un cifrado con el que tanto el cliente como el servidor pueden acordar, consulte el comando openssl-ciphers(1) para más detalles.

Si el handshake falla, hay varias causas posibles. Si no es algo obvio como la ausencia de certificado de cliente, se pueden probar las opciones -bugs y -ssl3 en caso de que sea un servidor defectuoso. En particular, debe experimentar con estas opciones antes de enviar un informe de error a una lista de correo de OpenSSL.

Un problema frecuente al intentar que los certificados de cliente funcionen es que un cliente web se queja de que no tiene certificados o proporciona una lista vacía para elegir. Esto se debe normalmente a que el servidor no envía su autoridad de certificación de cliente en su "lista de CA aceptables" cuando solicita un certificado. Usando openssl-s_client(1) se puede ver y comprobar la lista de CA. Sin embargo, algunos servidores solo solicitan autenticación de cliente después de que se solicita una URL específica. Para obtener la lista en este caso, es necesario usar la opción -prexit de openssl-s_client(1) y enviar una solicitud HTTP para una página apropiada.

ERRORES

Dado que este programa no tiene todas las opciones del programa openssl-s_client(1) para activar y desactivar protocolos, es posible que no pueda medir el rendimiento de todos los protocolos con todos los servidores.

La opción -verify debería salir si la verificación del servidor falla.

HISTORIA

La opción -cafile fue obsoleta en OpenSSL 3.0.
