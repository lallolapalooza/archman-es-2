NOMBRE

openssl-pkcs8 - comando de conversión de claves privadas en formato PKCS#8

SINOPSIS

openssl pkcs8 [-help] [-topk8] [-inform DER|PEM] [-outform DER|PEM] [-in nombre_archivo] [-passin arg] [-out nombre_archivo] [-passout arg] [-iter contador] [-noiter] [-nocrypt] [-traditional] [-v2 alg] [-v2prf alg] [-v1 alg] [-scrypt] [-scrypt_N N] [-scrypt_r r] [-scrypt_p p] [-saltlen tamaño] [-rand archivos] [-writerand archivo] [-engine id] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq]

DESCRIPCIÓN

Este comando procesa claves privadas en formato PKCS#8. Puede manejar tanto el formato PrivateKeyInfo PKCS#8 sin cifrar como el formato EncryptedPrivateKeyInfo con una variedad de algoritmos PKCS#5 (v1.5 y v2.0) y PKCS#12.

OPCIONES

-help
Imprime un mensaje de uso.
-topk8
Normalmente se espera una clave privada PKCS#8 en la entrada y se escribirá una clave privada en el archivo de salida. Con la opción -topk8 la situación se invierte: lee una clave privada y escribe una clave en formato PKCS#8.
-inform DER|PEM, -outform DER|PEM
Los formatos de entrada y salida; el valor predeterminado es PEM. Consulte openssl-format-options(1) para más detalles.

Si se está convirtiendo una clave del formato PKCS#8 (es decir, no se utiliza la opción -topk8), el archivo de entrada debe estar en formato PKCS#8. Se espera una clave cifrada a menos que se incluya -nocrypt.

Si no se usa -topk8 y se establece el modo PEM, el archivo de salida será una clave privada sin cifrar en formato PKCS#8. Si se utiliza la opción -traditional, se escribirá una clave privada en formato tradicional.

Si no se usa -topk8 y se establece el modo DER, el archivo de salida será una clave privada sin cifrar en formato DER tradicional.

Si se usa -topk8, se puede utilizar cualquier clave privada compatible para el archivo de entrada en un formato especificado por -inform. El archivo de salida será un formato PKCS#8 cifrado utilizando los parámetros de cifrado especificados, a menos que se incluya -nocrypt.

-traditional
Cuando esta opción está presente y -topk8 no lo está, se escribe una clave privada en formato tradicional.
-in nombre_archivo
Especifica el archivo de entrada del cual leer una clave o la entrada estándar si no se especifica esta opción. Si la clave está cifrada, se solicitará una contraseña a menos que se proporcione -passin.
-passin arg, -passout arg
El origen de la contraseña para el archivo de entrada y salida. Para más información sobre el formato de arg, consulte openssl-passphrase-options(1).
-out nombre_archivo
Especifica el archivo de salida donde escribir una clave o la salida estándar por defecto. El nombre del archivo de salida puede ser el mismo que el nombre del archivo de entrada, lo que lleva a reemplazar el contenido del archivo. Tenga en cuenta que la E/S de archivos no es atómica. El archivo de salida se trunca y luego se escribe.

Si se establecen opciones de cifrado y no se proporciona -passout, se solicitará una contraseña. Cuando la entrada de contraseña se interrumpe, el archivo de salida no se modifica.

-iter contador
Al crear nuevos contenedores PKCS#8, utilice un número dado de iteraciones en la contraseña para derivar la clave de cifrado para la salida PKCS#8. Valores altos aumentan el tiempo necesario para forzar una contraseña de un contenedor PKCS#8.
-noiter
Al crear nuevos contenedores PKCS#8, utilice 1 como recuento de iteraciones.
-nocrypt
Las claves PKCS#8 generadas o de entrada son normalmente estructuras EncryptedPrivateKeyInfo PKCS#8 que utilizan un algoritmo de cifrado adecuado basado en contraseña. Con esta opción se espera o se produce una estructura PrivateKeyInfo sin cifrar. Esta opción no cifra las claves privadas en absoluto y solo debe utilizarse cuando sea absolutamente necesario. Algunos programas, como ciertas versiones de software de firma de código de Java, utilizaban claves privadas sin cifrar.
-v2 alg
Esta opción establece el algoritmo PKCS#5 v2.0.

El argumento alg es el algoritmo de cifrado a utilizar, los valores válidos incluyen aes128, aes256 y des3. Si esta opción no se especifica, se utiliza aes256.

-v2prf alg
Esta opción establece el algoritmo PRF (función pseudoaleatoria) a utilizar con PKCS#5 v2.0. Un valor típico válido sería hmacWithSHA256. Si esta opción no se establece, se utiliza el valor predeterminado para el cifrador o hmacWithSHA256 si no hay predeterminado.

Algunas implementaciones pueden no admitir algoritmos PRF personalizados y pueden requerir la opción hmacWithSHA1 para funcionar.

-v1 alg
Esta opción indica que se debe utilizar un algoritmo PKCS#5 v1.5 o PKCS#12. Algunas implementaciones antiguas pueden no admitir PKCS#5 v2.0 y pueden requerir esta opción. Si no se especifica, se utiliza el formato PKCS#5 v2.0.
-scrypt
Utiliza el algoritmo scrypt para el cifrado de claves privadas con parámetros predeterminados: actualmente N=16384, r=8 y p=1 y AES en modo CBC con una clave de 256 bits. Estos parámetros se pueden modificar utilizando las opciones -scrypt_N, -scrypt_r, -scrypt_p y -v2.
-scrypt_N N, -scrypt_r r, -scrypt_p p
Establece los parámetros scrypt N, r o p.
-saltlen
Establece la longitud (en bytes) de la sal a utilizar para el algoritmo PBE (Password-Based Encryption). Si no se especifica este valor, el valor predeterminado para PBES2 es 16 (128 bits) y 8 (64 bits) para PBES1.
-rand archivos, -writerand archivo
Consulte "Opciones de Estado Aleatorio" en openssl(1) para obtener detalles.
-engine id
Consulte "Opciones de Motor" en openssl(1). Esta opción está obsoleta.
-provider nombre
-provider-path ruta
-provparam [nombre:]clave=valor
-propquery propq
Consulte "Opciones del Proveedor" en openssl(1), provider(7) y property(7).

NOTAS

Por defecto, al convertir una clave al formato PKCS#8, se utiliza PKCS#5 v2.0 con AES de 256 bits con HMAC y SHA256.

Algunas implementaciones antiguas no admiten el formato PKCS#5 v2.0 y requieren en su lugar la forma más antigua PKCS#5 v1.5, posiblemente también requiriendo algoritmos de cifrado débiles e inseguros como DES de 56 bits.

Las claves privadas cifradas utilizando algoritmos PKCS#5 v2.0 y altos recuentos de iteraciones son más seguras que las cifradas utilizando los formatos tradicionales compatibles con SSLeay. Por lo tanto, si se considera importante seguridad adicional, las claves deben convertirse.

Es posible escribir claves privadas cifradas codificadas en DER en formato PKCS#8 porque los detalles del cifrado se incluyen a nivel ASN1, mientras que el formato tradicional los incluye a nivel P

ALGORITMOS PKCS#5 V1.5 Y PKCS#12

Se pueden usar varios algoritmos con la opción de línea de comandos -v1, incluyendo PKCS#5 v1.5 y PKCS#12. Estos se describen con más detalle a continuación.

PBE-MD2-DES PBE-MD5-DES
Estos algoritmos se incluyeron en la especificación original de PKCS#5 v1.5. Solo ofrecen 56 bits de protección ya que ambos usan DES.
PBE-SHA1-RC2-64, PBE-MD2-RC2-64, PBE-MD5-RC2-64, PBE-SHA1-DES
Estos algoritmos no se mencionan en la especificación original de PKCS#5 v1.5, pero usan el mismo algoritmo de derivación de claves y son compatibles con algunos programas. Se mencionan en PKCS#5 v2.0. Usan RC2 de 64 bits o DES de 56 bits.
PBE-SHA1-RC4-128, PBE-SHA1-RC4-40, PBE-SHA1-3DES, PBE-SHA1-2DES, PBE-SHA1-RC2-128, PBE-SHA1-RC2-40
Estos algoritmos utilizan el algoritmo de cifrado basado en contraseña PKCS#12 y permiten usar algoritmos de cifrado seguros como triple DES o RC2 de 128 bits.

EJEMPLOS

Convertir una clave privada al formato PKCS#8 usando parámetros predeterminados (AES con clave de 256 bits y hmacWithSHA256):

openssl pkcs8 -in key.pem -topk8 -out enckey.pem

Convertir una clave privada al formato PKCS#8 sin cifrar:

openssl pkcs8 -in key.pem -topk8 -nocrypt -out enckey.pem

Convertir una clave privada al formato PKCS#5 v2.0 usando triple DES:

openssl pkcs8 -in key.pem -topk8 -v2 des3 -out enckey.pem

Convertir una clave privada al formato PKCS#5 v2.0 usando AES con 256 bits en modo CBC y PRF hmacWithSHA512:

openssl pkcs8 -in key.pem -topk8 -v2 aes-256-cbc -v2prf hmacWithSHA512 -out enckey.pem

Convertir una clave privada a PKCS#8 usando un algoritmo compatible con PKCS#5 1.5 (DES):

openssl pkcs8 -in key.pem -topk8 -v1 PBE-MD5-DES -out enckey.pem

Convertir una clave privada a PKCS#8 usando un algoritmo compatible con PKCS#12 (3DES):

openssl pkcs8 -in key.pem -topk8 -out enckey.pem -v1 PBE-SHA1-3DES

Leer una clave privada PKCS#8 sin cifrar en formato DER:

openssl pkcs8 -inform DER -nocrypt -in key.der -out key.pem

Convertir una clave privada de cualquier formato PKCS#8 cifrado a formato tradicional:

openssl pkcs8 -in pk8.pem -traditional -out key.pem

Convertir una clave privada al formato PKCS#8, cifrando con AES-256 y con un millón de iteraciones de la contraseña:

openssl pkcs8 -in key.pem -topk8 -v2 aes-256-cbc -iter 1000000 -out pk8.pem

ESTÁNDARES

Los vectores de prueba de esta implementación de PKCS#5 v2.0 se publicaron en la lista de correo pkcs-tng usando triple DES, DES y RC2 con altos recuentos de iteración. Varias personas confirmaron que podían descifrar las claves privadas producidas y, por lo tanto, se puede asumir que la implementación de PKCS#5 v2.0 es razonablemente precisa, al menos en lo que respecta a estos algoritmos.

El formato de las claves privadas DSA (y otras) PKCS#8 no está bien documentado: está oculto en PKCS#11 v2.01, sección 11.9. El formato de clave privada DSA PKCS#8 predeterminado de OpenSSL cumple con este estándar.

ERRORES

Debería haber una opción que muestre el algoritmo de cifrado en uso y otros detalles como el recuento de iteraciones.
