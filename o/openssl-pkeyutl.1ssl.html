NOMBRE

openssl-pkeyutl - comando de clave asimétrica

SINOPSIS

openssl pkeyutl [-help] [-in archivo] [-rawin] [-digest algoritmo] [-out archivo] [-secret archivo] [-sigfile archivo] [-inkey nombrearchivo|uri] [-keyform DER|PEM|P12|ENGINE] [-passin arg] [-pubin] [-certin] [-rev] [-sign] [-verify] [-verifyrecover] [-encrypt] [-decrypt] [-derive] [-peerkey archivo] [-peerform DER|PEM|P12|ENGINE] [-encap] [-decap] [-kdf algoritmo] [-kdflen longitud] [-kemop modo] [-pkeyopt opt:valor] [-pkeyopt_passin opt[:passarg]] [-hexdump] [-asn1parse] [-engine id] [-engine_impl] [-rand archivos] [-writerand archivo] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq] [-config archivo_config]

DESCRIPCIÓN

Este comando se puede utilizar para realizar operaciones de bajo nivel en claves asimétricas (públicas o privadas) utilizando cualquier algoritmo soportado.

Por defecto, se asume la operación de firma (ver opción -sign).

OPCIONES

-help
Imprime un mensaje de uso.
-in nombrearchivo
Este especifica el nombre del archivo de entrada del que leer datos o la entrada estándar si no se especifica esta opción.
-rawin
Esto indica que los datos de entrada para la firma o verificación son datos crudos, que no se han procesado con ningún algoritmo de resumen de mensajes. Excepto con EdDSA, el usuario puede especificar un algoritmo de resumen usando la opción -digest. Para algoritmos de firma como RSA, DSA y ECDSA, el algoritmo de resumen por defecto es SHA256. Para SM2, es SM3.

Esta opción solo se puede usar con -sign y -verify. Para EdDSA (los algoritmos Ed25519 y Ed448) esta opción está implícita desde OpenSSL 3.5, y requerida en versiones anteriores.

La opción -digest implica -rawin desde OpenSSL 3.5.

-digest algoritmo
Esta opción solo se puede usar con -sign y -verify. Especifica el algoritmo de resumen que se utiliza para procesar los datos de entrada antes de firmarlos o verificarlos con la clave de entrada. Esta opción podría omitirse si el algoritmo de firma no requiere preprocesar la entrada a través de una función hash enchufable antes de firmar (por ejemplo, EdDSA). Si se omite esta opción pero el algoritmo de firma la requiere y se proporciona la opción -rawin, se utilizará un valor por defecto (ver -rawin para más detalles). Si esta opción está presente, entonces la opción -rawin está implícita desde OpenSSL 3.5, y requerida en versiones anteriores.

En este momento, HashEdDSA (la variante ph o "prehash" de EdDSA) no está soportada, por lo que la opción -digest no se puede usar con EdDSA.

-out nombrearchivo
Especifica el nombre del archivo de salida al que escribir o la salida estándar por defecto.
-secret nombrearchivo
Especifica el nombre del archivo de salida para el secreto compartido para cuando se realiza encapsulación a través de la opción -encap o desencapsulación a través de la opción -decap. La opción -encap también produce una salida de texto cifrado (pública) separada que, por defecto, se escribe en la salida estándar, pero al ser datos binarios no textuales, normalmente también se redirige a un archivo seleccionado mediante la opción -out.
-sigfile archivo
Archivo de firma, requerido y permitido solo para operaciones de -verify.
-inkey nombrearchivo|uri
La clave de entrada, por defecto debería ser una clave privada.
-keyform DER|PEM|P12|ENGINE
El formato de la clave; no especificado por defecto. Ver openssl-format-options(1) para detalles.
-passin arg
La fuente de la contraseña de la clave de entrada. Para más información sobre el formato de arg ver openssl-passphrase-options(1).
-pubin
Por defecto se lee una clave privada de la entrada de la clave. Con esta opción se lee en su lugar una clave pública. Si la entrada no contiene una clave pública sino una clave privada, se usa su parte pública.
-certin
La entrada es un certificado que contiene una clave pública.
-rev
Invierte el orden del buffer de entrada. Esto es útil para algunas bibliotecas (como CryptoAPI) que representan el buffer en formato little-endian. Esto no se puede usar en conjunción con -rawin.
-sign
Firma los datos de entrada y produce el resultado firmado. Esto requiere una clave privada. Se recomienda usar una operación de resumen de mensajes junto con esto, cuando sea aplicable, ver las opciones -rawin y -digest para detalles. De lo contrario, los datos de entrada dados con la opción -in se asumen que ya son un resumen, pero esto puede requerir un adicional -pkeyopt "digest:"md en algunos casos (por ejemplo, RSA con el modo de relleno PKCS#1 por defecto). Incluso para otros algoritmos como ECDSA, donde la opción adicional -pkeyopt no afecta la salida de la firma, se recomienda, ya que permite comprobar que la longitud de entrada es consistente con el resumen previsto.
-verify
Verifica los datos de entrada contra la firma dada con la opción -sigfile e indica si la verificación tuvo éxito o falló. Los datos de entrada dados con la opción -in se asumen que son un valor de hash a menos que se especifique o implique la opción -rawin. Con datos crudos, cuando un algoritmo de resumen es aplicable, aunque puede inferirse de la firma o tomar un valor por defecto, también debe especificarse.
-verifyrecover
Verifica la firma dada y produce los datos recuperados (carga útil de la firma). Por ejemplo, en el caso de RSA PKCS#1 los datos recuperados son la codificación DER de EMSA-PKCS-v1_5 del OID del algoritmo de resumen y el valor según se especifica en RFC8017 Sección 9.2 https://datatracker.ietf.org/doc/html/rfc8017#section-9.2.

Tenga en cuenta que aquí la entrada dada con la opción -in no es una entrada de firma (como con las opciones -sign y -verify) sino un valor de salida de firma, típicamente producido usando la opción -sign.

Esta opción solo está disponible para su uso con claves RSA.

-encrypt
Cifra los datos de entrada utilizando una clave pública.
-decrypt
Descifra los datos de entrada utilizando una clave privada.
-derive
Deriva un secreto compartido usando la clave propia privada (EC)DH y la clave del par.
-peerkey archivo
Archivo que contiene la clave pública o privada (EC)DH del par a usar con la operación de derivación (acuerdo) de claves. Su tipo debe coincidir con el tipo de la clave privada propia dada con -inkey.
-peerform DER|PEM|P12|ENGINE
El formato de la clave del par; no especificado por defecto. Ver openssl-format-options(1) para detalles.
-encap

DESCRIPCIÓN

The pkeyutl command is a utility for using the OpenSSL public key engine (provider). It can perform a variety of public-key operations, including encryption, decryption, signing, verification, and key derivation.

-in file
Input file. This is used to specify the input file for operations such as encryption, signing, and key derivation. If not specified, standard input is used.
-out file
Output file. This is used to specify the output file for operations such as decryption, verification, and encapsulation. If not specified, standard output is used.
-inkey file
Input private key file. This is required for private key operations such as decryption and signing. The file format can be PEM or DER.
-pubin
Input public key. By default, the input key is treated as a private key. This option specifies that the input key is a public key.
-sign
Sign input data using the private key. The input data is read from standard input (or the file specified with -in) and the signature is written to standard output (or the file specified with -out).
-verify
Verify a signature using the public key. The input data and the signature are read from standard input (or the files specified with -in and -out respectively). The result of the verification (success or failure) is written to standard output.
-verifyrecover
Recover the original data from a signature using the private key. The signature is read from standard input (or the file specified with -in) and the recovered data is written to standard output (or the file specified with -out). This operation is only supported for RSA keys.
-encrypt
Encrypt input data using the public key. The input data is read from standard input (or the file specified with -in) and the encrypted data is written to standard output (or the file specified with -out).
-decrypt
Decrypt encrypted data using the private key. The encrypted data is read from standard input (or the file specified with -in) and the decrypted data is written to standard output (or the file specified with -out).
-derive
Derive a shared secret using the private key and a public key. The public key is read from standard input (or the file specified with -in) and the shared secret is written to standard output (or the file specified with -out).
-wrap
Wrap (encrypt) a secret key using a public key. The secret key is read from standard input (or the file specified with -in) and the wrapped key is written to standard output (or the file specified with -out).
-unwrap
Unwrap (decrypt) a secret key using a private key. The wrapped key is read from standard input (or the file specified with -in) and the unwrapped key is written to standard output (or the file specified with -out).
-encap
Encapsulate a shared secret. The public key is read from standard input (or the file specified with -inkey, which must be a public key file). The encapsulated secret (or ciphertext, non-text binary data) is written to standard output by default, or else to the file specified with -out. The -secret option must also be provided to specify the output file for the derived shared-secret value generated in the encapsulation process. Encapsulation is supported with a number of public key algorithms, currently: ML-KEM, X25519, X449, and EC. The ECX and EC algorithms use the RFC9180 https://www.rfc-editor.org/rfc/rfc9180 DHKEM construction. Encapsulation is also supported with RSA keys via the RSASVE construction.

At the API level, encapsulation and decapsulation are also supported for a few hybrid ECDHE (no DHKEM) plus ML-KEM algorithms, but these are intended primarily for use with TLS and should not be used standalone. There are in any case no standard public and private key formats for the hybrid algorithms, so it is not possible to provide the required key material.

-decap
Decode an encapsulated secret, with the use of a -private key, to derive the same shared-secret as that obtained when the secret was encapsulated to the corresponding public key. The encapsulated secret is by default read from the standard input, or else from the file specified with -in. The derived shared-secret is written to the file specified with the -secret option, which must also be provided. Decapsulation is supported with a number of public key algorithms, currently: ML-KEM, X25519, X448, and EC. The ECX and EC algorithms use the RFC9180 https://www.rfc-editor.org/rfc/rfc9180 DHKEM construction. Decapsulation is also supported with RSA keys via the RSASVE construction.
-kemop mode
This option is used with the -encap/-decap commands and specifies the KEM mode specific for the key algorithm when there is no default way to encapsulate and decapsulate shared secrets with the chosen key type. All the supported algorithms presently support only their default mode, and this option, though available, is not required.
-kdf algorithm
Use key derivation function algorithm. The supported algorithms are at present TLS1-PRF and HKDF. Note: additional parameters and the KDF output length will normally have to be set for this to work. See EVP_PKEY_CTX_set_hkdf_md(3) and EVP_PKEY_CTX_set_tls1_prf_md(3) for the supported string parameters of each algorithm.
-kdflen length
Set the output length for KDF.
-pkeyopt opt:value
Public key options specified as opt:value. See NOTES below for more details.
-pkeyopt_passin opt[:passarg]
Allows reading a public key option opt from stdin or a password source. If only opt is specified, the user will be prompted to enter a password on stdin. Alternatively, passarg can be specified which can be any value supported by openssl-passphrase-options(1).
-hexdump
hex dump the output data.
-asn1parse
Parse the ASN.1 output data to check its DER encoding and print any errors. When combined with the -verifyrecover option, this may be useful in case an ASN.1 DER-encoded structure had been signed directly (without hashing it) and when checking a signature in PKCS#1 v1.5 format, which has a DER encoding.
-engine id
See "Engine Options" in openssl(1). This option is deprecated.
-engine_impl
When used with the -engine option, it specifies to also use engine id for crypto operations.
-rand files, -writerand file
See "Random State Options" in openssl(1) for details.
-provider name
-provider-path path
-provparam [name:]key=value
-propquery propq
See "Provider Options" in openssl(1), provider(7), and property(7).
-config configfile
See "Configuration Option" in openssl(1).

NOTAS

Las operaciones y opciones soportadas varían según el algoritmo de clave y su implementación. Las operaciones y opciones de OpenSSL se indican a continuación.

A menos que se indique lo contrario, la opción -pkeyopt soporta para todos los tipos de clave pública el argumento "digest:"alg, que especifica el digest utilizado en las operaciones de firma y verificación. El valor alg debe representar un nombre de digest tal como se usa en la función EVP_get_digestbyname(), por ejemplo sha256. Este valor no se utiliza para hashear los datos de entrada. Se utiliza (por algunos algoritmos) para verificar la longitud de los datos introducidos y para crear las estructuras que componen la firma (por ejemplo, DigestInfo en firmas de RSASSA PKCS#1 v1.5).

Por ejemplo, si el valor del argumento "digest" de la opción -pkeyopt es sha256, la entrada de la firma o verificación debe ser el valor binario de 32 bytes de la salida de la función hash SHA256.

A menos que se utilice o implique -rawin, este comando no hashea los datos de entrada, sino que utiliza los datos directamente como entrada para el algoritmo de firma. Dependiendo del tipo de clave, el tipo de firma y el modo de relleno, las longitudes máximas sensibles de los datos de entrada difieren. Con RSA, los datos firmados no pueden ser más largos que el módulo de clave. En el caso de ECDSA y DSA, los datos no deben ser más largos que el tamaño del campo, de lo contrario se truncarán silenciosamente al tamaño del campo. En cualquier caso, el tamaño de entrada no debe ser mayor que el tamaño de salida del digest soportado más grande EVP_MAX_MD_SIZE, que actualmente es de 64 bytes.

ALGORITMO RSA

El algoritmo RSA generalmente soporta las operaciones de cifrado, descifrado, firma, verificación y recuperaciónde verificación. Sin embargo, algunos modos de relleno solo soportan un subconjunto de estas operaciones. Los siguientes valores adicionales de pkeyopt son soportados:

rsa_padding_mode:mode
Establece el modo de relleno de RSA. Los valores aceptables para mode son pkcs1 para el relleno PKCS#1, none para sin relleno, oaep para el modo OAEP, x931 para el modo X9.31 y pss para PSS.

En el relleno PKCS#1, si el digest del mensaje no está establecido, los datos suministrados se firman o verifican directamente en lugar de usar una estructura DigestInfo. Si se establece un digest, se utiliza la estructura DigestInfo y su longitud debe corresponder al tipo de digest.

Nota: para el relleno pkcs1, como protección contra el ataque de Bleichenbacher, el descifrado no fallará en caso de fallos en la comprobación del relleno. Utilice none y la inspección manual del mensaje descifrado para verificar si el valor descifrado tiene el relleno PKCS#1 v1.5 correcto.

Para el modo oaep, solo se soportan el cifrado y el descifrado.

Para x931, si se establece el tipo de digest, se utiliza para formatear los datos del bloque; de lo contrario, el primer byte se utiliza para especificar el ID del digest X9.31. Se pueden realizar firmas, verificaciones y recuperaciónde verificaciones en este modo.

Para pss, solo se soportan la firma y la verificación, y se debe especificar el tipo de digest.

rsa_pss_saltlen:len
Para el modo pss solamente, esta opción especifica la longitud de la sal. Se soportan tres valores especiales: digest establece la longitud de la sal a la longitud del digest, max establece la longitud de la sal al valor máximo permitido. Al verificar, auto hace que la longitud de la sal se determine automáticamente basándose en la estructura del bloque PSS.
rsa_mgf1_md:digest
Para el relleno PSS y OAEP, establece el digest MGF1. Si el digest MGF1 no se establece explícitamente en modo PSS, se utiliza el digest de firma.
rsa_oaep_md:digest
Establece el digest utilizado para la función hash OAEP. Si no se establece explícitamente, se utiliza SHA256.
rsa_pkcs1_implicit_rejection:flag
Deshabilita (cuando se establece en 0) o habilita (cuando se establece en 1) el uso de rechazo implícito con el descifrado PKCS#1 v1.5. Cuando está habilitada (por defecto), como protección contra el ataque de Bleichenbacher, la biblioteca generará un texto plano aleatorio determinista que devolverá al llamador en caso de fallo en la comprobación del relleno. Cuando está deshabilitada, es responsabilidad del llamador manejar los errores devueltos de manera que no sea susceptible a ataques de canal lateral.
