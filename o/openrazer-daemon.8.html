openrazer-daemon(8) Manual del Administrador del Sistema openrazer-daemon(8)

NOMBRE

openrazer-daemon - Demonio para gestionar dispositivos Razer en el espacio de usuario

SINOPSIS

openrazer-daemon [opciones...]

DESCRIPCIÓN

openrazer-daemon es un servicio del espacio de usuario diseñado para ser un intermediario entre los programas del espacio de usuario y los controladores de Razer. Proporcionará algunas funciones de alto nivel para permitir un funcionamiento similar al programa Razer Synapse de Windows. Este servicio está diseñado para ser iniciado por xdg-autostart como un servicio de sesión.

El servicio tiene la funcionalidad de sincronizar efectos entre múltiples dispositivos, realizar grabación y reproducción de macros sobre la marcha y reimplementa la lógica FN+Teclas para que funcionen cuando macro_keys está habilitado. El servicio también puede realizar varios efectos de onda y apagar los dispositivos cuando el salvapantallas está activo.

Tenga en cuenta que todas las rutas que se muestran como predeterminadas, por ejemplo, ~/.local/share/ o ~/.config/, pueden cambiarse con las variables de especificación del directorio base XDG: $XDG_CONFIG_HOME, $XDG_DATA_HOME y $XDG_RUNTIME_DIR.

OPCIONES

-v, --verbose

Habilita el registro de mensajes DEBUG.

-F, --foreground

Ejecuta el demonio en primer plano y no se bifurca. Esto también habilita el envío de la salida del registro a stdout (además del archivo de registro).

-r, --respawn

Detiene cualquier demonio en ejecución primero (si hay uno ejecutándose) antes de iniciarlo.

-s, --stop

Detiene graciosamente el demonio en ejecución.

--as-root

Permite que el demonio se inicie como root.

--config=archivo_config

Especifica la ubicación del archivo de configuración. Si no se proporciona, usará por defecto ~/.config/openrazer/razer.conf y lo creará si es necesario a partir del archivo de configuración de ejemplo.

--persistence=archivo_persistencia

Especifica la ubicación del archivo de persistencia. Se creará si no existe. Este archivo almacenará los estados de los dispositivos para que persistan entre reinicios.

--run-dir=directorio_ejecucion

Indica al demonio cuál es su directorio de ejecución, el directorio al que se cambiará una vez iniciado. Por defecto será $XDG_RUNTIME_DIR; si no está configurado, recurrirá a ~/.local/share/openrazer/.

--log-dir=directorio_log

Este argumento decide dónde estará el directorio de logs, el demonio en sí mismo manejará la rotación de logs ya que es un servicio de sesión de usuario. Por defecto, el demonio usará ~/.local/share/openrazer/logs/ para su directorio de logs.

--test-dir=directorio_prueba

Si se proporciona, el demonio operará en modo de controlador de prueba en el que expone dispositivos que no están conectados físicamente. Utiliza scripts/create_fake_device.py o scripts/setup_fake_devices.sh del repositorio de origen para crear la estructura de directorios.

DOCUMENTACIÓN

La documentación completa y más actualizada se puede encontrar en nuestro repositorio de GitHub en https://github.com/openrazer/openrazer.
