open(n)

Paquete: tcl

Licencias: TCL

open(n) Comandos integrados de Tcl open(n)

NOMBRE

open - Abrir un canal de archivo o de tubería de comandos

SINOPSIS

open nombreArchivo
open nombreArchivo modo
open nombreArchivo modo permisos

DESCRIPCIÓN

Este comando abre un archivo, puerto serie o tubería de comandos y devuelve un identificador de canal que puede ser usado en futuras invocaciones de comandos como read, puts y close. Si el primer carácter de nombreArchivo no es | entonces el comando abre un archivo: nombreArchivo da el nombre del archivo a abrir, y debe cumplir con las convenciones descritas en la entrada de manual filename.

El argumento modo, si está presente, indica la forma en la que se accederá al archivo (o tubería de comandos). En la primera forma modo puede tener cualquiera de los siguientes valores:

r
Abrir el archivo para solo lectura; el archivo debe existir. Este es el valor predeterminado si no se especifica modo.
r+
Abrir el archivo tanto para lectura como para escritura; el archivo debe existir.
w
Abrir el archivo solo para escritura. Truncarlo si existe. Si no existe, crear un nuevo archivo.
w+
Abrir el archivo para lectura y escritura. Truncarlo si existe. Si no existe, crear un nuevo archivo.
a
Abrir el archivo solo para escritura. Si el archivo no existe, crear un nuevo archivo vacío. Establecer el puntero de archivo al final del archivo antes de cada escritura.
a+
Abrir el archivo para lectura y escritura. Si el archivo no existe, crear un nuevo archivo vacío. Establecer la posición de acceso inicial al final del archivo.

Todos los valores legales de modo anteriores pueden tener el carácter b añadido como segundo o tercer carácter en el valor para indicar que el canal abierto debe configurarse como si fuera con la opción fconfigure -translation binary, haciendo el canal adecuado para lectura o escritura de datos binarios.

En la segunda forma, modo consiste en una lista de cualesquiera de las siguientes banderas, la mayoría de las cuales tienen los significados estándar de POSIX. Una de las banderas debe ser RDONLY, WRONLY o RDWR.

RDONLY
Abrir el archivo solo para lectura.
WRONLY
Abrir el archivo solo para escritura.
RDWR
Abrir el archivo tanto para lectura como para escritura.
APPEND
Establecer el puntero de archivo al final del archivo antes de cada escritura.
BINARY
Configurar el canal abierto con la opción -translation binary.
CREAT
Crear el archivo si no existe (sin esta bandera es un error que el archivo no exista).
EXCL
Si CREAT también está especificado, se devuelve un error si el archivo ya existe.
NOCTTY
Si el archivo es un dispositivo terminal, esta bandera previene que el archivo se convierta en el terminal de control del proceso.
NONBLOCK
Impide que el proceso se bloquee al abrir el archivo, y posiblemente en operaciones de I/O subsiguientes. El comportamiento exacto de esta bandera depende del sistema y del dispositivo; su uso no se recomienda (es mejor usar el comando fconfigure para poner un archivo en modo no bloqueante). Para más detalles consulte la documentación de su sistema sobre la bandera O_NONBLOCK de la llamada al sistema open.
TRUNC
Si el archivo existe, se trunca a longitud cero.

Si se crea un nuevo archivo como parte de su apertura, permisos (un entero) se usa para establecer los permisos para el nuevo archivo en conjunción con la máscara de creación de modo de archivo del proceso. Permisos tiene un valor predeterminado de 0666.

TUBERÍAS DE COMANDOS

Si el primer carácter de nombreArchivo es “|” entonces los caracteres restantes de nombreArchivo se tratan como una lista de argumentos que describen una tubería de comandos para invocar, en el mismo estilo que los argumentos para exec. En este caso, el identificador de canal devuelto por open puede ser usado para escribir en la tubería de entrada del comando o leer de su tubería de salida, dependiendo del valor de modo. Si se usa acceso solo escritura (ej. modo es “w”), entonces la salida estándar para la tubería se dirige a la salida estándar actual a menos que sea anulada por el comando. Si se usa acceso de solo lectura (ej. modo es “r”), la entrada estándar para la tubería se toma de la entrada estándar actual a menos que sea anulada por el comando. El id del proceso generado es accesible a través del comando pid, usando el id del canal devuelto por open como argumento.

Si el comando (o uno de los comandos) ejecutado en la tubería de comandos devuelve un error (según la definición en exec), se genera un error de Tcl cuando close se llama en el canal a menos que la tubería esté en modo no bloqueante, en cuyo caso no se devuelve estado de salida (un close silencioso con -blocking 0).

A menudo es útil usar el comando fileevent con tuberías para que otro procesamiento pueda ocurrir al mismo tiempo que se ejecuta el comando en segundo plano.

COMUNICACIONES SERIE

Si nombreArchivo se refiere a un puerto serie, entonces el puerto serie especificado se abre y se inicializa de manera dependiente de la plataforma. Los valores aceptables para nombreArchivo para abrir un puerto serie se describen en la sección PROBLEMAS DE PORTABILIDAD.

El comando fconfigure puede ser usado para consultar y establecer opciones de configuración adicionales específicas para puertos serie (donde se soporta):

-modo velocidadBaud,paridad,datos,stop
Esta opción es un conjunto de 4 valores separados por comas: la velocidad en baudios, paridad, número de bits de datos y número de bits de parada para este puerto serie. La velocidadBaud es un entero simple que especifica la velocidad de conexión. Paridad es una de las siguientes letras: n, o, e, m, s; que significan respectivamente las opciones de paridad de "ninguna", "impar", "par", "marca" o "espacio". Datos es el número de bits de datos y debe ser un entero de 5 a 8, mientras que stop es el número de bits de parada y debe ser el entero 1 o 2.
-handshake tipo
(Windows y Unix). Esta opción se usa para configurar el control automático de handshake. Tenga en cuenta que no todos los tipos de handshake pueden ser soportados por su sistema operativo. El parámetro tipo no distingue entre mayúsculas y minúsculas.

Si tipo es none entonces cualquier handshake se desactiva. rtscts activa el handshake de hardware. Las señales de handshake de hardware se describen a continuación. Para handshake de software xonxoff los caracteres de handshake pueden ser redefinidos con -xchar. Un handshake de hardware adicional dtrdsr está disponible solo en Windows. No hay configuración de handshake predeterminada, el valor inicial depende de la configuración de su sistema operativo. La opción -handshake no se puede consultar.

-queue
(Windows y Unix). La opción -queue solo se puede consultar. Devuelve una lista de dos enteros que representan el número actual de bytes en la cola de entrada y salida respectivamente.
-timeout msec
(Windows y Unix). Esta opción se usa para establecer el tiempo de espera para las operaciones de lectura bloqueantes. Especifica el intervalo máximo entre la recepción de dos bytes en milisegundos. Para sistemas Unix la granularidad es 100

When the channel is in blocking mode (the default), read and write operations will block until they complete. When the channel is in non-blocking mode, read and write operations will return immediately, even if they cannot complete. This option cannot be queried. .TP .B -buffering \fR\fIbufferMode\fR (Windows and Unix). This option is used to query or change the buffering mode for the channel. Possible values for \fIbufferMode\fR are \fBnone\fR, \fBline\fR, or \fBfull\fR. The default value is \fBfull\fR. When the buffering mode is \fBnone\fR, data is transferred immediately. When the buffering mode is \fBline\fR, data is transferred when a newline character is encountered. When the buffering mode is \fBfull\fR, data is transferred when the buffer is full or when the channel is closed. .TP .B -buffersize \fR\fIsize\fR (Windows and Unix). This option is used to query or change the size of the channel's buffer. The default buffer size is 4096 bytes. .TP .B -chunksize \fR\fIsize\fR (Windows and Unix). This option is used to query or change the chunk size for reading data from the channel. The default chunk size is 1024 bytes. .TP .B -command \fR\fIscript\fR (Windows and Unix). This option is used to associate a script with the channel. The script will be executed when the channel is ready for reading or writing. .TP .B -eof \fR\fIboolean\fR (Windows and Unix). This option is used to query whether the end of the file has been reached. This option cannot be changed. .TP .B -error \fR\fIerrorCode\fR (Windows and Unix). This option is used to query the error code associated with the channel. This option cannot be changed. .TP .B -inputsize \fR\fIsize\fR (Windows only). This option is used to query or change the size of the channel's input buffer. The default input buffer size is 4096 bytes. .TP .B -inputspeed \fR\fIspeed\fR (Windows only). This option is used to query or change the input speed of the channel. The speed is specified in bits per second. .TP .B -mode \fR\fImode\fR (Windows and Unix). This option is used to query or change the mode of the channel. The mode is a string of comma-separated options, such as: .RS .TP .B 9600,n,8,1 This specifies a baud rate of 9600, no parity, 8 data bits, and 1 stop bit. .TP .B 19200,e,7,2 This specifies a baud rate of 19200, even parity, 7 data bits, and 2 stop bits. .TP .B 38400,o,8,1 This specifies a baud rate of 38400, odd parity, 8 data bits, and 1 stop bit. .RE .TP .B -outputsize \fR\fIsize\fR (Windows only). This option is used to query or change the size of the channel's output buffer. The default output buffer size is 4096 bytes. .TP .B -outputspeed \fR\fIspeed\fR (Windows only). This option is used to query or change the output speed of the channel. The speed is specified in bits per second. .TP .B -polling \fR\fImsec\fR (Windows only). This option is used to query or change the polling interval for the channel. The polling interval is specified in milliseconds. .TP .B -rtscts \fR\fIboolean\fR (Windows and Unix). This option is used to query or change the RTS/CTS hardware flow control setting. When enabled, RTS/CTS flow control is used to regulate the flow of data. .TP .B -timeout \fR\fImsec\fR (Windows and Unix). This option is used to query or change the timeout for blocking read operations. The timeout is specified in milliseconds. A timeout of 0 means that reads will not block. This option does not affect write operations or nonblocking reads. This option cannot be queried. .TP .B -ttycontrol \fR\fI{signal boolean signal boolean ...}\fR (Windows and Unix). This option is used to set the handshake output lines (see below) permanently or to send a BREAK over the serial line. The \fIsignal\fR names are case-independent. \fB{RTS 1 DTR 0}\fR sets the RTS output to high and the DTR output to low. The BREAK condition (see below) is enabled and disabled with \fB{BREAK 1}\fR and \fB{BREAK 0}\fR respectively. It is not a good idea to change the \fBRTS\fR (or \fBDTR\fR) signal with active hardware handshake \fBrtscts\fR (or \fBdtrdsr\fR). The result is unpredictable. The \fB-ttycontrol\fR option cannot be queried. .TP .B -ttystatus (Windows and Unix). This option can only be queried. It returns the current modem status and handshake input signals (see below). The result is a list of signal,value pairs with a fixed order, e.g. \fB{CTS 1 DSR 0 RING 1 DCD 0}\fR. The \fIsignal\fR names are returned upper case. .TP .B -xchar \fR\fI{xonChar xoffChar}\fR (Windows and Unix). This option is used to query or change the software handshake characters. Normally the operating system default should be DC1 (0x11) and DC3 (0x13) representing the ASCII standard XON and XOFF characters. .TP .B -pollinterval \fR\fImsec\fR (Windows only). This option is used to set the maximum time between polling for fileevents. This affects the time interval between checking for events throughout the Tcl interpreter (the smallest value always wins). Use this option only if you want to poll the serial port more or less often than 10 msec (the default). .TP .B -sysbuffer \fR\fIinSize\fR .TP .B -sysbuffer \fR\fI{inSize outSize}\fR (Windows only). This option is used to change the size of Windows system buffers for a serial channel. Especially at higher communication rates the default input buffer size of 4096 bytes can overrun for latent systems. The first form specifies the input buffer size, in the second form both input and output buffers are defined. .TP .B -lasterror (Windows only). This option is query only. See below for an explanation of the various error codes. .PD .SS SERIAL PORT SIGNALS .PP RS-232 is the most commonly used standard electrical interface for serial communications. A negative voltage (-3V..-12V) define a mark (on=1) bit and a positive voltage (+3..+12V) define a space (off=0) bit (RS-232C). The following signals are specified for incoming and outgoing data, status lines and handshaking. Here we are using the terms \fIworkstation\fR for your computer and \fImodem\fR for the external device, because some signal names (DCD, RI) come from modems. Of course your external device may use these signal lines for other purposes. .TP .B TXD(output) Transmitted Data: Outgoing serial data. .TP .B RXD(input) Received Data:Incoming serial data. .TP .B RTS(output) Request To Send: This hardware handshake line informs the modem that your workstation is ready to receive data. Your workstation may automatically reset this signal to indicate that the input buffer is full. .TP .B CTS(input) Clear To Send: The complement to RTS. Indicates that the modem is ready to receive data. .TP .B DTR(output) Data Terminal Ready: This signal tells the modem that the workstation is ready to establish a link. DTR is often enabled automatically whenever a serial port is opened. .TP .B DSR(input) Data Set Ready: The complement to DTR. Tells the workstation that the modem is ready to establish a link. .TP .B DCD(input) Data Carrier Detect: This line becomes active when a modem detects a “Carrier” signal. .TP .B RI(input) Ring Indicator: Goes active when the modem detects an incoming call. .TP .B BREAK A BREAK condition is not a hardware signal line, but a logical zero on the TXD or RXD lines for a long period of time, usually 250 to 500 milliseconds. Normally a receive or transmit data signal stays at the mark (on=1) voltage until the next character is transferred. A BREAK is sometimes used to reset the communications line or change the operating mode of communications hardware. .SS ERROR CODES (Windows only) .PP A lot of different errors may occur during serial read operations or during event polling in background. The external device may have been switched off, the data lines may be noisy, system buffers may overrun or your mode settings may be wrong. That is why a reliable software should always catch serial read operations. In cases of an error Tcl returns a general file I/O error. Then \fBfconfigure\fR \fB-lasterror\fR may help to locate the problem. The following error codes may be returned. .TP .B RXOVER Windows input buffer overrun. The data comes faster than your scripts reads it or your system is overloaded. Use \fBfconfigure\fR \fB-sysbuffer\fR to avoid a temporary bottleneck and/or make your script faster. .TP .B TXFULL Windows output buffer overrun. Complement to RXOVER. This error should practically not happen, because Tcl cares about the output buffer status. .TP .B OVERRUN UART buffer overrun (hardware) with data lost. The data comes faster than the system driver receives it. Check your advanced serial port settings to enable the FIFO (16550) buffer and/or setup a lower(1) interrupt threshold value. .TP .B RXPARITY A parity error has been detected by your UART. Wrong parity settings with \fBfconfigure\fR \fB-mode\fR or a noisy data line (RXD) may cause this error. .TP .B FRAME A stop-bit error has been detected by your UART. EJEMPLOS

Open a file for writing, creating it if it does not exist, but failing if it does exist:

set fh [open filename.txt {WRONLY CREAT EXCL}]

Open a file for writing as a log file.

set myLogFile [open filename.log "a"]
fconfigure $myLogFile -buffering line

Open a command pipeline and catch any errors:

set fl [open "| ls this_file_does_not_exist"]
set data [read $fl]
if {[catch {close $fl} err]} {
    puts "ls command failed: $err"
}

Open a command pipeline and read binary data from it. Note the unusual form with “|[list” that handles non-trivial edge cases with arguments that potentially have spaces in.

set fl [open |[list create_image_data $input] "rb"]
set binData [read $fl]
close $fl
