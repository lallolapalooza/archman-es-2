NOMBRE

ovsqlite - método de almacenamiento de resumen basado en SQLite para INN

DESCRIPCIÓN

Este método utiliza SQLite para almacenar datos de resumen. Requiere la versión 3.8.2 o posterior de la biblioteca SQLite (se recomiendan 3.20.0+).

El código fuente, la documentación, etc. de SQLite están disponibles en https://www.sqlite.org/. Uno de los objetivos declarados del formato de archivo SQLite son la estabilidad a largo plazo y la compatibilidad, lo que convierte a ese método de almacenamiento en una opción perfecta para almacenar datos de resumen.

Actualmente solo existe una versión del protocolo del método de almacenamiento ovsqlite, implementada desde INN 2.7.0.

Este método viene con una utilidad de soporte (ovsqlite-util) y un módulo Perl ("INN::ovsqlite_client") que permiten acceder y manipular información de resumen. Consulte sus páginas del manual para obtener más detalles sobre sus posibilidades.

INSTALACIÓN

El script de configuración habilitará automáticamente el soporte ovsqlite si encuentra la biblioteca SQLite. Si la biblioteca no está instalada en una ubicación estándar, es posible que deba especificar la opción --with-sqlite3 para ayudar a la configuración a encontrarla. Para casos complicados, puede usar las opciones separadas --with-sqlite3-include y --with-sqlite3-lib. Finalmente, si *no* desea el soporte ovsqlite incluso cuando su sistema tiene la biblioteca SQLite, puede usar la opción --without-sqlite3.

Si tiene una instalación Linux reciente, lo más probable es que SQLite ya esté instalado. Es posible que deba instalar un paquete separado con un nombre similar a "libsqlite3-dev" para obtener los archivos de encabezado requeridos.

Planifique necesitar al menos 0.93 KB por cada artículo en su spool (sin contar los crossposts). Por lo tanto, si tiene 5 millones de artículos, necesitará al menos 4.65 GB de espacio en disco para ovsqlite. Con la compresión habilitada, esta estimación cambia a 0.4 KB por artículo, por lo que necesitará al menos 2 GB de espacio en disco para 5 millones de artículos. Además, necesitará espacio adicional para los registros de transacciones (unos pocos MB).

CONFIGURACIÓN

Para seleccionar ovsqlite como su método de resumen, establezca el parámetro ovmethod en inn.conf a "ovsqlite". El archivo de la base de datos se creará en el directorio especificado por el parámetro pathoverview en inn.conf. Reinicie INN para tener en cuenta el cambio (después de haber reconstruido su resumen existente con makehistory, si es necesario).

Estos parámetros adicionales se leen del archivo de configuración ovsqlite.conf:

cachesize
El tamaño de la caché de páginas en memoria de SQLite en kilobytes. El valor predeterminado se deja a la biblioteca SQLite y parece ser estable en 2000 KB.
compress
Si INN se compiló con soporte zlib y este parámetro es verdadero, ovsqlite comprimirá los registros de resumen siempre que esto ahorre espacio. Este parámetro solo se consulta al crear una nueva base de datos. Habilitar la compresión ahorra aproximadamente el 55 % del espacio en disco en datos de resumen estándar. El valor predeterminado es falso.
pagesize
El tamaño de página de la base de datos SQLite en bytes. Debe ser una potencia de 2, mínimo 512, máximo 65536. Los valores apropiados incluyen el tamaño de página de memoria virtual y el tamaño del bloque de asignación del sistema de archivos. Este parámetro solo se consulta al crear una nueva base de datos. El valor predeterminado se deja a la biblioteca SQLite y varía entre versiones.
transrowlimit
El número máximo de filas de artículos que se pueden insertar o eliminar en una sola transacción SQL. El valor predeterminado es 10000 artículos.
transtimelimit
La duración máxima de la transacción SQL en segundos. El valor predeterminado es 10 segundos.

Se produce una transacción cada transrowlimit artículos o transtimelimit segundos, lo que sea menor. Se recomienda mantener el valor predeterminado para los límites de filas y, en cambio, ajustar el límite de tiempo según cuántos artículos acepta normalmente su servidor de noticias por segundo durante la operación normal (puede encontrar estadísticas sobre los artículos entrantes en sus informes diarios de Usenet). Insertar o eliminar una fila de la base de datos dentro de una transacción es muy rápido, mientras que confirmar una transacción es lento, especialmente en almacenamiento rotatorio. Establecer los límites de transacción demasiado bajos conduce a un rendimiento deficiente. Al reconstruir datos de resumen, puede valer la pena aumentar temporalmente estos valores en sistemas con CPU lentas o almacenamiento rotatorio (por ejemplo, multiplique por 10 los valores predeterminados). El rendimiento no cambiará mucho en sistemas rápidos.

EJECUCIÓN

Todo el acceso a la base de datos de resumen pasa a través del demonio ovsqlite-server. Para la operación normal, rc.news lo iniciará y detendrá automáticamente. Si desea manipular la base de datos de resumen mientras innd no se está ejecutando, primero deberá iniciar ovsqlite-server manualmente. Vea ovsqlite-server(8).
