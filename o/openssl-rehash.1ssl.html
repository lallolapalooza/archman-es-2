openssl-rehash(1ssl)

Paquete: openssl

Licencias: Apache-2.0

OPENSSL-REHASH(1ssl) OpenSSL OPENSSL-REHASH(1ssl)

NOMBRE

openssl-rehash, c_rehash - Crea enlaces simbólicos a archivos con nombres basados en sus valores hash

SINOPSIS =para opciones duplicadas de openssl

openssl rehash [-h] [-help] [-old] [-compat] [-n] [-v] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq] [directorio] ...

c_rehash [-h] [-help] [-old] [-n] [-v] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq] [directorio] ...

DESCRIPCIÓN

Este comando es generalmente equivalente al script externo c_rehash, excepto por diferencias menores que se detallan a continuación.

openssl rehash escanea directorios y calcula un valor hash de cada archivo .pem, .crt, .cer o .crl en la lista de directorios especificada y crea enlaces simbólicos para cada archivo, donde el nombre del enlace es el valor hash. (Si la plataforma no soporta enlaces simbólicos, se realiza una copia.) Este comando es útil ya que muchos programas que usan OpenSSL requieren que los directorios estén configurados de esta manera para poder encontrar certificados.

Si se nombran directorios en la línea de comandos, estos se procesan en orden. Si no, se consulta la variable de entorno SSL_CERT_DIR; esta debe ser una lista de directorios separados por dos puntos, similar a la variable PATH de Unix. Si no está configurada, se procesa el directorio predeterminado (específico de la instalación, pero a menudo /usr/local/ssl/certs).

Para que un directorio sea procesado, el usuario debe tener permisos de escritura en ese directorio, de lo contrario se generará un error.

Los enlaces creados son del tipo HHHHHHHH.D, donde cada H es un carácter hexadecimal y D es un solo dígito decimal. Cuando se procesa un directorio, todos los enlaces en él que tengan un nombre en esa sintaxis se eliminan primero, incluso si se están utilizando para algún otro propósito. Para omitir el paso de eliminación, use la bandera -n. Los hashes para CRL (listas de revocación de certificados) tienen un aspecto similar, excepto que la letra r aparece después del punto, así: HHHHHHHH.rD.

Múltiples objetos pueden tener el mismo hash; se indicarán incrementando el valor D. Los duplicados se encuentran comparando la huella digital SHA-1 completa. Se mostrará una advertencia si se encuentra un duplicado.

También se mostrará una advertencia si hay archivos que no se pueden analizar como certificado o CRL, o si aparece más de un objeto de este tipo en el archivo.

Configuración del script

El script c_rehash utiliza el programa openssl para calcular los hashes y las huellas digitales. Si no se encuentra en el PATH del usuario, establezca la variable de entorno OPENSSL a la ruta completa. Se puede utilizar cualquier programa, se invocará de la siguiente manera para un certificado o un CRL:

$OPENSSL x509 -hash -fingerprint -noout -in NOMBRE_ARCHIVO
$OPENSSL crl -hash -fingerprint -noout -in NOMBRE_ARCHIVO

donde NOMBRE_ARCHIVO es el nombre del archivo. Debe producir el hash del archivo en la primera línea y la huella digital en la segunda, opcionalmente precedido por algún texto y un signo igual.

OPCIONES

-help -h
Muestra un breve mensaje de uso.
-old
Usa hashing de estilo antiguo (MD5, en lugar de SHA-1) para generar enlaces que se utilizarán para versiones anteriores a 1.0.0. Tenga en cuenta que las versiones actuales no utilizarán el estilo antiguo.
-n
No elimine los enlaces existentes. Esto es necesario cuando se mantienen enlaces de estilo nuevo y antiguo en el mismo directorio.
-compat
Genera enlaces tanto para el hashing de estilo antiguo (MD5) como para el de estilo nuevo (SHA1). Esto permite que las versiones anteriores a 1.0.0 utilicen estos enlaces junto con versiones más recientes.
-v
Muestra mensajes sobre los enlaces antiguos eliminados y los nuevos enlaces creados. Por defecto, este comando solo lista cada directorio a medida que se procesa.
-provider nombre
-provider-path ruta
-provparam [nombre:]clave=valor
-propquery propq
Consulte "Opciones del proveedor" en openssl(1), provider(7) y property(7).

AMBIENTE

OPENSSL
La ruta a un ejecutable que se utilizará para generar hashes y huellas digitales (ver arriba).
PATH
Lista de rutas, separadas por dos puntos (o punto y coma, en plataformas Windows), donde se busca el ejecutable openssl en caso de que la ruta del ejecutable generador de hashes no se proporcione en la variable de entorno OPENSSL o no sea utilizable (es decir, no exista o no sea ejecutable).
SSL_CERT_DIR
Lista de directorios separados por dos puntos en los que operar. Se ignora si se listan directorios en la línea de comandos.
