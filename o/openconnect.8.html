OPENCONNECT(8) Manual del Administrador del Sistema OPENCONNECT(8)

NOMBRE

openconnect - Cliente VPN multiprotocolo, para VPN de Cisco AnyConnect y otras

SINOPSIS

openconnect [--config archivo_config] [-b,--background] [--pid-file archivo_pid] [-c,--certificate certificado] [-e,--cert-expire-warning días] [-k,--sslkey clave] [-C,--cookie cookie] [--cookie-on-stdin] [--compression MODO] [-d,--deflate] [-D,--no-deflate] [--force-dpd intervalo] [--force-trojan intervalo] [-F,--form-entry formulario:opción=valor] [-g,--usergroup grupo] [-h,--help] [--http-auth métodos] [--external-browser navegador] [-i,--interface nombre_if] [-l,--syslog] [--timestamp] [--passtos] [-U,--setuid usuario] [--csd-user usuario] [-m,--mtu mtu] [--base-mtu mtu] [-p,--key-password contraseña] [-P,--proxy url_proxy] [--proxy-auth métodos] [--no-proxy] [--libproxy] [--key-password-from-fsid] [-q,--quiet] [-Q,--queue-len longitud] [-s,--script script_vpnc] [-S,--script-tun] [-u,--user nombre] [-V,--version] [-v,--verbose] [-x,--xmlconfig config] [--authgroup grupo] [--authenticate] [--cookieonly] [--printcookie] [--cafile archivo] [--disable-ipv6] [--dtls-ciphers lista] [--dtls12-ciphers lista] [--dtls-local-port puerto] [--dump-http-traffic] [--no-system-trust] [--pfs] [--no-dtls] [--no-http-keepalive] [--no-passwd] [--no-xmlpost] [--non-inter] [--passwd-on-stdin] [--protocol proto] [--token-mode modo] [--token-secret {secreto[,contador]|@archivo}] [--reconnect-timeout segundos] [--resolve host:ip] [--sni host] [--servercert sha1] [--useragent cadena] [--version-string cadena] [--local-hostname cadena] [--os cadena]
--force-dpd=INTERVAL
Use INTERVAL como intervalo de Detección de Peer Muerto (en segundos). Esto hará que el cliente use DPD en el intervalo especificado incluso si el servidor no lo ha solicitado, o en un intervalo diferente al solicitado por el servidor.

Los mecanismos de DPD varían según el protocolo y el transporte (TLS o DTLS/ESP), pero todos son funcionalmente similares: permiten que el cliente VPN o el servidor VPN transmitan una señal al par, solicitando una respuesta inmediata que se puede utilizar para confirmar que el enlace entre los dos pares todavía está funcionando.

-g,--usergroup=GROUP
Establecer la ruta URL de la conexión HTTPS inicial al servidor.

Con algunos protocolos, esta ruta puede funcionar como un grupo de inicio de sesión o un reino, de ahí el nombre de esta opción. Por ejemplo, las siguientes invocaciones de OpenConnect son equivalentes:

openconnect --usergroup=loginPath vpn.server.com
openconnect https://vpn.server.com/loginPath
-F,--form-entry=FORM:OPTION[=VALUE]
Proporcionar entrada de formulario de autenticación, donde FORM y OPTION son los identificadores del formulario y el campo de entrada específico, y VALUE es la cadena que se rellenará automáticamente. Por ejemplo, el campo de nombre de usuario estándar (también manejado por la opción --user) también podría proporcionarse con esta opción de la siguiente manera: --form-entry main:username=joebloggs.

Si VALUE no se especifica, esta opción hará que un campo oculto del formulario se trate como un campo de entrada de texto estándar.

Esta opción no debe usarse para ingresar contraseñas. --passwd-on-stdin debe usarse para ese propósito. No solo esta opción expondrá el valor de la contraseña en la línea de comandos del proceso OpenConnect, sino que, a diferencia de --passwd-on-stdin, esta opción no reconocerá el caso de una contraseña incorrecta y dejará de intentar ingresarla repetidamente.

-h,--help
Mostrar texto de ayuda
--http-auth=METHODS
Utilizar solo los métodos especificados para la autenticación HTTP a un servidor. Por defecto, solo Negotiate, NTLM y Digest la autenticación está habilitada. La autenticación Basic también es compatible, pero como es insegura, debe habilitarse explícitamente. El argumento es una lista separada por comas de métodos que se habilitarán. Tenga en cuenta que el orden no importa: OpenConnect utilizará la autenticación Negotiate, NTLM, Digest y Basic en ese orden, si cada una está habilitada, independientemente del orden especificado en la cadena METHODS.
--external-browser=BROWSER
Establecer BROWSER como el ejecutable utilizado por OpenConnect para manejar el proceso de autenticación con gateways que admiten el método de autenticación single-sign-on-external-browser.
-i,--interface=IFNAME
Usar IFNAME para la interfaz del túnel
-l,--syslog
Después de que el túnel se establezca, usar syslog para más mensajes de progreso
--timestamp
Prefijar una marca de tiempo a cada mensaje de progreso
--passtos
Copiar TOS / TCLASS del paquete de carga útil a los paquetes DTLS y ESP. Esto no se establece por defecto porque puede filtrar información sobre la carga útil (por ejemplo, al diferenciar el tráfico de voz/video).
-U,--setuid=USER
Reducir privilegios después de la conexión, para convertirse en el usuario USER
--csd-user=USER
Reducir privilegios durante la ejecución del binario o script troyano (CSD, TNCC o HIP).
--csd-wrapper=SCRIPT
Ejecutar SCRIPT en lugar del binario o script troyano.
--force-trojan=INTERVAL
Usar INTERVAL como intervalo (en segundos) para la ejecución repetida del binario o script troyano, anulando el intervalo predeterminado y/o el establecido por el servidor.
-m,--mtu=MTU
Solicitar MTU al servidor como la MTU del túnel.
--base-mtu=MTU
Indicar MTU como la MTU de ruta entre el cliente y el servidor en la red no cifrada. Los servidores más nuevos calcularán automáticamente la MTU a utilizar en el túnel a partir de este valor.
-p,--key-password=PASS [,--mca-key-password=PASS]
Proporcionar frase de contraseña para el archivo de certificado, o PIN de SRK (System Root Key) para TPM

--mca-key-password proporciona la frase de contraseña para el certificado secundario (ver --mca-certificate).

-P,--proxy=PROXYURL
Usar proxy HTTP o SOCKS para la conexión. Se puede proporcionar un nombre de usuario y una contraseña en la URL dada, y se utilizarán para la autenticación. Si se requiere autenticación pero no se proporcionan credenciales, se pueden intentar la autenticación GSSAPI y NTLM automática utilizando la herramienta auxiliar ntlm_auth de Samba.
--proxy-auth=METHODS
Utilizar solo los métodos especificados para la autenticación HTTP a un proxy. Por defecto, solo Negotiate, NTLM y Digest la autenticación están habilitadas. La autenticación Basic también es compatible, pero como es insegura, debe habilitarse explícitamente. El argumento es una lista separada por comas de métodos que se habilitarán. Tenga en cuenta que el orden no importa: OpenConnect utilizará Negotiate, NTLM, Digest y Basic la autenticación en ese orden, si cada una está habilitada, independientemente del orden especificado en la cadena METHODS.
--no-proxy
Deshabilitar el uso de proxy
--libproxy
Usar libproxy para configurar el proxy automáticamente (cuando se compila con soporte libproxy)
--key-password-from-fsid
La frase de contraseña para el archivo de certificado se genera automáticamente a partir del fsid del sistema de archivos en el que está almacenado. El fsid se obtiene de la llamada al sistema statvfs(2) o statfs(2), dependiendo del sistema operativo. En un sistema Linux o similar con GNU coreutils, el fsid utilizado por esta opción debe ser igual a la salida del comando: 
stat --file-system --printf=%i\\n $CERTIFICATE
No es lo mismo que el UUID de 128 bits del sistema de archivos.
-q,--quiet
Menos salida
-Q,--queue-len=LEN
Establecer el límite de cola de paquetes a LEN paquetes. El valor predeterminado es 32. Un valor alto puede permitir un mejor ancho de banda general, pero a costa de la latencia. Si ejecuta Voz sobre IP u otro tráfico interactivo a través de la VPN, no querrá que esos paquetes se pongan en cola detrás de miles de otros paquetes grandes que forman parte de una transferencia masiva.

Esta opción establece los tamaños máximos de cola de paquetes entrantes y salientes en OpenConnect, que controlan cuántos paquetes se enviarán y recibirán en un solo lote, además de afectar otros búferes como el búfer de envío de sockets (SO_SNDBUF) para las conexiones de red y el dispositivo de túnel del SO.

En última instancia, el tamaño correcto para una cola es "solo suficientes paquetes para que nunca se vacíe por completo antes de que se le envíen más". Cualquier cosa más alta simplemente introduce latencia adicional y bloat de búfer sin ningún beneficio. Con el valor predeterminado de 32, podemos saturar una sola Gigabit Ethernet desde hardware modesto, lo que es más que suficiente para la mayoría de los usuarios de VPN.

Si OpenConnect se compila con soporte vhost-net, solo se utilizará si la longitud de la cola se establece en 16 o más. Esto se debe a que vhost-net introduce una pequeña cantidad de latencia adicional, pero mejora considerablemente el ancho de banda total para aquellos que operan a altas tasas de tráfico. Por lo tanto, tiene sentido usarlo cuando el usuario ha indicado una preferencia por el ancho de banda sobre la latencia, aumentando el tamaño de la cola.

-s,--script=SCRIPT
Invocar SCRIPT para configurar la red después de la conexión. Sin esto, es poco probable que el enrutamiento y el servicio de nombres funcionen correctamente. Se espera que el script sea compatible con vpnc-script que se incluye con el cliente VPN "vpnc". Consulte https://www.infradead.org/openconnect/vpnc-script.html para más información. Esta versión de OpenConnect está configurada para usar /etc/vpnc/vpnc-script por defecto.

En Windows, un directorio relativo para el script predeterminado se manejará como comenzando desde el directorio desde el que se ejecuta el ejecutable de openconnect, en lugar del directorio actual. El script se invocará con el host de script basado en línea de comandos cscript.exe.

-S,--script-tun
Pasar tráfico a un programa 'script' a través de un socket UNIX, en lugar de a un dispositivo tun/tap del kernel. Esto permite que el tráfico IP de la VPN se maneje completamente en el espacio de usuario, por ejemplo, por un programa que utiliza lwIP para proporcionar acceso SOCKS a la VPN.
--server=[https://]HOST[:PORT][/PATH]
Definir el servidor VPN como un simple HOST o como una URL que contiene el HOST y opcionalmente el número de PORT y la PATH; con algunos protocolos, la ruta puede funcionar como un grupo de inicio de sesión o un reino, y puede especificarse de manera equivalente con --usergroup.

Alternativamente, definir el servidor VPN como un argumento de línea de comandos sin opción.

-u,--user=NAME
Establecer el nombre de usuario de inicio de sesión a NAME
-V,--version
Informar el número de versión
-v,--verbose
Más salida (puede especificarse varias veces para salida adicional)
-x,--xmlconfig=CONFIG
Archivo de configuración XML
--authgroup=GROUP
Seleccionar GROUP de la lista desplegable de autenticación o entrada de lista.

--resolve=HOST:IP
Resuelve automáticamente el nombre de host HOST a IP en lugar de utilizar el resolutor normal para buscarlo.
--sni=HOST
Al crear nuevas conexiones TLS, presenta siempre el nombre de host HOST como SNI (Server Name Indication) en lugar del nombre de host correcto, que aún se enviará en la cabecera HTTP 'Host:', y espera que el certificado del par coincida con el SNI en lugar del nombre de host correcto. Esto puede ser útil para el Domain Fronting, mediante el cual se pueden evitar algunas conexiones a Internet filtradas o censuradas.

Tenga en cuenta que enviar valores diferentes para el encabezado SNI y 'Host:' viola los estándares HTTP y es impedido por muchos proveedores de alojamiento en la nube.

--servercert=HASH
Acepta el certificado SSL del servidor solo si coincide con la huella digital proporcionada. Esta opción implica --no-system-trust, y puede especificarse varias veces para aceptar múltiples huellas digitales posibles.

Los tipos de huella digital permitidos son SHA1, SHA256, y PIN-SHA256. Se distinguen por los prefijos 'sha1:', 'sha256:' y 'pin-sha256:' al hash codificado. Los dos primeros son identificadores personalizados que proporcionan la codificación hexadecimal de la clave pública del par, mientras que 'pin-sha256:' es el PIN de clave RFC7469, que utiliza codificación base64. Para facilitar ciertos casos de uso de prueba, también se aceptará una coincidencia parcial del hash, si tiene al menos 4 caracteres después del prefijo.

--useragent=STRING
Utiliza STRING como valor del campo 'User-Agent:' en la cabecera HTTP.

Algunos servidores VPN pueden requerir valores específicos que coincidan con los enviados por clientes VPN propietarios para autenticarse o conectarse correctamente. Por ejemplo, al conectarse a un servidor Cisco VPN, --useragent 'AnyConnect Windows 4.10.06079' o --useragent 'Cisco AnyConnect VPN Agent for Windows 2.2.0133', o al conectarse a un servidor Pulse, --useragent 'Pulse-Secure/9.1.11.6725'.

--version-string=STRING
Utiliza STRING como la versión del software reportada al punto final. (ej. --version-string '2.2.0133')
--local-hostname=STRING
Utiliza STRING como valor del campo 'X-CSTP-Hostname:' en la cabecera HTTP. Por ejemplo, --local-hostname 'miordenador', anunciará el valor 'miordenador' como el nombre de host sugerido para apuntar a la dirección IP proporcionada.
--os=STRING
Tipo de SO a reportar a la puerta de enlace. Los valores reconocidos son: linux, linux-64, win, mac-intel, android, apple-ios. Reportar un tipo de SO diferente puede afectar la política de acceso dinámico (DAP) aplicada a la sesión VPN. Si la puerta de enlace requiere CSD, también provocará la descarga del binario troyano CSD correspondiente, por lo que es posible que necesite usar --csd-wrapper si este código no es ejecutable en la máquina local.

SEÑALES

En la fase de datos de la conexión, se manejan las siguientes señales:

SIGINT / SIGTERM
realiza un apagado limpio cerrando la sesión, desconectándose de la puerta de enlace y ejecutando el script vpnc-script para restaurar la configuración de red.
SIGHUP
se desconecta de la puerta de enlace y ejecuta el script vpnc-script, pero no cierra la sesión; esto permite la reconexión posterior usando --cookie.
SIGUSR1
escribe un mensaje de progreso con información detallada de la conexión y estadísticas.
SIGUSR2
fuerza una desconexión y reconexión inmediata; esto se puede utilizar para recuperarse rápidamente de cambios en la dirección IP de la LAN.
