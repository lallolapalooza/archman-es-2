NOMBRE

org.freedesktop.login1 - La interfaz D-Bus de systemd-logind

INTRODUCCIÓN

systemd-logind.service(8) es un servicio del sistema que realiza un seguimiento de los inicios de sesión de usuarios y los asientos (seats).

El demonio proporciona tanto una interfaz de biblioteca C como una interfaz D-Bus. La interfaz de biblioteca puede ser utilizada para introspeccionar y observar el estado de los inicios de sesión de usuarios y los asientos. La interfaz del bus proporciona la misma funcionalidad, pero además también puede ser utilizada para realizar cambios en el estado del sistema. Para más información, consulte sd-login(3).

Métodos


GetSession() puede ser utilizado para obtener el objeto de sesión para
    la sesión con el ID especificado. De manera similar, GetUser() y
    GetSeat() obtienen los objetos de usuario y asiento, respectivamente.
    GetSessionByPID() y GetUserByPID() obtienen la sesión/usuario
    al que pertenece el PID especificado, si existe alguno.


ListSessions() devuelve una matriz de todas las sesiones actuales.
    Las estructuras en la matriz consisten en los siguientes campos: ID de
    sesión, ID de usuario, nombre de usuario, ID de
    asiento y ruta del objeto de sesión. Si una sesión no tiene un
    asiento adjunto, el campo del ID de asiento será una cadena vacía.


ListSessionsEx() devuelve una matriz de todas las sesiones actuales
    con más metadatos que ListSessions(). Las estructuras en la matriz
    consisten en los siguientes campos: ID de sesión, ID de
    usuario, nombre de usuario, ID de asiento, PID
    líder, clase de sesión, nombre de tty, indicador
    inactivo, marca de tiempo monotónica del indicador inactivo y
    ruta del objeto de sesión. Los campos tty y ID de
    asiento podrían estar vacíos, si la sesión no tiene un tty asociado o
    la sesión no tiene un asiento adjunto, respectivamente.


ListUsers() devuelve una matriz de todos los usuarios actualmente
    conectados. Las estructuras en la matriz consisten en los siguientes
    campos: ID de usuario, nombre de usuario, ruta del objeto de usuario.


ListSeats() devuelve una matriz de todos los asientos actualmente
    disponibles. La estructura en la matriz consiste en los siguientes
    campos: ID de asiento, ruta del objeto de asiento.


ListInhibitors() lista todos los inhibidores activos actualmente.
    Devuelve una matriz de estructuras que consisten en qué,
    quién, por qué, modo, uid (ID de usuario) y
    pid (ID de proceso).


CreateSession(), CreateSessionWithPIDFD() y
    ReleaseSession() pueden ser utilizados para abrir o cerrar sesiones de
    inicio de sesión. Estas llamadas nunca deben ser invocadas
    directamente por los clientes. Crear/cerrar sesiones es exclusivamente trabajo
    de PAM y su módulo pam_systemd(8).


ActivateSession() trae la sesión con el ID especificado al
    primer plano. ActivateSessionOnSeat() hace lo mismo, pero solo si el
    ID del asiento coincide.


LockSession() solicita a la sesión con el ID especificado que active
    el bloqueo de pantalla. UnlockSession() solicita a la sesión con el ID
    especificado que elimine un bloqueo de pantalla activo, si existe alguno.
    Esto se implementa enviando las señales Lock() y Unlock() desde el objeto de
    sesión respectivo que los administradores de sesiones deben escuchar.


LockSessions() solicita a todas las sesiones que activen sus bloqueos
    de pantalla. Esto puede ser utilizado para bloquear el acceso a toda la
    máquina en una sola acción. De manera similar, UnlockSessions()
    solicita a todas las sesiones que desactiven sus bloqueos de pantalla.


KillSession() puede ser utilizado para enviar una señal Unix a uno
    o todos los procesos de una sesión. Como argumentos toma el ID de la
    sesión, ya sea la cadena "leader" o "all" y un número de señal. Si se pasa
    "leader", solo se mata al "líder" de la sesión. Si se pasa "all", se matan
    todos los procesos de la sesión.


KillUser() puede ser utilizado para enviar una señal Unix a todos
    los procesos de un usuario. Como argumentos toma el ID del usuario y un número
    de señal.


TerminateSession(), TerminateUser(),
    TerminateSeat() pueden ser utilizados para terminar forzosamente una
    sesión específica, todos los procesos de un usuario y todas las sesiones
    adjuntas a un asiento específico, respectivamente. La sesión, el usuario y el
    asiento se identifican por sus respectivos IDs.


SetUserLinger() habilita o deshabilita el "linger" de usuario. Si está
    habilitado, el directorio de tiempo de ejecución de un usuario se mantiene y
    puede seguir ejecutando procesos mientras está desconectado. Si está
    deshabilitado, el directorio de tiempo de ejecución desaparece tan pronto como
    se desconecta. SetUserLinger() espera tres argumentos: el UID, un
    booleano para habilitar/deshabilitar y un booleano que controla la interactividad
    de autorización de polkit[1] (ver abajo). Tenga en cuenta que el
    estado de "linger" del usuario se almacena de forma persistente en el disco.


AttachDevice() puede ser utilizado para asignar un dispositivo específico
    a un asiento específico. El dispositivo se identifica por su ruta /sys/ y debe
    ser elegible para asignaciones de asientos. AttachDevice() toma tres
    argumentos: el ID del asiento, la ruta sysfs y un booleano para controlar la
    interactividad de polkit (ver abajo). Las asignaciones de dispositivos se
    almacenan de forma persistente en el disco. Para crear un nuevo asiento,
    simplemente especifique un ID de asiento previamente no utilizado. Para más
    información sobre la lógica de asignación de asientos, consulte sd-login(3).


FlushDevices() elimina todas las asignaciones de asientos explícitas
    para los dispositivos, restableciendo todas las asignaciones a los valores
    predeterminados automáticos. El único argumento que toma es el booleano de
    interactividad de polkit (ver abajo).


PowerOff(), Reboot(), Halt(),
    Suspend() y Hibernate() resultan en el apagado, reinicio,
    parada (apagado sin cortar la energía), suspensión (el estado del sistema se
    guarda en RAM y la CPU se apaga) o hibernación (el estado del sistema se guarda
    en disco y la máquina se apaga) del sistema.
    HybridSleep() resulta en que el sistema entre en modo de sueño
    híbrido, es decir, el sistema se hiberna y se suspende.
    SuspendThenHibernate() resulta en que el sistema se suspende, luego
    se despierta más tarde usando un temporizador RTC y se hiberna. El único
    argumento es el booleano de interactividad de polkit interactive (ver
    abajo). El propósito principal de estas llamadas es que hacen cumplir la
    política de polkit y, por lo tanto, permiten apagar/reiniciar/suspender/hibernar
    incluso a usuarios no privilegiados. También hacen cumplir los bloqueos de
    inhibición para usuarios no privilegiados. Sleep() selecciona
    automáticamente la operación de sueño más adecuada soportada por la máquina.
    Las operaciones de sueño candidatas para verificar el soporte se pueden
    configurar a través de la configuración SleepOperation= en logind.conf(5).
    Las interfaces de usuario deben exponer estas llamadas como el mecanismo
    principal para apagar/reiniciar/suspender/hibernar la máquina. Los métodos
    PowerOffWithFlags(), RebootWithFlags(),
    HaltWithFlags(), SuspendWithFlags(),
    HibernateWithFlags(), HybridSleepWithFlags(),
    SuspendThenHibernateWithFlags() y Sleep() toman flags
    para permitir la extensibilidad, definidas de la siguiente manera:




#define SD_LOGIND_ROOT_CHECK_INHIBITORS          (UINT64_C(1) << 0)
#define SD_LOGIND_KEXEC_REBOOT                   (UINT64_C(1) << 1)
#define SD_LOGIND_SOFT_REBOOT                    (UINT64_C(1) << 2)
#define SD_LOGIND_SOFT_REBOOT_IF_NEXTROOT_SET_UP (UINT64_C(1) << 3)
#define SD_LOGIND_SKIP_INHIBITORS                (UINT64_C(1) << 4)




Cuando los flags son 0, estos métodos se comportan igual que las
    versiones sin flags. Desde la versión 257 de systemd, los inhibidores de tipo
    "block" se aplican a las operaciones solicitadas tanto por usuarios privilegiados
    como no privilegiados. Anteriormente, solo eran respetados por usuarios no
    privilegiados, excluyendo al usuario propietario del inhibidor. Este último
    comportamiento ahora está disponible a través del tipo de bloqueo de
    inhibidor "block-weak".
    SD_LOGIND_ROOT_CHECK_INHIBITORS (0x01) hace que los bloqueos
    "block-weak" se comporten como bloqueos "block" regulares, es decir, asegura
    que se respeten para cualquier usuario. Se puede especificar un flag
    SD_LOGIND_SKIP_INHIBITORS (0x10) para omitir los inhibidores "block" y
    "block-weak" (no tiene efecto en los inhibidores "delay"). Cuando
    SD_LOGIND_KEXEC_REBOOT (0x02) está establecido, entonces
    RebootWithFlags() realiza un reinicio kexec si el kernel kexec está
    cargado. Cuando SD_LOGIND_SOFT_REBOOT (0x04) está establecido, o
    SD_LOGIND_SOFT_REBOOT_IF_NEXTROOT_SET_UP (0x08) está establecido y se
    ha configurado un nuevo sistema de archivos raíz en "/run/nextroot/", entonces
    RebootWithFlags() realiza solo un reinicio en userspace.
    SD_LOGIND_SOFT_REBOOT_IF_NEXTROOT_SET_UP y
    SD_LOGIND_KEXEC_REBOOT se pueden combinar, con el reinicio suave teniendo
    precedencia.


SetRebootParameter() establece un parámetro para una operación de
    reinicio subsiguiente. Consulte la descripción de reboot en
    systemctl(1) y reboot(2) para más
    información.


SetRebootToFirmwareSetup(),
    SetRebootToBootLoaderMenu() y SetRebootToBootLoaderEntry()
    configuran la acción que se tomará desde el cargador de arranque después de
    un reinicio: respectivamente, entrar en modo de configuración del firmware,
    el menú del cargador de arranque o una entrada específica del cargador de
    arranque. Consulte systemctl(1) para más
    información.




Métodos


Consulte systemd-logind.service(8) para obtener la interfaz de línea de comandos correspondiente.


CanPowerOff(), CanReboot(), CanHalt(),
    CanSuspend(), CanHibernate(), CanHybridSleep(),
    CanSuspendThenHibernate(), CanSleep(),
    CanRebootParameter(), CanRebootToFirmwareSetup(),
    CanRebootToBootLoaderMenu(), y CanRebootToBootLoaderEntry()
    prueban si el sistema soporta la operación respectiva y si al usuario que llama se le permite ejecutarla. Devuelve uno de "na", "yes", "no" y "challenge". Si se devuelve "na", la operación no está disponible porque el hardware, el kernel o los controladores no la soportan. Si se devuelve "yes", la operación está soportada y el usuario puede ejecutar la operación sin autenticación adicional. Si se devuelve "no", la operación está disponible pero al usuario no se le permite ejecutarla. Si se devuelve "challenge", la operación está disponible pero solo después de la autorización.


ScheduleShutdown() programa una operación de apagado
    type en el momento usec en microsegundos desde la época UNIX.
    Alternativamente, si usec es "UINT64_MAX" y se configura una ventana de mantenimiento, systemd-logind utilizará la próxima hora de la ventana de mantenimiento en su lugar. type puede ser uno de "poweroff",
    "dry-poweroff", "reboot", "dry-reboot",
    "halt" y "dry-halt". (Las variantes "dry-" no ejecutan realmente la acción de apagado.)
    CancelScheduledShutdown() cancela un apagado programado. El parámetro de salida
    cancelled es verdadero si se programó una operación de apagado.


SetWallMessage() establece el mensaje de difusión (el mensaje que se enviará a todas las terminales y se almacenará en un registro utmp(5)) para una operación de apagado programada posterior. El parámetro wall_message
    especifica la razón del apagado (y puede estar vacío) que se incluirá en el mensaje de apagado. El parámetro enable especifica si se debe imprimir un mensaje de difusión al apagar.


Inhibit() crea un bloqueo de inhibición. Toma cuatro
    parámetros: what, who, why, y mode.
    what es uno o más de "shutdown", "sleep",
    "idle", "handle-power-key",
    "handle-suspend-key", "handle-hibernate-key",
    "handle-lid-switch", separados por dos puntos, para inhibir el apagado/reinicio, la suspensión/hibernación, la lógica automática de inactividad, o el manejo de teclas de hardware. who debe ser una cadena corta legible por humanos que identifique la aplicación que toma el bloqueo. why debe ser una cadena corta legible por humanos que identifique la razón por la que se toma el bloqueo. Finalmente, mode es "block" o "delay", que codifica si la inhibición debe considerarse obligatoria o si solo debe retrasar la operación hasta un cierto tiempo máximo, mientras que las variantes "block-weak" y
    crearán un inhibidor que se ignora automáticamente en algunas circunstancias. El método devuelve un descriptor de archivo. El bloqueo se libera en el momento en que este descriptor de archivo y todos sus duplicados se cierran. Para más información sobre la lógica de inhibición, consulte Inhibitor Locks[2].






Señales


Cada vez que cambia el estado de inhibición o la sugerencia de inactividad,
    se envían señales PropertyChanged a los clientes que se han suscrito.


La señal SecureAttentionKey() se envía cuando el usuario
    presiona Ctrl+Alt+Shift+Esc para solicitar al gestor de inicio de sesión que muestre el saludo, por ejemplo, en caso de un compositor bloqueado.


Las señales SessionNew(), SessionRemoved(),
    UserNew(), UserRemoved(), SeatNew() y
    SeatRemoved() se envían cada vez que se crea o elimina una sesión, un usuario inicia o cierra sesión, o se añade o elimina un asiento. Cada una de ellas contiene el ID del objeto más la ruta del objeto.


Las señales PrepareForShutdown(),
    PrepareForShutdownWithMetadata() y PrepareForSleep()
    se envían justo antes (con el argumento "true") o después (con el argumento "false") de que el sistema se apague para reiniciar/alimentar y suspender/hibernar, respectivamente. Esto puede ser utilizado por las aplicaciones para guardar datos en disco, liberar memoria, o realizar otras tareas que deban hacerse poco antes del apagado/suspensión, en conjunción con bloqueos de inhibición de retraso. Después de completar este trabajo, deben liberar sus bloqueos de inhibición para no retrasar más la operación. Para más información, consulte Inhibitor Locks[2]. La señal
    PrepareForShutdownWithMetadata() envía adicionalmente una lista de campos de metadatos clave/valor. Actualmente envía una cadena type que define el tipo de apagado. El tipo puede ser uno de
    "power-off", "reboot", "halt",
    "kexec" o "soft-reboot". Esta señal se envía primero, seguida por PrepareForShutdown() (por compatibilidad con versiones anteriores).






Propiedades


La mayoría de las propiedades simplemente reflejan la configuración, consulte
    logind.conf(5). Esto incluye: NAutoVTs, KillOnlyUsers,
    KillExcludeUsers, KillUserProcesses, IdleAction,
    InhibitDelayMaxUSec, InhibitorsMax, UserStopDelayUSec,
    HandlePowerKey, HandleSuspendKey, HandleHibernateKey,
    HandleLidSwitch, HandleLidSwitchExternalPower,
    HandleLidSwitchDocked, IdleActionUSec,
    HoldoffTimeoutUSec, RemoveIPC, RuntimeDirectorySize,
    RuntimeDirectoryInodesMax, InhibitorsMax y
    SessionsMax.


La propiedad IdleHint refleja el estado de la sugerencia de inactividad del
    sistema. Si el sistema está inactivo, podría entrar en suspensión o
    apagado automático dependiendo de la configuración.


IdleSinceHint y IdleSinceHintMonotonic codifican las
    marcas de tiempo del último cambio del booleano de sugerencia de inactividad, en
    marcas de tiempo de CLOCK_REALTIME y CLOCK_MONOTONIC, respectivamente, en microsegundos desde la época.


Las propiedades BlockInhibited, BlockWeakInhibited y
    DelayInhibited codifican los bloqueos activos actuales de los
    modos respectivos. Son listas separadas por dos puntos de "shutdown",
    "sleep" e "idle" (ver arriba).

    número de sesiones e inhibidores registrados actualmente.


La propiedad BootLoaderEntries contiene una lista de entradas del cargador de arranque. Esto incluye las entradas del cargador de arranque definidas en la configuración y cualquier entrada adicional del cargador reportada por el cargador de arranque. Consulte systemd-boot(7) para más información.


Las propiedades booleanas PreparingForShutdown y PreparingForSleep
    son verdaderas durante el intervalo entre las señales PrepareForShutdown() y PrepareForSleep(), respectivamente. La propiedad PreparingForShutdownWithMetadata proporciona una lista de campos de metadatos clave/valor. Actualmente enumera un booleano preparing que corresponde a la propiedad PreparingForShutdown y, si se está preparando un apagado, también contendrá una cadena type que define el tipo de apagado. El tipo puede ser uno de
    "power-off", "reboot", "halt",
    "kexec" o "soft-reboot". Tenga en cuenta que estas propiedades no envían señales PropertyChanged.


La propiedad RebootParameter muestra el valor establecido con el
    método SetRebootParameter() descrito anteriormente.


ScheduledShutdown muestra el par de valores establecido con el
    método ScheduleShutdown() descrito anteriormente.


RebootToFirmwareSetup, RebootToBootLoaderMenu y
    RebootToBootLoaderEntry son verdaderas cuando la operación post-reinicio correspondiente se seleccionó con SetRebootToFirmwareSetup(),
    SetRebootToBootLoaderMenu() o
    SetRebootToBootLoaderEntry().


Las propiedades WallMessage y EnableWallMessages
    reflejan la razón del apagado y el interruptor de habilitación del mensaje de difusión que se pueden establecer con el método SetWallMessage() descrito anteriormente.


Docked es verdadero si la máquina está conectada a una base.
    LidClosed es verdadero cuando la tapa (de un portátil) está cerrada.
    OnExternalPower es verdadero cuando la máquina está conectada a una fuente de alimentación externa.

Métodos

Terminate() y Activate() funcionan de manera similar a TerminateSession() y ActivateSession() en el objeto Manager.

Lock() y Unlock() bloquean y desbloquean la sesión. Esto se puede usar para proteger contra la intervención del usuario, por ejemplo, al hacer una copia de seguridad, o para asegurarse de que el usuario esté presente antes de continuar. Tenga en cuenta que el sistema no intentará bloquear la pantalla automáticamente.

SetIdleHint() y SetLockedHint() configuran las banderas de indicación de inactividad y bloqueo.

Kill() envía una señal al proceso líder de la sesión. Si whom se establece en "leader" (líder), se envía al proceso líder. Si se establece en "user" (usuario), se envía a todos los procesos del usuario. Si se establece en "group" (grupo), se envía al grupo de procesos del líder. Si se establece en "all" (todos), se envía a todos los procesos en la sesión.

TakeControl() y ReleaseControl() se utilizan para tomar y soltar el control de la sesión. Esto es principalmente para que un sistema administre la sesión de forma segura, por ejemplo, al iniciarla o cerrarla.

SetType(), SetClass(), SetDisplay() y SetTTY() establecen varios atributos de la sesión. Son principalmente para uso interno.

TakeDevice() otorga el control sobre un dispositivo de entrada a esta sesión y devuelve un descriptor de archivo para él, junto con un booleano que indica si el dispositivo se marcó como inactivo. ReleaseDevice() revoca el control sobre un dispositivo. PauseDeviceComplete() indica que una pausa de dispositivo ha sido completada (para dispositivos de entrada que requieren confirmación explícita).

SetBrightness() ajusta el brillo de un dispositivo de salida específico.

Señales

Las señales PauseDevice y ResumeDevice se emiten cuando un dispositivo de entrada está a punto de ser puesto en pausa o reanudado, respectivamente.

Las señales Lock y Unlock se emiten cuando el estado de bloqueo de la sesión cambia.

La propiedad Id codifica el ID de la sesión.

La propiedad User codifica el UID y la ruta del objeto del usuario asociado.

Name es el nombre de la sesión (por ejemplo, "TTY", "graphical").

Timestamp y TimestampMonotonic codifican la hora de inicio de sesión del usuario en microsegundos desde la época, en los relojes CLOCK_REALTIME y CLOCK_MONOTONIC, respectivamente.

VTNr es el número de terminal virtual, si la sesión usa una.

Seat es la ruta del objeto del asiento al que pertenece esta sesión.

TTY es la ruta del dispositivo tty asociado, si lo hay.

Display es el nombre de la pantalla X11 o la ruta del dispositivo del dispositivo de salida de la sesión, si lo hay.

Remote indica si la sesión es remota.

RemoteHost codifica el nombre del host remoto, si la sesión es remota.

RemoteUser codifica el nombre de usuario remoto, si la sesión es remota.

Service es el nombre de la unidad systemd que inició esta sesión.

Desktop es el nombre del archivo .desktop del entorno de escritorio que se está ejecutando, si lo hay.

Scope es el nombre de la unidad systemd que corresponde a esta sesión.

Leader es el PID del proceso líder de la sesión.

LeaderPIDFDId es el ID de PIDFD asociado con el proceso líder, si está disponible.

Audit es el número de auditoría asociado con el proceso líder, si se aplica.

Type es el tipo de sesión (por ejemplo, "tty", "x11", "wayland").

Class es la clase de sesión (por ejemplo, "desktop", "remote", "tty").

Active indica si la sesión está activa actualmente.

State codifica el estado de la sesión y es uno de "offline", "active", o "closing". Véase sd_session_get_state(3) para más detalles.

CanIdle indica si la sesión puede pasar a un estado inactivo. Las sesiones que no pueden ser inactivas son las sesiones gráficas o aquellas que tienen un dispositivo de entrada asignado.

CanLock indica si la sesión puede ser bloqueada. Las sesiones que no pueden ser bloqueadas son las sesiones gráficas.

LockedHint indica si la sesión está bloqueada.

Methods

Terminate(), Activate(), Lock(), Unlock() y Kill() funcionan de manera similar a las llamadas respectivas en el objeto Manager.

SetIdleHint() es llamado por el objeto de sesión para actualizar el estado inactivo de la sesión cada vez que cambia.

TakeControl() permite que un proceso tome el control de acceso exclusivo de dispositivos gestionados para esa sesión. Solo una conexión D-Bus puede ser un controlador para una sesión dada en cualquier momento. Si el argumento force está establecido (solo root), un controlador existente es expulsado y reemplazado. De lo contrario, este método falla si ya existe un controlador. Tenga en cuenta que este método está limitado a usuarios de D-Bus con el UID efectivo establecido al usuario de la sesión o root.

ReleaseControl() cede el control de una sesión dada. Cerrar la conexión D-Bus también cede implícitamente el control. Ver TakeControl() para más información. Este método también libera todos los dispositivos para los cuales el controlador solicitó la propiedad mediante TakeDevice().

SetType() permite que el tipo de la sesión se cambie dinámicamente. Solo puede ser llamado por el controlador actual de la sesión. Si TakeControl() no ha sido llamado, este método fallará. Además, el tipo de sesión se restablecerá a su valor original una vez que se ceda el control, ya sea llamando a ReleaseControl() o cerrando la conexión D-Bus. Esto debería ayudar a evitar que una sesión entre en un estado inconsistente, por ejemplo, si el controlador falla. El único argumento type es el nuevo tipo de sesión.

SetClass() permite al llamante cambiar la clase de la sesión dinámicamente. Solo puede ser llamado por el usuario propietario de la sesión. Actualmente, esta llamada solo puede usarse exclusivamente para cambiar la clase de "user-incomplete" a "user". La llamada es síncrona y solo devolverá una vez que el gestor de servicios del usuario se haya iniciado correctamente, si es necesario. El único argumento type es el nuevo tipo de sesión.

SetDisplay() permite cambiar el nombre de la pantalla de la sesión gráfica. Esto es útil si el servidor de pantalla se inicia como parte de la sesión. Solo puede ser llamado por el controlador actual de la sesión. Si TakeControl() no ha sido llamado, este método fallará. El único argumento display es el nuevo nombre de la pantalla.

SetTTY() permite cambiar el nombre del dispositivo de la sesión. Esto es útil si el dispositivo tty solo se conoce después de la autenticación. Solo puede ser llamado por el controlador actual de la sesión. Si TakeControl() no ha sido llamado, este método fallará. El único argumento tty_fd es un descriptor de archivo para el nuevo dispositivo tty.

TakeDevice() permite a un controlador de sesión obtener un descriptor de archivo para un dispositivo específico. Pase los números mayor y menor del dispositivo de caracteres y systemd-logind devolverá un descriptor de archivo para el dispositivo. Actualmente solo se admite un conjunto limitado de tipos de dispositivos (pero puede extenderse). systemd-logind silencia automáticamente el descriptor de archivo si la sesión está inactiva y lo reanuda una vez que la sesión se activa de nuevo. Esto garantiza que una sesión solo pueda acceder a los dispositivos de la sesión si la sesión está activa. Tenga en cuenta que este mecanismo de revocación/reanudación es asíncrono y puede ocurrir en cualquier momento. Esto solo funciona en dispositivos que están conectados al asiento de la sesión dada. No se requiere que un proceso tenga acceso directo al nodo del dispositivo. systemd-logind solo requiere que usted sea el controlador de sesión activo (ver TakeControl()). Tenga en cuenta también que cada dispositivo solo puede solicitarse una vez. Mientras no lo libere, las llamadas posteriores a TakeDevice() fallarán.

ReleaseDevice() libera un dispositivo nuevamente (ver TakeDevice()). Esto también se hace implícitamente por ReleaseControl() o al cerrar la conexión D-Bus.

PauseDeviceComplete() permite a un controlador de sesión pausar síncronamente un dispositivo después de recibir una señal PauseDevice("pause"). Las señales forzadas (o después de un tiempo de espera interno) se completan automáticamente de forma asíncrona por systemd-logind.

SetLockedHint() puede usarse para establecer la "pista de bloqueo" a locked, es decir, información sobre si la sesión está bloqueada. Esto está destinado a ser utilizado por el entorno de escritorio para informar a systemd-logind cuándo la sesión está bloqueada y desbloqueada.

SetBrightness() puede usarse para establecer el brillo de la pantalla. Esto está destinado a ser utilizado por el entorno de escritorio y permite que programas no privilegiados accedan a la configuración de hardware de manera controlada. El parámetro subsystem especifica un subsistema del kernel, ya sea "backlight" o "leds". El parámetro name especifica un nombre de dispositivo bajo el subsistema especificado. El parámetro brightness especifica el brillo. El rango está definido por controladores individuales, ver /sys/class/subsystem/name/max_brightness.

Señales

El controlador de sesión activo recibe exclusivamente eventos PauseDevice() y ResumeDevice() para cualquier dispositivo que haya solicitado a través de TakeDevice(). Notifican al controlador cada vez que un dispositivo se pausa o se reanuda. Un dispositivo nunca se reanuda si su sesión está inactiva. Tenga en cuenta también que las señales PauseDevice() se envían antes de la señal PropertyChanged para el estado Active. Lo contrario es cierto para ResumeDevice(). Un dispositivo puede permanecer pausado por razones desconocidas incluso si la sesión está activa.

Una señal PauseDevice() lleva los números mayor y menor y una cadena que describe el tipo como argumentos. force significa que el dispositivo ya fue pausado por systemd-logind y la señal es solo una notificación asíncrona. pause significa que systemd-logind le otorga una cantidad limitada de tiempo para pausar el dispositivo. Debe responder a esto a través de PauseDeviceComplete(). Este mecanismo de pausa síncrona se utiliza para la retrocompatibilidad con las VT y systemd-logind es libre de no utilizarlo. También es libre de enviar un PauseDevice() forzado si no responde a tiempo (o por cualquier otra razón). gone significa que el dispositivo fue desconectado del sistema y ya no recibirá ninguna notificación sobre él. No es necesario llamar a ReleaseDevice(). Puede llamar a TakeDevice() de nuevo si a una nueva combinación mayor+menor se le asigna un nuevo dispositivo.

ResumeDevice() se envía cada vez que una sesión está activa y un dispositivo se reanuda. Lleva los números mayor/menor como argumentos y proporciona un nuevo descriptor de archivo abierto. Debe cambiar al nuevo descriptor y cerrar el antiguo. No se garantiza que tengan el mismo descriptor de archivo subyacente abierto en el kernel (excepto para un conjunto limitado de tipos de dispositivos).

Cada vez que Active o el estado inactivo cambian, se envían señales PropertyChanged a los clientes que se han suscrito.

Lock()/Unlock() se envía cuando se le pide a la sesión que se bloquee/desbloquee la pantalla. Un gestor de sesiones de la sesión debe escuchar esta señal y actuar en consecuencia. Esta señal se emite como resultado de los métodos Lock() y Unlock(), respectivamente.

Las señales solo se emiten en objetos que hacen referencia a un ID de sesión específico, no en los objetos de conveniencia "/org/freedesktop/login1/session/self" o "/org/freedesktop/login1/session/auto", ya que solo se pueden desreferenciar en relación con el llamador del método.

Propiedades

Id codifica el ID de la sesión.

User codifica el ID de usuario del usuario al que pertenece esta sesión. Esta es una estructura que consta del UID de Unix y la ruta del objeto.

Name codifica el nombre de usuario.

Timestamp y TimestampMonotonic codifican los microsegundos desde la época en que se creó la sesión, en CLOCK_REALTIME o CLOCK_MONOTONIC, respectivamente.

VTNr codifica el número de terminal virtual de la sesión si lo hay, de lo contrario 0.

Seat codifica el asiento al que pertenece esta sesión si lo hay. Esta es una estructura que consta del ID y la ruta del objeto del asiento.

TTY codifica la ruta TTY del kernel de la sesión si se trata de un inicio de sesión de texto. Si no, es una cadena vacía.

Display codifica el nombre de pantalla X11 si se trata de un inicio de sesión gráfico. Si no, es una cadena vacía.

Remote codifica si la sesión es local o remota.

RemoteHost y RemoteUser codifican el host remoto y el usuario si se trata de una sesión remota, o una cadena vacía de lo contrario.

Service codifica el nombre del servicio PAM que registró la sesión.

Desktop describe el entorno de escritorio que se ejecuta en la sesión (si se conoce).

Scope contiene el nombre de la unidad de ámbito de systemd de esta sesión.

Leader codifica el PID del proceso que registró la sesión.

LeaderPIDFDId codifica el ID inodo de pidfd de Linux del proceso que registró la sesión.

Audit codifica el ID de sesión de auditoría del kernel de la sesión si la auditoría está disponible.

Type codifica el tipo de sesión. Es uno de "unspecified" (para sesiones PAM de cron y similares), "tty" (para inicios de sesión de texto), "web" (para inicios de sesión basados en web) o "x11"/"mir"/"wayland" (para inicios de sesión gráficos).

Class codifica la clase de sesión. Es uno de "user" (para sesiones de usuario normales), "greeter" (para pseudo-sesiones de gestor de pantalla) o "lock-screen" (para pantallas de bloqueo de pantalla).

Active es un booleano que es verdadero si la sesión está activa, es decir, actualmente en primer plano. Este campo es semi-redundante debido a State.

State codifica el estado de la sesión y uno de "online", "active" o "closing". Ver sd_session_get_state(3) para más información sobre los estados.

IdleHint, IdleSinceHint y IdleSinceHintMonotonic encapsulan el estado de la pista de inactividad de esta sesión, de manera similar a cómo las propiedades respectivas en el objeto manager lo hacen para todo el sistema.

LockedHint muestra el estado de la pista de bloqueo de esta sesión, tal como lo establece el método SetLockedHint() descrito anteriormente.

CanIdle indica si la sesión admite el concepto de pista de inactividad. De manera similar, CanLock indica si la sesión admite el concepto de bloqueo de pantalla.
