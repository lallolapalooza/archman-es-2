odbx_init(3)

Paquete: opendbx

Licencias: LGPL

odbx_init(3) OpenDBX odbx_init(3)

NOMBRE

odbx_init - Asigna estructuras de datos por conexión

SINOPSIS

#include <opendbx/api.h>


int odbx_init
(odbx_t** handle, const char* backend, const char* host, const char* port);

DESCRIPCIÓN

odbx_init() asigna e inicializa un objeto opaco requerido para todas las operaciones posteriores dentro de la biblioteca OpenDBX, que se utiliza para identificar la conexión y mantener información por conexión. Dependiendo del backend, puede abrir una conexión al servidor de base de datos, pero a menudo esto no se hace hasta que se realiza la autenticación a través de odbx_bind().

El puntero del objeto de conexión recién asignado se almacena en handle si odbx_init() se completa con éxito. De lo contrario, el valor de la variable handle no estará definido y no debe usarse como entrada para otras funciones de la biblioteca. El objeto de conexión devuelto debe ser liberado por odbx_finish() para evitar fugas de memoria si ya no será utilizado por la aplicación.

La biblioteca OpenDBX proporciona acceso a varias implementaciones de bases de datos diferentes a través de una única interfaz y, por lo tanto, necesita saber cuál de los módulos de backend disponibles debe utilizar para las operaciones. El parámetro backend se utilizará para buscar el módulo solicitado. Debe ser una cadena ASCII terminada en nulo con todos los caracteres en minúsculas. Actualmente, estos módulos de backend están disponibles:

•
firebird (Firebird/Interbase)
•
mssql (MS SQL Server vía FreeTDS)
•
mysql (MySQL)
•
oracle (Oracle 8i/9i/10g)
•
pgsql (PostgreSQL)
•
sqlite (SQLite v2)
•
sqlite3 (SQLite v3)
•
sybase (Sybase ASE)

Conectarse a un servidor de base de datos requiere al menos un identificador para saber dónde se encuentra la base de datos. Existen varios tipos de identificadores, como nombres de host, direcciones IP, tuberías con nombre, etc., que podrían usarse. Uno de ellos puede proporcionarse a través del parámetro host y depende de la biblioteca nativa de la base de datos lo que aceptará. La mayoría de las bibliotecas nativas aceptan al menos nombres de host y direcciones IP, y también usan el puerto proporcionado en este caso. Los métodos disponibles para host son:

cadena de nombre de host
soportado por los backends Firebird/Interbase, MySQL, Oracle y PostgreSQL
cadena de dirección IP
soportado por los backends Firebird/Interbase, MySQL, Oracle y PostgreSQL
ruta absoluta al socket de dominio Unix
actualmente soportado solo por el backend PostgreSQL
ruta de directorio (relativa) con barra inclinada/barra invertida al final
requerido por los backends SQLite y SQLite3
nombre de sección en el archivo de configuración
requerido por los backends MS SQL Server y Sybase ASE

Dependiendo de la biblioteca nativa de la base de datos, también es posible utilizar valores predeterminados específicos de la base de datos para los parámetros host y port proporcionando cadenas vacías terminadas en nulo o un valor NULL.

VALOR DE RETORNO

odbx_init() devuelve ODBX_ERR_SUCCESS, o un código de error cuyo valor es menor que cero si alguna de las operaciones no pudo completarse con éxito. Los códigos de error posibles se enumeran en la sección de errores y pueden ser alimentados a odbx_error() y odbx_error_type() para obtener más detalles.

ERRORES

-ODBX_ERR_BACKEND
El módulo backend devolvió un error porque no pudo configurar las estructuras necesarias
-ODBX_ERR_PARAM
handle es NULL y el objeto de conexión asignado no se puede almacenar
-ODBX_ERR_NOMEM
Falló la asignación de nueva memoria para el objeto de conexión
-ODBX_ERR_SIZE
La longitud de una cadena excedió el tamaño del buffer disponible
-ODBX_ERR_NOTEXIST
No se encontró un módulo backend con este nombre. O el módulo no está instalado, el nombre dado era incorrecto o no estaba en la caja de caracteres correcta
-ODBX_ERR_NOOP
El módulo backend no proporciona la función requerida
