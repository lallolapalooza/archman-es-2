NOMBRE

opam-repository - Gestiona repositorios de opam.

SINOPSIS

opam repository [--kind=TIPO] [--rank=RANGO] [--short] [OPCIÓN]… [COMANDO] [ARG]…

DESCRIPCIÓN

Este comando se utiliza para gestionar repositorios de paquetes. Los repositorios pueden registrarse a través de los subcomandos add, remove y set-url, y se actualizan desde sus URLs utilizando opam update. Sus nombres son globales para todos los switches, y cada switch tiene su propia selección de repositorios de donde obtiene las definiciones de paquetes.

Los comandos principales add, remove y set-repos actúan solo sobre el switch actual, a menos que se especifique lo contrario utilizando las opciones explicadas en OPCIONES DE ESPECIFICACIÓN DE ALCANCE.

Sin un subcomando, o con el subcomando list, lista los repositorios seleccionados, o todos los repositorios configurados con --all.

COMANDOS

Sin argumento, por defecto es list.

add NOMBRE [DIRECCIÓN] [QUORUM] [HUEL;AS]
Añade bajo NOMBRE el repositorio en la dirección DIRECCIÓN a la lista de repositorios configurados, si no está ya registrado, y establece este repositorio para su uso en el switch actual (o el alcance especificado). DIRECCIÓN es obligatorio si el nombre del repositorio no está ya registrado, y en caso contrario es un error si es diferente de la dirección registrada. El quórum es un entero positivo que determina el umbral de validación para repositorios firmados, con huellas digitales como anclas de confianza para dicha validación.
 
Nota: Por defecto, el repositorio solo se añade al switch actual. Para añadir un repositorio a otros switches, necesitas usar las opciones --all o --set-default (ver abajo). Si quieres habilitar un repositorio solo para instalar sus switches, podrías estar buscando opam switch create --repositories=REPOS.
remove NOMBRE...
Elimina los repositorios dados de los alcances seleccionados (el alcance por defecto es el switch actual, ver --this-switch). Los repositorios se eliminan completamente con --all-switches. Si se elimina el último repositorio en el alcance del switch actual, entonces la selección de repositorios se restaura a la selección por defecto (opam list --set-default).
set-repos NOMBRE...
Selecciona explícitamente la lista de repositorios para buscar definiciones de paquetes, en el orden de prioridad especificado (anulando la selección y rangos previos), de acuerdo con el alcance especificado.
set-url NOMBRE DIRECCIÓN [QUORUM] [HUEL;AS]
Actualiza la URL y las anclas de confianza asociadas con un nombre de repositorio dado. Nota que si no especificas [QUORUM] y [HUEL;AS], se borrarán todos los ajustes previos.
list
Lista los repositorios actualmente seleccionados en orden de prioridad desde el rango 1. Con --all, lista todos los repositorios configurados y los switches donde están activos.
priority NOMBRE RANGO
Sinónimo de add NOMBRE --rank RANGO

OPCIONES DE ESPECIFICACIÓN DE ALCANCE

Estas banderas permiten elegir qué selecciones se cambian con add, remove, set-repos. Si no se especifica ninguna bandera de esta sección, las selecciones actualizadas por defecto son las del switch actual. Se pueden seleccionar múltiples alcances, p. ej., --this-switch --set-default.

-a, --all-switches
Actúa sobre las selecciones de todos los switches configurados
--dont-select
No actualizar ninguna selección
--on-switches=SWITCHES
Actúa sobre las selecciones de la lista de switches dada
--set-default
Actúa sobre la selección de repositorios por defecto que se utiliza para los switches recién creados
--this-switch
Actúa sobre las selecciones para el switch actual (este es el valor predeterminado)

OPCIONES

-k TIPO, --kind=TIPO
Especifica el tipo de repositorio a utilizar (uno de http, local, git, darcs o hg).
--rank=RANGO (ausente=1)
Establece el rango del repositorio en la lista de repositorios configurados. Las definiciones de paquetes se buscan en los repositorios en orden de rango creciente, por lo tanto, 1 es la prioridad más alta. Se pueden usar enteros negativos para seleccionar desde la prioridad más baja, -1 es el último. set-repos de lo contrario se puede usar para establecer explícitamente la lista de repositorios a la vez.
-s, --short
Salida de listas de nombres sin formato, una por línea, omitiendo cualquier detalle.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Nota que no todos los solucionadores externos pueden soportar esta opción (versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Previsto para cualquier uso persistente de opam (scripts, posts de blogs, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. La bandera no estaba disponible en opam 2.0, así que para seleccionar la interfaz de línea de comandos 2.0, establece la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de always, never o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de ask, no, yes o unsafe-yes. Se puede especificar más de una vez. Si --yes o --no también se dan, se toma en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL`.
--criteria=CRITERIOS
Especifica las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para detalles sobre el lenguaje soportado, y los solucionadores externos disponibles, ver http://opam.ocaml.org/doc/External_solvers.html. Una guía general para usar preferencias de solucionadores se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBRE_ARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en NOMBRE_ARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Como --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está establecida (es decir, si estás usando una versión de desarrollo), y sale.
--help[=FMT] (por defecto=auto)
Muestra esta ayuda en el formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable de entorno TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora los pines extra requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBRE_ARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por ordenador. Si el nombre de archivo contiene el carácter `%`, será reemplazado por un índice que no sobrescribe un archivo existente. Similar

NAME

opam-repository - opam repository files

SYNOPSIS

A repository is a collection of opam packages and their definitions. This page describes the format of files composing a repository.

DESCRIPTION

An opam repository is a collection of directories, each containing metadata files describing opam packages. The root of a repository is identified by a (dir)/opam-version file, which contains the repository format version.

The structure is as follows:

repository_root/

(dir)/opam-version
Mandatory. Contains the repository format version (e.g. ‘2.0’).
(dir)/.opam-repositories
Optional. Contains a list of available repositories, used for displaying information about them.
(dir)/packages/
Directory containing definitions for all packages. This directory can contain sub-directories for organization.
(dir)/packages//package.opam
The definition file for package. It's a file in opam(5) format.
(dir)/types/
Optional. Contains custom type definitions for use in package files.
(dir)/types/type.opam
A type definition file.
(dir)/templates/
Optional. Contains files for templating package definitions.
(dir)/descr/
Optional. Contains description files for packages.
(dir)/descr/package.txt
The description of package.
(dir)/maintainers/
Optional. Lists package maintainers.
(dir)/maintainers/package.txt
A list of e-mail addresses for the maintainers of package.
(dir)/comp/
Optional. Contains files for custom compilation rules.
(dir)/comp/package.opam
Custom compilation rules for package.
(dir)/plugins/
Optional. Contains opam plugins.
(dir)/plugins/plugin.ml
A plugin file.

The structure of the repository can be customized by using subdirectories within packages/, descr/, etc. For example, you could have packages/graphics/foo.opam, packages/games/bar.opam.

The opam-version file indicates the repository format version. This allows opam to support different repository layouts over time. Currently, the format version is ‘2.0’.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified more than once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
