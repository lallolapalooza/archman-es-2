OGRMERGE(1) GDAL OGRMERGE(1)

NOMBRE

ogrmerge - Fusionar varios conjuntos de datos vectoriales en uno solo.

SINOPSIS

ogrmerge [--help] [--help-general]
            -o <nombre_ds_salida> <nombre_ds_entrada> [<nombre_ds_entrada>]...
            [-f formato] [-single] [-nln <plantilla_nombre_capa>]
            [-update | -overwrite_ds] [-append | -overwrite_layer]
            [-src_geom_type <tipo_geom_fuente>[,<tipo_geom_fuente>]...]
            [-dsco <NOMBRE>=<VALOR>]... [-lco <NOMBRE>=<VALOR>]...
            [-s_srs <def_srs>] [-t_srs <def_srs> | -a_srs <def_srs>]
            [-progress] [-skipfailures] [--help-general]

Opciones específicas de la opción -single:

[-field_strategy FirstLayer|Union|Intersection]
[-src_layer_field_name <nombre>]
[-src_layer_field_content <plantilla_nombre_capa>]

DESCRIPCIÓN

ogrmerge toma como entrada varios conjuntos de datos vectoriales, cada uno de ellos con una o varias capas vectoriales, y los copia a un conjunto de datos de destino.

Hay esencialmente dos modos:

  • el modo predeterminado, donde cada capa vectorial de entrada se copia como una capa separada en el conjunto de datos de destino
  • otro modo, activado con el modificador -single, donde el contenido de todas las capas vectoriales de entrada se anexa en una única capa de destino. Esto asume que el esquema de esas capas vectoriales es más o menos el mismo.

Internamente esto genera un archivo VRT -- OGR Virtual Format, y si el formato de salida no es VRT, la traducción final se realiza con ogr2ogr o gdal.VectorTranslate(). Por lo tanto, para usos avanzados, se puede generar la salida a VRT, editarla manualmente y luego usar ogr2ogr.

NOTA:

ogrmerge es una utilidad de Python y solo está disponible si las vinculaciones de Python de GDAL están disponibles.

NOTA:

A partir de GDAL 3.11, hay disponible un programa más nuevo llamado gdal vector concat.
--help
Mostrar este mensaje de ayuda y salir
--help-general
Muestra un breve mensaje de uso para las opciones genéricas de línea de comandos de GDAL y sale.
-o <nombre_ds_salida>
Nombre del conjunto de datos de salida. Requerido.
<nombre_ds_entrada>
Uno o varios conjuntos de datos vectoriales de entrada. Requerido
-f <formato>
Seleccionar el formato de salida. Si no se especifica, el formato se deduce de la extensión (anteriormente era ESRI Shapefile). Utilice el nombre corto del formato.
-single
Si se especifica, todas las capas vectoriales de entrada se fusionarán en una sola.
-nln <plantilla_nombre_capa>
Nombre de la capa vectorial de salida (en modo único, y el valor predeterminado es "merged"), o plantilla para nombrar las capas vectoriales de salida en modo predeterminado (el valor predeterminado es {AUTO_NAME}). La plantilla puede ser una cadena con las siguientes variables que serán sustituidas por un valor calculado a partir de la capa de entrada que se está procesando:
  • {AUTO_NAME}: equivalente a {DS_BASENAME}_{LAYER_NAME} si ambos valores son diferentes, o {LAYER_NAME} cuando son idénticos (caso de shapefile).
  • {DS_NAME}: nombre del conjunto de datos de origen
  • {DS_BASENAME}: nombre base del conjunto de datos de origen
  • {DS_INDEX}: índice del conjunto de datos de origen
  • {LAYER_NAME}: nombre de la capa de origen
  • {LAYER_INDEX}: índice de la capa de origen
-update
Abrir un conjunto de datos existente en modo de actualización.
-overwrite_ds
Sobrescribir el conjunto de datos existente si ya existe (para conjuntos de datos basados en archivos).
-append
Abrir un conjunto de datos existente en modo de actualización y, si las capas de salida ya existen, anexar el contenido de las capas de entrada a ellas.
-overwrite_layer
Abrir un conjunto de datos existente en modo de actualización y, si las capas de salida ya existen, reemplazar su contenido con el de la capa de entrada.
-src_geom_type <tipo_geom_fuente>[,<tipo_geom_fuente>]...
Solo tener en cuenta las capas de entrada cuyo tipo de geometría coincida con el (los) tipo(s) especificado(s). Los valores válidos para tipo_geom_fuente son GEOMETRY, POINT, LINESTRING, POLYGON, MULTIPOINT, MULTILINESTRING, MULTIPOLYGON, GEOMETRYCOLLECTION, CIRCULARSTRING, CURVEPOLYGON, MULTICURVE, MULTISURFACE, CURVE, SURFACE, TRIANGLE, POLYHEDRALSURFACE y TIN.
-dsco <NOMBRE>=<VALOR>
Opción de creación de conjunto de datos (específica del formato)
-lco <NOMBRE>=<VALOR>
Opción de creación de capa (específica del formato)
-a_srs <def_srs>
Asignar un SRS de salida
-t_srs <def_srs>
Reproyectar/transformar a este SRS en la salida
-s_srs <def_srs>
Anular el SRS de origen
-progress
Mostrar el progreso en la terminal. Solo funciona si las capas de entrada tienen la capacidad de "conteo rápido de características".
-skipfailures
Continuar después de un fallo, omitiendo la característica fallida.
-field_strategy FirstLayer|Union|Intersection
Solo se usa con -single. Determina cómo se construye el esquema de la capa de destino a partir de los esquemas de las capas de entrada. Puede ser FirstLayer para usar los campos de la primera capa encontrada, Union para usar un superconjunto de todos los campos de todas las capas de origen, o Intersection para usar un subconjunto de todos los campos comunes de todas las capas de origen. El valor predeterminado es Union.
-src_layer_field_name <nombre>
Solo se usa con -single. Si se especifica, el esquema de la capa de destino se ampliará con un nuevo campo 'nombre', cuyo contenido se determina mediante -src_layer_field_content. Ver Ejemplo 3.
-src_layer_field_content <plantilla_nombre_capa>
Solo se usa con -single. Si se especifica, el esquema de la capa de destino se ampliará con un nuevo campo (cuyo nombre se da en -src_layer_field_name, o 'source_ds_lyr' en caso contrario), cuyo contenido se determina mediante plantilla_nombre_capa. La sintaxis de plantilla_nombre_capa es la misma que para -nln.

EJEMPLOS

Ejemplo 1: Creación de un VRT con una capa por cada shapefile de entrada

ogrmerge -o output.vrt file1.shp file2.shp file3.shp

Esto creará un archivo VRT llamado output.vrt. Contendrá tres capas, llamadas file1, file2 y file3 (siendo el nombre base de los archivos de origen los nombres de las capas). El nombre de las capas de salida se puede personalizar con la opción -nln.

Ejemplo 2: Fusionar varios shapefiles en un único shapefile

ogrmerge -single -o merged.shp file1.shp file2.shp file3.shp

Esto creará un archivo shapefile llamado merged.shp. Todas las características de file1.shp, file2.shp y file3.shp se copiarán en la única capa de merged.shp.

Ejemplo 3: Fusionar varios shapefiles en un único shapefile, añadiendo un campo con el nombre de la fuente

ogrmerge -single \
    -src_layer_field_name src_name \
    -src_layer_field_content {LAYER_NAME} \
    -o merged.shp file1.shp file2.shp file3.shp

Esto creará un archivo shapefile llamado merged.shp. Todas las características de file1.shp, file2.shp y file3.shp se copiarán en la única capa de merged.shp. Además, se añadirá un campo llamado src_name a la capa de destino. Para las características que provienen de file1.shp, el valor de src_name será 'file1'. Para las características que provienen de file2.shp, será 'file2', y así sucesivamente.

Ejemplo 4: Fusionar varios shapefiles en un único shapefile, pero solo los campos comunes

ogrmerge -single -field_strategy Intersection -o merged.shp file1.shp file2.shp file3.shp

Esto creará un archivo shapefile llamado merged.shp. Todas las características de file1.shp, file2.shp y file3.shp se copiarán en la única capa de merged.shp. Sin embargo, solo se incluirán los campos que sean comunes a todas las capas de entrada.

Ejemplo 5: Fusionar un conjunto de datos GeoPackage en uno existente

ogrmerge -update -append -o existing.gpkg new_data.gpkg

Esto abrirá existing.gpkg en modo de actualización y anexará todas las capas de new_data.gpkg a las capas correspondientes en existing.gpkg. Si alguna capa de new_data.gpkg no existe en existing.gpkg, se creará.

Ejemplo 6: Fusionar un conjunto de datos GeoPackage en uno existente, sobrescribiendo capas existentes

ogrmerge -update -overwrite_layer -o existing.gpkg new_data.gpkg

Esto abrirá existing.gpkg en modo de actualización y reemplazará el contenido de las capas correspondientes de new_data.gpkg en existing.gpkg. Si alguna capa de new_data.gpkg no existe en existing.gpkg, se creará.

Ejemplo 7: Fusionar varios shapefiles en un único shapefile, pero solo las capas de tipo Polygon

ogrmerge -single -src_geom_type POLYGON -o merged.shp file1.shp file2.shp file3.shp

Esto creará un archivo shapefile llamado merged.shp. Solo se incluirán en la capa fusionada las características de tipo POLYGON de los shapefiles de entrada.

ogrmerge(1) man page

NAME

ogrmerge - Merge multiple vector datasets into a single dataset.

SYNOPSIS

ogrmerge [options] -o output_dataset input_dataset(s)

DESCRIPTION

The ogrmerge utility merges multiple vector datasets into a single vector dataset. The input datasets can be of various formats. The output dataset format is determined by the output filename extension.

By default, if multiple input files are specified, the operation will create a single layer in the output file. The layers of the input files will be appended to this single layer. This requires that the layers have compatible schema.

If the -single option is used, the behavior is similar to the default, but the input files are treated as single layers, even if they contain multiple layers.

If the -tiled option is used, the operation will create a layer for each input file. This is useful when the input files represent different entities or have different schemas.

The -src_layer_field_name option can be used to add a field to the output layer that indicates the source layer or file of each feature. This is useful when merging multiple datasets into a single layer.

The -src_filename_field_name option can be used to add a field to the output layer that indicates the source filename of each feature.

EXAMPLES

Example 1: Creating a VRT with a layer for each input shapefile

ogrmerge -f VRT -o merged.vrt *.shp

Example 2: Creating a GeoPackage with a layer for each input shapefile

ogrmerge -f GPKG -o merged.gpkg *.shp

Example 3: Adding a field to indicate the source layer

Concatenate the content of france.shp and germany.shp in merged.shp, and add a 'country' field to each feature whose value is 'france' or 'germany' depending where it comes from:

ogrmerge -single -o merged.shp france.shp germany.shp -src_layer_field_name country
