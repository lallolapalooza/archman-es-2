NOMBRE

openssl-rsautl - Comando RSA

SINOPSIS

openssl rsautl [-help] [-in archivo] [-passin arg] [-rev] [-out archivo] [-inkey nombrearchivo|uri] [-keyform DER|PEM|P12|ENGINE] [-pubin] [-certin] [-sign] [-verify] [-encrypt] [-decrypt] [-pkcs] [-x931] [-oaep] [-raw] [-hexdump] [-asn1parse] [-engine id] [-rand archivos] [-writerand archivo] [-provider nombre] [-provider-path ruta] [-provparam [nombre:]clave=valor] [-propquery propq]

DESCRIPCIÓN

Este comando ha sido obsoleto. Se debe usar el comando openssl-pkeyutl(1) en su lugar.

Este comando puede ser utilizado para firmar, verificar, cifrar y descifrar datos usando el algoritmo RSA.

OPCIONES

-help
Imprime un mensaje de uso.
-in nombrearchivo
Este especifica el nombre del archivo de entrada desde el cual leer los datos o la entrada estándar si esta opción no se especifica.
-passin arg
La contraseña utilizada en el archivo de salida. Ver openssl-passphrase-options(1).
-rev
Invierte el orden de la entrada.
-out nombrearchivo
Especifica el nombre del archivo de salida al que escribir o la salida estándar por defecto.
-inkey nombrearchivo|uri
La clave de entrada, por defecto debería ser una clave privada RSA.
-keyform DER|PEM|P12|ENGINE
El formato de la clave; no especificado por defecto. Ver openssl-format-options(1) para detalles.
-pubin
Por defecto se lee una clave privada del archivo de entrada. Con esta opción se lee una clave pública en su lugar. Si la entrada no contiene una clave pública pero sí una clave privada, se utiliza su parte pública.
-certin
La entrada es un certificado que contiene una clave pública RSA.
-sign
Firma los datos de entrada y produce el resultado firmado. Esto requiere una clave privada RSA.
-verify
Verifica los datos de entrada y produce los datos recuperados.
-encrypt
Cifra los datos de entrada usando una clave pública RSA.
-decrypt
Descifra los datos de entrada usando una clave privada RSA.
-pkcs, -oaep, -x931, -raw
El relleno a usar: PKCS#1 v1.5 (el predeterminado), PKCS#1 OAEP, ANSI X9.31 o sin relleno, respectivamente. Para firmas, solo se pueden usar -pkcs y -raw.

Nota: debido a la protección contra ataques de Bleichenbacher, el descifrado en modo PKCS#1 v1.5 no devolverá errores en caso de que la comprobación del relleno falle. Use -raw e inspeccione el valor devuelto manualmente para verificar si el relleno es correcto.

-hexdump
Muestra los datos de salida en formato hexadecimal.
-asn1parse
Analiza los datos de salida ASN.1, esto es útil cuando se combina con la opción -verify.
-engine id
Ver "Opciones de Motor" en openssl(1). Esta opción está obsoleta.
-rand archivos, -writerand archivo
Ver "Opciones de Estado Aleatorio" en openssl(1) para detalles.
-provider nombre
-provider-path ruta
-provparam [nombre:]clave=valor
-propquery propq
Ver "Opciones de Proveedor" en openssl(1), provider(7), y property(7).

NOTAS

Dado que este comando utiliza el algoritmo RSA directamente, solo se puede usar para firmar o verificar pequeñas piezas de datos.

EJEMPLOS

Ejemplos equivalentes a estos se pueden encontrar en la documentación del comando no obsoleto openssl-pkeyutl(1).

Firmar algunos datos usando una clave privada:

openssl rsautl -sign -in archivo -inkey clave.pem -out firma

Recuperar los datos firmados

openssl rsautl -verify -in firma -inkey clave.pem

Examinar los datos firmados en bruto:

openssl rsautl -verify -in firma -inkey clave.pem -raw -hexdump
0000 - 00 01 ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0010 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0020 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0030 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0040 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0050 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0060 - ff ff ff ff ff ff ff ff-ff ff ff ff ff ff ff ff   ................
0070 - ff ff ff ff 00 68 65 6c-6c 6f 20 77 6f 72 6c 64   .....hello world

El formato del bloque PKCS#1 es evidente en esto. Si se hubiera hecho usando cifrado y descifrado, el bloque habría sido del tipo 2 (el segundo byte) y se habrían visto datos de relleno aleatorios en lugar de los bytes 0xff.

Es posible analizar la firma de certificados usando este comando en conjunción con openssl-asn1parse(1). Considere el ejemplo autofirmado en certs/pca-cert.pem. Ejecutar openssl-asn1parse(1) de la siguiente manera produce:

openssl asn1parse -in pca-cert.pem
   0:d=0  hl=4 l= 742 cons: SEQUENCE
   4:d=1  hl=4 l= 591 cons:  SEQUENCE
   8:d=2  hl=2 l=   3 cons:   cont [ 0 ]
  10:d=3  hl=2 l=   1 prim:    INTEGER           :02
  13:d=2  hl=2 l=   1 prim:   INTEGER           :00
  16:d=2  hl=2 l=  13 cons:   SEQUENCE
  18:d=3  hl=2 l=   9 prim:    OBJECT            :md5WithRSAEncryption
  29:d=3  hl=2 l=   0 prim:    NULL
  31:d=2  hl=2 l=  92 cons:   SEQUENCE
  33:d=3  hl=2 l=  11 cons:    SET
  35:d=4  hl=2 l=   9 cons:     SEQUENCE
  37:d=5  hl=2 l=   3 prim:      OBJECT            :countryName
  42:d=5  hl=2 l=   2 prim:      PRINTABLESTRING   :AU
 ....
 599:d=1  hl=2 l=  13 cons:  SEQUENCE
 601:d=2  hl=2 l=   9 prim:   OBJECT            :md5WithRSAEncryption
 612:d=2  hl=2 l=   0 prim:   NULL
 614:d=1  hl=3 l= 129 prim:  BIT STRING

El BIT STRING final contiene la firma real. Se puede extraer con:

openssl asn1parse -in pca-cert.pem -out sig -noout -strparse 614

La clave pública del certificado se puede extraer con:

openssl x509 -in test/testx509.pem -pubkey -noout >pubkey.pem

La firma se puede analizar con:

openssl rsautl -in sig -verify -asn1parse -inkey pubkey.pem -pubin
   0:d=0  hl=2 l=  32 cons: SEQUENCE
   2:d=1  hl=2 l=  12 cons:  SEQUENCE
   4:d=2  hl=2 l=   8 prim:   OBJECT            :md5
  14:d=2  hl=2 l=   0 prim:   NULL
  16:d=1  hl=2 l=  16 prim:  OCTET STRING
     0000 - f3 46 9e aa 1a 4a 73 c9-37 ea 93 00 48 25 08 b5   .F...Js.7...H%..

Esta es la versión analizada de una estructura ASN1 DigestInfo. Se puede ver que el digest utilizado fue md5. La parte real del certificado que fue firmada se puede extraer con:

openssl asn1parse -in pca-cert.pem -out tbs -noout -strparse 4

y su digest calculado con:

openssl md5 -c tbs
MD5(tbs)= f3:46:9e:aa:1a:4a:73:c9:37:ea:93:00:48:25:08:b5

NOTAS

El comando rsautl se usa para realizar operaciones con claves RSA y, por lo tanto, puede ser usado para probar la integridad de los datos firmados digitalmente. La comprobación de la firma es una verificación de que la operación de descifrado usando la clave pública produce el mismo valor hash que se calculó a partir de los datos originales. Esto se puede ver que concuerda con el valor recuperado anteriormente.
