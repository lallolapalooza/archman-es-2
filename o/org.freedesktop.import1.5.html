NOMBRE

org.freedesktop.import1 - La interfaz D-Bus de systemd-importd

INTRODUCCIÓN

systemd-importd.service(8) es un servicio del sistema que puede utilizarse para importar, exportar y descargar imágenes de disco. Estas imágenes pueden ser utilizadas por herramientas como systemd-nspawn(1) para ejecutar contenedores locales. El servicio se utiliza como backend para los comandos importctl pull-raw, importctl pull-tar y comandos relacionados. Esta página describe la interfaz D-Bus.

Tenga en cuenta que systemd-importd.service(8) es principalmente un pequeño servicio complementario para systemd-machined.service(8). Por lo tanto, muchas operaciones para manipular imágenes de contenedores y VM locales están disponibles a través de la API D-Bus de systemd-machined, c.f. org.freedesktop.machine1(5).

EL OBJETO MANAGER

El servicio expone las siguientes interfaces en el objeto Manager en el bus:

node /org/freedesktop/import1 {
  interface org.freedesktop.import1.Manager {
    methods:
      ImportTar(in  h fd,
                in  s local_name,
                in  b force,
                in  b read_only,
                out u transfer_id,
                out o transfer_path);
      ImportTarEx(in  h fd,
                  in  s local_name,
                  in  s class,
                  in  t flags,
                  out u transfer_id,
                  out o transfer_path);
      ImportRaw(in  h fd,
                in  s local_name,
                in  b force,
                in  b read_only,
                out u transfer_id,
                out o transfer_path);
      ImportRawEx(in  h fd,
                  in  s local_name,
                  in  s class,
                  in  t flags,
                  out u transfer_id,
                  out o transfer_path);
      ImportFileSystem(in  h fd,
                       in  s local_name,
                       in  b force,
                       in  b read_only,
                       out u transfer_id,
                       out o transfer_path);
      ImportFileSystemEx(in  h fd,
                         in  s local_name,
                         in  s class,
                         in  t flags,
                         out u transfer_id,
                         out o transfer_path);
      ExportTar(in  s local_name,
                in  h fd,
                in  s format,
                out u transfer_id,
                out o transfer_path);
      ExportTarEx(in  s local_name,
                  in  s class,
                  in  h fd,
                  in  s format,
                  in  t flags,
                  out u transfer_id,
                  out o transfer_path);
      ExportRaw(in  s local_name,
                in  h fd,
                in  s format,
                out u transfer_id,
                out o transfer_path);
      ExportRawEx(in  s local_name,
                  in  s class,
                  in  h fd,
                  in  s format,
                  in  t flags,
                  out u transfer_id,
                  out o transfer_path);
      PullTar(in  s url,
              in  s local_name,
              in  s verify_mode,
              in  b force,
              out u transfer_id,
              out o transfer_path);
      PullTarEx(in  s url,
                in  s local_name,
                in  s class,
                in  s verify_mode,
                in  t flags,
                out u transfer_id,
                out o transfer_path);
      PullRaw(in  s url,
              in  s local_name,
              in  s verify_mode,
              in  b force,
              out u transfer_id,
              out o transfer_path);
      PullRawEx(in  s url,
                in  s local_name,
                in  s class,
                in  s verify_mode,
                in  t flags,
                out u transfer_id,
                out o transfer_path);
      ListTransfers(out a(usssdo) transfers);
      ListTransfersEx(in  s class,
                      in  t flags,
                      out a(ussssdo) transfers);
      CancelTransfer(in  u transfer_id);
      ListImages(in  s class,
                 in  t flags,
                 out a(ssssbtttttt) images);
    signals:
      TransferNew(u transfer_id,
                  o transfer_path);
      TransferRemoved(u transfer_id,
                      o transfer_path,
                      s result);
  };
  interface org.freedesktop.DBus.Peer { ... };
  interface org.freedesktop.DBus.Introspectable { ... };
  interface org.freedesktop.DBus.Properties { ... };
};

Métodos

ImportTar()/ImportTarEx() y ImportRaw()/ImportRawEx() importan una imagen de disco y la colocan en el directorio de imágenes. El primer argumento debe ser un descriptor de archivo (abierto para lectura) que se refiera al archivo tar o raw a importar. Debería referenciar un archivo en disco, una tubería o un socket. Cuando se usa ImportTar()/ImportTarEx(), el descriptor de archivo debe referirse a un archivo tar, opcionalmente comprimido con gzip(1), zstd(1), bzip2(1) o xz(1). systemd-importd detectará automáticamente el esquema de compresión utilizado (si lo hay). Cuando se usa ImportRaw()/ImportRawEx(), el descriptor de archivo debe referirse a una imagen de disco raw o qcow2 que contenga una etiqueta de disco MBR o GPT, también comprimida opcionalmente con gzip, zstd, bzip2 o xz. En cualquier caso, si el archivo se especifica como un descriptor de archivo en disco, se genera información de progreso para la operación de importación (ya que en ese caso conocemos el tamaño total en disco). Si se especifica un socket o una tubería, no hay información de progreso disponible. Al argumento del descriptor de archivo le sigue un nombre local para la imagen. Este debería ser un nombre adecuado como nombre de host y se utilizará para nombrar la imagen importada en /var/lib/machines/. Una importación tar se coloca como un árbol de directorios o un subvolumen de btrfs(8) debajo del directorio de imágenes bajo el nombre especificado sin sufijo. Una importación raw se coloca como un archivo en el directorio de imágenes con el sufijo .raw añadido. En caso de ImportTar()/ImportRaw(), si el argumento force es verdadero, cualquier imagen preexistente con el mismo nombre se elimina antes de iniciar la operación. De lo contrario, la operación falla si ya existe una imagen con el mismo nombre. El argumento read_only controla si se crea una imagen escribible o de solo lectura. En caso de ImportTarEx()/ImportRawEx(), estos flags booleanos se proporcionan en su lugar mediante un parámetro de flags de 64 bits, con el bit 0 mapeando al parámetro force y el bit 1 mapeando a read_only. El parámetro class especifica la clase de imagen y toma uno de los valores "machine", "portable", "sysext", "confext". Los cuatro métodos devuelven inmediatamente después de iniciar la importación, con la transferencia de importación en curso. Devuelven un par de identificador de transferencia y ruta de objeto, que pueden utilizarse para recuperar información de progreso sobre la transferencia o para cancelarla. El identificador de transferencia es un identificador numérico simple, la ruta del objeto hace referencia a un objeto org.freedesktop.import1.Transfer, véase más abajo. Escuche una señal TransferRemoved() para el ID de transferencia para detectar cuándo se completa una transferencia. El objeto de transferencia devuelto es útil para determinar el progreso actual o la salida de registro de la operación de importación en curso.

ExportTar()/ExportTarEx() y ExportRaw()/ExportRaw() implementan la operación inversa y pueden utilizarse para exportar una imagen del sistema para colocarla en un archivo tar o raw. Toman el nombre de la máquina a exportar como primer parámetro, seguido de un descriptor de archivo (abierto para escritura) donde se escribirá el archivo tar o raw. Puede hacer referencia a un archivo en disco o a una tubería/socket. El tercer argumento especifica en qué formato de compresión se escribirá la imagen. Toma uno de "uncompressed", "xz", "bzip2", "gzip" o "zstd", dependiendo del esquema de compresión requerido. La imagen escrita en el descriptor de archivo especificado será un archivo tar en el caso de ExportTar()/ExportTarEx() o una imagen de disco raw en el caso de ExportRaw()/ExportRawEx(). Tenga en cuenta que actualmente las imágenes de disco raw no se pueden exportar como archivos tar, y viceversa. Esta restricción podría levantarse eventualmente. El método devuelve un identificador de transferencia y una ruta de objeto para cancelar o rastrear la operación de exportación, de manera similar a ImportTar()/ImportTarEx() o ImportRaw()/ImportRawEx() como se describe anteriormente. PullTar()/PullTarEx() y PullRaw()/PullRawEx() pueden usarse para descargar, verificar e importar una imagen del sistema desde una URL. Toman un argumento de URL que debe apuntar a un archivo tar o raw en los protocolos "http://" o "https://", posiblemente comprimido con xz, bzip2, gzip o zstd. El segundo argumento es un nombre local para la imagen. Debería ser adecuado como un nombre de host, de manera similar al argumento coincidente de los métodos ImportTar()/ImportTarEx() y ImportRaw()/ImportRawEx() mencionados anteriormente. El tercer argumento indica el modo de verificación de la imagen. Puede ser uno de "no", "checksum", "signature". "no" desactiva cualquier tipo de verificación de la imagen; "checksum" busca un archivo SHA256SUM junto a la imagen descargada y verifica cualquier valor hash SHA256 en ese archivo contra la imagen; "signature" hace lo mismo pero también intenta autenticar el archivo SHA256SUM a través de gpg(8) primero. En el caso de PullTar()/PullRaw(), el último argumento indica si se debe reemplazar una imagen preexistente con el mismo nombre local (si es "true"), o si se debe fallar (si es "false"). En el caso de PullTarEx()/PullRawEx(), el último argumento es un parámetro de banderas de 64 bits, donde el bit 0 controla la bandera "force", el bit 1 es una bandera "read_only" que controla si la imagen creada debe marcarse como de solo lectura, y el bit 2 es una bandera "keep_download" que indica si se debe mantener una copia prístina y de solo lectura de la imagen descargada, además de la copia local de la imagen. Las variantes ..._Ex() también esperan una cadena de clase de imagen (como se indicó anteriormente). Al igual que las llamadas de importación y exportación anteriores, estas llamadas devuelven un par de identificador de transferencia y ruta de objeto para la descarga en curso.

ImportFileSystem()/ImportFileSystemEx() son similares a ImportTar()/ImportTarEx() pero importan un árbol de directorios. El primer argumento debe referirse a un descriptor de archivo de directorio para la jerarquía de origen a importar.

ListTransfers()/ListTransfersEx() devuelven una lista de operaciones de importación, exportación o descarga en curso creadas con las seis llamadas descritas anteriormente. Devuelven una matriz de estructuras que consisten en el identificador de transferencia numérico, una cadena que indica la operación (una de "import-tar", "import-raw", "export-tar", "export-raw", "pull-tar" o "pull-raw"), una cadena que describe el archivo remoto (en caso de operaciones de descarga es la URL de origen, en caso de operaciones de importación/exportación es una cadena corta que describe el descriptor de archivo pasado), una cadena con el nombre de la imagen de la máquina local, la clase de imagen (solo en el caso de ListTransfersEx(); una de "machine", "portable", "sysext", "confext"), un valor de progreso entre 0.0 (para 0%) y 1.0 (para 100%), así como la ruta del objeto de transferencia.

CancelTransfer() puede usarse para cancelar una operación de importación, exportación o descarga en curso. Simplemente especifique el identificador de transferencia para cancelar la operación en curso.

ListImages() devuelve una lista de las imágenes instaladas actualmente. Toma una cadena de clase de imagen y un parámetro de banderas. La clase de imagen es la cadena vacía o especifica una de las cuatro clases de imagen, por las cuales filtrará. El parámetro de banderas debe ser cero en este momento. Devuelve una matriz de elementos, cada uno describiendo una imagen. Los campos del elemento están en orden: la clase de imagen, el nombre local de la imagen, el tipo de imagen, la ruta de la imagen, la bandera de solo lectura, los tiempos de creación y modificación (en microsegundos desde la época de UNIX), así como el uso actual del disco en bytes (tanto general como exclusivo), así como cualquier límite de tamaño en bytes establecido en la imagen (tanto general como exclusivo).

Señales

La señal TransferNew() se genera cada vez que se inicia una nueva transferencia con las llamadas de importación, exportación o descarga descritas anteriormente. Transporta el ID de transferencia y la ruta del objeto que se han creado recientemente.

La señal TransferRemoved() se envía cada vez que una transferencia finaliza, se cancela o falla. También transporta el ID de transferencia y la ruta del objeto, seguidos de una cadena que indica el resultado de la operación, que es una de "done" (en caso de éxito), "canceled" o "failed".

EL OBJETO TRANSFERENCIA

node /org/freedesktop/import1/transfer/_1 {
  interface org.freedesktop.import1.Transfer {
    methods:
      Cancel();
    signals:
      LogMessage(u priority,
                 s line);
      ProgressUpdate(d progress);
    properties:
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly u Id = ...;
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s Local = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s Remote = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s Type = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("const")
      readonly s Verify = '...';
      @org.freedesktop.DBus.Property.EmitsChangedSignal("false")
      readonly d Progress = ...;
  };
  interface org.freedesktop.DBus.Peer { ... };
  interface org.freedesktop.DBus.Introspectable { ... };
  interface org.freedesktop.DBus.Properties { ... };
};

Métodos

El método Cancel() puede usarse para cancelar la transferencia. No toma parámetros. Este método es prácticamente equivalente al método CancelTransfer() en la interfaz Manager (ver arriba), pero se expone en el propio objeto Transfer en lugar de tomar un ID de transferencia.

Propiedades

La propiedad Id expone el ID numérico de transferencia del objeto de transferencia.

Las propiedades Local, Remote y Type exponen el nombre local del contenedor de esta transferencia, la fuente remota (en caso de descarga: la URL, en caso de importación/exportación: una cadena que describe el descriptor de archivo pasado) y el tipo de operación (ver el método ListTransfer() del Manager arriba para una explicación de los valores posibles).

La propiedad Verify expone la configuración de verificación seleccionada y solo está definida para operaciones de descarga (ver arriba).

La propiedad Progress expone el progreso actual de la transferencia como un valor entre 0.0 y 1.0. Para mostrar una barra de progreso en pantalla, recomendamos consultar este valor en intervalos regulares, por ejemplo, cada 500 ms o así.

Señales

La señal LogMessage() se emite para mensajes de registro generados por una transferencia. Transporta un par de un entero de nivel de registro de syslog y una cadena de registro.

La señal ProgressUpdate() se emite en intervalos regulares cuando hay nueva información de progreso de descarga disponible para una transferencia. Transporta un número de punto flotante de doble precisión entre 0.0 y 1.0 que indica el progreso de la transferencia.
