ocsptool(1) Comandos de usuario ocsptool(1)

NOMBRE

ocsptool - Herramienta OCSP de GnuTLS

SINOPSIS

ocsptool [-flags] [-flag [valor]] [--nombre-opcion[[=| ]valor]]

Todos los argumentos deben ser opciones.

DESCRIPCIÓN

Al verificar
Las respuestas suelen estar firmadas/emitidas por certificados designados o autoridades certificadoras y, por lo tanto, esta herramienta requiere en la verificación el certificado del emisor o la cadena completa de certificados para determinar la autoridad de firma apropiada. Se asume que el certificado del emisor especificado es de confianza.

OPCIONES

-d num, --debug=num

Habilita la depuración. Esta opción toma un número entero como argumento. El valor de num está restringido a estar: 
en el rango de 0 a 9999

Especifica el nivel de depuración.

-V, --verbose

Salida más detallada.
--infile=archivo

Archivo de entrada.
--outfile=str

Archivo de salida.
--ask=nombre del servidor|url

Pregunta a un servidor OCSP/HTTP sobre la validez de un certificado.

Se conecta al servidor OCSP HTTP especificado y consulta la validez del certificado cargado. Su argumento puede ser una URL o un nombre de servidor simple. Se puede combinar con --load-chain, donde verifica todos los certificados de la cadena proporcionada, o con las opciones --load-cert y --load-issuer. Estas últimas verifican el certificado proporcionado contra su certificado emisor especificado.

-e, --verify-response

Verifica la respuesta.

Verifica la respuesta OCSP proporcionada contra las anclas de confianza del sistema (a menos que se proporcione --load-trust). Requiere las opciones --load-signer o --load-chain para obtener el firmante de la respuesta OCSP.

-i, --request-info

Muestra información sobre una solicitud OCSP.

Muestra información detallada sobre la solicitud OCSP proporcionada.

-j, --response-info

Muestra información sobre una respuesta OCSP.

Muestra información detallada sobre la respuesta OCSP proporcionada.

-q, --generate-request

Genera una solicitud OCSP.
--nonce, --no-nonce

Usa (o no) un nonce en la solicitud OCSP. La forma no-nonce deshabilitará la opción.
--load-chain=archivo

Lee un conjunto de certificados que forman una cadena desde el archivo.
--load-issuer=archivo

Lee el certificado del emisor desde el archivo.
--load-cert=archivo

Lee el certificado a verificar desde el archivo.
--load-trust=archivo

Lee las anclas de confianza OCSP desde el archivo. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: load-signer.

Al verificar una respuesta OCSP, lee las anclas de confianza del archivo proporcionado. Si no se proporciona, se utilizarán las anclas de confianza del sistema.

--load-signer=archivo

Lee el firmante de la respuesta OCSP desde el archivo. Esta opción no debe aparecer en combinación con ninguna de las siguientes opciones: load-trust.
--inder, --no-inder

Usa el formato DER para los certificados de entrada y las claves privadas. La forma no-inder deshabilitará la opción.
--outder

Usa el formato DER para la salida de respuestas (este es el valor por defecto).

La salida estará en formato codificado DER. A diferencia de otras herramientas de GnuTLS, este es el valor predeterminado para esta herramienta.

--outpem

Usa el formato PEM para la salida de respuestas.

La salida estará en formato PEM.

-Q archivo, --load-request=archivo

Lee la solicitud OCSP codificada en DER desde el archivo.
-S archivo, --load-response=archivo

Lee la respuesta OCSP codificada en DER desde el archivo.
--ignore-errors

Ignora cualquier error de verificación.
--verify-allow-broken

Permite algoritmos rotos, como MD5 para la verificación.

Esto se puede combinar con --verify-response.

--attime=marca de tiempo

Realiza la validación en la marca de tiempo en lugar de la hora del sistema.

La marca de tiempo es un punto en el tiempo codificado como tiempo Unix o en una cadena de tiempo legible por humanos, como "29 Feb 2004", "2004-02-29". Documentación completa disponible en https://www.gnu.org/software/coreutils/manual/html_node/Date-input-formats.html o localmente a través de info '(coreutils) date invocation'.

-v arg, --version=arg

Muestra la versión del programa y sale. El modo predeterminado es `v`, una versión simple. El modo `c` mostrará información de copyright y `n` mostrará el aviso de copyright completo.
-h, --help

Muestra información de uso y sale.
-!, --more-help

Pasa la información de uso extendida a través de un paginador.

EJEMPLOS

Mostrar información sobre una solicitud OCSP

Para analizar una solicitud OCSP y mostrar información sobre su contenido, se puede usar el parámetro -i o --request-info de la siguiente manera. El parámetro -Q especifica el nombre del archivo que contiene la solicitud OCSP, y debe contener la solicitud OCSP en formato DER binario.


$ ocsptool -i -Q ocsp-request.der

El archivo de entrada también se puede enviar a la entrada estándar de la siguiente manera:


$ cat ocsp-request.der | ocsptool --request-info

Mostrar información sobre una respuesta OCSP

Similar al análisis de solicitudes OCSP, las respuestas OCSP se pueden analizar utilizando -j o --response-info de la siguiente manera.


$ ocsptool -j -Q ocsp-response.der
$ cat ocsp-response.der | ocsptool --response-info

Generar una solicitud OCSP

Los parámetros -q o --generate-request se utilizan para generar una solicitud OCSP. Por defecto, la solicitud OCSP se escribe en la salida estándar en formato DER binario, pero se puede almacenar en un archivo usando --outfile. Para generar una solicitud OCSP, se debe especificar el emisor del certificado a verificar con --load-issuer y el certificado a verificar con --load-cert. Por defecto se usa el formato PEM para estos archivos, aunque --inder se puede usar para especificar que los archivos de entrada están en formato DER.


$ ocsptool -q --load-issuer issuer.pem --load-cert client.pem            --outfile ocsp-request.der

Al generar solicitudes OCSP, la herramienta agregará una extensión OCSP que contiene un nonce. Este comportamiento se puede deshabilitar especificando --no-nonce.

Verificar la firma en la respuesta OCSP


$ ocsptool -e --load-chain chain.pem --load-response ocsp-response.der

En el ejemplo anterior, la respuesta OCSP se verificará usando la cadena de certificados proporcionada. También se pueden especificar anclas de confianza separadas con --load-trust.


$ ocsptool -e --load-trust ca.pem --load-signer responder.pem --load-response ocsp-response.der

Aquí, la respuesta OCSP se verifica usando el certificado del firmante proporcionado, y la respuesta se confía si está firmada por el firmante especificado y el firmante está incluido en las anclas de confianza proporcionadas.

">Para verificar la firma en una respuesta OCSP se utiliza el parámetro -e o --verify-response. La herramienta leerá una respuesta OCSP en formato DER de la entrada estándar, o del archivo especificado por --load-response. La respuesta OCSP se verifica contra un conjunto de anclas de confianza, que se especifican usando --load-trust. Las anclas de confianza son certificados concatenados en formato PEM. El certificado que firmó la respuesta OCSP debe estar en el conjunto de anclas de confianza, o el emisor del certificado firmante debe estar en el conjunto de anclas de confianza y el bit de Uso Extendido de Clave OCSP debe estar activado en el certificado firmante.


$ ocsptool -e --load-trust issuer.pem --load-response ocsp-response.der

La herramienta imprimirá el estado de la verificación.

Verificar firma en respuesta OCSP contra certificado dado

Es posible anular la lógica de confianza normal si sabe que un determinado certificado debe haber firmado la respuesta OCSP y desea usarlo para verificar la firma. Esto se logra usando --load-signer en lugar de --load-trust. Esto cargará un certificado y se utilizará para verificar la firma en la respuesta OCSP. No verificará el bit de Uso Extendido de Clave.


$ ocsptool -e --load-signer ocsp-signer.pem --load-response ocsp-response.der

Este enfoque normalmente solo es relevante en dos situaciones. La primera es cuando la respuesta OCSP no contiene una copia del certificado firmante, por lo que el código --load-trust fallaría. La segunda es si desea evitar el modo indirecto en el que el certificado firmante de la respuesta OCSP está firmado por un ancla de confianza.

Ejemplo del mundo real

Aquí hay un ejemplo de cómo generar una solicitud OCSP para un certificado y verificar la respuesta. Para ilustrar, usaremos el host blog.josefsson.org, que (en el momento de escribir esto) utiliza un certificado de CACert. Primero, usaremos gnutls-cli para obtener una copia de la cadena de certificados del servidor. El servidor no está obligado a enviar esta información, pero este en particular está configurado para hacerlo.


$ echo | gnutls-cli -p 443 blog.josefsson.org --save-cert chain.pem

Los certificados guardados normalmente contienen un puntero a dónde se encuentra el respondedor OCSP, en la extensión de Información de Acceso de Autoridad (Authority Information Access Information). Por ejemplo, de certtool -i < chain.pem hay esta información:


		Authority Information Access Information (not critical):
			Access Method: 1.3.6.1.5.5.7.48.1 (id-ad-ocsp)
			Access Location URI: https://ocsp.CAcert.org/

Esto significa que ocsptool puede descubrir los servidores a los que contactar a través de HTTP. Ahora podemos solicitar información sobre los certificados de la cadena.


$ ocsptool --ask --load-chain chain.pem

La solicitud se envía a través de HTTP a la dirección del servidor OCSP encontrada en los certificados. Es posible anular la dirección del servidor OCSP, así como solicitar información sobre un certificado particular usando --load-cert y --load-issuer.


$ ocsptool --ask https://ocsp.CAcert.org/ --load-chain chain.pem
