OCAMLDEP(1) General Commands Manual OCAMLDEP(1)

NOMBRE

ocamldep - Generador de dependencias para OCaml

SINOPSIS

ocamldep [ opciones ] nombre_archivo ...

DESCRIPCIÓN

El comando ocamldep(1) escanea un conjunto de archivos fuente de OCaml (.ml y .mli) en busca de referencias a unidades de compilación externas, y genera líneas de dependencia en un formato adecuado para la utilidad make(1). Esto asegura que make compilará los archivos fuente en el orden correcto, y recompilará aquellos archivos que necesiten serlo cuando un archivo fuente se modifique.

El uso típico es:

ocamldep opciones *.mli *.ml > .depend

donde .depend es el archivo que debe contener las dependencias.

Las dependencias se generan tanto para compilar con el compilador de bytecode ocamlc(1) como con el compilador de código nativo ocamlopt(1).

OPCIONES

Las siguientes opciones de línea de comandos son reconocidas por ocamldep(1).

-absname
Mostrar nombres de archivo absolutos en mensajes de error.
-no-absname
No intentar mostrar nombres de archivo absolutos en mensajes de error (por defecto).
-all
Generar dependencias en todos los archivos requeridos, en lugar de asumir dependencias implícitas.
-allow-approx
Permitir recurrir a una aproximación basada en lexer cuando el análisis falla.
-as-map
Para los siguientes archivos, no incluir dependencias retrasadas para alias de módulo. Esta opción asume que se compilan usando las opciones "-no-alias-deps -w -49", y que esos archivos o su interfaz se pasan con la opción "-map" al calcular dependencias para otros archivos. Nótese también que para que las dependencias sean correctas en la implementación de un archivo de mapeo, su interfaz no debe coaccionar ninguno de los alias que contiene.
-debug-map
Volcar el mapa de dependencias retrasadas para cada archivo de mapeo.
-I directorio
Añadir el directorio dado a la lista de directorios donde buscar archivos fuente. Si un archivo fuente foo.ml menciona una unidad de compilación externa Bar, se genera una dependencia en la interfaz de esa unidad bar.cmi solo si la fuente de bar se encuentra en el directorio actual o en uno de los directorios especificados con -I. De lo contrario, Bar se asume que es un módulo de la biblioteca estándar, y no se generan dependencias. Para programas que abarcan varios directorios, se recomienda pasar a ocamldep(1) las mismas opciones -I que se pasan al compilador.
-nocwd
No añadir el directorio de trabajo actual a la lista de directorios de inclusión.
-impl archivo
Procesar archivo como un archivo .ml.
-intf archivo
Procesar archivo como un archivo .mli.
-keywords version+lista
Establecer palabras clave según la especificación version+lista.
-map archivo
Leer y propagar las dependencias retrasadas para alias de módulo en archivo, de modo que los siguientes archivos dependan de los módulos alias exportados si los usan.
-ml-synonym .ext
Considerar la extensión dada (con punto inicial) como sinónimo de .ml.
-mli-synonym .ext
Considerar la extensión dada (con punto inicial) como sinónimo de .mli.
-modules
Generar dependencias crudas del tipo nombre_archivo: Módulo1 Módulo2 ... MóduloN donde Módulo1, ..., MóduloN son los nombres de las unidades de compilación referenciadas dentro del archivo nombre_archivo, pero estos nombres no se resuelven a nombres de archivo fuente. Dichas dependencias crudas no pueden ser usadas por make(1), pero pueden ser post-procesadas por otras herramientas como Omake(1).
-native
Generar dependencias para un programa puramente de código nativo (sin versión de bytecode). Cuando un archivo de implementación (.ml) no tiene un archivo de interfaz explícito (.mli), ocamldep(1) genera dependencias en el archivo compilado de bytecode (.cmo) para reflejar cambios en la interfaz. Esto puede causar recompilaciones innecesarias de bytecode para programas que solo se compilan a código nativo. La opción -native causa que se generen dependencias en archivos compilados nativos (.cmx) en lugar de en archivos .cmo. (Esta opción no hace ninguna diferencia si todos los archivos fuente tienen archivos de interfaz .mli explícitos).
-one-line
Generar una línea por archivo, independientemente de la longitud.
-open módulo
Asumir que el módulo módulo está abierto antes de analizar cada uno de los siguientes archivos.
-pp comando
Hacer que ocamldep(1) llame al comando dado como un preprocesador para cada archivo fuente.
-ppx comando
Canalizar el árbol de sintaxis abstracta a través del preprocesador comando.
-shared
Generar dependencias para archivos de plugin nativos (.cmxs) además de los archivos compilados nativos (.cmx).
-slash
(Windows) Usar la barra inclinada / en lugar de la barra invertida \ en las rutas de archivo. En Unix, esta opción no hace nada.
-no-slash
(Windows) Preservar cualquier barra invertida \ en las rutas de archivo. En Unix, esta opción no hace nada.
-sort
Ordenar los archivos según sus dependencias.
-version
Imprimir la cadena de versión y salir.
-vnum
Imprimir el número de versión corto y salir.
-args archivo
Leer argumentos de línea de comandos adicionales separados por saltos de línea desde archivo.
-args0 archivo
Leer argumentos de línea de comandos adicionales separados por NUL desde archivo.
-help o --help
Mostrar un resumen corto de uso y salir.

VER TAMBIÉN

ocamlc(1), ocamlopt(1).
El manual del usuario de OCaml, capítulo "Generador de dependencias".

ocamldep(1)

ocamldep - Imprime las dependencias de los archivos fuente de OCaml.

SINÓPSIS

ocamldep [opción...] [archivo...]

DESCRIPCIÓN

ocamldep es una herramienta para la gestión de dependencias en compilaciones de código fuente de OCaml. Analiza los archivos fuente de OCaml y genera una lista de dependencias entre los módulos. Esta información se puede utilizar para construir un grafo de dependencias y determinar el orden de compilación correcto de los archivos.

Al ejecutar ocamldep con uno o más archivos fuente de OCaml como argumentos, la herramienta imprimirá en la salida estándar las dependencias de cada archivo. El formato de salida es típicamente una lista de pares `archivo.ml: archivo1.mli archivo2.mli ...`, donde `archivo.ml` depende de los archivos `.mli` enumerados.

OPCIONES

-o archivo
Especifique un archivo de salida para las dependencias. Si no se especifica, la salida se dirige a la salida estándar.
-modules
Imprima los nombres de los módulos en lugar de los nombres de archivo.
-intf
Incluya las dependencias de los archivos de interfaz (.mli) además de los archivos fuente (.ml).
-help
Muestra un mensaje de ayuda y sale.
-version
Muestra la versión del compilador y sale.

VER TAMBIÉN

ocamlc(1), ocamlopt(1)
