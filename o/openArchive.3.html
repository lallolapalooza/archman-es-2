Descripción Detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es para usuarios avanzados. No lo necesitarás a menos que sepas realmente lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se han limitado a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivo.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo no proporcionado directamente por PhysicsFS: quizás algún formato propietario que solo tu aplicación necesite entender.

Internamente, todo el soporte de archivo incorporado utiliza esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver son el código fuente de PhysicsFS.

Un archivador se añade al sistema con PHYSFS_registerArchiver(), y luego estará disponible para su uso automáticamente con PHYSFS_mount(); si un archivo dado puede ser manejado por tu archivador, se le dará el control según corresponda.

Estos métodos tratan con manejadores de directorios. Tienes una instancia de tu archivador, y genera un manejador único y opaco para cada archivo abierto en su método openArchive(). Dado que la vida útil de un Archivador (no de un archivo) es generalmente la vida útil completa del proceso, y se asume que es un singleton, no proporcionamos datos de instancia para el archivador en sí; la aplicación puede usar variables estáticas si es necesario.

Los enlaces simbólicos siempre deben seguirse (excepto en stat()); PhysicsFS utilizará el método stat() para verificar los enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en eso.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de devolver. PhysicsFS pasará estos errores a la aplicación sin modificaciones en la mayoría de los casos.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Archiver sean seguras para hilos por sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador dado dentro de la biblioteca, pero no promete que usar el mismo PHYSFS_File desde dos hilos a la vez sea seguro para hilos; como tal, tu PHYSFS_Archiver puede asumir que el bloqueo se maneja por ti siempre que el PHYSFS_Io que devuelvas de PHYSFS_open* no cambie ningún estado de tu Archivador, ya que el PHYSFS_Io no estará tan agresivamente protegido.

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruye un archivo previamente abierto. Cierra este archivo y libera cualquier memoria asociada, incluyendo el PHYSFS_Io original y (opaque) en sí mismo, si aplica. La implementación puede asumir que no se llamará si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Lista todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, para que puedas desecharla al regresar de la llamada de retorno. (dirname) está en notación independiente de la plataforma. Si tienes un fallo, llama a PHYSFS_SetErrorCode() con el código que parezca apropiado y devuelve PHYSFS_ENUM_ERROR. Si la llamada de retorno devuelve PHYSFS_ENUM_ERROR, llama a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y devuelve PHYSFS_ENUM_ERROR también. No llames a la llamada de retorno de nuevo bajo ninguna circunstancia. Si la llamada de retorno devuelve PHYSFS_ENUM_STOP, deja de enumerar y devuelve PHYSFS_ENUM_STOP también. No llames a la llamada de retorno de nuevo bajo ninguna circunstancia. No establezcas un código de error en este caso. Las llamadas de retorno solo deben devolver un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene comportamiento indefinido. Mientras la llamada de retorno haya devuelto PHYSFS_ENUM_OK y tú no hayas experimentado ningún error propio, continúa enumerando hasta que hayas terminado y luego devuelve PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate devuelve cero o no cero (éxito o fallo), así que ten en cuenta que esta función puntero devuelve valores diferentes.

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Esto se utiliza para identificar tu archivo y se devuelve en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crea un directorio en el archivo. Si la aplicación está intentando crear múltiples directorios, PhysicsFS los dividirá en múltiples llamadas antes de pasarlos a tu controlador. Si el archivo es de solo lectura, esta operación debería fallar. Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abre un archivo en este archivo para añadir. Si el archivo no existe, debe crearse. La posición de escritura debe ser el final del archivo. Si el archivo es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de la plataforma. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaque" para llamadas posteriores de archivo.

NAME

PHYSFS_Archiver — Información sobre el formato del archivo.

SYNOPSIS

#include <physfs.h>

typedef struct PHYSFS_Archiver {
PHYSFS_uint32 version;
int(* openArchive)(void *, const char *, int);
void(* closeArchive)(void *);
PHYSFS_sint64(* enumerate)(void *, const char *, PHYSFS_Enumeration *);
PHYSFS_Io *(* openRead)(void *, const char *);
PHYSFS_Io *(* openWrite)(void *, const char *);
int(* remove)(void *, const char *);
int(* stat)(void *, const char *, PHYSFS_Stat *);
}PHYSFS_Archiver;

Descripción detallada

Esta estructura se utiliza para registrar nuevos tipos de archivos comprimidos con PhysFS. Los miembros de esta estructura son punteros a funciones que implementan la funcionalidad del archivo comprimido.

Cada implementación de archivo comprimido (por ejemplo, ZIP, RAR, etc.) debe proporcionar una instancia de esta estructura. Al iniciar PhysFS, se registran todas las implementaciones de archivos comprimidos disponibles.

Cuando PhysFS necesita acceder a un archivo, itera a través de cada implementador de archivo comprimido registrado y llama a su función openArchive. Si el implementador dice que puede manejar el archivo, PhysFS utiliza ese implementador para todas las operaciones posteriores en ese archivo. Si ningún implementador puede manejar el archivo, se informa un error.

int(* PHYSFS_Archiver::openArchive) (void *opaque, const char *fn, int forWrite)

Intenta abrir un archivo comprimido. (fn) es la ruta al archivo comprimido. Si (forWrite) es distinto de cero, el archivo comprimido debe ser modificable; de lo contrario, es de solo lectura. La implementación debe devolver un puntero opaco (a menudo un puntero a una estructura que representa el archivo comprimido abierto) si tiene éxito, o NULL si falla. Si devuelve un puntero opaco, también debe establecer el miembro (claimed) de la estructura devuelta. La estructura devuelta se pasa como parámetro "opaque" para todas las llamadas posteriores a las funciones de este implementador. La cadena (fn) está en notación independiente de la plataforma. El valor de (claimed) debe establecerse en 1 si este es definitivamente un archivo que su implementación de archivo comprimido puede manejar, incluso si falla. Lo usamos para decidir si debemos dejar de intentar con otros implementadores de archivo comprimido si falla al abrirlo. Por ejemplo: el implementador .zip establecerá esto en 1 para algo que tenga una firma de archivo .zip, incluso si falló porque el archivo también estaba truncado. No tiene sentido intentar con otros implementadores de archivo comprimido aquí, ¡ya hemos intentado manejarlo con la implementación apropiada!. Devuelve NULL en caso de fallo y establece (claimed) apropiadamente. Si ningún implementador de archivo comprimido abrió el archivo o estableció (claimed), PHYSFS_mount() informará PHYSFS_ERR_UNSUPPORTED. De lo contrario, informará el error del implementador de archivo comprimido que reclamó los datos a través de (claimed). Devuelve no NULL en caso de éxito. El puntero devuelto se pasará como el parámetro "opaque" para las llamadas posteriores.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fn)

Abre un archivo en este archivo comprimido para lectura. Este nombre de archivo, (fn), está en notación independiente de la plataforma. Falla si el archivo no existe. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve no NULL en caso de éxito. El puntero devuelto se pasará como el parámetro "opaque" para las llamadas de archivo posteriores.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Abre un archivo en este archivo comprimido para escritura. Si el archivo no existe, debe crearse. Si existe, debe truncarse a cero bytes. El desplazamiento de escritura debe ser el inicio del archivo. Si el archivo comprimido es de solo lectura, esta operación debe fallar. Este nombre de archivo está en notación independiente de la plataforma. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve no NULL en caso de éxito. El puntero devuelto se pasará como el parámetro "opaque" para las llamadas de archivo posteriores.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Elimina un archivo o directorio en el archivo comprimido. Esta misma llamada se utiliza tanto para archivos como para directorios; no hay una llamada rmdir() separada. Los directorios solo están destinados a ser eliminados si están vacíos. Si el archivo comprimido es de solo lectura, esta operación debe fallar.

Devuelve distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtiene metadatos básicos del archivo. En caso de éxito, rellena todos los campos en (stat), utilizando valores predeterminados razonables para los campos que se aplican a su archivo comprimido.

Devuelve distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Información de compatibilidad binaria. Debe establecerse en cero en este momento. Las versiones futuras de esta estructura incrementarán este campo, para que sepamos qué soporta una implementación dada. Presumiblemente, seguiremos admitiendo versiones anteriores a medida que ofrezcamos nuevas funciones, sin embargo.
