OPAM-UNINSTALL(1) Manual de Opam OPAM-UNINSTALL(1)

NOMBRE

opam-uninstall - Un alias para remove.

SINOPSIS

opam uninstall [OPCIÓN]… [PAQUETES]…

DESCRIPCIÓN

opam uninstall es un alias para opam remove.

Ver opam remove --help para más detalles.

OPCIONES DE COMPILACIÓN DE PAQUETES

--assume-depexts
Omitir el paso de instalación para cualquier paquete del sistema faltante, e intentar continuar con la compilación de los paquetes opam de todos modos. Si la instalación es exitosa, opam no volverá a preguntar sobre estos paquetes del sistema. Solo tiene sentido si el manejo de dependencias externas está habilitado.
-b, --keep-build-dir
Mantener los directorios de compilación después de compilar los paquetes. Esto es equivalente a establecer $OPAMKEEPBUILDDIR a "true".
--build-doc
Eliminado en la versión 2.1, usar --with-doc en su lugar.
--build-test
Eliminado en la versión 2.1, usar --with-test en su lugar.
-d, --with-doc
Compilar la documentación del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Es equivalente a establecer $OPAMWITHDOC (o el obsoleto $OPAMBUILDDOC) a "true".
--dry-run
Simular el comando, pero sin realizar ningún cambio. Esto también se puede establecer mediante la variable de entorno $OPAMDEBUG.
--fake
Esta opción registra las acciones en la base de datos de opam, sin realizarlas realmente. ADVERTENCIA: Esta opción es peligrosa y probablemente rompa tu entorno opam. Probablemente quieras usar --dry-run. Has sido advertido.
--ignore-constraints-on[=PAQUETES] (predeterminado=)
Obliga a opam a ignorar las restricciones de versión en todas las dependencias de los paquetes listados. Esto se puede usar para probar la compatibilidad, pero se esperan fallos de compilación al usarlo. Ten en cuenta que la disponibilidad de los paquetes, así como las restricciones de versión en dependencias opcionales y conflictos, no se ven afectadas. Esto es equivalente a establecer $OPAMIGNORECONSTRAINTS.
--inplace-build
Al compilar un paquete cuyas fuentes están vinculadas a un directorio local, procesar las acciones de compilación e instalación directamente en ese directorio, en lugar de hacerlo en una copia limpia manejada por opam. Esto solo afecta a los paquetes que se listan explícitamente en la línea de comandos. Es equivalente a establecer $OPAMINPLACEBUILD a "true".
-j JOBS, --jobs=JOBS
Establece el número máximo de trabajos concurrentes a utilizar. El valor predeterminado se calcula a partir del número de núcleos. También puedes establecerlo usando la variable de entorno $OPAMJOBS.
--lock-suffix=SUFIJO (ausente=locked)
Establece el sufijo de los archivos de bloqueo a SUFIJO.
--locked
En comandos que utilizan archivos opam encontrados en fuentes fijadas, si se encuentra una variante del archivo con una extensión .locked añadida (por ejemplo, foo.opam.locked además de foo.opam), se utilizará esa en su lugar. Esto es típicamente útil para ofrecer un conjunto más específico de dependencias y reproducir contextos de compilación similares, de ahí el nombre. La opción lock se puede usar para generar dichos archivos, basándose en las versiones de las dependencias actualmente instaladas en el host. Esto es equivalente a establecer la variable de entorno $OPAMLOCKED. Ten en cuenta que esta opción generalmente no afecta a los paquetes ya fijados.
-m MAKE, --make=MAKE
Eliminado en la versión 2.1, usar opam config set[-global] make MAKE en su lugar.
--no-checksums
No verificar la suma de control (checksum) de los archivos descargados. Es equivalente a establecer $OPAMNOCHECKSUMS a "true".
--no-depexts
Deshabilita temporalmente el manejo de dependencias externas. Esto se puede usar si un paquete no está disponible en el gestor de paquetes de tu sistema, pero instalaste la dependencia requerida manualmente. Implica --assume-depexts, y también almacena las excepciones tras el éxito.
--require-checksums
Rechaza la instalación de paquetes que no proporcionan una suma de control para los archivos de origen. Es equivalente a establecer $OPAMREQUIRECHECKSUMS a "true".
--reuse-build-dir
Reutiliza los directorios de compilación existentes (mantenidos usando --keep-build-dir), en lugar de compilar desde una copia limpia de las fuentes. Esto puede ser más rápido, pero también puede llevar a fallos si los sistemas de compilación de los paquetes no manejan bien las actualizaciones de dependencias. Es equivalente a establecer $OPAMREUSEBUILDDIR a "true".
--show-actions
Llama al solucionador y muestra las acciones. No realiza ningún cambio. Es equivalente a establecer $OPAMSHOW.
--skip-updates
Al ejecutar una instalación, actualización o reinstalación en paquetes fijados desde fuentes, normalmente se actualizan primero desde su origen. Esta bandera deshabilita ese comportamiento y los mantiene a su versión en la caché. Es equivalente a establecer $OPAMSKIPUPDATE.
-t, --with-test
Compilar y ejecutar las pruebas unitarias del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Es equivalente a establecer $OPAMWITHTEST (o el obsoleto $OPAMBUILDTEST) a "true".
--unlock-base
Eliminado en la versión 2.1, usar --update-invariant en su lugar.
--update-invariant
Permite cambios en los paquetes que se establecen como base del switch (típicamente, el compilador principal). Usar con precaución. Es equivalente a establecer la variable de entorno $OPAMUNLOCKBASE
--verbose-on=PAQUETES
Ser más verboso en paquetes específicos. Es equivalente a establecer $OPAMVERBOSE.
--with-dev-setup
Incluir dependencias solo de herramientas de desarrollo.

ARGUMENTOS

PAQUETES
Lista de nombres de paquetes, con una versión o restricción opcional, por ejemplo `pkg', `pkg.1.0' o `pkg>=0.5'; o nombres de directorios que contienen la descripción del paquete, con directorio explícito (por ejemplo, `./srcdir' o `.')

OPCIONES

-a, --auto-remove
Elimina todos los paquetes que no han sido instalados explícitamente y que ya no son necesarios. Es posible evitar la eliminación de un paquete ya instalado ejecutando opam install <pkg> --set-root. Esta bandera también se puede establecer usando la variable de configuración $OPAMAUTOREMOVE.
--destdir=DIR
En lugar de desinstalar los paquetes, revierte la acción de opam install --destdir: elimina los archivos correspondientes a lo que los paquetes listados instalaron al switch actual desde el DIR dado. Ten en cuenta que el paquete debe seguir instalado en la misma versión que se utilizó para install --destdir para que esto funcione de manera confiable. Los paquetes no se eliminan del switch opam actual cuando se especifica esto.
--force
Ejecuta los comandos de eliminación de los paquetes dados directamente, incluso si no son considerados instalados por opam.
--formula=FÓRMULA (predeterminado=[])
Experimental. Especifica una fórmula de dependencia para ser verificada por la solución, además de la invariante del switch. El formato es el mismo que para expresar dependencias en archivos de definición de paquetes, por ejemplo, '"foo" {>= "1.1"}'
--recursive
Permite búsquedas recursivas de archivos *.opam. Cf. --subpath también.
--subpath=RUTA
Los archivos *.opam se recuperan del subdirectorio dado en lugar del directorio principal. Las fuentes se toman entonces del subdirectorio objetivo, internamente solo este subdirectorio se copia/descarga. Se puede combinar con --recursive para tener una búsqueda recursiva en el subpath.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Ten en cuenta que no todos los solucionadores externos pueden soportar esta opción (las versiones recientes de aspcud o mccs deberían). Es equivalente a establecer $OPAMBESTEFFORT<

OPTIONS

--debug-solver
Activa la depuración del solucionador para el solucionador subyacente. Esto es equivalente a establecer la variable de entorno $OPAMDEBUG_SOLVER.
--cli=MAJOR.MINOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAJOR.MINOR. Previsto para cualquier uso persistente de opam (scripts, publicaciones de blogs, etc.), cualquier versión de opam en la misma serie MAJOR se comportará como para la versión MINOR especificada. El indicador no estaba disponible en opam 2.0, por lo que para seleccionar la CLI 2.0, establece la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUANDO
Colorea la salida. CUANDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o unsafe-yes. Se puede especificar varias veces. Si también se proporcionan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especifica las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje soportado y los solucionadores externos disponibles, consulta http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre el uso de preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBREARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en NOMBREARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está establecida (es decir, si estás usando una versión de desarrollo), y sale.
--help[=FMT] (predeterminado=auto)
Muestra esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable de entorno TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBREARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%`, será reemplazado por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Ten en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Usa ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegúrate de que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de autocompletado, por ejemplo. Fallará cuando se necesite tal operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el solucionador CUDF a usar para resolver problemas de instalación de paquetes. Esto es un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentre un error en la definición de un paquete o un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.
--switch=SWITCH
Usa SWITCH como el cambio de compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier solucionador externo y usa el interno (esto requiere que opam haya sido compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más verboso. Un -v muestra todos los comandos de paquetes, repetir para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra información de la versión.
-w, --working-dir
Siempre que se actualicen paquetes asociados a un directorio local controlado por versiones, actualiza al estado de trabajo actual de su fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio fuente se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

AMBIENTE

Opam utiliza las variables de entorno listadas aquí. Las variables booleanas deben establecerse a "0", "no", "false" o la cadena vacía para deshabilitar, "1", "yes" o "true" para habilitar.

OPAMALLPARENS rodea todos los filtros con paréntesis.

OPAMASSUMEDEPEXTS ver opción `--assume-depexts'.

OPAMAUTOREMOVE ver opción de eliminación `--auto-remove'.

OPAMBESTEFFORT ver opción `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA establece la cadena que debe anteponerse a los criterios cuando se establece la opción `--best-effort', y se espera que maximice la propiedad `opam-query' en la solución.

OPAMBUILDDOC Eliminado en 2.1.

OPAMBUILDTEST Eliminado en 2.1.

OPAMCLI ver opción `--cli'.

OPAMCOLOR cuando se establece a always o never, establece un valor predeterminado para la opción `--color'.

OPAMCONFIRMLEVEL ver opción `--confirm-level`. OPAMCONFIRMLEVEL tiene prioridad sobre OPAMYES y OPAMNO.

OPAMCRITERIA especifica las preferencias del usuario para la resolución de dependencias. El valor predeterminado depende de la versión del solucionador, usa `config report' para conocer la configuración actual. Ver también la opción --criteria.

OPAMCUDFFILE guarda el grafo cudf en file-actions-explicit.dot.

OPAMCUDFTRIM controla el filtrado de paquetes no relacionados durante el preprocesamiento de CUDF.

OPAMCURL se puede usar para seleccionar un programa 'curl' dado. Ver OPAMFETCH para más opciones.

OPAMDEBUG ver opciones `--debug' y `--debug-level'.

OPAMDEBUGSECTIONS si está establecido, limita los mensajes de depuración a la lista de secciones separadas por espacios. Las secciones pueden opcionalmente tener un nivel de depuración específico (por ejemplo, CLIENT:2 o CLIENT CUDF:2), pero de lo contrario usan `--debug-level'.

OPAMDIGDEPTH define la agresividad de la búsqueda de conflictos durante el preprocesamiento de CUDF.

OPAMDOWNLOADJOBS establece el número máximo de descargas simultáneas.

OPAMDROPWORKINGDIR anula los paquetes previamente actualizados con --working-dir en la actualización. Sin esta variable establecida, opam los mantendría sin cambios a menos que se nombren explícitamente en la línea de comandos.

OPAMDRYRUN ver opción `--dry-run'.

OPAMEDITOR establece el editor a usar para editar archivos de opam, anula $EDITOR y $VISUAL.

OPAMERRLOGLEN establece el número de líneas de registro impresas cuando un subproceso falla. 0 para imprimir todas.

OPAMEXTERNALSOLVER ver opción `--solver'.

OPAMFAKE ver opción `--fake'.

OPAMFETCH especifica cómo descargar archivos: `wget', `curl' o un comando personalizado donde las variables %{url}%, %{out}%, %{retry}%, %{compress}% y %{checksum}% serán reemplazadas. Anula el valor de 'download-command' del archivo de configuración principal.

OPAMFIXUPCRITERIA igual que OPAMUPGRADECRITERIA, pero específico para fixup y reinstall.

OPAMIGNORECONSTRAINTS ver opción de instalación `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS ver opción `--ignore-pin-depends'.

OPAMINPLACEBUILD ver opción `--inplace-build'.

OPAMJOBS establece el número máximo de trabajadores paralelos a ejecutar.

OPAMJSON registra la salida json en el archivo dado (usa el carácter `%` para indexar los archivos).

OPAMKEEPBUILDDIR ver opción de instalación `--keep-build-dir'.

OPAMKEEPLOGS indica a opam que no elimine algunos registros de comandos temporales y algunas copias de seguridad. Esto omite algunos finalizadores y también puede ayudar a obtener backtraces más confiables.

OPAMLOCKED combinación de las opciones `--locked' y `--lock-suffix'.

OPAMLOGS dirlog establece el directorio de logs, el predeterminado es un directorio temporal en /tmp

OPAMMAKECMD establece el comando make del sistema a usar.

OPAMMERGEOUT fusiona las salidas de procesos, stderr en stdout.

OPAMNO responde no a cualquier pregunta realizada, ver opciones `--no' y `--confirm-level`. OPAMNO se ignora si OPAMCONFIRMLEVEL o OPAMYES están establecidos.

OPAMNOAGGREGATE con

`opam admin check', no agregation de paquetes.

OPAMNOASPCUD Obsoleto.

OPAMNOAUTOUPGRADE deshabilita la actualizacion interna automatica de repositorios en un formato anterior al actual, en 'update' o 'init'.

OPAMNOCHECKSUMS habilita la opcion --no-checksums cuando esta disponible.

OPAMNODEPEXTS deshabilita el manejo de dependencias del sistema, vea la opcion `--no-depexts'.

OPAMNOENVNOTICE Interno.

OPAMNOSELFUPGRADE vea la opcion `--no-self-upgrade'

OPAMPINKINDAUTO establece si los sistemas de control de versiones deben ser detectados al fijar a una ruta local. Habilitado por defecto desde 1.3.0.

OPAMPRECISETRACKING seguimiento de directorios de grano fino.

OPAMPREPRO establezca esto a falso para deshabilitar el preprocesamiento de CUDF. Menos eficiente, pero puede ayudar a depurar problemas del solucionador.

OPAMREPOSITORYTARRING almacena internamente los repositorios como archivos tar.gz. Esto puede ser mucho mas rapido en sistemas de archivos que no manejan bien el escaneo de arboles grandes pero que tienen buena cache en /tmp. Sin embargo, esto es mas lento en el caso general.

OPAMREQUIRECHECKSUMS Habilita la opcion `--require-checksums' cuando esta disponible (p. ej., para `opam install').

OPAMRETRIES establece el numero de intentos antes de fallar las descargas.

OPAMREUSEBUILDDIR vea la opcion `--reuse-build-dir'.

OPAMROOT vea la opcion `--root'. Esto se establece automaticamente mediante `opam env --root=DIR --set-root'.

OPAMROOTISOK no se queje al ejecutarse como root.

OPAMSAFE vea la opcion `--safe'.

OPAMSHOW vea la opcion `--show'.

OPAMSKIPUPDATE vea la opcion `--skip-updates'.

OPAMSKIPVERSIONCHECKS omite algunas verificaciones de version. Inseguro, solo para pruebas de compatibilidad.

OPAMSOLVERALLOWSUBOPTIMAL (por defecto `true') permite que algunos solucionadores aun devuelvan una solucion cuando alcanzan el tiempo de espera; mientras que la solucion sigue estando garantizada como consistente, no hay garantia en este caso de que se ajuste a los criterios de optimizacion esperados. Si es `true', opam continuara con una advertencia, si es `false' el tiempo de espera es un error. Actualmente solo el backend builtin-z3 maneja este caso degradado.

OPAMSOLVERTIMEOUT cambia la asignacion de tiempo del solucionador. Por defecto es 60.0, establecido a 0 para ilimitado. Tenga en cuenta que no todos los solucionadores pueden soportar esta opcion.

OPAMSOLVERTOLERANCE cambia la tolerancia hacia que el solucionador elija una solucion no optimizada (es decir, podria descargar paquetes desactualizados). Los valores tipicos oscilan entre 0.0 (mejor solucion conocida por el solucionador) y 1.0 (solucion no optimizada). El valor por defecto es 0.0. Esta opcion es util en caso de que el solucionador no pueda encontrar una solucion en un tiempo razonable (vea $OPAMSOLVERTIMEOUT). Tenga en cuenta que no todos los solucionadores pueden soportar esta opcion.

OPAMSTATS Eliminado en 2.4.

OPAMSTATUSLINE muestra una linea de estado dinamica que muestra lo que esta sucediendo actualmente en la terminal. (uno de siempre, nunca o auto)

OPAMSTRICT falla ante inconsistencias (lectura de archivos, importacion de switch, etc.).

OPAMSWITCH vea la opcion `--switch'. Establecido automaticamente por `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE vea la opcion de instalacion `--unlock-base'.

OPAMUPGRADECRITERIA especifica las preferencias del usuario para la resolucion de dependencias al realizar una actualizacion. Sobrescribe OPAMCRITERIA en las actualizaciones si ambas estan establecidas. Vea tambien la opcion --criteria.

OPAMUSEINTERNALSOLVER vea la opcion `--use-internal-solver'.

OPAMUSEOPENSSL Eliminado en 2.2.

OPAMUTF8 usa caracteres UTF8 en la salida (uno de siempre, nunca o auto). Por defecto `auto', que se determina a partir de la configuracion regional).

OPAMUTF8MSGS usa caracteres UTF8 extendidos (camellos) en los mensajes de opam. Implica OPAMUTF8. Esto esta establecido por defecto solo en macOS.

OPAMVALIDATIONHOOK si esta establecido, utiliza el comando `%{hook%}' para validar una actualizacion de repositorio de opam.

OPAMVERBOSE vea la opcion `--verbose'.

OPAMVERBOSEON vea la opcion --verbose-on

OPAMVERSIONLAGPOWER no usar.

OPAMWITHDEVSETUP vea la opcion de instalacion `--with-dev-setup'.

OPAMWITHDOC vea la opcion de instalacion `--with-doc'.

OPAMWITHTEST vea la opcion de instalacion `--with-test.

VERSIÓN DEL CLI

Todos los scripts e invocaciones programaticas de opam deberian usar `--cli' para garantizar que funcionen sin problemas con futuras versiones del cliente opam. Ademas, las publicaciones de blog u otra documentacion pueden beneficiarse, ya que evita que la informacion se vuelva obsoleta.

Aunque opam solo admite raices (~/.opam/) para la version actual, proporciona compatibilidad hacia atras para su interfaz de linea de comandos.

Dado que el soporte de la version CLI solo se agrego en opam 2.1, use OPAMCLI para seleccionar el soporte 2.0 (ya que opam 2.0 simplemente lo ignorara), y `--cli=2.1' para versiones 2.1 (o posteriores), ya que una variable de entorno que controla el analisis de sintaxis es fragil. Para ello, opam muestra una advertencia si OPAMCLI especifica una version valida distinta de 2.0, y tambien si se especifica `--cli=2.0'.

La version de la linea de comandos se selecciona utilizando la opcion `--cli' o la variable de entorno OPAMCLI. `--cli' puede especificarse mas de una vez, donde la ultima instancia tiene prioridad. OPAMCLI solo se inspecciona si no se proporciona `--cli'.

ESTADO DE SALIDA

Como excepcion a lo siguiente, el comando `exec' devuelve 127 si el comando no se encontro o no se pudo ejecutar, y el valor de salida del comando en caso contrario.

0
Exito, o verdadero para consultas booleanas.
1
Falso. Devuelto cuando se espera un valor booleano de retorno, por ejemplo, al ejecutar con --check, o para consultas como opam lint.
2

    NAME

    opam-uninstall — Uninstall packages

    SYNOPSIS

    opam uninstall [OPTION]... [PACKAGE]...

    DESCRIPTION

    This command uninstalls packages from the current switch. If no packages are specified, it will uninstall all installed packages. The uninstallation process is recursive: if a package is not required by any other installed package, it is removed.

    PACKAGE BUILD OPTIONS

    When uninstalling packages, opam may need to rebuild dependencies if some packages are removed and others are kept. These options influence this process:

    • --keep-build-depends: Do not uninstall packages that are depended on by other packages currently being uninstalled. This is useful when you want to uninstall a package but keep its dependencies.

    • --unlock-update: If a package is installed from a locked version, this option allows opam to update its dependencies.

    ARGUMENTS

    A list of package names to uninstall. If none are provided, all installed packages will be uninstalled.

    OPTIONS

    These options directly control the uninstallation process:

    • -y, --yes: Assume "yes" to all prompts. This bypasses the confirmation prompt before starting the uninstallation.

    • -a, --all: Uninstall all installed packages in the current switch. This is equivalent to running `opam uninstall` without any arguments.

    • --keep-deps: Keep the dependencies of the packages being uninstalled. This option is an alias for --keep-build-depends.

    • --force: Force the uninstallation even if there are errors. Use with caution.

    • --no-deps: Do not uninstall dependencies of the specified packages. This means that dependencies will be left installed even if they are no longer needed by any other package.

    COMMON OPTIONS

    These options are common to many opam commands:

    • --help: Display a help message and exit.

    • --root <DIR>: Use a different root directory for the opam state. Defaults to ~/.opam.

    • --switch <SWITCH>: Use a different switch. Defaults to the current switch.

    • --jobs <NUM>: Use NUM parallel jobs for operations that can be parallelized. Defaults to the number of CPU cores.

    • --no-autoalloc: Do not automatically allocate packages.

    • --log-level <LEVEL>: Set the logging level. Possible values are fatal, error, warn, info, debug. Defaults to info.

    • --log-file <FILE>: Log to a file instead of stderr.

    • --color <WHEN>: Control colorized output. WHEN can be auto, always, or never. Defaults to auto.

    ENVIRONMENT

    See opam-env(1) for environment variables that can affect opam commands.

    CLI VERSION

    This command is available from version 2.0.0.

    EXIT STATUS

    0 on success, non-zero otherwise.
