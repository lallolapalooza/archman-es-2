NAME

org.freedesktop.machine1 - The D-Bus interface of systemd-machined

INTRODUCTION

systemd-machined.service(8) es un servicio del sistema que realiza un seguimiento de las máquinas virtuales y contenedores que se ejecutan localmente. Esta página describe la interfaz D-Bus.

Métodos

GetMachine() puede usarse para obtener la ruta del objeto de la máquina para la máquina con el nombre especificado. De manera similar, GetMachineByPID() obtiene el objeto de la máquina al que pertenece el PID especificado, si hay alguno.

GetImage() puede usarse para obtener la ruta del objeto de la imagen con el nombre especificado.

ListMachines() devuelve una matriz de todas las máquinas actualmente registradas. Las estructuras en la matriz consisten en los siguientes campos: nombre de la máquina, clase de la máquina, un identificador del servicio que registró la máquina y la ruta del objeto de la máquina.

ListImages() devuelve una matriz de todas las imágenes actualmente conocidas. Las estructuras en la matriz consisten en los siguientes campos: nombre de la imagen, tipo, indicador de solo lectura, hora de creación, hora de modificación, espacio actual en disco y ruta del objeto de la imagen.

CreateMachine() puede usarse para registrar una nueva máquina virtual o contenedor con systemd-machined, creando una unidad de ámbito para ella. Acepta los siguientes argumentos: un nombre de máquina elegido por el registrador, un UUID opcional como matriz de 32 bytes, una cadena que identifica el servicio que registra la máquina, una cadena de clase, el PID del proceso líder de la máquina, un directorio raíz opcional del contenedor y una matriz de propiedades adicionales para usar en el registro del ámbito. El nombre de la máquina virtual debe ser adecuado como nombre de host y, por lo tanto, debe seguir las reglas habituales de nombres de host DNS, así como las restricciones de nombres de host de Linux. Específicamente, solo se permite ASCII de 7 bits, se aplica una longitud máxima de 64 caracteres, solo se permiten caracteres del conjunto "a-zA-Z0-9-_.", el nombre no puede comenzar con un punto y no puede contener dos puntos seguidos. Los administradores de contenedores y VM deben utilizar idealmente el nombre de host utilizado internamente en la máquina para este parámetro. Se hace esta recomendación para que el nombre de la máquina sea resoluble de forma natural utilizando nss-mymachines(8). Si un administrador de contenedores necesita incrustar caracteres fuera del rango indicado, se requiere escape, posiblemente usando "_" como carácter de escape. Otra opción (algo natural) sería utilizar la codificación IDNA de Internet. El UUID se pasa como una matriz de 32 bytes o, si no hay un UUID adecuado disponible, se pasará una matriz vacía (de longitud cero) o una matriz con ceros. El UUID debe identificar la máquina virtual/contenedor de forma única y, idealmente, debería ser el mismo UUID a partir del cual se inicializa /etc/machine-id en la VM/contenedor. La cadena de servicio puede ser de formato libre, pero se recomienda pasar un identificador corto en minúsculas como "systemd-nspawn", "libvirt-lxc" o similar. La cadena de clase debe ser "container" o "vm", indicando si la máquina a registrar es de la clase respectiva. El PID líder debe ser el PID del host del proceso init del contenedor o el proceso encapsulador de la VM. Si el directorio raíz del contenedor se conoce y está disponible en la jerarquía del host, se debe pasar (tenga en cuenta que esto es solo para fines informativos.

MÉTODOS

CreateMachine() crea una nueva máquina virtual o contenedor en el sistema. Como argumentos, toma el nombre de la máquina, un identificador de máquina (que generalmente se usa para el ID de usuario del espacio de nombres de la máquina y que se pasa a la utilidad machine-id(5)), un directorio raíz para el sistema de archivos de la máquina, la imagen de la máquina a utilizar y el PID del proceso líder de la máquina. El PID del líder se utiliza para identificar la máquina y se puede obtener mediante llamadas a getpid(2). El método devuelve el objeto de máquina recién creado para la interfaz org.freedesktop.machine1.Machine (ver abajo).

CreateMachine() también puede recibir parámetros opcionales adicionales. La especificación del tipo de máquina se pasa como una cadena de caracteres (actualmente solo se admite "machine"). Las opciones de red para la máquina se pasan como una matriz de cadenas que describen cómo se deben conectar las interfaces de red. Vea systemd.net-setup(5) para más detalles. Las propiedades del alcance se pasan como una matriz de la misma manera que a StartTransientUnit() de PID1. La llamada a este método registrará internamente una unidad de alcance transitoria para el cliente que llama (utilizando las scope_properties pasadas) y moverá el PID líder a ella. El método devuelve un objeto de ruta para el objeto de máquina registrado que implementa la interfaz org.freedesktop.machine1.Machine (ver abajo). Consulte también las Nuevas interfaces de control de grupo[1] para obtener detalles sobre las unidades de alcance y cómo modificar la configuración de control de recursos en la máquina creada en tiempo de ejecución.

RegisterMachine() es similar a CreateMachine(). Sin embargo, solo registra una máquina y no crea una unidad de alcance para ella. En su lugar, se registra la unidad del llamante. Recomendamos usar este método solo para gestores de contenedores o VM que se ejecutan varias veces, una instancia para cada contenedor/VM que gestionan, y se invocan como servicios del sistema.

CreateMachineWithNetwork() y RegisterMachineWithNetwork() son similares a CreateMachine() y RegisterMachine() pero toman un argumento adicional: una matriz de índices de interfaz de red que apuntan a la máquina virtual o contenedor. Los índices de interfaz deben hacer referencia a una o más interfaces de red en el host que se pueden usar para comunicarse con el invitado. Comúnmente, el índice de interfaz pasado se refiere al lado del host de un enlace "veth" (en el caso de contenedores), un enlace "tun"/"tap" (en el caso de VM) o el lado del host de una interfaz de puente que conecta el acceso a las interfaces de la VM/ contenedor. Especificar esta información es útil para habilitar el soporte para la comunicación IPv6 de enlace local a las máquinas, ya que el campo de alcance de sockaddr_in6 puede ser inicializado por el ifindex especificado. nss-mymachines(8) utiliza esta información.

KillMachine() envía una señal UNIX a los procesos de la máquina. Como argumentos, toma el nombre de la máquina (tal como se pasó originalmente a CreateMachine() o se devolvió de ListMachines()), un identificador que especifica qué enviar exactamente a la señal (ya sea "leader" o "all"), y un entero de señal UNIX numérico.

TerminateMachine() termina una máquina virtual, matando sus procesos. Toma el nombre de la máquina como único argumento.

GetMachineAddresses() recupera las direcciones IP de un contenedor. Este método devuelve una matriz de pares que consisten en un especificador de familia de direcciones (AF_INET o AF_INET6) y una matriz de bytes que contiene las direcciones. Esto solo es compatible con contenedores que utilizan la asignación de nombres de red.

GetMachineSSHInfo() recupera la información SSH de una máquina. Este método devuelve dos cadenas, la dirección SSH que se puede usar para indicar a SSH dónde conectarse, y la ruta a la clave privada SSH requerida para que la conexión tenga éxito.

GetMachineOSRelease() recupera la información de la versión del sistema operativo de un contenedor. Este método devuelve una matriz de pares clave-valor leídos del archivo os-release(5) en el contenedor y es útil para identificar el sistema operativo utilizado en un contenedor.

OpenMachinePTY() asigna una pseudo TTY en el contenedor y devuelve un descriptor de archivo y su ruta. Esto es equivalente a la transición al contenedor y la invocación de posix_openpt(3).

OpenMachineLogin() asigna una pseudo TTY en el contenedor y asegura que un prompt de inicio de sesión getty del contenedor se esté ejecutando en el otro extremo. Devuelve el descriptor de archivo de la PTY y la ruta de la PTY. Esto es útil para obtener una PTY con un prompt de inicio de sesión del contenedor.

OpenMachineShell() asigna una pseudo TTY en el contenedor, como el usuario especificado, e invoca el ejecutable en la ruta especificada con una lista de argumentos (comenzando desde argv[0]) y un bloque de entorno. Luego devuelve el descriptor de archivo de la PTY y la ruta de la PTY.

BindMountMachine() monta enlazado un archivo o directorio desde el host al contenedor. Sus argumentos consisten en el nombre de la máquina, el directorio de origen en el host, el directorio de destino en el contenedor y dos booleanos, uno que indica si el montaje enlazado debe ser de solo lectura, el otro que indica si el punto de montaje de destino debe crearse primero, si falta.

CopyFromMachine() copia archivos o directorios desde un contenedor al host. Toma el nombre del contenedor, un directorio de origen en el contenedor y un directorio de destino en el host como argumentos. CopyToMachine() hace lo contrario y copia archivos desde un directorio de origen en el host a un directorio de destino en el contenedor. CopyFromMachineWithFlags() y CopyToMachineWithFlags() hacen lo mismo pero toman un argumento de flags adicional.

RemoveImage() elimina la imagen con el nombre especificado.

RenameImage() renombra la imagen especificada.

CloneImage() clona la imagen especificada con un nuevo nombre. También toma un argumento booleano que indica si la imagen resultante debe ser de solo lectura o no.

MarkImageReadOnly() cambia el flag de solo lectura de una imagen.

SetPoolLimit() establece un límite de cuota general en el pool de imágenes.

SetImageLimit() establece un límite de cuota por imagen.

MapFromMachineUser(), MapToMachineUser(), MapFromMachineGroup() y MapToMachineGroup() pueden usarse para mapear UIDs/GIDs del espacio de nombres de usuario del host a un espacio de nombres de usuario del contenedor o viceversa.

Señales

MachineNew() y MachineRemoved() se envían cada vez que se registra o elimina una nueva máquina. Estas señales transportan el nombre de la máquina y la ruta del objeto a la interfaz org.freedesktop.machine1.Machine correspondiente (ver abajo).

Propiedades

PoolPath especifica la ruta del sistema de archivos donde se escriben las imágenes.

PoolUsage especifica el tamaño de uso actual del pool de imágenes en bytes.

PoolLimit especifica el límite de tamaño del pool de imágenes en bytes.

NAME

org.freedesktop.machine1 - machine management

INTRODUCTION

This document describes the D-Bus API of the systemd machined daemon. See systemd-machined.service(8) for a higher-level overview.

The primary object is /org/freedesktop/machine1, implementing the org.freedesktop.machine1.Manager interface.

Objects implementing the org.freedesktop.machine1.Machine interface represent individual machines. The paths are of the form /org/freedesktop/machine1/machine/<name>.

Name is the unique name of the machine. This is the same name used in the object path of the machine. (The name is typically a path component, e.g. "rawhide".)

Class is the class of the machine and is either the string "vm" (for real VMs based on virtualized hardware) or "container" (for lightweight userspace virtualization sharing the same kernel as the host).

Leader is the PID of the leader process of the machine. (The leader process is the top-level process of the payload of the machine, i.e. for containers PID 1 inside the container, and for VMs the process encapsulating the VM. Its lifetime defines the lifetime of the machine.)

LeaderPIDFDId encodes the Linux pidfd inode ID of the leader process of the machine.

Supervisor is the PID of the supervisor process of the machine. (The supervisor process is the process that manages the machine, if there's a separate one for it. A supervisor process is not always defined, and does not define the machine's lifetime.)

SupervisorPIDFDId encodes the Linux pidfd inode ID of the supervisor process of the machine.

RootDirectory is the root directory of the container if it is known and applicable or the empty string.

NetworkInterfaces contains an array of network interface indices that point towards the container, the VM or the host. For details about this information see the description of CreateMachineWithNetwork() above.

VSockCID is the VSOCK CID of the VM if it is known, or VMADDR_CID_ANY otherwise.

SSHAddress is the address of the VM in a format ssh can understand if it is known or the empty string.

SSHPrivateKeyPath is the path to the SSH private key of the VM if it is known or the empty string.

State is the state of the machine and is one of "opening", "running", or "closing". Note that the state machine is not considered part of the API and states might be removed or added without this being considered API breakage.

Subgroup contains the sub-control-group path this machine's processes reside in, relative to the specified unit's control group.

UID contains the numeric UNIX UID of the user who registered the machine.
