NOMBRE

ovdb_init - Prepara la base de datos ovdb para su uso

SINOPSIS

ovdb_init [-r|-u]

DESCRIPCIÓN

Este comando debe ejecutarse antes de que cualquier otro proceso pueda acceder a la base de datos de vistas generales. ovdb_init se invoca normalmente de forma automática con rc.news al iniciar el sistema de noticias.

ovdb_init realiza los siguientes pasos:

1.
Crea el entorno de la base de datos, si es necesario.
2.
Si la base de datos está inactiva (y si no se especifica la opción -u), realiza una recuperación normal. La recuperación eliminará bloqueos obsoletos, recreará la caché del grupo de memoria y reparará cualquier daño causado por un fallo del sistema o un apagado incorrecto.
3.
Si se especifica la opción -u, realiza las actualizaciones necesarias en la base de datos. Consulte la sección "ACTUALIZACIÓN" más abajo.
4.
Inicia los procesos de mantenimiento de la base de datos (ovdb_monitor) si no están ya en ejecución. (A menos que se especifique la opción -r.)
5.
Inicia los procesos del servidor de lectura de ovdb (ovdb_server) si readserver en ovdb.conf es verdadero, y si no están ya en ejecución. (A menos que se especifique la opción -r.)

Devuelve el estado de salida 0 si todos los pasos se completaron con éxito. En caso de error, los mensajes se escriben en syslog y/o en la salida de error estándar.

Si se intentó una recuperación pero falló, la base de datos puede estar dañada e irrecuperable, requiriendo una reconstrucción con makehistory.

Este comando se puede ejecutar varias veces.

OPCIONES

-r
Realiza solo la recuperación. No se inicia ovdb_monitor.
-u
Realiza las actualizaciones necesarias. No se intenta la recuperación. Se inicia ovdb_monitor si la actualización tuvo éxito.

Esta opción se puede usar incluso si no se necesitan actualizaciones.

ACTUALIZACIÓN

Hay dos situaciones en las que la base de datos necesitará ser actualizada:

  • Actualizas la biblioteca Berkeley DB a una versión más nueva, por ejemplo, de 2.7.7 a 3.1.17. En este caso, se utiliza el método de Berkeley DB "db->upgrade()".
  • Actualizas ovdb a una versión principal más nueva; es decir, de ovdb-1.0 (incluido en INN 2.3.0 hasta INN 2.3.5) a ovdb-2.0 (desde INN 2.4.0).

En ambos casos, la base de datos se actualiza in situ; y la actualización no se puede deshacer. No interrumpas el proceso de actualización una vez que haya comenzado, ya que existe el riesgo de corrupción irreparable. La actualización puede tardar varios minutos en completarse. Si una actualización se interrumpe, intenta ejecutarla de nuevo.

Aquí tienes un ejemplo de procedimiento para actualizar una base de datos creada con Berkeley DB 2.7.7 para usar Berkeley DB 3.1.17:

1.
Compila e instala la versión de Berkeley DB 3.1.17;
2.
Ejecuta configure en el árbol de fuentes de INN y asegúrate de que selecciona el directorio correcto de Berkeley DB (por ejemplo, /usr/local/BerkeleyDB.3.1);
3.
Realiza un "make";
4.
Detén INN (por ejemplo, con "rc.news stop") y asegúrate de matar también todas las instancias de nnrpd;
5.
Realiza un "make update" para instalar los nuevos binarios;
6.
Ejecuta "ovdb_init -u" como usuario de noticias;
7.
Inicia INN con el comando "rc.news".
