OID2NAME(1) Documentación de PostgreSQL 18.1 OID2NAME(1)

NOMBRE

oid2name - resuelve OIDs y nodos de archivo en un directorio de datos de PostgreSQL

SINOPSIS

oid2name [opción...]

DESCRIPCIÓN

oid2name es un programa utilitario que ayuda a los administradores a examinar la estructura de archivos utilizada por PostgreSQL. Para hacer uso de él, necesitas estar familiarizado con la estructura de archivos de la base de datos, la cual se describe en el Capítulo 66.


Nota

El nombre “oid2name” es histórico y, de hecho, es bastante engañoso, ya que la mayoría de las veces que lo utilices, te interesarán los números de filenode de las tablas (que son los nombres de archivo visibles en los directorios de la base de datos). ¡Asegúrate de entender la diferencia entre los OIDs de las tablas y los filenodes de las tablas!

oid2name se conecta a una base de datos objetivo y extrae información de OID, filenode y/o nombre de tabla. También puedes hacer que muestre OIDs de bases de datos u OIDs de tablespaces.

OPCIONES

oid2name acepta los siguientes argumentos de línea de comandos:

-f filenode
--filenode=filenode

muestra información para la tabla con filenode filenode.

-i
--indexes

incluye índices y secuencias en la lista.

-o oid
--oid=oid

muestra información para la tabla con OID oid.

-q
--quiet

omite las cabeceras (útil para scripts).

-s
--tablespaces

muestra OIDs de tablespaces.

-S
--system-objects

incluye objetos del sistema (aquellos en los esquemas information_schema, pg_toast y pg_catalog).

-t patrón_nombretabla
--table=patrón_nombretabla

muestra información para tabla(s) que coinciden con patrón_nombretabla.

-V
--version

Imprime la versión de oid2name y sale.

-x
--extended

muestra información adicional sobre cada objeto: nombre de tablespace, nombre de esquema y OID.

-?
--help

Muestra ayuda sobre los argumentos de línea de comandos de oid2name y sale.

oid2name también acepta los siguientes argumentos de línea de comandos para parámetros de conexión:

-d database
--dbname=database

base de datos a la que conectarse.

-h host
--host=host

host del servidor de base de datos.

-H host

host del servidor de base de datos. El uso de este parámetro está obsoleto a partir de PostgreSQL 12.

-p port
--port=port

puerto del servidor de base de datos.

-U username
--username=username

nombre de usuario para conectarse como.

Para mostrar tablas específicas, selecciona qué tablas mostrar usando -o, -f y/o -t. -o toma un OID, -f toma un filenode y -t toma un nombre de tabla (en realidad, es un patrón LIKE, por lo que puedes usar cosas como foo%). Puedes usar tantas de estas opciones como quieras, y la lista incluirá todos los objetos que coincidan con cualquiera de las opciones. Pero ten en cuenta que estas opciones solo pueden mostrar objetos en la base de datos dada por -d.

Si no proporcionas ninguna de -o, -f o -t, pero sí proporcionas -d, listará todas las tablas en la base de datos nombrada por -d. En este modo, las opciones -S e -i controlan qué se lista.

Si tampoco proporcionas -d, mostrará una lista de OIDs de bases de datos. Alternativamente, puedes proporcionar -s para obtener una lista de tablespaces.

MEDIO AMBIENTE

PGHOST
PGPORT
PGUSER

Parámetros de conexión por defecto.

Esta utilidad, como la mayoría de las otras utilidades de PostgreSQL, también utiliza las variables de entorno soportadas por libpq (ver Sección 32.15).

La variable de entorno PG_COLOR especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son siempre, automático y nunca.

NOTAS

oid2name requiere un servidor de base de datos en ejecución con catálogos del sistema no corruptos. Por lo tanto, su utilidad es limitada para recuperarse de situaciones de corrupción catastrófica de la base de datos.

EJEMPLOS

$ # ¿qué hay en este servidor de bases de datos, de todos modos?
$ oid2name

$ ls -lS * | head -10

$ # Oh, ¿qué era la base de datos 17228 de nuevo?

  Filenode  Nombre Tabla

oid2name - translate OIDs to names

NAME

oid2name - translate OIDs to names

SYNOPSIS

oid2name [-d] [-I initial_oid] [-n name] [-o oid] [-p path] [-S separator] [-v] [oid ...]

DESCRIPTION

oid2name is a utility to translate Object Identifiers (OIDs) to symbolic names. It can also translate names back to OIDs. oid2name can traverse OID trees. It may also be useful for finding OIDs that are related to a given OID or name.

The OID database is searched in the directory specified by the environment variable $OID2NAME_DB, or by the default directory /usr/share/oid2name. The database consists of text files with OID definitions. The format of these files is described in oid2name.conf(5).

OPTIONS

-d
Dump the entire OID database. This option is mainly intended for debugging purposes.
-I initial_oid
Start the OID tree traversal at initial_oid. This option is only useful in conjunction with the -n or -o options.
-n name
Translate the symbolic name name to its corresponding OID. If name is an OID, it is translated to its symbolic name. This option is only useful if you want to translate a single name or OID. If you want to translate multiple names or OIDs, you can provide them as arguments.
-o oid
Translate the OID oid to its symbolic name. This option is only useful if you want to translate a single OID. If you want to translate multiple OIDs, you can provide them as arguments.
-p path
Search for OID definitions in the specified directory path instead of the default directory.
-S separator
Use separator as the separator between OID components when printing OIDs. The default separator is a dot (.).
-v
Print the version of oid2name and exit.

ENVIRONMENT

$OID2NAME_DB
Specifies the directory containing the OID database files. If not set, the default directory /usr/share/oid2name is used.

NOTES

The default OID database directory is /usr/share/oid2name. This directory contains text files with OID definitions. The format of these files is described in oid2name.conf(5).

EXAMPLES

Translate an OID to its name:

oid2name 1.3.6.1.2.1.1.1.0

Translate a name to its OID:

oid2name -n sysDescr.0

Start traversal from a specific OID:

oid2name -I 1.3.6.1.2.1.1 sysDescr.0

Use a different separator:

oid2name -S : 1.3.6.1.2.1.1.1.0
