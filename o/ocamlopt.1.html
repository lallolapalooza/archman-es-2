OCAMLOPT(1) Manual de Comandos Generales OCAMLOPT(1)

NOMBRE

ocamlopt - El compilador de código nativo de OCaml

SINOPSIS

ocamlopt [ opciones ] nombre_archivo ...

ocamlopt.opt (mismas opciones)

DESCRIPCIÓN

El compilador de código nativo de alto rendimiento de OCaml ocamlopt(1) compila archivos fuente de OCaml a archivos objeto de código nativo y enlaza estos archivos objeto para producir ejecutables independientes.

El comando ocamlopt(1) tiene una interfaz de línea de comandos muy similar a la de ocamlc(1). Acepta los mismos tipos de argumentos y los procesa secuencialmente, después de que todas las opciones hayan sido procesadas:

Los argumentos que terminan en .mli se consideran archivos fuente para interfaces de unidades de compilación. Las interfaces especifican los nombres exportados por las unidades de compilación: declaran nombres de valores con sus tipos, definen tipos de datos públicos, declaran tipos de datos abstractos, etc. Del archivo x.mli, el compilador ocamlopt(1) produce una interfaz compilada en el archivo x.cmi. La interfaz producida es idéntica a la producida por el compilador de bytecode ocamlc(1).

Los argumentos que terminan en .ml se consideran archivos fuente para implementaciones de unidades de compilación. Las implementaciones proporcionan definiciones para los nombres exportados por la unidad, y también contienen expresiones que se evaluarán por sus efectos secundarios. Del archivo x.ml, el compilador ocamlopt(1) produce dos archivos: x.o, que contiene código objeto nativo, y x.cmx, que contiene información adicional para enlazar y optimizar los clientes de la unidad. La implementación compilada debe referirse siempre bajo el nombre x.cmx (cuando se le da un archivo .o, ocamlopt(1) asume que contiene código compilado desde C, no desde OCaml).

La implementación se verifica contra el archivo de interfaz x.mli (si existe) como se describe en el manual de ocamlc(1).

Los argumentos que terminan en .cmx se consideran código objeto compilado. Estos archivos se enlazan juntos, junto con los archivos objeto obtenidos al compilar argumentos .ml (si los hay), y la biblioteca estándar de OCaml, para producir un programa ejecutable de código nativo. El orden en que los argumentos .cmx y .ml se presentan en la línea de comandos es relevante: las unidades de compilación se inicializan en ese orden en tiempo de ejecución, y es un error en tiempo de enlace usar un componente de una unidad antes de haberla inicializado. Por lo tanto, un archivo x.cmx dado debe preceder a todos los archivos .cmx que hagan referencia a la unidad x.

Los argumentos que terminan en .cmxa se consideran bibliotecas de código objeto. Dicha biblioteca empaqueta en dos archivos lib.cmxa y lib.a un conjunto de archivos objeto (.cmx/.o). Las bibliotecas se construyen con ocamlopt -a (ver la descripción de la opción -a más abajo). Los archivos objeto contenidos en la biblioteca se enlazan como archivos .cmx regulares (ver arriba), en el orden especificado cuando se construyó la biblioteca. La única diferencia es que si un archivo objeto contenido en una biblioteca no se referencia en ningún lugar del programa, entonces no se enlaza.

Los argumentos que terminan en .c se pasan al compilador C, que genera un archivo objeto .o. Este archivo objeto se enlaza con el programa.

Se asume que los argumentos que terminan en .o o .a son archivos objeto y bibliotecas C. Se enlazan con el programa.

La salida de la fase de enlace es un archivo ejecutable Unix regular. No necesita ocamlrun(1) para ejecutarse.

ocamlopt.opt es el mismo compilador que ocamlopt, pero compilado consigo mismo en lugar de con el compilador de bytecode ocamlc(1). Por lo tanto, se comporta exactamente como ocamlopt, pero compila más rápido. ocamlopt.opt no está disponible en todas las instalaciones de OCaml.

OPCIONES

Las siguientes opciones de línea de comandos son reconocidas por ocamlopt(1).

-a
Construye una biblioteca (.cmxa/.a) con los archivos objeto (.cmx/.o) proporcionados en la línea de comandos, en lugar de enlazarlos en un archivo ejecutable. El nombre de la biblioteca debe establecerse con la opción -o.

Si se pasan las opciones -cclib o -ccopt en la línea de comandos, estas opciones se almacenan en la biblioteca .cmxa resultante. Luego, enlazar con esta biblioteca añade automáticamente las opciones -cclib y -ccopt como si se hubieran proporcionado en la línea de comandos, a menos que se dé la opción -noautolink. Adicionalmente, una subcadena $CAMLORIGIN dentro de una opción -ccopt será reemplazada por la ruta completa a la biblioteca .cma, excluyendo el nombre del archivo.

-absname
Muestra nombres de archivo absolutos en mensajes de error.
-no-absname
No intentes mostrar nombres de archivo absolutos en mensajes de error.
-annot
Obsoleto desde OCaml 4.11. Por favor, usa -bin-annot en su lugar.
-bin-annot
Vuelca información detallada sobre la compilación (tipos, enlaces, llamadas en cola, etc.) en formato binario. La información para el archivo src.ml se coloca en el archivo src.cmt. En caso de error de tipo, vuelca toda la información inferida por el verificador de tipos antes del error. Los archivos de anotación producidos por -bin-annot contienen más información y son mucho más compactos que los archivos producidos por -annot.
-c
Solo compilar. Suprime la fase de enlace de la compilación. Los archivos de código fuente se convierten en archivos compilados, pero no se produce ningún archivo ejecutable. Esta opción es útil para compilar módulos por separado.
-cc ccomp
Usa ccomp como enlazador C llamado para construir el ejecutable final y como compilador C para compilar archivos fuente .c.
-cclib -lnombre_lib
Pasa la opción -lnombre_lib al enlazador. Esto hace que la biblioteca C dada se enlace con el programa.
-ccopt opción
Pasa la opción dada al compilador C y al enlazador. Por ejemplo, -ccopt -Ldir hace que el enlazador C busque bibliotecas C en el directorio dir.
-color modo
Habilita o deshabilita los colores en los mensajes del compilador (especialmente advertencias y errores). Los siguientes modos son compatibles:

auto usa heurísticas para habilitar colores solo si la salida los soporta (una terminal tty compatible con ANSI);

always habilita colores incondicionalmente;

never deshabilita la salida en color.

Se considera la variable de entorno "OCAML_COLOR" si no se proporciona -color. Sus valores son auto/always/never como se indicó anteriormente.

Si no se proporciona -color, "OCAML_COLOR" no está configurado y la variable de entorno "NO_COLOR" está configurada, entonces la salida en color está deshabilitada. De lo contrario, la configuración predeterminada es auto, y la heurística actual verifica que la variable de entorno "TERM" exista y no esté vacía o sea "dumb", y que isatty(stderr) sea verdadero.

-error-style modo
Controla la forma en que se imprimen los mensajes de error y las advertencias. Los siguientes modos son compatibles:

short solo imprime el error y su ubicación;

contextual como "short", pero también muestra el fragmento de código fuente correspondiente a la ubicación del error.

La configuración predeterminada es contextual.

Se considera la variable de entorno "OCAML_ERROR_STYLE" si no se proporciona -error-style. Sus valores son short/contextual como se indicó anteriormente.

-compact
Optimiza el código producido para el espacio en lugar del tiempo. Esto da como resultado programas más pequeños pero ligeramente más lentos. El valor predeterminado es optimizar para la velocidad.
-config
Imprime el número de versión de ocamlopt(1) y un resumen detallado de su configuración, y luego sale.
-config-var
Imprime el valor de una variable de configuración específica de la salida de -config, luego sale. Si la variable no existe, el código de salida es distinto de cero.
-depend ocamldep-args
Calcula las dependencias, como lo haría ocamldep.
-for-pack module-path
Genera un archivo objeto (.cmx y .o) que posteriormente puede ser incluido como un submódulo (con la ruta de acceso dada) de una unidad de compilación construida con -pack. Por ejemplo, ocamlopt -for-pack P -c A.ml generará los archivos a.cmx y a.o que posteriormente se pueden usar con ocamlopt -pack -o P.cmx a.cmx.
-g
Agrega información de depuración durante la compilación y el enlazado. Esta opción es necesaria para producir rastreos de pila cuando el programa termina con una excepción no capturada (ver ocamlrun(1)).
-no-g
No registra información de depuración (por defecto).
-i
Hace que el compilador imprima todos los nombres definidos (con sus tipos inferidos o sus definiciones) al compilar una implementación (.ml). No se producen archivos compilados (.cmo y .cmi). Esto puede ser útil para verificar los tipos inferidos por el compilador. Además, dado que la salida sigue la sintaxis de las interfaces, puede ayudar a escribir una interfaz explícita (.mli) para un archivo: simplemente redirige la salida estándar del compilador a un archivo .mli, y edita ese archivo para eliminar todas las declaraciones de nombres no exportados.
-cmi-file filename
Verifica el tipo de la implementación fuente a compilar contra el archivo de interfaz especificado (omite la búsqueda normal de archivos .mli y .cmi).
-I directory
Agrega el directorio dado a la lista de directorios buscados para archivos de interfaz compilados (.cmi), archivos de código objeto compilado (.cmx), y bibliotecas (.cmxa). Por defecto, se busca primero el directorio actual, luego el directorio de la biblioteca estándar. Los directorios agregados con -I se buscan después del directorio actual, en el orden en que se proporcionaron en la línea de comandos, pero antes del directorio de la biblioteca estándar. Ver también la opción -nostdlib.

Si el directorio dado comienza con +, se toma relativo al directorio de la biblioteca estándar. Por ejemplo, -I +compiler-libs agrega el subdirectorio compiler-libs de la biblioteca estándar a la ruta de búsqueda.

-impl filename
Compila el archivo filename como un archivo de implementación, incluso si su extensión no es .ml.
-inline n
Establece la agresividad de la inlining a n, donde n es un entero positivo. Especificar -inline 0 evita que todas las funciones se inserten en línea, excepto aquellas cuyo cuerpo es más pequeño que el sitio de la llamada. Por lo tanto, la inlining no causa expansión en el tamaño del código. La agresividad por defecto, -inline 1, permite que funciones un poco más grandes se inserten en línea, lo que resulta en una ligera expansión del tamaño del código. Valores más altos para la opción -inline hacen que funciones cada vez más grandes sean candidatas a la inlining, pero pueden resultar en un aumento considerable del tamaño del código.
-insn-sched
Habilita el paso de programación de instrucciones en el backend del compilador.
-intf filename
Compila el archivo filename como un archivo de interfaz, incluso si su extensión no es .mli.
-intf-suffix string
Reconoce los nombres de archivo que terminan en string como archivos de interfaz (en lugar del valor predeterminado .mli).
-keep-docs
Conserva las cadenas de documentación en los archivos .cmi generados.
-keep-locs
Conserva las ubicaciones en los archivos .cmi generados.
-labels
Las etiquetas no se ignoran en los tipos, las etiquetas se pueden usar en aplicaciones y los parámetros etiquetados se pueden dar en cualquier orden. Esto es lo predeterminado.
-linkall
Fuerza el enlace de todos los módulos contenidos en las bibliotecas. Si no se proporciona esta bandera, los módulos no referenciados no se enlazan. Al construir una biblioteca (bandera -a), establecer la bandera -linkall fuerza que todos los enlaces posteriores de programas que involucren esa biblioteca enlacen todos los módulos contenidos en la biblioteca. Al compilar un módulo (opción -c), establecer la opción -linkall asegura que este módulo siempre se enlazará si se coloca en una biblioteca y esta biblioteca se enlaza.
-linscan
Utiliza asignación de registros por escaneo lineal. Compilar con este asignador es más rápido que con el asignador habitual de coloración de grafos, a veces drásticamente más rápido para funciones y módulos largos. Por otro lado, el código generado puede ser un poco más lento.
-match-context-rows
Establece el número de filas de contexto utilizadas durante la compilación de coincidencia de patrones. Valores más bajos causan una compilación más rápida, pero un código menos optimizado. El valor predeterminado es 32.
-no-alias-deps
No registra dependencias para alias de módulo.
-no-app-funct
Desactiva el comportamiento aplicativo de los functores. Con esta opción, cada aplicación de functor genera nuevos tipos en su resultado y aplicar el mismo functor dos veces al mismo argumento produce dos estructuras incompatibles.
-noassert
No compila las verificaciones de aserción. Tenga en cuenta que la forma especial assert false siempre se compila porque está tipada especialmente. Esta bandera no tiene efecto al enlazar archivos ya compilados.
-noautolink
Al enlazar bibliotecas .cmxa, ignora las opciones -cclib y -ccopt potencialmente contenidas en las bibliotecas (si estas opciones se proporcionaron al construir las bibliotecas). Esto puede ser útil si una biblioteca contiene especificaciones incorrectas de bibliotecas C u opciones C; en este caso, durante el enlace, establezca -noautolink y pase las bibliotecas y opciones C correctas en la línea de comandos.
-nodynlink
Permite que el compilador utilice algunas optimizaciones que solo son válidas para código que nunca se enlaza dinámicamente.
-no-insn-sched
Deshabilita el paso de programación de instrucciones en el backend del compilador.
-nostdlib
No agrega automáticamente el directorio de la biblioteca estándar a la lista de directorios buscados para archivos de interfaz compilados (.cmi), archivos de código objeto compilado (.cmx), y bibliotecas (.cmxa). Ver también la opción -I.
-nolabels
Ignora las etiquetas no opcionales en los tipos. Las etiquetas no se pueden usar en aplicaciones, y el orden de los parámetros se vuelve estricto.
-o exec-file
Especifica el nombre del archivo de salida producido por el enlazador. El nombre de salida predeterminado es a.out, siguiendo la tradición Unix. Si se proporciona la opción -a, especifica el nombre de la biblioteca producida. Si se proporciona la opción -pack, especifica el nombre del archivo objeto empaquetado producido. Si se proporciona la opción -output-obj, especifica el nombre del archivo de salida producido. Si se proporciona la opción -shared, especifica el nombre del archivo plugin producido. Esto también se puede usar al compilar un archivo de interfaz o implementación, sin enlazar, en cuyo caso establece el nombre del archivo cmi o cmo, y también establece el nombre del módulo al nombre del archivo hasta el primer punto.
-opaque
Al compilar un archivo de interfaz .mli, esto tiene el mismo efecto que la opción -opaque del compilador de bytecode. Al compilar un archivo de implementación .ml, produce un archivo .cmx sin información de optimización entre módulos, lo que reduce la recompilación ante cambios en el módulo.
-open module
Abre el módulo dado antes de procesar los archivos de interfaz o implementación. Si se proporcionan varias opciones -open, se procesan en orden, como si las sentencias open! module1;; ... open! moduleN;; se agregaran al principio de cada archivo.
-output-obj
Hace que el enlazador produzca un archivo objeto C en lugar de un archivo ejecutable. Esto es útil para empaquetar código OCaml como una biblioteca C, invocable desde cualquier programa C. El nombre del archivo objeto de salida debe establecerse con la opción -o. Esta opción también se puede usar para producir una biblioteca compartida/dinámica compilada (.so). -output-complete-obj Igual que -output-obj excepto que el archivo objeto producido incluye las bibliotecas de tiempo de ejecución y autolink.
-pack
Construye un archivo objeto (.cmx y .o) y su interfaz compilada asociada (.cmi) que combina los archivos objeto .cmx proporcionados en la línea de comandos, haciéndolos aparecer como submódulos del archivo .cmx de salida. El nombre del archivo .cmx de salida debe proporcionarse con la opción -o. Por ejemplo, ocamlopt -pack -o P.cmx A.cmx B.cmx C.cmx genera los archivos compilados P.cmx, P.o y P.cmi que describen una unidad de compilación con tres submódulos A, B y C, correspondientes al contenido de los archivos objeto A.cmx, B.cmx y C.cmx. Estos contenidos se pueden referenciar como P.A, P.B y P.C en el resto del programa.

Los archivos objeto .cmx que se combinan deben haber sido compilados con la opción apropiada -for-pack. En el ejemplo anterior, A.cmx, B.cmx y C.cmx deben haber sido compilados con ocamlopt -for-pack P.

Se pueden lograr múltiples niveles de empaquetado combinando -pack con -for-pack. Ver El manual del usuario de OCaml, capítulo "Compilación de código nativo" para más detalles.

-pp command
Hace que el compilador llame al command dado como preprocesador.

OPTIONS FOR THE COMPILER

-A=cname=cvalue
Set the value of a C compiler or linker argument to cvalue. For example, -A=cc=gcc.

This option is intended for use with the -custom option. When using it with other options, the behavior is undefined.

-absname
Print absolute path names in diagnostics. This is the default.
-no-absname
Print file names relative to the current directory in diagnostics.
-a-tags
Generate Etags symbol files. Equivalent to ocamldep.

If you use this option, the compiler will generate an additional file filename.tags for each compiled file filename.ml.

-all-warnings
Enable all the warnings that are enabled by default. This is the default.
-annot
Print information about type annotations in diagnostics. This is the default.
-no-annot
Do not print information about type annotations in diagnostics.
-as-needed
When linking, only link against libraries that are required by the program. This option is passed to the linker. This is the default.

This option is only supported on systems that use GNU ld. It is ignored on other systems.

-no-as-needed
Link against all libraries, even if they are not required by the program. This option is passed to the linker.
-bin-annot
Generate binary type information files (.cmt). This is the default.

This option is intended for use with the -opaque option.

-no-bin-annot
Do not generate binary type information files.
-c
Compile only, do not link. The generated object files will have the extension .cmo (for bytecode) or .cmx (for native code). This option can be used multiple times.
-cccommand
Use the specified C compiler and linker command command, instead of the default one. For example, -cc=gcc.

This option is intended for use with the -custom option.

-cclib-lname
Pass the C library option -lname to the C compiler and linker. For example, -cclib=-lm links the standard math library.

This option is intended for use with the -custom option.

-ccoptoptions
Pass the given options options to the C compiler and linker. For example, -ccopt=-g.

This option is intended for use with the -custom option.

-cflagsoptions
Pass the given options options to the C compiler. For example, -cflags=-O2.

This option is intended for use with the -custom option.

-classpath dir1:,dir2:...
Specify the directories where the compiler should look for compiled interface files (.cmi) and packed files (.cmi). Defaults to the current directory. The separators are : on Unix and ; on Windows.
-custom
Build a custom runtime system. This option is intended for use when embedding the OCaml interpreter into a larger C application. It requires the use of the -c, -cc, -cclib, and -ccopt options.

-custom is equivalent to -runtime-variant=c.

-dnum
Output debugging information into file num.ml. The meaning of num depends on the compiler internal representation. Currently, supported values are 1 to 11.
-debug
Turn on all debugging information. This is equivalent to -d=11.
-dtypes
Print the computed type for each value. This is the default.
-no-dtypes
Do not print the computed type for each value.
-depend
Print the dependencies of the compiler components. Equivalent to ocamldep.

If you use this option, the compiler will print the dependencies of the compiled file filename.ml in the standard output, in the format expected by make.

-for-module name
When compiling a compilation unit, assume it is part of a larger module named name. This is used to generate the .cmi file.

This option is used automatically by the ocamlbuild build system.

-for-pack name
When compiling a packed compilation unit, assume the pack is named name. This is used to generate the .cmi file.

This option is used automatically by the ocamlbuild build system.

-g
Add debugging information to the compiled code. This is useful for native code generation when using a debugger.
-i
Print the names of external modules (compilation dependencies) of the given files. This is equivalent to running ocamldep on the given files.

If you use this option, the compiler will print the dependencies of the compiled file filename.ml in the standard output, in the format expected by make.

-Idir
Add directory dir to the list of directories where the compiler searches for compiled interface files (.cmi). The default is the current directory. This option can be repeated.
-intf
Compile an interface file (.mli). This is the default.
-interp
Interpret the bytecode produced by the compiler. This is equivalent to invoking ocamlrun on the compiled program.
-intf-only
Compile an interface file (.mli), but do not generate object code.
-inline-alloc
Enable inlining of functions that allocate closures. This is the default.
-no-inline-alloc
Disable inlining of functions that allocate closures.
-inline-fail-value
Perform inlining of functions that may raise exceptions. This is the default.

Warning: This option may lead to incorrect behavior if the inlined function raises an exception that is caught by the caller.

-no-inline-fail-value
Do not perform inlining of functions that may raise exceptions.
-inline-globally
Enable global inlining. This is the default.

This option may lead to larger code size.

-no-inline-globally
Disable global inlining.
-inline-prim
Perform inlining of functions that may return polymorphic primitives. This is the default.

Warning: This option may lead to incorrect behavior if the inlined primitive is used in a context where its behavior is different.

-no-inline-prim
Do not perform inlining of functions that may return polymorphic primitives.
-inline-recursive
Perform inlining of recursive functions. This is the default.

This option may lead to larger code size and longer compilation times.

-no-inline-recursive
Do not perform inlining of recursive functions.
-inline-thresholdn
Set the inlining threshold to n. Functions smaller than n instructions are candidates for inlining. The default is 10.

This option has an effect only when inlining is enabled.

-intf
Compile an interface file (.mli). This is the default.
-intf-only
Compile an interface file (.mli), but do not generate object code.
-jn
Use n processes (threads, on Unix) to run the compiler. The default is to use a single process. This option can speed up compilation on multi-core machines. It is recommended to use a number of processes equal to the number of cores available.
-keep-locs
Keep source code locations in the compiled code. This is useful for debugging and profiling. This is the default for native code.
-no-keep-locs
Do not keep source code locations in the compiled code. This may reduce code size and improve performance.

This option is the default for bytecode.

-labels
Generate code that uses labels for function arguments. This is the default.

This option is intended for use with the -nodynlink option.

-legacy-heap
Use the legacy heap implementation. This is the default.

The legacy heap is slower but more compatible with older OCaml versions.

-no-legacy-heap
Use the new heap implementation. This is faster but may not be compatible with older OCaml versions.
-linkall
Link all modules, even those that are not used. This is the default.

This option is intended for use with the -nodynlink option.

-link-runtime-obj
Link the runtime system object file (.o) into the executable. This is the default.

This option is intended for use with the -custom option.

-make-runtime
Build a custom runtime system. This is the default.

This option is intended for use with the -custom option.

-make-runtime-unsafe
Build a custom runtime system without safety checks. This is the default.

This option is intended for use with the -custom option.

-ml-words
Print the number of words used by each module. This is the default.
-no-ml-words
Do not print the number of words used by each module.
-modules
Generate a .cmxa or .cmxs file that contains all modules, even those that are not explicitly exported. This is the default.

This option is intended for use with the -nodynlink option.

-native-robust
Generate code that is more robust to runtime errors. This is the default.
-no-native-robust
Generate code that is less robust to runtime errors. This may improve performance.
-native-stack-overflow
Enable stack overflow detection for native code. This is the default.

This option can slow down native code execution.

-no-native-stack-overflow
Disable stack overflow detection for native code. This may improve performance.
-no-check-prims
Disable checks for primitive operations. This is the default.

This option is intended for use with the -custom option.

-no-data-str-check
Disable runtime checks for data structure validity. This is the default.

This option is intended for use with the -custom option.

-no-float-strict-args
Disable strict argument checking for floating-point operations. This is the default.

This option is intended for use with the -custom option.

-no-generics
Disable support for generic modules. This is the default.

This option is intended for use with the -custom option.

-no-import-native-libs
Do not import native libraries. This is the default.

This option is intended for use with the -custom option.

-no-inline
Disable inlining of functions. This is the default.
-no-link-runtime-obj
Do not link the runtime system object file (.o) into the executable. This is the default.

This option is intended for use with the -custom option.

-no-punits
Disable support for polymorphic units. This is the default.

This option is intended for use with the -custom option.

-no-record-updates
Disable support for record updates. This is the default.

This option is intended for use with the -custom option.

-no-relax-dims
Disable relaxation of dimension checks. This is the default.

This option is intended for use with the -custom option.

-no-runtime-tables
Do not include runtime tables. This is the default.

This option is intended for use with the -custom option.

-no-safe-string
Allow strings to be mutated. This is not the default.

This option is intended for compatibility with older source code and should not be used with new software.

-no-smaller-intf
Do not generate smaller interface files. This is the default.

This option is intended for use with the -custom option.

-no-strict-seq
Allow sequences whose left-hand part does not have type unit. This is the default.

This option is intended for compatibility with older source code and should not be used with new software.

-no-super-recursion
Disable super recursion optimization. This is the default.
-no-tracking-width
Disable tracking of width of values. This is the default.

This option is intended for use with the -custom option.

-no-unbox-small-structs
Do not unbox small structures. This is the default.

This option is intended for use with the -custom option.

-no-unboxed-types
Box all types. This is the default.

This option is intended for compatibility with older source code and should not be used with new software.

-no-unit-locations
Do not generate unit locations. This is the default.

This option is intended for use with the -custom option.

-no-val-shadow
Disable value shadowing checks. This is the default.

This option is intended for use with the -custom option.

-no-width-optimized
Disable width optimization. This is the default.

This option is intended for use with the -custom option.

-nodynlink
Disable dynamic loading of compiled modules. This is the default.

This option is intended for use with the -custom option.

-nolabels
Generate code that does not use labels for function arguments. This option is intended for compatibility with older source code and should not be used with new software.

This option is intended for use with the -nodynlink option.

-nomutables
Disable support for mutable objects. This is the default.

This option is intended for use with the -custom option.

-nolocaldef
Disable local definition optimization. This is the default.
-nostdlib
Do not link the standard library. This is intended for use when embedding the OCaml interpreter into a larger C application.

This option is intended for use with the -custom option.

-ofile
Name the output file file. If this option is not given, the default name is a.out.

This option is intended for use with the -custom option.

-opaque
Compile modules in opaque mode. This means that the compiler will not look inside the module's implementation to optimize calls to it. This is useful for enforcing an interface and for improving compilation times.

This option is intended for use with the -bin-annot option.

-optimizen
Perform optimization level n. The levels are:
0:
No optimization.
1:
Basic optimization.
2:
More optimization.
3:
Even more optimization.
The default optimization level is 1. Levels 2 and 3 may significantly increase compilation time.

Note that the native code compiler performs more optimizations than the bytecode compiler.

-output-complete-ir
Output a complete intermediate representation after the given pass. The supported passes are: scheduling.

This option is intended for use with the -save-ir-after option.

-p
Generate profiling information for function calls. This produces an x.prof file for each compiled file x.ml.

This option is intended for use with the gprof tool.

-packname
Pack the modules in the given compilation units into a single compilation unit named name. The packed compilation unit will have the extension .cmx (for native code) or .cmo (for bytecode).

This option is intended for use with the -for-pack option.

-Pfilename
Add filename to the list of preprocessors to be used. The preprocessor is invoked as follows: for each source file, the preprocessor is executed, and its output is redirected to an intermediate file, which is then compiled. If there are no compilation errors, the intermediate file is deleted afterwards.
-ppxcommand
After parsing, pipe the abstract syntax tree through the preprocessor command. The module Ast_mapper(3) implements the external interface of a preprocessor.
-principal
Check information path during type-checking, to make sure that all types are derived in a principal way. All programs accepted in -principal mode are also accepted in default mode with equivalent types, but different binary signatures.
-no-principal
Do not check principality of type inference. This is the default.
-rectypes
Allow arbitrary recursive types during type-checking. By default, only recursive types where the recursion goes through an object type are supported. Note that once you have created an interface using this flag, you must use it again for all dependencies.
-no-rectypes
Do no allow arbitrary recursive types during type-checking. This is the default.
-runtime-variantsuffix
Add suffix to the name of the runtime library that will be used by the program. If OCaml was configured with option -with-debug-runtime, then the d suffix is supported and gives a debug version of the runtime.
-S
Keep the assembly code produced during the compilation. The assembly code for the source file x.ml is saved in the file x.s.
-safe-string
Enforce the separation between types string and bytes, thereby making strings read-only. This is the default.
-safer-matching
Do not use type information to optimize pattern-matching. This allows to detect match failures even if a pattern-matching was wrongly assumed to be exhaustive. This only impacts GADT and polymorphic variant compilation.
-save-ir-afterpass
Save intermediate representation after the given compilation pass. The currently supported passes are: scheduling.
-shared
Build a plugin (usually .cmxs) that can be dynamically loaded with the Dynlink module. The name of the plugin must be set with the -o option. A plugin can include a number of OCaml modules and libraries, and extra native objects (.o, .a files). Building native plugins is only supported for some operating system. Under some systems (currently, only Linux AMD 64), all the OCaml code linked in a plugin must have been compiled without the -nodynlink flag. Some constraints might also apply to the way the extra native objects have been compiled (under Linux AMD 64, they must contain only position-independent code).
-short-paths
When a type is visible under several module-paths, use the shortest one when printing the type's name in inferred interfaces and error and warning messages.
-stop-afterpass
Stop compilation after the given compilation pass. The currently supported passes are: parsing, typing, scheduling, emit.
-strict-sequence
The left-hand part of a sequence must have type unit.
-no-strict-sequence
Left-hand part of a sequence need not have type unit. This is the default.
-unboxed-types
When a type is unboxable (i.e. a record with a single argument or a concrete datatype with a single constructor of one argument) it will be unboxed unless annotated with [@@ocaml.boxed].
-no-unboxed-types
When a type is unboxable it will be boxed unless annotated with [@@ocaml.unboxed]. This is the default.
-unsafe
Turn bound checking off for array and string accesses (the v.(i) and s.[i] constructs). Programs compiled with -unsafe are therefore faster, but unsafe: anything can happen if the program accesses an array or string outside of its bounds. Additionally, turn off the check for zero divisor in integer division and modulus operations. With -unsafe, an integer division (or modulus) by zero can halt the program or continue with an unspecified result instead of raising a Division_by_zero exception.
-unsafe-string
Identify the types string and bytes, thereby making strings writable. This is intended for compatibility with old source code and should not be used with new software.
-v
Print the version number of the compiler and the location of the standard library directory, then exit.
-verbose
Print all external commands before they are executed, in particular invocations of the assembler, C compiler, and linker.
-version or -vnum
Print the version number of the compiler in short form (e.g. "3.11.0"), then exit.
-wwarning-list
Enable, disable, or mark as fatal the warnings specified by the argument warning-list. See ocamlc(1) for the syntax of warning-list.
-warn-errorwarning-list
Mark as fatal the warnings specified in the argument warning-list. The compiler will stop with an error when one of these warnings is emitted. The warning-list has the same meaning as for the -w option: a + sign (or an uppercase letter) marks the corresponding warnings as fatal, a - sign (or a lowercase letter) turns them back into non-fatal warnings, and a @ sign both enables and marks as fatal the corresponding warnings.

Note: it is not recommended to use the -warn-error option in production code, because it will almost certainly prevent compiling your program with later versions of OCaml when they add new warnings or modify existing warnings.

The default setting is -warn-error -a (no warning is fatal).

-warn-help
Show the description of all available warning numbers.
-where
Print the location of the standard library, then exit.
-with-runtime
Include the runtime system in the generated program. This is the default.
-without-runtime
The compiler does not include the runtime system (nor a reference to it) in the generated program; it must be supplied separately.
- file
Process file as a file name, even if it starts with a dash (-) character.
-help or --help
Display a short usage summary and exit.

OPTIONS FOR THE FLAMBDA MIDDLE-END

When the Flambda code generator has been enabled at configuration time, its behavior may be tuned up with the following additional options:

-02
Perform more optimisation than usual. Compilation times may be lengthened.
-03
Perform even more optimisation than usual, possibly including unrolling of recursive functions. Compilation times may be significantly lengthened.
-Oclassic
Makes inlining decisions at the point of definition of a function rather than at the call site(s). This mirrors the behaviour of OCaml compilers not using Flambda. Compared to compilation using the new Flambda inlining heuristics (for example at -O2) it produces smaller .cmx files, shorter compilation times and code that probably runs rather slower.
-inlining-report
Emit .inlining files (one per round of optimisation) showing all of the inliner's decisions.

OPTIONS FOR THE AMD64 ARCHITECTURE

The AMD64 code generator (64-bit versions of Intel Pentium and AMD Athlon) supports the following additional options:

-fPIC
Generate position-independent machine code. This is the default.
-fno-PIC
Generate position-dependent machine code.
