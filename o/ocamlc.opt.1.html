OCAMLC(1) Manual de Comandos Generales OCAMLC(1)

NOMBRE

ocamlc - El compilador de bytecode de OCaml

SINOPSIS

ocamlc [ opciones ] archivo ...

ocamlc.opt [ opciones ] archivo ...

DESCRIPCIÓN

El compilador de bytecode de OCaml ocamlc(1) compila archivos fuente de OCaml a archivos objeto de bytecode y enlaza estos archivos objeto para producir archivos ejecutables de bytecode independientes. Estos archivos ejecutables son luego ejecutados por el intérprete de bytecode ocamlrun(1).

El comando ocamlc(1) tiene una interfaz de línea de comandos similar a la de la mayoría de los compiladores C. Acepta varios tipos de argumentos y los procesa secuencialmente, después de que se hayan procesado todas las opciones:

Los argumentos que terminan en .mli se toman como archivos fuente para interfaces de unidades de compilación. Las interfaces especifican los nombres exportados por las unidades de compilación: declaran nombres de valores con sus tipos, definen tipos de datos públicos, declaran tipos de datos abstractos, etc. Desde el archivo x.mli, el compilador ocamlc(1) produce una interfaz compilada en el archivo x.cmi.

Los argumentos que terminan en .ml se toman como archivos fuente para implementaciones de unidades de compilación. Las implementaciones proporcionan definiciones para los nombres exportados por la unidad, y también contienen expresiones que se evaluarán por sus efectos secundarios. Desde el archivo x.ml, el compilador ocamlc(1) produce un archivo objeto compilado en bytecode en el archivo x.cmo.

Si el archivo de interfaz x.mli existe, la implementación x.ml se verifica contra la interfaz compilada correspondiente x.cmi, que se supone que existe. Si no se proporciona ninguna interfaz x.mli, la compilación de x.ml produce un archivo de interfaz compilado x.cmi además del archivo de código objeto compilado x.cmo. El archivo x.cmi producido corresponde a una interfaz que exporta todo lo que se define en la implementación x.ml.

Los argumentos que terminan en .cmo se toman como bytecode de objeto compilado. Estos archivos se enlazan juntos, junto con los archivos objeto obtenidos al compilar argumentos .ml (si los hay), y la biblioteca estándar de OCaml, para producir un programa ejecutable de bytecode independiente. El orden en que se presentan los argumentos .cmo y .ml en la línea de comandos es relevante: las unidades de compilación se inicializan en ese orden en tiempo de ejecución, y es un error en tiempo de enlace usar un componente de una unidad antes de haberlo inicializado. Por lo tanto, un archivo x.cmo dado debe preceder a todos los archivos .cmo que se refieren a la unidad x.

Los argumentos que terminan en .cma se toman como bibliotecas de bytecode de objeto. Una biblioteca de bytecode de objeto agrupa en un solo archivo un conjunto de archivos de bytecode de objeto (.cmo files). Las bibliotecas se construyen con ocamlc -a (ver la descripción de la opción -a abajo). Los archivos objeto contenidos en la biblioteca se enlazan como archivos .cmo normales (ver arriba), en el orden especificado cuando se construyó el archivo .cma. La única diferencia es que si un archivo objeto contenido en una biblioteca no es referenciado en ningún lugar del programa, entonces no se enlaza.

Los argumentos que terminan en .c se pasan al compilador C, que genera un archivo objeto .o. Este archivo objeto se enlaza con el programa si se establece el indicador -custom (ver la descripción de -custom abajo).

Los argumentos que terminan en .o o .a se suponen que son archivos objeto C y bibliotecas. Se pasan al enlazador C al enlazar en modo -custom (ver la descripción de -custom abajo).

Los argumentos que terminan en .so se suponen que son bibliotecas compartidas C (DLLs). Durante el enlace, se buscan funciones C externas referenciadas desde el código OCaml, y sus nombres se escriben en el ejecutable de bytecode generado. El sistema en tiempo de ejecución ocamlrun(1) luego las carga dinámicamente en tiempo de inicio del programa.

La salida de la fase de enlace es un archivo que contiene bytecode compilado que puede ser ejecutado por el intérprete de bytecode OCaml: el comando ocamlrun(1). Si caml.out es el nombre del archivo producido por la fase de enlace, el comando ocamlrun caml.out arg1 arg2 ... argn ejecuta el código compilado contenido en caml.out, pasándole como argumentos las cadenas de caracteres arg1 a argn. (Ver ocamlrun(1) para más detalles.)

En la mayoría de los sistemas, el archivo producido por la fase de enlace se puede ejecutar directamente, como en: ./caml.out arg1 arg2 ... argn. El archivo producido tiene el bit ejecutable activado, y se las arregla para lanzar el intérprete de bytecode por sí mismo.

ocamlc.opt es el mismo compilador que ocamlc, pero compilado con el compilador de código nativo ocamlopt(1). Por lo tanto, se comporta exactamente como ocamlc, pero compila más rápido. Es posible que ocamlc.opt no esté disponible en todas las instalaciones de OCaml.

OPCIONES

Las siguientes opciones de línea de comandos son reconocidas por ocamlc(1).

-a
Construye una biblioteca (.cma file) con los archivos objeto (.cmo files) dados en la línea de comandos, en lugar de enlazarlos en un archivo ejecutable. El nombre de la biblioteca debe establecerse con la opción -o.
Si se pasan las opciones -custom, -cclib o -ccopt en la línea de comandos, estas opciones se almacenan en la biblioteca .cma resultante. Luego, el enlace con esta biblioteca añade automáticamente las opciones -custom, -cclib y -ccopt como si se hubieran proporcionado en la línea de comandos, a menos que se dé la opción -noautolink. Además, una subcadena $CAMLORIGIN dentro de una opción -ccopt se reemplazará por la ruta completa a la biblioteca .cma, excluyendo el nombre del archivo.
-absname
Mostrar nombres de archivo absolutos en mensajes de error.
-no-absname
No intentar mostrar nombres de archivo absolutos en mensajes de error.
-annot
Obsoleto desde 4.11. Por favor, use -bin-annot en su lugar.
-bin-annot
Volcar información detallada sobre la compilación (tipos, enlaces, llamadas en cola, etc.) en formato binario. La información para el archivo src.ml se coloca en el archivo src.cmt. En caso de error de tipo, volcar toda la información inferida por el verificador de tipos antes del error. Los archivos de anotación producidos por -bin-annot contienen más información y son mucho más compactos que los archivos producidos por -annot.
-c
Compilar solamente. Suprimir la fase de enlace de la compilación. Los archivos de código fuente se convierten en archivos compilados, pero no se produce ningún archivo ejecutable. Esta opción es útil para compilar módulos por separado.
-cc ccomp
Usar ccomp como enlazador C al enlazar en modo de "runtime personalizado" (ver la opción -custom) y como compilador C para compilar archivos fuente .c.
-cclib -llibname
Pasar la opción -llibname al enlazador C al enlazar en modo de "runtime personalizado" (ver la opción -custom). Esto hace que la biblioteca C dada se enlace con el programa.
-ccopt opción
Pasar la opción dada al compilador C y al enlazador, al enlazar en modo de "runtime personalizado" (ver la opción -custom). Por ejemplo, -ccopt -Ldir hace que el enlazador C busque bibliotecas C en el directorio dir.
-color modo
Habilitar o deshabilitar colores en los mensajes del compilador (especialmente advertencias y errores). Los siguientes modos son compatibles:

auto usa heurísticas para habilitar colores solo si la salida los soporta (una terminal tty compatible con ANSI);

always habilita colores incondicionalmente;

never deshabilita la salida de colores.

La variable de entorno "OCAML_COLOR" se considera si no se proporciona -color. Sus valores son auto/always/never como arriba.

Si no se proporciona -color, "OCAML_COLOR" no está establecido y la variable de entorno "NO_COLOR"

-error-style modo
Controla la forma en que se imprimen los mensajes de error y las advertencias. Los siguientes modos son compatibles:

short solo imprime el error y su ubicación;

contextual como "short", pero también muestra el fragmento de código fuente correspondiente a la ubicación del error.

La configuración predeterminada es contextual.

La variable de entorno "OCAML_ERROR_STYLE" se considera si no se proporciona -error-style. Sus valores son short/contextual como se describe arriba.

-compat-32
Comprueba que el ejecutable de bytecode generado pueda ejecutarse en plataformas de 32 bits y señala un error si no puede. Esto es útil al compilar bytecode en una máquina de 64 bits.
-config
Imprime el número de versión de ocamlc(1) y un resumen detallado de su configuración, y luego sale.
-config-var
Imprime el valor de una variable de configuración específica de la salida de -config, y luego sale. Si la variable no existe, el código de salida es distinto de cero.
-custom
Enlaza en modo de "runtime personalizado". En el modo de enlace predeterminado, el enlazador produce bytecode que está destinado a ser ejecutado con el sistema de runtime compartido, ocamlrun(1). En el modo de runtime personalizado, el enlazador produce un archivo de salida que contiene tanto el sistema de runtime como el bytecode del programa. El archivo resultante es más grande, pero se puede ejecutar directamente, incluso si el comando ocamlrun(1) no está instalado. Además, el modo "runtime personalizado" permite enlazar código OCaml con funciones C definidas por el usuario.

Nunca use el comando strip(1) en ejecutables producidos por ocamlc -custom, esto eliminaría la parte de bytecode del ejecutable.

Advertencia de seguridad: nunca establezca los bits de "setuid" o "setgid" en ejecutables producidos por ocamlc -custom, esto los haría vulnerables a ataques.

-depend ocamldep-args
Calcula las dependencias, como lo haría ocamldep.
-dllib -llibname
Organiza para que la biblioteca compartida C dlllibname.so sea cargada dinámicamente por el sistema de runtime ocamlrun(1) al inicio del programa.
-dllpath dir
Agrega el directorio dir a la ruta de búsqueda del runtime para bibliotecas C compartidas. En el momento del enlace, las bibliotecas compartidas se buscan en la ruta de búsqueda estándar (la que corresponde a la opción -I). La opción -dllpath simplemente almacena dir en el archivo ejecutable producido, donde ocamlrun(1) puede encontrarlo y usarlo.
-for-pack ruta-modulo
Genera un archivo objeto (.cmo) que posteriormente puede ser incluido como un sub-módulo (con la ruta de acceso dada) de una unidad de compilación construida con -pack. Por ejemplo, ocamlc -for-pack P -c A.ml generará a.cmo que posteriormente puede ser usado con ocamlc -pack -o P.cmo a.cmo. Nota: todavía puedes empaquetar un módulo que fue compilado sin -for-pack pero en ese caso las excepciones se imprimirán con nombres incorrectos.
-g
Agrega información de depuración al compilar y enlazar. Esta opción es requerida para poder depurar el programa con ocamldebug(1) y para producir rastreos de pila cuando el programa termina con una excepción no capturada.
-no-g
No registra información de depuración (predeterminado).
-i
Hace que el compilador imprima todos los nombres definidos (con sus tipos inferidos o sus definiciones) al compilar una implementación (.ml file). No se producen archivos compilados (.cmo y .cmi files). Esto puede ser útil para verificar los tipos inferidos por el compilador. Además, dado que la salida sigue la sintaxis de las interfaces, puede ayudar a escribir una interfaz explícita (.mli file) para un archivo: simplemente redirige la salida estándar del compilador a un archivo .mli, y edita ese archivo para eliminar todas las declaraciones de nombres no exportados.
-cmi-file nombre-archivo
Comprueba el tipo de la implementación fuente a compilar contra el archivo de interfaz especificado (omite la búsqueda normal de archivos .mli y .cmi).
-I directorio
Agrega el directorio dado a la lista de directorios buscados para archivos de interfaz compilados (.cmi), archivos de código objeto compilados (.cmo), bibliotecas (.cma) y bibliotecas C especificadas con -cclib -lxxx. Por defecto, se busca primero el directorio actual, luego el directorio de la biblioteca estándar. Los directorios agregados con -I se buscan después del directorio actual, en el orden en que se proporcionaron en la línea de comandos, pero antes del directorio de la biblioteca estándar. Ver también la opción -nostdlib.

Si el directorio dado comienza con +, se toma relativo al directorio de la biblioteca estándar. Por ejemplo, -I +compiler-libs agrega el subdirectorio compiler-libs de la biblioteca estándar a la ruta de búsqueda.

-impl nombre-archivo
Compila el archivo nombre-archivo como un archivo de implementación, incluso si su extensión no es .ml.
-intf nombre-archivo
Compila el archivo nombre-archivo como un archivo de interfaz, incluso si su extensión no es .mli.
-intf-suffix cadena
Reconoce los nombres de archivo que terminan en cadena como archivos de interfaz (en lugar del .mli predeterminado).
-keep-docs
Mantiene las cadenas de documentación en los archivos .cmi generados.
-keep-locs
Mantiene las ubicaciones en los archivos .cmi generados.
-keywords version+lista
Establece las palabras clave según la especificación version+lista.

Esta especificación comienza con un número de versión opcional, que define el conjunto base de palabras clave, seguido de una lista separada por + de palabras clave adicionales para agregar a este conjunto base. Sin un número de versión explícito, el conjunto base de palabras clave es el conjunto de palabras clave en la versión actual de OCaml. Las palabras clave adicionales que no coinciden con ninguna palabra clave conocida en la versión actual del lenguaje generan un error cada vez que están presentes en el código fuente.

-labels
Las etiquetas no se ignoran en los tipos, se pueden usar etiquetas en las aplicaciones, y los parámetros etiquetados se pueden proporcionar en cualquier orden. Este es el valor predeterminado.
-linkall
Fuerza que todos los módulos contenidos en las bibliotecas sean enlazados. Si esta bandera no se da, los módulos no referenciados no se enlazan. Al construir una biblioteca (opción -a), establecer la opción -linkall fuerza que todos los enlaces posteriores de programas que involucren esa biblioteca enlacen todos los módulos contenidos en la biblioteca. Al compilar un módulo (opción -c), establecer la opción -linkall asegura que este módulo siempre se enlaza si se coloca en una biblioteca y esta biblioteca se enlaza.
-make-runtime
Construye un sistema de runtime personalizado (en el archivo especificado por la opción -o) incorporando los archivos objeto C y las bibliotecas dadas en la línea de comandos. Este sistema de runtime personalizado puede ser usado posteriormente para ejecutar bytecode ejecutables producidos con la opción ocamlc -use-runtime nombre-runtime.
-match-context-rows
Establece el número de filas de contexto utilizadas durante la compilación de coincidencias de patrones. Valores más bajos causan una compilación más rápida, pero un código menos optimizado. El valor predeterminado es 32.
-no-alias-deps
No registra dependencias para alias de módulos.
-no-app-funct
Desactiva el comportamiento aplicativo de los functores. Con esta opción, cada aplicación de functor genera nuevos tipos en su resultado y aplicar el mismo functor dos veces al mismo argumento produce dos estructuras incompatibles.
-noassert
No compila las verificaciones de aserción. Tenga en cuenta que la forma especial assert false siempre se compila porque tiene un tipo especial. Esta bandera no tiene efecto al enlazar archivos ya compilados.
-noautolink
Al enlazar bibliotecas .cma, ignora las opciones -custom, -cclib y -ccopt potencialmente contenidas en las bibliotecas (si estas opciones se dieron al construir las bibliotecas). Esto puede ser útil si una biblioteca contiene especificaciones incorrectas de bibliotecas C u opciones C; en ese caso, durante el enlace, establezca -noautolink y pase las bibliotecas C y las opciones correctas en la línea de comandos.
-nolabels
Ignora etiquetas no opcionales en los tipos. Las etiquetas no se pueden usar en aplicaciones, y el orden de los parámetros se vuelve estricto.
-nostdlib
No agrega automáticamente el directorio de la biblioteca estándar a la lista de directorios buscados para archivos de interfaz compilados (.cmi), archivos de código objeto compilados (.cmo), bibliotecas (.cma) y bibliotecas C especificadas con -cclib -lxxx. Ver también la opción -I.
-o archivo-ejecutable
Especifica el nombre del archivo de salida producido por el enlazador. El nombre de salida predeterminado es a.out, de acuerdo con la tradición de Unix. Si se da la opción -a, especifica
si el nombre de la biblioteca producida. Si se da la opción -pack, especifica el nombre del archivo de objeto empaquetado producido. Si se da la opción -output-obj o -output-complete-obj, especifica el nombre del archivo de salida producido. Esto también se puede usar al compilar un archivo de interfaz o implementación, sin enlazar, en cuyo caso establece el nombre del archivo cmi o cmo, y también establece el nombre del módulo al nombre del archivo hasta el primer punto.
-opaque
Los archivos de interfaz compilados con esta opción se marcan de manera que otras unidades de compilación que dependan de ella no dependerán de ningún detalle de implementación de la implementación compilada. El compilador nativo no accederá al archivo .cmx de esta unidad, ni advertirá si está ausente. Esto puede mejorar la velocidad de compilación, tanto para compilaciones iniciales como incrementales, a expensas del rendimiento del código generado.
-open módulo
Abre el módulo dado antes de procesar los archivos de interfaz o implementación. Si se dan varias opciones -open, se procesan en orden, como si las sentencias open! module1;; ... open! moduleN;; se añadieran al principio de cada archivo.
-output-obj
Hace que el enlazador produzca un archivo de objeto C en lugar de un archivo ejecutable de bytecode. Esto es útil para empaquetar código OCaml como una biblioteca C, invocable desde cualquier programa C. El nombre del archivo de objeto de salida debe establecerse con la opción -o. Esta opción también se puede usar para producir un archivo fuente C (extensión .c) o una biblioteca compartida/dinámica compilada (extensión .so).
-output-complete-obj
Igual que -output-obj excepto al crear un archivo de objeto donde incluye la biblioteca de tiempo de ejecución y la biblioteca de autoinserción.
-pack
Crea un archivo de objeto de bytecode (.cmo) y su interfaz compilada asociada (.cmi) que combina los archivos de objeto dados en la línea de comandos, haciéndolos aparecer como submódulos del archivo .cmo de salida. El nombre del archivo .cmo de salida debe darse con la opción -o. Por ejemplo, ocamlc -pack -o p.cmo a.cmo b.cmo c.cmo genera los archivos compilados p.cmo y p.cmi que describen una unidad de compilación con tres submódulos A, B y C, correspondientes al contenido de los archivos de objeto a.cmo, b.cmo y c.cmo. Estos contenidos se pueden referenciar como P.A, P.B y P.C en el resto del programa.
-pp comando
Hace que el compilador llame al comando dado como preprocesador para cada archivo fuente. La salida del comando se redirige a un archivo intermedio, que se compila. Si no hay errores de compilación, el archivo intermedio se elimina después.
-ppx comando
Después de analizar, canaliza el árbol de sintaxis abstracta a través del preprocesador comando. El módulo Ast_mapper(3) implementa la interfaz externa de un preprocesador.
-principal
Verifica la ruta de información durante la verificación de tipos, para asegurarse de que todos los tipos se derivan de manera principal. Al usar argumentos etiquetados y/o métodos polimórficos, esta bandera es necesaria para garantizar que las versiones futuras del compilador puedan inferir tipos correctamente, incluso si los algoritmos internos cambian. Todos los programas aceptados en modo -principal también se aceptan en modo predeterminado con tipos equivalentes, pero con firmas binarias diferentes, y esto puede ralentizar la verificación de tipos; sin embargo, es una buena idea usarlo una vez antes de publicar el código fuente.
-no-principal
No verifique la principalidad de la inferencia de tipos. Este es el valor predeterminado.
-rectypes
Permite tipos recursivos arbitrarios durante la verificación de tipos. Por defecto, solo se admiten tipos recursivos donde la recursión pasa a través de un tipo de objeto. Tenga en cuenta que una vez que haya creado una interfaz usando esta bandera, deberá usarla nuevamente para todas las dependencias.
-no-rectypes
No permite tipos recursivos arbitrarios durante la verificación de tipos. Este es el valor predeterminado.
-runtime-variant sufijo
Agrega sufijo al nombre de la biblioteca de tiempo de ejecución que será utilizada por el programa. Si OCaml se configuró con la opción -with-debug-runtime, entonces se admite el sufijo d y proporciona una versión de depuración del tiempo de ejecución.
-safe-string
Refuerza la separación entre los tipos string y bytes, haciendo que las cadenas sean de solo lectura. Este es el valor predeterminado.
-safer-matching
No utilice información de tipos para optimizar la coincidencia de patrones. Esto permite detectar fallos de coincidencia incluso si se asumió erróneamente que una coincidencia de patrones era exhaustiva. Esto solo afecta la compilación de GADT y variantes polimórficas.
-short-paths
Cuando un tipo es visible bajo varias rutas de módulo, usa la más corta al imprimir el nombre del tipo en las interfaces inferidas y en los mensajes de error y advertencia.
-stop-after paso
Detiene la compilación después del paso de compilación dado. Los pasos actualmente compatibles son: parsing, typing.
-strict-sequence
Fuerza que la parte izquierda de cada secuencia tenga el tipo unit.
-no-strict-sequence
La parte izquierda de una secuencia no necesita tener el tipo unit. Este es el valor predeterminado.
-unboxed-types
Cuando un tipo se puede desempaquetar (es decir, un registro con un solo argumento o un tipo de dato concreto con un solo constructor de un argumento) se desempaquetará a menos que se anote con [@@ocaml.boxed].
-no-unboxed-types
Cuando un tipo se puede desempaquetar, se empaquetará a menos que se anote con [@@ocaml.unboxed]. Este es el valor predeterminado.
-unsafe
Desactiva la verificación de límites para accesos a matrices y cadenas (las construcciones v.(i) y s.[i]). Por lo tanto, los programas compilados con -unsafe son ligeramente más rápidos, pero inseguros: cualquier cosa puede suceder si el programa accede a una matriz o cadena fuera de sus límites.
-unsafe-string
Identifica los tipos string y bytes, haciendo así que las cadenas sean escribibles. Esto está diseñado para la compatibilidad con código fuente antiguo y no debe usarse con software nuevo.
-use-runtime nombre-runtime
Genera un archivo ejecutable de bytecode que se puede ejecutar en el sistema de tiempo de ejecución personalizado nombre-runtime, construido anteriormente con ocamlc -make-runtime nombre-runtime.
-v
Imprime el número de versión del compilador y la ubicación del directorio de la biblioteca estándar, luego sale.
-verbose
Imprime todos los comandos externos antes de que se ejecuten, en particular las invocaciones del compilador C y el enlazador en modo -custom. Útil para depurar problemas de bibliotecas C.
-vnum o -version
Imprime el número de versión del compilador en formato corto (por ejemplo, "3.11.0"), luego sale.
-w lista-advertencias
Habilita, deshabilita o marca como fatal las advertencias especificadas por el argumento lista-advertencias.

Cada advertencia puede ser habilitada o deshabilitada, y cada advertencia puede ser fatal o no fatal. Si una advertencia está deshabilitada, no se muestra y no afecta la compilación de ninguna manera (incluso si es fatal). Si una advertencia está habilitada, el compilador la mostrará normalmente cada vez que el código fuente la active. Si está habilitada y es fatal, el compilador también se detendrá con un error después de mostrarla.

El argumento lista-advertencias es un especificador de advertencia mnemónico o una secuencia de especificadores de advertencia de un solo carácter, sin separadores entre ellos. Un especificador de advertencia mnemónico es uno de los siguientes:

+nombre   Habilita la advertencia nombre.

-nombre   Deshabilita la advertencia nombre.

@nombre   Habilita y marca como fatal la advertencia nombre.

Un especificador de advertencia de un solo carácter es uno de los siguientes:

+num   Habilita la advertencia número num.

-num   Deshabilita la advertencia número num.

@num   Habilita y marca como fatal la advertencia número num.

+num1..num2   Habilita todas las advertencias entre num1 y num2 (inclusive).
