odbx_error_type(3)

Paquete: opendbx

Licencias: LGPL

odbx_error_type(3) OpenDBX odbx_error_type(3)

NOMBRE

odbx_error_type - Devuelve la severidad de un error

SINOPSIS

#include <opendbx/api.h>


int odbx_error_type
(odbx_t* handle, int error);

DESCRIPCIÓN

odbx_error_type() indica la severidad del código de error devuelto por la última llamada a función y proporcionado a través del parámetro de error. Se puede utilizar para distinguir errores críticos de advertencias y permite a una aplicación reaccionar adecuadamente. Mientras que las aplicaciones generalmente pueden continuar si ocurren advertencias, informando al usuario y tomando medidas a nivel de lógica de la aplicación, los errores graves siempre requieren recrear la conexión. En ambos casos, todos los errores devueltos se sobrescriben cuando se llama a la siguiente función odbx_*(). Esta función está disponible desde la versión 1.1.2.

Tomemos odbx_query() (o cualquier otra función) como ejemplo, que devolvió un error. Si el valor de retorno de odbx_error_type() es negativo, se ha encontrado un error grave, como que la conexión con el servidor está rota. En este caso, deberá llamar a odbx_unbind(), odbx_finish(), odbx_init() y odbx_bind() en este orden para recrear la conexión. De lo contrario, si el valor de retorno fue positivo, su sentencia puede no haber sido entendida por el servidor de base de datos. Aquí puede continuar enviando la siguiente sentencia al servidor sin necesidad de recrear la conexión.

El parámetro handle es el objeto de conexión creado y devuelto por odbx_init() si la llamada fue exitosa y se vuelve inválido tan pronto como se proporcionó a odbx_finish(). De todos modos, no es necesario proporcionar un handle válido para errores cuyos códigos de error no sean iguales a -ODBX_ERR_BACKEND. Por lo tanto, es posible utilizar odbx_error_type() incluso si odbx_init() devolvió un error. Si en este caso se proporciona -ODBX_ERR_BACKEND, el valor de retorno indicará un error crítico.

Todos los valores devueltos por las funciones odbx_*() se pueden alimentar directamente a través del parámetro error a esta función. Si el valor dado no indica un error, el código devuelto siempre será cero para una finalización exitosa. Los valores negativos se separarán en clases para errores críticos y advertencias en su lugar.

VALOR DE RETORNO

En caso de éxito, es decir, si se proporciona ODBX_ERR_SUCCESS o un valor positivo como valor de error, la función devuelve cero. De lo contrario, habrá valores positivos y negativos devueltos, dependiendo de la severidad del error ocurrido.

Los valores positivos (valores mayores que cero) indican errores recuperables que dejan la conexión de la base de datos intacta. Un ejemplo podría ser una advertencia si no se pudo insertar un registro en la tabla por alguna razón. En este caso, se pueden enviar más sentencias al servidor de la base de datos y es probable que tengan éxito.

Por otro lado, si se devuelven valores negativos (valores menores que cero), ha ocurrido un error grave en el módulo backend, la biblioteca cliente nativa de la base de datos o el servidor de base de datos. La conexión con el servidor podría haberse perdido o podría haber ocurrido una condición de falta de memoria. Esto significa que todas las llamadas posteriores a la biblioteca OpenDBX probablemente fallarán y la única forma de recuperarse de esta situación es limpiar la conexión utilizando odbx_unbind() y odbx_finish() y tratando de crear una nueva conexión desde cero.

ERRORES

Esta función no devuelve ningún error.

VER TAMBIÉN

odbx_finish(), odbx_init(), odbx_unbind()
