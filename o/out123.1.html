out123(1) Manual de comandos generales out123(1)

NOMBRE

out123 - envía PCM crudo o un patrón de forma de onda a un dispositivo de salida

SINOPSIS

cat audio.raw | out123 [ - ] [ opciones ]

out123 [ opciones ] nombre_archivo [ nombre_archivo ... ]

out123 --wave-freq freq1[,freq2,...] [ opciones ]

out123 --source geiger [ opciones ]

DESCRIPCIÓN

out123 lee datos PCM crudos (en orden de bytes del host) de la entrada estándar y los reproduce en el dispositivo de audio especificado por las opciones dadas. Alternativamente, puede generar señales periódicas o aleatorias para su reproducción.

OPCIONES

Las opciones de out123 pueden ser las opciones tradicionales de una letra de POSIX, o las opciones largas de estilo GNU. Las opciones de estilo POSIX comienzan con un único '-', mientras que las opciones largas de GNU comienzan con '--'. Los argumentos de las opciones (si son necesarios) siguen separados por espacios (no por '='). Tenga en cuenta que algunas opciones pueden estar ausentes en su instalación si se deshabilitaron durante el proceso de compilación.

--name nombre
Establece el nombre de esta instancia, posiblemente utilizado en varios lugares. Esto establece el nombre del cliente para la salida JACK.
-o módulo, --output módulo
Selecciona el módulo de salida de audio. Puede proporcionar una lista separada por comas para usar la primera que funcione. Consulte también -a.
--list-modules
Enumera los módulos disponibles.
--list-devices
Enumera los dispositivos de salida disponibles para el módulo de salida dado. Si no hay funcionalidad para enumerar dispositivos en el módulo elegido, se imprimirá un error y out123 saldrá con un código distinto de cero.
-a dev, --audiodevice dev
Especifica el dispositivo de audio a usar. El valor predeterminado, así como los valores posibles, dependen de la salida activa. Para la salida JACK, se puede especificar una lista separada por comas de puertos a los que conectarse (para cada canal).
-s, --stdout
Las muestras de audio se escriben en la salida estándar, en lugar de reproducirse a través del dispositivo de audio. El formato de salida es el mismo que el de entrada ... por lo que en este modo, out123 actúa de manera similar a la herramienta estándar cat, posiblemente con algunas conversiones involucradas. Este atajo es equivalente a '-o raw -a -'.
-S, --STDOUT
Esta variante adicionalmente escribe los datos en la salida estándar, mientras los reproduce en el dispositivo de salida. Por lo tanto, se parece más a algún tipo de tee que a un cat.
-O archivo, --outfile
Escribe la salida cruda en un archivo (en lugar de simplemente redirigir la salida estándar a un archivo con el shell). Este atajo es equivalente a '-o raw -a archivo'.
-w archivo, --wav
Escribe la salida como un archivo WAV archivo, o la salida estándar si se usa '-' o la cadena vacía como nombre de archivo. También puede usar --au y --cdr para los formatos AU y CDR, respectivamente. Tenga en cuenta que escribir WAV/AU en archivos no buscables o en la salida estándar redirigida requiere algo de reflexión. La cabecera se escribe con los primeros datos reales. El resultado de decodificar nada a WAV/AU es un archivo que consiste solo en la cabecera cuando es buscable y realmente nada cuando no lo es (ni siquiera una cabecera). Escribir correctamente datos con cabeceras proféticas a la salida estándar no es un asunto fácil. Este atajo es equivalente a '-o wav -a archivo'.
--au archivo
Escribe en archivo en formato de audio SUN. Si se usa '-' o la cadena vacía como nombre de archivo, el archivo AU se escribe en la salida estándar. Consulte el párrafo sobre escritura WAV para ver la diversión de las cabeceras con flujos no buscables. Este atajo es equivalente a '-o au -a archivo'.
--cdr archivo
Escribe en archivo como CDR (audio de CD-ROM, más correctamente CDDA para audio digital de CD). Si se usa '-' o la cadena vacía como nombre de archivo, el archivo CDR se escribe en la salida estándar. Este atajo es equivalente a '-o cdr -a archivo'.
-r tasa, --rate tasa
Establece la tasa de muestreo en Hz (predeterminado: 44100). Si esto no coincide con la tasa de muestreo de entrada real, obtendrá un cambio de tono. Podría ser intencional ;-)
-R tasa, --inputrate tasa
Establece la tasa de muestreo de entrada a un valor diferente. Esto activa el remuestreo si la tasa de salida es realmente diferente. Consulte --resample.
--speed factor
Acelera/desacelera la reproducción por ese factor utilizando remuestreo. Consulte --resample.
--resample método
Esto elige el método para remuestrear entre tasas de muestreo diferentes o para aplicar un cambio de tempo. Puede elegir entre dos variantes del remuestreador syn123: fina (predeterminada) y sucia. La fina presenta un rango dinámico de 108 dB y, en el peor de los casos, un ancho de banda del 84%. La sucia utiliza menos tiempo de CPU (aunque no mucho) al reducir el rango dinámico a 72 dB con un ancho de banda en el peor de los casos del 85%. Las propiedades exactas varían con la relación de tasas de muestreo, ya que hay interpolación de coeficientes de filtro involucrada.
-c conteo, --channels conteo
Establece el número de canales al valor dado.
-C conteo, --inputch conteo
Establece el número de canales de entrada a un valor diferente al de salida. Esto probablemente significa que desea alguna remezcla. Consulte también --mix.
-e codificación, --encoding codificación
Elige la codificación de muestra de salida. Los valores posibles son como f32 (punto flotante de 32 bits), s32 (entero con signo de 32 bits), u32 (entero sin signo de 32 bits) y las variantes con diferentes números de bits (s24, u24, s16, u16, s8, u8) y también variantes especiales como ulaw y alaw de 8 bits. Consulte la salida de la ayuda larga de out123 para ver las codificaciones disponibles. El valor predeterminado es s16.
--endian elección
Selecciona la endianidad de salida (orden de bytes). La elección es big, little o native, que es la predeterminada. El procesamiento solo puede funcionar en modo nativo, por lo que debe especificar el orden de bytes de entrada o salida si no coincide con su máquina. Esto también establece la endianidad de entrada si no se establece por separado. Consulte también --inputend y --byteswap.
-E codificación, --inputenc codificación
Especifica una codificación de entrada diferente a la de salida para la conversión.
--inputend elección
Selecciona la endianidad de entrada (orden de bytes). Por defecto, es la misma que el orden de bytes de salida. Consulte --endian.
--byteswap
Un interruptor para activar el intercambio del orden de bytes justo antes de la salida, después de cualquier otra transformación. Esto funciona sobre cualquier endianidad que especifique con
-m, --mono
Establece para audio de un solo canal (el predeterminado es dos canales, estéreo).
--stereo
Selecciona salida estéreo (2 canales, predeterminado).
--list-encodings
Enumera los nombres cortos y largos de codificación conocidos en la salida estándar.
--mix matriz
Especifica una matriz de mezcla entre los canales de entrada y salida como factores lineales, una lista separada por comas para los factores del canal de entrada para el canal de salida 1, luego para el canal de salida 2, y así sucesivamente. El valor predeterminado es una matriz unitaria si los recuentos de canales coinciden, por lo que para 3 canales, el equivalente de ambos canales con amplitud reducida a la mitad, sería '--mix 0.5,0.5'. Para dividir mono a estéreo, es '--mix 1,1' para mantener la simetría.
--filter coeff
Aplica filtros digitales antes de la preamplificación (ver --preamp) con la lista de coeficientes coeff como
b_0,...,b_N,a_0,
...,a_N
donde a_0=1 es obligatorio y quizás ayuda un poco a la orientación. Múltiples filtros se separan por ':'.
-P dbvalue --preamp dbvalue
Habilita una etapa de preamplificación que amplifica la señal con el valor dado en dB antes de la salida.
--offset valor
Aplica un desplazamiento PCM (valor de punto flotante escalado en [-1:1] en la etapa de preamplificación. Normalmente, harías esto para corregir un desplazamiento DC conocido en una grabación.
--clip modo
Selecciona el modo de recorte: 'soft' o 'hard' para recorte forzado también para salida de punto flotante, 'implicit' (por defecto) para recorte duro implícito durante la conversión cuando sea necesario.
--dither
Habilita el dithering para conversiones a entero. Si insistes. Esto es solo algún dithering TPDF poco espectacular. A la mayoría de la gente no le importa de una forma u otra.
--test-format
Comprueba si el formato dado es compatible con el controlador y dispositivo dados (en la línea de comandos antes de encontrar esto), devolviendo silenciosamente 0 como valor de salida si es así.
--test-encodings
Imprime los nombres cortos de las codificaciones compatibles con la configuración actual.
--query-format
Si el controlador y el dispositivo seleccionados comunican algún formato predeterminado aceptado, imprime un fragmento de línea de comandos para out123 que establece ese formato, siempre en este orden: --rate <r> --channels <c> --encoding <e>
-o h, --headphones
Dirige la salida de audio al conector de auriculares (solo algunos hardware; AIX, HP, SUN).
-o s, --speaker
Dirige la salida de audio al altavoz (solo algunos hardware; AIX, HP, SUN).
-o l, --lineout
Dirige la salida de audio al conector de salida de línea (solo algunos hardware; AIX, HP, SUN).
-b tamaño, --buffer tamaño
Usa un búfer de salida de audio de tamaño Kbytes. Esto es útil para evitar períodos cortos de actividad intensa del sistema, que normalmente causarían interrupciones en la salida de audio. Deberías especificar un tamaño de búfer de al menos 1024 (es decir, 1 Mb, lo que equivale a unos 6 segundos de datos de audio habituales) o más; menos de unos 300 no tiene mucho sentido. El valor predeterminado es 0, que desactiva el búfer.
--preload fracción
Espera a que el búfer se llene hasta la fracción antes de comenzar la reproducción (fracción entre 0 y 1). Puedes ajustar este pre-búfer para obtener sonido más rápido a tus oídos o para una radio web ininterrumpida más segura. El valor predeterminado es 0.2 (cambiado de 1 desde la versión 1.23).
--devbuffer segundos
Establece el búfer del dispositivo en segundos; <= 0 significa el valor predeterminado. Este es el pequeño búfer entre la aplicación y el backend de audio, posiblemente relacionado directamente con los búferes de hardware.
--timelimit muestras
Establece el límite de tiempo de reproducción en muestras PCM si se establece en un valor mayor que cero. out123 dejará de leer desde stdin o de reproducir desde la tabla de ondas generada después de alcanzar ese número de muestras.
--seconds segundos
Establece el límite de tiempo en segundos en su lugar.
--source nombre
Elige la fuente de la señal: 'file' (predeterminado) para reproducir el(los) archivo(s) dado(s) en la línea de comandos o la entrada estándar si no hay ninguno, o uno de los generadores 'wave' (ver --wave-freq), geiger (ver --geiger-activity), o simplemente 'white' para algo de ruido blanco.
--wave-freq frecuencias
Establece la frecuencia del generador de ondas o una lista de ellas con separación de comas para habilitar una señal de prueba generada en lugar de la entrada estándar. Los valores vacíos repiten el anterior.
--wave-pat patrones
Establece los patrones de forma de onda de las ondas generadas como una lista separada por comas. Las opciones incluyen senoidal, cuadrada, triangular, diente de sierra, gaussiana, pulso y pulso corto. Los valores vacíos repiten el anterior.
--wave-phase fases
Establece el desplazamiento de fase de la forma de onda como una lista separada por comas, los valores negativos invierten el patrón en el tiempo y un valor vacío repite el anterior. También está --wave-direction que anula el bit negativo.
--wave-direction
Establece la dirección de la onda explícitamente (el signo cuenta).
--wave-sweep frecuencia
Barrido de una onda generada a la frecuencia dada, desde la primera especificada para --wave-freq, utilizando también el primer patrón y dirección de onda.
--sweep-time segundos
Establece la duración del barrido de frecuencia en segundos si es > 0. Esto toma por defecto el límite de tiempo configurado si está establecido, de lo contrario un segundo, ya que los barridos infinitos no son sensatos.
--sweep-count cuenta
Establece el límite de tiempo para producir exactamente esa cantidad de barridos (suaves).
--sweep-type tipo
Establece el tipo de barrido: lin(eal) para lineal, qua(d) (predeterminado) para cuadrático, o exp(onencial) para un cambio exponencial de frecuencia con el tiempo.
--sweep-hard
Deshabilita el suavizado posterior al barrido para la periodicidad.
--genbuffer bytes
Establece el tamaño del búfer (límite) para los generadores de señal, si es > 0 (predeterminado), esto impone un búfer periódico también para señales no periódicas, beneficio: menor sobrecarga de CPU en tiempo de ejecución, ya que todo está precalculado como una señal periódica impuesta.
--wave-limit muestras
Este es un alias para --genbuffer.
--pink-rows número
Activa la fuente de ruido rosa y elige las filas para el algoritmo (<1 elige el predeterminado). El generador sigue el código proporcionado por Phil Burk (http://softsynth.com) y usa el método de Gardner.
--geiger-activity número
Esto configura la simulación de un contador Geiger-Mueller como fuente, con el número dado como eventos promedio por segundo. ¡Juega con él. Es divertido!
-t, --test
Modo de prueba. Se lee el flujo de audio, pero no se produce ninguna salida.
-v, --verbose
Aumenta el nivel de verbosidad.
-q, --quiet
Silencioso. Suprime los mensajes de diagnóstico.
--aggressive
Intenta obtener una mayor prioridad.
-T, --realtime
Intenta obtener prioridad en tiempo real. Esta opción generalmente requiere privilegios de root para tener algún efecto.
-?, --help
Muestra instrucciones de uso breves.
--longhelp
Muestra instrucciones de uso extensas.
--version
Imprime la cadena de versión.
