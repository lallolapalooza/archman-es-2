NOMBRE

opam admin-upgrade - Actualiza el repositorio de versiones anteriores de opam.

SINOPSIS

opam admin upgrade [--clear-cache] [--mirror=URL] [OPCIÓN]…

DESCRIPCIÓN

Este comando lee repositorios de versiones anteriores de opam y los convierte a repositorios adecuados para la versión actual de opam. Los paquetes pueden ser creados o renombrados, y cualquier compilador definido en el formato antiguo (directorio 'compilers/') se convertirá en paquetes, utilizando una jerarquía predefinida que asume compiladores OCaml.

OPCIONES

--clear-cache
En lugar de ejecutar la actualización, borra la caché de hashes de archivo (almacenada en ~/.cache), que se utiliza para evitar la redescarga de archivos para obtener sus hashes en cada ejecución.
-m URL, --mirror=URL
No sobrescribir el repositorio actual, sino colocar un espejo actualizado en un subdirectorio, con redirecciones adecuadas. Necesita la URL desde la que se servirá el repositorio para colocar las redirecciones (versiones anteriores de opam no entienden redirecciones relativas).

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden soportar esta opción (versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Usar la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Destinado a cualquier uso persistente de opam (scripts, publicaciones de blog, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. El flag no estaba disponible en opam 2.0, así que para seleccionar la interfaz de línea de comandos 2.0, establezca la variable de entorno $OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorear la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o sí-inseguro. Se puede especificar varias veces. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especificar preferencias del usuario para la resolución de dependencias en esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para detalles sobre el lenguaje soportado y los solucionadores externos disponibles, ver http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre el uso de preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBREARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en NOMBREARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Igual que --debug, pero permite especificar el nivel de depuración (--debug lo establece a 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está establecida (es decir, si está usando una versión de desarrollo), y sale.
--help[=FMT] (por defecto=auto)
Muestra esta ayuda en el formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIRECTORIO. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBREARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por máquina. Si el nombre del archivo contiene el carácter `%', se reemplazará por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio que está escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
-q, --quiet
Deshabilita --verbose.
--root=RAÍZ
Usa RAÍZ como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a RAÍZ.
--safe, --readonly
Asegura que nada se actualizará o reescribirá automáticamente. Útil para llamarlo desde scripts de autocompletado, por ejemplo. Fallará cuando se necesite tal operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el solucionador CUDF a usar para resolver problemas de instalación de paquetes. Este es un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. El valor por defecto es continuar en silencio si es posible.
--switch=SWITCH
Usa SWITCH como el switch de compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier solucionador externo y usa el interno (esto requiere que opam haya sido compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más detallado. Una -v muestra todos los comandos de paquetes, repite para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra la información de la versión.
-w, --working-dir
Siempre que se actualicen paquetes vinculados a un directorio local controlado por versiones, actualiza al estado de trabajo actual de su código fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio de código fuente se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

NAME

opam-admin-upgrade - upgrade an opam installation to a new version

SYNOPSIS

opam-admin upgrade [OPTION]...

DESCRIPTION

This command upgrades the opam state and installed packages to a new version of opam. It is intended to be run by the user after upgrading the opam binary.

The operation can be split into several steps:

1. Update the opam internal format (if needed).

2. Re-evaluate the repository definitions.

3. Install new versions of packages if the opam version changed their requirements or if new constraints are introduced.

4. Clean up packages that are no longer required.

This command might fail if the new version of opam introduces incompatible changes in the package format, or if there are repository changes that cannot be resolved.

OPTIONS

--help, -h
Show this help message and exit.
--verbose, -v
Show more information about the command execution.
--debug, -d
Show debug information.
--force, -f
Force the upgrade, even if some checks indicate it might be risky.
--dry-run, -n
Do not perform any changes, just show what would be done.

COMMON OPTIONS

These options are common to all opam commands:

--color=[auto|always|never]
Control the use of terminal colors.
--jobs=N, -j N
Set the number of parallel jobs (default: number of cores).
--root=DIR
Use an alternative opam database directory.
--skip-update
Do not update the repositories before the operation.
--dev-version
Use development versions for packages.

ENVIRONMENT

See opam(1) for common environment variables.

CLI VERSION

This command was introduced in opam 2.0.

EXIT STATUS

1

2

10

30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
