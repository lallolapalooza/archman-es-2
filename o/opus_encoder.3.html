Descripción Detallada

Esta página describe el proceso y las funciones utilizadas para codificar Opus.

Dado que Opus es un códec con estado, el proceso de codificación comienza con la creación de un estado de codificador. Esto se puede hacer con:

int          error;
OpusEncoder *enc;
enc = opus_encoder_create(Fs, channels, application, &error);

A partir de este punto, enc puede ser utilizado para codificar un flujo de audio. Un estado de codificador no debe ser utilizado para más de un flujo simultáneamente. De manera similar, el estado del codificador no debe ser reinicializado para cada fotograma.

Mientras que opus_encoder_create() asigna memoria para el estado, también es posible inicializar memoria preasignada:

int          size;
int          error;
OpusEncoder *enc;
size = opus_encoder_get_size(channels);
enc = malloc(size);
error = opus_encoder_init(enc, Fs, channels, application);

donde opus_encoder_get_size() devuelve el tamaño requerido para el estado del codificador. Tenga en cuenta que las versiones futuras de este código pueden cambiar el tamaño, por lo que no se deben hacer suposiciones al respecto.

El estado del codificador es siempre continuo en memoria y solo una copia superficial es suficiente para copiarlo (por ejemplo, memcpy())

Es posible cambiar algunas de las configuraciones del codificador utilizando la interfaz opus_encoder_ctl(). Todas estas configuraciones ya tienen el valor recomendado por defecto, por lo que solo deben cambiarse cuando sea necesario. Las configuraciones más comunes que se pueden desear cambiar son:

opus_encoder_ctl(enc, OPUS_SET_BITRATE(bitrate));
opus_encoder_ctl(enc, OPUS_SET_COMPLEXITY(complexity));
opus_encoder_ctl(enc, OPUS_SET_SIGNAL(signal_type));

donde

  • bitrate está en bits por segundo (b/s)
  • complexity es un valor de 1 a 10, donde 1 es la complejidad más baja y 10 es la más alta
  • signal_type es OPUS_AUTO (por defecto), OPUS_SIGNAL_VOICE, u OPUS_SIGNAL_MUSIC

Consulte CTLs relacionados con el codificador y CTLs genéricos para obtener una lista completa de parámetros que se pueden establecer o consultar. La mayoría de los parámetros se pueden establecer o cambiar en cualquier momento durante un flujo.

Para codificar un fotograma, se debe llamar a opus_encode() o opus_encode_float() con exactamente un fotograma (2.5, 5, 10, 20, 40 o 60 ms) de datos de audio:

len = opus_encode(enc, audio_frame, frame_size, packet, max_packet);

donde

  • audio_frame son los datos de audio en opus_int16 (o float para opus_encode_float())
  • frame_size es la duración del fotograma en muestras (por canal)
  • packet es el array de bytes al que se escriben los datos comprimidos
  • max_packet es el número máximo de bytes que se pueden escribir en el paquete (se recomiendan 4000 bytes). No utilice max_packet para controlar la tasa de bits objetivo de VBR, utilice en su lugar el CTL OPUS_SET_BITRATE.

opus_encode() y opus_encode_float() devuelven el número de bytes escritos realmente en el paquete. El valor de retorno puede ser negativo, lo que indica que ha ocurrido un error. Si el valor de retorno es de 2 bytes o menos, el paquete no necesita ser transmitido (DTX).

Una vez que el estado del codificador ya no sea necesario, se puede destruir con

opus_encoder_destroy(enc);

Si el codificador se creó con opus_encoder_init() en lugar de opus_encoder_create(), entonces no se requiere ninguna acción aparte de posiblemente liberar la memoria que se asignó manualmente para él (llamando a free(enc) para el ejemplo anterior)

opus_int32 opus_encode (OpusEncoder * st, const opus_int16 * pcm, int frame_size, unsigned char * data, opus_int32 max_data_bytes)

Codifica un fotograma Opus.

Parámetros

st OpusEncoder*: Estado del codificador
pcm opus_int16*: Señal de entrada (intercalada si son 2 canales). La longitud es frame_size*channels*sizeof(opus_int16)
frame_size int: Número de muestras por canal en la señal de entrada. Debe ser un tamaño de fotograma Opus para la frecuencia de muestreo del codificador. Por ejemplo, a 48 kHz los valores permitidos son 120, 240, 480, 960, 1920 y 2880. Pasar una duración inferior a 10 ms (480 muestras a 48 kHz) impedirá que el codificador utilice los modos LPC o híbridos.
data unsigned char*: Carga útil de salida. Debe contener espacio para al menos max_data_bytes.
max_data_bytes opus_int32: Tamaño de la memoria asignada para la carga útil de salida. Esto se puede usar para imponer un límite superior en la tasa de bits instantánea, pero no debe usarse como único control de la tasa de bits. Utilice OPUS_SET_BITRATE para controlar la tasa de bits.

Devuelve

La longitud del paquete codificado (en bytes) en caso de éxito o un código de error negativo (consulte Códigos de error) en caso de fallo.

Detailed Description

opus_encode

Encodes one frame of non-interleaved audio. Use this for low-bandwidth applications that want to use Opus over a real-time transport protocol like RTP.

Parameters

st OpusEncoder*: Encoder state.
pcm const opus_int16*: Input signal (Little-endian PCM samples). A NULL pointer can be passed to indicate that the encoder should generate silence.
frame_size int: Number of samples per channel in the frame to be encoded.
buffer unsigned char*: Allocated buffer to store the encoded packet.
max_data_bytes int: The maximum number of bytes to store in buffer.

Returns

The length of the encoded packet (in bytes) on success or a negative error code (see Error codes) on failure.

OpusEncoder * opus_encoder_create (opus_int32 Fs, int channels, int application, int * error)

Allocates and initializes an encoder state. There are three coding modes:

OPUS_APPLICATION_VOIP gives best quality at a given bitrate for voice signals. It enhances the input signal by high-pass filtering and emphasizing formants and harmonics. Optionally it includes in-band forward error correction to protect against packet loss. Use this mode for typical VoIP applications. Because of the enhancement, even at high bitrates the output may sound different from the input.

OPUS_APPLICATION_AUDIO gives best quality at a given bitrate for most non-voice signals like music. Use this mode for music and mixed (music/voice) content, broadcast, and applications requiring less than 15 ms of coding delay.

OPUS_APPLICATION_RESTRICTED_LOWDELAY configures low-delay mode that disables the speech-optimized mode in exchange for slightly reduced delay. This mode can only be set on an newly initialized or freshly reset encoder because it changes the codec delay.

This is useful when the caller knows that the speech-optimized modes will not be needed (use with caution).

Parameters

Fs opus_int32: Sampling rate of input signal (Hz) This must be one of 8000, 12000, 16000, 24000, or 48000.
channels int: Number of channels (1 or 2) in input signal
application int: Coding mode (OPUS_APPLICATION_VOIP/ OPUS_APPLICATION_AUDIO/OPUS_APPLICATION_RESTRICTED_LOWDELAY)
error int*: Error codes

Note

Regardless of the sampling rate and number channels selected, the Opus encoder can switch to a lower audio bandwidth or number of channels if the bitrate selected is too low. This also means that it is safe to always use 48 kHz stereo input and let the encoder optimize the encoding.
