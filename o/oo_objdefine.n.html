oo_objdefine(n)

Paquete: tcl

Licencias: TCL

define(n) Comandos TclOO define(n)

NOMBRE

oo::define, oo::objdefine, oo::Slot - definir y configurar clases y objetos

SINOPSIS

package require TclOO
oo::define clase scriptDefinicion
oo::define clase subcomando argumento ?argumento ...?
oo::objdefine objeto scriptDefinicion
oo::objdefine objeto subcomando argumento ?argumento ...?
oo::Slot argumento...

JERARQUIA DE CLASES

oo::object
   → oo::Slot

DESCRIPCION

El comando oo::define se utiliza para controlar la configuración de las clases, y el comando oo::objdefine se utiliza para controlar la configuración de los objetos (incluyendo las clases como objetos de instancia), con la configuración aplicada a la entidad nombrada en el argumento de clase u objeto. Configurar una clase también actualiza la configuración de todas las subclases de la clase y de todos los objetos que son instancias de esa clase o que la mezclan (modificada por cualquier configuración por instancia). La forma en que se realiza la configuración se controla bien por el argumento scriptDefinicion o bien por el subcomando y los argumentos siguientes; cuando este último está presente, es exactamente como si todos los argumentos desde subcomando en adelante se hicieran una lista y esa lista se usara como el argumento scriptDefinicion.

CONFIGURACION DE CLASES

Los siguientes comandos son compatibles en el scriptDefinicion para oo::define, cada uno de los cuales también puede usarse en la forma de subcomando:

constructor listaArgumentos scriptCuerpo
Esto crea o actualiza el constructor de una clase. Los argumentos formales del constructor (definidos con el mismo formato que para el comando proc de Tcl) serán listaArgumentos, y el cuerpo del constructor será scriptCuerpo. Cuando se evalúa el cuerpo del constructor, el espacio de nombres actual del constructor será un espacio de nombres único para el objeto que se está construyendo. Dentro del constructor, el comando next debe usarse para llamar a los constructores de las superclases. Si scriptCuerpo es la cadena vacía, el constructor será eliminado.
deletemethod nombre ?nombre ...?
Esto elimina cada uno de los métodos llamados nombre de una clase. Los métodos deben haber existido previamente en esa clase. No afecta a las superclases de la clase, ni afecta a las subclases o instancias de la clase (excepto cuando tienen una cadena de llamadas a través de la clase que se modifica) o al objeto de clase en sí mismo.
destructor scriptCuerpo
Esto crea o actualiza el destructor de una clase. Los destructores no toman argumentos, y el cuerpo del destructor será scriptCuerpo. El destructor se llama cuando se eliminan objetos de la clase, y cuando se llama tendrá el espacio de nombres único del objeto como espacio de nombres actual. Los destructores deben usar el comando next para llamar a los destructores de las superclases. Tenga en cuenta que los destructores no se llaman en todas las situaciones (por ejemplo, si el intérprete se destruye). Si scriptCuerpo es la cadena vacía, el destructor será eliminado.
Tenga en cuenta que los errores durante la evaluación de un destructor *no se devuelven* al código que causa la destrucción de un objeto. En su lugar, se pasan al manejador bgerror actualmente definido.
export nombre ?nombre ...?
Esto organiza que cada uno de los métodos nombrados, nombre, sea exportado (es decir, usable fuera de una instancia a través del comando del objeto de instancia) por la clase que se está definiendo. Tenga en cuenta que los métodos en sí mismos pueden ser definidos por una superclase; las exportaciones de subclase anulan la visibilidad de la superclase y pueden ser anuladas por instancias.
filter ?-operacionSlot? ?nombreMetodo ...?
Esta ranura (ver DEFINICIONES CON RANURAS abajo) establece o actualiza la lista de nombres de métodos que se utilizan para proteger si las llamadas a métodos a instancias de la clase pueden ser llamadas y cuáles son los resultados del método. Cada nombreMetodo nombra un único método de filtrado (que puede estar expuesto o no); no es un error nombrar un método inexistente ya que pueden ser definidos por subclases. Por defecto, esta ranura funciona añadiendo.
forward nombre nombreComando ?argumento ...?
Esto crea o actualiza un método reenviado llamado nombre. El método se define reenviándolo al comando llamado nombreComando, con argumentos adicionales, argumento etc., añadidos antes de los argumentos especificados por el invocador del método. El nombreComando se resolverá siempre utilizando las reglas de los espacios de nombres de los objetos invocadores, es decir, cuando nombreComando no está completamente calificado, el comando se buscará en el espacio de nombres de cada objeto, utilizando la ruta del espacio de nombres de las instancias, o buscando en el espacio de nombres global. El método se exportará si nombre empieza por una letra minúscula, y no se exportará si no.
method nombre listaArgumentos scriptCuerpo
Esto crea o actualiza un método que se implementa como un script similar a un procedimiento. El nombre del método es nombre, los argumentos formales del método (definidos con el mismo formato que para el comando proc de Tcl) serán listaArgumentos, y el cuerpo del método será scriptCuerpo. Cuando se evalúa el cuerpo del método, el espacio de nombres actual del método será un espacio de nombres único para el objeto actual. El método se exportará si nombre empieza por una letra minúscula, y no se exportará en caso contrario; este comportamiento puede ser anulado mediante export y unexport.
mixin ?-operacionSlot? ?nombreClase ...?
Esta ranura (ver DEFINICIONES CON RANURAS abajo) establece o actualiza la lista de clases adicionales que se mezclarán en todas las instancias de la clase que se está definiendo. Cada argumento nombreClase nombra una clase que se va a mezclar. Por defecto, esta ranura funciona por reemplazo.
renamemethod nombreOrigen nombreDestino
Esto renombra el método llamado nombreOrigen en una clase a nombreDestino. El método debe haber existido previamente en la clase, y nombreDestino no debe referirse previamente a un método en esa clase. No afecta a las superclases de la clase, ni afecta a las subclases o instancias de la clase (excepto cuando tienen una cadena de llamadas a través de la clase que se modifica), o al objeto de clase en sí mismo. No cambia el estado de exportación del método; si estaba exportado antes, lo estará después.
self subcomando argumento ...
self script
Este comando es equivalente a llamar a oo::objdefine en la clase que se está definiendo (ver CONFIGURACION DE OBJETOS abajo para una descripción de los valores compatibles de subcomando). Sigue el mismo patrón general de manejo de argumentos que los comandos oo::define y oo::objdefine, y “oo::define cls self subcomando ...” opera idénticamente a “oo::objdefine cls subcomando ...”.
superclass ?-operacionSlot? ?nombreClase ...?
Esta ranura (ver DEFINICIONES CON RANURAS abajo) permite la alteración de las superclases de la clase que se está definiendo. Cada argumento nombreClase nombra una clase que será una superclase de la clase definida. Tenga en cuenta que los objetos no deben cambiarse de ser clases a no ser clases o viceversa, que una clase padre vacía es equivalente a oo::object, y que las clases padre de oo::object y oo::class no pueden modificarse. Por defecto, esta ranura funciona por reemplazo.
unexport nombre ?nombre ...?
Esto organiza que cada uno de los métodos nombrados, nombre, no sean exportados (es decir, no usables fuera de la instancia a través del objeto de instancia.

CONFIGURACION DE OBJETOS

Los comandos compatibles en el scriptDefinicion para oo::objdefine son los mismos que para oo::define, con la excepción de los comandos self y self~2, que no tienen sentido para objetos que no son clases.

Además, cada uno de los comandos de configuración de clases puede ser utilizado en forma de subcomando. Los siguientes comandos de subcomando se aplican a los objetos:

callnextmethod
Este comando se utiliza en el cuerpo de un método para llamar a la siguiente implementación de ese método que se encuentre en la jerarquía de clases.
class
Esto devuelve el nombre de la clase de la que es instancia el objeto.
delete
Esto elimina el objeto. Esto llamará a cualquier destructor de objeto, y luego eliminará el objeto de la memoria.
destroy
Esto es idéntico a delete.
forwardedmethod name
Esto devuelve el nombre del comando al que se reenvía el método llamado name.
get slotName
Esto devuelve el valor del slot llamado slotName. Si el slot no está definido, se produce un error.
isa className
Esto devuelve verdadero si el objeto es una instancia de la clase className o de una de sus subclases, y falso en caso contrario.
methodlist
Esto devuelve una lista de todos los métodos conocidos por el objeto.
next
Esto se utiliza en los cuerpos de los constructores y destructores para llamar a la implementación de la superclase de esos métodos.
objectid
Esto devuelve un identificador único para el objeto.
ownmethodlist
Esto devuelve una lista de los métodos definidos en el objeto que no han sido heredados de una superclase.
parent
Esto devuelve el nombre de la clase padre del objeto (es decir, la clase de la que hereda directamente).
set slotName value
Esto establece el valor del slot llamado slotName al valor value. Si el slot no está definido, se produce un error.

DEFINICIONES CON RANURAS

Los comandos oo::define y oo::objdefine pueden ser utilizados para manipular las "ranuras" de las clases y objetos. Las ranuras son una generalización de métodos y constructores, y pueden ser vistas como propiedades de las clases y objetos que pueden ser accedidas y modificadas mediante operaciones específicas.

Las ranuras se utilizan principalmente para configurar la estructura de las clases y objetos, por ejemplo, para definir las clases padre, las mezclas, los métodos de filtrado y los métodos reenviados.

Los comandos que manipulan ranuras son:

filter ?-slotOperation? ?methodName ...?
Esto establece o actualiza la lista de métodos de filtrado para una clase u objeto. El argumento -slotOperation puede ser uno de los siguientes: append, clear, prepend, remove, replace. El valor por defecto es append.
mixin ?-slotOperation? ?className ...?
Esto establece o actualiza la lista de clases mezcladas para una clase u objeto. El argumento -slotOperation puede ser uno de los siguientes: append, clear, prepend, remove, replace. El valor por defecto es replace.
superclass ?-slotOperation? ?className ...?
Esto establece o actualiza la lista de clases padre para una clase u objeto. El argumento -slotOperation puede ser uno de los siguientes: append, clear, prepend, remove, replace. El valor por defecto es replace.

El comando oo::Slot se utiliza para crear nuevas ranuras personalizadas. Su uso es similar al de los comandos de definición de métodos y constructores, permitiendo definir el comportamiento de la ranura en diferentes operaciones (acceso, modificación, etc.).

EJEMPLO

package require TclOO
oo::class create MiClase {
    variable contador 0
    constructor {args} {
        set contador [expr {$contador + 1}]
        puts "Constructor llamado, contador=$contador"
        next {*}$args
    }
    method saludar {nombre} {
        puts "Hola, $nombre! (Soy una instancia de [self class])"
    }
    destructor {} {
        puts "Destructor llamado para instancia con contador=$contador"
        next
    }
}
set obj1 [MiClase new]
set obj2 [MiClase new]
$obj1 saludar Hola
$obj2 saludar Mundo
destroy $obj1
destroy $obj2

Este ejemplo define una clase llamada MiClase con un constructor, un método saludar y un destructor. Se crean dos instancias de la clase, se llama al método saludar en cada una, y luego se destruyen las instancias, mostrando la salida del constructor y el destructor.

variable ?-operaciónDeRanura? ?nombre ...?
Esta ranura (ver DEFINICIONES CON RANURAS más abajo) organiza para que cada una de las variables nombradas esté automáticamente disponible en los métodos, el constructor y el destructor declarados por la clase que se está definiendo. Cada nombre de variable no debe tener separadores de espacio de nombres y no debe parecerse a un acceso a matriz. Todas las variables estarán realmente presentes en el objeto de instancia en el que se ejecuta el método. Tenga en cuenta que las listas de variables declaradas por una superclase o subclase son completamente disjuntas, al igual que las listas de variables declaradas por instancias; la lista de nombres de variables es solo para métodos (y constructores y destructores) declarados por esta clase. Por defecto, esta ranura funciona añadiendo.

CONFIGURACIÓN DE OBJETOS

Los siguientes comandos son compatibles con el defScript para oo::objdefine, cada uno de los cuales también puede usarse en el modo subcomando:

class nombreClase
Esto permite cambiar la clase de un objeto después de su creación. Tenga en cuenta que los constructores de la clase no se llaman cuando se hace esto, y por lo tanto, el objeto puede estar en un estado inconsistente a menos que se realicen trabajos de configuración adicionales.
deletemethod nombre ?nombre ...
Esto elimina cada uno de los métodos llamados nombre de un objeto. Los métodos deben haber existido previamente en ese objeto (por ejemplo, porque fue creado a través de oo::objdefine method). No afecta a las clases de las que el objeto es una instancia, ni elimina la exposición de esos métodos proporcionados por la clase en la instancia de esa clase.
export nombre ?nombre ...?
Esto organiza para que cada uno de los métodos nombrados, nombre, sea exportado (es decir, utilizable fuera del objeto a través del comando del objeto) por el objeto que se está definiendo. Tenga en cuenta que los métodos en sí mismos pueden ser definidos por una clase o superclase; las exportaciones de objetos anulan la visibilidad de la clase.
filter ?-operaciónDeRanura? ?nombreMetodo ...?
Esta ranura (ver DEFINICIONES CON RANURAS más abajo) establece o actualiza la lista de nombres de métodos que se utilizan para controlar si una llamada a método al objeto puede ser realizada y cuáles son los resultados del método. Cada nombreMetodo nombra un único método de filtrado (que puede estar expuesto o no); no es un error nombrar un método inexistente. Tenga en cuenta que la lista real de filtros también depende de los filtros establecidos en cualquier clase de la que el objeto sea instancia. Por defecto, esta ranura funciona añadiendo.
forward nombre nombreCmd ?arg ...?
Esto crea o actualiza un método de objeto reenviado llamado nombre. El método se define para ser reenviado al comando llamado nombreCmd, con argumentos adicionales, arg etc., añadidos antes de aquellos argumentos especificados por el llamador del método. Los métodos reenviados deben ser eliminados usando el subcomando method. El método será exportado si nombre comienza con una letra minúscula, y no exportado de lo contrario.
method nombre listaArgs scriptCuerpo
Esto crea, actualiza o elimina un método de objeto. El nombre del método es nombre, los argumentos formales para el método (definidos usando el mismo formato que para el comando proc de Tcl) serán listaArgs, y el cuerpo del método será scriptCuerpo. Cuando se evalúe el cuerpo del método, el espacio de nombres actual del método será un espacio de nombres que es único para el objeto. El método será exportado si nombre comienza con una letra minúscula, y no exportado de lo contrario.
mixin ?-operaciónDeRanura? ?nombreClase ...?
Esta ranura (ver DEFINICIONES CON RANURAS más abajo) establece o actualiza una lista por objeto de clases adicionales que se mezclarán en el objeto. Cada argumento, nombreClase, nombra una única clase que se va a mezclar. Por defecto, esta ranura funciona mediante reemplazo.
renamemethod nombreOrigen nombreDestino
Esto renombra el método llamado nombreOrigen en un objeto a nombreDestino. El método debe haber existido previamente en el objeto, y nombreDestino no debe referirse previamente a un método en ese objeto. No afecta a las clases de las que el objeto es instancia y no puede renombrar en un objeto de instancia los métodos proporcionados por esas clases (aunque un método oo::objdefine forward puede proporcionar una capacidad equivalente). No cambia el estado de exportación del método; si fue exportado antes, lo será después.
unexport nombre ?nombre ...?
Esto organiza para que cada uno de los métodos nombrados, nombre, no sea exportado (es decir, no utilizable fuera del objeto a través del comando del objeto, sino solo a través del comando my visible en el contexto del objeto) por el objeto que se está definiendo. Tenga en cuenta que los métodos en sí mismos pueden ser definidos por una clase; los unexports de instancia anulan la visibilidad de la clase.
variable ?-operaciónDeRanura? ?nombre ...?
Esta ranura (ver DEFINICIONES CON RANURAS más abajo) organiza para que cada una de las variables nombradas esté automáticamente disponible en los métodos declarados por el objeto que se está definiendo. Cada nombre de variable no debe tener ningún separador de espacio de nombres y no debe parecerse a un acceso a matriz. Todas las variables estarán realmente presentes en el objeto en el que se ejecuta el método. Tenga en cuenta que las listas de variables declaradas por las clases y mixins de las que el objeto es instancia son completamente disjuntas; la lista de nombres de variables es solo para métodos declarados por este objeto. Por defecto, esta ranura funciona añadiendo.

DEFINICIONES CON RANURAS

Algunas de las definiciones configurables de una clase u objeto son definiciones con ranuras. Esto significa que la configuración se implementa mediante un objeto de ranura, que es una instancia de la clase oo::Slot, que gestiona una lista de valores (nombres de clases, nombres de variables, etc.) que componen el contenido de la ranura.

La clase oo::Slot define tres operaciones (como métodos) que se pueden realizar en la ranura:

ranura -append ?miembro ...?
Esto añade los elementos miembro dados a la definición de la ranura.
ranura -clear
Esto establece la definición de la ranura a la lista vacía.
ranura -set ?miembro ...?
Esto reemplaza la definición de la ranura con los elementos miembro dados.

Una consecuencia de esto es que cualquier uso de la operación por defecto de una ranura donde el primer argumento miembro comience con un guion será un error. Se debe usar explícitamente una de las operaciones anteriores en esas circunstancias.

Solo necesita hacer una instancia de oo::Slot si está definiendo su propia ranura que se comporte como una ranura estándar.

IMPLEMENTACIÓN DE RANURAS

Internamente, los objetos de ranura también definen un método --default-operation que se reenvía a la operación por defecto de la ranura (por lo tanto, para la ranura de clase “variable”, esto se reenvía a “my -append”), y estos métodos que proporcionan la interfaz de implementación:

ranura Get
Devuelve una lista que es el contenido actual de la ranura. Este método siempre debe ser llamado desde un frame de pila creado por una llamada a oo::define u oo::objdefine.
ranura Resolve elemento
Esto convierte un elemento de la colección con ranuras en su forma resuelta; para un valor simple, podría simplemente devolver el valor, pero para una ranura que contiene referencias a comandos o clases, debe convertirlas en sus formas completamente calificadas (para que puedan compararse con string equals): eso podría hacerse reenviando a namespace which o similar.
ranura Set listaElementos
Establece el contenido de la ranura a la lista listaElementos y devuelve la cadena vacía. Este método siempre debe ser llamado desde un frame de pila creado por una llamada a oo::define u oo::objdefine.

La implementación de estos métodos depende de la ranura (y es responsable de acceder a la parte correcta de la definición de la clase u objeto). Las ranuras también tienen un manejador de métodos desconocidos para unir todas estas piezas, y ocultan su método destroy para que no se invoque inadvertidamente. Se recomienda que cualquier cambio de usuario en el propio mecanismo de ranura se restrinja a definir nuevas operaciones cuyos nombres comiencen con un guion.

Tenga en cuenta que no se espera que las instancias de ranura contengan el almacenamiento para la ranura que gestionan; ese estará en o adjunto a la clase u objeto que gestionan. Esas instancias deben proporcionar sus propias implementaciones de los métodos Get y Set (y opcionalmente Resolve; este por defecto es un paso sin hacer nada).

EJEMPLOS

Este ejemplo demuestra cómo usar ambas formas de los comandos oo::define y oo::objdefine (funcionan de la misma manera), además de ilustrar cuatro de sus subcomandos.

oo::class create c
c create o
oo::define c method foo {} {
    puts "world"
}
oo::objdefine o {
    method bar {} {
        my Foo "hello "
        my foo
    }
    forward Foo ::puts -nonewline
    unexport foo
}
o bar                → imprime "
oo::objdefine - TclOO Manual

NAME

oo::objdefine - Define methods and slots on an object

SYNOPSIS

oo::objdefine objName ?-define method|slot|variable|code|proc|const? ?<definition>...

DESCRIPTION

The oo::objdefine command provides a convenient syntax for defining methods, slots, variables, code blocks, procedures, or constants on a given object. All definitions apply to the specified object, objName, and are added to its object-specific definition space.

The keyword arguments supported are:

-define type
Specifies the type of definition to be created. The default type is method. The following types are supported:
  • method: Defines a method on the object. The definition must be a method specification (name, arguments, body).
  • slot: Defines a slot on the object. The definition must be a slot specification (name, initial value).
  • variable: Defines a variable on the object. The definition must be a variable specification (name, initial value).
  • code: Evaluates the definition as Tcl code within the object's definition space. This is useful for setting up instance variables via Tcl commands, for example.
  • proc: Defines a Tcl procedure that is accessible within the object's definition space. The definition must be a procedure specification (name, arguments, body).
  • const: Defines a constant on the object. The definition must be a constant specification (name, value).

The definition argument varies according to the type:

For method, slot, variable, proc, const:
The definition is typically a list of arguments and a Tcl script body, as used by the `oo::class define` command. For example:
oo::objdefine my_obj method foo {arg1 arg2} {
    # method body
}

For method and proc, the definition can also be just the method name, in which case it refers to a method defined in a mixin class or the object's parent class. For example:

oo::objdefine my_obj method bar

This makes the method named `bar` available on `my_obj`.

For code:
The definition is a Tcl script. For example:
oo::objdefine my_obj code {
    set my_var 10
    puts "Initialized my_var"
}

Multiple definitions can be provided in a single command. The definitions are processed in the order they appear.

The oo::objdefine command is often used in conjunction with `oo::objdefine renamemethod` and `oo::objdefine mixin`.

SLOTTED DEFINITIONS

This section demonstrates the use of `oo::objdefine` for defining methods and slots, and how they interact with class definitions.

oo::object create foo
foo configure → error "unknown method configure"
oo::objdefine foo method configure {args} {
    puts "configuring foo with args: $args"
}

Now, the `configure` method is available on the `foo` object:

foo configure → configuring foo with args: 
foo configure -x 10 -y 20 → configuring foo with args: -x 10 -y 20

This example shows how to define a slot on an object:

oo::object create bar
oo::objdefine bar slot color "red"

Accessing the slot:

bar color → prints "red"
bar color blue → prints "blue"
bar color → prints "blue"

This example shows how to rename a method:

oo::object create lollipop
oo::objdefine lollipop method hello {msg} {
    puts $msg
}
oo::objdefine lollipop renamemethod hello world
lollipop world "hello world" → prints "hello world"
lollipop hello "hello world" → error "unknown method hello"
o foo                → error "unknown method foo"
o Foo Bar            → error "unknown method Foo"
oo::objdefine o renamemethod bar lollipop
o lollipop           → prints "hello world"

This example shows how additional classes can be mixed into an object. It also shows how mixin is a slot that supports appending:

oo::object create inst
inst m1              → error "unknown method m1"
inst m2              → error "unknown method m2"
oo::class create A {
    method m1 {} {
        puts "red brick"
    }
}
oo::objdefine inst {
    mixin A
}
inst m1              → prints "red brick"
inst m2              → error "unknown method m2"
oo::class create B {
    method m2 {} {
        puts "blue brick"
    }
}
oo::objdefine inst {
    mixin -append B
}
inst m1              → prints "red brick"
inst m2              → prints "blue brick"
