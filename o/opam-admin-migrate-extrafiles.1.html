OPAM ADMIN-MIGRATE-EXTRAFILES(1) Manual de administración de Opam OPAM ADMIN-MIGRATE-EXTRAFILES(1)

NOMBRE

opam admin-migrate-extrafiles - Mover archivos extra a extra-source.

SINOPSIS

opam admin migrate-extrafiles [--hash=ALGORITMO_HASH] [--packages=PAQUETES] [OPCIÓN]… DIR URL

DESCRIPCIÓN

Este comando escanea las definiciones de paquetes y migra los campos extra-files a extra-source según se solicite.

ARGUMENTOS

DIR (requerido)
Nombre del directorio local donde colocar los archivos extra. Se colocarán en DIR/patches/<nombrepaquete>/<nombrepaquete.versión>/filenameYY
URL (requerido)
Prefijo de la URL a emitir en extra-sources.

OPCIONES

--hash=ALGORITMO_HASH (ausente=sha256)
El hash, o los hashes, a añadir
-p PAQUETES, --packages=PAQUETES
Solo añadir archivos extra para los paquetes dados

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Nota que no todos los solucionadores externos pueden soportar esta opción (versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Usar la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Destinado a cualquier uso persistente de opam (scripts, entradas de blog, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. El flag no estaba disponible en opam 2.0, así que para seleccionar la CLI 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorear la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o sí-inseguro. Se puede especificar más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especificar las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para detalles sobre el lenguaje soportado y los solucionadores externos disponibles, ver http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre cómo usar las preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBRE_ARCHIVO
Opción de depuración: Guardar las solicitudes CUDF enviadas al solucionador en NOMBRE_ARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprimir mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Igual que --debug, pero permite especificar el nivel de depuración (--debug lo establece a 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprimir la versión git de opam, si está configurada (es decir, si está usando una versión de desarrollo), y salir.
--help[=FMT] (default=auto)
Mostrar esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o no esté definida.
--ignore-pin-depends
Ignorar pines adicionales requeridos por paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBRE_ARCHIVO
Guardar los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%', se reemplazará por un índice que no sobrescribirá un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responder no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio que está escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
-q, --quiet
Deshabilita --verbose.
--root=RAÍZ
Usar RAÍZ como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a RAÍZ.
--safe, --readonly
Asegurarse de que nada se actualice o reescriba automáticamente. Útil para llamar desde scripts de finalización, por ejemplo. Fallará siempre que se necesite tal operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especificar el solucionador CUDF a usar para resolver problemas de instalación de paquetes. Este es un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Fallar siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. Por defecto, continúa silenciosamente si es posible.
--switch=SWITCH
Usar SWITCH como el switch de compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilitar cualquier solucionador externo y usar el incorporado (esto requiere que opam se haya compilado con un solucionador incorporado). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Ser más verboso. Una -v muestra todos los comandos de paquetes, repítalo para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Mostrar información de la versión.
-w, --working-dir
Siempre que se actualicen paquetes vinculados a un directorio local y controlado por versiones, actualizar al estado de trabajo actual de su fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio fuente se copia tal cual, si no está limpio, puede resultar en un fallo en la compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responder sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

AMBIENTE

Opam utiliza las variables de entorno listadas aquí. Las variables booleanas deben establecerse a "0", "no", "false" o la cadena vacía para deshabilitar, "1", "yes" o "true" para habilitar.

OPAMALLPARENS rodea todos los filtros con paréntesis.

OPAMASSUMEDEPEXTS ver opción `--assume-depexts'.

OPAMAUTOREMOVE ver opción remove `--auto-remove'.

OPAMBESTEFFORT ver opción `--best-ef

VARIABLES DE ENTORNO DE OPAM

OPAMBESTEFFORTPREFIXCRITERIA establece la cadena que debe añadirse a los criterios cuando se activa la opción --best-effort, y se espera que maximice la propiedad `opam-query' en la solución.

OPAMBUILDDOC Eliminada en 2.1.

OPAMBUILDTEST Eliminada en 2.1.

OPAMCLI véase la opción --cli.

OPAMCOLOR cuando se establece en always o never, establece un valor predeterminado para la opción --color.

OPAMCONFIRMLEVEL véase la opción --confirm-level. OPAMCONFIRMLEVEL tiene prioridad sobre OPAMYES y OPAMNO.

OPAMCRITERIA especifica las preferencias del usuario para la resolución de dependencias. El valor predeterminado depende de la versión del solucionador, use `config report' para conocer la configuración actual. Véase también la opción --criteria.

OPAMCUDFFILE guarda el grafo cudf en file-actions-explicit.dot.

OPAMCUDFTRIM controla el filtrado de paquetes no relacionados durante el preprocesamiento CUDF.

OPAMCURL se puede usar para seleccionar un programa 'curl' determinado. Véase OPAMFETCH para más opciones.

OPAMDEBUG véase las opciones --debug y --debug-level.

OPAMDEBUGSECTIONS si está establecida, limita los mensajes de depuración a la lista de secciones separadas por espacios. Las secciones pueden tener opcionalmente un nivel de depuración específico (por ejemplo, CLIENT:2 o CLIENT CUDF:2), pero de lo contrario usan --debug-level.

OPAMDIGDEPTH define qué tan agresiva es la búsqueda de conflictos durante el preprocesamiento CUDF.

OPAMDOWNLOADJOBS establece el número máximo de descargas simultáneas.

OPAMDROPWORKINGDIR anula los paquetes previamente actualizados con --working-dir en la actualización. Sin esta variable establecida, opam los mantendría sin cambios a menos que se nombren explícitamente en la línea de comandos.

OPAMDRYRUN véase la opción --dry-run.

OPAMEDITOR establece el editor a usar para editar archivos opam, anula $EDITOR y $VISUAL.

OPAMERRLOGLEN establece el número de líneas de registro que se imprimen cuando falla un subproceso. 0 para imprimir todas.

OPAMEXTERNALSOLVER véase la opción --solver.

OPAMFAKE véase la opción --fake.

OPAMFETCH especifica cómo descargar archivos: `wget', `curl' o un comando personalizado donde las variables %{url}%, %{out}%, %{retry}%, %{compress}% y %{checksum}% serán reemplazadas. Anula el valor de 'download-command' del archivo de configuración principal.

OPAMFIXUPCRITERIA igual que OPAMUPGRADECRITERIA, pero específico para fixup y reinstall.

OPAMIGNORECONSTRAINTS véase la opción de instalación --ignore-constraints-on.

OPAMIGNOREPINDEPENDS véase la opción --ignore-pin-depends.

OPAMINPLACEBUILD véase la opción --inplace-build.

OPAMJOBS establece el número máximo de trabajadores paralelos a ejecutar.

OPAMJSON registra la salida json en el archivo dado (use el carácter % para indexar los archivos).

OPAMKEEPBUILDDIR véase la opción de instalación --keep-build-dir.

OPAMKEEPLOGS indica a opam que no elimine algunos registros temporales de comandos y algunas copias de seguridad. Esto omite algunos finalizadores y también puede ayudar a obtener backtraces más confiables.

OPAMLOCKED combinación de las opciones --locked y --lock-suffix.

OPAMLOGS logdir establece el directorio de registros, el valor predeterminado es un directorio temporal en /tmp

OPAMMAKECMD establece el comando make del sistema a usar.

OPAMMERGEOUT fusiona las salidas del proceso, stderr en stdout.

OPAMNO responde no a cualquier pregunta realizada, véase las opciones --no y --confirm-level. OPAMNO se ignora si OPAMCONFIRMLEVEL u OPAMYES están establecidas.

OPAMNOAGGREGATE con `opam admin check', no agrega paquetes.

OPAMNOASPCUD Obsoleto.

OPAMNOAUTOUPGRADE deshabilita la actualización automática interna de repositorios en un formato anterior al actual, en 'update' o 'init'.

OPAMNOCHECKSUMS habilita la opción --no-checksums cuando está disponible.

OPAMNODEPEXTS deshabilita el manejo de dependencias del sistema, véase la opción --no-depexts.

OPAMNOENVNOTICE Interno.

OPAMNOSELFUPGRADE véase la opción --no-self-upgrade

OPAMPINKINDAUTO establece si los sistemas de control de versiones deben detectarse al fijar una ruta local. Habilitado por defecto desde 1.3.0.

OPAMPRECISETRACKING seguimiento detallado de directorios.

OPAMPREPRO establezca esto en falso para deshabilitar el preprocesamiento CUDF. Menos eficiente, pero podría ayudar a depurar problemas del solucionador.

OPAMREPOSITORYTARRING almacena internamente los repositorios como archivos tar.gz. Esto puede ser mucho más rápido en sistemas de archivos que no manejan bien el escaneo de árboles grandes pero que tienen buena caché en /tmp. Sin embargo, es más lento en el caso general.

OPAMREQUIRECHECKSUMS habilita la opción `--require-checksums' cuando está disponible (por ejemplo, para `opam install').

OPAMRETRIES establece el número de intentos antes de que las descargas fallen.

OPAMREUSEBUILDDIR véase la opción --reuse-build-dir.

OPAMROOT véase la opción --root. Esto se establece automáticamente mediante `opam env --root=DIR --set-root'.

OPAMROOTISOK no se queja al ejecutarse como root.

OPAMSAFE véase la opción --safe.

OPAMSHOW véase la opción --show.

OPAMSKIPUPDATE véase la opción --skip-updates.

OPAMSKIPVERSIONCHECKS omite algunas verificaciones de versión. Inseguro, solo para pruebas de compatibilidad.

OPAMSOLVERALLOWSUBOPTIMAL (predeterminado `true') permite que algunos solucionadores devuelvan una solución cuando alcanzan el tiempo límite; si bien se asegura que la solución sea consistente, no hay garantía en este caso de que se ajuste a los criterios de optimización esperados. Si es `true', opam continuará con una advertencia; si es `false', un tiempo límite es un error. Actualmente, solo el backend builtin-z3 maneja este caso degradado.

OPAMSOLVERTIMEOUT cambia el tiempo de asignación del solucionador. El valor predeterminado es 60.0, establecido en 0 para ilimitado. Tenga en cuenta que no todos los solucionadores pueden admitir esta opción.

OPAMSOLVERTOLERANCE cambia la tolerancia hacia que el solucionador elija una solución no optimizada (es decir, puede extraer paquetes desactualizados). Los valores típicos varían de 0.0 (mejor solución conocida por el solucionador) a 1.0 (solución no optimizada). El valor predeterminado es 0.0. Esta opción es útil en caso de que el solucionador no pueda encontrar una solución en un tiempo razonable (véase $OPAMSOLVERTIMEOUT). Tenga en cuenta que no todos los solucionadores pueden admitir esta opción.

OPAMSTATS Eliminada en 2.4.

OPAMSTATUSLINE muestra una línea de estado dinámica que indica lo que está sucediendo actualmente en la terminal. (uno de always, never o auto)

OPAMSTRICT falla ante inconsistencias (lectura de archivos, importación de switch, etc.).

OPAMSWITCH véase la opción --switch. Se establece automáticamente mediante `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE véase la opción de instalación --unlock-base.

OPAMUPGRADECRITERIA especifica las preferencias del usuario para la resolución de dependencias al realizar una actualización. Anula OPAMCRITERIA en las actualizaciones si ambas están establecidas. Véase también la opción --criteria.

OPAMUSEINTERNALSOLVER véase la opción --use-internal-solver.

OPAMUSEOPENSSL Eliminada en 2.2.

OPAMUTF8 usa caracteres UTF8 en la salida (uno de always, never o auto). Por defecto `auto', que se determina a partir de la configuración regional).

OPAMUTF8MSGS usa caracteres UTF8 extendidos (camellos) en los mensajes de opam. Implica OPAMUTF8. Esto está establecido por defecto solo en macOS.

OPAMVALIDATIONHOOK si está establecida, utiliza el comando `%{hook%}' para validar una actualización del repositorio opam.

OPAMVERBOSE véase la opción --verbose.

OPAMVERBOSEON véase la opción --verbose-on

OPAMVERSIONLAGPOWER no usar.

OPAMWITHDEVSETUP véase la opción de instalación --with-dev-setup.

OPAMWITHDOC véase la opción de instalación --with-doc.

OPAMWITHTEST véase la opción de instalación --with-test.

OPAMWORKINGDIR véase la opción --working-dir.

OPAMYES véase las opciones --yes y --confirm-level. OPAMYES tiene prioridad sobre OPAMNO y se ignora si OPAMCONFIRMLEVEL está establecida.

OPAMVAR_var anula el contenido de la variable var al sustituir las cadenas `%{var}%' en los archivos `opam'.

OPAMVAR_package_var anula el contenido de la variable package:var al sustituir las cadenas `%{package:var}%' en los archivos `opam'.

VERSIÓN DEL CLI

Todos los scripts e invocaciones programáticas de opam deben usar `--cli' para asegurar que funcionen sin problemas con versiones futuras del cliente opam. Además, las publicaciones de blog u otra documentación pueden beneficiarse, ya que evita que la información se desactualice.

Aunque opam solo admite raíces (~/.opam/) para la versión actual, proporciona compatibilidad retroactiva para su interfaz de línea de comandos.

Dado que el soporte de la versión CLI solo se agregó en opam 2.1, use OPAMCLI para seleccionar el soporte 2.0 (ya que opam 2.0 lo ignorará), y `--cli=2.1' para versiones 2.1 (o posteriores), ya que una variable de entorno que controla el análisis de sintaxis es frágil. Con este fin, opam muestra una advertencia si OPAMCLI especifica una versión válida que no sea 2.0, y también si se especifica `--cli=2.0'.

La versión de la línea de comandos se selecciona utilizando la opción `--cli' o la variable de entorno OPAMCLI. `--cli' puede especificarse más de una vez, donde la última instancia tiene precedencia. OPAMCLI solo se inspecciona si no se proporciona `--cli'.

ESTADO DE SALIDA

Como excepción a lo siguiente, el comando `exec' devuelve 127 si el comando no se encontró o no se pudo ejecutar, y el valor de salida del comando en caso contrario.

0
Éxito, o verdadero para consultas booleanas.
1
Falso. Devuelto cuando se espera un valor de retorno booleano, por ejemplo, al ejecutarse con --check, o para consultas como opam lint.
2
Argumentos de línea de comandos incorrectos, o argumentos de línea de comandos que apuntan a un contexto inválido (por ejemplo, archivo que no sigue el formato esperado).
5
No encontrado. Solicitó algo (paquete, versión, repositorio, etc.) que no se pudo encontrar.
10
Abortado. La operación requería confirmación, que no se dio.
15
No se pudieron adquirir los bloqueos requeridos para la operación.
20
29
No hay solución para la solicitud del usuario. Esto puede deberse a que se solicita la instalación de dos paquetes incompatibles, por ejemplo.
30
Error en la definición del paquete o en otros archivos de metadatos. El uso de --strict genera este error con más frecuencia.
31
Error en el script del paquete. Algunas operaciones del paquete no tuvieron éxito. Puede ser un error en los paquetes o una incompatibilidad con su sistema. Esto puede ser un error parcial.
40
Error de sincronización. No se pudieron obtener algunos remotos de la red. Esto puede ser un error parcial.
50
Error de configuración. La configuración de opam o del sistema no permite la operación y necesita ser corregida.
60
Fallo del solucionador. El solucionador no pudo devolver una respuesta sólida. Puede deberse a un solucionador externo dañado o a un error en la configuración del solucionador.
99
Error interno. Algo salió mal, probablemente debido a un error en opam en sí.
130
Interrupción del usuario. Se recibió SIGINT, generalmente debido a que el usuario presionó Ctrl-C.
0
En caso de éxito.
123
En errores indiscriminados reportados en la salida estándar.
124
En errores de análisis de la línea de comandos.
125
En errores internos inesperados (bugs).
