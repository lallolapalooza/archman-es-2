ogmmerge(1)

OGMMERGE(1) Comandos de usuario OGMMERGE(1)

NOMBRE

ogmmerge - Fusionar flujos multimedia en un archivo OGG/OGM

SINOPSIS

ogmmerge [opciones globales] -o salida [opciones] <archivo1> [[opciones] <archivo2> ...]

DESCRIPCIÓN

Este programa toma la entrada de varios archivos multimedia y une sus flujos (todos o solo una selección) en un OGM. Anteriormente se conocía como 'oggmerge' y se basa en el módulo CVS 'oggmerge' del repositorio de Xiph <http://www.xiph.org/>.

Opciones globales:

-v, --verbose
Aumenta la verbosidad.
-q, --quiet
Suprime la salida de estado.
-o, --output salida
Escribe en el archivo 'salida'.

Opciones que se pueden usar para cada archivo de entrada:

-a, --astreams <n,m,...>
Copia el flujo de audio número n, NO el flujo con el número de serie n. Por defecto: copia todos los flujos de audio.
-d, --vstreams <n,m,...>
Copia el flujo de video número n, NO el flujo con el número de serie n. Por defecto: copia todos los flujos de video.
-t, --tstreams <n,m,...>
Copia el flujo de texto número n, NO el flujo con el número de serie n. Por defecto: copia todos los flujos de texto.
-A, --noaudio
No copies ningún flujo de audio de este archivo.
-D, --novideo
No copies ningún flujo de video de este archivo.
-T, --notext
No copies ningún flujo de texto de este archivo.
-s, --sync <d[,o[/p]]>
Sincroniza manualmente, retrasa el flujo de audio en d ms.
d > 0: Rellena con muestras silenciosas.
d < 0: Elimina muestras del principio.
o/p: ajusta las marcas de tiempo en o/p para corregir derivas lineales. p por defecto es 1000 si se omite. Tanto o como p pueden ser números de punto flotante.
Por defecto: sin corrección de sincronización manual (que es lo mismo que d = 0 y o/p = 1.0).
-r, --range <inicio-fin>
Procesa solo desde inicio hasta fin. Ambos valores toman el formato 'HH:MM:SS.mmm' o 'SS.mmm', por ejemplo, '00:01:00.500' o '60.500'. Si se omite inicio o fin, se establecerá por defecto a 0 o al final del archivo respectivamente.
Si deseas dividir un archivo en otros más pequeños, te sugiero encarecidamente que uses ogmsplit(1), ya que puede hacer un trabajo mucho mejor que usar la opción -r.
-c, --comment 'A=B#C=D' o '@nombre_archivo'
Establece campos de comentarios adicionales para los flujos. Valores sensibles serían 'LANGUAGE=English' o 'TITLE=Ally McBeal'. Si el parámetro comienza con '@', los comentarios se leerán de un archivo con el mismo nombre sin el '@' inicial. Se puede especificar -c varias veces por archivo. Todos los comentarios se concatenarán.
-f, --fourcc <FourCC>
Fuerza el FourCC al valor especificado. Funciona solo para flujos de video. Ten en cuenta que no puedes simplemente usar un editor hexadecimal y cambiar el FourCC manualmente, ya que el formato de archivo OGG utiliza sumas de verificación que serían incorrectas después de tal cambio.
--omit-empty-packets
Normalmente, cuando se debe eliminar una entrada de subtítulo, se crea un paquete vacío y se inserta con la marca de tiempo apropiada. Con esta opción, estos paquetes vacíos se omiten por completo.
--old-headers
Asume que el archivo de entrada ha sido creado con una versión anterior de ogmmerge (< 1.1). Esto puede ser necesario si ogmmerge no puede leer dicho archivo correctamente.
--nav-seek <nombre_archivo>
Usa un archivo de índice AVI externo generado por aviindex del paquete transcode. Se puede usar si un archivo AVI tiene un índice corrupto.

Otras opciones:

-l, --list-types
Lista los tipos de archivo de entrada admitidos.
-h, --help
Muestra información de uso.
-V, --version
Muestra información de la versión.

USO

Para cada archivo, el usuario puede seleccionar qué pistas debe tomar ogmmerge. Todas se colocan en el archivo especificado con '-o'. Una lista de formatos de origen conocidos (y admitidos) se puede obtener con la opción '-l'.

EJEMPLOS

Supongamos que tienes un archivo llamado MiPelícula.avi y la pista de audio en un archivo separado, por ejemplo, MiPelícula.wav. Primero, querrás codificar el audio a OGG:

$ oggenc -q4 -oMiPelícula.ogg MiPelícula.wav

Después de un par de minutos, puedes unir el video y el audio:

$ ogmmerge -o MiPelícula-con-sonido.ogm MiPelícula.avi MiPelícula.ogg

Si tu AVI ya contiene una pista de audio, también se copiará (si ogmmerge admite el formato de audio). Para evitarlo, simplemente haz:

$ ogmmerge -o MiPelícula-con-sonido.ogm -A MiPelícula.avi MiPelícula.ogg

Después de unos minutos de consideración, extraes otra pista de audio, por ejemplo, los comentarios del director u otro idioma, a MiPelícula-audio-adicional.wav. Codifícala de nuevo y únala con el otro archivo:

$ oggenc -q4 -oMiPelícula-audio-adicional.ogg MiPelícula-audio-adicional.wav
$ ogmmerge -o MM-completa.ogm MiPelícula-con-sonido.ogm MiPelícula-audio-adicional.ogg

Se puede lograr el mismo resultado con:

$ ogmmerge -o MM-completa.ogm -A MiPelícula.avi MiPelícula.ogg \
MiPelícula-audio-adicional.ogg

Ahora inicia mplayer y disfruta. Si tienes múltiples pistas de audio (o incluso de video), puedes indicarle a mplayer qué pista reproducir con los parámetros '-vid' y '-aid'. Estos son basados en 0 y no distinguen entre video y audio.

Si necesitas que una pista de audio esté sincronizada, puedes hacerlo fácilmente con:

$ ogmmerge -o buenasonc.ogm -A origen.avi -s 200 fuera_de_sinc.ogg

Esto añadiría 200 ms de silencio al principio de las pistas de audio tomadas de fuera_de_sinc.ogg. Y -s siempre se aplica a todas las pistas de audio en un archivo de origen. Si deseas aplicar -s solo a una pista específica, toma el mismo archivo de origen varias veces y añade -a y -s en consecuencia.

Algunas películas comienzan sincronizadas correctamente pero lentamente se desincronizan. Para este tipo de películas, puedes especificar un factor de retraso que se aplica a todas las marcas de tiempo; no se agregan ni se eliminan datos. Por lo tanto, si haces que ese factor sea demasiado grande o demasiado pequeño, obtendrás malos resultados. Un ejemplo es que un episodio que transcodifiqué estaba desincronizado 0.2 segundos al final de la película, que tenía 77340 fotogramas. A 29.97 fps, 0.2 segundos corresponden aproximadamente a 6 fotogramas. Así que hice:

$ ogmmerge -o buenasonc.ogm -s 0,77346/77340 fuera_de_sinc.ogm

El resultado fue bueno.

Las opciones de sincronización también se pueden usar para subtítulos de la misma manera.

Para subtítulos de texto, puedes usar algún software de Windows (como SubRipper) o el paquete subrip que se encuentra en las fuentes de transcode(1) (en contrib/subrip). El proceso general es:

1.
extraer un flujo de subtítulos sin procesar del origen:
$ tccat -i /ruta/al/dvd/copiado/ -T 1 -L | \
tcextract -x ps1 -t vob -a 0x20 | \
subtitle2pgm -o mi_pelicula
2.
convertir las imágenes PGM resultantes a texto con gocr:
$ pgm2txt mi_pelicula
3.
corregir la ortografía de los archivos de texto resultantes:
$ ispell -d america

EXAMPLES

\n

Merge two AVI files and an OGG file into a new OGM file:

\n

$ ogmmerge -o mymovie.ogm mymovie.avi movie_part2.avi intro.ogg

\n

Add a title and select specific audio and video streams:

\n

$ ogmmerge -o mymovie.ogm -c TITLE=\"My Awesome Movie\" \\n
\n -v 0 -a 1 mymovie.avi

\n

Add a subtitle track from a SRT file:

\n

First convert the SRT file to the OGM text stream format\n (srttool is part of the ogmtools package):

\n
    $ mkfifo mypipe.srtx\n    $ srttool -s -w -i mymovie.srt -o mypipe.srtx &\n
\n

Then merge it with the video and audio:

\n

$ ogmmerge -o mymovie.ogm mymovie.avi mypipe.srtx

\n

Alternatively, you can convert the text files to a SRT file first:\n
\n $ srttool -s -w -i mymovie.srtx -o mymovie.srt

\n

The resulting file can be used as another input file for\n ogmmerge:

\n

$ ogmmerge -o mymovie.ogm -c 'TITLE=My Movie' mymovie.avi \\n
\n -c LANGUAGE=English mymovie.ogg -c LANGUAGE=English mymovie.srt

FILE SIZE

\n

Using OGG as the container format introduces overhead - each OGG\n packet has a header, and each OGG packet can span one or more OGG pages,\n which itself again contain headers. Several tests show that the overhead is\n bigger than the overhead introduced by AVI (comparing video only files and\n files with video and MP3 audio).

\n

The overhead is defined as file size - raw stream\n size. mencoder prints the raw stream size after encoding, so\n you'll be able to get that information rather easily.

\n

Most of the times you want to calculate the overhead prior to\n encoding in order to adjust the bitrate accordingly. Unfortunately the\n overhead per frame is not constant - only the percentage is constant. This\n percentage is calculated as 100 * (OGG size - raw size) /\n raw size and seems to be somewhere between 1.1% and\n 1.2%. This depends on the number of streams and the stream types\n used.

\n

The raw size itself can be approximated by\n
\n frames * vbitrate\n
\n raw size = ( ----------------- + length * abitrate ) / 8\n * 1000 * 1024\n
\n frames per sec\n
\n assuming that vbitrate and abitrate are given in kbit/s = 1000\n bit/s, and length is given in seconds.

CHAPTERS

\n

ogmmerge supports chapter information as generated by\n dvdxchap(1). The format is very simple:

\n

CHAPTER01=HH:MM:SS.sss\n
\n CHAPTER01NAME=the first chapter\n
\n CHAPTER02=HH:MM:SS.sss\n
\n CHAPTER02NAME=another chapter

\n

with HH = hour, MM = minute, SS = seconds, sss = milliseconds.

\n

The chapter information is stored in the video stream's comments.\n Therefore you could also specify the chapters with -c CHAPTER01=...\n Using a chapter file has an advantage: If the video stream's comments\n already contain chapter information and the command line contains a chapter\n information file then the existing chapter information will be completely\n replaced.

TECHNICAL ASPECTS

\n

This section is not needed by the average user.

\n

ogmmerge consists of three parts:

\n
\n
*
\n
Demultiplexers (called readers) open and read input files specified on the\n command line and extract specific tracks.
\n
*
\n
Packetizers (or output modules) take data from a demultiplexer and\n encapsulate them into OGG pages. These are stored in queues.
\n
*
\n
The main program requests from every known demultiplexer that it should\n read some data. It then gets the OGG page with the smallest timestamp from\n all the packetizer queues. This page is written to the output file.
\n
\n

The general class definitions for the readers and the packetizers\n can be found in ogmmerge.h.

\n

The main loop expects that the queues managed by the demuxer's\n packetizers are filled with at least one page after a call to the demuxer's\n read() function. The demuxer must make sure that enough data is\n passed to each of its associated packetizers. Have a look at\n r_ogm.cpp.

\n

A possible setup might look like this:

\n

\n
\n +-> p_video\n
\n +-> r_avi -+\n
\n | +-> p_pcm\n
\n | \n
\n ogmmerge -+-> r_ogm ---> p_vorbis\n
\n | \n
\n | +-> p_video\n
\n | | \n
\n +-> r_ogm -+-> p_vorbis\n
\n | \n
\n +-> p_vorbis

\n

One AVI source with a video and an audio track, one OGG/OGM source\n with only one Vorbis track, another OGG/OGM source with a video and two\n Vorbis tracks.
