DESCRIPCIÓN

Este comando implementa un cliente genérico SSL/TLS que se conecta a un host remoto usando SSL/TLS. Es una herramienta de diagnóstico *muy* útil para servidores SSL.

OPCIONES

Además de las opciones que se detallan a continuación, este comando también admite las opciones comunes y exclusivas para clientes documentadas en la sección "Comandos de Línea de Comandos Soportados" de la página del manual de SSL_CONF_cmd(3).

-help
Muestra un mensaje de uso.
-ssl_config sección
Utiliza la sección especificada del archivo de configuración para configurar el objeto SSL_CTX.
-connect host:puerto
Esto especifica el host y el puerto opcional al que conectarse. Es posible seleccionar el host y el puerto utilizando el argumento posicional de destino opcional en su lugar. Si no se especifica ni esto ni el argumento posicional de destino, se intentará conectar al host local en el puerto 4433. Si la cadena de host es una dirección IPv6, debe estar encerrada entre "[" y "]".
-host nombrehost
Host al que conectarse; usar -connect en su lugar.
-port puerto
Conectar al puerto especificado; usar -connect en su lugar.
-bind host:puerto
Esto especifica la dirección del host y/o el puerto a vincular como origen de la conexión. Para sockets de dominio Unix, se ignora el puerto y el host se utiliza como la dirección del socket de origen. Si la cadena de host es una dirección IPv6, debe estar encerrada entre "[" y "]".
-proxy host:puerto
Cuando se usa con el flag -connect, el programa utiliza el host y el puerto especificados con este flag y emite un comando HTTP CONNECT para conectarse al servidor deseado. Si la cadena de host es una dirección IPv6, debe estar encerrada entre "[" y "]".
-proxy_user idusuario
Cuando se usa con el flag -proxy, el programa intentará autenticarse con el proxy especificado usando autenticación básica (base64). NOTA: La autenticación básica no es segura; las credenciales se envían al proxy codificadas en base64, fácilmente reversible, antes de que se establezca cualquier sesión TLS/SSL. Por lo tanto, estas credenciales pueden ser recuperadas fácilmente por cualquiera que pueda espiar/rastrear la red. Úselo con precaución.
-proxy_pass arg
La fuente de la contraseña del proxy, utilizada con el flag -proxy_user. Para más información sobre el formato de arg ver openssl-passphrase-options(1).
-unix ruta
Co
-4
Usar solo IPv4.
-6
Usar solo IPv6.
-quic
Conectar usando el protocolo QUIC. Si se especifica, la opción -alpn debe proporcionarse también.
-servername nombre
Establecer la extensión SNI (Server Name Indication) de TLS en el mensaje ClientHello al valor dado. Si no se proporciona -servername, la extensión SNI de TLS se poblará con el nombre dado a -connect si sigue un formato de nombre DNS. Si tampoco se proporciona -connect, el SNI se establece en "localhost". Esto es lo predeterminado desde OpenSSL 1.1.1.

Aunque SNI normalmente debería ser un nombre DNS y no una dirección IP, si se proporciona -servername, se enviará ese nombre, independientemente de si es un nombre DNS o no.

Esta opción no se puede usar junto con -noservername.

-noservername
Suprime el envío de la extensión SNI (Server Name Indication) en el mensaje ClientHello. No se puede usar junto con las opciones -servername o -dane_tlsa_domain.
-cert nombre_archivo
El certificado del cliente a usar, si el servidor lo solicita. El valor predeterminado es no usar un certificado.

La cadena para el certificado del cliente se puede especificar usando -cert_chain.

-certform DER|PEM|P12
El formato del archivo del certificado del cliente a usar; no especificado por defecto. Ver openssl-format-options(1) para detalles.
-cert_chain
Un archivo o URI de certificados no confiables a usar al intentar construir la cadena de certificados relacionada con el certificado especificado a través de la opción -cert. La entrada puede estar en formato PEM, DER o PKCS#12.
-build_chain
Especifica si la aplicación debe construir la cadena de certificados del cliente para proporcionarla al servidor.
-CRL nombre_archivo
Archivo CRL a usar para verificar el certificado del servidor.
-CRLform DER|PEM
El formato del archivo CRL; no especificado por defecto. Ver openssl-format-options(1) para detalles.
-crl_download
Descarga CRL de los puntos de distribución en el certificado. Tenga en cuenta que esta opción se ignora si la opción -crl_check no se proporciona. Tenga en cuenta que el tamaño máximo de CRL está limitado por la función X509_CRL_load_http(3).
-key nombre_archivo|uri
La clave privada del cliente a usar. Si no se especifica, el archivo del certificado se usará también para leer la clave.
-keyform DER|PEM|P12|ENGINE
El formato de la clave; no especificado por defecto. Ver openssl-format-options(1) para detalles.
-pass arg
la fuente de la contraseña del archivo de clave privada y certificado. Para más información sobre el formato de arg ver openssl-passphrase-options(1).
-verify profundidad
La profundidad de verificación a usar. Esto especifica la longitud máxima de la cadena de certificados del servidor y activa la verificación del certificado del servidor. A menos que se proporcione la opción -verify_return_error, la operación de verificación continúa después de los errores, de modo que se puedan ver todos los problemas con una cadena de certificados. Como efecto secundario, la conexión nunca fallará debido a un fallo de verificación del certificado del servidor.

Por defecto, la validación de los certificados del servidor y su cadena se realiza con respecto al propósito (D)TLS Server ("sslserver"). Para más detalles ver "Certificate Extensions" en openssl-verification-options(1).

-verify_return_error
Activa la verificación del certificado del servidor, como con -verify, pero devuelve los errores de verificación en lugar de continuar. Esto normalmente abortará el handshake con un error fatal.
-verify_quiet
Limita la salida de verificación solo a los errores.
-verifyCAfile nombre_archivo
Un archivo en formato PEM que contiene certificados confiables a usar para verificar el certificado del servidor.
-verifyCApath directorio
Un directorio que contiene certificados confiables a usar para verificar el certificado del servidor. Este directorio debe estar en "formato hash", ver openssl-verify(1) para más información.
-verifyCAstore uri
La URI de un almacén que contiene certificados confiables a usar para verificar el certificado del servidor.
-chainCAfile archivo
Un archivo en formato PEM que contiene certificados confiables a usar al intentar construir la cadena de certificados del cliente.
-chainCApath directorio
Un directorio que contiene certificados confiables a usar para construir la cadena de certificados del cliente proporcionada al servidor. Este directorio debe estar en "formato hash", ver openssl-verify(1) para más información.
-chainCAstore uri
La URI de un almacén que contiene certificados confiables a usar al intentar construir la cadena de certificados del cliente. La URI puede indicar un solo certificado, así como una colección de ellos. Con URIs en el esquema "file:", esto actúa como -chainCAfile o -chainCApath, dependiendo de si la URI indica un directorio o un solo archivo. Ver ossl_store-file(7) para más información sobre el esquema "file:".
-requestCAfile archivo
Un archivo que contiene una lista de certificados cuyos nombres de sujeto se enviarán al servidor en la extensión certificate_authorities. Solo compatible con TLS 1.3.
-dane_tlsa_domain dominio
Habilita la autenticación DANE TLSA de RFC6698/RFC7671 y especifica el dominio base TLSA que se convierte en la pista SNI predeterminada y el identificador de referencia principal para las comprobaciones del nombre de host. Debe usarse en combinación con al menos una instancia de la opción -dane_tlsa_rrdata a continuación.

Cuando la autenticación DANE tiene éxito, la salida de diagnóstico incluirá la profundidad más baja (más cercana a 0) en la que un registro TLSA autenticó un certificado de cadena. Cuando ese registro TLSA es un ancla de confianza pública "2 1 0" que firmó (en lugar de coincidir con) el certificado de nivel superior de la cadena, el resultado se informa como "TA public key verified". De lo contrario, o bien el registro TLSA "matched TA certificate" en una profundidad positiva o bien "matched EE certificate" en la profundidad 0.

-dane_tlsa_rrdata rrdata
Se usa una o más veces para especificar los campos RRDATA del conjunto RR DANE TLSA asociado con el servicio objetivo. El valor rrdata se especifica en "forma de presentación", es decir, cuatro campos separados por espacios en blanco que especifican el uso, el selector, el tipo de coincidencia y los datos asociados, siendo este último codificado en hexadecimal. Se ignoran los espacios en blanco opcionales en el campo de datos asociados. Por ejemplo: 
$ openssl s_client -brief -starttls smtp \
  -connect smtp.example.com:25 \
  -dane_tlsa_domain smtp.example.com \
  -dane_tlsa_rrdata "2 1 1
    B111DD8A1C2091A89BD4FD60C57F0716CCE50FEEFF8137CDBEE0326E 02CF362B" \
  -dane_tlsa_rrdata "2 1 1
    60B87575447DCBA2A36B7D11AC09FB24A9DB406FEE12D2CC90180517 616E8A18"
...
Verification: OK
Verified peername: smtp.example.com
DANE TLSA 2 1 1 ...ee12d2cc90180517616e8a18 matched TA certificate at depth 1
...
-dane_ee_no_namechecks
Esto deshabilita las comprobaciones del nombre del servidor al autenticarse a través de registros TLSA DANE-EE(3). Para algunas aplicaciones, principalmente navegadores web, no es seguro deshabilitar las comprobaciones de nombre debido a ataques de "clave compartida desconocida", en los que un servidor malicioso puede convencer a un cliente de que una conexión a un servidor víctima es en realidad una conexión segura al servidor malicioso. El servidor malicioso puede entonces violar las restricciones de scripting entre orígenes. Por lo tanto, a pesar del texto de RFC7671, las comprobaciones de nombre están habilitadas por defecto para los registros TLSA DANE-EE(3), y se pueden deshabilitar en aplicaciones donde sea seguro hacerlo. En particular, los clientes SMTP y XMPP deben establecer esta opción ya que los registros SRV y MX permiten que un dominio remoto redirija las conexiones del cliente a cualquier servidor de su elección, y en cualquier caso los clientes SMTP y XMPP no ejecutan scripts descargados de servidores remotos.
-reconnect
Se reconecta al mismo servidor 5 veces usando el mismo ID de sesión, esto se puede usar como prueba de que el almacenamiento en caché de sesiones está funcionando.
-showcerts
Muestra la lista de certificados del servidor tal como la envía el servidor: solo consta de los certificados que el servidor ha enviado (en el orden en que el servidor los ha enviado). No es una cadena verificada.
-prexit
Imprime la información de la sesión cuando el programa sale. Siempre intentará imprimir información incluso si la conexión falla. Normalmente, la información solo se imprimirá una vez si la conexión tiene éxito. Th is option es útil porque el cifrado en uso puede ser renegociado o la conexión puede fallar porque se requiere un certificado de cliente o se solicita solo después de que se intenta acceder a una URL determinada. Nota: la salida producida por esta opción no siempre es precisa porque es posible que una conexión nunca se haya establecido.
-no-interactive
Esta bandera se puede usar para ejecutar el cliente en modo no interactivo.
-state
Imprime los estados de la sesión SSL.
-debug
Imprime información de depuración extensa, incluyendo un volcado hexadecimal de todo el tráfico.
-nocommands
No usar letras de comando interactivas.
-adv
Usar modo de comando avanzado.
-security_debug
Habilita mensajes de depuración de seguridad.
-security_debug_verbose
Genera más salida de depuración de seguridad.
-msg
Muestra mensajes del protocolo.
-timeout
Habilita el tiempo de espera de envío/recepción en conexiones DTLS.
-mtu tamaño
Establece la MTU de la capa de enlace al tamaño especificado.
-no_ems
Deshabilita la negociación de Extended master secret.
-keymatexport etiqueta
Exporta material de clave usando la etiqueta especificada.
-keymatexportlen len
Exporta el número especificado de bytes de material de clave; el valor predeterminado es 20.

Muestra todos los mensajes del protocolo con volcado hexadecimal.

-trace
Muestra una salida de rastreo detallada de los mensajes del protocolo.
-msgfile nombre_archivo
Archivo al que enviar la salida de -msg o -trace, por defecto salida estándar.
-nbio_test
Prueba E/S no bloqueante.
-nbio
Activa la E/S no bloqueante.
-crlf
Esta opción traduce un salto de línea de la terminal a CR+LF como lo requieren algunos servidores.
-ign_eof
Inhibe el cierre de la conexión cuando se alcanza el fin de archivo en la entrada. Esto activa implícitamente -nocommands también.
-quiet
Inhibe la impresión de información de sesión y certificado. Esto activa implícitamente -ign_eof y -nocommands también.
-no_ign_eof
Cierra la conexión cuando se alcanza el fin de archivo en la entrada. Se puede usar para anular el -ign_eof implícito después de -quiet.
-psk_identity identidad
Usa la identidad PSK identidad al usar un conjunto de cifrado PSK. El valor predeterminado es "Client_identity" (sin las comillas).
-psk clave
Usa la clave PSK clave al usar un conjunto de cifrado PSK. La clave se proporciona como un número hexadecimal sin el prefijo 0x, por ejemplo, -psk 1a2b3c4d. Esta opción debe proporcionarse para usar un cifrado PSK.
-psk_session archivo
Usa los datos de sesión SSL codificados en formato pem almacenados en archivo como base para un PSK. Ten en cuenta que esto solo funcionará si se negocia TLSv1.3.
-sctp
Usa SCTP para el protocolo de transporte en lugar de UDP en DTLS. Debe usarse junto con -dtls, -dtls1 o -dtls1_2. Esta opción solo está disponible donde OpenSSL tiene soporte para SCTP habilitado.
-sctp_label_bug
Usa el comportamiento incorrecto de implementaciones anteriores de OpenSSL al calcular secretos compartidos de pares de puntos finales para DTLS/SCTP. Esto permite la comunicación con implementaciones antiguas defectuosas pero rompe la interoperabilidad con implementaciones correctas. Debe usarse junto con -sctp. Esta opción solo está disponible donde OpenSSL tiene soporte para SCTP habilitado.
-fallback_scsv
Envía TLS_FALLBACK_SCSV en el ClientHello.
-async
Activa el modo asíncrono. Las operaciones criptográficas se realizarán de forma asíncrona. Esto solo tendrá efecto si también se utiliza un motor capaz de asincronía a través de la opción -engine. Para fines de prueba, se puede usar el motor asíncrono ficticio (dasync) (si está disponible).
-maxfraglen len
Habilita la negociación de Longitud Máxima de Fragmento; los valores permitidos son 512, 1024, 2048 y 4096.
-max_send_frag int
El tamaño máximo del fragmento de datos a enviar. Consulte SSL_CTX_set_max_send_fragment(3) para obtener más información.
-split_send_frag int
El tamaño utilizado para dividir los datos para canalizaciones de cifrado. Si se escriben más datos de una vez que este valor, se dividirá en múltiples canalizaciones, hasta el número máximo de canalizaciones definido por max_pipelines. Esto solo tiene efecto si se ha negociado un conjunto de cifrado adecuado, se ha cargado un motor que admite canalizaciones y max_pipelines es mayor que 1. Consulte SSL_CTX_set_split_send_fragment(3) para obtener más información.
-max_pipelines int
El número máximo de canalizaciones de cifrado/descifrado a utilizar. Esto solo tendrá efecto si se ha cargado un motor que admite canalizaciones (por ejemplo, el motor dasync) y se ha negociado un conjunto de cifrado adecuado. El valor predeterminado es 1. Consulte SSL_CTX_set_max_pipelines(3) para obtener más información.
-read_buf int
El tamaño del búfer de lectura predeterminado a utilizar para las conexiones. Esto solo tendrá efecto si el tamaño del búfer es mayor que el tamaño que se usaría de otro modo y se están utilizando canalizaciones (consulte SSL_CTX_set_default_read_buffer_len(3) para obtener más información).
-ignore_unexpected_eof
Algunas implementaciones de TLS no envían la alerta close_notify obligatoria al cerrar. Si la aplicación intenta esperar la alerta close_notify pero el par cierra la conexión sin enviarla, se genera un error. Cuando esta opción está habilitada, el par no necesita enviar la alerta close_notify y una conexión cerrada se tratará como si se hubiera recibido la alerta close_notify. Para obtener más información sobre el cierre de una conexión, consulte SSL_shutdown(3).
-no_tx_cert_comp
Deshabilita el soporte para el envío de certificados comprimidos TLSv1.3.
-no_rx_cert_comp
Deshabilita el soporte para la recepción de certificados comprimidos TLSv1.3.
-brief
Solo proporciona un resumen breve de los parámetros de conexión en lugar de la salida detallada normal.
-starttls protocolo
Envía el mensaje específico del protocolo para cambiar a TLS para la comunicación. protocolo es una palabra clave para el protocolo deseado. Actualmente, las únicas palabras clave admitidas son "smtp", "pop3", "imap", "ftp", "xmpp", "xmpp-server", "irc", "postgres", "mysql", "lmtp", "nntp", "sieve" y "ldap".
-xmpphost nombre_host
Esta opción, cuando se usa con "-starttls xmpp" o "-starttls xmpp-server", especifica el host para el atributo "to" del elemento stream. Si no se especifica esta opción, se utilizará el host especificado con "-connect".

Esta opción es un alias de la opción -name para "xmpp" y "xmpp-server".

-name nombre_host
Esta opción se utiliza para especificar información del nombre de host para varios protocolos utilizados con la opción -starttls. Actualmente, solo "xmpp", "xmpp-server", "smtp" y "lmtp" pueden utilizar esta opción -name.

Si esta opción se usa con "-starttls xmpp" o "-starttls xmpp-server", especifica el host para el atributo "to" del elemento stream. Si no se especifica esta opción, se utilizará el host especificado con "-connect".

Si esta opción se usa con "-starttls lmtp" o "-starttls smtp", especifica el nombre a usar en el mensaje "LMTP LHLO" o "SMTP EHLO", respectivamente. Si no se especifica esta opción, se usará "mail.example.com".

-tlsextdebug
Imprime un volcado hexadecimal de cualquier extensión TLS recibida del servidor.
-sess_out nombre_archivo
Exporta la sesión SSL al nombre_archivo.
-sess_in nombre_archivo
Carga la sesión SSL desde nombre_archivo. El cliente intentará reanudar una conexión desde esta sesión.
-serverinfo tipos
Una lista de Tipos de Extensión TLS separados por comas (números entre 0 y 65535). Cada tipo se enviará como una Extensión TLS ClientHello vacía. La respuesta del servidor (si la hay) se codificará y se mostrará como un archivo PEM.
-status
Envía una solicitud de estado del certificado al servidor (OCSP stapling). La respuesta del servidor (si la hay) se imprime.
-ocsp_check_leaf
Requerir la comprobación del estado del certificado del servidor (entidad final), donde primero se intenta cualquier respuesta OCSP proporcionada en el handshake TLS (por el llamado "OCSP stapling"). Si no se puede encontrar una respuesta OCSP válida y concluyente, se intenta la comprobación basada en CRL si está habilitada, de lo contrario, la comprobación de estado falla.

Esto implica -status.

-ocsp_check_all
Como la opción anterior, pero requiere realizar la comprobación del estado del certificado también para la cadena de emisores del certificado del servidor (es decir, certificados de CA intermedios, excluyendo el ancla de confianza).

Esto implica -status y -ocsp_check_leaf.

-alpn protocolos, -nextprotoneg protocolos
Estas banderas habilitan la Negociación de Protocolos de Capa de Aplicación o la Negociación de Siguiente Protocolo (NPN), respectivamente. ALPN es el estándar IETF y reemplaza a NPN. La lista protocolos es una lista de nombres de protocolo separados por comas que el cliente debe anunciar soporte. La lista debe contener los protocolos más deseables primero. Los nombres de protocolo son cadenas de texto ASCII imprimibles, por ejemplo "http/1.1" o "spdy/3". Una lista vacía de protocolos se trata de forma especial y hará que el cliente anuncie el soporte para la extensión TLS pero se desconecte justo después de recibir ServerHello con una lista de protocolos soportados por el servidor. La bandera -nextprotoneg no puede especificarse si se utiliza -tls1_3.
-ct, -noct

COMANDOS CONECTADOS (BÁSICOS)

Si se establece una conexión con un servidor SSL/TLS, se mostrarán todos los datos recibidos del servidor y se enviarán al servidor todas las pulsaciones de teclas. Si se alcanza el fin de archivo, la conexión se cerrará.

Cuando se utiliza de forma interactiva (lo que significa que no se han proporcionado ni -quiet ni -ign_eof), y no se proporcionan ni -adv ni -nocommands, se entra en el modo de comandos "Básico". En este modo, se reconocen ciertos comandos que realizan operaciones especiales. Estos comandos son una letra que debe aparecer al principio de una línea. Todos los datos posteriores a la letra inicial en la línea se ignoran. Los comandos se enumeran a continuación.

Q
Finaliza la conexión SSL actual y sale.
R
Renegocia la sesión SSL (solo TLSv1.2 y versiones anteriores).
C
Intenta reconectarse al servidor utilizando un handshake de reanudación.
k
Envía un mensaje de actualización de clave al servidor (solo TLSv1.3)
K
Envía un mensaje de actualización de clave al servidor y solicita uno de vuelta (solo TLSv1.3)

COMANDOS CONECTADOS (AVANZADOS)

Si se ha proporcionado -adv, se entra en el modo de comandos "avanzado". Al igual que en el modo básico, si se establece una conexión con un servidor SSL/TLS, se mostrarán todos los datos recibidos del servidor y se enviarán al servidor todas las pulsaciones de teclas. Si se alcanza el fin de archivo, la conexión se cerrará.

Se pueden suministrar comandos especiales encerrándolos entre llaves, por ejemplo, "{help}" o "{quit}". Estos comandos pueden aparecer en cualquier lugar del texto introducido en s_client, pero no se envían al servidor. Algunos comandos pueden tomar un argumento terminando el nombre del comando con ":" y luego proporcionando el argumento, por ejemplo, "{keyup:req}". Algunos comandos solo están disponibles cuando se han negociado ciertas versiones del protocolo.

Si aparece un salto de línea al final de una línea introducida en s_client, este también se envía al servidor. Si un comando aparece en una línea por sí solo sin ningún otro texto en la misma línea, el salto de línea se suprime y no se envía al servidor.

Se reconocen los siguientes comandos.

help
Imprime un resumen de ayuda sobre los comandos disponibles.
quit
Cierra la conexión con el par.
reconnect
Se reconecta con el par e intenta un handshake de reanudación.
keyup
Envía un mensaje de Actualización de Clave. Solo TLSv1.3. Este comando acepta un argumento opcional. Si se proporciona el argumento "req", también se solicita al par que actualice sus claves. De lo contrario, si se proporciona "noreq", no se solicita al par que actualice sus claves. El valor predeterminado es "req".
reneg
Inicia una renegociación con el servidor. (Solo D)TLSv1.2 o inferior).
fin
Indica FIN en la secuencia actual. Solo QUIC. Una vez enviado FIN, se ignora cualquier texto posterior introducido para esta secuencia.

NOTAS

Este comando se puede utilizar para depurar servidores SSL. Para conectarse a un servidor HTTP SSL, el comando:

openssl s_client -connect nombre_servidor:443

se utilizaría típicamente (https usa el puerto 443). Si la conexión tiene éxito, se puede proporcionar un comando HTTP como "GET /" para recuperar una página web.

Si el handshake falla, hay varias causas posibles. Si no es nada obvio como la falta de un certificado de cliente, se pueden probar las opciones -bugs, -ssl3, -tls1, -no_ssl3, -no_tls1 en caso de que sea un servidor defectuoso. En particular, debería jugar con estas opciones antes de enviar un informe de error a una lista de correo de OpenSSL.

Un problema frecuente al intentar que los certificados de cliente funcionen es que un cliente web se queja de que no tiene certificados o proporciona una lista vacía para elegir. Esto se debe normalmente a que el servidor no envía la lista de autoridades de certificación aceptables de su "lista de CA aceptables" cuando solicita un certificado. Utilizando este comando, se puede ver y comprobar la lista de CA. Sin embargo, algunos servidores solo solicitan autenticación de cliente después de que se solicita una URL específica. Para obtener la lista en este caso, es necesario usar la opción -prexit y enviar una solicitud HTTP para una página apropiada.

Si se especifica un certificado en la línea de comandos usando la opción -cert, no se utilizará a menos que el servidor solicite específicamente un certificado de cliente. Por lo tanto, la mera inclusión de un certificado de cliente en la línea de comandos no garantiza que el certificado funcione.

Si hay problemas para verificar un certificado de servidor, se puede utilizar la opción -showcerts para mostrar todos los certificados enviados por el servidor.

Este comando es una herramienta de prueba y está diseñado para continuar el handshake después de cualquier error de verificación de certificado. Como resultado, aceptará cualquier cadena de certificados (de confianza o no) enviada por el par. Las aplicaciones que no son de prueba no deben hacer esto, ya que las hace vulnerables a un ataque MITM. Este comportamiento se puede cambiar con la opción -verify_return_error: los errores de verificación se devuelven y se aborta el handshake.

La opción -bind puede ser útil si el servidor o un firewall requieren que las conexiones provengan de una dirección y/o puerto particulares.

Nota sobre uso no interactivo

Cuando s_client se ejecuta en un entorno no interactivo (por ejemplo, un trabajo cron o un script sin una entrada estándar válida), puede cerrar la conexión prematuramente, especialmente con TLS 1.3. Para evitar esto, puede usar la opción -ign_eof, que mantiene s_client en ejecución incluso después de alcanzar el fin de archivo de la entrada estándar.

Por ejemplo:

openssl s_client -connect <dirección_servidor>:443 -tls1_3
                 -sess_out /ruta/al/archivo_parámetros_sesión_tls
                 -ign_eof </dev/null

Sin embargo, depender únicamente de -ign_eof puede generar problemas si el servidor mantiene la conexión abierta, esperando que el cliente la cierre primero. En tales casos, el cliente puede colgarse indefinidamente. Este comportamiento no es infrecuente, especialmente con protocolos donde el servidor espera una desconexión elegante del cliente.

Por ejemplo, al conectarse a un servidor SMTP, la sesión puede pausarse si el servidor espera un comando QUIT antes de cerrar:

$ openssl s_client -brief -ign_eof -starttls smtp
                   -connect <dirección_servidor>:25 </dev/null
CONEXIÓN ESTABLECIDA
Versión del protocolo: TLSv1.3
Ciphersuite: TLS_AES_256_GCM_SHA384
...
250 CHUNKING
[pausa larga]

Para evitar estas pausas, es mejor utilizar un comando a nivel de aplicación para iniciar una desconexión limpia. Para SMTP, puede enviar un comando QUIT:

printf 'QUIT\r\n' | openssl s_client -connect <dirección_servidor>:25
                                     -starttls smtp -brief -ign_eof

De manera similar, para conexiones HTTP/1.1, incluir un encabezado `Connection: close` asegura que el servidor cierre la conexión después de responder:

printf 'GET / HTTP/1.1\r\nHost: <dirección_servidor>\r\nConnection: close\r\n\r\n'
    | openssl s_client -connect <dirección_servidor>:443 -brief

Estos enfoques ayudan a gestionar el cierre de la conexión de forma elegante y a prevenir bloqueos causados por el servidor esperando que el cliente inicie la desconexión.

ERRORES

Debido a que este programa tiene muchas opciones y también porque algunas de las técnicas utilizadas son bastante antiguas, el código fuente C de este comando es bastante difícil de leer y no es un modelo de cómo deben hacerse las cosas. Un programa cliente SSL típico sería mucho más simple.

La opción -prexit es un poco un parche. Realmente deberíamos informar de la información cada vez que se renegocia una sesión.

DESCRIPTION

The openssl s_client command is a command line tool which can be used to interact with any SSL/TLS capable server. It opens a connection to the specified host and port, performs the SSL/TLS handshake, and then enters an interactive mode where you can type data to be sent to the server, and any data received from the server will be printed to standard output. This is useful for testing SSL/TLS servers, or for debugging issues with the SSL/TLS protocol itself.

CONNECTED COMMANDS (BASIC)

Once the connection is established, you can type data to be sent to the server. Any data received from the server will be printed to standard output.

  • QUIT: Close the connection.
  • CTRL+C: Interrupt the connection.

CONNECTED COMMANDS (ADVANCED)

The following commands can be used to control the SSL/TLS session:

  • RENEGOTIATE: Initiate a renegotiation of the SSL/TLS session.
  • GET_CLIENT_CERTIFICATE: Request a client certificate from the server.
  • GET_SERVER_CERTIFICATE: Request the server's certificate.
  • GET_SESSION_INFO: Print information about the current SSL/TLS session.

NOTES

This command is intended for testing and debugging purposes only. It is not recommended for use in production environments.
