OIDENTD.CONF(5) Manual de usuario de oidentd OIDENTD.CONF(5)

NOMBRE

oidentd.conf - archivos de configuración de oidentd

DESCRIPCIÓN

Los archivos de configuración de oidentd se utilizan para controlar las respuestas que oidentd envía a los clientes después de recibir una consulta para una conexión propiedad de un usuario particular.

El archivo de configuración a nivel de sistema /usr/local/etc/oidentd.conf especifica los tipos de respuestas que los usuarios individuales tienen permiso para enviar. Por defecto, los usuarios deben responder con su nombre de usuario real.

Los archivos de configuración de usuario ~/.config/oidentd.conf permiten a los usuarios enviar respuestas Ident personalizadas o ocultar sus identidades, siempre que se les hayan concedido las capacidades necesarias a través del archivo de configuración del sistema. Si este archivo no existe o oidentd fue compilado sin soporte para XDG Base Directory, se utiliza en su lugar el archivo ~/.oidentd.conf. Tenga en cuenta que los archivos de configuración de usuario solo se leen después de que se determina que una conexión pertenece al usuario en cuestión.

ARCHIVO DE CONFIGURACIÓN A NIVEL DE SISTEMA

El archivo de configuración a nivel de sistema se utiliza para conceder capacidades a los usuarios o forzar a los usuarios a usar una capacidad determinada. El comportamiento predeterminado es no conceder ningún privilegio, lo que significa que todos los usuarios deben enviar sus nombres de usuario reales en respuesta a las consultas de Ident. El archivo de configuración a nivel de sistema puede estar vacío o ausente, en cuyo caso se aplica este valor predeterminado. Los cambios en este archivo solo surten efecto después de que oidentd se recarga (lo que ocurre cuando se recibe una señal SIGHUP) o se reinicia.

El archivo de configuración a nivel de sistema contiene cero o una directiva de la siguiente forma:

default {
        directivas-de-rango...
}

Esta directiva predeterminada coincide con todos los usuarios para los cuales no se han definido reglas explícitas. Cualquier directiva de usuario posterior a esta directiva hereda las capacidades que define. Si está presente, la directiva predeterminada debe ser la primera directiva en el archivo de configuración del usuario.

El archivo de configuración a nivel de sistema también puede contener cero o más directivas de la siguiente forma:

user nombredeusuario {
        directivas-de-rango...
}

Esta directiva de usuario se aplica solo al usuario especificado.

ARCHIVO DE CONFIGURACIÓN DE USUARIO

Cada usuario puede crear un archivo de configuración de usuario en ~/.config/oidentd.conf o ~/.oidentd.conf. Este archivo debe ser legible por el usuario con el que se ejecuta oidentd. El archivo de configuración de usuario se lee automáticamente después de cada búsqueda exitosa, por lo que cualquier cambio surte efecto de inmediato.

El archivo de configuración de usuario contiene cero o una directiva de la siguiente forma:

global {
        declaraciones-de-capacidad...
}

Esta directiva global coincide con todas las conexiones propiedad del usuario. Si está presente, debe ser la primera directiva en el archivo de configuración del usuario.

El archivo de configuración de usuario también puede contener cero o más directivas de la siguiente forma:

especificación-de-rango {
        declaraciones-de-capacidad...
}

Esta directiva de rango se aplica solo a las conexiones que coinciden con la especificación de rango dada.

DIRECTIVAS DE RANGO

Como máximo, una directiva de rango en cualquier ámbito dado puede tener la siguiente forma:

default {
        directivas-de-capacidad...
}

Esta directiva predeterminada define reglas para todas las conexiones que no coinciden con ninguna otra directiva de rango. Si está presente, la directiva predeterminada debe ser la primera directiva en su ámbito.

Una directiva de rango también puede tener la siguiente forma:

especificación-de-rango {
        directivas-de-capacidad...
}

Esta directiva de rango se aplica solo a las conexiones que coinciden con la especificación de rango dada.

ESPECIFICACIONES DE RANGO

Una especificación de rango consta de filtros que definen a qué conexiones se aplica una directiva de rango. Tiene la siguiente forma:

to fhost fport fport from lhost lport lport

Esta especificación de rango coincide solo con conexiones con el host o dirección remotos especificados, puerto o rango de puertos remotos, host o dirección locales y puerto o rango de puertos locales. Debe especificarse al menos uno de estos filtros. Los filtros omitidos coinciden con cualquier valor. Los filtros pueden especificarse en cualquier orden.

El filtro fhost especifica el host o dirección remotos de una conexión, desde la perspectiva de la máquina que ejecuta oidentd.

El filtro fport especifica el puerto o rango de puertos remotos de una conexión.

El filtro lhost especifica el host o dirección locales de una conexión, desde la perspectiva de la máquina que ejecuta oidentd. Esto puede ser útil para admitir hosts virtuales en sistemas con más de una dirección IP.

El filtro lport especifica el puerto o rango de puertos locales de una conexión.

Los puertos se pueden especificar numéricamente (por ejemplo, 113) o utilizando un nombre de servicio (por ejemplo, ident). Los rangos de puertos se especifican numéricamente como min:max. El puerto min puede omitirse para seleccionar todos los puertos menores o iguales al puerto max. De manera similar, el puerto max puede omitirse para seleccionar todos los puertos mayores o iguales al puerto min.

DIRECTIVAS DE CAPACIDAD

Una directiva de capacidad puede tener una de las siguientes formas:

allow capacidad

En esta forma, la directiva otorga al usuario permiso para usar la capacidad especificada.

deny capacidad

En esta forma, la directiva revoca el permiso del usuario para usar la capacidad especificada.

force declaración-de-capacidad

En esta forma, la directiva obliga al usuario a usar la capacidad especificada.

CAPACIDADES

Las siguientes expresiones son capacidades válidas:

forward
hide
numeric
random
random_numeric

Estas capacidades permiten a los usuarios utilizar las declaraciones de capacidad correspondientes.

spoof

La capacidad spoof permite a los usuarios enviar respuestas Ident personalizadas. Tenga en cuenta que esto no incluye responder con el nombre de otro usuario o falsificar respuestas para conexiones a puertos remotos privilegiados.

spoof_all

La capacidad spoof_all permite a los usuarios responder con los nombres de otros usuarios. Esta capacidad debe usarse con cuidado, ya que permite a los usuarios suplantar a otros usuarios en el sistema local. La capacidad spoof_all solo funciona en conjunto con spoof, pero no la implica.

spoof_privport

La capacidad spoof_privport permite a los usuarios falsificar respuestas para conexiones a puertos remotos privilegiados (con números de puerto inferiores a 1024). La capacidad spoof_privport solo funciona en conjunto con spoof, pero no la implica.

DECLARACIONES DE CAPACIDAD

Una declaración de capacidad puede tener una de las siguientes formas:

forward host puerto

Reenvía las consultas recibidas a otro servidor Ident. El servidor de destino debe admitir el reenvío (como oidentd con la opción --proxy).

Pueden requerirse capacidades adicionales para que el reenvío tenga éxito. Por ejemplo, se requiere la capacidad spoof si el servidor de destino envía una respuesta que no sea el nombre del usuario en el servidor de reenvío. Por lo tanto, puede ser deseable conceder también al menos una de las capacidades hide, spoof, spoof_all y spoof_privport además de la capacidad forward. Si se utiliza force forward, no se realizan comprobaciones adicionales y no se requieren capacidades.

Si el reenvío falla, oidentd responde con un error "HIDDEN-USER" o con el nombre del usuario
