NOMBRE

opam-search - Un alias para list --search.

SINOPSIS

opam search [--check] [--no-depexts] [--silent] [OPCIÓN]… [PATRONES]…

DESCRIPCIÓN

opam search es un alias para opam list --search.

Ver opam list --help para detalles.

OPCIONES DE SELECCIÓN DE PAQUETES

--coinstallable-with=PAQUETES
Listar solo paquetes que sean compatibles con todos los de PAQUETES.
--conflicts-with=PAQUETES
Listar paquetes que han declarado conflictos con al menos uno de la lista dada. Esto incluye conflictos definidos desde los paquetes de la lista, desde el otro paquete, o por un campo común conflict-class:.
--depends-on=PAQUETES
Listar solo paquetes que dependen de uno de (separados por comas) PAQUETES.
--depopts
Incluir dependencias opcionales en las solicitudes de dependencias.
--dev
Incluir paquetes de desarrollo en las dependencias.
--field-match=CAMPO:PATRÓN
Filtrar paquetes con una coincidencia para PATRÓN en el CAMPO dado
--has-flag=FLAG
Incluir solo paquetes que tengan la bandera dada establecida. Las banderas de paquetes son: light-uninstall verbose plugin compiler conf
--has-tag=TAG
Incluir solo paquetes que tengan la etiqueta dada establecida
--no-switch
Listar lo que está disponible en los repositorios, sin considerar el switch actual (o cualquier otro) (paquetes instalados o fijados, etc.)
--nobuild
Excluir dependencias de compilación (se incluyen por defecto).
--or
En lugar de seleccionar paquetes que coincidan con *todos* los criterios, seleccionar paquetes que coincidan con *cualquiera* de ellos
--owns-file=ARCHIVO
Encontrar paquetes instalados responsables de instalar el archivo dado
--post
Incluir dependencias marcadas como post.
--recursive
Con `--depends-on' y `--required-by', mostrar todas las dependencias transitivas en lugar de solo las dependencias directas.
--repos=REPOS
Incluir solo paquetes que se originaron en uno de los repositorios dados (a menos que también se especifique no-switch, esto excluye los paquetes fijados).
--required-by=PAQUETES
Listar solo las dependencias de PAQUETES (separados por comas).
--resolve=PAQUETES
Restringir a una solución para instalar PAQUETES (separados por comas), es decir, un conjunto consistente de paquetes incluyéndolos. Esto es sutilmente diferente de `--required-by --recursive', que es más predecible y no puede fallar, pero lista todas las dependencias independientemente sin garantizar la consistencia. Sin `--installed', la respuesta es autocontenida e independiente de la instalación actual. Con `--installed', se calcula a partir del conjunto de paquetes actualmente instalados. `--no-switch' además hace que la solución sea independiente de los paquetes fijados, la arquitectura y la versión del compilador actuales. La combinación con `--depopts' no está soportada.
-t, --with-test, --test
Incluir dependencias solo de prueba.
--with-dev-setup
Incluir dependencias solo de desarrollo.
--with-doc, --doc
Incluir dependencias solo de documentación.

OPCIONES DE FORMATO DE SALIDA

--columns=COLUMNAS
Seleccionar las columnas a mostrar entre: name, version, package, synopsis, synopsis-or-target, description, <campo>:, installed-version, pin, source-hash, opam-file, all-installed-versions, available-versions, all-versions, repository, installed-files, vc-ref, depexts. El valor por defecto es name cuando se especifica --short y name, installed-version, synopsis-or-target en caso contrario.
-e, --external, --depexts
En lugar de mostrar los paquetes, mostrar sus dependencias externas asociadas al sistema actual. Esto excluye otras opciones de visualización. En lugar de usar esto directamente, probablemente deberías ir al plugin `depext', que usará tu sistema de gestión de paquetes para manejar la instalación de las dependencias. Ejecuta `opam depext'.
--normalise
Imprimir los valores de los campos de opam normalizados
-S, --sort
Ordenar los paquetes en orden de dependencia (es decir, un orden en el que podrían ser instalados individualmente.)
-s, --short
No imprimir encabezado, y establece las columnas por defecto a name solamente. Si necesitas incluir las versiones de los paquetes, usa --columns=package en su lugar.
--separator=CADENA (ausente= )
Establecer la cadena separadora de columnas
-V, --all-versions
Normalmente, cuando coinciden múltiples versiones de un paquete, solo se muestra una en la salida (la instalada, la fijada, o, en su defecto, la más alta disponible o la más alta). Esta bandera deshabilita este comportamiento y muestra todas las versiones coincidentes. Esto también cambia el formato de visualización por defecto para incluir las versiones de los paquetes en lugar de solo los nombres de los paquetes (incluso cuando se establece --short). Esto se activa automáticamente cuando se proporciona un solo nombre de paquete no patrón en la línea de comandos.
--vars=[VAR=STR,...]
Definir los enlaces de variables dados. Típicamente útil con --external para anular los valores de arch, os, os-distribution, os-version, os-family.
--wrap
Ajustar líneas largas, el valor por defecto es truncar al mostrar en una terminal, o mantener tal cual en caso contrario

SELECTORES SENSIBLES AL ORDEN

-a, --available

-A, --all

Listar solo la última versión de cada paquete.

--roots, --installed-roots

ARGUMENTOS

PATRONES
Patrones de paquetes con comodines. A menos que se especifique --search, coinciden con NOMBRE o NOMBRE.VERSIÓN

OPCIONES

--check
No escribir nada en la salida, salir con código de retorno 0 si la lista no está vacía, 1 en caso contrario.
--no-depexts
Deshabilitar el manejo de dependencias externas para la consulta. Esto puede usarse para incluir paquetes que están marcados como no disponibles debido a una dependencia del sistema no disponible.

Eliminado en 2.1, usar --check en su lugar.

OPTIONS

--best-effort
This option is equivalent to setting the $OPAMBESTEFFORT environment variable.
--cli=MAJOR.MINOR (absent=2.4)
Use the command-line interface syntax and semantics of MAJOR.MINOR. Intended for any persistent use of opam (scripts, blog posts, etc.), any version of opam in the same MAJOR series will behave as for the specified MINOR release. The flag was not available in opam 2.0, so to select the 2.0 CLI, set the OPAMCLI environment variable to 2.0 instead of using this parameter.
--color=WHEN
Colorize the output. WHEN must be one of always, never or auto.
--confirm-level=LEVEL
Confirmation level, LEVEL must be one of ask, no, yes or unsafe-yes. Can be specified more than once. If --yes or --no are also given, the value of the last --confirm-level is taken into account. This is equivalent to setting $OPAMCONFIRMLEVEL.
--criteria=CRITERIA
Specify user preferences for dependency solving for this run. Overrides $OPAMCRITERIA, $OPAMFIXUPCRITERIA and $OPAMUPGRADECRITERIA. For details on the supported language, and the external solvers available, see http://opam.ocaml.org/doc/External_solvers.html. A general guide to using solver preferences can be found at http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=FILENAME
Debug option: Save the CUDF requests sent to the solver to FILENAME-<n>.cudf where <n> is the n-th call to the solver during the opam run.
--debug
Print debug message to stderr. This is equivalent to setting $OPAMDEBUG to "true".
--debug-level=LEVEL
Like --debug, but allows specifying the debug level (--debug sets it to 1). Equivalent to setting $OPAMDEBUG to a positive integer.
--git-version
Print the git version of opam, if set (i.e. you are using a development version), and exit.
--help[=FMT] (default=auto)
Show this help in format FMT. The value FMT must be one of auto, pager, groff or plain. With auto, the format is pager or plain whenever the TERM env var is dumb or undefined.
--ignore-pin-depends
Ignore extra pins required by packages that get pinned, either manually through opam pin or through opam install DIR. This is equivalent to setting IGNOREPINDEPENDS=true.
--json=FILENAME
Save the results of the opam run in a computer-readable file. If the filename contains the character `%', it will be replaced by an index that doesn't overwrite an existing file. Similar to setting the $OPAMJSON variable.
--no
Answer no to all opam yes/no questions without prompting. See also --confirm-level. This is equivalent to setting $OPAMNO to "true".
--no-aspcud
Removed in 2.1.
--no-auto-upgrade
When configuring or updating a repository that is written for an earlier opam version (1.2), opam internally converts it to the current format. This disables this behaviour. Note that repositories should define their format version in a 'repo' file at their root, or they will be assumed to be in the older format. It is, in any case, preferable to upgrade the repositories manually using opam admin upgrade [--mirror URL] when possible.
--no-self-upgrade
Opam will replace itself with a newer binary found at OPAMROOT/opam if present. This disables this behaviour.
-q, --quiet
Disables --verbose.
--root=ROOT
Use ROOT as the current root path. This is equivalent to setting $OPAMROOT to ROOT.
--safe, --readonly
Make sure nothing will be automatically updated or rewritten. Useful for calling from completion scripts, for example. Will fail whenever such an operation is needed ; also avoids waiting for locks, skips interactive questions and overrides the $OPAMDEBUG variable. This is equivalent to set environment variable $OPAMSAFE.
--solver=CMD
Specify the CUDF solver to use for resolving package installation problems. This is either a predefined solver (this version of opam supports builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), or a custom command that should contain the variables %{input}%, %{output}%, %{criteria}%, and optionally %{timeout}%. This is equivalent to setting $OPAMEXTERNALSOLVER.
--strict
Fail whenever an error is found in a package definition or a configuration file. The default is to continue silently if possible.
--switch=SWITCH
Use SWITCH as the current compiler switch. This is equivalent to setting $OPAMSWITCH to SWITCH.
--use-internal-solver
Disable any external solver, and use the built-in one (this requires that opam has been compiled with a built-in solver). This is equivalent to setting $OPAMNOASPCUD or $OPAMUSEINTERNALSOLVER.
-v, --verbose
Be more verbose. One -v shows all package commands, repeat to also display commands called internally (e.g. tar, curl, patch etc.) Repeating n times is equivalent to setting $OPAMVERBOSE to "n".
--version
Show version information.
-w, --working-dir
Whenever updating packages that are bound to a local, version-controlled directory, update to the current working state of their source instead of the last committed state, or the ref they are pointing to. As source directory is copied as it is, if it isn't clean it may result on a opam build failure. This only affects packages explicitly listed on the command-line. It can also be set with $OPAMWORKINGDIR.
-y, --yes
Answer yes to all opam yes/no questions without prompting. See also --confirm-level. This is equivalent to setting $OPAMYES to "true".

NAME

opam, opam-installer - OCaml package manager

SYNOPSIS

opam [options] command [args...]

opam-installer [options] command [args...]

DESCRIPTION

The opam command line interface.

opam is a utility for managing OCaml software packages. It allows you to easily install, update, remove, query, and freeze packages and their dependencies. opam supports multiple switch bases and provides fine-grained control over your OCaml development environments.

The following environment variables can be used to customise opam's behaviour:

OPAMACTION
if set, opam will perform this action on the given packages instead of following the user request. The value is a colon-separated list of actions (e.g. install:upgrade:remove). Use this to force opam's hand on specific packages.
OPAMALWAYSWARN
if set, opam will always warn the user before performing any action, even if the request is not ambiguous.
OPAMBUILDDIR
specifies the base directory for building packages. By default, it is located in the current switch's directory.
OPAMBUILDID
This is an internal variable used to identify package builds. You should not set it.
OPAMCACHE
Specifies the directory where opam should store its cache (downloaded archives, build results, etc.). Defaults to `~/.opam/cache'.
OPAMCAST
This is an internal variable used for type casting. You should not set it.
OPAMCOMPILERGIT
If set, opam will download the requested compiler version from the git repository specified by the variable instead of fetching it from the official distribution.
OPAMCOMPILERGITBRANCH
If OPAMCOMPILERGIT is set, this specifies the branch to use.
OPAMCONFIRMLEVEL
sets the confirmation level for operations. Values are 0 (no confirmation), 1 (confirm only destructive operations), 2 (confirm all operations). Default is 2. This variable is ignored if OPAMYES is set.
OPAMCONFLICTS
A colon-separated list of packages that should be considered as in conflict with each other (e.g. `pkgA:pkgB:pkgC'). This is mostly used internally to handle conflicts between different versions of the same package, but can be used to enforce user-defined conflicts.
OPAMCRITERIA
A list of criteria for package selection. These are hints for the solver, e.g. `orderable-use-best-package' or `install-stronger-dependencies'. See also option `--criteria'.
OPAMDEBUG
if set, opam will print debug messages. The value can be a specific component to debug (e.g. `solver') or empty to enable all debugging.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
