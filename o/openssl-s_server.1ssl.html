DESCRIPCIÓN

Este comando implementa un servidor SSL/TLS genérico que escucha conexiones en un puerto dado usando SSL/TLS.

OPCIONES

Además de las opciones a continuación, este comando también admite las opciones comunes y solo para el servidor documentadas en "Comandos comunes de la línea de comandos" en SSL_CONF_cmd(3)

-help
Muestra un mensaje de uso.
-port +int
El puerto TCP en el que escuchar conexiones. Si no se especifica, se usa el 4433.
-accept val
El host y puerto TCP opcional en el que escuchar conexiones. Si no se especifica, se usa *:4433.
-unix val
Socket de dominio Unix en el que aceptar.
-4
Usar solo IPv4.
-6
Usar solo IPv6.
-unlink
Para -unix, eliminar cualquier socket existente primero.
-context val
Establece el ID del contexto SSL. Puede tener cualquier valor de cadena. Si esta opción no está presente, se usará un valor predeterminado.
-verify int, -Verify int
La profundidad de verificación a usar. Esto especifica la longitud máxima de la cadena de certificados del cliente y hace que el servidor solicite un certificado al cliente. Con la opción -verify se solicita un certificado pero el cliente no tiene que enviar uno, con la opción -Verify el cliente debe proporcionar un certificado o se produce un error.

Si el conjunto de cifrado no puede solicitar un certificado de cliente (por ejemplo, un conjunto de cifrado anónimo o PSK) esta opción no tiene ningún efecto.

Por defecto, la validación de cualquier certificado de cliente suministrado y su cadena se realiza con respecto al propósito de Certificado de Cliente (D)TLS ("sslclient"). Para más detalles, ver "Extensiones de Certificado" en openssl-verification-options(1).

-cert infile
El certificado a usar, la mayoría de los conjuntos de cifrado de servidor requieren el uso de un certificado y algunos requieren un certificado con un tipo de clave pública específico: por ejemplo, los conjuntos de cifrado DSS requieren un certificado que contenga una clave DSS (DSA). Si no se especifica, se utilizará el nombre de archivo server.pem.
-cert2 infile
El archivo de certificado a usar para servername; el valor predeterminado es "server2.pem".
-certform DER|PEM|P12
El formato del archivo de certificado del servidor; no especificado por defecto.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

default. Ver openssl-format-options(1) para obtener detalles.
-cert_chain
Un archivo o URI de certificados no confiables para usar al intentar construir la cadena de certificados relacionada con el certificado especificado a través de la opción -cert. Estos certificados no confiables se envían a los clientes y se utilizan para generar solicitudes de estado de certificado (también conocido como OCSP stapling). La entrada puede estar en formato PEM, DER o PKCS#12.
-build_chain
Especifica si la aplicación debe construir la cadena de certificados del servidor para proporcionarla al cliente.
-serverinfo val
Un archivo que contiene uno o más bloques de datos PEM. Cada bloque PEM debe codificar una extensión TLS ServerHello (2 bytes de tipo, 2 bytes de longitud, seguido por "longitud" bytes de datos de extensión). Si el cliente envía una extensión TLS ClientHello vacía que coincide con el tipo, se devolverá la extensión ServerHello correspondiente.
-key nombre_archivo|uri
La clave privada a utilizar. Si no se especifica, se utilizará el archivo de certificado.
-key2 nombre_archivo|uri
El archivo de clave privada a utilizar para servername si no se proporciona a través de -cert2.
-keyform DER|PEM|P12|ENGINE
El formato de la clave; no especificado por defecto. Ver openssl-format-options(1) para obtener detalles.
-pass val
La fuente de la contraseña de la clave privada y el archivo de certificado. Para más información sobre el formato de val, ver openssl-passphrase-options(1).
-dcert archivo_entrada, -dkey nombre_archivo|uri
Especifica un certificado y clave privada adicionales, estos se comportan de la misma manera que las opciones -cert y -key, excepto que no hay valor predeterminado si no se especifican (no se utiliza certificado ni clave adicionales). Como se mencionó anteriormente, algunas suites de cifrado requieren un certificado que contenga una clave de un cierto tipo. Algunas suites de cifrado necesitan un certificado que contenga una clave RSA y otras una clave DSS (DSA). Al usar certificados y claves RSA y DSS, un servidor puede admitir clientes que solo admiten suites de cifrado RSA o DSS utilizando un certificado apropiado.
-dcert_chain
Un archivo o URI de certificados no confiables para usar al intentar construir la cadena de certificados del servidor cuando se utiliza un certificado especificado a través de la opción -dcert. La entrada puede estar en formato PEM, DER o PKCS#12.
-dcertform DER|PEM|P12
El formato del archivo de certificado adicional; no especificado por defecto. Ver openssl-format-options(1) para obtener detalles.
-dkeyform DER|PEM|P12|ENGINE
El formato de la clave privada adicional; no especificado por defecto. Ver openssl-format-options(1) para obtener detalles.
-dpass val
La frase de contraseña para la clave privada y el certificado adicionales. Para más información sobre el formato de val, ver openssl-passphrase-options(1).
-nbio_test
Prueba la E/S no bloqueante.
-crlf
Esta opción traduce un salto de línea de la terminal a CR+LF.
-debug
Imprime información de depuración extensa, incluyendo un volcado hexadecimal de todo el tráfico.
-security_debug
Imprime la salida del framework de seguridad SSL/TLS.
-security_debug_verbose
Imprime más salida del framework de seguridad SSL/TLS
-msg
Muestra todos los mensajes del protocolo con volcado hexadecimal.
-msgfile archivo_salida
Archivo al que enviar la salida de -msg o -trace, por defecto la salida estándar.
-state
Imprime los estados de la sesión SSL.
-CRL archivo_entrada
El archivo CRL a utilizar.
-CRLform DER|PEM
El formato del archivo CRL; no especificado por defecto. Ver openssl-format-options(1) para obtener detalles.
-crl_download
Descarga CRLs de los puntos de distribución dados en las extensiones CDP de los certificados
-verifyCAfile nombre_archivo
Un archivo en formato PEM de CA que contiene certificados confiables para usar para verificar certificados de cliente.
-verifyCApath directorio
Un directorio que contiene certificados confiables para usar para verificar certificados de cliente. Este directorio debe estar en "formato hash", ver openssl-verify(1) para más información.
-verifyCAstore uri
La URI de un almacén que contiene certificados confiables para usar para verificar certificados de cliente.
-chainCAfile archivo
Un archivo en formato PEM que contiene certificados confiables para usar al intentar construir la cadena de certificados del servidor.
-chainCApath directorio
Un directorio que contiene certificados confiables para usar para construir la cadena de certificados del servidor proporcionada al cliente. Este directorio debe estar en "formato hash", ver openssl-verify(1) para más información.
-chainCAstore uri
La URI de un almacén que contiene certificados confiables para usar para construir la cadena de certificados del servidor proporcionada al cliente. La URI puede indicar un certificado único, así como una colección de ellos. Con URIs en el esquema "file:", esto actúa como -chainCAfile o -chainCApath, dependiendo de si la URI indica un directorio o un archivo único. Ver ossl_store-file(7) para más información sobre el esquema "file:".
-nocert
Si esta opción está activada, no se utiliza ningún certificado. Esto restringe las suites de cifrado disponibles a las anónimas (actualmente solo DH anónimo).
-quiet
Inhibir la impresión de información de sesión y certificado.
-no_resume_ephemeral
Deshabilitar caché y tickets si se usa DH (EC) efímero.
-tlsextdebug
Imprime un volcado hexadecimal de cualquier extensión TLS recibida del servidor.
-www
Envía un mensaje de estado de vuelta al cliente cuando se conecta. Esto incluye información sobre los cifrados utilizados y varios parámetros de sesión. La salida está en formato HTML, por lo que esta opción se puede utilizar con un navegador web. La URL especial "/renegcert" activa la validación de certificado de cliente, y "/reneg" indica al servidor que solicite la renégociation.
-WWW, -HTTP
Emula un servidor web simple. Las páginas se resolverán en relación con el directorio actual, por ejemplo, si se solicita la URL "https://myhost/page.html" se enviará el archivo ./page.html. Si se utiliza la bandera -HTTP, los archivos se envían directamente y deben contener las cabeceras de respuesta HTTP (incluida la línea de respuesta de estado). Si se utiliza la opción -WWW, las cabeceras de respuesta son generadas por el servidor y se examina la extensión del archivo para determinar la cabecera Content-Type. Las extensiones de "html", "htm" y "php" son "text/html" y todas las demás son "text/plain". Además, la URL especial "/stats" devolverá información de estado como la opción -www.
-http_server_binmode
Cuando actúa como servidor web (usando la opción -WWW o -HTTP) abre archivos solicitados por el cliente en modo binario.
-no_ca_names
Deshabilita los Nombres CA de Extensión TLS. Es posible que desees deshabilitarlo por razones de seguridad o por compatibilidad con algunas implementaciones TLS de Windows que fallan cuando esta extensión es mayor que 1024 bytes.
-ignore_unexpected_eof
Algunas implementaciones TLS no envían la alerta obligatoria close_notify al cerrar. Si la aplicación intenta esperar la alerta close_notify pero el par cierra la conexión sin enviarla, se genera un error. Cuando esta opción está habilitada, el par no necesita enviar la alerta close_notify y una conexión cerrada se tratará como si se hubiera recibido la alerta close_notify. Para más información sobre cómo cerrar una conexión, ver SSL_shutdown(3).
-servername
Servername para la extensión TLS HostName.
-servername_fatal
En caso de discrepancia de servername, envía una alerta fatal (predeterminado: alerta de advertencia).
-id_prefix val
Genera IDs de sesión SSL/TLS prefijados por val. Esto es principalmente útil para probar código SSL/TLS (por ejemplo, proxies) que desean manejar múltiples servidores, donde cada uno podría generar un rango único de IDs de sesión (por ejemplo, con un prefijo determinado).
-keymatexport
Exporta material de clave usando una etiqueta.
-keymatexportlen
Exporta el número dado de bytes de material de clave; por defecto 20.
-no_cache
Deshabilita la caché de sesiones.
-ext_cache.
Deshabilita la caché interna, configura y usa caché externa.
-verify_return_error
Los errores de verificación normalmente solo imprimen un mensaje pero permiten que la conexión continúe, con fines de depuración. Si se usa esta opción, los errores de verificación cierran la conexión.
-verify_quiet
Sin salida de verificación excepto errores de verificación.
-ign_eof
Ignora EOF de entrada (por defecto: cuando se usa -quiet).
-no_ign_eof
No ignora EOF de entrada.
-no_ems
Deshabilita la negociación de secreto maestro extendido.
-status
Habilita el soporte de solicitud de estado de certificado (también conocido como OCSP stapling): se proporciona una respuesta OCSP para el certificado hoja (servidor) si es solicitado por el lado del cliente.
-status_all
Al igual que antes, pero para TLS v1.3 y posteriores, se proporcionan respuestas de estado para todos los certificados en la cadena (excepto el ancla de confianza) si es solicitado por el lado del cliente.
-status_verbose
Habilita el soporte de solicitud de estado de certificado (también conocido como OCSP stapling) y proporciona una salida detallada de la respuesta OCSP. Usa la opción -cert_chain para especificar el certificado del firmante del certificado del servidor que se requiere para las solicitudes de estado de certificado.
-status_timeout int
Establece el tiempo de espera para la respuesta OCSP a int segundos.
-proxy [http[s]://][usuario:contraseña@]host[:puerto][/ruta][?consulta][#fragmento]
El servidor proxy HTTP(S) a usar para alcanzar el servidor OCSP a menos que aplique -no_proxy, ver más abajo. Si la cadena del host es una dirección IPv6, debe estar encerrada entre "[" y "]". El puerto del proxy por defecto es 80 o 443 si el esquema es "https"; aparte de eso, el prefijo opcional "http://" o "https://" se ignora, así como cualquier componente de usuario, ruta, consulta y fragmento. Por defecto, usa la variable de entorno "http_proxy" si está configurada, de lo contrario "HTTP_PROXY" si no se usa TLS, de lo contrario "https_proxy" si está configurada, de lo contrario "HTTPS_PROXY".
-no_proxy direcciones
Lista de direcciones IP y/o nombres DNS de servidores para los que no se debe usar un proxy HTTP(S), separados por comas y/o espacios en blanco (donde en este último caso, el argumento completo debe estar encerrado entre comillas "..."). Por defecto, se toma de la variable de entorno "no_proxy" si está configurada, de lo contrario "NO_PROXY".
-status_url val
Establece una URL de respondedor de respaldo para usar si no hay una URL de respondedor presente en el certificado del servidor. Sin esta opción, se devuelve un error si el certificado del servidor no contiene una dirección de respondedor. Los componentes opcionales de usuario e información y fragmento de la URL se ignoran. Cualquier componente de consulta dado se maneja como parte del componente de ruta.
-status_file infile
Anula cualquier URL de respondedor OCSP del certificado y siempre proporciona la Respuesta OCSP almacenada en el archivo. El archivo debe estar en formato DER. Esta opción se puede usar varias veces para especificar respuestas OCSP para todos los certificados en la cadena del certificado del servidor.
-ssl_config val
Configura SSL_CTX usando el valor de configuración dado.
-trace
Muestra una salida de rastreo detallada de los mensajes del protocolo.
-brief
Proporciona un resumen breve de los parámetros de conexión en lugar de la salida detallada normal.
-rev
Servidor de eco simple que envía el texto recibido invertido. También establece -brief. No se puede usar en conjunción con -early_data.
-async
Activa el modo asíncrono. Las operaciones criptográficas se realizarán de forma asíncrona. Esto solo tendrá efecto si también se utiliza un motor capaz de asincronía a través de la opción -engine. Para fines de prueba, se puede usar el motor asíncrono ficticio (dasync) (si está disponible).
-max_send_frag +int
El tamaño máximo de fragmento de datos a enviar. Consulte SSL_CTX_set_max_send_fragment(3) para más información.
-split_send_frag +int
El tamaño utilizado para dividir datos para canalizaciones de cifrado. Si se escriben más datos en una sola operación que este valor, se dividirá en múltiples canalizaciones, hasta el número máximo de canalizaciones definido por max_pipelines. Esto solo tendrá efecto si se ha negociado una suite de cifrado adecuada, se ha cargado un motor que admite canalizaciones y max_pipelines es mayor que 1. Consulte SSL_CTX_set_split_send_fragment(3) para más información.
-max_pipelines +int
El número máximo de canalizaciones de cifrado/descifrado a utilizar. Esto solo tendrá efecto si se ha cargado un motor que admita canalizaciones (por ejemplo, el motor dasync) y se ha negociado una suite de cifrado adecuada. El valor por defecto es 1. Consulte SSL_CTX_set_max_pipelines(3) para más información.
-naccept +int
El servidor se cerrará después de recibir el número especificado de conexiones, por defecto ilimitado.
-read_buf +int
El tamaño por defecto del búfer de lectura a utilizar para las conexiones. Esto solo tendrá efecto si el tamaño del búfer es mayor que el tamaño que se usaría de lo contrario y la canalización está en uso (consulte SSL_CTX_set_default_read_buffer_len(3) para más información).
-no_tx_cert_comp
Deshabilita el soporte para enviar certificados comprimidos TLSv1.3.
-no_rx_cert_comp
Deshabilita el soporte para recibir certificados comprimidos TLSv1.3.
-no_comp
Deshabilita la negociación de compresión TLS. La compresión TLS no se recomienda y está desactivada por defecto a partir de OpenSSL 1.1.0.
-num_tickets
Controla el número de tickets que se enviarán al cliente después de un handshake completo en TLSv1.3. El número por defecto de tickets es 2. Esta opción no afecta el número de tickets enviados después de un handshake de reanudación.
-dhparam infile
El archivo de parámetros DH a utilizar. Las suites de cifrado efímeras DH generan claves utilizando un conjunto de parámetros DH. Si no se especifica, se intentará cargar los parámetros desde el archivo del certificado del servidor. Si esto falla, se utilizará un conjunto estático de parámetros codificado en este comando.
-nbio
Activa la E/S no bloqueante.
-timeout
Habilita tiempos de espera.
-mtu
Establece la MTU de la capa de enlace.
-psk_identity val
Espera que el cliente envíe la identidad PSK val al usar una suite de cifrado PSK, y advierte si no lo hacen. Por defecto, la identidad PSK esperada es la cadena "Client_identity".
-psk_hint val
Usa la pista de identidad PSK val al usar una suite de cifrado PSK.
-psk val
Usa la clave PSK val al usar una suite de cifrado PSK. La clave se proporciona como un número hexadecimal sin el prefijo 0x, por ejemplo, -psk 1a2b3c4d. Esta opción debe proporcionarse para usar una suite de cifrado PSK.
-psk_session file
Usa los datos SSL_SESSION codificados en PEM almacenados en file como base para un PSK. Ten en cuenta que esto solo funcionará si se negocia TLSv1.3.
-srpvfile
El archivo verificador para SRP. Esta opción está obsoleta.
-srpuserseed
Una cadena de semilla para una sal de usuario por defecto. Esta opción está obsoleta.
-listen
Esta opción solo se puede usar en conjunción con una de las opciones DTLS anteriores. Con esta opción, este comando escuchará en un puerto UDP las conexiones entrantes. Cualquier ClientHello que llegue se verificará para ver si tiene una cookie o no. A cualquiera que no tenga una cookie se le responderá con un HelloVerifyRequest. Si se recibe un ClientHello con una cookie, este comando cooperará

OPCIONES

-new
Inicia una nueva conexión de cliente. El cliente intentará realizar un handshake de TLS o SSL y, si tiene éxito, intentará enviar los datos solicitados. Si el servidor lo requiere, se le pedirá un certificado cliente. Si la opción -www o -WWW se ha especificado, entonces se intentará conectar a ese par y completar el handshake.
-sctp
Utiliza SCTP como protocolo de transporte en lugar de UDP en DTLS. Debe usarse junto con -dtls, -dtls1 o -dtls1_2. Esta opción solo está disponible donde OpenSSL tiene soporte para SCTP habilitado.
-sctp_label_bug
Utiliza el comportamiento incorrecto de implementaciones anteriores de OpenSSL al calcular secretos compartidos de pares de puntos finales para DTLS/SCTP. Esto permite la comunicación con implementaciones antiguas defectuosas, pero rompe la interoperabilidad con implementaciones correctas. Debe usarse junto con -sctp. Esta opción solo está disponible donde OpenSSL tiene soporte para SCTP habilitado.
-use_srtp
Ofrece gestión de claves SRTP con una lista de perfiles separados por dos puntos.
-no_dhe
Si esta opción está activada, no se cargarán parámetros DH, lo que deshabilita efectivamente las suites de cifrado DH efímero.
-alpn val, -nextprotoneg val
Estas banderas habilitan la negociación de protocolo de capa de aplicación o la negociación de protocolo siguiente (NPN), respectivamente. ALPN es el estándar IETF y reemplaza a NPN. La lista val es una lista separada por comas de nombres de protocolo compatibles. La lista debe contener los protocolos más deseables primero. Los nombres de protocolo son cadenas ASCII imprimibles, por ejemplo, "http/1.1" o "spdy/3". La bandera -nextprotoneg no se puede especificar si se utiliza -tls1_3.
-ktls
Habilita Kernel TLS para enviar y recibir. Esta opción se introdujo en OpenSSL 3.2.0. Kernel TLS está desactivado por defecto a partir de OpenSSL 3.2.0.
-sendfile
Si esta opción está activada y KTLS está habilitado, se utilizará SSL_sendfile() en lugar de BIO_write() para enviar la respuesta HTTP solicitada por un cliente. Esta opción solo es válida cuando se especifican -ktls junto con -WWW o -HTTP.
-zerocopy_sendfile
Si esta opción está activada, SSL_sendfile() utilizará el modo TX zerocopy, lo que proporciona un aumento de rendimiento cuando se utiliza con la descarga de hardware KTLS. Tenga en cuenta que se pueden transmitir registros TLS no válidos si el archivo se modifica mientras se envía. Esta opción depende de -sendfile; cuando se usa sola, -sendfile se implica y se muestra una advertencia. Tenga en cuenta que sendfile de KTLS en FreeBSD siempre se ejecuta en modo zerocopy.
-keylogfile outfile
Añade secretos TLS al archivo de registro de claves especificado para que programas externos (como Wireshark) puedan descifrar conexiones TLS.
-max_early_data int
Cambia el tamaño máximo predeterminado de datos tempranos que se especifican para nuevas sesiones y cualquier dato temprano entrante (cuando se usa en conjunción con la bandera -early_data). El valor predeterminado es aproximadamente 16k. El argumento debe ser un entero mayor o igual a 0.
-recv_max_early_data int
Especifica el límite estricto en el número máximo de bytes de datos tempranos que se aceptarán.
-early_data
Acepta datos tempranos cuando sea posible. No se puede usar junto con -www, -WWW, -HTTP o -rev.
-stateless
Requiere cookies TLSv1.3.
-anti_replay, -no_anti_replay
Activa o desactiva la protección contra repetición, respectivamente. La protección contra repetición está activada por defecto a menos que se anule mediante un archivo de configuración. Cuando está activada, OpenSSL detectará automáticamente si un ticket de sesión se ha utilizado más de una vez, se ha negociado TLSv1.3 y los datos tempranos están habilitados en el servidor. Se fuerza un handshake completo si se utiliza un ticket de sesión por segunda vez o subsiguientes. Cualquier dato temprano enviado será rechazado.
-tfo
Habilita la aceptación de conexiones TCP Fast Open (RFC7413).
-cert_comp
Pre-comprime certificados (RFC8879) que se enviarán durante el handshake.
-nameopt option
Esto especifica cómo se muestran los nombres del sujeto o del emisor. Ver openssl-namedisplay-options(1) para detalles.
-no_ssl3, -no_tls1, -no_tls1_1, -no_tls1_2, -no_tls1_3, -ssl3, -tls1, -tls1_1, -tls1_2, -tls1_3
Ver "Opciones de versión TLS" en openssl(1).
-dtls, -dtls1, -dtls1_2
Estos especifican el uso de DTLS en lugar de TLS. Ver "Opciones de versión TLS" en openssl(1).
-bugs, -comp, -no_comp, -no_ticket, -serverpref, -client_renegotiation, -legacy_renegotiation, -no_renegotiation, -no_resumption_on_reneg, -legacy_server_connect, -no_legacy_server_connect, -no_etm -allow_no_dhe_kex, -prefer_no_dhe_kex, -prioritize_chacha, -strict, -sigalgs algs, -client_sigalgs algs, -groups groups, -curves curves, -named_curve curve, -cipher ciphers, -ciphersuites 1.3ciphers, -min_protocol minprot, -max_protocol maxprot, -record_padding padding, -debug_broken_protocol, -no_middlebox
Ver "COMANDOS ADMITIDOS EN LÍNEA DE COMANDOS" en SSL_CONF_cmd(3) para detalles.
-xkey infile, -xcert file, -xchain file, -xchain_build file, -xcertform DER|PEM, -xkeyform DER|PEM
Establece opciones extendidas de verificación de certificados. Ver "Opciones de verificación extendidas" en openssl-verification-options(1) para detalles.
-CAfile file, -no-CAfile, -CApath dir, -no-CApath, -CAstore uri, -no-CAstore
Ver "Opciones de certificados de confianza" en openssl-verification-options(1) para detalles.
-rand files, -writerand file
Ver "Opciones de estado aleatorio" en openssl(1) para detalles.
-engine id
Ver "Opciones de motor" en openssl(1). Esta opción está obsoleta.
-provider name
-provider-path path
-provparam [name:]key=value
-propquery propq
Ver "Opciones de proveedor" en openssl(1), provider(7) y property(7).
-allow_proxy_certs, -attime, -no_check_time, -check_ss_sig, -crl_check, -crl_check_all, -explicit_policy, -extended_crl, -ignore_critical, -inhibit_any, -inhibit_map, -no_alt_chains, -partial_chain, -policy, -policy_check, -policy_print, -purpose, -suiteB_128, -suiteB_128_only, -suiteB_192, -trusted_first, -use_deltas, -auth_level, -verify_depth, -verify_email, -verify_hostname, -verify_ip, -verify_name, -x509_strict -issuer_checks
Establece varias opciones de verificación de la cadena de certificados. Ver "Opciones de verificación" en openssl-verification-options(1) para obtener detalles.

Si el servidor solicita un certificado de cliente, los errores de verificación se muestran, para depuración, pero el comando continuará a menos que se utilice la opción -verify_return_error.

-enable_server_rpk
Habilita el soporte para enviar claves públicas sin procesar (RFC7250) al cliente. Se enviará una clave pública sin procesar por el servidor, si es solicitada por el cliente, siempre que se configure un par de clave y certificado público adecuados. Los clientes que no admiten claves públicas sin procesar o prefieren usar certificados X.509 aún pueden optar por recibir certificados X.509 como de costumbre.

Las claves públicas sin procesar se extraen del par certificado/clave privada configurado.

-enable_client_rpk
Habilita el soporte para recibir claves públicas sin procesar (RFC7250) del cliente. El uso de certificados X.509 por parte del cliente es opcional, y los clientes que admiten claves públicas sin procesar pueden optar por usarlas. Los clientes que no admiten claves públicas sin procesar o prefieren usar certificados X.509 aún pueden optar por enviar certificados X.509 como de costumbre.

Las claves públicas sin procesar se extraen del par certificado/clave privada configurado.

COMANDOS CONECTADOS

Si se establece una solicitud de conexión con un cliente SSL y no se ha utilizado la opción -www ni la opción -WWW, normalmente cualquier dato recibido del cliente se mostrará y cualquier pulsación de tecla se enviará al cliente.

También se reconocen ciertos comandos que realizan operaciones especiales. Estos comandos son una letra que debe aparecer al principio de una línea. Se enumeran a continuación.

DESCRIPTION

The s_server and s_client utilities are simple SSL/TLS servers and clients that allow you to debug SSL protocols. They can be used for testing and debugging client or server applications, or for evaluating the security of an SSL/TLS implementation.

The programs accept a wide range of command-line options to configure various aspects of the SSL/TLS connection, including certificate handling, cipher suites, protocol versions, and session management.

They can also be used to interact with the established SSL/TLS connection by sending and receiving data, and to perform various SSL/TLS operations such as renegotiation and certificate requests.

OPTIONS

A comprehensive list of options is available in the manual pages for openssl-s_server and openssl-s_client. Some common options include:

-quiet
Suppresses verbose output.
-state
Prints the SSL state machine state and transitions.
-msg
Prints SSL message contents.
-debug
Enables detailed debugging output.
-verify depth
Sets the certificate verification depth.
-cert file
Specifies the certificate file.
-key file
Specifies the private key file.
-cipher list
Specifies the cipher list to use.
-tls1_2
Enables TLSv1.2.
-tls1_3
Enables TLSv1.3.
-connect host:port
Connects to the specified host and port (for s_client).
-accept port
Listens on the specified port (for s_server).

CONNECTED COMMANDS

Once a connection is established, the following commands can be sent to the server by typing them followed by Enter:

q
Finaliza la conexión SSL actual pero sigue aceptando nuevas conexiones.
Q
Finaliza la conexión SSL actual y sale.
r
Renegocia la sesión SSL (solo TLSv1.2 y anteriores).
R
Renegocia la sesión SSL y solicita un certificado de cliente (solo TLSv1.2 y anteriores).
P
Envía texto plano a través de la conexión TCP subyacente: esto debería hacer que el cliente se desconecte debido a una violación del protocolo.
S
Imprime información sobre el estado de la caché de sesiones.
k
Envía un mensaje de actualización de clave al cliente (solo TLSv1.3)
K
Envía un mensaje de actualización de clave al cliente y solicita uno a cambio (solo TLSv1.3)
c
Envía una solicitud de certificado al cliente (solo TLSv1.3)

NOTES

Este comando se puede usar para depurar clientes SSL. Para aceptar conexiones de un navegador web, el comando:

openssl s_server -accept 443 -www

se puede usar, por ejemplo.

Aunque especificar una lista vacía de CA al solicitar un certificado de cliente es, en sentido estricto, una violación del protocolo, algunos clientes SSL lo interpretan como que cualquier CA es aceptable. Esto es útil con fines de depuración.

Los parámetros de la sesión se pueden imprimir usando el comando openssl-sess_id(1).

BUGS

Debido a que este programa tiene muchas opciones y también porque algunas de las técnicas utilizadas son bastante antiguas, el código fuente en C de este comando es bastante difícil de leer y no es un modelo de cómo deberían hacerse las cosas. Un programa de servidor SSL típico sería mucho más simple.

La salida de los cifrados comunes es incorrecta: solo da la lista de cifrados que OpenSSL reconoce y el cliente soporta.

Debería haber una forma para que este comando imprima detalles de cualquier suite de cifrado desconocida que un cliente diga que soporta.

HISTORY

La opción -no_alt_chains se añadió en OpenSSL 1.1.0.

Las opciones -allow-no-dhe-kex y -prioritize_chacha se añadieron en OpenSSL 1.1.1.

Las opciones -srpvfile, -srpuserseed y -engine fueron marcadas como obsoletas en OpenSSL 3.0.

Las opciones -enable_client_rpk, -enable_server_rpk, -no_rx_cert_comp, -no_tx_cert_comp y -tfo se añadieron en OpenSSL 3.2.

La opción -status_all se añadió en OpenSSL 3.6.
