NOMBRE

ostree.repo-config - configuración de repositorios OSTree

DESCRIPCIÓN

El archivo de configuración en un repositorio OSTree es un "keyfile" en el formato de la Especificación de entradas de escritorio XDG[1]. Tiene varias banderas globales, así como cero o más entradas remotas que describen cómo acceder a los repositorios remotos.

Consulte ostree.repo(5) para obtener más información sobre los repositorios OSTree.

OPCIONES DE SECCIÓN [CORE]

Opciones globales del repositorio. Las siguientes entradas están definidas:

mode

Una de bare, bare-user, bare-user-only, o archive-z2 (tenga en cuenta que archive se usa en todas partes).

repo_version

Actualmente, esto debe establecerse en 1.

auto-update-summary

Valor booleano que controla si se actualiza o no el archivo de resumen automáticamente después de agregar, eliminar o actualizar cualquier ref. Otras modificaciones que pueden hacer que un archivo de resumen quede obsoleto (como deltas estáticos o IDs de colección) no activan actualmente una actualización automática.

commit-update-summary

Esta opción está obsoleta. Use auto-update-summary en su lugar, para lo cual esta opción es ahora un alias.

fsync

Valor booleano que controla si se garantiza que los archivos están en almacenamiento estable al realizar operaciones como commits, pulls y checkouts. Por defecto es true.

Si deshabilita fsync, OSTree ya no será robusto contra fallos del kernel o pérdida de energía.

Puede optar por deshabilitar esto para repositorios de desarrollo locales, asumiendo que se pueden recrear desde el código fuente. De manera similar, podría deshabilitarlo para un espejo donde podría volver a descargar.

Para el repositorio del sistema, puede optar por deshabilitar fsync si tiene fuentes de alimentación ininterrumpidas y un kernel bien probado.

per-object-fsync

Por defecto, OSTree agrupará fsync() después de escribir todo; sin embargo, esto puede causar picos de latencia para otros procesos que también invocan fsync(). Active este booleano para reducir posibles picos de latencia, a costa de ralentizar las actualizaciones de OSTree. Lo más probable es que desee que esto esté activado por defecto para las actualizaciones del sistema operativo "en segundo plano".

min-free-space-percent

Valor de porcentaje entero (0-99) que especifica un porcentaje mínimo de espacio total (en bloques) en el sistema de archivos subyacente para mantener libre. El valor por defecto es 3, que se aplica cuando no se establece ni esta opción ni min-free-space-size.

Si min-free-space-size se establece en un valor distinto de cero, se ignora min-free-space-percent. Tenga en cuenta que min-free-space-percent no se aplica a los objetos de metadatos. Se asume que los objetos de metadatos son relativamente pequeños en tamaño en comparación con los objetos de contenido y, por lo tanto, se mantienen fuera del alcance de esta opción.

min-free-space-size

Valor (en MB, GB o TB potencias de 2) que especifica un espacio mínimo en el sistema de archivos subyacente para mantener libre. Ejemplos de valores aceptables: 500MB (524 288 000 bytes), 1GB (1 073 741 824 bytes), 1TB (1 099 511 627 776 bytes).

Si esta opción se establece en un valor distinto de cero, y min-free-space-percent también está establecido, esta opción tiene prioridad. Tenga en cuenta que min-free-space-size no se aplica a los objetos de metadatos. Se asume que los objetos de metadatos son relativamente pequeños en tamaño en comparación con los objetos de contenido y, por lo tanto, se mantienen fuera del alcance de esta opción.

add-remotes-config-dir

Valor booleano que controla si los nuevos remotos se agregarán en el directorio de configuración de remotos. Por defecto es true para los repositorios ostree del sistema. Cuando esto es false, los remotos se agregarán en el archivo de configuración del repositorio.

Esto solo se aplica a los repositorios que utilizan un directorio de configuración de remotos, como los repositorios ostree del sistema, que utilizan /etc/ostree/remotes.d. Los repositorios no del sistema no utilizan un directorio de configuración de remotos a menos que se especifique uno al abrir el repositorio.

payload-link-threshold

Un valor entero que especifica un tamaño mínimo de archivo para crear un enlace de carga útil. Por defecto está deshabilitado.

collection-id

Un nombre de dominio DNS inverso bajo su control, que permite la distribución peer-to-peer de refs en este repositorio. Consulte la sección --collection-id en ostree-init(1)

locking

Valor booleano que controla si OSTree realiza el bloqueo del repositorio internamente. Utiliza bloqueos de archivos y, por lo tanto, es para la exclusión de múltiples procesos (por ejemplo, Flatpak y OSTree escribiendo en el mismo repositorio por separado). Esto está habilitado por defecto desde 2018.5.

lock-timeout-secs

Valor entero que controla el número de segundos que se bloqueará al intentar adquirir un bloqueo (ver arriba). Un valor de -1 significa bloquear indefinidamente. El valor por defecto es 300. Este tiempo de espera ahora se considera un error; porque es probable que cause fallos. Se recomienda establecerlo en -1, y tener tiempos de espera a un nivel de aplicación superior si se desea.

default-repo-finders

Lista separada por punto y coma de localizadores predeterminados (fuentes de refs) a usar al descargar. Esto se puede usar para deshabilitar la descarga desde sistemas de archivos montados, peers en la red local o Internet. Sin embargo, tenga en cuenta que solo se aplica cuando no se especifican explícitamente un conjunto de localizadores, ya sea por un consumidor de la API de libostree o en la línea de comandos. Los valores posibles son: config, lan y mount (o cualquier combinación de ellos). Si no está establecido, esto por defecto es config;mount; (ya que el localizador LAN es costoso).

no-deltas-in-summary

Valor booleano que controla si OSTree debe omitir la inclusión de un índice de deltas disponibles en el archivo de resumen. Por defecto es false.

Desde 2020.7, OSTree puede usar índices delta fuera del archivo de resumen, lo que hace que el archivo de resumen sea más pequeño (especialmente para repositorios más grandes). Sin embargo, por defecto, aún creamos el índice en el archivo de resumen para que funcionen los clientes más antiguos. Si sabe que todos los clientes serán versiones posteriores a 2020.7, puede habilitar esto para ahorrar ancho de banda de red.

OPCIONES DE SECCIÓN [NOMBRE_REMOTO"]

Describe la ubicación de un repositorio remoto.

url

Debe estar presente; declara la URL para acceder a metadatos y contenido del remoto. Consulte también contenturl. Los esquemas soportados se documentan a continuación.

contenturl

Declara la URL para acceder al contenido (archivos, partes delta estáticas). Cuando se especifica, url se utiliza solo para metadatos: resumen, "superbloques" delta estáticos.

branches

Una lista de cadenas. Representa las ramas predeterminadas configuradas para descargar del remoto cuando no se solicitan ramas específicas durante una operación de descarga.

proxy

Un valor de cadena, si se proporciona, debe ser una URL para un proxy HTTP a utilizar para acceder a este repositorio.

gpg-verify

Un valor booleano, por defecto es true. Controla si OSTree requerirá que los commits estén firmados por una clave GPG conocida. Para más información, consulte el manual de ostree(1) bajo GPG.

gpg-verify-summary

Un valor booleano, por defecto es false. Controla si OSTree verificará si el resumen está firmado por una clave GPG conocida. Para más información, consulte el manual de ostree(1) bajo GPG.

tls-permissive

Un valor booleano, por defecto es false. Por defecto, los certificados TLS del servidor se verificarán con la tienda de certificados del sistema. Si esta variable está establecida, se aceptará cualquier certificado.

tls-client-cert-path

Ruta al archivo del certificado del lado del cliente, para presentarlo al realizar solicitudes a este repositorio.

tls-client-key-path

Ruta al archivo que contiene la clave del certificado del lado del cliente, para presentarla al realizar solicitudes a este repositorio.

tls-ca-path

Ruta al archivo que contiene anclas de confianza en lugar de la base de datos de CA del sistema.

http2

Un valor booleano, por defecto es true. Por defecto, libostree utilizará HTTP2; establecer esto en false lo deshabilitará. Puede ser útil para solucionar problemas con servidores defectuosos.

u

NAME

ostree.repo-config — Repository configuration file format for OSTree

DESCRIPTION

The repository configuration file is an INI-style file that defines various options for the repository. It is located at /ostree/repo/config, and may also include configuration from files in /etc/ostree/repo.d/. The options are grouped into sections, indicated by square brackets.

The following sections are defined:

[CORE] SECTION OPTIONS

This section contains core repository options.

elected-subdirs

An array of strings. If set, OSTree will only consider subdirectories specified in this list when looking for content. This can be useful for splitting up a large repository into smaller parts.

fsck-on-mount

A boolean value. If true, OSTree will perform a filesystem check on the repository when it is mounted. Defaults to true.

priority

An integer value. If multiple repositories are configured, OSTree will prefer to pull from repositories with a higher priority. Defaults to 0.

[REMOTE NAME"] SECTION OPTIONS"

This section defines options for a specific remote repository. Replace "REMOTE_NAME" with the actual name of the remote.

url

The base URL of the remote repository. This can be a local path, HTTP, or HTTPS URL.

contenturl

The URL where content (e.g., commit objects) can be fetched. This is often different from the url, for example, when using a CDN.

mirrorlist

A URL pointing to a mirror list file. This file contains a newline-separated list of URLs that OSTree will randomly choose from. This can be combined with url or contenturl.

gpgkeypath

The path to the GPG public key used to verify signatures from this remote. If not specified, OSTree will use the system-wide GPG keys.

tls-ca-path

The path to a custom CA certificate bundle for verifying TLS certificates from this remote.

tls-client-cert-path

The path to a client certificate for TLS client authentication with this remote.

disabled

A boolean value. If true, this remote will be ignored. Defaults to false.

configured-state

If set, pulls from this remote will fail with the configured text. This is intended for OS vendors which have a subscription process to access content.

custom-backend

If set, pulls from this remote via libostree will fail with an error that mentions the value. It is recommended to make this a software identifier token (e.g. "examplecorp-fetcher"), not freeform text ("ExampleCorp Fetcher"). This is intended to be used by higher level software that wants to fetch ostree commits via some other mechanism, while still reusing the core libostree infrastructure around e.g. signatures.

[SYSROOT] SECTION OPTIONS

Options for the sysroot, which contains the OSTree repository, deployments, and stateroots. The following entries are defined:

readonly

A boolean value. If this is set to true, then the /sysroot mount point is mounted read-only. This is configured a legacy repository configuration and the equivalent option in ostree/prepare-root.conf should be used instead - see ostree-prepare-root(1).

bootloader

Configure the bootloader that OSTree uses when deploying the sysroot. This may take the values bootloader=none, bootloader=auto, bootloader=grub2, bootloader=syslinux, bootloader=uboot or bootloader=zipl. Default is auto.

If none, then OSTree will generate only BLS (Boot Loader Specification) fragments in sysroot/boot/loader/entries/ for the deployment.

If auto, then in addition to generating BLS fragments, OSTree will dynamically check for the existence of grub2, uboot, and syslinux bootloaders. If one of the bootloaders is found, then OSTree will generate a config for the bootloader found. For example, grub2-mkconfig is run for the grub2 case.

A specific bootloader type may also be explicitly requested by choosing grub2, syslinux, uboot or zipl.

boot-counting-tries

Integer value controlling the number of maximum boot attempts. The boot counting data is stored in the name of the boot loader entry. A boot loader entry file name may contain a plus (+) followed by a number. This may optionally be followed by a minus (-) followed by a second number. The dot (.) and file name suffix (conf or efi) must immediately follow. More details in the The Boot Loader Specification[2]

bls-append-except-default

A semicolon separated string list of key-value pairs. For example: bls-append-except-default=key1=value1;key2=value2. These key-value pairs will be injected into the generated BLS fragments of the non-default deployments. In other words, the BLS fragment of the default deployment will be unaffected by bls-append-except-default.

bootprefix

A boolean value; defaults to false. If set to true, the bootloader entries generated will include /boot as a prefix. This will likely be turned on by default in the future.

[EX-INTEGRITY] SECTION OPTIONS

The "ex-" prefix here signifies experimental options. The ex-integrity section contains options related to system integrity. Information about experimental options is canonically found in upstream tracking issues.

/ETC/OSTREE/REMOTES.D

In addition to the /ostree/repo/config file, remotes may also be specified in /etc/ostree/remotes.d. The remote configuration file must end in .conf; files whose name does not end in .conf will be ignored.

REPOSITORY URL/CONTENTURL

Originally, OSTree had just a url option for remotes. Since then, the contenturl option was introduced. Both of these support file, http, and https schemes.

Additionally, both of these can be prefixed with the string mirrorlist=, which instructs the client that the target url is a "mirrorlist" format, which is a plain text file of newline-separated URLs. Earlier URLs will be given precedence.

Note that currently, the tls-ca-path and tls-client-cert-path options apply to every HTTP request, even when contenturl and/or mirrorlist are in use. This may change in the future to only apply to metadata (i.e. url, not contenturl) fetches.

PER-REMOTE GPG KEYRINGS AND VERIFICATION

OSTree supports a per-remote GPG keyring, as well as a gpgkeypath option. For more information see ostree(1). in the section GPG verification.

PER-REMOTE HTTP COOKIES

Some content providers may want to control access to remote repositories via HTTP cookies. The ostree remote add-cookie and ostree remote delete-cookie commands will update a per-remote lookaside cookie jar, named $remotename.cookies.txt.
