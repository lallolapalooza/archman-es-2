NOMBRE

ovs-dpctl - administrar datapath de Open vSwitch

SINOPSIS

ovs-dpctl [opciones] comando [switch] [args...]

DESCRIPCIÓN

El programa ovs-dpctl puede crear, modificar y eliminar datapaths de Open vSwitch. Una única máquina puede alojar cualquier número de datapaths.

Este programa solo funciona con datapaths que se implementan fuera del propio ovs-vswitchd, como los datapaths basados en el kernel de Linux y Windows. Para administrar datapaths que están integrados en ovs-vswitchd, como el datapath de espacio de usuario (netdev), use ovs-appctl(8) para invocar los comandos dpctl/*, que se documentan en ovs-vswitchd(8).

Un datapath recién creado se asocia con un solo dispositivo de red, un dispositivo de red virtual a veces llamado el "puerto local" del datapath. Sin embargo, un datapath recién creado no está asociado con ninguno de los otros dispositivos de red del host. Para interceptar y procesar el tráfico en un dispositivo de red determinado, use el comando add-if para agregar explícitamente ese dispositivo de red al datapath.

Si se está utilizando ovs-vswitchd(8), use ovs-vsctl(8) en lugar de ovs-dpctl.

La mayoría de los comandos de ovs-dpctl que funcionan con datapaths toman un argumento que especifica el nombre del datapath. Los nombres de datapath tienen el formato [tipo@]nombre, donde nombre es el dispositivo de red asociado con el puerto local del datapath. Si se proporciona tipo, especifica el proveedor del datapath de nombre, de lo contrario, se asume el proveedor predeterminado system.

Los siguientes comandos administran datapaths. No use comandos para agregar, eliminar o modificar datapaths si ovs-vswitchd se está ejecutando, ya que esto interfiere con la propia gestión de datapaths de ovs-vswitchd.

add-dp dp [netdev[,opción]...]
Crea el datapath dp, con un puerto local también llamado dp. Esto fallará si ya existe un dispositivo de red dp.
Si se especifican netdevs, ovs-dpctl los agrega al nuevo datapath, como si se hubiera especificado add-if.
del-dp dp
Elimina el datapath dp. Si dp está asociado con algún dispositivo de red, se eliminan automáticamente.
add-if dp netdev[,opción]...
Agrega cada netdev al conjunto de dispositivos de red que el datapath dp monitorea, donde dp es el nombre de un datapath existente, y netdev es el nombre de uno de los dispositivos de red del host, por ejemplo, eth0. Una vez que un dispositivo de red se ha agregado a un datapath, el datapath tiene control total sobre el tráfico del dispositivo de red y el dispositivo de red aparece silencioso para el resto del sistema.
Un netdev puede ir seguido de una lista de opciones separadas por comas. Actualmente se admiten las siguientes opciones:
type=tipo
Especifica el tipo de puerto a agregar. El tipo predeterminado es system.
port_no=puerto
Solicita un número de puerto específico dentro del datapath. Si esta opción no se especifica, se le asignará automáticamente uno.
clave=valor
Agrega una opción arbitraria de clave-valor a la configuración del puerto.
ovs-vswitchd.conf.db(5) documenta los tipos de puerto y las opciones disponibles.
set-if dp puerto[,opción]...
Reconfigura cada puerto en dp según lo especificado. Una opción del tipo clave=valor agrega la opción clave-valor especificada o reemplaza el valor de una clave existente. Una opción del tipo clave=, es decir, sin valor, elimina la clave-valor llamada clave. El tipo y el número de puerto de un puerto no se pueden cambiar, por lo que type y port_no solo se permiten si coinciden con la configuración existente.
del-if dp netdev...
Elimina cada netdev de la lista de dispositivos de red que el datapath dp monitorea.
dump-dps
Imprime el nombre de cada datapath configurado en una línea separada.
[-s | --statistics] show [dp...]
Imprime un resumen de los datapaths configurados, incluyendo sus números de datapath y una lista de puertos conectados a cada datapath. (El puerto local se identifica como puerto 0). Si se especifica -s o --statistics, entonces también se imprimen los contadores de paquetes y bytes para cada puerto.
Los números de datapath consisten en estadísticas de flujo y estadísticas de máscara de megaflujo.
La fila "lookups" muestra tres estadísticas relacionadas con la búsqueda de flujos activada por el procesamiento de paquetes entrantes en el datapath. "hit" muestra el número de paquetes que coinciden con flujos existentes. "missed" muestra el número de paquetes que no coinciden con ningún flujo existente y requieren procesamiento en el espacio de usuario. "lost" muestra el número de paquetes destinados al proceso del espacio de usuario pero que posteriormente se cayeron antes de llegar al espacio de usuario. La suma de "hit" y "miss" es igual al número total de paquetes procesados por el datapath.
La fila "flows" muestra el número de flujos en el datapath.
La fila "masks" muestra las estadísticas de máscara de megaflujo. Esta fila se omite para datapaths que no implementan megaflujo. "hit" muestra el número total de máscaras visitadas para hacer coincidir paquetes entrantes. "total" muestra el número de máscaras en el datapath. "hit/pkt" muestra el número promedio de máscaras visitadas por paquete; la relación entre "hit" y el número total de paquetes procesados por el datapath.
Si se especifican uno o más datapaths, solo se muestra información sobre esos datapaths. De lo contrario, ovs-dpctl muestra información sobre todos los datapaths configurados.

COMANDOS DE DEPURACIÓN DE LA TABLA DE FLUJOS DEL DATAPATH

Los siguientes comandos son principalmente útiles para depurar Open vSwitch. Las entradas de la tabla de flujos (tanto coincidencias como acciones) con las que funcionan no son entradas de flujo OpenFlow. En cambio, son flujos diferentes y considerablemente más simples mantenidos por el módulo del kernel de Open vSwitch. No use comandos para agregar, eliminar o modificar flujos de datapath si ovs-vswitchd se está ejecutando, ya que interfiere con la propia gestión de flujos de datapath de ovs-vswitchd. Use ovs-ofctl(8), en su lugar, para trabajar con entradas de flujo OpenFlow.

El argumento dp para cada uno de estos comandos es opcional cuando existe exactamente un datapath, en cuyo caso ese datapath es el predeterminado. Cuando existen múltiples datapaths, se requiere un nombre de datapath.

[-m | --more] [--names | --no-names] dump-flows [dp] [filter=filtro] [type=tipo] [pmd=pmd]
Imprime en la consola todas las entradas de flujo en la tabla de flujos del datapath dp. Sin -m o --more, la salida omite los campos de coincidencia que un flujo comodín descarta por completo; con -m o --more, la salida incluye todos los campos comodín.
Si se especifica filter=filtro, solo se muestran los flujos que coinciden con el filtro. filtro es un flujo en un formato similar al aceptado por el comando add-flow de ovs-ofctl(8). (Esto no es un flujo OpenFlow: además de otras diferencias, nunca contiene comodines). El filtro también es útil para hacer coincidir campos comodín en el flujo del datapath. Como ejemplo, filter='tcp,tp_src=100' coincidirá con el flujo del datapath que contiene 'tcp(src=80/0xff00,dst=8080/0xff)'.
Si se especifica pmd=pmd, solo se muestran los flujos del pmd especificado. Usar pmd=-1 restringirá la exportación a los flujos del hilo principal. Esta opción solo está disponible en sistemas con soporte para pmd (hilo de procesamiento de paquetes).
add-flow [dp] match[,match...] actions
Agrega una entrada de flujo al datapath dp. El argumento match especifica los campos que se deben hacer coincidir y actions especifica las acciones que se deben tomar si se hace coincidencia. Consulte la documentación de ovs-ofctl(8) para obtener detalles sobre el formato de los argumentos match y actions.
del-flows [dp] [filter=filtro]
Elimina todas las entradas de flujo del datapath dp. Si se especifica filter=filtro, solo se eliminan los flujos que coinciden con el filtro. El filtro tiene el mismo formato que el argumento filter para dump-flows.
netflow-stat [dp]
Imprime estadísticas de NetFlow para el datapath dp. Esto solo es relevante si el datapath ha sido configurado para usar NetFlow.
sflow-flush [dp]
Elimina las estadísticas de sFlow para el datapath dp. Esto solo es relevante si el datapath ha sido configurado para usar sFlow.
sflow-list-conf [dp]
Imprime la configuración de sFlow para el datapath dp. Esto solo es relevante si el datapath ha sido configurado para usar sFlow.
sflow-get-sample-rate [dp]
Obtiene la tasa de muestreo de sFlow para el datapath dp. Esto solo es relevante si el datapath ha sido configurado para usar sFlow.
sflow-get-polling-interval [dp]
Obtiene el intervalo de sondeo de sFlow para el datapath dp. Esto solo es relevante si el datapath ha sido configurado para usar sFlow.
sflow-set-sample-rate dp rate
Establece la tasa de muestreo de sFlow para el datapath dp a rate. Esto solo es relevante si el datapath ha sido configurado para usar sFlow.
sflow-set-polling-interval dp interval
Establece el intervalo de sondeo de sFlow para el datapath dp a interval. Esto solo es relevante si el datapath ha sido configurado para usar sFlow.

OPCIONES

Los siguientes comandos modifican el comportamiento de ovs-dpctl:

--strict
Produce errores si un comando falla en una operación que podría fallar silenciosamente (por ejemplo, eliminar una interfaz que no existe).
-t TABLE
--table=TABLE
En comandos que operan sobre tablas de flujo, como dump-flows o add-flow, seleccione la tabla TABLE en lugar de la tabla predeterminada 0.

OPCIONES COMUNES

Estos son los argumentos de línea de comandos comunes a todos los programas de Open vSwitch.

--help
Imprime un resumen de los comandos y opciones de la línea de comandos y sale.
--version
Imprime la versión del programa y sale.

VER TAMBIÉN

ovs-vswitchd(8), ovs-vsctl(8), ovs-ofctl(8), ovs-appctl(8), ovs-vswitchd.conf.db(5)

y soportado por el **userspace datapath**.
Si se especifica **type=**type, solo muestra flujos de los tipos especificados. Esta opción solo se soporta para **ovs-appctl dpctl/dump-flows**. type es una lista separada por comas, que puede contener cualquiera de los siguientes:
**ovs** - muestra flujos manejados en el dp de ovs
**tc** - muestra flujos manejados en el dp de tc
**dpdk** - muestra flujos completamente descargados por dpdk
**offloaded** - muestra flujos descargados a HW
**non-offloaded** - muestra flujos no descargados a HW
**partially-offloaded** - muestra flujos donde solo parte de su procesamiento se realiza en HW
**all** - muestra todos los tipos de flujos
Por defecto, se muestran todos los tipos de flujos. **ovs-dpctl** siempre actúa como si el **type** fuera ovs.
add-flow [dp] flow actions
[--clear] [--may-create] [-s | --statistics] mod-flow [dp] flow actions
Agrega o modifica un flujo en la tabla de flujos de dp que, cuando llega un paquete que coincide con flow, causa que se ejecuten las actions.
El comando **add-flow** solo tiene éxito si flow no existe ya en dp. Por el contrario, **mod-flow** sin **--may-create** solo modifica las acciones para un flujo existente. Con **--may-create**, **mod-flow** agregará un nuevo flujo o modificará uno existente.
Si se especifica **-s** o **--statistics**, entonces **mod-flow** imprime las estadísticas del flujo modificado. Las estadísticas de un flujo son el número de paquetes y bytes que han pasado por el flujo, el tiempo transcurrido desde que el flujo procesó un paquete por última vez (si es que lo hizo), y (para flujos TCP) la unión de las banderas TCP procesadas a través del flujo.
Con **--clear**, **mod-flow** pone a cero las estadísticas del flujo. Las estadísticas impresas si también se especifican **-s** o **--statistics** son las de justo antes de borrar las estadísticas.
NOTA: flow y actions no coinciden con la sintaxis usada con el comando **add-flow** de ovs-ofctl(8).
Ejemplos de Uso

Reenvío de ARP entre los puertos 1 y 2 en el datapath myDP:

ovs-dpctl add-flow myDP \
"in_port(1),eth(),eth_type(0x0806),arp()" 2
ovs-dpctl add-flow myDP \
"in_port(2),eth(),eth_type(0x0806),arp()" 1

Reenvío de todo el tráfico IPv4 entre dos direcciones en los puertos 1 y 2:

ovs-dpctl add-flow myDP \
"in_port(1),eth(),eth_type(0x800),\
ipv4(src=172.31.110.4,dst=172.31.110.5)" 2
ovs-dpctl add-flow myDP \
"in_port(2),eth(),eth_type(0x800),\
ipv4(src=172.31.110.5,dst=172.31.110.4)" 1
add-flows [dp] file
mod-flows [dp] file
del-flows [dp] file
Lee entradas de flujo desde file (o stdin si file es **-**) y agrega, modifica o elimina cada entrada del datapath. Cada especificación de flujo (por ejemplo, cada línea en file) puede comenzar con la palabra clave **add**, **modify** o **delete** para especificar si un flujo se va a agregar, modificar o eliminar. Una especificación de flujo sin una de estas palabras clave se trata según el comando utilizado. Todas las modificaciones de flujo se ejecutan como transacciones individuales en el orden especificado.
[-s | --statistics] del-flow [dp] flow
Elimina el flujo de la tabla de flujos de dp que coincide con flow. Si se especifica **-s** o **--statistics**, entonces **del-flow** imprime las estadísticas del flujo eliminado.
[-m | --more] [--names | --no-names] get-flow [dp] ufid:ufid
Recupera el flujo de la tabla de flujos de dp con el identificador único ufid. ufid debe especificarse como una cadena de 32 caracteres hexadecimales.
del-flows [dp]
Elimina todas las entradas de flujo de la tabla de flujos del datapath dp.

COMANDOS DE CACHÉ DE FLUJOS DEL DATAPATH

Los siguientes comandos son útiles para depurar y configurar los ajustes de la caché de flujos del datapath.

cache-get-size [dp]
Imprime los tamaños de caché actuales en la consola.
cache-set-size dp cache size
Establece la cache específica de dp al size dado. El nombre de la caché se puede encontrar usando el comando **cache-get-size**.

COMANDOS DE TABLA DE SEGUIMIENTO DE CONEXIONES

Los siguientes comandos son útiles para depurar y configurar la tabla de seguimiento de conexiones en el datapath.

El argumento dp en cada uno de estos comandos es opcional cuando solo existe un datapath, en cuyo caso ese datapath es el predeterminado. Cuando existen varios datapath, se requiere un nombre de datapath.

N.B. (Específico de Linux): los datapath del sistema (es decir, los datapath del módulo del kernel de Open vSwitch) comparten una única tabla de seguimiento de conexiones (que también es utilizada por otros subsistemas del kernel, como iptables, nftables y la pila host regular). Por lo tanto, los siguientes comandos no se aplican específicamente a un datapath.

ipf-set-enabled [dp] v4|v6
ipf-set-disabled [dp] v4|v6
Habilita o deshabilita el manejo de fragmentación IP para el rastreador de conexiones en el espacio de usuario. Se debe especificar **v4** o **v6**. Tanto el reensamblaje de fragmentos IPv4 como IPv6 están habilitados por defecto. Solo compatible con el datapath en espacio de usuario.
ipf-set-min-frag [dp] v4|v6 minfrag
Establece el tamaño mínimo de fragmento (cabecera L3 y datos) para fragmentos no finales a minfrag. Se debe especificar **v4** o **v6**. Para una mayor seguridad contra ataques de denegación de servicio (DoS), generalmente se pueden usar tamaños mínimos de fragmentos más altos. El valor predeterminado de IPv4 es 1200 y el mínimo limitado es 400. El valor predeterminado de IPv6 es 1280, con un mínimo limitado de 400, para flexibilidad de prueba. El tamaño máximo de fragmento no está limitado, sin embargo, establecer este valor demasiado alto podría resultar en la eliminación de fragmentos válidos. Solo compatible con el datapath en espacio de usuario.
ipf-set-max-nfrags [dp] maxfrags
Establece el número máximo de fragmentos rastreados por el rastreador de conexiones del datapath en espacio de usuario a maxfrags. El valor predeterminado es 1000 y el máximo limitado es 5000. Tenga en cuenta que los búferes de paquetes pueden ser retenidos por el módulo de fragmentación mientras los fragmentos están incompletos, pero caducarán después de 15 segundos. El tamaño del grupo de memoria debe configurarse en consecuencia cuando la fragmentación esté habilitada. Solo compatible con el datapath en espacio de usuario.
[-m | --more] ipf-get-status [dp]
Obtiene la configuración y los contadores de fragmentos asociados con el manejo de fragmentación del rastreador de conexiones del datapath en espacio de usuario. Con **-m** o **--more**, también vuelca las listas de fragmentos IP. Solo compatible con el datapath en espacio de usuario.
[-m | --more] [-s | --statistics] dump-conntrack [dp] [zone=zone]
Imprime en la consola todas las entradas de conexión en el rastreador utilizado por dp. Si se especifica **zone=**zone, solo muestra las conexiones en zone. Con **--more**, se incluyen algunos detalles específicos de la implementación. Con **--statistics**, se agregan tiempos de espera y marcas de tiempo a la salida.
dump-conntrack-exp [dp] [zone=zone]
Imprime en la consola todas las entradas de expectativa en el rastreador utilizado por dp. Si se especifica **zone=**zone, solo muestra las expectativas en zone. Solo compatible con el datapath en espacio de usuario.
flush-conntrack [dp] [zone=zone] [ct-origin-tuple [ct-reply-tuple]]
Elimina las entradas de conexión en el rastreador utilizado por dp basándose en zone y la tupla de seguimiento de conexiones ct-origin-tuple. Si no se proporciona ct-tuple, elimina todas las entradas de conexión. Si se especifica **zone**=zone, solo elimina las conexiones en zone.
Si se proporciona ct-[orig|reply]-tuple, elimina la entrada de conexión especificada por ct-[orig|reply]-tuple en zone. La zona tiene como valor predeterminado 0 si no se proporciona. El rastreador de conexiones en espacio de usuario requiere la eliminación con la tupla original pre-NAT y, de lo contrario, se generará un registro de advertencia. La tupla puede ser parcial y eliminará todas las conexiones que coincidan con los campos especificados. Para especificar solo ct-reply-tuple, proporcione una cadena vacía como ct-origin-tuple.
Nota: Actualmente existe una limitación para coincidir con ICMP; para coincidir parcialmente con parámetros ICMP, ct-[orig|reply]-tuple debe incluir la IP de origen o destino.
Un ejemplo de una tupla ct-[orig|reply]-tuple ICMP IPv4:
"ct_nw_src=10.1.1.1,ct_nw_dst=10.1.1.2,ct_nw_proto=1,icmp_type=8,icmp_code=0,icmp_id=10"
Un ejemplo de una tupla ct-[orig|reply]-tuple TCP IPv6:
"ct_ipv6_src=fc00::1,ct_ipv6_dst=fc00::2,ct_nw_proto=6,ct_tp_src=1,ct_tp_dst=2"
[-m | --more] ct-stats-show [dp] [zone=zone]
Muestra el número de conexiones agrupadas por protocolo utilizado por dp. Si se especifica **zone=**zone, los números se refieren a las conexiones en zone. Con **--more**, se agrupa por estado de conexión para cada protocolo.
ct-b

COMMANDS

ct-get-conns [dp] [gt=threshold]
Para cada bucket de conntrack, muestra el número de conexiones utilizadas por dp. Si se especifica gt=threshold, se muestran los números de bucket cuando el número de conexiones en un bucket es mayor que threshold.
ct-set-maxconns [dp] maxconns
Establece el límite máximo de entradas del rastreador de conexiones a maxconns en dp. Esto se puede utilizar para reducir la carga de procesamiento en el sistema debido al seguimiento de conexiones o simplemente para limitar el seguimiento de conexiones. Si el número de conexiones ya supera el nuevo límite máximo solicitado, el nuevo límite máximo se aplicará cuando el número de conexiones disminuya hasta ese límite, lo que normalmente ocurre debido a la expiración de la conexión. Solo compatible con datapath de espacio de usuario.
ct-get-maxconns [dp]
Imprime el límite máximo de entradas del rastreador de conexiones en dp. Solo compatible con datapath de espacio de usuario.
ct-get-nconns [dp]
Imprime el número actual de entradas del rastreador de conexiones en dp. Solo compatible con datapath de espacio de usuario.
ct-enable-tcp-seq-chk [dp]
ct-disable-tcp-seq-chk [dp]
Habilita o deshabilita la verificación de secuencia TCP. Cuando se establece en deshabilitado, toda la verificación de números de secuencia se deshabilita, incluso para reinicios TCP. Esto es similar, pero no idéntico, al modo 'be_liberal' de Netfilter. La deshabilitación de la verificación de números de secuencia no es una optimización en sí misma, pero es necesaria para algunos soportes de descarga de hardware que podrían ofrecer alguna ventaja de rendimiento. La verificación de números de secuencia está habilitada por defecto para garantizar una mejor seguridad y solo debe deshabilitarse si es necesario para soporte de descarga de hardware. Este comando solo es compatible con el datapath de espacio de usuario.
ct-get-tcp-seq-chk [dp]
Imprime si la verificación de secuencia TCP está habilitada o deshabilitada en dp. Solo compatible con el datapath de espacio de usuario.
ct-set-sweep-interval [dp] ms
Establece el intervalo de barrido. Solo compatible con el datapath de espacio de usuario.
ct-get-sweep-interval [dp]
Imprime el intervalo de barrido actual en ms. Solo compatible con el datapath de espacio de usuario.
ct-set-limits [dp] [default=default_limit] [zone=zone,limit=limit]...
Establece el número máximo permitido de conexiones en una zona de seguimiento de conexiones. Se puede establecer una zona específica en limit, y se pueden especificar múltiples zonas con una lista separada por comas. Si no se especifica un límite por zona para una zona particular en el datapath, se utiliza el límite predeterminado por zona. Se puede especificar una zona predeterminada con el argumento default=default_limit. Inicialmente, el límite predeterminado por zona es ilimitado. Se puede establecer un número ilimitado de entradas con un límite de 0.
ct-del-limits [dp] zone=zone[,zone]...
Elimina el límite de seguimiento de conexiones para zone. Se pueden especificar múltiples zonas con una lista separada por comas.
ct-get-limits [dp] [zone=zone[,zone]...]
Recupera el número máximo permitido de conexiones y los recuentos actuales por zona. Si se proporciona zone, solo se imprimen las zonas especificadas. Si no se especifican zonas, se proporcionan todos los límites y recuentos de zonas. El comando siempre muestra el límite de la zona predeterminada.

OPTIONS

-t

--timeout=secs
Limita el tiempo de ejecución de ovs-dpctl a aproximadamente secs segundos. Si expira el tiempo de espera, ovs-dpctl saldrá con una señal SIGALRM.
-v[spec]

--verbose=[spec]
Establece los niveles de registro. Sin ningún spec, establece el nivel de registro para cada módulo y destino en dbg. De lo contrario, spec es una lista de palabras separadas por espacios, comas o dos puntos, hasta una de cada categoría a continuación:
  • Un nombre de módulo válido, como se muestra en el comando vlog/list en ovs-appctl(8), limita el cambio de nivel de registro al módulo especificado.
  • syslog, console o file, para limitar el cambio de nivel de registro solo al registro del sistema, a la consola o a un archivo, respectivamente. (Si se especifica --detach, ovs-dpctl cierra sus descriptores de archivo estándar, por lo que el registro en la consola no tendrá efecto.)
En la plataforma Windows, se acepta syslog como palabra y solo es útil junto con la opción --syslog-target (la palabra no tiene efecto de otra manera).
•
off, emer, err, warn, info o dbg, para controlar el nivel de registro. Se registrarán los mensajes de la gravedad dada o superior, y los mensajes de menor gravedad se filtrarán. off filtra todos los mensajes. Consulte ovs-appctl(8) para obtener una definición de cada nivel de registro.
La capitalización no es significativa dentro de spec.
Independientemente de los niveles de registro establecidos para file, el registro en un archivo no se llevará a cabo a menos que también se especifique --log-file (ver más abajo).
Para compatibilidad con versiones anteriores de OVS, se acepta any como palabra pero no tiene efecto.
-v

--verbose
Establece el nivel de verbosidad de registro máximo, equivalente a --verbose=dbg.
-vPATTERN:destination:pattern

--verbose=PATTERN:destination:pattern
Establece el patrón de registro para destination a pattern. Consulte ovs-appctl(8) para obtener una descripción de la sintaxis válida para pattern.
-vFACILITY:facility

--verbose=FACILITY:facility
Establece la instalación RFC5424 del mensaje de registro. facility puede ser uno de kern, user, mail, daemon, auth, syslog, lpr, news, uucp, clock, ftp, ntp, audit, alert, clock2, local0, local1, local2, local3, local4, local5, local6 o local7. Si esta opción no se especifica, se utiliza daemon como valor predeterminado para el syslog del sistema local y se utiliza local0 al enviar un mensaje al destino proporcionado a través de la opción --syslog-target.
--log-file[=file]
Habilita el registro en un archivo. Si se especifica file, se utiliza como el nombre exacto del archivo de registro. El nombre de archivo de registro predeterminado utilizado si se omite file es /var/log/openvswitch/ovs-dpctl.log.
--syslog-target=host:port
Envía mensajes de syslog al puerto UDP port en host, además del syslog del sistema. El host debe ser una dirección IP numérica, no un nombre de host.
--syslog-method=method
Especifica el method de cómo se deben enviar los mensajes de syslog al demonio syslog. Se admiten las siguientes formas:
  • libc, utiliza la función syslog() de libc. La desventaja de usar esta opción es que libc agrega un prefijo fijo a cada mensaje antes de que se envíe realmente al demonio syslog a través del socket de dominio UNIX /dev/log.
  • unix:file, utiliza el socket de dominio UNIX directamente. Es posible especificar un formato de mensaje arbitrario con esta opción. Sin embargo, las versiones anteriores de rsyslogd 8.9 y anteriores utilizan de todos modos una función de análisis codificada que limita el uso del socket de dominio UNIX. Si desea utilizar un formato de mensaje arbitrario con versiones anteriores de rsyslogd, utilice en su lugar un socket UDP a la dirección IP de localhost.
  • udp:ip:port, utiliza un socket UDP. Con este método es posible utilizar un formato de mensaje arbitrario también con rsyslogd anterior. Al enviar mensajes de syslog a través de un socket UDP, se deben tomar precauciones adicionales, por ejemplo, el demonio syslog debe estar configurado para escuchar en el puerto UDP especificado, las reglas de iptables accidentales podrían interferir con el tráfico local de syslog y existen algunas consideraciones de seguridad que se aplican a los sockets UDP, pero no a los sockets de dominio UNIX.
  • null, descarta todos los mensajes registrados en syslog.
El valor predeterminado se toma de la variable de entorno OVS_SYSLOG_METHOD; si no está establecida, el valor predeterminado es libc.
