NOMBRE

opam-switch - Gestiona múltiples prefijos de instalación.

SINOPSIS

opam switch [OPCIÓN]… [COMANDO] [ARG]…

DESCRIPCIÓN

Este comando se utiliza para gestionar "switches" (cambios), que son prefijos de instalación independientes con su propio compilador y conjuntos de paquetes instalados y fijados. Esto es típicamente útil para tener diferentes versiones del compilador disponibles a la vez.

Utiliza opam switch create para crear un nuevo switch y opam switch set para establecer el switch activo actualmente. Sin argumento, lista los switches instalados, con un argumento de switch, se utiliza por defecto set.

Los *SWITCHES* de switch pueden ser un nombre simple, para switches que se mantendrán dentro de ~/.opam, o un nombre de directorio, que en ese caso es el directorio donde se instalará el prefijo del switch, como _opam. Opam seleccionará automáticamente un switch con ese nombre encontrado en el directorio actual o sus padres, a menos que se establezca OPAMSWITCH o se especifique --switch. Al crear un switch de directorio, si se encuentran definiciones de paquetes localmente, se le pedirá automáticamente al usuario que los instale después de que el switch se cree, a menos que se especifique --no-install.

opam switch set establece el switch predeterminado globalmente. El hook del shell, cuando está habilitado, sincroniza la sesión del shell actual con este switch, a menos que el directorio actual sea un switch local, en cuyo caso se utiliza ese switch local. Siempre puedes usar eval $(opam env --switch=SWITCH --set-switch) para especificar el switch explícitamente, lo que anula el hook del shell.

COMANDOS

Sin argumento, se utiliza por defecto list.

SWITCH
Con un argumento SWITCH, se utiliza por defecto set SWITCH.
-
Vuelve al switch no local anterior (similar a git switch -). Para establecer el switch actual a un switch llamado - usa --cli=2.1 o inferior, o usa opam switch set -
create SWITCH [COMPILADOR]
Crea un nuevo switch e instala el compilador dado allí. SWITCH puede ser un nombre simple o un directorio, absoluto o relativo, en cuyo caso se crea un switch local debajo del directorio dado. COMPILADOR, si se omite, se utiliza por defecto SWITCH si es un nombre simple, a menos que se especifique --packages, --formula o --empty. Al crear un switch local, y si ninguna de estas opciones está presente, el compilador se elige de acuerdo con el valor predeterminado de la configuración (ver opam-init(1)). Si el directorio elegido contiene definiciones de paquetes, se busca un compilador compatible dentro de la selección predeterminada, y los paquetes se instalarán automáticamente.
set SWITCH
Establece el switch activo actualmente, entre los switches instalados.
remove SWITCH
Elimina el switch dado del disco.
export ARCHIVO
Guarda el estado del switch actual en un archivo. Si se especifica --full, incluye los metadatos de todos los paquetes instalados, y si se especifica --freeze, congela todos los VCS a su commit actual.
import ARCHIVO
Importa un estado de switch guardado. Si se especifica --switch y no apunta a un switch existente, el switch se creará para la importación.
reinstall [SWITCH]
Reinstala el switch de compilador dado y todos sus paquetes.
list
Lista los switches instalados.
list-available [PATRON]
Lista todos los paquetes posibles que se recomiendan para la instalación al crear un nuevo switch, es decir, paquetes con la bandera compiler activada. Si no se proporciona un patrón, se muestran todas las versiones. Por defecto, los paquetes marcados con avoid-version o deprecated no aparecerán a menos que se proporcione --all.
show
Imprime el nombre del switch actual.
invariant
Imprime el invariante del switch activo.
set-invariant PAQUETES
Actualiza el invariante del switch, es decir, la fórmula que el switch debe seguir verificando a lo largo de todas las operaciones. La configuración anterior se anula. Ver también las opciones --force y --no-action. Sin argumentos, se elige un invariante automáticamente.
set-description CADENA
Establece la descripción para el switch seleccionado.
link SWITCH [DIR]
Establece un alias local para un switch dado, de modo que el switch se seleccione automáticamente siempre que esté en ese directorio o en uno descendente.
install SWITCH
Eliminado en la versión 2.1, usa create en su lugar.
set-base PAQUETES
Eliminado en la versión 2.1, usa set-invariant en su lugar.

EJEMPLOS

    opam switch create 4.08.0

Crea un nuevo switch llamado "4.08.0" y lo selecciona, con un compilador seleccionado automáticamente en la versión 4.08.0 (tenga en cuenta que esto puede fallar si hay más de un compilador que coincida con esa versión).

    opam switch create ./ --deps-only

Prepara un switch local para construir los paquetes definidos en ./. Esto escanea el directorio actual en busca de definiciones de paquetes, elige un compilador compatible, crea un switch local e instala las dependencias de los paquetes locales.

    opam switch create trunk --repos default,beta=https://github.com/ocaml/ocaml-beta-repository.git ocaml-variants.4.10.0+trunk

Crea un nuevo switch llamado "trunk", con ocaml-variants.4.10.0+trunk como compilador, con un nuevo repositorio beta enlazado a la URL dada seleccionado además del predeterminado.

OPCIONES

-A COMP, --alias-of=COMP
Eliminado en la versión 2.1.
--all
Solo para list-available: muestra todos los compiladores disponibles, independientemente de si están marcados con avoid-version o deprecated.
--deps-only
Al crear un switch local en un directorio de proyecto (es decir, un directorio que contiene definiciones de paquetes opam), instala las dependencias del proyecto pero no el proyecto en sí. Al importar un switch, no instala los paquetes raíz.
--description=CADENA
Adjunta la descripción dada a un switch al crearlo. Usa el subcomando set-description para modificar la descripción de un switch existente.
--empty
Permite crear un switch vacío, sin invariante.
--force
Solo para set-invariant: fuerza el establecimiento del invariante, omitindo las comprobaciones de consistencia.
--formula=FORMULA
Permite especificar una "fórmula de dependencia" completa, que posiblemente incluya casos de disyunción, como invariante del switch. El formato es el mismo que para expresar dependencias en archivos de definición de paquetes, p. ej., '"foo" {>= "1.1"}'
--freeze
Al exportar, bloquea todas las URLs de VCS a su commit actual, fallando si no se puede recuperar. Esto asegura que una importación restaurará el estado exacto. Implica --full.
--full
Al exportar, incluye los metadatos de todos los paquetes instalados, permitiendo la reimportación incluso si no existen en los repositorios (el valor predeterminado es incluir solo los metadatos de los paquetes fijados).
-n, --no-action
Solo para set-invariant: establece el invariante, pero no lo aplique inmediatamente: espere al próximo comando install, upgrade o similar.
--no-autoinstall
Eliminado en la versión 2.1.
--no-install

--no-switch
No seleccione automáticamente los interruptores recién instalados.
--packages=PACKAGES
Al instalar un interruptor, defina explícitamente el conjunto de paquetes que se aplicarán como invariante del interruptor.
--repositories=REPOS
Al crear un nuevo interruptor, use la selección dada de repositorios en lugar de los predeterminados. REPOS debe ser una lista separada por comas de nombres de repositorios ya registrados (configurados a través de, por ejemplo, opam repository add --dont-select), o enlaces NAME=URL, en cuyo caso NAME no debe estar registrado previamente a una URL diferente, y el nuevo repositorio será registrado. -s, --short
Genere listas sin formato de nombres, uno por línea, omitiendo cualquier detalle.

PACKAGE BUILD OPTIONS

--assume-depexts
Omita el paso de instalación para cualquier paquete del sistema faltante e intente continuar con la compilación de los paquetes opam de todos modos. Si la instalación tiene éxito, opam no volverá a preguntar sobre estos paquetes del sistema. Solo tiene sentido si el manejo de dependencias externas está habilitado.
-b, --keep-build-dir
Mantenga los directorios de compilación después de compilar los paquetes. Esto es equivalente a establecer $OPAMKEEPBUILDDIR en "true".
--build-doc
Eliminado en 2.1, use --with-doc en su lugar.
--build-test
Eliminado en 2.1, use --with-test en su lugar.
-d, --with-doc
Compile la documentación del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Esto es equivalente a establecer $OPAMWITHDOC (o el obsoleto $OPAMBUILDDOC) en "true".
--dry-run
Simule el comando, pero no realice ningún cambio. Esto también se puede establecer con la variable de entorno $OPAMDEBUG.
--fake
Esta opción registra las acciones en la base de datos opam, sin ejecutarlas realmente. ADVERTENCIA: Esta opción es peligrosa y es probable que rompa su entorno opam. Probablemente quiera --dry-run. Usted ha sido advertido.
--ignore-constraints-on[=PACKAGES] (predeterminado=)
Fuerza a opam a ignorar las restricciones de versión en todas las dependencias de los paquetes listados. Esto se puede usar para probar la compatibilidad, pero espere que las compilaciones fallan al usar esto. Tenga en cuenta que la disponibilidad de los paquetes, así como las restricciones de versión en dependencias opcionales y conflictos, no se ven afectadas. Esto es equivalente a establecer $OPAMIGNORECONSTRAINTS.
--inplace-build
Al compilar un paquete cuya fuente está vinculada a un directorio local, procese las acciones de compilación e instalación directamente en ese directorio, en lugar de en una copia limpia manejada por opam. Esto solo afecta a los paquetes que están explícitamente listados en la línea de comandos. Esto es equivalente a establecer $OPAMINPLACEBUILD en "true".
-j JOBS, --jobs=JOBS
Establezca el número máximo de trabajos concurrentes a utilizar. El valor predeterminado se calcula a partir del número de núcleos. También puede establecerlo usando la variable de entorno $OPAMJOBS.
--lock-suffix=SUFFIX (ausente=locked)
Establezca el sufijo de los archivos bloqueados a SUFFIX.
--locked
En comandos que utilizan archivos opam encontrados desde fuentes fijadas, si se encuentra una variante del archivo con una extensión .locked añadida (por ejemplo, foo.opam.locked además de foo.opam), se utilizará esa en su lugar. Esto suele ser útil para ofrecer un conjunto más específico de dependencias y reproducir contextos de compilación similares, de ahí el nombre. La opción lock se puede usar para generar dichos archivos, basándose en las versiones de las dependencias actualmente instaladas en el host. Esto es equivalente a establecer la variable de entorno $OPAMLOCKED. Tenga en cuenta que esta opción generalmente no afecta a los paquetes ya fijados.
-m MAKE, --make=MAKE
Eliminado en 2.1, use opam config set[-global] make MAKE en su lugar.
--no-checksums
No verifique la suma de verificación de los archivos descargados. Esto es equivalente a establecer $OPAMNOCHECKSUMS en "true".
--no-depexts
Deshabilita temporalmente el manejo de dependencias externas. Esto se puede usar si un paquete no está disponible en su gestor de paquetes del sistema, pero usted instaló la dependencia requerida manualmente. Implica --assume-depexts, y también almacena las excepciones en caso de éxito.
--require-checksums
Rechace la instalación de paquetes que no proporcionen una suma de verificación para los archivos de origen. Esto es equivalente a establecer $OPAMREQUIRECHECKSUMS en "true".
--reuse-build-dir
Reutilice los directorios de compilación existentes (mantenidos usando --keep-build-dir), en lugar de compilar desde una copia nueva de la fuente. Esto puede ser más rápido, pero también puede llevar a fallos si los sistemas de compilación de los paquetes no manejan bien las actualizaciones de dependencias. Esto es equivalente a establecer $OPAMREUSEBUILDDIR en "true".
--show-actions
Llame al solucionador y muestre las acciones. No realice ningún cambio. Esto es equivalente a establecer $OPAMSHOW.
--skip-updates
Al ejecutar una instalación, actualización o reinstalación en paquetes fijados desde la fuente, normalmente se actualizan primero desde su origen. Esta bandera deshabilita ese comportamiento y los mantiene en su versión en caché. Esto es equivalente a establecer $OPAMSKIPUPDATE.
-t, --with-test
Compile y ejecute las pruebas unitarias del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Esto es equivalente a establecer $OPAMWITHTEST (o el obsoleto $OPAMBUILDTEST) en "true".
--unlock-base
Eliminado en 2.1, use --update-invariant en su lugar.
--update-invariant
Permita cambios en los paquetes que se establecen como base del interruptor (típicamente, el compilador principal). Úselo con precaución. Esto es equivalente a establecer la variable de entorno $OPAMUNLOCKBASE
--verbose-on=PACKAGES
Sea más verboso en paquetes específicos. Esto es equivalente a establecer $OPAMVERBOSE.
--with-dev-setup
Incluya dependencias de herramientas de desarrollo solamente.

COMMON OPTIONS

Estas opciones son comunes a todos los comandos.

--best-effort
No falle si no se pueden instalar todos los paquetes solicitados: intente instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (ausente=2.4)
Utilice la sintaxis y semántica de la interfaz de línea de comandos de MAJOR.MINOR. Está pensado para cualquier uso persistente de opam (scripts, publicaciones de blog, etc.), cualquier versión de opam de la misma serie MAJOR se comportará como para la versión MINOR especificada. El flag no estaba disponible en opam 2.0, por lo que para seleccionar la interfaz de línea de comandos 2.0, establezca la variable de entorno OPAMCLI en 2.0 en lugar de usar este parámetro.
--color=WHEN
Coloree la salida. WHEN debe ser uno de always, never o auto.
--confirm-level=LEVEL
Nivel de confirmación, LEVEL debe ser uno de ask, no, yes o unsafe-yes. Se puede especificar varias veces. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL`.
--criteria=CRITERIA
Especifique preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje compatible y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Una guía general para usar preferencias de solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=FILENAME
Opción de depuración: Guarde las solicitudes CUDF enviadas al solucionador en FILENAME-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprima mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG en "true".
--debug-level=LEVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprima la versión git de opam, si está establecida (es decir, si está utilizando una versión de desarrollo), y salga.
--help[=FMT] (predeterminado=auto)
Muestre esta ayuda en el formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain cuando la variable TERM es dumb o indefinida.
--ignore-pin-depends
Ignore los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=FILENAME
Guarde los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%`, se reemplazará por un índice que no sobrescribirá un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responda no a todas las preguntas de sí/no de opam sin preguntar. Vea también --confirm-level. Esto es equivalente a establecer $OPAMNO en "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio que está escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato anterior. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Usa ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegúrate de que nada se actualizará o reescribirá automáticamente. Útil para llamarlo desde scripts de autocompletado, por ejemplo. Fallará siempre que se necesite una operación de este tipo; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el solucionador CUDF a utilizar para resolver problemas de instalación de paquetes. Este puede ser un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentre un error en una definición de paquete o un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.
--switch=SWITCH
Usa SWITCH como el switch del compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier solucionador externo y usa el interno (esto requiere que opam se haya compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más verboso. Un -v muestra todos los comandos de los paquetes, repite para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.). Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra información de la versión.
-w, --working-dir
Cuando se actualizan paquetes asociados a un directorio local controlado por versión, actualiza al estado actual de su código fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio de código fuente se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

ENTORNO

Opam utiliza las variables de entorno que se enumeran aquí. Las variables booleanas deben establecerse a "0", "no", "false" o la cadena vacía para deshabilitar, "1", "sí" o "true" para habilitar.

OPAMALLPARENS rodea todos los filtros con paréntesis.

OPAMASSUMEDEPEXTS ver la opción `--assume-depexts'.

OPAMAUTOREMOVE ver la opción de eliminación `--auto-remove'.

OPAMBESTEFFORT ver la opción `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA establece la cadena que debe anteponerse a los criterios cuando se establece la opción `--best-effort', y se espera que maximice la propiedad `opam-query' en la solución.

OPAMBUILDDOC Eliminado en 2.1.

OPAMBUILDTEST Eliminado en 2.1.

OPAMCLI ver la opción `--cli'.

OPAMCOLOR cuando se establece a always o never, establece un valor predeterminado para la opción `--color'.

OPAMCONFIRMLEVEL ver la opción `--confirm-level`. OPAMCONFIRMLEVEL tiene prioridad sobre OPAMYES y OPAMNO.

OPAMCRITERIA especifica las preferencias del usuario para la resolución de dependencias. El valor predeterminado depende de la versión del solucionador, usa `config report' para conocer la configuración actual. Ver también la opción --criteria.

OPAMCUDFFILE guarda el grafo cudf en file-actions-explicit.dot.

OPAMCUDFTRIM controla el filtrado de paquetes no relacionados durante el preprocesamiento de CUDF.

OPAMCURL se puede usar para seleccionar un programa 'curl' dado. Ver OPAMFETCH para más opciones.

OPAMDEBUG ver las opciones `--debug' y `--debug-level'.

OPAMDEBUGSECTIONS si se establece, limita los mensajes de depuración a la lista de secciones separadas por espacios. Las secciones pueden tener opcionalmente un nivel de depuración específico (por ejemplo, CLIENT:2 o CLIENT CUDF:2), pero de lo contrario usan `--debug-level'.

OPAMDIGDEPTH define qué tan agresiva es la búsqueda de conflictos durante el preprocesamiento de CUDF.

OPAMDOWNLOADJOBS establece el número máximo de descargas simultáneas.

OPAMDROPWORKINGDIR anula los paquetes actualizados previamente con --working-dir en la actualización. Sin esta variable establecida, opam los mantendría sin cambios a menos que se nombren explícitamente en la línea de comandos.

OPAMDRYRUN ver la opción `--dry-run'.

OPAMEDITOR establece el editor a usar para editar archivos opam, anula $EDITOR y $VISUAL.

OPAMERRLOGLEN establece el número de líneas de registro impresas cuando falla un subproceso. 0 para imprimir todas.

OPAMEXTERNALSOLVER ver la opción `--solver'.

OPAMFAKE ver la opción `--fake'.

OPAMFETCH especifica cómo descargar archivos: `wget', `curl' o un comando personalizado donde las variables %{url}%, %{out}%, %{retry}%, %{compress}% y %{checksum}% serán reemplazadas. Anula el valor de 'download-command' del archivo de configuración principal.

OPAMFIXUPCRITERIA igual que OPAMUPGRADECRITERIA, pero específico para corrección y reinstalación.

OPAMIGNORECONSTRAINTS ver la opción de instalación `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS ver la opción `--ignore-pin-depends'.

OPAMINPLACEBUILD ver la opción `--inplace-build'.

OPAMJOBS establece el número máximo de trabajadores paralelos a ejecutar.

OPAMJSON registra la salida JSON en el archivo dado (usa el carácter `%' para indexar los archivos).

OPAMKEEPBUILDDIR ver la opción de instalación `--keep-build-dir'.

OPAMKEEPLOGS indica a opam que no elimine algunos registros de comandos temporales y algunas copias de seguridad. Esto omite algunos finalizadores y también puede ayudar a obtener rastreos de error más fiables.

OPAMLOCKED combinación de las opciones `--locked' y `--lock-suffix'.

OPAMLOGS logdir establece el directorio de registros, el valor predeterminado es un directorio temporal en /tmp

OPAMMAKECMD establece el comando make del sistema a utilizar.

OPAMMERGEOUT fusiona las salidas de los procesos, stderr en stdout.

OPAMNO responde no a cualquier pregunta formulada, ver las opciones `--no` y `--confirm-level`. OPAMNO se ignora si OPAMCONFIRMLEVEL o OPAMYES está establecido.

OPAMNOAGGREGATE con `opam admin check', no agrupar paquetes.

OPAMNOASPCUD Obsoleto.

OPAMNOAUTOUPGRADE deshabilita la actualización interna automática de repositorios en un formato anterior al actual, en 'update' o 'init'.

OPAMNOCHECKSUMS habilita la opción --no-checksums cuando está disponible.

OPAMNODEPEXTS deshabilita el manejo de dependencias del sistema, ver la opción `--no-depexts'.

OPAMNOENVNOTICE Interno.

OPAMNOSELFUPGRADE ver la opción `--no-self-upgrade'

OPAMPINKINDAUTO establece si los sistemas de control de versiones deben detectarse al fijar a una ruta local. Habilitado por defecto desde 1.3.0.

OPAMPRECISETRACKING seguimiento detallado de directorios.

OPAMPREPRO establece esto a falso para deshabilitar el preprocesamiento de CUDF. Menos eficiente, pero podría ayudar a depurar problemas del solucionador.

OPAMREPOSITORYTARRING almacena internamente los repositorios como archivos tar.gz. Esto puede ser mucho más rápido en sistemas de archivos que no manejan bien el escaneo de árboles grandes pero que tienen una buena caché en /tmp. Sin embargo, es más lento en el caso general.

OPAMREQUIRECHECKSUMS Habilita la opción `--require-checksums' cuando está disponible (por ejemplo, para `opam install').

OPAMRETRIES establece el número de intentos antes de fallar las descargas.

OPAMREUSEBUILDDIR ver la opción `--reuse-build-dir'.

OPAMROOT ver la opción `--root'. Esto se establece automáticamente con `opam env --root=DIR --set-root'.

OPAMROOTISOK no te quejes al ejecutar como root.

OPAMSAFE ver la opción `--safe'.

OPAMSHOW ver la opción `--show'.

OPAMSKIPUPDATE ver la opción `--skip-updates'.

OPAMSKIPVERSIONCHECKS omite algunas verificaciones de versión. Peligroso, solo para pruebas de compatibilidad.

OPAMSOLVERALLOWSUBOPTIMAL (predeterminado `true') permite que algunos solucionadores devuelvan una solución cuando alcanzan el tiempo de espera; si bien la solución sigue estando garantizada como consistente, no hay garantía en este caso de que cumpla con los criterios de optimización esperados. Si es `true', opam continuará con una advertencia, si es `false' un tiempo de espera es un error. Actualmente solo el backend builtin-z3 maneja este caso degradado.

OPAMSOLVERTIMEOUT cambia el tiempo permitido para el solucionador. El valor predeterminado es 60.0, establecido a 0 para ilimitado. Tenga en cuenta que es posible que no todos los solucionadores admitan esta opción.

OPAMSOLVERTOLERANCE cambia la tolerancia hacia el solucionador que elige una solución no optimizada (es decir, puede extraer paquetes obsoletos). Los valores típicos varían de 0.0 (la mejor solución conocida por el solucionador) a 1.0 (solución no optimizada). El valor predeterminado es 0.0. Esta opción es útil en caso de que el solucionador no pueda encontrar una solución en un tiempo razonable (ver $OPAMSOLVERTIMEOUT). Tenga en cuenta que es posible que no todos los solucionadores admitan esta opción.

OPAMSTATS Eliminado en 2.4.

OPAMSTATUSLINE muestra una línea de estado dinámica que indica lo que está sucediendo actualmente en la terminal. (una de always, never o auto)

OPAMSTRICT falla ante inconsistencias (lectura de archivos, importación de switches, etc.).

OPAMSWITCH ver la opción `--switch'. Se establece automáticamente con `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE ver la opción de instalación `--unlock-base'.

OPAMUPGRADECRITERIA especifica las preferencias del usuario para la resolución de dependencias al realizar una actualización. Anula OPAMCRITERIA en las actualizaciones si ambas están establecidas. Ver también la opción --criteria.

OPAMUSEINTERNALSOLVER ver la opción `--use-internal-solver'.

OPAMUSEOPENSSL Eliminado en 2.2.

OPAMUTF8 usa caracteres UTF8 en la salida (uno de always, never o auto). Por defecto `auto', que se determina de la configuración regional).

OPAMUTF8MSGS usa opam(1) — Arch Linux man pages

ENVIRONMENT

opam consults the following environment variables:

OPAMABS_ROOT Deprecated. Use OPAMROOT instead.

OPAMCOLOR auto, always or never. Override the detection of terminal color support.

OPAMCONFIRMLEVEL 0, 1, or 2. Default is 0. Affects how many questions opam asks for confirmation during operations. Level 1 confirms only destructive operations, level 2 confirms everything that is not automated with OPAMYES.

OPAMDEBUG true or false. Enables debug messages. Implies OPAMUTF8.

OPAMDEVMODE true or false. If true, opam will not try to install sources for packages from the repositories. Instead, it will try to use the sources already present in the build directory or will fail. For development, consider using opam user-build.

OPAMDOWNLOADCMD a command template for downloading files. See option --download-cmd for details.

OPAMDOWNLOADDIR the directory where downloads are stored. See option --download-dir for details.

OPAMEDITCMD a command template for editing files. See option --edit-cmd for details.

OPAMEXT_OPAM_ROOT if set, this is prepended to OPAMROOT. This can be useful for testing.

OPAMGLOBALCONFIGDIR the directory containing opam's global configuration files. Defaults to ~/.config/opam.

OPAMHOOK_PRE_CHANGESET if set, runs the command on updates before any changes are applied.

OPAMHOOK_POST_CHANGESET if set, runs the command on updates after any changes are applied.

OPAMHOOK_PRE_UPDATE if set, runs the command before fetching repository updates.

OPAMHOOK_POST_UPDATE if set, runs the command after fetching repository updates.

OPAMHOOK_PRE_INSTALL if set, runs the command before installing packages.

OPAMHOOK_POST_INSTALL if set, runs the command after installing packages.

OPAMHOOK_PRE_REMOVE if set, runs the command before removing packages.

OPAMHOOK_POST_REMOVE if set, runs the command after removing packages.

OPAMKEEPBUILDDIR true or false. If true, opam will not remove build directories after a successful build.

OPAMLOCKCMD a command template for locking files. See option --lock-cmd for details.

OPAMKEEPWINEDLL true or false. If true, opam will not remove Windows DLLs from the build directory after compilation.

OPAMLOCALTRACK true or false. If true, opam will automatically track local packages that are installed using `opam install .`. This is enabled by default for new configurations.

OPAMNO true or false. If true, opam will not ask for confirmation for any operation. This is equivalent to --yes.

OPAMNO_ANALYZE_OPTS true or false. If true, opam will not try to optimize the solver options, which might speed up solver runs on large configurations.

OPAMNO_PROMPT true or false. If true, opam will not prompt for user input (e.g. for confirmations).

OPAMNO_REPOSITORIES true or false. If true, opam will not automatically update repositories when needed.

OPAMONLY_DOWNLOAD true or false. If true, opam will only download packages, not install them.

OPAMONLY_INSTALL true or false. If true, opam will only install packages, not download them.

OPAMONLY_UPGRADE true or false. If true, opam will only upgrade packages, not install or remove them.

OPAMONLY_SOLVE true or false. If true, opam will only run the solver, not perform any installations or removals.

OPAMOPTIONS a string containing space-separated options to be passed to the solver. For example: OPAMOPTIONS='--version-sort=rev'

OPAMOUT a file where all output will be redirected. Useful for debugging.

OPAMPARALLEL_INSTALL true or false. Default is true. Allows opam to install multiple packages in parallel.

OPAMPRETTY_MESSAGES true or false. Default is auto. Tries to detect if the terminal supports UTF-8 characters (camels) in opam messages. Implies OPAMUTF8. This is set by default on macOS only.

OPAMROOT the directory containing opam's root installation. Defaults to ~/.opam.

OPAMSCRIPTCMD a command template for running scripts. See option --script-cmd for details.

OPAMSIMPLE_OUTPUT true or false. If true, opam will use a simpler output format, suitable for scripting.

OPAMSOLVER a command template for the solver. See option --solver for details.

OPAMSOLVER_PRESOLVER a command template for the presolver. See option --solver-presolver for details.

OPAMSOLVER_TIMEOUT the maximum time in seconds for the solver to run. Defaults to 120 seconds.

OPAMSYSROOT path to use as the system root. Only useful for cross-compilation setups.

OPAMTERMSPECIALCHARS true or false. If true, opam will try to use special characters (like arrows) in its output. This is enabled by default if OPAMUTF8 is enabled.

OPAMTESTDIR the directory where test results are stored. Defaults to ~/.opam/test-results.

OPAMTRACE true or false. If true, opam will print all commands it executes.

OPAMUTF8 true or false. If true, opam will use UTF-8 characters in its output. This is enabled by default on systems that support UTF-8.

OPAMVALIDATIONHOOK if set, uses the `%{hook%}' command to validate an opam repository update.

OPAMVERBOSE see option --verbose.

OPAMVERBOSEON see option --verbose-on

OPAMVERSIONLAGPOWER do not use.

OPAMWITHDEVSETUP see install option --with-dev-setup.

OPAMWITHDOC see install option --with-doc.

OPAMWITHTEST see install option --with-test.

OPAMWORKINGDIR see option --working-dir.

OPAMYES see options --yes and --confirm-level. OPAMYES has priority over OPAMNO and is ignored if OPAMCONFIRMLEVEL is set.

OPAMVAR_var overrides the contents of the variable var when substituting `%{var}%` strings in `opam` files.

OPAMVAR_package_var overrides the contents of the variable package:var when substituting `%{package:var}%` strings in `opam` files.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
