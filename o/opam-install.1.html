OPAM-INSTALL(1) Manual de Opam OPAM-INSTALL(1)

NOMBRE

opam-install - Instala una lista de paquetes.

SINOPSIS

opam install [OPCIÓN]… [PAQUETES]…

DESCRIPCIÓN

Este comando instala uno o más paquetes dentro del switch actualmente seleccionado (ver opam switch). Una vez instalados, puedes eliminar paquetes con opam remove, actualizarlos con opam upgrade y listarlos con opam list. Ver también opam pin para gestionar versiones de paquetes, redirigir paquetes existentes o añadir paquetes que no estén definidos en los repositorios.

Todas las dependencias requeridas de los paquetes seleccionados se instalarán primero. Cualquier paquete ya instalado que tenga dependencias, o dependencias opcionales con los paquetes modificados, se recompilará. La solución propuesta también puede implicar la eliminación de paquetes incompatibles o conflictivos.

Si se proporcionan rutas como argumento en lugar de paquetes, se asume que apuntan a directorios de origen de proyectos que contienen una o más definiciones de paquetes (archivos opam), o directamente a archivos opam. Entonces, los paquetes correspondientes se fijarán a su directorio local y se instalarán (a menos que se especificara --deps-only).

ARGUMENTOS

PAQUETES
Lista de nombres de paquetes, con una versión opcional o restricción, p. ej., `pkg', `pkg.1.0' o `pkg>=0.5'; o nombres de archivos o directorios que contienen la descripción del paquete, con directorio explícito (p. ej., `./foo.opam' o `.')

OPCIONES

--assume-built
Para uso en paquetes fijados localmente: asume que ya se han compilado correctamente, y solo ejecuta sus instrucciones de instalación, directamente desde su directorio de origen. Esto omite las instrucciones de compilación y puede ser útil para instalar paquetes en los que se está trabajando. Implica --inplace-build. No se omitirán paquetes fijados localmente.
--check
Sale con 0 si todas las dependencias de PAQUETES ya están instaladas. Si no, muestra los nombres de las dependencias faltantes en stdout y sale con 1.
--depext-only
Resuelve la instalación del paquete normalmente, pero solo instala las dependencias del sistema requeridas, sin afectar el estado del switch opam o instalar paquetes opam.
--deps-only
Instala todas sus dependencias, pero no instala realmente el paquete.
--destdir=DIR
Copia los archivos instalados por el paquete dado dentro del switch opam actual debajo del prefijo DIR, respetando su jerarquía, después de la instalación. Precaución: llamar a esto puede sobrescribir, pero nunca eliminar archivos, incluso si fueron instalados por un uso anterior de --destdir, p. ej., en una versión anterior del mismo paquete. Ver opam remove --destdir para revertir.
--download-only
Descarga las fuentes de los paquetes, pero no compila ni instala nada.
--formula=FORMULA (ausente=[])
Experimental. Especifica una fórmula de dependencia que será verificada por la solución, además del invariante del switch. El formato es el mismo que para expresar dependencias en archivos de definición de paquetes, p. ej., '"foo" {>= "1.1"}'
--ignore-conflicts
Usado con --deps-only, ignora los conflictos del paquete dado.
--recursive
Permite búsquedas recursivas de archivos *.opam. Cf. también --subpath.
--restore
Intenta restaurar paquetes que fueron marcados para instalación pero han sido eliminados debido a errores.
--set-root
Marca los paquetes dados como raíces instaladas. Este es el valor predeterminado para paquetes recién instalados manualmente.
--subpath=PATH
Los archivos *.opam se recuperan del subdirectorio dado en lugar del directorio principal. Las fuentes se toman entonces del subdirectorio objetivo, internamente solo este subdirectorio se copia/descarga. Se puede combinar con --recursive para tener una búsqueda recursiva en el subdirectorio.
--unset-root
Marca los paquetes dados como "instalados automáticamente".

OPCIONES DE COMPILACIÓN DE PAQUETES

--assume-depexts
Omite el paso de instalación para cualquier paquete del sistema faltante e intenta continuar con la compilación de los paquetes opam de todos modos. Si la instalación tiene éxito, opam no volverá a preguntar sobre estos paquetes del sistema. Solo tiene sentido si el manejo de dependencias externas está habilitado.
-b, --keep-build-dir
Conserva los directorios de compilación después de compilar los paquetes. Esto es equivalente a establecer $OPAMKEEPBUILDDIR a "true".
--build-doc
Eliminado en 2.1, usar --with-doc en su lugar.
--build-test
Eliminado en 2.1, usar --with-test en su lugar.
-d, --with-doc
Compila la documentación del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Esto es equivalente a establecer $OPAMWITHDOC (o el obsoleto $OPAMBUILDDOC) a "true".
--dry-run
Simula el comando, pero no realiza ninguna acción real. Esto también se puede establecer con la variable de entorno $OPAMDEBUG.
--fake
Esta opción registra las acciones en la base de datos de opam, sin realizarlas realmente. ADVERTENCIA: Esta opción es peligrosa y es probable que rompa tu entorno opam. Probablemente quieras --dry-run. Se te ha advertido.
--ignore-constraints-on[=PAQUETES] (predeterminado=)
Fuerza a opam a ignorar las restricciones de versión en todas las dependencias de los paquetes listados. Esto se puede usar para probar la compatibilidad, pero se espera que las compilaciones fallen al usar esto. Tenga en cuenta que la disponibilidad de los paquetes, así como las restricciones de versión en dependencias opcionales y conflictos, no se ven afectadas. Esto es equivalente a establecer $OPAMIGNORECONSTRAINTS.
--inplace-build
Al compilar un paquete cuya fuente está vinculada a un directorio local, procesa las acciones de compilación e instalación directamente en ese directorio, en lugar de una copia limpia manejada por opam. Esto solo afecta a los paquetes que se listan explícitamente en la línea de comandos. Esto es equivalente a establecer $OPAMINPLACEBUILD a "true".
-j JOBS, --jobs=JOBS
Establece el número máximo de trabajos concurrentes a utilizar. El valor predeterminado se calcula a partir del número de núcleos. También puedes establecerlo usando la variable de entorno $OPAMJOBS.
--lock-suffix=SUFFIX (ausente=locked)
Establece el sufijo de los archivos de bloqueo a SUFFIX.
--locked
En comandos que utilizan archivos opam encontrados en fuentes fijadas, si se encuentra una variante del archivo con una extensión .locked añadida (por ejemplo, foo.opam.locked además de foo.opam), se usará esa en su lugar. Esto es típicamente útil para ofrecer un conjunto de dependencias más específico y reproducir contextos de compilación similares, de ahí el nombre. La opción lock se puede utilizar para generar dichos archivos, basándose en las versiones de las dependencias actualmente instaladas en el host. Esto es equivalente a establecer la variable de entorno $OPAMLOCKED. Tenga en cuenta que esta opción generalmente no afecta a los paquetes ya fijados.
-m MAKE, --make=MAKE
Eliminado en 2.1, usar opam config set[-global] make MAKE en su lugar.
--no-checksums
No verificar la suma de control de los archivos descargados. Esto es equivalente a establecer $OPAMNOCHECKSUMS a "true".
--no-depexts
Deshabilita temporalmente el manejo de dependencias externas. Esto se puede usar si un paquete no está disponible en el gestor de paquetes de tu sistema, pero has instalado la dependencia requerida manualmente. Implica --assume-depexts, y también almacena las excepciones en caso de éxito.
--require-checksums
Rechaza la instalación de paquetes que no proporcionan una suma de control para los archivos originales. Esto es equivalente a establecer $OPAMREQUIRECHECKSUMS a "true".
--reuse-build-dir
Reutiliza los directorios de compilación existentes (conservados usando --keep-build-dir), en lugar de compilar desde una copia nueva de las fuentes. --show-actions
Llama al resolvedor y muestra las acciones. No realiza ningún cambio. Esto es equivalente a establecer $OPAMSHOW.
--skip-updates
Al ejecutar una instalación, actualización o reinstalación en paquetes fijados desde el código fuente, normalmente se actualizan primero desde su origen. Esta opción deshabilita ese comportamiento y los mantiene a su versión en caché. Esto es equivalente a establecer $OPAMSKIPUPDATE.
-t, --with-test
Compila y ejecuta las pruebas unitarias del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Esto es equivalente a establecer $OPAMWITHTEST (o el obsoleto $OPAMBUILDTEST) a "true".

Permite cambios en el conjunto de paquetes base del switch (típicamente, el compilador principal). Úsalo con precaución. Esto es equivalente a establecer la variable de entorno $OPAMUNLOCKBASE.
--verbose-on=PAQUETES

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No falles si no se pueden instalar todos los paquetes solicitados: intenta instalar tantos como sea posible. Ten en cuenta que no todos los resolvedores externos pueden soportar esta opción (versiones recientes de aspcud o mccs deberían hacerlo). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Usa la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Destinado a cualquier uso persistente de opam (scripts, publicaciones de blog, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. La opción no estaba disponible en opam 2.0, por lo que para seleccionar la CLI de 2.0, establece la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o sí-inseguro. Puede especificarse más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especifica preferencias del usuario para la resolución de dependencias para esta ejecución. Sobrescribe $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para detalles sobre el lenguaje soportado y los resolvedores externos disponibles, consulta http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre el uso de preferencias del resolvedor se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBRE_ARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al resolvedor en NOMBRE_ARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al resolvedor durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece a 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está configurada (es decir, si estás usando una versión de desarrollo), y sale.
--help[=FMT] (predeterminado=auto)
Muestra esta ayuda en formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain cuando la variable de entorno TERM es dumb o indefinida.
--ignore-pin-depends
Ignora las dependencias adicionales requeridas por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBRE_ARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por máquina. Si el nombre del archivo contiene el carácter `%', se reemplazará por un índice que no sobrescribe un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en la versión 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Ten en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=RAÍZ
Usa RAÍZ como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a RAÍZ.
--safe, --readonly
Asegúrate de que nada se actualice o reescriba automáticamente. Útil para llamar desde scripts de finalización, por ejemplo. Fallará siempre que sea necesaria dicha operación; también evita esperar por bloqueos, omite preguntas interactivas y sobrescribe la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el resolvedor CUDF a usar para resolver problemas de instalación de paquetes. Puede ser un resolvedor predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falla siempre que se encuentre un error en la definición de un paquete o un archivo de configuración. El valor predeterminado es continuar silenciosamente si es posible.
--switch=SWITCH
Usa SWITCH como el switch de compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier resolvedor externo y usa el interno (esto requiere que opam haya sido compilado con un resolvedor interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más verboso. Un -v muestra todos los comandos de paquetes, repite para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.). Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra información de la versión.
-w, --working-dir
Siempre que se actualicen paquetes vinculados a un directorio local controlado por versión, actualiza al estado de trabajo actual de su código fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio de código fuente se copia tal cual, si no está limpio puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede configurar con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
