NOMBRE

osm2pgsql-replication - actualizador de base de datos de osm2pgsql

SINOPSIS

osm2pgsql-replication {init,update,status} ...

DESCRIPCIÓN

Actualiza una base de datos de osm2pgsql con cambios de un servidor de replicación de OSM.

Esta herramienta inicializa el proceso de actualización observando el archivo de importación
o el objeto más reciente en la base de datos. El estado se guarda luego en una tabla
en la base de datos. Las ejecuciones posteriores descargan los datos disponibles recientemente y los aplican
a la base de datos.

Consulte la ayuda del comando ’init’ y ’update’ para más información sobre
cómo usar osm2pgsql-replication.

OPCIONES

Subcomandos

osm2pgsql-replication init

Inicializa el proceso de replicación.
osm2pgsql-replication update

Descarga los datos disponibles recientemente y los aplica a la base de datos.
osm2pgsql-replication status

Imprime información sobre el estado actual de replicación, opcionalmente en formato JSON.

OPCIONES 'osm2pgsql-replication init'

uso: osm2pgsql-replication init [-h] [-q] [-v] [-d DB] [-U NOMBRE]
[-H HOST] [-P PUERTO] [-p PREFIJO]
[--middle-schema SCHEMA] [--schema SCHEMA]
[--osm-file ARCHIVO | --server URL]
[--start-at TIEMPO]

Inicializa el proceso de replicación.

Esta función establece el servicio de replicación a utilizar y determina desde
qué fecha aplicar las actualizaciones. Debe llamar a esta función al menos una vez
para configurar el proceso de replicación. Puede llamarse de nuevo más tarde
sin problemas para cambiar los servidores de replicación o para retroceder el proceso de actualización y
volver a aplicar las actualizaciones.

Hay diferentes métodos disponibles para la inicialización. Cuando no se dan parámetros adicionales,
los datos se inicializan desde los datos en la base de datos. Si los datos se importaron de un archivo con información de replicación
y la tabla de propiedades está disponible (para osm2pgsql >= 1.9), entonces se usa la replicación del archivo. De lo contrario,
el servicio de actualización minuciosa de openstreetmap.org se usa como servicio de replicación predeterminado. La fecha de inicio se toma
de la marca de tiempo de la base de datos (para osm2pgsql >= 1.9) o se determina a partir de la forma más reciente en la base de datos
consultando la API de OSM sobre su fecha de creación.

El servicio de replicación se puede cambiar con el parámetro ’--server’.
Para usar una fecha de inicio diferente, añada ’--start-at’ con una marca de tiempo ISO absoluta (por ejemplo, 2007-08-20T12:21:53Z). Cuando el programa determina la
fecha de inicio a partir de la marca de tiempo de la base de datos o la fecha de creación de la forma, resta
otros 3 horas por defecto para asegurar que todos los cambios nuevos estén disponibles. Para cambiar este período de retroceso, use ’--start-at’ con el
número de minutos de retroceso. Este modo de retroceso también se puede usar para forzar la inicialización para usar la fecha de la base de datos e ignorar la fecha
de la información de replicación en el archivo.

El proceso de inicialización también puede usar información de replicación de
un archivo OSM directamente e ignorar toda la otra información de fecha.
Use el comando ’osm2pgsql-replication --osm-file <nombre_archivo>’ para esto.

-q, --quiet
Imprime solo mensajes de error
-v, --verbose
Aumenta la verbosidad de la salida
-d DB, --database DB
Nombre de la base de datos PostgreSQL a la que conectarse o cadena de información de conexión
-U NOMBRE, --username NOMBRE
Nombre de usuario de PostgreSQL
-H HOST, --host HOST
Nombre del host del servidor de base de datos o ubicación del socket
-P PUERTO, --port PUERTO
Puerto del servidor de base de datos
-p PREFIJO, --prefix PREFIJO
Prefijo para los nombres de tabla (por defecto 'planet_osm')
--middle-schema SCHEMA
Nombre del esquema para almacenar la tabla del estado de replicación
--schema SCHEMA
Nombre del esquema para la base de datos
--osm-file ARCHIVO
Obtener información de replicación del archivo dado.
--server URL
Usar el servidor de replicación en la URL dada
--start-at TIEMPO
Hora a la que iniciar la replicación. Si se da una marca de tiempo absoluta (en formato ISO), se usará. Si se da un número, la replicación comenzará el número de minutos antes de la fecha conocida de la base de datos.

OPCIONES 'osm2pgsql-replication update'

uso: osm2pgsql-replication update update [opciones] [-- param [param ...]]

Descarga los datos disponibles recientemente y los aplica a la base de datos.

Los datos se descargan en fragmentos de ’--max-diff-size’ MB. Cada fragmento se
guarda en un archivo temporal y se importa con osm2pgsql desde allí. El
archivo temporal normalmente se elimina después, a menos que especifique una ubicación explícita con
’--diff-file’. Una vez que la base de datos está actualizada con la
fuente de replicación, el proceso de actualización sale con 0.

Cualquier argumento adicional para osm2pgsql debe proporcionarse después de ’--’. La base de
datos y el parámetro de prefijo se pasan a osm2pgsql. No necesitan repetirse. ’--append’ y ’--slim’ siempre se añadirán también.

Use el parámetro ’--post-processing’ para ejecutar un script después de que osm2pgsql se
haya ejecutado correctamente. Si las actualizaciones consisten en múltiples ejecuciones debido a que se alcanzó el
tamaño máximo de datos descargados, el script se ejecuta cada vez que osm2pgsql ha ejecutado. Si el post-procesamiento falla, entonces
toda la ejecución de actualización se considera un fallo y la información de replicación no se actualiza. Eso significa que cuando se ejecuta
'update' la próxima vez, se reanudará descargando los diffs nuevamente y volviéndolos a aplicar a la base de datos. Esto es generalmente seguro. El script
recibe dos parámetros: el ID de secuencia y la marca de tiempo de la última ejecución exitosa. La marca de tiempo
puede faltar en el raro caso de que el servicio de replicación deje de responder después de que se hayan descargado las actualizaciones.

param
Parámetros adicionales para pasar a osm2pgsql.
--diff-file ARCHIVO
Archivo para guardar cambios antes de que se apliquen a osm2pgsql.
--max-diff-size MAX_DIFF_SIZE
Tamaño máximo de datos a cargar en MB (por defecto: 500MB)
--osm2pgsql-cmd OSM2PGSQL_CMD
Ruta al comando osm2pgsql
--once
Ejecuta las actualizaciones solo una vez, incluso si hay más datos disponibles.
--post-processing SCRIPT
Script de post-procesamiento para ejecutar después de cada ejecución de osm2pgsql.
-q, --quiet
Imprime solo mensajes de error
-v, --verbose
Aumenta la verbosidad

NAME

osm2pgsql-replication - Replication handling for osm2pgsql

SYNOPSIS

osm2pgsql-replication [COMMAND] [OPTIONS]

DESCRIPTION

This command provides utilities for managing replication state in a PostgreSQL database.

OPTIONS

These options apply to all subcommands:

-h, --help
Show help message and exit.
-q, --quiet
Only print error messages.
-v, --verbose
Increase verboseness of output.
-d DB, --database DB
Name of PostgreSQL database to connect to or conninfo string.
-U NAME, --username NAME
PostgreSQL user name.
-H HOST, --host HOST
Database server host name or socket location.
-P PORT, --port PORT
Database server port.
-p PREFIX, --prefix PREFIX
Prefix for table names (default 'planet_osm').
--middle-schema SCHEMA
Name of the schema to store the table for the replication state in.
--schema SCHEMA
Name of the schema for the database.

OPTIONS 'osm2pgsql-replication status'

usage: osm2pgsql-replication status [-h] [-q] [-v] [-d DB] [-U NAME] [-H HOST]
[-P PORT] [-p PREFIX]
[--middle-schema SCHEMA] [--schema SCHEMA]
[--json]

Print information about the current replication status, optionally as JSON.

Sample output:


2021-08-17 15:20:28 [INFO]: Using replication service 'https://planet.openstreetmap.org/replication/minute', which is at sequence 4675115 ( 2021-08-17T13:19:43Z )
2021-08-17 15:20:28 [INFO]: Replication server's most recent data is <1 minute old
2021-08-17 15:20:28 [INFO]: Local database is 8288 sequences behind the server, i.e. 5 day(s) 20 hour(s) 58 minute(s)
2021-08-17 15:20:28 [INFO]: Local database's most recent data is 5 day(s) 20 hour(s) 59 minute(s) old

With the ’--json’ option, the status is printed as a json object.


{
"server": {
"base_url": "https://planet.openstreetmap.org/replication/minute",
"sequence": 4675116,
"timestamp": "2021-08-17T13:20:43Z",
"age_sec": 27
},
"local": {
"sequence": 4666827,
"timestamp": "2021-08-11T16:21:09Z",
"age_sec": 507601
},
"status": 0
}

’status’ is 0 if there were no problems getting the status. 1 & 2 for
improperly set up replication. 3 for network issues. If status ≠ 0, then
the ’error’ key is an error message (as string). ’status’ is used as the
exit code.

’server’ is the replication server's current status. ’sequence’ is it's
sequence number, ’timestamp’ the time of that, and 'age_sec' the age of the
data in seconds.

’local’ is the status of your server.

Output status as json.
