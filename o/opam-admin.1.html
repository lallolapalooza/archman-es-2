OPAM ADMIN(1) Opam admin Manual OPAM ADMIN(1)

NOMBRE

opam admin - Herramientas para administradores de repositorios

SINOPSIS

opam admin [COMANDO] …

DESCRIPCIÓN

Este comando puede realizar varias acciones en repositorios en formato opam. Se espera que se ejecute desde la raíz de un repositorio, es decir, un directorio que contenga un archivo 'repo' y un subdirectorio 'packages/' que albergue las definiciones de paquetes dentro de subdirectorios. Un subdirectorio 'compilers/' (formato de repositorio opam versión < 2) también será utilizado por el subcomando upgrade-format.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No fallar si no se pueden instalar todos los paquetes solicitados: intentar instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden soportar esta opción (versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAJOR.MINOR (ausente=2.4)
Utiliza la sintaxis y semántica de la interfaz de línea de comandos de MAJOR.MINOR. Previsto para cualquier uso persistente de opam (scripts, publicaciones de blogs, etc.), cualquier versión de opam en la misma serie MAJOR se comportará como para la versión MINOR especificada. La bandera no estaba disponible en opam 2.0, por lo que para seleccionar la interfaz de línea de comandos 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de siempre, nunca o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de preguntar, no, sí o unsafe-yes. Se puede especificar más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor de la última --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especifica preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje soportado y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre el uso de preferencias del solucionador se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBRE_ARCHIVO
Opción de depuración: Guarda las solicitudes CUDF enviadas al solucionador en NOMBRE_ARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprime mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprime la versión git de opam, si está establecida (es decir, si estás usando una versión de desarrollo), y sale.
--help[=FMT] (por defecto=auto)
Muestra esta ayuda en el formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o indefinida.
--ignore-pin-depends
Ignora los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBRE_ARCHIVO
Guarda los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre de archivo contiene el carácter `%`, se reemplazará por un índice que no sobrescribirá un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responde no a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deben definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato anterior. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Usa ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegura que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de finalización, por ejemplo. Fallará siempre que se necesite tal operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifica el solucionador CUDF a utilizar para resolver problemas de instalación de paquetes. Este es un solucionador predefinido (esta versión de opam soporta builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un cu

--strict
Falla siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. Por defecto, continúa silenciosamente si es posible.
--switch=SWITCH
Usa SWITCH como el switch del compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilita cualquier solucionador externo y usa el interno (esto requiere que opam haya sido compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sé más detallado. Un -v muestra todos los comandos de paquetes, repite para mostrar también comandos llamados internamente (ej. tar, curl, patch etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestra información de la versión.
-w, --working-dir
Siempre que se actualizan paquetes vinculados a un directorio local controlado por versión, actualiza al estado actual de su fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio fuente se copia tal cual, si no está limpio, puede resultar en un fallo de compilación de opam. Esto solo afecta a paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responde sí a todas las preguntas de sí/no de opam sin preguntar. Ver también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

ENTORNO

Opam hace uso de las variables de entorno listadas aquí. Las variables booleanas deben establecerse a "0", "no", "false" o la cadena vacía para deshabilitar, "1", "yes" o "true" para habilitar.

OPAMALLPARENS envuelve todos los filtros con paréntesis.

OPAMASSUMEDEPEXTS ver opción `--assume-depexts'.

OPAMAUTOREMOVE ver opción de eliminación `--auto-remove'.

OPAMBESTEFFORT ver opción `--best-effort'.

OPAMBESTEFFORTPREFIXCRITERIA establece la cadena que debe anteponerse a los criterios cuando se establece la opción `--best-effort', y se espera que maximice la propiedad `opam-query' en la solución.

OPAMBUILDDOC Eliminado en 2.1.

OPAMBUILDTEST Eliminado en 2.1.

OPAMCLI ver opción `--cli'.

OPAMCOLOR cuando se establece a always o never, establece un valor predeterminado para la opción `--color'.

OPAMCONFIRMLEVEL ver opción `--confirm-level`. OPAMCONFIRMLEVEL tiene prioridad sobre OPAMYES y OPAMNO.

OPAMCRITERIA especifica las preferencias del usuario para la resolución de dependencias. El valor predeterminado depende de la versión del solucionador, usa `config report' para conocer la configuración actual. Ver también la opción --criteria.

OPAMCUDFFILE guarda el gráfico cudf en file-actions-explicit.dot.

OPAMCUDFTRIM controla el filtrado de paquetes no relacionados durante el preprocesamiento de CUDF.

OPAMCURL se puede usar para seleccionar un programa 'curl' dado. Ver OPAMFETCH para más opciones.

OPAMDEBUG ver opciones `--debug' y `--debug-level'.

OPAMDEBUGSECTIONS si está establecido, limita los mensajes de depuración a la lista de secciones separadas por espacios. Las secciones opcionalmente pueden tener un nivel de depuración específico (por ejemplo, CLIENT:2 o CLIENT CUDF:2), pero de lo contrario usan `--debug-level'.

OPAMDIGDEPTH define la agresividad de la búsqueda de conflictos durante el preprocesamiento de CUDF.

OPAMDOWNLOADJOBS establece el número máximo de descargas simultáneas.

OPAMDROPWORKINGDIR anula los paquetes previamente actualizados con --working-dir en la actualización. Sin esta variable establecida, opam los mantendría sin cambios a menos que se nombren explícitamente en la línea de comandos.

OPAMDRYRUN ver opción `--dry-run'.

OPAMEDITOR establece el editor a usar para editar archivos opam, anula $EDITOR y $VISUAL.

OPAMERRLOGLEN establece el número de líneas de registro impresas cuando falla un subproceso. 0 para imprimir todas.

OPAMEXTERNALSOLVER ver opción `--solver'.

OPAMFAKE ver opción `--fake'.

OPAMFETCH especifica cómo descargar archivos: `wget', `curl' o un comando personalizado donde las variables %{url}%, %{out}%, %{retry}%, %{compress}% y %{checksum}% serán reemplazadas. Anula el valor de 'download-command' del archivo de configuración principal.

OPAMFIXUPCRITERIA igual que OPAMUPGRADECRITERIA, pero específico para fixup y reinstall.

OPAMIGNORECONSTRAINTS ver opción de instalación `--ignore-constraints-on'.

OPAMIGNOREPINDEPENDS ver opción `--ignore-pin-depends'.

OPAMINPLACEBUILD ver opción `--inplace-build'.

OPAMJOBS establece el número máximo de procesos trabajadores paralelos a ejecutar.

OPAMJSON registra la salida json en el archivo dado (usa el carácter `%' para indexar los archivos).

OPAMKEEPBUILDDIR ver opción de instalación `--keep-build-dir'.

OPAMKEEPLOGS indica a opam que no elimine algunos registros temporales de comandos y algunas copias de seguridad. Esto omite algunos finalizadores y también puede ayudar a obtener rastreos de pila más fiables.

OPAMLOCKED combinación de las opciones `--locked' y `--lock-suffix'.

OPAMLOGS logdir establece el directorio de registros, por defecto es un directorio temporal en /tmp

OPAMMAKECMD establece el comando make del sistema a usar.

OPAMMERGEOUT fusiona las salidas del proceso, stderr en stdout.

OPAMNO responde no a cualquier pregunta, ver opciones `--no` y `--confirm-level`. OPAMNO se ignora si OPAMCONFIRMLEVEL o OPAMYES están establecidos.

OPAMNOAGGREGATE con `opam admin check', no agrega paquetes.

OPAMNOASPCUD Obsoleto.

OPAMNOAUTOUPGRADE deshabilita la actualización automática interna de repositorios en un formato anterior al actual, en 'update' o 'init'.

OPAMNOCHECKSUMS habilita la opción --no-checksums cuando esté disponible.

OPAMNODEPEXTS deshabilita el manejo de dependencias del sistema, ver opción `--no-depexts'.

OPAMNOENVNOTICE Interno.

OPAMNOSELFUPGRADE ver opción `--no-self-upgrade'

OPAMPINKINDAUTO establece si los sistemas de control de versiones deben detectarse al fijar a una ruta local. Habilitado por defecto desde 1.3.0.

OPAMPRECISETRACKING seguimiento detallado de directorios.

OPAMPREPRO establece esto en falso para deshabilitar el preprocesamiento de CUDF. Menos eficiente, pero podría ayudar a depurar problemas del solucionador.

OPAMREPOSITORYTARRING almacena internamente los repositorios como archivos tar.gz. Esto puede ser mucho más rápido en sistemas de archivos que no manejan bien el escaneo de árboles grandes pero tienen buen caché en /tmp. Sin embargo, es más lento en el caso general.

OPAMREQUIRECHECKSUMS Habilita la opción `--require-checksums' cuando está disponible (ej. para `opam install').

OPAMRETRIES establece el número de intentos antes de fallar descargas.

OPAMREUSEBUILDDIR ver opción `--reuse-build-dir'.

OPAMROOT ver opción `--root'. Esto se establece automáticamente con `opam env --root=DIR --set-root'.

OPAMROOTISOK no se queja al ejecutarse como root.

OPAMSAFE ver opción `--safe'.

OPAMSHOW ver opción `--show'.

OPAMSKIPUPDATE ver opción `--skip-updates'.

OPAMSKIPVERSIONCHECKS omite algunas verificaciones de versión. Inseguro, solo para pruebas de compatibilidad.

OPAMSOLVERALLOWSUBOPTIMAL (predeterminado `true') permite que algunos solucionadores devuelvan una solución cuando alcanzan el tiempo de espera; aunque la solución sigue estando garantizada como consistente, no hay garantía en este caso de que se ajuste a los criterios de optimización esperados. Si es `true', opam continuará con una advertencia, si es `false' un tiempo de espera es un error. Actualmente solo el backend builtin-z3 maneja este caso degradado.

OPAMSOLVERTIMEOUT cambia el tiempo de asignación del solucionador. El valor predeterminado es 60.0, establecido en 0 para ilimitado. Tenga en cuenta que no todos los solucionadores pueden soportar esta opción.

OPAMSOLVERTOLERANCE cambia la tolerancia hacia el solucionador que elige una solución no optimizada (es decir, podría extraer paquetes desactualizados). Los valores típicos varían de 0.0 (la mejor solución conocida por el solucionador) a 1.0 (solución no optimizada). El valor predeterminado es 0.0. Esta opción es útil en caso de que el solucionador no pueda encontrar una solución en un tiempo razonable (ver $OPAMSOLVERTIMEOUT). Tenga en cuenta que no todos los solucionadores pueden admitir esta opción.

OPAMSTATS Eliminado en 2.4.

OPAMSTATUSLINE muestra una línea de estado dinámica que muestra lo que está sucediendo actualmente en la terminal. (uno de always, never o auto)

OPAMSTRICT falla ante inconsistencias (lectura de archivos, importación de switches, etc.).

OPAMSWITCH ver opción `--switch'. Se establece automáticamente con `opam env --switch=SWITCH --set-switch'.

OPAMUNLOCKBASE ver opción de instalación `--unlock-base'.

OPAMUPGRADECRITERIA especifica las preferencias del usuario para la resolución de dependencias al realizar una actualización. Anula OPAMCRITERIA en las actualizaciones si ambas están establecidas. Ver también la opción --criteria.

OPAMUSEINTERNALSOLVER ver opción `--use-internal-solver'.

OPAMUSEOPENSSL Eliminado en 2.2.

OPAMUTF8 usa caracteres UTF8 en la salida (uno de always, never o auto). Por defecto `auto', que se determina según la configuración regional).

OPAMUTF8MSGS usa caracteres UTF8 extendidos (camellos) en mensajes de opam. Implica OPAMUTF8. Esto está establecido por defecto solo en macOS.

OPAMVALIDATIONHOOK si está establecido, usa el comando `%{hook%}' para validar una actualización de repositorio opam.

OPAMVERBOSE ver opción `--verbose'.

OPAMVERBOSEON ver opción --verbose-on

OPAMVERSIONLAGPOWER no usar.

OPAMWITHDEVSETUP ver opción de instalación `--with-dev-setup'.

OPAMWITHDOC ver opción de instalación `--with-doc'.

OPAMWITHTEST ver opción de instalación `--with-test.

OPAMWORKINGDIR ver opción `--working-dir'.

OPAMYES ver opciones `--yes' y `--confirm-level`. OPAMYES tiene prioridad sobre OPAMNO y se ignora si OPAMCONFIRMLEVEL está establecido.

ENVIRONMENT

The following environment variables may be set to modify the behavior of opam.

OPAMKEEPUNSAFE
If set, opam will not try to keep a safe environment (i.e. it will not override certain variables like PATH or OCAMLPATH).
OPAMEXT_foo_bar
The foo:bar variable is overridden by the contents of the environment variable OPAMEXT_foo_bar when substituting `%{foo:bar}%' strings in opam files.
OPAMVAR_foo
The variable var when substituting `%{var}%' strings in opam files.
OPAMVAR_package_var
Overrides the contents of the variable package:var when substituting `%{package:var}%' strings in opam files.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

EXIT STATUS

As an exception to the following, the `exec' command returns 127 if the command was not found or couldn't be executed, and the command's exit value otherwise.

0
Success, or true for boolean queries.
1
False. Returned when a boolean return value is expected, e.g. when running with --check, or for queries like opam lint.
2
Bad command-line arguments, or command-line arguments pointing to an invalid context (e.g. file not following the expected format).
5
Not found. You requested something (package, version, repository, etc.) that couldn't be found.
10
Aborted. The operation required confirmation, which wasn't given.
15
Could not acquire the locks required for the operation.
20
There is no solution to the user request. This can be caused by asking to install two incompatible packages, for example.
30
Error in package definition, or other metadata files. Using --strict raises this error more often.
31
Package script error. Some package operations were unsuccessful. This may be an error in the packages or an incompatibility with your system. This can be a partial error.
40
Sync error. Could not fetch some remotes from the network. This can be a partial error.
50
Configuration error. Opam or system configuration doesn't allow operation, and needs fixing.
60
Solver failure. The solver failed to return a sound answer. It can be due to a broken external solver, or an error in solver configuration.
99
Internal error. Something went wrong, likely due to a bug in opam itself.
130
User interrupt. SIGINT was received, generally due to the user pressing Ctrl-C.
0
on success.
123
on indiscriminate errors reported on standard error.
124
on command line parsing errors.
125
on unexpected internal errors (bugs).
