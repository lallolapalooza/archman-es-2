NOMBRE

ogr2ogr - Convierte datos de características simples entre formatos de archivo.

SINOPSIS

Uso: ogr2ogr [--help] [--long-usage] [--help-general]
               [-of <formato_salida>] [-dsco <NOMBRE>=<VALOR>]...
               [-lco <NOMBRE>=<VALOR>]...
               [[-append]|[-upsert]|[-overwrite]]

DESCRIPCIÓN

ogr2ogr se puede usar para convertir datos de características simples entre formatos de archivo. También puede realizar varias operaciones durante el proceso, como la selección espacial o de atributos, reducir el conjunto de atributos, establecer el sistema de coordenadas de salida o incluso reproyectar las características durante la traducción.

--help
Muestra este mensaje de ayuda y sale.
--help-general
Muestra un breve mensaje de uso para las opciones generales de línea de comandos de GDAL y sale.
-if <formato>
Nombre del formato/controlador que se intentará para abrir el/los archivo(s) de entrada. Generalmente no es necesario especificarlo, pero se puede usar para omitir la detección automática del controlador, cuando esta falla al seleccionar el controlador apropiado. Esta opción se puede repetir varias veces para especificar varios controladores candidatos. Tenga en cuenta que no fuerza a esos controladores a abrir el conjunto de datos. En particular, algunos controladores tienen requisitos sobre las extensiones de archivo.

Añadido en la versión 3.2.

-of <nombre_formato>, -f <nombre_formato>
Nombre del formato de archivo de salida, por ejemplo, ESRI Shapefile, MapInfo File, PostgreSQL. Si no se especifica, el formato se adivina a partir de la extensión.
-append
Añade a la capa existente en lugar de crear una nueva. Esta opción también habilita -update.
-upsert
Añadido en la versión 3.6.

Variante de -append donde la operación OGRLayer::UpsertFeature() se utiliza para insertar o actualizar características en lugar de añadir con OGRLayer::CreateFeature().

Actualmente, esto solo está implementado en unos pocos controladores: GPKG -- GeoPackage vector, Elasticsearch: Geographically Encoded Objects for Elasticsearch y MongoDBv3 (los controladores que implementan upsert exponen la capacidad GDAL_DCAP_UPSERT).

La operación upsert utiliza el FID de la característica de entrada, cuando está establecido y es "significativo" (es decir, el nombre de la columna FID no es una cadena vacía), como clave para actualizar características existentes. Es crucial asegurarse de que el FID en las capas de origen y destino sean consistentes.

Para el controlador GPKG, también es posible realizar upserts de características cuyo FID no está establecido o no es significativo (se puede usar -unsetFid para ignorar el FID de la característica de origen), cuando hay una columna UNIQUE que no es la clave primaria entera.

-overwrite
Elimina la capa de salida y la recrea vacía.
-update
Abre el conjunto de datos de salida existente en modo de actualización en lugar de intentar crear uno nuevo.
-select <lista_campos>
Lista delimitada por comas de los campos de la capa de entrada para copiar a la nueva capa.

A partir de GDAL 3.9, los nombres de campo con espacios, comas o comillas dobles deben ir rodeados de un carácter de comillas dobles de inicio y fin, y las comillas dobles en un nombre de campo deben escaparse con una barra invertida.

Dependiendo de la shell utilizada, esto podría requerir comillas adicionales. Por ejemplo, para seleccionar campo_regular, un_campo_con espacio, y coma y un campo con " comilla doble con una shell de Unix:

-select "campo_regular,\"un_campo_con espacio, y coma\",\"un campo con \\\" comilla doble\""

Un campo solo se selecciona una vez, incluso si se menciona varias veces en la lista y si la capa de entrada tiene nombres de campo duplicados.

Los campos de geometría también se pueden especificar en la lista.

Se seleccionan todos los campos cuando no se especifica -select. Especificar una cadena vacía se puede usar para deshabilitar la selección de cualquier campo de atributo, y mantener solo las geometrías.

Tenga en cuenta que esta configuración no se puede usar junto con -append. Para controlar la selección de campos al añadir a una capa, use -fieldmap o -sql.

-progress
Muestra el progreso en la terminal. Solo funciona si las capas de entrada tienen la capacidad de "conteo rápido de características".
-sql <sentencia_sql>|@<archivo>
Sentencia SQL a ejecutar. La tabla/capa resultante se guardará en la salida. La sintaxis @archivo se puede usar para indicar que el contenido está en el archivo señalado. (No se puede usar con -spat_srs).
-dialect <dialecto>
Dialecto SQL. En algunos casos, se puede usar para usar el dialecto OGR SQL (no optimizado) en lugar del SQL nativo de un SGBDR al pasar el valor de dialecto OGRSQL. El dialecto SQL SQLite (dialecto SQL de SQLite) se puede usar también.

n se puede elegir con los valores de dialecto SQLITE e INDIRECT_SQLITE, y esto se puede usar con cualquier origen de datos.
-where <restricted_where>|@<filename>
Consulta de atributos (como SQL WHERE). La sintaxis @nombre_archivo se puede usar para indicar que el contenido se encuentra en el archivo apuntado.
-skipfailures
Continuar después de un error, omitiendo la entidad fallida. Tenga en cuenta que esta opción anula el valor de -gt a 1, lo que puede provocar una ralentización severa al insertar en bases de datos.
-spat <xmin> <ymin> <xmax> <ymax>
Límites de consulta espacial, en el SRS de las capa(s) de origen (o el especificado con -spat_srs). Solo se seleccionarán las entidades cuya geometría intersecte los límites. Las geometrías no se recortarán a menos que se especifique -clipsrc.
-spat_srs <srs_def>
Anular el SRS del filtro espacial. (No se puede usar con -sql).
-geomfield <campo>
Nombre del campo de geometría sobre el que opera el filtro espacial.
-dsco <NOMBRE>=<VALOR>
Opción de creación de conjunto de datos (específica del formato)
-lco <NOMBRE>=<VALOR>
Opción de creación de capa (específica del formato)
-nln <nombre>
Asignar un nombre alternativo a la nueva capa
-nlt <tipo>
Definir el tipo de geometría para la capa creada. Uno de NONE, GEOMETRY, POINT, LINESTRING, POLYGON, GEOMETRYCOLLECTION, MULTIPOINT, MULTIPOLYGON, MULTILINESTRING, CIRCULARSTRING, COMPOUNDCURVE, CURVEPOLYGON, MULTICURVE y MULTISURFACE tipos de geometría no lineal. Añada Z, M, o ZM al nombre del tipo para especificar coordenadas con elevación, medida, o elevación y medida. PROMOTE_TO_MULTI se puede usar para promocionar automáticamente capas que mezclan polígonos o multipolígonos a multipolígonos, y capas que mezclan linestrings o multilinestrings a multilinestrings. Puede ser útil al convertir shapefiles a PostGIS y otros drivers de destino que implementan verificaciones estrictas para tipos de geometría. CONVERT_TO_LINEAR se puede usar para convertir tipos de geometría no lineal a tipos de geometría lineal aproximándolos, y CONVERT_TO_CURVE para promocionar un tipo no lineal a su tipo de curva generalizado (POLYGON a CURVEPOLYGON, MULTIPOLYGON a MULTISURFACE, LINESTRING a COMPOUNDCURVE, MULTILINESTRING a MULTICURVE). A partir de la versión 2.1 el tipo puede definirse como medido ("25D" sigue siendo un alias para "Z" simple). Algunas conversiones forzadas de geometría pueden resultar en geometrías inválidas, por ejemplo, al forzar la conversión de multipolígonos de múltiples partes con -nlt POLYGON, el polígono resultante romperá las reglas de Simple Features.

A partir de GDAL 3.0.5, -nlt CONVERT_TO_LINEAR y -nlt PROMOTE_TO_MULTI se pueden usar simultáneamente.

-dim <val>
Forzar la dimensión de coordenadas a val (los valores válidos son XY, XYZ, XYM y XYZM - para compatibilidad con versiones anteriores, 2 es un alias para XY y 3 es un alias para XYZ). Esto afecta tanto al tipo de geometría de la capa como a las geometrías de las entidades. El valor se puede establecer en layer_dim para instruir que las geometrías de las entidades se promocionen a la dimensión de coordenadas declarada por la capa.
-a_srs <srs_def>
Asignar un SRS de salida, pero sin reproyectar (usar -t_srs para reproyectar)

Anular el SRS de origen. Si no se especifica, se utilizará el SRS que se encuentre en la capa de entrada. Esta opción solo tiene efecto si se usa junto con -t_srs para reproyectar.

-xyRes "<val>[ m|mm|deg]"
Añadido en la versión 3.9.

Establecer/anular la resolución de coordenadas X/Y de la geometría. Si solo se especifica un valor numérico, se asume que está expresado en las unidades del SRS de destino. Los sufijos m, mm o deg pueden especificarse para indicar que el valor debe interpretarse como metros, milímetros o grados.

Al especificar esta opción, se ejecuta el método OGRGeometry::SetPrecision() en las geometrías (que no sean curvas) antes de pasarlas al driver de salida, para evitar generar geometrías inválidas debido a la precisión potencialmente reducida (a menos que la opción de configuración OGR_APPLY_GEOM_SET_PRECISION se establezca en NO)

Añadido en la versión 3.0.

Una cadena PROJ (operación de un solo paso o cadena de múltiples pasos que comience con +proj=pipeline), una cadena WKT2 que describa una Operación de Coordenadas, o un URN urn:ogc:def:coordinateOperation:EPSG::XXXX que anule la transformación por defecto del CRS de origen al de destino.

-ct_opt <NOMBRE>=<VALOR>
Añadido en la versión 3.11.

Especifica una opción de operación de coordenadas que influye en cómo PROJ selecciona operaciones de coordenadas cuando -ct no está establecido.

Las siguientes opciones están disponibles:

  • ONLY_BEST``=``YES/NO. Por defecto (al menos en la serie PROJ 9.x), PROJ puede usar operaciones de coordenadas que no son las "mejores" si faltan los recursos (típicamente grids) necesarios para usarlas. Entonces, recurrirá a otras operaciones de coordenadas de menor precisión, por ejemplo, usando transformaciones de Helmert, o en ausencia de tales operaciones, a aquellas con una precisión potencialmente muy baja, usando transformaciones de "estimación" (ver https://proj.org/glossary.html). Al llamar a este método con YES, PROJ solo considerará la operación "mejor" y generará un error (en el momento de Transform()) si no se pueden usar. SYNOPSIS

ogr2ogr [OPTIONS] [SRCLAYER [SRCLAYER ...]] DST_DSN [SRCLAYER [SRCLAYER ...]]

ogr2ogr -sql SQLStatement [-dialect DIALECT] [OPTIONS] DST_DSN [SRCLAYER]

DESCRIPTION

The ogr2ogr utility is a command line tool to convert data between different vector geospatial file formats. It relies on the GDAL/OGR vector library.

The first syntax form copies the specified SRCLAYER (or all layers if none are specified) from the source dataset SRC_DSN to the destination dataset DST_DSN. The layer creation options for the destination dataset can be specified before DST_DSN. The layer creation options for the destination layer can be specified after DST_DSN.

The second syntax form queries the source dataset using the SQLStatement and writes the result to the destination dataset. The -dialect option can be used to specify the SQL dialect.

OPTIONS

The following options are available:

-append
Appends the source layer(s) to the destination layer. If the destination layer does not exist, it is created. By default, source and destination layers must have the same fields, except for the FID field. It is possible to override this behaviour by using -fieldmap, -relaxedFieldNameMatch, -forceNullable, -addfields, etc. options.
-update
Opens the destination dataset in update mode. This implies that existing layers can be modified. By default, if the destination dataset exists and is not opened in update mode, it is truncated.
-overwrite
Causes the existing destination layer to be erased and recreated with the source layer's definition. This is the default behaviour if the destination dataset exists and is not opened in update mode, and if the source layer is not appended. This option is generally implied when not using -append or -update.
-skipfailures
Causes the process to continue if an error occurs on a feature after it has started. This is only useful if the source driver and the destination driver are different and if the destination driver does not report errors for features that it doesn't support.
-limit <n>
Limit the number of features processed to n.
-where <expression>
Limits the features read from the source layer to those that satisfy the where clause. The expression is a SQL-like WHERE clause, without the keyword WHERE. For example: -where "type=1".
-selectfields <fieldlist>
Comma separated list of fields to copy from the source layer. If not specified, all fields are copied. Field names with spaces must be quoted or enclosed in square brackets. Example: -selectfields "FID,name,name2,[field with spaces]".
-fieldmap <fieldmap>
Specifies the list of field indexes to be copied from the source to the destination. The (n)th value specified in the list is the index of the field in the target layer definition in which the n(th) field of the source layer must be copied. Index count starts at zero. To omit a field, specify a value of -1. There must be exactly as many values in the list as the count of the fields in the source layer. We can use the 'identity' setting to specify that the fields should be transferred by using the same order. This setting should be used along with the -append setting.
-sql <statement>
Specifies a SQL statement to be executed for querying the source data. This statement should be compatible with the OGR SQL dialect (ogrsql(1)). If this option is used, only one source layer name can be provided, which will be the table name in the SQL statement. This option should generally be used in conjonction with -dialect.
-dialect <dialect>
Select the SQL dialect. Supported values are sqlite, mssql, oracle, and none (OGR default). The default is sqlite.
-gt <n>
Set the number of features to be processed between BEGIN TRANSACTION and COMMIT TRANSACTION statements. The default is 20000. A value of 1 means no transaction is used (each feature is committed individually).
-propto
Causes the source SRS to be copied to the destination layer. If the destination layer already has an SRS, it will be overwritten.
-a_srs <SRS Name>
Assign a new spatial reference system to the copied data. This option can be used in combination with the -propto option. If used alone, it implies a reprojection of the source data. SRS Name can be any valid OGR SRS definition (e.g. EPSG:4269, WGS84, "+proj=longlat +datum=WGS84").
-t_srs <SRS Name>
Transform the output data to the specified target SRS. This option implies reprojection of the source data. SRS Name can be any valid OGR SRS definition. This option is synonymous with -a_srs.
-s_srs <SRS Name>
Source SRS name. This option can be used to override the SRS of the source dataset when it is not correctly defined. SRS Name can be any valid OGR SRS definition.
-dim {2|3}
Sets the dimension of the geometries in the output dataset. By default, the dimension of the output geometries is the same as the dimension of the input geometries. Use 2 to force 2D geometries and 3 to force 3D geometries.
-zfield <field_name>
Uses the specified field to fill the Z coordinate of geometries.
-gcp <ungeoref_x> <ungeoref_y> <georef_x> <georef_y> [<elevation>]
Use the indicated ground control point to compute a coordinate transformation. The transformation method can be selected by specifying the -order or -tps options. Note that unlike raster tools such as gdal_edit or gdal_translate, GCPs are not added to the output dataset. This option may be provided multiple times to provide a set of GCPs (at least 2 GCPs are needed).
-order <n>
Order of polynomial used for warping (1 to 3). The default is to select a polynomial order based on the number of GCPs.
-tps
Force use of thin plate spline transformer based on available GCPs.
-fieldTypeToString
All fields of type Integer, Real or Binary are converted to String. This is an alternate way to using the CAST operator of OGR SQL, that may avoid typing a long SQL query. Note that this does not influence the field types used by the source driver, and is only an afterwards conversion. Also note that this option is without effects on fields whose presence and type is hard-coded in the output driver (e.g KML, GPX). For an alternative way to manipulate field types earlier in the process while they are read from the input dataset see -oo OGR_SCHEMA (only available for a limited set of formats).
-mapFieldType {<srctype>|All=<dsttype>[,<srctype2>=<dsttype2>]...}
Converts any field of the specified type to another type. Valid types are : Integer, Integer64, Real, String, Date, Time, DateTime, Binary, IntegerList, Integer64List, RealList, StringList. Types can also include subtype between parenthesis, such as Integer(Boolean), Real(Float32), ... Special value All can be used to convert all fields to another type. This is an alternate way to using the CAST operator of OGR SQL, that may avoid typing a long SQL query. This is a generalization of -fieldTypeToString. Note that this does not influence the field types used by the source driver, and is only an afterwards conversion. Also note that this option is without effects on fields whose presence and type is hard-coded in the output driver (e.g KML, GPX). For an alternative way to manipulate field types earlier in the process while they are read from the input dataset see -oo OGR_SCHEMA (only available for a limited set of formats).
-dateTimeTo {UTC|UTC(+|-)<HH>|UTC(+|-)<HH>:<MM>}
Added in version 3.7.

Converts date time values from the timezone specified in the source value to the target timezone expressed with -dateTimeTo. Datetime whose timezone is unknown or localtime are not modified.

HH must be in the [0,14] range and MM=00, 15, 30 or 45.

-unsetFieldWidth
Set field width and precision to 0.
-splitlistfields
Split fields of type StringList, RealList or IntegerList into as many fields of type String, Real or Integer as necessary.
-maxsubfields <val>
To be combined with -splitlistfields to limit the number of subfields created for each split field.
-explodecollections
Produce one feature for each geometry in any kind of geometry collection in the source file, applied after any -sql option. This options is not compatible with -preserve_fid but -sql "SELECT fid AS original_fid, * FROM ..." can be used to store the original FID if needed.
-zfield <field_name>

-gcp <ungeoref_x> <ungeoref_y> <georef_x> <georef_y> [<elevation>]

-tps
Force use of thin plate spline transformer based on available GCPs.
-fieldmap

The (n)th value specified in the list is the index of the field in the target layer definition in which the n(th) field of the source layer must be copied. Index count starts at zero. To omit a field, specify a value of -1. There must be exactly as many values in the list as the count of the fields in the source layer. We can use the 'identity' setting to specify that the fields should be transferred by using the same order. This setting should be used along with the -append setting.
-addfields
This is a specialized version of -append. Contrary to -append, -addfields has the effect of adding, to existing target layers, the new fields found in source layers. This option is useful when merging files that have non-strictly identical structures. This might not work for output formats that don't support adding fields to existing non-empty layers. Note that if you plan to use -addfields, you may need to combine it with -forceNullable, including for the initial import.
-relaxedFieldNameMatch
Do field name matching between source and existing target layer in a more relaxed way if the target driver has an implementation for it.
-forceNullable
Do not propagate not-nullable constraints to target layer if they exist in source layer.
-unsetDefault
Do not propagate default field values to target layer if they exist in source layer.
-unsetFid
Can be specified to prevent the name of the source FID column and source feature IDs from being reused for the target layer. This option can for example be useful if selecting source features with a ORDER BY clause.
-emptyStrAsNull
Added in version 3.3.

Treat empty string values as null.

-resolveDomains
Added in version 3.3.

When this is specified, any selected field that is linked to a coded field domain will be accompanied by an additional field ({dstfield}_resolved), that will contain the description of the coded value.

-nomd
To disable copying of metadata from source dataset and layers into target dataset and layers, when supported by output driver.
-mo <META-TAG>=<VALUE>
Passes a metadata key and value to set on the output dataset, when supported by output driver.
-noNativeData
To disable copying of native data, i.e. details of source format not captured by OGR abstraction, that are otherwise preserved by some drivers (like GeoJSON) when converting to same format.
<dst_dataset_name>
Output dataset name.
<src_dataset_name>
Source dataset name.
<layer_name>
One or more source layer names to copy to the output dataset. If no layer names are passed, then all source layers are copied.

PERFORMANCE HINTS

When writing into transactional DBMS (SQLite/PostgreSQL,MySQL, etc...), it might be beneficial to increase the number of INSERT statements executed between BEGIN TRANSACTION and COMMIT TRANSACTION statements. This number is specified with the -gt option. For example, for SQLite, explicitly defining -gt 65536 ensures optimal performance while populating some table containing many hundreds of thousands or millions of rows. However, note that -skipfailures overrides -gt and sets the size of transactions to 1.

For PostgreSQL, the PG_USE_COPY config option can be set to YES for a significant insertion performance boost. See the PG driver documentation page.

More generally, consult the documentation page of the input and output drivers for performance hints.

KNOWN ISSUES

Starting with GDAL 3.8, ogr2ogr uses internally an Arrow array based API (cf RFC 86: Column-oriented read API for vector layers) for some source formats (in particular GeoPackage or FlatGeoBuf), and for the most basic types of operations, to improve performance. This substantial change in the ogr2ogr internal logic has required a number of fixes throughout the GDAL 3.8.x bugfix releases to fully stabilize it, and we believe most issues are resolved with GDAL 3.9. If you hit errors not met with earlier GDAL versions, you may specify --config OGR2OGR_USE_ARROW_API NO on the ogr2ogr command line to opt for the classic algorithm using an iterative feature based approach.
