NOMBRE

getopt, getopt_long, getopt_long_only, optarg, optind, opterr, optopt - Analizar opciones de línea de comandos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int getopt(int argc, char *argv[],
           const char *optstring);
extern char *optarg;
extern int optind, opterr, optopt;
#include <getopt.h>
int getopt_long(int argc, char *argv[],
           const char *optstring,
           const struct option *longopts, int *longindex);
int getopt_long_only(int argc, char *argv[],
           const char *optstring,
           const struct option *longopts, int *longindex);

DESCRIPCIÓN

La función getopt() analiza los argumentos de la línea de comandos. Sus argumentos argc y argv son el recuento y la matriz de argumentos tal como se pasan a la función main() en la invocación del programa. Un elemento de argv que comienza con '-' (y no es exactamente "-" ni "--") es un elemento de opción. Los caracteres de este elemento (aparte del '-' inicial) son caracteres de opción. Si getopt() se llama repetidamente, devuelve sucesivamente cada uno de los caracteres de opción de cada uno de los elementos de opción.

La variable optind es el índice del siguiente elemento a procesar en argv. El sistema inicializa este valor a 1. El llamante puede restablecerlo a 1 para reiniciar el escaneo del mismo argv, o al escanear un vector de argumentos nuevo.

Si getopt() encuentra otro carácter de opción, devuelve ese carácter, actualizando la variable externa optind y una variable estática nextchar para que la siguiente llamada a getopt() pueda reanudar el escaneo con el siguiente carácter de opción o elemento argv.

Si no quedan más caracteres de opción, getopt() devuelve -1. Entonces optind es el índice en argv del primer elemento argv que no es una opción.

optstring es una cadena que contiene los caracteres de opción legítimos. Un carácter de opción legítimo es cualquier carácter visible de un byte ascii(7) (para el cual isgraph(3) devolvería distinto de cero) que no sea '-', ':' ni ';'. Si dicho carácter va seguido de dos puntos, la opción requiere un argumento, por lo que getopt() coloca un puntero al texto siguiente en el mismo elemento argv, o el texto del siguiente elemento argv, en optarg. Dos dos puntos significan que una opción toma un argumento opcional; si hay texto en el elemento argv actual (es decir, en la misma palabra que el nombre de la opción, por ejemplo, "-oarg"), entonces se devuelve en optarg, de lo contrario optarg se establece a cero. Esta es una extensión de GNU. Si optstring contiene W seguido de un punto y coma, entonces -W foo se trata como la opción larga --foo. (La opción -W está reservada por POSIX.2 para extensiones de implementación.) Este comportamiento es una extensión de GNU, no está disponible con bibliotecas anteriores a glibc 2.

Por defecto, getopt() permuta el contenido de argv mientras escanea, de modo que eventualmente todas las no-opciones queden al final. Se implementan otros dos modos de escaneo. Si el primer carácter de optstring es '+' o la variable de entorno POSIXLY_CORRECT está establecida, entonces el procesamiento de opciones se detiene tan pronto como se encuentra un argumento no-opción. Si '+' no es el primer carácter de optstring, se trata como una opción normal. Si se requiere el comportamiento POSIXLY_CORRECT en este caso, optstring contendrá dos símbolos '+'. Si el primer carácter de optstring es '-', entonces cada elemento argv no-opción se maneja como si fuera el argumento de una opción con el código de carácter 1. (Esto lo usan los programas que fueron escritos para esperar opciones y otros elementos argv en cualquier orden y que se preocupan por el orden de los dos.) El argumento especial "--" fuerza el fin del escaneo de opciones independientemente del modo de escaneo.

Mientras procesa la lista de opciones, getopt() puede detectar dos tipos de errores: (1) un carácter de opción que no estaba especificado en optstring y (2) un argumento de opción faltante (es decir, una opción al final de la línea de comandos sin el argumento esperado). Tales errores se manejan y reportan de la siguiente manera:

•
Por defecto, getopt() imprime un mensaje de error en la salida estándar, coloca el carácter de opción erróneo en optopt y devuelve '?' como resultado de la función.
•
Si el llamante ha establecido la variable global opterr a cero, entonces getopt() no imprime un mensaje de error. El llamante puede determinar que hubo un error probando si el valor de retorno de la función es '?'. (Por defecto, opterr tiene un valor distinto de cero).
•
Si el primer carácter (después de cualquier '+' o '-' opcional descrito anteriormente) de optstring es un dos puntos (':'), entonces getopt() tampoco imprime un mensaje de error. Además, devuelve ':' en lugar de '?' para indicar un argumento de opción faltante. Esto permite al llamante distinguir los dos tipos de errores diferentes.

getopt_long() y getopt_long_only()

La función getopt_long() funciona como getopt() excepto que también acepta opciones largas, iniciadas con dos guiones. (Si el programa solo acepta opciones largas, entonces optstring debe especificarse como una cadena vacía (""), no NULL.) Los nombres de las opciones largas pueden abreviarse si la abreviatura es única o es una coincidencia exacta con alguna opción definida. Una opción larga puede tomar un parámetro, con el formato --arg=param o --arg param.

longopts es un puntero al primer elemento de una matriz de struct option declarada en <getopt.h> como


struct option {
    const char *name;
    int         has_arg;
    int        *flag;
    int         val;
};

Los significados de los diferentes campos son:

name
es el nombre de la opción larga.
has_arg
es: no_argument (o 0) si la opción no toma argumento; required_argument (o 1) si la opción requiere un argumento; o optional_argument (o 2) si la opción toma un argumento opcional.
flag
especifica cómo se devuelven los resultados para una opción larga. Si flag es NULL, entonces getopt_long() devuelve val. (Por ejemplo, el programa que llama puede establecer val al carácter de opción corto equivalente.) De lo contrario, getopt_long() devuelve 0, y flag apunta a una variable que se establece a val si se encuentra la opción, pero se deja sin cambios si no se encuentra la opción.
val
es el valor a devolver, o a cargar en la variable apuntada por flag.

El último elemento de la matriz debe estar relleno de ceros.

Si longindex no es NULL, apunta a una variable que se establece al índice de la opción larga en relación con longopts.

getopt_long_only() es como getopt_long(), pero '-' así como "--" pueden indicar una opción larga. Si una opción que comienza con '-' (no "--") no coincide con una opción larga, pero sí coincide con una opción corta, se analiza como una opción corta en su lugar.

opterr(3) - Linux man-pages (Spanish)

NAME

opterr, optarg, optind, opte, optreset - parse command line options

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <unistd.h>

extern int opterr;
extern char *optarg;
extern int optind;
extern int opte;
extern int optreset;

int getopt(int argc, char *const argv[], const char *optstring);

#if __GLIBC__ >= 2
#include <getopt.h>

int getopt_long(int argc, char *const argv[], const char *optstring,
                const struct option *longopts, int *idx);
int getopt_long_only(int argc, char *const argv[], const char *optstring,
                     const struct option *longopts, int *idx);
#endif

DESCRIPTION

The getopt() function parses the default option characters specified in optstring from the argument list found in argv. If there are no options to be parsed, the return value is -1. Each invocation of getopt() returns the next option character specified in optstring. The caller must be prepared to rearrange the argv array, or call getopt() repeatedly.

The global variable optind is the index of the next argument to be processed. The system initializes this index to 1. When getopt() returns -1, the caller can use optind to find the first nonoption argument.

The global variable optarg points to the option argument, when an option is found which requires an argument, and when an option is found which is optional. If the option is optional, then getopt() returns the option only when it is the first argument in argv. If the option requires an argument, then optarg points to the option argument.

If optstring begins with a colon (':'), then getopt() enters the silent error-reporting mode. In this mode, if an option requires an argument but no argument is found, optarg is set to NULL, and ':' is returned. If an unknown option character is encountered, optarg is set to NULL, and ':' is returned. If optstring does not begin with a colon, the first unrecognized option character causes '?' to be returned, and optarg is set to NULL. The first unrecognized argument causes '?' to be returned, and optarg is set to NULL.

The global variable opterr controls whether messages may be printed to standard error when an error is encountered. If opterr is non-zero (the default), an error message is printed to standard error. If opterr is zero, no error message is printed. The silent error reporting mode described above overrides this behavior.

The global variable opte is the character that was passed to optstring.

The global variable optreset is a flag that can be used to reset the operation of getopt(). When optreset is set to a non-zero value, getopt() resets optind to 1, and the value of optreset is set to 0. This is useful if you need to rescan the argument list more than once.

The argument optstring can contain the following characters:

A:
The colon is used for silent error reporting.
A-:
The hyphen allows for the handling of options preceded by a single hyphen. With the default behavior, options are preceded by a single hyphen. With the hyphen as the first character, options are preceded by a double hyphen. The GNU version of getopt() handles GNU style options.
A+:
The plus sign resets the behavior of getopt() to the POSIX standard behavior. All options must be preceded by a single hyphen. Options are not sorted. Nonoption arguments terminate the option processing.
A:
The character is the name of an option. If the character is followed by a colon, the option requires an argument, which should be placed after the option on the command line, with whitespace placed between the option and its argument. If the character is followed by two colons, the option takes an optional argument. The argument is either immediately following the option without whitespace or it is the next argument in argv. If the option does not take an argument, then the option character is returned, and the next argument is not an option.

getopt_long() and getopt_long_only() handle both short options (like getopt()) and long options (like --long-option).

The longopts argument is a pointer to the first element of an array of struct option.

struct option {
    const char *name;       // Name of the long option without the leading "no" prefix.
    int has_arg;            // Values are no_argument, required_argument, or optional_argument.
    int *flag;              // If not NULL, then the long option causes val to be stored in the location pointed to by flag.
    int val;                // If flag is NULL, then this is the return value for the option or the negative value for a negative option.
};

The idx argument is a pointer to an integer that is set to the index of the long option within the longopts array if flag is NULL. Otherwise, the value specified in val is returned.

getopt_long_only() allows options to be long-only or short-only. Short options may be prefixed with a single hyphen.

RETURN VALUE

On success, getopt() returns the next option character found in argv. When all options have been processed, -1 is returned. If optstring begins with a colon, ':' is returned when an option requires an argument but none is found, or when an unknown option character is encountered. If optstring does not begin with a colon, '?' is returned when an unknown option character is encountered, or when an option requires an argument but none is found. The return value depends on the first character in optstring: if it is ':', then ':' is returned; otherwise '?' is returned.

getopt_long() and getopt_long_only() also return the option character when a short option is recognized. For a long option, they return val if flag is NULL, and 0 otherwise. Error and -1 returns are the same as for getopt(), plus '?' for an ambiguous match or an extraneous parameter.

ENVIRONMENT

POSIXLY_CORRECT
If this is set, then option processing stops as soon as a nonoption argument is encountered.

VERSIONS

POSIX specifies that the argv array argument should be const, but these functions permute its elements unless the environment variable POSIXLY_CORRECT is set. const is used in the actual prototype to be compatible with other systems; however, this page doesn't show the qualifier, to avoid confusing readers.

STANDARDS

POSIX.1-2008.
getopt_long()
getopt_long_only()
GNU.

HISTORY

getopt()
POSIX.1-2001, and POSIX.2.

On some older implementations, getopt() was declared in <stdio.h>. SUSv1 permitted the declaration to appear in either <unistd.h> or <stdio.h>. POSIX.1-1996 marked the use of <stdio.h> for this purpose as LEGACY. POSIX.1-2001 does not require the declaration to appear in <stdio.h>.

Very old versions of glibc were affected by a _PID_GNU_nonoption_argv_flags_ environment variable.

NOTES

A program that scans multiple argument vectors, or rescans the same vector more than once, and wants to make use of GNU extensions such as '+' and '-' at the start of optstring, or changes the value of POSIXLY_CORRECT between scans, must reinitialize getopt() by resetting optind to 0, rather than the traditional value of 1. (Resetting to 0 forces the invocation of an internal initialization routine that rechecks POSIXLY_CORRECT and checks for GNU extensions in optstring.)

Command-line arguments are parsed in strict order meaning that an option requiring an argument will consume the next argument, regardless of whether that argument is the correctly specified option argument or simply the next option (in the scenario the user mis-specifies the command line). For example, if optstring is specified as "1n:" and the user specifies the command line arguments incorrectly as prog -n -1, the -n option will be given the optarg value "-1", and the -1 option will be considered to have not been specified.

EXAMPLES

getopt()

The following trivial example program uses getopt() to handle two program options: -n, with no associated value; and -t val, which expects an associated value.

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int flags, opt;
    int nsecs, tfnd;
    nsecs = 0;
    tfnd = 0;
    flags = 0;
    while ((opt = getopt(argc, argv, "nt:")) != -1) {
        switch (opt) {
        case 'n':
            flags = 1;
            break;
        case 't':
            nsecs = atoi(optarg);
            tfnd = 1;
            break;
        default: /* '?' */
            fprintf(stderr, "Usage: %s [-t nsecs] [-n] name\n",
                    argv[0]);
            exit(EXIT_FAILURE);
        }
    }
    printf("flags=%d; tfnd=%d; nsecs=%d; optind=%d\n",
           flags, tfnd, nsecs, optind);
    if (optind >= argc) {
        fprintf(stderr, "Expected argument after options\n");
        exit(EXIT_FAILURE);
    }
    printf("name argument = %s\n", argv[optind]);
    /* Other code omitted */
    exit(EXIT_SUCCESS);
}

getopt_long()

The following example program illustrates the use of getopt_long() with most of its features.

#include <getopt.h>
#include <stdio.h>     /* for printf */
#include <stdlib.h>    /* for exit */
int
main(int argc, char *argv[])
{
    int c;
    int digit_optind = 0;
    while (1) {
        int this_option_optind = optind ? optind : 1;
        int option_index = 0;
        static struct option long_options[] = {
            {"add",     required_argument, 0,  0 },
            {"append",  no_argument,       0,  0 },
            {"delete",  required_argument, 0,  0 },
            {"verbose", no_argument,       0,  0 },
            {"create",  required_argument, 0, 'c'},
            {"file",    required_argument, 0,  0 },
            {0,         0,                 0,  0 }
        };
        c = getopt_long(argc, argv, "abc:d:012",
                        long_options, &option_index);
        if (c == -1)
            break;
        switch (c) {
        case 0:
            printf("option %s", long_options[option_index].name);
            if (optarg)
                printf(" with arg %s", optarg);
            printf("\n");
            break;
        case '0':
        case '1':
        case '2':
            if (digit_optind != 0 && digit_optind != this_option_optind)
              printf("digits occur in two different argv-elements.\n");
            digit_optind = this_option_optind;
            printf("option %c\n", c);
            break;
        case 'a':
            printf("option a\n");
            break;
        case 'b':
            printf("option b\n");
            break;
        case 'c':
            printf("option c with value '%s'\n", optarg);
            break;
        case 'd':
            printf("option d with value '%s'\n", optarg);
            break;
        case '?':
            break;
        default:
            printf("?? getopt returned character code 0%o ??\n", c);
        }
    }
    if (optind < argc) {
        printf("non-option ARGV-elements: ");
        while (optind < argc)
            printf("%s ", argv[optind++]);
        printf("\n");
    }
    exit(EXIT_SUCCESS);
}
