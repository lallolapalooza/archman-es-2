NOMBRE

ossl-guide-libssl-introduction, ssl - Guía de OpenSSL: Una introducción a libssl

INTRODUCCIÓN

La biblioteca OpenSSL "libssl" proporciona implementaciones de varios protocolos de comunicación segura de red. Específicamente, proporciona SSL/TLS (SSLv3, TLSv1, TLSv1.1, TLSv1.2 y TLSv1.3), DTLS (DTLSv1 y DTLSv1.2) y QUIC (solo del lado del cliente). La biblioteca depende de "libcrypto" para sus operaciones criptográficas subyacentes (ver ossl-guide-libcrypto-introduction(7)).

El conjunto de APIs proporcionado por "libssl" es común para todos estos diferentes protocolos de red, por lo que un desarrollador familiarizado con la escritura de aplicaciones que utilizan uno de estos protocolos debería poder transitar a usar otro con relativa facilidad.

Una aplicación escrita para usar "libssl" incluirá el archivo de encabezado <openssl/ssl.h> y típicamente usará dos estructuras de datos principales, es decir, SSL y SSL_CTX.

Un objeto SSL se utiliza para representar una conexión a un par remoto. Una vez que se ha establecido una conexión con un par remoto, los datos pueden intercambiarse con ese par.

Cuando se utiliza DTLS, cualquier dato que se intercambia utiliza la semántica de "datagrama", es decir, los paquetes de datos pueden entregarse en cualquier orden y no se garantiza que lleguen. En este caso, el objeto SSL utilizado para la conexión también se utiliza para intercambiar datos con el par.

Tanto TLS como QUIC admiten el concepto de un "flujo" de datos. Los datos enviados a través de un flujo garantizan la entrega en orden sin pérdida de datos. Un flujo puede ser unidireccional o bidireccional.

SSL/TLS solo admite un flujo de datos por conexión y siempre es bidireccional. En este caso, el objeto SSL utilizado para la conexión también representa ese flujo. Ver ossl-guide-tls-introduction(7) para más información.

El protocolo QUIC puede admitir múltiples flujos por conexión y pueden ser unidireccionales o bidireccionales. En este caso, un objeto SSL puede representar la conexión subyacente, o un flujo, o ambos. Donde se utilizan múltiples flujos, se utiliza un objeto SSL separado para cada uno. Ver ossl-guide-quic-introduction(7) para más información.

Un objeto SSL_CTX se utiliza para crear el objeto SSL para la conexión subyacente. Un solo objeto SSL_CTX puede usarse para crear muchas conexiones (cada una representada por un objeto SSL separado). Muchas funciones de la API en libssl existen en dos formas: una que toma un SSL_CTX y otra que toma un SSL. Típicamente, las configuraciones que aplicas al SSL_CTX serán heredadas por cualquier objeto SSL que crees a partir de él. Alternativamente, puedes aplicar configuraciones directamente al objeto SSL sin afectar a otros objetos SSL. Ten en cuenta que normalmente no deberías realizar cambios en un SSL_CTX después de que se haya creado el primer objeto SSL a partir de él.

ESTRUCTURAS DE DATOS

Además de SSL_CTX y SSL, hay una serie de otras estructuras de datos que una aplicación puede necesitar usar. Se resumen a continuación.

SSL_METHOD (Método SSL)
Esta estructura se utiliza para indicar el tipo de conexión que deseas realizar, por ejemplo, si es para representar al cliente o al servidor, y si es para usar SSL/TLS, DTLS o QUIC. Se pasa como parámetro al crear el SSL_CTX.
SSL_SESSION (Sesión SSL)
Después de establecer una conexión con un par, el material criptográfico acordado puede reutilizarse para crear futuras conexiones con el mismo par de forma más rápida. El conjunto de datos utilizado para un intento de establecimiento de conexión futura se recopila en un objeto SSL_SESSION. Una única conexión exitosa con un par puede generar cero o más objetos SSL_SESSION para su uso en futuros intentos de conexión.
SSL_CIPHER (Cifrado SSL)
Durante el establecimiento de la conexión, el cliente y el servidor acuerdan los algoritmos criptográficos que van a utilizar para el cifrado y otros usos. Un conjunto único de algoritmos criptográficos que se van a utilizar juntos se conoce como un conjunto de cifrado (ciphersuite). Dicho conjunto está representado por un objeto SSL_CIPHER.

El conjunto de conjuntos de cifrado disponibles que se pueden utilizar se configura en el SSL_CTX o SSL.
