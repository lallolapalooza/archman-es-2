NOMBRE

ossl-guide-quic-server-non-block - Guía de OpenSSL: Escribiendo un servidor QUIC no bloqueante simple

EJEMPLO DE SERVIDOR QUIC NO BLOQUEANTE SIMPLE

Esta página presenta varios ejemplos de código que demuestran cómo escribir una aplicación de servidor QUIC "eco" simple y no concurrente, que acepta una conexión de cliente a la vez, devolviendo la entrada del cliente al mismo cliente. Una vez que el cliente actual se desconecta, se acepta la siguiente conexión de cliente.

El servidor solo acepta los ALPN "http/1.0" y "hq-interop" y en realidad no implementa HTTP, sino que solo realiza un simple eco. Esto no es estándar y no será compatible con servidores del mundo real. Esto es solo para fines demostrativos.

Hay varios métodos para probar este servidor: quic-client-block.c y quic-client-non-block.c enviarán una solicitud HTTP/1.0 básica, que el servidor devolverá. También puedes probar este servidor ejecutando "openssl s_client -connect localhost:4443 -4 -quic -alpn http/1.0" e introduciendo texto que el servidor devolverá.

Tanto el socket de escucha como el socket conectado son "no bloqueantes". Sin embargo, usamos select() para que el socket de escucha se bloquee cuando no puede leer/escribir. En lugar de detenerse y esperar, tu aplicación puede necesitar realizar otras tareas mientras el objeto SSL no puede leer/escribir. Por ejemplo: actualizar una GUI o realizar operaciones en alguna otra conexión o flujo.

El código fuente completo para este servidor QUIC no bloqueante de ejemplo está disponible en el directorio demos/guide de la distribución fuente de OpenSSL en el archivo quic-server-non-block.c. También está disponible en línea en https://github.com/openssl/openssl/blob/master/demos/guide/quic-server-non-block.c.

Suponemos que ya tienes OpenSSL instalado en tu sistema; que ya tienes una comprensión fundamental de los conceptos de OpenSSL y QUIC (ver ossl-guide-libraries-introduction(7) y ossl-guide-quic-introduction(7)); y que sabes cómo escribir y compilar código C y enlazarlo contra las bibliotecas libcrypto y libssl que proporciona OpenSSL. También asume que tienes una comprensión básica de UDP/IP y sockets.

Creación de los objetos SSL_CTX y SSL

El primer paso es crear un objeto SSL_CTX para nuestro servidor. Utilizamos la función SSL_CTX_new(3) para este propósito. Pasamos como argumento el valor de retorno de la función OSSL_QUIC_server_method(3). Debes usar este método siempre que estés escribiendo un servidor QUIC.

/*
 * Un SSL_CTX contiene información de configuración compartida para múltiples
 * conexiones SSL posteriores por cliente. Aquí cargamos específicamente un método
 * de servidor QUIC.
 */
ctx = SSL_CTX_new(OSSL_QUIC_server_method());
if (ctx == NULL)
    goto err;

Los servidores necesitan una clave privada y un certificado. A menudo se requieren certificados de CA emisores intermedios, y tanto el certificado del servidor (entidad final o EE) como los certificados del emisor ("cadena") se configuran más fácilmente en un único "archivo de cadena". A continuación, cargamos dicho archivo de cadena (el certificado EE debe aparecer primero), y luego cargamos la clave privada correspondiente, verificando que coincide con el certificado del servidor. No se realizan comprobaciones para verificar la integridad de la cadena (firmas de CA o fechas de caducidad de certificados, por ejemplo), pero sí verificamos la coherencia de la clave privada con el certificado correspondiente.

/*
 * Carga el archivo de cadena de certificado del servidor (formato PEM), que incluye
 * no solo el certificado del servidor hoja (entidad final), sino también cualquier
 * certificado de CA intermedio emisor. El certificado hoja debe ser el
 * primer certificado en el archivo.
 *
 * En casos de uso avanzados, esto se puede llamar varias veces, una por cada
 * algoritmo de clave pública para el cual el servidor tenga un certificado
 * correspondiente.
 * Sin embargo, la clave privada correspondiente (ver más abajo) debe cargarse primero,
 * *antes* de pasar al siguiente archivo de cadena.
 */
if (SSL_CTX_use_certificate_chain_file(ctx, cert_path) <= 0) {
    fprintf(stderr, "no se pudo cargar el archivo de certificado: %s\n", cert_path);
    goto err;
}
/*
 * Carga la clave privada correspondiente, esto también comprueba que la clave
 * privada coincide con el certificado de entidad final recién cargado. No comprueba
 * si la cadena de certificados es válida, los certificados podrían estar
 * caducados, o podrían no formar una cadena que un cliente pueda
 * validar.
 */
if (SSL_CTX_use_PrivateKey_file(ctx, key_path, SSL_FILETYPE_PEM) <= 0) {
    fprintf(stderr, "no se pudo cargar el archivo de clave: %s\n", key_path);
    goto err;
}

La mayoría de los servidores, incluido este, no solicitan certificados de cliente. Por lo tanto, no necesitamos un "almacén de confianza" y permitimos que el handshake se complete incluso cuando el cliente no presenta un certificado. Nota: Incluso si un cliente presentara un certificado de confianza, para que sea útil, la aplicación del servidor aún necesitaría código personalizado para usar la identidad verificada para otorgar acceso no predeterminado a ese cliente en particular. Algunos servidores otorgan acceso a todos los clientes con certificados de una CA privada, esto requiere el procesamiento de listas de revocación de certificados para desautorizar a un cliente. A menudo es más simple y seguro mantener una lista de claves públicas autorizadas.

Aunque esta es la configuración predeterminada, llamamos explícitamente a la función SSL_CTX_set_verify(3) y le pasamos el valor SSL_VERIFY_NONE. El último argumento de esta función es una función de devolución de llamada que puedes proporcionar opcionalmente para anular el manejo predeterminado para la verificación de certificados. La mayoría de las aplicaciones no necesitan hacer esto, por lo que se puede establecer de forma segura en NULL para obtener el manejo predeterminado.

/*
 * Los clientes rara vez emplean autenticación basada en certificados, por lo que no
 * requerimos autenticación TLS "mutua" (de hecho, no hay forma de saber
 * si y cómo el cliente autenticó al servidor, por lo que el término "mutuo"
 * es potencialmente engañoso).
 *
 * Dado que no solicitamos ni procesamos certificados de cliente, no
 * necesitamos configurar un almacén de certificados de confianza, por lo que no se
 * necesita una llamada a SSL_CTX_set_default_verify_paths(). Se asume que la
 * cadena de certificados del servidor es válida.
 */
SSL_CTX_set_verify(ctx, SSL_VERIFY_NONE, NULL);

QUIC también dicta el uso de la Negociación de Protocolos de Capa de Aplicación (ALPN) para seleccionar un protocolo de aplicación. Utilizamos SSL_CTX_set_alpn_select_cb(3) para este propósito. Podemos pasar una función de devolución de llamada que se llamará para cada conexión para seleccionar un ALPN que el servidor considere aceptable.

/* Configura la devolución de llamada de negociación ALPN para decidir qué ALPN se acepta. */
SSL_CTX_set_alpn_select_cb(ctx, select_alpn, NULL);

En este caso, solo aceptamos "http/1.0" y "hq-interop".

/*
* Cadenas ALPN para el handshake TLS. Solo se aceptan 'http/1.0' y 'hq-interop'.
*/
static const unsigned char alpn_ossltest[] = {
    8,  'h', 't', 't', 'p', '/', '1', '.', '0',
    10, 'h', 'q', '-', 'i', 'n', 't', 'e', 'r', 'o', 'p',
};
static int select_alpn(SSL *ssl, const unsigned char **out,
                       unsigned char *out_len, const unsigned char *in,
                       unsigned int in_len, void *arg)
{
    if (SSL_select_next_proto((unsigned char **)out, out_len, alpn_ossltest,
                              sizeof(alpn_ossltest), in,
                              in_len) == OPENSSL_NPN_NEGOTIATED)
        return SSL_TLSEXT_ERR_OK;
    return SSL_TLSEXT_ERR_ALERT_FATAL;
}

Eso es todo lo que necesitamos configurar para el SSL_CTX. A continuación, creamos un socket UDP y lo enlazamos a localhost.

/* Recupera el descriptor de archivo para un nuevo socket UDP */
if ((fd = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP)) < 0) {
    fprintf(stderr, "no se puede crear el socket");
    return -1;
}
sa.sin_family = AF_INET;
sa.sin_port = htons(port);
/* Enlaza al nuevo socket UDP en localhost */
if (bind(fd, (const struct sockaddr *)&sa, sizeof(sa)) < 0) {
    fprintf(stderr, "no se puede enlazar a %u\n", port);
    BIO_closesocket(fd);
    return -1;
}
/* Establece el puerto en modo no bloqueante */
if (BIO_socket_nbio(fd, 1) <= 0) {
    fprintf(stderr, "no se puede establecer el puerto en modo no bloqueante");
    BIO_closesocket(fd);
    return -1;
}

Para ejecutar el servidor QUIC, creamos un SSL_LISTENER para escuchar las conexiones entrantes. Le proporcionamos el puerto UDP enlazado para que comience explícitamente a escuchar nuevas conexiones.

/* Crea un nuevo

QUIC listener

/* QUIC listener */
if ((listener = SSL_new_listener(ctx, 0)) == NULL)
    goto err;
/* Provide the listener with our UDP socket. */
if (!SSL_set_fd(listener, fd))
    goto err;
/* Set the listener mode to nonblocking, which is inherited by
 * child objects.
 */
if (!SSL_set_blocking_mode(listener, 0))
    goto err;
/*
 * Begin listening. Note that is not usually needed as SSL_accept_connection
 * will implicitly start listening. It is only needed if a server wishes to
 * ensure it has started to accept incoming connections but does not wish to
 * actually call SSL_accept_connection yet.
 */
if (!SSL_listen(listener))
    goto err;

Bucle del servidor

El servidor entra ahora en un bucle "infinito", gestionando una conexión de cliente a la vez. Antes de cada conexión, limpiamos la pila de errores de OpenSSL para que cualquier informe de error se relacione solo con la nueva conexión.

/* Pristine error stack for each new connection */
ERR_clear_error();

Luego esperamos hasta que una conexión esté lista para ser leída. Utiliza la función select para esperar hasta que el socket sea legible o escribible, dependiendo de lo que requiera la conexión SSL.

A continuación, aceptamos una nueva conexión en la que el handshake ya se habrá producido. Sin embargo, como estamos en modo no bloqueante, SSL_accept_connection(3) devolverá inmediatamente. Por lo tanto, utilizamos una función auxiliar para bloquear esencialmente hasta que se establezca una conexión.

printf("Waiting for connection\n");
while ((conn = SSL_accept_connection(listener, 0)) == NULL) {
    wait_for_activity(listener);
}
printf("Accepted new connection\n");

La función auxiliar wait_for_activity utiliza select() para bloquear hasta que el descriptor de archivo perteneciente al objeto SSL pasado sea legible. Como se mencionó anteriormente, una aplicación del mundo real probablemente usaría este tiempo para realizar otras tareas.

/* Initialize the fd_set structure */
FD_ZERO(&read_fd);
FD_ZERO(&write_fd);
/*
 * Determine if we would like to write to the socket, read from it, or both.
 */
if (SSL_net_write_desired(ssl))
    FD_SET(sock, &write_fd);
if (SSL_net_read_desired(ssl))
    FD_SET(sock, &read_fd);
/*
 * Find out when OpenSSL would next like to be called, regardless of
 * whether the state of the underlying socket has changed or not.
 */
if (SSL_get_event_timeout(ssl, &tv, &isinfinite) && !isinfinite)
    tvp = &tv;
/*
 * Wait until the socket is writeable or readable. We use select here
 * for the sake of simplicity and portability, but you could equally use
 * poll/epoll or similar functions
 *
 * NOTE: For the purposes of this demonstration code this effectively
 * makes this demo block until it has something more useful to do. In a
 * real application you probably want to go and do other work here (e.g.
 * update a GUI, or service other connections).
 *
 * Let's say for example that you want to update the progress counter on
 * a GUI every 100ms. One way to do that would be to use the timeout in
 * the last parameter to "select" below. If the tvp value is greater
 * than 100ms then use 100ms instead. Then, when select returns, you
 * check if it did so because of activity on the file descriptors or
 * because of the timeout. If the 100ms GUI timeout has expired but the
 * tvp timeout has not then go and update the GUI and then restart the
 * "select" (with updated timeouts).
 */
select(sock + 1, &read_fd, &write_fd, NULL, tvp);

Con el handshake completo, el servidor lee toda la entrada del cliente.

/* Read from client until the client sends a end of stream packet */
while (!eof) {
    ret = SSL_read_ex(conn, buf + total_read, sizeof(buf) - total_read,
                      &nread);
    total_read += nread;
    if (total_read >= 8192) {
        fprintf(stderr, "Could not fit all data into buffer\n");
        goto err;
    }
    switch (handle_io_failure(conn, ret)) {
    case 1:
        continue; /* Retry */
    case 0:
        /* Reached end of stream */
        if (!SSL_has_pending(conn))
            eof = 1;
        break;
    default:
        fprintf(stderr, "Failed reading remaining data\n");
        goto err;
    }
}

Finalmente, devolvemos los datos recibidos al cliente. Podemos usar SSL_write_ex2(3) para pasar un indicador especial SSL_WRITE_FLAG_CONCLUDE que enviará un paquete FIN una vez que la escritura haya terminado de escribir con éxito todos los datos al par.

/* Echo client input */
while (!SSL_write_ex2(conn, buf,
                      total_read,
                      SSL_WRITE_FLAG_CONCLUDE, &total_written)) {
    if (handle_io_failure(conn, 0) == 1)
        continue;
    fprintf(stderr, "Failed to write data\n");
    goto err;
}

Luego cerramos la conexión con SSL_shutdown(3), que puede necesitar ser llamada varias veces para asegurar que la conexión se cierre completamente.

/*
 * Shut down the connection. We may need to call this multiple times
 * to ensure the connection is shutdown completely.
 */
while ((ret = SSL_shutdown(conn)) != 1) {
    if (ret < 0 && handle_io_failure(conn, ret) == 1)
        continue; /* Retry */
}

Finalmente, liberamos la conexión SSL, y el servidor está ahora listo para aceptar la siguiente conexión de cliente.

SSL_free(conn);

Limpieza final

Si el servidor, de alguna manera, logra salir del bucle infinito y está listo para salir, deasignaría el SSL construido.

SSL_free(listener);

Y en la función principal, deasignaría el SSL_CTX construido.

SSL_CTX_free(ctx);
BIO_closesocket(fd);
