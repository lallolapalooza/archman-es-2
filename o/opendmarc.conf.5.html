opendmarc.conf(5) Manual de Formatos de Archivo opendmarc.conf(5)

NOMBRE

opendmarc.conf - Archivo de configuración para opendmarc

UBICACIÓN

/etc/opendmarc/opendmarc.conf

DESCRIPCIÓN

opendmarc(8) implementa la especificación DMARC propuesta para autenticación de mensajes, aplicación de políticas e informes. Este archivo es su archivo de configuración.

Las líneas en blanco se ignoran. Las líneas que contienen un carácter de almohadilla ("#") se truncan en el carácter de almohadilla para permitir comentarios en el archivo.

Otro contenido debe ser el nombre de un parámetro, seguido de espacios en blanco, seguido del valor de ese parámetro, cada uno en una línea separada.

Para parámetros que son booleanos por naturaleza, solo se procesa el primer byte del valor. Para valores positivos, se aceptan los siguientes: "T", "t", "Y", "y", "1". Para valores negativos, se aceptan los siguientes: "F", "f", "N", "n", "0".

Algunos, pero no todos, de estos parámetros también están disponibles como opciones de línea de comandos para opendmarc(8). Sin embargo, generalmente no se agregan nuevos parámetros como opciones de línea de comandos, por lo que el conjunto completo de opciones está disponible aquí, y por lo tanto se fomenta el uso del archivo de configuración. En alguna versión futura, es probable que el conjunto de opciones de línea de comandos disponibles se reduzca.

Consulte la página del manual de opendmarc(8) para obtener detalles sobre cómo y cuándo se recargan los contenidos del archivo de configuración.

A menos que se indique lo contrario, los valores booleanos predeterminados son "falso", los valores enteros predeterminados son 0, y las cadenas y los conjuntos de datos predeterminados no están definidos.

PARÁMETROS

AuthservID (cadena)
Establece el "authserv-id" a utilizar al generar el campo de encabezado Authentication-Results: después de verificar un mensaje. El valor predeterminado es usar el nombre del MTA que procesa el mensaje. Si se proporciona la cadena "HOSTNAME", se utilizará el nombre del host que ejecuta el filtro (tal como lo devuelve la función gethostname(3)).
AuthservIDWithJobID (booleano)
Si es "verdadero", solicita que la parte authserv-id de los campos de encabezado Authentication-Results: agregados contengan el ID del trabajo del mensaje que se está evaluando.
AutoRestart (booleano)
Reinicia automáticamente en caso de fallos. Úselo con precaución; si el filtro falla instantáneamente después de iniciarse, esto puede causar un bucle estrecho de fork(2).
AutoRestartCount (entero)
Establece el recuento máximo de reinicios automáticos. Después de este número de reinicios automáticos, el filtro se rendirá y terminará. Un valor de 0 implica que no hay límite; este es el valor predeterminado.
AutoRestartRate (cadena)
Establece la tasa máxima de reinicios automáticos. Si el filtro comienza a reiniciarse más rápido que la tasa definida aquí, se rendirá y terminará. Es una cadena de la forma n/t[u] donde n es un entero que limita el recuento de reinicios en el intervalo dado y t[u] define el intervalo de tiempo a través del cual se calcula la tasa; t es un entero y u define las unidades representadas ("s" o "S" para segundos, el valor predeterminado; "m" o "M" para minutos; "h" o "H" para horas; "d" o "D" para días). Por ejemplo, un valor de "10/1h" limita los reinicios a 10 en una hora. No hay valor predeterminado, lo que significa que la tasa de reinicio no está limitada.
Background (booleano)
Hace que opendmarc se bifurque y salga inmediatamente, dejando el servicio ejecutándose en segundo plano. El valor predeterminado es "verdadero".
BaseDirectory (cadena)
Si se establece, instruye al filtro a cambiar al directorio especificado usando chdir(2) antes de hacer cualquier otra cosa. Esto significa que los archivos a los que se hace referencia en otras partes del archivo de configuración se pueden especificar en relación con este directorio. También es útil para organizar que cualquier volcado de fallos se guarde en una ubicación específica.
ChangeRootDirectory (cadena)
Solicita que el sistema operativo cambie el directorio raíz efectivo del proceso al especificado aquí antes de comenzar la ejecución. chroot (2) requiere acceso de superusuario. Se generará una advertencia si UserID tampoco está establecido.
CopyFailuresTo (cadena)
Agrega el destinatario especificado al sobre del mensaje si falla la evaluación DMARC.
DomainWhitelist (cadena)
Una lista breve de dominios en lista blanca para los cuales los encabezados de firma ARC son confiables según la evaluación de las entradas en el campo "arc.chain" que se encuentra en un encabezado Authentication-Results generado localmente.

Esta lista se concatenará con DomainWhitelistFile (si se proporciona).

DomainWhitelistFile (cadena)
Una lista completa de dominios en lista blanca para los cuales los encabezados de firma ARC son confiables según la evaluación de las entradas en el campo "arc.chain" que se encuentra en un encabezado Authentication-Results generado localmente.

Esta lista se concatenará con DomainWhitelist (si se proporciona).

DomainWhitelistSize (entero)
Establece la capacidad de la estructura de datos de dominios en lista blanca. El valor especifica el número máximo de entradas, incluidos los dominios listados en el parámetro de configuración DomainWhitelist y los dominios listados en DomainWhiteListFile. El tamaño final se incrementará en aproximadamente un 20% para aumentar la eficiencia del algoritmo de hash.
DNSTimeout (entero)
Establece el tiempo de espera de DNS en segundos. Un valor de 0 provoca una espera infinita. El valor predeterminado es 5. Se ignora si no se utiliza un paquete de resolución asíncrono.
EnableCoredumps (booleano)
En sistemas que tienen dicho soporte, haga una solicitud explícita al kernel para volcar núcleos si el filtro falla por alguna razón. Algunos sistemas UNIX modernos suprimen los volcados de núcleos durante los fallos por razones de seguridad si el ID de usuario ha cambiado durante la vida útil del proceso. Actualmente solo se admite en Linux.
FailureReports (booleano)
Habilita la generación de informes de fallos cuando falla la prueba DMARC y el remitente supuesto del mensaje ha solicitado dichos informes. Los informes se formatean según RFC6591.
FailureReportsBcc (cadena)
Cuando los informes de fallos están habilitados y se va a generar uno, siempre envíelo a las direcciones especificadas aquí. Si el propietario del dominio solicita un informe de fallos, las direcciones se agregan en un campo Bcc:. Si no se realiza ninguna solicitud, las direcciones se utilizan en un campo To:. No hay valor predeterminado.
FailureReportsOnNone (booleano)
Complementario a la configuración anterior, habilita la generación de informes de fallos para dominios de envío que publican una política de "ninguno".
FailureReportsSentBy (cadena)
Establece el valor del campo From: que se utilizará al enviar informes de fallos (ver arriba). El valor predeterminado es usar el ID de usuario del usuario que ejecuta el filtro y el nombre del host local para construir una dirección de correo electrónico.
HistoryFile (cadena)
Si se establece, especifica la ubicación de un archivo de texto al que se registrarán los registros

DESCRIPCIÓN

El milter de opendmarc proporciona un servicio de filtrado de correo para la autenticación de DMARC. Evalúa los resultados de SPF y DKIM y aplica las directivas de DMARC (si las hay) publicadas por el dominio del remitente. También puede generar informes de agregación DMARC para su análisis posterior.

OPCIONES DE CONFIGURACIÓN

opendmarc se puede configurar mediante un archivo de configuración o especificando opciones en la línea de comandos. Las opciones de configuración son las siguientes:

AuthservID (string)
Proporciona una cadena de identificación para el servidor de autenticación que se incluirá en el encabezado Authentication-Results que se añade a los mensajes. El valor predeterminado es el nombre del host del sistema. Si no se proporciona, los informes de agregación pueden no incluir información sobre el servidor de autenticación.
AuthservID (string)
Proporciona una cadena de identificación para el servidor de autenticación que se incluirá en el encabezado Authentication-Results que se añade a los mensajes. El valor predeterminado es el nombre del host del sistema. Si no se proporciona, los informes de agregación pueden no incluir información sobre el servidor de autenticación.
FailureReports (Boolean)
Si se establece en "true", se generarán informes de fallos y se enviarán a la dirección especificada en el registro DMARC del remitente. Por defecto es "false".
Failure-mode (string)
Define cómo debe responder el filtro si no se puede completar la evaluación de DMARC. Los valores posibles son "immediate" y "report". El valor predeterminado es "report", que significa que se registrará el fallo pero el mensaje se seguirá procesando. "immediate" hará que el mensaje sea rechazado o temporalmente fallado.
FilterReporters (Boolean)
Si se establece en "true", el filtro intentará identificar y filtrar los informes de abuso o retroalimentación de remitentes conocidos de informes de abuso. El valor predeterminado es "false".
HistoryFile (string)
Especifica la ruta de un archivo en el que se registrarán los resultados de las autenticaciones de correo electrónico. Este archivo se utiliza para generar informes de agregación DMARC. El formato del archivo es una colección de registros, cada uno de los cuales representa un mensaje recibido y se compone de una serie de filas que comienzan con una letra que indica el tipo de registro. Los registros son lotes de filas que contienen información sobre un solo mensaje recibido e incluyen toda la información relevante necesaria para generar un informe de agregación DMARC. Se espera que esto no se utilice en su forma bruta, sino que se importe periódicamente en una base de datos relacional de la que se puedan extraer los informes de agregación utilizando opendmarc-importstats(8).
HoldQuarantinedMessages (Boolean)
Si se establece, el milter indicará al mta que los mensajes con p=quarantine, que fallan la autenticación dmarc, deben mantenerse en la cola "Hold" o "Quarantine" del MTA. El nombre varía según el MTA. Si es falso, los mensajes se aceptarán y se pasarán junto con el flujo de correo normal, y la cuarentena se dejará a los filtros MTA/MDA/MUA posteriores, si los hay, para que la manejen reevaluando los encabezados, incluido el encabezado Authentication-Results añadido por este filtro. El valor predeterminado es "false".
HoldQuarantinedMessages (Boolean)
Si se establece, el milter indicará al mta que los mensajes con p=quarantine, que fallan la autenticación dmarc, deben mantenerse en la cola "Hold" o "Quarantine" del MTA. El nombre varía según el MTA. Si es falso, los mensajes se aceptarán y se pasarán junto con el flujo de correo normal, y la cuarentena se dejará a los filtros MTA/MDA/MUA posteriores, si los hay, para que la manejen reevaluando los encabezados, incluido el encabezado Authentication-Results añadido por este filtro. El valor predeterminado es "false".
IgnoreAuthenticatedClients (Boolean)
Si se establece, hace que el filtro ignore el correo de clientes autenticados (es decir, aquellos que utilizaron SMTP AUTH). El valor predeterminado es "false".
IgnoreHosts (string)
Especifica la ruta a un archivo que contiene una lista de nombres de host, direcciones IP y/o expresiones CIDR que identifican los hosts cuyas conexiones SMTP deben ser ignoradas por el filtro. Si no se especifica, por defecto solo se ignora "127.0.0.1".
IgnoreMailFrom (string)
Proporciona una lista de nombres de dominio cuyo correo (basado en el dominio From:) debe ser ignorado por el filtro. La lista debe estar separada por comas. La coincidencia con esta lista no distingue entre mayúsculas y minúsculas. El valor predeterminado es una lista vacía, lo que significa que no se ignora ningún correo.
MilterDebug (integer)
Establece el nivel de depuración que se solicitará a la biblioteca milter. El valor predeterminado es 0.
PidFile (string)
Especifica la ruta a un archivo que debe crearse al inicio del proceso y que contendrá el ID del proceso.
PublicSuffixList (string)
Especifica la ruta a un archivo que contiene dominios de nivel superior (TLD) que se utilizarán para calcular el Dominio Organizacional de un nombre de dominio dado, como se describe en la especificación DMARC. Si no se proporciona, el filtro no podrá determinar el Dominio Organizacional y solo se evaluará el dominio presentado. Este archivo debe actualizarse periódicamente. Una ubicación para recuperar el archivo es https://publicsuffix.org/list/
RecordAllMessages (Boolean)
Si se establece y se está utilizando HistoryFile, todos los mensajes recibidos se registrarán en el archivo de historial. Si no se establece (por defecto), solo se registrarán en el archivo de historial los mensajes para los que el dominio From: publicó un registro DMARC.
RejectFailures (Boolean)
Si se establece, los mensajes serán rechazados si fallan la evaluación DMARC, o fallarán temporalmente si la evaluación no se pudo completar. Por defecto, ningún mensaje será rechazado o fallará temporalmente independientemente del resultado de la evaluación DMARC del mensaje. En su lugar, se añadirá un campo de encabezado Authentication-Results. El valor predeterminado es "false".
RejectMultiValueFrom (Boolean)
Si se establece, los mensajes con múltiples direcciones en el campo From: del mensaje serán rechazados a menos que todos los nombres de dominio en ese campo sean los mismos. De lo contrario, serán ignorados por el filtro (por defecto).
ReportCommand (string)
Indica el comando del shell al que se deben pasar los informes de fallos para su entrega cuando FailureReports está habilitado. Por defecto es /usr/sbin/sendmail.
RequiredHeaders (Boolean)
Si se establece, el filtro se asegurará de que el encabezado del mensaje cumpla con las restricciones básicas de recuento de campos de encabezado establecidas en RFC5322, Sección 3.6. Los mensajes que fallen esta prueba se rechazarán sin más procesamiento. También se rechazará un campo From: del que no se pueda extraer ningún nombre de dominio.
Socket (string)
Especifica el socket que debe establecer el filtro para recibir conexiones de sendmail(8) para proporcionar servicio. socketspec tiene una de dos formas: local:ruta, que crea un socket de dominio UNIX en la ruta especificada, o inet:puerto[@host] o inet6:puerto[@host], que crea un socket TCP en el puerto especificado para la familia de protocolos apropiada. Si el host no se proporciona como nombre de host o dirección IP, el socket escuchará en todas las interfaces. Esta opción es obligatoria, ya sea en el archivo de configuración o en la línea de comandos. Si se utiliza una dirección IP, debe ir entre corchetes.
SoftwareHeader (Boolean)
Hace que opendmarc añada un campo de encabezado "DMARC-Filter" que indique la presencia de este filtro en la ruta del mensaje desde la inyección hasta la entrega. El nombre del producto, la versión y el ID del trabajo se incluyen en el contenido del campo de encabezado.
SPFIgnoreResults (Boolean)
Hace que el filtro ignore los resultados de SPF en el encabezado del mensaje. Esto es útil si desea que el filtro realice las comprobaciones de SPF por sí mismo, o porque no confía en el encabezado entrante. El valor predeterminado es "false".
SPFSelfValidate (Boolean)
Hace que el filtro realice una comprobación de SPF de reserva por sí mismo cuando no encuentra resultados de SPF en el encabezado del mensaje. Si también se establece SPFIgnoreResults, nunca busca resultados de SPF en los encabezados y siempre realiza la comprobación de SPF por sí mismo cuando esto está establecido. El valor predeterminado es "false".
Syslog (Boolean)
Registra mediante llamadas a syslog(3) cualquier actividad interesante.
SyslogFacility (string)
Registra mediante llamadas a syslog(3) utilizando la instalación designada. Los nombres de las instalaciones son los mismos que los permitidos en syslog.conf(5). El valor predeterminado es "mail".
TrustedAuthservIDs (string)
Proporciona una lista de authserv-ids que se utilizarán para identificar los campos de encabezado Authentication-Results cuyo contenido se asumirá como entrada válida para la evaluación DMARC. Para proporcionar una lista, separe los valores por comas. Si se proporciona la cadena "HOSTNAME", se utilizará el nombre del host que ejecuta el filtro (según lo devuelva la función gethostname(3)). La coincidencia con esta lista no distingue entre mayúsculas y minúsculas. El valor predeterminado es usar el valor de AuthservID.
UMask (integer)
Solicita una máscara de permisos específica que se utilizará para la creación de archivos. Esto solo se aplica realmente a la creación del socket cuando Socket especifica un socket de dominio UNIX, y al PidFile (si lo hay); los archivos temporales se crean mediante la función mkstemp(3) que aplica un modo de archivo específico en la creación independientemente de la máscara umask del proceso. Consulte umask(2) para obtener más información.
UserID (string)
Intenta convertirse en el usuario especificado antes de iniciar las operaciones. El valor tiene el formato usuario[:grupo]. Al proceso se le asignarán todos los grupos y el ID de grupo principal del usuario especificado, a menos que se especifique un grupo alternativo.
