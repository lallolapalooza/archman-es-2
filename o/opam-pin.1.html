NOMBRE

opam-pin - Fijar un paquete dado a una versión o fuente específica.

SINOPSIS

opam pin [OPCIÓN]… [COMANDO] [ARG]…

DESCRIPCIÓN

Este comando permite la personalización local de los paquetes en un entorno de ejecución dado. Una fijación puede simplemente forzar una versión dada, o proporcionar una versión local y editable de la definición del paquete. También es posible crear un nuevo paquete simplemente fijando un nombre de paquete inexistente.

Cualquier personalización está disponible a través del subcomando edit, pero la línea de comandos ofrece facilidad para alterar la URL de la fuente del paquete, ya que es el uso más común: opam pin add PKG URL modifica el paquete PKG para obtener su fuente desde URL. Si se encuentra una definición de paquete en el árbol de fuentes del paquete, se utilizará localmente.

Si se especifica (o -), el paquete se fija sin un archivo de fuente. El nombre del paquete puede omitirse si el objetivo es un directorio que contiene una o más definiciones de paquetes válidas (esto permite hacer, por ejemplo, opam pin add . desde un directorio de fuentes).

Si PAQUETE tiene el formato nombre.versión, el paquete fijado se considerará de la versión versión por opam. Tenga en cuenta que esto no está relacionado con la versión de la fuente que se utiliza realmente para el paquete. Ver también la opción --with-version.

El subcomando predeterminado es list si no hay más argumentos, y add en caso contrario si es inequívoco.

COMANDOS

Sin argumento, el valor predeterminado es list.

list
Lista los paquetes fijados. Si la fuente es un repositorio remoto, muestra el hash que representa su estado.
scan DIR
Lista los paquetes disponibles para fijar en el directorio.
add PAQUETE OBJETIVO
Fija el paquete PAQUETE a OBJETIVO, que puede ser una versión, una ruta o una URL. PAQUETE puede omitirse si OBJETIVO contiene una o más descripciones de paquetes. OBJETIVO puede reemplazarse por --dev-repo si ya se conoce un paquete con ese nombre, o --current si el paquete ya está instalado. Si OBJETIVO es -, el paquete se fija como un paquete virtual, sin ninguna fuente. opam inferirá el tipo de fijación a partir del formato (y contenido, si es local) de OBJETIVO. Utilice --kind o una URL explícita para desactivar ese comportamiento. Las fijaciones a sistemas de control de versiones pueden apuntar a una rama o commit específico usando #rama, por ejemplo git://host/me/pkg#testing. Si PAQUETE no es un nombre de paquete conocido, se creará un nuevo paquete con ese nombre localmente. Para fijaciones de fuentes, la versión del paquete puede especificarse usando el formato NOMBRE.VERSIÓN para PAQUETE, en el archivo opam de la fuente, o con edit.
remove PAQUETES...|OBJETIVO
Elimina la fijación de los paquetes PAQUETES, restaurando su definición desde el repositorio, si existe. Con un OBJETIVO, elimina la fijación de todo lo que esté fijado actualmente a ese objetivo.
edit NOMBRE
Abre un editor que le da la oportunidad de cambiar la definición del paquete que opam utilizará localmente para el paquete NOMBRE, incluyendo su versión y URL de fuente. Usar el formato NOMBRE.VERSIÓN actualizará la versión en el archivo opam por adelantado, sin cambiar el objetivo real. El editor elegido se determina a partir de las variables de entorno OPAMEDITOR, VISUAL o EDITOR, en ese orden.

OPCIONES

--all
Al eliminar fijaciones, elimina todas las fijaciones en el entorno de ejecución dado.
--current
Al fijar, utiliza la versión e metadatos actualmente instalados del paquete: esto evitará reinstalaciones debido a cambios en los metadatos originales, y también puede usarse para mantener un paquete que fue eliminado originalmente.
--dev-repo
Fija a la fuente de paquete original para la última versión de desarrollo.
-e, --edit
Con opam pin add, edita el archivo opam como con `opam pin edit' después de fijar.
-k TIPO, --kind=TIPO
Establece el tipo de fijación. Debe ser uno de los siguientes: version, path, http, git, darcs, hg, none o auto. Si no se establece o es auto, se infiere del formato del objetivo, siendo el valor predeterminado el sistema de control de versiones apropiado si se detecta uno en el directorio dado, o path en caso contrario. OPAMPINKINDAUTO puede establecerse a "0" para deshabilitar la detección automática de control de versiones. Use none para fijar sin un objetivo (para paquetes virtuales).
-n, --no-action
Solo registra el nuevo estado de fijación, y no solicita (re)instalación o eliminación de paquetes afectados.
--normalise
Imprime la lista de paquetes disponibles para fijar en el formato `nombre.version^url`, que es comprensible por `opam pin add`. Disponible solo con el subcomando scan. Un ejemplo de uso es `opam pin scan . --normalise | grep foo | xargs opam pin add`
--recursive
Permite búsquedas recursivas de archivos *.opam. Cf. --subpath también.
-s, --short
Salida de listas de nombres en bruto, uno por línea, omitiendo cualquier detalle.
--subpath=RUTA
Los archivos *.opam se recuperan del subdirectorio dado en lugar del directorio principal. Las fuentes se toman entonces del subdirectorio seleccionado; internamente, solo se copia/descarga este subdirectorio. Se puede combinar con --recursive para tener una búsqueda recursiva en el subdirectorio.
--with-version=VERSIÓN
Establece la versión de fijación a VERSIÓN para los PAQUETES nombrados o para los paquetes recuperados de OBJETIVO. Tiene prioridad sobre cualquier otra especificación de versión (campo de versión del archivo opam, argumento nombre.vers). Al fijar a una versión, se utiliza la fuente del paquete de esa versión, pero se declara como VERSIÓN para opam. Usar --with-version es equivalente a usar --edit y ajustar la versión en el archivo de definición del paquete.

OPCIONES DE COMPILACIÓN DE PAQUETES

--assume-depexts
Omite el paso de instalación para cualquier paquete del sistema faltante, e intenta continuar con la compilación de los paquetes opam de todos modos. Si la instalación tiene éxito, opam no volverá a preguntar sobre estos paquetes del sistema. Solo tiene significado si el manejo de dependencias externas está habilitado.
-b, --keep-build-dir
Mantiene los directorios de compilación después de compilar los paquetes. Esto es equivalente a establecer $OPAMKEEPBUILDDIR a "true".
--build-doc
Eliminado en 2.1, use --with-doc en su lugar.
--build-test
Eliminado en 2.1, use --with-test en su lugar.
-d, --with-doc
Compila la documentación del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Es equivalente a establecer $OPAMWITHDOC (o el obsoleto $OPAMBUILDDOC) a "true".
--dry-run
Simula el comando, pero no realiza ninguna acción real. Esto también puede configurarse con la variable de entorno $OPAMDEBUG.
--fake
Esta opción registra las acciones en la base de datos de opam, sin realizarlas. ADVERTENCIA: Esta opción es peligrosa y es probable que rompa su entorno de opam. Probablemente quiera --dry-run. Ha sido advertido.
--ignore-constraints-on[=PAQUETES] (valor predeterminado=)
Fuerza a opam a ignorar las restricciones de versión en todas las dependencias de los paquetes listados. Esto se puede usar para probar la compatibilidad, pero se espera que las compilaciones fallen al usar esto. Tenga en cuenta que la disponibilidad de los paquetes, así como las restricciones de versión en dependencias opcionales y conflictos, no se ven afectados. Esto es equivalente a establecer $OPAMIGNORECONSTRAINTS.
--inplace-build
Al compilar un paquete cuya fuente está vinculada a un directorio local, procesa las acciones de compilación e instalación directamente en ese directorio, en lugar de hacerlo en una copia limpia gestionada por opam. Esto solo afecta a los paquetes que se listan explícitamente en la línea de comandos. Esto

OPTIONS

--keep-build-dir
Keep build directories after successful builds. This is useful for debugging. This is equivalent to setting $OPAMKEEPBUILDDIR to "true".
--in-place
In-place builds are builds that happen directly in the source tree. This is equivalent to setting $OPAMINPLACEBUILD a "true".
-j JOBS, --jobs=JOBS
Establece el número máximo de trabajos concurrentes a utilizar. El valor por defecto se calcula a partir del número de núcleos. También se puede establecer utilizando la variable de entorno $OPAMJOBS.
--lock-suffix=SUFIJO (ausente=locked)
Establece el sufijo de los archivos bloqueados a SUFIJO.
--locked
En comandos que utilizan archivos opam encontrados en fuentes fijadas, si se encuentra una variante del archivo con una extensión .locked añadida (por ejemplo, foo.opam.locked además de foo.opam), se usará esa en su lugar. Esto es típicamente útil para ofrecer un conjunto más específico de dependencias y reproducir contextos de compilación similares, de ahí el nombre. La opción lock puede ser usada para generar dichos archivos, basándose en las versiones de las dependencias actualmente instaladas en el host. Esto es equivalente a establecer la variable de entorno $OPAMLOCKED. Tenga en cuenta que esta opción generalmente no afecta a los paquetes ya fijados.
-m MAKE, --make=MAKE
Eliminado en la versión 2.1, use opam config set[-global] make MAKE en su lugar.
--no-checksums
No verifique la suma de control de los archivos descargados. Esto es equivalente a establecer $OPAMNOCHECKSUMS a "true".
--no-depexts
Deshabilita temporalmente el manejo de dependencias externas. Esto puede ser utilizado si un paquete no está disponible en el gestor de paquetes de su sistema, pero instaló la dependencia requerida manualmente. Implica --assume-depexts, y también almacena las excepciones en caso de éxito.
--require-checksums
Rechace la instalación de paquetes que no proporcionen una suma de control para los archivos de origen. Esto es equivalente a establecer $OPAMREQUIRECHECKSUMS a "true".
--reuse-build-dir
Reutilice los directorios de compilación existentes (mantenidos usando --keep-build-dir), en lugar de compilar desde una copia fresca del código fuente. Esto puede ser más rápido, pero también puede llevar a fallos si los sistemas de compilación de los paquetes no manejan bien las actualizaciones de dependencias. Esto es equivalente a establecer $OPAMREUSEBUILDDIR a "true".
--show-actions
Llame al solucionador y muestre las acciones. No realice ningún cambio. Esto es equivalente a establecer $OPAMSHOW.
--skip-updates
Al ejecutar una instalación, actualización o reinstalación en paquetes fijados desde el código fuente, normalmente se actualizan desde su origen primero. Esta bandera deshabilita ese comportamiento y los mantendrá a su versión en caché. Esto es equivalente a establecer $OPAMSKIPUPDATE.
-t, --with-test
Compile y ejecute las pruebas unitarias del paquete. Esto solo afecta a los paquetes listados en la línea de comandos. Esto es equivalente a establecer $OPAMWITHTEST (o el obsoleto $OPAMBUILDTEST) a "true".
--unlock-base
Eliminado en la versión 2.1, use --update-invariant en su lugar.
--update-invariant
Permite cambios en los paquetes establecidos como base del switch (típicamente, el compilador principal). Úselo con precaución. Esto es equivalente a establecer la variable de entorno $OPAMUNLOCKBASE.
--verbose-on=PAQUETES
Sea más detallado en paquetes específicos. Esto es equivalente a establecer $OPAMVERBOSE.
--with-dev-setup
Incluya dependencias solo de herramientas de desarrollo.

OPCIONES COMUNES

Estas opciones son comunes a todos los comandos.

--best-effort
No falle si no se pueden instalar todos los paquetes solicitados: intente instalar tantos como sea posible. Tenga en cuenta que no todos los solucionadores externos pueden admitir esta opción (las versiones recientes de aspcud o mccs deberían). Esto es equivalente a establecer la variable de entorno $OPAMBESTEFFORT.
--cli=MAYOR.MENOR (ausente=2.4)
Utilice la sintaxis y semántica de la interfaz de línea de comandos de MAYOR.MENOR. Diseñado para cualquier uso persistente de opam (scripts, publicaciones de blog, etc.), cualquier versión de opam en la misma serie MAYOR se comportará como para la versión MENOR especificada. El indicador no estaba disponible en opam 2.0, por lo que para seleccionar la CLI 2.0, establezca la variable de entorno OPAMCLI a 2.0 en lugar de usar este parámetro.
--color=CUÁNDO
Colorea la salida. CUÁNDO debe ser uno de always, never o auto.
--confirm-level=NIVEL
Nivel de confirmación, NIVEL debe ser uno de ask, no, yes o unsafe-yes. Se puede especificar más de una vez. Si también se dan --yes o --no, se tiene en cuenta el valor del último --confirm-level. Esto es equivalente a establecer $OPAMCONFIRMLEVEL.
--criteria=CRITERIOS
Especifique las preferencias del usuario para la resolución de dependencias para esta ejecución. Anula $OPAMCRITERIA, $OPAMFIXUPCRITERIA y $OPAMUPGRADECRITERIA. Para obtener detalles sobre el lenguaje compatible y los solucionadores externos disponibles, consulte http://opam.ocaml.org/doc/External_solvers.html. Una guía general sobre el uso de preferencias de solucionadores se puede encontrar en http://www.dicosmo.org/Articles/usercriteria.pdf.
--cudf=NOMBREARCHIVO
Opción de depuración: Guarde las solicitudes CUDF enviadas al solucionador en NOMBREARCHIVO-<n>.cudf donde <n> es la n-ésima llamada al solucionador durante la ejecución de opam.
--debug
Imprima mensajes de depuración en stderr. Esto es equivalente a establecer $OPAMDEBUG a "true".
--debug-level=NIVEL
Similar a --debug, pero permite especificar el nivel de depuración (--debug lo establece en 1). Equivalente a establecer $OPAMDEBUG a un entero positivo.
--git-version
Imprima la versión git de opam, si está establecida (es decir, está usando una versión de desarrollo), y salga.
--help[=FMT] (predeterminado=auto)
Muestre esta ayuda en el formato FMT. El valor FMT debe ser uno de auto, pager, groff o plain. Con auto, el formato es pager o plain siempre que la variable TERM sea dumb o indefinida.
--ignore-pin-depends
Ignore los pines adicionales requeridos por los paquetes que se fijan, ya sea manualmente a través de opam pin o a través de opam install DIR. Esto es equivalente a establecer IGNOREPINDEPENDS=true.
--json=NOMBREARCHIVO
Guarde los resultados de la ejecución de opam en un archivo legible por computadora. Si el nombre del archivo contiene el carácter `%`, será reemplazado por un índice que no sobrescribirá un archivo existente. Similar a establecer la variable $OPAMJSON.
--no
Responda no a todas las preguntas de sí/no de opam sin preguntar. Vea también --confirm-level. Esto es equivalente a establecer $OPAMNO a "true".
--no-aspcud
Eliminado en la versión 2.1.
--no-auto-upgrade
Al configurar o actualizar un repositorio escrito para una versión anterior de opam (1.2), opam lo convierte internamente al formato actual. Esto deshabilita este comportamiento. Tenga en cuenta que los repositorios deberían definir su versión de formato en un archivo 'repo' en su raíz, o se asumirá que están en el formato antiguo. En cualquier caso, es preferible actualizar los repositorios manualmente usando opam admin upgrade [--mirror URL] cuando sea posible.
--no-self-upgrade
Opam se reemplazará a sí mismo con un binario más nuevo encontrado en OPAMROOT/opam si está presente. Esto deshabilita este comportamiento.
-q, --quiet
Deshabilita --verbose.
--root=ROOT
Use ROOT como la ruta raíz actual. Esto es equivalente a establecer $OPAMROOT a ROOT.
--safe, --readonly
Asegúrese de que nada se actualizará o reescribirá automáticamente. Útil para llamar desde scripts de finalización, por ejemplo. Fallará siempre que se necesite dicha operación; también evita esperar bloqueos, omite preguntas interactivas y anula la variable $OPAMDEBUG. Esto es equivalente a establecer la variable de entorno $OPAMSAFE.
--solver=CMD
Especifique el solucionador CUDF a utilizar para resolver problemas de instalación de paquetes. Puede ser un solucionador predefinido (esta versión de opam admite builtin-mccs+lp(), builtin-mccs+glpk, builtin-dummy-z3-solver, builtin-0install, aspcud, mccs, aspcud-old, packup), o un comando personalizado que debe contener las variables %{input}%, %{output}%, %{criteria}%, y opcionalmente %{timeout}%. Esto es equivalente a establecer $OPAMEXTERNALSOLVER.
--strict
Falle siempre que se encuentre un error en la definición de un paquete o en un archivo de configuración. Por defecto, continúa silenciosamente si es posible.
--switch=SWITCH
Use SWITCH como el switch del compilador actual. Esto es equivalente a establecer $OPAMSWITCH a SWITCH.
--use-internal-solver
Deshabilite cualquier solucionador externo y use el interno (esto requiere que opam se haya compilado con un solucionador interno). Esto es equivalente a establecer $OPAMNOASPCUD o $OPAMUSEINTERNALSOLVER.
-v, --verbose
Sea más detallado. Un -v muestra todos los comandos de paquetes, repita para mostrar también los comandos llamados internamente (por ejemplo, tar, curl, patch, etc.) Repetir n veces es equivalente a establecer $OPAMVERBOSE a "n".
--version
Muestre información de la versión.
-w, --working-dir
Siempre que actualice paquetes que están vinculados a un directorio local controlado por versiones, actualice al estado de trabajo actual de su código fuente en lugar del último estado confirmado, o la referencia a la que apuntan. Como el directorio fuente se copia tal cual, si no está limpio, puede resultar en un fallo de compilación de opam. Esto solo afecta a los paquetes listados explícitamente en la línea de comandos. También se puede establecer con $OPAMWORKINGDIR.
-y, --yes
Responda sí a todas las preguntas de sí/no de opam sin preguntar. Vea también --confirm-level. Esto es equivalente a establecer $OPAMYES a "true".

OPAMSOLVERALLOWSUBOPTIMAL (default `true') allows some solvers to still return a solution when they reach timeout; while the solution remains assured to be consistent, there is no guarantee in this case that it fits the expected optimisation criteria. If `true', opam willcontinue with a warning, if `false' a timeout is an error. Currently only the builtin-z3 backend handles this degraded case.

OPAMSOLVERTIMEOUT change the time allowance of the solver. Default is 60.0, set to 0 for unlimited. Note that all solvers may not support this option.

OPAMSOLVERTOLERANCE changes the tolerance towards the solver choosing an unoptimized solution (i.e. might pull outdated packages). Typical values range from 0.0 (best solution known to the solver) to 1.0 (unoptimized solution). Default is 0.0. This option is useful in case the solver can't find a solution in a reasonable time (see $OPAMSOLVERTIMEOUT). Note that all solvers may not support this option.

CLI VERSION

All scripts and programmatic invocations of opam should use `--cli' in order to ensure that they work seamlessly with future versions of the opam client. Additionally, blog posts or other documentation can benefit, as it prevents information from becoming stale.

Although opam only supports roots (~/.opam/) for the current version, it does provide backwards compatibility for its command-line interface.

Since CLI version support was only added in opam 2.1, use OPAMCLI to select 2.0 support (as opam 2.0 will just ignore it), and `--cli=2.1' for 2.1 (or later) versions, since an environment variable controlling the parsing of syntax is brittle. To this end, opam displays a warning if OPAMCLI specifies a valid version other than 2.0, and also if `--cli=2.0' is specified.

The command-line version is selected by using the `--cli' option or the OPAMCLI environment variable. `--cli' may be specified morethan once, where the last instance takes precedence. OPAMCLI is only inspected if `--cli' is not given.

NAME

opam-pin

opam package pinning utility

SYNOPSIS

opam pin [--ignore-conflicts] [--no-update] [--root DIR] [--jobs=N] PACKAGE [-- ARG…]

opam pin [--ignore-conflicts] [--no-update] [--root DIR] [--jobs=N] [--all]

opam pin [--ignore-conflicts] [--no-update] [--root DIR] [--jobs=N] [--edit] [PACKAGE]

opam pin [--ignore-conflicts] [--no-update] [--root DIR] [--jobs=N] [--uninstall] [PACKAGE]

opam pin [--ignore-conflicts] [--no-update] [--root DIR] [--jobs=N] [--list]

opam pin [--ignore-conflicts] [--no-update] [--root DIR] [--jobs=N] [--info] [PACKAGE]

opam pin [--ignore-conflicts] [--no-update] [--root DIR] [--jobs=N] [--set-version VERSION] [PACKAGE]

opam pin [--ignore-conflicts] [--no-update] [--root DIR] [--jobs=N] [--unset] [PACKAGE]

DESCRIPTION

This command allows to pin packages to a specific version, or to a local directory. This is useful for developing a package, or for testing a specific version of a dependency.

A pinned package will be kept at the specified version or source, even if newer versions are available in the repositories. It is also removed from the repository's update list.

Pinning a package to a local directory will cause opam to use the package found at that directory. This directory must contain a valid opam file.

When pinning a package to a specific version, opam will try to find the corresponding version in the configured repositories. If it is not found, opam will error out.

The pinning information is stored in the opam state. Removing the pinning information can be done using opam pin --uninstall or opam pin --unset.

opam pin --edit allows to edit the pinning information for a package. It will open the package's opam file in the editor defined by the OPAMEDIT environment variable.

COMMANDS

PACKAGE
The name of the package to pin. If omitted, actions like --edit, --uninstall, --info, --set-version and --unset will be applied to all pinned packages.
VERSION
The version of the package to pin to. This can be a specific version (e.g. 1.2.3) or a path to a local directory (e.g. /path/to/my/package).

OPTIONS

--ignore-conflicts
When pinning a package, ignore any reported conflicts with other packages. This is not recommended, as it can lead to an unstable environment.
--no-update
Do not run opam update before performing the pinning operation.
--root DIR
Use the specified DIR as the opam root directory. Defaults to $HOME/.opam.
--jobs=N
Use N parallel jobs for operations that require downloading or building packages. Defaults to the number of available CPU cores.
--all
Apply the action to all pinned packages.
--edit
Edit the opam file of the specified package (or all pinned packages if none is specified).
--uninstall
Uninstall the specified package (or all pinned packages if none is specified). This will remove the pinning information and allow the package to be updated or removed according to the repository configurations.
--list
List all pinned packages and their pinned versions or sources.
--info [PACKAGE]
Show detailed information about the pinning of the specified package, or all pinned packages if none is specified.
--set-version VERSION
Set the pinned version of the specified package to VERSION. This is useful to change the pinned version without re-installing the package.
--unset [PACKAGE]
Remove the pinning information for the specified package, or for all pinned packages if none is specified. This is equivalent to opam pin --uninstall but does not uninstall the package.

PACKAGE BUILD OPTIONS

The following options are passed to the build system of the pinned package. These are only applicable when pinning to a local directory or when rebuilding a pinned package.

--
Signifies the end of opam options. Any subsequent arguments are passed directly to the build system of the package being pinned.

COMMON OPTIONS

These options are common to most opam commands:

-y, **--yes**

--no-as-needed
Do not use the --as-needed linker flag.
--no-partial-updates
Deprecated. This option is ignored.
--no-check-signature
Do not check GPG signatures of downloaded files.
--no-depexts
Do not install dependencies using the system package manager.
--no-global-locks
Do not use global locks when accessing the state directory.
--no-install-fixups
Do not perform fixups after installation.
--no-parallel
Do not use parallel execution.
--no-resolve
Do not perform dependency resolution.
--no-sources
Do not download package sources.
--no-user-conf

--no-verify-paths

--no-warn-seats
Do not warn about unused variables in opam files.
--offline

--switch=NAME

-v, **--verbose**

-w, **--warnings-as-errors**

ENVIRONMENT

OPAMROOT
The opam root directory. Defaults to $HOME/.opam.
OPAMEDIT
The editor to use for opam pin --edit. Defaults to vim.

This describes the version of the CLI. It is not related to the version of the OCaml compiler.

This option is available since opam 2.0.0.
