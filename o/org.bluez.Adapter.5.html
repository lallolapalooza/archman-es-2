Nombre

org.bluez.Adapter - Documentación de la API del Adaptador BlueZ D-Bus

Interfaz

Servicio
org.bluez
Interfaz
org.bluez.Adapter1
Ruta de objeto
[prefijo variable]/{hci0,hci1,...}

Métodos

void IniciarDescubrimiento()

Inicia la sesión de descubrimiento de dispositivos, que puede incluir el inicio de un procedimiento de consulta y/o escaneo y la resolución de nombres de dispositivos remotos.

Use DetenerDescubrimiento para liberar las sesiones adquiridas.

Este proceso comenzará a crear objetos de Dispositivo a medida que se descubran nuevos dispositivos.

Durante el descubrimiento, se aplica un umbral delta de RSSI.

Cada cliente puede solicitar una única sesión de descubrimiento de dispositivos por adaptador.

Posibles errores:

org.bluez.Error.NoListo
org.bluez.Error.Fallido
org.bluez.Error.EnCurso

void DetenerDescubrimiento()

Detiene la sesión de descubrimiento de dispositivos iniciada por IniciarDescubrimiento.

Tenga en cuenta que un procedimiento de descubrimiento es compartido por todas las sesiones de descubrimiento, por lo que llamar a DetenerDescubrimiento solo liberará una sesión y el descubrimiento se detendrá cuando todas las sesiones de todos los clientes hayan finalizado.

Posibles errores:

org.bluez.Error.NoListo
org.bluez.Error.Fallido
org.bluez.Error.NoAutorizado

void EliminarDispositivo(objeto device)

Elimina el objeto del dispositivo remoto en la ruta dada, incluida la información almacenada en caché, como la información de emparejamiento.

Posibles errores:

org.bluez.Error.ArgumentosInvalidos
org.bluez.Error.Fallido

void EstablecerFiltroDescubrimiento(dict filtro)

Establece el filtro de descubrimiento de dispositivos para el llamador. Cuando se llama a este método sin ningún parámetro de filtro, se elimina el filtro.

Posibles valores de filtro:

array{cadena} UUIDs
Filtra por UUID de servicio, vacío significa que coincide con cualquier UUID.

Cuando se encuentra un dispositivo remoto que anuncia cualquier UUID de los UUIDs, se informará si:

  • Pathloss y RSSI están ambos vacíos.
  • solo se establece el parámetro Pathloss, el dispositivo anuncia la potencia TX y el pathloss calculado es menor que el parámetro Pathloss.
  • solo se establece el parámetro RSSI, y el RSSI recibido es mayor que el parámetro RSSI.
int16 RSSI
Valor umbral de RSSI.

Se emitirán señales PropertiesChanged para objetos de Dispositivo ya existentes, con el valor RSSI actualizado. Si se han establecido uno o más filtros de descubrimiento, no se aplicará el umbral delta de RSSI, que se impone por defecto con StartDiscovery.

uint16 Pathloss
Valor umbral de Pathloss.

Se emitirán señales PropertiesChanged para objetos de Dispositivo ya existentes, con el valor Pathloss actualizado.

cadena Transporte (Por defecto "auto")
El parámetro Transporte determina el tipo de escaneo.

Posibles valores:

"auto"
Escaneo intercalado, usa LE, BREDR, o ambos, dependiendo de lo que esté actualmente habilitado.
"bredr"
Solo consulta BR/EDR.
"le"
Solo escaneo LE.
bool DatosDuplicados (Por defecto falso)
Deshabilita la detección de duplicados de datos publicitarios.

Cuando está habilitado, se generarán señales PropertiesChanged para ManufacturerData y ServiceData cada vez que se descubran.

bool Descubrible (Por defecto falso)
Hace que el adaptador sea descubrible mientras descubre, si el adaptador ya es descubrible, la configuración de este filtro no hará nada.
cadena Patrón (Por defecto ninguno)
Descubre dispositivos donde el patrón coincide con el prefijo de la dirección o el nombre del dispositivo, lo cual es una forma conveniente de limitar el número de objetos de dispositivo creados durante un descubrimiento.

Cuando se establece, ignora las banderas de descubribilidad del dispositivo.

Nota: El emparejamiento de patrones se ignora si hay otros clientes que no establecen ningún patrón, ya que funciona como una OR lógica, y también establecer un patrón de cadena vacía "" coincidirá con cualquier dispositivo encontrado.

bool AutoConectar (Por defecto falso)
Se conecta automáticamente a los dispositivos descubiertos si se ha establecido un Patrón y coincide con la dirección o el nombre del dispositivo y es conectable.

Cuando se establece un filtro de descubrimiento, se crearán objetos de Dispositivo a medida que se descubran nuevos dispositivos con criterios coincidentes, independientemente de si son conectables o descubribles, lo que permite escuchar dispositivos no conectables y no descubribles.

Cuando varios clientes llaman a SetDiscoveryFilter, sus filtros se fusionan internamente y se envían notificaciones sobre nuevos dispositivos a todos los clientes. Por lo tanto, cada cliente debe verificar que las actualizaciones del dispositivo coincidan realmente con su filtro.

Cuando el mismo cliente llama a SetDiscoveryFilter varias veces, el último filtro pasado estará activo para ese cliente.

SetDiscoveryFilter se puede llamar antes de StartDiscovery. Es útil cuando un cliente creará la primera sesión de descubrimiento, para asegurar que se inicie el escaneo adecuado justo después de la llamada a StartDiscovery.

Posibles errores:

org.bluez.Error.NoListo
org.bluez.Error.NoSoportado
org.bluez.Error.Fallido

array{cadena} ObtenerFiltrosDescubrimiento()

Devuelve los filtros disponibles que se pueden pasar a EstablecerFiltroDescubrimiento.

Posibles errores: Ninguno

objeto ConectarDispositivo(dict propiedades) [experimental]

Se conecta al dispositivo sin necesidad de realizar un descubrimiento general.

El mecanismo de conexión es similar al método Connect en la interfaz org.bluez.Device1(5) con la excepción de que este método devuelve éxito cuando se establece la conexión física.

NAME

bluetoothd - Bluetooth daemon

SYNOPSIS

bluetoothd [-n] [-d] [-p policy] [-P plugin,...] [-e] [-C] [-r] [-m mac_address] [-a adapter] [-H transport] [-t timeout] [-f config_file] [-?]

DESCRIPTION

The bluetoothd daemon is the system daemon that provides the core Bluetooth functionality for the system. It provides support for both Bluetooth 4.0 Low Energy and older Bluetooth protocols. It uses D-Bus for system-wide communication and allows clients to discover and connect to Bluetooth devices and manage Bluetooth profiles.

OPTIONS

-n
Don't fork into the background.
-d
Enable debug logging.
-p policy
Set connection policy. Possible values are auto, auto-pair, and skip.
-P plugin,...
Enable only specified plugins.
-e
Enable experimental features.
-C
Compat mode. Keep old D-Bus API.
-r
Disable remote control support.
-m mac_address
Use the specified MAC address for the default adapter.
-a adapter
Use the specified adapter name.
-H transport
Use the specified transport for the default adapter. Possible values are hci, uart, etc.
-t timeout
Set the timeout for discoverable mode in seconds. Default is 180.
-f config_file
Use the specified configuration file.
-?
Display help message and exit.

D-BUS API

bluetoothd provides a D-Bus API that allows clients to interact with the Bluetooth stack. The main objects are org.bluez, org.bluez.Manager, org.bluez.Adapter, and org.bluez.Device.

The following table lists the most commonly used methods and properties:

org.bluez.Manager

This interface provides methods for managing Bluetooth adapters.

GetAdapters

Returns a list of object paths for all available Bluetooth adapters.

DefaultAdapter

Returns the object path of the default Bluetooth adapter.

org.bluez.Adapter

This interface represents a Bluetooth adapter. It provides methods for controlling the adapter's state and discovering devices.

StartDiscovery

Starts the device discovery procedure.

StopDiscovery

Stops the device discovery procedure.

CreateDevice

Creates a new device object for a remote device. This is typically used to initiate a connection to a known device.

The connection is established and you can specify bearer to connect with parameter.

After this method returns, services discovery will continue and any supported profile will be connected. There is no need for calling Connect on Device1 after this call. If connection was successful this method returns object path to created device object or device that already exist.

Possible properties values:

string Address (Mandatory)
The Bluetooth device address of the remote device.
string AddressType (Default "BR/EDR")
The Bluetooth device Address Type. This is address type that should be used for initial connection.

Possible values:

"public"
Public address
"random"
Random address

Possible errors:

org.bluez.Error.InvalidArguments
org.bluez.Error.AlreadyExists
org.bluez.Error.NotSupported
org.bluez.Error.NotReady
org.bluez.Error.Failed

Possible properties values:

string Address (Mandatory)

Possible errors:

Properties

string Address [readonly]

The Bluetooth device address.

string AddressType [readonly]

The Bluetooth Address Type. For dual-mode and BR/EDR only adapter this defaults to "public". Single mode LE adapters may have either value. With privacy enabled this contains type of Identity Address and not type of address used for connection.

Possible values:

"public"
Public address.
"random"
Random address.

string Name [readonly]

The Bluetooth system name (pretty hostname).

This property is either a static system default or controlled by an external daemon providing access to the pretty hostname configuration.

string Alias [readwrite]

The Bluetooth friendly name. This value can be changed.

In case no alias is set, it will return the system provided name. Setting an empty string as alias will convert it back to the system provided name.

When resetting the alias with an empty string, the property will default back to system name.

On a well configured system, this property never needs to be changed since it defaults to the system name and provides the pretty hostname.

Only if the local name needs to be different from the pretty hostname, this property should be used as last resort.

uint32 Class [readonly]

The Bluetooth class of device.

This property represents the value that is either automatically configured by DMI/ACPI information or provided as static configuration.

boolean Connectable [readwrite]

Set an adapter to connectable or non-connectable. This is a global setting and should only be used by the settings application.

Setting this property to false will set the Discoverable property of the adapter to false as well, which will not be reverted if Connectable is set back to true.

If required, the application will need to manually set Discoverable to true.

Note that this property only affects incoming connections.

boolean Powered [readwrite]

Switch an adapter on or off. This will also set the appropriate connectable state of the controller.

The value of this property is not persistent. After restart or unplugging of the adapter it will reset back to false.

string PowerState [readonly, experimental]

The power state of an adapter.

The power state will show whether the adapter is turning off, or turning on, as well as being on or off.

Possible values:

"on"
Powered on.
"off"
Powered off
"off-enabling"
Transitioning from "off" to "on".
"on-disabling"
Transitioning from "on" to "off".
"off-blocked"
Blocked by rfkill.

boolean Discoverable [readwrite] (Default: false)

Switch an adapter to discoverable or non-discoverable to either make it visible or hide it. This is a global setting and should only be used by the settings application.

If the DiscoverableTimeout is set to a non-zero value then the system will set this value back to false after the timer expired.

In case the adapter is switched off, setting this value will fail.

When changing the Powered property the new state of this property will be updated via a PropertiesChanged signal.

boolean Pairable [readwrite] (Default: true)

Switch an adapter to pairable or non-pairable. This is a global setting and should only be used by the settings application.

Note that this property only affects incoming pairing requests.

uint32 PairableTimeout [readwrite] (Default: 0)

The pairable timeout in seconds. A value of zero means that the timeout is disabled and it will stay in pairable mode forever.

uint32 DiscoverableTimeout [readwrite] (Default: 180)

The discoverable timeout in seconds. A value of zero means that the timeout is disabled and it will stay in discoverable/limited mode forever.

boolean Discovering [readonly]

Indicates that a device discovery procedure is active.

array{string} UUIDs [readonly]

List of 128-bit UUIDs that represents the available local services.

string Modalias [readonly, optional]

Local Device ID information in modalias format used by the kernel and udev.

array{string} Roles [readonly]

List of supported roles.

Possible values:

"central"
Supports the central role.
"peripheral"
Supports the peripheral role.
"central-peripheral"
Supports both roles concurrently.

array{string} ExperimentalFeatures [readonly, optional]

List of 128-bit UUIDs that represents the experimental features currently enabled.

uint16 Manufacturer [readonly]

The manufacturer of the device, as a uint16 company identifier defined by the Core Bluetooth Specification.

byte Version [readonly]

The Bluetooth version supported by the device, as a core version code defined by the Core Bluetooth Specification.

org.bluez.Device

This interface represents a remote Bluetooth device. It provides methods for connecting to and disconnecting from the device, as well as accessing device properties.

Connect

Connects to the remote device.

Disconnect

Disconnects from the remote device.

Pair

Pairs with the remote device.

Unpair

Unpairs with the remote device.

Properties

string Address
The Bluetooth device address.
string Name
The Bluetooth system name.
boolean Paired
Indicates whether the device is paired.
boolean Connected
Indicates whether the device is connected.
array{string} UUIDs
List of 128-bit UUIDs that represents the services supported by the device.
