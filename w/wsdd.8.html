wsdd(8) Manual del Administrador del Sistema wsdd(8)

NOMBRE

wsdd - Un demonio host y cliente de descubrimiento de servicios web.

SINOPSIS

wsdd [opciones]

DESCRIPCIÓN

wsdd implementa tanto un host de Descubrimiento de Servicios Web (WSD) como un demonio cliente WSD. La implementación del host permite que los hosts (Samba), como tu dispositivo NAS local, sean encontrados por clientes de Descubrimiento de Servicios Web como Windows. El modo cliente permite buscar otros hosts WSD en la red local.

El modo de operación por defecto es el modo host. El modo cliente o de descubrimiento debe ser habilitado explícitamente. A menos que se configure lo contrario, el modo host está siempre activo. Ambos modos se pueden usar al mismo tiempo.

OPCIONES

Opciones generales

-4, --ipv4only
Ver abajo.
-6, --ipv6only
Restringir a la familia de direcciones dada. Si se especifican ambas opciones, no habrá direcciones disponibles y wsdd saldrá.
-A, --no-autostart
No iniciar las actividades de red automáticamente al iniciar el programa. La interfaz API (ver abajo) se puede usar para iniciar y detener las actividades de red mientras la aplicación se está ejecutando.
-c DIRECTORIO, --chroot DIRECTORIO
Cambiar la raíz del sistema de archivos a el DIRECTORIO dado después de que se haya realizado la inicialización y justo antes del manejo de los mensajes entrantes. El nuevo directorio raíz puede estar vacío. Considera usar también la opción -u.
-h, --help
Mostrar ayuda y salir.
-H LIMITE_SALTOS, --hoplimit LIMITE_SALTOS
Establecer el límite de saltos para los paquetes multicast. El valor por defecto es 1, lo que debería evitar que los paquetes salgan del segmento de red local.
-i INTERFAZ/DIRECCIÓN, --interface INTERFAZ/DIRECCIÓN
Especificar en qué interfaces estará escuchando wsdd. Si no se especifican interfaces, se usarán todas. Las interfaces de loopback nunca se usan, incluso cuando se especifican explícitamente. Para interfaces con direcciones IPv6, solo se usarán direcciones de enlace local para anunciar el host en la red. Esta opción se puede proporcionar varias veces para restringir el tráfico a más de una interfaz. Esta opción también acepta direcciones IP a las que el servicio debería enlazarse. Para IPv6, solo se consideran las direcciones de enlace local, como se señaló anteriormente.
--metadata-timeout TIEMPO_ESPERA
Establecer el tiempo de espera para el intercambio de metadatos basado en HTTP. El valor por defecto es 2.0 segundos.
--source-port PUERTO
Establecer el puerto de origen para los mensajes multicast salientes, de modo que las respuestas usen este puerto como puerto de destino. Esto es útil para cortafuegos que no detectan las respuestas unicast entrantes como parte del flujo, por lo que el puerto necesita ser fijo para ser permitido manualmente.
-s, --shortlog
Usar un formato de registro más corto que solo incluye el nivel y el mensaje. Esto es útil en casos donde el mecanismo de registro, como systemd en Linux, añade automáticamente una fecha y un nombre de proceso más ID al mensaje de registro.
-u USUARIO[:GRUPO], --user USUARIO[:GRUPO]
Cambiar el usuario (y grupo) al ejecutarse antes de manejar los paquetes de red. Junto con la opción -c, esta opción se puede usar para aumentar la seguridad si el entorno de ejecución, como el sistema de inicialización, no puede garantizar esto de otra manera.
-U UUID, --uuid UUID
La especificación WSD requiere que un dispositivo tenga una dirección única que sea estable a través de reinicios o cambios en las redes. En el contexto del estándar, se asume que esto es algo así como un número de serie. Wsdd intenta leer el ID de la máquina de /etc/machine-id y /etc/hostid (en ese orden) antes de potencialmente hacer chroot en otro entorno. Si la lectura del ID de la máquina falla, wsdd recurre a un UUID de versión 5 con el espacio de nombres DNS y el nombre de host de la máquina local como entradas. Por lo tanto, el nombre de host debe ser estable y no ser modificado, por ejemplo, por DHCP. Sin embargo, si quieres que wsdd use un UUID específico, puedes usar esta opción.
-v, --verbose
Incrementar aditivamente la verbosidad de la salida del registro. Una sola aparición de -v/--verbose establece el nivel de registro en INFO. Más opciones -v establecen el nivel de registro en DEBUG.
-V, --version
Mostrar el número de versión y salir.

Opciones del modo host

-d DOMINIO, --domain DOMINIO
Asumir que el host que ejecuta wsdd se unió a un dominio ADS. Esto hará que wsdd informe que el host es un miembro del dominio. Deshabilita el informe de membresía en grupos de trabajo. El nombre de host (proporcionado) se convierte automáticamente a minúsculas. Usa la opción `-p` para cambiar este comportamiento.
-n NOMBRE_HOST, --hostname NOMBRE_HOST
Anular el nombre de host que wsdd utiliza durante el descubrimiento. Por defecto, se usa el nombre de host de la máquina (ver hostname(1)). Solo la parte del nombre de host de un posible FQDN se utilizará en el caso por defecto.
-o, --no-host
Deshabilitar el modo de operación host. Si se proporciona esta opción, el host no puede ser descubierto por otros hosts (Windows). Puede ser útil cuando se usa el modo cliente/descubrimiento y no se debe hacer ningún anuncio del host que ejecuta wsdd.
-p, --preserve-case
Preservar el nombre de host tal como está. Sin esta opción, el nombre de host se convierte de la siguiente manera. Para entornos de grupos de trabajo (ver -w), el nombre de host se convierte a mayúsculas por defecto. Viceversa, se convierte a minúsculas para su uso en dominios (ver -d).
-t, --no-http
No atender solicitudes HTTP del protocolo WSD. Esta opción está destinada a fines de depuración, donde otro proceso puede manejar los mensajes Get.
-w GRUPO_TRABAJO, --workgroup GRUPO_TRABAJO
Por defecto, wsdd informa que el host es miembro de un grupo de trabajo en lugar de un dominio (use la opción -d/--domain para anular esto). Con -w/--workgroup, se puede cambiar el nombre del grupo de trabajo por defecto. El nombre del grupo de trabajo por defecto es WORKGROUP. El nombre de host (proporcionado) se convierte automáticamente a mayúsculas. Usa la opción `-p` para cambiar este comportamiento.

Opciones del modo cliente/descubrimiento

-D, --discovery
Habilitar el modo de descubrimiento para buscar otros hosts/servidores WSD. Los hosts encontrados se registran con prioridad INFO. La interfaz del servidor (ver abajo) se puede usar para una interfaz programática. Consulte la página del manual para obtener detalles de la interfaz del servidor.
-l RUTA/PUERTO, --listen RUTA/PUERTO
Especificar la ubicación del socket para la interfaz de programación del servidor. Si el valor de la opción es numérico, se interpreta como un puerto numérico para un puerto de servidor TCP. Luego, el socket del servidor se enlaza solo al localhost. Si el valor de la opción no es numérico, se supone que es una ruta a un socket de dominio UNIX al que un cliente puede conectarse.

EJEMPLO DE USO

Manejar tráfico en eth0 y eth2 solo, pero solo con direcciones IPv6


wsdd -i eth0 -i eth2 -6


o


wsdd --interface eth0 --interface eth2 --ipv6only

Parescanos


wsdd -D


o


wsdd --discovery

Manejar tráfico de red en la interfaz con nombre eth0, pero solo con el grupo de trabajo de nombre REDLOCAL


wsdd -i eth0 -w REDLOCAL


o


wsdd --interface eth0 --workgroup REDLOCAL

Ejecutar wsdd como un servicio de solo lectura en el puerto TCP 8080, con el nombre de host de la máquina llamado MI_NAS


wsdd -n MI_NAS -l 8080


o


wsdd --hostname MI_NAS --listen 8080

SMB_GROUP=$(grep -i '^\s*workgroup\s*=' smb.conf | cut -f2 -d= | tr -d '[:blank:]')


wsdd -v -w $SMB_GROUP -u daemon:daemon -c /var/run/wsdd/chroot

CONFIGURACIÓN DEL FIREWALL

Se debe permitir el tráfico para los siguientes puertos, direcciones y direcciones:

- Tráfico de entrada y salida a udp/3702 con destino multicast: 239.255.255.250 para IPv4 y ff02::c para IPv6
- Tráfico de unidifusión de salida desde udp/3702
- Tráfico de entrada a tcp/5357

Debe restringir aún más el tráfico a la subred (local) del enlace, por ejemplo, utilizando el espacio de direcciones `fe80::/10` para IPv6. Tenga en cuenta que el tráfico IGMP debe estar habilitado para que el tráfico multicast IPv4 funcione.

INTERFAZ API

Wsdd proporciona una interfaz de API basada en texto y orientada a líneas para consultar información y activar acciones. La interfaz se puede utilizar con sockets de dominio TCP y UNIX (consulte la opción -l/--listen). El socket TCP se vincula solo al host local. Se pueden emitir los siguientes comandos:

clear - Borrar lista de dispositivos descubiertos

Borra la lista de todos los dispositivos descubiertos. Utilice el comando probe para buscar dispositivos nuevamente. Este comando no devuelve ningún dato y solo está disponible en modo de descubrimiento.

list [TIPO] - Listar dispositivos descubiertos

Devuelve una lista separada por tabulaciones de los dispositivos descubiertos del TIPO proporcionado (por ejemplo, "pub:Computer") con la siguiente información. Si no se proporciona ningún tipo, se listan todos los dispositivos descubiertos. La lista posiblemente vacía de hosts detectados siempre se termina con un solo punto ('.') en una línea por lo demás vacía. Este comando solo está disponible en modo de descubrimiento.

URI
URI del dispositivo descubierto. Tenga en cuenta que un dispositivo multihoming solo debe aparecer una vez pero con varias direcciones (ver abajo)
nombre
El nombre informado por el dispositivo. Para hosts de Windows descubiertos, es el nombre del equipo configurado el que se informa aquí.
asociación
Especifica el dominio o grupo de trabajo al que pertenece el host descubierto. El tipo de asociación (grupo de trabajo o dominio) está separado de su valor por dos puntos.
visto_por_ultimo
La fecha y hora en que el dispositivo fue visto por última vez como consecuencia de los mensajes Probe/Hello proporcionados en ISO8601 con segundos.
direcciones
Lista de todas las direcciones de transporte que se recopilaron durante el proceso de descubrimiento delimitadas por comas. Las direcciones se proporcionan junto con la interfaz (separadas por '%') en la que se descubrieron. Las direcciones IPv6 se informan entre corchetes. Tenga en cuenta que las direcciones informadas pueden no coincidir con el dispositivo real en el que se puede alcanzar el dispositivo.
tipos
Tipos del dispositivo detectado, delimitados por comas.

probe [INTERFAZ] - Buscar dispositivos

Activa un mensaje Probe en la INTERFAZ proporcionada (eth0, por ejemplo) para buscar hosts WSD. Si no se proporciona ninguna interfaz, se sondean todas las interfaces en las que wsdd escucha. Un mensaje Probe inicia el flujo de mensajes de descubrimiento. Puede llevar algún tiempo que los hosts se descubran realmente. Este comando no devuelve ningún dato y solo está disponible en modo de descubrimiento.

start - Iniciar actividades de red

Este comando inicia las actividades de red de wsdd si aún no se han iniciado. Se emiten mensajes "Hello" y el host se anuncia en la(s) red(es) cuando el modo de host está activo. Si el modo de descubrimiento está habilitado, también se inicia un proceso de sondeo.

stop - Detener actividades de red

Esta es la operación inversa a iniciar. Cuando se recibe este comando, se envían mensajes "Bye" para notificar a los hosts de la red la desaparición del host. Todos los sockets de red utilizados para el protocolo WSD también se cierran. Las actividades se pueden reiniciar con la operación start.

SEGURIDAD

wsdd no implementa ninguna característica de seguridad, por ejemplo, utilizando TLS para el servicio http. Esto se debe a que el uso previsto de wsdd es dentro de redes LAN privadas, es decir, domésticas. El mensaje *Hello* contiene la dirección de transporte del host, es decir, la dirección IP que acelera el descubrimiento (evita el mensaje *Resolve*).

PROBLEMAS CONOCIDOS

Usar solo IPv6 en FreeBSD

Si wsdd se ejecuta en FreeBSD utilizando solo IPv6, es posible que el host que ejecuta wsdd no se descubra de manera confiable. La razón parece ser que Windows no siempre puede conectarse al servicio HTTP por razones desconocidas. Como solución alternativa, ejecute wsdd solo con IPv4.

Interfaz de Túnel/Puente

Si existen interfaces de túnel/puente como las creadas por OpenVPN o Docker, pueden interferir con wsdd si se ejecuta sin proporcionar una interfaz a la que deba vincularse (por lo que se vincula a todas). En tales casos, los hosts wsdd aparecen después de que se haya iniciado wsdd, pero desaparecen cuando se fuerza una actualización de la vista Red en el Explorador de Windows, ya sea actualizando la vista o reiniciando la máquina Windows. Para resolver este problema, se debe especificar la interfaz que está conectada a la red en la que se debe anunciar el host con la opción -i/--interface. Esto evita el uso de las interfaces de túnel/puente.

Antecedentes: las interfaces de túnel/puente pueden hacer que las solicitudes *Resolve* de los hosts de Windows se entreguen a wsdd varias veces, es decir, se crean duplicados de dichas solicitudes. Si wsdd recibe una solicitud de este tipo por primera vez desde un túnel/puente, utiliza la dirección de transporte (dirección IP) de esa interfaz y envía la respuesta a través de unidifusión. Los duplicados adicionales no se procesan debido a la detección de mensajes duplicados que se basa en los UUID de los mensajes. El host de Windows que recibe la respuesta parece detectar una discrepancia entre la dirección de transporte en el mensaje *ResolveMatch* (que es la dirección del túnel/puente) y la IP del host/interfaz que envía (IP de LAN, por ejemplo). Posteriormente, Windows ignora el host wsdd.
