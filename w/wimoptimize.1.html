WIMOPTIMIZE(1) Comandos de usuario WIMOPTIMIZE(1)

NOMBRE

wimoptimize - Optimizar un archivo WIM

SINOPSIS

wimoptimize ARCHIVO_WIM [OPCIÓN...]

DESCRIPCIÓN

wimoptimize, o equivalentemente wimlib-imagex optimize, reconstruye el archivo WIM independiente ARCHIVO_WIM. El nuevo WIM se escribe en un archivo temporal y se renombra al archivo original cuando está listo. Esto eliminará cualquier hueco que haya quedado en el WIM como resultado de añadir o eliminar archivos o imágenes, por lo que el nuevo WIM puede ser más pequeño que el WIM antiguo.

Por defecto, wimoptimize reutilizará (no volverá a comprimir) los datos comprimidos y no cambiará el estado sólido o susceptible de ser canalizado (`pipable`) del WIM. Sin embargo, también puede realizar la recompresión y/o convertir entre WIMs sólidos, no sólidos, `pipable` y no `pipable`; consulte las opciones y ejemplos a continuación.

OPCIONES

--check
Antes de optimizar el WIM, verifica su integridad si contiene información de integridad adicional. También incluye información de integridad adicional en el WIM optimizado, incluso si no estaba presente antes.
--nocheck
No incluye información de integridad adicional en el WIM optimizado, incluso si estaba presente antes.
--include-integrity
Incluye información de integridad adicional en el WIM optimizado, es decir, como --check pero sin verificar también el WIM de antemano.
--recompress
Recomprime todos los datos del WIM mientras lo optimiza. Esto aumentará significativamente el tiempo necesario para optimizar el WIM, pero puede resultar en una mejor relación de compresión si wimlib puede hacerlo mejor que el programa que creó el WIM --- lo cual es probable si el WIM fue creado por Microsoft, ya que los compresores de wimlib son ligeramente más potentes.
--compress=TIPO[:NIVEL]
Recomprime el WIM usando el tipo de compresión especificado, y opcionalmente el nivel de compresión especificado para ese tipo de compresión. Esto implica --recompress. Consulte la documentación de esta opción para wimcapture(1) para más detalles.
--chunk-size=TAMAÑO
Establece el tamaño del fragmento de compresión del WIM a TAMAÑO. Consulte la documentación de esta opción para wimcapture(1) para más detalles.
--solid
Crea un archivo "sólido" que comprime múltiples archivos juntos. Esto generalmente resulta en una relación de compresión significativamente mejor pero tiene desventajas como una menor compatibilidad. Consulte la documentación de esta opción para wimcapture(1) para más detalles.
--solid-compress=TIPO[:NIVEL]
Similar a --compress, pero establece el tipo de compresión usado en recursos sólidos. Consulte la documentación de esta opción para wimcapture(1) para más detalles.
--solid-chunk-size=TAMAÑO
Similar a --chunk-size, pero establece el tamaño del fragmento usado en recursos sólidos. Consulte la documentación de esta opción para wimcapture(1) para más detalles.
--threads=NUM_HILOS
Número de hilos a usar para comprimir datos. Por defecto: autodetectar (número de procesadores).
--pipable
Reconstruye el WIM para que pueda aplicarse de forma totalmente secuencial, incluso desde una tubería (`pipe`). Consulte wimcapture(1) para más detalles sobre cómo crear WIMs `pipable`. Por defecto, cuando ni --pipable ni --not-pipable se especifican, el WIM optimizado será `pipable` si y solo si lo era antes.
--not-pipable
Reconstruye el WIM en formato no `pipable`.
--unsafe-compact
Compacta el WIM en el lugar (`in-place`), sin usar un archivo temporal. Los recursos existentes se desplazan hacia abajo para llenar huecos y los nuevos recursos se añaden según sea necesario. El WIM se trunca a su tamaño final, lo que puede reducir el archivo en disco. Esto es más eficiente que una reconstrucción completa, pero solo se admite cuando no se está realizando ninguna recompresión. Más importante aún, ¡UNA OPERACIÓN DE COMPACTACIÓN INSEGURA NO PUEDE INTERRUMPIRSE DE FORMA SEGURA! Si la operación se interrumpe, el WIM se corromperá y puede ser imposible (o al menos muy difícil) recuperar cualquier dato de él. Se espera que los usuarios de esta opción sepan lo que hacen y asuman la responsabilidad de cualquier corrupción de datos que pueda resultar.

NOTAS

wimoptimize no admite WIMs divididos ni WIMs delta. Para tales archivos, considere usar wimexport(1) en su lugar. Tenga en cuenta que wimoptimize es aproximadamente equivalente a:

wimexport ARCHIVO_WIM all tmp.wim && mv tmp.wim ARCHIVO_WIM

EJEMPLOS

Reconstruye 'install.wim':

wimoptimize install.wim

Reconstruye y recomprime 'install.wim':

wimoptimize install.wim --recompress

Reconstruye y recomprime 'install.wim' usando LZX ("máximo") compresión en un nivel de compresión superior al predeterminado. El tamaño del fragmento de compresión permanece sin cambios. Este comando será lento, pero puede ser útil para optimizar archivos para su distribución. Consulte https://wimlib.net/compression.html para ver algunos resultados de pruebas de rendimiento.

wimoptimize install.wim --compress=LZX:100

Recomprime 'install.wim' usando compresión en modo sólido, luego renómbralo a ´install.esd´. Esto disminuirá el tamaño del archivo significativamente. (También considere usar 'wimexport install.wim all install.esd --solid'.):

wimoptimize install.wim --solid
mv install.wim install.esd

Convierte 'install.esd' de nuevo en 'install.wim':

wimoptimize install.esd --compress=LZX
mv install.esd install.wim
