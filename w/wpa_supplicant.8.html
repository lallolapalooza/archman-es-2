NOMBRE

wpa_supplicant - Cliente Wi-Fi Protected Access y suplicante IEEE 802.1X

SINOPSIS

wpa_supplicant [ -BddfhKLqqsTtuvW ] [ -iifname ] [ -carchivo de configuración ] [ -Ddriver ] [ -Parchivo PID ] [ -farchivo de salida ] [ -Iarchivo de configuración adicional ]

DESCRIPCIÓN GENERAL

Las redes inalámbricas no requieren acceso físico al equipo de red de la misma manera que las redes cableadas. Esto facilita que los usuarios no autorizados monitoreen pasivamente una red y capturen todos los fotogramas transmitidos. Además, el uso no autorizado de la red es mucho más fácil. En muchos casos, esto puede ocurrir incluso sin el conocimiento explícito del usuario, ya que el adaptador de red local inalámbrica puede haber sido configurado para unirse automáticamente a cualquier red disponible.

Se puede utilizar el cifrado de capa de enlace para proporcionar una capa de seguridad para las redes inalámbricas. El estándar original de red local inalámbrica, IEEE 802.11, incluía un mecanismo de cifrado simple, WEP. Sin embargo, este demostró ser defectuoso en muchas áreas y las redes protegidas con WEP no pueden considerarse seguras. La autenticación IEEE 802.1X y las claves WEP dinámicas que cambian frecuentemente pueden usarse para mejorar la seguridad de la red, pero incluso eso tiene problemas de seguridad heredados debido al uso de WEP para el cifrado. Wi-Fi Protected Access y la enmienda IEEE 802.11i al estándar de red local inalámbrica introducen un mecanismo mucho mejorado para asegurar las redes inalámbricas. Las redes habilitadas con IEEE 802.11i que utilizan CCMP (un mecanismo de cifrado basado en el sólido algoritmo criptográfico AES) finalmente pueden llamarse seguras y usarse para aplicaciones que requieren una protección eficiente contra el acceso no autorizado.

wpa_supplicant es una implementación del componente WPA Supplicant, es decir, la parte que se ejecuta en las estaciones cliente. Implementa la negociación de claves WPA con un Autenticador WPA y la autenticación EAP con un Servidor de Autenticación. Además, controla el roaming y la autenticación/asociación IEEE 802.11 del controlador de red local inalámbrica.

wpa_supplicant está diseñado para ser un programa "demonio" que se ejecuta en segundo plano y actúa como el componente de backend que controla la conexión inalámbrica. wpa_supplicant admite programas frontend independientes y se incluye un frontend de texto de ejemplo, wpa_cli.

Antes de que wpa_supplicant pueda hacer su trabajo, la interfaz de red debe estar disponible. Esto significa que el dispositivo físico debe estar presente y habilitado, y el controlador del dispositivo debe estar cargado. El demonio saldrá inmediatamente si el dispositivo no está ya disponible.

Después de que wpa_supplicant haya configurado el dispositivo de red, puede proceder la configuración de nivel superior del dispositivo, como DHCP. Existen varias formas de integrar wpa_supplicant en los scripts de red de una máquina, algunas de las cuales se describen en las secciones siguientes.

Los siguientes pasos se utilizan al asociarse con un AP usando WPA:

•
wpa_supplicant solicita al controlador del kernel que escanee los BSS (Basic Service Set) vecinos.
•
wpa_supplicant selecciona un BSS basándose en su configuración.
•
wpa_supplicant solicita al controlador del kernel que se asocie con el BSS elegido.
•
Si es WPA-EAP: el Suplicante IEEE 802.1X integrado completa la autenticación EAP con el servidor de autenticación (gestionado por el Autenticador en el AP).
•
Si es WPA-EAP: la clave maestra se recibe del Suplicante IEEE 802.1X.
•
Si es WPA-PSK: wpa_supplicant usa PSK como la clave de sesión maestra.
•
wpa_supplicant completa el 4-Way Handshake WPA y el Group Key Handshake con el Autenticador (AP).
•
wpa_supplicant configura las claves de cifrado para unicast y broadcast.
•
los paquetes de datos normales pueden ser transmitidos y recibidos.

CONTROLADORES DISPONIBLES

A continuación se resume un resumen de los backends de controladores disponibles. El soporte para cada uno de los backends de controladores se elige en el momento de la compilación de wpa_supplicant. Para obtener una lista de los backends de controladores soportados que pueden usarse con la opción -D en su sistema, consulte la ayuda de wpa_supplicant (wpa_supplicant -h).

nl80211
Utiliza la moderna interfaz de Linux basada en netlink nl80211/cfg80211 (la mayoría de los controladores nuevos).
wext
Utiliza la interfaz heredada de extensiones inalámbricas de Linux basada en ioctl (hardware/controladores más antiguos).
wired
Controlador Ethernet cableado de wpa_supplicant
macsec_linux
Controlador Ethernet MACsec para Linux
roboswitch
Controlador de switch Broadcom de wpa_supplicant
none
sin controlador (solo servidor RADIUS/WPS ER)
bsd
Soporte BSD 802.11 (Atheros, etc.).
ndis
Controlador NDIS de Windows.

OPCIONES DE LÍNEA DE COMANDOS

La mayoría de las opciones de línea de comandos tienen alcance global. Algunas se especifican por interfaz y solo son válidas si se especifica al menos una opción -i, de lo contrario se ignoran. Los grupos de opciones para diferentes interfaces deben estar separados por la opción -N.

-b br_ifname
Nombre opcional de la interfaz de puente. (Por interfaz)
-B
Ejecuta el demonio en segundo plano.
-c filename
Ruta al archivo de configuración. (Por interfaz)
-C ctrl_interface
Ruta al socket ctrl_interface (Por interfaz. Solo se usa si -c no está presente).
-i ifname
Interfaz en la que escuchar. Se pueden presentar múltiples instancias de esta opción, una por interfaz, separadas por -N.

OPTIONS

The following options are available:

-B
Run daemon in the background. This is only available if wpa_supplicant was built with the CONFIG_NO_FORK option.
-c configuration file
Path to configuration file. If this is omitted, wpa_supplicant.conf will be used from the current directory or from /etc/. (See below for more on configuration file.)
-i interface
Interface to use. If this is omitted, the first interface found will be used. (See below for more on interface specific configuration.)
-I filename
Path to additional configuration file.
-d
Increase debugging verbosity (-dd even more).
-D driver
Driver to use (can be multiple drivers: nl80211,wext). (Per interface, see the available options below.)
-e entropy file
File for wpa_supplicant to use to maintain its internal entropy store in over restarts.
-f output file
Log output to specified file instead of stdout. (This is only available if wpa_supplicant was built with the CONFIG_DEBUG_FILE option.)
-g global ctrl_interface
Path to global ctrl_interface socket. If specified, interface definitions may be omitted.
-K
Include keys (passwords, etc.) in debug output.
-h
Help. Show a usage message.
-L
Show license (BSD).
-o override driver
Override the driver parameter for new interfaces.
-O override ctrl_interface
Override the ctrl_interface parameter for new interfaces.
-p
Driver parameters. (Per interface)
-P PID_file
Path to PID file.
-q
Decrease debugging verbosity (-qq even less).
-s
Log output to syslog instead of stdout. (This is only available if wpa_supplicant was built with the CONFIG_DEBUG_SYSLOG option.)
-T
Log output to Linux tracing in addition to any other destinations. (This is only available if wpa_supplicant was built with the CONFIG_DEBUG_LINUX_TRACING option.)
-t
Include timestamp in debug messages.
-u
Enable DBus control interface. If enabled, interface definitions may be omitted. (This is only available if wpa_supplicant was built with the CONFIG_CTRL_IFACE_DBUS_NEW option.)
-v
Show version.
-W
Wait for a control interface monitor before starting.
-N
Start describing new interface.

EJEMPLOS

En la mayoría de los casos comunes, wpa_supplicant se inicia con:

wpa_supplicant -B -c/etc/wpa_supplicant.conf -iwlan0

Esto hace que el proceso se bifurque y se ejecute en segundo plano.

La forma más fácil de depurar problemas y obtener un registro de depuración para informes de errores es iniciar wpa_supplicant en primer plano con la depuración activada:

wpa_supplicant -c/etc/wpa_supplicant.conf -iwlan0 -d

Si el envoltorio del controlador específico no se conoce de antemano, es posible especificar varios envoltorios de controlador separados por comas en la línea de comandos. wpa_supplicant utilizará el primer envoltorio de controlador que sea capaz de inicializar la interfaz.

wpa_supplicant -Dnl80211,wext -c/etc/wpa_supplicant.conf -iwlan0

wpa_supplicant puede controlar múltiples interfaces (radios) ya sea ejecutando un proceso por cada interfaz por separado o ejecutando un solo proceso y una lista de opciones en la línea de comandos. Cada interfaz se separa con el argumento -N. Como ejemplo, el siguiente comando iniciará wpa_supplicant para dos interfaces:

wpa_supplicant \
	-c wpa1.conf -i wlan0 -D nl80211 -N \
	-c wpa2.conf -i ath0 -D wext

CONTROLADORES_SOPORTADOS

Linux nl80211/cfg80211
Este es el controlador preferido para Linux.
Extensiones inalámbricas de Linux
En teoría, se puede usar cualquier controlador que soporte las Extensiones inalámbricas de Linux con IEEE 802.1X (es decir, no WPA) cuando se utiliza la opción ap_scan=0 en el archivo de configuración.
Controladores de Ethernet cableada
Usar ap_scan=0.
Capa net80211 de BSD (por ejemplo, controlador Atheros)
En este momento, esto es para la rama FreeBSD 6-CURRENT.
NDIS de Windows
El puerto actual de Windows requiere WinPcap (http://winpcap.polito.it/). Consulte README-Windows.txt para obtener más información.

wpa_supplicant fue diseñado para ser portable a diferentes controladores y sistemas operativos. Esperamos que se agregue soporte para más tarjetas WLAN y sistemas operativos en el futuro. Consulte developer.txt para obtener más información sobre el diseño de wpa_supplicant y la portabilidad a otros controladores. Un objetivo principal es agregar soporte completo para WPA/WPA2 a las extensiones inalámbricas de Linux para permitir que se admitan nuevos controladores sin tener que implementar código de interfaz específico del controlador en wpa_supplicant.

ARQUITECTURA

El sistema wpa_supplicant consta de los siguientes componentes:

wpa_supplicant.conf
el archivo de configuración que describe todas las redes a las que el usuario desea que se conecte la computadora.
wpa_supplicant
el programa que interactúa directamente con la interfaz de red.
wpa_cli
el programa cliente que proporciona una interfaz de alto nivel a la funcionalidad del demonio.
wpa_passphrase
una utilidad necesaria para construir archivos wpa_supplicant.conf que incluyen contraseñas cifradas.

INICIO_RÁPIDO

Primero, cree un archivo de configuración, por ejemplo /etc/wpa_supplicant.conf, que describa las redes que le interesan. Consulte wpa_supplicant.conf(5) para obtener detalles.

Una vez que la configuración esté lista, puede probar si funciona ejecutando wpa_supplicant con el siguiente comando para iniciarlo en primer plano con la depuración activada:

wpa_supplicant -iwlan0 -c/etc/wpa_supplicant.conf -d

Suponiendo que todo va bien, puede comenzar a usar el siguiente comando para iniciar wpa_supplicant en segundo plano sin depuración:

wpa_supplicant -iwlan0 -c/etc/wpa_supplicant.conf -B

Tenga en cuenta que si incluyó más de una interfaz de controlador en la configuración en tiempo de compilación (.config), puede que necesite especificar qué interfaz usar incluyendo la opción -D<nombre del controlador> en la línea de comandos.

INTERFAZ_CON_PCMCIA-CS/CARDMRG

Por ejemplo, los siguientes pequeños cambios en los scripts de pcmcia-cs pueden usarse para habilitar el soporte WPA:

Agregue MODE="Managed" y WPA="y" al esquema de red en /etc/pcmcia/wireless.opts.

Agregue el siguiente bloque al final del manejador de acciones start en /etc/pcmcia/wireless:

if [ "$WPA" = "y" -a -x /usr/local/bin/wpa_supplicant ]; then
    /usr/local/bin/wpa_supplicant -B -c/etc/wpa_supplicant.conf -i$DEVICE
fi

Agregue el siguiente bloque al final del manejador de acciones stop (puede que necesite separarse de otras acciones) en /etc/pcmcia/wireless:

if [ "$WPA" = "y" -a -x /usr/local/bin/wpa_supplicant ]; then
    killall wpa_supplicant
fi

Esto hará que cardmgr inicie wpa_supplicant cuando se conecte la tarjeta.
