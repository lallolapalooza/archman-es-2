NOMBRE

Wget - El descargador de red no interactivo.

SINOPSIS

wget [opción]... [URL]...

DESCRIPCIÓN

GNU Wget es una utilidad gratuita para la descarga no interactiva de archivos desde la Web. Soporta los protocolos HTTP, HTTPS y FTP, así como la recuperación a través de proxies HTTP.

Wget es no interactivo, lo que significa que puede funcionar en segundo plano, mientras el usuario no está conectado. Esto le permite iniciar una recuperación y desconectarse del sistema, dejando que Wget termine el trabajo. Por el contrario, la mayoría de los navegadores Web requieren la presencia constante del usuario, lo que puede ser un gran inconveniente al transferir muchos datos.

Wget puede seguir enlaces en páginas HTML, XHTML y CSS, para crear versiones locales de sitios web remotos, recreando completamente la estructura de directorios del sitio original. Esto a veces se denomina "descarga recursiva". Mientras lo hace, Wget respeta el Estándar de Exclusión de Robots (/robots.txt). Wget puede ser instruido para convertir los enlaces en los archivos descargados para que apunten a los archivos locales, para visualización sin conexión.

Wget ha sido diseñado para ser robusto en conexiones de red lentas o inestables; si una descarga falla debido a un problema de red, seguirá intentándolo hasta que se haya recuperado el archivo completo. Si el servidor soporta la reanudación, instruirá al servidor para continuar la descarga desde donde se quedó.

OPCIONES

Sintaxis de opciones

Dado que Wget utiliza GNU getopt para procesar los argumentos de la línea de comandos, cada opción tiene una forma larga además de la corta. Las opciones largas son más convenientes de recordar, pero requieren más tiempo para escribirlas. Puede mezclar libremente diferentes estilos de opciones, o especificar opciones después de los argumentos de la línea de comandos. Así puede escribir:

wget -r --tries=10 http://fly.srk.fer.hr/ -o log

El espacio entre la opción que acepta un argumento y el argumento puede omitirse. En lugar de -o log puede escribir -olog.

Puede agrupar varias opciones que no requieren argumentos, como:

wget -drc <URL>

Esto es completamente equivalente a:

wget -d -r -c <URL>

Dado que las opciones pueden especificarse después de los argumentos, puede terminarlas con --. Así, lo siguiente intentará descargar la URL -x, informando del fallo a log:

wget -o log -- -x

Todas las opciones que aceptan listas separadas por comas respetan la convención de que especificar una lista vacía borra su valor. Esto puede ser útil para borrar la configuración de .wgetrc. Por ejemplo, si su .wgetrc establece "exclude_directories" a /cgi-bin, el siguiente ejemplo primero lo restablecerá y luego lo establecerá para excluir /~nobody y /~somebody. También puede borrar las listas en .wgetrc.

wget -X "" -X /~nobody,/~somebody

La mayoría de las opciones que no aceptan argumentos son opciones *booleanas*, llamadas así porque su estado puede ser capturado con una variable de sí o no ("booleana"). Por ejemplo, --follow-ftp indica a Wget que siga enlaces FTP desde archivos HTML y, por otro lado, --no-glob le dice que no realice globbing de archivos en URLs FTP. Una opción booleana es *afirmativa* o *negativa* (que empieza por --no). Todas estas opciones comparten varias propiedades.

A menos que se indique lo contrario, se asume que el comportamiento predeterminado es lo opuesto a lo que la opción realiza. Por ejemplo, la existencia documentada de --follow-ftp asume que el valor predeterminado es *no* seguir enlaces FTP desde páginas HTML.

Las opciones afirmativas se pueden negar anteponiendo --no- al nombre de la opción; las opciones negativas se pueden negar omitiendo el prefijo --no-. Esto puede parecer superflua: si el valor predeterminado para una opción afirmativa es no hacer algo, ¿por qué proporcionar una forma de desactivarla explícitamente? Pero el archivo de inicio puede de hecho cambiar el valor predeterminado. Por ejemplo, usar "follow_ftp = on" en .wgetrc hace que Wget *siga* los enlaces FTP por defecto, y usar --no-follow-ftp es la única forma de restaurar el valor predeterminado de fábrica desde la línea de comandos.

Opciones de inicio básicas

-V
--version
Muestra la versión de Wget.
-h
--help
Imprime un mensaje de ayuda que describe todas las opciones de línea de comandos de Wget.
-b
--background
Pasa a segundo plano inmediatamente después de iniciarse. Si no se especifica un archivo de salida con -o, la salida se redirige a wget-log.
-e comando
--execute comando
Ejecuta comando como si fuera parte de .wgetrc. Un comando invocado de esta manera se ejecutará *después* de los comandos en .wgetrc, por lo tanto, tendrá precedencia sobre ellos. Si necesita especificar más de un comando de wgetrc, use múltiples instancias de -e.

Opciones de registro y archivo de entrada

-o archivo_de_log
--output-file=archivo_de_log
Registra todos los mensajes en archivo_de_log. Los mensajes se informan normalmente al error estándar.
-a archivo_de_log
--append-output=archivo_de_log
Añade a archivo_de_log. Esto es lo mismo que -o, solo que añade a archivo_de_log en lugar de sobrescribir el archivo de log antiguo. Si archivo_de_log no existe, se crea un nuevo archivo.
-d
--debug
Activa la salida de depuración, lo que significa información diversa importante para los desarrolladores de Wget si no funciona correctamente. Es posible que su administrador del sistema haya elegido compilar Wget sin soporte de depuración, en cuyo caso -d no funcionará. Tenga en cuenta que compilar con soporte de depuración es siempre seguro: Wget compilado con soporte de depuración *no* mostrará ninguna información de depuración a menos que se solicite con -d.
-q
--quiet
Desactiva la salida de Wget.
-v
--verbose
Activa la salida detallada, con todos los datos disponibles. La salida predeterminada es detallada.
-nv
--no-verbose
Desactiva la salida detallada sin ser completamente silencioso (use -q para eso), lo que significa que los mensajes de error y la información básica todavía se imprimen.
--report-speed=tipo
Muestra el ancho de banda como tipo. El único valor aceptado es bits.
-i archivo
--input-file=archivo
Lee las URLs desde un archivo local o externo. Si se especifica - como archivo, las URLs se leen desde la entrada estándar. (Use ./- para leer desde un archivo llamado literalmente -.)

Si se utiliza esta función, no es necesario que haya URLs en la línea de comandos. Si hay URLs tanto en la línea de comandos como en un archivo de entrada, las de la línea de comandos serán las primeras en ser recuperadas. Si no se especifica --force-html, entonces archivo debe consistir en una serie de URLs, una por línea.

Sin embargo, si especificas --force-html, el documento será considerado como html. En ese caso, podrías tener problemas con los enlaces relativos, que puedes solucionar añadiendo "<base href="url">" a los documentos o especificando --base=url en la línea de comandos.

Si el archivo es un archivo externo, el documento se tratará automáticamente como html si el Content-Type coincide con text/html. Además, la ubicación del archivo se usará implícitamente como href base si no se especificó ninguno.

Si el archivo es un archivo local, en sistemas que lo soportan, se abrirá con el flag "O_NONBLOCK" para permitir lecturas no bloqueantes del archivo. Wget intentará continuar leyendo del archivo hasta que se alcance el EOF o se cierre. Esto permite transmitir una lista de archivos para su recuperación donde la lista se genera dinámicamente durante la ejecución del proceso. Actualmente, esta característica no está disponible en plataformas Windows.

--input-metalink=archivo
Descarga archivos cubiertos en el archivo Metalink local archivo. Se admiten las versiones 3 y 4 de Metalink.
--keep-badhash
Conserva los archivos descargados de Metalink con un hash incorrecto. Añade .badhash al nombre de los archivos de Metalink que tengan una discrepancia en la suma de verificación, excepto sin sobrescribir los archivos existentes.
--metalink-over-http
Emite una solicitud HEAD HTTP en lugar de GET y extrae metadatos de Metalink de las cabeceras de respuesta. Luego cambia a descarga de Metalink. Si no se encuentran metadatos de Metalink válidos, vuelve a la descarga HTTP ordinaria. Habilita la descarga/procesamiento de archivos Content-Type: application/metalink4+xml.
--metalink-index=número
Establece el ordinal NUMBER del metaurl de Metalink application/metalink4+xml. De 1 al número total de "application/metalink4+xml" disponibles. Especifica 0 o inf para elegir el primero válido. Los metaurls, como los de --metalink-over-http, pueden haber sido ordenados por el valor de la clave de prioridad; ten esto en cuenta para elegir el NUMBER correcto.
--preferred-location
Establece la ubicación preferida para los recursos de Metalink. Esto tiene efecto si hay múltiples recursos con la misma prioridad disponibles.
--xattr
Habilita el uso de atributos extendidos del sistema de archivos para guardar la URL original y el valor de la cabecera HTTP Referer si se utilizó.

Ten en cuenta que la URL puede contener información privada como tokens de acceso o credenciales.

-F
--force-html
Cuando la entrada se lee de un archivo, fuerza a que se trate como un archivo HTML. Esto te permite recuperar enlaces relativos de archivos HTML existentes en tu disco local, añadiendo "<base href="url">" al HTML, o usando la opción de línea de comandos --base.
-B URL
--base=URL
Resuelve enlaces relativos usando URL como punto de referencia, al leer enlaces de un archivo HTML especificado a través de la opción -i/--input-file (junto con --force-html, o cuando el archivo de entrada fue obtenido remotamente de un servidor que lo describió como HTML). Esto es equivalente a la presencia de una etiqueta "BASE" en el archivo de entrada HTML, con URL como valor para el atributo "href".

Por ejemplo, si especificas http://foo/bar/a.html para URL, y Wget lee ../baz/b.html del archivo de entrada, se resolvería a http://foo/baz/b.html.

--config=ARCHIVO
Especifica la ubicación de un archivo de inicio que deseas usar en lugar del predeterminado. Usa --no-config para deshabilitar la lectura de archivos de configuración. Si se dan tanto --config como --no-config, se ignora --no-config.
--rejected-log=archivo_log
Registra todas las URL rechazadas en archivo_log como valores separados por comas. Los valores incluyen la razón del rechazo, la URL y la URL padre en la que se encontró.

Opciones de Descarga

--bind-address=DIRECCION
Al establecer conexiones TCP/IP de cliente, enlaza a DIRECCION en la máquina local. DIRECCION puede especificarse como un nombre de host o una dirección IP. Esta opción puede ser útil si tu máquina está enlazada a múltiples IPs.
--bind-dns-address=DIRECCION
[solo libcares] Esta dirección anula la ruta para las solicitudes DNS. Si alguna vez necesitas eludir la configuración estándar de /etc/resolv.conf, esta opción junto con --dns-servers es tu aliada. DIRECCION debe especificarse como una dirección IPv4 o IPv6. Wget necesita ser compilado con libcares para que esta opción esté disponible.
--dns-servers=DIRECCIONES
[solo libcares] Las direcciones dadas anulan las direcciones estándar del servidor de nombres, por ejemplo, como se configuran en /etc/resolv.conf. DIRECCIONES pueden especificarse como direcciones IPv4 o IPv6, separadas por comas. Wget necesita ser compilado con libcares para que esta opción esté disponible.
-t número
--tries=número
Establece el número de intentos a número. Especifica 0 o inf para reintentos infinitos. El valor predeterminado es reintentar 20 veces, con la excepción de errores fatales como "conexión rechazada" o "no encontrado" (404), que no se reintentan.
-O archivo
--output-document=archivo
Los documentos no se escribirán en los archivos apropiados, sino que todos se concatenarán y se escribirán en archivo. Si se usa - como archivo, los documentos se imprimirán en la salida estándar, deshabilitando la conversión de enlaces. (Usa ./- para imprimir en un archivo llamado literalmente -).

El uso de -O *no* significa simplemente "usar el nombre archivo en lugar del de la URL"; más bien, es análogo a la redirección del shell: se pretende que wget -O archivo http://foo funcione como wget -O - http://foo > archivo; archivo se truncará inmediatamente y todo el contenido descargado se escribirá allí.

Por esta razón, -N (para verificación de marca de tiempo) no se admite en combinación con -O: dado que archivo se crea nuevo cada vez, siempre tendrá una marca de tiempo muy reciente. Se emitirá una advertencia si se usa esta combinación.

Del mismo modo, usar -r o -p con -O puede no funcionar como esperas: Wget no solo descargará el primer archivo a archivo y luego descargará el resto a sus nombres normales: todo el contenido descargado se colocará en archivo. Esto se deshabilitó en la versión 1.11, pero se restableció (con una advertencia) en 1.11.2, ya que hay algunos casos en los que este comportamiento puede tener algún uso.

Una combinación con -nc solo se acepta si el archivo de salida dado no existe.

Ten en cuenta que una combinación con -k solo se permite al descargar un único documento, ya que en ese caso convertirá todos los URI relativos en externos; -k no tiene sentido para múltiples URI cuando todos se descargan en un solo archivo; -k solo se puede usar cuando la salida es un archivo regular.

-nc
--no-clobber
Si un archivo se descarga más de una vez en el mismo directorio, el comportamiento de Wget depende de algunas opciones, incluida -nc. En ciertos casos, el archivo local será sobrescrito (clobbered), o sobrescrito, al descargarlo repetidamente. En otros casos, se conservará.

Al ejecutar Wget sin -N, -nc, -r o -p, descargar el mismo archivo en el mismo directorio dará como resultado la conservación de la copia original de archivo y que la segunda copia se llame archivo.1. Si ese archivo se descarga una vez más, la tercera copia se llamará archivo.2, y así sucesivamente. (Este es también el comportamiento con -nd, incluso si -r o -p están en efecto). Cuando se especifica -nc, este comportamiento se suprime, y Wget se negará a descargar copias más nuevas de archivo. Por lo tanto, "no-clobber" es en realidad un nombre inapropiado en este modo: no se evita el clobber (ya que los sufijos numéricos ya lo prevenían), sino que se evita la duplicación de versiones.

Al ejecutar Wget con -r o -p, pero sin -N, -nd o -nc, la nueva descarga de un archivo dará como resultado que la nueva copia sobrescriba simplemente la antigua. Añadir -nc evitará este comportamiento, haciendo en cambio que la versión original se conserve y se ignoren las copias más nuevas en el servidor.

Al ejecutar Wget con -N, con o sin -r o -p, la decisión de descargar o no una copia más nueva de un archivo depende de la marca de tiempo y el tamaño local y remoto del archivo. -nc no puede especificarse al mismo tiempo que -N.

Una combinación con -O/--output-document solo se acepta si el archivo de salida dado no existe.

Ten en cuenta que cuando se especifica -nc, los archivos con los sufijos .html o .htm se cargarán desde el disco local y se analizarán como si se hubieran obtenido de la Web.

--backups=copias_de_seguridad
Antes de (sobrescribir)
g un archivo, haz una copia de seguridad de un archivo existente añadiendo un sufijo .1 (_1 en VMS) al nombre del archivo. Dichos archivos de copia de seguridad se rotan a .2, .3 y así sucesivamente, hasta backups (y se pierden más allá de eso).
--no-netrc
No intentes obtener credenciales del archivo .netrc. Por defecto se busca en el archivo .netrc credenciales en caso de que no se haya pasado ninguna en la línea de comandos y se requiera autenticación.
-c
--continue
Continuar descargando un archivo parcialmente descargado. Esto es útil cuando quieres terminar una descarga iniciada por una instancia anterior de Wget, o por otro programa. Por ejemplo: 
wget -c ftp://sunsite.doc.ic.ac.uk/ls-lR.Z

Si hay un archivo llamado ls-lR.Z en el directorio actual, Wget asumirá que es la primera parte del archivo remoto y le pedirá al servidor que continúe la recuperación desde un desplazamiento igual a la longitud del archivo local.

Ten en cuenta que no necesitas especificar esta opción si solo quieres que la invocación actual de Wget reintente descargar un archivo si la conexión se pierde a mitad de camino. Este es el comportamiento por defecto. -c solo afecta a la reanudación de descargas iniciadas *antes* de esta invocación de Wget, y cuyos archivos locales aún existen.

Sin -c, el ejemplo anterior simplemente descargaría el archivo remoto a ls-lR.Z.1, dejando el archivo truncado ls-lR.Z intacto.

Si usas -c en un archivo no vacío, y el servidor no soporta descargas continuas, Wget reiniciará la descarga desde cero y sobrescribirá completamente el archivo existente.

A partir de Wget 1.7, si usas -c en un archivo de igual tamaño que el del servidor, Wget se negará a descargar el archivo e imprimirá un mensaje explicativo. Lo mismo ocurre cuando el archivo es más pequeño en el servidor que localmente (presumiblemente porque ha sido cambiado en el servidor desde tu último intento de descarga)---porque "continuar" no tiene sentido, no se realiza ninguna descarga.

Por otro lado, al usar -c, cualquier archivo que sea más grande en el servidor que localmente se considerará una descarga incompleta y solo se descargarán "(longitud(remoto) - longitud(local))" bytes y se añadirán al final del archivo local. Este comportamiento puede ser deseable en ciertos casos---por ejemplo, puedes usar wget -c para descargar solo la nueva porción que se ha añadido a una colección de datos o archivo de registro.

Sin embargo, si el archivo es más grande en el servidor porque ha sido *cambiado*, en lugar de solo *añadido*, terminarás con un archivo corrupto. Wget no tiene forma de verificar que el archivo local es realmente un prefijo válido del archivo remoto. Debes tener especial cuidado con esto cuando uses -c junto con -r, ya que cada archivo se considerará un candidato de "descarga incompleta".

Otro caso en el que obtendrás un archivo corrupto si intentas usar -c es si tienes un proxy HTTP defectuoso que inserta una cadena de "transferencia interrumpida" en el archivo local. En el futuro, puede que se añada una opción de "reversión" para tratar este caso.

Ten en cuenta que -c solo funciona con servidores FTP y con servidores HTTP que soportan la cabecera "Range".

--start-pos=OFFSET
Comenzar la descarga en la posición OFFSET basada en cero. El desplazamiento puede expresarse en bytes, kilobytes con el sufijo `k', o megabytes con el sufijo `m', etc.

--start-pos tiene mayor precedencia sobre --continue. Cuando se especifican tanto --start-pos como --continue, wget emitirá una advertencia y luego procederá como si --continue estuviera ausente.

Se requiere el soporte del servidor para descargas continuas, de lo contrario --start-pos no podrá ayudar. Ver -c para más detalles.

--progress=type
Selecciona el tipo de indicador de progreso que deseas utilizar. Los indicadores legales son "dot" y "bar".

El indicador "bar" se utiliza por defecto. Dibuja una barra de progreso gráfica ASCII (también conocida como visualización de "termómetro") indicando el estado de la recuperación. Si la salida no es una TTY, el indicador "dot" se utilizará por defecto.

Usa --progress=dot para cambiar a la visualización "dot". Rastrea la recuperación imprimiendo puntos en la pantalla, cada punto representando una cantidad fija de datos descargados.

El tipo de progreso también puede tomar uno o más parámetros. Los parámetros varían según el tipo seleccionado. Los parámetros para *type* se pasan añadiéndolos al tipo separados por dos puntos (:) así: --progress=type:parameter1:parameter2.

Al usar la recuperación punteada, puedes establecer el *estilo* especificando el tipo como dot:style. Diferentes estilos asignan un significado diferente a un punto. Con el estilo "default" cada punto representa 1K, hay diez puntos en un clúster y 50 puntos en una línea. El estilo "binary" tiene una orientación más "de ordenador"---puntos de 8K, clústeres de 16 puntos y 48 puntos por línea (lo que suma 384K por línea). El estilo "mega" es adecuado para descargar archivos grandes---cada punto representa 64K recuperados, hay ocho puntos en un clúster y 48 puntos en cada línea (por lo que cada línea contiene 3M). Si "mega" no es suficiente, puedes usar el estilo "giga"---cada punto representa 1M recuperado, hay ocho puntos en un clúster y 32 puntos en cada línea (por lo que cada línea contiene 32M).

Con --progress=bar, actualmente hay dos parámetros posibles, force y noscroll.

Cuando la salida no es una TTY, la barra de progreso siempre vuelve a "dot", incluso si se pasó --progress=bar a Wget durante la invocación. Este comportamiento puede ser anulado y la salida "bar" forzada utilizando el parámetro "force" como --progress=bar:force.

Por defecto, la barra de progreso del estilo bar desplaza el nombre del archivo de izquierda a derecha para el archivo que se está descargando si el nombre del archivo excede la longitud máxima asignada para su visualización. En ciertos casos, como con --progress=bar:force, uno puede no querer el nombre del archivo desplazándose en la barra de progreso. Pasando el parámetro "noscroll", Wget puede ser forzado a mostrar la mayor parte del nombre del archivo posible sin desplazarse.

Ten en cuenta que puedes establecer el estilo por defecto usando el comando "progress" en .wgetrc. Esa configuración puede ser anulada desde la línea de comandos. Por ejemplo, para forzar la salida de barra sin desplazamiento, usa --progress=bar:force:noscroll.

--show-progress
Forzar a wget a mostrar la barra de progreso en cualquier nivel de verbosidad.

Por defecto, wget solo muestra la barra de progreso en modo detallado. Sin embargo, puede que desees que wget muestre la barra de progreso en pantalla en conjunción con cualquier otro modo de verbosidad como --no-verbose o --quiet. Esta es a menudo una propiedad deseada al invocar wget para descargar varios archivos pequeños/grandes. En tal caso, wget simplemente podría invocarse con este parámetro para obtener una salida mucho más limpia en la pantalla.

Esta opción también forzará la impresión de la barra de progreso a stderr cuando se use junto con la opción --output-file.

-N
--timestamping
Activar la marca de tiempo.
--no-if-modified-since
No enviar la cabecera If-Modified-Since en modo -N. Enviar una solicitud HEAD preliminar en su lugar. Esto solo tiene efecto en modo -N.
--no-use-server-timestamps
No establecer la marca de tiempo del archivo local con la del servidor.

Por defecto, cuando se descarga un archivo, sus marcas de tiempo se establecen para que coincidan con las del archivo remoto. Esto permite el uso de --timestamping en invocaciones posteriores de wget. Sin embargo, a veces es útil basar la marca de tiempo del archivo local en el momento en que se descargó realmente; para ello, se ha proporcionado la opción --no-use-server-timestamps.

-S
--server-response
Imprimir las cabeceras enviadas por los servidores HTTP y las respuestas enviadas por los servidores FTP.
--spider
Cuando se invoca con esta opción, Wget se comportará como una araña web, lo que significa que no descargará las páginas, solo verificará que estén allí. Por ejemplo, puedes usar Wget para comprobar tus marcadores: 
wget --spider --force-html -i bookmarks.html

Esta característica necesita mucho más trabajo para que Wget se acerque a la funcionalidad de las arañas web reales.

-T seconds
--timeout=seconds
Establecer el tiempo de espera de red a seconds segundos. Esto es equivalente a especificar --dns-timeout, --connect-timeout y --read-timeout, todos al mismo tiempo.

Al interactuar con la red, Wget puede comprobar si hay tiempo de espera y abortar la operación si tarda demasiado. Esto previene anomalías como lecturas colgadas y conexiones infinitas. El único tiempo de espera habilitado por defecto es un tiempo de espera de lectura de 900 segundos. Establecer un tiempo de espera a 0 lo deshabilita por completo. A menos que sepas lo que estás haciendo, es mejor no cambiar la configuración de tiempo de espera por defecto.

Todas las opciones relacionadas con el tiempo de espera aceptan valores decimales, así como valores subsegundarios. Por ejemplo, 0.1 segundos es una opción de tiempo de espera legal (aunque poco aconsejable). Los tiempos de espera subsegundarios son útiles para comprobar los tiempos de respuesta del servidor o para probar la latencia de la red.

--dns-timeout=seconds
Establecer el tiempo de espera de la resolución DNS
--dns-timeout=seconds
Establece el tiempo de espera de DNS a segundos segundos. Las búsquedas de DNS que no se completen dentro del tiempo especificado fallarán. Por defecto, no hay tiempo de espera en las búsquedas de DNS, aparte del implementado por las bibliotecas del sistema.
--connect-timeout=seconds
Establece el tiempo de espera de conexión a segundos segundos. Las conexiones TCP que tarden más en establecerse se abortarán. Por defecto, no hay tiempo de espera de conexión, aparte del implementado por las bibliotecas del sistema.
--read-timeout=seconds
Establece el tiempo de espera de lectura (y escritura) a segundos segundos. El «tiempo» de este tiempo de espera se refiere al tiempo de inactividad: si, en algún momento de la descarga, no se reciben datos durante más del número de segundos especificado, la lectura falla y la descarga se reinicia. Esta opción no afecta directamente a la duración de toda la descarga.

Por supuesto, el servidor remoto puede optar por terminar la conexión antes de lo que requiere esta opción. El tiempo de espera de lectura por defecto es de 900 segundos.

--limit-rate=amount
Limita la velocidad de descarga a amount bytes por segundo. La cantidad puede expresarse en bytes, kilobytes con el sufijo k o megabytes con el sufijo m. Por ejemplo, --limit-rate=20k limitará la velocidad de recuperación a 20 KB/s. Esto es útil cuando, por cualquier motivo, no se desea que Wget consuma todo el ancho de banda disponible.

Esta opción permite el uso de números decimales, generalmente junto con sufijos de potencia; por ejemplo, --limit-rate=2.5k es un valor legal.

Tenga en cuenta que Wget implementa la limitación durmiendo la cantidad de tiempo apropiada después de una lectura de red que tomó menos tiempo que el especificado por la tasa. Con el tiempo, esta estrategia hace que la transferencia TCP se ralentice aproximadamente a la tasa especificada. Sin embargo, puede llevar algún tiempo lograr este equilibrio, así que no se sorprenda si limitar la tasa no funciona bien con archivos muy pequeños.

-w seconds
--wait=seconds
Espera el número especificado de segundos entre recuperaciones. Se recomienda el uso de esta opción, ya que aligera la carga del servidor al hacer las solicitudes con menos frecuencia. En lugar de segundos, el tiempo puede especificarse en minutos usando el sufijo "m", en horas usando el sufijo "h" o en días usando el sufijo "d".

Especificar un valor grande para esta opción es útil si la red o el host de destino están caídos, de modo que Wget pueda esperar lo suficiente para esperar razonablemente que el error de red se solucione antes de reintentar. El intervalo de espera especificado por esta función está influenciado por "--random-wait", véase.

--waitretry=seconds
Si no desea que Wget espere entre cada recuperación, sino solo entre reintentos de descargas fallidas, puede usar esta opción. Wget utilizará la exponenciación lineal, esperando 1 segundo después del primer fallo en un archivo determinado, luego esperando 2 segundos después del segundo fallo en ese archivo, hasta el número máximo de segundos que especifique.

Por defecto, Wget asumirá un valor de 10 segundos.

--random-wait
Algunos sitios web pueden realizar análisis de registro para identificar programas de recuperación como Wget buscando similitudes estadísticamente significativas en el tiempo entre solicitudes. Esta opción hace que el tiempo entre solicitudes varíe entre 0.5 y 1.5 * wait segundos, donde wait se especificó usando la opción --wait, para enmascarar la presencia de Wget de dicho análisis.

Un artículo de 2001 en una publicación dedicada al desarrollo en una plataforma de consumo popular proporcionó código para realizar este análisis sobre la marcha. Su autor sugirió bloquear a nivel de dirección de clase C para garantizar que los programas de recuperación automática fueran bloqueados a pesar de cambiar las direcciones proporcionadas por DHCP.

La opción --random-wait se inspiró en esta desafortunada recomendación de bloquear a muchos usuarios no relacionados de un sitio web debido a las acciones de uno.

--no-proxy
No utilice proxies, incluso si la variable de entorno *_proxy correspondiente está definida.
-Q quota
--quota=quota
Especifique la cuota de descarga para recuperaciones automáticas. El valor puede especificarse en bytes (por defecto), kilobytes (con el sufijo k) o megabytes (con el sufijo m).

Tenga en cuenta que la cuota nunca afectará a la descarga de un solo archivo. Así que si especifica wget -Q10k https://example.com/ls-lR.gz, se descargará todo el ls-lR.gz. Lo mismo ocurre incluso cuando se especifican varias URLs en la línea de comandos. La cuota se comprueba solo al final de cada archivo descargado, por lo que nunca resultará en un archivo parcialmente descargado. Por lo tanto, puede escribir de forma segura wget -Q2m -i sitios; la descarga se abortará después de que el archivo que agota la cuota se haya descargado por completo.

Establecer la cuota a 0 o a inf elimina el límite de la cuota de descarga.

--no-dns-cache
Desactiva el almacenamiento en caché de las búsquedas de DNS. Normalmente, Wget recuerda las direcciones IP que buscó en DNS para no tener que contactar repetidamente al servidor DNS para los mismos hosts (típicamente pequeños) de los que recupera datos. Esta caché existe solo en memoria; una nueva ejecución de Wget contactará al DNS nuevamente.

Sin embargo, se ha informado que en algunas situaciones no es deseable almacenar en caché nombres de host, incluso durante la duración de una aplicación de corta ejecución como Wget. Con esta opción, Wget realiza una nueva búsqueda de DNS (más precisamente, una nueva llamada a "gethostbyname" o "getaddrinfo") cada vez que realiza una nueva conexión. Tenga en cuenta que esta opción no afectará al almacenamiento en caché que pueda realizar la biblioteca de resolución o una capa de almacenamiento en caché externa, como NSCD.

Si no entiende exactamente lo que hace esta opción, probablemente no la necesite.

--restrict-file-names=modes
Cambia qué caracteres encontrados en las URL remotas deben ser escapados durante la generación de nombres de archivo locales. Los caracteres que están restringidos por esta opción son escapados, es decir, reemplazados por %HH, donde HH es el número hexadecimal que corresponde al carácter restringido. Esta opción también puede usarse para forzar que todas las letras mayúsculas se conviertan en minúsculas o mayúsculas.

Por defecto, Wget escapa los caracteres que no son válidos o seguros como parte de los nombres de archivo en su sistema operativo, así como los caracteres de control que normalmente no son imprimibles. Esta opción es útil para cambiar estos valores predeterminados, quizás porque está descargando en una partición no nativa, o porque desea deshabilitar el escape de los caracteres de control, o desea restringir aún más los caracteres a solo aquellos en el rango de valores ASCII.

Los modos son un conjunto de valores de texto separados por comas. Los valores aceptables son unix, windows, nocontrol, ascii, lowercase y uppercase. Los valores unix y windows son mutuamente excluyentes (uno anulará al otro), al igual que lowercase y uppercase. Estos últimos son casos especiales, ya que no cambian el conjunto de caracteres que serían escapados, sino que fuerzan que las rutas de archivo locales se conviertan a minúsculas o mayúsculas.

Cuando se especifica "unix", Wget escapa el carácter / y los caracteres de control en los rangos 0--31 y 128--159. Este es el valor predeterminado en los sistemas operativos tipo Unix.

Cuando se especifica "windows", Wget escapa los caracteres \, |, /, :, ?, ", *, <, >, y los caracteres de control en los rangos 0--31 y 128--159. Además de esto, Wget en modo Windows utiliza + en lugar de : para separar el host y el puerto en los nombres de archivo locales, y utiliza @ en lugar de ? para separar la parte de consulta del nombre de archivo del resto. Por lo tanto, una URL que se guardaría como www.xemacs.org:4300/search.pl?input=blah en modo Unix se guardaría como www.xemacs.org+4300/search.pl@input=blah en modo Windows. Este modo es el valor predeterminado en Windows.

Si especifica nocontrol, entonces el escape de los caracteres de control también se desactiva. Esta opción puede tener sentido cuando se descargan URL cuyos nombres contienen caracteres UTF-8, en un sistema que puede guardar y mostrar nombres de archivo en UTF-8 (algunos posibles valores de bytes utilizados en secuencias de bytes UTF-8 caen en el rango de valores designados por Wget como "controles").

El modo ascii se utiliza para especificar que cualquier byte cuyos valores estén fuera del rango de los caracteres ASCII (es decir, mayor que 127) será escapado. Esto puede ser útil al guardar nombres de archivo cuya codificación no coincide con la utilizada localmente.

-4
--inet4-only
-6
--inet6-only
Fuerza la conexión a direcciones IPv4 o IPv6. Con --inet4-only o -4, Wget solo se conectará a hosts IPv4, ignorando los registros AAAA en DNS y negándose a conectarse a direcciones IPv6 especificadas en las URL. Por el contrario, con --inet6-only o -6, Wget solo se conectará a hosts IPv6 e ignorará los registros A y las direcciones IPv4.

Ninguna de las opciones debería ser necesaria normalmente. Por defecto, un Wget compatible con IPv6 utilizará la familia de direcciones especificada por el registro DNS del host. Si el DNS responde con direcciones IPv4 e IPv6, Wget las probará en secuencia hasta que encuentre una a la que pueda conectarse. (Consulte también la opción "--prefer-family" descrita a continuación).

Estas opciones se pueden utilizar para forzar deliberadamente el uso de familias de direcciones IPv4 o IPv6 en sistemas duales, generalmente para ayudar a la depuración o para tratar con configuraciones de red defectuosas. Solo se puede especificar una de las opciones --inet6-only y --inet4-only.

 igual. Ninguna de las opciones está disponible en Wget compilado sin soporte IPv6.

--prefer-family=none/IPv4/IPv6
Cuando se le da a elegir entre varias direcciones, conéctese primero a las direcciones con la familia de direcciones especificada. El orden de las direcciones devuelto por DNS se utiliza sin cambios por defecto.

Esto evita errores y intentos de conexión erróneos al acceder a hosts que se resuelven tanto a direcciones IPv6 como IPv4 desde redes IPv4. Por ejemplo, www.kame.net se resuelve a 2001:200:0:8002:203:47ff:fea5:3085 y a 203.178.141.194. Cuando la familia preferida es "IPv4", se utiliza primero la dirección IPv4; cuando la familia preferida es "IPv6", se utiliza primero la dirección IPv6; si el valor especificado es "none", el orden de las direcciones devuelto por DNS se utiliza sin cambios.

A diferencia de -4 y -6, esta opción no inhibe el acceso a ninguna familia de direcciones, solo cambia el *orden* en el que se accede a las direcciones. Tenga en cuenta también que la reordenación realizada por esta opción es *estable*, no afecta al orden de las direcciones de la misma familia. Es decir, el orden relativo de todas las direcciones IPv4 y de todas las direcciones IPv6 permanece intacto en todos los casos.

--retry-connrefused
Considere "conexión rechazada" como un error transitorio e intente de nuevo. Normalmente Wget abandona una URL cuando no puede conectarse al sitio porque la falla de conexión se toma como una señal de que el servidor no se está ejecutando en absoluto y que los reintentos no ayudarían. Esta opción es para la duplicación de sitios no confiables cuyos servidores tienden a desaparecer por cortos períodos de tiempo.
--user=usuario
--password=contraseña
Especifique el nombre de usuario usuario y la contraseña contraseña para la recuperación de archivos FTP y HTTP. Estos parámetros pueden ser anulados utilizando las opciones --ftp-user y --ftp-password para conexiones FTP y las opciones --http-user y --http-password para conexiones HTTP.
--ask-password
Solicite una contraseña para cada conexión establecida. No se puede especificar cuando se está utilizando --password, ya que son mutuamente excluyentes.
--use-askpass=comando
Solicite un usuario y contraseña utilizando el comando especificado. Si no se especifica ningún comando, se utiliza el comando en la variable de entorno WGET_ASKPASS. Si WGET_ASKPASS no está configurada, se utiliza el comando en la variable de entorno SSH_ASKPASS.

Puede establecer el comando predeterminado para use-askpass en el archivo .wgetrc. Esa configuración puede ser anulada desde la línea de comandos.

--no-iri
Desactivar el soporte de URI internacionalizados (IRI). Use --iri para activarlo. El soporte IRI está activado por defecto.

Puede establecer el estado predeterminado del soporte IRI utilizando el comando "iri" en .wgetrc. Esa configuración puede ser anulada desde la línea de comandos.

--local-encoding=codificación
Forzar a Wget a usar codificación como la codificación del sistema predeterminada. Esto afecta a cómo Wget convierte las URL especificadas como argumentos de la configuración regional a UTF-8 para el soporte IRI.

Wget utiliza la función nl_langinfo() y luego la variable de entorno "CHARSET" para obtener la configuración regional. Si falla, se utiliza ASCII.

Puede establecer la codificación local predeterminada utilizando el comando "local_encoding" en .wgetrc. Esa configuración puede ser anulada desde la línea de comandos.

--remote-encoding=codificación
Forzar a Wget a usar codificación como la codificación del servidor remoto predeterminada. Esto afecta a cómo Wget convierte las URI encontradas en archivos de la codificación remota a UTF-8 durante una recuperación recursiva. Esta opción solo es útil para el soporte IRI, para la interpretación de caracteres no ASCII.

Para HTTP, la codificación remota se puede encontrar en la cabecera HTTP "Content-Type" y en la etiqueta meta HTML "Content-Type http-equiv".

Puede establecer la codificación predeterminada utilizando el comando "remoteencoding" en .wgetrc. Esa configuración puede ser anulada desde la línea de comandos.

--unlink
Forzar a Wget a eliminar el archivo en lugar de sobrescribir el archivo existente. Esta opción es útil para descargar a un directorio con enlaces duros.

Opciones de Directorio

-nd
--no-directories
No crear una jerarquía de directorios al recuperar recursivamente. Con esta opción activada, todos los archivos se guardarán en el directorio actual, sin sobrescribir (si un nombre aparece más de una vez, los nombres de archivo obtendrán extensiones .n).
-x
--force-directories
Lo opuesto a -nd: crear una jerarquía de directorios, incluso si no se hubiera creado de otra manera. Por ejemplo, wget -x http://fly.srk.fer.hr/robots.txt guardará el archivo descargado en fly.srk.fer.hr/robots.txt.
-nH
--no-host-directories
Desactivar la generación de directorios prefijados por el host. Por defecto, al invocar Wget con -r http://fly.srk.fer.hr/ se creará una estructura de directorios que comienza con fly.srk.fer.hr/. Esta opción deshabilita dicho comportamiento.
--protocol-directories
Utilizar el nombre del protocolo como componente de directorio de los nombres de archivo locales. Por ejemplo, con esta opción, wget -r http://host guardará en http/host/... en lugar de solo en host/....
--cut-dirs=número
Ignorar número componentes de directorio. Esto es útil para obtener un control detallado sobre el directorio donde se guardará la recuperación recursiva.

Tomemos, por ejemplo, el directorio en ftp://ftp.xemacs.org/pub/xemacs/. Si lo recupera con -r, se guardará localmente bajo ftp.xemacs.org/pub/xemacs/. Si bien la opción -nH puede eliminar la parte ftp.xemacs.org/, todavía queda atrapado con pub/xemacs. Aquí es donde --cut-dirs resulta útil; hace que Wget no "vea" número componentes de directorio remotos. Aquí hay varios ejemplos de cómo funciona la opción --cut-dirs.

Sin opciones        -> ftp.xemacs.org/pub/xemacs/
-nH               -> pub/xemacs/
-nH --cut-dirs=1  -> xemacs/
-nH --cut-dirs=2  -> .

--cut-dirs=1      -> ftp.xemacs.org/xemacs/
...

Si solo desea deshacerse de la estructura de directorios, esta opción es similar a una combinación de -nd y -P. Sin embargo, a diferencia de -nd, --cut-dirs no pierde subdirectorios; por ejemplo, con -nH --cut-dirs=1, un subdirectorio beta/ se colocará en xemacs/beta, como cabría esperar.

-P prefijo
--directory-prefix=prefijo
Establecer el prefijo del directorio a prefijo. El prefijo del directorio es el directorio donde se guardarán todos los demás archivos y subdirectorios, es decir, la parte superior del árbol de recuperación. El valor predeterminado es . (el directorio actual).

Opciones HTTP

--default-page=nombre
Utilice nombre como nombre de archivo predeterminado cuando no se conozca (es decir, para URL que terminan en una barra), en lugar de index.html.
-E
--adjust-extension
Si se descarga un archivo de tipo application/xhtml+xml o text/html y la URL no termina con la expresión regular \.[Hh][Tt][Mm][Ll]?, esta opción hará que se añada el sufijo .html al nombre de archivo local. Esto es útil, por ejemplo, cuando se duplica un sitio remoto que utiliza páginas .asp, pero se desea que las páginas duplicadas sean visibles en su servidor Apache estándar. Otro buen uso para esto es al descargar materiales generados por CGI. Una URL como http://site.com/article.cgi?25 se guardará como article.cgi?25.html.

Tenga en cuenta que los nombres de archivo cambiados de esta manera se volverán a descargar cada vez que vuelva a duplicar un sitio, ya que Wget no puede determinar que el archivo local X.html corresponde a la URL remota X (ya que aún no sabe que la URL produce una salida de tipo text/html o application/xhtml+xml.

A partir de la versión 1.12, Wget también garantizará que cualquier archivo descargado de tipo text/css termine con el sufijo .css, y la opción se renombró de --html-extension para reflejar mejor su nuevo comportamiento. El nombre de opción anterior todavía es aceptable, pero ahora debe considerarse obsoleto.

A partir de la versión 1.19.2, Wget también garantizará que cualquier archivo descargado con una "Content-Encoding" de br, compress, deflate o gzip termine con los sufijos .br, .Z, .zlib y .gz respectivamente.

En algún momento en el futuro, esta opción podría expandirse para incluir sufijos para otros tipos de contenido, incluidos tipos de contenido que no son analizados por Wget.

--http-user=usuario
--http-password=con
  • --user user --password password
    • Especifica el nombre de usuario user y la contraseña password en un servidor HTTP. Según el tipo de desafío, Wget los codificará usando el esquema de autenticación "basic" (inseguro), "digest" o el esquema "NTLM" de Windows.
    • Otra forma de especificar el nombre de usuario y la contraseña es en la propia URL. Cualquiera de los métodos revela tu contraseña a quien se moleste en ejecutar "ps". Para evitar que las contraseñas sean vistas, usa --use-askpass o almacénalas en .wgetrc o .netrc, y asegúrate de proteger esos archivos de otros usuarios con "chmod". Si las contraseñas son realmente importantes, no las dejes tampoco en esos archivos; edita los archivos y elimínalas después de que Wget haya iniciado la descarga.
  • --no-http-keep-alive
    • Desactiva la función de "keep-alive" para las descargas HTTP. Normalmente, Wget pide al servidor que mantenga la conexión abierta para que, al descargar más de un documento del mismo servidor, estos se transfieran a través de la misma conexión TCP. Esto ahorra tiempo y, al mismo tiempo, reduce la carga en el servidor.
    • Esta opción es útil cuando, por alguna razón, las conexiones persistentes (keep-alive) no funcionan para ti, por ejemplo, debido a un error del servidor o a la incapacidad de los scripts del lado del servidor para manejar las conexiones.
  • --no-cache
    • Deshabilita la caché del lado del servidor. En este caso, Wget enviará directivas apropiadas al servidor remoto ( Cache-Control: no-cache y Pragma: no-cache) para obtener el archivo del servicio remoto, en lugar de devolver la versión en caché. Esto es especialmente útil para recuperar y purgar documentos obsoletos en servidores proxy.
    • La caché está permitida por defecto.
  • --no-cookies
    • Deshabilita el uso de cookies. Las cookies son un mecanismo para mantener el estado del lado del servidor. El servidor envía una cookie al cliente usando la cabecera "Set-Cookie", y el cliente responde con la misma cookie en solicitudes posteriores. Dado que las cookies permiten a los propietarios del sitio web rastrear a los visitantes y a los sitios intercambiar esta información, algunos las consideran una violación de la privacidad. Por defecto se usan cookies; sin embargo, el *almacenamiento* de cookies no está activado por defecto.
  • --load-cookies archivo
    • Carga las cookies del archivo antes de la primera recuperación HTTP. El archivo es un archivo textual en el formato originalmente utilizado por el archivo cookies.txt de Netscape.
    • Normalmente usarás esta opción al replicar sitios que requieren que estés conectado para acceder a todo o parte de su contenido. El proceso de inicio de sesión normalmente funciona haciendo que el servidor web emita una cookie HTTP al recibir y verificar tus credenciales. La cookie se reenvía luego por el navegador al acceder a esa parte del sitio, y demuestra tu identidad.
    • La replicación de un sitio así requiere que Wget envíe las mismas cookies que tu navegador envía al comunicarse con el sitio. Esto se logra con --load-cookies: simplemente apunta Wget a la ubicación del archivo cookies.txt, y enviará las mismas cookies que tu navegador enviaría en la misma situación. Diferentes navegadores guardan archivos de cookies textuales en diferentes ubicaciones:
    • "Netscape 4.x."
      • Las cookies están en ~/.netscape/cookies.txt.
    • "Mozilla y Netscape 6.x."
      • El archivo de cookies de Mozilla también se llama cookies.txt, ubicado en algún lugar bajo ~/.mozilla, en el directorio de tu perfil. La ruta completa suele terminar pareciéndose a ~/.mozilla/default/some-weird-string/cookies.txt.
    • "Internet Explorer."
      • Puedes producir un archivo de cookies que Wget pueda usar utilizando el menú Archivo, Importar y Exportar, Exportar Cookies. Esto se ha probado con Internet Explorer 5; no se garantiza que funcione con versiones anteriores.
    • "Otros navegadores."
      • Si estás utilizando otro navegador para crear tus cookies, --load-cookies solo funcionará si puedes localizar o producir un archivo de cookies en el formato Netscape que Wget espera.
    • Si no puedes usar --load-cookies, todavía podría haber una alternativa. Si tu navegador soporta un "gestor de cookies", puedes usarlo para ver las cookies utilizadas al acceder al sitio que estás replicando. Anota el nombre y el valor de la cookie, e instruye manualmente a Wget para que envíe esas cookies, omitiendo el soporte de cookies "oficial": 
      wget --no-cookies --header "Cookie: <nombre>=<valor>"
  • --save-cookies archivo
    • Guarda las cookies en el archivo antes de salir. Esto no guardará las cookies que hayan expirado o que no tengan tiempo de expiración (las llamadas "cookies de sesión"), pero consulta también --keep-session-cookies.
  • --keep-session-cookies
    • Cuando se especifica, hace que --save-cookies guarde también las cookies de sesión. Las cookies de sesión normalmente no se guardan porque están pensadas para mantenerse en memoria y olvidarse al salir del navegador. Guardarlas es útil en sitios que requieren que inicies sesión o visites la página de inicio antes de poder acceder a algunas páginas. Con esta opción, múltiples ejecuciones de Wget se consideran una sola sesión de navegador en lo que respecta al sitio.
    • Dado que el formato del archivo de cookies normalmente no contiene cookies de sesión, Wget las marca con una marca de tiempo de expiración de 0. El --load-cookies de Wget reconoce esas como cookies de sesión, pero podría confundir a otros navegadores. Ten en cuenta también que las cookies cargadas de esta manera se tratarán como otras cookies de sesión, lo que significa que si quieres que --save-cookies las preserve de nuevo, debes usar de nuevo --keep-session-cookies.
  • --ignore-length
    • Lamentablemente, algunos servidores HTTP (programas CGI, para ser más precisos) envían cabeceras "Content-Length" falsas, lo que hace que Wget se vuelva loco, ya que cree que no se ha recuperado todo el documento. Puedes detectar este síndrome si Wget intenta obtener el mismo documento una y otra vez, reclamando cada vez que la conexión (por lo demás normal) se ha cerrado en el mismo byte.
    • Con esta opción, Wget ignorará la cabecera "Content-Length", como si nunca hubiera existido.
  • --header=línea-de-cabecera
    • Envía la línea-de-cabecera junto con el resto de las cabeceras en cada solicitud HTTP. La cabecera proporcionada se envía tal cual, lo que significa que debe contener el nombre y el valor separados por dos puntos, y no debe contener saltos de línea.
    • Puedes definir más de una cabecera adicional especificando --header más de una vez. 
      wget --header='Accept-Charset: iso-8859-2' \
     --header='Accept-Language: hr'        \
       http://fly.srk.fer.hr/
    • Especificar una cadena vacía como valor de la cabecera eliminará todas las cabeceras definidas por el usuario previamente.
    • A partir de Wget 1.10, esta opción puede usarse para anular cabeceras generadas automáticamente. Este ejemplo instruye a Wget a conectarse a localhost, pero a especificar foo.bar en la cabecera "Host": 
      wget --header="Host: foo.bar" http://localhost/
    • En versiones de Wget anteriores a la 1.10, dicho uso de --header causaba el envío de cabeceras duplicadas.
  • --compression=tipo
    • Elige el tipo de compresión a utilizar. Los valores legales son auto, gzip y none.

General Options

--user-agent=agent
Specify the User-Agent line issued to the HTTP server. Some servers use the User-Agent line to differentiate the clients, and to differentiate the clients "User-Agent"-supplied information. While this is not such a bad idea in theory, it has been abused by servers denying information to clients other than (historically) Netscape or, more frequently, Microsoft Internet Explorer. This option allows you to change the "User-Agent" line issued by Wget. Use of this option is discouraged, unless you really know what you are doing.

Specifying empty user agent with --user-agent="" instructs Wget not to send the "User-Agent" header in HTTP requests.

--post-data=string
--post-file=file
Use POST as the method for all HTTP requests and send the specified data in the request body. --post-data sends string as data, whereas --post-file sends the contents of file. Other than that, they work in exactly the same way. In particular, they both expect content of the form "key1=value1&key2=value2", with percent-encoding for special characters; the only difference is that one expects its content as a command-line parameter and the other accepts its content from a file. In particular, --post-file is not for transmitting files as form attachments: those must appear as "key=value" data (with appropriate percent-coding) just like everything else. Wget does not currently support "multipart/form-data" for transmitting POST data; only "application/x-www-form-urlencoded". Only one of --post-data and --post-file should be specified.

Please note that wget does not require the content to be of the form "key1=value1&key2=value2", and neither does it test for it. Wget will simply transmit whatever data is provided to it. Most servers however expect the POST data to be in the above format when processing HTML Forms.

When sending a POST request using the --post-file option, Wget treats the file as a binary file and will send every character in the POST request without stripping trailing newline or formfeed characters. Any other control characters in the text will also be sent as-is in the POST request.

Please be aware that Wget needs to know the size of the POST data in advance. Therefore the argument to "--post-file" must be a regular file; specifying a FIFO or something like /dev/stdin won't work. It's not quite clear how to work around this limitation inherent in HTTP/1.0. Although HTTP/1.1 introduces chunked transfer that doesn't require knowing the request length in advance, a client can't use chunked unless it knows it's talking to an HTTP/1.1 server. And it can't know that until it receives a response, which in turn requires the request to have been completed -- a chicken-and-egg problem.

Note: As of version 1.15 if Wget is redirected after the POST request is completed, its behaviour will depend on the response code returned by the server. In case of a 301 Moved Permanently, 302 Moved Temporarily or 307 Temporary Redirect, Wget will, in accordance with RFC2616, continue to send a POST request. In case a server wants the client to change the Request method upon redirection, it should send a 303 See Other response code.

This example shows how to log in to a server using POST and then proceed to download the desired pages, presumably only accessible to authorized users:

# Log in to the server.  This can be done only once.
wget --save-cookies cookies.txt \
     --post-data 'user=foo&password=bar' \
     http://example.com/auth.php

# Now grab the page or pages we care about.
wget --load-cookies cookies.txt \
     -p http://example.com/interesting/article.php

If the server is using session cookies to track user authentication, the above will not work because --save-cookies will not save them (and neither will browsers) and the cookies.txt file will be empty. In that case use --keep-session-cookies along with --save-cookies to force saving of session cookies.

Using this option is intended to support special use cases only and is generally not recommended, as it can force retries even in cases where the server is actually trying to decrease its load. Please use wisely and only if you know what you are doing.

HSTS Options

--hsts-file=file
Use file to store HSTS database. By default, ~/.wget-hsts is used.

When Wget is invoked with the --hsts-file option, it will merge HSTS policies requested by the remote servers and those in the file. When Wget exits, it effectively updates the HSTS database by rewriting the database file with the new entries.

FTP Options

--ftp-user=user
--ftp-password=password
Specify the username user and password password on an FTP server. Without this, or the corresponding startup option, the password defaults to -wget@, normally used for anonymous FTP.

Another way to specify username and password is in the URL itself. Either method reveals your password to anyone who bothers to run "ps". To prevent the passwords from being seen, store them in .wgetrc or .netrc, and make sure to protect those files from other users with "chmod". If the passwords are really important, do not leave them lying in those files either---edit the files and delete them after Wget has started the download.

--no-remove-listing
Don't remove the temporary .listing files generated by FTP retrievals. Normally, these files contain the raw directory listings received from FTP servers. Not removing them can be useful for debugging purposes, or when you want to be able to easily check on the contents of remote server directories (e.g. to verify that a mirror you're running is complete).

Note that even though Wget writes to a known filename for this file, this is not a security hole in the scenario of a user making .listing a symbolic link to /etc/passwd or something and asking "root" to run Wget in his or her directory. Depending on the options used, either Wget will refuse to write to .listing, making the globbing/recursion/time-stamping operation fail, or the symbolic link will be deleted and replaced with the actual .listing file, or the listing will be written to a .listing.number file.

Even though this situation isn't a problem, though, "root" should never run Wget in a non-trusted user's directory. A user could do something as simple as linking index.html to /etc/passwd and asking "root" to run Wget with -N or -r so the file will be overwritten.

--no-glob
Turn off FTP globbing. Globbing refers to the use of shell-like special characters (wildcards), like *, ?, [ and ] to retrieve more than one file from the same directory at once, like: 
wget ftp://gnjilux.srk.fer.hr/*.msg

By default, globbing will be turned on if the URL contains a globbing character. This option may be used to turn globbing on or off permanently.

You may have to quote the URL to protect it from being expanded by your shell. Globbing makes Wget look for a directory listing, which is system-specific. This is why it currently works only with Unix FTP servers (and the ones emulating Unix "ls" output).

--no-passive-ftp
Disable the use of the passive FTP transfer mode. Passive FTP mandates that the client connect to the server to establish the data connection rather than the other way around.

If the machine is connected to the Internet directly, both passive and active FTP should work equally well. Behind most firewall and NAT configurations passive FTP has a better chance of working. However, in some rare firewall configurations, active FTP actually works when passive FTP doesn't. If you suspect this to be the case, use this option, or set "passive_ftp=off" in your init file.

--preserve-permissions
Preserve remote file permissions instead of permissions set by umask.
--retr-symlinks
By default, when retrieving FTP directories recursively and a symbolic link is encountered, the symbolic link is traversed and the pointed-to files are retrieved. Currently, Wget does not traverse symbolic links to directories to download them recursively, though this feature may be added in the future.

When --retr-symlinks=no is specified, the linked-to file is not downloaded. Instead, a matching symbolic link is created on the local file system. The pointed-to file will not be retrieved unless this recursive retrieval would have encountered it separately and downloaded it anyway. This option poses a security risk where a malicious FTP Server may cause Wget to write to files outside of the intended directories through a specially crafted .LISTING file.

Note that when retrieving a file (not a directory) because it was specified on the command-line, rather than because it was recursed to, this option has no effect. Symbolic links are always traversed in this case.

FTPS Options

--ftps-implicit
This option tells Wget to use FTPS implicitly. Implicit FTPS consists of initializing SSL/TLS from the very beginning of the control connection. This option does not send an "AUTH TLS" command: it assumes the server speaks FTPS and directly starts an SSL/TLS connection. If the attempt is successful, the session continues just like regular FTPS ("PBSZ" and "PROT" are sent, etc.). Implicit FTPS is no longer a requirement for FTPS implementations, and thus many servers may not support it. Do not resume the SSL/TLS session in the data channel. When starting a data connection, Wget tries to resume the SSL/TLS session previously started in the control connection. SSL/TLS session resumption avoids performing an entirely new handshake by reusing the SSL/TLS parameters of a previous session. Typically, the FTPS servers want it that way, so Wget does this by default. Under rare circumstances however, one might want to start an entirely new SSL/TLS session in every data connection. This is what --no-ftps-resume-ssl is for.
--ftps-clear-data-connection
All the data connections will be in plain text. Only the control connection will be under SSL/TLS. Wget will send a "PROT C" command to achieve this, which must be approved by the server.
--ftps-fallback-to-ftp

If a server does not successfully reply to the initial "AUTH TLS" command, or in the case of implicit FTPS, if the initial SSL/TLS connection attempt is rejected, it is considered that such server does not support FTPS.

Esta opción indica a Wget que elimine cada archivo que descarga, después de haberlo hecho. Es útil para pre-descargar páginas populares a través de un proxy, por ejemplo: 
wget -r -nd --delete-after http://whatever.com/~popular/page/

La opción -r es para recuperar recursivamente, y -nd para no crear directorios.

Tenga en cuenta que --delete-after elimina archivos en la máquina local. No emite el comando DELE a sitios FTP remotos, por ejemplo. Tenga en cuenta también que cuando se especifica --delete-after, se ignora --convert-links, por lo que los archivos .orig simplemente no se crean en primer lugar.

-k
--convert-links
Después de que la descarga se complete, convierta los enlaces en el documento para hacerlos adecuados para su visualización local. Esto afecta no solo a los hipervínculos visibles, sino a cualquier parte del documento que enlace a contenido externo, como imágenes incrustadas, enlaces a hojas de estilo, hipervínculos a contenido no HTML, etc.

Cada enlace se modificará de una de las dos maneras:

  • Los enlaces a archivos que han sido descargados por Wget se cambiarán para referirse al archivo al que apuntan como un enlace relativo.

    Ejemplo: si el archivo descargado /foo/doc.html enlaza a /bar/img.gif, también descargado, entonces el enlace en doc.html se modificará para apuntar a ../bar/img.gif. Este tipo de transformación funciona de manera confiable para combinaciones arbitrarias de directorios.

  • Los enlaces a archivos que no han sido descargados por Wget se cambiarán para incluir el nombre del host y la ruta absoluta de la ubicación a la que apuntan.

    Ejemplo: si el archivo descargado /foo/doc.html enlaza a /bar/img.gif (o a ../bar/img.gif), entonces el enlace en doc.html se modificará para apuntar a http://hostname/bar/img.gif.

Debido a esto, la navegación local funciona de manera confiable: si un archivo enlazado fue descargado, el enlace se referirá a su nombre local; si no fue descargado, el enlace se referirá a su dirección de Internet completa en lugar de presentar un enlace roto. El hecho de que los enlaces anteriores se conviertan en enlaces relativos asegura que puede mover la jerarquía descargada a otro directorio.

Tenga en cuenta que solo al final de la descarga Wget puede saber qué enlaces se han descargado. Debido a esto, el trabajo realizado por -k se realizará al final de todas las descargas.

--convert-file-only
Esta opción convierte solo la parte del nombre de archivo de las URL, dejando el resto de las URL sin modificar. Esta parte del nombre de archivo a veces se denomina "basename", aunque evitamos este término aquí para no causar confusión.

Funciona particularmente bien en conjunto con --adjust-extension, aunque esta combinación no está forzada. Resulta útil para poblar cachés de Internet con archivos descargados de diferentes hosts.

Ejemplo: si un enlace apunta a //foo.com/bar.cgi?xyz con --adjust-extension activada y su destino local está previsto que sea ./foo.com/bar.cgi?xyz.css, entonces el enlace se convertiría a //foo.com/bar.cgi?xyz.css. Tenga en cuenta que solo la parte del nombre de archivo se ha modificado. El resto de la URL se ha dejado sin modificar, incluida la ruta de red ("//") que de otro modo sería procesada por Wget y convertida al esquema efectivo (es decir, "http://").

-K
--backup-converted
Al convertir un archivo, haga una copia de seguridad de la versión original con un sufijo .orig. Afecta al comportamiento de -N.
-m
--mirror
Activa las opciones adecuadas para la duplicación (mirroring). Esta opción activa la recursión y la marca de tiempo, establece una profundidad de recursión infinita y conserva las listas de directorios FTP. Actualmente es equivalente a -r -N -l inf --no-remove-listing.
-p
--page-requisites
Esta opción hace que Wget descargue todos los archivos que son necesarios para mostrar correctamente una página HTML dada. Esto incluye elementos como imágenes incrustadas, sonidos y hojas de estilo referenciadas.

Normalmente, al descargar una única página HTML, no se descargan los documentos requisitos que puedan ser necesarios para mostrarla correctamente. Usar -r junto con -l puede ayudar, pero como Wget no distingue normalmente entre documentos externos e incrustados, generalmente uno se queda con "documentos hoja" que carecen de sus requisitos.

Por ejemplo, supongamos que el documento 1.html contiene una etiqueta "<IMG>" que hace referencia a 1.gif y una etiqueta "<A>" que apunta al documento externo 2.html. Supongamos que 2.html es similar pero que su imagen es 2.gif y enlaza a 3.html. Supongamos que esto continúa hasta un número arbitrariamente alto.

Si se ejecuta el comando:

wget -r -l 2 http://<sitio>/1.html

entonces se descargarán 1.html, 1.gif, 2.html, 2.gif y 3.html. Como puede ver, 3.html está sin su requisito 3.gif porque Wget simplemente está contando el número de saltos (hasta 2) desde 1.html para determinar dónde detener la recursión. Sin embargo, con este comando:

wget -r -l 2 -p http://<sitio>/1.html

se descargarán todos los archivos anteriores y el requisito de 3.html, 3.gif. De manera similar,

wget -r -l 1 -p http://<sitio>/1.html

provocará la descarga de 1.html, 1.gif, 2.html y 2.gif. Uno podría pensar que:

wget -r -l 0 -p http://<sitio>/1.html

descargaría solo 1.html y 1.gif, pero desafortunadamente este no es el caso, porque -l 0 es equivalente a -l inf, es decir, recursión infinita. Para descargar una única página HTML (o un puñado de ellas, todas especificadas en la línea de comandos o en un archivo de entrada de URL -i) y sus requisitos, simplemente omita -r y -l:

wget -p http://<sitio>/1.html

Tenga en cuenta que Wget se comportará como si se hubiera especificado -r, pero solo se descargarán esa única página y sus requisitos. Los enlaces de esa página a documentos externos no se seguirán. De hecho, para descargar una única página y todos sus requisitos (incluso si existen en sitios web separados), y asegurarse de que el conjunto se muestre correctamente localmente, a este autor le gusta usar algunas opciones además de -p:

wget -E -H -k -K -p http://<sitio>/<documento>

Para terminar este tema, vale la pena saber que la idea de Wget de un enlace de documento externo es cualquier URL especificada en una etiqueta "<A>", una etiqueta "<AREA>" o una etiqueta "<LINK>" distinta de "<LINK REL="stylesheet">".

--strict-comments
Activa el análisis estricto de comentarios HTML. Por defecto, se terminan los comentarios en la primera aparición de -->.

Según las especificaciones, los comentarios HTML se expresan como declaraciones de SGML. Una declaración es una marca especial que comienza con <! y termina con >, como <!DOCTYPE ...>, que puede contener comentarios entre un par de delimitadores --. Los comentarios HTML son "declaraciones vacías", declaraciones SGML sin texto que no sea un comentario. Por lo tanto, <!--foo--> es un comentario válido, y también lo es <!--one-- --two-->, pero <!--1--2--> no lo es.

Por otro lado, la mayoría de los autores de HTML no perciben los comentarios como algo más que texto delimitado con <!-- y -->, lo cual no es exactamente lo mismo. Por ejemplo, algo como <!------------> funciona como un comentario válido siempre que el número de guiones sea múltiplo de cuatro (!). Si no lo es, el comentario técnicamente dura hasta el siguiente --, que puede estar al otro extremo del documento. Debido a esto, muchos navegadores populares ignoran por completo la especificación e implementan lo que los usuarios han llegado a esperar: comentarios delimitados por <!-- y -->.

Hasta la versión 1.9, Wget interpretaba los comentarios estrictamente, lo que resultaba en la pérdida de enlaces en muchas páginas web que se mostraban bien en los navegadores, pero que tenían la desgracia de contener comentarios no conformes. A partir de la versión 1.9, Wget se ha unido a las filas de los clientes que implementan comentarios "ingenuos", terminando cada comentario en la primera aparición de -->.

Si, por la razón que sea, desea un análisis estricto de comentarios, utilice esta opción para activarlo.

Turning on globbing is the default behavior when downloading from an FTP server. This option enables globbing for FTP. Turning it off disables globbing for FTP. For example, if you say -A "*.mp3", and Wget is downloading from an FTP server, the server will be asked to return only files ending in .mp3.

wget --ignore-tags=a,area -H -k -K -r http://<site>/<document>

However, the author of this option came across a page with tags like "<LINK REL="home" HREF="/">" and came to the realization that specifying tags to ignore was not enough. One can't just tell Wget to ignore "<LINK>", because then stylesheets will not be downloaded. ENVIRONMENT

Wget supports proxies for both HTTP and FTP retrievals. The standard way to specify proxy location, which Wget recognizes, is using the following environment variables:

http_proxy
https_proxy
If set, the http_proxy and https_proxy variables should contain the URLs of the proxies for HTTP and HTTPS connections respectively.
ftp_proxy
This variable should contain the URL of the proxy for FTP connections. It is quite common that http_proxy and ftp_proxy are set to the same URL.
no_proxy
This variable should contain a comma-separated list of domain extensions proxy should not be used for. For instance, if the value of no_proxy is .mit.edu, proxy will not be used to retrieve documents from MIT.

EXIT STATUS

Wget may return one of several error codes if it encounters problems.

0
No problems occurred.
1
Generic error code.
2
Parse error---for instance, when parsing command-line options, the .wgetrc or .netrc...
3
File I/O error.
4
Network failure.
5
SSL verification failure.
6
Username/password authentication failure.
7
Protocol errors.
8
Server issued an error response.

With the exceptions of 0 and 1, the lower-numbered exit codes take precedence over higher-numbered ones, when multiple types of errors are encountered.

In versions of Wget prior to 1.12, Wget's exit status tended to be unhelpful and inconsistent. Recursive downloads would virtually always return 0 (success), regardless of any issues encountered, and non-recursive fetches only returned the status corresponding to the most recently-attempted download.

BUGS

You are welcome to submit bug reports via the GNU Wget bug tracker (see <https://savannah.gnu.org/bugs/?func=additem&group=wget>) or to our mailing list <bug-wget@gnu.org>.

Visit https://lists.gnu.org/mailman/listinfo/bug-wget to get more info (how to subscribe, list archives, ...).

Before actually submitting a bug report, please try to follow a few simple guidelines.

1.
Please try to ascertain that the behavior you see really is a bug. If Wget crashes, it's a bug. If Wget does not behave as documented, it's a bug. If things work strange, but you are not sure about the way they are supposed to work, it might well be a bug, but you might want to double-check the documentation and the mailing lists.
2.
Try to repeat the bug in as simple circumstances as possible. E.g. if Wget crashes while downloading wget -rl0 -kKE -t5 --no-proxy http://example.com -o /tmp/log, you should try to see if the crash is repeatable, and if will occur with a simpler set of options. You might even try to start the download at the page where the crash occurred to see if that page somehow triggered the crash.

Also, while I will probably be interested to know the contents of your .wgetrc file, just dumping it into the debug message is probably a bad idea. Instead, you should first try to see if the bug repeats with .wgetrc moved out of the way. Only if it turns out that .wgetrc settings affect the bug, mail me the relevant parts of the file.

3.
Please start Wget with -d option and send us the resulting output (or relevant parts thereof). If Wget was compiled without debug support, recompile it---it is much easier to trace bugs with debug support on.

Note: please make sure to remove any potentially sensitive information from the debug log before sending it to the bug address. The "-d" won't go out of its way to collect sensitive information, but the log will contain a fairly complete transcript of Wget's communication with the server, which may include passwords and pieces of downloaded data. Since the bug address is publicly archived, you may assume that all bug reports are visible to the public.

4.
If Wget has crashed, try to run it in a debugger, e.g. "gdb `which wget` core" and type "where" to get the backtrace. This may not work if the system administrator has disabled core files, but it is safe to try.
