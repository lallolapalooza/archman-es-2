WL-CLIPBOARD(1) Manual de comandos generales WL-CLIPBOARD(1)

NOMBRE

wl-clipboard - Utilidades de línea de comandos para copiar y pegar en Wayland

SINOPSIS

wl-copy [--primary] [--type mime/type] [texto...]

wl-paste [--primary] [--type mime/type]

Solo se enumeran aquí las opciones más útiles; consulte más abajo para ver la lista completa.

DESCRIPCIÓN

wl-copy copia el texto dado al portapapeles de Wayland. Si no se proporciona ningún texto, wl-copy copia los datos de su entrada estándar.

wl-paste pega datos del portapapeles de Wayland en su salida estándar.

Aunque wl-copy y wl-paste están especialmente optimizados para texto plano y otros formatos de contenido textual, admiten completamente contenido de tipos MIME arbitrarios. wl-copy infiere automáticamente el tipo de contenido copiado ejecutando xdg-mime(1) sobre él. wl-paste hace todo lo posible para elegir un tipo para pegar basándose en la lista de tipos MIME ofrecidos y la extensión del archivo en el que está pegando. Si no está satisfecho con el tipo que eligen o no desea confiar en esta inferencia implícita de tipo, puede especificar explícitamente el tipo a usar con la opción --type.

OPCIONES

Para analizar las opciones, wl-clipboard utiliza las rutinas de la biblioteca getopt(3), cuyas características dependen de las bibliotecas C en uso. En particular, es posible que se pueda especificar -- como argumento por sí solo para evitar que se analicen más argumentos como opciones (lo que le permite copiar texto que contiene palabras que comienzan con el signo -), y para acortar opciones largas a sus prefijos no ambiguos.

-p, --primary
Utiliza el portapapeles "primario" en lugar del portapapeles regular.
-o, --paste-once (para wl-copy)
Sirve solo una solicitud de pegado y luego sale. A menos que se utilice un gestor de portapapeles diseñado específicamente para evitar esto, esto tiene el efecto de borrar el portapapeles después del primer pegado, lo cual es útil para copiar datos sensibles como contraseñas. Tenga en cuenta que esto puede romper el pegado en algunos clientes que esperan poder pegar varias veces, en particular se sabe que el pegado en ventanas XWayland se rompe cuando se usa esta opción.
-f, --foreground (para wl-copy)
Por defecto, wl-copy se bifurca y atiende las solicitudes de datos en segundo plano; esta opción anula ese comportamiento, haciendo que wl-copy se ejecute en primer plano.
-c, --clear (para wl-copy)
En lugar de copiar nada, borra el portapapeles para que no se copie nada.
-n, --trim-newline (para wl-copy)
No copie el carácter de nueva línea final si está presente en el archivo de entrada.
-n, --no-newline (para wl-paste)
No agregue un carácter de nueva línea después del contenido del portapapeles pegado. Esta opción se habilita automáticamente para tipos de contenido no textuales y al usar el modo --watch.
-t mime/type, --type mime/type
Anula el tipo MIME seleccionado automáticamente. Para wl-copy esta opción controla como se ofrecerá el contenido. Para wl-paste controla en qué tipo de los ofrecidos solicitará el contenido. Además de tipos MIME específicos como image/png, wl-paste también acepta nombres de tipo genéricos como text e image que le hacen elegir automáticamente algún tipo MIME ofrecido que coincida con el nombre genérico dado.
-s nombre-asiento, --seat nombre-asiento
Especifica con qué asiento deben funcionar wl-copy y wl-paste. Wayland admite de forma nativa configuraciones multiasiento donde cada asiento obtiene su propio puntero de ratón, foco de teclado y, entre otras cosas, su propio portapapeles separado. El nombre del asiento predeterminado probablemente sea default o seat0, y los nombres de asientos adicionales normalmente provienen de la propiedad udev(7) ENV{WL_SEAT}. Puede ver la lista de los asientos actualmente disponibles anunciados por el compositor usando la herramienta weston-info(1). Si no especifica el nombre del asiento explícitamente, wl-copy y wl-paste elegirán un asiento arbitrariamente. Si está utilizando un sistema de un solo asiento, hay pocas razones para usar esta opción.
-l, --list-types (para wl-paste)
En lugar de pegar la selección, muestra la lista de tipos MIME en los que se ofrece.
-w comando..., --watch comando... (para wl-paste)
En lugar de pegar una vez y salir, vigila continuamente el portapapeles en busca de cambios y ejecuta el comando especificado cada vez que aparece una nueva selección. El proceso generado puede leer el contenido del portapapeles desde su entrada estándar. wl-paste también establece la variable CLIPBOARD_STATE en el entorno de los procesos generados (ver más abajo).
Este modo requiere un compositor que admita el protocolo de control de datos de wlroots.
-v, --version
Muestra la versión de wl-clipboard y alguna información breve sobre su licencia.
-h, --help
Muestra un breve mensaje de ayuda enumerando las opciones disponibles.

ENTORNO

WAYLAND_DISPLAY
Especifica a qué servidor Wayland deben conectarse wl-copy y wl-paste. Esta es la misma variable de entorno que se pasa a otros clientes de Wayland, como las aplicaciones gráficas, que se conectan a este servidor Wayland. Normalmente la configura automáticamente la sesión gráfica y el compositor de Wayland. Consulte wl_display_connect(3) para más detalles.
WAYLAND_DEBUG
Cuando se establece en 1, hace que la biblioteca wayland-client(7) registre cada interacción que wl-copy y wl-paste realizan con el compositor de Wayland en stderr.
CLIPBOARD_STATE
Establecido por wl-paste para el comando generado en modo --watch. Actualmente los siguientes valores posibles están definidos:
CLIPBOARD_STATE=data
Indica que el portapapeles contiene datos que el comando generado puede leer desde su entrada estándar. Este es el caso más común.
CLIPBOARD_STATE=nil
Indica que el portapapeles está vacío. En este caso, la entrada estándar del comando generado se adjuntará a /dev/null. Tenga en cuenta que esto es sutilmente diferente de que el portapapeles contenga datos de tamaño cero (lo que se puede lograr, por ejemplo, ejecutando wl-copy < /dev/null).
CLIPBOARD_STATE=clear
Indica que el portapapeles está vacío debido a una solicitud de borrado explícita, como después de ejecutar wl-copy --clear. Al igual que con nil, la entrada estándar del comando se adjuntará a /dev/null.
CLIPBOARD_STATE=sensitive
Indica que el portapapeles contiene datos sensibles como una contraseña o una clave. Probablemente sea mejor evitar mostrar visiblemente o guardar permanentemente el contenido del portapapeles.

Sin embargo, los protocolos de portapapeles de Wayland existentes actualmente no permiten que wl-clipboard identifique los casos en los que se deben establecer los valores **clear** y **sensitive**, por lo que actualmente wl-clipboard solo establece **CLIPBOARD_STATE** en **data** o **nil**. El protocolo **CLIPBOARD_STATE** fue diseñado intencionadamente para no ser específico de wl-clipboard ni de Wayland; de hecho, se anima a otras herramientas de portapapeles a implementar el mismo protocolo. Actualmente, la utilidad **paste(1)** de SerenityOS se sabe que implementa el mismo protocolo **CLIPBOARD_STATE**.

ARCHIVOS

/etc/mime.types
Si está presente, **wl-paste** lo lee para inferir el tipo MIME a pegar basándose en la extensión del nombre de archivo de su salida estándar.

ERRORES

A menos que el compositor de Wayland implemente el protocolo de control de datos de wlroots, wl-clipboard tiene que recurrir a un truco para acceder al portapapeles: mostrará brevemente una pequeña superficie transparente (ventana). En algunos entornos de escritorio (en particular cuando se utilizan gestores de ventanas de mosaico), esto puede causar problemas visuales como breves destellos. En algunos casos, el compositor de Wayland no otorga el foco a la superficie emergente, lo que impide que wl-clipboard acceda al portapapeles y se manifiesta como un bloqueo.

Actualmente no hay forma de copiar datos en varios tipos MIME, como varios formatos de imagen, al mismo tiempo.
Ver https://github.com/bugaevc/wl-clipboard/issues/71.

wl-clipboard no siempre es capaz de detectar que un tipo MIME es textual, lo que puede romper el pegado en clientes que esperan formatos textuales, no *application/something*. La solución alternativa, igual que para todos los problemas de inferencia de formatos, es especificar explícitamente el tipo MIME deseado, como **wl-copy --type** *text/plain*.

**wl-copy --clear** y **wl-copy --paste-once** no siempre interactúan bien con los gestores de portapapeles que son demasiado entusiastas en preservar el contenido del portapapeles.

Las aplicaciones escritas con el kit de herramientas GTK 3 copian texto con finales de línea "\r\n" (también conocidos como CR LF), lo que sorprende a la mayoría del otro software. wl-cipboard no hace nada para rectificar esto. La solución recomendada es canalizar la salida de **wl-paste** a través de dos2unix(1) al pegar desde una aplicación GTK 3.
Ver https://gitlab.gnome.org/GNOME/gtk/-/issues/2307.

Al intentar pegar contenido copiado con **wl-copy**, **wl-copy** no comprueba si el tipo MIME solicitado está entre los que ha ofrecido, y siempre proporciona los mismos datos en respuesta.

EJEMPLOS

Copiar un mensaje de texto simple:
$ wl-copy*¡Hola mundo!
Copiar un mensaje que comienza con guiones:
wl-copy -- *--long
Copiar la lista de archivos en *~/Downloads*:
$ ls ~/Downloads | wl-copy
Copiar una imagen:
$ wl-copy < ~/Pictures/photo.png
Copiar el comando anterior:
$ wl-copy "!!"
Pegar en un archivo, sin añadir una nueva línea:
$ wl-paste -n > clipboard.txt
Ordenar el contenido del portapapeles:
$ wl-paste | sort | wl-copy
Subir el contenido del portapapeles a un pastebin en cada cambio:
$ wl-paste --watch nc paste.example.org 5555
