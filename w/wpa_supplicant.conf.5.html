NOMBRE

wpa_supplicant.conf - archivo de configuración para wpa_supplicant

DESCRIPCIÓN GENERAL

wpa_supplicant se configura mediante un archivo de texto que enumera todas las redes y políticas de seguridad aceptadas, incluidas las claves precompartidas. Consulte el archivo de configuración de ejemplo, probablemente en /usr/share/doc/wpa_supplicant/, para obtener información detallada sobre el formato de configuración y los campos compatibles.

Todas las rutas de archivos en este archivo de configuración deben utilizar una ruta completa (absoluta, no relativa al directorio de trabajo) para permitir que se cambie el directorio de trabajo. Esto puede ocurrir si wpa_supplicant se ejecuta en segundo plano.

Los cambios en el archivo de configuración se pueden recargar enviando la señal SIGHUP a wpa_supplicant ('killall -HUP wpa_supplicant'). De manera similar, la recarga se puede activar con el comando wpa_cli reconfigure.

El archivo de configuración puede incluir uno o más bloques de red, por ejemplo, uno para cada SSID utilizado. wpa_supplicant seleccionará automáticamente la mejor red basándose en el orden de los bloques de red en el archivo de configuración, el nivel de seguridad de la red (se prefiere WPA/WPA2) y la intensidad de la señal.

EJEMPLOS RÁPIDOS

1.
WPA-Personal (PSK) como red doméstica y WPA-Enterprise con EAP-TLS como red de trabajo. 
# permitir que la interfaz (por ejemplo, wpa_cli) sea utilizada por todos los usuarios del grupo 'wheel'
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
#
# red doméstica; permitir todas las cifradores válidos
network={
	ssid="casa"
	scan_ssid=1
	key_mgmt=WPA-PSK
	psk="contraseña muy secreta"
}
#
# red de trabajo; usar EAP-TLS con WPA; permitir solo cifradores CCMP y TKIP
network={
	ssid="trabajo"
	scan_ssid=1
	key_mgmt=WPA-EAP
	pairwise=CCMP TKIP
	group=CCMP TKIP
	eap=TLS
	identity="usuario@ejemplo.com"
	ca_cert="/etc/cert/ca.pem"
	client_cert="/etc/cert/usuario.pem"
	private_key="/etc/cert/usuario.prv"
	private_key_passwd="contraseña"
}
2.
WPA-RADIUS/EAP-PEAP/MSCHAPv2 con servidores RADIUS que utilizan el antiguo peaplabel (por ejemplo, Funk Odyssey y SBR, Meetinghouse Aegis, Interlink RAD-Series) 
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
network={
	ssid="ejemplo"
	scan_ssid=1
	key_mgmt=WPA-EAP
	eap=PEAP
	identity="usuario@ejemplo.com"
	password="foobar"
	ca_cert="/etc/cert/ca.pem"
	phase1="peaplabel=0"
	phase2="auth=MSCHAPV2"
}
3.
Configuración EAP-TTLS/EAP-MD5-Challenge con identidad anónima para uso no cifrado. La identidad real se envía solo dentro de un túnel TLS cifrado. 
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
network={
	ssid="ejemplo"
	scan_ssid=1
	key_mgmt=WPA-EAP
	eap=TTLS
	identity="usuario@ejemplo.com"
	anonymous_identity="anonimo@ejemplo.com"
	password="foobar"
	ca_cert="/etc/cert/ca.pem"
	phase2="auth=MD5"
}
4.
IEEE 802.1X (es decir, sin WPA) con claves WEP dinámicas (requiere unidifusión y difusión); usar EAP-TLS para la autenticación 
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
network={
	ssid="1x-test"
	scan_ssid=1
	key_mgmt=IEEE8021X
	eap=TLS
	identity="usuario@ejemplo.com"
	ca_cert="/etc/cert/ca.pem"
	client_cert="/etc/cert/usuario.pem"
	private_key="/etc/cert/usuario.prv"
	private_key_passwd="contraseña"
	eapol_flags=3
}
5.
Ejemplo general que permite más o menos todos los modos de configuración. Las opciones de configuración se utilizan en función de la política de seguridad utilizada en el SSID seleccionado. Esto es principalmente para pruebas y no se recomienda para uso normal. 
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
network={
	ssid="ejemplo"
	scan_ssid=1
	key_mgmt=WPA-EAP WPA-PSK IEEE8021X NONE
	pairwise=CCMP TKIP
	group=CCMP TKIP WEP104 WEP40
	psk="contraseña muy secreta"
	eap=TTLS PEAP TLS
	identity="usuario@ejemplo.com"
	password="foobar"
	ca_cert="/etc/cert/ca.pem"
	client_cert="/etc/cert/usuario.pem"
	private_key="/etc/cert/usuario.prv"
	private_key_passwd="contraseña"
	phase1="peaplabel=0"
	ca_cert2="/etc/cert/ca2.pem"
	client_cert2="/etc/cer/usuario.pem"
	private_key2="/etc/cer/usuario.prv"
	private_key2_passwd="contraseña"
}
6.
Autenticación para Ethernet cableada. Esto se puede usar con la interfaz wired o roboswitch (-Dwired o -Droboswitch en la línea de comandos). 
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=wheel
ap_scan=0
network={
	key_mgmt=IEEE8021X
	eap=MD5
	identity="usuario"
	password="contraseña"
	eapol_flags=0
}

CERTIFICADOS

Algunos métodos de autenticación EAP requieren el uso de certificados. EAP-TLS utiliza certificados tanto del lado del servidor como del cliente, mientras que EAP-PEAP y EAP-TTLS solo requieren el certificado del lado del servidor. Cuando se utiliza un certificado de cliente, también se debe incluir un archivo de clave privada coincidente en la configuración. Si la clave privada utiliza una contraseña, esta debe configurarse en wpa_supplicant.conf ("private_key_passwd").

wpa_supplicant admite certificados X.509 en formatos PEM y DER. El certificado de usuario y la clave privada se pueden incluir en el mismo archivo.

Si el certificado de usuario y la clave privada se reciben en formato PKCS#12/PFX, deben convertirse a un formato PEM/DER adecuado para wpa_supplicant. Esto se puede hacer, por ejemplo, con los siguientes comandos:

# convertir certificado de cliente y clave privada a formato PEM
openssl pkcs12 -in example.pfx -out user.pem -clcerts
# convertir certificado CA (si está incluido en el archivo PFX) a formato PEM
openssl pkcs12 -in example.pfx -out ca.pem -cacerts -nokeys
