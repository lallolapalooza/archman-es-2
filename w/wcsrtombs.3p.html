WCSRTOMBS(3P) Manual del programador POSIX WCSRTOMBS(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

wcsnrtombs, wcsrtombs — convertir una cadena de caracteres anchos a una cadena de caracteres (reanudable)

SINOPSIS

#include <wchar.h>
size_t wcsnrtombs(char *restrict dst, const wchar_t **restrict src,
    size_t nwc, size_t len, mbstate_t *restrict ps);
size_t wcsrtombs(char *restrict dst, const wchar_t **restrict src,
    size_t len, mbstate_t *restrict ps);

DESCRIPCIÓN

Para wcsrtombs(): la funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es no intencional. Este volumen de POSIX.1‐2017 remite al estándar ISO C.

La función wcsrtombs() convertirá una secuencia de caracteres anchos del array indirectamente apuntado por src a una secuencia de caracteres correspondientes, comenzando en el estado de conversión descrito por el objeto apuntado por ps. Si dst no es un puntero nulo, los caracteres convertidos se almacenarán en el array apuntado por dst. La conversión continuará hasta e incluyendo un carácter ancho nulo terminador, que también se almacenará. La conversión se detendrá antes en los siguientes casos:

*
Cuando se alcance un código que no corresponde a un carácter válido
*
Cuando el siguiente carácter exceda el límite de len bytes totales a almacenar en el array apuntado por dst (y dst no sea un puntero nulo)

Cada conversión se realizará como si fuera una llamada a la función wcrtomb().

Si dst no es un puntero nulo, el objeto puntero apuntado por src se asignará bien un puntero nulo (si la conversión se detuvo debido a alcanzar un carácter ancho nulo terminador) o la dirección justo después del último carácter ancho convertido (si lo hubiera). Si la conversión se detuvo debido a alcanzar un carácter ancho nulo terminador, el estado resultante descrito será el estado de conversión inicial.

Si ps es un puntero nulo, la función wcsrtombs() utilizará su propio objeto mbstate_t interno, que se inicializa al inicio del programa al estado de conversión inicial. De lo contrario, el objeto mbstate_t apuntado por ps se utilizará para describir completamente el estado de conversión actual de la secuencia de caracteres asociada.

Las funciones wcsnrtombs() y wcsrtombs() no necesitan ser seguras para hilos si se llaman con un argumento ps nulo.

La función wcsnrtombs() será equivalente a la función wcsrtombs(), excepto que la conversión se limita a los primeros nwc caracteres anchos.

La función wcsrtombs() no cambiará la configuración de errno si tiene éxito.

El comportamiento de estas funciones se verá afectado por la categoría LC_CTYPE de la configuración regional actual.

La implementación se comportará como si ninguna función definida en el volumen Interfaces del Sistema de POSIX.1‐2017 llamara a estas funciones.

VALOR DE RETORNO

Si la conversión se detiene porque se alcanza un código que no corresponde a un carácter válido, ocurre un error de codificación. En este caso, estas funciones almacenarán el valor de la macro [EILSEQ] en errno y devolverán (size_t)-1; el estado de conversión es indefinido. De lo contrario, estas funciones devolverán el número de bytes en la secuencia de caracteres resultante, sin incluir el nulo terminador (si lo hubiera).

ERRORES

Estas funciones fallarán si:

EILSEQ
Un código de carácter ancho no corresponde a un carácter válido.

Estas funciones pueden fallar si:

EINVAL
ps apunta a un objeto que contiene un estado de conversión inválido.
