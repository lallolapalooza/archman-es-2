WC(1P) Manual de Programador POSIX WC(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

wc — conteo de palabras, líneas y bytes o caracteres

SINOPSIS

wc [-c|-m] [-lw] [archivo...]

DESCRIPCIÓN

El utilitario wc leerá uno o más archivos de entrada y, por defecto, escribirá en la salida estándar el número de caracteres de <nueva línea>, palabras y bytes contenidos en cada archivo de entrada.

El utilitario también escribirá un conteo total para todos los archivos nombrados, si se especifica más de un archivo de entrada.

El utilitario wc considerará una palabra como una cadena de caracteres de longitud distinta de cero delimitada por espacios en blanco.

OPCIONES

El utilitario wc cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Pautas de Sintaxis de Utilitarios.

Se soportarán las siguientes opciones:

-c
Escribir en la salida estándar el número de bytes en cada archivo de entrada.
-l
Escribir en la salida estándar el número de caracteres de <nueva línea> en cada archivo de entrada.
-m
Escribir en la salida estándar el número de caracteres en cada archivo de entrada.
-w
Escribir en la salida estándar el número de palabras en cada archivo de entrada.

Cuando se especifica alguna opción, wc informará solo la información solicitada por las opciones especificadas.

OPERANDOS

Se soportará el siguiente operando:

archivo
Un nombre de ruta de un archivo de entrada. Si no se especifican operandos de archivo, se utilizará la entrada estándar.

ENTRADA ESTÁNDAR

Se utilizará la entrada estándar si no se especifican operandos de archivo, y se utilizará si un operando de archivo es '-' y la implementación trata el '-' como entrada estándar. De lo contrario, no se utilizará la entrada estándar. Consulte la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

Los archivos de entrada pueden ser de cualquier tipo.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de wc:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de locale.)
LC_ALL
Si se establece en un valor de cadena no vacío, anule los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar el locale para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a multibyte en argumentos y archivos de entrada) y qué caracteres se definen como caracteres de espacio en blanco.
LC_MESSAGES

Determinar el locale que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar y los mensajes informativos escritos en la salida estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

Por defecto, la salida estándar contendrá una entrada para cada archivo de entrada del formato:

"%d %d %d %s\n", <nuevas líneas>, <palabras>, <bytes>, <archivo>

Si se especifica la opción -m, el número de caracteres reemplazará el campo <bytes> en este formato.

Si se especifican opciones y no se especifica la opción -l, no se escribirá el número de caracteres de <nueva línea>.

Si se especifican opciones y no se especifica la opción -w, no se escribirá el número de palabras.

Si se especifican opciones y no se especifica ni -c ni -m, no se escribirá el número de bytes o caracteres.

Si no se especifican operandos de archivo de entrada, no se escribirá ningún nombre y no se escribirán caracteres de <espacio en blanco> que precedan al nombre de ruta.

Si se especifican más de un operando de archivo de entrada, se escribirá una línea adicional, del mismo formato que las otras líneas, excepto que la palabra total (en el locale POSIX) se escribirá en lugar de un nombre de ruta y se escribirán los totales de cada columna según corresponda. Dicha línea adicional, si existe, se escribe al final de la salida.

SALIDA DE ERROR ESTÁNDAR

La salida de error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

Ninguna.

 0

>0

USO POR PARTE DE LAS APLICACIONES

La opción -m no es un conmutador, sino una opción al mismo nivel que -c. Por lo tanto, para producir la salida predeterminada completa con recuentos de caracteres en lugar de bytes, el comando requerido es:

wc -mlw

EJEMPLOS

Ninguno.

FUNDAMENTO

La cadena de formato de la salida del pseudo-printf() difiere de la versión de System V de wc:

"%7d%7d%7d %s\n"

que produce resultados posiblemente ambiguos e irrecuperables para archivos muy grandes, ya que asume que ningún número excederá los seis dígitos.

Algunas implementaciones históricas utilizan solo <espacio en blanco>, <tabulador> y <nueva línea> como separadores de palabras. El equivalente a la función isspace() del estándar ISO C es más apropiado.

La opción -c significa conteo de ``caracteres'', aunque cuente bytes. Esto proviene de la visión histórica a veces errónea de que los bytes y los caracteres son del mismo tamaño. Debido a requisitos internacionales, se añadió la opción -m (que recuerda a ``multibyte'') para obtener recuentos reales de caracteres.

RATIONALE

The wc utility counts lines, words, and bytes. The definitions of these quantities are straightforward:

  • A line is defined as a sequence of zero or more non-newline characters followed by a newline character.
  • A word is defined as a contiguous sequence of non-blank characters, where blank characters are the space (' '), tab ('\t'), and newline ('\n') characters.
  • A byte is equivalent to a character in the POSIX locale.

The wc utility has historically supported multiple options to specify which counts to write. However, the historical implementations varied regarding the handling of multiple option occurrences and the order of fields.

This volume of POSIX.1‐2017 specifies that:

  • The options -c, -l, and -w are independent.
  • Each specified option causes its corresponding count to be written.
  • The order of the options on the command line determines the order of the fields in the output.

Historical implementations of the wc utility only accepted one argument to specify the options -c, -l, and -w. Some of them also had multiple occurrences of an option cause the corresponding count to be written multiple times and had the order of specification of the options affect the order of the fields on output, but did not document either of these. Because common usage either specifies no options or only one option, and because none of this was documented, the changes required by this volume of POSIX.1‐2017 should not break many historical applications (and do not break any historical conforming applications).
