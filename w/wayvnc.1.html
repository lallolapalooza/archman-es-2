wayvnc(1) Manual de Comandos Generales wayvnc(1)

NOMBRE

wayvnc - Un servidor VNC para compositores de Wayland basados en wlroots.

SINOPSIS

wayvnc [opciones] [dirección [puerto]]

OPCIONES

-C, --config=<ruta>

Selecciona un archivo de configuración.

-d, --disable-input

Deshabilita toda la entrada remota. Esto permite usar wayvnc sin soporte del compositor para protocolos virtuales de ratón/teclado.

-D, --detached

Inicia desconectado de un compositor. Ejecuta wayvncctl attach para adjuntarte a un compositor.

-f, --max-fps=<fps>

Establece el límite de velocidad (por defecto 30).

-g, --gpu

Habilita características que requieren GPU.

-h, --help

Obtiene ayuda.

-k, --keyboard=<layout>[-variant]

Selecciona la distribución del teclado. La variante puede añadirse si es necesario.

-L, --log-level

Establece el nivel de registro. Los niveles son: error, warning, info, debug, trace y quiet (silencioso).

-o, --output=<nombre>

Selecciona la salida a capturar.

-p, --show-performance

Muestra contadores de rendimiento.

-r, --render-cursor

Habilita la renderización del cursor superpuesto.

-R, --disable-resizing

Deshabilita el redimensionamiento automático del escritorio.

-s, --seat=<nombre>

Selecciona el asiento por nombre.

-t, --transient-seat

Crea un asiento transitorio para cada sesión de cliente.

-S, --socket=<ruta>

Establece la ruta del socket de control de wayvnc. Por defecto: $XDG_RUNTIME_DIR/wayvncctl o /tmp/wayvncctl-$UID

-u, --unix-socket

Crea un socket de dominio UNIX en lugar de TCP, tratando la dirección como una ruta.

-v, --verbose

Sea más verboso. Igual que establecer `--log-level=info`.

-V, --version

Muestra información de la versión.

-w, --websocket

Crea un websocket.

-x, --external-listener-fd

Que el servidor VNC escuche en un socket ya enlazado. El argumento de dirección se convierte en un descriptor de archivo que debe ser heredado del proceso padre de wayvnc.

DESCRIPCIÓN

Este es un servidor VNC para compositores de Wayland basados en wlroots. Se conecta a una sesión de Wayland en ejecución, crea dispositivos de entrada virtuales y expone una única pantalla a través del protocolo RFB. La sesión de Wayland puede ser sin cabeza, por lo que también es posible ejecutar wayvnc sin una pantalla física conectada.

MÚLTIPLES SALIDAS

Si la sesión de Wayland consta de varias salidas, solo se capturará una. Por defecto, será la primera, pero se puede especificar mediante el argumento de línea de comandos -o. El argumento acepta el nombre corto como eDP-1 o DP-4. Ejecutar wayvnc en modo verboso (-v) mostrará los nombres de todas las salidas al inicio, o puede consultarlas en tiempo de ejecución a través del comando wayvncctl output-list.

También puede cambiar qué salida se está capturando sobre la marcha a través del comando wayvncctl output-set.

CONFIGURACIÓN

wayvnc busca un archivo de configuración en la ubicación

~/$XDG_CONFIG_HOME/wayvnc/config
o si $XDG_CONFIG_HOME no está establecido
~/.config/wayvnc/config

SINTAXIS

El archivo de configuración consta de pares clave-valor separados por un signo igual. Los espacios en blanco alrededor de la clave o el valor son insignificantes y no se consideran parte de la clave o del valor.

PALABRAS_CLAVE

address

La dirección a la que se enlazará el servidor, p.ej., 0.0.0.0 o localhost.

certificate_file

La ruta al archivo del certificado para cifrado. Solo aplicable cuando enable_auth=true.

enable_auth

Habilita la autenticación y el cifrado. Establecer este valor en true requiere también establecer certificate_file, private_key_file, username y password.

password

Elige una contraseña para la autenticación.

port

El puerto al que se enlazará el servidor. Por defecto es 5900.

private_key_file_file

La ruta al archivo de clave privada para el cifrado TLS. Solo aplicable cuando enable_auth=true.

relax_encryption

No requerir cifrado después de que el usuario haya sido autenticado. Esto habilita algunos tipos de seguridad como Apple Diffie-Hellman.

rsa_private_key_file

La ruta al archivo de clave privada para el cifrado RSA-AES. Solo aplicable cuando enable_auth=true.

username

Elige un nombre de usuario para la autenticación.

use_relative_paths

Hace que las rutas de archivo sean relativas a la ubicación del archivo de configuración.

xkb_layout

La distribución del teclado a usar para la búsqueda de códigos de tecla.

Por defecto: XKB_DEFAULT_LAYOUT o el valor predeterminado del sistema.

xkb_model

El modelo de teclado por el cual interpretar los códigos de tecla y los LEDs.

Por defecto: "pc105"

xkb_options

Una lista de opciones separadas por comas, a través de las cuales el usuario especifica preferencias no relacionadas con la distribución, como qué tecla es la tecla Compose.

Por defecto: XKB_DEFAULT_OPTIONS o el valor predeterminado del sistema.

xkb_rules

El archivo de reglas describe cómo interpretar los valores de los campos de modelo, distribución, variante y opciones.

Por defecto: XKB_DEFAULT_RULES o el valor predeterminado del sistema.

xkb_variant

La variante del teclado a usar para la búsqueda de códigos de tecla.

Por defecto: XKB_DEFAULT_VARIANT o el valor predeterminado del sistema.

EJEMPLO

use_relative_paths=true
address=0.0.0.0
enable_auth=true
username=luser
password=p455w0rd
rsa_private_key_file=rsa_key.pem
private_key_file=tls_key.pem
certificate_file=tls_cert.pem

SOCKET_DE_CONTROL_WAYVNCCTL

Para facilitar la interacción y el control en tiempo de ejecución, wayvnc abre un socket de dominio unix en $XDG_RUNTIME_DIR/wayvncctl (o una alternativa de respaldo de /tmp/wayvncctl-$UID). Un cliente puede conectarse e intercambiar mensajes IPC formateados en JSON para consultar y controlar la instancia de wayvnc en ejecución.

COMANDOS_IPC

HELP

El comando help, cuando se ejecuta sin parámetros, enumera los nombres de todos los comandos disponibles.

Si un parámetro opcional command se refiere a uno de esos comandos por nombre, los datos de respuesta serán una descripción detallada de ese comando y sus parámetros.

EVENT-RECEIVE

El comando event-receive se registra para eventos de servidor asíncronos. Consulte la sección EVENTOS a continuación para obtener detalles sobre el formato del mensaje de evento, y la sección IPC EVENTOS a continuación para una descripción de todos los eventos posibles del servidor.

El registro de eventos se registra para todos los eventos de servidor disponibles y tiene el alcance de la conexión actual únicamente. Si un cliente se desconecta y vuelve a conectarse, debe volver a registrarse para recibir eventos.

CLIENT-LIST

El comando client-list recupera una lista de todos los clientes VNC actualmente conectados a wayvnc.

CLIENT-DISCONNECT

El comando client-disconnect desconecta un único cliente VNC.

Parámetros:

id

Requerido: El ID
del cliente para desconectarse. Este ID se puede encontrar en el comando GET-CLIENTS o al recibir un evento CLIENT-CONNECTED.

OUTPUT-LIST

El comando output-list recupera una lista de todas las salidas conocidas por wayvnc y si cada una está siendo capturada actualmente o no.

OUTPUT-CYCLE

Para pantallas Wayland con múltiples salidas, el comando output-cycle cambia la salida que está siendo capturada activamente por wayvnc. Ejecutarlo una vez cambiará a la siguiente salida disponible. Si no hay más salidas disponibles, vuelve a la primera.

OUTPUT-SET

Para pantallas Wayland con múltiples salidas, el comando output-set cambia la salida que está siendo capturada activamente por wayvnc por nombre.

output-name=nombre

Requerido: El nombre de la salida a capturar a continuación.

VERSION

El comando version consulta la instancia de wayvnc en ejecución para obtener información sobre su versión. De forma similar a la opción -V, los datos de respuesta contendrán los números de versión de wayvnc, así como las versiones de los componentes neatvnc y aml.

WAYVNC-EXIT

El comando wayvnc-exit desconecta todos los clientes y apaga wayvnc.

EVENTOS IPC

CAPTURE_CHANGED

El evento capture-changed se envía cuando cambia la salida capturada actualmente.

Parámetros:

output=...

El nombre de la salida que se está capturando ahora.

CLIENT-CONNECTED

El evento client-connected se envía cuando un nuevo cliente VNC se conecta a wayvnc.

Parámetros:

id=...

Un identificador único para este cliente.

connection_count=...

El número total de clientes VNC conectados, incluyéndolo a este.

address=...

La dirección IP de este cliente. Puede ser nula.

username=...

El nombre de usuario utilizado para autenticar a este cliente. Puede ser nulo.

CLIENT-DISCONNECTED

El evento client-disconnected se envía cuando un cliente VNC se desconecta de wayvnc.

Parámetros:

id=...

Un identificador único para este cliente.

connection_count=...

El número total de clientes VNC conectados, sin incluir a este.

address=...

La dirección IP de este cliente. Puede ser nula.

username=...

El nombre de usuario utilizado para autenticar a este cliente. Puede ser nulo.

FORMATO DE MENSAJE IPC

La utilidad de línea de comandos wayvncctl(1) construirá mensajes IPC JSON formateados correctamente, pero cualquier cliente funcionará. El cliente inicia la conexión y envía uno o más objetos de solicitud, cada uno de los cuales recibirá un objeto de respuesta correspondiente.

Nota Este formato de mensaje es inestable y puede cambiar sustancialmente en los próximos lanzamientos.

REQUEST

La forma general de un mensaje de solicitud JSON-IPC es:

{
	"method": "nombre-comando",
	"id": 123,
	"params": {
		"clave1": "valor1",
		"clave2": "valor2",
	}
}

El method es el nombre del comando a ejecutar. Utilice el método help para consultar una lista de todos los nombres de método válidos.

El campo id es opcional y puede ser cualquier número o cadena JSON válida. Si se proporciona, la respuesta a esta solicitud contendrá el mismo valor de id, que el cliente puede usar para coordinar múltiples solicitudes y respuestas.

El objeto params proporciona parámetros opcionales por método, y puede omitirse si está vacío.

RESPONSE

{
	"id": 123,
	"code": 0,
	"data": {
		...
	}
}

Si la solicitud tenía un id, la respuesta tendrá un valor idéntico para id.

El code numérico proporciona una indicación de cómo se manejó la solicitud. Un valor de 0 siempre significa éxito. Cualquier otro valor significa fallo y varía según el método en cuestión.

El objeto data contiene datos de retorno específicos del método. Estos pueden ser datos estructurados en respuesta a una consulta, una simple cadena de error en caso de una solicitud fallida, o pueden omitirse por completo si el código de error por sí solo es suficiente.

EVENTS

Los eventos son mensajes asíncronos enviados desde un servidor a todos los clientes registrados. El formato del mensaje es idéntico a una REQUEST, pero sin el campo "id", y un cliente no debe enviar una respuesta.

Ejemplo de mensaje de evento:

{
	"method": "nombre-evento",
	"params": {
		"clave1": "valor1",
		"clave2": "valor2",
	}
}

Para recibir eventos, un cliente debe registrarse primero para recibirlos enviando una solicitud IPC de event-receive. Una vez que el servidor haya enviado la respuesta de éxito, el cliente debe esperar que el servidor pueda enviar mensajes de eventos asíncronos en cualquier momento, incluso entre una solicitud y su respuesta asociada.

ENTORNO

Las siguientes variables de entorno tienen un efecto en wayvnc:

WAYLAND_DISPLAY

Especifica el nombre de la pantalla Wayland en la que se está ejecutando el compositor al que se conectará wayvnc.

XDG_CONFIG_HOME

Especifica la ubicación de los archivos de configuración.

XDG_RUNTIME_DIR

Especifica la ubicación predeterminada para el socket de control de wayvncctl.

FAQ

Wayvnc se queja de que un protocolo no es compatible

El error podría ser similar a esto: 
wl_registry@2: error 0: invalid version for global zxdg_output_manager_v1 (4): have 2, wanted 3
ERROR: ../src/main.c: 388: Screencopy protocol not supported by compositor. Exiting. Refer to FAQ section in man page.
ERROR: ../src/main.c: 1024: Failed to initialise wayland
Esto significa que tu compositor wayland no implementa el protocolo de screencopy y wayvnc no funcionará con él. Screencopy es implementado por compositores basados en wlroots como Sway y Wayfire.

¿Cómo puedo ejecutar wayvnc en modo sin cabeza / a través de una sesión SSH?

Establece las variables de entorno WLR_BACKENDS=headless y WLR_LIBINPUT_NO_DEVICES=1 antes de iniciar el compositor, luego ejecuta wayvnc como de costumbre.

¿Cómo puedo pasar mi tecla modificadora (mod-key) de Sway a la sesión de escritorio remoto?

Crea un modo casi vacío en tu configuración de sway. Ejemplo: 
mode passthrough {
	bindsym $mod+Pause mode default
}
bindsym $mod+Pause mode passthrough
Esto hace que cuando presiones $mod+Pause, todas las combinaciones de teclas, excepto la de volver, se desactiven.

No todos los símbolos aparecen cuando escribo. ¿Qué puedo hacer para solucionar esto?

Intenta establecer la distribución del teclado en wayvnc a la que más se parezca a la distribución del teclado que estás utilizando en el lado del cliente. No es necesario una distribución exacta, solo una que tenga todos los símbolos que utilizas.

¿Cómo activo la tecla Compose?

Establece "xkb_options=compose:menu" en el archivo de configuración. Cualquier tecla que no se esté utilizando de otra manera funcionará. Solo tiene que haber alguna tecla que wayvnc pueda igualar.
