NOMBRE

WhiteDB - biblioteca de base de datos en memoria compartida

SINOPSIS

[consultar la carpeta Doc y http://whitedb.org para el manual completo]

DESCRIPCIÓN

WhiteDB es una biblioteca de bases de datos NoSQL ligera escrita en C, que opera completamente en memoria principal. No hay un proceso de servidor. Los datos se leen y escriben directamente desde/hacia la memoria compartida, no se utilizan sockets entre WhiteDB y el programa de aplicación. Todos los datos son accesibles para procesos separados.

Cada registro de base de datos es una tupla de N elementos, codificada en el simple formato compacto de WhiteDB. Puede almacenar tanto tipos de datos convencionales como punteros directos a registros: estos últimos permiten la traversa altamente eficiente de datos complejos.

Cada elemento se codifica como un entero: configurable como de 32 o 64 bits. Los enteros en la tupla codifican valores directamente o como punteros. Las columnas no tienen tipo: cualquier valor codificado se puede almacenar en cualquier campo. Siempre puede obtener un puntero directo a un registro, almacenarlo en un campo de un registro o usarlo directamente en su propio programa. Por lo tanto, un puntero de registro se puede usar como un ID de registro asignado automáticamente que no requiere ninguna búsqueda para acceder al registro.

Los bits bajos de un entero en un registro indican el tipo de datos. Cualquier cosa que no quepa en los bits restantes se asigna por separado y se apunta mediante el mismo entero.

Utilizamos un bloqueo a nivel de base de datos implementado a través de una cola de spinlock atómica justa para el control de concurrencia, pero se pueden configurar políticas de preferencia alternativas más rápidas y simples: un spinlock con preferencia de lector o un spinlock con preferencia de escritor. Proporcionamos actualizaciones atómicas seguras de valores simples sin tomar un bloqueo de escritura.

El índice más simple proporcionado es un índice T-tree en cualquier campo que contenga cualquier mezcla de objetos (enteros, cadenas, etc.). El índice se mantiene automáticamente cuando se agregan, eliminan o modifican registros.

Hay dos mecanismos disponibles para almacenar la base de datos de memoria compartida en disco. Primero, se puede volcar y restaurar toda la base de datos. Segundo, todas las inserciones, eliminaciones y actualizaciones se pueden registrar en un archivo.
