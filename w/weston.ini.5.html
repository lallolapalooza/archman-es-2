NOMBRE

weston.ini - archivo de configuración para Weston - el compositor Wayland de referencia

INTRODUCCIÓN

Weston obtiene la configuración de sus parámetros de línea de comandos y del archivo de configuración descrito aquí.

DESCRIPCIÓN

Weston utiliza un archivo de configuración llamado weston.ini para su configuración. El archivo de configuración weston.ini se busca en uno de los siguientes lugares al iniciar el servidor:

$XDG_CONFIG_HOME/weston.ini   (si $XDG_CONFIG_HOME está establecido)
$HOME/.config/weston.ini      (si $HOME está establecido)
weston/weston.ini en cada
    $XDG_CONFIG_DIR           (si $XDG_CONFIG_DIRS está establecido)
/etc/xdg/weston/weston.ini    (si $XDG_CONFIG_DIRS no está establecido)

donde la variable de entorno $HOME es el directorio principal del usuario, y $XDG_CONFIG_HOME es el directorio de configuración específico del usuario, y $XDG_CONFIG_DIRS es una lista de directorios base de configuración separados por dos puntos ':', como por ejemplo /etc/xdg-foo:/etc/xdg.

El archivo weston.ini se compone de un número de secciones que pueden estar presentes en cualquier orden, u omitirse para usar los valores de configuración predeterminados. Cada sección tiene el formato:

[EncabezadoSección]
Clave1=Valor1
Clave2=Valor2
    ...

Los espacios son significativos. Las líneas de comentario se ignoran:

#comentario

Los encabezados de sección son:

core           Los módulos y opciones principales
libinput       Configuración del dispositivo de entrada
shell          Personalización del escritorio
launcher       Añadir lanzador al panel
output         Configuración de salida
input-method   Entrada de teclado en pantalla
keyboard       Diseños de teclado
terminal       Opciones de la aplicación de terminal
xwayland       Opciones de XWayland
screen-share   Opciones de compartir pantalla
autolaunch     Opciones de autolanzamiento

Los tipos de valor posibles son cadena, entero con signo y sin signo de 32 bits, y booleano. Las cadenas no deben estar entre comillas, no admiten secuencias de escape y se extienden hasta el final de la línea. Los enteros pueden proporcionarse en forma decimal (por ejemplo, 123), octal (por ejemplo, 0173) y hexadecimal (por ejemplo, 0x7b). Los valores booleanos solo pueden ser 'true' o 'false'.

SECCIÓN CORE

La sección core se utiliza para seleccionar los módulos del compositor de inicio y las opciones generales.

shell=desktop
especifica un shell para cargar (cadena). Esto se puede utilizar para cargar tu propio shell implementado o uno con Weston como predeterminado. Los shells disponibles en el directorio /usr/lib/weston son:
desktop
fullscreen
ivi
kiosk
xwayland=true
pide a Weston que cargue el módulo XWayland (booleano).
modules=screen-share.so
especifica los módulos a cargar (cadena, separados por comas). Los módulos disponibles en el directorio /usr/lib/weston son:
screen-share.so
backend=headless
anula el backend predeterminado. Los backends disponibles son:
drm
headless
rdp
pipewire
vnc
wayland
x11
repaint-window=N
Establece la duración aproximada de la ventana de repintado en milisegundos. La ventana de repintado se utiliza para controlar y reducir la latencia de salida para los clientes. Si la ventana es más larga que el período de actualización de salida, el repintado se realizará inmediatamente cuando finalice el repintado anterior, sin procesar solicitudes de clientes en medio. Si la ventana de repintado es demasiado corta, el compositor puede perder el borrado vertical objetivo, lo que aumenta la latencia de salida. El valor predeterminado es 7 milisegundos. El rango permitido es de -10 a 1000 milisegundos. Usar un valor negativo forzará al compositor a perder siempre el borrado vertical objetivo.
idle-time=segundos
establece el tiempo de inactividad de Weston en segundos. Este tiempo de inactividad es el tiempo después del cual Weston entrará en modo "inactivo" y la pantalla se atenuará a negro. Un valor de 0 desactiva el tiempo de inactividad.

Importante : Esta opción también puede configurarse a través de la opción de línea de comandos '-i' de Weston y tendrá precedencia sobre la opción actual de .ini. Esto significa que si tanto weston.ini como la línea de comandos definen este tiempo de inactividad, se utilizará el especificado en la línea de comandos. Por otro lado, si ninguno de estos establece el valor, se establecerá un tiempo de inactividad predeterminado de 300 segundos.

require-input=true
requerir un dispositivo de entrada para iniciar
require-outputs=any
configura el comportamiento si Weston no logra configurar y habilitar las salidas.

Dependiendo del caso de uso, puede ser preferible asegurarse de que Weston solo se inicie si puede habilitar todas las salidas disponibles, o que ignore las salidas fallidas. Las opciones posibles son:

all-found    todas las salidas disponibles deben estar habilitadas
any          iniciar si alguna salida pudo ser habilitada
none         iniciar incluso si ninguna salida fue habilitada
wait-for-debugger=true
Lanza SIGSTOP antes de inicializar el compositor. Esto permite al usuario adjuntar con un depurador y continuar la ejecución enviando SIGCONT. Esto es útil para depurar un fallo al inicio cuando sería inconveniente lanzar weston directamente desde un depurador. Booleano, por defecto es false. También hay una opción de línea de comandos para hacer lo mismo.
remoting=remoting-plugin.so
especifica un plugin para salida remota para cargar (cadena). Esto se puede utilizar para cargar tu propio plugin de remoting implementado o uno con Weston como predeterminado. Los plugins de remoting disponibles en el directorio __libweston_modules_dir__ son:
remoting-plugin.so
renderer=auto
Selecciona un renderizador para usar en la composición interna cuando sea necesario, o auto para seleccionar el renderizador más apropiado. Los renderizadores disponibles son:
auto
gl
noop
pixman
No todos los backends admiten todos los renderizadores.
use-pixman=true
Obsoleto en favor de la opción renderer=. Habilita la renderización basada en pixman para todas las salidas en backends que lo admitan. Booleano, por defecto es false. También hay una opción de línea de comandos para hacer lo mismo.
color-management=true
Habilita la gestión del color y requiere el uso del renderizador GL. Booleano, por defecto es false.

TENTATIVO, EXPERIMENTAL, EN PROGRESO: La gestión del color habilita el uso de archivos ICC para describir el comportamiento del color del monitor, extensiones del protocolo Wayland para que los clientes describan sus espacios de color y realicen el perfilado del monitor, y el mapeo de tonos necesario para habilitar los modos de video HDR. Esta funcionalidad extendida tiene el costo de un procesamiento de imagen más pesado y, a veces, la pérdida de algunas características de descarga de hardware, como el composite-bypass.

output-decorations=true
Solo para el backend headless con renderizador GL: dibuja decoraciones de ventana de salida, similar a lo que hace el backend wayland para ventanas de salida flotantes. Booleano, por defecto es false. Estas decoraciones normalmente no se pueden capturar en pantalla. Esta opción es útil solo para el conjunto de pruebas de Weston.

SECCIÓN LIBINPUT

La sección libinput se utiliza para configurar el dispositivo de entrada

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

ces al usar el backend de dispositivos de entrada libinput. Los valores predeterminados son determinados por libinput y varían según lo que sea más sensato para cualquier dispositivo dado.

Las configuraciones disponibles son:

enable-tap=false
Habilita el toque para hacer clic en dispositivos táctiles (touchpads).
tap-and-drag=false
Para dispositivos táctiles con enable-tap habilitado. Si el usuario toca, luego toca una segunda vez, esta vez manteniendo presionado, el botón del ratón virtual permanece presionado tanto tiempo como el usuario mantenga el dedo en el panel táctil, permitiendo al usuario hacer clic y arrastrar solo con toques.
tap-and-drag-lock=false
Para dispositivos táctiles con enable-tap y tap-and-drag habilitados. En medio de un toque y arrastre, si el usuario suelta el panel táctil durante menos de un cierto número de milisegundos, luego lo vuelve a tocar, el botón del ratón virtual permanecerá presionado y el arrastre podrá continuar.
disable-while-typing=true
Para dispositivos que pueden ser activados accidentalmente mientras se escribe en el teclado, causando una interrupción de la escritura. Los deshabilita mientras el teclado está en uso.
middle-button-emulation=false
Para dispositivos de puntero con botones izquierdo y derecho, pero sin botón central. Cuando está habilitado, se emite un evento de botón central cuando se presionan los botones izquierdo y derecho simultáneamente.
left-handed=false
Configura el dispositivo para ser utilizado por personas zurdas. Exactamente lo que hace esta opción depende del dispositivo. Para punteros con botones izquierdo y derecho, los botones se intercambian. En las tabletas, la tableta se gira lógicamente boca abajo, ya que se girará físicamente boca abajo.
rotation=n
Cambia la dirección del norte lógico, rotándolo n grados en sentido horario desde la orientación predeterminada, donde n es un número entero entre 0 y 359 inclusive. Necesario principalmente para trackballs. Permite al usuario orientar el trackball de lado, por ejemplo.
accel-profile={flat,adaptive}
Establece el perfil de aceleración del puntero. La velocidad en pantalla del puntero es proporcional a la velocidad física con una cierta constante de proporcionalidad. Llamemos a esa constante alfa. flat mantiene alfa fijo. Ver accel-speed. adaptive hace que alfa aumente con la velocidad física, dando al usuario más control cuando la velocidad es lenta, y más alcance cuando la velocidad es alta. adaptive es el valor predeterminado.
accel-speed=v
Si accel-profile se establece en flat, simplemente establece el valor de alfa. Si accel-profile se establece en adaptive, el efecto es más complicado, pero en general, cambiará la velocidad del puntero. v está normalizado y debe estar en el rango [-1, 1]. El mapeo exacto entre v y alfa depende del hardware, pero valores más altos causan velocidades de cursor más altas.
natural-scroll=false
Habilita el desplazamiento natural, imitando el comportamiento del desplazamiento de pantalla táctil. Es decir, si la rueda, el dedo o los dedos se mueven hacia abajo, la superficie se desplaza hacia arriba en lugar de hacia abajo, como si el dedo o los dedos estuvieran en contacto con la superficie que se está desplazando.
scroll-method={two-finger,edge,button,none}
Establece el método de desplazamiento. two-finger se desplaza con dos dedos en un panel táctil. edge se desplaza con un dedo en el borde derecho de un panel táctil. button se desplaza cuando el puntero se mueve mientras se presiona un botón específico. Ver scroll-button. none deshabilita el desplazamiento por completo.
scroll-button={BTN_LEFT,BTN_RIGHT,BTN_MIDDLE,...}
Para dispositivos con scroll-method establecido en button. Especifica el botón que activará el desplazamiento. Ver /usr/include/linux/input-event-codes.h para la lista completa de valores posibles.
touchscreen_calibrator=true
Anuncia la interfaz del calibrador de pantalla táctil a todos los clientes. Este es un posible vector de ataque de denegación de servicio, por lo que solo debe habilitarse en entornos de usuario confiables. Booleano, por defecto es false.

La interfaz es necesaria para ejecutar aplicaciones calibradoras de pantalla táctil. Proporciona a la aplicación eventos táctiles sin procesar, omitiendo el manejo táctil normal. También permite a la aplicación cargar una nueva calibración en el compositor.

Aunque esta opción se enumera en la sección libinput, afecta a todas las configuraciones de Weston, independientemente del backend utilizado. Si el backend no utiliza libinput, la interfaz aún puede anunciarse, pero no listará ningún dispositivo.

calibration_helper=/bin/echo
Un programa auxiliar de calibración opcional para guardar permanentemente una nueva calibración de pantalla táctil. Cadena, por defecto no está establecido.

El programa dado se ejecutará con siete argumentos cuando una aplicación calibradora solicite al servidor que ponga en uso una nueva matriz de calibración. El programa se ejecuta de forma síncrona y, por lo tanto, bloqueará Weston durante su ejecución. Si el estado de salida del programa es distinto de cero, Weston no aplicará la nueva calibración. Si el auxiliar no está establecido o el estado de salida del programa es cero, Weston utilizará la nueva calibración inmediatamente.

El programa se invoca como:

calibration_helper syspath m1 m2 m3 m4 m5 m6
donde syspath es la ruta sys de udev para el dispositivo y m1 a m6 son los elementos de la matriz de calibración en el formato de propiedad udev LIBINPUT_CALIBRATION_MATRIX de libinput. La ruta sys es una ruta absoluta y comienza con el punto de montaje de sys.

SECCIÓN SHELL

La sección shell se utiliza para personalizar el compositor. Algunas claves pueden no ser manejadas por diferentes complementos de shell.

Las entradas que pueden aparecer en esta sección son:

client=/usr/lib/weston/weston-desktop-shell
especifica la ruta para el cliente shell a ejecutar. Es posible pasar argumentos y variables de entorno al programa, por ejemplo, 'ENVFOO=bar ENVBAR=baz /path/to/program --arg anotherarg', con entradas separadas por espacios pero sin soporte para comillas. Si no se especificó ningún cliente, se lanza weston-desktop-shell (cadena).
background-image=archivo
establece la ruta para el archivo de imagen de fondo (cadena).
background-type=tile
determina cómo se dibuja la imagen de fondo (cadena). Puede ser centered, scale, scale-crop o tile (predeterminado). Centered muestra la imagen una vez centrada. Si la imagen es más pequeña que la salida, el resto de la superficie tendrá el color de fondo. Si el tamaño de la imagen encaja en la salida, se recortará a izquierda y derecha, o arriba y abajo. Scale significa escalado para ajustarse exactamente a la salida, sin preservar la relación de aspecto. Scale-crop preserva la relación de aspecto, escala la imagen de fondo lo suficiente como para cubrir la salida y la centra. La imagen resultante se recortará por la izquierda y la derecha, o por arriba y por abajo, si la relación de aspecto no coincide con la de la salida. Tile repite la imagen de fondo para llenar la salida.
background-color=0xAARRGGBB
establece el color de fondo (entero sin signo). Los pares de dígitos hexadecimales están en orden alfa, rojo, verde y azul.
clock-format=formato
establece el formato del reloj del panel (cadena). Puede ser none, minutes, seconds, minutes-24h, seconds-24h. Por defecto, se utiliza el formato de minutos.
panel-color=0xAARRGGBB
establece el color del panel (entero sin signo). Los pares de dígitos hexadecimales están en orden transparencia, rojo, verde y azul. Ejemplos:
0xffff0000    Rojo
0xff00ff00    Verde
0xff0000ff    Azul
0x00ffffff    Totalmente transparente
panel-position=top
establece la posición del panel (cadena). Puede ser top, bottom, left, right, none.
locking=true
habilita el bloqueo de pantalla (booleano).
animation=zoom
establece el efecto utilizado para abrir nuevas ventanas (cadena). Puede ser zoom, fade, none. Por defecto, no se utiliza animación.
close-animation=fade
establece el efecto utilizado al cerrar ventanas (cadena). Puede ser fade, none. Por defecto, se utiliza la animación de desvanecimiento.
startup-animation=fade
establece el efecto utilizado por desktop-shell al iniciarse (cadena). Puede ser fade, none. Por defecto, se utiliza la animación de desvanecimiento.
focus-animation=dim-layer
establece el efecto utilizado con las ventanas enfocadas y desenfocadas. Puede ser dim-layer, none. Por defecto, no se utiliza animación.
allow-zap=true
si el shell debe cerrarse cuando se presiona la combinación de teclas Ctrl-Alt-Retroceso
binding-modifier=ctrl
establece la tecla modificadora utilizada para las combinaciones comunes (cadena), como mover superficies, redimensionar

GENERAL SECTION

modules=module1,module2
Loads the given modules. See weston.module(7).
backend=backend
Selects the backend. The available backends are drm, fbdev, head- less, logind-launch, x11, and wayland. Defaults to drm.
xwayland=true
Starts XWayland. XWayland is an X server that can be run as a Wayland client. This allows running X11 applications under Wayland. Defaults to true.
backend-specific-options=...
Backend-specific configuration. For example, the X11 backend can be configured to use a specific display, or the DRM backend can be configured to use a specific device. See the man pages for the specific backend for more details.
gbm-backend=backend
Selects the GL buffer management backend. Available backends are DRM and NULL. Defaults to DRM.
client-library=library
Specifies the GL client library to load. Defaults to libGL.so.1.
vlog-level=level
Sets the logging level for weston. The level can be one of the following: error, warning, info, debug. Defaults to warning.
shell=shell
Sets the shell to use. The default shell is weston-shell. You can also use kiosk-shell for a kiosk environment.
use-libinput=true|false
Enables or disables the use of libinput for input handling. Defaults to true.
disable-set-locale=true|false
Disables the setting of locale by weston. Defaults to false.
animation-start-delay=delay
Sets the delay in milliseconds before starting animations. Defaults to 0.
animation-end-delay=delay
Sets the delay in milliseconds after ending animations. Defaults to 0.
color-management=true|false
Enables or disables color management. Defaults to false.
restore-resolution=true|false
Restores the resolution of the output when weston exits. Defaults to true.

LAUNCHER SECTION

There can be multiple launcher sections, one for each launcher.

icon=icon
sets the path to icon image (string). Svg images are not currently supported.
displayname=displayname
sets the display name of the launcher that appears in the tooltip.
path=program

path=GDK_BACKEND=wayland gnome-terminal --full-screen

OUTPUT SECTION

There can be multiple output sections, each corresponding to one output. It is currently only recognized by the drm and x11 backends.

name=name
sets a name for the output (string). The backend uses the name to identify the output. All X11 output names start with a letter X. All Wayland output names start with the letters WL. Examples of usage: 
LVDS1    DRM backend, Laptop internal panel no.1
VGA1     DRM backend, VGA connector no.1
X1       X11 backend, X window no.1
WL1      Wayland backend, Wayland window no.1
See weston-drm(7) for more details.
mode=mode
sets the output mode (string). The mode parameter is handled differently depending on the backend. On the X11 backend, it just sets the WIDTHxHEIGHT of the weston window. The DRM backend accepts different modes, along with an option of a modeline string.

See weston-drm(7) for examples of modes-formats supported by DRM backend.

transform=normal
How you have rotated your monitor from its normal orientation (string). The transform key can be one of the following 8 strings: 
normal               Normal output.
rotate-90            90 degrees clockwise.
rotate-180           Upside down.
rotate-270           90 degrees counter clockwise.
flipped              Horizontally flipped
flipped-rotate-90    Flipped and 90 degrees clockwise
flipped-rotate-180   Flipped and upside down
flipped-rotate-270   Flipped and 90 degrees counter clockwise
scale=factor
The scaling multiplier applied to the entire output, in support of high resolution ("HiDPI" or "retina") displays, that roughly corresponds to the pixel ratio of the display's physical resolution to the logical resolution. Applications that do not support high resolution displays typically appear tiny and unreadable. Weston will scale the output of such applications by this multiplier, to make them readable. Applications that do support their own output scaling can draw their content in high resolution, in which case they avoid compositor scaling. Weston will not scale the output of such applications, and they are not affected by this multiplier.
An integer, 1 by default, typically configured as 2 or higher when needed, denoting the scaling multiplier for the output.
icc_profile=file
If option color-management is true, load the given ICC file as the output color profile. This works only on DRM, headless, wayland, and x11 backends, and for remoting and pipewire outputs.
seat=name
The logical seat name that this output should be associated with. If this is set then the seat's input will be confined to the output that has the seat set on it. The expectation is that this functionality will be used in a multiheaded environment with a single compositor for multiple output and input configurations. The default seat is called "default" and will always be present. This seat can be constrained like any other.
allow_hdcp=true
Allows HDCP support for this output. If set to true, HDCP can be tried for the content-protection, provided by the backends, on this output. By default, HDCP support is always allowed for an output. The content-protection can actually be realized, only if the hardware (source and sink) support HDCP, and the backend has the implementation of content-protection protocol. Currently, HDCP is supported by drm-backend.
content-type=content_type
The type of the content being primarily displayed to this output. Can be "no data" (default), "graphics", "photo", "cinema" or "game".
app-ids=app-id[,app_id]*
A comma separated list of the IDs of applications to place on this output. These IDs should match the application IDs as set with the xdg_shell.set_app_id request. Currently, this option is supported by kiosk-shell.
colorimetry-mode=default
Sets the colorimetry mode on the output. The colorimetry mode together with the EOTF mode below define the color encoding used in the video signal. The colorimetry mode is used for choosing between the default sink defined colorimetry (intended to be described by EDID), and standardised other encodings that support wide color gamut (WCG).

The display driver, the graphics card, and the video sink (monitor) need to support the chosen mode, otherwise the result is undefined or fails.

The mode can be one of the following strings:

default              default (RGB) colorimetry, video sink dependant
bt2020cycc           Rec. ITU-R BT.2020 constant luminance YCbCr
bt2020ycc            Rec. ITU-R BT.2020 non-constant luminance YCbCr
bt2020rgb            Rec. ITU-R BT.2020 RGB
p3d65                SMPTE ST 2113 DCI-P3 RGB D65
p3dci                SMPTE ST 2113 DCI-P3 RGB Theater
ictcp                Rec. ITU-R BT.2100 ICtCp
Defaults to default. Non-default modes require color-management=true.

Note: The operating system might not honor the choice between RGB and YCbCr, that may be picked by a Linux display driver automatically.

eotf-mode=sdr
Sets the EOTF mode on the output. This is used for choosing between standard dynamic range (SDR) mode and the various high dynamic range (HDR) modes. The display driver, the graphics card, and the video sink (monitor) need to support the chosen mode, otherwise the result is undefined. The mode can be one of the following strings: 
sdr                  traditional gamma, SDR
hdr-gamma            traditional gamma, HDR
st2084               SMPTE ST 2084, a.k.a Perceptual Quantizer
hlg                  Hybrid Log-Gamma (ITU-R BT.2100)
Defaults to sdr. Non-SDR modes require color-management=true.
color_characteristics=name
Sets the basic output color characteristics by loading the parameters from the color_characteristics section with the key name=name . If an ICC profile is also set, the ICC profile takes precedence.
mirror-of=ouput_name
Makes the remote output overlap (mirror) the native output identified by the mirror-of value. This is useful for sharing or mirroring a native DRM output. The output mirroring the DRM native one, will inherit the same video modeline as the DRM native one, including the refresh rate and scale of the native output. Note that depending on the remote backend, automatic output resize will be disabled when mirroring is in effect. Mirroring a DRM native output to another DRM native output is yet not supported, being intended only for remote outputs.

NOTE: The native outputs created by the DRM backend using the 'clone-of' are for cloning the outputs, and not sharing or mirroring. See also weston-drm(7).

NAME

weston.ini – weston configuration file

INTRODUCTION

The weston configuration file is located at ~/.config/weston.ini or /etc/xdg/weston/weston.ini. It is divided into sections, each starting with a name in square brackets (e.g. [core]). Each section contains key-value pairs, where the key and value are separated by an equals sign (=). A number sign (#) or semicolon (;) indicates the start of a comment.

DESCRIPTION

The configuration file allows to customize the behavior of the Weston desktop environment and its components.

CORE SECTION

set-locale=en_US.UTF-8
set the locale for weston (string). Default is the value of $LANG. If this value is not valid, the locale is not set.
xwayland=true
whether to load xwayland on startup (boolean). Default is true.
log-backtrace-on-error=false
whether to log a backtrace when an error occurs (boolean). Default is false.
disable-setlocale=false
whether to disable the setlocale() calls that are done by default (boolean). Default is false.
modules=/usr/lib/weston/keybindings.so
comma separated list of modules to load. If the path is relative, it is relative to the modules directory (e.g. /usr/lib/weston/).
gbm-backend=drm
select the backend for gbm (string). Possible values are: drm, kms. Defaults to drm.

LIBINPUT SECTION

These settings are options passed to libinput.

send-events=keyboard,pointer,touch
Comma separated list of device types for which events should be sent to libinput. Supported device types are: keyboard, pointer, touch. Default is all of them.
enable-tap=true
enable tap-to-click on the touchpad (boolean). Default is true.
tap-duration=true
sets the maximum tap duration (integer). Default is 10ms.
natural-scrolling=true
enable natural scrolling on the touchpad (boolean). Default is false.
disable-while-typing=true
enable disable-while-typing on the touchpad (boolean). Default is true.
disable-while-typing-timeout=true
sets the disable-while-typing timeout (integer). Default is 0.
left-handed=true
set the device to left-handed mode (boolean). Default is false.
dwt=true
enable disable-while-typing on the touchpad (boolean). Default is true.
dwt-timeout=true
sets the disable-while-typing timeout (integer). Default is 200ms.
scroll-factor-y=1.0
sets the scroll factor for the y axis (float). Default is 1.0.
scroll-factor-x=1.0
sets the scroll factor for the x axis (float). Default is 1.0.
middle-emulation=true
enable middle button emulation (boolean). Default is false.
motion-threshold=10
sets the motion threshold in pixels (integer). Default is 10.
motion-noise=4
sets the motion noise in pixels (integer). Default is 4.
action-buttons=true
enable action buttons (boolean). Default is true.
num-button-triggers=2
sets the number of button triggers for action buttons (integer). Default is 2.

SHELL SECTION

shell=/usr/bin/weston-simple-shell.so
path to the shell plugin to use (string).
client-limit=10
maximum number of clients allowed (unsigned integer).
background-image=/usr/share/backgrounds/weston.png
path to the background image (string).
background-color=#000000
background color in hex format (string).

LAUNCHER SECTION

icon=/usr/share/icons/hicolor/scalable/apps/weston-terminal.svg
path to the icon for the launcher (string).
tooltip=Terminal
tooltip text for the launcher (string).
path=/usr/bin/weston-terminal
path to the executable to launch (string).
startup-id=weston-terminal.desktop
startup notification id (string).

OUTPUT SECTION

Configure output devices.

name=DSI-1
name of the output device (string).
mode=1920x1080@60
output mode (string). Format is WxH@R, where W is width, H is height and R is refresh rate.
pos=0x0
position of the output (string). Format is XxY.
enable=true
whether to enable the output (boolean).
primary=true
whether to set this output as primary (boolean).
hdr-metadata=my-hdr-metadata
name of the color_characteristics section to use for HDR metadata (string).

INPUT-METHOD SECTION

path=/usr/lib/weston/wayland-input-method-server
path to the input method server (string).

KEYBOARD SECTION

keymap=/etc/default/keyboard
sets the keymap configuration file (string). See the Models section in xkeyboard-config(7).
keymap_layout=us,de,gb
sets the comma separated list of keyboard layout codes (string). See the Layouts section in xkeyboard-config(7).
keymap_variant=euro,,intl
sets the comma separated list of keyboard layout variants (string). The number of variants must be the same as the number of layouts above. See the Layouts section in xkeyboard-config(7).
keymap_options=grp:alt_shift_toggle,grp_led:scroll
sets the keymap options (string). See the Options section in xkeyboard-config(7).
repeat-rate=40
sets the rate of repeating keys in characters per second (unsigned integer)
repeat-delay=400
sets the delay in milliseconds since key down until repeating starts (unsigned integer)
numlock-on=false
sets the default state of the numlock on weston startup for the backends which support it.
vt-switching=true
Whether to allow the use of Ctrl+Alt+Fn key combinations to switch away from the compositor's virtual console.

TERMINAL SECTION

Contains settings for the weston terminal application (weston-terminal). It allows to customize the font and shell of the command line interface.

font=DejaVu Sans Mono
sets the font of the terminal (string). For a good experience it is recommended to use monospace fonts. In case the font is not found, the default one is used.
font-size=14
sets the size of the terminal font (unsigned integer).
term=xterm-256color
The terminal shell (string). Sets the $TERM variable.

XWAYLAND SECTION

path=/usr/bin/Xwayland
sets the path to the xserver to run (string).

SCREEN-SHARE SECTION

command=/usr/bin/weston --backend=rdp --shell=fullscreen --no-clients-resize --no-config
sets the command to start a fullscreen-shell server for screen sharing (string).
start-on-startup=false
If set to true, start screen sharing of all outputs available on Weston startup. Set to false by default. Set to false by default. When using this option make sure you enable --no-config to avoid re-loading the screen-share module and implictly trigger screen-sharing for the RDP output already performing the screen share. Alternatively, you could also supply a different configuration file, by using --config /path/to/config/file, and make sure that the configuration file doesn't load the screen-share module.

AUTOLAUNCH SECTION

path=/usr/bin/echo
Path to an executable file to run after startup. This file is executed in parallel to Weston, so it does not have to immediately exit. Defaults to empty.
watch=false
If set to true, quit Weston after the auto-launched executable exits. Set to false by default.

COLOR CHARACTERISTICS SECTION

Each color_characteristics section records one set of basic display or monitor color characterisation parameters. The parameters are defined in CTA-861-H specification as Static Metadata Type 1, and they can also be found in EDID. The parameters are divided into groups. Each group must be given either fully or not at all.

Each section should be named with name key by which it can be referenced from other sections. A metadata section is just a collection of parameter values and does nothing on its own. It has an effect only when referenced from elsewhere.

See output section key color_characteristics.

name=name
An arbitrary name for this section. You can choose any name you want as long as it does not contain the colon (:) character. Names with at least one colon are reserved.

Primaries group

red_x=x
red_y=y
green_x=x
green_y=y
blue_x=x
blue_y=y
The CIE 1931 xy chromaticity coordinates of the display primaries. These floating point values must reside between 0.0 and 1.0, inclusive.

White point group

white_x=x
white_y=y
The CIE 1931 xy chromaticity coordinates of the display white point. These floating point values must reside between 0.0 and 1.0, inclusive.

Independent parameters

Each parameter listed here has its own group and therefore can be given alone.

max_L=L
Display's desired maximum content luminance (peak) L cd/m², a floating point value in the range 0.0–100000.0.
min_L=L
Display's desired minimum content luminance L cd/m², a floating point value in the range 0.0–100000.0.
maxFALL=L
Display's desired maximum frame-average light level L cd/m², a floating point value in the range 0.0–100000.0.
