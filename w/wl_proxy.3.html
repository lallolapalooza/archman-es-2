Descripción Detallada

Representa un objeto de protocolo en el lado del cliente.

Un wl_proxy actúa como un proxy del lado del cliente para un objeto existente en el compositor. El proxy es responsable de convertir las solicitudes realizadas por los clientes con wl_proxy_marshal() al formato de cable de Wayland. Los eventos que provienen del compositor también son manejados por el proxy, que a su vez llamará al manejador establecido con wl_proxy_add_listener().

Nota

Con la excepción de la función wl_proxy_set_queue(), las funciones que acceden a un wl_proxy normalmente no son utilizadas por el código del cliente. Los clientes normalmente deberían usar la interfaz de nivel superior generada por el escáner para interactuar con los objetos del compositor.

int wl_proxy_add_dispatcher (struct wl_proxy * proxy, wl_dispatcher_func_t dispatcher, const void * implementation, void * data)

Establece el oyente (con despachador) de un proxy.

Parámetros

proxy El objeto proxy
dispatcher El despachador a utilizar para este proxy
implementation La implementación del oyente específica del despachador
data Datos de usuario a asociar con el proxy

Devuelve

0 en caso de éxito o -1 en caso de fallo

Establece el oyente del proxy para usar dispatcher_func como su despachador y dispatcher_data como su implementación específica del despachador y sus datos de usuario a data. Si ya se ha establecido un oyente, esta función falla y no se realiza ningún cambio.

Los detalles exactos de dispatcher_data dependen del despachador utilizado. Esta función está destinada a ser utilizada por enlaces de lenguaje, no por código de usuario.

proxy no debe ser un wrapper de proxy.

int wl_proxy_add_listener (struct wl_proxy * proxy, void(** implementation )(void), void * data)

Establece el oyente de un proxy.

Parámetros

proxy El objeto proxy
implementation El oyente a agregar al proxy
data Datos de usuario a asociar con el proxy

Devuelve

0 en caso de éxito o -1 en caso de fallo

Establece el oyente del proxy a implementation y sus datos de usuario a data. Si ya se ha establecido un oyente, esta función falla y no se realiza ningún cambio.

implementation es un vector de punteros a función. Para un código de operación n, implementation[n] debe apuntar al manejador de n para el objeto dado.

proxy no debe ser un wrapper de proxy.

struct wl_proxy * wl_proxy_create (struct wl_proxy * factory, const struct wl_interface * interface)

Crea un objeto proxy con una interfaz dada.

Parámetros

factory Objeto proxy de fábrica
interface Interfaz que debe usar el objeto proxy

Devuelve

Un objeto proxy recién asignado o NULL en caso de fallo

Esta función crea un nuevo objeto proxy con la interfaz suministrada. Al objeto proxy se le asignará un id del espacio de ids del cliente. El id debe ser creado en el lado del compositor enviando una solicitud apropiada con wl_proxy_marshal().

El proxy heredará la pantalla y la cola de eventos del objeto de fábrica.

Nota

Esto no debería ser utilizado normalmente por código no generado.

void wl_proxy_wrapper_destroy (void * proxy_wrapper)

Destruye un wrapper de proxy.

Parámetros

proxy_wrapper El wrapper de proxy a destruir

ng queue assignments

thread-safe

Parámetros

proxy El objeto proxy a envolver

Retorna

Un envoltorio de proxy para el proxy dado o NULL en caso de fallo

Un envoltorio de proxy es un tipo de instancia de 'struct wl_proxy' que se puede usar al enviar solicitudes en lugar de usar el proxy original. Un envoltorio de proxy no tiene implementación ni despachador, y los eventos recibidos en el objeto todavía se emiten en el proxy original. Intentar establecer una implementación o un despachador no tendrá ningún efecto pero resultará en un aviso en el registro.

Establecer la cola de proxies del envoltorio de proxy hará que los nuevos objetos creados usando el envoltorio de proxy utilicen la cola de proxies establecida. Incluso aunque no haya implementación ni despachador, la cola de proxies se puede cambiar. Esto afectará la cola predeterminada de los nuevos objetos creados por solicitudes enviadas a través del envoltorio de proxy.

Un envoltorio de proxy solo puede ser destruido usando wl_proxy_wrapper_destroy().

Un envoltorio de proxy debe ser destruido antes que el proxy del que fue creado.

Si un usuario lee y despacha eventos en más de un hilo, es necesario usar un envoltorio de proxy al enviar solicitudes en objetos cuando la intención es que un proxy recién creado utilice una cola de proxies diferente a la del proxy en el que se envió la solicitud, ya que la creación del nuevo proxy y luego el establecimiento de la cola no es thread-safe.

Por ejemplo, un módulo que se ejecuta usando su propia cola de proxies que necesita realizar un roundtrip de visualización debe envolver el objeto proxy wl_display antes de enviar la solicitud wl_display.sync. Por ejemplo:

struct wl_event_queue *queue = ...;
struct wl_display *wrapped_display;
struct wl_callback *callback;
wrapped_display = wl_proxy_create_wrapper(display);
wl_proxy_set_queue((struct wl_proxy *) wrapped_display, queue);
callback = wl_display_sync(wrapped_display);
wl_proxy_wrapper_destroy(wrapped_display);
wl_callback_add_listener(callback, ...);

void wl_proxy_destroy (struct wl_proxy * proxy)

Destruye un objeto proxy

Parámetros

proxy El proxy a destruir

proxy no debe ser un envoltorio de proxy.

Nota

Esta función abortará en respuesta a errores graves, y lo hará con el bloqueo de visualización adquirido. Esto significa que los manejadores de SIGABRT no deben realizar ninguna acción que intente adquirir ese bloqueo, o se produciría un interbloqueo.

Obtiene la versión del objeto de protocolo de un objeto proxy, o 0 si el proxy fue creado con una API sin versión.

Un nuevo wl_proxy para el argumento new_id o NULL en caso de error

Traduce la solicitud dada por el código de operación y los argumentos adicionales al formato de cable y lo escribe en el búfer de conexión.

Para los argumentos new-id, esta función asignará un nuevo wl_proxy y enviará el ID al servidor. El nuevo wl_proxy será devuelto en caso de éxito o NULL en caso de error con errno establecido en consecuencia. El proxy recién creado tendrá la versión especificada.

La bandera WL_MARSHAL_FLAG_DESTROY puede pasarse para asegurar que el proxy se destruya atómicamente con el marshalling, a fin de prevenir condiciones de carrera que pueden ocurrir si el bloqueo de pantalla se libera entre las operaciones de marshal y destroy.

Nota

Normalmente, esto no debe ser utilizado por código no generado.

void wl_proxy_set_queue (struct wl_proxy * proxy, struct wl_event_queue * queue)

Asigna un proxy a una cola de eventos

Parámetros

proxy El objeto proxy
queue La cola de eventos que manejará este proxy o NULL

Asigna el proxy a la cola de eventos. Los eventos provenientes del proxy se pondrán en cola en `queue` a partir de ahora. Si `queue` es NULL, entonces se establecerá la cola predeterminada del display para el proxy.

Para garantizar el manejo adecuado de todos los eventos que se pusieron en cola antes de que el cambio de cola surta efecto, es necesario despachar la cola de eventos antigua del proxy después de establecer una nueva cola de eventos.

Esto es particularmente importante para configuraciones multihilo, donde es posible que los eventos se pongan en cola en la cola antigua del proxy desde un hilo diferente durante la invocación de esta función.

Para asegurar que todos los eventos de un proxy recién creado se despachen en una cola particular, es necesario usar un envoltorio de proxy si los eventos se leen y despachan en más de un hilo. Consulte wl_proxy_create_wrapper() para obtener más detalles.

Nota

Por defecto, la cola establecida en el proxy es la heredada de su padre.

void wl_proxy_set_tag (struct wl_proxy * proxy, const char *const * tag)

Establece la etiqueta de un objeto proxy

Un toolkit o aplicación puede establecer una etiqueta única en un proxy para identificar si un objeto es administrado por sí mismo o por alguna parte externa.

Para crear una etiqueta, la forma recomendada es definir un array de caracteres constante asignado estáticamente que contenga una cadena descriptiva. La etiqueta será el puntero al puntero no constante al principio del array.

Por ejemplo, para definir y establecer una etiqueta en una superficie administrada por un cierto subsistema:

    static const char *my_tag = "my tag";
    wl_proxy_set_tag((struct wl_proxy *) surface, &my_tag);

Luego, en una devolución de llamada con wl_surface como argumento, para verificar si es una superficie administrada por el mismo subsistema.

    const char * const *tag;
    tag = wl_proxy_get_tag((struct wl_proxy *) surface);
    if (tag != &my_tag)
    return;
 ...

Para fines de depuración, una etiqueta debe ser adecuada para ser incluida en una entrada de registro de depuración, por ejemplo:

    const char * const *tag;
    tag = wl_proxy_get_tag((struct wl_proxy *) surface);
    printf("Got a surface with the tag %p (%s)\n",
           tag, (tag && *tag) ? *tag : "");

proxy El objeto proxy
tag La etiqueta

NAME

wl_proxy — Wayland proxy object

SYNOPSIS

#include <wayland-client.h>

struct wl_proxy;

Detailed Description

This structure is used to represent a Wayland client-side proxy object. A proxy object is a client-side representation of a Wayland object that exists on the server side. All Wayland objects are identified by a unique object ID on the server and the client. The client uses a wl_proxy structure to refer to such objects.

The client can send requests to the server via the proxy object. The server can send asynchronous events to the client, which are dispatched through a set of callbacks registered with the display object.

The wl_proxy structure itself is opaque and should not be accessed directly. Instead, use the functions provided by the Wayland client library to interact with proxy objects.
