NOMBRE

welf2dlf - convierte registros de firewall en formato WELF (WebTrends Enhanced Log Format) a DLF

SINOPSIS

welf2dlf archivo

DESCRIPCIÓN

welf2dlf convierte los registros de firewall en formato WELF (WebTrends Enhanced Log Format) al formato DLF de firewall.

Este formato se define en la siguiente URL: http://www.netiq.com/partners/technology/welf.asp

Este conversor también soporta las extensiones de SonicWall.

Una lista de productos de firewall que soportan este formato se puede encontrar en la siguiente URL: http://www.netiq.com/products/fwr/compatible.asp

NOTAS DE IMPLEMENTACIÓN

Dado que el formato DLF de firewall solo admite filtros de paquetes, no todos los registros se mapearán a DLF.

Los mensajes de paquetes descartados (aquellos con msg="XXX packet dropped") se mapearán a un paquete DLF denegado. (Así como todos los registros msg="TCP connection dropped"). Estos paquetes tendrán una longitud de 0 (esta es una limitación del formato que no registra esa información en los paquetes descartados).

Los mensajes con un campo proto= establecido se interpretarán como un paquete "permitido". Esto no es exactamente "correcto" porque este mensaje representa realmente un "flujo de paquetes" y no un solo paquete.

Otros registros serán ignorados.

Puede usar el servicio welf_proxy en el super-servicio proxy para extraer información a nivel de proxy de los registros WELF.

EJEMPLOS

Para procesar un registro tal como lo produce WebTrends:

$ welf2dlf < welf.log

welf2dlf rara vez se usará por sí solo, sino que es más probable que sea llamado por lr_log2report:

$ lr_log2report welf < /var/log/welf.log
