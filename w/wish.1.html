NOMBRE

wish - Intérprete de ventanas simple

SINOPSIS

wish ?-encoding nombre? ?archivo nombre arg arg ...?

OPCIONES

-encoding nombre
Especifica la codificación del texto almacenado en archivo nombre. Esta opción solo se reconoce antes del argumento archivo nombre.
-colormap nuevo
Especifica que la ventana debe tener un mapa de colores privado nuevo en lugar de usar el mapa de colores predeterminado de la pantalla.
-display display
Pantalla (y monitor) en la que mostrar la ventana.
-geometry geometría
Geometría inicial a usar para la ventana. Si se especifica esta opción, su valor se almacena en la variable global geometry del intérprete Tcl de la aplicación.
-name nombre
Usa nombre como título para ser mostrado en la ventana, y como nombre del intérprete para comandos send.
-sync
Ejecuta todos los comandos del servidor X de forma síncrona, de modo que los errores se informen de inmediato. Esto resultará en una ejecución mucho más lenta, pero es útil para depurar.
-use id
Especifica que la ventana principal de la aplicación se incrustará en la ventana cuyo identificador es id, en lugar de crearse como una ventana independiente de nivel superior. Id debe especificarse de la misma forma que el valor de la opción -use para widgets toplevel (es decir, tiene la forma de la devuelta por el comando winfo id).
Tenga en cuenta que en algunas plataformas esto solo funcionará correctamente si id se refiere a un frame o toplevel de Tk que tenga habilitada la opción -container.
-visual visual
Especifica el visual a usar para la ventana. Visual puede tener cualquiera de las formas admitidas por el procedimiento Tk_GetVisual.
--
Pasa todos los argumentos restantes al script a través de la variable argv sin interpretarlos. Esto proporciona un mecanismo para pasar argumentos como -name a un script en lugar de que wish los interprete.

DESCRIPCIÓN

Wish es un programa simple que consta del lenguaje de comandos Tcl, el toolkit Tk y un programa principal que lee comandos de la entrada estándar o de un archivo. Crea una ventana principal y luego procesa comandos Tcl. Si wish se invoca con argumentos, entonces los primeros argumentos, ?-encoding nombre? ?archivo nombre?, especifican el nombre de un archivo de script y, opcionalmente, la codificación de los datos de texto almacenados en ese archivo de script. Se reconoce un valor para archivo nombre si el argumento apropiado no comienza con “-”.

Si no hay argumentos, o los argumentos no especifican un archivo nombre, entonces wish lee comandos Tcl interactivamente desde la entrada estándar. Continuará procesando comandos hasta que se hayan eliminado todas las ventanas o se alcance el final del archivo en la entrada estándar. Si existe un archivo “.wishrc” en el directorio principal del usuario, wish evalúa el archivo como un script Tcl justo antes de leer el primer comando de la entrada estándar.

Si los argumentos para wish especifican un archivo nombre, entonces archivo nombre se trata como el nombre de un archivo de script. Wish evaluará el script en archivo nombre (que presumiblemente crea una interfaz de usuario), luego responderá a eventos hasta que se eliminen todas las ventanas. No se leerán comandos de la entrada estándar. No hay evaluación automática de “.wishrc” cuando se presenta el nombre de un archivo de script en la línea de comandos de wish, pero el archivo de script siempre puede sourcearlo si lo desea.

Tenga en cuenta que en Windows, el programa wishversion.exe difiere del programa tclshversion.exe en un aspecto adicional importante: no se conecta a una consola de Windows estándar y es un programa con ventanas. Debido a esto, además proporciona acceso a su propio comando console.

PROCESAMIENTO DE OPCIONES

Wish procesa automáticamente todas las opciones de línea de comandos descritas en el resumen de OPCIONES anterior. Cualquier otro argumento de línea de comandos además de estos se pasa a la aplicación utilizando las variables argc y argv descritas más adelante.

NOMBRE Y CLASE DE APLICACIÓN

El nombre de la aplicación, que se utiliza para fines como los comandos send, se toma de la opción -name, si se especifica; de lo contrario, se toma de archivo nombre, si se especifica, o del nombre del comando mediante el cual se invocó wish. En estos dos últimos casos, si el nombre contiene un carácter “/”, solo los caracteres después de la última barra se utilizan como nombre de la aplicación.

La clase de la aplicación, que se utiliza para fines como la especificación de opciones con una propiedad RESOURCE_MANAGER o un archivo .Xdefaults, es la misma que su nombre excepto que la primera letra está en mayúscula.

VARIABLES

Wish establece las siguientes variables Tcl:

argc
Contiene un recuento del número de argumentos arg (0 si no hay ninguno), sin incluir las opciones descritas anteriormente.
argv
Contiene una lista Tcl cuyos elementos son los argumentos arg que siguen a una opción -- o que no coinciden con ninguna de las opciones descritas en OPCIONES, en orden, o una cadena vacía si no hay tales argumentos.
argv0
Contiene archivo nombre si se especificó. De lo contrario, contiene el nombre mediante el cual se invocó wish.
geometry
Si se especifica la opción -geometry, wish copia su valor en esta variable. Si la variable todavía existe después de que se haya evaluado archivo nombre, wish usa el valor de la variable en un comando wm geometry para establecer la geometría de la ventana principal.
tcl_interactive
Contiene 1 si wish está leyendo comandos interactivamente (archivo nombre no se especificó y la entrada estándar es un dispositivo similar a una terminal), 0 en caso contrario.

ARCHIVOS DE SCRIPT

Si crea un script Tcl en un archivo cuya primera línea es

#!/usr/local/bin/wish
entonces puede invocar el archivo de script directamente desde su shell si lo marca como ejecutable. Esto asume que wish se ha instalado en la ubicación predeterminada en /usr/local/bin; si se ha instalado en otro lugar, deberá modificar la línea anterior para que coincida. Muchos sistemas UNIX no permiten que la línea #! exceda los 30 caracteres, así que asegúrese de que el ejecutable wish sea accesible con un nombre de archivo corto.

Un enfoque aún mejor es comenzar sus archivos de script con las siguientes tres líneas:

#!/bin/sh
# la siguiente línea reinicia usando wish \
exec wish "$0" ${1+"$@"}
Este enfoque tiene tres ventajas sobre el enfoque del párrafo anterior. Primero, la ubicación del binario wish no tiene que estar codificada en el script: puede estar en cualquier lugar de la ruta de búsqueda de su shell. Segundo, evita el límite de 30 caracteres del nombre de archivo en el enfoque anterior. Las tres líneas hacen que tanto sh como wish procesen el script, pero el exec solo lo ejecuta sh. sh procesa el script primero; trata la segunda línea como un comentario y ejecuta la tercera línea. El statement exec hace que el shell deje de procesar y, en su lugar, inicie wish para reprocesar todo el script. Cuando wish se inicia, trata las tres líneas como comentarios, ya que la barra invertida al final de la segunda línea hace que la tercera línea sea tratada como parte del comentario en la segunda línea.

El final de un archivo de script puede estar marcado ya sea por el final físico del medio, o por el carácter “\032” (“\u001a”, control-Z). Si este carácter está presente en el archivo, la aplicación wish leerá texto hasta, pero sin incluir, el carácter. Una aplicación que requiere este carácter en el archivo puede codificarlo como “\032”, “\x1a”, o “\u001a”; o puede generarlo mediante el uso de comandos como format o binary.

PROMPTS

Cuando wish se invoca interactivamente, normalmente solicita cada comando con “% ”. Puede cambiar el prompt estableciendo las variables tcl_prompt1 y tcl_prompt2. Si la variable tcl_prompt1 existe, debe consistir en un script Tcl para mostrar un prompt; en lugar de mostrar un prompt, wish evaluará el script en tcl_prompt1. La variable tcl_prompt2 se utiliza de manera similar cuando se escribe un salto de línea pero el comando actual aún no está completo; si tcl_prompt2 no está establecida, no se muestra ningún prompt para comandos incompletos.
