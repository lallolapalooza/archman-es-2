wait(2) Manual de llamadas al sistema wait(2)

NOMBRE

wait, waitpid, waitid - esperar a que un proceso cambie de estado

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/wait.h>
pid_t wait(int *_Nullable wstatus);
pid_t waitpid(pid_t pid, int *_Nullable wstatus, int options);
int waitid(idtype_t idtype, id_t id, siginfo_t *infop, int options);
                /* Esta es la interfaz de glibc y POSIX; ver
                   VERSIONS para obtener información sobre la llamada al sistema
                   directa.  */

            || /* glibc <= 2.19: */ _BSD_SOURCE

DESCRIPCIÓN

Todas estas llamadas al sistema se utilizan para esperar cambios de estado en un hijo del proceso llamante, y obtener información sobre el hijo cuyo estado ha cambiado. Un cambio de estado se considera: el hijo terminó; el hijo fue detenido por una señal; o el hijo fue reanudado por una señal. En el caso de un hijo que ha terminado, la realización de una espera permite al sistema liberar los recursos asociados con el hijo; si no se realiza una espera, entonces el hijo terminado permanece en un estado de "zombi" (ver NOTAS más abajo).

Si un hijo ya ha cambiado de estado, entonces estas llamadas regresan inmediatamente. De lo contrario, se bloquean hasta que un hijo cambie de estado o un manejador de señales interrumpa la llamada (suponiendo que las llamadas al sistema no se reinician automáticamente usando la bandera SA_RESTART de sigaction(2)). En el resto de esta página, un hijo cuyo estado ha cambiado y que aún no ha sido esperado por una de estas llamadas al sistema se denomina esperable.

wait() y waitpid()

La llamada al sistema wait() suspende la ejecución del hilo llamante hasta que uno de sus hijos termine. La llamada wait(&wstatus) es equivalente a:


waitpid(-1, &wstatus, 0);

La llamada al sistema waitpid() suspende la ejecución del hilo llamante hasta que un hijo especificado por el argumento pid haya cambiado de estado. Por defecto, waitpid() solo espera a los hijos terminados, pero este comportamiento es modificable a través del argumento options, como se describe a continuación.

El valor de pid puede ser:

< -1
significa esperar cualquier proceso hijo cuyo ID de grupo de procesos sea igual al valor absoluto de pid.
-1
significa esperar cualquier proceso hijo.
0
significa esperar cualquier proceso hijo cuyo ID de grupo de procesos sea igual al del proceso llamante en el momento de la llamada a waitpid().
> 0
significa esperar al hijo cuyo ID de proceso sea igual al valor de pid.

El valor de options es una combinación OR de cero o más de las siguientes constantes:

WNOHANG
regresar inmediatamente si ningún hijo ha terminado.
WUNTRACED
regresar también si un hijo se ha detenido (pero no está siendo rastreado mediante ptrace(2)). Se proporciona información de estado para hijos *rastreados* que se han detenido incluso si esta opción no está especificada.
WCONTINUED (desde Linux 2.6.10)
regresar también si un hijo detenido ha sido reanudado por la entrega de SIGCONT.

(Para opciones solo de Linux, ver más abajo).

Si wstatus no es NULL, wait() y waitpid() almacenan información de estado en el int al que apunta. Este entero puede ser inspeccionado con las siguientes macros (que toman el entero mismo como argumento, no un puntero a él, como se hace en wait() y waitpid!):

WIFEXITED(wstatus)
devuelve verdadero si el hijo terminó normalmente, es decir, llamando a exit(3) o _exit(2), o al regresar de main().
WEXITSTATUS(wstatus)
devuelve el estado de salida del hijo. Esto consiste en los 8 bits menos significativos del argumento status que el hijo especificó en una llamada a exit(3) o _exit(2) o como argumento para una sentencia return en main(). Esta macro solo debe emplearse si WIFEXITED devolvió verdadero.
WIFSIGNALED(wstatus)
devuelve verdadero si el proceso hijo fue terminado por una señal.
WTERMSIG(wstatus)
devuelve el número de la señal que provocó la terminación del proceso hijo. Esta macro solo debe emplearse si WIFSIGNALED devolvió verdadero.
WCOREDUMP(wstatus) // POSIX.1-2024
devuelve verdadero si el hijo produjo un volcado de núcleo (ver core(5)). Esta macro solo debe emplearse si WIFSIGNALED devolvió verdadero.
WIFSTOPPED(wstatus) // POSIX.1-2024
devuelve verdadero si el proceso hijo fue detenido por la entrega de una señal; esto solo es posible si la llamada se realizó usando WUNTRACED o cuando el hijo está siendo rastreado (ver ptrace(2)).
WSTOPSIG(wstatus)
devuelve el número de la señal que provocó que el hijo se detuviera. Esta macro solo debe emplearse si WIFSTOPPED devolvió verdadero.
WIFCONTINUED(wstatus)
(desde Linux 2.6.10) devuelve verdadero si el proceso hijo fue reanudado por la entrega de SIGCONT.

waitid()

La llamada al sistema waitid() (disponible desde Linux 2.6.9) proporciona un control más preciso sobre los cambios de estado de los hijos que se desean esperar.

Los argumentos idtype e id seleccionan el(los) hijo(s) por los que esperar, de la siguiente manera:

idtype == P_PID
Esperar al hijo cuyo ID de proceso coincide con id.
idtype == P_PIDFD (desde Linux 5.4)
Esperar al hijo al que se refiere el descriptor de archivo PID en id. (Ver pidfd_open(2) para más información sobre descriptores de archivo PID.)
idtype == P_PGID
Esperar a cualquier hijo cuyo ID de grupo de procesos coincida con id. Desde Linux 5.4, si id es cero, entonces esperar a cualquier hijo que esté en el mismo grupo de procesos que el grupo de procesos del llamante en el momento de la llamada.
idtype == P_ALL
Esperar a cualquier hijo; id se ignora.

Los cambios de estado del hijo por los que esperar se especifican combinando OR una o más de las siguientes banderas en options:

WEXITED
Esperar a los hijos que han terminado.
WSTOPPED
Esperar a los hijos que han sido detenidos por la entrega de una señal.

DESCRIPCIÓN

Las llamadas al sistema wait(), waitpid() y waitid() se utilizan para permitir que un proceso espere a que cambien de estado sus hijos. Un cambio de estado incluye la terminación de un hijo, o la detención o continuación de un hijo por una señal.

WCONTINUED
Esperar a los hijos (previamente detenidos) que han sido reanudados por la entrega de SIGCONT.

Las siguientes banderas pueden ser ORed adicionalmente en options:

WNOHANG
Como para waitpid().
WNOWAIT
Dejar al hijo en un estado esperable; una llamada posterior a wait puede ser utilizada para recuperar nuevamente la información del estado del hijo.

Al regresar exitosamente, waitid() llena los siguientes campos de la estructura siginfo_t apuntada por infop:

si_pid
El ID del proceso del hijo.
si_uid
El ID de usuario real del hijo. (Este campo no se establece en la mayoría de las otras implementaciones.)
si_signo
Siempre establecido a SIGCHLD.
si_status
El estado de salida del hijo, tal como se le dio a _exit(2) (o exit(3)), o la señal que causó que el hijo terminara, se detuviera o continuara. El campo si_code puede ser utilizado para determinar cómo interpretar este campo.
si_code
Establecido a uno de: CLD_EXITED (hijo llamó a _exit(2)); CLD_KILLED (hijo matado por señal); CLD_DUMPED (hijo matado por señal, y volcó un core); CLD_STOPPED (hijo detenido por señal); CLD_TRAPPED (hijo rastreado ha atrapado); o CLD_CONTINUED (hijo continuado por SIGCONT).

Si se especificó WNOHANG en options y no había hijos en estado esperable, entonces waitid() regresa 0 inmediatamente y el estado de la estructura siginfo_t apuntada por infop depende de la implementación. Para distinguir (portablemente) este caso del donde un hijo estaba en un estado esperable, ponga a cero el campo si_pid antes de la llamada y verifique un valor distinto de cero en este campo después de que la llamada regrese.

El Corregendum Técnico 1 (2013) de POSIX.1-2008 agrega el requisito de que cuando se especifica WNOHANG en options y no había hijos en estado esperable, entonces waitid() debe poner a cero los campos si_pid y si_signo de la estructura. En Linux y otras implementaciones que se adhieren a este requisito, no es necesario poner a cero el campo si_pid antes de llamar a waitid(). Sin embargo, no todas las implementaciones siguen la especificación POSIX.1 en este punto.

VALOR DE RETORNO

wait(): en éxito, regresa el ID del proceso del hijo terminado; en caso de fallo, se regresa -1.

waitpid(): en éxito, regresa el ID del proceso del hijo cuyo estado ha cambiado; si se especificó WNOHANG y uno o más hijos especificados por pid existen, pero aún no han cambiado de estado, entonces se regresa 0. En caso de fallo, se regresa -1.

waitid(): regresa 0 en éxito o si se especificó WNOHANG y ningún hijo especificado por id ha cambiado de estado aún; en caso de fallo, se regresa -1.

En caso de fallo, cada una de estas llamadas establece errno para indicar el error.

ERRORES

EAGAIN
El descriptor de archivo PID especificado en id no es bloqueante y el proceso al que se refiere no ha terminado.
ECHILD
(para wait()) El proceso llamante no tiene hijos que no hayan sido esperados.
ECHILD
(para waitpid() o waitid()) El proceso especificado por pid (waitpid()) o idtype e id (waitid()) no existe o no es un hijo del proceso llamante. (Esto puede ocurrir para el propio hijo si la acción para SIGCHLD está establecida a SIG_IGN. Ver también la sección de Notas de Linux sobre hilos.)
EINTR
WNOHANG no estaba configurado y se capturó una señal no bloqueada o una SIGCHLD; ver signal(7).
EINVAL
El argumento options era inválido.
ESRCH
(para wait() o waitpid()) pid es igual a INT_MIN.

VERSIONES

Diferencias entre biblioteca C/kernel

wait() es en realidad una función de biblioteca que (en glibc) se implementa como una llamada a wait4(2).

En algunas arquitecturas, no existe la llamada al sistema waitpid(); en su lugar, esta interfaz se implementa a través de una función de envoltura de la biblioteca C que llama a wait4(2).

La llamada al sistema bruta waitid() toma un quinto argumento, de tipo struct rusage *. Si este argumento no es NULL, se utiliza para devolver información de uso de recursos sobre el hijo, de la misma manera que wait4(2). Ver getrusage(2) para detalles.

ESTANDARES

POSIX.1-2024.

HISTORIAL

SVr4, 4.3BSD, POSIX.1-2001.

NOTAS

Un hijo que termina, pero que no ha sido esperado se convierte en un "zombie". El kernel mantiene un conjunto mínimo de información sobre el proceso zombie (PID, estado de terminación, información de uso de recursos) para permitir que el padre realice una espera posteriormente para obtener información sobre el hijo. Mientras un zombie no sea eliminado del sistema mediante una espera, consumirá una ranura en la tabla de procesos del kernel y, si esta tabla se llena, no será posible crear más procesos. Si un proceso padre termina, sus hijos "zombies" (si los hay) son adoptados por init(1) (o por el proceso "subreaper" más cercano, según se defina a través del uso de la operación PR_SET_CHILD_SUBREAPER de prctl(2)); init(1) realiza automáticamente una espera para eliminar los zombies.

POSIX.1-2001 especifica que si la disposición de SIGCHLD está establecida a SIG_IGN o si la bandera SA_NOCLDWAIT está establecida para SIGCHLD (ver sigaction(2)), entonces los hijos que terminan no se convierten en zombies y una llamada a wait() o waitpid() se bloqueará hasta que todos los hijos hayan terminado, y luego fallará con errno establecido a ECHILD. (El estándar POSIX original dejó sin especificar el comportamiento de establecer SIGCHLD a SIG_IGN. Tenga en cuenta que aunque la disposición predeterminada de SIGCHLD es "ignorar", establecer explícitamente la disposición a SIG_IGN resulta en un tratamiento diferente de los hijos zombies.)

Linux 2.6 cumple con los requisitos de POSIX. Sin embargo, Linux 2.4 (y anteriores) no lo hace: si se realiza una llamada wait() o waitpid() mientras se está ignorando SIGCHLD, la llamada se comporta como si SIGCHLD no estuviera siendo ignorada, es decir, la llamada se bloquea hasta que el siguiente hijo termina y luego regresa el ID del proceso y el estado de ese hijo.

Notas de Linux

En el kernel de Linux, un hilo programado por el kernel no es una construcción distinta de un proceso. En cambio, un hilo es simplemente un proceso que se crea utilizando la llamada al sistema clone(2), única en Linux; otras rutinas como la llamada portable pthread_create(3) se implementan utilizando clone(2). Antes de Linux 2.4, un hilo era solo un caso especial de un proceso, y como consecuencia, un hilo no podía esperar a los hijos de otro hilo, incluso cuando este último pertenece al mismo grupo de hilos. Sin embargo, POSIX prescribe dicha funcionalidad, y desde Linux 2.4 un hilo puede, y por defecto lo hará, esperar a los hijos de otros hilos en el mismo grupo de hilos.

Las siguientes options específicas de Linux son para usar con hijos creados utilizando clone(2); también pueden, desde Linux 4.7, usarse con waitid():

__WCLONE
Esperar solo a hijos "clone". Si se omite, entonces esperar solo a hijos "no-clone". (Un hijo "clone" es aquel que no entrega ninguna señal, o una señal distinta de SIGCHLD a su padre al terminar). Esta opción se ignora si también se especifica __WALL.
__WALL (desde Linux 2.4)
Esperar a todos los hijos, independientemente del tipo ("clone" o "no-clone").
__WNOTHREAD (desde Linux 2.4)
No esperar a los hijos de otros hilos en el mismo grupo de hilos. Este era el comportamiento predeterminado antes de Linux 2.4.

Desde Linux 4.7, la bandera __WALL se implica automáticamente si el hijo está siendo ptraced.

ERRORES DE PROGRAMACIÓN

Según POSIX.1-2008, una aplicación que llama a waitid() debe asegurarse de que infop apunte a una estructura siginfo_t (es decir, que sea un puntero no nulo). En Linux, si infop es NULL, waitid() tiene éxito y devuelve el ID del proceso del hijo esperado. Las aplicaciones deben evitar depender de esta característica inconsistente, no estándar e innecesaria.

DESCRIPCIÓN

El padre procede a través de un bucle que supervisa al hijo utilizando waitpid(), y usa las macros W*() descritas anteriormente para analizar el valor de estado de espera. La llamada al sistema `waitpid` proporciona información detallada sobre el estado de un proceso hijo terminado o detenido.

La siguiente sesión de shell demuestra el uso del programa:


$ ./a.out &
Child PID is 32360
[1] 32359
$ kill -STOP 32360
stopped by signal 19
$ kill -CONT 32360
continued
$ kill -TERM 32360
killed by signal 15
[1]+  Done                    ./a.out
$

Código fuente del programa

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int    wstatus;
    pid_t  cpid, w;
    cpid = fork();
    if (cpid == -1) {
        perror("fork");
        exit(EXIT_FAILURE);
    }
    if (cpid == 0) {            /* Código ejecutado por el hijo */
        printf("Child PID is %jd\n", (intmax_t) getpid());
        if (argc == 1)
            pause();                    /* Esperar señales */
        _exit(atoi(argv[1]));
    } else {                    /* Código ejecutado por el padre */
        do {
            w = waitpid(cpid, &wstatus, WUNTRACED | WCONTINUED);
            if (w == -1) {
                perror("waitpid");
                exit(EXIT_FAILURE);
            }
            if (WIFEXITED(wstatus)) {
                printf("exited, status=%d\n", WEXITSTATUS(wstatus));
            } else if (WIFSIGNALED(wstatus)) {
                printf("killed by signal %d\n", WTERMSIG(wstatus));
            } else if (WIFSTOPPED(wstatus)) {
                printf("stopped by signal %d\n", WSTOPSIG(wstatus));
            } else if (WIFCONTINUED(wstatus)) {
                printf("continued\n");
            }
        } while (!WIFEXITED(wstatus) && !WIFSIGNALED(wstatus));
        exit(EXIT_SUCCESS);
    }
}
