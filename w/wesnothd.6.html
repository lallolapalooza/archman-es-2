WESNOTHD(6) Daimon de red multijugador de Battle for Wesnoth WESNOTHD(6)

NOMBRE

wesnothd - Daemón de red multijugador de Battle for Wesnoth

SINOPSIS

wesnothd [-dv] [-c ruta] [-p puerto] [-t número] [-T número]
wesnothd -V

DESCRIPCIÓN

Gestiona partidas multijugador de Battle for Wesnoth. Consulta https://www.wesnoth.org/wiki/ServerAdministration sobre qué comandos acepta el servidor a través del cliente wesnoth (/query ...) o el fifo.

OPCIONES

-c ruta, --config ruta
indica a wesnothd dónde encontrar el archivo de configuración a utilizar. Consulta la sección CONFIGURACIÓN DEL SERVIDOR más abajo para ver la sintaxis. Puedes recargar la configuración enviando SIGHUP al proceso del servidor.
-d, --daemon
ejecuta wesnothd como un demonio.
-h, --help
muestra qué hacen las opciones de la línea de comandos.
--log-nivel=dominio1,dominio2,...
establece el nivel de severidad de los dominios de registro. all puede usarse para coincidir con cualquier dominio de registro. Niveles disponibles: error, warning, info, debug. Por defecto, se usa el nivel error y el nivel info para el dominio server.
-p puerto, --port puerto
enlaza el servidor al puerto especificado. Si no se especifica ningún puerto, se usará el puerto 15000.
-t número, --threads número
establece el número máximo de hilos trabajadores en espera para E/S de red a n (por defecto: 5, máx.: 30).
-T número, --max-threads número
establece el número máximo de hilos trabajadores que se crearán. Si se establece en 0, no habrá límite (por defecto: 0).
-V, --version
muestra el número de versión y sale.
-v, --verbose
activa el registro de depuración.

CONFIGURACIÓN DEL SERVIDOR

La sintaxis general es:

[etiqueta]

clave="valor"
clave="valor,valor,..."

[/etiqueta]

Claves generales:

allow_remote_shutdown
Si se establece en no (por defecto), las solicitudes de apagado y reinicio se ignoran a menos que provengan del fifo. Establécelo en yes para permitir el apagado remoto a través de un /query de un administrador.
ban_save_file
Ruta completa o relativa a un archivo (comprimido con gzip) que el servidor puede leer y escribir. Las prohibiciones se guardarán en este archivo y se leerán de nuevo al inicio del servidor.
compress_stored_rooms
Determina si el archivo de salas debe leerse y escribirse en formato comprimido. Por defecto es yes.
connections_allowed
El número de conexiones permitidas desde la misma IP. 0 significa infinito. (por defecto: 5)
deny_unregistered_login
Si se debe impedir que inicien sesión usuarios que no están registrados con el manejador de usuarios user_handler que se esté utilizando. (por defecto: false)
disallow_names
Nombres/nicks que no son aceptados por el servidor. Se admiten patrones comodín * y ?. Consulta glob(7) para más detalles. Los valores por defecto (usados si no se especifica nada) son: *admin*,*admln*,*server*,ai,ai?,computer,human,network,player.
fifo_path
La ruta al fifo en el que puedes enviar comandos del servidor (lo mismo que /query ... desde wesnoth). Si no se especifica, se usa la ruta definida en tiempo de compilación (por defecto: /var/run/wesnothd/socket).
max_messages
El número de mensajes permitidos en messages_time_period. (por defecto: 4)
messages_time_period
El período de tiempo (en segundos) en el que se detecta el bombardeo de mensajes. (por defecto: 10 segundos)
motd
El mensaje del día.
new_room_policy
Determina quién puede crear salas nuevas en el servidor. Los valores disponibles son everyone, registered, admin y nobody, y otorgan el permiso respectivamente a todo el mundo, usuarios registrados, usuarios administradores o deshabilitan la creación de salas nuevas. El valor por defecto es everyone.
passwd
La contraseña utilizada para obtener privilegios de administrador (a través de /query admin contraseña).
replay_save_path
El directorio donde el servidor guarda las repeticiones de partidas. (¡No olvides la barra inclinada al final!) Por defecto es `'`, lo que significa el directorio en el que se inició wesnothd.
restart_command
El comando que utiliza el servidor para iniciar un nuevo proceso de servidor a través del comando restart. (Solo se puede emitir a través del fifo. Consulta la configuración allow_remote_shutdown.)
room_save_file
Ruta a un archivo donde se debe almacenar la información de las salas. Este archivo se lee al inicio del servidor y se escribe más tarde. Si está vacío o no está establecido, las salas no se cargan ni se guardan.
save_replays
Define si el servidor guardará automáticamente las repeticiones de las partidas. (por defecto: false)
tls_enabled
Habilita el uso de TLS. Si es verdadero, requiere que también se establezcan las 3 opciones siguientes.
tls_fullchain
Cadena completa de certificados TLS en formato .pem
tls_private_key
clave privada para TLS en formato .pem
tls_dh
parámetros DH de TLS, como archivo .pem. Generar con openssl dhparam -out nombre_archivo.pem 4096
versions_accepted
Lista de versiones de Wesnoth que el servidor aceptará. Las versiones se especifican como listas separadas por comas de rangos de versiones, como por ejemplo "1.13.0-1.13.10,1.14.0". Si está vacío, cualquier versión es aceptada. Por defecto, se especifica la versión de compilación.

Errores

Los errores son reportados a la consola, o a syslog si el servidor se ejecuta como demonio.

SERVER CONFIG

The configuration file for the server is located in ~/.local/share/wesnoth/config/servers.cfg (or %APPDATA%/wesnoth/config/servers.cfg on Windows). This file is an INI file with some special tags.

versions_accepted
Una lista separada por comas de cadenas de versión que serán aceptadas por el servidor. Se admiten * y ? de patrones comodín. (por defecto es la versión de wesnoth correspondiente)
Ejemplo: versions_accepted="*" acepta cualquier cadena de versión.
id
La identificación del servidor cuando se utiliza la funcionalidad de base de datos para almacenar información del juego. Generalmente es la versión principal.secundaria de los clientes aceptados, como 1.16 o 1.17.

Etiquetas globales:

[redirect] Una etiqueta para especificar un servidor al que redirigir ciertas versiones de cliente. No se utiliza si versions_accepted no está configurado.

host
La dirección del servidor al que redirigir.
port
El puerto al que conectarse.
version
Una lista separada por comas de versiones a redirigir. Se comporta de la misma manera que versions_accepted con respecto a los patrones comodín.

[ban_time] Una etiqueta para definir palabras clave convenientes para duraciones de tiempo de prohibición temporal.

name
El nombre utilizado para referirse al tiempo de prohibición.
time
La definición de la duración. El formato es: %d[%s[%d%s[...]]] donde %s es s (segundos), m (minutos), h (horas), D (días), M (meses) o Y (años) y %d es un número. Si no se proporciona modificador de tiempo, se asumen minutos (m). Ejemplo: time="1D12h30m" da como resultado un tiempo de prohibición de 1 día, 12 horas y 30 minutos.

[proxy] Una etiqueta para indicar al servidor que actúe como un proxy y reenvíe las solicitudes del cliente conectado al servidor especificado. Acepta las mismas claves que [redirect].

[user_handler] Configura el manejador de usuarios. Si no hay una sección [user_handler] en la configuración, el servidor se ejecutará sin ningún servicio de registro de nicks. Todas las tablas adicionales que se necesiten para que el forum_user_handler funcione se pueden encontrar en table_definitions.sql en el repositorio de código fuente de Wesnoth. Requiere que el soporte mysql esté habilitado. Para cmake esto es ENABLE_MYSQL y para scons es forum_user_handler.

db_host
El nombre del host del servidor de base de datos
db_name
El nombre de la base de datos
db_user
El nombre del usuario con el que iniciar sesión en la base de datos
db_password
La contraseña de este usuario
db_users_table
El nombre de la tabla en la que tu foro phpbb guarda sus datos de usuario. Lo más probable es que sea <prefijo-tabla>_users (por ejemplo, phpbb3_users).
db_extra_table
El nombre de la tabla en la que wesnothd guardará sus propios datos sobre los usuarios.
db_game_info_table
El nombre de la tabla en la que wesnothd guardará sus propios datos sobre los juegos.
db_game_player_info_table
El nombre de la tabla en la que wesnothd guardará sus propios datos sobre los jugadores en un juego.
db_game_modification_info_table
El nombre de la tabla en la que wesnothd guardará sus propios datos sobre las modificaciones utilizadas en un juego.
db_user_group_table
El nombre de la tabla en la que tu foro phpbb guarda sus datos de grupo de usuarios. Lo más probable es que sea <prefijo-tabla>_user_group (por ejemplo, phpbb3_user_group).
db_connection_history_table
El nombre de la tabla en la que se almacenarán los tiempos de inicio/cierre de sesión. También se utiliza para relacionar IPs con usuarios y viceversa.
db_topics_table
El nombre de la tabla en la que tu foro phpbb guarda la información de sus temas (hilos). Lo más probable es que sea <prefijo-tabla>_topics (por ejemplo, phpbb3_topics).
db_banlist_table
El nombre de la tabla en la que tu foro phpbb guarda los datos de prohibición de usuarios. Lo más probable es que sea <prefijo-tabla>_banlist (por ejemplo, phpbb3_banlist).
mp_mod_group
La identificación del grupo del foro que se considerará que tiene autoridad de moderación.

ESTADO DE SALIDA

El estado de salida normal es 0 cuando el servidor se apaga correctamente. Un estado de salida de 2 indica un error con las opciones de línea de comandos.
