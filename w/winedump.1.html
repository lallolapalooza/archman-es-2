NOMBRE

winedump - Herramienta de DLL de Wine

SINOPSIS

winedump [-h | sym sym | spec dll | dump archivo ] [opciones_modo]

DESCRIPCIÓN

winedump es una herramienta de Wine que tiene como objetivo ayudar a:

- A: Reimplementar una DLL de Win32 para usarla dentro de Wine, o
- B: Compilar una aplicación de Win32 con Winelib que utiliza DLLs x86

Para ambas tareas, con el fin de poder enlazar las funciones de Win, se necesita algo de código de conexión. Este 'pegamento' viene en forma de un archivo .spec. El archivo .spec, junto con algo de código dummy, se utiliza para crear un archivo .so de Wine correspondiente a la DLL de Windows. El programa winebuild puede entonces resolver las llamadas a las funciones de la DLL.

Crear un archivo .spec es una tarea laboriosa durante la cual es fácil cometer un error. La idea de winedump es automatizar esta tarea y crear la mayoría del código de soporte necesario para tu DLL. Además, puedes hacer que winedump cree código para ayudarte a reimplementar una DLL, proporcionando un seguimiento de las llamadas a la DLL y (en algunos casos) determinando automáticamente los parámetros, las convenciones de llamada y los valores de retorno de las funciones de la DLL.

Otro uso para esta herramienta es mostrar (volcar) información sobre una DLL de 32 bits o un archivo de imagen en formato PE. Cuando se utiliza de esta manera, winedump funciona de forma similar a herramientas como pedump proporcionadas por muchos proveedores de compiladores Win32.

Finalmente, winedump también se puede utilizar para 'desenredar' símbolos de C++.

MODOS

winedump se puede utilizar en varios modos diferentes. El primer argumento del programa determina el modo en que se ejecutará winedump.

-h
Modo de ayuda. Se imprime una ayuda básica de uso.
dump
Para volcar el contenido de un archivo.
spec
Para generar archivos .spec y DLLs stub.
sym
Modo de símbolos. Se utiliza para desenredar símbolos de C++.

OPCIONES

Las opciones del modo dependen del modo dado como primer argumento.

Modo de ayuda

No se utilizan opciones. El programa imprime la información de ayuda y luego sale.

Modo de volcado

archivo
Vuelca el contenido del archivo. Se admiten varios formatos de archivo (PE, NE, LE, Minidumps, .lnk).
-C
Activa el desenredado de símbolos.
-f
Vuelca información del encabezado del archivo. Esta opción solo vuelca las estructuras estándar del encabezado PE, junto con las secciones COFF disponibles en el archivo.
-j nombre_dir
Vuelca solo el contenido del directorio nombre_dir, para archivos cuyos encabezados apuntan a directorios. Para archivos PE, se implementan los directorios import, export, debug, resource, tls, loadcfg, clr, reloc y except, así como la sección apiset. Para archivos NE, se implementan los directorios export y resource.
-x
Vuelca todo. Este comando imprime toda la información disponible (incluidos todos los directorios disponibles - ver opción -j) sobre el archivo. Es posible que desees canalizar la salida a través de more/less o a un archivo, ya que se producirá una gran cantidad de salida.
-G
Vuelca el contenido de la sección de depuración, si existe (por ahora, solo se admite información stabs).

Modo de especificación

dll
Usa dll como archivo de entrada y genera código de implementación.
-I dir
Busca prototipos en dir (implica -c). En el caso de DLLs de Windows, este podría ser el directorio de inclusión estándar de tu compilador o un directorio de inclusión de SDK. Si tienes un documento de texto con prototipos (como documentación) que también se puede usar, es posible que necesites eliminar algunas líneas que no son de código para asegurarte de que los prototipos se analicen correctamente. El argumento dir también puede ser una especificación de archivo (por ejemplo, include/*). Si contiene comodines, debes entrecomillarlo para evitar que el shell lo expanda. Si no tienes prototipos, especifica /dev/null como dir. winedump aún podría ser capaz de generar algo de código stub funcional para ti.
-c
Genera código esqueleto (requiere -I). Esta opción indica a winedump que cree stubs de función para cada función en la DLL. A medida que winedump lee cada símbolo exportado de la DLL de origen, primero intenta desenredar el nombre. Si el nombre es un símbolo de C++, los argumentos, la clase y el valor de retorno se codifican en el nombre del símbolo. Winedump convierte esta información en un prototipo de función C. Si esto falla, se escanean los archivos especificados en el argumento -I en busca de un prototipo de función. Si se encuentra uno, se utiliza para el siguiente paso del proceso, la generación de código.
-t
Argumentos de RASTREO (implica -c). Esta opción produce el mismo código que -c, excepto que los argumentos se imprimen cuando se llama a la función. Las estructuras que se pasan por valor se imprimen como "struct", y las funciones que toman listas de argumentos variables imprimen "...".
-f dll
Reenvía llamadas a dll (implica -t). Este es el nivel más complicado de generación de código. Se genera el mismo código que con **-t**, sin embargo, se agrega soporte para reenviar llamadas a otra DLL. La DLL a la que se reenviarán se proporciona como dll.
-D
Genera documentación. Por defecto, winedump genera un comentario estándar en la cabecera de cada función que genera. Al pasar esta opción, winedump genera una plantilla de encabezado completa para la documentación estándar de Wine, que enumera los parámetros y el valor de retorno de la función.
-o nombre
Establece el nombre de la DLL de salida (por defecto: dll). Por defecto, si winedump se ejecuta en la DLL foo, crea los archivos foo.spec, foo_main.c, etc., y antepone cualquier función generada con FOO_. Si se proporciona -o bar, estos se convertirán en bar.spec, bar_main.c y BAR_, respectivamente. Esta opción es útil principalmente al generar una DLL de reenvío.
-C
Asume llamadas __cdecl (por defecto: __stdcall). Si winebuild no puede determinar la convención de llamada, se utiliza __stdcall por defecto, a menos que se haya proporcionado esta opción. A menos que se proporcione **-q**, se imprimirá una advertencia para cada función para la que winedump determine la convención de llamada y que no coincida con la convención de llamada asumida.
-s num
Comienza la búsqueda de prototipos después del símbolo num.
-e num
Finaliza la búsqueda de prototipos después del símbolo num. Al proporcionar las opciones -s o -e, puedes hacer que winedump intente generar código solo para algunas funciones de tu DLL. Esto se puede utilizar para generar una sola función, por ejemplo, si desearas añadir funcionalidad a una DLL existente.
-S archivo_simbolos
Busca solo los nombres de prototipos encontrados en archivo_simbolos. Si deseas generar código solo para un subconjunto de las funciones exportadas de tu DLL de origen, puedes usar esta opción para proporcionar un archivo de texto que contenga los nombres de los símbolos a extraer, uno por línea. Solo los símbolos presentes en este archivo se utilizarán en tu DLL de salida.
-q
No mostrar progreso (silencioso). No se imprime ninguna salida a menos que se produzca un error fatal.
-v

Modo de símbolos

simbolo
Desenreda el símbolo proporcionado.

EJEMPLOS

Para generar una especificación y código stub para la DLL user32.dll:

$ winedump spec user32.dll

Para generar código stub para la DLL user32.dll, especificando el directorio de inclusión y activando el rastreo de argumentos y la generación de documentación:

$ winedump spec -I/usr/include/wine -t -D user32.dll

Para reenviar todas las llamadas de user32.dll a native/user32.dll:

$ winedump spec -f native/user32.dll user32.dll

Para volcar la información del encabezado de la DLL user32.dll:

$ winedump dump -f user32.dll

Para volcar el directorio de importación de la DLL user32.dll:

$ winedump dump -j import user32.dll

Para volcar toda la información de la DLL user32.dll y guardarla en un archivo:

$ winedump dump -x user32.dll > user32.dump

Para desenredar un símbolo C++:

$ winedump sym "?MyClass@MyNamespace::MyMethod(int,float)"

OPTIONS

-q
Quiet mode. Suppresses the normal output detailing the progress of winedump. Only error messages will be shown.
-v
Show lots of detail while working (verbose). There are 3 levels of output while winedump is running. The default level, when neither -q or -v are given, prints the number of exported functions found in the dll, followed by the name of each function as it is processed, and a status indication of whether it was processed OK. With -v given, a lot of information is dumped while winedump works: this is intended to help debug any problems.

Modo Sym

sym
Desanuda el símbolo C++ sym y luego sale.

FILES

function_grep.pl
Script de Perl utilizado para recuperar un prototipo de función.

Archivos de salida en modo spec para foo.dll:

foo.spec
Este es el archivo .spec.
foo_dll.h, foo_main.c
Estos son los archivos de código fuente que contienen el conjunto mínimo de código para construir una DLL de stub. El archivo C contiene una función, FOO_Init, que no hace nada (pero debe estar presente).
Makefile.in
Esta es una plantilla para que configure produzca un makefile. Está diseñada para una DLL que se insertará en el árbol de fuentes de Wine.

BUGS

La desanidación de nombres de C++ no está completamente sincronizada con la implementación en msvcrt. Puede ser útil enviar su nombre de C++ al conjunto de pruebas para msvcrt.

Los errores pueden ser reportados en el rastreador de errores de Wine.
