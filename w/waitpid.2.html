wait(2) Manual de llamadas al sistema wait(2)

NOMBRE

wait, waitpid, waitid - esperar a que un proceso cambie de estado

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/wait.h>
pid_t wait(int *_Nullable wstatus);
pid_t waitpid(pid_t pid, int *_Nullable wstatus, int options);
int waitid(idtype_t idtype, id_t id, siginfo_t *infop, int options);
                /* Esta es la interfaz de glibc y POSIX; ver
                   VERSIONS para información sobre la llamada al sistema
                   en bruto.  */

DESCRIPCIÓN

Todas estas llamadas al sistema se utilizan para esperar cambios de estado en un hijo del proceso llamante, y obtener información sobre el hijo cuyo estado ha cambiado. Se considera un cambio de estado: que el hijo terminó; que el hijo fue detenido por una señal; o que el hijo se reanudó por una señal. En el caso de un hijo terminado, realizar una espera permite al sistema liberar los recursos asociados con el hijo; si no se realiza una espera, el hijo terminado permanece en un estado de "zombi" (ver NOTAS más abajo).

Si un hijo ya ha cambiado de estado, estas llamadas regresan inmediatamente. De lo contrario, se bloquean hasta que un hijo cambie de estado o un manejador de señales interrumpa la llamada (suponiendo que las llamadas al sistema no se reinician automáticamente usando la bandera SA_RESTART de sigaction(2)). En el resto de esta página, un hijo cuyo estado ha cambiado y que aún no ha sido esperado por una de estas llamadas al sistema se denomina esperable.

wait() y waitpid()

La llamada al sistema wait() suspende la ejecución del hilo llamante hasta que uno de sus hijos termine. La llamada wait(&wstatus) es equivalente a:


waitpid(-1, &wstatus, 0);

La llamada al sistema waitpid() suspende la ejecución del hilo llamante hasta que un hijo especificado por el argumento pid haya cambiado de estado. Por defecto, waitpid() espera solo a hijos terminados, pero este comportamiento se puede modificar a través del argumento options, como se describe a continuación.

El valor de pid puede ser:

< -1
significa esperar a cualquier proceso hijo cuyo ID de grupo de procesos sea igual al valor absoluto de pid.
-1
significa esperar a cualquier proceso hijo.
0
significa esperar a cualquier proceso hijo cuyo ID de grupo de procesos sea igual al del proceso llamante en el momento de la llamada a waitpid().
> 0
significa esperar al hijo cuyo ID de proceso sea igual al valor de pid.

El valor de options es una combinación OR de cero o más de las siguientes constantes:

WNOHANG
regresar inmediatamente si ningún hijo ha terminado.
WUNTRACED
también regresar si un hijo se ha detenido (pero no está siendo rastreado mediante ptrace(2)). El estado para hijos *rastreados* que se han detenido se proporciona incluso si esta opción no se especifica.
WCONTINUED (desde Linux 2.6.10)
también regresar si un hijo detenido se ha reanudado por la entrega de SIGCONT.

(Para opciones solo de Linux, ver más abajo.)

Si wstatus no es NULL, wait() y waitpid() almacenan información de estado en el int al que apunta. Este entero puede ser inspeccionado con las siguientes macros (que toman el entero mismo como argumento, no un puntero a él, como se hace en wait() y waitpid!):

WIFEXITED(wstatus)
devuelve verdadero si el hijo terminó normalmente, es decir, llamando a exit(3) o _exit(2), o al regresar de main().
WEXITSTATUS(wstatus)
devuelve el estado de salida del hijo. Esto consiste en los 8 bits menos significativos del argumento status que el hijo especificó en una llamada a exit(3) o _exit(2) o como argumento para una declaración de retorno en main(). Esta macro solo debe emplearse si WIFEXITED devolvió verdadero.
WIFSIGNALED(wstatus)
devuelve verdadero si el proceso hijo fue terminado por una señal.
WTERMSIG(wstatus)
devuelve el número de la señal que provocó la terminación del proceso hijo. Esta macro solo debe emplearse si WIFSIGNALED devolvió verdadero.
WCOREDUMP(wstatus) // POSIX.1-2024
devuelve verdadero si el hijo produjo un volcado de núcleo (ver core(5)). Esta macro solo debe emplearse si WIFSIGNALED devolvió verdadero.
WIFSTOPPED(wstatus) // POSIX.1-2024
devuelve verdadero si el proceso hijo fue detenido por la entrega de una señal; esto es posible solo si la llamada se realizó usando WUNTRACED o cuando el hijo está siendo rastreado (ver ptrace(2)).
WSTOPSIG(wstatus)
devuelve el número de la señal que causó que el hijo se detuviera. Esta macro solo debe emplearse si WIFSTOPPED devolvió verdadero.
WIFCONTINUED(wstatus)
(desde Linux 2.6.10) devuelve verdadero si el proceso hijo se reanudó por la entrega de SIGCONT.

waitid()

La llamada al sistema waitid() (disponible desde Linux 2.6.9) proporciona un control más preciso sobre los cambios de estado del hijo que se deben esperar.

Los argumentos idtype e id seleccionan el(los) hijo(s) a esperar, de la siguiente manera:

idtype == P_PID
Esperar al hijo cuyo ID de proceso coincide con id.
idtype == P_PIDFD (desde Linux 5.4)
Esperar al hijo al que se refiere el descriptor de archivo PID en id. (Ver pidfd_open(2) para más información sobre descriptores de archivo PID.)
idtype == P_PGID
Esperar a cualquier hijo cuyo ID de grupo de procesos coincida con id. Desde Linux 5.4, si id es cero, entonces esperar a cualquier hijo que esté en el mismo grupo de procesos que el grupo de procesos del llamante en el momento de la llamada.
idtype == P_ALL
Esperar a cualquier hijo; id es ignorado.

Los cambios de estado del hijo a esperar se especifican combinando (OR) una o más de las siguientes banderas en options:

WEXITED
Esperar a los hijos que han terminado.
WSTOPPED
Esperar a los hijos que han sido detenidos por la entrega de una señal.
WCONTINUED
Esperar a los hijos (previamente detenidos) que se han reanudado por la entrega de SIGCONT.

Las siguientes banderas pueden combinarse adicionalmente (OR) en options:

WNOHANG
Como en
r waitpid().
WNOWAIT
Deja el hijo en un estado que permite esperar; una llamada posterior a wait puede ser usada para recuperar nuevamente la información del estado del hijo.

Al retornar exitosamente, waitid() llena los siguientes campos de la estructura siginfo_t apuntada por infop:

si_pid
El ID de proceso del hijo.
si_uid
El ID de usuario real del hijo. (Este campo no está establecido en la mayoría de otras implementaciones.)
si_signo
Siempre establecido a SIGCHLD.
si_status
El estado de salida del hijo, como se le dio a _exit(2) (o exit(3)), o la señal que causó que el hijo terminara, se detuviera, o continuara. El campo si_code puede ser usado para determinar cómo interpretar este campo.
si_code
Establecido a uno de: CLD_EXITED (hijo llamó a _exit(2)); CLD_KILLED (hijo terminado por señal); CLD_DUMPED (hijo terminado por señal y volcó un core); CLD_STOPPED (hijo detenido por señal); CLD_TRAPPED (hijo trazado ha sido atrapado); o CLD_CONTINUED (hijo continuado por SIGCONT).

Si WNOHANG fue especificado en options y no había hijos en un estado que permitiera esperar, entonces waitid() retorna 0 inmediatamente y el estado de la estructura siginfo_t apuntada por infop depende de la implementación. Para distinguir (de forma portable) este caso del en que un hijo estaba en un estado que permitía esperar, ponga a cero el campo si_pid antes de la llamada y verifique un valor no cero en este campo después de que la llamada retorne.

POSIX.1-2008 Technical Corrigendum 1 (2013) agrega el requisito de que cuando WNOHANG se especifica en options y no había hijos en un estado que permitiera esperar, entonces waitid() debe poner a cero los campos si_pid y si_signo de la estructura. En Linux y otras implementaciones que se adhieren a este requisito, no es necesario poner a cero el campo si_pid antes de llamar a waitid(). Sin embargo, no todas las implementaciones siguen la especificación POSIX.1 en este punto.

VALOR DE RETORNO

wait(): en éxito, retorna el ID de proceso del hijo terminado; en fallo, se retorna -1.

waitpid(): en éxito, retorna el ID de proceso del hijo cuyo estado ha cambiado; si WNOHANG fue especificado y uno o más hijo(s) especificado(s) por pid existen, pero aún no han cambiado de estado, entonces se retorna 0. En fallo, se retorna -1.

waitid(): retorna 0 en éxito o si WNOHANG fue especificado y ningún hijo(s) especificado(s) por id ha cambiado de estado todavía; en fallo, se retorna -1.

En fallo, cada una de estas llamadas establece errno para indicar el error.

ERRORES

EAGAIN
El descriptor de archivo PID especificado en id no es bloqueante y el proceso al que se refiere no ha terminado.
ECHILD
(para wait()) El proceso llamante no tiene hijos sin esperar.
ECHILD
(para waitpid() o waitid()) El proceso especificado por pid (waitpid()) o idtype e id (waitid()) no existe o no es un hijo del proceso llamante. (Esto puede ocurrir para un hijo propio si la acción para SIGCHLD está establecida a SIG_IGN. Ver también la sección de Notas de Linux sobre hilos.)
EINTR
WNOHANG no estaba establecido y una señal no bloqueada o una SIGCHLD fue capturada; ver signal(7).
EINVAL
El argumento options era inválido.
ESRCH
(para wait() o waitpid()) pid es igual a INT_MIN.

VERSIONES

Diferencias de la biblioteca C/núcleo

wait() es en realidad una función de biblioteca que (en glibc) está implementada como una llamada a wait4(2).

En algunas arquitecturas, no hay llamada de sistema waitpid(); en su lugar, esta interfaz se implementa a través de una función envoltorio de la biblioteca C que llama a wait4(2).

La llamada de sistema cruda waitid() toma un quinto argumento, de tipo struct rusage *. Si este argumento no es NULL, entonces se usa para retornar información de uso de recursos sobre el hijo, de la misma manera que wait4(2). Ver getrusage(2) para detalles.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

SVr4, 4.3BSD, POSIX.1-2001.

NOTAS

Un hijo que termina, pero no ha sido esperado se convierte en un "zombie". El kernel mantiene un conjunto mínimo de información sobre el proceso zombie (PID, estado de terminación, información de uso de recursos) para permitir que el padre realice una espera para obtener información sobre el hijo. Mientras un zombie no sea eliminado del sistema mediante una espera, consumirá un espacio en la tabla de procesos del kernel, y si esta tabla se llena, no será posible crear más procesos. Si un proceso padre termina, entonces sus hijos "zombie" (si los hay) son adoptados por init(1), (o por el proceso "subreaper" más cercano según se define a través del uso de la operación prctl(2) PR_SET_CHILD_SUBREAPER); init(1) realiza automáticamente una espera para eliminar los zombies.

POSIX.1-2001 especifica que si la disposición de SIGCHLD está establecida a SIG_IGN o la bandera SA_NOCLDWAIT está establecida para SIGCHLD (ver sigaction(2)), entonces los hijos que terminan no se convierten en zombies y una llamada a wait() o waitpid() se bloqueará hasta que todos los hijos hayan terminado, y luego fallará con errno establecido a ECHILD. (El estándar POSIX original dejó sin especificar el comportamiento de establecer SIGCHLD a SIG_IGN. Tenga en cuenta que aunque la disposición predeterminada de SIGCHLD es "ignorar", establecer explícitamente la disposición a SIG_IGN resulta en un tratamiento diferente de los hijos zombie.)

Linux 2.6 cumple con los requisitos POSIX. Sin embargo, Linux 2.4 (y anteriores) no lo hace: si se realiza una llamada a wait() o waitpid() mientras se está ignorando SIGCHLD, la llamada se comporta como si SIGCHLD no estuviera siendo ignorado, es decir, la llamada se bloquea hasta que el próximo hijo termina y luego retorna el ID de proceso y el estado de ese hijo.

Notas de Linux

En el kernel de Linux, un hilo programado por el kernel no es una construcción distinta de un proceso. En cambio, un hilo es simplemente un proceso que se crea usando la llamada de sistema clone(2), única de Linux; otras rutinas como la llamada portable pthread_create(3) se implementan usando clone(2). Antes de Linux 2.4, un hilo era solo un caso especial de un proceso, y como consecuencia, un hilo no podía esperar por los hijos de otro hilo, incluso cuando este último pertenecía al mismo grupo de hilos. Sin embargo, POSIX prescribe tal funcionalidad, y desde Linux 2.4, un hilo puede, y por defecto lo hará, esperar por los hijos de otros hilos en el mismo grupo de hilos.

Las siguientes options específicas de Linux son para uso con hijos creados usando clone(2); también pueden ser usadas, desde Linux 4.7, con waitid():

__WCLONE
Esperar solo por hijos "clone". Si se omite, esperar solo por hijos "no-clone". (Un hijo "clone" es uno que no entrega ninguna señal, o una señal diferente de SIGCHLD a su padre al terminar.) Esta opción se ignora si también se especifica __WALL.
__WALL (desde Linux 2.4)
Esperar por todos los hijos, independientemente del tipo ("clone" o "no-clone").
__WNOTHREAD (desde Linux 2.4)
No esperar por hijos de otros hilos en el mismo grupo de hilos. Este era el comportamiento predeterminado antes de Linux 2.4.

Desde Linux 4.7, la bandera __WALL se implica automáticamente si el hijo está siendo ptraced.

ERRORES DE PROGRAMACIÓN

Según POSIX.1-2008, una aplicación que llama a waitid() debe asegurarse de que infop apunte a una estructura siginfo_t (es decir, que sea un puntero no nulo). En Linux, si infop es NULL, waitid() tiene éxito y retorna el ID de proceso del hijo esperado. Las aplicaciones deben evitar depender de esta característica inconsistente, no estándar y innecesaria.

EJEMPLOS

El siguiente programa demuestra el uso de fork(2) y waitpid(). El programa crea un proceso hijo. Si no se proporciona ningún argumento de línea de comandos al programa, entonces el hijo suspende su ejecución usando pause(2), para permitir al usuario enviar señales al hijo. De lo contrario, si se proporciona un argumento de línea de comandos, entonces el hijo sale inmediatamente, utilizando el entero proporcionado en la línea de comandos como estado de salida. El proceso padre ejecuta un bucle que monitorea al hijo usando waitpid(), y utiliza las macros W*() descritas anteriormente para analizar el valor de estado de espera.

La siguiente sesión de shell demuestra el uso del programa:


$ ./a.out &
PID del hijo i
s 32360 [1] 32359 $ kill -STOP 32360 stopped by signal 19 $ kill -CONT 32360 continued $ kill -TERM 32360 killed by signal 15 [1]+ Done ./a.out $

Fuente del programa

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int    wstatus;
    pid_t  cpid, w;
    cpid = fork();
    if (cpid == -1) {
        perror("fork");
        exit(EXIT_FAILURE);
    }
    if (cpid == 0) {            /* Código ejecutado por el hijo */
        printf("El PID del hijo es %jd\n", (intmax_t) getpid());
        if (argc == 1)
            pause();                    /* Esperar señales */
        _exit(atoi(argv[1]));
    } else {                    /* Código ejecutado por el padre */
        do {
            w = waitpid(cpid, &wstatus, WUNTRACED | WCONTINUED);
            if (w == -1) {
                perror("waitpid");
                exit(EXIT_FAILURE);
            }
            if (WIFEXITED(wstatus)) {
                printf("finalizado, estado=%d\n", WEXITSTATUS(wstatus));
            } else if (WIFSIGNALED(wstatus)) {
                printf("terminado por señal %d\n", WTERMSIG(wstatus));
            } else if (WIFSTOPPED(wstatus)) {
                printf("detenido por señal %d\n", WSTOPSIG(wstatus));
            } else if (WIFCONTINUED(wstatus)) {
                printf("continuado\n");
            }
        } while (!WIFEXITED(wstatus) && !WIFSIGNALED(wstatus));
        exit(EXIT_SUCCESS);
    }
}
