NOMBRE

wg-quick - configura una interfaz WireGuard de forma sencilla

SINOPSIS

wg-quick [ up | down | save | strip ] [ ARCHIVO_CONFIG | INTERFAZ ]

DESCRIPCIÓN

Este es un script extremadamente simple para activar fácilmente una interfaz WireGuard, adecuado para algunos casos de uso comunes.

Utilice up para añadir y configurar una interfaz, y utilice down para desactivar y eliminar una interfaz. Ejecutar up añade una interfaz WireGuard, activa la interfaz con las direcciones IP suministradas, configura el MTU y las rutas, y opcionalmente ejecuta scripts pre/post de subida. Ejecutar down opcionalmente guarda la configuración actual, elimina la interfaz WireGuard y opcionalmente ejecuta scripts pre/post de bajada. Ejecutar save guarda la configuración de una interfaz existente sin desactivarla. Utilice strip para generar un archivo de configuración con todas las opciones específicas de wg-quick(8) eliminadas, adecuado para su uso con wg(8).

ARCHIVO_CONFIG es un archivo de configuración, cuyo nombre es el nombre de la interfaz seguido de `.conf'. De lo contrario, INTERFAZ es un nombre de interfaz, con la configuración encontrada en `/etc/wireguard/INTERFAZ.conf', buscada primero, seguida de las rutas de búsqueda específicas de la distribución.

En términos generales, esta utilidad es solo un script simple que envuelve invocaciones a wg(8) y ip(8) para configurar una interfaz WireGuard. Está diseñado para usuarios con necesidades simples, y se anima encarecidamente a los usuarios con necesidades más avanzadas a utilizar una herramienta más específica, un gestor de red más completo o, de lo contrario, simplemente a usar wg(8) y ip(8), como es habitual.

CONFIGURACIÓN

El archivo de configuración añade algunos valores de configuración adicionales al formato entendido por wg(8) para configurar atributos adicionales de una interfaz. Maneja los valores que comprende y luego pasa los restantes directamente a wg(8) para su posterior procesamiento.

Infiere todas las rutas de la lista de IPs permitidas de los peers, y las añade automáticamente a la tabla de enrutamiento del sistema. Si una de esas rutas es la ruta por defecto (0.0.0.0/0 o ::/0), utiliza ip-rule(8) para gestionar la anulación de la puerta de enlace predeterminada.

El archivo de configuración se pasará directamente al subcomando `setconf' de wg(8), con la excepción de las siguientes adiciones a la sección Interface, que son manejadas por esta herramienta:

  • Address — una lista separada por comas de direcciones IP (v4 o v6) (opcionalmente con máscaras CIDR) que se asignarán a la interfaz. Puede especificarse varias veces.
  • DNS — una lista separada por comas de direcciones IP (v4 o v6) que se establecerán como servidores DNS de la interfaz, o nombres de host no IP que se establecerán como dominios de búsqueda DNS de la interfaz. Puede especificarse varias veces. Al activar la interfaz, esto ejecuta `resolvconf -a tun.INTERFAZ -m 0 -x' y al desactivarla, ejecuta `resolvconf -d tun.INTERFAZ'. Si estas invocaciones particulares de resolvconf(8) son indeseables, las claves PostUp y PostDown a continuación pueden usarse en su lugar.
  • MTU — si no se especifica, el MTU se determina automáticamente a partir de las direcciones de punto final o de la ruta por defecto del sistema, lo cual suele ser una opción sensata. Sin embargo, para especificar manualmente un MTU y anular este descubrimiento automático, este valor puede especificarse explícitamente.
  • Table — Controla la tabla de enrutamiento a la que se añaden las rutas. Hay dos valores especiales: `off' deshabilita la creación de rutas por completo, y `auto' (el valor predeterminado) añade rutas a la tabla por defecto y habilita el manejo especial de las rutas por defecto.
  • PreUp, PostUp, PreDown, PostDown — fragmentos de script que serán ejecutados por bash(1) antes/después de configurar/desactivar la interfaz, comúnmente utilizados para configurar opciones DNS personalizadas o reglas de firewall. La cadena especial `%i' se expande a INTERFAZ. Cada uno puede especificarse varias veces, en cuyo caso los comandos se ejecutan en orden.
  • SaveConfig — si se establece en `true', la configuración se guarda del estado actual de la interfaz al apagarse. Cualquier cambio realizado en el archivo de configuración antes de que se elimine la interfaz se sobrescribirá por lo tanto.

Los nombres de INTERFAZ recomendados incluyen `wg0' o `wgvpn0' o incluso `wgmgmtlan0'. Sin embargo, el número al final es opcional, y realmente cualquier cadena de formato libre [a-zA-Z0-9_=+.-]{1,15} funcionará. Por lo tanto, incluso nombres de interfaz que corresponden a ubicaciones geográficas serían suficientes, como `cincinnati', `nyc' o `paris', si eso fuera de alguna manera deseable.

EJEMPLOS

Estos ejemplos se basan en la misma sintaxis que para wg(8), y una descripción más completa se puede encontrar allí. Las líneas en negrita a continuación son para opciones que extienden wg(8).

Lo siguiente podría usarse para conectarse como cliente a una puerta de enlace VPN para tunelizar todo el tráfico:


[Interface]
Address = 10.200.100.8/24
DNS = 10.200.100.1
PrivateKey = oK56DE9Ue9zK76rAc8pBl6opph+1v36lm7cXXsQKrQM=


[Peer]
PublicKey = GtL7fZc/bLnqZldpVofMCD6hDjrK28SsdLxevJ+qtKU=
PresharedKey = /UwcSPg38hW/D9Y3tcS1FOV0K1wuURMbS0sesJEP5ak=
AllowedIPs = 0.0.0.0/0
Endpoint = demo.wireguard.com:51820

El campo `Address` se añade aquí para configurar la dirección de la interfaz. El campo `DNS` indica que un servidor DNS para la interfaz debe ser configurado a través de resolvconf(8). La entrada de IPs permitidas del peer implica que esta interfaz debe ser configurada como la puerta de enlace predeterminada, lo cual hace este script.

Ampliando el último ejemplo, uno podría intentar el llamado "kill-switch", para prevenir el flujo de paquetes sin cifrar a través de las interfaces no-WireGuard, añadiendo las siguientes dos líneas `PostUp` y `PreDown` a la sección `[Interface]`:


PostUp = iptables -I OUTPUT ! -o %i -m mark ! --mark $(wg show %i fwmark) -m addrtype ! --dst-type LOCAL -j REJECT
PreDown = iptables -D OUTPUT ! -o %i -m mark ! --mark $(wg show %i fwmark) -m addrtype ! --dst-type LOCAL -j REJECT

Los campos `PostUp' y `PreDown' se han añadido para especificar un comando iptables(8) que, cuando se usa con interfaces que tienen un peer que especifica 0.0.0.0/0 como parte de `AllowedIPs', funciona junto con el uso de fwmark de wg-quick para descartar todos los paquetes que no salen del túnel cifrados o no pasan por el túnel en sí. (Tenga en cuenta que esto sigue permitiendo el paso de la mayoría del tráfico DHCP, ya que la mayoría de los clientes DHCP utilizan sockets PF_PACKET, que omiten Netfilter). Cuando se usa IPv6, se podrían añadir líneas adicionales similares usando ip6tables(8).

O, tal vez sea deseable almacenar claves privadas en forma cifrada, como mediante el uso de pass(1):


PreUp = wg set %i private-key <(pass WireGuard/private-keys/%i)

Para uso en un servidor, el siguiente es un ejemplo más complejo que involucra múltiples peers:


[Interface]
Address = 10.192.122.1/24
Address = 10.10.0.1/16
SaveConfig = true
PrivateKey = yAnz5TF+lXXJte14tji3zlMNq+hd2rYUIgJBgB3fBmk=
ListenPort = 51820


[Peer]
PublicKey = xTIBA5rboUvnH4htodjb6e697QjLERt1NAB4mZqp8Dg=
AllowedIPs = 10.192.122.3/32, 10.192.124.1/24


[Peer]
PublicKey = TrMvSoP4jYQlY6RIzBgbssQqY3vxI2Pi+y71lOWWXX0=
AllowedIPs = 10.192.122.4/32, 192.168.0.0/16


[Peer]
PublicKey = gN65BkIKy1eCE9pP1wdc8ROUtkHLF2PfAqYdyYBz6EA=
AllowedIPs = 10.10.10.230/32

Observe las dos líneas `Address` en la parte superior, y que `SaveConfig' está establecido en `true', lo que indica que el archivo de configuración se guardará al apagar utilizando el estado actual de la interfaz.

Una combinación de los campos `Table', `PostUp' y `PreDown' puede utilizarse también para el enrutamiento de políticas. Por ejemplo, lo siguiente puede usarse para enviar tráfico SSH (puerto TCP 22) a través del túnel:

NAME

wg-quick - utility for quick bring up and tear down of WireGuard® interfaces

SYNOPSIS

wg-quick [-h|--help] [-V|--version] [up|down] interface...

wg-quick [-h|--help] [-V|--version] command interface [interface...]

DESCRIPTION

wg-quick is a small utility intended for creating and destroying WireGuard® interfaces. It reads configuration files to set up or tear down the necessary wg(8) interface, ip(8) rules, ip-route(8) routes, and resolvconf(8) nameservers.

CONFIGURATION

Configuration files are expected to be named interface.conf and reside in /etc/wireguard/. For example, if your interface is named wgnet0, the configuration file would be /etc/wireguard/wgnet0.conf.

The configuration file format is standard wg(8) configuration syntax, with the addition of the following directives:

PostUp
A command or list of commands to execute after the interface has been brought up. These commands are executed in a subshell.
PreDown
A command or list of commands to execute before the interface is torn down. These commands are executed in a subshell.
Table
A routing table number to use for the interface. This value is used by the PostUp and PreDown commands. By default, it is set to 2000.

It is important to note that PostUp and PreDown commands are run with root privileges. As such, they should be carefully written and reviewed.

Example configuration file:


[Interface]
Address = 10.192.122.1/24
PrivateKey = yAnz5TF+lXXJte14tji3zlMNq+hd2rYUIgJBgB3fBmk=
ListenPort = 51820
Table = 1234
PostUp = ip rule add ipproto tcp dport 22 table 1234
PreDown = ip rule delete ipproto tcp dport 22 table 1234


[Peer]
PublicKey = xTIBA5rboUvnH4htodjb6e697QjLERt1NAB4mZqp8Dg=
AllowedIPs = 0.0.0.0/0

EXAMPLES

These configuration files may be placed in any directory, putting the desired interface name in the filename:

# wg-quick up /path/to/wgnet0.conf

For convenience, if only an interface name is supplied, it automatically chooses a path in `/etc/wireguard/':

# wg-quick up wgnet0

This will load the configuration file `/etc/wireguard/wgnet0.conf'.

The strip command is useful for reloading configuration files without disrupting active sessions:

# wg syncconf wgnet0 <(wg-quick strip wgnet0)
