NOMBRE

wav2gig - Crear archivo GigaStudio (.gig) a partir de un conjunto de archivos WAV.

SINOPSIS

wav2gig [ OPCIONES ] ARCHIVO_GIG ARCHIVO_O_DIRECTORIO_WAV_1 [ ARCHIVO_O_DIRECTORIO_WAV_2 ... ]

DESCRIPCIÓN

Toma una lista de archivos wave (.wav) y/o directorios que contienen archivos wave como argumento(s) y crea un nuevo archivo GigaStudio / GigaSampler (.gig) para esas muestras.

El archivo GigaStudio (.gig) creado contendrá las muestras de entrada dadas. La meta-información de las muestras (en la medida de lo posible), como la nota raíz (también conocida como 'nota de unidad'), afinación fina, puntos de bucle, tipo de bucle y número de reproducciones del bucle, se extrae automáticamente de los archivos wave (.wav) de entrada y se aplica en consecuencia.

Además, esta herramienta crea exactamente un instrumento dentro del nuevo archivo GigaStudio (.gig) y trata de mapear automáticamente las muestras de forma significativa a ese instrumento. Dado que el formato wave (.wav) actualmente no admite mucha de la meta-información requerida para esta tarea en particular, esta herramienta intenta extraer la información requerida (faltante) del nombre del archivo de cada muestra individual para poder mapear las muestras en consecuencia. Consulte NOMBRES DE MUESTRAS a continuación para obtener detalles sobre el esquema de nombres asumido para los archivos de muestra de entrada y cómo anular ese esquema de nombres predeterminado proporcionando patrones de expresiones regulares personalizados.

OPCIONES

 ARCHIVO_GIG
Nombre del archivo GigaStudio / GigaSampler (.gig) que se creará
 ARCHIVO_O_DIRECTORIO_WAV_1
Nombre del archivo o directorio que contiene archivos wave (.wav)
 ARCHIVO_O_DIRECTORIO_WAV_2
Nombre del archivo o directorio que contiene archivos wave (.wav)
 -r
Recorre todos los subdirectorios de los directorios WAV de entrada proporcionados.
 -f
Sobrescribe el archivo GigaStudio (.gig) de salida en caso de que ya exista.
 -v
Imprime la versión y sale.
 --dry-run
Escanea los archivos de muestra de entrada (.wav), pero sale antes de crear cualquier archivo .gig.
 --verbose
Aumenta la cantidad de información que se muestra.
 --regex-name1 PATRÓN
Expresión regular para anular la parte NAME1 del esquema de nombres de archivos de muestra de entrada.

Por defecto es '([^-\]+) - [^-]+ - [^-]+ - [^-]+ - [^.]+'.

 --regex-name2 PATRÓN
Expresión regular para anular la parte NAME2 del esquema de nombres de archivos de muestra de entrada.

Por defecto es '[^-\]+ - ([^-]+) - [^-]+ - [^-]+ - [^.]+'.

 --regex-velocity-nr PATRÓN
Expresión regular para anular la parte VELOCITY_NR del esquema de nombres de archivos de muestra de entrada.

Por defecto es '[^-\]+ - [^-]+ - ([^-]+) - [^-]+ - [^.]+'.

 --regex-note-nr PATRÓN
Expresión regular para anular la parte NOTE_NR del esquema de nombres de archivos de muestra de entrada.

Por defecto es '[^-\]+ - [^-]+ - [^-]+ - ([^-]+) - [^.]+'.

 --regex-note-name PATRÓN
Expresión regular para anular la parte NOTE_NAME del esquema de nombres de archivos de muestra de entrada.

Por defecto es '[^-\]+ - [^-]+ - [^-]+ - [^-]+ - ([^.]+)'.

NOMBRES DE MUESTRAS

Por defecto, esta herramienta asume el siguiente esquema de nombres de archivos de muestra de entrada para mapear automáticamente las muestras a regiones del teclado, así como para mapearlas adecuadamente a divisiones de velocidad:

'NOMBRE1 - NOMBRE2 - NUM_VELOCIDAD - NUM_NOTA - NOMBRE_NOTA.wav'

Que se interpretan de la siguiente manera:

 NOMBRE1
Nombre principal de la muestra (por ejemplo, "Violín").

Esto no se interpreta para el mapeo de muestras, pero se utilizará para ensamblar el nombre final de la muestra dentro del archivo GigaStudio (.gig).

Puede usar --regex-name1 para anular esta parte del esquema de nombres.

 NOMBRE2
Nombre secundario de la muestra (por ejemplo, "Cresc").

Actualmente se ignora, pero podría usarse en el futuro.

Puede usar --regex-name2 para anular esta parte del esquema de nombres.

 NUM_VELOCIDAD
Número de velocidad MIDI de la muestra (por ejemplo, "18").

Esta información se utilizará para crear automáticamente divisiones de velocidad.

Puede usar --regex-velocity-nr para anular esta parte del esquema de nombres.

 NUM_NOTA
Número de nota MIDI de la muestra (por ejemplo, "021" para la nota a-1).

Esta información se utilizará para mapear automáticamente la muestra a una región del teclado. La nota raíz de la muestra (también conocida como "nota de unidad") se toma directamente del contenido del archivo .wav, sin embargo, si el contenido del archivo .wav no contiene información de nota raíz, entonces  NUM_NOTA se usa también como nota raíz.

Puede usar --regex-note-nr para anular esta parte del esquema de nombres.

 NOMBRE_NOTA
Nombre de la nota de la muestra (por ejemplo, "a-1").

Esto no se interpreta para el mapeo de muestras, pero se utilizará para ensamblar el nombre final de la muestra dentro del archivo GigaStudio (.gig).

Puede usar --regex-note-name para anular esta parte del esquema de nombres.

Esta herramienta utiliza la biblioteca de *expresiones regulares* proporcionada por C++ (introducida con la revisión del estándar C++11). Cada expresión regular personalizada (abreviada como 'RegEx' a partir de ahora a continuación) pasada a una de las opciones --regex-* debe contener *exactamente un* 'grupo de captura' de RegEx activo, que se denota en expresiones regulares por un par de paréntesis como:

(PATRÓN)

Por lo tanto, el 'grupo de captura' marca la porción en la cadena general del nombre de archivo que se extraerá para el componente respectivo del esquema de nombres de archivo. Si se necesitan grupos de RegEx adicionales para construir el patrón de RegEx general, entonces esos otros grupos deben definirse como 'grupos pasivos' denotados en patrones de RegEx por un signo de interrogación y dos puntos adicionales como:

(?:PATRÓN)

Tenga en cuenta que los escáneres de RegEx se comportan de forma 'codiciosa' por defecto, lo que significa que por defecto intentan hacer coincidir la cadena más larga posible según su patrón de RegEx definido. Si eso no es deseable, puede anular las partes requeridas de su patrón de RegEx para que se comporten de forma 'no codiciosa', de modo que esas partes coincidan con la cadena más corta posible en su lugar, o alternativamente considere usar el operador de 'alternancia' de RegEx, que se denota en expresiones regulares por un carácter de barra vertical como:

PATRÓN1|PATRÓN2|PATRÓN3

El operador de 'alternancia' de RegEx es a veces más intuitivo, ya que intenta hacer coincidir los patrones proporcionados estrictamente en orden de izquierda a derecha. Por lo tanto, primero intentaría hacer coincidir el primer patrón, y solo si no se pudo hacer coincidir el primer patrón (independientemente de la longitud de la cadena) intentaría hacer coincidir el segundo patrón, y así sucesivamente.
