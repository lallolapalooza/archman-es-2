wslay_event_context_client_init(3)

Paquete: libwslay

Licencias: MIT

WSLAY_EVENT_CONTEXT_CLIENT_INIT(3) wslay WSLAY_EVENT_CONTEXT_CLIENT_INIT(3)

NOMBRE

wslay_event_context_client_init - Inicializa un contexto de API basado en eventos

SINOPSIS

#include <wslay/wslay.h>

int wslay_event_context_server_init(wslay_event_context_ptr *ctx, const struct wslay_event_callbacks *callbacks, void *user_data)
int wslay_event_context_client_init(wslay_event_context_ptr *ctx, const struct wslay_event_callbacks *callbacks, void *user_data)
void wslay_event_context_free(wslay_event_context_ptr ctx)

DESCRIPCIÓN

La función wslay_event_context_server_init() inicializa un contexto de API :c:basado en eventos para uso de servidor WebSocket. La función wslay_event_context_client_init() inicializa un contexto de API :c:basado en eventos para uso de cliente WebSocket. Si devuelven :c:exitosamente, ctx apuntará a una estructura que contiene todos los recursos :c:necesarios para procesar transferencias de protocolo WebSocket.

callbacks es un puntero a struct wslay_event_callbacks, que se define de la siguiente manera:

struct wslay_event_callbacks {
    wslay_event_recv_callback                recv_callback;
    wslay_event_send_callback                send_callback;
    wslay_event_genmask_callback             genmask_callback;
    wslay_event_on_frame_recv_start_callback on_frame_recv_start_callback;
    wslay_event_on_frame_recv_chunk_callback on_frame_recv_chunk_callback;
    wslay_event_on_frame_recv_end_callback   on_frame_recv_end_callback;
    wslay_event_on_msg_recv_callback         on_msg_recv_callback;
};

recv_callback

typedef ssize_t (*wslay_event_recv_callback)(wslay_event_context_ptr ctx, uint8_t *buf, size_t len, int flags, void *user_data)

recv_callback es invocado por wslay_event_recv() cuando quiere recibir más datos del par. La implementación de esta función de callback debe leer datos como máximo len bytes del par y almacenarlos en buf, y devolver el número de bytes leídos. flags es siempre 0 en esta versión.

Si hay un error, devuelve -1 y establece el código de error WSLAY_ERR_CALLBACK_FAILURE usando wslay_event_set_error(). La API de eventos de Wslay en su conjunto asume E/S no bloqueante. Si la causa del error es EAGAIN o EWOULDBLOCK, establece WSLAY_ERR_WOULDBLOCK en su lugar. Esto es importante porque le dice a wslay_event_recv() que deje de recibir más datos y devuelva.

send_callback

typedef ssize_t (*wslay_event_send_callback)(wslay_event_context_ptr ctx, const uint8_t *data, size_t len, int flags, void *user_data)

send_callback es invocado por wslay_event_send() cuando quiere enviar más datos al par. La implementación de esta función de callback debe enviar datos como máximo len bytes al par y devolver el número de bytes enviados. flags es el OR a nivel de bits de cero o más de las siguientes banderas:

WSLAY_MSG_MORE
Hay más datos para enviar

Proporciona algunas pistas para ajustar el rendimiento y el comportamiento.

Si hay un error, devuelve -1 y establece el código de error WSLAY_ERR_CALLBACK_FAILURE usando wslay_event_set_error(). La API de eventos de Wslay en su conjunto asume E/S no bloqueante. Si la causa del error es EAGAIN o EWOULDBLOCK, establece WSLAY_ERR_WOULDBLOCK en su lugar. Esto es importante porque le dice a wslay_event_send() que deje de enviar datos y devuelva.

genmask_callback

typedef int (*wslay_event_genmask_callback)(wslay_event_context_ptr ctx, uint8_t *buf, size_t len, void *user_data)

genmask_callback es invocado por wslay_event_send() cuando quiere una nueva clave de máscara. Como se describe en RFC6455, solo el tráfico del cliente WebSocket está enmascarado, por lo que esta función de callback solo es necesaria si se inicializa una API basada en eventos para uso de cliente WebSocket. La implementación de esta función de callback debe llenar exactamente len bytes de datos en buf y devolver 0 con éxito. Si hay un error, devuelve -1 y establece el código de error WSLAY_ERR_CALLBACK_FAILURE usando wslay_event_set_error().

on_frame_recv_start_callback

typedef void (*wslay_event_on_frame_recv_start_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_frame_recv_start_arg *arg, void *user_data)

on_frame_recv_start_callback es invocado por wslay_event_recv() cuando se empieza a recibir un nuevo frame. Esta función de callback se invoca una sola vez por cada frame. struct wslay_event_on_frame_recv_start_arg se define de la siguiente manera:

struct wslay_event_on_frame_recv_start_arg {
    uint8_t  fin;
    uint8_t  rsv;
    uint8_t  opcode;
    uint64_t payload_length;
};

fin, rsv y opcode son el bit fin y los bits reservados y el opcode de un frame. payload_length es la longitud de la carga útil de un frame.

on_frame_recv_chunk_callback

typedef void (*wslay_event_on_frame_recv_chunk_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_frame_recv_chunk_arg *arg, void *user_data)

on_frame_recv_chunk_callback es invocado por wslay_event_recv() cuando se recibe un fragmento de la carga útil del frame. struct wslay_event_on_frame_recv_chunk_arg se define de la siguiente manera:

struct wslay_event_on_frame_recv_chunk_arg {
    const uint8_t *data;
    size_t         data_length;
};

data apunta a un fragmento de datos de carga útil. data_length es la longitud de un fragmento.

on_frame_recv_end_callback

typedef void (*wslay_event_on_frame_recv_end_callback)(wslay_event_context_ptr ctx, void *user_data)

on_frame_recv_end_callback es invocado por wslay_event_recv() cuando un frame se recibe completamente.

on_msg_recv_callback

typedef void (*wslay_event_on_msg_recv_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_msg_recv_arg *arg, void *user_data)

on_msg_recv_callback es invocado por wslay_event_recv() cuando un mensaje se recibe completamente. struct wslay_event_on_msg_recv_arg se define de la siguiente manera:

struct wslay_event_on_msg_recv_arg {
    uint8_t        rsv;
    uint8_t        opcode;
    const uint8_t *msg;
    size_t         msg_length;
    uint16_t       status_code;
};

El miembro rsv y el miembro opcode son

reservados los bits y el opcode del mensaje recibido respectivamente. El miembro rsv se construye de la siguiente manera:

rsv = (RSV1 << 2) | (RSV2 << 1) | RSV3

El miembro msg apunta al mensaje del mensaje recibido. El miembro msg_length es la longitud del mensaje. Si un mensaje es un marco de control de cierre, en otras palabras, opcode == WSLAY_CONNECTION_CLOSE, status_code se establece en el código de estado en el marco de control de cierre. Si no se incluye ningún código de estado en el marco de control de cierre, status_code se establece en 0.

user_data es un puntero arbitrario, que se pasa directamente a cada función de devolución de llamada como argumento user_data.

Cuando el contexto de la API basado en eventos inicializado ctx ya no se utiliza, use wslay_event_context_free() para liberar cualquier recurso asignado para ctx.

VALOR DE RETORNO

wslay_event_context_server_init() y wslay_event_context_client_init() devuelven 0 si tiene éxito, o uno de los siguientes códigos de error negativos:

WSLAY_ERR_NOMEM
Fuera de memoria.

VER TAMBIÉN

wslay_event_send(), wslay_event_recv(), wslay_event_set_error()
