warnings(3perl) Guía de Referencia del Programador de Perl warnings(3perl)

NOMBRE

warnings - Pragma de Perl para controlar advertencias opcionales

SINOPSIS

use warnings;
no warnings;
# Las advertencias estándar se habilitan con use v5.35 o superior
use v5.35;
use warnings "all";
no warnings "uninitialized";
# o equivalente a las dos últimas ...
use warnings qw(all -uninitialized);
use warnings::register;
if (warnings::enabled()) {
    warnings::warn("alguna advertencia");
}
if (warnings::enabled("void")) {
    warnings::warn("void", "alguna advertencia");
}
if (warnings::enabled($objeto)) {
    warnings::warn($objeto, "alguna advertencia");
}
warnings::warnif("alguna advertencia");
warnings::warnif("void", "alguna advertencia");
warnings::warnif($objeto, "alguna advertencia");

DESCRIPCIÓN

El pragma "warnings" proporciona control sobre qué advertencias están habilitadas en qué partes de un programa Perl. Es una alternativa más flexible tanto para el indicador de línea de comandos -w como para la variable Perl equivalente, $^W.

Este pragma funciona igual que el pragma "strict". Esto significa que el alcance del pragma de advertencia se limita al bloque que lo contiene. También significa que la configuración del pragma no se filtrará entre archivos (a través de "use", "require" o "do"). Esto permite a los autores definir independientemente el grado de verificación de advertencias que se aplicará a su módulo.

Por defecto, las advertencias opcionales están deshabilitadas, por lo que cualquier código heredado que no intente controlar las advertencias funcionará sin cambios.

Todas las advertencias se habilitan en un bloque mediante cualquiera de las siguientes opciones:

use warnings;
use warnings 'all';

De manera similar, todas las advertencias se deshabilitan en un bloque mediante cualquiera de las siguientes opciones:

no warnings;
no warnings 'all';

Por ejemplo, considere el siguiente código:

use warnings;
my @x;
{
    no warnings;
    my $y = @x[0];
}
my $z = @x[0];

El código en el bloque que lo contiene tiene las advertencias habilitadas, pero el bloque interior las tiene deshabilitadas. En este caso, eso significa que la asignación al escalar $z activará la advertencia "Scalar value @x[0] better written as $x[0]", pero la asignación al escalar $y no.

Todas las advertencias se habilitan automáticamente dentro del ámbito de una declaración "use v5.35" (o superior).

Advertencias Predeterminadas y Advertencias Opcionales

Antes de la introducción de las advertencias léxicas, Perl tenía dos clases de advertencias: obligatorias y opcionales.

Como su nombre indica, si tu código activaba una advertencia obligatoria, obtendrías una advertencia sin importar si la querías o no. Por ejemplo, el siguiente código siempre produciría una advertencia de "isn't numeric" sobre el "2:".

my $x = "2:" + 3;

Con la introducción de las advertencias léxicas, las advertencias obligatorias se convierten ahora en advertencias *predeterminadas*. La diferencia es que, aunque las advertencias previamente obligatorias todavía están habilitadas por defecto, pueden ser habilitadas o deshabilitadas posteriormente con el pragma de advertencia léxica. Por ejemplo, en el siguiente código, solo se informará una advertencia de "isn't numeric" para la variable $x.

my $x = "2:" + 3;
no warnings;
my $y = "2:" + 3;

Tenga en cuenta que ni el indicador -w ni $^W se pueden usar para deshabilitar/habilitar advertencias predeterminadas. Todavía son obligatorias en este caso.

"Advertencias Negativas"

Como conveniencia, puede (a partir de Perl 5.34) pasar argumentos al método import() tanto positiva como negativamente. Las advertencias negativas son aquellas con un signo "-" antepuesto a sus nombres; las advertencias positivas son cualquier otra cosa. Esto le permite activar algunas advertencias y desactivar otras en un solo comando. Entonces, asumiendo que ya ha activado un montón de advertencias pero quiere ajustarlas un poco en algún bloque, puede hacer esto:

{
    use warnings qw(uninitialized -redefine);
    ...
}

que es equivalente a:

{
    use warnings qw(uninitialized);
    no warnings qw(redefine);
    ...
}

La lista de argumentos se procesa en el orden en que la especifica. Por lo tanto, por ejemplo, si no desea que se le advierta sobre el uso de características experimentales, excepto por "somefeature" que realmente le disgusta, puede decir esto:

use warnings qw(all -experimental experimental::somefeature);

que es equivalente a:

use warnings 'all';
no warnings  'experimental';
use warnings 'experimental::somefeature';

A medida que las características experimentales se convierten en características regulares de Perl, las advertencias correspondientes ya no se imprimen. Tampoco se siguen listando en la "Jerarquía de Categorías" a continuación.

Todavía es posible solicitar la activación o desactivación de estas advertencias, pero hacerlo no tiene ningún efecto.

¿Qué sale mal con -w y $^W

Aunque muy útil, el gran problema de usar -w en la línea de comandos para habilitar advertencias es que es todo o nada. Tome el escenario típico cuando está escribiendo un programa Perl. Partes del código las escribirá usted mismo, pero es muy probable que utilice módulos Perl preescritos. Si utiliza el indicador -w en este caso, terminará habilitando advertencias en fragmentos de código que no ha escrito.

De manera similar, usar $^W para deshabilitar o habilitar bloques de código es fundamentalmente defectuoso. Para empezar, diga que quiere deshabilitar las advertencias en un bloque de código. Puede esperar que esto sea suficiente para lograr el objetivo:

{
    local ($^W) = 0;
    my $x =+ 2;
    my $y; chop $y;
}

Cuando este código se ejecuta con el indicador -w, se producirá una advertencia para la línea de $x: "Reversed += operator".

El problema es que Perl tiene advertencias tanto en tiempo de compilación como en tiempo de ejecución. Para deshabilitar las advertencias en tiempo de compilación, necesita reescribir el código de esta manera:

{
    BEGIN { $^W = 0 }
    my $x =+ 2;
    my $y; chop $y;
}

Y tenga en cuenta que, a diferencia del primer ejemplo, esto establecerá permanentemente $^W ya que no puede ejecutarse en tiempo de compilación y ser localizado a un bloque en tiempo de ejecución.

El otro gran problema con $^W es la forma en que puede cambiar inadvertidamente la configuración de advertencia en lugares inesperados de su código. Por ejemplo, cuando se ejecuta el código a continuación (sin el indicador -w), la segunda llamada a "doit" activará una advertencia de "Use of uninitialized value", mientras que la primera no.

sub doit
{
    my $y; chop $y;
}
doit();
{
    local ($^W) = 1;
    doit()
}

Este es un efecto secundario de que $^W tenga un ámbito dinámico.

Las advertencias léxicas superan estas limitaciones al permitir un control más preciso sobre dónde se pueden activar o no las advertencias.

Control de Advertencias desde la Línea de Comandos

Hay tres indicadores de línea de comandos que se pueden utilizar para controlar cuándo se producen (o no) las advertencias:

-w
Este es el indicador existente. Si el pragma de advertencias léxicas no se utiliza en ninguno de sus códigos, o en ninguno de los módulos que utiliza, este indicador habilitará las advertencias en todas partes. Consulte "Compatibilidad con versiones anteriores" para obtener detalles sobre cómo interactúa este indicador con las advertencias léxicas.
-W
Si se utiliza el indicador -W en la línea de comandos, habilitará todas las advertencias en todo el programa, independientemente de si las advertencias se deshabilitaron localmente usando "no warnings" o "$^W =0". Command Line Flags

-w
Habilita advertencias. Esto es equivalente a establecer la variable global $^W a un valor verdadero. Piensa en ello como el equivalente de Perl del comando "lint".
-W
Habilita todas las advertencias. Esto es el equivalente a establecer $^W a 1, y al mismo tiempo habilita las advertencias lexicales por defecto.
-X
Hace exactamente lo contrario de la bandera -W, es decir, deshabilita todas las advertencias.

Compatibilidad con Versiones Anteriores

Si estás acostumbrado a trabajar con una versión de Perl anterior a la introducción de advertencias de alcance léxico, o tienes código que utiliza tanto advertencias léxicas como $^W, esta sección describirá cómo interactúan.

Cómo interactúan las advertencias léxicas con -w/$^W:

1.
Si no se utiliza ninguna de las tres banderas de línea de comandos (-w, -W o -X) que controlan las advertencias, y tampoco se utiliza $^W ni el pragma "warnings", entonces las advertencias por defecto se habilitarán y las advertencias opcionales se deshabilitarán. Esto significa que el código heredado que no intenta controlar las advertencias funcionará sin cambios.
2.
La bandera -w simplemente establece la variable global $^W como en 5.005. Esto significa que cualquier código heredado que actualmente dependa de la manipulación de $^W para controlar el comportamiento de las advertencias seguirá funcionando tal cual.
3.
Aparte de ser ahora un booleano, la variable $^W funciona exactamente de la misma manera global horrible y descontrolada, excepto que no puede deshabilitar/habilitar las advertencias por defecto.
4.
Si un trozo de código está bajo el control del pragma "warnings", tanto la variable $^W como la bandera -w serán ignoradas para el ámbito de la advertencia léxica.
5.
La única forma de anular una configuración de advertencias léxicas es con las banderas de línea de comandos -W o -X.

El efecto combinado de 3 y 4 es que permitirá que el código que utiliza el pragma "warnings" controle el comportamiento de las advertencias del código tipo $^W (usando un "local $^W=0") si realmente lo desea, pero no a la inversa.

Al igual que el pragma "strict", cualquiera de estas categorías se puede combinar

no warnings qw(io syntax untie);

También, al igual que el pragma "strict", si hay más de una instancia del pragma "warnings" en un ámbito dado, el efecto acumulativo es aditivo.

use warnings qw(void); # solo advertencias "void" habilitadas
...
use warnings qw(io);   # solo advertencias "void" y "io" habilitadas
...
no warnings qw(void);  # solo advertencias "io" habilitadas

Para determinar a qué categoría se ha asignado una advertencia específica, consulta perldiag.

Advertencias Fatales

La presencia de la palabra "FATAL" en la lista de categorías convertirá las advertencias en esas categorías en errores fatales en ese ámbito léxico.

NOTA: Las advertencias FATAL deben usarse con cuidado, particularmente "FATAL => 'all'".

Las bibliotecas que utilizan warnings::warn para categorías de advertencia personalizadas generalmente no esperan que warnings::warn sea fatal y pueden terminar en un estado inesperado como resultado. Para módulos XS que emiten advertencias categorizadas, tales excepciones imprevistas también podrían exponer errores de fuga de memoria.

Además, el propio intérprete de Perl ha tenido errores graves relacionados con advertencias fatalizadas. Para un resumen de problemas resueltos y no resueltos a enero de 2015, consulte esta publicación de perl5-porters http://www.nntp.perl.org/group/perl.perl5.porters/2015/01/msg225235.html.

Si bien algunos desarrolladores encuentran que fatalizar algunas advertencias es una técnica útil de programación defensiva, usar "FATAL => 'all'" para fatalizar todas las categorías de advertencia posibles, incluidas las personalizadas, es particularmente arriesgado. Por lo tanto, se desaconseja el uso de "FATAL => 'all'".

El módulo strictures en CPAN ofrece un ejemplo de un subconjunto de advertencias que los autores del módulo creen que es relativamente seguro fatalizar.

NOTA: Los usuarios de advertencias FATAL, especialmente aquellos que usan "FATAL => 'all'", deben ser plenamente conscientes de que están arriesgando la portabilidad futura de sus programas al hacerlo. Perl no se compromete en absoluto a no introducir nuevas advertencias o categorías de advertencia en el futuro; de hecho, nos reservamos explícitamente el derecho de hacerlo. El código que puede no advertir ahora puede advertir en una versión futura de Perl si el equipo de desarrollo de Perl5 lo considera en el mejor interés de la comunidad. Si el código que usa advertencias FATAL se rompe debido a la introducción de una nueva advertencia, NO lo consideraremos un cambio incompatible. Los usuarios de advertencias FATAL deben tener especial cuidado durante las actualizaciones para verificar si su código activa alguna advertencia nueva y deben prestar especial atención a la letra pequeña de la documentación de las funciones que utilizan para asegurarse de que no explotan funciones que se documentan como riesgosas, obsoletas o no especificadas, o donde la documentación dice "así que no hagas eso", o cualquier cosa con el mismo sentido y espíritu. El uso de tales funciones en combinación con advertencias FATAL es ENTIERAMENTE BAJO EL RIESGO DEL USUARIO.

La siguiente documentación describe cómo usar advertencias FATAL, pero los programadores de Perl 5 recomiendan encarecidamente que comprendan los riesgos antes de hacerlo, especialmente para el código de biblioteca destinado a ser utilizado por otros, ya que no hay forma de que los usuarios descendentes cambien la elección de categorías fatales.

En el siguiente código, el uso de "time", "length" y "join" puede producir una advertencia de "Uso inútil de xxx en contexto void".

use warnings;
time;
{
    use warnings FATAL => qw(void);
    length "abc";
}
join "", 1,2,3;
print "done\n";

Al ejecutarlo, produce esta salida

Useless use of time in void context at fatal line 3.
Useless use of length in void context at fatal line 7.

ADVERTENCIAS FATALES

Algunos desarrolladores de módulos pueden querer que sus advertencias se conviertan en un error fatal, por lo que el programa termina inmediatamente cuando se encuentra la advertencia.

Para desactivar explícitamente una advertencia "FATAL" que acabas de desactivar, simplemente deshabilita la advertencia con la que está asociada. Por lo tanto, por ejemplo, para deshabilitar la advertencia "void" en el ejemplo anterior, cualquiera de las siguientes opciones hará el truco:

no warnings qw(void);
no warnings FATAL => qw(void);

Si deseas degradar una advertencia que ha sido elevada a un error fatal a una advertencia normal, puedes usar la palabra clave "NONFATAL". Por ejemplo, el siguiente código promocionará todas las advertencias a errores fatales, excepto las de la categoría "syntax".

use warnings FATAL => 'all', NONFATAL => 'syntax';

A partir de Perl 5.20, en lugar de "use warnings FATAL => 'all';" puedes usar:

use v5.20;       # Se requiere Perl 5.20 o superior para lo siguiente
use warnings 'FATAL';  # forma corta de "use warnings FATAL => 'all';"

Sin embargo, aún debes seguir la guía anterior en esta sección en contra del uso de "use warnings FATAL => 'all';".

Si deseas que tu programa sea compatible con versiones de Perl anteriores a la 5.20, debes usar "use warnings FATAL => 'all';" en su lugar. (En versiones anteriores de Perl, el comportamiento de las sentencias "use warnings 'FATAL';", "use warnings 'NONFATAL';" y "no warnings 'FATAL';" no estaba especificado; no se comportaban como si incluyeran la parte "=> 'all'". A partir de la 5.20, sí lo hacen).

Informar Advertencias de un Módulo

El pragmatismo "warnings" proporciona una serie de funciones que son útiles para los autores de módulos. Estas se utilizan cuando se desea informar una advertencia específica del módulo a un módulo que llama, el cual ha habilitado las advertencias a través del pragmatismo "warnings".

Considera el módulo "MyMod::Abc" a continuación.

package MyMod::Abc;
use warnings::register;
sub open {
    my $path = shift;
    if ($path !~ m#^/#) {
        warnings::warn("changing relative path to /var/abc")
            if warnings::enabled();
        $path = "/var/abc/$path";
    }
}
1;

La llamada a "warnings::register" creará una nueva categoría de advertencias llamada "MyMod::Abc", es decir, el nuevo nombre de categoría coincide con el nombre del paquete actual. La función "open" en el módulo mostrará un mensaje de advertencia si se le da una ruta relativa como parámetro. Esta advertencia solo se mostrará si el código que utiliza "MyMod::Abc" las ha habilitado con el pragmatismo "warnings" como se muestra a continuación; ten en cuenta que un simple "use warnings" habilita incluso las advertencias que aún no se han registrado.

use warnings;
use MyMod::Abc;
...
abc::open("../fred.txt");

La advertencia específica se puede habilitar o deshabilitar, pero solo después de que se haya importado el módulo:

# no warnings 'MyMod::Abc';     # error, categoría desconocida antes de
                                # cargar el módulo
use MyMod::Abc;
no warnings 'MyMod::Abc';       # ok después de cargar el módulo
...
abc::open("../fred.txt");

También es posible probar si las categorías de advertencias predefinidas están configuradas en el módulo que llama con la función "warnings::enabled". Considera este fragmento de código:

package MyMod::Abc;
sub open2 {
    if (warnings::enabled("deprecated")) {
        warnings::warn("deprecated",
                       "open2 is deprecated, use open instead");
    }
    open(@_);
}
sub open
...
1;

La función "open2" ha sido obsoleta, por lo que se ha incluido código para mostrar un mensaje de advertencia cada vez que el módulo que llama tenga habilitada (al menos) la categoría de advertencias "deprecated". Algo como esto, por ejemplo.

use warnings 'deprecated';
use MyMod::Abc;
...
MyMod::Abc::open2($filename);

Se debe usar la función "warnings::warn" o "warnings::warnif" para mostrar realmente el mensaje de advertencia. Esto se debe a que pueden utilizar la característica que permite que las advertencias se conviertan en errores fatales. Así que en este caso

use MyMod::Abc;
use warnings FATAL => 'MyMod::Abc';
...
MyMod::Abc::open('../fred.txt');

la función "warnings::warnif" detectará esto y morirá después de mostrar el mensaje de advertencia.

Las tres funciones de advertencia, "warnings::warn", "warnings::warnif" y "warnings::enabled", pueden tomar opcionalmente una referencia a un objeto en lugar de un nombre de categoría. En este caso, las funciones utilizarán el nombre de la clase del objeto como la categoría de advertencia.

Considera este ejemplo:

package Original;
no warnings;
use warnings::register;
sub new
{
    my $class = shift;
    bless [], $class;
}
sub check
{
    my $self = shift;
    my $value = shift;
    if ($value % 2 && warnings::enabled($self))
      { warnings::warn($self, "Odd numbers are unsafe") }
}
sub doit
{
    my $self = shift;
    my $value = shift;
    $self->check($value);
    # ...
}
1;
package Derived;
use warnings::register;
use Original;
our @ISA = qw( Original );
sub new
{
    my $class = shift;
    bless [], $class;
}
1;

El siguiente código utiliza ambos módulos, pero solo habilita las advertencias de "Derived".

use Original;
use Derived;
use warnings 'Derived';
my $x = Original->new();
$x->doit(1);
my $y = Derived->new();
$x->doit(1);

Cuando se ejecuta este código, solo el objeto "Derived", $y, generará una advertencia.

Odd numbers are unsafe at main.pl line 7

Observa también que la advertencia se informa en la línea donde se usa el objeto por primera vez.

Al registrar nuevas categorías de advertencia, puedes proporcionar más nombres a warnings::register de la siguiente manera:

package MyModule;
use warnings::register qw(format precision);
...
warnings::warnif('MyModule::format', '...');

FUNCIONES

Nota: Las funciones con nombres que terminan en "_at_level" se agregaron en Perl 5.28.

use warnings::register
Crea una nueva categoría de advertencias con el mismo nombre que el paquete donde se utiliza la llamada al pragmatismo.
warnings::enabled()
Usa la categoría de advertencias con el mismo nombre que el paquete actual.

Devuelve TRUE si esa categoría de advertencias está habilitada en el módulo que llama. De lo contrario, devuelve FALSE.

warnings::enabled($category)
Devuelve TRUE si la categoría de advertencias, $category, está habilitada en el módulo que llama. De lo contrario, devuelve FALSE.
warnings::enabled($object)
Usa el nombre de la clase de la referencia del objeto, $object, como categoría de advertencias.

Devuelve TRUE si esa categoría de advertencias está habilitada en el primer ámbito donde se utiliza el objeto. De lo contrario, devuelve FALSE.

warnings::enabled_at_level($category, $level)
Similar a "warnings::enabled", pero $level especifica el marco de llamada exacto, siendo 0 el llamador inmediato.
warnings::fatal_enabled()
Devuelve TRUE si la categoría de advertencias con el mismo nombre que el paquete actual ha sido configurada como FATAL en el módulo que llama. De lo contrario, devuelve FALSE.
warnings::fatal_enabled($category)
Devuelve TRUE si la categoría de advertencias $category ha sido configurada como FATAL en el módulo que llama. De lo contrario, devuelve FALSE.
warnings::fatal_enabled($object)
Usa el nombre de la clase de la referencia del objeto, $object, como categoría de advertencias.

Devuelve TRUE si esa categoría de advertencias ha sido configurada como FATAL en el primer ámbito donde se utiliza el objeto. De lo contrario, devuelve FALSE.

warnings::fatal_enabled_at_level($category, $level)
Similar a "warnings::fatal_enabled", pero $level especifica el marco de llamada exacto, siendo 0 el llamador inmediato.
warnings::warn($message)
Imprime $message en STDERR.

Usa la categoría de advertencias con el mismo nombre que el paquete actual.

Si esa categoría de advertencias ha sido configurada como "FATAL" en el módulo que llama, entonces muere. De lo contrario, retorna.

warnings::warn($category, $message)
Imprime $message en STDERR.

Si la categoría de advertencias, $category, ha sido configurada como "FATAL" en el módulo que llama, entonces muere. De lo contrario, retorna.

warnings::warn($object, $message)
Imprime $message en STDERR.

Usa el nombre de la clase de la referencia del objeto, $object, como categoría de advertencias.

Si esa categoría de advertencias ha sido configurada como "FATAL" en el ámbito donde se utiliza el objeto por primera vez, entonces muere. De lo contrario, retorna.
