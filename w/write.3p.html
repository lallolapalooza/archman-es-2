WRITE(3P) Manual del programador de POSIX WRITE(3P)

PROLOGO

Esta página del manual forma parte del Manual del programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

pwrite, write — escribir en un archivo

SINOPSIS

#include <unistd.h>
ssize_t pwrite(int fildes, const void *buf, size_t nbyte,
    off_t offset);
ssize_t write(int fildes, const void *buf, size_t nbyte);

DESCRIPCION

La función write() intentará escribir nbyte bytes del búfer apuntado por buf en el archivo asociado con el descriptor de archivo abierto, fildes.

Antes de que se tome cualquiera de las acciones descritas a continuación, y si nbyte es cero y el archivo es un archivo regular, la función write() puede detectar y devolver errores como se describe a continuación. En ausencia de errores, o si no se realiza la detección de errores, la función write() devolverá cero y no tendrá otros resultados. Si nbyte es cero y el archivo no es un archivo regular, los resultados no están especificados.

En un archivo regular u otro archivo capaz de ser buscado, la escritura real de datos procederá desde la posición en el archivo indicada por el desplazamiento de archivo asociado con fildes. Antes de un retorno exitoso de write(), el desplazamiento de archivo se incrementará en el número de bytes escritos realmente. En un archivo regular, si la posición del último byte escrito es mayor o igual que la longitud del archivo, la longitud del archivo se establecerá en esta posición más uno.

En un archivo no capaz de ser buscado, la escritura siempre tendrá lugar comenzando en la posición actual. El valor de un desplazamiento de archivo asociado con dicho dispositivo no está definido.

Si la bandera O_APPEND del estado del archivo está establecida, el desplazamiento del archivo se establecerá al final del archivo antes de cada escritura y ninguna operación de modificación de archivo intermedia ocurrirá entre el cambio del desplazamiento del archivo y la operación de escritura.

Si write() solicita escribir más bytes de los que caben (por ejemplo, el límite del tamaño del archivo del proceso o el final físico de un medio), solo se escribirán tantos bytes como quepan. Por ejemplo, suponga que quedan 20 bytes libres en un archivo antes de alcanzar un límite. Una escritura de 512 bytes devolverá 20. La siguiente escritura de un número de bytes no cero daría un retorno de fallo (excepto como se indica a continuación).

Si la solicitud hiciera que el tamaño del archivo excediera el límite suave del tamaño del archivo para el proceso y no hay espacio para escribir ningún byte, la solicitud fallará y la implementación generará la señal SIGXFSZ para el hilo.

Si write() es interrumpida por una señal antes de que escriba algún dato, devolverá -1 con errno establecido a [EINTR].

Si write() es interrumpida por una señal después de haber escrito correctamente algunos datos, devolverá el número de bytes escritos.

Si el valor de nbyte es mayor que {SSIZE_MAX}, el resultado no está definido por la implementación.

Después de que una write() a un archivo regular haya retornado exitosamente:

*
Cualquier read() exitoso desde cada posición de byte en el archivo que fue modificado por esa escritura devolverá los datos especificados por la write() para esa posición hasta que dichas posiciones de byte sean modificadas nuevamente.
*
Cualquier write() exitosa posterior a la misma posición de byte en el archivo sobrescribirá esos datos del archivo.

Las solicitudes de escritura a una tubería (pipe) o FIFO se manejarán de la misma manera que un archivo regular con las siguientes excepciones:

*
No hay desplazamiento de archivo asociado con una tubería, por lo tanto, cada solicitud de escritura se agregará al final de la tubería.
*
Las solicitudes de escritura de {PIPE_BUF} bytes o menos no se intercalarán con datos de otros procesos que realicen escrituras en la misma tubería. Las escrituras de más de {PIPE_BUF} bytes pueden tener datos intercalados, en límites arbitrarios, con escrituras de otros procesos, independientemente de si la bandera O_NONBLOCK del estado del archivo está establecida o no.
*
Si la bandera O_NONBLOCK está deshabilitada, una solicitud de escritura puede hacer que el hilo se bloquee, pero en una finalización normal devolverá nbyte.
*
Si la bandera O_NONBLOCK está establecida, las solicitudes de write() se manejarán de manera diferente, de las siguientes maneras:
--
La función write() no bloqueará el hilo.
--
Una solicitud de escritura de {PIPE_BUF} bytes o menos tendrá el siguiente efecto: si hay espacio suficiente disponible en la tubería, write() transferirá todos los datos y devolverá el número de bytes solicitados. De lo contrario, write() no transferirá ningún dato y devolverá -1 con errno establecido a [EAGAIN].
--
Una solicitud de escritura de más de {PIPE_BUF} bytes provocará una de las siguientes:
--
Cuando se pueda escribir al menos un byte, transferirá lo que pueda y devolverá el número de bytes escritos. Cuando todos los datos escritos previamente en la tubería se lean, transferirá al menos {PIPE_BUF} bytes.
--
Cuando no se puedan escribir datos, no transferirá ningún dato y devolverá -1 con errno establecido a [EAGAIN].

Al intentar escribir en un descriptor de archivo (que no sea una tubería o FIFO) que soporte escrituras no bloqueantes y no pueda aceptar los datos inmediatamente:

*
Si la bandera O_NONBLOCK está deshabilitada, write() bloqueará el hilo de llamada hasta que los datos puedan ser aceptados.
*
Si la bandera O_NONBLOCK está establecida, write() no bloqueará el hilo. Si se pueden escribir algunos datos sin bloquear el hilo, write() escribirá lo que pueda y devolverá el número de bytes escritos. De lo contrario, devolverá -1 y establecerá errno a [EAGAIN].

Al completarse con éxito, cuando nbyte sea mayor que 0, write() marcará para actualización las marcas de tiempo de la última modificación de datos y el último cambio de estado del archivo, y si el archivo es un archivo regular, los bits S_ISUID y S_ISGID del modo de archivo pueden ser borrados.

Para archivos regulares, no se transferirán datos más allá del desplazamiento máximo establecido en la descripción del archivo abierto asociada con fildes.

Si fildes se refiere a un socket, write() será equivalente a send() sin banderas establecidas.

Si se ha establecido la bit O_DSYNC, las operaciones de E/S de escritura en el descriptor de archivo se completarán según lo definido por la finalización de la integridad de los datos de E/S sincronizada.

Si se ha establecido la bit O_SYNC, las operaciones de E/S de escritura en el descriptor de archivo se completarán según lo definido por la finalización de la integridad del archivo de E/S sincronizada.

Si fildes se refiere a un objeto de memoria compartida, el resultado de la función write() no está especificado.

Si fildes se refiere a un objeto de memoria tipificada, el resultado de la función write() no está especificado.

Si fildes se refiere a un STREAM, la operación de write() se determinará por los valores del rango mínimo y máximo de nbyte (tamaño del paquete) aceptados por el STREAM. Estos valores se determinan por el módulo STREAM superior. Si nbyte cae dentro del rango del tamaño del paquete, se escribirán nbyte bytes. Si nbyte no cae dentro del rango y el valor del tamaño mínimo del paquete es 0, write() dividirá el búfer en segmentos de tamaño máximo de paquete antes de enviar los datos río abajo (el último segmento puede contener menos que el tamaño máximo del paquete). Si nbyte no cae dentro del rango y el valor mínimo es distinto de cero, write() fallará con errno establecido a [ERANGE]. Escribir un búfer de longitud cero (nbyte es 0) a un dispositivo STREAMS envía 0 bytes devolviendo 0. Sin embargo, escribir un búfer de longitud cero a una tubería o FIFO basada en STREAMS no envía ningún mensaje y se devuelve 0. El proceso puede emitir ioctl() I_SWROPT para habilitar el envío de mensajes de longitud cero a través de la tubería o FIFO.

Al escribir en un STREAM, se crean mensajes de datos con una banda de prioridad de 0. Al escribir en un STREAM que no es una tubería o FIFO:

*
Si O_NONBLOCK está deshabilitado y el STREAM no puede aceptar datos (la cola de escritura del STREAM está llena debido a condiciones de control de flujo internas), write() bloqueará hasta que se puedan aceptar datos.
*
Si O_NONBLOCK está establecido y el STREAM no puede aceptar datos, write

DESCRIPTION

The write() function shall attempt to write nbyte bytes from the buffer pointed to by buf to the file described by fildes. The operation can be interrupted by signals.

The number of bytes actually written can be less than that specified by nbyte. For example, this can happen if the implementation imposes a limit on the number of bytes that can be written at a call, or if the file is a pipe or FIFO and the read end has been closed, or if the number of available bytes in a STREAMS file is less than that requested.

If the O_APPEND flag is set for the file description associated with fildes, the file offset shall be set to the end of the file prior to each write operation. The file offset is updated by the number of bytes actually written.

If the O_DIRECT flag is set for the file description associated with fildes, the behavior of write() is file type and implementation-dependent. If the underlying filesystem or device does not support O_DIRECT, or if the requests do not meet the alignment requirements of the underlying filesystem or device, an error may be returned.

If the O_SYNC flag is set for the file description associated with fildes, the write operation need not complete synchronously. Although the write operation might return before any data has been committed to the physical device, subsequent calls to fsync() or fdatasync() for the same file descriptor shall block until all outstanding write I/O operations at the time of the write() call have completed.

*
If O_NONBLOCK is set and the call would block, write() shall return -1 and set errno to [EAGAIN].
*
If O_NONBLOCK is set and part of the buffer has been written while a condition in which the STREAM cannot accept additional data occurs, write() shall terminate and return the number of bytes written.

In addition, write() shall fail if the STREAM head has processed an asynchronous error before the call. In this case, the value of errno does not reflect the result of write(), but reflects the prior error.

The pwrite() function shall be equivalent to write(), except that it writes into a given position and does not change the file offset (regardless of whether O_APPEND is set). The first three arguments to pwrite() are the same as write() with the addition of a fourth argument offset for the desired position inside the file. An attempt to perform a pwrite() on a file that is incapable of seeking shall result in an error.

RETURN VALUE

Upon successful completion, these functions shall return the number of bytes actually written to the file associated with fildes. This number shall never be greater than nbyte. Otherwise, -1 shall be returned and errno set to indicate the error.

ERRORS

These functions shall fail if:

EAGAIN
The file is neither a pipe, nor a FIFO, nor a socket, the O_NONBLOCK flag is set for the file descriptor, and the thread would be delayed in the write() operation.
EBADF
The fildes argument is not a valid file descriptor open for writing.
EFBIG
An attempt was made to write a file that exceeds the implementation-defined maximum file size or the file size limit of the process, and there was no room for any bytes to be written.
EFBIG
The file is a regular file, nbyte is greater than 0, and the starting position is greater than or equal to the offset maximum established in the open file description associated with fildes.
EINTR
The write operation was terminated due to the receipt of a signal, and no data was transferred.
EIO
The process is a member of a background process group attempting to write to its controlling terminal, TOSTOP is set, the calling thread is not blocking SIGTTOU, the process is not ignoring SIGTTOU, and the process group of the process is orphaned. This error may also be returned under implementation-defined conditions.
ENOSPC
There was no free space remaining on the device containing the file.
ERANGE
The transfer request size was outside the range supported by the STREAMS file associated with fildes.

The pwrite() function shall fail if:

EINVAL
The file is a regular file or block special file, and the offset argument is negative. The file offset shall remain unchanged.
ESPIPE
The file is incapable of seeking.

The write() function shall fail if:

EAGAIN
The file is a pipe or FIFO, the O_NONBLOCK flag is set for the file descriptor, and the thread would be delayed in the write operation.
EAGAIN or EWOULDBLOCK

The file is a socket, the O_NONBLOCK flag is set for the file descriptor, and the thread would be delayed in the write operation.
ECONNRESET
A write was attempted on a socket that is not connected.
EPIPE
An attempt is made to write to a pipe or FIFO that is not open for reading by any process, or that only has one end open. A SIGPIPE signal shall also be sent to the thread.
EPIPE
A write was attempted on a socket that is shut down for writing, or is no longer connected. In the latter case, if the socket is of type SOCK_STREAM, a SIGPIPE signal shall also be sent to the thread.

These functions may fail if:

EINVAL
The STREAM or multiplexer referenced by fildes is linked (directly or indirectly) downstream from a multiplexer.
EIO
A physical I/O error has occurred.
ENOBUFS
Insufficient resources were available in the system to perform the operation.
ENXIO
A request was made of a nonexistent device, or the request was outside the capabilities of the device.
ENXIO
A hangup occurred on the STREAM being written to.

A write to a STREAMS file may fail if an error message has been received at the STREAM head. In this case, errno is set to the value included in the error message.

The write() function may fail if:

EACCES
A write was attempted on a socket and the calling process does not have appropriate privileges.
ENETDOWN
A write was attempted on a socket and the local network interface used to reach the destination is down.
ENETUNREACH

A write was attempted on a socket and no route to the network is present.

EXAMPLES

Writing from a Buffer

The following example writes data from the buffer pointed to by buf to the file associated with the file descriptor fd.

#include <sys/types.h>
#include <string.h>
...
char buf[20];
size_t nbytes;
ssize_t bytes_written;
int fd;
...
strcpy(buf, "This is a test\n");
nbytes = strlen(buf);
bytes_written = write(fd, buf, nbytes);
...

APPLICATION USAGE

None.

RATIONALE

See also the RATIONALE section in read().

An attempt to write to a pipe or FIFO has several major characteristics:

*
Atomic/non-atomic: A write is atomic if the whole amount written in one operation is not interleaved with data from any other process. This is useful when there are multiple writers sending data to a single reader. Applications need to know how large a write request can be expected to be performed atomically. This maximum is called {PIPE_BUF}. This volume of POSIX.1‐2017 does not say whether write requests for more than {PIPE_BUF} bytes are atomic, but requires that writes of {PIPE_BUF} or fewer bytes shall be atomic.
*
Blocking/immediate: Blocking is only possible with O_NONBLOCK clear. If there is enough space for all the data requested to be written immediately, the implementation should do so. Otherwise, the calling thread may block; that is, pause until enough space is available for writing. The effective size of a pipe or FIFO (the maximum amount that can be written in one operation without blocking) may vary dynamically, depending on the implementation, so it is not possible to specify a fixed value for it.
*
Complete/partial/deferred: A write request:
int fildes;
size_t nbyte;
ssize_t ret;
char *buf;
ret = write(fildes, buf, nbyte);

may return:

Complete
ret=nbyte
Partial
ret<nbyte

This shall never happen if nbyte≤{PIPE_BUF}. If it does happen (with nbyte>{PIPE_BUF}), this volume of POSIX.1‐2017 does not guarantee atomicity, even if ret≤{PIPE_BUF}, because atomicity is guaranteed according to the amount requested, not the amount written.

Deferred:
ret=-1, errno=[EAGAIN]

This error indicates that a later request may succeed. It does not indicate that it shall succeed, even if nbyte≤{PIPE_BUF}, because if no process reads from the pipe or FIFO, the write never succeeds. An application could usefully count the number of times [EAGAIN] is caused by a particular value of nbyte>{PIPE_BUF} and perhaps do later writes with a smaller value, on the assumption that the effective size of the pipe may have decreased.

Partial and deferred writes are only possible with O_NONBLOCK set.

The relations of these properties are shown in the following tables:

Write to a Pipe or FIFO with O_NONBLOCK clear
Immediately Writable: None Some nbyte
Complete: Yes Yes Yes
Partial: No No No
Deferred: No No No
Write to a Pipe or FIFO with O_NONBLOCK set
Immediately Writable: None Some nbyte
Complete: Yes Yes Yes
Partial: No Yes Yes
Deferred: Yes No No

This volume of POSIX.1‐2017 requires that write operations to pipes and FIFOs be atomic up to {PIPE_BUF} bytes. This implies that if nbyte is less than or equal to {PIPE_BUF}, the write operation will either transfer nbyte bytes or it will fail. It will not transfer part of the request. It can still fail with [EAGAIN] if O_NONBLOCK is set and the write would block, or it can fail for other reasons. The atomicity requirement only states that the data is not interleaved with data from other processes writing to the same pipe or FIFO.

The behavior of write() to a regular file is specified to handle partial writes. Applications that expect writes to regular files to be atomic can write up to {PIPE_BUF} bytes at a time. This volume of POSIX.1‐2017 does not specify whether writes to regular files are atomic.

The behavior of pwrite() is similar to write(), but it does not change the file offset. This is useful for random access I/O, where the application maintains its own file offset. The atomicity semantics are the same as for write().

RATIONALE

El comportamiento de write() a tuberías y FIFO se define en términos de si la cantidad de datos solicitada (nbyte) es menor o igual, o mayor que la constante {PIPE_BUF}. Si nbyte es menor o igual a {PIPE_BUF}, la escritura es atómica; es decir, se escribe la cantidad solicitada o no se escribe nada, y la operación no se mezcla con otras escrituras atómicas. Si nbyte es mayor que {PIPE_BUF}, la escritura puede no ser atómica y puede escribir menos de la cantidad solicitada.

Escribir a una Tubería o FIFO sin O_NONBLOCK
Solicitado: Tubería Vacía Tubería Parcialmente Llena Tubería Llena
nbyte≤{PIPE_BUF} Bloqueo atómico Bloqueo atómico Bloqueo atómico
nbyte nbyte nbyte
nbyte>{PIPE_BUF} Bloqueo nbyte Bloqueo nbyte Bloqueo nbyte

Si la bandera O_NONBLOCK está deshabilitada, una solicitud de escritura se bloqueará si la cantidad que se puede escribir inmediatamente es menor que la solicitada. Si la bandera está establecida (por fcntl()), una solicitud de escritura nunca se bloqueará.

Escribir a una Tubería o FIFO con O_NONBLOCK establecido
Inmediatamente Escribible: Ninguno Algo nbyte
nbyte≤{PIPE_BUF} -1, [EAGAIN] -1, [EAGAIN] nbyte atómico
nbyte>{PIPE_BUF} -1, [EAGAIN] <nbyte o -1, ≤nbyte o -1,
[EAGAIN] [EAGAIN]

No hay excepción con respecto a escrituras parciales cuando O_NONBLOCK está establecido. Con la excepción de escribir en una tubería vacía, este volumen de POSIX.1‐2017 no especifica exactamente cuándo se realiza una escritura parcial, ya que eso requeriría especificar detalles internos de la implementación. Cada aplicación debe estar preparada para manejar escrituras parciales cuando O_NONBLOCK está establecido y la cantidad solicitada es mayor que {PIPE_BUF}, al igual que cada aplicación debe estar preparada para manejar escrituras parciales en otros tipos de descriptores de archivo.

La intención de forzar la escritura de al menos un byte si se puede escribir alguno es asegurar que cada escritura progrese si hay espacio en la tubería. Si la tubería está vacía, se deben escribir {PIPE_BUF} bytes; si no, al menos se debe haber progresado algo.

Donde este volumen de POSIX.1‐2017 requiere devolver -1 y establecer errno a [EAGAIN], la mayoría de las implementaciones históricas devuelven cero (con la bandera O_NDELAY establecida, que es el predecesor histórico de O_NONBLOCK, pero que en sí misma no está en este volumen de POSIX.1‐2017). Las indicaciones de error en este volumen de POSIX.1‐2017 fueron elegidas para que una aplicación pueda distinguir estos casos del fin de archivo. Mientras que write() no puede recibir una indicación de fin de archivo, read() sí puede, y las dos funciones tienen valores de retorno similares. Además, algunos sistemas existentes (por ejemplo, Eighth Edition) permiten que una escritura de cero bytes signifique que el lector debe obtener una indicación de fin de archivo; para esos sistemas, un valor de retorno de cero de write() indica una escritura exitosa de una indicación de fin de archivo.

Las implementaciones tienen permitido, pero no están obligadas a, realizar comprobaciones de errores para solicitudes de write() de cero bytes.

El concepto de un límite {PIPE_MAX} (que indica el número máximo de bytes que se pueden escribir en una tubería en una sola operación) se consideró, pero se rechazó, ya que este concepto limitaría innecesariamente la escritura de aplicaciones.

Véase también la discusión de O_NONBLOCK en read().

Las escrituras pueden serializarse con respecto a otras lecturas y escrituras. Si se puede demostrar (por cualquier medio) que una read() de datos del archivo ocurre después de una write() de los datos, debe reflejar esa write(), incluso si las llamadas son realizadas por procesos diferentes. Un requisito similar se aplica a múltiples operaciones de escritura en la misma posición de archivo. Esto es necesario para garantizar la propagación de datos de las llamadas write() a las llamadas read() posteriores. Este requisito es particularmente significativo para los sistemas de archivos en red, donde algunos esquemas de caché violan estas semánticas.

Tenga en cuenta que esto se especifica en términos de read() y write(). Las extensiones XSI readv() y writev() también obedecen estas semánticas. Una nueva escritura análoga de "alto rendimiento" que no siguiera estos requisitos de serialización también estaría permitida por esta redacción. Este volumen de POSIX.1‐2017 también guarda silencio sobre cualquier efecto de la caché a nivel de aplicación (como la realizada por stdio).

Este volumen de POSIX.1‐2017 no especifica el valor del desplazamiento del archivo después de que se devuelve un error; hay demasiados casos. Para errores de programación, como [EBADF], el concepto no tiene sentido ya que no hay ningún archivo involucrado. Para errores que se detectan inmediatamente, como [EAGAIN], claramente el puntero no debería cambiar. Sin embargo, después de una interrupción o un error de hardware, un valor actualizado sería muy útil y es el comportamiento de muchas implementaciones.

Este volumen de POSIX.1‐2017 no especifica el comportamiento de escrituras concurrentes a un archivo regular desde múltiples hilos, excepto que cada escritura es atómica (ver Sección 2.9.7, Interacciones de Hilos con Operaciones de Archivo Regular). Las aplicaciones deben usar alguna forma de control de concurrencia.

Este volumen de POSIX.1‐2017 intencionalmente no especifica ningún error de pwrite() relacionado con tuberías, FIFO y sockets, aparte de [ESPIPE].
