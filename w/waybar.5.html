waybar(5) Manual de formatos de archivo waybar(5)

NOMBRE

waybar - archivo de configuración

DESCRIPCIÓN

La configuración utiliza el formato de archivo JSONC y se denomina config o config.jsonc.

Las ubicaciones válidas para este archivo son:

  • $XDG_CONFIG_HOME/waybar/
  • ~/.config/waybar/
  • ~/waybar/
  • /etc/xdg/waybar/
  • /etc/xdg/waybar/

Un buen punto de partida es la configuración predeterminada que se encuentra en https://github.com/Alexays/Waybar/blob/master/resources/config.jsonc. Además, un ejemplo de configuración mínima se puede encontrar al final de esta página del manual.

Los elementos de visualización visual para waybar utilizan una hoja de estilos CSS, consulte waybar-styles(5) para obtener más detalles.

CONFIGURACIÓN DE LA BARRA

expand-center
tipo: booleano
predeterminado: falso
Habilita que los módulos centrales consuman todo el espacio restante dinámicamente.

expand-left
tipo: booleano
predeterminado: falso
Habilita que los módulos izquierdos consuman todo el espacio restante dinámicamente.

expand-right
tipo: booleano
predeterminado: falso
Habilita que los módulos derechos consuman todo el espacio restante dinámicamente.

layer
tipo: cadena
predeterminado: bottom
Decide si la barra se muestra delante (top) de las ventanas o detrás (bottom).

de ellas.

output
tipo: cadena|arreglo
Especifica en qué pantalla se mostrará esta barra. El signo de exclamación (!) se puede usar para excluir salidas específicas.

La especificación de salida sigue a la de sway y puede ser el puerto de salida como "HDMI-A-1" o una cadena que consiste en el fabricante, modelo y serie como "Some Company ABC123 0x00000000". Consulte sway-output(5) para obtener detalles. En un arreglo, el asterisco '*' se puede usar al final para aceptar todas las salidas, en caso de que todas las entradas anteriores sean exclusiones.

position
tipo: cadena
predeterminado: top
Posición de la barra, puede ser top, bottom, left, right.

height
tipo: entero
Altura a utilizar por la barra si es posible. Dejar en blanco para un valor dinámico.

width
tipo: entero
Ancho a utilizar por la barra si es posible. Dejar en blanco para un valor dinámico.

modules-left
tipo: arreglo
Módulos que se mostrarán a la izquierda.

modules-center
tipo: arreglo
Módulos que se mostrarán en el centro.

modules-right
tipo: arreglo

Módulos que se mostrarán a la derecha.

margin
tipo: cadena
Valor de márgenes utilizando el formato CSS sin unidades.

margin-<top|left|bottom|right>
tipo: entero
Valor de márgenes sin unidades.

no-center
tipo: booleano
predeterminado: falso
Opción para deshabilitar completamente los módulos centrales, muy útil junto con expand-*.

spacing
tipo: entero
Tamaño de los espacios entre los diferentes módulos.

name
tipo: cadena
Nombre opcional agregado como una clase CSS, para estilizar múltiples waybars.

mode
tipo: cadena
Selecciona uno de los modos de visualización preconfigurados. Esto es un equivalente del comando mode de sway-bar(5) y admite los mismos valores: dock, hide, invisible, overlay.
Nota: Los modos hide e invisible pueden no ser tan útiles sin Sway IPC.

start_hidden
tipo: booleano
predeterminado: false
Opción para iniciar la barra oculta.

modifier-reset
tipo: cadena
predeterminado: press

Define el momento en que la tecla modificadora reinicia la visibilidad de la barra. Para reiniciar la visibilidad de la barra con la presión de la tecla modificadora, use press. Use release para reiniciar la visibilidad al soltar la tecla modificadora y solo si no ocurrió ninguna otra acción mientras la tecla estaba presionada. Esto evita ocultar la barra cuando el modificador se usa para cambiar de espacio de trabajo, cambiar el modo de enlace o iniciar una combinación de teclas.

exclusive
tipo: booleano
predeterminado: true
Opción para solicitar una zona exclusiva del compositor. Deshabilite esto para permitir que las ventanas de aplicaciones se dibujen debajo o encima de la barra.

fixed-center
tipo: booleano
predeterminado: true

Prefiere la posición central fija para el bloque `modules-center`. El bloque central permanecerá en medio de la barra siempre que sea posible. Aún puede ser empujado si otros bloques necesitan más espacio. Cuando es falso, el bloque central se centra en el espacio entre el bloque izquierdo y el derecho.

passthrough
tipo: booleano
predeterminado: false
Opción para pasar cualquier evento del puntero a la ventana debajo de la barra.

Destinado a ser utilizado con capas top u overlay y sin zona exclusiva.

ipc
tipo: booleano
predeterminado: falso
Opción para suscribirse a los eventos de configuración y visibilidad de la barra de Sway IPC y controlar waybar con comandos swaymsg bar.
Requiere que el valor bar_id de la configuración de sway se pase con el argumento de línea de comandos -b o se especifique con la opción id.

id
tipo: cadena
bar_id para el Sway IPC. Úselo si necesita anular el valor pasado con el argumento de línea de comandos -b bar_id para la instancia de barra específica.

include
tipo: cadena|arreglo
Rutas a archivos de configuración adicionales.

Cada archivo puede contener un solo objeto con cualquiera de las opciones de configuración de la barra. En caso de opciones duplicadas, el primer valor definido tiene prioridad, es decir, archivo de inclusión -> primer archivo incluido -> etc. Se permiten inclusiones anidadas, pero asegúrese de evitar importaciones circulares. Para una configuración de múltiples barras, la directiva include afecta solo al objeto de configuración de la barra actual.

reload_style_on_change
tipo: booleano
predeterminado: false
Opción para habilitar la recarga del estilo CSS si se detecta una modificación en el archivo de hoja de estilos o en cualquier archivo CSS importado.

on-sigusr1
tipo: cadena
predeterminado: toggle
Acción que se realiza al recibir la señal de terminación SIGUSR1.
Valores posibles: show, hide, toggle, reload, noop.
Valor predeterminado: toggle.

on-sigusr2
tipo: cadena
predeterminado: reload
Acción que se realiza al recibir la señal de terminación SIGUSR2.
Valores posibles: show, hide, toggle, reload, noop.
Valor predeterminado: reload.

FORMATO DE MÓDULO

Puede usar PangoMarkupFormat (Ver https://developer.gnome.org/pango/stable/PangoMarkupFormat.html#PangoMarkupFormat).

por ejemplo.

"format": "<span style="italic">{}</span>"

MÚLTIPLES INSTANCIAS DE UN MÓDULO

Si desea tener una segunda instancia de un módulo, puede agregarle un sufijo '#' y un nombre personalizado. Por ejemplo, si desea un segundo módulo de batería, puede agregar "battery#bat2" a sus módulos. Para configurar el nuevo módulo agregado, también agregará una configuración de módulo con el mismo nombre.

Esto podría parecerse a esto (este es un ejemplo incompleto):

"modules-right": ["battery", "battery#bat2"],
"battery": {
	"bat": "BAT1"
},
"battery#bat2": {
	"bat": "BAT2"
}

CONFIGURACIÓN MÍNIMA

Un archivo config mínimo podría verse así:

{
	"layer": "top",
	"
{ "modules-left": ["sway/workspaces", "sway/mode"], "modules-center": ["sway/window"], "modules-right": ["battery", "clock"], "sway/window": { "max-length": 50 }, "battery": { "format": "{capacity}% {icon}", "format-icons": ["\uf244", "\uf243", "\uf242", "\uf241", "\uf240"] }, "clock": { "format-alt": "{:%a, %d. %b %H:%M}" } } ```

SEÑALES

Waybar acepta las siguientes señales:

SIGUSR1

Por defecto, alterna la visibilidad de la barra (la oculta si se muestra, la muestra si está oculta).
SIGUSR2
Por defecto, recarga (reinicia) la barra.
SIGINT
Cierra la barra.

Por ejemplo, para alternar la barra programáticamente, puedes ejecutar `killall -SIGUSR1 waybar`.

Configuración de señales de usuario

Los parámetros de configuración on-sigusr1 y on-sigusr2 cambian lo que sucede cuando las barras reciben las señales SIGUSR1 y SIGUSR2.

Esto significa que los comandos `killall -SIGUSR1 waybar` y `killall -SIGUSR2 waybar` pueden realizar acciones configuradas por el usuario.

También significa que si un script externo tiene el PID de la barra, puede realizar una lógica más compleja de `show`/`hide`/`reload` para cada instancia de Waybar. Se puede encontrar el PID, por ejemplo, haciendo `pgrep -a waybar`, que luego podría coincidir por nombre de configuración u otros parámetros.

Significados de los parámetros de kill

show Cambia el estado a visible (por barra). hide Cambia el estado a oculto (por barra). toggle Cambia el estado entre visible y oculto (por barra). reload Recarga todas las barras del proceso actual de waybar (básicamente equivalente a reiniciar con la configuración actualizada que establece los valores de visibilidad iniciales). noop No hace nada cuando se recibe la señal de kill.

CONFIGURACIÓN MULTIPLE DE SALIDA

Limitar una configuración a algunas salidas

{
	"layer": "top",
	"output": "eDP-1",
	"modules-left": ["sway/workspaces", "sway/mode"],
	...
}
{
	"layer": "top",
	"output": ["eDP-1", "VGA"],
	"modules-left": ["sway/workspaces", "sway/mode"],
	...
}

Configuración de múltiples salidas

No especifiques una salida para crear múltiples barras en la misma pantalla.

[{
	"layer": "top",
	"output": "eDP-1",
	"modules-left": ["sway/workspaces", "sway/mode"],
	...
}, {
	"layer": "top",
	"output": "VGA",
	"modules-right": ["clock"],
	...
}]

Rotación de módulos

Al posicionar Waybar en el lado izquierdo o derecho de la pantalla, a veces es útil poder rotar el contenido de un módulo para que el texto se muestre verticalmente. Esto se puede hacer usando la propiedad "rotate" del módulo. Ejemplo:

{
	"clock": {
		"rotate": 90
	}
}

Las opciones válidas para la propiedad "rotate" son: 0, 90, 180 y 270.

Intercambio de icono y etiqueta

Si un módulo muestra tanto una etiqueta como un icono, podría ser deseable intercambiarlos (por ejemplo, para paneles en el lado izquierdo o derecho de la pantalla, o para usuarios que adoptan un script de derecha a izquierda). Esto se puede lograr con la propiedad "swap-icon-label", que toma un valor booleano. Ejemplo:

{
	"sway/window": {
		"swap-icon-label": true
	}
}

Agrupación de módulos

Los grupos de módulos permiten apilar módulos en cualquier dirección. Por defecto, cuando la barra se posiciona en la parte superior o inferior de la pantalla, los módulos de un grupo se apilan verticalmente. De manera similar, cuando se posiciona a la izquierda o a la derecha, los módulos de un grupo se apilan horizontalmente. Esto se puede cambiar con la propiedad "orientation".

Un grupo de módulos se define especificando un módulo llamado "group/some-group-name". El grupo también debe configurarse con una lista de módulos contenidos. Ejemplo:

{
	"modules-right": ["group/hardware", "clock"],
	"group/hardware": {
		"orientation": "vertical",
		"modules": [
			"cpu",
			"memory",
			"battery"
		]
	},
	...
}

Las opciones válidas para la propiedad (opcional) "orientation" son: "horizontal", "vertical", "inherit" y "orthogonal" (por defecto).

Cajones de grupo

Un grupo puede ocultar todos los elementos excepto uno, mostrándolos solo al pasar el ratón por encima. Para configurar esto, puedes usar la propiedad `drawer`, cuyo valor es un objeto con las siguientes propiedades:

transition-duration:
tipo: integer
predeterminado: 500
Define la duración de la animación de transición en milisegundos.

children-class:
tipo: string
predeterminado: "hidden"
Define la clase CSS que se aplicará a los elementos ocultos.

click-to-reveal:
tipo: bool
predeterminado: false
Si el clic izquierdo debe revelar el contenido en lugar del paso del ratón. Ten en cuenta que los módulos agrupados aún pueden procesar sus propios eventos on-click.

transition-left-to-right:
tipo: bool
predeterminado: true
Define la dirección de la animación de transición. Si es verdadero, los elementos ocultos se deslizarán de izquierda a derecha. Si es falso, se deslizarán de derecha a izquierda.

Cuando la barra es vertical, se lee de arriba a abajo.
"group/power": {
    "orientation": "inherit",
    "drawer": {
        "transition-duration": 500,
        "children-class": "not-power",
        "transition-left-to-right": false,
    },
    "modules": [
        "custom/power", // El primer elemento es el "líder del grupo" y nunca se ocultará
        "custom/quit",
        "custom/lock",
        "custom/reboot",
    ]
},
