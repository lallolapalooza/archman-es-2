WIREFILTER(1) Manual de Comandos Generales WIREFILTER(1)

NOMBRE

wirefilter - Filtro de paquetes de alambre para Ethernet Distribuido Virtual

SINOPSIS

wirefilter

[-f archivo_rc] [-l pérdida] [-l racha_perdida] [-d retraso] [-D duplicación] [-b ancho_banda] [-s velocidad_interfaz] [-c tamaño_buffer_canal] [-n factor_ruido] [-m tamaño_mtu] [-M socket_gestion] [-v vde_plug1:vde_plug2] [--daemon] [--pidfile ruta_archivo_pid] [--blink blink] [--blinkid identificador_blink] [-N]

DESCRIPCIÓN

Un wirefilter es capaz de emular retrasos y pérdida de paquetes en alambres virtuales. por ejemplo:

dpipe vde_plug /tmp/s1 = wirefilter -l 10 = vde_plug /tmp/s2

crea un alambre entre dos vde_switches (con sockets /tmp/s1 y /tmp/s2 respectivamente). Este cable pierde el 10% de los paquetes en cada dirección.

El mismo cable se puede crear usando:

wirefilter -v /tmp/s1:/tmp/s2 -l 10

OPCIONES

-f archivo_rc
usa un archivo de configuración de inicio. Es útil para definiciones complejas tales como las del modo Markov (ver abajo). El archivo de configuración de inicio tiene la misma sintaxis que la interfaz de gestión, en otras palabras, es un script de comandos de gestión ejecutado antes de que se transmita el primer paquete.
-l pérdida
porcentaje de pérdida como un número de punto flotante. Es posible especificar diferentes porcentajes de pérdida para los dos canales: IZ20.5 significa que el 20.5% de los paquetes que fluyen de izquierda a derecha se pierden, DE10 significa que el 10% de derecha a izquierda.
-L racha_perdida
cuando esto no es cero, wirefilter usa el modelo de Gilbert para errores de racha. Esta es la longitud media de las rachas de paquetes perdidos. (es una cadena de Markov de dos estados: la probabilidad de salir del estado defectuoso es 1/racha_perdida, la probabilidad de entrar en el estado defectuoso es pérdida/(racha_perdida-(1-pérdida)). La tasa de pérdida converge al valor pérdida.
-d retraso
Retraso adicional (en milisegundos). Este retraso se suma al retraso real de comunicación. Los paquetes se almacenan temporalmente y se reenvían después del retraso. Es posible especificar valores diferentes para IZ y DE como en la opción anterior. Cuando el retraso se especifica como dos números con un + en medio, el primero es el retraso estándar y el segundo es una variación aleatoria. 1000+500 significa que el retraso se puede elegir aleatoriamente entre medio segundo y 1.5 segundos. Es posible añadir 'U' o 'N' al final. 1000+500U significa que los retrasos se distribuyen uniformemente, 1000+500N significa que los retrasos siguen una distribución normal Gaussiana (más del 98% de los valores están dentro de los límites).
-D duplicación
porcentaje de paquetes duplicados. Tiene la misma sintaxis que -l. No uses un factor de duplicación del 100% porque significa que cada paquete se envía infinitas veces.
-b ancho_banda
Ancho de banda del canal en Bytes/segundo. Tiene la misma sintaxis que -d. También es posible usar los sufijos K, M, G para abreviar 2^10, 2^20, 2^30. 128K significa 128 KBytes/segundo. 128+64K significa de 64i a 196 KBytes/segundo. El remitente no tiene impedimentos para enviar paquetes, la entrega se retrasa para limitar el ancho de banda al valor deseado. (Como un cuello de botella en la ruta) U y N después de los valores (ej. 128+64KN) establecen la distribución estadística a usar (uniforme o normal).
-s velocidad
Velocidad de la interfaz en Bytes/segundo. Tiene la misma sintaxis que -b. La entrada se bloquea durante el tiempo de transmisión del paquete, impidiendo así que el remitente envíe demasiado rápido.
-c tamaño_buffer_canal
Tamaño del buffer del canal (en Bytes): tamaño máximo de la cola de paquetes. Los paquetes que excedan se descartan.
-n factor_ruido
Número de bits dañados/un megabyte.
-m tamaño_mtu
Los paquetes más largos que tamaño_mtu se descartan.
-N
sin cola. con -N los paquetes pueden reordenarse.
-M socket_gestion
el socket unix donde se pueden verificar y cambiar los parámetros (porcentaje de pérdida, retraso, etc.) en tiempo real. unixterm(1) puede ser usado como un terminal remoto para wirefilter.
-v vde_plug1:vde_plug2
Si se usa esta opción, los dos vde_plugs locales (vde_plug1 y vde_plug2) se conectarán entre sí en lugar de stdin/stdout, usando las bibliotecas libvdeplug. Esta opción activa una sesión de gestión interactiva en la consola (stdin/stdout).
--mgmtmode modo
esta opción establece el modo de acceso del socket de gestión. La sintaxis del comando es bastante simple. help proporciona la lista de comandos. Es posible cargar un archivo de script usando el comando de gestión load.
--daemon
wirefilter se convierte en un demonio
--pidfile ruta_archivo_pid
wirefilter guarda su pid en el archivo.
--blinkid nombre
Esta opción define el id enviado para cada paquete al servidor blink (ver la opción --blink abajo). El identificador estándar para un wirefilter es el pid del proceso.
--blink socket
wirefilter envía un mensaje de registro al socket PF_UNIX/DATAGRAM especificado por cada paquete enviado. Cada paquete tiene el formato: id dirección longitud. por ejemplo: 


6768 IZ 44
6768 IZ 44
6768 DE 100
6768 IZ 100
6768 IZ 44

Modo Markov

wirefilter también proporciona un conjunto de parámetros más complejo utilizando una cadena de Markov para emular diferentes estados del enlace y las transiciones entre estados. Cada estado está representado por un nodo. Los parámetros de la cadena de Markov se pueden establecer solo con comandos de gestión o archivos rc. De hecho, debido al gran número de parámetros, la línea de comandos habría sido ilegible.

markov-numnodes n
define el número de diferentes estados. Todos los parámetros de la conexión se pueden definir nodo por nodo. Los nodos se numeran a partir de cero (hasta n-1). por ejemplo: 


retraso 100+10N[4]
pérdida 10[2]

estos comandos definen un retraso de 90-110 ms (distribución normal) para el nodo número 4 y una pérdida de 10 para el nodo 2. Es posible redimensionar la cadena de Markov en tiempo de ejecución. Los nuevos nodos son inalcanzables y no tienen ninguna arista hacia otros estados (es decir, cada nuevo nodo tiene una arista de bucle hacia el nodo mismo con un 100% de probabilidad). Al reducir el número de nodos, el peso de las aristas hacia los nodos eliminados se añade a la arista de bucle. Cuando se elimina el nodo actual de la emulación, el nodo 0 se convierte en el nodo actual. (La emulación siempre comienza desde el nodo 0).

markov-time ms
período de tiempo (ms) para el cálculo de la cadena de Markov. Cada ms microsegundos, un generador de números aleatorios decide cuál es el siguiente estado (valor predeterminado=100ms).
markov-name n,nombre
asigna un nombre a un nodo de la cadena de Markov.
markov-setnode n
establece manualmente el nodo actual al nodo n.
setedge n1,n2,p
define una arista entre n1 y n2; p es el peso (porcentaje de probabilidad) de la arista. La arista de bucle (desde un nodo a sí mismo) siempre se calcula como 100% menos la suma de los pesos de las aristas salientes.

NAME

vdeq - Virtual Distributed Ethernet query utility

SYNOPSIS

vdeq [ -d ] [ -h ] [ -v ] [ -c ] [ -m ] [ command ]

DESCRIPTION

The vdeq utility is used to query the status and control the Virtual Distributed Ethernet network.

It can be used to list the switches, the nodes connected to them, and their status.

The tool supports different commands to inspect and manipulate the VDE network state.

OPTIONS

vdeq accepts the following options:

-d
Dump the entire VDE network state.
-h
Show a help message and exit.
-v
Show version information and exit.
-c
Show the list of available VDE control sockets.
-m
Enter Markov mode (interactive commands).

Markov mode

When the -m option is specified, vdeq enters an interactive mode where specific commands can be issued to query and control the VDE network. The following commands are available in Markov mode:

showedges [ n ]
Muestra los bordes del nodo n (o del nodo actual cuando el comando no tiene parámetros). Se omiten los bordes de peso nulo.
showcurrent
Muestra el estado de Markov actual.
showinfo [ n ]
Muestra el estado e información del estado (nodo) n. Si se omite el parámetro, muestra el estado e información del estado actual.
markov-debug [ n ]
Establece el nivel de depuración para la conexión de gestión actual. En la implementación actual, cuando n es mayor que cero, cada cambio de nodo de markov provoca la salida de un rastro de depuración. El rastreo de depuración se desactiva cuando n es cero o falta el parámetro.
