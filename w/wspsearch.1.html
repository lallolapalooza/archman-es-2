WSPSEARCH(1) Comandos de usuario WSPSEARCH(1)

NOMBRE

wspsearch - Ejecuta búsquedas de Windows Search Protocol contra un servidor SMB

SINOPSIS

wspsearch {//servidor/recurso} [--limit=resultados] [--search=frase] [--kind=TIPO] [--query=CONSULTA] [-?|--help] [--usage] [-d|--debuglevel=NIVELDEBUG] [--debug-stdout] [-s|--configfile=ARCHIVO_CONFIG] [--option=nombre=valor] [-l|--log-basename=ARCHIVO_LOG] [--leak-report] [--leak-report-full] [-R|--name-resolve=ORDEN_RESOLUCION_NOMBRES] [-O|--socket-options=OPCIONES_SOCKET] [-m|--max-protocol=MAXPROTOCOLO] [-n|--netbiosname=NOMBRE_NETBIOS] [--netbios-scope=SCOPE] [-W|--workgroup=GRUPO_TRABAJO] [--realm=REALM] [-U|--user=[DOMINIO/]USUARIO[%CONTRASEÑA]] [-N|--no-pass] [--password=CADENA] [--pw-nt-hash] [-A|--authentication-file=ARCHIVO] [-P|--machine-pass] [--simple-bind-dn=DN] [--use-kerberos=deseado|requerido|apagado] [--use-krb5-ccache=CCACHE] [--use-winbind-ccache] [--client-protection=firmar|cifrar|apagado]

DESCRIPCIÓN

Esta herramienta forma parte del conjunto samba(1).

wspsearch es una utilidad simple para ejecutar búsquedas de Windows Search Protocol contra un servidor SMB que tenga habilitado el servicio WSP.

OPCIONES

servidor

El nombre o la dirección IP del servidor SMB al que conectarse.

nombredelrecurso

El nombre de un recurso compartido en el servidor.

--query

Una consulta especificada en un formato similar a AQS (Advanced Query Syntax) simplificado.

Se admite la sintaxis básica (AQS) (Ver VER TAMBIÉN). Una consulta consta de una secuencia de consultas conectadas por operadores booleanos AND, OR y NOT. Los elementos de la consulta son esencialmente restricciones definidas por una propiedad. Existen algunas limitaciones en los operadores admitidos y algunos tipos de propiedades, como los rangos enumerados, no se admiten en absoluto. Además, los valores de rango sintácticos no están delimitados como se especifica en AQS (los rangos se especifican en su lugar como valor-valor). Algunos casos especiales que se ven en la interfaz de búsqueda de Windows (por ejemplo, tamaños como 'tiny', 'small', 'large', etc.) son excepciones que se manejan más o menos como palabras clave. Ver EJEMPLOS.

--limit

Un límite en el número de resultados devueltos, por defecto hay un límite de 500 resultados, un límite de 0 indica sin límite y se devolverán todos los resultados.

-?|--help

Imprime un resumen de las opciones de la línea de comandos.

--usage

Muestra un breve mensaje de uso.

-d|--debuglevel=nivel

nivel es un entero de 0 a 10. El valor por defecto si este parámetro no se especifica es 1 para aplicaciones cliente.

Cuanto mayor sea este valor, más detalle se registrará en los archivos de registro sobre las actividades del servidor. En el nivel 0, solo se registrarán errores críticos y advertencias graves. El nivel 1 es un nivel razonable para el uso diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben usarse al investigar un problema. Los niveles superiores a 3 están diseñados solo para uso de desarrolladores y generan enormes cantidades de datos de registro, la mayoría de los cuales son extremadamente crípticos.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro log level en el archivo /etc/samba/smb.conf.

--debug-stdout

Esto redirigirá la salida de depuración a STDOUT. Por defecto, todos los clientes registran en STDERR.

--configfile=<archivo de configuración>

El archivo especificado contiene los detalles de configuración requeridos por el cliente. La información en este archivo puede ser general para cliente y servidor o solo proporcionar opciones específicas del cliente como client smb encrypt. Consulte /etc/samba/smb.conf para obtener más información. El nombre del archivo de configuración por defecto se determina en tiempo de compilación.

--option=<nombre>=<valor>

Establece la opción de smb.conf(5) "<nombre>" al valor "<valor>" desde la línea de comandos. Esto anula los valores predeterminados compilados y las opciones leídas del archivo de configuración. Si un nombre o un valor incluyen un espacio, encierre todo --option=nombre=valor entre comillas.

-l|--log-basename=directorio_log

Nombre base para los archivos de registro/depuración. La extensión ".progname" se añadirá (por ejemplo, log.smbclient, log.smbd, etc...). El cliente nunca elimina el archivo de registro.

--leak-report

Habilita el informe de fugas de talloc al salir.

--leak-report-full

Habilita el informe completo de fugas de talloc al salir.

-V|--version

Imprime el número de versión del programa.

-U|--user=[DOMINIO\]USUARIO[%CONTRASEÑA]

Establece el nombre de usuario SMB o el nombre de usuario y contraseña.

Si no se especifica %CONTRASEÑA, se le pedirá al usuario. El cliente primero comprobará la variable de entorno USER (que también tiene permitido contener la contraseña separada por un %), luego la variable LOGNAME (que no tiene permitido contener una contraseña) y si alguna existe, se usará el valor. Si no se encuentran estas variables de entorno, se puede usar el nombre de usuario encontrado en una caché de credenciales de Kerberos.

Una tercera opción es usar un archivo de credenciales que contenga el texto plano del nombre de usuario y la contraseña. Esta opción se proporciona principalmente para scripts donde el administrador no desea pasar las credenciales en la línea de comandos o a través de variables de entorno. Si se utiliza este método, asegúrese de que los permisos del archivo restrinjan el acceso a usuarios no deseados. Ver la opción -A para más detalles.

Tenga cuidado al incluir contraseñas en scripts o al pasar valores proporcionados por el usuario en la línea de comandos. Por seguridad, es mejor dejar que la herramienta cliente de Samba pida la contraseña si es necesario, u obtenga la contraseña una vez con kinit.

Aunque Samba intentará limpiar la contraseña del título del proceso (como se ve en ps), esto ocurre después del inicio y está sujeto a una condición de carrera.

-N|--no-pass

Si se especifica, este parámetro suprime el aviso normal de contraseña del cliente al usuario. Esto es útil al acceder a un servicio que no requiere contraseña.

A menos que se especifique una contraseña en la línea de comandos o se defina este parámetro, el cliente solicitará una contraseña.

Si se especifica una contraseña en la línea de comandos y también se define esta opción, la contraseña en la línea de comandos será ignorada silenciosamente y no se utilizará ninguna contraseña.

--password

Especifica la contraseña en la línea de comandos.

Tenga cuidado al incluir contraseñas en scripts o al pasar valores proporcionados por el usuario en la línea de comandos. Por seguridad, es mejor dejar que la herramienta cliente de Samba pida la contraseña si es necesario, u obtenga la contraseña una vez con kinit.

Si no se especifica --password, la herramienta comprobará la variable de entorno PASSWD, seguida de PASSWD_FD que se espera que contenga un número de descriptor de archivo (FD) abierto.

Finalmente, comprobará PASSWD_FILE (que contiene una ruta de archivo a abrir). El archivo solo debe contener la contraseña. ¡Asegúrese de que los permisos del archivo restrinjan el acceso a usuarios no deseados!

Aunque Samba intentará limpiar la contraseña del título del proceso (como se ve en ps), esto ocurre después del inicio y está sujeto a una condición de carrera.

-A|--authentication-file=filename

Esta opción te permite especificar un archivo desde el cual leer el nombre de usuario y la contraseña utilizados en la conexión. El formato del archivo es: 
username = <valor>
password = <valor>
domain   = <valor>

¡Asegúrate de que los permisos del archivo restrinjan el acceso a usuarios no deseados!

-P|--machine-pass

Utiliza la contraseña de la cuenta de máquina almacenada.

--simple-bind-dn=DN

DN a utilizar para un enlace simple.

--use-kerberos=desired|required|off

Este parámetro determina si las herramientas cliente de Samba intentarán autenticarse usando Kerberos. Para la autenticación Kerberos, deberías usar nombres DNS en lugar de direcciones IP al conectarte a un servicio. Por defecto, las herramientas cliente de Samba intentarán usar la caché de credenciales Kerberos (ccache) predeterminada. En caso de que la ccache no exista o se haya especificado la opción -U|--user, los clientes pedirán una contraseña y obtendrán un ticket Kerberos (kinit) para ti. Si quieres usar una caché de credenciales Kerberos alternativa, usa la opción --use-krb5-ccache.

Ten en cuenta que especificar este parámetro aquí anulará el parámetro client use kerberos en el archivo /etc/samba/smb.conf.

--use-krb5-ccache=CCACHE

Especifica la ubicación de la caché de credenciales para la autenticación Kerberos.

Esto forzará --use-kerberos=required.

--use-winbind-ccache

Intenta usar la caché de credenciales de winbind.

--client-protection=sign|encrypt|off

Establece la protección de conexión que debe usar la herramienta cliente.

Ten en cuenta que especificar este parámetro aquí anulará el parámetro client protection en el archivo /etc/samba/smb.conf.

En caso de que necesites un control más detallado, puedes usar: --option=clientsmbencrypt=OPTION, --option=clientipcsigning=OPTION, --option=clientsigning=OPTION.

EJEMPLOS

Buscar usando una frase básica:

'wspsearch -Usomeuser%password //server/share --phrase="gatos"'

Buscar usando una consulta similar a AQS para una imagen cuyo nombre comienza con p403 o p404:

'wspsearch -Usomeuser%password //server/share --query="ALL:$<p403 OR ALL:$<p404 AND System.Kind:picture"'
