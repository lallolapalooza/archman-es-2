WESTON(1) Manual de Comandos Generales WESTON(1)

NOMBRE

weston - el servidor Wayland de referencia

SINOPSIS

weston

DESCRIPCIÓN

weston es la implementación de referencia de un servidor Wayland. Un servidor Wayland es un servidor de pantalla, un gestor de ventanas y un compositor, todo en uno. Weston tiene varios backends como módulos cargables: puede ejecutarse en Linux KMS (modo de configuración del kernel a través de DRM), como un cliente X, o dentro de otra instancia de servidor Wayland.

Weston soporta paradigmas de interfaz gráfica de usuario fundamentalmente diferentes a través de plugins de shell. Se proporcionan dos plugins: el shell de escritorio y el shell de quiosco.

Weston también soporta clientes X a través de Xwayland, véase más abajo.

BACKENDS

drm
El backend DRM utiliza KMS de Linux para la salida y dispositivos evdev para la entrada. Soporta múltiples monitores en un escritorio unificado con DPMS. Véase weston-drm(7), si está instalado.
wayland
El backend Wayland se ejecuta en otro servidor Wayland, una instancia diferente de Weston, por ejemplo. Weston aparece como una única ventana de escritorio en el servidor padre.
x11
El backend X11 se ejecuta en un servidor X. Cada salida de Weston se convierte en una ventana X. Esta es una forma económica de probar el soporte multi-monitor de un shell, escritorio o aplicaciones Wayland.
rdp
El backend RDP se ejecuta en memoria sin necesidad de hardware gráfico. El acceso al escritorio se realiza utilizando el protocolo RDP. Cada cliente conectado tiene su propio asiento, lo que lo convierte en una forma económica de probar el soporte multi-asiento. Véase weston-rdp(7), si está instalado.
vnc
El backend VNC se ejecuta en memoria sin necesidad de hardware gráfico. El acceso al escritorio se realiza utilizando el protocolo RFB. Actualmente solo se soporta un cliente conectado. Véase weston-vnc(7), si está instalado.
pipewire
El backend PipeWire se ejecuta en memoria sin necesidad de hardware gráfico y crea un nodo PipeWire para cada salida. Puede usarse para capturar salidas de Weston para procesarlas con otra aplicación.
headless
El backend headless se ejecuta en memoria. Puede usarse para capturar salidas de Weston o para probar aplicaciones cliente.

SHELLS

La interfaz de usuario de Weston se implementa mediante 'plugins' de shell individuales. Se proporcionan varios shells para diferentes casos de uso.

desktop
El shell de escritorio es el modo predeterminado de Weston. Proporciona un ejemplo de un entorno similar a un escritorio, con un panel con lanzadores y un reloj, un fondo de pantalla y un conmutador de tareas interactivo. Aunque no está diseñado para ser un entorno de escritorio completo por sí mismo, es un ejemplo de cómo se puede construir tal entorno.
kiosk
El shell de quiosco está pensado para entornos que desean ejecutar una sola aplicación a la vez. Las aplicaciones se pondrán a pantalla completa y se activarán al iniciarse.
fullscreen
El shell de pantalla completa es una implementación obsoleta de las ideas detrás del shell de quiosco. Requiere soporte específico del cliente para la interfaz zwp_fullscreen_shell_v1.
ivi
El shell IVI es un shell de propósito especial que expone una API compatible con el GENIVI Layer Manager a módulos de control HMI proporcionados por el usuario. Está pensado para su uso en entornos automotrices.

XWAYLAND

Weston puede soportar clientes X11 ejecutándose dentro de una sesión de Weston a través de un servidor X llamado Xwayland. Xwayland se compila como un ejecutable separado, proporcionado por X.Org. Una vez compilado e instalado, puede activarse con la opción --xwayland. Weston escuchará en un nuevo socket de pantalla X11 y lo exportará a través de la variable de entorno DISPLAY.

También tiene su propio gestor de ventanas X donde los temas y tamaños de cursor se pueden elegir utilizando las variables de entorno XCURSOR_PATH y XCURSOR_SIZE. Véase ENTORNO.

OPCIONES

Opciones principales de Weston:

-Bbackend1,backend2, --backend=backend1,backend2
Carga la lista de backends separada por comas en lugar del backend predeterminado, véase BACKENDS. Los módulos backend se buscan en /usr/lib/weston. El backend predeterminado es drm a menos que el entorno sugiera lo contrario, véase DISPLAY y WAYLAND_DISPLAY. El primer backend es el backend principal y proporciona el renderizador. No todos los backends soportan ser cargados como backends secundarios, los cuales reutilizan el renderizador del backend principal.
-cconfig.ini, --config=config.ini
Carga config.ini en lugar de weston.ini. El argumento también puede ser una ruta absoluta que comience con /. Si la ruta no es absoluta, se buscará en las rutas de configuración normales, véase weston.ini(5). Esta opción se ignora si se pasa la opción --no-config.
--debug
Habilita la extensión del protocolo de depuración weston_debug_v1 que cualquier cliente puede utilizar para recibir mensajes de depuración del compositor.

ADVERTENCIA: Esto es arriesgado por dos razones. Primero, un cliente puede causar una denegación de servicio bloqueando el compositor al proporcionar un descriptor de archivo inadecuado, y segundo, los mensajes de depuración pueden exponer información sensible. Además, esto expondrá la interfaz weston-screenshooter, permitiendo al usuario tomar capturas de pantalla de las salidas utilizando la aplicación weston-screenshooter, lo que puede llevar a una filtración silenciosa del contenido de la salida. Esta opción no debe usarse en producción.

-fámbito1,ámbito2, --flight-rec-scopes=ámbito1,ámbito2
Especifica a qué ámbitos deben suscribirse. Útil para controlar qué flujos de datos se escriben en el grabador de vuelo. El grabador de vuelo tiene un espacio limitado; una vez que está lleno, los datos nuevos sobrescribirán los antiguos. Sin ningún ámbito especificado, se suscribe a los ámbitos 'log' y 'drm-backend'. Pasar un valor vacío deshabilitará el grabador de vuelo por completo.
-h, --help
Imprime un resumen de las opciones de línea de comandos y sale.
-iN, --idle-time=N
Establece el tiempo de inactividad en N segundos. El tiempo de inactividad predeterminado es de 300 segundos. Cuando no ha habido ninguna entrada del usuario durante el tiempo de inactividad, Weston entra en modo inactivo. La pantalla se atenúa hasta el negro, los monitores pueden apagarse y el shell puede bloquear la sesión. Un valor de 0 deshabilita efectivamente el tiempo de inactividad.
--log=archivo.log
Añade mensajes de registro al archivo archivo.log en lugar de escribirlos en stderr.
-lámbito1,ámbito2, --logger-scopes=ámbito1,ámbito2
Especifica a qué ámbitos de registro deben suscribirse. Cuando no se proporcionan ámbitos, se suscribe al ámbito de registro "log" por defecto. Útil para controlar a qué flujos de datos se escribe en el registrador y puede ser útil para diagnosticar el código de inicio temprano.
--modules=módulo1.so,módulo2.so
Carga la lista de módulos separada por comas. Solo se utiliza por el conjunto de pruebas. El archivo se busca en /usr/lib/weston, o se puede pasar una ruta absoluta.
--no-config
No leer weston.ini para el compositor. Evita, por ejemplo, cargar módulos del compositor a través del

OPTIONS

--config=filename
Use configuration file filename. By default Weston uses weston.ini located in $XDG_CONFIG_HOME or $HOME/.config. See FILES.
--debug
Enable debugging. This is equivalent to setting the following options:
--debug-assertions
Enable assertions.
--debug-disable-atoms
Disable atoms.
--debug-disable-shm
Disable shared memory.
--debug-no-realloc
Disable realloc.
--debug-no-sleep
Disable sleep.
--debug-quiet
Disable printing client information.
--debug-no-realloc
Disable realloc.
--debug-no-sleep
Disable sleep.
--debug-quiet
Disable printing client information.
--debug-no-libinput
Disable libinput.
--debug-no-setuid
Disable setuid.
This is useful for debugging a crash on start-up when it would be inconvenient to launch weston directly from a debugger. There is also a weston.ini option to do the same.
--developer-mode
Enable developer mode. This is a shortcut for enabling a few configuration options that are useful for development and testing. Currently, this enables the following:
--no-reset-timestamp
Do not reset the timestamp of the last commit.
--no-sleep
Do not sleep.
--no-idle
Do not go idle.
--no-compositor-layout
Do not use the compositor layout.
--no-input-validation
Do not validate input.
--no-output-regression
Do not test output regression.
--no-compositor-regression
Do not test compositor regression.
This is useful for debugging weston, and it is also useful for testing, because it is useful for unit tests.
--log-level=level
Set the log level. Possible values are error, warning, info, debug. Defaults to info.
--no-runtime-config
Do not read the runtime configuration file. This is useful for debugging Weston's behavior under different runtime configurations.
--renderer=renderer
Select which renderer to use for Weston's internal composition. Defaults to automatic selection.
--shell=shell
Select which shell to load to provide Weston's user interface. See ENVIRONMENT.
-Sname, --socket=name
Weston will listen in the Wayland socket called name. Weston will export WAYLAND_DISPLAY with this value in the environment for all child processes to allow them to connect to the right server automatically. --version Print the program version.
--wait-for-debugger
Raises SIGSTOP before initializing the compositor. This allows the user to attach with a debugger and continue execution by sending SIGCONT. This is useful for debugging a crash on start-up when it would be inconvenient to launch weston directly from a debugger. There is also a weston.ini option to do the same.
--xwayland
Support X11 clients through the Xwayland server.

DRM backend options:

See weston-drm(7).

Wayland backend options:

--display=display
Name of the Wayland display to connect to, see also WAYLAND_DISPLAY of the environment.
--fullscreen
Create a single fullscreen output
--output-count=N
Create N Wayland windows to emulate the same number of outputs.
--width=W, --height=H
Make all outputs have a size of WxH pixels.
--scale=N
Give all outputs a scale factor of N.
--use-pixman
Deprecated in favour of the --renderer option. Use the pixman renderer. By default weston will try to use EGL and GLES2 for rendering and will fall back to the pixman-based renderer for software compositing if EGL cannot be used. Passing this option will force weston to use the pixman renderer.

X11 backend options:

--fullscreen
--no-input
Do not provide any input devices. Used for testing input-less Weston.
--output-count=N
Create N X windows to emulate the same number of outputs.
--width=W, --height=H
Make the default size of each X window WxH pixels.
--scale=N
Give all outputs a scale factor of N.
--use-pixman
Deprecated in favour of the --renderer option. Use the pixman renderer. By default weston will try to use EGL and GLES2 for rendering. Passing this option will make weston use the pixman library for software compsiting.

RDP backend options:

See weston-rdp(7).

VNC backend options:

See weston-vnc(7).

headless backend options:

--width=W, --height=H
Make the default size of each output WxH pixels.
--scale=N
Give all outputs a scale factor of N.
--transform=transform
Transform for the output, which can be rotated in 90-degree steps and possibly flipped. Possible values are normal, rotate-90, rotate-180, rotate-270, flipped, flipped-rotate-90, flipped-rotate-180, and flipped-rotate-270.
--no-outputs
Do not create any virtual outputs.
--refresh-rate=N
Give all outputs a refresh rate of N mHz (60,000 mHz by default). Supported values range from 0 mHz to 1,000,000 mHz. 0 is a special value that repaints as soon as possible on capture requests only, not on damages.

FILES

If the environment variable is set, the configuration file is read from the respective path.

$XDG_CONFIG_HOME/weston.ini
$HOME/.config/weston.ini

ENVIRONMENT

DISPLAY
The X display. If DISPLAY is set, and WAYLAND_DISPLAY is not set, the default backend becomes x11.
WAYLAND_DEBUG
If set to any value, causes libwayland to print the live protocol to stderr.
WAYLAND_DISPLAY
The name of the display (socket) of an already running Wayland server, without the path. The directory path is always taken from XDG_RUNTIME_DIR. If WAYLAND_DISPLAY is not set, the socket name is "wayland-0".

If WAYLAND_DISPLAY is already set, the default backend becomes wayland. This allows launching Weston as a nested server.

WAYLAND_SOCKET
For Wayland clients, holds the file descriptor of an open local socket to a Wayland server.
WESTON_CONFIG_FILE
Weston sets this variable to the absolute path of the configuration file it loads, or to the empty string if no file is used. Programs that use weston.ini will read the file specified by this variable instead, or do not read any file if it is empty. Unset variable causes falling back to the default name weston.ini.
XCURSOR_PATH
Set the list of paths to look for cursors in. It changes both libwayland-cursor and libXcursor, so it affects both Wayland and X11 based clients. See xcursor (3).
XCURSOR_SIZE
This variable can be set for choosing an specific size of cursor. Affect Wayland and X11 clients. See xcursor (3).
XDG_CONFIG_HOME
If set, specifies the directory where to look for weston.ini.
XDG_RUNTIME_DIR
The directory for Weston's socket and lock files. Wayland clients will automatically use this.

PROGRAM EXECUTION

It is possible to execute a program that will be run by Weston.

By using this syntax :
weston [options] -- [program [arguments]]

The '--' here is mandatory to execute a program. There are examples in the EXAMPLES section.

Bugs should be reported to https://gitlab.freedesktop.org/wayland/weston/.

EXAMPLES

Launch Weston with the DRM backend on a VT
weston
Launch Weston with the DRM backend and XWayland support
weston --xwayland
Launch Weston (wayland-1) nested in another Weston instance (wayland-0)
WAYLAND_DISPLAY=wayland-0 weston -Swayland-1
From an X terminal, launch Weston with the x11 backend
weston
Launch Weston and make it start weston-terminal
weston -- /usr/local/bin/weston-terminal
Launch Weston with the kiosk shell and make it start weston-simple-egl
weston --shell=kiosk-shell.so -- /usr/local/bin/weston-simple-egl
Launch Weston with the kiosk shell and open a pdf document with mupdf
weston --shell=kiosk-shell.so -- mupdf /home/user/Documents/krh/wayland.pdf

weston(7) - Weston Composite, Wayland Compositor

NAME

weston - Weston Composite, Wayland Compositor

SYNOPSIS

weston [options]

DESCRIPTION

Weston is the reference implementation of a Wayland compositor. A Wayland compositor is a display server that manages screen output, input devices, and Wayland clients. Weston can run as a Wayland client itself, for example in a web browser or in a virtual machine. It also supports other backends like X11 and RDP.

BACKENDS

Weston can be configured to use different backends:

  • libweston: The core library.
  • DRM/KMS: Direct Rendering Manager, Kernel Mode Setting. This is the primary backend for running Weston directly on hardware. It requires a Linux kernel with KMS support and appropriate graphics drivers.
  • X11: Runs Weston as an X11 application. Useful for testing or running Wayland applications within an existing X11 session.
  • Wayland: Runs Weston as a Wayland client, nested inside another Wayland compositor. This is useful for testing or running Weston inside a virtual machine.
  • RDP/VNC: For remote desktop access.

SHELLS

Weston can use different shells to provide a user interface:

  • Desktop shell: A traditional desktop environment with panels, launchers, and windows.
  • Fullscreen shell: A minimal shell for fullscreen applications, often used in embedded systems or kiosks.

XWAYLAND

Weston includes Xwayland, which allows X11 applications to run on a Wayland compositor. This provides backward compatibility for applications that do not yet support Wayland natively.

OPTIONS

Weston supports various command-line options to configure its behavior. Some common options include:

  • --config=FILE: Specify a configuration file.
  • --log-level=LEVEL: Set the logging verbosity (e.g., error, info, debug).
  • --backend=BACKEND: Specify the backend to use (e.g., drm, x11, wayland).
  • --shell=SHELL: Specify the shell to use (e.g., /usr/bin/weston-desktop-shell).
  • --tty=TTY: Specify the TTY to use for the DRM backend.
  • --seat=SEAT: Specify the seat for input/output devices.

Refer to the weston.ini(5) man page for a complete list of configuration options.

FILES

  • /etc/weston.ini: Global configuration file.
  • ~/.config/weston.ini: User-specific configuration file.

ENVIRONMENT

  • WAYLAND_DISPLAY: Specifies the display name for Wayland clients.
  • XDG_RUNTIME_DIR: Specifies the directory for runtime data, including the Wayland socket.

PROGRAM EXECUTION

To start Weston, run the weston command. If running under DRM/KMS, it's typically started from a virtual console (TTY).

Example: weston --tty=/dev/tty1 --backend=drm --shell=/usr/bin/weston-desktop-shell

If running under X11 or Wayland, it can be launched like any other application.

BUGS

Report bugs to the Wayland mailing list or bug tracker.

WWW

More information can be found on the Wayland project website: https://wayland.freedesktop.org/

EXAMPLES

Start Weston with the default configuration:

weston

Start Weston using the X11 backend:

weston --backend=x11
