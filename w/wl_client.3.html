void wl_client_add_destroy_late_listener (struct wl_client * client, struct wl_listener * listener)

Añade un oyente a ser llamado al final de la destrucción de wl_client

El oyente proporcionado será llamado cuando la destrucción de wl_client esté casi completa, después de que todos los recursos de ese cliente hayan sido destruidos.

No hay requisito de eliminar el enlace del wl_listener cuando se emite la señal.

void wl_client_flush (struct wl_client * client)

Envía los eventos pendientes al cliente

Parámetros

client El objeto cliente

Los eventos enviados a los clientes se ponen en cola en un búfer y se escriben en el socket más tarde, típicamente cuando el compositor ha gestionado todas las solicitudes y vuelve a bloquearse en el bucle de eventos. Esta función envía inmediatamente todos los eventos en cola para un cliente.

void wl_client_for_each_resource (struct wl_client * client, wl_client_for_each_resource_iterator_func_t iterator, void * user_data)

Itera sobre todos los recursos de un cliente

Parámetros

client El objeto cliente
iterator La función iteradora
user_data El puntero de datos de usuario

La función apuntada por iterator será llamada para cada recurso propiedad del cliente. El user_data se pasará como segundo argumento de la función iteradora. Si la función iterator devuelve WL_ITERATOR_CONTINUE la iteración continuará, si devuelve WL_ITERATOR_STOP se detendrá.

La creación y destrucción de recursos durante la iteración es segura, pero es posible que los nuevos recursos sean o no recogidos por el iterador.

void wl_client_get_credentials (const struct wl_client * client, pid_t * pid, uid_t * uid, gid_t * gid)

Devuelve las credenciales de Unix para el cliente

Parámetros

client El objeto de visualización
pid Devuelve el ID del proceso
uid Devuelve el ID de usuario
gid Devuelve el ID del grupo

Esta función devuelve el ID del proceso, el ID de usuario y el ID del grupo para el cliente dado. Las credenciales provienen de getsockopt() con SO_PEERCRED, en el fd del socket del cliente. Todos los punteros pueden ser NULL, si el llamante no está interesado en un ID en particular.

Nota: los ID de proceso están sujetos a condiciones de carrera y no son una forma fiable de identificar a un cliente.

Tenga en cuenta que para los clientes que un compositor genera y ejecuta y luego conecta usando socketpair(), esta función devolverá las credenciales del compositor. Las credenciales para el socketpair se establecen en el momento de la creación en el compositor.

int wl_client_get_fd (struct wl_client * client)

Get the file descriptor for the client

Parameters

client The display object

Returns

The file descriptor to use for the connection

This function returns the file descriptor for the given client.

Be sure to use the file descriptor from the client for inspection only. If the caller does anything to the file descriptor that changes its state, it will likely cause problems.

See also wl_client_get_credentials(). It is recommended that you evaluate whether wl_client_get_credentials() can be applied to your use case instead of this function.

If you would like to distinguish just between the client and the compositor itself from the client's request, it can be done by getting the client credentials and by checking the PID of the client and the compositor's PID. Regarding the case in which the socketpair() is being used, you need to be careful. Please note the documentation for wl_client_get_credentials().

This function can be used for a compositor to validate a request from a client if there are additional information provided from the client's file descriptor. For instance, suppose you can get the security contexts from the client's file descriptor. The compositor can validate the client's request with the contexts and make a decision whether it permits or deny it.

void wl_client_set_max_buffer_size (struct wl_client * client, size_t max_buffer_size)

Adjust the maximum size of the client connection buffers

Parameters

client The client object
max_buffer_size The maximum size of the connection buffers

The actual size of the connection buffers is a power of two, the requested max_buffer_size is therefore rounded up to the nearest power of two value.

Lowering the maximum size may not take effect immediately if the current content of the buffer does not fit within the new size limit.

The minimum buffer size is 4096. The default buffers size can be set using wl_display_set_default_max_buffer_size().
