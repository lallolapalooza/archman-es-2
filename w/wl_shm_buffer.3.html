Descripción detallada

Un buffer SHM.

wl_shm_buffer proporciona una ayuda para acceder al contenido de un recurso wl_buffer creado a través de la interfaz wl_shm.

Un wl_shm_buffer se vuelve inválido tan pronto como su wl_resource es destruido.

Documentación de funciones miembro

void wl_shm_buffer_begin_access (struct wl_shm_buffer * buffer)

Marca que el buffer SHM dado va a ser accedido.

Parámetros

buffer El buffer SHM

Un buffer SHM es un archivo mapeado en memoria proporcionado por el cliente. Según POSIX, leer de una región mapeada en memoria que se extiende más allá del final del archivo generará una señal SIGBUS. Normalmente, esto provocaría la terminación del compositor. Para hacer que el compositor sea robusto frente a clientes que cambian el tamaño del archivo subyacente o mienten sobre su tamaño, debes proteger el acceso al buffer llamando a esta función antes de leer de la memoria y llamar a wl_shm_buffer_end_access() después. Esto instalará un manejador de señal para SIGBUS que evitará que el compositor falle.

Después de llamar a esta función, el manejador de señal permanecerá instalado durante la vida útil del proceso del compositor. Ten en cuenta que esta función no funcionará correctamente si el compositor también está instalando su propio manejador para SIGBUS.

Si se recibe una señal SIGBUS para una dirección dentro del rango del pool SHM del buffer dado, se enviará un evento de error al cliente cuando se llame a wl_shm_buffer_end_access(). Si la señal es para una dirección fuera de ese rango, el manejador de señal relanzará la señal, lo que probablemente provocará la terminación del compositor.

Es seguro anidar llamadas a estas funciones siempre que las llamadas anidadas accedan al mismo pool. El número de llamadas a wl_shm_buffer_end_access() debe coincidir con el número de llamadas a wl_shm_buffer_begin_access(). Estas funciones son seguras para hilos y se permite acceder simultáneamente a diferentes buffers o al mismo buffer desde múltiples hilos.

void wl_shm_buffer_end_access (struct wl_shm_buffer * buffer)

Termina el acceso a un buffer iniciado por wl_shm_buffer_begin_access().

Parámetros

buffer El buffer SHM

Esto debe llamarse después de wl_shm_buffer_begin_access() una vez que el buffer ya no esté siendo accedido. Si se generó una señal SIGBUS entre estas dos llamadas, se enviará un error al recurso del buffer dado.

void * wl_shm_buffer_get_data (struct wl_shm_buffer * buffer)

Obtiene un puntero a la memoria del buffer SHM.

Parámetros

buffer El objeto buffer

Devuelve un puntero que se puede usar para leer los datos contenidos en el buffer SHM dado.

Dado que este buffer está mapeado en memoria, leer de él puede generar señales SIGBUS. Esto puede ocurrir si el cliente afirma que el buffer es más grande de lo que es o si algo trunca el archivo subyacente. Para evitar que esta señal provoque que el compositor falle, debes llamar a wl_shm_buffer_begin_access() y wl_shm_buffer_end_access() alrededor del código que lee de la memoria.

struct wl_shm_buffer * wl_shm_buffer_ref (struct wl_shm_buffer * buffer)

Referencia un shm_buffer.

Parámetros

buffer El objeto buffer

Devuelve un puntero al buffer y aumenta el contador de referencias.

El compositor debe recordar llamar a wl_shm_buffer_unref() cuando ya no necesite la referencia para asegurar la destrucción adecuada del buffer.

NAME

wl_shm_buffer - shared memory buffer object

SYNOPSIS

struct wl_shm_buffer

Detailed Description

A wl_shm_buffer is a buffer attached to a wl_surface. It is created from a wl_shm_pool and contains the pixel data for the surface.

The memory layout is defined by the format specified in the wl_shm.format event. The buffer is divided into rows and columns. The stride is the number of bytes from the start of one row to the start of the next. The width is the number of pixels in a row.

A wl_shm_buffer is a global object. The client can get a wl_shm_buffer by creating a wl_buffer using wl_shm.buffer_new.

The wl_shm_buffer object is created from a wl_shm_pool using the wl_shm.buffer_new request. The arguments are the offset within the pool and the width and height of the buffer. The format is inherited from the pool.

The wl_shm_buffer is destroyed using the wl_buffer.destroy request.

The client must unmap the buffer before destroying it.
