WIPE(1) Manual de Comandos Generales WIPE(1)

NOMBRE

wipe - utilidad de borrado seguro de archivos

SINOPSIS

wipe

[-ucwsiIhfFdDnNvVzZrRtTkKaAeE] [-B(count)] [-S(size)] [-C(size)] [-o[size] -O] [-l[0-2]] [-x[1-32] -X] [-p(1-32)] [-b(0-255)] [archivos]

PREDETERMINADO

wipe -ZdNTVEAkO -S512 -C4096 -l1 -x1 -p1

DESCRIPCIÓN

Wipe es una utilidad de borrado seguro de archivos. Hay algunos problemas de bajo nivel que deben tenerse en cuenta. Uno de ellos es que debe haber algún tipo de barrera de escritura entre pasadas. Wipe utiliza fdatasync(2) (o fsync(2)) como barrera de escritura, o si fsync(2) no está disponible, el archivo se abre con el indicador O_DSYNC o O_SYNC. Para que wipe sea efectivo, cada pasada debe estar completamente escrita. Para asegurar esto, la unidad debe admitir algún tipo de barrera de escritura, vaciado de caché de escritura o deshabilitación de caché de escritura. SCSI admite etiquetas de comando ordenadas, tiene un bit de acceso forzado a medios para comandos y la caché de escritura se puede deshabilitar en la página de modo 8. Las unidades IDE/ATA admiten vaciados de caché de escritura y deshabilitación de caché de escritura. Desafortunadamente, no todas las unidades deshabilitan realmente la caché de escritura cuando se les solicita. Esas unidades están defectuosas. La caché de escritura siempre debería estar deshabilitada, a menos que su sistema tenga respaldo de batería y siempre se apague limpiamente.

En Linux, la opción de montaje "mand" debe usarse (ver linux/Documentation/mandatory.txt) para que los bloqueos de archivos obligatorios estén habilitados. Wipe debería hacer que sea extremadamente difícil para todos, excepto para las personas más decididas, recuperar los datos originales en texto plano. Utilidades como PGP y GNU Privacy Guard proporcionan un cifrado sólido, pero el cifrado es inútil si se puede recuperar el texto plano original. Al usar PGP y GPG, los archivos temporales respaldados por disco deben almacenarse en un sistema de archivos cifrado. De esa manera, el texto plano nunca llega a los discos. Wipe está diseñado para situaciones en las que un sistema de archivos cifrado no es práctico.

Wipe utiliza /dev/urandom, o si no está disponible, /dev/random, como fuente de entropía. Se utiliza el PRNG Mersenne Twister para la velocidad. El sitio de MT está en:

http://www.math.keio.ac.jp/~matumoto/emt.html

Para obtener más información sobre el borrado seguro de medios magnéticos y dispositivos de almacenamiento de estado sólido (como DRAM), consulte el artículo de USENIX de Peter Gutmann en:

http://www.cs.auckland.ac.nz/~pgut001/secure_del.html

OPCIONES

-h
Muestra la pantalla de ayuda. Muestra las opciones y lo que hacen.
-u
uso - muestra las opciones
-c
muestra información de derechos de autor
-w
muestra la garantía
-i
interactivo - pregunta si eliminar cada archivo explícitamente verifica los permisos del archivo
-I
deshabilita la interacción
-f
fuerza el borrado de archivos y suprime las advertencias de permisos
-r o -R
recursión - recorre subdirectorios
-s
silencioso - deshabilita el reporte de porcentaje y algunas advertencias
-V
verboso - muestra el porcentaje si el tamaño del archivo está por encima de cierto límite (ver wipe -h)
-v
forzar verboso - siempre muestra el porcentaje
-e y -E
activado (-e) hace que el porcentaje (solo si se muestra) sea más preciso llamando a fdatasync() antes de cada actualización desactivado (-E) será ligeramente menos preciso, pero wipe solo llamará a fdatasync() entre pasadas
-d y -D
eliminar (-d) o mantener (-D) después de borrar
-n y -N
eliminar (-n) o omitir (-N) fifos, sockets, enlaces simbólicos y dispositivos de caracteres
-k y -K
bloquear (-k) o no bloquear (-K) archivos durante el borrado
-z
rellena de ceros el archivo - realiza una única pasada de ceros
-Z
realiza pasadas normales - anula -z
-t y -T
habilitar (-t) o deshabilitar (-T) pasadas estáticas
-a y -A
escribir hasta quedarse sin espacio (-a) o no (-A)
-o y -O
escribir [tamaño] a stdout (-o) o usar archivos (-O)

Dado que wipe no tiene soporte específico para dispositivos de caracteres, como lo tiene para dispositivos de bloque, este es el método preferido para borrarlos, como unidades de cinta; por ejemplo, wipe -za -o | buffer > /dev/nst0 También se puede usar para dispositivos de bloque; por ejemplo, wipe -To | dd count=tamaño of=blkdev

También puedes usar esto para crear archivos que contengan salida pseudoaleatoria del PRNG MT; por ejemplo, wipe -To10240 -x1 > prand

Para pasadas estáticas, debes especificar una longitud de stdout.

-B
anula el recuento de sectores del dispositivo de bloque
-S
anula el tamaño de sector del dispositivo de bloque
-C
tamaño del fragmento - el tamaño máximo del búfer del archivo
-l
establece el nivel de seguridad genérico

nivel 0, el PRNG solo se inicializa una vez

nivel 1, el PRNG se inicializa una vez por archivo

nivel 2, el PRNG se inicializa una vez por pasada aleatoria

-x
habilita pasadas aleatorias y, opcionalmente, cuántas pasadas aleatorias realizar - ten en cuenta que esta opción ahora establece el número de pasadas aleatorias por bucle de borrado - en otras palabras, el número total de pasadas aleatorias será pasadas aleatorias * bucles de borrado (-p)
-X
deshabilita pasadas aleatorias
-p
bucles de pasadas - realiza la secuencia de borrado x veces, incluyendo pasadas aleatorias
-b
byte personalizado - sobrescribe una vez con un byte específico

ARCHIVOS

/dev/urandom
Wipe utiliza este dispositivo de caracteres como fuente de entropía
/dev/random
Wipe recurre a usar este si /dev/urandom no está disponible

DIAGNÓSTICOS

Si ocurre un error, el código de salida será el valor de errno. Un código de salida de 2 indica un uso incorrecto.

BUGS

Wipe no funciona en sistemas de archivos con registro de auditoría (log structured file systems), ni en ningún otro tipo de sistema de archivos o dispositivo de bloque que reasigne sectores al escribir.

Algunos programas son vulnerables a carreras de enlaces simbólicos. Para evitar este problema con wipe, solo borra archivos en directorios que no sean escribibles por usuarios no confiables.

NOTAS

Cintas y otros dispositivos de acceso secuencial

Elige un tamaño de búfer apropiado para que coincida con la lógica o el tamaño de bloque físico del dispositivo. Al usar las pasadas de patrón, debes deshabilitar la compresión en la unidad, y generalmente es mejor hacer lo mismo para otras pasadas.

Para unidades VXA, usé mt-st en Linux para establecer el tamaño de bloque en 0 (variable) y desactivar la compresión, y ejecuto wipe con un tamaño de bloque de 64k, para que coincida con el tamaño de bloque nativo del formato en cinta.

Ejemplo:

mt-st setblk 0

mt-st compression 0

wipe -C64 /dev/st0

wipe(1) - Arch Linux Manual Pages

NOMBRE

wipe - borra de forma segura archivos, particiones o discos completos

SINOPSIS

wipe [OPTION...] FILE...

DESCRIPCIÓN

Borra de forma segura archivos, particiones o discos completos, sobrescribiéndolos con patrones aleatorios o especificados. El objetivo es hacer que los datos sean irrecuperables incluso con hardware o software especializado.

OPCIONES

-d, --devices
Borra dispositivos (discos o particiones).
-i, --interactive
Solicita confirmación antes de cada operación.
-k, --keepzero
No borra el último bloque de datos con ceros.
-q, --quiet
Supresin de mensajes detallados.
-r, --recursive
Borra directorios y su contenido de forma recursiva.
-s, -S, --status, --no-status
Muestra u oculta la barra de progreso.
-v, --verbose
Muestra información detallada sobre la operación.
-h, --help
Muestra un mensaje de ayuda y sale.
-V, --version
Muestra información de la versión y sale.

ARCHIVOS

/dev/urandom: fuente de números aleatorios utilizada por defecto.

DIAGNÓSTICOS

Los mensajes de error se imprimen en la salida de error estándar.

ERRORES

No se han reportado errores conocidos.

NOTAS

El uso de wipe en dispositivos puede provocar la pérdida irrecuperable de datos. Utilice con precaución y asegúrese de haber seleccionado el dispositivo correcto.

La opción -d requiere privilegios de superusuario.
