WG(8) WireGuard WG(8)

NOMBRE

wg - configurar y recuperar la configuración de las interfaces WireGuard

SINOPSIS

wg [ COMANDO ] [ OPCIONES ]... [ ARGUMENTOS ]...

DESCRIPCIÓN

wg es la utilidad de configuración para obtener y establecer la configuración de las interfaces de túnel WireGuard. Las interfaces en sí se pueden agregar y eliminar usando ip-link(8) y sus direcciones IP y tablas de enrutamiento se pueden configurar usando ip-address(8) y ip-route(8). La utilidad wg proporciona una serie de subcomandos para cambiar los aspectos específicos de WireGuard de las interfaces WireGuard.

Si no se especifica ningún COMANDO, el COMANDO predeterminado es show. Los subcomandos que toman una INTERFAZ deben pasar una interfaz WireGuard.

COMANDOS

show { <interfaz> | all | interfaces } [public-key | private-key | listen-port | fwmark | peers | preshared-keys | endpoints | allowed-ips | latest-handshakes | persistent-keepalive | transfer | dump]
Muestra la configuración actual de WireGuard y la información de ejecución de la <interfaz> especificada. Si no se especifica ninguna <interfaz>, la <interfaz> predeterminada es all. Si se especifica interfaces, imprime una lista de todas las interfaces WireGuard, una por línea, y sale. Si no se proporcionan opciones después de la especificación de la interfaz, entonces imprime una lista de todos los atributos de una manera visualmente agradable destinada al terminal. De lo contrario, imprime la información especificada agrupada por saltos de línea y tabulaciones, destinada a ser utilizada en scripts. Para esta visualización amigable para scripts, si se especifica all, entonces el primer campo para todas las categorías de información es el nombre de la interfaz. Si se especifica dump, se imprimen varias líneas; la primera contiene en orden separado por tabulación: clave privada, clave pública, puerto de escucha, marca de firewall. Las líneas subsiguientes se imprimen para cada par y contienen en orden separado por tabulación: clave pública, clave precompartida, punto final, ips permitidas, últimos handshakes, transferencia-rx, transferencia-tx, keepalive persistente.
showconf <interfaz>
Muestra la configuración actual de la <interfaz> en el formato descrito en FORMATO DEL ARCHIVO DE CONFIGURACIÓN a continuación.
set <interfaz> [listen-port <puerto>] [fwmark <marca de firewall>] [private-key <ruta-archivo>] [peer <clave-publica-base64> [remove] [preshared-key <ruta-archivo>] [endpoint <ip>:<puerto>] [persistent-keepalive <intervalo segundos>] [allowed-ips [+|-]<ip1>/<cidr1>[,[+|-]<ip2>/<cidr2>]...] ]...
Establece valores de configuración para la <interfaz> especificada. Se pueden especificar varios peers, y si se proporciona el argumento remove para un par, ese par se elimina, no se configura. Si no se especifica listen-port, o se establece en 0, el puerto se elegirá aleatoriamente cuando la interfaz se active. Tanto private-key como preshared-key deben ser archivos, ya que los argumentos de línea de comandos no se consideran privados en la mayoría de los sistemas, pero si está utilizando bash(1), puede pasar una cadena de forma segura especificando como private-key o preshared-key la expresión: <(echo CADENA_CLAVE_PRIVADA). Si se especifica /dev/null u otro archivo vacío como nombre de archivo para private-key o preshared-key, la clave se elimina del dispositivo. El uso de preshared-key es opcional y puede omitirse; agrega una capa adicional de criptografía de clave simétrica para mezclar en la criptografía de clave pública ya existente, para resistencia post-cuántica. Si se especifica allowed-ips, pero el valor es una cadena vacía, todas las ips permitidas se eliminan del par. Por defecto, allowed-ips reemplaza las ips permitidas de un par. Si se antepone + o - a alguna de las ips, la actualización es incremental; las ips prefijadas con '+' o '' se agregan a las ips permitidas del par si no están presentes, mientras que las ips prefijadas con '-' se eliminan si están presentes. El uso de persistent-keepalive es opcional y está desactivado por defecto; establecerlo en 0 o "off" lo deshabilita. De lo contrario, representa, en segundos, entre 1 y 65535 inclusive, con qué frecuencia enviar un paquete vacío autenticado al par, con el fin de mantener un mapa de estado de firewall o NAT válido persistentemente. Por ejemplo, si la interfaz rara vez envía tráfico, pero en cualquier momento podría recibir tráfico de un par, y está detrás de NAT, la interfaz podría beneficiarse de tener un intervalo de keepalive persistente de 25 segundos; sin embargo, la mayoría de los usuarios no necesitarán esto. El uso de fwmark es opcional y está desactivado por defecto; establecerlo en 0 o "off" lo deshabilita. De lo contrario, es una marca de firewall de 32 bits para paquetes salientes y puede especificarse en hexadecimal anteponiendo "0x".
setconf <interfaz> <nombre-archivo-configuracion>
Establece la configuración actual de la <interfaz> al contenido del <nombre-archivo-configuracion>, que debe estar en el formato descrito en FORMATO DEL ARCHIVO DE CONFIGURACIÓN a continuación.
addconf <interfaz> <nombre-archivo-configuracion>
Agrega el contenido de <nombre-archivo-configuracion>, que debe estar en el formato descrito en FORMATO DEL ARCHIVO DE CONFIGURACIÓN a continuación, a la configuración actual de la <interfaz>.
syncconf <interfaz> <nombre-archivo-configuracion>
Similar a setconf, pero lee primero la configuración existente y solo realiza cambios que son explícitamente diferentes entre el archivo de configuración y la interfaz. Esto es mucho menos eficiente que setconf, pero tiene el beneficio de no interrumpir las sesiones de pares actuales. El contenido de <nombre-archivo-configuracion> debe estar en el formato descrito en FORMATO DEL ARCHIVO DE CONFIGURACIÓN a continuación.
genkey
Genera una clave privada aleatoria en base64 y la imprime en la salida estándar.
genpsk
Genera una clave precompartida aleatoria en base64 y la imprime en la salida estándar.
pubkey
Calcula una clave pública y la imprime en base64 en la salida estándar a partir de una clave privada correspondiente (generada con genkey) dada en base64 en la entrada estándar.

Una clave privada y su clave pública correspondiente pueden generarse a la vez llamando a:
$ umask 077
$ wg genkey | tee private.key | wg pubkey > public.key

help
Muestra el mensaje de uso.

FORMATO DEL ARCHIVO DE CONFIGURACIÓN

El formato del archivo de configuración se basa en INI. Hay dos secciones de nivel superior: Interface y Peer. Se pueden especificar múltiples secciones Peer, pero solo una sección Interface.

La sección Interface puede contener los siguientes campos:

  • PrivateKey — una clave privada en base64 generada por wg genkey. Requerido.
  • ListenPort — un puerto de 16 bits para escuchar. Opcional; si no se especifica, se elige aleatoriamente.
  • FwMark — una marca de firewall de 32 bits para paquetes salientes. Si se establece en 0 o "off", esta opción se deshabilita. Puede especificarse en hexadecimal anteponiendo "0x". Opcional.

Las secciones Peer pueden contener los siguientes campos:

  • PublicKey — una clave pública en base64 calculada por wg pubkey a partir de una clave privada, y generalmente transmitida fuera de banda al autor del archivo de configuración. Requerido.
  • PresharedKey — una clave precompartida en base64 generada por wg genpsk. Opcional y puede omitirse. Esta opción agrega una capa adicional de criptografía de clave simétrica para mezclar en la criptografía de clave pública ya existente.

wg(8) — Arch manual pages

NAME

wg ― local key generation, peer configuration, and tunneling

SYNOPSIS

wg [OPTION...] [COMMAND]

wg show [interface] [peer public-key]

wg set interface [private-key] [listen-port]

wg set interface peer public-key [[private-key]] [endpoint] [persistent-keepalive] [allowed-ips...]

wg setconf interface conf-file

wg getconf interface

wg set-config-from-file interface config-file

wg addpeer interface public-key

wg removepeer interface public-key

wg genkey

wg pubkey

wg mutations interface

wg country country-code [interface]

DESCRIPTION

The wg utility is used to control and manage WireGuard secure network tunnels. It allows for key generation, configuration of interfaces and peers, and inspection of tunnel state.

COMMANDS

show [interface] [peer public-key]
Displays information about the current WireGuard interfaces and their peers. If an interface is specified, only that interface's information is shown. If a peer public key is also specified, only information about that specific peer is shown.
set interface [private-key] [listen-port]
Sets the private key and listen port for the specified interface. The private key should be an unencrypted base64 string. The listen port must be between 1 and 65535 inclusive.
set interface peer public-key [[private-key]] [endpoint] [persistent-keepalive] [allowed-ips...]
Adds or modifies a peer for the specified interface. The public-key is the base64 encoded public key of the peer. The optional private-key is the preshared key for the peer, if one is used. The optional endpoint is the IP address and port of the peer. The optional persistent-keepalive is an interval in seconds. The allowed-ips is a comma-separated list of IP addresses with CIDR masks for which this peer is responsible. See CONFIGURATION FILE FORMAT below for details.
setconf interface conf-file
Applies the configuration from the specified file to the WireGuard interface. The configuration file uses the format described in CONFIGURATION FILE FORMAT.
getconf interface
Prints the current configuration of the specified WireGuard interface to standard output in the format described in CONFIGURATION FILE FORMAT.
set-config-from-file interface config-file
This command is an alias for setconf.
addpeer interface public-key
Adds a new peer to the specified interface, identified by its public key. Further configuration for this peer needs to be done using wg set.
removepeer interface public-key
Removes the specified peer from the WireGuard interface.
genkey
Generates a new private key and prints it to standard output. This key can then be used as the private key for an interface or a preshared key for a peer.
pubkey
Reads a private key from standard input and prints the corresponding public key to standard output.
mutations interface
Prints information about the number of times cryptographic mutations have occurred on the interface. This can be useful for detecting potential issues with key exchange or configuration.
country country-code [interface]
Sets the country code for the specified interface. This can be used to automatically configure the interface with appropriate settings for a given country, such as disabling certain features or setting specific ports. If no interface is specified, the setting applies to all WireGuard interfaces.

CONFIGURATION FILE FORMAT

WireGuard configuration files follow an INI-like format. Each section represents a part of the configuration, typically an interface or a peer. The following keys are recognized:

  • [Interface] section:

PrivateKey
The private key for this interface. This key must be kept secret. It is used to derive the public key. A base64 encoded key must be provided.
ListenPort
The UDP port on which the interface will listen for incoming connections. If not specified, the interface will not listen for incoming connections. A port number between 1 and 65535 inclusive must be provided.
PublicKey
The public key of the interface. This is derived from the PrivateKey and is used for identifying the interface to other peers. This field is optional, as the public key can be generated from the private key.
DNS
A comma-separated list of DNS servers to be used when this interface is active. These DNS servers will be queried for name resolution for traffic routed through this interface. This is particularly useful when using wg-quick with specific routing rules.

  • [Peer] section:

PublicKey
The public key of the peer. This is a required field for any peer configuration. A base64 encoded key must be provided.
PresharedKey
An optional preshared key for added security. This key must be generated separately using wg genkey and shared securely between the peers. A base64 encoded key must be provided.
AllowedIPs
A comma-separated list of IP (v4 or v6) addresses with CIDR masks from which incoming traffic for this peer is allowed and to which outgoing traffic for this peer is directed. The catch-all 0.0.0.0/0 may be specified for matching all IPv4 addresses, and ::/0 may be specified for matching all IPv6 addresses. May be specified multiple times.
Endpoint
An endpoint IP or hostname, followed by a colon, and then a port number. This endpoint will be updated automatically to the most recent source IP address and port of correctly authenticated packets from the peer. Optional.
PersistentKeepalive
A seconds interval, between 1 and 65535 inclusive, of how often to send an authenticated empty packet to the peer for the purpose of keeping a stateful firewall or NAT mapping valid persistently. For example, if the interface very rarely sends traffic, but it might at anytime receive traffic from a peer, and it is behind NAT, the interface might benefit from having a persistent keepalive interval of 25 seconds. If set to 0 or "off", this option is disabled. By default or when unspecified, this option is off. Most users will not need this. Optional. Post-quantum resistance is enabled by default when using WireGuard versions that support it.

CONFIGURATION FILE FORMAT EXAMPLE

This example may be used as a model for writing configuration files, following an INI-like syntax. Characters after and including a '#' are considered comments and are thus ignored.


[Interface]
PrivateKey = yAnz5TF+lXXJte14tji3zlMNq+hd2rYUIgJBgB3fBmk=
ListenPort = 51820


[Peer]
PublicKey = xTIBA5rboUvnH4htodjb6e697QjLERt1NAB4mZqp8Dg=
Endpoint = 192.95.5.67:1234
AllowedIPs = 10.192.122.3/32, 10.192.124.1/24


[Peer]
PublicKey = TrMvSoP4jYQlY6RIzBgbssQqY3vxI2Pi+y71lOWWXX0=
Endpoint = [2607:5300:60:6b0::c05f:543]:2468
AllowedIPs = 10.192.122.4/32, 192.168.0.0/16


[Peer]
PublicKey = gN65BkIKy1eCE9pP1wdc8ROUtkHLF2PfAqYdyYBz6EA=
Endpoint = test.wireguard.com:18981
AllowedIPs = 10.10.10.230/32

DEBUGGING INFORMATION

Sometimes it is useful to have information on the current runtime state of a tunnel. When using the Linux kernel module on a kernel that supports dynamic debugging, debugging information can be written into dmesg(1) by running as root:

# modprobe wireguard && echo module wireguard +p > /sys/kernel/debug/dynamic_debug/control

On OpenBSD and FreeBSD, debugging information can be written into dmesg(1) on a per-interface basis by using ifconfig(1):

# ifconfig wg0 debug

On userspace implementations, it is customary to set the LOG_LEVEL environment variable to verbose.

ENVIRONMENT VARIABLES

WG_COLOR_MODE
If set to always, always print ANSI colorized output. If set to never, never print ANSI colorized output. If set to auto, something invalid, or unset, then print ANSI colorized output only when writing to a TTY.
WG_HIDE_KEYS
If set to never, then the pretty-printing show sub-command will show private and preshared keys in the output. If set to always, something invalid, or unset, then private and preshared keys will be printed as "(hidden)".
WG_ENDPOINT_RESOLUTION_RETRIES
If set to an integer or to infinity, DNS resolution for each peer's endpoint will be retried that many times for non-permanent errors, with an increasing delay between retries. If unset, the default is 15 retries.
