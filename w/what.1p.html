WHAT(1P) Manual del programador POSIX WHAT(1P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

what — identificar archivos SCCS (DESARROLLO)

SINOPSIS

what [-s] archivo...

DESCRIPCIÓN

La utilidad what buscará en los archivos dados todas las ocurrencias del patrón que get (ver get) sustituye por la palabra clave %Z% ("@(#)") y escribirá en la salida estándar lo que sigue hasta la primera ocurrencia de uno de los siguientes:

"   >   nueva línea   \   NULO

OPCIONES

La utilidad what cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidad.

Se admitirá la siguiente opción:

-s
Detenerse después de encontrar la primera ocurrencia del patrón en cada archivo.

OPERANDOS

Se admitirán los siguientes operandos:

archivo
Una ruta de acceso a un archivo para buscar.

ENTRADA ESTÁNDAR

No se utiliza.

ARCHIVOS DE ENTRADA

Los archivos de entrada serán de cualquier tipo de archivo.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de what:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determinar la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

La salida estándar consistirá en lo siguiente para cada operando de archivo:

"%s:\n\t%s\n", <ruta_acceso>, <cadena_identificación>

ERROR ESTÁNDAR

El error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

0
Se encontraron coincidencias.
1
En caso contrario.

CONSECUENCIAS DE LOS ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO POR PARTE DE LA APLICACIÓN

La utilidad what está pensada para usarse junto con el comando SCCS get, que inserta automáticamente información de identificación, pero también se puede utilizar donde la información se inserta por cualquier otro medio.

Cuando la cadena "@(#)" se incluye en una rutina de biblioteca en una biblioteca compartida, es posible que no se encuentre en un archivo a.out que utilice esa rutina de biblioteca.

EJEMPLOS

Si el programa en lenguaje C en el archivo f.c contiene:

char ident[] = "@(#)información de identificación";

y f.c se compila para producir f.o y a.out, entonces el comando:

what f.c f.o a.out

escribe:

f.c:
    información de identificación
    ...
f.o:
    información de identificación
    ...
a.out:
    información de identificación
    ...
