WSLAY_EVENT_CONTEXT_SERVER_INIT(3) wslay WSLAY_EVENT_CONTEXT_SERVER_INIT(3)

NOMBRE

wslay_event_context_server_init - Inicializa un contexto de API basado en eventos

SINOPSIS

#include <wslay/wslay.h>

int wslay_event_context_server_init(wslay_event_context_ptr *ctx, const struct wslay_event_callbacks *callbacks, void *user_data)
int wslay_event_context_client_init(wslay_event_context_ptr *ctx, const struct wslay_event_callbacks *callbacks, void *user_data)
void wslay_event_context_free(wslay_event_context_ptr ctx)

DESCRIPCIÓN

La función wslay_event_context_server_init() inicializa un contexto de API basado en eventos para uso de servidor WebSocket. La función wslay_event_context_client_init() inicializa un contexto de API basado en eventos para uso de cliente WebSocket. Si se ejecutan correctamente, ctx apuntará a una estructura que contiene todos los recursos necesarios para procesar transferencias de protocolo WebSocket.

callbacks es un puntero a struct wslay_event_callbacks, que se define de la siguiente manera:

struct wslay_event_callbacks {
    wslay_event_recv_callback                recv_callback;
    wslay_event_send_callback                send_callback;
    wslay_event_genmask_callback             genmask_callback;
    wslay_event_on_frame_recv_start_callback on_frame_recv_start_callback;
    wslay_event_on_frame_recv_chunk_callback on_frame_recv_chunk_callback;
    wslay_event_on_frame_recv_end_callback   on_frame_recv_end_callback;
    wslay_event_on_msg_recv_callback         on_msg_recv_callback;
};

recv_callback

typedef ssize_t (*wslay_event_recv_callback)(wslay_event_context_ptr ctx, uint8_t *buf, size_t len, int flags, void *user_data)

recv_callback es invocado por wslay_event_recv() cuando quiere recibir más datos del par. La implementación de esta función de callback debe leer datos de hasta len bytes del par y almacenarlos en buf, y devolver el número de bytes leídos. flags es siempre 0 en esta versión.

Si hay un error, devuelva -1 y establezca el código de error WSLAY_ERR_CALLBACK_FAILURE usando wslay_event_set_error(). La API basada en eventos de Wslay en general asume E/S no bloqueante. Si la causa del error es EAGAIN o EWOULDBLOCK, establezca WSLAY_ERR_WOULDBLOCK en su lugar. Esto es importante porque le indica a wslay_event_recv() que deje de recibir más datos y retorne.

send_callback

typedef ssize_t (*wslay_event_send_callback)(wslay_event_context_ptr ctx, const uint8_t *data, size_t len, int flags, void *user_data)

send_callback es invocado por wslay_event_send() cuando quiere enviar más datos al par. La implementación de esta función de callback debe enviar datos de hasta len bytes al par y devolver el número de bytes enviados. flags es el OR a nivel de bits de cero o más de las siguientes banderas:

WSLAY_MSG_MORE
Hay más datos para enviar

Proporciona algunas pistas para ajustar el rendimiento y el comportamiento.

Si hay un error, devuelva -1 y establezca el código de error WSLAY_ERR_CALLBACK_FAILURE usando wslay_event_set_error(). La API basada en eventos de Wslay en general asume E/S no bloqueante. Si la causa del error es EAGAIN o EWOULDBLOCK, establezca WSLAY_ERR_WOULDBLOCK en su lugar. Esto es importante porque le indica a wslay_event_send() que deje de enviar datos y retorne.

genmask_callback

typedef int (*wslay_event_genmask_callback)(wslay_event_context_ptr ctx, uint8_t *buf, size_t len, void *user_data)

genmask_callback es invocado por wslay_event_send() cuando quiere una nueva clave de enmascaramiento. Como se describe en RFC6455, solo el tráfico del cliente WebSocket está enmascarado, por lo que esta función de callback solo es necesaria si se inicializa una API basada en eventos para uso de cliente WebSocket. La implementación de esta función de callback debe llenar exactamente len bytes de datos en buf y devolver 0 si tiene éxito. Si hay un error, devuelva -1 y establezca el código de error WSLAY_ERR_CALLBACK_FAILURE usando wslay_event_set_error().

on_frame_recv_start_callback

typedef void (*wslay_event_on_frame_recv_start_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_frame_recv_start_arg *arg, void *user_data)

on_frame_recv_start_callback es invocado por wslay_event_recv() cuando un nuevo frame comienza a ser recibido. Esta función de callback solo se invoca una vez por frame. struct wslay_event_on_frame_recv_start_arg se define de la siguiente manera:

struct wslay_event_on_frame_recv_start_arg {
    uint8_t  fin;
    uint8_t  rsv;
    uint8_t  opcode;
    uint64_t payload_length;
};

fin, rsv y opcode son el bit fin, los bits reservados y el opcode de un frame. payload_length es la longitud de la carga útil de un frame.

on_frame_recv_chunk_callback

typedef void (*wslay_event_on_frame_recv_chunk_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_frame_recv_chunk_arg *arg, void *user_data)

on_frame_recv_chunk_callback es invocado por wslay_event_recv() cuando se recibe un fragmento de la carga útil del frame. struct wslay_event_on_frame_recv_chunk_arg se define de la siguiente manera:

struct wslay_event_on_frame_recv_chunk_arg {
    const uint8_t *data;
    size_t         data_length;
};

data apunta a un fragmento de datos de la carga útil. data_length es la longitud del fragmento.

on_frame_recv_end_callback

typedef void (*wslay_event_on_frame_recv_end_callback)(wslay_event_context_ptr ctx, void *user_data)

on_frame_recv_end_callback es invocado por wslay_event_recv() cuando un frame se ha recibido completamente.

on_msg_recv_callback

typedef void (*wslay_event_on_msg_recv_callback)(wslay_event_context_ptr ctx, const struct wslay_event_on_msg_recv_arg *arg, void *user_data)

on_msg_recv_callback es invocado por wslay_event_recv() cuando un mensaje se ha recibido completamente. struct wslay_event_on_msg_recv_arg se define de la siguiente manera:

    uint8_t        rsv;
    uint8_t        opcode;
    const uint8_t *msg;
    size_t         msg_length;
    uint16_t       status_code;
};

NAME

wslay_event_context_server_init, wslay_event_context_client_init — initialize event-based API context

SYNOPSIS

#include <wslay/event.h>

int
wslay_event_context_server_init(
    struct wslay_event_context **ctx,
    const struct wslay_event_callbacks *callbacks,
    void *user_data);

int
wslay_event_context_client_init(
    struct wslay_event_context **ctx,
    const struct wslay_event_callbacks *callbacks,
    void *user_data);

DESCRIPTION

The event-based API is suitable for applications which uses event loop like libev or libevent. The application must initialize one event-based API context for each WebSocket connection.

wslay_event_context_server_init() and wslay_event_context_client_init() initialize the event-based API context pointed by ctx.

The callbacks parameter is a pointer to struct wslay_event_callbacks structure, which contains function pointers for the callbacks. The callbacks are:

struct wslay_event_callbacks {
    int (*on_open_reply)(wslay_event_context_t ctx, const uint8_t *subprot,
        size_t subprot_len, void *user_data);
    int (*on_message)(wslay_event_context_t ctx, const struct wslay_message *msg,
        void *user_data);
    int (*on_close)(wslay_event_context_t ctx, struct wslay_message *msg,
        void *user_data);
    int (*on_request)(wslay_event_context_t ctx, const char *version,
        const char *path, const char *host, uint16_t port, void *user_data);
    int (*on_subprotocol)(wslay_event_context_t ctx, const char **token,
        size_t *n_tokens, const char *chosen_subprotocol, void *user_data);
    int (*on_ping)(wslay_event_context_t ctx, const uint8_t *payload,
        size_t payload_len, void *user_data);
    int (*on_pong)(wslay_event_context_t ctx, const uint8_t *payload,
        size_t payload_len, void *user_data);
};

The callback functions are called when an event occurs. on_open_reply is called when server received connection open reply from client. on_message is called when server received a message from client. on_close is called when server received close frame from client. on_request is called when server received HTTP request. on_subprotocol is called when server received subprotocol negotiation request from client. on_ping is called when server received PING frame. on_pong is called when server received PONG frame.

If a callback function returns a negative value, the connection is terminated.

The struct wslay_message structure is defined as follows:

struct wslay_message {
    uint8_t opcode;
    int fin;
    uint8_t *msg;
    size_t msg_length;
    uint8_t rsv;
    uint16_t status_code;
};

The opcode member is the opcode of the received message. The fin member is 1 if the FIN bit is set, and 0 otherwise. The rsv member is the reserved bits of the received message.

The rsv member is constructed as follows:

rsv = (RSV1 << 2) | (RSV2 << 1) | RSV3

The msg member points to the message of the received message. The msg_length member is the length of message. If a message is close control frame, in other words, opcode == WSLAY_CONNECTION_CLOSE, status_code is set to the status code in the close control frame. If no status code is included in the close control frame, status_code set to 0.

user_data is an arbitrary pointer, which is directly passed to each callback functions as user_data argument.

When initialized event-based API context ctx is no longer used, use wslay_event_context_free() to free any resources allocated for ctx.

RETURN VALUE

wslay_event_context_server_init() and wslay_event_context_client_init() returns 0 if it succeeds, or one of the following negative error codes:

WSLAY_ERR_NOMEM
Out of memory.
