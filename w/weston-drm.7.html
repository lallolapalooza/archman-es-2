NOMBRE

weston-drm - el backend DRM para Weston

SINOPSIS

weston --backend=drm

DESCRIPCIÓN

El backend DRM es el backend nativo de Weston para sistemas que soportan el DRM del kernel de Linux, la configuración del modo del kernel (KMS) y los dispositivos de entrada evdev. Es el backend recomendado para PCs de escritorio y tiene como objetivo proporcionar la experiencia completa de Wayland con el concepto de "cada fotograma es perfecto". También depende de la interfaz GBM de Mesa.

Con el backend DRM, weston se ejecuta sin ningún sistema de ventanas subyacente. El backend utiliza la API KMS de Linux para detectar los monitores conectados. Se soporta la conexión/desconexión en caliente de monitores. Los dispositivos de entrada son encontrados automáticamente por udev(7). La composición ocurre principalmente en GL ES 2, inicializado a través de EGL. También es posible aprovechar los cursores y superposiciones de hardware, cuando existen y son funcionales. Las superficies a pantalla completa se escanearán directamente sin composición, cuando sea posible. Los clientes acelerados por hardware son soportados a través de EGL.

El backend elige primero el dispositivo gráfico DRM basado en el identificador de asiento (seat id). Si los identificadores de asiento no están configurados, busca el dispositivo gráfico que se usó al arrancar. Si no se encuentra, finalmente elige el primer dispositivo DRM devuelto por udev(7). La combinación de múltiples dispositivos gráficos aún no está soportada.

El backend DRM también soporta salidas virtuales que se transmiten a través de una sesión RTP como una serie de imágenes JPEG (tipo de carga útil RTP 26) a un cliente remoto. Las salidas virtuales se configuran en la sección remote-output de weston.ini.

CONFIGURACIÓN

El backend DRM utiliza las siguientes entradas de weston.ini.

Sección core

gbm-format=formato
Establece el formato de píxeles predeterminado para los fotogramas DRM KMS. Formato puede ser xrgb8888, xrgb2101010, rgb565 u otros. Weston reconoce los nombres de la mayoría de los formatos de píxeles definidos por el subsistema DRM del kernel en el archivo de cabecera drm_fourcc.h sin el prefijo DRM_FORMAT_. Los formatos de píxeles realmente soportados dependen del controlador DRM y del hardware, y del renderizador utilizado. Usando el renderizador Pixman, el backend DRM soporta xrgb8888, xrgb2101010, rgb565 y algunas de sus permutaciones. Los formatos soportados con el renderizador GL dependen de las implementaciones de EGL y OpenGL ES 2 o 3. Los nombres no distinguen mayúsculas de minúsculas. Esta configuración se aplica solo a las salidas en modo SDR, ver eotf-mode en weston.ini(5). Si la plataforma de hardware soporta planos de hardware colocados debajo del tipo de plano principal DRM (underlays), se necesitaría especificar argb8888 para que Weston muestre contenido elevado a dichos planos de hardware. Si no se especifica, se utiliza xrgb8888. Ver también gbm-format en la sección output.
pageflip-timeout=milisegundos
establece el tiempo de espera de pageflip de Weston en milisegundos. Esto configura un temporizador para salir elegantemente con un mensaje de log y un código de salida de 1 en caso de que el controlador DRM no responda. Establecerlo a 0 deshabilita esta función.

Sección output

name=conector
El nombre del conector KMS que identifica la salida, por ejemplo LVDS1.
mode=modo
Especifica el modo de video para la salida. El argumento modo puede ser una de las palabras off para apagar la salida, preferred para usar el modo de video preferido del monitor, o current para usar el modo de video actual y evitar un cambio de modo. También puede ser una resolución como:
mode=anchoxalto
mode=anchoxalto@frecuencia_refresco
Especifica un modo con una frecuencia de refresco dada medida en Hz.
mode=anchoxalto@frecuencia_refresco relación_aspecto
Aquí relación_aspecto es la Relación de Aspecto de Imagen que puede tener valores como 4:3, 16:9, 64:27, y 256:135. Este formato de resolución ayuda a seleccionar un modo CEA, si existe tal modo de video en la lista de modos de la salida.

CEA define la temporización de un modo de video, que se considera un estándar para la especificación HDMI y las pruebas de cumplimiento. Define cada parámetro de un modo de video, como hactive, vactive, vfront, vback, etc., incluida la información de la relación de aspecto. Para los modos CEA, la capa DRM almacena esta información de relación de aspecto en bits de bandera (drmModeModeInfo) 19-22 en modo de usuario. Para los modos no CEA, se almacena un valor de 0 en los bits de bandera de relación de aspecto.

Cada modo CEA se identifica por un Código de Identificación de Video (VIC) único. Por ejemplo, VIC=4 es 1280x720@60 relación de aspecto 16:9. Este modo será diferente de un modo no CEA 1280x720@60 0:0. Cuando se aplica el modo de video 1280x720@60 0:0, dado que su temporización no coincide exactamente con la información CEA para VIC=4, se tratará como un modo no CEA. Además, al configurar el HDMI-AVI-Inforframe, el parámetro VIC se establecerá como '0'. Si se aplica el modo de video 1280x720@60 16:9, su temporización CEA coincide con la del modo de video con VIC=4, por lo que el parámetro VIC en el HDMI-AVI-Infoframe se establecerá en 4.

Muchas veces, una salida puede tener modos CEA y no CEA, que son similares en todos los aspectos, difiriendo solo en la relación de aspecto. Un usuario puede seleccionar un modo CEA proporcionando la relación de aspecto, junto con los otros argumentos para el modo. Al omitir la relación de aspecto, el usuario puede especificar los modos no CEA. Esto es útil cuando se realizan pruebas de certificación, en pruebas como 7-27, el analizador HDMI aplica un modo CEA particular y espera que el modo aplicado sea exactamente con la misma temporización, incluida la relación de aspecto y el campo VIC.

La resolución también puede ser una línea de modo detallada como la siguiente.

mode=dotclock hdisp hsyncstart hsyncend htotal vdisp vsyncstart vsyncend vtotal hflag vflag
Usa la línea de modo detallada dada como el modo de video para esta salida. La definición es la misma que en xorg.conf(5), y cvt(1) puede generar líneas de modo detalladas.
transform=transformación
Transformación para la salida, que puede rotarse en pasos de 90 grados y posiblemente voltearse. Los valores posibles son normal, rotate-90, rotate-180, rotate-270, flipped, flipped-rotate-90, flipped-rotate-180 y flipped-rotate-270.
gbm-format=formato
Establece el formato del fotograma DRM KMS para esta salida específica. Si no se establece, se utiliza el valor de la opción gbm-format en la sección core para las salidas en modo SDR y xrgb2101010 para otros modos. Para los valores posibles de formato ver la opción gbm-format en la sección core. Para el modo SDR, ver eotf-mode en weston.ini(7).
pixman-shadow=booleano
Si se utiliza el renderizador Pixman, utiliza fotogramas en sombra. Por defecto es true.
clone-of=nombre
Convierte esta salida (conector) en un clon de otra. El argumento nombre es el valor name de otra sección de salida. La sección de salida referenciada debe existir. Cuando esta clave está presente en una sección de salida, todas las demás claves no tienen efecto en la configuración.
force-on=true
Fuerza la habilitación de la salida incluso si el conector está desconectado. Por defecto es false. Ten en cuenta que mode=off anulará force-on=true. Cuando un conector está desconectado, no hay información EDID para proporcionar una lista de modos de video. Por lo tanto, una salida forzada también debería tener especificada una línea de modo detallada.
max-bpc=N

NAME

weston-drm - Weston DRM backend configuration

SYNOPSIS

The DRM backend configuration file is typically located at /etc/ Weston/drm-backend.conf. This file is read by the Weston compositor when the DRM backend is loaded.

DESCRIPTION

This file allows you to configure the DRM backend used by Weston. The configuration is divided into several sections, each controlling a specific aspect of the DRM backend's behavior.

Section kms

max bpc=N
Establece la propiedad KMS "max bpc" al valor N, ajustado silenciosamente al rango admitido por el controlador de hardware. Esto limita artificialmente los bits por canal (link bits-per-channel) seleccionados por el controlador, lo que puede ser útil para solucionar limitaciones del hardware del receptor (por ejemplo, monitor). El valor predeterminado es 16, lo que es prácticamente ilimitado. Si necesita solucionar problemas de hardware, pruebe con un valor inferior como 8. Un valor de 0 significa que el max bpc actual se reprogramará.

Section remote-output

name=name
Especifica un nombre único para la salida.
mode=mode
Especifica el modo de video para la salida. El argumento mode es una configuración de resolución, como:
mode=widthxheight
mode=widthxheight@refresh_rate
Si no se especifica la tasa de refresco (refresh_rate), se usará por defecto 60Hz.
host=host
Especifica el nombre de host o la dirección IP a la que se transmitirá la salida remota.
port=port
Especifica el número de puerto al que se transmitirá la salida remota. El rango de puertos utilizable es 1-65533.
gst-pipeline=pipeline
Especifica la tubería de gstreamer. Es necesario que la fuente sea appsrc, su nombre sea "src", y el nombre del receptor (sink) sea "sink" en la pipeline. Ignora la configuración de puerto y host si se especifica la gst-pipeline.

OPTIONS

Cuando se carga el backend DRM, weston entenderá las siguientes opciones de línea de comandos adicionales.

--current-mode
Por defecto, utiliza el modo de video actual de todas las salidas, en lugar de cambiar al modo preferido del monitor.
--drm-device=cardN
Utiliza el dispositivo DRM cardN para renderizado y salida en lugar de la heurística predeterminada basada en la asignación de asientos y el estado de la VGA de arranque. Por ejemplo, usa card0.
--additional-devices=cardN
Lista separada por comas de dispositivos DRM secundarios cardM,cardN que solo se utilizarán como salidas, pero no para renderizado. Por ejemplo, usa card1,card2.
--seat=seatid
Utiliza los dispositivos gráficos y de entrada designados para el asiento seatid en lugar del asiento definido en la variable de entorno XDG_SEAT. Si no se especifica ninguno, se asumirá seat0.
--continue-without-input
Permite que Weston se inicie sin dispositivos de entrada. Se utiliza con fines de prueba.

ENVIRONMENT

WESTON_LIBINPUT_LOG_PRIORITY
El nivel mínimo de verbosidad de libinput que se imprimirá en el registro de Weston. Los valores válidos son debug, info y error. El valor predeterminado es info.
XDG_SEAT
El asiento en el que se iniciará Weston, a menos que se anule en la línea de comandos.
