NOMBRE

winbindd - Demonio del Name Service Switch para resolver nombres de servidores NT

SINOPSIS

winbindd [-D|--daemon] [-i|--interactive] [-F|--foreground] [--no-process-group] [-n|--no-caching] [-d <nivel de depuración>] [--debug-stdout] [--configfile=<archivo de configuración>] [--option=<nombre>=<valor>] [-l|--log-basename <directorio de registros>] [--leak-report] [--leak-report-full] [-V|--version]

DESCRIPCIÓN

Este programa forma parte del conjunto samba(7).

winbindd es un demonio que proporciona una serie de servicios a la capacidad Name Service Switch presente en la mayoría de las bibliotecas C modernas, a aplicaciones arbitrarias a través de PAM y ntlm_auth, y al propio Samba.

Incluso si winbind no se utiliza para nsswitch, todavía proporciona un servicio a smbd, ntlm_auth y al módulo PAM pam_winbind.so, gestionando conexiones a los controladores de dominio. En esta configuración, el parámetro idmap config * : range no es necesario. (Esto se conoce como 'modo solo proxy netlogon'.)

El Name Service Switch permite obtener información de usuarios y sistemas de diferentes servicios de bases de datos como NIS o DNS. El comportamiento exacto se puede configurar a través del archivo /etc/nsswitch.conf. Los usuarios y grupos se asignan a medida que se resuelven a un rango de IDs de usuario y grupo especificado por el administrador del sistema Samba.

El servicio proporcionado por winbindd se llama 'winbind' y se puede utilizar para resolver información de usuarios y grupos de un servidor Windows NT. El servicio también puede proporcionar servicios de autenticación a través de un módulo PAM asociado.

El módulo pam_winbind soporta los tipos de módulo auth, account y password. Cabe señalar que el módulo account simplemente realiza un getpwnam() para verificar que el sistema puede obtener un uid para el usuario, ya que el controlador de dominio ya ha realizado el control de acceso. Si la biblioteca libnss_winbind se ha instalado correctamente, o se ha configurado una fuente alternativa de nombres, esto siempre debería tener éxito.

Las siguientes bases de datos de nsswitch son implementadas por el servicio winbindd:

hosts

Esta característica solo está disponible en IRIX. Información de usuario tradicionalmente almacenada en el archivo hosts(5) y utilizada por las funciones gethostbyname(3). Los nombres se resuelven a través del servidor WINS o por difusión.

passwd

Información de usuario tradicionalmente almacenada en el archivo passwd(5) y utilizada por las funciones getpwent(3).

group

Información de grupo tradicionalmente almacenada en el archivo group(5) y utilizada por las funciones getgrent(3).

Por ejemplo, la siguiente configuración simple en el archivo /etc/nsswitch.conf se puede utilizar para resolver inicialmente la información de usuarios y grupos de /etc/passwd y /etc/group y luego del servidor Windows NT.

passwd:         files winbind
group:          files winbind
## solo disponible en IRIX: usa winbind para resolver hosts:
# hosts:        files dns winbind
## Todos los demás sistemas habilitados para NSS deberían usar libnss_wins.so de esta manera:
hosts:          files dns wins

La siguiente configuración simple en el archivo /etc/nsswitch.conf se puede utilizar para resolver inicialmente los nombres de host de /etc/hosts y luego del servidor WINS.

hosts:		files wins

OPCIONES

-D|--daemon

Si se especifica, este parámetro hace que el servidor opere como un demonio. Es decir, se desvincula y se ejecuta en segundo plano en el puerto apropiado. Esta opción se asume si winbindd se ejecuta en la línea de comandos de una shell.

-i|--interactive

Indica a winbindd que no se convierta en un demonio y que no se desvincule de la terminal actual. Esta opción es utilizada por los desarrolladores cuando se requiere la depuración interactiva de winbindd. winbindd también registra en la salida estándar, como si se hubiera dado el parámetro -S.

-F|--foreground

Si se especifica, este parámetro hace que el proceso principal de winbindd no se demonice, es decir, que no haga doble fork y no se desvincule de la terminal. Todavía se crean procesos hijos como de costumbre para atender cada solicitud de conexión, pero el proceso principal no sale. Este modo de operación es adecuado para ejecutar winbindd bajo supervisores de procesos como supervise y svscan del paquete daemontools de Daniel J. Bernstein, o el monitor de procesos de AIX.

--no-process-group

No crear un nuevo grupo de procesos para winbindd.

-n|--no-caching

Desactivar cierto almacenamiento en caché. Esto significa que winbindd a menudo tendrá que esperar una respuesta del controlador de dominio antes de poder responder a un cliente y, por lo tanto, esto hace que las cosas sean más lentas. Sin embargo, los resultados serán más precisos, ya que los resultados de la caché podrían no estar actualizados. Esto también podría bloquear temporalmente winbindd si el DC no responde. Esto no deshabilita la caché de samlogon, que es necesaria para el seguimiento de la pertenencia a grupos en entornos de confianza.

-d|--debuglevel=nivel

nivel es un entero de 0 a 10. El valor por defecto si este parámetro no se especifica es 0.

Cuanto mayor sea este valor, más detalles se registrarán en los archivos de registro sobre las actividades del servidor. Con el nivel 0, solo se registrarán errores críticos y advertencias serias. El nivel 1 es un nivel razonable para el funcionamiento diario: genera una pequeña cantidad de información sobre las operaciones realizadas.

Los niveles superiores a 1 generarán una cantidad considerable de datos de registro y solo deben utilizarse al investigar un problema. Los niveles superiores a 3 están diseñados para ser utilizados solo por desarrolladores y generan ENORMES cantidades de datos de registro, la mayoría de los cuales son extremadamente crípticos.

Tenga en cuenta que especificar este parámetro aquí anulará el parámetro log level en el archivo /etc/samba/smb.conf.

--debug-stdout

Esto redirigirá la salida de depuración a STDOUT. Por defecto, los demonios del servidor registran en un archivo de registro.

--configfile=ARCHIVO_CONFIGURACION

El archivo especificado contiene los detalles de configuración requeridos por el servidor. La información en este archivo incluye información específica del servidor, como qué archivo printcap usar, así como descripciones de todos los servicios que el servidor debe proporcionar. Consulte /etc/samba/smb.conf para obtener más información. El nombre del archivo de configuración por defecto se determina en tiempo de compilación.

--option=<nombre>=<valor>

Establece la opción smb.conf(5) "<nombre>" al valor "<valor>" desde la línea de comandos. Esto anula los valores predeterminados compilados y las opciones leídas del archivo de configuración. Si un nombre o un valor incluye un espacio, envuelva todo --option=nombre=valor entre comillas.

-l|--log-basename=directorio_registros

Nombre base para los archivos de registro/depuración. El proceso padre utiliza el nombre de archivo log.winbindd, el proceso hijo utiliza el nombre de archivo log.wb-<nombre>. winbindd nunca elimina el archivo de registro.

--leak-report

Habilitar informes de fugas de talloc al salir.

--leak-report-full

Habilitar informes completos de fugas de talloc al salir.

-V|--version

Imprime el número de versión del programa.

-?|--help

Imprime un resumen de las opciones de la línea de comandos.

--usage

Muestra un breve mensaje de uso.

RESOLUCIÓN DE NOMBRES E IDS

Los usuarios y grupos en un servidor Windows NT reciben un ID de seguridad (SID) que es globalmente único cuando se crea el usuario o grupo. Para convertir un usuario o grupo de Windows NT en un usuario o grupo de Unix, se requiere un mapeo entre los SIDs y los IDs de usuario y grupo de Unix. Este es uno de los trabajos que realiza winbindd.

A medida que los usuarios y grupos de winbindd se resuelven desde un servidor, los IDs de usuario y grupo se asignan desde un rango especificado. Esto se hace por orden de llegada, aunque todos los usuarios y grupos existentes se mapearán tan pronto como un cliente realice un comando de enumeración de usuarios o grupos. Los IDs de Unix asignados se almacenan en una base de datos y se recordarán.

ADVERTENCIA: La base de datos de SID a ID de Unix es la única ubicación donde winbindd almacena los mapeos de usuarios y grupos. Si este almacén se elimina o se corrompe, no hay forma de que winbindd determine qué IDs de usuario y grupo corresponden a los RIDs de usuario y grupo de Windows NT.

NOMBRE

winbindd - Daemon de Daemon de servicios de nombres de Windows NT

SINOPSIS

winbindd [-F] [-S]

DESCRIPCIÓN

El demonio winbindd es un servicio que proporciona la capacidad de resolución de nombres de usuario y grupo de Windows NT para sistemas Linux. Es el principal demonio de Samba que interactúa con los controladores de dominio de Windows NT.

El demonio winbindd proporciona servicios de nombres de usuario y grupo a otros demonios de Samba y a las utilidades del sistema operativo. Actualmente, los servicios proporcionados son:

  • Resolución de nombres de usuario y grupo de dominios de Windows NT a IDs de usuario y grupo de UNIX.
  • Autenticación de usuarios de dominios de Windows NT.

Cuando las bases de datos de nombres de usuario y grupo de un dominio de Windows NT se expanden a nivel local, el demonio winbindd se encarga de la resolución de nombres de usuario y grupo de dominios de Windows NT a IDs de usuario y grupo de UNIX.

OPCIONES

-F
Forzar la ejecución en primer plano (útil para depuración).
-S
Cargar la configuración de Samba, pero no convertirse en un demonio. Esto es útil para verificar que la configuración es correcta antes de iniciar el demonio.
