Descripción Detallada

Una fuente de eventos abstracta.

Este es el tipo genérico para fuentes de fd, temporizadores, señales y tareas idle. Las funciones que operan sobre tipos de fuentes específicas no deben usarse con un tipo diferente, incluso si la firma de la función lo permite.

typedef int(* wl_event_loop_fd_func_t) (int fd, uint32_t mask, void *data)

Tipo de función de distribución de descriptor de archivo

Las funciones de este tipo se utilizan como callbacks para eventos de descriptor de archivo.

Parámetros

fd El descriptor de archivo que entrega el evento.
mask Describe el tipo del evento como un OR a nivel de bits de: WL_EVENT_READABLE, WL_EVENT_WRITABLE, WL_EVENT_HANGUP, WL_EVENT_ERROR.
data El argumento de datos de usuario de la llamada relacionada wl_event_loop_add_fd().

Devuelve

Si la fuente de eventos está registrada para volver a ser comprobada con wl_event_source_check(): 0 si todo está hecho, 1 si necesita una nueva comprobación. Si no está registrada, el valor de retorno se ignora y debe ser cero.

struct wl_event_source * wl_event_loop_add_fd (struct wl_event_loop * loop, int fd, uint32_t mask, wl_event_loop_fd_func_t func, void * data)

Crear una fuente de eventos de descriptor de archivo

Parámetros

loop El bucle de eventos que procesará la nueva fuente.
fd El descriptor de archivo a vigilar.
mask Un OR a nivel de bits de los eventos a vigilar: WL_EVENT_READABLE, WL_EVENT_WRITABLE.
func La función de distribución del descriptor de archivo.
data Datos de usuario.

Devuelve

Una nueva fuente de eventos de descriptor de archivo.

El descriptor de archivo dado se vigila inicialmente para los eventos indicados en mask. Esto puede cambiarse según sea necesario con wl_event_source_fd_update().

Si es posible que la ejecución del programa cause que el descriptor de archivo se lea mientras deja los datos en un búfer sin procesarlos realmente, puede ser necesario registrar la fuente del descriptor de archivo para que se vuelva a comprobar, ver wl_event_source_check(). Esto asegurará que la función de distribución se llame incluso si el descriptor de archivo ya no es legible o escribible. Esto es especialmente útil con bibliotecas IPC que almacenan en búfer automáticamente los datos entrantes, posiblemente como un efecto secundario de otras operaciones.

struct wl_event_source * wl_event_loop_add_idle (struct wl_event_loop * loop, wl_event_loop_idle_func_t func, void * data)

Crear una tarea idle

Parámetros

loop El bucle de eventos que procesará la nueva tarea.
func La función de distribución de la tarea idle.
data Datos de usuario.

Devuelve

Una nueva tarea idle (una fuente de eventos).

Las tareas idle se distribuyen antes de que wl_event_loop_dispatch() se ponga a dormir. Ver wl_event_loop_dispatch() para más detalles.

Las tareas idle se disparan una vez y se destruyen automáticamente justo después de que se haya llamado a la función callback.

Una tarea idle puede ser cancelada antes de que se haya llamado a la función callback mediante wl_event_source_remove(). Llamar a wl_event_source_remove() después o desde dentro del callback resulta en un comportamiento indefinido.

NAME

wl_event_source - handle to an event source

SYNOPSIS

#include <wayland-server.h>

struct wl_event_source;

wl_event_loop_add_fd, wl_event_loop_add_signal, wl_event_loop_add_timer, wl_event_source_check, wl_event_source_fd_update, wl_event_source_remove, wl_event_source_timer_update

Detailed Description

An event source is a handle to an object that can trigger callbacks within the Wayland event loop.

There are three types of event sources:

File descriptor sources
Triggered when a file descriptor is ready for reading or writing.
Signal sources
Triggered when a specific signal is received.
Timer sources
Triggered after a specified delay.

Event sources are created by calling functions like wl_event_loop_add_fd(), wl_event_loop_add_signal() and wl_event_loop_add_timer(). They are destroyed by calling wl_event_source_remove().

The event loop is entered by calling wl_event_loop_dispatch(). This function waits for an event source to become ready, then calls its dispatch function. If the dispatch function returns non-zero, wl_event_loop_dispatch() will re-check all event sources that have been marked with wl_event_source_check().

Member Typedef Documentation

typedef int (* wl_event_loop_fd_func_t)(int fd, uint32_t events, void *data)

File descriptor event dispatch function pointer.

The function will be called with the file descriptor, a mask of received events (WL_EVENT_READABLE and/or WL_EVENT_WRITABLE), and the user data provided when the source was created.

The function should return 0 to indicate that the source is no longer interesting, or non-zero to indicate that the source should be re-checked after the current dispatch cycle. This is useful for sources that may become ready again as a side-effect of being dispatched.

typedef int (* wl_event_loop_signal_func_t)(int sig, void *data)

Signal event dispatch function pointer.

The function will be called with the signal number and the user data provided when the source was created.

The function should return 0 to indicate that the source is no longer interesting, or non-zero to indicate that the source should be re-checked after the current dispatch cycle. This is useful for sources that may become ready again as a side-effect of being dispatched.

typedef int (* wl_event_loop_timer_func_t)(void *data)

Timer event dispatch function pointer.

The function will be called with the user data provided when the source was created.

The function should return 0 to indicate that the source is no longer interesting, or non-zero to indicate that the source should be re-checked after the current dispatch cycle. This is useful for sources that may become ready again as a side-effect of being dispatched.

struct wl_event_source * wl_event_loop_add_signal (struct wl_event_loop *loop, int sig, wl_event_loop_signal_func_t func, void *data)

Create a signal event source

Parameters

loop The event loop that will process the new source.
sig The signal number to catch.
func The signal dispatch function.
data User data.

Returns

A new signal event source.

This function blocks the normal delivery of the given signal in the calling thread, and creates a "watch" for it. Signal delivery no longer happens asynchronously, but by wl_event_loop_dispatch() calling the dispatch callback function func.

It is the caller's responsibility to ensure that all other threads have also blocked the signal.

void wl_event_source_check (struct wl_event_source * source)

Mark event source to be re-checked

Parameters

source The event source to be re-checked.

This function permanently marks the event source to be re-checked after the normal dispatch of sources in wl_event_loop_dispatch(). Re-checking will keep iterating over all such event sources until the dispatch function for them all returns zero.

Re-checking is used on sources that may become ready to dispatch as a side-effect of dispatching themselves or other event sources, including idle sources. Re-checking ensures all the incoming events have been fully drained before wl_event_loop_dispatch() returns.

int wl_event_source_fd_update (struct wl_event_source * source, uint32_t mask)

Update a file descriptor source's event mask

Parameters

source The file descriptor event source to update.
mask The new mask, a bitwise-or of: WL_EVENT_READABLE, WL_EVENT_WRITABLE.

Returns

0 on success, -1 on failure.

This changes which events, readable and/or writable, cause the dispatch callback to be called on.

File descriptors are usually writable to begin with, so they do not need to be polled for writable until a write actually fails. When a write fails, the event mask can be changed to poll for readable and writable, delivering a dispatch callback when it is possible to write more. Once all data has been written, the mask can be changed to poll only for readable to avoid busy-looping on dispatch.

int wl_event_source_remove (struct wl_event_source * source)

Remove an event source from its event loop

Parameters

source The event source to be removed.

Returns

Zero.

The event source is removed from the event loop it was created for, and is effectively destroyed. This invalidates source . The dispatch function of the source will no longer be called through this source.

int wl_event_source_timer_update (struct wl_event_source * source, int ms_delay)

Arm or disarm a timer

Parameters

source The timer event source to modify.
ms_delay The timeout in milliseconds.

Returns

0 on success, -1 on failure.

If the timeout is zero, the timer is disarmed.

If the timeout is non-zero, the timer is set to expire after the given timeout in milliseconds. When the timer expires, the dispatch function set with wl_event_loop_add_timer() is called once from wl_event_loop_dispatch(). If another dispatch is desired after another expiry, wl_event_source_timer_update() needs to be called again.
