Descripción detallada

Lista doblemente enlazada.

Por sí sola, una instancia de struct wl_list representa la cabeza centinela de una lista doblemente enlazada y debe inicializarse usando wl_list_init(). Cuando está vacía, los miembros next y prev de la cabeza de la lista apuntan a la propia cabeza de la lista; de lo contrario, next hace referencia al primer elemento de la lista y prev se refiere al último elemento de la lista.

Utilice el tipo struct wl_list para representar tanto la cabeza de la lista como los enlaces entre los elementos dentro de la lista. Utilice wl_list_empty() para determinar si la lista está vacía en tiempo O(1).

Todos los elementos de la lista deben ser del mismo tipo. El tipo del elemento debe tener un miembro struct wl_list, a menudo llamado link por convención. Antes de la inserción, no es necesario inicializar el link de un elemento; invocar wl_list_init() en el miembro struct wl_list de un elemento individual es innecesario si la siguiente operación es wl_list_insert(). Sin embargo, un idiomaticomún es inicializar el link de un elemento antes de su eliminación; asegure la seguridad invocando wl_list_init() antes de wl_list_remove().

Considere una referencia de lista struct wl_list foo_list, un tipo de elemento como struct element y un miembro de enlace de un elemento como struct wl_list link.

El siguiente código inicializa una lista y le añade tres elementos.

struct wl_list foo_list;
struct element {
        int foo;
        struct wl_list link;
};
struct element e1, e2, e3;
wl_list_init(&foo_list);
wl_list_insert(&foo_list, &e1.link);   // e1 es el primer elemento
wl_list_insert(&foo_list, &e2.link);   // e2 es ahora el primer elemento
wl_list_insert(&e2.link, &e3.link); // inserta e3 después de e2

La lista ahora se ve así: [e2, e3, e1].

La API de wl_list proporciona algunas macros iteradoras. Por ejemplo, para iterar una lista en orden ascendente:

struct element *e;
wl_list_for_each(e, foo_list, link) {
        do_something_with_element(e);
}

Consulte la documentación de cada iterador para obtener más detalles.

Detailed Description

The wl_list structure describes a doubly linked list node. It is intended to be embedded within another structure. The list itself is represented by a wl_list node, whose next and prev pointers point to itself when the list is empty.

The list nodes are assumed to be part of a larger structure. This structure must contain a member of type struct wl_list. The wl_container_of macro is used to get the pointer to the containing structure from the pointer to the embedded wl_list member.

The list macros (wl_list_for_each, wl_list_for_each_safe, wl_list_for_each_reverse, wl_list_for_each_reverse_safe) require the list head, a cursor pointer (pos), and the name of the wl_list member within the containing structure.

The macros wl_list_for_each_safe and wl_list_for_each_reverse_safe require an additional temporary pointer (tmp) of the same type as the cursor pointer. This is used to safely remove the current element from the list during iteration.

The wl_container_of macro is defined in <wayland-util.h> and is implemented as:

#define wl_container_of(ptr, type, member) \
        (type *)((char *)(ptr) - offsetof(type, member))

The offsetof macro is defined in <stddef.h>.

The wl_list structure is commonly used in Wayland protocol implementations for managing client and surface lists, event queues, etc.

struct client {
        struct wl_list link;
        // ... other client data
};

struct wl_list client_list;
struct client *c;
struct client *tmp;

wl_list_init(&client_list);

// Add a client
struct client *new_client = malloc(sizeof *new_client);
wl_list_insert(&client_list, &new_client->link);

// Iterate over clients
wl_list_for_each_safe(c, tmp, &client_list, link) {
        // Process client 'c'
        // ...

        // Remove client if needed
        // wl_list_remove(&c->link);
        // free(c);
}
