WRITE(1P) Manual del programador POSIX WRITE(1P)

PROLOG

Esta página del manual es parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

write — escribir a otro usuario

SINOPSIS

write nombre_usuario [terminal]

DESCRIPCIÓN

La utilidad write leerá líneas de la entrada estándar y las escribirá en la terminal del usuario especificado. Al invocarse por primera vez, escribirá el mensaje:

Mensaje de id_login_remitente (terminal_envío) [fecha]...

a nombre_usuario. Cuando haya completado con éxito la conexión, la terminal del destinatario se alertará dos veces para indicar que lo que el remitente está escribiendo se está escribiendo en la terminal del destinatario.

Si el destinatario desea responder, esto se puede lograr escribiendo:

write id_login_remitente [terminal_envío]

al recibir el mensaje inicial. Cada vez que se acumula una línea de entrada delimitada por un carácter NL, EOF o EOL especial (ver el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 11, Interfaz General de Terminal) mientras está en modo de entrada canónico, los datos acumulados se escribirán en la terminal del otro usuario. Los caracteres se procesarán de la siguiente manera:

*
Escribir <alerta> escribirá el carácter <alerta> en la terminal del destinatario.
*
Escribir los caracteres de borrado y de matar afectará a la terminal del remitente de la manera descrita por la interfaz termios en el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 11, Interfaz General de Terminal.
*
Escribir los caracteres de interrupción o fin de archivo hará que write escriba un mensaje apropiado ("EOT\n" en la localidad POSIX) en la terminal del destinatario y saldrá.
*
Escribir caracteres de las clasificaciones print o space de LC_CTYPE hará que esos caracteres se envíen a la terminal del destinatario.
*
Cuando y solo cuando el modo local stty iexten esté habilitado, la existencia y el procesamiento de caracteres de control adicionales y funciones multibyte o de un solo byte son definidos por la implementación.
*
Escribir otros caracteres no imprimibles provocará que se escriban secuencias definidas por la implementación de caracteres imprimibles en la terminal del destinatario.

Para escribir a un usuario que ha iniciado sesión más de una vez, el argumento terminal se puede utilizar para indicar a qué terminal escribir; de lo contrario, la terminal del destinatario se seleccionará de una manera definida por la implementación y se escribirá un mensaje informativo al la salida estándar del remitente, indicando qué terminal se eligió.

El permiso para ser destinatario de un mensaje de write puede ser denegado o concedido mediante el uso de la utilidad mesg. Sin embargo, el privilegio de un usuario puede restringir aún más el dominio de accesibilidad de las terminales de otros usuarios. La utilidad write fallará cuando el usuario carezca de los privilegios apropiados para realizar la acción solicitada.

OPCIONES

Ninguna.

OPERANDOS

Se admitirán los siguientes operandos:

nombre_usuario
Nombre de inicio de sesión de la persona a la que se escribirá el mensaje. La aplicación se asegurará de que este operando tenga el formato devuelto por la utilidad who.
terminal
Identificación de la terminal en el mismo formato proporcionado por la utilidad who.

ENTRADA ESTÁNDAR

Las líneas que se copiarán en la terminal del destinatario se leen de la entrada estándar.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de write:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Ver el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en comparación con caracteres multibyte en argumentos y archivos de entrada). Si la localización del destinatario no utiliza un equivalente de LC_CTYPE al del remitente, los resultados no están definidos.
LC_MESSAGES

Determinar la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar y los mensajes informativos escritos en la salida estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Si se recibe una señal de interrupción, write escribirá un mensaje apropiado en la terminal del destinatario y saldrá con un estado de cero. Tomará la acción estándar para todas las demás señales.

SALIDA ESTÁNDAR

Se escribirá un mensaje informativo en la salida estándar si un destinatario ha iniciado sesión más de una vez.

SALIDA DE ERROR ESTÁNDAR

La salida de error estándar se utilizará solo para mensajes diagnósticos.

ARCHIVOS DE SALIDA

La terminal del destinatario se utiliza para la salida.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
El usuario al que se dirige no ha iniciado sesión o el usuario al que se dirige deniega el permiso.

USO DE LA APLICACIÓN

La utilidad talk es considerada por algunos usuarios como una utilidad más utilizable en terminales de pantalla completa.

JUSTIFICACIÓN

La utilidad write se incluyó en este volumen de POSIX.1‐2017 ya que se puede implementar en todos los tipos de terminal. Los desarrolladores del estándar consideraron que la utilidad talk, que no se puede implementar en ciertas terminales, era una interfaz de comunicación "mejor". Ambos programas están en uso generalizado en implementaciones históricas. Por lo tanto, los desarrolladores del estándar decidieron que ambas utilidades debían especificarse.

write(1p) — Arch Linux

RATIONALE

The write utility is used to send messages to other users. It writes the user's terminal in users from the terminal in write. If users is not specified, it defaults to the recipient specified by the RECIPIENT environment variable, if it is set. If neither is specified, the behavior is undefined.

The talk and write utilities were historically different. talk was designed to permit a two-way conversation, while write was a one-way message from one user to another. The POSIX.1‐2001 standard consolidated the functionality of the two, creating the specification for the write utility described here, which supports two-way communication. Implementations are permitted to provide the functionality of the historical talk utility when write is invoked.

The mesg utility controls whether other users can send messages to the invoking user's terminal. The write utility relies on the permissions set by mesg. If messages are blocked, the write utility cannot write to the terminal.

The description of write is intended to be compatible with the historical talk utility. The write utility sends a message to another user's terminal. If the recipient is logged in multiple times, write writes to the first terminal found. If the --write option is used, it writes to all terminals where the user is logged in.

The who utility can be used to determine which users are logged on and which terminals they are using. The ps utility can also provide information about users and processes.

Historically, the talk utility allowed two users to have a conversation. Each user's terminal was split into two parts, one for each user. The write utility was a simpler utility that allowed one user to send a message to another user's terminal. The POSIX standard consolidated these into a single write utility that supports two-way communication. However, the description here is based on the simpler, one-way communication model for write. The description of ps, talk, who, and write require that they all use or accept the same format.
