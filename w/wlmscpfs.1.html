NOMBRE

wlmscpfs - DICOM Basic Worklist Management SCP (basado en archivos de datos)

SINOPSIS

wlmscpfs [opciones] puerto

DESCRIPCIÓN

La aplicación wlmscpfs implementa un Proveedor de Servicio (SCP) para el Servicio de Gestión Básica de Listas de Trabajo. La aplicación escuchará en un puerto TCP/IP especificado las solicitudes de asociación entrantes de un SCU de Gestión de Listas de Trabajo. En caso de que una asociación sea reconocida y se reciba una consulta de lista de trabajo, la aplicación wlmscpfs consultará archivos particulares en un directorio determinado (que puede especificarse a través de las opciones del programa correspondientes) en el sistema de archivos en busca de información correspondiente de la lista de trabajo, y enviará esta información de vuelta al SCU de Gestión de Listas de Trabajo que llama. Aparte de tratar las consultas de Gestión de Listas de Trabajo, la aplicación wlmscpfs también soporta la Clase de Servicio de Verificación como SCP.

PARÁMETROS

puerto  número de puerto tcp/ip en el que escuchar

NOTAS

El impacto semántico de las opciones mencionadas anteriormente es claro para la mayoría de las opciones. Sin embargo, algunas opciones particulares son tan específicas que necesitan descripciones detalladas que se darán en este pasaje.

Las opciones de conjunto de caracteres devuelto están pensadas para situaciones en las que la aplicación wlmscpfs devolverá valores de atributos que no están compuestos de caracteres del repertorio de caracteres predeterminado de DICOM. En tales casos, por ejemplo, la opción --return-iso-ir-100 puede usarse para especificar que una respuesta a la solicitud C-FIND de gestión de lista de trabajo de una modalidad deberá contener el atributo Conjunto de Caracteres Específico de DICOM (0008,0005) con un valor correspondiente, indicando el repertorio de caracteres del cual se tomaron los caracteres de los valores de atributos devueltos (en este ejemplo, el repertorio ISO IR 100). Tenga en cuenta que la aplicación wlmscpfs no se asegurará de que todos los valores devueltos estén realmente compuestos de este conjunto de caracteres; la aplicación espera que así sea.

En general, el atributo Conjunto de Caracteres Específico (0008,0005) solo se incluirá en la respuesta C-FIND si contiene algún atributo que se vea afectado por el conjunto de caracteres, es decir, para representaciones de valor PN, LO, LT, SH, ST y UT.

Tenga en cuenta que una solicitud C-FIND que es manejada por esta aplicación puede contener el atributo Conjunto de Caracteres Específico de DICOM (0008,0005), pero esta aplicación nunca usará el valor de este atributo para la coincidencia. Además, la cuestión de si el atributo Conjunto de Caracteres Específico de DICOM (0008,0005) estará contenido en una respuesta C-FIND devuelta por esta aplicación siempre está determinada por la opción de conjunto de caracteres devuelto que se especificó cuando se inició esta aplicación.

Las opciones --enable-file-reject y --disable-file-reject se pueden utilizar para habilitar o deshabilitar un mecanismo de rechazo de archivos que garantiza que solo se utilicen archivos de lista de trabajo completos durante el proceso de coincidencia. Se considera que un archivo de lista de trabajo está completo si contiene toda la información necesaria de tipo 1 que el SCP podría tener que devolver a un SCU en un mensaje de respuesta C-FIND. La tabla K.6-1 del anexo K, parte 4 del estándar DICOM, enumera todos los atributos de tipo 1 correspondientes (ver la columna "Tipo de clave de retorno").

Escribir archivos de solicitud

Proporcionar la opción --request-file-path habilita la escritura de las solicitudes C-FIND entrantes en archivos de texto. El valor de la opción proporciona el directorio de destino donde se almacenarán estos archivos. Todos los archivos de solicitud se almacenan en formato "dump" como lo proporciona la herramienta dcmdump y son crudos, es decir, se escriben tal como llegan a wlmscpfs, sin ningún procesamiento de etiquetas aplicado por wlmscpfs.

La escritura de archivos de solicitud permite a los usuarios preparar "interactivamente" la base de datos de la lista de trabajo (para wlmscpfs, los archivos de lista de trabajo servidos desde el directorio --data-file-path) observando el directorio de archivos de solicitud. Una vez que aparece un archivo de solicitud, se necesita tiempo para actualizar las entradas de la lista de trabajo en la base de datos. Por esta razón, tiene sentido usar --request-file-path en combinación con la opción --sleep-before, que permite a los usuarios especificar una cierta cantidad de segundos que wlmscpfs debe esperar antes de comenzar a verificar la base de datos de la lista de trabajo. NOMBRE

wlmscpfs - Módulo de servicio de consultas de lista de trabajo para consultas de pacientes y de estudios.

SINOPSIS

wlmscpfs [-h | --help] [-q | --quiet] [-v | --verbose] [-d | --debug] [-ll | --log-level level] [-c | --config-file file] [-ip | --inet-port port] [-ap | --assoc-port port] [-ta | --task-async] [--help-config]

DESCRIPCIÓN

El módulo de servicio de consultas de lista de trabajo (Worklist Management SCP) para consultas de pacientes y de estudios implementa el perfil de servicio de la interfaz de consulta de lista de trabajo del DICOM. El módulo puede ser configurado para responder a consultas de pacientes y/o de estudios. El servicio puede ser iniciado en el puerto TCP especificado por el parámetro de línea de comandos --inet-port. Si este parámetro se omite, el módulo intentará obtener el número de puerto de la configuración del módulo asociado. Si esto también falla, el módulo no se iniciará y saldrá con un error.

El módulo de servicio de consultas de lista de trabajo proporciona la funcionalidad de un SCP (Service Class Provider) para los servicios de consulta de lista de trabajo de la clase de servicio de gestión de lista de trabajo DICOM. El módulo responde a las solicitudes de consulta enviadas por un cliente de lista de trabajo (MWL CS) que actúa como un SCU (Service Class User).

Este módulo puede ser iniciado como un servicio independiente y configurado mediante un archivo de configuración. El archivo de configuración especifica parámetros como el número de puerto de red, la información del AE (Application Entity) y el comportamiento de la consulta.

PARÁMETROS

Los parámetros siguientes pueden ser pasados al módulo de servicio de consultas de lista de trabajo:

-h, --help
Muestra un mensaje de ayuda y sale.
-q, --quiet
Suprime la salida de información durante la ejecución.
-v, --verbose
Imprime información detallada sobre las operaciones del módulo.
-d, --debug
Habilita la salida de depuración. Esto es útil para diagnosticar problemas.
-ll, --log-level level
Establece el nivel de registro. Los niveles posibles son: debug, info, warning, error.
-c, --config-file file
Especifica la ruta al archivo de configuración que se utilizará para configurar el módulo.
-ip, --inet-port port
Establece el número de puerto TCP en el que el módulo escuchará las conexiones entrantes.
-ap, --assoc-port port
Establece el número de puerto del módulo asociado. Este parámetro se utiliza si el módulo de servicio de consultas de lista de trabajo necesita comunicarse con otro módulo DICOM. Si este parámetro se omite, el número de puerto se obtendrá del archivo de configuración o de las variables de entorno.
-ta, --task-async
Habilita la ejecución asíncrona de tareas. Esto puede mejorar el rendimiento al permitir que el módulo maneje múltiples solicitudes simultáneamente.
--help-config
Muestra información detallada sobre el archivo de configuración y las opciones disponibles.

OPCIONES

Este módulo no tiene opciones de línea de comandos específicas además de los parámetros descritos anteriormente.

NOTAS

El módulo de servicio de consultas de lista de trabajo requiere un archivo de configuración para definir su comportamiento. El archivo de configuración debe especificar el nombre de la Entidad de Aplicación (AE Title), el número de puerto de red y otros parámetros relevantes para la comunicación DICOM.

La comunicación con otros servicios DICOM se basa en la información proporcionada en el archivo de configuración y en la red. Asegúrese de que la configuración de red y la información de AE sean correctas para permitir una comunicación exitosa.

LOGGING

El módulo soporta varios niveles de registro. El nivel de registro predeterminado es 'info'. Se pueden utilizar los parámetros de línea de comandos --log-level, --verbose y --debug para controlar la cantidad de información de registro generada. La salida de registro se enviará a la salida estándar por defecto, pero puede ser redirigida a un archivo o a un sistema de registro centralizado según la configuración.

LÍNEA DE COMANDOS

Ejemplo de cómo iniciar el módulo con un archivo de configuración y un puerto específico:

wlmscpfs --config-file /etc/dcmtk/wlmscpfs.cfg --inet-port 104

Este comando iniciará el módulo de servicio de consultas de lista de trabajo utilizando el archivo de configuración /etc/dcmtk/wlmscpfs.cfg y escuchará en el puerto TCP 104.

ENTORNO

La variable de entorno DCMWLM_CONFIG puede usarse para especificar la ruta al archivo de configuración. Si esta variable está definida, anula el parámetro --config-file de la línea de comandos.

Si la variable de entorno DCMDICTPATH no está establecida, por defecto se cargará el archivo <datadir>/dicom.dic, a menos que el diccionario esté integrado en la aplicación (predeterminado para Windows).

Se debe preferir el comportamiento predeterminado y la variable de entorno DCMDICTPATH solo debe usarse cuando se requieran diccionarios de datos alternativos. La variable de entorno DCMDICTPATH tiene el mismo formato que la variable PATH del shell de Unix, en la que dos puntos (":") separan las entradas. En sistemas Windows, un punto y coma (";") se utiliza como separador. El código del diccionario de datos intentará cargar cada archivo especificado en la variable de entorno DCMDICTPATH. Es un error si no se puede cargar ningún diccionario de datos.
