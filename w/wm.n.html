Paquete: tk

Licencias: TCL

wm(n) Comandos integrados de Tk wm(n)

NOMBRE

wm - Comunicarse con el gestor de ventanas

SINOPSIS

wm opción ventana ?args?

DESCRIPCIÓN

El comando wm se utiliza para interactuar con los gestores de ventanas con el fin de controlar cosas como el título de una ventana, su geometría o los incrementos en los que se puede redimensionar. El comando wm puede tomar cualquiera de una serie de formas diferentes, dependiendo del argumento opción. Todas las formas esperan al menos un argumento adicional, ventana, que debe ser el nombre de la ruta de una ventana de nivel superior.

Las formas legales para el comando wm son:

wm aspect ventana ?minNumer minDenom maxNumer maxDenom?
Si se especifican minNumer, minDenom, maxNumer y maxDenom, se pasarán al gestor de ventanas y este debería utilizarlos para imponer un rango de relaciones de aspecto aceptables para ventana. La relación de aspecto de ventana (ancho/alto) se restringirá para que se encuentre entre minNumer/minDenom y maxNumer/maxDenom. Si minNumer, etc., son cadenas vacías, se eliminan las restricciones de relación de aspecto existentes. Si se especifican minNumer, etc., el comando devuelve una cadena vacía. De lo contrario, devuelve una lista de Tcl que contiene cuatro elementos, que son los valores actuales de minNumer, minDenom, maxNumer y maxDenom (si no hay restricciones de aspecto activas, se devuelve una cadena vacía).
wm attributes ventana
wm attributes ventana ?opción?
wm attributes ventana ?opción valor opción valor...?
Esta subfunción devuelve o establece atributos específicos de la plataforma asociados con una ventana. La primera forma devuelve una lista de las banderas específicas de la plataforma y sus valores. La segunda forma devuelve el valor de la opción específica. La tercera forma establece uno o más de los valores. Los valores son los siguientes:

Todas las plataformas soportan los siguientes atributos (aunque los usuarios de X11 deberían ver las notas a continuación):

-alpha
Especifica el nivel de transparencia alfa del nivel superior. Acepta un valor desde 0.0 (completamente transparente) hasta 1.0 (opaco). Los valores fuera de ese rango se limitarán. Donde no se soporte, el valor de -alpha permanecerá en 1.0.
-fullscreen
Coloca la ventana en un modo que ocupa toda la pantalla, no tiene bordes y cubre el área de uso general (es decir, el menú de inicio y la barra de tareas en Windows, el dock y la barra de menús en macOS, las decoraciones generales de ventanas en X11).
-topmost
Especifica si esta es una ventana de nivel superior (se muestra encima de todas las demás ventanas).

En Windows, se pueden establecer los siguientes atributos.

-disabled
Especifica si la ventana está en estado deshabilitado.
-toolwindow
Especifica un estilo de ventana de herramienta (como se define en MSDN).
-transparentcolor
Especifica el índice de color transparente del nivel superior. Acepta cualquier valor de color aceptado por Tk_GetColor. Si se especifica la cadena vacía (por defecto), no se utiliza ningún color transparente. Esto es compatible con Windows 2000/XP+. Donde no se soporte, el valor de -transparentcolor permanecerá en {}.

En macOS, se pueden establecer los siguientes atributos.

-modified
Especifica el estado de modificación de la ventana (determina si el widget de cierre de la ventana contiene el indicador de modificación y si el icono proxy es arrastrable).
-notify
Especifica el estado de notificación del proceso (rebotar el icono del dock de la aplicación).
-titlepath
Especifica la ruta del archivo al que se hace referencia como icono proxy de la ventana (que se puede arrastrar y soltar en lugar del icono del archivo en Finder).
-transparent
Hace que el área de contenido de la ventana sea transparente y desactiva la sombra de la ventana. Para que la transparencia sea efectiva, el fondo del nivel superior debe establecerse en un color con algo de alfa, por ejemplo, “systemTransparent”.

En X11, se pueden establecer los siguientes atributos. No todos los gestores de ventanas los soportan y no tendrán efecto bajo WMs más antiguos.

-type
Solicita que la ventana sea interpretada por el gestor de ventanas como del tipo especificado. Esto puede hacer que la ventana se decore de manera diferente o se gestione de otra forma, aunque exactamente lo que sucede depende completamente del gestor de ventanas. Se puede usar una lista de tipos, en orden de preferencia. Los siguientes valores se mapean a constantes definidas en la especificación EWMH (no se recomienda usar otros):
desktop
indica una característica de escritorio,
dock
indica una característica de dock/panel,
toolbar
indica una ventana de barra de herramientas que debe actuar en nombre de otra ventana, como se indica con wm transient,
menu
indica un menú desprendido que debe actuar en nombre de otra ventana, como se indica con wm transient,
utility
indica una ventana de utilidad (por ejemplo, paleta o caja de herramientas) que debe actuar en nombre de otra ventana, como se indica con wm transient,
splash
indica una pantalla de bienvenida, que se muestra durante el inicio de la aplicación,
dialog
indica una ventana de diálogo general, que debe actuar en nombre de otra ventana, como se indica con wm transient,
dropdown_menu
indica un menú invocado desde una barra de menús, que normalmente también debe configurarse como override-redirected (con wm overrideredirect),
popup_menu
indica un menú contextual, que normalmente también debe configurarse como override-redirected (con wm overrideredirect),
tooltip
indica una ventana de información sobre herramientas, que normalmente también debe configurarse como override-redirected (con wm overrideredirect),
notification
indica una ventana que proporciona una notificación de fondo de algún evento, que normalmente también debe configurarse como override-redirected (con wm overrideredirect),
combo
indica la lista desplegable de un widget combobox, que normalmente también debe configurarse como override-redirected (con wm overrideredirect),
dnd
indica una ventana que representa algo que se está arrastrando, que normalmente también debe configurarse como override-redirected (con wm overrideredirect),
normal
indica una ventana que no tiene ninguna interpretación especial.
-zoomed
Solicita que la ventana se maximice. Esto es lo mismo que wm state zoomed en Windows y macOS.

wm client ventana ?nombre?
Si se especifica nombre, este comando almacena nombre (que debería ser el nombre del host en el que se está ejecutando la aplicación) en la propiedad WM_CLIENT_MACHINE de ventana para que lo utilice el administrador de ventanas o el administrador de sesiones. El comando devuelve una cadena vacía en este caso. Si no se especifica nombre, el comando devuelve el último nombre establecido en un comando wm client para ventana. Si nombre se especifica como una cadena vacía, el comando elimina la propiedad WM_CLIENT_MACHINE de ventana.
wm colormapwindows ventana ?listaVentanas?
Este comando se utiliza para manipular la propiedad WM_COLORMAP_WINDOWS, que proporciona información a los administradores de ventanas sobre las ventanas que tienen mapas de color privados.

Si no se especifica listaVentanas, el comando devuelve una lista cuyos elementos son los nombres de las ventanas en la propiedad WM_COLORMAP_WINDOWS. Si se especifica listaVentanas, consiste en una lista de nombres de ruta de ventanas; el comando sobrescribe la propiedad WM_COLORMAP_WINDOWS con las ventanas dadas y devuelve una cadena vacía. La propiedad WM_COLORMAP_WINDOWS normalmente debería contener una lista de las ventanas internas dentro de ventana cuyos mapas de color difieren de sus padres.

El orden de las ventanas en la propiedad indica un orden de prioridad: el administrador de ventanas intentará instalar tantos mapas de color como sea posible desde el principio de esta lista cuando ventana obtenga el foco del mapa de color. Si ventana no está incluida entre las ventanas en listaVentanas, Tk la agrega implícitamente al final de la propiedad WM_COLORMAP_WINDOWS, de modo que su mapa de color tenga la menor prioridad. Si no se invoca wm colormapwindows, Tk establecerá automáticamente la propiedad para cada ventana de nivel superior a todas las ventanas internas cuyos mapas de color difieren de sus padres, seguido de la ventana de nivel superior misma; el orden de las ventanas internas no está definido. Consulte la documentación del ICCCM para obtener más información sobre la propiedad WM_COLORMAP_WINDOWS.

wm command ventana ?valor?
Si se especifica valor, este comando almacena valor en la propiedad WM_COMMAND de ventana para que la utilicen el administrador de ventanas o el administrador de sesiones y devuelve una cadena vacía. Valor debe tener una estructura de lista correcta; los elementos deben contener las palabras del comando utilizado para invocar la aplicación. Si no se especifica valor, el comando devuelve el último valor establecido en un comando wm command para ventana. Si valor se especifica como una cadena vacía, el comando elimina la propiedad WM_COMMAND de ventana.
wm deiconify ventana
Organiza para que ventana se muestre en forma normal (no iconificada). Esto se hace mapeando la ventana. Si la ventana nunca se ha mapeado, este comando no la mapeará, pero se asegurará de que cuando la ventana se mapee por primera vez, se muestre en forma desiconificada. En Windows, una ventana desiconificada también se elevará y recibirá el foco (se convertirá en la ventana activa). Devuelve una cadena vacía.
wm focusmodel ventana ?active|passive?
Si se proporciona active o passive como argumento opcional al comando, entonces especifica el modelo de foco para ventana. En este caso, el comando devuelve una cadena vacía. Si no se proporciona ningún argumento adicional, el comando devuelve el modelo de foco actual para ventana.

Un modelo de foco active significa que ventana reclamará el foco de entrada para sí misma o sus descendientes, incluso en momentos en que el foco esté actualmente en alguna otra aplicación. Passive significa que ventana nunca reclamará el foco para sí misma: el administrador de ventanas debería darle el foco a ventana en los momentos apropiados. Sin embargo, una vez que el foco se le ha dado a ventana o a uno de sus descendientes, la aplicación puede reasignar el foco entre los descendientes de ventana. El modelo de foco tiene como valor predeterminado passive, y el comando focus de Tk asume un modelo pasivo de enfoque.

wm forget ventana
La ventana se desmapeará de la pantalla y ya no será gestionada por wm. Las ventanas creadas con el comando toplevel se tratarán como ventanas frame una vez que ya no sean gestionadas por wm, sin embargo, la configuración -menu se recordará y los menús volverán una vez que el widget se gestione nuevamente.
wm frame ventana
Si el administrador de ventanas ha reparentado ventana en un marco decorativo, el comando devuelve el identificador de ventana específico de la plataforma para el marco más externo que contiene ventana (la ventana cuyo padre es la raíz o la raíz virtual). Si el administrador de ventanas no ha reparentado ventana, entonces el comando devuelve el identificador de ventana específico de la plataforma para ventana.
wm geometry ventana ?nuevaGeometria?
Si se especifica nuevaGeometria, entonces la geometría de ventana cambia y se devuelve una cadena vacía. De lo contrario, se devuelve la geometría actual de ventana (esta es la geometría más reciente especificada ya sea por redimensionamiento manual o en un comando wm geometry). NuevaGeometria tiene el formato =anchoxalto±x±y, donde cualquiera de =, anchoxalto, o ±x±y puede omitirse. Ancho y alto son enteros positivos que especifican las dimensiones deseadas de ventana. Si ventana está enrejada (consulte GESTIÓN DE GEOMETRÍA ENREJADA a continuación), entonces las dimensiones se especifican en unidades de rejilla; de lo contrario, se especifican en unidades de píxeles.

X e Y especifican la ubicación deseada de ventana en la pantalla, en píxeles. Si x está precedido por +, especifica el número de píxeles entre el borde izquierdo de la pantalla y el borde izquierdo del borde de ventana; si está precedido por -, entonces x especifica el número de píxeles entre el borde derecho de la pantalla y el borde derecho del borde de ventana. Si y está precedido por +, entonces especifica el número de píxeles entre la parte superior de la pantalla y la parte superior del borde de ventana; si y está precedido por -, entonces especifica el número de píxeles entre la parte inferior del borde de ventana y la parte inferior de la pantalla.

Si nuevaGeometria se especifica como una cadena vacía, entonces se cancela cualquier geometría especificada por el usuario para ventana, y la ventana volverá al tamaño solicitado internamente por sus widgets.

Tenga en cuenta que esto está relacionado con winfo geometry, pero no es lo mismo. Ese solo puede consultar la geometría y siempre refleja la comprensión actual de Tk del tamaño y la ubicación reales de ventana, mientras que wm geometry permite tanto establecer como consultar la comprensión del administrador de ventanas del tamaño y la ubicación de la ventana. Esto puede variar significativamente, por ejemplo, para reflejar la adición de elementos decorativos a ventana, como barras de título, y los administradores de ventanas no están obligados a seguir con precisión las solicitudes realizadas a través de este comando.

wm grid ventana ?anchoBase altoBase anchoInc altoInc?
Este comando indica que ventana se gestionará como una ventana enrejada. También especifica la relación entre las unidades de rejilla y las unidades de píxeles. AnchoBase y altoBase especifican el número de unidades de rejilla que corresponden a las dimensiones de píxeles solicitadas internamente por ventana utilizando Tk_GeometryRequest. AnchoInc y altoInc especifican el número de píxeles en cada unidad de rejilla horizontal y vertical. Estos cuatro valores determinan un rango de tamaños aceptables para ventana, correspondientes a anchos y altos basados en rejillas que son enteros no negativos. Tk pasará esta información al administrador de ventanas; durante el redimensionamiento manual, el administrador de ventanas restringirá el tamaño de la ventana a uno de estos tamaños aceptables.

Además, durante el redimensionamiento manual, el administrador de ventanas mostrará el tamaño actual de la ventana en términos de unidades de rejilla en lugar de píxeles. Si anchoBase, etc., se especifican como cadenas vacías, entonces ventana ya no se gestionará como una ventana enrejada. Si se especifican anchoBase, etc., el valor de retorno es una cadena vacía.

De lo contrario, el valor de retorno es una lista Tcl que contiene cuatro elementos correspondientes al anchoBase, altoBase, anchoInc y altoInc actuales; si ventana no está actualmente enrejada, se devuelve una cadena vacía.

Tenga en cuenta que este comando no debería ser necesario con mucha frecuencia, ya que el procedimiento de la biblioteca Tk_SetGrid y la opción setGrid proporcionan un acceso más fácil a la misma funcionalidad.

wm group ventana ?nombreRuta?
Si se especifica nombreRuta, proporciona el nombre de ruta para el líder de un grupo de ventanas relacionadas. El administrador de ventanas puede usar esta información, por ejemplo, para desmapear todas las ventanas de un grupo cuando se iconifica el líder del grupo. NombreRuta puede especificarse como una cadena vacía para eliminar ventana de cualquier asociación de grupo. Si se especifica nombreRuta, el comando devuelve una cadena vacía; de lo contrario, devuelve el nombre de ruta del líder de grupo actual de ventana, o una cadena vacía si ventana no forma parte de ningún grupo.
wm iconbitmap ventana ?bitmap?
Si se especifica bitmap, entonces nombra un bitmap en los formatos estándar aceptados por Tk (ver la entrada de manual Tk_GetBitmap para más detalles). Este bitmap se pasa al administrador de ventanas para que se muestre en el icono de ventana, y el comando devuelve una cadena vacía. Si se especifica una cadena vacía para bitmap, entonces cualquier bitmap de icono actual se cancela para ventana. Si se especifica bitmap, el comando devuelve una cadena vacía. De lo contrario, devuelve el nombre del bitmap de icono actual asociado con ventana, o una cadena vacía si ventana no tiene bitmap de icono. En el sistema operativo Windows, un adicional
tional flag is supported:
wm iconbitmap window ?-default? ?image?
Si se proporciona el indicador -default, el icono se aplica a todas las ventanas de nivel superior (existentes y futuras) a las que aún no se ha aplicado ningún otro icono específico. Además de los tipos de imagen de mapa de bits, también se acepta una especificación de ruta completa a cualquier archivo que contenga un icono válido de Windows (generalmente archivos .ico o .icr), o cualquier archivo para el que el shell haya asignado un icono. Tcl primero probará si el archivo contiene un icono, luego si tiene un icono asignado y, finalmente, si eso falla, probará un mapa de bits.
wm iconify window
Organizar para que window se convierta en un icono. Si window aún no se ha mapeado por primera vez, este comando organizará para que aparezca en el estado de icono cuando finalmente se mapee.
wm iconmask window ?bitmap?
Si se especifica bitmap, entonces nombra un mapa de bits en las formas estándar aceptadas por Tk (ver la entrada del manual Tk_GetBitmap para más detalles). Este mapa de bits se pasa al administrador de ventanas para que se use como máscara junto con la opción iconbitmap: donde la máscara tiene ceros no se mostrará ningún icono; donde tenga unos, se mostrarán los bits del mapa de bits del icono. Si se especifica una cadena vacía para bitmap, se cancela cualquier máscara de icono actual para window (esto es equivalente a especificar un mapa de bits de todos unos). Si se especifica bitmap, el comando devuelve una cadena vacía. De lo contrario, devuelve el nombre de la máscara de icono actual asociada con window, o una cadena vacía si no hay ninguna máscara activa.
wm iconname window ?newName?
Si se especifica newName, se pasa al administrador de ventanas; el administrador de ventanas debería mostrar newName dentro del icono asociado con window. En este caso, se devuelve una cadena vacía como resultado. Si no se especifica newName, el comando devuelve el nombre del icono actual para window, o una cadena vacía si no se ha especificado ningún nombre de icono (en este caso, el administrador de ventanas normalmente mostrará el título de la ventana, como se especifica con el comando wm title).
wm iconphoto window ?-default? image1 ?image2 ...?
Establece el icono de la barra de título para window basándose en las imágenes fotográficas nombradas. Si se especifica -default, esto se aplica también a todos los niveles superiores creados en el futuro. Los datos de las imágenes se toman como una instantánea en el momento de la invocación. Si las imágenes se cambian más tarde, esto no se reflejará en los iconos de la barra de título. Se aceptan múltiples imágenes para permitir diferentes tamaños de imagen (por ejemplo, 16x16 y 32x32). El administrador de ventanas puede escalar los iconos proporcionados a un tamaño apropiado.

En Windows, las imágenes se empaquetan en una estructura de icono de Windows. Esto anulará un icono especificado a wm iconbitmap, y vice versa.

En X, las imágenes se organizan en la propiedad X _NET_WM_ICON, que la mayoría de los administradores de ventanas modernos soportan. Un wm iconbitmap puede existir simultáneamente. Se recomienda no usar más de 2 iconos, colocando el icono más grande primero.

En Macintosh, la primera imagen llamada se carga en un formato de icono nativo del sistema operativo y se convierte en el icono de la aplicación en diálogos, el Dock y otros contextos. A nivel de script, el comando solo aceptará la primera imagen pasada en los parámetros, ya que el soporte para múltiples tamaños/resoluciones en macOS está fuera del alcance de Tk. Los desarrolladores deben usar el icono más grande que puedan soportar (preferiblemente 512 píxeles) para garantizar una renderización fluida en Mac.

wm iconposition window ?x y?
Si se especifican x e y, se pasan al administrador de ventanas como una pista sobre dónde posicionar el icono para window. En este caso, se devuelve una cadena vacía. Si x e y se especifican como cadenas vacías, se cancela cualquier pista de posición de icono existente. Si no se especifica ni x ni y, el comando devuelve una lista de Tcl que contiene dos valores, que son las pistas de posición de icono actuales (si no hay pistas activas, se devuelve una cadena vacía).
wm iconwindow window ?pathName?
Si se especifica pathName, es el nombre de ruta de una ventana que se utilizará como icono para window: cuando window se convierta en icono, se mapeará pathName para que sirva como icono, y cuando window se descomprima, se desmapeará pathName nuevamente. Si se especifica pathName como una cadena vacía, se cancelará cualquier asociación de ventana de icono existente para window. Si se especifica el argumento pathName, se devuelve una cadena vacía. De lo contrario, el comando devuelve el nombre de ruta de la ventana de icono actual para window, o una cadena vacía si actualmente no hay ninguna ventana de icono especificada para window. Los eventos de clic de botón se deshabilitan para window mientras sea una ventana de icono; esto es necesario para permitir que los administradores de ventanas "posean" esos eventos. Tenga en cuenta que no todos los administradores de ventanas admiten la noción de una ventana de icono, y el concepto no tiene sentido en plataformas que no son X11.
wm manage widget
El widget especificado se convertirá en una ventana independiente de nivel superior. La ventana estará decorada con la barra de título del administrador de ventanas, etc. Solo los widgets frame, labelframe y toplevel se pueden usar con este comando. Intentar pasar cualquier otro tipo de widget generará un error. Intentar gestionar un widget toplevel es benigno y no logra nada. Ver también GEOMETRY MANAGEMENT.
wm maxsize window ?width height?
Si se especifican width y height, dan las dimensiones máximas permitidas para window. Para ventanas en cuadrícula, las dimensiones se especifican en unidades de cuadrícula; de lo contrario, se especifican en unidades de píxeles. El administrador de ventanas restringirá las dimensiones de la ventana a ser menores o iguales a width y height. Si se especifican width y height, el comando devuelve una cadena vacía. De lo contrario, devuelve una lista de Tcl con dos elementos, que son el ancho y alto máximos actualmente en vigor. El tamaño máximo por defecto es el tamaño de la pantalla. Ver las secciones sobre gestión de geometría más abajo para más información.
wm minsize window ?width height?
Si se especifican width y height, dan las dimensiones mínimas permitidas para window. Para ventanas en cuadrícula, las dimensiones se especifican en unidades de cuadrícula; de lo contrario, se especifican en unidades de píxeles. El administrador de ventanas restringirá las dimensiones de la ventana a ser mayores o iguales a width y height. Si se especifican width y height, el comando devuelve una cadena vacía. De lo contrario, devuelve una lista de Tcl con dos elementos, que son el ancho y alto mínimos actualmente en vigor. El tamaño mínimo por defecto es de un píxel en cada dimensión. Ver las secciones sobre gestión de geometría más abajo para más información.
wm overrideredirect window ?boolean?
Si se especifica boolean, debe tener una forma booleana correcta y la bandera de anulación de redirección para window se establece en ese valor. Si no se especifica boolean, se devuelve 1 o 0 para indicar si la bandera de anulación de redirección está actualmente establecida para window. Establecer la bandera de anulación de redirección para una ventana hace que sea ignorada por el administrador de ventanas; entre otras cosas, esto significa que la ventana no será reparentada desde la ventana raíz a un marco decorativo y el usuario no podrá manipular la ventana utilizando los mecanismos normales del administrador de ventanas.

Tenga en cuenta que la bandera de anulación de redirección solo se garantiza que se tenga en cuenta cuando la ventana se mapea por primera vez o cuando se mapea después de que el estado cambia de retirado a normal. Algunas, pero no todas, las plataformas tendrán en cuenta en momentos adicionales.

wm positionfrom window ?who?
Si se especifica who, debe ser program o user, o una abreviatura de uno de estos dos. Indica si la posición actual de window fue solicitada por el programa o por el usuario. Muchos administradores de ventanas ignoran las posiciones iniciales solicitadas por el programa y piden al usuario que posicione la ventana manualmente; si se especifica user, el administrador de ventanas debería posicionar la ventana en el lugar dado sin pedir ayuda al usuario. Si se especifica who como una cadena vacía, se cancela la fuente de posición actual. Si se especifica who, el comando devuelve una cadena vacía. De lo contrario, devuelve user o program para indicar la fuente de la posición actual de la ventana, o una cadena vacía si aún no se ha especificado ninguna fuente. La mayoría de los administradores de ventanas interpretan "sin fuente" como equivalente a program. Tk establecerá automáticamente la fuente de posición a user cuando se invoque un comando wm geometry, a menos que la fuente se haya establecido explícitamente en program.
wm protocol window ?name? ?command?
Este comando se utiliza para gestionar los protocolos del administrador de ventanas. El argumento name en el comando wm protocol es el nombre de un átomo que corresponde a un protocolo del administrador de ventanas. Los ejemplos incluyen WM_DELETE_WINDOW o WM_SAVE_YOURSELF o WM_TAKE_FOCUS.

Un protocolo del administrador de ventanas es una clase de mensajes enviados desde un administrador de ventanas a una aplicación Tk fuera del sistema de procesamiento de eventos normal. El principal ejemplo es el protocolo WM_DELETE_WINDOW; estos mensajes se envían cuando el usuario hace clic en el widget de cierre en la barra de título de una ventana. Los manejadores de protocolos del administrador de ventanas se instalan con el comando wm protocol. BUGS

La mayoría de los gestores de ventanas existentes parecen tener errores que afectan al funcionamiento del comando wm. Por ejemplo, algunos cambios no surtirán efecto si la ventana ya está activa: la ventana tendrá que ser retirada y desiconizada para que el cambio se produzca.

EJEMPLOS

Una ventana de tamaño fijo que también indica que es de tamaño fijo:

toplevel .fixed
wm title     .fixed "Ventana de tamaño fijo"
wm resizable .fixed 0 0

Una ventana simple similar a un diálogo, centrada en la pantalla:

# Crear y organizar el contenido del diálogo.
toplevel .msg
label  .msg.l  -text "Esta es una demostración de un diálogo muy simple."
button .msg.ok -text OK -default active -command {destroy .msg}
pack .msg.ok -side bottom -fill x
pack .msg.l  -expand 1    -fill both
# Ahora configurar el widget como un diálogo centrado.
# Pero primero, necesitamos que los gestores de geometría terminen de configurar
# el interior del diálogo, para lo cual necesitamos ejecutar el
# bucle de eventos con el widget completamente oculto...
wm withdraw .msg
update
set x [expr {([winfo screenwidth .] - [winfo width .msg]) / 2}]
set y [expr {([winfo screenheight .] - [winfo height .msg]) / 2}]
wm geometry  .msg +$x+$y
wm transient .msg .
wm title     .msg "Demostración de diálogo"
wm deiconify .msg
