wsgen(1) Herramientas de Servicios Web Java wsgen(1)

NOMBRE

wsgen - Lee una implementación de extremo de servicio web (SEI) y genera todos los artefactos requeridos para el despliegue e invocación de servicios web.

SINOPSIS

wsgen [ opciones ] SEI
opciones
Las opciones de línea de comandos. Ver Opciones.
SEI
La clase de implementación del extremo del servicio web (SEI) a leer.

DESCRIPCIÓN

El comando wsgen genera artefactos portátiles JAX-WS utilizados en servicios web JAX-WS. La herramienta lee una clase de extremo de servicio web y genera todos los artefactos requeridos para el despliegue e invocación de servicios web. La implementación de referencia JAXWS 2.1.1 también proporciona una tarea Ant wsgen, consulte la pestaña Herramientas de la página JAX-WS (wsgen) en http://jax-ws.java.net/nonav/2.1.1/docs/wsgenant.html

Para iniciar el comando wsgen, haga lo siguiente:

export JAXWS_HOME=/ruta/a/jaxws-ri
$JAXWS_HOME/bin/wsgen.sh -help

OPCIONES

-classpath ruta

La ubicación de los archivos de clase de entrada.
-cp ruta

La ubicación de los archivos de clase de entrada.
-d directorio

La ubicación donde colocar los archivos de salida generados.
-extension

Permite extensiones del proveedor. El uso de extensiones puede resultar en aplicaciones que no son portátiles o que no funcionan con otras implementaciones.
-help

Muestra un mensaje de ayuda sobre el comando wsgen.
-keep

Conserva los archivos generados.
-r directorio

Utiliza esta opción con la opción -wsdl para especificar dónde colocar los archivos de recursos generados, como los WSDL.
-s directorio

La ubicación donde colocar los archivos fuente generados.
-verbose

Muestra mensajes del compilador.
-version

Imprime información de la versión.
-wsdl [ :protocolo ]

Un comando opcional que genera un archivo WSDL para revisar antes del despliegue del extremo. Los archivos WSDL contienen una descripción legible por máquina de cómo se puede llamar al servicio, qué parámetros espera y qué estructuras de datos devuelve.

Por defecto, el comando wsgen no genera un archivo WSDL. El valor protocolo es opcional y se utiliza para especificar qué protocolo se debe usar para el enlace WSDL (wsdl:binding). Los protocolos válidos son soap1.1 y Xsoap1.2. El valor predeterminado es soap1.1. El protocolo Xsoap1.2 no es estándar y solo se puede usar con la opción -extension.

-servicename nombre

Se utiliza solo con la opción -wsdl para especificar un nombre de servicio WSDL (wsdl:service) particular que se generará en el WSDL, por ejemplo: -servicename "{http://mynamespace/}MyService".
-portname nombre

Se utiliza solo con la opción -wsdl para especificar un nombre de puerto WSDL (wsdl:port) particular que se generará en el WSDL, por ejemplo: -portname "{http://mynamespace/}MyPort".

EJEMPLOS

El siguiente ejemplo genera las clases envoltorio para StockService con anotaciones @WebService dentro del directorio stock.

wsgen -d stock -cp myclasspath stock.StockService

El siguiente ejemplo genera un WSDL y un esquema SOAP 1.1 para la clase stock.StockService con anotaciones @WebService.

wsgen -wsdl -d stock -cp myclasspath stock.StockService

El siguiente ejemplo genera un WSDL SOAP 1.2.

wsgen -wsdl:Xsoap1.2 -d stock -cp myclasspath stock.StockService

Nota: No es necesario generar un WSDL en tiempo de desarrollo porque el entorno de ejecución JAXWS genera un WSDL para usted cuando despliega su servicio.
