WEBVIS(1) Manual de Comandos Generales WEBVIS(1)

NOMBRE

webvis - visualiza la actividad del servidor Web a nivel de sistema

SINOPSIS

webvis [-CVz] [-A alineación] [-a archivo] [-b ocupado máximo] [-h host] [-i io máximo] [-m máximo] [-n archivo_pmns] [-O tiempo] [-p puerto] [-r req máximo] [-S tiempo] [-T tiempo] [-t intervalo] [-x versión] [-Z zona horaria] [interfaz ...]

DESCRIPCIÓN

webvis muestra una visión general de las estadísticas de rendimiento del servidor Web a nivel de sistema recopiladas de la infraestructura Performance Co-Pilot (PCP). La visualización se modula por los valores de las métricas de rendimiento recuperadas del host de destino (que está ejecutando pmcd(1) y el Agente de Dominio de Métricas de Rendimiento pmdaweblog(1)) o del archivo de registro PCP identificado por archivo. La visualización se actualiza cada intervalo segundos (predeterminado 2 segundos).

Como en todas las escenas de pmview(1), cuando el ratón se mueve sobre una de las barras, el valor actual y la información métrica de esa barra se mostrarán en el cuadro de texto cerca de la parte superior de la visualización.

La altura de las barras de solicitudes web y actividad de red es proporcional a los valores de las métricas de rendimiento en relación con la actividad máxima esperada, según lo controlado por las opciones -m y -r (ver abajo). De manera similar, las opciones -b y -i controlan la escala de las barras de actividad de disco.

Las barras en la escena webvis representan la siguiente información;

Solicitudes por Tamaño
En la parte frontal de la escena, la fila de barras "Solicitudes por Tamaño" muestra la tasa de solicitudes para diferentes tamaños de solicitudes (los histogramas se definen por los siguientes recuentos de bytes: 0, 3 Kbytes, 10 Kbytes, 30 Kbytes, 100 Kbytes, 300 Kbytes, 1 Mbyte, 3 Mbytes y más de 3 Mbytes). Tenga en cuenta que las divisiones de tamaño no son uniformes. El "tamaño" es la porción de datos de la respuesta a cada solicitud del servidor Web. Estas tasas se agregan en todos los servidores Web monitorizados.
Solicitudes por Tipo
Esta fila de barras muestra la tasa de solicitudes para cada tipo de solicitud HTTP (get, post, head y otros), agregada en todos los servidores Web monitorizados. Para una visualización detallada que muestre el desglose de solicitudes *por servidor Web*, consulte weblogvis(1).
Red
Para cada interfaz de red hay dos barras apiladas. Una de las barras muestra el tráfico de entrada, mientras que la otra muestra el tráfico de salida. Las pilas están compuestas por el número de errores (rojo), el número de caídas (naranja) y el número de paquetes (verde). En general, si hay algún "paquete de entrada perdido", la interfaz de red correspondiente está saturada, o no hay suficientes recursos de red disponibles en el kernel para atender adecuadamente la carga de solicitudes de entrada. Si este es el caso, las filas de Condiciones de Alarma (ver abajo) pueden proporcionar más detalles sobre el origen del problema.
Condiciones de Alarma
La fila roja de barras muestra una variedad de condiciones de error de TCP (agregadas para todas las interfaces de red), las barras naranjas muestran problemas críticos de asignación de búfer del kernel y la barra amarilla muestra condiciones severas de paginación. Si alguna de estas barras tiene una altura distinta de cero, el sistema que se está monitorizando puede requerir ajuste de parámetros del kernel, reconfiguración del software o más recursos de hardware. Las métricas de rendimiento detrás de las barras son:
network.tcp.drops
- tasa de conexiones caídas
network.tcp.conndrops
- tasa de conexiones embrionarias caídas
network.tcp.timeoutdrop
- tasa de conexiones caídas por tiempo de espera de retransmisión
network.tcp.rcvbadsum
- tasa de paquetes descartados por checksums incorrectos
network.tcp.rexmttimeo
- tasa de tiempos de espera de retransmisión
network.tcp.sndrexmitpack
- tasa de paquetes de datos retransmitidos
swap.pagesout
- tasa de paginación de intercambio hacia fuera (indicando memoria insuficiente)
network.mbuf.failed
- tasa de incidentes en los que el kernel no pudo encontrar espacio mbuf
network.mbuf.waited
- tasa de incidentes en los que el kernel esperó para encontrar espacio mbuf
CPU
Esta columna muestra la utilización de la CPU, agregada en todas las CPUs. (El tiempo de inactividad de la CPU no está incluido en la columna).
Disco
Hay dos cilindros que muestran métricas de disco. El primer cilindro muestra la tasa de operaciones de lectura (amarillo) y escritura (violeta), agregada en todos los discos. El segundo cilindro muestra el porcentaje promedio (sobre todos los discos) de tiempo durante el cual un disco está ocupado o activo. Esta métrica no está disponible en las versiones de PCP1.x, por lo tanto, si se utiliza webvis para monitorizar un host que ejecuta PCP1.x, este cilindro no se mostrará.

Para ajustar la escala de estos objetos, consulte las opciones -b y -i descritas a continuación.

Mem
Hay dos barras que muestran métricas de memoria. La primera barra muestra la memoria utilizada, con diferentes colores que representan diferentes tipos de utilización (kernel, usuario, etc.), mientras que la segunda barra muestra la cantidad de memoria libre. Si se utiliza webvis para monitorizar un host que ejecuta PCP1.x, solo se mostrará la barra que muestra la memoria libre.

Si se especifican argumentos opcionales de interfaz en la línea de comandos, solo las interfaces de red que coincidan con los argumentos de interfaz aparecerán en la sección Red. Por defecto, se utilizarán *todas* las interfaces. Los argumentos de interfaz se utilizan como patrones para egrep(1) que coinciden con los nombres de las interfaces, por lo que ec seleccionaría todas las interfaces Ethernet externas para un Challenge S.

webvis utiliza pmview(1), por lo que la interfaz de usuario sigue la descrita para pmview(1), que a su vez muestra la escena dentro de un visor examinador de Inventor.

webvis pasa la mayoría de las opciones de la línea de comandos a pmview(1). Por lo tanto, las opciones de línea de comandos -A, -a, -C, -h, -n, -O, -p, -S, -t, -T, -x, -Z y -z, y la interfaz de usuario se describen en la página del manual de pmview(1).

Las opciones específicas para webvis son:

-b ocupado máximo
Controla el valor máximo (normalización) para el porcentaje promedio del tiempo activo en todos los discos. El valor predeterminado es 30% activo.
-i io máximo
Controla el valor máximo (normalización) para la suma de las tasas agregadas de lectura de disco y escritura de disco. El valor predeterminado es 100 operaciones de E/S por segundo.
-m máximo
Controla el valor máximo (normalización) para las tasas de entrada y salida de paquetes. El valor predeterminado es 750 paquetes/segundo.
-r req máximo
Controla la tasa máxima de solicitudes web. El valor predeterminado es el 5% de la tasa máxima de paquetes (es decir, 38 solicitudes/segundo por defecto). La tasa máxima de errores web está fijada en el 20% de la tasa máxima de solicitudes web (es decir, 7 errores/segundo por defecto).
-V
El archivo de configuración derivado

webvis(1)

NAME

webvis — Visualisation of Performance Co-Pilot (PCP) archives

SYNOPSIS

webvis [-h]

DESCRIPTION

The webvis command is a simple Perl script that can be used to visualize PCP archives via a web browser. It functions by initiating a small web server that serves files from a specified directory. The script also generates a pmview(1) compatible event stream which is written on standard output. This may be saved and used directly with pmview if the user wishes to customize the display, or modify some of the normalization parameters.

FILES

$PCP_VAR_DIR/pmns/*
default PMNS specification files
$PCP_VAR_DIR/config/pmlogger/config.web
pmlogger(1) configuration file that can be used to create a PCP archive suitable for display with webvis

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(4).
