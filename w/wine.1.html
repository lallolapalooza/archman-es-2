WINE(1) Windows On Unix WINE(1)

NOMBRE

wine - ejecutar programas de Windows en Unix

SINOPSIS

wine programa [argumentos]
wine --ayuda
wine --version

Para obtener instrucciones sobre cómo pasar argumentos a programas de Windows, consulte la sección PROGRAMA/ARGUMENTOS de la página del manual.

DESCRIPCIÓN

wine carga y ejecuta el programa dado, que puede ser un ejecutable DOS, Windows 3.x, Win32 o Win64 (en sistemas de 64 bits).

Para depurar wine, utilice winedbg en su lugar.

Para ejecutar ejecutables CUI (programas de consola de Windows), utilice wineconsole en lugar de wine. Esto mostrará la salida en una ventana separada. No utilizar wineconsole para programas CUI solo proporcionará un soporte de consola muy limitado, y su programa podría no funcionar correctamente.

Cuando se invoca con --ayuda o --version como único argumento, wine simplemente imprimirá un pequeño mensaje de ayuda o su versión respectivamente y saldrá.

PROGRAMA/ARGUMENTOS

El nombre del programa puede especificarse en formato DOS (C:\\WINDOWS\\SOL.EXE) o en formato Unix (/msdos/windows/sol.exe). Puede pasar argumentos al programa que se está ejecutando añadiéndolos al final de la línea de comandos que invoca a wine (por ejemplo: wine notepad C:\\TEMP\\README.TXT). Tenga en cuenta que necesita escapar con '\' los caracteres especiales (y los espacios) al invocar Wine a través de un shell, por ejemplo:

wine C:\\Program\ Files\\MyPrg\\test.exe

También puede ser uno de los ejecutables de Windows incluidos con Wine, en cuyo caso especificar la ruta completa no es obligatorio, por ejemplo: wine explorer o wine notepad.

ENTORNO

wine hace accesibles las variables de entorno del shell desde el cual se inicia para los procesos de Windows/DOS iniciados. Por lo tanto, utilice la sintaxis adecuada para su shell para introducir las variables de entorno que necesite.

WINEPREFIX
Si está establecida, el contenido de esta variable se toma como el nombre del directorio donde Wine almacena sus datos (el valor predeterminado es $HOME/.wine). Este directorio también se utiliza para identificar el socket que se utiliza para comunicarse con el wineserver. Todos los procesos de wine que utilizan el mismo wineserver (es decir: el mismo usuario) comparten ciertas cosas como el registro, la memoria compartida y el archivo de configuración. Al establecer WINEPREFIX en valores diferentes para diferentes procesos de wine, es posible ejecutar un número de procesos de wine verdaderamente independientes.
WINESERVER
Especifica la ruta y el nombre del binario wineserver. Si no está establecida, Wine buscará un archivo llamado "wineserver" en la ruta y en otras ubicaciones probables.
WINEDEBUG
Activa o desactiva los mensajes de depuración. La sintaxis de la variable es del tipo [clase][+|-]canal[,[clase2][+|-]canal2]

clase es opcional y puede ser una de las siguientes: err, warn, fixme, o trace. Si no se especifica clase, se activan todos los mensajes de depuración para el canal especificado. Cada canal imprimirá mensajes sobre un componente particular de Wine. El siguiente carácter puede ser + o - para activar o desactivar respectivamente el canal especificado. Si no hay parte de clase antes, se puede omitir un + inicial. Tenga en cuenta que no se permiten espacios en ninguna parte de la cadena.

Ejemplos:

WINEDEBUG=warn+all
activará todos los mensajes de advertencia (recomendado para depuración).
WINEDEBUG=warn+dll,+heap
activará los mensajes de advertencia de DLL y todos los mensajes del heap.
WINEDEBUG=fixme-all,warn+cursor,+relay
desactivará todos los mensajes FIXME, activará los mensajes de advertencia del cursor y activará todos los mensajes de retransmisión (llamadas API).
WINEDEBUG=relay
activará todos los mensajes de retransmisión. Para un mayor control sobre la inclusión o exclusión de funciones y DLL del rastreo de retransmisión, consulte la clave de registro HKEY_CURRENT_USER\Software\Wine\Debug.

Para obtener más información sobre los mensajes de depuración, consulte el capítulo Ejecución de Wine de la Guía del Usuario de Wine.

WINEDLLPATH
Especifica las rutas en las que buscar DLL integradas y aplicaciones Winelib. Es una lista de directorios separados por ":". Además de cualquier directorio especificado en WINEDLLPATH, Wine también buscará en el directorio de instalación.
WINEDLLOVERRIDES
Define el tipo de anulación y el orden de carga de las DLL utilizadas en el proceso de carga para cualquier DLL. Actualmente hay dos tipos de bibliotecas que pueden cargarse en el espacio de direcciones de un proceso: DLL nativas de Windows (native) y DLL internas de Wine (builtin). El tipo puede abreviarse con la primera letra del tipo (n o b). La biblioteca también puede ser deshabilitada (''). Cada secuencia de órdenes debe separarse por comas.

Cada DLL puede tener su propio orden de carga específico. El orden de carga determina qué versión de la DLL se intenta cargar en el espacio de direcciones. Si la primera falla, se intenta la siguiente y así sucesivamente. Se pueden separar varias bibliotecas con el mismo orden de carga con comas. También es posible especificar diferentes órdenes de carga para diferentes bibliotecas separando las entradas con ";".

El orden de carga de una DLL de 16 bits siempre está definido por el orden de carga de la DLL de 32 bits que la contiene (lo que se puede identificar mirando el enlace simbólico del archivo .dll.so de 16 bits). Por ejemplo, si ole32.dll está configurada como interna, storage.dll también se cargará como interna, ya que la ole32.dll de 32 bits contiene la storage.dll de 16 bits.

Ejemplos:

WINEDLLOVERRIDES="comdlg32,shell32=n,b"

Intenta cargar comdlg32 y shell32 como DLL nativas de Windows primero e intenta la versión interna si la carga nativa falla.
WINEDLLOVERRIDES="comdlg32,shell32=n;c:\\foo\\bar\\baz=b"

Intenta cargar las bibliotecas comdlg32 y shell32 como DLL nativas de Windows. Además, si una aplicación solicita cargar c:\foo\bar\baz.dll, carga la biblioteca interna baz.
WINEDLLOVERRIDES="comdlg32=b,n;shell32=b;comctl32=n;oleaut32="

Intenta cargar comdlg32 como interna primero y la versión nativa si la carga interna falla; carga shell32 siempre como interna y comctl32 siempre como nativa; oleaut32 será deshabilitada.
WINEPATH
Especifica rutas adicionales que se antepondrán a la variable de entorno de PATH de Windows predeterminada. Es una lista de directorios estilo Windows separados por ";".

Para una alternativa permanente, edite (cree si es necesario) el valor PATH bajo la clave de registro HKEY_CURRENT_USER\Environment.

WINEARCH
Especifica la arquitectura de Windows a soportar. Puede configurarse a win32 (soporte solo para aplicaciones de 32 bits), a win64 (soporte para aplicaciones de 64 bits y también para las de 32 bits), o a wow64 (soporte para 64 -aplicaciones de 32 bits y de 64 bits, utilizando en todos los casos un proceso host de 64 bits).
La arquitectura soportada por un prefijo de Wine dado se establece en el momento de la creación del prefijo y no se puede cambiar posteriormente. Al ejecutarse con un prefijo existente, Wine se negará a iniciarse si WINEARCH no coincide con la arquitectura del prefijo. Sin embargo, es posible cambiar libremente entre win64 y wow64 con un prefijo de 64 bits existente.
WINE_D3D_CONFIG
Especifica las opciones de configuración de Direct3D. Se puede usar en lugar de modificar la clave del registro HKEY_CURRENT_USER\Software\Wine\Direct3D. El valor es una lista separada por comas o puntos y comas de pares clave-valor.
Por ejemplo:
WINE_D3D_CONFIG="renderer=vulkan;VideoPciVendorID=0xc0de"

Si una configuración individual se especifica tanto en la variable de entorno como en el registro, la primera tiene prioridad.

DISPLAY
Especifica la pantalla X11 a utilizar.
Variables de configuración del controlador de sonido OSS:
AUDIODEV
Establece el dispositivo para entrada/salida de audio. Por defecto /dev/dsp.
MIXERDEV
Establece el dispositivo para controles de mezclador. Por defecto /dev/mixer.
MIDIDEV
Establece el dispositivo MIDI (secuenciador). Por defecto /dev/sequencer.

ARCHIVOS

wine
El cargador de programas de Wine.
wineconsole
El cargador de programas de Wine para aplicaciones CUI (consola).
wineserver
El servidor de Wine
winedbg
El depurador de Wine
$WINEPREFIX/dosdevices
Directorio que contiene los mapeos de dispositivos DOS. Cada archivo en ese directorio es un enlace simbólico al archivo de dispositivo Unix que implementa un dispositivo determinado. Por ejemplo, si COM1 se mapea a /dev/ttyS0, tendrías un enlace simbólico del tipo $WINEPREFIX/dosdevices/com1 -> /dev/ttyS0.
Las unidades DOS también se especifican con enlaces simbólicos; por ejemplo, si la unidad D: corresponde al CDROM montado en /mnt/cdrom, tendrías un enlace simbólico $WINEPREFIX/dosdevices/d: -> /mnt/cdrom. El dispositivo Unix correspondiente a una unidad DOS se puede especificar de la misma manera, excepto que se usa '::' en lugar de ':'. Así, para el ejemplo anterior, si el dispositivo CDROM se monta desde /dev/hdc, el enlace simbólico correspondiente sería $WINEPREFIX/dosdevices/d:: -> /dev/hdc.

AUTORES

Wine está disponible gracias al trabajo de muchos desarrolladores. Para obtener una lista de los autores, consulta el archivo AUTHORS en el directorio principal de la distribución fuente.

COPYRIGHT

Wine puede distribuirse bajo los términos de la licencia LGPL. Una copia de la licencia se encuentra en el archivo COPYING.LIB en el directorio principal de la distribución fuente.

ERRORES

Un informe de estado sobre muchas aplicaciones está disponible en la Base de Datos de Aplicaciones de Wine. Por favor, añade entradas a esta lista para las aplicaciones que ejecutas actualmente, si es necesario.

Los errores se pueden informar en el rastreador de errores de Wine.

DISPONIBILIDAD

La versión pública más reciente de wine está disponible a través de WineHQ, el cuartel general de desarrollo de Wine.
