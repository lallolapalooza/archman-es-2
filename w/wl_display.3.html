Descripción detallada

Representa una conexión con el compositor y actúa como proxy para el objeto singleton wl_display.

Un objeto wl_display representa una conexión de cliente a un compositor Wayland. Se crea con wl_display_connect() o wl_display_connect_to_fd(). La conexión se termina usando wl_display_disconnect().

Un wl_display también se utiliza como el wl_proxy para el objeto singleton wl_display en el lado del compositor.

Un wl_display maneja todos los datos que se envían desde y hacia el compositor. Cuando un wl_proxy organiza una solicitud, escribirá su representación en el cable en el búfer de escritura del display. Los datos se envían al compositor cuando el cliente llama a wl_display_flush().

Los datos entrantes se manejan en dos pasos: puesta en cola y despacho. En el paso de puesta en cola, los datos que provienen del fd del display se interpretan y se agregan a una cola. En el paso de despacho, se llama al manejador del evento entrante establecido por el cliente en el wl_proxy correspondiente.

Un wl_display tiene al menos una cola de eventos, llamada la cola predeterminada. Los clientes pueden crear colas de eventos adicionales con wl_display_create_queue() y asignarles wl_proxy. Los eventos que ocurren en un proxy particular siempre se ponen en cola en su cola asignada. Un cliente puede asegurarse de que una cierta suposición, como mantener un bloqueo o ejecutarse desde un hilo determinado, sea cierta cuando se llama al manejador de eventos de un proxy, asignando ese proxy a una cola de eventos y asegurándose de que esta cola solo se despacha cuando la suposición se cumple.

La cola predeterminada se despacha llamando a wl_display_dispatch(). Esto despachará cualquier evento en cola en la cola predeterminada e intentará leer del fd del display si está vacío. Los eventos leídos luego se pondrán en cola en las colas apropiadas según la asignación del proxy.

Una cola creada por el usuario se despacha con wl_display_dispatch_queue(). Esta función se comporta exactamente igual que wl_display_dispatch() pero despacha la cola dada en lugar de la cola predeterminada.

Un ejemplo del mundo real del uso de colas de eventos es la implementación de Mesa de eglSwapBuffers() para la plataforma Wayland. Esta función podría necesitar bloquear hasta que se reciba un callback de fotograma, pero despachar la cola predeterminada podría hacer que un manejador de eventos en el cliente comience a dibujar de nuevo. Este problema se resuelve usando otra cola de eventos, de modo que solo los eventos manejados por el código EGL se despachan durante el bloqueo.

Esto crea un problema donde un hilo despacha una cola no predeterminada, leyendo todos los datos del fd del display. Si la aplicación llamase a poll(2) después de eso, se bloquearía, a pesar de que podría haber eventos en cola en la cola predeterminada. Esos eventos deben despacharse con wl_display_dispatch_pending() o wl_display_dispatch_queue_pending() antes de vaciar y bloquear.

struct wl_client * wl_client_create (struct wl_display * display, int fd)

Crea un cliente para el descriptor de archivo dado

Parámetros

display El objeto display
fd El descriptor de archivo para el socket al cliente

Retorna

El nuevo objeto cliente o NULL en caso de fallo.

Dado un descriptor de archivo que corresponde a un extremo de un socket, esta función creará una estructura wl_client y agregará el nuevo cliente a la lista de clientes del compositor. En ese momento, el cliente está inicializado y listo para ejecutarse, como si el cliente se hubiera conectado al socket de escucha del servidor. Cuando el cliente finalmente envíe solicitudes al compositor, el argumento wl_client al manejador de solicitudes será el wl_client devuelto por esta función.

struct wl_callback * wl_display_add_client_created_listener (struct wl_display * display, wl_client_created_func_t func, void * user_data)

Adds a listener that will be called when a new client is created.

The listener will be called after the client object is fully constructed but before any client-specific setup is done on the server side.

Listeners added with wl_display_add_client_created_listener() will be notified by this function after the client is fully constructed.

On failure this function sets errno accordingly and returns NULL.

On success, the new client object takes the ownership of the file descriptor. On failure, the ownership of the socket endpoint file descriptor is unchanged, it is the responsibility of the caller to perform cleanup, e.g. call close().

struct wl_protocol_logger * wl_display_add_protocol_logger (struct wl_display * display, wl_protocol_logger_func_t func, void * user_data)

Agrega un nuevo registrador de protocolo.

Cuando llega un nuevo mensaje de protocolo o se envía desde el servidor, se llamará a todas las funciones del registrador de protocolo, pasando el puntero user_data, el tipo del mensaje (solicitud o evento) y el mensaje real. La vida útil de los mensajes que se pasan a la función de registro finaliza cuando estas regresan, por lo que los mensajes no se pueden almacenar y acceder a ellos más tarde.

errno se establece en caso de error.

Parámetros

display El objeto de pantalla
func La función a llamar para registrar un nuevo mensaje de protocolo
user_data El puntero de datos de usuario para pasar a func

Devoluciones

El objeto del registrador de protocolo en caso de éxito, NULL en caso de error.

uint32_t * wl_display_add_shm_format (struct wl_display * display, uint32_t format)

Agrega soporte para un formato de píxel de wl_shm

Parámetros

display El objeto de pantalla
format El formato de píxel de wl_shm que se anunciará

Devoluciones

Un puntero al formato wl_shm que se agregó a la lista o NULL si falló al agregarlo a la lista.

Agrega el formato wl_shm especificado a la lista de formatos que el objeto wl_shm anuncia cuando un cliente se une a él. Agregar un formato a la lista significa que los clientes sabrán que el compositor soporta este formato y pueden usarlo para crear búferes de wl_shm. El compositor debe ser capaz de manejar el formato de píxel cuando un cliente lo solicita.

El compositor, por defecto, soporta WL_SHM_FORMAT_ARGB8888 y WL_SHM_FORMAT_XRGB8888.

int wl_display_add_socket (struct wl_display * display, const char * name)

Agrega un socket a la pantalla de Wayland para que los clientes se conecten.

Parámetros

display Pantalla de Wayland a la que se debe agregar el socket.
name Nombre del socket Unix.

Devoluciones

0 si éxito. -1 si falla.

Esto agrega un socket Unix a la pantalla de Wayland que los clientes pueden usar para conectarse a la pantalla de Wayland.

Si se pasa NULL como nombre, buscará la variable de entorno WAYLAND_DISPLAY para obtener el nombre del socket. Si WAYLAND_DISPLAY no está configurada, se usará el valor predeterminado wayland-0.

Si el nombre del socket es una ruta relativa, el socket Unix se creará en el directorio apuntado por la variable de entorno XDG_RUNTIME_DIR. Si XDG_RUNTIME_DIR no es válido o no está configurado, esta función falla y devuelve -1.

Si el nombre del socket es una ruta absoluta, se usará tal cual para el socket Unix.

La longitud de la ruta del socket calculada no debe exceder la longitud máxima de una ruta de socket Unix. La función también falla si el usuario no tiene permisos de escritura en el directorio o si la ruta ya está en uso.

int wl_display_add_socket_fd (struct wl_display * display, int sock_fd)

Agrega un socket con un fd existente a la pantalla de Wayland para que los clientes se conecten.

Parámetros

display Pantalla de Wayland a la que se debe agregar el socket.
sock_fd El descriptor de archivo de socket existente que se utilizará

Devoluciones

0 si éxito. -1 si falla.

El fd del socket existente debe estar creado, abierto y bloqueado. El fd debe estar configurado correctamente como CLOEXEC y enlazado a un archivo de socket con bind() y listen() ya llamados.

En caso de éxito, la propiedad del fd del socket se transfiere a libwayland: libwayland cerrará el socket cuando se destruya la pantalla.

struct wl_display * wl_display_connect (const char * name)

Conéctate a una pantalla de Wayland

Parámetros

name Nombre de la pantalla de Wayland a la que conectar

Devoluciones

Un objeto wl_display o NULL en caso de fallo

Se conecta a la pantalla de Wayland llamada name. Si name es NULL, su valor será reemplazado por la variable de entorno WAYLAND_DISPLAY si está configurada, de lo contrario, se usará la pantalla "wayland-0".

Si WAYLAND_SOCKET está configurada, se interpreta como un número de descriptor de archivo que hace referencia a un socket ya abierto. En este caso, el socket se usa tal cual y se ignora name.

Si name es una ruta relativa, el socket se abre relativo al directorio XDG_RUNTIME_DIR.

Si name es una ruta absoluta, esa ruta se usa tal cual para la ubicación del socket en el que está escuchando el servidor Wayland; no se intenta ninguna cualificación dentro de XDG_RUNTIME_DIR.

Si name es NULL y la variable de entorno WAYLAND_DISPLAY está configurada como una ruta de archivo absoluta, esa ruta se utiliza tal cual para el socket de la misma manera que si name contuviera una ruta absoluta. El soporte para rutas absolutas en name y WAYLAND_DISPLAY está presente desde la versión 1.15 de Wayland.

int wl_display_dispatch (struct wl_display * display)

Procesa eventos entrantes

Parámetros

display El objeto de contexto de pantalla

Retorna

El número de eventos despachados con éxito o -1 en caso de fallo

Despacha eventos en la cola de eventos predeterminada.

Si la cola de eventos predeterminada está vacía, esta función se bloquea hasta que haya eventos para leer del fd de la pantalla. Los eventos se leen y se ponen en cola en las colas de eventos apropiadas. Finalmente, los eventos en la cola de eventos predeterminada se despachan. En caso de fallo, se devuelve -1 y errno se establece apropiadamente.

En un entorno multihilo, no esperes manualmente usando poll() (o equivalente) antes de llamar a esta función, ya que hacerlo podría causar un interbloqueo. Si se requiere dependencia externa de poll() (o equivalente), consulta wl_display_prepare_read_queue() para saber cómo hacerlo.

Esta función es segura para hilos siempre que despache la cola correcta en el hilo correcto. También es compatible con la API de preparación de lectura de eventos multihilo (consulta wl_display_prepare_read_queue()) y utiliza internamente funcionalidad equivalente. No está permitido llamar a esta función mientras el hilo se está preparando para leer eventos, y hacerlo causará un interbloqueo.

Nota

No es posible comprobar si hay eventos en la cola o no. Para despachar eventos de la cola predeterminada sin bloquear, consulta wl_display_dispatch_pending().

int wl_display_dispatch_queue (struct wl_display * display, struct wl_event_queue * queue)

Despacha eventos en una cola de eventos

Parámetros

display El objeto de contexto de pantalla
queue La cola de eventos a despachar

Retorna

El número de eventos despachados con éxito o -1 en caso de fallo

Despacha eventos en la cola de eventos dada.

Si la cola de eventos dada está vacía, esta función se bloquea hasta que haya eventos para leer del fd de la pantalla. Los eventos se leen y se ponen en cola en las colas de eventos apropiadas. Finalmente, los eventos en la cola de eventos dada se despachan. En caso de fallo, se devuelve -1 y errno se establece apropiadamente.

En un entorno multihilo, no esperes manualmente usando poll() (o equivalente) antes de llamar a esta función, ya que hacerlo podría causar un interbloqueo. Si se requiere dependencia externa de poll() (o equivalente), consulta wl_display_prepare_read_queue() para saber cómo hacerlo.

Esta función es segura para hilos siempre que despache la cola correcta en el hilo correcto. También es compatible con la API de preparación de lectura de eventos multihilo (consulta wl_display_prepare_read_queue()) y utiliza internamente funcionalidad equivalente. No está permitido llamar a esta función mientras el hilo se está preparando para leer eventos, y hacerlo causará un interbloqueo.

Puede usarse como función auxiliar para facilitar el procedimiento de lectura y despacho de eventos.

Nota

Desde Wayland 1.5, la pantalla tiene una cola adicional para sus propios eventos (es decir, delete_id). Esta cola se despacha siempre, independientemente de la cola que pasamos como argumento a esta función. Esto significa que esta función puede retornar incluso cuando no ha despachado ningún evento para la cola dada.

int wl_display_dispatch_queue_timeout (struct wl_display * display, struct wl_event_queue * queue, const struct timespec * timeout)

int wl_display_flush (struct wl_display * display)

Envía todas las solicitudes en búfer de la pantalla al servidor

Parámetros

display El objeto de contexto de pantalla

Retorna

El número de bytes enviados con éxito o -1 en caso de fallo

Envía todos los datos en búfer en el lado del cliente al servidor. Los clientes siempre deben llamar a esta función antes de bloquearse esperando entrada del fd de la pantalla. Con éxito, se devuelve el número de bytes enviados al servidor. En caso de fallo, esta función devuelve -1 y errno se establece apropiadamente.

wl_display_flush() nunca se bloquea. Escribirá la mayor cantidad de datos posible, pero si no se pueden escribir todos los datos, errno se establecerá en EAGAIN y se devolverá -1. En ese caso, utiliza poll en el descriptor de archivo de la pantalla para esperar a que vuelva a estar disponible para escritura.

int wl_display_prepare_read_queue (struct wl_display * display, struct wl_event_queue * queue)

Prepararse para leer eventos del descriptor de archivo de la pantalla a una cola

Parámetros

display El objeto de contexto de pantalla
queue La cola de eventos a utilizar

Devuelve

0 en caso de éxito o -1 si la cola de eventos no estaba vacía

Esta función (o wl_display_prepare_read()) debe llamarse antes de leer desde el descriptor de archivo usando wl_display_read_events(). Llamar a wl_display_prepare_read_queue() anuncia la intención del hilo que llama de leer y asegura que hasta que el hilo esté listo para leer y llame a wl_display_read_events(), ningún otro hilo leerá del descriptor de archivo. Esto solo tiene éxito si la cola de eventos está vacía, y si no, se devuelve -1 y errno se establece en EAGAIN.

Si un hilo llama con éxito a wl_display_prepare_read_queue(), debe llamar a wl_display_read_events() cuando esté listo o cancelar la intención de lectura llamando a wl_display_cancel_read().

Use esta función antes de realizar sondeos en el descriptor de archivo de la pantalla o integrar el descriptor de archivo en un bucle de eventos de un toolkit de manera libre de condiciones de carrera. Un uso correcto sería (dejando fuera la mayoría de las comprobaciones de errores):

while (wl_display_prepare_read_queue(display, queue) != 0)
        wl_display_dispatch_queue_pending(display, queue);
wl_display_flush(display);
ret = poll(fds, nfds, -1);
if (has_error(ret))
        wl_display_cancel_read(display);
else
        wl_display_read_events(display);
wl_display_dispatch_queue_pending(display, queue);

Aquí llamamos a wl_display_prepare_read_queue(), que asegura que entre la devolución de esa llamada y la eventual llamada a wl_display_read_events(), ningún otro hilo leerá del descriptor de archivo y pondrá eventos en nuestra cola. Si la llamada a wl_display_prepare_read_queue() falla, enviamos los eventos pendientes y volvemos a intentarlo hasta que tengamos éxito.

La función wl_display_prepare_read_queue() no adquiere acceso exclusivo al descriptor de archivo de la pantalla. Solo registra que el hilo que llama a esta función tiene la intención de leer del descriptor de archivo. Cuando todos los lectores registrados llaman a wl_display_read_events(), solo uno (al azar) finalmente lee y pone en cola los eventos y los demás duermen mientras tanto. De esta manera, evitamos condiciones de carrera y aún podemos leer desde más hilos.

int wl_display_read_events (struct wl_display * display)

Leer eventos del descriptor de archivo de la pantalla

Parámetros

display El objeto de contexto de pantalla

Devuelve

0 en caso de éxito o -1 en caso de error. En caso de error, errno se establecerá en consecuencia

Llamar a esta función provocará la lectura de los datos disponibles en el descriptor de archivo de la pantalla y los eventos de lectura se pondrán en cola en sus respectivas colas de eventos.

Antes de llamar a esta función, dependiendo del hilo desde el que se vaya a llamar, se debe haber llamado a wl_display_prepare_read_queue() o wl_display_prepare_read(). Consulte wl_display_prepare_read_queue() para obtener más detalles.

Cuando se llama en un punto donde otros hilos se han preparado para leer (usando wl_display_prepare_read_queue() o wl_display_prepare_read()), esta función dormirá hasta que todos los demás hilos preparados se hayan cancelado (usando wl_display_cancel_read()) o ellos mismos hayan entrado en esta función. El último hilo que llame a esta función leerá y pondrá en cola los eventos en sus respectivas colas de eventos, y finalmente despertará a todas las demás llamadas a wl_display_read_events(), haciendo que devuelvan.

Si un hilo cancela una preparación de lectura cuando todos los demás hilos que se han preparado para leer han llamado a wl_display_cancel_read() o han llamado a wl_display_read_events(), todos los hilos lectores devolverán sin haber leído ningún dato.

Para enviar eventos que puedan haberse puesto en cola, llame a wl_display_dispatch_pending() o wl_display_dispatch_queue_pending().

Detailed Description

The wl_display object is the core Wayland server object. It represents the Wayland server itself. It manages clients, globals, and the event loop.

A new display object is created with wl_display_create(). The display should be added to the Wayland protocol by binding sockets using wl_display_add_socket() or wl_display_add_socket_auto(). The display then needs to be added to an event loop using wl_display_get_event_loop() and run using wl_display_run().

When the display is no longer needed, it should be destroyed using wl_display_destroy().

The display object can be associated with arbitrary user data using wl_display_set_user_data() and retrieved using wl_display_get_user_data().

Signals are available for various display events:

struct wl_priv_signal wl_display::create_client_signal

This signal is emitted just before a new client is accepted. The signal's data is the new struct wl_client*.

struct wl_priv_signal wl_display::destroy_signal

This signal is emitted just before the display is destroyed. The signal's data is the struct wl_display* being destroyed.

bool wl_display::run

This field controls whether the display is running or not. Setting it to false will cause wl_display_run() to return.

uint32_t wl_display::serial

This holds the next serial number to be used for events. It is incremented by wl_display_next_serial().

int wl_display::terminate_efd

This holds a file descriptor that, when written to, will cause wl_display_run() to return. It is set up by wl_display_run() and can be written to by calling wl_display_terminate().

void wl_display_set_global_filter (struct wl_display * display, wl_display_global_filter_func_t filter, void * data)

Set a filter function for global objects

Parameters

display The Wayland display object.
filter The global filter function.
data User data to be associated with the global filter.

Set a filter for the wl_display to advertise or hide global objects to clients. The set filter will be used during wl_global advertisement to determine whether a global object should be advertised to a given client, and during wl_global binding to determine whether a given client should be allowed to bind to a global.

Clients that try to bind to a global that was filtered out will have an error raised.

Setting the filter NULL will result in all globals being advertised to all clients. The default is no filter.

The filter should be installed before any client connects and should always take the same decision given a client and a global. Not doing so will result in inconsistent filtering and broken wl_registry event sequences.

void wl_display_set_max_buffer_size (struct wl_display * display, size_t max_buffer_size)

Adjust the maximum size of the client connection buffers

Parameters

display The display context object
max_buffer_size The maximum size of the connection buffers

Client buffers are unbounded by default. This function sets a limit to the size of the connection buffers.

A value of 0 for max_buffer_size requests the buffers to be unbounded.

The actual size of the connection buffers is a power of two, the requested max_buffer_size is therefore rounded up to the nearest power of two value.

Lowering the maximum size may not take effect immediately if the current content of the buffer does not fit within the new size limit.
