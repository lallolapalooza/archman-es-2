Advertencia

Esto es algo avanzado y complicado. No lo necesitas a menos que realmente sepas lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba acceso al sistema de archivos físico y a los archivos dentro de ese sistema de archivos. Sin embargo, a veces se necesita más potencia que esto. Quizás necesites proporcionar un archivo que esté completamente contenido en RAM, o necesites conectar alguna otra API de E/S de archivos a PhysicsFS, o necesites traducir los bits (quizás tengas un archivo .zip estándar cifrado y necesites descifrarlo sobre la marcha para el desarchivador zip desprevenido).

Un PHYSFS_Io es la interfaz que los Archivos utilizan para obtener datos de archivos. Históricamente, esto se mapeaba a E/S de archivos al sistema de archivos físico, pero a partir de PhysicsFS 2.1, las aplicaciones pueden proporcionar sus propias implementaciones de E/S en tiempo de ejecución.

Esta interfaz no es necesariamente un buen ajuste universal para la E/S. Hay algunos requisitos a tener en cuenta:

  • Solo realizan E/S bloqueantes (al menos, por ahora).
  • Necesitan poder duplicarse. Si tienes un manejador de archivos de fopen(), necesitas poder crear un clon único de él (para que tengamos dos manejadores del mismo archivo que puedan buscar/leer/etc. sin interferir entre sí).
  • Necesitan conocer el tamaño de todo su conjunto de datos.
  • Necesitan poder buscar y rebobinar bajo demanda.

...en resumen, probablemente no vas a escribir una implementación HTTP.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Io sean seguras para hilos por sí mismas. Bajo el capó, donde PhysicsFS las utiliza, la biblioteca proporciona sus propios bloqueos. Si planeas usarlas directamente desde hilos separados, deberías usar mutexes para protegerlas, o no usar el mismo PHYSFS_Io desde dos hilos al mismo tiempo.

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Limpiar y desasignar la instancia de E/S. Liberar recursos asociados, incluido (opaque) si corresponde.

Esta función siempre debe tener éxito: como tal, devuelve void. El sistema puede llamar a tu método flush() antes que a este. Puedes informar un error allí si es necesario. Este método aún puede ser llamado si flush() falla, en cuyo caso tendrás que abandonar los datos no vacantes y otras condiciones de error, y limpiar.

Una vez que se llama a este método para una instancia dada, el sistema asumirá que no es seguro volver a tocar esa instancia y desechará cualquier referencia a ella.

Parámetros

s La instancia de E/S a destruir.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Duplicar esta instancia de E/S. Esto debe resultar en una copia completa de este PHYSFS_Io, que pueda vivir de forma completamente independiente. La copia debe ser capaz de realizar todas sus operaciones sin alterar el original, incluido que cada objeto pueda ser destruido por separado (por lo tanto, por ejemplo: no pueden compartir un manejador de archivos; cada uno necesita el suyo).

Si no puedes duplicar un manejador, es legal devolver NULL, pero casi con certeza necesitarás esta funcionalidad si quieres usar este PHYSFS_Io para respaldar un archivo.

Parámetros

io La instancia de E/S a duplicar.

Devoluciones

Un nuevo valor para el campo (opaque) de un flujo, o NULL en caso de error.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vaciar recursos a los medios, o donde sea. Esta es la oportunidad de informar un error para escrituras que habían reclamado éxito anteriormente, pero que aún tenían la posibilidad de fallar. Este método puede ser NULL si el vaciado no es necesario.

Esta función puede ser llamada antes de destroy(), ya que puede informar de errores y destroy() no puede. Puede ser llamada en otros momentos también.

Parámetros

io La instancia de E/S a vaciar.

Devoluciones

Cero en caso de error, distinto de cero en caso de éxito.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Determinar el tamaño del conjunto de datos de la instancia de E/S. Devolver el número de bytes disponibles en el archivo, o -1 si no se puede determinar. Un error casi seguramente será fatal para el uso posterior de este flujo, por lo que no puedes dejar esto sin implementar.

Parámetros

io La instancia de E/S a consultar.

Devoluciones

Tamaño total, en bytes, del conjunto de datos.

void* PHYSFS_Io::opaque

Datos de instancia para esta estructura. Cada instancia tiene un puntero asociado que se puede usar para almacenar lo que quiera. Este puntero es por instancia del flujo, por lo que presumiblemente cambiará al llamar a duplicate(). Esto puede ser desasignado durante el método destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Leer más datos. Leer (len) bytes de la interfaz, en la posición actual de E/S, y almacenarlos en (buffer). La posición actual de E/S debe avanzar el número de bytes leídos con éxito.

No tienes que implementar esto; establécelo en NULL si no está implementado. Esto solo se usará si el archivo se abre para lectura. Si se establece en NULL, se utilizará una implementación predeterminada que informa inmediatamente un error.

Parámetros

io La instancia de E/S de la que leer.
buf El búfer para almacenar los datos. Debe tener al menos (len) bytes de longitud y no puede ser NULL.
len El número de bytes a leer de la interfaz.

Devoluciones

número de bytes leídos del archivo, 0 en EOF, -1 si el fallo es completo.

physfs.3.en - PHYSFS_Io

NAME

PHYSFS_Io - an interface for platform-agnostic i/o.

SYNOPSIS

struct PHYSFS_Io

{
  PHYSFS_sint64 (*read) (struct PHYSFS_Io *io, void *buffer,
                         PHYSFS_uint64 len);
  PHYSFS_sint64 (*write) (struct PHYSFS_Io *io, const void *buffer,
                          PHYSFS_uint64 len);
  PHYSFS_sint64 (*seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset);
  PHYSFS_sint64 (*tell) (struct PHYSFS_Io *io);
  PHYSFS_uint32 version;
};

Detailed Description

This is the core interface for input/output in PhysFS. If you want to mount archives, you will need to implement this interface to let PhysFS know how to read from and write to your archives.

PhysFS provides default implementations for read, write, and seek if you choose to use PHYSFS_mount() with a simple file on disk. These default implementations will handle the actual file i/o for you.

Field Documentation

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buffer, PHYSFS_uint64 len)

Read more data. Read up to (len) bytes from the interface into (buffer). The current i/o position should move ahead by the number of bytes successfully read.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for reading. If set to NULL, a default implementation that immediately reports failure will be used.

Parameters

io The i/o instance to read from.
buffer The buffer to read data into. It must be at least (len) bytes long and can't be NULL.
len The maximum number of bytes to read into (buffer).

Returns

number of bytes read, or -1 if an error occurred.

PHYSFS_sint64(* PHYSFS_Io::seek) (struct PHYSFS_Io *io, PHYSFS_uint64 offset)

Set the current i/o position. Sets the new byte offset for the i/o position. If the new position is invalid, it will be treated as an error condition.

Parameters

io The i/o instance to seek.
offset The new byte offset for the i/o position.

Returns

non-zero on success, zero on error.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Report current i/o position. Return bytes offset, or -1 if you aren't able to determine. A failure will almost certainly be fatal to further use of this stream, so you may not leave this unimplemented.

Parameters

io The i/o instance to query.

Returns

The current byte offset for the i/o position, -1 if unknown.

PHYSFS_uint32 PHYSFS_Io::version

Binary compatibility information. This must be set to zero at this time. Future versions of this struct will increment this field, so we know what a given implementation supports. We'll presumably keep supporting older versions as we offer new features, though.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Write more data. Write (len) bytes from (buffer) to the interface at the current i/o position. The current i/o position should move ahead by the number of bytes successfully written.

You don't have to implement this; set it to NULL if not implemented. This will only be used if the file is opened for writing. If set to NULL, a default implementation that immediately reports failure will be used.

You are allowed to buffer; a write can succeed here and then later fail when flushing. Note that PHYSFS_setBuffer() may be operating a level above your i/o, so you should usually not implement your own buffering routines.

Parameters

io The i/o instance to write to.
buffer The buffer to read data from. It must be at least (len) bytes long and can't be NULL.
len The number of bytes to read from (buffer).

Returns

number of bytes written to file, -1 if complete failure.
