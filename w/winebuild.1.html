WINEBUILD(1) Manual de Desarrolladores de Wine WINEBUILD(1)

NOMBRE

winebuild - Constructor de DLL de Wine

SINOPSIS

winebuild [opciones] [archivo_entrada...]

DESCRIPCIÓN

winebuild genera los archivos de ensamblaje que son necesarios para construir una DLL de Wine, que es básicamente una DLL Win32 encapsulada dentro de una biblioteca Unix.

winebuild tiene diferentes modos, dependiendo de qué tipo de archivo se le pida generar. El modo se especifica mediante una de las opciones de modo indicadas a continuación. Además de la opción de modo, se pueden especificar varias otras opciones de línea de comandos, como se describe en la sección OPCIONES.

OPCIONES DE MODO

Debe especificar exactamente una de las siguientes opciones, dependiendo de lo que quiera que genere winebuild.

--dll
Construye un archivo de ensamblaje a partir de un archivo .spec (ver SINTAXIS DE ARCHIVOS SPEC para más detalles) o de un archivo .def estándar de Windows. El archivo .spec/.def se especifica mediante la opción -E. El archivo resultante debe ser ensamblado y enlazado con los demás archivos objeto para construir una DLL de Wine funcional. En este modo, los archivos de entrada deben ser la lista de todos los archivos objeto que se enlazarán en la DLL final, para permitir a winebuild obtener la lista de todos los símbolos indefinidos que necesitan ser importados de otras DLL.
--exe
Construye un archivo de ensamblaje para un ejecutable. Esto es básicamente lo mismo que el modo --dll, excepto que no requiere un archivo .spec/.def como entrada, ya que un ejecutable no necesita exportar funciones. Sin embargo, algunos ejecutables sí exportan funciones, y para ellos se puede especificar un archivo .spec/.def mediante la opción -E. El ejecutable se nombra a partir del nombre del archivo .spec/.def si está presente, o explícitamente a través de la opción -F. El archivo resultante debe ser ensamblado y enlazado con los demás archivos objeto para construir un ejecutable de Wine funcional, y todos los demás archivos objeto deben listarse como archivos de entrada.
--def
Construye un archivo .def a partir de un archivo spec. El archivo .spec se especifica mediante la opción -E. Esto se utiliza al construir DLL con un compilador PE (Win32).
--implib
Construye una biblioteca de importación .a a partir de un archivo spec. El archivo .spec se especifica mediante la opción -E. Si el nombre de la biblioteca de salida termina en .delay.a, se construye una biblioteca de importación retardada.
--staticlib
Construye una biblioteca estática .a a partir de archivos objeto.
--resources
Genera un archivo .o que contiene todos los recursos de entrada. Esto es útil al construir con un compilador PE, ya que las utilidades binarias PE no pueden manejar múltiples archivos de recursos como entrada. Para una construcción Unix estándar, los archivos de recursos se incluyen automáticamente al construir el archivo spec, por lo que no hay necesidad de un archivo .o intermedio.
--builtin
Marca un módulo PE como un módulo integrado de Wine, añadiendo la cadena de firma "Wine builtin DLL" después de la cabecera DOS.
--fixup-ctors
Corrige los constructores después de que se ha construido un módulo. Esto debe hacerse en el módulo .so final si su código contiene constructores, para asegurar que Wine tenga la oportunidad de inicializar el módulo antes de que se ejecuten los constructores.

OPCIONES

--as-cmd=comando_as
Especifica el comando a usar para compilar archivos de ensamblaje; el valor predeterminado es as.
-b, --target=cpu-fabricante[-kernel]-os
Especifica la CPU y la plataforma de destino en las que se construirá el código generado. La especificación de destino está en el formato estándar de autoconf tal como lo devuelve config.sub.
-B directorio
Añade el directorio a la ruta de búsqueda de las diversas herramientas binutils como as, nm y ld.
--cc-cmd=comando_cc
Especifica el compilador C a usar para compilar archivos de ensamblaje; el valor predeterminado es usar en su lugar el ensamblador especificado con --as-cmd.
--data-only
Construye un módulo que contiene solo datos y recursos, y ningún código ejecutable. Con esta opción, winebuild genera directamente un archivo PE, en lugar de un archivo de ensamblaje u objeto.
-d, --delay-lib=nombre
Establece el modo de importación retardada para la biblioteca especificada, la cual debe ser una de las bibliotecas importadas con la opción -l. El modo retardado significa que la biblioteca no se cargará hasta que se llame a una función importada de ella.
-D simbolo
Ignorado por compatibilidad con el compilador C.
--disable-dynamicbase
Desactiva la aleatorización del diseño del espacio de direcciones 'ASLR' en la imagen ejecutable. El valor predeterminado es 'ASLR' activado.
-e, --entry=funcion
Especifica la función de punto de entrada del módulo; si no se especifica, el valor predeterminado es DllMain para DLL y main para ejecutables (si el main estándar de C no está definido, se usa WinMain en su lugar). Esto solo es válido para módulos Win32.
-E, --export=nombre_archivo
Especifica un archivo .spec (ver SINTAXIS DE ARCHIVOS SPEC para más detalles) o un archivo .def estándar de Windows que define las exportaciones de la DLL o ejecutable que se está construyendo.
--external-symbols
Permite enlazar con símbolos externos directamente desde el archivo spec. Normalmente, los símbolos exportados por una DLL tienen que definirse en la propia DLL; esta opción hace posible usar símbolos definidos en otra biblioteca Unix (para símbolos definidos en otra DLL, se debe usar una especificación de reenvío en su lugar).
-f opción
Especifica una opción de generación de código. Actualmente se admiten -fPIC y -fasynchronous-unwind-tables. Otras opciones se ignoran por compatibilidad con el compilador C.
--fake-module
Crea un módulo PE falso para una DLL o ejecutable, en lugar del archivo de ensamblaje u objeto normal. El módulo PE contiene los recursos para el módulo, pero ningún código ejecutable.
-F, --filename=nombre_archivo
Establece el nombre del archivo del módulo. El valor predeterminado es usar el nombre base del archivo spec (sin ninguna extensión).
-h, --help
Muestra un mensaje de uso y sale.
-H, --heap=tamaño
Especifica el tamaño del montón local del módulo en bytes (solo válido para módulos Win16); el valor predeterminado es sin montón local.
-I directorio
Ignorado por compatibilidad con el compilador C.
-k, --kill-at
Elimina las decoraciones stdcall de los nombres de símbolos en el archivo .def generado. Solo tiene significado en modo --def.
-K flags
Ignorado por compatibilidad con el compilador C.
--large-address-aware
Establece una bandera en el ejecutable para notificar al cargador que esta aplicación es compatible con espacios de direcciones mayores a 2 gigabytes.
--ld-cmd=comando_ld
Especifica el comando a usar para enlazar los archivos objeto; el valor predeterminado es ld.
-m16, -m32, -m64
Genera respectivamente código de 16, 32 o 64 bits.
-march=opción, -mcpu=opción<

OPTIONS

-mfpu=option
Establece las opciones de generación de código para el ensamblador.
-mno-cygwin
Compila una biblioteca que utiliza el runtime de Windows en lugar de la biblioteca C de Unix.
-M, --main-module=module
Al compilar un dll de 16 bits, establece el nombre de su contraparte de 32 bits a module. Esto se utiliza para forzar que el orden de carga del dll de 16 bits coincida con el del de 32 bits.
-N, --dll-name=dllname
Establece el nombre interno del módulo. Solo se utiliza en módulos Win16. El valor predeterminado es usar el nombre base del archivo spec (sin ninguna extensión). Esto se utiliza para KERNEL, ya que reside en KERNEL386.EXE. No debería ser necesario de otra manera.
--nm-cmd=nm-command
Especifica el comando a utilizar para obtener la lista de símbolos indefinidos; el valor predeterminado es nm.
--nxcompat=yes|no
Especifica si el módulo es compatible con la compatibilidad no-ejecución. El valor predeterminado es sí.
-o, --output=file
Establece el nombre del archivo de salida (el valor predeterminado es la salida estándar). Si el nombre del archivo de salida termina en .o, la salida de texto se envía a un archivo temporal que luego se ensambla para producir el archivo .o especificado.
--prefer-native
Especifica que se debe preferir el DLL nativo si está disponible en tiempo de ejecución. Esto se puede usar en módulos que están mayormente sin implementar.
-r, --res=rsrc.res
Carga recursos del archivo de recursos binarios especificado. El archivo rsrc.res puede ser producido a partir de un archivo de recursos fuente con wrc(1) (o con un compilador de recursos de Windows).
Esta opción solo es necesaria para archivos de recursos Win16, los de Win32 simplemente pueden listarse como archivos de entrada y se manejarán automáticamente correctamente (aunque la opción -r también funcionará para archivos Win32).
--safeseh
Marca los archivos objeto como compatibles con SEH.
--save-temps
No elimina los diversos archivos temporales que genera winebuild.
--strip-cmd=strip-command
Especifica el comando a usar para eliminar módulos PE. Solo tiene sentido en modo --builtin.
--subsystem=subsystem[:major[.minor]]
Establece el subsistema del ejecutable, que puede ser uno de los siguientes:
console para un ejecutable de línea de comandos,
windows para un ejecutable gráfico,
native para un DLL en modo nativo,
wince para un DLL de CE.
El punto de entrada de un ejecutable de línea de comandos es una función C normal main. Se puede usar una función wmain en su lugar si necesita que la matriz de argumentos use cadenas Unicode. Un ejecutable gráfico tiene un punto de entrada WinMain.
Opcionalmente, también se puede especificar una versión principal y secundaria del subsistema; la versión predeterminada del subsistema es 4.0.
-u, --undefined=symbol
Agrega symbol a la lista de símbolos indefinidos al invocar el enlazador. Esto hace posible forzar la inclusión de un módulo específico de una biblioteca estática al resolver importaciones.
-v, --verbose
Muestra los diversos subcomandos que está invocando winebuild.
--version
Muestra la versión del programa y sale.
-w, --warnings
Activa las advertencias.
--without-dlltool
Genera una biblioteca de importación sin usar dlltool.

SINTAXIS DE ARCHIVO SPEC

Sintaxis general

Un archivo spec debe contener una lista de declaraciones ordinales. La sintaxis general es la siguiente:

ordinal functype [flags] exportname ( [args...] ) [handler]
ordinal variable [flags] exportname ( [data...] )
ordinal extern [flags] exportname [symbolname]
ordinal stub [flags] exportname [ (args...) ]
ordinal equate [flags] exportname data
# comentarios

Las declaraciones deben caber en una sola línea, excepto si el final de línea se escapa usando un carácter de barra invertida. El carácter # en cualquier parte de una línea hace que el resto de la línea se ignore como comentario.

ordinal especifica el número ordinal correspondiente al punto de entrada, o '@' para la asignación automática de ordinales (solo Win32).

flags es una serie de indicadores opcionales, precedidos por un carácter '-'. Los indicadores compatibles son:

-norelay
El punto de entrada no se muestra en los rastreos de depuración de retransmisión (solo Win32).
-noname
El punto de entrada se exportará por ordinal en lugar de por nombre. El nombre todavía está disponible para la importación.
-ret16
La función devuelve un valor de 16 bits (solo Win16).
-ret64
La función devuelve un valor de 64 bits (solo Win32).
-register
La función utiliza registros de CPU para pasar argumentos.
-private
La función no puede ser importada desde otros DLLs, solo se puede acceder a ella a través de GetProcAddress.
-ordinal
El punto de entrada se importará por ordinal en lugar de por nombre. El nombre todavía se exporta.
-thiscall
La función utiliza la convención de llamada thiscall (primer parámetro en el registro %ecx en i386).
-fastcall
La función utiliza la convención de llamada fastcall (primeros dos parámetros en los registros %ecx/%edx en i386).
-syscall[=number]
La función es una llamada al sistema NT. Se generará un thunk de llamada al sistema, y la función real será llamada por la función __wine_syscall_dispatcher en ntdll. El número de llamada al sistema se puede especificar explícitamente; por defecto se asignará secuencialmente a partir de 0.
-import
La función se importa de otro módulo. Esto se puede usar en lugar de una especificación forward cuando una aplicación espera encontrar la implementación de la función dentro del DLL.
-arch=[!]cpu[,cpu]
El punto de entrada solo está disponible en las arquitecturas de CPU especificadas. Los nombres win32 y win64 coinciden con todas las arquitecturas de CPU de 32 o 64 bits respectivamente. En DLLs de 16 bits, especificar -arch=win32 hace que el punto de entrada se exporte desde el módulo wrapper de 32 bits. Un nombre de CPU puede ser precedido por ! para excluir solo esa arquitectura específica.

Ordinales de función

Sintaxis:
ordinal functype [flags] exportname ( [args...] ) [handler]

Esta declaración define un punto de entrada de función. El prototipo definido por exportname ( [args...] ) especifica el nombre disponible para el enlace dinámico y el formato de los argumentos. '@' se puede usar en lugar de exportname para exportaciones solo ordinales.

functype debe ser uno de:

stdcall
para una función Win32 normal
pascal
para una función Win16 normal
cdecl
para una función Win16 o Win32 que utiliza la convención de llamada C
varargs
para una función Win16 o Win32 que utiliza la convención de llamada C con un número variable de argumentos

args debe ser uno o varios de:

word
(valor sin signo de 16 bits)
s_word
(palabra con signo de 16 bits)
long
(valor entero de tamaño puntero)
int64
(valor entero de 64 bits)
int128
(valor entero de 128 bits)
float
(valor de punto flotante de 32 bits)
double
(valor de punto flotante de 64 bits)
ptr
(puntero lineal)
str
(puntero lineal a una cadena ASCII terminada en nulo)
wstr
(puntero lineal a una cadena Unicode terminada en nulo)
segptr
(puntero segmentado)
