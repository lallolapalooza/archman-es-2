DESCRIPCIÓN

wimlib-imagex se encarga de archivos de tipo archivo en el formato Windows Imaging (WIM). Su interfaz es similar a la de ImageX de Microsoft, pero wimlib-imagex es multiplataforma y tiene útiles mejoras y extensiones.

Para realizar su trabajo, wimlib-imagex utiliza wimlib, una biblioteca C de código abierto que proporciona interfaces para manipular archivos WIM. wimlib es completamente independiente de la implementación equivalente de Microsoft (WIMGAPI, o wimgapi.dll). Puedes usar wimlib en tus propios programas, aunque para uso en línea de comandos wimlib-imagex ya proporciona acceso a la mayoría de las funcionalidades de wimlib.

INFORMACIÓN DE ANTECEDENTES

El formato Windows Imaging (WIM) fue diseñado por Microsoft principalmente para archivar sistemas de archivos de Windows, como NTFS. Sin embargo, también se puede usar en otras plataformas, con algunas limitaciones. Un archivo WIM contiene una o más imágenes, cada una de las cuales es un árbol de directorios lógicamente independiente. Las imágenes se indexan a partir de 1, y cada una puede tener también un nombre. Los datos de los archivos se almacenan como "blobs" direccionables por contenido que se desduplican en todo el archivo. Los datos pueden comprimirse utilizando uno de varios algoritmos de compresión.

Una actualización del formato WIM que Microsoft lanzó con Windows 8 utiliza compresión LZMS en modo sólido para lograr una mejor relación de compresión. Estos archivos también se denominan "archivos ESD" y pueden tener la extensión .esd en lugar de .wim. wimlib admite completamente estos archivos, excepto cuando están cifrados.

COMANDOS

wimlib-imagex acepta uno de varios comandos (listados anteriormente en SINOPSIS), y argumentos adicionales dependiendo del comando específico. Aunque wimlib-imagex mostrará información de uso con --help o si lo invoca incorrectamente, la documentación completa para cada comando de wimlib-imagex se puede encontrar en la página del manual correspondiente.

Nota: si se han instalado los enlaces duros o scripts por lotes apropiados, un comando wimlib-imagex COMANDO también se puede acceder simplemente como wimCOMANDO; por ejemplo, wimapply para wimlib-imagex apply. Por brevedad, la documentación utiliza los nombres más cortos.

CARACTERÍSTICAS DETALLADAS

Esta sección presenta algunas de las características interesantes de wimlib-imagex con más detalle.

•
Soporte multiplataforma. wimlib-imagex es compatible tanto en sistemas tipo UNIX (principalmente Linux, pero también FreeBSD, Mac OS X, etc.) como en Windows. La mayor parte del código se comparte entre todas las plataformas, pero las características específicas de la plataforma todavía se admiten cuando es posible.
•
Compresión y descompresión XPRESS, LZX y LZMS. wimlib contiene implementaciones avanzadas de todos estos algoritmos de compresión. Estos han sido mejorados con el tiempo y ahora suelen superar y comprimir más que sus equivalentes de Microsoft, a la vez que permanecen totalmente compatibles.
•
Soporte de compresión en modo sólido, o "archivo ESD". Los "archivos ESD" son un formato WIM actualizado que utiliza LZMS en modo sólido para lograr una mejor relación de compresión.
•
Compresión multihilo. Por defecto, la compresión de datos de wimlib es multihilo y utilizará todos los procesadores disponibles.
•
En sistemas tipo UNIX, integración con libntfs-3g que permite capturar una imagen WIM directamente desde un volumen NTFS, o aplicar una imagen WIM directamente a un volumen NTFS. Esto permite guardar y restaurar datos y metadatos específicos de NTFS, como descriptores de seguridad y flujos de datos con nombre, que de otro modo solo serían compatibles en Windows.
•
En sistemas tipo UNIX, soporte opcional para guardar y restaurar permisos de archivos UNIX estándar (propietario/grupo/modo), archivos especiales UNIX y atributos extendidos. (Esta es una extensión de wimlib; el software WIM de Microsoft ignora esta información adicional.)
•
En Linux, soporte para montar imágenes WIM con FUSE (Filesystem in UserSpacE), tanto en modo de solo lectura como de lectura/escritura.
•
WIMs divididos. Un WIM dividido es un archivo WIM que se divide en varias partes. wimsplit puede crear un WIM dividido a partir de un WIM independiente, y wimjoin puede crear un WIM independiente a partir de un WIM dividido.
•
WIMs delta. Un WIM delta contiene metadatos de imagen pero excluye los datos de archivos que ya están presentes en otro archivo WIM. Un WIM delta se puede crear usando wimcapture con la opción --delta-from.
•
WIMs "pipeable". Como extensión de wimlib (no compatible con la implementación de Microsoft), wimcapture soporta la captura de un archivo WIM a la salida estándar en un formato especial "pipeable" que luego puede ser aplicado enviándolo a wimapply en la entrada estándar. Entre otras cosas, esto se puede usar para enviar imágenes hacia o desde un servidor a través de la red para implementar imágenes y restauraciones rápidas del sistema de archivos.

CARACTERÍSTICAS DETALLADAS

•
Soporte de metadatos de imagen específicos de Windows. Al capturar una imagen de un sistema operativo Windows, wimlib poblará automáticamente campos de metadatos XML como los detalles de la versión del sistema operativo Windows escaneando archivos del sistema conocidos.
•
Soporte de WIMBoot. En Windows 8.1 y versiones posteriores, los archivos pueden ser "respaldados externamente" por un archivo WIM con la ayuda del controlador de filtro de Windows Overlay Filesystem (WOF) de Microsoft. Con la opción --wimboot, wimapply extraerá "archivos puntero" al archivo WIM en lugar de los archivos mismos.
•
Soporte de instantáneas de VSS. En Windows, wimcapture o wimappend con la opción --snapshot crearán automáticamente una instantánea temporal de VSS y capturarán la imagen de ella. Esto se puede utilizar para crear imágenes de un sistema Windows "en vivo".
•
Soporte de rutas largas en Windows. wimlib-imagex puede capturar y aplicar archivos con rutas que exceden la limitación MAX_PATH (260 caracteres) del subsistema Win32.
•
Soporte sin administrador en Windows. Puede ejecutar wimlib-imagex sin derechos de administrador, sujeto a algunas limitaciones.

SENSIBILIDAD A MAYÚSCULAS/MINÚSCULAS

Por defecto, la sensibilidad a mayúsculas/minúsculas de wimlib-imagex difiere ligeramente entre los sistemas tipo UNIX y Windows. Las imágenes WIM pueden (pero generalmente no lo hacen) tener múltiples archivos con el mismo nombre insensible a mayúsculas/minúsculas. Internamente, wimlib almacena los nombres de archivo como sensibles a mayúsculas/minúsculas, pero en Windows las rutas proporcionadas por el usuario para su uso en una imagen WIM (por ejemplo, para extraer, añadir, renombrar o eliminar archivos) se tratarán por defecto como insensibles a mayúsculas/minúsculas para obtener el comportamiento "esperado". Esto difiere del comportamiento por defecto en sistemas tipo UNIX, donde dichas rutas se tratarán como sensibles a mayúsculas/minúsculas.

Tenga en cuenta que con la insensibilidad a mayúsculas/minúsculas, un componente de ruta puede ser ambiguo debido a que varios archivos o directorios tienen el mismo nombre insensible a mayúsculas/minúsculas. En tales casos, si existe un archivo o directorio con un nombre que coincide exactamente, se elige; de lo contrario, se elige arbitrariamente uno de los archivos o directorios que coinciden de forma insensible a mayúsculas/minúsculas.

La sensibilidad a mayúsculas/minúsculas por defecto de wimlib-imagex puede ser anulada estableciendo explícitamente la variable de entorno WIMLIB_IMAGEX_IGNORE_CASE a 1, en cuyo caso dichas rutas se tratarán de forma insensible a mayúsculas/minúsculas, o a 0, en cuyo caso dichas rutas se tratarán de forma sensible a mayúsculas/minúsculas.

Independientemente de estas configuraciones, las opciones y los argumentos que no son rutas deben especificarse en minúsculas.
