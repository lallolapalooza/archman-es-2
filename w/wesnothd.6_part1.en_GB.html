WESNOTHD(6) Demonio de red multijugador de Battle for Wesnoth WESNOTHD(6)

NOMBRE

wesnothd - Demonio de red multijugador de Battle for Wesnoth

SINOPSIS

wesnothd [-dv] [-c ruta] [-p puerto] [-t número] [-T número]
wesnothd -V

DESCRIPCIÓN

Gestiona las partidas multijugador de Battle for Wesnoth. Consulta https://www.wesnoth.org/wiki/ServerAdministration para ver qué comandos acepta el servidor a través del cliente de Wesnoth (/query ...) o el fifo.

OPCIONES

-c ruta, --config ruta
indica a wesnothd dónde encontrar el archivo de configuración a utilizar. Consulta la sección CONFIGURACIÓN DEL SERVIDOR más abajo para ver la sintaxis. Puedes recargar la configuración enviando SIGHUP al proceso servidor.
-d, --daemon
ejecuta wesnothd como un demonio.
-h, --help
indica qué hacen las opciones de la línea de comandos.
--log-nivel=dominio1,dominio2,...
establece el nivel de severidad de los dominios de registro. all se puede usar para coincidir con cualquier dominio de registro. Niveles disponibles: error, warning, info, debug. Por defecto, se utiliza el nivel error y el nivel info para el dominio server.
-p puerto, --port puerto
enlaza el servidor al puerto especificado. Si no se especifica ningún puerto, se usará el puerto 15000.
-t número, --threads número
establece el número máximo de hilos de trabajo en espera para E/S de red a n (predeterminado: 5, máx.: 30).
-T número, --max-threads número
establece el número máximo de hilos de trabajo que se crearán. Si se establece en 0, no habrá límite (predeterminado: 0).
-V, --version
muestra el número de versión y sale.
-v, --verbose
activa el registro de depuración.

CONFIGURACIÓN DEL SERVIDOR

La sintaxis general es:

[etiqueta]

clave="valor"
clave="valor,valor,..."

[/etiqueta]

Claves globales:

allow_remote_shutdown
Si se establece en no (predeterminado), se ignoran las solicitudes de apagado (`shut_down`) y reinicio (`restart`), a menos que provengan del fifo. Establécelo en yes para permitir el apagado remoto a través de un /query de un administrador.
ban_save_file
Ruta completa o relativa a un archivo (comprimido con gzip) que el servidor puede leer y escribir. Los baneos se guardarán en este archivo y se volverán a leer al iniciar el servidor.
compress_stored_rooms
Determina si el archivo de salas (`rooms`) debe leerse y escribirse en formato comprimido. El valor predeterminado es yes.
connections_allowed
El número de conexiones permitidas desde la misma IP. 0 significa infinito. (predeterminado: 5)
deny_unregistered_login
Si se deben impedir los inicios de sesión de usuarios que no estén registrados con el manejador de usuarios (`user_handler`) que se esté utilizando. (predeterminado: `false`)
disallow_names
Nombres/nicks que no son aceptados por el servidor. Se admiten patrones de comodines * y ?. Consulta glob(7) para más detalles. Los valores predeterminados (que se usan si no se especifica nada) son: *admin*,*admln*,*server*,ai,ai?,computer,human,network,player.
fifo_path
La ruta al fifo en el que puedes escribir comandos del servidor (igual que `/query ...` desde wesnoth). Se utiliza la ruta definida en tiempo de compilación por defecto si no se especifica (predeterminado: /var/run/wesnothd/socket).
max_messages
El número máximo de mensajes permitidos en messages_time_period. (predeterminado: 4)
messages_time_period
El período de tiempo (en segundos) en el que se detecta el envío excesivo de mensajes. (predeterminado: 10 segundos)
motd
El mensaje del día (Message Of The Day).
new_room_policy
Determina quién puede crear nuevas salas en el servidor. Los valores disponibles son everyone, registered, admin y nobody, y otorgan el permiso respectivamente a todos, usuarios registrados, usuarios administradores o deshabilitan la creación de nuevas salas. El valor predeterminado es everyone.
passwd
La contraseña utilizada para obtener privilegios de administrador (a través de `/query admin contraseña`).
replay_save_path
El directorio donde el servidor almacena las repeticiones de las partidas. (¡No olvides la barra final `/`!) Por defecto está vacío (`'`), lo que significa el directorio desde el que se inició wesnothd.
restart_command
El comando que utiliza el servidor para iniciar un nuevo proceso de servidor a través del comando restart. (Solo se puede ejecutar a través del fifo. Consulta la configuración de allow_remote_shutdown).
room_save_file
Ruta a un archivo donde se debe almacenar la información de las salas. Este archivo se lee al iniciar el servidor y se escribe más tarde. Si está vacío o no está configurado, las salas no se cargan ni se guardan.
save_replays
Define si el servidor guardará automáticamente las repeticiones de las partidas. (predeterminado: false)
tls_enabled
Habilita el uso de TLS. Si es `true`, requiere que las 3 opciones siguientes también estén establecidas.
tls_fullchain
Cadena completa de certificados TLS en formato .pem
tls_private_key
Clave privada para TLS en formato .pem
tls_dh
Parámetros DH de TLS, como archivo .pem. Generar con openssl dhparam -out nombre_archivo.pem 4096
versions
Lista de versiones del cliente que el servidor acepta. Las versiones se comparan como números de versión de Wesnoth. Por ejemplo, la entrada "1.16" coincide con todas las versiones desde 1.16.0 hasta 1.17.0. Por defecto, se aceptan todas las versiones.
