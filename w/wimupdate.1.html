WIMUPDATE(1) User Commands WIMUPDATE(1)

NOMBRE

wimupdate - Actualizar una imagen WIM

SINOPSIS

wimupdate ARCHIVO WIM [IMAGEN] [OPCION...] [< ARCHIVO COMANDO]

DESCRIPCIÓN

wimupdate, o equivalentemente wimlib-imagex update, modifica la IMAGEN especificada en el archivo ARCHIVO WIM de Windows Imaging (WIM) añadiendo, eliminando o renombrando archivos o directorios en él.

IMAGEN especifica la imagen en ARCHIVO WIM a actualizar. Puede ser el índice basado en 1 de una imagen o el nombre de una imagen. Puede omitirse si ARCHIVO WIM contiene solo una imagen. Puede usar wiminfo(1) para listar las imágenes contenidas en ARCHIVO WIM.

Las modificaciones a realizar en la imagen WIM se especifican como una secuencia de comandos, una por línea, leídas de un archivo de texto (codificado en UTF-8 o UTF-16LE; ASCII plano también está bien) desde la entrada estándar. Se recomienda que la entrada estándar se redirija desde un archivo (ARCHIVO COMANDO), como se muestra arriba, en lugar de escribir los comandos interactivamente. Alternativamente, para especificar un comando directamente en la línea de comandos, consulte la opción --command.

COMANDOS DISPONIBLES

Esta sección documenta los comandos que pueden aparecer en el ARCHIVO COMANDO descrito anteriormente.

add [OPCION...] ORIGEN DESTINO

Añade un archivo o árbol de directorios a la imagen WIM. ORIGEN debe especificar la ruta a un archivo o directorio en su sistema de archivos. DESTINO debe especificar la ruta dentro del WIM en la que añadir el archivo o árbol de directorios.

Si DESTINO nombra un directorio existente en la imagen WIM, entonces ORIGEN también debe nombrar un directorio. Esto causa que el contenido del directorio ORIGEN se añada al directorio DESTINO.

Si DESTINO nombra un archivo no directorio existente en la imagen WIM, entonces ORIGEN también debe nombrar un archivo no directorio. Por defecto, esto causa que el archivo DESTINO sea reemplazado con el archivo ORIGEN. O, con --no-replace especificado, esto genera un error.

Si DESTINO no existe en la imagen WIM, entonces se crearán los directorios preexistentes necesarios para añadir el ORIGEN en esa ubicación.

El comando add soporta un subconjunto de las opciones aceptadas por wimcapture; a saber, --dereference, --unix-data, --no-acls y --strict-acls. Ver wimcapture(1) para explicaciones de estas opciones.

Además, el comando add soporta la opción --no-replace, que causa que el comando add se niegue a sobrescribir archivos no directorio existentes en la imagen WIM.

delete [OPCION...] RUTA

Elimina un archivo o árbol de directorios de la imagen WIM. RUTA debe especificar la ruta dentro de la imagen WIM del archivo o árbol de directorios a eliminar.

Las opciones disponibles para el comando delete son:

--force
No emitir un error si la ruta a eliminar no existe.
--recursive
Eliminar el archivo o árbol de directorios recursivamente; si no se especifica, se emite un error si la ruta a eliminar es un directorio.

rename RUTA_ANTIGUA RUTA_NUEVA

Renombra un archivo o árbol de directorios dentro de la imagen WIM. RUTA_ANTIGUA debe especificar la ruta antigua del archivo o árbol de directorios dentro de la imagen WIM, y RUTA_NUEVA debe especificar la nueva ruta para el archivo o árbol de directorios. Este comando sigue la semántica de la función POSIX rename (3); en particular, un archivo preexistente en RUTA_NUEVA será eliminado si está presente, excepto en ciertos casos como intentar renombrar un directorio a un no directorio, lo cual no está permitido.

No hay opciones disponibles para el comando rename.

OPCIONES

Las siguientes opciones son aceptadas en la línea de comandos por wimupdate mismo:

--dereference
Usar --dereference para todos los comandos add.
--unix-data
Usar --unix-data para todos los comandos add.
--no-acls
Usar --no-acls para todos los comandos add.
--strict-acls
Usar --strict-acls para todos los comandos add.
--no-replace
Usar --no-replace para todos los comandos add.
--config=ARCHIVO
Establece el archivo de configuración de captura para todos los comandos add. Ver la descripción de esta opción en wimcapture(1).
--force
Usar --force para todos los comandos delete.
--recursive
Usar --recursive para todos los comandos delete.
--check
Antes de actualizar el WIM, verifica su integridad si contiene información de integridad adicional. También incluye información de integridad adicional en el WIM actualizado, incluso si no estaba presente antes.
--include-integrity
Incluye información de integridad adicional en el WIM actualizado, es decir, como --check pero sin verificar el WIM de antemano.
--threads=NUM_HILOS
Número de hilos a usar para comprimir archivos recién añadidos. Por defecto: autodetectar (número de procesadores).
--rebuild
Reconstruye todo el WIM en lugar de añadir los datos actualizados al final del mismo. Reconstruir el WIM es más lento, pero ahorrará un poco de espacio que de otro modo quedaría como un hueco en el archivo WIM.
Ver wimoptimize(1) para una forma más personalizable de reconstruir (y opcionalmente recomprimir) un archivo WIM. Si ejecuta wimoptimize después de wimupdate, no es necesario especificar --rebuild a wimupdate.
--command=CADENA
En lugar de leer comandos de actualización de la entrada estándar, lee un único comando de actualización directamente de la cadena CADENA especificada en la línea de comandos. Esta opción no puede proporcionarse más de una vez y no puede usarse para especificar más de un comando de actualización. Tenga en cuenta que la CADENA, así como cualquier ruta que contenga espacios dentro de la CADENA, debe estar debidamente entrecomillada. Si ejecuta desde cmd.exe en Windows, debe usar comillas dobles para las comillas exteriores y comillas simples para las comillas interiores. Ejemplo:
wimupdate boot.wim 1 --command="add 'C:\My Dir' '\My Dir'"
Esta opción se proporciona solo por conveniencia. ¡No ejecute wimupdate varias veces consecutivas, cada vez pasando la opción --command! Esto es ineficiente. En su lugar, genere un archivo de comandos de actualización y proporciónelo (en la entrada estándar) a una única invocación de wimupdate, como se explica en este documento.
--wimboot-config=ARCHIVO
Si se especifica esta opción, no se leerán comandos de la entrada estándar, y en su lugar se ejecutará el siguiente comando:
add ARCHIVO /Windows/System32/WimBootCompress.ini
Esto establece ARCHIVO como el archivo de configuración de WIMBoot para la imagen. La sección [PrepopulateList] de este archivo especifica patrones de ruta que no deben extraerse como archivos puntero de WIMBoot (quizás porque son necesarios al principio del proceso de arranque). Ver la documentación para el --wim

wimupdate(1) — wimlib 1.14.4

NAME

wimupdate - modify an existing WIM image

SYNOPSIS

wimupdate WIMFILE [IMAGENUM] CMDFILE [OPTIONS]...

wimupdate WIMFILE [IMAGENUM] [OPTIONS]... < CMDFILE

DESCRIPTION

The wimupdate utility modifies an existing image within a WIM archive. The modifications are specified by a list of commands in the file CMDFILE, or read from standard input if no file is specified.

If IMAGENUM is specified, it identifies which image within WIMFILE to modify. Images are numbered starting from 1. If it is omitted, then the first image in the WIM archive is modified.

The CMDFILE contains a list of commands, one per line, that specify the operations to perform. For a detailed description of the available commands, see the AVAILABLE COMMANDS section.

By default, wimupdate modifies the WIM archive in-place. If this is not desired, the --rebuild option can be used to create a new WIM archive instead of modifying the existing one.

AVAILABLE COMMANDS

add SRCPATH DSTPATH
Add the file or directory specified by SRCPATH to the WIM image at the location specified by DSTPATH. If DSTPATH is a directory that already exists in the image, then the contents of SRCPATH are added as members of that directory. If DSTPATH specifies a file path and the file does not exist, it will be created. If DSTPATH specifies a file path and the file *does* exist, it will be overwritten.
delete [OPTIONS] PATH
Delete the file or directory specified by PATH from the WIM image. If PATH refers to a directory, it will be deleted recursively by default. Use the --recursive option to explicitly enable or disable recursive deletion.
rename OLDPATH NEWPATH
Rename the file or directory specified by OLDPATH to NEWPATH within the WIM image.
set-comment [PATH]
Set the comment for the WIM image. If PATH is specified, the comment is read from the file PATH. Otherwise, the comment is read from standard input. If no argument is provided and standard input is a TTY, standard input will be read until EOF. This command can only be run once per invocation of wimupdate.
set-description [PATH]
Set the description for the WIM image. Similar to set-comment.
set-flags FLAGS
Set the image flags. FLAGS is a comma-separated list of flags. Supported flags are:
no_compression
Do not compress files in this image.
only_வுகளில்
Only store files that are referenced by multiple other files in the WIM archive.
This command can only be run once per invocation of wimupdate.

OPTIONS

--check
Integrity check the WIM archive after the update. This is equivalent to running wimlib-imagex(1) --check WIMFILE after the update is complete.
--compact
Compact the WIM archive in-place, eliminating "holes". This is an efficient operation, but it may fail if the WIM archive is open for reading by another process. This option implies --rebuild is not used. See also the --unsafe-compact option and the documentation for wimoptimize(1).
--rebuild
Instead of modifying the WIM archive in-place, create a new WIM archive with the modifications. The original WIM archive will not be deleted. This option is slower than in-place updates, but it is safer as it does not risk corrupting the original WIM archive if the update process is interrupted.
--unsafe-compact
Compact the WIM archive in-place and append any new data, eliminating "holes". This is efficient, but in general this option should not be used because a failed or interrupted compaction will corrupt the WIM archive. For more information, see the documentation for this option in wimoptimize(1).
--ref="GLOB"
File glob of WIM(s) on which the delta WIM is based. Updating split WIMs is not allowed, but updating delta WIMs is allowed. When updating a delta WIM, the WIM(s) on which the delta WIM is based should be specified using this option. (It isn't a hard requirement, but it's needed for data deduplication to work fully and for the TOTALBYTES statistic to be correctly updated.)

NOTES

wimupdate can be viewed as redundant with wimmountrw, since a WIM image can also be updated by mounting it read-write. However, wimupdate works on all platforms including Windows, whereas wimmountrw only works on Linux.

Symbolic links inside a WIM image are not dereferenced when being interpreted. So, for example, if you have a WIM image that contains a symbolic link "/Documents and Settings" -> "/Users" where "/Users" is a directory, then a subdirectory named "Public" in this directory must be specified as "/Users/Public" rather than "/Documents and Settings/Public".

All paths to files or directories within the WIM image must be specified relative to the root of the image. However, the leading slash is optional, and both forward slashes and backslashes are accepted. In addition, on Windows, the paths are by default treated case-insensitively, while on UNIX-like systems, the paths are by default treated case-sensitively. The default case sensitivity may be changed by setting the WIMLIB_IMAGEX_IGNORE_CASE environmental variable to 0 or 1.

The command file (CMDFILE) is parsed by wimupdate itself and not by the system shell. Therefore, its syntax is limited. However, comment lines beginning with '#' are allowed, and it is also possible to quote arguments with whitespace inside them.

On UNIX-like systems, you cannot use wimupdate to add files to an image directly from an NTFS volume using libntfs-3g, even though wimcapture supports capturing a full image this way.

Except when using --unsafe-compact, it is safe to abort a wimupdate command partway through; however, after doing this, it is recommended to run wimoptimize to remove any data that was appended to the physical WIM file but not yet incorporated into the structure of the WIM, unless --rebuild was specified, in which case you should delete the temporary file left over.

EXAMPLES

All the examples below show the update command file to be created as well as the wimupdate command to run to perform the updates.

Delete two files from a WIM image:

update_commands.txt: 
delete /setup.exe
delete /sources/setup.exe
$ wimupdate boot.wim 2 < update_commands.txt

Add some files and directories to a WIM image. Note that the first path of each add command specifies the files to add, while the second path of each add command specify the locations at which to add them inside the WIM image:

update_commands.txt: 
add somedir     /dir
add somefile    /dir/file
$ wimupdate boot.wim 2 < update_commands.txt

Rename a file inside a WIM image.

update_commands.txt: 
rename /dir_in_wim/oldfile.txt /dir_in_wim/newfile.txt
$ wimupdate boot.wim 2 < update_commands.txt

Using additional features, such as comments, options, and overlays, and including extra integrity information in the updated WIM:

update_commands.txt: 
#
# This file specifies some changes to make to a WIM image.
#
# Add a new directory containing files I want in the image.
# The quotes are necessary because the directory name
# contains a space.
add "My Directory" "/My Directory"
# Add the contents of "Another Directory" to the
# "/My Directory" we just created in the WIM image.  Since
# the destination path already exists, this performs an
# overlay.
add "Another Directory" "/My Directory"
# Rename some file for some reason.
rename /dir_in_wim/oldfile.txt /dir_in_wim/newfile.txt
# Delete an unwanted directory.
delete --recursive /Users/Me/Documents/Junk
$ wimupdate boot.wim 2 --check < update_commands.txt
