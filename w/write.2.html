write(2) Manual de Llamadas al Sistema write(2)

NOMBRE

write - escribir en un descriptor de archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
ssize_t write(size_t count;
              int fd, const void buf[count], size_t count);

DESCRIPCIÓN

write() escribe hasta count bytes del buffer que comienza en buf en el archivo al que se refiere el descriptor de archivo fd.

El número de bytes escritos puede ser menor que count si, por ejemplo, no hay espacio suficiente en el medio físico subyacente, o si se encuentra el límite de recursos RLIMIT_FSIZE (ver setrlimit(2)), o si la llamada fue interrumpida por un manejador de señales después de haber escrito menos de count bytes. (Ver también pipe(7).)

Para un archivo buscable (es decir, uno al que se puede aplicar lseek(2), por ejemplo, un archivo regular) la escritura se realiza en la posición del archivo, y la posición del archivo se incrementa en el número de bytes realmente escritos. Si el archivo fue abierto con open(2) y la bandera O_APPEND, la posición del archivo se establece primero al final del archivo antes de escribir. El ajuste de la posición del archivo y la operación de escritura se realizan como un paso atómico.

POSIX requiere que una lectura (read(2)) que se pueda demostrar que ocurre después de que un write() ha retornado, devuelva los nuevos datos. Tenga en cuenta que no todos los sistemas de archivos cumplen con POSIX.

Según POSIX.1, si count es mayor que SSIZE_MAX, el resultado es definido por la implementación; ver NOTAS para el límite superior en Linux.

VALOR DE RETORNO

En caso de éxito, se devuelve el número de bytes escritos. En caso de error, se devuelve -1 y se establece errno para indicar el error.

Tenga en cuenta que una llamada exitosa a write() puede transferir menos de count bytes. Dichas escrituras parciales pueden ocurrir por varias razones; por ejemplo, porque no había espacio suficiente en el dispositivo de disco para escribir todos los bytes solicitados, o porque una escritura bloqueada (write) en un socket, pipe, o similar fue interrumpida por un manejador de señales después de haber transferido algunos, pero antes de haber transferido todos los bytes solicitados. En caso de una escritura parcial, el llamador puede hacer otra llamada a write() para transferir los bytes restantes. La llamada subsiguiente transferirá más bytes o podría resultar en un error (por ejemplo, si el disco ahora está lleno).

Si count es cero y fd se refiere a un archivo regular, entonces write() puede devolver un estado de fallo si se detecta alguno de los errores siguientes. Si no se detectan errores, o no se realiza la detección de errores, se devuelve 0 sin causar ningún otro efecto. Si count es cero y fd se refiere a un archivo que no sea un archivo regular, los resultados no están especificados.

ERRORES

EAGAIN
El descriptor de archivo fd se refiere a un archivo distinto de un socket y ha sido marcado como no bloqueante (O_NONBLOCK), y la escritura se bloquearía. Ver open(2) para más detalles sobre la bandera O_NONBLOCK.
EAGAIN o EWOULDBLOCK
El descriptor de archivo fd se refiere a un socket y ha sido marcado como no bloqueante (O_NONBLOCK), y la escritura se bloquearía. POSIX.1-2001 permite que cualquiera de los dos errores sea devuelto para este caso, y no requiere que estas constantes tengan el mismo valor, por lo que una aplicación portable debe verificar ambas posibilidades.
EBADF
fd no es un descriptor de archivo válido o no está abierto para escritura.
EDESTADDRREQ
fd se refiere a un socket de datagrama para el cual no se ha establecido una dirección de par usando connect(2).
EDQUOT
La cuota del usuario de bloques de disco en el sistema de archivos que contiene el archivo al que se refiere fd se ha agotado.
EFAULT
buf está fuera de su espacio de direcciones accesible.
EFBIG
Se intentó escribir en un archivo que excede el tamaño máximo de archivo definido por la implementación o el límite de tamaño de archivo del proceso, o escribir en una posición más allá del desplazamiento máximo permitido.
EINTR
La llamada fue interrumpida por una señal antes de que se escribiera ningún dato; ver signal(7).
EINVAL
fd está adjunto a un objeto que no es adecuado para escribir; o el archivo se abrió con la bandera O_DIRECT, y la dirección especificada en buf, el valor especificado en count, o la posición del archivo no están debidamente alineados.
EIO
Se produjo un error de E/S de bajo nivel al modificar el inodo. Este error puede estar relacionado con la escritura diferida de datos escritos por una llamada anterior a write(), que podría haber sido emitida en un descriptor de archivo diferente en el mismo archivo. Desde Linux 4.13, los errores de escritura diferida prometen que *pueden* ser reportados por solicitudes de write() posteriores, y *serán* reportados por una llamada posterior a fsync(2) (independientemente de si también fueron reportados por write()). Otra causa de EIO en sistemas de archivos en red es cuando se ha tomado un bloqueo de asesoría en el descriptor de archivo y este bloqueo se ha perdido. Ver la sección Bloqueos perdidos de fcntl(2) para más detalles.
ENOSPC
El dispositivo que contiene el archivo al que se refiere fd no tiene espacio para los datos.
EPERM
La operación fue impedida por un sello de archivo; ver fcntl(2).
EPIPE
fd está conectado a una tubería o socket cuyo extremo de lectura está cerrado. Cuando esto sucede, el proceso de escritura también recibirá una señal SIGPIPE. (Por lo tanto, el valor de retorno de la escritura sólo se ve si el programa captura, bloquea o ignora esta señal.)

Pueden ocurrir otros errores, dependiendo del objeto conectado a fd.

ESTANDARES

POSIX.1-2024.

HISTORIA

SVr4, 4.3BSD, POSIX.1-2001.

Bajo SVr4, una escritura puede ser interrumpida y devolver EINTR en cualquier punto, no solo antes de que se escribieran datos.

NOTAS

Un retorno exitoso de write() no garantiza que los datos se hayan confirmado en disco. En algunos sistemas de archivos, incluido NFS, ni siquiera garantiza que se haya reservado espacio para los datos. En este caso, algunos errores podrían retrasarse hasta una futura llamada a write(), fsync(2), o incluso close(2). La única forma de estar seguro es llamar a fsync(2) después de haber terminado de escribir todos sus datos.

Si una llamada a write() es interrumpida por un manejador de señales antes de que se hayan escrito bytes, la llamada falla con el error EINTR; si se interrumpe después de que se hayan escrito al menos un byte, la llamada tiene éxito,

VALOR DE RETORNO

En caso de éxito, write() devuelve el número de bytes escritos, que puede ser menor que el número solicitado (numbytes), pero nunca será cero.

En caso de error, write() devuelve -1 y establece errno para indicar el error.

Un valor de retorno de error al realizar write() utilizando E/S directas no significa que la escritura completa haya fallado. Es posible que se hayan escrito datos parciales y los datos en la posición del archivo en la que se intentó write() deben considerarse inconsistentes.

ERRORES

EAGAIN
El archivo está abierto en modo no bloqueante y la escritura bloquearía la operación.
EBADF
El descriptor de archivo fd no es válido o no está abierto para escritura.
EDEADLK
Se produjo un interbloqueo.
EFBIG
El archivo es demasiado grande.
EINTR
La llamada fue interrumpida por una señal antes de que se hubieran escrito datos.
EINVAL
El descriptor de archivo fd no está asociado a un archivo regular, o la dirección especificada en buf es inválida.
EIO
Se produjo un error de E/S al leer de un dispositivo o al escribir en él.
ENOSPC
No quedan bloques libres en el dispositivo.
EPIPE
La tubería está rota. Para el tratamiento de pipe(2), esto ocurre si el extremo de lectura de la tubería ha sido cerrado. Para el tratamiento de write(2), esto ocurre si el archivo no es una tubería y no es una FIFO, y el único descriptor de archivo abierto para el archivo es fd y está abierto en modo de solo lectura.
ROFS
El archivo reside en un sistema de archivos de solo lectura.
SPARSE file
Escribir en un archivo disperso (sparse file) que excede el tamaño máximo permitido para un archivo.

Se pueden producir otros errores según la naturaleza del descriptor de archivo fd.

ESTÁNDARES

La llamada al sistema write() está definida por POSIX.1-2008.

HISTORIA

La llamada al sistema write() apareció por primera vez en Version 1 Unix.

NOTAS

El comportamiento de write() con un descriptor de archivo que no sea de archivo regular (por ejemplo, una tubería o una terminal) depende del tipo de descriptor de archivo.

En Linux, write() (y llamadas similares al sistema) transferirá un máximo de 0x7ffff000 (2.147.479.552) bytes, devolviendo el número de bytes realmente transferidos. (Esto es cierto tanto en sistemas de 32 bits como de 64 bits).

Un valor de retorno de error al realizar write() utilizando E/S directas no significa que la escritura completa haya fallado. Es posible que se hayan escrito datos parciales y los datos en la posición del archivo en la que se intentó write() deben considerarse inconsistentes.

ERRORES

Según POSIX.1-2008/SUSv4 Sección XSI 2.9.7 ("Interacciones de hilos con operaciones de archivos regulares"):

Todas las siguientes funciones serán atómicas con respecto a las demás en los efectos especificados en POSIX.1-2008 cuando operen en archivos regulares o enlaces simbólicos: ...

Entre las API listadas posteriormente se encuentran write() y writev(2). Y entre los efectos que deben ser atómicos entre hilos (y procesos) se encuentran las actualizaciones de la posición del archivo. Sin embargo, antes de Linux 3.14, este no era el caso: si dos procesos que comparten una descripción de archivo abierta (ver open(2)) realizan un write() (o writev(2)) al mismo tiempo, las operaciones de E/S no eran atómicas con respecto a la actualización de la posición del archivo, con el resultado de que los bloques de datos salidos por los dos procesos podían (incorrectamente) superponerse. Este problema se solucionó en Linux 3.14.
