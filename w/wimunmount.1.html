WIMMOUNT(1) Comandos de usuario WIMMOUNT(1)

NOMBRE

wimmount, wimmountrw, wimunmount - Montar o desmontar una imagen WIM

SINOPSIS

wimmount ARCHIVO WIM [IMAGEN] DIRECTORIO [OPCIÓN...]
wimmountrw ARCHIVO WIM [IMAGEN] DIRECTORIO [OPCIÓN...]
wimunmount DIRECTORIO [OPCIÓN...]

DESCRIPCIÓN

En Linux, los comandos wimmount (equivalente: wimlib-imagex mount) y wimmountrw (equivalente: wimlib-imagex mountrw) montan la IMAGEN especificada en el archivo de imágenes de Windows (WIM) ARCHIVO WIM en el directorio DIRECTORIO usando FUSE (Sistema de archivos en espacio de usuario). wimmount montará la imagen de solo lectura, mientras que wimmountrw la montará de lectura/escritura.

IMAGEN especifica la imagen en ARCHIVO WIM a montar. Puede ser el índice 1-basado de una imagen o el nombre de una imagen. Se puede omitir si ARCHIVO WIM contiene solo una imagen. Puede usar wiminfo(1) para listar las imágenes contenidas en ARCHIVO WIM.

La imagen WIM se puede desmontar usando wimunmount (equivalente: wimlib-imagex unmount). Los cambios realizados en una imagen montada de lectura/escritura se descartarán a menos que se proporcione la bandera --commit a wimunmount.

SOPORTE DE DATOS Y METADATOS

Las imágenes WIM pueden contener una variedad de tipos de archivos y metadatos de archivos, algunos de los cuales son específicos de Windows. Actualmente, la característica de montaje puede traducir algunos, pero no todos, los conceptos de Windows a equivalentes de Linux. Brevemente, las siguientes características son *soportadas* (lectura/escritura):

•
Enlaces duros.
•
Enlaces simbólicos. Los enlaces simbólicos nativos de Windows y las uniones en una imagen WIM montada se traducirán automáticamente a enlaces simbólicos de UNIX, potencialmente con sus objetivos corregidos para ser válidos dado el directorio de punto de montaje real. Los enlaces simbólicos de UNIX creados en una imagen WIM montada de lectura/escritura se traducirán automáticamente a enlaces simbólicos nativos de Windows.
•
Flujos de datos con nombre (en su mayoría). Ver la opción --streams-interface.

Además, los permisos de archivo UNIX estándar (propietario, grupo y modo) y los archivos especiales se soportan si se usa la opción --unix-data.

Sin embargo, las siguientes características *no son soportadas* y no se exponen en las imágenes montadas:

•
Descriptores de seguridad de Windows. A los archivos nuevos no se les asignan descriptores de seguridad.
•
Nombres DOS (nombres 8.3) (nombres cortos). A los archivos nuevos no se les asignan nombres DOS.
•
Atributos de archivo de Windows. A los archivos nuevos se les asignan atributos predeterminados basados en los bits de modo de archivo de UNIX.
•
Identificadores de objeto. A los archivos nuevos no se les asignan identificadores de objeto.
•
Archivos cifrados con EFS. Los archivos en sí serán visibles en las imágenes WIM montadas, pero sus datos no estarán disponibles.
•
Atributos extendidos. Aunque wimlib soporta imágenes WIM que contienen atributos extendidos, estos aún no se exponen en las imágenes WIM montadas. (Esto podría implementarse en el futuro, aunque entraría en conflicto con el uso de atributos extendidos para exponer conceptos de Windows como flujos de datos con nombre).

WIMS DIVIDIDOS

Puede usar wimmount para montar una imagen de un WIM dividido de solo lectura. Sin embargo, no puede montar una imagen de un WIM dividido de lectura/escritura.

El argumento ARCHIVO WIM debe especificar la primera parte del WIM dividido, mientras que las partes adicionales del WIM dividido deben especificarse en una o más opciones --ref="GLOB". Dado que el globbing está integrado en la opción --ref, normalmente solo se necesita una opción --ref. Por ejemplo, los nombres de las partes del WIM dividido suelen ser algo así:

miwim.swm
miwim2.swm
miwim3.swm
miwim4.swm
miwim5.swm
Para montar la primera imagen de este WIM dividido en el directorio
"dir", ejecute:
wimmount miwim.swm 1 dir --ref="miwim*.swm"

NOTAS

Disponibilidad: El montaje de imágenes WIM solo está disponible en sistemas basados en Linux. Estos comandos no funcionarán en otras plataformas. Además, la biblioteca no podría haber sido configurada --without-fuse.

Múltiples montajes: Puede montar muchas imágenes WIM al mismo tiempo, siempre que no haya dos imágenes montadas de lectura/escritura del mismo archivo al mismo tiempo.

Anexos vs. reconstrucciones: Por defecto, los cambios en un WIM de lectura/escritura se realizan in situ anexando al WIM. Esto es útil para archivos WIM grandes, ya que todo el archivo no tiene que ser reconstruido para hacer un pequeño cambio. Pero, si está haciendo muchos cambios en un WIM montado de lectura/escritura, especialmente eliminando archivos grandes, se sugiere proporcionar la opción --rebuild a wimunmount para forzar la reconstrucción del WIM, o ejecutar wimoptimize después.

Archivos ESD (WIMs sólidos): Puede montar WIMs de la versión 3584, que generalmente contienen recursos sólidos comprimidos con LZMS y pueden tener la extensión de archivo .esd en lugar de .wim. Sin embargo, estos archivos no están diseñados para acceso aleatorio, por lo que leer datos de ellos cuando están montados puede ser muy lento. Además, los archivos .esd descargados directamente por el descargador web de Windows 8 tienen segmentos cifrados, y wimlib no puede montar tales archivos hasta que se descifren primero.

OPCIONES DE MONTAJE

--check
Antes de montar la imagen WIM, verifique la integridad del WIM si contiene información de integridad adicional.
--streams-interface=INTERFAZ
Esta opción está inspirada en el controlador del sistema de archivos ntfs-3g(8). Controla cómo se ponen a disposición los flujos de datos con nombre (también llamados "flujos de datos alternativos") en los archivos WIM.
Si es "none", será imposible leer o escribir los flujos de datos con nombre.
Si es "xattr" (predeterminado), los flujos de datos con nombre serán accesibles a través de atributos de archivo extendidos, a menos que este soporte se haya deshabilitado al compilar wimlib. Los flujos de datos con nombre pueden accederse a través de atributos de archivo extendidos llamados "user.*", donde * es el nombre del flujo de datos con nombre. Ver setfattr(1) y getfattr(1). Tenga en cuenta que esta no es una interfaz ideal, ya que los flujos de datos con nombre pueden ser más grandes que el tamaño máximo permitido de atributos extendidos.
Si es "windows", los flujos de datos con nombre serán accesibles especificando el nombre del archivo, luego dos puntos, luego el nombre del flujo de datos con nombre; por ejemplo, "miarchivo:miflujo".
--debug
Activar información de depuración impresa por la biblioteca FUSE y no separar en segundo plano.
--ref="GLOB"
Glob de archivo de WIMs adicionales o partes de WIM divididas para referenciar recursos. Ver WIMS DIVIDIDOS. Esta opción se puede especificar varias veces. Nota: GLOB está entre comillas porque es interpretado por wimlib-imagex y puede necesitar ser citado para proteger contra la expansión del shell.
--staging-dir=DIR
Almacenar archivos temporales de staging en un subdirectorio del directorio DIR. Solo válido para wimmountrw.
--unix-data
Respetar los metadatos específicos de UNIX que fueron capturados por wimcapture con la opción --unix-data. Por defecto, wimmount (y wimmountrw) ignorarán tanto los descriptores de seguridad estilo Windows como los metadatos específicos de UNIX. En este modo predeterminado, todos los archivos serán simplemente propiedad del usuario que ejecuta wimmount y tendrán el modo 0777. (Todavía no serán accesibles para otros usuarios a menos que también especifique --allow-other.) Si en su lugar proporciona la opción --unix-data, estos permisos predeterminados se anularán archivo por archivo con los metadatos específicos de UNIX del W

OPCIONES DE DESMONTAJE

--commit
Actualiza el archivo WIM con los cambios que se han realizado. No tiene efecto si el montaje es de solo lectura.
--force
En combinación con --commit, fuerza la confirmación de la imagen WIM incluso si hay descriptores de archivo abiertos a la imagen WIM. Dichos descriptores de archivo se cerrarán inmediatamente y la imagen WIM se confirmará y desmontará.
--check
Si se confirman cambios en el WIM, incluye información de integridad adicional, incluso si no estaba presente antes.
--rebuild
Reconstruye todo el WIM en lugar de añadir nuevos datos al final del mismo. Reconstruir el WIM es más lento, pero ahorrará un poco de espacio que de otro modo quedaría como un hueco en el WIM. Se ahorrará aún más espacio si el montaje de lectura/escritura resultó en la eliminación de flujos del WIM. Ver también
--new-image
En combinación con --commit para una imagen montada de lectura/escritura, causa que la imagen modificada se confirme como una nueva imagen sin nombre añadida al archivo WIM. La imagen original no se modificará.

DETALLES DE IMPLEMENTACIÓN

Dado que un WIM es un archivo y no un sistema de archivos en sí, wimmountrw crea un directorio temporal de preparación para contener los archivos que se crean o modifican. Este directorio se encuentra en el mismo directorio que WIMFILE por defecto, pero la ubicación se puede establecer usando la opción --staging-dir. Cuando el sistema de archivos se desmonta con --commit, el WIM se modifica en el lugar (o se reconstruye completamente con --rebuild), fusionando los archivos de preparación según sea necesario. Luego, se elimina el directorio temporal de preparación.

wimunmount se ejecuta en un proceso separado del proceso que ejecutó previamente wimmount. Al desmontar una imagen WIM montada de lectura/escritura con --commit, estos dos procesos se comunican utilizando una cola de mensajes POSIX para que el proceso de desmontaje pueda rastrear el progreso del proceso de montaje. Ver src/mount_image.c en el código fuente para obtener detalles.
