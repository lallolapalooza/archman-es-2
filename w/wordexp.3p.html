WORDEXP(3P) Manual del programador POSIX WORDEXP(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual correspondiente de Linux para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

wordexp, wordfree — realizar expansiones de palabras

SINOPSIS

#include <wordexp.h>
int wordexp(const char *restrict words, wordexp_t *restrict pwordexp,
    int flags);
void wordfree(wordexp_t *pwordexp);

DESCRIPCIÓN

La función wordexp() realizará expansiones de palabras como se describe en el volumen Shell y Utilidades de POSIX.1‐2017, Sección 2.6, Expansiones de palabras, sujeta a las comillas como se describe en el volumen Shell y Utilidades de POSIX.1‐2017, Sección 2.2, Comillas, y colocará la lista de palabras expandidas en la estructura apuntada por pwordexp.

El argumento words es un puntero a una cadena que contiene una o más palabras para expandir. Las expansiones serán las mismas que realizaría el intérprete de línea de comandos si words fuera parte de una línea de comandos que representa los argumentos de una utilidad. Por lo tanto, la aplicación deberá asegurarse de que words no contenga un carácter de <í>nueva línea sin comillas o cualquiera de los caracteres especiales del shell sin comillas '|', '&', ';', '<', '>' excepto en el contexto de sustitución de comandos como se especifica en el volumen Shell y Utilidades de POSIX.1‐2017, Sección 2.6.3, Sustitución de comandos. Tampoco deberá contener paréntesis o llaves sin comillas, excepto en el contexto de sustitución de comandos o variables. La aplicación deberá asegurarse de que cada palabra de words que espera que sea expandida por wordexp() no contenga un carácter de comentario inicial sin comillas. La aplicación también deberá asegurarse de que todas las palabras que pretende que se ignoren (porque comienzan o continúan un comentario) se eliminen de words. Si el argumento words contiene un carácter de comentario sin comillas (<signo de número>) que es el principio de un token, wordexp() tratará el carácter de comentario como un carácter regular, o lo interpretará como un indicador de comentario e ignorará el resto de words.

El tipo de estructura wordexp_t está definido en la cabecera <wordexp.h> e incluye al menos los siguientes miembros:

Tipo de miembro Nombre del miembro Descripción
size_t we_wordc Número de palabras coincidentes por words.
char ** we_wordv Puntero a la lista de palabras expandidas.
size_t we_offs Espacios para reservar al principio de pwordexp->we_wordv.

La función wordexp() almacenará el número de palabras generadas en pwordexp->we_wordc y un puntero a una lista de punteros a palabras en pwordexp->we_wordv. Cada campo individual creado durante la división de campos (ver el volumen Shell y Utilidades de POSIX.1‐2017, Sección 2.6.5, División de campos) o la expansión de nombres de archivo (ver el volumen Shell y Utilidades de POSIX.1‐2017, Sección 2.6.6, Expansión de nombres de archivo) será una palabra separada en la lista pwordexp->we_wordv. Las palabras estarán en el orden descrito en el volumen Shell y Utilidades de POSIX.1‐2017, Sección 2.6, Expansiones de palabras. El primer puntero después del último puntero de palabra será un puntero nulo. La expansión de parámetros especiales descritos en el volumen Shell y Utilidades de POSIX.1‐2017, Sección 2.5.2, Parámetros especiales no está especificada.

Es responsabilidad del llamador asignar el almacenamiento apuntado por pwordexp. La función wordexp() asignará otro espacio según sea necesario, incluida la memoria apuntada por pwordexp->we_wordv. La función wordfree() libera cualquier memoria asociada con pwordexp de una llamada anterior a wordexp().

El argumento flags se utiliza para controlar el comportamiento de wordexp(). El valor de flags es el OR inclusivo a nivel de bits de cero o más de las siguientes constantes, que están definidas en <wordexp.h>:

WRDE_APPEND
Añadir palabras generadas a las de una llamada anterior a wordexp().
WRDE_DOOFFS
Utilizar pwordexp->we_offs. Si se establece esta bandera, pwordexp->we_offs se utiliza para especificar cuántos punteros nulos añadir al principio de pwordexp->we_wordv. En otras palabras, pwordexp->we_wordv apuntará a pwordexp->we_offs punteros nulos, seguidos por pwordexp->we_wordc punteros de palabra, seguidos por un puntero nulo.
WRDE_NOCMD
Si la implementación soporta las utilidades definidas en el volumen Shell y Utilidades de POSIX.1‐2017, fallar si se solicita la sustitución de comandos, como se especifica en el volumen Shell y Utilidades de POSIX.1‐2017, Sección 2.6.3, Sustitución de comandos.
WRDE_REUSE
El argumento pwordexp se pasó a una llamada anterior exitosa a wordexp(), y no se ha pasado a wordfree(). El resultado será el mismo que si la aplicación hubiera llamado a wordfree() y luego a wordexp() sin WRDE_REUSE.
WRDE_SHOWERR
No redirigir stderr a /dev/null.
WRDE_UNDEF
Informar de un error en un intento de expandir una variable de shell indefinida.

La bandera WRDE_APPEND se puede utilizar para añadir un nuevo conjunto de palabras a las generadas por una llamada anterior a wordexp(). Las siguientes reglas se aplican a las aplicaciones cuando se realizan dos o más llamadas a wordexp() con el mismo valor de pwordexp y sin llamadas intermedias a wordfree():

1.
La primera llamada de este tipo no establecerá WRDE_APPEND. Todas las llamadas posteriores deberán establecerla.
2.
Todas las llamadas establecerán WRDE_DOOFFS, o ninguna lo hará.
3.
Después de la segunda y cada llamada subsiguiente, pwordexp->we_wordv apuntará a una lista que contiene lo siguiente:
a.
Cero o más punteros nulos, como se especifica por WRDE_DOOFFS y pwordexp->we_offs
b.
Punteros a las palabras que estaban en la lista pwordexp->we_wordv antes de la llamada, en el mismo orden que antes
c.
Punteros a las nuevas palabras generadas por la última llamada, en el orden especificado
4.
El recuento devuelto en pwordexp->we_wordc será el número total de palabras de todas las llamadas.
5.
La aplicación puede cambiar cualquiera de los campos después de una llamada a wordexp(), pero si lo hace, deberá restablecerlos al valor original antes de una llamada subsiguiente, utilizando el mismo valor de pwordexp, a wordfree() o a wordexp() con la bandera WRDE_APPEND o WRDE_REUSE.

Si la implementación soporta las utilidades definidas en el volumen Shell y Utilidades de POSIX.1‐2017, y words contiene un carácter sin comillas —<nueva línea>, '|', '&', ';', '<', '>', '(', ')', '{', '}'—en un contexto inapropiado, wordexp() fallará, y el número de palabras expandidas será 0.

FLAGS

The following flags are defined for the flags argument:

WRDE_APPEND
Append the results of the expansion to the we_wordv array. If WRDE_DOOFFS is also set, the offset is relative to the start of the existing array. The application shall ensure that we_offs is set correctly before the call. If WRDE_APPEND is set and WRDE_NOSPACE is returned, pwordexp->we_wordc and pwordexp->we_wordv will not be modified.
WRDE_DOOFFS
The we_offs field of the pwordexp structure contains an offset. This offset is added to the size of the expanded words. This flag is intended to allow the results of multiple calls to wordexp() to be stored contiguously in the same buffer. The application shall ensure that pwordexp->we_offs has the same value for each wordexp() call and wordfree() call using a given pwordexp.
WRDE_NOCMD
Do not perform command substitution.
WRDE_REUSE
Reuse the memory pointed to by pwordexp->we_wordv. The application must have previously called wordexp() with the same pwordexp structure. This flag allows the same buffer to be reused for multiple expansions, potentially improving performance by avoiding repeated memory allocation and deallocation. The results of the new expansion will overwrite the previous results. If this flag is used, wordfree() should not be called between successive calls to wordexp().
WRDE_SHOWERR
If syntax errors are detected while expanding words, the implementation shall write messages describing the errors to the stderr stream. Otherwise, the implementation may write error messages to stderr, or it may discard them, or redirect stderr to /dev/null for any utilities executed as a result of command substitution while expanding words. If WRDE_SHOWERR is set, wordexp() may write messages to stderr if syntax errors are detected while expanding words, unless the stderr stream has wide orientation in which case the behavior is undefined. It is unspecified whether any write errors encountered while outputting such messages will affect the stderr error indicator or the value of errno.

The application shall ensure that if WRDE_DOOFFS is set, then pwordexp->we_offs has the same value for each wordexp() call and wordfree() call using a given pwordexp.

The results are unspecified if WRDE_APPEND and WRDE_REUSE are both specified.

The following constants are defined as error return values:

WRDE_BADCHAR
One of the unquoted characters—<newline>, '|', '&', ';', '<', '>', '(', ')', '{', '}'—appears in words in an inappropriate context.
WRDE_BADVAL
Reference to undefined shell variable when WRDE_UNDEF is set in flags.
WRDE_CMDSUB
Command substitution requested when WRDE_NOCMD was set in flags.
WRDE_NOSPACE
Attempt to allocate memory failed.
WRDE_SYNTAX
Shell syntax error, such as unbalanced parentheses or unterminated string.

RETURN VALUE

Upon successful completion, wordexp() shall return 0. Otherwise, a non-zero value, as described in <wordexp.h>, shall be returned to indicate an error. If wordexp() returns the value WRDE_NOSPACE, then pwordexp->we_wordc and pwordexp->we_wordv shall be updated to reflect any words that were successfully expanded. In other error cases, if the WRDE_APPEND flag was specified, pwordexp->we_wordc and pwordexp->we_wordv shall not be modified.

The wordfree() function shall not return a value.

ERRORS

No errors are defined.

EXAMPLES

None.

APPLICATION USAGE

The wordexp() function is intended to be used by an application that wants to do all of the shell's expansions on a word or words obtained from a user. For example, if the application prompts for a pathname (or list of pathnames) and then uses wordexp() to process the input, the user could respond with anything that would be valid as input to the shell.

The WRDE_NOCMD flag is provided for applications that, for security or other reasons, want to prevent a user from executing shell commands. Disallowing unquoted shell special characters also prevents unwanted side-effects, such as executing a command or writing a file.

POSIX.1-2008 does not require the wordexp() function to be thread-safe if passed an expression referencing an environment variable while any other thread is concurrently modifying any environment variable; see exec.

Even though the WRDE_SHOWERR flag allows the implementation to write messages to stderr during command substitution or syntax errors, this standard does not provide any way to detect write failures during the output of such messages.

Applications which use wide-character output functions with stderr should ensure that any calls to wordexp() do not write to stderr, by avoiding use of the WRDE_SHOWERR flag.

RATIONALE

This function was included as an alternative to glob(). There had been continuing controversy over exactly what features should be included in glob(). It is hoped that by providing wordexp() (which provides all of the shell word expansions, but which may be slow to execute) and glob() (which is faster, but which only performs pathname expansion, without tilde or parameter expansion) this will satisfy the majority of applications.

While wordexp() could be implemented entirely as a library routine, it is expected that most implementations run a shell in a subprocess to do the expansion.

Two different approaches have been proposed for how the required information might be presented to the shell and the results returned. They are presented here as examples.

One proposal is to extend the echo utility by adding a -q option. This option would cause echo to add a <backslash> before each <backslash> and <blank> that occurs within an argument. The wordexp() function could then invoke the shell as follows:

(void) strcpy(buffer, "echo -q");
(void) strcat(buffer, words);
if ((flags & WRDE_SHOWERR) == 0)
    (void) strcat(buffer, "2>/dev/null");
f = popen(buffer, "r");

The wordexp() function would read the resulting output, remove unquoted <backslash> characters, and break into words at unquoted <blank> characters. If the WRDE_NOCMD flag was set, wordexp() would have to scan words before starting the subshell to make sure that there would be no command substitution. In any case, it would have to scan words for unquoted special characters.

Another proposal is to add the following options to sh:

-w wordlist

This option provides a wordlist expansion service to applications. The words in wordlist shall be expanded and the following written to standard output:
1.
The count of the number of words after expansion, in decimal, followed by a null byte
2.
The number of bytes needed to represent the expanded words (not including null separators), in decimal, followed by a null byte
3.
The expanded words, each terminated by a null byte

If an error is encountered during word expansion, sh exits with a non-zero status after writing the former to report any words successfully expanded

-P
Run in ``protected'' mode. If specified with the -w option, no command substitution shall be performed.

With these options, wordexp() could be implemented fairly simply by creating a subprocess using fork() and executing sh using the line:

execl(<shell path>, "sh", "-P", "-w", words, (char *)0);

after directing standard error to /dev/null.

It seemed objectionable for a library routine to write messages to standard error, unless explicitly requested, so wordexp() is required to redirect standard error to /dev/null to ensure that no messages are generated, even for commands executed for command substitution. The WRDE_SHOWERR flag can be specified to request that error messages be written.

The WRDE_REUSE flag allows the implementation to avoid the expense of freeing and reallocating memory, if that is possible. A minimal implementation can call wordfree() when WRDE_REUSE is set.
