NOMBRE

winedbg - Depurador de Wine

SINOPSIS

winedbg [ opciones ] [ nombre_programa [ argumentos_programa ] | wpid ]

winedbg --gdb [ opciones ] [ nombre_programa [ argumentos_programa ] | wpid ]

winedbg --auto wpid

winedbg --minidump [ archivo.mdmp ] wpid

winedbg archivo.mdmp

DESCRIPCIÓN

winedbg es un depurador para Wine. Permite:

- depurar aplicaciones Win32 nativas
- depurar aplicaciones Winelib
- ser un reemplazo directo para Dr. Watson

MODOS

winedbg puede usarse en cinco modos. El primer argumento del programa determina el modo en el que se ejecutará winedbg.

predeterminado
Sin ningún modo explícito, este es el modo de operación estándar de winedbg. winedbg actuará como la interfaz de usuario.
--gdb
winedbg se usará como un proxy para gdb. gdb será la interfaz para el manejo de comandos, y winedbg actuará como proxy para todas las solicitudes de depuración de gdb a las APIs de Win32.
--auto
Este modo se usa cuando winedbg está configurado en la entrada del registro AeDebug como depurador predeterminado. winedbg entonces mostrará información básica sobre un fallo. Esto es útil para usuarios que no quieren depurar un fallo, sino recopilar información relevante sobre el fallo para enviarla a los desarrolladores.
--minidump
Este modo es similar al modo --auto, excepto que en lugar de imprimir la información en la pantalla (como hace --auto), se guarda en un archivo minidump. El nombre del archivo se pasa en la línea de comandos o lo genera WineDbg cuando no se proporciona ninguno. Este archivo podría recargarse más tarde en winedbg para su posterior examen.
archivo.mdmp
En este modo, winedbg recarga el estado de un depurado que se ha guardado en un archivo minidump. Consulte el comando minidump a continuación, o el modo --minidump.

OPCIONES

Cuando está en modo predeterminado, las siguientes opciones están disponibles:

--comando cadena
winedbg ejecutará el comando cadena como si se hubiera escrito en la línea de comandos de winedbg, y luego saldrá. Esto puede ser útil para obtener el PID de procesos en ejecución (winedbg --comando "info proc").
--ejec nombre_archivo
Establece el nombre del ejecutable, sin iniciar el ejecutable.
--archivo nombre_archivo
winedbg ejecutará la lista de comandos contenidos en el archivo nombre_archivo como si se hubieran escrito en la línea de comandos de winedbg, y luego saldrá.

Cuando está en modo proxy gdb, las siguientes opciones están disponibles:

--no-iniciar
No inicies gdb directamente; en su lugar, imprime el comando GDB target remote a ejecutar y espera la conexión de cualquier depurador compatible con GDB. Normalmente, --gdb iniciará tanto el servidor de depuración proxy como una instancia de gdb para la interfaz. Esta opción instruye a winedbg a omitir el inicio de gdb, y en su lugar imprime el comando GDB que se puede usar para conectarse manualmente al servidor. Este comando tiene el formato
target remote localhost:<puerto>

donde <puerto> es el puerto TCP al que está enlazado el servidor de depuración proxy de winedbg.

Esta opción permite al usuario reemplazar gdb con alguna otra interfaz de depuración, como ddd, kgdb, gdbgui, o Qt Creator. Independientemente de si se especifica --no-iniciar, winedbg se cerrará después de que la primera conexión se desconecte (por ejemplo, gdb se desvincula del depurado).
--puerto puerto
Inicia el servidor de depuración proxy GDB en el puerto dado. Si esta opción no se especifica, winedbg dejará que el sistema operativo elija un puerto disponible. Esta opción se puede usar junto con --no-iniciar para especificar el puerto al que se enlazará el servidor.
--con-xterm
Esto ejecutará la interfaz gdb en una nueva ventana de xterm(1) en lugar de usar la terminal Unix actual para su interfaz. Esta opción se ignora si se especifica --no-iniciar.

En todos los modos, el resto de la línea de comandos, cuando se proporciona, se utiliza para identificar qué programa, si lo hay, debe ser depurado:

nombre_programa
Este es el nombre de un ejecutable para iniciar una sesión de depuración. winedbg creará realmente un proceso con este ejecutable. Si también se proporcionan argumentos_programa, se usarán como argumentos para crear el proceso a depurar.
wpid
winedbg se adjuntará al proceso cuyo PID de Windows es wpid. Usa el comando info proc dentro de winedbg para listar los procesos en ejecución y sus PIDs de Windows.
predeterminado
Si no se especifica nada, entrarás en el depurador sin ningún proceso en ejecución ni adjunto. Tendrás que hacer el trabajo tú mismo.

COMANDOS

Modo predeterminado, y al recargar un archivo minidump:

La mayoría de los comandos utilizados en winedbg son similares a los de gdb. Consulte las documentaciones de gdb para obtener más detalles. Consulte la sección diferencias_con_gdb más adelante para obtener una lista de las variaciones de los comandos de gdb.

Comandos varios

abortar
Aborta el depurador.
salir
Sale del depurador.

Manejo de procesos

adjuntar N
Adjuntar a un proceso de Wine (N es su ID de Windows, numérico o hexadecimal). Los IDs se pueden obtener usando el comando info proceso. Tenga en cuenta que el comando info proceso devuelve valores hexadecimales
adjuntar archivo.mdmp
Recarga el estado de un depurado desde el minidump archivo.mdmp. Consulte el comando minidump para guardar dicho archivo.
desadjuntar
Desadjunta el proceso de Wine actual. El proceso ya no es depurado por WineDbg, pero sigue en ejecución (para un objetivo en vivo).
matar
Mata el proceso de Wine actual. El proceso ya no es depurado por WineDbg, y también se termina (para un objetivo en vivo).
minidump archivo.mdmp
Guarda el contexto de depuración del depurado en un archivo minidump llamado archivo.mdmp.
ejecutar
Vuelve a ejecutar el mismo proceso con los mismos argumentos. Nota: todos los puntos de interrupción del proceso precedente ya no están disponibles.
ejecutar arg1 arg2...
Vuelve a ejecutar el mismo proceso con los argumentos arg1 arg2.... Nota: todos los puntos de interrupción del proceso precedente ya no están disponibles.
hilo N
>
Cambia el hilo actual a N (su TID de Windows, numérico o hexadecimal).

Comandos de ayuda

help
Imprime ayuda sobre los comandos.
help info
Imprime ayuda sobre los comandos de info

Comandos de control de flujo

cont
Continúa la ejecución hasta el próximo punto de interrupción o excepción.
pass
Pasa el evento de excepción a la cadena de filtros.
step
Continúa la ejecución hasta la próxima línea de código C (entra en la llamada a función)
next
Continúa la ejecución hasta la próxima línea de código C (no entra en la llamada a función)
stepi
Ejecuta la próxima instrucción de ensamblaje (entra en la llamada a función)
nexti
Ejecuta la próxima instrucción de ensamblaje (no entra en la llamada a función)
finish
Ejecuta hasta que se alcanza el retorno de la función actual.

cont, step, next, stepi, nexti pueden ir seguidos de un número (N), lo que significa que el comando debe ejecutarse N veces antes de devolver el control al usuario.

Puntos de interrupción, puntos de vigilancia

enable N
Habilita el punto de interrupción (break|watch) N

Inhabilita el punto de interrupción (break|watch) N

Elimina el punto de interrupción (break|watch) N

Elimina cualquier condición existente en el punto de interrupción (break|watch) N

Añade la condición expr al punto de interrupción (break|watch) N. expr se evaluará cada vez que se alcance el punto de interrupción (break|watch). Si el resultado es un valor cero, el punto de interrupción no se activará.
break * N
Añade un punto de interrupción en la dirección N
break id
Añade un punto de interrupción en la dirección del símbolo id
break id N
Añade un punto de interrupción en la línea N dentro del símbolo id.
break N
Añade un punto de interrupción en la línea N del archivo fuente actual.
break
Añade un punto de interrupción en la dirección actual de $PC.
watch * N
Añade un comando de vigilancia (en escritura) en la dirección N (en 4 bytes).
watch id
Añade un comando de vigilancia (en escritura) en la dirección del símbolo id. El tamaño depende del tamaño de id.
rwatch * N
Añade un comando de vigilancia (en lectura) en la dirección N (en 4 bytes).
rwatch id
Añade un comando de vigilancia (en lectura) en la dirección del símbolo id. El tamaño depende del tamaño de id.
info break
Lista todos los puntos de interrupción (break|watch) (con su estado).

Puedes usar el símbolo EntryPoint para representar el punto de entrada del Dll.

Al establecer un punto de interrupción (break|watch) por id, si el símbolo no se encuentra (por ejemplo, el símbolo está contenido en un módulo que aún no se ha cargado), winedbg recordará el nombre del símbolo y intentará establecer el punto de interrupción cada vez que se cargue un nuevo módulo (hasta que tenga éxito).

MODES

Wine Debugger can run in several modes. The default mode is the interactive one.

Interactive mode:

In this mode, you can type commands at the winedbg> prompt. The command syntax is similar to the one of gdb(1).

Type Formatting

The following type formatting characters can be used:

x
integer
c
character (only printable 0x20-0x7f are actually printed)
b
8-bit unsigned hexadecimal integer
g
Win32 GUID

Expressions

Expressions in Wine Debugger are mostly written in a C form. However, there are a few discrepancies:

Identifiers can take a '!' in their names. This allows mainly to specify a module where to look the ID from, e.g. USER32!CreateWindowExA.

In a cast operation, when specifying a structure or a union, you must use the struct or union keyword (even if your program uses a typedef).

When specifying an identifier, if several symbols with this name exist, the debugger will prompt for the symbol you want to use. Pick up the one you want from its number.

Information on Wine internals

info class
Lists all Windows classes registered in Wine
info class id
Prints information on Windows class id
info share
Lists all the dynamic libraries loaded in the debugged program (including .so files, NE and PE DLLs)
info share N
Prints information on module at address N
info regs
Prints the value of the CPU registers
info all-regs
Prints the value of the CPU and Floating Point registers
info segment
Lists all allocated segments (i386 only)
info segment N
Prints information on segment N (i386 only)
info stack
Prints the values on top of the stack
info map
Lists all virtual mappings used by the debugged program
info map N
Lists all virtual mappings used by the program of Windows pid N
info wnd
Displays the window hierarchy starting from the desktop window
info wnd N
Prints information of Window of handle N
info process
Lists all w-processes in Wine session
info thread
Lists all w-threads in Wine session
info frame
Lists the exception frames (starting from current stack frame). You can also pass, as optional argument, a thread id (instead of current thread) to examine its exception frames.

Debug messages can be turned on and off as you are debugging using the set command, but only for channels initialized with the WINEDEBUG environment variable.

set warn + win
Turns on warn on win channel
set + win
Turns on warn/fixme/err/trace on win channel
set - win
Turns off warn/fixme/err/trace on win channel
set fixme - all
Turns off fixme class on all channels

Gdb mode:

See the gdb documentation for all the gdb commands.

However, a few Wine extensions are available, through the monitor command:

monitor wnd
Lists all windows in the Wine session
monitor proc
Lists all processes in the Wine session
monitor mem
Displays memory mapping of debugged process

Auto and minidump modes:

Since no user input is possible, no commands are available.

ENVIRONMENT

WINE_GDB
When used in gdb proxy mode, WINE_GDB specifies the name (and the path) of the executable to be used for gdb. "gdb" is used by default.
