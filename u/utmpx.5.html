utmp(5) Manual de Formatos de Archivo utmp(5)

NOMBRE

utmp, wtmp - registros de inicio de sesión

SINOPSIS

#include <utmp.h>

DESCRIPCIÓN

El archivo utmp permite descubrir información sobre quién está usando el sistema actualmente. Puede haber más usuarios usando el sistema actualmente, ya que no todos los programas usan el registro utmp.

Advertencia: utmp no debe ser escribible por la clase de usuario "otro", ya que muchos programas del sistema (tontamente) dependen de su integridad. Corre el riesgo de que los archivos de registro del sistema sean falsificados y de modificaciones de archivos del sistema si deja utmp escribible para cualquier usuario que no sea el propietario y el propietario del grupo del archivo.

El archivo es una secuencia de estructuras utmp, declaradas de la siguiente manera en <utmp.h> (tenga en cuenta que esta es solo una de varias definiciones; los detalles dependen de la versión de libc):


/* Valores para el campo ut_type, abajo */
#define EMPTY         0 /* El registro no contiene información válida
                           (anteriormente conocido como UT_UNKNOWN en Linux) */
#define RUN_LVL       1 /* Cambio en el nivel de ejecución del sistema (ver
init(1)) 
*/
#define BOOT_TIME     2 /* Hora de arranque del sistema (en ut_tv) */
#define NEW_TIME      3 /* Hora después del cambio del reloj del sistema
                           (en ut_tv) */
#define OLD_TIME      4 /* Hora antes del cambio del reloj del sistema
                           (en ut_tv) */
#define INIT_PROCESS  5 /* Proceso iniciado por 
init(1) 
*/
#define LOGIN_PROCESS 6 /* Proceso líder de sesión para inicio de sesión de usuario */
#define USER_PROCESS  7 /* Proceso normal */
#define DEAD_PROCESS  8 /* Proceso terminado */
#define ACCOUNTING    9 /* No implementado */
#define UT_LINESIZE      32
#define UT_NAMESIZE      32
#define UT_HOSTSIZE     256
struct exit_status {              /* Tipo para ut_exit, abajo */
    short e_termination;          /* Estado de terminación del proceso */
    short e_exit;                 /* Estado de salida del proceso */
};
struct utmp {
    short   ut_type;              /* Tipo de registro */
    pid_t   ut_pid;               /* PID del proceso de inicio de sesión */
    char    ut_line[UT_LINESIZE]; /* Nombre del dispositivo de tty - "/dev/" */
    char    ut_id[4];             /* Sufijo del nombre de la terminal,
                                     o ID de inittab(5) */
    char    ut_user[UT_NAMESIZE]; /* Nombre de usuario */
    char    ut_host[UT_HOSTSIZE]; /* Nombre del host para inicio de sesión remoto, o
                                     versión del kernel para mensajes de nivel de ejecución */
    struct  exit_status ut_exit;  /* Estado de salida de un proceso
                                     marcado como DEAD_PROCESS; no
                                     utilizado por init(1) de Linux 
*/
    /* Los campos ut_session y ut_tv deben tener el mismo tamaño cuando
       se compila en 32 y 64 bits. Esto permite que los archivos de datos y la
       memoria compartida se compartan entre aplicaciones de 32 y 64 bits. */
#if __WORDSIZE == 64 && defined __WORDSIZE_COMPAT32
    int32_t ut_session;           /* ID de sesión (
getsid(2)),
                                     utilizado para ventanas */
    struct {
        int32_t tv_sec;           /* Segundos */
        int32_t tv_usec;          /* Microsegundos */
    } ut_tv;                      /* Hora en que se creó la entrada */
#else
     long   ut_session;           /* ID de sesión */
     struct timeval ut_tv;        /* Hora en que se creó la entrada */
#endif
    int32_t ut_addr_v6[4];        /* Dirección de Internet del host
                                     remoto; la dirección IPv4 utiliza
                                     solo ut_addr_v6[0] */
    char __unused[20];            /* Reservado para uso futuro */
};
/* Trucos de compatibilidad hacia atrás */
#define ut_name ut_user
#ifndef _NO_UT_TIME
#define ut_time ut_tv.tv_sec
#endif
#define ut_xtime ut_tv.tv_sec
#define ut_addr ut_addr_v6[0]

Esta estructura proporciona el nombre del archivo especial asociado a la terminal del usuario, el nombre de inicio de sesión del usuario y la hora del inicio de sesión en formato de time(2). Los campos de cadena están terminados por un byte nulo ('\0') si son más cortos que el tamaño del campo.

Las primeras entradas creadas resultan del procesamiento de inittab(5) por parte de init(1). Sin embargo, antes de procesar una entrada, init(1) limpia utmp estableciendo ut_type a DEAD_PROCESS, limpiando ut_user, ut_host y ut_time con bytes nulos para cada registro cuyo ut_type no es DEAD_PROCESS o RUN_LVL y para el cual no existe un proceso con PID ut_pid. Si no se encuentra un registro vacío con el ut_id necesario, init(1) crea uno nuevo. Establece ut_id a partir de inittab, ut_pid y ut_time a los valores actuales, y ut_type a INIT_PROCESS.

mingetty(8) (o agetty(8)) localiza la entrada por el PID, cambia ut_type a LOGIN_PROCESS, cambia ut_time, establece ut_line y espera a que se establezca la conexión. login(1), después de que un usuario ha sido autenticado, cambia ut_type a USER_PROCESS, cambia ut_time y establece ut_host y ut_addr. Dependiendo de mingetty(8) (o agetty(8)) y login(1), los registros pueden ser localizados por ut_line en lugar del preferible ut_pid.

Cuando init(1) detecta que un proceso ha salido, localiza su entrada utmp por ut_pid, establece ut_type a DEAD_PROCESS y limpia ut_user, ut_host y ut_time con bytes nulos.

xterm(1) y otros emuladores de terminal crean directamente un registro USER_PROCESS y generan el ut_id usando la cadena que es la parte sufijo del nombre de la terminal (los caracteres después de /dev/[pt]ty). Si encuentran un DEAD_PROCESS para este ID, lo reciclan, de lo contrario crean una nueva entrada. Si pueden, lo marcarán como DEAD_PROCESS al salir y es aconsejable que también limpien ut_line, ut_time, ut_user y ut_host.

telnetd(8) configura una entrada LOGIN_PROCESS y deja el resto a login(1) como de costumbre. Después de que la sesión telnet termina, telnetd(8) limpia utmp de la manera descrita.

El archivo wtmp registra todos los inicios y cierres de sesión. Su formato es exactamente como utmp excepto que un nombre de usuario nulo indica un cierre de sesión en la terminal asociada. Además, el nombre de terminal ~ con nombre de usuario shutdown o reboot indica un apagado o reinicio del sistema y el par de nombres de terminal |/} registra la hora antigua/nueva del sistema cuando date(1) la cambia. wtmp es mantenido por login(1), init(1) y algunas versiones de getty(8) (por ejemplo, mingetty(8) o agetty(8)). Ninguno de estos programas crea el archivo, por lo que si se elimina, el registro se desactiva.

ARCHIVOS

/var/run/utmp
/var/log/wtmp

VERSIONES

POSIX.1 no especifica una estructura utmp, sino una llamada utmpx (como parte de la extensión XSI), con especificaciones para los campos ut_type, ut_pid, ut_line, ut_id, ut_user y ut_tv. POSIX.1 no especifica las longitudes de los campos ut_line y ut_user.

Linux define la estructura utmpx para que sea la misma que la estructura utmp.

ESTANDARES

Linux.

HISTORIA

Las entradas utmp de Linux no se ajustan ni a v7/BSD ni a System V; son una mezcla de ambos.

v7/BSD tiene menos campos; lo más importante es que carece de ut_type, lo que hace que los programas nativos tipo v7/BSD muestren (por ejemplo) entradas muertas o de inicio de sesión. Además, no hay un archivo de configuración que asigne ranuras a las sesiones. BSD lo hace porque carece de campos ut_id.

En Linux (como en System V), el campo ut_id de un registro nunca cambiará una vez que se haya establecido, lo que reserva esa ranura sin necesitar un archivo de configuración. Limpiar ut_id puede resultar en condiciones de carrera que conducen a entradas utmp corruptas y posibles agujeros de seguridad. Limpiar los campos mencionados anteriormente con fill

SYSTEM V VERSUS BSD

The System V and BSD versions of the utmp file differ in a few respects. System V who(1) is said to zero pad the ut_name field and the utmpx(5) file format (the BSD version) is said to pad with null bytes.

Padding with null bytes is not required by System V semantics, but makes it possible to run many programs which assume BSD semantics and which do not modify utmp. Linux uses the BSD conventions for line contents, as documented above.

System V has no ut_host or ut_addr_v6 fields.

NOTES

Unlike various other systems, where utmp logging can be disabled by removing the file, utmp must always exist on Linux. If you want to disable who(1), then do not make utmp world readable.

The file format is machine-dependent, so it is recommended that it be processed only on the machine architecture where it was created.

Note that on biarch platforms, that is, systems which can run both 32-bit and 64-bit applications (x86-64, ppc64, s390x, etc.), ut_tv is the same size in 32-bit mode as in 64-bit mode. The same goes for ut_session and ut_time if they are present. This allows data files and shared memory to be shared between 32-bit and 64-bit applications. This is achieved by changing the type of ut_session to int32_t, and that of ut_tv to a struct with two int32_t fields tv_sec and tv_usec. Since ut_tv may not be the same as struct timeval, then instead of the call:


gettimeofday((struct timeval *) &ut.ut_tv, NULL);

the following method of setting this field is recommended:


struct utmp ut;
struct timeval tv;
gettimeofday(&tv, NULL);
ut.ut_tv.tv_sec = tv.tv_sec;
ut.ut_tv.tv_usec = tv.tv_usec;
