NOMBRE

update-alternatives - mantener enlaces simbólicos que determinan los comandos por defecto

SINOPSIS

update-alternatives [opción...] comando

DESCRIPCIÓN

update-alternatives crea, elimina, mantiene y muestra información sobre los enlaces simbólicos que componen el sistema de alternativas.

Es posible que varios programas que cumplen la misma función o funciones similares estén instalados en un mismo sistema al mismo tiempo. Por ejemplo, muchos sistemas tienen varios editores de texto instalados a la vez. Esto ofrece opciones a los usuarios de un sistema, permitiendo a cada uno usar un editor diferente, si así lo desean, pero dificulta que un programa tome una buena decisión sobre qué editor invocar si el usuario no ha especificado una preferencia particular.

El sistema de alternativas tiene como objetivo resolver este problema. Un nombre genérico en el sistema de archivos es compartido por todos los archivos que proporcionan funcionalidad intercambiable. El sistema de alternativas y el administrador del sistema determinan conjuntamente a qué archivo real hace referencia este nombre genérico. Por ejemplo, si los editores de texto ed(1) y nvi(1) están ambos instalados en el sistema, el sistema de alternativas hará que el nombre genérico /usr/bin/editor apunte a /usr/bin/nvi por defecto. El administrador del sistema puede anular esto y hacer que apunte a /usr/bin/ed en su lugar, y el sistema de alternativas no alterará esta configuración hasta que se le solicite explícitamente.

El nombre genérico no es un enlace simbólico directo a la alternativa seleccionada. En cambio, es un enlace simbólico a un nombre en el directorio de alternativas, que a su vez es un enlace simbólico al archivo real al que se hace referencia. Esto se hace para que los cambios del administrador del sistema puedan confinarse dentro del directorio /etc: el FHS (véase) da razones por las que esto es Algo Bueno.

Cuando cada paquete que proporciona un archivo con una funcionalidad particular se instala, se cambia o se elimina, se llama a update-alternatives para actualizar la información sobre ese archivo en el sistema de alternativas. update-alternatives se llama generalmente desde los scripts del mantenedor de paquetes de Debian, postinst (configurar) para instalar la alternativa y desde prerm y postrm (eliminar) para eliminar la alternativa. Nota: En la mayoría de los casos (si no en todos) ninguna otra acción de script del mantenedor debería llamar a update-alternatives, en particular ninguna de upgrade ni disappear, ya que cualquier otra acción de este tipo puede perder el estado manual de una alternativa, o hacer que la alternativa cambie temporalmente, o cambie completamente cuando varias de ellas tengan la misma prioridad.

A menudo es útil que varias alternativas estén sincronizadas, de modo que se cambien como un grupo; por ejemplo, cuando se instalan varias versiones del editor vi(1), la página del manual referenciada por /usr/share/man/man1/vi.1 debe corresponder al ejecutable referenciado por /usr/bin/vi. update-alternatives maneja esto mediante enlaces maestro y esclavo; cuando se cambia el maestro, también se cambian los esclavos asociados. Un enlace maestro y sus esclavos asociados forman un grupo de enlaces.

Cada grupo de enlaces se encuentra, en un momento dado, en uno de dos modos: automático o manual. Cuando un grupo está en modo automático, el sistema de alternativas decidirá automáticamente, a medida que se instalan y eliminan paquetes, si actualiza los enlaces y cómo hacerlo. En modo manual, el sistema de alternativas conservará la elección del administrador y evitará cambiar los enlaces (excepto cuando algo está roto).

Los grupos de enlaces están en modo automático cuando se introducen por primera vez en el sistema. Si el administrador del sistema realiza cambios en la configuración automática del sistema, esto se notará la próxima vez que se ejecute update-alternatives en el grupo de enlaces modificado, y el grupo se cambiará automáticamente al modo manual.

Cada alternativa tiene una prioridad asociada. Cuando un grupo de enlaces está en modo automático, las alternativas a las que apuntan los miembros del grupo serán aquellas que tengan la mayor prioridad.

Al usar la opción --config, update-alternatives listará todas las opciones para el grupo de enlaces del cual nombre dado es el nombre de alternativa maestro. La opción actual se marca con un ‘*’. Luego se le pedirá que elija respecto a este grupo de enlaces. Dependiendo de la opción elegida, el grupo de enlaces podría ya no estar en modo automático. Necesitará usar la opción --auto para volver al modo automático (o puede volver a ejecutar --config y seleccionar la entrada marcada como automática).

Si desea configurar interactivamente puede usar la opción --set en su lugar (ver más abajo).

Diferentes paquetes que proporcionan el mismo archivo necesitan hacerlo de forma **cooperativa**. En otras palabras, el uso de update-alternatives es **obligatorio** para todos los paquetes involucrados en dicho caso. No es posible anular algún archivo en un paquete que no emplee el mecanismo de update-alternatives.

TERMINOLOGÍA

Dado que las actividades de update-alternatives son bastante complejas, algunos términos específicos ayudarán a explicar su funcionamiento.

nombre genérico (o enlace de alternativa)
Un nombre, como /usr/bin/editor, que apunta, a través del sistema de alternativas, a uno de varios archivos de función similar.
nombre alternativo
El nombre de un enlace simbólico en el directorio de alternativas.
alternativa (o ruta alternativa)
El nombre de un archivo específico en el sistema de archivos, que puede ser accesible a través de un nombre genérico utilizando el sistema de alternativas.
directorio de alternativas
Un directorio, por defecto /etc/alternatives, que contiene los enlaces simbólicos.
directorio administrativo
Un directorio, por defecto /var/lib/dpkg/alternatives, que contiene la información de estado de update-alternatives.
grupo de enlaces
Un conjunto de enlaces simbólicos relacionados, destinados a ser actualizados como un grupo.
enlace maestro
El enlace de alternativa en un grupo de enlaces que determina cómo se configuran los otros enlaces del grupo.
enlace esclavo
Un enlace de alternativa en un grupo de enlaces que está controlado por la configuración del enlace maestro.
modo automático
Cuando un grupo de enlaces está en modo automático, el sistema de alternativas se asegura de que los enlaces del grupo apunten a la alternativa de mayor prioridad adecuada para el grupo.
modo manual
Cuando un grupo de enlaces está en modo manual, el sistema de alternativas no realizará ningún cambio en la configuración del administrador del sistema.

COMANDOS

--install enlace nombre ruta prioridad [--slave enlace nombre ruta]...
Añade un grupo de alternativas al sistema. enlace es el nombre genérico para el enlace maestro, nombre es el nombre de su enlace simbólico en el directorio de alternativas, y ruta es la alternativa que se está introduciendo para el enlace maestro. Los argumentos después de --slave son el nombre genérico, el nombre del enlace simbólico en el directorio de alternativas y la ruta alternativa para un enlace esclavo. Se pueden especificar cero o más opciones --slave, cada una seguida de tres argumentos. Tenga en cuenta que la alternativa maestro debe existir o la llamada fallará. Sin embargo, si una alternativa esclava no existe, el enlace de alternativa esclavo correspondiente simplemente no se instalará (aún se mostrará una advertencia). Si algún archivo real se instala donde debe instalarse un enlace de alternativa, se mantiene a menos que se utilice --force.

Si el nombre de alternativa especificado ya existe en los registros del sistema de alternativas, la información proporcionada se añadirá como un nuevo conjunto de alternativas para el grupo. De lo contrario, se añadirá un nuevo grupo, configurado en modo automático, con esta información. Si el grupo está en modo automático y la prioridad de las alternativas recién añadidas es mayor

DIAGNOSTICS

If problems occur, update-alternatives outputs error messages on its standard error channel and returns an exit status of 2. These diagnostics should be self-explanatory; if you do not find them so, please report this as a bug.

EXAMPLES

There are several packages which provide a text editor compatible with vi, for example nvi and vim. Which one is used is controlled by the link group vi, which includes links for the program itself and the associated manual page.

To display the available packages which provide vi and the current setting for it, use the --display action:

update-alternatives --display vi

To choose a particular vi implementation, use this command as root and then select a number from the list:

update-alternatives --config vi

To go back to having the vi implementation chosen automatically, do this as root:

update-alternatives --auto vi
