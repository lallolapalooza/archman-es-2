UNLINK(3P) Manual del programador POSIX UNLINK(3P)

PROLOGO

Esta página del manual es parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

unlink, unlinkat — eliminar una entrada de directorio

SINOPSIS

#include <unistd.h>
int unlink(const char *path);
#include <fcntl.h>
int unlinkat(int fd, const char *path, int flag);

DESCRIPCION

La función unlink() elimina un enlace a un archivo. Si path nombra un enlace simbólico, unlink() eliminará el enlace simbólico nombrado por path y no afectará a ningún archivo o directorio nombrado por el contenido del enlace simbólico. De lo contrario, unlink() eliminará el enlace nombrado por la ruta de acceso señalada por path y decrementará el contador de enlaces del archivo al que hace referencia el enlace.

Cuando el contador de enlaces del archivo llega a 0 y ningún proceso tiene el archivo abierto, el espacio ocupado por el archivo se liberará y el archivo ya no será accesible. Si uno o más procesos tienen el archivo abierto cuando se elimina el último enlace, el enlace se eliminará antes de que unlink() devuelva, pero la eliminación del contenido del archivo se pospondrá hasta que se cierren todas las referencias al archivo.

El argumento path no debe nombrar un directorio a menos que el proceso tenga los privilegios apropiados y la implementación admita el uso de unlink() en directorios.

Tras una finalización exitosa, unlink() marcará para actualización las marcas de tiempo de la última modificación de datos y del último cambio de estado del archivo del directorio padre. Además, si el contador de enlaces del archivo no es 0, se marcará para actualizar la marca de tiempo del último cambio de estado del archivo.

La función unlinkat() será equivalente a la función unlink() o rmdir() excepto en el caso en que path especifique una ruta relativa. En este caso, la entrada de directorio a eliminar se determinará en relación con el directorio asociado con el descriptor de archivo fd en lugar del directorio de trabajo actual. Si el modo de acceso de la descripción del archivo abierto asociado con el descriptor de archivo no es O_SEARCH, la función verificará si se permiten las búsquedas de directorios utilizando los permisos actuales del directorio subyacente al descriptor de archivo. Si el modo de acceso es O_SEARCH, la función no realizará la verificación.

Los valores para flag se construyen mediante una operación OR inclusiva a nivel de bits de las banderas de la siguiente lista, definidas en <fcntl.h>:

AT_REMOVEDIR

Elimina la entrada de directorio especificada por fd y path como directorio, no como archivo normal.

Si a unlinkat() se le pasa el valor especial AT_FDCWD en el parámetro fd, se utilizará el directorio de trabajo actual y el comportamiento será idéntico al de una llamada a unlink() o rmdir() respectivamente, dependiendo de si el bit AT_REMOVEDIR está establecido o no en flag.

VALOR DE RETORNO

Tras una finalización exitosa, estas funciones devolverán 0. De lo contrario, estas funciones devolverán -1 y establecerán errno para indicar el error. Si se devuelve -1, el archivo nombrado no se modificará.

ERRORES

Estas funciones fallarán y no eliminarán el archivo si:

EACCES
Se deniega el permiso de búsqueda para un componente del prefijo de ruta, o se deniega el permiso de escritura en el directorio que contiene la entrada de directorio a eliminar.
EBUSY
El archivo nombrado por el argumento path no puede ser eliminado porque está siendo utilizado por el sistema u otro proceso y la implementación lo considera un error.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un componente de una ruta de acceso es mayor que {NAME_MAX}.
ENOENT
Un componente de path no nombra un archivo existente o path es una cadena vacía.
ENOTDIR
Un componente del prefijo de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o el argumento path contiene al menos un carácter que no es <barra> y termina con una o más barras (<barra>) finales y el último componente de la ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.
EPERM
El archivo nombrado por path es un directorio, y el proceso que llama no tiene los privilegios apropiados, o la implementación prohíbe el uso de unlink() en directorios.
EPERM o EACCES

El bit S_ISVTX está establecido en el directorio que contiene el archivo al que se refiere el argumento path y el proceso no cumple los criterios especificados en el volumen de Definiciones Base de POSIX.1‐2017, Sección 4.3, Protección de directorios.
EROFS
La entrada de directorio a eliminar es parte de un sistema de archivos de solo lectura.

La función unlinkat() fallará si:

EACCES
El modo de acceso de la descripción del archivo abierto asociado con fd no es O_SEARCH y los permisos del directorio subyacente a fd no permiten búsquedas de directorios.
EBADF
El argumento path no especifica una ruta absoluta y fd no es ni AT_FDCWD ni un descriptor de archivo válido abierto para lectura o búsqueda.
ENOTDIR
El argumento path no es una ruta absoluta y fd es un descriptor de archivo asociado con un archivo que no es un directorio.
EEXIST o ENOTEMPTY

El parámetro flag tiene el bit AT_REMOVEDIR establecido y el argumento path nombra un directorio que no está vacío, o existen enlaces duros al directorio distintos de punto o una única entrada en punto-punto.
ENOTDIR
El parámetro flag tiene el bit AT_REMOVEDIR establecido y path no nombra un directorio.

Estas funciones pueden fallar y no eliminar el archivo si:

EBUSY
El archivo nombrado por path es un STREAM con nombre.
ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
ENAMETOOLONG

La longitud de una ruta de acceso excede {PATH_MAX}, o la resolución de una ruta de acceso de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.
ETXTBSY
La entrada a eliminar es la última entrada de directorio de un archivo de procedimiento puro (texto compartido) que se está ejecutando.

La función unlinkat() puede fallar si:

EINVAL
El valor del argumento flag no es válido.

unlink(3p) — Arch manual pages

NAME

unlink, unlinkat - remove a name from a filesystem

SYNOPSIS

#include <unistd.h>

int
unlink(const char *pathname);

int
unlinkat(int dirfd, const char *pathname, int flags);

DESCRIPTION

The unlink() function shall remove a reference to a file from the filesystem. If that reference was the last reference to the file, then the file shall be removed. If the pathname points to a non-empty directory, the function shall fail. Otherwise, the pathname is removed from the filesystem.

When unlink() is called on a path name that resolves to a symbolic link, a symbolic link is removed. The symbolic link itself is removed, not the file it points to.

If the pathname is a character special or block special file, or a FIFO, the function shall fail.

If the pathname refers to a directory, the behavior is implementation-defined, but it is required that unlink() fails for non-empty directories. It is recommended that the function fail for empty directories as well.

The unlinkat() function may be used to operate on a file relative to a directory specified by the file descriptor dirfd. If pathname is relative, then it is interpreted relative to the directory associated with the file descriptor dirfd. If pathname is absolute, the dirfd is ignored.

If pathname is relative and begins with a slash (/), or if pathname is absolute, it is resolved relative to the process's current working directory. If pathname is relative, then it is interpreted relative to the directory associated with the file descriptor dirfd. If dirfd is AT_FDCWD, then pathname is interpreted relative to the current working directory.

The flags argument is a bitmask and can include or be zero. The only value supported in this volume of POSIX.1‐2017 is:

AT_REMOVEDIR
This flag causes unlinkat() to behave like rmdir() for a directory name. The function will fail if the named file is not an empty directory. If this flag is set, the call to unlinkat() may remove a directory entry in a directory other than the current working directory without exposure to race conditions. Any part of the path of a file could be changed in parallel to a call to unlink() or rmdir(), resulting in unspecified behavior. By opening a file descriptor for the target directory and using the unlinkat() function with the AT_REMOVEDIR flag, it can be guaranteed that the removed directory entry is located relative to the desired directory.

The standard POSIX.1‐2017 requires that the file descriptor dirfd be the file descriptor for a directory. It may be opened using the open() function with the O_DIRECTORY flag. However, that flag is not specified by POSIX.1‐2017, and the application should expect that the descriptor might be for a non-directory file. If the descriptor dirfd is for a regular file, character special file, block special file, FIFO, or socket, the call to unlinkat() will fail.

If flags is 0, then unlinkat() behaves like unlink().

The link count of the file is decremented by one. If the link count becomes zero and no process has the file open, the space occupied by the file shall be freed. If, however, the file is open by some process, the space shall not be freed until the last process closes the file descriptor referring to the file. (See open()).

If pathname names a symbolic link, the symbolic link itself is removed.

If pathname names a directory, it must be empty. If it is empty, it is removed. If it is not empty, unlink() fails.

The unlink() function shall fail if:

EACCES
Search permission is denied for a component of the path prefix.
EACCES
Write permission is denied for the directory in which the link is to be created.
EACCES
The file is a non-empty directory, and the calling process does not have permission to remove it.
EBUSY
The file referred to by pathname is busy.
EINVAL
The named file is a directory and the calling process does not have permission to remove it.
EISDIR
The named file is a directory. This error is returned by some implementations if the file is a directory.
ELOOP
A loop exists in symbolic links encountered in resolving pathname.
EMLINK
The directory in which the link is to be created has the maximum number of links to it.
ENAMETOOLONG
The length of pathname exceeds {PATH_MAX}, or a pathname component is longer than {NAME_MAX}.
ENOENT
A component of pathname does not exist, or pathname is an empty string.
ENOTDIR
A component of the path prefix is not a directory.
ENXIO
The named file is a character special or block special file, and the device does not exist.
EPERM
The named file is a directory, and the calling process does not have permission to remove it.
EROFS
The named file is on a read-only filesystem.
ETXTBSY
The file is a regular file that is currently being executed, and the calling process does not have permission to remove it.

The unlinkat() function shall fail if:

EBADF
pathname is relative but dirfd is not a valid file descriptor.
EINVAL
flags contains an unsupported value.
EINVAL
dirfd was specified as AT_FDCWD and pathname referred to a directory that the calling process does not have permission to remove.
ELOOP
More than {SYMLOOP_MAX} symbolic links were encountered during resolution of the pathname.
ENOTDIR
pathname is relative, and dirfd refers to a file that is not a directory.
ENOTDIR
A component of the path prefix is not a directory (when pathname is relative to an opened directory).
ENOENT
pathname does not exist or pathname is an empty string (when pathname is relative to an opened directory).
ENOMEM
Insufficient system memory is available.
EOVERFLOW
The file is a directory and the system cannot remove it because the directory is not empty and the file system does not support the removal of directories or the file is too large for the system to handle.
EPERM
The file referred to by pathname is a directory, and the calling process does not have permission to remove it.
EROFS
The file referred to by pathname is on a read-only filesystem.
ETXTBSY
The file referred to by pathname is a regular file that is currently being executed, and the calling process does not have permission to remove it.

The unlinkat() function may fail if:

EBUSY
The file referred to by pathname is busy.
EISDIR
The file referred to by pathname is a directory. This error is returned by some implementations if the file is a directory. If the AT_REMOVEDIR flag is set, this error is not returned for empty directories.

The unlinkat() function may fail and return [EBADF] if dirfd refers to a file that is not a directory and the AT_REMOVEDIR flag is specified.

The unlinkat() function may fail if the file referred to by pathname is a directory and the calling process does not have permission to remove it.

The unlinkat() function may fail if the file referred to by pathname is a regular file that is currently being executed, and the calling process does not have permission to remove it.

The unlinkat() function may fail if the file referred to by pathname is a character special or block special file, or a FIFO, and the device does not exist.

The following sections are informative.

EXAMPLES

The following example fragment removes the file /modules/pass1.

#include <unistd.h>
char *path = "/modules/pass1";
int   status;
...
status = unlink(path);

Checking for an Error

The following example fragment creates a temporary password lock file named LOCKFILE, which is defined as /etc/ptmp, and gets a file descriptor for it. If the file cannot be opened for writing, unlink() is used to remove the link between the file descriptor and LOCKFILE.

#include <sys/types.h>
#include <stdio.h>
#include <fcntl.h>
#include <errno.h>
#include <unistd.h>
#include <sys/stat.h>
#define LOCKFILE "/etc/ptmp"
int pfd;  /* Integer for file descriptor returned by open call. */
FILE *fpfd;  /* File pointer for use in putpwent(). */
...
/* Open password Lock file. If it exists, this is an error. */
if ((pfd = open(LOCKFILE, O_WRONLY| O_CREAT | O_EXCL, S_IRUSR
    | S_IWUSR | S_IRGRP | S_IROTH)) == -1)  {
    fprintf(stderr, "Cannot open /etc/ptmp. Try again later.\n");
    exit(1);
}
/* Lock file created; proceed with fdopen of lock file so that
   putpwent() can be used.
 */
if ((fpfd = fdopen(pfd, "w")) == NULL) {
    close(pfd);
    unlink(LOCKFILE);
    exit(1);
}

Replacing Files

The following example fragment uses unlink() to discard links to files, so that they can be replaced with new versions of the files. The first call removes the link to LOCKFILE if an error occurs. Successive calls remove the links to SAVEFILE and PASSWDFILE so that new links can be created, then removes the link to LOCKFILE when it is no longer needed.

#include <sys/types.h>
#include <stdio.h>
#include <fcntl.h>
#include <errno.h>
#include <unistd.h>
#include <sys/stat.h>
#define LOCKFILE "/etc/ptmp"
#define PASSWDFILE "/etc/passwd"
#define SAVEFILE "/etc/opasswd"
...
/* If no change was made, assume error and leave passwd unchanged. */
if (!valid_change) {
    fprintf(stderr, "Could not change password for user %s\n", user);
    unlink(LOCKFILE);
    exit(1);
}
/* Change permissions on new password file. */
chmod(LOCKFILE, S_IRUSR | S_IRGRP | S_IROTH);
/* Remove saved password file. */
unlink(SAVEFILE);
/* Save current password file. */
link(PASSWDFILE, SAVEFILE);
/* Remove current password file. */
unlink(PASSWDFILE);
/* Save new password file as current password file. */
link(LOCKFILE,PASSWDFILE);
/* Remove lock file. */
unlink(LOCKFILE);
exit(0);

APPLICATION USAGE

Applications should use rmdir() to remove a directory.

RATIONALE

Unlinking a directory is restricted to the superuser in many historical implementations for reasons given in link() (see also rename()).

The meaning of [EBUSY] in historical implementations is ``mount point busy''. Since this volume of POSIX.1‐2017 does not cover the system administration concepts of mounting and unmounting, the description of the error was changed to ``resource busy''. (This meaning is used by some device drivers when a second process tries to open an exclusive use device.) The wording is also intended to allow implementations to refuse to remove a directory if it is the root or current working directory of any process.

The standard developers reviewed TR 24715‐2006 and noted that LSB-conforming implementations may return [EISDIR] instead of [EPERM] when unlinking a directory. A change to permit this behavior by changing the requirement for [EPERM] to [EPERM] or [EISDIR] was considered, but decided against since it would break existing strictly conforming and conforming applications. Applications written for portability to both POSIX.1‐2008 and the LSB should be prepared to handle either error code.

The purpose of the unlinkat() function is to remove directory entries in directories other than the current working directory without exposure to race conditions. Any part of the path of a file could be changed in parallel to a call to unlink(), resulting in unspecified behavior. By opening a file descriptor for the target directory and using the unlinkat() function it can be guaranteed that the removed directory entry is located relative to the desired directory.
