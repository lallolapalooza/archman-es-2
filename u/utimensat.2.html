utimensat(2) Manual de llamadas al sistema utimensat(2)

NOMBRE

utimensat, futimens - cambiar las marcas de tiempo de archivos con precisión de nanosegundos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <fcntl.h> /* Definición de las constantes AT_* */
#include <sys/stat.h>
int utimensat(int dirfd, const char *path,
              const struct timespec times[_Nullable 2], int flags);
int futimens(int fd, const struct timespec times[_Nullable 2]);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

utimensat():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _ATFILE_SOURCE

futimens():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _GNU_SOURCE

DESCRIPCIÓN

utimensat() y futimens() actualizan las marcas de tiempo de un archivo con precisión de nanosegundos. Esto contrasta con las históricas llamadas utime(2) y utimes(2), que permiten solo precisión de segundos y microsegundos, respectivamente, al establecer marcas de tiempo de archivos.

Con utimensat(), el archivo se especifica a través de la ruta dada en path. Con futimens(), el archivo cuyas marcas de tiempo se van a actualizar se especifica a través de un descriptor de archivo abierto, fd.

Para ambas llamadas, las nuevas marcas de tiempo del archivo se especifican en el array times: times[0] especifica la nueva "hora de último acceso" (atime); times[1] especifica la nueva "hora de última modificación" (mtime). Cada uno de los elementos de times especifica una hora como el número de segundos y nanosegundos desde la Época, 1970-01-01 00:00:00 +0000 (UTC). Esta información se transmite en una estructura timespec(3).

Las marcas de tiempo actualizadas del archivo se establecerán al mayor valor soportado por el sistema de archivos que no sea mayor que el tiempo especificado.

Si el campo tv_nsec de una de las estructuras timespec tiene el valor especial UTIME_NOW, entonces la marca de tiempo correspondiente del archivo se establecerá a la hora actual. Si el campo tv_nsec de una de las estructuras timespec tiene el valor especial UTIME_OMIT, entonces la marca de tiempo correspondiente del archivo se dejará sin cambios. En ambos casos, el valor del campo tv_sec correspondiente se ignora.

Si times es NULL, entonces ambas marcas de tiempo se establecerán a la hora actual.

La hora de cambio de estado (ctime) se establecerá a la hora actual, incluso si las otras marcas de tiempo no cambian realmente.

Requisitos de permisos

Para establecer ambas marcas de tiempo del archivo a la hora actual (es decir, times es NULL, o ambos campos tv_nsec especifican UTIME_NOW), se requiere una de las siguientes opciones:

•
el llamador debe tener acceso de escritura al archivo;
•
el ID de usuario efectivo del llamador debe coincidir con el propietario del archivo; o
•
el llamador debe tener privilegios apropiados.

Para realizar cualquier cambio que no sea establecer ambas marcas de tiempo a la hora actual (es decir, times no es NULL, y ningún campo tv_nsec es UTIME_NOW y ningún campo tv_nsec es UTIME_OMIT), se debe aplicar una de las condiciones 2 o 3 anteriores.

Si ambos campos tv_nsec se especifican como UTIME_OMIT, entonces no se realizan comprobaciones de propiedad o permisos del archivo, y las marcas de tiempo del archivo no se modifican, pero aún pueden detectarse otras condiciones de error.

Especificidades de utimensat()

Si path es relativo, entonces por defecto se interpreta en relación con el directorio al que se refiere el descriptor de archivo abierto, dirfd (en lugar de en relación con el directorio de trabajo actual del proceso llamador, como se hace con utimes(2) para un nombre de ruta relativo). Ver openat(2) para una explicación de por qué esto puede ser útil.

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso llamador (como utimes(2)).

Si path es absoluto, entonces dirfd se ignora.

El argumento flags es una máscara de bits creada combinando mediante OR cero o más de los siguientes valores definidos en <fcntl.h>:

AT_EMPTY_PATH (desde Linux 5.8)
Si path es una cadena vacía, opera sobre el archivo al que se refiere dirfd (que puede haber sido obtenido usando la bandera O_PATH de open(2)). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio. Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; define _GNU_SOURCE para obtener su definición.
AT_SYMLINK_NOFOLLOW
Si path especifica un enlace simbólico, entonces actualiza las marcas de tiempo del enlace, en lugar de las del archivo al que apunta.

VALOR DE RETORNO

En caso de éxito, utimensat() y futimens() devuelven 0. En caso de error, devuelven -1 y errno se establece para indicar el error.

ERRORES

EACCES
times es NULL, o ambos valores tv_nsec son UTIME_NOW, y el ID de usuario efectivo del llamador no coincide con el propietario del archivo, el llamador no tiene acceso de escritura al archivo, y el llamador no tiene privilegios (Linux: no tiene ni la capacidad CAP_FOWNER ni la capacidad CAP_DAC_OVERRIDE).
EBADF
(futimens()) fd no es un descriptor de archivo válido.
EBADF
(utimensat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
times apuntaba a una dirección inválida; o, dirfd era AT_FDCWD, y path es NULL o una dirección inválida.
EINVAL
Valor inválido en flags.
EINVAL
Valor inválido en uno de los campos tv_nsec (valor fuera del rango [0, 999.999.999], y no es UTIME_NOW o UTIME_OMIT); o un valor inválido en uno de los campos tv_sec.
EINVAL
path es NULL, dirfd no es AT_FDCWD, y flags contiene AT_SYMLINK_NOFOLLOW.
ELOOP
(utimensat()) Se encontraron demasiados enlaces simbólicos al resolver path.
ENAMETOOLONG
(utimensat()) path es demasiado largo.
ENOENT
(utimensat()) Un componente de path no se refiere a un directorio o archivo existente, o path es una cadena vacía.
ENOTDIR
(utimensat()) path es relativo, pero dirfd no es AT_FDCWD ni un descriptor de archivo que se refiera a un directorio; o, un componente prefijo de path no es un directorio.
EPERM
El llamador intentó cambiar una o ambas marcas de tiempo a un valor distinto de la hora actual, o cambiar una de las marcas de tiempo a la hora actual mientras dejaba la otra marca de tiempo sin cambios (es decir, times no es NULL, ningún campo tv_nsec i
s UTIME_NOW, y ninguno de los campos tv_nsec es UTIME_OMIT) y además:
•
el ID de usuario efectivo del llamante no coincide con el propietario del archivo, y el llamante no tiene privilegios (Linux: no tiene la capacidad CAP_FOWNER); o,
•
el archivo está marcado como solo para añadir o inmutable (ver chattr(1)).
EROFS
El archivo está en un sistema de archivos de solo lectura.
ESRCH
(utimensat()) Se deniega el permiso de búsqueda para uno de los componentes prefijo de path.

VERSIONES

Diferencias ABI de la biblioteca C/kernel

En Linux, futimens() es una función de biblioteca implementada sobre la llamada al sistema utimensat(). Para soportar esto, la llamada al sistema utimensat() de Linux implementa una característica no estándar: si path es NULL, entonces la llamada modifica las marcas de tiempo del archivo al que se refiere el descriptor de archivo dirfd (que puede referirse a cualquier tipo de archivo). Usando esta característica, la llamada futimens(fd, times) se implementa como:


utimensat(fd, NULL, times, 0);

Sin embargo, ten en cuenta que la envoltura de glibc para utimensat() no permite pasar NULL como valor para path: la función envoltoria devuelve el error EINVAL en este caso.

NOTAS

utimensat() deja obsoleto futimesat(2).

En Linux, las marcas de tiempo no se pueden modificar para un archivo marcado como inmutable, y el único cambio permitido para los archivos marcados como solo para añadir es establecer las marcas de tiempo a la hora actual. (Esto es coherente con el comportamiento histórico de utime(2) y utimes(2) en Linux).

Si ambos campos tv_nsec se especifican como UTIME_OMIT, entonces la implementación de Linux de utimensat() tiene éxito incluso si el archivo al que se hace referencia mediante dirfd y path no existe.

ERRORES

Varios errores afectan a utimensat() y futimens() antes de Linux 2.6.26. Estos errores son no conformidades con la especificación del borrador POSIX.1 o inconsistencias con el comportamiento histórico de Linux.

•
POSIX.1 especifica que si uno de los campos tv_nsec tiene el valor UTIME_NOW o UTIME_OMIT, entonces el valor del campo tv_sec correspondiente debe ser ignorado. En cambio, se requiere que el valor del campo tv_sec sea 0 (o se producirá el error EINVAL).
•
Varios errores implican que, a efectos de comprobación de permisos, el caso en que ambos campos tv_nsec se establecen en UTIME_NOW no siempre se trata igual que especificar times como NULL, y el caso en que un valor tv_nsec es UTIME_NOW y el otro es UTIME_OMIT no se trata igual que especificar times como un puntero a una matriz de estructuras que contienen valores de tiempo arbitrarios. Como resultado, en algunos casos: a) las marcas de tiempo de los archivos pueden ser actualizadas por un proceso que no debería tener permiso para realizar actualizaciones; b) las marcas de tiempo de los archivos no se pueden actualizar por un proceso que debería tener permiso para realizar actualizaciones; y c) se devuelve el valor errno incorrecto en caso de error.
•
POSIX.1 dice que un proceso que tiene acceso de escritura al archivo puede hacer una llamada con times como NULL, o con times apuntando a una matriz de estructuras en la que ambos campos tv_nsec son UTIME_NOW, para actualizar ambas marcas de tiempo a la hora actual. Sin embargo, futimens() en su lugar comprueba si el modo de acceso del descriptor de archivo permite la escritura.
