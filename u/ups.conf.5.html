UPS.CONF(5) Manual NUT UPS.CONF(5)

NOMBRE

ups.conf - Definiciones de UPS para Network UPS Tools

DESCRIPCIÓN

Este archivo es leído por el controlador de drivers upsdrvctl(8), los drivers de UPS que usan el núcleo común (ver nutupsdrv(8)), nut-driver-enumerator(8), y el servidor de datos NUT upsd(8). El archivo comienza con directivas globales, y luego cada UPS tiene una sección que contiene un número de directivas que establecen parámetros para esa UPS.

Una sección de UPS comienza con el nombre de la UPS entre corchetes, y continúa hasta el siguiente nombre de UPS entre corchetes o hasta EOF. El nombre "default" se usa internamente en upsd(8), por lo que no puedes usarlo en este archivo.

Debes definir los elementos driver y port para cada entrada. Cualquier cosa después de eso en una sección es opcional. Un ejemplo simple podría verse así:

[miups]
        driver = blazer_ser
        port = /dev/ttyS0
        desc = "UPS del servidor web"

Una versión un poco más complicada incluye algunos extras para la parte específica del hardware del driver:

[bigups]
        driver = apcsmart
        port = /dev/cua00
        cable = 940-0095B
        sdtype = 2
        desc = "UPS del servidor de base de datos"

En este caso, el driver apcsmart(8) recibirá variables llamadas "cable" y "sdtype" que tienen significados especiales. Consulta las páginas del manual de tu(s) driver(s) para saber qué variables son compatibles y qué hacen.

Aquí hay otro ejemplo, al conectar una UPS serial en Windows:

[windows-ups]
        driver = mge-shut
        port = "\\\\.\\COM10"
        desc = "UPS en una máquina Windows"

NOTAS IMPORTANTES

•El contenido de este archivo debe ser puro ASCII (los códigos de caracteres que no estén en el rango serán ignorados con un mensaje de advertencia).
•Equilibra los permisos del usuario en tiempo de ejecución para acceder al archivo (y quizás al directorio en el que se encuentra) solo para que upsd y los drivers puedan leerlo; no se necesita acceso de escritura. Es común usar chown root:nut y chmod 640 para configurar permisos de archivo aceptables.
•Los paquetes (y las recetas de compilación) preparan típicamente un conjunto de cuentas de usuario y grupo para NUT. Las compilaciones personalizadas con configuración mínima podrían incluso usar nobody:nogroup o similar, lo cual es intrínsecamente inseguro.
•En sistemas con preocupaciones de seguridad adicionales, los drivers de NUT y el servidor de datos deben ejecutarse como cuentas de usuario separadas que sean miembros del mismo grupo para el acceso compartido a los archivos de socket Unix locales y al directorio en el que se encuentran, así como para leer ups.conf, pero grupos diferentes para el acceso a otros archivos de configuración. Esto requeriría que algunos demonios utilicen configuraciones personalizadas de usuario, grupo, RUN_AS_USER y/o RUN_AS_GROUP para anular el único valor incorporado.
•Ten en cuenta que los clientes de monitoreo, registro, etc. son solo de red. No necesitan acceso a estos archivos y directorios, y pueden ejecutarse como un usuario y grupo independientes en su totalidad.
•Ten en cuenta la seguridad de también cualquier copia de seguridad de este archivo, por ejemplo, los archivos de archivo en los que podría terminar.

DIRECTIVAS GLOBALES

chroot

Opcional. El driver hará chroot(2) a este directorio durante la inicialización. Esto puede ser útil al asegurar sistemas.

driverpath

Opcional. Nombre de la ruta del directorio en el que residen los ejecutables del driver de UPS. Si no especificas esto, los programas buscarán en un directorio predeterminado incorporado, que a menudo es /usr/local/ups/bin.

statepath

Opcional. Nombre de la ruta del directorio en el que los drivers de UPS deben colocar sus sockets de estado para la comunicación local con el servidor de datos upsd, en lugar de la ubicación predeterminada que se compiló en el programa, que a menudo es /var/state/ups.

Ten en cuenta que los drivers deben usar la misma ruta que upsd, por lo que el servidor de datos preferirá esta configuración de la sección global de ups.conf, si está presente, sobre la suya propia en upsd.conf.

La variable de entorno NUT_STATEPATH establecida por el llamador puede anular esta configuración.

maxstartdelay

Opcional. Igual que el campo UPS del mismo nombre, pero este es el valor predeterminado para las UPS que no tienen el campo.

maxretry

Opcional. Especifica el número de intentos de iniciar los drivers, en caso de fallo, antes de rendirse. Se inserta un retraso de retrydelay entre cada intento. Se debe tener precaución al usar esta opción, ya que puede afectar el tiempo que tarda tu sistema en iniciarse.

El valor predeterminado es 1 intento.

nowait

Opcional. Especifica a upsdrvctl que no espere en absoluto a que los drivers ejecuten el comando de solicitud.

El valor predeterminado (omisión) es esperar.

Puede ser anulado por la variable de entorno NUT_IGNORE_NOWAIT (por ejemplo, utilizada para solucionar problemas con systemd de lo contrario).

retrydelay

Opcional. Especifica el retraso entre cada intento de reinicio de los drivers, como se especifica en maxretry. Se debe tener precaución al usar esta opción, ya que puede afectar el tiempo que tarda tu sistema en iniciarse.

El valor predeterminado es 5 segundos.

pollinterval

Opcional. El estado de la UPS se actualizará después de un retraso máximo controlado por esta configuración. Normalmente es de 2 segundos. Esta configuración puede ser útil si el driver está creando demasiada carga en tu sistema de monitoreo o red.

Ten en cuenta que algunos drivers (como usbhid-ups(8), snmp-ups(8) y nutdrv_qx(8)) también tienen una opción llamada pollfreq que controla la frecuencia con la que se consultan algunos de los parámetros menos críticos. Los detalles se proporcionan en las páginas del manual correspondientes.

synchronous

Opcional. Los drivers funcionan por defecto en modo asíncrono inicialmente, pero pueden volver a modo síncrono si las escrituras al socket del servidor fallan (es decir, synchronous=auto). Esto significa que todos los datos son enviados por el driver al socket de comunicación a upsd (socket Unix en Unix, tubería con nombre en Windows) sin esperar a que estos datos sean realmente consumidos. Con algunos dispositivos de hardware, como las ePDUs, que pueden producir muchos datos, el modo asíncrono puede causar congestión, lo que resulta en que el socket se llene y el driver parezca desconectado. En ese caso, el driver proporcionará el siguiente mensaje de depuración: 
write XX bytes to socket Y failed

Al habilitar el indicador synchronous (valor = yes), el driver esperará a que upsd consuma los datos antes de publicar más. Esto se puede habilitar de forma global o por driver.

El valor predeterminado de auto actúa como no (es decir, modo asíncrono) para la compatibilidad hacia atrás del comportamiento del driver, hasta que las comunicaciones fallen con una condición de "Resource temporarily unavailable" (Recurso temporalmente no disponible), que ocurre cuando el driver tiene muchos puntos de datos que enviar en ráfaga, y el servidor no puede manejarlo lo suficientemente rápido, por lo que el buffer se llena.

user

Opcional. Anula el nombre de usuario sin privilegios predeterminado compilado para todos los drivers de dispositivos NUT. Consulta la discusión de la opción -u en nutupsdrv(8) para obtener detalles.

group

Opcional. Anula el nombre de grupo sin privilegios predeterminado compilado (y/o de la sección global) para todos los drivers de dispositivos NUT, utilizado para el acceso al archivo de socket. Consulta la discusión de la opción -g en nutupsdrv(8) para obtener detalles. Esto puede ser especialmente útil para garantizar el acceso a nodos del sistema de archivos de dispositivos dinámicos, como el soporte de conexión en caliente USB (o serial sobre USB), o con sistemas de archivos de dispositivos regenerados por un sistema operativo en cada reinicio.

debug_min ENTERO

Opcional. Especifica un nivel de depuración mínimo para todos los demonios de drivers, por ejemplo, para solucionar problemas de una implementación, sin afectar directamente el modo de ejecución en primer plano o en segundo plano. La opción de línea de comandos -D solo puede aumentar este nivel de verbosidad.

LIBUSB_DEBUG ENTERO

Opcional. Para la solución de problemas en tiempo de ejecución de drivers NUT compatibles con USB, puedes especificar la verbosidad de la depuración específica de LibUSB como un núme

debug_min

Opcional. Especifique un nivel de depuración mínimo para este demonio controlador, p. ej., para solucionar problemas de implementación, sin afectar directamente al modo de ejecución en primer plano o en segundo plano. Si también está configurado el debug_min global, esta configuración a nivel de controlador la anula. La opción de línea de comandos -D solo puede aumentar este nivel de verbosidad.

LIBUSB_DEBUG

Opcional. Para la solución de problemas en tiempo de ejecución de controladores NUT capaces de usar USB, puede especificar la verbosidad de la depuración específica de LibUSB como un valor numérico, como 4 ("Se emiten todos los mensajes"). No debería tener ningún impacto práctico en otros controladores NUT.

Para más detalles, incluyendo los valores actualmente admitidos para su versión de la biblioteca, consulte, por ejemplo:

•https://libusb.sourceforge.io/api-1.0/
•https://libusb.sourceforge.io/api-1.0/group__libusb__lib.html

CAMPOS DE UPS

driver

Requerido. Esto especifica qué programa supervisará esta UPS. Debe especificar el que sea compatible con su hardware. Consulte nutupsdrv(8) para obtener más información sobre los controladores en general y enlaces a las páginas del manual de controladores específicos.

port

Requerido. Este es el puerto serie al que está conectada la UPS. En un sistema Linux, el primer puerto serie suele ser /dev/ttyS0. En sistemas FreeBSD y similares, probablemente será /dev/cuaa0. En Windows, el primer puerto serie será "\\\\.\\COM1" (tenga en cuenta las barras invertidas escapadas).

user

Opcional. Anula el nombre de usuario privilegiado predeterminado compilado (y/o de la sección global) para un controlador de dispositivo NUT particular. Consulte la discusión de la opción -u en nutupsdrv(8) para obtener detalles. Esto puede ser útil específicamente para garantizar el acceso a nodos dinámicos del sistema de archivos de dispositivos, como el soporte de conexión en caliente USB (o serie sobre USB), o con sistemas de archivos de dispositivos regenerados por un SO en cada reinicio.

group

Opcional. Anula el nombre de grupo privilegiado predeterminado compilado (y/o de la sección global) para un controlador de dispositivo NUT particular, utilizado para el acceso al archivo del socket. Consulte la discusión de la opción -g en nutupsdrv(8) para obtener detalles. Esto puede ser útil específicamente para garantizar el acceso a nodos dinámicos del sistema de archivos de dispositivos, como el soporte de conexión en caliente USB (o serie sobre USB), o con sistemas de archivos de dispositivos regenerados por un SO en cada reinicio.

sdorder

Opcional. Cuando tiene varias UPS en su sistema, generalmente necesita apagarlas en un orden determinado. upsdrvctl apaga todas las 0, luego las 1, 2, etc. Para excluir una UPS de la secuencia de apagado, configúrela en -1.

El valor predeterminado para este parámetro es 0.

sdcommands

Opcional. Lista separada por comas de nombres de comandos instantáneos que se enviarán a la UPS cuando se solicite su apagado.

La lógica predeterminada está integrada en cada controlador (donde se admite) y se puede referenciar aquí como el valor shutdown.default.

El caso de uso principal es para dispositivos cuyos controladores admiten "nativamente" probar varios comandos, pero el orden predeterminado de esas llamadas contiene un comando que se maneja mal por el modelo de dispositivo específico (por lo que el manejo se informa como exitoso y el bucle se detiene, pero no sucede nada en lo que respecta a la desconexión de energía de la carga).

Otro caso de uso es la diferenciación de escenarios de apagado automatizado donde la UPS y su carga deben permanecer "APAGADOS" (por ejemplo, mediante la generación de apagado de emergencia) frente a aquellos donde la carga debe volver a funcionar automáticamente cuando sea seguro hacerlo. NOTA: Esto requeriría **actualmente** editar ups.conf para tales casos antes de que nutshutdown vea el archivo; pero podría automatizarse mejor en futuras versiones de NUT.


Nota
Los comandos proporcionados por el usuario pueden ser algo más que un apagado real, por ejemplo, un avisador para probar que el INSTCMD ocurrió y cuándo se esperaba, y que el dispositivo fue contactado, sin afectar la carga alimentada por la UPS.

allow_killpower

Opcional. Esto le permite solicitar el comando instantáneo driver.killpower, para llamar inmediatamente a la implementación predeterminada específica del controlador del método upsdrv_shutdown(), con el mismo efecto que cuando un controlador NUT se inicia con la bandera de línea de comandos -k. Esta opción se puede alternar con upsrw(8) como driver.flag.allow_killpower en tiempo de ejecución.

desc

Opcional. Esto le permite establecer una breve descripción que upsd proporcionará a los clientes que soliciten una lista de equipos conectados.

nolock

Opcional. Cuando especifica esto, el controlador omite las rutinas de bloqueo del puerto cada vez que se inicia. Esto puede permitir que otros procesos se apoderen del puerto si inicia más de uno accidentalmente.

Solo debe usar esto si su sistema no funciona sin él.

Esto puede ser necesario en sistemas Mac OS X.

ignorelb

Opcional. Cuando especifica esto, el controlador ignora una bandera de condición de batería baja que informa la UPS (algunos dispositivos se apagan casi inmediatamente después de establecer esta bandera, o informan esto tan pronto como falla la red eléctrica). En su lugar, utilizará alguna de las siguientes condiciones para determinar cuándo la batería está baja: 
battery.charge < battery.charge.low
battery.runtime < battery.runtime.low

La idea es establecer los niveles battery.charge.low y/o battery.runtime.low en ups.conf a un valor que dé tiempo suficiente para apagar limpiamente su sistema:

override.battery.charge.low = 30
override.battery.runtime.low = 180

Para que esto funcione, su UPS debería poder informar (de manera confiable) la carga y/o el tiempo de ejecución restante con batería. ¡Úselo con precaución!

maxstartdelay

Opcional. Esto se puede establecer como una variable global por encima de su primera definición de UPS y también se puede establecer en una sección de UPS. Este valor controla cuánto tiempo esperará upsdrvctl para que el controlador termine de iniciarse. Esto evita que su sistema se quede atascado debido a un controlador o UPS defectuosos.

Tenga en cuenta que después de este tiempo, upsdrvctl seguirá con sus asuntos (ya sea reintentando el mismo controlador si maxretry>1, o intentando otro controlador si los inicia todos, o simplemente saliendo eventualmente); sin embargo, cada uno de esos procesos de controlador "atascados" iniciados más recientemente puede seguir inicializándose en segundo plano, e incluso tener éxito eventualmente.

No serán terminados activamente por upsdrvctl después de que expire este tiempo de espera.

El valor predeterminado es 75 segundos.

maxretry

Opcional. Esto se puede establecer como una variable global por encima de su primera definición de UPS y también se puede establecer en una sección de UPS. Consulte la explicación anterior, en la sección global.

retrydelay

Opcional. Esto se puede establecer como una variable global por encima de su primera definición de UPS y también se puede establecer en una sección de UPS. Consulte la explicación anterior, en la sección global.

synchronous

Opcional. Igual que la directiva global del mismo nombre, pero esto es para un dispositivo específico.

usb_set_altinterface[=altinterface]

Opcional. Fuerza al código USB a llamar a usb_set_altinterface(0), como se hizo en NUT 2.7.2 y versiones anteriores. Esto no debería ser necesario, ya que el valor predeterminado para bAlternateSetting (como se muestra en lsusb) es cero en todos los dispositivos USB vistos hasta la fecha. Sin embargo, esta llamada redundante a usb_set_altinterface() evita que ciertas UPS funcionen en Mac OS X. Si su UPS requiere establecer explícitamente la interfaz alternativa, incluya esta bandera y envíe un correo a la lista nut-upsdev con detalles sobre su UPS y sistema operativo.

usb_config_index, usb_hid_rep_index, usb_hid_desc_index, usb_hid_ep_in, usb_hid_ep_out

Opcional. Fuerza el uso de números específicos de interfaz, endpoint, índice de descriptor, etc., en lugar de usar el valor predeterminado 0 (raramente otros valores en ciertos controladores para algunos dispositivos conocidos por usar números distintos de cero). Se especifica como un número hexadecimal.

Como regla general para el descubrimiento de usb_hid_desc_index, puede ver valores más grandes de wDescriptorLength (aproximadamente 600+ bytes) en los informes de lsusb o herramientas similares.

default.<variable>

Opcional. Establezca un valor predeterminado para <variable> que se utiliza en caso de que la UPS no proporcione un valor, pero se anulará si hay un valor disponible de la UPS: 
default.input.voltage.nominal = 230

Lo anterior informará que el voltaje de entrada nominal es 230, a menos que la UPS nos indique lo contrario.

override.<variable>

Opcional. Establezca un valor para <value> que anule cualquier valor que pueda leerse de la UPS. Se utiliza para anular valores de la UPS que son claramente incorrectos (algunos dispositivos informan valores incorrectos para el voltaje de la batería, por ejemplo): 
override.battery.voltage.nominal = 12

¡Úselo con precaución! Esto solo cambiará la apariencia de la variable para el mundo exterior, internamente en la UPS se utiliza el valor original.

Todos los demás campos se pasan a la parte específica del hardware del controlador. Consulte esos manuales para ver la lista de lo que está permitido.

debug_min INTEGER

Opcional. Especifique un nivel de depuración mínimo para este demonio controlador, p. ej., para solucionar problemas de implementación, sin afectar directamente al modo de ejecución en primer plano o en segundo plano. Si también está configurado el debug_min global, esta configuración a nivel de controlador la anula. La opción de línea de comandos -D solo puede aumentar este nivel de verbosidad.

LIBUSB_DEBUG INTEGER

Opcional. Para la solución de problemas en tiempo de ejecución de controladores NUT capaces de usar USB, puede especificar la verbosidad de la depuración específica de LibUSB como un valor numérico, como 4 ("Se emiten todos los mensajes").

Para más detalles, incluyendo los valores actualmente admitidos para su versión de la biblioteca, consulte, por ejemplo:

•https://libusb.sourceforge.io/api-1.0/
•https://libusb.sourceforge.io/api-1.0/group__libusb__lib.html

INTEGRACIÓN

upsdrvctl(8) utiliza este archivo para iniciar y detener los controladores.

Los propios controladores también obtienen datos de configuración de este archivo. Cada controlador busca su sección y la utiliza para configurarse a sí mismo.

upsd(8) se entera de qué UPS están instaladas en este sistema leyendo este archivo. Si este sistema se llama "doghouse" y ha definido una UPS en su ups.conf llamada "snoopy", entonces puede supervisarla desde upsc(8) o similar como "snoopy@doghouse".
