umount(2) Manual de llamadas al sistema umount(2)

NOMBRE

umount, umount2 - desmontar sistema de archivos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/mount.h>
int umount(const char *target);
int umount2(const char *target, int flags);

DESCRIPCIÓN

umount() y umount2() eliminan la conexión del sistema de archivos (el más alto) montado en target.

Se requiere privilegios apropiados (Linux: la capacidad CAP_SYS_ADMIN) para desmontar sistemas de archivos.

Linux 2.1.116 agregó la llamada al sistema umount2(), que, al igual que umount(), desmonta un objetivo, pero permite flags adicionales que controlan el comportamiento de la operación:

MNT_FORCE (desde Linux 2.1.116)
Pide al sistema de archivos que aborte las solicitudes pendientes antes de intentar el desmontaje. Esto puede permitir que el desmontaje se complete sin esperar a un servidor inaccesible, pero podría causar pérdida de datos. Si, después de abortar las solicitudes, algunos procesos aún tienen referencias activas al sistema de archivos, el desmontaje aún fallará. A partir de Linux 4.12, MNT_FORCE solo es compatible con los siguientes sistemas de archivos: 9p (desde Linux 2.6.16), ceph (desde Linux 2.6.34), cifs (desde Linux 2.6.12), fuse (desde Linux 2.6.16), lustre (desde Linux 3.11) y NFS (desde Linux 2.1.116).
MNT_DETACH (desde Linux 2.4.11)
Realiza un desmontaje perezoso: hace que el montaje no esté disponible para nuevos accesos, desconecta inmediatamente el sistema de archivos y todos los sistemas de archivos montados debajo de él entre sí y de la tabla de montajes, y realiza realmente el desmontaje cuando el montaje deja de estar ocupado.
MNT_EXPIRE (desde Linux 2.6.8)
Marca el montaje como expirado. Si un montaje no está actualmente en uso, una llamada inicial a umount2() con esta bandera falla con el error EAGAIN, pero marca el montaje como expirado. El montaje permanece expirado mientras no sea accedido por ningún proceso. Una segunda llamada a umount2() especificando MNT_EXPIRE desmonta un montaje expirado. Esta bandera no se puede especificar con MNT_FORCE ni con MNT_DETACH.
UMOUNT_NOFOLLOW (desde Linux 2.6.34)
No desreferencie target si es un enlace simbólico. Esta bandera permite evitar problemas de seguridad en programas set-user-ID-root que permiten a los usuarios sin privilegios desmontar sistemas de archivos.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

Los valores de error dados a continuación resultan de errores independientes del tipo de sistema de archivos. Cada tipo de sistema de archivos puede tener sus propios errores especiales y su propio comportamiento especial. Consulte el código fuente del kernel de Linux para obtener más detalles.

EAGAIN
Una llamada a umount2() especificando MNT_EXPIRE marcó exitosamente un sistema de archivos no ocupado como expirado.
EBUSY
No se pudo desmontar target porque está ocupado.
EFAULT
target apunta fuera del espacio de direcciones del usuario.
EINVAL
target no es un punto de montaje.
EINVAL
target está bloqueado; consulte mount_namespaces(7).
EINVAL
Se llamó a umount2() con MNT_EXPIRE y MNT_DETACH o MNT_FORCE.
EINVAL (desde Linux 2.6.34)
Se llamó a umount2() con un valor de bandera inválido en flags.
ENAMETOOLONG
Un nombre de ruta era más largo que MAXPATHLEN.
ENOENT
Un nombre de ruta estaba vacío o tenía un componente inexistente.
ENOMEM
El kernel no pudo asignar una página libre para copiar nombres de archivo o datos.
EPERM
El llamador no tiene los privilegios requeridos.

ESTÁNDARES

Linux.

HISTORIA

MNT_DETACH y MNT_EXPIRE están disponibles desde glibc 2.11.

La función original umount() se llamaba como umount(device) y devolvía ENOTBLK cuando se llamaba con algo que no fuera un dispositivo de bloque. En Linux 0.98p4, se agregó una llamada umount(dir), para soportar dispositivos anónimos. En Linux 2.3.99-pre7, se eliminó la llamada umount(device), dejando solo umount(dir) (ya que ahora los dispositivos se pueden montar en más de un lugar, por lo que especificar el dispositivo no es suficiente).

NOTAS

umount() y montajes compartidos

Los montajes compartidos hacen que cualquier actividad de montaje en un montaje, incluidas las operaciones umount(), se reenvíe a cada montaje compartido en el grupo de pares y a cada montaje esclavo de ese grupo de pares. Esto significa que umount() de cualquier par en un conjunto de montajes compartidos hará que todos sus pares se desmonten y todos sus esclavos también se desmonten.

Esta propagación de la actividad de desmontaje puede ser particularmente sorprendente en sistemas donde cada montaje se comparte por defecto. En tales sistemas, montar recursivamente el directorio raíz del sistema de archivos en un subdirectorio y luego desmontar ese subdirectorio con MNT_DETACH hará que cada montaje en el espacio de nombres de montaje se desmonte perezosamente.

Para garantizar que umount() no se propague de esta manera, el montaje puede volver a montarse utilizando una llamada a mount(2) con un argumento mount_flags que incluya tanto MS_REC como MS_PRIVATE antes de llamar a umount().

NAME

umount - unmount filesystem

LIBRARY

libc, support library for the Linux kernel calls

SYNOPSIS

#define _GNU_SOURCE

int umount(const char *target );

int umount2(const char *target , int flags );

DESCRIPTION

The umount() and umount2() system calls unmount a previously mounted filesystem. The filesystem is specified by the pathname target. The pathname can be a mount point or a device file. The filesystem associated with target is detached from the system's process tree. A filesystem can be unmounted even if it is currently busy.

The umount2() system call is a variant of umount() that supports additional options specified by the flags argument. The following flags are defined:

MNT_FORCE
Force unmounting. If a process is still using the filesystem, the unmount will succeed, but the filesystem will be remounted automatically. This is useful for handling recursive unmounts.
MNT_DETACH
Detach the filesystem. This is the default behavior if MNT_FORCE is not specified. The filesystem is detached from the process tree, but it may still be in use by some processes. Processes that subsequently try to access the filesystem will receive an error.
MNT_EXPIRE
Lazy unmount. If the filesystem is busy, the unmount will be scheduled to occur when the filesystem is no longer busy. This is useful for unmounting network filesystems that may be temporarily unavailable.

If flags is 0, the unmount will fail if the filesystem is busy.

RETURN VALUE

On success, umount() and umount2() return 0. On error, they return -1, and errno is set to indicate the error.

ERRORS

EBUSY
The filesystem is busy and cannot be unmounted.
EINVAL
Invalid argument.
ENOENT
The specified filesystem does not exist.
ENOTBLK
target is not a block device.
ENOTDIR
A component of target is not a directory.
EPERM
The caller does not have the necessary privileges to unmount the filesystem.

STANDARDS

umount() is part of the POSIX.1 standard. umount2() is a Linux-specific extension.

HISTORY

The umount() system call first appeared in Version 7 Unix. The umount2() system call was added in Linux kernel version 1.3.45.

NOTES

The umount() system call should not be confused with the umount(8) command, which is a user-space utility that calls the umount() system call.

The MNT_EXPIRE flag is only supported for network filesystems. If used with local filesystems, it will be ignored.
