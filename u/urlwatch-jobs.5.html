NOMBRE

urlwatch-jobs - Tipos de trabajos y configuración para urlwatch

SINOPSIS

urlwatch --edit

DESCRIPCIÓN

Los trabajos son el tipo de cosas que urlwatch(1) puede monitorizar.

La lista de trabajos a ejecutar se encuentra en el archivo de configuración urls.yaml, al que se accede con el comando urlwatch --edit, cada uno separado por una línea que contiene únicamente ---. El comando urlwatch --list imprime el nombre de cada trabajo, junto con su número de índice (1, 2, 3, ...) que se asigna automáticamente según su posición en el archivo de configuración.

Aunque es opcional, se recomienda que cada trabajo comience con una entrada name:

name: "Este es un nombre/etiqueta legible por humanos del trabajo"

Los siguientes tipos de trabajos están disponibles:

URL

Este es el tipo de trabajo principal: recupera un documento de un servidor web:

name: "página de inicio de urlwatch"
url: "https://thp.io/2008/urlwatch/"

Claves requeridas:

•
url: La URL del documento a vigilar por cambios.

Claves opcionales específicas del trabajo:

  • cookies: Cookies para enviar con la solicitud (ver Temas Avanzados).
  • method: Método HTTP a usar (por defecto: GET).
  • data: Datos POST/PUT HTTP.
  • ssl_no_verify: No verificar certificados SSL (verdadero/falso).
  • ignore_cached: No usar valores de control de caché (ETag/Last-Modified) (verdadero/falso).
  • http_proxy: Servidor proxy a usar para peticiones HTTP (puede ser http:// o socks5://).
  • https_proxy: Servidor proxy a usar para peticiones HTTPS (puede ser http:// o socks5://).
  • headers: Cabecera HTTP a enviar junto con la solicitud.
  • encoding: Anular la codificación de caracteres del servidor (ver Temas Avanzados).
  • timeout: Anular el tiempo de espera del socket por defecto (ver Temas Avanzados).
  • ignore_connection_errors: Ignorar errores de conexión (temporales) (ver Temas Avanzados).
  • ignore_http_error_codes: Lista de errores HTTP a ignorar (ver Temas Avanzados).
  • ignore_timeout_errors: No reportar errores cuando se alcanza el tiempo de espera.
  • ignore_too_many_redirects: Ignorar bucles de redireccionamiento (ver Temas Avanzados).
  • ignore_incomplete_reads: Ignorar respuestas HTTP incompletas (ver Temas Avanzados).

(Nota: url implica kind: url)

BROWSER

Este tipo de trabajo es una variante que consume muchos recursos de "URL" para manejar páginas web que requieren JavaScript para renderizar el contenido que se está monitorizando.

El paquete opcional playwright debe estar instalado para poder ejecutar trabajos de Navegador (ver Dependencias). También necesitará instalar los navegadores usando playwright install (ver Instalación de Playwright en https://playwright.dev/python/docs/intro para más detalles).

name: "Una página con JavaScript"
navigate: "https://example.org/"

Claves requeridas:

•
navigate: URL a la que navegar con el navegador.

Claves opcionales específicas del trabajo:

  • wait_until: Ya sea load, domcontentloaded, networkidle o commit (ver Temas Avanzados).
  • wait_for: Un selector CSS o XPath basado en la especificación de : https://playwright.dev/python/docs/locators#locate-by-css-or-xpath. El trabajo esperará el tiempo de espera predeterminado de 30 segundos.
  • useragent: Cabecera User-Agent utilizada para las solicitudes (de lo contrario, se usa el valor predeterminado del navegador).
  • browser: Ya sea chromium, chrome, chrome-beta, msedge, msedge-beta, msedge-dev, firefox, webkit (debe instalarse con playwright install).

Debido a que este trabajo utiliza Playwright https://playwright.dev/python/ para renderizar la página en una instancia de navegador sin cabeza, utiliza masivamente más recursos que un trabajo de "URL". Úselo solo en páginas donde url no devuelva los resultados correctos. En muchos casos, en lugar de usar un trabajo de "Navegador", puede usar la salida de una API llamada por la página mientras se carga, que contiene la información que está buscando al usar el tipo de trabajo "URL", mucho más rápido.

(Nota: navigate implica kind: browser)

SHELL

Este tipo de trabajo permite monitorizar la salida de comandos shell arbitrarios, lo cual es útil, por ejemplo, para monitorizar una carpeta de cargador FTP, la salida de scripts que consultan dispositivos externos (GPIO de RPi), etc...

name: "¿Qué hay en mi Directorio de Inicio?"
command: "ls -al ~"

Claves requeridas:

•
command: El comando shell a ejecutar.

Claves opcionales específicas del trabajo:

•
stderr: Cambiar cómo se trata la salida estándar de error, ver más abajo.

(Nota: command implica kind: shell)

Configuración del comportamiento de stderr para trabajos shell

Por defecto, urlwatch captura stderr para la notificación de errores (código de salida distinto de cero), pero ignora la salida cuando el trabajo shell sale con código de salida 0.

Este comportamiento se puede personalizar usando la clave stderr:

  • ignore: Capturar stderr, notificar sobre código de salida distinto de cero, ignorar en caso contrario (predeterminado).
  • urlwatch: La salida stderr del trabajo shell se envía a stderr del proceso urlwatch; cualquier mensaje de error en stderr no será visible en el mensaje de error del reporter (comportamiento predeterminado heredado de urlwatch 2.24 y anteriores).
  • fail: Tratar el trabajo como fallido si hay *cualquier* salida en stderr, incluso con código de salida 0.
  • stdout: Fusionar la salida de stderr en stdout, lo que significa que la salida de stderr también se considera para la detección de cambios/diferencias de urlwatch (esto es similar a 2>&1 en un shell).

Por ejemplo, esta definición de trabajo hará que el trabajo parezca fallido, aunque el script salga con el código de salida 0:

command: |
  echo "Salida estándar normal."
  echo "Algo va a stderr, lo que hace que este trabajo falle." 1>&2
  exit 0
stderr: fail

Por otro lado, si desea comparar tanto stdout como stderr del trabajo, use esto:

command: |
  echo "Una línea importante en stdout."
  echo "Otra línea importante en stderr." 1>&2
stderr: stdout

CLAVES OPCIONALES PARA TODOS LOS TIPOS DE TRABAJOS

  • name: Nombre/etiqueta legible por humanos del trabajo.
  • tags: Matriz de etiquetas, o una sola etiqueta como cadena.
  • filter: Filtros (si los hay) a aplicar a la salida (se pueden probar con --test-filter).
  • max_tries: Después de este número de ejecuciones fallidas secuenciales, el error se notificará en lugar de ignorarse.
  • diff_tool: Comando para una herramienta personalizada para generar texto de diff.
  • diff_filter: Filtros (si los hay) a aplicar al resultado de diff (se pueden probar con --test-diff-filter).
  • treat_new_as_changed: Tratará los trabajos que no tengan datos históricos como CAMBIADOS en lugar de NUEVOS (y creará un diff para el nuevo trabajo).
