NOMBRE

unbound-control - Utilidad de control remoto del servidor Unbound 1.24.2.

SINOPSIS

unbound-control [-hq] [-c archivo_config] [-s servidor] comando

DESCRIPCIÓN

unbound-control realiza la administración remota del servidor DNS unbound(8). Lee el archivo de configuración, se contacta con el servidor Unbound a través de TLS, envía el comando y muestra el resultado.

Las opciones disponibles son:

-h
Muestra la versión y la ayuda de las opciones de la línea de comandos.
-c <archivo_config>
El archivo de configuración a leer con los ajustes. Si no se proporciona, se utiliza el archivo de configuración predeterminado /etc/unbound/unbound.conf.
-s <servidor[@puerto]>
Dirección IPv4 o IPv6 del servidor al que contactar. Si no se proporciona, la dirección se lee del archivo de configuración.
-q
Silencioso, si se proporciona la opción, no imprime nada si funciona correctamente.

COMANDOS

Hay varios comandos que el servidor entiende.

start
Inicia el servidor. Simplemente ejecuta unbound(8). El ejecutable unbound se busca en el PATH establecido en el entorno. Se inicia con el archivo de configuración especificado con -c o el archivo de configuración predeterminado.
stop
Detiene el servidor. El demonio del servidor se cierra.
reload
Recarga el servidor. Esto vacía la caché y lee el archivo de configuración nuevamente.
reload_keep_cache
Recarga el servidor pero intenta mantener la caché de RRset y mensajes si la configuración (re)lo permite. Eso significa que los tamaños de la caché y el número de hilos no deben cambiar entre recargas.
fast_reload [+dpv]
Recarga el servidor, pero minimiza el tiempo de inactividad, para que las consultas de los usuarios sigan recibiendo servicio. Esto requiere que el código esté compilado con hilos. La configuración se carga en un hilo, se prepara, luego pausa brevemente el servidor existente y actualiza las opciones de configuración. La intención es que la pausa no afecte el servicio de las consultas de los usuarios. La caché se mantiene. Las consultas de usuario en curso también se mantienen y continúan, pero con las nuevas opciones de configuración.

NOTA:

Este comando es experimental en este momento.

La cantidad de memoria temporal necesaria durante una fast_reload es el doble de la necesaria para la configuración. Esto se debe a que Unbound necesita temporalmente almacenar tanto los valores de configuración actuales como los nuevos mientras intenta la fast_reload. Las zonas cargadas desde disco (zonas de autoridad y zonas RPZ) se incluyen en estas necesidades de memoria.

Las opciones que se pueden cambiar son para forwards, stubs, views, zonas de autoridad, zonas RPZ y zonas locales.

También access-control y opciones similares, interface-action y opciones similares, y tcp-connection-limit. Puede recargar algunos cambios de define-tag, más sobre esto a continuación. Otras opciones incluyen insecure-lan-zones, domain-insecure, trust-anchor-file, trust-anchor, trusted-keys-file, auto-trust-anchor-file, edns-client-string, ipset, log-identity, infra-cache-numhosts, msg-cache-size, rrset-cache-size, key-cache-size, ratelimit-size, neg-cache-size, num-queries-per-thread, jostle-timeout, use-caps-for-id, unwanted-reply-threshold, tls-use-sni, outgoing-tcp-mss, ip-dscp, max-reuse-tcp-queries, tcp-reuse-timeout, tcp-auth-query-timeout, delay-close. iter-scrub-promiscuous.

No funciona con cambios en interface y outgoing-interface, tampoco con remote control, outgoing-port-permit, outgoing-port-avoid, msg-buffer-size, ninguna opción *-slabs y cambios en statistics-interval.

Para dnstap, se pueden cambiar estas opciones: dnstap-log-resolver-query-messages, dnstap-log-resolver-response-messages, dnstap-log-client-query-messages, dnstap-log-client-response-messages, dnstap-log-forwarder-query-messages y dnstap-log-forwarder-response-messages.

No funciona con estas opciones: dnstap-enable, dnstap-bidirectional, dnstap-socket-path, dnstap-ip, dnstap-tls, dnstap-tls-server-name, dnstap-tls-cert-bundle, dnstap-tls-client-key-file y dnstap-tls-client-cert-file.

Las opciones dnstap-send-identity, dnstap-send-version, dnstap-identity y dnstap-version se pueden cargar cuando no se usa +p.

La opción +v hace que la salida sea detallada, lo que incluye el tiempo que tardó en realizar la recarga. Con +vv es más detallada, lo que incluye la cantidad de memoria que se asignó temporalmente para realizar la recarga; esta cantidad de memoria puede ser grande si la configuración tiene un contenido extenso. En la salida de tiempos, el tiempo de 'recarga' es el tiempo durante el cual el servidor estuvo pausado.

La opción +p hace que la recarga no pause los hilos, estos siguen ejecutándose. Se adquieren bloqueos, pero los elementos se actualizan en secuencia, por lo que es posible que los hilos vean un estado inconsistente con algunas opciones de la configuración antigua y otras de la nueva, como parámetros de TTL de caché de la configuración antigua y forwards de la nueva. Los stubs y forwards se actualizan al mismo tiempo, para que se vean de forma coherente, ya sea con valores antiguos o nuevos juntos. La opción hace que el tiempo de recarga sea, por ejemplo, 3 microsegundos en lugar de 0.3 milisegundos durante los cuales los hilos de trabajo se interrumpen. Por lo tanto, la interrupción es mucho más corta, a expensas de cierta inconsistencia. Después de la recarga en sí, cada hilo de trabajo se contacta brevemente para hacer que libere recursos, esto hace que el tiempo de eliminación sea un poco más largo y consume tiempo del hilo de trabajo que atiende el control remoto.

Con la opción nopause (+p), la recarga no funciona para recargar algunas opciones, que la recarga rápida sí funciona sin la opción nopause: val-bogus-ttl, val-override-date, val-sig-skew-min, val-sig-skew-max, val-max-restart, val-nsec3-keysize-iterations, target-fetch-policy, outbound-msg-retry, max-sent-count, max-query-restarts, do-not-query-address, do-not-query-localhost, private-address, private-domain, caps-exempt, nat64-prefix, do-nat64, infra-host-ttl, infra-keep-probing, ratelimit, ip-ratelimit, ip-ratelimit-cookie, wait-limit-netblock, wait-limit-cookie-netblock, ratelimit-below-domain, ratelimit-for-domain.

La opción +d hace que la recarga descarte las consultas en las que los hilos de trabajo están procesando. Esto es como flush_requestlist. Sin ella, las consultas se mantienen para que los usuarios sigan recibiendo respuestas para esas consultas que se están procesando actualmente. El descarte hace que las consultas durante la vida útil del procesamiento de consultas vean solo opciones de configuración antiguas o solo nuevas.

Cuando hay cambios en las etiquetas de configuración, de la opción define-tag, entonces la opción +d se activa implícitamente con un mensaje de advertencia, y las consultas se descartan. Esto es para detener las referencias a la información de la etiqueta antigua, por las consultas antiguas. Si el número de etiquetas aumenta en la configuración recién cargada, agregando etiquetas al final, entonces la opción implícita +d no es necesaria.

Para la IP de respuesta, que son acciones asociadas con direcciones IP, y quizás intersectadas con información de etiqueta y acción de control de acceso, esos ajustes se almacenan con una consulta cuando llega según su dirección IP de origen. La

EJEMPLOS

Para iniciar el servidor Unbound:

unbound-control start

Para detener el servidor Unbound:

unbound-control stop

Para recargar el servidor Unbound:

unbound-control reload

Para detener y luego iniciar el servidor Unbound (utilizando el archivo de configuración especificado):

unbound-control stop
unbound-control -c /etc/unbound/unbound.conf start

Para reiniciar el servidor Unbound, mostrando los detalles de la recarga:

unbound-control reload -v

Para reiniciar el servidor Unbound con el mínimo tiempo de inactividad (requiere compilación con soporte para hilos y solo con algunos cambios de configuración):

unbound-control fast_reload

Para reiniciar el servidor Unbound con el mínimo tiempo de inactividad, descartando las consultas en progreso y mostrando la información detallada sobre la recarga:

unbound-control fast_reload -vd

ESTADO DE SALIDA

unbound-control devuelve 0 si el comando tuvo éxito y un valor distinto de cero si hubo un error.

ARCHIVOS

/etc/unbound/unbound.conf

El archivo de configuración predeterminado para el servidor Unbound.

verbosity número
Cambia el valor de verbosidad para el registro. Los mismos valores que la palabra clave verbosity: en unbound.conf(5). Esta nueva configuración dura hasta que al servidor se le emite una recarga (tomada nuevamente del archivo de configuración), o el siguiente comando de control de verbosidad.
log_reopen
Reabre el archivo de registro, lo cierra y lo abre. Útil para la rotación de registros para que el demonio libere el archivo al que está registrando. Si está utilizando syslog, intentará cerrar y abrir syslog (lo que puede no funcionar si está en chroot).
stats
Imprime estadísticas. Restablece los contadores internos a cero, esto puede ser controlado usando la instrucción de configuración statistics-cumulative:. Las estadísticas se imprimen con un [nombre]: [valor] por línea.
stats_noreset
Echa un vistazo a las estadísticas. Las imprime como lo hace el comando stats, pero no restablece los contadores internos a cero.
status
Muestra el estado del servidor. Código de salida 3 si no se está ejecutando (la conexión al puerto es rechazada), 1 en caso de error, 0 si se está ejecutando.
local_zone nombre tipo
Agrega una nueva zona local con nombre y tipo. Similar a la instrucción de configuración local-zone. Si la zona ya existe, el tipo se cambia al argumento proporcionado.
local_zone_remove nombre
Elimina la zona local con el nombre dado. Elimina todos los datos locales dentro de ella. Si la zona no existe, el comando se completa correctamente.
local_data RR datos...
Agrega nuevos datos locales, el registro de recursos dado. Similar a la palabra clave local-data:, excepto cuando no existe una zona que lo cubra. En ese caso, este comando de control remoto crea una zona transparente con el mismo nombre que este registro.
local_data_remove nombre
Elimina todos los datos RR del nombre local. Si el nombre ya no tiene elementos, no sucede nada. A menudo resulta en NXDOMAIN para el nombre (en una zona estática), pero si el nombre se ha convertido en un no terminal vacío (todavía hay datos en los nombres de dominio debajo del nombre eliminado), las respuestas NOERROR nodata son el resultado para ese nombre.
local_zones
Agrega zonas locales leídas desde la entrada estándar de unbound-control. La entrada se lee por línea, con nombre espacio tipo en una línea. Para adiciones masivas.
local_zones_remove
Elimina zonas locales leídas desde la entrada estándar de unbound-control. La entrada es un nombre por línea. Para eliminaciones masivas.
local_datas
Agrega RRs de datos locales leídas desde la entrada estándar de unbound-control. La entrada es un RR por línea. Para adiciones masivas.
local_datas_remove
Elimina RRs de datos locales leídas desde la entrada estándar de unbound-control. La entrada es un nombre por línea. Para eliminaciones masivas.
dump_cache
El contenido de la caché se imprime en formato de texto a stdout. Puede redirigirlo a un archivo para almacenar la caché en un archivo. No compatible en Unbounds remotos en operación multi-proceso.
load_cache
El contenido de la caché se carga desde la entrada estándar. Utiliza el mismo formato que utiliza dump_cache. Cargar la caché con datos antiguos o incorrectos puede dar lugar a datos antiguos o incorrectos devueltos a los clientes. Cargar datos en la caché de esta manera es compatible para ayudar con la depuración. No compatible en Unbounds remotos en operación multi-proceso.
cache_lookup [+t] nombres
Imprime en stdout los RRsets y mensajes que están en la caché. Para cada nombre listado, se imprime el contenido en o debajo del nombre. Se pueden proporcionar varios nombres separados por espacios, cada uno se imprime. Cuando el subnetcache está habilitado, también se imprimen las entradas coincidentes del subnet cache.

La opción +t permite nombres de TLD y raíz. Con ella, se pueden usar nombres como 'com' y '.', pero requiere mucho esfuerzo para buscarlos en la caché.

lookup nombre
Imprime en stdout los servidores de nombres que se utilizarían para buscar el nombre especificado.
flush [+c] nombre
Elimina el nombre de la caché. Elimina los tipos A, AAAA, NS, SOA, CNAME, DNAME, MX, PTR, SRV, NAPTR, SVCB e HTTPS. Porque eso es rápido de hacer. Otros tipos de registros se pueden eliminar usando flush_type o flush_zone.

La opción +c elimina también los elementos de la caché cachedb. Si cachedb está en uso.

flush_type [+c] nombre tipo
Elimina el nombre y el tipo de información de la caché.

La opción +c elimina también los elementos de la caché cachedb. Si cachedb está en uso.

flush_zone [+c] nombre
Elimina toda la información en o debajo del nombre de la caché. Los rrsets y las entradas de claves se eliminan para que se realicen nuevas búsquedas. Esto necesita recorrer e inspeccionar toda la caché y es una operación lenta. Las entradas se establecen como expiradas en la implementación de este comando (por lo tanto, con serve-expired habilitado, servirá esa información pero programará una re-búsqueda de nueva información).

La opción +c elimina también los elementos de la caché cachedb. Si cachedb está en uso.

flush_bogus [+c]
Elimina todos los datos falsos de la caché.

La opción +c elimina también los elementos de la caché cachedb. Si cachedb está en uso.

flush_negative [+c]
Elimina todos los datos negativos de la caché. Estas son respuestas nxdomain, respuestas nodata y respuestas servfail. También elimina entradas de claves incorrectas (que podrían deberse a búsquedas fallidas) de la caché de claves dnssec, y fallos de búsqueda de último recurso del iterador de la caché de rrsets.

La opción +c elimina también los elementos de la caché cachedb. Si cachedb está en uso.

flush_stats
Restablece las estadísticas a cero.
flush_requestlist
Descarta las consultas en las que se está trabajando. Detiene el trabajo en las consultas en las que el servidor está trabajando actualmente. La caché no se ve afectada. No se enviará ninguna respuesta para esas consultas, lo que probablemente hará que esos usuarios vuelvan a solicitar más tarde. Útil para hacer que el servidor vuelva a trabajar en consultas con nueva configuración, como un nivel de verbosidad más alto.
dump_requestlist
Muestra en qué se está trabajando. Imprime todas las consultas en las que el servidor está trabajando actualmente. Imprime el tiempo que los usuarios han estado esperando. Para solicitudes internas, no se imprime tiempo. Y luego imprime el estado del módulo. Esto imprime las consultas del primer hilo, y no las consultas que se están atendiendo desde otros hilos.
flush_infra all|IP
Si es all, toda la caché de infraestructura se vacía. Si es una dirección IP específica, se elimina la entrada de esa dirección de la caché. Contiene datos EDNS, ping y latencia.
dump_infra
Muestra el contenido de la caché de infraestructura.
set_option opt: val
Establece la opción al valor dado sin recarga. Por lo tanto, la caché no se vacía. La opción debe terminar con un ":" y debe haber un espacio entre la opción y el valor. Algunos valores pueden no tener efecto si se establecen de esta manera, los nuevos valores no se escriben en el archivo de configuración, no todas las opciones son compatibles. Esto es diferente de la llamada set_option en libunbound, donde todos los valores funcionan porque Unbound no se ha inicializado.

Los valores que funcionan son: statistics-interval, statistics-cumulative, do-not-query-localhost, harden-short-bufsize, harden-large-queries, harden-glue, harden-dnssec-stripped, harden-below-nxdomain, harden-referral-path, prefetch, prefetch-key, log-queries, hide-identity, hide-version, identity, version, val-log-level, val-log-squelch, ignore-cd-flag, add-holddown, del-holddown, keep-missing, tcp-upstream, ssl-upstream, max-udp-size, ratelimit, ip-ratelimit, cache-max-ttl, cache-m

in-ttl, cache-max-negative-ttl.

get_option opt
Obtiene el valor de la opción. Proporciona el nombre de la opción sin el sufijo ':'. Se imprime el valor. Si el valor es "", no se imprime nada y la conexión se cierra. En caso de error se imprime 'error ...' (genera un error de sintaxis en opciones desconocidas). Para algunas opciones se imprime una lista de valores, uno por línea. Las opciones se muestran desde el archivo de configuración tal como fueron modificadas con set_option. Para algunas opciones puede haberse tomado una derogación que no aparece con este comando, ni los resultados de comandos como el de verbosidad y reenvío. No todas las opciones funcionan, véase list_stubs, list_forwards, list_local_zones y list_local_data para esas opciones.
list_stubs
Lista las zonas stub en uso. Se imprimen una por una en la salida. Esto incluye las pistas raíz en uso.
list_forwards
Lista las zonas de reenvío en uso. Se imprimen zona por zona en la salida.
list_insecure
Lista las zonas con domain-insecure.
list_local_zones
Lista las zonas locales en uso. Se imprimen una por línea con el tipo de zona.
list_local_data
Lista los RR de datos locales en uso. Se imprimen los registros de recursos.
insecure_add zone
Añade un dominio-inseguro para la zona dada, similar a la declaración en unbound.conf. Se añade a Unbound en ejecución sin afectar el contenido de la caché (que todavía puede ser erróneo, usa flush_zone para eliminarlo), no afecta al archivo de configuración.
insecure_remove zone
Elimina el dominio-inseguro para la zona dada.
forward_add [+it] zone addr ...
Añade una nueva zona de reenvío a Unbound en ejecución. Con la opción +i también añade un dominio-inseguro para la zona (para que pueda resolver de forma insegura si tienes un ancla de confianza raíz DNSSEC configurada para otros nombres). La dirección puede ser IP4, IP6 o nombres de servidor de nombres, como la configuración de forward-zone en unbound.conf. La opción +t la configura para usar TLS aguas arriba, como forward-tls-upstream: yes.
forward_remove [+i] zone
Elimina una zona de reenvío de Unbound en ejecución. El +i también elimina un dominio-inseguro para la zona.
stub_add [+ipt] zone addr ...
Añade una nueva zona stub a Unbound en ejecución. Con la opción +i también añade un dominio-inseguro para la zona. Con +p la zona stub se configura como prime, sin ella se configura como notprime. La dirección puede ser IP4, IP6 o nombres de servidor de nombres, como la configuración de stub-zone: en unbound.conf. La opción +t la configura para usar TLS aguas arriba, como stub-tls-upstream: yes.
stub_remove [+i] zone
Elimina una zona stub de Unbound en ejecución. El +i también elimina un dominio-inseguro para la zona.
forward [off | addr ... ]
Configura el modo de reenvío. Configura si el servidor debe preguntar a otros servidores de nombres aguas arriba, si debe ir directamente a los servidores de nombres raíz de Internet o mostrar la configuración actual. Puedes pasar los servidores de nombres después de una actualización de DHCP.

Sin argumentos, se imprime la lista actual de direcciones utilizadas para reenviar todas las consultas. Al inicio, esto proviene de la configuración de la zona de reenvío ".". Después, muestra el estado. Imprime off cuando no se usa ningún reenvío.

Si se pasa off, el reenvío se deshabilita y se utilizan los servidores de nombres raíz. Esto se puede usar para evitar servidores de nombres erróneos o que no soportan DNSSEC devueltos por DHCP. Pero puede no funcionar en hoteles o puntos de acceso.

Si se dan una o más direcciones IPv4 o IPv6, estas se utilizarán para reenviar las consultas. Las direcciones deben separarse con espacios. Con '@puerto' se puede establecer explícitamente el número de puerto (el puerto por defecto es 53 (DNS)).

Por defecto, se utiliza la información del reenviador del archivo de configuración para la raíz ".". El archivo de configuración no se modifica, por lo que después de una recarga estos cambios desaparecerán. Otras zonas de reenvío del archivo de configuración no se ven afectadas por este comando.

ratelimit_list [+a]
Lista los dominios con límite de velocidad. Se imprimen uno por línea con el QPS estimado actual y el límite de QPS de la configuración. Con +a imprime todos los dominios, no solo los que tienen límite de velocidad, con sus QPS estimados. Los dominios con límite de velocidad devuelven un error para consultas no cacheadas (nuevas), pero las consultas cacheadas funcionan normalmente.
ip_ratelimit_list [+a]
Lista las direcciones IP con límite de velocidad. Se imprimen una por línea con el QPS estimado actual y el límite de QPS de la configuración. Con +a imprime todas las IPs, no solo las que tienen límite de velocidad, con sus QPS estimados. Las IPs con límite de velocidad se descartan antes de comprobar la caché.
list_auth_zones
Lista las zonas de autoridad configuradas. Se imprimen una por línea con un estado, indicando si la zona ha expirado y el número de serie actual. Se incluyen las zonas RPZ configuradas.
auth_zone_reload zone
Recarga la zona de autoridad (o zona RPZ) desde el archivo de zona. El archivo de zona se lee sobrescribiendo el contenido actual de la zona en memoria. Esto cambia el contenido de la zona de autoridad en sí, no el contenido de la caché. Dicho contenido de caché existe si configuras Unbound para validar con for-upstream: yes y se puede limpiar con flush_zone zone.
auth_zone_transfer zone
Transfiere la zona de autoridad (o zona RPZ) desde el maestro. Se inicia la secuencia de sondeo de la zona de autoridad, donde se sondea a los maestros para ver si tienen una zona actualizada (con la comprobación de serie SOA). Y luego se transfiere la zona para una versión más nueva.
rpz_enable zone
Habilita la zona RPZ si previamente había sido deshabilitada.
rpz_disable zone
Deshabilita la zona RPZ.
view_list_local_zones view
list_local_zones para la vista dada.
view_local_zone view name type
local_zone para la vista dada.
view_local_zone_remove view name
local_zone_remove para la vista dada.
view_list_local_data view
list_local_data para la vista dada.
view_local_data view RR data...
local_data para la vista dada.
view_local_data_remove view name
local_data_remove para la vista dada.
view_local_datas_remove view
Elimina una lista de local_data para la vista dada desde stdin. Como local_datas_remove.
view_local_datas view
Añade una lista de local_data para la vista dada desde stdin. Como local_datas.
add_cookie_secret secret
Añade o reemplaza un secreto de cookie de forma persistente. secret debe ser una cadena hexadecimal de 128 bits.

Los secretos de cookie pueden ser activos o de preparación. Los secretos de cookie activos se utilizan para crear Cookies DNS, pero la verificación de una Cookie DNS tiene éxito con cualquiera de los secretos de cookie activos o de preparación. El estado de los secretos de cookie actuales se puede imprimir con el comando print_cookie_secrets.

Cuando aún no hay secretos de cookie configurados, el secret se añade como activo. Si ya existe un secreto de cookie activo, el secret se añade como de preparación o reemplazando un secreto de preparación existente.

Para "rotar" un c

okie secreto utilizado en un conjunto anycast. El nuevo secreto debe añadirse como secreto de staging a todos los nodos del conjunto anycast. Cuando todos los nodos puedan verificar las Cookies DNS con el nuevo secreto, el nuevo secreto podrá activarse con el comando activate_cookie_secret. Después de que todos los nodos tengan el nuevo secreto activo durante al menos una hora, el secreto anterior podrá eliminarse con el comando drop_cookie_secret.

La persistencia se logra escribiendo en un archivo que se configura con la opción cookie-secret-file en la sección server del archivo de configuración. Esto está deshabilitado por defecto, "".

drop_cookie_secret
Elimina el secreto de cookie de staging.
activate_cookie_secret
Convierte el secreto de cookie de staging actual en activo, y el secreto de cookie activo actual en staging.
print_cookie_secrets
Muestra los secretos de cookie configurados actualmente con su estado.

El programa unbound-control sale con el código de estado 1 en caso de error, 0 en caso de éxito.

CONFIGURACIÓN

La configuración requiere un certificado autofirmado y claves privadas tanto para el servidor como para el cliente. El script unbound-control-setup los genera en el directorio de ejecución predeterminado, o con -d en otro directorio. Si cambia los permisos de control de acceso en los archivos de clave, puede decidir quién puede usar unbound-control; por defecto, el propietario y el grupo, pero no todos los usuarios. Ejecute el script bajo el mismo nombre de usuario con el que se ha configurado en unbound.conf o como root, para que el demonio tenga permiso para leer los archivos, por ejemplo, con:

sudo -u unbound unbound-control-setup

Si no ha configurado un nombre de usuario en unbound.conf, las claves necesitan permiso de lectura para las credenciales de usuario bajo las cuales se inicia el demonio. El script conserva las claves privadas presentes en el directorio. Después de ejecutar el script como root, active control-enable en unbound.conf.

NOMBRE

unbound-control-setup - configura el control de Unbound y los permisos del socket

SINOPSIS

unbound-control-setup [-h] [-d dir] [-u user] [-p group]

DESCRIPCIÓN

El script unbound-control-setup configura el control remoto de Unbound. Crea los archivos de configuración y certificados necesarios para que unbound-control y unbound-control-setup funcionen, y establece los permisos correctos para que el usuario root pueda acceder a ellos. El script debe ejecutarse como root.

El directorio dir se puede especificar con la opción -d, el valor predeterminado es /etc/unbound. El script también puede cambiar la propiedad de los archivos creados al usuario y grupo especificados con las opciones -u y -p.

OPCIONES

-h
Muestra un resumen de las opciones.
-d dir
Establece el directorio donde se guardarán los archivos de configuración y certificados. El valor predeterminado es /etc/unbound.
-u user
Establece el usuario propietario de los archivos de configuración y certificados. El valor predeterminado es root.
-p group
Establece el grupo propietario de los archivos de configuración y certificados. El valor predeterminado es root.

CÓDIGO DE SALIDA

El script unbound-control-setup devuelve 0 si la configuración se realizó correctamente, y un valor distinto de cero si se produjo un error.

CONFIGURACIÓN

Para configurar el control remoto de Unbound, ejecute el script unbound-control-setup como root:

# unbound-control-setup

Esto creará los archivos necesarios en el directorio /etc/unbound. Si desea especificar un directorio diferente, puede usar la opción -d:

# unbound-control-setup -d /var/unbound

También puede especificar el usuario y grupo propietarios de los archivos:

# unbound-control-setup -u unbound -p unbound
