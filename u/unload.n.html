unload(n) Comandos integrados de Tcl unload(n)

NOMBRE

unload - Descargar código máquina

SINOPSIS

unload ?switches? nombreArchivo
unload ?switches? nombreArchivo prefijo
unload ?switches? nombreArchivo prefijo intèrprete

DESCRIPCIÓN

Este comando intenta descargar bibliotecas compartidas cargadas previamente con load del espacio de direcciones de la aplicación. nombreArchivo es el nombre del archivo que contiene el archivo de la biblioteca a descargar; debe ser el mismo que el nombre de archivo proporcionado a load para cargar la biblioteca. El argumento prefijo es el prefijo (tal como lo determina o lo pasa a load) y se utiliza para calcular el nombre del procedimiento de descarga; si no se proporciona, se calcula a partir de nombreArchivo de la misma manera que load. El argumento intèrprete es el nombre de ruta del intérprete desde el cual descargar el paquete (consulte la entrada del manual interp para obtener detalles); si se omite intèrprete, se asume por defecto el intérprete en el que se invocó el comando unload.

Si los argumentos iniciales de unload comienzan con - entonces se tratan como opciones. Las siguientes opciones son compatibles actualmente:

-nocomplain
Suprime todos los mensajes de error. Si se proporciona esta opción, unload nunca informará un error.
-keeplibrary
Esta opción evitará que unload emita la llamada al sistema operativo que descargará la biblioteca del proceso.
--
Marca el final de las opciones. El argumento que sigue a este se tratará como un nombreArchivo incluso si comienza con un -.

OPERACIÓN DE DESCARGA

Cuando un archivo que contiene una biblioteca compartida se carga a través del comando load, Tcl asocia dos contadores de referencias al archivo de la biblioteca. El primer contador muestra cuántas veces se ha cargado la biblioteca en intérpretes normales (de confianza), mientras que el segundo describe cuántas veces se ha cargado la biblioteca en intérpretes seguros. Dado que un archivo que contiene una biblioteca compartida solo puede cargarse una vez por Tcl (con la primera llamada load al archivo), estos contadores rastrean cuántos intérpretes utilizan la biblioteca. Cada llamada posterior a load después de la primera simplemente incrementa el contador de referencias adecuado.

unload funciona en la dirección opuesta. Como primer paso, unload verificará si la biblioteca es descargable: una biblioteca descargable exporta un procedimiento de descarga especial. El nombre del procedimiento de descarga se determina mediante prefijo y si el intérprete de destino es seguro o no. Para intérpretes normales, el nombre del procedimiento de inicialización tendrá la forma pfx_Unload, donde pfx es el mismo que prefijo excepto que la primera letra se convierte a mayúscula y todas las demás letras se convierten a minúscula. Por ejemplo, si prefijo es foo o FOo, el nombre del procedimiento de inicialización será Foo_Unload. Si el intérprete de destino es un intérprete seguro, entonces el nombre del procedimiento de inicialización será pkg_SafeUnload en lugar de pkg_Unload.

Si unload determina que una biblioteca no es descargable (o la funcionalidad de descarga ha sido deshabilitada durante la compilación), se devolverá un error. Si la biblioteca es descargable, entonces unload llamará al procedimiento de descarga. Si el procedimiento de descarga devuelve TCL_OK, unload continuará y disminuirá el contador de referencias adecuado (dependiendo del tipo de intérprete de destino). Cuando ambos contadores de referencias lleguen a 0, la biblioteca se desvinculará del proceso.

PROTO-TIPO DEL GANCHO DE DESCARGA

El procedimiento de descarga debe coincidir con el siguiente prototipo:

typedef int Tcl_PackageUnloadProc(
        Tcl_Interp *interp,
        int flags);

El argumento interp identifica el intérprete desde el cual se descargará la biblioteca. El procedimiento de descarga debe devolver TCL_OK o TCL_ERROR para indicar si se completó con éxito o no; en caso de error, debe establecer el resultado del intérprete para que apunte a un mensaje de error. En este caso, el resultado del comando unload será el resultado devuelto por el procedimiento de descarga.

El argumento flags puede ser TCL_UNLOAD_DETACH_FROM_INTERPRETER o TCL_UNLOAD_DETACH_FROM_PROCESS. En caso de que la biblioteca permanezca conectada al proceso después de que el procedimiento de descarga regrese (es decir, porque la biblioteca es utilizada por otros intérpretes), se definirá TCL_UNLOAD_DETACH_FROM_INTERPRETER. Sin embargo, si la biblioteca es utilizada solo por el intérprete de destino y la biblioteca se desvinculará de la aplicación tan pronto como el procedimiento de descarga regrese, el argumento flags se establecerá en TCL_UNLOAD_DETACH_FROM_PROCESS.

NOTAS

El comando unload no puede descargar bibliotecas que estén enlazadas estáticamente con la aplicación. Si nombreArchivo es una cadena vacía, entonces se debe especificar el argumento prefijo.

Si se omite prefijo o se especifica como una cadena vacía, Tcl intenta adivinar el prefijo. Esto puede hacerse de manera diferente en distintas plataformas. La suposición predeterminada, que se utiliza en la mayoría de las plataformas UNIX, es tomar el último elemento de nombreArchivo, quitar los primeros tres caracteres si son lib, y utilizar cualquier carácter alfabético y guion bajo subsiguientes, convertidos a mayúsculas como prefijo. Por ejemplo, el comando unload libxyz4.2.so utiliza el prefijo Xyz y el comando unload bin/last.so {} utiliza el prefijo Last.

PROBLEMAS DE PORTABILIDAD

Unix     
No todos los sistemas operativos unix admiten la descarga de bibliotecas. En un sistema operativo de este tipo, unload devuelve un error (a menos que se haya especificado -nocomplain).

ERRORES

Si el mismo archivo se carga con diferentes nombreArchivo, se cargará en el espacio de direcciones del proceso varias veces. El comportamiento de esto varía de un sistema a otro (algunos sistemas pueden detectar las cargas redundantes, otros puede que no). En caso de que una biblioteca haya sido desvinculada silenciosamente por el sistema operativo (y como resultado Tcl piense que la biblioteca todavía está cargada), puede ser peligroso usar unload en dicha biblioteca (ya que la biblioteca se desvinculará completamente de la aplicación mientras que algunos intérpretes continuarán usándola).

EJEMPLO

Si un módulo descargable en el archivo foobar.dll se hubiera cargado usando el comando load de esta manera (en Windows):

load c:/some/dir/foobar.dll

entonces se descargaría de la siguiente manera:

unload c:/some/dir/foobar.dll

Esto permite que un módulo de código C se instale temporalmente en un programa Tcl de larga ejecución y luego se elimine de nuevo (ya sea porque ya no se necesita o porque se está actualizando con una nueva versión) sin tener que apagar el proceso Tcl general.

NAME:
unload — Cargar o descargar bibliotecas compartidas
SYNOPSIS:
unload channelName
DESCRIPTION:
The unload command unloads the shared library associated with the channel channelName. The channel should have been opened previously using the load command. If the unload is successful, the command returns an empty string. Otherwise, it returns an error message describing the problem. This command can be used to unload libraries that are no longer needed, freeing up resources. It is important to ensure that no part of the program is still using the library before unloading it, as this could lead to unpredictable behavior or crashes.
PORTABILITY ISSUES:
Tcl/Tk has no built-in support for dynamically loading or unloading libraries.
BUGS:
The unload command is not implemented in Tcl/Tk. It is a placeholder for future functionality.
EXAMPLE:
# Load a shared library
set chan [load "/path/to/my_library.so"]

# Use functions from the library...

# Unload the library when it's no longer needed
unload $chan
