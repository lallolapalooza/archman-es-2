DESCRIPCIÓN

Unbound es una implementación de un resolvedor DNS, que realiza caching y validación DNSSEC. Esta es la API de la biblioteca, para usar la biblioteca -lunbound. El demonio del servidor se describe en unbound(8). La biblioteca funciona independientemente de un servidor unbound en ejecución, y puede usarse para convertir nombres de host a direcciones IP y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de clave pública de los resultados con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Puede ser creada y eliminada en cualquier momento. Crearla de nuevo elimina cualquier configuración previa (como claves de confianza) y borra cualquier resultado en caché.

Las funciones son seguras para hilos (thread-safe), y un contexto puede ser utilizado en un entorno con hilos (así como en uno sin hilos). Además, la resolución (y validación) puede realizarse de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve el control inmediatamente desde la llamada, de modo que el procesamiento puede continuar, mientras que los resultados estarán disponibles más tarde.

Las funciones se discuten a continuación, una por una.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza por defecto. Usa ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esta función, usa las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si usas lib openssl (la aplicación llama a estas funciones una vez para la inicialización). Openssl 1.0.0 o posterior utiliza la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y las devoluciones de llamada (callbacks) no se llaman para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que permite especificar una de las opciones del formato de archivo de configuración, véase unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclas de confianza, existen rutinas especiales. Pasa el nombre de la opción con los dos puntos finales ':'.
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene un valor de opción. Algunas opciones no se pueden obtener, y otras devuelven una lista separada por saltos de línea. Pasa el nombre de la opción sin los dos puntos finales ':'. El valor devuelto debe ser liberado con free(2) por el llamador.
ub_ctx_config
Una interfaz para usuarios avanzados que permite especificar un archivo de configuración de unbound, véase unbound.conf(5), que se lee para la configuración. No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclas de confianza, existen rutinas especiales. Esta función solo es segura para hilos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no sea llamada en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se reenviarán las consultas DNS, el resolvedor de caché a utilizar. Dirección IP4 o IP6. Reenvía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolvedor recursivo. Si el proxy no es compatible con DNSSEC, la validación puede fallar. Se puede llamar varias veces; en ese caso, las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autoritativos a utilizar para una zona particular. Dirección IP4 o IP6. Si la dirección es NULL, se elimina la entrada stub. Establece `isprime` a true si la configuras con hints de raíz. De lo contrario, es similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas, o para agregar múltiples direcciones para una zona particular. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolución completa, pero puedes usar esta llamada para leer la lista de servidores de nombres a usar desde el nombre de archivo dado. Generalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no soportan DNSSEC, la validación puede fallar. Solo se seleccionan los servidores de nombres; el dominio de búsqueda, ndots y otras configuraciones de resolv.conf(5) se ignoran. Si se pasa un fname NULL, se utiliza "/etc/resolv.conf" (si estás en Windows, se selecciona el servidor de nombres configurado a nivel de sistema). En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_hosts
Lee la lista de hosts del nombre de archivo dado. Generalmente "/etc/hosts". Cuando se consultan, estas direcciones no se marcan como seguras por DNSSEC. Si se pasa un fname NULL, se utiliza "/etc/hosts" (si estás en Windows, se selecciona `etc/hosts` desde WINDIR). En este momento, solo es posible establecer la configuración antes de que se realice la primera reso

DESCRIPTION

The unbound library provides functions to perform DNS lookups and DNSSEC validation. It is a validating, recursive, caching DNS resolver.

The library is configured via a context object, struct ub_ctx. This object holds all configuration and state for the resolver instance.

Before any DNS lookups can be performed, a context must be created using ub_ctx_create. This function returns a pointer to a new context object, or NULL on allocation failure.

When done with the context, it must be deallocated using ub_ctx_destroy.

The resolver needs to know where to find upstream resolvers. It can do this by reading the system's resolv.conf(5) file (using ub_ctx_resolvconf), or by reading a specified configuration file (using ub_ctx_config). For detailed configuration options see unbound.conf(5).

Trust anchors are needed for DNSSEC validation. These can be added using ub_ctx_add_ta, ub_ctx_add_ta_autr, ub_ctx_add_ta_file, or ub_ctx_trustedkeys.

Debug output can be directed to a specific file stream using ub_ctx_debugout. Verbosity of debug messages can be set using ub_ctx_debuglevel.

By default, the library performs synchronous lookups when calling ub_resolve. The ub_ctx_async function can be used to set the context to perform asynchronous operations. If enabled, ub_resolve_async can be used instead of ub_resolve. Asynchronous operations require polling or waiting for results.

ub_poll checks if any results are ready from the resolver. It returns nonzero if results are available, and zero otherwise. Do not call this in a loop; instead, use ub_fd to get a file descriptor that can be polled for readability. When ub_poll returns nonzero, call ub_process to handle the callbacks.

ub_wait waits for all outstanding asynchronous queries to finish and then processes any results. It calls ub_process internally.

ub_fd returns a file descriptor for the context. This file descriptor becomes readable when results are available from asynchronous queries. It can be used with select(2), poll(2), epoll(7) etc. On error, -1 is returned.

ub_process processes any pending results and performs the necessary callbacks for asynchronous queries. It should be called after notification that the file descriptor returned by ub_fd is ready for reading.

ub_resolve performs a synchronous DNS lookup and validation of the given name, type, and class. It returns a pointer to a newly allocated result structure in the `result` argument. The caller is responsible for freeing this structure using ub_resolve_free.

ub_resolve_async performs an asynchronous DNS lookup and validation. Instead of returning the result immediately, it takes a callback function pointer and a data pointer. The callback function will be invoked when the result is ready or an error occurs. The `async_id` can be used to cancel the query later using ub_cancel.

ub_cancel attempts to cancel an asynchronous query. Note that the callback might still be invoked if the query is already in progress or being delivered.

ub_resolve_free deallocates the memory associated with a result structure obtained from ub_resolve or ub_resolve_async.

ub_strerror converts an error code returned by other library functions into a human-readable string.

ub_ctx_print_local_zones prints the configured local zones to the debug output stream.

ub_ctx_zone_add adds a new zone to the local authority information. The `zone_type` specifies if the zone is 'primary' or 'stub'.

ub_ctx_zone_remove removes a zone from the local authority information.

ub_ctx_data_add adds resource record data to the local authority information. The `data_string` must be in the format as specified in unbound.conf(5) for the local-data directive.

ub_ctx_data_remove removes local authority data for the given name.

FUNCTIONS

ub_ctx_create
Create a new Unbound context. Returns a pointer to the context or NULL on failure.
ub_ctx_destroy
Destroy the given Unbound context and free all associated resources.
ub_ctx_resolvconf
Read system resolver configuration (e.g. /etc/resolv.conf) and configure the context accordingly. Uses the given filename, or defaults to /etc/resolv.conf if NULL is passed.
ub_ctx_config
Read Unbound configuration file and configure the context accordingly. Uses the given filename, or defaults to unbound.conf if NULL is passed.
ub_ctx_add_ta
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
ub_ctx_add_ta_autr
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta_file
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_trustedkeys
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_debugout
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
ub_ctx_debuglevel
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
ub_ctx_async
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
ub_poll
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
ub_wait
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
ub_fd
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
ub_process
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
ub_resolve
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
ub_resolve_async
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

ub_cancel
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
ub_resolve_free
Free struct ub_result contents after use.
ub_strerror
Convert error value from one of the unbound library functions to a human readable string.
ub_ctx_print_local_zones
Debug printout the local authority information to debug output.
ub_ctx_zone_add
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
ub_ctx_zone_remove
Delete zone from local authority info.
ub_ctx_data_add
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
ub_ctx_data_remove
Delete local authority data from the name given.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Else, they are not both true, one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.
