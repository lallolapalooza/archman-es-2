NOMBRE

uucico - demonio de transferencia de archivos UUCP

SINOPSIS

uucico [ opciones ]

DESCRIPCIÓN

El demonio uucico procesa las solicitudes de transferencia de archivos puestas en cola por uucp (1) y uux (1). Se inicia cuando se ejecuta uucp o uux (a menos que se les dé la opción -r). También se inicia típicamente de forma periódica usando entradas en las tablas crontab.

Cuando se invoca con -r1, --master, -s, --system, o -S, el demonio realizará una llamada a un sistema remoto, ejecutándose en modo maestro. De lo contrario, el demonio se iniciará en modo esclavo, aceptando una llamada de un sistema remoto. Típicamente se configurará un nombre de inicio de sesión especial para UUCP que invoca automáticamente uucico cuando se realiza una llamada.

Cuando uucico termina, invoca al demonio uuxqt (8), a menos que se proporcione la opción -q o --nouuxqt; uuxqt (8) ejecuta cualquier orden de trabajo creada por uux (1) en un sistema remoto, y cualquier orden de trabajo creada localmente para la cual se han recibido archivos remotos que estaba esperando.

Si una llamada falla, uucico normalmente se negará a intentar la llamada hasta que haya transcurrido una cierta cantidad de tiempo (configurable). Esto puede ser anulado por las opciones -f, --force, o -S.

Las opciones -l, --prompt, -e, o --loop pueden usarse para forzar a uucico a producir sus propias indicaciones de "login: " y "Password:". Cuando otro demonio llama, verá estas indicaciones e iniciará sesión como de costumbre. El nombre de inicio de sesión y la contraseña se comprobarán normalmente contra una lista separada mantenida especialmente para uucico en lugar del archivo /etc/passwd; es posible en algunos sistemas dirigir uucico para que utilice el archivo /etc/passwd. La opción -l o --prompt solicitará una vez y luego saldrá; en este modo, el administrador de UUCP o el superusuario pueden usar la opción -u o --login para forzar un nombre de inicio de sesión, en cuyo caso uucico no solicitará uno. La opción -e o --loop solicitará de nuevo después de que la primera sesión haya terminado; en este modo, uucico controlará permanentemente un puerto.

Si uucico recibe una señal SIGQUIT, SIGTERM o SIGPIPE, interrumpirá limpiamente cualquier conversación actual con un sistema remoto y saldrá. Si recibe una señal SIGHUP, interrumpirá cualquier conversación actual, pero continuará llamando a (si se invocó con -r1 o --master) y aceptando llamadas de (si se invocó con -e o --loop) otros sistemas. Si recibe una señal SIGINT, terminará la conversación actual, pero no realizará ni aceptará más llamadas.

OPCIONES

Las siguientes opciones pueden ser dadas a uucico.

-r1, --master
Iniciar en modo maestro (llamar a un sistema); implícito por -s, --system, o -S. Si no se especifica ningún sistema, llamar a cualquier sistema para el cual haya trabajo pendiente.
-r0, --slave
Iniciar en modo esclavo. Este es el valor predeterminado.
-s system, --system system
Llamar al sistema especificado.
-S system
Llamar al sistema especificado, ignorando cualquier espera requerida. Esto es equivalente a -s system -f.
-f, --force
Ignorar cualquier espera requerida para los sistemas a llamar.
-l, --prompt
Solicitar nombre de inicio de sesión y contraseña usando "login: " y "Password:". Esto permite que uucico se ejecute fácilmente desde inetd (8). El nombre de inicio de sesión y la contraseña se comprueban contra el archivo de contraseñas de UUCP, que probablemente no tiene conexión con el archivo /etc/passwd. La opción --login puede usarse para forzar un nombre de inicio de sesión, en cuyo caso uucico solo solicitará la contraseña.
-p port, --port port
Especificar un puerto para llamar o para escuchar.
-e, --loop
Entrar en un bucle infinito de solicitudes de inicio de sesión/contraseña y ejecución del demonio en modo esclavo. El programa no se detendrá por sí mismo; debe usar kill (1) para apagarlo.
-w, --wait
Después de llamar (a un sistema específico cuando se especifica -s, --system, o -S, o a todos los sistemas que tienen trabajo cuando solo se especifica -r1 o --master), iniciar un bucle infinito como con --loop.
-q, --nouuxqt
No iniciar el demonio uuxqt (8) al finalizar.
-c, --quiet
Si no se permiten llamadas en este momento, no realizar la llamada, pero tampoco poner un mensaje de error en el archivo de registro ni actualizar el estado del sistema (como lo informa uustat (1)). Esto puede ser útil para scripts de sondeo automatizados, que pueden querer simplemente intentar llamar a todos los sistemas en lugar de preocuparse por qué sistemas específicos pueden ser llamados en este momento. Esta opción también suprime el mensaje de registro que indica que no hay trabajo que hacer.
-C, --ifwork
Solo llamar al sistema nombrado por -s, --system o -S si hay trabajo para ese sistema.
-D, --nodetach
No separarse de la terminal de control. Normalmente uucico se separa de la terminal antes de cada llamada a otro sistema y antes de invocar uuxqt. Esta opción evita esto.
-u name, --login name
Establecer el nombre de inicio de sesión a usar en lugar del del usuario que lo invoca. Esta opción solo puede ser utilizada por el administrador de UUCP o el superusuario. Si se usa con --prompt, esto hará que uucico solicite solo la contraseña, no el nombre de inicio de sesión.
-z, --try-next
Si una llamada falla después de que se alcanza el sistema remoto, intentar el siguiente alternativo en lugar de simplemente salir.
-i type, --stdin type
Establecer el tipo de puerto a usar cuando se usa la entrada estándar. El único tipo de puerto soportado es TLI, y esto solo está disponible en máquinas que soportan la interfaz de red TLI. Especificar -iTLI hace que uucico use llamadas TLI para realizar E/S.
-x type, -X type, --debug type
Activar tipos de depuración específicos. Los siguientes tipos son reconocidos: abnormal, chat, handshake, uucp-proto, proto, port, config, spooldir, execute, incoming, outgoing.

Se pueden proporcionar varios tipos, separados por comas, y la opción --debug puede aparecer varias veces. También se puede proporcionar un número, que activará ese número de tipos de la lista anterior; por ejemplo, --debug 2 es equivalente a --debug abnormal,chat.

La salida de depuración se envía al archivo de depuración, que puede imprimirse usando uulog -D.

-I file, --config file
Establecer el archivo de configuración a usar. Esta opción puede no estar disponible, dependiendo de cómo se compiló uucico.
-v, --version
Informar la información de la versión y salir.
--help
Imprimir un mensaje de ayuda y salir.
