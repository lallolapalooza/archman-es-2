UNGET(1P) Manual de Programador POSIX UNGET(1P)

PROLOG

Esta página del manual es parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

unget — deshacer una obtención previa de un archivo SCCS (DESARROLLO)

SINOPSIS

unget [-ns] [-r SID] archivo...

DESCRIPCIÓN

El utilidad unget revertirá el efecto de un get -e realizado antes de crear el delta previsto.

OPCIONES

La utilidad unget cumplirá con el volumen de Definiciones Base de POSIX.1-2017, Sección 12.2, Directrices de Sintaxis de Utilidades.

Se admitirán las siguientes opciones:

-r SID
Identifica de forma única qué delta ya no es deseado. (Esto habría sido especificado por get como el nuevo delta). El uso de esta opción solo es necesario si dos o más comandos get pendientes para edición en el mismo archivo SCCS fueron realizados por la misma persona (nombre de inicio de sesión).
-s
Suprime la escritura en la salida estándar del SID del delta previsto.
-n
Conserva el archivo que fue obtenido por get, el cual normalmente sería eliminado del directorio actual.

OPERANDOS

Se admitirán los siguientes operandos:

archivo
Una ruta a un archivo SCCS existente o un directorio. Si archivo es un directorio, la utilidad unget se comportará como si cada archivo en el directorio fuera especificado como un archivo nombrado, excepto que los archivos no-SCCS (el componente final de la ruta no comienza con s.) y los archivos ilegibles serán ignorados silenciosamente.

Si aparece exactamente un operando archivo, y este es '-', se leerá la entrada estándar; cada línea de la entrada estándar se tomará como el nombre de un archivo SCCS a procesar. Los archivos no-SCCS y los archivos ilegibles serán ignorados silenciosamente.

ENTRADA ESTÁNDAR

La entrada estándar será un archivo de texto utilizado solo cuando el operando archivo se especifica como '-'. Cada línea del archivo de texto se interpretará como una ruta SCCS.

ARCHIVOS DE ENTRADA

Cualquier archivo SCCS procesado serán archivos de formato no especificado.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de unget:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1-2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en una cadena de valor no vacía, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en comparación con caracteres multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASINCRÓNICOS

Predeterminado.

SALIDA ESTÁNDAR

La salida estándar consistirá en una línea por cada archivo, en el siguiente formato:

"%s\n", <SID eliminado del archivo>

Si hay más de un archivo nombrado o si se nombra un directorio o la entrada estándar, cada ruta se escribirá antes de cada una de las líneas anteriores:

"\n%s:\n", <ruta>

ERROR ESTÁNDAR

El error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Cualquier archivo SCCS actualizado será un archivo de formato no especificado. Durante el procesamiento de un archivo, se puede crear y eliminar un archivo z de bloqueo, como se describe en get, y un archivo q (una copia de trabajo del archivo p). El archivo p y el archivo g, como se describe en get, serán eliminados.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.
