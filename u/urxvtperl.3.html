NOMBRE

urxvtperl - intérprete perl incrustado de rxvt-unicode

SINOPSIS

# crear un archivo grab_test en algún directorio:
sub on_sel_grab {
   warn "has seleccionado ", $_[0]->selection;
   ()
}
# iniciar una instancia de urxvt usándolo:
urxvt --perl-lib ruta/a/algun/directorio -pe grab_test

DESCRIPCIÓN

Cada vez que se crea un objeto de terminal, se cargan los scripts de extensión especificados a través del recurso "perl" y se asocian con él.

Los scripts se compilan en un entorno 'use strict qw(vars subs)' y 'use utf8', y por lo tanto deben estar codificados como UTF-8.

Cada script solo se cargará una vez, incluso en urxvtd, donde los scripts se compartirán (pero no se habilitarán) para todas las terminales.

Puede deshabilitar el intérprete perl incrustado estableciendo los recursos "perl-ext" y "perl-ext-common" a la cadena vacía.

EXTENSIONES PREEMPAQUETADAS

Varias extensiones se entregan con esta versión. Puede encontrarlas en <libdir>/urxvt/perl/, y la documentación se puede ver usando man urxvt-<NOMBREDEEXTENSION>.

Puede activarlas así:

urxvt -pe <nombredeextension>

O añadiéndolas al recurso para las extensiones cargadas por defecto:

URxvt.perl-ext-common: default,selection-autotransform

Las extensiones pueden añadir recursos adicionales y "acciones", es decir, métodos que se pueden enlazar a una tecla e invocar por el usuario. Una extensión puede definir los recursos que soporta usando los llamados comentarios META, descritos a continuación. De forma similar a los recursos integrados, los recursos de extensión también se pueden especificar en la línea de comandos como opciones largas (con "." reemplazado por "-"), en cuyo caso la extensión correspondiente se carga automáticamente. Para que esto funcione, la extensión debe definir comentarios META para sus recursos.

DOCUMENTACIÓN DE LA API

Consideraciones Generales de la API

Todos los objetos (como terminales, observadores de tiempo, etc.) son objetos típicos de referencia a hash. El hash se puede usar para almacenar cualquier cosa que desee. Todos los miembros que comienzan con un guion bajo (como "_ptr" o "_hook") están reservados para usos internos y NO DEBEN ser accedidos o modificados).

Cuando los objetos se destruyen en el lado C++, los hashes de objetos perl se vacían, por lo que es mejor almacenar objetos relacionados como observadores de tiempo y similares dentro del objeto terminal para que se destruyan tan pronto como se destruya la terminal.

Los nombres de los argumentos también suelen indicar el tipo de un parámetro. Aquí hay algunas pistas sobre lo que significan:

$text
La forma especial de codificación de texto de Rxvt-unicode, donde un carácter "unicode" representa siempre una celda de pantalla. Véase ROW_t para una discusión de este formato.
$string
Una cadena de texto perl, con énfasis en texto. Puede almacenar todos los caracteres unicode y se distingue de texto codificado en una codificación específica (a menudo específica de la configuración regional) y datos binarios.
$octets
Datos binarios o, más comúnmente, una cadena de texto codificada de forma específica de la configuración regional.
$keysym
un entero que es un código keysym válido de X11. Puede convertir una cadena en un keysym y viceversa usando "XStringToKeysym" y "XKeysymToString".

Objetos de Extensión

Cada extensión perl es una clase perl. Se crea un objeto perl separado para cada terminal, y cada terminal tiene su propio conjunto de objetos de extensión, que se pasan como primer parámetro a los hooks. Por lo tanto, las extensiones pueden usar su objeto $self sin tener que pensar en conflictos con otras extensiones u otras terminales, con la excepción de los métodos y miembros que comienzan con un carácter de guion bajo "_": estos están reservados para uso interno.

Aunque no es un objeto "urxvt::term", puede llamar a todos los métodos de la clase "urxvt::term" en este objeto.

Los métodos adicionales que solo se soportan para objetos de extensión se describen en la sección "urxvt::extension" a continuación.

Comentarios META

Rxvt-unicode reconoce comentarios meta especiales en las extensiones que definen diferentes tipos de metadatos. Estos comentarios se escanean cada vez que se crea una terminal y se utilizan típicamente para cargar automáticamente las extensiones cuando se utilizan sus recursos o parámetros de línea de comandos.

Actualmente, reconoce los siguientes comentarios. Los componentes individuales están separados por dos puntos (":") y no deben contener dos puntos; además, actualmente no se proporciona ningún mecanismo de escape para esto.

#:META:RESOURCE:nombre:tipo:desc
El comentario RESOURCE define un recurso utilizado por la extensión, donde "nombre" es el nombre del recurso, "tipo" es el tipo de recurso, "boolean" o "string", y "desc" es la descripción del recurso.

La extensión se cargará automáticamente cuando se especifique este recurso o se utilice como parámetro de línea de comandos.

Ejemplo: matcher proporciona el recurso "matcher.launcher" teniendo este comentario:

#:META:RESOURCE:%.launcher:string:comando lanzador por defecto

Ejemplo: carga esta extensión cuando se utiliza la opción de línea de comandos "-tr" o el nombre del recurso.

#:META:RESOURCE:tr:boolean:establecer el pixmap raíz como fondo
#:META:OSC:numero:desc
El comentario OSC especifica una secuencia OSC, donde "numero" es el código numérico OSC y "desc" es una breve descripción que actualmente no se utiliza.

Esto hará que la extensión se cargue automáticamente cuando se utilice la secuencia OSC por primera vez.

Tenga en cuenta que la carga automática conlleva algunas responsabilidades adicionales: aunque la terminal no puede protegerse realmente contra fuentes maliciosas de secuencias de comandos, por lo que depende de los programas que se ejecutan dentro para sanear los datos que emiten, es muy común que los programas emitan secuencias de comandos de fuentes no confiables.

Si bien esto significa que las extensiones deberían, como mecanismo de defensa en profundidad, considerar siempre si las secuencias OSC son seguras, la carga automática expone automáticamente cualquier extensión cargada automáticamente en todas las ventanas de terminal, por lo que se debe tener especial cuidado.

Ejemplo: la extensión de fondo registra OSC 20 de esta manera:

#:META:OSC:20:cambiar/consultar imagen de fondo
#:META:OSC_PERL:prefijo:desc
Lo mismo que el comentario OSC, pero para la secuencia OSC de Perl (777). El "prefijo" debe ser único entre las extensiones, por supuesto, lo que se organiza más fácilmente utilizando el nombre de la extensión, aunque esto no es obligatorio.

Ejemplo: la extensión overlay-osc registra su OSC de Perl de esta manera:

#:META:OSC_PERL:overlay:man overlay-osc

Hooks

Las siguientes subrutinas se pueden declarar en archivos de extensión y se llamarán cada vez que ocurra el evento relevante.

El primer argumento que se les pasa es un objeto de extensión, como se describe en la sección "Objetos de Extensión".

Todos estos hooks deben devolver un valor booleano. Si alguno de los hooks llamados devuelve verdadero, el evento se considera consumido, y la acción relevante podría no ser llevada a cabo por el código C++.

En caso de duda, devuelva un valor falso (preferiblemente "()" o undef).

Variables en el paquete "urxvt"

$urxvt::LIBDIR
El directorio de bibliotecas de rxvt-unicode, donde, entre otras cosas, se almacenan los módulos y scripts perl.
$urxvt::RESCLASS, $urxvt::RESNAME
La clase y el nombre de recurso que rxvt-unicode utiliza para buscar recursos X.
$urxvt::RXVTNAME
El nombre base de los binarios instalados, generalmente "urxvt".
$urxvt::TERM
El terminal actual. Esta variable almacena el objeto "urxvt::term" actual, cada vez que se ejecuta una devolución de llamada/hook.
@urxvt::TERM_INIT
Todas las referencias de código en esta matriz se llamarán como métodos del próximo objeto "urxvt::term" recién creado (durante la fase "on_init"). La matriz se borra antes de que se ejecuten las referencias de código que estaban en ella, por lo que las referencias pueden añadirse a sí mismas si lo desean.

Esto complementa la opción de línea de comandos perl-eval, pero se ejecuta primero.

@urxvt::TERM_EXT
Funciona de manera similar a @TERM_INIT, pero contiene nombres de paquetes/clases perl, que se registran como extensiones normales después de llamar a los hooks en @TERM_INIT pero antes que otras extensiones. Se borra igual que @TERM_INIT.

Funciones en el paquete "urxvt"

urxvt::fatal $errormessage
Aborta fatalmente la ejecución con el mensaje de error dado (que debe incluir una nueva línea al final). ¡Evitar a toda costa! La única vez que esto es aceptable (y útil) es en el hook de inicialización, donde evita que el terminal se inicie.
urxvt::warn $string
Llama a "rxvt_warn" con la cadena dada, que debe incluir una nueva línea al final. El módulo también sobrescribe la función incorporada "warn" con una función que llama a esta función.

Usar esta función tiene la ventaja de que su salida termina en el lugar correcto, por ejemplo, en stderr del cliente urxvtc conectado.

Actualmente, los mensajes tienen un límite de tamaño de 1023 bytes.

RENDITION

Los conjuntos de bits de rendition contienen información sobre el color, la fuente, los estilos de fuente y otra información similar para cada celda de la pantalla.

Las siguientes "macros" se ocupan de los cambios en los conjuntos de rendition. Nunca debes crear un conjunto de bits directamente, siempre debes modificar uno existente, ya que contienen información importante requerida para el correcto funcionamiento de rxvt-unicode.

$rend = urxvt::DEFAULT_RSTYLE
Devuelve la rendition por defecto, tal como se utiliza cuando el terminal se está iniciando o se está restableciendo. Útil como base para empezar al crear renditions.
$rend = urxvt::OVERLAY_RSTYLE
Devuelve la máscara de rendition utilizada para las superposiciones por defecto.
$rendbit = urxvt::RS_Bold, urxvt::RS_Italic, urxvt::RS_Blink, urxvt::RS_RVid, urxvt::RS_Uline
Devuelve el bit que activa negrita, cursiva, parpadeo, vídeo inverso y subrayado, respectivamente. Para activar dicho estilo, simplemente OR lógica en el conjunto de bits.
$foreground = urxvt::GET_BASEFG $rend
Obtiene el color de primer plano base de la rendition.
$background = urxvt::GET_BASEBG $rend
Obtiene el color de fondo base de la rendition.
$rend = urxvt::SET_FGCOLOR $rend, $new_colour
Establece el color de primer plano en la rendition.
$rend = urxvt::SET_BGCOLOR $rend, $new_colour
Establece el color de fondo en la rendition.
$rend = urxvt::SET_COLOR $rend, $new_fg, $new_bg
Reemplaza el color de primer plano/fondo en la máscara de rendition con el especificado.
$value = urxvt::GET_CUSTOM $rend
Devuelve el valor "personalizado": Cada rendition tiene 5 bits para uso de extensiones. Se pueden establecer y cambiar como se desee y están inicialmente a cero.
$rend = urxvt::SET_CUSTOM $rend, $new_value
Cambia el valor personalizado.

La clase "urxvt::term::extension"

Cada extensión adjunta a un objeto de terminal está representada por un objeto "urxvt::term::extension".

Puede utilizar estos objetos, que se pasan a todas las devoluciones de llamada, para almacenar cualquier estado relacionado con la instancia del terminal y la extensión.

Los métodos (y miembros de datos) documentados a continuación se pueden llamar en objetos de extensión, además de llamar a los métodos documentados para la clase <urxvt::term>.

$urxvt_term = $self->{term}
Devuelve el objeto "urxvt::term" asociado con esta instancia de la extensión. Este miembro no debe cambiarse de ninguna manera.
$self->enable ($hook_name => $cb[, $hook_name => $cb..])
Habilita dinámicamente los hooks dados (nombrados sin el prefijo "on_") para esta extensión, reemplazando cualquier hook instalado previamente a través de "enable" en esta extensión.

Esto es útil cuando se quieren sobrescribir hooks críticos en cuanto a tiempo solo temporalmente.

Para instalar devoluciones de llamada adicionales para el mismo hook, puede usar el método "on" de la clase "urxvt::term".

$self->disable ($hook_name[, $hook_name..])
Deshabilita dinámicamente los hooks dados.
$guard = $self->on ($hook_name => $cb[, $hook_name => $cb..])
Similar a "enable", pero instala devoluciones de llamada adicionales para el(los) hook(s) dados (es decir, no reemplaza las devoluciones de llamada existentes), y devuelve un objeto guardia.

La instalación de devoluciones de llamada a través de "on" se garantiza que se elimine correctamente cuando el objeto guardia se sale del ámbito (por ejemplo, al final de un bloque).

The "urxvt::line" Class

bool = $term->ROW_encoded ()
This is a boolean value indicating whether the terminal uses the special encoding described in the last section. If it returns true, you have to obey the encoding when changing text. The advantage is that "substr" and similar functions work on screen cells and not on characters.

The methods "$term->special_encode" and "$term->special_decode" can be used to convert normal strings into this encoding and vice versa.

$rend = $term->ROW_r ($row_number[, $new_rend[, $start_col]])
Like "$term->ROW_t", but returns an arrayref with rendition bitsets. Rendition bitsets contain information about colour, font, font styles and similar information. See also "$term->ROW_t".

When setting rendition, the font mask will be ignored.

See the section on RENDITION, above.

$length = $term->ROW_l ($row_number[, $new_length])
Returns the number of screen cells that are in use ("the line length"). Unlike the urxvt core, this returns "$term->ncol" if the line is joined with the following one.
$bool = $term->is_longer ($row_number)
Returns true if the row is part of a multiple-row logical "line" (i.e. joined with the following row), which means all characters are in use and it is continued on the next row (and possibly a continuation of the previous row(s)).
$line = $term->line ($row_number)
Create and return a new "urxvt::line" object that stores information about the logical line that row $row_number is part of. It supports the following methods:
$text = $line->t ([$new_text])
Returns or replaces the full text of the line, similar to "ROW_t"
$rend = $line->r ([$new_rend])
Returns or replaces the full rendition array of the line, similar to "ROW_r"
$length = $line->l
Returns the length of the line in cells, similar to "ROW_l".
$rownum = $line->beg
$rownum = $line->end
Return the row number of the first/last row of the line, respectively.
$offset = $line->offset_of ($row, $col)
Returns the character offset of the given row|col pair within the logical line. Works for rows outside the line, too, and returns corresponding offsets outside the string.
(<code>$row</code>, <code>$col</code>) = $line->coord_of ($offset)
Translates a string offset into terminal coordinates again.
$text = $term->special_encode ($string)
Converts a perl string into the special encoding used by rxvt-unicode, where one character corresponds to one screen cell. See "$term->ROW_t" for details.
$string = $term->special_decode ($text)
Converts rxvt-unicode's text representation into a perl string. See "$term->ROW_t" for details.
$success = $term->grab_button ($button, $modifiermask[, $window = $term->vt])
$term->ungrab_button ($button, $modifiermask[, $window = $term->vt])

The "urxvt::timer" Class

This class implements timer watchers/events. Time is represented as a fractional number of seconds since the epoch. Example:

$term->{overlay} = $term->overlay (-1, 0, 8, 1, urxvt::OVERLAY_RSTYLE, 0);
$term->{timer} = urxvt::timer
                 ->new
                 ->interval (1)
                 ->cb (sub {
                    $term->{overlay}->set (0, 0,
                       sprintf "%2d:%02d:%02d", (localtime urxvt::NOW)[2,1,0]);
                 });
$timer = new urxvt::timer
Create a new timer object in started state. It is scheduled to fire immediately.
$timer = $timer->cb (sub { my ($timer) = @_; ... })
Set the callback to be called when the timer triggers.
$timer = $timer->set ($tstamp[, $interval])
Set the time the event is generated to $tstamp (and optionally specifies a new $interval).
$timer = $timer->interval ($interval)
By default (and when $interval is 0), the timer will automatically stop after it has fired once. If $interval is non-zero, then the timer is automatically rescheduled at the given intervals.
$timer = $timer->start
Start the timer.
$timer = $timer->start ($tstamp[, $interval])
Set the event trigger time to $tstamp and start the timer. Optionally also replaces the interval.
$timer = $timer->after ($delay[, $interval])
Like "start", but sets the expiry timer to c<urxvt::NOW + $delay>.
$timer = $timer->stop
Stop the timer.

The "urxvt::iow" Class

This class implements io watchers/events. Example:

$term->{socket} = ...
$term->{iow} = urxvt::iow
               ->new
               ->fd (fileno $term->{socket})
               ->events (urxvt::EV_READ)
               ->start
               ->cb (sub {
                 my ($iow, $revents) = @_;
                 # $revents must be 1 here, no need to check
                 sysread $term->{socket}, my $buf, 8192
                    or end-of-file;
               });
$iow = new urxvt::iow
Create a new io watcher object in stopped state.
$iow = $iow->cb (sub { my ($iow, $reventmask) = @_; ... })
Set the callback to be called when io events are triggered. $reventmask is a bitset as described in the "events" method.

$iow = $iow->events ($eventmask)
Set the event mask to watch. The only allowed values are "urxvt::EV_READ" and "urxvt::EV_WRITE", which might be ORed together, or "urxvt::EV_NONE".

URXVT_PERL_VERBOSITY

This variable controls the verbosity level of the perl extension. Higher numbers indicate more verbose output.

>= 2 - general warnings (default level)

>=10 - all called hooks
