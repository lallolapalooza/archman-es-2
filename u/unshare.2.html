unshare(2) Manual de llamadas al sistema unshare(2)

NOMBRE

unshare - desagrupa partes del contexto de ejecución del proceso

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE
#include <sched.h>
int unshare(int flags);

DESCRIPCIÓN

unshare() permite a un proceso (o hilo) desagrupar partes de su contexto de ejecución que actualmente se están compartiendo con otros procesos (o hilos). Parte del contexto de ejecución, como el espacio de nombres de montaje, se comparte implícitamente cuando se crea un nuevo proceso usando fork(2) o vfork(2), mientras que otras partes, como la memoria virtual, pueden ser compartidas por solicitud explícita al crear un proceso o hilo usando clone(2).

El uso principal de unshare() es permitir que un proceso controle su contexto de ejecución compartido sin crear un nuevo proceso.

El argumento flags es una máscara de bits que especifica qué partes del contexto de ejecución deben ser desagrupadas. Este argumento se especifica OR-ando cero o más de las siguientes constantes:

CLONE_FILES
Revierte el efecto de la bandera clone(2) CLONE_FILES. Desagrupa la tabla de descriptores de archivo, de modo que el proceso que llama ya no comparte sus descriptores de archivo con ningún otro proceso.
CLONE_FS
Revierte el efecto de la bandera clone(2) CLONE_FS. Desagrupa los atributos del sistema de archivos, de modo que el proceso que llama ya no comparte su directorio raíz (chroot(2)), directorio actual (chdir(2)), o umask (umask(2)) con ningún otro proceso.
CLONE_NEWCGROUP (desde Linux 4.6)
Esta bandera tiene el mismo efecto que la bandera clone(2) CLONE_NEWCGROUP. Desagrupa el espacio de nombres de cgroup. El uso de CLONE_NEWCGROUP requiere la capacidad CAP_SYS_ADMIN.
CLONE_NEWIPC (desde Linux 2.6.19)
Esta bandera tiene el mismo efecto que la bandera clone(2) CLONE_NEWIPC. Desagrupa el espacio de nombres IPC, de modo que el proceso que llama tenga una copia privada del espacio de nombres IPC que no se comparte con ningún otro proceso. Especificar esta bandera implica automáticamente CLONE_SYSVSEM. El uso de CLONE_NEWIPC requiere la capacidad CAP_SYS_ADMIN.
CLONE_NEWNET (desde Linux 2.6.24)
Esta bandera tiene el mismo efecto que la bandera clone(2) CLONE_NEWNET. Desagrupa el espacio de nombres de red, de modo que el proceso que llama sea movido a un nuevo espacio de nombres de red que no se comparte con ningún proceso existente previamente. El uso de CLONE_NEWNET requiere la capacidad CAP_SYS_ADMIN.
CLONE_NEWNS
Esta bandera tiene el mismo efecto que la bandera clone(2) CLONE_NEWNS. Desagrupa el espacio de nombres de montaje, de modo que el proceso que llama tenga una copia privada de su espacio de nombres que no se comparte con ningún otro proceso. Especificar esta bandera implica automáticamente CLONE_FS. El uso de CLONE_NEWNS requiere la capacidad CAP_SYS_ADMIN. Para más información, véase mount_namespaces(7).
CLONE_NEWPID (desde Linux 3.8)
Esta bandera tiene el mismo efecto que la bandera clone(2) CLONE_NEWPID. Desagrupa el espacio de nombres PID, de modo que el proceso que llama tenga un nuevo espacio de nombres PID para sus hijos que no se comparte con ningún proceso existente previamente. El proceso que llama no es movido al nuevo espacio de nombres. El primer hijo creado por el proceso que llama tendrá el ID de proceso 1 y asumirá el rol de init(1) en el nuevo espacio de nombres. CLONE_NEWPID implica automáticamente CLONE_THREAD. El uso de CLONE_NEWPID requiere la capacidad CAP_SYS_ADMIN. Para más información, véase pid_namespaces(7).
CLONE_NEWTIME (desde Linux 5.6)
Desagrupa el espacio de nombres de tiempo, de modo que el proceso que llama tenga un nuevo espacio de nombres de tiempo para sus hijos que no se comparte con ningún proceso existente previamente. El proceso que llama no es movido al nuevo espacio de nombres. El uso de CLONE_NEWTIME requiere la capacidad CAP_SYS_ADMIN. Para más información, véase time_namespaces(7).
CLONE_NEWUSER (desde Linux 3.8)
Esta bandera tiene el mismo efecto que la bandera clone(2) CLONE_NEWUSER. Desagrupa el espacio de nombres de usuario, de modo que el proceso que llama sea movido a un nuevo espacio de nombres de usuario que no se comparte con ningún proceso existente previamente. Al igual que con el proceso hijo creado por clone(2) con la bandera CLONE_NEWUSER, el llamador obtiene un conjunto completo de capacidades en el nuevo espacio de nombres.
CLONE_NEWUSER requiere que el proceso que llama no esté en modo hilo; especificar CLONE_NEWUSER implica automáticamente CLONE_THREAD. Desde Linux 3.9, CLONE_NEWUSER también implica automáticamente CLONE_FS. CLONE_NEWUSER requiere que el ID de usuario y el ID de grupo del proceso que llama se mapeen a IDs de usuario e IDs de grupo en el espacio de nombres de usuario del proceso que llama en el momento de la llamada.
Para más información sobre los espacios de nombres de usuario, véase user_namespaces(7).
CLONE_NEWUTS (desde Linux 2.6.19)
Esta bandera tiene el mismo efecto que la bandera clone(2) CLONE_NEWUTS. Desagrupa el espacio de nombres IPC de UTS, de modo que el proceso que llama tenga una copia privada del espacio de nombres UTS que no se comparte con ningún otro proceso. El uso de CLONE_NEWUTS requiere la capacidad CAP_SYS_ADMIN.
CLONE_SYSVSEM (desde Linux 2.6.26)
Esta bandera revierte el efecto de la bandera clone(2) CLONE_SYSVSEM. Desagrupa los valores de ajuste de semáforos de System V (semadj), de modo que el proceso que llama tenga una nueva lista vacía de semadj que no se comparte con ningún otro proceso. Si este es el último proceso que tiene una referencia a la lista de semadj actual del proceso, entonces los ajustes en esa lista se aplican a los semáforos correspondientes, como se describe en semop(2).

Además, se pueden especificar CLONE_THREAD, CLONE_SIGHAND y CLONE_VM en flags si el llamador está en un solo hilo (es decir, no está compartiendo su espacio de direcciones con otro proceso o hilo). En este caso, estas banderas no tienen ningún efecto. (Tenga en cuenta también que especificar CLONE_THREAD implica automáticamente CLONE_VM, y especificar CLONE_VM implica automáticamente CLONE_SIGHAND). Si el proceso está multihilo, entonces el uso de estas banderas resulta en un error.

Si flags se especifica como cero, entonces unshare() no hace nada; no se realizan cambios en el contexto de ejecución del proceso que llama.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

EINVAL
Se especificó una máscara de bits inválida en flags.
EINVAL
Se especificó CLONE_THREAD, CLONE_SIGHAND o CLONE_VM en flags, y el llamador está multihilo.
EPERM
Se especificó una bandera de creación de espacio de nombres (CLONE_NEWCGROUP, CLONE_NEWIPC, CLONE_NEWNET, CLONE_NEWNS, CLONE_NEWPID, CLONE_NEWUSER, CLONE_NEWUTS, o CLONE_NEWTIME) pero el proceso que llama no tiene la capacidad requerida (normalmente CAP_SYS_ADMIN).
EUNSETENFORK
Se especificó CLONE_NEWPID, pero la característica de "un-set-en-fork" de los espacios de nombres PID no está habilitada en el kernel.

CONFORMIDAD CON POSIX

La llamada al sistema unshare() no forma parte de ninguna estándar de POSIX y solo está disponible en Linux.

ENOMEM
No se pudo asignar suficiente memoria para copiar partes del contexto del llamador que necesitan ser separadas.
ENOSPC (desde Linux 3.7)
Se especificó CLONE_NEWPID en flags, pero se habría excedido el límite de profundidad de anidamiento de los espacios de nombres PID; véase pid_namespaces(7).
ENOSPC (desde Linux 4.9; anteriormente EUSERS)
Se especificó CLONE_NEWUSER en flags, y la llamada habría excedido el límite del número de espacios de nombres de usuario anidados. Véase user_namespaces(7).
Desde Linux 3.11 hasta Linux 4.8, el error diagnosticado en este caso fue EUSERS.
ENOSPC (desde Linux 4.9)
Uno de los valores en flags especificó la creación de un nuevo espacio de nombres de usuario, pero hacerlo habría excedido el límite definido por el archivo correspondiente en /proc/sys/user. Para más detalles, véase namespaces(7).
EPERM
El proceso llamador no tenía los privilegios requeridos para esta operación.
EPERM
Se especificó CLONE_NEWUSER en flags, pero ni el ID de usuario efectivo ni el ID de grupo efectivo del llamador tienen un mapeo en el espacio de nombres padre (véase user_namespaces(7)).
EPERM (desde Linux 3.9)
Se especificó CLONE_NEWUSER en flags y el llamador se encuentra en un entorno chroot (es decir, el directorio raíz del llamador no coincide con el directorio raíz del espacio de nombres de montaje en el que reside).
EUSERS (desde Linux 3.11 hasta Linux 4.8)
Se especificó CLONE_NEWUSER en flags, y se habría excedido el límite del número de espacios de nombres de usuario anidados. Véase la discusión del error ENOSPC anterior.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.16.

NOTAS

No todos los atributos del proceso que se pueden compartir cuando se crea un nuevo proceso usando clone(2) se pueden separar usando unshare(). En particular, a partir del kernel 3.8, unshare() no implementa banderas que reviertan los efectos de CLONE_SIGHAND, CLONE_THREAD o CLONE_VM. Dicha funcionalidad puede añadirse en el futuro, si se requiere.

La creación de todo tipo de espacios de nombres, excepto los de usuario, requiere la capacidad CAP_SYS_ADMIN. Sin embargo, dado que la creación de un espacio de nombres de usuario confiere automáticamente un conjunto completo de capacidades, la creación de un espacio de nombres de usuario y cualquier otro tipo de espacio de nombres en la misma llamada a unshare() no requiere la capacidad CAP_SYS_ADMIN en el espacio de nombres original.

EJEMPLOS

El programa siguiente proporciona una implementación simple del comando unshare(1), que separa espacios de nombres y ejecuta el comando suministrado en sus argumentos de línea de comandos. Aquí hay un ejemplo de uso de este programa, ejecutando un shell en un nuevo espacio de nombres de montaje, y verificando que el shell original y el nuevo shell están en espacios de nombres de montaje separados:


$ readlink /proc/$$/ns/mnt;
mnt:[4026531840]
$ sudo ./unshare -m /bin/bash;
# readlink /proc/$$/ns/mnt;
mnt:[4026532325]

La salida diferente de los dos comandos readlink(1) muestra que los dos shells están en diferentes espacios de nombres de montaje.

Código fuente del programa

/* unshare.c
   Una implementación simple del comando unshare(1): separa
   espacios de nombres y ejecuta un comando.
*/
#define _GNU_SOURCE
#include <err.h>
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
static void
usage(char *pname)
{
    fprintf(stderr, "Uso: %s [opciones] programa [arg...]\n", pname);
    fprintf(stderr, "Las opciones pueden ser:\n");
    fprintf(stderr, "    -C   separar espacio de nombres cgroup\n");
    fprintf(stderr, "    -i   separar espacio de nombres IPC\n");
    fprintf(stderr, "    -m   separar espacio de nombres de montaje\n");
    fprintf(stderr, "    -n   separar espacio de nombres de red\n");
    fprintf(stderr, "    -p   separar espacio de nombres PID\n");
    fprintf(stderr, "    -t   separar espacio de nombres de tiempo\n");
    fprintf(stderr, "    -u   separar espacio de nombres UTS\n");
    fprintf(stderr, "    -U   separar espacio de nombres de usuario\n");
    exit(EXIT_FAILURE);
}
int
main(int argc, char *argv[])
{
    int flags, opt;
    flags = 0;
    while ((opt = getopt(argc, argv, "CimnptuU")) != -1) {
        switch (opt) {
        case 'C': flags |= CLONE_NEWCGROUP;     break;
        case 'i': flags |= CLONE_NEWIPC;        break;
        case 'm': flags |= CLONE_NEWNS;         break;
        case 'n': flags |= CLONE_NEWNET;        break;
        case 'p': flags |= CLONE_NEWPID;        break;
        case 't': flags |= CLONE_NEWTIME;       break;
        case 'u': flags |= CLONE_NEWUTS;        break;
        case 'U': flags |= CLONE_NEWUSER;       break;
        default:  usage(argv[0]);
        }
    }
    if (optind >= argc)
        usage(argv[0]);
    if (unshare(flags) == -1)
        err(EXIT_FAILURE, "unshare");
    execvp(argv[optind], &argv[optind]);
    err(EXIT_FAILURE, "execvp");
}
