DESCRIPCIÓN

Unbound es una implementación de un resolvedor DNS, que realiza caché y validación DNSSEC. Esta es la API de la biblioteca, para usar la biblioteca -lunbound. El demonio del servidor se describe en unbound(8). La biblioteca funciona de forma independiente de un servidor unbound en ejecución, y puede usarse para convertir nombres de host en direcciones IP, y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de claves públicas de los resultados con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Se puede crear y eliminar en cualquier momento. Crear una nueva elimina cualquier configuración previa (como claves de confianza) y borra cualquier resultado en caché.

Las funciones son seguras para hilos (thread-safe) y un contexto puede utilizarse en un entorno con hilos (así como en uno sin hilos). También la resolución (y la validación) se puede realizar de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve el control inmediatamente, para que el procesamiento pueda continuar, mientras los resultados están disponibles más tarde.

Las funciones se discuten a continuación, una por una.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza por defecto. Usa ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esta función, utiliza las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si utilizas lib openssl (la aplicación llama a estas funciones una vez para la inicialización). Openssl 1.0.0 o posterior utiliza la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y las devoluciones de llamada no se invocan para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que permite especificar una de las opciones del formato de archivo de configuración, consulta unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como añadir anclas de confianza, existen rutinas especiales. Pasa el nombre de la opción con los dos puntos finales ':'.
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene el valor de una opción. Algunas opciones no se pueden obtener, y otras devuelven una lista separada por saltos de línea. Pasa el nombre de la opción sin los dos puntos finales ':'. El valor devuelto debe ser liberado con free(2) por el llamante.
ub_ctx_config
Una interfaz para usuarios avanzados que permite especificar un archivo de configuración de unbound, consulta unbound.conf(5), que se lee para configurar. No todas las opciones son relevantes. Para algunas opciones específicas, como añadir anclas de confianza, existen rutinas especiales. Esta función solo es segura para hilos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no se llame en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se reenviarán las consultas DNS, el resolvedor de caché a utilizar. Dirección IP4 o IP6. Reenvía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolvedor recursivo. Si el proxy no es compatible con DNSSEC, la validación puede fallar. Se puede llamar varias veces, en cuyo caso las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible configurar antes de que se realice la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autoritativos a utilizar para una zona particular. Dirección IP4 o IP6. Si la dirección es NULL, se elimina la entrada stub. Establece isprime a true si configuras hints de raíz con ella. De lo contrario, es similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas, o para añadir varias direcciones para una zona particular. En este momento, solo es posible configurar antes de que se realice la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible configurar antes de que se realice la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolución completo, pero puedes usar esta llamada para leer la lista de servidores de nombres a utilizar desde el nombre de archivo dado. Normalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no soportan DNSSEC, la validación puede fallar. Solo se recogen los servidores de nombres, se ignoran el dominio de búsqueda, ndots y otras configuraciones de resolv.conf(5). Si se pasa NULL como fname, se usa "/etc/resolv.conf" (si en Windows, se selecciona el servidor de nombres configurado a nivel de sistema). En este momento, solo es posible configurar antes de que se realice la primera resolución.
ub_ctx_hosts
Lee la lista de hosts del nombre de archivo dado. Normalmente "/etc/hosts". Cuando se consultan, estas direcciones no se marcan como seguras por DNSSEC. Si se pasa NULL como fname, se usa "/etc/hosts" (si en Windows, se selecciona etc/hosts de WINDIR en su lugar). En este momento, solo es posible configurar antes de la primera resolución.
ub_ctx_add_ta
Añade un ancla de confianza. Los anclas de confianza son claves públicas para la validación DNSSEC. El formato es como en el archivo de configuración unbound.conf, una línea con el tipo de clave, el nombre de dominio, y el contenido de la clave. Puede ser llamado varias veces.
ub_ctx_add_ta_autr
Añade el contenido de un archivo que contiene anclas de confianza. El archivo debe contener claves en el formato apropiado, véase unbound.conf(5).
ub_ctx_add_ta_file
Añade las anclas de confianza desde un archivo. El archivo debe contener claves en el formato apropiado, véase unbound.conf(5).
ub_ctx_trustedkeys
Lee las claves de confianza del archivo especificado. Las claves de confianza son anclas de confianza para la validación DNSSEC. Si se llama varias veces, las claves de cada archivo se añaden a las existentes. El archivo debe contener claves en el formato apropiado, véase unbound.conf(5).
ub_ctx_debugout
Escribe los mensajes de depuración a un descriptor de archivo. Por defecto, stderr. Si se llama con NULL, se deshabilita la salida de depuración.
ub_ctx_debuglevel
Establece el nivel de depuración. Más alto es más detallado. El nivel 0 es silencioso. Los niveles más altos muestran más información.
ub_ctx_async
Si dothread es 1, usa hilos para resolver las consultas de forma asíncrona. Si dothread es 0, no usa hilos y la aplicación debe llamar a ub_poll y ub_process para manejar las consultas (esto es más cercano a un bucle de eventos). Si dothread es 2, usa el hilo de fondo del sistema operativo. Si dothread es 3, usa hilos y no inicia el hilo de fondo por defecto. El valor por defecto es 1 (usa hilos).
ub_poll
Espera a que haya actividad en los sockets de red. Devuelve la cantidad de descriptores de archivo listos para leer. Si devuelve 0, se debe llamar a ub_process para procesar los resultados. Si devuelve -1, hubo un error.
ub_wait
Espera a que haya actividad en los sockets de red, y luego llama a ub_process para procesar los resultados. Esto es para llamadas bloqueantes, y la función devuelve cuando se procesa una consulta.
ub_fd
Devuelve un descriptor de archivo (o el valor más alto si hay varios) que contiene la actividad de red para la que se está esperando. El usuario debe hacer un poll() o select() en este fd, y cuando esté listo, llamar a ub_process.
ub_process
Procesa los resultados de las consultas en curso. Esto se llama típicamente después de ub_poll o ub_wait. Para la operación asíncrona sin hilos, esta función debe ser llamada en el bucle de eventos cuando los descriptores de archivo indicados por ub_fd estén listos.
ub_resolve
Resuelve un nombre de host a direcciones IP, o realiza cualquier otra consulta DNS. Esto es una llamada bloqueante. Devuelve el resultado en la estructura ub_result. La memoria de esta estructura debe ser liberada por el usuario con ub_resolve_free. La función devuelve 0 en caso de éxito, y un código de error distinto de cero en caso de fallo. El mensaje de error se puede obtener con ub_strerror.
ub_resolve_async
Resuelve un nombre de host de forma no bloqueante (asíncrona). El resultado se pasará a la función callback proporcionada cuando esté disponible. Mydata es un puntero a datos definidos por el usuario, que se pasan a la función callback. Si la operación es exitosa, async_id se llena con un identificador único para esta operación. La función callback debe tener la firma ub_callback_type. Los tipos de registro (rrtype) y clase (rrclass) se pueden encontrar en /usr/include/netinet/dns.h. Si se utiliza la opción de hilo, la devolución de llamada se ejecutará en un hilo separado. Si se utiliza la opción sin hilo, la devolución de llamada se ejecutará en el hilo principal después de llamar a ub_process.
ub_cancel
Cancela una operación de resolución asíncrona dada por async_id.
ub_resolve_free
Libera la memoria usada por la estructura ub_result. Debe ser llamada después de que ya no se necesite el resultado.
ub_strerror
Devuelve una cadena que describe el código de error devuelto por las funciones de libunbound.
ub_ctx_print_local_zones
Imprime las zonas locales configuradas a la salida de depuración (ver ub_ctx_debugout).
ub_ctx_zone_add
Añade una zona local al contexto. zone_type puede ser 'overturn' o 'static'. 'overturn' es para zonas que se resuelven a sí mismas (por ejemplo, localhost), y 'static' es para zonas que se añaden al servidor DNS y se devuelven a los clientes.
ub_ctx_zone_remove
Elimina una zona local del contexto.
ub_ctx_data_add
Añade datos al contexto, se puede usar para zonas de datos.
ub_ctx_data_remove
Elimina datos del contexto.

FUNCTIONS

ub_ctx_create
Create a new context for the validating resolver. You must create a context before you can call any other unbound library functions. The context is used to keep track of state for DNS queries.
ub_ctx_destroy
Destroy the context and free all associated resources. All pending operations are cancelled.
ub_ctx_config
Load configuration from the given filename. This can be used to load the configuration from a file like unbound.conf(5). If the filename is NULL, default configuration is loaded.
ub_ctx_resolvconf
Load system resolver configuration from the given filename. On most systems this is /etc/resolv.conf. If the filename is NULL, the system default is used.
ub_ctx_set_fwd
Set forward zone. The zone is a domain name, the servers are a NULL terminated array of IP address strings. If zone is NULL, sets the global forward target. If servers is NULL, clears the forward target.
ub_ctx_add_stub
Add stub zone. The zone is a domain name, the servers are a NULL terminated array of IP address strings. If servers is NULL, clears the stub target.
ub_ctx_add_zone
Add a new zone to the local authority data. This is similar to the local-zone statement in unbound.conf(5). The zone name is a zero-terminated string. The zone type is an integer, e.g. 0 for a transparent zone, 1 for a deny-something zone, 2 for a redirect zone, etc. The state is enabled (1) or disabled (0). A negative zone type means use the default zone type (which is transparent).
ub_ctx_zone_add
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
ub_ctx_zone_remove
Delete zone from local authority info.
ub_ctx_data_add
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
ub_ctx_data_remove
Delete local authority data from the name given.
ub_ctx_add_ta
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
ub_ctx_add_ta_autr
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta_file
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_trustedkeys
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_debugout
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
ub_ctx_debuglevel
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
ub_ctx_async
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
ub_poll
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
ub_wait
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
ub_fd
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
ub_process
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
ub_resolve
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
ub_resolve_async
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

ub_cancel
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
ub_resolve_free
Free struct ub_result contents after use.
ub_strerror
Convert error value from one of the unbound library functions to a human readable string.
ub_ctx_print_local_zones
Debug printout the local authority information to debug output.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Else, they are not both true, one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.
