NOMBRE

uconv - convertir datos de una codificación a otra

SINOPSIS

uconv [ -h, -?, --help ] [ -V, --version ] [ -s, --silent ] [ -v, --verbose ] [ -l, --list | -l, --list-code código | --default-code | -L, --list-transliterators ] [ --canon ] [ -x transliteración ] [ --to-callback callback | -c ] [ --from-callback callback | -i ] [ --callback callback ] [ --fallback | --no-fallback ] [ -b, --block-size tamaño ] [ -f, --from-code codificación ] [ -t, --to-code codificación ] [ --add-signature ] [ --remove-signature ] [ -o, --output archivo ] [ archivo... ]

DESCRIPCIÓN

uconv convierte, o transcodifica, cada archivo dado (o su entrada estándar si no se especifica ningún archivo) de una codificación a otra. La transcodificación se realiza utilizando Unicode como codificación pivote (es decir, los datos se transcodifican primero de su codificación original a Unicode, y luego de Unicode a la codificación de destino).

Si no se especifica una codificación o es -, se utiliza la codificación predeterminada. Por lo tanto, llamar a uconv sin ninguna codificación proporciona una forma sencilla de validar y sanear archivos de datos para su posterior consumo por herramientas que requieren datos en la codificación predeterminada.

Al llamar a uconv, es posible especificar callbacks que se utilizan para manejar caracteres inválidos en la entrada, o caracteres que no se pueden transcodificar a la codificación de destino. Algunas codificaciones, por ejemplo, ofrecen un carácter de sustitución predeterminado que se puede usar para representar la ocurrencia de dichos caracteres en la entrada. Otros callbacks ofrecen una representación visual útil de los datos inválidos.

uconv también puede ejecutar la transliteración especificada en los datos transcodificados, en cuyo caso la transliteración ocurrirá como un paso intermedio, después de que los datos hayan sido transcodificados a Unicode. La transliteración puede ser una lista de nombres de transliteradores separados por punto y coma, o un conjunto arbitrariamente complejo de reglas en el formato de reglas de transliteración de ICU.

Para fines de transcodificación, las opciones de uconv son compatibles con las de iconv(1), lo que facilita su reemplazo en scripts. Sin embargo, no es necesariamente el caso de que los nombres de codificación utilizados por uconv e ICU sean los mismos que los utilizados por iconv(1). Además, las opciones que proporcionan datos informativos, como la opción -l, --list que ofrecen algunas variantes de iconv(1) como la de GNU, producen datos en un formato ligeramente diferente y más fácil de analizar.

OPCIONES

-h, -?, --help
Imprime ayuda sobre el uso y sale.
-V, --version
Imprime la versión de uconv y sale.
-s, --silent
Suprime mensajes durante la ejecución.
-v, --verbose
Muestra mensajes informativos adicionales durante la ejecución.
-l, --list
Lista todas las codificaciones disponibles y sale.
-l, --list-code código
Lista solo la codificación código y sale. Si código no es una codificación válida, sale con un error.
--default-code
Lista solo el nombre de la codificación predeterminada y sale.
-L, --list-transliterators
Lista todos los transliteradores disponibles y sale.
--canon
Si se usa con -l, --list o --default-code, la lista de codificaciones se produce en un formato compatible con convrtrs.txt(5). Si se usa con -L, --list-transliterators, imprime solo un nombre de transliterador por línea.
-x transliteración
Ejecuta la transliteración dada en los datos Unicode transcodificados, y utiliza los datos transliterados como entrada para la transcodificación a la codificación de destino.
--to-callback callback
Utiliza callback para manejar caracteres que no se pueden transcodificar a la codificación de destino. Consulte la sección CALLBACKS para obtener detalles sobre los callbacks válidos.
-c
Omite los caracteres inválidos de la salida. Igual que --to-callback skip.
--from-callback callback
Utiliza callback para manejar caracteres que no se pueden transcodificar desde la codificación original. Consulte la sección CALLBACKS para obtener detalles sobre los callbacks válidos.
-i
Ignora secuencias inválidas en la entrada. Igual que --from-callback skip.
--callback callback
Utiliza callback para manejar tanto los caracteres que no se pueden transcodificar desde la codificación original como los caracteres que no se pueden transcodificar a la codificación de destino. Consulte la sección CALLBACKS para obtener detalles sobre los callbacks válidos.
--fallback
Utiliza el mapeo de fallback al transcodificar de Unicode a la codificación de destino.
--no-fallback
No utiliza el mapeo de fallback al transcodificar de Unicode a la codificación de destino. Este es el comportamiento predeterminado.
-b, --block-size tamaño
Lee la entrada en bloques de tamaño bytes a la vez. El tamaño de bloque predeterminado es 4096.
-f, --from-code codificación
Establece la codificación original de los datos a codificación.
-t, --to-code codificación
Transcodifica los datos a codificación.
--add-signature
Agrega un carácter de firma Unicode U+FEFF (BOM) si el conjunto de caracteres de salida lo admite y no agrega uno de todos modos.
--remove-signature
Elimina un carácter de firma Unicode U+FEFF (BOM).
-o, --output archivo
Escribe los datos transcodificados en archivo.

CALLBACKS

uconv admite la especificación de callbacks para manejar datos inválidos. Los callbacks se pueden configurar para ambas direcciones de transcodificación: de la codificación original a Unicode, con la opción --from-callback, y de Unicode a la codificación de destino, con la opción --to-callback.

La siguiente es una lista de nombres de callback válidos, junto con una descripción de su comportamiento. La lista de callbacks realmente soportados por uconv se muestra cuando se llama con -h, --help.

substitute
Escribe la secuencia de sustitución de la codificación, o el carácter de reemplazo Unicode U+FFFD al transcodificar a Unicode.
skip
Ignora los datos inválidos.
stop
Detiene con un error al encontrar datos inválidos. Este es el callback predeterminado.
escape
Igual que escape-icu.
escape-icu
Escribe una secuencia de escape ICU para el carácter inválido. Por ejemplo, el carácter U+00E1 se representaría como \u00E1.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

CALLBACKS

escape-icu
Reemplaza los caracteres faltantes con una cadena del formato %Uhhhh para caracteres del plano 0, y %Uhhhh%Uhhhh para caracteres de planos 1 y superiores, donde hhhh es el valor hexadecimal de una de las unidades de código UTF-16 que representan el carácter. Los caracteres de planos 1 y superiores se escriben como un par de unidades de código sustitutas UTF-16.
escape-java
Reemplaza los caracteres faltantes con una cadena del formato \uhhhh para caracteres del plano 0, y \uhhhh\uhhhh para caracteres de planos 1 y superiores, donde hhhh es el valor hexadecimal de una de las unidades de código UTF-16 que representan el carácter. Los caracteres de planos 1 y superiores se escriben como un par de unidades de código sustitutas UTF-16.
escape-c
Reemplaza los caracteres faltantes con una cadena del formato \uhhhh para caracteres del plano 0, y \Uhhhhhhhh para caracteres de planos 1 y superiores, donde hhhh y hhhhhhhh son los valores hexadecimales del punto de código Unicode.
escape-xml
Igual que escape-xml-hex.
escape-xml-hex
Reemplaza los caracteres faltantes con una cadena del formato &#xhhhh;, donde hhhh es el valor hexadecimal del punto de código Unicode.
escape-xml-dec
Reemplaza los caracteres faltantes con una cadena del formato &#nnnn;, donde nnnn es el valor decimal del punto de código Unicode.
escape-unicode
Reemplaza los caracteres faltantes con una cadena del formato {U+hhhh}, donde hhhh es el valor hexadecimal del punto de código Unicode. Esa cadena hexadecimal es de longitud variable y puede usar de 4 a 6 dígitos. Este es el formato universalmente utilizado para denotar un punto de código Unicode en la literatura, delimitado por llaves para facilitar el reconocimiento de esas sustituciones en la salida.

EJEMPLOS

Convierte datos de una codificación dada a la codificación de la plataforma:

$ uconv -f codificación

Comprueba si un archivo contiene datos válidos para una codificación dada:

$ uconv -f codificación -c archivo >/dev/null

Convierte un archivo UTF-8 a una codificación dada y asegura que el texto resultante sea válido para cualquier versión de HTML:

$ uconv -f utf-8 -t codificación \
--callback escape-xml-dec archivo

Muestra los nombres de los puntos de código Unicode en un archivo UTF:

$ uconv -f utf-8 -x any-name archivo

Imprime el nombre de un punto de código Unicode cuyo valor se conoce (U+30AB en este ejemplo):

$ echo '\u30ab' | uconv -x 'hex-any; any-name'; echo
{KATAKANA LETTER KA}{LINE FEED}
$

(Los nombres están delimitados por llaves. Además, también se muestra el nombre del terminador de línea.)

Normaliza datos UTF-8 usando Unicode NFKC, elimina todos los caracteres de control y mapea Katakana a Hiragana:

$ uconv -f utf-8 -t utf-8 \
-x '::nfkc; [:Cc:] >; ::katakana-hiragana;'

ADVERTENCIAS Y ERRORES

uconv informa de los errores como si ocurrieran en el primer byte inválido encontrado. Esto puede ser confuso para los usuarios de GNU iconv(1), que informa de los errores como si ocurrieran en el primer byte de una secuencia inválida. Para conjuntos de caracteres o codificaciones multibyte, esto significa que las posiciones de error de uconv pueden estar en un desplazamiento posterior en el flujo de entrada de lo que sería el caso con GNU iconv(1).

El informe de las posiciones de error cuando se utiliza un transliterador puede ser inexacto o no estar disponible, en cuyo caso uconv informará del desplazamiento en el flujo de salida en el que ocurrió el error.
