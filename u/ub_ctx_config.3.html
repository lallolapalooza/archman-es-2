DESCRIPCIÓN

Unbound es una implementación de un resolvedor DNS, que realiza caché y validación DNSSEC. Esta es la API de la biblioteca, para usar la biblioteca -lunbound. El demonio del servidor se describe en unbound(8). La biblioteca funciona independientemente de un servidor unbound en ejecución y puede usarse para convertir nombres de host en direcciones IP y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de claves públicas de los resultados con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Puede crearse y eliminarse en cualquier momento. Crearla de nuevo elimina cualquier configuración previa (como claves de confianza) y borra cualquier resultado en caché.

Las funciones son seguras para hilos (thread-safe) y un contexto puede usarse en un entorno con hilos (así como en uno sin hilos). La resolución (y validación) también se puede realizar de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve la llamada inmediatamente, de modo que el procesamiento puede continuar mientras los resultados están disponibles más tarde.

Las funciones se discuten a continuación, una por una.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza por defecto. Use ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esto, use las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si usa lib openssl (la aplicación llama a estas funciones una vez para la inicialización). Openssl 1.0.0 o posterior usa la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y las devoluciones de llamada no se llaman para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que permite especificar una de las opciones del formato de archivo de configuración, ver unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclas de confianza, existen rutinas especiales. Pase el nombre de la opción con el ':' final.
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene un valor de opción. Algunas opciones no se pueden obtener y otras devuelven una lista separada por saltos de línea. Pase el nombre de la opción sin el ':' final. El valor devuelto debe ser liberado (free(2)) por el llamador.
ub_ctx_config
Una interfaz para usuarios avanzados que permite especificar un archivo de configuración de unbound, ver unbound.conf(5), que se lee para la configuración. No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclas de confianza, existen rutinas especiales. Esta función solo es segura para hilos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no se llame en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se reenviarán las consultas DNS, el resolvedor de caché a utilizar. Dirección IP4 o IP6. Reenvía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolvedor recursivo. Si el proxy no es compatible con DNSSEC, la validación puede fallar. Se puede llamar varias veces, en cuyo caso las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible configurar la configuración antes de que se realice la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autorizados a utilizar para una zona particular. Dirección IP4 o IP6. Si la dirección es NULL, se elimina la entrada stub. Establezca isprime en true si lo configura con pistas de raíz. De lo contrario, es similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas, o para agregar múltiples direcciones para una zona particular. En este momento, solo es posible configurar la configuración antes de que se realice la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible configurar la configuración antes de que se realice la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolución completa, pero puede utilizar esta llamada para leer la lista de servidores de nombres a utilizar desde el nombre de archivo proporcionado. Normalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no son compatibles con DNSSEC, la validación puede fallar. Solo se seleccionan los servidores de nombres; el dominio de búsqueda, ndots y otras configuraciones de resolv.conf(5) se ignoran. Si se pasa NULL como fname, se utiliza "/etc/resolv.conf" (si está en Windows, se selecciona el servidor de nombres configurado a nivel de sistema en su lugar). En este momento, solo es posible configurar la configuración antes de la primera resolución.
ub_ctx_hosts
Lee la lista de hosts desde el nombre de archivo proporcionado. Normalmente "/etc/hosts". Cuando se consultan, estas direcciones no se marcan como seguras con DNSSEC. Si se pasa NULL como fname, se utiliza "/etc/hosts" (si está en Windows, se selecciona etc/hosts de WINDIR en su lugar). NAME

libunbound - the unbound validating, recursive, caching DNS resolver library

SYNOPSIS

#include <unbound.h>

DESCRIPTION

The libunbound library implements the unbound validating, recursive, caching DNS resolver. It can be used by applications to perform DNS lookups that are verified and secure (DNSSEC).

This library can be used to implement DNS resolution within an application. It allows the application to configure its own stub resolver.

The library operates on contexts. A context holds the configuration and state of the resolver. You typically create a context, configure it with trust anchors and other options, and then use it to perform DNS lookups.

Lookups can be performed synchronously or asynchronously. Asynchronous lookups are recommended for most applications as they do not block the main application thread. Asynchronous lookups use callbacks or a file descriptor that can be polled.

FUNCTIONS

ub_ctx* ub_ctx_create(void);
Create a new unbound context. The context holds the configuration and state of the resolver. Returns a pointer to the context, or NULL on error (e.g. out of memory).
void ub_ctx_delete(ub_ctx* ctx);
Delete the unbound context and free all associated memory. Any outstanding asynchronous queries are cancelled.
int ub_ctx_config(ub_ctx* ctx, const char* fname);
Load configuration from a file. This file is typically unbound.conf. The configuration is appended to any existing configuration in the context. For details, see unbound.conf(5).
int ub_ctx_resolvconf(ub_ctx* ctx, const char* fname);
Load system nameserver configuration from a file. The file is typically /etc/resolv.conf. This can be used to get the upstream servers if you are not using root hints. If the file is NULL, it attempts to read the system default.
int ub_ctx_set_option(ub_ctx* ctx, const char* opt, const char* val);
Set an option in the context. Options are name-value pairs, where both are strings. For a list of options, see unbound.conf(5). The option value is copied. Returns 0 on success, and a non-zero error code on failure.
int ub_ctx_add_ta(ub_ctx* ctx, const char* ta);
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
int ub_ctx_add_ta_autr(ub_ctx* ctx, const char* fname);
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
int ub_ctx_add_ta_file(ub_ctx* ctx, const char* fname);
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
int ub_ctx_trustedkeys(ub_ctx* ctx, const char* fname);
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
void ub_ctx_debugout(ub_ctx* ctx, FILE* stream);
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
void ub_ctx_debuglevel(ub_ctx* ctx, int level);
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
void ub_ctx_async(ub_ctx* ctx, int enable_threading);
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
int ub_poll(ub_ctx* ctx);
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
void ub_wait(ub_ctx* ctx);
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
int ub_fd(ub_ctx* ctx);
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
void ub_process(ub_ctx* ctx);
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
int ub_resolve(ub_ctx* ctx, const char* name, int type, int class, struct ub_result** result);
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
int ub_resolve_async(ub_ctx* ctx, const char* name, int type, int class, void* mydata, void (*callback)(void*, int, struct ub_result*), int* async_id);
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

int ub_cancel(ub_ctx* ctx, int async_id);
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
void ub_resolve_free(struct ub_result* result);
Free struct ub_result contents after use.
const char* ub_strerror(int err);
Convert error value from one of the unbound library functions to a human readable string.
void ub_ctx_print_local_zones(ub_ctx* ctx);
Debug printout the local authority information to debug output.
int ub_ctx_zone_add(ub_ctx* ctx, const char* zone_name, int zone_type);
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
int ub_ctx_zone_remove(ub_ctx* ctx, const char* zone_name);
Delete zone from local authority info.
int ub_ctx_data_add(ub_ctx* ctx, const char* data_name, int data_type, const char* data_rdata);
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
int ub_ctx_data_remove(ub_ctx* ctx, const char* data_name);
Delete local authority data from the name given.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Else, they are not both true, one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.
