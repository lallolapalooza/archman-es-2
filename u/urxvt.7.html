¿Mi pregunta no está respondida aquí, puedo preguntar a un humano?

Antes de enviarme un correo, podrías ir a IRC: "irc.libera.chat", el canal "#rxvt-unicode" tiene algunos entusiastas de rxvt-unicode que podrían estar interesados en aprender sobre problemas nuevos y emocionantes (¡pero no FAQs!).

Uso Gentoo y tengo un problema...

Hay dos grandes problemas con Gentoo Linux: primero, la mayoría, si no todos, los sistemas Gentoo están completamente rotos (faltan o son incompatibles archivos de cabecera, compilador roto, etc. son solo la punta del iceberg); segundo, debería llamarse Gentoo GNU/Linux.

Por estas razones, es imposible dar soporte a rxvt-unicode en Gentoo. Los problemas que aparezcan en sistemas Gentoo generalmente serán ignorados a menos que puedan reproducirse en sistemas que no sean Gentoo.

¿Soporta pestañas, puedo tener un rxvt-unicode con pestañas?

A partir de la versión 7.3, hay una extensión de perl que implementa una simple terminal con pestañas. Se instala por defecto, así que cualquiera de estos comandos te dará pestañas:

urxvt -pe tabbed
URxvt.perl-ext-common: default,tabbed

También funcionará bien con la funcionalidad de pestañas de muchos gestores de ventanas o programas similares de pestañas, y sus características de incrustación permiten que se incruste en otros programas, como lo demuestran "doc/rxvt-tabbed" o el próximo módulo de perl "Gtk2::URxvt", que presenta una terminal urxvt con pestañas (murxvt) como ejemplo de aplicación de incrustación.

¿Cómo sé qué versión de rxvt-unicode estoy usando?

El número de versión se muestra con el uso (-h). También la secuencia de escape "ESC [ 8 n" establece el título de la ventana al número de versión. Al usar el cliente urxvtc, la versión que se muestra es la del demonio.

rxvt-unicode consume mucha memoria, ¿cómo puedo reducirla?

rxvt-unicode intenta cumplir la regla de no cobrarte por algo que no usas. Una cosa que deberías intentar es configurar y eliminar todas las configuraciones que no necesites. Por ejemplo, el soporte Xft es un consumidor de recursos por diseño, cuando se usa. Compilarlo para que no se incluya asegura que no se cargará accidentalmente ninguna fuente Xft cuando rxvt-unicode intente encontrar una fuente para tus caracteres.

Además, a mucha gente (incluido yo) le gustan las ventanas grandes y los búferes de desplazamiento aún más grandes: Sin "--enable-unicode3", rxvt-unicode usa 6 bytes por celda de pantalla. Para una ventana de 160x?? esto equivale a casi un kilobyte por línea. Un búfer de desplazamiento de 10000 líneas entonces (si está lleno) usará 10 Megabytes de memoria. Con "--enable-unicode3" empeora, ya que rxvt-unicode usa entonces 8 bytes por celda de pantalla.

¿Cómo puedo iniciar urxvtd de forma segura contra condiciones de carrera?

Prueba "urxvtd -f -o", que le dice a urxvtd que abra la pantalla, cree el socket de escucha y luego haga fork.

¿Cómo puedo iniciar urxvtd automáticamente cuando ejecuto urxvtc?

Si quieres iniciar urxvtd automáticamente cada vez que ejecutes urxvtc y el demonio aún no está en ejecución, usa este script:

#!/bin/sh
urxvtc "$@"
if [ $? -eq 2 ]; then
   urxvtd -q -o -f
   urxvtc "$@"
fi

Esto intenta crear una nueva terminal, y si falla con estado de salida 2, lo que significa que no pudo conectarse al demonio, iniciará el demonio y volverá a ejecutar el comando. Las invocaciones posteriores del script reutilizarán el demonio existente.

Otra opción es usar la activación basada en sockets de systemd (ver systemd.socket(5)). Aquí tienes un ejemplo de un archivo de unidad de servicio y de un archivo de unidad de socket para la ruta de socket por defecto:

urxvtd.service
[Unit]
Description=urxvt terminal daemon
Requires=urxvtd.socket
[Service]
ExecStart=/usr/bin/urxvtd -o
urxvtd.socket
[Unit]
Description=urxvt terminal daemon socket
[Socket]
ListenStream=%h/.urxvt/urxvtd-%H
[Install]
WantedBy=sockets.target

¿Cómo distingo si estoy ejecutando rxvt-unicode o un xterm regular? Necesito esto para decidir si establecer colores, etc.

El rxvt y rxvt-unicode originales siempre exportan la variable "COLORTERM", por lo que puedes verificar y ver si está configurada. Ten en cuenta que varios programas, JED, slrn, Midnight Commander, comprueban automáticamente esta variable para decidir si usar o no color.

¿Cómo establezco la dirección IP correcta y completa para la variable DISPLAY?

Si has compilado rxvt-unicode con DISPLAY_IS_IP y has habilitado el modo inseguro, entonces es posible usar los siguientes fragmentos de script de shell para establecer correctamente la pantalla. Si tu versión de rxvt-unicode tampoco fue compilada con ESCZ_ANSWER (como se asume en estos fragmentos) entonces la variable COLORTERM puede usarse para distinguir rxvt-unicode de un xterm regular.

Cortesía de Chuck Blake <cblake@BBN.COM> con los siguientes fragmentos de script de shell:

# Familia de shells Bourne/Korn/POSIX:
[ ${TERM:-foo} = foo ] && TERM=xterm # asumimos un xterm si no lo sabemos
if [ ${TERM:-foo} = xterm ]; then
   stty -icanon -echo min 0 time 15 # ver si es rxvt mejorado o no
   printf "\eZ"
   read term_id
   stty icanon echo
   if [ ""${term_id} = '^[[?1;2C' -a ${DISPLAY:-foo} = foo ]; then
      printf '\e[7n'        # preguntar al rxvt en el que estamos por la cadena DISPLAY
      read DISPLAY          # establecerla en nuestro shell local
   fi
fi

¿Cómo puedo compilar las páginas del manual por mi cuenta?

Necesitas tener una versión reciente de perl instalada como /usr/bin/perl, una que venga con pod2man, pod2text y pod2xhtml (de Pod::Xhtml). Luego ve al subdirectorio doc e introduce "make alldoc".

- section: title: Problemas de Renderizado, Fuentes y Aspecto Visual content: | * No puedo conseguir que la transparencia funcione, ¿qué estoy haciendo mal?

En primer lugar, la transparencia no está oficialmente soportada en rxvt-unicode, así que estás mayormente por tu cuenta. No molestes al autor al respecto (pero puedes molestar a todos los demás). Además, si no puedes conseguir que funcione, considéralo un rito de paso: ... y has fallado.

Aquí hay cuatro maneras de conseguir transparencia. Sí lee la página del manual y las descripciones de las opciones para los programas mencionados y rxvt-unicode. ¡De verdad, hazlo!

1. Usa pseudo-transparencia:

Esetroot wallpaper.jpg
urxvt -tr -tint red -sh 40

Eso funciona. Si crees que no funciona, te falta soporte de transparencia y tintado, o eres incapaz de leer. Este método requiere que el programa que establece el fondo establezca la propiedad _XROOTPMAP_ID o ESETROOT_PMAP_ID. Los programas compatibles son Esetroot, hsetroot y feh.

2. Usa un pixmap simple y emula la pseudo-transparencia. Esto te permite usar efectos distintos al tintado y sombreado: Simplemente sombrea/tiñe/lo que sea tu imagen con gimp o cualquier otra herramienta:

convert wallpaper.jpg -blur 20x20 -modulate 30 background.jpg
urxvt -pixmap "background.jpg;:root"

Eso funciona. Si crees que no funciona, te falta soporte de GDK-PixBuf, o eres incapaz de leer.

3. Usa una visualización ARGB:

urxvt -depth 32 -fg grey90 -bg rgba:0000/0000/4444/cccc

Esto requiere soporte XFT y el soporte de tu servidor X. Si eso no te funciona, busca un gestor de composición o un gestor de ventanas que funcione, ambos deben soportar visualizaciones ARGB para ventanas de cliente.

4. Usa xcompmgr y deja que haga el trabajo:

xprop -frame -f _NET_WM_WINDOW_OPACITY 32c \
            -set _NET_WM_WINDOW_OPACITY 0xc0000000

Luego haz clic en una ventana que quieras hacer transparente. Reemplaza 0xc0000000 por otros valores para cambiar el grado de opacidad. Si no funciona y tu servidor se bloquea, te quedas con los trozos.

* ¿Por qué rxvt-unicode a veces deja restos de píxeles?

La mayoría de las fuentes no fueron diseñadas para uso en terminal, lo que significa que el tamaño de los caracteres varía mucho. Una fuente que de otro modo sería buena para uso en terminal podría contener algunos caracteres que son simplemente demasiado anchos. Rxvt-unicode evitará estos caracteres. Para caracteres que son solo "un poco" anchos, se utiliza un modo de renderizado especial de "cuidado" que redibuja caracteres adyacentes.

Todo esto requiere que las fuentes no mientan sobre los tamaños de los caracteres, sin embargo: las fuentes Xft a menudo dibujan glifos más grandes que su caja delimitadora anunciada, y rxvt-unicode no tiene forma de detectar esto (la forma correcta es pedir la caja delimitadora del carácter, lo cual desafortunadamente es incorrecto en estos casos).

No está claro (al menos para mí), si esto es un error en Xft, freetype, o la fuente respectiva. Si encuentras este problema, puedes intentar usar la opción "-lsp" para darle más altura a la fuente. Si eso no funciona, podrías verte obligado a usar una fuente diferente.

Todo esto no es un problema cuando se usan fuentes base de X11, ya que sus datos de caja delimitadora son correctos.

* ¿Cómo puedo evitar que rxvt-unicode use video inverso tanto?

En primer lugar, asegúrate de que estás ejecutando con la configuración de terminal correcta ("TERM=rxvt-unicode"), lo que eliminará la mayoría de estos efectos. Luego, asegúrate de haber especificado colores para cursiva y negrita, ya que de lo contrario rxvt-unicode podría usar video inverso para simular el efecto:

URxvt.colorBD:  white
URxvt.colorIT:  green

* Algunos programas asumen colores totalmente extraños (rojo en lugar de azul), ¿cómo puedo solucionarlo?

Por alguna razón inexplicable, algunos programas raros asumen una paleta de colores muy extraña cuando se enfrentan a una terminal con más de los 8 colores estándar (rxvt-unicode soporta 88). La solución correcta es, por supuesto, corregir estos programas para que no asuman colores no ISO sin muy buenas razones.

Mientras tanto, puedes editar tu definición de terminfo de "rxvt-unicode" para que solo reclame soporte de 8 colores o usar "TERM=rxvt", lo que corregirá los colores pero te impedirá usar otras funciones de rxvt-unicode.

* ¿Puedo cambiar las fuentes en tiempo de ejecución?

Sí, usando una secuencia de escape. Prueba algo como esto, que tiene el mismo efecto que usar el modificador "-fn", y tiene efecto inmediatamente:

printf '\33]50;%s\007' "9x15bold,xft:Kochi Gothic"

Esto es útil si, por ejemplo, trabajas principalmente con japonés (y prefieres una fuente japonesa), pero tienes que cambiar temporalmente a chino, donde las fuentes japonesas solo te estorbarían.

Puedes pensar en esto como una especie de cambio manual ISO-2022.

* ¿Por qué los caracteres en cursiva parecen recortados?

Muchas fuentes tienen dificultades con los caracteres en cursiva y el hinting. Por ejemplo, la fuente "xft:Bitstream Vera Sans Mono", aunque muy bien detallada, falla por completo en su versión cursiva. Una solución podría ser habilitar el autohinting de freetype, es decir, así:

URxvt.italicFont:        xft:Bitstream Vera Sans Mono:italic:autohint=true
URxvt.boldItalicFont:    xft:Bitstream Vera Sans Mono:bold:italic:autohint=true

* ¿Puedo acelerar el renderizado de Xft de alguna manera?

Sí, la forma más obvia de acelerarlo es evitar Xft por completo, ya que es simplemente lento. Si aún deseas fuentes Xft, puedes intentar deshabilitar el suavizado (añadiendo ":antialias=false"), lo que ahorra mucha memoria y también acelera considerablemente el renderizado.

* Rxvt-unicode no parece suavizar sus fuentes, ¿qué está mal?

Rxvt-unicode usará lo que especifiques como fuente. Si necesita recurrir a su lista de búsqueda de fuentes predeterminada, preferirá las fuentes base de X11, porque son pequeñas y rápidas, y luego usará fuentes Xft. Tiene el suavizado deshabilitado para la mayoría de ellas, porque el autor piensa que se ven mejor de esa manera.

Si quieres suavizado, tienes que especificar las fuentes manualmente.

* ¿Qué pasa con este asunto del negrita/parpadeo?

Si no se establece ningún color en negrita a través de "colorBD:", la negrita invertirá el texto usando el color de primer plano estándar.

Para el color de fondo estándar, el parpadeo hará que el texto parpadee cuando se compile con "--enable-text-blink". Sin "--enable-text-blink", el atributo de parpadeo será ignorado.

En los colores ANSI, los atributos negrita/parpadeo se utilizan para establecer colores de primer plano/fondo de alta intensidad.

color0-7 son los colores de baja intensidad.

color8-15 son los colores de alta intensidad correspondientes.

* ¿Por qué algunos caracteres se ven tan diferentes de otros?

Ver la siguiente entrada.

* ¿Cómo elige rxvt-unicode las fuentes?

La mayoría de las fuentes no contienen el rango completo de Unicode, lo cual está bien. Es probable que la fuente que tú (o el administrador/mantenedor del paquete de tu sistema

tem/os) especificados no cubren todos los caracteres que deseas mostrar.

rxvt-unicode hace un intento por encontrar una fuente de reemplazo. A menudo el resultado es aceptable, pero a veces la fuente elegida se ve mal/fea/incorrecta. Algunas fuentes tienen caracteres totalmente extraños que no se parecen en nada a los glifos correctos, y rxvt-unicode carece de la inteligencia artificial para detectar que un glifo específico es incorrecto: tiene que creer que la fuente que afirma contener los caracteres los muestra correctamente.

En ese caso, selecciona una fuente de tu agrado y agrégala a la lista de fuentes, por ejemplo:

urxvt -fn basefont,font2,font3...

Cuando rxvt-unicode ve un carácter, primero buscará en la fuente base. Si la fuente base no contiene el carácter, pasará a la siguiente fuente, y así sucesivamente. Especificar tus propias fuentes también acelerará esta búsqueda y usará menos recursos dentro de rxvt-unicode y el servidor X.

La única limitación es que ninguna de las fuentes puede ser más grande que la fuente base, ya que la fuente base define el tamaño de la celda de caracteres de la terminal, que debe ser el mismo debido a la forma en que funcionan las terminales.

¿Por qué algunos caracteres chinos se ven tan diferentes a otros?

Esto se debe a que hay una diferencia entre escritura e idioma: rxvt-unicode no sabe qué idioma es el texto que se está generando, ya que solo conoce los códigos de caracteres unicode. Si rxvt-unicode primero ve un carácter japonés/chino, podría elegir una fuente japonesa para mostrarlo. Los caracteres japoneses subsiguientes usarán esa fuente. Ahora bien, muchos caracteres chinos no están representados en fuentes japonesas, por lo que cuando aparece el primer carácter no japonés, rxvt-unicode buscará una fuente china; desafortunadamente, en ese momento, seguirá usando la fuente japonesa para los caracteres chinos que también están en la fuente japonesa.

La solución es fácil: simplemente agrega una fuente china al final de tu lista de fuentes (ver la pregunta anterior). La clave es ver la lista de fuentes como una lista de preferencias: Si esperas más caracteres japoneses, coloca una fuente japonesa primero. Si esperas más caracteres chinos, coloca una fuente china primero.

En el futuro, podría ser posible cambiar las preferencias de idioma en tiempo de ejecución (la estructura de datos interna no tiene problemas para usar diferentes fuentes para el mismo carácter al mismo tiempo, pero aún no se ha diseñado una interfaz para esto).

Hasta entonces, podrías arreglártelas cambiando las fuentes en tiempo de ejecución (ver "¿Puedo cambiar las fuentes en tiempo de ejecución?" más adelante en este documento).

¿Cómo hago para que mplayer muestre video correctamente?

Estamos trabajando en ello, mientras tanto, como solución temporal, usa algo como:

urxvt -b 600 -geometry 20x1 -e sh -c 'mplayer -wid $WINDOWID file...'

¿Por qué el cursor ahora parpadea en emacs/vi/... ?

Esto probablemente sea causado por el uso que tu editor/programa hace de la capacidad de terminfo "cvvis". Emacs la usa por defecto, al igual que algunas versiones de vi y posiblemente otros programas.

En emacs, puedes desactivarla agregando esto a tu archivo ".emacs":

(setq visible-cursor nil)

Para otros programas, si no tienen una opción, deberás eliminar la capacidad "cvvis" de la descripción de terminfo.

Cuando urxvt agregó por primera vez la opción de cursor parpadeante, no agregó una capacidad "cvvis", que no tenía ningún propósito antes. La versión 9.21 introdujo "cvvis" (y la capacidad de controlar el parpadeo independientemente de la forma del cursor) para compatibilidad con otras terminales, que tradicionalmente usan un cursor parpadeante para "cvvis". Esto también refleja la intención de programas como emacs, que esperan que "cvvis" active un cursor parpadeante.

Teclado, Ratón & Interacción del Usuario

La nueva selección selecciona fragmentos demasiado grandes, ¿cómo puedo seleccionar palabras individuales?

Si deseas seleccionar, por ejemplo, palabras alfanuméricas, puedes usar la siguiente configuración:

URxvt.selection.pattern-0: ([[:word:]]+)

Si haces clic más de dos veces, la selección se extenderá cada vez más.

Para obtener una selección muy similar al código antiguo, prueba este patrón:

URxvt.selection.pattern-0: ([^"&'()*,;<=>?@[\\\\]^`{|})]+)

What is rxvt-unicode?

Version numbers are of the form "MM.DD.YYYY.Revision", where "MM" is the month, "DD" the day, "YYYY" the year of the release, and "Revision" is a 2-digit revision number starting with 00.

rxvt-unicode (urxvt) is a fork of rxvt that adds Unicode support. It also includes many other features and bug fixes.

Encoding / Locale / Input Method Issues

Rxvt-unicode does not seem to understand the selected encoding?

This is almost always a locale issue. Rxvt-unicode relies on the "LC_CTYPE" locale setting to determine the character encoding. Ensure your locale is set correctly and that rxvt-unicode is started with that same locale setting. See the next question.

Unicode does not seem to work?

Problems with character display, input, or program output often stem from incorrect locale settings. Rxvt-unicode needs to be started with the same "LC_CTYPE" setting as the applications running inside it.

A common issue is starting rxvt-unicode in the default "C" locale, while the login scripts or shell configuration change the locale to something like "en_GB.UTF-8". This mismatch causes problems.

The best solution is to fix your environment so that the locale is consistently set. You can try setting the locale explicitly in your ".profile" before starting rxvt-unicode, or use the following escape sequence to tell rxvt-unicode about the locale:

printf '\33]701;%s\007' "$LC_CTYPE"   # You might also try $LANG or $LC_ALL

If this doesn't resolve the issue, your system might not support the specified locale. You can check your system's supported locales using the "locale -a" command. If the output shows an error like:

locale: Cannot set LC_CTYPE to default locale: ...

Then the locale you're trying to use is not available on your system.

In rare cases, some older applications might not properly support locales, even if everything is configured correctly.

How does rxvt-unicode determine the encoding to use?

Rxvt-unicode uses the system's locale settings, specifically the "LC_CTYPE" environment variable, to determine the character encoding. It doesn't have its own internal encoding modes like some other terminals.

Is there an option to switch encodings?

Rxvt-unicode does not have a direct option to switch encodings like some other terminals (e.g., xterm). It relies entirely on the system's locale settings. The primary mechanism for handling different character sets is the locale system.

The locale setting, particularly "LC_CTYPE", informs both rxvt-unicode and the applications running within it about the correct character encoding, width, and properties. This ensures consistent interpretation of characters across the system.

Common locale names often follow the pattern "language_country.encoding" (e.g., "en_US.UTF-8", "de_DE.ISO-8859-15"). Rxvt-unicode primarily cares about the encoding part of the locale string.

To use a specific encoding, you must ensure that rxvt-unicode is started with the appropriate "LC_CTYPE" setting.

Can I switch locales at runtime?

Yes, you can change rxvt-unicode's interpretation of the locale using a specific escape sequence. This is useful when running applications that require different locale settings.

To set the locale, use:

printf '\33]701;%s\007' <locale_name>

For example, to switch to a Japanese SJIS locale:

printf '\33]701;%s\007' ja_JP.SJIS

This can be used in scripts to temporarily change the locale for specific applications. For instance, to run "xjdic" which might require a Japanese locale, and then switch back:

printf '\33]701;%s\007' ja_JP.SJIS

I have problems getting my input method working.

Getting input methods (IMs) to work correctly with rxvt-unicode can sometimes be tricky. Here’s a checklist and common issues:

- Ensure Locale Support:
Verify that both your primary locale (e.g., "LC_CTYPE") and the locale required by your input method (often called "imLocale") are supported on your operating system. Use "locale -a" to list available locales.
- Locale Compatibility:
Ensure that the locale used by your input method server is compatible with the one rxvt-unicode is using. For example, some older IM servers like "kinput2" might not support UTF-8 and require an older encoding like "ja_JP.EUC-JP".
- XIM Server Running:
Confirm that your X Input Method (XIM) server is actually running. You can often check this using tools like "xprop -root XIM_SERVERS".
- Environment Variables:
The "XMODIFIERS" environment variable is crucial. It tells the XIM system which input method server to use. Ensure it's set correctly *before* starting rxvt-unicode. For example:
export XMODIFIERS="@im=kinput2"  # For kinput2
export XMODIFIERS="@im=SCIM"     # For SCIM

My input method wants <some encoding> but I want UTF-8, what can I do?

You can configure rxvt-unicode to use a specific locale for the input method independently of the terminal's main locale setting using the "imlocale" resource. This is particularly useful if your input method server doesn't support UTF-8.

Add the following to your ".Xresources" file:

URxvt.imlocale: ja_JP.EUC-JP

With this setting, you can start rxvt-unicode with "LC_CTYPE=ja_JP.UTF-8" (or just let it use your system's default UTF-8 locale), and your input method will still function correctly using the specified "imlocale". However, be aware that this might limit the characters you can input if the input method's locale doesn't support all the characters you intend to use.

Rxvt-unicode crashes when the X Input Method changes or exits.

This is a known issue related to the X Input Method (XIM) protocol, which can be inherently unstable. Crashes can occur due to timing issues or improper handling of XIM events by either the terminal emulator or the input method server.

While developers strive to minimize these issues, completely eliminating crashes in all scenarios is difficult due to the protocol's design. Some input methods (like older versions of "kinput2") may handle exits more gracefully than others (like "SCIM").

The most reliable workaround is to avoid stopping or restarting your Input Method Server while rxvt-unicode is running.

Estoy en FreeBSD y rxvt-unicode no parece funcionar en absoluto.

Rxvt-unicode requiere que el símbolo "__STDC_ISO_10646__" esté definido en su entorno de compilación, o una implementación que lo implemente, ya sea que defina el símbolo o no. "__STDC_ISO_10646__" requiere que wchar_t se represente como unicode.

Como habrá adivinado, FreeBSD no define este símbolo ni lo soporta. En su lugar, utiliza su propia representación interna de wchar_t. Esto está, por supuesto, completamente bien con respecto a los estándares.

Sin embargo, eso significa que rxvt-unicode solo funciona en las localidades "POSIX", "ISO-8859-1" y "UTF-8" bajo FreeBSD (que todas usan Unicode como wchar_t).

"__STDC_ISO_10646__" es la única forma sensata de soportar aplicaciones multilingües en un SO, ya que usar una representación de wchar_t dependiente de la localidad (y no estandarizada) hace imposible la conversión entre wchar_t (tal como la usan X11 y sus aplicaciones) y cualquier otra codificación sin implementar envoltorios específicos del SO para cada una de las localidades. Simplemente no hay APIs para convertir wchar_t en nada más que la codificación de la localidad actual.

Algunas aplicaciones (como el formidable mlterm) lo solucionan llevando sus propias funciones de reemplazo para el manejo de conjuntos de caracteres, e implementando hacks dependientes del SO o realizando múltiples conversiones (lo que es lento y poco fiable en caso de que el SO implemente codificaciones ligeramente diferentes al emulador de terminal).

El autor de rxvt-unicode insiste en que la forma correcta de solucionar esto es en las bibliotecas del sistema de una vez por todas, en lugar de obligar a cada aplicación a llevar reemplazos completos para ellas :)

Mouse Reporting

When mouse reporting is enabled and none of the extended mouse modes (1005, 1006, 1015) is active, urxvt sends the following sequence on a mouse event:

"ESC [ M <b> <x> <y>"

The lower 2 bits of "<b>" indicate the button:

Button = "(<b> - SPACE) & 3"
0 Button1 pressed
1 Button2 pressed
2 Button3 pressed
3 button released (X11 mouse report)

The upper bits of "<b>" indicate the modifiers when the button was pressed and are added together (X11 mouse report only):

State = "(<b> - SPACE) & ~3"
4 Shift
8 Meta
16 Control
32 Motion Notify
32 Double Click (rxvt extension), disabled by default
64 Button1 is actually Button4, Button2 is actually Button5 etc.

"x" and "y" encode the coordinates (1|1 is the upper left corner, just as with cursor positioning):

Col = "<x> - SPACE"
Row = "<y> - SPACE"
Columna = "<x> - SPACE"
Fila = "<y> - SPACE"

Los parámetros incluyen un desplazamiento de 32 para asegurar que sean caracteres imprimibles.

Ejemplo: Pulsación del botón 1 con Shift en la fila superior, columna 80.

ESC [ M $ p !

La coordenada más grande que se puede representar en esta codificación es 223. El rango se puede extender usando uno de los modos de ratón extendidos, que deben habilitarse *antes* de habilitar el reporte del ratón, por razones que no son del todo obvias.

Modo 1005

Si el modo 1005 está activo, urxvt envía la secuencia

"ESC [ M <b> <x> <y>"

con las coordenadas proporcionadas como caracteres en la codificación de la configuración regional en lugar de octetos de 1 byte. Este modo no funciona de manera sensata en configuraciones regionales que no sean UTF-8 y, por lo tanto, debe evitarse.

Modo 1006

Si el modo 1006 está activo, urxvt envía las siguientes secuencias:

"ESC [ < <b>;<x>;<y> M"
pulsación de botón y movimiento
"ESC [ < <b>;<x>;<y> m"
liberación de botón

donde los parámetros se proporcionan como números decimales en lugar de octetos y no incluyen un desplazamiento de 32.

Los 2 bits inferiores de "b" codifican el número de botón también en la liberación del botón (en lugar del valor 3). El carácter final de la secuencia (M o m) especifica el tipo de evento (pulsación/movimiento o liberación).

Ejemplo: Pulsación del botón 1 con Shift en la fila superior, columna 80.

ESC [ < 4 ; 80 ; 1 M

Modo 1015

Si el modo 1015 está activo, urxvt envía la secuencia

"ESC [ <b>;<x>;<y> M"

donde los parámetros se proporcionan como números decimales en lugar de octetos y solo "b" incluye un desplazamiento de 32.

Ejemplo: Pulsación del botón 1 con Shift en la fila superior, columna 80.

ESC [ 36 ; 80 ; 1 M

OPCIONES DE CONFIGURE

Sugerencia general: si obtiene errores de compilación, es probable que su configuración no se haya probado bien. Intente con "--enable-everything" o use la configuración predeterminada (es decir, sin los modificadores "--enable-xxx" o "--disable-xxx"). Por supuesto, siempre debe informar cuando una combinación no funciona, para que pueda solucionarse. Marc Lehmann <rxvt@schmorp.de>.

Todo

--enable-everything
Añadir (o quitar) soporte para todas las opciones no multiselección listadas en "./configure --help", excepto "--enable-assert" y "--enable-256-color".

Puede especificar esto y luego deshabilitar las opciones que no le gustan *siguiéndolo* con los argumentos apropiados de "--disable-...", o puede comenzar con una configuración mínima especificando "--disable-everything" y luego añadiendo solo los argumentos de "--enable-..." que desee.

--enable-xft (predeterminado: activado)
Añadir soporte para fuentes Xft (con anti-aliasing, entre otras). Las fuentes Xft son
más lentas y requieren mucha memoria, pero mientras no las uses, no pagas por ellas.
--enable-font-styles (predeterminado: activado)
Añade soporte para los estilos de fuente en **negrita** *cursiva* y **_negrita cursiva_**. Las fuentes se pueden configurar manual o automáticamente.
--with-codesets=CS,... (predeterminado: all)
Compila soporte para grupos de juegos de códigos (codificaciones) adicionales ("eu", "vn" siempre se compilan, lo que incluye la mayoría de los conjuntos de caracteres de 8 bits). Estas tablas de juegos de códigos se utilizan para controlar las fuentes principales de X11; no son necesarias para las fuentes Xft, aunque tenerlas compiladas permite a rxvt-unicode elegir fuentes de reemplazo de forma más inteligente. Compilarlas hará que tu binario sea más grande (todas juntas cuestan unos 700 kB), pero no aumenta el uso de memoria a menos que uses una fuente que requiera una de estas codificaciones.
all todos los grupos de juegos de códigos disponibles
zh codificaciones comunes chinas

jp codificaciones comunes japonesas

kr codificaciones coreanas
--enable-xim (predeterminado: activado)
Añade soporte para el protocolo XIM (X Input Method). Esto permite usar métodos de entrada alternativos (p. ej., kinput2) y también configurará correctamente la entrada para personas que usan teclas muertas o teclas de composición.
--enable-unicode3 (predeterminado: desactivado)
Se recomienda dejarlo desactivado a menos que realmente necesites muchos caracteres no BMP.

Habilita el soporte para el almacenamiento directo de caracteres unicode por encima de 65535 (la página básica multilingüe). Esto aumenta los requisitos de almacenamiento por carácter de 2 a 4 bytes. Las fuentes X11 aún no soportan estos caracteres adicionales, pero Xft sí.

Ten en cuenta que rxvt-unicode puede almacenar y mostrar caracteres unicode por encima de 65535 incluso sin esta opción, pero el número de dichos caracteres se limita a unos pocos miles (compartido con caracteres combinados, ver el siguiente interruptor).

--enable-combining (predeterminado: activado)
Habilita la composición automática de caracteres combinados en caracteres compuestos. Esto es necesario para ver correctamente texto donde los acentos se codifican como caracteres unicode separados. Esto se hace usando caracteres precompuestos cuando están disponibles o creando nuevos pseudocaracteres cuando no existe una forma precompuesta.

Sin "--enable-unicode3", el número de caracteres precompuestos adicionales es algo limitado (se usarán (mal) los 6400 caracteres de uso privado). Con "--enable-unicode3", no existe un límite práctico.

Esta opción también habilitará el almacenamiento (pero no la visualización) de caracteres más allá del plano 0 (>65535) cuando no se especificó "--enable-unicode3".

La tabla de combinaciones también contiene entradas para formas de presentación árabe, pero estas no se utilizan actualmente. Contáctame si quieres que se usen (y dime cómo se deben usar...).

Añade soporte para GDK-PixBuf para ser usado en imágenes de fondo. Añade soporte para muchos formatos de archivo incluyendo JPG, PNG, TIFF, GIF, XPM, BMP, ICO y TGA.

CONFIGURE OPTIONS

These options are used when configuring the source, typically run from the top of the source tree:

--enable-fallback-pipe
Enable the fallback pipe implementation, which is used on systems that don't support the POSIX pipe2() system call and when the default pipe() implementation is not sufficient.
--enable-selection-wrap
Enable the selection wrap behaviour, which is useful when copying text from one application to another.
--enable-wide-chars
Enable wide character support, which is necessary for handling characters that require more than one byte of storage (e.g. UTF-8). This is generally recommended, as it allows urxvt to display a wider range of characters and supports internationalization better. However, it may result in higher memory usage and can slow down urxvt dramatically when more than six fonts are in use by a terminal instance.

It also results in higher memory usage and can slow down urxvt dramatically when more than six fonts are in use by a terminal instance.

--with-name=NAME (default: urxvt)
Set the basename for the installed binaries, resulting in "urxvt", "urxvtd" etc.). Specify "--with-name=rxvt" to replace with "rxvt".
--with-term=NAME (default: rxvt-unicode)
Sets the default "TERM" value that urxvt sets. The default is either "rxvt-unicode" or "rxvt-unicode-256color", as appropriate.
--with-terminfo=PATH
If set, urxvt will set the environment variable "TERMINFO" to the given PATH, which can be useful as a last resort if installing the terminfo entries system-wide is not possible.
--with-x
Use the X Window System (pretty much default, eh?).
