UPSLOG(8) Manual NUT UPSLOG(8)

NOMBRE

upslog - registrador de estado de UPS

SINOPSIS

upslog -h

upslog [OPCIONES]

DESCRIPCIÓN

upslog es un demonio que consultará una UPS a intervalos periódicos, obtendrá las variables que le interesen, las formateará y las escribirá en un archivo.

La cadena de formato predeterminada incluye variables que son compatibles con muchos modelos de UPS comunes. Consulte la descripción a continuación para crear la suya.

OPCIONES

-f formato

Monitorea la UPS usando esta cadena de formato. Asegúrese de encerrar formato entre comillas para que su shell no lo divida. Las secuencias de escape válidas dentro de esta cadena son:

%%

Inserta un único "%"

%t

Inserta un único carácter TAB (como printf("\t"))

%TIME formato%

Inserta la hora con formato strftime

%ETIME%

Inserta el número de segundos desde el inicio de "Epoch", tipo time_t. Este es ahora un número de 10 dígitos.

%HOST%

Inserta el nombre de host local

%UPSHOST%

Inserta el host de la UPS que se está monitoreando (la parte <system> de su especificación de registro, p. ej., ups[@host[:puerto]])

%PID%

Inserta el PID del propio upslog

%VAR varname%

Inserta el valor de la variable varname (consulte la documentación del desarrollador de NUT, capítulo "Variables", en línea o en el archivo docs/nut-names.txt en las fuentes de la versión de NUT que tiene instalada para más detalles)

La cadena de formato predeterminada es:

%TIME @Y@m@d @H@M@S% %VAR battery.charge% %VAR input.voltage%
%VAR ups.load% [%VAR ups.status%] %VAR ups.temperature%
%VAR input.frequency%

-N

Prefija %UPSHOST%%t antes de la cadena de formato (ya sea predeterminada o personalizada). Útil al registrar varios sistemas en el mismo destino.

Nota
Actualmente, esta opción NO verifica si ya tiene %UPSHOST% en la cadena de formato (por ejemplo, especificado explícitamente).

-i intervalo

Espera esta cantidad de segundos entre sondeos. Esto predetermina en 30 segundos.

Si requiere una temporización más precisa, considere escribir su propio registrador utilizando la biblioteca upsclient(3).

-d contador

Sale después de la cantidad de actualizaciones especificada. El valor predeterminado es 0 para un bucle infinito (hasta que se interrumpa de otra manera).

-l archivo_log

Almacena los resultados en este archivo.

Puede usar - para stdout, pero upslog permanecerá en primer plano por defecto.

Requiere que la opción -s <system> también se utilice para el registro de un solo sistema.

Se puede usar con -m <tupla>, se agregará a la lista.

-D

Aumenta el nivel de verbosidad de depuración en uno; upslog permanecerá en primer plano por defecto.

-F

upslog se ejecutará en primer plano, independientemente del destino del registro.

-B

upslog se ejecutará en segundo plano, independientemente del destino del registro o la depuración.

-s ups

Monitorea esta UPS. El formato para esta opción es upsname[@hostname[:puerto]]. El nombre de host predeterminado es "localhost".

El upsname puede ser un asterisco * para consultar UPS que actualmente son atendidas por hostname, y monitorearlas cada una (dentro del mismo destino de registro).

Requiere que la opción -l <archivo_log> también se utilice para el registro de un solo sistema.

Se puede usar con -m <tupla>, se agregará a la lista.

-m tupla

Monitorea múltiples UPS (se proporcionan varias instancias de dicha opción).

El formato para esta opción es una tupla de especificación del sistema UPS y del archivo de registro, separadas por comas. Un ejemplo sería:

upsname@hostname:9999,/var/log/nut/cps.log

El upsname puede ser un asterisco * para consultar UPS que actualmente son atendidas por hostname, y monitorearlas cada una (dentro del mismo destino de registro).

Las tuplas pueden especificar - como archivo de registro, para emitir mensajes en stdout (p. ej., para ser recopilados por el journal del sistema para servicios).

El uso de stdout a través de especificaciones de registro basadas en tuplas también implica que upslog permanecerá en primer plano por defecto.

-u nombre_usuario

Si se inicia como root, upslog usará setuid(2) al id de usuario asociado con nombre_usuario por seguridad.

Si nombre_usuario no está definido, usará el valor que se compiló en el programa. Esto predermina en nobody (si no se configuró de otra manera), lo cual está lejos de ser ideal.

OPCIONES COMUNES

-h

Muestra el mensaje de ayuda de la línea de comandos.

-V

Muestra el banner de la versión de NUT. Más detalles pueden estar disponibles si también exporta NUT_DEBUG_LEVEL=1 o un nivel de verbosidad mayor.

-W secs

Establece el tiempo de espera para las conexiones de red iniciales (por defecto son indefinidamente no bloqueantes, o hasta que el sistema interrumpe el intento). Anula la variable de entorno opcional NUT_DEFAULT_CONNECT_TIMEOUT.

RETRASOS DEL SERVICIO

El valor del intervalo es simplemente el número dado a sleep(3) después de ejecutar la cadena de formato. Por lo tanto, una consulta tomará realmente un poco más que el intervalo, dependiendo de la velocidad de su sistema.

REGISTRO BAJO DEMANDA

Enviar una señal SIGUSR1 a un proceso upslog en ejecución hace que despierte del sueño actual y registre inmediatamente. Esto es útil cuando se activa desde un disparador de evento de upssched (p. ej., AT ONBATT o AT ONLINE) para garantizar que siempre exista una entrada, incluso si la alimentación se interrumpe por un período de tiempo más corto que el especificado por el argumento -i.

CO-UBICACIÓN DE REGISTROS

Es posible y seguro especificar el mismo archivo de registro (incluido - para stdout) en varias tuplas, y solo se abrirá o cerrará una vez sin conflictos.

Considere agregar %UPSHOST% a su cadena de formato personalizada (p. ej., usando la opción de línea de comandos -N), para diferenciar fácilmente las líneas correspondientes a diferentes sistemas, cuando se registran en el mismo destino.

ROTACIÓN DE REGISTROS

upslog escribe su PID en upslog.pid, y reabrirá el archivo de registro si le envía una SIGHUP. Esto le permite seguir ejecutándose cuando el registro es rotado por un programa externo.

CONSIDERACIONES

Históricamente, este demonio admitía el registro de datos para un sistema UPS por ejecución (especificado por la opción -s) en un nombre de archivo de registro o stdout (especificado por la opción -l).

Desde NUT v2.8.1, permitía registrar varios dispositivos (cada uno registrado en su archivo de destino individual o stdout común) según lo especificado por múltiples opciones de tupla -m. Pero los dos modos eran efectivamente exclusivos entre sí (las opciones de UPS única se ignoraban si también se proporcionaban tuplas).

Desde NUT v2.8.3, las opciones de UPS única se agregan a la lista de tuplas, por lo que tanto las opciones heredadas como las nuevas se pueden utilizar de manera confiable para monitorear varios dispositivos en la misma ejecución.

upssched(8) — Network UPS Tools 2.8.4

NAME

upssched

Scheduler for the NUT server

SYNOPSIS

upssched [ ... ]

DESCRIPTION

This is the manual page for the upssched daemon. It handles the scheduling of actions based on events that occur with the UPS systems managed by upsd(8).

The upssched daemon reads its configuration from the /etc/ups/upssched.conf file.

This daemon is not typically started by the user, but rather by the system's startup scripts when the NUT package is installed.

The configuration file format is:

  • ACTION @ SERVER[:PORT] [USER]:[PASSWORD] UPS [DEVICE] [DEVICE_TYPE] [EVENT] [DELAY]

Where:

ACTION
The command to execute. This can be a full path to an executable, or a script name. The command will be executed with arguments specified later in the line.
SERVER
The hostname or IP address of the upsd server to connect to. If not specified, defaults to localhost.
PORT
The port number of the upsd server. If not specified, defaults to 3052.
USER
The username to log in to upsd as. If not specified, defaults to root.
PASSWORD
The password to log in to upsd as. If not specified, no password will be used.
UPS
The name of the UPS device to monitor. This is the name that appears in the upsd configuration.
DEVICE
Optional. The device name associated with the UPS. This is typically the serial port or USB device path. If not specified, it is taken from the upsd configuration.
DEVICE_TYPE
Optional. The type of the device (e.g., usb, serial). If not specified, it is taken from the upsd configuration.
EVENT
The event that triggers the action. Possible events include:
  • ONLINE: The UPS is online.
  • OFFLINE: The UPS is offline.
  • LOADAVG: The load average has exceeded a threshold.
  • LOWBATT: The battery is low.
  • BATTFROZEN: The battery is frozen (temperature too low).
  • BATTRECHG: The battery is recharging.
  • CAPDOWN: The UPS is entering a low capacity state.
  • COMMPD: Communication lost with the UPS.
  • COMMOK: Communication restored with the UPS.
  • OVERLOAD: The UPS is overloaded.
  • REMOTE: A remote command has been issued.
  • STARTTOTEST: Initiate a battery test.
  • ENDTOTEST: End a battery test.
  • TESTFAILED: The battery test failed.
  • RESET: The UPS has been reset.
  • KILLPOWER: The UPS has been instructed to kill power.
  • DELAY: A delay has occurred.
  • CHGB: Battery charge reached high limit.
  • CHGL: Battery charge reached low limit.
  • TIMELEFT: Estimated runtime is low.
  • FIRMWARE: UPS firmware has been updated.
  • UPGRADE: UPS firmware upgrade in progress.
  • NEWBATT: A new battery has been installed.
  • USERVAR: A user-defined variable has changed.
DELAY
Optional. The number of seconds to wait before executing the action. This is useful for events like LOWBATT to allow the UPS to recover before initiating a shutdown. If not specified, defaults to 0 seconds.

The action command will be executed with the following arguments:

  • $UPSNAME: The name of the UPS.
  • $EVENT: The event that triggered the action.
  • $VALUE: The value associated with the event (e.g., load percentage for LOADAVG, time left for TIMELEFT).
  • $DEVICE: The device name of the UPS.
  • $DEVICE_TYPE: The device type of the UPS.

For example, a typical shutdown script might be configured as follows:

    /sbin/upsdrvctl shutdown

Or, to send an email notification on low battery:

    /usr/bin/mail -s "UPS Low Battery Alert" admin@example.com < /var/log/ups/ups.log

OPTIONS

The upssched daemon does not accept any command-line options.

COMMON OPTIONS

See upsd(8) for common options related to the upsd server.

SERVICE DELAYS

The upssched daemon can be configured to delay actions based on specific events. This is useful for preventing unnecessary actions, such as initiating a shutdown when the UPS only briefly loses power.

The delay is specified in seconds as the last argument on the line in the upssched.conf file.

ON-DEMAND LOGGING

The upssched daemon supports on-demand logging of events. This allows you to log specific events without having to manually parse the upsd logs.

To enable on-demand logging, add the following line to your upssched.conf file:

    LOG_ON_DEMAND

When this option is enabled, upssched will log any events that are not explicitly configured with an action. This can be useful for debugging and monitoring.

LOG CO-LOCATION

The upssched daemon can be configured to co-locate log entries with their corresponding events. This means that all log entries related to a specific event will be grouped together in the log file.

To enable log co-location, add the following line to your upssched.conf file:

    LOG_CO_LOCATION

When this option is enabled, upssched will add a tag to each log entry indicating the event it is associated with. This can make it easier to track down the cause of specific problems.

LOG ROTATION

The upssched daemon supports log rotation to prevent log files from growing too large. This is essential for systems that are expected to run for extended periods.

To enable log rotation, add the following lines to your upssched.conf file:

    LOG_SIZE 102400  # Rotate logs when they reach 100MB
    LOG_COUNT 5      # Keep up to 5 rotated log files

The LOG_SIZE option specifies the maximum size of the log file in bytes. The LOG_COUNT option specifies the number of rotated log files to keep.

CAVEATS

The upssched daemon relies on the upsd server to provide event information. If upsd is not running or is not configured correctly, upssched will not be able to function.

Ensure that the actions specified in your upssched.conf file are executable by the user running upssched (typically root).
