NOMBRE

udpxy - un demonio de retransmisión de tráfico multicast de UDP a HTTP.

SINOPSIS

udpxy [-vTS] [-a <direcciónescucha>] [-m <direccióninterfazmulticast>] [-c <clientes>] [-l <archivolog>] [-B <tamañoK>] [-R <mensajes>] [-H <seg>] [-n <incremento_nice>] [-M <seg>] -p <puerto>

DESCRIPCIÓN

udpxy es un demonio de retransmisión de tráfico multicast de UDP a HTTP: reenvía el tráfico UDP de una suscripción multicast dada a liente HTTP solicitante.

udpxy escucha (en una dirección/puerto dedicado) las solicitudes HTTP emitidas por los clientes. Una solicitud de cliente debe estructurarse como:

http://{dirección}:{puerto}/{comando}/{direccióngrupo_multicast}[SEP]{puertogrupo_multicast}

[SEP]
:|%|~|+|-|^
{comando}
udp|rtp

donde dirección y puerto coinciden con la combinación de dirección/puerto de escucha de udpxy, y direccióngrupo_multicast:puertogrupo_multicast identifican el grupo/canal multicast al que suscribirse.

udp
el comando udp hará que udpxy sonde los tipos conocidos de carga útil (como MPEG-TS y RTP sobre MPEG-TS);
rtp
el comando rtp hace que udpxy asuma la carga útil de RTP sobre MPEG-TS, omitiendo así las sondas.

udpxy iniciará un proceso cliente separado para cada nueva solicitud de retransmisión (dentro del límite especificado de clientes activos). El proceso cliente retransmitirá/reenviará todo el tráfico de red recibido (a través de un socket UDP) desde el grupo multicast especificado a la conexión HTTP solicitante.

udpxy también admite algunas solicitudes administrativas:

estado
http://dirección:puerto/estado/ para devolver una página HTML con el estado del demonio y estadísticas de clientes.
reiniciar
http://dirección:puerto/reiniciar/ para cerrar todas las conexiones activas y reiniciar.

EJEMPLOS

http://192.168.0.12:5056/udp/224.0.2.26:24012

http://192.168.0.12:5056/rtp/224.0.2.26:24012

http://192.168.0.15:5056/rtp/224.0.2.26^24055

http://192.168.0.15:5056/status/

OPCIONES

udpxy acepta las siguientes opciones:

-v
Habilitar salida detallada [por defecto = deshabilitado].
-S
Habilitar estadísticas de clientes [por defecto = deshabilitado].
-T
NO ejecutar como demonio [por defecto = demonio si es root].
-a <direcciónescucha>
Dirección/interfaz IPv4 en la que escuchar [por defecto = 0.0.0.0].
-m <direccióninterfazmulticast>
Dirección/interfaz IPv4 de la fuente (multicast) [por defecto = 0.0.0.0].
-c <clientes>
Número máximo de clientes a aceptar [por defecto = 3, máx = 5000].
-l <archivolog>
Registrar salida en archivo [por defecto = stderr].
-B <tamañoK>
Tamaño del búfer (65536, 32Kb, 1Mb) para datos entrantes (multicast) [por defecto = 2048 bytes].
-R <mensajes>
Número máximo de mensajes a almacenar en búfer (-1 = todos) [por defecto = 1].
-H <seg>
Tiempo máximo (en segundos) para mantener los datos en un búfer (-1 = ilimitado) [por defecto = 1].
-n <incremento_nice>
Incremento del valor nice [por defecto = 0].
-M <seg>
Renovar la suscripción multicast cada M segundos (omitir si es 0) [por defecto = 0].
-p <puerto>
Puerto en el que escuchar.

TIPOS DE CARGA ÚTIL Y MANEJO

udpxy reconoce las cargas útiles MPEG-TS y RTP sobre MPEG-TS dentro de los paquetes retransmitidos; si udpxy encuentra una carga útil RTP, automáticamente la 'traduce' a MPEG-TS (eliminando las cabeceras RTP) para que los reproductores multimedia que no reconocen RTP puedan reproducir la transmisión.

Hasta ahora, no se realiza ninguna traducción para otros tipos de carga útil.

GRABACIÓN DE TRÁFICO MPEG

udpxy incluye funcionalidad para grabar el tráfico capturado como un flujo MPEG-TS crudo en un archivo. Esta funcionalidad se habilita a través de udpxrec: una aplicación incluida que se enlaza junto con udpxy (como un solo ejecutable).

udpxrec se invoca a través de un enlace simbólico (llamado udpxrec) al ejecutable udpxy (es decir, no renombrar el ejecutable udpxy).

udpxrec crea archivos MPEG que encapsulan segmentos MPEG-TS; ciertos reproductores multimedia NO reproducirán dichos archivos; para hacerlos reproducibles, la transmisión debe ser transcodificada a MPEG-PS; vlc 'sabe' cómo realizar dicha transcodificación, aquí hay un ejemplo de línea de comandos:

vlc input-ts.mpg --sout="#std{access=file,mux=ps,dst=out-ps.mpg}"

El archivo MPEG-PS resultante puede ser reproducido por la mayoría de los reproductores multimedia.

ENTORNO

udpxy utiliza las siguientes variables de entorno para complementar sus opciones de línea de comandos; las variables se consideran para las opciones que la mayoría de las personas no necesitarían cambiar con frecuencia (o que simplemente son inconvenientes de usar desde la línea de comandos).

NB: Si hay un interruptor de línea de comandos que interfiere funcionalmente con una variable de entorno, el interruptor tiene siempre mayor prioridad.

UDPXY_RCV_TMOUT
tiempo de espera (seg) en el flujo de datos entrante (multicast), por defecto=5;
UDPXY_DHOLD_TMOUT
tiempo de espera (seg) para mantener los datos en búfer antes de enviarlos/vacíarlos al(os) cliente(s), por defecto=1;
UDPXY_SREAD_TMOUT
tiempo de espera (seg) para leer del socket de escucha (manejo de solicitudes HTTP), por defecto=1;
UDPXY_SWRITE_TMOUT
tiempo de espera (seg) para escribir en el socket de escucha (manejo de solicitudes HTTP), por defecto=1;
UDPXY_SSEL_TMOUT
tiempo de espera (seg) para select(2) en el bucle del servidor (no utilizado si se emplea pselect(2)), por defecto=30;
UDPXY_LQ_BACKLOG
tamaño del backlog del socket del oyente, por defecto=16;
UDPXY_SRV_RLWMARK
marca de agua baja en el socket de recepción (m-cast), por defecto=0 (no establecida);

ENVIRONMENT

UDPXY_LOG_DST
sets the destination for log messages (default=stderr). Can be a filename or a network destination (e.g. udp:127.0.0.1:12345).
UDPXY_LOG_LEVEL
sets the logging level. Possible values are: err, warning, info, debug (default=info).
UDPXY_MAX_CONNECTIONS
maximum number of client connections (default=1024).
UDPXY_BIND_ADDRESS
set the address to bind to. By default it is bound to all interfaces.
UDPXY_GROUP_JOIN
join the specified multicast group (e.g. 239.1.1.1).
UDPXY_GROUP_IFACE
set the interface to use for joining the multicast group.
UDPXY_UDP_SO_RCVBUF
set the SO_RCVBUF size for the UDP socket (default=65536).
UDPXY_UDP_SO_SNDBUF
set the SO_SNDBUF size for the UDP socket (default=65536).
UDPXY_TCP_SO_RCVBUF
set the SO_RCVBUF size for the TCP socket (default=16384).
UDPXY_TCP_SO_SNDBUF
set the SO_SNDBUF size for the TCP socket (default=16384).
UDPXY_BUFFER_SIZE
set the size of the internal buffer for data processing. Default is set by -B option, default=1 (sync);
UDPXY_TCP_NODELAY
disable the Nagle algorithm on the newly accepted socket (faster channel switching), default=1;
UDPXY_HTTP200_FTR_FILE
append the contents of the given text file to the HTTP 200 response, default=none;
UDPXY_HTTP200_FTR_LN
append the text (line) to the HTTP 200 response, default=none;
UDPXY_ALLOW_PAUSES
if blocked on a write(2), keep reading data until the buffer (-B <sizeK>) is full, default=disabled;
UDPXY_PAUSE_MSEC
allow only N milliseconds of reading data when blocked on a write(2).
UDPXY_CONTENT_TYPE
specify custom Content-Type in HTTP responses.
