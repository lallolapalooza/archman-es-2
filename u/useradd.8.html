USERADD(8) Comandos de Administración del Sistema USERADD(8)

NOMBRE

useradd - crear un nuevo usuario o actualizar la información por defecto de un nuevo usuario

SINOPSIS

useradd [opciones] USUARIO

useradd -D

useradd -D [opciones]

DESCRIPCIÓN

Cuando se invoca sin la opción -D, el comando useradd crea una nueva cuenta de usuario utilizando los valores especificados en la línea de comandos más los valores predeterminados del sistema. Dependiendo de las opciones de la línea de comandos, el comando useradd actualizará los archivos del sistema y también podrá crear el directorio personal del nuevo usuario y copiar archivos iniciales.

Por defecto, también se creará un grupo para el nuevo usuario (ver -g, -N, -U y USERGROUPS_ENAB).

OPCIONES

Las opciones que se aplican al comando useradd son:

--badname 

Permitir nombres que no se ajustan a los estándares.

-b, --base-dir DIR_BASE

El directorio base por defecto para el sistema si no se especifica -d DIR_USUARIO. DIR_BASE se concatena con el nombre de la cuenta para definir el directorio personal.

Si esta opción no se especifica, useradd utilizará el directorio base especificado por la variable HOME en /etc/default/useradd, o /home por defecto.

-c, --comment COMENTARIO

Cualquier cadena de texto. Generalmente es una breve descripción de la cuenta y actualmente se usa como el campo para el nombre completo del usuario.

-d, --home-dir DIR_USUARIO

El nuevo usuario se creará utilizando DIR_USUARIO como valor para el directorio de inicio de sesión del usuario. Por defecto, se añade el nombre USUARIO a DIR_BASE y se utiliza como nombre de directorio de inicio de sesión. El directorio DIR_USUARIO no se crea por defecto. Sin embargo, se creará para usuarios no del sistema si se especifica la opción -m o si CREATE_HOME en login.defs está establecido en verdadero. Sin embargo, nunca se creará si se especifica la opción -M.

-D, --defaults

Ver más abajo, la subsección "Cambiar los valores por defecto".

-e, --expiredate FECHA_EXPIRACIÓN

Establece la fecha en la que la cuenta de usuario será desactivada. El valor se puede especificar como una fecha en formato AAAA-MM-DD o como un número de días desde 1970-01-01. La fecha se interpreta usando la zona horaria UTC.

Si no se especifica, useradd utiliza la fecha de expiración por defecto especificada por la variable EXPIRE en /etc/default/useradd, o una cadena vacía (sin expiración) por defecto.

-f, --inactive INACTIVO

Define el número de días después de que una contraseña supere su edad máxima antes de que la cuenta de usuario se bloquee. Si el usuario no cambia su contraseña dentro de este período de tiempo, su cuenta se vuelve inactiva. Este valor se almacena en el archivo de contraseñas shadow. Para más información, ver shadow(5).

Un valor de 0 desactiva la cuenta cuando la contraseña expira, sin demora.

Un valor de -1 vacía el campo respectivo en el archivo de contraseñas shadow, lo que significa que el período de inactividad no se aplica.

Si no se especifica, useradd utiliza el período de inactividad por defecto especificado por la variable INACTIVE en /etc/default/useradd, o -1 por defecto si no se especifica ningún valor.

-F, --add-subids-for-system

Actualiza /etc/subuid y /etc/subgid incluso al crear una cuenta del sistema con la opción -r.

-g, --gid GRUPO

El nombre o el número del grupo principal del usuario. El nombre del grupo debe existir. Un número de grupo debe referirse a un grupo ya existente.

Si no se especifica, el comportamiento de useradd dependerá de la variable USERGROUPS_ENAB en /etc/login.defs. Si esta variable está configurada como yes (o se especifica -U/--user-group en la línea de comandos), se creará un grupo para el usuario, con el mismo nombre que el nombre de inicio de sesión. Si la variable está configurada como no (o se especifica -N/--no-user-group en la línea de comandos), useradd establecerá el grupo principal del nuevo usuario al valor especificado por la variable GROUP en /etc/default/useradd, o 1000 por defecto.

-G, --groups GRUPO1[,GRUPO2,...[,GRUPON]]]

Una lista de grupos suplementarios de los que el usuario también es miembro. Cada grupo está separado del siguiente por una coma, sin espacios intermedios. Los grupos están sujetos a las mismas restricciones que el grupo dado con la opción -g. Por defecto, el usuario pertenece solo al grupo inicial. Además de pasar la opción -G, puede añadir la opción GROUPS al archivo /etc/default/useradd que añadirá a todos los usuarios a esos grupos suplementarios.

-h, --help

Muestra el mensaje de ayuda y sale.

-k, --skel DIR_ESQUELETO

El directorio esqueleto, que contiene los archivos y directorios que se copiarán en el directorio personal del usuario, cuando el directorio personal sea creado por useradd.

Esta opción solo es válida si se especifica la opción -m (o --create-home).

Si esta opción no está configurada, el directorio esqueleto se define por la variable SKEL en /etc/default/useradd o, por defecto, en /etc/skel.

Los enlaces simbólicos absolutos que enlazan de vuelta al directorio esqueleto tendrán el prefijo /etc/skel reemplazado por el directorio personal del usuario.

Si es posible, se copian las ACLs y los atributos extendidos.

-K, --key CLAVE=VALOR

Anula los valores predeterminados de /etc/login.defs (UID_MIN, UID_MAX, UMASK, PASS_MAX_DAYS y otros).

Ejemplo: -K PASS_MAX_DAYS =-1 se puede utilizar al crear una cuenta para desactivar el envejecimiento de la contraseña. Se pueden especificar múltiples opciones -K, por ejemplo: -K UID_MIN=100 -K  UID_MAX=499

-l, --no-log-init

No añadir al usuario a las bases de datos lastlog y faillog.

Por defecto, las entradas del usuario en las bases de datos lastlog y faillog se restablecen para evitar reutilizar la entrada de un usuario previamente eliminado.

Si esta opción no se especifica, useradd también consultará la variable LOG_INIT en /etc/default/useradd; si está configurada como no, el usuario no se añadirá a las bases de datos lastlog y faillog.

-m, --create-home

Crear el directorio personal del usuario si no existe. Los archivos y directorios contenidos en el directorio esqueleto (que se puede definir con la opción -k) se copiarán al directorio personal.

Por defecto, si esta opción no se especifica y CREATE_HOME no está habilitado, no se crean directorios personales.

El directorio donde se crea el directorio personal del usuario debe existir y tener el contexto SELinux y los permisos adecuados. De lo contrario, el directorio personal del usuario no podrá ser creado o accedido.

-M, --no-create-home

No crear el directorio personal del usuario, incluso si la configuración a nivel de sistema de /etc/login.defs (CREATE_HOME) está configurada como yes.

-N, --no-user-group

No crear un grupo con el mismo nombre que el usuario, sino añadir al usuario al grupo especificado por la opción -g o por la variable GROUP en /etc/default/useradd.

El comportamiento por defecto (si las opciones -g, -N y -U no se especifican) se define por la variable USERGROUPS_ENAB en /etc/login.defs.

-o, --non-

-o, --non-unique

permite la creación de una cuenta con un UID ya existente.

Esta opción solo es válida en combinación con la opción -u. Dado que la identidad de usuario sirve como clave para mapear entre usuarios por un lado y permisos, propiedad de archivos y otros aspectos que determinan el comportamiento del sistema por otro, más de un nombre de inicio de sesión accederá a la cuenta del UID dado.

-p, --password CONTRASEÑA

define una contraseña inicial para la cuenta. Se espera que CONTRASEÑA esté cifrada, tal como la devuelve crypt (3). Dentro de un script de shell, esta opción permite crear lotes de usuarios de manera eficiente.

Sin esta opción, la nueva cuenta se bloqueará y no tendrá contraseña definida, es decir, un solo signo de exclamación en el campo respectivo de /etc/shadow. Este es un estado en el que el usuario no podrá acceder a la cuenta ni definir una contraseña por sí mismo.

Nota: Evite esta opción en la línea de comandos, ya que la contraseña (o contraseña cifrada) será visible por los usuarios que listen los procesos.

Debe asegurarse de que la contraseña respete la política de contraseñas del sistema.

-r, --system

Crea una cuenta del sistema.

Los usuarios del sistema se crearán sin información de caducidad en /etc/shadow, y sus identificadores numéricos se elegirán en el rango SYS_UID_MIN-SYS_UID_MAX, definido en /etc/login.defs, en lugar de UID_MIN-UID_MAX (y sus contrapartes GID para la creación de grupos).

Tenga en cuenta que useradd no creará un directorio personal para dicho usuario, independientemente de la configuración predeterminada en /etc/login.defs (CREATE_HOME). Debe especificar las opciones -m si desea que se cree un directorio personal para una cuenta del sistema.

Tenga en cuenta que esta opción no actualizará /etc/subuid y /etc/subgid. Debe especificar las opciones -F si desea actualizar los archivos para crear una cuenta del sistema.

-R, --root CHROOT_DIR

Aplica cambios en el directorio CHROOT_DIR y utiliza los archivos de configuración del directorio CHROOT_DIR. Solo se admiten rutas absolutas.

-P, --prefix PREFIX_DIR

Aplica cambios a los archivos de configuración bajo el sistema de archivos raíz encontrado en el directorio PREFIX_DIR. Esta opción no chroot y está destinada a preparar un objetivo de compilación cruzada. Algunas limitaciones: los usuarios/grupos NIS y LDAP no se verifican. La autenticación PAM utiliza los archivos del host. Sin soporte SELINUX.

-s, --shell SHELL

establece la ruta al shell de inicio de sesión del usuario. Sin esta opción, el sistema utilizará la variable SHELL especificada en /etc/default/useradd, o, si tampoco está establecida, el campo para el shell de inicio de sesión en /etc/passwd permanecerá vacío.

-u, --uid UID

El valor numérico del ID del usuario. Este valor debe ser único, a menos que se utilice la opción -o. El valor debe ser no negativo. El valor predeterminado es utilizar el valor de ID más pequeño mayor o igual a UID_MIN y mayor que cualquier otro usuario.

Consulte también la opción -r y la descripción de UID_MAX.

-U, --user-group

Crea un grupo con el mismo nombre que el usuario y añade al usuario a este grupo.

El comportamiento predeterminado (si no se especifican las opciones -g, -N y -U) está definido por la variable USERGROUPS_ENAB en /etc/login.defs.

-Z, --selinux-user SEUSER

define el usuario SELinux para la nueva cuenta. Sin esta opción, SELinux utiliza el usuario predeterminado. Tenga en cuenta que el sistema shadow no almacena el selinux-user, utiliza semanage(8) para eso.

--selinux-range SERANGE

define el rango MLS SELinux para la nueva cuenta. Sin esta opción, SELinux utiliza el rango predeterminado. Tenga en cuenta que el sistema shadow no almacena el selinux-range, utiliza semanage(8) para eso.

Esta opción solo es válida si se especifica la opción -Z (o --selinux-user).

Cambiar los valores predeterminados

Cuando se invoca solo con la opción -D, useradd mostrará los valores predeterminados actuales. Cuando se invoca con -D más otras opciones, useradd actualizará los valores predeterminados para las opciones especificadas. Las opciones válidas para cambiar los predeterminados son:

-b, --base-dir BASE_DIR

establece la ruta de prefijo para el directorio personal de un nuevo usuario. El nombre del usuario se añadirá al final de BASE_DIR para formar el nombre del directorio personal del nuevo usuario, si la opción -d no se utiliza al crear una nueva cuenta.

Esta opción establece la variable HOME en /etc/default/useradd.

-e, --expiredate FECHA_CADUCIDAD

establece la fecha en la que se desactivarán las cuentas de usuario recién creadas.

Esta opción establece la variable EXPIRE en /etc/default/useradd.

-f, --inactive INACTIVO

especifica el número de días después de que caduca una contraseña durante los cuales el usuario aún puede iniciar sesión. Después de este período, la cuenta se bloquea.

Esta opción establece la variable INACTIVE en /etc/default/useradd.

-g, --gid GRUPO

establece el grupo primario predeterminado para los usuarios recién creados, aceptando nombres de grupo o un ID de grupo numérico. El grupo nombrado debe existir, y el GID debe tener una entrada existente.

Esta opción establece la variable GROUP en /etc/default/useradd.

-s, --shell SHELL

define el shell de inicio de sesión predeterminado para los nuevos usuarios.

Esta opción establece la variable SHELL en /etc/default/useradd.

NOTAS

El administrador del sistema es responsable de colocar los archivos de usuario predeterminados en el directorio /etc/skel/ (o cualquier otro directorio esqueleto especificado en /etc/default/useradd o en la línea de comandos).

ADVERTENCIAS

No puede añadir un usuario a un grupo NIS o LDAP. Esto debe realizarse en el servidor correspondiente.

Del mismo modo, si el nombre de usuario ya existe en una base de datos de usuarios externa como NIS o LDAP, useradd denegará la solicitud de creación de la cuenta de usuario.

Los nombres de usuario solo pueden contener letras mayúsculas y minúsculas, dígitos, guiones bajos o guiones. Pueden terminar con un signo de dólar. Los guiones no están permitidos al principio del nombre de usuario. Los nombres de usuario completamente numéricos y los nombres de usuario . o .. también están desautorizados. No se recomienda el uso de nombres de usuario que comiencen con el carácter . ya que sus directorios personales estarán ocultos en la salida de ls.

Los nombres de usuario solo pueden tener hasta 256 caracteres de longitud.

CONFIGURACIÓN

Las siguientes variables de configuración en /etc/login.defs cambian el comportamiento de esta herramienta:

CREATE_HOME (booleano)

Indica si se debe crear un directorio personal por predeterminado para los nuevos usuarios.

Esta configuración no se aplica a los usuarios del sistema y puede ser anulada en la línea de comandos.

GID_MAX (número), GID_MIN (número)

Rango de IDs de grupo utilizados para la creación de grupos regulares por useradd, groupadd o newusers.

El valor predeterminado para GID_MIN (respectivamente GID_MAX) es 1000 (respectivamente 60000).

HOME_MODE (número)

El modo para los nuevos directorios personales. Si no se especifica, el UMASK se utiliza para crear el modo.

useradd y newusers utilizan esto para establecer el modo del directorio personal que crean.

LASTLOG_UID_MAX (número)

ID de usuario más alto para el cual se deben actualizar las entradas de lastlog. Como los IDs de usuario más altos suelen ser rastreados por servicios de identidad y autenticación de usuarios remotos, no hay necesidad de crear un archivo lastlog disperso y grande para ellos.

La ausencia de la opción LASTLOG_UID_MAX en la configuración significa que no hay límite de ID de usuario para escribir entradas de lastlog.

MAIL_DIR (cadena)

El directorio de spool de correo. Esto es necesario para manipular el buzón cuando su cuenta de usuario correspondiente se modifica o elimina. Si no se especifica, se utiliza un valor predeterminado en tiempo de compilación. El parámetro CREATE_MAIL_SPOOL en /etc/default/useradd determina si se debe crear el spool de correo.

MAIL_FILE (cadena)

Define la ubicación de los archivos de spool de correo de los usuarios en relación con su directorio personal.

Las variables MAIL_DIR y MAIL_FILE son utilizadas por useradd, usermod y userdel para crear, mover o eliminar el spool de correo del usuario.

MAX_MEMBERS_PER_GROUP (número)

Miembros máximos por entrada de grupo. Cuando se alcanza el máximo, se inicia una nueva entrada de grupo (línea) en /etc/group (con el mismo nombre, la misma contraseña y el mismo GID).

El valor predeterminado es 0, lo que significa que no hay límites en el número de miembros de un grupo.

Esta característica (grupo dividido) permite limitar la longitud de las líneas en el archivo de grupo. Esto es útil para asegurar que las líneas de los grupos NIS no superen los 1024 caracteres.

Si necesita aplicar dicho límite, puede usar 25.

Nota: los grupos divididos pueden no ser compatibles con todas las herramientas (incluso en la suite de herramientas Shadow). No debe usar esta variable a menos que realmente la necesite.

PASS_MAX_DAYS (número)

El número máximo de días que se puede utilizar una contraseña. Si la contraseña es anterior a esto, se forzará un cambio de contraseña. Si no se especifica, se asumirá -1 (lo que deshabilita la restricción).

PASS_MIN_DAYS (número)

El número mínimo de días permitidos entre cambios de contraseña. Cualquier intento de cambio de contraseña antes de esto será rechazado. Si no se especifica, se asumirá 0 (lo que deshabilita la restricción).

PASS_WARN_AGE (número)

El número de días de advertencia que se dan antes de que una contraseña expire. Un cero significa que la advertencia se da solo el día de la expiración, un valor de -1 significa que no se da ninguna advertencia. Si no se especifica, no se proporcionará ninguna advertencia.

SUB_GID_MIN (número), SUSUB_GID_MAX (número), SUB_GID_COUNT (número)

Si /etc/subuid existe, los comandos useradd y newusers (a menos que el usuario ya tenga IDs de grupo subordinados) asignan SUB_GID_COUNT IDs de grupo no utilizados del rango SUB_GID_MIN a SUB_GID_MAX para cada nuevo usuario.

Los valores predeterminados para SUB_GID_MIN, SUB_GID_MAX, SUB_GID_COUNT son respectivamente 100000, 600100000 y 65536.

SUB_UID_MIN (número), SUB_UID_MAX (número), SUB_UID_COUNT (número)

Si /etc/subuid existe, los comandos useradd y newusers (a menos que el usuario ya tenga IDs de usuario subordinados) asignan SUB_UID_COUNT IDs de usuario no utilizados del rango SUB_UID_MIN a SUB_UID_MAX para cada nuevo usuario.

Los valores predeterminados para SUB_UID_MIN, SUB_UID_MAX, SUB_UID_COUNT son respectivamente 100000, 600100000 y 65536.

SYS_GID_MAX (número), SYS_GID_MIN (número)

Rango de IDs de grupo utilizados para la creación de grupos del sistema por useradd, groupadd, o newusers.

El valor predeterminado para SYS_GID_MIN (resp. SYS_GID_MAX) es 101 (resp. GID_MIN-1).

SYS_UID_MAX (número), SYS_UID_MIN (número)

Rango de IDs de usuario utilizados para la creación de usuarios del sistema por useradd o newusers.

El valor predeterminado para SYS_UID_MIN (resp. SYS_UID_MAX) es 101 (resp. UID_MIN-1).

UID_MAX (número), UID_MIN (número)

Rango de IDs de usuario utilizados para la creación de usuarios regulares por useradd o newusers.

El valor predeterminado para UID_MIN (resp. UID_MAX) es 1000 (resp. 60000).

UMASK (número)

La máscara de creación de archivos se inicializa con este valor. Si no se especifica, la máscara se inicializará con 022.

useradd y newusers usan esta máscara para establecer el modo del directorio de inicio que crean si HOME_MODE no está establecido.

También es utilizada por pam_umask como el valor umask predeterminado.

ARCHIVOS

/etc/passwd

Información de la cuenta de usuario.

/etc/shadow

Información segura de la cuenta de usuario.

/etc/group

Información de la cuenta de grupo.

/etc/gshadow

Información segura de la cuenta de grupo.

/etc/default/useradd

Valores predeterminados para la creación de cuentas.

/etc/shadow-maint/useradd-pre.d/*, /etc/shadow-maint/useradd-post.d/*

Archivos run-part para ejecutar durante la adición de usuarios. La variable de entorno ACTION se poblará con useradd y SUBJECT con el nombre de usuario. useradd-pre.d se ejecutará antes de cualquier adición de usuario. useradd-post.d se ejecutará después de la adición de usuario. Si un script sale con un valor distinto de cero, la ejecución terminará.

/etc/skel/

Directorio que contiene archivos predeterminados.

/etc/subgid

IDs de grupo subordinados por usuario.

/etc/subuid

IDs de usuario subordinados por usuario.

/etc/login.defs

Configuración del conjunto de contraseñas shadow.

VALORES DE SALIDA

El comando useradd sale con los siguientes valores:

0

éxito

1

no se puede actualizar el archivo de contraseñas

2

sintaxis de comando inválida

3

argumento inválido para la opción

4

UID ya en uso (y sin -o)

6

el grupo especificado no existe

9

nombre de usuario o grupo ya en uso

10

no se puede actualizar el archivo de grupos

12

no se puede crear el directorio de inicio

14

no se puede actualizar el mapeo de usuarios SELinux

19

nombre de usuario o grupo inválido
