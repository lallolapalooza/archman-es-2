USERMOD(8) Comandos de gestión del sistema USERMOD(8)

NOMBRE

usermod - modificar una cuenta de usuario

SINOPSIS

usermod [opciones] USUARIO

DESCRIPCIÓN

El comando usermod modifica los archivos de cuentas del sistema.

OPCIONES

Las opciones que se aplican al comando usermod son:

-a, --append

Añade el usuario a los grupos suplementarios. Usar solo con la opción -G.

-b, --badname

Permite nombres que no cumplen los estándares.

-c, --comment COMENTARIO

actualiza el campo de comentarios del usuario en /etc/passwd, que normalmente se modifica utilizando la utilidad chfn(1).

-d, --home DIR_INICIO

El nuevo directorio de inicio del usuario.

Si se da la opción -m, el contenido del directorio de inicio actual se moverá al nuevo directorio de inicio, que se creará si no existe. Si el directorio de inicio actual no existe, el nuevo directorio de inicio no se creará.

-e, --expiredate FECHA_EXPIRACIÓN

Especifica la fecha en la que se deshabilitará la cuenta de usuario. El valor se puede especificar como una fecha en formato YYYY-MM-DD o como un número de días desde 1970-01-01. La fecha se interpreta utilizando la zona horaria UTC.

Una entrada de -1 o una cadena vacía borra el campo de expiración de la cuenta en el archivo de contraseñas shadow. La cuenta permanecerá disponible sin fecha de expiración.

Esta opción requiere el archivo /etc/shadow. Si no existe ninguna entrada en el archivo /etc/shadow, el sistema creará una automáticamente.

-f, --inactive INACTIVO

Define el número de días después de que una contraseña supere su antigüedad máxima durante los cuales el usuario aún puede iniciar sesión cambiando inmediatamente su contraseña. Si el usuario no cambia su contraseña dentro de este período, su cuenta se vuelve inactiva. Este valor se almacena en el archivo de contraseñas shadow.

Un valor de 0 deshabilita la cuenta cuando la contraseña expira, sin demora.

Un valor de -1 vacía el campo respectivo en el archivo de contraseñas shadow, lo que significa que no se aplicará el período de inactividad.

Esta opción requiere el archivo /etc/shadow. Si no existe ninguna entrada en el archivo /etc/shadow, el sistema creará una automáticamente.

-g, --gid GRUPO

El nombre o ID numérico del nuevo grupo principal del usuario. El grupo debe existir.

Los archivos del directorio de inicio del usuario que sean propiedad del grupo principal anterior del usuario pasarán a ser propiedad de este nuevo grupo.

La propiedad del grupo de archivos fuera del directorio de inicio del usuario debe arreglarse manualmente.

El cambio de propiedad del grupo de archivos dentro del directorio de inicio del usuario tampoco se realiza si el propietario del directorio de inicio (UID) es diferente del UID actual o nuevo del usuario. Esto es una medida de seguridad para directorios de inicio especiales, como /.

-G, --groups GRUPO1[,GRUPO2,...[,GRUPON]]]

Una lista de grupos suplementarios de los que el usuario también es miembro. Cada grupo está separado del siguiente por una coma, sin espacios intermedios. Los grupos deben existir.

Si el usuario es actualmente miembro de un grupo que no está en la lista, el usuario será eliminado de ese grupo. Este comportamiento se puede cambiar con la opción -a, que añade al usuario a la lista de grupos suplementarios actual.

-l, --login NUEVO_USUARIO

El nombre del usuario se cambiará de USUARIO a NUEVO_USUARIO. No se cambia nada más. En particular, el directorio de inicio o el buzón de correo del usuario probablemente deberían renombrarse manualmente para reflejar el nuevo nombre de usuario.

-L, --lock

Bloquea la contraseña de un usuario. Esto añade un '!' delante de la contraseña cifrada, deshabilitando efectivamente la contraseña. No puede usar esta opción con -p o -U.

Nota: si desea bloquear la cuenta (no solo el acceso con contraseña), también debería establecer la FECHA_EXPIRACIÓN a 1.

-m, --move-home

mueve el contenido del directorio de inicio del usuario a la nueva ubicación. Si el directorio de inicio actual no existe, el nuevo directorio de inicio no se creará.

Esta opción solo es válida en combinación con la opción -d (o --home).

usermod intentará adaptar la propiedad de los archivos y copiar los permisos, ACLs y atributos extendidos, pero pueden ser necesarios cambios manuales posteriormente.

-o, --non-unique

permite cambiar el ID de usuario a un valor no único.

Esta opción solo es válida en combinación con la opción -u. Dado que la identidad de usuario sirve como clave para mapear entre usuarios por un lado, y permisos, propiedades de archivos y otros aspectos que determinan el comportamiento del sistema por otro, más de un nombre de usuario accederá a la cuenta del UID dado.

-p, --password CONTRASENA

define una nueva contraseña para el usuario. Se espera que CONTRASENA esté cifrada, tal como devuelve crypt(3).

Nota: Evite esta opción en la línea de comandos, ya que la contraseña (o contraseña cifrada) será visible por los usuarios que listen los procesos.

La contraseña se escribirá en el archivo local /etc/passwd o /etc/shadow. Esto podría diferir de la base de datos de contraseñas configurada en su configuración de PAM.

Debe asegurarse de que la contraseña respeta la política de contraseñas del sistema.

-r, --remove

Elimina al usuario de los grupos suplementarios nombrados. Usar solo con la opción -G.

-R, --root DIR_CHROOT

Aplica los cambios en el directorio DIR_CHROOT y utiliza los archivos de configuración del directorio DIR_CHROOT. Solo se admiten rutas absolutas.

-P, --prefix DIR_PREFIJO

Aplica los cambios dentro del árbol de directorios que comienza con DIR_PREFIJO y utiliza también los archivos de configuración ubicados allí. Esta opción no realiza chroot y está pensada para preparar un objetivo de compilación cruzada. Algunas limitaciones: los usuarios/grupos NIS y LDAP no se verifican. La autenticación PAM utiliza los archivos del host. No hay soporte SELinux.

-s, --shell SHELL

cambia el shell de inicio de sesión del usuario. Una cadena vacía para SHELL vacía el campo en /etc/passwd y registra al usuario en el shell por defecto del sistema.

-u, --uid UID

El nuevo valor del ID del usuario.

Este valor debe ser único, a menos que se utilice la opción -o. El valor debe ser no negativo.

El buzón del usuario y cualquier archivo que posea y que se encuentre en su directorio de inicio tendrán automáticamente el ID de archivo cambiado.

La propiedad de los archivos fuera del directorio de inicio del usuario debe arreglarse manualmente.

El cambio de propiedad del usuario de archivos dentro del directorio de inicio del usuario tampoco se realiza si el propietario del directorio de inicio (UID) es diferente del UID actual o nuevo del usuario. Esto es una medida de seguridad para directorios de inicio especiales, como /.

No se realizarán comprobaciones con respecto a UID_MIN, UID_MAX, SYS_UID_MIN, o SYS_UID_MAX de /etc/login.defs.

-U, --unlock

Desbloquea la contraseña de un usuario. Elimina el '!' delante de la contraseña cifrada. No puede usar esta opción con -p o -L.

OPCIONES

-e, --expire FECHA

Establece la fecha de caducidad de la cuenta de usuario. La fecha puede ser un número de días desde el inicio (0 para deshabilitar, nunca caduca) o una fecha en formato YYYY-MM-DD.

También puedes establecer la FECHA_CADUCIDAD (por ejemplo a 99999, o al valor EXPIRE de /etc/default/useradd).

-v, --add-subuids PRIMERO-ULTIMO

Añade un rango de UIDs subordinados a la cuenta del usuario.

Esta opción puede especificarse varias veces para añadir múltiples rangos a la cuenta de un usuario.

No se realizarán comprobaciones con respecto a SUB_UID_MIN, SUB_UID_MAX o SUB_UID_COUNT de /etc/login.defs.

-V, --del-subuids PRIMERO-ULTIMO

Elimina un rango de UIDs subordinados de la cuenta del usuario.

Esta opción puede especificarse varias veces para eliminar múltiples rangos de la cuenta de un usuario. Cuando se especifican tanto --del-subuids como --add-subuids, la eliminación de todos los rangos de UIDs subordinados ocurre antes de que se añada cualquier rango de UIDs subordinados.

No se realizarán comprobaciones con respecto a SUB_UID_MIN, SUB_UID_MAX o SUB_UID_COUNT de /etc/login.defs.

-w, --add-subgids PRIMERO-ULTIMO

Añade un rango de GIDs subordinados a la cuenta del usuario.

Esta opción puede especificarse varias veces para añadir múltiples rangos a la cuenta de un usuario.

No se realizarán comprobaciones con respecto a SUB_GID_MIN, SUB_GID_MAX o SUB_GID_COUNT de /etc/login.defs.

-W, --del-subgids PRIMERO-ULTIMO

Elimina un rango de GIDs subordinados de la cuenta del usuario.

Esta opción puede especificarse varias veces para eliminar múltiples rangos de la cuenta de un usuario. Cuando se especifican tanto --del-subgids como --add-subgids, la eliminación de todos los rangos de GIDs subordinados ocurre antes de que se añada cualquier rango de GIDs subordinados.

No se realizarán comprobaciones con respecto a SUB_GID_MIN, SUB_GID_MAX o SUB_GID_COUNT de /etc/login.defs.

-Z, --selinux-user SEUSER

Define el usuario SELinux que se mapeará con LOGIN. Una cadena vacía ("") eliminará la entrada correspondiente (si existe). Ten en cuenta que el sistema shadow no almacena el selinux-user, sino que utiliza semanage(8) para ello.

--selinux-range SERANGE

Define el rango MLS de SELinux para la nueva cuenta. Ten en cuenta que el sistema shadow no almacena el selinux-range, sino que utiliza semanage(8) para ello.

Esta opción solo es válida si se especifica la opción -Z (o --selinux-user).

ADVERTENCIAS

Debes asegurarte de que el usuario nombrado no esté ejecutando ningún proceso cuando se ejecute este comando si se está cambiando el ID de usuario numérico, el nombre de usuario o el directorio principal del usuario. usermod lo comprueba en Linux. En otros sistemas operativos, solo utiliza utmp para verificar si el usuario ha iniciado sesión.

Debes cambiar el propietario de cualquier archivo crontab o trabajo at manualmente.

Debes realizar cualquier cambio que involucre NIS en el servidor NIS.

CONFIGURACIÓN

Las siguientes variables de configuración en /etc/login.defs cambian el comportamiento de esta herramienta:

LASTLOG_UID_MAX (número)

El número de ID de usuario más alto para el cual se actualizarán las entradas de lastlog. Como los IDs de usuario más altos suelen ser rastreados por servicios de autenticación y de identidad de usuario remoto, no hay necesidad de crear un archivo lastlog disperso y enorme para ellos.

La ausencia de la opción LASTLOG_UID_MAX en la configuración significa que no hay límite de ID de usuario para escribir entradas de lastlog.

MAIL_DIR (cadena)

El directorio de spool de correo. Esto es necesario para manipular el buzón cuando se modifica o elimina la cuenta de usuario correspondiente. Si no se especifica, se utiliza un valor predeterminado en tiempo de compilación. El parámetro CREATE_MAIL_SPOOL en /etc/default/useradd determina si se debe crear el spool de correo.

MAIL_FILE (cadena)

Define la ubicación de los archivos de spool de correo de los usuarios en relación con su directorio principal.

Las variables MAIL_DIR y MAIL_FILE son utilizadas por useradd, usermod y userdel para crear, mover o eliminar el spool de correo del usuario.

MAX_MEMBERS_PER_GROUP (número)

Miembros máximos por entrada de grupo. Cuando se alcanza el máximo, se inicia una nueva entrada de grupo (línea) en /etc/group (con el mismo nombre, la misma contraseña y el mismo GID).

El valor predeterminado es 0, lo que significa que no hay límites en el número de miembros en un grupo.

Esta característica (grupo dividido) permite limitar la longitud de las líneas en el archivo de grupo. Esto es útil para asegurar que las líneas de los grupos NIS no sean mayores de 1024 caracteres.

Si necesitas aplicar tal límite, puedes usar 25.

Nota: los grupos divididos pueden no ser compatibles con todas las herramientas (incluso dentro de la suite de herramientas Shadow). No debes utilizar esta variable a menos que realmente la necesites.

SUB_GID_MIN (número), SUB_GID_MAX (número), SUB_GID_COUNT (número)

Si existe /etc/subuid, los comandos useradd y newusers (a menos que el usuario ya tenga GIDs subordinados) asignan SUB_GID_COUNT GIDs no utilizados del rango de SUB_GID_MIN a SUB_GID_MAX para cada nuevo usuario.

Los valores predeterminados para SUB_GID_MIN, SUB_GID_MAX, SUB_GID_COUNT son respectivamente 100000, 600100000 y 65536.

SUB_UID_MIN (número), SUB_UID_MAX (número), SUB_UID_COUNT (número)

Si existe /etc/subuid, los comandos useradd y newusers (a menos que el usuario ya tenga UIDs subordinados) asignan SUB_UID_COUNT UIDs no utilizados del rango de SUB_UID_MIN a SUB_UID_MAX para cada nuevo usuario.

Los valores predeterminados para SUB_UID_MIN, SUB_UID_MAX, SUB_UID_COUNT son respectivamente 100000, 600100000 y 65536.
