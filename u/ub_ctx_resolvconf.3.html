DESCRIPCIÓN

Unbound es una implementación de un resolvedor DNS, que realiza caché y validación DNSSEC. Esta es la API de la biblioteca, para usar la biblioteca -lunbound. El demonio del servidor se describe en unbound(8). La biblioteca funciona de forma independiente de un servidor unbound en ejecución, y puede usarse para convertir nombres de host en direcciones IP, y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de clave pública de los resultados con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Puede crearse y eliminarse en cualquier momento. Crearla de nuevo elimina cualquier configuración previa (como claves de confianza) y borra cualquier resultado en caché.

Las funciones son seguras para hilos, y un contexto puede usarse en un entorno con hilos (así como en uno sin hilos). La resolución (y la validación) también se pueden realizar de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve el control de la llamada inmediatamente, de modo que el procesamiento pueda continuar, mientras que los resultados estarán disponibles más tarde.

Las funciones se discuten a continuación, una por una.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza por defecto. Use ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esta función, use las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si utiliza lib openssl (la aplicación llama a estas funciones una vez para inicialización). Openssl 1.0.0 o posterior usa la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y las devoluciones de llamada no se llaman para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que le permite especificar una de las opciones del formato de archivo de configuración, consulte unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclajes de confianza, existen rutinas especiales. Pase el nombre de la opción con los dos puntos (':') al final.
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene el valor de una opción. Algunas opciones no se pueden obtener, y otras devuelven una lista separada por saltos de línea. Pase el nombre de la opción sin los dos puntos (':') al final. El valor devuelto debe ser liberado (free(2)) por el llamador.
ub_ctx_config
Una interfaz para usuarios avanzados que le permite especificar un archivo de configuración de unbound, consulte unbound.conf(5), que se lee para la configuración. No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclajes de confianza, existen rutinas especiales. Esta función solo es segura para hilos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no se llame en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se reenviarán las consultas DNS, el resolvedor de caché a utilizar. Dirección IP4 o IP6. Reenvía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolvedor recursivo. Si el proxy no es compatible con DNSSEC, la validación puede fallar. Se puede llamar varias veces, en cuyo caso las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autoritativos a usar para una zona particular. Dirección IP4 o IP6. Si la dirección es NULL, se elimina la entrada stub. Establezca isprime en true si configura las sugerencias de raíz con ella. De lo contrario, es similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas, o para agregar varias direcciones para una zona particular. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolución completa, pero puede usar esta llamada para leer la lista de servidores de nombres a usar desde el nombre de archivo proporcionado. Normalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no admiten DNSSEC, la validación puede fallar. Solo se capturan los servidores de nombres, los dominios de búsqueda, ndots y otras configuraciones de resolv.conf(5) se ignoran. Si se pasa NULL a fname, se utiliza "/etc/resolv.conf" (si está en Windows, se selecciona el servidor de nombres configurado a nivel del sistema en su lugar). En este momento, solo es posible establecer la configuración antes de la primera resolución.
ub_ctx_hosts
Lee la lista de hosts del nombre de archivo proporcionado. Normalmente "/etc/hosts". Cuando se consultan, estas direcciones no se marcan como seguras por DNSSEC. Si se pasa NULL a fname, se utiliza "/etc/hosts" (si está en Windows, se selecciona etc/hosts del WINDIR en su lugar). En este momento, solo es posible establecer la configuración antes de la prime

NAME

ub_ctx_resolvconf - load system resolv.conf file into context

SYNOPSIS

#include <unbound.h>

int ub_ctx_resolvconf(ub_ctx *ctx, const char *filename);

DESCRIPTION

Loads the system's resolver configuration file into the context. This file contains information about DNS servers to use, such as IP addresses and options like search paths and domain names. The format is the standard Unix resolv.conf file. If filename is NULL, it uses the default system resolv.conf location.

This function is a convenience function that parses the given file and then calls ub_ctx_resolver_name, ub_ctx_searchlist_add and ub_ctx_domain_add to populate the context with the information.

The system configuration file can specify nameservers and search domains. For example:

nameserver 10.0.0.1
search example.com
domain example.com

If the file contains multiple nameserver lines, they are all added to the context. If the file contains both a domain and a search line, the domain line is used as the default domain, and the search line specifies the search path. If only domain is specified, the search path is limited to that domain name.

FUNCTIONS

The unbound library provides the following functions:

ub_ctx_create
Create a new unbound context. This context is used for all subsequent operations. Returns a pointer to the context on success, or NULL on failure.
ub_ctx_destroy
Destroy the given unbound context and free all associated resources.
ub_ctx_config
Load configuration from a file. The file should be in the format used by unbound.conf(5). An empty filename loads the default configuration file, typically /usr/local/etc/unbound/unbound.conf.
ub_ctx_resolver_name
Add a DNS resolver server by IP address. The IP address should be a string (e.g., "192.168.1.1"). This is equivalent to a nameserver directive in resolv.conf.
ub_ctx_searchlist_add
Add a domain name to the search list. This is equivalent to a search directive in resolv.conf.
ub_ctx_domain_add
Add a domain name to be used for short name resolution. This is equivalent to a domain directive in resolv.conf.
ub_ctx_add_ta
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
ub_ctx_add_ta_autr
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta_file
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_trustedkeys
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_debugout
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
ub_ctx_debuglevel
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
ub_ctx_async
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
ub_poll
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
ub_wait
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
ub_fd
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
ub_process
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
ub_resolve
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
ub_resolve_async
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

ub_cancel
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
ub_resolve_free
Free struct ub_result contents after use.
ub_strerror
Convert error value from one of the unbound library functions to a human readable string.
ub_ctx_print_local_zones
Debug printout the local authority information to debug output.
ub_ctx_zone_add
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
ub_ctx_zone_remove
Delete zone from local authority info.
ub_ctx_data_add
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
ub_ctx_data_remove
Delete local authority data from the name given.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Else, they are not both true, one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.

Sobre Arch Linux

Arch Linux es una distribución de Linux independiente, desarrollada con un enfoque en la simplicidad, la modernidad, el pragmatismo, el centralismo del usuario y la versatilidad. Se desarrolla principalmente para sistemas x86-64 y su base de paquetes se puede encontrar en un repositorio de Git.

Arch ofrece un modelo de lanzamiento continuo ("rolling release") que actualiza el sistema con las últimas versiones estables de software. Su sistema de gestión de paquetes, Pacman, junto con la colección de scripts de compilación AUR (Arch User Repository), permiten personalizar el sistema de forma sencilla.

La documentación oficial de Arch Linux, conocida como ArchWiki, es un recurso exhaustivo y muy apreciado por la comunidad, que cubre una amplia gama de temas relacionados con la instalación, configuración y uso de Arch Linux.
