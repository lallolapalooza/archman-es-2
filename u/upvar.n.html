upvar(n) Comandos integrados de Tcl upvar(n)

NOMBRE

upvar - Crea un enlace a una variable en un frame de pila diferente

SINOPSIS

upvar ?nivel? otraVar miVar ?otraVar miVar ...?

DESCRIPCIÓN

Este comando organiza para que una o más variables locales en el procedimiento actual hagan referencia a variables en una llamada de procedimiento anterior o a variables globales. Nivel puede tener cualquiera de las formas permitidas para el comando uplevel, y puede omitirse (por defecto es 1). Por cada argumento otraVar, upvar hace que la variable con ese nombre en el frame del procedimiento dado por nivel (o en el nivel global, si nivel es #0) sea accesible en el procedimiento actual con el nombre dado en el argumento miVar correspondiente. La variable llamada otraVar no necesita existir en el momento de la llamada; se creará la primera vez que se haga referencia a miVar, al igual que una variable ordinaria. No debe existir una variable con el nombre miVar en el momento en que se invoca upvar. MiVar siempre se trata como el nombre de una variable, no como un elemento de array. Se devuelve un error si el nombre parece ser un elemento de array, como a(b). OtraVar puede referirse a una variable escalar, un array o un elemento de array. Upvar devuelve una cadena vacía.

El comando upvar simplifica la implementación de la llamada a procedimientos por nombre y también facilita la creación de nuevas construcciones de control como procedimientos Tcl. Por ejemplo, considere el siguiente procedimiento:

proc add2 nombre {
    upvar $nombre x
    set x [expr {$x + 2}]
}

Si se invoca add2 con un argumento que da el nombre de una variable, suma dos al valor de esa variable. Aunque add2 podría haberse implementado usando uplevel en lugar de upvar, upvar hace que sea más simple para add2 acceder a la variable en el frame del procedimiento del llamador.

namespace eval es otra forma (además de las llamadas a procedimientos) en que el contexto de nombres de Tcl puede cambiar. Agrega un frame de llamada a la pila para representar el contexto del espacio de nombres. Esto significa que cada comando namespace eval cuenta como otro nivel de llamada para los comandos uplevel y upvar. Por ejemplo, info level 1 devolverá una lista que describe un comando que es la llamada al procedimiento más externa o el comando namespace eval más externo. Además, uplevel #0 evalúa un script en el nivel superior en el espacio de nombres más externo (el espacio de nombres global).

Si una variable de upvar se desestablece (por ejemplo, x en add2 arriba), la operación unset afecta a la variable a la que está enlazada, no a la variable de upvar. No hay forma de desestablecer una variable de upvar excepto saliendo del procedimiento en el que está definida. Sin embargo, es posible reasignar una variable de upvar ejecutando otro comando upvar.

TRACERS Y UPVAR

Upvar interactúa con los tracers de una manera sencilla pero posiblemente inesperada. Si se define un tracer de variable en otraVar, ese tracer se activará por acciones que involucren a miVar. Sin embargo, al procedimiento tracer se le pasará el nombre de miVar, en lugar del nombre de otraVar. Por lo tanto, la salida del siguiente código será “localVar” en lugar de “originalVar”:

proc traceproc { name index op } {
    puts $name
}
proc setByUpvar { name value } {
    upvar $name localVar
    set localVar $value
}
set originalVar 1
trace variable originalVar w traceproc
setByUpvar originalVar 2

Si otraVar se refiere a un elemento de un array, los tracers de variables establecidos para todo el array no se invocarán cuando se acceda a miVar (pero los tracers del elemento particular aún se invocarán). En particular, si el array es env, los cambios realizados en miVar no se pasarán correctamente a los subprocesos.

EJEMPLO

Un comando decr que funciona como incr excepto que resta el valor de la variable en lugar de sumarlo:

proc decr {varName {decrement 1}} {
    upvar 1 $varName var
    incr var [expr {-$decrement}]
}
