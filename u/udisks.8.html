UDISKS(8) Administración del Sistema UDISKS(8)

NOMBRE

udisks - Gestor de Discos

DESCRIPCIÓN

udisks proporciona interfaces para enumerar y realizar operaciones en discos y dispositivos de almacenamiento. Cualquier aplicación (incluidas las que no tienen privilegios) puede acceder al demonio udisksd(8) a través del nombre org.freedesktop.UDisks2 en el bus de mensajes del sistema[1]. Además de la API de D-Bus, también se proporciona una biblioteca, libudisks2. Esta biblioteca puede ser utilizada desde C/C++ y cualquier lenguaje de alto nivel con soporte para GObjectIntrospection[2], como Javascript y Python. udisks solo participa indirectamente en qué dispositivos y objetos se muestran en la interfaz de usuario.

CONTROL DE ACCESO

Por defecto, los usuarios conectados en sesiones de inicio de sesión activas tienen permitido realizar operaciones (por ejemplo, montar, desbloquear o modificar) en dispositivos adjuntos al asiento de su sesión. El control de acceso es granular y se basa en polkit(8), consulte el capítulo "Comprobaciones de Autorización" en la documentación de udisks para más información. Tenga en cuenta que la opción x-udisks-auth puede ser utilizada en los archivos /etc/fstab y /etc/crypttab para especificar que se requiere autorización adicional para montar o desbloquear el dispositivo (requiriendo típicamente que el usuario se autentique como administrador).

CONFIGURACIÓN DE UNIDAD

Al arrancar y cuando se conecta una unidad, udisksd(8) aplicará la configuración almacenada en el archivo /etc/udisks2/IDENTIFICADOR.conf donde IDENTIFICADOR es el valor de la propiedad Drive:Id para la unidad. Si el archivo cambia en el disco, su nuevo contenido también se aplicará a la unidad. Típicamente, los usuarios o administradores nunca necesitarán editar los archivos de configuración de la unidad, ya que son administrados efectivamente a través de aplicaciones gráficas como gnome-disks(1). Sin embargo, se admite la edición manual de los archivos de configuración; el formato del archivo es un simple formato similar a .ini (consulte la Especificación de Entrada de Escritorio[3] para la sintaxis exacta). Se pueden agregar nuevos grupos y claves en el futuro.

GRUPO ATA

El grupo ATA es para configuraciones que se aplican a unidades que utilizan el conjunto de comandos ATA. Las siguientes claves son compatibles:

StandbyTimeout

El tiempo de espera en espera. Un valor de cero significa "tiempos de espera deshabilitados": el dispositivo no entrará automáticamente en modo de espera. Los valores de 1 a 240 especifican múltiplos de 5 segundos, resultando en tiempos de espera de 5 segundos a 20 minutos. Los valores de 241 a 251 especifican de 1 a 11 unidades de 30 minutos, resultando en tiempos de espera de 30 minutos a 5.5 horas. Un valor de 252 significa un tiempo de espera de 21 minutos. Un valor de 253 establece un período de tiempo de espera definido por el proveedor entre 8 y 12 horas, y el valor 254 está reservado. 255 se interpreta como 21 minutos y 15 segundos. Tenga en cuenta que algunas unidades más antiguas pueden tener interpretaciones muy diferentes de estos valores. Esto es similar a la opción -S en hdparm(8).

APMLevel

El nivel de Gestión Avanzada de Energía. Un valor bajo significa gestión agresiva de energía y un valor alto significa mejor rendimiento. La configuración posible varía entre los valores 1 y 127 (que permiten la desaceleración), y los valores 128 y 254 (que no permiten la desaceleración). El mayor grado de gestión de energía se logra con un ajuste de 1, y el mayor rendimiento de E/S con un ajuste de 254. Un valor de 255 se puede usar para deshabilitar completamente la Gestión Avanzada de Energía en la unidad (no todas las unidades admiten la deshabilitación, pero la mayoría sí). Esto es similar a la opción -B en hdparm(8).

AAMLevel

El nivel de Gestión Acústica Automática. La mayoría de las unidades de disco duro modernas tienen la capacidad de reducir la velocidad de los movimientos del cabezal para reducir su salida de ruido. Los valores posibles están entre 0 y 254. 128 es la configuración más silenciosa (y por lo tanto más lenta) y 254 la más rápida (y ruidosa). La mayoría de las unidades tienen solo dos niveles (silencioso/rápido), mientras que otras pueden tener diferentes niveles entre 128 y 254. En este momento, la mayoría de las unidades solo admiten 3 opciones: desactivado, silencioso y rápido. Estos se han asignado los valores 0, 128 y 254 respectivamente, pero el espacio de enteros se ha incorporado para una futura expansión, en caso de que esto cambie. Esto es similar a la opción -M en hdparm(8).

WriteCacheEnabled

Un booleano que especifica si habilitar o deshabilitar la Caché de Escritura. Los valores válidos para esta clave son "true" y "false". Esto es similar a la opción -W en hdparm(8). Esta clave se añadió en 2.1.

ReadLookaheadEnabled

Un booleano que especifica si habilitar o deshabilitar la Lectura Anticipada. Los valores válidos para esta clave son "true" y "false". Esto es similar a la opción -A en hdparm(8). Esta clave se añadió en 2.6.0.

INFORMACIÓN DE DISPOSITIVO

udisks se basa en versiones recientes de udev(7) y el kernel de Linux. Las propiedades del dispositivo influyentes en la base de datos de udev incluyen:

UDISKS_SYSTEM

Si se establece, esto anula el valor de la propiedad HintSystem.

UDISKS_IGNORE

Si se establece, esto anula el valor de la propiedad HintIgnore.

UDISKS_AUTO

Si se establece, esto anula el valor de la propiedad HintAuto.

UDISKS_CAN_POWER_OFF

Si se establece, esto anula el valor de la propiedad CanPowerOff.

UDISKS_NAME

El nombre a usar para el dispositivo al presentarlo en una interfaz de usuario. Esto corresponde a la propiedad HintName.

UDISKS_ICON_NAME

El icono a usar para el dispositivo al presentarlo en una interfaz de usuario. Si se establece, el nombre debe cumplir con la especificación del tema de iconos de freedesktop.org[4]. Esto corresponde a la propiedad HintIconName.

UDISKS_SYMBOLIC_ICON_NAME

El icono a usar para el dispositivo al presentarlo en una interfaz de usuario utilizando un icono simbólico. Si se establece, el nombre debe cumplir con la especificación del tema de iconos de freedesktop.org[4]. Esto corresponde a la propiedad HintSymbolicIconName.

UDISKS_FILESYSTEM_SHARED

Si se establece en 1, el sistema de archivos del dispositivo se montará en un directorio compartido (por ejemplo, /media/NombreVolumen) en lugar de un directorio privado (por ejemplo, /run/media/$USER/NombreVolumen) cuando se maneje el método Filesystem.Mount().

ID_SEAT

El asiento físico al que está adjunto el dispositivo. Si no se establece o se establece en una cadena vacía, se asume "seat0" (el primer asiento).

ID_ATA_SMART_ACCESS

Anula el método de acceso para la recuperación de datos SMART. Los valores válidos incluyen: sat16, sat12, linux-ide, sunplus, jmicron, none y auto (predeterminado). Especifique none para evitar cualquier E/S, en tal caso, la propiedad SmartUpdated siempre será igual a "0".

ESTABILIDAD DE LA API

udisks garantiza una API de D-Bus estable dentro de la misma versión principal y esta garantía también se extiende a la biblioteca del lado del cliente libudisks2. Además, varias versiones principales de udisks pueden instalarse y operar al mismo tiempo, aunque la interoperabilidad puede ser limitada; por ejemplo, un dispositivo montado usando la API N.x de udisks puede requerir autorización adicional si se intenta desmontar a través de la API (N-1).x.

Los desarrolladores de udisks no prevén romper la API, pero se reservan el derecho de hacerlo y, si ocurre, prometen aumentar la versión principal y garantizar que la nueva versión principal de udisks sea instalable en paralelo con cualquier versión principal anterior. Sin embargo, tenga en cuenta que los programas, páginas de manual y otros artefactos pueden cambiar de nombre (por ejemplo, adoptar un sufijo "2") para dar cabida a la próxima versión principal. Por lo tanto, las aplicaciones no pueden confiar en que herramientas como, por ejemplo, udisksctl(1) estén disponibles. Además, no hay garantía de que las opciones, los modificadores de línea de comandos, etc. de las herramientas de línea de comandos o similares permanezcan estables.

En su lugar, las aplicaciones solo deben usar la API de D-Bus, la biblioteca libudisks2 o herramientas como dbus-send(1) o gdbus(1) para interactuar con

NAME

udisks - management daemon for storage devices

DESCRIPTION

udisks is a daemon that manages storage devices. It can be used for operations like partitioning disks, formatting partitions with file systems, managing swap devices and managing RAID arrays. It is a daemon that runs in the background and listens for requests coming in over the system message bus.

udisks is implemented as a set of D-Bus1 services. The main service is called udisksd, which can be found in the udisksd(8) man page.

ACCESS CONTROL

udisks uses polkit(8) for access control. All operations performed by udisks are subject to authorization. By default, only users in the wheel group can perform privileged operations like partitioning and formatting disks. Users can grant or deny permissions using polkit policies.

DRIVE CONFIGURATION

udisks provides a mechanism for configuring drives. This can be used to e.g. disable certain drive features or to configure specific drive settings. Note that drive configuration is not always supported by hardware, and may be restricted by operating system policies.

DEVICE INFORMATION

udisks provides a wealth of information about storage devices, including partition tables, file systems, RAID devices, SMART status, drive health and more. This information is available through the D-Bus API, and can be used by applications like GNOME Disks.

API STABILITY

The udisks API is considered stable. However, the stability of the API is tied to the stability of the operating system vendor's release cycle. For example, if an operating system vendor releases a new major version of udisks, it may not be backward compatible with the previous major version. This means that applications depending on a specific version of udisks may need to be updated when the operating system is updated.

For applications that need a more stable API, it is recommended to use lower-level APIs or higher-level APIs that abstract away the specifics of udisks. For example, desktop applications might benefit from using GVolumeMonitor, which provides a higher-level abstraction over storage devices.

For more information on API stability and best practices, see the AUDIENCE section below.

The D-Bus API is documented in the man page for udisksd(8).

AUDIENCE

The intended audience of udisks include operating system developers working on the higher-level parts of the operating system, for example the desktop shell (such as GNOME[5]) and disk management applications (e.g. GNOME's Disks[6] application). Software on this level typically depend on a specific (major) version of udisks and may even have support for previous versions of udisks or alternative interfaces performing the same role as udisks.

While udisks indeed provides a stable API and a clear upgrade path, it may not be an appropriate dependency for third party applications. For example, if the operating system switches to udisks version N.x and an application is still using the udisks (N-1).x API, the application will not work unless udisks (N-1).x is installed. While this situation is still workable (since both udisks N.x and udisks (N-1).x can be installed) it may not be desirable to ask the user to install the old version - in fact, the operating system vendor may not even provide a packaged version of the old version. Hence, if an application does not want to tie itself to a specific version of the operating system, it should not use udisks.

Viable alternatives to udisks are APIs that are guaranteed to be around for longer time-frames, including:

•Low-level APIs and commands such as e.g. sysfs[7], libudev[8], /proc/self/mountinfo[9] and util-linux[10].
•High-level APIs such as GVolumeMonitor[11].

In particular, for desktop applications it is a much better idea to use something like GVolumeMonitor since it will make the application show the same devices as the desktop shell (e.g. file manager, file chooser and so on) is showing.
