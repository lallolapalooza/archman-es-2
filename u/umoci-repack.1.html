NOMBRE

umoci repack - Empaqueta un paquete de tiempo de ejecución OCI en una etiqueta de imagen

SINOPSIS

umoci repack --image=imagen[:etiqueta] [--no-history] [--history.comment=comentario] [--history.created_by=creado_por] [--history.author=autor] [--history-created=fecha] [--refresh-bundle] paquete

DESCRIPCIÓN

Dado un paquete OCI modificado extraído con umoci-unpack(1) (en la ruta dada paquete), umoci-repack(1) calcula la diferencia del sistema de archivos para el rootfs del paquete OCI. La diferencia se utiliza para generar una capa de diferencia, que luego se añade al manifiesto de imagen original (que se usó como argumento para umoci-unpack(1)) y se etiqueta como una nueva etiqueta de imagen. Entre una llamada a umoci-unpack(1) y umoci-repack(1), los usuarios NO DEBEN modificar la imagen OCI de ninguna manera (específicamente, NO DEBEN usar umoci-gc(1)).

Todos los ajustes de --uid-map y --gid-map se implican de los valores guardados especificados en umoci-unpack(1), por lo que no están disponibles para umoci-repack(1).

Si no se especificó --no-history, se añade una entrada de historial a la imagen OCI etiquetada para este cambio (con las diversas banderas --history. controlando los valores utilizados). Para ver el historial, consulte umoci-stat(1).

Tenga en cuenta que la etiqueta de imagen original (utilizada con umoci-unpack(1)) NO se modificará a menos que el destino de umoci-repack(1) sea la etiqueta de imagen original.

OPCIONES

Las opciones globales se definen en umoci(1).

--image=imagen[:etiqueta]
La etiqueta de destino para la imagen OCI reempaquetada. imagen debe ser una ruta
a una imagen OCI válida (y la misma imagen utilizada en umoci-unpack(1) para crear
el paquete) y etiqueta debe ser un nombre de etiqueta válido. Si otra etiqueta ya tiene
el mismo nombre que etiqueta, se sobrescribirá. Si no se proporciona etiqueta,
se utilizará "latest" por defecto.

--no-history
Hace que no se añada ninguna entrada de historial para esta operación. **Esto NO**
se recomienda para su uso con umoci-repack(1), ya que provoca que el historial no
incluya todas las capas de la imagen, lo que provocará confusión con las herramientas
que examinan el historial de la imagen.

--history.comment=comentario
Comentario para la entrada de historial correspondiente a esta modificación de la imagen.
Si no se especifica, umoci(1) generará un valor dependiente de la implementación.

--history.created_by=creado_por
Entrada CreatedBy para la entrada de historial correspondiente a esta modificación de
la imagen. Si no se especifica, umoci(1) generará un
valor dependiente de la implementación.

--history.author=autor
Valor del autor para la entrada de historial correspondiente a esta modificación de la
imagen. Si no se especifica, este valor será el valor del autor de la imagen después
de cualquier modificación realizada por esta llamada a umoci-config(1).

--history-created=fecha
Fecha de creación para la entrada de historial correspondiente a esta modificación de
la imagen. Debe ser una marca de tiempo con formato ISO8601 (ver date(1)). Si
no se especifica, se utiliza la hora actual.

--refresh-bundle
Si se debe actualizar los metadatos del paquete OCI (es decir, metadatos mtree y umoci)
después de reempaquetar la imagen. Si se establece, el nuevo estado del
paquete debe ser equivalente a desempaquetar la nueva etiqueta de imagen.

EJEMPLO

Lo siguiente descarga una imagen de un registro de docker(1) usando skopeo(1), la desempaqueta con umoci-unpack(1), la modifica y luego la reempaqueta.

% skopeo copy docker://opensuse/amd64:42.2 oci:image:latest
# umoci unpack --image image bundle
# touch bundle/rootfs/a_new_file
# umoci repack --image image:new-42.2 bundle
