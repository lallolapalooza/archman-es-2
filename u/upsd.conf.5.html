UPSD.CONF(5) Manual de NUT UPSD.CONF(5)

NOMBRE

upsd.conf - Configuración del servidor de datos upsd de Network UPS Tools

DESCRIPCIÓN

upsd(8) utiliza este archivo para controlar el acceso al servidor y establecer otros valores de configuración misceláneos. Este archivo contiene detalles sobre los controles de acceso, así que mantenlo seguro. Idealmente, solo el proceso upsd debería poder leerlo.

NOTAS IMPORTANTES

•El contenido de este archivo debe ser texto ASCII puro (los códigos de caracteres que no estén en el rango serán ignorados con un mensaje de advertencia).
•Ajusta los permisos del usuario en tiempo de ejecución para acceder al archivo (y quizás al directorio en el que se encuentra) de modo que solo upsd pueda leerlo; no se necesita acceso de escritura. Es común usar chown root:nut y chmod 640 para establecer permisos de archivo aceptables.
•Los paquetes (y las recetas de compilación) suelen preparar un conjunto de cuentas de usuario y grupo para NUT. Las compilaciones personalizadas con una configuración mínima podrían incluso usar nobody:nogroup o similar, lo cual es intrínsecamente inseguro.
•En sistemas con preocupaciones de seguridad adicionales, los controladores NUT y el servidor de datos deben ejecutarse como cuentas de usuario separadas que serían miembros de un mismo grupo para acceso compartido a archivos de socket Unix locales y al directorio en el que se encuentran, pero grupos diferentes para el acceso a archivos de configuración. Esto requeriría que algunos demonios usen configuraciones personalizadas de usuario, grupo, RUN_AS_USER y/o RUN_AS_GROUP para anular el único valor incorporado.
•Ten en cuenta que los clientes de monitoreo, registro, etc., son solo de red. No necesitan acceso a estos archivos y directorios, y pueden ejecutarse con un usuario y grupo completamente independientes.
•Ten en cuenta la seguridad de cualquier copia de seguridad de este archivo, por ejemplo, los archivos de archivo en los que pueda terminar.

DIRECTIVAS DE CONFIGURACIÓN

MAXAGE segundos

upsd normalmente permite que un controlador deje de responder hasta por 15 segundos antes de declarar los datos como "obsoletos". Si tu controlador tarda mucho en procesar actualizaciones pero está operativo de otra manera, puedes usar MAXAGE para hacer que upsd espere más tiempo.

La mayoría de los usuarios deberían dejar este valor en el valor predeterminado.

TRACKINGDELAY segundos

Cuando están habilitadas las instantáneas de comandos y las variables que configuran el seguimiento de estado, la información de ejecución del estado se conserva durante este período de tiempo y luego se limpia. Esto tiene un valor predeterminado de 3600 (1 hora).

ALLOW_NO_DEVICE Booleano

Normalmente, upsd requiere que se defina al menos una sección de dispositivo en ups.conf cuando el demonio se inicia, para servir sus datos. Para servicios administrados automáticamente, puede ser preferible tener upsd siempre en ejecución y recargar la configuración cuando los dispositivos de alimentación se definan.

Los valores booleanos true, yes, on y 1 significan que el servidor no se negará a iniciarse si no se encuentran secciones de dispositivo en ups.conf.

Los valores booleanos false, no, off y 0 significan que el servidor debe negarse a iniciarse si no se encontraron secciones de dispositivo en ups.conf. Este es el valor predeterminado, a menos que el entorno de llamada establezca una variable con el mismo nombre para forzar un valor para la ejecución actual. Una forma en que esto puede suceder es que alguien descomente la línea en el archivo nut.conf utilizado por los scripts de inicio y los scripts del método de servicio.

ALLOW_NOT_ALL_LISTENERS Booleano

Normalmente, upsd requiere que todas las directivas LISTEN puedan cumplirse en el momento en que se inicia el demonio. Si la dirección IP de tu LAN (o nombre de host) utilizada en una de las directivas LISTEN no siempre es accesible, y por alguna razón no quieres simplemente escuchar en * en la interfaz comodín, sino que, por ejemplo, todavía quieres usar upsmon en localhost, esta opción puede ayudar. Ten en cuenta que tendrías que reiniciar upsd para que capte la dirección IP de LISTEN si aparece más tarde.

Los valores booleanos true, yes, on y 1 significan que el servidor no se negará a iniciarse si puede escuchar en al menos una interfaz.

Los valores booleanos false, no, off y 0 significan que el servidor debe negarse a iniciarse si no puede escuchar en todas y cada una de las interfaces (que no sean localhost) que se encuentran en upsd.conf. Este es el valor predeterminado, a menos que el entorno de llamada establezca una variable con el mismo nombre para forzar un valor para la ejecución actual. Una forma en que esto puede suceder es que alguien descomente la línea en el archivo nut.conf utilizado por los scripts de inicio y los scripts del método de servicio.

STATEPATH ruta

Indica a upsd que busque los sockets de estado del controlador en ruta en lugar de la predeterminada que se compiló en el programa.

Ten en cuenta que los controladores deben usar la misma ruta, por lo que upsd preferirá la configuración con el mismo nombre de la sección global de ups.conf, si está presente, sobre la suya propia.

La variable de entorno NUT_STATEPATH establecida por el llamador (por ejemplo, script de inicio o método de servicio) puede anular esta configuración.

LISTEN interfaz puerto

Vincula un puerto de escucha a la interfaz especificada por su dirección o nombre de Internet. Esto puede ser útil en hosts con múltiples interfaces. No debes confiar exclusivamente en esto para la seguridad, ya que puede ser subvertido en muchos sistemas.

Opcionalmente, escucha en el puerto TCP puerto en lugar del valor predeterminado que se compiló en el código. Esto anula cualquier valor que hayas establecido con configure --with-port. Si no lo cambias con configure o este valor, upsd escuchará en el puerto 3493 para esta interfaz.

Se pueden especificar múltiples direcciones LISTEN. El valor predeterminado es vincular a 127.0.0.1 si no se especifican direcciones LISTEN (y también ::1 si se compiló el soporte IPv6).

Para escuchar en todas las interfaces disponibles y direcciones IP configuradas de tu sistema, también puedes usar :: para IPv6 y 0.0.0.0 para IPv4, respectivamente. Como caso especial, una única directiva LISTEN * <puerto> (con un asterisco) intentará escuchar en las direcciones IP comodín IPv6 (::0) e IPv4 (0.0.0.0), sujeto a los argumentos de línea de comandos de upsd o a la configuración del sistema. Ten en cuenta que si el sistema admite el direccionamiento IPv6 mapeado a IPv4 según RFC-3493, y no permite deshabilitar este modo, entonces puede haber un socket de escucha para manejar ambas familias de direcciones.

LISTEN 127.0.0.1
LISTEN 192.168.50.1
LISTEN miredes.midominio
LISTEN ::1
LISTEN 2001:0db8:1234:08d3:1319:8a2e:0370:7344

Este parámetro solo se leerá al inicio. Necesitarás reiniciar (en lugar de simplemente recargar) upsd para aplicar cualquier cambio realizado aquí.

Ten en cuenta que las versiones anteriores de NUT podrían haber utilizado el modo de direccionamiento IPv6 mapeado a IPv4 (a veces también conocido como "doble pila"), si lo proporcionaba el sistema. Las versiones actuales (desde la versión 2.8.1 de NUT) intentan explícitamente restringir sus sockets de escucha para admitir solo una familia de direcciones en cada socket, y así evitar el modo mapeado a IPv4 siempre que sea posible.

MAXCONN conexiones

Esto tiene un valor predeterminado igual al máximo permitido en tu sistema. Cada UPS, cada dirección LISTEN y cada cliente cuentan como una conexión. Si el servidor se queda sin conexiones, ya no aceptará nuevas conexiones de clientes entrantes. Solo establece esto si sabes exactamente lo que estás haciendo.

CERTFILE archivo de certificado

Cuando se compila con soporte SSL con backend OpenSSL, puedes introducir el archivo de certificado aquí.

Los certificados deben estar en formato PEM y deben estar ordenados comenzando por el certificado del sujeto (certificado del servidor), seguido por los certificados intermedios de CA (si aplica) y el nivel más alto (raíz) de CA. Debe terminar con la clave del servidor. Consulta docs/security.txt en las fuentes de NUT, o el capítulo de Seguridad del manual de usuario de NUT, para obtener más información sobre el soporte SSL en NUT.

CERTPATH base de datos de certificados

Cuando se compila con soporte SSL con backend NSS, puedes introducir la ruta del certificado aquí.

Los certificados se almacenan en una base de datos dedicada (datos divididos en 3 archivos). Especifica la ruta del directorio de la base de datos.

CERTIDENT nombre del certificado contraseña de la base de datos

Cuando se compila con soporte SSL con backend NSS, puedes especificar el nombre del certificado a recuperar de la base de datos para autenticarse y la contraseña requerida para acceder a la clave privada relacionada con el certificado.

Nota
Asegúrate de encerrar el "nombre del certificado" entre comillas dobles si estás utilizando un valor con espacios en él.

upsd.conf(5) — Network UPS Tools 2.8.4

NAME

upsd.conf

Network UPS Tools server configuration

DESCRIPTION

The upsd.conf file contains configuration directives for the upsd(8) server process.

upsd(8) is the server that listens on the network for client connections (e.g. from upsc(8) or upsmon(8)) and mediates access to the UPS driver.

It is important to consult the documentation for the specific version of Network UPS Tools that you are using, as the options available and their behavior may change between versions. upsd.conf directives are case sensitive.

The configuration file consists of directives, one per line. Directives consist of a name, followed by a value. Comments start with a ‘#’ character and extend to the end of the line. Leading and trailing whitespace is ignored.

The default location for this file is /etc/nut/upsd.conf.

IMPORTANT NOTES

  • upsd(8) must be able to read this file.
  • If you change the configuration file, you must restart or reload upsd(8) for the changes to take effect.

CONFIGURATION DIRECTIVES

I-PACKET-TIMEOUT INTEGER
Sets the timeout in seconds for receiving data from the UPS driver. Defaults to 10 seconds.
O-PACKET-TIMEOUT INTEGER
Sets the timeout in seconds for sending data to the UPS driver. Defaults to 5 seconds.
MAXAGE INTEGER
Sets the maximum age in seconds for stale data from the UPS driver. If data is older than this, it will be considered stale. Defaults to 15 seconds.
DEADTIME INTEGER
Sets the time in seconds after which a UPS driver is considered dead if no data has been received. Defaults to 30 seconds.
HOST−CONNECT−TIMEOUT INTEGER
Sets the timeout in seconds for establishing a connection to the UPS driver. Defaults to 5 seconds.
MAXTHREADS INTEGER
Sets the maximum number of worker threads upsd(8) can create to handle client connections. Defaults to 16.
MAXCLIENTS INTEGER
Sets the maximum number of concurrent client connections. Defaults to 16.
LISTEN IP-ADDRESS
Specifies the IP address on which upsd(8) should listen for incoming connections. If not specified, upsd(8) will listen on all available network interfaces.
PORT PORT-NUMBER
Specifies the port number on which upsd(8) should listen for incoming connections. Defaults to 3493.
CERTIFICATE-REQUEST-LEVEL certificate request level

When compiled with SSL support with NSS backend and client certificate validation (disabled by default, see ‘docs/security.txt` in NUT sources), you can specify if upsd requests or requires clients’ certificates.

Possible values are:

•0 to not request to clients to provide any certificate
•1 to require to all clients a certificate
•2 to require to all clients a valid certificate
DISABLE-WEAK-SSL BOOLEAN
Tell upsd to disable older/weak SSL/TLS protocols and ciphers. With relatively recent versions of OpenSSL or NSS it will be restricted to TLSv1.2 or better.

Unless you have really ancient clients, you probably want to enable this. Currently disabled by default to ensure compatibility with existing setups.

DEBUG-MIN INTEGER
Optionally specify a minimum debug level for upsd data daemon, e.g. for troubleshooting a deployment, without impacting foreground or background running mode directly. Command-line option -D can only increase this verbosity level.

Note
If the running daemon receives a reload command, presence of the DEBUG_MIN NUMBER value in the configuration file can be used to tune debugging verbosity in the running service daemon (it is recommended to comment it away or set the minimum to explicit zero when done, to avoid huge journals and I/O system abuse). Keep in mind that for this run-time tuning, the DEBUG_MIN value present in reloaded configuration files is applied instantly and overrides any previously set value, from file or CLI options, regardless of older logging level being higher or lower than the newly found number; a missing (or commented away) value however does not change the previously active logging verbosity.
