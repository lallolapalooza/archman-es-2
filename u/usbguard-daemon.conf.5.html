NOMBRE

usbguard-daemon.conf - Archivo de configuración del demonio USBGuard

DESCRIPCIÓN

El archivo usbguard-daemon.conf es cargado por el demonio USBGuard después de analizar sus opciones de línea de comandos. Se utiliza para configurar los parámetros de tiempo de ejecución del demonio. La ruta de búsqueda predeterminada es /etc/usbguard/usbguard-daemon.conf. Puede ser anulada utilizando la opción de línea de comandos -c, consulte usbguard-daemon(8) para más detalles.

OPCIONES

RuleFile=ruta

El demonio USBGuard utilizará este archivo para cargar el conjunto de reglas de la política desde él y para escribir nuevas reglas recibidas a través de la interfaz IPC. Por defecto: %sysconfdir%/usbguard/rules.conf

RuleFolder=ruta

El demonio USBGuard utilizará esta carpeta para cargar el conjunto de reglas de la política desde ella y para escribir nuevas reglas recibidas a través de la interfaz IPC. Normalmente, la opción se establece en /etc/usbguard/rules.d/. El demonio USBGuard debe comportarse como cualquier otro demonio estándar de Linux, por lo tanto, carga los archivos de reglas en orden alfanumérico. Los nombres de archivo dentro del directorio RuleFolder deben comenzar con un prefijo de dos dígitos que indique la posición en la que las reglas son escaneadas por el demonio. El uso de RuleFile y RuleFolder al mismo tiempo está permitido. Sin embargo, la modificación de la política permanente no es posible si se cumple una de las siguientes condiciones:
•Ni RuleFile ni RuleFolder están especificados.
•RuleFile no está especificado, RuleFolder lo está pero no contiene ningún archivo donde podamos guardar reglas permanentes.

ImplicitPolicyTarget=objetivo

Cómo tratar los dispositivos USB que no coinciden con ninguna regla en la política. El objetivo debe ser uno de allow (permitir), block (bloquear) o reject (rechazar, eliminar lógicamente el nodo del dispositivo del sistema). Por defecto: block

PresentDevicePolicy=política

Cómo tratar los dispositivos USB que ya están conectados cuando se inicia el demonio. La política debe ser una de allow (permitir), block (bloquear), reject (rechazar), keep (mantener cualquier estado en el que se encuentre actualmente el dispositivo) o apply-policy (evaluar el conjunto de reglas para cada dispositivo presente). Por defecto: apply-policy

PresentControllerPolicy=política

Cómo tratar los dispositivos **controlador** USB que ya están conectados cuando se inicia el demonio. Una de allow (permitir), block (bloquear), reject (rechazar), keep (mantener) o apply-policy (aplicar política). Por defecto: keep

InsertedDevicePolicy=política

Cómo tratar los dispositivos USB que ya están conectados *después* de que el demonio se inicia. Una de block (bloquear), reject (rechazar), apply-policy (aplicar política). Por defecto: apply-policy

AuthorizedDefault=authorizedDefault

El demonio USBGuard modifica algunos de los atributos de autorización predeterminados de los dispositivos controladores. Esta configuración le permite definir a qué valor se establece la autorización predeterminada. Authorized default (autorización predeterminada) debe ser uno de keep (mantener el estado de autorización), none (ninguno, cada nuevo dispositivo comienza desautorizado), all (todos, cada nuevo dispositivo comienza autorizado) o internal (interno, los dispositivos internos comienzan autorizados, los externos no). Por defecto: none

RestoreControllerDeviceState=booleano

El demonio USBGuard modifica algunos atributos de los dispositivos controladores, como el estado de autorización predeterminado de las nuevas instancias de dispositivos hijos. Usando esta configuración, puede controlar si el demonio intentará restaurar los valores de los atributos al estado anterior a la modificación al apagarse. Por defecto: false

DeviceManagerBackend=backend

Qué implementación de backend del administrador de dispositivos utilizar. Backend debe ser uno de uevent (predeterminado) o umockdev (útil para pruebas). El backend UEvent es una implementación basada en netlink que utiliza sysfs para escanear dispositivos presentes y un socket de uevent para recibir eventos relacionados con dispositivos USB. El administrador de dispositivos basado en UMockDev es capaz de simular dispositivos basándose en archivos de registro de umockdev. Por defecto: uevent

IPCAllowedUsers=nombredeusuario [nombredeusuario ...]

Una lista de nombres de usuario separados por espacios a los que el demonio aceptará conexiones IPC. Por defecto: root

IPCAllowedGroups=nombrede grupo [nombrede grupo ...]

Una lista de nombres de grupos separados por espacios a los que el demonio aceptará conexiones IPC.

IPCAccessControlFiles=ruta

Los archivos en esta ubicación serán interpretados por el demonio como archivos de definición de control de acceso IPC. Consulte la sección CONTROL DE ACCESO IPC para más detalles.

DeviceRulesWithPort=booleano

Genera reglas específicas del dispositivo incluyendo el atributo "via-port". Por defecto: false

AuditBackend=backend

Backend de registro de eventos de auditoría de USBGuard. El valor backend debe ser uno de FileAudit o LinuxAudit. Por defecto: FileAudit

AuditFilePath=rutadearchivo

Ruta del archivo de registro de eventos de auditoría de USBGuard. Requerido si AuditBackend está configurado como FileAudit. Por defecto: %localstatedir%/log/usbguard/usbguard-audit.log

HidePII=booleano

Oculta información de identificación personal como números de serie de dispositivos y hashes de descriptores (que incluyen el número de serie) de las entradas de auditoría. Por defecto: false

CONSIDERACIONES DE SEGURIDAD

IPC

El demonio proporciona la interfaz IPC pública de USBGuard. Dependiendo de la configuración predeterminada de su distribución, el acceso a esta interfaz está limitado solo a un grupo específico o a un usuario específico. Por favor, configure las opciones IPCAllowedUsers, IPCAllowedGroups o IPCAccessControlFiles para limitar el acceso a la interfaz IPC. **No deje la ACL sin configurar, ya que esto expondrá la interfaz IPC a todos los usuarios locales y les permitirá manipular el estado de autorización de los dispositivos USB y modificar la política de USBGuard**.

La opción de configuración RestoreControllerDeviceState

Si se establece en true, la política de autorización USB podría ser eludida realizando algún tipo de ataque al demonio (a través de un exploit local o de un dispositivo USB) para hacer que se apague y restaure al estado predeterminado del sistema operativo (conocido por ser permisivo).

CONTROL DE ACCESO IPC

El acceso a la interfaz IPC de USBGuard se puede limitar por usuario o grupo. Además, utilizando los archivos de Control de Acceso IPC, es posible limitar el acceso hasta el nivel de Secciones y Privilegios como se explica a continuación.

Recomendado: IPCAccessControlFiles

Cuando configura la opción IPCAccessControlFiles, el demonio buscará archivos de control de acceso IPC en el directorio especificado por el valor establecido. Cada archivo en el directorio se procesa de la siguiente manera:

1.El nombre base del archivo se interpreta como un nombre de usuario, UID, nombre de grupo o GID. Si el nombre comienza con : (dos puntos), se asume que el resto del nombre representa un identificador de grupo (nombre de grupo o GID en caso de una cadena puramente numérica). De lo contrario, se interpreta como un identificador de usuario (nombre de usuario o UID en caso de una cadena puramente numérica).
2.El contenido del archivo se analiza como líneas con el formato Section=[privilegio1][,privilegio2] ... que especifican los privilegios de la sección. Si se omite una sección, se asume que no se otorgan privilegios para esa sección.

Secciones y privilegios disponibles:

•Devices
•modify: Cambiar el estado de autorización de los dispositivos, incluyendo cambios permanentes (es decir, modificación de reglas específicas del dispositivo en la política).
•list: Capacidad para obtener una lista de dispositivos reconocidos y sus atributos.
•listen: Escuchar la presencia de dispositivos y los cambios de política de dispositivos.
•Policy
•modify: Añadir reglas o eliminar cualquier regla de la política.
•list: Capacidad para ver la política actualmente impuesta.
•Exceptions
•listen: Recibir mensajes de excepción.

NAME

usbguard-daemon.conf

configuration file for usbguard-daemon

DESCRIPTION

This file contains configuration options for the usbguard-daemon(8).

OPTIONS

The configuration file consists of KEY=VALUE pairs separated by newlines. Lines starting with a hash sign (#) are comments. The values are string, integer or boolean values. The default values are listed in the comments for each option.

IPCAllowedDevices

# Example:
# IPCAllowedDevices=modify,list,listen

A comma-separated list of device identifiers for which the corresponding IPC access rights are granted to the client connecting to the usbguard-daemon(8). The following device identifiers are supported:

Devices: A special identifier that grants access to all IPC methods that are
         associated with the Devices object. Currently supported operations are:
         modify: Set values of run-time parameters.
         list: Get values of run-time parameters.
         listen: Listen to property parameter changes.
Policy: A special identifier that grants access to all IPC methods that are
        associated with the Policy object. Currently supported operations are:
        list: Get values of the rules.
        apply: Apply rules from a file.
        override: Override rules by adding new ones.
        remove: Remove rules.
        listen: Listen to policy changes.
Exceptions: A special identifier that grants access to all IPC methods that are
            associated with the Exceptions object. Currently supported operations are:
            add: Add new exceptions.
            remove: Remove existing exceptions.
            list: List exceptions.
            listen: Listen to exception changes.

The following is a generally usable and reasonably safe example of an access control file. It allows one to modify USB device authorization state (Devices=modify), list USB devices (Devices=list), listen to USB device related events (Devices=listen), list USB authorization policy rules (Policy=list) and listen to exception events (Exceptions=listen):

Devices=modify,list,listen
Policy=list
Exceptions=listen

You can create or remove the IPC access control files using usbguard add-user and usbguard remove-user CLI commands. See usbguard(1) for more details. If you want to create the IPC access control files manually, you need to set the files permissions to 0600.

Legacy: IPCAllowedUsers and IPCAllowedGroups

Example configuration allowing full IPC access to users root, joe and members of the group wheel:

IPCAllowedUsers=root joe
IPCAllowedGroups=wheel
