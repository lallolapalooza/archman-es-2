udplite(7) Información Miscelánea Manual udplite(7)

NOMBRE

udplite — Protocolo de Datagramas de Usuario Ligero

SINOPSIS

#include <sys/socket.h>
sockfd = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDPLITE);

DESCRIPCIÓN

Esta es una implementación del Protocolo de Datagramas de Usuario Ligero (UDP-Lite), tal como se describe en la RFC 3828.

UDP-Lite es una extensión de UDP (RFC 768) para soportar sumas de verificación de longitud variable. Esto tiene ventajas para algunos tipos de transporte multimedia que pueden hacer uso de datagramas ligeramente dañados, en lugar de que sean descartados por protocolos de capa inferior.

La cobertura de suma de verificación de longitud variable se establece a través de una opción setsockopt(2). Si esta opción no está establecida, la única diferencia con UDP es el uso de un identificador de protocolo IP diferente (número IANA 136).

La implementación de UDP-Lite es una extensión completa de udp(7); es decir, comparte la misma API y comportamiento de API, y además ofrece dos opciones de socket para controlar la cobertura de suma de verificación.

Formato de dirección

UDP-Litev4 utiliza el formato de dirección sockaddr_in descrito en ip(7). UDP-Litev6 utiliza el formato de dirección sockaddr_in6 descrito en ipv6(7).

Opciones de socket

Para establecer o obtener una opción de socket UDP-Lite, llame a getsockopt(2) para leer o setsockopt(2) para escribir la opción con el argumento de nivel de opción establecido en IPPROTO_UDPLITE. Además, todas las opciones de socket de IPPROTO_UDP son válidas en un socket UDP-Lite. Consulte udp(7) para obtener más información.

Las dos opciones siguientes son específicas de UDP-Lite.

UDPLITE_SEND_CSCOV
Esta opción establece la cobertura de suma de verificación del remitente y toma un int como argumento, con un valor de cobertura de suma de verificación en el rango 0..2^16-1.
Un valor de 0 significa que todo el datagrama está siempre cubierto. Los valores del 1 al 7 son ilegales (RFC 3828, 3.1) y se redondean al mínimo de cobertura de 8.
Con respecto a los jumbogramas IPv6 (RFC 2675), la cobertura de suma de verificación de UDP-Litev6 se limita a los primeros 2^16-1 octetos, según la RFC 3828, 3.5. Por lo tanto, los valores más altos se truncan silenciosamente a 2^16-1. En caso de duda, el valor de cobertura actual siempre se puede consultar utilizando getsockopt(2).
UDPLITE_RECV_CSCOV
Este es el análogo del lado del receptor y utiliza el mismo formato de argumento y rango de valores que UDPLITE_SEND_CSCOV. Esta opción no es necesaria para habilitar el tráfico con cobertura parcial de suma de verificación. Su función es la de un filtro de tráfico: cuando está habilitada, instruye al kernel a descartar todos los paquetes que tengan una cobertura menor que el valor de cobertura especificado.
Cuando el valor de UDPLITE_RECV_CSCOV excede la cobertura real del paquete, los paquetes entrantes se descartan silenciosamente, pero pueden generar un mensaje de advertencia en el registro del sistema.

ERRORES

Todos los errores documentados para udp(7) pueden ser devueltos. UDP-Lite no añade errores adicionales.

VERSIÓNES

UDP-Litev4/v6 apareció por primera vez en Linux 2.6.20.

ERRORES DE PROGRAMACIÓN

Donde falte el soporte de glibc, se necesitan las siguientes definiciones:


#define IPPROTO_UDPLITE     136
#define UDPLITE_SEND_CSCOV  10
#define UDPLITE_RECV_CSCOV  11
