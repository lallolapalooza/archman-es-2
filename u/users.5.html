USUARIOS(5) Archivo de autorización de usuarios de FreeRADIUS USUARIOS(5)

NOMBRE

users - archivo de autorización de usuarios para el servidor FreeRADIUS

DESCRIPCIÓN

Los archivos users residen en el directorio de configuración del módulo files, por defecto /etc/raddb/mods-config/files/. Contiene una serie de directivas de configuración que son utilizadas por el módulo files para decidir cómo autorizar y autenticar cada solicitud de usuario.

Cada línea que comienza con un signo de almohadilla ('#') se trata como un comentario y se ignora.

Cada entrada del archivo comienza con un nombre de usuario, seguido de una lista (posiblemente vacía) de elementos de verificación, todo en una sola línea. La siguiente línea comienza con una tabulación y una lista (posiblemente vacía) de elementos de respuesta. Cada elemento en la lista de elementos de verificación o respuesta es un atributo de la forma nombre = valor. Se pueden colocar varios elementos en una línea, en cuyo caso deben separarse por comas. Los elementos de respuesta pueden especificarse en varias líneas, en cuyo caso cada línea debe terminar con una coma, y la última línea de los elementos de respuesta no debe terminar con una coma.

Los elementos de verificación son una lista de atributos utilizados para hacer coincidir la solicitud entrante. Si el nombre de usuario coincide, Y todos los elementos de verificación coinciden con la solicitud entrante, entonces los elementos de respuesta se agregan a la lista de atributos que se utilizarán en la respuesta a esa solicitud. Este proceso se repite para todas las entradas del archivo users.

Si la solicitud entrante NO coincide con ninguna entrada, la solicitud es rechazada.

ADVERTENCIAS

La palabra clave especial DEFAULT coincide con cualquier nombre de usuario.

Las entradas se procesan en orden, desde la parte superior del archivo users, hacia abajo. Si una entrada contiene el elemento especial Fall-Through = No como atributo de respuesta, el procesamiento del archivo se detiene y no se emparejan más entradas. Cualquier lista de elementos de respuesta sin ningún atributo Fall-Through se trata como si incluyera un atributo Fall-Through = No.

Si una entrada contiene el elemento especial Fall-Through = Yes como atributo de respuesta, el procesamiento continúa con la siguiente entrada en orden.

Se debe tener cuidado al usar Fall-Through. El servidor debe ser probado en modo de depuración con una serie de solicitudes de prueba, para verificar que las entradas configuradas se comporten como se espera.

El atributo especial Auth-Type se utiliza para identificar el tipo de autenticación que se utilizará para ese usuario. Consulte el archivo dictionary para obtener una lista de valores permitidos para el atributo Auth-Type.

Una vez que se ha procesado el archivo users, la solicitud se autentica, utilizando el método dado por Auth-Type.

OPERADORES

Además del operador =, se pueden usar otros operadores para los atributos en la lista de elementos de verificación o de respuesta. La siguiente es una lista de operadores y su significado.

Atributo = Valor
No permitido como elemento de verificación para atributos del protocolo RADIUS. Se permite para atributos de configuración del servidor (Auth-Type, etc.), y establece el valor de un atributo, solo si no hay otro elemento del mismo atributo.
Como elemento de respuesta, significa "agregar el elemento a la lista de respuestas, pero solo si no hay otro elemento del mismo atributo".
Atributo := Valor
Siempre coincide como elemento de verificación y reemplaza en los elementos de configuración cualquier atributo del mismo nombre. Si no aparece ningún atributo de ese nombre en la solicitud, se agrega este atributo.
Como elemento de respuesta, tiene un significado idéntico, pero para los elementos de respuesta, en lugar de los elementos de solicitud.
Atributo == Valor
Como elemento de verificación, coincide si el atributo nombrado está presente en la solicitud Y tiene el valor dado.
No permitido como elemento de respuesta.
Atributo += Valor
Siempre coincide como elemento de verificación y agrega el atributo actual con el valor al final de la lista de elementos de configuración.
Como elemento de respuesta, tiene un significado idéntico, pero el atributo se agrega al final de la lista de elementos de respuesta.
Atributo ^= Valor
Siempre coincide como elemento de verificación y agrega el atributo actual con el valor al principio de la lista de elementos de configuración.
Como elemento de respuesta, tiene un significado idéntico, pero el atributo se agrega al principio de la lista de elementos de respuesta.
Atributo != Valor
Como elemento de verificación, coincide si el atributo dado está presente en la solicitud Y no tiene el valor dado.
No permitido como elemento de respuesta.
Atributo > Valor
Como elemento de verificación, coincide si la solicitud contiene un atributo con un valor mayor que el dado.
No permitido como elemento de respuesta.
Atributo >= Valor
Como elemento de verificación, coincide si la solicitud contiene un atributo con un valor mayor o igual al dado.
No permitido como elemento de respuesta.
Atributo < Valor
Como elemento de verificación, coincide si la solicitud contiene un atributo con un valor menor que el dado.
No permitido como elemento de respuesta.
Atributo <= Valor
Como elemento de verificación, coincide si la solicitud contiene un atributo con un valor menor o igual al dado.
No permitido como elemento de respuesta.
Atributo =* Valor
Como elemento de verificación, coincide si la solicitud contiene el atributo nombrado, sin importar el valor.
No permitido como elemento de respuesta.
Atributo !* Valor
Como elemento de verificación, coincide si la solicitud no contiene el atributo nombrado, sin importar el valor.
No permitido como elemento de respuesta.

EJEMPLOS

bob	Cleartext-Password := "hola"
Las solicitudes que contengan el atributo User-Name, con el valor "bob", serán autenticadas usando la contraseña "correcta" "hola". No hay elementos de respuesta, por lo que la respuesta estará vacía.
DEFAULT Service-Type == Framed-User, Framed-Protocol == PPP
	Service-Type = Framed-User,
	Framed-Protocol = PPP,
	Fall-Through = Yes
Si el paquete de solicitud contiene los atributos Service-Type y Framed-Protocol, con los valores dados, entonces incluya esos atributos en la respuesta.

Es decir, dale al usuario lo que pide. Esta entrada también muestra cómo especificar varios elementos de respuesta.

Consulte el archivo users suministrado con el servidor para ver más ejemplos y comentarios.

SUGERENCIAS

Ejecute el servidor en modo de depuración (-X) y use el programa radclient para enviarle paquetes de prueba que crea que coincidirán con entradas específicas. El servidor imprimirá qué entradas coincidieron para esa solicitud, para que pueda verificar sus expectativas. ¡Esto debería ser lo PRIMERO que haga si sospecha problemas con el archivo!

Se debe tener cuidado al escribir entradas para el archivo users. Es fácil configurar incorrectamente el servidor de modo que se acepten solicitudes cuando se desea rechazarlas. Las entradas deben ordenarse, y el elemento Fall-Through debe usarse ÚNICAMENTE donde sea necesario.

Las entradas que rechazan ciertas solicitudes deben ir al principio del archivo y no deben tener un elemento Fall-Through en sus elementos de respuesta. Las entradas para usuarios específicos, que no tienen un elemento Fall-Through, deben venir después. Cualquier entrada DEFAULT generalmente debe ir al final, excepto como entradas de paso que establecen atributos de respuesta.
