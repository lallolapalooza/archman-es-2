Paquete: unibilium

Licencias: LGPL3

doc::unibi_format(3) unibilium doc::unibi_format(3)

NOMBRE

unibi_format, unibi_run - interpretar una cadena de formato terminfo

SINOPSIS

#include <unibilium.h>

void unibi_format(
    unibi_var_t var_dyn[26],
    unibi_var_t var_static[26],
    const char *fmt,
    unibi_var_t param[9],
    void (*out)(void *, const char *, size_t),
    void *ctx1,
    void (*pad)(void *, size_t, int, int),
    void *ctx2
);

size_t unibi_run(const char *fmt, unibi_var_t param[9], char *p, size_t n);

DESCRIPCIÓN

"unibi_format" toma una cadena de formato fmt y la ejecuta. Toda la salida se realiza mediante llamadas (posiblemente repetidas) a out. En las llamadas a out, el primer argumento es siempre ctx1, el segundo argumento es un puntero a un trozo de datos y el tercer argumento es un contador que especifica el tamaño del trozo en bytes.

pad se utiliza cuando la cadena de formato contiene instrucciones de relleno de "$<...>". En las llamadas a pad, el primer argumento es siempre ctx2, el segundo argumento es el retraso en décimas de milisegundo, el tercer argumento es un indicador booleano que indica si "*" (retraso proporcional) se especificó en la cadena de formato, y el cuarto argumento es un indicador booleano que indica si "/" (relleno forzado) se especificó en la cadena de formato. Por lo tanto, una cadena de formato de "$<5/>" se traduciría en "pad(ctx2, 50, 0, 1)". Puede pasar un puntero nulo para pad; en ese caso, las instrucciones de relleno se omiten silenciosamente.

Los valores de param se utilizan para los códigos de formato %p1 .. %p9; los valores de var_dyn y var_static se utilizan para las llamadas variables dinámicas/estáticas %Pa .. %Pz y %PA .. %PZ, respectivamente.

"unibi_run" es un envoltorio alrededor de "unibi_format". Pasa dos arreglos (cada uno inicializado a 26 ceros) como var_dyn y var_static. fmt y param se pasan sin cambios. Ignora el relleno y coloca toda la salida normal en el búfer apuntado por p. n es el tamaño del búfer; como máximo se escribirán n bytes en p.

VALOR DE RETORNO

"unibi_run" devuelve el número de bytes que se habrían escrito si el búfer hubiera sido lo suficientemente grande. Por lo tanto, el número de bytes válidos en p después de una llamada a "unibi_run" es el mínimo de n y el valor de retorno de "unibi_run".
