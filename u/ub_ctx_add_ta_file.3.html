DESCRIPCIÓN

Unbound es una implementación de un resolvedor DNS, que realiza caché y validación DNSSEC. Esta es la API de la biblioteca, para usar la biblioteca -lunbound. El demonio del servidor se describe en unbound(8). La biblioteca funciona independientemente de un servidor unbound en ejecución, y se puede utilizar para convertir nombres de host en direcciones IP y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de claves públicas de los resultados con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Se puede crear y eliminar en cualquier momento. Crear una nueva elimina cualquier configuración previa (como claves de confianza) y borra cualquier resultado en caché.

Las funciones son seguras para hilos (thread-safe), y un contexto se puede utilizar en un entorno multihilo (así como en uno de un solo hilo). La resolución (y validación) también se puede realizar de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve el control de la llamada inmediatamente, de modo que el procesamiento pueda continuar, mientras que los resultados estarán disponibles más tarde.

Las funciones se discuten una por una a continuación.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza por defecto. Utilice ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esta función, utilice las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si utiliza lib openssl (la aplicación llama a estas funciones una vez para la inicialización). Openssl 1.0.0 o posterior utiliza la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y no se llaman a las devoluciones de llamada para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que permite especificar una de las opciones del formato de archivo de configuración, consulte unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como añadir anclas de confianza, existen rutinas especiales. Pase el nombre de la opción con los dos puntos finales (':').
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene un valor de opción. Algunas opciones no se pueden obtener, y otras devuelven una lista separada por saltos de línea. Pase el nombre de la opción sin los dos puntos finales (':'). El valor devuelto debe ser liberado (free(2)) por el llamador.
ub_ctx_config
Una interfaz para usuarios avanzados que permite especificar un archivo de configuración de unbound, consulte unbound.conf(5), que se lee para la configuración. No todas las opciones son relevantes. Para algunas opciones específicas, como añadir anclas de confianza, existen rutinas especiales. Esta función solo es segura para hilos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no se llame en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se reenviarán las consultas DNS, el resolvedor de caché a utilizar. Dirección IP4 o IP6. Reenvía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolvedor recursivo. Si el proxy no es capaz de DNSSEC, la validación puede fallar. Se puede llamar varias veces, en cuyo caso las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autoritativos a utilizar para una zona particular. Dirección IP4 o IP6. Si la dirección es NULL, la entrada stub se elimina. Establezca isprime a true si configura hints de raíz con ella. De lo contrario, similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas, o para añadir múltiples direcciones para una zona particular. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolvedor completo, pero puede utilizar esta llamada para leer la lista de servidores de nombres a utilizar del nombre de archivo proporcionado. Normalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no admiten DNSSEC, la validación puede fallar. Solo se seleccionan los servidores de nombres, se ignoran el dominio de búsqueda, ndots y otras configuraciones de resolv.conf(5). Si se pasa fname NULL, se utiliza "/etc/resolv.conf" (si está en Windows, se selecciona el servidor de nombres configurado globalmente). En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_hosts
Lee la lista de hosts del nombre de archivo proporcionado. Normalmente "/etc/hosts". Cuando se consultan, estas direcciones no se marcan como DNSSEC seguras. Si se pasa fname NULL, se utiliza "/etc/hosts" (si está en Windows, se selecciona etc/hosts del WINDIR). En este momento, solo es posible establecer la configuración antes de la pri

ub_ctx_add_ta
Añade un ancla de confianza al contexto dado. En este momento solo es posible añadir claves de confianza antes de que se complete la primera resolución. El formato es una cadena, similar al formato de archivo de zona, [nombre de dominio] [tipo] [contenido del rdata]. Se aceptan registros DS y DNSKEY.
ub_ctx_add_ta_autr
Añade un archivo con un ancla de confianza rastreada automáticamente al contexto dado. Pasa el nombre de un archivo con el ancla de confianza administrada. Puedes crear este archivo con unbound-anchor(8) para el ancla raíz. También puedes crearlo con un archivo inicial que contenga una sola línea con un registro DNSKEY o DS. Si el archivo es escribible, se actualiza cuando el ancla de confianza cambia. En este momento solo es posible añadir claves de confianza antes de que se complete la primera resolución.
ub_ctx_add_ta_file
Añade anclas de confianza al contexto dado. Pasa el nombre de un archivo con registros DS y DNSKEY en formato de archivo de zona. En este momento solo es posible añadir claves de confianza antes de que se complete la primera resolución.
ub_ctx_trustedkeys
Añade anclas de confianza al contexto dado. Pasa el nombre de un archivo de configuración estilo bind con trusted-keys{}. En este momento solo es posible añadir claves de confianza antes de que se complete la primera resolución.
ub_ctx_debugout
Establece la salida de registro de depuración y errores al flujo dado. Pasa NULL para deshabilitar la salida. Por defecto es stderr. Los nombres de archivo o el uso de syslog se pueden habilitar utilizando las opciones de configuración, esta rutina es para usar tu propio flujo.
ub_ctx_debuglevel
Establece la verbosidad de depuración para el contexto. La salida se dirige a stderr. Un nivel de depuración más alto proporciona más salida.
ub_ctx_async
Establece un comportamiento del contexto para acciones asíncronas. Si se establece en true, habilita hilos y una llamada a ub_resolve_async crea un hilo para manejar el trabajo en segundo plano. Si es false, se crea un proceso para manejar el trabajo en segundo plano. Los cambios en esta configuración después de que se hayan realizado llamadas a ub_resolve_async no tienen efecto (elimina y recrea el contexto para cambiar).
ub_poll
Sondea un contexto para ver si tiene algún resultado nuevo. No sondeos en un bucle, sino que extrae el fd a continuación para sondear la preparación, y luego verifica, o espera usando la rutina de espera. Devuelve 0 si no hay nada que leer, o un valor distinto de cero si hay un resultado disponible. Si es distinto de cero, llama a ub_process para realizar las devoluciones de llamada.
ub_wait
Espera a que un contexto finalice con los resultados. Llama a ub_process después de la espera por ti. Después de la espera, no hay más consultas asíncronas pendientes.
ub_fd
Obtiene el descriptor de archivo. Espera a que se vuelva legible, momento en el cual las respuestas se devuelven del resolvedor de validación asíncrono. Luego llama a ub_process para continuar procesando.
ub_process
Llama a esta rutina para continuar procesando los resultados del resolvedor de validación (cuando el fd se vuelve legible). Realizará las devoluciones de llamada necesarias.
ub_resolve
Realiza la resolución y validación del nombre de destino. El nombre es un nombre de dominio en una cadena de texto terminada en cero. Los tipos y clases rrtype y rrclass son códigos de tipo y clase DNS. La estructura de resultado se asigna de nuevo con los datos resultantes.
ub_resolve_async
Realiza la resolución y validación asíncrona del nombre de destino. Los argumentos significan lo mismo que para ub_resolve, excepto que no se devuelven datos inmediatamente, sino que se llama a una devolución de llamada más tarde. La devolución de llamada recibe una copia del puntero mydata, que puedes usar para pasar información a la devolución de llamada. El tipo de devolución de llamada es un puntero a función a una función declarada como:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

El async_id se devuelve para que puedas (opcionalmente) decidir rastrearlo y cancelar la solicitud si es necesario. Si pasas un puntero NULL, el async_id no se devuelve.

ub_cancel
Cancela una consulta asíncrona en curso. Esto puede devolver un error si la consulta no existe, o si la consulta ya se está entregando, en cuyo caso aún podrías recibir una devolución de llamada para la consulta.
ub_resolve_free
Libera el contenido de la estructura ub_result después de su uso.
ub_strerror
Convierte el valor de error de una de las funciones de la biblioteca unbound a una cadena legible por humanos.
ub_ctx_print_local_zones
Imprime información de autoridad local para depuración en la salida de depuración.
ub_ctx_zone_add
Añade una nueva zona a la información de autoridad local, como la declaración local-zone de unbound.conf(5).
ub_ctx_zone_remove
Elimina una zona de la información de autoridad local.
ub_ctx_data_add
Añade datos de registro de recursos a la información de autoridad local, como la declaración local-data de unbound.conf(5).
ub_ctx_data_remove
Elimina los datos de autoridad local del nombre dado.

ESTRUCTURA DE DATOS DE RESULTADO

El resultado de la resolución y validación DNS se devuelve como struct ub_result. La estructura de resultado contiene las siguientes entradas:

struct ub_result {
     char* qname;         /* cadena de texto, pregunta original */
     int qtype;           /* código de tipo solicitado */
     int qclass;          /* código de clase solicitado */
     char** data;         /* array de elementos rdata, terminado en NULL*/
     int* len;            /* array con longitudes de los elementos rdata */
     char* canonname;     /* nombre canónico del resultado */
     int rcode;           /* código de error adicional en caso de no tener datos */
     void* answer_packet; /* paquete de respuesta completo en formato de red */
     int answer_len;      /* longitud del paquete en octetos */
     int havedata;        /* true si hay datos */
     int nxdomain;        /* true si no hay datos porque el nombre no existe */
     int secure;          /* true si el resultado es seguro */
     int bogus;           /* true si ocurrió un fallo de seguridad */
     char* why_bogus;     /* cadena con el error si es bogus */
     int was_ratelimited; /* true si la consulta fue limitada por tasa (SERVFAIL) por unbound */
     int ttl;             /* número de segundos que el resultado es válido */
};

Si tanto secure como bogus son falsos, la seguridad no estaba habilitada para el dominio de la consulta. De lo contrario, no son ambos verdaderos, uno de ellos es verdadero.

VALORES DE RETORNO

Muchas rutinas devuelven un código de error. El valor 0 (cero) denota que no ocurrió ningún error. Otros valores se pueden pasar a ub_strerror para obtener una cadena de error legible. ub_strerror devuelve una cadena terminada en cero. ub_ctx_create devuelve NULL en caso de error (un fallo de malloc). ub_poll devuelve true si puede haber información disponible, false en caso contrario. ub_fd devuelve un descriptor de archivo o -1 en caso de error. ub_ctx_config y ub_ctx_resolvconf intentan dejar errno informativo en un retorno de función con fallo de lectura de archivo.
