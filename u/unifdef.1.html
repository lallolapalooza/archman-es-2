unifdef(1)

Paquete: unifdef

Licencias: GPL

UNIFDEF(1) Manual de comandos generales (prm) UNIFDEF(1)

NOMBRE

unifdef, unifdefall — elimina condicionales del preprocesador del código

SINOPSIS

unifdef [-bBcdehKkmnsStV] [-Iruta] [-[i]Dsim[=val]] [-[i]Usim] ... [-f archivo_definiciones] [-x {012}] [-M ext_copia_seguridad] [-o archivo_salida] [archivo_entrada ...]

unifdefall [-Iruta] ... archivo

DESCRIPCIÓN

La utilidad unifdef procesa selectivamente las directivas condicionales de cpp(1). Elimina de un archivo tanto las directivas como cualquier texto adicional que especifiquen que debe eliminarse, dejando el archivo sin cambios por lo demás.

La utilidad unifdef actúa sobre las líneas #if, #ifdef, #ifndef, #elif, #else y #endif, utilizando macros especificadas en las opciones de línea de comandos -D y -U o en los archivos de definiciones -f. Una directiva se procesa si las especificaciones de macro son suficientes para proporcionar un valor definitivo para su expresión de control. Si el resultado es falso, se eliminan la directiva y las líneas siguientes bajo su control. Si el resultado es verdadero, solo se elimina la directiva. Las directivas #ifdef o #ifndef se pasan sin cambios si la macro que las controla no está especificada. Cualquier expresión de control #if o #elif que tenga un valor desconocido o que unifdef no pueda analizar se pasa sin cambios. Por defecto, unifdef ignora las líneas #if y #elif con expresiones constantes; se le puede indicar que las procese especificando la bandera -k en la línea de comandos.

Entiende un subconjunto comúnmente utilizado de la sintaxis de expresiones para las líneas #if y #elif: constantes enteras, valores enteros de macros definidas en la línea de comandos, el operador defined(), los operadores !, ~, - (unario), *, /, %, +, -, <, <=, >, >=, ==, !=, &, ^, |, &&, || y expresiones entre paréntesis. La división por cero se trata como un valor desconocido. Se utiliza una especie de evaluación “cortocircuito” para el operador &&: si alguno de los operandos es definitivamente falso, el resultado es falso, incluso si el valor del otro operando es desconocido. De manera similar, si alguno de los operandos de || es definitivamente verdadero, el resultado es verdadero.

Al evaluar una expresión, unifdef no expande las macros primero. El valor de una macro debe ser un número simple, no una expresión. Se permite una forma limitada de indirección, donde el valor de una macro es el nombre de otra.

En la mayoría de los casos, unifdef no distingue entre macros de objeto (sin argumentos) y macros de función (con argumentos). Una invocación de macro similar a una función puede aparecer en las expresiones de control #if y #elif. Si la macro no está definida explícitamente, o está definida con la bandera -D en la línea de comandos, o con #define en un archivo de definiciones -f, sus argumentos se ignoran. Si una macro se redefine explícitamente en la línea de comandos con la bandera -U, o con #undef en un archivo de definiciones -f, puede que no tenga argumentos, ya que esto conduce a un error de sintaxis.

La utilidad unifdef entiende lo suficiente de C como para saber cuándo una de las directivas está inactiva porque está dentro de un comentario, o no puede evaluarse porque está dividida por una línea continuada con barra invertida. Detecta directivas del preprocesador con formato inusual y las pasa sin cambios cuando el diseño es demasiado extraño para que pueda manejarlo. (Ver la sección BUGS más abajo).

Un script llamado unifdefall se puede usar para eliminar todas las directivas condicionales de cpp(1) de un archivo. Utiliza unifdef -s y cpp -dM para obtener listas de todas las macros de control y sus definiciones (o falta de ellas), luego invoca unifdef con los argumentos apropiados para procesar el archivo.

OPCIONES

-Dsim=val
Especifica que una macro está definida con un valor dado.
-Dsim
Especifica que una macro está definida con el valor 1.
-Usim
Especifica que una macro está indefinida.

Si la misma macro aparece en más de un argumento, la última ocurrencia domina.

-iDsim[=val]
 
-iUsim
Las cadenas de caracteres C, los comentarios y las continuaciones de línea se ignoran dentro de los bloques #ifdef y #ifndef controlados por macros especificadas con estas opciones.
-f archivo_definiciones
El archivo archivo_definiciones contiene directivas de preprocesador #define y #undef, que tienen el mismo efecto que los argumentos de línea de comandos correspondientes -D y -U. Puede tener múltiples argumentos -f y mezclarlos con argumentos -D y -U; las opciones posteriores anulan las anteriores.

Cada directiva debe estar en una sola línea. Las definiciones de macros de tipo objeto (sin argumentos) se establecen al valor dado. Las definiciones de macros de tipo función (con argumentos) se tratan como si se establecieran a 1.

Advertencia: las cadenas literales y las constantes de caracteres no se analizan correctamente en los archivos -f.

-b
Reemplaza las líneas eliminadas con líneas en blanco en lugar de eliminarlas. Mutuamente exclusiva con la opción -B.
-B
Comprime las líneas en blanco alrededor de una sección eliminada. Mutuamente exclusiva con la opción -b.
-c
Complementario, es decir, las líneas que habrían sido eliminadas o dejadas en blanco se conservan y viceversa.
-d
Activa la impresión de mensajes de depuración.
-e
Por defecto, unifdef informará de un error si necesita eliminar una directiva de preprocesador...

EJEMPLOS

Para eliminar el código dentro de #ifdef DEBUG y #endif, y para eliminar las directivas #if y #endif asociadas:

unifdef -DDEBUG=0 -UDEBUG file.c

Para eliminar el código dentro de #ifdef y #endif, pero dejar las líneas vacías en su lugar:

unifdef -b -DDEBUG=0 -UDEBUG file.c

Para eliminar condicionales de código si las macros se definen en un archivo de definiciones:

unifdef -f defs.h file.c

VER TAMBIÉN

cpp(1)

BUGS

unifdef no puede procesar archivos que contengan directivas de preprocesador divididas por comentarios en línea o por barras invertidas al final de una línea, especialmente si la directiva misma está dentro de un comentario.

La sintaxis de los preprocesadores C a veces es muy compleja. Las siguientes características de #if y #elif no son manejadas:

  • Las macros con argumentos que no se establecen en la línea de comandos o en un archivo -f.
  • Los valores de macros que no son números enteros simples o que contienen espacios en blanco.
  • Las expresiones con valores desconocidos en el momento de la evaluación.
  • Los valores de macros que son nombres de otras macros (indirección).

La siguiente característica de #ifdef y #ifndef no es manejada:

  • Las macros que están definidas con argumentos pero cuyo valor es desconocido en el momento de la evaluación.

Por ejemplo, unifdef no sabe si MYMACRO tiene o no argumentos en el siguiente ejemplo:

#define MYMACRO(x) 1
#if MYMACRO
...
#endif

El procesador unifdef no puede, en general, reconocer líneas que están dentro de comentarios o cadenas de caracteres literales. Tampoco distingue entre diferentes tipos de preprocesadores C (como cpp(1), gcc(1), etc.). Por lo tanto, los archivos que utilizan estas características del preprocesador C pueden no ser procesados correctamente.

NAME

unifdef — remove code conditional on preprocessor controls

SYNOPSIS

unifdef [-abcDdegKkMmNnOopPqrsSTtV] [-e file] [-f file] [-I path] [-M backext] [-o outfile] [-x 012] [file …]

DESCRIPTION

The unifdef utility removes conditional preprocessor statements (like #if, #ifdef, #ifndef, #then, #elif, #else, and #endif) and the code that they control from C source files. It can also remove #define and #undef statements and conditionally deleted code sections.

It is particularly useful for preparing source files for distribution, as it can remove debugging code, platform-specific code, or code that relies on macros that are not defined in the target environment.

By default, unifdef removes sections controlled by #ifdef and #ifndef directives if the macro is not defined, and sections controlled by #if and #elif directives if the expression evaluates to false. Sections controlled by #if 0 are removed by default.

The unifdef utility handles nested conditionals correctly. It attempts to parse the expressions in #if and #elif directives, recognizing most standard C operators. It understands a limited number of built-in macros like __LINE__, __FILE__, __DATE__, and __TIME__.

The unifdef utility tries to be smart about comments and string literals. It will not remove preprocessor control lines that are within C comments or string literals.

The unifdef utility handles preprocessor directives that span more than one line, either by comments or backslash-newline sequences, but it may not handle all cases correctly (see BUGS).

The unifdef utility processes files sequentially. It does not perform macro expansion or macro definition tracking like a C preprocessor does.

Command Line Options

-a
Process #if and #elif lines with constant expressions. By default, sections controlled by such lines are passed through unchanged because they typically start “#if 0” and are used as a kind of comment to sketch out future or past development. It would be rude to strip them out, just as it would be for normal comments.
-b
Remove #define and #undef statements as well as the code that they control.
-c
Remove C++ style comments (//). By default, only C style comments (/* ... */) are removed.
-D sym[=val]
Pre-define sym to be val. If val is not given, sym is defined to the value 1. This option may be specified more than once.
-d
Remove #define and #undef statements themselves, but do not remove the code that they control.
-e
Process preprocessor directives that span more than one line, for example, if it has a multi-line comment hanging off its right hand end. The -e flag makes it ignore the line instead.
-f file
Read macro definitions and undefinitions from file. Each line in file is treated as a preprocessor directive. Lines starting with whitespace, non-preprocessor directives, or comments are ignored. This option may be specified more than once.
-h
Print help.
-Ipath
Specifies to unifdefall an additional place to look for #include files. This option is ignored by unifdef for compatibility with cpp(1) and to simplify the implementation of unifdefall.
-i {CcdD}
Ignore certain input. -iC: Ignore C style comments. -ic: Ignore C++ style comments. -D: Ignore #define lines. -d: Ignore #undef lines.
-K
Always treat the result of && and || operators as unknown if either operand is unknown, instead of short-circuiting when unknown operands can't affect the result. This option is for compatibility with older versions of unifdef.
-k
Process #if and #elif lines with constant expressions. By default, sections controlled by such lines are passed through unchanged because they typically start “#if 0” and are used as a kind of comment to sketch out future or past development. It would be rude to strip them out, just as it would be for normal comments.
-m
Modify one or more input files in place. If an input file is not modified, the original is preserved instead of being overwritten with an identical copy.
-M backext
Modify input files in place, and keep backups of the original files by appending the backext to the input filenames. A zero length backext behaves the same as the -m option.
-n
Add #line directives to the output following any deleted lines, so that errors produced when compiling the output file correspond to line numbers in the input file.
-N
Do not remove #if, #ifdef, #ifndef, #then, #elif, #else, and #endif lines even if the conditions are false or the macros are undefined.
-O file
Output to file. This is equivalent to using -o with a filename.
-o outfile
Write output to the file outfile instead of the standard output when processing a single file.
-p
Do not remove conditional code related to the #if and #elif directives. Only remove code related to #ifdef and #ifndef.
-P
Remove #include lines as well as conditional code.
-q
Quiet mode. Suppresses informational messages.
-r
Remove #include lines. This option is ignored if -P is given.
-s
Instead of processing an input file as usual, this option causes unifdef to produce a list of macros that are used in preprocessor directive controlling expressions. Macros defined with -D or -f are not included in the list.
-S
Like the -s option, but the nesting depth of each macro is also printed. This is useful for working out the number of possible combinations of interdependent defined/undefined macros.
-T
Treat #if and #elif lines containing only the keyword defined as errors.
-t
Disables parsing for C strings, comments, and line continuations, which is useful for plain text. This is a blanket version of the -iD and -iU flags.
-U sym
Pre-undefine sym. This option may be specified more than once.
-V
Print version details.
-x {012}
Set exit status mode to zero, one, or two. See the EXIT STATUS section below for details.

The unifdef utility takes its input from stdin if there are no file arguments. You must use the -m or -M options if there are multiple input files. You can specify inut from stdin or output to stdout with ‘-’.

The unifdef utility works nicely with the -Dsym option of diff(1).

EXIT STATUS

In normal usage the unifdef utility's exit status depends on the mode set using the -x option.

If the exit mode is zero (the default) then unifdef exits with status 0 if the output is an exact copy of the input, or with status 1 if the output differs.

If the exit mode is one, unifdef exits with status 1 if the output is unmodified or 0 if it differs.

If the exit mode is two, unifdef exits with status zero in both cases.

In all exit modes, unifdef exits with status 2 if there is an error.

The exit status is 0 if the -h or -V command line options are given.

DIAGNOSTICS

  • EOF in comment
  • Inappropriate #elif, #else or #endif
  • Missing macro name in #define or #undef
  • Obfuscated preprocessor control line
  • Premature EOF (with the line number of the most recent unterminated #if)
  • Too many levels of nesting
  • Unrecognized preprocessor directive
  • Unterminated char or string literal

HISTORY

The unifdef command appeared in 2.9BSD. ANSI C support was added in FreeBSD 4.7.

AUTHORS

The original implementation was written by Dave Yost <Dave@Yost.com>. Tony Finch <dot@dotat.at> rewrote it to support ANSI C.

BUGS

  • Expression evaluation is very limited.
  • Character constants are not evaluated. String literals and character constants in -f definition files are ignored rather than parsed as part of a macro's replacement tokens.
  • Only the basic form of C++ raw string literals is recognized, like R"(string)" without delimiters as in R"delimiter(string)delimiter".
  • Source files are processed one line at a time, so preprocessor directives split across more than one physical line (because of comments or backslash-newline) cannot be handled in every situation.
  • Trigraphs are not recognized.
  • There is no support for macros with different definitions at different points in the source file.
  • The text-mode and ignore functionality does not correspond to modern cpp(1) behaviour.
