UUDECODE(1P) Manual de Programador POSIX UUDECODE(1P)

PROLOGO

Esta página del manual forma parte del Manual de Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual correspondiente de Linux para obtener detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

uudecode — decodifica un archivo binario

SINOPSIS

uudecode [-o archivo_salida] [archivo]

DESCRIPCIÓN

La utilidad uudecode leerá un archivo, o la entrada estándar si no se especifica ningún archivo, que incluya datos creados por la utilidad uuencode. La utilidad uudecode escaneará el archivo de entrada, buscando datos compatibles con uno de los formatos especificados en uuencode, e intentará crear o sobrescribir el archivo descrito por los datos (o anulado por la opción -o). La ruta del archivo estará contenida en los datos o especificada por la opción -o. Los bits de permisos de acceso al archivo y el contenido del archivo a producir estarán contenidos en esos datos. Los bits de modo del archivo creado (aparte de la salida estándar) se establecerán a partir de los bits de permisos de acceso al archivo contenidos en los datos; es decir, otros atributos del modo, incluido la máscara de creación de modo de archivo (ver umask), no afectarán al archivo que se está produciendo. Si alguno de los caracteres op '+' y '-' (ver chmod) se especifican en modo simbólico, el modo inicial en el que se basan esas operaciones no está especificado.

Si la ruta del archivo se resuelve a un archivo existente y el usuario no tiene permiso de escritura en ese archivo, uudecode terminará con un error. Si la ruta del archivo se resuelve a un archivo existente y el usuario tiene permiso de escritura en ese archivo, el archivo existente se sobrescribirá y, si es posible, se establecerán los bits de modo del archivo (aparte de la salida estándar) como se describió anteriormente; si los bits de modo no se pueden establecer, uudecode no tratará esto como un error.

Si los datos de entrada fueron producidos por uuencode en un sistema con un número de bits por byte diferente al del sistema de destino, los resultados de uudecode no están especificados.

OPCIONES

La utilidad uudecode se ajustará al volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Guías de Sintaxis de Utilidad.

La implementación deberá admitir la siguiente opción:

-o archivo_salida
Una ruta de un archivo que se utilizará en lugar de cualquier ruta contenida en los datos de entrada. Especificar un argumento de opción archivo_salida de /dev/stdout indicará la salida estándar.

OPERANDOS

Se deberá admitir el siguiente operando:

archivo
La ruta de un archivo que contiene la salida de uuencode.

ENTRADA ESTÁNDAR

Ver la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

Los archivos de entrada serán archivos que contienen la salida de uuencode.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de uudecode:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no estén establecidas o estén vacías. (Ver el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional.)
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada).
LC_MENSAJES

Determinar la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MENSAJES.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTÁNDAR

Si la cabecera de datos del archivo codificada por uuencode es - o /dev/stdout, o si la opción -o /dev/stdout anula los datos del archivo, la salida estándar estará en el mismo formato que el archivo originalmente codificado por uuencode. De lo contrario, la salida estándar no se utilizará.

SALIDA DE ERROR ESTÁNDAR

La salida de error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

El archivo de salida estará en el mismo formato que el archivo originalmente codificado por uuencode.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO DE APLICACIÓN

El usuario que invoca uudecode debe tener permiso de escritura en cualquier archivo que se esté creando.

La salida de uuencode es esencialmente un flujo de bits codificado que no tiene en cuenta los límites de bytes. Es posible que una máquina de destino con 9 bits por byte pueda procesar una entrada de una fuente de 8 bits, si es consciente del requisito, pero lo contrario es poco probable que sea satisfactorio. Por supuesto, los únicos datos que tienen sentido para tal transferencia entre arquitecturas son generalmente datos de caracteres.

EJEMPLOS

Ninguno.

FUNDAMENTOS RACIONALES

Los archivos de entrada no son necesariamente archivos de texto, como se indica en una propuesta anterior. Aunque la salida de uuencode es un archivo de texto, esa salida podría haber sido encapsulada dentro de otro archivo o mensaje de correo que no es un archivo de texto.

La opción -o no es una práctica histórica, sino que se agregó a petición de WG15 para que el usuario pudiera anular la ruta de destino sin tener que editar los datos de entrada.

En borradores anteriores, el argumento de opción [-o archivo_salida] permitía el uso de - para significar salida estándar. El símbolo - solo se ha utilizado anteriormente en POSIX.1‐2008 como indicador de entrada estándar. Los desarrolladores del estándar no deseaban sobrecargar el significado de - de esta manera. El concepto /dev/stdout existe en la mayoría de los sistemas modernos. La sintaxis /dev/stdout no se refiere a un nuevo archivo especial. Es solo una "cookie mágica" para especificar la salida estándar.

DIRECCIONES FUTURAS

Ninguna.

NAME

uuencode - encode a binary file in base64 or radix-64

SYNOPSIS

uuencode [OPTION]... input output

DESCRIPTION

Encode the contents of input file into the output file using uuencode format. This format is a way to represent binary data using only printable ASCII characters. It is commonly used in email attachments and Usenet posts.

The uuencode format consists of lines, each starting with a character that indicates the number of bytes encoded on that line, followed by the encoded data. The first line usually contains the name of the original file. The encoding scheme is radix-64, where each group of three bytes is converted into four ASCII characters.

OPTIONS

This command also accepts the following option:

--help
Display a help message and exit.
--version
Output version information and exit.

OPERANDS

input
The path to the binary file to be encoded.
output
The path to the file where the encoded output will be written.

STDIN

If input is specified as a hyphen (-), uuencode reads from standard input.

INPUT FILES

If input is not specified as a hyphen (-), it must be a readable file.

ENVIRONMENT VARIABLES

The behavior of uuencode may be affected by the following environment variables:

LANG
For default locale settings.
LC_ALL
If set, override both LANG and the locale settings that would otherwise be used.
LC_CTYPE
Determine the locale for the interpretation of sequences of bytes of text data.

See locale(7) for more information.

ASYNCHRONOUS EVENTS

No special asynchronous event handling is described.

STDOUT

The encoded output is written to the file specified by the output operand.

STDERR

Standard error is used for diagnostic messages.

OUTPUT FILES

The output file contains the uuencoded representation of the input file.

EXTENDED DESCRIPTION

The uuencode utility encodes a binary file into a text format that can be safely transmitted over systems that only support ASCII characters, such as email. The encoding scheme used is radix-64, also known as base64, but with a specific format used by the `uucp` suite of utilities. Each line of the output begins with a character that represents the number of bytes that follow on that line. The encoded data itself consists of ASCII characters from the set ` !"#$%&'()*+,-./0123456789:;<=>?@ABCDEFGHIJKLMNOPQRSTUVWXYZ[\]^_``abcdefghijklmnopqrstuvwxyz{|}~`. The first line of the output typically contains the name of the original file, preceded by a header line like `begin 644 filename` and followed by a `end` line.

EXIT STATUS

The exit status is 0 on success, and non-zero otherwise.

CONSEQUENCES OF ERRORS

If an error occurs (e.g., input file not found, output file not writable), an error message is printed to standard error, and the utility exits with a non-zero status. The output file may be incomplete or not created.

APPLICATION USAGE

This utility is typically used when you need to send a binary file via a medium that only supports plain text. For example:

uuencode my_document.pdf my_document.pdf.uu

This will create a file named my_document.pdf.uu which contains the text-based representation of my_document.pdf. This file can then be sent via email or posted to a Usenet group. The recipient would then use uudecode to convert it back to the original binary file.

EXAMPLES

Encode the file image.jpg into image.jpg.uu:

$ uuencode image.jpg image.jpg.uu

Encode standard input to standard output:

$ cat binary_data | uuencode - - > encoded_data.uu

RATIONALE

The uuencode utility is part of the traditional Unix toolset for handling binary file transfers over text-based networks. It provides a simple and widely understood method for encoding binary data into ASCII characters. While newer encoding schemes like MIME base64 are more efficient and widely adopted, uuencode remains relevant for compatibility with older systems and specific use cases.

The POSIX standard defines uuencode as part of the shell and utilities, emphasizing its role in basic file manipulation and data transmission.

FUTURE DIRECTIONS

The use of uuencode is generally discouraged in favor of more modern encoding methods like MIME base64, which is more efficient and better integrated with modern communication protocols like email (MIME). However, the utility is expected to remain available for backward compatibility.
