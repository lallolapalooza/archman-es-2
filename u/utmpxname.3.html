getutent(3) Library Functions Manual getutent(3)

NOMBRE

getutent, getutid, getutline, pututline, setutent, endutent, utmpname - acceder a las entradas del archivo utmp

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <utmp.h>
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *ut);
struct utmp *getutline(const struct utmp *ut);
struct utmp *pututline(const struct utmp *ut);
void setutent(void);
void endutent(void);
int utmpname(const char *path);

DESCRIPCIÓN

Las nuevas aplicaciones deberían usar las funciones de la versión "utmpx" especificadas por POSIX.1; ver ESTÁNDARES.

utmpname() establece la ruta del archivo de formato utmp para que las otras funciones utmp accedan. Si no se utiliza utmpname() para establecer la ruta antes de usar las otras funciones, estas asumen _PATH_UTMP, tal como se define en <paths.h>.

setutent() rebobina el puntero del archivo al principio del archivo utmp. Generalmente es una buena idea llamarla antes que a cualquiera de las otras funciones.

endutent() cierra el archivo utmp. Debería llamarse cuando el código del usuario haya terminado de acceder al archivo con las otras funciones.

getutent() lee una línea desde la posición actual del archivo en el archivo utmp. Devuelve un puntero a una estructura que contiene los campos de la línea. La definición de esta estructura se muestra en utmp(5).

getutid() busca hacia adelante desde la posición actual del archivo en el archivo utmp basándose en ut. Si ut->ut_type es uno de RUN_LVL, BOOT_TIME, NEW_TIME, o OLD_TIME, getutid() encontrará la primera entrada cuyo campo ut_type coincida con ut->ut_type. Si ut->ut_type es uno de INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS, o DEAD_PROCESS, getutid() encontrará la primera entrada cuyo campo ut_id coincida con ut->ut_id.

getutline() busca hacia adelante desde la posición actual del archivo en el archivo utmp. Escanea entradas cuyo ut_type sea USER_PROCESS o LOGIN_PROCESS y devuelve la primera cuyo campo ut_line coincida con ut->ut_line.

pututline() escribe la estructura utmp ut en el archivo utmp. Utiliza getutid() para buscar el lugar adecuado en el archivo para insertar la nueva entrada. Si no puede encontrar una ranura adecuada para ut, pututline() añadirá la nueva entrada al final del archivo.

VALOR DE RETORNO

getutent(), getutid() y getutline() devuelven un puntero a una struct utmp en caso de éxito, y NULL en caso de fallo (lo que incluye el caso de "registro no encontrado"). Esta struct utmp se asigna en almacenamiento estático y puede ser sobrescrita por llamadas posteriores.

En caso de éxito, pututline() devuelve ut; en caso de fallo, devuelve NULL.

utmpname() devuelve 0 si el nuevo nombre se almacenó correctamente, o -1 en caso de fallo.

En caso de fallo, estas funciones establecen errno para indicar el error.

ERRORES

ENOMEM
Memoria agotada.
ESRCH
Registro no encontrado.

setutent(), pututline() y las funciones getut*() también pueden fallar por las razones descritas en open(2).

ARCHIVOS

/var/run/utmp
base de datos de usuarios actualmente conectados
/var/log/wtmp
base de datos de inicios de sesión de usuarios anteriores

ESTÁNDARES

Ninguno.

HISTORIA

XPG2, SVr4.

En XPG2 y SVID 2, la función pututline() se documenta como void, y eso es lo que hace en muchos sistemas (AIX, HP-UX). HP-UX introduce una nueva función _pututline() con el prototipo dado arriba para pututline().

Todas estas funciones están obsoletas ahora en sistemas que no son Linux. POSIX.1-2001 y POSIX.1-2008, siguiendo SUSv1, no tienen ninguna de estas funciones, sino que utilizan

#include <utmpx.h>
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *);
struct utmpx *getutxline(const struct utmpx *);
struct utmpx *pututxline(const struct utmpx *);
void setutxent(void);
void endutxent(void);

Estas funciones son proporcionadas por glibc y realizan la misma tarea que sus equivalentes sin la "x", pero utilizan struct utmpx, que en Linux se define como igual a struct utmp. Para completitud, glibc también proporciona utmpxname(), aunque esta función no está especificada por POSIX.1.

En algunos otros sistemas, la estructura utmpx es un superconjunto de la estructura utmp, con campos adicionales y versiones más grandes de los campos existentes, y se mantienen archivos paralelos, a menudo /var/*/utmpx y /var/*/wtmpx.

Linux glibc, por otro lado, no utiliza un archivo utmpx paralelo ya que su estructura utmp es lo suficientemente grande. Las funciones "x" enumeradas anteriormente son solo alias para sus contrapartes sin la "x" (por ejemplo, getutxent() es un alias para getutent()).

NOTAS

Notas de glibc

Las funciones anteriores no son seguras para hilos. glibc añade versiones reentrables

#include <utmp.h>
int getutent_r(struct utmp *ubuf, struct utmp **ubufp);
int getutid_r(struct utmp *ut,
              struct utmp *ubuf, struct utmp **ubufp);
int getutline_r(struct utmp *ut,
                struct utmp *ubuf, struct utmp **ubufp);

Requisitos de Macro de Prueba de Funcionalidades para glibc (ver feature_test_macros(7)):

getutent_r(), getutid_r(), getutline_r():

    _GNU_SOURCE
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */    _SVID_SOURCE || _BSD_SOURCE

Estas funciones son extensiones de GNU, análogas a las funciones del mismo nombre sin el sufijo _r. El argumento ubuf proporciona a estas funciones un lugar donde almacenar su resultado. En caso de éxito, devuelven 0 y un puntero al resultado se escribe en *ubufp. En caso de error, estas funciones devuelven -1. No existen equivalentes utmpx de las funciones anteriores. (POSIX.1 no especifica tales funciones.)

NAME

LIBRARY

#include <utmp.h>

void endutxent(void);
int pututxline(const struct utmp *entry);
struct utmp *getutxid(const struct utmp *entry);
int pututxid(const struct utmp *entry);

DESCRIPTION

The functions described here provide an interface to the user login accounting file, which is typically named /var/run/utmp. The structure of this file is described in utmp(5).

The functions are grouped as follows:

  • Reading the file: getutent(), getutline(), getutid(), getutxent(), getutxline(), getutxid()
  • Writing to the file: pututline(), pututid(), pututxline(), pututxid()
  • File positioning: setutent(), setutxent()
  • File closing: endutent(), endutxent()
  • Conversion between utmp and utmpx structures: getutmp(), pututmp()
  • Updating the file: updwtmpx()
  • Setting the filename: utmpxname()

getutent() reads the next entry from the utmp file. If the file has not been opened yet, it is opened.

setutent() rewinds the utmp file, so that the next call to getutent() will read the first entry.

endutent() closes the utmp file.

getutline() searches the utmp file for an entry that matches the given entry. The matching is done using the ut_line field. It returns a pointer to the found entry, or NULL if no match is found.

getutid() searches the utmp file for an entry that matches the given entry. The matching is done using the ut_id field. It returns a pointer to the found entry, or NULL if no match is found.

pututline() writes the given entry to the utmp file. If an entry with the same ut_line already exists, it is replaced. Otherwise, the new entry is appended to the file. This function works on the current utmp file.

pututid() writes the given entry to the utmp file. If an entry with the same ut_id already exists, it is replaced. Otherwise, the new entry is appended to the file. This function works on the current utmp file.

getutxent(), setutxent(), endutxent(), getutxline(), getutxid(), pututxline(), and pututxid() are the "extended" versions that operate on the utmpx structure and file, which can hold more information than the traditional utmp structure.

utmpxname() allows the application to specify a different utmp file to be used. By default, the file is /var/run/utmp. It returns the name of the file previously in use.

getutmp() and pututmp() are used to convert between utmp and utmpx structures. getutmp() converts from a utmp structure to an utmpx structure. pututmp() converts from an utmpx structure to a utmp structure.

updwtmpx() is a simplified interface to update the utmp file. It takes the filename, an id, a pid, and a type, and updates the corresponding entry in the utmp file.

RETURN VALUE

The getutent(), getutline(), getutid(), getutxent(), getutxline(), and getutxid() functions return a pointer to a static utmp or utmpx structure, respectively. This pointer is invalidated on the next call to any of these functions. They return NULL on error or if end-of-file is reached.

The pututline(), pututid(), pututxline(), and pututxid() functions return a pointer to the written entry on success, and NULL on error.

The utmpxname() function returns the name of the utmp file previously in use.

ERRORS

Error conditions are not explicitly indicated by return values other than NULL for the get... and put... functions. Errors are typically due to file access permissions or other system errors.

FILES

/var/run/utmp
The default user login accounting file.
/var/run/utmpx
The extended user login accounting file.

STANDARDS

The getutent, getutline, setutent, endutent, pututline, getutid, and pututid functions conform to POSIX.1-2001 and POSIX.1-2008.

The utmpxname, getutxent, getutxline, setutxent, endutxent, pututxline, getutxid, pututxid, getutmp, pututmp, and updwtmpx functions are extensions of the POSIX standard and are specific to certain Unix-like systems, including Linux.

HISTORY

The getutent, getutline, setutent, endutent, and pututline functions first appeared in Version 7 Unix.

The getutid and pututid functions were added in FreeBSD 2.1.

The extended functions getutxent, getutxline, setutxent, endutxent, pututxline, getutxid, pututxid, utmpxname, getutmp, pututmp, and updwtmpx first appeared in the Solaris operating system.

NOTES

These functions are generally considered obsolete in favor of the logind.conf(5) mechanisms and the utmpdump(8) utility.

The utmp file is not protected by file permissions, so any user can append entries to it. However, only the root user can modify or delete existing entries.

EXAMPLES

The following example adds and removes a utmp record, assuming it is run from within a pseudo terminal. For usage in a real application, you should check the return values of getpwuid(3) and ttyname(3).

#include <err.h>
#include <pwd.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <utmp.h>
int
main(void)
{
    struct utmp entry;
    if (system("echo before adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = USER_PROCESS;
    entry.ut_pid = getpid();
    strcpy(entry.ut_line, ttyname(STDIN_FILENO) + strlen("/dev/"));
    /* only correct for ptys named /dev/tty[pqr][0-9a-z] */
    strcpy(entry.ut_id, ttyname(STDIN_FILENO) + strlen("/dev/tty"));
    entry.ut_time = time(NULL);
    strcpy(entry.ut_user, getpwuid(getuid())->pw_name);
    memset(entry.ut_host, 0, UT_HOSTSIZE);
    entry.ut_addr = 0;
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = DEAD_PROCESS;
    memset(entry.ut_line, 0, UT_LINESIZE);
    entry.ut_time = 0;
    memset(entry.ut_user, 0, UT_NAMESIZE);
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after removing entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    endutent();
    exit(EXIT_SUCCESS);
}
