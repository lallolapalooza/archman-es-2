NOMBRE

user-session-keyring - keyring de sesión predeterminado por usuario

DESCRIPCIÓN

El keyring de sesión de usuario es un keyring utilizado para anclar claves en nombre de un usuario. Cada UID que el kernel maneja tiene su propio keyring de sesión de usuario que es compartido por todos los procesos con ese UID. El keyring de sesión de usuario tiene un nombre (descripción) de la forma _uid_ses.<UID> donde <UID> es el ID de usuario del usuario correspondiente.

El keyring de sesión de usuario está asociado con el registro que el kernel mantiene para el UID. Entra en existencia tras el primer intento de acceder al keyring de sesión de usuario, al user-keyring(7), o al session-keyring(7). El keyring permanece fijado en existencia mientras haya procesos ejecutándose con ese UID real o archivos abiertos por esos procesos permanezcan abiertos. (El keyring también puede ser fijado indefinidamente enlazándolo a otro keyring.)

El keyring de sesión de usuario se crea bajo demanda cuando un hilo lo solicita o cuando un hilo solicita su session-keyring(7) y ese keyring no existe. En este último caso, se creará un keyring de sesión de usuario y, si el keyring de sesión no iba a crearse, el keyring de sesión de usuario se establecerá como el keyring de sesión real del proceso.

El keyring de sesión de usuario es buscado por request_key(2) si el keyring de sesión real no existe y se ignora de lo contrario.

Se define un valor especial de número de serie, KEY_SPEC_USER_SESSION_KEYRING, que puede usarse en lugar del número de serie real del keyring de sesión de usuario del proceso que llama.

Desde la utilidad keyctl(1), '@us' puede usarse en lugar de un ID numérico de clave de la misma manera.

Los keyrings de sesión de usuario son independientes de clone(2), fork(2), vfork(2), execve(2), y _exit(2) excepto que el keyring se destruye cuando el registro UID se destruye al salir el último proceso que lo fija.

Si un keyring de sesión de usuario no existe cuando se accede a él, se creará.

En lugar de depender del keyring de sesión de usuario, se recomienda encarecidamente —especialmente si el proceso se ejecuta como root— que se establezca explícitamente un session-keyring(7), por ejemplo mediante pam_keyinit(8).

NOTAS

El keyring de sesión de usuario se añadió para dar soporte a situaciones en las que un proceso no tiene un keyring de sesión, quizás porque fue creado a través de una vía que no implicaba PAM (por ejemplo, quizás era un demonio iniciado por inetd(8)). En tal escenario, el keyring de sesión de usuario actúa como un sustituto del session-keyring(7).
