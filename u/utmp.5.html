utmp(5) Manual de formatos de archivo utmp(5)

NOMBRE

utmp, wtmp - registros de inicio de sesión

SINOPSIS

#include <utmp.h>

DESCRIPCIÓN

El archivo utmp permite descubrir información sobre quién está usando actualmente el sistema. Puede haber más usuarios usando el sistema actualmente, porque no todos los programas registran en utmp.

Advertencia: utmp no debe ser escribible por la clase de usuario "otro", porque muchos programas del sistema (tontamente) dependen de su integridad. Corre el riesgo de falsos archivos de registro del sistema y modificaciones de archivos del sistema si deja utmp escribible por cualquier usuario que no sea el propietario y el propietario del grupo del archivo.

El archivo es una secuencia de estructuras utmp, declaradas de la siguiente manera en <utmp.h> (tenga en cuenta que esta es solo una de varias definiciones; los detalles dependen de la versión de libc):


/* Valores para el campo ut_type, abajo */
#define EMPTY         0 /* El registro no contiene información válida
                           (anteriormente conocido como UT_UNKNOWN en Linux) */
#define RUN_LVL       1 /* Cambio en el nivel de ejecución del sistema (ver
init(1))
*/
#define BOOT_TIME     2 /* Hora de arranque del sistema (en ut_tv) */
#define NEW_TIME      3 /* Hora después del cambio del reloj del sistema
                           (en ut_tv) */
#define OLD_TIME      4 /* Hora antes del cambio del reloj del sistema
                           (en ut_tv) */
#define INIT_PROCESS  5 /* Proceso iniciado por
init(1)
*/
#define LOGIN_PROCESS 6 /* Proceso líder de sesión para inicio de sesión de usuario */
#define USER_PROCESS  7 /* Proceso normal */
#define DEAD_PROCESS  8 /* Proceso terminado */
#define ACCOUNTING    9 /* No implementado */
#define UT_LINESIZE      32
#define UT_NAMESIZE      32
#define UT_HOSTSIZE     256
struct exit_status {              /* Tipo para ut_exit, abajo */
    short e_termination;          /* Estado de terminación del proceso */
    short e_exit;                 /* Estado de salida del proceso */
};
struct utmp {
    short   ut_type;              /* Tipo de registro */
    pid_t   ut_pid;               /* PID del proceso de inicio de sesión */
    char    ut_line[UT_LINESIZE]; /* Nombre del dispositivo tty - "/dev/" */
    char    ut_id[4];             /* Sufijo del nombre de la terminal,
                                     o ID de inittab(5) */
    char    ut_user[UT_NAMESIZE]; /* Nombre de usuario */
    char    ut_host[UT_HOSTSIZE]; /* Nombre del host para inicio de sesión remoto, o
                                     versión del kernel para mensajes de nivel de ejecución */
    struct  exit_status ut_exit;  /* Estado de salida de un proceso
                                     marcado como DEAD_PROCESS; no
                                     utilizado por el 
init(1) de Linux
*/
    /* Los campos ut_session y ut_tv deben tener el mismo tamaño cuando
       se compila en 32 y 64 bits. Esto permite que los archivos de datos y la memoria
       compartida se compartan entre aplicaciones de 32 y 64 bits. */
#if __WORDSIZE == 64 && defined __WORDSIZE_COMPAT32
    int32_t ut_session;           /* ID de sesión (
getsid(2)),
                                     utilizado para ventanas */
    struct {
        int32_t tv_sec;           /* Segundos */
        int32_t tv_usec;          /* Microsegundos */
    } ut_tv;                      /* Momento en que se creó la entrada */
#else
     long   ut_session;           /* ID de sesión */
     struct timeval ut_tv;        /* Momento en que se creó la entrada */
#endif
    int32_t ut_addr_v6[4];        /* Dirección de Internet del host
                                     remoto; la dirección IPv4 usa
                                     solo ut_addr_v6[0] */
    char __unused[20];            /* Reservado para uso futuro */
};
/* Trucos de compatibilidad hacia atrás */
#define ut_name ut_user
#ifndef _NO_UT_TIME
#define ut_time ut_tv.tv_sec
#endif
#define ut_xtime ut_tv.tv_sec
#define ut_addr ut_addr_v6[0]

Esta estructura proporciona el nombre del archivo especial asociado al terminal del usuario, el nombre de usuario y la hora de inicio de sesión en formato de time(2). Los campos de cadena están terminados por un byte nulo ('\0') si son más cortos que el tamaño del campo.

Las primeras entradas que se crean resultan del procesamiento de inittab(5) por parte de init(1). Antes de procesar una entrada, sin embargo, init(1) limpia utmp estableciendo ut_type a DEAD_PROCESS, borrando ut_user, ut_host, y ut_time con bytes nulos para cada registro cuyo ut_type no sea DEAD_PROCESS o RUN_LVL y para el que no exista ningún proceso con PID ut_pid. Si no se encuentra ningún registro vacío con el ut_id necesario, init(1) crea uno nuevo. Establece ut_id a partir de inittab, ut_pid y ut_time a los valores actuales, y ut_type a INIT_PROCESS.

mingetty(8) (o agetty(8)) localiza la entrada por el PID, cambia ut_type a LOGIN_PROCESS, cambia ut_time, establece ut_line y espera a que se establezca la conexión. login(1), después de que un usuario haya sido autenticado, cambia ut_type a USER_PROCESS, cambia ut_time y establece ut_host y ut_addr. Dependiendo de mingetty(8) (o agetty(8)) y login(1), los registros pueden localizarse por ut_line en lugar del preferible ut_pid.

Cuando init(1) detecta que un proceso ha terminado, localiza su entrada utmp por ut_pid, establece ut_type a DEAD_PROCESS y borra ut_user, ut_host y ut_time con bytes nulos.

xterm(1) y otros emuladores de terminal crean directamente un registro USER_PROCESS y generan el ut_id utilizando la cadena que es el sufijo del nombre de la terminal (los caracteres que siguen a /dev/[pt]ty). Si encuentran un DEAD_PROCESS para este ID, lo reciclan, de lo contrario crean una nueva entrada. Si pueden, la marcarán como DEAD_PROCESS al salir y es recomendable que también pongan a nulo ut_line, ut_time, ut_user y ut_host.

telnetd(8) configura una entrada LOGIN_PROCESS y deja el resto a login(1) como de costumbre. Después de que la sesión telnet finaliza, telnetd(8) limpia utmp de la manera descrita.

El archivo wtmp registra todos los inicios y cierres de sesión. Su formato es exactamente igual al de utmp excepto que un nombre de usuario nulo indica un cierre de sesión en la terminal asociada. Además, el nombre de terminal ~ con el nombre de usuario shutdown o reboot indica un apagado o reinicio del sistema y el par de nombres de terminal |/} registra la hora antigua/nueva del sistema cuando date(1) la cambia. wtmp es mantenido por login(1), init(1) y algunas versiones de getty(8) (por ejemplo, mingetty(8) o agetty(8)). Ninguno de estos programas crea el archivo, por lo que si se elimina, el registro de información se desactiva.

ARCHIVOS

/var/run/utmp
/var/log/wtmp

VERSIONES

POSIX.1 no especifica una estructura utmp, sino una llamada utmpx (como parte de la extensión XSI), con especificaciones para los campos ut_type, ut_pid, ut_line, ut_id, ut_user y ut_tv. POSIX.1 no especifica las longitudes de los campos ut_line y ut_user.

Linux define la estructura utmpx para que sea la misma que la estructura utmp.

ESTÁNDARES

Linux.

HISTORIA

Las entradas utmp de Linux no cumplen ni con v7/BSD ni con System V; son una mezcla de ambos.

/p>

v7/BSD tiene menos campos; lo más importante es que carece de ut_type, lo que hace que los programas nativos tipo v7/BSD muestren (por ejemplo) entradas muertas o de inicio de sesión. Además, no hay un archivo de configuración que asigne ranuras a las sesiones. BSD lo hace porque carece de los campos ut_id.

En Linux (como en System V), el campo ut_id de un registro nunca cambiará una vez que se haya establecido, lo que reserva esa ranura sin necesidad de un archivo de configuración. Borrar ut_id puede dar lugar a condiciones de carrera que provoquen entradas utmp corruptas y posibles brechas de seguridad. Borrar los campos mencionados anteriormente rellenándolos con bytes nulos no es un requisito de la semántica de System V, pero hace posible ejecutar muchos programas que asumen la semántica de BSD y que no modifican utmp. Linux utiliza las convenciones de BSD para el contenido de las líneas, como se describe anteriormente.

System V no tiene los campos ut_host o ut_addr_v6.

NOTAS

A diferencia de varios otros sistemas, donde el registro de utmp se puede deshabilitar eliminando el archivo, utmp siempre debe existir en Linux. Si desea deshabilitar who(1), entonces no haga utmp legible para todos.

El formato del archivo depende de la máquina, por lo que se recomienda que solo se procese en la arquitectura de la máquina donde se creó.

Tenga en cuenta que en plataformas biarch, es decir, sistemas que pueden ejecutar aplicaciones de 32 bits y 64 bits (x86-64, ppc64, s390x, etc.), ut_tv tiene el mismo tamaño en modo de 32 bits que en modo de 64 bits. Lo mismo ocurre con ut_session y ut_time si están presentes. Esto permite compartir archivos de datos y memoria compartida entre aplicaciones de 32 bits y 64 bits. Esto se logra cambiando el tipo de ut_session a int32_t, y el de ut_tv a una estructura con dos campos int32_t tv_sec y tv_usec. Dado que ut_tv puede no ser lo mismo que struct timeval, en lugar de la llamada:


gettimeofday((struct timeval *) &ut.ut_tv, NULL);

el siguiente método de establecimiento de este campo es recomendado:


struct utmp ut;
struct timeval tv;
gettimeofday(&tv, NULL);
ut.ut_tv.tv_sec = tv.tv_sec;
ut.ut_tv.tv_usec = tv.tv_usec;
