USB_MODESWITCH(1) Manual de Comandos Generales USB_MODESWITCH(1)

NOMBRE

usb_modeswitch - controla el modo de dispositivos USB 'multi-estado'

SINOPSIS

usb_modeswitch [-heWQDIvpVPmM23rwKdHSOBGTNALnsRiuagft] [-c archivo_config]

DESCRIPCIÓN

Varios dispositivos USB nuevos tienen sus drivers propietarios para Windows a bordo, la mayoría son módems WWAN y WLAN. Cuando se conectan por primera vez, actúan como un dispositivo de almacenamiento flash y comienzan a instalar el driver de Windows desde allí. Si el driver está instalado, hace que el dispositivo de almacenamiento desaparezca y aparece un nuevo dispositivo, principalmente compuesto (por ejemplo, con puertos de módem).

En Linux, en la mayoría de los casos, los drivers están disponibles como módulos del kernel, como "usbserial" u "option". Sin embargo, el dispositivo se enlaza inicialmente con "usb-storage" por defecto. usb_modeswitch puede entonces enviar un mensaje de bloque (lo más probable es un comando de almacenamiento masivo) al dispositivo; este mensaje debe determinarse analizando las acciones del driver de Windows.

En algunos casos, se utilizan comandos de control USB para el cambio. Estos casos son manejados por funciones personalizadas, y no se necesita proporcionar ningún mensaje de bloque.

Por lo general, el programa se distribuye con un conjunto de configuraciones para muchos dispositivos conocidos, lo que permite un manejo totalmente automático de un dispositivo al insertarlo, posible gracias a la combinación de usb_modeswitch con el script wrapper usb_modeswitch_dispatcher que es lanzado por el demonio udev. Esto requiere un sistema de tipo Linux, sin embargo.

Tenga en cuenta que usb_modeswitch en sí mismo no tiene dependencias específicas de Linux.

OPCIONES

Este programa sigue la sintaxis habitual de línea de comandos de GNU, con opciones largas que comienzan con dos guiones ('--'). A continuación se incluye un resumen de las opciones.

-h --help
Muestra un resumen de las opciones.
-e --version
Imprime la información de la versión y sale
-v --default-vendor NUM
ID del proveedor a buscar (obligatorio), generalmente dada como número hexadecimal (ejemplo: 0x12d1). Cada dispositivo USB se identifica por un número asignado oficialmente al proveedor por la asociación USB y un número para el modelo respectivo (ID de producto) elegido por el proveedor
-p --default-product NUM
ID del producto a buscar (obligatorio)
-V --target-vendor NUM
ID del proveedor de destino. Si se proporciona, se buscará y detectará inicialmente con fines informativos. Si está activa la comprobación de éxito (opción -s), se recomienda proporcionar IDs de destino (proveedor/producto) o clase de destino
-j --find-mbim
Devuelve el número de configuración con interfaz MBIM y sale.
-P --target-product NUM
ID del producto de destino
-b --bus-num NUM
-g --device-num NUM
Si se proporcionan el número de bus y de dispositivo, se garantiza el manejo de un dispositivo específico en un puerto USB específico, a diferencia de usar solo la ID USB. Esto es importante si hay varios dispositivos similares en un sistema
-C --target-class NUM
Clase de dispositivo de destino según la especificación USB. Algunos dispositivos conservan su ID de proveedor/producto original después de un cambio exitoso. Para evitar que se traten de nuevo, se puede comprobar la clase del dispositivo. Para dispositivos sin cambio es siempre 8 (clase de almacenamiento), para módems cambiados a menudo es 0xff (específico del proveedor). En modos compuestos, se vigila la clase de la primera interfaz
-m --message-endpoint NUM
Un punto final específico para usar en transferencias de datos. Solo para fines de prueba; generalmente los puntos finales se determinan a partir de los atributos del dispositivo
-M --message-content STRING
Un mensaje de bloque para enviar como comando de cambio. Proporcionado como una cadena hexadecimal
-2 --message-content2 STRING
-3 --message-content3 STRING
Mensajes de bloque adicionales para enviar como comandos de cambio. Proporcionados como cadenas hexadecimales. Cuando se usan con comandos de almacenamiento masivo, se recomienda encarecidamente establecer --need-response para cumplir con las especificaciones y evitar errores probables
-w --release-delay <milisegundos>
Después de emitir todos los mensajes de bloque, espere el tiempo dado antes de liberar la interfaz. Requerido para algunos módems en sistemas antiguos (especialmente después de un mensaje EJECT)
-n --need-response
Obsoleto. CSW siempre se intenta leer después de las transferencias de almacenamiento masivo. Sin inconvenientes
-r --response-endpoint NUM
Intenta leer la respuesta a un comando de almacenamiento desde allí. Solo para fines de prueba; generalmente los puntos finales se determinan a partir de los atributos del dispositivo
-K --std-eject
Aplica la secuencia estándar de SCSI de "Permitir extracción de medios" y "Expulsar". Implica -n. Se puede añadir un 'Mensaje' con -M que se transmitirá después de la secuencia de expulsión. Utilizado por muchos módems
-d --detach-only
Simplemente desconecta el driver actual. Esto es suficiente para que algunos dispositivos tempranos cambien con éxito. De lo contrario, esta característica se puede utilizar como un 'bisturí' para casos especiales, como separar el driver de interfaces individuales
-H --huawei-mode
Envía un mensaje de control especial utilizado por dispositivos Huawei antiguos
-J --huawei-new-mode
Envía un mensaje de bloque específico utilizado por todos los dispositivos Huawei más nuevos
-X --huawei-alt-mode
Envía un mensaje de bloque alternativo a dispositivos Huawei
-S --sierra-mode
Envía un mensaje de control especial utilizado por dispositivos Sierra
-G --gct-mode
Envía un mensaje de control especial utilizado por chipsets GCT
-T --kobil-mode
Envía un mensaje de control especial utilizado por dispositivos Kobil
-N --sequans-mode
Envía un mensaje de control especial utilizado por el chipset Sequans
-A --mobileaction-mode
Envía un mensaje de control especial utilizado por el dispositivo MobileAction
-B --qisda-mode
Envía un mensaje de control especial utilizado por dispositivos Qisda
-E --quanta-mode
Envía un mensaje de control especial utilizado por dispositivos Quanta
-F --pantech-mode NUM
Envía un mensaje de control especial utilizado por dispositivos Pantech. El valor NUM se usará en el mensaje de control como 'wValue'
-Z --blackberry-mode
Envía un mensaje de control especial utilizado por algunos dispositivos Blackberry más nuevos
-S --option-mode
Envía un mensaje de control especial utilizado por todos los dispositivos Option
-O --sony-mode
Aplica una secuencia especial utilizada por dispositivos Sony Ericsson. Implica la opción --check-success
-L --cisco-mode
Envía una secuencia de mensajes de bloque utilizada por dispositivos Cisco
-R --reset-usb
Envía un comando de reinicio USB al dispositivo. Se puede combinar con cualquier método de cambio o de forma independiente. Siempre se realiza como último paso de todas las interacciones del dispositivo. Pocos dispositivos lo necesitan para completar el cambio; aparte de eso, puede ser útil durante las pruebas
-c --config-file ARCHIVO
Lee las configuraciones de los dispositivos de un archivo de configuración específico en lugar de la ubicación predeterminada de los archivos de configuración del sistema.
-i --disable-command
Deshabilita el envío de un mensaje de conmutación. Útil para probar si el dispositivo cambia correctamente por sí solo después de la desconexión o el reinicio. También puede ser utilizado para desactivar la conmutación de un dispositivo específico si ya se está manejando por otro método.
-u --update-mbim
Actualiza el número de configuración para la interfaz MBIM.
-a --use-last-config
Utiliza la última configuración exitosa para el dispositivo actual. Útil si el dispositivo cambia a un estado diferente después de un reinicio o una desconexión.
-g --quirks STRING
Establece una lista de 'quirks' (comportamientos especiales) para el dispositivo. Estos son ajustes que se pueden aplicar para manejar casos problemáticos específicos, como el comportamiento de dispositivos particulares o problemas de compatibilidad del sistema.
-f --force-load
Fuerza la carga de la interfaz incluso si ya está en uso. Tenga cuidado al usar esta opción, ya que puede causar inestabilidad o pérdida de datos.
-t --verbose
Habilita la salida detallada. Esto puede ser útil para depurar problemas o para comprender el proceso de cambio en detalle.

EJEMPLOS

Cambiar un dispositivo con ID de proveedor 0x12d1 e ID de producto 0x1001 a su modo de módem usando el archivo de configuración predeterminado:

  $ usb_modeswitch -v 0x12d1 -p 0x1001

Desconectar el driver de almacenamiento de un dispositivo con ID de proveedor 0x12d1 e ID de producto 0x1001:

  $ usb_modeswitch -v 0x12d1 -p 0x1001 -d

Utilizar un archivo de configuración específico y salida detallada:

  $ usb_modeswitch -v 0x12d1 -p 0x1001 -c /etc/usb_modeswitch.conf -t

OPCIONES

-c --config ARCHIVO
Usar un archivo de configuración específico. Si se proporcionan identificadores o opciones de conmutación como parámetros de línea de comandos, esta opción se ignora. En ese caso, todos los parámetros obligatorios deben ser proporcionados en la línea de comandos.
-f --long-config CADENA
Proporcionar los detalles del dispositivo en la sintaxis del archivo de configuración como una cadena multilínea en la línea de comandos.
-t --stdinput
Leer los detalles del dispositivo en la sintaxis del archivo de configuración desde la entrada estándar, por ejemplo, redirigida desde una tubería de comandos (texto multilínea).
-Q --quiet
No mostrar mensajes de progreso ni de error.
-W --verbose
Imprimir todas las configuraciones antes de ejecutar y mostrar mensajes de depuración de libusb.
-D --sysmode
Cambia el comportamiento del programa ligeramente. Se muestra un mensaje de éxito que incluye el identificador efectivo del dispositivo de destino y se emite un aviso en syslog. Principalmente para la integración con un script envoltorio.
-s --check-success <segundos>
Después de la conmutación, seguir comprobando el resultado hasta el tiempo indicado. Si se proporcionaron identificadores de destino o clase de destino, su aparición indica un éxito seguro. De lo contrario, la desconexión del dispositivo original se considera una prueba probable.
-I --inquire
Obsoleto. Obtenía anteriormente atributos SCSI, ahora se ignora.
-i --interface NUM
Seleccionar la interfaz USB inicial (por defecto: 0). Solo para fines de prueba.
-u --configuration NUM
Seleccionar la configuración USB (aplicada después de cualquier otra acción de conmutación posible).
-a --altsetting NUM
Seleccionar la configuración alternativa de la interfaz USB (aplicada después de la conmutación). Principalmente para pruebas.
