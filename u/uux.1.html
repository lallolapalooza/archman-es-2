uux(1) Manual de Comandos Generales uux(1)

NOMBRE

uux - Ejecución remota de comandos sobre UUCP

SINOPSIS

uux [ opciones ] comando

DESCRIPCIÓN

El comando uux se utiliza para ejecutar un comando en un sistema remoto, o para ejecutar un comando en el sistema local usando archivos de sistemas remotos. El comando no se ejecuta inmediatamente; la solicitud se pone en cola hasta que el demonio uucico (8) llama al sistema y lo ejecuta. El demonio se inicia automáticamente a menos que se proporcione una de las opciones -r o --nouucico.

La ejecución real del comando la realiza el demonio uuxqt (8).

Los argumentos de archivo pueden obtenerse de sistemas remotos al sistema de ejecución, al igual que la entrada estándar. La salida estándar puede dirigirse a un archivo en un sistema remoto.

El nombre del comando puede ir precedido por un nombre de sistema seguido de un signo de exclamación si se va a ejecutar en un sistema remoto. Un nombre de sistema vacío se toma como el sistema local.

Cada argumento que contiene un signo de exclamación se trata como un nombre de archivo. El sistema en el que se encuentra el archivo está antes del signo de exclamación, y la ruta en ese sistema le sigue. Un nombre de sistema vacío se toma como el sistema local; esto debe usarse para transferir un archivo a un comando que se ejecuta en un sistema remoto. Si la ruta no es absoluta, se añadirá al directorio de trabajo actual en el sistema local; el resultado puede no ser significativo en el sistema remoto. Una ruta puede comenzar con ~/, en cuyo caso es relativa al directorio público de UUCP (generalmente /usr/spool/uucppublic o /var/spool/uucppublic) en el sistema correspondiente. Una ruta puede comenzar con ~nombre/, en cuyo caso es relativa al directorio principal del usuario nombrado en el sistema correspondiente.

La entrada y salida estándar pueden redirigirse como de costumbre; las rutas utilizadas pueden contener signos de exclamación para indicar que están en sistemas remotos. Tenga en cuenta que los caracteres de redirección deben entrecomillarse para que sean pasados a uux en lugar de ser interpretados por el shell. La redirección de adición (>>) no funciona.

Todos los archivos especificados se recopilan en un solo directorio antes de que comience la ejecución del comando. Esto significa que cada archivo debe tener un nombre base distinto. Por ejemplo, 

uux 'sys1!diff sys2!~user1/foo sys3!~user2/foo >!foo.diff'
fallará porque ambos archivos se copiarán a sys1 y se almacenarán bajo el nombre foo.

Los argumentos pueden entrecomillarse mediante paréntesis para evitar la interpretación de los signos de exclamación. Esto es útil al ejecutar el comando uucp en un sistema remoto.

Una solicitud para ejecutar un comando vacío (por ejemplo, uux sys!) creará un archivo de sondeo para el sistema especificado.

El estado de salida de uux es uno de los códigos que se encuentran en el archivo de cabecera sysexits.h. En particular, EX_OK ( 0 ) indica éxito, y EX_TEMPFAIL ( 75 ) indica un fallo temporal.

OPCIONES

Las siguientes opciones pueden ser dadas a uux.

-, -p, --stdin
Lee la entrada estándar y la usa como entrada estándar para el comando a ejecutar.
-c, --nocopy
No copiar archivos locales al directorio de spool. Este es el valor predeterminado. Si se eliminan antes de ser procesados por el demonio uucico (8), la copia fallará. Los archivos deben ser legibles por el demonio uucico (8), así como por el que invoca uux.
-C, --copy
Copiar archivos locales al directorio de spool.
-l, --link
Enlazar archivos locales en el directorio de spool. Si un archivo no puede ser enlazado porque está en un dispositivo diferente, se copiará a menos que también aparezcan las opciones -c o --nocopy (en otras palabras, el uso de --link cambia el valor predeterminado de --nocopy a --copy). Si los archivos se modifican antes de ser procesados por el demonio uucico (8), se usarán las versiones modificadas. Los archivos deben ser legibles por el demonio uucico (8), así como por el que invoca uux.
-g grado, --grade grado
Establece el grado del comando de transferencia de archivos. Los trabajos de mayor grado se ejecutan primero. Los grados van de 0 a 9, A a Z, a a z, de mayor a menor.
-n, --notification=no
No enviar correo sobre el estado del trabajo, incluso si falla.
-z, --notification=error
Enviar correo sobre el estado del trabajo si ocurre un error. Para muchos demonios uuxqt, incluido el uuxqt de Taylor UUCP, esta es la acción predeterminada; para ellos, --notification=error no tendrá ningún efecto. Sin embargo, algunos demonios uuxqt enviarán correo si el trabajo tiene éxito a menos que se use la opción --notification=error, y algunos otros demonios uuxqt no enviarán correo si el trabajo falla a menos que se use la opción --notification=error.
-r, --nouucico
No iniciar el demonio uucico (8) inmediatamente; simplemente poner en cola la solicitud de ejecución para su procesamiento posterior.
-j, --jobid
Imprimir jobids en la salida estándar. Se generará un jobid para cada operación de copia de archivo requerida para realizar la operación. Estas copias de archivo pueden ser canceladas pasando el jobid al interruptor --kill de uustat (1), lo que hará imposible completar la ejecución.
-a direccion, --requestor direccion
Informar del estado del trabajo a la dirección de correo electrónico especificada.
-x tipo, --debug tipo
Activar tipos de depuración específicos. Se reconocen los siguientes tipos: abnormal, chat, handshake, uucp-proto, proto, port, config, spooldir, execute, incoming, outgoing. Solo abnormal, config, spooldir y execute son significativos para uux.

Se pueden dar varios tipos, separados por comas, y la opción --debug puede aparecer varias veces. También se puede dar un número, que activará ese número de tipos de la lista anterior; por ejemplo, --debug 2 es equivalente a --debug abnormal,chat.

-I archivo, --config archivo
Establece el archivo de configuración a utilizar. Esta opción puede no estar disponible, dependiendo de cómo se compiló uux.
-v, --version
Informar la información de la versión y salir.
--help
Imprimir un mensaje de ayuda y salir.

EJEMPLOS

uux -z - sys1!rmail usuario1

Ejecuta el comando ``rmail usuario1'' en el sistema sys1, dándole como entrada estándar lo que se le da a uux como entrada estándar. Si ocurre un fallo, envía un mensaje usando mail (1).

uux 'diff -c sys1!~usuario1/archivo1 sys2!~usuario2/archivo2 >!archivo.diff'
Obtiene los dos archivos nombrados del sistema sys1 y del sistema sys2 y ejecuta diff, colocando el resultado en archivo.diff en el directorio actual. El directorio actual debe ser escribible por el demonio uuxqt (8) para que esto funcione. 
uux 'sys1!uucp ~usuario1/archivo1 (sys2!~usuario2/archivo2)'
Ejecuta uucp en el sistema sys1 copiando archivo1 (en el sistema sys1) a sys2. Esto ilustra el uso de paréntesis para entrecomillar.

RESTRICCIONES

El sistema remoto puede no permitirle ejecutar ciertos comandos. Muchos sistemas remotos solo permiten la ejecución de rmail y rnews.

Algunas de las opciones dependen de las capacidades del demonio uuxqt (8) en el sistema remoto.

VER TAMBIÉN

mail(1), uustat(1), uucp(1), uucico(8), uuxqt(8)

ERRORES

Los archivos no se pueden referenciar a través de múltiples sistemas.

Se emiten demasiados jobids con --jobid, y no hay una forma fácil de cancelar una ejecución local que requiera archivos remotos.

NAME

uux - invoca comandos en una máquina remota (UUCP)

SYNOPSIS

uux [-CgrstAaNn] [-pproto] [-Llocale] [-eruta] [-oruta] [-r] [-druta] [-xdebug] máquina! comando ...

DESCRIPTION

uux invoca un comando en una máquina remota usando el sistema UUCP. El argumento comando es una secuencia de comandos y argumentos que se enviará a la máquina remota máquina para su ejecución. Los comandos y argumentos se pueden redirigir usando la sintaxis estándar de shell, como <, > y |.

El comando especificado se ejecuta en la máquina remota. Si el comando genera alguna salida estándar, esta se redirige a un archivo en el directorio de trabajo local. Si el comando genera algún error estándar, este se envía por correo electrónico al usuario que invocó el comando.

Las siguientes opciones están disponibles:

-C
Envía el comando al sistema de colas de la máquina remota sin ejecutarlo.
-g
Especifica el nivel de grado para el comando. El valor predeterminado es 7.
-r
No reinicies la ejecución del comando si falla.
-s
Envía el estado del comando por correo electrónico al usuario.
-t
Envía la salida del comando por correo electrónico al usuario.
-A
Activa la notificación de fin de trabajo para el comando.
-a
Desactiva la notificación de fin de trabajo para el comando.
-N
Especifica el número de trabajos para el comando.
-n
No envíes notificaciones por correo electrónico.
-pproto
Especifica el protocolo a utilizar para la comunicación remota.
-Llocale
Especifica la configuración regional a utilizar para el comando.
-eruta
Especifica la ruta del archivo de salida de errores.
-oruta
Especifica la ruta del archivo de salida estándar.
-druta
Especifica el directorio de trabajo para el comando.
-xdebug
Activa el modo de depuración con el nivel especificado.

OPTIONS

Para obtener una lista completa de opciones y sus descripciones, consulta la página del manual de uux (`man uux`).

EXAMPLES

Ejecutar el comando ls en la máquina remota maquina_remota y guardar la salida en salida.txt:

uux maquina_remota! ls > salida.txt

Copiar el archivo archivo.txt de la máquina local a la máquina remota maquina_remota y ejecutar el comando cat en él:

uux - - < archivo.txt | maquina_remota! cat > resultado.txt

RESTRICTIONS

El comando uux solo se puede utilizar para ejecutar comandos que se sabe que existen en la máquina remota. No se pueden ejecutar comandos arbitrarios.

El acceso a las máquinas remotas y la ejecución de comandos están sujetos a las configuraciones de seguridad del sistema UUCP.
