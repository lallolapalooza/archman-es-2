DESCRIPCIÓN

Unbound es una implementación de un resolvedor DNS, que realiza caché y validación DNSSEC. Esta es la API de la biblioteca, para usar la biblioteca -lunbound. El demonio del servidor se describe en unbound(8). La biblioteca funciona independientemente de un servidor unbound en ejecución y se puede utilizar para convertir nombres de host en direcciones IP, y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de resultados con claves públicas con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Puede ser creada y eliminada en cualquier momento. Crearla de nuevo elimina cualquier configuración previa (como claves de confianza) y borra cualquier resultado en caché.

Las funciones son seguras para hilos (thread-safe), y un contexto puede ser utilizado en un entorno multihilo (así como en uno de un solo hilo). La resolución (y validación) también puede realizarse de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve la llamada inmediatamente, de modo que el procesamiento puede continuar, mientras los resultados están disponibles más tarde.

Las funciones se discuten a continuación.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza por defecto. Usa ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esto, utiliza las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si usas lib openssl (la aplicación llama a estas funciones una vez para la inicialización). Openssl 1.0.0 o posterior utiliza la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y las devoluciones de llamada (callbacks) no se llaman para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que permite especificar una de las opciones del formato de archivo de configuración, véase unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como añadir anclajes de confianza, existen rutinas especiales. Pasa el nombre de la opción con el sufijo ':'.
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene un valor de opción. Algunas opciones no se pueden obtener, y otras devuelven una lista separada por saltos de línea. Pasa el nombre de la opción sin el sufijo ':'. El valor devuelto debe ser liberado con free(2) por el llamador.
ub_ctx_config
Una interfaz para usuarios avanzados que permite especificar un archivo de configuración de unbound, véase unbound.conf(5), que se lee para la configuración. No todas las opciones son relevantes. Para algunas opciones específicas, como añadir anclajes de confianza, existen rutinas especiales. Esta función solo es segura para hilos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no se llame en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se enviarán las consultas DNS, el resolvedor de caché a utilizar. Dirección IP4 o IP6. Reenvía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolvedor recursivo. Si el proxy no es compatible con DNSSEC, la validación puede fallar. Se puede llamar varias veces, en cuyo caso las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible configurar antes de la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autoritativos a utilizar para una zona particular. Dirección IP4 o IP6. Si la dirección es NULL, se elimina la entrada stub. Establece isprime en true si se configuran hints de raíz con ella. De lo contrario, es similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas, o para añadir varias direcciones para una zona particular. En este momento, solo es posible configurar antes de la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible configurar antes de la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolvedor completo, pero puedes usar esta llamada para leer la lista de servidores de nombres a utilizar del nombre de archivo dado. Normalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no admiten DNSSEC, la validación puede fallar. Solo se seleccionan los servidores de nombres, el dominio de búsqueda, ndots y otros ajustes de resolv.conf(5) se ignoran. Si se pasa NULL como fname, se utiliza "/etc/resolv.conf" (si estás en Windows, se selecciona el servidor de nombres configurado a nivel de sistema en su lugar). En este momento, solo es posible configurar antes de la primera resolución.
ub_ctx_hosts
Lee la lista de hosts del nombre de archivo dado. Normalmente "/etc/hosts". Cuando se consultan, estas direcciones no se marcan como seguras con DNSSEC. Si se pasa NULL como fname, se utiliza "/etc/hosts" (si estás en Windows, se selecciona etc/hosts de WINDIR en su lugar). En este momento, solo es posible configurar antes de la primera

DESCRIPTION

The unbound library provides routines to perform DNS resolution and DNSSEC validation. It is a validating, recursive, caching DNS resolver. The library can be used by applications to perform DNS queries and obtain DNSSEC-signed results. The library routines can be used to build advanced DNS clients or servers.

A context (struct ub_ctx) is needed for all operations. Create it with ub_ctx_create and destroy it with ub_ctx_destroy. The context holds the configuration and state for the resolver instance.

Options can be set and retrieved using ub_ctx_set_option and ub_ctx_get_option. The options correspond to the options in the unbound.conf file, see unbound.conf(5). Note that not all options are available from the library API. Some options can only be set during creation, and some may not be settable at all.

Use ub_ctx_prev to iterate through previous contexts. This is useful if you want to use the same configuration but need a new context for a new set of tasks.

Trust anchors (trusted keys) can be added to the context. They are used for DNSSEC validation. They can be added directly as strings, from files, or from files that are automatically updated.

Debug output can be directed to a specific file stream using ub_ctx_debugout. Verbosity can be controlled using ub_ctx_debuglevel.

The library can operate in synchronous or asynchronous mode. Use ub_ctx_async to control this. By default, asynchronous mode is off, and calls to ub_resolve block until the result is ready. If asynchronous mode is on, calls to ub_resolve_async return immediately, and the results are delivered later via a callback function.

For asynchronous operation, you need to use the file descriptor obtained from ub_fd to poll for readiness. When the file descriptor is readable, call ub_process to perform the callbacks. Alternatively, you can use ub_wait to block until results are ready.

ub_resolve performs a synchronous DNS query and validation. It returns the result in a newly allocated structure.

ub_resolve_async performs an asynchronous DNS query and validation. The results are delivered to the specified callback function. An identifier for the asynchronous query is returned, which can be used with ub_cancel to cancel the query.

ub_resolve_free is used to free the memory allocated for the result structure.

ub_strerror converts error codes returned by the library functions into human-readable strings.

Local zones and data can be added to the context using ub_ctx_zone_add, ub_ctx_zone_remove, ub_ctx_data_add, and ub_ctx_data_remove. This allows the library to act as an authoritative server for specific zones or data.

FUNCTIONS

ub_ctx_create
Create a new context for the unbound library. Returns a pointer to the context, or NULL on error.
ub_ctx_destroy
Destroy the context and free all associated resources.
ub_ctx_set_option
Set an option for the context. The option name and value are given as strings. Returns 0 on success, or an error code.
ub_ctx_get_option
Get the value of an option for the context. The option name is given as a string. The value is returned as a newly allocated string via the val argument. The caller is responsible for freeing this string. Returns 0 on success, or an error code.
ub_ctx_prev
Get the previous context in the list of contexts. Used to iterate through contexts. Returns NULL if there is no previous context.
ub_ctx_add_ta
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
ub_ctx_add_ta_autr
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta_file
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_trustedkeys
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_debugout
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
ub_ctx_debuglevel
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
ub_ctx_async
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
ub_poll
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
ub_wait
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
ub_fd
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
ub_process
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
ub_resolve
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
ub_resolve_async
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

ub_cancel
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
ub_resolve_free
Free struct ub_result contents after use.
ub_strerror
Convert error value from one of the unbound library functions to a human readable string.
ub_ctx_print_local_zones
Debug printout the local authority information to debug output.
ub_ctx_zone_add
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
ub_ctx_zone_remove
Delete zone from local authority info.
ub_ctx_data_add
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
ub_ctx_data_remove
Delete local authority data from the name given.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Else, they are not both true, one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.

Acerca de Arch Linux

Arch Linux es una distribución de Linux independiente, desarrollada para usuarios experimentados que aprecian la simplicidad, la modernidad, el pragmatismo y la versatilidad. Los usuarios son responsables de configurar su sistema para satisfacer sus necesidades específicas.

Arch Linux se adhiere a un modelo de lanzamiento continuo. Las actualizaciones de software se lanzan periódicamente en forma de paquetes que se pueden actualizar inmediatamente, lo que permite a los usuarios mantener su sistema actualizado con las últimas versiones estables de software.

Un gestor de paquetes avanzado, Pacman, se utiliza para instalar, eliminar y actualizar software. El sistema de compilación de Arch Linux (ABS) es un sistema basado en Makefiles que facilita a los usuarios la compilación de software a partir de sus archivos fuente.

La filosofía de diseño de Arch Linux se centra en la simplicidad, la elegancia y la transparencia del código, y se esfuerza por mantener el código lo más "puro" posible sin modificaciones innecesarias.

Los usuarios pueden obtener una experiencia de escritorio completamente funcional con una instalación mínima de Arch Linux y luego instalar solo los componentes que desean. Una instalación estándar de Arch Linux proporciona un sistema base minimalista.

Arch Linux incluye una gran cantidad de paquetes disponibles a través de los repositorios oficiales, y los usuarios pueden encontrar muchos más paquetes en el Arch User Repository (AUR).
