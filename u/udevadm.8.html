UDEVADM(8) udevadm UDEVADM(8)

NOMBRE

udevadm - herramienta de gestión de udev

SINOPSIS

udevadm [--debug] [--version] [--help]

udevadm info [opciones...] [devpath|syspath|id|unit...]

udevadm trigger [opciones...] [devpath|syspath|id|unit...]

udevadm settle [opciones...]

udevadm control opciones...

udevadm monitor [opciones...]

udevadm test [opciones...] devpath|syspath|id|unit

udevadm test-builtin [opciones...] comando devpath|syspath|id|unit

udevadm verify [opciones...] [archivos...]

udevadm cat [opciones...] [archivos...]

udevadm wait [opciones...] devpath|syspath...

udevadm lock [opciones...] comando...

DESCRIPCIÓN

udevadm espera un comando y opciones específicas del comando. Controla el comportamiento en tiempo de ejecución de systemd-udevd, solicita eventos del kernel, gestiona la cola de eventos y proporciona mecanismos de depuración sencillos.

OPCIONES

-d, --debug

Imprime mensajes de depuración en la salida de error estándar. Esta opción se implica en los comandos udevadm test y udevadm test-builtin.

-V, --version

Imprime una cadena de versión corta y sale.

-h, --help

Imprime un texto de ayuda corto y sale.

udevadm info [opciones...] [devpath|syspath|id|unit...]

Consulta la base de datos de udev para obtener información del dispositivo.

Los argumentos posicionales se deben utilizar para especificar uno o más dispositivos. Cada uno puede ser un nombre de dispositivo (en cuyo caso debe empezar por /dev/), una ruta sys (en cuyo caso debe empezar por /sys/), un ID de dispositivo (como "n1", "c5:1" o "b259:1", véase sd_device_get_device_id(3)) o un nombre de unidad de dispositivo systemd (en cuyo caso debe terminar con ".device", véase systemd.device(5)).

-q, --query=TIPO

Consulta la base de datos para el tipo de datos del dispositivo especificado. Los TIPOS válidos son: name, symlink, path, property, all.

--property=NOMBRE

Al mostrar propiedades de dispositivo con la opción --query=property, limita la visualización a las propiedades especificadas en el argumento. El argumento debe ser una lista de nombres de propiedad separados por comas. Si no se especifica, se muestran todas las propiedades conocidas.

Añadido en la versión 250.

--value

Al mostrar propiedades de dispositivo con la opción --query=property, imprime solo sus valores y omite el nombre de la propiedad y el "=".

No se puede usar junto con -x/--export o -P/--export-prefix.

Añadido en la versión 250.

-p, --path=DEVPATH

La ruta /sys/ del dispositivo a consultar, por ejemplo, [/sys/]/class/block/sda. Esta opción es una alternativa al argumento posicional con prefijo /sys/. udevadm info --path=/class/block/sda es equivalente a udevadm info /sys/class/block/sda.

-n, --name=ARCHIVO

El nombre del nodo del dispositivo o un enlace simbólico a consultar, por ejemplo, [/dev/]/sda. Esta opción es una alternativa al argumento posicional con prefijo /dev/. udevadm info --name=sda es equivalente a udevadm info /dev/sda.

-r, --root

Imprime rutas absolutas en la consulta name o symlink.

-a, --attribute-walk

Imprime todas las propiedades de sysfs del dispositivo especificado que se pueden usar en las reglas de udev para que coincidan con el dispositivo especificado. Imprime todos los dispositivos a lo largo de la cadena, hasta la raíz de sysfs que se puede usar en las reglas de udev.

Este modificador admite el modo de salida JSON (ver --json= más abajo). Dado que este modificador genera múltiples objetos JSON, el modo JSON-SEQ se habilita automáticamente (RFC7464). (Nota: las herramientas como jq[1] admiten JSON-SEQ de forma nativa a través del modificador --seq).

-t, --tree

Muestra un árbol de sysfs. Esto itera recursivamente a través de la jerarquía de sysfs y la muestra en una estructura de árbol. Si se especifica una ruta, solo se mostrará el subárbol inferior y sus directorios padre. Esto mostrará elementos tanto de dispositivos como de subsistemas.

Añadido en la versión 251.

-x, --export

Imprime la salida como pares clave/valor. Los valores se encierran entre comillas simples. Esto solo tiene efecto cuando se especifica --query=property o --device-id-of-file=ARCHIVO.

-P, --export-prefix=NOMBRE

Añade un prefijo al nombre clave de los valores exportados. Esto implica --export.

-d, --device-id-of-file=ARCHIVO

Imprime los números mayor/menor del dispositivo subyacente donde reside el archivo. Si se especifica esto, se ignoran todos los argumentos posicionales.

-e, --export-db

Exporta el contenido de la base de datos de udev.

-c, --cleanup-db

Limpia la base de datos de udev.

-w[SEGUNDOS], --wait-for-initialization[=SEGUNDOS]

Espera a que el dispositivo se inicialice. Si no se especifica el argumento SEGUNDOS, el valor predeterminado es esperar infinitamente.

Añadido en la versión 243.

--subsystem-match[=SUBSISTEMA], --subsystem-nomatch[=SUBSISTEMA]

Cuando se utiliza con --export-db, solo muestra dispositivos del subsistema especificado o que no sean de dicho subsistema, respectivamente.

Añadido en la versión 255.

--attr-match[=ARCHIVO[=VALOR]], --attr-nomatch[=ARCHIVO[=VALOR]]

Cuando se utiliza con --export-db, solo muestra dispositivos que coinciden o no coinciden con el atributo especificado, respectivamente.

Añadido en la versión 255.

--property-match[=CLAVE=VALOR]

Cuando se utiliza con --export-db, solo muestra dispositivos que coinciden con la propiedad y el valor especificados.

Añadido en la versión 255.

--tag-match[=TAG]

Cuando se utiliza con --export-db, solo muestra dispositivos con la etiqueta especificada.

Añadido en la versión 255.

--sysname-match[=NOMBRE]

Cuando se utiliza con --export-db, solo muestra dispositivos con la ruta "/sys" especificada.

Añadido en la versión 255.

--name-match[=NOMBRE]

Cuando se utiliza con --export-db, solo muestra dispositivos con el nombre especificado en "/dev".

Añadido en la versión 255.

--parent-match[=NOMBRE]

Cuando se utiliza con --export-db, solo muestra dispositivos con el dispositivo padre especificado.

Añadido en la versión 255.

--initialized-match, --initialized-nomatch

Cuando se utiliza con --export-db, solo muestra dispositivos que están inicializados o no inicializados, respectivamente.

Añadido en la versión 255.

--json=MODO

Muestra la salida formateada como JSON. Espera uno de los valores: "short" (para la salida más corta posible sin espacios en blanco redundantes ni saltos de línea), "pretty" (para una versión bonita de la misma, con indentación y saltos de línea) o "off" (para desactivar la salida JSON, el valor predeterminado).

--no-pager

No canalizar la salida a un paginador.

La salida generada muestra la base de datos de dispositivos actual

udevadm

udev rules processing utility

SYNOPSIS

udevadm [options...] subcommand [args...]

DESCRIPTION

udevadm is used for introspecting and controlling the udev device manager.

It can be used to trigger device events, query device information, and reload rules.

This utility is primarily intended for debugging and runtime device management tasks.

SUBCOMMANDS

The following subcommands are available:

  • trigger
  • settle

Additional subcommands are available, but are not described here.

udevadm info [options] [devpath|syspath|id|unit]

Query device information.

The udevadm info command shows information about a specific device. The device can be specified by its syspath, devpath, or by an existing device node name. If no device is specified, information about all devices is printed.

-e, --export-db

Export the internal event queue database. The output is in a terse format. Each line shown is prefixed with one of the following characters:

Table 1. udevadm info output prefixes

Prefix Meaning
"P:" Device path in /sys/
"M:" Device name in /sys/ (i.e. the last component of "P:")
"R:" Device number in /sys/ (i.e. the numeric suffix of the last component of "P:")
"J:" Device ID
"U:" Kernel subsystem
"B:" Driver subsystem
"T:" Kernel device type within subsystem
"D:" Kernel device node major/minor
"I:" Network interface index
"N:" Kernel device node name
"L:" Device node symlink priority
"S:" Device node symlink
"Q:" Block device sequence number (DISKSEQ)
"V:" Attached driver
"E:" Device property

udevadm trigger [options...] [devpath|syspath|id|unit...]

Request device events from the kernel. Primarily used to replay events at system coldplug time.

Takes device specifications as positional arguments. See the description of udevadm info above.

-v, --verbose

Print the list of devices which will be triggered.

-n, --dry-run

Do not actually trigger the event.

-q, --quiet

Suppress error logging in triggering events.

Added in version 248.

-t, --type=TYPE

Trigger a specific type of devices. Valid types are "all", "devices", and "subsystems". The default value is "devices".

-c, --action=ACTION

Type of event to be triggered. Possible actions are "add", "remove", "change", "move", "online", "offline", "bind", and "unbind". Also, the special value "help" can be used to list the possible actions. The default value is "change".

--prioritized-subsystem=SUBSYSTEM[,SUBSYSTEM...]

Takes a comma separated list of subsystems. When triggering events for devices, the devices from the specified subsystems and their parents are triggered first. For example, if --prioritized-subsystem=block,net, then firstly all block devices and their parents are triggered, in the next all network devices and their parents are triggered, and lastly the other devices are triggered. This option can be specified multiple times, and in that case the lists of the subsystems will be merged. That is, --prioritized-subsystem=block --prioritized-subsystem=net is equivalent to --prioritized-subsystem=block,net.

Added in version 251.

-s, --subsystem-match=SUBSYSTEM

Trigger events for devices which belong to a matching subsystem. This option supports shell style pattern matching. When this option is specified more than once, then each matching result is ORed, that is, all the devices in each subsystem are triggered.

-S, --subsystem-nomatch=SUBSYSTEM

Do not trigger events for devices which belong to a matching subsystem. This option supports shell style pattern matching. When this option is specified more than once, then each matching result is ANDed, that is, devices which do not match all specified subsystems are triggered.

-a, --attr-match=ATTRIBUTE=VALUE

Trigger events for devices with a matching sysfs attribute. If a value is specified along with the attribute name, the content of the attribute is matched against the given value using shell style pattern matching. If no value is specified, the existence of the sysfs attribute is checked. When this option is specified multiple times, then each matching result is ANDed, that is, only devices which have all specified attributes are triggered.

-A, --attr-nomatch=ATTRIBUTE=VALUE

Do not trigger events for devices with a matching sysfs attribute. If a value is specified along with the attribute name, the content of the attribute is matched against the given value using shell style pattern matching. If no value is specified, the existence of the sysfs attribute is checked. When this option is specified multiple times, then each matching result is ANDed, that is, only devices which have none of the specified attributes are triggered.

-p, --property-match=PROPERTY=VALUE

Trigger events for devices with a matching property value. This option supports shell style pattern matching. When this option is specified more than once, then each matching result is ORed, that is, devices which have one of the specified properties are triggered.

-g, --tag-match=TAG

Trigger events for devices with a matching tag. When this option is specified multiple times, then each matching result is ANDed, that is, devices which have all specified tags are triggered.

-y, --sysname-match=NAME

Trigger events for devices for which the last component (i.e. the filename) of the /sys/ path matches the specified PATH. This option supports shell style pattern matching. When this option is specified more than once, then each matching result is ORed, that is, all devices which have any of the specified NAME are triggered.

--name-match=NAME

Trigger events for devices with a matching device path. When this option is specified more than once, then each matching result is ORed, that is, all specified devices are triggered.

Added in version 218.

-b, --parent-match=SYSPATH

Trigger events for all children of a given device. When this option is specified more than once, then each matching result is ORed, that is, all children of each specified device are triggered.

--initialized-match, --initialized-nomatch

When --initialized-match is specified, trigger events for devices that are already initialized by systemd-udevd, and skip devices that are not initialized yet.

When --initialized-nomatch is specified, trigger events for devices that are not initialized by systemd-udevd yet, and skip devices that are already initialized.

Typically, it is essential that applications which intend to use such a match, make sure a suitable udev rule is installed that sets at least one property on devices that shall be matched. See also Initialized Devices section below for more details.


Warning
--initialized-nomatch can potentially save a significant amount of time compared to re-triggering all devices in the system and e.g. can be used to optimize boot time. However, this is not safe to be used in a boot sequence in general. Especially, when udev rules for a device depend on its parent devices (e.g. "ATTRS" or "IMPORT{parent}" keys, see udev(7) for more details), the final state of the device becomes easily unstable with this option.
Added in version 251.

--include-parents

Trigger parent devices of found devices even if the parents will not match the filter condition. This is useful if we are interested to limit the coldplug activities to some devices or subsystems.

Added in version 258.

-w, --settle

Apart from triggering events, also waits for those events to finish. Note that this is different from calling udevadm settle. udevadm settle waits for all events to finish. This option only waits for events triggered by the same command to finish.

Added in version 238.

--uuid

Trigger the synthetic device events, and associate a randomized UUID with each. These UUIDs are printed to standard output, one line for each event. These UUIDs are included in the uevent environment block (in the "SYNTH_UUID=" property) and may be used to track delivery of the generated events.

Added in version 249.

--wait-daemon[=SECONDS]

Before triggering uevents, wait for systemd-udevd daemon to be initialized. Optionally takes timeout value. Default timeout is 5 seconds. This is equivalent to invoking udevadm control --ping before udevadm trigger.

Added in version 241.

In addition, optional positional arguments can be used to specify device names or sys paths. They must start with /dev/ or /sys/ respectively.

udevadm settle [options...]

Watches the udev event queue, and exits if all current events are handled.

-t, --timeout=SECONDS

Maximum number of seconds to wait for the event queue to become empty. The default value is 120 seconds. A value of 0 will check if the queue is empty and always return immediately. A non-zero value will return an exit code of 0 if queue became empty before timeout was reached, non-zero otherwise.

-E, --exit-if-exists=FILE

Stop waiting if file exists.

See systemd-udev-settle.service(8) for more information.

udevadm control options...

Modifica el estado interno del demonio udev en ejecución.

-e, --exit

Envía una señal y espera a que systemd-udevd salga. No se puede especificar ninguna opción excepto --timeout después de esta opción. Tenga en cuenta que systemd-udevd.service contiene Restart=always y como resultado, esta opción reinicia systemd-udevd. Si desea detener systemd-udevd.service, utilice lo siguiente: 
systemctl stop systemd-udevd-control.socket systemd-udevd-kernel.socket systemd-udevd-varlink.socket systemd-udevd.service

-l, --log-level=valor

Establece el nivel de registro interno de systemd-udevd. Los valores válidos son las prioridades numéricas de syslog o sus representaciones textuales: emerg, alert, crit, err, warning, notice, info y debug.

-s, --stop-exec-queue

Envía una señal a systemd-udevd para que deje de ejecutar nuevos eventos. Los eventos entrantes se pondrán en cola.

-S, --start-exec-queue

Envía una señal a systemd-udevd para que habilite la ejecución de eventos.

-R, --reload

Envía una señal a systemd-udevd para que recargue los archivos de reglas y otras bases de datos como el índice de módulos del kernel. La recarga de reglas y bases de datos no aplica ningún cambio a los dispositivos ya existentes; la nueva configuración solo se aplicará a los nuevos eventos.

-p, --property=CLAVE=valor

Establece una propiedad global para todos los eventos.

-m, --children-max=valor

Establece el número máximo de eventos que systemd-udevd manejará al mismo tiempo. Cuando se especifica 0, el máximo se determina en función de los recursos del sistema.

--ping

Envía un mensaje ping a systemd-udevd y espera la respuesta. Esto puede ser útil para comprobar que el demonio systemd-udevd está en ejecución.

Añadido en la versión 241.

--trace=BOOL

Habilita/deshabilita el registro de rastreo en systemd-udevd.

Añadido en la versión 258.

--revert

Revierte la configuración previamente establecida con el comando udevadm control. Cuando se especifica, se borrarán la configuración establecida con -l/--log-level=, --trace, -m/--children-max= y -p/--property=.

Añadido en la versión 258.

-t, --timeout=segundos

El número máximo de segundos para esperar una respuesta de systemd-udevd.

--load-credentials

Cuando se especifica, se utilizan las siguientes credenciales cuando se pasan:

udev.conf.*

Estas credenciales deben contener datos de configuración válidos de udev.conf(5). De cada credencial coincidente se crea un archivo separado. Ejemplo: una credencial pasada udev.conf.50-foobar se copiará en un archivo de configuración /run/udev/udev.conf.d/50-foobar.conf.

Añadido en la versión 256.

udev.rules.*

Estas credenciales deben contener reglas válidas de udev(7). De cada credencial coincidente se crea un archivo separado. Ejemplo: una credencial pasada udev.rules.50-foobar se copiará en un archivo de configuración /run/udev/rules.d/50-foobar.rules.

Añadido en la versión 256.

Tenga en cuenta que esto no implica la opción --reload. Por lo tanto, si systemd-udevd ya está en ejecución, considere también especificar -reload para que los archivos de reglas de udev copiados sean utilizados por systemd-udevd.

Añadido en la versión 256.

udevadm monitor [options...]

Escucha los uevents del kernel y los eventos enviados por una regla de udev e imprime la ruta del dispositivo (devpath) del evento en la consola. Puede usarse para analizar el tiempo de los eventos, comparando las marcas de tiempo del uevent del kernel y el evento de udev.

-k, --kernel

Imprime los uevents del kernel.

-u, --udev

Imprime el evento de udev después del procesamiento de la regla.

-p, --property

También imprime las propiedades del evento.

-s, --subsystem-match=cadena[/cadena]

Filtra los uevents del kernel y los eventos de udev por subsistema[/tipo de dispositivo]. Solo pasarán los eventos con un valor de subsistema coincidente. Si esta opción se especifica más de una vez, cada resultado coincidente se unirá con OR, es decir, se supervisarán todos los dispositivos en los subsistemas especificados.

-t, --tag-match=cadena

Filtra los eventos de udev por etiqueta. Solo pasarán los eventos de udev con una etiqueta dada adjunta. Si esta opción se especifica más de una vez, cada resultado coincidente se unirá con OR, es decir, se supervisarán los dispositivos que tengan una de las etiquetas especificadas.

udevadm test [options...] devpath|syspath|id|unit

Simula una ejecución de eventos de udev para el dispositivo dado, e imprime la salida de depuración. La opción --json= puede ser útil para analizar el resultado final. Consulte también la sección de ejemplos.

-a, --action=ACCIÓN

Tipo de evento a simular. Las acciones posibles son "add", "remove", "change", "move", "online", "offline", "bind" y "unbind". Además, el valor especial "help" se puede usar para listar las acciones posibles. El valor predeterminado es "add".

-N, --resolve-names=early|late|never

Especifica cuándo udevadm debe resolver los nombres de usuarios y grupos especificados en las reglas de udev. Cuando se establece en early (el valor predeterminado), los nombres se resolverán al analizar las reglas. Cuando se establece en late, los nombres se resolverán durante el procesamiento del evento. Cuando se establece en never, los nombres nunca se resolverán y las reglas de udev relevantes serán ignoradas.

Añadido en la versión 209.

-D DIR, --extra-rules-dir=DIR

También carga archivos de reglas de udev del directorio especificado. Esta opción se puede especificar varias veces. Puede ser útil para depurar reglas de udev copiando algunos archivos de reglas de udev a un directorio temporal, editándolos y especificando el directorio con esta opción. Los archivos encontrados en los directorios especificados tienen una prioridad mayor que los archivos de reglas en los directorios predeterminados udev/rules.d utilizados por systemd-udevd. Consulte udev(7) para obtener más detalles sobre las rutas de búsqueda.

Añadido en la versión 258.

-v, --verbose

Muestra registros detallados en el procesamiento de reglas de udev.

Añadido en la versión 258.

--json=MODO

Muestra la salida formateada como JSON. Espera uno de "short" (para la salida más corta posible sin espacios en blanco redundantes ni saltos de línea), "pretty" (para una versión bonita de lo mismo, con indentación y saltos de línea) o "off" (para desactivar la salida JSON, el valor predeterminado).

udevadm test-builtin [options...] command devpath|file|unit

Ejecuta un comando incorporado COMMAND para el dispositivo DEVPATH, e imprime la salida de depuración.

-a, --action=ACCIÓN

Tipo de evento a simular. Las acciones posibles son "add", "remove", "change", "move", "online", "offline", "bind" y "unbind". Además, el valor especial "help" se puede usar para listar las acciones posibles. El valor predeterminado es "add".

udevadm verify [options...] [files...]

Verifica la corrección sintáctica, semántica y estilística de los archivos de reglas de udev.

Los argumentos posicionales se pueden usar para especificar uno o más archivos a verificar. Cada argumento debe ser una ruta absoluta a un archivo de reglas de udev o un directorio que contenga archivos de reglas, o un nombre de archivo de reglas de udev (por ejemplo, 99-systemd.rules). Si se especifica un nombre de archivo, el archivo se buscará en los directorios udev/rules.d que procesa systemd-udevd, y se buscará en el directorio de trabajo actual si no se encuentra. Si no se especifican archivos, las reglas de udev se leerán de los archivos ubicados en los mismos directorios udev/rules.d que procesa systemd-udevd. Consulte udev(7) para obtener más detalles sobre las rutas de búsqueda.

El estado de salida es 0 si todos los archivos de reglas de udev especificados son sintáctica, semántica y estilísticamente correctos, y un código de error distinto de cero en caso contrario.

-N, --resolve-names=early|late|never

Especifica cuándo udevadm debe resolver los nombres de usuarios y grupos especificados en las reglas de udev. Cuando se establece en early (el valor predeterminado), los nombres se resolverán al analizar las reglas. Cuando se establece en late, los nombres no se verificarán, ya que systemd-udevd resuelve los nombres durante cada evento que se procesa. Cuando se establece en never, los nombres nunca se resolverán y las reglas relevantes serán ignoradas.

INTRODUCCIÓN

udevadm es una utilidad para inspeccionar y controlar el systemd-udevd.service(8) subsystem. Se pueden obtener vistas sobre el estado actual, y se pueden activar eventos y reglas de dispositivo.

COMANDOS

udevadm info [options...] [NODE...]

Obtener información detallada sobre los dispositivos. Si no se especifica ningún NODE, se utiliza el nodo del dispositivo actual. El NODE puede ser un nombre de archivo de dispositivo (por ejemplo, /dev/sda1) o una ruta en el árbol sysfs (por ejemplo, /sys/class/net/eth0).

-a, --attribute-walk

Muestra todos los atributos de dispositivo, incluyendo los atributos de los dispositivos padres, recursivamente.

Added in version 183.

-p, --path=

Especifica la ruta de sysfs del dispositivo, en lugar de la ruta del nodo del dispositivo. Por ejemplo, /sys/devices/pci0000:00/0000:00:1f.6/net/eth0.

Added in version 183.

-q, --query=

Pregunta por el valor de un atributo específico. Si el atributo no se encuentra, se devuelve un código de salida distinto de cero.

Added in version 183.

-n, --name=

Busca la ruta de sysfs del dispositivo dado su nombre de nodo de dispositivo. Por ejemplo, -n /dev/network/eth0.

Added in version 183.

-s, --sys-path=

Busca la ruta de sysfs del dispositivo dado su nombre de nodo de dispositivo.

Added in version 197.

-e, --export-variables=

Lista todas las variables de entorno que serán exportadas cuando se procese el dispositivo dado.

Added in version 183.

-c, --cleanup=

Limpia el caché de dispositivos. Sólo tiene efecto si se ejecuta como root.

Added in version 183.

-l, --link-path=

Lista todos los enlaces simbólicos que apuntan al dispositivo dado.

Added in version 183.

--property=

Lista el valor de todas las propiedades establecidas para el dispositivo dado.

Added in version 246.

--json={auto,off,pretty,export}

Establece el formato de salida. Se pueden usar argumentos posicionales para especificar uno o más archivos para mostrar. udevadm lock [options...] command...

udevadm lock toma un bloqueo exclusivo (advisory) en un dispositivo de bloque (o todos los dispositivos especificados), según lo definido en Locking Block Device Access[2], e invoca un programa con los bloqueos tomados. Cuando el programa invocado sale, los bloqueos se liberan automáticamente y su valor de retorno se propaga como código de salida de udevadm lock.

Esta herramienta es particularmente útil para garantizar que systemd-udevd.service(8) no investigue un dispositivo de bloque mientras se realizan cambios en él, por ejemplo, se crean particiones o se formatean sistemas de archivos. Tenga en cuenta que muchas herramientas que interactúan con dispositivos de bloque soportan de forma nativa la toma de bloqueos relevantes, consulte por ejemplo el modificador --lock de sfdisk(8).

El comando espera al menos un dispositivo de bloque especificado a través de --device= o --backing=, y una línea de comandos para ejecutar como argumentos.

--device=DEVICE, -d DEVICE

Toma una ruta a un nodo de dispositivo del dispositivo a bloquear. Este modificador puede usarse múltiples veces (y en combinación con --backing=) para bloquear múltiples dispositivos. Si se especifica un nodo de dispositivo de bloque de partición, el dispositivo de bloque "completo" que lo contiene se determina y utiliza automáticamente para el bloqueo, según la especificación. Si se especifican múltiples dispositivos, se eliminan los duplicados, se ordenan por el mayor/menor de sus nodos de dispositivo y luego se bloquean en orden.

Este modificador debe usarse al menos una vez, para especificar al menos un dispositivo a bloquear. (Alternativamente, use --backing=, ver más abajo).

Added in version 251.

--backing=PATH, -b PATH

Si se especifica una ruta a un nodo de dispositivo, idéntico a --device=. Sin embargo, este modificador acepta alternativamente una ruta a un archivo regular o directorio, en cuyo caso el dispositivo de bloque del sistema de archivos en el que reside el archivo/directorio se determina y utiliza automáticamente como si se hubiera especificado con --device=.

Added in version 251.

--timeout=SECS, -t SECS

Especifica cuánto tiempo esperar como máximo hasta que se puedan tomar todos los bloqueos. Toma un valor en segundos, o en las unidades de tiempo habituales soportadas, ver systemd.time(7). Si se especifica como cero, se intenta el bloqueo y si no tiene éxito, la invocación fallará inmediatamente. Si se pasa como "infinito" (el valor predeterminado) la invocación esperará indefinidamente hasta que se pueda adquirir el bloqueo. Si el bloqueo no se puede tomar en el tiempo especificado, el comando especificado no se ejecutará y la invocación fallará.

Added in version 251.

--print, -p

En lugar de bloquear los dispositivos especificados y ejecutar un comando, simplemente imprime las rutas de los dispositivos que serían bloqueadas, y no ejecuta ningún comando. Este comando es útil para determinar el dispositivo de bloque "completo" en caso de que se especifique un dispositivo de bloque de partición. Los dispositivos se ordenarán por su número mayor de nodo de dispositivo como clave de ordenación primaria y el número menor como clave de ordenación secundaria (es decir, se muestran en el orden en que serían bloqueados). Tenga en cuenta que el número de líneas impresas aquí puede ser menor que el número de modificadores --device= y --backing= especificados en caso de que estos se resuelvan a los mismos dispositivos "completos".

Added in version 251.

DISPOSITIVOS_INICIALIZADOS

Los dispositivos inicializados son aquellos para los cuales al menos una regla de udev ya completó su ejecución – para cualquier acción que no sea "remove" – que estableció una propiedad u otra configuración del dispositivo (y por lo tanto tiene una entrada en la base de datos de dispositivos de udev). Los dispositivos ya no se consideran inicializados si se ve una acción de "remove" para ellos (que elimina su entrada en la base de datos de dispositivos de udev). Tenga en cuenta que los dispositivos que no tienen reglas de udev nunca se consideran inicializados, pero aún pueden ser anunciados a través de la API sd-device (o similar).

EJEMPLO

Ejemplo 1. Formatear un Sistema de Archivos

Tomar un bloqueo en el dispositivo de bloque de respaldo mientras se crea un sistema de archivos, para asegurar que systemd-udevd no investigue ni anuncie la nueva superbloque antes de que esté completamente escrita:

# udevadm lock --device=/dev/sda1 mkfs.ext4 /dev/sda1

Ejemplo 2. Formatear un Sistema de Archivos RAID

Similar, pero tomar bloqueos en múltiples dispositivos a la vez:

# udevadm lock --device=/dev/sda1 --device=/dev/sdb1 mkfs.btrfs /dev/sda1 /dev/sdb1

Ejemplo 3. Copiar un Sistema de Archivos

Tomar un bloqueo en el dispositivo de bloque de respaldo mientras se copia una imagen de sistema de archivos preparada, para asegurar que systemd-udevd no investigue ni anuncie la nueva superbloque antes de que esté completamente escrita:

# udevadm lock -d /dev/sda1 dd if=fs.raw of=/dev/sda1

Ejemplo 4. Predecir el Cambio de Nombre de una Interfaz de Red

Para predecir un nombre de interfaz de red, se puede usar udevadm test:

$ udevadm test /sys/class/net/wlan0 --json=pretty 2>/dev/null | jq .networkInterface.name
"wlp59s0"

Ejemplo 5. Predecir Enlaces Simbólicos de un Nodo de Dispositivo

Para predecir enlaces simbólicos a un nodo de dispositivo, se puede usar udevadm test:

$ udevadm test /dev/nvme0n1p1 --json=pretty 2>/dev/null | jq .node.symlinks
[
  "/dev/disk/by-diskseq/1-part1",
  "/dev/disk/by-id/nvme-WDC_PC_SN720_SDAQNTW-512G-1001_192290802247-part1",
  "/dev/disk/by-id/nvme-WDC_PC_SN720_SDAQNTW-512G-1001_192290802247_1-part1",
  "/dev/disk/by-id/nvme-eui.1922908022470001001b448b44ccb9d6-part1",
  "/dev/disk/by-path/pci-0000:3c:00.0-nvme-1-part/by-partnum/1",
  "/dev/disk/by-path/pci-0000:3c:00.0-nvme-1-part1"
]
$ udevadm test /dev/input/event3 --json=pretty 2>/dev/null | jq .node.symlinks
[
  "/dev/input/by-path/platform-i8042-serio-0-event-kbd"
]

NAME

udevadm — Control the systemd device manager

SYNOPSIS

udevadm ACTION [OPTIONS] [PATTERN]...

DESCRIPTION

The udevadm utility allows you to control and query the state of the systemd device manager (systemd-udevd.service).

It supports various operations for querying device information, monitoring udev events, and triggering device events.

OPTIONS

-h, --help
Print a short help text and exit.
--version, -V
Print the program version and exit.
--quiet, -q
Suppress output. This option can be used with most actions, but it doesn't suppress error messages.
--verbose, -v
Enable verbose output. This option can be used with most actions.
--monitor, -m
Monitor udev events. This action prints events as they are detected.
--cleanup-db
Remove all devices from the udev database that are no longer needed. This is useful to clean up stale entries.
--retry-startup
Retry starting the udev event processing. This can be useful if udev failed to start correctly during system boot.
--trigger
Trigger all udev events. This action sends a signal to systemd-udevd to re-process all devices.
--settle [PATTERN]...
Wait until the udev event queue is empty. If patterns are given, it waits until all events matching the patterns have been processed.
--change-root NEW_ROOT
Change the root directory for subsequent operations. This is useful for chroot environments.
--query [OPTIONS] VARIABLE [PATTERN]...
Query device properties. VARIABLE is the name of the property to query. If no patterns are given, it queries properties of all devices. Supported options include:
--attribute-walk
Walk up the device tree and collect all attributes.
--path PATH
Query device at the specified path.
--subsystem-match SUBSYSTEM
Match devices in the specified subsystem.
--source-file FILE
Read device events from a file.
--info [OPTIONS] [PATTERN]...
Print information about devices. If no patterns are given, it prints information about all devices.
--test
Run systemd-udevd in test mode. This mode simulates device events and allows testing of udev rules without affecting the actual system.
--verify [OPTIONS] [PATTERN]...
Verify udev rules. This action checks the syntax and semantics of udev rules.
--rule [OPTIONS] [PATTERN]...
Print the udev rule that matches the specified device.
--import [OPTIONS] [PATTERN]...
Import device information from a file or stdin. This is useful for programmatically adding or modifying device information.
--export [OPTIONS] [PATTERN]...
Export device information to a file or stdout. This can be used to back up or transfer device configurations.

INITIALIZED DEVICES

When udevadm is called without any action, it defaults to listing all initialized devices.

EXAMPLE

List all devices:

udevadm

Monitor udev events:

udevadm monitor

Query the kernel name of the device at /dev/sda1:

udevadm info --query=kernel --path=/dev/sda1

Trigger all udev events:

udevadm trigger

Wait until the udev event queue is empty:

udevadm settle

Verify udev rules:

udevadm verify --verify-rules
