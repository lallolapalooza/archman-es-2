NOMBRE

urlwatch-cookbook - Temas avanzados y recetas para urlwatch

AÑADIR  URLS  DESDE  LA  LÍNEA  DE  COMANDOS

Añadir rápidamente nuevas URLs a la lista de trabajos desde la línea de comandos:

urlwatch --add url=http://example.org,name=Ejemplo

USAR  DIFERENCIAS  BASADAS  EN  PALABRAS

También puedes especificar una herramienta externa de tipo diff (una herramienta que toma dos nombres de archivo (antiguo, nuevo) como parámetro y devuelve la diferencia de los archivos en su salida estándar), por ejemplo, para usar wdiff(1) para obtener diferencias basadas en palabras en lugar de diferencias basadas en líneas, o pandiff https://github.com/davidar/pandiff para obtener diferencias de markdown:

url: https://example.com/
diff_tool: wdiff

Ten en cuenta que diff_tool especifica una herramienta de línea de comandos externa, por lo que esa herramienta debe instalarse por separado (por ejemplo, apt install wdiff en Debian o brew install wdiff en macOS). La resaltación de sintaxis es compatible con la salida de tipo wdiff, pero potencialmente no con otras herramientas de diff.

IGNORAR  CAMBIOS  DE  ESPACIOS  EN  BLANCO

Si deseas ignorar los cambios en los espacios en blanco para no recibir notificaciones por diferencias triviales, puedes usar diff_tool para esto. Por ejemplo:

diff_tool: "diff --ignore-all-space --unified"

Al usar otra herramienta externa similar a diff, asegúrate de que devuelva el formato de salida unificado para mantener la resaltación de sintaxis.

MOSTRAR  SOLO  LÍNEAS  AÑADIDAS  O  ELIMINADAS

La función diff_filter se puede usar para filtrar el texto de salida del diff con las mismas herramientas (ver Filtros) que se usan para filtrar páginas web.

Para mostrar solo las líneas de diff con líneas añadidas, usa:

url: http://example.com/things-get-added.html
diff_filter:
  - grep: '^[@+]'

Esto solo conservará las líneas de diff que comiencen con @ o +. De manera similar, para conservar solo las líneas eliminadas:

url: http://example.com/things-get-removed.html
diff_filter:
  - grep: '^[@-]'

Es posible un filtrado de diff más sofisticado combinando filtros existentes, escribiendo un nuevo filtro o usando shellpipe para delegar el filtrado/procesamiento de la salida del diff a una herramienta externa.

Lee la siguiente sección si quieres deshabilitar notificaciones vacías.

DESHABILITAR  NOTIFICACIONES  VACÍAS

Como extensión del ejemplo anterior, digamos que solo quieres recibir notificaciones con todas las líneas añadidas, pero no recibir ninguna notificación si se eliminan líneas.

Un diff generalmente se ve así:

--- @       Vie, 04 Mar 2022 19:58:14 +0100
+++ @       Vie, 04 Mar 2022 19:58:22 +0100
@@ -1,3 +1,3 @@
 someline
-someotherlines
+someotherline
 anotherline

Queremos filtrar solo todas las líneas que comiencen con "+", pero debido a las cabeceras, también queremos filtrar las líneas que comiencen con "+++", lo que se puede lograr así:

url: http://example.com/only-added.html
diff_filter:
  - grep: '^[+]'      # Incluir todas las líneas que comiencen con "+"
  - grepi: '^[+]{3}'  # Excluir la línea que comience con "+++"

Esto maneja todas las líneas de diff ahora, pero como urlwatch reporta páginas "cambiadas" incluso cuando diff_filter devuelve una cadena vacía (lo que podría ser útil en algunos casos), debes optar explícitamente por no hacerlo usando urlwatch --edit-config y estableciendo la opción empty-diff a false en la categoría display:

display:
  empty-diff: false

PASAR  LA  SALIDA  DEL  DIFF  A  UN  SCRIPT  PERSONALIZADO

En algunas situaciones, podría ser útil ejecutar un script con el diff como entrada cuando se detectan cambios (por ejemplo, para iniciar una actualización o procesar algo). Esto se puede hacer combinando diff_filter con el filtro shellpipe, que puede ser cualquier script personalizado.

La salida del script personalizado será entonces el resultado del diff tal como lo informa urlwatch, por lo que si genera algún estado, la notificación CHANGED que hace urlwatch contendrá la salida del script personalizado, no el diff original. Esto puede incluso tener un filtro "normal" adjunto para ver solo enlaces (la parte css: a de las definiciones de filtro):

url: http://example.org/downloadlist.html
filter:
  - css: a
diff_filter:
  - shellpipe: /usr/local/bin/process_new_links.sh

COMPARAR  PÁGINAS  WEB  VISUALMENTE

Para comparar el contenido visual de las páginas web, Nicolai ha escrito pyvisualcompare https://github.com/nspo/pyvisualcompare como una interfaz (con GUI) para urlwatch. La herramienta se puede usar para seleccionar una región de una página web. Luego genera una configuración para urlwatch para ejecutar pyvisualcompare y generar un hash para el contenido de la pantalla.

IGNORAR  ERRORES  DE  CONEXIÓN

En algunos casos, podría ser útil ignorar errores de red (temporales) para evitar que se envíen notificaciones. Si bien existe una opción de configuración display.error (que por defecto es true) para controlar la notificación de errores globalmente, para ignorar los errores de red solo para trabajos específicos, puedes usar la clave ignore_connection_errors en el archivo de configuración de la lista de trabajos:

url: https://example.com/
ignore_connection_errors: true

De manera similar, es posible que desees ignorar algunos errores HTTP (temporales) en el lado del servidor:

url: https://example.com/
ignore_http_error_codes: 408, 429, 500, 502, 503, 504

o ignorar todos los errores HTTP si lo deseas:

url: https://example.com/
ignore_http_error_codes: 4xx, 5xx

También puedes ignorar lecturas incompletas:

url: "https://example.com/"
ignore_incomplete_reads: true

SOBRESCRIBIR  LA  CODIFICACIÓN  DEL  CONTENIDO

Para páginas web con cabeceras HTTP mal configuradas o codificaciones raras, puede ser útil especificar explícitamente una codificación de las Codificaciones Estándar de Python https://docs.python.org/3/library/codecs.html#standard-encodings.

url: https://example.com/
encoding: utf-8

CAMBIAR  EL  TIEMPO  DE  ESPERA  PREDETERMINADO

Por defecto, los trabajos de url expiran después de 60 segundos. Si deseas un período de espera diferente, usa la clave timeout para especificarlo en número de segundos, o establécelo a 0 para que nunca expire.

url: https://example.com/
timeout: 300

SUMINISTRAR  DATOS  DE  GALLETAS

Es posible agregar galletas a las solicitudes HTTP para páginas que lo necesiten, la sintaxis YAML para esto es:

url: http://example.com/
cookies:
    Key: ValueForKey
    OtherKey: OtherValue

COMPARANDO  W

COMPARACIÓN CON VARIAS INSTANTÁNEAS RECIENTES

Si una página web cambia frecuentemente entre varios estados estables conocidos, puede ser deseable que los cambios solo se informen si la página web cambia a un estado nuevo y desconocido. Puede usar compared_versions para esto.

url: https://example.com/
compared_versions: 3

En este ejemplo, los cambios solo se informan si la página web se vuelve diferente de los tres estados distintos más recientes. Las diferencias se muestran en relación con la coincidencia más cercana.

RECIBIR UN INFORME CADA VEZ QUE SE EJECUTA URLWATCH

Si está monitorizando páginas que cambian con poca frecuencia, pero aún así desea recibir notificaciones diarias si urlwatch todavía funciona, puede monitorizar la salida del comando date, por ejemplo:

name: "urlwatch watchdog"
command: "date"

Dado que la salida de date cambia cada segundo, este trabajo debería producir un informe cada vez que se ejecute urlwatch.

USAR REDIS COMO UN BACKEND DE CACHÉ

Si desea usar Redis como backend de caché en lugar del archivo SQLite3 predeterminado:

urlwatch --cache=redis://localhost:6379/

No hay ruta de migración desde el formato SQLite3, la caché estará vacía la primera vez que se use Redis.

MONITORIZAR CAMBIOS EN PÁGINAS .ONION (TOR)

Dado que las páginas en la Red Tor https://www.torproject.org no son accesibles a través de DNS público y TCP, debe configurar un cliente Tor como proxy HTTP/HTTPS o usar la herramienta torify(1) del paquete tor (apt install tor en Debian, brew install tor en macOS). La configuración de Tor está fuera del alcance de este documento. En una instalación de Tor correctamente configurada, uno puede simplemente prefijar el comando urlwatch con el envoltorio torify para acceder a las páginas .onion:

torify urlwatch

MONITORIZAR EVENTOS DE PÁGINAS DE FACEBOOK

Si desea que se le notifiquen eventos nuevos en una página pública de Facebook, puede usar el siguiente patrón de trabajo, reemplace PAGE con el nombre de la página (se puede encontrar navegando a la página de eventos en su navegador):

url: http://m.facebook.com/PAGE/pages/permalink/?view_type=tab_events
filter:
  - css:
      selector: div#objects_container
      exclude: 'div.x, #m_more_friends_who_like_this, img'
  - re.sub:
      pattern: '(/events/\d*)[^"]*'
      repl: '\1'
  - html2text: pyhtml2text

CONFIGURAR EL ANCHO DE CONTENIDO PARA HTML2TEXT (MÉTODO LYNX)

Cuando se usa el método lynx en el filtro html2text, utiliza un ancho predeterminado que provocará la inserción de saltos de línea adicionales.

Para establecer el ancho de salida de lynx en 400 caracteres, use esta configuración de filtro:

url: http://example.com/longlines.html
filter:
  - html2text:
      method: lynx
      width: 400

CONFIGURAR CUÁNTO TIEMPO ESPERAN LOS TRABAJOS DEL NAVEGADOR A QUE CARGUEN LAS PÁGINAS

Para los trabajos del navegador, puede configurar cuánto tiempo esperará el navegador sin cabeza antes de que una página se considere cargada utilizando la opción wait_until.

Puede tomar uno de los cuatro valores (consulte la documentación de wait_until https://playwright.dev/python/docs/api/class-page#page-goto-option-wait-until de Playwright):

  • load - considere que la operación ha finalizado cuando se dispara el evento load.
  • domcontentloaded - considere que la operación ha finalizado cuando se dispara el evento DOMContentLoaded.
  • networkidle - desaconsejado considere que la operación ha finalizado cuando no hay conexiones de red durante al menos 500 ms. No utilice este método para pruebas, confíe en las aserciones web para evaluar la preparación en su lugar.
  • commit - considere que la operación ha finalizado cuando se recibe la respuesta de la red y el documento ha comenzado a cargarse.

TRATAR TRABAJOS NUEVOS COMO CAMBIADOS

En algunos casos (por ejemplo, cuando el diff_tool o diff_filter ejecuta algún comando externo como efecto secundario que también debería ejecutarse para el estado inicial de la página), puede establecer treat_new_as_changed en true, lo que hará que el trabajo se informe como NEW (nuevo) en lugar de CHANGED (cambiado) la primera vez que se recupera (y la diferencia también se informará).

url: http://example.com/initialpage.html
treat_new_as_changed: true

Esta opción también cambiará el comportamiento de --test-diff-filter y permitirá probar el filtro de diferencias si solo se ha recuperado una única versión de la página.

MONITORIZAR LA MISMA URL EN MÚLTIPLES TRABAJOS

Debido a que urlwatch utiliza la clave url/navigate (para trabajos URL/Navegador) y/o la clave command (para trabajos Shell) como identificador único, cada URL solo puede aparecer en un único trabajo. Si desea monitorizar la misma URL varias veces, puede añadir #1, #2, ... (o cualquier cosa que las haga únicas) a las URLs, de la siguiente manera:

name: "Buscando Cosa A"
url: http://example.com/#1
filter:
  - grep: "Cosa A"
---
name: "Buscando Cosa B"
url: http://example.com/#2
filter:
  - grep: "Cosa B"

ACTUALIZAR UNA URL Y CONSERVAR EL HISTORIAL PASADO

El historial de trabajos se almacena basándose en el valor del parámetro url, por lo que actualizar la URL de un trabajo en el archivo de configuración urls.yaml creará un nuevo trabajo sin historial. Conserve el historial utilizando --change-location:

urlwatch --change-location http://example.org#old http://example.org#new

El comando también funciona con trabajos de Navegador y Shell, cambiando navigate y command respectivamente.

EJECUTAR UN SUBCONJUNTO DE TRABAJOS

Para ejecutar uno o varios trabajos específicos en lugar de todos los trabajos conocidos, proporcione los números de índice del trabajo al comando urlwatch. Por ejemplo, para ejecutar los trabajos con índice 2, 4 y 7:

urlwatch 2 4 7

ENVIAR DATOS DE FORMULARIO HTML USANDO POST

Para simular el envío de un formulario HTML utilizando el método POST, puede pasar los campos del formulario en el campo data de la descripción del trabajo:

name: "Mi Trabajo POST"
url: http://example.com/foo
data:
  username: "foo"
  password: "bar"
  submit: "Enviar consulta"

Por defecto, la solicitud utilizará el método HTTP POST y el Content-type se establecerá en application/x-www-form-urlencoded.

ENVIAR DATOS ARBITRARIOS USANDO HTTP PUT

Es posible personalizar el método HTTP y la cabecera Content-type, lo que le permite enviar solicitudes arbitrarias al servidor:

name: "Mi Solicitud PUT"
url: http://example.com/item/new
method: PUT
headers:
  Content-type: application/json
data: '{"foo": true}'

SOPORTE UTF-8 EN WINDOWS

En Windows, la codificación de archivos predeterminada puede depender de la configuración regional y no funcionar correctamente si los archivos se guardan utilizando la codificación UTF-8 (recomendada).

Si tiene problemas para cargar archivos codificados en UTF-8 en Windows, puede experimentar un problema como el siguiente cuando urlwatch analiza sus archivos de configuración:

UnicodeDecodeError: 'charmap' codec can't decode byte 0x9d in position 214: character maps to <undefined>

Para solucionar este problema, Python 3.7 y versiones posteriores tienen un nuevo Modo UTF-8 https://peps.python.org/pep-0540/ que se puede habilitar estableciendo la variable de entorno PYTHONUTF8 en 1:

set PYTHONUTF8=1
urlwatch

También puede agregar esta variable de entorno a su entorno de usuario o entorno del sistema para aplicar el Modo UTF-8 a todos los programas de Python en su máquina.
