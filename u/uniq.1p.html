UNIQ(1P) Manual del programador POSIX UNIQ(1P)

PROLOGO

Esta página del manual es parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

uniq — informar o filtrar líneas repetidas en un archivo

SINTAXIS

uniq [-c|-d|-u] [-f campos] [-s car] [archivo_entrada [archivo_salida]]

DESCRIPCION

La utilidad uniq leerá un archivo de entrada comparando líneas adyacentes, y escribirá una copia de cada línea de entrada en la salida. Las copias segundas y subsiguientes de líneas de entrada repetidas adyacentes no se escribirán. El salto de línea final (<newline>) de cada línea en la entrada se ignorará al hacer comparaciones.

Las líneas repetidas en la entrada no se detectarán si no son adyacentes.

OPCIONES

La utilidad uniq se ajustará a las Definiciones Base del volumen POSIX.1‐2017, Sección 12.2, Pautas de sintaxis de utilidad, excepto que '+' puede ser reconocido como delimitador de opción además de '-'.

Se admitirán las siguientes opciones:

-c
Anteponga a cada línea de salida un recuento del número de veces que la línea apareció en la entrada.
-d
Suprima la escritura de líneas que no se repiten en la entrada.
-f campos
Ignore los primeros campos campos en cada línea de entrada al hacer comparaciones, donde campos es un entero decimal positivo. Un campo es la cadena maximal que coincide con la expresión regular básica:
[[:blank:]]*[^[:blank:]]*

Si el argumento de opción campos especifica más campos de los que aparecen en una línea de entrada, se utilizará una cadena nula para la comparación.

-s car
Ignore los primeros car caracteres al hacer comparaciones, donde car será un entero decimal positivo. Si se especifica en conjunción con la opción -f, se ignorarán los primeros car caracteres después de los primeros campos campos. Si el argumento de opción car especifica más caracteres de los que quedan en una línea de entrada, se utilizará una cadena nula para la comparación.
-u
Suprima la escritura de líneas que se repiten en la entrada.

OPERANDOS

Se admitirán los siguientes operandos:

archivo_entrada
Una ruta del archivo de entrada. Si no se especifica el operando archivo_entrada, o si el archivo_entrada es '-', se utilizará la entrada estándar.
archivo_salida
Una ruta del archivo de salida. Si no se especifica el operando archivo_salida, se utilizará la salida estándar. Los resultados no están definidos si el archivo nombrado por archivo_salida es el mismo archivo que el nombrado por archivo_entrada.

ENTRADA ESTÁNDAR

La entrada estándar se utilizará solo si no se especifica ningún operando archivo_entrada o si archivo_entrada es '-'. Consulte la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

El archivo de entrada será un archivo de texto.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de uniq:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para ver la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de la configuración regional).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a multibyte en argumentos y archivos de entrada) y qué caracteres constituyen un <espacio en blanco> (<blank>) en la configuración regional actual.
LC_MENSAJES

Determina la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MENSAJES.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

La salida estándar se utilizará si no se especifica ningún operando archivo_salida, y se utilizará si el operando archivo_salida es '-' y la implementación trata el '-' como salida estándar. De lo contrario, la salida estándar no se utilizará. Consulte la sección ARCHIVOS DE SALIDA.

ERROR ESTÁNDAR

El error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Si se especifica la opción -c, el archivo de salida estará vacío o cada línea tendrá el formato:

"%d %s", <número de duplicados>, <línea>

de lo contrario, el archivo de salida estará vacío o cada línea tendrá el formato:

"%s", <línea>

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
La utilidad se ejecutó correctamente.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Predeterminado.

USO DE LA APLICACIÓN

Si la secuencia de ordenación de la configuración regional actual tiene un orden total de todos los caracteres, la utilidad sort puede usarse para hacer que las líneas repetidas estén adyacentes en el archivo de entrada. Si la secuencia de ordenación no tiene un orden total de todos los caracteres, la utilidad sort debería hacerlo de todos modos, pero puede que no. Para asegurarse de que todas las líneas duplicadas se eliminen y que la salida se ordene según la secuencia de ordenación de la configuración regional actual, las aplicaciones deben usar:

LC_ALL=C sort -u | sort

en lugar de:

sort | uniq

Para eliminar líneas duplicadas basándose en si ordenan igualmente en lugar de si son idénticas, las aplicaciones deben usar:

sort -u

en lugar de:

sort | uniq

Al usar uniq para procesar rutas, se recomienda que LC_ALL, o al menos LC_CTYPE y LC_COLLATE, se establezcan en POSIX o C en el entorno, ya que las rutas pueden contener secuencias de bytes que no forman caracteres válidos

EJEMPLOS

Los siguientes datos del archivo de entrada (pero alineados a la izquierda) se utilizaron para una serie de pruebas en uniq:

#01 foo0 bar0 foo1 bar1
#02 bar0 foo1 bar1 foo1
#03 foo0 bar0 foo1 bar1
#04
#05 foo0 bar0 foo1 bar1
#06 foo0 bar0 foo1 bar1
#07 bar0 foo1 bar1 foo0

A continuación se presenta una serie de invocaciones de prueba de la utilidad uniq que utilizan una mezcla de opciones de uniq contra los datos del archivo de entrada. Estas pruebas verifican el significado de adyacente. La utilidad uniq ve los datos de entrada como una secuencia de cadenas delimitadas por '\n'. En consecuencia, para el miembro campos de la secuencia, uniq interpreta líneas únicas o repetidas adyacentes estrictamente en relación con el miembro campos+1.

1.
Este primer ejemplo prueba la opción de conteo de líneas, comparando cada línea de los datos del archivo de entrada a partir del segundo campo:
uniq -c -f 1 uniq_0I.t
    1 #01 foo0 bar0 foo1 bar1
    1 #02 bar0 foo1 bar1 foo1
    1 #03 foo0 bar0 foo1 bar1
    1 #04
    2 #05 foo0 bar0 foo1 bar1
    1 #07 bar0 foo1 bar1 foo0

El número '2', que precede a la quinta línea de salida, significa que la utilidad uniq detectó un par de líneas repetidas. Dados los datos de entrada, esto solo puede ser cierto cuando uniq se ejecuta utilizando la opción -f 1 (que hará que uniq ignore el primer campo de cada línea de entrada).

2.
El segundo ejemplo prueba la opción para suprimir líneas únicas, comparando cada línea de los datos del archivo de entrada a partir del segundo campo:
uniq -d -f 1 uniq_0I.t
#05 foo0 bar0 foo1 bar1
3.
Esta prueba suprime líneas repetidas, comparando cada línea de los datos del archivo de entrada a partir del segundo campo:
uniq -u -f 1 uniq_0I.t
#01 foo0 bar0 foo1 bar1
#02 bar0 foo1 bar1 foo1
#03 foo0 bar0 foo1 bar1
#04
#07 bar0 foo1 bar1 foo0
4.
Esto suprime líneas únicas, comparando cada línea de los datos del archivo de entrada a partir del tercer carácter:
uniq -d -s 2 uniq_0I.t

En el último ejemplo, la utilidad uniq no encontró ninguna entrada que coincidiera con los criterios anteriores.

RACIÓNALE

Algunas implementaciones históricas han limitado las líneas a 1080 bytes de longitud, lo que no cumple con el límite implícito {LINE_MAX}.

Las versiones anteriores de este estándar permitían las opciones -número y +número. Estas opciones ya no se especifican en POSIX.1-2008 pero pueden estar presentes en algunas implementaciones.
