NOMBRE

unbound-anchor - Utilidad de anclaje de Unbound 1.24.2.

SINOPSIS

unbound-anchor [opciones]

DESCRIPCIÓN

unbound-anchor realiza la configuración o actualización del anclaje de confianza raíz para la validación DNSSEC. El programa obtiene el anclaje de confianza con el método de RFC 7958 cuando la actualización normal de RFC 5011 falla en ponerlo al día. Puede ejecutarse (como root) desde la línea de comandos, o ejecutarse como parte de los scripts de inicio. Antes de iniciar el servidor DNS de unbound(8).

Uso sugerido:

# en los scripts de init.
# proporcionar o actualizar el anclaje raíz (si es necesario)
unbound-anchor -a "/etc/trusted-key.key"
# Tenga en cuenta que el uso de este anclaje raíz es bajo su propio riesgo
# y bajo los términos de nuestra LICENCIA (ver fuente).
#
# iniciar el resolvedor de validación
# el unbound.conf contiene:
# auto-trust-anchor-file: "/etc/trusted-key.key"
unbound -c unbound.conf

Esta herramienta proporciona contenidos predeterminados incorporados para los archivos de anclaje raíz y certificado de actualización raíz.

Prueba si el archivo de anclaje raíz funciona y, si no es así, y si es posible una actualización, intenta actualizar el anclaje raíz utilizando el certificado de actualización raíz. Realiza una búsqueda https de root-anchors.xml y comprueba los resultados (RFC 7958); si todas las comprobaciones son exitosas, actualiza el archivo de anclaje raíz. De lo contrario, el archivo de anclaje raíz no se modifica. Realiza el seguimiento de RFC 5011 si la información DNSSEC disponible a través de DNS lo hace posible.

No realiza una actualización si el certificado está caducado, si la red está caída o si ocurren otros errores.

Las opciones disponibles son:

-a <archivo>
El archivo de clave de anclaje raíz, que se lee y se escribe. Por defecto es /etc/trusted-key.key. Si el archivo no existe o está vacío, se escribe una clave raíz incorporada en él.
-c <archivo>
El archivo de certificado de actualización raíz, que se lee. Por defecto es /etc/unbound/icannbundle.pem. Si el archivo no existe o está vacío, se utiliza un certificado incorporado.
-l
Lista la clave raíz incorporada y el certificado de actualización raíz incorporado en la salida estándar.
-u <nombre>
El nombre del servidor, se conecta a https://name. Especifique sin el prefijo https://. El valor predeterminado es "data.iana.org". Se conecta al puerto especificado con -P. Puede pasar una dirección IPv4 o IPv6 (sin corchetes) si lo desea.
-S
No usar SNI para la conexión HTTPS. Por defecto es usar SNI.
-b <dirección>
La dirección de origen a la que enlazarse para la resolución de dominios y el contacto con el servidor en https. Puede ser una dirección IPv4 o IPv6 (sin corchetes).
-x <ruta>
La ruta al archivo root-anchors.xml en el servidor. (forma URL con -u). El valor predeterminado es /root-anchors/root-anchors.xml.
-s <ruta>
La ruta al archivo root-anchors.p7s en el servidor. (forma URL con -u). El valor predeterminado es /root-anchors/root-anchors.p7s. Este archivo debe ser una firma PKCS7 sobre el archivo xml, utilizando el archivo pem (-c) como anclaje de confianza.
-n <nombre>
La dirección de correo electrónico para el Asunto del certificado del firmante del archivo p7s. Solo se permiten firmas de este nombre. El valor predeterminado es dnssec@iana.org. Si pasa "", la dirección de correo electrónico no se comprobará.
-4
Usar IPv4 para la resolución de dominios y el contacto con el servidor en https. Por defecto es usar IPv4 e IPv6 cuando sea apropiado.
-6
Usar IPv6 para la resolución de dominios y el contacto con el servidor en https. Por defecto es usar IPv4 e IPv6 cuando sea apropiado.
-f <resolv.conf>
Usar el archivo resolv.conf proporcionado. No está habilitado por defecto, pero podría intentar pasar /etc/resolv.conf en algunos sistemas. Contiene las direcciones IP de los servidores de nombres recursivos a utilizar. Sin embargo, dado que esta herramienta podría utilizarse para iniciar ese mismo servidor recursivo, no sería útil (ya que ese servidor aún no está en funcionamiento, ya que lo estamos iniciando). Podría ser útil en una situación en la que se sepa que una caché intermedia está desplegada (y en funcionamiento) y en situaciones de portal cautivo.
-r <root.hints>
Usar el archivo root.hints proporcionado (misma sintaxis que el archivo de pistas raíz de BIND y Unbound) para iniciar la resolución de dominios. Por defecto se utiliza una lista de pistas raíz incorporadas. unbound-anchor va a la red por sí mismo para estas raíces, para resolver el servidor (opción -u) y para comprobar los registros DNSKEY raíz. Lo hace porque la herramienta, cuando se utiliza para iniciar el resolvedor recursivo, no puede utilizar ese resolvedor recursivo porque está iniciando ese servidor.
-R
Permitir retroceso desde el archivo -f <resolv.conf> a la consulta directa de servidores raíz. Le permite preferir resolvedores locales, pero retroceder automáticamente a la consulta directa de raíces si no responden o no admiten DNSSEC.
-v
Más verboso. Una vez imprime mensajes informativos, varias veces pueden habilitar grandes cantidades de depuración (como certificados completos o volcados de bytes de archivos descargados). Por defecto, no imprime casi nada. Tampoco imprime nada en caso de error por defecto; en ese caso, el archivo de anclaje raíz original se deja intacto, para que un servidor recursivo pueda iniciarse justo después de él.
-C <unbound.conf>
Opción de depuración para leer <unbound.conf> en el proceso del resolvedor utilizado.
-P <puerto>
Establecer el número de puerto a utilizar para la conexión https. El valor predeterminado es 443.
-F
Opción de depuración para forzar la actualización del anclaje raíz descargando el archivo xml y verificándolo con el certificado. Por defecto, primero intenta actualizar contactando con el DNS, lo que utiliza mucha menos banda ancha, es mucho más rápido (200 mseg en lugar de 2 seg) y es mejor para la infraestructura desplegada. Con esta opción, todavía intenta hacerlo (y puede informarle detalladamente), pero luego ignora el resultado y continúa utilizando el método de respaldo xml.
-h
Mostrar la versión y la ayuda de las opciones de línea de comandos.

CÓDIGO DE SALIDA

Esta herramienta sale con el valor 1 si el anclaje raíz se actualizó utilizando el certificado o si se utilizó el anclaje raíz incorporado. Sale con el código 0 si no fue necesaria ninguna actualización, si la actualización fue posible con el seguimiento RFC 5011, o si ocurrió algún error.

Puede comprobar el valor de salida de esta manera:

unbound-anchor -a "root.key" || logger "Por favor, compruebe root.key"

O algo más adecuado para su entorno operativo.

unbound-anchor(8)

NAME

unbound-anchor - provides the root trust anchor for DNSSEC validation

SYNOPSIS

unbound-anchor [-c anchor_file] [-l] [-v]

DESCRIPTION

The unbound-anchor program obtains and verifies the root trust anchor for DNSSEC validation. It is used to set up the initial trust anchor, and can be run periodically to update the anchor.

The DNSSEC root anchor is a public key that is used to start the chain of trust for validating DNSSEC signed responses. Without a correct root anchor, DNSSEC validation cannot function.

If the anchor is not found, it is downloaded from the IANA web server.

It checks the downloaded anchor against the built-in trusted root certificate. If it matches, the anchor is saved to disk. If it does not match, it reports an error. The anchor can be fetched from https://data.iana.org/root-anchors/root-anchors.xml, and signed by https://data.iana.org/root-anchors/root-anchors.p7s.

The built-in root certificate is icannbundle.pem.

OPTIONS

-c anchor_file
Use the specified file as the anchor file. Defaults to /etc/trusted-key.key.
-l
Print the configured root keys and certificates to standard output. This is useful for debugging and for checking the built-in keys.
-v
Print verbose output, including progress messages and diagnostic information.

EXIT CODE

The exit code is 0 on success, and a non-zero value on failure.

TRUST

The certificate included in this tool are provided for convenience and under the terms of our license (see the LICENSE file in the source distribution or https://github.com/NLnetLabs/unbound/blob/master/LICENSE and might be stale or not suitable to your purpose.

By running unbound-anchor -l the keys and certificate that are configured in the code are printed for your convenience.

The built-in configuration can be overridden by providing a root-cert file and a rootkey file.

FILES

/etc/trusted-key.key
The root anchor file, updated with 5011 tracking, and read and written to. The file is created if it does not exist.
/etc/unbound/icannbundle.pem
The trusted self-signed certificate that is used to verify the downloaded DNSSEC root trust anchor. You can update it by fetching it from https://data.iana.org/root-anchors/icannbundle.pem (and validate it). If the file does not exist or is empty, a builtin version is used.
https://data.iana.org/root-anchors/root-anchors.xml
Source for the root key information.
https://data.iana.org/root-anchors/root-anchors.p7s
Signature on the root key information.
