DESCRIPCIÓN

La biblioteca DNS, udns, implementa funcionalidad de resolución DNS de tipo stub segura para hilos, que puede usarse tanto de forma tradicional y síncrona como asíncrona, con el bucle de eventos proporcionado por la aplicación.

Aunque DNS funciona tanto con TCP como con UDP, realizando primero una consulta UDP y, si el resultado no cabe en el búfer UDP (512 bytes como máximo para el protocolo DNS original), repitiendo la consulta sobre TCP, la biblioteca solo usa UDP, pero utiliza extensiones EDNS0 (RFC2671) que permiten búferes UDP más grandes.

La biblioteca utiliza un único socket UDP para realizar todas las operaciones, incluso cuando se consulta a múltiples servidores de nombres. De esta manera, es muy sencillo utilizar la biblioteca en aplicaciones con bucle de eventos asíncrono: una aplicación solo debe añadir un único socket al conjunto de descriptores de archivo que supervisa para E/S.

La biblioteca utiliza dos objetos principales, el *contexto del resolutor* de tipo struct dns_ctx, y la *estructura de consulta* de tipo struct dns_query, ambos opacos para una aplicación. El contexto del resolutor contiene información global sobre el resolutor, como la lista de servidores de nombres a utilizar, la lista de solicitudes activas y similares. Los objetos de consulta contienen información sobre una única consulta DNS en progreso y son asignados/procesados/liberados por la biblioteca. Un puntero a la estructura de consulta puede tratarse como un identificador de una consulta en progreso y puede utilizarse para cancelar la consulta asíncrona o esperar a que se complete.

La interfaz asíncrona funciona de la siguiente manera. Una aplicación inicializa el contexto del resolutor, envía cualquier número de consultas para él utilizando una de las rutinas dns_submit_XXX() proporcionadas (cada una devuelve el identificador de la consulta como puntero a la estructura de consulta), espera entrada en el socket UDP utilizado por la biblioteca y cede cierto control a la biblioteca llamando a las rutinas dns_ioevent() y dns_timeouts() cuando sea apropiado. La biblioteca realiza todo el procesamiento necesario y ejecuta la rutina de devolución de llamada proporcionada por la aplicación cuando una consulta se completa (ya sea con éxito o no), proporcionándole el resultado si lo hay, un puntero al contexto del resolutor (desde el cual se puede obtener el estado de finalización) y el puntero de datos proporcionado por una aplicación cuando se envió la consulta. Al enviar una consulta, una aplicación solicita cómo manejar la respuesta: ya sea para devolver el paquete de respuesta DNS sin procesar para su propio procesamiento de bajo nivel, o puede proporcionar la dirección de una *rutina de análisis* de tipo dns_parse_fn para realizar la conversión del formato en línea a una estructura de datos fácil de usar (la biblioteca proporciona rutinas de análisis para varios tipos de registros de recursos comúnmente utilizados, así como una interfaz de alto nivel segura para tipos que solicita el análisis automáticamente). La supervisión de E/S y el manejo de tiempos de espera pueden ser basados en select() o poll() tradicionales, o se puede utilizar cualquier técnica basada en devolución de llamadas.

Además, la biblioteca proporciona una interfaz síncrona tradicional, que puede mezclarse con llamadas asíncronas (durante el procesamiento de consultas síncronas, otras consultas asíncronas para el mismo contexto de resolutor continuaron procesándose como de costumbre). Una aplicación utiliza una de las numerosas rutinas dns_resolve_XXX() proporcionadas por la biblioteca para realizar una consulta. Al igual que con la interfaz asíncrona, una aplicación puede solicitar que se devuelva el paquete DNS sin procesar o una estructura de datos específica del tipo proporcionando la rutina de análisis para manejar la respuesta. Cada rutina de la serie dns_resolve_XXX() devuelve un puntero al resultado o NULL en caso de cualquier error. El estado de finalización de la consulta (o la longitud del paquete DNS sin procesar) está disponible en el contexto del resolutor usando la rutina dns_status(), de la misma manera que para la interfaz asíncrona.

Internamente, la biblioteca utiliza el formato en línea de los nombres de dominio, al que se hace referencia como formato *DN* en esta página del manual. Se trata de una serie de *etiquetas* de dominio con un byte de longitud precedente, terminadas por una etiqueta de longitud cero que es parte integral del formato DN. Hay varias rutinas proporcionadas para convertir de la cadena asciiz tradicional a DN y viceversa. La interfaz de consulta de alto nivel específica de tipo oculta el formato DN a la aplicación.

DEFINICIONES COMUNES

Cada Registro de Recursos (RR) de DNS tiene un *tipo* y una *clase*. La biblioteca define varias constantes enteras, DNS_C_XXX y DNS_T_XXX, para usarlas como nombres simbólicos para las clases y tipos de RR, como DNS_C_IN para la clase Internet, DNS_T_A para el tipo de registro de dirección IPv4 y así sucesivamente. Consulte el archivo de cabecera udns.h para obtener una lista completa de todas estas constantes.

Las siguientes constantes están definidas en el archivo de cabecera udns.h:

DNS_MAXDN (255 bytes)
Longitud máxima del nombre de dominio en formato interno (en línea) DN.
DNS_MAXLABEL (63 bytes)
Longitud máxima de una sola etiqueta en formato DN.
DNS_MAXNAME (1024 bytes)
Longitud máxima del formato asciiz de un nombre de dominio.
DNS_HSIZE (12 bytes)
Tamaño de la cabecera en el paquete DNS.
DNS_PORT (53)
Puerto predeterminado a utilizar al contactar a un servidor DNS.
DNS_MAXSERV (6 servidores)
Número máximo de servidores DNS a utilizar.
DNS_MAXPACKET (512 bytes)
Longitud máxima del paquete UDP DNS según lo especificado por el protocolo DNS original
DNS_EDNS0PACKET (4096 bytes)
Longitud predeterminada del paquete UDP DNS (con extensiones EDNS0) que utiliza la biblioteca. Tenga en cuenta que los servidores de nombres recursivos suelen residir cerca del cliente que les pide que resuelvan nombres, por ejemplo, en el mismo segmento de red o incluso en el mismo host, por lo que la fragmentación de paquetes UDP no es un problema en la mayoría de los casos. Tenga en cuenta también que el tamaño de los paquetes reales será tantos bytes como requiera el tamaño de la respuesta real, que es menor que este valor en casi todos los casos.

Además, se definen varias constantes para simplificar el trabajo con paquetes DNS sin procesar, como los códigos de respuesta DNS (DNS_R_XXX), el diseño de la cabecera DNS (DNS_H_XXX) y otros. Nuevamente, consulte udns.h para obtener la lista completa. Los códigos de error de la biblioteca (DNS_E_XXX) se describen más adelante en esta página del manual.

CONTEXTO DEL RESOLUTOR

El contexto del resolutor, de tipo struct dns_ctx, es un objeto opaco para la aplicación. Varias rutinas proporcionadas por la biblioteca para inicializar, copiar y liberar contextos de resolutor. La mayoría de las otras rutinas de alto nivel de esta biblioteca esperan un puntero al contexto del resolutor, ctx, como primer argumento. Hay un contexto de resolutor predeterminado disponible, llamado dns_defctx. Cuando el puntero de contexto ctx pasado a una rutina es NULL, se utiliza dns_defctx. Varios contextos de resolutor pueden estar activos al mismo tiempo, por ejemplo, cuando una aplicación es multihilo y cada hilo utiliza el resolutor.

Para utilizar la biblioteca, una aplicación debe inicializar y abrir uno o más objetos de contexto de resolutor. Estas son dos acciones separadas, realizadas por dns_init() (o dns_reset()), y dns_open(). Entre ambas llamadas, una aplicación es libre de realizar una inicialización adicional, como establecer servidores de nombres personalizados, opciones o listas de búsqueda de dominios. Opcionalmente, en caso de que no se requiera inicialización personalizada adicional, dns_init() puede abrir el contexto si el argumento do_open (ver más abajo) es distinto de cero.

Al inicializar el contexto del resolutor, la biblioteca utiliza información del archivo del sistema /etc/resolv.conf (ver resolv.conf(5)), consulta las variables de entorno $LOCALDOMAIN, $NSCACHEIP, $NAMESERVERS y $RES_OPTIONS, y el nombre de host local para obtener la lista de servidores de nombres locales, la lista de búsqueda de nombres de dominio y varias opciones del resolutor.

CONTEXT MANAGEMENT

The resolver context dns_ctx structure holds all the information needed for performing DNS queries for a given client. You can use the default context dns_defctx, or allocate your own contexts using dns_new().

void dns_reset(ctx)
int dns_init(ctx, int do_open)
dns_reset() reinicia un contexto de resolución dado a valores predeterminados, preparándolo para ser abierto por dns_open(). Está bien llamar a esta rutina contra un contexto abierto y activo; todas las consultas activas se descartarán, los sockets se cerrarán, etc. Esta rutina no inicializa ningún parámetro de los archivos de configuración del sistema; use dns_init() para eso. No hay retorno de error; la operación siempre tiene éxito. dns_init() hace todo lo que hace dns_reset(), además de inicializar varios parámetros del contexto de acuerdo con la configuración del sistema y las variables de entorno del proceso. Si do_open no es cero, dns_init() llama a dns_open(), de modo que toda la inicialización de la biblioteca se realiza en un solo paso.
struct dns_ctx *dns_new(struct dns_ctx *copy)
void dns_free(ctx)
dns_new() asigna un nuevo contexto de resolución y copia todos los parámetros de un contexto de resolución dado copy, o el contexto predeterminado si copy es NULL, y devuelve un puntero al contexto recién asignado. El contexto que se copia debe estar inicializado. dns_new() puede fallar si no hay memoria disponible para hacer una copia de copy, en cuyo caso la rutina devolverá un puntero NULL. dns_free() se utiliza para cerrar el socket asociado y liberar los recursos del contexto de resolución y cancelar (abandonar) todas las consultas activas asociadas a él. Es un error liberar dns_defctx; solo los contextos asignados dinámicamente devueltos por dns_new() se pueden liberar con dns_free().

void dns_ioevent(ctx, time_t now)

En caso de que no haya solicitudes pendientes, este tiempo es -1. La rutina no solicitará un tiempo mayor que maxwait segundos si es mayor o igual a cero. Si now es 0, la rutina obtendrá la hora actual por sí misma; cuando no es 0, debe contener la hora actual devuelta por time().

void dns_set_tmcbck(ctx, dns_utm_fn *utmfn, void *data)
Una aplicación puede utilizar un mecanismo de multiplexación de E/S basado en retrollamadas personalizado. Por lo general, dicho mecanismo tiene el concepto de un temporizador y la capacidad de registrar un evento de temporizador en forma de una rutina de retrollamada que se ejecutará después de una cierta cantidad de tiempo. Para utilizar dicho mecanismo de eventos, udns proporciona la capacidad de registrar y anular el registro de eventos de temporizador necesarios para el procesamiento interno utilizando cualquier mecanismo de eventos que utilice una aplicación. Para que esto funcione, es posible asociar un puntero a una rutina que realizará el trabajo necesario para (des)registrar eventos de temporizador con un contexto de resolución dado, y udns llamará a esa rutina en los momentos apropiados. El prototipo de dicha rutina se muestra en el typedef dns_utm_fn anterior. Libudns asocia un único temporizador con el contexto de resolución. La rutina utmfn proporcionada por el usuario será llamada por la biblioteca con los siguientes argumentos:
ctx == NULL
eliminar el temporizador del usuario, al liberar el contexto o cuando una aplicación cambia la rutina de solicitud de temporizador del usuario usando dns_set_tmcbck();
ctx != NULL, timeout < 0
no activar más el temporizador, cuando no hay solicitudes activas;
ctx != NULL, timeout == 0
activar el temporizador en la próxima posibilidad, pero no inmediatamente;
ctx != NULL, timeout > 0
activar el temporizador después de timeout segundos a partir de ahora.

El argumento data pasado a la rutina será el mismo que se pasó a dns_set_tmcbck().

Cuando expira un temporizador, una aplicación debe llamar a la rutina dns_timeouts() (ver más abajo). También se proporciona el uso de temporizadores no de retrollamada.

INTERFAZ DE CONSULTA

Hay dos formas de realizar consultas DNS: la forma síncrona tradicional, donde udns realiza todo el procesamiento necesario y devuelve el control a la aplicación solo cuando la consulta se completa, y la forma asíncrona, donde una aplicación envía una o más consultas a la biblioteca utilizando un contexto de resolución dado y espera la finalización monitoreando el descriptor de archivo utilizado por la biblioteca y llamando a las rutinas de la biblioteca para procesar la entrada en ese descriptor de archivo. El modo asíncrono funciona con rutinas de retrollamada: una aplicación proporciona la dirección de una rutina para ejecutar cuando se completa la consulta y un puntero de datos, que se pasa a la rutina de retrollamada.

Las consultas se envían a la biblioteca en forma de struct dns_query. Para realizar una consulta asíncrona, una aplicación llama a una de las rutinas dns_submit_XXX() y proporciona la información necesaria para una retrollamada, junto con todos los parámetros de la consulta. Cuando la consulta se completa, la biblioteca llamará a la rutina de retrollamada proporcionada por la aplicación, dándole el contexto de resolución (que contiene el estado de finalización de la consulta), el resultado asignado dinámicamente (que será un paquete DNS crudo o, si la aplicación solicitó el análisis del resultado al especificar una rutina de análisis distinta de NULL, una estructura específica del tipo lista para usar) y un puntero de datos proporcionado por una aplicación cuando envió la consulta. Es responsabilidad de la aplicación liberar la memoria del resultado.

Una rutina de retrollamada de consulta genérica se ve así:

typedef void
dns_query_fn(ctx, void *result, void *data)
La interfaz de consulta específica del tipo espera una forma similar de rutina de retrollamada con la única diferencia en el tipo de argumento result, que será un puntero a una estructura de datos específica (respuesta decodificada) en lugar de este puntero void a los datos del paquete DNS crudo.

La rutina de análisis de resultados se ve así:

typedef int
dns_parse_fn(const unsigned char *qdn,
      const unsigned char *pkt,
      const unsigned char *cur,
      const unsigned char *end,
      void **resultp);
Cuando es llamada por la biblioteca, los argumentos son los siguientes: pkt apunta al inicio del paquete recibido; end apunta más allá del final del paquete recibido; cur apunta más allá del DN de la consulta en la sección de consulta del paquete; qdn apunta al DN de la consulta original. La rutina debe asignar un único búfer para contener el resultado, analizar la respuesta y rellenar el búfer, y devolver el búfer usando el argumento resultp. Devuelve 0 en caso de éxito, o un código de error de udns (constantes DNS_E_XXX) en caso de error. Tenga en cuenta que cuando la biblioteca llama a la rutina de análisis, el paquete ya ha sido verificado para ser una respuesta a la consulta original, al hacer coincidir el DN de la consulta, la clase de consulta y el tipo de consulta.

La interfaz de consulta específica del tipo proporciona rutinas de análisis necesarias automáticamente.

La biblioteca proporciona dos series de rutinas que utilizan una interfaz similar: una para consultas asíncronas y otra para consultas síncronas. Hay dos rutinas generales de bajo nivel en cada serie para enviar (interfaz asíncrona) y resolver (interfaz síncrona) consultas, así como varias rutinas específicas del tipo con interfaces más fáciles de usar. Para enviar una consulta asíncrona, use una de las rutinas dns_submit_XXX(), cada una de las cuales acepta parámetros de consulta, punteros a la rutina de devolución de llamada y a los datos de devolución de llamada, y una sugerencia de hora actual opcional. Tenga en cuenta que las rutinas específicas del tipo dns_submit_XXX() esperan también un tipo específico de rutina de devolución de llamada, que acepta la respuesta como un puntero a la estructura correspondiente, no como un puntero void). Cada rutina dns_submit_XXX() devuelve un puntero a la estructura de consulta interna de tipo struct dns_query, que se utiliza como identificador de la consulta dada.

Para resolver una consulta de forma síncrona, utilice una de las rutinas dns_resolve_XXX(), que acepta los mismos parámetros de consulta (pero no los punteros de devolución de llamada) que la rutina dns_submit_XXX() correspondiente, y devuelve el resultado de la consulta, que es el mismo que se pasa a la rutina de devolución de llamada en el caso de la interfaz asíncrona.

En cualquier caso, la memoria del resultado (si la consulta se completó con éxito) se asigna dinámicamente y debe ser liberada por la aplicación. Si la consulta falló por cualquier motivo, el resultado será NULL, y el estado de error estará disponible en la rutina dns_status(ctx) como se muestra arriba.

Las dos rutinas solo difieren en el tercer argumento, que es el nombre de dominio en formato DN (dn) o una cadena asciiz (name). void *dns_resolve(ctx, struct dns_query *q)
espera a que la consulta dada q, devuelta por una de las rutinas dns_submit_XXX(), se complete y devuelve el resultado. La rutina de devolución de llamada no se llamará para esta consulta. Después de la finalización, el identificador de consulta q no es válido. Tanto dns_resolve_dn() como dns_resolve_p() son solo envoltorios alrededor de las rutinas de envío correspondientes y esta rutina dns_resolve().
void dns_cancel(ctx, struct dns_query *q)
cancela una consulta activa q, sin llamar a una rutina de devolución de llamada. Después de la finalización, el identificador de consulta q no es válido.

CONSULTAS ESPECÍFICAS DE TIPO

Además de la interfaz de consulta genérica de bajo nivel, la biblioteca proporciona un conjunto de rutinas para realizar consultas específicas de manera segura en cuanto al tipo, así como analizadores para varios tipos de registros de recursos bien conocidos. La biblioteca implementa una interfaz de alto nivel para registros A, AAAA, PTR, MX y TXT y funcionalidades DNSBL y RHSBL. INTERFAZ DE BAJO NIVEL

Nombres de Dominio (DNs)

Un DN es una serie de etiquetas de nombres de dominio, cada una comienza con un byte de longitud, seguida de una etiqueta vacía (etiqueta de longitud cero). Las siguientes rutinas para trabajar con DNs se proporcionan.

unsigned dns_dnlen(const unsigned char *dn)
devuelve la longitud del nombre de dominio dn, incluyendo la etiqueta de terminación.
unsigned dns_dnlabels(const unsigned char *dn)
devuelve el número de etiquetas distintas de cero en el nombre de dominio dn.
unsigned dns_dnequal(dn1, dn2)
  const unsigned char *dn1, *dn2;
prueba si los dos nombres de dominio, dn1 y dn2, son iguales (sin distinguir mayúsculas y minúsculas). Devuelve la longitud del nombre de dominio si son iguales o 0 si no lo son.
unsigned dns_dntodn(sdn, ddn, dnsiz)
  const unsigned char *sdn;
  unsigned char *ddn;
  unsigned dnsiz;
copia el nombre de dominio de origen sdn al buffer de destino ddn de tamaño dnsiz. Devuelve la longitud del nombre de dominio o 0 si ddn es demasiado pequeño.
int dns_ptodn(name, namelen, dn, dnsiz, isabs)
int dns_sptodn(name, dn, dnsiz)
  const char *name; unsigned namelen;
  unsigned char *dn; unsigned dnsiz;
  int *isabs;
convierte el nombre asciiz name de longitud namelen al formato DN, colocando el resultado en el buffer dn de tamaño dnsiz. Devuelve la longitud del DN si tiene éxito, 0 si el buffer dn proporcionado es demasiado pequeño, o un valor negativo si name es inválido. Si isabs no es NULL y la conversión tuvo éxito, *isabs se establecerá en 1 o 0 dependiendo de si name era absoluto (es decir, terminaba con un punto) o no. La longitud del nombre, namelength, puede ser cero, en cuyo caso se utilizará strlen(name). La segunda forma, dns_sptodn(), es una forma simplificada de dns_ptodn(), equivalente a 
dns_ptodn(name, 0, dn, dnlen, 0).
extern const unsigned char dns_inaddr_arpa_dn[]
int dns_a4todn(const struct in_addr *addr, const unsigned char *tdn,
      unsigned char *dn, unsigned dnsiz)
int dns_a4ptodn(const struct in_addr *addr, const char *tname,
      unsigned char *dn, unsigned dnsiz)
extern const unsigned char dns_ip6_arpa_dn[]
int dns_a6todn(const struct in6_addr *addr, const unsigned char *tdn,
      unsigned char *dn, unsigned dnsiz)
int dns_a6ptodn(const struct in6_addr *addr, const char *tname,
      unsigned char *dn, unsigned dnsiz)
varias variantes de rutinas para convertir la dirección IPv4 y IPv6 addr en un nombre de dominio similar a reverseDNS en formato DN, almacenando el resultado en dn de tamaño dnsiz. tdn (o tname) es el nombre de la zona base, como in-addr.arpa para IPv4 o in6.arpa para IPv6. Si tdn (o tname) es NULL, se utilizará dns_inaddr_arpa_dn (o dns_ip6_arpa_dn). Las rutinas se pueden usar para construir un DN para una búsqueda DNSBL, por ejemplo. Todas las rutinas devuelven la longitud del DN resultante en caso de éxito, -1 si el DN resultante no es válido, o 0 si el buffer dn (dnsiz) es demasiado pequeño. Para almacenar un DN rDNS estándar, un buffer de tamaño DNS_A4RSIZE (30 bytes) para una dirección IPv4, o DNS_A6RSIZE (74 bytes) para una dirección IPv6, es suficiente.
int dns_dntop(dn, name, namesiz)
   const unsigned char *dn;
   const char *name; unsigned namesiz;
convierte el nombre de dominio dn en formato DN a una cadena asciiz, colocando el resultado en el buffer name de tamaño namesiz. La longitud máxima de la representación asciiz de un nombre de dominio es DNS_MAXNAME (1024) bytes. El dominio raíz se representa como una cadena vacía. Devuelve la longitud del nombre resultante (incluyendo el carácter de terminación, es decir, strlen(name)+1) en caso de éxito, 0 si el buffer name es demasiado pequeño, o un valor negativo si dn no es válido (este último caso nunca debería ocurrir, ya que todas las rutinas de esta biblioteca que producen nombres de dominio garantizan que los DN generados son válidos).
const char *dns_dntosp(const unsigned char *dn)
convierte el nombre de dominio dn en formato DN a una cadena asciiz utilizando un buffer estático. Devuelve la cadena asciiz resultante en caso de éxito o NULL en caso de fallo. Tenga en cuenta que, dado que esta rutina utiliza un buffer estático, no es segura para hilos.
unsigned dns_dntop_size(const unsigned char *dn)
devuelve el tamaño del buffer necesario para convertir el nombre de dominio dn en formato DN a una cadena asciiz, para dns_dntop(). La rutina devuelve el tamaño del buffer requerido, incluido el byte cero final, o 0 si dn no es válido.

Trabajando con Paquetes DNS

Las siguientes rutinas se proporcionan para codificar y decodificar paquetes DNS en la red. Esta es una interfaz de bajo nivel.

Los códigos de respuesta DNS (devueltos por la rutina dns_rcode()) se definen como constantes prefijadas con DNS_R_. Consulte el archivo de cabecera udns.h para obtener la lista completa. En particular, las constantes DNS_R_NOERROR (0), DNS_R_SERVFAIL, DNS_R_NXDOMAIN pueden ser de interés para una aplicación.

unsigned dns_get16(const unsigned char *p)
unsigned dns_get32(const unsigned char *p)
rutinas auxiliares, convierten un entero de 16 o 32 bits en formato de red apuntado por p a unsigned.
unsigned char *dns_put16(unsigned char *d, unsigned n)
unsigned char *dns_put32(unsigned char *d, unsigned n)
rutina auxiliar, convierte un entero unsigned de 16 o 32 bits n a formato de red en el buffer apuntado por d, devuelve d+2 o d+4.
DNS_HSIZE (12)
define el tamaño de la cabecera DNS. La sección de datos en el paquete DNS sigue inmediatamente a la cabecera. INTERFAZ DE BAJO NIVEL

Esta sección describe las rutinas de bajo nivel para el análisis de paquetes DNS. Se debe tener precaución al usarlas, ya que requieren una comprensión detallada del formato del paquete DNS y de las estructuras internas de la biblioteca udns.

struct dns_parse {
  const unsigned char *dnsp_pkt; /* pointer to the start of the packet */
  const unsigned char *dnsp_end; /* pointer to the byte after the end of the packet */
  const unsigned char *dnsp_cur; /* current pointer in the packet */
  int dnsp_rrl;                  /* número de RR restantes */
  int dnsp_nrr;                  /* número de RR relevantes vistos hasta ahora */
  unsigned dnsp_ttl;             /* valor TTL hasta ahora */
  const unsigned char *dnsp_qdn; /* el dominio de interés o NULL */
  enum dns_class dnsp_qcls;      /* clase de interés o 0 para cualquiera */
  enum dns_type  dnsp_qtyp;      /* tipo de interés o 0 para cualquiera */
  unsigned char dnsp_dnbuf[DNS_MAXDN]; /* buffer del nombre de dominio */
};
La estructura dns_parse se utiliza para analizar paquetes de respuesta DNS. Contiene información sobre el paquete que se está analizando (campos dnsp_pkt, dnsp_end y dnsp_cur), el número de RR en la sección actual que quedan por procesar y la información sobre el RR específico que estamos buscando (campos dnsp_qdn, dnsp_qcls y dnsp_qtyp).
int dns_initparse(struct dns_parse *p,
  const unsigned char *qdn,
  const unsigned char *pkt,
  const unsigned char *cur,
  const unsigned char *end)
inicializa la estructura de análisis de RR p. Los argumentos pkt, cur y end deben describir el paquete recibido: pkt es el inicio del paquete, end apunta al siguiente byte después del final del paquete y cur apunta más allá del DN de la consulta en la sección de consulta (a la información de clase+tipo). Y qdn apunta al DN de la consulta. Estos son los argumentos pasados a la rutina dns_parse_fn(). dns_initparse() inicializa los campos dnsp_pkt, dnsp_end y dnsp_qdn a los argumentos correspondientes, extrae e inicializa los campos dnsp_qcls y dnsp_qtyp a los valores encontrados en el puntero cur, inicializa los campos dnsp_cur y dnsp_ans para que sean cur+4 (al inicio de la sección de respuesta), e inicializa el campo dnsp_rrl al número de entradas en la sección de respuesta. dnsp_ttl se establecerá en el valor TTL máximo, 0xffffffff, y dnsp_nrr en 0.
int dns_nextrr(struct dns_parse *p, struct dns_rr *rr);
busca el siguiente RR en el paquete según los criterios proporcionados en la estructura p, rellenando la estructura rr y avanzando p->dnsp_cur al siguiente RR en el paquete. La selección de RR se basa en los campos dnsp_qdn, dnsp_qcls y dnsp_qtyp en la estructura dns_parse. Cualquiera (o todos) de los 3 campos pueden ser 0, lo que significa que cualquier valor real del paquete es aceptable. En caso de que el campo no sea 0 (o NULL para dnsp_qdn), solo se aceptan RR con características correspondientes. Además, cuando dnsp_qdn no es NULL, dns_nextrr() realiza la expansión automática de CNAME. La rutina devolverá un valor positivo en caso de éxito, 0 en caso de que haya alcanzado el final de la sección actual en el paquete (p->dnsp_rrl es cero), o un valor negativo si el siguiente RR no se puede decodificar (el formato del paquete es inválido). La rutina actualiza p->dnsp_qdn automáticamente cuando este campo no es NULL y encuentra RR CNAME apropiados (guardando el destino CNAME en p->dnsp_dnbuf), por lo que después del final del proceso, p->dnsp_qdn apuntará al nombre canónico del dominio en cuestión. La rutina actualiza el valor p->dnsp_ttl para que sea el TTL mínimo de todos los RR encontrados.
void dns_rewind(struct dns_parse *p, const unsigned char *qdn)
esta rutina "rebobina" la estructura de estado de análisis del paquete para que esté en el mismo estado que después de una llamada a dns_initparse(), es decir, reposiciona la estructura de análisis p al inicio de la sección de respuesta e inicializa p->dnsp_rrl al número de entradas en la sección de respuesta.
int dns_stdrr_size(const struct dns_parse *p);
devuelve el tamaño para mantener la información estándar de la estructura RRset, como se muestra en la estructura dns_rr_null (para los nombres de consulta y canónicos). Se utiliza para calcular la cantidad de memoria a asignar para la parte común de las estructuras RR específicas de tipo en las rutinas de análisis.
void *dns_stdrr_finish(struct dns_rr_null *ret, char *cp,
  const struct dns_parse *p);
inicializa los campos estándar de RRset en la estructura ret utilizando el buffer apuntado por cp, que debe tener al menos tantos bytes como los devueltos por dns_stdrr_size(p). Se utiliza para finalizar la parte común de las estructuras RR específicas de tipo en las rutinas de análisis.

Consulte el código fuente de la biblioteca para ver ejemplos de uso de todas las rutinas de bajo nivel anteriores, especialmente el código fuente de las rutinas de análisis.

Rutinas Auxiliares

int dns_pton(int af, const char *src, void *dst);
proporciona funcionalidad similar a la rutina estándar inet_pton(), para convertir la representación imprimible de una dirección IP de la familia af (ya sea AF_INET o AF_INET6) apuntada por src a forma binaria adecuada para direcciones de socket y transmisión a través de la red, en el buffer apuntado por dst. El buffer de destino debe tener un tamaño de 4 para la familia AF_INET o 16 para AF_INET6. El valor de retorno es positivo en caso de éxito, 0 si src no es una representación de texto válida de una dirección de la familia af, o negativo si la familia de direcciones dada no es compatible.
const char *dns_ntop(int af, const void *src,
    char *dst, int dstsize)
proporciona funcionalidad similar a la rutina estándar inet_ntop(), para convertir la representación binaria de una dirección IP de la familia af (ya sea AF_INET o AF_INET6) apuntada por src (4 o 16 bytes) a forma imprimible en el buffer apuntado por dst de tamaño dstsize. El buffer de destino debe tener al menos 16 bytes para la familia AF_INET o 46 bytes para AF_INET6. El valor de retorno es dst, o un puntero NULL si dstsize es demasiado pequeño para contener esta dirección o si la familia de direcciones dada no es compatible.
