ULIMIT(1P) Manual del programador POSIX ULIMIT(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual correspondiente de Linux para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

ulimit — establecer o informar del límite del tamaño del archivo

SINOPSIS

ulimit [-f] [bloques]

DESCRIPCIÓN

La utilidad ulimit establecerá o informará del límite de tamaño de archivo impuesto a los archivos escritos por el shell y sus procesos hijos (se pueden leer archivos de cualquier tamaño). Solo un proceso con los privilegios apropiados puede aumentar el límite.

OPCIONES

La utilidad ulimit se ajustará al volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidades.

Se soportará la siguiente opción:

-f
Establecer (o informar, si no hay operando bloques presente), el límite del tamaño del archivo en bloques. La opción -f también será el caso por defecto.

OPERANDOS

Se soportará el siguiente operando:

bloques
El número de bloques de 512 bytes a utilizar como nuevo límite de tamaño de archivo.

ENTRADA ESTÁNDAR

No se utiliza.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de ulimit:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en los argumentos).
LC_MESSAGES

Determinar la localización que debe utilizarse para afectar el formato y contenido de los mensajes de diagnóstico escritos en la salida estándar de errores.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

SALIDA ESTÁNDAR

La salida estándar se utilizará cuando no haya ningún operando bloques presente. Si el número actual de bloques está limitado, el número de bloques en el límite actual se escribirá en el siguiente formato:

"%d\n", <número de bloques de 512 bytes>

Si no hay un límite actual en el número de bloques, en la localización POSIX se utilizará el siguiente formato:

"unlimited\n"

SALIDA ESTÁNDAR DE ERRORES

La salida estándar de errores se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Se rechazó una solicitud de un límite superior o ocurrió un error.

CONSECUENCIAS DE LOS ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

Dado que ulimit afecta al entorno de ejecución del shell actual, siempre se proporciona como un shell integrado regular. Si se llama en un entorno de ejecución de utilidad separado, como uno de los siguientes:

nohup ulimit -f 10000
env ulimit 10000

no afecta al límite de tamaño de archivo del entorno del llamador.

Una vez que un límite ha sido reducido por un proceso, no se puede aumentar (a menos que involucre privilegios apropiados), ni siquiera de vuelta al límite del sistema original.

EJEMPLOS

Establecer el límite del tamaño del archivo a 51200 bytes:

ulimit -f 100
