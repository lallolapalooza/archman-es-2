NOMBRE

upsclient - Biblioteca de acceso al cliente de Network UPS Tools

DESCRIPCIÓN

La biblioteca upsclient de Network UPS Tools (NUT) proporciona un número de funciones útiles para que los programas cliente las utilicen al comunicarse con upsd(8). Muchos de los detalles de bajo nivel del socket y del protocolo se manejan automáticamente al usar esta interfaz, también conocida como API "upscli".

El estado se mantiene entre llamadas en una estructura opaca llamada UPSCONN_t. Se espera que los llamantes creen una por conexión. Estas se proporcionarán a la mayoría de las funciones de upsclient. El formato de esta estructura está sujeto a cambios, y los programas cliente no deben referenciar directamente los elementos dentro de ella.

INICIALIZACIÓN Y LIMPIEZA

Antes de crear cualquier conexión, y en general al usar cualquier función upscli, debe llamar a upscli_init(3) con los parámetros correctos para inicializar el módulo upscli.

Para registrar una política de seguridad específica para el host, debe llamar a upscli_add_host_cert(3) antes de inicializar una conexión a él.

De la misma manera, justo antes de salir, y después de todo el uso de upscli, debe llamar a upscli_cleanup(3) para vaciar los archivos de caché y realizar otra limpieza.

FUNCIONES DE RED

Para crear una nueva conexión, use upscli_connect(3). Esto también inicializará la estructura UPSCONN_t. Para verificar que se ha establecido una conexión más tarde, se puede usar upscli_fd(3) para devolver el descriptor de archivo. Los clientes que deseen verificar la presencia y operación de SSL en una conexión pueden llamar a upscli_ssl(3).

La mayoría de los clientes usarán upscli_get(3) para recuperar elementos individuales del servidor. Para recuperar una lista, use upscli_list_start(3) para iniciarla, luego llame a upscli_list_next(3) para cada elemento.

Se pueden enviar líneas de texto sin procesar a upsd(8) con upscli_sendline(3). La lectura de líneas sin procesar es posible con upscli_readline(3). Se espera que los programas cliente den formato a estas líneas de acuerdo con el protocolo, ya que no se realizará ninguna comprobación antes de la transmisión.

Al final de una conexión, debe llamar a upsclient_disconnect(3) para desconectarse de upsd y liberar cualquier memoria dinámica asociada con la estructura UPSCONN_t. No llamar a esta función resultará en fugas de memoria y descriptores de archivo en su programa.

FUNCIONES DE CADENA

Para analizar los valores ups.status (comprobar si un token particular está presente) se recomienda utilizar el método upscli_str_contains_token(3).

Para recopilar tokens únicos en una cadena de la misma manera que lo hace un driver NUT, upscli_str_add_unique_token(3) puede ser útil.

Le invitamos a consultar la base de código fuente de NUT para ver el uso de métodos equivalentes para implementar características como los métodos status_init(), status_get(), status_set() y status_commit() en sus bucles de procesamiento de datos.

MANEJO DE ERRORES

En caso de error, upscli_strerror(3) proporcionará detalles legibles por humanos sobre lo que sucedió. upscli_upserror(3) también puede usarse para recuperar el número de error. Estos números se definen en upsclient.h como UPSCLI_ERR_*.
