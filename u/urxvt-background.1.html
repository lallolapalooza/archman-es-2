NOMBRE

background - gestionar fondo de terminal

SINOPSIS

urxvt --background-expr 'expresión de fondo'
      --background-border
      --background-interval segundos

HOJA DE TRUCOS RÁPIDA Y SUCIA

Cargar una imagen jpeg aleatoria y rellenar el fondo con ella sin escalado ni nada más:

load "/ruta/a/img.jpg"

Lo mismo, pero usar reflejo en lugar de mosaico:

mirror load "/ruta/a/img.jpg"

Cargar una imagen y escalarla para que llene exactamente la ventana de la terminal:

scale keep { load "/ruta/a/img.jpg" }

Implementar pseudo-transparencia usando una imagen de fondo de la raíz adecuadamente alineada como fondo de ventana:

rootalign root

Igualmente, pero mantener una copia difuminada:

rootalign keep { blur 10, root }

DESCRIPCIÓN

Esta extensión gestiona el fondo de la terminal creando una imagen que se coloca detrás del texto, reemplazando el color de fondo normal.

Lo hace evaluando una expresión Perl que calcula la imagen sobre la marcha, por ejemplo, capturando el fondo de la raíz o cargando un archivo.

Aunque está disponible todo el poder de Perl, los operadores han sido diseñados para ser lo más simples posible.

Por ejemplo, para cargar una imagen y escalarla al tamaño de la ventana, usarías:

urxvt --background-expr 'scale keep { load "/ruta/a/mi_fondo.png" }'

O especificado como un recurso X:

URxvt.background.expr: scale keep { load "/ruta/a/mi_fondo.png" }

TEORÍA DE OPERACIÓN

Al inicio, justo antes de que la ventana se mapee por primera vez, se evalúa la expresión y debe devolver una imagen. Luego, la imagen se extiende según sea necesario para cubrir toda la ventana de la terminal y se establece como un pixmap de fondo.

Si la imagen contiene un canal alfa, se usará tal cual en visualizaciones que soporten canales alfa (por ejemplo, para un gestor de composición). En otras visualizaciones, el color de fondo de la terminal se usará para reemplazar cualquier transparencia.

Si la expresión se basa, directa o indirectamente, en el tamaño de la ventana, la posición, el pixmap de la raíz o un temporizador, se recordará. Si no, se eliminará.

Si alguno de los parámetros en los que se basa la expresión cambia (cuando la ventana se mueve o redimensiona, cambia su posición o tamaño; cuando el pixmap de la raíz es reemplazado por otro, cambia el fondo de la raíz; o cuando el temporizador expira), la expresión se evaluará de nuevo.

Por ejemplo, una expresión como "scale keep { load "$HOME/mi_fondo.png" }" escala la imagen al tamaño de la ventana, por lo que depende del tamaño de la ventana y se reevaluará cada vez que cambie, pero no cuando se mueva, por ejemplo. Eso asegura que la imagen siempre llene la terminal, incluso después de que su tamaño cambie.

EXPRESIONES

Las expresiones son expresiones Perl normales, de hecho, son bloques Perl, lo que significa que podrías usar múltiples líneas y sentencias:

scale keep {
   again 3600;
   if (localtime now)[6]) {
      return load "$HOME/dia_semana.png";
   } else {
      return load "$HOME/domingo.png";
   }
}

Esta expresión interna se evalúa una vez por hora (y cada vez que se redimensiona la ventana de la terminal). Establece domingo.png como fondo los domingos y dia_semana.png los demás días.

Afortunadamente, esperamos que la mayoría de las expresiones sean mucho más simples, necesitando poco conocimiento de Perl.

Básicamente, siempre comienzas con una función que "genera" un objeto de imagen, como "load", que carga una imagen del disco, o "root", que devuelve la imagen de fondo de la ventana raíz:

load "$HOME/mi_foto.png"

La ruta generalmente se especifica como una cadena entre comillas (las reglas exactas se pueden encontrar en la página del manual perlop). El $HOME al principio de la cadena se expande al directorio de inicio.

Luego, antepones uno o más modificadores o expresiones de filtrado, como "scale":

scale load "$HOME/mi_foto.png"

Al igual que una expresión matemática con funciones, debes leer estas expresiones de derecha a izquierda, ya que "load" se evalúa primero y su resultado se convierte en el argumento de la función "scale".

Muchos operadores también permiten algunos parámetros que preceden a la imagen de entrada que modifican su comportamiento. Por ejemplo, "scale" sin argumentos adicionales escala la imagen al tamaño de la ventana de la terminal. Si especificas un argumento adicional, lo usas como factor de escala (multiplica por 100 para obtener un porcentaje):

scale 2, load "$HOME/mi_foto.png"

Esto agranda la imagen en un factor de 2 (200%). Como puedes ver, "scale" ahora tiene dos argumentos, el 2 y la expresión "load", mientras que "load" solo tiene un argumento. Los argumentos se separan entre sí por comas.

Scale también acepta dos argumentos, que son entonces factores separados para las dimensiones horizontal y vertical. Por ejemplo, esto reduce a la mitad el ancho de la imagen y duplica la altura de la imagen:

scale 0.5, 2, load "$HOME/mi_foto.png"

SI intentas usar estas expresiones, podrías experimentar cierta lentitud, porque cada vez que se redimensiona la terminal, vuelve a cargar la imagen PNG y la escala. Escalar suele ser rápido (e inevitable), pero cargar la imagen puede consumir bastante tiempo. Aquí es donde "keep" resulta útil:

scale 0.5, 2, keep { load "$HOME/mi_foto.png" }

El operador "keep" ejecuta todas las sentencias dentro de las llaves solo una vez, o cuando cree que el resultado podría cambiar. En otros casos, devuelve el último valor computado por el bloque de llaves.

Esto significa que "load" solo se ejecuta una vez, lo que lo hace mucho más rápido, pero también significa que se está utilizando más memoria, porque la imagen cargada debe mantenerse en memoria en todo momento. En esta expresión, la compensación probablemente vale la pena.

Pero volviendo a los efectos: otros efectos además de escalar también están fácilmente disponibles, por ejemplo, puedes rellenar la ventana completa con la imagen, en lugar de redimensionarla:

tile keep { load "$HOME/mi_foto.png" }

De hecho, las imágenes devueltas por "load" están en modo "tile" por defecto, por lo que el operador "tile" es algo superfluo.

Otro efecto común es reflejar la imagen, de modo que los mismos bordes se toquen:

mirror keep { load "$HOME/mi_foto.png" }

Otra expresión de fondo común es:

rootalign root

Esta toma primero una instantánea de la imagen de fondo de la pantalla y luego la mueve a la esquina superior izquierda de la pantalla (en lugar de la esquina superior izquierda de la ventana de la terminal). El resultado es pseudo-transparencia: la imagen parece ser estática mientras la ventana se mueve.

ESPECIFICACIONES DE COLOR

Siempre que un operador espere un "color", esto se puede especificar de dos maneras: O como una cadena con una especificación de color X11, como:

"red"               # color con nombre
"#f00"              # rgb simple
"[50]red"           # rojo con 50% de alfa
"TekHVC:300/50/50"  # vale cualquier cosa

O como una referencia de matriz con uno, tres o cuatro componentes:

[0.5]               # gris al 50%, alfa al 100%
[0.5, 0, 0]         # rojo oscuro, sin verde ni desenfoque, alfa al 100%
[0.5, 0, 0, 0.7]    # lo mismo con alfa explícito al 70%

CACHÉ Y SENSIBILIDAD

Dado que algunas operaciones (como "load" y "blur") pueden llevar mucho tiempo, el almacenamiento en caché de resultados puede ser muy importante

Para un funcionamiento fluido. El almacenamiento en caché también puede ser útil para reducir el uso de memoria, aunque, por ejemplo, cuando una imagen se almacena en caché mediante "load", podría ser compartida por varias ventanas de terminal que se ejecutan dentro de urxvtd.

Caché de "keep { ... }"

La forma más importante de almacenar en caché operaciones costosas es usar "keep { ... }". El operador "keep" toma un bloque de múltiples declaraciones encerradas entre "{}" y mantiene el valor de retorno en memoria.

Una expresión puede ser "sensible" a varios eventos externos, como escalar o mover la ventana, cambios en el fondo de la raíz y temporizadores. Simplemente usar una expresión (como "scale" sin parámetros) que depende de ciertos valores cambiantes (llamados "variables"), o usar esas variables directamente, hará que una expresión sea sensible a estos eventos; por ejemplo, usar "scale" o "TW" hará que la expresión sea sensible al tamaño de la terminal y, por lo tanto, a los eventos de redimensionamiento.

Cuando ocurre un evento de este tipo, "keep" disparará automáticamente una reevaluación de toda la expresión con el nuevo valor de la expresión.

"keep" es más útil para operaciones costosas, como "blur":

rootalign keep { blur 20, root }

Esto crea una copia difuminada del fondo de la raíz una vez y, en llamadas subsiguientes, solo la alinea con la raíz. Dado que "blur" suele ser bastante lento y "rootalign" es bastante rápido, esto intercambia memoria adicional (para el pixmap difuminado en caché) por velocidad (el difuminado solo necesita rehacerse cuando la raíz cambia).

Caché de "load"

El operador "load" en sí mismo no mantiene las imágenes en memoria, pero mientras la imagen siga en memoria, "load" utilizará la imagen en memoria en lugar de cargarla de nuevo desde el disco.

Eso significa que esta expresión:

keep { load "$HOME/path..." }

No solo almacena la imagen en caché en memoria, sino que otras instancias de terminal que intenten cargarla pueden reutilizar esa copia en memoria.

REFERENCIA

OPCIONES DE LÍNEA DE COMANDOS

--background-expr expresión-perl
Especifica la expresión Perl a evaluar.
--background-border
Por defecto, la expresión crea una imagen que llena toda la ventana, sobrescribiendo bordes y otras áreas, como la barra de desplazamiento.

Especificar esta bandera cambia el comportamiento, de modo que la imagen solo reemplaza el fondo del área de caracteres.

--background-interval segundos
Dado que algunas operaciones en la extensión subyacente XRender pueden congelar efectivamente tu servidor X durante un tiempo prolongado, esta extensión impone un tiempo mínimo entre actualizaciones, que normalmente es de aproximadamente 0.1 segundos.

Si deseas realizar actualizaciones con mayor frecuencia, puedes reducir este intervalo de seguridad con esta opción.

PROVEEDORES/GENERADORES

Estas funciones proporcionan una imagen, ya sea cargándola desde el disco, capturándola de la pantalla raíz o simplemente generándola. Se utilizan como puntos de partida para obtener una imagen con la que se pueda jugar.

load $ruta
Carga la imagen en la $ruta dada. La imagen se establece en modo de teselado plano.

Si la imagen ya está en memoria (por ejemplo, porque otra instancia de terminal la está utilizando), se devuelve la copia en memoria.

load_uc $ruta
Cargar sin caché: igual que load, pero no almacena la imagen en caché, lo que significa que *siempre* se carga desde el sistema de archivos de nuevo, incluso si hay otra copia de ella en memoria en ese momento.
root
Devuelve el pixmap de la ventana raíz, que, con suerte, es la imagen de fondo de tu pantalla.

Esta función hace que tu expresión sea sensible a la raíz, es decir, se reevaluará cuando cambie la imagen de fondo.

solid $color
solid $ancho, $alto, $color
Crea una nueva imagen y la rellena completamente con el color dado. La imagen se establece en modo de teselado.

Si se omiten $ancho y $alto, crea una imagen de 1x1, lo cual es útil para fondos sólidos o para usar en efectos de filtrado.

clone $img
Devuelve una copia exacta de la imagen. Esto es útil si deseas tener múltiples copias de la misma imagen para aplicarles diferentes efectos.
merge $img ...
Toma cualquier número de imágenes y las fusiona, creando una sola imagen que las contiene a todas. El modo de teselado de la primera imagen se usa como el modo de teselado de la imagen resultante.

Esta función se llama automáticamente cuando una expresión devuelve múltiples imágenes.

MODOS DE TESELADO

Los siguientes operadores modifican el modo de teselado de una imagen, es decir, la forma en que se pintan los píxeles fuera del área de la imagen cuando se utiliza la imagen.

tile $img
Tesela todo el plano con la imagen y devuelve esta nueva imagen; en otras palabras, devuelve una copia de la imagen en modo de teselado plano.

Ejemplo: carga una imagen y la tesela sobre el fondo, sin cambiar el tamaño. La llamada "tile" es superflua porque "load" ya usa el modo de teselado por defecto.

tile load "mybg.png"
mirror $img
Similar a tile, pero refleja la imagen cada vez que utiliza una nueva copia, de modo que los bordes superiores siempre tocan los bordes superiores, los bordes derechos siempre tocan los bordes derechos, etc. (con el teselado normal, los bordes izquierdos siempre tocan los bordes derechos y los superiores siempre tocan los inferiores).

Ejemplo: carga una imagen y la refleja sobre el fondo, evitando bordes afilados en los bordes de la imagen a costa de reflejar la imagen misma.

mirror load "mybg.png"
pad $img
Toma una imagen y la modifica de modo que todos los píxeles fuera del área de la imagen se vuelvan transparentes. Este modo es más útil cuando deseas colocar una imagen sobre otra imagen o sobre el color de fondo, dejando todos los píxeles de fondo fuera de la imagen sin cambios.

Ejemplo: carga una imagen y la muestra en la esquina superior izquierda. El resto del espacio se deja "vacío" (transparente o lo que sea que tu compositor haga en modo alfa, de lo contrario, color de fondo).

pad load "mybg.png"
extend $img
Extiende la imagen sobre todo el plano, utilizando el píxel más cercano en el área fuera de la imagen. Este modo es principalmente útil cuando se utilizan operaciones de filtrado más complejas y se desea que los píxeles fuera de la imagen tengan los mismos valores que los píxeles cercanos al borde.

Ejemplo: solo por curiosidad, ¿cómo funciona esta extensión de píxeles?

extend move 50, 50, load "mybg.png"

VALORES DE VARIABLES

Las siguientes funciones proporcionan datos variables como las dimensiones de la ventana de la terminal. No son variables (de Perl), solo devuelven cosas que varían. La mayoría de ellas hacen que tu expresión sea sensible a algunos eventos, por ejemplo, usar "TW" (ancho de la terminal) significa que tu expresión se evalúa de nuevo cuando la terminal se redimensiona.

TX
TY
Devuelven las coordenadas X e Y de la ventana de la terminal (la ventana de la terminal es la ventana completa por defecto, y solo el área de caracteres cuando está en modo de respeto a los bordes).

Usar estas funciones hace que tu expresión sea sensible a los movimientos de ventana.

Estas funciones son principalmente útiles para alinear imágenes con la ventana raíz.

Ejemplo: carga una imagen y la alinea para que parezca anclada al fondo (eso es exactamente lo que hace "rootalign", por cierto):

move -TX, -TY, keep { load "mybg.png" }
TW
TH
Devuelven el ancho ("TW") y la altura ("TH") de la ventana de la terminal (la ventana de la terminal es la ventana completa por defecto, y solo el área de caracteres cuando está en modo de respeto a los bordes).

Usar estas funciones hace que tu expresión sea sensible a los redimensionamientos de ventana.

Estas funciones son principalmente útiles para escalar imágenes o para recortar imágenes al tamaño de la ventana para conservar memoria.

Ejemplo: toma el fondo de pantalla, lo recorta al tamaño de la ventana, lo difumina un poco, lo alinea a la posición de la ventana y lo usa como fondo.

clip move -TX, -TY, keep { blur 5, root }
FOCUS
Devuelve un booleano que indica si la ventana de la terminal tiene el foco del teclado, en cuyo caso devuelve verdadero.

Usar esta función hace que tu expresión sea sensible a los cambios de foco.

Un caso de uso común es desvanecer la imagen de fondo cuando la terminal pierde el foco, a menudo junto con la opción de línea de comandos "-fade". De hecho, existe una función especial solo para ese caso de uso: "focus_fade".

.

Ejemplo: usar dos imágenes de fondo completamente diferentes, dependiendo de si la ventana tiene el foco.

FOCUS ? keep { load "has_focus.jpg" } : keep { load "no_focus.jpg" }
now
Devuelve la hora actual en segundos (fraccionarios) desde la época.

El uso de esta expresión *no* hace que su expresión sea sensible al tiempo, pero las dos siguientes funciones sí lo hacen.

again $segundos
Cuando se utiliza esta función, la expresión se reevaluará de nuevo en $segundos segundos.

Ejemplo: cargar una imagen y rotarla según la hora del día (como si fuera la aguja de las horas de un reloj). Actualizar esta imagen cada minuto.

again 60;
rotate 50, 50, (now % 86400) * -72 / 8640, scale keep { load "myclock.png" }
counter $segundos
Similar a "again", pero también devuelve un contador creciente, comenzando en 0, lo que podría ser útil para algunos efectos de animación simples.

OPERADORES QUE CAMBIAN LA FORMA

Los siguientes operadores modifican la forma, el tamaño o la posición de la imagen.

clip $img
clip $ancho, $alto, $img
clip $x, $y, $ancho, $alto, $img
Recorta una imagen al rectángulo dado. Si el rectángulo está fuera del área de la imagen (por ejemplo, cuando $x o $y son negativos) o el rectángulo es más grande que la imagen, el modo de mosaico define cómo se rellenarán los píxeles adicionales.

Si $x e $y faltan, se asume 0 para ambos.

Si $ancho y $alto faltan, se asumirá el tamaño de la ventana.

Ejemplo: cargar una imagen, difuminarla y recortarla al tamaño de la ventana para ahorrar memoria.

clip keep { blur 10, load "mybg.png" }
scale $img
scale $factor_tamaño, $img
scale $factor_ancho, $factor_alto, $img
Escala la imagen por los factores dados en la dirección horizontal ($ancho) y vertical ($alto).

Si solo se da un factor, se utiliza para ambas direcciones.

Si no se dan factores, escala la imagen al tamaño de la ventana sin mantener la proporción.

resize $ancho, $alto, $img
Redimensiona la imagen a exactamente $ancho por $alto píxeles.
fit $img
fit $ancho, $alto, $img
Ajusta la imagen al $ancho y $alto dados sin cambiar la proporción, o al tamaño de la terminal. Eso significa que se encogerá o agrandará hasta que la imagen completa quepa en el área dada, dejando posiblemente bordes.
cover $img
cover $ancho, $alto, $img
Similar a "fit", pero encoge o agranda hasta que toda el área esté cubierta por la imagen, por lo que en lugar de dejar posiblemente bordes, cortará los datos de la imagen que no caben.
move $dx, $dy, $img
Mueve la imagen $dx píxeles en horizontal y $dy píxeles en vertical.

Ejemplo: mover la imagen 20 píxeles a la derecha y 30 hacia abajo.

move 20, 30, ...
align $xalign, $yalign, $img
Alinea la imagen según un factor: 0 significa que la imagen se mueve al borde izquierdo o superior (para $xalign o $yalign), 0.5 significa que está exactamente centrada y 1 significa que toca el borde derecho o inferior.

Ejemplo: eliminar cualquier borde visible alrededor de una imagen, centrarla verticalmente pero moverla hacia el lado derecho.

align 1, 0.5, pad $img
center $img
center $ancho, $alto, $img
Centra la imagen, es decir, el centro de la imagen se mueve al centro de la ventana de la terminal (o al cuadro especificado por $ancho y $alto si se proporcionan).

Ejemplo: cargar una imagen y centrarla.

center keep { pad load "mybg.png" }
rootalign $img
Mueve la imagen para que parezca pegada a la pantalla en lugar de a la ventana. Esto da la ilusión de un área más grande detrás de la ventana. Es exactamente equivalente a "move -TX, -TY", es decir, mueve la imagen a la esquina superior izquierda de la pantalla.

Ejemplo: cargar una imagen de fondo, ponerla en modo espejo y alinearla a la raíz.

rootalign keep { mirror load "mybg.png" }

Ejemplo: tomar el fondo de pantalla y alinearlo, dando la ilusión de transparencia siempre que la ventana no esté delante de otras ventanas.

rootalign root
rotate $centro_x, $centro_y, $grados, $img
Rota la imagen en sentido horario $grados grados, alrededor del punto en $centro_x y $centro_y (especificado como factor del ancho/alto de la imagen).

Ejemplo: rotar la imagen 90 grados alrededor de su centro.

rotate 0.5, 0.5, 90, keep { load "$HOME/mybg.png" }

MODIFICACIONES DE COLOR

Los siguientes operadores cambian los píxeles de la imagen.

tint $color, $img
Tiñe la imagen con el color dado.

Ejemplo: teñir la imagen de rojo.

tint "red", load "rgb.png"

Ejemplo: lo mismo, pero especificando el color por componente.

tint [1, 0, 0], load "rgb.png"
shade $factor, $img
Sombra la imagen por el factor dado.
contrast $factor, $img
contrast $r, $g, $b, $img
contrast $r, $g, $b, $a, $img
Ajusta el *contraste* de una imagen.

La primera forma aplica un único $factor a rojo, verde y azul; la segunda forma aplica factores separados a cada canal de color; y la última incluye el canal alfa.

Los valores de 0 a 1 reducen el contraste, los valores mayores que 1 aumentan el contraste.

Debido a limitaciones en la extensión XRender subyacente, reducir el contraste también reduce el brillo, mientras que aumentar el contraste actualmente también aumenta el brillo.

brightness $bias, $img
brightness $r, $g, $b, $img
brightness $r, $g, $b, $a, $img
Ajusta el brillo de una imagen.

La primera forma aplica un único $bias a rojo, verde y azul; la segunda forma aplica sesgos separados a cada canal de color; y la última incluye el canal alfa.

Los valores menores que 0 reducen el brillo, mientras que los valores mayores que 0 lo aumentan. El rango útil es de -1 a 1: el primero resulta en una imagen negra, el último en una imagen blanca.

Debido a las peculiaridades de la extensión XRender subyacente, los sesgos menores que cero pueden ser *muy* lentos.

También puedes probar el operador experimental(!) "muladd".

muladd $mul, $add, $img # EXPERIMENTAL
Primero multiplica los píxeles por $mul y luego suma $add. Esto se puede usar para implementar brillo y contraste al mismo tiempo, con un rango de valores más amplio que los operadores de contraste y brillo.

Debido a numerosos errores en las implementaciones de XRender, también puede introducir una serie de artefactos visuales.

Ejemplo: aumentar el contraste en un factor de $c sin cambiar demasiado el brillo de la imagen.

muladd $c, (1 - $c) * 0.5, $img
blur $radio, $img
blur $radio_horz, $radio_vert, $img
Aplica un desenfoque gaussiano a la imagen con un radio de $radio píxeles (aproximadamente). Los radios también se pueden especificar por separado.

El desenfoque suele ser *muy* lento, al menos en comparación con otros operadores. Los radios de desenfoque más grandes son más lentos que los más pequeños, por lo que si no quieres congelar tu pantalla durante mucho tiempo, empieza experimentando con valores bajos para el radio (<5).

focus_fade $factor, $img
focus_fade $factor, $color, $img

NAME

urxvt-background - extended background image support for rxvt-unicode

SYNOPSIS

The background image extension is enabled by default. It provides the following:

URxvt.background.expr: expression
-background-expr expression

The expression is a sequence of operations on images, which are described below.

QUICK AND DIRTY CHEAT SHEET

load file
loads the specified image file.
blur radius
blurs the image.
fade factor
fades the image to the background colour. factor is a percentage value (0..100).
tint colour
tints the image with the specified colour.
trans colour
makes the specified colour transparent.
color colour
equivalent to tint.
scale width%xheight%
scales the image to the given dimensions.
resize width%xheight%
equivalent to scale.
rotate degrees
rotates the image.
flip horz|vert
flips the image.
crop widthxheight+x+y
crops the image.
rotal width%xheight%
rotates the image by 90/180/270 degrees and aligns it to the window.
keep
caches the result of the expression.
paste op
pastes the image according to the specified operation.

Operations can be combined, e.g.:

load bg.png ; scale 50%x50% ; rotal 100%x100%

DESCRIPTION

This extension replaces the older background image extension, adding support for more image manipulation operations and a more flexible, expression-based configuration.

The image expression is evaluated once for the initial window setup and then re-evaluated whenever the window is resized, moved, or the root window background changes.

THEORY OF OPERATION

The background image itself is implemented as a pseudo-transparent window layered below the main terminal window. This window can be dimmed, blurred, tinted, and have an image drawn onto it.

The actual image manipulation is done using the imlib2 library.

REFERENCE

The expression is a sequence of operations, each potentially taking arguments. Operations are separated by semicolons (;).

load file
Loads the image file specified. Supported formats depend on the installed `imlib2` version, but usually include PNG, JPEG, GIF, BMP, TIFF, etc. The filename can be an absolute path or a relative path to the current directory.
scale width% [x height%]
Resizes the image to the specified dimensions. If only width is specified, height is scaled proportionally. If no dimensions are specified, the image is scaled to fit the window. A scale of 0 disables scaling.
resize width% [x height%]
Equivalent to scale.
rotate degrees
Rotates the image by the specified number of degrees (clockwise).
flip horz | vert
Flips the image horizontally or vertically.
crop WxH+X+Y
Crops the image to the specified dimensions and offset. W and H specify the width and height, while X and Y specify the offset from the top-left corner.
tint colour
Tints the image with the specified colour. The colour can be specified as a name (e.g., red, blue) or as a hexadecimal value (e.g., #RRGGBB).
color colour
Equivalent to tint.
fade factor
Fades the image towards the background colour. The factor is a percentage value from 0 to 100. A factor of 0 means no fading, and a factor of 100 means the image is completely replaced by the background colour.
trans colour
Makes the specified colour transparent in the image. This is useful for images with transparency masks.
blur radius
Applies a Gaussian blur to the image. The radius specifies the blur amount. A radius of 0 disables blurring.
rotal width% [x height%]
Rotates and aligns the image. This is typically used to rotate the image by 90, 180, or 270 degrees and then scale it to fit the window while maintaining the aspect ratio. The specified dimensions are the target dimensions for the rotated image.
paste op
Pastes the image onto the background according to the specified operation. Supported operations include:
center
Center the image on the background.
left-top
Align the image to the top-left corner.
right-bottom
Align the image to the bottom-right corner.
tile
Tile the image across the background.
scale
Scale the image to fit the window, maintaining aspect ratio.
scale-fill
Scale the image to fill the window, ignoring aspect ratio.
root
Align the image according to the root window's alignment.
keep
This operation caches the result of the preceding operations. If the expression is re-evaluated, the cached result is used instead of recomputing it. This is useful for expensive operations like blurring or loading large images. The cache is invalidated if the window is resized, moved, or the root background changes.
focus_fade factor
Similar to fade, but applied only when the window is not in focus. The factor is a real value between 0 and 1. This allows for smooth fading effects when the window loses or gains focus. Unlike with -fade, the $factor is a real value, not a percentage value (that is, 0..1, not 0..100).

Example: do the right thing when focus fading is requested.

focus_fade load "mybg.jpg";

OTHER STUFF

Anything that didn't fit any of the other categories, even after applying force and closing our eyes.

keep { ... }
This operator takes a code block as argument, that is, one or more statements enclosed by braces.

The trick is that this code block is only evaluated when the outcome changes - on other calls the "keep" simply returns the image it computed previously (yes, it should only be used with images). Or in other words, "keep" caches the result of the code block so it doesn't need to be computed again.

This can be extremely useful to avoid redoing slow operations - for example, if your background expression takes the root background, blurs it and then root-aligns it it would have to blur the root background on every window move or resize.

Another example is "load", which can be quite slow.

In fact, urxvt itself encloses the whole expression in some kind of "keep" block so it only is reevaluated as required.

Putting the blur into a "keep" block will make sure the blur is only done once, while the "rootalign" is still done each time the window moves.

rootalign keep { blur 10, root }

This leaves the question of how to force reevaluation of the block, in case the root background changes: If expression inside the block is sensitive to some event (root background changes, window geometry changes), then it will be reevaluated automatically as needed.

OLD BACKGROUND IMAGE SETTINGS

This extension also provides support for the old options/resources and OSC sequences for setting a background image. These settings are deprecated and will be removed in future versions.

OPTIONS AND RESOURCES

-pixmap file[;oplist]
backgroundPixmap: file[;oplist]
Use the specified image file as the window's background and also optionally specify a colon separated list of operations to modify it. Note that you may need to quote the ";" character when using the command line option, as ";" is usually a metacharacter in shells. Supported operations are:
WxH+X+Y
sets scale and position. "W" / "H" specify the horizontal/vertical scale (percent), and "X" / "Y" locate the image centre (percent). A scale of 0 disables scaling.
op=tile
enables tiling
op=keep-aspect
maintain the image aspect ratio when scaling
op=root-align
use the position of the terminal window relative to the root window as the image offset, simulating a root window background

The default scale and position setting is "100x100+50+50". Alternatively, a predefined set of templates can be used to achieve the most common setups:

style=tiled
the image is tiled with no scaling. Equivalent to 0x0+0+0:op=tile
style=aspect-stretched
the image is scaled to fill the whole window maintaining the aspect ratio and centered. Equivalent to 100x100+50+50:op=keep-aspect
style=stretched
the image is scaled to fill the whole window. Equivalent to 100x100
style=centered
the image is centered with no scaling. Equivalent to 0x0+50+50
style=root-tiled
the image is tiled with no scaling and using 'root' positioning. Equivalent to 0x0:op=tile:op=root-align

If multiple templates are specified the last one wins. Note that a template overrides all the scale, position and operations settings.

If used in conjunction with pseudo-transparency, the specified image will be blended over the transparent background using alpha-blending.

-tr|+tr
transparent: boolean
Turn on/off pseudo-transparency by using the root pixmap as background.
-tint colour
tintColor: colour
Tint the transparent background with the given colour. Note that a black tint yields a completely black image while a white tint yields the image unchanged.
-sh number
shading: number
Darken (0 .. 99) or lighten (101 .. 200) the transparent background. A value of 100 means no shading.
-blr HxV
blurRadius: HxV
Apply gaussian blur with the specified radius to the transparent background. If a single number is specified, the vertical and horizontal radii are considered to be the same. Setting one of the radii to 1 and the other to a large number creates interesting effects on some backgrounds. The maximum radius value is 128. An horizontal or vertical radius of 0 disables blurring.

OSC sequences

This extension will react to the following OSC sequences. Note that this extension will not be autoloaded when these are used currently, so to make urxvt recognize them, you have to enable the "background" extension. One way to achieve that is to use the "--background-expr ''" command line argument or by specifying an empty "URxvt.background.expr:"> resource.

"ESC ] 705 ; Pt ST" Change transparent background tint colour to "Pt".
"ESC ] 20 ; Pt ST" Change/Query background image parameters: the value of "Pt" can be one of the following commands:
"?"
display scale and position in the title
";WxH+X+Y"
change scale and/or position
"FILE;WxH+X+Y"
change background image
