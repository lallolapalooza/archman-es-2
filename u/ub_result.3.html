DESCRIPCIÓN

Unbound es una implementación de un resolvedor DNS, que realiza caché y validación DNSSEC. Esta es la API de la biblioteca, para usar la biblioteca -lunbound. El demonio del servidor se describe en unbound(8). La biblioteca funciona independientemente de un servidor unbound en ejecución y puede usarse para convertir nombres de host a direcciones IP y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de clave pública de los resultados con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Puede crearse y eliminarse en cualquier momento. Crear una nueva elimina cualquier configuración previa (como claves de confianza) y vacía cualquier resultado en caché.

Las funciones son seguras para hilos (thread-safe) y un contexto puede usarse en un entorno con hilos (así como en uno sin hilos). La resolución (y validación) también puede realizarse de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve la llamada inmediatamente, para que el procesamiento pueda continuar mientras los resultados están disponibles más tarde.

Las funciones se discuten a continuación, una por una.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza por defecto. Usa ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esta función, usa las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si usas lib openssl (la aplicación llama a estas funciones una vez para inicialización). Openssl 1.0.0 o posterior usa la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y no se llamarán a las devoluciones de llamada para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que permite especificar una de las opciones del formato de archivo de configuración, ver unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclas de confianza, existen rutinas especiales. Pasa el nombre de la opción con el ':' al final.
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene el valor de una opción. Algunas opciones no se pueden obtener y otras devuelven una lista separada por saltos de línea. Pasa el nombre de la opción sin el ':' al final. El valor devuelto debe ser liberado (free(2)) por el llamante.
ub_ctx_config
Una interfaz para usuarios avanzados que permite especificar un archivo de configuración de unbound, ver unbound.conf(5), que se lee para la configuración. No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclas de confianza, existen rutinas especiales. Esta función solo es segura para hilos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no se llame en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se enviarán las consultas DNS, el resolvedor de caché a usar. Dirección IP4 o IP6. Envía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolvedor recursivo. Si el proxy no es compatible con DNSSEC, la validación puede fallar. Se puede llamar varias veces, en cuyo caso las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible configurar antes de que se realice la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autorizados a usar para una zona particular. Dirección IP4 o IP6. Si la dirección es NULL, se elimina la entrada stub. Establece isprime en true si configuras las pistas raíz con ella. De lo contrario, es similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas, o para agregar varias direcciones para una zona particular. En este momento, solo es posible configurar antes de que se realice la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible configurar antes de que se realice la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolución completa, pero puedes usar esta llamada para leer la lista de servidores de nombres a utilizar desde el nombre de archivo proporcionado. Normalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no soportan DNSSEC, la validación puede fallar. Solo se capturan los servidores de nombres, se ignoran el dominio de búsqueda (searchdomain), ndots y otras configuraciones de resolv.conf(5). Si se pasa NULL como fname, se usa "/etc/resolv.conf" (si estás en Windows, se elige el servidor de nombres configurado a nivel del sistema en su lugar). En este momento, solo es posible configurar antes de que se realice la primera resolución.
ub_ctx_hosts
Lee la lista de hosts del nombre de archivo dado. Normalmente "/etc/hosts". Cuando se consultan, estas direcciones no se marcan como seguras con DNSSEC. Si se pasa NULL como fname, se usa "/etc/hosts" (si estás en Windows, se elige etc/hosts de WINDIR en su lugar). En este momento, solo es posible configurar antes de la primera resolución.
