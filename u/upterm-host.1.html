NOMBRE

upterm-host - Aloja una sesión de terminal

SINOPSIS

upterm host [flags]

DESCRIPCIÓN

Aloja una sesión de terminal a través de un túnel SSH inverso al servidor Upterm.

La sesión vincula la E/S del host y del cliente a la E/S de un comando. La autenticación con el servidor Upterm utiliza claves privadas en este orden:
1. Archivos de clave privada: ~/.ssh/id_dsa, ~/.ssh/id_ecdsa, ~/.ssh/id_ed25519, ~/.ssh/id_rsa
2. Claves del Agente SSH
3. Clave efímera generada automáticamente (si no se encuentran claves)

Para autorizar conexiones de clientes, use --authorized-keys para especificar un archivo authorized_keys que contenga las claves públicas del cliente.

OPCIONES

--accept[=false] Acepta automáticamente las conexiones de clientes sin solicitar confirmación.

--authorized-keys="" Especifica un archivo authorized_keys que enumera las claves públicas autorizadas para la conexión.

--codeberg-user=[] Autoriza a usuarios de Codeberg especificados permitiendo la conexión de sus claves públicas.

-f, --force-command="" Fuerza un comando especificado para que los clientes se unan, y vincula la entrada/salida del comando al terminal del cliente.

--github-user=[] Autoriza a usuarios de GitHub especificados permitiendo la conexión de sus claves públicas. Configure las variables de entorno de la CLI de GitHub según sea necesario; consulte https://cli.github.com/manual/gh_help_environment para obtener detalles.

--gitlab-user=[] Autoriza a usuarios de GitLab especificados permitiendo la conexión de sus claves públicas.

-h, --help[=false] Ayuda para host

--hide-client-ip[=false] Oculta las direcciones IP de los clientes en la salida (activado automáticamente en entornos de CI).

--known-hosts="/build/.ssh/known_hosts" Especifica un archivo que contiene las claves conocidas para hosts remotos (requerido).

-i, --private-key=[] Especifica archivos de clave privada para la autenticación de clave pública con el servidor upterm (requerido).

-r, --read-only[=false] Aloja una sesión de solo lectura, impidiendo la interacción del cliente.

--server="ssh://uptermd.upterm.dev:22" Especifica la dirección del servidor upterm (requerido). Protocolos admitidos: ssh, ws, wss.

--skip-host-key-check[=false] Acepta automáticamente las claves de host desconocidas del servidor y las añade a known_hosts (similar a StrictHostKeyChecking=accept-new de SSH). Esto omite la verificación de la clave del host para nuevas conexiones.

--srht-user=[] Autoriza a usuarios de SourceHut especificados permitiendo la conexión de sus claves públicas.

OPCIONES HEREDADAS DE COMANDOS PADRE

--debug[=false] activa el registro de nivel de depuración (archivo de registro: /build/.upterm/upterm.log).

EJEMPLO

  # Aloja una sesión de terminal que ejecuta $SHELL, adjuntando la E/S del cliente a la del host:
  upterm host
  # Acepta conexiones de clientes automáticamente sin solicitar confirmación:
  upterm host --accept
  # Aloja una sesión de terminal permitiendo que solo las claves públicas especificadas se conecten:
  upterm host --authorized-keys RUTA_AL_ARCHIVO_DE_CLAVES_AUTORIZADAS
  # Aloja una sesión ejecutando un comando personalizado:
  upterm host -- docker run --rm -ti ubuntu bash
  # Aloja una sesión 'tmux new -t pair-programming', forzando a los clientes a unirse con 'tmux attach -t pair-programming':
  upterm host --force-command 'tmux attach -t pair-programming' -- tmux new -t pair-programming
  # Utiliza un servidor Uptermd diferente, alojando una sesión a través de WebSocket:
  upterm host --server wss://TU_SERVIDOR_UPTERMD -- TU_COMANDO
