random(4) Manual de Controladores de Dispositivos random(4)

NOMBRE

random, urandom - dispositivos de fuente de números aleatorios del kernel

SINOPSIS

#include <linux/random.h>
int ioctl(fd, RNDrequest, param);

DESCRIPCIÓN

Los archivos especiales de caracteres /dev/random y /dev/urandom (presentes desde Linux 1.3.30) proporcionan una interfaz al generador de números aleatorios del kernel. El archivo /dev/random tiene el número de dispositivo mayor 1 y el número de dispositivo menor 8. El archivo /dev/urandom tiene el número de dispositivo mayor 1 y el número de dispositivo menor 9.

El generador de números aleatorios recopila ruido ambiental de los controladores de dispositivos y otras fuentes en una piscina de entropía. El generador también mantiene una estimación del número de bits de ruido en la piscina de entropía. A partir de esta piscina de entropía, se crean números aleatorios.

Linux 3.17 y posteriores proporcionan la interfaz getrandom(2), más simple y segura, que no requiere archivos especiales; consulte la página del manual de getrandom(2) para obtener detalles.

Cuando se lee, el dispositivo /dev/urandom devuelve bytes aleatorios utilizando un generador de números pseudoaleatorios sembrado a partir de la piscina de entropía. Las lecturas de este dispositivo no se bloquean (es decir, no se cede la CPU), pero pueden incurrir en un retraso considerable al solicitar grandes cantidades de datos.

Cuando se lee durante el tiempo de arranque temprano, /dev/urandom puede devolver datos antes de que la piscina de entropía se inicialice. Si esto es una preocupación en su aplicación, utilice getrandom(2) o /dev/random en su lugar.

El dispositivo /dev/random es una interfaz heredada que data de una época en la que las primitivas criptográficas utilizadas en la implementación de /dev/urandom no eran ampliamente confiables. Devolverá bytes aleatorios solo dentro del número estimado de bits de ruido fresco en la piscina de entropía, bloqueándose si es necesario. /dev/random es adecuado para aplicaciones que necesitan aleatoriedad de alta calidad y pueden permitirse retrasos indeterminados.

Cuando la piscina de entropía está vacía, las lecturas de /dev/random se bloquearán hasta que se recopile ruido ambiental adicional. Desde Linux 5.6, la bandera O_NONBLOCK se ignora ya que /dev/random ya no se bloqueará excepto durante el proceso de arranque temprano. En versiones anteriores, si se llama a open(2) para /dev/random con la bandera O_NONBLOCK, una llamada posterior a read(2) no se bloqueará si no está disponible el número solicitado de bytes. En su lugar, se devuelven los bytes disponibles. Si no hay ningún byte disponible, read(2) devolverá -1 y errno se establecerá en EAGAIN.

La bandera O_NONBLOCK no tiene ningún efecto al abrir /dev/urandom. Al llamar a read(2) para el dispositivo /dev/urandom, las lecturas de hasta 256 bytes devolverán tantos bytes como se soliciten y no serán interrumpidas por un manejador de señales. Las lecturas con un búfer por encima de este límite pueden devolver menos bytes que los solicitados o fallar con el error EINTR, si son interrumpidas por un manejador de señales.

Desde Linux 3.16, una lectura read(2) de /dev/urandom devolverá como máximo 32 MiB. Una lectura read(2) de /dev/random devolverá como máximo 512 bytes (340 bytes antes de Linux 2.6.12).

Escribir en /dev/random o /dev/urandom actualizará la piscina de entropía con los datos escritos, pero esto no dará como resultado un recuento de entropía más alto. Esto significa que afectará al contenido leído de ambos archivos, pero no hará que las lecturas de /dev/random sean más rápidas.

Uso

La interfaz /dev/random se considera una interfaz heredada, y /dev/urandom se prefiere y es suficiente en todos los casos de uso, con la excepción de las aplicaciones que requieren aleatoriedad durante el tiempo de arranque temprano; para estas aplicaciones, se debe usar getrandom(2) en su lugar, ya que se bloqueará hasta que la piscina de entropía se inicialice.

Si se guarda un archivo de semilla a través de reinicios como se recomienda a continuación, la salida es criptográficamente segura contra ataques sin acceso root local tan pronto como se recarga en la secuencia de arranque, y perfectamente adecuada para claves de sesión de cifrado de red. (Todas las principales distribuciones de Linux han guardado el archivo de semilla a través de reinicios desde al menos el año 2000). Dado que las lecturas de /dev/random pueden bloquearse, los usuarios normalmente querrán abrirlo en modo no bloqueante (o realizar una lectura con tiempo de espera), y proporcionar alguna notificación al usuario si la entropía deseada no está disponible de inmediato.

Configuración

Si su sistema no tiene /dev/random y /dev/urandom creados ya, se pueden crear con los siguientes comandos:


mknod -m 666 /dev/random c 1 8
mknod -m 666 /dev/urandom c 1 9
chown root:root /dev/random /dev/urandom

Cuando un sistema Linux se inicia sin mucha interacción del operador, la piscina de entropía puede estar en un estado bastante predecible. Esto reduce la cantidad real de ruido en la piscina de entropía por debajo de la estimación. Para contrarrestar este efecto, es útil conservar la información de la piscina de entropía a través de apagados y arranques. Para hacer esto, agregue las siguientes líneas a un script apropiado que se ejecute durante la secuencia de arranque del sistema Linux:


echo "Inicializando generador de números aleatorios..."
random_seed=/var/run/random-seed
# Conservar una semilla aleatoria de arranque a arranque
# Cargar y luego guardar toda la piscina de entropía
if [ -f $random_seed ]; then
    cat $random_seed >/dev/urandom
else
    touch $random_seed
fi
chmod 600 $random_seed
poolfile=/proc/sys/kernel/random/poolsize
[ -r $poolfile ] && bits=$(cat $poolfile) || bits=4096
bytes=$(expr $bits / 8)
dd if=/dev/urandom of=$random_seed count=1 bs=$bytes

Además, agregue las siguientes líneas en un script apropiado que se ejecute durante el apagado del sistema Linux:


# Conservar una semilla aleatoria de apagado a arranque
# Guardar toda la piscina de entropía
echo "Guardando semilla aleatoria..."
random_seed=/var/run/random-seed
touch $random_seed
chmod 600 $random_seed
poolfile=/proc/sys/kernel/random/poolsize
[ -r $poolfile ] && bits=$(cat $poolfile) || bits=4096
bytes=$(expr $bits / 8)
dd if=/dev/urandom of=$random_seed count=1 bs=$bytes

En los ejemplos anteriores, asumimos Linux 2.6.0 o posterior, donde /proc/sys/kernel/random/poolsize devuelve el tamaño de la piscina de entropía en bits (ver más abajo).

interfaces de /proc

Los archivos en el directorio /proc/sys/kernel/random (presentes desde Linux 2.3.16) proporcionan información adicional sobre el dispositivo /dev/random:

entropy_avail
Este archivo de solo lectura proporciona la entropía disponible, en bits. Será un número en el rango de 0 a 4096.
poolsize
Este archivo proporciona el tamaño de la piscina de entropía. La semántica de este archivo varía según las versiones del kernel:
Linux 2.4:
Este archivo proporciona el tamaño de la piscina de entropía en bytes. Normalmente, este archivo tendrá el valor 512, pero es escribible y se puede cambiar a cualquier valor para el cual haya un algoritmo disponible. Las opciones son 32, 64, 128, 256, 512, 1024 o 2048.
Linux 2.6 y posteriores:
Este archivo es de solo lectura y proporciona el tamaño de la piscina de entropía en bits. Contiene el valor 4096.
read_wakeup_threshold
Este archivo contiene el número de bits de entropía necesarios para activar los procesos que duermen esperando entropía de /dev/random. El valor predeterminado es 64.
write_wakeup_threshold
Este archivo contiene el número de bits de entropía por debajo del cual activamos los procesos que realizan una llamada a select(2) o poll(2) para acceso de escritura a /dev/random. Estos valores se pueden cambiar escribiendo en los archivos.
uuid
boot_id
Estos archivos de solo lectura contienen cadenas aleatorias como 6fd5a44b-35f4-4ad4-a9
b9-6b9be13e1fe9. El primero se genera de nuevo en cada lectura, el último se generó una vez.

Interfaz ioctl(2)

Las siguientes solicitudes de ioctl(2) se definen en descriptores de archivo conectados a /dev/random o /dev/urandom. Todas las solicitudes realizadas interactuarán con el pool de entropía de entrada, afectando tanto a /dev/random como a /dev/urandom. Se requiere la capacidad CAP_SYS_ADMIN para todas las solicitudes excepto RNDGETENTCNT.

RNDGETENTCNT
Recupera el recuento de entropía del pool de entrada; el contenido será el mismo que el archivo entropy_avail en proc. El resultado se almacenará en el int apuntado por el argumento.
RNDADDTOENTCNT
Incrementa o decrementa el recuento de entropía del pool de entrada en el valor apuntado por el argumento.
RNDGETPOOL
Eliminado en Linux 2.6.9.
RNDADDENTROPY
Añade algo de entropía adicional al pool de entrada, incrementando el recuento de entropía. Esto difiere de escribir en /dev/random o /dev/urandom, que solo añaden algunos datos pero no incrementan el recuento de entropía. Se utiliza la siguiente estructura:

struct rand_pool_info {
    int    entropy_count;
    int    buf_size;
    __u32  buf[0];
};

Aquí entropy_count es el valor que se añade (o resta) al recuento de entropía, y buf es el buffer de tamaño buf_size que se añade al pool de entropía.
RNDZAPENTCNT
RNDCLEARPOOL
Pone a cero el recuento de entropía de todos los pools y añade algunos datos del sistema (como el reloj de pared) a los pools.

ARCHIVOS

/dev/urandom

NOTAS

Para una descripción general y comparación de las diversas interfaces que se pueden utilizar para obtener aleatoriedad, consulte random(7).

ERRORES

Durante el arranque temprano, las lecturas de /dev/urandom pueden devolver datos antes de que el pool de entropía se haya inicializado.
