upscli_init(3)

Paquete: nut

Licencias: GPL-2.0-or-later AND GPL-3.0-or-later

UPSCLI_INIT(3) Manual de NUT UPSCLI_INIT(3)

NOMBRE

upscli_init - Inicializa el módulo upsclient especificando propiedades de seguridad.

SINOPSIS

        #include <upsclient.h>
        int upscli_init(
                int certverify,
                const char *certpath,
                const char *certname,
                const char *certpasswd);

DESCRIPCIÓN

La función upscli_init() inicializa el módulo upsclient y establece muchas propiedades relacionadas con TLS/SSL: certverify a 1 hace que la verificación del certificado sea obligatoria para todas las conexiones SSL y certpath es la ubicación de la base de datos de certificados.

•Si se compila con OpenSSL, certpath se refiere al directorio que contiene los certificados donde estos deben ser nombrados según sus valores hash terminando en la extensión ".0". Si dos certificados resultan en el mismo valor hash (y por lo tanto nombre de archivo), el ".0" puede ser incrementado a ".1" y así sucesivamente, según sea necesario. El comando de shell para crear enlaces de esta manera sería: 
:; ln -s ca.pem ./$(openssl x509 -hash -noout -in ca.pem).0

Alternativamente, la utilidad c_rehash (proporcionada por, por ejemplo, el paquete openssl-perl) puede tomar un directorio e iterarlo para enlazar todos los certificados encontrados en ese directorio, de la manera descrita anteriormente.

•Si se compila con NSS, certpath se refiere a un directorio que contiene sus archivos de base de datos.

Si se compila con NSS y se usa SSL, puedes especificar certname con el nombre del certificado a enviar a upsd, y certpasswd con la contraseña utilizada para descifrar la clave privada del certificado.

Si se compila con NSS, normalmente registraría el infame mensaje "Init SSL without certificate database" si no se proporcionó certpath, o "Init SSL with certificate database located at %s" en caso contrario. Dado que algunos consumidores programáticos se confunden con texto adicional en la salida de error estándar de las herramientas que llaman (como los sistemas de monitoreo que realizan consultas upsc), puedes exportar la variable de entorno NUT_QUIET_INIT_SSL con los valores de cadena "true", "TRUE" o "1", para evitar registrar estos mensajes y emitirlos solo como flujo de depuración (con verbosidad 1 o superior).

Como parte de la inicialización general, la función upscli_init() puede llamar al método upscli_init_default_connect_timeout(3) (si nunca se usó antes): esto permite que los clientes NUT no modificados (legados) se beneficien consistentemente de la presencia de la variable de entorno NUT_DEFAULT_CONNECT_TIMEOUT para que los intentos de upscli_connect(3) no sean bloqueantes (por defecto).

Puedes llamar a upscli_add_host_cert(3) para registrar una política de seguridad específica del host antes de inicializar las conexiones a ellos.

Debes llamar a upscli_cleanup(3) al salir de la aplicación.

VALOR DE RETORNO

La función upscli_init() devuelve 1 si tiene éxito, o -1 si ocurre un error.
