DESCRIPCIÓN

Un Identificador Uniforme de Recurso (URI) es una cadena corta de caracteres que identifica un recurso abstracto o físico (por ejemplo, una página web). Un Localizador Uniforme de Recurso (URL) es un URI que identifica un recurso a través de su mecanismo de acceso primario (por ejemplo, su "ubicación" en la red), en lugar de por su nombre o algún otro atributo de dicho recurso. Un Nombre Uniforme de Recurso (URN) es un URI que debe permanecer globalmente único y persistente incluso cuando el recurso deje de existir o se vuelva inaccesible.

Los URI son la forma estándar de nombrar destinos de enlaces de hipertexto para herramientas como los navegadores web. La cadena "http://www.kernel.org" es una URL (y por lo tanto también es un URI). Muchas personas usan el término URL de forma imprecisa como sinónimo de URI (aunque técnicamente las URLs son un subconjunto de los URI).

Los URI pueden ser absolutos o relativos. Un identificador absoluto se refiere a un recurso independientemente del contexto, mientras que un identificador relativo se refiere a un recurso describiendo la diferencia con el contexto actual. Dentro de una referencia de ruta relativa, los segmentos de ruta completos "." y ".." tienen significados especiales: "el nivel jerárquico actual" y "el nivel por encima de este nivel jerárquico", respectivamente, al igual que en los sistemas tipo UNIX. Un segmento de ruta que contiene un carácter de dos puntos no puede usarse como el primer segmento de una ruta de URI relativa (por ejemplo, "this:that"), porque se confundiría con un nombre de esquema; precede a tales segmentos con ./ (por ejemplo, "./this:that"). Tenga en cuenta que los descendientes de MS-DOS (por ejemplo, Microsoft Windows) reemplazan los dos puntos del nombre del dispositivo con la barra vertical ("|") en los URI, por lo que "C:" se convierte en "C|".

Un identificador de fragmento, si se incluye, se refiere a una parte específica (fragmento) de un recurso; el texto después de un '#' identifica el fragmento. Un URI que comienza con '#' se refiere a ese fragmento en el recurso actual.

USO

Existen muchos esquemas de URI diferentes, cada uno con reglas y significados específicos adicionales, pero están diseñados intencionadamente para ser lo más similares posible. Por ejemplo, muchos esquemas de URL permiten que la autoridad tenga el siguiente formato, llamado aquí ip_server (los corchetes muestran lo que es opcional):

ip_server = [user [ : password ] @ ] host [ : port]

Este formato le permite insertar opcionalmente un nombre de usuario, un usuario más una contraseña y/o un número de puerto. El host es el nombre del ordenador host, ya sea su nombre determinado por DNS o una dirección IP (números separados por puntos). Por lo tanto, el URI http://fred:fredpassword@example.com:8080/ inicia sesión en un servidor web en el host example.com como fred (usando fredpassword) usando el puerto 8080. Evite incluir una contraseña en un URI si es posible debido a los muchos riesgos de seguridad de tener una contraseña escrita. Si la URL proporciona un nombre de usuario pero no una contraseña, y el servidor remoto solicita una contraseña, el programa que interpreta la URL debería solicitarla al usuario.

Aquí hay algunos de los esquemas más comunes en uso en sistemas tipo UNIX que son entendidos por muchas herramientas. Tenga en cuenta que muchas herramientas que usan URI también tienen esquemas internos o especializados; consulte la documentación de esas herramientas para obtener información sobre esos esquemas.

http - Servidor Web (HTTP)

http://ip_server/path
http://ip_server/path?query

Esta es una URL que accede a un servidor web (HTTP). El puerto predeterminado es 80. Si la ruta se refiere a un directorio, el servidor web elegirá qué devolver; generalmente, si hay un archivo llamado "index.html" o "index.htm", se devuelve su contenido; de lo contrario, se genera y devuelve una lista de los archivos en el directorio actual (con enlaces apropiados). Un ejemplo es http://lwn.net.

Se puede proporcionar una consulta en el formato arcaico "isindex", que consiste en una palabra o frase y no incluye un signo igual (=). Una consulta también puede estar en el formato más largo "GET", que tiene una o más entradas de consulta del tipo key=value separadas por el ampersand (&). Tenga en cuenta que key puede repetirse más de una vez, aunque depende del servidor web y sus programas de aplicación determinar si eso tiene algún significado. Existe una interacción desafortunada con HTML/XML/SGML y el formato de consulta GET; cuando tales URI con más de una clave se incrustan en documentos SGML/XML (incluyendo HTML), el ampersand (&) debe reescribirse como &amp;. Tenga en cuenta que no todas las consultas usan este formato; formularios más grandes pueden ser demasiado largos para almacenarlos como un URI, por lo que utilizan un mecanismo de interacción diferente (llamado POST) que no incluye los datos en el URI. Consulte la especificación Common Gateway Interface en http://www.w3.org/CGI para obtener más información.

ftp - Protocolo de Transferencia de Archivos (FTP)

ftp://ip_server/path

Esta es una URL que accede a un archivo a través del protocolo de transferencia de archivos (FTP). El puerto predeterminado (para control) es 21. Si no se incluye ningún nombre de usuario, se proporciona el nombre de usuario "anonymous", y en ese caso muchos clientes proporcionan como contraseña la dirección de correo electrónico de Internet del solicitante. Un ejemplo es <ftp://ftp.is.co.za/rfc/rfc1808.txt>.

gopher - Servidor Gopher

gopher://ip_server/gophertype selector
gopher://ip_server/gophertype selector%09search
gopher://ip_server/gophertype selector%09search%09gopher+_string

El puerto gopher predeterminado es 70. gophertype es un campo de un solo carácter para denotar el tipo Gopher del recurso al que se refiere la URL. Toda la ruta también puede estar vacía, en cuyo caso la barra delimitadora "/" también es opcional, y el gophertype predeterminado es "1".

selector es la cadena selectora de Gopher. En el protocolo Gopher, las cadenas selectoras de Gopher son una secuencia de octetos que pueden contener cualquier octeto excepto 09 hexadecimal (US-ASCII HT o tab), 0A hexadecimal (carácter US-ASCII LF) y 0D (carácter US-ASCII CR).

mailto - Dirección de correo electrónico

mailto:email-address

Esta es una dirección de correo electrónico, generalmente de la forma name@hostname. Consulte mailaddr(7) para obtener más información sobre el formato correcto de una dirección de correo electrónico. Tenga en cuenta que cualquier carácter % debe reescribirse como %25. Un ejemplo es <mailto:dwheeler@dwheeler.com>.

news - Grupo de noticias o mensaje de noticias

news:newsgroup-name
news:message-id

ldap://hostport/dn?attributes?scope?filter?extensions This scheme supports queries to the Lightweight Directory Access Protocol (LDAP), a protocol for querying a set of servers for hierarchically organized information (such as people and computing resources). See RFC 2255 for more information on the LDAP URL scheme. The components of this URL are: hostport the LDAP server to query, written as a hostname optionally followed by a colon and the port number. The default LDAP port is TCP port 389. If empty, the client determines which the LDAP server to use. dn the LDAP Distinguished Name, which identifies the base object of the LDAP search (see RFC 2253 section 3). attributes a comma-separated list of attributes to be returned; see RFC 2251 section 4.1.5. If omitted, all attributes should be returned. scope specifies the scope of the search, which can be one of "base" (for a base object search), "one" (for a one-level search), or "sub" (for a subtree search). If scope is omitted, "base" is assumed. filter specifies the search filter (subset of entries to return). If omitted, all entries should be returned. See RFC 2254 section 4. extensions a comma-separated list of type=value pairs, where the =value portion may be omitted for options not requiring it. An extension prefixed with a '!' is critical (must be supported to be valid), otherwise it is noncritical (optional). LDAP queries are easiest to explain by example. Here's a query that asks ldap.itd.umich.edu for information about the University of Michigan in the U.S.: ldap://ldap.itd.umich.edu/o=University%20of%20Michigan,c=US To just get its postal address attribute, request: ldap://ldap.itd.umich.edu/o=University%20of%20Michigan,c=US?postalAddress To ask a host.com at port 6666 for information about the person with common name (cn) "Babs Jensen" at University of Michigan, request: ldap://host.com:6666/o=University%20of%20Michigan,c=US??sub?(cn=Babs%20Jensen) wais - Wide Area Information Servers wais://hostport/database

Hostport is the hostname, optionally followed by a colon and port number (the default port number is 210). The first form designates a WAIS database for searching. The second form designates a particular search of the WAIS database database. The third form designates a particular document within a WAIS database to be retrieved. wtype is the WAIS designation of the type of the object, and wpath is the WAIS document-id. other schemes There are many other URI schemes. Most tools that accept URIs support a set of internal URIs (e.g., Mozilla has the about: scheme for internal information, and the GNOME help browser has the toc: scheme for various starting locations). There are many schemes that have been defined but are not as widely used at the current time (e.g., prospero). The nntp: scheme is deprecated in favor of the news: scheme. URNs are to be supported by the urn: scheme, with a hierarchical name space (e.g., urn:ietf:... would identify IETF documents); at this time, URNs are not widely implemented. The following characters are reserved, that is, they may appear in a URI but their use is limited to their reserved purpose (conflicting data must be escaped before forming the URI): ; / ? : @ & = + $ , Unreserved characters may be included in a URI. Unreserved characters include uppercase and lowercase Latin letters, decimal digits, and the following limited set of punctuation marks and symbols: - _ . ! ~ * ' ( ) All other characters must be escaped. An escaped octet is encoded as a character triplet, consisting of the percent character "%" followed by the two hexadecimal digits representing the octet code (you can use uppercase or lowercase letters for the hexadecimal digits). For example, a blank space must be escaped as "%20", a tab character as "%09", and the "&" as "%26". Because the percent "%" character always has the reserved purpose of being the escape indicator, it must be escaped as "%25". It is common practice to escape space characters as the plus symbol (+) in query text; this practice isn't uniformly defined in the relevant RFCs (which recommend %20 instead) but any tool accepting URIs with query text should be prepared for them.
