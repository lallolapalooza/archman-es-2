UMASK(1P) Manual del programador de POSIX UMASK(1P)

PRÓLOGO

Esta página del manual es parte del Manual del programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

umask — obtener o establecer la máscara de creación de modo de archivo

SINOPSIS

umask [-S] [máscara]

DESCRIPCIÓN

La utilidad umask establecerá la máscara de creación de modo de archivo del entorno de ejecución del shell actual (consulte la Sección 2.12, Entorno de ejecución del shell) al valor especificado por el operando máscara. Esta máscara afectará el valor inicial de los bits de permiso de archivo de los archivos creados posteriormente. Si se llama a umask en un subshell o en un entorno de ejecución de utilidad separado, como uno de los siguientes:

(umask 002)
nohup umask ...
find . -exec umask ... \;

no afectará la máscara de creación de modo de archivo del entorno del llamador.

Si no se especifica el operando máscara, la utilidad umask escribirá en la salida estándar el valor de la máscara de creación de modo de archivo del proceso invocador.

OPCIONES

La utilidad umask cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidades.

Se admitirá la siguiente opción:

-S
Producir salida simbólica.

El estilo de salida predeterminado no está especificado, pero será reconocido en una invocación posterior de umask en el mismo sistema como un operando máscara para restaurar la máscara de creación de modo de archivo anterior.

OPERANDOS

Se admitirá el siguiente operando:

máscara
Una cadena que especifica la nueva máscara de creación de modo de archivo. La cadena se trata de la misma manera que el operando modo descrito en la sección DESCRIPCIÓN EXTENDIDA para chmod.

Para un valor modo_simbólico, el nuevo valor de la máscara de creación de modo de archivo será el complemento lógico de la parte de los bits de permiso de archivo del modo de archivo especificado por la cadena modo_simbólico.

En un valor modo_simbólico, los caracteres de operación de permisos '+' y '-' se interpretarán en relación con la máscara actual de creación de modo de archivo; '+' provocará que se borren los bits de los permisos indicados en la máscara; '-' provocará que se establezcan los bits de los permisos indicados en la máscara.

La interpretación de los valores de modo que especifican bits de modo de archivo distintos de los bits de permiso de archivo no está especificada.

En la forma de entero octal de modo, los bits especificados se establecen en la máscara de creación de modo de archivo.

La máscara de creación de modo de archivo se establecerá en el valor numérico resultante.

La salida predeterminada de una invocación anterior de umask en el mismo sistema sin operando también se reconocerá como un operando máscara.

ENTRADA ESTÁNDAR

No se utiliza.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de umask:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en comparación con caracteres multibyte en argumentos).
LC_MESSAGES

Determinar la localización que se debe utilizar para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTÁNDAR

Cuando no se especifica el operando máscara, la utilidad umask escribirá un mensaje en la salida estándar que posteriormente podrá utilizarse como un operando máscara de umask.

Si se especifica -S, el mensaje tendrá el siguiente formato:

"u=%s,g=%s,o=%s\n", <permisos del propietario>, <permisos del grupo>,
    <permisos de otros>

donde los tres valores serán combinaciones de letras del conjunto {r, w, x}; la presencia de una letra indicará que el bit correspondiente está borrado en la máscara de creación de modo de archivo.

Si se especifica un operando máscara, no se escribirá ninguna salida en la salida estándar.

ERROR ESTÁNDAR

El error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
La máscara de creación de modo de archivo se cambió correctamente, o no se suministró ningún operando máscara.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO DE APLICACIÓN

Dado que umask afecta al entorno de ejecución del shell actual, generalmente se proporciona como una rutina interna regular del shell.

En contraste con la lógica de permisos negativa proporcionada por la máscara de creación de modo de archivo y la forma de número octal del argumento máscara, la forma simbólica del argumento máscara especifica los permisos que se dejan intactos.

EJEMPLOS

Cualquiera de los comandos:

umask a=rx,ug+w
umask 002

establece la máscara de modo para que los archivos creados posteriormente tengan su bit S_IWOTH borrado.

Después de establecer la máscara de modo con cualquiera de los comandos anteriores, el comando umask se puede usar para mostrar el valor actual de la máscara de modo:

$ umask
0002

(El formato de salida no está especificado, pero las implementaciones históricas utilizan el formato de modo de entero octal).

$ umask -S
u=rwx,g=rwx,o=rx

Cualquiera de estas salidas puede usarse como operando máscara para una invocación posterior de la utilidad umask.

Asumiendo que la máscara de modo se establece como se indicó anteriormente, el comando:

umask g-w

establece el modo

PROLOG

Este documento describe la sintaxis y semántica del comando `umask` tal como se especifica en el Estándar de POSIX.1-2017. Las discrepancias entre el estándar y esta página de manual se abordarán en notas.

NOMBRE

umask - obtener o establecer la máscara de modo de creación de archivos

SINOPSIS

umask [-S] [mode]

umask -- -r -w -x

DESCRIPCIÓN

La máscara de modo de creación de archivos de un proceso afecta a los bits de permisos establecidos cuando se crea un archivo nuevo. El comportamiento de `umask` es determinar o establecer esta máscara.

Si se invoca sin argumentos, `umask` escribirá la máscara de modo de creación de archivos actual en la salida estándar en formato octal. Si se invoca con el argumento -S, `umask` escribirá la máscara de modo de creación de archivos actual en la salida estándar en formato simbólico.

Si se invoca con un argumento mode, `umask` establecerá la máscara de modo de creación de archivos del proceso actual a partir de la mode especificada.

El argumento mode debe ser un modo octal o un modo simbólico.

El modo octal se describe en `chmod`.

El modo simbólico se describe en `chmod`.

Si se especifica un modo simbólico, se aplicará a la máscara de modo de creación actual de la misma manera que el modo simbólico especificado se aplica a los permisos de un archivo (como se describe en `chmod`), excepto que el efecto de las operaciones + y - se invierte.

Es decir, umask -w elimina los permisos de escritura para el propietario, el grupo y otros, mientras que umask +w agrega bits de permisos de escritura, que solo pueden ser eliminados por operaciones posteriores.

Los modos simbólicos que establecen los permisos de usuario, grupo u otros (por ejemplo, u=rwx, g=rx, o=rx) establecen la máscara de modo de creación correspondiente a los bits indicados, que luego se borran de la máscara de modo de creación. El uso de a=rwx establecería la máscara de modo de creación a 000.

El resultado de la operación de modo simbólico en la máscara de modo de creación es que los bits correspondientes a los permisos solicitados se eliminan de la máscara de modo de creación. Por ejemplo, el comando:

umask g+w

establece la máscara de modo de creación para que los archivos creados posteriormente tengan los bits S_IWGRP borrados. El comando:

umask a-w

establece la máscara de modo de creación para que los archivos creados posteriormente tengan los bits S_IWGRP y S_IWOTH borrados.

El comando:

umask -- -w

establece la máscara de modo para que los archivos creados posteriormente tengan todos sus bits de escritura borrados. Tenga en cuenta que los operandos de máscara -r, -w, -x o cualquier cosa que comience con un guion-menos, debe ir precedida por "--" para evitar que se interprete como una opción.

RATIONALE

Dado que `umask` afecta al entorno de ejecución del shell actual, generalmente se proporciona como un shell regular incorporado. Si se llama en un subshell o en un entorno de ejecución de utilidad separado, como uno de los siguientes:

(umask 002)
nohup umask ...
find . -exec umask ... \;

no afecta a la máscara de creación de modo del entorno del llamante.

La descripción de la utilidad histórica se modificó para permitirle utilizar los modos simbólicos de `chmod`. La opción -s utilizada en las primeras propuestas se cambió a -S porque -s podría confundirse con una forma modo_simbólico de máscara que se refiere a los bits S_ISUID y S_ISGID.

El estilo de salida predeterminado no se especifica para permitir a los implementadores proporcionar migración al nuevo estilo simbólico en el momento más apropiado para sus usuarios. Se omitió un indicador -o para forzar la salida en modo octal porque el modo octal puede no ser suficiente para especificar toda la información que puede estar presente en la máscara de modo de creación de archivos cuando se implementan verificaciones de permisos de acceso a archivos más seguras.

Se ha sugerido que los desarrolladores de sistemas de confianza podrían apreciar la mitigación del requisito de que la máscara de modo "afecte" a los permisos de acceso a archivos, ya que parece que las listas de control de acceso podrían reemplazar la máscara de modo en cierta medida. La redacción se ha modificado para indicar que afecta a los bits de permisos de archivo y deja los detalles del comportamiento de cómo afectan a los permisos de acceso a archivos a la descripción en el volumen System Interfaces de POSIX.1-2017.
