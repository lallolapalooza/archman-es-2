UTIME(3P) Manual del Programador POSIX UTIME(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

utime — establecer tiempos de acceso y modificación de archivo

SINOPSIS

#include <utime.h>
int utime(const char *path, const struct utimbuf *times);

DESCRIPCIÓN

La función utime() establecerá los tiempos de acceso y modificación del archivo denominado por el argumento path.

Si times es un puntero nulo, los tiempos de acceso y modificación del archivo se establecerán a la hora actual. El ID de usuario efectivo del proceso deberá coincidir con el propietario del archivo, o el proceso tendrá permiso de escritura sobre el archivo o tendrá los privilegios adecuados para usar utime() de esta manera.

Si times no es un puntero nulo, times se interpretarán como un puntero a una estructura utimbuf y los tiempos de acceso y modificación se establecerán a los valores contenidos en la estructura designada. Solo un proceso con el ID de usuario efectivo igual al ID de usuario del archivo o un proceso con privilegios adecuados puede usar utime() de esta forma.

La estructura utimbuf se define en la cabecera <utime.h>. Los tiempos en la estructura utimbuf se miden en segundos desde la Época.

Tras una finalización exitosa, la función utime() marcará la marca de tiempo del último cambio de estado del archivo para su actualización; consulte <sys/stat.h>.

VALOR DE RETORNO

Tras una finalización exitosa, se devolverá 0. De lo contrario, se devolverá -1 y se establecerá errno para indicar el error, y los tiempos del archivo no se verán afectados.

ERRORES

La función utime() fallará si:

EACCES
Se deniega el permiso de búsqueda por un componente del prefijo de ruta; o el argumento times es un puntero nulo y el ID de usuario efectivo del proceso no coincide con el propietario del archivo, el proceso no tiene permiso de escritura para el archivo y el proceso no tiene privilegios adecuados.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un componente de un nombre de ruta es mayor que {NAME_MAX}.
ENOENT
Un componente de path no nombra un archivo existente o path es una cadena vacía.
ENOTDIR
Un componente del prefijo de ruta nombra un archivo existente que no es un directorio ni un enlace simbólico a un directorio, o el argumento path contiene al menos un carácter que no es <barra> y termina con uno o más caracteres de <barra> finales y el último componente del nombre de ruta nombra un archivo existente que no es un directorio ni un enlace simbólico a un directorio.
EPERM
El argumento times no es un puntero nulo y el ID de usuario efectivo del proceso de llamada no coincide con el propietario del archivo y el proceso de llamada no tiene privilegios adecuados.
EROFS
El sistema de archivos que contiene el archivo es de solo lectura.

La función utime() puede fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un nombre de ruta excede {PATH_MAX}, o la resolución de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.

Las siguientes secciones son informativas.

EJEMPLOS

Ninguno.

USO EN LA APLICACIÓN

Dado que la estructura utimbuf solo contiene variables time_t y no es precisa a fracciones de segundo, las aplicaciones deben utilizar la función utimensat() en lugar de la función obsoleta utime().

FUNDAMENTO

El miembro de la estructura actime debe estar presente para que una aplicación pueda establecerlo, aunque una implementación pueda ignorar esta parte y no cambiar la marca de tiempo del último acceso a datos del archivo. Si una aplicación pretende dejar uno de los tiempos de un archivo sin cambios mientras cambia el otro, debe usar stat() o fstat() para recuperar los parámetros st_atim y st_mtim del archivo, establecer actime y modtime en el búfer y cambiar uno de ellos antes de realizar la llamada a utime().

DIRECCIONES FUTURAS

La función utime() puede ser eliminada en una versión futura.
