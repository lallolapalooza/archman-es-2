NOMBRE

urxvtd - demonio de terminal urxvt

SINOPSIS

urxvtd [-q|--quiet] [-o|--opendisplay] [-f|--fork] [-m|--mlock] [-e|--eval cadena_perl]

urxvtd -q -o -f # para uso en .xsession

DESCRIPCIÓN

Esta página del manual describe el demonio urxvtd, que es el mismo emulador de terminal vt102 que urxvt, pero se ejecuta como un demonio que puede abrir múltiples ventanas de terminal dentro del mismo proceso.

Puedes ejecutarlo desde tus scripts de inicio de X, por ejemplo, aunque no depende de que DISPLAY funcione y, de hecho, puede abrir ventanas en múltiples pantallas X al mismo tiempo.

Las ventajas de ejecutar un demonio urxvt incluyen un tiempo de creación más rápido para las ventanas de terminal y un gran ahorro de memoria.

La desventaja es un posible impacto en la estabilidad: si el programa principal falla, todos los procesos en las ventanas del terminal se terminan. Por ejemplo, como no hay forma de reaccionar limpiamente a los cierres de conexión anormales, "xkill" y los restablecimientos/reinicios del servidor matarán la instancia de urxvtd, incluidas todas las ventanas que haya abierto.

OPCIONES

urxvtd actualmente solo entiende unas pocas opciones. La agrupación de opciones aún no es compatible.

-q, --quiet
Normalmente, urxvtd muestra el mensaje "rxvt-unicode daemon listening on <path>" después de enlazarse a su socket de control. Esta opción suprimirá este mensaje (los errores y advertencias seguirán registrándose).
-o, --opendisplay
Esto fuerza a urxvtd a abrir una conexión a la $DISPLAY actual y mantenerla abierta.

Esto es útil si desea vincular una instancia de urxvtd a la vida útil de un servidor/pantalla específico. Si el servidor se reinicia, urxvtd se matará automáticamente.

-f, --fork
Esto hace que urxvtd se bifurque después de haberse enlazado a su socket de control.
-m, --mlock
Esto hace que urxvtd llame a mlockall(2) sobre sí mismo. Esto bloquea urxvtd en la RAM y evita que sea intercambiado a disco, a costa de consumir mucha más memoria en la mayoría de los sistemas operativos.

Nota: Para usar esta función, su administrador del sistema debe haber configurado el RLIMIT_MEMLOCK de su usuario a un tamaño mayor o igual al tamaño del binario de urxvtd (o ilimitado). Consulte /etc/security/limits.conf.

Nota 2: Existe un error conocido en glibc (posiblemente corregido en las versiones 2.8 y posteriores) donde calloc devuelve memoria no inicializada cuando mlockall está en efecto. Si experimenta bloqueos u otros comportamientos extraños al usar --mlock, pruébelo sin él.

-e, --eval cadena_perl
Evalúa el código perl dado después de la inicialización básica (requiere que la compatibilidad con perl esté habilitada al compilar urxvtd).

Esto se puede usar, por ejemplo, para configurar el intérprete perl interno, que se comparte entre todas las instancias de terminal, o para crear sockets de escucha adicionales para protocolos adicionales.

El código se ejecuta actualmente *antes* de crear los sockets de escucha normales: esto puede cambiar en versiones futuras.

EJEMPLOS

Esta es una invocación útil de urxvtd en un script estilo .xsession:

urxvtd -q -f -o

Esto espera hasta que el socket de control esté disponible, abre la pantalla actual y se bifurca en segundo plano. Cuando cierras sesión, el servidor se reinicia y urxvtd se mata.

ENTORNO

RXVT_SOCKET
Tanto urxvtc como urxvtd usan la variable de entorno RXVT_SOCKET para crear un socket de escucha y para contactar con urxvtd, respectivamente. Si falta la variable, se usa $HOME/.urxvt/urxvtd-<nombre_nodo>.
LISTEN_PID, LISTEN_FDS, LISTEN_FDNAMES
si estas variables de entorno están configuradas, urxvtd comprueba un descriptor de archivo pasado por el gestor de servicios a través de la interfaz nativa de systemd. Si se proporciona uno, urxvtd lo utiliza como su socket de escucha en lugar de crear uno como se especifica anteriormente.
DISPLAY
Solo se usa cuando se especifica la opción "--opendisplay". Debe contener un nombre de pantalla X válido.
