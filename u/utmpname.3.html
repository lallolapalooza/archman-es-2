getutent(3) Manual de funciones de biblioteca getutent(3)

NOMBRE

getutent, getutid, getutline, pututline, setutent, endutent, utmpname - acceder a las entradas del archivo utmp

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <utmp.h>
struct utmp *getutent(void);
struct utmp *getutid(const struct utmp *ut);
struct utmp *getutline(const struct utmp *ut);
struct utmp *pututline(const struct utmp *ut);
void setutent(void);
void endutent(void);
int utmpname(const char *path);

DESCRIPCIÓN

Las aplicaciones nuevas deben usar las versiones de estas funciones "utmpx" especificadas por POSIX.1; ver ESTÁNDARES.

utmpname() establece la ruta del archivo en formato utmp para que las otras funciones utmp accedan. Si no se utiliza utmpname() para establecer la ruta antes de utilizar las otras funciones, estas asumen _PATH_UTMP, tal como se define en <paths.h>.

setutent() rebobina el puntero del archivo al principio del archivo utmp. Generalmente, es una buena idea llamarla antes que cualquiera de las otras funciones.

endutent() cierra el archivo utmp. Debería llamarse cuando el código del usuario haya terminado de acceder al archivo con las otras funciones.

getutent() lee una línea desde la posición actual del archivo en el archivo utmp. Devuelve un puntero a una estructura que contiene los campos de la línea. La definición de esta estructura se muestra en utmp(5).

getutid() busca hacia adelante desde la posición actual del archivo en el archivo utmp basándose en ut. Si ut->ut_type es uno de RUN_LVL, BOOT_TIME, NEW_TIME, o OLD_TIME, getutid() encontrará la primera entrada cuyo campo ut_type coincida con ut->ut_type. Si ut->ut_type es uno de INIT_PROCESS, LOGIN_PROCESS, USER_PROCESS, o DEAD_PROCESS, getutid() encontrará la primera entrada cuyo campo ut_id coincida con ut->ut_id.

getutline() busca hacia adelante desde la posición actual del archivo en el archivo utmp. Escanea las entradas cuyo ut_type es USER_PROCESS o LOGIN_PROCESS y devuelve la primera cuyo campo ut_line coincida con ut->ut_line.

pututline() escribe la estructura utmp ut en el archivo utmp. Utiliza getutid() para buscar el lugar adecuado en el archivo para insertar la nueva entrada. Si no puede encontrar una ranura adecuada para ut, pututline() añadirá la nueva entrada al final del archivo.

VALOR DE RETORNO

getutent(), getutid() y getutline() devuelven un puntero a una struct utmp en caso de éxito, y NULL en caso de fallo (lo que incluye el caso de "registro no encontrado"). Esta struct utmp se asigna en almacenamiento estático y puede ser sobrescrita por llamadas posteriores.

En caso de éxito, pututline() devuelve ut; en caso de fallo, devuelve NULL.

utmpname() devuelve 0 si el nuevo nombre se almacenó correctamente, o -1 en caso de fallo.

En caso de fallo, estas funciones establecen errno para indicar el error.

ERRORES

ENOMEM
Sin memoria.
ESRCH
Registro no encontrado.

setutent(), pututline() y las funciones getut*() también pueden fallar por las razones descritas en open(2).

ARCHIVOS

/var/run/utmp
base de datos de usuarios conectados actualmente
/var/log/wtmp
base de datos de inicios de sesión de usuarios anteriores

ATRIBUTOS

Para obtener una explicación de los términos utilizados en esta sección, consulte attributes(7).

Interfaz Atributo Valor
getutent () Seguridad de hilos MT-Unsafe init race:utent race:utentbuf sig:ALRM timer
getutid (), getutline () Seguridad de hilos MT-Unsafe init race:utent sig:ALRM timer
pututline () Seguridad de hilos MT-Unsafe race:utent sig:ALRM timer
setutent (), endutent (), utmpname () Seguridad de hilos MT-Unsafe race:utent

En la tabla anterior, utent en race:utent significa que si alguna de las funciones setutent(), getutent(), getutid(), getutline(), pututline(), utmpname(), o endutent() se utilizan en paralelo en diferentes hilos de un programa, podrían producirse condiciones de carrera de datos.

ESTÁNDARES

Ninguno.

HISTORIA

XPG2, SVr4.

En XPG2 y SVID 2, la función pututline() se documenta como void, y eso es lo que hace en muchos sistemas (AIX, HP-UX). HP-UX introduce una nueva función _pututline() con el prototipo dado arriba para pututline().

Todas estas funciones están obsoletas ahora en sistemas no Linux. POSIX.1-2001 y POSIX.1-2008, siguiendo SUSv1, no tienen ninguna de estas funciones, sino que utilizan

#include <utmpx.h>
struct utmpx *getutxent(void);
struct utmpx *getutxid(const struct utmpx *);
struct utmpx *getutxline(const struct utmpx *);
struct utmpx *pututxline(const struct utmpx *);
void setutxent(void);
void endutxent(void);

Estas funciones son proporcionadas por glibc, y realizan la misma tarea que sus equivalentes sin la "x", pero utilizan struct utmpx, definida en Linux como igual a struct utmp. Para mayor exhaustividad, glibc también proporciona utmpxname(), aunque esta función no está especificada por POSIX.1.

En algunos otros sistemas, la estructura utmpx es un superconjunto de la estructura utmp, con campos adicionales y versiones más grandes de los campos existentes, y se mantienen archivos paralelos, a menudo /var/*/utmpx y /var/*/wtmpx.

Linux glibc, por otro lado, no utiliza un archivo utmpx paralelo ya que su estructura utmp es lo suficientemente grande. Las funciones "x" enumeradas anteriormente son solo alias para sus contrapartes sin la "x" (por ejemplo, getutxent() es un alias para getutent()).

NOTAS

Notas de glibc

Las funciones anteriores no son seguras para hilos. glibc añade versiones reentrantes

#include <utmp.h>
int getutent_r(struct utmp *ubuf, struct utmp **ubufp);
int getutid_r(struct utmp *ut,
              struct utmp *ubuf, struct utmp **ubufp);
int getutline_r(struct utmp *ut,
                struct utmp *ubuf, struct utmp **ubufp);

Requisitos de Macro de Prueba de Características para glibc (ver feature_test_macros(7)):

getutent_r(), getutid_r(), getutline_r():

    _GNU_SOURCE
        || /* Desde glibc 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */    _SVID_SOURCE || _BSD_SOURCE

Estas funciones son extensiones de GNU, análogas a las funciones con el mismo nombre sin el sufijo _r. El argumento ubuf proporciona a estas funciones un lugar para almacenar su resultado. En caso de éxito, devuelven 0 y se escribe un puntero al resultado en *ubufp. En caso de error, estas funciones devuelven -1. No hay equivalentes utmpx de las funciones anteriores. (POSIX.1 no especifica tales funciones).

EJEMPLOS

Th

El siguiente ejemplo agrega y elimina un registro de utmp, asumiendo que se ejecuta desde dentro de una terminal pseudo. Para su uso en una aplicación real, debería verificar los valores de retorno de getpwuid(3) y ttyname(3).

#include <err.h>
#include <pwd.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>
#include <utmp.h>
int
main(void)
{
    struct utmp entry;
    if (system("echo before adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = USER_PROCESS;
    entry.ut_pid = getpid();
    strcpy(entry.ut_line, ttyname(STDIN_FILENO) + strlen("/dev/"));
    /* only correct for ptys named /dev/tty[pqr][0-9a-z] */
    strcpy(entry.ut_id, ttyname(STDIN_FILENO) + strlen("/dev/tty"));
    entry.ut_time = time(NULL);
    strcpy(entry.ut_user, getpwuid(getuid())->pw_name);
    memset(entry.ut_host, 0, UT_HOSTSIZE);
    entry.ut_addr = 0;
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after adding entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    entry.ut_type = DEAD_PROCESS;
    memset(entry.ut_line, 0, UT_LINESIZE);
    entry.ut_time = 0;
    memset(entry.ut_user, 0, UT_NAMESIZE);
    setutent();
    if (pututline(&entry) == NULL)
        err(EXIT_FAILURE, "pututline");
    if (system("echo after removing entry:;who") == -1)
        err(EXIT_FAILURE, "system");
    endutent();
    exit(EXIT_SUCCESS);
}
