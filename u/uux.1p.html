UUX(1P) Manual del programador POSIX UUX(1P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

uux — ejecución remota de comandos

SINOPSIS

uux [-jnp] cadena-comando

DESCRIPCIÓN

La utilidad uux recopilará cero o más archivos de varios sistemas, ejecutará una tubería de shell (consulte la Sección 2.9, Comandos de Shell) en un sistema especificado y luego enviará la salida estándar del comando a un archivo en un sistema especificado. Solo el primer comando de una tubería puede tener el prefijo nombre-sistema!. Todos los demás comandos de la tubería se ejecutarán en el sistema del primer comando.

Las siguientes restricciones se aplican a la tubería de shell procesada por uux:

*
Al recopilar archivos de diferentes sistemas, la expansión de nombres de ruta no será realizada por uux. Por lo tanto, una solicitud como:
uux "c99 remsys!~/*.c"

Intentaría copiar el archivo llamado literalmente *.c al sistema local.

*
Los operadores de redirección ">>", "<<", ">|" y ">&" no serán aceptados. Cualquier uso de estos operadores de redirección provocará que esta utilidad escriba un mensaje de error que describa el problema y salga con un estado de salida distinto de cero.
*
La palabra reservada ! no se puede usar al principio de la tubería para modificar el estado de salida. (Consulte la descripción del operando cadena-comando a continuación).
*
La sustitución de alias no se realizará.

Un nombre de archivo puede especificarse como para uucp; puede ser una ruta absoluta, una ruta precedida por ~nombre (que se reemplaza por el directorio de inicio correspondiente), una ruta especificada como ~/destino (a destino se le antepone el directorio público llamado PUBDIR; la ubicación real de PUBDIR no está definida por la implementación), o un nombre de archivo simple (al que uux antepone el directorio actual). Consulte uucp para obtener más detalles.

La ejecución de comandos en sistemas remotos se llevará a cabo en un directorio de ejecución conocido por el sistema uucp. Todos los archivos requeridos para la ejecución se colocarán en este directorio a menos que ya residan en esa máquina. Por lo tanto, la aplicación garantizará que los nombres de archivo no locales (sin referencia de ruta o máquina) sean únicos dentro de la solicitud uux.

La utilidad uux intentará obtener todos los archivos en el sistema de ejecución. Para los archivos que son archivos de salida, la aplicación asegurará que el nombre del archivo se escape utilizando paréntesis.

El sistema remoto notificará al usuario por correo si el comando solicitado en el sistema remoto fue desautorizado o si los archivos no eran accesibles. Esta notificación se puede desactivar con la opción -n.

Las implementaciones típicas de esta utilidad requieren una línea de comunicación configurada para usar el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 11, Interfaz de Terminal General, pero se pueden utilizar otros medios de comunicación. En sistemas donde no hay medios de comunicación disponibles (temporal o permanentemente), esta utilidad escribirá un mensaje de error que describa el problema y saldrá con un estado de salida distinto de cero.

La utilidad uux no puede garantizar el soporte para todas las codificaciones de caracteres en todas las circunstancias. Por ejemplo, los datos de transmisión pueden estar restringidos a 7 bits por la red subyacente, los datos y los nombres de archivo de 8 bits no necesitan ser portátiles a sistemas no internacionalizados, etc. En estas circunstancias, se recomienda que solo se utilicen caracteres definidos en el rango de 7 bits del estándar ISO/IEC 646:1991, Versión de Referencia Internacional (equivalente a ASCII) y que solo se utilicen caracteres definidos en el conjunto de caracteres de nombres de archivo portátiles para nombrar archivos.

OPCIONES

La utilidad uux se ajustará a las Directrices de sintaxis de utilidad del volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2.

Se admitirán las siguientes opciones:

-j
Escribe la cadena de identificación del trabajo en la salida estándar. Esta identificación del trabajo puede ser utilizada por uustat para obtener el estado o terminar un trabajo.
-n
No notificar al usuario si el comando falla.
-p
Haga que la entrada estándar de uux sea la entrada estándar de la cadena-comando.

OPERANDOS

Se admitirá el siguiente operando:

cadena-comando

Una cadena compuesta por uno o más argumentos que son similares a los argumentos de comando normales, excepto que el comando y cualquier nombre de archivo pueden ser precedidos por nombre-sistema!. Un nombre-sistema nulo se interpretará como el sistema local.

STDIN

La entrada estándar no se utilizará a menos que se especifique la opción '-' o -p; en esos casos, la entrada estándar se convertirá en la entrada estándar de la cadena-comando.

ARCHIVOS DE ENTRADA

Los archivos de entrada se seleccionarán de acuerdo con el contenido de cadena-comando.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de uux:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están configuradas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos).
LC_MESSAGES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida estándar de errores.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

STDOUT

La salida estándar no se utilizará a menos que se especifique la opción -j; en ese caso, la cadena de identificación del trabajo se escribirá en la salida estándar en el siguiente formato:

"%s\n", <jobid>

STDERR

La salida estándar de errores solo se utilizará para mensajes diagnósticos.

ARCHIVOS DE SALIDA

Los archivos de salida se crearán o escribirán, o ambos, de acuerdo con el contenido de cadena-comando.

Si no se usa -n, los archivos de correo se modificarán después de cualquier error de comando o acceso a archivos en el sistema remoto.

DESCRIPCIÓN EXTENDIDA

SALIDA

None.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.

USO DE APLICACIONES

Esta utilidad forma parte de la opción UUCP Utilities y no tiene por qué ser soportada por todas las implementaciones.

Tenga en cuenta que, por razones de seguridad, muchas instalaciones limitan la lista de comandos ejecutables en nombre de una solicitud entrante de uux. Muchos sitios permiten poco más que la recepción de correo a través de uux.

Cualquier carácter especial para el intérprete de comandos debe ser citado, ya sea citando la cadena-comando completa o citando los caracteres especiales como argumentos individuales.

Como se señaló en uucp, los caracteres de notación de coincidencia de patrones del shell que aparecen en las rutas de archivos se expanden en el sistema local apropiado. Esto se hace bajo el control de la configuración local de LC_COLLATE y LC_CTYPE. Por lo tanto, se debe tener cuidado al usar patrones de nombres de archivo entre corchetes, ya que las reglas de ordenación y de tipos pueden variar de un sistema a otro. También tenga en cuenta que ciertos tipos de expresiones (es decir, clases de equivalencia, clases de caracteres y símbolos de ordenación) no tienen por qué ser compatibles en sistemas no internacionalizados.

EJEMPLOS

1.
El siguiente comando obtiene file1 del sistema a y file2 del sistema b, ejecuta diff en el sistema local y coloca los resultados en file.diff en el directorio local PUBDIR. (PUBDIR es el directorio público de uucp en el sistema local.)
uux "!diff a!/usr/file1 b!/a4/file2 >!~/file.diff"
2.
El siguiente comando falla porque uux coloca todos los archivos copiados a un sistema en el mismo directorio de trabajo. Aunque los archivos xyz son de dos sistemas diferentes, sus nombres de archivo son los mismos y entran en conflicto.
uux "!diff a!/usr1/xyz b!/usr2/xyz >!~/xyz.diff"
3.
El siguiente comando tiene éxito (suponiendo que diff esté permitido en el sistema a) porque el archivo local del sistema a no se copia al directorio de trabajo, y por lo tanto no entra en conflicto con el archivo del sistema c.
uux "a!diff a!/usr/xyz c!/usr/xyz >!~/xyz.diff"
