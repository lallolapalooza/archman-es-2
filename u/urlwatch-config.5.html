NOMBRE

urlwatch-config - Configuración del comportamiento de urlwatch

SINOPSIS

urlwatch --edit-config

DESCRIPCIÓN

La configuración global de urlwatch contiene ajustes básicos para el comportamiento genérico de urlwatch, así como para los Reporters.

MOSTRAR

Además de reportar siempre los cambios (que es el propósito de urlwatch), urlwatch por defecto reporta las páginas recién añadidas (new) y los errores (error). Puedes cambiar este comportamiento en la sección display de la configuración:

display:
  new: true
  error: true
  unchanged: false
  empty-diff: true

Si estableces unchanged a true, urlwatch reportará siempre todas las páginas que se comprueban pero no han cambiado.

La configuración empty-diff controla lo que sucede si una página cambia, pero debido a, por ejemplo, un diff_filter, la diferencia se reduce a una cadena vacía. Si se establece a true, urlwatch reportará un cambio (vacío). Si se establece a false, el cambio no se incluirá en el informe.

Los cambios de filtro no se aplican para sin cambios

Debido a la forma en que se almacena la salida filtrada, unchanged siempre reportará el contenido antiguo con los filtros del momento de la recuperación, lo que significa que cualquier cambio que hagas en el filter de un trabajo no será visible en el informe unchanged. Cuando la página cambie, se aplicará el nuevo filtro.

Por esta razón, unchanged no se puede usar para probar filtros; deberías usar la opción de línea de comandos --test-filter para aplicar tu filtro actual al contenido actual de la página.

REPORTERS

"Reporters" son los módulos que entregan notificaciones a través de su medio respectivo cuando se activan a través del archivo de configuración.

Consulta urlwatch-reporters(5) para opciones específicas del reporter.

Además de las opciones específicas del reporter, todos los reporters admiten estas opciones:

  • enabled: [booleano] Activa el reporter. (predeterminado: False)
  • separate: [booleano] Envía un informe para cada trabajo en lugar de un informe combinado para todos los trabajos. (predeterminado: False)

Los reporters se implementan en una jerarquía, de modo que estas configuraciones comunes se aplicarán a todos los reporters descendientes:

html
text
├───stdout
├───email
├───ifttt
├───webservice
│   ├───pushover
│   └───pushbullet
├───mailgun
├───telegram
├───slack
│   └───mattermost
├───discord
├───xmpp
├───prowl
└───shell
markdown
├───matrix
└───gotify

NOTA:

Establecer la opción html del reporter email a true hará que herede de la configuración html.

Aquí tienes un ejemplo de configuración que reporta en salida estándar en color, así como en correo electrónico HTML usando sendmail:

report:
  text:
    details: true
    footer: true
    line_length: 75
  html:
    diff: unified
    separate: true
  email:
    enabled: true
    method: sendmail
    sendmail:
        path: /usr/sbin/sendmail
    from: 'urlwatch@example.org'
    to: 'you@example.org'
    html: true
    subject: '{count} cambios: {jobs}'
  stdout:
    color: true
    enabled: true

Cualquier configuración específica del reporter debe estar debajo de la clave report en la configuración.

VALORES PREDETERMINADOS DEL TRABAJO

Si deseas cambiar algunos ajustes para todos tus trabajos, edita la sección job_defaults en tu archivo de configuración:

job_defaults:
  all:
    diff_tool: wdiff
  url:
    ignore_connection_errors: true

El archivo de configuración anterior establece todos los trabajos para usar wdiff como herramienta de diferencia, y todos los trabajos url para ignorar errores de conexión.

Las posibles sub-claves para job_defaults son:

  • all: Se aplica a todos tus trabajos, independientemente de su tipo.
  • shell: Se aplica solo a trabajos shell (con clave command).
  • url: Se aplica solo a trabajos url (con clave url).
  • browser: Se aplica solo a trabajos browser (con clave navigate).

Consulta Jobs sobre los diferentes tipos de trabajos y cuáles son las claves posibles.
