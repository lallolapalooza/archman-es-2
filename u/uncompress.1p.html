UNCOMPRESS(1P) Manual del Programador POSIX UNCOMPRESS(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

uncompress — expandir datos comprimidos

SINOPSIS

uncompress [-cfv] [archivo...]

DESCRIPCIÓN

La utilidad uncompress restaurará los archivos a su estado original después de que hayan sido comprimidos usando la utilidad compress. Si no se especifican archivos, la entrada estándar será descomprimida a la salida estándar. Si el proceso invocador tiene los privilegios apropiados, se conservarán la propiedad, los modos, el tiempo de acceso y el tiempo de modificación del archivo original.

Esta utilidad soportará la descompresión de cualquier archivo producido por la utilidad compress en la misma implementación. Para archivos producidos por compress en otros sistemas, uncompress soporta compresión de 9 a 14 bits (ver compress, -b); está definido por la implementación si los valores de -b mayores que 14 son soportados.

OPCIONES

La utilidad uncompress se ajustará al volumen de Definiciones Básicas de POSIX.1-2017, Sección 12.2, Directrices de Sintaxis de Utilidad, excepto que la Directriz 1 se aplica ya que el nombre de la utilidad tiene diez letras.

Se soportarán las siguientes opciones:

-c
Escribir en la salida estándar; ningún archivo será modificado.
-f
No preguntar para sobrescribir archivos. Excepto cuando se ejecuta en segundo plano, si -f no se proporciona, se le pedirá al usuario si un archivo existente debe ser sobrescrito. Si la entrada estándar no es una terminal y -f no se proporciona, uncompress escribirá un mensaje de diagnóstico en la salida de error estándar y saldrá con un estado mayor que cero.
-v
Escribir mensajes en la salida de error estándar relacionados con la expansión de cada archivo.

OPERANDOS

Se soportará el siguiente operando:

archivo
Una ruta de archivo. Si archivo ya tiene el sufijo .Z especificado, se usará como archivo de entrada y el archivo de salida se llamará archivo con el sufijo .Z eliminado. De lo contrario, archivo se usará como el nombre del archivo de salida y archivo con el sufijo .Z añadido se usará como archivo de entrada.

STDIN

La entrada estándar se usará solo si no se proporcionan operandos archivo, o si un operando archivo es '-'.

ARCHIVOS DE ENTRADA

Los archivos de entrada estarán en el formato producido por la utilidad compress.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de uncompress:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están definidas o están vacías. (Consulte el volumen de Definiciones Básicas de POSIX.1-2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización.)
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en contraposición a caracteres multibyte en argumentos).
LC_MESSAGES

Determinar la localización que debe usarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

STDOUT

Cuando no hay operandos archivo o se especifica la opción -c, la salida descomprimida se escribe en la salida estándar.

STDERR

Las indicaciones se escribirán en la salida de error estándar en las condiciones especificadas en las secciones DESCRIPCIÓN y OPCIONES. Las indicaciones contendrán la ruta del archivo, pero su formato no se especifica de otra manera. De lo contrario, la salida de error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Los archivos de salida son los mismos que los archivos de entrada respectivos para compress.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0
Ocurrió un error.

CONSECUENCIAS DE ERRORES

El archivo de entrada no se modifica.

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

El límite de 14 en el argumento bits de compress -b es para lograr la portabilidad a todos los sistemas (dentro de las restricciones impuestas por la falta de un formato de archivo publicado explícito). Algunas implementaciones basadas en arquitecturas de 16 bits no pueden soportar descompresión de 15 o 16 bits.
