DESCRIPCIÓN

Unbound es una implementación de un resolvedor de DNS, que realiza caché y validación DNSSEC. Esta es la API de la biblioteca, para usar la biblioteca -lunbound. El demonio servidor se describe en unbound(8). La biblioteca funciona de forma independiente a un servidor unbound en ejecución y puede usarse para convertir nombres de host a direcciones IP, y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de clave pública de los resultados con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Se puede crear y eliminar en cualquier momento. Crearla de nuevo elimina cualquier configuración previa (como claves de confianza) y borra cualquier resultado en caché.

Las funciones son seguras para hilos y un contexto puede usarse en un entorno con hilos (así como en uno sin hilos). La resolución (y validación) también puede realizarse de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve la llamada inmediatamente, de modo que el procesamiento pueda continuar mientras los resultados están disponibles más tarde.

Las funciones se discuten en orden a continuación.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza de forma predeterminada. Utilice ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esto, use las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si usa lib openssl (la aplicación llama a estas funciones una vez para la inicialización). Openssl 1.0.0 o posterior usa la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y las devoluciones de llamada no se llaman para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que permite especificar una de las opciones del formato de archivo de configuración, consulte unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclas de confianza, existen rutinas especiales. Pase el nombre de la opción con los dos puntos finales ':'.
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene el valor de una opción. Algunas opciones no se pueden obtener, y otras devuelven una lista separada por saltos de línea. Pase el nombre de la opción sin los dos puntos finales ':'. El valor devuelto debe ser liberado con free(2) por el llamador.
ub_ctx_config
Una interfaz para usuarios avanzados que permite especificar un archivo de configuración de unbound, consulte unbound.conf(5), que se lee para la configuración. No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclas de confianza, existen rutinas especiales. Esta función solo es segura para hilos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no se llame en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se reenviarán las consultas DNS, el resolvedor de caché a usar. Dirección IP4 o IP6. Reenvía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolvedor recursivo. Si el proxy no es capaz de DNSSEC, la validación puede fallar. Se puede llamar varias veces, en cuyo caso las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autorizados a usar para una zona particular. Dirección IP4 o IP6. Si la dirección es NULL, se elimina la entrada de stub. Establezca isprime en verdadero si configura sugerencias de raíz con ella. De lo contrario, similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas, o para agregar varias direcciones para una zona particular. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolución completa, pero puede utilizar esta llamada para leer la lista de servidores de nombres a utilizar desde el nombre de archivo proporcionado. Normalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no admiten DNSSEC, la validación puede fallar. Solo se seleccionan los servidores de nombres, se ignoran el dominio de búsqueda, ndots y otras configuraciones de resolv.conf(5). Si se pasa NULL como fname, se utiliza "/etc/resolv.conf" (si está en Windows, se selecciona el servidor de nombres configurado a nivel del sistema). En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_hosts
Lee la lista de hosts desde el nombre de archivo proporcionado. Normalmente "/etc/hosts". Cuando se consultan, estas direcciones no se marcan como seguras por DNSSEC. Si se pasa NULL como fname, se utiliza "/etc/hosts" (si está en Windows, se selecciona etc/hosts de WINDIR en su lugar). En este momento, solo es posible establecer la configuración antes de la primera.

FUNCTIONS

ub_ctx_create
Create a context for the validating recursive resolver. If it fails, NULL is returned. The context needs to be freed with ub_ctx_free when finished.
ub_ctx_destroy
Destroy a context. All outstanding queries are cancelled. The context is freed.
ub_ctx_config
Load configuration from a configuration file. This function is only useful if you want to load configuration from a file and not specify it using the other ub_ctx_* routines. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_resolvconf
Load configuration from the system's resolv.conf file. Uses system's nameservers, and options like search path. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta
Añade un ancla de confianza al contexto dado. En este momento solo es posible añadir claves de confianza antes de que se complete la primera resolución. El formato es una cadena, similar al formato de archivo de zona, [nombre de dominio] [tipo] [contenido rdata]. Se aceptan registros DS y DNSKEY.
ub_ctx_add_ta_autr
Añade un archivo con ancla de confianza rastreada automáticamente al contexto dado. Pasa el nombre de un archivo con el ancla de confianza gestionada. Puedes crear este archivo con unbound-anchor(8) para el ancla raíz. También puedes crearlo con un archivo inicial con una línea con un registro DNSKEY o DS. Si el archivo es escribible, se actualiza cuando cambia el ancla de confianza. En este momento solo es posible añadir claves de confianza antes de que se complete la primera resolución.
ub_ctx_add_ta_file
Añade anclas de confianza al contexto dado. Pasa el nombre de un archivo con registros DS y DNSKEY en formato de archivo de zona. En este momento solo es posible añadir claves de confianza antes de que se complete la primera resolución.
ub_ctx_trustedkeys
Añade anclas de confianza al contexto dado. Pasa el nombre de un archivo de configuración estilo bind con trusted-keys{}. En este momento solo es posible añadir claves de confianza antes de que se complete la primera resolución.
ub_ctx_debugout
Establece la salida de depuración y registro de errores al flujo dado. Pasa NULL para deshabilitar la salida. Por defecto es stderr. Los nombres de archivo o el uso de syslog se pueden habilitar usando opciones de configuración, esta rutina es para usar tu propio flujo.
ub_ctx_debuglevel
Establece la verbosidad de depuración para el contexto. La salida se dirige a stderr. Un nivel de depuración más alto produce más salida.
ub_ctx_async
Establece un comportamiento del contexto para acciones asíncronas. Si se establece a verdadero, habilita hilos y una llamada a ub_resolve_async crea un hilo para manejar el trabajo en segundo plano. Si es falso, se bifurca un proceso para manejar el trabajo en segundo plano. Los cambios en esta configuración después de que se hayan realizado llamadas a ub_resolve_async no tienen efecto (elimina y recrea el contexto para cambiar).
ub_poll
Sondea un contexto para ver si tiene nuevos resultados. No sondee en un bucle, en su lugar extraiga el fd a continuación para sondea de disponibilidad, y luego compruebe, o espere usando la rutina de espera. Devuelve 0 si no hay nada que leer, o un valor distinto de cero si hay un resultado disponible. Si es distinto de cero, llame a ub_process para realizar las devoluciones de llamada.
ub_wait
Espera a que un contexto termine con resultados. Llama a ub_process después de la espera por usted. Después de la espera, no hay más consultas asíncronas pendientes.
ub_fd
Obtiene un descriptor de archivo. Espera a que se vuelva legible, en ese momento se devuelven las respuestas del resolvedor de validación asíncrono. Luego llame a ub_process para continuar procesando.
ub_process
Llame a esta rutina para continuar procesando resultados del resolvedor de validación (cuando el fd se vuelve legible). Realizará las devoluciones de llamada necesarias.
ub_resolve
Realiza la resolución y validación del nombre objetivo. El nombre es un nombre de dominio en una cadena de texto terminada en cero. El tipo rrtype y la clase rrclass son códigos de tipo y clase DNS. La estructura de resultado se asigna de nuevo con los datos resultantes.
ub_resolve_async
Realiza la resolución y validación asíncrona del nombre objetivo. Los argumentos significan lo mismo que para ub_resolve excepto que no se devuelven datos inmediatamente, en su lugar se llama a una devolución de llamada más tarde. La devolución de llamada recibe una copia del puntero mydata, que puedes usar para pasar información a la devolución de llamada. El tipo de devolución de llamada es un puntero a una función declarada como:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

El async_id se devuelve para que usted pueda (opcionalmente) decidir rastrearlo y cancelar la solicitud si es necesario. Si pasa un puntero NULL, el async_id no se devuelve.

ub_cancel
Cancela una consulta asíncrona en progreso. Esto puede devolver un error si la consulta no existe, o si la consulta ya se está entregando, en cuyo caso aún podría recibir una devolución de llamada para la consulta.
ub_resolve_free
Libera el contenido de la estructura ub_result después de su uso.
ub_strerror
Convierte el valor de error de una de las funciones de la biblioteca unbound a una cadena legible por humanos.
ub_ctx_print_local_zones
Imprime información de autoridad local para depuración en la salida de depuración.
ub_ctx_zone_add
Añade una nueva zona a la información de autoridad local, como la declaración local-zone de unbound.conf(5).
ub_ctx_zone_remove
Elimina una zona de la información de autoridad local.
ub_ctx_data_add
Añade datos de registro de recursos a la información de autoridad local, como la declaración local-data de unbound.conf(5).
ub_ctx_data_remove
Elimina datos de autoridad local del nombre dado.

RESULT DATA STRUCTURE

El resultado de la resolución y validación de DNS se devuelve como struct ub_result. La estructura de resultado contiene las siguientes entradas:

struct ub_result {
     char* qname;         /* cadena de texto, pregunta original */
     int qtype;           /* código de tipo solicitado */
     int qclass;          /* código de clase solicitada */
     char** data;         /* matriz de elementos rdata, terminada en NULL */
     int* len;            /* matriz con longitudes de elementos rdata */
     char* canonname;     /* nombre canónico del resultado */
     int rcode;           /* código de error adicional en caso de no tener datos */
     void* answer_packet; /* paquete de respuesta completo en formato de red */
     int answer_len;      /* longitud del paquete en octetos */
     int havedata;        /* verdadero si hay datos */
     int nxdomain;        /* verdadero si nodata porque el nombre no existe */
     int secure;          /* verdadero si el resultado es seguro */
     int bogus;           /* verdadero si ocurrió una falla de seguridad */
     char* why_bogus;     /* cadena con el error si es bogus */
     int was_ratelimited; /* verdadero si la consulta fue limitada por tasa (SERVFAIL) por unbound */
     int ttl;             /* número de segundos que el resultado es válido */
};

Si tanto secure como bogus son falsos, la seguridad no estaba habilitada para el dominio de la consulta. De lo contrario, no ambos son verdaderos, uno de ellos es verdadero.

VALORES DE RETORNO

Muchas rutinas devuelven un código de error. El valor 0 (cero) denota que no ocurrió ningún error. Otros valores se pueden pasar a ub_strerror para obtener una cadena de error legible. ub_strerror devuelve una cadena terminada en cero. ub_ctx_create devuelve NULL en caso de error (un fallo de malloc). ub_poll devuelve verdadero si puede haber alguna información disponible, falso en caso contrario. ub_fd devuelve un descriptor de archivo o -1 en caso de error. ub_ctx_config y ub_ctx_resolvconf intentan dejar errno informativo en un retorno de función con fallo de lectura de archivo.
