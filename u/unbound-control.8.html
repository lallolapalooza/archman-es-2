NOMBRE

unbound-control - Utilidad de control remoto del servidor Unbound 1.24.2.

SINOPSIS

unbound-control [-hq] [-c archivo_config] [-s servidor] comando

DESCRIPCIÓN

unbound-control realiza la administración remota del servidor DNS unbound(8). Lee el archivo de configuración, contacta al servidor Unbound a través de TLS, envía el comando y muestra el resultado.

Las opciones disponibles son:

-h
Muestra la versión y la ayuda de las opciones de la línea de comandos.
-c <archivo_config>
El archivo de configuración a leer con los ajustes. Si no se proporciona, se utiliza el archivo de configuración predeterminado /etc/unbound/unbound.conf.
-s <servidor[@puerto]>
Dirección IPv4 o IPv6 del servidor a contactar. Si no se proporciona, la dirección se lee del archivo de configuración.
-q
Silencioso, si se proporciona la opción, no imprime nada si funciona correctamente.

COMANDOS

Hay varios comandos que el servidor entiende.

start
Inicia el servidor. Simplemente ejecuta unbound(8). El ejecutable unbound se busca en el PATH establecido en el entorno. Se inicia con el archivo de configuración especificado usando -c o el archivo de configuración predeterminado.
stop
Detiene el servidor. El demonio del servidor se cierra.
reload
Recarga el servidor. Esto vacía la caché y lee el archivo de configuración de nuevo.
reload_keep_cache
Recarga el servidor pero intenta mantener la caché de RRset y mensajes si la configuración (re)lo permite. Esto significa que los tamaños de caché y el número de hilos no deben cambiar entre recargas.
fast_reload [+dpv]
Recarga el servidor, pero minimiza el tiempo de inactividad, para que las consultas de los usuarios sigan recibiendo servicio. Esto requiere que el código esté compilado con hilos. La configuración se carga en un hilo y se prepara, luego pausa brevemente el servidor existente y actualiza las opciones de configuración. La intención es que la pausa no afecte el servicio de las consultas de los usuarios. La caché se mantiene. Las consultas de los usuarios en curso también se mantienen y continúan, pero con las nuevas opciones de configuración.

NOTA:

Este comando es experimental en este momento.

La cantidad de memoria temporal necesaria durante una recarga rápida es el doble de la cantidad necesaria para la configuración. Esto es debido a que Unbound necesita almacenar temporalmente tanto los valores de configuración actuales como los nuevos mientras intenta realizar la recarga rápida. Las zonas cargadas desde disco (zonas de autoridad y zonas RPZ) se incluyen en estas necesidades de memoria.

Las opciones que se pueden cambiar son para forwards, stubs, views, zonas de autoridad, zonas RPZ y zonas locales.

También access-control y opciones similares, interface-action y opciones similares y tcp-connection-limit. Puede recargar algunos cambios de define-tag, más información a continuación. Otras opciones incluyen insecure-lan-zones, domain-insecure, trust-anchor-file, trust-anchor, trusted-keys-file, auto-trust-anchor-file, edns-client-string, ipset, log-identity, infra-cache-numhosts, msg-cache-size, rrset-cache-size, key-cache-size, ratelimit-size, neg-cache-size, num-queries-per-thread, jostle-timeout, use-caps-for-id, unwanted-reply-threshold, tls-use-sni, outgoing-tcp-mss, ip-dscp, max-reuse-tcp-queries, tcp-reuse-timeout, tcp-auth-query-timeout, delay-close. iter-scrub-promiscuous.

No funciona con cambios en interface y outgoing-interface, tampoco con remote control, outgoing-port-permit, outgoing-port-avoid, msg-buffer-size, ninguna opción *-slabs y cambios en statistics-interval.

Para dnstap se pueden cambiar estas opciones: dnstap-log-resolver-query-messages, dnstap-log-resolver-response-messages, dnstap-log-client-query-messages, dnstap-log-client-response-messages, dnstap-log-forwarder-query-messages y dnstap-log-forwarder-response-messages.

No funciona con estas opciones: dnstap-enable, dnstap-bidirectional, dnstap-socket-path, dnstap-ip, dnstap-tls, dnstap-tls-server-name, dnstap-tls-cert-bundle, dnstap-tls-client-key-file y dnstap-tls-client-cert-file.

Las opciones dnstap-send-identity, dnstap-send-version, dnstap-identity y dnstap-version se pueden cargar cuando no se utiliza +p.

La opción +v hace que la salida sea detallada, incluyendo el tiempo que tardó en realizar la recarga. Con +vv es más detallada e incluye la cantidad de memoria que se asignó temporalmente para realizar la recarga; esta cantidad de memoria puede ser grande si la configuración tiene un contenido extenso. En la salida de tiempo, el tiempo de 'recarga' es el tiempo durante el cual el servidor estuvo en pausa.

La opción +p hace que la recarga no pause los hilos, estos continúan ejecutándose. Se adquieren bloqueos, pero los elementos se actualizan en secuencia, por lo que es posible que los hilos vean un estado inconsistente con algunas opciones de la configuración antigua y algunas de la nueva, como parámetros de TTL de caché de la configuración antigua y forwards de la nueva configuración. Los stubs y forwards se actualizan al mismo tiempo, de modo que se ven de forma coherente, ya sea con valores antiguos o nuevos juntos. La opción hace que el tiempo de recarga sea, por ejemplo, 3 microsegundos en lugar de 0.3 milisegundos durante los cuales los hilos de trabajo se interrumpen. Por lo tanto, la interrupción es mucho más corta, a expensas de cierta inconsistencia. Después de la recarga en sí, cada hilo de trabajo es contactado brevemente para que libere recursos, esto alarga un poco el tiempo de eliminación y consume tiempo del hilo de trabajo que atiende el control remoto.

Con la opción nopause (+p), la recarga no funciona para recargar algunas opciones que la recarga rápida sí funciona sin la opción nopause: val-bogus-ttl, val-override-date, val-sig-skew-min, val-sig-skew-max, val-max-restart, val-nsec3-keysize-iterations, target-fetch-policy, outbound-msg-retry, max-sent-count, max-query-restarts, do-not-query-address, do-not-query-localhost, private-address, private-domain, caps-exempt, nat64-prefix, do-nat64, infra-host-ttl, infra-keep-probing, ratelimit, ip-ratelimit, ip-ratelimit-cookie, wait-limit-netblock, wait-limit-cookie-netblock, ratelimit-below-domain, ratelimit-for-domain.

La opción +d hace que la recarga descarte las consultas en las que los hilos de trabajo están operando. Esto es como flush_requestlist. Sin ella, las consultas se mantienen para que los usuarios sigan recibiendo respuestas para esas consultas que se están procesando actualmente. El descarte hace que las consultas durante el tiempo de vida del procesamiento de la consulta vean solo opciones de configuración antiguas o solo nuevas.

Cuando hay cambios en las etiquetas de configuración, de la opción define-tag, entonces la opción +d se activa implícitamente con una advertencia impresa, y las consultas se descartan. Esto es para detener las referencias a la información de la etiqueta antigua, por las consultas antiguas. verbosity número
Cambia el valor de verbosidad para el registro. Los mismos valores que la palabra clave verbosity: en unbound.conf(5). Esta nueva configuración dura hasta que al servidor se le emite una recarga (tomada nuevamente del archivo de configuración), o el siguiente comando de control de verbosidad.
log_reopen
Reabre el archivo de registro, lo cierra y lo abre. Útil para la rotación de registros para que el demonio libere el archivo al que está registrando. Si está usando syslog, intentará cerrar y abrir syslog (lo que puede no funcionar si está en chroot).
stats
Imprime estadísticas. Restablece los contadores internos a cero, esto puede controlarse mediante la declaración de configuración statistics-cumulative:. Las estadísticas se imprimen con un par [nombre]: [valor] por línea.
stats_noreset
Inspecciona las estadísticas. Las imprime como lo hace el comando stats, pero no restablece los contadores internos a cero.
status
Muestra el estado del servidor. Código de salida 3 si no se está ejecutando (se rechaza la conexión al puerto), 1 en caso de error, 0 si se está ejecutando.
local_zone nombre tipo
Agrega una nueva zona local con nombre y tipo. Similar a la declaración de configuración local-zone. Si la zona ya existe, el tipo se cambia al argumento dado.
local_zone_remove nombre
Elimina la zona local con el nombre dado. Elimina todos los datos locales dentro de ella. Si la zona no existe, el comando tiene éxito.
local_data RR datos...
Agrega nuevos datos locales, el registro de recursos dado. Similar a la palabra clave local-data:, excepto cuando no existe una zona que la cubra. En ese caso, este comando de control remoto crea una zona transparente con el mismo nombre que este registro.
local_data_remove nombre
Elimina todos los datos RR del nombre local. Si el nombre ya no tiene elementos, no sucede nada. A menudo resulta en NXDOMAIN para el nombre (en una zona estática), pero si el nombre se ha convertido en un no terminal vacío (todavía hay datos en nombres de dominio por debajo del nombre eliminado), las respuestas NOERROR sin datos son el resultado para ese nombre.
local_zones
Agrega zonas locales leídas de la entrada estándar de unbound-control. La entrada se lee por línea, con el nombre y el tipo separados por un espacio en una línea. Para adiciones masivas.
local_zones_remove
Elimina zonas locales leídas de la entrada estándar de unbound-control. La entrada es un nombre por línea. Para eliminaciones masivas.
local_datas
Agrega RRs de datos locales leídos de la entrada estándar de unbound-control. La entrada es un RR por línea. Para adiciones masivas.
local_datas_remove
Elimina RRs de datos locales leídos de la entrada estándar de unbound-control. La entrada es un nombre por línea. Para eliminaciones masivas.
dump_cache
El contenido de la caché se imprime en formato de texto a la salida estándar. Puede redirigirlo a un archivo para guardar la caché en un archivo. No soportado en Unbounds remotos en operación multihilo.
load_cache
El contenido de la caché se carga desde la entrada estándar. Utiliza el mismo formato que usa dump_cache. Cargar la caché con datos viejos o incorrectos puede resultar en que se devuelvan datos viejos o incorrectos a los clientes. Cargar datos en la caché de esta manera está soportado para ayudar en la depuración. No soportado en Unbounds remotos en operación multihilo.
cache_lookup [+t] nombres
Imprime en la salida estándar los conjuntos de RR y los mensajes que están en la caché. Para cada nombre listado se imprime el contenido en o por debajo del nombre. Se pueden dar varios nombres separados por espacios, cada uno se imprime. Cuando la caché de subredes está habilitada, también se imprimen las entradas coincidentes de la caché de subredes.

La opción +t permite nombres de dominio de nivel superior (TLD) y nombres raíz. Con ella se pueden usar nombres como 'com' y '.', pero requiere un gran esfuerzo buscar en la caché.

lookup nombre
Imprime en la salida estándar los servidores de nombres que se utilizarían para buscar el nombre especificado.
flush [+c] nombre
Elimina el nombre de la caché. Elimina los tipos A, AAAA, NS, SOA, CNAME, DNAME, MX, PTR, SRV, NAPTR, SVCB y HTTPS. Porque es rápido de hacer. Otros tipos de registros se pueden eliminar usando flush_type o flush_zone.

La opción +c elimina también los elementos de la caché cachedb. Si se está usando cachedb.

flush_type [+c] nombre tipo
Elimina el nombre y el tipo de información de la caché.

La opción +c elimina también los elementos de la caché cachedb. Si se está usando cachedb.

flush_zone [+c] nombre
Elimina toda la información en o por debajo del nombre de la caché. Los conjuntos de RR y las entradas de claves se eliminan para que se realicen nuevas búsquedas. Esto requiere recorrer e inspeccionar toda la caché, y es una operación lenta. Las entradas se establecen como expiradas en la implementación de este comando (por lo tanto, si serve-expired está habilitado, servirá esa información pero programará una re-búsqueda para obtener nueva información).

La opción +c elimina también los elementos de la caché cachedb. Si se está usando cachedb.

flush_bogus [+c]
Elimina todos los datos erróneos de la caché.

La opción +c elimina también los elementos de la caché cachedb. Si se está usando cachedb.

flush_negative [+c]
Elimina todos los datos negativos de la caché. Estas son respuestas nxdomain, respuestas nodata y respuestas servfail. También elimina las entradas de claves incorrectas (que podrían deberse a búsquedas fallidas) de la caché de claves dnssec, y los fallos de búsqueda de último recurso del iterador de la caché de conjuntos de RR.

La opción +c elimina también los elementos de la caché cachedb. Si se está usando cachedb.

Restablece las estadísticas a cero.
flush_requestlist
Descarta las consultas en las que se está trabajando. Detiene el trabajo en las consultas que el servidor está procesando actualmente. La caché no se ve afectada. No se enviará ninguna respuesta para esas consultas, lo que probablemente hará que esos usuarios vuelvan a solicitarlas más tarde. Útil para hacer que el servidor comience a procesar consultas con nuevas configuraciones, como un nivel de verbosidad más alto.
dump_requestlist
Muestra lo que se está procesando. Imprime todas las consultas en las que el servidor está trabajando actualmente. Imprime el tiempo que los usuarios han estado esperando. Para solicitudes internas, no se imprime tiempo. Y luego imprime el estado del módulo. Esto imprime las consultas del primer hilo y no las consultas que se están atendiendo desde otros hilos.
flush_infra all|IP
Si se especifica 'all', se vacía toda la caché de infraestructura. Si se especifica una dirección IP concreta, se elimina la entrada de esa dirección de la caché. Contiene datos EDNS, ping y de lentitud.
dump_infra
Muestra el contenido de la caché de infraestructura.
set_option opt: val
Establece la opción al valor dado sin recargar. Por lo tanto, la caché no se vacía. La opción debe terminar con ':' y debe haber un espacio entre la opción y el valor. Algunos valores pueden no tener efecto si se establecen de esta manera, los nuevos valores no se escriben en el archivo de configuración, no todas las opciones son compatibles. Esto es diferente de la llamada set_option en libunbound, donde todos los valores funcionan porque Unbound no ha sido inicializado.

Los valores que funcionan son: statistics-interval, statistics-cumulative, do-not-query-localhost, harden-short-bufsize, harden-large-queries, harden-glue, harden-dnssec-stripped, harden-below-nxdomain, harden-referral-path, prefetch, prefetch-key, log-queries, hide-identity, hide-version, identity, version, val-log-level, val-log-squelch, ignore-cd-flag, add-holddown, del-holddown, keep-missing, tcp-upstream, ssl-upstream, max-udp-size, ratelimit, ip-ratelimit, cache-max-ttl, cache-min-ttl

control commands

This section lists the commands that can be sent to the unbound daemon using the unbound-control utility. These commands allow you to inspect and modify the running unbound server's state.

access_list
Print the list of access control entries. The entries are printed in the order they are processed.
access_add ip/mask
Add an access control entry for the given ip/mask. This adds an entry that allows access from the given subnet. It is added to the end of the list, so it is processed after existing entries.
access_remove ip/mask
Remove an access control entry for the given ip/mask. If no such entry exists, nothing happens.
flush_zone zone
Flush all records for the given zone (and all subdomains) from the cache. The zone name should be followed by a dot, e.g. 'example.com.'. If the zone name is empty ('.'), the entire cache is flushed.
flush_client_subnet
Flush all client subnets from the cache. This is useful if the client subnet prefix length changes. This command does not affect the server's operational mode, only its cache.
flush_request_list
Flush the internal request list. This can help if the server gets stuck processing many requests.
flush_common_servfail
Flush the internally stored count of common server failure responses. This counter is used to stop sending queries to servers that return server failure responses too often.
flush_hints
Flush the root hints from the cache. This causes Unbound to re-read the root hints file.
flush_dnssec_negative_cache
Flush DNSSEC NSEC records from the cache. This can be useful if you suspect an issue with DNSSEC validation or if NSEC records have been updated.
flush_cookie_secrets
Flush all DNS cookie secrets from the server. This forces the server to generate new secrets.
set_option name value
Set the value of an option. Give the option name without a trailing ':'. The value is read from the input. If the value is empty, the option is reset to its default. Some options are boolean and do not take a value, in this case, provide the option name only. On error 'error ...' is printed (it gives a syntax error on unknown option). This command modifies the running Unbound configuration and affects the cache and subsequent queries. However, it does not modify the configuration file, so the changes are lost upon reload or restart of unbound. The command list_stubs, list_forwards, list_local_zones and list_local_data are not affected. Not all options can be set with this command; see get_option for a partial list.

Supported options include:

verbosity
Set the verbosity level.
log-queries
Enable or disable logging of queries.
harden-dnssec-stripped
Enable or disable hardening against DNSSEC stripping attacks.
harden-large-queries
Enable or disable hardening against large queries.
qname-minimisation
Enable or disable QNAME minimisation.
prefetch
Enable or disable prefetching of expired cache entries.
prefetch-key
Enable or disable prefetching of DNSKEY records.
num-threads
Set the number of threads to use.
so-rcvbuf
Set the size of the socket receive buffer.
so-sndbuf
Set the size of the socket send buffer.
edns-buffer-size
Set the EDNS buffer size.
max-udp-size
Set the maximum UDP packet size.
root-hints
Set the path to the root hints file.
h-random-seed
Set the random seed for hostname generation.
chase-client-glue
Enable or disable chasing client glue records.
ip-ratelimiting
Enable or disable IP rate limiting.
ip-ratelimit-factor
Set the IP rate limit factor.
id-type
Set the ID type for DNS cookies.
cookie-secret
Add or replace a DNS cookie secret.
cookie-secret-remove
Remove a DNS cookie secret.
cookie-secret-reset
Reset all DNS cookie secrets.
cache-max-ttl
Set the maximum TTL for cache entries.
cache-min-ttl
Set the minimum TTL for cache entries.
cache-max-negative-ttl
Set the maximum TTL for negative cache entries.
get_option opt
Get the value of the option. Give the option name without a trailing ':'. The value is printed. If the value is "", nothing is printed and the connection closes. On error 'error ...' is printed (it gives a syntax error on unknown option). For some options a list of values, one on each line, is printed. The options are shown from the config file as modified with set_option. For some options an override may have been taken that does not show up with this command, not results from e.g. the verbosity and forward control commands. Not all options work, see list_stubs, list_forwards, list_local_zones and list_local_data for those.
list_stubs
List the stub zones in use. These are printed one by one to the output. This includes the root hints in use.
list_forwards
List the forward zones in use. These are printed zone by zone to the output.
list_insecure
List the zones with domain-insecure.
list_local_zones
List the local zones in use. These are printed one per line with zone type.
list_local_data
List the local data RRs in use. The resource records are printed.
insecure_add zone
Add a domain-insecure for the given zone, like the statement in unbound.conf. Adds to the running Unbound without affecting the cache contents (which may still be bogus, use flush_zone to remove it), does not affect the config file.
insecure_remove zone
Removes domain-insecure for the given zone.
forward_add [+it] zone addr ...
Add a new forward zone to running Unbound. With +i option also adds a domain-insecure for the zone (so it can resolve insecurely if you have a DNSSEC root trust anchor configured for other names). The addr can be IP4, IP6 or nameserver names, like forward-zone config in unbound.conf. The +t option sets it to use TLS upstream, like forward-tls-upstream: yes.
forward_remove [+i] zone
Remove a forward zone from running Unbound. The +i also removes a domain-insecure for the zone.
stub_add [+ipt] zone addr ...
Add a new stub zone to running Unbound. With +i option also adds a domain-insecure for the zone. With +p the stub zone is set to prime, without it it is set to notprime. The addr can be IP4, IP6 or nameserver names, like the stub-zone: config in unbound.conf. The +t option sets it to use TLS upstream, like stub-tls-upstream: yes.
stub_remove [+i] zone
Remove a stub zone from running Unbound. The +i also removes a domain-insecure for the zone.
forward [off | addr ... ]
Setup forwarding mode. Configures if the server should ask other upstream nameservers, should go to the internet root nameservers itself, or show the current config. You could pass the nameservers after a DHCP update.

Without arguments the current list of addresses used to forward all queries to is printed. On startup this is from the forward-zone "." configuration. Afterwards it shows the status. It prints off when no forwarding is used.

If off is passed, forwarding is disabled and the root nameservers are used. This can be used to avoid to avoid buggy or non-DNSSEC supporting nameservers returned from DHCP. But may not work in hotels or hotspots.

If one or more IPv4 or IPv6 addresses are given, those are then used to forward queries to. The addresses must be separated with spaces. With '@port' the port number can be set explicitly (default port is 53 (DNS)).

By default the forwarder information from the config file for the root "." is used. The config file is not changed, so after a reload these changes are gone. Other forward zones from the config file are not affected by this command.

ratelimit_list [+a]
List the domains that are ratelimited. Printed one per line with current estimated qps and qps limit from config. With +a it prints all domains, not just the ratelimited domains, with their estimated qps. The ratelimited domains return an error for uncached (new) queries, but cached queries work as normal.
ip_ratelimit_list [+a]
List the ip addresses that are ratelimited. Printed one per line with current estimated qps and qps limit from config. With +a it prints all ips, not just the ratelimited ips, with their estimated qps. The ratelimited ips are dropped before checking the cache.
list_auth_zones
List the auth zones that are configured. Printed one per line with a status, indicating if the zone is expired and current serial number. Configured RPZ zones are included.
auth_zone_reload zone
Reload the auth zone (or RPZ zone) from zonefile. The zonefile is read in overwriting the current contents of the zone in memory. This changes the auth zone contents itself, not the cache contents. Such cache contents exists if you set Unbound to validate with for-upstream: yes and that can be cleared with flush_zone zone.
auth_zone_transfer zone
Transfer the auth zone (or RPZ zone) from master. The auth zone probe sequence is started, where the masters are probed to see if they have an updated zone (with the SOA serial check). And then the zone is transferred for a newer zone version.
rpz_enable zone
Enable the RPZ zone if it had previously been disabled.
rpz_disable zone
Disable the RPZ zone.
view_list_local_zones view
list_local_zones for given view.
view_local_zone view name type
local_zone for given view.
view_local_zone_remove view name
local_zone_remove for given view.
view_list_local_data view
list_local_data for given view.
view_local_data view RR data...
local_data for given view.
view_local_data_remove view name
local_data_remove for given view.
view_local_datas_remove view
Remove a list of local_data for given view from stdin. Like local_datas_remove.
view_local_datas view
Add a list of local_data for given view from stdin. Like local_datas.
add_cookie_secret secret
Add or replace a cookie secret persistently. secret needs to be an 128 bit hex string.

Cookie secrets can be either active or staging. Active cookie secrets are used to create DNS Cookies, but verification of a DNS Cookie succeeds with any of the active or staging cookie secrets. The state of the current cookie secrets can be printed with the print_cookie_secrets command.

When there are no cookie secrets configured yet, the secret is added as active. If there is already an active cookie secret, the secret is added as staging or replacing an existing staging secret.
