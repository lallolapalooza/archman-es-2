uustat(1) Manual de comandos generales uustat(1)

NOMBRE

uustat - consulta y control de estado de UUCP

SINOPSIS

uustat -a

uustat --all

uustat [ -eKRiMNQ ] [ -sS sistema ] [ -uU usuario ] [ -cC comando ] [ -oy horas ] [ -B líneas ] [ --executions ] [ --kill-all ] [ --rejuvenate-all ] [ --prompt ] [ --mail ] [ --notify ] [ --no-list ] [ --system sistema ] [ --not-system sistema ] [ --user usuario ] [ --not-user usuario ] [ --command comando ] [ --not-command comando ] [ --older-than horas ] [ --younger-than horas ] [ --mail-lines líneas ]

uustat [ -kr jobid ] [ --kill jobid ] [ --rejuvenate jobid ]

uustat -q [ -sS sistema ] [ -oy horas ] [ --system sistema ] [ --not-system sistema ] [ --older-than horas ] [ --younger-than horas ]

uustat --list [ -sS sistema ] [ -oy horas ] [ --system sistema ] [ --not-system sistema ] [ --older-than horas ] [ --younger-than horas ]

uustat -m

uustat --status

uustat -p

uustat --ps

DESCRIPCIÓN

El comando uustat puede mostrar varios tipos de información de estado sobre el sistema UUCP. También puede ser utilizado para cancelar o rejuvenecer solicitudes realizadas por uucp (1) o uux (1).

Por defecto, uustat muestra todos los trabajos en cola para el usuario que lo invoca, como si se le hubiera dado la opción --user con el argumento apropiado.

Si se proporcionan alguna de las opciones -a, --all, -e, --executions, -s, --system, -S, --not-system, -u, --user, -U, --not-user, -c, --command, -C, --not-command, -o, --older-than, -y, --younger-than, entonces se mostrarán todos los trabajos que coincidan con las especificaciones combinadas.

La opción -K o --kill-all puede ser utilizada para eliminar un grupo seleccionado de trabajos, como todos los trabajos de más de 7 días de antigüedad.

OPCIONES

Las siguientes opciones pueden ser dadas a uustat.

-a, --all
Listar todas las solicitudes de transferencia de archivos en cola.
-e, --executions
Listar solicitudes de ejecución en cola en lugar de solicitudes de transferencia de archivos en cola. Las solicitudes de ejecución en cola son procesadas por uuxqt (8) en lugar de uucico (8). Las solicitudes de ejecución en cola pueden estar esperando que algún archivo sea transferido desde un sistema remoto. Son creadas por una invocación de uux (1).
-s sistema, --system sistema
Listar todos los trabajos en cola para el sistema nombrado. Estas opciones pueden ser especificadas múltiples veces, en cuyo caso se listarán todos los trabajos para todos los sistemas. Si se usa con --list solo se listarán los sistemas nombrados.
-S sistema, --not-system sistema
Listar todos los trabajos en cola para sistemas distintos al nombrado. Estas opciones pueden ser especificadas múltiples veces, en cuyo caso no se listarán trabajos de ninguno de los sistemas especificados. Si se usa con --list solo se listarán los sistemas no nombrados. Estas opciones no pueden usarse con -s o --system.
-u usuario, --user usuario
Listar todos los trabajos en cola para el usuario nombrado. Estas opciones pueden ser especificadas múltiples veces, en cuyo caso se listarán todos los trabajos para todos los usuarios.
-U usuario, --not-user usuario
Listar todos los trabajos en cola para usuarios distintos al nombrado. Estas opciones pueden ser especificadas múltiples veces, en cuyo caso no se listarán trabajos de ninguno de los usuarios especificados. Estas opciones no pueden usarse con -u o --user.
-c comando, --command comando
Listar todos los trabajos que solicitan la ejecución del comando nombrado. Si comando es ALL esto listará todos los trabajos que solicitan la ejecución de algún comando (en contraposición a simplemente solicitar una transferencia de archivos). Estas opciones pueden ser especificadas múltiples veces, en cuyo caso se listarán todos los trabajos que solicitan cualquiera de los comandos.
-C comando, --not-command comando
Listar todos los trabajos que solicitan la ejecución de algún comando distinto al comando nombrado, o, si comando es ALL, listar todos los trabajos que simplemente solicitan una transferencia de archivos (en contraposición a solicitar la ejecución de algún comando). Estas opciones pueden ser especificadas múltiples veces, en cuyo caso no se listará ningún trabajo que solicite uno de los comandos especificados. Estas opciones no pueden usarse con -c o --command.
-o horas, --older-than horas
Listar todos los trabajos en cola de más de la cantidad de horas dada. Si se usa con --list solo se listarán los sistemas cuyo trabajo más antiguo tenga más de la cantidad de horas dada.
-y horas, --younger-than horas
Listar todos los trabajos en cola de menos de la cantidad de horas dada. Si se usa con --list solo se listarán los sistemas cuyo trabajo más antiguo tenga menos de la cantidad de horas dada.
-k jobid, --kill jobid
Eliminar el trabajo nombrado. El ID del trabajo se muestra en el formato de salida por defecto, así como con la opción -j o --jobid de uucp (1) o uux (1). Un trabajo solo puede ser eliminado por el usuario que lo creó, o por el administrador de UUCP o el superusuario. Las opciones -k o --kill pueden usarse múltiples veces en la línea de comandos para eliminar varios trabajos.
-r jobid, --rejuvenate jobid
Rejuvenecer el trabajo nombrado. Esto lo marcará como invocado en el momento actual, afectando la salida de las opciones -o, --older-than, -y, o --younger-than y preservándolo de cualquier demonio de limpieza automática. El ID del trabajo se muestra en el formato de salida por defecto, así como con las opciones -j o --jobid de uucp (1) o uux (1). Un trabajo solo puede ser rejuvenecido por el usuario que lo creó, o por el administrador de UUCP o el superusuario. Las opciones -r o --rejuvenate pueden usarse múltiples veces en la línea de comandos para rejuvenecer varios trabajos.
-q, --list
Mostrar el estado de los comandos, ejecuciones y conversaciones para todos los sistemas remotos para los cuales hay comandos o ejecuciones en cola. Las opciones -s, --system, -S, --not-system, -o, --older-than, -y, y --younger-than pueden usarse para restringir los sistemas que se listan. Los sistemas para los cuales no hay comandos o ejecuciones en cola nunca se listarán.
-m, --status
Mostrar el estado de las conversaciones para todos los sistemas remotos.
-p, --ps
Mostrar el estado de todos los procesos que mantienen bloqueos de UUCP en sistemas o puertos.
-i, --prompt
Para cada trabajo listado, preguntar si se debe eliminar el trabajo o no. Si el primer carácter de la línea de entrada es y o Y el trabajo será eliminado.
-K, --kill-all
Eliminar automáticamente cada trabajo listado. Esto puede ser útil para scripts de limpieza automática, en conjunción con las opciones --mail y --notify.
-R, --rejuvenate-all
Rejuvenecer automáticamente cada trabajo listado. Esto no puede usarse con --kill-all.
-M, --mail
Para cada trabajo listado, enviar correo al administrador de UUCP. Si el trabajo es eliminado (debido a --kill-all o --prompt con una respuesta afirmativa) el correo lo indicará. Un comentario especificado por la opción --comment puede ser incluido. Si el trabajo es una ejecución, la porción inicial de su entrada estándar será incluida en el mensaje de correo; el número de líneas a incluir puede ser establecido con la opción --mail-lines (el valor por defecto es 100). Si la entrada estándar contiene caracteres nulos, se asume que es un archivo binario y el mensaje contendrá solo el nombre de archivo y no se incluirá su contenido en el mensaje de correo.
-N, --notify
Similar a -M, --mail, pero solo envía correo si el trabajo es eliminado.
-Q, --no-list
No listar explícitamente los trabajos que cumplen los criterios de selección. Útil cuando se usan las opciones -K, --kill-all o -R, --rejuvenate-all para realizar acciones sin mostrar la lista de trabajos afectados.
-B lines, --mail-lines lines
Establecer el número de líneas de la entrada estándar de un trabajo de ejecución a incluir en el correo electrónico de notificación (por defecto es 100). Esta opción solo tiene efecto cuando se usan las opciones -M, --mail o -N, --notify en trabajos de ejecución.

EJEMPLOS

Para ver todos los trabajos de transferencia de archivos en cola para el usuario actual:

uustat

Para ver todos los trabajos en cola para el sistema "zeus":

uustat -s zeus

Para ver todas las solicitudes de ejecución en cola para el usuario "mary":

uustat -e -u mary

Para eliminar el trabajo con ID "12345":

uustat -k 12345

Para eliminar todos los trabajos en cola para el sistema "hades" que tengan más de 7 días de antigüedad:

uustat -s hades -o 168 -K

Para ver el estado de todas las conversaciones de UUCP:

uustat -m

Para ver qué procesos de UUCP están manteniendo bloqueos:

uustat -p

VER TAMBIÉN

uucp(1), uux(1), uuxqt(8)

DIAGNÓSTICOS

El comando uustat reportará problemas al intentar acceder a los archivos de estado o al ejecutar las acciones solicitadas (por ejemplo, si no tiene los permisos necesarios para eliminar un trabajo).

HISTORIA

El comando uustat fue originalmente parte del paquete UUCP de AT&T. Su comportamiento y opciones pueden variar ligeramente entre diferentes implementaciones de UUCP.

uustat(1) - Arch manual pages

NOMBRE

uustat

resumen de trabajos de UUCP

SINOPSIS

uustat [-[aA]] [-c command] [-e] [-f file] [-i] [-K] [-l] [-m] [-n type] [-p] [-q] [-r] [-s system] [-t] [-u user] [-v] [-x type] [--all] [--asctime] [--command command] [--config file] [--comment comment] [--debug type] [--executions] [--help] [--jobid jobid] [--kill jobid] [--kill-all] [--list] [--mail] [--mail-lines lines] [--newer-than date] [--no-command] [--no-list] [--no-system] [--no-user] [--older-than date] [--prompt] [--ps] [--quiet] [--rejuvenate jobid] [--status] [--system system] [--user user] [--version] [--verbose] [--w comment] [--wait jobid]

DESCRIPCIÓN

El comando uustat se utiliza para comprobar el estado de los trabajos enviados a través de UUCP. Puede mostrar el estado de todos los trabajos, trabajos pendientes de ejecución, sistemas con trabajos en cola, o procesos UUCP activos.

Las opciones disponibles permiten filtrar los trabajos por sistema, usuario, comando, fecha, etc., así como realizar acciones como cancelar trabajos, solicitar notificaciones por correo, o depurar el funcionamiento del programa.

OPCIONES

-a, -A, --all
Mostrar todos los trabajos pendientes y ejecutados. Si se usa junto con otras opciones de filtrado, solo se mostrarán los trabajos que coincidan con los criterios especificados.
-c
Ignorado.
-e, --executions
Mostrar sólo las solicitudes de ejecución pendientes.
-f file
Ignorado.
-i, --prompt
Pedir confirmación antes de ejecutar cualquier acción que modifique el estado de los trabajos (como cancelar o reenviar).
-K, --kill-all
Cancelar todos los trabajos pendientes y en ejecución. Esta opción sobrescribe cualquier otra opción de filtrado de trabajos.
-l, --list
Mostrar el estado de todos los sistemas remotos con trabajos en cola.
-m, --mail
Enviar correo electrónico al usuario que solicitó el trabajo cuando este se complete o falle. El contenido del correo es idéntico al que se envía con la opción -N o --notify.
-n type
Ignorado.
-p, --ps
Mostrar el estado de todos los procesos que tienen bloqueos de UUCP. El formato de salida depende del sistema, ya que uustat invoca simplemente ps(1) en cada proceso que mantiene un bloqueo.
-q, --quiet
Suprimir la salida detallada. Sólo se mostrarán los mensajes de error críticos.
-r, --rejuvenate jobid
Restablecer el temporizador de un trabajo específico, haciendo que parezca más reciente. Esto puede ser útil para evitar que trabajos antiguos se cancelen automáticamente.
-s system, --system system
Mostrar sólo los trabajos que van dirigidos al sistema especificado.
-t, --status
Mostrar el estado de la conversación con todos los sistemas remotos. Si la última conversación falló, uustat indicará cuántos intentos se han realizado para llamar al sistema. Si el período de reintento está impidiendo actualmente las llamadas a ese sistema, uustat también mostrará la hora en que se permitirá la próxima llamada.
-u user, --user user
Mostrar sólo los trabajos enviados por el usuario especificado.
-v, --version
Informar de la información de la versión y salir.
-x type, --debug type
Activar tipos de depuración específicos. Los siguientes tipos son reconocidos: abnormal, chat, handshake, uucp-proto, proto, port, config, spooldir, execute, incoming, outgoing. Sólo abnormal, config, spooldir y execute tienen sentido para uustat.

Se pueden dar varios tipos, separados por comas, y la opción --debug puede aparecer varias veces. También se puede dar un número, que activará ese número de tipos de la lista anterior; por ejemplo, --debug 2 es equivalente a --debug abnormal,chat.

-N, --notify
Para cada trabajo listado, enviar un correo electrónico al usuario que solicitó el trabajo. El correo es idéntico al enviado por las opciones -M o --mail.
-W comment, --comment comment
Especificar un comentario que se incluirá en el correo enviado con las opciones -M, --mail, -N, o --notify.
-B lines, --mail-lines lines
Cuando las opciones -M, --mail, -N, o --notify se utilizan para enviar correo sobre una ejecución con entrada estándar, esta opción controla el número de líneas de entrada estándar a incluir en el mensaje. El valor predeterminado es 100.
-Q, --no-list
No listar realmente el trabajo, sino sólo realizar las acciones indicadas por las opciones -i, --prompt, -K, --kill-all, -M, --mail, -N o --notify.
-x type, --debug type
Activar tipos de depuración específicos. Los siguientes tipos son reconocidos: abnormal, chat, handshake, uucp-proto, proto, port, config, spooldir, execute, incoming, outgoing. Sólo abnormal, config, spooldir y execute tienen sentido para uustat.

Se pueden dar varios tipos, separados por comas, y la opción --debug puede aparecer varias veces. También se puede dar un número, que activará ese número de tipos de la lista anterior; por ejemplo, --debug 2 es equivalente a --debug abnormal,chat.

-I file, --config file
Establecer el archivo de configuración a utilizar. Es posible que esta opción no esté disponible, dependiendo de cómo se compiló uustat.
-v, --version
Informar de la información de la versión y salir.
--help
Imprimir un mensaje de ayuda y salir.

EJEMPLOS

uustat --all
Mostrar el estado de todos los trabajos. Una línea de salida de ejemplo es la siguiente: 

bugsA027h bugs ian 04-01 13:50 Executing rmail ian@airs.com (sending 1283 bytes)
El formato es 

jobid system user queue-date command (size)
El jobid puede pasarse a las opciones --kill o --rejuvenate. El tamaño indica cuántos datos se van a transferir al sistema remoto y está ausente para una solicitud de recepción de archivo. Las opciones --system, --not-system, --user, --not-user, --command, --not-command, --older-than, y --younger-than pueden utilizarse para controlar qué trabajos se listan. 
uustat --executions
Mostrar el estado de las solicitudes de ejecución en cola. Una línea de salida de ejemplo es la siguiente: 

bugs bugs!ian 05-20 12:51 rmail ian
El formato es 

system requestor queue-date command
Las opciones --system, --not-system, --user, --not-user, --command, --not-command, --older-than, y --younger-than pueden utilizarse para controlar qué solicitudes se listan. 
uustat --list
Mostrar el estado de todos los sistemas con comandos en cola. Una línea de salida de ejemplo es la siguiente: 

bugs            4C (1 hour)   0X (0 secs) 04-01 14:45 Dial failed
Esto indica el sistema, el número de comandos en cola, la antigüedad del comando más antiguo en cola, el número de ejecuciones locales en cola, la antigüedad de la ejecución más antigua en cola, la fecha de la última conversación y el estado de esa conversación. 
uustat --status
Mostrar el estado de la conversación para todos los sistemas remotos. Una línea de salida de ejemplo es la siguiente: 

bugs           04-01 15:51 Conversation complete
Esto indica el sistema, la fecha de la última conversación y el estado de esa conversación. Si la última conversación falló, uustat indicará cuántos intentos se han realizado para llamar al sistema. Si el período de reintento está impidiendo actualmente las llamadas a ese sistema, uustat también mostrará la hora en que se permitirá la próxima llamada. 
uustat --ps
Mostrar el estado de todos los procesos que tienen bloqueos de UUCP. El formato de salida depende del sistema, ya que uustat simplemente invoca ps (1) en cada proceso que tiene un bloqueo. 


uustat --command rmail --older-than 168 --kill-all --no-list --mail --notify --comment "Queued for over 1 week"
Esto cancelará todos los comandos rmail que han estado en cola esperando la entrega durante más de 1 semana (168 horas). Para cada comando de este tipo, se enviará un correo electrónico tanto al administrador de UUCP como al usuario que solicitó la ejecución de rmail. El mensaje de correo enviado incluirá la cadena proporcionada por la opción --comment. La opción --no-list evita que se listen los trabajos en la terminal, por lo que cualquier salida del programa serán mensajes de error.
