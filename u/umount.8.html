UMOUNT(8) Administración del Sistema UMOUNT(8)

NOMBRE

umount - desmontar sistemas de archivos

SINOPSIS

umount -a [-dflnrv] [-t tipo_fs] [-O opción...]

umount [-dflnrv] {directorio|dispositivo}

umount -h|-V

DESCRIPCIÓN

El comando umount desmonta el/los sistema(s) de archivos mencionado(s) de la jerarquía de archivos. Un sistema de archivos se especifica dando el directorio donde ha sido montado. Dar el dispositivo especial en el que reside el sistema de archivos también puede funcionar, pero es obsoleto, principalmente porque fallará en caso de que ese dispositivo haya sido montado en más de un directorio.

Tenga en cuenta que un sistema de archivos no se puede desmontar cuando está 'ocupado', por ejemplo, cuando hay archivos abiertos en él, o cuando algún proceso tiene su directorio de trabajo allí, o cuando un archivo de intercambio en él está en uso. El proceso infractor podría incluso ser el propio umount; abre la libc, y la libc a su vez puede abrir, por ejemplo, archivos de localización. Un desmontaje perezoso evita este problema, pero puede introducir otros problemas. Consulte la descripción de --lazy a continuación.

OPCIONES

-a, --all

Todos los sistemas de archivos descritos en /proc/self/mountinfo (o en el obsoleto /etc/mtab) se desmontan, excepto los sistemas de archivos proc, devfs, devpts, sysfs, rpc_pipefs y nfsd. Esta lista de sistemas de archivos puede ser reemplazada por la opción --types de umount.

-A, --all-targets

Desmonta todos los puntos de montaje en el espacio de nombres de montaje actual para el sistema de archivos especificado. El sistema de archivos puede especificarse por uno de los puntos de montaje o el nombre del dispositivo (o UUID, etc.). Cuando esta opción se usa junto con --recursive, todos los montajes anidados dentro del sistema de archivos se desmontan recursivamente. Esta opción solo se admite en sistemas donde /etc/mtab es un enlace simbólico a /proc/mounts.

-c, --no-canonicalize

No canonicalizar rutas. La canonicalización de rutas se basa en las llamadas al sistema stat(2) y readlink(2). Estas llamadas al sistema pueden colgarse en algunos casos (por ejemplo, en NFS si el servidor no está disponible). La opción debe usarse con la ruta canónica al punto de montaje.

Esta opción es ignorada silenciosamente por umount para usuarios no root.

Para más detalles sobre esta opción, consulte la página del manual de mount(8). Tenga en cuenta que umount no pasa esta opción a los ayudantes /sbin/umount.tipo.

-d, --detach-loop

Cuando el dispositivo desmontado era un dispositivo de bucle, también libera este dispositivo de bucle. Esta opción no es necesaria para los dispositivos inicializados por mount(8); en este caso, la funcionalidad de "autolimpieza" está habilitada por defecto.

--fake

Hace que se haga todo excepto la llamada al sistema real o la ejecución del ayudante de desmontaje; esto 'simula' el desmontaje del sistema de archivos. Se puede utilizar para eliminar entradas de /etc/mtab obsoleto que se desmontaron anteriormente con la opción -n.

-f, --force

Forzar el desmontaje (en caso de un sistema NFS inalcanzable).

Tenga en cuenta que esta opción no garantiza que el comando umount no se cuelgue. Se recomienda encarecidamente utilizar rutas absolutas sin enlaces simbólicos para evitar llamadas al sistema readlink(2) y stat(2) no deseadas a NFS inalcanzable en umount.

-i, --internal-only

No llamar al ayudante /sbin/umount.sistema_de_archivos incluso si existe. Por defecto, se llama a un programa ayudante de este tipo si existe.

-l, --lazy

Desmontaje perezoso. Desconecta el sistema de archivos de la jerarquía de archivos ahora y limpia todas las referencias a este sistema de archivos tan pronto como ya no esté ocupado.

Se esperaría un reinicio del sistema en un futuro cercano si va a utilizar esta opción para un sistema de archivos de red o un sistema de archivos local con submontajes. El caso de uso recomendado para umount -l es evitar bloqueos al apagar debido a un recurso compartido de red inalcanzable donde un umount normal se colgará debido a un servidor caído o a una partición de red. Los remontajes del recurso no serán posibles.

-N, --namespace ns

Realiza umount en el espacio de nombres de montaje especificado por ns. ns es el PID de un proceso que se ejecuta en ese espacio de nombres o un archivo especial que representa ese espacio de nombres.

umount cambia al espacio de nombres al leer /etc/fstab, escribir /etc/mtab (o escribir en /run/mount) y llama a la llamada al sistema umount(2); de lo contrario, se ejecuta en el espacio de nombres original. Esto significa que el espacio de nombres de montaje de destino no tiene por qué contener bibliotecas u otros requisitos necesarios para ejecutar el comando umount(2).

Consulte mount_namespaces(7) para más información.

-n, --no-mtab

Desmontar sin escribir en /etc/mtab.

-O, --test-opts opción...

Desmontar solo los sistemas de archivos que tienen la opción especificada establecida en /etc/fstab. Se pueden especificar más de una opción en una lista separada por comas. Cada opción puede ir precedida de no para indicar que no se debe tomar ninguna medida para esa opción.

-q, --quiet

Suprimir los mensajes de error de "no montado".

-R, --recursive

Desmontar recursivamente cada directorio especificado. La recursión para cada directorio se detendrá si alguna operación de desmontaje en la cadena falla por cualquier motivo. La relación entre los puntos de montaje se determina mediante las entradas de /proc/self/mountinfo. El sistema de archivos debe especificarse por la ruta del punto de montaje; el desmontaje recursivo por nombre de dispositivo (o UUID) no está admitido. Desde la versión 2.37 también desmonta todos los sistemas de archivos sobremontados (más sistemas de archivos en el mismo punto de montaje).

-r, --read-only

Cuando un desmontaje falla, intente remontar el sistema de archivos como solo lectura.

-t, --types tipo...

Indicar que las acciones solo se tomarán en sistemas de archivos del tipo especificado. Se pueden especificar varios tipos en una lista separada por comas. La lista de tipos de sistemas de archivos puede ir precedida de no para indicar que no se debe tomar ninguna medida para todos los tipos mencionados. Tenga en cuenta que umount lee la información sobre los sistemas de archivos montados del kernel (/proc/mounts) y los nombres de los sistemas de archivos pueden ser diferentes de los nombres de los sistemas de archivos utilizados en /etc/fstab (por ejemplo, "nfs4" frente a "nfs").

-v, --verbose

Modo detallado.

-h, --help

Mostrar texto de ayuda y salir.

-V, --version

Mostrar versión y salir.

DESMONTAJES DE NO SUPERUSUARIO

Normalmente, solo el superusuario puede desmontar sistemas de archivos. Sin embargo, cuando fstab contiene la opción user en una línea, cualquiera puede desmontar el sistema de archivos correspondiente. Para más detalles, consulte la página del manual de mount(8).

Desde la versión 2.34, el comando umount se puede utilizar para realizar la operación de desmontaje también para sistemas de archivos fuse si la tabla de montaje del kernel contiene el ID del usuario. En este caso, la opción de montaje user= de fstab no es necesaria.

Desde la versión 2.35, el comando umount no sale cuando los permisos del usuario son inadecuados según las reglas de seguridad internas de libmount. Elimina los permisos suid y continúa como un usuario regular no root. Esto se puede utilizar para admitir casos de uso donde los permisos de root no son necesarios (por ejemplo, sistemas de archivos fuse, espacios de nombres de usuario, etc.).

NAME

umount — unmount file systems

SYNOPSIS

umount [-c|--delete-loop] [-d|--detach-loop] [-f|--force] [-l|--lazy] [-N namespace] [-R|--recursive] [-r|--read-only] [-v|--verbose] [-h|--help] [-V|--version]

umount -a [-N namespace] [-c|--delete-loop] [-d|--detach-loop] [-f|--force] [-l|--lazy] [-r|--read-only] [-v|--verbose] [-h|--help] [-V|--version]

umount -A [-N namespace] [-c|--delete-loop] [-d|--detach-loop] [-f|--force] [-l|--lazy] [-r|--read-only] [-v|--verbose] [-h|--help] [-V|--version]

umount --mountpoint dir...

umount --source device...

umount --all [-N namespace] [-c|--delete-loop] [-d|--detach-loop] [-f|--force] [-l|--lazy] [-r|--read-only] [-v|--verbose] [-h|--help] [-V|--version]

DESCRIPTION

The umount command is used to detach (or "unmount") a filesystem from the system. The filesystem is specified by its mount point directory or device name. If the filesystem was mounted with certain options, or if the system supports lazy unmounting, the umount command may not necessarily block until the filesystem is fully unmounted.

The -a, -A, and --all options are used to unmount all filesystems listed in /etc/fstab (no-swap and pseudo, except remote filesystem types). The -A option is like -a but also unmounts remote file systems.

Note that umount does not support the -a option for all types. Use findmnt -t type -o SOURCE -n to get a list of filesystems of a specific type.

OPTIONS

Options are grouped together. For example, -r-v is the same as -rv.

The available options are:

-a, --all
Unmount all filesystems mentioned in /etc/fstab that are not specified as "noauto" and are not of pseudo or remote filesystem types. If the -A option is used, remote filesystems are also unmounted.
-A
Unmount all filesystems listed in /etc/fstab, including remote ones.
-c, --delete-loop
When a loop device is unmounted, automatically clear the loop device if it is not used by any other process. See also losetup(8).
-d, --detach-loop
When a loop device is unmounted, detach the loop device. This is equivalent to losetup -d device.
-f, --force
Force unmounting. This option can be used when a filesystem is unresponsive. The use of this option might lead to data loss. This option implies the -l option.
-h, --help
Display help text and exit.
-l, --lazy
Lazy unmount. Detach the filesystem from the file hierarchy now, and clean up all references to the filesystem later. This is useful when a filesystem cannot be unmounted immediately (e.g. it is busy). The filesystem will be properly cleaned up when it is no longer used.
-N, --namespace namespace
Unmount the filesystem in the specified namespace. The namespace is identified by its label or pid.
-n, --no-mtab
Do not update /etc/mtab.
-r, --read-only
Unmount the filesystem read-only. This may be useful for write-protected devices.
-R, --recursive
Unmount filesystem and all filesystems mounted upon it.
--source device...
Unmount the specified device(s). This is a synonym for specifying the device name directly.
--mountpoint dir...
Unmount the specified mount point(s). This is a synonym for specifying the mount point directly.
-v, --verbose
Produce verbose output.
-V, --version
Display version information and exit.

NON-SUPERUSER UMOUNTS

A non-superuser can unmount a filesystem if and only if it was mounted by that user and the following conditions are met: the `userallowed_unmount' option is set in /etc/fstab, and the filesystem is not a setuid or nosuid mount.

LOOP DEVICE

When a filesystem on a loop device is unmounted, the umount(8) command will automatically detach loop device previously initialized by mount(8) command independently of /etc/mtab.

In this case the device is initialized with "autoclear" flag (see losetup(8) output for more details), otherwise it’s necessary to use the option --detach-loop or call losetup -d device. The autoclear feature is supported since Linux 2.6.25.

Note that since Linux v3.7 kernel uses "lazy device destruction". The system just marks the loop device by autoclear flag and destroys it later. If you need to wait for a complete removal of the loop device, call udevadm settle after umount.

EXIT STATUS

umount has the following exit status values (the bits can be ORed):

0

success

1

incorrect invocation or permissions

2

system error (out of memory, cannot fork, no more loop devices)

4

internal mount bug

8

user interrupt

16

problems writing or locking /etc/mtab

32

mount failure

64

some umount succeeded

The command umount -a returns 0 (all succeeded), 32 (all failed), or 64 (some failed, some succeeded).

126

failed to execute external /sbin/umount.<type> mount helper (since util-linux v2.41)

EXTERNAL HELPERS

The syntax of external unmount helpers is:

umount.suffix {directory|device} [-flnrv] [-N namespace] [-t type.subtype]

where suffix is the filesystem type (or the value from a uhelper= or helper= marker in the mtab file). The -t option can be used for filesystems that have subtype support. For example:

umount.fuse -t fuse.sshfs

A uhelper=something marker (unprivileged helper) can appear in the /etc/mtab file when ordinary users need to be able to unmount a mountpoint that is not defined in /etc/fstab (for example for a device that was mounted by udisks(1)).

A helper=type marker in the mtab file will redirect all unmount requests to the /sbin/umount.type helper independently of UID.

Note that /etc/mtab is currently deprecated and helper= and other userspace mount options are maintained by libmount.

The exit status value of the helper is returned as the exit status of umount(8). The value 126 is used if the mount helper program is found, but the execl() failed.

ENVIRONMENT

LIBMOUNT_FSTAB=<path>

overrides the default location of the fstab file (ignored for suid)

LIBMOUNT_DEBUG=all

enables libmount debug output

FILES

/etc/mtab

table of mounted filesystems (deprecated and usually replaced by symlink to /proc/mounts)

/etc/fstab

table of known filesystems

/proc/self/mountinfo

table of mounted filesystems generated by kernel.
