DESCRIPCIÓN

Unbound es una implementación de un resolutor DNS, que realiza caché y validación DNSSEC. Esta es la API de la biblioteca, para usar la biblioteca -lunbound. El demonio servidor se describe en unbound(8). La biblioteca funciona independientemente de un servidor unbound en ejecución y puede usarse para convertir nombres de host en direcciones IP y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de clave pública de los resultados con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Puede crearse y eliminarse en cualquier momento. Crear un nuevo contexto elimina cualquier configuración previa (como claves de confianza) y borra cualquier resultado en caché.

Las funciones son seguras para subprocesos (thread-safe) y un contexto puede usarse en un entorno con subprocesos (así como en uno sin ellos). La resolución (y validación) también se puede realizar de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve el control inmediatamente, para que el procesamiento pueda continuar, mientras los resultados están disponibles más tarde.

Las funciones se discuten a continuación, una por una.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza por defecto. Utilice ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esto, use las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si usa lib openssl (la aplicación llama a estas funciones una vez para la inicialización). Openssl 1.0.0 o posterior utiliza la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y las devoluciones de llamada (callbacks) no se activan para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que le permite especificar una de las opciones del formato de archivo de configuración, consulte unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como la adición de anclas de confianza, existen rutinas especiales. Pase el nombre de la opción con los dos puntos finales ':'.
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene un valor de opción. Algunas opciones no se pueden obtener y otras devuelven una lista separada por saltos de línea. Pase el nombre de la opción sin los dos puntos finales ':'. El valor devuelto debe ser liberado (free(2)) por el llamador.
ub_ctx_config
Una interfaz para usuarios avanzados que le permite especificar un archivo de configuración de unbound, consulte unbound.conf(5), que se lee para la configuración. No todas las opciones son relevantes. Para algunas opciones específicas, como la adición de anclas de confianza, existen rutinas especiales. Esta función solo es segura para subprocesos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no se llame en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se reenviarán las consultas DNS, el resolutor de caché a utilizar. Dirección IP4 o IP6. Reenvía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolutor recursivo. Si el proxy no es compatible con DNSSEC, la validación puede fallar. Se puede llamar varias veces, en cuyo caso las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autorizados a utilizar para una zona particular. Dirección IP4 o IP6. Si la dirección es NULL, se elimina la entrada stub. Establezca isprime en true si lo configura con indicios de raíz (root hints). De lo contrario, es similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas o para agregar varias direcciones para una zona particular. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolutor completo, pero puede usar esta llamada para leer la lista de servidores de nombres a utilizar desde el nombre de archivo dado. Normalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no admiten DNSSEC, la validación puede fallar. Solo se capturan los servidores de nombres, se ignoran el dominio de búsqueda (searchdomain), ndots y otras configuraciones de resolv.conf(5). Si se pasa NULL como fname, se usa "/etc/resolv.conf" (si está en Windows, se selecciona el servidor de nombres configurado a nivel del sistema en su lugar). En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_hosts

DESCRIPTION

This manual page describes the API for the unbound validating, recursive, caching DNS resolver library.

First, create a context with ub_ctx_create(). Then, configure the context using the following functions:

  • ub_ctx_resolvconf() and ub_ctx_config() read nameserver configuration and unbound specific settings from the given filename. Default system resolver configuration is read if no filename is given.

  • ub_ctx_add_ta(), ub_ctx_add_ta_file(), ub_ctx_add_ta_autr() and ub_ctx_trustedkeys() set the trust anchors for DNSSEC validation. They can be provided as a string, a file with zone file format DS and DNSKEY records, a file containing a single managed trust anchor (created by unbound-anchor) or a bind-style configuration file with trusted-keys{} block. At this time it is only possible to add trusted keys before the first resolve is done.

  • ub_ctx_debugout() sets the log output stream. Default is stderr. NULL disables output.

  • ub_ctx_debuglevel() sets the verbosity of the debug output. Higher means more output. Default is 1.

  • ub_ctx_async() enables or disables threaded operation for asynchronous calls. If enabled, it uses threads. If disabled, it forks a child process. Default is disabled.

  • ub_ctx_zone_add() and ub_ctx_data_add() add local zones and data to the authority information of the resolver. This can be used for custom DNS data or for creating a local DNS server.

  • ub_ctx_zone_remove() and ub_ctx_data_remove() remove local zone information.

  • ub_ctx_print_local_zones() prints the local authority information to the debug output.

After configuration, you can perform DNS lookups:

  • ub_resolve() performs a synchronous DNS lookup and validation. It returns the result in a newly allocated struct ub_result.

  • ub_resolve_async() performs an asynchronous DNS lookup and validation. A callback function is called when the result is ready. The callback receives a pointer to user data (mydata), an error code, and a pointer to the result structure. The result structure is allocated by the library and must be freed by the caller using ub_resolve_free().

For asynchronous operations, you need to interact with the context's file descriptor and processing routines:

  • ub_fd() returns a file descriptor that can be polled for readability. When it becomes readable, it means results are available.

  • ub_poll() checks if there is any new information to read from the context without blocking. Returns non-zero if data is available.

  • ub_process() processes any pending results and invokes callbacks for asynchronous queries. This should be called when ub_poll() returns non-zero or when the file descriptor returned by ub_fd() indicates readability.

  • ub_wait() waits until all asynchronous queries in the context are finished. It automatically calls ub_process() internally. After the wait, there are no more outstanding asynchronous queries.

  • ub_cancel() cancels an asynchronous query that is in progress. Provide the async_id returned by ub_resolve_async().

Finally, free the context when done using ub_ctx_destroy() and the result structure using ub_resolve_free(). ub_strerror() converts error codes to human-readable strings.

The function ub_resolve_async may return an async_id. This ID can be used with ub_cancel() to cancel the request. If you pass a NULL pointer for async_id, the ID is not returned.

The trust anchor functions (ub_ctx_add_ta, ub_ctx_add_ta_file, ub_ctx_add_ta_autr, ub_ctx_trustedkeys) must be called before the first resolve operation. The trust anchor is added to the context. At this time it is only possible to add trusted keys before the first resolve is done.

ub_ctx_create
Create a new unbound context. Returns a pointer to the context or NULL on failure.
ub_ctx_destroy
Destroy the unbound context and free all associated resources.
ub_ctx_resolvconf
Read system resolver configuration (nameservers, search domains) from the given file. If filename is NULL, uses system default (/etc/resolv.conf).
ub_ctx_config
Read unbound configuration settings from the given file. If filename is NULL, uses default unbound configuration file.
ub_ctx_add_ta
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
ub_ctx_add_ta_autr
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta_file
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_trustedkeys
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_debugout
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
ub_ctx_debuglevel
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
ub_ctx_async
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
ub_poll
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
ub_wait
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
ub_fd
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
ub_process
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
ub_resolve
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
ub_resolve_async
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

ub_cancel
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
ub_resolve_free
Free struct ub_result contents after use.
ub_strerror
Convert error value from one of the unbound library functions to a human readable string.
ub_ctx_print_local_zones
Debug printout the local authority information to debug output.
ub_ctx_zone_add
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
ub_ctx_zone_remove
Delete zone from local authority info.
ub_ctx_data_add
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
ub_ctx_data_remove
Delete local authority data from the name given.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Else, they are not both true, one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.
