USER@.SERVICE(5) user@.service USER@.SERVICE(5)

NOMBRE

user@.service, user-runtime-dir@.service, systemd-user-runtime-dir - Unidades del sistema para iniciar el gestor de usuario

SINOPSIS

user@UID.service

user-runtime-dir@UID.service

/usr/lib/systemd/systemd-user-runtime-dir

user-UID.slice

DESCRIPCIÓN

El gestor del sistema systemd(1) (PID 1) inicia instancias del gestor de usuario como user@UID.service, utilizando el UID numérico del usuario como identificador de la instancia. Estas instancias utilizan el mismo ejecutable que el gestor del sistema, pero ejecutándose en un modo que inicia un conjunto diferente de unidades. Cada instancia de systemd --user gestiona una jerarquía de unidades específicas para ese usuario. Consulte systemd(1) para una discusión sobre las unidades y systemd.special(7) para una lista de unidades que forman la base de las jerarquías de unidades del sistema y del usuario.

user@UID.service va acompañada de la unidad del sistema user-runtime-dir@UID.service, que crea el directorio de tiempo de ejecución del usuario /run/user/UID al iniciarse y lo elimina al detenerse. También puede aplicar configuraciones de cuotas de tiempo de ejecución en /tmp/ y/o /dev/shm/ para el usuario. user-runtime-dir@UID.service ejecuta el binario systemd-user-runtime-dir para realizar el trabajo real.

Los procesos del usuario pueden ser iniciados por la instancia user@.service, en cuyo caso formarán parte de esa unidad en la jerarquía del sistema. También pueden iniciarse en otro lugar, por ejemplo, por sshd(8) o un gestor de pantalla como gdm, en cuyo caso formarán una unidad .scope (consulte systemd.scope(5)). Tanto user@UID.service como las unidades de scope se agrupan bajo user-UID.slice.

Las slices individuales user-UID.slice se agrupan bajo user.slice, consulte systemd.special(7).

CONTROL DE RECURSOS PARA USUARIOS CONECTADOS

Las opciones que controlan los recursos disponibles para los usuarios conectados se pueden configurar en varios niveles. Como se describe en la sección anterior, user.slice contiene procesos de todos los usuarios, por lo que cualquier límite de recursos en esa slice se aplica a todos los usuarios juntos. La forma habitual de configurarlos sería a través de drop-ins, por ejemplo, /etc/systemd/system/user.slice.d/resources.conf.

Los procesos de un solo usuario se agrupan bajo user-UID.slice. Los límites de recursos para ese usuario se pueden configurar a través de drop-ins para esa unidad, por ejemplo, /etc/systemd/system/user-1000.slice.d/resources.conf. Si los límites deben aplicarse a todos los usuarios en su lugar, se pueden configurar a través de drop-ins para el nombre truncado de la unidad, user-.slice. Por ejemplo, la configuración en /etc/systemd/system/user-.slice.d/resources.conf se incluye en todas las unidades user-UID.slice, consulte systemd.unit(5) para una discusión sobre el mecanismo de drop-in.

Cuando un usuario inicia sesión y se crea una unidad .scope para la sesión (consulte la sección anterior), la creación del scope puede ser gestionada a través de pam_systemd(8). Este módulo PAM se comunica con systemd-logind(8) para crear el scope de la sesión y proporcionar acceso a los recursos de hardware. Los límites de recursos para el scope se pueden configurar a través de la configuración del módulo PAM, consulte pam_systemd(8). La configuración a través de la configuración normal de la unidad también es posible, pero dado que el nombre de la unidad de slice es generalmente impredecible, esto es menos útil.

En general, cualquier recurso que se aplique a las unidades se puede establecer para user@UID.service y las unidades de slice mencionadas anteriormente, consulte systemd.resource-control(5) para una visión general.

EJEMPLOS

Ejemplo 1. Jerarquía de grupos de control con dos usuarios conectados

$ systemd-cgls
Control group /:
-.slice
├─user.slice
│ ├─user-1000.slice
│ │ ├─user@1000.service
│ │ │ ├─pulseaudio.service
│ │ │ │ └─2386 /usr/bin/pulseaudio --daemonize=no
│ │ │ └─gnome-terminal-server.service
│ │ │   └─init.scope
│ │ │     ├─ 4127 /usr/libexec/gnome-terminal-server
│ │ │     └─ 4198 zsh
│ │ └─session-4.scope
│ │   ├─ 1264 gdm-session-worker [pam/gdm-password]
│ │   ├─ 2339 /usr/bin/gnome-shell
│ │   ...
│ │ ├─session-19.scope
│ │   ├─6497 sshd: zbyszek [priv]
│ │   ├─6502 sshd: zbyszek@pts/6
│ │   ├─6509 -zsh
│ │   └─6602 systemd-cgls --no-pager
│ ...
│ └─user-1001.slice
│   ├─session-20.scope
│   │ ├─6675 sshd: guest [priv]
│   │ ├─6708 sshd: guest@pts/6
│   │ └─6717 -bash
│   └─user@1001.service
│     ├─init.scope
│     │ ├─6680 /usr/lib/systemd/systemd --user
│     │ └─6688 (sd-pam)
│     └─sleep.service
│       └─6706 /usr/bin/sleep 30
...

El usuario con UID 1000 está conectado usando gdm (session-4.scope) y ssh(1) (session-19.scope), y también tiene una instancia de gestor de usuario en ejecución (user@1000.service). El usuario con UID 1001 está conectado usando ssh (session-20.scope) y también tiene una instancia de gestor de usuario en ejecución (user@1001.service). Todas estas son unidades de sistema (hojas), y forman parte de la jerarquía de slices, con user-1000.slice y user-1001.slice debajo de user.slice. Las unidades de usuario son visibles debajo de las instancias de user@.service (pulseaudio.service, gnome-terminal-server.service, init.scope, sleep.service).

Ejemplo 2. Límites de recursos de usuario por defecto

$ systemctl cat user-1000.slice
# /usr/lib/systemd/system/user-.slice.d/10-defaults.conf
# ...
[Unit]
Description=User Slice of UID %j
After=systemd-user-sessions.service
[Slice]
TasksMax=33%

Las unidades user-UID.slice por defecto no tienen un archivo de unidad. Los límites de recursos se establecen a través de un drop-in, que puede ser fácilmente reemplazado o extendido siguiendo los mecanismos de drop-in estándar discutidos en la primera sección.
