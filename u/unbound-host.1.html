NOMBRE

unbound-host - Utilidad de consulta DNS de Unbound 1.24.2.

SINOPSIS

unbound-host [-C archivo_config] [-vdhr46D] [-c clase] [-t tipo] [-y clave] [-f archivo_clave] [-F archivo_clave_named] nombre_host

DESCRIPCIÓN

unbound-host utiliza el resolvedor de validación Unbound para consultar el nombre de host y mostrar los resultados. Con la opción -v, muestra el estado de validación: seguro, inseguro, falso (fallo de seguridad).

Por defecto, no lee ningún archivo de configuración. Intenta alcanzar los servidores raíz de Internet. Con -C se puede leer un archivo de configuración de unbound y con -r se puede leer resolv.conf.

Las opciones disponibles son:

nombre_host
Este nombre se resuelve (se consulta en el DNS). Si se proporciona una dirección IPv4 o IPv6, se realiza una consulta inversa.
-h
Muestra la versión y la ayuda de las opciones de la línea de comandos.
-v
Habilita la salida detallada y muestra los resultados de validación en cada línea. Seguro significa que la respuesta NXDOMAIN (nombre de dominio inexistente), nodata (datos inexistentes) o de datos positivos se validó correctamente con una de las claves. Inseguro significa que ese nombre de dominio no tiene seguridad configurada. Falso (fallo de seguridad) significa que la respuesta falló una o más comprobaciones, es probable que sea incorrecta, obsoleta, manipulada o errónea.
-d
Habilita la salida de depuración en stderr. Un -d muestra lo que hacen el resolvedor y el validador, y puede indicar lo que está sucediendo. Más veces, -d -d, produce mucha salida, con cada paquete enviado y recibido.
-c <clase>
Especifica la clase para la consulta, el valor predeterminado es IN (Internet).
-t <tipo>
Especifica el tipo de datos a consultar. Por defecto, se buscan datos de manejador de correo y de IPv4, IPv6, o punteros de nombre de dominio para consultas inversas.
-y <clave>
Especifica una clave pública para usar como ancla de confianza. Esta es la base para una cadena de confianza que se construye desde el ancla de confianza hasta la respuesta, para validar el mensaje de respuesta. Puede proporcionarse como un registro DS o DNSKEY. Por ejemplo:
-y "example.com DS 31560 5 1 1CFED84787E6E19CCF9372C1187325972FE546CD"
-D
Habilita la validación DNSSEC. Lee el ancla raíz de la configuración predeterminada del ancla raíz en la ubicación predeterminada, /etc/trusted-key.key.
-f <archivo_clave>
Lee claves de un archivo. Cada línea tiene un registro DS o DNSKEY, en el formato como para -y. El formato de archivo de zona, el mismo que producen dig y drill.
-F <archivo_clave_named>
Lee claves de un archivo named.conf estilo BIND. Solo se leen las entradas trusted-key {};.
-C <archivo_config>
Utiliza el unbound.conf especificado para inicializar libunbound(3). Pásalo como primer argumento si deseas anular algunas opciones del archivo de configuración con argumentos posteriores en la línea de comandos.
-r
Lee /etc/resolv.conf, y usa los servidores DNS de reenvío de allí (los que podrían haber sido establecidos por DHCP). Más información en resolv.conf(5). Rompe la validación si esos servidores no soportan DNSSEC.
-4
Usa únicamente la red IPv4 para enviar paquetes.
-6
Usa únicamente la red IPv6 para enviar paquetes.

EJEMPLOS

Algunos ejemplos de uso. Las claves mostradas a continuación son falsas, por lo tanto, se encontrará un fallo de seguridad.

$ unbound-host www.example.com
$ unbound-host -v -y "example.com DS 31560 5 1 1CFED84787E6E19CCF9372C1187325972FE546CD" www.example.com
$ unbound-host -v -y "example.com DS 31560 5 1 1CFED84787E6E19CCF9372C1187325972FE546CD" 192.0.2.153

CÓDIGO DE SALIDA

El programa unbound-host sale con el código de estado 1 en caso de error, 0 si no hay error. Los datos pueden no estar disponibles con código de salida 0, el código de salida 1 significa que la consulta encontró un error fatal.
