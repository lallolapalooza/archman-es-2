NOMBRE

udev - Gestión dinámica de dispositivos

DESCRIPCIÓN

udev suministra al software del sistema eventos de dispositivos, gestiona los permisos de los nodos de dispositivos y puede crear enlaces simbólicos adicionales en el directorio /dev/, o renombrar interfaces de red. El kernel generalmente solo asigna nombres de dispositivos impredecibles basados en el orden de descubrimiento. Los enlaces simbólicos significativos o los nombres de dispositivos de red proporcionan una forma de identificar de forma fiable los dispositivos basándose en sus propiedades o su configuración actual.

El demonio udev, systemd-udevd.service(8), recibe uevents de dispositivos directamente del kernel cada vez que un dispositivo se añade o se elimina del sistema, o cambia su estado. Cuando udev recibe un evento de dispositivo, compara su conjunto de reglas configuradas contra varios atributos del dispositivo para identificar el dispositivo. Las reglas que coinciden pueden proporcionar información adicional del dispositivo para ser almacenada en la base de datos de udev o para ser utilizada para crear nombres de enlaces simbólicos significativos.

Toda la información del dispositivo que udev procesa se almacena en la base de datos de udev y se envía a posibles suscriptores de eventos. El acceso a todos los datos almacenados y a las fuentes de eventos se proporciona a través de la biblioteca libudev.

ARCHIVOS DE REGLAS

Las reglas de udev se leen de los archivos ubicados en los directorios de reglas del sistema /usr/lib/udev/rules.d y /usr/local/lib/udev/rules.d, el directorio volátil de tiempo de ejecución /run/udev/rules.d y el directorio local de administración /etc/udev/rules.d. Todos los archivos de reglas se ordenan y procesan colectivamente en orden léxico, independientemente de los directorios en los que residan. Sin embargo, los archivos con nombres idénticos se reemplazan entre sí. Los archivos en /etc/ tienen la máxima prioridad, los archivos en /run/ prevalecen sobre los archivos con el mismo nombre bajo /usr/. Esto se puede usar para anular un archivo de reglas proporcionado por el sistema con un archivo local si es necesario; un enlace simbólico en /etc/ con el mismo nombre que un archivo de reglas en /usr/lib/, que apunte a /dev/null, deshabilita el archivo de reglas por completo. Los archivos de reglas deben tener la extensión .rules; se ignoran otras extensiones.

Cada línea en el archivo de reglas contiene al menos un par clave-valor. Excepto las líneas vacías o las líneas que comienzan con "#", que se ignoran. Hay dos tipos de claves: coincidencia y asignación. Si todas las claves de coincidencia coinciden con sus valores, la regla se aplica y las claves de asignación reciben los valores especificados.

Una regla coincidente puede renombrar una interfaz de red, añadir enlaces simbólicos que apunten al nodo del dispositivo, o ejecutar un programa especificado como parte del manejo del evento.

Una regla consta de una lista separada por comas de una o más expresiones clave-operador-valor. Cada expresión tiene un efecto distinto, dependiendo de la clave y el operador utilizados.

Operadores

"=="

Compara para igualdad. (La clave especificada tiene el valor especificado).

"!="

Compara para desigualdad. (La clave especificada no tiene el valor especificado, o la clave especificada no está presente en absoluto).

"="

Asigna un valor a una clave. Las claves que representan una lista se restablecen y solo se asigna este único valor.

"+="

Añade el valor a una clave que contiene una lista de entradas.

"-="

Elimina el valor de una clave que contiene una lista de entradas.

Añadido en la versión 217.

":="

Asigna un valor a una clave de forma definitiva; prohíbe cualquier cambio posterior.

Añadido en la versión 247.

Valores

Los valores se escriben como cadenas entre comillas dobles, como ("cadena"). Para incluir una comilla (") en el valor, precederla con una barra invertida (\"). Cualquier otra aparición de una barra invertida seguida de un carácter no se escapa. Es decir, "\t\n" se trata como cuatro caracteres: barra invertida, te minúscula, barra invertida, ene minúscula.

La cadena puede ir precedida por una e minúscula (e"cadena\n") para marcar la cadena como escapada al estilo C, ver Secuencias de escape en C[1]. Por ejemplo, e"cadena\n" se analiza como 7 caracteres: 6 letras minúsculas y un salto de línea. Esto puede ser útil para escribir caracteres especiales cuando un controlador del kernel los requiere.

La cadena puede ir precedida por una i minúscula (i"cadena") para indicar que la cadena o el patrón coincidirá sin distinguir mayúsculas de minúsculas. Por ejemplo, i"foo" coincidirá con "foo", "FOO", "FoO" y así sucesivamente. El prefijo solo se puede utilizar para reglas de coincidencia ("==") o de no coincidencia ("!="), por ejemplo, ATTR{foo}==i"abcd".

Tenga en cuenta que el carácter NUL no está permitido en ninguna variante de cadena.

Claves

Los siguientes nombres de claves se pueden utilizar para comparar propiedades del dispositivo. Algunas de las claves también comparan propiedades de los dispositivos padre en sysfs, no solo del dispositivo que generó el evento. Si múltiples claves que coinciden con un dispositivo padre se especifican en una sola regla, todas estas claves deben coincidir en el mismo dispositivo padre.

ACTION

Coincide con el nombre de la acción del evento.

DEVPATH

Coincide con el devpath del dispositivo del evento.

KERNEL

Coincide con el nombre del dispositivo del evento.

KERNELS

Busca en el devpath hacia arriba un nombre de dispositivo coincidente.

NAME

Coincide con el nombre de una interfaz de red. Se puede utilizar una vez que la clave NAME se haya establecido en una de las reglas precedentes.

SYMLINK

Coincide con el nombre de un enlace simbólico que apunta al nodo. Se puede utilizar una vez que una clave SYMLINK se haya establecido en una de las reglas precedentes. Puede haber múltiples enlaces simbólicos; solo uno necesita coincidir. Si el operador es "!=", el token devuelve verdadero solo si no se coincide ningún enlace simbólico.

SUBSYSTEM

Coincide con el subsistema del dispositivo del evento.

SUBSYSTEMS

Busca en el devpath hacia arriba un nombre de subsistema de dispositivo coincidente.

DRIVER

Coincide con el nombre del controlador del dispositivo del evento. Solo establezca esta clave para los dispositivos que estén vinculados a un controlador en el momento en que se genera el evento.

DRIVERS

Busca en el devpath hacia arriba un nombre de controlador de dispositivo coincidente.

ATTR{nombre_archivo}

Compara el valor del atributo sysfs del dispositivo del evento.

Los espacios en blanco al final de los valores de los atributos se ignoran a menos que el valor de coincidencia especificado contenga espacios en blanco al final.

ATTRS{nombre_archivo}

Busca en el devpath hacia arriba un dispositivo con valores de atributos sysfs coincidentes. Si se especifican múltiples coincidencias de ATTRS, todas deben coincidir en el mismo dispositivo.

Los espacios en blanco al final de los valores de los atributos se ignoran a menos que el valor de coincidencia especificado contenga espacios en blanco al final.

SYSCTL{parámetro_kernel}

Compara el valor de un parámetro del kernel.

Añadido en la versión 240.

ENV{clave}

Compara contra el valor de una propiedad del dispositivo.

CONST{clave}

Compara contra una constante del sistema. Las claves soportadas son:

"arch"

Arquitectura del sistema. Ver ConditionArchitecture= en systemd.unit(5) para valores posibles.

Añadido en la versión 244.

"virt"

Entorno de virtualización del sistema. Ver systemd-detect-virt(1) para valores posibles.

Añadido en la versión 244.

"cvm"

Tecnología de virtualización confidencial del sistema. Ver systemd-detect-virt(1) para valores posibles.

Añadido en la versión 254.

Las claves desconocidas nunca coincidirán.

Añadido en la versión 244.

TAG

Compara contra una de las etiquetas del dispositivo. Se puede utilizar una vez que una clave TAG se haya establecido en una de las reglas precedentes.
s. Pueden haber múltiples etiquetas; solo una necesita coincidir. Si el operador es "!= ", el token devuelve verdadero solo si no hay ninguna etiqueta que coincida.

TAGS

Busca en el devpath hacia arriba un dispositivo con una etiqueta que coincida. Si el operador es "!= ", el token devuelve verdadero solo si no hay ninguna etiqueta que coincida.

TEST{máscara de modo octal}

Prueba la existencia de un archivo. Se puede especificar una máscara de modo octal si es necesario.

PROGRAM

Ejecuta un programa para determinar si hay una coincidencia; la clave es verdadera si el programa se ejecuta correctamente. Las propiedades del dispositivo se ponen a disposición del programa ejecutado en el entorno. La salida estándar del programa está disponible en la clave RESULT.

Esto solo se puede usar para tareas de primer plano de muy corta duración. Para obtener detalles, consulte RUN.

Tenga en cuenta que se pueden especificar varias claves PROGRAM en una sola regla, y "=", ":=", y "+=" tienen el mismo efecto que "==".

RESULT

Coincide con la cadena devuelta de la última llamada a PROGRAM. Esta clave se puede usar en la misma regla o en cualquier regla posterior después de una llamada a PROGRAM.

La mayoría de los campos admiten la coincidencia de patrones de globbing de shell y patrones alternativos. Se admiten los siguientes caracteres especiales:

"*"

Coincide con cero o más caracteres.

"?"

Coincide con cualquier carácter individual.

"[]"

Coincide con cualquier carácter individual especificado entre corchetes. Por ejemplo, la cadena de patrón "tty[SR]" coincidiría con "ttyS" o "ttyR". También se admiten rangos a través del carácter "-". Por ejemplo, para coincidir con el rango de todos los dígitos, se podría usar el patrón "[0-9]". Si el primer carácter después de "[" es "!", se coinciden con los caracteres que no están entre corchetes.

"|"

Separa patrones alternativos. Por ejemplo, la cadena de patrón "abc|x*" coincidiría con "abc" o "x*".

Añadido en la versión 217.

A los siguientes campos se les pueden asignar valores:

NAME

El nombre a utilizar para una interfaz de red. Consulte systemd.link(5) para conocer un mecanismo de nivel superior para establecer el nombre de la interfaz. El nombre de un nodo de dispositivo no puede ser cambiado por udev, solo se pueden crear enlaces simbólicos adicionales.

SYMLINK

El nombre de un enlace simbólico que apunta al nodo. Cada regla coincidente agrega este valor a la lista de enlaces simbólicos que se crearán.

El conjunto de caracteres para nombrar un enlace simbólico es limitado. Los caracteres permitidos son "0-9A-Za-z#+-.:=@_/ ", secuencias de caracteres UTF-8 válidas y la codificación hexadecimal "\x00". Todos los demás caracteres se reemplazan por un carácter "_".

Se pueden especificar varios enlaces simbólicos separando los nombres con un espacio. En caso de que varios dispositivos reclamen el mismo nombre, el enlace siempre apunta al dispositivo con la mayor prioridad de enlace. Si el dispositivo actual desaparece, los enlaces se reevalúan y el dispositivo con la siguiente mayor prioridad de enlace se convierte en el propietario del enlace. Si no se especifica ninguna prioridad de enlace, el orden de los dispositivos (y cuál de ellos posee el enlace) no está definido.

Los nombres de los enlaces simbólicos nunca deben entrar en conflicto con los nombres de los nodos de dispositivos predeterminados del kernel, ya que eso resultaría en un comportamiento impredecible.

OWNER, GROUP, MODE

Los permisos para el nodo del dispositivo. Cada valor especificado anula el valor predeterminado compilado.

SECLABEL{módulo}

Aplica la etiqueta especificada del Módulo de Seguridad de Linux al nodo del dispositivo.

Añadido en la versión 209.

ATTR{clave}

El valor que se debe escribir en un atributo sysfs del dispositivo del evento.

SYSCTL{parámetro del kernel}

El valor que se debe escribir en el parámetro del kernel.

Añadido en la versión 220.

ENV{clave}

Establece un valor de propiedad del dispositivo. Los nombres de propiedad con un "." inicial no se almacenan en la base de datos ni se exportan a eventos o herramientas externas (ejecutadas por la clave de coincidencia PROGRAM, por ejemplo).

TAG

Adjunta una etiqueta a un dispositivo. Esto se utiliza para filtrar eventos para los usuarios de la funcionalidad de monitor de libudev, o para enumerar un grupo de dispositivos etiquetados. La implementación solo puede funcionar de manera eficiente si se adjuntan pocas etiquetas a un dispositivo. Solo está previsto su uso en contextos con requisitos específicos de filtrado de dispositivos, y no como una bandera de propósito general. Un uso excesivo podría resultar en un manejo ineficiente de eventos.

RUN{tipo}

Especifica un programa que se ejecutará después de procesar todas las reglas para el evento. Con "+=", esta invocación se agrega a la lista, y con "=" o ":=", reemplaza el contenido anterior de la lista. Tenga en cuenta que tanto los tipos "program" como "builtin" descritos a continuación comparten una lista común, por lo que borrar la lista con ":=" y "=" afecta a ambos tipos.

tipo puede ser:

"program"

Ejecuta un programa externo especificado como el valor asignado. Si no se proporciona una ruta absoluta, se espera que el programa resida en /usr/lib/udev; de lo contrario, se debe especificar la ruta absoluta.

Este es el valor predeterminado si no se especifica ningún tipo.

"builtin"

Al igual que program, pero utiliza uno de los programas integrados en lugar de uno externo.

Añadido en la versión 199.

El nombre del programa y los argumentos siguientes están separados por espacios. Las comillas simples se pueden usar para especificar argumentos con espacios.

Esto solo se puede usar para tareas de primer plano de muy corta duración. Ejecutar un proceso de evento durante mucho tiempo puede bloquear todos los eventos posteriores para este o un dispositivo dependiente.

Tenga en cuenta que no se permite ejecutar programas que accedan a la red o monten/desmonten sistemas de archivos dentro de las reglas de udev, debido al sandbox predeterminado que se aplica en systemd-udevd.service.

No se permite iniciar demonios u otros procesos de larga duración; los procesos bifurcados, independientes o no, se eliminarán incondicionalmente después de que finalice el manejo del evento. Para activar procesos de larga duración desde reglas de udev, proporcione una unidad de servicio y extráigala de un dispositivo udev usando la propiedad de dispositivo SYSTEMD_WANTS. Consulte systemd.device(5) para obtener detalles.

LABEL

Una etiqueta con nombre a la que puede saltar un GOTO.

GOTO

Salta a la siguiente LABEL con un nombre coincidente.

IMPORT{tipo}

Importa un conjunto de variables como propiedades del dispositivo, dependiendo de tipo:

"program"

Ejecuta un programa externo especificado como el valor asignado y, si se ejecuta correctamente, importa su salida, que debe estar en formato de clave de entorno. La especificación de ruta, la separación de comandos/argumentos y el uso de comillas funcionan como en RUN.

Añadido en la versión 199.

"builtin"

Similar a "program", pero utiliza uno de los programas integrados en lugar de uno externo.

Añadido en la versión 199.

"file"

Importa un archivo de texto especificado como el valor asignado, cuyo contenido debe estar en formato de clave de entorno.

"db"

Importa una sola propiedad especificada como el valor asignado de la base de datos de dispositivos actual. Esto solo funciona si la base de datos ya está poblada por un evento anterior.

"cmdline"

Importa una sola propiedad de la línea de comandos del kernel. Para indicadores simples, el valor de la propiedad se establece en "1".

"parent"

Importa las claves almacenadas del dispositivo padre leyendo la entrada de la base de datos del dispositivo padre. El valor asignado a IMPORT{parent} se utiliza como un filtro de nombres de clave a importar (con los mismos patrones de globbing de shell utilizados para las comparaciones).

Esto solo se puede usar para tareas de primer plano de muy corta duración. Para obtener detalles, consulte RUN.

Tenga en cuenta que se pueden especificar varias claves IMPORT{} en una sola regla, y "=", ":=", y "+=" tienen el mismo efecto que "==". La clave es verdadera si la importación es exitosa, a menos que se use "!=" como operador, lo que hace que la clave sea verdadera si la importación falla.

OPTIONS

Opciones de regla y dispositivo:

link_priority=valor

Especifica la prioridad de los enlaces simbólicos creados. Los dispositivos con prioridades más altas sobrescriben los enlaces simbólicos existentes de otros dispositivos. El valor predeterminado es 0.

string_escape=none|replace

Cuando es "replace", los caracteres posiblemente inseguros en las cadenas asignadas a NAME, SYMLINK y ENV{clave} se reemplazan. Cuando es "none", no se realiza ningún reemplazo. Cuando no está establecido, el reemplazo se realiza para NAME, SYMLINK, pero no para ENV{clave}. Predeterminado: no establecido.

static_node=

Aplica los permisos especificados en esta regla al nodo de dispositivo estático con el nombre especificado. Además, para cada etiqueta especificada en esta regla, crea un enlace simbólico en el directorio /run/udev/static_node-tags/tag que apunta al nodo de dispositivo estático con el nombre especificado. La creación de nodos de dispositivo estáticos la realiza systemd-tmpfiles antes de que se inicie systemd-udevd. Los nodos estáticos pueden no tener un dispositivo kernel correspondiente; se utilizan para activar la carga automática de módulos kernel cuando se accede a ellos.

watch

Observa el nodo del dispositivo con inotify; cuando el nodo se cierra después de abrirse para escritura, se sintetiza un uevent de cambio.

nowatch

Deshabilita la observación de un nodo de dispositivo con inotify.

db_persist

Establece el indicador (bit sticky) en la entrada de la base de datos de udev del dispositivo del evento. Las propiedades del dispositivo se conservan en la base de datos incluso cuando se llama a udevadm info --cleanup-db. Esta opción puede ser útil en ciertos casos (por ejemplo, dispositivos Device Mapper) para persistir el estado del dispositivo en la transición desde initrd.

Añadido en la versión 241.

log_level=nivel

Toma un nombre de nivel de registro como quo"info" o "debug", o un valor especial "reset". Cuando se especifica un nombre de nivel de registro, el nivel de registro máximo se cambia a ese nivel. Cuando se establece "reset", se revoca el nivel de registro especificado anteriormente. Por defecto, es el nivel de registro del proceso principal de **systemd-udevd**.

Esto puede ser útil al depurar eventos para ciertos dispositivos. Tenga en cuenta que el nivel de registro se aplica cuando se procesa la línea que incluye esta regla. Por lo tanto, para depurar, se recomienda especificar esto en un lugar anterior, por ejemplo, la primera línea de 00-debug.rules.

Ejemplo para depurar el procesamiento de uevent para interfaces de red:

# /etc/udev/rules.d/00-debug-net.rules
SUBSYSTEM=="net", OPTIONS="log_level=debug"

Añadido en la versión 248.

dump

Descarga el estado del evento que se está procesando actualmente. Puede ser útil para depurar reglas de udev insertando esta opción.

Añadido en la versión 258.

Los campos ENV, GROUP, MODE, NAME, OWNER, PROGRAM, RUN, SECLABEL y SYMLINK admiten sustituciones de cadenas simples. Las sustituciones de RUN se realizan después de que se hayan procesado todas las reglas, justo antes de que se ejecute el programa, lo que permite el uso de propiedades del dispositivo establecidas por reglas coincidentes anteriores. Para todos los demás campos, las sustituciones se realizan mientras se procesa la regla individual. Las sustituciones disponibles son:

$kernel, %k

El nombre del kernel para este dispositivo.

$number, %n

El número del kernel para este dispositivo. Por ejemplo, "sda3" tiene el número de kernel 3.

$devpath, %p

El devpath del dispositivo.

$id, %b

El nombre del dispositivo coincidente al buscar el devpath hacia arriba para SUBSYSTEMS, KERNELS, DRIVERS y ATTRS.

$driver

El nombre del controlador coincidente al buscar el devpath hacia arriba para SUBSYSTEMS, KERNELS, DRIVERS y ATTRS.

$attr{archivo}, %s{archivo}

El valor de un atributo sysfs encontrado en el dispositivo donde coincidieron todas las claves de la regla. Si el dispositivo coincidente no tiene dicho atributo, y una prueba anterior de KERNELS, SUBSYSTEMS, DRIVERS o ATTRS seleccionó un dispositivo padre, entonces se usa el atributo de ese dispositivo padre.

Si el atributo es un enlace simbólico, se devuelve el último elemento del destino del enlace simbólico como valor.

$env{clave}, %E{clave}

Un valor de propiedad del dispositivo.

$major, %M

El número mayor del kernel para el dispositivo.

$minor, %m

El número menor del kernel para el dispositivo.

$result, %c

La cadena devuelta por el programa externo solicitado con PROGRAM. Una sola parte de la cadena, separada por un espacio en blanco, puede seleccionarse especificando el número de parte como atributo: "%c{N}". Si el número va seguido del carácter "+", esta parte más todas las partes restantes de la cadena de resultado se sustituyen: "%c{N+}".

$parent, %P

El nombre del nodo del dispositivo padre.

$name

El nombre actual del dispositivo. Si no lo cambia una regla, es el nombre del dispositivo del kernel.

$links

Una lista separada por espacios de los enlaces simbólicos actuales. El valor solo se establece durante un evento de eliminación o si una regla anterior le asignó un valor.

$root, %r

El valor de udev_root.

$sys, %S

El punto de montaje de sysfs.

$devnode, %N

El nombre del nodo del dispositivo.

%%

El propio carácter "%".

$$

El propio carácter "$".
