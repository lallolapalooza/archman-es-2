NOMBRE

update-ca-trust - gestionar la configuración consolidada y dinámica de certificados de CA y la confianza asociada

SINOPSIS

update-ca-trust [extract] [-o DIR|--output=DIR]

DESCRIPCIÓN

update-ca-trust(8) se utiliza para gestionar una función de configuración consolidada y dinámica de certificados de Autoridad de Certificación (CA) y la confianza asociada.

La función está disponible para aplicaciones nuevas que leen los archivos de configuración consolidados que se encuentran en el directorio /etc/ca-certificates/extracted o que cargan el módulo PKCS#11 p11-kit-trust.so

Partes de la nueva función también se proporcionan de forma que sea útil para aplicaciones heredadas.

Muchas aplicaciones heredadas esperan certificados de CA y configuración de confianza en una ubicación fija, contenidos en archivos con un nombre y ruta específicos, o haciendo referencia a un módulo de confianza PKCS#11 clásico proporcionado por la biblioteca criptográfica NSS.

La función de configuración dinámica proporciona reemplazos funcionalmente compatibles para archivos de configuración clásicos y para el módulo de confianza PKCS#11 clásico llamado libnssckbi.

Para permitir que las aplicaciones heredadas, que leen los archivos clásicos o acceden al módulo clásico, utilicen la nueva función de configuración consolidada y dinámica, los nombres de archivo clásicos se han cambiado a enlaces simbólicos. Los enlaces simbólicos hacen referencia a la salida consolidada y generada dinámicamente almacenada en la jerarquía del directorio /etc/ca-certificates/extracted.

La salida se produce utilizando el comando update-ca-trust (sin parámetros), o utilizando el comando update-ca-trust extract. Para producir la salida, se lee un conjunto flexible de configuración de origen, como se describe en la sección CONFIGURACIÓN DE ORIGEN.

Además, el módulo PKCS#11 clásico se reemplaza por un nuevo módulo PKCS#11 (p11-kit-trust.so) que lee dinámicamente la misma configuración de origen.

CONFIGURACIÓN DE ORIGEN

La función de configuración dinámica utiliza varios directorios de origen que se escanearán para detectar cualquier número de archivos de origen. Es importante seleccionar el subdirectorio correcto para agregar archivos, ya que el subdirectorio define cómo se confiará o no en los certificados contenidos, y qué formatos de archivo se leen.

Los archivos en subdirectorios debajo de la jerarquía de directorios /usr/share/ca-certificates/trust-source/ contienen certificados de CA y configuraciones de confianza en formato de archivo PEM. Las configuraciones de confianza que se encuentran aquí se interpretarán con una baja prioridad.

Los archivos en subdirectorios debajo de la jerarquía de directorios /etc/ca-certificates/trust-source/ contienen certificados de CA y configuraciones de confianza en formato de archivo PEM. Las configuraciones de confianza que se encuentran aquí se interpretarán con una alta prioridad.

Puede usar las siguientes reglas generales para decidir si sus archivos de configuración deben agregarse al jerarquía de directorios /etc o más bien a la jerarquía de directorios /usr:

•Si está agregando manualmente un archivo de configuración a un sistema, probablemente querrá que anule cualquier otra configuración predeterminada, y lo más probable es que deba agregarlo al subdirectorio respectivo en la jerarquía /etc.
•Si está creando un paquete que proporciona certificados de CA raíz adicionales, que está destinado a la distribución a varios sistemas informáticos, pero aún desea permitir que el administrador anule su lista, entonces su paquete debe agregar sus archivos al subdirectorio respectivo en la jerarquía /usr.
•Si está creando un paquete que se supone que debe anular la configuración de confianza del sistema predeterminada, que está destinado a la distribución a varios sistemas informáticos, entonces su paquete debe instalar los archivos en el subdirectorio respectivo en la jerarquía /etc.

AYUDA RÁPIDA 1: Para agregar un certificado en los formatos de archivo PEM o DER simples a la lista de CA de confianza en el sistema:

•agréguelo como un nuevo archivo al directorio /etc/ca-certificates/trust-source/anchors/
•ejecute update-ca-trust extract

AYUDA RÁPIDA 2: Si su certificado está en el formato de archivo BEGIN TRUSTED extendido (que puede contener indicadores de confianza de no confianza/lista negra, o indicadores de confianza para usos distintos de TLS), entonces:

•agréguelo como un nuevo archivo al directorio /etc/ca-certificates/trust-source/
•ejecute update-ca-trust extract

Para ofrecer simplicidad y flexibilidad, la forma en que se tratan los archivos de certificado depende del subdirectorio en el que se instalan.

•subdirectorio de anclajes de confianza simples: /usr/share/ca-certificates/trust-source/anchors/ o /etc/ca-certificates/trust-source/anchors/
•subdirectorio de lista negra (no confianza) simple: /usr/share/ca-certificates/trust-source/blocklist/ o /etc/ca-certificates/trust-source/blocklist/
•directorio de formato extendido: /usr/share/ca-certificates/trust-source/ o /etc/ca-certificates/trust-source/

En los directorios principales /usr/share/ca-certificates/trust-source/ o /etc/ca-certificates/trust-source/ puede instalar uno o varios archivos en los siguientes formatos de archivo:

•archivos de certificado que incluyen indicadores de confianza, en formato de archivo BEGIN/END TRUSTED CERTIFICATE (cualquier nombre de archivo), que se han creado utilizando la herramienta openssl x509 y las opciones -addreject -addtrust. Se admiten archivos de paquete con múltiples certificados.
•archivos en formato de archivo p11-kit usando la extensión de nombre de archivo .p11-kit, que pueden (por ejemplo) usarse para no confiar en certificados basados en número de serie y nombre del emisor, sin tener el certificado completo disponible. (Este es actualmente un formato no documentado, que se ampliará más adelante. Para ver ejemplos de los formatos admitidos, consulte los archivos distribuidos con el paquete ca-certificates-mozilla).
•archivos de certificado sin indicadores de confianza en formato de archivo DER o en formato de archivo PEM (BEGIN/END CERTIFICATE) (cualquier nombre de archivo). Dichos archivos se agregarán con confianza neutral, ni confiables ni no confiables. Simplemente serán conocidos por el sistema, lo que puede ser útil para ayudar al software criptográfico a construir cadenas de certificados. (Si desea que un certificado de CA en estos formatos de archivo sea confiable, debe eliminarlo de este directorio y moverlo al subdirectorio ./anchors en su lugar).

En los subdirectorios de anclajes /usr/share/ca-certificates/trust-source/anchors/ o /etc/ca-certificates/trust-source/anchors/ puede instalar uno o varios certificados en formato de archivo DER o en formato de archivo PEM (BEGIN/END CERTIFICATE). Cada certificado se tratará como confiable para todos los propósitos.

En los subdirectorios de lista negra /usr/share/ca-certificates/trust-source/blocklist/ o /etc/ca-certificates/trust-source/blocklist/ puede instalar uno o varios certificados en formato de archivo DER o en formato de archivo PEM (BEGIN/END CERTIFICATE). Cada certificado se tratará como no confiable para todos los propósitos.

Consulte la página del manual de x509(1) para obtener la documentación de los formatos de archivo BEGIN/END CERTIFICATE y BEGIN/END TRUSTED CERTIFICATE.

Las aplicaciones que dependen de un archivo estático para obtener una lista de CA confiables pueden cargar uno de los archivos que se encuentran en el directorio /etc/ca-certificates/extracted/. Después de modificar cualquier archivo en los directorios /usr/share/ca-certificates/trust-source/ o /etc/ca-certificates/trust-source/ o en cualquiera de sus subdirectorios, o después de agregar un archivo, es necesario ejecutar el comando update-ca-trust extract para actualizar los archivos consolidados en /etc/ca-certificates/extracted/.

Las aplicaciones que cargan el módulo PKCS#11 clásico usando el nombre de archivo libnssckbi.so (que se ha convertido en un enlace simbólico que apunta al nuevo módulo) y cualquier aplicación capaz de cargar módulos PKCS#11 y cargar p11-kit-trust.so, se beneficiarán del conjunto dinámicamente combinado de certificados e información de confianza almacenada en los directorios /usr/share/ca-certificates/trust-source/ y /etc/ca-certificates/trust-source/.

CONFIGURACIÓN EXTRAÍDA

El directorio /etc/ca-certificates/extracted/ contiene archivos generados de paquetes de certificados de CA que se crean y actualizan, basándose en la CONFIGURACIÓN DE ORIGEN, ejecutando el comando update-ca-trust extract.

update-ca-trust(8) — Arch Linux manual pages

NAME

update-ca-trust ― update the trust store

SYNOPSIS

update-ca-trust [extract [-o DIR]]

DESCRIPTION

The update-ca-trust command is used to manage the system wide collection of trusted CA certificates. It scans the directories described in section SOURCE CONFIGURATION and consolidates the found CA certificates and their trust attributes into a set of files described in section EXTRACTED CONFIGURATION.

This command is typically run automatically during rpm package installation or upgrades. It can also be run manually.

When run manually, it can be invoked with the extract command, or without any command, which behaves identically. When invoked without a command and not during package installation, it may print more warnings about missing dependencies or potential problems.

SOURCE CONFIGURATION

The directories:

/usr/share/ca-certificates/trust-source/

/etc/ca-certificates/trust-source/

are scanned for source configuration files. Files in / are explicitly ignored. Files in / are parsed as trusted certificates. Files in / are parsed as trusted certificates. Files in / are parsed as trusted certificates.

The default trust policy is to trust certificates that are not explicitly distrusted.

Source configuration files are expected to be in the extended BEGIN/END TRUSTED CERTIFICATE file format, as described in the x509(1) manual page. The files in / can also be in the simple BEGIN/END CERTIFICATE file format, without trust attributes.

Subdirectories are searched recursively. The search order depends on the specific filename, which is defined by the trust policy, and is not specified here.

EXTRACTED CONFIGURATION

The directory /etc/ca-certificates/extracted/ contains the consolidated output files generated by the update-ca-trust extract command. These files are intended for consumption by applications.

Please never manually edit the files stored in this directory, because your changes will be lost and the files automatically overwritten, each time the update-ca-trust extract command gets executed.

In order to install new trusted or distrusted certificates, please rather install them in the respective subdirectory below the /usr/share/ca-certificates/trust-source/ or /etc/ca-certificates/trust-source/ directories, as described in the SOURCE CONFIGURATION section.

The directory /etc/ca-certificates/extracted/ contains a CA certificate bundle in the java keystore file format. Distrust information cannot be represented in this file format, and distrusted certificates are missing from these files. File java-cacerts.jks contains CA certificates trusted for TLS server authentication.

It also contains CA certificate bundle files in the extended BEGIN/END TRUSTED CERTIFICATE file format, as described in the x509(1) manual page. File ca-bundle.trust.crt contains the full set of all trusted or distrusted certificates, including the associated trust flags.

It also contains CA certificate bundle files in the simple BEGIN/END CERTIFICATE file format, as described in the x509(1) manual page. Distrust information cannot be represented in this file format, and distrusted certificates are missing from these files. File tls-ca-bundle.pem contains CA certificates trusted for TLS server authentication. File email-ca-bundle.pem contains CA certificates trusted for E-Mail protection. File objsign-ca-bundle.pem contains CA certificates trusted for code signing.

It also contains a CA certificate bundle ("edk2-cacerts.bin") in the "sequence of EFI_SIGNATURE_LISTs" format, defined in the UEFI-2.7 specification, sections "31.4.1 Signature Database" and "EFI_CERT_X509_GUID". Distrust information cannot be represented in this file format, and distrusted certificates are missing from these files. File "edk2-cacerts.bin" contains CA certificates trusted for TLS server authentication.

COMMANDS

(absent/empty command)

Same as the extract command described below. (However, the command may print fewer warnings, as this command is being run during rpm package installation, where non-fatal status output is undesired.)

extract

Instruct update-ca-trust to scan the SOURCE CONFIGURATION and produce updated versions of the consolidated configuration files stored below the /etc/ca-certificates/extracted directory hierarchy.

EXTRACT OPTIONS

-o DIR, --output=DIR

Write the extracted trust store into the given directory instead of updating /etc/ca-certificates/extracted.

FILES

/etc/ssl/cert.pem

Classic filename, file contains a list of CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/etc/ssl/certs/

Classic directory, contains individual CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. Also includes the necessary hash symlinks expected by OpenSSL. The files are symbolic links that refer to the output created by the update-ca-trust command.

/etc/ssl/certs/ca-bundle.crt

Classic filename for compatibility with RHEL/Fedora, file contains a list of CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/etc/ssl/certs/ca-certificates.crt

Classic filename for compatibility with Debian, file contains a list of CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/etc/ssl/certs/java/cacerts

Classic filename, file contains a list of CA certificates trusted for TLS server authentication usage, in the Java keystore file format, without distrust information. This file is a symbolic link that refers to the consolidated output created by the update-ca-trust command.

/usr/share/ca-certificates/trust-source

Contains multiple, low priority source configuration files as explained in section SOURCE CONFIGURATION. Please pay attention to the specific meanings of the respective subdirectories.

/etc/ca-certificates/trust-source

Contains multiple, high priority source configuration files as explained in section SOURCE CONFIGURATION. Please pay attention to the specific meanings of the respective subdirectories.

/etc/ca-certificates/extracted

Contains consolidated and automatically generated configuration files for consumption by applications, which are created using the update-ca-trust extract command. Don’t edit files in this directory, because they will be overwritten. See section EXTRACTED CONFIGURATION for additional details.

/etc/ca-certificates/extracted/ca-bundle.trust.crt

File contains a list of CA certificates in the extended BEGIN/END TRUSTED CERTIFICATE file format, which includes trust (and/or distrust) flags specific to certificate usage. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/email-ca-bundle.pem

File contains a list of CA certificates trusted for E-Mail protection, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/objsign-ca-bundle.pem

File contains a list of CA certificates trusted for code signing, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/tls-ca-bundle.pem

File contains a list of CA certificates trusted for TLS server authentication, in the simple BEGIN/END CERTIFICATE file format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/cadir/

Contains individual CA certificates trusted for TLS server authentication usage, in the simple BEGIN/END CERTIFICATE file format, without distrust information. Also includes the necessary hash symlinks expected by OpenSSL. These files are maintained by the update-ca-trust command.

/etc/ca-certificates/extracted/edk2-cacerts.bin

File contains a list of CA certificates trusted for TLS server authentication usage, in the UEFI signature database format, without distrust information. This file is consolidated output created by the update-ca-trust command.

/etc/ca-certificates/extracted/java-cacerts.jks

File contains a list of CA certificates trusted for TLS server authentication usage, in the Java keystore file format, without distrust information. This file is consolidated output created by the update-ca-trust command.
