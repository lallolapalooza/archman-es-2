unw_create_addr_space(3)

Paquete: libunwind

Licencias: MIT

UNW_CREATE_ADDR_SPACE(3libunwind) Programming Library UNW_CREATE_ADDR_SPACE(3libunwind)

NOMBRE

unw_create_addr_space -- crear espacio de direcciones para desenrollado remoto

SINOPSIS

#include <libunwind.h>

unw_addr_space_t unw_create_addr_space(unw_accessors_t *ap, int byteorder);

DESCRIPCIÓN

La rutina unw_create_addr_space() crea un nuevo espacio de direcciones de desenrollado y lo inicializa basándose en las rutinas de callback pasadas a través del puntero ap y el orden de bytes especificado. Las rutinas de callback se describen en detalle a continuación. El orden de bytes se puede establecer en 0 para solicitar el orden de bytes predeterminado del destino de desenrollado. Para solicitar un orden de bytes particular, byteorder se puede establecer en cualquier constante definida por <endian.h>. En particular, UNW_LITTLE_ENDIAN solicitaría el orden de bytes little-endian y UNW_BIG_ENDIAN solicitaría el orden de bytes big-endian. Que un orden de bytes particular sea compatible depende de la plataforma de destino.

RUTINAS DE CALLBACK

Libunwind utiliza un conjunto de rutinas de callback para acceder a la información que necesita para desenrollar una cadena de frames de pila. Estas rutinas se especifican a través del argumento ap, que apunta a una variable de tipo unw_accessors_t. El contenido de esta variable se copia en el espacio de direcciones recién creado, por lo que la variable debe seguir siendo válida solo durante la duración de la llamada a unw_create_addr_space().

El primer argumento de cada rutina de callback es un identificador de espacio de direcciones (as) y el último argumento es un puntero void arbitrario especificado por la aplicación (arg). Al invocar una rutina de callback, libunwind establece el argumento as en el espacio de direcciones en cuyo nombre se realiza la invocación y el argumento arg en el valor que se especificó cuando se llamó a unw_init_remote(3libunwind).

La sinopsis y una descripción detallada de cada rutina de callback se presentan a continuación.

SINOPSIS DE LA RUTINA DE CALLBACK

int find_proc_info(unw_addr_space_t as,
unw_word_t ip, unw_proc_info_t *pip,
int need_unwind_info, void *arg);
void put_unwind_info(unw_addr_space_t as,
unw_proc_info_t *pip, void *arg);
int get_dyn_info_list_addr(unw_addr_space_t as,
unw_word_t *dilap, void *arg);
int access_mem(unw_addr_space_t as,
unw_word_t addr, unw_word_t *valp,
int write, void *arg);
int access_reg(unw_addr_space_t as,
unw_regnum_t regnum, unw_word_t *valp,
int write, void *arg);
int access_fpreg(unw_addr_space_t as,
unw_regnum_t regnum, unw_fpreg_t *fpvalp,
int write, void *arg);
int resume(unw_addr_space_t as,
unw_cursor_t *cp, void *arg);
int get_proc_name(unw_addr_space_t as,
unw_word_t addr, char *bufp,
size_t buf_len, unw_word_t *offp,
void *arg);

FIND_PROC_INFO

Libunwind invoca la rutina de callback find_proc_info() para localizar la información necesaria para desenrollar un procedimiento en particular. El argumento ip es una dirección de instrucción dentro del procedimiento cuya información se necesita. El argumento pip es un puntero a la variable que se utiliza para devolver la información deseada. El tipo de esta variable es unw_proc_info_t. Véase unw_get_proc_info(3libunwind) para más detalles. El argumento need_unwind_info es cero si la callback no necesita proporcionar valores para los siguientes miembros de la estructura unw_proc_info_t: format, unwind_info_size y unwind_info. Si need_unwind_info es distinto de cero, se deben devolver valores válidos en estos miembros. Además, el contenido de la memoria a la que apunta el miembro unwind_info debe seguir siendo válido hasta que la información se libere mediante la callback put_unwind_info (véase más abajo).

Al completarse con éxito, la callback find_proc_info() debe devolver cero. De lo contrario, se puede devolver el valor negativo de uno de los códigos de error unw_error_t. En particular, esta callback puede devolver -UNW_ESTOPUNWIND para señalar el final de la cadena de frames.

PUT_UNWIND_INFO

Libunwind invoca la rutina de callback put_unwind_info() para liberar los recursos (como memoria) asignados por una llamada anterior a find_proc_info() con el argumento need_unwind_info establecido a un valor distinto de cero. El argumento pip tiene el mismo valor que el argumento del mismo nombre en la llamada anterior coincidente a find_proc_info(). Tenga en cuenta que libunwind no invoca put_unwind_info para las llamadas a find_proc_info() con un argumento need_unwind_info cero.

GET_DYN_INFO_LIST_ADDR

Libunwind invoca la rutina de callback get_dyn_info_list_addr() para obtener la dirección de la cabeza de la lista de registro de información de desenrollado dinámico. La variable almacenada en la dirección devuelta debe tener el tipo unw_dyn_info_list_t (véase _U_dyn_register(3libunwind)). El argumento dliap es un puntero a una variable de tipo unw_word_t que se utiliza para devolver la dirección de la lista de registro de información de desenrollado dinámico. Si no existe ninguna lista de registro de información de desenrollado dinámico, el valor apuntado por dliap debe establecerse a cero. Libunwind almacenará en caché el valor devuelto por get_dyn_info_list_addr() si el almacenamiento en caché está habilitado para el espacio de direcciones dado. La caché se puede limpiar con una llamada a unw_flush_cache().

Al completarse con éxito, la callback get_dyn_info_list_addr() debe devolver cero. De lo contrario, se puede devolver el valor negativo de uno de los códigos de error unw_error_t.

ACCESS_MEM

Libunwind invoca la rutina de callback access_mem() para leer o escribir una palabra de memoria en el espacio de direcciones de destino. La dirección de la palabra a acceder se pasa en el argumento addr. Para leer memoria, libunwind establece el argumento write a cero y valp para que apunte a la palabra que recibe el valor leído. Para escribir memoria, libunwind establece el argumento write a un valor distinto de cero y valp para que apunte a la palabra que contiene el valor a escribir. La palabra a la que apunta valp siempre está en el orden de bytes de la plataforma anfitriona, independientemente del orden de bytes del destino. En otras palabras, es responsabilidad de la rutina de callback convertir entre el orden de bytes del destino y el del anfitrión, si es necesario.

Al completarse con éxito, la callback access_mem() debe devolver cero. De lo contrario, se puede devolver el valor negativo de uno de los códigos de error unw_error_t.

unw_create_addr_space(3)

NAME

unw_create_addr_space, unw_destroy_addr_space - create and destroy an address space for unwinding

SYNOPSIS

#include <libunwind.h>

unw_addr_space_t unw_create_addr_space(unw_access_reg_list_t access_reg_list, int flags);

void unw_destroy_addr_space(unw_addr_space_t as);

DESCRIPTION

The unw_create_addr_space() routine creates a new address space object that can be used by libunwind for unwinding stack frames in a target address space. The access_reg_list argument specifies the callbacks that libunwind should use to access the registers of the target. The flags argument is a bitmask of flags that control the behaviour of the address space. Currently, the only defined flag is UNW_ADDRSPACE_FOR_REMOTE, which indicates that the address space is for unwinding a remote process.

The unw_destroy_addr_space() routine destroys an address space object that was previously created by a call to unw_create_addr_space(). This routine must be called on all address space objects that are no longer needed, to prevent memory leaks.

CALLBACK ROUTINES

The access_reg_list argument to unw_create_addr_space() is a pointer to a structure of type unw_access_reg_list_t, which is defined as follows:

typedef struct unw_access_reg_list {
    int (*access_reg)(unw_addr_space_t as, unw_access_reg_t reg,
                      unw_word_t *val, int write);
    int (*access_fpreg)(unw_addr_space_t as, unw_access_reg_t reg,
                        unw_fpreg_t *val, int write);
    int (*resume)(unw_addr_space_t as, unw_cursor_t *cp,
                  unw_word_t flags);
    int (*get_proc_name)(unw_addr_space_t as, unw_word_t addr,
                         char *bufp, size_t buf_len,
                         unw_word_t *offp);
    /* ... other fields ... */
} unw_access_reg_list_t;

ACCESS_REG

Libunwind invokes the access_reg() callback to read from or write to a non-floating-point CPU register. The index of the register to be accessed is passed in argument reg. To read a register, libunwind sets argument write to zero and valp to point to the word that receives the read value. To write a register, libunwind sets argument write to a non-zero value and valp to point to the word that contains the value to be written. The word that valp points to is always in the byte order of the host platform, regardless of the byte order of the target. In other words, it is the responsibility of the callback routine to convert between the target's and the host's byte order, if necessary.

On successful completion, the access_reg() callback must return zero. Otherwise, the negative value of one of the unw_error_t error codes may be returned.

ACCESS_FPREG

Libunwind invokes the access_fpreg() callback to read from or write to a floating-point CPU register. The index of the register to be accessed is passed in argument regnum. To read a register, libunwind sets argument write to zero and fpvalp to point to a variable of type unw_fpreg_t that receives the read value. To write a register, libunwind sets argument write to a non-zero value and fpvalp to point to the variable of type unw_fpreg_t that contains the value to be written. The word that fpvalp points to is always in the byte order of the host platform, regardless of the byte order of the target. In other words, it is the responsibility of the callback routine to convert between the target's and the host's byte order, if necessary.

On successful completion, the access_fpreg() callback must return zero. Otherwise, the negative value of one of the unw_error_t error codes may be returned.

RESUME

Libunwind invokes the resume() callback to resume execution in the target address space. Argument cp is the unwind cursor that identifies the stack frame in which execution should resume. By the time libunwind invokes the resume callback, it has already established the desired machine and memory state via calls to the access_reg(), access_fpreg, and access_mem() callbacks. Thus, all the callback needs to do is perform whatever action is needed to actually resume execution.

The resume callback is invoked only in response to a call to unw_resume(3libunwind), so applications which never invoke unw_resume(3libunwind) need not define the resume callback.

On successful completion, the resume() callback must return zero. Otherwise, the negative value of one of the unw_error_t error codes may be returned. As a special case, when resuming execution in the local address space, the callback will not return on success.

GET_PROC_NAME

Libunwind invokes the get_proc_name() callback to obtain the procedure name of a static (not dynamically generated) procedure. Argument addr is an instruction address within the procedure whose name is to be obtained. The bufp argument is a pointer to a character buffer used to return the procedure name. The size of this buffer is specified in argument buf_len. The returned name must be terminated by a NUL character. If the procedure's name is longer than buf_len bytes, it must be truncated to buf_len-1 bytes, with the last byte in the buffer set to the NUL character and -UNW_ENOMEM must be returned. Argument offp is a pointer to a word which is used to return the byte offset relative to the start of the procedure whose name is being returned. For example, if procedure foo() starts at address 0x40003000, then invoking get_proc_name() with addr set to 0x40003080 should return a value of 0x80 in the word pointed to by offp (assuming the procedure is at least 0x80 bytes long).

On successful completion, the get_proc_name() callback must return zero. Otherwise, the negative value of one of the unw_error_t error codes may be returned.

RETURN VALUE

On successful completion, unw_create_addr_space() returns a non-NULL value that represents the newly created address space. Otherwise, NULL is returned.

THREAD AND SIGNAL SAFETY

unw_create_addr_space() is thread-safe but not safe to use from a signal handler.
