DESCRIPCIÓN

Las funciones son un sistema bastante extensible para analizar varios archivos de configuración en tiempo de ejecución de una aplicación. El flujo del archivo de configuración se divide en las siguientes fases:

1.
Registro de manejadores.
2.
Lectura de los archivos de configuración para requisitos de análisis previo a MIB.
3.
Lectura y análisis de los archivos MIB textuales.
4.
Lectura de los archivos de configuración para directivas de configuración.
5.
Opcionalmente, volver a leer los archivos de configuración en un momento posterior.

La idea es que la aplicación que llama pueda registrar manejadores para ciertos tokens especificados en ciertos archivos de configuración con nombre. La función read_configs() puede ser llamada entonces para buscar todos los archivos de configuración relevantes, comparar la primera palabra de cada línea con la lista de tokens registrados y pasar el resto de la línea al manejador registrado apropiado.

REGISTRO DE UN MANEJADOR

register_config_handler()
Registra una rutina manejadora de configuración, que debe ser llamada para procesar directivas de configuración que comiencen con el token especificado. Por ejemplo:
register_config_handler("snmp", "exampleToken", example_handler, NULL, "ARG1 [ARG2]");
registraría la función example_handler() para que sea llamada cada vez que la primera palabra de una línea en el(los) archivo(s) de configuración snmp.conf coincida con "exampleToken".
Llamar a los manejadores apropiados para procesar las directivas del archivo de configuración es responsabilidad de read_configs() (ver abajo).
register_const_config_handler()
Similar a la función register_config_handler(), pero la rutina analizadora está explícitamente restringida a no modificar la cadena que se está analizando.
register_prenetsnmp_mib_handler()
Similar a la función register_config_handler(), pero la rutina manejadora registrada se llamará *antes* de que se lean los MIBs textuales. Esto se usa típicamente para tokens que afectarán la configuración del analizador de MIB, y normalmente solo se usará dentro de la propia biblioteca SNMP.
register_mib_handlers()
Rutina de inicialización para registrar los manejadores de configuración internos de la biblioteca SNMP.
unregister_config_handler()
Elimina el manejador de configuración registrado para el filePrefix y token especificados.
unregister_all_config_handlers()
Elimina todos los manejadores de configuración registrados.

Manejadores de Tokens

Las funciones manejadoras deben tener la siguiente firma:

void handler(const char *token, char *line);
o
void handler(const char *token, const char *line); br (si se registra usando register_const_config_handler)

La función será llamada con dos argumentos, el primero siendo el token que activó la llamada a esta función (es decir, el token utilizado al registrar el manejador), y el segundo siendo el resto de la línea del archivo de configuración (es decir, todo lo que sigue al espacio en blanco después del token coincidente).

Manejadores de Liberación

Si la función manejadora de tokens asigna dinámicamente recursos al procesar una entrada de configuración, es posible que deban liberarse antes de volver a leer los archivos de configuración. Si el cuarto parámetro ( releaser ) pasado a register_config_handler no es NULL, entonces especifica una función que se llamará antes de volver a leer los archivos de configuración. Esta función debe liberar cualquier recurso asignado por la función manejadora de tokens y restablecer su noción de la configuración a su valor predeterminado. El manejador de tokens puede ser llamado de nuevo de forma segura. No se pasan argumentos al manejador de liberación de recursos.
Tenga en cuenta que esta función no se llama cuando el manejador se desregistra individualmente (pero *se llama* como parte de unregister_all_config_handlers()).

Manejadores de Aplicación

register_app_config_handler()
register_app_prenetsnmp_mib_handler()
unregister_app_config_handler()

LEER CONFIGURACIONES

read_premib_configs()
Lee los archivos de configuración que son necesarios para la fase de análisis de MIBs. Esto está diseñado principalmente para uso interno de la biblioteca SNMP, pero puede ser invocado por aplicaciones si es necesario.
read_configs()
Lee todos los archivos de configuración relevantes y llama a los manejadores registrados para procesar las directivas correspondientes. El orden en que se procesan las directivas de configuración está determinado por el orden en que se registran los manejadores y por la fase de procesamiento (pre-MIB o post-MIB).

UTILIDADES

read_config_print_usage()
Imprime una cadena de uso para todos los manejadores de configuración registrados. El argumento lead se imprimirá antes de cada línea de uso.
config_pwarn()
Imprime una cadena de advertencia en stderr.
config_perror()
Imprime una cadena de error en stderr y luego llama a exit(1).

EJEMPLO

Para registrar un manejador para un token `myToken` en el archivo `myApp.conf`:

static void
my_handler(const char *token, char *line)
{
    // procesar la línea
}

static void
my_releaser(void)
{
    // liberar recursos
}

void init_my_app(void) {
    register_config_handler("myApp", "myToken", my_handler, my_releaser, "argumentos de ejemplo");
}

Luego, en la inicialización de la aplicación, llamar a:

init_my_app();
read_configs();

procesará las líneas en `myApp.conf` que comiencen con `myToken` llamando a `my_handler`.

unregister_all_config_handlers(3) — net-snmp

NAME

unregister_all_config_handlers, unregister_app_config_handler, unregister_prenetsnmp_mib_handler, unregister_config_handler - registrar y desregistrar manipuladores de configuración

SYNOPSIS

#include <net-snmp/library/config_api.h>

void
unregister_config_handler(const char *token);

void
unregister_prenetsnmp_mib_handler(const char *token);

void
unregister_app_config_handler(const char *token);

void
unregister_app_prenetsnmp_mib_handler(const char *token);

void
unregister_all_config_handlers(void);

DESCRIPTION

Estas funciones son análogas a register_config_handler(), register_prenetsnmp_mib_handler() y register_app_config_handler() pero no requieren el argumento del tipo de archivo (que es completado por la aplicación). La intención es que los módulos MIB escritos para el agente utilicen estas funciones para permitir que el agente tenga más control sobre qué archivos de configuración se leen (típicamente los archivos snmpd.conf).

REGISTERING A HANDLER

unregister_app_config_handler()
Estas funciones son análogas a register_config_handler(), register_prenetsnmp_mib_handler() y unregister_config_handler() pero no requieren el argumento del tipo de archivo (que es completado por la aplicación). La intención es que los módulos MIB escritos para el agente utilicen estas funciones para permitir que el agente tenga más control sobre qué archivos de configuración se leen (típicamente los archivos snmpd.conf).

READING CONFIGURATION FILES

read_premib_configs()
read_configs()
Estas rutinas procesan los archivos de configuración encontrados en la ruta de búsqueda de configuración (ver abajo). Para cada entrada, se llama al manipulador registrado para ese token de configuración.

read_premib_configs() se ejecuta antes de que se lean los archivos MIB y procesa los tokens de configuración registrados usando register_prenetsnmp_mib_handler() (o register_app_prenetsnmp_mib_handler()). Todas las demás entradas se ignoran.

read_configs() se ejecuta después de que se han leído los archivos MIB y procesa los tokens de configuración registrados usando register_config_handler() (o register_app_config_handler()). Si encuentra un token de configuración para el cual no se ha registrado ningún manipulador (ni pre- ni post-mib), mostrará un mensaje de advertencia y continuará procesando con la siguiente línea del archivo de configuración.

Configuration Search Path

Los archivos de configuración que se van a leer se encuentran buscando en una lista de directorios de configuración archivos con nombres apropiados. En cada uno de esos directorios, la biblioteca buscará archivos llamados snmp.conf, snmp.local.conf, app.conf, app.local.conf,
(donde app es el prefijo de archivo específico de la aplicación utilizado para registrar los manipuladores de configuración). No es necesario que todos o ninguno de estos archivos estén presentes en cada directorio. Los archivos faltantes se omitirán silenciosamente.
La idea detrás de los dos sufijos diferentes es que el primer archivo puede ser compartido (a través de rdist o un montaje NFS) en un gran número de máquinas y el segundo archivo puede usarse para configurar ajustes locales para una máquina en particular.

La lista predeterminada de directorios a buscar es /etc/snmp, seguido por /usr/share/snmp, seguido por /usr/lib/snmp, seguido por $HOME/.snmp. Esta lista se puede cambiar estableciendo la variable ambiental SNMPCONFPATH a una lista (separada por dos puntos) de directorios para buscar.

init_snmp()

El modo normal de operación sería registrar los manipuladores de configuración específicos de la aplicación y luego invocar init_snmp(). Esto llamaría a las rutinas enumeradas anteriormente para registrar los manipuladores de configuración de la biblioteca interna, procesar cualquier token de configuración registrado con register_prenetsnmp_mib_handler(), leer los archivos MIB de texto usando init_mib(), y finalmente analizar los tokens de archivo de configuración registrados con register_config_handler().

Si se utiliza la función init_snmp(), la aplicación no necesita llamar explícitamente a ninguna de estas funciones.

HELP STRINGS AND ERRORS

El parámetro usageLine pasado a register_config_handler() y llamadas similares, se utiliza para mostrar información de ayuda cuando se llama a la función read_config_print_usage(). Esta función es utilizada por todas las aplicaciones cuando se pasa el flag -H en la línea de comandos. Imprime un resumen de todas las líneas del archivo de configuración, y los archivos asociados, que el sistema de configuración entiende. El parámetro usageLine debe ser una lista de argumentos esperados después del token, y no una descripción larga (que debería ir en una página de manual en su lugar). El prefijo lead se antepondrá a cada línea que la función imprima en stderr, donde muestra su salida.

La función init_snmp() debe llamarse antes de la función read_config_print_usage() para que la biblioteca pueda registrar sus directivas de archivo de configuración también para que la función read_config_print_usage() las muestre.

Error Handling Functions

Las dos funciones config_pwarn() y config_perror() toman una cadena de error como argumento y la imprimen en stderr junto con el archivo y el número de línea que causó el error. Una llamada a la segunda función también forzará a read_configs() a devolver eventualmente un código de error indicando a su función llamante que debe abortar la operación de la aplicación.

ENVIRONMENT VARIABLES

SNMPCONFPATH
Una lista separada por dos puntos de directorios para buscar archivos de configuración. Predeterminado:
/etc/snmp:/usr/share/snmp:/usr/lib/snmp:$HOME/.snmp
