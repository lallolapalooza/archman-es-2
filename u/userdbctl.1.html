NOMBRE

userdbctl - Inspeccionar usuarios, grupos y membresías de grupos

SINOPSIS

userdbctl [OPCIONES...] {COMANDO} [NOMBRE...]

DESCRIPCIÓN

userdbctl puede ser utilizado para inspeccionar usuarios y grupos (así como membresías de grupos) del sistema. Esta utilidad cliente consulta información de usuarios/grupos proporcionada por varios servicios del sistema, tanto operando sobre registros de usuarios/grupos JSON (como se define en las Definiciones de Registros de Usuarios JSON[1] y Definiciones de Registros de Grupos JSON[2]), como registros clásicos de usuarios y grupos NSS/glibc. Esta herramienta es principalmente un cliente de la API de Búsqueda de Registros de Usuarios/Grupos vía Varlink[3], y también puede capturar registros de usuarios y grupos JSON drop-in de /etc/userdb/, /run/userdb/, /run/host/userdb/, /usr/lib/userdb/ (ver nss-systemd(8) para detalles sobre registros de usuarios drop-in).

OPCIONES

Se entienden las siguientes opciones:

--output=MODO

Elige el modo de salida. Toma uno de los valores "classic", "friendly", "table" o "json". Si es "classic", se genera una salida muy similar al formato de /etc/passwd o /etc/group. Si es "friendly", se genera una salida más completa y fácil de usar, legible por humanos. Si es "table", se genera una salida tabular mínima. Si es "json", se genera una salida con formato JSON. Por defecto es "friendly" si se especifica un usuario/grupo en la línea de comandos, y "table" en caso contrario.

Tenga en cuenta que la mayoría de los formatos de salida no muestran toda la información disponible. En particular, "classic" y "table" solo muestran los campos más importantes. Varios modos tampoco muestran hashes de contraseñas. Use "json" para ver todos los campos, incluidos cualquier campo de autenticación.

Añadido en la versión 245.

--json=FORMATO

Selecciona el modo de salida JSON (como --output=json) y selecciona el modo de visualización preciso. Toma uno de los valores "pretty" o "short". Si es "pretty", se insertan espacios en blanco y saltos de línea amigables para humanos en la salida para hacer que los datos JSON sean más legibles. Si es "short", se suprimen todos los espacios en blanco superfluos.

Añadido en la versión 250.

--service=SERVICIO[:SERVICIO...], -s SERVICIO:SERVICIO...

Controla qué servicios consultar para usuarios/grupos. Toma una lista de uno o más nombres de servicio, separados por ":". Consulte abajo para ver una lista de nombres de servicio conocidos. Si no se especifica, se consultan todos los servicios disponibles a la vez.

Añadido en la versión 245.

--with-nss=BOOL

Controla si se incluyen búsquedas de usuarios/grupos clásicos glibc/NSS en la salida. Si se usa --with-nss=no, se suprimen todos los intentos de resolver o enumerar usuarios/grupos proporcionados solo a través de glibc NSS. Si se especifica --with-nss=yes, se incluyen dichos usuarios/grupos en la salida (que es el valor predeterminado).

Añadido en la versión 245.

--with-varlink=BOOL

Controla si se incluyen búsquedas de usuarios/grupos Varlink en la salida, es decir, las realizadas a través de la API de Búsqueda de Registros de Usuarios/Grupos vía Varlink[3]. Si se usa --with-varlink=no, se suprimen todos los intentos de resolver o enumerar usuarios/grupos proporcionados solo a través de Varlink. Si se especifica --with-varlink=yes, se incluyen dichos usuarios/grupos en la salida (que es el valor predeterminado).

Añadido en la versión 249.

--with-dropin=BOOL

Controla si se incluyen en la salida búsquedas de usuarios/grupos definidas utilizando archivos drop-in en /etc/userdb/, /run/userdb/, /run/host/userdb/, /usr/lib/userdb/. Si se usa --with-dropin=no, se suprimen estos registros. Si se especifica --with-dropin=yes, se incluyen dichos usuarios/grupos en la salida (que es el valor predeterminado).

Añadido en la versión 249.

--synthesize=BOOL

Controla si se sintetizan registros para los usuarios/grupos root y nobody si no están definidos de otra manera, así como los usuarios/grupos para el rango de UID "externo". Por defecto (o con "yes"), dichos registros se sintetizan implícitamente si faltan de otra manera, ya que tienen una importancia especial para el SO. Cuando es "no", esta síntesis se desactiva.

Añadido en la versión 245.

-N

Esta opción es un atajo para --with-nss=no --synthesize=no. Use esta opción para mostrar solo registros que están definidos nativamente como registros de usuario o grupo JSON, con toda la compatibilidad NSS/glibc y toda la síntesis implícita desactivada.

Añadido en la versión 245.

--multiplexer=BOOL

Controla si se realizan búsquedas a través del servicio multiplexor (si se especifica como verdadero, que es el valor predeterminado) o si se realizan búsquedas en el cliente (si se especifica como falso). Usar el servicio multiplexor es típicamente preferible, ya que se ejecuta en un entorno controlado y aislado.

Añadido en la versión 250.

--chain

Cuando se usa con el comando ssh-authorized-keys, esto permitirá pasar un comando adicional después del nombre de usuario que se ejecuta en cadena después de que la búsqueda se complete. Esto permite encadenar múltiples herramientas que muestran claves autorizadas de SSH.

Añadido en la versión 250.

--fuzzy, -z

Cuando se usa con el comando user o group, realiza una búsqueda de cadena difusa. Los argumentos especificados se compararán con el nombre de usuario, el nombre real del registro de usuario, la dirección de correo electrónico y otras cadenas descriptivas del registro de usuario o grupo. Además, en lugar de una coincidencia precisa, se aplica una coincidencia de subcadena o una coincidencia que permite ligeras desviaciones en la ortografía.

Añadido en la versión 257.

--disposition=

Cuando se usa con el comando user o group, filtra por la disposición del registro. Toma uno de los valores "intrinsic", "system", "regular", "dynamic", "container". Puede usarse múltiples veces, en cuyo caso solo se mostrarán los usuarios que coincidan con cualquiera de las disposiciones especificadas.

Añadido en la versión 257.

-I, -S, -R

Atajos para --disposition=intrinsic, --disposition=system, --disposition=regular, respectivamente.

Añadido en la versión 257.

--uid-min=, --uid-max=

Cuando se usa con el comando user o group, filtra la salida por rangos de UID/GID. Toma valores numéricos mínimos o máximos de UID/GID, respectivamente. Muestra solo registros dentro del rango especificado. Cuando se aplica al comando user, coincide con UIDs. Cuando se aplica al comando group, coincide con GIDs (a pesar del nombre del interruptor). Si no se especifica, el valor predeterminado es 0 (para el mínimo) y 4294967294 (para el máximo), es decir, por defecto, no se aplica ningún filtro, ya que se cubre todo el rango de UID/GID.

Añadido en la versión 257.

--boundaries=

Cuando se usa con el comando user o group, controla si se muestran las informaciones relevantes sobre los límites del rango de UID/GID en la salida tabular. Toma un valor booleano. Por defecto es verdadero.

Añadido en la versión 257.

-B

Atajo para --boundaries=no.

Añadido en la versión 257.

--from-file=RUTA, -f

Cuando se usa con el comando user o group, lee la definición de usuario en formato JSON del archivo especificado, en lugar de consultarla en el sistema. Si la ruta se especifica como "-", lee los datos JSON de la entrada estándar. Esto es útil para validar e introspeccionar registros de usuario o grupo JSON rápidamente, y verificar cómo se interpretarían en el sistema local.

Añadido en la versión 258.

--no-pager

No canalizar la salida a un paginador.

--no-legend

No imprimir la leyenda, es decir, las cabeceras de las columnas y el pie de página con sugerencias.

-h, --help

Imprime un texto de ayuda corto y sale.

--version

Imprime una cadena de versión corta y sale.

$SYSTEMD_LESS

Anula las opciones pasadas a less (por defecto "FRSXMK").

Los usuarios podrían querer cambiar dos opciones en particular:

K

Esta opción indica al paginador que salga inmediatamente cuando se presiona Ctrl+C. Para permitir que less maneje Ctrl+C por sí mismo para volver al prompt del comando del paginador, desestablece esta opción.

Si el valor de $SYSTEMD_LESS no incluye "K", y el paginador que se invoca es less, Ctrl+C será ignorado por el ejecutable y deberá ser manejado por el paginador.

X

Esta opción indica al paginador que no envíe cadenas de inicialización y desinicialización de termcap a la terminal. Está configurada por defecto para permitir que la salida del comando permanezca visible en la terminal incluso después de que el paginador salga. Sin embargo, esto impide que algunas funcionalidades del paginador funcionen, en particular la salida paginada no se puede desplazarse con el ratón.

Tenga en cuenta que establecer la variable de entorno regular $LESS no tiene ningún efecto para las invocaciones de less por parte de las herramientas de systemd.

Consulte less(1) para más discusión.

$SYSTEMD_LESSCHARSET

Anula el conjunto de caracteres pasado a less (por defecto "utf-8", si se determina que la terminal invocadora es compatible con UTF-8).

Tenga en cuenta que establecer la variable de entorno regular $LESSCHARSET no tiene ningún efecto para las invocaciones de less por parte de las herramientas de systemd.

$SYSTEMD_PAGERSECURE

Comandos de paginador comunes como less(1), además de "paginación", es decir, desplazamiento a través de la salida, soportan la apertura o escritura de otros archivos y la ejecución de comandos de shell arbitrarios. Cuando los comandos se invocan con privilegios elevados, por ejemplo bajo sudo(8) o pkexec(1), el paginador se convierte en un límite de seguridad. Se debe tener cuidado de que solo se utilicen programas con funcionalidad estrictamente limitada como paginadores, y no se permitan funciones interactivas no deseadas como la apertura o creación de nuevos archivos o el inicio de subprocesos. El "modo seguro" para el paginador puede habilitarse como se describe a continuación, si el paginador lo soporta (la mayoría de los paginadores no están escritos de manera que tengan esto en cuenta). Se recomienda habilitar explícitamente el "modo seguro" o deshabilitar completamente el paginador usando --no-pager o PAGER=cat al permitir que usuarios no confiables ejecuten comandos con privilegios elevados.

Esta opción toma un argumento booleano. Cuando se establece a verdadero, el "modo seguro" del paginador se habilita. En "modo seguro", se establecerá LESSSECURE=1 al invocar el paginador, lo que indica al paginador que deshabilite los comandos que abren o crean nuevos archivos o inician nuevos subprocesos. Actualmente, solo se sabe que less(1) entiende esta variable e implementa el "modo seguro".

Cuando se establece a falso, no se impone ninguna limitación al paginador. Establecer SYSTEMD_PAGERSECURE=0 o no eliminarlo del entorno heredado puede permitir al usuario invocar comandos arbitrarios.

Cuando $SYSTEMD_PAGERSECURE no está configurado, las herramientas de systemd intentan determinar automáticamente si se debe habilitar el "modo seguro" y si el paginador lo soporta. El "modo seguro" se habilita si la UID efectiva no es la misma que la del propietario de la sesión de inicio de sesión, consulte geteuid(2) y sd_pid_get_owner_uid(3), o al ejecutarse bajo sudo(8) o herramientas similares ($SUDO_UID está configurado [4]). En esos casos, se establecerá SYSTEMD_PAGERSECURE=1 y los paginadores que no se sabe que implementan el "modo seguro" no se utilizarán en absoluto. Tenga en cuenta que esta autodetección solo cubre los mecanismos más comunes para elevar privilegios y está destinada a ser una conveniencia. Se recomienda establecer explícitamente $SYSTEMD_PAGERSECURE o deshabilitar el paginador.

Tenga en cuenta que si las variables $SYSTEMD_PAGER o $PAGER van a ser honradas, aparte de deshabilitar el paginador, $SYSTEMD_PAGERSECURE también debe estar configurado.

$SYSTEMD_COLORS

Toma un argumento booleano. Cuando es verdadero, systemd y utilidades relacionadas usarán colores en su salida, de lo contrario la salida será monocromática. Adicionalmente, la variable puede tomar uno de los siguientes valores especiales: "16", "256" para restringir el uso de colores a los 16 o 256 colores ANSI base, respectivamente. Esto puede especificarse para anular la decisión automática basada en $TERM y a qué está conectada la consola.

$SYSTEMD_URLIFY

El valor debe ser un booleano. Controla si se deben generar enlaces clicables en la salida para los emuladores de terminal que soportan esto. Esto puede especificarse para anular la decisión que systemd toma basándose en $TERM y otras condiciones.
