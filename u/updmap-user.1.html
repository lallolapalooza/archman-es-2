UPDMAP(1) Comandos de usuario UPDMAP(1)

NOMBRE

updmap - gestionar mapas de fuentes TeX
updmap-sys - gestionar mapas de fuentes TeX, a nivel de sistema
updmap-user - gestionar mapas de fuentes TeX, por usuario

SINOPSIS

updmap [-user|-sys] [OPCIÓN] ... [COMANDO]
updmap-user [OPCIÓN] ... [COMANDO]
updmap-sys [OPCIÓN] ... [COMANDO]

DESCRIPCIÓN

updmap versión r65932 (2023-02-19 21:49:48 +0100)

Actualiza los archivos de mapa de fuentes predeterminados utilizados por pdftex y dvipdfm(x) (pdftex.map), dvips (psfonts.map) y opcionalmente pxdvi, según lo determinado por todos los archivos de configuración updmap.cfg (generalmente los devueltos al ejecutar "kpsewhich --all updmap.cfg", pero véase más abajo).

Entre otras cosas, estos archivos de mapa se utilizan para determinar qué fuentes deben usarse como mapas de bits y cuáles como contornos, y para determinar qué archivos de fuentes se incluyen, típicamente subdivididos, en la salida PDF o PostScript.

updmap-sys (o updmap -sys) está destinado a afectar la configuración a nivel de sistema, mientras que updmap-user (o updmap -user) afecta solo a los archivos de configuración personales, anulando los archivos del sistema.

Como consecuencia, una vez que se ha ejecutado updmap-user, incluso una sola vez, ejecutar updmap-sys ya no tiene ningún efecto. updmap-sys emite una advertencia sobre esto, ya que rara vez es deseable. Consulte https://tug.org/texlive/scripts-sys-user.html para más detalles.

Por defecto, la base de datos de nombres de archivo TeX (ls-R) también se actualiza.

El sistema updmap es lamentablemente complicado, tanto por razones inherentes como históricas. Una visión general:

- Los archivos updmap.cfg se refieren principalmente a la enumeración de otros archivos, a saber, los

archivos .maps específicos de fuentes, en los que cada línea proporciona información sobre una fuente TeX (.tfm) diferente.

- updmap lee los archivos updmap.cfg y luego concatena el

contenido de esos archivos .map en los archivos de salida principales: psfonts.map para dvips y pdftex.map para pdftex y dvipdfmx.

- Los archivos updmap.cfg se crean y actualizan en el momento de la instalación del

paquete, por el instalador del sistema, el gestor de paquetes o manualmente, y no (por defecto) por updmap.

La salida principal:

La salida principal de updmap son los archivos que contienen las líneas individuales de mapa de fuentes que los drivers (dvips, pdftex, etc.) leen para manejar las fuentes.
Los archivos de mapa para dvips (psfonts.map) y pdftex y dvipdfmx (pdftex.map) se escriben en TEXMFVAR/fonts/map/updmap/{dvips,pdftex}/.
Además, la información sobre fuentes Kanji se escribe en TEXMFVAR/fonts/map/updmap/dvipdfmx/kanjix.map, y opcionalmente en TEXMFVAR/fonts/map/updmap/pxdvi/xdvi-ptex.map. Estos son solo para Kanji y no son como otros archivos de mapa. dvipdfmx lee pdftex.map para las entradas del mapa para fuentes no Kanji.
Si no se da ninguna opción, de modo que la invocación sea solo "updmap-user" o "updmap-sys", estos archivos de salida siempre se recrean.
De lo contrario, si se da una opción como --enable o --disable, los archivos de salida se recrean si la lista de mapas habilitados (de updmap.cfg) ha cambiado. La opción --force anula esto, recreando siempre los archivos de salida.

Explicación de los tipos de mapa:

El tipo normal es Map.
La única diferencia entre Map y MixedMap es que las entradas de MixedMap no se añaden a psfonts_pk.map. El propósito es ayudar a los usuarios con dispositivos que renderizan fuentes de contorno Type 1 peor que fuentes de mapa de bits Type 3 ajustadas al modo. Por lo tanto, MixedMap se usa para fuentes que están disponibles tanto en Type 1 como en Metafont.
Las entradas de KanjiMap se añaden a psfonts_t1.map y kanjix.map.

Explicación de los nombres de OPCIÓN para --showoptions, --showoption, --setoption:

dvipsPreferOutline
true,false (predeterminado true)
Si dvips usa mapas de bits o contornos, cuando ambos están disponibles.
dvipsDownloadBase35
true,false (predeterminado true)
Si dvips incluye las 35 fuentes estándar de PostScript en su salida.
pdftexDownloadBase14
true,false (predeterminado true)
Si pdftex incluye las 14 fuentes estándar de PDF en su salida.

COMANDOS

--enable MAPTYPE MAPFILE
añadir "MAPTYPE MAPFILE" a updmap.cfg, donde MAPTYPE es Map, MixedMap, o KanjiMap
--disable MAPFILE
deshabilitar MAPFILE, de cualquier tipo
--listmaps
mostrar el contenido de los archivos de mapa principales (pdftex.map, psfonts.map, etc.), y la lista de mapas habilitados en updmap.cfg.

Los mapas en los archivos de mapa están separados por una línea que contiene solo un asterisco (*).

--listavailablemaps
listar los nombres de los mapas que están instalados en el árbol Texmf.

Los nombres de los mapas en los archivos de mapa son solo el nombre del archivo sin la extensión .map.

--syncwithtrees
deshabilitar los mapas que no se encuentran en los árboles Texmf. Esto es útil después de eliminar paquetes de fuentes.

OPTIONS

The configuration file updmap.cfg can contain configuration commands. Each command is of the form

command [arguments...]

The possible commands are:

Map
(mapfile)
MixedMap
(mapfile)
KanjiMap
(mapfile)
SetDesignerFontMap
(fontname, mapfile)
These commands are processed in the order they appear in the configuration files.
The command Map adds the given map file to the list of available maps. The file is searched for in the TeX search path.
MixedMap is like Map, but the map file may contain references to PostScript Type 1 font files, which are then substituted by Type 42 font files. This is useful for dvips.
KanjiMap is like Map, but is intended for use with Kanji fonts.
SetDesignerFontMap is used to specify a map file for a given font family.
The commands below are processed after all the map files have been read.
pdftexUse
true,false (default true)
Whether pdftex includes the standard 14 PDF fonts in its output.
pxdviUse
true,false (default false)
Whether maps for pxdvi (Japanese-patched xdvi) are under updmap's control.
jaEmbed
(any string)
jaVariant
(any string)
scEmbed
(any string)
tcEmbed
(any string)
koEmbed
(any string)
See below.
LW35
URWkb,URW,ADOBEkb,ADOBE (default URWkb)
Adapt the font and file names of the standard 35 PostScript fonts.
URWkb
URW fonts with "berry" filenames    (e.g. uhvbo8ac.pfb)
URW
URW fonts with "vendor" filenames   (e.g. n019064l.pfb)
ADOBEkb
Adobe fonts with "berry" filenames (e.g. phvbo8an.pfb)
ADOBE
Adobe fonts with "vendor" filenames (e.g. hvnbo___.pfb)
These options are only read and acted on by updmap; dvips, pdftex, etc., do not know anything about them. They work by changing the default map file which the programs read, so they can be overridden by specifying command-line options or configuration files to the programs, as explained at the beginning of updmap.cfg.
The options jaEmbed and jaVariant (formerly kanjiEmbed and kanjiVariant) specify special replacements in the map lines. If a map contains the string @jaEmbed@, then this will be replaced by the value of that option; similarly for jaVariant. In this way, users of Japanese TeX can select different fonts to be included in the final output. The counterpart for Simplified Chinese, Traditional Chinese and Korean fonts are scEmbed, tcEmbed and koEmbed respectively.

ENVIRONMENT

Explanation of trees and files normally used:

If --cnffile is specified on the command line (can be given multiple times), its value(s) is(are) used. Otherwise, updmap reads all the updmap.cfg files found by running `kpsewhich -all updmap.cfg', in the order returned by kpsewhich (which is the order of trees defined in texmf.cnf).
In either case, if multiple updmap.cfg files are found, all the maps mentioned in all the updmap.cfg files are merged.
Thus, if updmap.cfg files are present in all trees, and the default layout is used as shipped with TeX Live, the following files are read, in the given order.
For updmap-sys:
TEXMFSYSCONFIG $TEXLIVE/YYYY/texmf-config/web2c/updmap.cfg
TEXMFSYSVAR    $TEXLIVE/YYYY/texmf-var/web2c/updmap.cfg
TEXMFLOCAL     $TEXLIVE/texmf-local/web2c/updmap.cfg
TEXMFDIST      $TEXLIVE/YYYY/texmf-dist/web2c/updmap.cfg
For updmap-user:
TEXMFCONFIG    $HOME/.texliveYYYY/texmf-config/web2c/updmap.cfg
TEXMFVAR       $HOME/.texliveYYYY/texmf-var/web2c/updmap.cfg
TEXMFHOME      $HOME/texmf/web2c/updmap.cfg
TEXMFSYSCONFIG $TEXLIVE/YYYY/texmf-config/web2c/updmap.cfg
TEXMFSYSVAR    $TEXLIVE/YYYY/texmf-var/web2c/updmap.cfg
TEXMFLOCAL     $TEXLIVE/texmf-local/web2c/updmap.cfg
TEXMFDIST      $TEXLIVE/YYYY/texmf-dist/web2c/updmap.cfg
(where YYYY is the TeX Live release version).
According to the actions, updmap might write to one of the given files or create a new updmap.cfg, described further below.

Where and which updmap.cfg changes are saved:

When no options are given, the updmap.cfg file(s) are only read, not written. It's when an option --setoption, --enable or --disable is specified that an updmap.cfg needs to be updated. In this case:
1) If config files are given on the command line, then the first one given is used to save any such changes.
2) If the config files are taken from kpsewhich output, then the algorithm is more complex:
2a) If $TEXMFCONFIG/web2c/updmap.cfg or $TEXMFHOME/web2c/updmap.cfg appears in the list of used files, then the one listed first by kpsewhich --all (equivalently, the one returned by kpsewhich updmap.cfg), is used.
2b) If neither of the above two are present and changes are made, a new config file is created in $TEXMFCONFIG/web2c/updmap.cfg.
In general, the idea is that if the user cannot write to a given config file, a higher-level one can be used. That way, the distribution's settings can be overridden system-wide using TEXMFLOCAL, and system settings can be overridden again in a particular user's TEXMFHOME or TEXMFCONFIG.

Resolving multiple definitions of a font:

If a font is defined in more than one map file, then the definition coming from the first-listed updmap.cfg is used. If a font is defined multiple times within the same map file, one is chosen arbitrarily. In both cases a warning is issued.

Disabling maps:

updmap.cfg files with higher priority (listed earlier) can disable maps mentioned in lower priority (listed later) updmap.cfg files by writing, e.g.,
#! Map mapname.map
or
#! MixedMap mapname.map
in the higher-priority updmap.cfg file.
(The #! must be at the
beginning of the line, with at least one space or tab afterward, and whitespace between each word on the list.)
As an example, suppose you have a copy of MathTime Pro fonts and want to disable the Belleek version of the fonts; that is, disable the map belleek.map. You can create the file $TEXMFCONFIG/web2c/updmap.cfg with the content
#! Map belleek.map Map mt-plus.map Map mt-yy.map
and call updmap.

Listing of maps:

The two options --listmaps and --listavailablemaps list all maps defined in any of the updmap.cfg files (for --listmaps), and only those actually found on the system (for --listavailablemaps). The output format is one line per font map, with the following fields separated by tabs: map, type (Map, MixedMap, KanjiMap), status (enabled, disabled), origin (the updmap.cfg file where it is mentioned, or 'builtin' for the three basic maps).
In the case of --listmaps there can be one additional fields (again separated by tab) containing '(not available)' for those map files that cannot be found.

updmap-user vs. updmap-sys:

When updmap-sys is run, TEXMFSYSCONFIG and TEXMFSYSVAR are used instead of TEXMFCONFIG and TEXMFVAR, respectively. This is the primary difference between updmap-sys and updmap-user.
Other locations may be used if you give them on the command line, or these trees don't exist, or you are not using the original TeX Live.

To see the precise locations of the various files that will be read and written, give the -n option (or read the source).

EXAMPLES

The log file is written to TEXMFVAR/web2c/updmap.log.

For step-by-step instructions on making new fonts known to TeX, read https://tug.org/fonts/fontinstall.html. For even more terse instructions, read the beginning of the main updmap.cfg file.

FILES

Configuration and input files:

updmap.cfg
Main configuration file. In texmf-dist/web2c by default, but may be located elsewhere depending on your distribution. Each texmf tree read should have its own updmap.cfg.
dvips35.map
Map file for standard 35 PostScript fonts for use with dvips(1).
pdftex35.map
Map file for standard 35 PostScript fonts for use with pdftex(1).
ps2pk35.map
Map file for standard 35 PostScript fonts for use with ps2pk(1).

Output files:

psfonts.map
For dvips(1). Same as psfonts_t1.map if option dvipsPreferOutline active, else as psfonts_pk.map.
psfonts_pk.map
For dvips(1). Without information from MixedMap files. (Setting of dvipsPreferOutline ignored.)
psfonts_t1.map
For dvips(1). With information from MixedMap files. (Setting of dvipsPreferOutline ignored.)
download35.map
For dvips(1). Always downloads the standard 35 fonts. (Setting of dvipsDownloadBase35 ignored.)
builtin35.map
For dvips(1). Never downloads the standard 35 fonts. (Setting of dvipsDownloadBase35 ignored.)
pdftex.map
For pdftex(1). Same as pdftex_dl14.map if option pdftexDownloadBase14 active, else as pdftex_n

FILES

Map files for updmap-user(1):

psfonts.map
The default map file for PostScript fonts. This includes Type 1 fonts and older Type 3 fonts.
psfonts_t1.map
This map file contains only Type 1 fonts. Use this when you want to avoid using Type 3 fonts or when generating PDF files.
psfonts_pk.map
This map file is used when generating PK fonts, for example, with dvips(1) or xdvi(1) when a PK font is required.
pdftex_dl14.map
For pdftex(1). Always downloads the standard 14 fonts.
pdftex_ndl14.map
For pdftex(1). Never downloads the standard 14 fonts.
ps2pk.map
Similar to psfonts.map file, but forces all fonts to be downloaded, so this map file can be used with xdvi(1) and ps2pk(1).

Configuration files for dvips(1):

config.builtin35
Loads builtin35.map instead of psfonts.map.
config.download35
Loads download35.map instead of psfonts.map.
config.outline
Loads psfonts_t1.map instead of psfonts.map.
config.pdf
Loads psfonts_t1.map instead of psfonts.map and has additional settings for PDF generation.
config.pk
Loads psfonts_pk.map instead of psfonts.map.
config.www
Loads psfonts_t1.map instead of psfonts.map. (For compatibility with old versions.)
config.gstopk
Loads psfonts_t1.map instead of psfonts.map.
