DESCRIPCIÓN

Unbound es una implementación de un resolvedor DNS que realiza caché y validación DNSSEC. Esta es la API de la biblioteca para usar la biblioteca -lunbound. El demonio del servidor se describe en unbound(8). La biblioteca funciona independientemente de un servidor unbound en ejecución, y puede ser utilizada para convertir nombres de host en direcciones IP y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de las claves públicas de los resultados con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Puede ser creada y eliminada en cualquier momento. Crearla de nuevo elimina cualquier configuración previa (como claves de confianza) y borra cualquier resultado en caché.

Las funciones son seguras para hilos, y un contexto puede ser utilizado en un entorno con hilos (así como en uno sin hilos). La resolución (y validación) también puede ser realizada de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve el control de la llamada inmediatamente, para que el procesamiento pueda continuar mientras los resultados están disponibles más tarde.

Las funciones se discuten por turnos a continuación.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza por defecto. Utiliza ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esta función, utiliza las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si utilizas lib openssl (la aplicación llama a estas funciones una vez para inicialización). Openssl 1.0.0 o posterior utiliza la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y las devoluciones de llamada no se llaman para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que permite especificar una de las opciones del formato del archivo de configuración, véase unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como añadir anclas de confianza, existen rutinas especiales. Pasa el nombre de la opción con los dos puntos al final (:).
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene el valor de una opción. Algunas opciones no se pueden obtener, y otras devuelven una lista separada por saltos de línea. Pasa el nombre de la opción sin los dos puntos al final (:). El valor devuelto debe ser liberado (free(2)) por el llamador.
ub_ctx_config
Una interfaz para usuarios avanzados que permite especificar un archivo de configuración de unbound, véase unbound.conf(5), que se lee para la configuración. No todas las opciones son relevantes. Para algunas opciones específicas, como añadir anclas de confianza, existen rutinas especiales. Esta función solo es segura para hilos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no se llama en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se reenviarán las consultas DNS, el resolvedor de caché a utilizar. Dirección IP4 o IP6. Reenvía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolvedor recursivo. Si el proxy no es capaz de DNSSEC, la validación puede fallar. Se puede llamar varias veces, en cuyo caso las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autoritativos a utilizar para una zona en particular. Dirección IP4 o IP6. Si la dirección es NULL, se elimina la entrada stub. Establece isprime a true si configuras hints de raíz con ella. De lo contrario, es similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas, o para añadir múltiples direcciones para una zona en particular. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolución completo, pero puedes usar esta llamada para leer la lista de servidores de nombres a utilizar desde el nombre de archivo proporcionado. Normalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no soportan DNSSEC, la validación puede fallar. Solo se recogen los servidores de nombres, el dominio de búsqueda, ndots y otras configuraciones de resolv.conf(5) se ignoran. Si se pasa NULL como fname, se utiliza "/etc/resolv.conf" (si en Windows, se elige el servidor de nombres configurado a nivel del sistema en su lugar). En este momento, solo es posible establecer la configuración antes de la primera resolución.
ub_ctx_hosts
Lee la lista de hosts desde el nombre de archivo proporcionado. Normalmente "/etc/hosts". Cuando se consultan, estas direcciones no se marcan como seguras con DNSSEC. Si se pasa NULL como fname, se utiliza "/etc/hosts" (si en Windows, se elige etc/hosts desde WINDIR en su lugar). En este momento, solo es posible establecer la configuración antes de la primera resolución.
ub_ctx_add_ta
Añade una clave de confianza a la lista de anclas de confianza. La cadena de entrada debe estar en el formato: clave-algoritmo:base32-clave. Ejemplo: 8:zD8OHV02V83aL0eXvPzB4e0j+p5S2t+cK3o3X9bFp2Q=. Esto es para añadir una clave de confianza para la zona raíz. La validación DNSSEC requiere la clave de confianza correcta de la zona raíz.
ub_ctx_add_ta_autr
Añade anclas de confianza desde un archivo de autor, que contiene las claves de confianza para una zona especificada en el archivo.
ub_ctx_add_ta_file
Añade anclas de confianza desde un archivo especificado. El archivo contiene líneas con la clave de confianza en el formato: clave-algoritmo:base32-clave.
ub_ctx_trustedkeys
Lee las claves de confianza de un archivo especificado. El archivo contiene líneas con la clave de confianza en el formato: clave-algoritmo:base32-clave. Esto se utiliza para validar las claves de confianza para el DNSSEC.
ub_ctx_debugout
Establece el flujo de salida para los mensajes de depuración. Por defecto, es stderr.
ub_ctx_debuglevel
Establece el nivel de depuración. 0 es sin depuración, 1 es información general, 2 es detallada, 3 es más detallada. Los niveles más altos pueden ralentizar el rendimiento.
ub_ctx_async
Si dothread es 1, habilita el modo asíncrono, donde las llamadas de resolución devuelven inmediatamente. La aplicación debe entonces llamar a ub_poll o ub_wait para obtener los resultados. Si dothread es 0, se desactiva el modo asíncrono y las llamadas de resolución son bloqueantes.
ub_poll
Comprueba si hay datos disponibles de las consultas asíncronas y procesa cualquier dato recibido. Debe llamarse repetidamente cuando el contexto está en modo asíncrono y se está esperando una respuesta. Devuelve el número de descriptores de archivo que se están vigilando, o 0 si no hay actividad.
ub_wait
Espera hasta que haya actividad de red disponible en cualquier descriptor de archivo asociado con el contexto. Se bloquea hasta que haya datos disponibles o hasta que expire un temporizador. Útil en modo asíncrono para esperar resultados.
ub_fd
Devuelve un descriptor de archivo que se puede utilizar con select() o poll() para detectar actividad de red. Esto es útil cuando se utiliza el modo asíncrono para saber cuándo hay datos listos para ser procesados por ub_process().
ub_process
Procesa cualquier dato de red disponible en los descriptores de archivo asociados con el contexto. Debe llamarse cuando ub_poll() indica actividad o cuando se recibe una notificación de que los datos están listos. Esto es necesario para completar las consultas asíncronas.
ub_resolve
Resuelve un nombre de host en una dirección IP, o viceversa, utilizando la configuración del contexto. rrtype especifica el tipo de registro DNS (por ejemplo, 1 para A (IPv4), 28 para AAAA (IPv6)). rrclass especifica la clase DNS (normalmente 1 para IN (Internet)). El resultado se devuelve en la estructura ub_result, que debe ser liberada con ub_resolve_free(). Esta es una llamada bloqueante.
ub_resolve_async
Similar a ub_resolve, pero realiza la resolución de forma asíncrona. mydata es un puntero a datos definidos por el usuario que se pasarán a la función de devolución de llamada. callback es un puntero a una función de devolución de llamada que se llamará cuando la resolución se complete. async_id es un puntero a un entero que recibirá un ID único para esta consulta asíncrona. La función devuelve inmediatamente. La aplicación debe entonces llamar a ub_poll() y ub_process() para obtener los resultados.
ub_cancel
Cancela una consulta de resolución asíncrona dada por su async_id.
ub_resolve_free
Libera la memoria utilizada por la estructura ub_result devuelta por ub_resolve() o ub_resolve_async().
ub_strerror
Devuelve una cadena de texto que describe un código de error devuelto por las funciones de libunbound.
ub_ctx_print_local_zones
Imprime las zonas locales configuradas para el contexto actual.
ub_ctx_zone_add
Añade una zona local al contexto. zone_type puede ser "static" o "transparent".
ub_ctx_zone_remove
Elimina una zona local del contexto.
ub_ctx_data_add
Añade datos DNS (registros) al contexto. Los datos deben estar en formato BIND zone file.
ub_ctx_data_remove
Elimina datos DNS (registros) del contexto.

DESCRIPTION

The libunbound library provides an API to the unbound validating, recursive, caching DNS resolver. This API allows applications to perform DNS lookups that are validated using DNSSEC. It supports both synchronous and asynchronous lookups.

A context struct ub_ctx must be created using ub_ctx_create before any other functions can be called. The context holds the configuration and state of the resolver. When the context is no longer needed, it must be freed using ub_ctx_delete.

The context can be configured using functions like ub_ctx_resolvconf to read system resolver information, ub_ctx_config to read unbound configuration files, and ub_ctx_add_ta, ub_ctx_add_ta_autr, ub_ctx_add_ta_file, and ub_ctx_trustedkeys to add DNSSEC trust anchors. Debug output can be directed to a specific file stream using ub_ctx_debugout and verbosity controlled with ub_ctx_debuglevel.

ub_ctx_async controls whether asynchronous operations use threading or forking. By default, threading is used.

To perform DNS lookups, you can use either synchronous ub_resolve or asynchronous ub_resolve_async.

ub_resolve performs a lookup and blocks until the result is available. It returns a pointer to a dynamically allocated struct ub_result, which must be freed using ub_resolve_free.

ub_resolve_async initiates a lookup that completes later. A callback function is invoked when the result is ready. The callback receives a user-provided pointer (mydata), an error code, and the result structure. The async_id can be used to cancel the query using ub_cancel.

For asynchronous operations, you need to interact with the event loop. ub_fd returns a file descriptor that becomes readable when results are available. You should poll this descriptor. When it's readable, call ub_process to handle callbacks. Alternatively, ub_poll can be used to check if any results are ready without blocking, and ub_wait blocks until all pending asynchronous queries are finished.

The library also supports adding and removing local authority information for zones and specific data using functions like ub_ctx_zone_add and ub_ctx_data_add.

Error codes returned by most functions can be converted to human-readable strings using ub_strerror.

FUNCTIONS

ub_ctx_create
Create a new context for the unbound validating resolver. Returns a pointer to the context, or NULL on error (e.g., memory allocation failure).
ub_ctx_delete
Delete the context and free all associated resources. Call this when you are done with the context.
ub_ctx_resolvconf
Read system resolver configuration (e.g., from /etc/resolv.conf). Pass the name of the configuration file. If NULL is passed, it attempts to read the system's default resolv.conf file.
ub_ctx_config
Read unbound configuration options from a file. Pass the name of the configuration file. This can be used to set options like trust anchors, forwarding, interfaces, etc., as described in unbound.conf(5).
ub_ctx_add_ta
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
ub_ctx_add_ta_autr
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta_file
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_trustedkeys
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_debugout
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
ub_ctx_debuglevel
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
ub_ctx_async
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
ub_poll
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
ub_wait
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
ub_fd
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
ub_process
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
ub_resolve
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
ub_resolve_async
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

ub_cancel
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
ub_resolve_free
Free struct ub_result contents after use.
ub_strerror
Convert error value from one of the unbound library functions to a human readable string.
ub_ctx_print_local_zones
Debug printout the local authority information to debug output.
ub_ctx_zone_add
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
ub_ctx_zone_remove
Delete zone from local authority info.
ub_ctx_data_add
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
ub_ctx_data_remove
Delete local authority data from the name given.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Else, they are not both true, one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.
