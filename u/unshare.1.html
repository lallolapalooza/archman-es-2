UNSHARE(1) Comandos de usuario UNSHARE(1)

NOMBRE

unshare - ejecutar programa en nuevos espacios de nombres

SINOPSIS

unshare [opciones] [programa [argumentos]]

DESCRIPCIÓN

El comando unshare crea nuevos espacios de nombres (según se especifica en las opciones de línea de comandos descritas a continuación) y luego ejecuta el programa especificado. Si no se proporciona programa, se ejecuta "${SHELL}" (por defecto: /bin/sh).

Por defecto, un nuevo espacio de nombres solo persiste mientras tenga procesos miembros. Un nuevo espacio de nombres puede hacerse persistente incluso cuando no tiene procesos miembros montando mediante enlace (bind mount) los archivos /proc/pid/ns/tipo a una ruta de sistema de archivos. Un espacio de nombres que se ha hecho persistente de esta manera puede ser accedido posteriormente con nsenter(1) incluso después de que el programa termine (excepto para los espacios de nombres PID donde se requiere un proceso init en ejecución permanente). Una vez que un espacio de nombres persistente ya no es necesario, puede hacerse no persistente usando umount(8) para eliminar el montaje de enlace. Vea la sección de EJEMPLOS para más detalles.

unshare desde la versión 2.36 de util-linux utiliza los archivos /proc/[pid]/ns/pid_for_children y /proc/[pid]/ns/time_for_children para los espacios de nombres PID y TIME persistentes. Este cambio requiere el kernel de Linux 4.17 o más reciente.

Los siguientes tipos de espacios de nombres pueden ser creados con unshare:

Espacio de nombres de montaje

Montar y desmontar sistemas de archivos no afectará al resto del sistema, excepto a los sistemas de archivos que estén explícitamente marcados como compartidos (con mount --make-shared; vea /proc/self/mountinfo o findmnt -o+PROPAGATION para las banderas shared). Para más detalles, vea mount_namespaces(7).

unshare desde la versión 2.27 de util-linux establece automáticamente la propagación a private en un nuevo espacio de nombres de montaje para asegurarse de que el nuevo espacio de nombres esté realmente separado. Es posible deshabilitar esta característica con la opción --propagation unchanged. Tenga en cuenta que private es el valor predeterminado del kernel.

Espacio de nombres UTS

Establecer el nombre de host o dominio no afectará al resto del sistema. Para más detalles, vea uts_namespaces(7).

Espacio de nombres IPC

El proceso tendrá un espacio de nombres independiente para colas de mensajes POSIX, así como para colas de mensajes System V, conjuntos de semáforos y segmentos de memoria compartida. Para más detalles, vea ipc_namespaces(7).

Espacio de nombres de red

El proceso tendrá pilas IPv4 e IPv6 independientes, tablas de enrutamiento IP, reglas de firewall, los árboles de directorios /proc/net y /sys/class/net, sockets, etc. Para más detalles, vea network_namespaces(7).

Espacio de nombres PID

Los hijos tendrán un conjunto distinto de mapeos PID-proceso de sus padres. Para más detalles, vea pid_namespaces(7).

Espacio de nombres cgroup

El proceso tendrá una vista virtualizada de /proc/self/cgroup, y los nuevos montajes de cgroup estarán enraizados en la raíz de cgroup del espacio de nombres. Para más detalles, vea cgroup_namespaces(7).

Espacio de nombres de usuario

El proceso tendrá un conjunto distinto de UID, GID y capacidades. Para más detalles, vea user_namespaces(7).

Espacio de nombres de tiempo

El proceso puede tener una vista distinta de CLOCK_MONOTONIC y/o CLOCK_BOOTTIME que puede ser modificada usando /proc/self/timens_offsets. Para más detalles, vea time_namespaces(7).

OPCIONES

-i, --ipc[=archivo]

Crea un nuevo espacio de nombres IPC. Si se especifica archivo, entonces el espacio de nombres se hace persistente creando un montaje de enlace en archivo.

-m, --mount[=archivo]

Crea un nuevo espacio de nombres de montaje. Si se especifica archivo, entonces el espacio de nombres se hace persistente creando un montaje de enlace en archivo. Tenga en cuenta que archivo debe estar ubicado en un montaje cuyo tipo de propagación no sea shared (o se producirá un error). Use el comando findmnt -o+PROPAGATION cuando no esté seguro de la configuración actual. Vea también los ejemplos a continuación.

-n, --net[=archivo]

Crea un nuevo espacio de nombres de red. Si se especifica archivo, entonces el espacio de nombres se hace persistente creando un montaje de enlace en archivo.

-p, --pid[=archivo]

Crea un nuevo espacio de nombres PID. Si se especifica archivo, entonces el espacio de nombres se hace persistente creando un montaje de enlace en archivo. (La creación de un espacio de nombres PID persistente fallará si la opción --fork no se especifica también).

Vea también las opciones --fork y --mount-proc.

-u, --uts[=archivo]

Crea un nuevo espacio de nombres UTS. Si se especifica archivo, entonces el espacio de nombres se hace persistente creando un montaje de enlace en archivo.

-U, --user[=archivo]

Crea un nuevo espacio de nombres de usuario. Si se especifica archivo, entonces el espacio de nombres se hace persistente creando un montaje de enlace en archivo.

-C, --cgroup[=archivo]

Crea un nuevo espacio de nombres cgroup. Si se especifica archivo, entonces el espacio de nombres se hace persistente creando un montaje de enlace en archivo.

-T, --time[=archivo]

Crea un nuevo espacio de nombres de tiempo. Si se especifica archivo, entonces el espacio de nombres se hace persistente creando un montaje de enlace en archivo. Las opciones --monotonic y --boottime pueden usarse para especificar el desplazamiento correspondiente en el espacio de nombres de tiempo.

-f, --fork

Crea un proceso hijo del programa especificado mediante llamada a fork(2) en lugar de ejecutarlo directamente. Esto es útil al crear un nuevo espacio de nombres PID. Tenga en cuenta que cuando unshare está esperando al proceso hijo, ignora SIGINT y SIGTERM y no reenvía ninguna señal al hijo. Es necesario enviar señales al proceso hijo.

--keep-caps

Cuando se da la opción --user, asegúrese de que las capacidades otorgadas en el espacio de nombres de usuario se conserven en el proceso hijo.

--kill-child[=signame]

Cuando unshare termine, envíe signame al proceso hijo creado. Combinado con --pid esto permite una eliminación fácil y confiable de todo el árbol de procesos debajo de unshare. Si no se proporciona, signame por defecto es SIGKILL. Esta opción implica --fork.

--mount-proc[=punto de montaje]

Justo antes de ejecutar el programa, monte el sistema de archivos proc en punto de montaje (por defecto es /proc). Esto es útil al crear un nuevo espacio de nombres PID. También implica la creación de un nuevo espacio de nombres de montaje ya que el montaje de /proc de lo contrario podría dañar los programas existentes en el sistema. El nuevo sistema de archivos proc se monta explícitamente como privado (con MS_PRIVATE|MS_REC).

--mount-binfmt[=punto de montaje]

Justo antes de ejecutar el programa, monte el sistema de archivos binfmt_misc en punto de montaje (por defecto es /proc/sys/fs/binfmt_misc). También implica la creación de un nuevo espacio de nombres de montaje ya que el montaje binfmt_misc de lo contrario podría dañar los programas existentes en el sistema. El nuevo sistema de archivos binfmt_misc se monta explícitamente como privado (con MS_PRIVATE|MS_REC).

--map-user uid|nombre

Ejecuta el programa solo después de que el ID de usuario efectivo actual haya sido mapeado a uid. Si esta opción se especifica varias veces, la última ocurrencia tiene precedencia. Esta opción implica --user.

--map-users uidinterno:uidexterno:conteo|auto|subids|todos

Ejecuta el programa solo después de que el bloque de IDs de usuario de tamaño conteo comenzando en uidexterno haya sido mapeado al bloque de IDs de usuario

Si el rango de IDs de usuario se superpone con el mapeo especificado por --map-user, entonces se eliminará un "agujero" del mapeo. Esto puede resultar en que el ID de usuario más alto del mapeo no se mapee. Utilice --map-users varias veces para mapear más de un bloque de IDs de usuario. El valor especial auto mapeará el primer bloque de IDs de usuario propiedad del usuario efectivo de /etc/subuid a un bloque que comience en el ID de usuario 0. El valor especial subids mapeará idénticamente el mismo bloque. El valor especial all creará un mapa de paso para cada ID de usuario disponible en el espacio de nombres padre. Esta opción implica --user.

Antes de la versión 2.39 de util-linux, esta opción esperaba un argumento separado por comas de la forma outeruid,inneruid,count pero ese formato está ahora obsoleto para mantener la coherencia con el orden utilizado en /proc/[pid]/uid_map y la opción de montaje X-mount.idmap.

--map-group gid|name

Ejecute el programa solo después de que el ID de grupo efectivo actual se haya mapeado a gid. Si esta opción se especifica varias veces, la última aparición tiene precedencia. Esta opción implica --setgroups=deny y --user.

--map-groups innergid:outergid:count|auto|subids|all

Ejecute el programa solo después de que el bloque de IDs de grupo de tamaño count que comienza en outergid se haya mapeado al bloque de IDs de grupo que comienza en innergid. Este mapeo se crea con newgidmap(1) si unshare se ejecutó sin privilegios. Si el rango de IDs de grupo se superpone con el mapeo especificado por --map-group, entonces se eliminará un "agujero" del mapeo. Esto puede resultar en que el ID de grupo más alto del mapeo no se mapee. Utilice --map-groups varias veces para mapear más de un bloque de IDs de grupo. El valor especial auto mapeará el primer bloque de IDs de grupo propiedad del grupo efectivo de /etc/subgid a un bloque que comience en el ID de grupo 0. El valor especial subids mapeará idénticamente el mismo bloque. El valor especial all creará un mapa de paso para cada ID de grupo disponible en el espacio de nombres padre. Esta opción implica --user.

Antes de la versión 2.39 de util-linux, esta opción esperaba un argumento separado por comas de la forma outergid,innergid,count pero ese formato está ahora obsoleto para mantener la coherencia con el orden utilizado en /proc/[pid]/gid_map y la opción de montaje X-mount.idmap.

--map-auto

Mapee el primer bloque de IDs de usuario propiedad del usuario efectivo de /etc/subuid a un bloque que comience en el ID de usuario 0. De la misma manera, también mapee el primer bloque de IDs de grupo propiedad del grupo efectivo de /etc/subgid a un bloque que comience en el ID de grupo 0. Esta opción está destinada a manejar el caso común en el que el primer bloque de IDs de usuario y grupo subordinados puede mapear todo el espacio de IDs de usuario y grupo. Esta opción es equivalente a especificar --map-users=auto y --map-groups=auto.

--map-subids

Mapee idénticamente el primer bloque de IDs de usuario propiedad del usuario efectivo de /etc/subuid. De la misma manera, también mapee idénticamente el primer bloque de IDs de grupo propiedad del grupo efectivo de /etc/subgid. Esta opción es equivalente a especificar --map-users=subids y --map-groups=subids.

-r, --map-root-user

Ejecute el programa solo después de que los IDs de usuario y grupo efectivos actuales se hayan mapeado al UID y GID de superusuario en el espacio de nombres de usuario recién creado. Esto hace posible obtener convenientemente las capacidades necesarias para administrar varios aspectos de los espacios de nombres recién creados (como configurar interfaces en el espacio de nombres de red o montar sistemas de archivos en el espacio de nombres de montaje) incluso cuando se ejecuta sin privilegios. Como una mera característica de conveniencia, no admite casos de uso más sofisticados, como mapear múltiples rangos de UID y GID. Esta opción implica --setgroups=deny y --user. Esta opción es equivalente a --map-user=0 --map-group=0.

-c, --map-current-user

Ejecute el programa solo después de que los IDs de usuario y grupo efectivos actuales se hayan mapeado al mismo UID y GID en el espacio de nombres de usuario recién creado. Esta opción implica --setgroups=deny y --user. Esta opción es equivalente a --map-user=$(id -ru) --map-group=$(id -rg).

--propagation private|shared|slave|unchanged

Establezca recursivamente el indicador de propagación de montaje en el nuevo espacio de nombres de montaje. El valor predeterminado es establecer la propagación en private. Es posible deshabilitar esta característica con el argumento unchanged. La opción se ignora silenciosamente cuando no se solicita el espacio de nombres de montaje (--mount).

--setgroups allow|deny

Permitir o denegar la llamada al sistema setgroups(2) en un espacio de nombres de usuario.

Para poder llamar a setgroups(2), el proceso llamante debe tener al menos CAP_SETGID. Pero desde Linux 3.19 se aplica una restricción adicional: el kernel otorga permiso para llamar a setgroups(2) solo después de que se haya configurado el mapa GID (/proc/pid*/gid_map*). El mapa GID es escribible por root cuando setgroups(2) está habilitado (es decir, allow, el valor predeterminado), y el mapa GID se vuelve escribible por procesos sin privilegios cuando setgroups(2) se deshabilita permanentemente (con deny).

-R, --root dir

ejecute el comando con el directorio raíz establecido en dir.

-w, --wd dir

cambie el directorio de trabajo a dir.

-S, --setuid uid

Establezca el ID de usuario que se utilizará en el espacio de nombres al que se accede.

-G, --setgid gid

Establezca el ID de grupo que se utilizará en el espacio de nombres al que se accede y deseche los grupos suplementarios.

-l, --load-interp string

Cargue la definición de binfmt_misc en el espacio de nombres (implica --mount-binfmt). El argumento string es :name:type:offset:magic:mask:interpreter:flags. Para más detalles sobre el registro de nuevos tipos binarios, consulte https://www.kernel.org/doc/Documentation/admin-guide/binfmt-misc.rst. Para administrar la bandera F en flags con el parámetro --root, binfmt_misc se monta dos veces, una antes del chroot para cargar el intérprete desde el sistema de archivos del llamador y otra después para que esté disponible desde el espacio de usuarios del chroot.

--monotonic offset

Establezca el desplazamiento de CLOCK_MONOTONIC que se utilizará en el espacio de tiempos de tiempo al que se accede. Esta opción requiere la desvinculación de un espacio de tiempos con --time.

--boottime offset

Establezca el desplazamiento de CLOCK_BOOTTIME que se utilizará en el espacio de tiempos de tiempo al que se accede. Esta opción requiere la desvinculación de un espacio de tiempos con --time.

-h, --help

Muestre el texto de ayuda y salga.

-V, --version

Muestre la versión y salga.

NOTAS

Los sistemas de archivos proc y sysfs que se montan como raíz en un espacio de nombres de usuario deben restringirse para que un usuario menos privilegiado no pueda obtener más acceso a archivos sensibles que un usuario más privilegiado hizo inaccesibles. En resumen, la regla para proc y sysfs es lo más cercana posible a un montaje bind.

EJEMPLOS

El siguiente comando crea un espacio de nombres PID, utilizando --fork para garantizar que el comando ejecutado se realice en un proceso hijo que (siendo el primer proceso en el espacio de nombres) tiene el PID 1. La opción --mount-proc garantiza que también se cree simultáneamente un nuevo espacio de nombres de montaje y que se monte un nuevo sistema de archivos proc(5) que contiene información correspondiente al nuevo espacio de nombres PID. Cuando el comando readlink(1) termina, los nuevos espacios de nombres se desmantelan automáticamente.

# unshare --fork --pid --mount-proc readlink /proc/self
1

Como usuario sin privilegios, cree un nuevo espacio de nombres de usuario donde las credenciales del usuario se mapean a los IDs raíz dentro del espacio de nombres:

$ id -u; id -g
1000
1000
$ unshare --user --map-root-user \
        sh -c 'whoami; cat /proc/self/uid_map /proc/self/gid_map'
root
         0       1000          1
         0       1000          1

Como usuario sin privilegios, cree un espacio de nombres de usuario donde los primeros 65536 IDs se mapean, y las credenciales del usuario se mapean a los IDs raíz dentro del espacio de nombres. El mapa está determinado por los IDs subordinados asignados en subuid(5) y subgid(5). Demuestre este mapeo creando un archivo con ID de usuario 1 y ID de grupo 1. Por brevedad, solo se muestran los mapeos de ID de usuario:

$ id -u
1000
$ cat /etc/subuid
1000:100000:65536
$ unshare --user --map-auto --map-root-user
# id -u
0
# cat /proc/self/uid_map
         0       1000          1
         1     100000      65535
# touch file; chown 1:1 file
# ls -ln --time-style=+ file
-rw-r--r-- 1 1 1 0  file
# exit
$ ls -ln --time-style=+ file
-rw-r--r-- 1 100000 100000 0  file

El primero de los siguientes comandos crea un nuevo espacio de nombres UTS persistente y modifica el nombre del host como se ve en ese espacio de nombres. Luego, se accede al espacio de nombres con nsenter(1) para mostrar el nombre del host modificado; este paso demuestra que el espacio de nombres UTS continúa existiendo incluso si el espacio de nombres no tenía procesos miembros después de que terminó el comando unshare. Luego, el espacio de nombres se destruye eliminando el montaje bind.

# touch /root/uts-ns
# unshare --uts=/root/uts-ns hostname FOO
# nsenter --uts=/root/uts-ns hostname
FOO
# umount /root/uts-ns

Los siguientes comandos establecen un espacio de nombres de montaje persistente referenciado por el montaje bind /root/namespaces/mnt. Para garantizar que la creación de ese montaje bind sea exitosa, el directorio padre (/root/namespaces) se convierte en un montaje bind cuya tipo de propagación no es shared.

# mount --bind /root/namespaces /root/namespaces
# mount --make-private /root/namespaces
# touch /root/namespaces/mnt

Los siguientes comandos demuestran el uso de la opción
                    --kill-child al crear un espacio de nombres PID, para asegurar
                    que cuando unshare sea terminado, todos los procesos dentro del espacio
                    de nombres PID también lo sean.

                

                    
# set +m                # No imprimir mensajes de estado de trabajos
# unshare --pid --fork --mount-proc --kill-child -- \
       bash --norc -c '(sleep 555 &) && (ps a &) && sleep 999' &
[1] 53456
#     PID TTY      STAT   TIME COMMAND
      1 pts/3    S+     0:00 sleep 999
      3 pts/3    S+     0:00 sleep 555
      5 pts/3    R+     0:00 ps a
# ps h -o 'comm' $!     # Mostrar que el trabajo en segundo plano es unshare(1)
unshare
# kill $!               # Terminar unshare(1)
# pidof sleep

                

                
El comando pidof(1) no muestra
                    salida, porque los procesos sleep han sido terminados. Más
                    precisamente, cuando el proceso sleep con PID 1 en el espacio de
                    nombres (es decir, el proceso init del espacio de nombres) fue terminado,
                    esto causó que todos los demás procesos en el espacio de nombres también lo
                    fueran. Por el contrario, una serie similar de comandos donde la opción
                    --kill-child no se usa, muestra que cuando unshare
                    termina, los procesos en el espacio de nombres PID no son terminados:

                

                    
# unshare --pid --fork --mount-proc -- \
       bash --norc -c '(sleep 555 &) && (ps a &) && sleep 999' &
[1] 53479
#     PID TTY      STAT   TIME COMMAND
      1 pts/3    S+     0:00 sleep 999
      3 pts/3    S+     0:00 sleep 555
      5 pts/3    R+     0:00 ps a
# kill $!
# pidof sleep
53482 53480

                

                
El siguiente ejemplo demuestra la creación de un espacio de
                    nombres de tiempo donde el reloj de arranque se establece en un punto de
                    hace varios años:

                

                    
# uptime -p             # Mostrar tiempo de actividad en el espacio de nombres de tiempo inicial
up 21 hours, 30 minutes
# unshare --time --fork --boottime 300000000 uptime -p
up 9 years, 28 weeks, 1 day, 2 hours, 50 minutes

                

                
El siguiente ejemplo ejecuta un chroot en el directorio
                    /chroot/powerpc/jessie e instala el intérprete /bin/qemu-ppc-static para
                    ejecutar los binarios de powerpc.

                

                    
$  unshare --map-root-user --fork --pid --load-interp=":qemu-ppc:M::\\x7fELF\\x01\\x02\\x01\\x00\\x00\\x00\\x00\\x00\\x00\\x00\\x00\\x00\\x00\\x02\\x00\\x14:\\xff\\xff\\xff\\xff\\xff\\xff\\xff\\x00\\xff\\xff\\xff\\xff\\xff\\xff\\xff\\xff\\xff\\xfe\\xff\\xff:/bin/qemu-ppc-static:OCF" --root=/chroot/powerpc/jessie /bin/bash -l

                

                
El parámetro load-interp se puede leer de la
                    siguiente manera:

                

                    
qemu-ppc

                    
es el nombre del nuevo archivo creado debajo de
                        /proc/sys/fs/binfmt_misc para registrar el
                        intérprete

                    
M

                    
define el intérprete para un tipo dado de número
                        mágico

                    
\\x7fELF\\x01\\x02\\x01\\x00\\x00\\x00\\x00\\x00\\x00\\x00\\x00\\x00\\x00\\x02\\x00\\x1

                    
es el número mágico para reconocer el archivo a
                        interpretar (en este caso, la cabecera ELF para PPC32)

                    
\\xff\\xff\\xff\\xff\\xff\\xff\\xff\\x00\\xff\\xff\\xff\\xff\\xff\\xff\\xff\\xff\\xff\\xfe\\xff\\xff

                    
la máscara a aplicar al número mágico

                    
/bin/qemu-ppc-static

                    
el intérprete a usar con el archivo

                    
OCF

                    
el archivo es abierto por el kernel con credenciales y
                        tokens de seguridad del propio archivo y cargado tan pronto como lo
                        registramos.
