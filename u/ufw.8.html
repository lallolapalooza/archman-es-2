NOMBRE

ufw - programa para gestionar un cortafuegos netfilter

DESCRIPCIÓN

Este programa es para gestionar un cortafuegos de Linux y tiene como objetivo proporcionar una interfaz fácil de usar para el usuario.

USO

ufw [--dry-run] enable|disable|reload
ufw [--dry-run] default allow|deny|reject [incoming|outgoing|routed]
ufw [--dry-run] logging on|off|LEVEL
ufw [--dry-run] reset
ufw [--dry-run] status [verbose|numbered]
ufw [--dry-run] show REPORT
ufw [--dry-run] [delete] [insert NUM] [prepend] allow|deny|reject|limit [in|out] [log|log-all] [ PORT[/PROTOCOL] | APPNAME ] [comment COMMENT]
ufw [--dry-run] [rule] [delete] [insert NUM] [prepend] allow|deny|reject|limit [in|out [on INTERFACE]] [log|log-all] [proto PROTOCOL] [from ADDRESS [port PORT | app APPNAME ]] [to ADDRESS [port PORT | app APPNAME ]] [comment COMMENT]
ufw [--dry-run] route [delete] [insert NUM] [prepend] allow|deny|reject|limit [in|out on INTERFACE] [log|log-all] [proto PROTOCOL] [from ADDRESS [port PORT | app APPNAME]] [to ADDRESS [port PORT | app APPNAME]] [comment COMMENT]
ufw [--dry-run] [--force] delete NUM
ufw [--dry-run] app list|info|default|update

OPCIONES

--version
muestra el número de versión del programa y sale
-h, --help
muestra el mensaje de ayuda y sale
--dry-run
no modifiques nada, solo muestra los cambios
enable
recarga el cortafuegos y habilita el cortafuegos al arrancar.
disable
descarga el cortafuegos y deshabilita el cortafuegos al arrancar
reload
recarga el cortafuegos
default allow|deny|reject DIRECTION
cambia la política por defecto para el tráfico que va en la DIRECCIÓN, donde DIRECCIÓN es una de incoming, outgoing o routed. Ten en cuenta que las reglas existentes deberán ser migradas manualmente al cambiar la política por defecto. Consulta SINTAXIS DE REGLAS para más información sobre deny y reject.
logging on|off|LEVEL
activa/desactiva el registro. Los paquetes registrados usan la facilidad syslog LOG_KERN. Los sistemas configurados para el soporte de rsyslog también pueden registrar en /var/log/ufw.log. Especificar un LEVEL activa el registro para el LEVEL especificado. El nivel de registro por defecto es 'low'. Consulta REGISTRO para más detalles.
reset
Deshabilita y restaura el cortafuegos a los valores por defecto de instalación. También puede proporcionar la opción --force para realizar el restablecimiento sin confirmación.
status
muestra el estado del cortafuegos y las reglas gestionadas por ufw. Usa status verbose para información adicional. En la salida de estado, 'Anywhere' es sinónimo de 'any', 0.0.0.0/0 (IPv4) y ::/0 (IPv6). Ten en cuenta que al usar status, hay una diferencia sutil al informar sobre las interfaces. Por ejemplo, si se añaden las siguientes reglas:


ufw allow in on eth0 from 192.168.0.0/16
ufw allow out on eth1 to 10.0.0.0/8
ufw route allow in on eth0 out on eth1 to 10.0.0.0/8 from 192.168.0.0/16
ufw limit 2222/tcp comment 'SSH port'

ufw status mostrará:


To Action From
-- ------ ----
Anywhere on eth0 ALLOW 192.168.0.0/16
10.0.0.0/8 ALLOW OUT Anywhere on eth1
10.0.0.0/8 on eth1 ALLOW FWD 192.168.0.0/16 on eth0
Anywhere LIMIT Anywhere # SSH port

Para las reglas de entrada y salida, la interfaz se informa en relación con el sistema de cortafuegos como punto final, mientras que con las reglas de ruta, la interfaz se informa en relación con la dirección en la que fluyen los paquetes a través del cortafuegos.

show REPORT
muestra información sobre el cortafuegos en ejecución. Consulta INFORMES
allow ARGS
añade regla de permiso. Consulta SINTAXIS DE REGLAS
deny ARGS
añade regla de denegación. Consulta SINTAXIS DE REGLAS
reject ARGS
añade regla de rechazo. Consulta SINTAXIS DE REGLAS
limit ARGS
añade regla de límite. Consulta SINTAXIS DE REGLAS
delete RULE|NUM
elimina la REGLA correspondiente
insert NUM RULE
inserta la REGLA correspondiente como regla número NUM
prepend RULE
antepone la REGLA correspondiente al principio del conjunto de reglas

SINTAXIS DE REGLAS

Los usuarios pueden especificar reglas utilizando una sintaxis sencilla o una sintaxis completa. La sintaxis sencilla solo especifica el puerto y, opcionalmente, el protocolo a permitir o denegar en el host.

Ambas sintaxis admiten la especificación de un comentario para la regla. Para las reglas existentes, especificar un comentario diferente actualiza el comentario y especificar '' elimina el comentario (nota: 'insert' y 'prepend' no se pueden usar para actualizar el comentario).

Ejemplos de reglas usando la sintaxis sencilla:


ufw allow 53

Esta regla permitirá el puerto 53 de TCP y UDP a cualquier dirección en este host. Para especificar un protocolo, añade '/protocol' al puerto. Por ejemplo:


ufw allow 25/tcp

Esto permitirá el puerto 25 de TCP a cualquier dirección en este host. ufw también buscará en /etc/services el puerto y protocolo si se especifica un servicio por nombre. Ej:


ufw allow smtp

ufw soporta tanto filtrado de entrada como de salida y los usuarios pueden especificar opcionalmente una dirección de in o out para el tráfico entrante o saliente. Si no se proporciona ninguna dirección, la regla se aplica al tráfico entrante. Ej:


ufw allow in http
ufw reject out smtp
ufw reject telnet comment 'telnet no está cifrado'

Los usuarios también pueden usar una sintaxis más completa, especificando las direcciones y puertos de origen y destino. Esta sintaxis está vagamente basada en la sintaxis PF de OpenBSD. Por ejemplo:


ufw deny proto tcp to any port 80

Esto denegará todo el tráfico al puerto 80 de TCP en este host. Otro ejemplo:


ufw deny proto tcp from 10.0.0.0/8 to 192.168.0.1 port 25

Esto denegará todo el tráfico de la red RFC1918 Clase A al puerto 25 de TCP con la dirección 192.168.0.1.


ufw deny proto tcp from 2001:db8::/32 to any port 25

Esto denegará todo el tráfico de la red IPv6 2001:db8::/32 al puerto 25 de TCP en este host. IPv6 debe estar habilitado en /etc/default/ufw para que el cortafuegos IPv6 funcione.


ufw deny in on eth0 to 224.0.0.1 proto igmp

Esto denegará todo el tráfico igmp a 224.0.0.1 en la interfaz eth0.


ufw allow in on eth0 to 192.168.0.1 proto gre

ufw(8)

ufw — interface for controlling a network firewall

SYNOPSIS

ufw [enable|disable|restart|status]
ufw [delete|insert N|prepend] [rule|delay]
ufw [allow|deny|reject] [in|out] [on INTERFACE] [log|log-all]
[proto PROTOCOL] [from SRC] [to DST] [port PORT|app PROFILE]

DESCRIPTION

UFW stands for Uncomplicated Firewall. It is intended as an easy to use interface for a user or an administrator to manage a firewall. It uses command-line arguments and aims for an intuitive interface, and de-emphasizes the complexity of Debian's iptables(8) service. UFW is a tool for managing netfilter firewall rules.

The default operation mode for ufw is to deny all incoming connections and allow all outgoing connections.

The state of the firewall can be found by running:


ufw status

This will show whether the firewall is active and enabled, and any rules that have been added.

To enable the firewall, use:


ufw enable

This will enable the firewall and ensure that it is enabled across reboots. Note that enabling the firewall will start the firewall. Be sure to add any required rules before enabling the firewall.

To disable the firewall, use:


ufw disable

This will disable the firewall and ensure that it is disabled across reboots.

To restart the firewall, use:


ufw restart

To see a list of rules currently loaded into the firewall, use:


ufw status

This will show the firewall status and any rules that have been added. If the firewall is active, the rules are listed in the order they are processed.

For example, to allow all traffic to network interface `eth0`:


ufw allow eth0

To allow all incoming traffic on interface `eth0`:


ufw allow in on eth0

To allow all outgoing traffic on interface `eth0`:


ufw allow out on eth0

To deny all incoming traffic on interface `eth0`:


ufw deny in on eth0

To deny all outgoing traffic on interface `eth0`:


ufw deny out on eth0

To deny all traffic to port 80:


ufw deny 80

To allow all traffic to port 22 on interface `eth0`:


ufw allow in on eth0 to any port 22 proto tcp

To allow all traffic from RFC1918 private networks to this host:


ufw allow from 10.0.0.0/8
ufw allow from 172.16.0.0/12
ufw allow from 192.168.0.0/16

To allow GRE traffic to 192.168.0.1 on the eth0 interfaz.


ufw allow proto gre to 192.168.0.1 port 50
ufw allow proto gre from any to 192.168.0.1

Lo siguiente permitirá todo el tráfico a los puertos tcp 80, 443 y 8080-8090 inclusive y añade un comentario a la regla. Al especificar múltiples puertos, la lista de puertos debe ser numérica, no puede contener espacios y debe ser modificada en su totalidad. Por ejemplo, en el ejemplo anterior no se puede intentar eliminar solo el puerto '443'. No se pueden especificar más de 15 puertos (los rangos cuentan como 2 puertos, por lo que el recuento de puertos en el ejemplo anterior es 4).

ufw admite varios protocolos diferentes. Los siguientes son válidos en cualquier regla y se habilitan cuando no se especifica el protocolo:


tcp
udp

Los siguientes tienen ciertas restricciones y no se habilitan cuando no se especifica el protocolo:


ah válido sin número de puerto
esp válido sin número de puerto
gre válido sin número de puerto
vrrp válido sin número de puerto
ipv6 válido para direcciones IPv4 y sin número de puerto
igmp válido para direcciones IPv4 y sin número de puerto

Las reglas para el tráfico no destinado al propio host, sino al tráfico que debe ser enrutado/reenviado a través del firewall, deben especificar la palabra clave route antes de la regla (las reglas de enrutamiento difieren significativamente de la sintaxis de PF y en su lugar tienen en cuenta las convenciones de la cadena FORWARD de netfilter). Por ejemplo:


ufw route allow in on eth1 out on eth2

Esto permitirá que todo el tráfico enrutado a eth2 y que entra por eth1 atraviese el firewall.


ufw route allow in on eth0 out on eth1 to 12.34.45.67 port 80 proto tcp

Esta regla permite que cualquier paquete que entre por eth0 atraviese el firewall hacia el exterior por eth1 al puerto tcp 80 en 12.34.45.67.

Además de las reglas de enrutamiento y la política, también debe configurar el reenvío de IP. Esto se puede hacer configurando lo siguiente en /etc/ufw/sysctl.conf:


net/ipv4/ip_forward=1
net/ipv6/conf/default/forwarding=1
net/ipv6/conf/all/forwarding=1

y luego reiniciando el firewall:


ufw disable
ufw enable

Tenga en cuenta que la configuración de parámetros del kernel es específica del sistema operativo y los ajustes de sysctl de ufw pueden ser anulados. Consulte la página del manual de sysctl para obtener más detalles.

ufw admite la limitación de la tasa de conexiones, que es útil para protegerse contra ataques de fuerza bruta. Cuando se utiliza una regla de límite, ufw normalmente permitirá la conexión, pero denegará las conexiones si una dirección IP intenta iniciar 6 o más conexiones en 30 segundos. Consulte http://www.debian-administration.org/articles/187 para obtener más detalles. El uso típico es:


ufw limit ssh/tcp

A veces es deseable informar al remitente cuando se deniega el tráfico, en lugar de simplemente ignorarlo. En estos casos, utilice reject en lugar de deny. Por ejemplo:


ufw reject auth

Por defecto, ufw aplicará las reglas a todas las interfaces disponibles. Para limitarlo, especifique DIRECTION on INTERFACE, donde DIRECTION es uno de in u out (los alias de interfaz no están soportados). Por ejemplo, para permitir todas las nuevas conexiones entrantes de http en eth0, utilice:


ufw allow in on eth0 to any port 80 proto tcp

Para eliminar una regla, simplemente prefije la regla original con delete con o sin el comentario de la regla. Por ejemplo, si la regla original fue:


ufw deny 80/tcp

Utilice esto para eliminarla:


ufw delete deny 80/tcp

También puede especificar la regla por NUM, como se ve en la salida de status numbered. Por ejemplo, si desea eliminar la regla número '3', utilice:


ufw delete 3

Si tiene IPv6 habilitado y está eliminando una regla genérica que se aplica tanto a IPv4 como a IPv6 (ej. 'ufw allow 22/tcp'), la eliminación por número de regla solo eliminará la regla especificada. Para eliminar ambas con un solo comando, prefije la regla original con delete.

Para insertar una regla, especifique la nueva regla como de costumbre, pero prefije la regla con el número de regla a insertar. Por ejemplo, si tiene cuatro reglas y desea insertar una nueva regla como la regla número tres, utilice:


ufw insert 3 deny to any port 22 from 10.0.0.135 proto tcp

De manera similar, para agregar una regla antes que todas las demás reglas que coinciden con el tipo de IP de la regla, use la regla prepend:


ufw prepend deny from 1.2.3.4

Esto es particularmente útil para firewalls dinámicos como los que se encuentran en un IPS. Es importante destacar que si la regla especificada es una regla IPv4, se antepondrá a todas las demás reglas IPv4. Si es una regla IPv6, se antepondrá a cualquier regla IPv6.

Para ver una lista de reglas numeradas, utilice:


ufw status numbered

ufw admite el registro por regla. Por defecto, no se realiza ningún registro cuando un paquete coincide con una regla. Especificar log registrará todas las nuevas conexiones que coincidan con la regla, y log-all registrará todos los paquetes que coincidan con la regla. Por ejemplo, para permitir y registrar todas las nuevas conexiones ssh, utilice:


ufw allow log 22/tcp

Consulte LOGGING para obtener más información sobre el registro.

EJEMPLOS

Denegar todo acceso al puerto 53:


ufw deny 53

Permitir todo acceso al puerto tcp 80:


ufw allow 80/tcp

Permitir todo acceso desde redes RFC1918 a este host:


ufw allow from 10.0.0.0/8
ufw allow from 172.16.0.0/12
ufw allow from 192.168.0.0/16

Denegar acceso al puerto udp 514 desde el host 1.2.3.4:


ufw deny proto udp from 1.2.3.4 to any port 514

Permitir acceso a udp 1.2.3.4 puerto 5469 desde 1.2.3.5 puerto 5469:


ufw allow proto udp from 1.2.3.5 port 5469 to 1.2.3.4 port 5469

GESTIÓN REMOTA

Al ejecutar ufw enable o iniciar ufw a través de su script de inicio, ufw vaciará sus cadenas. Esto es necesario para que ufw pueda mantener un estado consistente, pero puede descartar conexiones existentes (por ejemplo, ssh). ufw admite la adición de reglas antes de habilitar el firewall, por lo que los administradores pueden hacer:


ufw allow proto tcp from any to any port 22

antes de ejecutar 'ufw enable'. Las reglas aún se vaciarán, pero el puerto ssh estará abierto después de habilitar el firewall. Tenga en cuenta que una vez que ufw esté 'habilitado', ufw no vaciará las cadenas al agregar o eliminar reglas (pero lo hará al modificar una regla o cambiar la política por defecto). Por defecto, ufw le pedirá confirmación al habilitar el firewall mientras se ejecuta a través de ssh. Esto se puede deshabilitar usando 'ufw --force enable'.

INTEGRACIÓN DE APLICACIONES

ufw admite la integración de aplicaciones leyendo perfiles ubicados en /etc/ufw/applications.d. Para enumerar los nombres de los perfiles de aplicación conocidos por ufw, utilice:


ufw app list

Los usuarios pueden especificar un nombre de aplicación al agregar una regla (entre comillas los nombres de perfil con espacios). Por ejemplo, al utilizar la sintaxis simple, los usuarios pueden usar:


ufw allow <name>

O para la sintaxis extendida:


ufw allow from 192.168.0.0/16 to any app <name>

No debe especificar el protocolo con ninguna de las sintaxis y, con la sintaxis extendida, utilice app en lugar de la cláusula port.

Los detalles sobre el perfil del firewall para una aplicación dada se pueden ver con:


ufw app info <name>

donde '<name>' es una de las aplicaciones vistas con el comando app list. Los usuarios también pueden especificar all para ver los perfiles de todas las aplicaciones conocidas.

La sintaxis para los perfiles de aplicación es un formato .INI simple:


[<name>]
title=<title>
description=<description>
ports=<ports>

El campo 'ports' puede especificar una lista de puertos/protocolos separada por '|', donde el protocolo es opcional. También se puede usar una lista separada por comas o un rango (especificado con 'start:end') para especificar varios puertos, en cuyo caso el protocolo es obligatorio. Por ejemplo:


[SomeService]
title=Some title
description=Some description
ports=12/udp|34|56,78:90/tcp

En el ejemplo anterior, 'SomeService' se puede usar en reglas de aplicación y especifica el puerto UDP 12, TCP y UDP en el puerto 34 y los puertos TCP 56 y 78-90 inclusive.

Después de crear o editar un perfil de aplicación, los usuarios pueden ejecutar:


ufw app update <name>

Este comando actualizará automáticamente el firewall con la información de perfil actualizada. Si especifica 'all' para el nombre, se actualizarán todos los perfiles. Para actualizar un perfil y agregar una nueva regla al firewall automáticamente, los usuarios pueden ejecutar:


ufw app update --add-new <name>

El comportamiento del comando update --add-new se puede configurar usando:


ufw app default <policy>

La política de aplicación por defecto es skip, lo que significa que el comando update --add-new no hará nada. Los usuarios también pueden especificar una política de allow o deny para que el comando update --add-new pueda actualizar automáticamente el firewall. **ADVERTENCIA:** puede ser un riesgo de seguridad utilizar una política allow por defecto para los perfiles de aplicación. Considere cuidadosamente las implicaciones de seguridad antes de usar una política predeterminada de allow.

REGISTRO

ufw admite varios niveles de registro. ufw tiene un nivel de registro predeterminado de 'low' cuando no se especifica un nivel de registro. Los usuarios pueden especificar un nivel de registro con:


ufw logging LEVEL

LEVEL puede ser 'off', 'low', 'medium', 'high' y 'full'. Los niveles de registro se definen como:

off
deshabilita el registro gestionado por ufw
low
registra todos los paquetes bloqueados que no coinciden con la política definida (con limitación de velocidad), así como los paquetes que coinciden con las reglas registradas
medium
nivel de registro bajo, más todos los paquetes permitidos que no coinciden con

LOGGING

Los siguientes niveles de registro están disponibles:

low
Registra todas las conexiones entrantes y salientes y todos los paquetes inválidos. Sin limitación de velocidad.
medium
Nivel de registro bajo, más todas las nuevas conexiones. Se registra toda la política definida, todos los paquetes INVÁLIDOS y todas las nuevas conexiones. Todo el registro se realiza con limitación de velocidad.
high
Nivel de registro medio (sin limitación de velocidad), más todos los paquetes con limitación de velocidad
full
Nivel de registro alto sin limitación de velocidad

Los niveles de registro superiores a medio generan una gran cantidad de salida de registro y pueden llenar rápidamente su disco. El nivel de registro medio puede generar una gran cantidad de salida de registro en un sistema ocupado.

Especificar 'on' simplemente habilita el registro en el nivel de registro 'low' si el registro no está habilitado actualmente.

INFORMES

Se admiten los siguientes informes. Cada uno se basa en el sistema en vivo y, a excepción del informe listening, está en formato raw iptables:


raw
builtins
before-rules
user-rules
after-rules
logging-rules
listening
added

El informe raw muestra el firewall completo, mientras que los otros muestran un subconjunto de lo que hay en el informe raw.

El informe listening mostrará los puertos en el sistema en vivo en estado de escucha para tcp y estado abierto para udp, junto con la dirección de la interfaz y el ejecutable que escucha en el puerto. Se utiliza un '*' en lugar de la dirección de la interfaz cuando el ejecutable está vinculado a todas las interfaces en ese puerto. A continuación de esta información, hay una lista de reglas que pueden afectar a las conexiones en este puerto. Las reglas se enumeran en el orden en que son evaluadas por el kernel, y la primera coincidencia gana. Tenga en cuenta que la política predeterminada no se enumera y tcp6 y udp6 se muestran solo si IPV6 está habilitado.

El informe added muestra la lista de reglas tal como se agregaron en la línea de comandos. Este informe no muestra el estado del firewall en ejecución (use 'ufw status' en su lugar). Debido a que ufw normaliza las reglas, las reglas pueden verse diferentes a la regla originalmente agregada. Además, ufw no registra el orden de los comandos, por lo que se utiliza un ordenamiento equivalente que enumera las reglas solo para IPv6 después de otras reglas.

NOTAS

Al instalarse, ufw está deshabilitado con una política predeterminada de denegación entrante, una política de reenvío predeterminada de denegación y una política de salida predeterminada de permitir, con seguimiento con estado para conexiones NUEVAS para conexiones entrantes y reenviadas. Además de lo anterior, se establece un conjunto de reglas predeterminado que hace lo siguiente:

- DROP paquetes con encabezados RH0
- DROP paquetes INVÁLIDOS
- ACCEPT ciertos paquetes icmp (INPUT y FORWARD): destination-unreachable, source-quench, time-exceeded, parameter-problem y echo-request para IPv4. destination-unreachable, packet-too-big, time-exceeded, parameter-problem y echo-request para IPv6.
- ACCEPT paquetes icmpv6 para autoconfiguración sin estado (INPUT)
- ACCEPT respuestas de ping de direcciones IPv6 de enlace local (ffe8::/10) (INPUT)
- ACCEPT tráfico de cliente DHCP (INPUT)
- DROP tráfico no local (INPUT)
- ACCEPT mDNS (zeroconf/bonjour/avahi 224.0.0.251 para IPv4 y ff02::fb para IPv6) para descubrimiento de servicios (INPUT)
- ACCEPT UPnP (239.255.255.250 para IPv4 y ff02::f para IPv6) para descubrimiento de servicios (INPUT)

El orden de las reglas es importante y la primera coincidencia gana. Por lo tanto, al agregar reglas, agregue primero las reglas más específicas con reglas más generales más tarde.

ufw no está diseñado para proporcionar funcionalidad completa de firewall a través de su interfaz de línea de comandos, sino que proporciona una forma sencilla de agregar o eliminar reglas simples.

El comando de estado muestra información básica sobre el estado del firewall, así como las reglas administradas a través del comando ufw. No muestra las reglas de los archivos de reglas en /etc/ufw. Para ver el estado completo del firewall, los usuarios pueden usar ufw show raw. Esto muestra las tablas filter, nat, mangle y raw usando:


iptables -n -L -v -x -t <table>
ip6tables -n -L -v -x -t <table>

Consulte la documentación de iptables e ip6tables para obtener más detalles.

Si la política predeterminada se establece en REJECT, ufw puede interferir con las reglas agregadas fuera del marco de ufw. Ver README para más detalles.

IPV6 está permitido por defecto. Para cambiar este comportamiento y solo aceptar tráfico IPv6 en la interfaz de loopback, establezca IPV6 en 'no' en /etc/default/ufw y recargue ufw. Cuando IPv6 está habilitado, puede especificar reglas de la misma manera que para las reglas IPv4, y se mostrarán con ufw status. Las reglas que coinciden con direcciones IPv4 e IPv6 se aplican a ambas versiones de IP. Por ejemplo, cuando IPv6 está habilitado, la siguiente regla permitirá el acceso al puerto 22 tanto para tráfico IPv4 como IPv6:


ufw allow 22

Los túneles IPv6 sobre IPv4 y 6to4 son compatibles utilizando el protocolo 'ipv6' ('41'). Este protocolo solo se puede utilizar con la sintaxis completa. Por ejemplo:


ufw allow to 10.0.0.1 proto ipv6
ufw allow to 10.0.0.1 from 10.4.0.0/16 proto ipv6

IPSec es compatible con el uso de los protocolos 'esp' ('50') y 'ah' ('51'). Estos protocolos solo se pueden utilizar con la sintaxis completa. Por ejemplo:


ufw allow to 10.0.0.1 proto esp
ufw allow to 10.0.0.1 from 10.4.0.0/16 proto esp
ufw allow to 10.0.0.1 proto ah
ufw allow to 10.0.0.1 from 10.4.0.0/16 proto ah

keepalived es compatible con el uso del protocolo 'vrrp' ('112'). Este protocolo solo se puede utilizar con la sintaxis completa. Por ejemplo:


ufw allow to 224.0.0.0/24 from 10.0.0.1 proto vrrp

Además de la interfaz de línea de comandos, ufw también proporciona un marco que permite a los administradores modificar el comportamiento predeterminado, así como aprovechar al máximo netfilter. Consulte la página del manual ufw-framework para obtener más información.
