UPSD(8) Manual de NUT UPSD(8)

NOMBRE

upsd - Servidor de datos de Network UPS Tools

SINOPSIS

upsd -h

upsd [OPCIONES]

DESCRIPCIÓN

upsd es responsable de servir los datos de los drivers a los clientes. Se conecta a cada driver y mantiene una caché local del estado actual. Las consultas de los clientes se atienden desde esta caché, por lo que los retrasos son mínimos.

También transmite mensajes administrativos de los clientes de vuelta a los drivers, como iniciar pruebas o establecer valores.

La comunicación entre upsd y los clientes se maneja en un puerto TCP. Los detalles de configuración para este puerto se describen en upsd.conf(5).

Este programa es esencial y debe ejecutarse en todo momento para aprovechar realmente los drivers y clientes (excepto los comandos finales de apagado de la UPS justo antes de que su servidor se apague, que los programas drivers de NUT pueden hacer solos cuando se les llama como nombre_driver -k en un hook de apagado o un script de inicio SysV de orden tardía).

Los controles en los archivos de configuración le permiten limitar el acceso al servidor, pero también debe usar un firewall para mayor protección. Los procesos cliente como upsmon(8) confían en upsd para obtener información de estado sobre el hardware de la UPS, así que manténgalo seguro.

OPCIONES

-c comando

Envía comando al proceso en segundo plano como una señal. Comandos válidos son:

reload

relee los archivos de configuración

stop

detiene el proceso y sale

-P pid

Envía la señal de comando anterior usando el número PID especificado, en lugar de consultar el archivo PID. Esto puede ayudar a definir unidades de servicio que inician upsd como un proceso en primer plano para que no cree un archivo PID. Ver también la opción -FF como alternativa.

-D

Aumenta el nivel de depuración. upsd se ejecutará en primer plano por defecto, e imprimirá información en stdout sobre el proceso de monitorización. Utilice esta opción varias veces para obtener más detalles.

-F

upsd se ejecutará en primer plano, independientemente de la configuración de depuración. Especifique dos veces (-FF o -F -F) para guardar el archivo PID incluso en este modo.

-B

upsd se ejecutará en segundo plano, independientemente de la configuración de depuración.

-h

Muestra el texto de ayuda.

-r directorio

upsd hará chroot(2) al directorio poco después de iniciarse y antes de analizar cualquier archivo de configuración con esta opción establecida. Puede usar esto para crear una "jaula" para mayor seguridad.

Debe coordinar esto con sus drivers, ya que upsd debe poder encontrar la ruta del estado dentro del directorio. Ver upsdrvctl(8) y nutupsdrv(8).

-u usuario

Cambia al usuario usuario después de iniciarse si se inició como root. Esto anula lo que sea que haya compilado con configure --with-user.

-V

Muestra la versión del programa.

RECARGA

upsd puede recargar sus archivos de configuración sin apagar el proceso si le envía una SIGHUP o lo inicia de nuevo con -c reload. Esto solo funciona si el proceso en segundo plano puede leer esos archivos (permisos, jaula chroot), y si el demonio guardó un archivo PID cuando se inició (para que el comando de recarga encuentre la instancia anterior).


Nota

Las instancias de servicio envueltas por systemd o SMF podrían no guardar esto por defecto (¡use las acciones de recarga/actualización respectivas del framework entonces!), por ejemplo, systemctl reload nut-server

Las versiones de NUT posteriores a 2.8.0 definen alias para estas unidades, por lo que si su distribución de Linux utiliza definiciones de unidad proporcionadas por NUT, systemctl reload upsd también podría funcionar.

Si cree que upsd no puede recargar, revise su syslog en busca de mensajes de error. Si se queja de no poder leer los archivos, necesita ajustar su sistema para que sea posible. Cambie los permisos de los archivos, o ejecute upsd como otro usuario que pueda leerlos, o reinícielo completamente (puede ser necesario, por ejemplo, si se ejecuta en una jaula chroot).

NO haga que sus archivos upsd.conf(5) o upsd.users(5) sean legibles por todos, ya que contienen información de autenticación importante. En las manos equivocadas, podría ser utilizada por alguna persona malintencionada para suplantar su upsmon de modo principal y ordenar el apagado de sus sistemas, por ejemplo.

DIAGNÓSTICO

upsd espera que los drivers actualicen su estado regularmente o al menos respondan a consultas periódicas, llamadas pings. Si un driver no responde, upsd lo declarará como "obsoleto" y no se proporcionará más información a los clientes.

Si upsd se queja de obsolescencia cuando lo inicia, entonces es probable que su driver o sus archivos de configuración estén rotos. Asegúrese de que el driver se está ejecutando realmente, y de que la definición de la UPS en ups.conf(5) es correcta. Asegúrese también de que inicia sus drivers antes de iniciar upsd.

Los datos también pueden marcarse como obsoletos si el driver ya no puede comunicarse con la UPS. En este caso, el driver también debería proporcionar información de diagnóstico en el syslog. Si esto ocurre, revise el cableado serial o USB, o inspeccione la ruta de red en el caso de una UPS SNMP.

CONTROL DE ACCESO

Si el servidor se compila con soporte para tcp-wrappers habilitado, comprobará si al usuario de NUT se le permite conectarse desde la dirección del cliente a través de los archivos /etc/hosts.allow y /etc/hosts.deny. Tenga en cuenta que esto solo se hará para los comandos que requieran iniciar sesión en el servidor. Se describen más detalles en hosts_access(5).

ARCHIVOS

El archivo de configuración general de upsd es upsd.conf(5).

Las funciones administrativas como SET e INSTCMD para usuarios, y varios roles de upsmon, se definen y controlan en upsd.users(5).

Las definiciones de UPS se encuentran en ups.conf(5) (compartido con los drivers actuales).

VARIABLES DE ENTORNO

NUT_DEBUG_LEVEL establece la verbosidad de depuración por defecto si no se proporcionaron argumentos -D en la línea de comandos, pero no solicita que el demonio se ejecute en modo primer plano.

NUT_CONFPATH es el nombre de ruta del directorio que contiene upsd.conf y otros archivos de configuración. Si esta variable no está establecida, upsd usa un valor predeterminado integrado, que a menudo es /usr/local/ups/etc.

NUT_STATEPATH es el nombre de ruta del directorio en el que upsd mantiene la información de estado. Si esta variable no está establecida, upsd usa un valor predeterminado integrado, que a menudo es /var/state/ups. La directiva STATEPATH en upsd.conf(5) anula esta variable.

NUT_ALTPIDPATH es el nombre de ruta del directorio en el que upsd y los drivers almacenan los archivos .pid. Si esta variable no está establecida, upsd y los drivers usan NUT_STATEPATH si está establecido, o ALTPIDPATH si está establecido, o de lo contrario, el valor predeterminado integrado STATEPATH.

NUT_QUIET_INIT_UPSNOTIFY=true puede usarse para evitar que los demonios que pueden notificar a los frameworks de gestión de servicios (como systemd) sobre el paso de sus hitos del ciclo de vida emitan dichas notificaciones (incluyendo las sobre la falta de soporte del sistema para dichas características modernas, una vez por ejecución).

NUT_QUIET_INIT_BANNER=true puede usarse para suprimir el banner con el nombre y la versión de la herramienta NUT. NO se recomienda para servicios debido al impacto adverso en la resolución de problemas, pero puede ser útil en perfiles de shell o scripts que procesan las salidas de las herramientas NUT.
