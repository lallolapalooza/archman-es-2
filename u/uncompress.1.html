COMPRESS(1) Manual de Comandos Generales COMPRESS(1)

NOMBRE

compress, uncompress, zcat - comprimir y descomprimir datos

SINOPSIS

compress [ -f ] [ -k ] [ -v ] [ -c ] [ -V ] [ -r ] [ -b bits ] [ -- ] [ nombre ... ]
uncompress [ -f ] [ -k ] [ -v ] [ -c ] [ -V ] [ -- ] [ nombre ... ]
zcat [ -V ] [ -- ] [ nombre ... ]

DESCRIPCIÓN

Compress reduce el tamaño de los archivos con nombre utilizando codificación adaptativa Lempel-Ziv. Siempre que sea posible, cada archivo se reemplaza por uno con la extensión .Z, manteniendo los mismos permisos de propietario, acceso y tiempos de modificación. Si no se especifican archivos, la entrada estándar se comprime a la salida estándar. Compress solo intentará comprimir archivos regulares. En particular, ignorará los enlaces simbólicos. Si un archivo tiene varios enlaces duros, compress se negará a comprimirlo a menos que se proporcione la opción -f.

Si no se proporciona -f y compress se ejecuta en primer plano, se le preguntará al usuario si se debe sobrescribir un archivo existente.

Los archivos comprimidos se pueden restaurar a su forma original utilizando uncompress o zcat.

uncompress toma una lista de archivos en su línea de comandos y reemplaza cada archivo cuyo nombre termina en .Z y que comienza con el número mágico correcto con un archivo descomprimido sin el .Z. El archivo descomprimido tendrá el modo, la propiedad y las marcas de tiempo del archivo comprimido.

La opción -k hace que compress/uncompress conserve los archivos de entrada en lugar de eliminarlos automáticamente.

La opción -c hace que compress/uncompress escriba en la salida estándar; no se modifican archivos.

zcat es idéntico a uncompress -c. zcat descomprime una lista de archivos en la línea de comandos o su entrada estándar y escribe los datos descomprimidos en la salida estándar. zcat descomprimirá archivos que tengan el número mágico correcto, tengan o no el sufijo .Z.

Si se especifica la opción -r, compress operará recursivamente. Si alguno de los nombres de archivo especificados en la línea de comandos son directorios, compress descenderá al directorio y comprimirá todos los archivos que encuentre allí. Al comprimir, se ignorarán los archivos ya comprimidos y al descomprimir, se ignorarán los archivos ya descomprimidos.

La opción -V indica a cada uno de estos programas que imprima su versión y nivel de parche, junto con cualquier indicador del preprocesador especificado durante la compilación, en stderr antes de realizar cualquier compresión o descompresión.

Compress utiliza el algoritmo Lempel-Ziv modificado popularizado en "A Technique for High Performance Data Compression", Terry A. Welch, IEEE Computer, vol. 17, no. 6 (junio de 1984), pp. 8-19. Las subcadenas comunes en el archivo se reemplazan primero por códigos de 9 bits 257 y superiores. Cuando se alcanza el código 512, el algoritmo cambia a códigos de 10 bits y continúa usando más bits hasta que se alcanza el límite especificado por la opción -b (por defecto 16). Bits debe estar entre 9 y 16. El valor predeterminado se puede cambiar en el código fuente para permitir que compress se ejecute en una máquina más pequeña.

Después de alcanzar el límite de bits, compress verifica periódicamente la relación de compresión. Si está aumentando, compress continúa utilizando el diccionario de códigos existente. Sin embargo, si la relación de compresión disminuye, compress descarta la tabla de subcadenas y la reconstruye desde cero. Esto permite que el algoritmo se adapte al siguiente "bloque" del archivo.

Tenga en cuenta que la opción -b se omite para uncompress, ya que el parámetro bits especificado durante la compresión está codificado dentro de la salida, junto con un número mágico para garantizar que no se intente descomprimir datos aleatorios ni recomprimir datos comprimidos.

La cantidad de compresión obtenida depende del tamaño de la entrada, el número de bits por código y la distribución de subcadenas comunes. Típicamente, el texto como código fuente o inglés se reduce entre un 50% y un 60%. La compresión es generalmente mucho mejor que la lograda por la codificación Huffman (como se usa en pack), o la codificación Huffman adaptativa (compact), y lleva menos tiempo de cómputo.

Con la opción -v, se imprime un mensaje que indica el porcentaje de reducción para cada archivo comprimido.

-- se puede usar para detener el análisis de opciones y forzar que todos los argumentos restantes se traten como rutas.

DIAGNÓSTICOS

El estado de salida normalmente es 0; si el último archivo es más grande después de la compresión (intentada), el estado es 2; si ocurre un error, el estado de salida es 1.

Uso: compress [-dfvcVr] [-b maxbits] [archivo ...]
Se especificaron opciones inválidas en la línea de comandos.
Falta maxbits
maxbits debe seguir a -b.
archivo: no está en formato comprimido
El archivo especificado para uncompress no ha sido comprimido.
archivo: comprimido con xx bits, solo puede manejar yy bits
Archivo fue comprimido por un programa que podía manejar más bits que el código compress en esta máquina. Recomprima el archivo con bits más pequeños.
archivo: ya tiene el sufijo .Z - sin cambios
Se asume que el archivo ya está comprimido. Renombre el archivo e intente de nuevo.
archivo: nombre de archivo demasiado largo para añadir .Z
El archivo no se puede comprimir porque su nombre es más largo de 12 caracteres. Renombre e intente de nuevo. Este mensaje no aparece en sistemas BSD.
archivo ya existe; ¿desea sobrescribir (s o n)?
Responda "s" si desea que el archivo de salida sea reemplazado; "n" si no.
uncompress: entrada corrupta
Se detectó una violación de SIGSEGV, lo que generalmente significa que el archivo de entrada ha sido corrompido.
Compresión: xx.xx%
Porcentaje del archivo de entrada ahorrado por la compresión. (Solo relevante para -v.)
-- no es un archivo regular ni un directorio: ignorado
Cuando el archivo de entrada no es un archivo regular ni un directorio (por ejemplo, un enlace simbólico, socket, FIFO, archivo de dispositivo), se deja inalterado.
-- tiene xx enlaces más: sin cambios
El archivo de entrada tiene enlaces; se deja sin cambios. Consulte ln(1) para más información. Utilice la opción -f para forzar la compresión de archivos con múltiples enlaces.
-- archivo sin cambios
No se logra ningún ahorro con la compresión. La entrada permanece virgen.

ERRORES

Aunque los archivos comprimidos son compatibles entre máquinas con gran memoria, se debe usar -b12 para la transferencia de archivos a arquitecturas con un pequeño espacio de datos de proceso (64KB o menos, como exhiben las series PDP de DEC, el Intel 80286, etc.)

    NAME

    uncompress - decompress files

    SYNOPSIS

    uncompress [-cfv] [-b bits] [-n] [-o outfile] [-O infile] [file ...]

    DESCRIPTION

    uncompress expands files that have been compressed by compress. The original file is uncompressed unless the -c option is used. If no file is specified, uncompress reads standard input.

    uncompress uses the LZW compression algorithm. This is a lossless data compression compression technique. It is patent-free and is widely used.

    OPTIONS

    -b bits
    Maximum number of bits used in codes (4 to 16, default is 16).
    -c
    Write output to standard output. Keep original file unchanged.
    -f
    Force compression or decompression. Overwrite existing files without prompting.
    -n
    Do not save the original file name and timestamp.
    -o outfile
    Write output to outfile. Implies -c.
    -O infile
    Read input from infile. This is equivalent to using shell redirection (e.g. uncompress < infile).
    -v
    Print the compression ratio for each file.

    DIAGNOSTICS

    uncompress reports the following error conditions:

    • uncompress: bad magic number: The file was not compressed by compress, or it is corrupted.
    • uncompress: unknown block type: Internal error.
    • uncompress: incomplete code: The compressed file is truncated or corrupted.
    • uncompress: file name too long: The original file name saved in the compressed file is longer than the system limit.
