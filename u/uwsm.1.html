UWSM(1) Manual de Comandos Generales UWSM(1)

NOMBRE

UWSM - Gestor Universal de Sesiones Wayland.

SINOPSIS

uwsm [-h|-v] {subcomando} [opciones ...]

DESCRIPCIÓN

Lanza un compositor Wayland arbitrario a través de un conjunto de unidades systemd de usuario para proporcionar una sesión gráfica con gestión del entorno, soporte de autoinicio XDG y apagado limpio. Proporciona utilidades para lanzar aplicaciones como ámbitos (scopes) o servicios.

SUBCOMANDOS

select Selecciona la Entrada del compositor por defecto.
start Inicia el compositor y la sesión gráfica.
finalize Envía las variables establecidas por el compositor y la notificación de inicio de unidad al gestor de usuario de systemd.
stop Detiene la sesión gráfica y el compositor.
app Lanzador de unidades de aplicación (con soporte de Entrada de Escritorio).
check Realiza comprobaciones de estado (para scripting e información).
aux Funciones técnicas para usar dentro de las unidades.

Consulta las subsecciones correspondientes de SUBCOMANDOS a continuación para obtener más información.

La ayuda para cada subcomando es accesible ejecutando "uwsm {subcomando} -h".

CONFIGURACIÓN

Archivos

En la jerarquía de configuración XDG:

uwsm/env
uwsm/env-${compositor} Entorno (shell) que se cargará para la sesión gráfica. Se carga desde directorios de prioridad creciente, dentro de cada directorio se carga primero el archivo común, luego los archivos con sufijo en el orden de los elementos listados en la variable XDG_CURRENT_SESSION (en minúsculas).
uwsm/default-id Almacena el ID de Entrada de Escritorio del compositor por defecto.

El fallback también se extiende a la parte del sistema de la jerarquía de datos XDG, esto puede usarse para valores por defecto a nivel de distribución.

Variables de entorno

UWSM_UNIT_RUNG (run|home)
Qué nivel de la jerarquía systemd/user/ gestionar los archivos de unidad y drop-in generados: $XDG_RUNTIME_DIR o $XDG_CONFIG_HOME.
UWSM_NO_TWEAKS (valor booleano)
Elimina y no genera drop-ins de ajustes para otro software.
UWSM_FINALIZE_VARNAMES (nombres de variables de entorno separados por espacios)
Variables adicionales para "uwsm finalize".
UWSM_WAIT_VARNAMES (nombres de variables de entorno separados por espacios)
Variables a esperar en el entorno de activación antes de proceder a la sesión gráfica (además de WAYLAND_DISPLAY).
UWSM_WAIT_VARNAMES_TIMEOUT (valor entero)
Segundos a esperar a que aparezcan las variables en el entorno de activación. Esencialmente, el tiempo de espera de inicio (por defecto: 10).
UWSM_WAIT_VARNAMES_SETTLETIME (valor flotante)
Segundos a pausar después de que todas las variables esperadas sean encontradas en el entorno de activación (por defecto: 0.2).
UWSM_APP_UNIT_TYPE (scope|service)
Tipo de unidad por defecto para lanzar aplicaciones (por defecto: scope).
UWSM_SILENT_START (valor entero o booleano)
True o 1 para inhibir mensajes de salida estándar de uwsm start. 2 para inhibir también advertencias.
DEBUG (valor entero o booleano)
True o un número positivo para volcar información de depuración a stderr.

RESUMEN DE OPERACIÓN

Integración Secuencial de Inicio

uwsm puede ser lanzado usando un exec condicional en el perfil del shell para reemplazar el shell de inicio de sesión (ver sección Integración de Perfil de Shell).

Alternativamente, el comando "uwsm start ..." puede ser puesto en una Entrada de Escritorio de sesión Wayland para ser lanzada por un gestor de pantalla (ver sección Uso Dentro de una Entrada de Escritorio).

Selección del Compositor

uwsm puede ejecutar una línea de comandos de compositor arbitraria o una Entrada de Escritorio por ID (también se soporta la especificación de ID de Acción).

La Entrada de Escritorio también puede ser seleccionada a través de un menú whiptail (ver sección del subcomando select).

Inicio

Ver la sección del subcomando start para la sintaxis del comando.

UWSM utiliza un conjunto de unidades enlazadas a destinos de sesión de usuario estándar:

•
wayland-session-pre@.target (enlazado a graphical-session-pre.target)
•
wayland-wm-env@.service (servicio de precarga de entorno)
•
wayland-session@.target (enlazado a graphical-session.target)
•
wayland-wm@.service (servicio para el compositor seleccionado)
  • wayland-session-xdg-autostart@.target (enlazado a xdg-desktop-autostart.target)
  • wayland-session-shutdown.target (entra en conflicto con los destinos anteriores para el apagado)
  • wayland-session-bindpid@.service (killswitch de sesión para rastreo de PID)
  • wayland-session-waitenv.service (retraso de la sesión gráfica hasta que aparezcan las variables)

El ID del compositor (ID de Entrada de Escritorio o nombre del ejecutable) se convierte en el especificador para todas las unidades de plantilla.

En la etapa de graphical-session-pre.target, se carga el entorno guardado del contexto de "uwsm start" (o se carga el perfil del shell POSIX), se cargan los archivos de entorno de uwsm. La diferencia se exporta a los entornos de activación de systemd y D-Bus mediante el servicio de precarga de entorno y se marca para su limpieza en la etapa de apagado. El contexto de shell del precargador, para conveniencia, tiene la variable IN_UWSM_ENV_PRELOADER establecida en true.

En la etapa de graphical-session.target (antes de ella), se inician las unidades principales del compositor wayland-wm@${ID}.service y wayland-session-waitenv.service.

El compositor debe al menos colocar la variable WAYLAND_DISPLAY en el entorno de activación de systemd. Esto activará la lógica de finalización automática de uwsm. Sin WAYLAND_DISPLAY en el entorno de activación, el inicio caducará en 10 segundos.

La finalización manual es posible ejecutando "uwsm finalize" (ver sección del subcomando finalize), también en combinación con el ajuste de las variables UWSM_WAIT_VARNAMES y UWSM_WAIT_VARNAMES_SETTLETIME (ver sección Variables de entorno).

La activación exitosa de la unidad del compositor y la existencia de WAYLAND_DISPLAY en el entorno de activación permitirán que se declare alcanzado graphical-session.target.

Finalmente, se activa xdg-desktop-autostart.target.

Dentro de la sesión

Se recomienda encarecidamente configurar el compositor o el lanzador de aplicaciones para que lancen aplicaciones como ámbitos o servicios en trozos (slices) especiales de la sesión de usuario (app.slice, background.slice, session.slice). uwsm proporciona trozos anidados personalizados para que las aplicaciones residan y sean terminadas al final de la sesión:

  • app-graphical.slice
  • background-graphical.slice
  • session-graphical.slice

DAEMON DE APLICACIÓN

Se proporciona como wayland-wm-app-daemon.service para ser iniciado bajo demanda.

El daemon recibe los argumentos de la aplicación desde la tubería ${XDG_RUNTIME_DIR}/uwsm-app-daemon-in. Los argumentos resultantes se formatean como código de shell y se escriben en la tubería ${XDG_RUNTIME_DIR}/uwsm-app-daemon-out.

Se espera que los argumentos estén delimitados por \0, se eliminan los \0 iniciales. Se recibe un comando por cada escritura+cierre.

El primer argumento determina el comportamiento:

  • app: el resto se procesa igual que en "uwsm app".
  • ping: solo se devuelve "pong".
  • stop: el daemon se detiene.

Los comandos individuales se anteponen con exec, los comandos iterados se ensamblan con un & al final de cada uno, seguido de wait.

El propósito de todo esto es omitir todas las rutinas costosas de inicio e importación de Python que ralentizan las cosas cada vez que se llama a "uwsm app". En su lugar, el daemon lo hace una vez y luego espera las solicitudes, mientras que un script de shell simple puede volcar los argumentos en una tubería y ejecutar el código recibido de otra a través de `eval`, lo que es mucho más rápido.

El script más simple es:

#!/bin/sh
printf '0%s' app "$@" > "${XDG_RUNTIME_DIR}/uwsm-app-daemon-in"
IFS='' read -r cmd < "${XDG_RUNTIME_DIR}/uwsm-app-daemon-out"
eval "$cmd"

El script cliente uwsm-app proporcionado es un poco más inteligente: puede iniciar el daemon, aplica tiempos de espera y admite saltos de línea en los argumentos devueltos.

INTEGRACIÓN DEL PERFIL DE SHELL

Para iniciar uwsm automáticamente al iniciar sesión, agregue una de las construcciones a continuación (o similar) al perfil de shell.

Esto pide seleccionar un compositor (o rechazar y continuar con el shell de inicio de sesión) al iniciar sesión en la VT 1:

if uwsm may-start && uwsm select; then
	exec systemd-cat -t uwsm_start uwsm start default
fi

Esto simplemente inicia un compositor específico dependiendo de la VT activa:

if uwsm may-start 1; then
	exec systemd-cat -t uwsm_start uwsm start sway.desktop
elif uwsm may-start 2; then
	exec systemd-cat -t uwsm_start uwsm start labwc.desktop
fi

Usar "uwsm check may-start" como condición es esencial, no solo para prevenir intentos de inicio accidentales donde no se esperan, sino también porque el inicio puede implicar cargar el perfil del shell, lo que podría llevar a bucles molestos.

Consulte la sección del subcomando check para obtener información sobre el verificador may-start.

exec permite que uwsm reemplace el shell de inicio de sesión para enlazarse correctamente a la sesión del usuario y manejar la terminación de la sesión.

"systemd-cat -t uwsm_start" (opcional) ejecuta el comando que se le da (uwsm) con su salida estándar y error estándar conectados al registro de systemd, etiquetados con el identificador "uwsm_start". Consulte systemd-cat(1) para más opciones.

USO DENTRO DE UNA ENTRADA DE ESCRITORIO

Para iniciar uwsm desde un gestor de pantalla/inicio de sesión, se puede usar "uwsm start" dentro de las Entradas de Escritorio. Ejemplo /usr/local/share/wayland-sessions/my-compositor.desktop:

[Desktop Entry]
Name=Mi compositor (con UWSM)
Comment=Mi compositor genial
Exec=uwsm start -N "Mi compositor" -D mycompositor -C "Mi compositor genial" mywm
DesktopNames=mycompositor
Type=Application

Aspectos a tener en cuenta:

  • Para consistencia, los argumentos de la línea de comandos deben reflejar las claves de la entrada.
  • El comando en Exec= debe comenzar con "uwsm start".
  • No debe apuntar a sí mismo (como una combinación del ID de la Entrada de Escritorio y el ID de Acción).
  • No debe apuntar a un ID de Entrada de Escritorio y un ID de Acción que también utilicen `uwsm`.

Potencialmente, tales entradas pueden ser encontradas y utilizadas por uwsm, es decir, en una situación de integración de perfil de shell, o cuando se lanzan manualmente. Seguir los principios anteriores asegura que uwsm se reconocerá correctamente a sí mismo y analizará los argumentos solicitados dentro de la entrada sin efectos secundarios.
