DESCRIPCIÓN

Unbound es una implementación de un resolvedor DNS, que realiza caché y validación DNSSEC. Esta es la API de la biblioteca, para usar la biblioteca -lunbound. El demonio del servidor se describe en unbound(8). La biblioteca funciona independientemente de un servidor unbound en ejecución y puede usarse para convertir nombres de host en direcciones IP y viceversa, y obtener otra información del DNS. La biblioteca realiza la validación de clave pública de los resultados con DNSSEC.

La biblioteca utiliza una variable de tipo struct ub_ctx para mantener el contexto entre llamadas. El usuario debe mantenerla, creándola con ub_ctx_create y eliminándola con ub_ctx_delete. Puede crearse y eliminarse en cualquier momento. Crear una nueva elimina cualquier configuración previa (como claves de confianza) y borra cualquier resultado en caché.

Las funciones son seguras para hilos, y un contexto puede usarse en un entorno con hilos (así como en uno sin hilos). Además, la resolución (y validación) puede realizarse de forma bloqueante y no bloqueante (también llamada asíncrona). El método asíncrono devuelve el control de la llamada inmediatamente, para que el procesamiento pueda continuar, mientras que los resultados estarán disponibles más tarde.

Las funciones se discuten a continuación, una por una.

FUNCIONES

ub_ctx_create
Crea un nuevo contexto, inicializado con valores predeterminados. La información de /etc/resolv.conf y /etc/hosts no se utiliza por defecto. Usa ub_ctx_resolvconf y ub_ctx_hosts para leerlos. Antes de llamar a esta función, usa las funciones de openssl CRYPTO_set_id_callback y CRYPTO_set_locking_callback para configurar la operación asíncrona si usas la biblioteca openssl (la aplicación llama a estas funciones una vez para la inicialización). Openssl 1.0.0 o posterior usa la función CRYPTO_THREADID_set_callback.
ub_ctx_delete
Elimina el contexto de validación y libera los recursos asociados. Las consultas asíncronas pendientes se cancelan y las devoluciones de llamada no se llaman para ellas.
ub_ctx_set_option
Una interfaz para usuarios avanzados que permite especificar una de las opciones del formato del archivo de configuración, ver unbound.conf(5). No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclajes de confianza, existen rutinas especiales. Pasa el nombre de la opción con los dos puntos finales ':'.
ub_ctx_get_option
Una interfaz para usuarios avanzados que obtiene el valor de una opción. Algunas opciones no se pueden obtener, y otras devuelven una lista separada por saltos de línea. Pasa el nombre de la opción sin los dos puntos finales ':'. El valor devuelto debe ser liberado con free(2) por el llamador.
ub_ctx_config
Una interfaz para usuarios avanzados que permite especificar un archivo de configuración de unbound, ver unbound.conf(5), que se lee para la configuración. No todas las opciones son relevantes. Para algunas opciones específicas, como agregar anclajes de confianza, existen rutinas especiales. Esta función solo es segura para hilos si existe una única instancia de ub_ctx* en la aplicación. Si existen varias instancias, la aplicación debe asegurarse de que ub_ctx_config no se llame en paralelo por las diferentes instancias.
ub_ctx_set_fwd
Establece la máquina a la que se reenviarán las consultas DNS, el resolvedor de caché a utilizar. Dirección IP4 o IP6. Reenvía todas las solicitudes DNS a esa máquina, que se espera que ejecute un resolvedor recursivo. Si el proxy no es compatible con DNSSEC, la validación puede fallar. Se puede llamar varias veces, en cuyo caso las direcciones se utilizan como servidores de respaldo. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_stub
Establece una zona stub, servidores DNS autorizados a usar para una zona particular. Dirección IP4 o IP6. Si la dirección es NULL, se elimina la entrada stub. Establezca isprime en verdadero si configura sugerencias raíz con ella. De lo contrario, es similar al elemento de zona stub del archivo de configuración de unbound. Se puede llamar varias veces, para diferentes zonas, o para agregar múltiples direcciones para una zona particular. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_set_tls
Habilita DNS sobre TLS (DoT) para las máquinas configuradas con ub_ctx_set_fwd. En este momento, solo es posible establecer la configuración antes de que se realice la primera resolución.
ub_ctx_resolvconf
Por defecto, se consultan los servidores raíz y se utiliza el modo de resolución completa, pero puedes usar esta llamada para leer la lista de servidores de nombres a usar desde el nombre de archivo dado. Normalmente "/etc/resolv.conf". Utiliza esos servidores de nombres como proxies de caché. Si no soportan DNSSEC, la validación puede fallar. Solo se recogen los servidores de nombres, se ignoran el dominio de búsqueda (searchdomain), ndots y otras configuraciones de resolv.conf(5). Si se pasa NULL como fname, se usa "/etc/resolv.conf" (si estás en Windows, se selecciona el servidor de nombres configurado a nivel de sistema en su lugar). En este momento, solo es posible establecer la configuración antes de la primera resolución.
ub_ctx_hosts
Lee la lista de hosts del nombre de archivo dado. Normalmente "/etc/hosts". Cuando se consulta, estas direcciones no se marcan como seguras DNSSEC. Si se pasa NULL como fname, se usa "/etc/hosts" (si estás en Windows, se selecciona etc/hosts del WINDIR en su lugar). En este momento, solo es posible establecer la configuración antes de la primera resolución.
ub_ctx_add_ta
Agrega un anclaje de confianza (trust anchor) para validación DNSSEC. El anclaje de confianza se proporciona en el formato de cadena de texto específico de Unbound. Para una descripción de los formatos ver unbound.conf(5). Solo se pueden agregar anclajes de confianza antes de que se realice la primera consulta.
ub_ctx_add_ta_autr
Agrega anclajes de confianza para validación DNSSEC desde el nombre de archivo especificado. El archivo contiene anclajes de confianza en formato ATMA (RFC4034, sección 6.2). Para una descripción de los formatos ver unbound.conf(5). Solo se pueden agregar anclajes de confianza antes de que se realice la primera consulta.
ub_ctx_add_ta_file
Agrega anclajes de confianza para validación DNSSEC desde el nombre de archivo especificado. El archivo contiene anclajes de confianza en formato de cadena de texto específico de Unbound. Para una descripción de los formatos ver unbound.conf(5). Solo se pueden agregar anclajes de confianza antes de que se realice la primera consulta.
ub_ctx_trustedkeys
Lee anclajes de confianza desde el nombre de archivo dado. Normalmente "~/.unbound/root.key". Es una forma de leer el contenido de archivo trusted-keys del archivo de configuración de Unbound. Para una descripción de los formatos ver unbound.conf(5). Solo se pueden leer los anclajes de confianza antes de que se realice la primera consulta.
ub_ctx_debugout
Establece el flujo de salida de depuración. Por defecto es stderr. Poner NULL detiene la impresión.
ub_ctx_debuglevel
Establece el nivel de depuración. 0 para deshabilitar, 1 para solo errores, 2 para advertencias, 3 para información, 4 para estado detallado y 5 para mensajes de depuración verbosos.
ub_ctx_async
Establece si se deben usar hilos para la resolución. Si dothread es 1, se usan hilos. Si dothread es 0, se usa el bucle de eventos. El valor predeterminado es 1 (usar hilos). Si se usan hilos, entonces las llamadas de interfaz de usuario deben ser únicas por hilo.
ub_poll
Espera a que un descriptor de archivo esté listo para leerse o escribirse, o que expiren eventos pendientes. Devuelve el descriptor de archivo listo, o 0 si no hay ninguno listo pero hay eventos pendientes, o -1 si no hay ningún descriptor de archivo listo y ningún evento pendiente. Llamar a ub_poll() es una operación que debe usarse para obtener un descriptor de archivo que esté listo para ser procesado por ub_process() o para procesar eventos de temporizador.
ub_wait
Espera a que todos los eventos pendientes expiren. Devuelve 0 si todos los eventos han expirado. Devuelve -1 si se produce un error. Si un descriptor de archivo está listo, entonces no se espera hasta que se llame a ub_process().
ub_fd
Devuelve el descriptor de archivo principal para que se pueda usar con select(2) o poll(2). El usuario debe llamar a ub_process() si el descriptor de archivo está listo para leerse o escribirse.
ub_process
Procesa los datos del descriptor de archivo devuelto por ub_fd() o procesa los eventos pendientes. Las consultas asíncronas que se completan se notifican aquí.
ub_resolve
Resuelve un nombre de host de forma bloqueante. El resultado se almacena en el puntero de resultado. El puntero de resultado debe ser liberado con ub_resolve_free().
ub_resolve_async
Resuelve un nombre de host de forma no bloqueante (asíncrona). La llamada devuelve inmediatamente y la devolución de llamada se invoca cuando los resultados están listos. El identificador asíncrono se almacena en el puntero async_id. El usuario debe proporcionar un puntero a una función de devolución de llamada que coincida con ub_callback_type.
ub_cancel
Cancela una consulta asíncrona iniciada por ub_resolve_async() con el id dado.
ub_resolve_free
Libera la memoria asignada para el resultado de la consulta.
ub_strerror
Devuelve una cadena que describe el código de error dado.
ub_ctx_print_local_zones
Imprime todas las zonas locales configuradas en la salida estándar. Devuelve 0 en caso de éxito, -1 en caso de error.
ub_ctx_zone_add
Agrega una zona local al contexto. zone_name es el nombre de la zona (por ejemplo, "example.com.") y zone_type es el tipo de zona (por ejemplo, "PRIMARY" o "STEALTH"). Devuelve 0 en caso de éxito, -1 en caso de error.
ub_ctx_zone_remove
Elimina una zona local del contexto. zone_name es el nombre de la zona (por ejemplo, "example.com."). Devuelve 0 en caso de éxito, -1 en caso de error.
ub_ctx_data_add
Agrega datos de zona local al contexto. Los datos deben estar en el formato de archivo de zona estándar de BIND. Devuelve 0 en caso de éxito, -1 en caso de error.
ub_ctx_data_remove
Elimina datos de zona local del contexto. Los datos deben estar en el formato de archivo de zona estándar de BIND. Devuelve 0 en caso de éxito, -1 en caso de error.

NAME

libunbound - - Unbound async DNS resolver library

SYNOPSIS

#include <unbound.h>

DESCRIPTION

The libunbound library provides functions to perform DNS lookups and DNSSEC validation using the Unbound resolver. It is designed to be used by applications that need to perform DNS lookups. The library is asynchronous, meaning that lookups are non-blocking. This allows applications to perform other tasks while waiting for DNS query results.

The main components of the library are contexts, which hold configuration and state, and functions to perform lookups and process results. A context is created with ub_ctx_create and configured with various functions. Lookups can be performed synchronously with ub_resolve or asynchronously with ub_resolve_async. Results are processed using ub_poll, ub_wait, and ub_process.

The library supports DNSSEC validation, and can be configured with trust anchors to enable this. It also supports features like local zone data and name server configuration.

FUNCTIONS

ub_ctx_create
Create a new Unbound context. A context is needed for all operations. Returns a pointer to the context or NULL on error.
ub_ctx_destroy
Destroy the Unbound context and free all associated resources. This should be called when done with the context.
ub_ctx_config
Load configuration from a file. This is typically used to load the main Unbound configuration file. If the file is NULL, default settings are used.
ub_ctx_resolvconf
Load system resolver configuration (like from /etc/resolv.conf). This is used to configure the upstream name servers. If the file is NULL, the system's default resolv.conf is used.
ub_ctx_add_addr
Add a specific name server address to the context. This allows manually specifying upstream servers. The format is an IP address string. This can only be done before the first resolve is done.
ub_ctx_add_hoststr
Add a hostname to the context and resolve it to an IP address to use as a name server. This can only be done before the first resolve is done.
ub_ctx_add_ta
Add a trust anchor to the given context. At this time it is only possible to add trusted keys before the first resolve is done. The format is a string, similar to the zone-file format, [domainname] [type] [rdata contents]. Both DS and DNSKEY records are accepted.
ub_ctx_add_ta_autr
Add filename with automatically tracked trust anchor to the given context. Pass name of a file with the managed trust anchor. You can create this file with unbound-anchor(8) for the root anchor. You can also create it with an initial file with one line with a DNSKEY or DS record. If the file is writable, it is updated when the trust anchor changes. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_add_ta_file
Add trust anchors to the given context. Pass name of a file with DS and DNSKEY records in zone file format. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_trustedkeys
Add trust anchors to the given context. Pass the name of a bind-style config file with trusted-keys{}. At this time it is only possible to add trusted keys before the first resolve is done.
ub_ctx_debugout
Set debug and error log output to the given stream. Pass NULL to disable output. Default is stderr. File-names or using syslog can be enabled using config options, this routine is for using your own stream.
ub_ctx_debuglevel
Set debug verbosity for the context. Output is directed to stderr. Higher debug level gives more output.
ub_ctx_async
Set a context behaviour for asynchronous action. if set to true, enables threading and a call to ub_resolve_async creates a thread to handle work in the background. If false, a process is forked to handle work in the background. Changes to this setting after ub_resolve_async calls have been made have no effect (delete and re-create the context to change).
ub_poll
Poll a context to see if it has any new results. Do not poll in a loop, instead extract the fd below to poll for readiness, and then check, or wait using the wait routine. Returns 0 if nothing to read, or nonzero if a result is available. If nonzero, call ub_process to do callbacks.
ub_wait
Wait for a context to finish with results. Calls ub_process after the wait for you. After the wait, there are no more outstanding asynchronous queries.
ub_fd
Get file descriptor. Wait for it to become readable, at this point answers are returned from the asynchronous validating resolver. Then call the ub_process to continue processing.
ub_process
Call this routine to continue processing results from the validating resolver (when the fd becomes readable). Will perform necessary callbacks.
ub_resolve
Perform resolution and validation of the target name. The name is a domain name in a zero terminated text string. The rrtype and rrclass are DNS type and class codes. The result structure is newly allocated with the resulting data.
ub_resolve_async
Perform asynchronous resolution and validation of the target name. Arguments mean the same as for ub_resolve except no data is returned immediately, instead a callback is called later. The callback receives a copy of the mydata pointer, that you can use to pass information to the callback. The callback type is a function pointer to a function declared as:
void my_callback_function(void* my_arg, int err,
                struct ub_result* result);

The async_id is returned so you can (at your option) decide to track it and cancel the request if needed. If you pass a NULL pointer the async_id is not returned.

ub_cancel
Cancel an async query in progress. This may return an error if the query does not exist, or the query is already being delivered, in that case you may still get a callback for the query.
ub_resolve_free
Free struct ub_result contents after use.
ub_strerror
Convert error value from one of the unbound library functions to a human readable string.
ub_ctx_print_local_zones
Debug printout the local authority information to debug output.
ub_ctx_zone_add
Add new zone to local authority info, like local-zone unbound.conf(5) statement.
ub_ctx_zone_remove
Delete zone from local authority info.
ub_ctx_data_add
Add resource record data to local authority info, like local-data unbound.conf(5) statement.
ub_ctx_data_remove
Delete local authority data from the name given.

RESULT DATA STRUCTURE

The result of the DNS resolution and validation is returned as struct ub_result. The result structure contains the following entries:

struct ub_result {
     char* qname;         /* text string, original question */
     int qtype;           /* type code asked for */
     int qclass;          /* class code asked for */
     char** data;         /* array of rdata items, NULL terminated*/
     int* len;            /* array with lengths of rdata items */
     char* canonname;     /* canonical name of result */
     int rcode;           /* additional error code in case of no data */
     void* answer_packet; /* full network format answer packet */
     int answer_len;      /* length of packet in octets */
     int havedata;        /* true if there is data */
     int nxdomain;        /* true if nodata because name does not exist */
     int secure;          /* true if result is secure */
     int bogus;           /* true if a security failure happened */
     char* why_bogus;     /* string with error if bogus */
     int was_ratelimited; /* true if the query was ratelimited (SERVFAIL) by unbound */
     int ttl;             /* number of seconds the result is valid */
};

If both secure and bogus are false, security was not enabled for the domain of the query. Else, they are not both true, one of them is true.

RETURN VALUES

Many routines return an error code. The value 0 (zero) denotes no error happened. Other values can be passed to ub_strerror to obtain a readable error string. ub_strerror returns a zero terminated string. ub_ctx_create returns NULL on an error (a malloc failure). ub_poll returns true if some information may be available, false otherwise. ub_fd returns a file descriptor or -1 on error. ub_ctx_config and ub_ctx_resolvconf attempt to leave errno informative on a function return with file read failure.
