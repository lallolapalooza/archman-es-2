NOMBRE

urxvtc - controla el demonio urxvtd

SINOPSIS

urxvtc [mismas opciones que para urxvt]

DESCRIPCIÓN

Esta página del manual describe el programa cliente urxvtc. Se conecta al demonio urxvtd y solicita una nueva ventana de terminal. Toma los mismos argumentos que el programa urxvt. El entorno también será respetado. Actualmente, siempre regresa inmediatamente después de contactar al demonio.

OPCIONES

Si la primera opción es -k, urxvtc intenta matar el proceso demonio y regresa.

Todas las opciones válidas para urxvt también son válidas para urxvtc. Tenga en cuenta que las opciones se interpretan en el contexto del proceso demonio. Sin embargo, dado que el directorio de trabajo actual, el entorno del proceso y cualquier descriptor de archivo (por ejemplo, para "-pty-fd") se conservan, esto rara vez hace una diferencia.

ESTADO DE SALIDA

Si todo salió bien, urxvtc regresa con un estado de salida de 0. Si contactar al demonio falla, sale con el estado de salida 2. En todos los demás casos de error, regresa con el estado 1.

Esto se puede utilizar para implementar un comportamiento de inicio automático, comprobando un estado de salida de 2, ejecutando "urxvtd -f -q" y reintentando la llamada a urxvtc, de la siguiente manera:

#!/bin/sh
urxvtc "$@"
if [ $? -eq 2 ]; then
   urxvtd -q -o -f
   urxvtc "$@"
fi

ENTORNO

Todas las variables de entorno del proceso actual estarán disponibles para la nueva instancia y se interpretarán como si urxvt se hubiera iniciado directamente.

RXVT_SOCKET
Tanto urxvtc como urxvtd utilizan la variable de entorno RXVT_SOCKET para crear un socket de escucha y para contactar a urxvtd, respectivamente. Si la variable falta, se utiliza $HOME/.urxvt/urxvtd-<nodename>. La variable debe especificar la ruta absoluta del socket a crear.
