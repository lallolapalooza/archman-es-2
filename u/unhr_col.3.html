subroutine cunhr_col (integer m, integer n, integer nb, complex, dimension( lda, * ) a, integer lda, complex, dimension( ldt, * ) t, integer ldt, complex, dimension( * ) d, integer info)

CUNHR_COL

Purpose:

!>
!>  CUNHR_COL takes an M-by-N complex matrix Q_in with orthonormal columns
!>  as input, stored in A, and performs Householder Reconstruction (HR),
!>  i.e. reconstructs Householder vectors V(i) implicitly representing
!>  another M-by-N matrix Q_out, with the property that Q_in = Q_out*S,
!>  where S is an N-by-N diagonal matrix with diagonal entries
!>  equal to +1 or -1. The Householder vectors (columns V(i) of V) are
!>  stored in A on output, and the diagonal entries of S are stored in D.
!>  Block reflectors are also returned in T
!>  (same output format as CGEQRT).
!>

Parameters

M 
!>          M is INTEGER
!>          The number of rows of the matrix A. M >= 0.
!>

N

!>          N is INTEGER
!>          The number of columns of the matrix A. M >= N >= 0.
!>

NB

!>          NB is INTEGER
!>          The column block size to be used in the reconstruction
!>          of Householder column vector blocks in the array A and
!>          corresponding block reflectors in the array T. NB >= 1.
!>          (Note that if NB > N, then N is used instead of NB
!>          as the column block size.)
!>

A

!>          A is COMPLEX array, dimension (LDA,N)
!>
!>          On entry:
!>
!>             The array A contains an M-by-N orthonormal matrix Q_in,
!>             i.e the columns of A are orthogonal unit vectors.
!>
!>          On exit:
!>
!>             The elements below the diagonal of A represent the unit
!>             lower-trapezoidal matrix V of Householder column vectors
!>             V(i). The unit diagonal entries of V are not stored
!>             (same format as the output below the diagonal in A from
!>             CGEQRT). The matrix T and the matrix V stored on output
!>             in A implicitly define Q_out.
!>
!>             The elements above the diagonal contain the factor U
!>             of the  LU-decomposition:
!>                Q_in - ( S ) = V * U
!>                       ( 0 )
!>             where 0 is a (M-N)-by-(M-N) zero matrix.
!>

LDA

!>          LDA is INTEGER
!>          The leading dimension of the array A.  LDA >= max(1,M).
!>

T

!>          T is COMPLEX array,
!>          dimension (LDT, N)
!>
!>          Let NOCB = Number_of_output_col_blocks
!>                   = CEIL(N/NB)
!>
!>          On exit, T(1:NB, 1:N) contains NOCB upper-triangular
!>          block reflectors used to define Q_out stored in compact
!>          form as a sequence of upper-triangular NB-by-NB column
!>          blocks (same format as the output T in CGEQRT).
!>          The matrix T and the matrix V stored on output in A
!>          implicitly define Q_out. NOTE: The lower triangles
!>          below the upper-triangular blocks will be filled with
!>          zeros. See Further Details.
!>

LDT

!>          LDT is INTEGER
!>          The leading dimension of the array T.
!>          LDT >= max(1,min(NB,N)).
!>

D

!>          D is COMPLEX array, dimension min(M,N).
!>          The elements can be only plus or minus one.
!>
!>          D(i) is constructed as D(i) = -SIGN(Q_in_i(i,i)), where
!>          1 <= i <= min(M,N), and Q_in_i is Q_in after performing
!>          i-1 steps of “modified” Gaussian elimination.
!>          See Further Details.
!>

INFO

!>          INFO is INTEGER
!>          = 0:  successful exit
!>          < 0:  if INFO = -i, the i-th argument had an illegal value
!>

Further Details:

!>
!> The computed M-by-M unitary factor Q_out is defined implicitly as
!> a product of unitary matrices Q_out(i). Each Q_out(i) is stored in
!> the compact WY-representation format in the corresponding blocks of
!> matrices V (stored in A) and T.
!>
!> The M-by-N unit lower-trapezoidal matrix V stored in the M-by-N
!> matrix A contains the column vectors V(i) in NB-size column
!> blocks VB(j). For example, VB(1) contains the columns
!> V(1), V(2), ... V(NB). NOTE: The unit entries on
!> the diagonal of Y are not stored in A.
!>
!> The number of column blocks is
!>
!>     NOCB = Number_of_output_col_blocks = CEIL(N/NB)
!>
!> where each block is of order NB except for the last block, which
!> is of order LAST_NB = N - (NOCB-1)*NB.
!>
!> For example, if M=6,  N=5 and NB=2, the matrix V is
!>
!>
!>     V = (    VB(1),   VB(2), VB(3) ) =
!>
!>       = (   1                      )
!>         ( v21    1                 )
!>         ( v31  v32    1            )
!>         ( v41  v42  v43   1        )
!>         ( v51  v52  v53  v54    1  )
!>         ( v61  v62  v63  v54   v65 )
!>
!>
!> For each of the column blocks VB(i), an upper-triangular block
!> reflector TB(i) is computed. These blocks are stored as
!> a sequence of upper-triangular column blocks in the NB-by-N
!> matrix T. The size of each TB(i) block is NB-by-NB, except
!> for the last block, whose size is LAST_NB-by-LAST_NB.
!>
!> For example, if M=6,  N=5 and NB=2, the matrix T is
!>
!>     T  = (    TB(1),    TB(2), TB(3) ) =
!>
!>        = ( t11  t12  t13  t14   t15  )
!>          (      t22       t24        )
!>
!>
!> The M-by-M factor Q_out is given as a product of NOCB
!> unitary M-by-M matrices Q_out(i).
!>
!>     Q_out = Q_out(1) * Q_out(2) * ... * Q_out(NOCB),
!>
!> where each matrix Q_out(i) is given by the WY-representation
!> using corresponding blocks from the matrices V and T:
!>
!>     Q_out(i) = I - VB(i) * TB(i) * (VB(i))**T,
!>
!> where I is the identity matrix. Here is the formula with matrix
!> dimensions:
!>
!>  Q(i){M-by-M} = I{M-by-M} -
!>    VB(i){M-by-INB} * TB(i){INB-by-INB} * (VB(i))**T {INB-by-M},
!>
!> where INB = NB, except for the last block NOCB
!> for which INB=LAST_NB.
!>
!> =====
!> NOTE:
!> =====
!>
!> If Q_in is the result of doing a QR factorization
!> B = Q_in * R_in, then:
!>
!> B = (Q_out*S) * R_in = Q_out * (S * R_in) = Q_out * R_out.
!>
!> So if one wants to interpret Q_out as the result
!!> of the QR factorization of B, then the corresponding R_out
!> should be equal to R_out = S * R_in, i.e. some rows of R_in
!> should be multiplied by -1.
!>
!> For the details of the algorithm, see [1].
!>
!> [1] ,
!>     G. Ballard, J. Demmel, L. Grigori, M. Jacquelin, H.D. Nguyen,
!>     E. Solomonik, J. Parallel Distrib. Comput.,
!>     vol. 85, pp. 3-31, 2015.
!>

Description

DORHR_COL takes an M-by-N real matrix Q_in with orthonormal columns as input, stored in A, and performs Householder Reconstruction (HR), i.e. reconstructs Householder vectors V(i) implicitly representing another M-by-N matrix Q_out, with the property that Q_in = Q_out*S, where S is an N-by-N diagonal matrix with diagonal entries equal to +1 or -1. The Householder vectors (columns V(i) of V) are stored in A on output, and the diagonal entries of S are stored in D. Block reflectors are also returned in T (same output format as DGEQRT).

SORHR_COL is a single-precision version of DORHR_COL.

FURTHER DETAILS

The computed M-by-M orthogonal factor Q_out is defined implicitly as a product of orthogonal matrices Q_out(i). Each Q_out(i) is stored in the compact WY-representation format in the corresponding blocks of matrices V (stored in A) and T.

The M-by-N unit lower-trapezoidal matrix V stored in the M-by-N matrix A contains the column vectors V(i) in NB-size column blocks VB(j). For example, VB(1) contains the columns V(1), V(2), ... V(NB). NOTE: The unit entries on the diagonal of Y are not stored in A.

The number of column blocks is

     NOCB = Number_of_output_col_blocks = CEIL(N/NB)

where each block is of order NB except for the last block, which is of order LAST_NB = N - (NOCB-1)*NB.

For example, if M=6, N=5 and NB=2, the matrix V is

     V = (    VB(1),   VB(2), VB(3) ) =
       = (   1
         ( v21    1
         ( v31  v32    1
         ( v41  v42  v43   1
         ( v51  v52  v53  v54    1
         ( v61  v62  v63  v54   v65 )

For each of the column blocks VB(i), an upper-triangular block reflector TB(i) is computed. These blocks are stored as a sequence of upper-triangular column blocks in the NB-by-N matrix T. The size of each TB(i) block is NB-by-NB, except for the last block, whose size is LAST_NB-by-LAST_NB.

For example, if M=6, N=5 and NB=2, the matrix T is

     T  = (    TB(1),    TB(2), TB(3) ) =
        = ( t11  t12  t13  t14   t15
          (      t22       t24        )

The M-by-M factor Q_out is given as a product of NOCB orthogonal M-by-M matrices Q_out(i).

     Q_out = Q_out(1) * Q_out(2) * ... * Q_out(NOCB),

where each matrix Q_out(i) is given by the WY-representation using corresponding blocks from the matrices V and T:

     Q_out(i) = I - VB(i) * TB(i) * (VB(i))**T,

where I is the identity matrix. Here is the formula with matrix dimensions:

  Q(i){M-by-M} = I{M-by-M} -
    VB(i){M-by-INB} * TB(i){INB-by-INB} * (VB(i))**T {INB-by-M},

where INB = NB, except for the last block NOCB for which INB=LAST_NB.

===== NOTE: =====

If Q_in is the result of doing a QR factorization B = Q_in * R_in, then:

B = (Q_out*S) * R_in = Q_out * (S * R_in) = Q_out * R_out.

So if one wants to interpret Q_out as the result of the QR factorization of B, then the corresponding R_out should be equal to R_out = S * R_in, i.e. some rows of R_in should be multiplied by -1.

For the details of the algorithm, see [1].

!>             La matriz A contiene una matriz ortonormal M-por-N Q_in,
!>             es decir, las columnas de A son vectores unitarios ortogonales.
!>
!>          En la salida:
!>
!>             Los elementos debajo de la diagonal de A representan la matriz
!>             unitaria inferior trapezoidal V de los vectores de columna de Householder
!>             V(i). Las entradas unitarias de la diagonal de V no se almacenan
!>             (mismo formato que la salida debajo de la diagonal en A de
!>             CGEQRT). La matriz T y la matriz V almacenadas en la salida
!>             en A definen implícitamente Q_out.
!>
!>             Los elementos por encima de la diagonal contienen el factor U
!>             de la descomposición LU:
!>                Q_in - ( S ) = V * U
!>                       ( 0 )
!>             donde 0 es una matriz cero (M-N)-por-(M-N).

LDA

!>          LDA es INTEGER
!>          La dimensión principal de la matriz A. LDA >= max(1,M).

T

!>          T es una matriz COMPLEX,
!>          dimensión (LDT, N)
!>
!>          Sea NOCB = Número_de_bloques_de_salida_de_columnas
!>                   = CEIL(N/NB)
!>
!>          En la salida, T(1:NB, 1:N) contiene NOCB reflectores de bloque
!>          triangulares superiores utilizados para definir Q_out almacenados
!>          en forma compacta como una secuencia de bloques de columna
!>          triangulares superiores NB-por-NB (mismo formato que la salida T en CGEQRT).
!>          La matriz T y la matriz V almacenadas en la salida en A
!>          definen implícitamente Q_out. NOTA: Los triángulos inferiores
!>          debajo de los bloques triangulares superiores se rellenarán con
!>          ceros. Ver Detalles Adicionales.

LDT

!>          LDT es INTEGER
!>          La dimensión principal de la matriz T.
!>          LDT >= max(1,min(NB,N)).

D

!>          D es una matriz REAL, dimensión min(M,N).
!>          Los elementos solo pueden ser más o menos uno.
!>
!>          D(i) se construye como D(i) = -SIGN(Q_in_i(i,i)), donde
!>          1 <= i <= min(M,N), y Q_in_i es Q_in después de realizar
!>          i-1 pasos de eliminación Gaussiana "modificada".
!>          Ver Detalles Adicionales.

INFO

!>          INFO es INTEGER
!>          = 0:  salida exitosa
!>          < 0:  si INFO = -i, el i-ésimo argumento tenía un valor ilegal

Detalles Adicionales:

!>
!> El factor unitario M-por-M calculado Q_out se define implícitamente como
!> un producto de matrices unitarias Q_out(i). Cada Q_out(i) se almacena en
!> el formato de representación WY compacta en los bloques correspondientes de
!> las matrices V (almacenada en A) y T.
!>
!> La matriz unitaria inferior trapezoidal M-por-N V almacenada en la matriz
!> M-por-N A contiene los vectores de columna V(i) en bloques de columna de tamaño NB
!> VB(j). Por ejemplo, VB(1) contiene las columnas
!> V(1), V(2), ... V(NB). NOTA: Las entradas unitarias en
!> la diagonal de Y no se almacenan en A.
!>
!> El número de bloques de columna es
!>
!>     NOCB = Número_de_bloques_de_salida_de_columnas = CEIL(N/NB)
!>
!> donde cada bloque es de orden NB excepto el último bloque, que
!> es de orden LAST_NB = N - (NOCB-1)*NB.
!>
!> Por ejemplo, si M=6, N=5 y NB=2, la matriz V es
!>
!>
!>     V = (    VB(1),   VB(2), VB(3) ) =
!>
!>       = (   1                      )
!>         ( v21    1                 )
!>         ( v31  v32    1            )
!>         ( v41  v42  v43   1        )
!>         ( v51  v52  v53  v54    1  )
!>         ( v61  v62  v63  v54   v65 )
!>
!>
!> Para cada uno de los bloques de columna VB(i), se calcula un bloque
!> reflector triangular superior TB(i). Estos bloques se almacenan como
!> una secuencia de bloques de columna triangulares superiores en la matriz
!> NB-por-N T. El tamaño de cada bloque TB(i) es NB-por-NB, excepto
!> para el último bloque, cuyo tamaño es LAST_NB-por-LAST_NB.
!>
!> Por ejemplo, si M=6, N=5 y NB=2, la matriz T es
!>
!>     T  = (    TB(1),    TB(2), TB(3) ) =
!>
!>        = ( t11  t12  t13  t14   t15  )
!>          (      t22       t24        )
!>
!>
!> El factor Q_out M-por-M se da como un producto de NOCB
!> matrices unitarias M-por-M Q_out(i).
!>
!>     Q_out = Q_out(1) * Q_out(2) * ... * Q_out(NOCB),
!>
!> donde cada matriz Q_out(i) se da mediante la representación WY
!> utilizando los bloques correspondientes de las matrices V y T:
!>
!>     Q_out(i) = I - VB(i) * TB(i) * (VB(i))**T,
!>
!> donde I es la matriz identidad. Aquí está la fórmula con dimensiones de matriz:
!>
!>  Q(i){M-por-M} = I{M-por-M} -
!>    VB(i){M-por-INB} * TB(i){INB-por-INB} * (VB(i))**T {INB-por-M},
!>
!> donde INB = NB, excepto para el último bloque NOCB
!> para el cual INB=LAST_NB.
!>
!> =====
!> NOTA:
!> =====
!>
!> Si Q_in es el resultado de hacer una factorización QR
!> B = Q_in * R_in, entonces:
!>
!> B = (Q_out*S) * R_in = Q_out * (S * R_in) = Q_out * R_out.
!>
!> Por lo tanto, si se quiere interpretar Q_out como el resultado
!> de la factorización QR de B, entonces el R_out correspondiente
!> debe ser igual a R_out = S * R_in, es decir, algunas filas de R_in
!> deben multiplicarse por -1.
!>
!> Para los detalles del algoritmo, ver [1].
!>
!> [1] ,
!>     G. Ballard, J. Demmel, L. Grigori, M. Jacquelin, H.D. Nguyen,
!>     E. Solomonik, J. Parallel Distrib. Comput.,
!>     vol. 85, pp. 3-31, 2015.

Detailed Description

La subroutine unhr_col modifica los argumentos de entrada para que la matriz de salida Q coincida con el resultado de la factorización QR.

El propósito de esta rutina es permitir que las factorizaciones QR de diferentes bibliotecas se comparen entre sí. Si, por ejemplo, se ha calculado una factorización QR de una matriz B como

!> B = Q_in * R_in, then:
!>
!> B = (Q_out*S) * R_in = Q_out * (S * R_in) = Q_out * R_out.
!>
!> So if one wants to interpret Q_out as the result
!> of the QR factorization of B, then the corresponding R_out
!> should be equal to R_out = S * R_in, i.e. some rows of R_in
!> should be multiplied by -1.
!>
!> For the details of the algorithm, see [1].
!>
!> [1] ,
!>     G. Ballard, J. Demmel, L. Grigori, M. Jacquelin, H.D. Nguyen,
!>     E. Solomonik, J. Parallel Distrib. Comput.,
!>     vol. 85, pp. 3-31, 2015.
!>
