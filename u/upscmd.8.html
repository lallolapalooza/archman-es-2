UPSCMD(8) Manual NUT UPSCMD(8)

NOMBRE

upscmd - Herramienta de administración de comandos instantáneos del dispositivo/driver de Network UPS Tools

SINOPSIS

upscmd -h

upscmd -l ups

upscmd [-u usuario] [-p contraseña] [-w] [-t <tiempo_espera>] ups comando

DESCRIPCIÓN

upscmd te permite invocar "comandos instantáneos" en tu hardware de UPS. Envía comandos a través del servidor upsd(8) a tu driver, el cual administra el hardware por ti. Debes usar credenciales definidas en el archivo upsd.users(5) en ese servidor de datos con permisos apropiados.

No todo el hardware soporta esto, así que revisa la lista con -l para ver si algo funcionará en tu equipo.

En hardware que lo soporta, puedes usar este programa para iniciar y detener pruebas de batería, invocar una prueba del panel frontal (¡pitido!), encender o apagar la carga, y más.

OPCIONES

-l ups

Muestra la lista de comandos instantáneos soportados en esa UPS. Algunos hardwares pueden no soportar ninguno.

-u usuario

Establece el nombre de usuario para la conexión al servidor. Esto es opcional, y se te pedirá al invocar un comando si no se usa -u.

-p contraseña

Establece la contraseña para autenticarse en el servidor. Esto también es opcional como -u, y se te pedirá si es necesario.

-w

Espera a que el driver complete la ejecución del comando y devuelve su resultado real del dispositivo. Ten en cuenta que esta característica requiere que tanto upsd(8) como el driver soporten TRACKING (NUT versión 2.8.0 o superior), de lo contrario fallará.

El comando también se bloqueará hasta que se proporcione un resultado real del driver, o se alcance el tiempo de espera (ver -t).

-t segundos

Establece un tiempo de espera al usar -w. Por defecto es 10 segundos.

ups

Conéctate a esta UPS. El formato es nombre_ups[@hostname[:puerto]]. El hostname por defecto es "localhost".

OPCIONES COMUNES

-h

Muestra el mensaje de ayuda de la línea de comandos.

-V

Muestra el banner de la versión de NUT. Pueden estar disponibles más detalles si también exportas NUT_DEBUG_LEVEL=1 o un nivel de verbosidad mayor.

-W seg

Establece el tiempo de espera para las conexiones de red iniciales (por defecto son indefinidamente no bloqueantes, o hasta que el sistema interrumpa el intento). Anula la variable de entorno opcional NUT_DEFAULT_CONNECT_TIMEOUT.

MODO DESATENDIDO

Si ejecutas este programa dentro de un script de shell o similar para invocar un comando, necesitarás especificar toda la información en la línea de comandos. Esto significa usar -u y -p. De lo contrario, mostrará un prompt y tu programa se colgará.

Esto no es necesario al mostrar la lista, ya que el nombre de usuario y la contraseña no son necesarios para el modo de solo lectura.

Además, si ejecutas este programa dentro de un script de shell o similar, solo deberías considerar usar la salida estándar (stdout), no la salida de error (stderr).

COMANDOS PELIGROSOS

Algunos drivers como apcsmart(8) tienen una "paranoia" incorporada para los comandos peligrosos como load.off. Para que realmente apaguen la carga, tendrás que enviar el comando dos veces en un corto período de tiempo. Es decir, tendrás que enviarlo una vez, y luego enviarlo de nuevo después de que transcurran 3 segundos pero antes de que pasen 15 segundos.

Esta paranoia está definida completamente dentro del driver. upsd y upscmd no tienen control sobre la temporización.

DIAGNÓSTICOS

upscmd no funcionará a menos que proporciones un nombre de usuario y una contraseña válidos. Si obtienes errores de "acceso denegado", asegúrate de que tu upsd.users(5) tenga una entrada para ti, y que el nombre de usuario que estás usando tenga permisos para ESTABLECER variables.

upscmd sin -w mostraría, de forma algo confusa, "OK" significando solo que la conexión con el servidor de datos se estableció, y que el servidor no rechazó inmediatamente la solicitud debido, por ejemplo, a un nombre de comando instantáneo desconocido. Si te interesa conocer los resultados reales, usa la opción (-w (-t NUM)) para esperar por ellos.

ERRORES

Actualmente no hay forma de indicar al usuario cuándo el driver requiere confirmación para invocar un comando como load.off.

Esto está en la lista de cosas a corregir en el futuro, así que no desesperes. Implica "cookies" mágicas.
