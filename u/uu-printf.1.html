uudoc(1) Manual de Comandos Generales uudoc(1)

NOMBRE

uudoc - Imprime la salida basándose en la cadena de formato y los argumentos que le siguen.

SINOPSIS

uudoc [--ayuda] [--versión] [FORMATO] [ARGUMENTO]

DESCRIPCIÓN

Imprime la salida basándose en la cadena de formato y los argumentos que le siguen.

OPCIONES

--ayuda
Imprime información de ayuda
--versión
Imprime información de la versión
[FORMATO]
[ARGUMENTO]

EXTRA

plantillas anónimas básicas de cadenas:

imprime la cadena de formato al menos una vez, repitiendo mientras queden argumentos. La salida imprime literales escapados en la cadena de formato como literales de caracteres. La salida reemplaza los campos anónimos con el siguiente argumento no utilizado, formateado según el campo.

Imprime la cadena de formato, reemplazando secuencias de caracteres escapados con literales de caracteres y secuencias de sustitución con los argumentos pasados.

literalmente, con la excepción de las secuencias de caracteres escapados a continuación, y las secuencias de sustitución descritas más adelante.

### SECUENCIAS DE ESCAPE

Las siguientes secuencias de escape, organizadas aquí en orden alfabético, imprimirán el literal de carácter correspondiente:

- " comillas dobles

- \\ barra invertida

- \\a alerta (BEL)

- \\b retroceso

- \\c Fin-de-Entrada

- \\e escape

- \\f salto de página

- \\n nueva línea

- \\r retorno de carro

- \\t tabulación horizontal

- \\v tabulación vertical

- \\NNN byte con valor expresado en valor octal NNN (1 a 3 dígitos)
los valores mayores que 256 serán tratados

- \\xHH byte con valor expresado en valor hexadecimal NN (1 a 2 dígitos)

- \\uHHHH carácter Unicode (IEC 10646) con valor expresado en valor hexadecimal HHHH (4 dígitos)

- \\uHHHH carácter Unicode con valor expresado en valor hexadecimal HHHH (8 dígitos)

- %% un solo %

### SUSTITUCIONES

#### REFERENCIA RÁPIDA DE SUSTITUCIÓN

Campos

- %s: cadena - %b: cadena analizada para literales, el segundo parámetro es la longitud máxima

- %c: carácter, sin segundo parámetro

- %i o %d: entero de 64 bits - %u: entero sin signo de 64 bits - %x o %X: entero sin signo de 64 bits en hexadecimal - %o: entero sin signo de 64 bits en octal
el segundo parámetro es el ancho mínimo, entero.
la salida por debajo de ese ancho se rellena con ceros a la izquierda

- %q: El ARGUMENTO se imprime en un formato que se puede reutilizar como entrada del shell, escapando caracteres no imprimibles
con la sintaxis $'' propuesta por POSIX.

- %f o %F: valor de punto flotante decimal - %e o %E: valor de punto flotante en notación científica - %g o %G: el menor de los valores de punto flotante decimal o científico interpretados especialmente.
el segundo parámetro es
- el número máximo de lugares después del punto decimal para la salida de punto flotante
- el número máximo de dígitos significativos para la salida en notación científica

parametrización de campos

ejemplos:

printf '%4.3i' 7

Tiene un primer parámetro de 4 y un segundo parámetro de 3, y resultará en ' 007'

printf '%.1s' abcde

No tiene primer parámetro y tiene un segundo parámetro de 1, y resultará en 'a'

printf '%4c' q

Tiene un primer parámetro de 4 y ningún segundo parámetro, y resultará en ' q'

El primer parámetro de un campo es el ancho mínimo para rellenar la salida si la salida es menor que el valor absoluto de este ancho, se rellenará con espacios a la izquierda, o, si el argumento es negativo, con espacios a la derecha. El valor predeterminado es cero.

El segundo parámetro de un campo es particular del tipo de campo de salida. Los valores predeterminados se pueden encontrar en la ayuda completa de sustitución a continuación.

prefijos especiales para argumentos numéricos

- 0: (por ejemplo, 010) interpreta el argumento como octal (solo campos de salida de enteros) - 0x: (por ejemplo, 0xABC) interpreta el argumento como hexadecimal (solo campos de salida numéricos) - \': (por ejemplo, \'a) interpreta el argumento como una constante de carácter

#### CÓMO USAR SUSTITUCIONES

Las sustituciones se utilizan para pasar argumentos adicionales a la cadena de FORMATO, para que se formateen de una manera particular. Por ejemplo:

printf 'la letra %X viene antes que la letra %X' 10 11

imprimirá

la letra A viene antes que la letra B

porque el campo de sustitución %X significa 'tomar un argumento entero y escribirlo como un número hexadecimal'.

Pasar más argumentos de los que hay en la cadena de formato hará que la cadena de formato se repita para las sustituciones restantes.

printf 'son las %i en %s \n' 22 Portland 25 Boston 27 New York

imprimirá

son las 22 en Portland son las 25 en Boston son las 27 en Boston

Si se imprime una cadena de formato pero quedan menos argumentos de los que hay campos de sustitución, los campos de sustitución sin argumento tendrán como valor predeterminado cadenas vacías, o para campos numéricos el valor 0.

#### SUSTITUCIONES DISPONIBLES

Este programa, al igual que printf de GNU coreutils, interpreta un subconjunto modificado del printf de POSIX C. A continuación se presenta una referencia rápida de las sustituciones.

#### SUSTITUCIONES DE CADENA

Todos los campos de cadena tienen un parámetro de 'ancho máximo'. %.3s significa 'no imprimir más de tres caracteres de la entrada original'.

- %s: cadena

- %b: cadena con escape - la cadena se comprobará para ver si hay literales escapados de la lista de literales escapados anterior, y se traducirán a caracteres literales. Por ejemplo, \\n se transformará en un carácter de nueva línea. Una regla especial sobre el modo %b es que los literales octales se interpretan de forma diferente. En los argumentos pasados por %b, los literales interpretados como octales deben tener la forma de \\0NNN en lugar de \\NNN. (Aunque, por razones de compatibilidad, los literales octales con la forma \\NNN seguirán interpretándose y no generarán una advertencia, tendrá problemas si utiliza esto para un literal cuyo código comience con cero, ya que se considerará en formato \\0NNN).

- %q: cadena con escape - la cadena en un formato que se puede reutilizar como entrada para la mayoría de los shells. Los caracteres no imprimibles se escapan con la sintaxis de $'' propuesta por POSIX, y los metacaracteres del shell se entrecomillan adecuadamente. Este es un formato equivalente a la salida de ls --quoting=shell-escape.

#### SUSTITUCIONES DE CARACTERES

El campo de carácter no tiene parámetro secundario.

- %c: un solo carácter

#### SUSTITUCIONES DE ENTEROS

Todos los campos de enteros tienen un parámetro de 'relleno con cero'. %.4i significa un entero que, si tiene menos de 4 dígitos de longitud, se rellena con ceros a la izquierda hasta que tenga 4 dígitos de longitud.

- %d o %i: entero de 64 bits

- %u: entero sin signo de 64 bits

- %x o %X: entero sin signo de 64 bits impreso en hexadecimal (base 16). %X en lugar de %x significa usar letras mayúsculas para 'a' a 'f'.

- %o: entero sin signo de 64 bits impreso en octal (base 8)

#### SUSTITUCIONES DE PUNTO FLOTANTE

Todos los campos de punto flotante tienen un parámetro de 'número máximo de decimales / número máximo de dígitos significativos'. %.10f significa un punto flotante decimal con 7 lugares decimales después de 0. %.10e significa un número en notación científica con 10 dígitos significativos. %.10g significa el mismo comportamiento para decimal y científico, respectivamente, y proporciona la salida más corta de cada uno.

Al igual que con GNU coreutils, el valor después del punto decimal en estas salidas se analiza primero como un double antes de renderizarse a texto. Para ambas implementaciones, no espere una precisión significativa más allá del 18º lugar decimal. Al usar un número de lugares decimales de 18 o más, puede esperar variaciones en la salida entre printf de GNU coreutils y este printf en el 18º lugar decimal de +/- 1.

- %f: valor de punto flotante presentado en decimal, truncado y mostrado a 6 lugares decimales por defecto. No hay paridad de comportamiento post-double con Coreutils printf; los valores no se estiman ni se ajustan más allá de los valores de entrada.

- %e o %E: valor de punto flotante presentado en notación científica.
7 dígitos significativos por defecto.

DESCRIPTION

Print strings according to a format specification. The format specification is a character string containing any combination of literal characters and conversion specifications. Literal characters are copied to the output. Conversion specifications begin with a '%' character, followed by characters that specify the interpretation of the associated arguments. The arguments are converted and output according to the specification.

The conversion specifications are composed of the following parts, in the order presented here:

    [FLAG] [WIDTH] [.PRECISION] [MODIF] CONV

FLAG:

'-' The argument is left-justified in the field.

A field wider than the output is padded with spaces. By default, the padding is on the left with leading spaces. If the '-' flag is used, the padding is on the right with trailing spaces.

WIDTH:

A nonnegative decimal integer that specifies a minimum field width. If the output contains fewer characters than this width, the field is padded with spaces to the specified width. If the value is 0, the field is left unfilled.

PRECISION:

A nonnegative decimal integer, preceded by a dot ("."), that specifies the maximum number of characters to be written from a string, or the maximum number of digits to appear after the decimal point for floating- point values.

MODIF:

This utility does not support any modifiers.

CONV:

A character that indicates the type of conversion to be applied.

The following are the supported conversions:

- %a or %A: Floating-point hexadecimal representation (e.g., -0x1.23abcp+10)
%A uses uppercase letters for hexadecimal digits and the exponent indicator
%a uses lowercase letters for hexadecimal digits and the exponent indicator

- %b: Interprets arguments as a string and outputs the value.
Backslash-escape sequences are interpreted.
The backslash-escape sequences supported are:
\a: alert (bell)
\b: backspace
\e: escape character
\f: form-feed
\n: newline
\r: carriage return
\t: horizontal tab
\v: vertical tab
\\: backslash
\0: null character
\NNN: interpreted as an octal number

- %c: The argument is converted to an unsigned char and written.

- %d or %i: Signed decimal conversion. Displays the integer argument as a base-10 integer.
%d and %i are synonymous.

- %e or %E: Floating-point decimal format.
The general form of this format is:
[-]d.dddd e[+-]DD
%e uses a lowercase 'e' to introduce the exponent.
%E uses an uppercase 'E' to introduce the exponent.

- %f: Floating-point decimal format.
The general form of this format is:
[-]ddd.dddd

- %g or %G: Use the shorter of %e (%E for %G) and %f.
Precision specifies the number of significant digits to be printed.
%G uses uppercase letters for the exponent indicator.

- %o: Signed octal conversion. Displays the integer argument as an octal integer (base 8). If the argument is negative, zero, or positive, a minus sign, zero, or plus sign respectively is placed before the conversion. A leading zero is inserted for positive arguments.

- %s: Characters are read from the string argument and written to the output until an ending null character is encountered or the number of characters indicated by the precision specification is reached. If the argument is shorter than the precision, nothing is written past the end of the argument. If the precision is not specified, all characters in the argument are written.

- %u: Signed decimal conversion. Displays the integer argument as a base-10 integer. If the argument is negative, zero, or positive, a minus sign, zero, or plus sign respectively is placed before the conversion.

- %x or %X: Signed hexadecimal conversion. Displays the integer argument as a hexadecimal integer.
%x uses lowercase letters for hex digits.
%X uses uppercase letters for hex digits.

- %%: A '%' character is written.

- %%: A literal '%' character is printed.

This utility follows the behavior of GNU coreutils' printf from an inputs and outputs standpoint.

### USING PARAMETERS

Most substitution fields can be parameterized using up to 2 numbers that can be passed to the field, between the % sign and the field letter.

The 1st parameter always indicates the minimum width of output, it is useful for creating columnar output. Any output that would be less than this minimum width is padded with leading spaces The 2nd parameter is proceeded by a dot. You do not have to use parameters

### SPECIAL FORMS OF INPUT

For numeric input, the following additional forms of input are accepted besides decimal:

Octal (only with integer): if the argument begins with a 0 the proceeding characters will be interpreted as octal (base 8) for integer fields

Hexadecimal: if the argument begins with 0x the proceeding characters will be interpreted will be interpreted as hex (base 16) for any numeric fields for float fields, hexadecimal input results in a precision limit (in converting input past the decimal point) of 10^-15

Character Constant: if the argument begins with a single quote character, the first byte of the next character will be interpreted as an 8-bit unsigned integer. If there are additional bytes, they will throw an error (unless the environment variable POSIXLY_CORRECT is set)

- %g or %G: floating point value presented in the shortest of decimal and scientific notation
behaves differently from %f and %E, please see posix printf spec for full details,
some examples of different behavior:
Sci Note has 6 significant digits by default
Trailing zeroes are removed
Instead of being truncated, digit after last is rounded

Like other behavior in this utility, the design choices of floating point behavior in this utility is selected to reproduce in exact the behavior of GNU coreutils' printf from an inputs and outputs standpoint.
