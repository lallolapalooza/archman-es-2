UUCP(1P) Manual del Programador POSIX UUCP(1P)

PROLOG

Esta página del manual es parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

uucp — copia de sistema a sistema

SINOPSIS

uucp [-cCdfjmr] [-n usuario] archivo-origen... archivo-destino

DESCRIPCIÓN

La utilidad uucp copiará los archivos nombrados por el argumento archivo-origen al argumento archivo-destino. Los archivos nombrados pueden estar en sistemas locales o remotos.

La utilidad uucp no puede garantizar la compatibilidad con todas las codificaciones de caracteres en todas las circunstancias. Por ejemplo, los datos de transmisión pueden estar restringidos a 7 bits por la red subyacente, los nombres de archivo y datos de 8 bits no necesitan ser portátiles a sistemas no internacionalizados, etc. Bajo estas circunstancias, se recomienda usar solo caracteres definidos en el rango de 7 bits del estándar ISO/IEC 646:1991 International Reference Version (equivalente a ASCII), y usar solo caracteres definidos en el conjunto de caracteres de nombres de archivo portátiles para nombrar archivos. El protocolo para la transferencia de archivos no está especificado por POSIX.1‐2008.

Las implementaciones típicas de esta utilidad requieren una línea de comunicación configurada para usar el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 11, Interfaz de Terminal General, pero se pueden usar otros medios de comunicación. En sistemas donde no hay medios de comunicación disponibles (ya sea temporal o permanentemente), esta utilidad escribirá un mensaje de error describiendo el problema y saldrá con un estado de salida distinto de cero.

OPCIONES

La utilidad uucp cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades.

Se admitirán las siguientes opciones:

-c
No copiar el archivo local al directorio de cola para su transferencia a la máquina remota (predeterminado).
-C
Forzar la copia de archivos locales al directorio de cola para su transferencia.
-d
Crear todos los directorios necesarios para la copia del archivo (predeterminado).
-f
No crear directorios intermedios para la copia del archivo.
-j
Escribir la cadena de identificación del trabajo en la salida estándar. Esta identificación del trabajo puede ser utilizada por uustat para obtener el estado o terminar un trabajo.
-m
Enviar correo al solicitante cuando se complete la copia.
-n usuario
Notificar a usuario en el sistema remoto que se envió un archivo.
-r
No iniciar la transferencia del archivo; solo poner el trabajo en cola.

OPERANDOS

Se admitirán los siguientes operandos:

archivo-destino, archivo-origen

Una ruta de un archivo a copiar, o desde el cual copiar, respectivamente. Cualquier nombre puede ser una ruta en la máquina local, o puede tener la forma:
nombre-sistema!ruta

donde nombre-sistema se toma de una lista de nombres de sistema que uucp conoce. El nombre-sistema de destino también puede ser una lista de nombres como:

nombre-sistema!nombre-sistema!...!nombre-sistema!ruta

en cuyo caso, se intenta enviar el archivo a través de la ruta especificada al destino. Se debe tener cuidado para asegurar que los nodos intermedios en la ruta estén dispuestos a reenviar información.

Los caracteres de notación de coincidencia de patrones del shell '?', '*' y "[...]" que aparezcan en ruta se expandirán en el sistema apropiado.

Las rutas pueden ser:

1.
Una ruta absoluta.
2.
Una ruta precedida por ~usuario donde usuario es un nombre de inicio de sesión en el sistema especificado y se reemplaza por el directorio de inicio de sesión de dicho usuario. Tenga en cuenta que si se especifica un inicio de sesión no válido, el valor predeterminado es el directorio público (llamado PUBDIR; la ubicación real de PUBDIR depende de la implementación).
3.
Una ruta precedida por ~/destino donde destino se adjunta a PUBDIR.
Nota:
Este destino se trata como un nombre de archivo a menos que se transfiera más de un archivo en esta solicitud o el destino ya sea un directorio. Para asegurarse de que sea un directorio, siga el destino con un '/'. Por ejemplo, ~/dan/ como destino crea el directorio PUBDIR/dan si no existe y coloca los archivos solicitados en ese directorio.
4.
Cualquier otra cosa se prefijará con el directorio actual.

Si el resultado es una ruta errónea para el sistema remoto, la copia fallará. Si el archivo-destino es un directorio, se utilizará la última parte del nombre del archivo-origen.

Los permisos de lectura, escritura y ejecución que otorga uucp son definidos por la implementación.

ARCHIVOS DE ENTRADA

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de uucp:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional.)
LC_ALL
Si se establece en una cadena de valor no vacía, anule los valores de todas las demás variables de internacionalización.
LC_COLLATE

Determinar la configuración regional para el comportamiento de rangos, clases de equivalencia y elementos de ordenación multicarácter dentro de patrones de nombres de archivo entre corchetes.
LC_CTYPE
Determinar la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en comparación con caracteres multibyte en argumentos y archivos de entrada) y el comportamiento de las clases de caracteres dentro de patrones de nombres de archivo entre corchetes (por ejemplo, "'[[:lower:]]*'").
LC_MESSAGES

Determinar la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar y los mensajes informativos escritos en la salida estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

USO DE APLICACIÓN

Esta utilidad forma parte de la opción UUCP Utilities y no es necesario que sea compatible con todas las implementaciones.

El dominio de los archivos accesibles remotamente puede (y por razones de seguridad obvias, normalmente debería) estar severamente restringido.

Tenga en cuenta que el carácter '!' en las direcciones debe ser escapado cuando se usa csh como intérprete de comandos debido a su sintaxis de sustitución de historial. Para ksh y sh, el escape no es necesario, pero se puede usar.

Como se mencionó anteriormente, los metacaracteres del shell que aparecen en los nombres de ruta se expanden en el sistema apropiado. En un sistema internacionalizado, esto se hace bajo el control de la configuración local de LC_COLLATE y LC_CTYPE. Por lo tanto, se debe tener cuidado al usar patrones de nombres de archivo entre corchetes, ya que las reglas de ordenación y tipificación pueden variar de un sistema a otro. También tenga en cuenta que ciertos tipos de expresiones (es decir, clases de equivalencia, clases de caracteres y símbolos de ordenación) no necesitan ser compatibles en sistemas no internacionalizados.
