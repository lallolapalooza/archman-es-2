URLWATCH-DEPRECATED(7) Documentación de urlwatch URLWATCH-DEPRECATED(7)

NOMBRE

urlwatch-deprecated - Documentación de la deprecación de características en urlwatch

A medida que las características se deprecán y se eliminan, se documentan aquí con los pasos para actualizar su configuración para los reemplazos.

NETWORKIDLE0 Y NETWORKIDLE2 PARA WAIT_UNTIL EN TRABAJOS DE NAVEGADOR (DESDE 2.28)

Desde la versión 2.28, la ejecución de trabajos de navegador usa Playwright en lugar de pyppeteer.

Los valores de wait_until previamente soportados de networkidle0 y networkidle2 ya no son compatibles. Playwright soporta en su lugar los valores load, domcontentloaded, networkidle (desaconsejado) o commit.

La configuración existente de networkidle0 y networkidle2 se mapeará a networkidle, y se emitirá una advertencia. Para silenciar la advertencia y continuar usando networkidle, especifique explícitamente wait_until: networkidle.

FILTROS SIN SUBFILTROS (DESDE 2.22)

En versiones anteriores de urlwatch, era posible escribir filtros personalizados que no aceptaban un subfilter como argumento.

Si ha escrito su propio código de filtro como este:

class CustomFilter(filters.FilterBase):
    """Mi antiguo filtro personalizado"""
    __kind__ = 'foo'
    def filter(self, data):
        ...

Debe actualizar su filtro para que acepte un argumento opcional de subfiltro (si la configuración del filtro no tiene un subfiltro definido, el valor de subfilter será None):

class CustomFilter(filters.FilterBase):
    """Mi nuevo filtro personalizado"""
    __kind__ = 'foo'
    def filter(self, data, subfilter):
        ...

DEFINICIONES DE FILTRO BASADAS EN CADENAS (DESDE 2.19)

Con urlwatch 2.19, las listas de filtros basadas en cadenas están obsoletas, ya que no son tan flexibles como las listas de filtros basadas en diccionarios y tenían algunos problemas (por ejemplo, : y , se tratan de forma especial y no se pueden usar fácilmente en subfiltros). Si tiene una definición de filtro como esta:

filter: css:body,html2text:re,strip

Puede obtener los mismos resultados con una definición de filtro como esta:

filter:
  - css:
      selector: body
  - html2text:
      method: re
  - strip

Dado que selector es el subfiltro predeterminado para css, y method es el subfiltro predeterminado para html2text, esto también se puede escribir como:

filter:
  - css: body
  - html2text: re
  - strip

Si solo tiene un filtro único como:

filter: html2text

Puede cambiar este filtro a uno basado en diccionario usando:

filter:
  - html2text

AJUSTE DE KEYRING EN LA CONFIGURACIÓN DEL REPORTER SMTP (DESDE 2.18)

Desde la versión 2.18, la configuración del reporter SMTP usa auth para decidir si se debe realizar la autenticación SMTP o no. Anteriormente, este ajuste se llamaba keyring. Si tiene una configuración antigua como esta:

report:
  email:
    smtp:
      host: localhost
      keyring: false
      port: 25
      starttls: true
    subject: '{count} cambios: {jobs}'

Puede cambiar el ajuste a esto (reemplace keyring por auth):

report:
  email:
    smtp:
      host: localhost
      auth: false
      port: 25
      starttls: true
    subject: '{count} cambios: {jobs}'
