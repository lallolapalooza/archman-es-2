USDGENSCHEMAFROMSDR(1) Comandos de Usuario USDGENSCHEMAFROMSDR(1)

NOMBRE

usdgenschemafromsdr - página del manual para usdgenschemafromsdr 25.11

DESCRIPCIÓN

uso: usdgenschemafromsdr [-h] [--noreadme] [-v]

[configuracionSchema] [rutaGeneracionSchema]
Este script genera schema.usda dinámico, generatedSchema.usda y plugInfo.json. schema.usda se genera analizando los sdrNodes apropiados proporcionados en un archivo de configuración. Además de proporcionar tipos e identificadores de sdrNodes, el archivo de configuración también proporciona una lista de subLayers que debe subyacer el schema.usda autocompletado. La generación de código también se puede habilitar opcionalmente a través de la configuración JSON; tenga en cuenta que la generación de código está deshabilitada por defecto.
El script toma 3 argumentos:
- Una configuración JSON, que proporciona sdrNodes a través de sourceType, sdrNodeIdentifiers
o una lista explícita de rutas de archivos de assets absolutos (sourceAssetNodes) y una lista de subLayers. Las rutas de archivos de assets también pueden contener variables de entorno, por lo que los usuarios deben establecerlas antes de ejecutar el script.
- Un directorio de destino. Tenga en cuenta que un schema.usda con un prim GLOBAL apropiado que proporciona un libraryName en sus customData, debe estar presente en esta ubicación. Esta es también la ubicación donde se exportarán generatedSchema.usda y plugInfo.json. En caso de que la generación de código esté habilitada explícitamente en la configuración, también se debe proporcionar libraryPath junto con libraryName en customData, de lo contrario, usdGenSchema fallará.
- Un noreadme opcional para ignorar la generación de un README.md que proporcione una breve
explicación del contenido del directorio.
Este script ejecutará usdGenSchema en el schema.usda autocompletado.
Si está regenerando esquemas, se recomienda establecer la variable de entorno USD_DISABLE_AUTO_APPLY_API_SCHEMAS a true para evitar que cualquier esquema de API de aplicación automática generada previamente se aplique a las bases de esquema especificadas, lo que puede resultar en la eliminación de propiedades adicionales.
Las especificaciones completadas en schema.usda de los sdrNodes proporcionados usando UsdUtils.UpdateSchemaWithSdrNode y la metadato skipCodeGeneration se establecerán en true, a menos que se marque explícitamente como False en la configuración para este schema.usda.
UsdUtils.UpdateSchemaWithSdrNode es responsable de:

Actualiza el schemaLayer dado con primSpec y propertySpecs de los metadatos de sdrNode.

Se puede proporcionar un renderContext que se utiliza para determinar el espacio de nombres shaderId, que sigue el patrón: "<renderContext>:<SdrShaderNodeContext>:shaderId". Tenga en cuenta que estamos utilizando el contexto de un nodo (SDR_NODE_CONTEXT_TOKENS) aquí para construir el espacio de nombres shaderId, por lo que los analizadores de shaders deben asegurarse de usar los SDR_NODE_CONTEXT_TOKENS apropiados en las definiciones de los nodos.

El parámetro overrideIdentifier es el identificador que se debe utilizar cuando el identificador del nodo que se está procesando difiere del que Sdr descubrirá en tiempo de ejecución, como cuando esta función def un nodo construido a partir de una ruta de asset explícita. Esto solo debe usarse cuando los clientes saben que el identificador que se pasa es el identificador real que Sdr proporcionará al consultar usando GetShaderNodeByIdentifierAndType, etc.

Consume los siguientes atributos (que se manifiestan como metadatos de Sdr) además de muchos de los metadatos estándar de Sdr especificados y analizados (a través de su plugin de análisis).

Metadatos a nivel de nodo:

- "schemaName": Nombre del nuevo esquema completado a partir del sdrNode dado
(Requerido)
- "schemaKind": Especifica el UsdSchemaKind para el esquema que se está completando
a partir del sdrNode. (Tenga en cuenta que esto no admite múltiples tipos de esquemas aplicables).
- "schemaBase": Esquema base del cual debe heredar el nuevo esquema. Tenga en cuenta que esto, por defecto, es "APISchemaBase" para un esquema de API o "Typed" para un esquema concreto.
- "apiSchemasForAttrPruning": Una lista de esquemas de API principales que se
compondrán juntos y cualquier propiedad de shader compartida de esta definición de prim se eliminará del esquema resultante.
- "typedSchemaForAttrPruning": Un esquema típico principal que se compondrá
junto con los apiSchemasForAttrPruning y cualquier propiedad de shader compartida de esta definición de prim se eliminará del esquema resultante. Si no se proporciona un typedSchemaForAttrPruning, solo se compondrán los apiSchemasForAttrPruning para crear una definición de prim. Esto solo se utilizará al crear un APISchema.
- "apiSchemaAutoApplyTo": Los esquemas a los que se aplicará automáticamente el esquema de API
completado por sdrNode.
- "apiSchemaCanOnlyApplyTo": Si se especifica, el esquema de API generado a partir del
sdrNode solo será válido para aplicarse a este conjunto de esquemas.
- "providesUsdShadeConnectableAPIBehavior": Se utiliza para habilitar un comportamiento de
conectividad para un esquema de API.
- "isUsdShadeContainer": Solo se utiliza cuando providesUsdShadeConnectableAPIBehavior se establece en true. Marca el prim conectable como un tipo de contenedor UsdShade.
- "requiresUsdShadeEncapsulation": Solo se utiliza cuando providesUsdShadeConnectableAPIBehavior se establece en true. Configura las reglas de encapsulación de UsdShade que rigen su connectableBehavior.
- "tfTypeNameSuffix": Nombre de clase que se registrará con el sistema TfType. Esto se
añade al nombre de dominio para registrarse con TfType.
- "schemaPropertyNSPrefixOverride": Metadato a nivel de nodo que puede controlar
el prefijo del espacio de nombres de todas las propiedades del nodo. Esto puede ser útil para nodos no conectables que no deberían tener prefijo en el espacio de nombres de entradas y salidas de UsdShade.

Metadatos a nivel de propiedad:

- "usdVariability": Metadato a nivel de propiedad que especifica que una propiedad de
sdrNode específica debe tener su variabilidad USD establecida en Uniform o Varying
- "usdSuppressProperty": Un metadato a nivel de propiedad que determina si la propiedad
debe suprimirse de la traducción de argumentos a especificaciones de propiedad.
- "propertyNSPrefixOverride": Proporciona una forma de anular el espacio de nombres de una
propiedad del predeterminado (inputs:/outputs:) o de los metadatos schemaPropertyNSPrefixOverride de un nodo.

Traducciones de Metadatos de Propiedad de Sdr a Especificaciones de Propiedad de Sdf

- Un valor "null" para el metadato Widget SdrShaderProperty se traduce a 'hidden' en el diccionario de metadatos uiHints de la especificación de propiedad Sdf.
- El metadato Help (metadato Label si el metadato Help no está proporcionado) de SdrShaderProperty se traduce a las cadenas de metadatos custom userDocBrief y userDoc de la especificación de propiedad Sdf.
- El metadato Page de SdrShaderProperty se traduce a 'displayGroup' en la
especificación de propiedad Sdf.
- El metadato Label de SdrShaderProperty se traduce a 'displayName' en la
especificación de propiedad Sdf.
- Las Opciones de SdrShaderProperty se traducen a 'allowedTokens' (cuando se proporcionan etiquetas o valores) o 'valueLabels' (cuando se proporcionan tanto etiquetas como valores) en el diccionario de metadatos uiHints de la especificación de propiedad Sdf. Para compatibilidad con versiones anteriores, establezca USD_POPULATE_LEGACY_ALLOWED_TOKENS para escribir allowedTokens además de valueLabels para atributos de cadena y token que proporcionen ambas etiquetas y valores.
- El valor predeterminado de SdrShaderProperty se traduce al valor predeterminado de la
especificación de propiedad Sdf.
- Las entradas conectables se traducen a la conectividad InterfaceOnly de la
especificación de propiedad Sdf.
