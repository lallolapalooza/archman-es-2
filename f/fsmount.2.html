fsmount(2) Manual de Llamadas al Sistema fsmount(2)

NOMBRE

fsmount - instanciar un objeto de montaje desde el contexto del sistema de archivos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/mount.h>
int fsmount(int fsfd, unsigned int flags, unsigned int attr_flags);

DESCRIPCIÓN

La llamada al sistema fsmount() forma parte del conjunto de instalaciones de montaje basadas en descriptores de archivo en Linux.

fsmount() crea un nuevo objeto de montaje desvinculado para la raíz de la nueva instancia del sistema de archivos referenciada por el descriptor de archivo de contexto del sistema de archivos fsfd. Luego se devuelve un nuevo descriptor de archivo asociado con el objeto de montaje desvinculado. Para crear un objeto de montaje con fsmount(), el proceso llamante debe tener la capacidad CAP_SYS_ADMIN.

El contexto del sistema de archivos debe haber sido creado con una llamada a fsopen(2) y luego se le debe haber instanciado un sistema de archivos con una llamada a fsconfig(2) con FSCONFIG_CMD_CREATE o FSCONFIG_CMD_CREATE_EXCL para estar en el estado correcto para esta operación (el modo "esperando montaje" en la jerga de los desarrolladores del kernel). A diferencia de open_tree(2) con OPEN_TREE_CLONE, fsmount() solo puede llamarse una vez en la vida útil de un contexto de sistema de archivos para producir un objeto de montaje.

Al igual que con los descriptores de archivo devueltos por open_tree(2) llamados con OPEN_TREE_CLONE, el descriptor de archivo devuelto puede ser utilizado posteriormente con move_mount(2), mount_setattr(2), u otras llamadas al sistema similares para realizar más operaciones de montaje. Este objeto de montaje se desmontará y destruirá cuando se cierre el descriptor de archivo, si no se ha adjuntado de otra manera a un punto de montaje llamando a move_mount(2). (Tenga en cuenta que la operación de desmontaje en close(2) es perezosa — similar a llamar a umount2(2) con MNT_DETACH; cualquier referencia abierta existente a archivos del objeto de montaje continuará funcionando, y el objeto de montaje solo se destruirá completamente una vez que deje de estar ocupado). El descriptor de archivo devuelto también actúa de la misma manera que uno producido por open(2) con O_PATH, lo que significa que también se puede usar como argumento dirfd para las llamadas al sistema "*at()".

flags controla la creación del descriptor de archivo devuelto. Un valor para flags se construye combinando mediante OR a nivel de bits cero o más de las siguientes constantes:

FSMOUNT_CLOEXEC
Establece la bandera de cierre al ejecutar (FD_CLOEXEC) en el nuevo descriptor de archivo. Consulte la descripción de la bandera O_CLOEXEC en open(2) para conocer las razones por las que esto puede ser útil.

attr_flags especifica atributos de montaje que se aplicarán al objeto de montaje creado, en forma de banderas MOUNT_ATTR_*. Las banderas se interpretan como si se hubiera llamado a mount_setattr(2) con attr.attr_set establecido en el mismo valor que attr_flags. Las banderas MOUNT_ATTR_* que requerirían especificar campos adicionales en mount_attr(2type) (como MOUNT_ATTR_IDMAP) no son valores de bandera válidos para attr_flags.

Si la operación fsmount() es exitosa, el contexto del sistema de archivos asociado con el descriptor de archivo fsfd se reinicia y se coloca en modo de reconfiguración, como si acabara de ser devuelto por fspick(2). Puede seguir usando fsconfig(2) con el contexto del sistema de archivos ahora reiniciado, incluyendo la emisión del comando FSCONFIG_CMD_RECONFIGURE para reconfigurar la instancia del sistema de archivos.

VALOR DE RETORNO

En caso de éxito, se devuelve un nuevo descriptor de archivo. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EBUSY
El contexto del sistema de archivos asociado con fsfd no está en el estado correcto para ser utilizado por fsmount().
EINVAL
flags tenía una bandera inválida establecida.
EINVAL
attr_flags tenía una bandera MOUNT_ATTR_* inválida establecida.
EMFILE
El proceso llamante tiene demasiados archivos abiertos para crear más.
ENFILE
El sistema tiene demasiados archivos abiertos para crear más.
ENOSPC
El espacio de nombres de montaje "anónimo" necesario para contener el nuevo objeto de montaje no pudo ser asignado, ya que hacerlo excedería el límite configurado por usuario en el número de espacios de nombres de montaje en el espacio de nombres de usuario actual. (Véase también namespaces(7)).
ENOMEM
El kernel no pudo asignar suficiente memoria para completar la operación.
EPERM
El proceso llamante no tiene la capacidad requerida CAP_SYS_ADMIN.

ESTÁNDARES

Linux.

HISTORIA

Linux 5.2. glibc 2.36.

EJEMPLOS


int fsfd, mntfd, tmpfd;
fsfd = fsopen("tmpfs", FSOPEN_CLOEXEC);
fsconfig(fsfd, FSCONFIG_CMD_CREATE, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC,
                MOUNT_ATTR_NODEV | MOUNT_ATTR_NOEXEC);
/* Crear un archivo nuevo sin adjuntar el objeto de montaje */
tmpfd = openat(mntfd, "tmpfile", O_CREAT | O_EXCL | O_RDWR, 0600);
unlinkat(mntfd, "tmpfile", 0);
/* Adjuntar el objeto de montaje a "/tmp" */
move_mount(mntfd, "", AT_FDCWD, "/tmp", MOVE_MOUNT_F_EMPTY_PATH);
