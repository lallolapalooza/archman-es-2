FUSER(1) Comandos de usuario FUSER(1)

NOMBRE

fuser - identificar procesos que usan archivos o sockets

SINOPSIS

fuser [-fuv] [-a|-s] [-4|-6] [-c|-m|-n espacio] [ -k [-i] [-M] [-w] [-SEÑAL] ] nombre ...
fuser -l
fuser -V

DESCRIPCIÓN

fuser muestra los PIDs de los procesos que utilizan los archivos especificados. En el modo de visualización predeterminado, cada nombre de archivo va seguido de una letra que denota el tipo de acceso:

c
directorio actual.
e
ejecutable en ejecución.
f
archivo abierto. f se omite en el modo de visualización predeterminado.
F
archivo abierto para escritura. F se omite en el modo de visualización predeterminado.
r
directorio raíz.
m
archivo mmap'ed o biblioteca compartida.
.
Marcador de posición, omitido en el modo de visualización predeterminado.

fuser devuelve un código de retorno distinto de cero si ninguno de los archivos especificados es accedido o en caso de error fatal. Si se ha encontrado al menos un acceso, fuser devuelve cero.

Para buscar procesos que usan sockets TCP y UDP, se debe seleccionar el espacio de nombres correspondiente con la opción -n. Por predeterminado, fuser buscará en sockets IPv6 e IPv4. Para cambiar el comportamiento predeterminado, utilice las opciones -4 y -6. Los sockets se pueden especificar por el puerto local y remoto, y la dirección remota. Todos los campos son opcionales, pero las comas delante de los campos faltantes deben estar presentes:

[puerto_lcl][,[host_rmt][,[puerto_rmt]]]

Se pueden usar valores simbólicos o numéricos para las direcciones IP y los números de puerto.

fuser solo muestra los PIDs en la salida estándar, todo lo demás se envía a la salida de error estándar.

OPCIONES

-a, --all
Muestra todos los archivos especificados en la línea de comandos. Por predeterminado, solo se muestran los archivos a los que accede al menos un proceso.
-c
Igual que la opción -m, utilizada para compatibilidad con POSIX.
-f
Se ignora silenciosamente, utilizada para compatibilidad con POSIX.
-k, --kill
Termina los procesos que acceden al archivo. A menos que se cambie con -SEÑAL, se envía SIGKILL. Un proceso fuser nunca se termina a sí mismo, pero puede terminar otros procesos fuser. La ID de usuario efectiva del proceso que ejecuta fuser se establece a su ID de usuario real antes de intentar terminar.
-i, --interactive
Pregunta al usuario por confirmación antes de terminar un proceso. Esta opción se ignora silenciosamente si tampoco está presente -k.
-I, --inode
Para el espacio de nombres file, todas las comparaciones se basarán en los inodos de los archivos especificados y nunca en los nombres de archivo, incluso en sistemas de archivos basados en red.
-l, --list-signals
Lista todos los nombres de señales conocidos.
-m NOMBRE, --mount NOMBRE
NOMBRE especifica un archivo en un sistema de archivos montado o un dispositivo de bloque que está montado. Se listan todos los procesos que acceden a archivos en ese sistema de archivos. Si se especifica un directorio, se cambia automáticamente a NOMBRE/ para usar cualquier sistema de archivos que pueda estar montado en ese directorio.
-M, --ismountpoint
La solicitud se cumplirá solo si NOMBRE especifica un punto de montaje. Este es un cinturón de seguridad invaluable que evita que mate la máquina si NOMBRE resulta no ser un sistema de archivos.
-w
Termina solo los procesos que tienen acceso de escritura. Esta opción se ignora silenciosamente si tampoco está presente la opción -k.
-n NAMESPACE, --namespace NAMESPACE
Selecciona un espacio de nombres diferente. Los espacios de nombres file (nombres de archivo, el predeterminado), udp (puertos UDP locales) y tcp (puertos TCP locales) son compatibles. Para los puertos, se puede especificar el número de puerto o el nombre simbólico. Si no hay ambigüedad, se puede usar la notación abreviada nombre/espacio (por ejemplo, 80/tcp).
-s, --silent
Operación silenciosa. -u y -v se ignoran en este modo. -a no debe usarse con -s.
-SEÑAL
Utiliza la señal especificada en lugar de SIGKILL al terminar procesos. Las señales se pueden especificar por nombre (por ejemplo, -HUP) o por número (por ejemplo, -1). Esta opción se ignora silenciosamente si no se usa la opción -k.
-u, --user
Agrega el nombre de usuario del propietario del proceso a cada PID.
-v, --verbose
Modo detallado. Los procesos se muestran en un estilo similar a ps. Los campos PID, USUARIO y COMANDO son similares a los de ps. ACCESO muestra cómo el proceso accede al archivo. El modo detallado también mostrará cuándo se está accediendo a un archivo particular como punto de montaje, exportación de knfs o archivo de intercambio (swap). En este caso, se muestra kernel en lugar del PID.
-V, --version
Muestra información de la versión.
-4, --ipv4
Busca solo sockets IPv4. Esta opción no debe usarse con la opción -6 y solo tiene efecto con los espacios de nombres tcp y udp.
-6, --ipv6
Busca solo sockets IPv6. Esta opción no debe usarse con la opción -4 y solo tiene efecto con los espacios de nombres tcp y udp.

ARCHIVOS

/proc
ubicación del sistema de archivos proc

EJEMPLOS

fuser -km /home
termina todos los procesos que acceden al sistema de archivos /home de cualquier manera.
if fuser -s /dev/ttyS1; then :; else comando; fi
invoca comando si ningún otro proceso está usando /dev/ttyS1.
fuser telnet/tcp
muestra todos los procesos en el puerto TELNET (local).

RESTRICCIONES

Los procesos que acceden al mismo archivo o sistema de archivos varias veces de la misma manera solo se muestran una vez.

Si el mismo objeto se especifica varias veces en la línea de comandos, algunas de esas entradas pueden ser ignoradas.

fuser solo puede recopilar información parcial a menos que se ejecute con privilegios. Como consecuencia, los archivos abiertos por procesos que pertenecen a otros usuarios pueden no aparecer y los ejecutables pueden ser clasificados solo como mapeados.
