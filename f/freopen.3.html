NOTAS

notas de glibc

La biblioteca C de GNU permite las siguientes extensiones para la cadena especificada en mode:

c (desde glibc 2.3.3)
No hacer que la operación de apertura, o las subsecuentes operaciones de lectura y escritura, sean puntos de cancelación de hilos. Esta bandera es ignorada para fdopen().
e (desde glibc 2.7)
Abrir el archivo con la bandera O_CLOEXEC . Véase open(2) para más información. Esta bandera es ignorada para fdopen().
m (desde glibc 2.3)
Intentar acceder al archivo usando mmap(2), en lugar de llamadas al sistema de E/S (read(2), write(2)). Actualmente, el uso de mmap(2) se intenta solo para un archivo abierto para lectura.
x
Abrir el archivo exclusivamente (como la O_EXCL bandera de open(2)). Si el archivo ya existe, fopen() falla, y establece errno a EEXIST. Esta bandera es ignorada para fdopen().

Además de los caracteres anteriores, fopen() y freopen() soportan la siguiente sintaxis en mode:

,ccs=cadena

La cadena dada se toma como el nombre de un juego de caracteres codificado y el flujo se marca como orientado a anchos. Posteriormente, las funciones internas de conversión convierten la E/S a y desde el juego de caracteres cadena. Si la sintaxis ,ccs=cadena no se especifica, entonces la orientación a anchos del flujo es determinada por la primera operación de archivo. Si esa operación es una operación de caracteres anchos, el flujo se marca como orientado a anchos, y se cargan las funciones para convertir al juego de caracteres codificado.

ERRORES

Al analizar los caracteres individuales de bandera en mode (es decir, los caracteres que preceden a la especificación "ccs"), la implementación de glibc de fopen() y freopen() limita el número de caracteres examinados en mode a 7 (o, antes de glibc 2.14, a 6, lo cual no era suficiente para incluir posibles especificaciones como "rb+cmxe"). La implementación actual de fdopen() analiza como máximo 5 caracteres en mode.
