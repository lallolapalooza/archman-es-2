truncate(2) Manual de Llamadas al Sistema truncate(2)

NOMBRE

truncate, ftruncate - trunca un archivo a una longitud especificada

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <unistd.h>
int truncate(const char *path, off_t length);
int ftruncate(int fd, off_t length);
Requisitos de la macro de prueba de características para glibc (ver feature_test_macros(7)):

truncate():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.12: */ _POSIX_C_SOURCE >= 200809L
        || /* glibc <= 2.19: */ _BSD_SOURCE

ftruncate():

    _XOPEN_SOURCE >= 500
        || /* Desde glibc 2.3.5: */ _POSIX_C_SOURCE >= 200112L
        || /* glibc <= 2.19: */ _BSD_SOURCE

DESCRIPCIÓN

Las funciones truncate() y ftruncate() hacen que el archivo regular nombrado por path o referenciado por fd sea truncado a un tamaño de exactamente length bytes.

Si el archivo era anteriormente más grande que este tamaño, los datos extra se pierden. Si el archivo era anteriormente más corto, se extiende, y la parte extendida se lee como bytes nulos ('\0').

El desplazamiento del archivo no se cambia.

Si el tamaño cambió, entonces los campos st_ctime y st_mtime (respectivamente, hora del último cambio de estado y hora de la última modificación; ver inode(7)) del archivo se actualizan, y los bits de modo set-user-ID y set-group-ID pueden ser borrados.

Con ftruncate(), el archivo debe estar abierto para escritura; con truncate(), el archivo debe ser escribible.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1, y errno se establece para indicar el error.

ERRORES

Para truncate():

EACCES
Se deniega el permiso de búsqueda para un componente del prefijo de la ruta, o el archivo nombrado no es escribible por el usuario. (Ver también path_resolution(7).)
EFAULT
El argumento path apunta fuera del espacio de direcciones asignado al proceso.
EFBIG
El argumento length es más grande que el tamaño máximo de archivo. (XSI)
EINTR
Mientras estaba bloqueado esperando a completarse, la llamada fue interrumpida por un manejador de señales; ver fcntl(2) y signal(7).
EINVAL
El argumento length es negativo o más grande que el tamaño máximo de archivo.
EIO
Ocurrió un error de E/S al actualizar el inodo.
EISDIR
El archivo nombrado es un directorio.
ELOOP
Se encontraron demasiados enlaces simbólicos al traducir la ruta de acceso.
ENAMETOOLONG
Un componente de una ruta de acceso excedió los 255 caracteres, o una ruta de acceso completa excedió los 1023 caracteres.
ENOENT
El archivo nombrado no existe.
ENOTDIR
Un componente del prefijo de la ruta no es un directorio.
EPERM
El sistema de archivos subyacente no permite extender un archivo más allá de su tamaño actual.
EPERM
La operación fue impedida por un sello de archivo; ver fcntl(2).
EROFS
El archivo nombrado reside en un sistema de archivos de solo lectura.
ETXTBSY
El archivo es un archivo ejecutable que está siendo ejecutado.

Para ftruncate() se aplican los mismos errores, pero en lugar de cosas que pueden estar mal con path, ahora tenemos cosas que pueden estar mal con el descriptor de archivo, fd:

EBADF
fd no es un descriptor de archivo válido.
EBADF o EINVAL
fd no está abierto para escritura.
EINVAL
fd no referencia un archivo regular o un objeto de memoria compartida POSIX.
EINVAL o EBADF
El descriptor de archivo fd no está abierto para escritura. POSIX permite, y las aplicaciones portables deben manejar, cualquiera de los dos errores para este caso. (Linux produce EINVAL.)

VERSIONES

Los detalles en DESCRIPCIÓN son para sistemas compatibles con XSI. Para sistemas no compatibles con XSI, el estándar POSIX permite dos comportamientos para ftruncate() cuando length excede la longitud del archivo (note que truncate() no se especifica en absoluto en tal entorno): o bien devolver un error, o extender el archivo. Como la mayoría de las implementaciones de UNIX, Linux sigue el requisito XSI al tratar con sistemas de archivos nativos. Sin embargo, algunos sistemas de archivos no nativos no permiten que truncate() y ftruncate() se usen para extender un archivo más allá de su longitud actual: un ejemplo notable en Linux es VFAT.

En algunas arquitecturas de 32 bits, la firma de llamada para estas llamadas al sistema difiere, por las razones descritas en syscall(2).

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, SVr4, 4.2BSD.

Las llamadas al sistema originales de Linux truncate() y ftruncate() no fueron diseñadas para manejar desplazamientos de archivo grandes. En consecuencia, Linux 2.4 añadió las llamadas al sistema truncate64() y ftruncate64() que manejan archivos grandes. Sin embargo, estos detalles pueden ser ignorados por aplicaciones que usan glibc, cuyas funciones envoltorio emplean transparentemente las llamadas al sistema más recientes donde están disponibles.

NOTAS

ftruncate() también puede usarse para establecer el tamaño de un objeto de memoria compartida POSIX; ver shm_open(3).

ERRORES

Un error en un archivo de cabecera en glibc 2.12 significaba que el valor mínimo de _POSIX_C_SOURCE requerido para exponer la declaración de ftruncate() era 200809L en lugar de 200112L. Esto ha sido corregido en versiones posteriores de glibc.

VER TAMBIÉN

truncate(1), open(2), stat(2), path_resolution(7)
