FTW(3P) Manual del Programador POSIX FTW(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página manual de Linux correspondiente para detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

ftw — recorrer (caminar) un árbol de archivos

SINOPSIS

#include <ftw.h>
int ftw(const char *path, int (*fn)(const char *,
    const struct stat *ptr, int flag), int ndirs);

DESCRIPCIÓN

La función ftw() descenderá recursivamente por la jerarquía de directorios con raíz en path. Para cada objeto en la jerarquía, ftw() llamará a la función a la que apunta fn, pasándole un puntero a una cadena de caracteres terminada por nulo que contiene el nombre del objeto, un puntero a una estructura stat que contiene información sobre el objeto, rellenada como si se hubiera llamado a stat() o lstat() para recuperar la información. Los valores posibles del entero, definidos en el encabezado <ftw.h> , son:

FTW_D
Para un directorio.
FTW_DNR
Para un directorio que no se puede leer.
FTW_F
Para un archivo que no es un directorio.
FTW_SL
Para un enlace simbólico (pero véase también FTW_NS más abajo).
FTW_NS
Para un objeto que no es un enlace simbólico en el que stat() no pudo ejecutarse correctamente. Si el objeto es un enlace simbólico y stat() falló, no se especifica si ftw() pasa FTW_SL o FTW_NS a la función proporcionada por el usuario.

Si el entero es FTW_DNR, los descendientes de ese directorio no serán procesados. Si el entero es FTW_NS, la estructura stat contiene valores no definidos. Un ejemplo de un objeto que causaría que se pasara FTW_NS a la función a la que apunta fn sería un archivo en un directorio con permiso de lectura pero sin permiso de ejecución (búsqueda).

La función ftw() visitará un directorio antes de visitar cualquiera de sus descendientes.

La función ftw() usará como máximo un descriptor de archivo para cada nivel en el árbol.

El argumento ndirs debe estar en el rango [1,{OPEN_MAX}].

El recorrido del árbol continuará hasta que se agote el árbol, una invocación de fn devuelva un valor distinto de cero, o se detecte algún error, distinto de [EACCES], dentro de ftw().

El argumento ndirs especificará el número máximo de flujos de directorio o descriptores de archivo o ambos disponibles para su uso por ftw() mientras recorre el árbol. Cuando ftw() retorne, cerrará cualquier flujo de directorio y descriptor de archivo que use, sin contar los abiertos por la función fn proporcionada por la aplicación.

Los resultados no están especificados si la función fn proporcionada por la aplicación no preserva el directorio de trabajo actual.

La función ftw() no necesita ser segura para hilos.

VALOR DE RETORNO

Si el árbol se agota, ftw() retornará 0. Si la función a la que apunta fn retorna un valor distinto de cero, ftw() detendrá su recorrido del árbol y retornará cualquier valor que haya retornado la función a la que apunta fn. Si ftw() detecta un error, retornará -1 y establecerá errno para indicar el error.

Si ftw() encuentra un error distinto de [EACCES] (véase FTW_DNR y FTW_NS más arriba), retornará -1 y establecerá errno para indicar el error. La variable externa errno puede contener cualquier valor de error que sea posible cuando se abre un directorio o cuando se ejecuta una de las funciones stat sobre un directorio o archivo.

ERRORES

La función ftw() fallará si:

EACCES
Se deniega el permiso de búsqueda para cualquier componente de path o se deniega el permiso de lectura para path.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path .
ENAMETOOLONG

La longitud de un componente de una ruta de acceso es mayor que {NAME_MAX}.
ENOENT
Un componente de path no nombra un archivo existente o path es una cadena vacía.
ENOTDIR
Un componente de path nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.
EOVERFLOW
Un campo en la estructura stat no puede representarse correctamente en el entorno de programación actual para uno o más archivos encontrados en la jerarquía de archivos.

La función ftw() puede fallar si:

EINVAL
El valor del argumento ndirs es inválido.
ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path .
ENAMETOOLONG

La longitud de una ruta de acceso excede {PATH_MAX}, o la resolución de la ruta de acceso de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.

Además, si la función a la que apunta fn encuentra errores del sistema, errno puede establecerse en consecuencia.

EJEMPLOS

Recorrer una Estructura de Directorios

El siguiente ejemplo recorre la estructura de directorios actual, llamando a la función fn para cada entrada de directorio, usando como máximo 10 descriptores de archivo:

#include <ftw.h>
...
if (ftw(".", fn, 10) != 0) {
    perror("ftw"); exit(2);
}

USO EN APLICACIONES

La función ftw() puede asignar almacenamiento dinámico durante su operación. Si ftw() es terminada forzosamente, como por la ejecución de longjmp() o siglongjmp() por la función a la que apunta fn o una rutina de interrupción, ftw() no tiene la oportunidad de liberar ese almacenamiento, por lo que permanece asignado permanentemente. Una forma segura de manejar interrupciones es almacenar el hecho de que ha ocurrido una interrupción, y disponer que la función a la que apunta fn retorne un valor distinto de cero en su próxima invocación.

Las aplicaciones deberían usar la función nftw() en lugar de la función obsoleta ftw() .

JUSTIFICACIÓN

Ninguna.

DIRECCIONES FUTURAS

La función ftw() puede eliminarse en una versión futura.

VÉASE TAMBIÉN

fdopendir(), fstatat(), longjmp(), nftw(), siglongjmp()
