fort77(1P) Manual pages del programador POSIX fort77(1P)

PROLOG

Esta página de manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página de manual de Linux correspondiente para detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fort77 — Compilador FORTRAN (FORTRAN)

SINOPSIS

fort77 [-c] [-g] [-L directorio]... [-O nivelopt] [-o archivo_salida] [-s]
    [-w] operando...

DESCRIPCIÓN

La utilidad fort77 es la interfaz del sistema de compilación FORTRAN; aceptará el lenguaje FORTRAN-77 completo definido por el estándar ANSI X3.9‐1978. El sistema consiste conceptualmente en un compilador y un enlazador. Los archivos referenciados por los operandos se compilan y enlazan para producir un archivo ejecutable. No se especifica si el enlazado ocurre completamente dentro de la operación de fort77; algunas implementaciones pueden producir objetos que no se resuelven completamente hasta que el archivo se ejecuta.

Si está presente la opción -c, para todos los operandos de ruta del tipo archivo.f, los archivos:

$(basename ruta.f).o

se crearán o sobrescribirán como resultado de una compilación exitosa. Si la opción -c no está especificada, no se especifica si se crean o eliminan dichos archivos .o para los operandos archivo.f.

Si no hay opciones que impidan el enlazado (como -c) y todos los operandos compilan y enlazan sin errores, el archivo ejecutable resultante se escribirá en el archivo llamado por la opción -o (si está presente) o en el archivo a.out. El archivo ejecutable se creará según lo especificado en el Volumen de Interfaces del Sistema de POSIX.1‐2017, excepto que los permisos del archivo se establecerán en: S_IRWXO | S_IRWXG | S_IRWXU

y que los bits especificados por el umask del proceso se borrarán.

OPCIONES

La utilidad fort77 se ajustará a las Directrices de Sintaxis de Utilidad del Volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, excepto que:

*
Los operandos -l biblioteca tienen el formato de opciones, pero su posición dentro de una lista de operandos afecta el orden en que se buscan las bibliotecas.
*
El orden de especificación de las múltiples opciones -L es significativo.
*
Las aplicaciones que cumplan las normas especificarán cada opción por separado; es decir, la agrupación de letras de opción (por ejemplo, -cg) no tiene por qué ser reconocida por todas las implementaciones.

Se soportarán las siguientes opciones:

-c
Suprimir la fase de enlazado de la compilación y no eliminar ningún archivo objeto que se produzca.
-g
Producir información simbólica en los archivos objeto o ejecutables; la naturaleza de esta información no se especifica y puede ser modificada por interacciones definidas por la implementación con otras opciones.
-s
Producir archivos objeto o ejecutables, o ambos, de los cuales se haya eliminado (stripped) la información simbólica y otra información no requerida para una ejecución correcta utilizando la familia de funciones exec definida en el Volumen de Interfaces del Sistema de POSIX.1‐2017. Si están presentes ambas opciones -g y -s, la acción realizada no se especifica.
-o archivo_salida
Utilizar la ruta archivo_salida, en lugar del valor predeterminado a.out, para el archivo ejecutable producido. Si la opción -o está presente con -c, el resultado no se especifica.
-L directorio
Cambiar el algoritmo de búsqueda de las bibliotecas nombradas en los operandos -l para que busque en el directorio nombrado por la ruta directorio antes de buscar en los lugares habituales. Los directorios nombrados en las opciones -L se buscarán en el orden especificado. Se soportarán al menos diez instancias de esta opción en una única invocación del comando fort77. Si un directorio especificado por una opción -L contiene un archivo llamado libf.a, los resultados no se especifican.
-O nivelopt
Especificar el nivel de optimización del código. Si el argumento de opción nivelopt es el dígito '0', se deshabilitarán todas las optimizaciones especiales de código. Si es el dígito '1', la naturaleza de la optimización no se especifica. Si se omite la opción -O, la naturaleza de la optimización predeterminada del sistema no se especifica. No se especifica si el código generado en presencia de la opción -O 0 es el mismo que el generado cuando se omite -O. Pueden soportarse otros valores de nivelopt.
-w
Suprimir advertencias.

Se pueden especificar múltiples instancias de las opciones -L.

OPERANDOS

Un operando es o bien una ruta o bien del tipo -l biblioteca. Se deberá especificar al menos un operando del tipo ruta. Se soportarán los siguientes operandos:

archivo.f
La ruta de un archivo fuente FORTRAN para compilar y opcionalmente pasar al enlazador. El operando del nombre de archivo deberá ser de este tipo si se utiliza la opción -c.
archivo.a
Una biblioteca de archivos objeto producida típicamente por ar, y pasada directamente al enlazador. Las implementaciones pueden reconocer sufijos definidos por la implementación distintos de .a como que denotan bibliotecas de archivos objeto.
archivo.o
Un archivo objeto producido por fort77 -c y pasado directamente al enlazador. Las implementaciones pueden reconocer sufijos definidos por la implementación distintos de .o como que denotan archivos objeto.

El procesamiento de otros archivos no se especifica.

-l biblioteca
(La letra ele.) Buscar la biblioteca llamada:
libbiblioteca.a

Una biblioteca se busca cuando se encuentra su nombre, por lo que la colocación de un operando -l es significativa. Varias bibliotecas estándar pueden especificarse de esta manera, como se describe en la sección DESCRIPCIÓN EXTENDIDA. Las implementaciones pueden reconocer sufijos definidos por la implementación distintos de .a como que denotan bibliotecas.

STDIN

No se utiliza.

ARCHIVOS DE ENTRADA

El archivo de entrada deberá ser uno de los siguientes: un archivo de texto que contenga código fuente FORTRAN; un archivo objeto en el formato producido por fort77 -c; o una biblioteca de archivos objeto, en el formato producido al archivar cero o más archivos objeto, usando ar. Las implementaciones pueden proporcionar utilidades adicionales que produzcan archivos en estos formatos. Los archivos de entrada adicionales no se especifican.

Un carácter <tab> encontrado dentro de los primeros seis caracteres de una línea de código fuente hará que el compilador interprete el carácter siguiente como si fuera el séptimo carácter de la línea (es decir, en la columna 7).

JUSTIFICACIÓ

N

El nombre de esta utilidad se eligió como fort77 para paralelizar el renombrado del compilador C. El nombre f77 no se eligió para evitar problemas con implementaciones históricas. El estándar ANSI X3.9‐1978 se seleccionó como referencia normativa porque la versión ISO/IEC de FORTRAN-77 ha sido reemplazada por el estándar ISO/IEC 1539:

1991.

Los mecanismos de inclusión de archivos y definición de símbolos #define utilizados por la utilidad c99 no se incluyeron en este volumen de POSIX.1‐2017, incluso aunque se implementan comúnmente, ya que no hay requisito de que el compilador FORTRAN use el preprocesador de

C.

La opción -onetrip no se incluyó en este volumen de POSIX.1‐2017, aunque muchos compiladores históricos la soportan, porque se deriva de FORTRAN-66; es un anacronismo que no debería

perpetuarse.

Algunas implementaciones producen listados de compilación. Este aspecto de FORTRAN se ha dejado sin especificar porque hubo controversia sobre los diversos métodos propuestos para implementarlo: una opción -V se superponía con la práctica histórica de los proveedores y una convención de nombres para crear archivos con sufijos .l colisionaba con la práctica histórica de nombrado de archivos

de

lex. No hay

una

opción -I en esta versión de este volumen de POSIX.1‐2017 para especificar un directorio para la inclusión de archivos. Una directiva INCLUDE ha sido parte de las discusiones de Fortran-90, pero una interfaz que soporte ese estándar no está en el alcance

actual.

Se observa que muchos compiladores FORTRAN producen un módulo de objetos incluso cuando ocurren errores de compilación; durante una compilación posterior, el compilador puede parchear el módulo de objetos en lugar de recompilar todo el código. En consecuencia, se deja al implementador si se crea o no un archivo de

objetos.

Se eliminó una referencia a MIL-STD-1753 de una propuesta temprana en respuesta a una solicitud de los desarrolladores del estándar de enlace FORTRAN de POSIX. No era la intención de los desarrolladores del estándar requerir la certificación del compilador FORTRAN, y IEEE Std 1003.9‐1992 no especifica el estándar militar ni ningún requisito especial de preprocesamiento. Además, el uso de ese documento habría sido inapropiado para un estándar internacional. La especificación de la optimización ha estado sujeta a cambios a través de propuestas tempranas. En un momento, -O

y

No siempre está claro si "buena generación de código" es lo mismo que optimización. Las optimizaciones simples de acciones locales generalmente no afectan la semántica de un programa. La opción -O 0 se ha incluido para acomodar la naturaleza muy particular de los cálculos científicos en un entorno altamente optimizado; los compiladores cometen errores. Se espera algún grado de optimización, incluso si no está documentado aquí, y la capacidad de apagarla por completo podría ser importante al portar una aplicación. Una implementación puede tratar -O 0 como "hacer menos de lo normal" si lo desea, pero esto solo es significativo si alguna de las operaciones que realiza puede afectar la semántica de un programa. Es altamente dependiente de la implementación si hacer menos de lo normal es lógico. No es la intención de la opción -O 0 pedir una generación de código ineficiente, sino asegurar que cualquier optimización semánticamente visible se

suprima.

La especificación del acceso a la biblioteca estándar es consistente con la especificación del compilador C. No se requiere que las implementaciones tengan /usr/lib/libf.a, como lo tienen muchas implementaciones históricas, pero si no lo tienen, se les requiere reconocer f como un

token.

Los límites de tamaño de los símbolos externos están en texto normativo; las aplicaciones conformes necesitan conocer estos límites. Sin embargo, la longitud máxima mínima de símbolo debe tomarse como una restricción para una aplicación conforme, no para una implementación, y en consecuencia la acción tomada para un símbolo que excede el límite no está especificada. El tamaño mínimo para la tabla de símbolos externos se añadió por razones

similares.

La sección CONSECUENCIAS DE LOS ERRORES especifica claramente el comportamiento del compilador cuando ocurren errores de compilación o de edición de enlaces. Se examinó el comportamiento de varias implementaciones históricas, y se optó por ser silencioso sobre el estado del archivo ejecutable, o a.out, frente a errores del compilador o del enlazador. Si un enlazador escribe el archivo ejecutable y luego lo enlaza en disco con lseek() y write(), el archivo ejecutable parcialmente enlazado puede quedar en disco y sus bits de ejecución desactivados si la edición de enlaces falla. Sin embargo, si el enlazador enlaza la imagen en memoria antes de escribir el archivo en disco, no necesita tocar el archivo ejecutable (si ya existe) porque la edición de enlaces falla. Dado que ambos enfoques son práctica histórica, una aplicación conforme deberá confiar en el estado de salida de fort77, en lugar de en la existencia o el modo del archivo

ejecutable.

Las opciones -g y -s no se especifican como mutuamente excluyentes. Históricamente, estas dos opciones han sido mutuamente excluyentes, pero como ambas están especificadas de manera tan vaga, pareció apropiado dejar su interacción sin

especificar.

El requisito de que las aplicaciones conformes especifiquen las opciones del compilador por separado es para reservar el espacio de nombres de opciones de múltiples caracteres para las opciones del compilador específicas del proveedor, que se sabe que existen en muchas implementaciones históricas. No se exige a las implementaciones que reconozcan, por ejemplo, -gc como si fuera -g -c; ni se les prohíbe hacerlo. La SINOPSIS muestra todas las opciones por separado para resaltar este requisito en las

aplicaciones.

El eco de los nombres de archivo a la salida de error estándar se considera un mensaje de diagnóstico porque, de lo contrario, sería difícil asociar un mensaje de error con el archivo que causó el error. Se describen con ``may'' (puede) para permitir a las implementaciones usar otros métodos de identificación de archivos y para paralelizar la descripción en c9

9
.
