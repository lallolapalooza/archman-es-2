DESCRIPCIÓN

Fontconfig es una biblioteca diseñada para proporcionar configuración de fuentes a nivel de sistema, personalización y acceso para las aplicaciones.

VISIÓN FUNCIONAL

Fontconfig contiene dos módulos esenciales: el módulo de configuración, que construye una configuración interna a partir de archivos XML, y el módulo de coincidencia, que acepta patrones de fuentes y devuelve la fuente que mejor coincide.

CONFIGURACIÓN DE FUENTES

El módulo de configuración consiste en el tipo de datos FcConfig, libexpat y FcConfigParse, que recorre un árbol XML y modifica una configuración con los datos encontrados en él. Desde una perspectiva externa, la configuración de la biblioteca consiste en generar un árbol XML válido y pasárselo a FcConfigParse. El único otro mecanismo proporcionado a las aplicaciones para cambiar la configuración en ejecución es añadir fuentes y directorios a la lista de archivos de fuentes proporcionados por la aplicación.

La intención es hacer que las configuraciones de fuentes sean relativamente estáticas y compartidas por tantas aplicaciones como sea posible. Se espera que esto conduzca a una selección de fuentes más estable al pasar nombres de una aplicación a otra. Se eligió XML como formato de archivo de configuración porque proporciona un formato que es fácil de editar para agentes externos mientras conserva la estructura y sintaxis correctas.

La configuración de fuentes es independiente de la coincidencia de fuentes; las aplicaciones que necesiten realizar su propia coincidencia pueden acceder a las fuentes disponibles desde la biblioteca y realizar una coincidencia privada. La intención es permitir que las aplicaciones elijan y combinen la funcionalidad apropiada de la biblioteca en lugar de obligarlas a elegir entre esta biblioteca y un mecanismo de configuración privado. Se espera que esto asegure que la configuración de fuentes para todas las aplicaciones pueda centralizarse en un solo lugar. Centralizar la configuración de fuentes simplificará y regulará la instalación y personalización de fuentes.

COINCIDENCIA DE FUENTES

Fontconfig realiza la coincidencia midiendo la distancia desde un patrón proporcionado hasta todas las fuentes disponibles en el sistema. Se selecciona la fuente que más coincide. Esto asegura que siempre se devolverá una fuente, pero no asegura que sea parecida al patrón solicitado.

La coincidencia de fuentes comienza con un patrón construido por la aplicación. Los atributos deseados de la fuente resultante se recogen juntos en un patrón. Cada propiedad del patrón puede contener uno o más valores; estos se enumeran en orden de prioridad; las coincidencias anteriores en la lista se consideran "más cercanas" que las coincidencias posteriores en la lista.

El patrón inicial se modifica aplicando la lista de instrucciones de edición específicas para patrones encontradas en la configuración; cada una consiste en un predicado de coincidencia y un conjunto de operaciones de edición. Se ejecutan en el orden en que aparecieron en la configuración. Cada coincidencia hace que se aplique la secuencia asociada de operaciones de edición.

Después de que el patrón haya sido editado, se realiza una secuencia de sustituciones por defecto para canonizar el conjunto de propiedades disponibles; esto evita la necesidad de que las capas inferiores proporcionen constantemente valores por defecto para varias propiedades de fuentes durante el renderizado.

El patrón canónico de la fuente se compara finalmente con todas las fuentes disponibles. Se mide la distancia desde el patrón hasta la fuente para cada una de varias propiedades: foundry, charset, family, lang, spacing, pixelsize, style, slant, weight, antialias, rasterizer y outline. Esta lista está en orden de prioridad; los resultados de comparar elementos anteriores de esta lista pesan más que los elementos posteriores.

Hay un caso especial a esta regla; los nombres de familia se dividen en dos enlaces; fuertes y débiles. Los nombres de familia fuertes se les da mayor precedencia en la coincidencia que los elementos lang, mientras que los nombres de familia débiles se les da menor precedencia que los elementos lang. Esto permite que el idioma del documento dirija la selección de fuentes cuando cualquier fuente especificada por el documento no está disponible.

El patrón que representa esa fuente se amplía para incluir cualquier propiedad encontrada en el patrón pero no encontrada en la propia fuente; esto permite a la aplicación pasar instrucciones de renderizado o cualquier otro dato a través del sistema de coincidencia. Finalmente, se aplican al patrón las instrucciones de edición específicas para fuentes encontradas en la configuración. Este patrón modificado se devuelve a la aplicación.

El valor de retorno contiene información suficiente para localizar y rasterizar la fuente, incluyendo el nombre del archivo, el tamaño en píxeles y otros datos de renderizado. Como ninguna de la información involucrada pertenece a la biblioteca FreeType, las aplicaciones son libres de usar cualquier motor de rasterización o incluso tomar el archivo de fuente identificado y acceder a él directamente.

Para compilar e instalar fontconfig, se requieren las siguientes librerías:

  • libintl

Asegúrese de que las cabeceras de desarrollo para estas librerías estén instaladas. Luego, ejecute los siguientes comandos:

./configure
make
make install

Esto compilará e instalará fontconfig y sus archivos de configuración. Puede que necesite ejecutar `make install` como root, dependiendo de su sistema.

COINCIDENCIA DE PATRONES

La coincidencia de patrones se realiza en dos pasadas porque esencialmente hay dos operaciones diferentes necesarias: la primera es modificar cómo se seleccionan las fuentes; alias de familias y adición de valores predeterminados adecuados. La segunda es modificar cómo se rasterizan las fuentes seleccionadas. Estas deben aplicarse a la fuente seleccionada, no al patrón original, ya que a menudo se producirán coincidencias falsas.

NOMBRES DE FUENTES

Fontconfig proporciona una representación textual para patrones que la biblioteca puede tanto aceptar como generar. La representación consta de tres partes: primero una lista de nombres de familia, segundo una lista de tamaños en puntos y finalmente una lista de propiedades adicionales:

<familias>-<tamaños en puntos>:<nombre1>=<valores1>:<nombre2>=<valores2>...

Los valores de una lista están separados por comas. El nombre no necesita incluir familias ni tamaños en puntos; se pueden omitir. Además, existen constantes simbólicas que indican simultáneamente un nombre y un valor. Aquí hay algunos ejemplos:

Nombre                            Significado
----------------------------------------------------------
Times-12                        Times Roman de 12 puntos
Times-12:bold                   Times Bold de 12 puntos
Courier:italic                  Courier Italic en el tamaño predeterminado
Monospace:matrix=1 .1 0 1       La fuente monoespaciada preferida del usuario
                                con oblicuidad artificial

Los caracteres '\', '-', ':' y ',' en los nombres de familia deben estar precedidos por un carácter '\' para evitar que se malinterpreten. Del mismo modo, los valores que contienen '\', '=', '_', ':' y ',' también deben tenerlos precedidos por un carácter '\'. Los caracteres '\' se eliminan del nombre de familia y de los valores al leer el nombre de la fuente.

DEPURACIÓN DE APLICACIONES

Para ayudar a diagnosticar problemas de fuentes y aplicaciones, fontconfig está compilado con una gran cantidad de depuración interna habilitada. Se controla mediante la variable de entorno FC_DEBUG. El valor de esta variable se interpreta como un número, y cada bit dentro de ese valor controla diferentes mensajes de depuración.

Nombre         Valor    Significado
---------------------------------------------------------
MATCH            1    Información breve sobre la coincidencia de fuentes
MATCHV           2    Información exhaustiva sobre la coincidencia de fuentes
EDIT             4    Monitorización de la ejecución de coincidencias/pruebas/ediciones
FONTSET          8    Seguimiento de la carga de información de fuentes al inicio
CACHE           16    Observación de la escritura de archivos de caché
CACHEV          32    Información exhaustiva sobre la escritura de archivos de caché
PARSE           64    (ya no se utiliza)
SCAN           128    Observación del escaneo de archivos de fuentes para construir cachés
SCANV          256    Información detallada del escaneo de archivos de fuentes
MEMORY         512    Monitorización del uso de memoria de fontconfig
CONFIG        1024    Observación de qué archivos de configuración se cargan
LANGSET       2048    Volcado de conjuntos de caracteres utilizados para construir valores de idioma
MATCH2        4096    Visualización de la transformación de coincidencia de fuentes en patrones

Sume los valores de los niveles de depuración deseados y asígnele (en base 10) a la variable de entorno FC_DEBUG antes de ejecutar la aplicación. La salida de estas sentencias se envía a stdout.

ETIQUETAS DE IDIOMA

Cada fuente en la base de datos contiene una lista de los idiomas que soporta. Esto se calcula comparando la cobertura Unicode de la fuente con la ortografía de cada idioma. Los idiomas se etiquetan utilizando una nomenclatura compatible con RFC-3066 y constan de dos partes: la etiqueta de idioma ISO 639 seguida de un guion y luego el código de país ISO 3166. El guion y el código de país pueden omitirse.

Fontconfig tiene ortografías para varios idiomas incorporadas en la biblioteca. No se ha previsto la adición de nuevas, aparte de reconstruir la biblioteca. Actualmente soporta 122 de los 139 idiomas nombrados en ISO 639-1, 141 de los idiomas con códigos de dos letras de ISO 639-2 y otros 30 idiomas con solo códigos de tres letras. Los idiomas con códigos de dos y tres letras se proporcionan solo con el código de dos letras.

Para idiomas utilizados en múltiples territorios con conjuntos de caracteres radicalmente diferentes, fontconfig incluye ortografías por territorio. Esto incluye azerbaiyano, kurdo, pastún, tigriña y chino.

FORMATO DE ARCHIVO DE CONFIGURACIÓN

Los archivos de configuración para fontconfig se almacenan en formato XML; este formato facilita la escritura de herramientas de configuración externas y asegura que generarán archivos de configuración sintácticamente correctos. Como los archivos XML son texto plano, también pueden ser manipulados por el usuario experto utilizando un editor de texto.

La definición de tipo de documento de fontconfig reside en la entidad externa "fonts.dtd"; normalmente se almacena en el directorio de configuración de fuentes predeterminado (/etc/fonts ). Cada archivo de configuración debe contener la siguiente estructura:

<?xml version="1.0"?>
<!DOCTYPE fontconfig SYSTEM "urn:fontconfig:fonts.dtd">
<fontconfig>
...
</fontconfig>

<FONTCONFIG>

Este es el elemento de nivel superior para una configuración de fuentes y puede contener elementos <dir>, <cachedir>, <include>, <match> y <alias> en cualquier orden.

<DIR PREFIX= PREDETERMINADO" SALT="">"

Este elemento contiene el nombre de un directorio que se escaneará en busca de archivos de fuentes para incluir en el conjunto de fuentes disponibles.

Si 'prefix' se establece en "default" o "cwd", el directorio de trabajo actual se añadirá como prefijo de ruta antes del valor. Si 'prefix' se establece en "xdg", el valor de la variable de entorno XDG_DATA_HOME se añadirá como prefijo de ruta. consulte la Especificación de Directorios Base XDG para más detalles. Si 'prefix' se establece en "relative", la ruta del archivo actual se añadirá antes del valor.

'salt' property afecta a la determinación del nombre del archivo de caché. esto es útil, por ejemplo, al tener diferentes conjuntos de fuentes en la misma ruta en el contenedor y compartir fuentes del host en una ruta de fuente diferente.

<CACHEDIR PREFIX= PREDETERMINADO">"

Este elemento contiene el nombre de un directorio donde se almacenará o leerá la caché de información de fuentes. Si se especifican varios elementos en el archivo de configuración, el directorio al que se pueda acceder primero en la lista se utilizará para almacenar los archivos de caché. Si comienza con '~', se refiere a un directorio en el directorio principal del usuario. Si 'prefix' se establece en "xdg", el valor de la variable de entorno XDG_CACHE_HOME se añadirá como prefijo de ruta. consulte la Especificación de Directorios Base XDG para más detalles. El directorio predeterminado es ``$XDG_CACHE_HOME/fontconfig'' y contiene los archivos de caché nombrados ``<valor hash>-<arquitectura>.cache-<versión>'', donde <versión> es el número de versión del archivo de caché de fontconfig (actualmente 9).

<INCLUDE IGNORE_MISSING= NO" PREFIX="PREDETERMINADO">"

Este elemento contiene el nombre de un archivo o directorio de configuración adicional. Si es un directorio, cada archivo dentro de ese directorio que comience con un dígito ASCII (U+0030 - U+0039) y termine con la cadena ".conf" se procesará en orden ordenado. Cuando el tipo de dato XML es recorrido por FcConfigParse, el contenido de los archivos también se incorporará a la configuración pasando los nombres de archivo a FcConfigLoadAndParse. Si 'ignore_missing' se establece en "yes" en lugar del "no" predeterminado, un archivo o directorio faltante no generará ningún mensaje de advertencia de la biblioteca. Si 'prefix' se establece en "xdg", el valor de la variable de entorno XDG_CONFIG_HOME se añadirá como prefijo de ruta. consulte la Especificación de Directorios Base XDG para más detalles.

<CONFIG>

Este elemento proporciona un lugar para consolidar información de configuración adicional. <config> puede contener elementos <blank> y <rescan> en cualquier orden.

<DESCRIPTION DOMAIN= FONTCONFIG-CONF">"

Se supone que este elemento contiene cadenas que describen para qué se utiliza una configuración. Esta cadena se puede traducir a través de gettext. 'domain' debe establecerse en el nombre correcto para aplicarlo entonces. fontconfig intentará recuperar traducciones con 'domain' de gettext.

<BLANK>

Las fuentes a menudo incluyen glifos "rotos" que aparecen en la codificación pero se dibujan como espacios en blanco en la pantalla. Dentro del elemento <blank>, coloque cada carácter Unicode que se supone que debe ser un espacio en blanco en un elemento <int>. Los caracteres fuera de este conjunto que se dibujan como espacios en blanco se omitirán del conjunto de caracteres soportados por la fuente.

<REMAP-DIR PREFIX= PREDETERMINADO" AS-PATH="" SALT="">"

Este elemento contiene el nombre de un directorio donde se mapeará como la ruta 'as-path' en la información en caché. Esto es útil si el nombre del directorio es un alias (a través de un montaje de enlace o un enlace simbólico) a otro directorio en el sistema para el cual es probable que exista información de fuentes en caché.

'salt' property afecta a la determinación del nombre del archivo de caché de la misma manera que el elemento <dir>.

<RESET-DIRS />

Este elemento elimina todos los directorios de fuentes que se agregaron mediante elementos <dir>. Esto es útil para anular las fuentes de d

irectories from system to own fonts directories only.

<RESCAN>

El elemento <rescan> contiene un elemento <int> que indica el intervalo predeterminado entre comprobaciones automáticas de cambios en la configuración de fuentes. Fontconfig validará todos los archivos y directorios de configuración y reconstruirá automáticamente las estructuras de datos internas cuando pase este intervalo.

<SELECTFONT>

Este elemento se utiliza para denegar/permitir que las fuentes se enumeren o se comparen. Contiene elementos acceptfont y rejectfont. Esta lista se aplica solo una vez cuando se cargan las cachés. Por lo tanto, si desea filtrar por algunos patrones, los patrones se evalúan con algo que está en la caché únicamente. En otras palabras, los patrones de destino excepto "scan" no tendrán ningún efecto.

<ACCEPTFONT>

Las fuentes que coinciden con un elemento acceptfont están en la "lista blanca"; dichas fuentes se incluyen explícitamente en el conjunto de fuentes utilizado para resolver solicitudes de lista y coincidencia; incluirlas en esta lista las protege de ser "puestas en lista negra" por un elemento rejectfont. Los elementos acceptfont incluyen elementos glob y pattern que se utilizan para hacer coincidir fuentes.

<REJECTFONT>

Las fuentes que coinciden con un elemento rejectfont están en la "lista negra"; dichas fuentes se excluyen del conjunto de fuentes utilizado para resolver solicitudes de lista y coincidencia como si no existieran en el sistema. Los elementos rejectfont incluyen elementos glob y pattern que se utilizan para hacer coincidir fuentes.

<GLOB>

Los elementos glob contienen patrones de coincidencia de nombres de archivo al estilo del shell (incluyendo ? y *) que hacen coincidir fuentes basándose en sus rutas de acceso completas. Si comienza con '~', se refiere a un directorio en el directorio de inicio del usuario. Esto se puede utilizar para excluir un conjunto de directorios (/usr/share/fonts/uglyfont*), o tipos de archivo de fuente particulares (*.pcf.gz), pero este último mecanismo depende en gran medida de las convenciones de nombres de archivo en las que no se puede confiar. Tenga en cuenta que los comodines solo se aplican a los directorios, no a fuentes individuales.

<PATTERN>

Los elementos pattern realizan una coincidencia de estilo lista sobre las fuentes entrantes; es decir, contienen una lista de elementos y valores asociados. Si todos esos elementos tienen un valor que coincide, entonces el patrón coincide con la fuente. Esto se puede utilizar para seleccionar fuentes basándose en atributos de la fuente (escalable, negrita, etc.), que es un mecanismo más fiable que usar extensiones de archivo. Los elementos pattern incluyen elementos patelt.

<PATELT NAME= PROPERTY">"

Los elementos patelt contienen un solo elemento de patrón y una lista de valores. Deben tener un atributo 'name' que indica el nombre del elemento de patrón. Los elementos patelt incluyen elementos int, double, string, matrix, bool, charset y const.

<MATCH TARGET= PATTERN">"

Este elemento contiene primero una lista (posiblemente vacía) de elementos <test> y luego una lista (posiblemente vacía) de elementos <edit>. Los patrones que coinciden con todas las pruebas se someten a todas las ediciones. Si 'target' está establecido en "font" en lugar del predeterminado "pattern", entonces este elemento se aplica al nombre de la fuente resultante de una coincidencia en lugar de a un patrón de fuente que se va a comparar. Si 'target' está establecido en "scan", entonces este elemento se aplica cuando se escanea la fuente para construir la base de datos de fontconfig.

<TEST QUAL= ANY" NAME="PROPERTY" TARGET="DEFAULT" COMPARE="EQ">"

Este elemento contiene un único valor que se compara con la propiedad "property" del destino ('pattern', 'font', 'scan' o 'default') (sustituya cualquiera de los nombres de propiedad vistos anteriormente). 'compare' puede ser uno de "eq", "not_eq", "less", "less_eq", "more", "more_eq", "contains" o "not_contains". 'qual' puede ser el predeterminado, "any", en cuyo caso la coincidencia tiene éxito si cualquier valor asociado con la propiedad coincide con el valor de la prueba, o "all", en cuyo caso todos los valores asociados con la propiedad deben coincidir con el valor de la prueba. 'ignore-blanks' toma un valor booleano. Si 'ignore-blanks' está establecido en "true", cualquier espacio en blanco en la cadena se ignorará en su comparación. Esto solo tiene efecto cuando compare="eq" o compare="not_eq". Cuando se usa en un elemento <match target="font">, el atributo target= en el elemento <test> selecciona entre hacer coincidir el patrón original o la fuente. "default" selecciona el destino que haya seleccionado el elemento <match> externo.

<EDIT NAME= PROPERTY" MODE="ASSIGN" BINDING="WEAK">"

Este elemento contiene una lista de elementos de expresión (cualquiera de los elementos de valor u operador). Los elementos de expresión se evalúan en tiempo de ejecución y modifican la propiedad "property". La modificación depende de si "property" fue coincidida por uno de los elementos <test> asociados; si es así, la modificación puede afectar al primer valor coincidente. Cualquier valor insertado en la propiedad recibe la unión indicada ("strong", "weak" o "same"), con la unión "same" utilizando el valor del elemento de patrón coincidente. 'mode' es uno de:

Modo                    Con Coincidencia              Sin Coincidencia
---------------------------------------------------------------------
"assign"                Reemplaza valor coincidente  Reemplaza todos los valores
"assign_replace"        Reemplaza todos los valores  Reemplaza todos los valores
"prepend"               Inserta antes del coincidente  Inserta al inicio de la lista
"prepend_first"         Inserta al inicio de la lista  Inserta al inicio de la lista
"append"                Añade después del coincidente  Añade al final de la lista
"append_last"           Añade al final de la lista   Añade al final de la lista
"delete"                Elimina valor coincidente   Elimina todos los valores
"delete_all"            Elimina todos los valores       Elimina todos los valores

<INT>, <DOUBLE>, <STRING>, <BOOL>

Estos elementos contienen un solo valor del tipo indicado. Los elementos <bool> contienen true o false. Existe una limitación importante en el análisis de números de punto flotante: fontconfig requiere que la mantisa comience con un dígito, no con un punto decimal, así que inserte un cero inicial para valores puramente fraccionarios (por ejemplo, use 0.5 en lugar de .5 y -0.5 en lugar de -.5).

<MATRIX>

Este elemento contiene cuatro expresiones numéricas de una transformación afín. En su forma más simple serán cuatro elementos <double>, pero también pueden ser expresiones más complejas.

<RANGE>

Este elemento contiene los dos elementos <int> de una representación de rango.

<CHARSET>

Este elemento contiene al menos un elemento <int> de un punto de código Unicode o más.

<LANGSET>

Este elemento contiene al menos un elemento <string> de un idioma al estilo RFC-3066 o más.

<NAME>

Contiene un nombre de propiedad. Se evalúa al primer valor de la propiedad del patrón. Si el atributo 'target' no está presente, será 'default' por defecto, en cuyo caso la propiedad se devuelve del patrón de la fuente durante una coincidencia target="font", y del patrón durante una coincidencia target="pattern". El atributo también puede tomar los valores 'font' o 'pattern' para elegir explícitamente qué patrón usar. Es un error usar un destino 'font' en una coincidencia que tiene target="pattern".

<OR>, <AND>, <PLUS>, <MINUS>, <TIMES>, <DIVIDE>

Estos elementos realizan la operación especificada sobre una lista de elementos de expresión. <or> y <and> son booleanos, no de bits.

<EQ>, <NOT_EQ>, <LESS>, <LESS_EQ>, <MORE>, <MORE_EQ>, <CONTAINS>, <NOT_CONTAINS

Estos elementos comparan dos valores, produciendo un resultado booleano.

<NOT>

Invierte el sentido booleano de su único elemento de expresión

<IF>

Este elemento toma tres elementos de expresión; si el valor del primero es verdadero, produce el valor del segundo, de lo contrario produce el valor del tercero.

<ALIAS>

Los elementos de alias proporcionan una notación abreviada para el conjunto de operaciones de coincidencia comunes necesarias para sustituir una familia de fuentes por otra. Contienen un elemento <family> seguido de elementos opcionales <prefer>, <accept> y <default>. Las fuentes que coinciden con el elemento <family> se editan para anteponer la lista de familias <prefer>idas antes de la <family> coincidente, añadir las familias <accept>ables después de la <family> coincidente y añadir las familias <default> al final de la lista de familias.

<FAMILY>

Contiene un solo nombre de familia de fuentes

<PREFER>, <ACCEPT>, <DEFAULT>

Estos contienen una lista de elementos <family> para ser usados por el elemento <alias>.

ARCHIVO DE CONFIGURACIÓN DEL SISTEMA

Este es un ejemplo de un archivo de configuración de ámbito global

<?xml version="1.0"?>
<!DOCTYPE fontconfig SYSTEM "urn:fontconfig:fonts.dtd">
<!-- /etc/fonts
/fonts.conf file to configure system font access -->
<fontconfig>
  <!--
    Buscar fuentes en estos directorios
  -->
  <dir>/usr/share/fonts</dir>
  <dir>/usr/X11R6/lib/X11/fonts</dir>
  <!--
    Aceptar el alias obsoleto 'mono', reemplazándolo por 'monospace'
  -->
  <match target="pattern">
    <test qual="any" name="family">
      <string>mono</string>
    </test>
    <edit name="family" mode="assign">
      <string>monospace</string>
    </edit>
  </match>
  <!--
    Los nombres que no incluyen ningún alias bien conocido se les asigna 'sans-serif'
  -->
  <match target="pattern">
    <test qual="all" name="family" compare="not_eq">
      <string>sans-serif</string>
    </test>
    <test qual="all" name="family" compare="not_eq">
      <string>serif</string>
    </test>
    <test qual="all" name="family" compare="not_eq">
      <string>monospace</string>
    </test>
    <edit name="family" mode="append_last">
      <string>sans-serif</string>
    </edit>
  </match>
  <!--
    Cargar el archivo de personalización por usuario, pero no quejarse
    si no existe
  -->
  <include ignore_missing="yes" prefix="xdg">
    fontconfig/fonts.conf
  </include>
  <!--
    Cargar los archivos de personalización locales, pero no quejarse
    si no hay ninguno
  -->
  <include ignore_missing="yes">conf.d</include>
  <include ignore_missing="yes">local.conf</include>
  <!--
    Asignar alias a nombres de fuentes bien conocidos con las fuentes TrueType disponibles.
    Estas sustituyen tipos de letra TrueType por tipos similares Type1
    para mejorar la apariencia en pantalla.
  -->
  <alias>
    <family>Times</family>
    <prefer>
      <family>Times New Roman</family>
    </prefer>
    <default>
      <family>serif</family>
    </default>
  </alias>
  <alias>
    <family>Helvetica</family>
    <prefer>
      <family>Arial</family>
    </prefer>
    <default>
      <family>sans-serif</family>
    </default>
  </alias>
  <alias>
    <family>Courier</family>
    <prefer>
      <family>Courier New</family>
    </prefer>
    <default>
      <family>monospace</family>
    </default>
  </alias>
  <!--
    Proporcionar los alias requeridos para los nombres estándar.
    Hacer esto después del archivo de configuración del usuario para que
    cualquier alias allí se use preferentemente
  -->
  <alias>
    <family>serif</family>
    <prefer>
      <family>Times New Roman</family>
    </prefer>
  </alias>
  <alias>
    <family>sans-serif</family>
    <prefer>
      <family>Arial</family>
    </prefer>
  </alias>
  <alias>
    <family>monospace</family>
    <prefer>
      <family>Andale Mono</family>
    </prefer>
  </alias>
  <--
    El ejemplo de los requisitos del operador OR;
    Si la 'family' contiene 'Courier New' O 'Courier'
    añadir 'monospace' como alternativa
  -->
  <match target="pattern">
    <test name="family" compare="eq">
      <string>Courier New</string>
    </test>
    <edit name="family" mode="prepend">
      <string>monospace</string>
    </edit>
  </match>
  <match target="pattern">
    <test name="family" compare="eq">
      <string>Courier</string>
    </test>
    <edit name="family" mode="prepend">
      <string>monospace</string>
    </edit>
  </match>
</fontconfig>

ARCHIVO DE CONFIGURACIÓN DEL USUARIO

Este es un ejemplo de un archivo de configuración por usuario que reside en $XDG_CONFIG_HOME/fontconfig/fonts.conf

<?xml version="1.0"?>
<!DOCTYPE fontconfig SYSTEM "urn:fontconfig:fonts.dtd">
<!--
  $XDG_CONFIG_HOME/fontconfig/fonts.conf for per-user font configuration
-->
<fontconfig>
  <!--
    Directorio de fuentes privado
  -->
  <dir prefix="xdg">fonts</dir>
  <!--
    usar el orden de subpíxeles rgb para mejorar la apariencia de los glifos en
    pantallas LCD. Los cambios que afectan al renderizado, pero no a la coincidencia
    siempre deben usar target="font".
  -->
  <match target="font">
    <edit name="rgba" mode="assign">
      <const>rgb</const>
    </edit>
  </match>
  <!--
    usar la fuente WenQuanYi Zen Hei cuando se solicite serif para chino
  -->
  <match>
    <!--
      Si no desea usar la fuente WenQuanYi Zen Hei para zh-tw etc,
      puede usar zh-cn en lugar de zh.
      Tenga en cuenta que, incluso si establece zh-cn, todavía coincide con zh.
      Si no le gusta, puede usar compare="eq"
      en lugar de compare="contains".
    -->
    <test name="lang" compare="contains">
      <string>zh</string>
    </test>
    <test name="family">
      <string>serif</string>
    </test>
    <edit name="family" mode="prepend">
      <string>WenQuanYi Zen Hei</string>
    </edit>
  </match>
  <!--
    usar la fuente VL Gothic cuando se solicite sans-serif para japonés
  -->
  <match>
    <test name="lang" compare="contains">
      <string>ja</string>
    </test>
    <test name="family">
      <string>sans-serif</string>
    </test>
    <edit name="family" mode="prepend">
      <string>VL Gothic</string>
    </edit>
  </match>
</fontconfig>

ARCHIVOS

fonts.conf contiene la información de configuración para la biblioteca fontconfig, consistente en los directorios donde buscar información de fuentes así como instrucciones para editar los patrones de fuentes especificados por el programa antes de intentar hacer coincidir las fuentes disponibles. Está en formato XML.

conf.d es el nombre convencional para un directorio de archivos de configuración adicionales gestionados por aplicaciones externas o el administrador local. Los nombres de archivo que comienzan con dígitos decimales se ordenan en orden lexicográfico y se usan como archivos de configuración adicionales. Todos estos archivos están en formato XML. El archivo maestro fonts.conf referencia este directorio en una directiva <include>.

fonts.dtd es un DTD que describe el formato de los archivos de configuración.

$XDG_CONFIG_HOME/fontconfig/conf.d</b> y ~/.fonts.conf.d es el nombre convencional para un directorio por usuario de archivos de configuración (típicamente generados automáticamente), aunque la ubicación real está especificada en el archivo global fonts.conf. Tenga en cuenta que ~/.fonts.conf.d está obsoleto ahora. No se leerá de forma predeterminada en la versión futura.

$XDG_CONFIG_HOME/fontconfig/fonts.conf y ~/.fonts.conf es la ubicación convencional para la configuración de fuentes por usuario, aunque la ubicación real está especificada en el archivo global fonts.conf. Tenga en cuenta que ~/.fonts.conf está obsoleto ahora. No se leerá de forma predeterminada en la versión futura.

$XDG_CACHE_HOME/fontconfig/*.cache-* y ~/.fontconfig/*.cache-* es el repositorio convencional de información de fuentes que no se encuentra en las cachés por directorio. Este archivo es mantenido automáticamente por fontconfig. Tenga en cuenta que ~/.fontconfig/*.cache-* está obsoleto ahora. No se leerá de forma predeterminada en la versión futura.

VARIABLES DE ENTORNO

FONTCONFIG_FILE se usa para anular el archivo de configuración predeterminado.

FONTCONFIG_PATH se usa para anular el directorio de configuración predeterminado.

FONTCONFIG_SYSROOT se usa para establecer un directorio de sysroot predeterminado.

FC_DEBUG se usa para generar los mensajes de depuración detallados. Consulte la sección Depuración de aplicaciones para más detalles.

FC_DBG_MATCH_FILTER se usa para filtrar los patrones. Acepta una lista de nombres de objetos separados por comas y solo tiene efecto cuando FC_DEBUG tiene MATCH2. Consulte la sección Depuración de aplicaciones para más detalles.

FC_LANG se usa para especificar el idioma predeterminado como el enlace débil en la consulta. Si no se establece, el idioma predeterminado se determinará a partir de la configuración regional actual.

FONTCONFIG_USE_MMAP se usa para controlar el uso de mmap(2) para los archivos de caché si está disponible. Acepta un valor booleano. fontconfig comprobará si los archivos de caché están almacenados en el sistema de archivos en el que es seguro usar mmap(2). Establecer explícitamente esta variable de entorno hará que se omita esta comprobación y se impondrá el uso o no uso de mmap(2) de todos modos.

SOURCE_DATE_EPOCH se usa para garantizar que fc-cache(1) genere archivos de manera determinista para admitir compilaciones reproducibles. Cuando se establece en una representación numérica de la marca de tiempo UNIX, fontconfig preferirá este valor sobre el uso de las marcas de tiempo de modificación de los archivos de entrada para identificar qué archivos de caché requieren regeneración. Si SOURCE_DATE_EPOCH no está establecido (o es más reciente que el mtime del directorio), el comportamiento existente no cambia.
