FOPEN(3P) Manual del Programador POSIX FOPEN(3P)

PRÓLOGO

Esta página manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fopen — abrir un flujo

SINOPSIS

#include <stdio.h>
FILE *fopen(const char *restrict pathname, const char *restrict mode);

DESCRIPCIÓN

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es involuntario. Este volumen de POSIX.1‐2017 se subordina al estándar ISO C.

La función fopen() abrirá el archivo cuyo pathname es la cadena apuntada por pathname, y asociará un flujo con él.

El argumento mode apunta a una cadena. Si la cadena es una de las siguientes, el archivo se abrirá en el modo indicado. De lo contrario, el comportamiento es indefinido.

rorb
Abrir el archivo para lectura.
wowb
Truncar a longitud cero o crear el archivo para escritura.
aoab
Anexar; abrir o crear el archivo para escritura al final del archivo.
r+orb+or+b
Abrir el archivo para actualización (lectura y escritura).
w+owb+ow+b
Truncar a longitud cero o crear el archivo para actualización.
a+oab+oa+b
Anexar; abrir o crear el archivo para actualización, escribiendo al final del archivo.

El carácter 'b' no tendrá efecto, pero se permite para la conformidad con el estándar ISO C. Abrir un archivo en modo lectura (r como el primer carácter en el argumento mode ) fallará si el archivo no existe o no se puede leer.

Abrir un archivo en modo anexar (a como el primer carácter en el argumento mode ) hará que todas las escrituras posteriores en el archivo se realicen en el final del archivo actual, independientemente de las llamadas intermedias a fseek().

Cuando un archivo se abre en modo de actualización ('+' como el segundo o tercer carácter en el argumento mode ), tanto la entrada como la salida pueden realizarse en el flujo asociado. Sin embargo, la aplicación debe asegurarse de que la salida no sea seguida directamente por la entrada sin una llamada intermedia a fflush() o a una función de posicionamiento de archivos (fseek(), fsetpos(), o rewind()), y la entrada no sea seguida directamente por salida sin una llamada intermedia a una función de posicionamiento de archivos, a menos que la operación de entrada encuentre el fin de archivo.

Cuando se abre, un flujo está completamente almacenado en búfer si y solo si se puede determinar que no se refiere a un dispositivo interactivo. Los indicadores de error y de fin de archivo del flujo se borrarán.

Si mode es w, wb, a, ab, w+, wb+, w+b, a+, ab+, o a+b, y el archivo no existía previamente, al completarse con éxito, fopen() marcará para actualización la última marca de tiempo de acceso a datos, la última marca de tiempo de modificación de datos y la última marca de tiempo de cambio de estado del archivo, y la última marca de tiempo de cambio de estado y la última marca de tiempo de modificación de datos del directorio padre.

Si mode es w, wb, a, ab, w+, wb+, w+b, a+, ab+, o a+b, y el archivo no existía previamente, la función fopen() creará un archivo como si llamara a la función creat() con un valor apropiado para el argumento path interpretado desde pathname y un valor de S_IRUSR | S_IWUSR | S_IRGRP | S_IWGRP | S_IROTH | S_IWOTH para el argumento mode .

Si mode es w, wb, w+, wb+, o w+b, y el archivo existía previamente, al completarse con éxito, fopen() marcará para actualización la última marca de tiempo de modificación de datos y la última marca de tiempo de cambio de estado del archivo.

Después de una llamada exitosa a la función fopen(), la orientación del flujo se borrará, la regla de codificación se borrará, y el objeto mbstate_t asociado se establecerá para describir un estado de conversión inicial.

El descriptor de archivo asociado con el flujo abierto se asignará y abrirá como si por una llamada a open() con los siguientes indicadores:

fopen() Modo Indicadores deopen
r o rb O_RDONLY
w o wb O_WRONLY|O_CREAT|O_TRUNC
a o ab O_WRONLY|O_CREAT|O_APPEND
r+ o rb+ o r+b O_RDWR
w+ o wb+ o w+b O_RDWR|O_CREAT|O_TRUNC
a+ o ab+ o a+b O_RDWR|O_CREAT|O_APPEND

VALOR DE RETORNO

Al completarse con éxito, fopen() devolverá un puntero al objeto que controla el flujo. De lo contrario, se devolverá un puntero nulo, y errno se establecerá para indicar el error.

ERRORES

La función fopen() fallará si:

EACCES
Se deniega el permiso de búsqueda en un componente del prefijo de la ruta, o el archivo existe y los permisos especificados por mode se deniegan, o el archivo no existe y se deniega el permiso de escritura para el directorio padre del archivo a crear.
EINTR
Se capturó una señal durante fopen().
EISDIR
El archivo nombrado es un directorio y mode requiere acceso de escritura.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path .
EMFILE
Todos los descriptores de archivo disponibles para el proceso están actualmente abiertos.
EMFILE
Hay {STREAM_MAX} flujos abiertos actualmente en el proceso que llama.
ENAMETOOLONG

La longitud de un pathname excede {PATH_MAX}, o la resolución del pathname de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.
ENFILE
El número máximo permitido de archivos está actualmente abierto en el sistema.
ENOENT
La cadena mode comienza con 'r' y un componente de pathname no nombra un archivo existente, o mode comienza con 'w' o 'a' y un componente del prefijo de la ruta de pathname no nombra un archivo existente, o pathname es una cadena vacía.
ENOENT o ENOTDIR

El argumento pathname contiene al menos un carácter que no es <barra invertida> y termina con uno o más caracteres de barra invertida finales. Si pathname sin los caracteres de barra invertida finales nombraría un archivo existente, un error [ENOENT] no ocurrirá.
ENOSPC
El directorio o sistema de archivos que contendría el nuevo archivo no se puede expandir, el archivo no existe, y el archivo iba a ser creado.
ENOTDIR
Un componente de los nombres del prefijo de la ruta es un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o el argumento pathname contiene al menos un carácter que no es <barra> y termina con uno o más caracteres de <barra> finales y el último componente de la ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.
ENXIO
El archivo nombrado es un archivo especial de caracteres o de caracteres de bloque, y el dispositivo asociado a este archivo especial no existe.
EOVERFLOW
El archivo nombrado es un archivo regular y el tamaño del archivo no puede representarse correctamente en un objeto de tipo off_t.
EROFS
El archivo nombrado reside en un sistema de archivos de solo lectura y mode requiere acceso de escritura.

La función fopen() puede fallar si:

EINVAL
El valor del argumento mode no es válido.
ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
EMFILE
Actualmente hay {FOPEN_MAX} flujos abiertos en el proceso que llama.
ENAMETOOLONG

La longitud de un componente de una ruta es mayor que {NAME_MAX}.
ENOMEM
No hay suficiente espacio de almacenamiento disponible.
ETXTBSY
El archivo es un archivo de procedimiento puro (texto compartido) que se está ejecutando y mode requiere acceso de escritura.

EJEMPLOS

Abrir un Archivo

El siguiente ejemplo intenta abrir el archivo llamado file para lectura. La función fopen() devuelve un puntero de archivo que se utiliza en las llamadas posteriores a fgets() y fclose(). Si el programa no puede abrir el archivo, simplemente lo ignora.

#include <stdio.h>
...
FILE *fp;
...
void rgrep(const char *file)
{
...
    if ((fp = fopen(file, "r")) == NULL)
        return;
...
}
