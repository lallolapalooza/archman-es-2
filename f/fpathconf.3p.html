FPATHCONF(3P) Manual del Programador POSIX FPATHCONF(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fpathconf, pathconf — obtener variables de ruta configurables

SINOPSIS

#include <unistd.h>
long fpathconf(int fildes, int name);
long pathconf(const char *path, int name);

DESCRIPCIÓN

Las funciones fpathconf() y pathconf() deben determinar el valor actual de un límite u opción configurable (variable) que está asociada con un archivo o directorio.

Para pathconf(), el argumento path apunta al nombre de ruta de un archivo o directorio.

Para fpathconf(), el argumento fildes es un descriptor de archivo abierto.

El argumento name representa la variable a consultar relativa a ese archivo o directorio. Las implementaciones deben soportar todas las variables listadas en la siguiente tabla y pueden soportar otras. Las variables en la siguiente tabla provienen de <limits.h> o <unistd.h> y las constantes simbólicas, definidas en <unistd.h>, son los valores correspondientes usados para name.

Variable Valor de name Requisitos
{FILESIZEBITS} _PC_FILESIZEBITS 4,7
{LINK_MAX} _PC_LINK_MAX 1
{MAX_CANON} _PC_MAX_CANON 2
{MAX_INPUT} _PC_MAX_INPUT 2
{NAME_MAX} _PC_NAME_MAX 3,4
{PATH_MAX} _PC_PATH_MAX 4,5
{PIPE_BUF} _PC_PIPE_BUF 6
{POSIX2_SYMLINKS} _PC_2_SYMLINKS 4
{POSIX_ALLOC_SIZE_MIN} _PC_ALLOC_SIZE_MIN 10

Requisitos

1.
Si path o fildes se refiere a un directorio, el valor devuelto debe aplicarse al directorio en sí mismo.
2.
Si path o fildes no se refiere a un archivo terminal, no se especifica si una implementación soporta una asociación del nombre de la variable con el archivo especificado.
3.
Si path o fildes se refiere a un directorio, el valor devuelto debe aplicarse a los nombres de archivo dentro del directorio.
4.
Si path o fildes no se refiere a un directorio, no se especifica si una implementación soporta una asociación del nombre de la variable con el archivo especificado.
5.
Si path o fildes se refiere a un directorio, el valor devuelto debe ser la longitud máxima de una ruta relativa que no cruzaría ningún punto de montaje cuando el directorio especificado es el directorio de trabajo.
6.
Si path se refiere a un FIFO, o fildes se refiere a una tubería o FIFO, el valor devuelto debe aplicarse al objeto referenciado. Si path o fildes se refiere a un directorio, el valor devuelto debe aplicarse a cualquier FIFO que exista o pueda crearse dentro del directorio. Si path o fildes se refiere a cualquier otro tipo de archivo, no se especifica si una implementación soporta una asociación del nombre de la variable con el archivo especificado.
7.
Si path o fildes se refiere a un directorio, el valor devuelto debe aplicarse a cualquier archivo, distinto de directorios, que exista o pueda crearse dentro del directorio.
8.
Si path o fildes se refiere a un directorio, no se especifica si una implementación soporta una asociación del nombre de la variable con el archivo especificado.
9.
Si path o fildes se refiere a un directorio, el valor devuelto debe ser la longitud máxima de la cadena que un enlace simbólico en ese directorio puede contener.
10.
Si path o fildes no se refiere a un archivo regular, no se especifica si una implementación soporta una asociación del nombre de la variable con el archivo especificado. Si una implementación soporta tal asociación para algo distinto de un archivo regular, el valor devuelto no está especificado.

VALOR DE RETORNO

Si name es un valor inválido, tanto pathconf() como fpathconf() deben devolver -1 y establecer errno para indicar el error.

Si la variable correspondiente a name está descrita en <limits.h> como un valor máximo o mínimo y la variable no tiene límite para la ruta o el descriptor de archivo, tanto pathconf() como fpathconf() deben devolver -1 sin cambiar errno. Nótese que los límites indefinidos no implican límites infinitos; véase <limits.h>.

Si la implementación necesita usar path para determinar el valor de name y la implementación no soporta la asociación de name con el archivo especificado por path, o si el proceso no tenía los privilegios apropiados para consultar el archivo especificado por path, o path no existe, pathconf() debe devolver -1 y establecer errno para indicar el error.

Si la implementación necesita usar fildes para determinar el valor de name y la implementación no soporta la asociación de name con el archivo especificado por fildes, o si fildes es un descriptor de archivo inválido, fpathconf() debe devolver -1 y establecer errno para indicar el error.

De lo contrario, pathconf() o fpathconf() deben devolver el valor actual de la variableo del archivo o directorio sin cambiar errno. El valor devuelto no debe ser más restrictivo que el valor correspondiente disponible para la aplicación cuando se compiló con los <limits.h> o <unistd.h>de la implementación.

Si la variable correspondiente a name depende de una opción no soportada, los resultados no están especificados.

ERRORES

La función pathconf() fallará si:

EINVAL
El valor de name no es válido.
EOVERFLOW
El valor de name es _PC_TIMESTAMP_RESOLUTION y la resolución es mayor que {LONG_MAX}.

La función pathconf() puede fallar si:

EACCES
Se deniega el permiso de búsqueda para un componente del prefijo de la ruta.
EINVAL
La implementación no soporta una asociación de la variable name con el archivo especificado.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path
ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path argumento.
ENAMETOOLONG

La longitud de un componente de una ruta de acceso es mayor que {NAME_MAX}.
ENAMETOOLONG

La longitud de una ruta de acceso excede {PATH_MAX}, o la resolución de la ruta de acceso de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.
ENOENT
Un componente de path no nombra un archivo existente o path es una cadena vacía.
ENOTDIR
Un componente del prefijo de la ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o el argumento path contiene al menos un carácter que no es <slash> y termina con uno o más caracteres <slash> finales, y el último componente de la ruta de acceso nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.

La función fpathconf() fallará si:

EINVAL
El valor de name no es válido.
EOVERFLOW
El valor de name es _PC_TIMESTAMP_RESOLUTION y la resolución es mayor que {LONG_MAX}.

La función fpathconf() puede fallar si:

EBADF
El argumento fildes no es un descriptor de archivo válido.
EINVAL
La implementación no soporta una asociación de la variable name con el archivo especificado.

USO DE LA APLICACIÓN

Los desarrolladores de aplicaciones deben comprobar si una opción, como _POSIX_ADVISORY_INFO, es soportada antes de obtener y usar valores para variables relacionadas como {POSIX_ALLOC_SIZE_MIN}.

JUSTIFICACIÓN

La función pathconf() se propuso inmediatamente después de la función sysconf() cuando se dio cuenta de que algunos valores configurables pueden diferir a través de los límites del sistema de archivos, el directorio o el dispositivo.

Por ejemplo, {NAME_MAX} frecuentemente cambia entre los sistemas de archivos basados en System V y BSD; System V usa un máximo de 14, BSD 255. En una implementación que proporciona ambos tipos de sistemas de archivos, una aplicación se vería obligada a limitar todos los componentes de la ruta de acceso a 14 bytes, ya que este sería el valor especificado en <limits.h> en tal sistema.

Por lo tanto, se pueden consultar varios valores útiles en cualquier ruta de acceso o descriptor de archivo, asumiendo que los privilegios adecuados están en su lugar.

El valor devuelto para la variable {PATH_MAX} indica la ruta de acceso relativa más larga que podría darse si el directorio especificado es el directorio de trabajo actual del proceso. Un proceso no siempre podrá generar un nombre tan largo y usarlo si un subdirectorio en la ruta de acceso cruza hacia un sistema de archivos más restrictivo. Nótese que las implementaciones tienen permitido aceptar rutas de acceso más largas que {PATH_MAX} bytes, pero no se les permite devolver rutas de acceso más largas que esto a menos que el usuario especifique un búfer más grande usando una función que proporcione un argumento de tamaño de búfer.

El valor devuelto para la variable _POSIX_CHOWN_RESTRICTED también se aplica a los directorios que no tienen sistemas de archivos montados en ellos. El valor puede cambiar al cruzar un punto de montaje, por lo que las aplicaciones que necesiten saberlo deben comprobarlo para cada directorio. (Una comprobación aún más fácil es intentar la función chown() y buscar un error en caso de que ocurra.)

A diferencia de los valores devueltos por sysconf(), las variables orientadas a la ruta de acceso son potencialmente más volátiles y no se garantiza que permanezcan constantes durante la vida del proceso. Por ejemplo, entre dos llamadas a pathconf(), el sistema de archivos en cuestión puede haber sido desmontado y remontado con diferentes características.

Nótese también que la mayoría de los errores son opcionales. Si una de las variables siempre tiene el mismo valor en una implementación, la implementación no necesita examinar path o fildes para devolver ese valor y, por lo tanto, no está obligada a detectar ninguno de los errores excepto el significado de [EINVAL] que indica que el valor de name no es válido para esa variable, y el error [EOVERFLOW] que indica que el valor a devolver es mayor que {LONG_MAX}.

Si el valor de cualquiera de los límites no está especificado (lógicamente infinito), no se definirán en <limits.h> y las funciones pathconf() y fpathconf() devolverán -1 sin cambiar errno. Esto se puede distinguir del caso de dar un argumento name no reconocido porque errno se establece en [EINVAL] en este caso.

Dado que -1 es un valor de retorno válido para las funciones pathconf() y fpathconf(), las aplicaciones deben establecer errno a cero antes de llamarlas y comprobar errno solo si el valor de retorno es -1.

Para el caso de {SYMLINK_MAX}, ya que tanto pathconf() como open() siguen enlaces simbólicos, no hay forma de que path o fildes puedan referirse a un enlace simbólico.

Fue la intención de IEEE Std 1003.1d‐1999 que las siguientes variables:

{POSIX_ALLOC_SIZE_MIN} {POSIX_REC_INCR_XFER_SIZE} {POSIX_REC_MAX_XFER_SIZE} {POSIX_REC_MIN_XFER_SIZE} {POSIX_REC_XFER_ALIGN}

solo se aplicaran a archivos regulares, pero la Nota 10 también permite la implementación de la semántica asesorada en otros tipos de archivos únicos de una implementación (por ejemplo, un dispositivo especial de caracteres).

El error [EOVERFLOW] para _PC_TIMESTAMP_RESOLUTION no puede ocurrir en sistemas de archivos compatibles con POSIX porque POSIX requiere una resolución de marca de tiempo no mayor que un segundo. Incluso en sistemas de 32 bits, esto puede representarse sin desbordamiento.
