fp(1) Entorno de desarrollo integrado de Free Pascal fp(1)

NOMBRE

fp - Entorno de desarrollo integrado del compilador Free Pascal (FPC)

SINOPSIS

fp [opciones] [archivo_fuente]

DESCRIPCIÓN

Este binario es el entorno de desarrollo integrado del compilador Free Pascal (FPC), que es un compilador Pascal multitarget avanzado compatible con Turbo Pascal y Delphi (7.0). El motor del compilador no se basa en GCC, sino que es completamente independiente.

El compilador utiliza LD(1) y puede usar AS(1) (ver el parámetro -Aas), pero también tiene su propio escritor de objetos binarios.

Los objetivos principales actuales son Go32V2 (extensor DJGPP para Dos), Freebsd, Linux, MacOS, MacOSX, MorphOS, Netware, OS/2 y Win32. Los otros objetivos (compiladores M68K para Atari y Amiga) se basan en versiones anteriores del compilador o aún están en desarrollo.

Esta página del manual tiene fines de referencia rápida únicamente. FPC viene con un manual extenso (más de 2000 páginas), que se actualiza constantemente, mientras que esta página del manual puede estar desactualizada.

USO

La interfaz de usuario del IDE ha sido diseñada para ser similar a la de Turbo Pascal. Proporciona al usuario un editor amigable pero bastante potente, un extenso sistema de ayuda en línea y un depurador.

Un sistema de ventanas en modo texto es la base de la interfaz de usuario. El ratón es compatible, pero la mayoría de la gente usará el teclado. El usuario normalmente abrirá algunas ventanas de editor de texto en las que diseñará su programa, durante lo cual podrá verificar y depurar regularmente mediante teclas de acceso rápido. La alta velocidad del compilador garantiza que los programadores puedan hacer esto con frecuencia y, por lo tanto, permite un desarrollo rápido de código.

ARCHIVOS DE AYUDA

No se proporcionan archivos de ayuda por defecto. El usuario debe descargar la documentación de Free Pascal en formato HTML e instalarla en el IDE utilizando el menú Ayuda->Archivos. Los archivos .tph de Turbo Pascal también se pueden instalar en este menú y pueden ser útiles para el código fuente que se distribuye con archivos .tph como documentación.

JUEGOS DE CARACTERES

El IDE ha sido diseñado para fuentes de modo de texto VGA. Estas fuentes permiten modos de texto visualmente más interesantes que las fuentes VT100 utilizadas normalmente en sistemas Unix y también son más portátiles, ya que la mayoría de los sistemas operativos utilizan conjuntos de caracteres VGA para sus modos de texto.

Al ejecutarse en una terminal compatible con VT100, ocurrirá cierta emulación. Internamente, el IDE pensará que se está ejecutando con una fuente de modo de texto VGA (muy probablemente la página de códigos 850), mientras que todos los caracteres serán (en el caso de la página de códigos 850) convertidos a Latin-1 y caracteres del conjunto de caracteres alternativo VT100.

La consola de Linux puede usar fuentes VGA y, por lo tanto, el IDE se puede ver como se diseñó originalmente. El modo de consola de Linux admite todo el conjunto de caracteres VGA a través de los dispositivos /dev/vcsa* y la mayor parte a través de secuencias de escape normales. Para evitar malas experiencias de usuario, el IDE ha sido diseñado para ser bastante agresivo en el uso de conjuntos de caracteres VGA. Primero determinará el número de consola real en el que se está ejecutando (incluso si se ejecuta en una pty, como en Midnight Commander). Luego, el IDE abrirá el dispositivo /dev/vcsa* perteneciente a esa consola. Si se deniega el permiso, el IDE llamará a la utilidad grab_vcsa, que es una utilidad setuid root que otorgará permisos al dispositivo vcsa.

En caso de que el dispositivo vcsa no esté disponible, el IDE enviará códigos de escape para habilitar la fuente VGA. En este modo, faltan pocos caracteres en las 32 posiciones ASCII bajas, pero principalmente porque el conjunto completo de caracteres de dibujo de líneas está disponible, el usuario notará pocas diferencias.

El dispositivo de framebuffer de Linux y el IDE de Free Pascal son una combinación excelente. Con fbdev es posible utilizar resoluciones de modo de texto superiores a las 80x25 normales, lo que permite al programador ver mucho más código a la vez.

La consola de Linux permite al usuario cargar fuentes definidas por el usuario. Si hace esto, dicha fuente debe tener un diseño de estilo VGA, es decir, página de códigos 437/850/... (Tenga en cuenta que esto no significa que su sistema de archivos deba usar dicha codificación, la consola de Linux maneja la conversión de ISO-8859-1, UTF-8 o lo que sea a la fuente). Dado que las fuentes predeterminadas tienen un diseño de página de códigos 437, solo los usuarios que han experimentado con fuentes tendrán que tener cuidado aquí.

El IDE reconoce la variable de entorno CONSOLEFONT_CP en la que puede especificar la página de códigos de la fuente de la consola. Los valores reconocidos actualmente son "cp437" y "cp850". Si no establece esta variable, se asumirá la página de códigos 437. Actualmente, si usa la página de códigos 850 sin establecer la variable, no habrá un gran impacto en este momento, los caracteres que utiliza el IDE existen en ambas páginas de códigos.

Nota: Las fuentes KOI8-R/KOI8-U tienen todos los caracteres requeridos, pero los caracteres de dibujo de líneas no están en las posiciones correctas. Podemos admitir esto en el futuro, pero actualmente no lo hacemos.

TECLADO

El manejo del teclado en Unix es un asunto complicado porque no todas las combinaciones de teclas generan códigos de escape, diferentes emuladores de terminal generan diferentes códigos de escape y algunas combinaciones de teclas pueden activar acciones en el gestor de ventanas de X11.

Dado que la interfaz de usuario del IDE de Free Pascal está diseñada para ser similar a la de Turbo Pascal, incluidos los comandos del teclado, puede experimentar una de las situaciones anteriores. Se han agregado algunas teclas alternativas y quizás se necesiten agregar más en el futuro.

Al ejecutarse en la consola de Linux, el teclado se reprograma para una funcionalidad completa.

Aquí hay algunos problemas comunes que puede encontrar y posibles soluciones:

Problema: La selección de texto con las teclas shift+flecha no funciona.

Solución: Usa el ratón

Solución: Usa "ctrl+k b" para marcar el inicio del bloque, "ctrl+k e" para marcar el final del bloque, "ctrl+k h" para ocultar el bloque.

Problema: Las teclas de Cortar/Copiar/Pegar no funcionan.

Solución: Ve a Opciones->Entorno->Teclado y ratón y habilita las teclas de Cortar/Copiar/Pegar estilo Microsoft.

Solución: Usa la barra de menú.

Problema: La tecla Alt no funciona.

Solución: Presiona Escape primero, luego la tecla sin alt. Ten en cuenta que esto no es posible en la consola de Linux, pero la tecla Alt funciona allí.

Si por alguna razón el teclado reprogramado de la consola de Linux no se restaura a su estado original después de salir (¿un bloqueo del IDE?), puede hacer algo como "/etc/init.d/kbd start" para reprogramarlo a su comportamiento normal.
