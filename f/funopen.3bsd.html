funopen(3bsd)

Paquete: libbsd

Licencias: custom

funopen(3bsd) 3bsd funopen(3bsd)

NOMBRE

funopen, fropen, fwopen — abrir un flujo

BIBLIOTECA

biblioteca “libbsd”

SINOPSIS

#include <stdio.h> (Ver libbsd(7) para el uso de la inclusión.)
FILE *
funopen(const void *cookie, int (*readfn)(void *, char *, int), int (*writefn)(void *, const char *, int), off_t (*seekfn)(void *, off_t, int), int (*closefn)(void *));

FILE *
fropen(void *cookie, int (*readfn)(void *, char *, int));

FILE *
fwopen(void *cookie, int (*writefn)(void *, const char *, int));

DESCRIPCIÓN

La función funopen() asocia un flujo con hasta cuatro “funciones de E/S I/O”. Se debe especificar readfn o writefn; los otros pueden proporcionarse como un puntero NULL del tipo apropiado. Estas funciones de E/S se utilizarán para leer, escribir, buscar y cerrar el nuevo flujo.

En general, omitir una función significa que cualquier intento de realizar la operación asociada en el flujo resultante fallará. Si se omite la función de cierre, el cierre del flujo vaciará cualquier salida almacenada en búfer y luego tendrá éxito.

Las convenciones de llamada de readfn, writefn, seekfn y closefn deben coincidir con las de read(2), write(2), lseek(2) y close(2) respectivamente, con la única excepción de que se les pasa el argumento cookie especificado a funopen() en lugar del argumento tradicional de descriptor de archivo.

Las funciones de E/S de lectura y escritura pueden cambiar el búfer subyacente en flujos completamente almacenados en búfer o con búfer de línea llamando a setvbuf(3). Tampoco están obligadas a llenar o vaciar completamente el búfer. Sin embargo, no se les permite cambiar los flujos de sin búfer a con búfer ni cambiar el estado del indicador de búfer de línea. También deben estar preparadas para que se produzcan llamadas de lectura o escritura en búferes distintos al especificado más recientemente.

Todas las funciones de E/S de usuario pueden informar de un error devolviendo -1. Además, todas las funciones deben establecer la variable externa errno apropiadamente si ocurre un error.

Un error en closefn() no mantiene el flujo abierto.

Como conveniencia, el archivo de inclusión <stdio.h> define las macros fropen() y fwopen() como llamadas a funopen() con solo una función de lectura o escritura especificada.

VALORES DE RETORNO

Al completarse con éxito, funopen() devuelve un puntero FILE. De lo contrario, se devuelve NULL y la variable global errno se establece para indicar el error.

ERRORES

[EINVAL]
La función funopen() se llamó sin una función de lectura o escritura. La función funopen() también puede fallar y establecer errno para cualquiera de los errores especificados para la rutina malloc(3).

VER TAMBIÉN

fcntl(2), open(2), fclose(3), fopen(3), fseek(3), setbuf(3)

HISTORIA

Las funciones funopen() aparecieron por primera vez en 4.4BSD.

ERRORES

La función funopen() podría no ser portable a sistemas distintos de BSD y los basados en glibc y musl (ya que la implementación de libbsd solo se proporciona cuando el sistema tiene fopencookie() disponible).

En FreeBSD, OpenBSD y DragonFly, la interfaz funopen() asume erróneamente que fpos_t es un tipo integral y lo utiliza en el hook seekfn; pero dado que el código que utiliza un hook seekfn fallará al compilarse en sistemas donde fpos_t es una struct, y de todos modos necesitará ser corregido ligeramente, la implementación proporcionada por libbsd (de la misma manera que NetBSD) utiliza los tipos off_t correctos.
