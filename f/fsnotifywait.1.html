NOMBRE

inotifywait, fsnotifywait - esperar cambios en archivos usando inotify o fanotify

SINOPSIS

inotifywait [-hcmrPqIFS] [-e <evento> ] [-t <segundos> ] [--format <fmt> ] [--timefmt <fmt> ] <archivo> [ ... ]

fsnotifywait [-hcmrPqIFS] [-e <evento> ] [-t <segundos> ] [--format <fmt> ] [--timefmt <fmt> ] <archivo> [ ... ]

DESCRIPCIÓN

inotifywait espera eficientemente cambios en archivos usando la interfaz inotify(7) de Linux por defecto. Es adecuado para esperar cambios en archivos desde scripts de shell. Puede salir una vez que ocurre un evento, o ejecutarse continuamente y mostrar los eventos a medida que ocurren.

fsnotifywait es similar a inotifywait pero usa la interfaz fanotify(7) de Linux por defecto. Si se especifica explícitamente, usa la interfaz inotify(7).

SALIDA

inotifywait y fsnotifywait mostrarán información de diagnóstico en la salida estándar de error y información de eventos en la salida estándar. La salida de eventos puede ser configurada, pero por defecto consiste en líneas de la siguiente forma:

nombre_archivo_visto NOMBRES_EVENTO nombre_archivo_evento

nombre_archivo_visto
es el nombre del archivo en el que ocurrió el evento. Si el archivo es un directorio, se muestra una barra final.
NOMBRES_EVENTO
son los nombres de los eventos de inotify que ocurrieron, separados por comas.
nombre_archivo_evento
se muestra solo cuando el evento ocurrió en un directorio, y en este caso se muestra el nombre del archivo dentro del directorio que causó este evento.

Por defecto, los caracteres especiales en los nombres de archivo no se escapan de ninguna manera. Esto puede hacer que la salida de inotifywait sea difícil de parsear en scripts de awk o similares. Las opciones --csv y --format serán útiles en este caso.

OPCIONES

-h, --help
Muestra información de ayuda útil.
@<archivo>
Al observar un árbol de directorios recursivamente, excluye el archivo especificado de ser observado. El archivo debe especificarse con una ruta relativa o absoluta según si se da una ruta relativa o absoluta para los directorios observados. Si una ruta específica se incluye y excluye explícitamente, siempre será observada.

Nota: Si necesita observar un directorio o archivo cuyo nombre comience con @, proporcione la ruta absoluta.

--desdearchivo <archivo>
Lee los nombres de archivo a observar o excluir de un archivo, un nombre de archivo por línea. Si los nombres de archivo comienzan con @ se excluyen como se describe arriba. Si <archivo> es `-', los nombres de archivo se leen de la entrada estándar. Usa esta opción si necesitas observar demasiados archivos para pasarlos como argumentos de línea de comandos.
-m, --monitor
En lugar de salir después de recibir un solo evento, ejecútate indefinidamente. El comportamiento por defecto es salir después de que ocurra el primer evento.
-d, --daemon
Igual que --monitor, excepto que se ejecuta en segundo plano registrando eventos en un archivo que debe ser especificado por --outfile. Implica --syslog.
-o, --outfile <archivo>
Muestra los eventos en <archivo> en lugar de stdout.
-s, --syslog
Muestra los errores en el módulo de registro del sistema syslog(3) en lugar de stderr.
-P, --no-dereference
No seguir enlaces simbólicos.
-r, --recursive
Observa todos los subdirectorios de cualquier directorio pasado como argumento. Las observaciones se establecerán recursivamente a una profundidad ilimitada. Los enlaces simbólicos no se recorrerán. Los subdirectorios recién creados también serán observados.

Advertencia: Si usa esta opción al observar el directorio raíz de un árbol grande, puede tardar bastante en establecer todas las observaciones de inotify, y no se recibirán eventos durante este tiempo. Además, dado que se establecerá una observación de inotify por subdirectorio, es posible que se alcance la cantidad máxima de observaciones de inotify por usuario. El máximo por defecto es 8192; se puede incrementar escribiendo en /proc/sys/fs/inotify/max_user_watches.

-q, --quiet
Si se especifica una vez, el programa será menos detallado. Específicamente, no indicará cuándo ha terminado de establecer todas las observaciones de inotify.

Si se especifica dos veces, el programa no mostrará nada, excepto en caso de errores fatales.

--excluir <patrón>
No procesar ningún evento para el subconjunto de archivos cuyos nombres coincidan con la expresión regular POSIX especificada, sensible a mayúsculas/minúsculas.
--excluiri <patrón>
No procesar ningún evento para el subconjunto de archivos cuyos nombres coincidan con la expresión regular POSIX especificada, insensible a mayúsculas/minúsculas.
--incluir <patrón>
Procesar eventos solo para el subconjunto de archivos cuyos nombres coincidan con la expresión regular POSIX especificada, sensible a mayúsculas/minúsculas. Cuando se usa con --recursive, los eventos se seguirán generando para archivos coincidentes dentro de directorios recién creados, incluso si los nombres de los directorios mismos no coinciden con el patrón.
--incluiri <patrón>
Procesar eventos solo para el subconjunto de archivos cuyos nombres coincidan con la expresión regular POSIX especificada, insensible a mayúsculas/minúsculas.
-t <segundos>, --timeout <segundos>
Salir si no ha ocurrido un evento apropiado dentro de <segundos> segundos. Si <segundos> es cero (el valor por defecto), esperar indefinidamente por un evento.
-e <evento>, --event <evento>
Escuchar solo eventos específicos. Los eventos para los que se puede escuchar se enumeran en la sección EVENTOS. Esta opción se puede especificar más de una vez. Si se omite, se escuchan todos los eventos.
-c, --csv
Mostrar en formato CSV (valores separados por comas). Esto es útil cuando los nombres de archivo pueden contener espacios, ya que en este caso no es seguro simplemente dividir la salida en cada carácter de espacio.
--timefmt <fmt>
Establecer una cadena de formato de tiempo aceptada por strftime(3) para usar con la conversión `%T' en la opción --format.
--no-newline
No imprimir el símbolo de nueva línea después del formato especificado por el usuario en la opción --format.
--format <fmt>
Mostrar en un formato especificado por el usuario, usando sintaxis similar a printf. Las cadenas de evento mostradas se limitan a aproximadamente 4000 caracteres y se truncarán a esta longitud. Las siguientes conversiones son compatibles:
%w
Se reemplazará con el nombre del archivo observado en el que ocurrió un evento. Cuando ocurre un evento dentro de un directorio observado o al observar con fanotify, se reemplazará con el nombre del directorio en el que ocurrió el evento.
%f
Cuando ocurre un evento dentro de un directorio observado o al observar con fanotify, se reemplazará con el nombre del archivo que causó que ocurriera el evento. De lo contrario, se reemplazará con una cadena vacía.
%e
Se reemplazará con el(los) Evento(s) que ocurrieron, separados por comas.
%Xe
Se reemplazará con el(los) Evento(s) que ocurrieron, separados por el carácter que i

NAME

inotifywait - wait for events on directories/files, print them, and exit

SYNOPSIS

inotifywait [options] [file/directory ... ]

DESCRIPTION

inotifywait is a command-line utility that is designed to be simple and easy to use. It takes flags to indicate which events to listen for, and then returns when one of the specified events occurs on any of the specified files or directories.

inotifywait was started by Rohan McGovern and is currently maintained by Eric Curtin and Radu Voicilas.

OUTPUT

By default, each line of output corresponds to one event and consists of the filename that the event occurred on, followed by the event name(s), separated by spaces. The filename is relative to the directory being watched. If the event occurred on a watched directory itself, then no filename is printed.

If multiple events occur in quick succession, they may be printed on the same line. The events will be separated by commas.

The format of the output can be changed using the --format option.

%e
Replaced with the event name(s).
%f
Replaced with the name of the file which caused the event. This is only relevant if the event occurred within a watched directory. If the event occurred on the directory itself (e.g. a delete_self event), then the filename is empty.
%w
Replaced with the name of the file or directory being watched.
%x
Replaced with the file descriptor number of the watched file or directory.
%T
Replaced with the current Time in the format specified by the --timefmt option, which should be a format string suitable for passing to strftime(3).
%0
Replaced with NUL.
%n
Replaced with Line Feed.

OPTIONS

-I, --inotify
Watch using inotify (default for inotifywait).
-F, --fanotify
-S, --filesystem
Watch entire filesystem of any directories passed as arguments using fanotify.

EXIT STATUS

0
The program executed successfully, and an event occurred which was being listened for.
1
An error occurred in execution of the program, or an event occurred which was not being listened for. The latter generally occurs if something happens which forcibly removes the inotify watch, such as a watched file being deleted or the filesystem containing a watched file being unmounted.
2
The -t option was used and an event did not occur in the specified interval of time.

EVENTS

The following events are valid for use with the -e option:

access
A watched file or a file within a watched directory was read from.
modify
A watched file or a file within a watched directory was written to.
attrib
The metadata of a watched file or a file within a watched directory was modified. This includes timestamps, file permissions, extended attributes etc.
close_write
A watched file or a file within a watched directory was closed, after being opened in writable mode. This does not necessarily imply the file was written to.
close_nowrite
A watched file or a file within a watched directory was closed, after being opened in read-only mode.
close
A watched file or a file within a watched directory was closed, regardless of how it was opened. Note that this is actually implemented simply by listening for both close_write and close_nowrite, hence all close events received will be output as one of these, not CLOSE.
open
A watched file or a file within a watched directory was opened.
moved_to
A file or directory was moved into a watched directory. This event occurs even if the file is simply moved from and to the same directory.
moved_from
A file or directory was moved from a watched directory. This event occurs even if the file is simply moved from and to the same directory.
move
A file or directory was moved from or to a watched directory. Note that this is actually implemented simply by listening for both moved_to and moved_from, hence all move events received will be output as one or both of these, not MOVE.
move_self
A watched file or directory was moved. After this event, the file or directory is no longer being watched.
create
A file or directory was created within a watched directory.
delete
A file or directory within a watched directory was deleted.
delete_self
A watched file or directory was deleted. After this event the file or directory is no longer being watched. Note that this event can occur even if it is not explicitly being listened for.
unmount
The filesystem on which a watched file or directory resides was unmounted. After this event the file or directory is no longer being watched. Note that this event can occur even if it is not explicitly being listened to.

EXAMPLES

Example 1

Running inotifywait at the command-line to wait for any file in the `test' directory to be accessed. After running inotifywait, `cat test/foo' is run in a separate console.

% inotifywait test
Setting up watches.
Watches established.
test/ ACCESS foo

Example 2

A short shell script to efficiently wait for httpd-related log messages and do something appropriate.

#!/bin/sh
while ! inotifywait -e modify /var/log/messages; do
  if tail -n1 /var/log/messages | grep httpd; then
    kdialog --msgbox "Apache needs love!"
  fi
done

Example 3

A custom output format is used to watch `~/test'. Meanwhile, someone runs `touch ~/test/badfile; touch ~/test/goodfile; rm ~/test/badfile' in another console.

% inotifywait -m -r --format '%:e %f' ~/test
Setting up watches.  Beware: since -r was given, this may take a while!
Watches established.
CREATE badfile
OPEN badfile
ATTRIB badfile
CLOSE_WRITE:CLOSE badfile
CREATE goodfile
OPEN goodfile
ATTRIB goodfile
CLOSE_WRITE:CLOSE goodfile
DELETE badfile

Example 4

Enforce file permissions in directory `~/test'

inotifywait -qmr -e 'moved_to,create' --format '%w%f%0' --no-newline ~/test |\
    while IFS= read -r -d '' file
    do
	  chmod -v a+rX "$file"
    done

CAVEATS

When using inotifywait, the filename that is outputted is not guaranteed to be up to date after a move because it is the inode that is being monitored. Additionally, none of the observed operations are guaranteed to have been performed on the filename inotifywait was instructed to monitor in cases when the file is known by several names in the filesystem.

BUGS

There are race conditions in the recursive directory watching code which can cause events to be missed if they occur in a directory immediately after that directory is created. This is probably not fixable.

It is assumed the inotify event queue will never overflow.
