NOMBRE

fts, fts_open, fts_read, fts_children, fts_set, fts_close - recorrer una jerarquía de archivos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/types.h>
#include <sys/stat.h>
#include <fts.h>
FTS *fts_open(char *const *path_argv, int options,
              typeof(int (const FTSENT **, const FTSENT **))
                  *_Nullable compar);
FTSENT *fts_read(FTS *ftsp);
FTSENT *fts_children(FTS *ftsp, int instr);
int fts_set(FTS *ftsp, FTSENT *f, int instr);
int fts_close(FTS *ftsp);

DESCRIPCIÓN

Las funciones fts se proporcionan para recorrer jerarquías de archivos. Una descripción general simple es que la función fts_open() devuelve un "manejador" (de tipo FTS *) que se refiere a un flujo de jerarquía de archivos. Este manejador se suministra luego a las otras funciones fts. La función fts_read() devuelve un puntero a una estructura que describe uno de los archivos en la jerarquía de archivos. La función fts_children() devuelve un puntero a una lista enlazada de estructuras, cada una de las cuales describe uno de los archivos contenidos en un directorio de la jerarquía.

En general, los directorios se visitan dos veces distinguibles; en preorden (antes de que se visiten sus descendientes) y en postorden (después de que se hayan visitado todos sus descendientes). Los archivos se visitan una vez. Es posible recorrer la jerarquía "lógicamente" (visitando los archivos a los que apuntan los enlaces simbólicos) o físicamente (visitando los enlaces simbólicos en sí), ordenar el recorrido de la jerarquía o podar y/o volver a visitar porciones de la jerarquía.

Se definen dos estructuras (y tipos asociados) en el archivo de inclusión <fts.h>. El primer tipo es FTS, la estructura que representa la jerarquía de archivos en sí. El segundo tipo es FTSENT, la estructura que representa un archivo en la jerarquía de archivos. Normalmente, se devuelve una estructura FTSENT por cada archivo en la jerarquía de archivos. En esta página del manual, "archivo" y "estructura FTSENT" son generalmente intercambiables.

La estructura FTSENT contiene campos que describen un archivo. La estructura contiene al menos los siguientes campos (hay campos adicionales que deben considerarse privados de la implementación):


typedef struct _ftsent {
    unsigned short  fts_info;     /* flags para la estructura FTSENT */
    char           *fts_accpath;  /* ruta de acceso */
    char           *fts_path;     /* ruta raíz */
    short           fts_pathlen;  /* strlen(fts_path) +
                                     strlen(fts_name) */
    char           *fts_name;     /* nombre de archivo */
    short           fts_namelen;  /* strlen(fts_name) */
    short           fts_level;    /* profundidad (-1 a N) */
    int             fts_errno;    /* errno del archivo */
    long            fts_number;   /* valor numérico local */
    void           *fts_pointer;  /* valor de dirección local */
    struct _ftsent *fts_parent;   /* directorio padre */
    struct _ftsent *fts_link;     /* siguiente estructura de archivo */
    struct _ftsent *fts_cycle;    /* estructura de ciclo */
    struct stat    *fts_statp;    /* información de [l]stat(2) */
} FTSENT;

Estos campos se definen de la siguiente manera:

fts_info
Uno de los siguientes valores que describen la estructura FTSENT devuelta y el archivo que representa. Con la excepción de los directorios sin errores (FTS_D), todas estas entradas son terminales, es decir, no se volverán a visitar, ni se visitarán ninguno de sus descendientes.
FTS_D
Un directorio que se visita en preorden.
FTS_DC
Un directorio que causa un ciclo en el árbol. (El campo fts_cycle de la estructura FTSENT también se rellenará).
FTS_DEFAULT
Cualquier estructura FTSENT que represente un tipo de archivo no descrito explícitamente por uno de los otros valores de fts_info.
FTS_DNR
Un directorio que no se puede leer. Esta es una devolución de error, y el campo fts_errno se establecerá para indicar qué causó el error.
FTS_DOT
Un archivo llamado "." o ".." que no se especificó como nombre de archivo para fts_open() (ver FTS_SEEDOT).
FTS_DP
Un directorio que se visita en postorden. El contenido de la estructura FTSENT no cambiará desde cuando se devolvió en preorden, es decir, con el campo fts_info establecido en FTS_D.
FTS_ERR
Esta es una devolución de error, y el campo fts_errno se establecerá para indicar qué causó el error.
FTS_F
Un archivo regular.
FTS_NS
Un archivo para el cual no había información de [l]stat(2) disponible. El contenido del campo fts_statp no está definido. Esta es una devolución de error, y el campo fts_errno se establecerá para indicar qué causó el error.
FTS_NSOK
Un archivo para el cual no se solicitó información de [l]stat(2). El contenido del campo fts_statp no está definido.
FTS_SL
Un enlace simbólico.
FTS_SLNONE
Un enlace simbólico con un objetivo inexistente. El contenido del campo fts_statp hace referencia a la información de características del archivo para el propio enlace simbólico.
fts_accpath
Una ruta para acceder al archivo desde el directorio actual.
fts_path
La ruta del archivo relativa a la raíz del recorrido. Esta ruta contiene la ruta especificada a fts_open() como prefijo.
fts_pathlen
La suma de las longitudes de las cadenas a las que hacen referencia fts_path y fts_name.
fts_name
El nombre del archivo.
fts_namelen
La longitud de la cadena a la que hace referencia fts_name.
fts_level
La profundidad del recorrido, numerada de -1 a N, donde se encontró este archivo. La estructura FTSENT que representa al padre del punto de inicio (o raíz) del recorrido tiene el número -1, y la estructura FTSENT para la raíz en sí tiene el número 0.
fts_errno
Si fts_children() o fts_read() devuelve una estructura FTSENT cuyo campo fts_info está establecido en FTS_DNR, FTS_ERR o FTS_NS, el campo fts_errno contiene el número de error (es decir, el valor de errno) que especifica el error. De lo contrario, el contenido del campo fts_errno no está definido.
fts_number
Este campo se proporciona para el uso del programa de aplicación y no es modificado por las funciones fts. Se inicializa a 0.
fts_pointer
Este campo se proporciona para el uso del programa de aplicación y no es modificado por las funciones fts. Se inicializa a NULL.
fts_parent
Un puntero a la estructura FTSENT que hace referencia al archivo en la jerarquía inmediatamente anterior al archivo actual, es decir, el directorio del cual este archivo es miembro. También se proporciona una estructura padre para el punto de entrada inicial; sin embargo, solo los campos fts_level, fts_number y fts_pointer están garantizados para ser inicializados.
fts_link
Un puntero a la siguiente estructura FTSENT en la lista enlazada de archivos del directorio padre.
fts_cycle
Si el campo fts_info es FTS_DC, este campo apunta a la estructura FTSENT de la entrada del directorio que causó el ciclo. De lo contrario, este campo no está definido.
fts_statp
Un puntero a una estructura stat que contiene información sobre el archivo. Si se especifica la opción FTS_PHYS para fts_open(), esta información se obtiene mediante una llamada a stat(2). Si se especifican las opciones FTS_LOGICAL o FTS_COM L, la información se obtiene mediante una llamada a lstat(2). Si se especifica la opción FTS_COM, esta información se obtiene mediante una llamada a stat(2). Si se solicita información sobre enlaces simbólicos que no existen, la información obtenida será para el enlace simbólico en sí.

Los parámetros de la función son los siguientes:

fts_open()
El parámetro path_argv es una matriz de cadenas que representan las raíces de los recorridos del sistema de archivos. Si path_argv es NULL, se utiliza el directorio actual. El parámetro options es una máscara de bits ORed de las siguientes opciones:
FTS_ARCHIVE
Este modo está destinado a la creación de archivos. Por defecto, las estructuras FTSENT se devuelven en el orden correcto para ser escritas directamente en un archivo. Cuando se utiliza esta opción, se ignoran los enlaces simbólicos y se tratan como archivos regulares.
FTS_COM
Leer los archivos de forma lógica. El significado de esta opción es la misma que la de la opción FTS_LOGICAL.
FTS_CURRENT
Si se encuentra un enlace simbólico que apunta a un directorio existente, la entrada del enlace simbólico se colocará en la secuencia de recorrido después de la entrada del directorio al que apunta.
FTS_DEM apel
Si se encuentra un archivo o directorio para el cual el programa no tiene permiso para leerlo, y la opción FTS_NOSTAT no se ha establecido, se realizarán los intentos de leerlo de todos modos.
FTS_DIRONLY
Este es un modo de sólo lectura de directorios. Los archivos regulares se saltarán, y las entradas de enlaces simbólicos que apuntan a archivos se omitirán.
FTS_DONTCHDIR
No cambiar de directorio. La función de recorrido de archivos no cambiará de directorio durante la ejecución. Esto significa que fts_accpath siempre contendrá la ruta completa al archivo.
FTS_FLAG1
La definición de esta bandera se deja en blanco para su uso posterior por parte del usuario.
FTS_FOLLOW
La definición de esta bandera se deja en blanco para su uso posterior por parte del usuario.
FTS_LOGICAL
Seguir enlaces simbólicos. Por defecto, los enlaces simbólicos se siguen físicamente (es decir, el enlace simbólico en sí se visita). Si se especifica esta opción, los enlaces simbólicos se siguen lógicamente (es decir, se visita el archivo al que apunta el enlace simbólico).
FTS_NOCHDIR
Este es un sinónimo de la opción FTS_DONTCHDIR.
FTS_NO nlink
No seguir enlaces.
FTS_NO nsort
No ordenar los descendientes de un directorio.
FTS_NOSTAT
No obtener la información del stat. Si se especifica esta opción, las funciones fts no obtendrán la información de estado de los archivos. Esto puede ser útil si el programa de aplicación ya tiene la información del estado, o si solo está interesado en los nombres de los archivos.
FTS_PHYS
Seguir enlaces simbólicos físicamente. Esta es la opción por defecto.
FTS_PRUNE
No entrar en un directorio. Si se encuentra un directorio que el programa no desea visitar, se puede establecer la bandera fts_instr a FTS_PRUNE para evitar que la función fts_read() entre en él.
FTS_ROOTONLY
Tratar sólo las raíces. Esto significa que solo se devolverán las entradas de nivel superior especificadas en path_argv. No se recorrerán los directorios contenidos en estas raíces.
FTS_SEEDOT
Incluir "." y "..". Por defecto, estos directorios se omitirán. Si se especifica esta opción, se incluirán.
FTS_XDEV
No seguir las divisiones de sistemas de archivos. Por defecto, las funciones fts cruzarán los límites del sistema de archivos. Si se especifica esta opción, las funciones fts no cruzarán los límites del sistema de archivos.
fts_read()
El parámetro ftsp es el manejador devuelto por fts_open(). Esta función devuelve un puntero a una estructura FTSENT que representa el siguiente archivo en la jerarquía. Si se ha alcanzado el final de la jerarquía, o si se ha producido un error, se devuelve NULL. En caso de error, el campo fts_errno de la estructura devuelta contendrá el número de error.
fts_children()
El parámetro ftsp es el manejador devuelto por fts_open(). El parámetro instr es opcional y puede utilizarse para establecer instrucciones para el primer nivel de la jerarquía.
fts_set()
El parámetro ftsp es el manejador devuelto por fts_open(). El parámetro f es un puntero a la estructura FTSENT a la que se aplicará la instrucción. El parámetro instr es una máscara de bits ORed de las siguientes instrucciones:
FTS_FORCE
Forzar la entrada. Esto se utiliza para obtener información de stat para un archivo al que normalmente se omitiría (por ejemplo, un enlace simbólico a un directorio).
FTS_PRUNE
No entrar en un directorio. Si se llama a esta función en una entrada de directorio, el recorrido no entrará en ese directorio.
FTS_SKIP
Omitir un archivo. Si se llama a esta función en una entrada de archivo, esa entrada y todos sus descendientes serán omitidos del recorrido.
fts_close()
El parámetro ftsp es el manejador devuelto por fts_open(). Esta función libera todos los recursos asociados con el recorrido del sistema de archivos.

fts_open(

)

La función fts_open() toma un puntero a un array de punteros a caracteres que nombran uno o más caminos que componen una jerarquía lógica de archivos a recorrer. El array debe estar terminado por un puntero

nulo.

Hay una serie de opciones, de las cuales al menos una (ya sea FTS_LOGICAL o FTS_PHYSICAL) debe ser especificada. Las opciones se seleccionan aplicando el operador OR a los siguientes

valores:
FTS_LOGIC
AL
Esta opción hace que las rutinas fts devuelvan estructuras FTSENT para los destinos de los enlaces simbólicos en lugar de los propios enlaces simbólicos. Si esta opción está activada, los únicos enlaces simbólicos para los que se devuelven estructuras FTSENT a la aplicación son aquellos que hacen referencia a archivos inexistentes: el campo fts_statp se obtiene a través de stat(2) con un recurso de respaldo a lstat(
2).
FTS_PHYSIC
AL
Esta opción hace que las rutinas fts devuelvan estructuras FTSENT para los propios enlaces simbólicos en lugar de los archivos de destino a los que apuntan. Si esta opción está activada, se devuelven a la aplicación estructuras FTSENT para todos los enlaces simbólicos en la jerarquía: el campo fts_statp se obtiene a través de lstat(
2).
FTS_COMFOLL
OW
Esta opción hace que cualquier enlace simbólico especificado como una ruta raíz sea seguido inmediatamente, como si se hiciera a través de FTS_LOGICAL, independientemente del modo
principal.
FTS_NOCHD
IR
Como una optimización de rendimiento, las funciones fts cambian de directorio a medida que recorren la jerarquía de archivos. Esto tiene el efecto secundario de que una aplicación no puede confiar en encontrarse en un directorio particular durante el recorrido. Esta opción desactiva esta optimización, y las funciones fts no cambiarán el directorio actual. Tenga en cuenta que las aplicaciones no deben cambiar su directorio actual e intentar acceder a archivos a menos que se especifique FTS_NOCHDIR y se proporcionen rutas de acceso absolutas como argumentos a fts_ope
n().
FTS_NOST
AT

Esta opción relaja ese requisito como una optimización de rendimiento, permitiendo que las funciones fts establezcan el campo fts_info en FTS_NSOK y dejen el contenido del campo fts_statp
indefinido.

La función fts_read() devuelve un puntero a una estructura FTSENT que describe un archivo en la jerarquía. Los directorios (que son legibles y no causan ciclos) se visitan al menos dos veces, una en preorden y una en postorden. Todos los demás archivos se visitan al menos una vez. (Los enlaces duros entre directorios que no causan ciclos o los enlaces simbólicos a enlaces simbólicos pueden hacer que los archivos se visiten más de una vez, o los directorios más de dos veces.

fts_children(

La función fts_children() devuelve un puntero a una estructura FTSENT que describe la primera entrada en una lista enlazada terminada por NULL de los archivos en el directorio representado por la estructura FTSENT devuelta más recientemente por fts_read(). error.
