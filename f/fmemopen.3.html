DESCRIPCIÓ

N

La función fmemopen() abre un flujo que permite el acceso especificado por mode. El flujo permite realizar E/S en la cadena o el búfer de memoria al que apunta buf

.

El argumento mode especifica la semántica de la E/S en el flujo, y es uno de los

siguientes:
r
El flujo se abre para
lectura.
w
El flujo se abre para
escritura.
a
Añadir; abrir el flujo para escritura, con la posición inicial del búfer establecida en el primer byte
nulo.
r
+
Abrir el flujo para lectura y
escritura.
w
+
Abrir el flujo para lectura y escritura. El contenido del búfer se trunca (es decir, se coloca '\0' en el primer byte del búfer)
.
a
+
Añadir; abrir el flujo para lectura y esc
ritura, con la posición inicial del
búfer establecida en el primer byte nulo.

El flujo mantiene la noción de una posición actual, la ubicación donde se realizará la siguiente operación de E/S. La posición actual se actualiza implícitamente por las operaciones de E/S. Se puede actualizar explícitamente usando fseek(3), y determinar usando ftell(3). En todos los modos distintos de añadir, la posición inicial se establece al inicio del búfer. En modo añadir, si no se encuentra ningún byte nulo dentro del búfer, entonces la posición inicial es size+1

.

Si buf se especifica como NULL, entonces fmemopen() asigna un búfer de size bytes. Esto es útil para una aplicación que desea escribir datos en un búfer temporal y luego leerlos de nuevo. La posición inicial se establece al inicio del búfer. El búfer se libera automáticamente cuando se cierra el flujo. Tenga en cuenta que el llamante no tiene forma de obtener un puntero al búfer temporal asignado por esta llamada (pero ver open_memstream(3))

.

Si buf no es NULL, entonces debe apuntar a un búfer de al menos size bytes asignado por el

llamante.

Cuando un flujo que se ha abierto para escritura se vacía (fflush(3)) o se cierra (fclose(3)), se escribe un byte nulo al final del búfer si hay espacio. El llamante debe asegurarse de que haya un byte extra disponible en el búfer (y que size cuente ese byte) para permitir

esto.

En un flujo abierto para lectura, los bytes nulos ('\0') en el búfer no hacen que las operaciones de lectura devuelvan una indicación de fin de archivo. Una lectura del búfer indicará fin de archivo solo cuando la posición actual del búfer avance size bytes desde el inicio del

búfer.

Las operaciones de escritura tienen lugar ya sea en la posición actual (para modos distintos de añadir), o en el tamaño actual del flujo (para los modos de añadir)

.

Los intentos de escribir más de size bytes en el búfer resultan en un error. De forma predeterminada, tales errores serán visibles (por la ausencia de datos) solo cuando se vacíe el búfer stdio. Deshabilitar el almacenamiento en búfer con la siguiente llamada puede ser útil para detectar errores en el momento de una operación de

salida: 


setbuf(
stream,
NULL);

HISTORI

A

glibc 1.0.x. POSIX.

1-2008.

POSIX.1-2008 especifica que 'b' en mode debe ignorarse. Sin embargo, la Corrección Técnica 1 ajusta el estándar para permitir un tratamiento específico de la implementación para este caso, permitiendo así el tratamiento de 'b' por parte de

glibc.

Con glibc 2.22, el modo binario (ver abajo) se eliminó, se corrigieron muchos errores de larga data en la implementación de fmemopen(), y se creó un nuevo símbolo versionado para esta

interfaz.

Modo

binario

Desde glibc 2.9 hasta glibc 2.21, la implementación de glibc de fmemopen() soportaba un modo "binario", habilitado al especificar la letra 'b' como el segundo carácter en mode. En este modo, las escrituras no añaden implícitamente un byte nulo final, y fseek(3) SEEK_END es relativo al final del búfer (es decir, el valor especificado por el argumento size), en lugar de la longitud actual de la

cadena.

Un error de API afectaba la implementación del modo binario: para especificar el modo binario, la 'b' debe ser el segundo carácter en mode. Así, por ejemplo, "wb+" tiene el efecto deseado, pero "w+b" no. Esto es inconsistente con el tratamiento de mode por fopen(

3).

El modo binario se eliminó en glibc 2.22; una 'b' especificada en mode no

tiene
efe
cto.

NOTA

S

No hay un descriptor de archivo asociado con el flujo de archivo devuelto por esta función (es decir, fileno(3) devolverá un error si

se llama en el
flujo devuelto).

ERRORE

S

Antes de glibc 2.22, si size se especifica como cero, fmemopen() falla con el error EINVAL. Sería más consistente si este caso creara exitosamente un flujo que luego devolviera fin de archivo en el primer intento de lectura; desde glibc 2.22, la implementación de glibc proporciona ese

comportamiento.

Antes de glibc 2.22, especificar el modo añadir ("a" o "a+") para fmemopen() establece la posición inicial del búfer en el primer byte nulo, pero (si la posición actual se restablece a una ubicación distinta del final del flujo) no fuerza a que las escrituras posteriores se añadan al final del flujo. Este error se corrige en glibc 2.

22.

Antes de glibc 2.22, si el argumento mode de fmemopen() especifica añadir ("a" o "a+"), y el argumento size no cubre un byte nulo en buf, entonces, según POSIX.1-2008, la posición inicial del búfer debería establecerse en el siguiente byte después del final del búfer. Sin embargo, en este caso el glibc fmemopen() establece la posición del búfer en -1. Este error se corrige en glibc 2.

22.

Antes de glibc 2.22, cuando se realizaba una llamada a fseek(3) con un valor whence de SEEK_END en un flujo creado por fmemopen(), el desplazamiento se restaba de la posición de fin de flujo, en lugar de sumarse. Este error se corrige en glibc 2.

22.

La adición del modo "binario" en glibc 2.9 para fmemopen() cambió silenciosamente la ABI: anteriormente, fmemopen() ignoraba 'b' en mo

de
.

EJEMPLO

S

El prograbajo usa fmemopen() para abrir un búfer de entrada, y open_memstream(3) para abrir un búfer de salida de tamaño dinámico. El programa escanea su cadena de entrada (tomada del primer argumento de la línea de comandos del programa) leyendo enteros, y escribe los cuadrados de estos enteros en el búfer de salida. Un ejemplo de la salida producida por este programa es el

siguiente: 


$ ./a.out '1 23 43'
size=11; ptr=1 529
1849

Fuente del

programa 
#define _GNU_SOURCE
#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
int
main(int argc, char *argv[])
{
    FILE *out, *in;
    int v, s;
    size_t size;
    char *ptr;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s '<num>...'\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    in = fmemopen(argv[1], strlen(argv[1]), "r");
    if (in == NULL)
        err(EXIT_FAILURE, "fmemopen");
    out = open_memstream(&ptr, &size);
    if (out == NULL)
        err(EXIT_FAILURE, "open_memstream");
    for (;;) {
        s = fscanf(in, "%d", &v);
        if (s <= 0)
            break;
        s = fprintf(out, "%d ", v * v);
        if (s == -1)
            err(EXIT_FAILURE, "fprintf");
    }
    fclose(in);
    fclose(out);
    printf("size=%zu; ptr=%s\n", size, ptr);
    free(ptr);
    exit(EXIT_SUCCESS)
;
}
