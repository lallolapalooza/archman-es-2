Permitir

que
está montado en modo lectura-escritura (copia de seguridad en vivo). Por defecto, fsarchiver falla con un error si el dispositivo está montado en modo lectura-escritura, lo que permite que se realicen modificaciones en el sistema de archivos durante la copia de seguridad. Las modificaciones pueden llevar a inconsistencias en la copia de seguridad. El uso de instantáneas de LVM es la forma recomendada de hacer copias de seguridad, ya que proporcionará consistencia, pero solo está disponible para sistemas de archivos que están en volúmenes lógicos de LVM. Los archivos
eliminados
durante el proceso de copia de
seguridad
se ignoran cuando se usa esta opción. -a, --allow-no-acl-xattr Permitir guardar un sistema de archivos cuando el núcleo no soporta (o tiene deshabilitados) las ACL y los atributos extendidos. Por defecto, fsarchiver falla con un error si no puede acceder a las ACL y los atributos extendidos, ya que no se guardarían. Si no necesita que se
conserven
las ACL y los atributos
extendidos,
es seguro usar esta opción. -e patrón, --exclude=patrón Excluir archivos y directorios que coincidan con el patrón especificado. El patrón puede contener comodines de shell como * y ? o puede ser un nombre de archivo/directorio simple o una ruta absoluta de archivo/directorio. Debe usar comillas alrededor del patrón cada vez que use comodines, de lo contrario sería interpretado por el shell. Los comodines deben ser
interpretados
por fsarchiver. Vea los
ejemplos
a continuación para más detalles sobre esta opción. -L etiqueta, --label=etiqueta Establecer la etiqueta del archivo: es solo un comentario sobre su contenido. Puede usarse para recordar
algo
particular sobre el archivo
o el
estado del sistema de archivos, por ejemplo. -z nivel, --compress=nivel Los niveles de compresión heredados están entre 0 (muy rápido) y 9 (muy bueno). El requisito de memoria aumenta mucho con los mejores niveles de compresión, y se multiplica por el número de hilos de compresión (opción -j). El nivel 9 se considera un nivel de compresión extremo y requiere una enorme cantidad de memoria para ejecutarse. Para más
detalles,
lea esta página: http:
//www.
fsarchiver.org/compression/ -Z nivel, --zstd=nivel Los niveles de compresión de Zstd están entre 1 (muy rápido) y 22 (muy bueno). El requisito de memoria aumenta mucho con los mejores niveles de compresión, y se multiplica por el número de hilos de compresión (opción -j). Los niveles superiores a 20 se consideran niveles de compresión extremos y requieren una enorme cantidad de memoria para ejecutarse. Para más detalles, lea
esta
página: http://www.
fsarchiver.
org/compression/ -s tamañomb, --split=tamañomb Dividir el archivo
en

megabytes cada uno. -j cantidad, --jobs=cantidad Crear más de un hilo de (des)compresión. Útil en CPUs multinúcleo. Por defecto, fsarchiver solo usará un hilo de (des)compresión (-j 1) y luego solo se usará un procesador lógico para la tarea. Debería usar esta opción si tiene una CPU multinúcleo o más de una CPU física en su ordenador. La forma típica de usarla es especificar el número de procesadores lógicos disponibles para que se use toda la potencia de procesamiento para (des)comprimir el archivo muy rápidamente. También puede querer usar todos los procesadores lógicos excepto uno para que su sistema siga siendo receptivo para
otras
