NOMBRE

e2fsck - comprobar un sistema de archivos ext2/ext3/ext4 de Linux

SINOPSIS

e2fsck [ -pacnyrdfkvtDFV ] [ -b superblock ] [ -B tamaño_bloque ] [ -l|-L archivo_bloques_defectuosos ] [ -C fd ] [ -j journal_externo ] [ -E opciones_extendidas ] [ -z archivo_deshacer ] dispositivo

DESCRIPCIÓN

e2fsck se utiliza para comprobar la familia de sistemas de archivos ext2/ext3/ext4. Para los sistemas de archivos ext3 y ext4 que utilizan un diario, si el sistema se ha apagado de forma poco limpia sin errores, normalmente, después de reproducir las transacciones confirmadas en el diario, el sistema de archivos debería marcarse como limpio. Por lo tanto, para los sistemas de archivos que utilizan diarios, e2fsck normalmente reproducirá el diario y saldrá, a menos que su superbloque indique que se requiere una comprobación adicional.

dispositivo es un dispositivo de bloques (por ejemplo, /dev/sdc1) o un archivo que contiene el sistema de archivos.

Tenga en cuenta que, en general, no es seguro ejecutar e2fsck en sistemas de archivos montados. La única excepción es si se especifica la opción -n y las opciones -c, -l o -L no se especifican. Sin embargo, incluso si es seguro hacerlo, los resultados impresos por e2fsck no son válidos si el sistema de archivos está montado. Si e2fsck pregunta si debe comprobar un sistema de archivos montado, la única respuesta correcta es "no". Solo los expertos que realmente saben lo que hacen deben considerar responder a esta pregunta de otra manera.

Si e2fsck se ejecuta en modo interactivo (lo que significa que ninguna de las opciones -y, -n o -p está especificada), el programa preguntará al usuario si desea corregir cada problema encontrado en el sistema de archivos. Una respuesta de 'y' corregirá el error; 'n' dejará el error sin corregir; y 'a' corregirá el problema y todos los problemas posteriores; al presionar Enter se procederá con la respuesta predeterminada, que se imprime antes del signo de interrogación. Presionar Control-C termina e2fsck inmediatamente.

OPCIONES

-a
Esta opción hace lo mismo que la opción -p. Se proporciona solo para compatibilidad con versiones anteriores; se sugiere que las personas utilicen la opción -p siempre que sea posible.
-b superblock
En lugar de usar el superbloque normal, use un superbloque alternativo especificado por superblock. Esta opción se usa normalmente cuando el superbloque primario ha sido dañado. La ubicación de los superbloques de copia de seguridad depende del tamaño del bloque del sistema de archivos, el número de bloques por grupo y características como sparse_super.
Los superbloques de copia de seguridad adicionales se pueden determinar utilizando el programa mke2fs con la opción -n para imprimir dónde existen los superbloques, suponiendo que mke2fs recibe argumentos consistentes con la disposición del sistema de archivos (por ejemplo, tamaño de bloque, bloques por grupo, sparse_super, etc.).
Si se especifica un superbloque alternativo y el sistema de archivos no se abre en modo de solo lectura, e2fsck se asegurará de que el superbloque primario se actualice adecuadamente al finalizar la comprobación del sistema de archivos.
-B tamaño_bloque
Normalmente, e2fsck buscará el superbloque en varios tamaños de bloque diferentes para encontrar el tamaño de bloque adecuado. Esta búsqueda puede ser engañosa en algunos casos. Esta opción fuerza a e2fsck a solo intentar localizar el superbloque en un tamaño de bloque particular. Si no se encuentra el superbloque, e2fsck terminará con un error fatal.
-c
Esta opción hace que e2fsck use el programa badblocks(8) para realizar un escaneo de solo lectura del dispositivo para encontrar bloques defectuosos. Si se encuentran bloques defectuosos, se agregan al inodo de bloques defectuosos para evitar que se asignen a un archivo o directorio. Si esta opción se especifica dos veces, el escaneo de bloques defectuosos se realizará utilizando una prueba de lectura-escritura no destructiva.
-C fd
Esta opción hace que e2fsck escriba información de progreso en el descriptor de archivo especificado para que se pueda monitorear el progreso de la comprobación del sistema de archivos. Esta opción es típicamente utilizada por programas que ejecutan e2fsck. Si el número del descriptor de archivo es negativo, se utilizará el valor absoluto del descriptor de archivo y la información de progreso se suprimirá inicialmente. Posteriormente se podrá habilitar enviando una señal SIGUSR1 al proceso e2fsck. Si el descriptor de archivo especificado es 0, e2fsck mostrará una barra de progreso a medida que realiza su trabajo. Esto requiere que e2fsck se ejecute en una consola de video o terminal.
-d
Imprimir salida de depuración (inútil a menos que esté depurando e2fsck).
-D
Optimizar directorios en el sistema de archivos. Esta opción hace que e2fsck intente optimizar todos los directorios, ya sea reindexándolos si el sistema de archivos admite la indexación de directorios, o ordenando y comprimiendo directorios para directorios más pequeños, o para sistemas de archivos que utilizan directorios lineales tradicionales.
Incluso sin la opción -D, e2fsck a veces puede optimizar algunos directorios; por ejemplo, si la indexación de directorios está habilitada y un directorio no está indexado y se beneficiaría de ser indexado, o si las estructuras de índices están corruptas y necesitan ser reconstruidas. La opción -D fuerza a que todos los directorios del sistema de archivos se optimicen. Esto a veces puede hacerlos un poco más pequeños y ligeramente más rápidos de buscar, pero en la práctica, rara vez necesitará usar esta opción.
La opción -D detectará entradas de directorio con nombres duplicados en un solo directorio, lo cual e2fsck normalmente no impone por razones de rendimiento.
-E opciones_extendidas
Establecer opciones extendidas de e2fsck. Las opciones extendidas se separan con comas y pueden tomar un argumento usando el signo igual ('='). Las siguientes opciones son compatibles:
ea_ver=version_atributos_extendidos
Establecer la versión de los bloques de atributos extendidos que e2fsck requerirá al comprobar el sistema de archivos. El número de versión puede ser 1 o 2. El formato predeterminado de la versión de atributos extendidos es 2.
journal_only
Solo reproducir el diario si es necesario, pero no realizar ninguna comprobación o reparación adicional.
fragcheck
Durante la pasada 1, imprimir un informe detallado de cualquier bloque no contiguo para los archivos en el sistema de archivos.
discard
Intentar descartar bloques libres y bloques de inodos no utilizados después de la comprobación completa del sistema de archivos (descartar bloques es útil en dispositivos de estado sólido y almacenamiento escaso/aprovisionado dinámicamente). Tenga en cuenta que el descarte se realiza en la pasada 5 DESPUÉS de que el sistema de archivos se haya comprobado completamente y solo si no contiene errores reconocibles. Sin embargo, puede haber casos en los que e2fsck no reconozca completamente un problema y, por lo tanto, esta opción puede impedirle una recuperación manual de datos posterior.
nodiscard
No intentar descartar bloques libres y bloques de inodos no utilizados. Esta opción es exactamente lo opuesto a la opción discard. Está configurada por defecto.
no_optimize_extents
No ofrecer optimizar el árbol de extensiones eliminando ancho o profundidad innecesarios. Esto también se puede habilitar en la sección de opciones de /etc/e2fsck.conf.
optimize_extents
Ofrecer optimizar el árbol de extensiones eliminando ancho o profundidad innecesarios. Este es el valor predeterminado a menos que se especifique lo contrario en /etc/e2fsck.conf.
inode_count_fullmap
