NOMBRE

fuse-overlayfs - Implementación FUSE de overlayfs

SINOPSIS

montaje
fuse-overlayfs [-f] [--debug] [-o OPTS] MOUNT_TARGET

desmontaje
fusermount -u mountpoint

DESCRIPCIÓN

fuse-overlayfs proporciona una implementación FUSE de overlayfs para que pueda ser utilizada desde Linux 4.18 por usuarios sin privilegios en un espacio de nombres de usuario.

OPCIONES

--debug Habilita el modo de depuración, puede ser muy verboso.

-o lowerdir=low1[:low2...] Una lista de directorios separados por :. Su contenido se fusiona.

-o upperdir=upperdir Un directorio fusionado encima de todos los lowerdirs donde se escribirán todos los cambios realizados en el sistema de archivos.

-o workdir=workdir Un directorio utilizado internamente por fuse-overlays, debe estar en el mismo sistema de archivos que el upper dir.

-o uidmapping=UID:MAPPED-UID:LEN[,UID2:MAPPED-UID2:LEN2] -o gidmapping=GID:MAPPED-GID:LEN[,GID2:MAPPED-GID2:LEN2] Especifica el mapeo dinámico de UID/GID utilizado por fuse-overlayfs al leer/escribir archivos en el sistema.

El mapeo dinámico de fuse-overlayfs es una forma alternativa y más eficiente de cambiar el propietario de los archivos en el host para acomodar la configuración del espacio de nombres de usuario.

Es útil para compartir el mismo almacenamiento entre diferentes espacios de nombres de usuario y contrarrestar el mapeo realizado por el espacio de nombres de usuario en sí, y sin requerir el cambio de propietario de los archivos.

Por ejemplo, dados en el host dos archivos como:

$ stat -c %u:%g lower/a lower/b 0:0 1:1

Cuando ejecutamos en un espacio de nombres de usuario con la siguiente configuración: $ cat /proc/self/uid_map
0 1000 1
1 110000 65536

Veríamos:

$ stat -c %u:%g merged/a merged/b 65534:65534 65534:65534

65534 es el ID de desbordamiento utilizado cuando el UID/GID no se conoce dentro del espacio de nombres de usuario. Esto ocurre porque los usuarios 0:0 y 1:1 no están mapeados.

En el ejemplo anterior, si montamos el sistema de archivos fuse-overlayfs usando: -ouidmapping=0:1000:1:1:110000:65536,gidmapping=0:1000:1:1:110000:65536, que es la configuración del espacio de nombres especificada en una sola línea, veríamos desde el mismo espacio de nombres de usuario:

$ stat -c %u:%g merged/a merged/b 0:0 1:1

Esos son los mismos IDs visibles desde fuera del espacio de nombres de usuario.

-o squash_to_root Cada archivo y directorio es propiedad del usuario root (0:0).

-o squash_to_uid=uid -o squash_to_gid=gid Cada archivo y directorio es propiedad del uid o gid especificado.

Tiene mayor precedencia que squash_to_root.

-o static_nlink Establece st_nlink al valor estático 1 para todos los directorios.

Esto puede ser útil para sistemas de archivos de alta latencia como NFS, donde contar el número de enlaces duros de un directorio con muchos archivos puede ser una operación lenta. Con esta opción habilitada, el número de enlaces duros reportado al ejecutar stat para cualquier directorio es 1.

-o noacl Deshabilita el soporte ACL en el sistema de archivos FUSE.

VER TAMBIÉN

fuse(8), mount(8), user_namespaces(7)
