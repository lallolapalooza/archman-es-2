focus(n)

Paquete: tk

Licencias: TCL

focus(n) Comandos integrados de Tk focus(n)

NOMBRE

focus - Gestionar el foco de entrada

SINOPSIS

focus
focus ventana
focus opción ?arg arg ...?

DESCRIPCIÓN

El comando focus se utiliza para gestionar el foco de entrada de Tk. En cualquier momento dado, una ventana en cada pantalla se designa como la *ventana de foco*; cualquier evento de pulsación o liberación de tecla para la pantalla se envía a esa ventana. Normalmente, el gestor de ventanas se encarga de redirigir el foco entre las ventanas de nivel superior de una pantalla. Por ejemplo, algunos gestores de ventanas establecen automáticamente el foco de entrada en una ventana de nivel superior cada vez que el ratón entra en ella; otros redirigen el foco de entrada solo cuando el usuario hace clic en una ventana. Normalmente, el gestor de ventanas establece el foco solo en las ventanas de nivel superior, dejando que la aplicación redirija el foco entre los hijos de la ventana de nivel superior.

Tk recuerda una ventana de foco por cada nivel superior (el descendiente más reciente de ese nivel superior que recibió el foco); cuando el gestor de ventanas da el foco a una ventana de nivel superior, Tk la redirige automáticamente a la ventana recordada. Dentro de un nivel superior, Tk utiliza un modelo de foco *explícito* por defecto. Mover el ratón dentro de un nivel superior no cambia normalmente el foco; el foco cambia solo cuando un widget decide explícitamente reclamar el foco (por ejemplo, debido a un clic de botón), o cuando el usuario pulsa una tecla como Tab que mueve el foco.

El procedimiento Tcl tk_focusFollowsMouse puede invocarse para crear un modelo de foco *implícito*: reconfigura Tk para que el foco se establezca en una ventana cada vez que el ratón entra en ella. Los procedimientos Tcl tk_focusNext y tk_focusPrev implementan un orden de foco entre las ventanas de un nivel superior; se utilizan en las vinculaciones por defecto para Tab y Shift-Tab, entre otras cosas.

El comando focus puede tomar cualquiera de las siguientes formas:

focus
Devuelve el nombre de ruta de la ventana de foco en la pantalla que contiene la ventana principal de la aplicación, o una cadena vacía si ninguna ventana en esta aplicación tiene el foco en esa pantalla. Nota: es mejor especificar la pantalla explícitamente usando -displayof (ver más abajo) para que el código funcione en aplicaciones que utilizan múltiples pantallas.
focus ventana
Si la aplicación tiene actualmente el foco de entrada en la pantalla de ventana, este comando restablece el foco de entrada para la pantalla de ventana a ventana y devuelve una cadena vacía. Si la aplicación no tiene actualmente el foco de entrada en la pantalla de ventana, ventana será recordada como el foco para su nivel superior; la próxima vez que llegue el foco al nivel superior, Tk lo redirigirá a ventana. Si ventana es una cadena vacía, el comando no hace nada.
focus -displayof ventana
Devuelve el nombre de la ventana de foco en la pantalla que contiene ventana. Si la ventana de foco para la pantalla de ventana no está en esta aplicación, el valor de retorno es una cadena vacía.
focus -force ventana
Establece el foco de la pantalla de ventana a ventana, incluso si la aplicación no tiene actualmente el foco de entrada para la pantalla. Este comando debe usarse con moderación, si es que se usa. En el uso normal, una aplicación no debe reclamar el foco para sí misma; en cambio, debe esperar a que el gestor de ventanas le dé el foco. Si ventana es una cadena vacía, el comando no hace nada.
focus -lastfor ventana
Devuelve el nombre de la ventana más reciente que tuvo el foco de entrada entre todas las ventanas del mismo nivel superior que ventana. Si ninguna ventana en ese nivel superior ha tenido nunca el foco de entrada, o si la ventana de foco más reciente ha sido eliminada, se devuelve el nombre de la ventana de nivel superior. El valor de retorno es la ventana que recibirá el foco de entrada la próxima vez que el gestor de ventanas dé el foco al nivel superior.

OBSERVACIONES

Cuando una ventana interna recibe el foco de entrada, Tk no establece realmente el foco X en esa ventana; en lo que respecta a X, el foco permanecerá en la ventana de nivel superior que contiene la ventana con el foco. Sin embargo, Tk genera eventos FocusIn y FocusOut como si el foco X estuviera en la ventana interna. Este enfoque resuelve una serie de problemas que ocurrirían si el foco X se moviera realmente; el hecho de que el foco X esté en la ventana de nivel superior es invisible a menos que se utilice código C para consultar directamente el servidor X.

EJEMPLO

Para hacer que una ventana solo participe en el anillo de recorrido del foco cuando se establece una variable, agregue las siguientes vinculaciones a los widgets *antes* y *después* de ella en ese anillo de foco:

button .before -text "Antes"
button .middle -text "Medio"
button .after  -text "Después"
checkbutton .flag -variable traverseToMiddle -takefocus 0
pack .flag -side left
pack .before .middle .after
bind .before <Tab> {
   if {!$traverseToMiddle} {
      focus .after
      break
   }
}
bind .after <Shift-Tab> {
   if {!$traverseToMiddle} {
      focus .before
      break
   }
}
focus .before
