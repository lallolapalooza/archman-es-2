fsconfig(2) Manual de Llamadas al Sistema fsconfig(2)

NOMBRE

fsconfig - configurar un contexto de sistema de archivos nuevo o existente

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <sys/mount.h>
int fsconfig(int fd, unsigned int cmd,
             const char *_Nullable key,
             const void *_Nullable value, int aux);

DESCRIPCIÓN

La llamada al sistema fsconfig() es parte del conjunto de funcionalidades de montaje basadas en descriptores de archivo en Linux.

fsconfig() se utiliza para proporcionar parámetros y emitir comandos contra el contexto de configuración del sistema de archivos asociado con el descriptor de archivo fd. Los contextos de configuración del sistema de archivos pueden crearse con fsopen(2) o instanciarse a partir de una instancia de sistema de archivos existente con fspick(2).

El cmd argumento indica el comando a emitir. Algunos comandos proporcionan parámetros al contexto (equivalente a las opciones de montaje especificadas con mount(8)), mientras que otros son meta-operaciones sobre el contexto del sistema de archivos. La lista de valores válidos de cmd es:

FSCONFIG_SET_FLAG
Establece el parámetro de bandera (flag) nombrado por key. value debe ser NULL, y aux debe ser 0.
FSCONFIG_SET_STRING
Establece el parámetro de cadena (string) nombrado por key al valor especificado por value. value apunta a una cadena terminada en nulo, y aux debe ser 0.
FSCONFIG_SET_BINARY
Establece el parámetro de blob nombrado por key al contenido del blob binario especificado por value. value apunta al inicio de un búfer que tiene aux bytes de longitud.
FSCONFIG_SET_FD
Establece el parámetro de archivo nombrado por key a la descripción de archivo abierto referenciada por el descriptor de archivo aux. value debe ser NULL.
También puede usar FSCONFIG_SET_STRING para parámetros de archivo, con value establecido a una cadena terminada en nulo que contiene una representación en base 10 del número de descriptor de archivo. Este mecanismo está destinado principalmente a la compatibilidad con programas más antiguos basados en mount(2), y solo funciona para parámetros que solo aceptan argumentos de descriptor de archivo.
FSCONFIG_SET_PATH
Establece el parámetro de ruta nombrado por key al objeto en una ruta proporcionada, resuelta de una manera similar a openat(2). value apunta a una cadena de ruta de archivo terminada en nulo, y aux es equivalente al argumento dirfd de openat(2). Vea openat(2) para una explicación de la necesidad de FSCONFIG_SET_PATH.
También puede usar FSCONFIG_SET_STRING para parámetros de ruta, cuyo comportamiento es equivalente a FSCONFIG_SET_PATH con aux establecido a AT_FDCWD.
FSCONFIG_SET_PATH_EMPTY
Al igual que con FSCONFIG_SET_PATH, excepto que si value es una cadena vacía, el descriptor de archivo especificado por aux se opera directamente y puede ser de cualquier tipo de archivo (no solo un directorio). Esto es equivalente al comportamiento de AT_EMPTY_PATH con la mayoría de las llamadas al sistema "*at()". Si aux es AT_FDCWD, el parámetro se establecerá al directorio de trabajo actual del proceso que llama.
FSCONFIG_CMD_CREATE
Este comando instruye al controlador del sistema de archivos para instanciar una instancia de el sistema de archivos en el kernel con los parámetros especificados en el contexto de configuración del sistema de archivos. key y value deben ser NULL, y aux debe ser 0.
Este comando solo puede emitirse una vez en la vida útil de un contexto de sistema de archivos. Si la operación tiene éxito, el contexto de sistema de archivos asociado con el descriptor de archivo fd ahora referencia la instancia de sistema de archivos creada, y se coloca en un modo especial de "esperando montaje" que le permite usar fsmount(2) para crear un objeto de montaje a partir de la instancia de sistema de archivos. Si la operación falla, en la mayoría de los casos el contexto de sistema de archivos se coloca en un modo fallido y no puede usarse para ninguna operación posterior de fsconfig() (aunque aún puede recuperar mensajes de diagnóstico a través de la interfaz de recuperación de mensajes, como se describe en la subsección correspondiente de fsopen(2)).
Este comando solo puede emitirse contra contextos de configuración del sistema de archivos que fueron creados con fsopen(2). Para crear una instancia de sistema de archivos, el proceso que llama debe tener la capacidad CAP_SYS_ADMIN .
Una cosa importante a tener en cuenta es que el kernel de Linux silenciosamente reutilizará instancias de sistema de archivos existentes dependiendo del tipo de sistema de archivos y los parámetros configurados (cada controlador de sistema de archivos tiene su propia política sobre cómo se reutilizan las instancias de sistema de archivos). Esto significa que la instancia de sistema de archivos "creada" por FSCONFIG_CMD_CREATE puede, de hecho, ser una referencia a una instancia de sistema de archivos existente en el kernel. (Para referencia, este comportamiento también se aplica a mount(2).)
Un efecto secundario de este comportamiento es que si se reutiliza una instancia de sistema de archivos existente, todos los parámetros configurados para este contexto de configuración del sistema de archivos son ignorados silenciosamente (con la excepción de los parámetros de bandera ro y rw ; si el estado de la bandera de solo lectura en la instancia de sistema de archivos existente y el contexto de configuración del sistema de archivos no coinciden, esta operación devolverá EBUSY). Esto también significa que los comandos FSCONFIG_CMD_RECONFIGURE emitidos contra la instancia de sistema de archivos "creada" también afectarán a cualquier objeto de montaje asociado con la instancia de sistema de archivos existente.
Los programas que necesiten asegurarse de que crean una nueva instancia de sistema de archivos con parámetros específicos (notablemente, parámetros relacionados con la seguridad como acl para habilitar ACLs POSIX—como se describe en acl(5)) deberían usar FSCONFIG_CMD_CREATE_EXCL en su lugar.
FSCONFIG_CMD_CREATE_EXCL (desde Linux 6.6)
Al igual que con FSCONFIG_CMD_CREATE, excepto que se instruye al kernel a no reutilizar instancias de sistema de archivos existentes. Si la operación se viera forzada a reutilizar una instancia de sistema de archivos existente, esta operación devolverá EBUSY en su lugar.
Como resultado (a diferencia de FSCONFIG_CMD_CREATE), si esta operación tiene éxito, el proceso que llama puede estar seguro de que todos los parámetros configurados exitosamente con fsconfig() se aplicarán realmente a la instancia de sistema de archivos creada.
FSCONFIG_CMD_RECONFIGURE
Este comando instruye al controlador del sistema de archivos para aplicar los parámetros especificados en el contexto de configuración del sistema de archivos a la instancia de sistema de archivos existente referenciada por el contexto de configuración del sistema de archivos. key y value deben ser NULL, y aux debe ser 0.
Esto está destinado principalmente para su uso con fspick(2), pero también puede usarse para modificar los parámetros de una instancia de sistema de archivos después de que FSCONFIG_CMD_CREATE se usó para crearla y se creó un objeto de montaje usando fsmount(2). Para reconfigurar una instancia de sistema de archivos existente, el proceso que llama debe tener la capacidad CAP_SYS_ADMIN .
Si la operación tiene éxito, el contexto de sistema de archivos se restablece pero permanece en modo de reconfiguración y por lo tanto puede reutilizarse para comandos posteriores de FSCONFIG_CMD_RECONFIGURE . Si la operación falla, en la mayoría de los casos el contexto de sistema de archivos se coloca en un modo fallidode y no pueden usarse para nada más fsconfig() (aunque aún puedes recuperar mensajes de diagnóstico a través de la interfaz de recuperación de mensajes, como se describe en la subsección correspondiente de fsopen(2)).

Los parámetros especificados con FSCONFIG_SET_* no tienen efecto hasta que se emita un comando FSCONFIG_CMD_CREATE o FSCONFIG_CMD_RECONFIGURE correspondiente.

VALOR DE RETORNO

En caso de éxito, fsconfig() devuelve 0. En caso de error, se devuelve -1, y errno se establece para indicar el error.

ERRORES

Si ocurre un error, el controlador del sistema de archivos puede proporcionar información adicional sobre el error a través de la interfaz de recuperación de mensajes para contextos de configuración de sistemas de archivos. Esta información adicional puede recuperarse en cualquier momento llamando a read(2) sobre la instancia del sistema de archivos o el contexto de configuración del sistema de archivos referenciado por el descriptor de archivo fd. (Consulta la subsección "Interfaz de recuperación de mensajes" en fsopen(2) para más detalles sobre el formato del mensaje.)

Incluso después de que ocurra un error, el contexto de configuración del sistema de archivos no se invalida , y por lo tanto puede seguir usándose con otros comandos fsconfig(). Esto significa que los usuarios pueden probar el soporte para parámetros de sistemas de archivos a nivel de parámetro individual, y ajustar qué parámetros desean establecer.

Los valores de error dados a continuación resultan de errores independientes del tipo de sistema de archivos. Cada tipo de sistema de archivos puede tener sus propios errores especiales y su propio comportamiento especial. Consulta el código fuente del kernel de Linux para más detalles.

EACCES
Un componente de una ruta proporcionada como parámetro de ruta no era consultable. (Consulta también path_resolution(7).)
EACCES
Se intentó FSCONFIG_CMD_CREATE para un sistema de archivos de solo lectura sin especificar el parámetro de bandera 'ro'.
EACCES
Un parámetro de dispositivo de bloque especificado está ubicado en un sistema de archivos montado con la opción MS_NODEV .
EBADF
El descriptor de archivo dado por fd (o posiblemente por aux, dependiendo del comando) no es válido.
EBUSY
El contexto del sistema de archivos asociado con fd está en el estado incorrecto para el comando dado.
EBUSY
La instancia del sistema de archivos no puede reconfigurarse como de solo lectura con FSCONFIG_CMD_RECONFIGURE porque algunos programas aún tienen archivos abiertos para escritura.
EBUSY
Se solicitó una nueva instancia del sistema de archivos con FSCONFIG_CMD_CREATE_EXCL pero ya existía un superbloque coincidente.
EFAULT
Uno de los argumentos de puntero apunta a una ubicación fuera del espacio de direcciones accesible del proceso que llama.
EINVAL
fd no se refiere a un contexto de configuración de sistema de archivos o instancia de sistema de archivos.
EINVAL
Uno de los valores de key, valuey/o aux se estableció en un valor distinto de cero cuando cmd requería que fueran cero (o NULL).
EINVAL
El parámetro nombrado por key no puede establecerse usando el tipo especificado con cmd.
EINVAL
Uno de los parámetros de origen se refería a un superbloque no válido.
ELOOP
Se encontraron demasiados enlaces durante la resolución de la ruta de un argumento de ruta.
ENAMETOOLONG
Un argumento de ruta era más largo que PATH_MAX.
ENOENT
Un argumento de ruta tenía un componente inexistente.
ENOENT
Un argumento de ruta es una cadena vacía, pero cmd no es FSCONFIG_SET_PATH_EMPTY.
ENOMEM
El kernel no pudo asignar suficiente memoria para completar la operación.
ENOTBLK
El parámetro nombrado por key debe ser un dispositivo de bloque, pero el valor de parámetro proporcionado no era un dispositivo de bloque.
ENOTDIR
Un componente del prefijo de ruta de un argumento de ruta no era un directorio.
EOPNOTSUPP
El comando dado por cmd no es válido.
ENXIO
El número mayor de un parámetro de dispositivo de bloque está fuera de rango.
EPERM
El comando dado por cmd era FSCONFIG_CMD_CREATE, FSCONFIG_CMD_CREATE_EXCL, o FSCONFIG_CMD_RECONFIGURE, pero el proceso que llama no tiene la capacidad CAP_SYS_ADMIN requerida.

ESTÁNDARES

Linux.

HISTORIA

Linux 5.2. glibc 2.36.

NOTAS

Parámetros genéricos de sistemas de archivos

Cada controlador de sistema de archivos es responsable de analizar la mayoría de los parámetros especificados con fsconfig(), lo que significa que los sistemas de archivos individuales pueden tener comportamientos muy diferentes al encontrar parámetros con el mismo nombre. En general, no debes asumir que el comportamiento de fsconfig() al especificar un parámetro para un tipo de sistema de archivos coincidirá con el comportamiento del mismo parámetro con un tipo de sistema de archivos diferente.

Sin embargo, los siguientes parámetros genéricos se aplican a todos los sistemas de archivos y tienen un comportamiento unificado. Se establecen usando el comando FSCONFIG_SET_* listado.

royrw(FSCONFIG_SET_FLAG)
Configura si la instancia del sistema de archivos es de solo lectura.
dirsync(FSCONFIG_SET_FLAG)
Hace que los cambios de directorio en esta instancia del sistema de archivos sean síncronos.
syncyasync(FSCONFIG_SET_FLAG)
Configura si las escrituras en esta instancia del sistema de archivos se harán síncronas (como si se hubiera especificado la bandera O_SYNC para open(2) en todas las aperturas de archivos en esta instancia del sistema de archivos).
lazytimeynolazytime(FSCONFIG_SET_FLAG)
Configura si reducir las actualizaciones en disco de los timestamps de inodos en esta instancia del sistema de archivos (como se describe en la sección MS_LAZYTIME de mount(2)).
mandynomand(FSCONFIG_SET_FLAG)
Configura si la instancia del sistema de archivos debe permitir el bloqueo obligatorio. Desde Linux 5.15, el bloqueo obligatorio ha quedado obsoleto y establecer esta bandera no tiene efecto.
source(FSCONFIG_SET_STRING)
Este parámetro es equivalente al parámetro source pasado a mount(2) para el mismo tipo de sistema de archivos, y generalmente es la ruta de nombre de un dispositivo de bloque que contiene el sistema de archivos. Este parámetro solo puede establecerse una vez por transacción de contexto de configuración de sistema de archivos.

Además, cualquier parámetro de sistema de archivos asociado con los Módulos de Seguridad de Linux (LSM) también es genérico con respecto al sistema de archivos subyacente. Consulta la documentación del LSM que deseas configurar para más detalles.

Atributos de montaje y parámetros de sistemas de archivos

Algunos parámetros de sistemas de archivos (tradicionalmente asociados con opciones de estilo de mount(8)) tienen un atributo de montaje hermano con un comportamiento de cara al usuario superficialmente similar.

Para una descripción de la distinción entre atributos de montaje y parámetros de sistemas de archivos, consulta la subsección "Atributos de montaje y parámetros de sistemas de archivos" de mount_setattr(2).

ADVERTENCIAS

Tipos de parámetros de sistemas de archivos

Como resultado de que cada controlador de sistema de archivos sea responsable de analizar la mayoría de los parámetros especificados con fsconfig(), algunos controladores de sistemas de archivos pueden tener comportamientos no intuitivos con respecto a qué comandos FSCONFIG_SET_* se permiten para configurar un parámetro dado.

Para que los parámetros de sistemas de archivos sean compatibles hacia atrás con mount(2), deben ser analizables como cadenas; esto casi universalmente significa que FSCONFIG_SET_STRING también puede usarse para configurarlos. Sin embargo, otros comandos FSCONFIG_SET_* deben ser habilitados explícitamente por el analizador de parámetros de cada controlador de sistema de archivos.

Una de las instancias más visibles para el usuario de esta inconsistencia es que muchos sistemas de archivos no soportan configurar parámetros de ruta con FSCONFIG_SET_PATH (a pesar del nombre), lo que puede llevar a errores algo confusos de EINVAL . (Por ejemplo, el parámetro genérico source —que usualmente es una ruta— solo puede configurarse con FSCONFIG_SET_STRING.)

Al escribir programas que usan fsconfig() para configurar parámetros con comandos distintos de FSCONFIG_SET_STRING, los usuarios deben verificar que los comandos FSCONFIG_SET_* usados para configurar cada parámetro son soportados por el controlador de sistema de archivos correspondiente.

EJEMPLOS

Para ilustrar los diferentes tipos de indicadores que se pueden configurar con fsconfig(), aquí hay algunos ejemplos de diferentes sistemas de archivos que se están creando:


int fsfd, mntfd;
fsfd = fsopen("tmpfs", FSOPEN_CLOEXEC);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "inode64", NULL, 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "uid", "1234", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "huge", "never", 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "casefold", NULL, 0);
fsconfig(fsfd, FSCONFIG_CMD_CREATE, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC, MOUNT_ATTR_NOEXEC);
move_mount(mntfd, "", AT_FDCWD, "/tmp", MOVE_MOUNT_F_EMPTY_PATH);
fsfd = fsopen("erofs", FSOPEN_CLOEXEC);
fsconfig(fsfd, FSCONFIG_SET_STRING, "source", "/dev/loop0", 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "acl", NULL, 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "user_xattr", NULL, 0);
fsconfig(fsfd, FSCONFIG_CMD_CREATE_EXCL, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC, MOUNT_ATTR_NOSUID);
move_mount(mntfd, "", AT_FDCWD, "/mnt", MOVE_MOUNT_F_EMPTY_PATH);

Normalmente, especificar el mismo parámetro llamado por key varias veces con fsconfig() hace que el valor del parámetro sea reemplazado. Sin embargo, algunos sistemas de archivos pueden tener un comportamiento único:


int fsfd, mntfd;
int lowerdirfd = open("/o/ctr/lower1", O_DIRECTORY | O_CLOEXEC);
fsfd = fsopen("overlay", FSOPEN_CLOEXEC);
/* "lowerdir+" se añade a la pila de directorios inferiores cada vez */
fsconfig(fsfd, FSCONFIG_SET_FD, "lowerdir+", NULL, lowerdirfd);
fsconfig(fsfd, FSCONFIG_SET_STRING, "lowerdir+", "/o/ctr/lower2", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "lowerdir+", "/o/ctr/lower3", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "lowerdir+", "/o/ctr/lower4", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "xino", "auto", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "nfs_export", "off", 0);
fsconfig(fsfd, FSCONFIG_CMD_CREATE, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC, 0);
move_mount(mntfd, "", AT_FDCWD, "/mnt", MOVE_MOUNT_F_EMPTY_PATH);

Y aquí hay un ejemplo de cómo fspick(2) puede ser utilizado con fsconfig() para reconfigurar los parámetros de una instancia de sistema de archivos existente adjunta a /proc:


int fsfd = fspick(AT_FDCWD, "/proc", FSPICK_CLOEXEC);
fsconfig(fsfd, FSCONFIG_SET_STRING, "hidepid", "ptraceable", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "subset", "pid", 0);
fsconfig(fsfd, FSCONFIG_CMD_RECONFIGURE, NULL, NULL, 0);
