FOLD(1P) Manual del Programador POSIX FOLD(1P)

PRÓLOGO

Esta página de manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página de manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fold — filtro para plegar líneas

SINOPSIS

fold [-bs] [-w ancho] [archivo...]

DESCRIPCIÓN

La utilidad fold es un filtro que plegará las líneas de sus archivos de entrada, rompiendo las líneas para que tengan un máximo de ancho posiciones de columna (o bytes, si se especifica la opción -b ). Las líneas se romperán mediante la inserción de un <salto de línea> de modo que cada línea de salida (a la que se hará referencia más adelante en esta sección como segmento) sea el ancho máximo posible que no exceda el número especificado de posiciones de columna (o bytes). Una línea no se romperá en medio de un carácter. El comportamiento es indefinido si ancho es menor que el número de columnas que ocuparía cualquier carácter individual en la entrada.

Si se encuentran los caracteres <retorno de carro>, <retroceso> o <tabulador> en la entrada, y no se ha especificado la opción -b , se tratarán de forma especial:

<retroceso>
El recuento actual del ancho de línea se decrementará en uno, aunque el recuento nunca será negativo. La utilidad fold no insertará un <salto de línea> inmediatamente antes o después de ningún <retroceso>, a menos que el carácter siguiente tenga un ancho mayor que 1 y cause que el ancho de línea exceda ancho.
<retorno de carro>

El recuento actual del ancho de línea se pondrá a cero. La utilidad fold no insertará un <salto de línea> inmediatamente antes o después de ningún <retorno de carro>.
<tabulador>
Cada <tabulador> encontrado avanzará el puntero de posición de columna hasta la siguiente parada de tabulación. Las paradas de tabulación estarán en cada posición de columna n tal que n módulo 8 sea igual a 1.

OPCIONES

La utilidad fold deberá cumplir con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades.

Se deberán soportar las siguientes opciones:

-b
Contar ancho en bytes en lugar de posiciones de columna.
-s
Si un segmento de una línea contiene un <espacio en blanco> dentro de las primeras ancho posiciones de columna (o bytes), romper la línea después del último <espacio en blanco> que cumpla con las restricciones de ancho. Si no hay ningún <espacio en blanco> que cumpla con los requisitos, la opción -s no tendrá efecto para ese segmento de salida de la línea de entrada.
-wancho
Especificar la longitud máxima de línea, en posiciones de columna (o en bytes si se especifica -b ). Los resultados no están especificados si ancho no es un número decimal positivo. El valor por defecto será 80.

OPERANDOS

Se soportará el siguiente operando:

archivo
Una ruta de acceso a un archivo de texto que se va a plegar. Si no se especifican operandos archivo , se usará la entrada estándar.

ENTRADA ESTÁNDAR

Se usará la entrada estándar si no se especifican operandos archivo , y se usará si un operando archivo es '-' y la implementación trata el '-' como significando entrada estándar. De lo contrario, no se usará la entrada estándar. Vea la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

Si se especifica la opción -b , los archivos de entrada serán archivos de texto excepto que las líneas no están limitadas a {LINE_MAX} bytes de longitud. Si no se especifica la opción -b , los archivos de entrada serán archivos de texto.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de fold:

LANG
Proporcionar un valor por defecto para las variables de internacionalización que no estén definidas o sean nulas. (Vea el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para la precedencia de las variables de internacionalización usadas para determinar los valores de las categorías de configuración regional.)
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en oposición a multibyte en argumentos y archivos de entrada), y para la determinación del ancho en posiciones de columna que ocuparía cada carácter en un dispositivo de salida de fuente de ancho constante.
LC_MESSAGES

Determinar la configuración regional que debe usarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Por defecto.

SALIDA ESTÁNDAR

La salida estándar será un archivo que contiene una secuencia de caracteres cuyo orden se preservará desde los archivos de entrada, posiblemente con caracteres <salto de línea> insertados.

SALIDA DE ERROR ESTÁNDAR

La salida de error estándar se usará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

Ninguno.

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

0
Todos los archivos de entrada fueron procesados con éxito.
>0
Ocurrió un error.

USO DE LA APLICACIÓN

Las utilidades cut y fold pueden usarse para crear archivos de texto a partir de archivos con longitudes de línea arbitrarias. La utilidad cut debe usarse cuando el número de líneas (o registros) necesita permanecer constante. La utilidad fold debe usarse cuando el contenido de líneas largas necesita mantenerse contiguo.

La utilidad fold se usa frecuentemente para enviar archivos de texto a impresoras que truncan, en lugar de plegar, líneas más anchas de lo que la impresora es capaz de imprimir (usualmente 80 o 132 posiciones de columna).

EJEMPLOS

Un ejemplo de invocación que envía un archivo de posiblemente líneas largas a la impresora (bajo la suposición de que el usuario conoce el ancho de línea de la impresora a ser asignado por lp):

fold -w 132 bigfile | lp

JUSTIFICACIÓN

Aunque la entrada de terminal en modo de procesamiento canónico requiere el carácter de borrado (frecuentemente establecido a <retroceso>) para borrar el carácter anterior (no byte o posición de columna), teLa salida de la terminal no está almacenada en búfer y es extremadamente difícil, si no imposible, analizar correctamente; la interpretación depende completamente del dispositivo físico que realmente muestra/imprime/almacena la salida. En todas las implementaciones internacionalizadas conocidas, las utilidades que producen salida para columnas de ancho mixto asumen que un carácter <backspace> retrocede una posición de columna y emite suficientes caracteres <backspace> para volver al inicio del carácter cuando <backspace> se utiliza para proporcionar movimientos locales de línea para soportar operaciones de subrayado y negrita. Dado que fold sin la -b opción está lidiando con estas mismas restricciones, <backspace> siempre se trata como retroceder una posición de columna en lugar de retroceder un carácter.

Las versiones históricas de la utilidad fold asumían que 1 byte era un carácter y ocupaba una posición de columna al escribirse. Esto ya no es siempre cierto. Dado que se cree que el uso más común de fold es plegar líneas largas para la salida en dispositivos de salida de longitud limitada, esta capacidad se conservó como el caso predeterminado. La -b opción se añadió para que las aplicaciones pudieran fold archivos con líneas de longitud arbitraria en archivos de texto que luego podrían ser procesados por las utilidades estándar. Nótese que aunque el ancho para la -b opción está en bytes, una línea nunca se divide en medio de un carácter. (No se especifica qué sucede si se especifica un ancho demasiado pequeño para contener un solo carácter encontrado en la entrada seguido de un <newline>.)

Las tabulaciones están codificadas para ser cada octava columna para cumplir con la práctica histórica. No se inventó ningún nuevo método para especificar otras tabulaciones.
