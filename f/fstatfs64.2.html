statfs(2) Manual de Llamadas al Sistema statfs(2)

NOMBRE

statfs, fstatfs - obtener estadísticas del sistema de archivos

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <sys/vfs.h>    /* o <sys/statfs.h> */
int statfs(const char *path, struct statfs *buf);
int fstatfs(int fd, struct statfs *buf);

A menos que necesite el campo f_type , debería usar la interfaz estándar statvfs(3) en su lugar.

DESCRIPCIÓN

La llamada al sistema statfs() devuelve información sobre un sistema de archivos montado. path es la ruta de acceso de cualquier archivo dentro del sistema de archivos montado. buf es un puntero a una estructura statfs definida aproximadamente de la siguiente manera:


struct statfs {
    __fsword_t f_type;    /* Tipo de sistema de archivos (ver más abajo) */
    __fsword_t f_bsize;   /* Tamaño óptimo del bloque de transferencia */
    fsblkcnt_t f_blocks;  /* Bloques de datos totales en el sistema de archivos */
    fsblkcnt_t f_bfree;   /* Bloques libres en el sistema de archivos */
    fsblkcnt_t f_bavail;  /* Bloques libres disponibles para
                             un usuario sin privilegios */
    fsfilcnt_t f_files;   /* Inodos totales en el sistema de archivos */
    fsfilcnt_t f_ffree;   /* Inodos libres en el sistema de archivos */
    fsid_t     f_fsid;    /* ID del sistema de archivos */
    __fsword_t f_namelen; /* Longitud máxima de los nombres de archivo */
    __fsword_t f_frsize;  /* Tamaño del fragmento (desde Linux 2.6) */
    __fsword_t f_flags;   /* Opciones de montaje del sistema de archivos
                             (desde Linux 2.6.36) */
    __fsword_t f_spare[xxx];
                    /* Bytes de relleno reservados para uso futuro */
};

La mayoría de estas constantes MAGIC están definidas en /usr/include/linux/magic.h, y algunas están codificadas en los fuentes del núcleo.

El campo f_flags es una máscara de bits que indica las opciones de montaje para el sistema de archivos. Contiene cero o más de los siguientes bits:

ST_MANDLOCK
Se permite el bloqueo obligatorio en el sistema de archivos (ver fcntl(2)).
ST_NOATIME
No actualizar los tiempos de acceso; ver mount(2).
ST_NODEV
No permitir el acceso a ficheros especiales de dispositivo en este sistema de archivos.
ST_NODIRATIME
No actualizar los tiempos de acceso de los directorios; ver mount(2).
ST_NOEXEC
No se permite la ejecución de programas en este sistema de archivos.
ST_NOSUID
Los bits set-user-ID y set-group-ID son ignorados por exec(3) para ficheros ejecutables en este sistema de archivos
ST_RDONLY
Este sistema de archivos está montado solo lectura.
ST_RELATIME
Actualizar atime relativo a mtime/ctime; ver mount(2).
ST_SYNCHRONOUS
Las escrituras se sincronizan con el sistema de archivos inmediatamente (ver la descripción de O_SYNC en open(2)).
ST_NOSYMFOLLOW (desde Linux 5.10)
No se siguen los enlaces simbólicos al resolver rutas de acceso; ver mount(2).

Nadie sabe qué debería contener f_fsid (pero ver más abajo).

Los campos que están indefinidos para un sistema de archivos particular se establecen en 0.

fstatfs() devuelve la misma información sobre un archivo abierto referenciado por el descriptor fd.

VALOR DEVUELTO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1, y errno se establece para indicar el error.

ERRORES

EACCES
(statfs()) Se denegó el permiso de búsqueda para un componente del prefijo de la ruta de path. (Ver también path_resolution(7).)
EBADF
(fstatfs()) fd no es un descriptor de archivo abierto válido.
EFAULT
buf o path apunta a una dirección no válida.
EINTR
La llamada fue interrumpida por una señal; ver signal(7).
EIO
Ocurrió un error de E/S mientras se leía del sistema de archivos.
ELOOP
(statfs()) Se encontraron demasiados enlaces simbólicos al traducir path.
ENAMETOOLONG
(statfs()) path es demasiado largo.
ENOENT
(statfs()) El archivo referenciado por path no existe.
ENOMEM
No había suficiente memoria disponible en el núcleo.
ENOSYS
El sistema de archivos no admite esta llamada.
ENOTDIR
(statfs()) Un componente del prefijo de la ruta de path no es un directorio.
EOVERFLOW
Algunos valores eran demasiado grandes para ser representados en la estructura devuelta.

VERSIONES

El campo f_fsid

Solaris, Irix y POSIX tienen una llamada al sistema statvfs(2) que devuelve un struct statvfs (definido en <sys/statvfs.h>) que contiene un unsigned long f_fsid. Linux, SunOS, HP-UX, 4.4BSD tienen una llamada al sistema statfs() que devuelve un struct statfs (definido en <sys/vfs.h>) que contiene un fsid_t f_fsid, donde fsid_t está definido como struct { int val[2]; }. Lo mismo se aplica a FreeBSD, excepto que utiliza el archivo de inclusión <sys/mount.h>.

La idea general es que f_fsid contiene algún dato aleatorio de modo que el par (f_fsid,ino) determina de forma única un archivo. Algunos sistemas operativos usan (una variación de) el número de dispositivo, o el número de dispositivo combinado con el tipo de sistema de archivos. Varios sistemas operativos restringen la entrega del f_fsid campo solo al superusuario (y lo ponen a cero para usuarios no privilegiados), porque este campo se usa en el manejador de archivos cuando se exporta por NFS, y entregarlo es un problema de seguridad.

Bajo algunos sistemas operativos, el fsid puede usarse como el segundo argumento de la sysfs(2) llamada al sistema.

ESTÁNDARES

Linux.

HISTORIA

El Linux statfs() fue inspirado por el de 4.4BSD (pero no usan la misma estructura).

El Linux original statfs() y fstatfs() llamadas al sistema no fueron diseñadas pensando en tamaños de archivo extremadamente grandes. Posteriormente, Linux 2.6 añadió nuevas statfs64() y fstatfs64() llamadas al sistema que emplean una nueva estructura, statfs64. La nueva estructura contiene los mismos campos que la estructura original statfs , pero los tamaños de varios campos se incrementan, para acomodar grandes tamaños de archivo. Las funciones envolventes de glibc statfs() y fstatfs() manejan de forma transparente las diferencias del kernel.

LSB ha obsoleto las llamadas a la biblioteca statfs() y fstatfs() y nos dice que usemos statvfs(3) y fstatvfs(3) en su lugar.

NOTAS

El __fsword_t tipo usado para varios campos en la definición de la estructura statfs es un tipo interno de glibc, no destinado al uso público. Esto deja al programador en un poco de un dilema al intentar copiar o comparar estos campos con variables locales en un programa. Usar unsigned int para tales variables es suficiente en la mayoría de sistemas.

Algunos sistemas tienen solo <sys/vfs.h>, otros sistemas también tienen <sys/statfs.h>, donde el primero incluye al segundo. Así que parece que incluir el primero es la mejor opción.

ERRORES CONOCIDOS

Desde Linux 2.6.38 hasta Linux 3.1 inclusive, fstatfs() fallaba con el error ENOSYS para descriptores de archivo creados por pipe(2).
