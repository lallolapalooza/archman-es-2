DESCRIPCIÓ

N

Dados node y service, que identifican un host de Internet y un servicio, getaddrinfo() devuelve una o más estructuras addrinfo, cada una de las cuales contiene una dirección de Internet que puede especificarse en una llamada a bind(2) o connect(2). La función getaddrinfo() combina la funcionalidad proporcionada por las funciones gethostbyname(3) y getservbyname(3) en una sola interfaz, pero a diferencia de estas últimas

funciones,

getaddrinfo() es reentrante y permite a los programas eliminar las dependencias de IPv4 frente a IPv6. La estructura addrinfo utilizada

por

(POSIX especifica valores predeterminados diferentes para ai_flags; ver NOTAS.) node especifica una dirección de red numérica (para IPv4, notación de números y puntos según la soportada por inet_aton(3); para IPv6, formato de cadena hexadecimal según lo soportado por inet_pton(3)), o un nombre de host de red, cuyas direcciones de red se buscan y resuelven. Si hints.ai_flags contiene la bandera AI_NUMERICHOST, entonces node debe ser una dirección de red numérica. La bandera AI_NUMERICHOST suprime cualquier búsqueda potencialmente larga de direcciones de host de red. Si

la

bandera AI_PASSIVE está especificada en hints.ai_flags, y node es NULL, entonces las direcciones de socket devueltas serán adecuadas para hacer bind(2) a un socket que aceptará conexiones con accept(2). La dirección de socket devuelta contendrá la "dirección comodín" ( INADDR_ANY para direcciones IPv4,IN6ADDR_ANY_INIT para direcciones IPv6). La dirección comodín es utilizada por aplicaciones (típicamente servidores) que pretenden aceptar conexiones en cualquiera de las direcciones de red del host. Si node no es NULL, entonces la bandera AI_PASSIVE se ignora. Si

la

bandera AI_PASSIVE no está establecida en hints.ai_flags, entonces las direcciones de socket devueltas serán adecuadas para usarse con connect(2), sendto(2) o sendmsg(2). Si node es NULL, entonces la dirección de red se establecerá en la dirección de la interfaz de bucle ( INADDR_LOOPBACK para direcciones IPv4,IN6ADDR_LOOPBACK_INIT para direcciones IPv6); esto es usado por aplicaciones que pretenden comunicarse con pares que se ejecutan en el mismo host. service establece el puerto en cada estructura de dirección devuelta. Si este argumento es un nombre de servicio

(ver

services(5)), se traduce al número de puerto correspondiente. Este argumento también puede especificarse como un número decimal, que simplemente se convierte a binario. Si service es NULL, entonces el número de puerto de las direcciones de socket devueltas quedará sin inicializar. Si AI_NUMERICSERV está especificado en hints.ai_flags y service no es NULL, entonces service debe apuntar a una cadena que contenga un número de puerto numérico. Esta bandera se usa para inhibir la invocación de un servicio de resolución de nombres en casos donde se sabe que no es necesario. Tant

Los elementos de la lista enlazada están enlazados por el campo ai_next. Hay varias razones por las que la lista enlazada puede tener más de

Normalmente, la aplicación debe intentar usar las direcciones en el orden en que se devuelven.
