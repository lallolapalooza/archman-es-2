DESCRIPCIÓ

N

fwknopd es el componente servidor del FireWall Knock Operator, y es responsable de monitorizar y procesar los paquetes de Autorización de Paquete Único (SPA) que son generados por clientes fwknop, modificando una política de firewall o ACL para permitir el acceso deseado después de autenticar y descifrar un paquete SPA válido (en ese orden), y eliminando el acceso después de un tiempo de espera

configurable.

La aplicación principal de este programa es ocultar servicios como por ejemplo SSH con una capa adicional de seguridad para hacer que la explotación de vulnerabilidades (tanto de día cero como de código sin parchear) sea mucho más difícil. Además, los servicios que se ocultan de esta manera naturalmente no pueden ser escaneados con Nmap o Shodan

.

La configuración principal de fwknopd se mantiene dentro de dos archivos: fwknopd.conf y access.conf. La ubicación predeterminada para estos archivos se determina en la configuración del paquete (típicamente /etc/fwknop). Las variables de configuración dentro de estos archivos se describen a

continuación.

Se puede encontrar información adicional en el tutorial “Single Packet Authorization: A Comprehensive Guide to Strong Service Concealment with fwknop” disponible en línea (ver: http://www.cipherdyne.org/fwkn

op/docs/fwknop-
tutorial.html).

VARIABLES DE CONFIGURACIÓN Y ACCESO DE FWKNOPD

fwknopd hace referencia al archivo /etc/fwknop/fwknopd.conf para obtener variables de configuración que definen parámetros operativos (qué interfaz de red y puerto espiar, qué funciones habilitar/deshabilitar, etc.). El archivo fwknopd.conf no define ninguna directiva de control de acceso ni establece claves de cifrado o autenticación.

Las directivas de control de acceso se encuentran en el archivo /etc/fwknop/access.conf. Las directivas de control de acceso definen las claves de cifrado y el nivel de acceso que se otorga a un cliente fwknop que ha generado el mensaje SPA cifrado apropiado.

VARIABLES DE FWKNOPD.CONF

Esta sección enumera las variables de configuración más importantes utilizadas por fwknopd. Querrá asegurarse de verificar que tengan los valores apropiados, pero se proporcionan valores predeterminados sensatos para la mayoría de los sistemas. Consulte el archivo /etc/fwknop/fwknopd.conf para obtener detalles adicionales.

PCAP_INTF <interfaz>

Especifica la interfaz de red en la que fwknopd espiará los paquetes.

ENABLE_PCAP_PROMISC <S/N>

Por defecto, fwknopd pone la interfaz pcap en modo promiscuo. Establezca esto en “N” para deshabilitar ese comportamiento (no promiscuo).

PCAP_FILTER <especificación de filtro pcap>

Define el filtro utilizado para los modos PCAP; fwknopd usa por defecto el puerto UDP 62201. Sin embargo, si un cliente fwknop utiliza la opción --rand-port para enviar el paquete SPA a través de un puerto aleatorio, entonces esta variable debe actualizarse a algo como “udp dst portrange 10000-65535”.

ENABLE_SPA_PACKET_AGING <S/N>

Esto instruye a fwknopd a no honrar los paquetes SPA que tengan una marca de tiempo antigua. El valor de “antiguo” se define por la variable “MAX_SPA_PACKET_AGE”. Si “ENABLE_SPA_PACKET_AGING” se establece en “N”, fwknopd no utilizará la marca de tiempo del cliente en absoluto.

MAX_SPA_PACKET_AGE <segundos>

Define la edad máxima (en segundos) que se aceptará un paquete SPA. Esto requiere que el sistema cliente esté en sincronización de tiempo relativamente cercana con el sistema servidor fwknopd (NTP es bueno). La edad predeterminada es 120 segundos (dos minutos).

ENABLE_DIGEST_PERSISTENCE <S/N>

Rastrea las sumas de digestos asociadas con paquetes SPA anteriores procesados por fwknopd. Esto permite que las sumas de digestos permanezcan persistentes entre ejecuciones de fwknopd. El valor predeterminado es “S”. Si se establece en “N”, fwknopd no verificará los datos del paquete SPA entrante contra ningún digest guardado previamente. Es una buena idea dejar esta función activada para reducir la posibilidad de ser vulnerable a un ataque de repetición.

RULES_CHECK_THRESHOLD <contador>

Define el número de veces que se deben verificar las expiraciones de las reglas de firewall antes de ejecutar una verificación "profunda". Esto permite que fwknopd elimine reglas que contienen una exp<tiempo> apropiada, incluso si un programa de terceros las agregó en lugar de fwknopd. El valor predeterminado para esta variable es 20, y esto generalmente resulta en que esta verificación se ejecute cada dos segundos aproximadamente. Para deshabilitar este tipo de verificación por completo, establezca esta variable en cero.

ENABLE_IPT_FORWARDING <S/N>

Permite a los clientes SPA solicitar acceso a servicios a través de un firewall iptables en lugar de solo a él (es decir, acceso a través de la cadena FWKNOP_FORWARD en lugar de la cadena INPUT).

ENABLE_IPT_LOCAL_NAT <S/N>

Permite a los clientes SPA solicitar acceso a un socket local a través de NAT. Esto todavía inserta una regla ACCEPT en la cadena FWKNOP_INPUT, pero se traduce un puerto diferente a través de reglas DNAT al real. Por lo tanto, el usuario haría “ssh -p <puerto>” para acceder al servicio local (consulte --NAT-local y --NAT-rand-port en la línea de comandos del cliente fwknop).

ENABLE_IPT_SNAT <S/N>

Establezca esto en “S” para habilitar una regla SNAT correspondiente. Por defecto, si el acceso de reenvío está habilitado (consulte la variable “ENABLE_IPT_FORWARDING” anterior), entonces fwknopd crea reglas DNAT para las conexiones entrantes, pero no las complementa con reglas SNAT al mismo tiempo. En algunas situaciones, los sistemas internos pueden no tener una ruta de salida para la dirección de origen de la conexión entrante, por lo que es necesario aplicar también reglas SNAT para que los sistemas internos vean la IP de la interfaz interna donde se está ejecutando fwknopd.

SNAT_TRANSLATE_IP <direccion_ip>

Especifica la dirección IP para SNAT. Esta funcionalidad solo se habilita cuando “ENABLE_IPT_SNAT” se establece en “S” y, por defecto, las reglas SNAT se construyen con el objetivo MASQUERADE (ya que la IP interna no tiene que definirse aquí en el archivo /etc/fwknop/fwknopd.conf), pero si desea que fwknopd utilice el objetivo SNAT, también debe definir una dirección IP con la variable “SNAT_TRANSLATE_IP”. Tenga en cuenta que esta variable está generalmente obsoleta en favor de la variable “FORCE_SNAT” en el archivo /etc/fwknop/access.conf, que habilita el control por stanza sobre la IP SNAT.

ENABLE_IPT_OUTPUT <S/N>

Agrega reglas ACCEPT a la cadena FWKNOP_OUTPUT. Esto generalmente solo es útil si no hay reglas de seguimiento de estado para permitir la salida de respuestas de conexión y la cadena OUTPUT tiene una postura de caída por defecto.

MAX_SNIFF_BYTES <bytes>

Especifica el número máximo de bytes a espiar por trama. 1500 es el valor predeterminado.

FLUSH_IPT_AT_INIT <S/N>

Vacía todas las reglas existentes en las cadenas de fwknop al inicio de fwknopd. El valor predeterminado es “S”.

FLUSH_IPT_AT_EXIT <S/N>

Vacía todas las reglas existentes en las cadenas de fwknop cuando fwknopd se detiene o sale limpiamente. El valor predeterminado es “S”.

EXIT_AT_INTF_DOWN <S/N>

Cuando fwknopd está espiando una interfaz, si la interfaz se desactiva administrativamente o se desconecta, fwknopd saldrá limpiamente y se asume que cualquier infraestructura de monitoreo de procesos como systemd o upstart la reiniciará. Sin embargo, si fwknopd no está siendo monitoreado por systemd, upstart o cualquier otra cosa, este comportamiento se puede deshabilitar con la variable “EXIT_AT_INTF_DOWN”. Si está deshabilitado, fwknopd intentará recuperarse cuando una interfaz caída vuelva a estar activa.

ENABLE_RULE_PREPEND <S/N>

Para sistemas que ejecutan iptables o firewalld, haga que fwknopd inserte nuevas reglas SPA al principio de la cadena relevante (como “FWKNOP_INPUT”) en lugar de anexarlas al final de la cadena. Esto hace que las reglas recién creadas tengan precedencia sobre las anteriores.

ENABLE_NAT_DNS <S/N>

Permite que fwknopd resuelva nombres de host en mensajes de acceso NAT.

GPG_HOME_DIR <ruta>

Si se utilizan claves GPG en lugar de una clave simétrica Rijndael, este es el directorio de claves GPG predeterminado. Tenga en cuenta que cada stanza de acceso en /etc/fwknop/access.conf puede especificar su propio directorio GPG para anular este valor predeterminado. Si no se establece aquí o en una stanza de access.conf, entonces es el directorio $HOME/.gnupg del usuario que ejecuta fwknopd (lo más probable es que sea root).

GPG_EXE <ruta>

Especifica la ruta a GPG, y por defecto es /usr/bin/gpg si no se establece.

LOCALE <locale>

Permitir a fwknopd adquirir datos SPA de peticiones HTTP (generadas con el cliente fwknop en modo --HTTP). Tenga en cuenta que cuando esto está habilitado, la variable “PCAP_FILTER” necesitaría ser actualizada para rastrear tráfico sobre conexiones TCP/80 y un servidor web debería estar ejecutándose en el mismo servidor que fwknopd

Habilitar el servidor TCP de fwknopd. Este es un servidor TCP "ficticio" que aceptará peticiones de conexión TCP en el puerto TCPSERV_PORT especificado. Como se esperaría, cuando el servidor UDP es usado, ningún paquete entrante es nunca reconocido por fwknopd y por lo tanto la recolección de paquetes SPA en este modo es una buena alternativa a rastrear el cable

VARIABLES DE ACCESS.

CONF

Esta sección describe las directivas de control de acceso en el archivo /etc/fwknop/access.conf. Estas directivas definen claves de cifrado y autenticación, y el nivel de acceso que es otorgado a clientes fwknop que han generado un paquete SPA encriptado y autenticado

apropiado.

Las variables access.conf descritas a continuación proporcionan las directivas de acceso para los paquetes SPA con una IP de origen (o solicitud embebida) que coincide con una dirección o rango de red definido por la variable “SOURCE”. Todas las variables que siguen a “SOURCE” aplican a la fuente stanza. Cada directiva “SOURCE” inicia una nueva

stanza.

SOURCE <IP,..,IP/RED,..,

RED/ANY>
Esto define la dirección de origen desde la cual el paquete SPA será aceptado. La cadena “ANY” también es aceptada si un paquete SPA válido debe ser honrado desde cualquier IP de origen. Cada stanza de autorización en la definición de /etc/fwknop/access.conf debe comenzar con la palabra clave “SOURCE”. Las redes deben ser especificadas en notación CIDR (por ejemplo “192.168.10.0/24”), y las direcciones IP individuales pueden ser especificadas también. Además, múltiples IPs y/o redes pueden ser definidas como una lista separada por comas (por ejemplo “192.168.10.0/24,10.1.1.
123”)

DESTINATION <IP,..,IP/RED,..,

RED/ANY>
Esto define la dirección de destino para la cual el paquete SPA será aceptado. La cadena “ANY” también es aceptada si un paquete SPA válido debe ser honrado hacia cualquier IP de destino. Las redes deben ser especificadas en notación CIDR (por ejemplo “192.168.10.0/24”), y las direcciones IP individuales pueden ser especificadas también. Además, múltiples IPs y/o redes pueden ser definidas como una lista separada por comas (por ejemplo “192.168.10.0/24,10.1.1.
123”)

OPEN_PORTS <proto/puerto>,...,

<proto/puerto>
Define un conjunto de puertos y protocolos (tcp o udp) que serán abiertos si una secuencia de toques válida es vista. Si esta entrada no está establecida, fwknopd intentará honrar cualquier solicitud de proto/puerto especificada en los datos SPA (a menos que coincida con alguna entrada “RESTRICT_PORTS”). Múltiples entradas están separadas por
comas.

RESTRICT_PORTS <proto/puerto>,...,

<proto/puerto>
Define un conjunto de puertos y protocolos (tcp o udp) que son explícitamente no permitidos independientemente de la validez del paquete SPA entrante. Múltiples entradas están separadas por
comas.

KEY <frase de

contraseña>
Define la clave simétrica usada para descifrar un paquete SPA entrante que es encriptado por el cliente fwknop con Rijndael. La clave de encriptación real que es usada se deriva del algoritmo estándar PBKDF1. Esta variable es requerida para todos los paquetes SPA a menos que GnuPG sea usado en su lugar (vea las variables GPG a continuación)
.

KEY_BASE64 <frase de contraseña codificada en

base64>
Igual que la opción KEY de arriba, pero especifica la clave simétrica como una cadena codificada en base64. Esto permite que caracteres no ascii sean incluidos en la clave decodificada de
base64.

HMAC_KEY <clave

>
Especificar la clave HMAC para el cifrado autenticado de paquetes SPA. Esto soporta tanto los modos de encriptación Rijndael como GPG, y es aplicado de acuerdo al modelo de encriptar-luego-autenticar
.

HMAC_KEY_BASE64 <clave codificada en

base64>
Especificar la clave HMAC como una cadena codificada en base64. Esto permite que caracteres no ascii sean incluidos en la clave decodificada de
base64.

FW_ACCESS_TIMEOUT <segundos

>
Define la longitud de tiempo que el acceso será otorgado por fwknopd a través del firewall después de una secuencia de toques válida desde una dirección IP de origen. Si “FW_ACCESS_TIMEOUT” no está establecido entonces el tiempo de espera predeterminado de 30 segundos será establecido automáticamente
.

%include <archivo

>
Hacer que fwknopd importe un archivo access.conf adicional. Esto permite que más stanzas de acceso sean definidas en otras ubicaciones en el sistema de archivos, y esto puede ser ventajoso en algunos escenarios al dejar que usuarios no privilegiados definan sus propias claves de encriptación y autenticación para operaciones SPA. De esta manera, los usuarios no necesitan acceso de escritura al archivo principal /etc/fwknop/access.conf para cambiar claves o definir
nuevas.

%include_folder <directorio

>
De manera similar a la opción %include de arriba, la directiva %include_folder tiene a fwknopd importar todos los archivos .conf del directorio especificado. También hay soporte de línea de comandos para esto a través de la opción access-
folder.

ENCRYPTION_MODE <modo

>
Especificar el modo de encriptación cuando AES es usado. El valor predeterminado es el modo CBC, pero otros modos pueden ser seleccionados como OFB y CFB. En general, se recomienda no usar esta variable y dejarla como la predeterminada. Tenga en cuenta que la cadena “legacy” puede ser especificada para generar paquetes SPA con la estrategia de vector de inicialización antigua usada por versiones de fwknop antes de 2.5. Con la versión 2.5, fwknop usa PBKDF1 para la derivación de
claves.

HMAC_DIGEST_TYPE <algoritmo de

resumen>
Especificar el algoritmo de resumen para la autenticación de paquetes SPA entrantes. Debe ser uno de MD5, SHA1, SHA256, SHA384, SHA512, SHA3_256, o SHA3_512. Este es un campo opcional, y si no es especificado entonces fwknopd usa por defecto SHA256 si la stanza de acceso requiere un
HMAC.

ACCESS_EXPIRE <MM/DD/AAAA

>
Define una fecha de expiración para la stanza de acceso en formato MM/DD/AAAA. Todos los paquetes SPA que coincidan con una stanza expirada serán ignorados. Estarameter es
opcional.

ACCESS_EXPIRE_EPOCH <segundos

>
Define una fecha de caducidad para la stanza de acceso como el tiempo epoch, y es útil si se necesita dar un tiempo de caducidad más preciso que la resolución de día ofrecida por la variable ACCESS_EXPIRE anterior. Todos los paquetes SPA que coincidan con una stanza caducada serán ignorados. Este parámetro es
opcional.

ENABLE_CMD_EXEC <Y/N

>
Esto le indica a fwknopd que acepte comandos completos que están contenidos dentro de un paquete de autorización. Cualquier tal comando será ejecutado en el servidor fwknopd como el usuario especificado por “CMD_EXEC_USER” o como el usuario que inició fwknopd si eso no está
establecido.

ENABLE_CMD_SUDO_EXEC <Y/N

>
sudo proporciona un medio poderoso para restringir los conjuntos de comandos que los usuarios pueden ejecutar a través del archivo “sudoers”. Al habilitar esta característica (y en el modo “ENABLE_CMD_EXEC”), todos los comandos entrantes de paquetes SPA válidos serán prefijados por “/path/to/sudo -u <user> -g <group>” donde la ruta a sudo es establecida por la variable “SUDO_EXE”, “<user>” es establecida por la variable “CMD_SUDO_EXEC_USER” (por defecto es “root” si no está establecida), y “<group>” es establecida por “CMD_SUDO_EXEC_GROUP” (por defecto también es “root” si no está establecida)
.

CMD_EXEC_USER <nombre de

usuario>
Especifica el usuario (vía setuid) que ejecutará un comando contenido dentro de un paquete SPA. Si esta variable no es dada, fwknopd ejecutará el comando como el usuario bajo el cual está corriendo (muy probablemente root). Es altamente recomendable establecer esto a un usuario no root como “nobody” si no se necesitan permisos
elevados.

CMD_SUDO_EXEC_USER <nombre de

usuario>
Especifica el usuario (vía “sudo -u <user>”) que ejecutará un comando contenido dentro de un paquete SPA. Si esta variable no es dada, fwknopd asumirá que el comando debe ser ejecutado como
root.

CMD_EXEC_GROUP <nombre de

grupo>
Especifica el grupo (vía setgid) que ejecutará un comando contenido dentro de un paquete SPA. Si esta variable no es dada, fwknopd ejecutará el comando como el usuario bajo el cual está corriendo (muy probablemente root). Es altamente recomendable establecer esto a un usuario no root como “nobody” si no se necesitan permisos
elevados.

CMD_SUDO_EXEC_GROUP <nombre de

grupo>
Especifica el grupo (vía “sudo -g <group>”) que ejecutará un comando contenido dentro de un paquete SPA. Si esta variable no es dada, fwknopd asumirá que el comando debe ser ejecutado como
root.

CMD_CYCLE_OPEN <comando

>
Especifica un ciclo de comando de apertura/cierre a ser ejecutado al recibir un paquete SPA válido. Esta directiva establece el comando inicial, y está destinada a ser usada en conjunto con la variable “CMD_CYCLE_CLOSE” de abajo. La aplicación principal de esta característica es permitir que fwknopd interactúe con firewalls o ACLs que no son soportados nativamente, y facilitar el mismo modelo de acceso que para los firewalls principales soportados como iptables. Es decir, un comando es ejecutado para abrir el firewall o ACL, y luego un comando de cierre correspondiente es ejecutado después de que un temporizador expire. Tanto las variables “CMD_CYCLE_OPEN” como “CMD_CYCLE_CLOSE” soportan cadenas de sustitución especiales para permitir que valores sean tomados del payload del SPA y usados en la línea de comando del comando ejecutado. Estas cadenas comienzan con un carácter “$”, e incluyen “$IP” (la IP de permitir descifrada del payload del SPA), “$SRC” (sinónimo de “$IP”), “$PKT_SRC” (la IP de origen en la cabecera de la capa de red del paquete SPA), “$DST” (la IP de destino), “$PORT” (el puerto de permitir), y “$PROTO” (el protocolo de permitir), “$TIMEOUT” (establecer el timeout del cliente si se especifica)
.

CMD_CYCLE_CLOSE <comando

>
Especifica el comando de cierre que corresponde al comando de apertura establecido por la variable “CMD_CYCLE_OPEN” descrita arriba. Las mismas sustituciones de cadenas como “$IP”, “$PORT”, y “$PROTO” son soportadas. Además, el valor especial “NONE” puede ser establecido para permitir que ningún comando de cierre sea ejecutado después del comando de apertura. Esto podría ser útil en ciertas situaciones donde, digamos, se desea y se permite acceso
indefinido.

CMD_CYCLE_TIMER <segundos

>
Establece el número de segundos después de los cuales el comando de cierre establecido en “CMD_CYCLE_CLOSE” será ejecutado. Esto define el intervalo del temporizador de apertura/cierre
.

SUDO_EXE <ruta

>
Define la ruta al binario de sudo. Por defecto es “/usr/bin/sudo”
.

REQUIRE_USERNAME <nombre de

usuario>
Requiere un nombre de usuario específico del sistema cliente tal como está codificado en los datos del SPA. Esta variable es opcional y si no es especificada, el dato del nombre de usuario en los datos del SPA es
ignorado.

REQUIRE_SOURCE_ADDRESS <Y/N

>
Fuerza a todos los paquetes SPA a contener una dirección IP real dentro de los datos encriptados. Esto hace imposible usar el argumento de línea de comando -s en la línea de comando del cliente fwknop, así que o bien -R tiene que ser usado para resolver automáticamente la dirección externa (si el cliente está detrás de un NAT) o el cliente debe conocer la IP externa y establecerla a través del argumento
-a.

REQUIRE_SOURCE_ADDRESS <Y/N

>
Sinónimo para “REQUIRE_SOURCE_ADDRESS”
.

FORCE_NAT <IP>

<PUERTO>
Para cualquier paquete SPA válido, fuerza a que la conexión solicitada sea NATeada hacia el valor de IP y puerto (usualmente interno) especificado. Esto es útil si hay múltiples sistemas internos ejecutando un servicio como SSHD, y quieres dar acceso transparente a solo un sistema interno por cada stanza en el archivo access.conf. De esta manera, múltiples usuarios externos pueden cada uno acceder directamente a solo un sistema interno por clave
SPA.

FORCE_SNAT <IP

>
Para cualquier paquete SPA válido, añade una regla SNAT en adición a cualquier regla DNAT creada con la variable FORCE_NAT correspondiente (requerida). Esto es análogo a “SNAT_TRANSLATE_IP” del archivo /etc/fwknop/fwknopd.conf excepto que es por stanza de acceso y anula cualquier valor establecido con “SNAT_TRANSLATE_IP”. Esto es útil para situaciones donde una conexión NATeada entrante podría ser de otro modo irrespondera debido a restricciones de enrutamiento (es decir, el sistema que recibe la conexión autenticada SPA tiene una ruta por defecto hacia un dispositivo diferente al del propio sistema SPA)
.

FORCE_MASQUERADE <Y/N

>
Esto es similar a la variable “FORCE_SNAT”, excepto que no es necesario también especificar una dirección IP para las reglas SNAT porque el objetivo MASQUERADE es usado en su
lugar.

FORWARD_ALL <Y/N

>
En escenarios NAT, controla si todo el tráfico es reenviado a través del sistema fwknopd en oposición a solo reenviar conexiones a servicios específicos como es solicitado por el cliente fw
knop.

DISABLE_DNAT <Y/N

>
Controla si las reglas DNAT son creadas en escenarios FORCE_NAT. Esto es usado principalmente en conjunto con la variable FORWARD_ALL para permitir que fwknopd actúe esencialmente como una puerta de enlace SPA. Es decir, el cliente fwknop es usado para ganar acceso vía SPA al Internet más amplio después de serle concedida una IP vía DHCP, pero antes de enviar el paquete SPA todo el tráfico es bloqueado por defecto hacia el
Internet.

GPG_DECRYPT_ID <keyID

>
Define un ID de clave GnuPG a usar para descifrar mensajes SPA que han sido encriptados por un cliente fwknop. Esta palabra clave es requerida para la autenticación basada en claves GPG. El llavero GPG en el cliente debe haber importado y firmado la clave del servidor fwknopd, y viceversa. Está bien usar una clave GPG personal sensible en el cliente, pero cada servidor fwknopd debe tener su propia clave GPG que es generada específicamente para las comunicaciones fwknop. La razón para esto es que la contraseña de descifrado para la clave del servidor debe ser colocada dentro del archivo /etc/fwknop/access.conf para que fwknopd funcione (debe ser capaz de descifrar mensajes SPA que han sido encriptados con la clave pública del servidor). Para más información sobre el uso de fwknop con claves GnuPG, ver el siguiente enlace: “http://www.cipherdyne.org/fwknop/do
cs/gpghowto.html”.

GPG_DECRYPT_PW <contraseña de

descifrado>
Especifica la contraseña de descifrado para la clave gpg definida por la “GPG_DECRYPT_ID” de arriba. Este es un campo requerido para la autenticación basada en
gpg.

GPG_ALLOW_NO_PW <Y/N

>
Permite a fwknopd aprovechar un par de claves GnuPG que no tiene una contraseña asociada. Aunque esto pueda sonar como un modo de despliegue controvertido, en entornos automatizados tiene sentido porque "usualmente no hay manera de almacenar una contraseña de forma más segura que en el llavero secreto mismo" según: “http://www.gnupg.org/faq/GnuPG-FAQ.html#how-can-i-use-gnupg-in-an-automated-environment”. Usar esta característica y remover la frase de paso de un par de claves GnuPG es útil en algunos entornos donde libgpgme es forzado a usar gpg-agent y/o pinentry para recolectar una frase de
paso.

GPG_REQUIRE_SIG <Y/N

>
Con este ajuste establecido a Y, fwknopd verifica todos los mensajes SPA encriptados con GPG por una firma (firmada por la clave del remitente). Si el mensaje entrante no está firmado, el proceso de descifrado fallará. Si no está establecido, el valor por defecto es Y
.

GPG_DISABLE_SIG <Y/N

>
Deshabilita la verificación de firmas para mensajes SPA entrantes. Este no es un ajuste recomendado, y el valor por defecto es N
.

GPG_IGNORE_SIG_VERIFY_ERROR <Y/N

>
Establecer esto permitirá a fwknopd aceptar paquetes entrantes encriptados con GPG que están firmados, pero la firma no pasó la verificación (es decir, la clave del firmante estaba caducada, etc.). Este ajuste solo aplica si GPG_REQUIRE_SIG también está establecido a Y
.

GPG_REMOTE_ID <keyID,...,

keyID>
Define una lista de IDs de clave gpg que son requeridos para haber firmado cualquier mensaje SPA entrante que ha sido encriptado con la clave del servidor fwknopd. Esto asegura que la verificación del usuario remoto es lograda vía un mecanismo criptográfico fuerte. Firma La verificación está habilitada de forma predeterminada y solo se puede desactivar si se establece “GPG_DISABLE_SIG” a Y (no es una configuración recomendada). Separe múltiples entradas con una
coma.

GPG_FINGERPRINT_ID <keyID,...,

keyID>
Especifique un conjunto de huellas digitales completas de claves GnuPG en lugar de los identificadores de clave más cortos establecidos con la variable “GPG_REMOTE_ID”. Aquí hay un ejemplo de huella digital para una de las claves de la suite de pruebas de fwknop: 00CC95F05BC146B6AC4038C9E36F443C6A3FAD56
.

GPG_HOME_DIR <path

>
Defina la ruta al directorio GnuPG que utilizará el servidor fwknopd. Si esta palabra clave no se especifica dentro de /etc/fwknop/access.conf, entonces fwknopd utilizará por defecto el directorio /root/.gnupg para la(s) clave(s) del servidor de los paquetes SPA entrantes manejados por la sección coincidente de access.c
onf.

GPG_EXE <path

>
Defina la ruta al ejecutable GnuPG. Si esta palabra clave no se especifica dentro de /etc/fwknop/access.conf, entonces fwknopd utilizará por defecto /usr/
bin
/g
pg.

DEPENDENCIA

S

fwknopd requiere libfko, que normalmente se incluye tanto en las distribuciones de código fuente como en las binarias, y es una biblioteca dedicada desarrollada por el proyecto

fwknop.

Para el rastreo de paquetes, fwknopd actualmente requiere libpcap, pero las versiones futuras (opcionalmente) eliminarán esta

dependencia.

Para la funcionalidad GPG, GnuPG también debe estar correctamente instalado y configurado junto con la biblioteca

libgpgme.

Para aprovechar todas las características de autenticación y gestión de acceso del demonio/servicio fwknopd, se requiere un cortafuegos iptable

s, ipfw o pf funcionando en el
sistema operativo subyacente.

DIAGNÓSTIC

O

fwknopd se puede ejecutar en modo de depuración combinando las opciones de línea de comandos -f, --foreground y -v, --verbose. Esto desactivará la ejecución en modo demonio e imprimirá información detallada en la pantalla en stderr a medida que se reciben

paquetes.

La forma más completa de obtener información de diagnóstico sobre fwknopd es ejecutar el script de la suite de pruebas test-fwknop.pl ubicado en el directorio test/ en las fuentes de fwknop. La suite de pruebas ejecuta envía fwknop a través de un gran número de pruebas en tiempo de ejecución, tiene soporte para valgrind, valida tanto el cifrado SPA como los resultados HMAC cont

ra OpenSSL, e incluso tiene su propio fuz
zer integrado para las comunicaciones SPA.
