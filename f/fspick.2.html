fspick(2) Manuales de llamadas al sistema fspick(2)

NAME

fspick - seleccionar un sistema de archivos para la reconfiguración

LIBRARY

Biblioteca estándar C (libc, -lc)

SYNOPSIS

#include <fcntl.h>          /* Definición de las constantes AT_* */
#include <sys/mount.h>
int fspick(int dirfd, const char *path, unsigned int flags);

DESCRIPTION

La llamada al sistema fspick() forma parte del conjunto de instalaciones de montaje basadas en descriptores de archivo en Linux.

fspick() crea un nuevo contexto de configuración de sistema de archivos para la instancia existente de sistema de archivos asociada con el camino descrito por dirfd y path, lo coloca en modo de reconfiguración (similar a mount(8) con la opción -o remount). Se devuelve entonces un nuevo descriptor de archivo asociado con el contexto de configuración de sistema de archivos. El proceso llamante debe tener la capacidad CAP_SYS_ADMIN para crear un nuevo contexto de configuración de sistema de archivos.

El descriptor de archivo resultante se puede utilizar con fsconfig(2) para especificar el conjunto deseado de cambios en los parámetros de sistema de archivos de la instancia de sistema de archivos. Una vez que se han configurado los cambios deseados, los cambios se pueden aplicar llamando a fsconfig(2) con el comando FSCONFIG_CMD_RECONFIGURE. En contraste con el comportamiento de MS_REMOUNT con mount(2), fspick() instancia el contexto de configuración de sistema de archivos con una copia de los parámetros de sistema de archivos del sistema de archivos existente; por lo tanto, las operaciones posteriores FSCONFIG_CMD_RECONFIGURE actualizarán únicamente los parámetros de sistema de archivos modificados explícitamente con fsconfig(2).

Al igual que con las llamadas al sistema "*at()", fspick() utiliza el argumento dirfd junto con el argumento path para determinar el camino a operar, de la siguiente manera:

•
Si el nombre de ruta dado en path es absoluto, entonces dirfd es ignorado.
•
Si el nombre de ruta dado en path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta relativo al directorio de trabajo actual del proceso llamante (como open(2)).
•
Si el nombre de ruta dado en path es relativo, entonces se interpreta relativo al directorio al que se refiere el descriptor de archivo dirfd (en lugar de relativo al directorio de trabajo actual del proceso llamante, como se hace con open(2) para un nombre de ruta relativo). En este caso, dirfd debe ser un directorio que se abrió para lectura (O_RDONLY) o utilizando la bandera O_PATH.
•
Si path es una cadena vacía y flags contiene FSPICK_EMPTY_PATH, entonces se opera directamente en el descriptor de archivo dirfd. En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio.

Vea openat(2) para una explicación de por qué el argumento dirfd es útil.

flags se puede utilizar para controlar aspectos de cómo se resuelve path y propiedades del descriptor de archivo devuelto. Un valor para flags se construye realizando una operación OR bitwise con cero o más de las siguientes constantes:

FSPICK_CLOEXEC
Establece la bandera close-on-exec (FD_CLOEXEC) en el nuevo descriptor de archivo. Vea la descripción de la bandera O_CLOEXEC en open(2) para conocer las razones por las cuales esto puede ser útil.
FSPICK_EMPTY_PATH
Si path es una cadena vacía, operar en el archivo al que se refiere dirfd (que puede haber sido obtenido de open(2), fsmount(2), o open_tree(2)). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio. Si dirfd es AT_FDCWD, fspick() operará en el directorio de trabajo actual del proceso llamante.
FSPICK_SYMLINK_NOFOLLOW
No seguir enlaces simbólicos en el componente terminal de path. Si path se refiere a un enlace simbólico, el contexto de sistema de archivos devuelto se referirá al sistema de archivos en el que reside el enlace simbólico mismo.
FSPICK_NO_AUTOMOUNT
No montar automáticamente el componente (nombre base) terminal de path si es un directorio que es un punto de montaje automático. Esto permite reconfigurar un punto de montaje automático, en lugar de la ubicación que sería montada. Esta bandera no tiene efecto si el punto de montaje automático ya ha sido montado sobre él.

Al igual que con los contextos de sistema de archivos creados con fsopen(2), el descriptor de archivo devuelto por fspick() se puede consultar para cadenas de mensaje en cualquier momento llamando a read(2) en el descriptor de archivo. (Vea la sección de subsección "Interfaz de recuperación de mensajes" en fsopen(2) para más detalles sobre el formato del mensaje).

RETURN VALUE

En caso de éxito, se devuelve un nuevo descriptor de archivo. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORS

EACCES
Se deniega permiso de búsqueda para uno de los directorios en el prefijo de camino de path. (Vea también path_resolution(7).)
EBADF
path es relativo pero dirfd ni es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
path es NULL o un puntero a una ubicación fuera del espacio de direcciones accesible del proceso llamante.
EINVAL
Bandera inválida especificada en flags.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver path.
EMFILE
El proceso llamante tiene demasiados archivos abiertos para crear más.
ENAMETOOLONG
path es más largo que PATH_MAX.
ENFILE
El sistema tiene demasiados archivos abiertos para crear más.
ENOENT
Un componente de path no existe, o es un enlace simbólico colgante.
ENOENT
path es una cadena vacía, pero no se especifica FSPICK_EMPTY_PATH en flags.
ENOTDIR
Un componente del prefijo de camino de path no es un directorio; o path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo diferente a un directorio.
ENOMEM
El kernel no pudo asignar suficiente memoria para completar la operación.
EPERM
El proceso llamante no tiene la capacidad requerida CAP_SYS_ADMIN.

STANDARDS

Linux.

HISTORY

Linux 5.2. glibc 2.36.

EXAMPLES

El siguiente ejemplo establece la bandera read-only en la instancia de sistema de archivos referenciada por el objeto de montaje adjunto en /tmp.


int fsfd = fspick(AT_FDCWD, "/tmp", FSPICK_CLOEXEC);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "ro", NULL, 0);
fsconfig(fsfd, FSCONFIG_CMD_RECONFIGURE, NULL, NULL, 0);

mount(2):


mount(NULL, "/tmp", NULL, MS_REMOUNT | MS_RDONLY, NULL);

Con la notable salvedad de que en este ejemplo, mount(2) borrará todos los demás parámetros del sistema de archivos (como MS_DIRSYNC o MS_SYNCHRONOUS); fsconfig(2) solo modificará el ro parámetro.
