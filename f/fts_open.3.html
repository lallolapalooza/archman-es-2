fts(3) Manual de Funciones de Biblioteca fts(3)

NOMBRE

fts, fts_open, fts_read, fts_children, fts_set, fts_close - recorrer una jerarquía de archivos

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <sys/types.h>
#include <sys/stat.h>
#include <fts.h>
FTS *fts_open(char *const *path_argv, int options,
              typeof(int (const FTSENT **, const FTSENT **))
                  *_Nullable compar);
FTSENT *fts_read(FTS *ftsp);
FTSENT *fts_children(FTS *ftsp, int instr);
int fts_set(FTS *ftsp, FTSENT *f, int instr);
int fts_close(FTS *ftsp);

DESCRIPCIÓN

Las funciones fts se proporcionan para recorrer jerarquías de archivos. Una descripción general es que la fts_open() función devuelve un "manejador" (de tipo FTS *) que se refiere a un "flujo" de jerarquía de archivos. Este manejador se proporciona entonces a las otras funciones fts. La función fts_read() devuelve un puntero a una estructura que describe uno de los archivos en la jerarquía de archivos. La función fts_children() devuelve un puntero a una lista enlazada de estructuras, cada una de las cuales describe uno de los archivos contenidos en un directorio en la jerarquía.

En general, los directorios se visitan dos veces distinguibles; en preorden (antes de que cualquiera de sus descendientes sean visitados) y en postorden (después de que todos sus descendientes hayan sido visitados). Los archivos se visitan una vez. Es posible recorrer la jerarquía "lógicamente" (visitando los archivos a los que apuntan los enlaces simbólicos) o físicamente (visitando los enlaces simbólicos mismos), ordenar el recorrido de la jerarquía o podar y/o revisitar porciones de la jerarquía.

Dos estructuras (y tipos asociados) están definidas en el archivo de inclusión <fts.h>. El primer tipo es FTS, la estructura que representa la jerarquía de archivos misma. El segundo tipo es FTSENT, la estructura que representa un archivo en la jerarquía de archivos. Normalmente, una FTSENT estructura es devuelta para cada archivo en la jerarquía de archivos. En esta página de manual, "archivo" y "estructura FTSENT" son generalmente intercambiables.

La FTSENT estructura contiene campos que describen un archivo. La estructura contiene al menos los siguientes campos (hay campos adicionales que deben considerarse privados de la implementación):


typedef struct _ftsent {
    unsigned short  fts_info;     /* flags for FTSENT structure */
    char           *fts_accpath;  /* access path */
    char           *fts_path;     /* root path */
    short           fts_pathlen;  /* strlen(fts_path) +
                                     strlen(fts_name) */
    char           *fts_name;     /* filename */
    short           fts_namelen;  /* strlen(fts_name) */
    short           fts_level;    /* depth (-1 to N) */
    int             fts_errno;    /* file errno */
    long            fts_number;   /* local numeric value */
    void           *fts_pointer;  /* local address value */
    struct _ftsent *fts_parent;   /* parent directory */
    struct _ftsent *fts_link;     /* next file structure */
    struct _ftsent *fts_cycle;    /* cycle structure */
    struct stat    *fts_statp;    /* [l]stat(2) information */
} FTSENT;

Estos campos están definidos de la siguiente manera:

fts_info
Uno de los siguientes valores que describen la estructura FTSENT devuelta y el archivo que representa. Con la excepción de los directorios sin errores (FTS_D), todas estas entradas son terminales, es decir, no serán revisitados, ni ninguno de sus descendientes será visitado.
FTS_D
Un directorio que se está visitando en preorden.
FTS_DC
Un directorio que causa un ciclo en el árbol. (El fts_cycle campo de la FTSENT estructura también será rellenado.)
FTS_DEFAULT
Cualquier FTSENT estructura que representa un tipo de archivo no descrito explícitamente por uno de los otros fts_info valores.
FTS_DNR
Un directorio que no puede ser leído. Este es un retorno de error, y el fts_errno campo será establecido para indicar qué causó el error.
FTS_DOT
Un archivo llamado "." o ".." que no fue especificado como un nombre de archivo para fts_open() (ver FTS_SEEDOT).
FTS_DP
Un directorio que se está visitando en postorden. El contenido de la FTSENT estructura no cambiará desde cuando fue devuelta en preorden, es decir, con el fts_info campo establecido a FTS_D.
FTS_ERR
Este es un retorno de error, y el fts_errno campo será establecido para indicar qué causó el error.
FTS_F
Un archivo regular.
FTS_NS
Un archivo para el cual no había información del]stat(2) disponible. El contenido del fts_statp campo es indefinido. Este es un retorno de error, y el fts_errno campo será establecido para indicar qué causó el error.
FTS_NSOK
Un archivo para el cual no se solicitó información del]stat(2) . El contenido del fts_statp campo es indefinido.
FTS_SL
Un enlace simbólico.
FTS_SLNONE
Un enlace simbólico con un destino inexistente. El contenido del fts_statp campo referencia la información de características del archivo para el enlace simbólico mismo.
fts_accpath
Una ruta para acceder al archivo desde el directorio actual.
fts_path
La ruta para el archivo relativa a la raíz del recorrido. Esta ruta contiene la ruta especificada para fts_open() como prefijo.
fts_pathlen
La suma de las longitudes de las cadenas referenciadas por fts_path y fts_name.
fts_name
El nombre del archivo.
fts_namelen
La longitud de la cadena referenciada por fts_name.
fts_level
La profundidad del recorrido, numerada de -1 a N, donde se encontró este archivo. La FTSENT estructura que representa al padre del punto de inicio (o raíz) del recorrido está numerada -1, y la FTSENT estructura para la raíz misma está numerada 0.
fts_errno
Si fts_children() o fts_read() devuelve una FTSENT estructura cuyo fts_info campo está establecido a FTS_DNR, FTS_ERR, o FTS_NS, el fts_errno campo contiene el número de error (es decir, el valor errno ) que especifica el error. De lo contrario, el contenido del fts_errno campo es indefinido.
fts_number
Este campo se proporciona para el uso del programa de aplicación y no es modificado por las funciones fts. Se inicializa a 0.
fts_pointer
Este campo se proporciona para el uso del programa de aplicación y no es modificado por las funciones fts. Se inicializa a NULL.
fts_parent
Un puntero a la FTSENT estructura que referencia al archivo en la jerarquía inmediatamente encima del archivo actual, es decir, el directorio del cual este archivo es miembro. Una estructura padre para el punto de entrada inicial también se proporciona, sin embargo, solo se garantiza que los campos fts_level, fts_number, y fts_pointer estén eninicializado.
fts_link
Al regresar de la fts_children() función, el fts_link campo apunta a la siguiente estructura en la lista enlazada terminada por NULL de miembros del directorio. De lo contrario, el contenido del fts_link campo es indefinido.
fts_cycle
Si un directorio causa un ciclo en la jerarquía (ver FTS_DC), ya sea debido a un enlace duro entre dos directorios, o un enlace simbólico que apunta a un directorio, el fts_cycle campo de la estructura apuntará a la estructura FTSENT en la jerarquía que hace referencia al mismo archivo que la estructura actual FTSENT . De lo contrario, el contenido del campo fts_cycle es indefinido.
fts_statp
Un puntero a la información del]stat(2) del archivo.

Se utiliza un solo búfer para todas las rutas de todos los archivos en la jerarquía de archivos. Por lo tanto, se garantiza que los campos fts_path y fts_accpath estén terminados por un carácter nulo solo para el archivo más recientemente devuelto por fts_read(). Para usar estos campos para hacer referencia a archivos representados por otras estructuras FTSENT se requerirá que el búfer de ruta sea modificado usando la información contenida en el FTSENT campo fts_pathlen de esa estructura. Cualquier modificación de este tipo debe deshacerse antes de intentar más llamadas a fts_read(). El campo fts_name siempre está terminado por un carácter nulo.

fts_open()

La fts_open() función toma un puntero a un arreglo de punteros a caracteres que nombran una o más rutas que componen una jerarquía lógica de archivos a recorrer. El arreglo debe ser terminado por un puntero nulo.

Hay una serie de opciones, de las cuales al menos una (ya sea FTS_LOGICAL o FTS_PHYSICAL) debe ser especificada. Las opciones se seleccionan haciendo OR de los siguientes valores:

FTS_LOGICAL
Esta opción hace que las rutinas fts devuelvan estructuras FTSENT para los destinos de los enlaces simbólicos en lugar de los propios enlaces simbólicos. Si esta opción está establecida, los únicos enlaces simbólicos para los que se devuelven estructuras FTSENT a la aplicación son aquellos que hacen referencia a archivos inexistentes: el campo fts_statp se obtiene a través de stat(2) con un recurso de respaldo a lstat(2).
FTS_PHYSICAL
Esta opción hace que las rutinas fts devuelvan estructuras FTSENT para los propios enlaces simbólicos en lugar de los archivos de destino a los que apuntan. Si esta opción está establecida, se devuelven estructuras FTSENT para todos los enlaces simbólicos en la jerarquía a la aplicación: el campo fts_statp se obtiene a través de lstat(2).
FTS_COMFOLLOW
Esta opción hace que cualquier enlace simbólico especificado como una ruta raíz sea seguido inmediatamente, como si fuera a través de FTS_LOGICAL, independientemente del modo principal.
FTS_NOCHDIR
Como una optimización de rendimiento, las funciones fts cambian de directorio a medida que recorren la jerarquía de archivos. Esto tiene el efecto secundario de que una aplicación no puede confiar en estar en un directorio en particular durante el recorrido. Esta opción desactiva esta optimización, y las funciones fts no cambiarán el directorio actual. Tenga en cuenta que las aplicaciones no deben cambiar su directorio actual e intentar acceder a archivos a menos que FTS_NOCHDIR sea especificado y se proporcionen rutas de acceso absolutas como argumentos a fts_open().
FTS_NOSTAT
De forma predeterminada, las estructuras FTSENT devueltas hacen referencia a la información de características del archivo (el campo fts_statp ) para cada archivo visitado. Esta opción relaja ese requisito como una optimización de rendimiento, permitiendo que las funciones fts establezcan el campo fts_info en FTS_NSOK y dejen el contenido del campo fts_statp indefinido.
FTS_SEEDOT
De forma predeterminada, a menos que se especifiquen como argumentos de ruta a fts_open(), cualquier archivo nombrado "." o ".." encontrado en la jerarquía de archivos es ignorado. Esta opción hace que las rutinas fts devuelvan estructuras FTSENT para ellos.
FTS_XDEV
Esta opción evita que fts descienda a directorios que tengan un número de dispositivo diferente al del archivo desde el cual comenzó el descenso.

El argumento compar() especifica una función definida por el usuario que puede usarse para ordenar el recorrido de la jerarquía. Toma dos punteros a punteros a estructuras FTSENT como argumentos y debe devolver un valor negativo, cero o positivo para indicar si el archivo referenciado por su primer argumento viene antes, en cualquier orden con respecto a, o después, del archivo referenciado por su segundo argumento. Los campos fts_accpath, fts_pathy fts_pathlen de las estructuras FTSENT pueden nunca usarse en esta comparación. Si el campo fts_info está establecido en FTS_NS o FTS_NSOK, el campo fts_statp tampoco puede usarse. Si el argumento compar() es NULL, el orden de recorrido del directorio es el orden listado en path_argv para las rutas raíz, y en el orden listado en el directorio para todo lo demás.

fts_read()

La fts_read() función devuelve un puntero a una estructura FTSENT que describe un archivo en la jerarquía. Los directorios (que son legibles y no causan ciclos) se visitan al menos dos veces, una vez en preorden y una vez en postorden. Todos los demás archivos se visitan al menos una vez. (Los enlaces duros entre directorios que no causan ciclos o los enlaces simbólicos a enlaces simbólicos pueden hacer que los archivos se visiten más de una vez, o los directorios más de dos veces.)

Si todos los miembros de la jerarquía han sido devueltos, fts_read() devuelve NULL y establece errno en 0. Si ocurre un error no relacionado con un archivo en la jerarquía, fts_read() devuelve NULL y establece errno para indicar el error. Si ocurre un error relacionado con un archivo devuelto, se devuelve un puntero a una estructura FTSENT , y errno puede o no haber sido establecido (ver fts_info).

Las estructuras FTSENT devueltas por fts_read() pueden ser sobrescritas después de una llamada a fts_close() en el mismo flujo de jerarquía de archivos, o, después de una llamada a fts_read() en el mismo flujo de jerarquía de archivos a menos que representen un archivo de tipo directorio, en cuyo caso no serán sobrescritas hasta después de una llamada a fts_read() después de que la estructura FTSENT haya sido devuelta por la función fts_read() en postorden.

fts_children()

La fts_children() función devuelve un puntero a una estructura FTSENT que describe la primera entrada en una lista enlazada terminada por NULL de los archivos en el directorio representado por la estructura FTSENT devuelta más recientemente por fts_read(). La lista está enlazada a través del campo fts_link de la estructura FTSENT , y está ordenada por la función de comparación especificada por el usuario, si la hay. Llamadas repetidas a fts_children() recrearán esta lista enlazada.

Como caso especial, si fts_read() aún no ha sido llamada para una jerarquía, fts_children() devolverá un puntero a los archivos en el directorio lógico especificado a fts_open(), es decir, los argumentos especificados a fts_open(). De lo contrario, si la estructura FTSENT devuelta más recientemente por fts_read() no es un directorio siendo visitado en preorden, o el directorio no contiene ningún archivo, fts_children() devuelve NULL y establece errno en cero. Si ocurre un error, fts_children() devuelve NULL y establece errno para indicar el error.

Las estructuras FTSENT devueltas por fts_children() pueden ser sobrescritas después de una llamada a fts_children(), fts_close(), o fts_read() en el mismo flujo de jerarquía de archivos.

El argumento instr es cero o el siguiente valor:

FTS_NAMEONLY
Solo se necesitan los nombres de los archivos. El contenido de todos los campos en la lista enlazada de estructuras devueltas es indefinido con la excepción de los campos fts_name y fts_namelen .

fts_set()

La función fts_set() permite a la aplicación de usuario determinar el procesamiento posterior para el archivo f del flujo ftsp. La fts_set() función devuelve 0 en caso de éxito, y -1 si ocurre un error.

El argumento instr es 0 (significando "no hacer nada") o uno de los siguientes valores:

FTS_AGAIN
Volver a visitar el archivo; cualquier tipo de archivo puede ser visitado de nuevo. La siguiente llamada a fts_read() devolverá el archivo referenciado. Los campos fts_stat y fts_info de la estructura serán reinicializados en ese momento, pero ningún otro campo será cambiado. Esta opción es significativa solo para el archivo devuelto más recientemente por fts_read(). El uso normal es para visitas de directorio en postorden, donde hace que el directorio sea visitado de nuevo (tanto en preorden como en postorden) así como todos sus descendientes.
FTS_FOLLOW
El archivo referenciado debe ser un enlace simbólico. Si el archivo referenciado es el devuelto más recientemente por fts_read(), la siguiente llamada a fts_read() devuelve el archivo con los campos fts_info y fts_statp reinicializados para reflejar el destino del enlace simbólico en lugar del propio enlace simbólico. Si el archivo es uno de los devueltos más recientemente por fts_children(), los campos fts_info y fts_statp de la estructura, cuando sean devueltos por fts_read(), reflejarán el destino del enlace simbólico en lugar del enlace simbólico mismo. En cualquier caso, si el destino del enlace simbólico no existe, los campos de la estructura devuelta no serán cambiados y el campo fts_info será establecido en FTS_SLNONE.
Si el destino del enlace es un directorio, la devolución en preorden, seguido por el retorno de todos sus descendientes, seguido por un retorno en orden postorder, se realiza.
FTS_SKIP
No se visitan descendientes de este archivo. El archivo puede ser uno de los más devueltos recientemente por fts_children() o fts_read().

fts_close()

La fts_close() función cierra el flujo de jerarquía de archivos al que se refiere ftsp y restaura el directorio actual al directorio desde el que se llamó a fts_open() para abrir ftsp. La fts_close() función devuelve 0 en caso de éxito, y -1 si ocurre un error .

ERRORES

La función fts_open() puede fallar y establecer errno para cualquiera de los errores especificados para open(2) y malloc(3).

Además, fts_open() puede fallar y establecer errno como sigue:

ENOENT
Cualquier elemento de path_argv era una cadena vacía.

La función fts_close() puede fallar y establecer errno para cualquiera de los errores especificados para chdir(2) y close(2).

Las funciones fts_read() y fts_children() pueden fallar y establecer errno para cualquiera de los errores especificados para chdir(2), malloc(3), opendir(3), readdir(3), y [l]stat(2).

Además, fts_children(), fts_open(), y fts_set() pueden fallar y establecer errno como sigue:

EINVAL
options o instr era inválido.
