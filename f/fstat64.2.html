NOMBRE

stat, fstat, lstat, fstatat - obtener el estado del archivo

BIBLIOTECA

SINOPSIS

#include <sys/stat.h>

DESCRIPCIÓN

Estas funciones devuelven información sobre un archivo, en el búfer apuntado por statbuf. No se requieren permisos sobre el archivo en sí, pero —en el caso de stat(), fstatat() y lstat()— se requiere permiso de ejecución (búsqueda) en todos los directorios en path que conducen al archivo.

stat() y fstatat() recuperan información sobre el archivo apuntado por path; las diferencias para fstatat() se describen a continuación.

lstat() es idéntica a stat(), excepto que si path es un enlace simbólico, entonces devuelve información sobre el propio enlace, no sobre el archivo al que se refiere el enlace.

fstat() es idéntica a stat(), excepto que el archivo sobre el cual se debe obtener información se especifica mediante el descriptor de archivo fd.

La estructura stat

Todas estas llamadas al sistema devuelven una estructura stat (ver stat(3type)).

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura stat pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si st_mode o st_uid son modificados por otro proceso llamando a chmod(2) o chown(2), stat() podría devolver el st_mode antiguo junto con el nuevo st_uid, o el st_uid antiguo junto con el nuevo st_mode.

fstatat()

La llamada al sistema fstatat() es una interfaz más general para acceder a la información del archivo que aún puede proporcionar exactamente el comportamiento de cada una de stat(), lstat() y fstat().

Si path es relativo, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como hacen stat() y lstat() para un nombre de ruta relativo).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso que llama (como stat() y lstat()).

Si path es absoluto, entonces dirfd se ignora.

flags puede ser 0, o incluir una o más de las siguientes banderas ORed:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si path es una cadena vacía (o NULL, desde Linux 6.11) opere sobre el archivo al que se refiere dirfd (que puede haber sido obtenido usando la bandera O_PATH de open(2)). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio, y el comportamiento de fstatat() es similar al de fstat(). Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; defina _GNU_SOURCE para obtener su definición.
AT_NO_AUTOMOUNT (desde Linux 2.6.38)
No montar automáticamente el componente terminal ("basename") de path. Desde Linux 3.1 esta bandera se ignora. Desde Linux 4.11 esta bandera está implícita.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo desreferencie: en su lugar, devuelva información sobre el propio enlace, como lstat(). (Por defecto, fstatat() desreferencia enlaces simbólicos, como stat().)

Ver openat(2) para una explicación de la necesidad de fstatat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se deniega el permiso de búsqueda en uno de los directorios en el prefijo de ruta de path. (Ver también path_resolution(7).)
EBADF
fd no es un descriptor de archivo abierto válido.
EBADF
(fstatat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
Dirección incorrecta.
EINVAL
(fstatat()) Bandera inválida especificada en flags.
ELOOP
Demasiados enlaces simbólicos encontrados al recorrer la ruta.
ENAMETOOLONG
path es demasiado largo.
ENOENT
Un componente de path no existe o es un enlace simbólico colgante.
ENOENT
path es una cadena vacía y AT_EMPTY_PATH no se especificó en flags.
ENOMEM
Sin memoria (es decir, memoria del kernel).
ENOTDIR
Un componente del prefijo de ruta de path no es un directorio.
ENOTDIR
(fstatat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EOVERFLOW
path o fd se refieren a un archivo cuyo tamaño, número de inodo o número de bloques no se puede representar en los tipos, respectivamente, off_t, ino_t o blkcnt_t. Este error puede ocurrir cuando, por ejemplo, una aplicación compilada en una plataforma de 32 bits sin -D_FILE_OFFSET_BITS=64 llama a stat() sobre un archivo cuyo tamaño excede los (1<<31)-1 bytes.

NAME

fstat64, fstat, lstat64, lstat, stat64, stat - get file status

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/stat.h>

int stat(const char *pathname, struct stat *statbuf);
int lstat(const char *pathname, struct stat *statbuf);
int fstat(int fd, struct stat *statbuf);

#define _FILE_OFFSET_BITS 64
#include <sys/stat.h>

int stat64(const char *pathname, struct stat64 *statbuf);
int lstat64(const char *pathname, struct stat64 *statbuf);
int fstat64(int fd, struct stat64 *statbuf);

DESCRIPTION

These functions obtain information about the file referred to by the path name described by pathname, or by the open file descriptor fd, and store it in the buffer pointed to by statbuf.

The system provides three related functions:

  • stat() follows symbolic links.
  • lstat() does not follow symbolic links (a trailing component that is a symbolic link is not followed).
  • fstat() obtains information about an open file described by the file descriptor fd.

The stat64, lstat64, and fstat64 functions are versions of the respective functions that operate on a struct stat64 structure. These are necessary on 32-bit systems to support files larger than 2 GiB, where the struct stat might not be large enough to hold the larger file sizes and offsets.

On systems that support large files (typically 64-bit systems, or 32-bit systems where _FILE_OFFSET_BITS is defined as 64), the standard stat, lstat, and fstat functions are actually implemented as the stat64, lstat64, and fstat64 functions, and the struct stat is equivalent to struct stat64. On such systems, you do not need to use the ...64 versions explicitly.

On older 32-bit systems (or 32-bit systems where _FILE_OFFSET_BITS is not defined as 64), the standard stat, lstat, and fstat functions operate on a struct stat that might not be able to hold all the information for very large files. In this case, the ...64 versions should be used.

The struct stat (and struct stat64) structure contains at least the following fields:

char st_padding[__WORDSIZE - sizeof(struct stat) % __WORDSIZE]; /* force structure alignment */

       struct stat {
           ino_t     st_ino;       /* Inode number */
           off_t     st_size;      /* Total size, in bytes */
           struct timespec st_atim;  /* Time of last access */
           struct timespec st_mtim;  /* Time of last modification */
           struct timespec st_ctim;  /* Time of last status change */
       };
       struct stat64 {
           ino64_t   st_ino;       /* Inode number */
           off64_t   st_size;      /* Total size, in bytes */
           struct timespec st_atim;  /* Time of last access */
           struct timespec st_mtim;  /* Time of last modification */
           struct timespec st_ctim;  /* Time of last status change */
       };

The exact fields provided in the struct stat are implementation-dependent, but typically include:

  • st_dev: Device ID of the device containing the file. (This is an unsigned long long on Linux.)
  • st_ino: Inode number of the file.
  • st_mode: Protection information, including file type and permissions. This is a bitmask. See stat.h(3type) for details.
  • st_nlink: Number of hard links to the file.
  • st_uid: User ID of the file's owner.
  • st_gid: Group ID of the file's group.
  • st_rdev: Device ID if the file is a device file.
  • st_size: Total size, in bytes.
  • st_blksize: Preferred block size for file system I/O operations.
  • st_blocks: Number of blocks allocated for this file. The range and use of this field depend on the underlying file system. (This is an unsigned long long on Linux.)
  • st_atime: Time of the last access.
  • st_mtime: Time of the last modification.
  • st_ctime: Time of the last status change.

The st_atime, st_mtime, and st_ctime fields are specified as struct timespec structures. POSIX.1-2001 and later require that these fields have nanosecond precision. On older systems, they might be time_t values with only second precision.

The st_blocks field represents the number of 512-byte blocks actually allocated to the file. This value may differ from the logical size of the file obtained from st_size, for example, sparse files. The value may be rounded up.

The st_mode field contains information about the file type and its permissions. The file type is encoded in the lower bits of the field, using the masks S_IFMT, S_IFREG, S_IFDIR, S_IFLNK, S_IFCHR, S_IFBLK, S_IFIFO, and S_IFSOCK. The upper bits contain the file permission bits.

POSIX.1-2001 requires that stat() fill in all fields of the struct stat. POSIX.1-2008 tightens the specification, requiring lstat() to return valid information in all fields except the mode bits in st_mode.

Use of the st_blocks and st_blksize fields may be less portable. (They were introduced in BSD. The interpretation differs between systems, and possibly on a single system when NFS mounts are involved.)

C library/kernel differences

Over time, increases in the size of the stat structure have led to three successive versions of stat(): sys_stat() (slot __NR_oldstat), sys_newstat() (slot __NR_stat), and sys_stat64() (slot __NR_stat64) on 32-bit platforms such as i386. The first two versions were already present in Linux 1.0 (albeit with different names); the last was added in Linux 2.4. Similar remarks apply for fstat() and lstat().

The kernel-internal versions of the stat structure dealt with by the different versions are, respectively:

__old_kernel_stat
The original structure, with rather narrow fields, and no padding.
stat
Larger st_ino field and padding added to various parts of the structure to allow for future expansion.
stat64
Even larger st_ino field, larger st_uid and st_gid fields to accommodate the Linux-2.4 expansion of UIDs and GIDs to 32 bits, and various other enlarged fields and further padding in the structure. (Various padding bytes were eventually consumed in Linux 2.6, with the advent of 32-bit device IDs and nanosecond components for the timestamp fields.)

The glibc stat() wrapper function hides these details from applications, invoking the most recent version of the system call provided by the kernel, and repacking the returned information if required for old binaries.

On modern 64-bit systems, life is simpler: there is a single stat() system call and the kernel deals with a stat structure that contains fields of a sufficient size.

The underlying system call employed by the glibc fstatat() wrapper function is actually called fstatat64() or, on some architectures, newfstatat().

EXAMPLES

The following program calls lstat() and displays selected fields in the returned stat structure.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID of containing device:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("File type:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("block device\n");            break;
    case S_IFCHR:  printf("character device\n");        break;
    case S_IFDIR:  printf("directory\n");               break;
    case S_IFIFO:  printf("FIFO/pipe\n");               break;
    case S_IFLNK:  printf("symlink\n");                 break;
    case S_IFREG:  printf("regular file\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("unknown?\n");                break;
    }
    printf("I-node number:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Mode:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Link count:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Ownership:                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Preferred I/O block size: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("File size:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Blocks allocated:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Last status change:       %s", ctime(&sb.st_ctime));
    printf("Last file access:         %s", ctime(&sb.st_atime));
    printf("Last file modification:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
