footclient(1) General Commands Manual footclient(1)

NOMBRE

footclient - inicia nuevos terminales en un servidor foot

SINOPSIS

footclient [OPCIONES]
footclient [OPCIONES] <comando> [OPCIONES DE COMANDO]

Todos los argumentos finales (que no sean opciones) se tratan como un comando y sus argumentos, para ejecutar (en lugar del shell predeterminado).

DESCRIPCIÓN

footclient se utiliza junto con foot(1) en modo --server.

Ejecutarlo sin argumentos abrirá una nueva ventana de terminal (alojada en el servidor foot), con tu shell predeterminado. El código de salida será el de la terminal. Es decir, footclient no saldrá hasta que la terminal haya terminado.

OPCIONES

-t,--term=TERM

Valor para establecer la variable de entorno TERM (ver TERMINFO y ENTORNO). Predeterminado: foot.

-T,--title=TITLE

Título inicial de la ventana. Predeterminado: foot.

-a,--app-id=ID

Valor para establecer la propiedad app-id en la ventana de Wayland. Predeterminado: foot (modo normal), o footclient (modo servidor).

-w,--window-size-pixels=ANCHOxALTO

Establecer el ancho y alto inicial de la ventana, en píxeles. Predeterminado: 700x500.

-W,--window-size-chars=ANCHOxALTO

Establecer el ancho y alto inicial de la ventana, en caracteres. Predeterminado: no establecido.

-m,--maximized

Iniciar en modo maximizado. Si se especifican tanto --maximized como --fullscreen, el último tiene precedencia.

-F,--fullscreen

Iniciar en modo pantalla completa. Si se especifican tanto --maximized como --fullscreen, el último tiene precedencia.

-L,--login-shell

Iniciar un shell de inicio de sesión, anteponiendo un '-' a argv[0].

-D,--working-directory=DIR

Directorio de trabajo inicial para la aplicación cliente. Predeterminado: CWD de footclient.

-s,--server-socket=PATH

Conectar a PATH en lugar de a $XDG_RUNTIME_DIR/foot-$WAYLAND_DISPLAY.sock.

-H,--hold

Permanecer abierto después de que el proceso hijo termine.

-N,--no-wait

Desvincular el proceso cliente del terminal en ejecución, saliendo inmediatamente.

-o,--override=[SECCIÓN.]CLAVE=VALOR

Anular una opción establecida en el archivo de configuración. Si no se proporciona SECCIÓN, se asume main.

-E,--client-environment

El proceso hijo en la nueva instancia de terminal usará el entorno de footclient, en lugar del del servidor.

Las variables de entorno enumeradas en la sección Variables establecidas en el proceso hijo serán sobrescritas por el servidor foot. Por ejemplo, el nuevo terminal usará TERM de la configuración, no del entorno de footclient.

-d,--log-level={info,warning,error,none}

Nivel de registro, utilizado tanto para la salida de registros en stderr como para syslog. Predeterminado: warning.

-l,--log-colorize=[{never,always,auto}]

Habilita o deshabilita la colorización de la salida de registros en stderr.

-v,--version

Muestra el número de versión y sale

-e

Ignorado; para compatibilidad con xterm -e. Ver foot(1) para más detalles.

ESTADO DE SALIDA

Footclient saldrá con el código 220 si hay un fallo en el propio footclient (por ejemplo, el socket del servidor no existe).

Si se utiliza -N,--no-wait, footclient sale con el código 0 tan pronto como se ha instruido al servidor foot para que abra una nueva ventana.

Si no, footclient también puede salir con el código 230. Esto indica un fallo en el servidor foot.

En todos los demás casos, el código de salida será el de la aplicación cliente (es decir, el shell).

TERMINFO

Las aplicaciones cliente utilizan el identificador terminfo especificado por la variable de entorno TERM (establecida por foot) para determinar las capacidades de la terminal.

Foot tiene dos definiciones de terminfo: foot y foot-direct, siendo foot la predeterminada.

La diferencia entre ambas es el número de colores que describen; foot describe 256 colores y foot-direct 16.7 millones de colores (truecolor de 24 bits).

Tenga en cuenta que usar el terminfo foot no limita el número de colores utilizables a 256; las aplicaciones aún pueden usar colores RGB de 24 bits. De hecho, la mayoría de las aplicaciones funcionan mejor con foot (¡incluidos los colores de 24 bits!). Se sabe que usar entradas terminfo *-direct incluso ha provocado fallos en algunas aplicaciones ncurses.

Sin embargo, hay aplicaciones que necesitan una entrada terminfo *-direct para el soporte de 24 bits. Emacs es un ejemplo.

Aunque se recomienda encarecidamente el uso de foot o foot-direct, también es posible utilizar, por ejemplo, xterm-256color. Esto puede ser útil al conectarse de forma remota a un sistema donde las entradas terminfo de foot no se pueden instalar fácilmente.

Tenga en cuenta que las entradas terminfo se pueden instalar en el directorio de inicio del usuario. Es decir, si no tiene acceso root, o si no hay un paquete de distribución para las entradas terminfo de foot, puede instalar las entradas terminfo de foot manualmente, copiando foot y foot-direct a ~/.terminfo/f/.

ENTORNO

Variables utilizadas por footclient

XDG_RUNTIME_DIR

Se utiliza para construir la ruta predeterminada para la opción --server-socket, cuando no se proporciona ningún argumento explícito (ver arriba).

WAYLAND_DISPLAY

Se utiliza para construir la ruta predeterminada para la opción --server-socket, cuando no se proporciona ningún argumento explícito (ver arriba).

Si el socket en la ruta predeterminada no existe, footclient recurrirá a la ruta menos específica, con la siguiente prioridad: $XDG_RUNTIME_DIR/foot-$WAYLAND_DISPLAY.sock, $XDG_RUNTIME_DIR/foot.sock, /tmp/foot.sock.

Variables establecidas en el proceso hijo

TERM

Identificador de terminfo/termcap. Esto lo utilizan las aplicaciones cliente para determinar qué capacidades admite una terminal. El valor se establece según la opción de línea de comandos --term o la opción de configuración term en foot.ini(5).

COLORTERM

Esta variable se establece en truecolor, para indicar a las aplicaciones cliente que se admiten colores RGB de 24 bits.

PWD

Directorio de trabajo actual (en el momento de lanzar foot)

SHELL

Se establece en el shell lanzado, si el shell es válido (está listado en /etc/shells).

Además de las variables enumeradas anteriormente, se pueden definir variables de entorno personalizadas en foot.ini(5).

Variables *eliminadas* en el proceso hijo

TERM_PROGRAM TERM_PROGRAM_VERSION

Estas variables de entorno son establecidas por otros emuladores de terminal. Las eliminamos para evitar que las aplicaciones detecten foot incorrectamente.

Además de las variables enumeradas anteriormente, se pueden definir variables de entorno personalizadas para eliminar en foot.ini(5).

Señales

Signals

Las siguientes señales tienen un significado especial en footclient:

  • SIGUSR1: cambia al tema de color 1 (es decir, usa la sección [colors]).
  • SIGUSR2: cambia al tema de color 2 (es decir, usa la sección [colors2]).

Al enviar SIGUSR1/SIGUSR2 a una instancia de footclient, el tema se cambia solo en esa instancia. Esto es diferente de cuando envías SIGUSR1/SIGUSR2 al proceso del servidor, donde todas las instancias cambian el tema.

Nota: por razones obvias, esto no se admite cuando footclient se inicia con --no-wait.
