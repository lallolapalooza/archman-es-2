FNMATCH(3P) Manual de Programador de POSIX FNMATCH(3P)

PRÓLOGO

Esta página del manual forma parte del Manual de Programador de POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fnmatch — coincide con una cadena de nombre de archivo o una ruta de archivo

SINOPSIS

#include <fnmatch.h>
int fnmatch(const char *pattern, const char *string, int flags);

DESCRIPCIÓN

La función fnmatch() coincide con patrones como se describe en el volumen de Shell y Utilidades de POSIX.1‐2017, Sección 2.13.1, Patrones que coinciden con un solo carácter y Sección 2.13.2, Patrones que coinciden con varios caracteres. Comprueba si la cadena especificada por el argumento string coincide con el patrón especificado por el argumento pattern.

El argumento flags modifica la interpretación de pattern y string. Es el OR a nivel de bits inclusivo de cero o más de las banderas definidas en <fnmatch.h>. Si la bandera FNM_PATHNAME está establecida en flags, entonces un carácter <barra inclinada> ('/') en string será explícitamente coincidente con una <barra inclinada> en pattern; no será coincidente ni con el carácter <asterisco> ni con el carácter <signo de interrogación>, ni con una expresión entre corchetes. Si la bandera FNM_PATHNAME no está establecida, el carácter <barra inclinada> se tratará como un carácter ordinario.

Si FNM_NOESCAPE no está establecido en flags, un carácter <barra invertida> en pattern seguido de cualquier otro carácter coincidirá con ese segundo carácter en string. En particular, "\\" coincidirá con una <barra invertida> en string. Si pattern termina con una <barra invertida> sin escapar, fnmatch() devolverá un valor distinto de cero (indicando que no hay coincidencia o un error). Si FNM_NOESCAPE está establecido, un carácter <barra invertida> se tratará como un carácter ordinario.

Si FNM_PERIOD está establecido en flags, entonces un <punto> ('.') al principio de string coincidirá con un <punto> en pattern; como se describe en la regla 2 de el volumen de Shell y Utilidades de POSIX.1‐2017, Sección 2.13.3, Patrones utilizados para la expansión de nombres de archivo, donde la ubicación de "al principio" se indica por el valor de FNM_PATHNAME:

*
Si FNM_PATHNAME está establecido, un <punto> está "al principio" si es el primer carácter en string o si sigue inmediatamente a una <barra inclinada>.
*
Si FNM_PATHNAME no está establecido, un <punto> está "al principio" solo si es el primer carácter de string.

Si FNM_PERIOD no está establecido, entonces no se imponen restricciones especiales para la coincidencia de un punto.

VALOR DE RETORNO

Si string coincide con el patrón especificado por pattern, entonces fnmatch() devolverá 0. Si no hay coincidencia, fnmatch() devolverá FNM_NOMATCH, que está definido en <fnmatch.h>. Si ocurre un error, fnmatch() devolverá otro valor distinto de cero.

ERRORES

No se definen errores.

EJEMPLOS

Ninguno.

USO POR LA APLICACIÓN

La función fnmatch() tiene dos usos principales. Podría ser utilizada por una aplicación o utilidad que necesite leer un directorio y aplicar un patrón contra cada entrada. La utilidad find es un ejemplo de esto. También puede ser utilizada por la utilidad pax para procesar sus operandos de pattern, o por aplicaciones que necesiten hacer coincidir cadenas de manera similar.

El nombre fnmatch() pretende implicar la coincidencia de nombre de archivo, en lugar de la coincidencia de ruta de archivo. La acción por defecto de esta función es hacer coincidir cadenas de nombres de archivo, en lugar de rutas de archivo, ya que no da ninguna significación especial al carácter <barra inclinada>. Con la bandera FNM_PATHNAME, fnmatch() coincide con rutas de archivo, pero sin expansión de tilde, expansión de parámetros o tratamiento especial para un <punto> al principio de un nombre de archivo.

JUSTIFICACIÓN

Esta función reemplazó la bandera REG_FILENAME de regcomp() en las primeras propuestas de este volumen de POSIX.1‐2017. Proporciona prácticamente la misma funcionalidad que las funciones regcomp() y regexec() utilizando las banderas REG_FILENAME y REG_FSLASH (la bandera REG_FSLASH fue propuesta para regcomp(), y habría tenido el efecto opuesto a FNM_PATHNAME), pero con una función más simple y menos sobrecarga del sistema.
