ftw(3) Manual de funciones de biblioteca ftw(3)

NOMBRE

ftw, nftw - recorrer el árbol de archivos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <ftw.h>
int nftw(const char *dirpath,
        typeof(int (const char *fpath, const struct stat *sb,
                    int typeflag, struct FTW *ftwbuf))
            *fn,
        int nopenfd, int flags);
[[deprecated]]
int ftw(const char *dirpath,
        typeof(int (const char *fpath, const struct stat *sb,
                    int typeflag))
            *fn,
        int nopenfd);
Requisitos de la macro de prueba de características para glibc (ver feature_test_macros(7)):

nftw():

    _XOPEN_SOURCE >= 500

DESCRIPCIÓN

nftw() recorre el árbol de directorios ubicado bajo el directorio dirpath, y llama a fn() una vez por cada entrada en el árbol. Por defecto, los directorios se manejan antes que los archivos y subdirectorios que contienen (recorrido en preorden).

Para evitar agotar todos los descriptores de archivo del proceso llamante, nopenfd especifica el número máximo de directorios que nftw() mantendrá abiertos simultáneamente. Cuando la profundidad de búsqueda excede este límite, nftw() será más lento porque los directorios deberán cerrarse y reabrirse. nftw() utiliza como máximo un descriptor de archivo por cada nivel en el árbol de directorios.

Para cada entrada encontrada en el árbol, nftw() llama a fn() con cuatro argumentos: fpath, sb, typeflag y ftwbuf. fpath es la ruta del nombre de la entrada, y se expresa ya sea como una ruta relativa al directorio de trabajo actual del proceso llamante en el momento de la llamada a nftw(), si dirpath se expresó como una ruta relativa, o como una ruta absoluta, si dirpath se expresó como una ruta absoluta. sb es un puntero a la estructura stat devuelta por una llamada a stat(2) para fpath.

El argumento typeflag pasado a fn() es un entero que tiene uno de los siguientes valores:

FTW_F
fpath es un archivo regular.
FTW_D
fpath es un directorio.
FTW_DNR
fpath es un directorio que no se puede leer.
FTW_DP
fpath es un directorio, y se especificó FTW_DEPTH en flags. (Si no se especificó FTW_DEPTH en flags, entonces los directorios siempre se visitarán con typeflag establecido en FTW_D). Todos los archivos y subdirectorios dentro de fpath han sido procesados.
FTW_NS
La llamada stat(2) falló en fpath, que no es un enlace simbólico. La causa probable es que el llamador tenía permiso de lectura en el directorio padre, por lo que el nombre de archivo fpath era visible, pero no tenía permiso de ejecución, por lo que el archivo no se podía alcanzar para stat(2). El contenido del búfer apuntado por sb no está definido.
FTW_SL
fpath es un enlace simbólico, y se estableció FTW_PHYS en flags.
FTW_SLN
fpath es un enlace simbólico que apunta a un archivo inexistente. (Esto ocurre solo si FTW_PHYS no está establecido). En este caso, el argumento sb pasado a fn() contiene información devuelta al realizar lstat(2) sobre el enlace simbólico "colgante". (Pero ver BUGOS).

El cuarto argumento (ftwbuf) que nftw() proporciona al llamar a fn() es un puntero a una estructura de tipo FTW:


struct FTW {
    int base;
    int level;
};

base es el desplazamiento del nombre del archivo (es decir, el componente basename) en la ruta dada en fpath. level es la profundidad de fpath en el árbol de directorios, relativa a la raíz del árbol (dirpath, que tiene profundidad 0).

Para detener el recorrido del árbol, fn() devuelve un valor distinto de cero; este valor se convertirá en el valor de retorno de nftw(). Mientras fn() devuelva 0, nftw() continuará ya sea hasta que haya recorrido todo el árbol, en cuyo caso devolverá cero, o hasta que encuentre un error (como un fallo de malloc(3)), en cuyo caso devolverá -1.

Debido a que nftw() utiliza estructuras de datos dinámicas, la única forma segura de salir de un recorrido de árbol es devolver un valor distinto de cero de fn(). Para permitir que una señal termine el recorrido sin causar una fuga de memoria, haga que el manejador establezca una bandera global que fn() compruebe. No use longjmp(3) a menos que el programa vaya a terminar.

El argumento flags de nftw() se forma combinando con OR cero o más de las siguientes banderas:

FTW_ACTIONRETVAL (desde glibc 2.3.3)
Si esta bandera específica de glibc está establecida, entonces nftw() maneja el valor de retorno de fn() de manera diferente. fn() debe devolver uno de los siguientes valores:
FTW_CONTINUE
Indica a nftw() que continúe normalmente.
FTW_SKIP_SIBLINGS
Si fn() devuelve este valor, se omitirán los hermanos de la entrada actual y el procesamiento continuará en el padre.
FTW_SKIP_SUBTREE
Si se llama a fn() con una entrada que es un directorio (typeflag es FTW_D), este valor de retorno evitará que los objetos dentro de ese directorio se pasen como argumentos a fn(). nftw() continúa procesando con el siguiente hermano del directorio.
FTW_STOP
Hace que nftw() retorne inmediatamente con el valor de retorno FTW_STOP.

Otros valores de retorno podrían asociarse con nuevas acciones en el futuro; fn() no debe devolver valores que no sean los enumerados anteriormente.

La macro de prueba de características _GNU_SOURCE debe estar definida (antes de incluir cualquier archivo de cabecera) para obtener la definición de FTW_ACTIONRETVAL de <ftw.h>.

FTW_CHDIR
Si está establecido, realiza un chdir(2) a cada directorio antes de manejar su contenido. Esto es útil si el programa necesita realizar alguna acción en el directorio en el que reside fpath. (Especificar esta bandera no tiene efecto en la ruta que se pasa en el argumento fpath de fn).
FTW_DEPTH
Si está establecido, realiza un recorrido postorden, es decir, llama a fn() para el directorio en sí después de manejar el contenido del directorio y sus subdirectorios. (Por defecto, cada directorio se maneja antes de su contenido).
FTW_MOUNT
Si está establecido, permanece dentro del mismo sistema de archivos (es decir, no cruza puntos de montaje).
FTW_PHYS
Si está establecido, no sigue los enlaces simbólicos. (Esto es lo que quieres). Si no está establecido, se siguen los enlaces simbólicos, pero no se informa ningún archivo dos veces.
Si FTW_PHYS no está establecido, pero FTW_DEPTH sí lo está, entonces la función fn() nunca se llama para un directorio que sería un descendiente de sí mismo.

BIBLIOTECA

Biblioteca de C estándar (libc), desde la versión 2.1.

SINOPSIS

#define _XOPEN_SOURCE 500       /* Para nftw() y FTW_SL */
#include <ftw.h>
int ftw(const char *dirpath, int (*fn) (const char *,
          const struct stat *, int, struct FTW *),
          int nopenfd);
int nftw(const char *dirpath, int (*fn) (const char *,
           const struct stat *, int, struct FTW *),
           int nopenfd, int flags);

DESCRIPCIÓN

Las funciones ftw() y nftw() recorren recursivamente un árbol de directorios comenzando desde dirpath. Para cada archivo encontrado en el árbol, llaman a la función proporcionada por el usuario fn().

El argumento nopenfd especifica el número máximo de descriptores de archivo que la función puede mantener abiertos simultáneamente. Este límite se aplica al número de directorios abiertos para la traversal.

La función fn() se llama con los siguientes argumentos:

fpath
Un puntero a una cadena que contiene la ruta de acceso al archivo.
sb
Un puntero a una estructura stat que contiene información sobre el archivo.
tflag
Una bandera que indica el tipo de archivo. Los valores posibles son:
FTW_F El archivo es un archivo regular.
FTW_D El archivo es un directorio.
FTW_DNR El archivo es un directorio que no se puede leer.
FTW_NS La información sobre el archivo no se pudo obtener.
FTW_SL El archivo es un enlace simbólico. Esto puede ocurrir en diferentes momentos dependiendo de la implementación (ver VERSIONES).
FTW_DP El archivo es un directorio y se ha visitado después de sus hijos. Esto sólo se pasa si se especifica FTW_DP en el argumento flags de nftw().
FTW_SLN El archivo es un enlace simbólico que apunta a un archivo inexistente. Esto sólo se pasa si se especifica FTW_SLN en el argumento flags de nftw().
ftwbuf
Un puntero a una estructura FTW que contiene información adicional sobre la traversal.

La estructura FTW contiene los siguientes campos:

base
El índice del componente de nombre de archivo base dentro de fpath.
level
El nivel de profundidad de la traversal, donde el directorio inicial está en el nivel 0.
visit_runtime
(Sólo nftw()) El tiempo de ejecución en el que se visitó el archivo.
quit_expression
(Sólo nftw()) El puntero a la expresión de parada, si se utiliza.

nftw() ofrece un subconjunto de la funcionalidad de ftw(). Las diferencias notables son las siguientes:

•
ftw() no tiene argumento flags. Se comporta como cuando nftw() se llama con el argumento flags especificado como cero.
•
La función de devolución de llamada, fn(), no recibe un cuarto argumento.
•
El rango de valores que se pasa a través del argumento typeflag suministrado a fn() es más pequeño: sólo FTW_F, FTW_D, FTW_DNR, FTW_NS y (posiblemente) FTW_SL.

VALOR DE RETORNO

Estas funciones devuelven 0 en caso de éxito y -1 si ocurre un error.

Si fn() devuelve un valor distinto de cero, la traversal del árbol se termina y el valor devuelto por fn() se devuelve como resultado de ftw() o nftw().

Si se llama a nftw() con la bandera FTW_ACTIONRETVAL, el único valor distinto de cero que debe ser utilizado por fn() para terminar la traversal del árbol es FTW_STOP, y ese valor se devuelve como el resultado de nftw().

VERSIÓNES

En algunas implementaciones (por ejemplo, glibc), ftw() nunca utilizará FTW_SL; en otros sistemas, FTW_SL ocurre sólo para enlaces simbólicos que no apuntan a un archivo existente; y de nuevo en otros sistemas, ftw() utilizará FTW_SL para cada enlace simbólico. Si fpath es un enlace simbólico y stat(2) falló, POSIX.1-2008 establece que es indefinido si se pasa FTW_NS o FTW_SL en typeflag. Para obtener resultados predecibles, utilice nftw().

ESTÁNDARES

POSIX.1-2008.

HISTORIA

ftw()
POSIX.1-2001, SVr4, SUSv1. POSIX.1-2008 lo marca como obsoleto.
nftw()
glibc 2.1. POSIX.1-2001, SUSv1.
FTW_SL
POSIX.1-2001, SUSv1.

NOTAS

POSIX.1-2008 señala que los resultados no están especificados si fn no preserva el directorio de trabajo actual.

ERRORES

Según POSIX.1-2008, cuando el argumento typeflag pasado a fn() contiene FTW_SLN, el búfer apuntado por sb debe contener información sobre el enlace simbólico colgante (obtenido llamando a lstat(2) sobre el enlace). Las primeras versiones de glibc seguían correctamente la especificación POSIX en este punto. Sin embargo, como resultado de una regresión introducida en glibc 2.4, el contenido del búfer apuntado por sb no estaba definido cuando se pasaba FTW_SLN en typeflag. (Más precisamente, el contenido del búfer se dejaba sin cambios en este caso.) Esta regresión fue finalmente corregida en glibc 2.30, de modo que la implementación de glibc (una vez más) sigue la especificación POSIX.

EJEMPLOS

El siguiente programa recorre el árbol de directorios bajo la ruta de acceso especificada en su primer argumento de línea de comandos, o bajo el directorio actual si no se proporciona ningún argumento. Muestra diversa información sobre cada archivo. El segundo argumento de línea de comandos se puede utilizar para especificar caracteres que controlan el valor asignado al argumento flags al llamar a nftw().

Fuente del programa

#define _XOPEN_SOURCE 500
#include <ftw.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
static int
display_info(const char *fpath, const struct stat *sb,
             int tflag, struct FTW *ftwbuf)
{
    printf("%-3s %2d ",
           (tflag == FTW_D) ?   "d"   : (tflag == FTW_DNR) ? "dnr" :
           (tflag == FTW_DP) ?  "dp"  : (tflag == FTW_F) ?   "f" :
           (tflag == FTW_NS) ?  "ns"  : (tflag == FTW_SL) ?  "sl" :
           (tflag == FTW_SLN) ? "sln" : "???",
           ftwbuf->level);
    if (tflag == FTW_NS)
        printf("-------");
    else
        printf("%7jd", (intmax_t) sb->st_size);
    printf("   %-40s %d %s\n",
           fpath, ftwbuf->base, fpath + ftwbuf->base);
    return 0;           /* Para decirle a nftw() que continúe */
}
int
main(int argc, char *argv[])
{
    int flags = 0;
    if (argc > 2 && strchr(argv[2], 'd') != NULL)
        flags |= FTW_DEPTH;
    if (argc > 2 && strchr(argv[2], 'p') != NULL)
        flags |= FTW_PHYS;
    if (nftw((argc < 2) ? "." : argv[1], display_info, 20, flags)
        == -1)
    {
        perror("nftw");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS);
}
