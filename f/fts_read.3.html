fts(3) Manual de Funciones de Biblioteca fts(3)

NOMBRE

fts, fts_open, fts_read, fts_children, fts_set, fts_close - recorrer una jerarquía de archivos

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <sys/types.h>
#include <sys/stat.h>
#include <fts.h>
FTS *fts_open(char *const *path_argv, int options,
              typeof(int (const FTSENT **, const FTSENT **))
                  *_Nullable compar);
FTSENT *fts_read(FTS *ftsp);
FTSENT *fts_children(FTS *ftsp, int instr);
int fts_set(FTS *ftsp, FTSENT *f, int instr);
int fts_close(FTS *ftsp);

DESCRIPCIÓN

Las funciones fts se proporcionan para recorrer jerarquías de archivos. Una descripción general es que la fts_open() función devuelve un "manejador" (de tipo FTS *) que se refiere a un "flujo" de jerarquía de archivos. Este manejador se proporciona entonces a las otras funciones fts. La función fts_read() devuelve un puntero a una estructura que describe uno de los archivos en la jerarquía de archivos. La función fts_children() devuelve un puntero a una lista enlazada de estructuras, cada una de las cuales describe uno de los archivos contenidos en un directorio en la jerarquía.

En general, los directorios se visitan dos veces distinguibles; en preorden (antes de que se visiten cualquiera de sus descendientes) y en postorden (después de que se hayan visitado todos sus descendientes). Los archivos se visitan una sola vez. Es posible recorrer la jerarquía "lógicamente" (visitando los archivos a los que apuntan los enlaces simbólicos) o físicamente (visitando los enlaces simbólicos mismos), ordenar el recorrido de la jerarquía o podar y/o revisitar partes de la jerarquía.

Dos estructuras (y tipos asociados) están definidas en el archivo de inclusión <fts.h>. El primer tipo es FTS, la estructura que representa la jerarquía de archivos en sí. El segundo tipo es FTSENT, la estructura que representa un archivo en la jerarquía de archivos. Normalmente, una FTSENT estructura se devuelve por cada archivo en la jerarquía de archivos. En esta página del manual, "archivo" y "estructura FTSENT" son generalmente intercambiables.

La FTSENT estructura contiene campos que describen un archivo. La estructura contiene al menos los siguientes campos (hay campos adicionales que deben considerarse privados de la implementación):


typedef struct _ftsent {
    unsigned short  fts_info;     /* flags for FTSENT structure */
    char           *fts_accpath;  /* access path */
    char           *fts_path;     /* root path */
    short           fts_pathlen;  /* strlen(fts_path) +
                                     strlen(fts_name) */
    char           *fts_name;     /* filename */
    short           fts_namelen;  /* strlen(fts_name) */
    short           fts_level;    /* depth (-1 to N) */
    int             fts_errno;    /* file errno */
    long            fts_number;   /* local numeric value */
    void           *fts_pointer;  /* local address value */
    struct _ftsent *fts_parent;   /* parent directory */
    struct _ftsent *fts_link;     /* next file structure */
    struct _ftsent *fts_cycle;    /* cycle structure */
    struct stat    *fts_statp;    /* [l]stat(2) information */
} FTSENT;

Estos campos están definidos de la siguiente manera:

fts_info
Uno de los siguientes valores que describen la estructura FTSENT devuelta y el archivo que representa. Con la excepción de los directorios sin errores (FTS_D), todas estas entradas son terminales, es decir, no serán revisitadas, ni se visitará ninguno de sus descendientes.
FTS_D
Un directorio que se está visitando en preorden.
FTS_DC
Un directorio que causa un ciclo en el árbol. (El fts_cycle campo de la estructura FTSENT también se rellenará.)
FTS_DEFAULT
Cualquier FTSENT estructura que representa un tipo de archivo no descrito explícitamente por uno de los otros fts_info valores.
FTS_DNR
Un directorio que no se puede leer. Esta es una devolución de error, y el fts_errno campo se establecerá para indicar qué causó el error.
FTS_DOT
Un archivo llamado "." o ".." que no fue especificado como un nombre de archivo para fts_open() (ver FTS_SEEDOT).
FTS_DP
Un directorio que se está visitando en postorden. El contenido de la FTSENT estructura no cambiará desde cuando se devolvió en preorden, es decir, con el fts_info campo establecido a FTS_D.
FTS_ERR
Esta es una devolución de error, y el fts_errno campo se establecerá para indicar qué causó el error.
FTS_F
Un archivo regular.
FTS_NS
Un archivo para el cual no había información del]stat(2) disponible. El contenido del fts_statp campo es indefinido. Esta es una devolución de error, y el fts_errno campo se establecerá para indicar qué causó el error.
FTS_NSOK
Un archivo para el cual no se solicitó información del]stat(2) . El contenido del fts_statp campo es indefinido.
FTS_SL
Un enlace simbólico.
FTS_SLNONE
Un enlace simbólico con un destino inexistente. El contenido del fts_statp campo hace referencia a la información de característica del archivo para el enlace simbólico mismo.
fts_accpath
Una ruta para acceder al archivo desde el directorio actual.
fts_path
La ruta para el archivo relativa a la raíz del recorrido. Esta ruta contiene la ruta especificada a fts_open() como prefijo.
fts_pathlen
La suma de las longitudes de las cadenas referenciadas por fts_path y fts_name.
fts_name
El nombre del archivo.
fts_namelen
La longitud de la cadena referenciada por fts_name.
fts_level
La profundidad del recorrido, numerada de -1 a N, donde se encontró este archivo. La FTSENT estructura que representa al padre del punto de inicio (o raíz) del recorrido está numerada -1, y la FTSENT estructura para la raíz misma está numerada 0.
fts_errno
Si fts_children() o fts_read() devuelve una FTSENT estructura cuyo fts_info campo está establecido a FTS_DNR, FTS_ERR, o FTS_NS, el fts_errno campo contiene el número de error (es decir, el valor errno ) que especifica el error. De lo contrario, el contenido del fts_errno campo es indefinido.
fts_number
Este campo se proporciona para el uso del programa de aplicación y no es modificado por las funciones fts. Se inicializa a 0.
fts_pointer
Este campo se proporciona para el uso del programa de aplicación y no es modificado por las funciones fts. Se inicializa a NULL.
fts_parent
Un puntero a la FTSENT estructura que hace referencia al archivo en la jerarquía inmediatamente encima del archivo actual, es decir, el directorio del cual este archivo es miembro. fts_close()

La fts_close() función cierra el flujo de jerarquía de archivos al que se refiere ftsp y restaura el directorio actual al directorio desde el que se llamó a fts_open() para abrir ftsp. La fts_close() función devuelve 0 en caso de éxito, y -1 si ocurre un error .

ERRORES

La función fts_open() puede fallar y establecer errno para cualquiera de los errores especificados para open(2) y malloc(3).

Además, fts_open() puede fallar y establecer errno como sigue:

ENOENT
Cualquier elemento de path_argv era una cadena vacía.

La función fts_close() puede fallar y establecer errno para cualquiera de los errores especificados para chdir(2) y close(2).

Las funciones fts_read() y fts_children() pueden fallar y establecer errno para cualquiera de los errores especificados para chdir(2), malloc(3), opendir(3), readdir(3), y [l]stat(2).

Además, fts_children(), fts_open(), y fts_set() pueden fallar y establecer errno como sigue:

EINVAL
options o instr era inválido.
