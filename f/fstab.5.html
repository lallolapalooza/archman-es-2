FSTAB(5) Formatos de archivo FSTAB(5)

NOMBRE

fstab - información estática sobre los sistemas de archivos

SINOPSIS

/etc/fstab

DESCRIPCIÓN

El archivo fstab contiene información descriptiva sobre los sistemas de archivos que el sistema puede montar. fstab solo es leído por programas y no se escribe; es deber del administrador del sistema crear y mantener adecuadamente este archivo. El orden de los registros en fstab es importante porque fsck(8), mount(8) y umount(8) iteran secuencialmente a través de fstab haciendo sus tareas.

El archivo no es leído solo por mount(8), sino que es utilizado a menudo por muchas otras herramientas y demonios, y una funcionalidad adecuada puede requerir pasos adicionales. Por ejemplo, en sistemas basados en systemd, se recomienda usar systemctl daemon-reload después de modificar fstab.

Cada sistema de archivos se describe en una línea separada, con campos separados por tabulaciones o espacios. La línea se divide en campos antes de ser analizada. Esto significa que cualquier espacio o tabulación dentro de los campos debe escaparse usando \040 o \011, incluso dentro de cadenas entre comillas (por ejemplo, LABEL="foo\040bar").

Las líneas que comienzan con '#' son comentarios. Las líneas en blanco se ignoran.

El siguiente es un ejemplo típico de una entrada de fstab:

LABEL=t-home2   /home      ext4    defaults,auto_da_alloc      0  2

El primer campo (fs_spec).

Este campo describe el dispositivo especial de bloque, el sistema de archivos remoto o la imagen del sistema de archivos para el dispositivo de bucle que se montará o el archivo de intercambio o dispositivo de intercambio que se habilitará.

Para montajes ordinarios, contendrá (un enlace a) un nodo de dispositivo especial de bloque (como lo crea mknod(2)) para el dispositivo que se montará, como /dev/cdrom o /dev/sdb7. Para montajes NFS, este campo es <host>:<dir>, por ejemplo, knuth.aeb.nl:/. Para sistemas de archivos sin almacenamiento, se puede usar cualquier cadena, y aparecerá en la salida de df(1), por ejemplo. El uso típico es proc para procfs; mem, none o tmpfs para tmpfs. Otros sistemas de archivos especiales, como udev y sysfs, típicamente no se listan en fstab.

LABEL=<etiqueta> o UUID=<uuid> pueden ser dados en lugar de un nombre de dispositivo. Este es el método recomendado, ya que los nombres de dispositivo a menudo son una coincidencia del orden de detección de hardware y pueden cambiar cuando se agregan o eliminan otros discos. Por ejemplo, 'LABEL=Boot' o 'UUID=3e6be9de-8139-11d1-9106-a43f08d823a6'. (Use una herramienta específica del sistema de archivos como e2label(8), xfs_admin(8) o fatlabel(8) para establecer etiquetas en los sistemas de archivos).

También es posible usar PARTUUID= y PARTLABEL=. Estos identificadores de particiones son compatibles, por ejemplo, para la Tabla de Particiones GUID (GPT).

Consulte mount(8), blkid(8) o lsblk(8) para obtener más detalles sobre los identificadores de dispositivos.

Tenga en cuenta que mount(8) usa UUIDs como cadenas. La representación de cadena del UUID debe basarse en caracteres en minúscula. Pero al especificar el ID del volumen de sistemas de archivos FAT o NTFS se utilizan caracteres en mayúscula (por ejemplo, UUID="A40D-85E7" o UUID="61DB7756DB7779B3").

El segundo campo (fs_file).

Este campo describe el punto de montaje (destino) para el sistema de archivos. Para el área de intercambio, este campo debe especificarse como `none'. Si el nombre del punto de montaje contiene espacios o tabulaciones, estos pueden escaparse como `\040' y `\011' respectivamente.

El tercer campo (fs_vfstype).

Este campo describe el tipo de sistema de archivos. Linux admite muchos tipos de sistemas de archivos: ext4, xfs, btrfs, f2fs, vfat, ntfs, hfsplus, tmpfs, sysfs, proc, iso9660, udf, squashfs, nfs, cifs y muchos más. Para más detalles, consulte mount(8).

Una entrada swap denota un archivo o partición que se usará para el intercambio, cf. swapon(8). Una entrada none es útil para montajes bind o move.

Se pueden especificar más de un tipo en una lista separada por comas.

mount(8) y umount(8) admiten *subtipos* de sistemas de archivos. El subtipo se define por el sufijo '.subtype'. Por ejemplo, 'fuse.sshfs'. Se recomienda usar la notación de subtipo en lugar de agregar cualquier prefijo al primer campo de fstab (por ejemplo, 'sshfs#example.com' está obsoleto).

El cuarto campo (fs_mntops).

Este campo describe las opciones de montaje asociadas con el sistema de archivos.

Está formateado como una lista de opciones separadas por comas y es opcional para mount(8) o swapon(8). La convención usual es usar al menos la palabra clave "defaults" allí.

Generalmente contiene el tipo de montaje (ro o rw, el valor predeterminado es rw), más cualquier opción adicional apropiada para el tipo de sistema de archivos (incluidas las opciones de ajuste de rendimiento). Para más detalles, consulte mount(8) o swapon(8).

Las opciones básicas independientes del sistema de archivos son:

defaults

usa opciones predeterminadas. El valor predeterminado depende del kernel y del sistema de archivos. mount(8) no tiene ningún conjunto predeterminado de opciones codificado. El valor predeterminado del kernel suele ser rw, suid, dev, exec, auto, nouser y async.

noauto

no montar cuando se da mount -a (por ejemplo, al arrancar)

user

permitir que un usuario monte

owner

permitir que el propietario del dispositivo monte

comment

o x-<nombre> para uso por programas que mantienen fstab

nofail

no informar errores para este dispositivo si no existe.

El quinto campo (fs_freq).

Este campo es utilizado por dump(8) para determinar qué sistemas de archivos necesitan ser volcados (dumped). El valor predeterminado es cero (no volcar) si no está presente.

El sexto campo (fs_passno).

Este campo es utilizado por fsck(8) para determinar el orden en que se realizan las comprobaciones del sistema de archivos al arrancar. El sistema de archivos raíz debe especificarse con un fs_passno de 1. Otros sistemas de archivos deben tener un fs_passno de 2. Los sistemas de archivos dentro de una unidad se comprobarán secuencialmente, pero los sistemas de archivos en diferentes unidades se comprobarán al mismo tiempo para utilizar el paralelismo disponible en el hardware. El valor predeterminado es cero (no comprobar el sistema de archivos) si no está presente.

ARCHIVOS

/etc/fstab, <fstab.h>

NOTAS

La forma correcta de leer registros de fstab es usar las rutinas getmntent(3) o libmount.

La palabra clave ignore como tipo de sistema de archivos (3er campo) ya no es compatible con la base pura de libmount
