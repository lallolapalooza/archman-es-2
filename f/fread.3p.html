FREAD(3P) Manual del Programador POSIX FREAD(3P)

PRÓLOGO

Esta página de manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página de manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fread — entrada binaria

SINOPSIS

#include <stdio.h>
size_t fread(void *restrict ptr, size_t size, size_t nitems,
    FILE *restrict stream);

DESCRIPCIÓN

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C no es intencional. Este volumen de POSIX.1‐2017 se remite al estándar ISO C.

La función fread() leerá en el array apuntado por ptr hasta nitems elementos cuyo tamaño está especificado por size en bytes, del stream apuntado por stream. Para cada objeto, se harán size llamadas a la función fgetc() y los resultados se almacenarán, en el orden leído, en un array de unsigned char que cubre exactamente el objeto. El indicador de posición del archivo para el stream (si está definido) se avanzará por el número de bytes leídos con éxito. Si ocurre un error, el valor resultante del indicador de posición del archivo para el stream es indeterminado. Si se lee un elemento parcial, su valor es indeterminado.

La función fread() puede marcar la marca de tiempo de último acceso a datos del archivo asociado con stream para su actualización. La marca de tiempo de último acceso a datos será marcada para su actualización por la primera ejecución exitosa de fgetc(), fgets(), fread(), fscanf(), getc(), getchar(), getdelim(), getline(), gets(), o scanf() usando stream que retorna datos no provistos por una llamada previa a ungetc().

VALOR RETORNADO

Tras la finalización exitosa, fread() retornará el número de elementos leídos con éxito, el cual es menor que nitems solo si se encuentra un error de lectura o el fin del archivo. Si size o nitems es 0,fread () retornará 0 y el contenido del array y el estado del stream permanecerán sin cambios. De lo contrario, si ocurre un error de lectura, el indicador de error para el stream será establecido, y errno

será establecido para indicar el error.

ERRORES Refiérase afgetc().

Las siguientes secciones son informativas.

EJEMPLOS

Leyendo de un Stream

El siguiente ejemplo transfiere un registro de longitud fija de 100 bytes desde el stream fp al array apuntado por buf.

#include <stdio.h>
...
size_t elements_read;
char buf[100];
FILE *fp;
...
elements_read = fread(buf, sizeof(buf), 1, fp);
...

Si ocurre un error de lectura, elements_read será cero pero el número de bytes leídos del stream podría ser cualquiera desde cero hasta sizeof(buf)-1.

El siguiente ejemplo lee múltiples elementos de un byte desde el stream fp al array apuntado por buf.

#include <stdio.h>
...
size_t bytes_read;
char buf[100];
FILE *fp;
...
bytes_read = fread(buf, 1, sizeof(buf), fp);
...

Si ocurre un error de lectura, bytes_read contendrá el número de bytes leídos del stream.

USO EN APLICACIONES

Las funciones ferror() o feof() deben usarse para distinguir entre una condición de error y una condición de fin de archivo.

Debido a posibles diferencias en la longitud de los elementos y el ordenamiento de bytes, los archivos escritos usando fwrite() son dependientes de la aplicación, y posiblemente no puedan ser leídos usando fread() por una aplicación diferente o por la misma aplicación en un procesador diferente.
