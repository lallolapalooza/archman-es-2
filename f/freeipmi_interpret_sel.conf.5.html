freeipmi_interpret_sel.conf - especifica las reglas de interpretación del registro de

eventos del sistema (SEL)

DESC

RIP
CIÓN

E

l

/etc/freeipmi//freeipmi_interpret_sel.conf define cómo deben interpretarse las entradas del registro de eventos del sistema (SEL) de IPMI. Los eventos del sistema IPMI especifican una serie de estados/umbrales cuando se leen. Basándose en esos estados/umbrales, bibliotecas y herramientas como libipmimonitoring(3) e ipmi-sel(8) pueden informar si un evento es "bueno" o "malo" mediante un informe de un estado NOMINAL, ADVERTENCIA o CRÍTICO. Se puede informar un estado diferente para un evento dependiendo de si está afirmado o

desafirmado.

Cada uno de los estados enumerados a continuación es (con suerte) lo suficientemente descriptivo como para describir las condiciones de estado que pueden establecerse/anularse para cada sensor o tipo de evento. Para obtener información más detallada sobre cada uno de los estados individuales enumerados a continuación, consulte las "Tablas de códigos de sensores y eventos" de la Especificación IPMI. Ipmi-sensors(8) se puede utilizar para determinar los tipos de sensores y los estados/umbrales que existen en un sistema mediante la salida de una salida muy detallada y observando qué tipos de eventos de Afirmación o Desafirmación son

posibles.

Cada uno de los eventos siguientes puede tomar 1 o 2 de los siguientes estados como

entrada.

Nominal - Señala una lectura Nominal si el evento se

activa

Advertencia - Señala una lectura de Advertencia si el evento se

activa

Crítico - Señala una lectura Crítica si el evento se

activa

Si solo se enumera un estado, ese estado se interpretará cuando el evento esté afirmado o desafirmado. Si se enumeran dos estados, el primer estado se interpretará cuando un evento esté afirmado, y el segundo se interpretará cuando un evento esté

desafirmado.

No todos los tipos de sensores y tipos de eventos de IPMI son compatibles actualmente. Si desea que se admitan más, envíe un correo electrónico a la lista de correo de

FreeIPMI.

Los valores predeterminados seleccionados para la activación de eventos individuales se basan en suposiciones y en el análisis de placas base. Si cree que deberían cambiarse, envíe un correo electrónico a la lista de correo de FreeIPMI para discutir cuáles deberían ser los valores predeterminados

.

La mayoría de las interpretaciones predeterminadas se pueden determinar con bastante facilidad y pueden satisfacer las necesidades de la mayoría de los usuarios. Por ejemplo, una lectura de

"Performance_Met" normalmente es mejor que "Performance_Lags". Sin embargo, algunos sensores pueden ser ambiguos y depender completamente del fabricante. Por ejemplo, "State_Asserted" vs.
"State_Deasserted" dependen completamente de la interpretación del proveedor. Se recomienda a los usuarios que ajusten las interpretaciones siguientes según las necesidades de sus máquinas.

FORMAT

O

Las opciones de configuración que se pueden especificar en el archivo de configuración se enumeran a continuación. Cada opción de configuración debe figurar en una

línea separada. Los argumentos de una opción se separan por cualquier cantidad de espacios en blanco. Los argumentos múltiples también se separan por espacios en
blanco. Los comentarios se pueden marcar utilizando el signo de número ("#"), y las líneas se pueden continuar en la siguiente utilizando la barra invertida ("\").

NAME

freeipmi_interpret_sel.conf ― SEL record interpretation configuration file

DESCRIPTION

The freeipmi_interpret_sel.conf file allows users to configure how FreeIPMI should interpret SEL (System Event Log) records that are generated by hardware that does not conform to the IPMI specification. Specifically, it allows for the interpretation of OEM (Original Equipment Manufacturer) records.

The file is structured as a series of directives, each on its own line. Directives can be commented out using a hash symbol (#). Blank lines are ignored.

FORMAT

The file can contain the following directives:

IPMI_OEM_Timestamped_Record <Manufacturer-ID>:<Product-ID>,... Record-Type OEMDATA1 OEMDATA2 OEMDATA3 OEMDATA4 OEMDATA5 OEMDATA6 OEMDATA7 OEMDATA8 OEMDATA9 OEMDATA10 OEMDATA11 OEMDATA12 OEMDATA13
IPMI_OEM_Timestamped_Record can be used to configure an interpretation for a specific Manufacturer-ID, Product-ID, Record-Type, and OEM data combination. The Record-Type must be a legal record type for OEM Timestamped Records (currently 0xC0-0xDF). Each of the OEMDATA fields must specify a hex byte to match or the keyword ANY to match anything.
IPMI_OEM_Non_Timestamped_Record <Manufacturer-ID>:<Product-ID>,... Record-Type OEMDATA1 OEMDATA2 OEMDATA3 OEMDATA4 OEMDATA5 OEMDATA6 OEMDATA7 OEMDATA8 OEMDATA9 OEMDATA10 OEMDATA11 OEMDATA12 OEMDATA13 State
IPMI_OEM_Non_Timestamped_Record can be used to configure an interpretation for a specific Manufacturer-ID, Product-ID, Record-Type, and OEM data combination. The Record-Type must be a legal record type for OEM Non-Timestamped Records (currently 0xEO-0xFF). Each of the OEMDATA fields must specify a hex byte to match or the keyword ANY to match anything.
