NOMBRE

fw1_lea2dlf - convertir registros de Check Point FireWall-1 NG a firewall DLF

SINOPSIS

fw1_lea2dlf archivo

DESCRIPCIÓN

fw1_lea2dlf convierte los registros de Check Point FireWall-1 NG al formato firewall DLF. La entrada para este convertidor es la salida de fw1-loggrabber, un cliente LEA (Log Export Api) sencillo.

INSTRUCCIONES DE ACTIVACIÓN

Este convertidor DLF no está activado por defecto en Lire. Requiere el módulo perl Date::Manip y la herramienta fw1-loggrabber. Date::Manip puede instalarse desde CPAN. fw1-loggrabber está disponible en http://sourceforge.net/projects/fw1-loggrabber .

Si ambos componentes están instalados, puede activar el convertidor DLF fw1_lea descomentando su línea en el archivo @sysconfdir@/@PACKAGE@/address.cf

OTRAS NOTAS

¡Cuidado! En caso de que esté recibiendo muchas advertencias quejándose de caracteres UTF-8, con apariencia de:

all all UNSET fw1_lea2dlf warning Malformed UTF-8 character
 (unexpected non-continuation byte 0x7a, immediately after
 start byte 0xe3) at /usr/lib/perl5/vendor_perl/5.8.0/Date/Manip.pm
 line 5931.

, y su configuración regional (locale) tiene UTF-8 habilitado, hay una solución temporal: Establezca las variables de entorno LANG y LC_CTYPE a en_US en lugar de, por ejemplo, en_US.UTF-8. Puede hacerlo temporalmente dentro de la llamada del convertidor:

LANG=en_US LC_CTYPE=en_US ./fw12dlf < /su/archivo/de/registro

fw1-loggrabber

fw1-loggrabber está construido usando el Software Development Kit de OPSEC. OPSEC (Open Platform for Security, http://www.opsec.com/) es un marco de seguridad abierto y multivendedor.

Algunas notas sobre fw1-loggrabber citadas aquí.

1) Prerrequisitos
a) para ejecutar FW1-LOGGRABBER
FW1-LOGGRABBER está enlazado estáticamente y por lo tanto puede
ejecutarse en los siguientes sistemas:
* Linux (Las distribuciones probadas son Red Hat, SuSE y De-
  bian con versiones de kernel 2.2.x y 2.4.x)
* Solaris SPARC (Las versiones probadas son Solaris 8 y 9)
 * Windows NT/2000/XP (actualmente no hay una versión W32 de FW1-LOGGRABBER
  disponible y por lo tanto aún no se ha probado)
b) para compilar FW1-LOGGRABBER
FW1-LOGGRABBER usa funciones API del OPSEC SDK de Checkpoint.
Para poder compilar aplicaciones
que usen este SDK, se debe usar un entorno de compilación
muy especial. Actualmente, la compilación de FW1-LOGGRABBER
solo está soportada para la plataforma Solaris SPARC y la plataforma
Linux.
* Linux
 - Red Hat 6.2
 - gcc 2.95.1
 - Checkpoint OPSEC SDK NG-FP3 para Linux 2.2
* Solaris SPARC
 - Solaris 8
 - gcc 2.95.2
 - Checkpoint OPSEC SDK NG-FP3 para Solaris SPARC
* Windows
 - EDITAR
3) Cómo usarlo
a) Configurar FW1 para habilitar el protocolo LEA
Para poder usar esta herramienta con una instalación de Checkpoint
FW-1, se deben realizar las siguientes tareas:
* modificar $FWDIR/conf/fwopsec.conf y definir el puerto
  para conexiones LEA no autenticadas.
    #  lea_server  auth_port   18184
    lea_server       port       50001
* reiniciar FW1 (cpstop / cpstart) para activar los cambios
* añadir una regla a la política para habilitar conexiones en el puerto
  50001 hacia el Servidor de Gestión de FW-1
b) Uso de FW1-LOGGRABBER
FW1-LOGGRABBER está enlazado estáticamente y por lo tanto no
depende de las bibliotecas OPSEC. El binario puede ejecutarse en
cualquier sistema Linux o Solaris SPARC.
Opciones de línea de comandos:
 -s             Dirección IP del Servidor de Gestión de FW1
 -p             Puerto LEA no autenticado del Servidor de FW1
 -f             Nombre exacto del archivo de registro de FW1 o patrón a
                buscar en los archivos de registro de FW1.
 --resolve      Resolver direcciones IP a nombres
 --noresolve    No resolver direcciones IP a nombres
 --showfiles    Solo mostrar los archivos de registro de FW1 disponibles y salir.
 --debug        Habilitar el modo de depuración de FW1-LOGGRABBER
Ejemplos:
o fw1-loggrabber -s 192.168.2.254 -p 50001 --showfiles

 Mostrar todos los archivos de registro disponibles en el Servidor de Gestión
 de FW1 con la dirección IP 192.168.2.254. El puerto LEA
 en el que el Servidor de Gestión escucha conexiones no autenticadas
 es 50001.
o fw1-loggrabber -s 192.168.2.254 -p 50001
 Mostrar todas las entradas de registro del archivo de registro predeterminado de FW1 (fw.log)
 en el Servidor de Gestión de FW1 con la dirección IP
 192.168.2.254 y el puerto LEA 50001.
o fw1-loggrabber -s 192.168.2.254 -p 50001 -f 2003-03-27_213652.log
 Mostrar todas las entradas de registro del archivo especificado. Si el archivo de registro
 no existe en el Servidor de Gestión de FW1 especificado,
 no se devuelven entradas.
o fw1-loggrabber -s 192.168.2.254 -p 50001 -f 2003-03
 Mostrar todas las entradas de registro de todos los archivos de registro en el Servidor de Gestión
 de FW1 que contengan el patrón "2003-03", es decir, todos los archivos de
 registro de marzo de 2003
o fw1-loggrabber -s 192.168.2.254 -p 50001 -f fw.adtlog
 Mostrar todas las entradas de registro del archivo de auditoría en el Servidor de Gestión de FW1

EJEMPLOS

Para procesar un registro producido por FW-1:

$ fw1-loggrabber -s 192.168.2.254 -p 50001 -f fw.log | fw12dlf

fw1_lea2dlf rara vez se usará por sí solo, sino que es más probable que sea llamado por lr_log2report:

$ fw1-loggrabber -s 192.168.2.254 -p 50001 -f fw.log | \
   lr_log2report fw1_lea

ERRORES / POR HACER

Este convertidor necesita la biblioteca Date::Manip de perl. Sería mejor usar otro módulo para esto, usado por más código de Lire.

El estado y la licencia de fw1-loggrabber son desconocidos.
