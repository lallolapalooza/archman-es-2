FMEMOPEN(3P) Manual del Programador POSIX FMEMOPEN(3P)

PRÓLOGO

Esta página manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página manual correspondiente de Linux para detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

fmemopen — abrir un flujo de búfer de memoria

SINOPSIS

#include <stdio.h>
FILE *fmemopen(void *restrict buf, size_t size,
    const char *restrict mode);

DESCRIPCIÓN

La función fmemopen() asociará el búfer dado por los argumentos buf y size con un flujo. El argumento buf debe ser un puntero nulo o apuntar a un búfer que tenga al menos size bytes de longitud.

El argumento mode apunta a una cadena. Si la cadena es una de las siguientes, el flujo se abrirá en el modo indicado. De lo contrario, el comportamiento es indefinido.

r
Abrir el flujo para lectura.
w
Abrir el flujo para escritura.
a
Adjuntar; abrir el flujo para escritura en el primer byte nulo.
r+
Abrir el flujo para actualización (lectura y escritura).
w+
Abrir el flujo para actualización (lectura y escritura). Truncar el contenido del búfer.
a+
Adjuntar; abrir el flujo para actualización (lectura y escritura); la posición inicial está en el primer byte nulo.

Las implementaciones deben aceptar todas las cadenas de modo permitidas por fopen(), pero el uso del carácter 'b' producirá resultados definidos por la implementación, donde el resultado FILE * no necesita comportarse igual que si 'b' se hubiera omitido.

Si se especifica un puntero nulo como el argumento buf , fmemopen() asignará size bytes de memoria como si fuera una llamada a malloc(). Este búfer se liberará automáticamente cuando se cierre el flujo. Dado que esta característica solo es útil cuando el flujo se abre para actualización (porque no hay forma de obtener un puntero al búfer), la llamada fmemopen() puede fallar si el argumento mode no incluye un '+'.

El flujo mantendrá una posición actual en el búfer. Esta posición se establecerá inicialmente ya sea al comienzo del búfer (para los modos r y w ) o al primer byte nulo en el búfer (para los modos a ). Si no se encuentra ningún byte nulo en el modo de adjuntar, la posición inicial se establecerá a un byte después del final del búfer.

Si buf es un puntero nulo, la posición inicial siempre se establecerá al comienzo del búfer.

El flujo también mantendrá el tamaño del contenido actual del búfer; el uso de fseek() o fseeko() en el flujo con SEEK_END buscará relativo a este tamaño. Para los modos r y r+ el tamaño se establecerá al valor dado por el argumento size . Para los modos w y w+ el tamaño inicial será cero y para los modos a y a+ el tamaño inicial será:

*
Cero, si buf es un puntero nulo
*
La posición del primer byte nulo en el búfer, si se encuentra uno
*
El valor del argumento size , si buf no es un puntero nulo y no se encuentra ningún byte nulo

Una operación de lectura en el flujo no avanzará la posición actual del búfer más allá del tamaño actual del búfer. Alcanzar el tamaño del búfer en una operación de lectura se contará como ``fin de archivo''. Los bytes nulos en el búfer no tendrán ningún significado especial para las lecturas. La operación de lectura comenzará en la posición actual del búfer del flujo.

Una operación de escritura comenzará ya sea en la posición actual del flujo (si mode no ha especificado 'a' como el primer carácter) o en el tamaño actual del flujo (si mode tenía 'a' como el primer carácter). Si la posición actual al final de la escritura es mayor que el tamaño actual del búfer, el tamaño actual del búfer se establecerá a la posición actual. Una operación de escritura en el flujo no avanzará el tamaño actual del búfer más allá del tamaño dado en el argumento size .

Cuando un flujo abierto para escritura se vacía o se cierra, se escribirá un byte nulo en la posición actual o en el final del búfer, dependiendo del tamaño del contenido. Si un flujo abierto para actualización se vacía o se cierra y la última escritura ha avanzado el tamaño actual del búfer, se escribirá un byte nulo en el final del búfer si cabe.

Un intento de buscar en un flujo de búfer de memoria hacia una posición negativa o hacia una posición mayor que el tamaño del búfer dado en el argumento size fallará.

VALOR DE RETORNO

Tras una finalización exitosa, fmemopen() devolverá un puntero al objeto que controla el flujo. De lo contrario, se devolverá un puntero nulo, y errno se establecerá para indicar el error.

ERRORES

La función fmemopen() fallará si:

EMFILE
Hay {STREAM_MAX} flujos abiertos actualmente en el proceso que llama.

La función fmemopen() puede fallar si:

EINVAL
El valor del argumento mode no es válido.
EINVAL
El argumento buf es un puntero nulo y el argumento mode no incluye un carácter '+' .
EINVAL
El argumento size especifica un tamaño de búfer de cero y la implementación no lo soporta.
ENOMEM
El argumento buf es un puntero nulo y la asignación de un búfer de longitud size ha fallado.
EMFILE
Hay {FOPEN_MAX} flujos abiertos actualmente en el proceso que llama.

Las siguientes secciones son informativas.

EJEMPLOS

#include <stdio.h>
#include <string.h>
static char buffer[] = "foobar";
int
main (void)
{
    int ch;
    FILE *stream;
    stream = fmemopen(buffer, strlen (buffer), "r");
    if (stream == NULL)
        /* manejar error */;
    while ((ch = fgetc(stream)) != EOF)
        printf("Got %c\n", ch);
    fclose(stream);
    return (0);
}

Este programa produce la siguiente salida:

Got f
Got o
Got o
Got b
Got a
Got r

USO EN APLICACIONES

Ninguno.

JUSTIFICACIÓN

Esta interfaz se ha introducido para eliminar muchos de los errores encontrados en la construcción de cadenas, notablemente el desbordamiento de cadenas. Esta interfaz previene el desbordamiento.

DIRECCIONES FUTURAS

Una versión futura de este estándar puede prescribir un comportamiento específico cuando el argumento mode incluya 'b'.

Una versión futura de este estándar puede requerir el soporte explícito de flujos de búfer de longitud cero.

NAME

fmemopen

abrir un flujo en una cadena

SYNOPSIS

#include <stdio.h>

FILE *fmemopen(void *buf, size_t size, const char *mode);

DESCRIPTION

La función fmemopen abre un flujo en un búfer de memoria especificado por buf y size. El parámetro mode es una cadena que especifica cómo se debe acceder al flujo; su valor debe ser uno de los siguientes:

"r"
Abrir el flujo para lectura. El búfer se inicializa con la cadena apuntada por buf. Si buf es NULL, el flujo se abre como un flujo de solo lectura vacío.
"w"
Abrir el flujo para escritura. El búfer se inicializa vacío. Si buf es NULL, el flujo se abre como un flujo de solo escritura vacío.
"a"
Abrir el flujo para escritura. Las operaciones de escritura se añaden al final del contenido actual del búfer. Si buf es NULL, el flujo se abre como un flujo de solo escritura vacío.
"r+"
Abrir el flujo para lectura y escritura. El búfer se inicializa con la cadena apuntada por buf.
"w+"
Abrir el flujo para lectura y escritura. El búfer se inicializa vacío.
"a+"
Abrir el flujo para lectura y escritura. Las operaciones de escritura se añaden al final del contenido actual del búfer. Las operaciones de lectura se realizan desde la posición actual del puntero de archivo.

El parámetro mode puede contener un sufijo b, por ejemplo, "rb", pero no tiene ningún efecto, ya que los flujos de memoria siempre se manejan en modo binario.

Si buf no es NULL, se espera que buf apunte a un búfer de al menos size bytes de tamaño. Si buf es NULL y el modo es "r" o "r+", entonces el tamaño efectivo es 0, y el flujo se crea como un búfer vacío, pero no se asigna memoria; las escrituras aún resultarán en un error de segmentación. Si buf es NULL y el modo es "w", "w+", "a" o "a+", entonces se asigna un búfer de size bytes (o un tamaño predeterminado razonable si size es 0), y se debe llamar a free() sobre el puntero devuelto por fmemopen para liberar la memoria cuando ya no se necesite. Si size es 0, el comportamiento depende del modo: para "r", el flujo estará vacío; para "w", el flujo estará vacío pero se podrá escribir en él. Para los modos "a", "r+", "w+" y "a+", si size es 0, el comportamiento es indefinido si se intenta leer o escribir en el flujo sin haber asignado memoria explícitamente.

Si el modo es "r" o "r+", y buf apunta a una cadena terminada en nulo, el flujo se inicializará con el contenido de esa cadena. La operación de lectura en el flujo se detendrá en el carácter nulo, pero el carácter nulo no se incluirá en los datos leídos. Si la cadena termina en nulo y size es mayor que la longitud de la cadena más el carácter nulo, entonces las escrituras en el flujo no causarán un desbordamiento del búfer hasta que se escriban size bytes en total.

Los flujos creados por fmemopen son flujos de tamaño de registro 1. Las escrituras en un flujo de solo escritura no son permitidas. Las lecturas de un flujo de solo lectura son permitidas.

El comportamiento de llamar a fflush() o fclose() en un flujo abierto con fmemopen es el siguiente:

  • Si el modo incluye 'w' o 'a', fflush() o fclose() escribirán un carácter nulo nulo al final del contenido actual del búfer. Si el contenido resultante excede size bytes, el comportamiento es indefinido.
  • fclose() también liberará cualquier memoria asignada automáticamente (si buf era NULL y el modo lo requería).

El puntero de archivo dentro del flujo se mantiene entre las llamadas a las funciones de E/S, y se puede ajustar usando fseek() y rewind().

RETURN VALUE

En caso de éxito, fmemopen devuelve un puntero al objeto FILE que se puede usar para acceder al flujo. En caso de error, devuelve NULL y establece errno para indicar el error.

ERRORS

EINVAL
El valor de mode no es válido, o buf es NULL y el modo es "r" o "r+" y size no es 0.
ENOMEM
No hay suficiente memoria disponible para crear el flujo (cuando buf es NULL y el modo requiere asignación de búfer).

EXAMPLES

Para escribir una cadena en un búfer de memoria:

FILE *f;
char buf[100];
f = fmemopen (buf, sizeof (buf), "w");
fprintf (f, "Hello, world!\n");
fclose (f);
printf ("%s\n", buf);

Para leer una cadena de un búfer de memoria:

FILE *f;
char buf[] = "Hello, world!\n";
char line[100];
f = fmemopen (buf, sizeof (buf), "r");
fgets (line, sizeof (line), f);
printf ("%s", line);
fclose (f);

Para escribir en un búfer de memoria que se expande (hasta un límite):

FILE *f;
char *buf = NULL;
size_t len = 0;
f = fmemopen(buf, len, "w"); // Note: buf is NULL, len is 0
fprintf(f, "Some initial data.");
// Need to get the buffer pointer and size after writing.
// The man page doesn't describe how to do this, but some implementations
// provide a way to get the buffer pointer and current size.
// For example, on glibc:
// fflush(f); // Ensure buffer is flushed
// buf = ...; // Get the buffer pointer (implementation specific)
// len = ...; // Get the current buffer size (implementation specific)
fprintf(f, "Appending more data.");
fclose(f);
// Now buf contains the data if it was successfully written to.

APPLICATION USAGE

El uso de fmemopen permite a las aplicaciones manipular datos en memoria utilizando las funciones de E/S de la biblioteca estándar, lo que puede simplificar el código en comparación con el acceso directo a cadenas o búferes de memoria.

RATIONALE

La función fmemopen se añadió a POSIX.1-2008 para proporcionar una forma estándar de utilizar las funciones de E/S de flujo con búferes de memoria. Esto es útil para tareas como el análisis de cadenas de entrada, la creación de archivos temporales en memoria o la simulación de E/S de archivos para pruebas.

La opción de permitir buf NULL y size 0, especialmente para modos de escritura, permite a la biblioteca C asignar dinámicamente la memoria necesaria. Sin embargo, es importante que la aplicación libere esta memoria cuando ya no sea necesaria para evitar fugas de memoria.
