DESCRIPCIÓ

N

Estas funciones devuelven información sobre un archivo, en el búfer apuntado por statbuf. No se requieren permisos sobre el archivo en sí, pero —en el caso de stat(), fstatat(), y lstat()— se requiere permiso de ejecución (búsqueda) en todos los directorios en path que conducen al

archivo.

stat() y fstatat() recuperan información sobre el archivo apuntado por path; las diferencias para fstatat() se describen a

continuación.

lstat() es idéntico a stat(), excepto que si path es un enlace simbólico, entonces devuelve información sobre el enlace en sí, no sobre el archivo al que el enlace se

refiere.

fstat() es idéntico a stat(), excepto que el archivo sobre el cual se debe recuperar la información se especifica mediante el descriptor de archivo fd

.

La estructura

stat

Todas estas llamadas al sistema devuelven una estructura stat (ver stat(3type))

.

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura stat pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si st_mode o st_uid es cambiado por otro proceso al llamar a chmod(2) o chown(2), stat() podría devolver el antiguo st_mode junto con el nuevo st_uid, o el antiguo st_uid junto con el nuevo st_m

od
e.

fstatat(

)

La llamada al sistema fstatat() es una interfaz más general para acceder a la información del archivo que aún puede proporcionar exactamente el comportamiento de cada una de stat(), lstat(), y fstat

().

Si path es relativo, entonces se interpreta relativo al directorio referido por el descriptor de archivo dirfd (en lugar de relativo al directorio de trabajo actual del proceso que llama, como lo hace stat() y lstat() para una ruta relativa)

.

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta relativo al directorio de trabajo actual del proceso que llama (como stat() y lstat())

.

Si path es absoluto, entonces dirfd se

ignora.
