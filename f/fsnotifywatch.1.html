NAME

inotifywatch - Monitoriza archivos y directorios para cambios.

SYNOPSIS

inotifywatch [OPCIONES] [RUTA...]

DESCRIPTION

inotifywatch recopila y reporta información sobre eventos de inotify en archivos y directorios especificados. inotifywatch es útil para identificar qué archivos y directorios están siendo accedidos y modificados frecuentemente, o para identificar aplicaciones que acceden a archivos y directorios específicos.

inotifywatch puede ser usado para observar archivos y directorios individuales, o puede ser usado para observar directorios recursivamente. Los eventos que serán observados son especificados usando la opción -e.

inotifywatch continuará observando los archivos y directorios hasta que un tiempo límite sea alcanzado (especificado con la opción -t) o hasta que se presione Ctrl+C.

OUTPUT

La salida por defecto de inotifywatch es una tabla que contiene el recuento total de cada evento, el recuento de cada evento individual, y el nombre del archivo o directorio asociado con cada evento. La tabla es actualizada a medida que los eventos ocurren.

La siguiente tabla describe las columnas de salida:

total
El número total de eventos observados.
access
El número de accesos al archivo.
modify
El número de modificaciones al archivo.
attrib
El número de cambios de atributos al archivo.
close_write
El número de archivos cerrados que fueron escritos.
close_nowrite
El número de archivos cerrados que no fueron escritos.
close
El número de archivos cerrados (ya sea escritos o no).
open
El número de archivos abiertos.
moved_to
El número de archivos movidos al directorio observado.
moved_from
El número de archivos movidos desde el directorio observado.
move
El número de archivos movidos desde o hacia el directorio observado.
create
El número de archivos creados en el directorio observado.
delete
El número de archivos eliminados del directorio observado.
delete_self
El número de eventos de eliminación en el propio archivo observado.
move_self
El número de eventos de movimiento en el propio archivo observado.
unmount
El número de eventos de desmontaje del sistema de archivos.

OPTIONS

Las siguientes opciones están disponibles:

-q, --quiet
Suprime la salida de mensajes informativos.
-v, --verbose
Habilita la salida detallada. Esto incluye mostrar la información establecida, así como los eventos que fueron recibidos.
-e, --event EVENTO
Observa solo el evento especificado. Los eventos válidos son: access, modify, attrib, close_write, close_nowrite, close, open, moved_to, moved_from, move, create, delete, delete_self, move_self, unmount. Se pueden especificar múltiples eventos usando esta opción varias veces. Por defecto, todos los eventos son observados.
-t, --timeout SEGUNDOS
Sale después de que los segundos especificados hayan transcurrido. Un valor de 0 significa que no hay tiempo límite.
-r, --recursive
Observa los directorios recursivamente. Por defecto, solo los directorios especificados son observados.
-d, --daemonize
Ejecuta inotifywatch como un proceso demonio. Esto significa que se ejecutará en segundo plano y no producirá ninguna salida hasta que los eventos sean completados o ocurra un tiempo límite. Es útil cuando se quiere que inotifywatch se ejecute durante un período prolongado.
--pid PIDFILE
Escribe el PID del proceso demonio en el archivo especificado.
--exclude PATTERN
No muestra eventos que coincidan con el patrón de expresión regular especificado. El patrón se compara con el nombre del archivo.
--excludei PATTERN
Similar a --exclude, pero no distingue mayúsculas y minúsculas.

EXIT STATUS

inotifywatch devuelve 0 si tuvo éxito, y un valor distinto de cero si ocurre un error.

EVENTS

access
Un archivo o directorio fue accedido. Esto ocurre cuando el archivo o directorio es leído, o cuando se ejecuta como programa.
modify
Un archivo o directorio fue modificado. Esto ocurre cuando se escribe en el archivo o directorio.
attrib
Los atributos de un archivo o directorio fueron modificados. Esto incluye cambios en los permisos, tiempos de acceso/modificación, o número de enlaces.
close_write
Un archivo o directorio abierto para escribir fue cerrado. Este evento es disparado solo si se escribieron datos en el archivo mientras estaba abierto.
close_nowrite
Un archivo o directorio fue cerrado sin escribir datos en él. Esto ocurre si el archivo fue abierto para leer y luego cerrado, o si fue abierto para escribir pero no se escribieron datos.
close
Un archivo o directorio fue cerrado. Este evento es un alias para close_write y close_nowrite. Si se escucha para este evento, recibirá ambos eventos de cierre.
open
Un archivo o directorio observado fue abierto.
moved_to
Un archivo o directorio fue movido a un directorio observado. Este evento ocurre incluso si el archivo simplemente se mueve dentro y fuera del mismo directorio.
moved_from
Un archivo o directorio fue movido desde un directorio observado. Este evento ocurre incluso si el archivo simplemente se mueve dentro y fuera del mismo directorio.
move
Un archivo o directorio fue movido desde o hacia un directorio observado. Tenga en cuenta que esto se implementa simplemente escuchando tanto moved_to como moved_from, por lo tanto, todos los eventos de cierre recibidos se emitirán como uno o ambos de estos, no como MOVE.
move_self
Un archivo o directorio observado fue movido. Después de este evento, el archivo o directorio ya no se está observando.
create
Se creó un archivo o directorio dentro de un directorio observado.
delete
Se eliminó un archivo o directorio dentro de un directorio observado.
delete_self
Se eliminó un archivo o directorio observado. Después de este evento, el archivo o directorio ya no se está observando. Tenga en cuenta que este evento puede ocurrir incluso si no se está escuchando explícitamente para él.
unmount
El sistema de archivos en el que reside un archivo o directorio observado fue desmontado. Después de este evento, el archivo o directorio ya no se está observando. Tenga en cuenta que este evento puede ocurrir incluso si no se está escuchando explícitamente para él.

CAVEATS

Al usar inotifywatch, no se garantiza que el nombre de archivo que se muestra esté actualizado después de una operación de mover, ya que es el inodo el que se monitorea. Además, no se garantiza que ninguna de las operaciones observadas se haya realizado en el nombre de archivo que inotifywatch recibió instrucciones de monitorear en casos donde el archivo es conocido por varios nombres en el sistema de archivos.

BUGS

Existen condiciones de carrera en el código de monitoreo recursivo de directorios que pueden causar que se pierdan eventos si ocurren en un directorio inmediatamente después de la creación de dicho directorio. Esto probablemente no es solucionable.

Se asume que la cola de eventos de inotify nunca se desbordará.
