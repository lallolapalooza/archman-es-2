Para sistemas de archivos ext3 y ext4 que utilizan un diario, si el sistema se ha apagado de forma insegura sin ningún error, normalmente, después de reproducir las transacciones confirmadas en el diario, el sistema de archivos debería marcarse como limpio. Por lo tanto, para sistemas de archivos que utilizan diario, e2fsck normalmente reproducirá el diario y saldrá, a menos que su superbloque indique que se requiere una comprobación adicional. device es un dispositivo de bloque (por

Si e2fsck pregunta si debe comprobar un sistema de archivos que está montado, la única respuesta correcta es ``no''. INFORME DE

ERRORES

Casi cualquier software tendrá errores. Si logra encontrar un sistema de archivos que hace que e2fsck se bloquee, o que e2fsck no puede reparar, por favor repórtelo al

autor.

Por favor incluya tanta información como sea posible en su informe de error. Idealmente, incluya una transcripción completa de la ejecución de e2fsck, para que pueda ver exactamente qué mensajes de error se muestran. (Asegúrese de que los mensajes impresos por e2fsck estén en inglés; si su sistema ha sido configurado de modo que los mensajes de e2fsck se hayan traducido a otro idioma, por favor establezca la variable de entorno LC_ALL en C para que la transcripción de la salida de e2fsck me sea útil.) Si tiene un sistema de archivos grabable donde se pueda almacenar la transcripción, el programa script(1) es una forma conveniente de guardar la salida de e2fsck en un

archivo.

También es útil enviar la salida de dumpe2fs(8). Si un inodo o inodos específicos parecen causar problemas a e2fsck, intente ejecutar el comando debugfs(8) y envíe la salida del comando stat(1u) ejecutado en el/los inodo(s) relevante(s). Si el inodo es un directorio, el comando debugfs dump le permitirá extraer el contenido del inodo del directorio, que puede enviarme después de ser primero procesado por uuencode(1). Los datos más útiles que puede enviar para ayudar a reproducir el error son una imagen cruda comprimida del sistema de archivos, generada usando e2image(8). Vea la página del manual e2image(8) para más

detalles.

Siempre incluya la cadena de versión completa que e2fsck muestra cuando se ejecuta,

para que sepa qué v
ersión está usando.
