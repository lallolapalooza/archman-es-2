FTOK(3P) Manual del Programador POSIX FTOK(3P)

PRÓLOGO

Esta página manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página manual de Linux correspondiente para detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

ftok — generar una clave IPC

SINOPSIS

#include <sys/ipc.h>
key_t ftok(const char *path, int id);

DESCRIPCIÓN

La función ftok() devolverá una clave basada en path y id que es utilizable en llamadas posteriores a msgget(), semget(), y shmget(). La aplicación deberá asegurarse de que el argumento path sea la ruta de acceso de un archivo existente que el proceso sea capaz de stat(), con la excepción de que si stat() fallara con [EOVERFLOW] debido al tamaño del archivo, ftok() aún tendrá éxito.

La función ftok() devolverá el mismo valor de clave para todas las rutas que nombren el mismo archivo, cuando se llame con el mismo valor id , y debería devolver valores de clave diferentes cuando se llame con valores id diferentes o con rutas que nombren archivos diferentes que existan en el mismo sistema de archivos al mismo tiempo. No está especificado si ftok() devolverá el mismo valor de clave cuando se vuelva a llamar después de que el archivo nombrado por path sea eliminado y recreado con el mismo nombre.

Solo los 8 bits menos significativos de id son significativos. El comportamiento de ftok() no está especificado si estos bits son 0.

VALOR DE RETORNO

Tras la finalización exitosa, ftok() devolverá una clave. De lo contrario, ftok() devolverá (key_t)-1 y establecerá errno para indicar el error.

ERRORES

La función ftok() fallará si:

EACCES
Se deniega el permiso de búsqueda para un componente del prefijo de la ruta.
EIO
Ocurrió un error mientras se leía del sistema de archivos.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path
ENAMETOOLONG

La longitud de un componente de una ruta de acceso es mayor que {NAME_MAX}.
ENOENT
Un componente de path no nombra un archivo existente o path es una cadena vacía.
ENOTDIR
Un componente del prefijo de la ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o el argumento path contiene al menos un carácter que no es <barra invertida> y termina con uno o más caracteres de <barra invertida> finales y el último componente de la ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.

La función ftok() puede fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path .
ENAMETOOLONG

La longitud de una ruta de acceso excede {PATH_MAX}, o la resolución de la ruta de acceso de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.

Las siguientes secciones son informativas.

EJEMPLOS

Obtener una clave IPC

El siguiente ejemplo obtiene una clave basada en la ruta de acceso /tmp y el valor de ID a. También asigna el valor de la clave resultante a la variable semkey para que esté disponible para una llamada posterior a semget(), msgget(), o shmget().

#include <sys/ipc.h>
...
key_t semkey;
if ((semkey = ftok("/tmp", 'a')) == (key_t) -1) {
    perror("IPC error: ftok"); exit(1);
}

USO EN APLICACIONES

Para una portabilidad máxima, id debería ser un carácter de un solo byte.

Las aplicaciones no deberían asumir que el valor de clave resultante sea único.

JUSTIFICACIÓN

Ninguna.

DIRECCIONES FUTURAS

Las versiones futuras de este estándar podrían añadir nuevas interfaces para proporcionar claves únicas.

VÉASE TAMBIÉN

msgget(), semget(), shmget()
