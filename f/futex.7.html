NOMBRE

futex - bloqueos rápidos en el espacio de usuario

SINOPSIS

#include <linux/futex.h>

DESCRIPCIÓN

El kernel de Linux proporciona futexes ("Fast user-space mutexes" o mutexes rápidos en el espacio de usuario) como un bloque de construcción para mutexes y semáforos rápidos en el espacio de usuario. Los futexes son muy básicos y se prestan bien para construir abstracciones de bloqueo de nivel superior como mutexes, variables de condición, bloqueos de lectura-escritura, barreras y semáforos.

La mayoría de los programadores, de hecho, no usarán futexes directamente, sino que dependerán de bibliotecas del sistema construidas sobre ellos, como la Native POSIX Thread Library (NPTL) (ver pthreads(7)).

Un futex se identifica por una parte de memoria que puede ser compartida entre procesos o hilos. En estos diferentes procesos, el futex no necesita tener direcciones idénticas. En su forma desnuda, un futex tiene semántica de semáforo; es un contador que se puede incrementar y decrementar atmicamente; los procesos pueden esperar a que el valor se vuelva positivo.

La operación de futex ocurre completamente en el espacio de usuario para el caso no disputado. El kernel solo se involucra para arbitrar el caso disputado. Como cualquier diseño sensato se esforzará por la no contención, los futexes también están optimizados para esta situación.

En su forma desnuda, un futex es un entero alineado que solo se toca con instrucciones de ensamblador atómicas. Este entero tiene cuatro bytes de longitud en todas las plataformas. Los procesos pueden compartir este entero usando mmap(2), a través de segmentos de memoria compartida, o porque comparten espacio de memoria, en cuyo caso la aplicación se llama comúnmente multihilo.

Semántica

Cualquier operación de futex comienza en el espacio de usuario, pero puede ser necesario comunicarse con el kernel usando la llamada al sistema futex(2).

Para "subir" un futex, ejecute las instrucciones de ensamblador adecuadas que harán que la CPU host incremente atómicamente el entero. Después, verifique si efectivamente ha cambiado de 0 a 1, en cuyo caso no hubo ningún esperador y la operación está completa. Este es el caso no disputado que es rápido y debería ser común.

En el caso disputado, el incremento atómico cambió el contador de -1 (o algún otro número negativo). Si esto se detecta, hay esperadores. El espacio de usuario ahora debería establecer el contador a 1 e instruir al kernel para que despierte a cualquier esperador usando la operación FUTEX_WAKE.

Esperar en un futex, para "bajarlo", es la operación inversa. Decrementa atómicamente el contador y verifica si cambió a 0, en cuyo caso la operación está completa y el futex no tuvo contención. En todas las demás circunstancias, el proceso debería establecer el contador a -1 y solicitar que el kernel espere a que otro proceso suba el futex. Esto se hace usando la operación FUTEX_WAIT.

A la llamada al sistema futex(2) se le puede pasar opcionalmente un tiempo de espera que especifica cuánto tiempo debe esperar el kernel a que se suba el futex. En este caso, la semántica es más compleja y el programador es referido a futex(2) para más detalles. Lo mismo aplica para la espera asíncrona de futex.

VERSIÓNES

El soporte inicial de futex se fusionó en Linux 2.5.7 pero con una semántica diferente a la descrita anteriormente. La semántica actual está disponible a partir de Linux 2.5.40 en adelante.

NOTAS

Para reiterar, los futexes desnudos no están destinados a ser una abstracción fácil de usar para los usuarios finales. Se espera que los implementadores dominen el ensamblador y hayan leído las fuentes de la biblioteca de espacio de usuario de futex a la que se hace referencia a continuación.

Esta página del manual ilustra el uso más común de los primitivos de futex(2); no es de ninguna manera el único.
