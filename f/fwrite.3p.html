FWRITE(3P) Manual del Programador POSIX FWRITE(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux) o la interfaz puede no estar implementada en Linux.

NOMBRE

fwrite — salida binaria

SINOPSIS

#include <stdio.h>
size_t fwrite(const void *restrict ptr, size_t size, size_t nitems,
    FILE *restrict stream);

DESCRIPCIÓN

La funcionalidad descrita en esta página de referencia se alinea con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es involuntario. Este volumen de POSIX.1‐2017 remite al estándar ISO C.

La función fwrite() escribirá, desde el array apuntado por ptr, hasta nitems elementos cuyo tamaño se especifica por size, en el flujo apuntado por stream. Para cada objeto, se realizarán size llamadas a la función fputc(), tomando los valores (en orden) de un array de unsigned char que se superpone exactamente al objeto. El indicador de posición de archivo (si está definido) para el flujo se avanzará por el número de bytes escritos con éxito. Si ocurre un error, el valor resultante del indicador de posición de archivo para el flujo no está especificado.

Las marcas de tiempo de la última modificación de datos y del último cambio de estado del archivo se marcarán para actualizarse entre la ejecución exitosa de fwrite() y la siguiente finalización exitosa de una llamada a fflush() o fclose() en el mismo flujo, o una llamada a exit() o abort().

VALOR DE RETORNO

La función fwrite() devolverá el número de elementos escritos con éxito, que puede ser menor que nitems si se encuentra un error de escritura. Si size o nitems es 0, fwrite() devolverá 0 y el estado del flujo no cambiará. De lo contrario, si ocurre un error de escritura, se establecerá el indicador de error del flujo y se establecerá errno para indicar el error.

ERRORES

Consulte fputc().

USO DE LA APLICACIÓN

Debido a las posibles diferencias en la longitud de los elementos y el orden de los bytes, los archivos escritos con fwrite() dependen de la aplicación y, posiblemente, no puedan ser leídos con fread() por una aplicación diferente o por la misma aplicación en un procesador diferente.
