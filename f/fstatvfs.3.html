DESCRIPCIÓ

N

La función statvfs() devuelve información sobre un sistema de archivos montado. path es la ruta de nombre de cualquier archivo dentro del sistema de archivos montado. buf es un puntero a una estructura statvfs definida aproximadamente como

sigue: 


struct statvfs {
    unsigned long  f_bsize;    /* Tamaño de bloque del sistema de archivos */
    unsigned long  f_frsize;   /* Tamaño de fragmento */
    fsblkcnt_t     f_blocks;   /* Tamaño del fs en unidades de f_frsize */
    fsblkcnt_t     f_bfree;    /* Número de bloques libres */
    fsblkcnt_t     f_bavail;   /* Número de bloques libres para
                                  usuarios sin privilegios */
    fsfilcnt_t     f_files;    /* Número de inodos */
    fsfilcnt_t     f_ffree;    /* Número de inodos libres */
    fsfilcnt_t     f_favail;   /* Número de inodos libres para
                                  usuarios sin privilegios */
    unsigned long  f_fsid;     /* ID del sistema de archivos */
    unsigned long  f_flag;     /* Banderas de montaje */
    unsigned long  f_namemax;  /* Longitud máxima del nombre de archivo */
}
;

Aquí los tipos fsblkcnt_t y fsfilcnt_t se definen en <sys/types.h>. Ambos solían ser unsigned

long.

El campo f_flag es una máscara de bits que indica varias opciones que se emplearon al montar este sistema de archivos. Contiene cero o más de las siguientes

banderas:
ST_MANDLO
CK
Se permite el bloqueo obligatorio en el sistema de archivos (véase fcntl(2
)).
ST_NOATI
ME
No actualizar los tiempos de acceso; véase mount(
2).
ST_NOD
EV
No permitir el acceso a archivos especiales de dispositivo en este sistema de
archivos.
ST_NODIRATI
ME
No actualizar los tiempos de acceso de directorios; véase mount(
2).
ST_NOEX
EC
No se permite la ejecución de programas en este sistema de
archivos.
ST_NOSU
ID
Los bits set-user-ID y set-group-ID son ignorados por exec(3) para archivos ejecutables en este sistema de
archivos
ST_RDON

Este sistema de archivos está montado solo de

ST_RELATI

ST_SYNCHRONO

No se especifica si todos los miembros de la estructura devuelta tienen valores significativos en todos los sistemas de

archivos.

NOTA

S

El kernel de Linux tiene las llamadas al sistema statfs(2) y fstatfs(2) para soportar esta llamada a la

biblioteca.

Las implementaciones en glibc

de 


pathconf(path, _PC_REC_XFER_ALIGN);
pathconf(path, _PC_ALLOC_SIZE_MIN);
pathconf(path, _PC_REC_MIN_XFER_SIZE)
;

respectivamente usan los campos f_frsize, f_frsize, y f_bsize devueltos por una llamada a statvfs() con el argumento path

.

Bajo Linux, f_favail es siempre el mismo que f_ffree, y no hay forma de que un sistema de archivos reporte lo contrario. Esto no

es un problema, ya que no existen sistema

Antes de glibc 2.13, statvfs() poblaba los bits del campo f_flag escaneando las opciones de montaje mostradas en /proc/mounts. Sin embargo, a partir de Linux 2.6.36, la llamada al sistema statfs(2) subyacente proporciona la información necesaria a través del campo f_flags, y desde glibc 2.13, la función statvfs() usará la información de ese campo en lugar de escanear /proc/mount
