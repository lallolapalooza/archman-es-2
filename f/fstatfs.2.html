VERSIONES

El campo f_fsid

\n

Solaris, Irix y POSIX tienen una llamada al sistema statvfs(2) que\n devuelve una struct statvfs (definida en <sys/statvfs.h>)\n que contiene un unsigned long f_fsid. Linux, SunOS, HP-UX, y 4.4BSD\n tienen una llamada al sistema statfs() que devuelve una struct\n statfs (definida en <sys/vfs.h>) que contiene una fsid_t\n f_fsid, donde fsid_t se define como struct { int val[2];\n }. Lo mismo ocurre con FreeBSD, excepto que utiliza el archivo de\n inclusión <sys/mount.h>.

\n

La idea general es que f_fsid contiene alguna información\n aleatoria tal que el par (f_fsid,ino) determina de forma\n única un archivo. Algunos sistemas operativos utilizan (una variación de)\n el número de dispositivo, o el número de dispositivo combinado con el tipo de\n sistema de archivos. Varios sistemas operativos restringen la entrega del\n campo f_fsid solo al superusuario (y lo ponen a cero para usuarios\n no privilegiados), ya que este campo se utiliza en el filehandle del sistema\n de archivos cuando se exporta por NFS, y su entrega es una preocupación de\n seguridad.

\n

En algunos sistemas operativos, el fsid puede utilizarse\n como segundo argumento para la llamada al sistema sysfs(2).

HISTORIA

\n

La llamada statfs() de Linux se inspiró en la de 4.4BSD (pero no\n utilizan la misma estructura).

\n

Las llamadas al sistema originales statfs() y fstatfs()\n de Linux no fueron diseñadas teniendo en cuenta tamaños de archivo extremadamente\n grandes. Posteriormente, Linux 2.6 añadió nuevas llamadas al sistema statfs64()\n y fstatfs64() que utilizan una nueva estructura, statfs64.\n La nueva estructura contiene los mismos campos que la estructura original\n statfs, pero los tamaños de varios campos se incrementan para\n acomodar tamaños de archivo grandes. Las funciones de envoltura statfs()\n y fstatfs() de glibc manejan de forma transparente las diferencias del\n kernel.

\n

LSB ha desaprobado las llamadas a la biblioteca statfs() y\n fstatfs() y nos dice que utilicemos statvfs(3) y\n fstatvfs(3) en su lugar.

\n
\n
\n

NOTAS

\n

El tipo __fsword_t utilizado para varios campos en la\n definición de la estructura statfs es un tipo interno de glibc, no\n previsto para uso público. Esto deja al programador en una especie de\n dilema al intentar copiar o comparar estos campos con variables locales en\n un programa. Usar unsigned int para tales variables es suficiente en\n la mayoría de los sistemas.

\n

Algunos sistemas solo tienen <sys/vfs.h>, otros\n sistemas también tienen <sys/statfs.h>, donde el primero\n incluye el segundo. Por lo tanto, parece que incluir el primero es la\n mejor opción.

\n
\n
\n

ERRORES

\n

Desde Linux 2.6.38 hasta Linux 3.1 inclusive, fstatfs()\n fallaba con el error ENOSYS para descriptores de archivo creados por\n pipe(2).
