fsopen(2) Manual de Llamadas al Sistema fsopen(2)

NOMBRE

fsopen - crear un nuevo contexto de sistema de archivos

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <sys/mount.h>
int fsopen(const char *fsname, unsigned int flags);

DESCRIPCIÓN

La fsopen() llamada al sistema es parte del conjunto de funcionalidades de montaje basadas en descriptores de archivo en Linux.

fsopen() crea un contexto de configuración de sistema de archivos en blanco dentro del kernel para el sistema de archivos nombrado por fsname y lo coloca en modo de creación. Luego se devuelve un nuevo descriptor de archivo asociado con el contexto de configuración del sistema de archivos. El proceso que llama debe tener la CAP_SYS_ADMIN capacidad para crear un nuevo contexto de configuración del sistema de archivos.

Un contexto de configuración del sistema de archivos es una representación dentro del kernel de una transacción pendiente, que contiene un conjunto de parámetros de configuración que se aplicarán al crear una nueva instancia de un sistema de archivos (o al modificar la configuración de una instancia existente de sistema de archivos, como al usar fspick(2)).

Después de obtener un contexto de configuración del sistema de archivos con fsopen(), el flujo de trabajo general para operar con el contexto se ve como el siguiente:

(1)
Pase el descriptor de archivo del contexto del sistema de archivos a fsconfig(2) para especificar cualquier parámetro deseado del sistema de archivos. Esto puede hacerse tantas veces como sea necesario.
(2)
Pase el mismo descriptor de archivo del contexto del sistema de archivos a fsconfig(2) con FSCONFIG_CMD_CREATE para crear una instancia del sistema de archivos configurado.
(3)
Pase el mismo descriptor de archivo del contexto del sistema de archivos a fsmount(2) para crear un nuevo objeto de montaje desprendido para la raíz de la instancia del sistema de archivos, que luego se adjunta a un nuevo descriptor de archivo. (Esto también coloca el descriptor de archivo del contexto del sistema de archivos en modo de reconfiguración, similar al modo producido por fspick(2).) Una vez que un objeto de montaje ha sido creado con fsmount(2), el descriptor de archivo del contexto del sistema de archivos se puede cerrar de forma segura.
(4)
Ahora que se ha creado un objeto de montaje, puede
•
usar el descriptor de archivo del objeto de montaje desprendido como un dirfd argumento para las llamadas al sistema "*at()"; y/o
•
adjuntar el objeto de montaje a un punto de montaje pasando el descriptor de archivo del objeto de montaje a move_mount(2). Esto también evitará que el objeto de montaje sea desmontado y destruido cuando se cierre el descriptor de archivo del objeto de montaje.
El descriptor de archivo del objeto de montaje permanecerá asociado con el objeto de montaje incluso después de realizar las operaciones anteriores, por lo que puede usar repetidamente el descriptor de archivo del objeto de montaje con move_mount(2) y/o las llamadas al sistema "*at()" tantas veces como sea necesario.

Un contexto de sistema de archivos se moverá entre diferentes modos a lo largo de su ciclo de vida (como la fase de creación cuando se crea con fsopen(), la fase de reconfiguración cuando se selecciona una instancia existente de sistema de archivos con fspick(2), y la fase intermedia de "esperando montaje" entre FSCONFIG_CMD_CREATE y fsmount(2)), lo cual tiene un impacto en qué operaciones están permitidas en el contexto del sistema de archivos.

El descriptor de archivo devuelto por fsopen() también actúa como un canal para que los controladores de sistemas de archivos proporcionen información de diagnóstico más completa de la que normalmente se proporciona a través de la interfaz estándar errno(3) para las llamadas al sistema. Si ocurre un error en cualquier momento durante el flujo de trabajo mencionado anteriormente, llamar a read(2) en el descriptor de archivo del contexto del sistema de archivos recuperará cualquier información auxiliar sobre los errores encontrados. (Vea la sección "Interfaz de recuperación de mensajes" para más detalles sobre el formato del mensaje.)

flags se puede usar para controlar aspectos de la creación del descriptor de archivo del contexto de configuración del sistema de archivos. Un valor para flags se construye realizando un OR bit a bit de cero o más de las siguientes constantes:

FSOPEN_CLOEXEC
Establecer el indicador close-on-exec (FD_CLOEXEC) en el nuevo descriptor de archivo. Vea la descripción del O_CLOEXEC indicador en open(2) para las razones por las que esto puede ser útil.

Una lista de los sistemas de archivos soportados por el kernel en ejecución (y por lo tanto una lista de valores válidos para fsname) se puede obtener desde /proc/filesystems. (Vea también proc_filesystems(5).)

Interfaz de recuperación de mensajes

Al realizar operaciones en un contexto de configuración del sistema de archivos, el controlador del sistema de archivos puede optar por proporcionar información auxiliar a el espacio de usuario en forma de cadenas de mensajes.

Los descriptores de archivo del contexto del sistema de archivos devueltos por fsopen() y fspick(2) pueden ser consultados para cadenas de mensajes en cualquier momento llamando a read(2) en el descriptor de archivo. Cada llamada a read(2) devolverá un solo mensaje, con un prefijo que indica su clase:

emensaje
Se registró un mensaje de error. Esto generalmente está asociado con un error devuelto por la correspondiente llamada al sistema que desencadenó este mensaje.
wmensaje
Se registró un mensaje de advertencia.
imensaje
Se registró un mensaje informativo.

Los mensajes se eliminan de la cola a medida que se leen. Tenga en cuenta que la cola de mensajes tiene una profundidad limitada, por lo que es posible que los mensajes se pierdan. Si no hay mensajes en la cola de mensajes, read(2) devolverá -1 y errno se establecerá en ENODATA. Si el buf argumento de read(2) no es lo suficientemente grande para contener el mensaje completo, read(2) devolverá -1 y errno se establecerá en EMSGSIZE. (Vea ERRORES.)

Si hay múltiples contextos de sistema de archivos que referencian la misma instancia de sistema de archivos (como si llama a fspick(2) múltiples veces para el mismo montaje), cada uno recibe su propia cola de mensajes independiente. Esto no se aplica a múltiples descriptores de archivo que están vinculados a la misma descripción de archivo abierta subyacente (como aquellos creados con dup(2)).

Las cadenas de mensajes generalmente tendrán como prefijo el nombre del sistema de archivos o subsistema del kernel que registró el mensaje, aunque esto puede no ser siempre el caso. Vea el código fuente del kernel de Linux para más detalles.

VALOR DE RETORNO

En caso de éxito, se devuelve un nuevo descriptor de archivo. En caso de error, se devuelve -1, y errno se establece para indicar el error.

ERRORES

EFAULT
fsname es NULL o un puntero a una ubicación fuera del espacio de direcciones accesible del proceso que llama.
EINVAL
flags tenía un indicador inválido establecido.
EMFILE
El proceso que llama tiene demasiados archivos abiertos para crear más.
ENFILE
El sistema tiene demasiados archivos abiertos para crear más.
ENODEV
El sistema de archivos nombrado por fsname no es soportado por el kernel.
ENOMEM
El kernel no pudo asignar suficiente memoria para completar la operación.
EPERM
El proceso que llama no tiene la capacidad CAP_SYS_ADMIN requerida.

ESTÁNDARES

Linux.

HISTORIA

Linux 5.2. glibc 2.36.

ERRORES

Interfaz de recuperación de mensajes y EMSGSIZE

Como se describe en la subsección "Interfaz de recuperación de mensajes" anterior, llamar a read(2) con un búfer demasiado pequeño para contener el siguiente mensaje pendiente en la cola de mensajes para el contexto de configuración del sistema de archivos causará que read(2) devuelva -1 y establezca errno(3) en EMSGSIZE.

Sin embargo, esta operación fallida aún consume el mensaje de la cola de mensajes. Esto descarta el mensaje silenciosamente de manera efectiva, ya que no se copian datos en el búfer de read(2)

. Los programas deben asegurarse de que sus búferes sean lo suficientemente grandes para contener cualquier cadena de mensajes razonable, para evitar perder silenciosamente información de diagnóstico valiosa.

EJEMPLOS

Para ilustrar el flujo de trabajo para crear un nuevo montaje, el siguiente es un ejemplo de cómo montar un sistema de archivos ext4(5) almacenado en /dev/sdb1 en /mnt.


int fsfd, mntfd;
fsfd = fsopen("ext4", FSOPEN_CLOEXEC);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "ro", NULL, 0);
fsconfig(fsfd, FSCONFIG_SET_PATH, "source", "/dev/sdb1", AT_FDCWD);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "noatime", NULL, 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "acl", NULL, 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "user_xattr", NULL, 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "iversion", NULL, 0)
fsconfig(fsfd, FSCONFIG_CMD_CREATE, NULL, NULL, 0);
mntfd = fsmount(fsfd, FSMOUNT_CLOEXEC, MOUNT_ATTR_RELATIME);
move_mount(mntfd, "", AT_FDCWD, "/mnt", MOVE_MOUNT_F_EMPTY_PATH);

Primero, se crea un contexto de configuración ext4 y se adjunta al descriptor de archivo fsfd. Luego, se proporciona una serie de parámetros (como la fuente del sistema de archivos) usando fsconfig(2), seguido de la creación de la instancia del sistema de archivos con FSCONFIG_CMD_CREATE. fsmount(2) se usa luego para crear un nuevo objeto de montaje adjunto al descriptor de archivo mntfd, que luego se adjunta al punto de montaje deseado usando move_mount(2).

El procedimiento anterior es funcionalmente equivalente a la siguiente operación de montaje usando mount(2):


mount("/dev/sdb1", "/mnt", "ext4", MS_RELATIME,
      "ro,noatime,acl,user_xattr,iversion");

Y aquí hay un ejemplo de crear un objeto de montaje de un recurso compartido de servidor NFS y establecer una etiqueta del módulo de seguridad Smack. Sin embargo, en lugar de adjuntarlo a un punto de montaje, el programa usa el objeto de montaje directamente para abrir un archivo del recurso compartido NFS.


int fsfd, mntfd, fd;
fsfd = fsopen("nfs", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "source", "example.com/pub", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "nfsvers", "3", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "rsize", "65536", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "wsize", "65536", 0);
fsconfig(fsfd, FSCONFIG_SET_STRING, "smackfsdef", "foolabel", 0);
fsconfig(fsfd, FSCONFIG_SET_FLAG, "rdma", NULL, 0);
fsconfig(fsfd, FSCONFIG_CMD_CREATE, NULL, NULL, 0);
mntfd = fsmount(fsfd, 0, MOUNT_ATTR_NODEV);
fd = openat(mntfd, "src/linux-5.2.tar.xz", O_RDONLY);

A diferencia del ejemplo anterior, esta operación no tiene un equivalente trivial con mount(2), ya que no era posible crear previamente un objeto de montaje que no esté adjunto a ningún punto de montaje.
