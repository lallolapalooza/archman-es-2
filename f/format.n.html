Paquete: tcl

Licencias: TCL

format(n) Comandos integrados de Tcl format(n)

NOMBRE

format - Formatea una cadena al estilo de sprintf

SINOPSIS

format cadenaFormato ?arg arg ...?

INTRODUCCIÓN

Este comando genera una cadena formateada de manera similar al procedimiento sprintf de ANSI C. cadenaFormato indica cómo formatear el resultado, utilizando especificadores de conversión % como en sprintf, y los argumentos adicionales, si los hay, proporcionan valores para ser sustituidos en el resultado. El valor de retorno de format es la cadena formateada.

DETALLES SOBRE EL FORMATO

El comando opera escaneando cadenaFormato de izquierda a derecha. Cada carácter de la cadena de formato se añade a la cadena de resultado a menos que sea un signo de porcentaje. Si el carácter es un %, no se copia al resultado. En su lugar, los caracteres que siguen al carácter % se tratan como un especificador de conversión. El especificador de conversión controla la conversión del siguiente arg sucesivo a un formato particular y el resultado se añade a la cadena de resultado en lugar del especificador de conversión. Si hay varios especificadores de conversión en la cadena de formato, cada uno controla la conversión de un arg adicional. El comando format debe recibir suficientes args para satisfacer las necesidades de todos los especificadores de conversión en cadenaFormato.

Cada especificador de conversión puede contener hasta seis partes diferentes: un especificador de posición XPG3, un conjunto de banderas, un ancho de campo mínimo, una precisión, un modificador de tamaño y un carácter de conversión. Cualquiera de estos campos puede omitirse excepto el carácter de conversión. Los campos que estén presentes deben aparecer en el orden indicado anteriormente. Los párrafos siguientes discuten cada uno de estos campos por turno.

ESPECIFICADOR POSICIONAL OPCIONAL

Si el % va seguido de un número decimal y un $, como en “%2$d”, entonces el valor a convertir no se toma del argumento secuencial siguiente. En su lugar, se toma del argumento indicado por el número, donde 1 corresponde al primer arg. Si el especificador de conversión requiere varios argumentos debido a caracteres * en el especificador, entonces se utilizan argumentos sucesivos, comenzando con el argumento dado por el número. Esto sigue las convenciones XPG3 para especificadores posicionales. Si hay algún especificador posicional en cadenaFormato, entonces todos los especificadores deben ser posicionales.

BANDERA OPCIONAL

La segunda parte de un especificador de conversión puede contener cualquiera de los siguientes caracteres de bandera, en cualquier orden:

-
Especifica que el argumento convertido debe estar justificado a la izquierda en su campo (los números normalmente están justificados a la derecha con espacios iniciales si son necesarios).
+
Especifica que un número siempre debe imprimirse con un signo, incluso si es positivo.
espacio
Especifica que se añadirá un espacio al principio del número si el primer carácter no es un signo.
0
Especifica que el número debe rellenarse a la izquierda con ceros en lugar de espacios.
#
Solicita una forma de salida alternativa. Para las conversiones o garantiza que el primer dígito es siempre 0. Para las conversiones x o X, se añadirán 0x o 0X (respectivamente) al principio del resultado, a menos que sea cero. Para las conversiones b, se añadirá 0b al principio del resultado, a menos que sea cero. Para todas las conversiones de punto flotante (e, E, f, g, y G) garantiza que el resultado siempre tenga un punto decimal. Para las conversiones g y G especifica que los ceros finales no deben eliminarse.

ANCHO DE CAMPO OPCIONAL

La tercera parte de un especificador de conversión es un número decimal que indica un ancho de campo mínimo para esta conversión. Se utiliza normalmente para alinear columnas en impresiones tabulares. Si el argumento convertido contiene menos caracteres que el ancho de campo mínimo, se rellenará para que tenga el mismo ancho que el mínimo. El relleno normalmente se realiza añadiendo espacios adicionales a la izquierda del argumento convertido, pero las banderas 0 y - pueden usarse para especificar relleno con ceros a la izquierda o con espacios a la derecha, respectivamente. Si el ancho de campo mínimo se especifica como * en lugar de un número, entonces el siguiente argumento al comando format determina el ancho de campo mínimo; debe ser un valor entero.

PRECISIÓN/LÍMITE OPCIONAL

La cuarta parte de un especificador de conversión es una precisión, que consiste en un punto seguido de un número. El número se utiliza de diferentes maneras para diferentes conversiones. Para las conversiones e, E, y f especifica el número de dígitos que aparecen a la derecha del punto decimal. Para las conversiones g y G especifica el número total de dígitos a aparecer, incluyendo los de ambos lados del punto decimal (sin embargo, los ceros finales después del punto decimal seguirán siendo omitidos a menos que se haya especificado la bandera #). Para las conversiones de enteros, especifica un número mínimo de dígitos a imprimir (se añadirán ceros iniciales si es necesario). Para las conversiones s especifica el número máximo de caracteres a imprimir; si la cadena es más larga que esto, los caracteres finales se truncarán. Si la precisión se especifica con * en lugar de un número, entonces el siguiente argumento al comando format determina la precisión; debe ser una cadena numérica.

MODIFICADOR DE TAMAÑO OPCIONAL

La quinta parte de un especificador de conversión es un modificador de tamaño, que debe ser ll, h o l. Si es ll especifica que un valor entero se toma sin truncamiento para la conversión a una subcadena formateada. Si es h especifica que un valor entero se trunca a un rango de 16 bits antes de la conversión. Esta opción rara vez es útil. Si es l especifica que el valor entero se trunca al mismo rango que el producido por la función wide() del comando expr (al menos un rango de 64 bits). Si no están presentes ni h ni l, el valor entero se trunca al mismo rango que el producido por la función int() del comando expr (al menos un rango de 32 bits, pero determinado por el valor del elemento wordSize del array tcl_platform).

TIPO DE CONVERSIÓN OBLIGATORIO

Lo último en un especificador de conversión es un carácter alfabético que determina qué tipo de conversión realizar. Los siguientes caracteres de conversión son compatibles actualmente:

d
Convierte un entero a una cadena decimal con signo.
u
Convierte un entero a una cadena decimal sin signo. La conversión no tiene sentido sin referencia a un rango de truncamiento, por lo que el modificador de tamaño ll no está permitido en combinación con el carácter de conversión u.
i
Convierte un entero a una cadena decimal con signo (equivalente a d).
o
Convierte un entero a una cadena octal sin signo.
x o X
Convierte un entero a una cadena hexadecimal sin signo, utilizando los dígitos “0123456789abcdef” para x y “0123456789ABCDEF” para X).
b
Convierte un entero a una cadena binaria sin signo, utilizando los dígitos 0 y 1.
c
Convierte un entero al carácter Unicode que representa.
s
Sin conversión; simplemente inserta la cadena.
f
Convierte un número a una cadena decimal con signo de la forma xx.yyy, donde
el número de y's está determinado por la precisión (por defecto: 6). Si la precisión es 0, no se emite el punto decimal.
e o E
Convierte el número a notación científica en la forma x.yyye±zz, donde el número de y's está determinado por la precisión (por defecto: 6). Si la precisión es 0, no se emite el punto decimal. Si se usa la forma E , se imprime E en lugar de e.
g o G
Si el exponente es menor que -4 o mayor o igual que la precisión, convierte el número como para %e o %E. De lo contrario, convierte como para %f. Los ceros finales y el punto decimal final se omiten.
%
Sin conversión: simplemente inserta %.

DIFERENCIAS RESPECTO A ANSI SPRINTF

El comportamiento del comando de formato es el mismo que el del procedimiento sprintf de ANSI C, excepto por las siguientes diferencias:

[1]
Tcl garantiza que trabajará con caracteres UNICODE.
[2]
%p y %n no son compatibles.
[3]
Para las conversiones %c , el argumento debe ser un valor entero, que luego se convertirá al valor de carácter correspondiente.
[4]
Los modificadores de tamaño se ignoran al dar formato a valores de punto flotante. El modificador ll no tiene sprintf equivalente. El especificador b no tiene sprintf equivalente.

EJEMPLOS

Convertir el valor numérico de un carácter UNICODE al propio carácter:

set value 120
set char [format %c $value]

Convertir la salida de time en segundos con una precisión de centésimas de segundo:

set us [lindex [time $someTclCode] 0]
puts [format "%.2f segundos para ejecutar" [expr {$us / 1e6}]]

Crear una especificación de color literal X11 empaquetada:

# Cada componente de color debe estar en el rango (0..255)
set color [format "#%02x%02x%02x" $r $g $b]

Usar códigos de formato XPG3 para permitir el reordenamiento de campos (una técnica que se usa a menudo en catálogos de mensajes localizados; ver msgcat) sin reordenar los valores de datos pasados a format:

set fmt1 "Hoy, se compraron %d acciones de %s a $%.2f cada una"
puts [format $fmt1 123 "Global BigCorp" 19.37]
set fmt2 "Compramos acciones de %2\$s ($%3$.2f x %1\$d) hoy"
puts [format $fmt2 123 "Global BigCorp" 19.37]

Imprimir una pequeña tabla de potencias de tres:

# Configurar los anchos de columna
set w1 5
set w2 10
# Hacer primero un encabezado bonito (con separador) para la tabla
set sep +-[string repeat - $w1]-+-[string repeat - $w2]-+
puts $sep
puts [format "| %-*s | %-*s |" $w1 "Índice" $w2 "Potencia"]
puts $sep
# Imprimir el contenido de la tabla
set p 1
for {set i 0} {$i<=20} {incr i} {
    puts [format "| %*d | %*ld |" $w1 $i $w2 $p]
    set p [expr {wide($p) * 3}]
}
# Terminar imprimiendo el separador de nuevo
puts $sep
