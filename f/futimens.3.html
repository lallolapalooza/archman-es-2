utimensat()

y

futimens() actualizan las marcas de tiempo de un archivo con precisión de nanosegundos. Esto contrasta con las históricas utime(2) y utimes(2), que solo permiten precisión de segundos y microsegundos, respectivamente, al establecer marcas de tiempo de archivos. Co

n

utimensat() el archivo se especifica a través de la ruta de acceso dada en path. Con futimens() el archivo cuyas marcas de tiempo se van a actualizar se especifica a través de un descriptor de archivo abierto, fd. Para ambas llamadas, las nuevas marcas de tiempo del archivo se

especifican en el arreglo

times: times[0] especifica el nuevo "tiempo de último acceso" ( atime);times[1] especifica el nuevo "tiempo de última modificación" ( mtime). Cada uno de los elementos detimes especifica un tiempo como el número de segundos y nanosegundos desde la Época, 1970-01-01 00:00:00 +0000 (UTC). Esta información se transmite en una timespec(3) estructura. Las marcas de tiempo actualizadas del archivo se establecen en el valor máximo admitido por el sistema de archivos que no sea mayor que el tiempo

especificado.

Si

el

campo tv_nsec de una de las estructuras timespec tiene el valor especial UTIME_NOW, entonces la marca de tiempo correspondiente del archivo se establece en la hora actual. Si el campo tv_nsec de una de las estructuras timespec tiene el valor especial UTIME_OMIT, entonces la marca de tiempo correspondiente del archivo se deja sin cambios. En ambos casos, el valor del campo tv_sec correspondiente se

ignora.

Si times es NULL, entonces ambas marcas de tiempo se establecen en la hora

actual.

El tiempo de cambio de estado (ctime) se establecerá en la hora actual, incluso si las otras marcas de tiempo no cambian

realmente.

Requisitos de

permisos

Para establecer ambas marcas de tiempo del archivo en la hora actual (es decir, times es NULL, o ambos campos tv_nsec especifican UTIME_NOW), cualquiera de las

siguientes:
•
el llamador debe tener acceso de escritura al
archivo;
•
el ID de usuario efectivo del llamador debe coincidir con el propietario del archivo;
o
•
el llamador debe
tener los privil

Para realizar cualquier cambio distinto de establecer ambas marcas de tiempo en la hora actual (es decir, times no es NULL, y ninguno de los campos tv_nsec es UTIME_NOW y ninguno de los campos tv_nsec es UTIME_OMIT), debe aplicarse la condición 2 o 3

anterior.

Si ambos campos tv_nsec se especifican como UTIME_OMIT, entonces no se realizan comprobaciones de propiedad o permisos del archivo, y las marcas d

e tiempo del archivo no se modifican, pero otras
condiciones de error pueden seguir detectándose.

Véase openat(2) para una explicación de por qué esto puede ser

útil.
