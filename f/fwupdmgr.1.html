NOMBRE

fwupdmgr - utilidad cliente del gestor de actualizaciones de firmware

SINOPSIS

fwupdmgr [CMD]

DESCRIPCIÓN

fwupdmgr es un cliente fwupd de línea de comandos destinado a ser utilizado interactivamente. La salida de la terminal entre versiones de fwupd no está garantizada que sea estable, pero si planea analizar los resultados, entonces añadir --json podría ser justo lo que necesita.

También existen herramientas gráficas para firmware disponibles para varios entornos de escritorio. Estas aplicaciones pueden ser más útiles para muchos usuarios en comparación con el uso de la línea de comandos.

•
GNOME Software: https://wiki.gnome.org/Apps/Software
•
GNOME Firmware: https://gitlab.gnome.org/World/gnome-firmware
•
KDE Discover: https://userbase.kde.org/Discover
•
Canonical Firmware Updater: https://github.com/canonical/firmware-updater
•
System76 Firmware Manager: https://github.com/pop-os/firmware-manager

En la mayoría de los sistemas, fwupd está configurado para descargar metadatos del Linux Vendor Firmware Service https://fwupd.org/ y más información sobre el LVFS está disponible aquí: https://lvfs.readthedocs.io/

La mayoría de los usuarios que simplemente quieren actualizar todos los dispositivos a las últimas versiones pueden hacer fwupdmgr refresh y luego fwupdmgr update. En este punto, el sistema pedirá confirmación, actualizará algunos dispositivos y puede reiniciarse para desplegar actualizaciones que requieren un reinicio.

OPCIONES

El comando fwupdmgr acepta varias opciones dependiendo de la acción. Las acciones se dividen en grupos de comportamiento aproximados de la siguiente manera:

Interacción Con Dispositivos Detectados

Las siguientes acciones se pueden utilizar para ver detalles sobre los dispositivos enumerados en el sistema:

get-devices: Muestra todos los dispositivos, con filtrado opcional aplicado usando --filter.

get-updates: Muestra todas las actualizaciones disponibles para un dispositivo específico.

get-releases: Muestra todas las versiones instalables (más antiguas, las mismas o más nuevas) para un dispositivo específico.

get-details: Ver detalles sobre un archivo .cab específico, incluso si el dispositivo de destino no se ha encontrado en este sistema.

search: Encuentra actualizaciones presentes en los metadatos, independientemente de si el dispositivo ha sido enumerado en el sistema. La búsqueda coincidirá con versiones de firmware por:

•
El GUID completo de un dispositivo, p. ej. eb68dbae-3aef-5077-92ae-9016d1f0c856
•
El ID AppStream de un dispositivo, p. ej. work.frame.Desktop.RyzenAIMax300.BIOS.firmware
•
El nombre (completo o subconjunto) de una actualización de firmware, p. ej. Desktop Ryzen AI MAX 300
•
El nombre (completo o subconjunto) de un proveedor de firmware, p. ej. Framework
•
El protocolo utilizado por el firmware, p. ej. org.uefi.capsule
•
Cualquier problema reportado como resuelto por la actualización, p. ej. CVE-2022-21894
•
Cualquier suma de verificación del gabinete incluida con la actualización, en formato SHA-1 o SHA-256, p. ej. b34950fc65dabc0cb50e4c5f081829e40bf92e13

Desplegando Firmware

Las siguientes acciones se pueden utilizar para instalar firmware en dispositivos:

update: Actualiza cada dispositivo a su vez a la versión más nueva disponible.

install: Instala cualquier versión disponible en un dispositivo específico.

reinstall: Reinstala la misma versión en un dispositivo específico si está disponible.

downgrade: Instala una versión más antigua en una versión específica si está disponible.

switch-branch: Cambia entre diferentes "ramas" de firmware para un dispositivo específico. Por ejemplo, puede haber una rama "con soporte de la comunidad" y una rama "del proveedor upstream no libre" para exactamente el mismo hardware, ambas disponibles en el LVFS.

local-install: Instala un archivo de firmware local. El comando regular install también recurrirá a esto si el primer argumento es un archivo local que existe.

activate: Establece la versión de firmware instalada como en ejecución, lo que puede significar que el dispositivo se vuelva fuera de línea o no responda durante unos momentos.

sync: Instala todas las versiones con una etiqueta BKC coincidente si se ha establecido una "Configuración Mejor Conocida" para la máquina local.

Firmware Aprobado y Bloqueado

Las siguientes acciones se pueden utilizar para bloquear o permitir que se instalen versiones específicas de firmware:

get-blocked-firmware: Obtiene la lista de firmware bloqueado como una lista de sumas de verificación.

block-firmware: Bloquea que un firmware específico sea instalado por install o update.

unblock-firmware: Desbloquea que un firmware específico sea instalado o actualizado.

Las siguientes acciones se pueden utilizar para controlar la lista de permitidos de firmwares específicos:

set-approved-firmware: Establece la lista de firmware aprobado. Una vez que la lista de permitidos se ha establecido en un valor no vacío, solo el firmware que coincida con estas sumas de verificación será instalable.

get-approved-firmware: Obtiene la lista de firmware aprobado, devolviendo una lista vacía si no hay una lista de permitidos en su lugar.

Las sumas de verificación utilizadas para permitir o no permitir son las sumas de verificación del archivo del gabinete en formato SHA-1 o SHA-256.

Emulación

La emulación de dispositivos permite grabar el comportamiento del dispositivo para que podamos reproducir las respuestas del dispositivo y probar la escritura de firmware sin tener ese hardware real conectado.

Las siguientes acciones se pueden utilizar al emular dispositivos:

emulation-tag: Añade dispositivos a observar para futuras emulaciones.

emulation-save: Guarda los datos de emulación del dispositivo capturados en un archivo JSON. Solo se devolverán datos de dispositivos que hayan sido etiquetados previamente para emulación.

emulation-load: Carga datos de emulación de dispositivos desde un archivo JSON.

emulation-untag: Elimina dispositivos a observar para futuras emulaciones.

Al etiquetar dispositivos, se puede usar el ID o el GUID del dispositivo para identificar el dispositivo.

Las siguientes acciones se pueden utilizar para ejecutar pruebas automatizadas de dispositivos:

device-emulate: Emula un dispositivo usando un manifiesto JSON, que operará solo en dispositivos emulados.

device-test: Prueba un dispositivo usando un manifiesto JSON que descarga y verifica archivos de gabinete y los despliega en dispositivos físicos reales.

Remotos

Las siguientes acciones se pueden utilizar para controlar los remotos (el almacén de metadatos de firmware en línea) configurados en el demonio:

refresh: Descarga los metadatos en línea más recientes de los remotos configurados y habilitados.

get-remotes: Obtiene la lista de remotos configurados, que pueden estar habilitados o no.

enable-remote: Habilita un remoto preconfigurado para que pueda ser refrescado y utilizado.

disable-remote: Deshabilita un remoto, pero no elimina ni elimina los metadatos almacenados.

modify-remote: Edita un remoto, por ejemplo activando propiedades como AutomaticReports.

clean-remote: Limpia un remoto, eliminando metadatos donde sea necesario.

Datos Históricos

Las siguientes acciones se pueden utilizar para subir, exportar o borrar datos históricos:

report-export: Exporta el historial de firmware como un archivo sin conexión para subirlo manualmente a un servicio como el LVFS.

report-history: Comparte el historial de firmware con el remoto propioer, típicamente usado para indicar la tasa de éxito para una actualización específica. En algunos casos, compartir el historial devolverá resultados a páginas web que describan el fallo con más detalle, algunas con soluciones temporales.

get-history: Muestra el historial de actualizaciones de firmware tal como lo almacena fwupd.

get-results: Muestra el resultado de la última actualización de firmware para un dispositivo específico.

clear-results: Borra los resultados de la última actualización si es posible.

report-devices: Sube la lista de dispositivos actualizables a un servidor remoto para que puedan presionar al proveedor para que dé soporte a los usuarios de Linux.

Seguridad de la plataforma

Las siguientes acciones se pueden usar para ver o solucionar problemas de seguridad de la plataforma:

security: Obtiene la lista de atributos de seguridad del host que se utilizan para evaluar el nivel de seguridad de la máquina.

security-fix: Soluciona un fallo específico del atributo de seguridad del host.

security-undo: Deshace la corrección del atributo de seguridad del host, lo que puede ser necesario si security-fix causó una regresión.

Las siguientes acciones se pueden usar para listar o establecer la configuración del firmware de la BIOS:

get-bios-settings: Recupera la configuración del firmware de la BIOS y los valores permitidos.

set-bios-setting: Establece una o más configuraciones del firmware de la BIOS.

verify-update: Actualiza las sumas de verificación almacenadas que son utilizadas por la acción verify.

Otros

Las siguientes acciones pueden ser para scripts no interactivos o para usar en CI:

check-reboot-needed: Comprueba si algún dispositivo está pendiente de reinicio para completar la actualización.

device-wait: Espera a que un dispositivo aparezca en la lista de dispositivos del demonio.

download: Descarga un archivo utilizando los mismos mecanismos que se utilizan para el firmware y los metadatos.

modify-config: Modifica un valor de configuración del demonio como IgnorePower. Consulte man fwupd.conf para ver la lista completa de variables.

reset-config: Restaura una sección de configuración del demonio a los valores predeterminados.

quit: Pide al demonio que se cierre después de haber terminado cualquier actualización de firmware en curso.

inhibit: Inhabilita el sistema para evitar actualizaciones manuales o automáticas accidentales.

uninhibit: Habilita el sistema para permitir actualizaciones.

unlock: Desbloquea el dispositivo para el acceso al firmware, lo que puede ser necesario para algunos dispositivos de plataforma.

get-plugins: Muestra todos los plugins registrados con el demonio.

hwids: Devuelve todos los IDs de hardware de la máquina. Estas GUIDs a veces se llaman CHIDs cuando se usa Microsoft Windows, y los valores devueltos por fwupd también deberían coincidir con los de ComputerHardwareIds.exe.

ESTADO DE SALIDA

Los comandos que se ejecutan correctamente devolverán “0”, con un fallo genérico como “1”.

También hay varios códigos de salida adicionales: Un código de retorno de “2” se utiliza para comandos que no tienen acciones pero se ejecutaron correctamente, y “3” se utiliza cuando no se encontró un recurso.
