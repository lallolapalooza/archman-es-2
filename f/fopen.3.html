DESCRIPCIÓ

N

La función fopen() abre el archivo cuyo nombre es la cadena apuntada por path y asocia un flujo con

él.

El argumento mode apunta a una cadena que comienza con una de las siguientes secuencias (posiblemente seguidas de caracteres adicionales, como se describe a continuación)

:
r
Abre un archivo de texto para lectura. El flujo se posiciona al comienzo del
archivo.
r
+
Abre para lectura y escritura. El flujo se posiciona al comienzo del
archivo.
w
Trunca el archivo a longitud cero o crea un archivo de texto para escritura. El flujo se posiciona al comienzo del
archivo.
w
+
Abre para lectura y escritura. El archivo se crea si no existe, de lo contrario se trunca. El flujo se posiciona al comienzo del
archivo.
a
Abre para anexar (escritura al final del archivo). El archivo se crea si no existe. El flujo se posiciona al final del
archivo.
a
+
Abre para lectura y anexado (escritura al final del archivo). El archivo se crea si no existe. La salida siempre se anexa al final del arch
ivo. POSIX no especifica cuál es la posición de lectura inicial al usar este modo. Para glibc, la posición inicial del archivo para l
ectura es al comienzo del archivo, pero para Android/BSD/MacOS, la posición inicial del archivo para lectura es al final del archivo.

La cadena mode también puede incluir la letra 'b' ya sea como último carácter o como un carácter entre los caracteres en cualquiera de las cadenas de dos caracteres descritas anteriormente. Esto es estrictamente para compatibilidad con ISO C y no tiene efecto; la 'b' se ignora en todos los sistemas conformes a POSIX, incluyendo Linux. (Otros sistemas pueden tratar los archivos de texto y los archivos binarios de manera diferente, y agregar la 'b' puede ser una buena idea si realiza E/S a un archivo binario y espera que su programa pueda ser portado a entornos no UNIX.

)

Ver NOTAS más abajo para detalles de las extensiones de glibc para mode

.

Cualquier archivo creado tendrá el modo S_IRUSR | S_IWUSR | S_IRGRP | S_IWGRP | S_IROTH | S_IWOTH (0666), como se modifica por el valor umask del proceso (ver umask(2))

.

Las lecturas y escrituras pueden intercalarse en flujos de lectura/escritura en cualquier orden. Tenga en cuenta que ANSI C requiere que una función de posicionamiento de archivo interceda entre la salida y la entrada, a menos que una operación de entrada encuentre el fin de archivo. (Si esta condición no se cumple, entonces una lectura puede devolver el resultado de escrituras que no sean la más reciente.) Por lo tanto, es una buena práctica (y de hecho a veces es necesario bajo Linux) poner una fseek(3) o fsetpos(3] operación entre las operaciones de escritura y lectura en un flujo de este tipo. Esta operación puede ser un aparente no-op (como en fseek(..., 0L, SEEK_CUR) llamado por su efecto secundario de sincronización)

.

Abrir un archivo en modo anexado (a como el primer carácter de mode) hace que todas las operaciones de escritura posteriores a este flujo ocurran al final del archivo, como si estuvieran precedidas por la

llamada: 


fseek(stream, 0, SEEK_END)

fdopen(

)

La función fdopen() asocia un flujo con el descriptor de archivo existente, fd. El modo del flujo (uno de los valores "r", "r+", "w", "w+", "a", "a+") debe ser compatible con el modo del descriptor de archivo. El indicador de posición del archivo del nuevo flujo se establece al que pertenece a fd, y los indicadores de error y fin de archivo se limpian. Los modos "w" o "w+" no causan la truncación del archivo. El descriptor de archivo no se duplica (dup), y se cerrará cuando se cierre el flujo creado por fdopen(). El resultado de aplicar fdopen() a un objeto de me

moria compartida
es indefinido.

freopen(

)

La función freopen() abre el archivo cuyo nombre es la cadena apuntada por path y asocia el flujo apuntado por stream con él. El flujo original (si existe) se cierra. El argumento mode se usa igual que en la función fopen()

.

Si path es un puntero nulo, freopen() cambia el modo del flujo al especificado en mode; es decir, freopen() reabre la ruta de acceso que está asociada con el flujo. La especificación para este comportamiento se agregó en el estándar C99, que

dice:
En este caso, el descriptor de archivo asociado con el flujo no necesita cerrarse si la llamada a freopen() tiene éxito. Es definido por la implementación qué cambios de modo están permitidos (si los hay), y bajo qué
circunstancias.

El uso principal de la función freopen() es cambiar el archivo asociado con un flujo de texto estándar (stderr, stdin, o std

c (desde glibc 2.
3.3)
No hacer que la operación de apertura, o las subsecuentes operaciones de lectura y escritura, sean puntos de cancelación de hilos. Esta bandera se ignora para fdopen
().

2.7)
Abrir el archivo con la bandera O_CLOEXEC. Véase open(2) para más información. Esta bandera se ignora para fdopen
().

2.3)
Intentar acceder al archivo usando mmap(2), en lugar de llamadas al sistema de E/S (read(2), write(2)). Actualmente, el uso de mmap(2) se intenta solo para un archivo abierto para
lectura.

Además de los caracteres anteriores, fopen() y freopen() soportan la siguiente sintaxis en mode

:

,ccs=caden

La cadena dada se toma como el nombre de un juego de caracteres codificado y el flujo se marca como orientado a anchos. Después, las funciones internas de conversión convierten la E/S de y hacia el juego de caracteres cadena. Si la sintaxis ,ccs=cadena no se especifica, entonces la orientación a anchos del flujo se determina por la primera operación de archivo.

Si esa operación es una operación de caracteres anchos,
el flujo se marca como orientado a anchos, y se cargan la
