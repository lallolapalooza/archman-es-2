stat(2) Manual de llamadas al sistema stat(2)

NOMBRE

stat, fstat, lstat, fstatat - obtener estado del archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);

DESCRIPCIÓN

Estas funciones devuelven información sobre un archivo, en el búfer apuntado por statbuf. No se requieren permisos en el archivo mismo, pero - en el caso de stat(), fstatat(), y lstat() - se requiere permiso de ejecución (búsqueda) en todos los directorios en path que conducen al archivo.

stat() y fstatat() recuperan información sobre el archivo apuntado por path; las diferencias para fstatat() se describen a continuación.

lstat() es idéntica a stat(), excepto que si path es un enlace simbólico, entonces devuelve información sobre el enlace mismo, no sobre el archivo al que se refiere el enlace.

fstat() es idéntica a stat(), excepto que el archivo sobre el cual se debe recuperar la información se especifica mediante el descriptor de archivo fd.

La estructura stat

Todas estas llamadas al sistema devuelven una estructura stat (ver stat(3type)).

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura stat pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si st_mode o st_uid son modificados por otro proceso llamando a chmod(2) o chown(2), stat() podría devolver el st_mode antiguo junto con el nuevo st_uid, o el st_uid antiguo junto con el nuevo st_mode.

fstatat()

La llamada al sistema fstatat() es una interfaz más general para acceder a la información del archivo que aún puede proporcionar exactamente el comportamiento de cada una de stat(), lstat(), y fstat().

Si path es relativo, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso llamante, como hacen stat() y lstat() para un nombre de ruta relativo).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso llamante (como stat() y lstat()).

Si path es absoluto, entonces se ignora dirfd.

flags puede ser 0, o incluir una o más de las siguientes banderas ORed:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si path es una cadena vacía (o NULL, desde Linux 6.11) opera sobre el archivo al que se refiere dirfd (que puede haber sido obtenido usando la bandera O_PATH de open(2)). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio, y el comportamiento de fstatat() es similar al de fstat(). Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; defina _GNU_SOURCE para obtener su definición.
AT_NO_AUTOMOUNT (desde Linux 2.6.38)
No montar automáticamente el componente terminal ("basename") de path. Desde Linux 3.1 esta bandera se ignora. Desde Linux 4.11 esta bandera está implícita.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo desreferencie: en su lugar, devuelva información sobre el enlace mismo, como lstat(). (Por defecto, fstatat() desreferencia los enlaces simbólicos, como stat().)

Ver openat(2) para una explicación de la necesidad de fstatat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se niega el permiso de búsqueda en uno de los directorios del prefijo de ruta de path. (Ver también path_resolution(7)).
EBADF
fd no es un descriptor de archivo abierto válido.
EBADF
(fstatat()) path es relativo pero dirfd no es ni AT_FDCWD ni un descriptor de archivo válido.
EFAULT
Dirección incorrecta.
EINVAL
(fstatat()) Bandera inválida especificada en flags.
ELOOP
Demasiados enlaces simbólicos encontrados al recorrer la ruta.
ENAMETOOLONG
path es demasiado larga.
ENOENT
Un componente de path no existe o es un enlace simbólico colgante.
ENOENT
path es una cadena vacía y AT_EMPTY_PATH no se especificó en flags.
ENOMEM
Memoria agotada (es decir, memoria del kernel).
ENOTDIR
Un componente del prefijo de ruta de path no es un directorio.
ENOTDIR
(fstatat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo distinto de un directorio.
EOVERFLOW
path o fd se refieren a un archivo cuyo tamaño, número de inodo o número de bloques no pueden ser representados en, respectivamente, los tipos off_t, ino_t o blkcnt_t. Este error puede ocurrir cuando, por ejemplo, una aplicación compilada en una plataforma de 32 bits sin -D_FILE_OFFSET_BITS=64 llama a stat() sobre un archivo cuyo tamaño excede los (1<<31)-1 bytes.

El uso de los campos st_blocks y st_blksize puede ser menos portable. (Fueron introducidos en BSD. La interpretación difiere entre sistemas, y posiblemente en un solo sistema cuando se involucran montajes NFS.)

C Diferencias entre la biblioteca de C y el núcleo

Con el tiempo, los aumentos en el tamaño de la estructura stat han llevado a tres versiones sucesivas de stat(): sys_stat() (ranura __NR_oldstat), sys_newstat() (ranura __NR_stat), y sys_stat64() (ranura __NR_stat64) en plataformas de 32 bits como i386. Las dos primeras versiones ya estaban presentes en Linux 1.0 (aunque con nombres diferentes); la última se añadió en Linux 2.4. Observaciones similares se aplican a fstat() y lstat().

Las versiones internas del núcleo de la estructura stat tratadas por las diferentes versiones son, respectivamente:

__old_kernel_stat
La estructura original, con campos bastante estrechos y sin relleno.
stat
Campo st_ino más grande y relleno añadido a varias partes de la estructura para permitir una futura expansión.
stat64
Campo st_ino aún más grande, campos st_uid y st_gid más grandes para acomodar la expansión de UIDs y GIDs a 32 bits en Linux-2.4, y varios otros campos ampliados y más relleno en la estructura. (Varios bytes de relleno fueron finalmente consumidos en Linux 2.6, con la llegada de IDs de dispositivo de 32 bits y componentes de nanosegundos para los campos de marca de tiempo.)

La función envolvente stat() de glibc oculta estos detalles de las aplicaciones, invocando la versión más reciente de la llamada al sistema proporcionada por el núcleo, y reempaquetando la información devuelta si es necesario para binarios antiguos.

En sistemas modernos de 64 bits, la vida es más simple: hay una sola llamada al sistema stat() y el núcleo trata con una stat estructura que contiene campos de un tamaño suficiente.

La llamada al sistema subyacente empleada por la función envolvente fstatat() de glibc se llama en realidad fstatat64() o, en algunas arquitecturas, newfstatat().

EJEMPLOS

El siguiente programa llama a lstat() y muestra campos seleccionados en la estructura stat devuelta.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID of containing device:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("File type:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("block device\n");            break;
    case S_IFCHR:  printf("character device\n");        break;
    case S_IFDIR:  printf("directory\n");               break;
    case S_IFIFO:  printf("FIFO/pipe\n");               break;
    case S_IFLNK:  printf("symlink\n");                 break;
    case S_IFREG:  printf("regular file\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("unknown?\n");                break;
    }
    printf("I-node number:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Mode:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Link count:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Ownership:                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Preferred I/O block size: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("File size:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Blocks allocated:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Last status change:       %s", ctime(&sb.st_ctime));
    printf("Last file access:         %s", ctime(&sb.st_atime));
    printf("Last file modification:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
