fts(3) Manual de funciones de la biblioteca fts(3)

NOMBRE

fts, fts_open, fts_read, fts_children, fts_set, fts_close - recorrer una jerarquía de archivos

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/types.h>
#include <sys/stat.h>
#include <fts.h>
FTS *fts_open(char *const *path_argv, int options,
              typeof(int (const FTSENT **, const FTSENT **))
                  *_Nullable compar);
FTSENT *fts_read(FTS *ftsp);
FTSENT *fts_children(FTS *ftsp, int instr);
int fts_set(FTS *ftsp, FTSENT *f, int instr);
int fts_close(FTS *ftsp);

DESCRIPCIÓN

Las funciones fts se proporcionan para recorrer jerarquías de archivos. Una visión general simple es que fts_open() devuelve un "manejador" (de tipo FTS *) que hace referencia a un "flujo" de jerarquía de archivos. Este manejador se proporciona luego a las otras funciones fts. La función fts_read() devuelve un puntero a una estructura que describe uno de los archivos en la jerarquía de archivos. La función fts_children() devuelve un puntero a una lista enlazada de estructuras, cada una de las cuales describe uno de los archivos contenidos en un directorio de la jerarquía.

En general, los directorios se visitan dos veces distinguibles; en preorden (antes de que se visiten sus descendientes) y en postorden (después de que se hayan visitado todos sus descendientes). Los archivos se visitan una vez. Es posible recorrer la jerarquía "lógicamente" (visitando los archivos a los que apuntan los enlaces simbólicos) o físicamente (visitando los enlaces simbólicos mismos), ordenar el recorrido de la jerarquía o podar y/o volver a visitar porciones de la jerarquía.

Se definen dos estructuras (y tipos asociados) en el archivo de inclusión <fts.h>. El primer tipo es FTS, la estructura que representa la jerarquía de archivos en sí. El segundo tipo es FTSENT, la estructura que representa un archivo en la jerarquía de archivos. Normalmente, se devuelve una estructura FTSENT por cada archivo en la jerarquía de archivos. En esta página del manual, "archivo" y "estructura FTSENT" son generalmente intercambiables.

La estructura FTSENT contiene campos que describen un archivo. La estructura contiene al menos los siguientes campos (hay campos adicionales que deben considerarse privados para la implementación):


typedef struct _ftsent {
    unsigned short  fts_info;     /* banderas para la estructura FTSENT */
    char           *fts_accpath;  /* ruta de acceso */
    char           *fts_path;     /* ruta raíz */
    short           fts_pathlen;  /* strlen(fts_path) +
                                     strlen(fts_name) */
    char           *fts_name;     /* nombre de archivo */
    short           fts_namelen;  /* strlen(fts_name) */
    short           fts_level;    /* profundidad (-1 a N) */
    int             fts_errno;    /* errno del archivo */
    long            fts_number;   /* valor numérico local */
    void           *fts_pointer;  /* valor de dirección local */
    struct _ftsent *fts_parent;   /* directorio padre */
    struct _ftsent *fts_link;     /* siguiente estructura de archivo */
    struct _ftsent *fts_cycle;    /* estructura de ciclo */
    struct stat    *fts_statp;    /* información de [l]stat(2) */
} FTSENT;

Estos campos se definen de la siguiente manera:

fts_info
Uno de los siguientes valores que describen la estructura FTSENT devuelta y el archivo que representa. Con la excepción de los directorios sin errores (FTS_D), todas estas entradas son terminales, es decir, no se volverán a visitar, ni se visitarán sus descendientes.
FTS_D
Un directorio que se está visitando en preorden.
FTS_DC
Un directorio que provoca un ciclo en el árbol. (El campo fts_cycle de la estructura FTSENT también se llenará).
FTS_DEFAULT
Cualquier estructura FTSENT que represente un tipo de archivo no descrito explícitamente por uno de los otros valores de fts_info.
FTS_DNR
Un directorio que no se puede leer. Es un retorno de error y el campo fts_errno se establecerá para indicar qué causó el error.
FTS_DOT
Un archivo llamado "." o ".." que no se especificó como nombre de archivo a fts_open() (ver FTS_SEEDOT).
FTS_DP
Un directorio que se está visitando en postorden. El contenido de la estructura FTSENT no cambiará desde cuando se devolvió en preorden, es decir, con el campo fts_info establecido en FTS_D.
FTS_ERR
Es un retorno de error y el campo fts_errno se establecerá para indicar qué causó el error.
FTS_F
Un archivo regular.
FTS_NS
Un archivo para el cual no había información [l]stat(2) disponible. El contenido del campo fts_statp no está definido. Es un retorno de error y el campo fts_errno se establecerá para indicar qué causó el error.
FTS_NSOK
Un archivo para el cual no se solicitó información [l]stat(2). El contenido del campo fts_statp no está definido.
FTS_SL
Un enlace simbólico.
FTS_SLNONE
Un enlace simbólico con un destino inexistente. El contenido del campo fts_statp hace referencia a la información de características del archivo para el propio enlace simbólico.
fts_accpath
Una ruta para acceder al archivo desde el directorio actual.
fts_path
La ruta del archivo relativa a la raíz de la traversal. Esta ruta contiene la ruta especificada a fts_open() como prefijo.
fts_pathlen
La suma de las longitudes de las cadenas a las que hacen referencia fts_path y fts_name.
fts_name
El nombre del archivo.
fts_namelen
La longitud de la cadena a la que hace referencia fts_name.
fts_level
La profundidad de la traversal, numerada de -1 a N, donde se encontró este archivo. La estructura FTSENT que representa el padre del punto de inicio (o raíz) de la traversal está numerada -1, y la estructura FTSENT para la raíz en sí está numerada 0.
fts_errno
Si fts_children() o fts_read() devuelven una estructura FTSENT cuyo campo fts_info está establecido en FTS_DNR, FTS_ERR o FTS_NS, el campo fts_errno contiene el número de error (es decir, el valor de errno) que especifica el error. De lo contrario, el contenido del campo fts_errno no está definido.
fts_number
Este campo se proporciona para el uso del programa de aplicación y no es modificado por las funciones fts. Se inicializa a 0.
fts_pointer
Este campo se proporciona para el uso del programa de aplicación y no es modificado por las funciones fts. Se inicializa a NULL.
fts_parent
Un puntero a la estructura FTSENT que hace referencia al archivo en la jerarquía inmediatamente anterior al archivo actual, es decir, el directorio del cual este archivo es miembro. También se proporciona una estructura padre para el punto de entrada inicial, sin embargo, solo los campos fts_level, fts_number y fts_pointer están garantizados para estar
inicializado.
fts_li
nk
Al regresar de la función fts_children(), el campo fts_link apunta a la siguiente estructura en la lista enlazada terminada por NULL de miembros del directorio. De lo contrario, el contenido del campo fts_link es
indefinido.
fts_cyc
le
Si un directorio causa un ciclo en la jerarquía (véase FTS_DC), ya sea debido a un enlace duro entre dos directorios, o a un enlace simbólico que apunta a un directorio, el campo fts_cycle de la estructura apuntará a la estructura FTSENT en la jerarquía que hace referencia al mismo archivo que la estructura FTSENT actual. De lo contrario, el contenido del campo fts_cycle es
indefinido.
fts_sta
tp
Un puntero a la información del]stat(2) de
l archivo.

Se utiliza un único búfer para todas las rutas de todos los archivos en la jerarquía de archivos. Por lo tanto, los campos fts_path y fts_accpath están garantizados de estar terminados por nulo solo para el archivo devuelto más recientemente por fts_read(). Para usar estos campos para referenciar cualquier archivo representado por otras estructuras FTSENT se requerirá que el búfer de ruta sea modificado usando la información contenida en el campo fts_pathlen de esa estructura FTSENT. Cualquier modificación de este tipo debe deshacerse antes de intentar llamadas posteriores a fts_read(). El campo fts_name siempre está terminado por

nulo.

fts_open(

)

La función fts_open() toma un puntero a un array de punteros a caracteres que nombran uno o más caminos que componen una jerarquía lógica de archivos a recorrer. El array debe estar terminado por un puntero

nulo.

Hay una serie de opciones, al menos una de las cuales (ya sea FTS_LOGICAL o FTS_PHYSICAL) debe ser especificada. Las opciones se seleccionan haciendo OR de los siguientes

valores:
FTS_LOGIC
AL
Esta opción hace que las rutinas fts devuelvan estructuras FTSENT para los destinos de los enlaces simbólicos en lugar de los propios enlaces simbólicos. Si esta opción está activada, los únicos enlaces simbólicos para los que se devuelven estructuras FTSENT a la aplicación son aquellos que hacen referencia a archivos inexistentes: el campo fts_statp se obtiene mediante stat(2) con un recurso de respaldo a lstat(
2).
FTS_PHYSIC
AL
Esta opción hace que las rutinas fts devuelvan estructuras FTSENT para los propios enlaces simbólicos en lugar de los archivos de destino a los que apuntan. Si esta opción está activada, se devuelven estructuras FTSENT para todos los enlaces simbólicos en la jerarquía a la aplicación: el campo fts_statp se obtiene mediante lstat(
2).
FTS_COMFOLL
OW
Esta opción hace que cualquier enlace simbólico especificado como ruta raíz sea seguido inmediatamente, como si fuera mediante FTS_LOGICAL, independientemente del modo
principal.
FTS_NOCHD
IR
Como una optimización de rendimiento, las funciones fts cambian de directorio a medida que recorren la jerarquía de archivos. Esto tiene el efecto secundario de que una aplicación no puede confiar en estar en ningún directorio en particular durante el recorrido. Esta opción desactiva esta optimización, y las funciones fts no cambiarán el directorio actual. Tenga en cuenta que las aplicaciones no deben cambiar su directorio actual y tratar de acceder a archivos a menos que FTS_NOCHDIR sea especificado y se proporcionen rutas de acceso absolutas como argumentos a fts_ope
n().
FTS_NOST
AT
Por defecto, las estructuras FTSENT devueltas hacen referencia a la información de características del archivo (el campo fts_statp) de cada archivo visitado. Esta opción relaja ese requisito como una optimización de rendimiento, permitiendo a las funciones fts establecer el campo fts_info en FTS_NSOK y dejar el contenido del campo fts_statp
indefinido.
FTS_SEED
OT
Por defecto, a menos que se especifiquen como argumentos de ruta a fts_open(), cualquier archivo nombrado "." o ".." encontrado en la jerarquía de archivos es ignorado. Esta opción hace que las rutinas fts devuelvan estructuras FTSENT para
ellos.
FTS_XD
EV
Esta opción impide que fts descienda a directorios qu
e tengan un número de dispositivo diferente al
del archivo desde el cual comenzó el descenso.

El argumento compar() especifica una función definida por el usuario que puede usarse para ordenar el recorrido de la jerarquía. Toma dos punteros a punteros a estructuras FTSENT como argumentos y debe devolver un valor negativo, cero o positivo para indicar si el archivo referenciado por su primer argumento viene antes, en cualquier orden con respecto a, o después, del archivo referenciado por su segundo argumento. Los campos fts_accpath, fts_path y fts_pathlen de las estructuras FTSENT pueden nunca ser usados en esta comparación. Si el campo fts_info está establecido en FTS_NS o FTS_NSOK, el campo fts_statp tampoco puede ser usado. fts_read(

La función fts_read() devuelve un puntero a una estructura FTSENT que describe un archivo en la jerarquía. Los directorios (que son legibles y no causan ciclos) se visitan al menos dos veces, una en preorden y una en postorden. Todos los demás archivos se visitan al menos una vez. (Los enlaces duros entre directorios que no causan ciclos o los enlaces simbólicos a enlaces simbólicos pueden causar que los archivos se visiten más de una vez, o los directorios más de dos veces.

Si ocurre un error no relacionado con un archivo en la jerarquía, fts_read() devuelve NULL y establece errno para indicar el error. Si ocurre un error relacionado con un archivo devuelto, se devuelve un puntero a una estructura FTSENT, y errno puede o no haber sido establecido (véase fts_inf

fts_children(

)

La función fts_children() devuelve un puntero a una estructura FTSENT que describe la primera entrada en una lista enlazada terminada por NULL de los archivos en el directorio representado por la estructura FTSENT devuelta más recientemente por fts_read(). La lista está enlazada a través del campo fts_link de la estructura FTSENT, y está ordenada por la función de comparación especificada por el usuario, si existe. Llamadas repetidas a fts_children() re-crearán esta lista

enlazada.

Como caso especial, si fts_read() aún no ha sido llamado para una jerarquía, fts_children() devolverá un puntero a los archivos en el directorio lógico especificado a fts_open(), es decir, los argumentos especificados a fts_open(). De lo contrario, si la estructura FTSENT devuelta más recientemente por fts_read() no es un directorio siendo visitado en preorden, o el directorio no contiene ningún archivo, fts_children() devuelve NULL y establece errno a cero. Si ocurre un error, fts_children() devuelve NULL y establece errno para indicar el

error.

Las estructuras FTSENT devueltas por fts_children() pueden ser sobrescritas después de una llamada a fts_children(), fts_close() o fts_read() en el mismo flujo de jerarquía de

archivos.

fts_set(

La función fts_set() permite a la aplicación de usuario determinar el procesamiento posterior para el archivo f del flujo ftsp. La función fts_set() devuelve 0 en caso de éxito, y -1 si ocurre un
