NOMBRE

kernel_lockdown - función de prevención de acceso a la imagen del kernel

DESCRIPCIÓN

La función de Bloqueo del Kernel (Kernel Lockdown) está diseñada para prevenir el acceso directo e indirecto a una imagen de kernel en ejecución, intentando proteger contra la modificación no autorizada de la imagen del kernel y para prevenir el acceso a datos de seguridad y criptográficos ubicados en la memoria del kernel, al tiempo que permite la carga de módulos de controladores.

Si se accede o utiliza una característica prohibida o restringida, el kernel emitirá un mensaje que se parece a:


Lockdown: X: Y está restringido, consulte man kernel_lockdown.7

donde X indica el nombre del proceso y Y indica qué está restringido.

En una máquina x86 o arm64 con EFI habilitado, el bloqueo se habilitará automáticamente si el sistema arranca en modo EFI Secure Boot.

Cobertura

Cuando el bloqueo está en efecto, una serie de características se deshabilitan o se restringe su uso. Esto incluye archivos de dispositivo especiales y servicios del kernel que permiten el acceso directo a la imagen del kernel:

/dev/mem
/dev/kmem
/dev/kcore
/dev/ioports
BPF
kprobes

y la capacidad de configurar y controlar directamente los dispositivos, para evitar el uso de un dispositivo para acceder o modificar una imagen del kernel:

•
El uso de parámetros de módulo que especifican directamente parámetros de hardware a los controladores a través de la línea de comandos del kernel o al cargar un módulo.
•
El uso de acceso directo a PCI BAR.
•
El uso de las instrucciones ioperm e iopl en x86.
•
El uso de los ioctls de consola KD*IO.
•
El uso del ioctl serial TIOCSSERIAL.
•
La alteración de registros MSR en x86.
•
El reemplazo del CIS de PCMCIA.
•
La anulación de tablas ACPI.
•
El uso de inyección de errores ACPI.
•
La especificación de la dirección ACPI RDSP.
•
El uso de métodos personalizados ACPI.

Ciertas instalaciones están restringidas:

•
Solo se pueden cargar módulos firmados válidamente (exento si el archivo de módulo que se carga está avalado por la evaluación de IMA).
•
Solo se pueden ejecutar binarios firmados válidamente (exento si el archivo de imagen binaria a ejecutar está avalado por la evaluación de IMA).
•
Las hibernaciones/suspensiones a swap sin cifrar no están permitidas ya que la imagen del kernel se guarda en un medio al que luego se puede acceder.
•
No se permite el uso de debugfs ya que esto permite una amplia gama de acciones, incluida la configuración directa, el acceso y el control del hardware.
•
IMA requiere la adición de las reglas "secure_boot" a la política, ya sea que estén especificadas o no en la línea de comandos, tanto para las políticas integradas como para las personalizadas en modo de bloqueo seguro.

VERSIÓNES

La función Kernel Lockdown se agregó en Linux 5.4.

NOTAS

La función Kernel Lockdown está habilitada por CONFIG_SECURITY_LOCKDOWN_LSM. El parámetro de línea de comandos lsm=lsm1,...,lsmN controla la secuencia de inicialización de los Módulos de Seguridad de Linux. Debe contener la cadena lockdown para habilitar la función Kernel Lockdown. Si no se especifica el parámetro de línea de comandos, la inicialización recurre al valor del parámetro de línea de comandos obsoleto security= y, además, al valor de CONFIG_LSM.
