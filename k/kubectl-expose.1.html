NOMBRE

kubectl expose - Tomar un controlador de replicación, servicio, despliegue o pod y exponerlo como un nuevo servicio de Kubernetes

SINOPSIS

kubectl expose [OPCIONES]

DESCRIPCIÓN

Expone un recurso como un nuevo servicio de Kubernetes.

Busca un despliegue, servicio, conjunto de réplicas, controlador de replicación o pod por nombre y utiliza el selector de ese recurso como selector para un nuevo servicio en el puerto especificado. Un despliegue o conjunto de réplicas se expondrá como un servicio solo si su selector es convertible a un selector que el servicio soporte, es decir, cuando el selector contenga solo el componente matchLabels. Tenga en cuenta que si no se especifica ningún puerto a través de --port y el recurso expuesto tiene varios puertos, todos serán reutilizados por el nuevo servicio. Además, si no se especifican etiquetas, el nuevo servicio reutilizará las etiquetas del recurso que expone.

Los recursos posibles incluyen (sin distinción de mayúsculas y minúsculas):

pod (po), service (svc), replicationcontroller (rc), deployment (deploy), replicaset (rs)

OPCIONES

--allow-missing-template-keys=true Si es true, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida go-template y jsonpath.

--cluster-ip="" ClusterIP que se asignará al servicio. Dejar vacío para auto-asignar, o establecer a 'None' para crear un servicio sin encabezado.

--dry-run="none" Debe ser "none", "server" o "client". Si es estrategia de cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si es estrategia de servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--external-ip="" IP externa adicional (no gestionada por Kubernetes) para aceptar para el servicio. Si esta IP está enrutada a un nodo, el servicio se puede acceder con esta IP además de su IP de servicio generada.

--field-manager="kubectl-expose" Nombre del gestor utilizado para rastrear la propiedad de los campos.

-f, --filename=[] Nombre de archivo, directorio o URL a archivos que identifican el recurso para exponer un servicio

-k, --kustomize="" Procesa el directorio de kustomization. Esta bandera no se puede usar junto con -f o -R.

-l, --labels="" Etiquetas para aplicar al servicio creado por esta llamada.

--load-balancer-ip="" IP a asignar al Balanceador de Carga. Si está vacío, se creará y utilizará una IP efímera (específico del proveedor de la nube).

--name="" El nombre para el objeto recién creado.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--override-type="merge" El método utilizado para sobrescribir el objeto generado: json, merge o strategic.

--overrides="" Una sobrescritura JSON en línea para el objeto generado. Si esto no está vacío, se utiliza para sobrescribir el objeto generado. Requiere que el objeto proporcione un campo apiVersion válido.

--port="" El puerto en el que debe servir el servicio. Copiado del recurso que se expone, si no se especifica.

--protocol="" El protocolo de red para el servicio que se creará. El valor predeterminado es 'TCP'.

--record=false Registra el comando kubectl actual en la anotación del recurso. Si se establece en false, no registra el comando. Si se establece en true, registra el comando. Si no se establece, el valor predeterminado es actualizar el valor de anotación existente solo si ya existe uno.

-R, --recursive=false Procesa el directorio utilizado en -f, --filename recursivamente. Útil cuando desea gestionar manifiestos relacionados organizados dentro del mismo directorio.

--save-config=false Si es true, la configuración del objeto actual se guardará en su anotación. De lo contrario, la anotación no se modificará. Esta bandera es útil cuando desea realizar kubectl apply en este objeto en el futuro.

--selector="" Un selector de etiquetas para usar para este servicio. Solo se admiten los requisitos de selector basados en igualdad. Si está vacío (el valor predeterminado), infiere el selector del controlador de replicación o del conjunto de réplicas.

--session-affinity="" Si no está vacío, establezca la afinidad de sesión para el servicio en este; valores legales: 'None', 'ClientIP'

--show-managed-fields=false Si es true, mantenga los managedFields al imprimir objetos en formato JSON o YAML.

--target-port="" Nombre o número del puerto en el contenedor al que el servicio debe dirigir el tráfico. Opcional.

--template="" Cadena de plantilla o ruta a un archivo de plantilla a utilizar cuando -o=go-template, -o=go-template-file. El formato de plantilla es plantillas de golang [http://golang.org/pkg/text/template/#pkg-overview].

--type="" Tipo para este servicio: ClusterIP, NodePort, LoadBalancer o ExternalName. El valor predeterminado es 'ClusterIP'.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario regular o una cuenta de servicio en un espacio de nombres.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar varios grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad certificadora

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a utilizar

--context="" El nombre del contexto de kubeconfig a utilizar

--disable-compression=false Si es true, desactiva la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es true, el certificado del servidor no se verificará para determinar su validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes de CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para las preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funciones KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del espacio de nombres para esta solicitud de CLI

--password="" Contraseña para autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo a escribir el perfil.

--request-timeout="0" La duración antes de renunciar a una única solicitud de servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa que las solicitudes no caducan.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a usar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor.

--token="" Token de portador para la autenticación al servidor API

--user="" El nombre del usuario de kubeconfig a utilizar

--username="" Nombre de usuario para autenticación básica al servidor API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión reportada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero

NAME

kubectl-expose

create a Kubernetes Service for an existing workload

SYNOPSIS

kubectl expose (-f <filename> | TYPE NAME) [--port=port] [--target-port=target-port] [--interface=interface] [--node-port=node-port] [--create-external-load-balancer] [--external-ip-whitelist=<external-ip-whitelist>] [--type=type] [--name=name] [--protocol=protocol]

DESCRIPTION

Expose a service on a public port. Supports exposing services for Replication Controllers, Services, Deployments, ReplicaSets, and Pods.

The default supported protocol is TCP. If you want to use UDP you need to specify it explicitly.

If you want to expose your service as a nodeport, you can specify the --node-port flag.

If you want to expose your service as an external load balancer, you can specify the --create-external-load-balancer flag.

OPTIONS

--create-external-load-balancer

   create a external load balancer for the service

--f

   Filename, directory, or URL to files identifying the resource to expose.

--external-ip-whitelist

   List of external IPs authorized to access the service. Only set for type LoadBalancer and NodePort.

--name

   As above, "--name=NAME" is the label for the service.

--node-port

   port for the nodeport service, must be in the range 30000-32767.

--port

   The port that the service should serve on.

--protocol

   (default: "TCP")

--target-port

   (default: "--port") Port on the backend containers.

--type

   (default: "ClusterIP")
   ClusterIP: the service is only reachable inside the cluster, via the cluster IP.
   NodePort: the service is reachable on a static port on each selected Node in the cluster, without needing a load balancer.
   LoadBalancer: the service will be exposed using a cloud provider's load balancer.

OPTIONS INHERITED FROM PARENT COMMANDS

      --add-dir-header
      --alsologtostderr
      --as
      --as-group
      --cache-dir-ttl
      --certificate-authority
      --client-certificate
      --client-key
      --cluster

      --disable-compression

      --match-server-version
      --namespace
      --request-timeout
      --rotation-rate-limit

      --tls-server-name
      --token

EXAMPLE

  # Create a service for a replication controller identified by type and name specified in "nginx-controller.yaml", which serves on port 80 and connects to the containers on port 8000
  kubectl expose -f nginx-controller.yaml --port=80 --target-port=8000
  # Create a service for a pod valid-pod, which serves on port 444 with the name "frontend"
  kubectl expose pod valid-pod --port=444 --name=frontend
  # Create a second service based on the above service, exposing the container port 8443 as port 443 with the name "nginx-https"
  kubectl expose service nginx --port=443 --target-port=8443 --name=nginx-https
  # Create a service for a replicated streaming application on port 4100 balancing UDP traffic and named 'video-stream'.
  kubectl expose rc streamer --port=4100 --protocol=UDP --name=video-stream
  # Create a service for a replicated nginx using replica set, which serves on port 80 and connects to the containers on port 8000
  kubectl expose rs nginx --port=80 --target-port=8000
  # Create a service for an nginx deployment, which serves on port 80 and connects to the containers on port 8000
  kubectl expose deployment nginx --port=80 --target-port=8000
