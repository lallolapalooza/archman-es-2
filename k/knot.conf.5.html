NAME

knot.conf - Archivo de configuración de Knot DNS

DESCRIPCIÓN

Los archivos de configuración de Knot DNS utilizan un formato YAML simplificado. Simplificado significa que no todas las características son soportadas.

Para la descripción de los elementos de configuración, debemos declarar el significado de los siguientes símbolos:

  • INT – Entero
  • STR – Cadena de texto
  • HEXSTR – Cadena hexadecimal (con prefijo 0x)
  • BOOL – Valor booleano (on/off o true/false)
  • TIME – Número de segundos, un entero con un posible sufijo multiplicador de tiempo (s ~ 1, m ~ 60, h ~ 3600, d ~ 24 * 3600, w ~ 7 * 24 * 3600, M ~ 30 * 24 * 3600, y ~ 365 * 24 * 3600)
  • SIZE – Número de bytes, un entero con un posible sufijo multiplicador de tamaño (B ~ 1, K ~ 1024, M ~ 1024^2 o G ~ 1024^3)
  • BASE64 – Cadena codificada en Base64
  • ADDR – Dirección IPv4 o IPv6
  • DNAME – Nombre de dominio
  • ... – Elemento multivaluado, el orden de los valores se conserva
  • [ ] – Valor opcional
  • | – Elección

La configuración consta de varias secciones fijas y secciones de módulos opcionales. Hay 17 secciones fijas (module, server, xdp, control, log, statistics, database, keystore, key, remote, remotes, acl, submission, dnskey-sync, policy, template, zone). Las secciones de módulos tienen el prefijo mod- (por ejemplo, mod-stats).

La mayoría de las secciones (por ejemplo, zone) son secuencias de bloques de configuración. Cada bloque de configuración comienza con un identificador único, que puede usarse como referencia desde otras secciones (dicho identificador debe definirse con antelación).

Un elemento multivaluado puede especificarse como una secuencia de YAML:

address: [10.0.0.1, 10.0.0.2]

o como varios elementos de valor único, cada uno en una línea adicional:

address: 10.0.0.1
address: 10.0.0.2

Si el valor de un elemento contiene espacios u otros caracteres especiales, es necesario encerrar dicho valor entre comillas dobles " ".

Si no se especifica lo contrario, un elemento que representa una ruta de archivo o directorio puede definirse como una ruta absoluta (que comienza con /) o como una ruta relativa al mismo directorio que el valor predeterminado del elemento.

COMENTARIOS

Un comentario comienza con el carácter # y se ignora durante el procesamiento. Además, cada sección de configuración o bloque de secuencia permite un comentario permanente usando el elemento comment, que se almacena en el servidor junto con la configuración.

INCLUSIÓN DE CONFIGURACIÓN

Otro archivo o archivos de configuración, que coincidan con un patrón, pueden incluirse en el nivel superior del archivo actual.

include: STR

include

Una ruta o un patrón que especifica uno o más archivos que se incluyen en la posición de la opción de inclusión en la configuración. Si la ruta no es absoluta, se considera relativa al archivo actual. El patrón puede ser una cadena arbitraria que cumpla los requisitos de glob de POSIX, por ejemplo, dir/*.conf. Los archivos que coinciden se procesan en orden ordenado.

Predeterminado: no establecido

LIMPIEZA DE SECCIONES DE CONFIGURACIÓN

Es posible limpiar secciones de configuración especificadas en determinadas fases del análisis de la configuración.

clear: STR

clear

Un patrón que especifica las secciones de configuración que se limpian cuando se analiza este elemento. Esto permite anular la configuración existente en la base de datos de configuración al incluir un archivo de configuración o garantiza que alguna configuración no se especificó en inclusiones anteriores.

NOTA:

Para la coincidencia de patrones se utiliza la función POSIX fnmatch(). En Linux, se habilita la extensión GNU FNM_EXTMATCH, que permite la coincidencia de patrones extendida. Ejemplos:
  • clear: zone – Limpia la sección zone.
  • clear: mod-* – Limpia todas las secciones de módulos.
  • clear: "[!z]*" – Limpia todas las secciones que no comienzan con la letra z.
  • clear: !(zone) – (Solo GNU) Limpia todas las secciones excepto la de zone.
  • clear: @(zone|template) – (Solo GNU) Limpia las secciones zone y template.

Predeterminado: no establecido

Carga de módulos dinámicos de configuración.

module:
  - id: STR
    file: STR

id

Un identificador de módulo en forma del prefijo mod- y un sufijo con el nombre del módulo.

file

Una ruta a un archivo de biblioteca compartida con la implementación del módulo.

ADVERTENCIA:

Si la ruta no es absoluta, la biblioteca se busca en el conjunto de directorios del sistema. Consulte man dlopen para más detalles.

Cuando cambie los parámetros de configuración dinámicamente o mediante la recarga del archivo de configuración, algunos parámetros de la sección Server requerirán reiniciar el servidor Knot para que los cambios surtan efecto. Consulte a continuación para más detalles.

<

> Default: FQDN hostname

versión

Default: versión del servidor

nsid

Default: FQDN hostname en el momento del inicio del demonio

rundir

Una ruta para almacenar datos en tiempo de ejecución (archivo PID, sockets Unix, etc.). Una ruta no absoluta es relativa al directorio de inicio de knotd.

Dependiendo del uso de este parámetro, su cambio puede requerir un reinicio del servidor Knot para que tenga efecto.

Default: ${localstatedir}/run/knot (configurado con --with-rundir=path)

user

Un usuario del sistema con un grupo del sistema opcional (user:group) bajo el cual se ejecuta el servidor después de iniciarse y enlazarse a las interfaces. Se emplean capacidades de Linux si son compatibles.

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Default: root:root

pidfile

Una *ubicación* de archivo PID.

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Default: rundir/knot.pid

udp-workers

Un número de trabajadores UDP (hilos) utilizados para procesar consultas entrantes sobre UDP.

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Default: igual al número de CPUs en línea

tcp-workers

Un número de trabajadores TCP (hilos) utilizados para procesar consultas entrantes sobre TCP.

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Default: igual al número de CPUs en línea, el valor predeterminado es al menos 10

background-workers

Un número de trabajadores (hilos) utilizados para ejecutar operaciones en segundo plano (carga de zonas, actualizaciones de zonas, etc.).

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Default: igual al número de CPUs en línea, el valor predeterminado es como máximo 10

async-start

Si está habilitado, el servidor no espera a que se carguen las zonas y comienza a responder inmediatamente con respuestas SERVFAIL hasta que la zona se cargue.

Default: off

tcp-idle-timeout

Tiempo máximo de inactividad (en segundos) entre solicitudes en una conexión TCP entrante. Significa que si no hay actividad en una conexión TCP entrante durante este límite, la conexión es cerrada por el servidor.

Minimum: 1

Default: 10

tcp-io-timeout

Tiempo máximo (en milisegundos) para recibir o enviar un mensaje DNS sobre una conexión TCP entrante. Significa que este límite se aplica a consultas y respuestas DNS normales, DDNS entrantes y transferencias de zonas salientes. El tiempo de espera se mide desde que ya hay algunos datos disponibles para procesar. Establecer a 0 para infinito.

Default: 500 (milisegundos)

PRECAUCIÓN:

Para reducir el riesgo de ataques de Slow Loris, se recomienda establecer este límite lo más bajo posible en servidores públicos.

tcp-remote-io-timeout

Tiempo máximo (en milisegundos) para recibir o enviar un mensaje DNS sobre una conexión TCP saliente que ya se ha establecido a un servidor remoto configurado. Significa que este límite se aplica a transferencias de zonas entrantes, envío de NOTIFY, reenvío de DDNS y verificación o envío de DS. Este tiempo de espera incluye el tiempo necesario para un recorrido de red y para el procesamiento de una consulta por el remoto. Establecer a 0 para infinito.

Default: 5000 (milisegundos)

tcp-reuseport

Si está habilitado, cada trabajador TCP escucha en su propio socket y se emplea el balanceo de carga de sockets del kernel del SO utilizando SO_REUSEPORT (o SO_REUSEPORT_LB en FreeBSD). Debido a la falta de un socket compartido, el servidor puede ofrecer una mayor tasa de respuesta procesando sobre TCP. Sin embargo, en el caso de solicitudes que consumen mucho tiempo (por ejemplo, transferencias de zonas de una zona TLD), la reutilización de puertos habilitada puede resultar en solicitudes de clientes retrasadas o sin respuesta. Por lo tanto, se recomienda utilizar esta opción en servidores secundarios.

NOTA:

Esta opción se ignora para los sockets UNIX.

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Default: off

tcp-fastopen

Si está habilitado, utiliza TCP Fast Open para la comunicación TCP saliente (lado del cliente): transferencias de zonas entrantes, envío de NOTIFY y reenvío de DDNS. Este modo simplifica el handshake TCP y puede resultar en un mejor rendimiento de red. La comunicación TCP entrante (lado del servidor) no se ve afectada por esta configuración, ya que se habilita automáticamente si el SO lo admite.

NOTA:

El soporte de TCP Fast Open también debe estar habilitado a nivel del SO:
  • Linux/macOS: asegúrese de que el parámetro del kernel net.ipv4.tcp_fastopen sea 2 o 3 para el lado del servidor, y 1 o 3 para el lado del cliente.
  • FreeBSD: asegúrese de que el parámetro del kernel net.inet.tcp.fastopen.server_enable sea 1 para el lado del servidor, y net.inet.tcp.fastopen.client_enable sea 1 para el lado del cliente.

Default: off

quic-max-clients

Un número máximo de clientes QUIC conectados en paralelo.

Ver también quic.

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Minimum: 128

Default: 10000 (diez mil)

quic-outbuf-max-size

Tamaño máximo acumulativo de memoria utilizado para búferes de mensajes enviados sin ACK. Este límite es por trabajador UDP.

NOTA:

Establecer un valor bajo si hay poca memoria disponible (junto con quic-max-clients, ya que las conexiones QUIC consumen mucha memoria). Establecer un valor alto si se esperan transferencias de zonas salientes de zonas grandes sobre QUIC.

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Minimum: 1M (1 MiB)

Default: 100M (100 MiB)

quic-idle-close-timeout

Tiempo en segundos, después del cual cualquier conexión QUIC inactiva se cerrará elegantemente.

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Minimum: 1

Default: 4

remote-pool-limit

Si es distinto de cero, el servidor mantendrá abiertas hasta este número de conexiones TCP salientes para uso posterior. Esto es una optimización para evitar la apertura frecuente de conexiones TCP al mismo remoto.

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Default: 0

remote-pool-timeout

El tiempo de espera en segundos después del cual se cierran las conexiones TCP salientes inactivas mantenidas abiertas a servidores remotos.

Default: 5

remote-retry-delay

Cuando un intento de conexión falla a una dirección remota, esta información se mantendrá durante el tiempo especificado (en milisegundos) y no se intentarán otras conexiones a la misma dirección. Esto evita esperas repetitivas por tiempo de espera en un remoto inalcanzable.

Default: 0

socket-affinity

Si está habilitado y si SO_REUSEPORT está disponible en Linux, todos los sockets de red configurados se enlazan a los trabajadores UDP y TCP para aumentar el rendimiento de red. Este modo no se recomienda para configuraciones donde el número de colas de tarjetas de red es menor que el número de trabajadores UDP o TCP.

El cambio de este parámetro requiere un reinicio del servidor Knot para que tenga efecto.

Default: off

tcp-max-clients

Un número máximo de clientes TCP conectados en paralelo, establécelo por debajo del límite de descriptores de archivo para evitar el agotamiento de recursos.

NOTA:

Es aconsejable ajustar el número máximo de archivos abiertos por proceso en la configuración de su sistema operativo.

Default: la mitad del límite de descriptores de archivo para el proceso del servidor

udp-max-payload

Tamaño máximo de carga útil UDP EDNS0 predeterminado tanto para IPv4 como para IPv6.

Default: 1232

udp-max-payload-ipv4

Tamaño máximo de carga útil UDP EDNS0 para IPv4.

Default: 1232

udp-max-payload-ipv6

Tamaño máximo de carga útil UDP EDNS0 para IPv6.

Default: 1232

key-file

Ruta a un archivo PEM de clave del servidor que se utiliza para la comunicación DNS sobre QUIC/TLS. Una ruta no absoluta de un archivo de clave especificado por el usuario es relativa al directorio /etc/knot.

Default: clave autogenerada

cert-file

Ruta a un certificado de servidor

Path to the server's certificate PEM file which is used for DNS over QUIC/TLS communication. A non-absolute path is relative to the /etc/knot directory.

Default: one-time in-memory certificate

Default: off

Enable or disable sorted-rrset rotation in the answer section of normal replies. The rotation shift is simply determined by a query ID.

If enabled, automatic ACL setting of configured remotes is considered when evaluating authorized operations.

proxy-allowlist

NOTE:

TCP is not supported.

Default: not set

dbus-event

Specification of server or zone states which emit a D-Bus signal on the system bus. The bus name is cz.nic.knotd, the object path is /cz/nic/knotd, and the interface name is cz.nic.knotd.events.

Possible values:

  • none – No signal is emitted.
  • running – There are two possible signals emitted:
  • started when the server is started and all configured zones (including catalog zones and their members) are loaded or successfully bootstrapped.
  • stopped when the server shutdown sequence is initiated.
  • zone-updated – The signal zone_updated is emitted when a zone has been updated; the signal parameters are zone name and zone SOA serial.
  • keys-updated - The signal keys_updated is emitted when a DNSSEC key set is updated; the signal parameter is zone name.
  • ksk-submission – The signal zone_ksk_submission is emitted if there is a ready KSK present when the zone is signed; the signal parameters are zone name, KSK keytag, and KSK KASP id.
  • dnssec-invalid – The signal zone_dnssec_invalid is emitted when DNSSEC validation fails; the signal parameters are zone name, and remaining seconds until an RRSIG expires.

NOTE:

This function requires systemd version at least 221 or libdbus.

TIP:

A few sample script templates can be found in the project repository.

Change of this parameter requires restart of the Knot server to take effect.

Default: none

dbus-init-delay

Time in seconds which the server waits upon D-Bus initialization to ensure the D-Bus client is ready to receive signals.

Change of this parameter requires restart of the Knot server to take effect.

Minimum: 0

Default: 1

listen

One or more IP addresses where the server listens for incoming queries. Optional port specification (default is 53) can be appended to each address using @ separator. Use 0.0.0.0 for all configured IPv4 addresses or :: for all configured IPv6 addresses. Filesystem path can be specified for listening on local unix SOCK_STREAM socket. Non-absolute path (i.e. not starting with /) is relative to rundir. Non-local address binding is automatically enabled if supported by the operating system.

Change of this parameter requires restart of the Knot server to take effect.

Default: not set

listen-quic

One or more IP addresses (and optionally ports) where the server listens for incoming queries over QUIC protocol.

Change of this parameter requires restart of the Knot server to take effect.

Default: not set

listen-tls

One or more IP addresses (and optionally ports) where the server listens for incoming queries over TLS protocol (DoT).

Change of this parameter requires restart of the Knot server to take effect.

Default: not set

CAUTION:

When you change configuration parameters dynamically or via configuration file reload, some parameters in the XDP section require restarting the Knot server so that the changes take effect.

listen

One or more network device names (e.g. ens786f0) on which the Mode XDP is enabled. Alternatively, an IP address can be used instead of a device name, but the server will still listen on all addresses belonging to the same interface! Optional port specification (default is 53) can be appended to each device name or address using @ separator.

Change of this parameter requires restart of the Knot server to take effect.

CAUTION:

If XDP workers only process regular DNS traffic over UDP, it is strongly recommended to also listen on the addresses which are intended to offer the DNS service, at least to fulfil the DNS requirement for working TCP.

NOTE:

Incoming DDNS over XDP isn't supported. The server always responds with SERVFAIL.

Default: not set

udp

If enabled, DNS over UDP is processed with XDP workers.

Change of this parameter requires restart of the Knot server to take effect.

Default: on

tcp

If enabled, DNS over TCP traffic is processed with XDP workers.

The TCP stack limitations:

  • Congestion control is not implemented.
  • Lost packets that do not contain TCP payload may not be resend.
  • Not optimized for transfers of non-trivial zones.

Change of this parameter requires restart of the Knot server to take effect.

Default: off

quic

If enabled, DNS over QUIC is processed with XDP workers.

Change of this parameter requires restart of the Knot server to take effect.

Default: off

quic-port

DNS over QUIC will listen on the interfaces configured by listen, but on different port, configured by this option.

Change of this parameter requires restart of the Knot server to take effect.

Default: 853

tcp-max-clients

A maximum number of TCP clients connected in parallel.

Minimum: 1024

Default: 1000000 (one million)

tcp-inbuf-max-size

Maximum cumulative size of memory used for buffers of incompletely received messages.

Minimum: 1M (1 MiB)

Default: 100M (100 MiB)

tcp-outbuf-max-size

Maximum cumulative size of memory used for buffers of unACKed sent messages.

Minimum: 1M (1 MiB)

Default: 100M (100 MiB)

tcp-idle-close-timeout

Time in seconds, after which any idle connection is gracefully closed.

Minimum: 1

Default: 10

tcp-idle-reset-timeout

Time in seconds, after which any idle connection is forcibly closed.

Minimum: 1

Default: 20

tcp-resend-timeout

Resend outgoing data packets (with DNS response payload) if not ACKed before this timeout (in seconds).

Minimum: 1

Default: 5

route-check

If enabled, routing information from the operating system is considered when processing every incoming DNS packet received over the XDP interface:

  • Only packets destined for the server are processed.
  • Packets destined for other hosts are dropped.

This option helps to prevent the server from becoming a DNS open-relay.

Change of this parameter requires restart of the Knot server to take effect.

Default: on

ring-size

Size of the rings for communication between the kernel XDP program and the user-space worker.

Minimum: 1

Default: 4096

busypoll-budget

Maximum number of CPU cycles spent on busy-polling before returning from the receive function. A value of 0 means no busy-polling is performed.

Minimum: 0

Default: 0

busypoll-timeout

Timeout in microseconds to wait for a packet to arrive before returning from the receive function. A value of 0 means no timeout is set.

Minimum: 0

Default: 0

SECCIÓN ACL

Definiciones de reglas de lista de control de acceso. Una regla ACL es una descripción de una o más acciones autorizadas (solicitud de transferencia de zona, notificación de cambio de zona y actualización DNS dinámica) que se permiten procesar o denegar. Las consultas que no requieren autorización siempre se permiten.

acl:
  - id: STR
    address: ADDR[/INT] | ADDR-ADDR | STR ...
    key: key_id ...
    cert-key: BASE64 ...
    remote: remote_id | remotes_id ...
    action: query | notify | transfer | update ...
    protocol: udp | tcp | tls | quic ...
    deny: BOOL
    update-type: STR ...
    update-owner: key | zone | name
    update-owner-match: sub-or-equal | equal | sub | pattern
    update-owner-name: STR ...

id

Un identificador de regla ACL.

address

Una lista ordenada de direcciones IP, rutas absolutas de socket UNIX, subredes de red o rangos de red. La dirección de origen de la consulta debe coincidir con una de ellas. Si este elemento no está establecido, no se requiere coincidencia de dirección.

Predeterminado: no establecido

key

Una lista ordenada de referenciasa claves TSIG. La consulta debe coincidir con una de ellas. Si este elemento no está establecido, no se utiliza autenticación de transacción.

Predeterminado: no establecido

cert-key

Una lista ordenada de PINs de clave pública de certificado remoto. Si la lista no está vacía, la comunicación con el remoto solo es posible a través del protocolo QUIC y se requiere un certificado de par. La clave del certificado del par debe coincidir con uno de los PINs especificados.

Un PIN es un identificador único que representa la clave pública del certificado del par. Es un hash SHA-256 codificado en base64 de la clave pública. Este identificador permanece igual en la renovación de un certificado.

Predeterminado: no establecido

remote

Una lista ordenada de referencias remote y remotes. La consulta debe coincidir con uno de los remotos. Específicamente, una de las direcciones del remoto y la clave TSIG del remoto, si está configurada, deben coincidir.

Esta opción no puede especificarse junto con las opciones address, keyo protocol en un mismo elemento ACL.

action

Una lista ordenada de acciones permitidas o denegadas (tipos de solicitud).

Valores posibles:

  • query – Permite consultas DNS normales. Como las consultas normales siempre se permiten, esta acción solo es útil en combinación con una clave TSIG.
  • notify – Permite notificaciones entrantes (NOTIFY).
  • transfer – Permite transferencias de zona (AXFR, IXFR).
  • update – Permite actualizaciones de zona (DDNS).

Predeterminado: query

protocol

Lista de protocolos permitidos.

Valores posibles:

  • udp – Protocolo UDP.
  • tcp – Protocolo TCP.
  • tls – Protocolo TLS.
  • quic – Protocolo QUIC.

Predeterminado: no establecido (cualquiera)

Si está activado, en lugar de permitir, denegar la combinación coincidente de los elementos especificados.

Predeterminado: desactivado

Predeterminado: no establecido

update-owner

Esta opción restringe los posibles propietarios de Registros de Recursos en una actualización de zona comparándolos con la identidad de la clave TSIG , el nombre de zona actual, o una lista de nombres de dominio dada por la opción update-owner-name . Valores posibles:

  • key — El propietario de cada RR actualizado debe coincidir con la identidad de la clave TSIG si se utiliza.
  • name — El propietario de cada RR actualizado debe coincidir con al menos un nombre en la lista update-owner-name .
  • zone — El propietario de cada RR actualizado debe coincidir con el nombre de zona actual.

Predeterminado: no establecido

update-owner-match

Esta opción define cómo se comparan los propietarios de los Registros de Recursos en una actualización con el/los nombre(s) de dominio establecidos por la opción update-owner .

Valores posibles:

  • sub-or-equal — El propietario de cada RR en una actualización debe ser igual a o ser un subdominio de al menos un nombre de dominio establecido por update-owner.
  • equal — El propietario de cada RR actualizado debe ser igual a al menos un nombre de dominio establecido por update-owner.
  • sub — El propietario de cada RR actualizado debe ser un subdominio de, pero NO debe ser igual a al menos un nombre de dominio establecido por update-owner.
  • pattern — El propietario de cada RR actualizado debe coincidir con un patrón especificado por update-owner. El patrón puede ser un FQDN arbitrario o un nombre de dominio no-FQDN. dnssec-validation

Si está habilitado, el contenido de la zona se valida para asegurar que esté correctamente firmado (incluida la cadena NSEC/NSEC3) con firmas DNSSEC cada vez que la zona se carga o se modifica (incluyendo AXFR/IXFR).

Cuando la validación falla, la zona que se está cargando o la actualización que se está aplicando se cancela con un error, y se publica el estado anterior de la zona o ninguno.

Lista de comprobaciones DNSSEC:

  • Cada RRSet de zona está correctamente firmado por al menos un DNSKEY presente.
  • Por cada RRSIG hay como máximo 3 DNSKEYs no coincidentes con el mismo keytag.
  • El RRSet DNSKEY está firmado por KSK.
  • Existe un RR NSEC(3) para cada nombre (a menos que sea opt-out) con un mapa de bits correcto.
  • Cada RR NSEC(3) está enlazado al siguiente lexicográficamente.

La validación no se ve afectada por la configuración de dnssec-policy, excepto por la opción signing-threads, que especifica el número de hilos para la validación paralela, y rrsig-refresh, que define el intervalo mínimo permitido de validez restante de RRSIG (de lo contrario, se registra una advertencia).

serial-modulo

El valor de la opción es una cadena que consta de dos partes (sin separador entre ellas), cada una de las cuales es opcional.

La primera parte especifica que los seriales de zona deben ser congruentes módulo del valor especificado. El formato es R/M, donde R < M <= 256 son enteros positivos. Siempre que el serial de la zona se incrementa, se asegura que serial % M == R. Esto puede ser útil en el caso de múltiples primarios inconsistentes, donde secuencias de seriales de zona distintas impiden la IXFR inter-maestra por cualquier secundario.

NOTA:

Debido a que el serial de la zona efectivamente siempre se incrementa en M en lugar de 1, no se recomienda usar la política de serial dateserial o incluso unixtime en el caso de zonas actualizadas rápidamente.

La segunda parte especifica un desplazamiento numérico para el serial de zona generado. El desplazamiento se formatea como un entero con signo, incluido el signo (+ o -). Es útil principalmente con la política de serial unixtime, donde el serial de zona generado se desplaza en relación con la hora Unix.
