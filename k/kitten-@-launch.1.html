Nombre

kitten-@-launch - Ejecutar un proceso arbitrario en una ventana/pestaña nueva

Uso

kitten @ launch [CMD ...]

Descripción

Imprime el id de la ventana recién abierta. Se asume que cualquier argumento de línea de comandos es la línea de comandos utilizada para ejecutar en la nueva ventana; si no se proporcionan, se ejecuta el shell por defecto. Por ejemplo:


kitten @ launch --title=Email mutt

Opciones

--match, -m
La pestaña a coincidir. Las especificaciones de coincidencia son de la forma: campo:consulta. Donde campo puede ser uno de: id, index, title, window_id, window_title, pid, cwd, cmdline env, var, state, session y recent. consulta es la expresión a coincidir. Las expresiones pueden ser un número o una expresión regular, y se pueden combinar usando operadores booleanos.

El valor especial all coincide con todas las pestañas.

Para campos numéricos: id, index, window_id, pid y recent, la expresión se interpreta como un número, no como una expresión regular. Los valores negativos para id/window_id coinciden desde el número de id más alto hacia abajo, en particular, -1 es la pestaña/ventana creada más recientemente.

Al usar title o id, primero se busca una pestaña coincidente y, si no se encuentra, se busca una ventana coincidente y se utiliza la pestaña de esa ventana.

También puede usar window_id y window_title para coincidir con la pestaña que contiene la ventana con el id o título especificado.

El número de índice se utiliza para coincidir con la enésima pestaña en la ventana del sistema operativo activa actualmente. El número recent coincide con pestañas activas recientemente en la ventana del sistema operativo activa actualmente, siendo cero la pestaña activa actualmente, uno la pestaña activa anteriormente y así sucesivamente.

El campo session coincide con pestañas que se crearon en la sesión especificada. Use la expresión ^$ para coincidir con ventanas que no se crearon en una sesión y . para coincidir con la sesión activa actualmente y ~ para coincidir con la sesión activa actualmente o la última sesión activa cuando no hay ninguna sesión activa.

Al usar el campo env para coincidir con variables de entorno, puede especificar solo el nombre de la variable de entorno o un nombre y valor, por ejemplo, env:MY_ENV_VAR=2. Se coinciden las pestañas que contienen cualquier ventana con las variables de entorno especificadas. De manera similar, var coincide con pestañas que contienen cualquier ventana con las variables de usuario especificadas.

El campo state coincide con el estado de la pestaña. Los estados admitidos son: active, focused, needs_attention, parent_active, parent_focused y focused_os_window. Las pestañas activas son las pestañas que están activas en su ventana del sistema operativo padre. Solo hay una pestaña enfocada y es la pestaña a la que se entregan los eventos del teclado. Si ninguna pestaña está enfocada, se coincide con la última pestaña enfocada. El valor focused_os_window coincide con todas las pestañas en la ventana del sistema operativo actualmente enfocada.

Tenga en cuenta que puede usar el comando kitten @ ls para obtener una lista de pestañas.

--wait-for-child-to-exit [=no]
Espere hasta que el programa lanzado termine e imprima su código de salida. El código de salida se imprime en lugar del id de la ventana. Si el programa terminó normalmente, se imprime su código de salida, que siempre es mayor o igual a cero. Si el programa fue eliminado por una señal, se imprime el nombre simbólico de la SEÑAL, si está disponible; de lo contrario, se imprime el número de señal con un signo menos al principio.
--response-timeout [=86400]
El tiempo en segundos para esperar a que el proceso iniciado termine, cuando se utiliza la opción --wait-for-child-to-exit. Por defecto, un día.
--no-response [=no]
No imprima el id de la nueva ventana creada.
--self [=no]
Si se especifica, se utiliza la pestaña que contiene la ventana en la que se ejecuta este comando en lugar de la pestaña activa.
--source-window
Una expresión de coincidencia para seleccionar la ventana de la cual se copian datos como título, colores, variables de entorno, contenido de pantalla, etc. Cuando no se especifica, se utiliza la ventana activa actualmente. Consulte search_syntax para ver la sintaxis utilizada para especificar ventanas.
--title, --window-title
El título a establecer para la nueva ventana. Por defecto, el título es controlado por el proceso hijo. El valor especial current copiará el título de --source-window.
--tab-title
El título de la nueva pestaña si se lanza en una nueva pestaña. Por defecto, el título de la ventana activa en la pestaña se utiliza como título de la pestaña. El valor especial current copiará el título de la pestaña que contiene la --source-window.
--type [=window]
Dónde lanzar el proceso hijo:

window
Una nueva ventana de kitty en la pestaña actual

tab
Una nueva pestaña en la ventana del sistema operativo actual. No disponible cuando el comando launch <launch> se utiliza en sesiones de inicio.

os-window
Una nueva ventana del sistema operativo. No disponible cuando el comando launch <launch> se utiliza en sesiones de inicio.

overlay
Una ventana superpuesta que cubre la ventana de kitty activa actualmente

overlay-main
Una ventana superpuesta que cubre la ventana de kitty activa actualmente. A diferencia de una ventana superpuesta simple, esta ventana se considera una ventana principal, lo que significa que se utiliza como ventana activa para obtener el directorio de trabajo actual, el texto de entrada para los kittens, los comandos de lanzamiento, etc. Útil si esta superposición está destinada a ejecutarse durante mucho tiempo como ventana principal.

background
El proceso se ejecutará en segundo plano, sin una ventana de kitty. Tenga en cuenta que si se especifica --allow-remote-control, la variable de entorno KITTY_LISTEN_ON se establecerá en un descriptor de archivo de par de sockets dedicado que el proceso puede utilizar para control remoto.

clipboard, primary
Estos dos están diseñados para funcionar con --stdin-source para copiar datos al portapapeles del sistema o a la selección primaria.

os-panel
Similar a os-window, excepto que crea la nueva Ventana del Sistema Operativo como un panel de escritorio. Solo funciona en plataformas que lo admiten, como los compositores de Wayland que admiten el protocolo de shell de capa. Utilice la opción --os-panel para configurar el panel.

Opciones: window, background, clipboard, os-panel, os-window, overlay, overlay-main, primary, tab

--dont-take-focus, --keep-focus [=no]
Mantener el foco en la ventana activa actualmente en lugar de cambiar a la ventana recién abierta.
--cwd
El directorio de trabajo para el hijo recién lanzado. Use el valor especial current para usar el directorio de trabajo de la --source-window. El valor especial last_reported utiliza el último directorio de trabajo informado por el shell (necesita shell_integration para funcionar). El valor especial oldest funciona como current pero utiliza el directorio de trabajo del proceso en primer plano más antiguo asociado con la ventana activa actualmente en lugar del proceso en primer plano más nuevo. Finalmente, el valor especial root se refiere al proceso que se inició originalmente cuando se creó la ventana.

Cuando la apertura en el mismo directorio de trabajo que la ventana actual causa que la nueva ventana se conecte a un host remoto, puede usar el flag --hold-after-ssh para evitar que la nueva ventana se cierre cuando se termine la conexión.

--add-to-session
Agregue la ventana/pestaña recién creada a la sesión especificada. Use . para agregar a la sesión de la --source-window, si existe alguna. Consulte sessions para saber qué es una sesión y cómo usarla. Por defecto, la ventana se agrega a la sesión de la --source-window cuando --cwd se establece para usar el directorio de trabajo de esa ventana, de lo contrario, la ventana recién creada no pertenece a ninguna sesión. Para forzar una
añadiendo a ninguna sesión, use el valor !. Añadir una ventana recién creada a una sesión es puramente temporal, no cambia el archivo de sesión real, para eso debe volver a guardar la sesión. Tenga en cuenta que usar esta bandera en un comando de inicio dentro de un archivo de sesión no tiene efecto, ya que la ventana siempre se añade a la sesión perteneciente a ese archivo.
--env
Variables de entorno para establecer en el proceso hijo. Se puede especificar varias veces para establecer diferentes variables de entorno. Sintaxis: nombre=valor. Usar nombre= establecerá una cadena vacía y solo nombre eliminará la variable de entorno.
--var
Variables de usuario para establecer en la ventana creada. Se puede especificar varias veces para establecer diferentes variables de usuario. Sintaxis: nombre=valor. Usar nombre= establecerá una cadena vacía.
--hold [=no]
Mantener la ventana abierta incluso después de que el comando que se está ejecutando salga, en un prompt de shell. El shell se ejecutará después de que el comando lanzado salga.
--copy-colors [=no]
Establecer los colores de la ventana recién creada para que sean los mismos que los colores en la --source-window.
--copy-cmdline [=no]
Ignorar cualquier línea de comando especificada y en su lugar usar la línea de comando de la --source-window.
--copy-env [=no]
Copiar las variables de entorno de la --source-window al proceso hijo recién lanzado. Tenga en cuenta que esto solo copia el entorno cuando la ventana se creó por primera vez, ya que no es posible obtener variables de entorno actualizadas de procesos arbitrarios. Para copiar ese entorno, use la función clone-in-kitty o la función de control remoto de kitty con --copy-env.
--location [=default]
Dónde colocar la ventana recién creada cuando se añade a una pestaña que ya tiene ventanas existentes. after y before colocan la nueva ventana antes o después de la ventana activa. neighbor es un sinónimo de after. También se aplica a la creación de una nueva pestaña, donde el valor after hará que la nueva pestaña se coloque junto a la pestaña actual en lugar de al final. Los valores de vsplit, hsplit y split solo se usan con el diseño splits y controlan si la nueva ventana se coloca en una división vertical, horizontal o automática con la ventana actualmente activa. El valor predeterminado es colocar la ventana de una manera dependiente del diseño, típicamente, después de la ventana actualmente activa. Vea --next-to para usar una ventana que no sea la actualmente activa.

Opciones: default, after, before, first, hsplit, last, neighbor, split, vsplit

--next-to
Una expresión de búsqueda para seleccionar la ventana junto a la cual se crea la nueva ventana. Vea search_syntax para la sintaxis para especificar ventanas. Si no se especifica, por defecto es la ventana activa. Cuando se usa a través del control remoto y se especifica una pestaña de destino, esta opción se ignora a menos que la ventana coincidente esté en la pestaña especificada. Al usar --type de tab, la pestaña se creará en la ventana del SO que contiene la ventana coincidente.
--bias [=0]
El sesgo utilizado para alterar el tamaño de la ventana. Controla qué fracción del espacio disponible ocupa la ventana. El significado exacto del sesgo depende del diseño actual.

* Diseño splits: El sesgo se interpreta como un porcentaje entre 0 y 100. Al dividir una ventana en dos, la nueva ventana tomará la fracción especificada del espacio asignado a la ventana original y la ventana original tomará el resto del espacio.

* Diseño vertical/horizontal: El sesgo se interpreta como añadir/restar del tamaño normal de la ventana. Debe ser un número entre -90 y 90. Este número es el porcentaje del tamaño de la ventana del SO que debe añadirse al tamaño de la ventana. Así que por ejemplo, si una ventana normalmente tendría un tamaño de 50 en el diseño dentro de una ventana del SO que tiene una altura de 80 y se usa --bias -10, se convertirá en *aproximadamente* un tamaño de 42 de alto. Tenga en cuenta que los tamaños son aproximaciones, no puede usar este método para crear ventanas de tamaños fijos.

* Diseño tall: Si la ventana que se está creando es la *primera* ventana en una columna, entonces el sesgo se interpreta como un porcentaje, como en el diseño splits, dividiendo el ancho de la ventana del SO entre columnas. Si la ventana es la segunda o una ventana posterior en una columna, el sesgo se interpreta como añadir/restar del tamaño de la ventana como en el diseño vertical anterior.

* Diseño fat: Igual que el diseño tall excepto que va por filas en lugar de columnas.

* Diseño grid: El sesgo se interpreta de la misma manera que para los diseños Vertical y Horizontal, como algo que se añade/resta al tamaño normal. Sin embargo, dado que en un diseño grid hay filas *y* columnas, el sesgo en la primera ventana de una columna opera sobre las columnas. Cualquier ventana posterior en esa columna opera sobre la fila. Así, por ejemplo, si sesga la primera ventana en un diseño grid, cambiará el ancho de la primera columna, la segunda ventana, el ancho de la segunda columna, la tercera ventana, la altura de la segunda fila y así sucesivamente.

La opción bias se introdujo en la versión 0.36.0 de kitty.

--allow-remote-control [=no]
Los programas que se ejecutan en esta ventana pueden controlar kitty (incluso si el control remoto no está habilitado en kitty.conf). Tenga en cuenta que cualquier programa con el nivel correcto de permisos aún puede escribir en las tuberías de cualquier otro programa en la misma computadora y por lo tanto puede controlar kitty. Sin embargo, puede ser útil bloquear programas que se ejecutan en otras computadoras (por ejemplo, a través de SSH) o como otros usuarios. Vea --remote-control-password para formas de restringir las acciones permitidas por el control remoto.
--remote-control-password
Restringir las acciones que el control remoto está permitido realizar. Esto funciona como remote_control_password. Puede especificar una contraseña y una lista de acciones igual que para remote_control_password. Por ejemplo::


--remote-control-password '"mi frase de paso" get-* set-colors'

Esta contraseña estará en efecto solo para esta ventana. Tenga en cuenta que cualquier contraseña que haya definido para remote_control_password en kitty.conf también está en efecto. Puede anularlas usando la misma contraseña aquí. También puede deshabilitar todas las contraseñas globales de remote_control_password para esta ventana, usando::


--remote-control-password '!'

Esta opción solo tiene efecto si --allow-remote-control también se especifica. Se puede especificar varias veces para crear múltiples contraseñas. Esta opción se añadió a kitty en la versión 0.26.0

--stdin-source [=none]
Pasar el contenido de la pantalla como STDIN al proceso hijo.

@selection
es el texto actualmente seleccionado en la --source-window.

@screen
es el contenido de la --source-window.

@screen_scrollback
es lo mismo que @screen, pero incluye también el búfer de desplazamiento.

@alternate
es la pantalla secundaria de la --source-window. Por ejemplo, si ejecuta una aplicación de terminal a pantalla completa, la pantalla secundaria será la pantalla a la que regresa al salir de la aplicación.

@first_cmd_output_on_screen
es la salida del primer comando ejecutado en el shell en pantalla.

@last_cmd_output
es la salida del último comando ejecutado en el shell.

@last_visited_cmd_output
es la primera salida debajo de la última posición desplazada a través de scroll_to_prompt, esto necesita integración de shell para funcionar.

Opciones: none, @alternate, @alternate_scrollback, @first_cmd_output_on_screen, @last_cmd_output, @last_visited_cmd_output, @screen, @screen_scrollback, @selection

--stdin-add-formatting [=no]
Al usar --stdin-source añadir códigos de escape de formato, sin esto solo se enviará texto plano.
--stdin-add-line-wrap-markers [=no]
Al usar --stdin-source añadir un retorno de carro en cada ubicación de ajuste de línea (donde las líneas largas se ajustan en los bordes de la pantalla). Esto es útil si desea canalizar a un programa que quiere duplicar el diseño de la pantalla de la pantalla.
--marker
Crear un marcador que resalte texto en la ventana recién creada. La sintaxis es la misma que para la acción toggle_marker (vea /marks).
--os-window-class
Establecer la propiedad WM_CLASS en X11 y la propiedad de id de aplicación en Wayland para la ventana del SO recién creada al usar --type. Por defecto es lo que use el proceso kitty padre, que a su vez por defecto es kitty.
--os-window-name
Establecer la propiedad WM_NAME en X11 para la ventana del SO recién creada al usar --type. Por defecto es --os-window-class.
--os-window-title
Establecer el título para la ventana del SO recién creada. Este título anulará cualquier título establecido por programas que se ejecuten en kitty. El valor especial current copiará el título de la ventana del SO que contiene la --source-window.
--os-window-state [=normal]
El estado inicial para la ventana del SO recién creada.

Opciones: normal, fullscreen, maximized, minimized

--logo
Ruta a una imagen PNG para usar como el logotipo de la ventana recién creada. Vea window_logo_path. Las rutas relativas se resuelven desde el directorio de configuración de kitty.
--logo-position
La posición para el logotipo de la ventana. Solo tiene efecto si --log

Options

--window-logo [=no]
Display a logo in the window. You can specify the path to the logo image file with --logo-path. If no path is specified, the default logo is used. You can also specify the position of the logo with --logo-position. If the specified logo file is not found, this option is ignored. You can also specify the amount the logo is faded in with --logo-alpha.
--logo-path [=no]
Path to the logo image file. If not specified, the default logo is used. Only takes effect if --window-logo is specified. See window_logo_path.
--logo-position [=no]
The position of the window logo. Can be one of: top-left, top-right, bottom-left, bottom-right. If not specified, the default is top-right. Only takes effect if --window-logo is specified. See window_logo_position.
--logo-alpha [=-1]
The amount the window logo should be faded into the background. Only takes effect if --logo is specified. See window_logo_alpha.
--color
Change colors in the newly launched window. You can either specify a path to a .conf file with the same syntax as kitty.conf to read the colors from, or specify them individually, for example::


--color background=white --color foreground=red

--spacing
Set the margin and padding for the newly created window. For example: margin=20 or padding-left=10 or margin-h=30. The shorthand form sets all values, the *-h and *-v variants set horizontal and vertical values. Can be specified multiple times. Note that this is ignored for overlay windows as these use the settings from the base window.
--watcher, -w
Path to a Python file. Appropriately named functions in this file will be called for various events, such as when the window is resized, focused or closed. See the section on watchers in the launch command documentation: watchers. Relative paths are resolved relative to the kitty config directory. Global watchers for all windows can be specified with watcher in kitty.conf.
--os-panel
Options to control the creation of desktop panels. Takes the same settings as the panel kitten, except for --override and --config. Can be specified multiple times. For example, to create a desktop panel at the bottom of the screen two lines high::


launch --type os-panel --os-panel lines=2 --os-panel edge=bottom sh -c "echo; echo; echo hello; sleep 5s"

--hold-after-ssh [=no]
When using --cwd=current or similar from a window that is running the ssh kitten, the new window will run a local shell after disconnecting from the remote host, when this option is specified.
--help, -h [=no]
Show help for this command

Opciones globales

--to
Una dirección para la instancia de kitty que se controlará. Corresponde a la dirección dada a la instancia de kitty a través de la opción --listen-on o el ajuste listen_on en kitty.conf. Si no se especifica, se comprueba la variable de entorno KITTY_LISTEN_ON. Si tampoco se encuentra, los mensajes se envían a la terminal de control de este proceso, es decir, solo funcionarán si este proceso se ejecuta dentro de una ventana de kitty.
--password
Una contraseña para usar al contactar con kitty. Esto hará que kitty solicite al usuario permiso para realizar la acción especificada, a menos que la contraseña ya haya sido aceptada o esté preconfigurada en kitty.conf. Para usar una contraseña en blanco, especifique --use-password como siempre.
--password-file [=rc-pass]
Un archivo desde el cual leer la contraseña. Los espacios en blanco al final se ignoran. Las rutas relativas se resuelven desde el directorio de configuración de kitty. Usa - para leer desde STDIN. Usa fd:num para leer desde el descriptor de archivo num. Se usa si no se proporciona --password. Por defecto, busca el archivo rc-pass en el directorio de configuración de kitty.
--password-env [=KITTY_RC_PASSWORD]
El nombre de una variable de entorno desde la cual leer la contraseña. Se usa si no se proporciona --password-file. Por defecto, comprueba la variable de entorno KITTY_RC_PASSWORD.
--use-password [=if-available]
Si no hay ninguna contraseña disponible, kitty normalmente enviará el comando de control remoto sin contraseña. Esta opción se puede usar para forzar su uso siempre o nunca. Si se establece en always y no se proporciona ninguna contraseña, se utiliza la contraseña en blanco.

Opciones: if-available, always, never
