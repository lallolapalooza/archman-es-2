NOMBRE

kubeadm join phase control-plane-prepare all - Prepara la máquina para servir un plano de control

SINOPSIS

kubeadm join phase control-plane-prepare all [OPCIONES]

DESCRIPCIÓN

Prepara la máquina para servir un plano de control

OPCIONES

--apiserver-advertise-address="" Si el nodo debe alojar una nueva instancia del plano de control, la dirección IP que el API Server anunciará que está escuchando. Si no se establece, se utilizará la interfaz de red predeterminada.

--apiserver-bind-port=6443 Si el nodo debe alojar una nueva instancia del plano de control, el puerto al que se enlazará el API Server.

--certificate-key="" Usa esta clave para descifrar los secretos de certificado cargados por init. La clave de certificado es una cadena codificada en hexadecimal que es una clave AES de 32 bytes.

--config="" Ruta a un archivo de configuración de kubeadm.

--control-plane=false Crea una nueva instancia del plano de control en este nodo

--discovery-file="" Para el descubrimiento basado en archivos, un archivo o URL desde el cual cargar la información del clúster.

--discovery-token="" Para el descubrimiento basado en tokens, el token utilizado para validar la información del clúster obtenida del servidor API.

--discovery-token-ca-cert-hash=[] Para el descubrimiento basado en tokens, valida que la clave pública de la CA raíz coincida con este hash (formato: ":").

--discovery-token-unsafe-skip-ca-verification=false Para el descubrimiento basado en tokens, permite unirse sin el anclaje de --discovery-token-ca-cert-hash.

--dry-run=false No apliques ningún cambio; solo muestra lo que se haría.

--node-name="" Especifica el nombre del nodo.

--patches="" Ruta a un directorio que contiene archivos con nombres como "target[suffix][+patchtype].extension". Por ejemplo, "kube-apiserver0+merge.yaml" o simplemente "etcd.json". "target" puede ser uno de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" puede ser uno de "strategic", "merge" o "json" y coinciden con los formatos de parche admitidos por kubectl. El "patchtype" predeterminado es "strategic". "extension" debe ser "json" o "yaml". "suffix" es una cadena opcional que se puede usar para determinar qué parches se aplican primero alfanuméricamente.

--tls-bootstrap-token="" Especifica el token utilizado para autenticarse temporalmente con el Plano de Control de Kubernetes al unirse al nodo.

--token="" Usa este token tanto para discovery-token como para tls-bootstrap-token cuando esos valores no se proporcionan.

OPCIONES HEREDADAS DE COMANDOS PADRE

--rootfs="" La ruta al sistema de archivos raíz 'real' del host. Esto hará que kubeadm realice un chroot en la ruta proporcionada.

--version=false --version, --version=raw imprime información de la versión y sale; --version=vX.Y.Z... establece la versión reportada
