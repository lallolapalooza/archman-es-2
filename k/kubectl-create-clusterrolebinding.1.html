kubectl-create-clusterrolebinding(1)

Paquete: kubectl

Licencias: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)

NOMBRE

kubectl create clusterrolebinding - Crear una vinculación de rol de clúster para un rol de clúster particular

SINOPSIS

kubectl create clusterrolebinding [OPCIONES]

DESCRIPCIÓN

Crea una vinculación de rol de clúster para un rol de clúster particular.

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--clusterrole="" ClusterRole al que debe hacer referencia este ClusterRoleBinding

--dry-run="none" Debe ser "none", "server" o "client". Si es estrategia de cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si es estrategia de servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--field-manager="kubectl-create" Nombre del gestor utilizado para rastrear la propiedad de los campos.

--group=[] Grupos a vincular al clusterrole. La bandera se puede repetir para agregar varios grupos.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--save-config=false Si es verdadero, la configuración del objeto actual se guardará en su anotación. De lo contrario, la anotación permanecerá sin cambios. Esta bandera es útil cuando desea realizar kubectl apply en este objeto en el futuro.

--serviceaccount=[] Cuentas de servicio a vincular al clusterrole, en el formato :. La bandera se puede repetir para agregar varias cuentas de servicio.

--show-managed-fields=false Si es verdadero, conserva los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a un archivo de plantilla para usar cuando -o=go-template, -o=go-template-file. El formato de plantilla es plantillas de golang [http://golang.org/pkg/text/template/#pkg-overview].

--user=[] Nombres de usuario a vincular al clusterrole. La bandera se puede repetir para agregar varios usuarios.

--validate="strict" Debe ser uno de: strict (o true), warn, ignore (o false). "true" o "strict" usará un esquema para validar la entrada y fallará la solicitud si es inválida. Realizará validación del lado del servidor si ServerSideFieldValidation está habilitado en el api-server, pero recurrirá a una validación del lado del cliente menos confiable si no lo está. "warn" advertirá sobre campos desconocidos o duplicados sin bloquear la solicitud si la validación de campos del lado del servidor está habilitada en el servidor API, y se comportará como "ignore" de lo contrario. "false" o "ignore" no realizará ninguna validación de esquema, descartando silenciosamente cualquier campo desconocido o duplicado.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario normal o una cuenta de servicio en un espacio de nombres.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar varios grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster kubeconfig a utilizar

--context="" El nombre del contexto kubeconfig a utilizar

--disable-compression=false Si es verdadero, optar por no participar en la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará su validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funcionalidad KUBECTL_KUBERC=false o desactivando la funcionalidad KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del espacio de nombres para esta solicitud CLI

--password="" Contraseña para la autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" El tiempo de espera antes de renunciar a una única solicitud al servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa que las solicitudes no caducan.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor

--token="" Token de portador para la autenticación al servidor API

--username="" Nombre de usuario para la autenticación básica al servidor API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión informada

--warnings-as-errors=false Tratar las advertencias recibidas del servidor como errores y salir con un código de salida distinto de cero

EJEMPLO

  # Crear una vinculación de rol de clúster para user1, user2 y group1 usando el rol de clúster cluster-admin
  kubectl create clusterrolebinding cluster-admin --clusterrole=cluster-admin --user=user1 --user=user2 --group=group1
