NOMBRE

kubeadm join phase kubelet-start - Escribe la configuración de Kubelet, certificados y (re)inicia el Kubelet

SINOPSIS

kubeadm join phase kubelet-start [OPCIONES]

DESCRIPCIÓN

Escribe un archivo con la configuración de Kubelet (KubeletConfiguration) y un archivo de entorno con la configuración específica del nodo para kubelet, y luego (re)inicia kubelet.

OPCIONES

--config="" Ruta a un archivo de configuración de kubeadm.

--cri-socket="" Ruta al socket de la CRI para conectar. Si está vacío, kubeadm intentará detectar este valor automáticamente; use esta opción solo si tiene más de una CRI instalada o si tiene un socket CRI no estándar.

--discovery-file="" Para el descubrimiento basado en archivos, un archivo o URL desde el cual cargar la información del clúster.

--discovery-token="" Para el descubrimiento basado en tokens, el token utilizado para validar la información del clúster obtenida del servidor API.

--discovery-token-ca-cert-hash=[] Para el descubrimiento basado en tokens, valida que la clave pública raíz de la CA coincida con este hash (formato: ":").

--discovery-token-unsafe-skip-ca-verification=false Para el descubrimiento basado en tokens, permite unirse sin la fijación de --discovery-token-ca-cert-hash.

--dry-run=false No aplique ningún cambio; solo muestre lo que se haría.

--node-name="" Especifique el nombre del nodo.

--patches="" Ruta a un directorio que contiene archivos llamados "target[suffix][+patchtype].extension". Por ejemplo, "kube-apiserver0+merge.yaml" o simplemente "etcd.json". "target" puede ser uno de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" puede ser uno de "strategic", "merge" o "json" y coinciden con los formatos de parche admitidos por kubectl. El tipo de parche por defecto es "strategic". "extension" debe ser "json" o "yaml". "suffix" es una cadena opcional que puede utilizarse para determinar qué parches se aplican primero alfabéticamente.

--tls-bootstrap-token="" Especifique el token utilizado para autenticarse temporalmente con el plano de control de Kubernetes al unirse al nodo.

--token="" Utilice este token tanto para discovery-token como para tls-bootstrap-token cuando esos valores no se proporcionen.

OPCIONES HEREDADAS DE COMANDOS PADRE

--rootfs="" La ruta al sistema de archivos raíz 'real' del host. Esto hará que kubeadm realice un chroot en la ruta proporcionada.

--version=false --version, --version=raw imprime información de la versión y sale; --version=vX.Y.Z... establece la versión reportada
