NOMBRE

kresd.systemd - gestión de Knot Resolver 5.7.5 a través de systemd.

SINOPSIS

kresd@.service
kresd.target
system-kresd.slice

DESCRIPCIÓN

Esta página del manual describe cómo gestionar kresd utilizando las unidades de systemd.

INICIO RÁPIDO

systemctl start kresd@1 - instancia única de kresd, respondiendo en localhost

DAEMONS CONCURRENTES

El demonio kresd puede ejecutarse en múltiples procesos independientes, que se gestionan con systemd a través de plantillas de systemd (ver systemd.unit(5)). Cada instancia de servicio de systemd de kresd (kresd@.service) representa un único proceso kresd independiente.

Si tiene más de un núcleo de CPU disponible, un único demonio kresd en ejecución solo podrá utilizar un núcleo a la vez, dejando los otros núcleos inactivos. Si desea que kresd aproveche todos los núcleos disponibles, compartiendo tanto la caché como los sockets, debe habilitar e iniciar tantas instancias de kresd@.service como tenga núcleos. Típicamente, cada instancia se llama simplemente kresd@N.service, donde N es un número decimal. Por ejemplo, para habilitar e iniciar 3 demonios concurrentes:

systemctl enable --now kresd@1.service kresd@2.service kresd@3.service

El conjunto de servicios kresd gestionado por systemd se agrupa en la "slice" system-kresd.slice. La "slice" incluye todos los demonios en ejecución (instancias de kresd@.service).

EJEMPLOS

Para iniciar una única instancia de kresd y habilitarla al arrancar:

systemctl enable --now kresd@1.service

Para reiniciar (o detener) todas las instancias en ejecución, puede usar una expresión comodín. Tenga en cuenta que no se puede usar un comodín para iniciar o habilitar instancias.

systemctl restart 'kresd@*'

Los usuarios de Bash también pueden usar la Expansión de Llaves para habilitar o iniciar múltiples instancias, en lugar de listarlas manualmente.

systemctl enable --now kresd@{1..4}.service

Para iniciar todos los demonios kresd habilitados, también puede utilizar el kresd.target proporcionado:

systemctl start kresd.target
