NOMBRE

kubectl create secret generic - Crear un secreto desde un archivo local, directorio o valor literal

SINOPSIS

kubectl create secret generic [OPCIONES]

DESCRIPCIÓN

Crea un secreto basado en un archivo, directorio o valor literal especificado.

Un único secreto puede empaquetar uno o más pares clave/valor.

Al crear un secreto basado en un archivo, la clave por defecto será el nombre base del archivo y el valor será el contenido del archivo. Si el nombre base es una clave inválida o deseas elegir la tuya, puedes especificar una clave alternativa.

Al crear un secreto basado en un directorio, cada archivo cuyo nombre base sea una clave válida en el directorio se empaquetará en el secreto. Se ignoran todas las entradas de directorio excepto los archivos regulares (por ejemplo, subdirectorios, enlaces simbólicos, dispositivos, tuberías, etc.).

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--append-hash=false Añade un hash del secreto a su nombre.

--dry-run="none" Debe ser "none", "server" o "client". Si la estrategia es cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si la estrategia es servidor, envía una solicitud al servidor sin persistir el recurso.

--field-manager="kubectl-create" Nombre del gestor utilizado para rastrear la propiedad de los campos.

--from-env-file=[] Especifica la ruta de un archivo para leer líneas de pares clave=valor y crear un secreto.

--from-file=[] Los archivos clave se pueden especificar usando su ruta de archivo, en cuyo caso se les dará un nombre por defecto, u opcionalmente con un nombre y ruta de archivo, en cuyo caso se usará el nombre dado. Especificar un directorio iterará cada archivo con nombre en el directorio que sea una clave de secreto válida.

--from-literal=[] Especifica una clave y un valor literal para insertar en el secreto (es decir, miclave=algunvalor)

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--save-config=false Si es verdadero, la configuración del objeto actual se guardará en su anotación. De lo contrario, la anotación no se modificará. Esta bandera es útil cuando deseas realizar kubectl apply en este objeto en el futuro.

--show-managed-fields=false Si es verdadero, conserva los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a un archivo de plantilla para usar cuando -o=go-template, -o=go-template-file. El formato de plantilla son plantillas golang [http://golang.org/pkg/text/template/#pkg-overview].

--type="" El tipo de secreto a crear

--validate="strict" Debe ser uno de: strict (o true), warn, ignore (o false). "true" o "strict" usarán un esquema para validar la entrada y fallarán la solicitud si es inválida. Realizará validación del lado del servidor si ServerSideFieldValidation está habilitado en el api-server, pero recurrirá a una validación del lado del cliente menos confiable si no. "warn" advertirá sobre campos desconocidos o duplicados sin bloquear la solicitud si la validación de campos del lado del servidor está habilitada en el servidor API, y se comportará como "ignore" de lo contrario. "false" o "ignore" no realizarán ninguna validación de esquema, descartando silenciosamente cualquier campo desconocido o duplicado.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario regular o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché por defecto

--certificate-authority="" Ruta a un archivo de certificado para la autoridad certificadora

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a utilizar

--context="" El nombre del contexto de kubeconfig a utilizar

--disable-compression=false Si es verdadero, omite la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará para determinar su validez. Esto hará que sus conexiones HTTPS no sean seguras.

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes de CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para las preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funciones KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud de CLI

--password="" Contraseña para la autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" El tiempo de espera antes de desistir de una única solicitud al servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a usar para la validación del certificado del servidor. Si no se proporciona, se usa el nombre de host utilizado para contactar al servidor

--token="" Token Bearer para autenticación al servidor API

--user="" El nombre del usuario de kubeconfig a utilizar

--username="" Nombre de usuario para la autenticación básica al servidor API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión reportada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero

EJEMPLO

  # Crea un nuevo secreto llamado my-secret con claves para cada archivo en la carpeta bar
  kubectl create secret generic my-secret --from-file=ruta/a/bar
  # Crea un nuevo secreto llamado my-secret con claves especificadas en lugar de nombres en disco
  kubectl create secret generic my-secret --from-file=clave-ssh-privada=ruta/a/id_rsa --from-file=clave-ssh-publica=ruta/a/id_rsa.pub
  # Crea un nuevo secreto llamado my-secret con clave1=supersecreto y clave2=secretotop
  kubectl create secret generic my-secret --from-literal=clave1=supersecreto --from-literal=clave2=secretotop
  # Crea un nuevo secreto llamado my-secret usando una combinación de un archivo y un literal
  kubectl create secret generic my-secret --from-file=clave-ssh-privada=ruta/a/id_rsa --from-literal=contraseña=secretotop
  # Crea un nuevo secreto llamado my-secret desde archivos de entorno
  kubectl create secret generic my-secret --from-env-file=ruta/a/foo.env --from-env-file=ruta/a/bar.env
