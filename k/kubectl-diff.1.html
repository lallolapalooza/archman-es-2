NOMBRE

kubectl diff - Compara la versión en vivo contra una versión que se aplicaría

SINOPSIS

kubectl diff [OPCIONES]

DESCRIPCIÓN

Compara las configuraciones especificadas por nombre de archivo o entrada estándar entre la configuración en línea actual y la configuración tal como sería si se aplicara.

La salida es siempre YAML.

La variable de entorno KUBECTL_EXTERNAL_DIFF se puede usar para seleccionar su propio comando diff. Los usuarios pueden usar comandos externos con parámetros, por ejemplo: KUBECTL_EXTERNAL_DIFF="colordiff -N -u"

Por defecto, el comando "diff" disponible en su PATH se ejecutará con las opciones "-u" (diff unificado) y "-N" (tratar archivos ausentes como vacíos).

Estado de salida: 0 No se encontraron diferencias. 1 Se encontraron diferencias. >1 Kubectl o diff fallaron con un error.

Nota: Se espera que KUBECTL_EXTERNAL_DIFF, si se usa, siga esa convención.

OPCIONES

--concurrency=1 Número de objetos a procesar en paralelo al comparar con la versión en vivo. Un número mayor = más rápido, pero más memoria, E/S y CPU durante ese período de tiempo más corto.

--field-manager="kubectl-client-side-apply" Nombre del gestor utilizado para rastrear la propiedad de los campos.

-f, --filename=[] Nombre de archivo, directorio o URL a archivos que contienen la configuración a comparar

--force-conflicts=false Si es verdadero, la aplicación del lado del servidor forzará los cambios frente a los conflictos.

-k, --kustomize="" Procesa el directorio kustomization. Esta bandera no se puede usar junto con -f o -R.

--prune=false Incluye recursos que serían eliminados por la poda. Se puede usar con -l y por defecto muestra todos los recursos que serían podados

--prune-allowlist=[] Sobrescribe la lista de permitidos predeterminada para --prune

-R, --recursive=false Procesa el directorio utilizado en -f, --filename recursivamente. Útil cuando desea administrar manifiestos relacionados organizados dentro del mismo directorio.

-l, --selector="" Selector (consulta de etiquetas) para filtrar, soporta '=', '==', '!=', 'in', 'notin'. (ej. -l key1=value1,key2=value2,key3 in (value3)). Los objetos coincidentes deben satisfacer todas las restricciones de etiquetas especificadas.

--server-side=false Si es verdadero, la aplicación se ejecuta en el servidor en lugar de en el cliente.

--show-managed-fields=false Si es verdadero, incluye los campos administrados en la comparación.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario podría ser un usuario regular o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster kubeconfig a usar

--context="" El nombre del contexto kubeconfig a usar

--disable-compression=false Si es verdadero, se opta por no comprimir las respuestas para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará su validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a usar para las solicitudes CLI.

--kuberc="" Ruta al archivo kuberc a usar para preferencias. Esto puede ser deshabilitado exportando el gate de función KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud CLI

--password="" Contraseña para la autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" El tiempo de espera antes de rendirse en una única solicitud al servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de espera de las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a usar para la validación del certificado del servidor. Si no se proporciona, se usa el nombre de host utilizado para contactar al servidor

--token="" Token Bearer para la autenticación al servidor API

--user="" El nombre del usuario kubeconfig a usar

--username="" Nombre de usuario para la autenticación básica al servidor API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión informada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero

EJEMPLO

  # Compara los recursos incluidos en pod.json
  kubectl diff -f pod.json
  # Compara el archivo leído desde la entrada estándar
  cat service.yaml | kubectl diff -f -
