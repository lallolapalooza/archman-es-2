NOMBRE

kubectl set image - Actualiza la imagen de una plantilla de pod

SINOPSIS

kubectl set image [OPCIONES]

DESCRIPCIÓN

Actualiza las imágenes de contenedor existentes de los recursos.

Los recursos posibles incluyen (sin distinción de mayúsculas y minúsculas):

    pod (po), replicationcontroller (rc), deployment (deploy), daemonset (ds), statefulset (sts), cronjob (cj), replicaset (rs)

OPCIONES

--all=false Selecciona todos los recursos, en el espacio de nombres de los tipos de recursos especificados

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--dry-run="none" Debe ser "none", "server" o "client". Si es estrategia de cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si es estrategia de servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--field-manager="kubectl-set" Nombre del gestor utilizado para rastrear la propiedad de los campos.

-f, --filename=[] Nombre de archivo, directorio o URL a archivos que identifican el recurso a obtener de un servidor.

-k, --kustomize="" Procesa el directorio kustomization. Esta bandera no se puede usar junto con -f o -R.

--local=false Si es verdadero, set image NO contactará con el api-server sino que se ejecutará localmente.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--record=false Graba el comando kubectl actual en la anotación del recurso. Si se establece en falso, no graba el comando. Si se establece en verdadero, graba el comando. Si no se establece, por defecto actualiza el valor de la anotación existente solo si ya existe.

-R, --recursive=false Procesa el directorio usado en -f, --filename recursivamente. Útil cuando quieres gestionar manifiestos relacionados organizados dentro del mismo directorio.

-l, --selector="" Selector (consulta de etiquetas) para filtrar, soporta '=', '==', '!=', 'in', 'notin'.(ej. -l key1=value1,key2=value2,key3 in (value3)). Los objetos coincidentes deben satisfacer todas las restricciones de etiquetas especificadas.

--show-managed-fields=false Si es verdadero, conserva los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a archivo de plantilla a usar cuando -o=go-template, -o=go-template-file. El formato de plantilla es plantillas golang [http://golang.org/pkg/text/template/#pkg-overview].

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario normal o una cuenta de servicio en un espacio de nombres.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster kubeconfig a usar

--context="" El nombre del contexto kubeconfig a usar

--disable-compression=false Si es verdadero, se opta por no comprimir las respuestas para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará para su validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes de CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funciones KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requerir que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del espacio de nombres para esta solicitud de CLI

--password="" Contraseña para la autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" El tiempo de espera antes de renunciar a una única solicitud al servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de espera de las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a usar para la validación del certificado del servidor. Si no se proporciona, se usa el nombre de host utilizado para contactar al servidor

--token="" Token de portador para autenticación al servidor API

--user="" El nombre del usuario kubeconfig a usar

--username="" Nombre de usuario para la autenticación básica al servidor API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión informada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero

EJEMPLO

  # Establece la imagen del contenedor nginx de un deployment a 'nginx:1.9.1', y la imagen del contenedor busybox a 'busybox'
  kubectl set image deployment/nginx busybox=busybox nginx=nginx:1.9.1
  # Actualiza la imagen del contenedor nginx de todos los deployments y rc a 'nginx:1.9.1'
  kubectl set image deployments,rc nginx=nginx:1.9.1 --all
  # Actualiza la imagen de todos los contenedores del daemonset abc a 'nginx:1.9.1'
  kubectl set image daemonset abc *=nginx:1.9.1
  # Imprime el resultado (en formato yaml) de actualizar la imagen del contenedor nginx desde un archivo local, sin contactar al servidor
  kubectl set image -f path/to/file.yaml nginx=nginx:1.9.1 --local -o yaml

kubectl-set-image(1)

NAME

kubectl-set-image - Actualiza la imagen de un contenedor en un Deployment, StatefulSet o DaemonSet.

SYNOPSIS

kubectl set image (TYPE NAME) (-c CONTAINER_NAME | --all) NEW_IMAGE [IDENTIFIERS...]

kubectl set image TYPE/NAME (-c CONTAINER_NAME | --all) NEW_IMAGE [IDENTIFIERS...]

DESCRIPTION

Actualiza la imagen de un contenedor específico en un Deployment, StatefulSet o DaemonSet. Puede especificar el recurso y el nombre del contenedor a actualizar. Si no se especifica un nombre de contenedor, se actualizará el primer contenedor en el pod.

OPTIONS

-c, --container=
El nombre del contenedor a actualizar. Si no se especifica, se actualizará el primer contenedor.
--all
Actualizar todos los contenedores en el pod.
-f, --filename=
Nombre del archivo que contiene la definición del recurso.
-l, --selector=
Selector de etiquetas para filtrar los recursos.
--local
Si es true, no enviar la solicitud al servidor, sino que devolver el objeto local modificado.
--record
Grabar el comando de kubectl que realizó este cambio en la anotación de revolución.
-R, --recursive=
Procesar los archivos y directorios de forma recursiva.
--namespace=
Si se omite, se utiliza el namespace de la configuración actual.

EXAMPLE

Actualizar la imagen del contenedor 'mi-contenedor' en el Deployment 'mi-deployment' a 'nueva-imagen:v2': 

kubectl set image deployment/mi-deployment mi-contenedor=nueva-imagen:v2

Actualizar la imagen del primer contenedor en todos los pods del DaemonSet 'mi-daemonset' a 'nueva-imagen:v3': 

kubectl set image daemonset/mi-daemonset nuevas-imagen:v3

Actualizar la imagen del contenedor 'app' en todos los pods del StatefulSet 'mi-statefulset' a 'nueva-imagen:v4': 

kubectl set image statefulset/mi-statefulset -c app nueva-imagen:v4
