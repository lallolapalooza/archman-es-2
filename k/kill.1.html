KILL(1) Comandos de Usuario KILL(1)

NOMBRE

kill - terminar un proceso

SINOPSIS

kill [-señal|-s señal|-p] [-q valor] [-a] [--timeout milisegundos señal] [--] pid|nombre...

kill -l [número|0xmáscara_señal] | -L

kill -d pid

DESCRIPCIÓN

El comando kill envía la señal especificada a los procesos o grupos de procesos especificados.

Si no se especifica ninguna señal, se envía la señal TERM. La acción por defecto para esta señal es terminar el proceso. Esta señal debe usarse en preferencia a la señal KILL (número 9), ya que un proceso puede instalar un manejador para la señal TERM para realizar pasos de limpieza antes de terminar de manera ordenada. Si un proceso no termina después de que se haya enviado una señal TERM, entonces se puede usar la señal KILL; ten en cuenta que esta última señal no puede ser capturada, y por lo tanto no le da al proceso objetivo la oportunidad de realizar ninguna limpieza antes de terminar.

La mayoría de los shells modernos tienen un comando kill incorporado, con un uso bastante similar al del comando descrito aquí. Las opciones --all, --pid y --queue, y la posibilidad de especificar procesos por nombre de comando, son extensiones locales.

Si señal es 0, entonces no se envía ninguna señal real, pero aún se realizan verificaciones de errores.

ARGUMENTOS

La lista de procesos a los que se enviará la señal puede ser una mezcla de nombres y PIDs.

pid

Cada pid puede expresarse de una de las siguientes maneras:

n

donde n es mayor que 0. Se envía una señal al proceso con PID n.

0

Se envían señales a todos los procesos del grupo de procesos actual.

-1

Se envían señales a todos los procesos con un PID mayor que 1.

-n

donde n es mayor que 1. Se envían señales a todos los procesos del grupo de procesos n. Cuando se da un argumento de la forma '-n', y está destinado a denotar un grupo de procesos, se debe especificar primero una señal, o el argumento debe ir precedido de la opción '--', de lo contrario se tomará como la señal a enviar.

nombre

Se enviarán señales a todos los procesos invocados usando este nombre.

OPCIONES

-s, --signal señal

La señal a enviar. Puede darse como nombre o número.

-l, --list [número|0xmáscara_señal]

Imprime una lista de nombres de señales, convierte el número de señal dado a un nombre, o convierte la máscara de señal dada a nombres. Las señales se pueden encontrar en /usr/include/linux/signal.h. 
$ ps s $$
  UID     PID          PENDING          BLOCKED          IGNORED           CAUGHT STAT TTY        TIME COMMAND
 1000 1608069 0000000000000000 0000000000000002 0000000000384000 0000000008013003 Ss   pts/44     0:02 zsh
$ kill -l 0x0000000000384000
TERM
TSTP
TTIN
TTOU

-L, --table

Similar a -l, pero imprimirá nombres de señales y sus números correspondientes.

-a, --all

No restrinja la conversión de nombre de comando a PID a procesos con el mismo UID que el proceso actual.

-p, --pid

Solo imprime el ID de proceso (PID) de los procesos nombrados, no envía ninguna señal.

-r, --require-handler

No envíe la señal si no es capturada en el espacio de usuario por el proceso al que se le envía la señal.

--verbose

Imprime los PID(s) a los que se les enviará la señal con kill junto con la señal.

-q, --queue valor

Envía la señal usando sigqueue(3) en lugar de kill(2). El argumento valor es un entero que se envía junto con la señal. Si el proceso receptor ha instalado un manejador para esta señal usando la bandera SA_SIGINFO de sigaction(2), entonces puede obtener estos datos a través del campo si_sigval de la estructura siginfo_t.

--timeout milisegundos señal

Envía una señal definida de la forma habitual a un proceso, seguida de una señal adicional después de un retraso especificado. La opción --timeout hace que kill espere un período definido en milisegundos antes de enviar una señal de seguimiento señal al proceso. Esta característica se implementa utilizando la característica del descriptor de archivo PID del kernel de Linux para garantizar que la señal de seguimiento se envíe al mismo proceso o no se envíe si el proceso ya no existe.

Tenga en cuenta que el sistema operativo puede reutilizar PIDs y implementar una característica equivalente en un shell usando kill y sleep estaría sujeto a condiciones de carrera en las que la señal de seguimiento podría enviarse a un proceso diferente que utilizara un PID reciclado.

La opción --timeout se puede especificar varias veces: las señales se envían secuencialmente con los tiempos de espera especificados. La opción --timeout se puede combinar con la opción --queue.

Como ejemplo, el siguiente comando envía las señales QUIT, TERM y KILL en secuencia y espera 1000 milisegundos entre el envío de las señales:

kill --verbose --timeout 1000 TERM --timeout 1000 KILL \
        --signal QUIT 12345

-d, --show-process-state pid

Decodifica los campos relacionados con la señal en /proc/pid/status. 
$ kill -d $$
Blocked: INT
Ignored: TERM TSTP TTIN TTOU
Caught: HUP INT PIPE ALRM CHLD WINCH

ESTADO DE SALIDA

kill tiene los siguientes valores de estado de salida:

0

éxito

1

fallo

64

éxito parcial (cuando se especifica más de un proceso)

NOTAS

Aunque es posible especificar el TID (ID de hilo, ver gettid(2)) de uno de los hilos en un proceso multihilo como argumento de kill, la señal se dirige de todos modos al proceso (es decir, a todo el grupo de hilos). En otras palabras, no es posible enviar una señal a un hilo explícitamente seleccionado en un proceso multihilo. La señal se entregará a un hilo seleccionado arbitrariamente en el proceso objetivo que no esté bloqueando la señal. Para más detalles, ver signal(7) y la descripción de CLONE_THREAD en clone(2).

Varios shells proporcionan un comando kill incorporado que se prefiere en relación con el ejecutable kill(1) descrito en este manual. La forma más fácil de asegurar que se está ejecutando el comando descrito en esta página es usar la ruta completa al llamar al comando, por ejemplo: /bin/kill --version
