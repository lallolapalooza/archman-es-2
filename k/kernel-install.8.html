--entry-token

=
Controla cómo nombrar e identificar las entradas del cargador de arranque para esta instalación o eliminación del kernel. Acepta como argumento uno de "auto", "machine-id", "os-id", "os-image-id", o una cadena arbitraria con el prefijo "literal:".

Si se establece en machine-id, las entradas se nombran según la ID de la máquina del sistema en ejecución (por ejemplo, "b0e793a9baf14b5fa13ecbe84ff637ac"). Véase machine-id(5) para detalles sobre el concepto y el archivo de la ID de la

máquina.

Si se establece en os-id, las entradas se nombran según la ID del SO del sistema en ejecución, es decir, el campo ID= de os-release(5) (por ejemplo, "fedora"). De manera similar, si se establece en os-image-id, las entradas se nombran según la ID de la imagen del SO del sistema en ejecución, es decir, el campo IMAGE_ID= de os-release (por ejemplo, "vendorx-cashier-system")

.

Si se establece en auto (el valor por defecto), se leerá el archivo /etc/kernel/entry-token (o $KERNEL_INSTALL_CONF_ROOT/entry-token) si existe, y se usará el valor almacenado. De lo contrario, si la ID de la máquina local está inicializada, se usará. De lo contrario, IMAGE_ID= de os-release se usará, si está establecido. De lo contrario, ID= de os-release se usará, si está establecido. De lo contrario, se usará una ID de máquina generada

aleatoriamente.

Usar la ID de la máquina para nombrar las entradas es generalmente preferible, sin embargo hay casos donde usar los otros identificadores es una buena opción. Específicamente: si los datos de identificación que implica la ID de la máquina no deben almacenarse en la partición (sin cifrar) $BOOT_ROOT , o si la ID debe generarse en el primer arranque y no se conoce cuando se preparan las entradas. Tenga en cuenta que usar la ID de la máquina tiene la ventaja de que múltiples instalaciones paralelas del mismo SO pueden coexistir en el mismo medio, y pueden actualizar sus entradas del cargador de arranque de forma independiente. Al usar otro identificador (como la ID del SO o la ID de la imagen del SO), las instalaciones paralelas del mismo SO intentarían usar el mismo nombre de entrada. Para soportar instalaciones paralelas, el instalador debe usar un token de entrada diferente al añadir una segunda

instalación.

Se establece $KERNEL_INSTALL_MACHINE_ID para los plugins con la machine-id deseada a usar. Siempre es una ID de 128 bits. inicial.

Tenga en cuenta que aunque $KERNEL_INSTALL_ENTRY_TOKEN y $KERNEL_INSTALL_MACHINE_ID a menudo se establecen al mismo valor, el último está garantizado de ser una ID válida de 32 caracteres en hexadecimales en minúsculas mientras que el primero puede ser cualquier cadena corta. El token de entrada a usar se lee de /etc/kernel/entry-token, si existe. De lo contrario, se comprueban algunos posibles candidatos a continuación $BOOT para directorios de entradas Tipo 1 de la Especificación del Cargador de Arranque, y si se encuentra, el token de entrada se deriva de ese. $KERNEL_INSTALL_CONF_ROOT se puede establecer para anular la ubicación de los archivos de configuración leídos por kernel-install. Cuando se establece, install.conf, entry-token y otros archivos se leerán solo de este directorio. Tenga en cuenta que esta ruta es relativa al host, y en particular los enlaces simbólicos en este directorio se resuelven relativos al host, incluso si --root=root se usa. Esto significa que generalmente no es correcto usar esta variable para especificar un directorio debajo de root si se usan enlaces simbólicos

allí.

complemento.

máquina.
