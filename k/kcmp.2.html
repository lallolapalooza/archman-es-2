kcmp(2) System Calls Manual kcmp(2)

NOMBRE

kcmp - compara dos procesos para determinar si comparten un recurso del kernel

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/kcmp.h>       /* Definición de constantes KCMP_* */
#include <sys/syscall.h>      /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_kcmp, pid_t pid1, pid_t pid2, int type,
            unsigned long idx1, unsigned long idx2);

Nota: glibc no proporciona un envoltorio para kcmp(), haciendo necesario el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema kcmp() se puede usar para comprobar si los dos procesos identificados por pid1 y pid2 comparten un recurso del kernel, como memoria virtual, descriptores de archivo, etc.

El permiso para emplear kcmp() se rige por las comprobaciones del modo de acceso ptrace PTRACE_MODE_READ_REALCREDS contra ambos pid1 y pid2; véase ptrace(2).

El argumento type especifica qué recurso se va a comparar en los dos procesos. Tiene uno de los siguientes valores:

KCMP_FILE
Comprueba si un descriptor de archivo idx1 en el proceso pid1 se refiere a la misma descripción de archivo abierta (véase open(2)) que el descriptor de archivo idx2 en el proceso pid2. La existencia de dos descriptores de archivo que se refieren a la misma descripción de archivo abierta puede ocurrir como resultado de dup(2) (y similares) fork(2), o al pasar descriptores de archivo a través de un socket de dominio (véase unix(7)).
KCMP_FILES
Comprueba si los procesos comparten el mismo conjunto de descriptores de archivo abiertos. Los argumentos idx1 y idx2 se ignoran. Véase la discusión de la bandera CLONE_FILES en clone(2).
KCMP_FS
Comprueba si los procesos comparten la misma información del sistema de archivos (es decir, máscara de creación de modo de archivo, directorio de trabajo y raíz del sistema de archivos). Los argumentos idx1 y idx2 se ignoran. Véase la discusión de la bandera CLONE_FS en clone(2).
KCMP_IO
Comprueba si los procesos comparten el contexto de E/S. Los argumentos idx1 y idx2 se ignoran. Véase la discusión de la bandera CLONE_IO en clone(2).
KCMP_SIGHAND
Comprueba si los procesos comparten la misma tabla de disposiciones de señales. Los argumentos idx1 y idx2 se ignoran. Véase la discusión de la bandera CLONE_SIGHAND en clone(2).
KCMP_SYSVSEM
Comprueba si los procesos comparten la misma lista de operaciones de deshacer de semáforos System V. Los argumentos idx1 y idx2 se ignoran. Véase la discusión de la bandera CLONE_SYSVSEM en clone(2).
KCMP_VM
Comprueba si los procesos comparten el mismo espacio de direcciones. Los argumentos idx1 y idx2 se ignoran. Véase la discusión de la bandera CLONE_VM en clone(2).
KCMP_EPOLL_TFD (desde Linux 4.13)
Comprueba si el descriptor de archivo idx1 del proceso pid1 está presente en la instancia de epoll(7) descrita por idx2 del proceso pid2. El argumento idx2 es un puntero a una estructura donde se describe el archivo de destino. Esta estructura tiene la forma:


struct kcmp_epoll_slot {
    __u32 efd;
    __u32 tfd;
    __u64 toff;
};

Dentro de esta estructura, efd es un descriptor de archivo epoll devuelto por epoll_create(2), tfd es un número de descriptor de archivo de destino, y toff es un desplazamiento de archivo de destino contado desde cero. Varios destinos diferentes pueden registrarse con el mismo número de descriptor de archivo y establecer un desplazamiento específico ayuda a investigar cada uno de ellos.

Tenga en cuenta que kcmp() no está protegido contra falsos positivos que pueden ocurrir si los procesos se están ejecutando actualmente. Debería detener los procesos enviando SIGSTOP (véase signal(7)) antes de la inspección con esta llamada al sistema para obtener resultados significativos.

VALOR DE RETORNO

El valor de retorno de una llamada exitosa a kcmp() es simplemente el resultado de la comparación aritmética de punteros del kernel (cuando el kernel compara recursos, utiliza sus direcciones de memoria).

La forma más fácil de explicar es considerar un ejemplo. Suponiendo que v1 y v2 son las direcciones de los recursos apropiados, entonces el valor de retorno es uno de los siguientes:

0
v1 es igual a v2; en otras palabras, los dos procesos comparten el recurso.
1
v1 es menor que v2.
2
v1 es mayor que v2.
3
v1 no es igual a v2, pero no hay información de ordenamiento disponible.

En caso de error, se devuelve -1 y errno se establece para indicar el error.

kcmp() fue diseñado para devolver valores adecuados para la ordenación. Esto es particularmente útil si uno necesita comparar un gran número de descriptores de archivo.

ERRORES

EBADF
type es KCMP_FILE y fd1 o fd2 no es un descriptor de archivo abierto.
EFAULT
La ranura epoll dirigida por idx2 está fuera del espacio de direcciones del usuario.
EINVAL
type es inválido.
ENOENT
El archivo de destino no está presente en la instancia de epoll(7).
EPERM
Permiso insuficiente para inspeccionar los recursos del proceso. La capacidad CAP_SYS_PTRACE es necesaria para inspeccionar procesos que no te pertenecen. También pueden aplicarse otras limitaciones de ptrace, como CONFIG_SECURITY_YAMA, que, cuando /proc/sys/kernel/yama/ptrace_scope es 2, limita kcmp() a procesos hijos; véase ptrace(2).
ESRCH
El proceso pid1 o pid2 no existe.

ESTÁNDARES

Linux.

HISTORIA

Linux 3.5.

Antes de Linux 5.12, esta llamada al sistema solo estaba disponible si el kernel estaba configurado con CONFIG_CHECKPOINT_RESTORE, ya que el propósito original de la llamada al sistema era para la función de punto de control/restauración en espacio de usuario (CRIU). (La alternativa a esta llamada al sistema habría sido exponer información de proceso adecuada a través del sistema de archivos proc(5); esto se consideró inadecuado por razones de seguridad.) Desde Linux 5.12, esta llamada al sistema también está disponible si el kernel está configurado con CONFIG_KCMP.

Programa fuente

#define _GNU_SOURCE
#include <err.h>
#include <fcntl.h>
#include <linux/kcmp.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/syscall.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
static int
kcmp(pid_t pid1, pid_t pid2, int type,
     unsigned long idx1, unsigned long idx2)
{
    return syscall(SYS_kcmp, pid1, pid2, type, idx1, idx2);
}
static void
test_kcmp(char *msg, pid_t pid1, pid_t pid2, int fd_a, int fd_b)
{
    printf("\t%s\n", msg);
    printf("\t\tkcmp(%jd, %jd, KCMP_FILE, %d, %d) ==> %s\n",
           (intmax_t) pid1, (intmax_t) pid2, fd_a, fd_b,
           (kcmp(pid1, pid2, KCMP_FILE, fd_a, fd_b) == 0) ?
                        "same" : "different");
}
int
main(void)
{
    int                fd1, fd2, fd3;
    static const char  pathname[] = "/tmp/kcmp.test";
    fd1 = open(pathname, O_CREAT | O_RDWR, 0600);
    if (fd1 == -1)
        err(EXIT_FAILURE, "open");
    printf("Parent PID is %jd\n", (intmax_t) getpid());
    printf("Parent opened file on FD %d\n\n", fd1);
    switch (fork()) {
    case -1:
        err(EXIT_FAILURE, "fork");
    case 0:
        printf("PID of child of fork() is %jd\n", (intmax_t) getpid());
        test_kcmp("Compare duplicate FDs from different processes:",
                  getpid(), getppid(), fd1, fd1);
        fd2 = open(pathname, O_CREAT | O_RDWR, 0600);
        if (fd2 == -1)
            err(EXIT_FAILURE, "open");
        printf("Child opened file on FD %d\n", fd2);
        test_kcmp("Compare FDs from distinct open()s in same process:",
                  getpid(), getpid(), fd1, fd2);
        fd3 = dup(fd1);
        if (fd3 == -1)
            err(EXIT_FAILURE, "dup");
        printf("Child duplicated FD %d to create FD %d\n", fd1, fd3);
        test_kcmp("Compare duplicated FDs in same process:",
                  getpid(), getpid(), fd1, fd3);
        break;
    default:
        wait(NULL);
    }
    exit(EXIT_SUCCESS);
}
