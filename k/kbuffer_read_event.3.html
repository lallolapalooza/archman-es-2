kbuffer_read_event(3)

Paquete: libtraceevent

Licencias: GPL-2.0-only, LGPL-2.1-only

LIBTRACEEVENT(3) Manual de libtraceevent LIBTRACEEVENT(3)

NOMBRE

kbuffer_read_event, kbuffer_next_event, kbuffer_missed_events, kbuffer_event_size, kbuffer_curr_size, kbuffer_curr_offset, kbuffer_curr_index, kbuffer_read_buffer - Funciones para leer a través del sub-búfer de kbuffer.

SINOPSIS

#include <kbuffer.h>
void *kbuffer_read_event(struct kbuffer *kbuf, unsigned long long *ts);
void *kbuffer_next_event(struct kbuffer *kbuf, unsigned long long *ts);
void *kbuffer_read_at_offset(struct kbuffer *kbuf, int offset, unsigned long long *ts);
int kbuffer_missed_events(struct kbuffer *kbuf);
int kbuffer_event_size(struct kbuffer *kbuf);
int kbuffer_curr_size(struct kbuffer *kbuf);
int kbuffer_curr_offset(struct kbuffer *kbuf);
int kbuffer_curr_index(struct kbuffer *kbuf);
int kbuffer_read_buffer(struct kbuffer *kbuf, void *buffer, int len);

DESCRIPCIÓN

La función kbuffer_read_event() lee el siguiente evento en el descriptor kbuf y si ts no es NULL, colocará su marca de tiempo en él. Esto no modifica el descriptor kbuf, y llamar a esta función múltiples veces devolverá el mismo resultado.

La función kbuffer_next_event() devolverá el siguiente evento en el descriptor kbuf. También establecerá ts a la marca de tiempo del evento devuelto. Se devuelve NULL si no hay más eventos y ts no estará definido. Tenga en cuenta que si esto se llama directamente después de un kbuffer_load_subbuffer(), es probable que dé un resultado inesperado, ya que devolverá el segundo evento y no el primero. Normalmente, esta función solo se usa para pasar al siguiente evento y para saber si hay más eventos para leer, y kbuffer_read_event() siempre se llama primero.

La función kbuffer_read_at_offset() devuelve el evento ubicado en un offset dado desde el principio del sub-búfer. Este offset se puede obtener de kbuffer_curr_offset(). Si ts apunta a un unsigned long long, se establecerá a la marca de tiempo del evento en el offset dado.

Si el sub-búfer tuvo eventos perdidos antes que él, entonces kbuffer_missed_events() devolverá un valor distinto de cero. Si devuelve -1, significa que hubo eventos perdidos, pero el número exacto de eventos perdidos es desconocido. Si devuelve un número positivo, entonces el número de eventos perdidos es el valor de retorno.

La función kbuffer_event_size() devuelve el tamaño de la porción de datos del evento actual (el que sería devuelto por kbuffer_read_event().

La función kbuffer_curr_size() devuelve el tamaño total del registro del evento actual (el que sería devuelto por kbuffer_read_event(). La diferencia aquí es que el valor de retorno incluye el tamaño de los metadatos del registro del evento que no forman parte de lo que devuelve kbuffer_read_event().

La función kbuffer_curr_offset() devuelve el offset desde el principio del sub-búfer donde comienzan los metadatos del registro del evento actual. El primer evento no estará en el offset cero. Este offset se puede utilizar para obtener el evento con kbuffer_read_at_offset().

La función kbuffer_curr_index() devuelve el índice desde el principio de la sección de datos del sub-búfer donde se encuentran los metadatos del evento actual. El primer evento probablemente será cero, pero puede que no lo sea si hay una marca de tiempo adjunta a él.

La función kbuffer_read_buffer() llenará el buffer dado desde kbuf de la misma manera que el kernel realizaría una llamada al sistema read. Es decir, si la longitud len es menor que el tamaño del sub-búfer, o si el índice actual de kbuffer no es cero, comenzará a copiar desde el evento actual de kbuf y creará buffer como un nuevo sub-búfer (con una marca de tiempo y una cabecera de confirmación) con ese evento que se encontró e incluyendo todos los eventos posteriores que quepan dentro de len. El len debe incluir el tamaño de la cabecera del sub-búfer, así como los eventos a incluir. Es decir, len es el tamaño asignado de buffer que se puede llenar. El retorno de esta función es el índice del final del último evento que se agregó. Si no hay más eventos, se devuelve cero, y si el búfer no puede copiar ningún evento porque len era demasiado pequeño, se devuelve -1.

VALOR DE RETORNO

kbuffer_read_event() devuelve el evento en el que se encuentra actualmente el descriptor kbuf, o NULL si se ha pasado el último evento (por kbuffer_next_event()).

kbuffer_next_event() devuelve el siguiente evento después del evento actual o NULL si no hay más eventos.

kbuffer_read_at_offset() devuelve el evento en un offset dado desde el inicio del sub-búfer almacenado en kbuf, o NULL si no existe ningún evento. Tenga en cuenta que offset solo necesita ser un offset que apunte al registro, o esté al principio del mismo. No necesita estar exactamente al principio del registro.

kbuffer_missed_events() devuelve 0 si no hubo eventos perdidos antes del sub-búfer cargado. Devuelve -1 si hubo un número desconocido de eventos perdidos, o si el número de eventos perdidos se conoce, se devolverá ese número.

kbuffer_event_size() devuelve el tamaño de la carga útil de datos del evento actual de kbuf.

kbuffer_curr_size() devuelve el tamaño del registro completo del evento actual de kbuf. Esto incluye el tamaño de los metadatos de ese registro.

kbuf_curr_offset() devuelve el offset del registro actual desde el principio del sub-búfer de kbuf.

kbuf_curr_index() devuelve el índice del registro actual desde el principio de la sección de datos de kbuf.

kbuf_read_buffer() devuelve el índice del final del último evento que se llenó en buffer. Si no hay más eventos que copiar desde start, se devuelve 0. Si len no es lo suficientemente grande para contener ningún evento, se devuelve -1.

EJEMPLO

The function kbuffer_read_event_with_size is similar to kbuffer_read_event, but it also stores the size of the event data in the location pointed to by size.

After calling either function, the current position within the buffer is updated to point to the next event. The functions kbuffer_curr_size, kbuffer_curr_offset, and kbuffer_curr_index can be used to get the size, offset, and index of the event that was just read.

RETURN VALUE

On success, kbuffer_read_event and kbuffer_read_event_with_size return a non-zero value if an event was read, and 0 if there are no more events in the buffer.

EXAMPLE

        struct kbuffer *kbuf;
        trace_timestamp_t ts;
        int event;
        int i = 0;
        int record_size, size, index, offset;
        int save_offset = 0;

        kbuf = kbuffer_new("buffer.bin");
        if (!kbuf) {
                fprintf(stderr, "Failed to create kbuffer\n");
                return -1;
        }

        event = kbuffer_read_event(kbuf, &ts);
        do {
                if (event) {
                        record_size = kbuffer_curr_size(kbuf);
                        offset = kbuffer_curr_offset(kbuf);
                        index = kbuffer_curr_index(kbuf);
                        size = kbuffer_event_size(kbuf);
                        if (i == 20)
                                save_offset = offset;
                        printf(" event %3d ts:%lld\trecord_size:%d size:%d\tindex:%d offset:%d\n",
                               i++, ts, record_size, size, index, offset);
                        event = kbuffer_next_event(kbuf, NULL);
                }
        } while (event);
        if (!event)
                printf("Finished sub buffer\n");
        if (save_offset > 0) {
                event = kbuffer_read_at_offset(kbuf, save_offset, &ts);
                if (!event) {
                        fprintf(stderr, "Funny, can't find event 20 at offset %d\n", save_offset);
                        exit(-1);
                }
                record_size = kbuffer_curr_size(kbuf);
                offset = kbuffer_curr_offset(kbuf);
                index = kbuffer_curr_index(kbuf);
                size = kbuffer_event_size(kbuf);
                printf("\n saved event 20 ts:%lld\trecord_size:%d size:%d\tindex:%d offset:%d\n\n",
                       ts, record_size, size, index, offset);
        }
        kbuffer_free(kbuf);
        return 0;
