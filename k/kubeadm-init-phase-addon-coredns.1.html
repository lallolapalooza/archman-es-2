NOMBRE

kubeadm init phase addon coredns - Instala el complemento CoreDNS en un clúster de Kubernetes

SINOPSIS

kubeadm init phase addon coredns [OPCIONES]

DESCRIPCIÓN

Instala los componentes del complemento CoreDNS a través del servidor API. Tenga en cuenta que, aunque el servidor DNS se implementa, no se programará hasta que se instale CNI.

OPCIONES

--config="" Ruta a un archivo de configuración de kubeadm.

--dry-run=false No aplicar ningún cambio; solo mostrar lo que se haría.

--feature-gates="" Un conjunto de pares clave=valor que describen las puertas de características para varias funciones. Las opciones son: ControlPlaneKubeletLocalMode=true|false (BETA - predeterminado=true) NodeLocalCRISocket=true|false (BETA - predeterminado=true) PublicKeysECDSA=true|false (OBSOLETO - predeterminado=false) RootlessControlPlane=true|false (ALPHA - predeterminado=false) WaitForAllControlPlaneComponents=true|false (predeterminado=true)

--image-repository="registry.k8s.io" Elegir un repositorio de contenedores para descargar las imágenes del plano de control

--kubeconfig="/etc/kubernetes/admin.conf" El archivo kubeconfig a usar al comunicarse con el clúster. Si la bandera no está establecida, se puede buscar un archivo kubeconfig existente en una serie de ubicaciones estándar.

--kubernetes-version="stable-1" Elegir una versión específica de Kubernetes para el plano de control.

--print-manifest=false Imprimir las plantillas del complemento en STDOUT en lugar de instalarlas

--service-cidr="10.96.0.0/12" Usar un rango alternativo de direcciones IP para las VIP de servicios.

--service-dns-domain="cluster.local" Usar un dominio alternativo para los servicios, por ejemplo, "myorg.internal".

OPCIONES HEREDADAS DE COMANDOS PADRE

--rootfs="" La ruta al sistema de archivos raíz 'real' del host. Esto hará que kubeadm realice un chroot en la ruta proporcionada.

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión informada
