NOMBRE

kresd - Resolutor Knot completo con caché y habilitado para DNSSEC 5.7.5.

SINOPSIS

kresd [-a|--addr dir[@puerto]] [-t|--tls dir[@puerto]] [-S|--fd descriptor] [-T|--tlsfd descriptor] [-c|--config configuración] [-n|--noninteractive] [-q|--quiet] [-v|--verbose] [-V|--version] [-h|--help] [directorio de ejecución]

DESCRIPCIÓN

Knot Resolver es un resolutor completo con caché y habilitado para DNSSEC.

Modo de operación por defecto: cuando recibe una consulta DNS, pregunta iterativamente a los servidores de nombres autoritativos comenzando desde la zona raíz (.) y terminando con los servidores de nombres autoritativos para el nombre consultado. DNSSEC automático significa verificación de la integridad de las respuestas autoritativas siguiendo las claves y firmas a partir de la raíz. El ancla de confianza raíz se inicia automáticamente desde IANA, o puede proporcionar un archivo con anclas de confianza raíz (mismo formato que el archivo de claves raíz de Unbound o BIND9).

El demonio también almacena en caché las respuestas intermedias en la caché, que por defecto utiliza una base de datos de mapeo de memoria LMDB. Esto tiene una ventaja significativa sobre las cachés en memoria, ya que el proceso puede detenerse y reiniciarse sin pérdida de entradas de caché. En escenarios de múltiples usuarios, una caché compartida puede ser un problema de privacidad/seguridad; con kresd, cada usuario puede tener un resolutor de caché en su directorio privado y usarlo de manera similar a un llavero.

Para usar un kresd ejecutándose localmente para la resolución, coloque

nameserver 127.0.0.1

en resolv.conf(5) y inicie kresd

El demonio también puede configurarse como un simple reenviador utilizando políticas de consulta. Esto requiere el uso de un archivo de configuración. Por favor, consulte la documentación para ver las opciones del archivo de configuración. Está disponible en https://knot-resolver.readthedocs.io o en la documentación del paquete (disponible como paquete knot-resolver-doc en la mayoría de las distribuciones).

Las opciones de línea de comandos disponibles son:

-a dir[@puerto], --addr=<dir[@puerto]>
Escucha en el par de dirección (y puerto) dado. Si no se proporciona puerto, se utiliza 53 como predeterminado. La opción puede pasarse varias veces para escuchar en más direcciones.
-t dir[@puerto], --tls=<dir[@puerto]>
Escucha usando TLS en el par de dirección (y puerto) dado. Si no se proporciona puerto, se utiliza 853 como predeterminado. La opción puede pasarse varias veces para escuchar en más direcciones.
-S descriptor, --fd=<descriptor>
Escucha en los descriptores de archivo dados, pasados por el supervisor. La opción puede pasarse varias veces para escuchar en más descriptores de archivo.
-T descriptor, --tlsfd=<descriptor>
Escucha usando TLS en los descriptores de archivo dados, pasados por el supervisor. La opción puede pasarse varias veces para escuchar en más descriptores de archivo.
-c configuración, --config=<configuración>
Establece el archivo de configuración con ajustes para que kresd lea en lugar de leer el archivo en la ubicación predeterminada (configuración).
-f N, --forks=<N>
¡Esta opción está obsoleta desde la versión 5.0.0!

Con esta opción, el demonio se inicia en modo no interactivo y en su lugar crea un socket UNIX en directorio de ejecución al que el operador puede conectarse para una sesión interactiva. Un número mayor que 1 bifurca el demonio N veces, todas las bifurcaciones se enlazarán a las mismas direcciones y el kernel equilibrará la carga entre ellas en Linux con soporte para SO_REUSEPORT.

Si desea que varios procesos concurrentes sean supervisados de esta manera, deben ser supervisados de forma independiente (ver kresd.systemd(7)).

-n, --noninteractive
El demonio se abstendrá de entrar en un ciclo de lectura-evaluación-impresión para stdin+stdout.
-q, --quiet
El demonio se abstendrá de imprimir el prompt del comando.
-v, --verbose
Aumenta el registro al nivel de depuración.
-h
Muestra ayuda breve de las opciones de línea de comandos.
-V
Muestra la versión.
