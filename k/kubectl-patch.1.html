NOMBRE

kubectl patch - Actualiza campos de un recurso

SINOPSIS

kubectl patch [OPCIONES]

DESCRIPCIÓN

Actualiza campos de un recurso utilizando un parche de fusión estratégico, un parche de fusión JSON o un parche JSON.

Se aceptan formatos JSON y YAML.

Nota: El parche de fusión estratégico no es compatible con recursos personalizados.

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--dry-run="none" Debe ser "none", "server" o "client". Si es estrategia cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si es estrategia servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--field-manager="kubectl-patch" Nombre del gestor utilizado para rastrear la propiedad de los campos.

-f, --filename=[] Nombre de archivo, directorio o URL a archivos que identifican el recurso a actualizar

-k, --kustomize="" Procesa el directorio kustomization. Esta bandera no se puede usar junto con -f o -R.

--local=false Si es verdadero, el parche operará sobre el contenido del archivo, no sobre el recurso del lado del servidor.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

-p, --patch="" El parche a aplicar al archivo JSON del recurso.

--patch-file="" Un archivo que contiene un parche a aplicar al recurso.

--record=false Registra el comando kubectl actual en la anotación del recurso. Si se establece en falso, no registra el comando. Si se establece en verdadero, registra el comando. Si no se establece, por defecto actualiza el valor de la anotación existente solo si ya existe uno.

-R, --recursive=false Procesa el directorio utilizado en -f, --filename recursivamente. Útil cuando se desean gestionar manifiestos relacionados organizados dentro del mismo directorio.

--show-managed-fields=false Si es verdadero, conserva los managedFields al imprimir objetos en formato JSON o YAML.

--subresource="" Si se especifica, el parche operará sobre el subrecurso del objeto solicitado.

--template="" Cadena de plantilla o ruta a un archivo de plantilla a utilizar cuando -o=go-template, -o=go-template-file. El formato de plantilla es plantillas de golang [http://golang.org/pkg/text/template/#pkg-overview].

--type="strategic" El tipo de parche proporcionado; uno de [json merge strategic]

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario regular o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a utilizar

--context="" El nombre del contexto de kubeconfig a utilizar

--disable-compression=false Si es verdadero, desactiva la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará en cuanto a su validez. Esto hará que sus conexiones HTTPS no sean seguras.

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para solicitudes CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funciones KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud CLI

--password="" Contraseña para autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" La duración de tiempo a esperar antes de rendirse en una única solicitud del servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa que no se agoten las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor.

--token="" Token de portador para autenticación al servidor API

--user="" El nombre del usuario de kubeconfig a utilizar

--username="" Nombre de usuario para autenticación básica al servidor API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión reportada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero.

EJEMPLO

  # Actualiza parcialmente un nodo usando un parche de fusión estratégico, especificando el parche como JSON
  kubectl patch node k8s-node-1 -p '{"spec":{"unschedulable":true}}'
  # Actualiza parcialmente un nodo usando un parche de fusión estratégico, especificando el parche como YAML
  kubectl patch node k8s-node-1 -p $'spec:\n unschedulable: true'
  # Actualiza parcialmente un nodo identificado por el tipo y nombre especificados en "node.json" usando parche de fusión estratégico
  kubectl patch -f node.json -p '{"spec":{"unschedulable":true}}'
  # Actualiza la imagen de un contenedor; spec.containers[*].name es requerido porque es una clave de fusión
  kubectl patch pod valid-pod -p '{"spec":{"containers":[{"name":"kubernetes-serve-hostname","image":"new image"}]}}'
  # Actualiza la imagen de un contenedor usando un parche JSON con arrays posicionales
  kubectl patch pod valid-pod --type='json' -p='[{"op": "replace", "path": "/spec/containers/0/image", "value":"new image"}]'
  # Actualiza las réplicas de un deployment a través del subrecurso 'scale' usando un parche de fusión
  kubectl patch deployment nginx-deployment --subresource='scale' --type='merge' -p '{"spec":{"replicas":2}}'
