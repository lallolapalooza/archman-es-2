kubectl-apply-set-last-applied(1)

Paquete: kubectl

Licencias: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

NOMBRE

kubectl apply set-last-applied - Establece la anotación last-applied-configuration en un objeto en vivo para que coincida con el contenido de un archivo

SINOPSIS

kubectl apply set-last-applied [OPCIONES]

DESCRIPCIÓN

Establece las últimas anotaciones de configuración aplicada, estableciéndolas para que coincidan con el contenido de un archivo. Esto resulta en que la configuración aplicada más reciente se actualice como si se hubiera ejecutado 'kubectl apply -f ', sin actualizar ninguna otra parte del objeto.

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--create-annotation=false Creará anotaciones 'last-applied-configuration' si el objeto actual no tiene una

--dry-run="none" Debe ser "none", "server" o "client". Si la estrategia es del cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si la estrategia es del servidor, envía una solicitud del lado del servidor sin persistir el recurso.

-f, --filename=[] Nombre de archivo, directorio o URL a archivos que contienen las anotaciones last-applied-configuration

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--show-managed-fields=false Si es verdadero, conserva los campos administrados al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a un archivo de plantilla para usar cuando -o=go-template, -o=go-template-file. El formato de plantilla son plantillas golang [http://golang.org/pkg/text/template/#pkg-overview].

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario podría ser un usuario regular o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, este flag se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad certificadora

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a usar

--context="" El nombre del contexto de kubeconfig a usar

--disable-compression=false Si es verdadero, excluye la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará en cuanto a su validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes de CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para las preferencias. Esto se puede deshabilitar exportando el feature gate KUBECTL_KUBERC=false o desactivando el feature KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud de CLI

--password="" Contraseña para autenticación básica al servidor de la API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" La cantidad de tiempo a esperar antes de renunciar a una solicitud individual al servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de espera de las solicitudes.

-s, --server="" La dirección y el puerto del servidor de la API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor

--token="" Token Bearer para autenticación al servidor de la API

--user="" El nombre del usuario de kubeconfig a usar

--username="" Nombre de usuario para autenticación básica al servidor de la API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión informada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero

EJEMPLO

  # Establece la configuración aplicada más reciente para que coincida con el contenido de un archivo
  kubectl apply set-last-applied -f deploy.yaml
  # Ejecuta set-last-applied contra cada archivo de configuración en un directorio
  kubectl apply set-last-applied -f path/
  # Establece la configuración aplicada más reciente de un recurso para que coincida con el contenido de un archivo; creará la anotación si aún no existe
  kubectl apply set-last-applied -f deploy.yaml --create-annotation=true
