kubectl-create-rolebinding(1)

Paquete: kubectl

Licencias: Apache-2.0

KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Ene 2015

NOMBRE

kubectl create rolebinding - Crea un role binding para un rol o cluster role particular

SINOPSIS

kubectl create rolebinding [OPCIONES]

DESCRIPCIÓN

Crea un role binding para un rol o cluster role particular.

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando un campo o clave de mapa falta en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--clusterrole="" ClusterRole al que este RoleBinding debería hacer referencia

--dry-run="none" Debe ser "none", "server", o "client". Si es estrategia de cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si es estrategia de servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--field-manager="kubectl-create" Nombre del gestor utilizado para rastrear la propiedad de los campos.

--group=[] Grupos a vincular al rol. La bandera se puede repetir para añadir múltiples grupos.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--role="" Rol al que este RoleBinding debería referirse

--save-config=false Si es verdadero, la configuración del objeto actual se guardará en su anotación. De lo contrario, la anotación no se modificará. Esta bandera es útil cuando deseas realizar kubectl apply sobre este objeto en el futuro.

--serviceaccount=[] Cuentas de servicio a vincular al rol, en el formato :. La bandera se puede repetir para añadir múltiples cuentas de servicio.

--show-managed-fields=false Si es verdadero, conserva los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a un archivo de plantilla para usar cuando -o=go-template, -o=go-template-file. El formato de plantilla son plantillas de golang [http://golang.org/pkg/text/template/#pkg-overview].

--user=[] Nombres de usuario a vincular al rol. La bandera se puede repetir para añadir múltiples usuarios.

--validate="strict" Debe ser uno de: strict (o true), warn, ignore (o false). "true" o "strict" usarán un esquema para validar la entrada y fallarán la solicitud si es inválida. Realizará validación del lado del servidor si ServerSideFieldValidation está habilitado en el api-server, pero recurrirá a una validación del lado del cliente menos confiable si no. "warn" advertirá sobre campos desconocidos o duplicados sin bloquear la solicitud si la validación de campos del lado del servidor está habilitada en el servidor de API, y se comportará como "ignore" de lo contrario. "false" o "ignore" no realizarán ninguna validación de esquema, descartando silenciosamente cualquier campo desconocido o duplicado.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario regular o una cuenta de servicio en un espacio de nombres.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a usar

--context="" El nombre del contexto de kubeconfig a usar

--disable-compression=false Si es verdadero, desactiva la compresión de respuestas para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará en cuanto a validez. Esto hará que tus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes de la CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para preferencias. Esto puede ser deshabilitado exportando la puerta de enlace de funcionalidad KUBECTL_KUBERC=false o desactivando la funcionalidad KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del espacio de nombres para esta solicitud de CLI

--password="" Contraseña para la autenticación básica al servidor de API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo en el que escribir el perfil

--request-timeout="0" La duración de tiempo a esperar antes de renunciar a una solicitud de servidor individual. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de las solicitudes.

-s, --server="" La dirección y el puerto del servidor de API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor

--token="" Token de portador para la autenticación al servidor de API

--username="" Nombre de usuario para la autenticación básica al servidor de API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión reportada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero

EJEMPLO

  # Crea un role binding para los usuarios user1, user2 y el grupo group1 usando el cluster role admin
  kubectl create rolebinding admin --clusterrole=admin --user=user1 --user=user2 --group=group1
  # Crea un role binding para la cuenta de servicio monitoring:sa-dev usando el rol admin
  kubectl create rolebinding admin-binding --role=admin --serviceaccount=monitoring:sa-dev
