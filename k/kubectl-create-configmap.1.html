NOMBRE

kubectl create configmap - Crea un configmap a partir de un archivo local, directorio o valor literal

SINOPSIS

kubectl create configmap [OPCIONES]

DESCRIPCIÓN

Crea un configmap basado en un archivo, directorio o valor literal especificado.

Un solo configmap puede empaquetar uno o más pares clave/valor.

Al crear un configmap basado en un archivo, la clave por defecto será el nombre base del archivo, y el valor por defecto será el contenido del archivo. Si el nombre base es una clave inválida, puedes especificar una clave alternativa.

Al crear un configmap basado en un directorio, cada archivo cuyo nombre base sea una clave válida en el directorio será empaquetado en el configmap. Se ignorarán todas las entradas del directorio excepto los archivos regulares (por ejemplo, subdirectorios, enlaces simbólicos, dispositivos, tuberías, etc.).

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando un campo o clave de mapa falta en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--append-hash=false Añade un hash del configmap a su nombre.

--dry-run="none" Debe ser "none", "server" o "client". Si la estrategia es cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si la estrategia es servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--field-manager="kubectl-create" Nombre del gestor utilizado para rastrear la propiedad de los campos.

--from-env-file=[] Especifica la ruta a un archivo para leer líneas de pares clave=valor para crear un configmap.

--from-file=[] La clave del archivo puede especificarse utilizando su ruta de archivo, en cuyo caso el nombre base del archivo se usará como clave del configmap, o opcionalmente con una clave y ruta de archivo, en cuyo caso se usará la clave dada. Especificar un directorio iterará cada archivo con nombre en el directorio cuyo nombre base sea una clave de configmap válida.

--from-literal=[] Especifica una clave y un valor literal para insertar en el configmap (es decir, mijave=algunvalor)

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--save-config=false Si es verdadero, la configuración del objeto actual se guardará en su anotación. De lo contrario, la anotación no se modificará. Este indicador es útil cuando deseas realizar kubectl apply en este objeto en el futuro.

--show-managed-fields=false Si es verdadero, mantén los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a archivo de plantilla para usar cuando -o=go-template, -o=go-template-file. El formato de plantilla es de plantillas de Go [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Debe ser uno de: strict (o true), warn, ignore (o false). "true" o "strict" usará un esquema para validar la entrada y fallará la solicitud si es inválida. Realizará validación del lado del servidor si ServerSideFieldValidation está habilitado en el api-server, pero recurrirá a una validación del lado del cliente menos confiable si no lo está. "warn" advertirá sobre campos desconocidos o duplicados sin bloquear la solicitud si la validación de campos del lado del servidor está habilitada en el servidor API, y se comportará como "ignore" de lo contrario. "false" o "ignore" no realizará ninguna validación de esquema, descartando silenciosamente cualquier campo desconocido o duplicado.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario regular o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, este indicador puede repetirse para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad certificadora

--client-certificate="" Ruta a un archivo de clave de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster kubeconfig a utilizar

--context="" El nombre del contexto kubeconfig a utilizar

--disable-compression=false Si es verdadero, excluye la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará su validez. Esto hará que tus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para solicitudes CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para preferencias. Esto puede ser deshabilitado exportando la puerta de enlace de función KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud CLI

--password="" Contraseña para la autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" La duración de tiempo a esperar antes de desistir en una única solicitud al servidor. Valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no establecer tiempo de espera para las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a usar para la validación del certificado del servidor. Si no se proporciona, se usa el nombre de host utilizado para contactar al servidor

--token="" Token Bearer para autenticación al servidor API

--user="" El nombre del usuario kubeconfig a utilizar

--username="" Nombre de usuario para la autenticación básica al servidor API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión reportada

--warnings-as-errors=false Tratar las advertencias recibidas del servidor como errores y salir con un código de salida distinto de cero

EJEMPLO

  # Crea un nuevo configmap llamado my-config basado en la carpeta bar
  kubectl create configmap my-config --from-file=ruta/a/bar
  # Crea un nuevo configmap llamado my-config con claves especificadas en lugar de nombres base de archivo en disco
  kubectl create configmap my-config --from-file=clave1=/ruta/a/bar/archivo1.txt --from-file=clave2=/ruta/a/bar/archivo2.txt
  # Crea un nuevo configmap llamado my-config con clave1=config1 y clave2=config2
  kubectl create configmap my-config --from-literal=clave1=config1 --from-literal=clave2=config2
  # Crea un nuevo configmap llamado my-config a partir de los pares clave=valor en el archivo
  kubectl create configmap my-config --from-file=ruta/a/bar
  # Crea un nuevo configmap llamado my-config a partir de un archivo env
  kubectl create configmap my-config --from-env-file=ruta/a/foo.env --from-env-file=ruta/a/bar.env
