DESCRIPCIÓ

N

La llamada al sistema kill() se puede utilizar para enviar cualquier señal a cualquier grupo de procesos o

proceso.

Si pid es positivo, entonces la señal sig se envía al proceso con el ID especificado por pid

.

Si pid es igual a 0, entonces sig se envía a todos los procesos del grupo de procesos del proceso que realiza la

llamada.

Si pid es igual a -1, entonces sig se envía a todos los procesos para los que el proceso que realiza la llamada tiene permiso para enviar señales, excepto al proceso 1 (init), pero véase más

abajo.

Si pid es menor que -1, entonces sig se envía a todos los procesos del grupo de procesos cuyo ID es -pid

.

Si sig es 0, no se envía ninguna señal, pero aún se realizan comprobaciones de existencia y permisos; esto se puede usar para comprobar la existencia de un ID de proceso o un ID de grupo de procesos para el que el solicitante tiene permiso para enviar

señales.

Para que un proceso tenga permiso para enviar una señal, debe ser privilegiado (en Linux: tener la capacidad CAP_KILL en el espacio de nombres de usuario del proceso de destino), o el ID de usuario real o efectivo del proceso que envía debe ser igual al ID de usuario real o guardado del proceso de destino. En el caso de SIGCONT, es suficiente con que los procesos que envían y reciben pertenezcan a

la misma sesión. (Históricamente, las reg
las eran diferentes; véase HISTORIA.)

Notas sobre

Linux

En diferentes versiones del núcleo, Linux ha aplicado diferentes reglas sobre los permisos requeridos para que un proceso no privilegiado envíe una señal a otro

proceso. En Linux 1.0 hasta 1.2.2, se podía enviar una señal si el ID de usuario efectivo del emisor coincidía con el ID de usuario efectivo del destino, o si
el ID de usuario real del emisor coincidía con el ID de usuario real del destino. Desde Linux 1.2.3 hasta 1.3.77, se podía enviar una señal si el ID de usuari
o efectivo del emisor coincidía con el ID de usuario real o efectivo del destino. Las reglas actuales, que se ajustan a POSIX.1, se adoptaron en Linux 1.3.78.

NOTA

S

Las únicas señales que se pueden enviar al ID de proceso 1, el proceso init, son aquellas para las que init ha instalado explícitamente manejadores de señales. Esto se hace para asegurar que el sistema no se apague accidentalmente

.

POSIX.1 requiere que kill(-1,sig) envíe sig a todos los procesos a los que el proceso que realiza la llamada pueda enviar señales, excepto posiblemente a algunos procesos del sistema definidos por la implementación. Linux permite que un proceso se señale a sí mismo, pero en Linux la llamada kill(-1,sig) no señala al proceso que realiza la

llamada.

POSIX.1 requiere que si un proceso se envía una señal a sí mismo, y el hilo que envía no tiene la señal bloqueada, y ningún otro hilo la tiene desbloqueada o está esperándola en sigwait(3), al menos una señal desbloqueada debe ser entregada al hilo que envía antes de que kill() r

eto
rne.
