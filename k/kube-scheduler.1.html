KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Jan 2015

NOMBRE

kube-scheduler -

SINOPSIS

kube-scheduler [OPCIONES]

DESCRIPCIÓN

El planificador de Kubernetes es un proceso del plano de control que asigna Pods a Nodos. El planificador determina qué Nodos son ubicaciones válidas para cada Pod en la cola de planificación de acuerdo con las restricciones y los recursos disponibles. Luego, el planificador clasifica cada Nodo válido y enlaza el Pod a un Nodo adecuado. Se pueden utilizar múltiples planificadores diferentes dentro de un clúster; kube-scheduler es la implementación de referencia. Consulte planificación ⟨https://kubernetes.io/docs/concepts/scheduling-eviction/⟩ para obtener más información sobre la planificación y el componente kube-scheduler.

--disabled-metrics=[] Esta opción proporciona una vía de escape para métricas que se comportan mal. Debe proporcionar el nombre de métrica completamente calificado para deshabilitarla. Descargo de responsabilidad: deshabilitar métricas tiene mayor precedencia que mostrar métricas ocultas.

-h, --help=false ayuda para kube-scheduler

--http2-max-streams-per-connection=0 El límite que el servidor otorga a los clientes para el número máximo de flujos en una conexión HTTP/2. Cero significa usar el valor predeterminado de golang.

--kube-api-burst=100 DEPRECADO: ráfaga a usar al comunicarse con el servidor de API de kubernetes. Este parámetro se ignora si se especifica un archivo de configuración en --config.

--kube-api-content-type="application/vnd.kubernetes.protobuf" DEPRECADO: tipo de contenido de las solicitudes enviadas al servidor de API. Este parámetro se ignora si se especifica un archivo de configuración en --config.

--kube-api-qps=50 DEPRECADO: QPS a usar al comunicarse con el servidor de API de kubernetes. Este parámetro se ignora si se especifica un archivo de configuración en --config.

--kubeconfig="" DEPRECADO: ruta al archivo kubeconfig con información de autorización y ubicación del maestro. Este parámetro se ignora si se especifica un archivo de configuración en --config.

--leader-elect=true Inicia un cliente de elección de líder y obtiene el liderazgo antes de ejecutar el bucle principal. Habilite esto al ejecutar componentes replicados para alta disponibilidad.

--leader-elect-lease-duration=15s La duración que los candidatos no líderes esperarán después de observar una renovación de liderazgo antes de intentar adquirir el liderazgo de un espacio de líder asignado pero no renovado. Esta es efectivamente la duración máxima que un líder puede ser detenido antes de ser reemplazado por otro candidato. Esto solo es aplicable si la elección de líder está habilitada.

--leader-elect-renew-deadline=10s El intervalo entre los intentos del maestro en ejercicio de renovar un espacio de liderazgo antes de que deje de liderar. Esto debe ser menor que la duración del arrendamiento. Esto solo es aplicable si la elección de líder está habilitada.

--leader-elect-resource-lock="leases" El tipo de objeto de recurso que se utiliza para el bloqueo durante la elección de líder. Las opciones admitidas son 'leases'.

--leader-elect-resource-name="kube-scheduler" El nombre del objeto de recurso que se utiliza para el bloqueo durante la elección de líder.

--leader-elect-resource-namespace="kube-system" El espacio de nombres del objeto de recurso que se utiliza para el bloqueo durante la elección de líder.

--leader-elect-retry-period=2s La duración que los clientes deben esperar entre los intentos de adquisición y renovación de un liderazgo. Esto solo es aplicable si la elección de líder está habilitada.

--log-flush-frequency=5s Número máximo de segundos entre descargas de registros

--log-text-info-buffer-size=0 [Alpha] En formato de texto con flujos de salida divididos, los mensajes de información pueden almacenarse en búfer durante un tiempo para aumentar el rendimiento. El valor predeterminado de cero bytes deshabilita el almacenamiento en búfer. El tamaño se puede especificar como número de bytes (512), múltiplos de 1000 (1K), múltiplos de 1024 (2Ki) o potencias de estos (3M, 4G, 5Mi, 6Gi). Habilite la puerta de enlace de funciones LoggingAlphaOptions para usar esto.

--log-text-split-stream=false [Alpha] En formato de texto, escribe mensajes de error en stderr y mensajes de información en stdout. El predeterminado es escribir un único flujo en stdout. Habilite la puerta de enlace de funciones LoggingAlphaOptions para usar esto.

--logging-format="text" Establece el formato del registro. Formatos permitidos: "text".

--master="" La dirección del servidor de API de Kubernetes (anula cualquier valor en kubeconfig)

--permit-address-sharing=false Si es verdadero, se usará SO_REUSEADDR al enlazar el puerto. Esto permite enlazar a IPs comodín como 0.0.0.0 e IPs específicas en paralelo, y evita esperar a que el kernel libere los sockets en estado TIME_WAIT. [por defecto=false]

--permit-port-sharing=false Si es verdadero, se usará SO_REUSEPORT al enlazar el puerto, lo que permite que más de una instancia se enlace a la misma dirección y puerto. [por defecto=false]

--pod-max-in-unschedulable-pods-duration=5m0s DEPRECADO: el tiempo máximo que un pod puede permanecer en unschedulablePods. Si un pod permanece en unschedulablePods durante más tiempo que este valor, el pod se moverá de unschedulablePods a backoffQ o activeQ. Esta bandera está obsoleta y se eliminará en una versión futura.

--profiling=true DEPRECADO: habilita la generación de perfiles a través de la interfaz web host:port/debug/pprof/. Este parámetro se ignora si se especifica un archivo de configuración en --config.

--requestheader-allowed-names=[] Lista de nombres comunes de certificados de cliente permitidos para proporcionar nombres de usuario en los encabezados especificados por --requestheader-username-headers. Si está vacío, se permite cualquier certificado de cliente validado por las autoridades en --requestheader-client-ca-file.

--requestheader-client-ca-file="" Paquete de certificados raíz a utilizar para verificar los certificados de cliente en las solicitudes entrantes antes de confiar en los nombres de usuario en los encabezados especificados por --requestheader-username-headers. ADVERTENCIA: generalmente no dependa de que la autorización ya se haya realizado para las solicitudes entrantes.

--requestheader-extra-headers-prefix=[x-remote-extra-] Lista de prefijos de encabezados de solicitud a inspeccionar. X-Remote-Extra- es sugerido.

--requestheader-group-headers=[x-remote-group] Lista de encabezados de solicitud a inspeccionar para grupos. X-Remote-Group es sugerido.

--requestheader-uid-headers=[] Lista de encabezados de solicitud a inspeccionar para UIDs. X-Remote-Uid es sugerido. Requiere que la función RemoteRequestHeaderUID esté habilitada.

--requestheader-username-headers=[x-remote-user] Lista de encabezados de solicitud a inspeccionar para nombres de usuario. X-Remote-User es común.

--secure-port=10259 El puerto en el que servir HTTPS con autenticación y autorización. Si es 0, no sirva HTTPS en absoluto.

--show-hidden-metrics-for-version="" La versión anterior para la que desea mostrar métricas ocultas. Solo la versión menor anterior es significativa, otros valores no estarán permitidos. El formato es ., por ejemplo: '1.16'. El propósito de este formato es asegurarse de que tenga la oportunidad de notar si la próxima versión oculta métricas adicionales, en lugar de ser sorprendido cuando se eliminen permanentemente en la versión posterior.

--tls-cert-file="" Archivo que contiene el Certificado x509 predeterminado para HTTPS. (Certificado CA, si lo hay, concatenado después del certificado del servidor).
