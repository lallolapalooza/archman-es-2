NOMBRE

kpropd - Servidor de actualización de KDC de réplica Kerberos V5

SINOPSIS

kpropd [-r realm] [-A servidor_admin] [-a archivo_acl] [-f archivo_volcado_replica] [-F base_datos_principal] [-p programa_kdb5_util] [-P puerto] [--pid-file=archivo_pid] [-D] [-d] [-s archivo_keytab]

DESCRIPCIÓN

El comando kpropd se ejecuta en el KDC de réplica. Escucha las solicitudes de actualización realizadas por el programa kprop(8). Si la propagación incremental está habilitada, solicita periódicamente actualizaciones incrementales al KDC principal.

Cuando la réplica recibe una solicitud de kprop del principal, kpropd acepta la base de datos KDC volcada y la coloca en un archivo, y luego ejecuta kdb5_util(8) para cargar la base de datos volcada en la base de datos activa que utiliza krb5kdc(8). Esto permite al servidor Kerberos principal utilizar kprop(8) para propagar su base de datos a los servidores réplica. Tras una descarga exitosa del archivo de base de datos KDC, el servidor Kerberos réplica tendrá una base de datos KDC actualizada.

Donde no se utiliza la propagación incremental, kpropd se invoca comúnmente desde inetd(8) como un servicio nowait. Esto se hace agregando una línea al archivo /etc/inetd.conf que se ve así:

 kprop  stream  tcp  nowait  root  /usr/local/sbin/ kpropd  kpropd

kpropd también puede ejecutarse como un demonio independiente, poniéndose en segundo plano y esperando conexiones en el puerto 754 (o el puerto especificado con la opción -P si se proporciona). El modo independiente es necesario para la propagación incremental. A partir de la versión 1.11, kpropd detecta automáticamente si fue ejecutado desde inetd y se ejecuta en modo independiente si no lo fue. Antes de la versión 1.11, la opción -S es necesaria para ejecutar kpropd en modo independiente; esta opción ahora se acepta por compatibilidad con versiones anteriores pero no hace nada.

La propagación incremental puede habilitarse con la variable iprop_enable en kdc.conf(5). Si la propagación incremental está habilitada, la réplica consulta periódicamente al KDC principal para obtener actualizaciones, a un intervalo determinado por la variable iprop_replica_poll. Si la réplica recibe actualizaciones, kpropd actualiza su archivo de registro con cualquier actualización del KDC principal. kproplog(8) puede usarse para ver un resumen del registro de entradas de actualización en el KDC réplica. Si la propagación incremental está habilitada, el principal kiprop/nombre_host_replica@REALM (donde nombre_host_replica es el nombre del host KDC réplica y REALM es el nombre del realm Kerberos) debe estar presente en el archivo keytab de la réplica.

kproplog(8) puede usarse para forzar la replicación completa cuando iprop está habilitado.

OPCIONES

-r realm
Especifica el realm del servidor principal.
-A servidor_admin
Especifica el servidor al que se contactará para actualizaciones incrementales; por defecto, se contactará al servidor de administración principal.
-f archivo
Especifica el nombre del archivo donde se almacenará el archivo de base de datos principal volcada; por defecto, el archivo de base de datos volcada es /var/lib/krb5kdc/from_master.
-F krb5_db
Ruta al archivo de base de datos Kerberos, si no es la predeterminada.
-p
Permite al usuario especificar la ruta al programa kdb5_util(8); por defecto, la ruta utilizada es /usr/bin/kdb5_util.
-D
En este modo, kpropd no se separará del trabajo actual y se ejecutará en segundo plano. En su lugar, se ejecutará en primer plano.
-d
Activa el modo de depuración. kpropd imprimirá mensajes de depuración durante la propagación de la base de datos y se ejecutará en primer plano (implica -D).
-P
Permite un número de puerto alternativo para que kpropd escuche. Esto solo es útil en combinación con la opción -S.
-a archivo_acl
Permite al usuario especificar la ruta al archivo kpropd.acl; por defecto, la ruta utilizada es /var/lib/krb5kdc/ kpropd.acl.
--pid-file=archivo_pid
En modo independiente, escribe el ID del proceso del demonio en archivo_pid.
-s archivo_keytab
Ruta a un archivo keytab para usar en la adquisición de credenciales de aceptor.
-x args_db
Argumentos específicos de la base de datos. Consulte Opciones de base de datos en kadmin(1) para los argumentos compatibles.

ARCHIVOS

kpropd.acl
Archivo de acceso para kpropd; la ubicación predeterminada es /usr/local/var/krb5kdc/ kpropd.acl. Cada entrada es una línea que contiene el principal de un host desde el cual la máquina local permitirá la propagación de la base de datos Kerberos a través de kprop(8).

ENTORNO

Consulte kerberos(7) para una descripción de las variables de entorno de Kerberos.

VEASE TAMBIÉN

kprop(8), kdb5_util(8), krb5kdc(8), kerberos(7), inetd(8)
