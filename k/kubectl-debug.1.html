NOMBRE

kubectl debug - Crear sesiones de depuración para solucionar problemas de cargas de trabajo y nodos

SINOPSIS

kubectl debug [OPCIONES]

DESCRIPCIÓN

Depure recursos del clúster utilizando contenedores de depuración interactivos.

'debug' proporciona automatización para tareas de depuración comunes para objetos del clúster identificados por recurso y nombre. Los Pods se utilizarán por defecto si no se especifica ningún recurso.

La acción que realiza 'debug' varía según el recurso especificado. Las acciones compatibles incluyen:

  • Carga de trabajo: Crear una copia de un Pod existente con ciertos atributos modificados, por ejemplo, cambiar la etiqueta de la imagen a una nueva versión.
  • Carga de trabajo: Añadir un contenedor efímero a un Pod que ya se está ejecutando, por ejemplo, para añadir utilidades de depuración sin reiniciar el Pod.
  • Nodo: Crear un nuevo Pod que se ejecute en los espacios de nombres del host del nodo y pueda acceder al sistema de archivos del nodo.

Nota: Cuando se configura un usuario no root para todo el Pod de destino, algunas capacidades concedidas por el perfil de depuración pueden no funcionar.

OPCIONES

--arguments-only=false Si se especifica, todo lo que siga a -- se pasará al nuevo contenedor como Args en lugar de Command.

--attach=false Si es verdadero, espere a que el contenedor comience a ejecutarse y luego adjúntelo como si se hubiera llamado a 'kubectl attach ...'. Por defecto es falso, a menos que se establezca '-i/--stdin', en cuyo caso el valor predeterminado es verdadero.

-c, --container="" Nombre del contenedor a utilizar para el contenedor de depuración.

--copy-to="" Crea una copia del Pod de destino con este nombre.

--custom="" Ruta a un archivo JSON o YAML que contiene una especificación de contenedor parcial para personalizar los perfiles de depuración integrados.

--env=[] Variables de entorno a establecer en el contenedor.

-f, --filename=[] Identifica el recurso a depurar

--image="" Imagen del contenedor a utilizar para el contenedor de depuración.

--image-pull-policy="" La política de extracción de imágenes para el contenedor. Si se deja vacío, este valor no será especificado por el cliente y será predeterminado por el servidor.

--keep-annotations=false Si es verdadero, conserva las anotaciones originales del Pod. (Esta bandera solo funciona cuando se usa con '--copy-to')

--keep-init-containers=true Ejecuta los contenedores iniciales para el Pod. Predeterminado a verdadero. (Esta bandera solo funciona cuando se usa con '--copy-to')

--keep-labels=false Si es verdadero, conserva las etiquetas originales del Pod. (Esta bandera solo funciona cuando se usa con '--copy-to')

--keep-liveness=false Si es verdadero, conserva las sondas de vivacidad originales del Pod. (Esta bandera solo funciona cuando se usa con '--copy-to')

--keep-readiness=false Si es verdadero, conserva las sondas de preparación originales del Pod. (Esta bandera solo funciona cuando se usa con '--copy-to')

--keep-startup=false Si es verdadero, conserva las sondas de inicio originales del Pod. (Esta bandera solo funciona cuando se usa con '--copy-to')

--profile="legacy" Las opciones son "legacy", "general", "baseline", "netadmin", "restricted" o "sysadmin".

-q, --quiet=false Si es verdadero, suprime los mensajes informativos.

--replace=false Cuando se usa con '--copy-to', elimina el Pod original.

--same-node=false Cuando se usa con '--copy-to', programa la copia del Pod de destino en el mismo nodo.

--set-image=[] Cuando se usa con '--copy-to', una lista de pares nombre=imagen para cambiar las imágenes de los contenedores, similar a cómo funciona 'kubectl set image'.

--share-processes=true Cuando se usa con '--copy-to', habilita el intercambio de espacios de nombres de procesos en la copia.

-i, --stdin=false Mantener stdin abierto en los contenedores del Pod, incluso si nada está adjunto.

--target="" Al usar un contenedor efímero, dirige los procesos en este nombre de contenedor.

-t, --tty=false Asignar una TTY para el contenedor de depuración.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario regular o una cuenta de servicio en un espacio de nombres.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar varios grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a utilizar

--context="" El nombre del contexto de kubeconfig a utilizar

--disable-compression=false Si es verdadero, opte por no participar en la compresión de respuestas para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará en busca de validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes de CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para las preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funciones KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requerir que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del espacio de nombres para esta solicitud de CLI

--password="" Contraseña para la autenticación básica al servidor API

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" El tiempo de espera antes de renunciar a una sola solicitud del servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa que no se agotan las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor

--token="" Token de portador para la autenticación al servidor API

--user="" El nombre del usuario de kubeconfig a utilizar

--username="" Nombre de usuario para la autenticación básica al servidor API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión informada

--warnings-as-errors=false Tratar las advertencias recibidas del servidor como errores y salir con un código de salida distinto de cero

EJEMPLO

  # Crear una sesión de depuración interactiva en el pod mypod y adjuntarlo inmediatamente.
  kubectl debug mypod -it --image=busybox
  # Crear una sesión de depuración interactiva para el pod en el archivo pod.yaml y adjuntarlo inmediatamente.
  # (requiere que la función EphemeralContainers esté habilitada en el clúster)
  kubectl debug -f pod.yaml -it --image=busybox
  # Crear un contenedor de depuración llamado debugger usando una imagen de depuración automatizada personalizada.
  kubectl debug --image=myproj/debug-tools -c debugger mypod
  # Crear una copia de mypod añadiendo un contenedor de depuración y adjuntarlo
  kubectl debug mypod -it --image=busybox --copy-to=my-debugger
  # Crear una copia de mypod cambiando el comando de mycontainer
  kubectl debug mypod -it --copy-to=my-debugger --container=mycontainer -- sh
  # Crear una copia de mypod cambiando todas las imágenes de contenedor a busybox
  kubectl debug mypod --copy-to=my-debugger --set-image=*=busybox
  # Crear una copia de mypod añadiendo un contenedor de depuración y cambiando las imágenes de contenedor
  kubectl debug mypod -it --copy-to=my-debugger --image=debian --set-image=app=app:debug,sidecar=sidecar:debug
  # Crear una sesión de depuración interactiva en un nodo y adjuntarla inmediatamente.
  # El contenedor se ejecutará en los espacios de nombres del host y el sistema de archivos del host se montará en /host
  kubectl debug node/mynode -it --image=busybox
