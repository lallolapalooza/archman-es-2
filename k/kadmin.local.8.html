ldap_util(8)

ldap_util - utilities for OpenLDAP client library.

The OpenLDAP distribution includes a set of command-line utilities for performing common LDAP operations. This document describes the options understood by the OpenLDAP client library. The options described below are common to all the OpenLDAP command-line utilities.

The OpenLDAP command-line utilities understand the following options:

-1
Use a single-shot LDAPv3 bind. This option is equivalent to using the LDAPv2 protocol, but forces the use of LDAPv3.
-A
Perform a simple bind using an empty DN and password. This is equivalent to anonymous bind.
-b basedn
Use the specified basedn as the base DN for the LDAP operations. If not specified, the base DN from the LDAP configuration file is used.
-c
Continuous operation mode. Operations continue even if errors occur.
-d level
Turn on debugging messages. level is a bitmask of the desired debugging categories. Use -d help for a list of categories.
-e extops
Request LDAP extension operations. Valid extensions include manage (manage DSA IT), psearch (persistent search), sync (sync notification), exop (generic extended operation), abandon (abandon operation), deltree (delete subtree), crwithdn (create with DN), bindd (bind with DN), moddn (modify DN), modrdn (modify RDN), and add (add entry). Use -e help for a list of extensions.
-f ldif-file
Read input from an LDIF file instead of standard input.
-F ldif-indent
Write LDIF output indented by ldif-indent spaces. Default is 1.
-g
Do not automatically add the default search base to search filters. This option is useful when the search base is explicitly specified in the filter.
-h host
Use the specified host and port for the LDAP server. If not specified, the LDAP server is read from the LDAPCONF environment variable or defaults to localhost:389.
-H url
Use the specified LDAP URL(s) for the LDAP server. Multiple URLs can be provided, separated by spaces or commas. If not specified, the LDAP server is read from the LDAPCONF environment variable or defaults to ldap://localhost:389.
-i input-file
Read input from input-file instead of standard input.
-I
Use SASL GSSAPI authentication.
-j path
Write the client ID and client key to the specified path. This option is used by ldapsearch to retrieve Kerberos tickets.
-J mech
Use the specified SASL mechanism. If not specified, the client will attempt to negotiate the best mechanism supported by both the client and server.
-l limit
Set the maximum number of entries to return for a search operation. A limit of 0 means no limit.
-m filter
Use the specified filter for search operations. If not specified, the filter is read from the standard input.
-M
Manage DSA operations.
-n
No operation. Perform the requested operation, but do not actually make any changes to the LDAP directory.
-N
Do not automatically add the default realm to SASL principal names. This option is useful when the realm is explicitly specified in the principal name.
-O options
LDAPv3 options. Options are specified as a comma-separated list. See ldap.conf(5) for a list of options.
-p port
Use the specified port for the LDAP server. If not specified, defaults to 389.
-P path
Use the specified path as the base DN for LDIF operations. This option is useful when the base DN is not specified in the LDIF file.
-Q
Quiet mode. Do not display informational messages.
-r
Recursively add entries.
-R
Referrals. Follow referrals when searching the directory.
-s scope
Use the specified scope for search operations. Valid scopes are base, one, or sub. If not specified, defaults to sub.
-S criteria
Sort search results according to the specified criteria. Criteria are specified as a comma-separated list of attribute names. Use a leading '-' to sort in reverse order.
-t time
Set the time limit for search operations. A time limit of 0 means no limit.
-T type
Use the specified type for LDIF operations. Valid types are add, delete, modify, modrdn, and moddn.
-u
Use URL format for the LDAP server. This option is equivalent to using the -H option.
-U usage
Use the specified usage for SASL authentication. Valid usages are all, dNSHost, key, plugin, rfc4120, system, and user.
-v
Verbose mode. Display informational messages.
-V version
Use the specified LDAP protocol version. Valid versions are 2 and 3.
-w password
Use the specified password for the LDAP bind operation. If not specified, the password is read from the password environment variable or prompted for.
-W
Prompt for the password for the LDAP bind operation.
-x
Use simple authentication instead of SASL authentication.
-X secret
Use the specified secret for the LDAP bind operation. This option is equivalent to the -w option.
-y mode
Use the specified mode for LDIF operations. Valid modes are append, overwrite, and update.
-Y mech
Use the specified SASL mechanism. This option is equivalent to the -J option.
-z filter
Use the specified filter for search operations. This option is equivalent to the -m option.
-Z
Use StartTLS to encrypt the connection.
-x sasl_mech=mechanism
Specifies the SASL mechanism used to bind to the LDAP server. The bind DN is ignored if a SASL mechanism is used. New in release 1.13.
-x sasl_authcid=name
Specifies the authentication name used when binding to the LDAP server with a SASL mechanism, if the mechanism requires one. New in release 1.13.
-x sasl_authzid=name
Specifies the authorization name used when binding to the LDAP server with a SASL mechanism. New in release 1.13.
-x sasl_realm=realm
Specifies the realm used when binding to the LDAP server with a SASL mechanism, if the mechanism uses one. New in release 1.13.
-x debug=level
sets the OpenLDAP client library debug level. level is an integer to be interpreted by the library. Debugging messages are printed to standard error. New in release 1.12.

add_principal

add_principal [options] newprinc

Creates the principal newprinc, prompting twice for a password. If no password policy is specified with the -policy option, and the policy named default is assigned to the principal if it exists. However, creating a policy named default will not automatically assign this policy to previously existing principals. This policy assignment can be suppressed with the -clearpolicy option.

This command requires the add privilege.

Aliases: addprinc, ank

Options:

-expire expdate
(getdate string) The expiration date of the principal.
-pwexpire pwexpdate
(getdate string) The password expiration date.
-maxlife maxlife
(duration or getdate string) The maximum ticket life for the principal.
-maxrenewlife maxrenewlife
(duration or getdate string) The maximum renewable life of tickets for the principal.
-kvno kvno
The initial key version number.
-policy policy
The password policy used by this principal. If not specified, the policy default is used if it exists (unless -clearpolicy is specified).
-clearpolicy
Prevents any policy from being assigned when -policy is not specified.
{-|+}allow_postdated
-allow_postdated prohibits this principal from obtaining postdated tickets. +allow_postdated clears this flag.
{-|+}allow_forwardable
-allow_forwardable prohibits this principal from obtaining forwardable tickets. +allow_forwardable clears this flag.
{-|+}allow_renewable
-allow_renewable prohibits this principal from obtaining renewable tickets. +allow_renewable clears this flag.
{-|+}allow_proxiable
-allow_proxiable prohibits this principal from obtaining proxiable tickets. +allow_proxiable clears this flag.
{-|+}allow_dup_skey
-allow_dup_skey disables user-to-user authentication for this principal by prohibiting others from obtaining a service ticket encrypted in this principal's TGT session key. +allow_dup_skey clears this flag.
{-|+}requires_preauth
+requires_preauth requires this principal to preauthenticate before being allowed to kinit. -requires_preauth clears this flag. When +requires_preauth is set on a service principal, the KDC will only issue service tickets for that service principal if the client's initial authentication was performed using preauthentication.
{-|+}requires_hwauth
+requires_hwauth requires this principal to preauthenticate using a hardware device before being allowed to kinit. -requires_hwauth clears this flag. When +requires_hwauth is set on a service principal, the KDC will only issue service tickets for that service principal if the client's initial authentication was performed using a hardware device to preauthenticate.
{-|+}ok_as_delegate
+ok_as_delegate sets the okay as delegate flag on tickets issued with this principal as the service. Clients may use this flag as a hint that credentials should be delegated when authenticating to the service. -ok_as_delegate clears this flag.
{-|+}allow_svr
-allow_svr prohibits the issuance of service tickets for this principal. In release 1.17 and later, user-to-user service tickets are still allowed unless the -allow_dup_skey flag is also set. +allow_svr clears this flag.
{-|+}allow_tgs_req
-allow_tgs_req specifies that a Ticket-Granting Service (TGS) request for a service ticket for this principal is not permitted. +allow_tgs_req clears this flag.
{-|+}allow_tix
-allow_tix forbids the issuance of any tickets for this principal. +allow_tix clears this flag.
{-|+}needchange
+needchange forces a password change on the next initial authentication to this principal. -needchange clears this flag.
{-|+}password_changing_service
+password_changing_service marks this principal as a password change service principal.
{-|+}ok_to_auth_as_delegate
+ok_to_auth_as_delegate allows this principal to acquire forwardable tickets to itself from arbitrary users, for use with constrained delegation.
{-|+}no_auth_data_required
+no_auth_data_required prevents PAC or AD-SIGNEDPATH data from being added to service tickets for the principal.
{-|+}lockdown_keys
+lockdown_keys prevents keys for this principal from leaving the KDC via kadmind. The chpass and extract operations are denied for a principal with this attribute. The chrand operation is allowed, but will not return the new keys. The delete and rename operations are also denied if this attribute is set, in order to prevent a malicious administrator from replacing principals like krbtgt/* or kadmin/* with new principals without the attribute. This attribute can be set via the network protocol, but can only be removed using kadmin.local.
-randkey
Sets the key of the principal to a random value.
-nokey
Causes the principal to be created with no key. New in release 1.12.
-pw password
Sets the password of the principal to the specified string and does not prompt for a password. Note: using this option in a shell script may expose the password to other users on the system via the process list.
-e enc:salt,...
Uses the specified keysalt list for setting the keys of the principal. See Keysalt_lists in kdc.conf(5) for a list of possible values.
-x db_princ_args
Indicates database-specific options. The options for the LDAP database module are:
-x dn=dn
Specifies the LDAP object that will contain the Kerberos principal being created.
-x linkdn=dn
Specifies the LDAP object to which the newly created Kerberos principal object will point.
-x containerdn=container_dn
Specifies the container object under which the Kerberos principal is to be created.
-x tktpolicy=policy
Associates a ticket policy to the Kerberos principal.

NOTE:

  • The containerdn and linkdn options cannot be specified with the dn option.
  • If the dn or containerdn options are not specified while adding the principal, the principals are created under the principal container configured in the realm or the realm container.
  • dn and containerdn should be within the subtrees or principal container configured in the realm.

kadmin Full Commands

This section describes the full commands available to the kadmin utility. These commands are used to administer the Kerberos database.

add_principal

add_principal [options] principal

Adds a new principal to the Kerberos database. The principal name is of the form user/instance@REALM.

This command requires the add privilege.

Alias: addprinc

The following options are available:

-randkey
Sets the key of the principal to a random value.
-password password
Sets the password to the specified string. If this option is not specified, kadmin will prompt for a password.
-key key
Sets the key of the principal to the specified key. The key must be specified as a hexadecimal string.
-e enc[:salt,...]
Sets the keys for the principal using the specified encryption types and salts. The default is to use all encryption types supported by the KDC. See Keysalt_lists in kdc.conf(5) for a list of possible values.
-maxlife time
(duration or getdate string) Sets the maximum lifetime of a ticket issued to this principal.
-pw_expiration time
(date or getdate string) Sets the expiration date for the principal's password.
-policy policy
Assigns a password policy to the principal. If this option is not specified, the principal is assigned the default policy.
-expiration_time time
(date or getdate string) Sets the expiration time for the principal.
-attributes +|-attribute...
Sets or unsets principal attributes. Valid attributes are:
requires_preauth
Principal must perform preauthentication.
requires_hwauth
Principal must perform hardware authentication.
support_des_mac
Supports DES MAC encryption for ticket-granting tickets.
ok_as_delegate
Allows delegation of tickets issued to this principal.
password_changing_allowed
Principal may change their own password.
password_never_expires
Principal's password never expires.
endpoints
Principal is a server that supports endpoint-independent tickets.
allow_tgs_principal
Principal may act as a TGS.
-unlock
Unlocks the principal if it has been locked due to too many failed login attempts.
-randkey kvno
Sets the key for the specified key version number (kvno) to a random value.

Example:

kadmin: add_principal -maxlife 10h -policy mypol -expiration_time 01/01/05 -attributes +requires_preauth +ok_as_delegate testuser

Verify password:
Principal added.

This command requires the inquire privilege.

set_string

set_string principal name value

Sets a string attribute on principal. String attributes are used to supply per-principal configuration to the KDC and some KDC plugin modules. The following string attribute names are recognized by the KDC:

require_auth
Specifies an authentication indicator which is required to authenticate to the principal as a service. Multiple indicators can be specified, separated by spaces; in this case any of the specified indicators will be accepted. (New in release 1.14.)
session_enctypes
Specifies the encryption types supported for session keys when the principal is authenticated to as a server. See Encryption_types in kdc.conf(5) for a list of the accepted values.
otp
Enables One Time Passwords (OTP) preauthentication for a client principal. The value is a JSON string representing an array of objects, each having optional type and username fields.
pkinit_cert_match
Specifies a matching expression that defines the certificate attributes required for the client certificate used by the principal during PKINIT authentication. The matching expression is in the same format as those used by the pkinit_cert_match option in krb5.conf(5). (New in release 1.16.)
pac_privsvr_enctype
Forces the encryption type of the PAC KDC checksum buffers to the specified encryption type for tickets issued to this server, by deriving a key from the local krbtgt key if it is of a different encryption type. It may be necessary to set this value to "aes256-sha1" on the cross-realm krbtgt entry for an Active Directory realm when using aes-sha2 keys on the local krbtgt entry.

This command requires the modify privilege.

Alias: setstr

Example:

NAME

kadmin - Kerberos 5 administration program

SYNOPSIS

kadmin [ -p principal ] [ -k ] [ -M kadmind_server ] [ -r realm ] [ -R ] [ -w ] [ -q ] [ -l ] [ -d ] [ -i ] [ -n ] [ -m ] [ -V ] [ -e ] [ -S stash_file ] [ -F ] [ -T ticket_cache ] [ -x arg ... ]

DESCRIPTION

The kadmin program is an interactive command-line interface for administering the Kerberos 5 database. It allows administrators to add, delete, and modify principals, policies, and realms.

When kadmin is invoked without arguments, it enters an interactive mode. Commands can be entered directly at the prompt. When an argument is provided, kadmin executes that single command and then exits.

Many of the commands require authentication as a principal with administrative privileges. The default administrative principal is admin/admin@REALM, where REALM is the default realm. If you specify the -p option, the principal you specify is used for authentication.

OPTIONS

-p principal
Use principal for authentication. The default is admin/admin@REALM.
-k
Use keytab authentication instead of password authentication. This requires that the principal specified with -p (or the default principal) exists in the keytab file.
-M kadmind_server
Connect to the kadmind server on host kadmind_server. The default is to use the value of the KRB5_KADMIND environment variable, or the default server specified in /etc/krb5.conf.
-r realm
Use realm as the default realm. The default is determined by libkrb5.
-R
Get the default realm from the KDC. This overrides the default realm determined by libkrb5.
-w
Print the default realm and exit.
-q
Execute a single command and exit.
-l
Lock the database exclusively. Use with caution.
-d
Use the default database. This is the default.
-i
Interactive mode. This is the default.
-n
Do not perform automatic database name resolution.
-m
Use password-based authentication.
-V
Print the Kerberos version number and exit.
-e
Print the list of available encryption types and exit.
-S stash_file
Use stash_file as the stash file for storing the Kerberos database master key.
-F
Force database checking.
-T ticket_cache
Use ticket_cache as the ticket cache.
-x arg ...
Specify implementation-specific arguments. These arguments are passed directly to the underlying database module. The available arguments depend on the database module being used. For the default (DB2) module, use -x db_name=db_name to specify the database file.

DATABASE OPTIONS

Some commands accept options that modify the behavior of the Kerberos database. These options are typically specified as arguments to the commands themselves.

COMMANDS

The following commands are available in kadmin:

add_principal

add_principal [options] principal

Adds a new principal to the Kerberos database. The principal argument specifies the name of the principal to add. The principal name should be in the format user/instance@REALM.

This command requires the add privilege.

The options are:

-maxlife lifetime
(duration) Sets the maximum lifetime for tickets issued to this principal.
-minlife lifetime
(duration) Sets the minimum lifetime for tickets issued to this principal.
-maxrenewablelife lifetime
(duration) Sets the maximum renewable lifetime for tickets issued to this principal.
-pwexpire date
(date string) Sets the expiration date for the principal's password.
-policy policy
Assigns the specified password policy to the principal.
-randkey
Generates a random key for the principal.
-password
Prompts for a password for the principal.
-keysalt enc:salt,...
Uses the specified keysalt list for setting the new keys of the principal. See Keysalt_lists in kdc.conf(5) for a list of possible values.
-expiration date
(date string) Sets the expiration date for the principal.
-max_kvno kvno
(integer) Sets the maximum key version number for the principal.
-allow_tgs_principal principal
Allows the specified principal to obtain TGS tickets for this principal.

Alias: addpol

Example:

kadmin: addprinc -maxlife "10 days" -policy himalaya -pwexpire "2005-01-01 00:00:00" jdoe
Enter password for principal jdoe@ATHENA.MIT.EDU: 
Re-enter password: 
Principal added to the Kerberos database.

modify_principal [options] principal

Modifies an existing principal in the Kerberos database. The options are the same as for add_principal.

This command requires the modify privilege.

Alias: modprinc

Example:

kadmin: modprinc -maxrenewablelife "30 days" jdoe

delete_principal [-force] principal

Deletes a principal from the Kerberos database. The -force option suppresses the confirmation prompt.

This command requires the delete privilege.

add_policy

add_policy [options] policy

Creates a new password policy named policy. Policies are used to enforce password complexity and lifetime restrictions.

This command requires the add privilege.

The options are:

-maxlife lifetime
(duration or getdate string) Sets the maximum lifetime for a password. A value of 0 (the default) means the password never expires.
-minlife lifetime
(duration or getdate string) Sets the minimum time between password changes. A value of 0 (the default) means there is no restriction.
-minlength length
(integer) Sets the minimum length for a password. The default is 6.
-maxകെycount count
(integer) Sets the number of keys kept per principal. The default is 5.
-minclasses count
(integer) Sets the minimum number of character classes required in a password. The default is 0.
-historycount count
(integer) Sets the number of passwords to keep in the history. The default is 0.
-failurecountinterval failuretime
(duration or getdate string) Sets the allowable time between authentication failures. If an authentication failure happens after failuretime has elapsed since the previous failure, the number of authentication failures is reset to 1. A failuretime value of 0 (the default) means forever.
-lockoutduration lockouttime
(duration or getdate string) Sets the duration for which the principal is locked from authenticating if too many authentication failures occur without the specified failure count interval elapsing. A duration of 0 (the default) means the principal remains locked out until it is administratively unlocked with modprinc -unlock.
-allowedkeysalts
Specifies the key/salt tuples supported for long-term keys when setting or changing a principal's password/keys. See Keysalt_lists in kdc.conf(5) for a list of the accepted values, but note that key/salt tuples must be separated with commas (',') only. To clear the allowed key/salt policy use a value of '-'.

Example:

kadmin: add_policy -maxlife "2 days" -minlength 5 guests

ktadd

ktadd [options] principal
ktadd [options] -glob princ-exp

Adds a principal, or all principals matching princ-exp, to a keytab file. Each principal's keys are randomized in the process. The rules for princ-exp are described in the list_principals command.

This command requires the inquire and changepw privileges. With the -glob form, it also requires the list privilege.

The options are:

-k[eytab] keytab
Use keytab as the keytab file. Otherwise, the default keytab is used.
-e enc:salt,...
Uses the specified keysalt list for setting the new keys of the principal. See Keysalt_lists in kdc.conf(5) for a list of possible values.
-q
Display less verbose information.
-norandkey
Do not randomize the keys. The keys and their version numbers stay unchanged. This option cannot be specified in combination with the -e option.

An entry for each of the principal's unique encryption types is added, ignoring multiple keys with the same encryption type but different salt types.

Alias: xst

Example:

kadmin: ktadd -k /tmp/foo-new-keytab host/foo.mit.edu
Entry for principal host/foo.mit.edu@ATHENA.MIT.EDU with kvno 3,
     encryption type aes256-cts-hmac-sha1-96 added to keytab
     FILE:/tmp/foo-new-keytab
kadmin:

ktremove

ktremove [options] principal [kvno | all | old]

Removes entries for the specified principal from a keytab. Requires no permissions, since this does not require database access.

If the string "all" is specified, all entries for that principal are removed; if the string "old" is specified, all entries for that principal except those with the highest kvno are removed. Otherwise, the value specified is parsed as an integer, and all entries whose kvno match that integer are removed.

The options are:

-k[eytab] keytab
Use keytab as the keytab file. Otherwise, the default keytab is used.
-q
Display less verbose information.

Alias: ktrem

Example:

kadmin: ktremove kadmin/admin all
Entry for principal kadmin/admin with kvno 3 removed from keytab
     FILE:/etc/krb5.keytab
