NOMBRE

kxdpgun - Herramienta de benchmarking DNS potenciada por XDP

SINOPSIS

kxdpgun [opciones] -i nombre_archivo objetivo

DESCRIPCIÓN

Potente generador de tráfico DNS, que envía y recibe paquetes a través de XDP.

Las consultas se generan de acuerdo con un archivo de texto que se lee secuencialmente en un bucle hasta que transcurre una duración configurada. El orden de las consultas no está garantizado. Las respuestas se reciben (a menos que se deshabiliten) y se cuentan, pero no se comparan con las consultas.

El número de hilos paralelos se autodetecta según el número de colas configuradas para la interfaz de red.

Parámetros

nombre_archivo
Ruta al archivo de consultas. Consulte la descripción a continuación sobre el formato del archivo.
objetivo
El nombre de dominio, la dirección IPv4 o IPv6 de un objetivo remoto.

Opciones

-t, --duration segundos
Duración de la generación de tráfico, especificada como un número decimal en segundos (por defecto es 5.0).
-T, --tcp[=modo_depuracion]
Enviar consultas a través de TCP. Consulte la lista de modos de depuración opcionales a continuación.
-U, --quic[=modo_depuracion]
Enviar consultas a través de QUIC. Consulte la lista de modos de depuración opcionales a continuación.
-Q, --qps consultas
Número de consultas por segundo (aproximadamente) a enviar (por defecto es 1000). El programa no está optimizado para bajas velocidades en las que podría perder paquetes de comunicación. La velocidad mínima recomendada es de 2 paquetes por hilo (cola Rx/Tx).
-b, --batch tamaño
Enviar más consultas en un lote. Mejora el QPS pero puede afectar la pérdida de paquetes del homólogo (por defecto es 10 para UDP y 1 para TCP/QUIC).
-r, --drop
Descarta las respuestas entrantes. Mejora el QPS, pero deshabilita las estadísticas de respuesta.
-p, --port número
Puerto de destino remoto (por defecto es 53 para UDP/TCP, 853 para QUIC).
-F, --affinity espec_cpu
Afinidad de CPU para todos los hilos especificada en el formato [<cpu_inicio>][s<cpu_paso>], donde <cpu_inicio> es el ID de CPU para el primer hilo y <cpu_paso> es el incremento del ID de CPU para el siguiente hilo (por defecto es 0s1).
-i, --infile nombre_archivo
Ruta a un archivo con plantillas de consulta.
-B, --binary
Especifica que el archivo de entrada está en formato binario. Este formato es similar al formato de mensaje DNS TCP. El archivo contiene registros formateados como longitud de 2 octetos (orden de red) seguida de un mensaje en formato binario DNS.
-I, --interface interfaz
Interfaz de red para la comunicación saliente. Esto puede ser útil en situaciones en las que las interfaces están en un enlace (bond), por ejemplo.
-l, --local IP_local[/prefijo]
Anula la dirección IP de origen autodetectada. Si se especifica un rango de direcciones en su lugar, se utilizarán varias IPs del rango para diferentes consultas de manera uniforme (el rango de direcciones no es compatible en el modo QUIC).
-L, --mac-local
Anula la dirección MAC local autodetectada.
-R, --mac-remote
Anula la dirección MAC remota autodetectada.
-v, --vlan id
Añade una cabecera VLAN 802.1Q con el ID dado. La descarga de VLAN debe estar desactivada.
-e, --edns-size tamaño
Tamaño del paquete UDP EDNS, rango 512-4096 (por defecto es 1232). Tenga en cuenta que a través de XDP, la MTU máxima soportada es 1790.
-m, --mode modo
Establece el modo XDP. Los valores admitidos son:
  • auto (por defecto) - el modo XDP se selecciona automáticamente para lograr el mejor rendimiento, lo que significa que se prefiere el soporte nativo del controlador al genérico, y se utiliza zero-copy si está disponible.
  • copy - se fuerza el modo de copia del socket XDP aunque esté disponible zero-copy. Esto puede resolver varios problemas del controlador, pero a costa de un menor rendimiento.
  • generic - se fuerza la implementación genérica de XDP aunque esté disponible la implementación nativa. Este modo no requiere soporte del controlador ni del hardware, pero ofrece el peor rendimiento.
-G, --qlog ruta
Genera archivos qlog en el directorio especificado por ruta. El directorio debe existir.

Esta opción se ignora si no se está en modo QUIC. El uso recomendado es con --quic=R o con QPS bajos. De lo contrario, se generan demasiados archivos.

-j, --json
Imprime estadísticas formateadas como JSON.
-S, --stats-period periodo
Informa estadísticas automáticamente cada periodo milisegundos.

Estos informes solo contienen métricas recopiladas en el periodo dado.

-h, --help
Imprime la ayuda del programa.
-V, --version
Imprime la versión del programa. La opción -VV hace que el programa imprima el resumen de configuración en tiempo de compilación.

Formato del archivo de consultas

Cada línea describe una consulta en el formato:

nombre_consulta tipo_consulta [flags]

Donde nombre_consulta es un nombre de dominio a consultar, tipo_consulta es un nombre de tipo de registro y flags es un solo carácter:

E Enviar consulta con EDNS.

D Solicitar DNSSEC (EDNS + flag DO).

Modos de depuración TCP/QUIC

0
Realiza un handshake completo para todas las conexiones (solo QUIC).
1
Solo envía SYN (Inicial) y recibe SYN-ACK (Handshake).
2
Realiza el handshake TCP/QUIC y no envía nada, permite el cierre iniciado por el homólogo.
3
Realiza el handshake TCP/QUIC y no reacciona más.
5
Envía una consulta incompleta (N-1 bytes) y no reacciona más.
7
Envía la consulta y no confirma la respuesta ni nada más.
8
No cierra la conexión e ignora el cierre por parte del homólogo.
9
Opera normalmente excepto por no confirmar el FIN+ACK final (solo TCP).
R
En lugar de abrir una conexión para cada consulta, reutiliza las conexiones.

Señales

Enviar la señal USR1 a un proceso en ejecución activa un volcado de estadísticas actual en la salida estándar. En combinación con -S puede causar una impresión errática del tiempo.

NOTAS

Se requiere el kernel de Linux 4.18 o superior.

La utilidad debe ejecutarse como root o con estos privilegios: CAP_NET_RAW, CAP_NET_ADMIN, CAP_SYS_ADMIN, CAP_IPC_LOCK y CAP_SYS_RESOURCE (Linux < 5.11).

La utilidad asigna puertos UDP/TCP de origen del rango 2000-65535.

kxdpgun(8)

NOMBRE

kxdpgun - utilidad de prueba de DNS para knot(1)

SINOPSIS

kxdpgun [-v...] [-Q total] [-q num] [-t sec] [-i fichier] [-c fichier] [-b num] [-T] [-U] [-p port] [-d] [-r num] [-s num] [-S num] [-f num] [-a num] [-A num] [servidor]...

DESCRIPCIÓN

kxdpgun es una herramienta de línea de comandos para probar el rendimiento de los servidores DNS. Puede generar consultas DNS y enviarlas a los servidores DNS especificados. La herramienta puede generar sus propias consultas o leerlas de un archivo de consultas. Las consultas generadas aleatoriamente pueden ser de varios tipos y para nombres de dominio aleatorios. Las estadísticas se imprimen en la salida estándar.

Las opciones permiten controlar el comportamiento de la herramienta, como el número de consultas, el tiempo de ejecución, el tamaño del lote, el protocolo de transporte y la dirección del servidor.

NOTAS

Las estadísticas de hilos son un trabajo en progreso. Las estadísticas de los hilos se recopilan para cualquier hilo dado. Las impresiones de estadísticas lo ignoran y, por lo tanto, son ligeramente inexactas. El margen de error disminuye proporcionalmente al volumen de datos y al lapso de tiempo durante el cual se recopilan.

VALORES DE SALIDA

El estado de salida 0 significa operación exitosa. Cualquier otro estado de salida indica un error.

EJEMPLOS

Archivo de consultas creado manualmente:

abc6.example.com. AAAA
nxdomain.example.com. A
notzone. A
a.example.com. NS E
ab.example.com. A D
abcd.example.com. DS D

Archivo de consultas generado a partir de un archivo de zona (formato Knot DNS):

cat ZONE_FILE | awk "{print \$1,\$3}" | grep -E "(NS|DS|A|AAAA|PTR|MX|SOA)$" | sort -u -R > queries.txt

Uso básico:

# kxdpgun -i ~/queries.txt 2001:DB8::1

Usando UDP con tamaño de lote aumentado:

# kxdpgun -t 20 -Q 1000000 -i ~/queries.txt -b 20 -p 8853 192.0.2.1

Usando TCP:

# kxdpgun -t 20 -Q 100000 -i ~/queries.txt -T -p 8853 192.0.2.1
