NOMBRE

keyd-application-mapper - remapear teclas cuando el foco de la ventana cambia

SINOPSIS

keyd-application-mapper [-d]

DESCRIPCIÓN

Un script que lee ~/.config/keyd/app.conf y aplica las vinculaciones proporcionadas cada vez que una ventana con una clase coincidente obtiene el foco.

Puedes pensar en cada sección como un conjunto de máscaras específicas de aplicación aplicadas sobre las reglas globales definidas en /etc/keyd/*.conf.

El archivo de configuración tiene el siguiente formato:

[<filtro>]
<expresión 1>
<expresión 2>
...

Donde <filtro> tiene una de las siguientes formas:

[<exp cl>] # Coincidir por clase de ventana [<exp cl>|<exp título>] # Coincidir por clase y título

y cada <expresión> es un argumento válido para keyd bind (ver Vinculaciones).

<exp cl> y <exp título> son cadenas que describen los nombres de clase y título de ventana que coinciden, y pueden opcionalmente contener comodines estilo Unix (*). Por ejemplo, [gnome|*find*] coincidirá con cualquier ventana con una clase gnome y un título que contenga la subcadena find.

Ejemplo:

[kitty]
alt.] = C-tab
alt.[ = C-S-tab
alt.t = C-S-t
[st-*]
alt.1  = macro(Inside space st)
[chromium]
control.1 = macro(Inside space chrome!)
alt.] = C-tab
alt.[ = C-S-tab
alt.t = C-t

Remapeará A-1 a la cadena 'Inside st' cuando una ventana con una clase que comience con 'st-' (por ejemplo, st-256color) esté activa.

Los nombres de clase y título de ventana se pueden obtener inspeccionando la salida del registro mientras el demonio se está ejecutando (por ejemplo, tail -f ~/.config/keyd/app.log). Se puede activar una recarga enviando una señal USR1 al script.

Actualmente se admiten X, Sway y Gnome.

INSTALACIÓN

La instalación es tan sencilla como ejecutar el comando keyd-application-mapper -d en algún lugar de la lógica de inicialización de su servidor de pantalla (por ejemplo, ~/.xinitrc o ~/.xsession). Si está ejecutando Gnome, la primera vez que ejecute keyd-application-mapper se instalará una extensión que gestiona el ciclo de vida del script.

Para que esto funcione, keyd debe estar ejecutándose y el usuario debe tener acceso a /var/run/keyd.socket (es decir, ser miembro del grupo keyd).

VARIABLES DE ENTORNO

KEYD_DEBUG

Nivel de registro de depuración. Se puede especificar 0, 1 (por defecto: 0).

Una nota sobre seguridad

Se debe asumir que cualquier usuario que pueda interactuar con un programa que controle directamente los dispositivos de entrada tiene acceso completo al sistema.

Si bien keyd ofrece un aislamiento ligeramente mejor en comparación con otros remapeadores al mediar el acceso a través de un mecanismo IPC (en lugar de otorgar a los usuarios acceso general a /dev/input/* y /dev/uinput), todavía proporciona una oportunidad para el abuso y debe ser tratado con la debida deferencia.

Específicamente, el acceso a /var/run/keyd.socket solo debe otorgarse a usuarios de confianza y el grupo keyd debe ser considerado con la misma reverencia que wheel.
