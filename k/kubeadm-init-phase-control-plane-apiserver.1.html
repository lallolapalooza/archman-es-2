NOMBRE

kubeadm init phase control-plane apiserver - Genera el manifiesto del Pod estático de kube-apiserver

SINOPSIS

kubeadm init phase control-plane apiserver [OPCIONES]

DESCRIPCIÓN

Genera el manifiesto del Pod estático de kube-apiserver

OPCIONES

--apiserver-advertise-address="" La dirección IP que el servidor API anunciará que está escuchando. Si no se establece, se utilizará la interfaz de red predeterminada.

--apiserver-bind-port=6443 Puerto al que se enlazará el servidor API.

--apiserver-extra-args= Un conjunto de indicadores adicionales para pasar al servidor API o para anular los predeterminados en formato =

--cert-dir="/etc/kubernetes/pki" La ruta donde guardar y almacenar los certificados.

--config="" Ruta a un archivo de configuración de kubeadm.

--control-plane-endpoint="" Especifica una dirección IP o nombre DNS estable para el plano de control.

--dry-run=false No aplicar ningún cambio; solo mostrar lo que se haría.

--feature-gates="" Un conjunto de pares clave=valor que describen las puertas de características para varias funciones. Las opciones son: ControlPlaneKubeletLocalMode=true|false (BETA - predeterminado=true) NodeLocalCRISocket=true|false (BETA - predeterminado=true) PublicKeysECDSA=true|false (OBSOLETO - predeterminado=false) RootlessControlPlane=true|false (ALFA - predeterminado=false) WaitForAllControlPlaneComponents=true|false (predeterminado=true)

--image-repository="registry.k8s.io" Elige un registro de contenedores para descargar las imágenes del plano de control.

--kubernetes-version="stable-1" Elige una versión específica de Kubernetes para el plano de control.

--patches="" Ruta a un directorio que contiene archivos nombrados "target[suffix][+patchtype].extension". Por ejemplo, "kube-apiserver0+merge.yaml" o simplemente "etcd.json". "target" puede ser uno de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" puede ser uno de "strategic", "merge" o "json" y coinciden con los formatos de parche compatibles con kubectl. El "patchtype" predeterminado es "strategic". "extension" debe ser "json" o "yaml". "suffix" es una cadena opcional que se puede usar para determinar qué parches se aplican primero alfanuméricamente.

--service-cidr="10.96.0.0/12" Utiliza un rango alternativo de direcciones IP para las VIP de servicio.

OPCIONES HEREDADAS DE LOS COMANDOS PADRE

--rootfs="" La ruta al sistema de archivos raíz 'real' del host. Esto hará que kubeadm entre en el directorio especificado.

--version=false --version, --version=raw imprime la información de la versión y sale; --version=vX.Y.Z... establece la versión informada
