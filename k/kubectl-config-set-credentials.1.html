NOMBRE

kubectl config set-credentials - Establece una entrada de usuario en kubeconfig

SINOPSIS

kubectl config set-credentials [OPCIONES]

DESCRIPCIÓN

Establece una entrada de usuario en kubeconfig.

Especificar un nombre que ya existe fusionará los nuevos campos encima de los valores existentes.

    Opciones de certificado de cliente:
    --client-certificate=archivo_cert --client-key=archivo_clave
    Opciones de token de portador:
    --token=token_portador
    Opciones de autenticación básica:
    --username=usuario_basico --password=contraseña_basica

El token de portador y la autenticación básica son mutuamente excluyentes.

OPCIONES

--auth-provider="" Proveedor de autenticación para la entrada de usuario en kubeconfig

--auth-provider-arg=[] Argumentos 'clave=valor' para el proveedor de autenticación

--client-certificate="" Ruta al archivo client-certificate para la entrada de usuario en kubeconfig

--client-key="" Ruta al archivo client-key para la entrada de usuario en kubeconfig

--embed-certs=false Incrusta cert/clave de cliente para la entrada de usuario en kubeconfig

--exec-api-version="" Versión de API del plugin de credenciales exec para la entrada de usuario en kubeconfig

--exec-arg=[] Nuevos argumentos para el comando del plugin de credenciales exec para la entrada de usuario en kubeconfig

--exec-command="" Comando para el plugin de credenciales exec para la entrada de usuario en kubeconfig

--exec-env=[] Valores de entorno 'clave=valor' para el plugin de credenciales exec

--exec-interactive-mode="" Modo interactivo del plugin de credenciales exec para la entrada de usuario en kubeconfig

--exec-provide-cluster-info=false ProporcionarInformaciónDelCluster del plugin de credenciales exec para la entrada de usuario en kubeconfig

--password="" Contraseña para la entrada de usuario en kubeconfig

--token="" Token para la entrada de usuario en kubeconfig

--username="" Nombre de usuario para la entrada de usuario en kubeconfig

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario normal o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificados para la autoridad de certificación

--cluster="" El nombre del cluster kubeconfig a usar

--context="" El nombre del contexto kubeconfig a usar

--disable-compression=false Si es true, desactiva la compresión de respuestas para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es true, el certificado del servidor no se verificará en cuanto a validez. Esto hará que tus conexiones HTTPS no sean seguras

--kubeconfig="" usa un archivo kubeconfig particular

--kuberc="" Ruta al archivo kuberc a usar para preferencias. Esto puede ser deshabilitado exportando la puerta de enlace de función KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud CLI

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil.

--request-timeout="0" La cantidad de tiempo a esperar antes de darse por vencido en una solicitud de servidor individual. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de espera de las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a usar para la validación del certificado del servidor. Si no se proporciona, se usa el nombre de host utilizado para contactar al servidor

--user="" El nombre del usuario kubeconfig a usar

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión informada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero

EJEMPLO

  # Establece solo el campo "client-key" en la entrada "cluster-admin"
  # sin tocar otros valores
  kubectl config set-credentials cluster-admin --client-key=~/.kube/admin.key
  # Establece autenticación básica para la entrada "cluster-admin"
  kubectl config set-credentials cluster-admin --username=admin --password=uXFGweU9l35qcif
  # Incrusta datos de certificado de cliente en la entrada "cluster-admin"
  kubectl config set-credentials cluster-admin --client-certificate=~/.kube/admin.crt --embed-certs=true
  # Habilita el proveedor de autenticación de Google Compute Platform para la entrada "cluster-admin"
  kubectl config set-credentials cluster-admin --auth-provider=gcp
  # Habilita el proveedor de autenticación OpenID Connect para la entrada "cluster-admin" con argumentos adicionales
  kubectl config set-credentials cluster-admin --auth-provider=oidc --auth-provider-arg=client-id=foo --auth-provider-arg=client-secret=bar
  # Elimina el valor de configuración "client-secret" para el proveedor de autenticación OpenID Connect para la entrada "cluster-admin"
  kubectl config set-credentials cluster-admin --auth-provider=oidc --auth-provider-arg=client-secret-
  # Habilita el nuevo plugin de autenticación exec para la entrada "cluster-admin"
  kubectl config set-credentials cluster-admin --exec-command=/path/to/the/executable --exec-api-version=client.authentication.k8s.io/v1beta1
  # Habilita el nuevo plugin de autenticación exec para la entrada "cluster-admin" con modo interactivo
  kubectl config set-credentials cluster-admin --exec-command=/path/to/the/executable --exec-api-version=client.authentication.k8s.io/v1beta1 --exec-interactive-mode=Never
  # Define nuevos argumentos del plugin de autenticación exec para la entrada "cluster-admin"
  kubectl config set-credentials cluster-admin --exec-arg=arg1 --exec-arg=arg2
  # Crea o actualiza variables de entorno del plugin de autenticación exec para la entrada "cluster-admin"
  kubectl config set-credentials cluster-admin --exec-env=key1=val1 --exec-env=key2=val2
  # Elimina variables de entorno del plugin de autenticación exec para la entrada "cluster-admin"
  kubectl config set-credentials cluster-admin --exec-env=var-to-remove-

kubectl-config-set-credentials(1) — Arch Linux

kubectl-config set-credentials (⟨credential-name⟩ --token=⟨token⟩ | --client-key=⟨path-to-key⟩ | --client-certificate=⟨path-to-cert⟩ | --username=⟨username⟩ --password=⟨password⟩) [--embed-certs=true|false]

Set a kubeconfig entry for authentication

OPTIONS

--client-certificate string Path to a PEM-encoded client certificate file for TLS authentication.

--client-key string Path to a PEM-encoded client private key file for TLS authentication.

--embed-certs boolean If true, use client cert/key data from files directly in kubeconfig. (default true)

--password string Password for basic authentication.

--token string Bearer token for authentication.

--username string Username for basic authentication.

--kubeconfig string kubeconfig indicates the path to the kubeconfig file to use.

--context string The name of the kubeconfig context to use.

--disable-compression If true, do not compress requests and responses.

-h, --help help for set-credentials

--match-server-version Require server version to match client version.

--minify If true, remove all but the essential information from the response.

--output string Output format. One of: json|yaml|wide|name|go-template|go-template-file|template|templatefile|jsonpath|jsonpath-file.

--record whether to print has the command for recording to a future command.

--save-config If true, the configuration of current object will be saved in its annotation. Otherwise, the defaults of the object will be overwritten with the modified values based on the configuration of current object.

--server string The address and port for the Kubernetes API server.

--tls-server-name string Server name for certificate verification.

--as string Username to impersonate for the operation. User could be a regular user or a service account in a namespace. Look into the user’s access logs for the requests that made this impersonation.

--as-group strings Group is a list of strings which are tags on the user’s access.

--as-uid string UID of the user for impersonation.

--cache-dir strings Default cache directory. (default “~/.kube/cache”)

--certificate-authority strings path to a cert file for the certificate authority.

--client-certificate strings path to the client certificate files.

--client-key strings path to the client key files.

--cluster string The name of the kubeconfig cluster to use.

--consumer string Name of the identity provider that is being used.

--insecure-skip-tls-verify if true, the server’s certificate will not be checked for validity. This is unsafe, do not use in production.

--kubeconfig strings kubeconfig file (default is $KUBECONFIG or ~/.kube/config).

--request-timeout string The length of time to wait before giving up on a single server request. Non-zero values should contain a corresponding time unit, e.g. 1s per second, 2m for minutes, 3h for hours. A value of zero means don’t timeout requests. (default “0”)

--tls-server-name strings Return the server name you want to make a TLS connection to.

OPTIONS INHERITED FROM PARENT COMMANDS

The following options are inherited from parent commands.

--rootless run kubernetes in rootless mode.

EXAMPLE

Configure kubectl to use token authentication: $ kubectl config set-credentials my-token-user --token=1234567890abcdef

Configure kubectl to use client certificate authentication: $ kubectl config set-credentials my-cert-user --client-certificate=~/.certs/mycert.crt --client-key=~/.certs/mykey.key
