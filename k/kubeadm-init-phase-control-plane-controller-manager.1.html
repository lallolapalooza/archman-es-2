NOMBRE

kubeadm init phase control-plane controller-manager - Genera el manifiesto del Pod estático del controlador de plano de control

SINOPSIS

kubeadm init phase control-plane controller-manager [OPCIONES]

DESCRIPCIÓN

Genera el manifiesto del Pod estático del controlador de plano de control

OPCIONES

--cert-dir="/etc/kubernetes/pki" La ruta donde guardar y almacenar los certificados.

--config="" Ruta a un archivo de configuración de kubeadm.

--controller-manager-extra-args= Un conjunto de flags adicionales para pasar al Controlador de Gestión o para anular los predeterminados en formato =

--dry-run=false No aplicar ningún cambio; solo mostrar lo que se haría.

--image-repository="registry.k8s.io" Elegir un registro de contenedores para descargar las imágenes del plano de control

--kubernetes-version="stable-1" Elegir una versión específica de Kubernetes para el plano de control.

--patches="" Ruta a un directorio que contiene archivos con el nombre "target[suffix][+patchtype].extension". Por ejemplo, "kube-apiserver0+merge.yaml" o solo "etcd.json". "target" puede ser uno de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" puede ser uno de "strategic", "merge" o "json" y coinciden con los formatos de parcheo soportados por kubectl. El "patchtype" predeterminado es "strategic". "extension" debe ser "json" o "yaml". "suffix" es una cadena opcional que puede usarse para determinar qué parches se aplican primero en orden alfanumérico.

--pod-network-cidr="" Especificar el rango de direcciones IP para la red de pods. Si se establece, el plano de control asignará automáticamente CIDRs para cada nodo.

OPCIONES HEREDADAS DE COMANDOS PADRE

--rootfs="" La ruta al sistema de archivos raíz 'real' del host. Esto hará que kubeadm realice un chroot en la ruta proporcionada.

--version=false --version, --version=raw imprime información de la versión y sale; --version=vX.Y.Z... establece la versión reportada.
