NOMBRE

kinit - obtener y almacenar en caché un ticket de concesión de tickets Kerberos

SINOPSIS

kinit [-V] [-l duración] [-s hora_inicio] [-r vida_renovable] [-p | -P] [-f | -F] [-a] [-A] [-C] [-E] [-v] [-R] [-k [-i | -t archivo_keytab]] [-c nombre_caché] [-n] [-S nombre_servicio] [-I ccache_entrada] [-T ccache_armor] [-X atributo[=valor]] [--request-pac | --no-request-pac] [principal]

DESCRIPCIÓN

kinit obtiene y almacena en caché un ticket inicial de concesión de tickets para el principal. Si principal está ausente, kinit elige un nombre de principal apropiado basándose en el contenido de la caché de credenciales existente o el nombre de usuario local del usuario que invoca kinit. Algunas opciones modifican la elección del nombre de principal.

OPCIONES

-V
muestra salida detallada.
-l duración
(cadena de duración.) Solicita un ticket con la duración duración.

Por ejemplo, kinit -l 5:30 o kinit -l 5h30m.

Si la opción -l no se especifica, se utiliza la duración predeterminada del ticket (configurada por cada sitio). Especificar una duración de ticket mayor que la duración máxima del ticket (configurada por cada sitio) no anulará la duración máxima del ticket configurada.

-s hora_inicio
(cadena de duración.) Solicita un ticket posfechado. Los tickets posfechados se emiten con el flag invalid establecido, y necesitan ser reenviados al KDC para su validación antes de su uso.

hora_inicio especifica la duración del retraso antes de que el ticket pueda ser válido.

-r vida_renovable
(cadena de duración.) Solicita tickets renovables, con una duración total de vida_renovable.
-f
solicita tickets reenviables.
-F
solicita tickets no reenviables.
-p
solicita tickets que se pueden reenviar.
-P
solicita tickets que no se pueden reenviar.
-a
solicita tickets restringidos a la(s) dirección(es) local(es) del host.
-A
solicita tickets no restringidos por dirección.
-C
solicita la canonización del nombre de principal, y permite que el KDC responda con un principal de cliente diferente al solicitado.
-E
trata el nombre de principal como un nombre de empresa.
-v
solicita que el ticket de concesión de tickets en la caché (con el flag invalid establecido) se pase al KDC para su validación. Si el ticket está dentro de su rango de tiempo solicitado, la caché se reemplaza con el ticket validado.
-R
solicita la renovación del ticket de concesión de tickets. Tenga en cuenta que un ticket caducado no puede renovarse, incluso si el ticket todavía está dentro de su vida útil renovable.

Tenga en cuenta que los tickets renovables que han caducado según lo informado por klist(1) a veces pueden renovarse utilizando esta opción, ya que el KDC aplica un período de gracia para tener en cuenta la discrepancia horaria entre el cliente y el KDC. Ver la configuración clockskew en krb5.conf(5).

-k [-i | -t archivo_keytab]
solicita un ticket, obtenido de una clave en el keytab del host local. La ubicación del keytab se puede especificar con la opción -t archivo_keytab, o con la opción -i para especificar el uso del keytab de cliente predeterminado; de lo contrario, se utilizará el keytab predeterminado. Por defecto, se solicita un ticket de host para el host local, pero se puede especificar cualquier principal. En un KDC, la ubicación especial del keytab KDB: puede usarse para indicar que kinit debe abrir la base de datos del KDC y buscar la clave directamente. Esto permite a un administrador obtener tickets como cualquier principal que admita la autenticación basada en la clave.
-n
Solicita procesamiento anónimo. Se admiten dos tipos de principales anónimos.

Para Kerberos completamente anónimo, configure pkinit en el KDC y configure pkinit_anchors en el krb5.conf(5) del cliente. Luego use la opción -n con un principal de la forma @REALM (un nombre de principal vacío seguido por el signo arroba y un nombre de reino). Si está permitido por el KDC, se devolverá un ticket anónimo.

Se admite una segunda forma de tickets anónimos; estos tickets expuestos al reino ocultan la identidad del cliente pero no el reino del cliente. Para este modo, use kinit -n con un nombre de principal normal. Si es compatible con el KDC, el principal (pero no el reino) será reemplazado por el principal anónimo.

A partir de la versión 1.8, el KDC de MIT Kerberos solo admite la operación completamente anónima.

-I ccache_entrada

Especifica el nombre de una caché de credenciales que ya contiene un ticket. Al obtener ese ticket, si la información sobre cómo se obtuvo ese ticket también se almacenó en la caché, esa información se usará para afectar cómo se obtienen las nuevas credenciales, incluida la preselección de los mismos métodos de autenticación al KDC.
-T ccache_armor
Especifica el nombre de una caché de credenciales que ya contiene un ticket. Si el KDC lo admite, esta caché se utilizará para "armar" la solicitud, evitando ataques de diccionario sin conexión y permitiendo el uso de mecanismos de preautenticación adicionales. El armamento también asegura que la respuesta del KDC no se modifique en tránsito.
-c nombre_caché
usa nombre_caché como la ubicación de la caché de credenciales (ticket) de Kerberos 5. Si esta opción no se utiliza, se utiliza la ubicación predeterminada de la caché.

La ubicación predeterminada de la caché puede variar entre sistemas. Si la variable de entorno KRB5CCNAME está configurada, su valor se usa para localizar la caché predeterminada. Si se especifica un nombre de principal y el tipo de la caché predeterminada admite una colección (como el tipo DIR), se selecciona una caché existente que contenga credenciales para el principal o se crea una nueva y se convierte en la nueva caché principal. De lo contrario, kinit destruirá cualquier contenido existente de la caché predeterminada.

-S nombre_servicio
especifica un nombre de servicio alternativo a usar al obtener tickets iniciales.
-X atributo[=valor]
especifica un atributo y valor de preautenticación para ser interpretados por los módulos de preautenticación. Los atributos y valores aceptables varían de un módulo a otro. Esta opción se puede especificar varias veces para especificar varios atributos. Si no se especifica valor, se asume que es "yes".

Los siguientes atributos son reconocidos por el mecanismo de preautenticación PKINIT:

X509_user_identity=valor
especifica dónde encontrar la información de identidad X509 del usuario
X509_anchors=valor
especifica dónde encontrar información confiable del ancla X509
flag_RSA_PROTOCOL[=yes]
especifica el uso de RSA, en lugar del protocolo Diffie-Hellman predeterminado
disable_freshness[=yes]
deshabilita el envío de tokens de frescura (solo para fines de prueba)

NOMBRE

kinit — obtener un ticket de autenticación Kerberos

SINOPSIS

kinit [–...] [principal]

DESCRIPCIÓN

El programa kinit se usa para obtener un ticket de autenticación (TGT) para un principal Kerberos.

El principal es el nombre de usuario para el cual se obtendrá el TGT. Si no se especifica, kinit intentará obtener un TGT para el principal predeterminado del usuario. El principal predeterminado se determina intentando obtener el nombre de usuario del sistema actual, y si eso falla, solicitando el nombre de usuario en la entrada estándar.

Cuando se invoca kinit, se solicita la contraseña del usuario en la entrada estándar (a menos que se proporcione una contraseña a través de otros medios, como un archivo de credenciales). Luego, kinit utiliza esta contraseña para autenticarse en el Key Distribution Center (KDC) y solicitar un TGT.

Si se obtiene un TGT con éxito, se almacena en el archivo de caché de credenciales predeterminado. El programa kdestroy se puede usar para destruir la caché de credenciales.

Consulte la página del manual de kerberos(7) para obtener más información sobre los conceptos de Kerberos, incluidos los principales y las cachés de credenciales.

OPCIONES

–a
Solicita explícitamente un PAC (Privilege Attribute Certificate) en authdata. Si se establece –no-request-pac, le pide al KDC que no incluya un PAC. Si no se establece ninguno, el KDC seguirá su valor predeterminado, que normalmente es incluir un PAC si es compatible.
–f
Solicita un ticket con el bit de avance de forwards habilitado.
–p
Solicita un ticket con el bit de proxy habilitado.
–r
Solicita un ticket reenviable. Esto permite que el ticket se utilice para obtener otros tickets en otros sistemas.
–s
Solicita un ticket con el bit de recursividad habilitado.
–S
Solicita un ticket con el bit de silenciamiento habilitado.
–v
Solicita un ticket con el bit de validación habilitado.
–i
Solicita un ticket con el bit de información habilitado.
–k
No solicite una contraseña; en su lugar, obtenga la clave de servicio desde el archivo keytab. Esto se usa generalmente para la autenticación de demonios.
–n
No solicite una contraseña. Esto se puede usar si la autenticación ocurre a través de otros medios (por ejemplo, un archivo de credenciales preexistente).
–t
El nombre de usuario y la contraseña se encuentran en un archivo de credenciales.
–c cache:
Use la caché de credenciales especificada por cache. El formato de la caché es el mismo que se usa para el archivo de caché de credenciales (consulte kerberos(5)).
–D
Solicitar al KDC que incluya un PAC en authdata; si –no-request-pac está configurado, solicitar al KDC que no incluya un PAC; si ninguno está configurado, el KDC seguirá su valor predeterminado, que normalmente es incluir un PAC si es compatible.

AMBIENTE

Consulte kerberos(7) para una descripción de las variables de entorno de Kerberos.

ARCHIVOS

ubicación predeterminada de la caché de credenciales de Kerberos 5
FILE:/etc/krb5.keytab
ubicación predeterminada para el archivo keytab del host local.
