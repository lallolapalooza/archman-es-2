NOMBRE

kadmind - Servidor de administración de KADM5

SINOPSIS

kadmind [-x db_args] [-r realm] [-m] [-nofork] [-proponly] [-port numero_puerto] [-P archivo_pid] [-p ruta_kdb5_util] [-K ruta_kprop] [-k puerto_kprop] [-F archivo_dump]

DESCRIPCIÓN

kadmind inicia el servidor de administración de Kerberos. kadmind típicamente se ejecuta en el servidor Kerberos primario, que almacena la base de datos KDC. Si la base de datos KDC utiliza el módulo LDAP, el servidor de administración y el servidor KDC no necesitan ejecutarse en la misma máquina. kadmind acepta solicitudes remotas de programas como kadmin(1) y kpasswd(1) para administrar la información en estas bases de datos.

kadmind requiere que se configuren varios archivos de configuración para que funcione:

kdc.conf(5)
El archivo de configuración KDC contiene información de configuración para los servidores KDC y de administración. kadmind utiliza la configuración de este archivo para localizar la base de datos Kerberos, y también se ve afectado por los ajustes acl_file, dict_file, kadmind_port y los relacionados con iprop.
kadm5.acl(5)
La ACL (lista de control de acceso) de kadmind le indica qué principales tienen permitido realizar acciones de administración. La ruta al archivo de ACL se puede especificar con la variable acl_file de kdc.conf(5); por defecto, es /var/lib/krb5kdc/kadm5.acl.

Después de que el servidor comienza a ejecutarse, se pone en segundo plano y se disocia de su terminal de control.

kadmind se puede configurar para la propagación incremental de la base de datos. La propagación incremental permite a los servidores KDC réplica recibir actualizaciones incrementales de principales y políticas en lugar de recibir volcados completos de la base de datos. Esta función se puede habilitar en el archivo kdc.conf(5) con la opción iprop_enable. La propagación incremental requiere el principal kiprop/PRIMARIO\@REINO (donde PRIMARIO es el nombre canónico del host del KDC primario y REINO es el nombre del reino). En la versión 1.13, este principal se crea y se registra automáticamente en la base de datos.

OPCIONES

-r reino
especifica el reino que servirá kadmind; si no se especifica, se utiliza el reino por defecto del host.
-m
hace que la contraseña de la base de datos maestra se obtenga del teclado (antes de que el servidor se ponga en segundo plano, si no se invoca con la opción -nofork) en lugar de un archivo en disco.
-nofork
hace que el servidor permanezca en primer plano y asociado a la terminal.
-proponly
hace que el servidor solo escuche y responda a las solicitudes de sondeo de propagación incremental de réplicas de Kerberos. Esta opción se puede usar para configurar una topología de propagación jerárquica donde un KDC réplica proporciona actualizaciones incrementales a otras réplicas de Kerberos.
-port numero_puerto
especifica el puerto en el que el servidor de administración escucha las conexiones. El puerto por defecto lo determina la variable de configuración kadmind_port en kdc.conf(5).
-P archivo_pid
especifica el archivo en el que se debe escribir el PID del proceso kadmind después de que se inicie. Este archivo se puede usar para identificar si kadmind todavía se está ejecutando y para permitir que los scripts de inicialización detengan el proceso correcto.
-p ruta_kdb5_util
especifica la ruta al comando kdb5_util a usar al volcar el KDB en respuesta a solicitudes de resincronización completa cuando iprop está habilitado.
-K ruta_kprop
especifica la ruta al comando kprop a usar para enviar volcados completos a las réplicas en respuesta a solicitudes de resincronización completa.
-k puerto_kprop
especifica el puerto por el cual el proceso kprop iniciado por kadmind se conecta a kpropd réplica, para transferir el archivo de volcado durante una solicitud de resincronización completa de iprop.
-F archivo_dump
especifica la ruta del archivo a usar para volcar el KDB en respuesta a solicitudes de resincronización completa cuando iprop está habilitado.
-x db_args
especifica argumentos específicos de la base de datos. Consulte Opciones de base de datos en kadmin(1) para ver los argumentos admitidos.

ENTORNO

Consulte kerberos(7) para una descripción de las variables de entorno de Kerberos.

VEA TAMBIÉN
