DESCRIPCIÓN

Este programa se utiliza para controlar la instalación de gestión de claves de varias maneras utilizando una variedad de subcomandos.

IDENTIFICADORES DE CLAVE

Los identificadores de clave pasados ​​a o devueltos desde keyctl son, en general, enteros positivos. Sin embargo, hay algunos valores especiales con significados especiales que se pueden pasar como argumentos:

Sin clave: 0
Keyring de hilo: @t o -1
Cada hilo puede tener su propio keyring. Este se busca primero, antes que todos los demás. El keyring de hilo se reemplaza por (v)fork, exec y clone.
Keyring de proceso: @p o -2
Cada proceso (grupo de hilos) puede tener su propio keyring. Este se comparte entre todos los miembros de un grupo y se buscará después del keyring del hilo. El keyring del proceso se reemplaza por (v)fork y exec.
Keyring de sesión: @s o -3
Cada proceso se suscribe a un keyring de sesión que se hereda a través de (v)fork, exec y clone. Este se buscará después del keyring del proceso. Los keyrings de sesión se pueden nombrar y se puede unir un keyring existente en lugar del keyring de sesión actual de un proceso.
Keyring específico del usuario: @u o -4
Este keyring se comparte entre todos los procesos propiedad de un usuario particular. No se busca directamente, pero normalmente está enlazado desde el keyring de sesión.
Keyring de sesión predeterminado del usuario: @us o -5
Este es el keyring de sesión predeterminado para un usuario particular. Los procesos de inicio de sesión que cambian a un usuario particular se vincularán a esta sesión hasta que se establezca otra sesión.
Keyring específico del grupo: @g o -6
Este es un marcador de posición para un keyring específico del grupo, pero aún no está implementado en el kernel.
Clave de autorización assumed_key: @a o -7
Esto selecciona la clave de autorización proporcionada a la ayuda request_key() para permitirle acceder a los keyrings del llamador e instanciar la clave de destino.
Keyring por nombre: %:<nombre>
Un keyring con nombre. Este se buscará en los keyrings del proceso y en /proc/keys.
Clave por nombre: %<tipo>:<nombre>
Una clave con nombre del tipo dado. Esta se buscará en los keyrings del proceso y en /proc/keys.

Listar un llavero

keyctl list <llavero>
keyctl rlist <llavero>

Estos comandos listan el contenido de una clave como un llavero. "list" formatea el contenido para su lectura y "rlist" simplemente produce una lista de IDs de claves separados por espacios.

No se intenta comprobar que la llavero especificada sea un llavero.

$ keyctl list @us
2 keys in keyring:
       22: vrwsl----------  4043    -1 keyring: _uid.4043
       23: vrwsl----------  4043  4043 user: debug:hello
$ keyctl rlist @us
22 23

Describir una clave

keyctl describe <llavero>
keyctl rdescribe <llavero> [sep]

Estos comandos obtienen una descripción de un llavero. "describe" formatea la descripción para su lectura de la misma manera que el comando "list"; "rdescribe" imprime los datos sin procesar devueltos por el kernel.

$ keyctl describe @us
       -5: vrwsl----------  4043    -1 keyring: _uid_ses.4043
$ keyctl rdescribe @us
keyring;4043;-1;3f1f0000;_uid_ses.4043

La cadena sin procesar es "<tipo>;<uid>;<gid>;<perms>;<descripción>", donde uid y gid son los IDs de usuario y de grupo en decimal, perms es la máscara de permisos en hexadecimal, tipo y descripción son las cadenas de nombre de tipo y descripción (ninguna de las cuales contendrá punto y coma).

Cambiar los controles de acceso de una clave

keyctl chown <clave> <uid>
keyctl chgrp <clave> <gid>

Estos dos comandos cambian el UID y el GID asociados con la evaluación de la máscara de permisos de una clave. El UID también gobierna de qué cuota se descuenta la clave.

El comando chown no está soportado actualmente; intentarlo producirá como mucho el error "Operation not supported".

Para usuarios no superusuario, el GID solo puede establecerse en el GID del proceso o en un GID de la lista de grupos del proceso. El superusuario puede establecer cualquier GID que desee.

$ sudo keyctl chown 27 0
keyctl_chown: Operation not supported
$ sudo keyctl chgrp 27 0

Establecer la máscara de permisos en una clave

keyctl setperm <clave> <máscara>

Este comando cambia la máscara de control de permisos de una clave. La máscara puede especificarse como un número hexadecimal si comienza con "0x", un número octal si comienza con "0" o un número decimal en caso contrario.

Los números hexadimensionales son una combinación de:

Posesor UID       GID       Otros     Permiso Concedido
========  ========  ========  ========  ==================
01000000  00010000  00000100  00000001  Ver
02000000  00020000  00000200  00000002  Leer
04000000  00040000  00000400  00000004  Escribir
08000000  00080000  00000800  00000008  Buscar
10000000  00100000  00001000  00000010  Enlazar
20000000  00200000  00002000  00000020  Establecer Atributo
3f000000  003f0000  00003f00  0000003f  Todos

Ver permite ver el tipo, la descripción y otros parámetros de una clave.

Leer permite leer la carga útil (o la lista del llavero) si es soportado por el tipo.

Escribir permite modificar o actualizar la carga útil (o la lista del llavero).

Buscar en una clave permite que se la encuentre cuando se busca un llavero al que está enlazada.

Enlazar permite enlazar una clave a un llavero.

Establecer Atributo permite cambiar el propietario, la membresía de grupo, la máscara de permisos y el tiempo de espera de una clave.

$ keyctl setperm 27 0x1f1f1f00

Instanciar una clave

keyctl instantiate [-x] <clave> <datos> <llavero>
keyctl pinstantiate [-x] <clave> <llavero>
keyctl negate <clave> <tiempo_de_espera> <llavero>
keyctl reject <clave> <tiempo_de_espera> <error> <llavero>

Estos comandos se usan para adjuntar datos a una clave parcialmente configurada (como la creada por el kernel y pasada a /sbin/request-key). "instantiate" marca una clave como válida y adjunta los datos como la carga útil. "negate" y "reject" marcan una clave como inválida y le establecen un tiempo de espera para que desaparezca después de un tiempo. Esto evita que muchas solicitudes secuenciales rápidas ralenticen demasiado el sistema cuando todas fallan, ya que todas las solicitudes posteriores fallarán con el error "Requested key not found" (si se nega) o el error especificado (si se rechaza) hasta que la clave negativa haya expirado.

El argumento de error de reject puede ser un número de error UNIX o uno de 'rejected', 'expired' o 'revoked'.

La clave recién instanciada se adjuntará al llavero especificado.

Estos comandos solo pueden ejecutarse desde el programa ejecutado por request-key - el kernel establece una clave de autorización especial y la adjunta al llavero de sesión de request-key. Esta clave especial se revoca una vez que la clave a la que se refiere ha sido instanciada de una forma u otra.

$ keyctl instantiate $1 "Debug $3" $4
$ keyctl negate $1 30 $4
$ keyctl reject $1 30 64 $4

La variante pinstantiate del comando lee los datos desde stdin en lugar de tomarlos de la línea de comandos:

$ echo -n "Debug $3" | keyctl pinstantiate $1 $4

Si se proporciona -x , los datos se decodifican desde hexadecimal descartando los espacios en blanco:

$ echo 01 02 03 04 | keyctl pinstantiate -x $1 $4

Establecer el tiempo de expiración de una clave

keyctl timeout <clave> <tiempo_de_espera>

Este comando se usa para establecer el tiempo de espera de una clave, o borrar un tiempo de espera existente si el valor especificado es cero. El tiempo de espera se da como un número de segundos en el futuro.

$ keyctl timeout $1 45

Recuperar el contexto de seguridad de una clave

keyctl security <clave>

Este comando se usa para recuperar el contexto de seguridad LSM de una clave. La etiqueta se imprime en stdout.

$ keyctl security @s
unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023

Dar al proceso padre un nuevo llavero de sesión

keyctl new_session [<nombre>]

Este comando se usa para dar al proceso invocador (típicamente un shell) un nuevo llavero de sesión, descartando su llavero de sesión antiguo. Si se da un nombre, el llavero recibe ese nombre, de lo contrario recibirá un nombre de "_ses" y no se podrá unir manualmente a él.

$  keyctl session foo
Joined session keyring: 723488146
$  keyctl show
Session Keyring
       -3 --alswrv      0     0  keyring: foo
$  keyctl new_session
490511412
$  keyctl show
Session Keyring
       -3 --alswrv      0     0  keyring: _ses

Tenga en cuenta que esto afecta al padre del proceso que invoca la llamada al sistema, y por lo tanto solo puede afectar a procesos con credenciales coincidentes. Además, el cambio no surtirá efecto hasta que el proceso padre haga la próxima transición del espacio del kernel al espacio de usuario - típicamente cuando la llamada al sistema wait() regrese.

Eliminar claves muertas del árbol de llaveros de sesión

keyctl reap

Este comando realiza una búsqueda en profundidad del árbol de llaveros de sesión del invocador e intenta desvincular cualquier clave que encuentre que sea inaccesible debido a expiración, revocación, rechazo o negación. No intenta eliminar claves vivas que no estén disponibles simplemente por una falta de permiso concedido.

Una clave designada como recuperable solo se eliminará de un almacén de claves si el llamante tiene permiso de escritura en ese almacén, y solo se buscarán en los almacenes de claves que otorguen permiso de búsqueda al llamante.

El comando imprime el número de claves recuperadas antes de salir. Si se pasa el indicador -v, las claves recuperadas se enumeran a medida que se recuperan, junto con el éxito o el fracaso de la desvinculación.

Eliminar claves coincidentes del árbol de almacenes de claves de sesión

keyctl purge <tipo>
keyctl purge [-i] [-p] <tipo> <descripción>
keyctl purge -s <tipo> <descripción>

Estos comandos realizan una búsqueda en profundidad para encontrar claves coincidentes en el árbol de almacenes de claves de sesión del llamante y intentan desvincularlas. Al final se imprime el número de claves desvinculadas con éxito.

Los almacenes de claves deben otorgar permiso de lectura y vista al llamante para ser buscados, y las claves a eliminar también deben otorgar permiso de vista. Las claves solo se pueden eliminar de almacenes de claves que otorguen permiso de escritura.

La primera variante purga todas las claves del tipo especificado.

La segunda variante purga todas las claves del tipo especificado que también coincidan literalmente con la descripción dada. El indicador -i permite una coincidencia insensible a mayúsculas y minúsculas, y el indicador -p permite una coincidencia de prefijo.

La tercera variante purga todas las claves del tipo especificado y la descripción coincidente utilizando el comparador del tipo de clave en el núcleo para coincidir con la descripción. Esto permite que el tipo de clave coincida con una clave con una variedad de descripciones.

Obtener almacén de claves persistente

keyctl get_persistent <almacén_de_claves> [<uid>]

Este comando obtiene el almacén de claves persistente para la UID actual o la UID especificada y lo adjunta al almacén de claves nominado. La ID del almacén de claves persistente se imprimirá en stdout.

El núcleo creará el almacén de claves si no existe y cada vez que se ejecute este comando, restablecerá el tiempo de espera de expiración del almacén de claves al valor en:

/proc/sys/kernel/keys/persistent_keyring_expiry

(por defecto tres días). Si se alcanza el tiempo de espera, el almacén de claves persistente se eliminará y todo lo que ancle podrá ser recolectado como basura.

Si se especifica una UID distinta de las UID reales o efectivas del proceso, se producirá un error si el proceso no tiene la capacidad CAP_SETUID.

Calcular un secreto compartido o clave pública Diffie-Hellman

keyctl dh_compute <privada> <primo> <base>

Este comando calcula un secreto compartido Diffie-Hellman o la clave pública correspondiente a la clave privada proporcionada utilizando las cargas útiles de tres claves. El cálculo es:

base ^ privada (mod primo)

Las tres entradas deben ser claves de usuario con permiso de lectura. Si la clave base proporcionada contiene el valor del generador compartido, se calculará la clave pública. Si la clave base proporcionada contiene el valor de la clave pública remota, se calculará el secreto compartido.

El resultado se imprime en stdout como un volcado hexadecimal.

$ keyctl dh_compute $1 $2 $3
8 bytes de datos en el resultado:
00010203 04050607

Calcular un secreto compartido Diffie-Hellman y derivar material de clave

keyctl dh_compute_kdf <privada> <primo> <base> <longitud_salida> <tipo_hash>

Este comando calcula un secreto compartido Diffie-Hellman y deriva material de clave del secreto compartido utilizando una función de derivación de clave (KDF). El secreto compartido se deriva como se describe anteriormente y se introduce en el KDF utilizando el tipo de hash especificado. El tipo de hash debe apuntar a un nombre de hash conocido por la API criptográfica del núcleo.

La operación deriva material de clave de la longitud especificada por el llamante.

La operación cumple con la especificación de SP800-56A.

El resultado se imprime en stdout como volcado hexadecimal.

Calcular un secreto compartido Diffie-Hellman y aplicar KDF con otra entrada

keyctl dh_compute_kdf_oi [-x] <privada> <primo> <base> <longitud_salida> <tipo_hash>

Este comando es idéntico al comando dh_compute_kdf para generar un secreto compartido Diffie-Hellman seguido de una operación de derivación de clave. Este comando permite al llamante proporcionar los datos de otra entrada (datos OI) compatibles con SP800-56A a través de stdin.

Si se proporciona -x, los datos pasados a stdin se decodifican en hexadecimal descartando los espacios en blanco.

Realizar operaciones de clave pública con una clave asimétrica

keyctl pkey_query <clave> <contraseña> [k=v]*
keyctl pkey_encrypt <clave> <contraseña> <archivo_datos> [k=v]* > <archivo_cifrado>
keyctl pkey_decrypt <clave> <contraseña> <archivo_cifrado> [k=v]* > <archivo_datos>
keyctl pkey_sign <clave> <contraseña> <archivo_datos> [k=v]* > <archivo_firma>
keyctl pkey_verify <clave> <contraseña> <archivo_datos> <archivo_firma> [k=v]*

Estos comandos consultan una clave asimétrica, cifran datos con ella, descifran los datos cifrados, generan una firma sobre algunos datos y verifican esa firma. Para cifrar, descifrar y firmar, los datos resultantes se escriben en stdout; verify lee los archivos de datos y firma y los compara.

[!] TENGA EN CUENTA que los datos tienen una capacidad muy limitada, con no más bits que el tamaño de la clave. Para las firmas, se espera que el llamante digiera los datos reales y pase el resultado del digest como archivo de datos. El nombre del digest debe especificarse al final de la línea de comandos como "hash=<nombre>".

La ID de clave indica la clave a utilizar; contraseña es un marcador de posición para la futura provisión de contraseña y debe ser "0" por el momento; archivo_datos son los datos sin cifrar a cifrar, firmar o cuya firma se comprobará; archivo_cifrado es un archivo que contiene datos cifrados; y archivo_firma es un archivo que contiene una firma.

Se puede incluir una lista de parámetros en formato "clave [=valor]" al final de la línea de comandos. Estos especifican cosas como el algoritmo de digest utilizado ("hash=<nombre>") o el formato de codificación ("enc=<tipo>").

k=`keyctl padd asymmetric "" @s <key.pkcs8.der`
keyctl pkey_query $k 0 enc=pkcs1 hash=sha256
keyctl pkey_encrypt $k 0 foo.hash enc=pkcs1 >foo.enc
keyctl pkey_decrypt $k 0 foo.enc enc=pkcs1 >foo.hash
keyctl pkey_sign $k 0 foo.hash enc=pkcs1 hash=sha256 >foo.sig
keyctl pkey_verify $k 0 foo.hash foo.sig enc=pkcs1 hash=sha256

Consulte asymmetric-key(7) para obtener más información.

Notificaciones de cambios

keyctl watch [-f<filtros>] <clave>
keyctl watch_session [-f <filtros>] [-n <nombre>] \
<log_notificaciones> <log_gc> <fd> <prog> [<arg1> <arg2> ...] keyctl watch_add <fd> <clave>
keyctl watch_rm <fd> <clave>

El comando watch observa una sola clave, imprimiendo notificaciones en stdout hasta que la clave sea destruida. Se pueden emplear filtros para reducir los eventos que se entregarán. La cadena de filtro es una serie de letras, cada una de las cuales habilita un subtipo de evento particular:

i - La clave ha sido instanciada
p - La clave ha sido actualizada
l - Se ha añadido un enlace a un almacén de claves
n - Se ha eliminado un enlace de un almacén de claves
c - Se ha limpiado un almacén de claves
r - Una clave ha sido revocada
v - Una clave ha sido invalidada
s - Los atributos de una clave han sido modificados

La salida del comando se ve así:

<id_clave> <evento> [<auxiliar>]

Donde id_clave es el sujeto principal de la notificación, op es el evento y auxiliar es la clave secundaria si la hay (como en el enlace, donde la clave principal es el almacén de claves y la clave secundaria es la clave que se enlaza en él). Por ejemplo:

255913279 link 340681059
255913279 clr

Se genera una notificación adicional cuando una clave que se está observando es recolectada como basura, por ejemplo:

255913279 gc

El comando watch_session crea un nuevo almacén de claves de sesión, con el nombre nombre si se proporciona, lo observa para recibir notificaciones y ejecuta el programa prog con él. Al programa se le pasan los argumentos especificados.

Se crea un segundo proceso para monitorizar las notificaciones. La salida de este se dirige a los archivos log_notificaciones para la mayoría de las notificaciones y log_gc para las notificaciones de eliminación de claves (que son asíncronas y pueden ser diferidas).

El dispositivo watch_queue(7) se exporta al programa adjunto al descriptor de archivo número fd. Esto puede ser pasado por los otros dos comandos.

El comando watch_add añade una observación sobre clave al watch_queue adjunto a fd tal como lo exporta watch_session, y el comando watch_rm la elimina. Un watch_queue puede manejar múltiples claves e incluso fuentes que no sean claves.

ERRORES

Hay una serie de errores comunes devueltos por este programa:

"No es un directorio" - una clave no era un almacén de claves.

"Clave solicitada no encontrada" - la clave buscada no está disponible.

"Clave ha sido revocada" - se accedió a una clave revocada.

"Clave ha expirado" - se accedió a una clave caducada.

"Permiso denegado" - se denegó el permiso por una combinación de UID/GID/máscara.
