NOMBRE

knockd - servidor de port-knock

SINOPSIS

knockd [opciones]

DESCRIPCIÓN

knockd es un servidor de port-knock. Escucha todo el tráfico en una interfaz ethernet (o PPP), buscando secuencias especiales de "knock" de golpes de puerto. Un cliente realiza estos golpes de puerto enviando un paquete TCP (o UDP) a un puerto del servidor. Este puerto no necesita estar abierto -- dado que knockd escucha a nivel de enlace, ve todo el tráfico incluso si está destinado a un puerto cerrado. Cuando el servidor detecta una secuencia específica de golpes de puerto, ejecuta un comando definido en su archivo de configuración. Esto se puede usar para abrir agujeros en un firewall para acceso rápido.

OPCIONES DE LÍNEA DE COMANDOS

-i, --interface <int>
Especifica una interfaz en la que escuchar. El valor por defecto es eth0.
-d, --daemon
Conviértete en un demonio. Esto es generalmente deseable para la operación normal tipo servidor.
-c, --config <archivo>
Especifica una ubicación alternativa para el archivo de configuración. El valor por defecto es /etc/knockd.conf.
-D, --debug
Muestra mensajes de depuración.
-l, --lookup
Busca nombres DNS para las entradas de registro. ¡Esto puede ser un riesgo de seguridad! Ver sección NOTAS DE SEGURIDAD.
-4, --only-ip-v4
Ignora paquetes de IPv6 y maneja solo IPv4.
-v, --verbose
Muestra mensajes de estado detallados.
-V, --version
Muestra la versión.
-h, --help
Ayuda de sintaxis.

CONFIGURACIÓN

knockd lee todos los conjuntos de knocks/eventos de un archivo de configuración. Cada knock/evento comienza con un marcador de título, en la forma [nombre], donde nombre es el nombre del evento que aparecerá en el registro. Un marcador especial, [opciones], se usa para definir opciones globales.

Ejemplo #1:

Este ejemplo usa dos knocks. El primero permitirá al knocker acceder al puerto 22 (SSH), y el segundo cerrará el puerto cuando el knocker termine. Como puedes ver, esto podría ser útil si ejecutas un firewall muy restrictivo (política DENY) y quieres acceder a él discretamente. 
[opciones]
	logfile = /var/log/knockd.log
[openSSH]
	sequence    = 7000,8000,9000
	seq_timeout = 10
	tcpflags    = syn
	command     = /usr/sbin/iptables -A INPUT -s %IP% --dport 22 -j ACCEPT
[closeSSH]
	sequence    = 9000,8000,7000
	seq_timeout = 10
	tcpflags    = syn
	command     = /usr/sbin/iptables -D INPUT -s %IP% --dport 22 -j ACCEPT

Ejemplo #2:

Este ejemplo utiliza un único knock para controlar el acceso al puerto 22 (SSH). Después de recibir un knock exitoso, el demonio ejecutará el start_command, esperará el tiempo especificado en cmd_timeout, y luego ejecutará el stop_command. Esto es útil para cerrar automáticamente la puerta detrás de un knocker. La secuencia de knock usa puertos UDP y TCP. 
[opciones]
	logfile = /var/log/knockd.log
[opencloseSSH]
	sequence      = 2222:udp,3333:tcp,4444:udp
	seq_timeout   = 15
	tcpflags      = syn,ack
	start_command = /usr/sbin/iptables -A INPUT -s %IP% -p tcp --syn -j ACCEPT
	cmd_timeout   = 5
	stop_command  = /usr/sbin/iptables -D INPUT -s %IP% -p tcp --syn -j ACCEPT

Ejemplo #3:

Este ejemplo no utiliza una secuencia de knock fija y única para activar un evento, sino un conjunto de secuencias tomadas de un archivo de secuencias (secuencias de un solo uso), especificado por la directiva one_time_sequences. Después de cada intento de knock exitoso, la secuencia utilizada se invalidará y se deberá usar la siguiente secuencia del archivo para un knock exitoso. Esto evita que un atacante realice un ataque de repetición después de haber descubierto una secuencia (por ejemplo, al interceptar la red). 
[opciones]
	logfile = /var/log/knockd.log
[opencloseSMTP]
	one_time_sequences = /etc/knockd/smtp_sequences
	seq_timeout        = 15
	tcpflags           = fin,!ack
	start_command      = /usr/sbin/iptables -A INPUT -s %IP% -p tcp --dport 25 -j ACCEPT
	cmd_timeout        = 5
	stop_command       = /usr/sbin/iptables -D INPUT -s %IP% -p tcp --dport 25 -j ACCEPT

Ejemplo #4:

Ejemplo para soportar IPv4 e IPv6. Puedes proporcionar un comando dedicado para cada uno de los dos protocolos. 
[opciones]
	logfile = /var/log/knockd.log
[opencloseSMTP]
	one_time_sequences = /etc/knockd/smtp_sequences
	seq_timeout        = 15
	tcpflags           = fin,!ack
	start_command      = /usr/sbin/iptables -A INPUT -s %IP% -p tcp --dport 25 -j ACCEPT
	start_command_6    = /usr/sbin/ip6tables -A INPUT -s %IP% -p tcp --dport 25 -j ACCEPT
	cmd_timeout        = 5
	stop_command       = /usr/sbin/iptables -D INPUT -s %IP% -p tcp --dport 25 -j ACCEPT
	stop_command_6     = /usr/sbin/ip6tables -D INPUT -s %IP% -p tcp --dport 25 -j ACCEPT

CONFIGURACIÓN: DIRECTIVAS GLOBALES

UseSyslog
Registra mensajes de acción a través de syslog(). Esto insertará entradas de registro en tu /var/log/messages o equivalente.
LogFile = /ruta/a/archivo
Registra acciones directamente en un archivo, generalmente /var/log/knockd.log.
PidFile = /ruta/a/archivo
Archivo PID a usar cuando está en modo demonio, por defecto: /var/run/knockd.pid.
Interface = <nombre_interfaz>
Interfaz de red en la que escuchar. Solo se debe dar su nombre, no la ruta al dispositivo (ej., "eth0" y no "/dev/eth0"). Por defecto: eth0.

CONFIGURACIÓN: DIRECTIVAS DE KNOCK/EVENTO

Sequence = <puerto1>[:<tcp|udp>],<puerto2>[:<tcp|udp>][,<puerto3>[:<tcp|udp>] ...]
Especifica la secuencia de puertos en el knock especial. Si se recibe un puerto incorrecto con las mismas banderas, el knock se descarta. Opcionalmente, puedes definir el protocolo a usar por puerto (por defecto es TCP).
One_Time_Sequences = /ruta/a/archivo_de_secuencias_un_solo_uso
Archivo que contiene las secuencias de un solo uso a utilizar. En lugar de usar una secuencia fija, knockd leerá la secuencia a utilizar de ese archivo. Después de cada intento de knock exitoso, esta secuencia se invalidará escribiendo un carácter '#' en la primera posición de la línea que contiene la secuencia utilizada. Esa secuencia utilizada será entonces reemplazada por la siguiente secuencia válida del archivo.

Debido a que el primer carácter se reemplaza por un '#', se recomienda dejar un espacio al principio de cada línea. De lo contrario, el primer dígito de tu secuencia de knock se sobrescribirá con un '#' después de haber sido utilizado.

Cada línea en el archivo de secuencias de un solo uso contiene exactamente una secuencia y tiene el mismo formato que el de la directiva Sequence. Las líneas que comienzan con un carácter '#' serán ignoradas.

Nota: ¡No edites el archivo mientras knockd se está ejecutando!

Seq_Timeout = <tiempo_espera>
Tiempo de espera para que una secuencia se complete en segundos. Si el tiempo expira antes de que el knock se complete, se descarta.
TCPFlags = fin|syn|rst|psh|ack|urg

CONFIGURACIÓN: DIRECTIVAS DE KNOCK/EVENTO

TCPFlags = <flags>
Esto permite especificar qué flags de TCP se requieren para una coincidencia. Las flags válidas son: syn, ack, urg, psh, fin, rst, ecn, cwr. La flag por defecto es syn. Si se especifica un flag que no sea syn, la secuencia se reiniciará automáticamente después del primer knock. Utilizar "TCPFlags = syn" es útil si estás probando a través de una conexión SSH, ya que el tráfico SSH generalmente interferirá con el knock (e invalidará el knock).

Separa las flags múltiples con comas (ej., TCPFlags = syn,ack,urg). Las flags se pueden excluir explícitamente con un "!" (ej., TCPFlags = syn,!ack).

Target = <dirección-ip>
Utiliza la dirección IP especificada en lugar de la dirección determinada para la Interface al hacer coincidir la Sequence. Esto es útil si knockd se está ejecutando en un router y deseas hacer algo en respuesta a un intento de conexión real a un host enrutado - por ejemplo, invocar etherwake para enviar un paquete WOL a ese host.
Start_Command = <comando>
Especifica el comando que se ejecutará cuando un cliente haga el port-knock correcto con IPv4. Todas las instancias de %IP% serán reemplazadas con la dirección IP del atacante. La directiva Command es un alias para Start_Command.
Start_Command_6 = <comando>
Especifica el comando que se ejecutará cuando un cliente haga el port-knock correcto con IPv6. Todas las instancias de %IP% serán reemplazadas con la dirección IP del atacante. La directiva Command_6 es un alias para Start_Command_6. Si no está presente, recurrirá automáticamente al mismo valor de Start_Command de IPv4. Puedes usar un valor vacío para forzar que no haga nada.
Cmd_Timeout = <tiempo-de-espera>
Tiempo de espera (en segundos) entre Start_Command y Stop_Command. Esta directiva es opcional, solo se requiere si se utiliza Stop_Command.
Stop_Command = <comando>
Especifica el comando que se ejecutará cuando hayan transcurrido Cmd_Timeout segundos desde que se ejecutó Start_Command. Todas las instancias de %IP% serán reemplazadas con la dirección IP del atacante. Esta directiva es opcional.
Stop_Command_6 = <comando>
Especifica el comando que se ejecutará cuando hayan transcurrido Cmd_Timeout segundos desde que se ejecutó Start_Command_6. Todas las instancias de %IP% serán reemplazadas con la dirección IP del atacante. Esta directiva es opcional. Si no está presente, recurrirá automáticamente al mismo valor de Stop_Command de IPv4. Puedes usar un valor vacío para forzar que no haga nada.

NOTAS DE SEGURIDAD

¡Usar la opción de línea de comandos -l o --lookup para resolver nombres DNS para las entradas de registro puede ser un riesgo de seguridad! Un atacante puede averiguar el primer puerto de una secuencia si puede monitorizar el tráfico DNS del host que ejecuta knockd. Además, un host que se supone que debe ser sigiloso (por ejemplo, descartando paquetes a puertos TCP cerrados en lugar de responder con un paquete ACK+RST) puede delatarse al resolver un nombre DNS si un atacante logra alcanzar el primer puerto (desconocido) de una secuencia.

VER TAMBIÉN

knock es el cliente de port-knock que lo acompaña, aunque telnet o netcat podrían usarse para knocks TCP simples en su lugar. Para knocks más avanzados, consulta hping, sendip o packit.
