KEEPALIVED(8) Manual del Administrador del Sistema KEEPALIVED(8)

NOMBRE

keepalived - servicio de balanceo de carga y alta disponibilidad

SINOPSIS

keepalived [-f|--use-file=FICHERO] [-P|--vrrp] [-C|--check] [-B|--no_bfd] [--all] [-l|--log-console] [-D|--log-detail] [-S|--log-facility={0-7|local{0-7}|user|daemon}] [-g|--log-file=FICHERO] [--flush-log-file] [-G|--no-syslog] [-X|--release-vips] [-V|--dont-release-vrrp] [-I|--dont-release-ipvs] [-R|--dont-respawn] [-n|--dont-fork] [-d|--dump-conf] [-p|--pid=FICHERO] [-r|--vrrp_pid=FICHERO] [-T|--genhash] [-c|--checkers_pid=FICHERO] [-a|--address-monitoring] [-b|--bfd_pid=FICHERO] [-s|--namespace=NOMBRE] [-e|--all-config] [-i|--config-id id] [-x|--snmp] [-A|--snmp-agent-socket=FICHERO] [-u|--umask=NÚMERO] [-m|--core-dump] [-M|--core-dump-pattern[=PATRÓN]] [--signum=SIGFUNC] [-t|--config-test[=FICHERO]] [--perf[={all|run|end}]] [--debug[=debug-options]] [--no-mem-check] [--ignore-sigint] [-v|--version] [-h|--help]

DESCRIPCIÓN

Keepalived proporciona instalaciones sencillas y robustas para balanceo de carga y alta disponibilidad. El marco de balanceo de carga se basa en el conocido y ampliamente utilizado módulo del kernel Linux Virtual Server (IPVS) que proporciona balanceo de carga de Capa 4. Keepalived implementa un conjunto de verificadores para mantener y gestionar dinámicamente y de forma adaptativa un grupo de servidores balanceados según su estado de salud. Keepalived también implementa los protocolos VRRPv2 y VRRPv3 para lograr alta disponibilidad con conmutación por error del director.

OPCIONES

-f, --use-file=FICHERO
Utiliza el fichero de configuración especificado. El fichero de configuración por defecto es "/etc/keepalived/keepalived.conf".
-P, --vrrp
Ejecuta solo el subsistema VRRP. Esto es útil para configuraciones que no usan el balanceador de carga IPVS.
-C, --check
Ejecuta solo el subsistema de verificación de estado (healthcheck). Esto es útil para configuraciones que usan el balanceador de carga IPVS con un único director sin conmutación por error.
-B, --no_bfd
No ejecuta el subsistema BFD.
--all
Ejecuta todos los subsistemas, incluso si no tienen configuración.
-l, --log-console
Registra mensajes en la consola local. El comportamiento por defecto es registrar mensajes en syslog.
-D, --log-detail
Mensajes de registro detallados.
-S, --log-facility={0-7|local{0-7}|user|daemon}
Establece la instalación de syslog a LOG_LOCAL[0-7], LOG_USER o LOG_DAEMON. La instalación de syslog por defecto es LOG_DAEMON.
-g, --log-file=FICHERO
Escribe las entradas de registro en FICHERO. FICHERO tendrá _vrrp, _healthcheckers, y _bfd insertados antes del último '.' en FICHERO para la salida de registro de esos procesos.
--flush-log-file
Si se usa la opción -g, el flujo del fichero de registro se vaciará después de cada escritura.
-G, --no-syslog
No escribir entradas de registro en syslog. Esto puede ser útil si la tasa de escritura de entradas de registro es suficientemente alta como para que syslog las limite por tasa, y se usa la opción -g en su lugar.
-X, --release-vips
Libera la VIP en la transición desde una señal.
-V, --dont-release-vrrp
No elimina las VIPs y VROUTEs de VRRP al detener el demonio. El comportamiento por defecto es eliminar todas las VIPs y VROUTEs cuando keepalived sale.
-I, --dont-release-ipvs
No elimina la topología IPVS al detener el demonio. El comportamiento por defecto es eliminar todas las entradas de la tabla de servidores virtuales IPVS cuando keepalived sale.
-R, --dont-respawn
No reinicia los procesos hijos. El comportamiento por defecto es reiniciar los procesos VRRP y de verificación si alguno de ellos sale.
-n, --dont-fork
No crea un proceso demonio hijo. Esta opción hará que keepalived se ejecute en primer plano.
-d, --dump-conf
Volca los datos de configuración.
-p, --pid=FICHERO
Utiliza el fichero PID especificado para el proceso padre keepalived. El fichero PID por defecto para keepalived es "/run/keepalived.pid", a menos que se esté utilizando un espacio de nombres de red. Véase ESPACIOS DE NOMBRES a continuación para más detalles.
-r, --vrrp_pid=FICHERO
Utiliza el fichero PID especificado para el proceso hijo VRRP. El fichero PID por defecto para el proceso hijo VRRP es "/run/keepalived_vrrp.pid", a menos que se esté utilizando un espacio de nombres de red.
-T, --genhash
Entra en el modo de utilidad genhash. Versiones anteriores de keepalived incluían una utilidad genhash dedicada. Ahora genhash forma parte del código principal. Mantenemos la compatibilidad con la opción de línea de comandos de la utilidad genhash anterior. Para más información, consulte la página del manual genhash(1).
-c, --checkers_pid=FICHERO
Utiliza el fichero PID especificado para el proceso hijo de verificadores. El fichero PID por defecto para el proceso hijo de verificadores es "/run/keepalived_checkers.pid" a menos que se esté utilizando un espacio de nombres de red.
-a, --address-monitoring
Registra todas las adiciones/eliminaciones de direcciones notificadas por netlink.
-b, --bfd_pid=FICHERO
Utiliza el fichero PID especificado para el proceso hijo BFD. El fichero PID por defecto para el proceso hijo BFD es "/run/keepalived_bfd.pid" a menos que se esté utilizando un espacio de nombres de red.
-s, --namespace=NOMBRE
Ejecuta keepalived en el espacio de nombres de red NOMBRE. Véase ESPACIOS DE NOMBRES a continuación para más detalles.
-e, --all-config
No cargar si falta algún fichero de configuración o no se puede leer.
-i, --config-id ID
Utiliza el ID de configuración ID, para configuración condicional (por defecto es el nombre de host sin el nombre de dominio).
-x, --snmp
Habilita el subsistema SNMP.
-A, --snmp-agent-socket=FICHERO
Utiliza el socket especificado para la conexión al agente maestro SNMP.
-u, --umask=NÚMERO
La máscara de permisos especificada en la forma numérica habitual - véase man umask(2)
-m, --core-dump
Anula los límites duros y blandos de RLIMIT_CORE para permitir que keepalived produzca un volcado de memoria (coredump) en caso de un error de segmentación u otro fallo. Esto es muy útil si keepalived se ha compilado con 'make debug'. Los volcados de memoria se crearán en /, a menos que keepalived se ejecute con la opción --dont-fork, en cuyo caso se crearán en el directorio desde el que se ejecutó keepalived, o se crearán en el directorio de un fichero de configuración si el fallo ocurre al leer el fichero.
-M, --core-dump-pattern[=PATRÓN]
Establece la opción --core-dump, y también actualiza /proc/sys/kernel/core_pattern al patrón especificado, o 'core' si no se especifica ninguno. Siempre que el proceso padre no termine de forma anormal, restaurará /proc/sys/kernel/core_pattern a su valor original al salir.

Nota: Esto también afectará a cualquier otro proceso que produzca un volcado de memoria mientras keepalived está en ejecución.

--signum=PATRÓN
Devuelve el número de señal a utilizar para STOP, RELOAD, DATA, STATS,

STATS_CLEAR, JSON y TDATA. Por ejemplo, para detener keepalived en ejecución, ejecute: 
kill -s $(keepalived --signum=STOP) $(cat /run/keepalived.pid)
-t, --config-test[=ARCHIVO]
Keepalived verificará el archivo de configuración y saldrá con un estado de salida distinto de cero si hay errores en la configuración, de lo contrario, saldrá con el estado de salida 0 (ver Estado de salida abajo para más detalles).

En lugar de escribir en syslog, escribirá mensajes de diagnóstico en stderr a menos que se especifique un archivo, en cuyo caso escribirá en el archivo.

--perf[={all|run|end}]
Registra datos de perf para el proceso vrrp. Los datos se escribirán en /perf_vrrp.data. Los datos registrados son para su uso con la herramienta perf.
--no-mem-check
Deshabilita las comprobaciones de memoria como malloc() si se han compilado en keepalived.
--ignore-sigint
Deshabilita el manejo de SIGINT (por defecto, termina keepalived). Esto es necesario para ejecutar keepalived bajo GDB.
--debug[=opciones-debug]]
Habilita opciones de depuración si se han compilado en keepalived. opciones-debug se compone de una secuencia de cadenas del tipo Ulll.
La letra mayúscula especifica la opción de depuración y las letras minúsculas especifican para qué procesos se habilitará la opción.
Si una opción de depuración no va seguida de ninguna letra minúscula, la opción de depuración se habilitará para todos los procesos.
Los caracteres para identificar los procesos son:
Chr Proceso
p Proceso padre
b Proceso BFD
c Proceso checker
v Proceso VRRP

Los caracteres utilizados para identificar las opciones de depuración son:

Chr Opción de depuración
D Volcado de hilo Epoll
E Depuración Epoll
F Depuración de fd VRRP
N Temporizadores Netlink
P Marca de tiempo de red
X Temporizadores Regex
M Depuración de alertas por correo electrónico
T Depuración de temporizadores
S Depuración TSM
R Depuración Regex
B Depuración de conexión SMTP
U Diagnóstico de suma de verificación
O Depuración de proceso de seguimiento
A Depuración de proceso de seguimiento con detalle adicional
C Depuración del analizador (configuración)
H Depuración del checker
Z Depuración de errores de asignación/liberación de memoria
G Depuración de recvmsg() VRRP
J Datos rx de registro de recvmsg() VRRP
V Depuración de scripts
K Volcado de palabras clave

Ejemplo: --debug=DvEcvNR

-v, --version
Muestra la versión y sale.
-h, --help
Muestra este mensaje de ayuda y sale.

Estado de salida:

0
si está OK
1
si no se puede asignar memoria
2
si no se pueden inicializar subsistemas
3
si se ejecuta con --config-test y la configuración no se puede ejecutar
4
si se ejecuta con --config-test y hay errores de configuración pero keepalived se ejecutará después de modificar la configuración
5
si se ejecuta con --config-test y la seguridad de scripts no ha sido habilitada pero los scripts están configurados.

ESPACIOS DE NOMBRES

keepalived puede ejecutarse en un espacio de nombres de red (ver keepalived.conf(5) para detalles de configuración). Cuando se ejecuta en un espacio de nombres de red, también se crea un espacio de nombres de montaje local y /run/keepalived/keepalived_NamespaceName se monta en /run/keepalived. Por defecto, los archivos PID con los nombres predeterminados habituales se crean en /run/keepalived desde la perspectiva de un proceso en el espacio de nombres de montaje, y serán visibles en /run/keepalived/keepalived_NamespaceName para un proceso que se ejecute en el espacio de nombres de montaje predeterminado.

SEÑALES

keepalived reacciona a un conjunto de señales. Puede enviar una señal al proceso padre de keepalived usando:

kill -SEÑAL $(cat /run/keepalived.pid)

o mejor:

kill -s $(keepalived --signum=SIGFUNC) $(cat /run/keepalived.pid)

Tenga en cuenta que si se utiliza la primera opción, -SEÑAL debe ser reemplazado con la señal real que está intentando enviar, por ejemplo, HUP. Entonces se convierte en:

kill -HUP $(cat /run/keepalived.pid)

Las señales distintas de STOP, RELOAD, DATA y STATS pueden cambiar dependiendo del kernel, y también de qué funcionalidad se incluye en la versión de keepalived según las opciones de compilación utilizadas.

HUP o SIGFUNC=RELOAD
Esto hace que keepalived cierre todas las interfaces, recargue su configuración y se inicie con la nueva configuración.
Nota: Si una virtual_ipaddress, virtual_route o virtual_rule se está moviendo de una instancia VRRP a otra, serán necesarias dos recargas, la primera para eliminar la virtual ipaddress/route/rule, y la segunda recarga para añadirla a la instancia VRRP en la que ahora se va a configurar. No hacer esto puede resultar en que la ipaddress/route/rule no se configure en la nueva instancia si ambas instancias, la antigua y la nueva, están en estado master. Generalmente funcionará con una sola recarga, sin embargo, si alguna de las instancias VRRP no está en estado MASTER o si la instancia VRRP a la que se está añadiendo la ipaddress/route/rule está más adelante en el archivo de configuración original que la instancia de la que se está eliminando. Nota2: Si se está ejecutando una configuración con SNMP habilitado, y luego se realiza una recarga con una configuración que no habilita SNMP, no es posible volver a habilitar SNMP posteriormente. La razón de esto no se entiende actualmente.
TERM, INT o SIGFUNC=STOP
keepalived se cerrará.
USR1 o SIGFUNC=DATA
Escribe los datos de configuración en /tmp/keepalived.data o el archivo configurado por state_dump_file
USR2 o SIGFUNC=STATS
Escribe información de estadísticas en /tmp/keepalived.stats o el archivo configurado por stats_dump_file
SIGFUNC=STATS_CLEAR
Escribe información de estadísticas en /tmp/keepalived.stats o el archivo configurado por stats_dump_file y borra los contadores de estadísticas
SIGFUNC=JSON
Escribe los datos de configuración en formato JSON en /tmp/keepalived.json o el archivo configurado por json_dump_file
SIGFUNC=TDATA
Esto hace que keepalived escriba el estado actual de sus hilos internos en el registro

USAR KEEPALIVED CON FIREWALLD

Si está ejecutando un firewall (ver firewalld(8)) debe permitir el tráfico del protocolo VRRP a través del firewall. Por ejemplo, si esta instancia de keepalived(8) tiene un nodo peer en la dirección IPv4 192.168.0.1:

# firewall-cmd \
    --add-rich-rule="rule family='ipv4' \
                     source address='192.168.0.1' \
                     protocol value='vrrp' accept" --permanent
# firewall-cmd --reload
