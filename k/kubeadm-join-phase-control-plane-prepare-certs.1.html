NOMBRE

kubeadm join phase control-plane-prepare certs - Generar los certificados para los nuevos componentes del plano de control

SINOPSIS

kubeadm join phase control-plane-prepare certs [OPCIONES]

DESCRIPCIÓN

Generar los certificados para los nuevos componentes del plano de control

OPCIONES

--apiserver-advertise-address="" Si el nodo debe alojar una nueva instancia del plano de control, la dirección IP en la que el servidor API anunciará que está escuchando. Si no se establece, se utilizará la interfaz de red predeterminada.

--config="" Ruta a un archivo de configuración de kubeadm.

--control-plane=false Crear una nueva instancia del plano de control en este nodo

--discovery-file="" Para el descubrimiento basado en archivos, un archivo o URL desde el cual cargar la información del clúster.

--discovery-token="" Para el descubrimiento basado en tokens, el token utilizado para validar la información del clúster obtenida del servidor API.

--discovery-token-ca-cert-hash=[] Para el descubrimiento basado en tokens, validar que la clave pública de la CA raíz coincide con este hash (formato: ":").

--discovery-token-unsafe-skip-ca-verification=false Para el descubrimiento basado en tokens, permitir la unión sin la fijación de --discovery-token-ca-cert-hash.

--dry-run=false No aplicar ningún cambio; solo mostrar lo que se haría.

--node-name="" Especificar el nombre del nodo.

--tls-bootstrap-token="" Especificar el token utilizado para autenticarse temporalmente con el Plano de Control de Kubernetes mientras se une el nodo.

--token="" Utilizar este token tanto para discovery-token como para tls-bootstrap-token cuando esos valores no se proporcionan.

OPCIONES HEREDADAS DE COMANDOS PADRE

--rootfs="" La ruta al sistema de archivos raíz del host 'real'. Esto hará que kubeadm realice un chroot en la ruta proporcionada.

--version=false --version, --version=raw imprime la información de la versión y sale; --version=vX.Y.Z... establece la versión reportada
