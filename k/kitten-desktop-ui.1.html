Nombre

kitten-desktop-ui - Documentación de kitten

Descripción general

Añadido en la versión 0.43.0.

Los usuarios avanzados de terminales en Linux también suelen preferir usar gestores de ventanas minimalistas en lugar de entornos de escritorio completos. Este kitten ayuda a proporcionar partes del entorno de escritorio que faltan en dichas configuraciones, y lo hace utilizando componentes de interfaz de usuario rápidos y centrados en el teclado, orientados a la terminal. Algunas de sus características son:

  • Reemplazar los diálogos típicos de Abrir/Guardar archivo utilizados en programas gráficos con el rápido y centrado en el teclado kitten choose-files <> que se ejecuta en una superposición de kitty semitransparente.
  • Permitir la gestión basada en línea de comandos de los modos de luz/oscuridad del escritorio.

Cómo instalar

Nota:

Este kitten se basa en el kitten panel <> para proporcionar componentes de interfaz de usuario. Consulta la documentación <#panel-compat> de ese kitten para ver si tu gestor de ventanas funciona con él.

Primero, ejecuta:

kitten desktop-ui enable-portal

Luego, establece las siguientes dos variables de entorno, *en todo el sistema*, lo que significa en /etc/environment o el equivalente para tu distribución:

QT_QPA_PLATFORMTHEME=xdgdesktopportal
GTK_USE_PORTAL=1

Finalmente, reinicia. Ahora, cuando abras un diálogo de archivo en la mayoría de las aplicaciones gráficas, debería abrir el kitten choose-files <> en lugar de un diálogo normal de apertura de archivos. Puedes cambiar el esquema de luz/oscuridad actual de tu escritorio ejecutando:

kitten desktop-ui set-color-scheme dark
kitten desktop-ui set-color-scheme light

Consulta el valor actual usando:

dbus-send --session --print-reply --dest=org.freedesktop.portal.Desktop /org/freedesktop/portal/desktop org.freedesktop.portal.Settings.Read string:org.freedesktop.appearance string:color-scheme

Cómo funciona

Los entornos de escritorio Linux modernos tienen los llamados portales https://flatpak.github.io/xdg-desktop-portal/docs/index.html que fueron inventados para aplicaciones con sandboxing y proporcionan varias facilidades a dichas aplicaciones a través de DBUS, incluyendo diálogos de apertura de archivos, configuraciones comunes del escritorio, etc. Este kitten funciona implementando un backend para algunos de estos servicios.

Las aplicaciones gráficas normales pueden indicarse para que utilicen estos servicios, permitiéndonos así reemplazar partes de la experiencia del escritorio según sea necesario.

Existen múltiples implementaciones competidoras de los backends. Cada entorno de escritorio como KDE o GNOME tiene su propio backend y muchos gestores de ventanas proporcionan implementaciones para algunos backends también. El descubrimiento de servicios y la configuración de qué backend usar se realiza a través del programa xdg-desktop-portal, generalmente que se encuentra en /usr/lib/xdg-desktop-portal.

Se puede configurar mediante archivos en ~/.local/share/xdg-desktop-portal. Consulta la página man portals.conf https://man.archlinux.org/man/portals.conf.5. El comando kitten desktop-ui enable-portal se encarga de la configuración automáticamente. Si deseas personalizar exactamente para qué servicios utilizar este kitten, ejecuta el comando y luego edita el archivo conf que el comando indica que ha parcheado.

Solución de problemas

Primero, asegúrate de que DBUS pueda iniciar el kitten automáticamente cuando sea necesario. Si el kitten aún no se está ejecutando, intenta el siguiente comando:

dbus-send --session --print-reply --dest=org.freedesktop.impl.portal.desktop.kitty \
    /net/kovidgoyal/kitty/portal org.freedesktop.DBus.Properties.GetAll \
    string:net.kovidgoyal.kitty.settings

Si DBUS puede iniciar el kitten o si ya se está ejecutando, imprimirá la propiedad de la versión, de lo contrario fallará con un error. Si falla, comprueba el archivo ~/.local/share/dbus-1/services/org.freedesktop.impl.portal.desktop.kitty.service que debería haber sido creado por el comando enable-portal. Su clave Exec debe apuntar a la ruta completa del ejecutable del kitten.

A continuación, comprueba que el sistema de portales XDG esté utilizando realmente este kitten para su backend de configuración. Ejecuta:

dbus-send --session --print-reply --dest=org.freedesktop.portal.Desktop \
    /org/freedesktop/portal/desktop org.freedesktop.portal.Settings.Read \
    string:net.kovidgoyal.kitty string:status

Si esto devuelve una respuesta, entonces el kitten se está utilizando, como se esperaba. Si devuelve un error de no encontrado, entonces se está utilizando otro backend para la configuración.

Lee la página man de portals.conf y ejecuta:

/usr/lib/xdg-desktop-portal -r v

esto imprimirá mucha información de depuración, que debería decirte qué backend se elige para qué servicio. Lee cuidadosamente la salida de depuración para determinar por qué no se selecciona el kitten.

Si algunas aplicaciones gráficas no utilizan el kitten choose-files para sus diálogos de selección de archivos, asegúrate de que las variables de entorno mencionadas anteriormente estén establecidas. También puedes intentar ejecutar la aplicación gráfica con ellas establecidas explícitamente, como:

QT_QPA_PLATFORMTHEME=xdgdesktopportal GTK_USE_PORTAL=1 mi-app-grafica

Ten en cuenta que no todas las aplicaciones utilizan portales, por lo que si una aplicación en particular falla al usar el portal pero otras funcionan, informa del problema a los desarrolladores de esa aplicación.
