NOMBRE

kubectl edit - Editar un recurso en el servidor

SINOPSIS

kubectl edit [OPCIONES]

DESCRIPCIÓN

Edita un recurso desde el editor predeterminado.

El comando edit permite editar directamente cualquier recurso de la API que se pueda recuperar a través de las herramientas de línea de comandos. Abrirá el editor definido por las variables de entorno KUBE_EDITOR o EDITOR, o recurrirá a 'vi' para Linux o 'notepad' para Windows. Al intentar abrir el editor, primero intentará utilizar el shell que se haya definido en la variable de entorno 'SHELL'. Si esta no está definida, se utilizará el shell predeterminado, que es '/bin/bash' para Linux o 'cmd' para Windows.

Puedes editar múltiples objetos, aunque los cambios se aplican uno a la vez. El comando acepta nombres de archivo así como argumentos de línea de comandos, aunque los archivos a los que apuntes deben ser versiones previamente guardadas de los recursos.

La edición se realiza con la versión de la API utilizada para recuperar el recurso. Para editar usando una versión de API específica, califica completamente el recurso, la versión y el grupo.

El formato predeterminado es YAML. Para editar en JSON, especifica "-o json".

La bandera --windows-line-endings se puede utilizar para forzar finales de línea de Windows, de lo contrario se utilizará el valor predeterminado de su sistema operativo.

En caso de que ocurra un error al actualizar, se creará un archivo temporal en el disco que contendrá sus cambios no aplicados. El error más común al actualizar un recurso es que otro editor cambie el recurso en el servidor. Cuando esto ocurre, tendrás que aplicar tus cambios a la versión más reciente del recurso, o actualizar tu copia temporal guardada para incluir la versión más reciente del recurso.

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignore todos los errores en las plantillas cuando un campo o una clave de mapa falte en la plantilla. Solo se aplica a los formatos de salida go-template y jsonpath.

--field-manager="kubectl-edit" Nombre del gestor utilizado para rastrear la propiedad de los campos.

-f, --filename=[] Nombre de archivo, directorio o URL de los archivos a utilizar para editar el recurso

-k, --kustomize="" Procesa el directorio kustomization. Esta bandera no se puede usar junto con -f o -R.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--output-patch=false Emite el parche si el recurso es editado.

--record=false Registra el comando kubectl actual en la anotación del recurso. Si se establece en falso, no registres el comando. Si se establece en verdadero, registra el comando. Si no se establece, el valor predeterminado es actualizar el valor de la anotación existente solo si ya existe uno.

-R, --recursive=false Procesa el directorio utilizado en -f, --filename recursivamente. Útil cuando deseas gestionar manifiestos relacionados organizados dentro del mismo directorio.

--save-config=false Si es verdadero, la configuración del objeto actual se guardará en su anotación. De lo contrario, la anotación no cambiará. Esta bandera es útil cuando deseas realizar kubectl apply en este objeto en el futuro.

--show-managed-fields=false Si es verdadero, mantén los managedFields al imprimir objetos en formato JSON o YAML.

--subresource="" Si se especifica, edit operará en el subrecurso del objeto solicitado.

--template="" Cadena de plantilla o ruta a archivo de plantilla a usar cuando -o=go-template, -o=go-template-file. El formato de plantilla es plantillas de golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Debe ser uno de: strict (o true), warn, ignore (o false). "true" o "strict" usarán un esquema para validar la entrada y fallarán la solicitud si es inválida. Realizará validación en el lado del servidor si ServerSideFieldValidation está habilitado en el api-server, pero recurrirá a una validación del lado del cliente menos confiable si no. "warn" advertirá sobre campos desconocidos o duplicados sin bloquear la solicitud si la validación de campos del lado del servidor está habilitada en el servidor API, y se comportará como "ignore" de lo contrario. "false" o "ignore" no realizarán ninguna validación de esquema, descartando silenciosamente cualquier campo desconocido o duplicado.

--windows-line-endings=false Predeterminado a los finales de línea nativos de tu plataforma.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario podría ser un usuario regular o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a utilizar

--context="" El nombre del contexto de kubeconfig a utilizar

--disable-compression=false Si es verdadero, desactiva la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará su validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funcionalidades KUBECTL_KUBERC=false o desactivando la funcionalidad KUBERC=off.

--match-server-version=false Requerir que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud CLI

--password="" Contraseña para autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" El tiempo de espera antes de abandonar una única solicitud al servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de espera de las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utilizará el nombre de host utilizado para contactar al servidor

--token="" Token de portador para la autenticación al servidor API

--user="" El nombre del usuario de kubeconfig a utilizar

--username="" Nombre de usuario para autenticación básica al servidor API

--version=false --version, --version=raw imprime la información de versión y sale; --version=vX.Y.Z... establece la versión informada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sal con un código de salida distinto de cero

EJEMPLO

  # Editar el servicio llamado 'registry'
  kubectl edit svc/registry
  # Usar un editor alternativo
  KUBE_EDITOR="nano" kubectl edit svc/registry
  # Editar el job 'myjob' en JSON usando el formato de API v1
  kubectl edit job.v1.batch/myjob -o json
  # Editar el deployment 'mydeployment' en YAML y guardar la configuración modificada en su anotación
  kubectl edit deployment/mydeployment -o yaml --save-config
  # Editar el subrecurso 'status' para el deployment 'mydeployment'
  kubectl edit deployment mydeployment --subresource='status'
