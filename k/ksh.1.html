NOMBRE

ksh, rksh, pfksh - KornShell, un lenguaje de comandos y programación estándar/restringido

NOTA

Actualmente, rksh y pfksh no están disponibles en macOS / Darwin.

SINOPSIS

ksh [ ±abcefhiknoprstuvxBCDP ] [ -R archivo ] [ ±o opción ] ... [ - ] [ arg ... ]

DESCRIPCIÓN

Ksh es un lenguaje de comandos y programación que ejecuta comandos leídos desde un terminal o un archivo. Rksh es una versión restringida del intérprete de comandos ksh; se utiliza para configurar nombres de inicio de sesión y entornos de ejecución cuyas capacidades están más controladas que las del shell estándar. Rpfksh es una versión del shell de perfil del intérprete de comandos ksh; se utiliza para ejecutar comandos con los atributos especificados por los perfiles del usuario (ver pfexec(1)). Ver Invocación a continuación para conocer el significado de los argumentos del shell.

Definiciones.

Un metacaracter es uno de los siguientes caracteres:

; & ( ) ⎪ < > nueva-línea espacio tab

Un espacio en blanco es un tabulador o un espacio. Un identificador es una secuencia de letras, dígitos o guiones bajos que comienza con una letra o un guion bajo. Los identificadores se utilizan como componentes de los nombres de las variables. Un vname es una secuencia de uno o más identificadores separados por un . y opcionalmente precedidos por un .. Los vnames se utilizan como nombres de funciones y variables. Una palabra es una secuencia de caracteres del conjunto de caracteres definido por la configuración regional actual, excluyendo los metacaracteres no citados.

Un comando es una secuencia de caracteres en la sintaxis del lenguaje del shell. El shell lee cada comando y lleva a cabo la acción deseada ya sea directamente o invocando utilidades separadas. Un comando incorporado es un comando que es llevado a cabo por el propio shell sin crear un proceso separado. Algunos comandos son incorporados puramente por conveniencia y no se documentan aquí. Los comandos incorporados que causan efectos secundarios en el entorno del shell y los comandos incorporados que se encuentran antes de realizar una búsqueda de ruta (ver Ejecución a continuación) se documentan aquí. Por razones históricas, algunos de estos comandos incorporados se comportan de manera diferente a otros comandos incorporados y se denominan comandos incorporados especiales.

Comandos.

Un comando simple es una lista de asignaciones de variables (ver Asignaciones de Variables a continuación) o una secuencia de palabras separadas por espacios en blanco que puede ir precedida por una lista de asignaciones de variables (ver Entorno a continuación). La primera palabra especifica el nombre del comando a ejecutar. Excepto como se indica a continuación, las palabras restantes se pasan como argumentos al comando invocado. El nombre del comando se pasa como argumento 0 (ver exec(2)). El valor de un comando simple es su estado de salida; 0-255 si termina normalmente; 256+signum si termina anormalmente (el nombre de la señal correspondiente al estado de salida se puede obtener a través de la opción -l de la utilidad incorporada kill).

Una tubería es una secuencia de uno o más comandos separados por ⎪. La salida estándar de cada comando, excepto el último, está conectada por una tubería(2) a la entrada estándar del siguiente comando. Cada comando, excepto posiblemente el último, se ejecuta como un proceso separado; el shell espera a que el último comando termine. El estado de salida de una tubería es el estado de salida del último comando a menos que la opción pipefail esté habilitada. Cada tubería puede ir precedida por la palabra reservada ! lo que hace que el estado de salida de la tubería sea 0 si el estado de salida del último comando no es cero, y 1 si el estado de salida del último comando es 0.

Una lista es una secuencia de una o más tuberías separadas por ;, &, ⎪&, &&, o ⎪⎪, y opcionalmente terminada por ;, &, o ⎪&. De estos cinco símbolos, ;, &, y ⎪& tienen la misma precedencia, que es menor que la de && y ⎪⎪. Los símbolos && y ⎪⎪ también tienen la misma precedencia. Un punto y coma (;) causa la ejecución secuencial de la tubería anterior; un ampersand (&) causa la ejecución asíncrona de la tubería anterior (es decir, el shell *no* espera a que termine esa tubería). El símbolo ⎪& causa la ejecución asíncrona de la tubería anterior con una tubería bidireccional establecida con el shell padre; la entrada y salida estándar de la tubería generada se pueden escribir y leer desde el shell padre aplicando los operadores de redirección <& y >& con el argumento p a los comandos y usando la opción -p de los comandos incorporados read y print descritos más adelante. El símbolo && (⎪⎪) causa que la lista que le sigue se ejecute solo si la tubería anterior devuelve un valor cero (no cero). Uno o más saltos de línea pueden aparecer en una lista en lugar de un punto y coma, para delimitar un comando. El primer elemento de la primera tubería de una lista que es un comando simple que no comienza con una redirección, y que no ocurre dentro de una lista de while, until, o if, puede ir precedido por un punto y coma. Este punto y coma se ignora a menos que la opción showme esté habilitada como se describe con el comando incorporado set a continuación.

Un comando es un comando simple o uno de los siguientes. A menos que se indique lo contrario, el valor devuelto por un comando es el del último comando simple ejecutado en el comando.

for vname [ in palabra ... ] ;do lista ;done
Cada vez que se ejecuta un comando for, vname se establece en la siguiente palabra tomada de la lista in palabra .... Si se omite in palabra ..., entonces el comando for ejecuta la lista do una vez por cada parámetro posicional que esté establecido, comenzando por 1 (ver Expansión de Parámetros a continuación). La ejecución termina cuando no quedan más palabras en la lista.
for (( [exp1] ; [exp2] ; [exp3] )) ;do lista ;done
La expresión aritmética exp1 se evalúa primero (ver Evaluación aritmética a continuación). La expresión aritmética exp2 se evalúa repetidamente hasta que se evalúa como cero y cuando es distinto de cero, se ejecuta la lista y se evalúa la expresión aritmética exp3. Si se omite alguna expresión, se comporta como si se evaluara a 1.
select vname [ in palabra ... ] ;do lista ;done
Un comando select imprime en la salida estándar de error (descriptor de archivo 2) el conjunto de palabras, cada una precedida por un número. Si se omite in palabra ..., entonces se utilizan los parámetros posicionales comenzando por 1 (ver Expansión de Parámetros a continuación). Se imprime el prompt PS3 y se lee una línea de la entrada estándar. Si esta línea consiste en el número de una de las palabras listadas, entonces el valor de la variable vname se establece en la palabra correspondiente a este número. Si esta línea está vacía, la lista de selección se imprime de nuevo. De lo contrario, el valor de la variable vname se establece en nulo. El contenido de la línea leída de la entrada estándar se guarda en la variable REPLY. La lista se ejecuta para cada selección hasta que se encuentra un break o un fin de archivo. Si la variable REPLY se establece en nulo por la ejecución de lista, entonces la lista de selección se imprime antes de mostrar el prompt PS3 para la siguiente selección.
case palabra in [ [(]patrón [ ⎪ patrón ] ... ) lista ;; ] ... esac
Un comando case ejecuta la lista asociada con el primer patrón que coincida con palabra. La forma de los patrones es la misma que la utilizada para la generación de nombres de archivo (ver Generación de Nombres de Archivo a continuación). if lista ;then lista [ ;elif lista ;then lista ] ... [ ;else lista ] ;fi
Se ejecuta la lista que sigue a if y, si devuelve un estado de salida cero, se ejecuta la lista que sigue al primer then. De lo contrario, se ejecuta la lista que sigue a elif y, si su valor es cero, se ejecuta la lista que sigue al siguiente then. Si falla cada elif lista sucesivo, se ejecuta la lista del else. Si la lista del if tiene un estado de salida distinto de cero y no hay una lista del else, entonces el comando if devuelve un estado de salida cero.
while lista ;do lista ;done
until lista ;do lista ;done
Un comando while ejecuta repetidamente la lista del while y, si el estado de salida del último comando de la lista es cero, ejecuta la lista del do; de lo contrario, el bucle termina. Si no se ejecuta ningún comando en la lista del do, entonces el comando while devuelve un estado de salida cero; until puede usarse en lugar de while para negar la prueba de terminación del bucle.
((expresión))

La expresión se evalúa utilizando las reglas de evaluación aritmética descritas a continuación. Si el valor de la expresión aritmética no es cero, el estado de salida es 0, de lo contrario el estado de salida es 1.
(lista)

Ejecuta lista en un entorno separado. Tenga en cuenta que si se necesitan dos paréntesis abiertos adyacentes para anidar, se debe insertar un espacio para evitar la evaluación como un comando aritmético como se describe anteriormente.
{ lista;}

Simplemente se ejecuta lista. Tenga en cuenta que a diferencia de los metacaracteres ( y ), { y } son palabras reservadas y deben aparecer al principio de una línea o después de un ; para ser reconocidas.
[[ expresión ]]

Evalúa expresión y devuelve un estado de salida cero cuando expresión es verdadera. Consulte Expresiones Condicionales a continuación, para una descripción de expresión.
function nombrevar { lista ;}
nombrevar () { lista ;}
Define una función a la que se hace referencia por nombrevar. Una función cuyo nombrevar contiene un . se denomina función de disciplina y la porción del nombrevar anterior al último . debe referirse a una variable existente. El cuerpo de la función es la lista de comandos entre { y }. Una función definida con la sintaxis function nombrevar también se puede utilizar como argumento para el comando especial incorporado . para obtener un comportamiento equivalente como si se hubiera utilizado la sintaxis nombrevar() para definirla. (Véase Funciones a continuación.)

Define o utiliza el espacio de nombres identificador y ejecuta los comandos en lista en este espacio de nombres. (Véase Espacios de Nombres a continuación.)
& [ nombre [ arg... ] ]
Hace que los comandos de lista subsiguientes terminados por & se coloquen en el grupo de trabajos en segundo plano nombre. Si se omite nombre, se utiliza un grupo predeterminado sin nombre. Los comandos en un grupo en segundo plano con nombre pueden ejecutarse de forma remota.

De lo contrario, se ejecuta pipeline y se imprimen en la salida de error estándar el tiempo transcurrido, así como el tiempo de usuario y sistema. La variable TIMEFORMAT puede establecerse en una cadena de formato que especifica cómo se deben mostrar los datos de temporización. Consulte Variables del Shell a continuación para obtener una descripción de la variable TIMEFORMAT.

Asignaciones de Variables.

Una o más asignaciones de variables pueden iniciar un comando simple o pueden ser argumentos para los comandos incorporados especiales typeset, enum, export, o readonly, así como para otros comandos de declaración creados como tipos. La sintaxis de una asignación tiene la forma:

nombrevar=palabra
nombrevar[palabra]=palabra
No se permite espacio entre nombrevar y el = ni entre = y palabra.
nombrevar=(lista_asignación)
No se permite espacio entre nombrevar y el =. La variable nombrevar se anula antes de la asignación. Una lista_asignación puede ser una de las siguientes:
palabra ...
Asignación de array indexado.
[palabra]=palabra ...
Asignación de array asociativo. Si va precedido por typeset -a, creará un array indexado en su lugar.
asignación ...
Asignación de variable compuesta. Esto crea una variable compuesta nombrevar con subvariables de la forma nombrevar.nombre, donde nombre es la parte del nombre de la asignación. El valor de nombrevar contendrá todos los elementos de asignación. Las asignaciones adicionales realizadas a subvariables de nombrevar también se mostrarán como parte del valor de nombrevar. Si no se especifican asignaciones, nombrevar será una variable compuesta que permitirá definir elementos hijos subsiguientes.
typeset [opciones] asignación ...
Asignación de variable anidada. Se pueden especificar múltiples asignaciones separando cada una con un ;. El valor anterior se anula antes de la asignación. Otros comandos de declaración como readonly, enum y otros comandos de declaración pueden usarse en lugar de typeset.
. archivo
Incluye los comandos de asignación contenidos en archivo.

Además, se puede usar += en lugar de = para indicar que se añada o se concatene al valor anterior. Cuando += se aplica a un tipo aritmético, palabra se evalúa como una expresión aritmética y se suma al valor actual. Cuando se aplica a una variable de cadena, el valor definido por palabra se concatena al valor. Para asignaciones compuestas, el valor anterior no se anula y los nuevos valores se añaden a los actuales siempre que los tipos sean compatibles.

El lado derecho de una asignación de variable se somete a toda la expansión enumerada a continuación, excepto la división de palabras, la expansión de llaves y la generación de nombres de archivo. Cuando el lado izquierdo es una asignación de variable compuesta y el lado derecho es el nombre de una variable compuesta, la variable compuesta de la derecha se copiará o se añadirá a la variable compuesta de la izquierda.

Comentarios.

Una palabra que comienza con # hace que esa palabra y todos los caracteres siguientes hasta un salto de línea sean ignorados.

Alias.

La primera palabra de cada comando se reemplaza por el texto de un alias si se ha definido un alias para esta palabra. Un nombre de alias consiste en cualquier número de caracteres excluyendo metacaracteres, caracteres de comillas, caracteres de expansión de archivos, caracteres de expansión de parámetros y sustitución de comandos, los caracteres / y =. La cadena de reemplazo puede contener cualquier script válido, incluidos los metacaracteres enumerados anteriormente. La primera palabra de cada comando en el texto reemplazado, excepto aquellas que están en proceso de ser reemplazadas, se probará para detectar alias. Si el último carácter del valor del alias es un espacio en blanco, entonces la palabra que sigue al alias también se verificará para la sustitución de alias. Los alias se pueden usar para redefinir comandos incorporados, pero no se pueden usar para redefinir las palabras reservadas enumeradas anteriormente. Los alias se pueden crear y listar con el comando alias y se pueden eliminar con el comando unalias.

El aliasing se realiza cuando se leen los scripts, no mientras se ejecutan. Por lo tanto, para que un alias tenga efecto, el comando de definición de alias debe ejecutarse antes de que se lea el comando que hace referencia al alias.

Los siguientes alias están compilados en el shell, pero se pueden anular o redefinir:

autoload=′typeset -fu′
bool=′_Bool′
command=′command ′
compound=′typeset -C′
fc=hist
float=′typeset -lE′
functions=′typeset -f′
hash=′alias -t --′
history=′hist -l′
integer=′typeset -li′
nameref=′typeset -n′
nohup=′nohup ′
r=′hist -s′
redirect=′command exec′
source=′command .′
stop=′kill -s STOP′
suspend=′kill -s STOP "$$"′
type=′whence -v′

Sustitución de la tilde.

Después de realizar la sustitución de alias, cada palabra se comprueba para ver si comienza con un ~ sin comillas. Para la sustitución de la tilde, palabra también se refiere a la porción de palabra de la expansión de parámetros (ver Expansión de Parámetros más abajo). Si lo hace, entonces la palabra hasta un / se comprueba para ver si coincide con un nombre de usuario en la base de datos de contraseñas (ver getpwname(3).) Si se encuentra una coincidencia, el ~ y el nombre de inicio de sesión coincidente se reemplazan por el directorio de inicio de sesión del usuario coincidente. Si no se encuentra ninguna coincidencia, el texto original queda sin cambios. Un ~ por sí solo, o delante de un /, se reemplaza por $HOME. Un ~ seguido de un + o - se reemplaza por el valor de $PWD y $OLDPWD respectivamente. Un ~ seguido de {fd} donde fd es un número de descriptor de archivo o el nombre de una variable cuyo valor es un descriptor de archivo, se reemplaza por una cadena que es el equivalente al nombre de ruta del archivo o directorio correspondiente a este descriptor de archivo.

Además, al expandir una asignación de variable, la sustitución de tilde se intenta cuando el valor de la asignación comienza con un ~, y cuando un ~ aparece después de dos puntos (:). Los dos puntos (:) también terminan un nombre de inicio de sesión de ~.

Sustitución de Comando.

La salida estándar de una lista de comandos encerrada entre paréntesis precedida por un signo de dólar ( $(lista) ), o en un grupo de llaves precedido por un signo de dólar ( ${ lista;} ), o entre un par de comillas invertidas (``) puede usarse como parte o la totalidad de una palabra; se eliminan las nuevas líneas finales. En el segundo caso, el { y } se tratan como palabras reservadas, de modo que { debe ir seguido de un espacio en blanco y } debe aparecer al principio de la línea o seguir a un ;. En la tercera forma (obsoleta), la cadena entre las comillas se procesa para caracteres de comillas especiales antes de ejecutar el comando (ver Comillas más abajo). La sustitución de comando $(cat file) puede reemplazarse por el equivalente pero más rápido $(<file). La sustitución de comando $(n<#) se expandirá al desplazamiento de bytes actual para el descriptor de archivo n. Excepto para la segunda forma, la lista de comandos se ejecuta en un subshell para que no haya efectos secundarios posibles. Para la segunda forma, el } final se reconocerá como una palabra reservada después de cualquier token.

Sustitución Aritmética.

Una expresión aritmética encerrada entre dobles paréntesis precedida por un signo de dólar ( $(()) ) se reemplaza por el valor de la expresión aritmética dentro de los dobles paréntesis.

Sustitución de Procesos.

Cada argumento de comando de la forma <(lista) o >(lista) ejecutará el proceso lista de forma asíncrona conectado a algún archivo en /dev/fd si este directorio existe, o de lo contrario, a un fifo en un directorio temporal. El nombre de este archivo se convertirá en el argumento para el comando. Si se selecciona la forma con >, entonces la escritura en este archivo proporcionará entrada para lista. Si se usa <, entonces el archivo pasado como argumento contendrá la salida del proceso lista. Por ejemplo,

paste <(cut -f1 file1) <(cut -f3 file2) | tee >(process1) >(process2)

corta los campos 1 y 3 de los archivos file1 y file2 respectivamente, pega los resultados juntos y los envía a los procesos process1 y process2, además de ponerlos en la salida estándar. Tenga en cuenta que el archivo, que se pasa como argumento al comando, es una pipe(2) de UNIX, por lo que los programas que esperan hacer lseek(2) en el archivo no funcionarán.

La sustitución de procesos de la forma <(lista) también se puede usar con el operador de redirección <, que hace que la salida de lista sea la entrada estándar o la entrada para cualquier descriptor de archivo que se especifique.

Expansión de Parámetros.

Un parámetro es una variable, uno o más dígitos, o cualquiera de los caracteres *, @, #, ?, -, $ y !. Una variable se denota por un nombre de variable (vname). Para crear una variable cuyo nombre de variable (vname) contenga un ., debe existir previamente una variable cuyo nombre de variable (vname) consista en todo lo anterior al último .. Una variable tiene un valor y cero o más atributos. Las variables pueden asignarse valores y atributos usando el comando incorporado especial typeset. Los atributos admitidos por el shell se describen más adelante con el comando incorporado especial typeset. Las variables exportadas pasan valores y atributos al entorno.

El shell admite matrices indexadas y asociativas. Un elemento de una variable de matriz se referencia mediante un subíndice. Un subíndice para una matriz indexada se denota por una expresión aritmética (ver Evaluación aritmética más abajo) entre un [ y un ]. Para asignar valores a una matriz indexada, use nombre de variable (vname)=(valor ...) o set -A nombre de variable (vname) valor ... . El valor de todos los subíndices no negativos debe estar en el rango de 0 a 4,194,303. Un subíndice negativo se trata como un desplazamiento desde el índice máximo actual +1, de modo que -1 se refiere al último elemento. Las matrices indexadas se pueden declarar con la opción -a de typeset. Las matrices indexadas no necesitan declararse. Cualquier referencia a una variable con un subíndice válido es legal y se creará una matriz si es necesario.

Una matriz asociativa se crea con la opción -A de typeset. Un subíndice para una matriz asociativa se denota por una cadena encerrada entre [ y ].

Referenciar cualquier matriz sin un subíndice es equivalente a referenciar la matriz con el subíndice 0.

El valor de una variable puede asignarse escribiendo:

nombre de variable (vname)=valor [ nombre de variable (vname)=valor ] ...

o

nombre de variable (vname)[subíndice]=valor [ nombre de variable (vname)[subíndice]=valor ] ...
Tenga en cuenta que no se permite espacio antes o después del =.

Los atributos asignados por el comando incorporado especial typeset se aplican a todos los elementos de la matriz. Un elemento de matriz puede ser una variable simple, una variable compuesta o una variable de matriz. Un elemento de una matriz indexada puede ser una matriz indexada o una matriz asociativa. Un elemento de una matriz asociativa también puede ser cualquiera de los dos. Para referirse a un elemento de matriz que forma parte de otro elemento de matriz, concatene el subíndice entre corchetes. Por ejemplo, para referirse al elemento foobar de una matriz asociativa definida como el tercer elemento de la matriz indexada, use ${nombre de variable (vname)[3][foobar]}

Un nameref (referencia de nombre) es una variable que es una referencia a otra variable. Se crea un nameref con el atributo -n de typeset. El valor de la variable en el momento del comando typeset se convierte en la variable a la que se hará referencia cada vez que se utilice el nameref. El nombre de un nameref no puede contener un .. Cuando un nombre de variable o función contiene un ., y la porción del nombre hasta el primer . coincide con el nombre de un nameref, la variable a la que se hace referencia se obtiene reemplazando la porción del nameref con el nombre de la variable a la que se hace referencia mediante el nameref. Si se utiliza un nameref como índice de un bucle for, se establece una referencia de nombre para cada elemento de la lista. Un nameref proporciona una forma conveniente de referirse a la variable dentro de una función cuyo nombre se pasa como argumento a una función. Por ejemplo, si el nombre de una variable se pasa como primer argumento a una función, el comando

typeset -n var=$1

dentro de la función hace que las referencias y asignaciones a var sean referencias y asignaciones a la variable cuyo nombre se ha pasado a la función.

Si se establece alguno de los atributos de punto flotante, -E, -F o -X, o el atributo entero, -i, para nombre de variable (vname), entonces el valor está sujeto a evaluación aritmética como se describe a continuación.

Los parámetros posicionales, parámetros denotados por un número, pueden asignarse valores con el comando incorporado especial set. El parámetro $0 se establece a partir del argumento cero cuando se invoca el shell.

El carácter $ se utiliza para introducir parámetros sustituibles.

${parámetro}
El shell lee todos los caracteres desde ${ hasta el } coincidente como parte de la misma palabra, incluso si contiene llaves o metacaracteres. Se sustituye el valor, si lo hay, del parámetro. Las llaves son necesarias cuando parámetro va seguido de una letra, un dígito o un guion bajo que no debe interpretarse como parte de su nombre, cuando el nombre de la variable contiene un .. Las llaves también son necesarias cuando una variable se indexa, a menos que forme parte de una Expresión Aritmética o una Expresión Condicional. Si parámetro es uno o más dígitos, entonces es un parámetro posicional. Un parámetro posicional de más de un dígito debe estar encerrado entre llaves. Si parámetro es * o @, entonces se sustituyen todos los parámetros posicionales, comenzando por $1 (separados por un carácter separador de campo). División de Campos.

Después de la expansión de parámetros y la sustitución de comandos, los resultados de las sustituciones se escanean en busca de los caracteres separadores de campo (los que se encuentran en IFS) y se dividen en campos distintos donde se encuentran dichos caracteres. Los campos nulos explícitos ("" o '') se conservan. Los campos nulos implícitos (los que resultan de *parámetros* que no tienen valores o sustituciones de comandos sin salida) se eliminan.

Si la opción braceexpand (-B) está establecida, entonces cada uno de los campos resultantes de IFS se verifica para ver si contiene uno o más de los patrones de llaves {*,*}, {l1..l2}, {n1..n2}, {n1..n2% fmt}, {n1..n2..n3}, o {n1..n2..n3%fmt}, donde * representa cualquier carácter, l1,l2 son letras y n1,n2,n3 son números con signo y fmt es un formato especificado como el utilizado por printf. En cada caso, se crean campos anteponiendo los caracteres antes del { y añadiendo los caracteres después del } a cada una de las cadenas generadas por los caracteres entre el { y el }. Los campos resultantes se verifican para ver si tienen algún patrón de llaves.

En la primera forma, se crea un campo por cada cadena entre { y ,, entre , y ,, y entre , y }. La cadena representada por * puede contener caracteres { y } anidados coincidentes sin comillas. De lo contrario, cada { y } con * debe ser citado.

En la segunda forma, l1 y l2 deben ser ambos caracteres en mayúsculas o ambos en minúsculas en la configuración regional C. En este caso, se crea un campo por cada carácter desde l1 hasta l2.

En las formas restantes, se crea un campo por cada número que comienza en n1 y continúa hasta que alcanza n2, incrementando n1 en n3. Los casos en los que n3 no se especifica se comportan como si n3 fuera 1 si n1<=n2 y -1 de lo contrario. Si las formas que especifican %fmt se pueden especificar cualesquiera flags de formato, anchos y precisiones, y fmt puede terminar en cualquiera de los especificadores cdiouxX. Por ejemplo, {a,z}{1..5..3%02d}{b..c}x se expande a los 8 campos, a01bx, a01cx, a04bx, a04cx, z01bx, z01cx, z04bx y z4cx.

Generación de Nombres de Archivo.

Después de la división, cada campo se escanea en busca de los caracteres *, ?, ( y [ a menos que la opción -f se haya establecido. Si aparece uno de estos caracteres, la palabra se considera un *patrón*. Cada componente del nombre de archivo que contenga algún carácter de patrón se reemplaza por un conjunto ordenado lexicográficamente de nombres que coinciden con el patrón de ese directorio. Si no se encuentra ningún nombre de archivo que coincida con el patrón, ese componente del nombre de archivo se deja sin cambios, a menos que el patrón esté precedido por ∼(N) en cuyo caso se elimina como se describe a continuación. Si FIGNORE se establece, entonces cada componente del nombre de archivo que coincida con el patrón definido por el valor de FIGNORE se ignora al generar los nombres de archivo coincidentes. Los nombres . y .. también se ignoran. Si FIGNORE no está establecido, el carácter . al principio de cada componente del nombre de archivo se ignorará a menos que el primer carácter del patrón correspondiente a este componente sea el carácter . mismo. Coincide con cualquier cadena, incluida la cadena nula. Cuando se utiliza para la expansión de nombres de archivo, si la opción globstar está activada, un patrón aislado de dos * adyacentes coincidirá con todos los archivos y cero o más directorios y subdirectorios. Si va seguido de una /, solo coincidirán directorios y subdirectorios.
?
Coincide con cualquier carácter individual.
[...]

ARITHMETIC EVALUATION

Arithmetic expansion is an expression of the form $((expression)). The shell expands the expression and evaluates it as an arithmetic expression. The result of the evaluation is the expansion. Integers are supported. The syntax rules for the expression are the same as for the shell arithmetic command `((`. The result of the expansion is shell integer representation of the value of the expression.

An arithmetic expression is any expression that can be passed as an argument to the arithmetic command `((`. The precedence, associativity, and syntax of all operators apply in the same way as in the C language. Only the following constructs are accepted:

  • An arithmetic expression is a sequence of

    expression

    terms, separated by commas. The value of the arithmetic expression is the value of the last term.

  • Variables may be referenced by name without using the parameter expansion syntax (see shell parameters). When a variable is referenced, its value is evaluated as an arithmetic expression.

Arithmetic variables can be specified as floating point with the -f option of the typeset built-in command. The variable is treated as a double precision floating point number. Arithmetic expressions can be passed as argument to shell builtins. The shell treats the argument as an arithmetic expression and the return status is 0 if the expression is non-zero, and 1 if the expression is zero.

The -s option of the set built-in command can be used to sort its arguments or to sort indexed arrays, indexed arrays of compound variables, and indexed arrays of types (see "Type Variables" section below). Prompting.

When used interactively, the shell prompts with the value of PS1 after expanding it for parameter expansion, command substitution, and arithmetic substitution, before reading a command. In addition, each single ! in the prompt is replaced by the command number. A !! is required to place ! in the prompt. If at any time a new-line is typed and further input is needed to complete a command, then the secondary prompt (i.e., the value of PS2) is issued.

Before a command is executed, its input and output may be redirected using a special notation interpreted by the shell. The following may appear anywhere in a simple-command or may precede or follow a command and are not passed on to the invoked command. Command substitution, parameter expansion, and arithmetic substitution occur before word or digit is used except as noted below. File name generation occurs only if the shell is interactive and the pattern matches a single file. Field splitting is not performed.

In each of the following redirections, if file is of the form /dev/sctp/host/port, /dev/tcp/host/port, or /dev/udp/host/port, where host is a hostname or host address, and port is a service given by name or an integer port number, then the redirection attempts to make a tcp, sctp or udp connection to the corresponding socket.

Funciones.

Por razones históricas, existen dos formas de definir funciones, la sintaxis nombre() y la sintaxis function nombre, descritas en la sección Comandos anterior. Las funciones del shell se leen y se almacenan internamente. Los nombres de alias se resuelven cuando se lee la función. Las funciones se ejecutan como comandos con los argumentos pasados como parámetros posicionales. (Ver Ejecución más abajo).

Las funciones definidas por la sintaxis function nombre y llamadas por nombre se ejecutan en el mismo proceso que el llamador y comparten todos los archivos y el directorio de trabajo actual con el llamador. Las trampas (traps) capturadas por el llamador se restablecen a su acción predeterminada dentro de la función. Una condición de trampa que no es capturada o ignorada por la función hace que la función termine y la condición se pase al llamador. Una trampa en EXIT establecida dentro de una función se ejecuta en el entorno del llamador después de que la función se completa. Normalmente, las variables se comparten entre el programa llamador y la función. Sin embargo, el comando especial incorporado typeset utilizado dentro de una función define variables locales cuyo ámbito incluye la función actual. Estas pueden pasarse a las funciones que llaman en la lista de asignación de variables que precede a la llamada o como argumentos pasados como referencias de nombre. Los errores dentro de las funciones devuelven el control al llamador.

Las funciones definidas con la sintaxis nombre() y las funciones definidas con la sintaxis function nombre que se invocan con el comando especial incorporado . se ejecutan en el entorno del llamador y comparten todas las variables y trampas con el llamador. Los errores dentro de la ejecución de estas funciones hacen que el script que las contiene aborte.

El comando especial incorporado return se utiliza para retornar de las llamadas a funciones.

Los nombres de las funciones se pueden listar con la opción -f o +f del comando especial incorporado typeset. El texto de las funciones, cuando esté disponible, también se listará con -f. Las funciones se pueden anular con la opción -f del comando especial incorporado unset.

Normalmente, las funciones se anulan cuando el shell ejecuta un script de shell. Las funciones que necesitan definirse en invocaciones separadas del shell deben colocarse en un directorio y la variable FPATH debe contener el nombre de este directorio. También pueden especificarse en el archivo ENV.

Si la variable .sh.value se asigna un valor dentro de la función de disciplina, la variable referenciada se evaluará a este valor en su lugar. Si la disciplina set está definida para una variable, se invoca cada vez que se asigna un valor a la variable dada. Si la disciplina append está definida para una variable, se invoca cada vez que se agrega un valor a la variable dada. La variable .sh.value recibe el valor de la variable antes de invocar la disciplina, y la variable se asignará el valor de .sh.value después de que la disciplina se complete. Si .sh.value se anula dentro de la disciplina, ese valor no cambia. Si la disciplina unset está definida para una variable, se invoca cada vez que se anula la variable dada. La variable no se anulará a menos que se anule explícitamente desde dentro de esta función de disciplina.

La variable .sh.name contiene el nombre de la variable para la cual se llama la función de disciplina, .sh.subscript es el subíndice de la variable, y .sh.value contendrá el valor que se está asignando dentro de la función de disciplina set. La variable _ es una referencia a la variable, incluido el subíndice si lo hay. Para la disciplina set, cambiar .sh.value cambiará el valor que se asignará. Finalmente, la expansión ${var.name}, cuando name es el nombre de una disciplina, y no hay una variable con este nombre, es equivalente a la sustitución de comando ${ var.name;}.

Espacios de nombres.

Los comandos y funciones que se ejecutan como parte de la lista de un comando namespace que modifican variables o crean nuevas, crean una nueva variable cuyo nombre es el nombre del espacio de nombres dado por identificador precedido por .. Cuando se referencia una variable cuyo nombre es nombre, primero se busca usando .identificador.nombre. De manera similar, una función definida por un comando en la lista de namespace se crea utilizando el nombre del espacio de nombres precedido por un ..

Cuando la lista de un comando namespace contiene un comando namespace, los nombres de las variables y funciones que se crean consisten en el nombre de la variable o función precedido por la lista de identificadores, cada uno precedido por ..

Fuera de un espacio de nombres, una variable o función creada dentro de un espacio de nombres se puede referenciar precediéndola con el nombre del espacio de nombres.

Por defecto, las variables que comienzan con .sh están en el espacio de nombres sh.

Variables de tipo.

Las variables tipadas proporcionan una forma de crear estructuras de datos y objetos. Un tipo puede definirse ya sea por una biblioteca compartida, por el comando incorporado enum descrito a continuación, o utilizando la nueva opción -T del comando incorporado typeset. Con la opción -T de typeset, el nombre del tipo, especificado como un argumento de opción para -T, se establece con una asignación de variable compuesta que define el tipo. Las definiciones de funciones pueden aparecer dentro de la asignación de variable compuesta y estas se convierten en funciones de disciplina para este tipo y pueden ser invocadas o redefinidas por cada instancia del tipo. El nombre de función create se trata especialmente. Se invoca para cada instancia del tipo que se crea, pero no se hereda y no puede ser redefinida para cada instancia.

Cuando se define un tipo, se agrega un comando especial incorporado con ese nombre. Estos incorporados son comandos de declaración y siguen las mismas reglas de expansión que todos los comandos especiales incorporados descritos a continuación que van precedidos por ††. Estos comandos pueden usarse posteriormente dentro de definiciones de tipos adicionales. La página man para estos comandos se puede generar utilizando la opción --man o cualquiera de las otras opciones -- descritas con getopts. Las opciones -r, -a, -A, -h y -S de typeset están permitidas con cada uno de estos nuevos comandos incorporados.

Se crea una instancia de un tipo invocando el nombre del tipo seguido de uno o más nombres de instancia. Cada instancia del tipo se inicializa con una copia de las subvariables, excepto para las subvariables que se definen con la opción -S. Las variables definidas con -S son compartidas por todas las instancias del tipo. Cada instancia puede cambiar el valor de cualquier subvariable y también puede definir nuevas funciones de disciplina con los mismos nombres que las definidas por la definición del tipo, así como cualquier nombre de disciplina estándar. No se pueden definir subvariables adicionales para ninguna instancia.

Al definir un tipo, si el valor de una subvariable no está establecido y se especifica el atributo -r, esto hace que la subvariable sea una subvariable requerida. Cada vez que se crea una instancia de un tipo, se deben especificar todas las subvariables requeridas. Estas subvariables se vuelven de solo lectura en cada instancia.

Cuando se invoca unset en una subvariable dentro de un tipo, y el atributo -r no se ha especificado para este campo, el valor se restablece al valor predeterminado asociado con el tipo. Invocar unset en una instancia de tipo que no está contenida dentro de otro tipo elimina todas las subvariables y la variable misma.

Una definición de tipo puede derivarse de otra definición de tipo al definir el primer nombre de subvariable como _ y definir su tipo como el tipo base. Cualquier definición restante serán adiciones y modificaciones que se aplican al nuevo tipo. Si el nuevo nombre de tipo es el mismo que el del tipo base, el tipo será reemplazado y el tipo original ya no será accesible.

El comando typeset con la opción -T y sin argumento de opción u operandos escribirá todas las definiciones de tipo en la salida estándar en un formato que se puede leer para crear todos los tipos.

Trabajos.

Si la opción monitor del comando set está activada, un shell interactivo asocia un trabajo con cada pipeline. Mantiene una tabla de trabajos actuales, impresa por el comando jobs, y les asigna números enteros pequeños. Cuando se inicia un trabajo de forma asíncrona con &, el shell imprime una línea que se parece a:

[1] 1234

indicando que

Jobs.

El trabajo que se inició de forma asíncrona fue el trabajo número 1 y tenía un proceso (de nivel superior), cuyo id de proceso era 1234.

Este párrafo y el siguiente requieren características que no están en todas las versiones de UNIX y pueden no aplicarse. Si está ejecutando un trabajo y desea hacer otra cosa, puede presionar la tecla ^Z (control-Z) que envía una señal STOP al trabajo actual. El shell normalmente indicará que el trabajo se ha "Detenido" y mostrará otro prompt. Luego puede manipular el estado de este trabajo, poniéndolo en segundo plano con el comando bg, o ejecutar otros comandos y luego eventualmente traer el trabajo de vuelta al primer plano con el comando de primer plano fg. Un ^Z entra en vigor inmediatamente y es como una interrupción en el sentido de que la salida pendiente y la entrada no leída se descartan cuando se escribe.

Un trabajo que se ejecuta en segundo plano se detendrá si intenta leer desde la terminal. Normalmente se permite que los trabajos en segundo plano produzcan salida, pero esto se puede deshabilitar dando el comando stty to-stop. Si configura esta opción de tty, los trabajos en segundo plano se detendrán cuando intenten producir salida, tal como lo hacen cuando intentan leer entrada.

Un conjunto de trabajos es una colección de trabajos iniciados con lista & asociados a un nombre.

Hay varias formas de referirse a los trabajos en el shell. Un trabajo puede ser referido por el id del proceso de cualquiera de los procesos del trabajo o por uno de los siguientes:

%número
El trabajo con el número dado.
conjunto
Todos los trabajos en el conjunto de trabajos llamado por conjunto.
conjunto.número
El número de trabajo número en el conjunto de trabajos llamado por conjunto.
%cadena
Cualquier trabajo cuya línea de comando comience con cadena.
%?cadena
Cualquier trabajo cuya línea de comando contenga cadena.
%%
Trabajo actual.
%+
Equivalente a %%.
%-
Trabajo anterior. Además, a menos que se indique lo contrario, siempre que se pueda especificar un trabajo, el nombre de un conjunto de trabajos en segundo plano puede usarse para representar todos los trabajos en ese conjunto.

El shell se entera inmediatamente cada vez que un proceso cambia de estado. Normalmente le informa cada vez que un trabajo se bloquea, de modo que no sea posible un progreso posterior, pero justo antes de mostrar un prompt. Esto se hace para no perturbar su trabajo. La opción notify del comando set hace que el shell imprima estos mensajes de cambio de trabajo tan pronto como ocurran.

Cuando la opción monitor está activada, cada trabajo en segundo plano que se completa activa cualquier trampa configurada para CHLD.

Cuando intenta abandonar el shell mientras hay trabajos en ejecución o detenidos, se le advertirá que "Tiene trabajos detenidos (en ejecución)". Puede usar el comando jobs para ver cuáles son. Si intenta salir de nuevo inmediatamente, el shell no le advertirá por segunda vez y los trabajos detenidos serán terminados. Cuando un shell de inicio de sesión recibe una señal HUP, envía una señal HUP a cada trabajo que no ha sido desconectado con el comando interno disown descrito a continuación.

Señales.

Las señales INT y QUIT para un comando invocado se ignoran si el comando va seguido de & y la opción monitor está activa. De lo contrario, las señales tienen los valores heredados por el shell de su padre (pero vea también el comando interno trap a continuación).

Ejecución.

Cada vez que se lee un comando, se realizan las sustituciones anteriores. Si el nombre del comando coincide con uno de los Comandos Internos Especiales listados a continuación, se ejecuta dentro del proceso actual del shell. A continuación, se verifica el nombre del comando para ver si coincide con una función definida por el usuario. Si lo hace, los parámetros posicionales se guardan y luego se restablecen a los argumentos de la llamada a la función. Una función también se ejecuta en el proceso actual del shell. Cuando la función se completa o emite un return, la lista de parámetros posicionales se restaura. Para las funciones definidas con la sintaxis function nombre, se ejecuta cualquier trampa configurada en EXIT dentro de la función. El valor de salida de una función es el valor del último comando ejecutado. Si el nombre de un comando no es un comando interno especial o una función definida por el usuario, pero es uno de los comandos internos listados a continuación, se ejecuta en el proceso actual del shell.

Las variables del shell PATH seguidas de la variable FPATH definen la lista de directorios donde buscar el nombre del comando. Los nombres de directorios alternativos están separados por dos puntos (:). La ruta predeterminada es igual a la salida de getconf PATH. El directorio actual se puede especificar con dos o más dos puntos adyacentes, o con un dos puntos al principio o al final de la lista de rutas. Si el nombre del comando contiene un /, entonces no se utiliza la ruta de búsqueda. De lo contrario, cada directorio de la lista de directorios definida por PATH y FPATH se verifica en orden. Si el directorio que se está buscando está contenido en FPATH y contiene un archivo cuyo nombre coincide con el comando que se busca, este archivo se carga en el entorno actual del shell como si fuera el argumento del comando ., excepto que solo se expanden los alias preestablecidos, y se ejecuta una función con el nombre dado como se describió anteriormente.

Si este directorio no está en FPATH, el shell primero determina si existe una versión interna de un comando que corresponde a una ruta dada y, de ser así, se invoca en el proceso actual. Si no se encuentra ninguna interna, el shell busca un archivo llamado .paths en este directorio. Si se encuentra y hay una línea de la forma FPATH=ruta donde ruta nombra un directorio existente, entonces ese directorio se busca inmediatamente después del directorio actual como si se encontrara en la variable FPATH. Si ruta no comienza con /, se verifica en relación con el directorio que se está buscando.

Luego se verifica el archivo .paths para ver si hay una línea de la forma PLUGIN_LIB=nombre_libreria [: nombre_libreria ] .... Cada biblioteca nombrada por nombre_libreria se buscará como si fuera un argumento de opción para builtin -f, y si contiene una interna del nombre especificado, se ejecutará en lugar de un comando con este nombre. Cualquier interna cargada desde una biblioteca encontrada de esta manera se asociará con el directorio que contiene el archivo .paths, por lo que solo se ejecutará si no se encuentra en un directorio anterior.

Finalmente, el directorio se verificará en busca de un archivo con el nombre dado. Si el archivo tiene permiso de ejecución pero no es un archivo a.out, se asume que es un archivo que contiene comandos del shell. Se inicia un shell separado para leerlo. Todas las variables no exportadas se eliminan en este caso. Si el archivo de comandos del shell no tiene permiso de lectura, o si los bits setuid y/o setgid están establecidos en el archivo, entonces el shell ejecuta un agente cuyo trabajo es configurar los permisos y ejecutar el shell con el archivo de comandos del shell pasado como un archivo abierto. Si .paths contiene una línea de la forma nombre=valor en la primera o segunda línea, entonces la variable de entorno nombre se modifica anteponiendo el directorio especificado por valor a la lista de directorios. Si valor no es un directorio absoluto, entonces especifica un directorio relativo al directorio donde se encontró el ejecutable. Si la variable de entorno nombre aún no existe, se agregará a la lista de entorno para el comando especificado. Un comando entre paréntesis se ejecuta en un subshell sin eliminar las variables no exportadas.

Reentrada de Comandos.

El texto de los últimos HISTSIZE (por defecto 512) comandos ingresados desde un dispositivo de terminal se guarda en un archivo de historial. Se utiliza el archivo $HOME/.sh_history si la variable HISTFILE no está establecida o si el archivo que nombra no es escribible. Un shell puede acceder a los comandos de todos los shells interactivos que utilizan el mismo HISTFILE con nombre. El comando interno hist se utiliza para listar o editar una parte de este archivo. La parte del archivo que se va a editar o listar se puede seleccionar por número o proporcionando el primer carácter o caracteres del comando. Se puede especificar un solo comando o un rango de comandos. Si no especifica un programa editor como argumento para hist, entonces se utiliza el valor de la variable HISTEDIT. Si HISTEDIT no está definida, se utiliza la variable obsoleta FCEDIT. Si FCEDIT no está definida, entonces se utiliza /bin/ed. El comando editado (o comandos) se imprime y se re-ejecuta al salir del editor, a menos que salga sin guardar. La opción -s (y en versiones obsoletas, el nombre del editor -) se utiliza para omitir la fase de edición y para re-ejecutar el comando. En este caso, se puede usar un parámetro de sustitución de la forma viejo=nuevo para modificar el comando antes de la ejecución. Por ejemplo, con el alias preestablecido r, que está aliñado a ′hist -s′, escribir `r malo=bueno c' volverá a ejecutar el comando más reciente que comience con la letra c, reemplazando la primera aparición de la cadena malo con la cadena bueno.

La variable del shell HOME es el arg predeterminado. La variable PWD se establece en el directorio actual. La variable del shell CDPATH define la ruta de búsqueda para el directorio que contiene arg. Los nombres de directorio alternativos están separados por dos puntos (:). La ruta predeterminada es <nula> (especificando el directorio actual). Tenga en cuenta que el directorio actual se especifica mediante un nombre de ruta nulo, que puede aparecer inmediatamente después del signo igual o entre los delimitadores de dos puntos en cualquier otro lugar de la lista de rutas. Si arg comienza con /, no se utiliza la ruta de búsqueda. De lo contrario, se busca en cada directorio de la ruta arg.

La segunda forma de cd sustituye la cadena nuevo por la cadena antiguo en el nombre del directorio actual, PWD, e intenta cambiar a este nuevo directorio.

Por defecto, los nombres de enlaces simbólicos se tratan literalmente al encontrar el nombre del directorio. Esto es equivalente a la opción -L. La opción -P hace que los enlaces simbólicos se resuelvan al determinar el directorio. La última instancia de -L o -P en la línea de comandos determina qué método se utiliza.

El comando cd puede no ser ejecutado por rksh.

command [ -pvxV ] nombre [ arg ... ]
Sin las opciones -v o -V, command ejecuta nombre con los argumentos proporcionados por arg. La opción -p hace que se busque una ruta predeterminada en lugar de la definida por el valor de PATH. No se buscarán funciones al encontrar nombre. Además, si nombre se refiere a un builtin especial, ninguna de las propiedades especiales asociadas con las dagas iniciales se respetarán. (Por ejemplo, el alias predefinido redirect=′command exec′ evita que un script termine cuando se proporciona una redirección inválida). Con la opción -x, si la ejecución del comando resultara en un fallo debido a demasiados argumentos, errno E2BIG, el shell invocará el comando nombre varias veces con un subconjunto de los argumentos en cada invocación. Los argumentos que ocurren antes de la primera palabra que se expande a múltiples argumentos y después de la última palabra que se expande a múltiples argumentos se pasarán en cada invocación. El estado de salida será el estado de salida máximo de la invocación. Con la opción -v, command es equivalente al comando whence builtin descrito a continuación. La opción -V hace que command actúe como whence -v.

El builtin echo imprime todos sus argumentos separados por espacios y terminados por un salto de línea. -n omitirá la inserción de un carácter de salto de línea al final de la salida. Si -e está activado, interpretará secuencias de escape.
†† enum [ -i ] tipo[=(valor ...) ]
Crea un comando de declaración llamado tipo que es un tipo entero que permite uno de los valores especificados como nombres de enumeración. Si se omite =(valor ...), entonces tipo debe ser una variable de matriz indexada con al menos dos elementos y los valores se toman de esta variable de matriz. Si se especifica -i, los valores no distinguen entre mayúsculas y minúsculas.

Cuando se utiliza una variable de enumeración en una expresión aritmética, su valor es el índice de la matriz que la definió, comenzando desde el índice 0. Las cadenas de enumeración se pueden usar en una expresión aritmética al comparar con una variable de enumeración. Además, cada variable de enumeración no subíndice seguida de .nombre, donde nombre es uno de los nombres de enumeración, se expande al índice correspondiente a nombre.

El enum _Bool se crea con los valores true y false. El alias predefinido bool se define como _Bool.

† eval [ arg ... ]
Los argumentos se leen como entrada para el shell y los comandos resultantes se ejecutan.
† exec [ -c ] [ -a nombre ] [ arg ... ]
Si se proporciona arg, el comando especificado por los argumentos se ejecuta en lugar de este shell sin crear un nuevo proceso. La opción -c hace que el entorno se limpie antes de aplicar las asignaciones de variables asociadas con la invocación de exec. La opción -a hace que nombre, en lugar del primer arg, se convierta en argv[0] para el nuevo proceso. Pueden aparecer argumentos de entrada/salida y afectar al proceso actual. Si no se proporciona arg, el efecto de este comando es modificar los descriptores de archivo según lo prescrito por la lista de redirección de entrada/salida. En este caso, se cierran todos los números de descriptor de archivo mayores que 2 que se abren con este mecanismo al invocar otro programa.

Hace que el shell salga con el estado de salida especificado por n. El valor será los 8 bits menos significativos del estado especificado. Si se omite n, el estado de salida será el del último comando ejecutado. Un fin de archivo también hará que el shell salga, excepto para un shell que tenga activada la opción ignoreeof (ver set a continuación).
†† export [ -p ] [ nombre[=valor] ] ...
Si no se proporciona nombre, se imprimen los nombres y valores de cada variable con el atributo de exportación, con los valores entrecomillados de manera que permitan su reentrada. El comando export es el mismo que typeset -x excepto que si usa export dentro de una función, no se crea ninguna variable local. La opción -p hace que la palabra export se inserte antes de cada una. De lo contrario, los nombres proporcionados se marcan para exportación automática al entorno de los comandos ejecutados posteriormente.
false
No hace nada y sale con 1. Se utiliza con until para bucles infinitos.

Este comando solo está disponible en sistemas que admiten control de trabajos. Cada trabajo especificado se lleva al primer plano y se espera en el orden especificado. De lo contrario, el trabajo actual se lleva al primer plano. Consulte Trabajos para obtener una descripción del formato de trabajo.
getopts [  -a nombre ] cadenaop vnombre [ arg ... ]
Comprueba arg en busca de opciones legales. Si se omite arg, se utilizan los parámetros posicionales. Un argumento de opción comienza con un + o un -. Una opción que no comience con + o - o el argumento -- finaliza las opciones. Las opciones que comienzan con + solo se reconocen cuando cadenaop comienza con un +. cadenaop contiene las letras que getopts reconoce. Si una letra va seguida de un :, se espera que esa opción tenga un argumento. Las opciones pueden separarse del argumento por espacios. La opción -? hace que getopts genere un mensaje de uso en la salida estándar. El argumento -a se puede usar para especificar el nombre a usar para el mensaje de uso, que por defecto es $0.

getopts coloca la siguiente letra de opción que encuentra dentro de la variable vnombre cada vez que se invoca. La letra de opción se antepondrá con un + cuando arg comience con un +. El índice del siguiente arg se almacena en OPTIND. El argumento de la opción, si lo hay, se almacena en OPTARG.

Un : inicial en cadenaop hace que getopts almacene la letra de una opción inválida en OPTARG y que establezca vnombre en ? para una opción desconocida y en : cuando falta un argumento de opción requerido. De lo contrario, getopts imprime un mensaje de error. El estado de salida es no cero cuando no quedan más opciones.

No hay forma de especificar ninguna de las opciones :, +, -, ?, [ y ]. La opción # solo se puede especificar como la primera opción.

hist [ -e nombre_editor  ] [ -nlr ] [ primero [ último ] ]
hist -s [ antiguo=nuevo ] [ comando ]
En la primera forma, se selecciona un rango de comandos desde primero hasta último de los últimos HISTSIZE comandos que se escribieron en el terminal. Los argumentos primero y último pueden especificarse como un número o como una cadena. Una cadena se utiliza para localizar el comando más reciente que comienza con la cadena dada. Un número negativo se utiliza como compensación del número de comando actual. Si se selecciona la opción -l, los comandos se listan en la salida estándar. De lo contrario, se invoca el programa editor nombre_editor en un archivo que contiene estos comandos del teclado. Si no se suministra nombre_editor, se utiliza el valor de la variable HISTEDIT. Si HISTEDIT no está establecida, se utiliza FCEDIT (por defecto /bin/ed) como editor. Cuando se completa la edición, los comandos editados se ejecutan si se han guardado los cambios. Si no se especifica último, se establecerá en primero. Si no se especifica primero, el valor predeterminado es el comando anterior para editar y -16para listado. La opción -r invierte el orden de los comandos y la opción -n suprime los números de comando al listar. En la segunda forma, command se interpreta como first descrito anteriormente y por defecto es el último comando ejecutado. El comando resultante se ejecuta después de que se realiza la sustitución opcional old=new.
jobs [ -lnp ] [ job ... ]
Lista información sobre cada trabajo dado; o todos los trabajos activos si job se omite. La opción -l lista los IDs de proceso además de la información normal. La opción -n solo muestra los trabajos que se han detenido o salido desde la última notificación. La opción -p hace que solo se liste el grupo de procesos. Ver Jobs para una descripción del formato de job.
kill [ -s signame ] [ -q n  ] job ...
kill [ -n signum ] [ -q n  ] job ...
kill -Ll [ sig ... ]
Envía la señal TERM (terminar) o la señal especificada a los trabajos o procesos especificados. Las señales se dan por número con la opción -n o por nombre con la opción -s (tal como se da en <signal.h>, eliminando el prefijo ``SIG'' con la excepción de que SIGCLD se llama CHLD). Para compatibilidad hacia atrás, n y s se pueden omitir y el número o nombre se coloca inmediatamente después del -. Si la señal que se envía es TERM (terminar) o HUP (hangup), entonces el trabajo o proceso recibirá una señal CONT (continuar) si está detenido. El argumento job puede ser el ID de proceso de un proceso que no es miembro de uno de los trabajos activos. Ver Jobs para una descripción del formato de job. En la tercera forma, kill -l, o kill -L, si sig no se especifica, se listan los nombres de las señales. La opción -l lista solo los nombres de las señales. La opción -L lista cada nombre de señal y su número correspondiente. De lo contrario, para cada sig que sea un nombre, se lista el número de señal correspondiente. Para cada sig que sea un número, se lista el nombre de señal correspondiente a los 8 bits menos significativos de sig.

En sistemas que soportan sigqueue(2), la opción -q se puede usar para enviar una señal en cola con el número de mensaje n. Cada job especificado debe ser un número positivo. En sistemas que no soportan sigqueue(2), se envía una señal sin el número de mensaje n y la señal no se encolará. Si la señal no se puede encolar debido a un retorno de EAGAIN, el estado de salida será 2.

let arg ...
Cada arg es una expresión aritmética separada que se evaluará. let solo reconoce constantes octales que comienzan con 0 cuando la opción set letoctal está activada. Ver Evaluación Aritmética arriba, para una descripción de la evaluación de expresiones aritméticas.

El estado de salida es 0 si el valor de la última expresión es distinto de cero, y 1 en caso contrario.

print [ -CRenprsv ] [ -u unit] [ -f format ] [ arg ... ]
Sin opciones o con la opción - o --, cada arg se imprime en la salida estándar. La opción -f hace que los argumentos se impriman según lo descrito por printf. En este caso, las opciones e, n, r, R se ignoran. De lo contrario, a menos que se especifiquen las opciones -C, -R, -r o -v, se aplicarán las siguientes convenciones de escape:
\a
El carácter de alerta (ascii 07).
\b
El carácter de retroceso (ascii 010).
\c
Hace que print termine sin procesar más argumentos y sin añadir una nueva línea.
\f
El carácter de avance de página (ascii 014).
\n
El carácter de nueva línea (ascii 012).
\r
El carácter de retorno de carro (ascii 015).
\t
El carácter de tabulación (ascii 011).
\v
El carácter de tabulación vertical (ascii 013).
\E
El carácter de escape (ascii 033).
\\
El carácter de barra invertida \.
\0x
El carácter definido por la cadena octal de 1, 2 o 3 dígitos dada por x.

La opción -R imprimirá todos los argumentos y opciones subsiguientes excepto -n. La opción -e hace que las convenciones de escape anteriores se apliquen. Este es el comportamiento por defecto. Invierte el efecto de un -r anterior. La opción -p hace que los argumentos se escriban en la tubería del proceso iniciado con ⎪& en lugar de la salida estándar. La opción -v trata cada arg como un nombre de variable y escribe el valor en el formato %B de printf. La opción -C trata cada arg como un nombre de variable y escribe el valor en el formato %#B de printf. La opción -s hace que los argumentos se escriban en el archivo de historial en lugar de la salida estándar. La opción -u se puede usar para especificar un número de unidad de descriptor de archivo de un solo dígito unit en el que se colocará la salida. El valor por defecto es 1. Si se usa la opción -n, no se añade una nueva línea a la salida.

printf [ -v varname ] format [ arg ... ]
Los argumentos arg se imprimen en la salida estándar de acuerdo con las reglas de formato ANSI-C asociadas con la cadena de formato format. Si el número de argumentos excede el número de especificaciones de formato, la cadena de format se reutiliza para formatear los argumentos restantes. Si se especifica la opción -v, la salida se asigna a la variable varname. También se pueden usar las siguientes extensiones:
%b
Se puede usar un formato %b en lugar de %s para hacer que las secuencias de escape en el arg correspondiente se expandan como se describe en print.
%B
Una opción %B hace que cada uno de los argumentos se trate como nombres de variables y se imprima el valor binario de la variable. El indicador alternativo # hace que una variable compuesta se imprima en una sola línea. Esto es más útil para variables compuestas y variables cuyo atributo es -b.
%H
Se puede usar un formato %H en lugar de %s para hacer que los caracteres en arg que son especiales en HTML y XML se impriman como sus nombres de entidad. El indicador alternativo # formatea la salida para su uso como una URI.
%P
Se puede usar un formato %P en lugar de %s para hacer que arg se interprete como una expresión regular extendida y se imprima como un patrón de shell.
%R
Se puede usar un formato %R en lugar de %s para hacer que arg se interprete como un patrón de shell y se imprima como una expresión regular extendida.
%q
Se puede usar un formato %q en lugar de %s para hacer que la cadena resultante se cite de manera que pueda ser reintroducida en el shell. Cuando a q le precede el especificador de formato alternativo, #, la cadena se cita de manera adecuada como campo en un archivo con formato .csv.
%(date-format)T
Se puede usar un formato %(date-format)T para tratar un argumento como una cadena de fecha/hora y formatear la fecha/hora de acuerdo con el date-format tal como se define para el comando date(1). Los valores especificados como dígitos se interpretan como se describe en el comando touch(1).
%Z
Un formato %Z imprimirá un byte cuyo valor es 0.
%d
El campo de precisión del formato %d puede ir seguido de un punto y la base de salida. En este caso, el carácter indicador # hace que se anteponga base#.
#
El indicador #, cuando se usa con el formato %d sin una base de salida, muestra la salida en potencias de 1000 indicadas por uno de los siguientes sufijos: k M G T P E, y cuando se usa con el formato %i muestra la salida en potencias de 1024 indicadas por uno de los siguientes sufijos: Ki Mi Gi Ti Pi Ei.
=
El indicador = centra la salida dentro del ancho de campo especificado.
L
El indicador L, cuando se usa con los formatos %c o %s, trata la precisión como ancho de caracteres en lugar de recuento de bytes.
,
El indicador ,, cuando se usa con los formatos %d o %f, separa grupos de dígitos con el delimitador de agrupación (, en grupos de 3 en la configuración regional C).

read [ -AaCSprsv ] [ -d delim] [ -n n] [ -N n] [ -m method] [ -t timeout] [ -u unit] [ vname?prompt ] [ vname ... ]
El mecanismo de entrada del shell. Se lee una línea y se divide en campos utilizando los caracteres de IFS como separadores. El carácter de escape, \, se utiliza para eliminar cualquier significado especial del siguiente carácter y para la continuación de línea. La opción -d hace que la lectura continúe hasta el primer carácter de delim en lugar de una nueva línea. La opción -n hace que se lean como máximo n bytes en lugar de una línea completa, pero se detendrá al leerque un dispositivo lento tan pronto como se hayan leído caracteres. La opción -N provoca que se lean exactamente n a menos que se haya encontrado un fin de archivo o la lectura expire debido a la opción -t. En modo crudo, -r, el carácter \ no se trata de forma especial. El primer campo se asigna al primer vname, el segundo campo al segundo vname, etc., con los campos sobrantes asignados al último vname. Cuando vname tiene el atributo binario y se especifica -n o -N, los bytes que se leen se almacenan directamente en la variable. Si se especifica -v, entonces el valor del primer vname se utilizará como valor predeterminado al leer desde un terminal. La opción -A provoca que la variable vname se desestructure y que cada campo que se lee se almacene en elementos sucesivos del array indexado vname. -a es un alias de -A. La opción -m lee una variable compuesta con el método de lectura definido por method. Actualmente, solo existen los métodos json y ksh. La opción -C provoca que la variable vname se lea como una variable compuesta. Los espacios se ignorarán al encontrar el paréntesis de apertura. Esto es equivalente a -m ksh. La opción -S provoca que la línea se trate como un registro en un archivo con formato .csv para que las comillas dobles se puedan usar para permitir que el carácter delimitador y el carácter de nueva línea aparezcan dentro de un campo. La opción -p provoca que la línea de entrada se tome de la tubería de entrada de un proceso generado por el shell usando ⎪&. Si está presente la opción -s, la entrada se guardará como un comando en el archivo de historial. La opción -u se puede usar para especificar un descriptor de archivo de un solo dígito unit del que leer. El descriptor de archivo se puede abrir con el comando especial incorporado exec. El valor predeterminado de la unidad n es 0. La opción -t se utiliza para especificar un tiempo de espera en segundos al leer desde un terminal o tubería. Si se omite vname, entonces REPLY se utiliza como vname predeterminado. Un fin de archivo con la opción -p provoca la limpieza de este proceso para que se pueda generar otro. Si el primer argumento contiene un ?, el resto de esta palabra se utiliza como prompt en la salida de error estándar cuando el shell es interactivo. El estado de salida es 0 a menos que se encuentre un fin de archivo o la lectura haya expirado.

Rksh Solo.

Rksh se utiliza para configurar nombres de inicio de sesión y entornos de ejecución cuyas capacidades están más controladas que las del shell estándar. Las acciones de rksh son idénticas a las de ksh, excepto que se prohíben las siguientes acciones:

Anular la opción restringida.
cambiar de directorio (ver cd(1)),
establecer o anular el valor o los atributos de SHELL, ENV, FPATH o PATH,
especificar nombres de ruta o comando que contengan /,
redirigir la salida (>, >|, <> y >>).
agregar o eliminar comandos incorporados.
usar command -p para invocar un comando.

Las restricciones anteriores se aplican después de que se interpretan los archivos .profile y ENV.

Cuando un comando a ejecutar se encuentra como un procedimiento de shell, rksh invoca a ksh para ejecutarlo. Por lo tanto, es posible proporcionar al usuario final procedimientos de shell que tengan acceso a todo el poder del shell estándar, al tiempo que se imponen un menú limitado de comandos; este esquema asume que el usuario final no tiene permisos de escritura y ejecución en el mismo directorio.

El efecto neto de estas reglas es que el escritor del .profile tiene control total sobre las acciones del usuario, al realizar acciones de configuración garantizadas y dejar al usuario en un directorio apropiado (probablemente no el directorio de inicio de sesión).

El administrador del sistema a menudo configura un directorio de comandos (por ejemplo, /usr/rbin) que pueden ser invocados de forma segura por rksh.

ESTADO DE SALIDA

Los errores detectados por el shell, como errores de sintaxis, hacen que el shell devuelva un estado de salida distinto de cero. Si el shell se está utilizando de forma no interactiva, la ejecución del archivo del shell se abandona a menos que el error ocurra dentro de un subshell, en cuyo caso el subshell se abandona. De lo contrario, el shell devuelve el estado de salida del último comando ejecutado (ver también el comando exit anterior). Los errores de tiempo de ejecución detectados por el shell se informan imprimiendo el nombre del comando o función y la condición de error. Si el número de línea en el que ocurrió el error es mayor que uno, entonces el número de línea también se imprime entre corchetes ([]) después del nombre del comando o función.

ADVERTENCIAS

Si se ejecuta un comando y luego se instala un comando con el mismo nombre en un directorio de la ruta de búsqueda antes del directorio donde se encontró el comando original, el shell continuará ejecutando el comando original. Use la opción -t del comando alias para corregir esta situación.

Algunos scripts de shell muy antiguos contienen un ^ como sinónimo del carácter pipe ⎪.

Usar el comando incorporado hist dentro de un comando compuesto hará que todo el comando desaparezca del archivo de historial.

El comando incorporado . archivo lee todo el archivo antes de que se ejecuten los comandos. Por lo tanto, los comandos alias y unalias en el archivo no se aplicarán a ningún comando definido en el archivo.

Las trampas (traps) no se procesan mientras un trabajo espera un proceso en primer plano. Por lo tanto, una trampa en CHLD no se ejecutará hasta que termine el trabajo en primer plano.

Es una buena idea dejar un espacio después del operador coma en las expresiones aritméticas para evitar que la coma sea interpretada como el carácter de punto decimal en algunas configuraciones regionales.
