KAK(1) Manual de comandos generales KAK(1)

NOMBRE

kak — un editor de código orientado a la selección e inspirado en vim

SINOPSIS

kak [-d] [-n] [-ro] [-c id_sesion | -s id_sesion] [-ui tipo_ui] [-e comando] [-E comando] [+linea[:columna] | +:] [archivo ...]

kak -f teclas [-q] [-i sufijo] [archivo ...]

kak -p id_sesion

kak -l

kak -clear

kak -version

kak -help

DESCRIPCIÓN

Kakoune es un editor de código fuertemente inspirado en vim(1) y vi(1). Como tal, la mayoría de sus comandos son similares a los de vi(1), compartiendo su modelo de “pulsaciones de teclas como lenguaje de edición de texto”.

Kakoune opera en dos modos, normal e inserción. En modo inserción, las teclas se insertan directamente en el búfer actual. En modo normal, las teclas se utilizan para manipular la selección actual y para entrar en modo inserción.

Kakoune tiene un fuerte enfoque en la interactividad. La mayoría de los comandos proporcionan resultados inmediatos e incrementales, mientras siguen siendo competitivos en el número de pulsaciones con vim.

Kakoune trabaja sobre selecciones, que son rangos orientados e inclusivos de caracteres. Las selecciones tienen un ancla y un cursor. La mayoría de los comandos mueven ambos, excepto al extender la selección, donde el carácter del ancla permanece fijo y el cursor se mueve.

Las opciones son las siguientes:

-help
Muestra un mensaje de ayuda y sale.
-version
Muestra la versión de Kakoune y sale.
-n
No carga el kakrc del sistema. (a menudo, /usr/share/kak/kakrc)
-l
Lista las sesiones existentes.
-d
Ejecuta como una sesión sin interfaz gráfica (requiere -s).
-e comando
Ejecuta comando después de la fase de inicialización del cliente.
-E comando
Ejecuta comando después de la fase de inicialización del servidor.
-f teclas
Ejecuta Kakoune en modo ‘filtro’, como sed(1). Para la entrada estándar y cada archivo nombrado en la línea de comandos, se selecciona el búfer completo (como con %) y luego se ejecutan las teclas. La versión filtrada de la entrada estándar se escribe en la salida estándar. Cualquier archivo mencionado en la línea de comandos se modifica en el lugar, pero si se proporciona -i, entonces Kakoune crea una copia de seguridad de la versión original.
-i sufijo
Crea una copia de seguridad de los archivos sobre los que se aplica un filtro, utilizando el sufijo dado.
-q
Cuando está en modo ‘filtro’, no imprime ningún error.
-p id_sesion
Envía los comandos escritos en la entrada estándar a la sesión id_sesion.
-c id_sesion
Conéctate a la sesión dada id_sesion.
-s id_sesion
Establece el nombre de la sesión actual a id_sesion.
-ui tipo
Selecciona el tipo de interfaz de usuario, que puede ser terminal, dummy, o json.
-clear
Elimina las sesiones que terminaron en un estado incorrecto (por ejemplo, después de un fallo).
-ro
Comienza en modo de solo lectura, todos los búferes abiertos no se escribirán en disco.
+linea[:columna] | +:
Especifica una línea y columna objetivo para el primer archivo. Cuando el signo más está seguido solo por dos puntos, el cursor se envía a la última línea del archivo.
archivo ...
Uno o más archivos para editar.

ENTORNO

KAKOUNE_POSIX_SHELL
Anula el shell POSIX utilizado para la expansión %sh{...}, que es /bin/sh (sh(1)) si no está definido.
KAKOUNE_CONFIG_DIR
Anula la ubicación del directorio que contiene la configuración de usuario de Kakoune. Si no está definido, se utiliza $XDG_CONFIG_HOME/kak.
KAKOUNE_RUNTIME
Anula la ubicación del directorio que contiene los archivos de soporte de Kakoune. Si no está definido, la ubicación se determina a partir de la ubicación del binario de Kakoune.
XDG_CONFIG_HOME
Ruta al directorio de configuración del usuario. Si no está definido, se utiliza $HOME/.config.
XDG_RUNTIME_DIR
Ruta a los sockets de sesión del usuario. Si no está definido, se utiliza $TMPDIR/kakoune.

kak(1) - Arch Linux man pages

NAME

kak - code editor

SYNOPSIS

kak [-nqv] [-e SCRIPT] [-f FILE] [-t HOOK] [FILE...]

DESCRIPTION

Kakoune is a code editor with a focus on caller-before-callee, which means that you select the text first, and then you choose the command to apply to it.

In addition to the above, Kakoune also favors the use of the keyboard over the mouse and the editor will run commands in the background when possible.

In batch mode (no files given on the command line, nor the -e, -f nor -t options), Kakoune will start an interactive shell.

The options are as follows:

-n
Do not load the user configuration file $KAKOUNE_CONFIG_DIR/kakrc.
-q
Quiet mode, suppresses messages that are not error messages.
-v
Print version string and exit.
-e SCRIPT
Execute SCRIPT within Kakoune on the given files. The script is executed after the config files are loaded.
-f FILE
Execute the content of FILE within Kakoune on the given files. The file is executed after the config files are loaded.
-t HOOK
Trigger the client hook HOOK on the given files. The hook is executed after the config files are loaded.

ENVIRONMENT

$KAKOUNE_EDITOR

If set, this variable will be used instead of the default editor when invoked from external programs.

$KAKOUNE_CONFIG_DIR

If set, this variable will be used as the directory for user configuration files, overriding $XDG_CONFIG_HOME and $HOME.

$XDG_CONFIG_HOME

Standard XDG base directory specification. If $KAKOUNE_CONFIG_DIR is not set, Kakoune will look for its configuration files in $XDG_CONFIG_HOME/kak ($HOME/.config/kak if $XDG_CONFIG_HOME is not set).

$TERM

Kakoune requires the $TERM variable to be set to a terminal type that is recognized by the terminfo database.

FILES

Kakoune searches for configuration and autoload files in the following order:

  • <rtdir>/autoload: This is the system-wide directory containing default scripts. When the IG_DIR/autoload directory exists, recursively load every *.kak file in it, and its sub-directories.
  • If it does not exist, fall back to the system-wide autoload directory in <rtdir>/autoload, and recursively load all files in a similar way.
  • <rtdir>/kakrc.local, if it exists; this is a user-defined system-wide configuration.
  • $KAKOUNE_CONFIG_DIR/kakrc, if it exists; this is the user configuration.

Consequently, if the $KAKOUNE_CONFIG_DIR/autoload directory exists, only scripts stored within that directory will be loaded — the built-in *.kak files will not be.

Users who still want the built-in scripts to be loaded along their own can create a symbolic link to <rtdir>/autoload (or to individual scripts in it) in their user-configuration directory:

ln -s <rtdir>/autoload ${XDG_CONFIG_HOME:-$HOME/.config} /kak/autoload

EXAMPLES

Edit a file:
kak /path/to/file
Edit multiple files (multiple buffers will be created):
kak ./file1.txt /path/to/file2.c
Prepend a modeline that sets the tabstop to multiple files:
kak -f "ggO// kak: tabstop=8<esc>" *.c
