NOMBRE

kexec - arrancar directamente un nuevo kernel

SINOPSIS

/sbin/kexec [-v (--version)] [-f (--force)] [-x (--no-ifdown)] [-y (--no-sync)] [-l (--load)] [-p (--load-panic)] [-u (--unload)] [-e (--exec)] [-t (--type)] [--mem-min=dirección] [--mem-max=dirección]

DESCRIPCIÓN

kexec es una llamada al sistema que te permite cargar y arrancar otro kernel desde el kernel en ejecución actual. kexec realiza la función del cargador de arranque desde dentro del kernel. La principal diferencia entre un arranque del sistema estándar y un arranque con kexec es que la inicialización del hardware que normalmente realiza la BIOS o el firmware (dependiendo de la arquitectura) no se realiza durante un arranque con kexec. Esto tiene el efecto de reducir el tiempo requerido para un reinicio.

Asegúrate de haber seleccionado CONFIG_KEXEC=y al configurar el kernel. La opción CONFIG_KEXEC habilita la llamada al sistema kexec.

USO

Usar kexec consiste en

(1) cargar el kernel al que se va a reiniciar en memoria, y
(2) reiniciar efectivamente hacia el kernel pre-cargado.

Para cargar un kernel, la sintaxis es la siguiente:

kexec -l imagen-kernel --append=opciones-línea-comandos --initrd=imagen-initrd

donde imagen-kernel es el archivo del kernel al que pretendes reiniciar.

Inserta los parámetros de línea de comandos que deben pasarse al nuevo kernel en opciones-línea-comandos. Pasar el contenido exacto de /proc/cmdline en opciones-línea-comandos es la forma más segura de asegurar que se pasan los valores correctos al kernel que se reinicia.

La imagen-initrd opcional es la imagen initrd que se usará durante el arranque.

También es posible invocar kexec sin un parámetro de opción. En ese caso, kexec carga el kernel especificado y luego invoca shutdown(8). Si los scripts de apagado de tu distribución Linux soportan reinicios basados en kexec, entonces llaman a kexec -e justo antes de reiniciar la máquina. De esta manera, la máquina realiza un apagado limpio incluyendo todos los scripts de apagado.

EJEMPLO

Por ejemplo, si la imagen del kernel a la que quieres reiniciar es /boot/vmlinux, el contenido de /proc/cmdline es root=/dev/hda1, y la ruta al initrd es /boot/initrd, entonces usarías el siguiente comando para cargar el kernel:

kexec -l /boot/vmlinux --append=root=/dev/hda1 --initrd=/boot/initrd

Después de cargar este kernel, asumiendo que el espacio de usuario soporta reinicios basados en kexec, se puede arrancar hacia él, con un apagado limpio, usando el comando:

reboot

Alternativamente, también se puede arrancar hacia él, sin llamar a shutdown(8), con el comando:

kexec -e

OPCIONES

-d (--debug)
Habilita mensajes de depuración.
-S (--status)
Devuelve 1 si el tipo (por defecto crash) está cargado, 0 si no. Se puede usar junto con -l o -p para alternar el tipo. Nota: esta opción anula otras opciones y no carga ni descarga el kernel.
-e (--exec)
Ejecuta el kernel actualmente cargado. Nota que reiniciará al kernel cargado sin llamar a shutdown(8).
-f (--force)
Fuerza una llamada kexec inmediata, no llama a shutdown(8) (contrariamente a la acción predeterminada sin ningún parámetro de opción). Esta opción realiza las mismas acciones que ejecutar -l y -e en una sola llamada.
-h (--help)
Abre un archivo de ayuda para kexec.
--hotplug
Configura segmentos de kexec de modo que el kernel pueda actualizarlos de forma segura ante eventos de adición/eliminación de CPU/Memoria en caliente. Si esta opción está habilitada, el kernel realiza una actualización dentro del kernel de los segmentos de kexec ante eventos de adición/eliminación de CPU/Memoria en caliente, evitando así la necesidad de recargar el kernel kdump.
-i (--no-checks)
Reinicio rápido, sin comprobaciones de integridad de memoria.
-l (--load) kernel
Carga el kernel especificado en el kernel actual.
-p (--load-panic)
Carga el nuevo kernel para usarlo en caso de pánico.
-t (--type=tipo)
Especifica que el nuevo kernel es de este tipo.
-s (--kexec-file-syscall)
Especifica que la nueva llamada al sistema KEXEC_FILE_LOAD se usará exclusivamente. Ignorado en XEN.
-c (--kexec-syscall)
Especifica que la antigua llamada al sistema KEXEC_LOAD se usará exclusivamente.
-a (--kexec-syscall-auto)
Intenta primero la nueva llamada al sistema KEXEC_FILE_LOAD y cuando no sea compatible o el kernel no entienda la imagen proporcionada, recurre a la antigua interfaz KEXEC_LOAD.

No hay una única interfaz que siempre funcione, por lo que esta es la predeterminada.

KEXEC_FILE_LOAD es necesario en sistemas que usan arranque seguro con restricciones para verificar la firma del kernel. KEXEC_LOAD también puede estar deshabilitado en la configuración del kernel.

KEXEC_LOAD es necesario para algunos formatos de imagen de kernel y en arquitecturas que no implementan KEXEC_FILE_LOAD.

-u (--unload)
Descarga el kernel de kexec actual. Si se está descargando un kernel de captura, especifica -p con -u.
-v (--version)
Devuelve el número de versión de la utilidad instalada.
-x (--no-ifdown)
Apaga el kernel en ejecución, pero restaura la interfaz al recargar.
-y (--no-sync)
Apaga el kernel en ejecución, pero omite la sincronización de los sistemas de archivos.
--mem-min=dirección
Especifica la dirección de memoria más baja dirección para cargar el código.
--mem-max=dirección
Especifica la dirección de memoria más alta dirección para cargar el código.
--entry=dirección
Especifica la dirección de salto de retorno. (0 significa que no hay salto de retorno o preservación de contexto)
--load-preserve-context
Carga el nuevo kernel y preserva el contexto del kernel actual durante kexec.
--load-jump-back-helper
Carga una imagen auxiliar para saltar de vuelta al kernel original.
--reuseinitrd
Reutiliza el initrd del primer arranque.
--print-ckr-size
Imprime el tamaño de la región del kernel de volcado (crash kernel), si está disponible.

NAME

kexec - execute a new kernel from the context of the current kernel

SYNOPSIS

kexec [OPTIONS] [--command-line=string] kernel [initrd]

kexec [OPTIONS] --load

kexec [OPTIONS] --load-kdump

kexec [OPTIONS] --unload

kexec [OPTIONS] --reboot

kexec [OPTIONS] --kdump-reboot

DESCRIPTION

The kexec command allows you to load a new kernel into memory and then cleanly reboot the system into that new kernel. This avoids the BIOS/UEFI time and allows for faster kernel upgrades and system reboots.

The kexec command can also be used to load a kernel for the purpose of capturing a memory dump (kdump). In this case, kexec loads a secondary kernel that will be booted when the primary kernel crashes.

USAGE

The general usage involves loading a kernel and an optional initial ramdisk, and then triggering a reboot into the loaded kernel. Alternatively, you can load a kdump kernel, unload a previously loaded kernel, or simply reboot without loading a new kernel.

EXAMPLE

Load a new kernel and initrd, and reboot:

# kexec -l /boot/vmlinuz-linux --initrd=/boot/initramfs-linux.img --command-line="root=/dev/sda1"
# kexec -e

Load a kdump kernel and reboot:

# kexec -l /boot/vmlinuz-kdump --initrd=/boot/initramfs-kdump.img --command-line="root=/dev/sda1" --load-kdump
# kexec -k

OPTIONS

--load
Load the specified kernel and initrd into memory. This option must be used when specifying a kernel file. It can be used multiple times to load multiple kernels. The last one loaded is the one that will be executed by default.
--load-kdump
Load the specified kernel and initrd into memory as a kdump kernel. This option must be used when specifying a kernel file. It can be used multiple times to load multiple kdump kernels. The last one loaded is the one that will be executed by default upon a crash.
--unload
Unload the currently loaded kernel from memory.
-e, --execute
Execute the loaded kernel. This will cause the system to reboot into the new kernel without going through the BIOS/UEFI.
--reboot
Load the specified kernel and initrd into memory and then execute it. This is equivalent to using --load followed by --execute.
--kdump-reboot
Load the specified kernel and initrd into memory as a kdump kernel and then execute it. This is equivalent to using --load-kdump followed by --kdump-execute.
--append=string
Append string to the kernel command line.
--command-line=string
Set the kernel command line to string.
--reuse-cmdline
Use the command line from the running system. When a panic kernel is loaded, it strips the crashkernel parameter automatically. The BOOT_IMAGE parameter is also stripped.
--initrd=file
Use file as the kernel's initial ramdisk.
--ramdisk=file
Use file as the kernel's initial ramdisk.
