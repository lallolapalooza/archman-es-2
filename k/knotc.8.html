NOMBRE

knotc - Utilidad de control de Knot DNS

SINOPSIS

knotc [opción_config] [opciones] [acción]

DESCRIPCIÓN

Este programa controla un proceso knotd en ejecución utilizando un socket.

Si se especifica una acción, se realiza y knotc sale; de lo contrario, el programa se ejecuta en modo interactivo.

Opciones de configuración

-c, --config archivo
Utiliza un archivo de configuración de texto (el valor predeterminado es /etc/knot/knot.conf).
-C, --confdb directorio
Utiliza un directorio de base de datos de configuración binaria (el valor predeterminado es /var/lib/knot/confdb). La base de datos de configuración predeterminada, si existe, tiene preferencia sobre el archivo de configuración predeterminado.

Opciones

-m, --max-conf-size MiB
Establece el tamaño máximo de la base de datos de configuración (el valor predeterminado es 500 MiB, máximo 10000 MiB).
-s, --socket ruta
Utiliza una ruta de socket UNIX de control (el valor predeterminado es /run/knot/knot.sock).
-t, --timeout segundos
Utiliza un tiempo de espera de control en segundos. Establecer en 0 para infinito (predeterminado es 60). Las operaciones del socket de control también están sujetas al parámetro timeout establecido en el lado del servidor en la sección de configuración de Control del servidor.
-b, --blocking
Los comandos de activación de eventos de zona esperan hasta que el evento se complete. El tiempo de espera de control se establece en infinito si no se fuerza mediante una especificación de tiempo de espera explícita.
-e, --extended
Muestra salida extendida (incluso elementos vacíos en el estado de la zona).
-f, --force
Operación forzada. Anula algunas comprobaciones.
-x, --mono
No genera salida con colores.
-X, --color
Fuerza la salida con colores en la salida extendida o a una tubería.
-v, --verbose
Habilita la salida de depuración.
-h, --help
Imprime la ayuda del programa.
-V, --version
Imprime la versión del programa. La opción -VV hace que el programa imprima el resumen de configuración en tiempo de compilación.

Acciones

status [detalle]
Comprueba si el servidor se está ejecutando. Los detalles son version para la versión del servidor en ejecución, workers para el número de hilos de trabajo, configure para el resumen de configuración o cert-key para el pin de clave pública del certificado que se está utilizando actualmente.
stop
Detiene el servidor si se está ejecutando.
reload
Recarga la configuración del servidor y los archivos de zona modificados, y reabre los archivos de registro si están configurados. ¡Todas las transacciones de zona abiertas se abortarán!
stats [módulo[.contador]]
Muestra el(los) contador(es) global(es) de estadísticas. Para imprimir también los contadores con valor 0, utiliza la opción force.
zone-check [zona...]
Prueba si el servidor puede cargar la zona. Se ejecutan comprobaciones semánticas si están habilitadas en la configuración. Si se invoca con la opción force, se devuelve un error cuando aparece una advertencia de comprobación semántica. (*)
zone-status [zona...] [filtro]
Muestra el estado de la zona. Los filtros son +role, +serial, +transaction, +events, +freeze y +catalog. Los parámetros de zona vacíos se omiten, a menos que se utilice la opción --extended. Un guion único en la salida representa un valor no establecido. La colorización automática se puede anular utilizando las opciones --mono y --color.

El código de color es: verde - la zona actúa como maestro / rojo - la zona actúa como esclava, fuente en negrita (resaltada) - la zona está activa / normal - la zona está vacía, subrayado - la zona es un miembro del catálogo interpretado.

zone-reload [zona...]
Activa una recarga de la zona desde el disco sin comprobar su hora de modificación. Para las zonas secundarias, se programa el evento de actualización del servidor primario(s); para las zonas primarias, se programa el evento NOTIFY al servidor(es) secundario(s). ¡Se abortará una transacción de zona abierta! Si se invoca con la opción force, también se recargarán los módulos de zona, pero el modo de bloqueo podría no funcionar de forma fiable. (#)
zone-refresh [zona...]
Activa una comprobación del número de serie de la zona en el servidor primario de la zona. Si el servidor primario tiene una zona más nueva, se programa una transferencia. Este comando es válido para zonas secundarias. (#)
zone-retransfer [zona...]
Activa una transferencia de zona desde el servidor primario de la zona. El servidor no comprueba el número de serie de la zona del servidor primario. Este comando es válido para zonas secundarias. (#)
zone-notify [zona...]
Activa un mensaje NOTIFY a todos los remotos configurados. Esto puede ser útil en casos en que las NOTIFY anteriores se hayan perdido o los servidores secundarios hayan estado desconectados. (#)
zone-flush [zona...] [+outdir directorio]
Activa un vaciado del journal de la zona al archivo de zona configurado. Si la sincronización del archivo de zona está deshabilitada, se debe usar la opción force. Si se especifica un directorio de salida, la zona actual se descarga inmediatamente (en modo de bloqueo) a un archivo de zona en el directorio especificado. Consulte Notas a continuación sobre los permisos del directorio. (#)
zone-backup [zona...] +backupdir directorio [filtro...]
Activa una copia de seguridad de los datos y metadatos de la zona en un directorio especificado. Los filtros disponibles son +zonefile, +journal, +timers, +kaspdb, +keysonly, +catalog, +quic, y sus contrapartes negativas +nozonefile, +nojournal, +notimers, +nokaspdb, +nokeysonly, +nocatalog y +noquic. Con estos filtros establecidos, se copian los contenidos de la zona, el journal de la zona, los temporizadores relacionados con la zona, los datos relacionados con la zona en la base de datos KASP junto con las claves (o claves sin la base de datos KASP), el catálogo de la zona y la clave y certificado QUIC del servidor, respectivamente, o se omiten de la copia de seguridad. Por defecto, los filtros +zonefile, +timers, +kaspdb, +catalog, +quic, +nojournal y +nokeysonly se establecen para la copia de seguridad. Los mismos valores predeterminados se aplican a la restauración, con la única diferencia de +noquic. Establecer un filtro para un elemento no cambia los ajustes predeterminados para otros elementos. La única excepción es +keysonly, que deshabilita todos los demás filtros por defecto, pero aún pueden activarse explícitamente. Si se deshabilita el vaciado de la zona, se respalda el archivo de zona original en lugar de escribir los contenidos de la zona en un archivo. Al hacer una copia de seguridad de una zona de catálogo, se recomienda evitar cambios en curso en ella mediante zone-freeze. La opción force permite sobrescribir un directorio de copia de seguridad ya existente. Consulte Notas a continuación sobre los permisos del directorio. (#)
zone-restore [zona...] +backupdir directorio [filtro...]
Activa una restauración de los datos y metadatos de la zona desde un directorio de copia de seguridad especificado. Los filtros opcionales son equivalentes a los mismos filtros de zone-backup. La restauración desde copias de seguridad creadas por versiones de Knot DNS anteriores a la 3.1 es posible con la opción force.

NOMBRE

knotc - el cliente de línea de comandos para el servidor DNS Knot

SINOPSIS

$ knotc [opciones] comando [argumentos]

DESCRIPCIÓN

knotc es una utilidad de línea de comandos para comunicarse con el servidor DNS Knot (knotd). Permite consultar y modificar la configuración y el estado del servidor, así como gestionar las zonas.

knotc se comunica con el demonio knotd a través de un socket Unix (por defecto, /run/knot/knot.ctl).

Para ver la lista completa de comandos y opciones disponibles, ejecuta knotc --help.

VALORES DE SALIDA

Devuelve 0 si el comando se ejecutó correctamente, 1 si ocurrió un error.

EJEMPLOS

Obtener los servidores primarios de la zona example.com

$ knotc conf-read 'zone[example.com].master'

Añadir la zona example.org con una ubicación de archivo de zona

$ knotc conf-begin
$ knotc conf-set 'zone[example.org]'
$ knotc conf-set 'zone[example.org].file' '/var/zones/example.org.zone'
$ knotc conf-commit

Obtener el registro SOA de cada zona configurada

$ knotc zone-read -- @ SOA
