kexec_load(2) Manual de llamadas al sistema kexec_load(2)

NOMBRE

kexec_load, kexec_file_load - cargar un nuevo kernel para su posterior ejecución

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/kexec.h>      /* Definición de constantes KEXEC_* */
#include <sys/syscall.h>      /* Definición de constantes SYS_* */
#include <unistd.h>
long syscall(SYS_kexec_load, unsigned long entry,
             unsigned long nr_segments,
             struct kexec_segment segments[nr_segments],
             unsigned long flags);
long syscall(SYS_kexec_file_load, int kernel_fd, int initrd_fd,
             unsigned long cmdline_len, const char cmdline[cmdline_len],
             unsigned long flags);

Nota: glibc no proporciona envolturas para estas llamadas al sistema, lo que requiere el uso de syscall(2).

DESCRIPCIÓN

La llamada al sistema kexec_load() carga un nuevo kernel que puede ser ejecutado posteriormente por reboot(2).

El argumento flags es una máscara de bits que controla el funcionamiento de la llamada. Los siguientes valores pueden especificarse en flags:

KEXEC_ON_CRASH (desde Linux 2.6.13)
Ejecuta el nuevo kernel automáticamente en un fallo del sistema. Este "kernel de fallo" se carga en un área de memoria reservada que se determina en el momento del arranque utilizando el parámetro de línea de comandos del kernel crashkernel. La ubicación de esta memoria reservada se exporta al espacio de usuario a través del archivo /proc/iomem, en una entrada etiquetada como "Crash kernel". Una aplicación en espacio de usuario puede analizar este archivo y preparar una lista de segmentos (ver más abajo) que especifiquen esta memoria reservada como destino. Si se especifica esta bandera, el kernel comprueba que los segmentos de destino especificados en segments caigan dentro de la región reservada.
KEXEC_PRESERVE_CONTEXT (desde Linux 2.6.27)
Preserva el estado del hardware y software del sistema antes de ejecutar el nuevo kernel. Esto podría usarse para la suspensión del sistema. Esta bandera solo está disponible si el kernel fue configurado con CONFIG_KEXEC_JUMP, y es efectiva solo si nr_segments es mayor que 0.

Los bits de orden superior (correspondientes a la máscara 0xffff0000) de flags contienen la arquitectura del kernel a ejecutar. Especifique (o) la constante KEXEC_ARCH_DEFAULT para usar la arquitectura actual, o una de las siguientes constantes de arquitectura KEXEC_ARCH_386, KEXEC_ARCH_68K, KEXEC_ARCH_X86_64, KEXEC_ARCH_PPC, KEXEC_ARCH_PPC64, KEXEC_ARCH_IA_64, KEXEC_ARCH_ARM, KEXEC_ARCH_S390, KEXEC_ARCH_SH, KEXEC_ARCH_MIPS, y KEXEC_ARCH_MIPS_LE. La arquitectura debe ser ejecutable en la CPU del sistema.

El argumento entry es la dirección física de entrada en la imagen del kernel. El argumento nr_segments es el número de segmentos apuntados por el puntero segments; el kernel impone un límite (arbitrario) de 16 en el número de segmentos. El argumento segments es un array de estructuras kexec_segment que definen la disposición del kernel:


struct kexec_segment {
    void   *buf;        /* Buffer en espacio de usuario */
    size_t  bufsz;      /* Longitud del buffer en espacio de usuario */
    void   *mem;        /* Dirección física del kernel */
    size_t  memsz;      /* Longitud de la dirección física */
};

La imagen del kernel definida por segments se copia desde el proceso llamante al kernel, ya sea en memoria normal o en memoria reservada (si se establece KEXEC_ON_CRASH). El kernel primero realiza varias comprobaciones de seguridad sobre la información pasada en segments. Si estas comprobaciones pasan, el kernel copia los datos del segmento a la memoria del kernel. Cada segmento especificado en segments se copia como sigue:

•
buf y bufsz identifican una región de memoria en el espacio de direcciones virtual del llamante que es la fuente de la copia. El valor en bufsz no puede exceder el valor en el campo memsz.
•
mem y memsz especifican un rango de direcciones físicas que es el destino de la copia. Los valores especificados en ambos campos deben ser múltiplos del tamaño de página del sistema.
•
Se copian bufsz bytes desde el buffer de origen al buffer del kernel de destino. Si bufsz es menor que memsz, los bytes excedentes en el buffer del kernel se ponen a cero.

En caso de un kexec normal (es decir, la bandera KEXEC_ON_CRASH no está establecida), los datos del segmento se cargan en cualquier memoria disponible y se mueven a la destinación final en el momento del reinicio de kexec (por ejemplo, cuando se ejecuta el comando kexec(8) con la opción -e).

En caso de kexec en pánico (es decir, la bandera KEXEC_ON_CRASH está establecida), los datos del segmento se cargan en memoria reservada en el momento de la llamada, y, después de un fallo, el mecanismo kexec simplemente transfiere el control a ese kernel.

La llamada al sistema kexec_load() está disponible solo si el kernel fue configurado con CONFIG_KEXEC.

kexec_file_load()

La llamada al sistema kexec_file_load() es similar a kexec_load(), pero toma un conjunto diferente de argumentos. Lee el kernel a cargar desde el archivo al que se refiere el descriptor de archivo kernel_fd, y el initrd (disco RAM inicial) a cargar desde el archivo al que se refiere el descriptor de archivo initrd_fd. El argumento cmdline es un puntero a un buffer que contiene la línea de comandos para el nuevo kernel. El argumento cmdline_len especifica el tamaño del buffer. El último byte en el buffer debe ser un carácter nulo ('\0').

El argumento flags es una máscara de bits que modifica el comportamiento de la llamada. Los siguientes valores pueden especificarse en flags:

KEXEC_FILE_UNLOAD
Descarga el kernel actualmente cargado.
KEXEC_FILE_ON_CRASH
Carga el nuevo kernel en la región de memoria reservada para el kernel de fallo (como para KEXEC_ON_CRASH). Este kernel se inicia si el kernel actualmente en ejecución falla.
KEXEC_FILE_NO_INITRAMFS
La carga de initrd/initramfs es opcional. Especifique esta bandera si no se está cargando ningún initramfs. Si esta bandera está establecida, el valor pasado en initrd_fd se ignora.

La llamada al sistema kexec_file_load() se añadió para proporcionar soporte para sistemas donde la carga "kexec" debe restringirse solo a kernels que estén firmados. Esta llamada al sistema está disponible solo si el kernel fue configurado con CONFIG_KEXEC_FILE.

VALOR DEVUELTO

En caso de éxito, estas llamadas al sistema devuelven 0. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EADDRNOTAVAIL
Se especificó la bandera KEXEC_ON_CRASH, pero la región especificada por los campos mem y memsz de una de las entradas de segments se encuentra fuera del rango de memoria reservada para el kernel de fallo.
EADDRNOTAVAIL
El valor en un campo mem o memsz en una de las entradas de segments no es un múltiplo del tamaño de página del sistema.
EBADF
kernel_fd o initrd_fd no es un descriptor de archivo válido.
EBUSY
Ya se está cargando otro kernel de fallo o ya se está utilizando un kernel de fallo.
EINVAL
flags es inválido.
EINVAL
El valor de un campo bufsz en una de las entradas de segmen

kexec_file_load(2) — Arch Linux man pages

NAME

kexec_file_load() — cargar un nuevo núcleo y/o initrd en memoria y ejecutarlo

LIBRARY

Librería C estándar (libc, 3)

SYNOPSIS

#include <linux/kexec.h>


long kexec_file_load(int keyfd, int dirfd, off_t offset,
                       size_t image_size, unsigned flags);

DESCRIPTION

La llamada al sistema kexec_file_load() carga un nuevo núcleo y/o initrd en la memoria para su posterior ejecución. El nuevo núcleo se carga desde un archivo especificado por un descriptor de archivo.

Los argumentos son:

keyfd
Descriptor de archivo de un archivo clave (para verificación criptográfica, opcional).
dirfd
Descriptor de archivo de un directorio que contiene el archivo de imagen del núcleo y/o initrd.
offset
Desplazamiento dentro del archivo especificado por dirfd donde comienza la imagen del núcleo.
image_size
Tamaño de la imagen del núcleo que se va a cargar.
flags
Banderas que controlan el comportamiento de la carga. Consulte la documentación del núcleo para ver los valores posibles y sus significados.

RETURN VALUE

En caso de éxito, kexec_file_load() devuelve 0. En caso de error, devuelve -1 y establece errno para indicar el error.

ERRORS

EACCES
Se denegó el acceso a uno de los archivos o directorios especificados.
EBADF
Un descriptor de archivo proporcionado no es válido o no se refiere a un archivo abierto.
EINVAL
Se encontró un valor inválido. Esto puede deberse a varias razones, incluyendo:
El valor en cmdline[cmdline_len-1] no es '\0'.
El archivo al que se refiere kernel_fd o initrd_fd está vacío (longitud cero).
EINVAL
Los valores proporcionados para los segmentos del núcleo o initrd son incorrectos. Por ejemplo, el tamaño especificado en ts excede el valor en el campo memsz correspondiente.
EINVAL
nr_segments excede KEXEC_SEGMENT_MAX (16).
EINVAL
Dos o más de los búferes de destino del núcleo se superponen.
EINVAL
El valor en cmdline[cmdline_len-1] no es '\0'.
EINVAL
El archivo al que se refiere kernel_fd o initrd_fd está vacío (longitud cero).
ENOEXEC
kernel_fd no se refiere a un archivo abierto, o el núcleo no puede cargar este archivo. Actualmente, el archivo debe ser un bzImage y contener un núcleo x86 que pueda cargarse por encima de 4 GiB en memoria (consulte el archivo fuente del núcleo Documentation/x86/boot.txt).
ENOMEM
No se pudo asignar memoria.
EPERM
El llamante no tiene la capacidad CAP_SYS_BOOT.

STANDARDS

Linux.

HISTORY

Linux 2.6.13.
kexec_file_load()
Linux 3.17.
