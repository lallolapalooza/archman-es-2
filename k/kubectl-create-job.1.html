NOMBRE

kubectl create job - Crear un job con el nombre especificado

SINOPSIS

kubectl create job [OPCIONES]

DESCRIPCIÓN

Crea un job con el nombre especificado.

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando un campo o clave de mapa falta en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--dry-run="none" Debe ser "none", "server" o "client". Si es estrategia de cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si es estrategia de servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--field-manager="kubectl-create" Nombre del gestor utilizado para rastrear la propiedad de los campos.

--from="" El nombre del recurso desde el cual crear un Job (solo se admite cronjob).

--image="" Nombre de la imagen a ejecutar.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--save-config=false Si es verdadero, la configuración del objeto actual se guardará en su anotación. De lo contrario, la anotación permanecerá sin cambios. Este indicador es útil cuando desea realizar kubectl apply en este objeto en el futuro.

--show-managed-fields=false Si es verdadero, conserva los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a un archivo de plantilla a utilizar cuando -o=go-template, -o=go-template-file. El formato de plantilla es plantillas de golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Debe ser uno de: strict (o true), warn, ignore (o false). "true" o "strict" usarán un esquema para validar la entrada y fallarán la solicitud si es inválida. Realizará validación del lado del servidor si ServerSideFieldValidation está habilitado en el api-server, pero recurrirá a una validación del lado del cliente menos confiable si no lo está. "warn" advertirá sobre campos desconocidos o duplicados sin bloquear la solicitud si la validación del lado del servidor está habilitada en el API server, y se comportará como "ignore" en caso contrario. "false" o "ignore" no realizarán ninguna validación de esquema, descartando silenciosamente cualquier campo desconocido o duplicado.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario normal o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, este indicador se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad certificadora

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a utilizar

--context="" El nombre del contexto de kubeconfig a utilizar

--disable-compression=false Si es verdadero, desactiva la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará en cuanto a validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes de la CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funcionalidad KUBECTL_KUBERC=false o desactivando la funcionalidad KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud de CLI

--password="" Contraseña para autenticación básica al servidor de API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" El tiempo de espera antes de rendirse en una única solicitud al servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa que no hay tiempo de espera para las solicitudes.

-s, --server="" La dirección y el puerto del servidor de API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor

--token="" Token Bearer para la autenticación al servidor de API

--user="" El nombre del usuario de kubeconfig a utilizar

--username="" Nombre de usuario para autenticación básica al servidor de API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión reportada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero

EJEMPLO

  # Crear un job
  kubectl create job my-job --image=busybox
  # Crear un job con un comando
  kubectl create job my-job --image=busybox -- date
  # Crear un job a partir de un cron job llamado "a-cronjob"
  kubectl create job test-job --from=cronjob/a-cronjob
