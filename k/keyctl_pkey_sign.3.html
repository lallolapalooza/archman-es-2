keyctl_pkey_sign(3)

Paquete: keyutils

Licencias: GPL2, LGPL2.1

KEYCTL_PKEY_SIGN(3) Firmas de Clave Pública de Linux KEYCTL_PKEY_SIGN(3)

NOMBRE

keyctl_pkey_sign, keyctl_pkey_verify - Generar y verificar firmas

SINOPSIS

#include <keyutils.h>

long keyctl_pkey_sign(key_serial_t key, const char *info,
                      const void *data, size_t data_len,
                      void *sig, size_t sig_len);

long keyctl_pkey_verify(key_serial_t key, const char *info,
                        const void *data, size_t data_len,
                        const void *sig, size_t sig_len);

DESCRIPCIÓN

keyctl_pkey_sign() solicita al kernel que utilice los datos criptográficos adjuntos a una clave para generar una firma desvinculada para un bloque de datos. Tenga en cuenta que esto puede implicar llamar a hardware criptográfico.

keyctl_pkey_verify() solicita al kernel que utilice la clave para verificar la firma contra el mismo bloque de datos. Esto también puede implicar llamar a hardware criptográfico.

El llamante debe tener permiso de búsqueda sobre una clave para poder realizar cualquiera de las operaciones.

Al invocar la función, key indica la clave que proporcionará el material criptográfico e info apunta a una cadena de parámetros "key[=valor]" separados por espacios o tabulaciones que indican cosas como formas de codificación y contraseñas para desbloquear la clave; consulte asymmetric-key(7) para obtener más información.

data y datalen indican la dirección y el tamaño del búfer de datos a firmar y sig y siglen indican la dirección y el tamaño del búfer de firma. La función de firma extrae datos del búfer de datos, genera una firma a partir de ellos y coloca la salida en el búfer de firma. La función de verificación también extrae datos del búfer de datos, luego descifra la firma y compara el resultado.

Tenga en cuenta que el búfer de datos está estrictamente limitado en capacidad, y generalmente no puede contener más bits que el tamaño de la clave. Se espera que el llamante haya pre-procesado los datos reales y, por lo tanto, pasará la salida del digest a esta función. El nombre del digest utilizado debe pasarse como parte de la cadena de información como hash=<nombre> para usarlo en la construcción de los metadatos de la firma.

keyctl_pkey_query(2) puede ser llamado para averiguar cuán grandes deben ser los búferes y cuál puede ser el tamaño máximo de los datos para una codificación de firma específica.

Tenga en cuenta que no todas las claves de tipo asimétrico admitirán estas operaciones; además, las operaciones disponibles pueden depender de qué componentes del material clave están disponibles: típicamente, la cifrado solo requiere la clave pública, pero el descifrado requiere la clave privada también. Qué operaciones se admiten en una clave particular también se puede determinar utilizando la función de consulta.

VALOR DE RETORNO

En caso de éxito, keyctl_pkey_sign() devuelve la cantidad de datos escritos en el búfer de firma. keyctl_pkey_verify() devolverá 0 en este caso ya que no escribe en el espacio de usuario.

En caso de error, se devolverá el valor -1 y errno habrá sido configurado a un error apropiado.

ERRORES

ENOKEY
La clave especificada es inválida.
EKEYEXPIRED
La clave especificada ha expirado.
EKEYREVOKED
La clave especificada ha sido revocada.
EACCES
La clave existe, pero no es buscable por el proceso llamante.
EINVAL, EBADMSG, EOVERFLOW
Alguna parte del material clave o los datos de la firma es incorrecta.
EKEYREJECTED
La verificación de la firma falló.
ENOPKG
Alguna instalación necesaria para completar la operación solicitada no está disponible. Probablemente sea un algoritmo de digest o cifrado solicitado o requerido.
EFAULT
Dirección incorrecta.

ENLACE

Esta es una función de biblioteca que se puede encontrar en libkeyutils. Al enlazar, se debe especificar -lkeyutils al enlazador.
