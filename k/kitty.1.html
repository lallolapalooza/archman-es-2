Nombre

kitty - El emulador de terminal rápido y rico en funciones

kitty [opciones] [programa-a-ejecutar ...]

Ejecuta el emulador de terminal kitty. También puedes especificar el programa a ejecutar dentro de kitty como argumentos normales después de las opciones. Por ejemplo: kitty --hold sh -c "echo hola, mundo"

Para obtener documentación completa sobre kitty, consulta: https://sw.kovidgoyal.net/kitty/

Opciones

--app-id <CLS>, --class <CLS>
En Wayland, establece el ID de la aplicación. En X11, establece la parte de la clase de la propiedad de ventana WM_CLASS. Por defecto: kitty
--name <NOMBRE>, --os-window-tag <NOMBRE>
En Wayland, establece la etiqueta de la ventana, cuando se especifica. En X11, establece la parte del nombre de la propiedad WM_CLASS, cuando no está definida, por defecto se utiliza el valor de kitty --class.
--title <TÍTULO>, -T <TÍTULO>
Establece el título de la ventana del sistema operativo. Esto anulará cualquier título establecido por el programa que se ejecuta dentro de kitty, fijando permanentemente el título de la ventana del sistema operativo. Por lo tanto, úsalo solo si estás ejecutando un programa que no establece títulos.
--config <CONFIGURACIÓN>, -c <CONFIGURACIÓN>
Especifica una ruta a los archivos de configuración a utilizar. Todos los archivos de configuración se fusionan en el archivo incorporado kitty.conf, anulando los valores incorporados. Esta opción se puede especificar varias veces para leer varios archivos de configuración en secuencia, los cuales se fusionan. Utiliza el valor especial NONE para no cargar ningún archivo de configuración.

Si no se especifica esta opción, los archivos de configuración se buscan en el siguiente orden: $XDG_CONFIG_HOME/kitty/kitty.conf, ~/.config/kitty/kitty.conf, $XDG_CONFIG_DIRS/kitty/kitty.conf. El primero que exista se utiliza como archivo de configuración.

Si la variable de entorno KITTY_CONFIG_DIRECTORY <#envvar-KITTY_CONFIG_DIRECTORY> está especificada, ese directorio se utiliza siempre y la búsqueda anterior no ocurre.

Si existe /etc/xdg/kitty/kitty.conf, se fusiona antes (es decir, con menor prioridad) que cualquier archivo de configuración de usuario. Se puede utilizar para especificar valores predeterminados a nivel de sistema para todos los usuarios. Puedes usar - o /dev/stdin para leer la configuración desde STDIN.

--override <ANULACIÓN>, -o <ANULACIÓN>
Anula opciones de configuración individuales, se puede especificar varias veces. Sintaxis: nombre=valor. Por ejemplo: kitty -o tamaño_fuente=20
--directory <DIRECTORIO>, --working-directory <DIRECTORIO>, -d <DIRECTORIO>
Cambia al directorio especificado al iniciar. Por defecto: .
--detach [=no]
Desconéctate de la terminal de control, si existe. En macOS, usa open -a kitty.app -n en su lugar.
--detached-log <DETACHED_LOG>
Ruta a un archivo de registro para almacenar STDOUT/STDERR al usar --detach
--session <SESIÓN>
Ruta a un archivo que contiene la sesión de inicio (pestañas, ventanas, diseño, programas). Usa - para leer desde STDIN. Consulta Sesiones <#sessions> para obtener detalles y un ejemplo. Las variables de entorno en el nombre del archivo se expanden, las rutas relativas se resuelven en relación con el directorio de configuración de kitty. El valor especial none significa que no se utilizará ninguna sesión, incluso si la opción startup_session <#opt-kitty.startup_session> se ha especificado en kitty.conf. Ten en cuenta que el uso de esta opción significa que los argumentos de la línea de comandos que especifican un programa para ejecutar se ignoran.
--hold [=no]
Permanece abierto, en un prompt de shell, después de que el proceso hijo termine. Ten en cuenta que esto solo afecta a la primera ventana. Puedes salir usando el atajo de cerrar ventana o ejecutando el comando exit.
--single-instance [=no], -1 [=no]
Si se especifica, solo se ejecutará una única instancia de kitty. Las invocaciones nuevas crearán una nueva ventana de nivel superior en la instancia de kitty existente. Esto permite que kitty comparta una única caché de sprites en la GPU y también reduce el tiempo de inicio. También puedes tener grupos separados de instancias de kitty usando la opción kitty --instance-group.
--instance-group <GRUPO_INSTANCIA>
Se utiliza en combinación con la opción kitty --single-instance. Todas las invocaciones de kitty con el mismo kitty --instance-group resultarán en la creación de nuevas ventanas en la primera instancia de kitty dentro de ese grupo.
--wait-for-single-instance-window-close [=no]
Normalmente, al usar kitty --single-instance, kitty abrirá una nueva ventana en una instancia existente y saldrá inmediatamente. Con esta opción, no saldrá hasta que se cierre la ventana recién abierta. Ten en cuenta que si no se encuentra ninguna instancia previa, kitty esperará de todos modos, independientemente de esta opción.
--listen-on <LISTEN_ON>
Escucha en la dirección del socket especificada para mensajes de control. Por ejemplo, kitty --listen-on=unix:/tmp/mykitty o kitty --listen-on=tcp:localhost:12345. En sistemas Linux, también puedes usar sockets UNIX abstractos, no asociados con un archivo, de esta manera: kitty --listen-on=unix:@mykitty. Las variables de entorno se expanden y las rutas relativas se resuelven con respecto al directorio temporal. Para controlar kitty, puedes enviarle comandos con kitten @ usando la opción kitten @ --to <#cmdoption-kitten-to> para especificar esta dirección. Ten en cuenta que esto se ignorará a menos que allow_remote_control <#opt-kitty.allow_remote_control> se establezca en: yes, socket o socket-only. Esto también se puede especificar en kitty.conf. Para iniciar en modo sin cabeza, sin una ventana real, usa kitty --start-as=hidden.
--start-as <START_AS>
Controla cómo se crea la ventana inicial de kitty. Por defecto: normal Opciones: fullscreen, hidden, maximized, minimized, normal
--position <POSICIÓN>
La posición, por ejemplo 10x20, en la pantalla donde colocar la primera ventana del sistema operativo de kitty. Esto puede funcionar o no dependiendo de las políticas del entorno de escritorio/gestor de ventanas. Nunca funciona en Wayland. Consulta también remember_window_position <#opt-kitty.remember_window_position> para que kitty intente restaurar automáticamente la posición anterior de la ventana.
--grab-keyboard [=no]
Capturar el teclado. Esto significa que los atajos globales definidos en el sistema operativo se pasarán a kitty en su lugar. Útil si deseas crear una ventana modal del sistema operativo. Qué tan bien funciona esto depende del sistema operativo/gestor de ventanas/entorno de escritorio. En Wayland, solo funciona si el compositor implementa el protocolo inhibit-keyboard-shortcuts https://wayland.app/protocols/keyboard-shortcuts-inhibit-unstable-v1mite que las aplicaciones capture

Pestañas y

ventanas

kitty es capaz de ejecutar múltiples programas organizados en pestañas y ventanas. El nivel superior de organización es la ventana del SO <#term-os_window>. Cada ventana del SO consiste en una o más pestañas <#term-tab>. Cada pestaña consiste en una o más ventanas de kitty <#term-window>. Las ventanas de kitty pueden organizarse en múltiples diseños diferentes <#term-layout>, como las ventanas se organizan en un gestor de ventanas en mosaico. Name


kitty — GPU-accelerated cross-platform terminal emulator






Options


The most common way to use kitty is to invoke it and then use its
    keyboard shortcuts to manage windows and tabs. For example, to split the
    current window vertically:






map ctrl+shift+v split_v






To split the current window horizontally:






map ctrl+shift+h split_h






To move between windows, you can use the following shortcuts:






map ctrl+down neighboring_window down
map ctrl+up neighboring_window up
map ctrl+left neighboring_window left
map ctrl+right neighboring_window right






Alternatively, you can use the following shortcuts:






map w left
map shift+left move_window right
map ctrl+down neighboring_window down
map shift+down move_window up
...










Tabs   and windows


You can also define a shortcut to switch to the previously active
    window:






map ctrl+p nth_window -1






nth_window <#action-nth_window> will focus the nth
    window for positive numbers (starting from zero) and the previously active
    windows for negative numbers.


To switch to the nth OS window, you can define
    nth_os_window <#action-nth_os_window>. Only positive numbers
    are accepted, starting from one.


You can define shortcuts to detach the current window and move it
    to another tab or another OS window:






# moves the window into a new OS window
map ctrl+f2 detach_window
# moves the window into a new tab
map ctrl+f3 detach_window new-tab
# moves the window into the previously active tab
map ctrl+f3 detach_window tab-prev
# moves the window into the tab at the left of the active tab
map ctrl+f3 detach_window tab-left
# moves the window into a new tab created to the left of the active tab
map ctrl+f3 detach_window new-tab-left
# asks which tab to move the window into
map ctrl+f4 detach_window ask






Similarly, you can detach the current tab, with:






# moves the tab into a new OS window
map ctrl+f2 detach_tab
# asks which OS Window to move the tab into
map ctrl+f4 detach_tab ask






Finally, you can define a shortcut to close all windows in a tab
    other than the currently active window:






map f9 close_other_windows_in_tab
