KAMENE(1) Manual de Comandos Generales KAMENE(1)

NOMBRE

kamene - Herramienta interactiva de manipulación de paquetes

SINOPSIS

kamene [opciones]

DESCRIPCIÓN

Esta página del manual documenta brevemente la herramienta kamene.

kamene es una potente herramienta interactiva para la manipulación de paquetes, generador de paquetes, escáner de red, descubrimiento de red, capturador de paquetes, etc. Actualmente puede reemplazar a hping, partes de nmap, arpspoof, arp-sk, arping, tcpdump, tshark, p0f, ...

kamene utiliza el intérprete de Python como tablero de comandos. Eso significa que puedes usar directamente el lenguaje Python (asignar variables, usar bucles, definir funciones, etc.) Si proporcionas un archivo como parámetro al ejecutar kamene, tu sesión (variables, funciones, instancias, ...) se guardará al salir del intérprete y se restaurará la próxima vez que lances kamene.

La idea es simple. Este tipo de herramientas hacen dos cosas: enviar paquetes y recibir respuestas. Eso es lo que hace kamene: defines un conjunto de paquetes, los envía, recibe respuestas, empareja solicitudes con respuestas y devuelve una lista de pares de paquetes (solicitud, respuesta) y una lista de paquetes no emparejados. Esto tiene la gran ventaja sobre herramientas como nmap o hping de que una respuesta no se reduce a (abierto/cerrado/filtrado), sino que es el paquete completo.

Sobre esto se pueden construir funciones de nivel superior, por ejemplo, una que haga traceroutes y devuelva solo el TTL inicial de la solicitud y la IP de origen de la respuesta. Una que haga ping a toda una red y devuelva la lista de máquinas que responden. Una que haga un escaneo de puertos y devuelva un informe LaTeX.

OPCIONES

Las opciones para kamene son:

-h
muestra el uso
-d
aumenta la verbosidad del registro. Se puede usar varias veces.
-s ARCHIVO
usa ARCHIVO para guardar/cargar valores de sesión (variables, funciones, instancias, ...)
-p ARCHIVO_PREARRANQUE
usa ARCHIVO_PREARRANQUE en lugar de $HOME/.kamene_prestart.py como archivo de pre-arranque
-P
no ejecuta el archivo de pre-arranque
-c ARCHIVO_ARRANQUE
usa ARCHIVO_ARRANQUE en lugar de $HOME/.kamene_startup.py como archivo de arranque
-C
no ejecuta el archivo de arranque

COMANDOS

Solo se enumeran aquí los comandos esenciales para empezar por el momento.

ls()
lista las capas de protocolo soportadas. Si se proporciona una capa de protocolo como parámetro, lista sus campos y tipos de campos.
lsc()
lista algunos comandos de usuario. Si se proporciona un comando como parámetro, se muestra su documentación.
conf
este objeto contiene la configuración.

ARCHIVOS

$HOME/.kamene_prestart.py Este archivo se ejecuta antes de que se cargue el núcleo de kamene. Solo el objeto conf está disponible. Este archivo se puede usar para manipular la lista conf.load_layers para elegir qué capas se cargarán:

conf.load_layers.remove("bluetooth")
conf.load_layers.append("new_layer")

$HOME/.kamene_startup.py Este archivo se ejecuta después de que kamene se cargue. Se puede usar para configurar algunos de los comportamientos de kamene:

conf.prog.pdfreader="xpdf"
split_layers(UDP,DNS)

EJEMPLOS

Hay ejemplos más detallados disponibles en https://phaethon.github.io/kamene/ Simplemente ejecuta kamene y prueba los siguientes comandos en el intérprete.

Captura y disección de paquetes (con un filtro bpf o salida similar a ethereal):

a=sniff(filter="tcp port 110")
a=sniff(prn = lambda x: x.display)

Reemisión de paquetes capturados:

a=sniff(filter="tcp port 110")
sendp(a)

Reemisión de paquetes de archivo pcap:

sendp(rdpcap("file.cap"))

Traceroute TCP manual:

sr(IP(dst="www.google.com", ttl=(1,30))/TCP(seq=RandInt(), sport=RandShort(), dport=dport)

Escaneo de protocolo:

sr(IP(dst="172.16.1.28", proto=(1,254)))

Ping ARP:

srp(Ether(dst="ff:ff:ff:ff:ff:ff")/ARP(pdst="172.16.1.1/24"))

Escaneo ACK:

sr(IP(dst="172.16.1.28")/TCP(dport=(1,1024), flags="A"))

Envenenamiento de caché ARP:

sendp(Ether(dst=tmac)/ARP(op="who-has", psrc=victim, pdst=target))

Informes:

report_ports("192.168.2.34", (20,30))

ERRORES

No proporciona la IP de origen correcta para rutas que utilizan alias de interfaz.

Puede perder paquetes bajo carga pesada.

El guardado de sesión está limitado por la capacidad de Python para serializar objetos. Como consecuencia, las funciones lambda y los generadores no se pueden guardar, lo que reduce seriamente la utilidad de esta característica.

Los filtros BPF no funcionan en interfaces punto a punto.
