keyctl_dh_compute(3)

Paquete: keyutils

Licencias: GPL2, LGPL2.1

KEYCTL_DH_COMPUTE(3) Llamadas de gestión de claves de Linux KEYCTL_DH_COMPUTE(3)

NOMBRE

keyctl_dh_compute - Calcula una clave pública o secreto compartido Diffie-Hellman
keyctl_dh_compute_kdf - Deriva una clave a partir de un secreto compartido Diffie-Hellman

SINOPSIS

#include <keyutils.h>

long keyctl_dh_compute(key_serial_t private, key_serial_t prime,
key_serial_t base, char *buffer, size_t buflen);

long keyctl_dh_compute_alloc(key_serial_t private,
key_serial_t prime, key_serial_t base, void **_buffer);

long keyctl_dh_compute_kdf(key_serial_t private, key_serial_t prime,
key_serial_t base, char *hashname, char *otherinfo,
size_t otherinfolen, char *buffer, size_t buflen);

DESCRIPCIÓN

keyctl_dh_compute() calcula una clave pública Diffie-Hellman o un secreto compartido. Ese cálculo es:

base ^ private ( mod prime )

Cuando base es una clave que contiene el valor del generador compartido, se calcula la clave pública remota. Cuando base es una clave que contiene la clave pública remota, se calcula el secreto compartido.

base, private y prime deben referirse a claves de tipo user que contengan los parámetros para el cálculo. Cada una de estas claves debe otorgar al llamante permiso de lectura para poder ser utilizada.

buffer y buflen especifican el búfer en el que se colocará el resultado calculado. buflen puede ser cero, en cuyo caso el búfer no se utiliza y se obtiene la longitud mínima del búfer.

keyctl_dh_compute_alloc() es similar a keyctl_dh_compute() excepto en que asigna un búfer lo suficientemente grande como para contener los datos de la carga útil y coloca los datos en él. Si tiene éxito, un puntero al búfer se coloca en *_buffer. El llamante debe liberar el búfer.

keyctl_dh_compute_kdf() deriva una clave de un secreto compartido Diffie-Hellman de acuerdo con el protocolo especificado en SP800-56A. El cálculo Diffie-Hellman se basa en las mismas primitivas que se discuten para keyctl_dh_compute().

Para implementar el protocolo de SP800-56A, base es una clave que contiene la clave pública remota para calcular el secreto compartido Diffie-Hellman. Ese secreto compartido se post-procesa con una función de derivación de clave.

hashname especifica el nombre de la API criptográfica del kernel de Linux para un hash que se utilizará para la función de derivación de clave, como sha256. hashname debe ser una cadena terminada en NULL. Consulte /proc/crypto para ver los hashes disponibles en el sistema.

Siguiendo la especificación de SP800-56A, sección 5.8.1.2, se puede proporcionar el parámetro otherinfo. El formato del campo OtherInfo está definido por el llamante. El llamante también puede especificar NULL como un argumento válido cuando no se procesarán datos de OtherInfo. La longitud del parámetro otherinfo se especifica con otherinfolen y está restringida a una longitud máxima por el kernel.

El KDF devuelve el número de bytes solicitados especificado con el parámetro genlen o buflen dependiendo de la función invocada.

buffer y buflen especifican el búfer en el que se colocará el resultado calculado.

VALOR DE RETORNO

En caso de éxito, keyctl_dh_compute() devuelve la cantidad de datos colocados en el búfer cuando buflen no es cero. Cuando buflen es cero, se devuelve la longitud mínima del búfer para contener los datos.

En caso de éxito, keyctl_dh_compute_alloc() devuelve la cantidad de datos en el búfer.

En caso de error, ambas funciones establecen errno a un código apropiado y devuelven el valor -1.

ERRORES

ENOKEY
Una de las claves especificadas es inválida o no se puede leer.
EINVAL
El puntero del búfer es inválido o buflen es demasiado pequeño.
EOPNOTSUPP
Una de las claves no era una clave de usuario válida.
EMSGSIZE
Al usar keyctl_dh_compute_kdf(), el tamaño de otherinfolen o buflen es demasiado grande.

ENLAZADO

Esta es una función de biblioteca que se puede encontrar en libkeyutils. Al enlazar, se debe especificar -lkeyutils al enlazador.
