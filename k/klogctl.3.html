klogctl(3)

syslog(2) System Calls Manual syslog(2)

NOMBRE

syslog, klogctl - leer y/o borrar el buffer de mensajes del kernel; establecer el nivel de consola del log

LIBRERÍA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/syscall.h>     /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_syslog, int type, char *bufp, int size);
/* La interfaz de glibc */
#include <sys/klog.h>
int klogctl(int type, char *bufp, int size);

DESCRIPCIÓN

Nota: Probablemente, estás buscando la función de biblioteca C syslog(), que se comunica con syslogd(8); consulta syslog(3) para más detalles.

Esta página describe la llamada al sistema syslog() del kernel, que se utiliza para controlar el buffer del kernel deprintk(); la función wrapper de glibc para la llamada al sistema se llama klogctl().

El buffer de log del kernel

El kernel tiene un buffer cíclico de tamaño LOG_BUF_LEN en el que se almacenan los mensajes pasados como argumentos a la función del kernel printk() (independientemente de su nivel de log). En kernels tempranos, LOG_BUF_LEN tenía el valor 4096; desde Linux 1.3.54, era 8192; desde Linux 2.1.113, era 16384; desde Linux 2.4.23/2.6, el valor es una opción de configuración del kernel (CONFIG_LOG_BUF_SHIFT, valor por defecto dependiente de la arquitectura). Desde Linux 2.6.6, el tamaño se puede consultar con el tipo de comando 10 (ver más abajo).

Comandos

El argumento type determina la acción realizada por esta función. La lista siguiente especifica los valores para type. Los nombres simbólicos están definidos en el código fuente del kernel, pero no se exportan al espacio de usuario; tendrás que usar los números, o definir los nombres tú mismo.

SYSLOG_ACTION_CLOSE (0)
Cerrar el log. Actualmente no hace nada.
SYSLOG_ACTION_OPEN (1)
Abrir el log. Actualmente no hace nada.
SYSLOG_ACTION_READ (2)
Leer del log. La llamada espera hasta que el buffer de log del kernel no esté vacío, y entonces lee como máximo len bytes en el buffer apuntado por bufp. La llamada devuelve el número de bytes leídos. Los bytes leídos del log desaparecen del buffer de log: la información solo se puede leer una vez. Esta es la función ejecutada por el kernel cuando un programa de usuario lee /proc/kmsg.
SYSLOG_ACTION_READ_ALL (3)
Leer todos los mensajes restantes en el buffer circular, colocándolos en el buffer apuntado por bufp. La llamada lee los últimos len bytes del buffer de log (de forma no destructiva), pero no leerá más de lo que se escribió en el buffer desde el último comando de "borrar buffer circular" (ver comando 5 más abajo). La llamada devuelve el número de bytes leídos.
SYSLOG_ACTION_READ_CLEAR (4)
Leer y borrar todos los mensajes restantes en el buffer circular. La llamada hace exactamente lo mismo que para un type de 3, pero también ejecuta el comando "borrar buffer circular".
SYSLOG_ACTION_CLEAR (5)
La llamada ejecuta solo el comando "borrar buffer circular". Los argumentos bufp y size se ignoran.
Este comando no borra realmente el buffer circular. Más bien, establece una variable de contabilidad del kernel que determina los resultados devueltos por los comandos 3 (SYSLOG_ACTION_READ_ALL) y 4 (SYSLOG_ACTION_READ_CLEAR). Este comando no tiene ningún efecto en los comandos 2 (SYSLOG_ACTION_READ) y 9 (SYSLOG_ACTION_SIZE_UNREAD).
SYSLOG_ACTION_CONSOLE_OFF (6)
El comando guarda el valor actual de console_loglevel y luego establece console_loglevel a minimum_console_loglevel, de modo que no se impriman mensajes en la consola. Antes de Linux 2.6.32, el comando simplemente establecía console_loglevel a minimum_console_loglevel. Ver la discusión de /proc/sys/kernel/printk, más abajo.
Los argumentos bufp y size se ignoran.
SYSLOG_ACTION_CONSOLE_ON (7)
Si se ha realizado un comando previo SYSLOG_ACTION_CONSOLE_OFF, este comando restaura console_loglevel al valor que fue guardado por ese comando. Antes de Linux 2.6.32, este comando simplemente establecía console_loglevel a default_console_loglevel. Ver la discusión de /proc/sys/kernel/printk, más abajo.
Los argumentos bufp y size se ignoran.
SYSLOG_ACTION_CONSOLE_LEVEL (8)
La llamada establece console_loglevel al valor dado en size, que debe ser un entero entre 1 y 8 (inclusive). El kernel fuerza silenciosamente un valor mínimo de minimum_console_loglevel para size. Ver la sección de nivel de log para detalles. El argumento bufp se ignora.
SYSLOG_ACTION_SIZE_UNREAD (9) (desde Linux 2.4.10)
La llamada devuelve el número de bytes actualmente disponibles para ser leídos del buffer de log del kernel a través del comando 2 (SYSLOG_ACTION_READ). Los argumentos bufp y size se ignoran.
SYSLOG_ACTION_SIZE_BUFFER (10) (desde Linux 2.6.6)
Este comando devuelve el tamaño total del buffer de log del kernel. Los argumentos bufp y size se ignoran.

Todos los comandos excepto 3 y 10 requieren privilegios. En kernels de Linux anteriores a Linux 2.6.37, los tipos de comando 3 y 10 se permiten a procesos sin privilegios; desde Linux 2.6.37, estos comandos solo se permiten a procesos sin privilegios si /proc/sys/kernel/dmesg_restrict tiene el valor 0. Antes de Linux 2.6.37, "con privilegios" significa que el llamador tiene la capacidad CAP_SYS_ADMIN. Desde Linux 2.6.37, "con privilegios" significa que el llamador tiene la capacidad CAP_SYS_ADMIN (ahora obsoleta para este propósito) o la (nueva) capacidad CAP_SYSLOG.

/proc/sys/kernel/printk

/proc/sys/kernel/printk es un archivo escribible que contiene cuatro valores enteros que influyen en el comportamiento deprintk() del kernel al imprimir o registrar mensajes de error. Los cuatro valores son:

console_loglevel
Solo los mensajes con un nivel de log inferior a este valor se imprimirán en la consola. El valor por defecto para este campo es DEFAULT_CONSOLE_LOGLEVEL (7), pero se establece a 4 si la línea de comandos del kernel contiene la palabra "quiet", 10 si la línea de comandos del kernel contiene la palabra "debug", y a 15 en caso de un fallo del kernel (los 10 y 15 son simplemente tontos y equivalentes a 8). El valor de console_loglevel puede establecerse (a un valor en el rango 1–8) mediante una llamada a syslog() con un type de 8.
default_message_loglevel
Este valor se usará como nivel de log para los mensajes de printk() que no tengan un nivel explícito. Hasta e incluyendo Linux 2.6.38, el valor fijo por defecto para este campo era 4 (KERN_WARNING); desde Linux 2.6.39, el valor por defecto está definido por la opción de configuración del kernel CONFIG_DEFAULT_MESSAGE_LOGLEVEL, que por defecto es 4.
minimum_co
Este valor no puede ser excedido por console_loglevel (el valor máximo permitido para console_loglevel). El valor por defecto es 1 (KERN_EMERG). Los valores de minimum_console_loglevel solo pueden ser cambiados por el usuario root.
default_console_loglevel
Este es el valor que se restaura al campo console_loglevel por el comando 7 (SYSLOG_ACTION_CONSOLE_ON). El valor por defecto es 4 (KERN_WARNING).

El contenido de /proc/sys/kernel/printk se puede leer y modificar. Si se modifica, los cambios surten efecto inmediatamente. Por ejemplo, para ver los valores, ejecuta:

cat /proc/sys/kernel/printk

y para establecer el nivel de log de la consola a 4 (mensajes de advertencia y superiores), ejecuta:

echo "4 4 1 7" > /proc/sys/kernel/printk

El primer número, 4, es el nuevo console_loglevel. Los otros tres números son default_message_loglevel, minimum_console_loglevel, y default_console_loglevel, respectivamente. Establecerlos a sus valores por defecto usuales (4, 1, 7) hace que el cambio solo afecte a console_loglevel.

Tener un valor bajo para console_loglevel puede ser útil cuando se está depurando el kernel o si un mensaje de log está inundando la consola.

VALOR_DE_RETORNO

En caso de éxito, los comandos de lectura (2, 3, 4) devuelven el número de bytes leídos. El comando 9 (SYSLOG_ACTION_SIZE_UNREAD) devuelve el número de bytes sin leer. El comando 10 (SYSLOG_ACTION_SIZE_BUFFER) devuelve el tamaño total del buffer del kernel. Los otros comandos devuelven 0.

En caso de error, se devuelve -1 y errno se establece adecuadamente.

ERRORES

EBADF
El argumento bufp no es un puntero válido (por ejemplo, NULL).
EINVAL
Un argumento type no es válido. O bien size es negativo, o bien para los comandos 6-8, size está fuera del rango permitido.
ENOTTY
El tipo de llamada al sistema syslog() no está soportado en este kernel. (Esto no debería ocurrir en ningún kernel Linux moderno).
EPERM
El proceso no tiene los privilegios necesarios para realizar la operación solicitada (ver la sección de Comandos).

ESTÁNDARES

Esta llamada al sistema es específica de Linux.

VER_TAMBIÉN

dmesg(1), syslog(3), capabilities(7), syslogd(8)

NAME

klogctl, syslog - Control the kernel logging system

LIBRARY

Standard C library (libc, −lc)

SYNOPSIS

#include <sys/klog.h>

int klogctl(int type, char *buf, int len);

DESCRIPTION

The klogctl() system call is an interface to the kernel's logging system. It allows a process to read messages from the kernel's message buffer and to control the kernel's logging behavior.

The behavior of klogctl() is determined by the value of the type argument. The possible values for type are:

SYSLOG_ACTION_CLOSE (0)
Close the console device. This is intended for use by the kernel itself.
SYSLOG_ACTION_OPEN (1)
Open the console device. This is intended for use by the kernel itself.
SYSLOG_ACTION_READ_ALL (2)
Read all messages currently in the kernel log buffer. The messages are returned in buf, with a maximum of len bytes. The messages are null-terminated. If buf is not large enough, as many messages as possible will be returned.
SYSLOG_ACTION_READ_CURRENT (3)
Read messages logged since the last SYSLOG_ACTION_READ_ALL or SYSLOG_ACTION_READ_CURRENT. The messages are returned in buf, with a maximum of len bytes. The messages are null-terminated.
SYSLOG_ACTION_READ_LAST (4)
Read the last len messages from the kernel log buffer. The messages are returned in buf and are null-terminated.
SYSLOG_ACTION_GET_PARM (10)
Get parameters. Currently, only SYSLOG_ACTION_GET_PARM_SIZE_BUFFER is implemented. Returns the size of the kernel log buffer in len. buf is ignored.
However, many older systems implement a different set of values for type:
SYSLOG_ACTION_CONSOLE_PRINT (5)
Print the string in buf (up to len bytes) to the console.
SYSLOG_ACTION_CONSOLE_INFO (6)
Same as SYSLOG_ACTION_READ_ALL.
SYSLOG_ACTION_CONSOLE_SIZE (7)
Return the size of the console buffer in len.
SYSLOG_ACTION_CONSOLE_LEVEL (8)
Set the console log level. The new level is specified in len. See The log level section below for a description of the levels.
SYSLOG_ACTION_CONSOLE_OFF (9)
Turn off console logging.

The syslog() library function is a wrapper around klogctl().

When type is 2, 3, or 4, klogctl() reads messages from the kernel's message buffer. The messages are stored in the buffer pointed to by buf, and the number of bytes read is limited by len. The messages are null-terminated.

When type is 8, the level to which console logging is set is specified by the value in len. This level is an integer between 1 and 8, inclusive. The buf parameter is ignored.

When type is 10, this call returns the size of the kernel log buffer in the integer pointed to by len. The buf parameter is ignored.

Console logging parameters

The following parameters can be inspected or modified using klogctl() with appropriate values of type:

console_loglevel
The value in this field is the minimum value to which console_loglevel can be set.
default_console_loglevel
This is the default value for console_loglevel.

The log level

Every printk() message has its own log level. If the log level is not explicitly specified as part of the message, it defaults to default_message_loglevel. The conventional meaning of the log level is as follows:

Kernel constant Level value Meaning
KERN_EMERG 0 System is unusable
KERN_ALERT 1 Action must be taken immediately
KERN_CRIT 2 Critical conditions
KERN_ERR 3 Error conditions
KERN_WARNING 4 Warning conditions
KERN_NOTICE 5 Normal but significant condition
KERN_INFO 6 Informational
KERN_DEBUG 7 Debug-level messages

The kernel printk() routine will print a message on the console only if it has a log level less than the value of console_loglevel.

RETURN VALUE

For type equal to 2, 3, or 4, a successful call to syslog() returns the number of bytes read. For type 9, syslog() returns the number of bytes currently available to be read on the kernel log buffer. For type 10, syslog() returns the total size of the kernel log buffer. For other values of type, 0 is returned on success.

In case of error, -1 is returned, and errno is set to indicate the error.

ERRORS

EINVAL
Bad arguments (e.g., bad type; or for type 2, 3, or 4, buf is NULL, or size is less than zero; or for type 8, the level is outside the range 1 to 8).
ENOSYS
This syslog() system call is not available, because the kernel was compiled with the CONFIG_PRINTK kernel-configuration option disabled.
EPERM
An attempt was made to change console_loglevel or clear the kernel message ring buffer by a process without sufficient privilege (more precisely: without the CAP_SYS_ADMIN or CAP_SYSLOG capability).
ERESTARTSYS
System call was interrupted by a signal; nothing was read. (This can be seen only during a trace.)

STANDARDS

Linux.
