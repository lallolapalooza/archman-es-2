NOMBRE

kubectl create token - Solicitar un token de cuenta de servicio

SINOPSIS

kubectl create token [OPCIONES]

DESCRIPCIÓN

Solicita un token de cuenta de servicio.

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--audience=[] Audiencia del token solicitado. Si no se establece, por defecto se solicita un token para usarlo con el servidor de la API de Kubernetes. Se puede repetir para solicitar un token válido para múltiples audiencias.

--bound-object-kind="" Tipo de un objeto al que vincular el token. Los tipos admitidos son Nodo, Pod, Secreto. Si se establece, se debe proporcionar --bound-object-name.

--bound-object-name="" Nombre de un objeto al que vincular el token. El token expirará cuando se elimine el objeto. Requiere --bound-object-kind.

--bound-object-uid="" UID de un objeto al que vincular el token. Requiere --bound-object-kind y --bound-object-name. Si no se establece, se utiliza el UID del objeto existente.

--duration=0s Tiempo de vida solicitado del token emitido. Si no se establece o si se establece en 0, el tiempo de vida lo determinará el servidor automáticamente. El servidor puede devolver un token con un tiempo de vida más largo o más corto.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--show-managed-fields=false Si es verdadero, mantén los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a un archivo de plantilla para usar cuando -o=go-template, -o=go-template-file. El formato de plantilla son plantillas de golang [http://golang.org/pkg/text/template/#pkg-overview].

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario podría ser un usuario regular o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, este flag se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster kubeconfig a utilizar

--context="" El nombre del contexto kubeconfig a utilizar

--disable-compression=false Si es verdadero, desactiva la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará para determinar su validez. Esto hará que tus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes de CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para las preferencias. Esto se puede deshabilitar exportando el feature gate KUBECTL_KUBERC=false o desactivando el feature KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el scope del namespace para esta solicitud de CLI

--password="" Contraseña para la autenticación básica al servidor de la API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" El tiempo de espera antes de rendirse en una única solicitud al servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de espera de las solicitudes.

-s, --server="" La dirección y el puerto del servidor de la API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor

--token="" Token de portador para la autenticación al servidor de la API

--user="" El nombre del usuario kubeconfig a utilizar

--username="" Nombre de usuario para la autenticación básica al servidor de la API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión informada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero

EJEMPLO

  # Solicitar un token para autenticarse en el kube-apiserver como la cuenta de servicio "myapp" en el namespace actual
  kubectl create token myapp
  # Solicitar un token para una cuenta de servicio en un namespace personalizado
  kubectl create token myapp --namespace myns
  # Solicitar un token con una expiración personalizada
  kubectl create token myapp --duration 10m
  # Solicitar un token con una audiencia personalizada
  kubectl create token myapp --audience https://example.com
  # Solicitar un token vinculado a una instancia de un objeto Secret
  kubectl create token myapp --bound-object-kind Secret --bound-object-name mysecret
  # Solicitar un token vinculado a una instancia de un objeto Secret con un UID específico
  kubectl create token myapp --bound-object-kind Secret --bound-object-name mysecret --bound-object-uid 0d4691ed-659b-4935-a832-355f77ee47cc
