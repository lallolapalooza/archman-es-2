KUBERNETES(1)(kubernetes) KUBERNETES(1)(kubernetes)
Eric Paris Ene 2015

NOMBRE

kube-apiserver -

SINOPSIS

kube-apiserver [OPCIONES]

DESCRIPCIÓN

El servidor de API de Kubernetes valida y configura datos para los objetos de API que incluyen pods, servicios, controladores de replicación y otros. El servidor de API presta servicios a operaciones REST y proporciona el frontend al estado compartido del clúster a través del cual interactúan todos los demás componentes.

OPCIONES

--admission-control=[] La admisión se divide en dos fases. En la primera fase, solo se ejecutan los plugins de admisión mutables. En la segunda fase, solo se ejecutan los plugins de admisión de validación. Los nombres de la lista a continuación pueden representar un plugin de validación, un plugin mutable o ambos. El orden de los plugins que se pasan a esta bandera no importa. Lista separada por comas de: AlwaysAdmit, AlwaysDeny, AlwaysPullImages, CertificateApproval, CertificateSigning, CertificateSubjectRestriction, ClusterTrustBundleAttest, DefaultIngressClass, DefaultStorageClass, DefaultTolerationSeconds, DenyServiceExternalIPs, EventRateLimit, ExtendedResourceToleration, ImagePolicyWebhook, LimitPodHardAntiAffinityTopology, LimitRanger, MutatingAdmissionPolicy, MutatingAdmissionWebhook, NamespaceAutoProvision, NamespaceExists, NamespaceLifecycle, NodeRestriction, OwnerReferencesPermissionEnforcement, PersistentVolumeClaimResize, PodNodeSelector, PodSecurity, PodTolerationRestriction, PodTopologyLabels, Priority, ResourceQuota, RuntimeClass, ServiceAccount, StorageObjectInUseProtection, TaintNodesByCondition, ValidatingAdmissionPolicy, ValidatingAdmissionWebhook.

--admission-control-config-file="" Archivo con configuración de control de admisión.

--advertise-address= La dirección IP en la que se anunciará el servidor de API a los miembros del clúster. Esta dirección debe ser accesible por el resto del clúster. Si está en blanco, se utilizará la dirección IP de enlace ( --bind-address). Si --bind-address no se especifica, se utilizará la interfaz predeterminada del host.

--aggregator-reject-forwarding-redirect=true El agregador rechaza el reenvío de la respuesta de redirección al cliente.

--allow-metric-labels=[] El mapa de etiquetas métricas a listas de valores permitidos para esta etiqueta. El formato de la clave es ,. El formato del valor es ,...por ejemplo, métrica1,etiqueta1='v1,v2,v3', métrica1,etiqueta2='v1,v2,v3' métrica2,etiqueta1='v1,v2,v3'.

--allow-metric-labels-manifest="" La ruta al archivo de manifiesto que contiene el mapeo de la lista de permitidos. El formato del archivo es el mismo que el de la bandera --allow-metric-labels. Tenga en cuenta que la bandera --allow-metric-labels anulará el archivo de manifiesto.

--allow-privileged=false Si es verdadero, permite contenedores privilegiados. [predeterminado=falso]

--anonymous-auth=true Habilita las solicitudes anónimas al puerto seguro del servidor de API. Las solicitudes que no son rechazadas por otro método de autenticación se tratan como solicitudes anónimas. Las solicitudes anónimas tienen un nombre de usuario de system:anonymous y un nombre de grupo de system:unauthenticated.

--api-audiences=[] Identificadores de la API. El autenticador de tokens de cuenta de servicio validará que los tokens utilizados contra la API estén vinculados a al menos una de estas audiencias. Si se configura el indicador --service-account-issuer y este indicador no está configurado, este campo se establece por defecto en una lista de un solo elemento que contiene la URL del emisor.

--apiserver-count=1 El número de servidores de API que se ejecutan en el clúster, debe ser un número positivo. (En uso cuando --endpoint-reconciler-type=master-count está habilitado).

--audit-log-maxbackup=0 El número máximo de archivos de registro de auditoría antiguos a conservar. Establecer un valor de 0 significará que no hay restricción en el número de archivos.

--goaway-chance=0 Para evitar que los clientes HTTP/2 se queden atascados en un solo apiserver, cierre aleatoriamente una conexión (GOAWAY). Las otras solicitudes en curso del cliente no se verán afectadas y el cliente se reconectará, probablemente aterrizando en un apiserver diferente después de pasar nuevamente por el balanceador de carga. Este argumento establece la fracción de solicitudes que recibirán un GOAWAY. Los clústeres con apiservers únicos, o que no usan un balanceador de carga, NO deben habilitar esto. El mínimo es 0 (apagado), el máximo es .02 (1/50 solicitudes); .001 (1/1000) es un punto de partida recomendado.
