NOMBRE

korg2gig - Convierte archivos de sonido de KORG a formato GigaStudio.

SINOPSIS

korg2gig [-v] [-f] [--interpret-names] ARCHIVO1 [ ARCHIVO2 ... ] NUEVOARCHIVO

DESCRIPCIÓN

Esta herramienta toma una lista de archivos de sonido KORG, utilizados con teclados sintetizadores KORG como Trinity, Triton, OASYS, M3 o Kronos, y los convierte a un archivo GigaSampler/GigaStudio (.gig). Todos los archivos KORG de entrada se fusionan en un único archivo de salida (.gig).

Para cada archivo de "multisample" (.KMP) de KORG se creará un instrumento GigaStudio separado en el archivo de salida (.gig). Los archivos de muestra (.KSF) de KORG referenciados por dichos archivos de "multisample" (.KMP) se detectan, cargan y escriben automáticamente en el archivo de salida (.gig). Las asignaciones de muestras a regiones del teclado, bucles de muestras y otra información menor de articulación también se convierten. Pero ten en cuenta que el formato "multisample" (.KMP) es muy primitivo. NO guarda la información detallada de articulación de tu teclado KORG como envolventes, LFO y configuraciones de filtro. Esa información se almacena en un archivo de programa (.PCG) separado.

Desafortunadamente, todavía no hay soporte para los archivos de programa/combinaciones/banco (.PCG) de KORG. Echa un vistazo a la opción  --interpret-names para una solución alternativa. Debido a esta falta de soporte para archivos .PCG, aún tendrás que ajustar la configuración de articulación en el archivo de salida (.gig) posteriormente con una aplicación editora de instrumentos como gigedit(1).

Si también estás pasando explícitamente archivos de muestra (.KSF) de KORG, y no están referenciados por ningún archivo de "multisample" (.KMP) que hayas pasado, entonces esas muestras huérfanas se añaden al archivo de salida (.gig) en un grupo de muestras separado llamado "No referenciado". De esa manera, puedes distinguir fácilmente las muestras en el archivo de salida (.gig) que son realmente utilizadas por uno de los instrumentos, y las muestras que aún no se utilizan.

NOTA: Esta herramienta podría necesitar bastante RAM en este momento. Aproximadamente asignará tanta RAM como el tamaño esperado del archivo .gig de salida. Así que asegúrate de tener suficiente RAM libre y/o espacio de intercambio, de lo contrario, esta herramienta podría fallar si no puede asignar el espacio de RAM requerido.

OPCIONES

 ARCHIVO1 [ ARCHIVO2 ... ]
Una lista de archivos de sonido KORG de entrada (.KMP o .KSF). Debes proporcionar al menos un archivo KORG. Los archivos de muestra KORG (.KSF) referenciados en los llamados archivos "multisample" (.KMP) se detectan y cargan automáticamente. Así que en la mayoría de los casos, solo pasarías archivos .KMP como argumentos de archivo de entrada.
 NUEVOARCHIVO
Archivo de salida en formato Gigasampler/GigaStudio (.gig). Si este archivo de salida ya existe, korg2gig abortará con un mensaje de error a menos que especifiques  -f como argumento también.
 -v
muestra la versión y sale.
 -f
Sobrescribe el archivo de salida si ya existe.
 --interpret-names
Intenta adivinar pares de muestras izquierda/derecha y divisiones de velocidad. Esta es una solución desagradable para el hecho de que aún no hay soporte para leer archivos .PCG de KORG. Si nombraste manualmente los multisamples (archivos .KMP) en tu teclado con un esquema como "PIANO 003-120 -R", interpretará las dos pistas como a) rango de división de velocidad (en este ejemplo, de velocidad 3 a 120) y b) pares de muestras estéreo (en este caso, el multisample contiene el canal derecho). Por supuesto, también puedes omitir una o ambas pistas si no deseas una división de velocidad o un par de muestras estéreo para ciertos instrumentos o regiones.
