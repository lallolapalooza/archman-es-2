keyctl_instantiate(3)

Paquete: keyutils

Licencias: GPL2, LGPL2.1

KEYCTL_INSTANTIATE(3) Llamadas de gestión de claves de Linux KEYCTL_INSTANTIATE(3)

NOMBRE

keyctl_assume_authority, keyctl_instantiate, keyctl_instantiate_iov, keyctl_reject, keyctl_negate - funciones de instanciación de claves

SINOPSIS

#include <keyutils.h>

long keyctl_assume_authority(key_serial_t key);

long keyctl_instantiate(key_serial_t key, const void *payload,
size_t plen, key_serial_t keyring);

long keyctl_instantiate_iov(key_serial_t key,
const struct iovec *payload_iov, unsigned ioc,
key_serial_t keyring);

long keyctl_negate(key_serial_t key, unsigned timeout,
key_serial_t keyring);

long keyctl_reject(key_serial_t key, unsigned timeout,
unsigned error, key_serial_t keyring);

DESCRIPCIÓN

keyctl_assume_authority() asume la autoridad para que el hilo que llama pueda manipular e instanciar la key no instanciada especificada.

El hilo que llama debe tener la clave de autorización apropiada residente en uno de sus keyrings para que esto tenga éxito, y esa autoridad no debe haber sido revocada.

La clave autorizadora es asignada por request_key() cuando necesita invocar al espacio de usuario para generar una clave para el proceso solicitante. Esta se adjunta luego a uno de los keyrings del proceso de espacio de usuario al que se le da la tarea de instanciar la clave:

solicitante -> request_key() -> instanciador

Llamar a esta función modifica la forma en que request_key() funciona cuando es llamado posteriormente por el hilo que llama (instanciador); una vez asumida la autoridad, los keyrings del proceso inicial se añaden a la ruta de búsqueda, utilizando el UID, GID, grupos y contexto de seguridad del proceso inicial.

Si un hilo tiene múltiples instanciaciones que tratar, puede llamar a esta función para cambiar la clave de autorización actualmente en vigor. Proporcionar una key de cero desasume la autoridad actualmente asumida.

¡NOTA! Esta es una configuración por hilo y no por proceso, para que un proceso multihilo pueda utilizarse para instanciar varias claves a la vez.

keyctl_instantiate() instancia la carga útil (payload) de una clave no instanciada a partir de los datos especificados. payload y plen especifican los datos para la nueva carga útil. payload puede ser NULL y plen puede ser cero si el tipo de clave lo permite. El tipo de clave puede rechazar los datos si están en el formato incorrecto o son inválidos de alguna otra manera.

keyctl_instantiate_iov() es similar, pero los datos se pasan en una matriz de estructuras iovec en lugar de en un búfer plano. payload_iov apunta a la base de la matriz y ioc indica cuántos elementos hay. payload_iov puede ser NULL o ioc puede ser cero para indicar que no se están suministrando datos.

keyctl_reject() marca una clave como negativamente instanciada y establece el temporizador de expiración en ella. timeout especifica la vida útil de la clave en segundos. error especifica el error que se devolverá cuando una búsqueda alcance la clave (esto suele ser EKEYREJECTED, EKEYREVOKED o EKEYEXPIRED). Tenga en cuenta que keyctl_reject() recurre a keyctl_negate() si el kernel no lo soporta.

keyctl_negate() es como keyctl_reject() con un código de error de ENOKEY.

Solo una clave para la que se ha asumido autoridad puede ser instanciada o negativamente instanciada, y una vez instanciada, la clave de autorización será revocada y el proceso solicitante podrá reanudar.

El keyring de destino, si se proporciona, se asume que pertenece al solicitante inicial, y no al proceso instanciador. Por lo tanto, los IDs especiales de keyring se refieren a los keyrings del proceso solicitante, no a los del llamador, y el UID, etc., del solicitante se utilizarán para acceder a ellos.

El keyring de destino puede ser cero si no se desea un enlace adicional.

El solicitante, no el llamador, debe tener permiso de escritura en el destino para que se cree un enlace allí.

VALOR DE RETORNO

En caso de éxito, keyctl_instantiate() devuelve 0. En caso de error, se devolverá el valor -1 y errno se habrá establecido con un error apropiado.

ERRORES

ENOKEY
La clave o el keyring especificado no es válido.
EKEYEXPIRED
El keyring especificado ha expirado.
EKEYREVOKED
La clave o el keyring especificado ha sido revocado, o la autorización ha sido revocada.
EINVAL
Los datos de la carga útil no son válidos.
ENOMEM
Memoria insuficiente para almacenar la nueva carga útil o para expandir el keyring de destino.
EDQUOT
La cuota de claves del usuario de la clave se excedería al aumentar el tamaño de la clave para acomodar la nueva carga útil o la cuota de claves del usuario del keyring se excedería al expandir el keyring de destino.
EACCES
La clave existe, pero no es escribible por el solicitante.

ENLAZADO

Esta es una función de biblioteca que se puede encontrar en libkeyutils. Al enlazar, se debe especificar -lkeyutils al enlazador.
