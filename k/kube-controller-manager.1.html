NOMBRE

kube-controller-manager -

SINOPSIS

kube-controller-manager [OPCIONES]

DESCRIPCIÓN

El gestor de controladores de Kubernetes es un demonio que incorpora los bucles de control principales que se envían con Kubernetes. En aplicaciones de robótica y automatización, un bucle de control es un bucle que no termina y que regula el estado del sistema. En Kubernetes, un controlador es un bucle de control que observa el estado compartido del clúster a través del servidor de API y realiza cambios intentando mover el estado actual hacia el estado deseado. Ejemplos de controladores que se envían con Kubernetes hoy en día son el controlador de replicación, el controlador de endpoints, el controlador de namespaces y el controlador de serviceaccounts.

OPCIONES

--allocate-node-cidrs=false ¿Se deben asignar CIDRs para Pods y establecerlos en el proveedor de nube? Requiere --cluster-cidr.

--allow-metric-labels=[] El mapa de métrica-etiqueta a lista blanca de valores para esta etiqueta. El formato de la clave es ,. El formato del valor es ,...por ejemplo, métrica1,etiqueta1='v1,v2,v3', métrica1,etiqueta2='v1,v2,v3' métrica2,etiqueta1='v1,v2,v3'.

--allow-metric-labels-manifest="" La ruta al archivo de manifiesto que contiene el mapeo de lista blanca. El formato del archivo es el mismo que el de la opción --allow-metric-labels. Tenga en cuenta que la opción --allow-metric-labels anulará el archivo de manifiesto.

--allow-untagged-cloud=false Permitir que el clúster se ejecute sin el cluster-id en instancias en la nube. Este es un modo de operación heredado y se requerirá un cluster-id en el futuro.

--attach-detach-reconcile-sync-period=1m0s El tiempo de espera de sincronización del reconciliador entre la adjunción y desadjunción de volúmenes. Esta duración debe ser mayor que un segundo, y aumentar este valor desde el predeterminado puede permitir que los volúmenes no coincidan con los pods.

--authentication-kubeconfig="" Archivo kubeconfig que apunta al servidor 'core' de kubernetes con suficientes derechos para crear tokenreviews.authentication.k8s.io. Esto es opcional. Si está vacío, todas las solicitudes de token se consideran anónimas y no se busca ninguna CA de cliente en el clúster.

--authentication-skip-lookup=false Si es falso, se utilizará el kubeconfig de autenticación para buscar la configuración de autenticación faltante del clúster.

--authentication-token-webhook-cache-ttl=10s La duración para almacenar en caché las respuestas del autenticador de tokens webhook.

--authentication-tolerate-lookup-failure=false Si es verdadero, los fallos al buscar la configuración de autenticación faltante del clúster no se considerarán fatales. Tenga en cuenta que esto puede resultar en una autenticación que trata todas las solicitudes como anónimas.

--authorization-always-allow-paths=[/healthz,/readyz,/livez] Una lista de rutas HTTP para omitir durante la autorización, es decir, estas están autorizadas sin contactar al servidor 'core' de kubernetes.

--authorization-kubeconfig="" Archivo kubeconfig que apunta al servidor 'core' de kubernetes con suficientes derechos para crear subjectaccessreviews.authorization.k8s.io. Esto es opcional. Si está vacío, todas las solicitudes que no se omiten por autorización están prohibidas.

--authorization-webhook-cache-authorized-ttl=10s La duración para almacenar en caché las respuestas 'autorizadas' del autorizador webhook.

--authorization-webhook-cache-unauthorized-ttl=10s La duración para almacenar en caché las respuestas 'no autorizadas' del autorizador webhook.

--cidr-allocator-type="RangeAllocator" Tipo de asignador de CIDR a utilizar

OPTIONS

--ring-endpointslice-updates-batch-period=0s El período de agrupación de las actualizaciones de EndpointSlice para el controlador de duplicación de endpointslice. El procesamiento de los cambios de EndpointSlice se retrasará por esta duración para unirlos con posibles actualizaciones futuras y reducir el número total de actualizaciones de EndpointSlice. Un número mayor = mayor latencia de programación de puntos finales, pero menor número de revisiones de puntos finales generadas.

--mirroring-max-endpoints-per-subset=1000 El número máximo de puntos finales que se añadirán a un EndpointSlice por el controlador de duplicación de endpointslice. Más puntos finales por slice resultarán en menos slices de puntos finales, pero mayores recursos. El valor predeterminado es 100.

--namespace-sync-period=5m0s El período para sincronizar las actualizaciones del ciclo de vida del espacio de nombres.

--node-cidr-mask-size=0 Tamaño de máscara para el CIDR de nodo en el clúster. El valor predeterminado es 24 para IPv4 y 64 para IPv6.

--node-cidr-mask-size-ipv4=0 Tamaño de máscara para el CIDR de nodo IPv4 en un clúster de doble pila. El valor predeterminado es 24.

--node-cidr-mask-size-ipv6=0 Tamaño de máscara para el CIDR de nodo IPv6 en un clúster de doble pila. El valor predeterminado es 64.

--node-eviction-rate=0.1 Número de nodos por segundo en los que se eliminan los pods en caso de fallo de nodo cuando una zona está sana (ver --unhealthy-zone-threshold para la definición de sano/no sano). Zona se refiere a todo el clúster en clústeres no multizona.

--node-monitor-grace-period=50s Tiempo que permitimos que un nodo en ejecución no responda antes de marcarlo como no sano. Debe ser N veces el kubelet's nodeStatusUpdateFrequency, donde N es el número de reintentos permitidos para que el kubelet publique el estado del nodo. Este valor también debe ser mayor que la suma de HTTP2_PING_TIMEOUT_SECONDS y HTTP2_READ_IDLE_TIMEOUT_SECONDS.

--node-monitor-period=5s El período para sincronizar NodeStatus en el controlador de ciclo de vida del nodo en la nube.

--node-startup-grace-period=1m0s Tiempo que permitimos que un nodo en inicio no responda antes de marcarlo como no sano.

--node-sync-period=0s Esta bandera está obsoleta y se eliminará en futuras versiones. Consulte node-monitor-period para la comprobación del estado del nodo o route-reconciliation-period para la configuración de rutas del proveedor de nube.

--permit-address-sharing=false Si es verdadero, se usará SO_REUSEADDR al enlazar el puerto. Esto permite enlazar a IPs comodín como 0.0.0.0 e IPs específicas en paralelo, y evita esperar a que el kernel libere los sockets en estado TIME_WAIT. [predeterminado=falso]

--permit-port-sharing=false Si es verdadero, se usará SO_REUSEPORT al enlazar el puerto, lo que permite que más de una instancia se enlace a la misma dirección y puerto. [predeterminado=falso]

--profiling=true Habilita el perfilado a través de la interfaz web host:port/debug/pprof/

--pv-recycler-increment-timeout-nfs=30 El incremento de tiempo añadido por Gi a ActiveDeadlineSeconds para un pod de limpieza NFS.

--pv-recycler-minimum-timeout-hostpath=60 El ActiveDeadlineSeconds mínimo a utilizar para un pod de limpieza HostPath. Esto es solo para desarrollo y pruebas y no funcionará en un clúster multinodo.

--pv-recycler-minimum-timeout-nfs=300 El ActiveDeadlineSeconds mínimo a utilizar para un pod de limpieza NFS.

--pv-recycler-pod-template-filepath-hostpath="" La ruta del archivo a una definición de pod utilizada como plantilla para la limpieza de volúmenes persistentes HostPath. Esto es solo para desarrollo y pruebas y no funcionará en un clúster multinodo.

--pv-recycler-pod-template-filepath-nfs="" La ruta del archivo a una definición de pod utilizada como plantilla para la limpieza de volúmenes persistentes NFS.

--pv-recycler-timeout-increment-hostpath=30 El incremento de tiempo añadido por Gi a ActiveDeadlineSeconds para un pod de limpieza HostPath. Esto es solo para desarrollo y pruebas y no funcionará en un clúster multinodo.

--pvclaimbinder-sync-period=15s El período para sincronizar volúmenes persistentes y reclamos de volumen persistentes.

--requestheader-allowed-names=[] Lista de nombres comunes de certificados de cliente permitidos para proporcionar nombres de usuario en las cabeceras especificadas por --requestheader-username-headers. Si está vacío, se permite cualquier certificado de cliente validado por las autoridades en --requestheader-client-ca-file.

--requestheader-client-ca-file="" Paquete de certificados raíz para usar para verificar los certificados de cliente en las solicitudes entrantes antes de confiar en los nombres de usuario en las cabeceras especificadas por --requestheader-username-headers. ADVERTENCIA: generalmente no dependa de que la autorización ya se haya realizado para las solicitudes entrantes.

--requestheader-extra-headers-prefix=[x-remote-extra-] Lista de prefijos de cabecera de solicitud a inspeccionar. Se sugiere X-Remote-Extra-.

--requestheader-group-headers=[x-remote-group] Lista de cabeceras de solicitud a inspeccionar para grupos. Se sugiere X-Remote-Group.

--requestheader-uid-headers=[] Lista de cabeceras de solicitud a inspeccionar para UID. Se sugiere X-Remote-Uid. Requiere que la característica RemoteRequestHeaderUID esté habilitada.

--requestheader-username-headers=[x-remote-user] Lista de cabeceras de solicitud a inspeccionar para nombres de usuario. X-Remote-User es común.

--resource-quota-sync-period=5m0s El período para sincronizar el estado de uso de cuotas en el sistema.

--root-ca-file="" Si se establece, esta autoridad de certificado raíz se incluirá en el secreto del token de la cuenta de servicio. Debe ser un paquete CA válido codificado en PEM.

--route-reconciliation-period=10s El período para reconciliar las rutas creadas para los Nodos por el proveedor de nube.

--secondary-node-eviction-rate=0.01 Número de nodos por segundo en los que se eliminan los pods en caso de fallo de nodo cuando una zona no está sana (ver --unhealthy-zone-threshold para la definición de sano/no sano). Zona se refiere a todo el clúster en clústeres no multizona. Este valor se sobrescribe implícitamente a 0 si el tamaño del clúster es menor que --large-cluster-size-threshold.

--secure-port=10257 El puerto en el que servir HTTPS con autenticación y autorización. Si es 0, no servir HTTPS en absoluto.

--service-account-private-key-file="" Habilita los tokens heredados basados en secretos cuando se establece. Nombre de archivo que contiene una clave RSA o ECDSA privada codificada en PEM utilizada para firmar tokens de cuentas de servicio.

--service-cluster-ip-range="" Rango CIDR para Servicios en el clúster. Solo se usa cuando --allocate-node-cidrs=true; si es falso, esta opción se ignorará.

--show-hidden-metrics-for-version="" La versión anterior para la que desea mostrar métricas ocultas. Solo la versión menor anterior es significativa, otros valores no serán permitidos. El formato es ., por ejemplo: '1.16'. El propósito de este formato es asegurarse de que tenga la oportunidad de notar si la próxima versión oculta métricas adicionales, en lugar de ser sorprendido cuando se eliminan permanentemente en la versión posterior a esa.

--terminated-pod-gc-threshold=12500 Número de pods terminados que pueden existir antes de que el recolector de basura de pods terminados comience a eliminar pods terminados. Si es <= 0, el recolector de basura de pods terminados está deshabilitado.

--tls-cert-file="" Archivo que contiene el Certificado x509 predeterminado para HTTPS. (Certificado CA, si lo hay, concatenado después del certificado del servidor). Si el servicio HTTPS está habilitado y --tls-cert-file y --tls-private-key-file no se proporcionan, se genera un certificado y clave autofirmados para la dirección pública y se guardan en el directorio especificado por --cert-dir.

--tls-cipher-suites=[] Lista separada por comas de suites de cifrado para el servidor. Si se omite, se utilizarán las suites de cifrado predeterminadas de Go. Valores preferidos: TLS_AES_128_GCM_SHA256, TLS_AES_256_GCM_SHA384, TLS_CHACHA20_POLY1305_SHA256, TLS_ECDHE_ECDSA_WITH_AES_128_CBC_SHA, TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256, TLS_ECDHE_ECDSA_WITH_AES_256_CBC_SHA, TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384, TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305, TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256, TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256, TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384, TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305, TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256. Valores inseguros: TLS_ECDHE_ECDSA_WITH_AES_128_CBC_SHA256, TLS_ECDHE_ECDSA_WITH_RC4_128_SHA, TLS_ECDHE_RSA_WITH_3DES_EDE_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA256, TLS_ECDHE_RSA_WITH_RC4_128_SHA, TLS_RSA_WITH_3DES_EDE_CBC_SHA, TLS_RSA_WITH_AES_128_CBC_SHA, TLS_RSA_WITH_AES_128_CBC_SHA256, TLS_RSA_WITH_AES_128_GCM_SHA256, TLS_RSA_WITH_AES_256_CBC_SHA, TLS_RSA_WITH_AES_256_GCM_SHA384, TLS_RSA_WITH_RC4_128_SHA.

--tls-min-version="" Versión mínima de TLS soportada. Valores posibles: VersionTLS10, VersionTLS11, VersionTLS12, VersionTLS13

--tls-private-key-file="" Archivo que contiene la clave privada x509 predeterminada que coincide con --tls-cert-file.

--tls-sni-cert-key=[] Un par de certificado x509 y ruta de archivo de clave privada, opcionalmente con sufijo de una lista de patrones de dominio que son nombres de dominio completamente calificados, posiblemente con segmentos comodín prefijados. Los patrones de dominio también permiten direcciones IP, pero las IPs solo deben usarse si el apiserver tiene visibilidad de la dirección IP solicitada por un cliente. Si no se proporcionan patrones de dominio, se extraen los nombres del certificado. Las coincidencias no comodín prevalecen sobre las coincidencias comodín, los patrones de dominio explícitos prevalecen sobre los nombres extraídos. Para múltiples pares de clave/certificado, use --tls-sni-cert-key varias veces. Ejemplos: "example.crt,example.key" o "foo.crt,foo.key:*.foo.com,foo.com".

--unhealthy-zone-threshold=0.55 Fracción de Nodos en una zona que debe no estar en estado Ready (mínimo 3) para que la zona sea tratada como no sana.

--use-service-account-credentials=false Si es verdadero, usa credenciales de cuenta de servicio individuales para cada controlador.

-v, --v=0 número para la verbosidad del nivel de registro.

--version=false --version, --version=raw imprime la información de versión y sale; --version=vX.Y.Z... establece la versión informada.
