NOMBRE

kubeadm init - Ejecuta este comando para configurar el plano de control de Kubernetes

SINOPSIS

kubeadm init [OPCIONES]

DESCRIPCIÓN

Ejecuta este comando para configurar el plano de control de Kubernetes

El comando "init" ejecuta las siguientes fases:

preflight                     Ejecuta comprobaciones previas
certs                         Generación de certificados
  /ca                           Genera la CA autofirmada de Kubernetes para aprovisionar identidades para otros componentes de Kubernetes
  /apiserver                    Genera el certificado para servir la API de Kubernetes
  /apiserver-kubelet-client     Genera el certificado para que el servidor de API se conecte a kubelet
  /front-proxy-ca               Genera la CA autofirmada para aprovisionar identidades para el proxy frontal
  /front-proxy-client           Genera el certificado para el cliente del proxy frontal
  /etcd-ca                      Genera la CA autofirmada para aprovisionar identidades para etcd
  /etcd-server                  Genera el certificado para servir etcd
  /etcd-peer                    Genera el certificado para que los nodos etcd se comuniquen entre sí
  /etcd-healthcheck-client      Genera el certificado para que las comprobaciones de vivacidad (liveness probes) verifiquen etcd
  /apiserver-etcd-client        Genera el certificado que el servidor de API utiliza para acceder a etcd
  /sa                           Genera una clave privada para firmar tokens de cuenta de servicio junto con su clave pública
kubeconfig                    Genera todos los archivos kubeconfig necesarios para establecer el plano de control y el archivo kubeconfig de administrador
  /admin                        Genera un archivo kubeconfig para que lo use el administrador y para el propio kubeadm
  /super-admin                  Genera un archivo kubeconfig para el superadministrador
  /kubelet                      Genera un archivo kubeconfig para que lo use el kubelet *solo* con fines de arranque del clúster
  /controller-manager           Genera un archivo kubeconfig para que lo use el controlador de gestor
  /scheduler                    Genera un archivo kubeconfig para que lo use el planificador
etcd                          Genera el archivo de manifiesto de Pod estático para etcd local
  /local                        Genera el archivo de manifiesto de Pod estático para una instancia etcd local de un solo nodo
control-plane                 Genera todos los archivos de manifiesto de Pod estáticos necesarios para establecer el plano de control
  /apiserver                    Genera el manifiesto de Pod estático del servidor de API
  /controller-manager           Genera el manifiesto de Pod estático del controlador de gestor
  /scheduler                    Genera el manifiesto de Pod estático del planificador
kubelet-start                 Escribe la configuración de kubelet y (re)inicia kubelet
wait-control-plane            Espera a que se inicie el plano de control
upload-config                 Sube la configuración de kubeadm y kubelet a un ConfigMap
  /kubeadm                      Sube la configuración del clúster de kubeadm a un ConfigMap
  /kubelet                      Sube la configuración del componente kubelet a un ConfigMap
upload-certs                  Sube los certificados al secreto de certificados de kubeadm (kubeadm-certs)
mark-control-plane            Marca un nodo como plano de control
bootstrap-token               Genera tokens de arranque utilizados para unir un nodo a un clúster
kubelet-finalize              Actualiza la configuración relevante para kubelet después del arranque TLS
  /enable-client-cert-rotation  Habilita la rotación del certificado del cliente de kubelet
addon                         Instala los complementos necesarios para pasar las pruebas de conformidad
  /coredns                      Instala el complemento CoreDNS en un clúster de Kubernetes
  /kube-proxy                   Instala el complemento kube-proxy en un clúster de Kubernetes
show-join-command             Muestra el comando de unión para el nodo de plano de control y los nodos trabajadores

OPCIONES

--apiserver-advertise-address="" La dirección IP que el Servidor de API anunciará que está escuchando. Si no se establece, se utilizará la interfaz de red predeterminada.

--apiserver-bind-port=6443 Puerto al que se enlazará el Servidor de API.

--apiserver-cert-extra-sans=[] Nombres alternativos de sujeto (SANs) adicionales opcionales para usar en el certificado de servicio del Servidor de API. Pueden ser tanto direcciones IP como nombres DNS.

--cert-dir="/etc/kubernetes/pki" La ruta donde se guardarán y almacenarán los certificados.

--certificate-key="" Clave utilizada para cifrar los certificados del plano de control en el secreto de certificados de kubeadm (kubeadm-certs). La clave del certificado es una cadena codificada en hexadecimal que es una clave AES de 32 bytes.

--config="" Ruta a un archivo de configuración de kubeadm.

--control-plane-endpoint="" Especifica una dirección IP o nombre DNS estable para el plano de control.

--cri-socket="" Ruta al socket CRI para conectarse. Si está vacío, kubeadm intentará detectar este valor automáticamente; usa esta opción solo si tienes más de un CRI instalado o si tienes un socket CRI no estándar.

--dry-run=false No aplicar ningún cambio; solo muestra lo que se haría.

--feature-gates="" Un conjunto de pares clave=valor que describen las puertas de características para varias funcionalidades. Las opciones son: ControlPlaneKubeletLocalMode=true|false (BETA - predeterminado=true) NodeLocalCRISocket=true|false (BETA - predeterminado=true) PublicKeysECDSA=true|false (OBSOLETO - predeterminado=false) RootlessControlPlane=true|false (ALFA - predeterminado=false) WaitForAllControlPlaneComponents=true|false (predeterminado=true)

--ignore-preflight-errors=[] Una lista de comprobaciones cuyos errores se mostrarán como advertencias. Ejemplo: 'IsPrivilegedUser,Swap'. El valor 'all' ignora los errores de todas las comprobaciones.

--image-repository="registry.k8s.io" Elige un registro de contenedores para descargar las imágenes del plano de control.

--kubernetes-version="stable-1" Elige una versión específica de Kubernetes para el plano de control.

--node-name="" Especifica el nombre del nodo.

--patches="" Ruta a un directorio que contiene archivos con el nombre "target[suffix][+patchtype].extension". Por ejemplo, "kube-apiserver0+merge.yaml" o simplemente "etcd.json". "target" puede ser uno de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" puede ser uno de "strategic", "merge" o "json" y coinciden con los formatos de parche admitidos por kubectl. El "patchtype" predeterminado es "strategic". "extension" debe ser "json" o "yaml". "suffix" es una cadena opcional que se puede usar para determinar qué parches se aplican primero alfanuméricamente.

--pod-network-cidr="" Especifica el rango de direcciones IP para la red de pods. Si se establece, el plano de control asignará automáticamente CIDRs para cada nodo.

--service-cidr="10.96.0.0/12" Utiliza un rango alternativo de direcciones IP para las VIP de servicios.

--service-dns-domain="cluster.local" Utiliza un dominio alternativo para los servicios, por ejemplo, "myorg.internal".

--skip-certificate-key-print=false No imprime la clave utilizada para cifrar los certificados del plano de control.

--skip-phases=[] Lista de fases a omitir

--skip-token-print=false Omite la impresión del token de arranque predeterminado generado por 'kubeadm init'.

--token="" El token a utilizar para establecer la confianza bidireccional entre los nodos y los nodos del plano de control. El formato es [a-z0-9]{6}.[a-z0-9]{16} - por ejemplo, abcdef.0123456789abcdef

--token-ttl=24h0m0s La duración antes de que el token sea eliminado automáticamente (por ejemplo, 1s, 2m, 3h). Si se establece en '0', el token nunca caducará.

--upload-certs=false Sube los certificados del plano de control al secreto de certificados de kubeadm (kubeadm-certs).

OPCIONES HEREDADAS DE COMANDOS PADRE

--rootfs="" La ruta al sistema de archivos raíz 'real' del host. Esto hará que kubeadm realice un chroot en la ruta proporcionada.

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión informada

NAME

kubeadm-init - initialize a Kubernetes cluster

SYNOPSIS

kubeadm init [command]

DESCRIPTION

This is a placeholder for the actual description of the kubeadm-init command. It is used to initialize a new Kubernetes cluster. This command performs the necessary steps to set up a control plane for a Kubernetes cluster. It generates all the necessary configuration files, certificates, and starts the control plane components like etcd, kube-apiserver, kube-scheduler, and kube-controller-manager.

Key features of `kubeadm init` include:

  • Initializing the control plane on a machine.
  • Generating necessary cryptographic material (certificates and keys).
  • Creating static Pod manifests for control plane components.
  • Configuring Kubernetes networking (CNI).
  • Generating a kubeconfig file for administrative access.

The command can be used with various subcommands and flags to customize the initialization process. For example, specifying a Pod network CIDR, a control plane endpoint, or using a specific configuration file.

After running `kubeadm init`, you will typically need to join other nodes to the cluster using the `kubeadm join` command provided in the output.

OPTIONS

This section is a placeholder. The `kubeadm init` command has numerous options to customize the cluster initialization. Some common options include:

  • `--pod-network-cidr`: Specifies the CIDR for Pod networking. This is crucial for enabling communication between Pods.
  • `--control-plane-endpoint`: Specifies the address for the control plane, which can be an IP address or a DNS name.
  • `--kubernetes-version`: Specifies the version of Kubernetes to install.
  • `--config`: Path to a configuration file that provides more detailed initialization settings.
  • `--skip-phases`: Allows skipping specific phases of the initialization process.

Refer to the official Kubernetes documentation or run `kubeadm init --help` for a comprehensive list of options and their descriptions.

OPTIONS INHERITED FROM PARENT COMMANDS

This section is a placeholder. `kubeadm init` is a top-level command and does not inherit options from parent commands in the typical sense. However, it can be part of a larger workflow where configuration flags might be passed down or set via environment variables.

SEE ALSO

The following commands are related to `kubeadm init`:

  • `kubeadm join(1)`: Joins a node to an existing cluster.
  • `kubeadm reset(1)`: Resets a node to its default state.
  • `kubeadm config(1)`: Commands for managing kubeadm configuration.
  • `kubectl(1)`: The Kubernetes command-line tool for interacting with clusters.

HISTORY

The `kubeadm init` command has been a core part of the Kubernetes cluster bootstrapping process for a long time. Its functionality and options have evolved with each Kubernetes release. It is designed to simplify the initial setup of a Kubernetes control plane, making it easier for users to get started with Kubernetes.
