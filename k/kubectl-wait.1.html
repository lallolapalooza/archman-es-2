NOMBRE

kubectl wait - Experimental: Espera una condición específica en uno o varios recursos

SINOPSIS

kubectl wait [OPCIONES]

DESCRIPCIÓN

Experimental: Espera una condición específica en uno o varios recursos.

El comando toma múltiples recursos y espera hasta que la condición especificada se vea en el campo Status de cada recurso dado.

Alternativamente, el comando puede esperar a que el conjunto dado de recursos sea creado o eliminado proporcionando la palabra clave "create" o "delete" como valor para el flag --for.

Se imprimirá un mensaje de éxito en stdout indicando cuándo se ha cumplido la condición especificada. Puedes usar la opción -o para cambiar el destino de la salida.

OPCIONES

--all=false Selecciona todos los recursos en el namespace de los tipos de recursos especificados

-A, --all-namespaces=false Si está presente, lista los objetos solicitados en todos los namespaces. El namespace en el contexto actual se ignora incluso si se especifica con --namespace.

--allow-missing-template-keys=true Si es true, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--field-selector="" Selector (consulta de campo) para filtrar, soporta '=', '==', y '!='. (ej. --field-selector key1=value1,key2=value2). El servidor solo soporta un número limitado de consultas de campo por tipo.

-f, --filename=[] Identifica el recurso.

--for="" La condición a esperar: [create|delete|condition=nombre-condicion[=valor-condicion]|jsonpath='{expresión JSONPath}'=[valor JSONPath]]. El valor-condicion por defecto es true. Los valores de condición se comparan después de la plegado de mayúsculas y minúsculas simple de Unicode, que es una forma más general de insensibilidad a mayúsculas y minúsculas.

--local=false Si es true, la anotación NO contactará con el api-server sino que se ejecutará localmente.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

-R, --recursive=true Procesa el directorio usado en -f, --filename recursivamente. Útil cuando quieres gestionar manifiestos relacionados organizados dentro del mismo directorio.

-l, --selector="" Selector (consulta de etiqueta) para filtrar, soporta '=', '==', y '!='. (ej. -l key1=value1,key2=value2)

--show-managed-fields=false Si es true, conserva los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a archivo de plantilla a usar cuando -o=go-template, -o=go-template-file. El formato de plantilla es plantillas golang [http://golang.org/pkg/text/template/#pkg-overview].

--timeout=30s El tiempo a esperar antes de rendirse. Cero significa comprobar una vez y no esperar, negativo significa esperar una semana.

EJEMPLO

  # Espera a que el pod "busybox1" contenga la condición de estado de tipo "Ready"
  kubectl wait --for=condition=Ready pod/busybox1
  # El valor por defecto de la condición de estado es true; puedes esperar por otros objetivos después de un delimitador igual (comparado después del plegado de mayúsculas y minúsculas simple de Unicode, que es una forma más general de insensibilidad a mayúsculas y minúsculas)
  kubectl wait --for=condition=Ready=false pod/busybox1
  # Espera a que el pod "busybox1" contenga la fase de estado como "Running"
  kubectl wait --for=jsonpath='{.status.phase}'=Running pod/busybox1
  # Espera a que el pod "busybox1" esté "Ready"
  kubectl wait --for='jsonpath={.status.conditions[?(@.type=="Ready")].status}=True' pod/busybox1
  # Espera a que el servicio "loadbalancer" tenga ingress
  kubectl wait --for=jsonpath='{.status.loadBalancer.ingress}' service/loadbalancer
  # Espera a que el secreto "busybox1" sea creado, con un tiempo de espera de 30s
  kubectl create secret generic busybox1
  kubectl wait --for=create secret/busybox1 --timeout=30s
  # Espera a que el pod "busybox1" sea eliminado, con un tiempo de espera de 60s, después de haber emitido el comando "delete"
  kubectl delete pod/busybox1
  kubectl wait --for=delete pod/busybox1 --timeout=60s

kubectl-wait(1)

NOMBRE kubectl-wait - Espera a que se cumplan ciertas condiciones en uno o más recursos de Kubernetes

SINOPSIS 

kubectl wait <resource_type> [resource_name] --for=[delete|condition=string] [-n namespace] [--all]

DESCRIPCIÓN El comando `kubectl wait` se utiliza para esperar a que se cumplan ciertas condiciones en uno o más recursos de Kubernetes. Esto es útil en scripts y flujos de trabajo automatizados donde necesita asegurarse de que un recurso esté en un estado específico antes de continuar.

OPCIONES

--for=[delete|condition=string]
Especifica la condición a esperar. Puede ser `delete` para esperar a que el recurso sea eliminado, o `condition=<string>` para esperar a que una condición específica se cumpla. La cadena de condición debe tener el formato `tipo=valor`.
-n <namespace>, --namespace=<namespace>
El namespace en el que buscar el recurso.
--all
Si se especifica, el comando esperará a que todos los recursos del tipo especificado cumplan la condición.

OPCIONES HEREDADAS DE COMANDOS PADRE Este comando hereda opciones comunes de `kubectl`, como:

  • --cache-dir=""
  • --context=""
  • --kubeconfig=""
  • --log-flush-frequency=0
  • --log-dir=""
  • --log-file-max-size=0
  • --log-file=""
  • --master=""
  • --namespace=""
  • --one-output=false
  • --plugins=
  • --propagate-exceptions=false
  • --request-timeout="0"
  • --stderr-threshold=0
  • --tls-server-name=""
  • --tracing-config=""
  • --user=""

EJEMPLO 

# Esperar a que el pod 'my-pod' en el namespace 'default' sea eliminado
kubectl wait pod my-pod --for=delete

# Esperar a que todos los pods en el namespace 'development' tengan el estado 'Running'
kubectl wait pod --all --for=condition=Ready --namespace=development
