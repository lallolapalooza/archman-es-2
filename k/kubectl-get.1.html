NOMBRE

kubectl get - Mostrar uno o varios recursos

SINOPSIS

kubectl get [OPCIONES]

DESCRIPCIÓN

Muestra uno o varios recursos.

Imprime una tabla con la información más importante sobre los recursos especificados. Puedes filtrar la lista usando un selector de etiquetas y la opción --selector. Si el tipo de recurso deseado está en un namespace, solo verás resultados en el namespace actual si no especificas ninguno.

Al especificar la salida como 'template' y proporcionar una plantilla de Go como valor de la opción --template, puedes filtrar los atributos de los recursos obtenidos.

Usa "kubectl api-resources" para obtener una lista completa de los recursos compatibles.

OPCIONES

-A, --all-namespaces=false Si está presente, lista los objetos solicitados en todos los namespaces. El namespace en el contexto actual se ignora incluso si se especifica con --namespace.

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--chunk-size=500 Devuelve listas grandes en fragmentos en lugar de todas a la vez. Pasa 0 para deshabilitar. Esta opción es beta y puede cambiar en el futuro.

--field-selector="" Selector (consulta de campo) para filtrar, soporta '=', '==', y '!='. (por ejemplo, --field-selector key1=value1,key2=value2). El servidor solo soporta un número limitado de consultas de campo por tipo.

-f, --filename=[] Nombre de archivo, directorio o URL de archivos que identifican el recurso a obtener de un servidor.

--ignore-not-found=false Si se establece en verdadero, suprime el error NotFound para objetos específicos que no existen. Usar esta opción con comandos que consultan colecciones de recursos no tiene efecto cuando no se encuentran recursos.

-k, --kustomize="" Procesa el directorio de kustomization. Esta opción no se puede usar junto con -f o -R.

-L, --label-columns=[] Acepta una lista separada por comas de etiquetas que se presentarán como columnas. Los nombres distinguen entre mayúsculas y minúsculas. También puedes usar múltiples opciones de bandera como -L etiqueta1 -L etiqueta2...

--no-headers=false Al usar el formato de salida predeterminado o de columnas personalizadas, no imprime encabezados (imprime encabezados por defecto).

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file, custom-columns, custom-columns-file, wide). Ver columnas personalizadas [https://kubernetes.io/docs/reference/kubectl/#custom-columns], plantilla golang [http://golang.org/pkg/text/template/#pkg-overview] y plantilla jsonpath [https://kubernetes.io/docs/reference/kubectl/jsonpath/].

--output-watch-events=false Imprime eventos de tipo watch cuando se usa --watch o --watch-only. Los objetos existentes se imprimen como eventos INITIAL ADDED.

--raw="" URI sin procesar para solicitar al servidor. Utiliza el transporte especificado por el archivo kubeconfig.

-R, --recursive=false Procesa el directorio utilizado en -f, --filename recursivamente. Útil cuando deseas administrar manifiestos relacionados organizados dentro del mismo directorio.

-l, --selector="" Selector (consulta de etiquetas) para filtrar, soporta '=', '==', '!=', 'in', 'notin'. (por ejemplo, -l key1=value1,key2=value2,key3 in (value3)). Los objetos coincidentes deben cumplir todas las restricciones de etiquetas especificadas.

--server-print=true Si es verdadero, haz que el servidor devuelva la salida de tabla apropiada. Soporta APIs de extensión y CRDs.

--show-kind=false Si está presente, lista el tipo de recurso para los objetos solicitados.

--show-labels=false Al imprimir, muestra todas las etiquetas como la última columna (oculta la columna de etiquetas por defecto)

--show-managed-fields=false Si es verdadero, conserva los managedFields al imprimir objetos en formato JSON o YAML.

--sort-by="" Si no está vacío, ordena los tipos de lista usando esta especificación de campo. La especificación de campo se expresa como una expresión JSONPath (por ejemplo, '{.metadata.name}'). El campo en el recurso de la API especificado por esta expresión JSONPath debe ser un entero o una cadena.

--subresource="" Si se especifica, obtiene el subrecurso del objeto solicitado.

--template="" Cadena de plantilla o ruta a un archivo de plantilla a usar cuando -o=go-template, -o=go-template-file. El formato de plantilla es plantillas golang [http://golang.org/pkg/text/template/#pkg-overview].

-w, --watch=false Después de listar/obtener el objeto solicitado, observa los cambios.

--watch-only=false Observa los cambios en los objetos solicitados, sin listar/obtener primero.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario regular o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a usar

--context="" El nombre del contexto de kubeconfig a usar

--disable-compression=false Si es verdadero, desactiva la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará en cuanto a su validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a usar para las solicitudes de CLI.

--kuberc="" Ruta al archivo kuberc a usar para preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funcionalidad KUBECTL_KUBERC=false o desactivando la funcionalidad KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud de CLI

--password="" Contraseña para autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" La duración antes de rendirse en una solicitud de servidor única. Valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de espera de las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a usar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor

--token="" Token de portador para la autenticación al servidor API

--user="" El nombre del usuario de kubeconfig a usar

--username="" Nombre de usuario para autenticación básica al servidor API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión informada

--warnings-as-errors=false Tratar las advertencias recibidas del servidor como errores y salir con un código de salida distinto de cero

NAME

kubectl-get - Print the list of resources.

SYNOPSIS

kubectl get TYPE [NAME | -l selector] [options]

kubectl get TYPE/NAME [options]

kubectl get TYPE -f FILENAME [-f FILENAME]... [options]

kubectl get TYPE -k FORMAT [options]

DESCRIPTION

Get information about one or more resources. You can retrieve information about specific resources or lists of resources.

Supported resource types include:

EXAMPLE

  # List a single replication controller with specified NAME in ps output format
  kubectl get replicationcontroller web
  # List deployments in JSON output format, in the "v1" version of the "apps" API group
  kubectl get deployments.v1.apps -o json
  # List a single pod in JSON output format
  kubectl get -o json pod web-pod-13je7
  # List a pod identified by type and name specified in "pod.yaml" in JSON output format
  kubectl get -f pod.yaml -o json
  # List resources from a directory with kustomization.yaml - e.g. dir/kustomization.yaml
  kubectl get -k dir/
  # Return only the phase value of the specified pod
  kubectl get -o template pod/web-pod-13je7 --template={{.status.phase}}
  # List resource information in custom columns
  kubectl get pod test-pod -o custom-columns=CONTAINER:.spec.containers[0].name,IMAGE:.spec.containers[0].image
  # List all replication controllers and services together in ps output format
  kubectl get rc,services
  # List one or more resources by their type and names
  kubectl get rc/web service/frontend pods/web-pod-13je7
  # List the 'status' subresource for a single pod
  kubectl get pod web-pod-13je7 --subresource status
  # List all deployments in namespace 'backend'
  kubectl get deployments.apps --namespace backend
  # List all pods existing in all namespaces
  kubectl get pods --all-namespaces
