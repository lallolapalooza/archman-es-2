NOMBRE

kubectl create priorityclass - Crea una clase de prioridad con el nombre especificado

SINAPSIS

kubectl create priorityclass [OPCIONES]

DESCRIPCIÓN

Crea una clase de prioridad con el nombre, valor, globalDefault y descripción especificados.

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--description="" descripción es una cadena arbitraria que generalmente proporciona pautas sobre cuándo se debe utilizar esta clase de prioridad.

--dry-run="none" Debe ser "none", "server", o "client". Si es estrategia de cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si es estrategia de servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--field-manager="kubectl-create" Nombre del gestor utilizado para rastrear la propiedad de los campos.

--global-default=false global-default especifica si esta PriorityClass debe considerarse como la prioridad predeterminada.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--preemption-policy="PreemptLowerPriority" preemption-policy es la política para interrumpir pods con menor prioridad.

--save-config=false Si es verdadero, la configuración del objeto actual se guardará en su anotación. De lo contrario, la anotación permanecerá sin cambios. Esta bandera es útil cuando desea realizar kubectl apply en este objeto en el futuro.

--show-managed-fields=false Si es verdadero, mantén los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a un archivo de plantilla para usar cuando -o=go-template, -o=go-template-file. El formato de plantilla son plantillas de golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Debe ser uno de: strict (o true), warn, ignore (o false). "true" o "strict" usarán un esquema para validar la entrada y fallarán la solicitud si es inválida. Realizará validación del lado del servidor si ServerSideFieldValidation está habilitado en el api-server, pero recurrirá a una validación del lado del cliente menos confiable si no. "warn" advertirá sobre campos desconocidos o duplicados sin bloquear la solicitud si la validación del lado del servidor está habilitada en el API server, y se comportará como "ignore" en caso contrario. "false" o "ignore" no realizarán ninguna validación de esquema, omitiendo silenciosamente cualquier campo desconocido o duplicado.

--value=0 el valor de esta clase de prioridad.

EJEMPLO

  # Crear una clase de prioridad llamada high-priority
  kubectl create priorityclass high-priority --value=1000 --description="prioridad alta"
  # Crear una clase de prioridad llamada default-priority que se considera como la prioridad global predeterminada
  kubectl create priorityclass default-priority --value=1000 --global-default=true --description="prioridad predeterminada"
  # Crear una clase de prioridad llamada high-priority que no puede interrumpir pods con menor prioridad
  kubectl create priorityclass high-priority --value=1000 --description="prioridad alta" --preemption-policy="Never"

NAME

kubectl-create-priorityclass - Create a PriorityClass object

SYNOPSIS

kubectl create priorityclass NAME --value VALUE [--global] [options]

DESCRIPTION

Create a PriorityClass object with the specified name and value. A PriorityClass is a non-namespaced object that defines the priority of pods. Pods with higher priority values are scheduled before pods with lower priority values. If two pods have the same priority, the scheduler will use FIFO (first-in, first-out) to determine which pod is scheduled first. The value of a PriorityClass must be an integer. Higher integers represent higher priority. The value of 0 is reserved for pods with no priority. The --global flag makes the PriorityClass globally available. This means that any pod can reference it without needing to be in the same namespace. The --value flag is mandatory and specifies the priority of the PriorityClass. For example, to create a PriorityClass named 'high-priority' with a value of 1000, you would use the following command:

kubectl create priorityclass high-priority --value 1000

To make this PriorityClass globally available, you would use the --global flag:

kubectl create priorityclass high-priority --value 1000 --global

OPTIONS

--global=false:               Allow pods from all namespaces to use this PriorityClass.

OPTIONS INHERITED FROM PARENT COMMANDS

      --context string   The name of the kubeconfig context to use
  -h, --help   help for priorityclass
      --kubeconfig string   path to the kubeconfig file
  -n, --namespace string   If present, the namespace scope for this CLI request
  -q, --quiet   If true, suppresses log output
      --server string   The address and port of the Kubernetes API server
      --tls-server-name string   Server name for certificate verification
  -v, --verbose int   number for the log level verbosity

EXAMPLE

# Create a PriorityClass named "my-priority" with value 1000000
kubectl create priorityclass my-priority --value=1000000
