KCOV(1) Manual de comandos generales KCOV(1)

NOMBRE

kcov - Análisis de cobertura de código para programas compilados y scripts de Python

SINOPSIS

kcov [opciones] dir-salida archivo-entrada [args-para-ejecutable...]

kcov --merge dir-salida <ruta-a-cobertura> [ruta-a-mas-cobertura...]

DESCRIPCIÓN

Esta página del manual documenta brevemente el comando kcov. kcov es un probador de cobertura de código para binarios ELF, scripts de Python y scripts de shell. Permite recopilar información de cobertura de código de ejecutables sin directivas especiales del compilador, y produce continuamente salida de aplicaciones de larga duración.

Consulte la página de GitHub, https://github.com/SimonKagstrom/kcov, para obtener más documentación.

OPCIONES

-p, --pid=PID
Rastrea el PID en lugar de ejecutar el ejecutable (pasar el ejecutable es opcional en este caso). Bajo este modo, la recopilación de cobertura para bibliotecas compartidas no funcionará.
-l, --limits=bajo,alto
Configura los límites de cobertura baja/alta (por defecto: 25,75).
--include-path=P1[,P2...]
Lista separada por comas de rutas a incluir en el informe.
--exclude-path=P1[,P2...]
Lista separada por comas de rutas a excluir del informe.
--include-pattern=P1[,P2...]
Lista separada por comas de patrones de rutas a incluir en el informe.
--exclude-pattern=P1[,P2...]
Lista separada por comas de patrones de rutas a excluir del informe.
--exclude-line=P1[,P2...]
Lista separada por comas de patrones de líneas a excluir (marcar como no código)
--exclude-region=INICIO:FIN[,INICIO1:FIN1...]
Lista separada por comas de regiones de patrones de líneas a excluir (marcar como no código). La región comienza con INICIO y termina con FIN.
--clean
No acumular datos de múltiples ejecuciones.
--collect-only
Solo recopilar datos de cobertura, no generar salida HTML/Cobertura.
--dump-summary
Volcar un resumen breve de cobertura en stdout después de la ejecución.
--report-only
Solo generar salida HTML/Cobertura, no recopilar datos.
--merge
Fusionar el resultado de múltiples ejecuciones de kcov. En lugar de un programa para probar, las rutas de salida de ejecuciones anteriores deben darse en la línea de comandos, o a través de un comodín (*).
--coveralls-id=id
Cargar datos en coveralls.io usando el token secreto del repositorio o el ID del trabajo del servicio Travis CI id. El ID se toma como token de repositorio si tiene 32 caracteres o más.
--strip-path=ruta
Si no se establece, se eliminará la ruta común máxima.

OPCIONES POCO COMUNES

--path-strip-level=N
Número de niveles de ruta a mostrar para rutas comunes (por defecto: 2).
--skip-solibs
Omitir la recopilación de cobertura para bibliotecas compartidas (mejora el rendimiento).
--verify
Verificar que los puntos de interrupción se configuran en los límites de instrucción. Esto ralentizará enormemente la ejecución, pero puede detectar problemas donde el compilador genera datos DWARF incorrectos.
--exit-first-process
Salir cuando el primer proceso termine, es decir, respetar el comportamiento de los demonios. El comportamiento por defecto es volver a la consola cuando el último proceso termina.
--cobertura-only
Generar solo salida de cobertura en formato Cobertura, como cov.xml, en el directorio de salida. El uso previsto es para, por ejemplo, las canaletas de cobertura de vscode, donde el directorio de salida se puede apuntar a algún lugar del directorio del proyecto para obtener cobertura con mínimas gotas.
--python-parser=PARSER
Establecer el analizador de Python a usar para programas Python (el predeterminado es python). Se puede usar para ejecutar con Python 3 en sistemas donde Python 2 es el predeterminado.
--bash-parser=PARSER
Establecer el analizador de bash a usar para scripts de shell (el predeterminado es /bin/bash).
--bash-method=METODO
Usar el método de recopilación METODO para scripts bash. El método puede ser PS4, para usar la variable de entorno PS4, o DEBUG para usar la trampa DEBUG.
--bash-handle-sh-invocation
Manejar invocaciones de scripts /bin/sh usando una biblioteca cargada con LD_PRELOAD que reemplaza execve (es decir, /bin/sh se ejecuta como /bin/bash). No funciona bien en algunos sistemas, por lo que el predeterminado es no usarlo.
--bash-dont-parse-binary-dir
Kcov analiza el directorio del binario en busca de otros scripts y los añade al informe. Si no desea este comportamiento, esta opción lo desactiva.
--bash-parse-files-in-dir=P1[,P2...]
Analizar directorios en busca de scripts bash.
--bash-tracefd-closeexec
Forzar a los hijos a no ser rastreados configurando el descriptor de traza como no clonable con LD_PRELOAD. Erróneo en algunos sistemas.
--replace-src-path=P1:P2
Reemplazar la ruta del archivo fuente P1 con P2, si se encuentra.
--system-record
Realizar instrumentación completa del sistema en un sysroot, produciendo binarios parcheados que recopilan datos de cobertura. Consulte doc/full-system-instrumentation.md para obtener más información sobre la instrumentación completa del sistema.
--system-report
Producir salida de cobertura para una ejecución de cobertura completa del sistema.
--debug=nivel
Establecer el nivel de depuración, 0...31 (como máscara). El valor predeterminado es 0 para no mostrar salida de depuración.
--output-interval=MS
Establecer el intervalo de escritura de salida en milisegundos. El valor predeterminado es 5000.
--configure=CLAVE=VALOR
Configurar pares clave/valor de opciones internas. Consulte --help --uncommon-options para ver las opciones de configuración posibles.
--patchelf=CMD
Para el modo del sistema, establecer el comando patchelf (predeterminado patchelf).

EJEMPLOS

Comprueba la cobertura de ./frodo y genera salida HTML en /tmp/kcov y salida de cobertura en /tmp/kcov/frodo/cobertura.xml

kcov /tmp/kcov ./frodo

Comprueba la cobertura de ./frodo pero solo incluye archivos fuente cuyos nombres contengan la cadena src/frodo

kcov --include-pattern=src/frodo /tmp/kcov ./frodo

Igual que el anterior pero divide la recopilación y la generación de informes (quizás en dos ordenadores diferentes)

kcov --collect-only /tmp/kcov ./frodo

kcov --report-only --include-pattern=src/frodo /tmp/kcov ./frodo

SALIDA HTML

La salida HTML muestra las líneas de código fuente ejecutadas y no ejecutadas. Algunas líneas pueden corresponder a múltiples puntos de instrumentación, por ejemplo, para funciones insertadas (donde cada inserción de ellas generará una instrumentación separada

NAME

kcov - count code execution

SYNOPSIS

kcov OPTIONS ... COMMAND [ ARG ... ]

kcov OPTIONS ... --pid=PID

DESCRIPTION

kcov is a code coverage and instrumentation tool for compiled programs. It works by instrumenting the binary during the linking stage, and then counting how many times each executable code line is run.

kcov supports multiple programming languages and compilers, as long as they use standard linker mechanisms (e.g. GCC, Clang, Rustc, Go).

It supports various output formats for integration with CI/CD systems and code coverage analysis tools.

HTML OUTPUT

By default, kcov generates an HTML report of the code coverage. This report is placed in a directory named out-path/exec-filename/html.

The HTML report includes:

  • A summary page with overall coverage percentage.
  • A list of all source files with their coverage status.
  • Detailed coverage views for each source file, highlighting covered and uncovered lines.

The coverage percentage for each file is displayed as a fraction, like 1/3. This means that one out of three instrumentation points has been executed (on point).

A special output link is [merged], which shows the union of all covered programs. This can be useful for example when you have unit tests in multiple binaries which share a subset of source files.

COBERTURA OUTPUT

Kcov also outputs data in the Cobertura XML format, which allows integrating kcov output in Jenkins (see https://cobertura.github.io/cobertura/ and https://www.jenkins.io/).

The Cobertura output is placed in a file named out-path/exec-filename/cobertura.xml.

JSON OUTPUT

Kcov generates a very generic json file which includes the overall percent covered for a single command and the count of lines instrumented and covered. It also includes a summary of each source file with a percentage and line counts. This allows easy integration with GitlabCI (see https://docs.gitlab.com/ce/user/project/pipelines/settings.html).

The JSON output is placed in a file named out-path/exec-filename/coverage.json.
