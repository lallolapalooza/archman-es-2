NOMBRE

kubectl create - Crear un recurso desde un archivo o desde stdin

SINOPSIS

kubectl create [OPCIONES]

DESCRIPCIÓN

Crear un recurso desde un archivo o desde stdin.

Se aceptan formatos JSON y YAML.

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida go y jsonpath.

--dry-run="none" Debe ser "none", "server", o "client". Si la estrategia es cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si la estrategia es servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--edit=false Edita el recurso de la API antes de crearlo

--field-manager="kubectl-create" Nombre del gestor utilizado para rastrear la propiedad de los campos.

-f, --filename=[] Nombre de archivo, directorio o URL de archivos a utilizar para crear el recurso

-k, --kustomize="" Procesa el directorio kustomization. Esta bandera no se puede usar junto con -f o -R.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--raw="" URI sin procesar para enviar POST al servidor. Utiliza el transporte especificado por el archivo kubeconfig.

--record=false Registra el comando kubectl actual en la anotación del recurso. Si se establece en falso, no registra el comando. Si se establece en verdadero, registra el comando. Si no se establece, por defecto actualiza el valor de la anotación existente solo si ya existe.

-R, --recursive=false Procesa el directorio utilizado en -f, --filename recursivamente. Útil cuando desea administrar manifiestos relacionados organizados dentro del mismo directorio.

--save-config=false Si es verdadero, la configuración del objeto actual se guardará en su anotación. De lo contrario, la anotación no se modificará. Esta bandera es útil cuando desea realizar kubectl apply en este objeto en el futuro.

-l, --selector="" Selector (consulta de etiquetas) para filtrar, soporta '=', '==', '!=', 'in', 'notin'. (ej. -l clave1=valor1,clave2=valor2,clave3 in (valor3)). Los objetos coincidentes deben cumplir todas las restricciones de etiquetas especificadas.

--show-managed-fields=false Si es verdadero, conserva los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a un archivo de plantilla a utilizar cuando -o=go-template, -o=go-template-file. El formato de plantilla es plantillas de golang [http://golang.org/pkg/text/template/#pkg-overview].

--validate="strict" Debe ser uno de: strict (o true), warn, ignore (o false). "true" o "strict" utilizarán un esquema para validar la entrada y fallarán la solicitud si no es válida. Realizará validación del lado del servidor si ServerSideFieldValidation está habilitado en el api-server, pero recurrirá a una validación del lado del cliente menos confiable si no lo está. "warn" advertirá sobre campos desconocidos o duplicados sin bloquear la solicitud si la validación de campos del lado del servidor está habilitada en el servidor API, y se comportará como "ignore" de lo contrario. "false" o "ignore" no realizarán ninguna validación de esquema, descartando silenciosamente cualquier campo desconocido o duplicado.

--windows-line-endings=false Solo relevante si --edit=true. Por defecto, utiliza el final de línea nativo de su plataforma.

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario podría ser un usuario regular o una cuenta de servicio en un espacio de nombres.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad certificadora

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a utilizar

--context="" El nombre del contexto de kubeconfig a utilizar

--disable-compression=false Si es verdadero, excluye la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará en busca de validez. Esto hará que sus conexiones HTTPS sean inseguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funciones KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del espacio de nombres para esta solicitud CLI

--password="" Contraseña para la autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo en el que escribir el perfil

--request-timeout="0" El tiempo de espera antes de rendirse en una sola solicitud de servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de espera de las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor

--token="" Token Bearer para la autenticación al servidor API

--user="" El nombre de usuario de kubeconfig a utilizar

--username="" Nombre de usuario para la autenticación básica al servidor API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión reportada

--warnings-as-errors=false Tratar las advertencias recibidas del servidor como errores y salir con un código de salida distinto de cero

EJEMPLO

  # Crear un pod utilizando los datos en pod.json
  kubectl create -f ./pod.json
  # Crear un pod basado en el JSON pasado a stdin
  cat pod.json | kubectl create -f -
  # Editar los datos en registry.yaml en JSON y luego crear el recurso utilizando los datos editados
  kubectl create -f registry.yaml --edit -o json

NAME

kubectl-create - create resources from a file or stdin

SYNOPSIS

kubectl create -f FILENAME | -f -
kubectl create TYPE NAME [--dry-run=server|client|none] [options]

DESCRIPTION

Create a resource from a file or from stdin.

To see available commands and options use `kubectl create --help`.

OPTIONS

   -f, --filename=""
      Filename, directory, or URL to files identifying the resource to create.
      If the filename or - is provided, the resource will be created from the
      data in the file or stdin.
   --save-config
      If true, the configuration of a created resource will be saved in its
      annotation. This is an experimental option.
   --validate=true|false
      Either true or false. If true, call out to the apiserver to validate
      the resource before creation.
   --dry-run=server|client|none
      Run the command in dry run mode. Defaults to none.
      --dry-run=client can be used for fine grained validation of the
      resource before it is sent to the server, and allows you to see the
      object that would be sent to the server.
      --dry-run=server will tell the server to simulate the creation of the
      object, returning what the final object would look like and
      returning any validation errors, without actually persisting the
      object. The default is client.

OPTIONS INHERITED FROM PARENT COMMANDS

      --add-dir-header
        If true, adds the same header to all files in a directory.
      --allow-missing-template-keys=true
        If true, ignore any errors in templates when a field or map key is missing
      in the template. Only applies to golang and jsonpath output formats.
      --cache-dir="/home/user/.kube/cache"
        Default cache directory
      --certificate-authority=""
        Path to a cert file for the certificate authority
      --client-certificate=""
        Path to a client certificate file for TLS
      --client-key=""
        Path to a client key file for TLS
      --cluster=""
        The name of the kubeconfig cluster to use
      --context=""
        The name of the kubeconfig context to use
      --disable-compression
        Should JSON streaming is disabled for this request? This is disabled by
      default.
      --home-dir=""
        The path to the home directory of the user
      --insecure-skip-tls-verify
        If true, the server's certificate will not be checked for validity. This
      is only useful if the server has self-signed certificates. Private
      client certificates should not be used with this option.
      --kubeconfig=""
        Path to the kubeconfig file:
      --log-backtrace-at="=10,local
      interleave>=10,runtime
      interleave>=10"
        only log the full stack trace on errors value Keywords:
      "critical", "debug", "error", "fatal", "info", "panic",
      "trace", "warn".
      --log-dir=""
        If set, all logs will be written to this directory, based on the
      log file pattern.
      --log-file-max-size=0
        Define the maximum size in bytes of the log file before it's rotated.
      --log-file-max-size-age=0
        Define the maximum number of days to retain log files.
      --log-file-max-size-count=0
        Define the maximum number of log files to retain.
      --log-flush-frequency=0
        Maximum number of seconds it can take for a message to be
      flushed.
      --log-format="text"
        Set the log format. One of: text, json
      --logtostderr=false
        Log to standard error instead of files
      --match-client-version
        Require client version to match server version
      --namespace=""
        If present, the namespace scope for this CLI request
      --password-file=""
        File containing the password for basic authentication to the API server
      --request-timeout="0"
        The length of time to wait before giving up on a single server request.
      Non-zero values should contain a corresponding time unit, e.g.
      1s0ms (1 second) or 2h45m (2 hours 45 minutes).  A value of zero means
      don't timeout requests.
      --tls-server-name=""
        Return the name given to a server for common name validation in TLS
      --token=""
        Bearer token for authentication to the API server
      --user=""
        The name of the kubeconfig user to use
      --username=""
        Username for basic authentication to the API server
      --version=false
        Print the version number of kubectl and exit; see also 'kubectl version'
      --warnings-as-errors=false
        Treat warnings as errors for validation.

EXAMPLE

# Create a pod from the file pod.yaml
   kubectl create -f pod.yaml
# Create resources from stdin
   cat pod.yaml | kubectl create -f -
# Create a secret named my-secret using literal values
   kubectl create secret generic my-secret --from-literal=key1=value1 --from-literal=key2=value2
# Create a deployment named nginx-deployment using an image
   kubectl create deployment nginx-deployment --image=nginx
