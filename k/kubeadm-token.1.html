NOMBRE

kubeadm token - Gestionar tokens de arranque

SINOPSIS

kubeadm token [OPCIONES]

DESCRIPCIÓN

Este comando gestiona los tokens de arranque. Es opcional y solo se necesita para casos de uso avanzados.

En resumen, los tokens de arranque se utilizan para establecer confianza bidireccional entre un cliente y un servidor. Un token de arranque se puede utilizar cuando un cliente (por ejemplo, un nodo que está a punto de unirse al clúster) necesita confiar en el servidor con el que está hablando. En ese caso, se puede usar un token de arranque con el uso de "firma". Los tokens de arranque también pueden funcionar como una forma de permitir la autenticación de corta duración al servidor API (el token sirve como una forma para que el servidor API confíe en el cliente), por ejemplo, para realizar el arranque TLS.

¿Qué es un token de arranque exactamente?
- Es un Secret en el namespace kube-system de tipo "bootstrap.kubernetes.io/token".
- Un token de arranque debe tener el formato "[a-z0-9]{6}.[a-z0-9]{16}". La primera parte es el ID público del token,
mientras que la segunda es el Secreto del Token y debe mantenerse privado en todas las circunstancias.
- El nombre del Secret debe llamarse "bootstrap-token-(id-del-token)".

Puedes leer más sobre los tokens de arranque aquí:
https://kubernetes.io/docs/admin/bootstrap-tokens/

OPCIONES

--dry-run=false Indica si se habilita el modo de prueba o no

--kubeconfig="/etc/kubernetes/admin.conf" El archivo kubeconfig a utilizar al hablar con el clúster. Si la opción no está establecida, se puede buscar en un conjunto de ubicaciones estándar un archivo kubeconfig existente.

OPCIONES HEREDADAS DE COMANDOS PADRE

--rootfs="" La ruta al sistema de archivos raíz del host 'real'. Esto hará que kubeadm realice un chroot a la ruta proporcionada.

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión reportada
