DESCRIPCIÓ

N

keyd es un demonio de remapeo de teclas a nivel de sistema que soporta características como capas, modificadores de un solo uso y macros. En su forma más básica, puede usarse para definir una disposición de teclas personalizada que persiste a través de los límites del servidor de visualización (por ejemplo, wayland/X/tty)

.

El programa se ejecuta en primer plano, imprimiendo información de diagnóstico en los flujos de salida estándar, y está destinado a ser ejecutado como una única instancia gestionada por el sistema de

init.

NOTA

:

Debido a que keyd modifica tu dispositivo de entrada principal, es posible dejar tu máquina inutilizable con un archivo de configuración incorrecto. Si te encuentras en esta situación, la secuencia de pánico <backspace>+<escape>+<enter> f

orzará a keyd
a terminar.

CONFIGURACIÓ

N

Los archivos de configuración siguen libremente un formato de estilo INI que consiste en encabezados de la forma [section_name] seguidos de un conjunto de enlaces. Las líneas que comienzan con un signo de almohadilla se

ignoran.

Los archivos de configuración se almacenan en /etc/keyd/ y se cargan al inicializar. El comando reload se puede usar para actualizar el conjunto de trabajo de archivos de configuración (por ejemplo, sudo keyd reload)

.

Un archivo de configuración válido tiene la extensión .conf y debe comenzar con una sección [ids] que tenga una de las siguientes

formas:

<id 1 (obtenido mediante keyd monitor)>
<id 2>

La primera forma especifica una lista de ids a ser emparejados explícitamente, mientras que la segunda empareja cualquier id que no haya sido excluido

explícitamente.

Por

ejemplo: 
[ids]

Emparejará todos los teclados que no(2) tengan el id 0123:4567, mientras

[ids]

emparejará exclusivamente cualquier dispositivo que sí lo tenga. Los ids de dispositivo se pueden obtener del comando monitor (ver COMANDOS). Ten en cuenta que un id de dispositivo solo puede aparecer en un único archivo de

configuración.

Cada sección posterior del archivo corresponde a una capa (con la excepción de [global] (ver GLOBALE

S).

Los errores de configuración aparecerán en la salida del registro y se pueden acceder de la manera habitual usando el gestor de servicios de tu sistema (por ejemplo, sudo journalctl -eu keyd)

Si un id coincide con más de un tipo de dispositivo, se puede usar el prefijo k: para emparejar exclusivamente teclados y el prefijo m: para emparejar exclusivamente ratones. (Por ejemplo, m:046d:

b01d)

Nota: Todos los teclados definidos dentro de un archivo de configuración dado compartirán el mismo estado. Esto es útil para vincular dispositivos de entrada separados (por ejemplo, pedales de pie)

.

Nota 2: El comodín solo emparejará dispositivos que keyd identifique como teclados. keyd también es capaz de gestionar ratones (por ejemplo, para facilitar la limpieza de modificadores de un solo uso al hacer clic), pero sus ids deben listarse

explícitamente.

Nota 3: El soporte de ratón es actualmente experimental y está mayormente confinado a ratones tradicionales (por ejemplo, touchpads). Añadir algunos ratones a tu sección ids puede romper tu puntero. También puede ser necesario poner en lista negra explícitamente ratones que son mal identificados como teclados (por ejemplo, si encuentras que tu ratón se comporta mal)

.

Capa

s

Una capa es una colección de enlaces, cada uno de los cuales especifica el comportamiento de una tecla en particular. Múltiples capas pueden estar activas en cualquier momento dado, formando una pila de mapas de teclas que se consultan en orden de activación. La capa por defecto se llama main y es donde se deben definir los enlaces

comunes.

Por ejemplo, el siguiente fragmento de configuración define una capa llamada nav y crea un conmutador para ella en la capa ma

in: 
[main]
capslock = layer
(nav) [nav] h = left k
= up j = down l = right

Cuando se mantiene presionado capslock, la capa nav oculta la capa main, haciendo que hjkl funcione como las teclas de flecha correspondientes

.

A diferencia de la mayoría de las otras herramientas de remapeo, keyd proporciona soporte de primera clase para modificadores. El nombre de una capa puede terminar opcionalmente con un ':' seguido de un conjunto de modificadores a emular en ausencia de un mapeo explícito. Los nombres de capa pueden constar de un máximo de 64 caracteres (incluyendo todos los modificadores)

.

Estas capas funcionan bien con otros modificadores y preservan la semántica de apilamiento

existente.

Por

ejemplo: 
[main]
capslock =
layer(capslock) [ca
pslock:C] j = down

hará que capslock se comporte como control, excepto en el caso de capslock+j, que emitirá down. Esto hace que sea trivial definir modificadores personalizados que no interfieran entre

sí.

Ten en cuenta que los enlaces no se ven afectados por los modificadores de la capa en la que están definidos. Así que capslock+j producirá una pulsación de down sin modificar, mientras que shift+capslock+j producirá shift+down como se

esperaba.

Alia

s

A cada tecla se le puede asignar opcionalmente un alias. Este alias puede usarse en lugar de la tecla como un valor válido del lado izquierdo. Varias teclas pueden estar vinculadas al mismo alias, pero solo un alias puede asignarse a una tecla a la

vez.

Por ejemplo, las teclas 'leftmeta' y 'rightmeta' están vinculadas al alias meta de forma predeterminada. Por lo tanto, la asignación 'meta = a' es equivalente a las asignaciones 'leftmeta = a' y 'rightmeta =

a'.

Los alias se definen en una sección especial llamada 'aliases' donde cada línea tiene la

forma:
<key> =
<name>

donde <key> debe ser un nombre de tecla

válido.

Tenga en cuenta que <name> puede ser en sí mismo un nombre de tecla válido, en cuyo caso todas las referencias a la tecla dentro del archivo de configuración serán reemplazadas con la nueva tecla. Además, si el alias asignado es un nombre de tecla válido, el código de tecla correspondiente se asignará a la tecla de forma predeterminada. Esto hace posible redefinir teclas antes de que se apliquen las asignaciones y es particularmente útil en conjunto con el mecanismo de inclusión para tener en cuenta variaciones en el

hardware.

Por

ejemplo:

	alt = oneshot(alt)
	a = a
	s = o
	# etc..
/etc/keyd/defa

liases] leftalt = meta rightalt = meta rightmeta = alt leftmeta = alt [main] include common

Permite al usuario definir un conjunto de asignaciones universales en

/etc/keyd/common sin tener que tener en cuenta explícitamente las teclas m

MACROS

Macros are sequences of keypresses which are defined as a unit. They may be used in place of key definitions, and are expanded inline. Macros are useful for automating repetitive tasks, and for defining complex key sequences.

A macro expression is comprised of one or more of the following:

•A valid key code.
•A type 2 macro.
•A contiguous group of unicode characters.
•A group of key codes delimited by + to be depressed as a unit.
•A timeout of the form <time>ms (where <time> < 1024).

The following are all valid macro expressions:

•C-a
•macro(C-a)
•macro(leftcontrol+leftmeta) # simultaneously taps the left meta and left control keys
•A-M-x
•macro(Hello space World)
•macro(h e l l o space w o r ld) (identical to the above)
•macro(C-t 100ms google.com enter)

Splitting into smaller tokens serves as an escaping mechanism: macro(space) inserts a space but macro(s pace) writes "space". Likewise, macro(3+5) depresses the 3 and 5 keys as a unit while macro(3 + 5) writes "3+5".

Some prerequisites are needed for non-ASCII characters to work, see Unicode Support.

ACCIONES

Una tecla puede estar opcionalmente enlazada a una acción que acepta cero o más argumentos.

layer(<capa>)

Activa la capa dada durante la pulsación de la tecla.

oneshot(<capa>)

Si se pulsa, activa la capa suministrada para la duración de la siguiente pulsación de tecla.

swap(<capa>)

Intercambia la capa actualmente activa con la suministrada. Si la capa actual se activa/desactiva, se desactiva y la capa suministrada se activa/desactiva en su lugar. De lo contrario, la capa activa se desactiva y la capa suministrada permanece activa durante la pulsación de la tecla que activa el intercambio.
[ids]
*
[main]
x = swap(xlayer)
[xlayer]
s = C-s
b = S-insert

Probablemente no necesites usar esto a menos que estés tratando de hacer algo bastante complicado. Piensa detenidamente si lo que intentas lograr se puede hacer por otros medios, ya que es fácil terminar en estados de los que es imposible salir.

setlayout(<disposicion>)

Establece la disposición actual.

clear()

Borra cualquier capa activada/desactivada o de un solo uso.

toggle(<capa>)

Activa/desactiva permanentemente el estado de la capa dada.

layerm(<capa>, <macro>)

Idéntico a layer, pero ejecuta la macro suministrada antes del cambio de capa.

oneshotm(<capa>, <macro>)

Idéntico a oneshot, pero ejecuta la macro suministrada antes del cambio de capa.

swapm(<capa>, <macro>)

Idéntico a swap, pero acepta una macro para ser ejecutada inmediatamente después del cambio de capa.

togglem(<capa>, <macro>)

Equivalente a toggle, pero además ejecuta la macro suministrada antes de activar/desactivar la capa.

clearm(<macro>)

Idéntico a clear, pero ejecuta la macro suministrada antes de borrar las capas.

Sobrecarga de teclas

overload(<capa>, <accion>)

Activa la capa dada mientras se mantiene pulsada y ejecuta <accion> al pulsarla.

overloadt(<capa>, <accion>, <tiempo_de_espera>)

Idéntico a overload, pero solo activa la capa si la tecla enlazada se mantiene pulsada durante <tiempo_de_espera> milisegundos. Esto es principalmente útil para sobrecargar teclas que se pulsan comúnmente en secuencia (por ejemplo, teclas de letras).

Ten en cuenta que esto añadirá un retraso visual al escribir, ya que las teclas sobrecargadas se pondrán en cola hasta que expire el tiempo de espera o se suelte la tecla enlazada.

overloadt2(<capa>, <accion>, <tiempo_de_espera>)

Idéntico a overloadt, pero además se resuelve como una pulsación larga en caso de una pulsación de tecla intermedia.

overloadi(<accion 1>, <accion 2>, <tiempo_de_espera_inactivo>)

Activa <accion 1> si la última tecla no de acción (es decir, símbolo) se pulsó hace menos de <tiempo_de_espera> milisegundos, de lo contrario activa <accion 2>.

Esto se puede usar en combinación con otros tiempos de espera de sobrecarga y es particularmente útil para sobrecargar teclas de letras (a menudo llamadas 'modificadores de fila principal').

Por ejemplo:

a = overloadi(a, overloadt2(control, a, 200), 150)
producirá a si y solo si:
•a se pulsa dentro de los 150ms de otra tecla no de acción.
•a se pulsa más de 150ms después de la última tecla no de acción pero se mantiene pulsada durante menos de 200ms y no hay pulsaciones de tecla intermedias.

Esto reduce la latencia visual resolviendo inmediatamente la tecla como una letra cuando se escribe a mitad de palabra, pero también facilita su uso como disparador de capa si se mantiene pulsada durante un tiempo suficiente sin símbolos intermedios.

Dado que este es un caso de uso común, se ha definido una macro llamada lettermod (definida a continuación) para facilitar tales definiciones.

lettermod(<capa>, <tecla>, <tiempo_espera_inactivo>, <tiempo_espera_pulsacion>)

Un alias para:
overloadi(<tecla>, overloadt2(<capa>, <tecla>, <tiempo_espera_pulsacion>), <tiempo_espera_inactivo>)

timeout(<accion 1>, <tiempo_de_espera>, <accion 2>)

Si la tecla se mantiene pulsada de forma aislada durante más de <tiempo_de_espera> ms, se activa la segunda acción; si la tecla se mantiene pulsada durante menos de <tiempo_de_espera> ms o se pulsa otra tecla antes de que expiren <tiempo_de_espera> ms, se ejecuta la primera acción.

Ejemplo:

timeout(a, 500, layer(control))

Hará que la tecla asignada se comporte como control si se mantiene pulsada durante más de 500 ms.

macro2(<tiempo_de_espera>, <tiempo_de_espera_repeticion>, <macro>)

Crea una macro con el tiempo de espera y el tiempo de espera de repetición dados. Si se usa un valor de tiempo de espera de 0, la repetición de la macro se deshabilita.

Ten en cuenta que <macro> debe ser una expresión de macro válida.

Ejemplo:

macro2(400, 50, macro(Hello space World))
macro2(120, 80, left)
command(<comando_shell>)
Ejecuta el comando de shell dado.

Ejemplo:

command(brightness down)

NOTA: Los comandos son ejecutados por el usuario que ejecuta el proceso keyd (probablemente root), usa esta característica con prudencia.

noop

No hacer nada.

IPC

Para facilitar la extensibilidad, keyd emplea un modelo cliente-servidor accesible mediante el uso de -e. El mapa de teclas puede concebirse así como una entidad viva que puede modificarse en tiempo de ejecución.

Además de permitir al usuario probar nuevas asignaciones sobre la marcha, esto permite al usuario aprovechar al máximo el poder expresivo de keyd desde otros programas sin incurrir en una penalización de rendimiento.

Por ejemplo, el usuario puede usar esta funcionalidad para escribir un script que altere el mapa de teclas cuando cambie entre diferentes sesiones de tmux.

La herramienta de reasignación de aplicaciones (keyd-application-mapper(1)) que se incluye con keyd es un buen ejemplo de esto. Es un pequeño script de python que realiza la detección de eventos para los diversos servidores de pantalla (por ejemplo, X/sway/gnome, etc.) y alimenta las asignaciones deseadas al núcleo usando -e.

NOTA: Los usuarios con acceso al socket de keyd deben ser considerados privilegiados (es decir, se asume que tienen acceso a todo el sistema).

Asignaciones

El comando bind acepta una o más asignaciones, cada una de las cuales debe tener el siguiente formato:

[<capa>.]<tecla> = <tecla>|<macro>|<accion>

Donde <capa> es el nombre de una capa (existente) en la que se enlazará la tecla.

Como caso especial, la cadena "reset" puede usarse en lugar de una asignación, en cuyo caso el mapa de teclas actual volverá a su estado original (se descartarán todas las asignaciones aplicadas dinámicamente).

Ejemplos:

$ keyd bind '- = C-c'
$ keyd bind reset '+ = C-c' # Restablece el teclado antes de aplicar la asignación '+' (descarta la asignación '-' anterior)

Por defecto, las expresiones se aplican al teclado activo más reciente.
