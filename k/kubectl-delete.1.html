NOMBRE

kubectl delete - Eliminar recursos por nombres de archivo, stdin, recursos y nombres, o por recursos y selector de etiquetas

SINOPSIS

kubectl delete [OPCIONES]

DESCRIPCIÓN

Eliminar recursos por nombres de archivo, stdin, recursos y nombres, o por recursos y selector de etiquetas.

Se aceptan formatos JSON y YAML. Solo se puede especificar un tipo de argumento: nombres de archivo, recursos y nombres, o recursos y selector de etiquetas.

Algunos recursos, como los pods, admiten la eliminación gradual. Estos recursos definen un período predeterminado antes de que se terminen de forma forzada (el período de gracia), pero puede anular ese valor con la opción --grace-period, o pasar --now para establecer un período de gracia de 1. Dado que estos recursos a menudo representan entidades en el clúster, la eliminación puede no ser reconocida inmediatamente. Si el nodo que aloja un pod está caído o no puede acceder al servidor de la API, la terminación puede tardar significativamente más que el período de gracia. Para forzar la eliminación de un recurso, debe especificar la opción --force. Nota: solo un subconjunto de recursos admite la eliminación gradual. En ausencia de soporte, la opción --grace-period se ignora.

IMPORTANTE: Forzar la eliminación de pods no espera confirmación de que los procesos del pod se han terminado, lo que puede dejar esos procesos en ejecución hasta que el nodo detecte la eliminación y complete la eliminación gradual. Si sus procesos usan almacenamiento compartido o se comunican con una API remota y dependen del nombre del pod para identificarse, forzar la eliminación de esos pods puede resultar en múltiples procesos en ejecución en diferentes máquinas que usan la misma identificación, lo que puede llevar a corrupción o inconsistencia de datos. Solo fuerce la eliminación de pods cuando esté seguro de que el pod se ha terminado, o si su aplicación puede tolerar múltiples copias del mismo pod en ejecución al mismo tiempo. Además, si fuerza la eliminación de pods, el planificador puede colocar nuevos pods en esos nodos antes de que el nodo haya liberado esos recursos, lo que provoca que esos pods sean desalojados inmediatamente.

Tenga en cuenta que el comando delete NO realiza verificaciones de versión de recurso, por lo que si alguien envía una actualización a un recurso justo cuando usted envía una eliminación, su actualización se perderá junto con el resto del recurso.

Después de eliminar una CustomResourceDefinition, la invalidación de la caché de descubrimiento puede tardar hasta 6 horas. Si no desea esperar, puede ejecutar "kubectl api-resources" para actualizar la caché de descubrimiento.

OPCIONES

--all=false Eliminar todos los recursos, en el namespace del tipo de recurso especificado.

-A, --all-namespaces=false Si está presente, listar los objetos solicitados en todos los namespaces. El namespace en el contexto actual se ignora incluso si se especifica con --namespace.

--cascade="background" Debe ser "background", "orphan" o "foreground". Selecciona la estrategia de eliminación en cascada para los dependientes (por ejemplo, Pods creados por un ReplicationController). Por defecto es background.

--dry-run="none" Debe ser "none", "server" o "client". Si la estrategia es client, solo imprime el objeto que se enviaría, sin enviarlo. Si la estrategia es server, envía una solicitud del lado del servidor sin persistir el recurso.

--field-selector="" Selector (consulta de campo) para filtrar, admite '=', '==' y '!='. (por ejemplo, --field-selector clave1=valor1,clave2=valor2). El servidor solo admite un número limitado de consultas de campo por tipo.

-f, --filename=[] que contiene el recurso a eliminar.

--force=false Si es true, elimina inmediatamente los recursos de la API y omite la eliminación gradual. Tenga en cuenta que la eliminación inmediata de algunos recursos puede resultar en inconsistencia o pérdida de datos y requiere confirmación.

--grace-period=-1 Período de tiempo en segundos otorgado al recurso para terminar de forma gradual. Ignorado si es negativo. Establecer en 1 para apagado inmediato. Solo se puede establecer en 0 cuando --force es true (eliminación forzada).

--ignore-not-found=false Tratar "recurso no encontrado" como una eliminación exitosa. Por defecto es "true" cuando se especifica --all.

-i, --interactive=false Si es true, elimina el recurso solo cuando el usuario confirma.

-k, --kustomize="" Procesa un directorio kustomization. Esta opción no se puede usar junto con -f o -R.

--now=false Si es true, se señalan los recursos para apagado inmediato (igual que --grace-period=1).

-o, --output="" Modo de salida. Usa "-o name" para una salida más corta (recurso/nombre).

--raw="" URI sin procesar para DELETE al servidor. Usa el transporte especificado por el archivo kubeconfig.

-R, --recursive=false Procesa el directorio utilizado en -f, --filename recursivamente. Útil cuando desea administrar manifiestos relacionados organizados dentro del mismo directorio.

-l, --selector="" Selector (consulta de etiquetas) para filtrar, admite '=', '==', '!=', 'in', 'notin'. (por ejemplo, -l clave1=valor1,clave2=valor2,clave3 in (valor3)). Los objetos coincidentes deben cumplir todas las restricciones de etiquetas especificadas.

--timeout=0s El tiempo de espera antes de abandonar una eliminación, cero significa determinar un tiempo de espera del tamaño del objeto

--wait=true Si es true, espera a que los recursos desaparezcan antes de retornar. Esto espera a los finalizadores.

kubectl-delete(1) — Manual de Arch Linux

NAME

kubectl-delete

delete resources

SYNOPSIS

kubectl delete -f NAME ... --all -k DIR -l SELECTOR --force --now --ignore-not-found --cascade --namespace NS --confirm --context CONTEXT --kubeconfig KUBECONFIG --match-labels LABEL_SELECTOR --resource-version VERSION --timeout DURATION

DESCRIPTION

Delete resources by filenames, stdin, resources and label selector.

The most common way to specify resources is by name. You can also specify resources by label selector, or by filename.

If you specify a directory, it will be considered a kustomization directory.

This command takes a list of resource types and names, or a file containing resource definitions, and deletes them from the cluster.

If you use -f filename or -k dir, the command will delete the resources defined in the specified file or directory.

If you want to delete resources by label selector, use -l followed by the selector.

You can also delete all resources of a certain type by using --all flag.

The --force flag can be used to force delete resources. This is generally not recommended as it can lead to data loss.

The --now flag deletes the resources immediately, without a grace period.

The --ignore-not-found flag will ignore "not found" errors when deleting resources.

The --cascade flag controls whether to cascade delete. If true (default), the resource will be deleted, and its dependents will also be deleted. If false, only the resource itself will be deleted.

The --namespace flag specifies the namespace to use for the deletion. If not specified, the default namespace will be used.

The --confirm flag will prompt the user for confirmation before deleting resources.

OPTIONS

The following options are available:

-f, --filename FILENAME
Filename, directory, or URL to files identifying the resource to delete.
-k, --kustomize DIR
Process the kustomization directory. This flag tells the command to look for kustomization.yaml in the specified directory and run the delete command on the resources defined there.
-l, --selector LABEL_SELECTOR
Selector (label query) to filter on, supports '=', '!=', and 'in' (e.g. 'environment=production,tier!=frontend').
--all
Do not prompt for confirmation.
--cascade [=true]
Must be true or false. With true, the default, child resources of the deleted resource will also be deleted. With false, only the resource itself will be deleted.
--force
Force delete resources. This is not recommended and can lead to data loss. Use with caution.
--ignore-not-found
If true, ignore "not found" errors when deleting resources.
--now
If true, delete resources immediately, without a grace period.
--namespace NS
If present, the namespace scope for this CLI request.
--resource-version VERSION
Only delete the resource if its current value matches this specified version.
--timeout DURATION
The length of time to wait before giving up on a delete operation for the specified resources. Each of these resources will be deleted independently. If the timeout expires before all resources are deleted, the command will exit with a non-zero exit code.

OPTIONS INHERITED FROM PARENT COMMANDS

The following options are inherited from parent commands:

--context CONTEXT
The name of the kubeconfig context to use
--kubeconfig KUBECONFIG
Path to the kubeconfig file.
--match-labels LABEL_SELECTOR
Selector (label query) to filter on, raw format of --selector. For example, 'environment=production,tier!=frontend'.
--confirm
Prompt on confirming delete operations.

EXAMPLE

  # Eliminar un pod usando el tipo y nombre especificados en pod.json
  kubectl delete -f ./pod.json
  # Eliminar recursos de un directorio que contiene kustomization.yaml - por ejemplo dir/kustomization.yaml
  kubectl delete -k dir
  # Eliminar recursos de todos los archivos que terminan en '.json'
  kubectl delete -f '*.json'
  # Eliminar un pod basado en el tipo y nombre en el JSON pasado a stdin
  cat pod.json | kubectl delete -f -
  # Eliminar pods y servicios con los mismos nombres "baz" y "foo"
  kubectl delete pod,service baz foo
  # Eliminar pods y servicios con la etiqueta name=myLabel
  kubectl delete pods,services -l name=myLabel
  # Eliminar un pod con un retraso mínimo
  kubectl delete pod foo --now
  # Eliminar forzadamente un pod en un nodo muerto
  kubectl delete pod foo --force
  # Eliminar todos los pods
  kubectl delete pods --all
  # Eliminar todos los pods solo si el usuario confirma la eliminación
  kubectl delete pods --all --confirm
