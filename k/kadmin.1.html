DESCRIPCIÓ

N

kadmin y kadmin.local son interfaces de línea de comandos para el sistema de administración de Kerberos V5. Proporcionan funcionalidades casi idénticas; la diferencia es que kadmin.local accede directamente a la base de datos del KDC, mientras que kadmin realiza operaciones utilizando kadmind(8). Excepto cuando se indique explícitamente lo contrario, esta página del manual usará "kadmin" para referirse a ambas versiones. kadmin permite el mantenimiento de principios de Kerberos, políticas de contraseñas y tablas de claves de servicios (keytabs)

.

El cliente kadmin remoto usa Kerberos para autenticarse en kadmind utilizando el principio de servicio kadmin/admin o kadmin/ADMINHOST (donde ADMINHOST es el nombre de host completamente calificado del servidor de administración). Si la caché de credenciales contiene un ticket para uno de estos principios, y se especifica la opción -c credentials_cache, ese ticket se usa para autenticarse en kadmind. De lo contrario, se usan las opciones -p y -k para especificar el nombre del principio de cliente de Kerberos utilizado para la autenticación. Una vez que kadmin ha determinado el nombre del principio, solicita un ticket de servicio al KDC y utiliza ese ticket de servicio para autenticarse en

kadmind.

Dado que kadmin.local accede directamente a la base de datos del KDC, generalmente debe ejecutarse directamente en

el KDC primario con permisos suficientes para leer la base de datos del KDC. Si la base de datos del KDC utiliza e
l módulo de base de datos LDAP, kadmin.local puede ejecutarse en cualquier host que pueda acceder al servidor LDAP.

COMANDOS

Al utilizar el cliente remoto, los comandos disponibles pueden estar restringidos de acuerdo con los privilegios especificados en el archivo kadm5.acl(5) en el servidor de administración.

agregar_principal

agregar_principal [opciones] nuevoprincipal

Crea el principal nuevoprincipal, solicitando la contraseña dos veces. Si no se especifica ninguna política de contraseña con la opción -política, y la política llamada predeterminada está asignada al principal si existe. Sin embargo, la creación de una política llamada predeterminada no asignará automáticamente esta política a los principales preexistentes. Esta asignación de política puede suprimirse con la opción -clearpolicy.

Este comando requiere el privilegio agregar.

Alias: addprinc, ank

Opciones:

-expirar fechavencimiento
(cadena getdate) La fecha de vencimiento del principal.
-expirarpw fechavencimientopw
(cadena getdate) La fecha de vencimiento de la contraseña.
-vidamaxima vidamaxima
(duración o cadena getdate) La vida máxima del ticket para el principal.
-vidarenovablemaxima vidarenovablemaxima
(duración o cadena getdate) La vida renovable máxima de los tickets para el principal.
-kvno kvno
El número de versión de clave inicial.
-política política
La política de contraseña utilizada por este principal. Si no se especifica, se utiliza la política predeterminada si existe (a menos que se especifique -clearpolicy).
-clearpolicy
Evita que se asigne cualquier política cuando no se especifica -política.
{-|+}allow_postdated
-allow_postdated prohíbe que este principal obtenga tickets postdatados. +allow_postdated borra esta bandera.
{-|+}allow_forwardable
-allow_forwardable prohíbe que este principal obtenga tickets reenviables. +allow_forwardable borra esta bandera.
{-|+}allow_renewable
-allow_renewable prohíbe que este principal obtenga tickets renovables. +allow_renewable borra esta bandera.
{-|+}allow_proxiable
-allow_proxiable prohíbe que este principal obtenga tickets proxy. +allow_proxiable borra esta bandera.
{-|+}allow_dup_skey
-allow_dup_skey deshabilita la autenticación de usuario a usuario para este principal al prohibir que otros obtengan un ticket de servicio cifrado con la clave de sesión TGT de este principal. +allow_dup_skey borra esta bandera.
{-|+}requires_preauth
+requires_preauth requiere que este principal se preautentique antes de permitirle usar kinit. -requires_preauth borra esta bandera. Cuando se establece +requires_preauth en un principal de servicio, el KDC solo emitirá tickets de servicio para ese principal de servicio si la autenticación inicial del cliente se realizó utilizando preautenticación.
{-|+}requires_hwauth
+requires_hwauth requiere que este principal se preautentique utilizando un dispositivo de hardware antes de permitirle usar kinit. -requires_hwauth borra esta bandera. Cuando se establece +requires_hwauth en un principal de servicio, el KDC solo emitirá tickets de servicio para ese principal de servicio si la autenticación inicial del cliente se realizó utilizando un dispositivo de hardware para preautenticarse.
{-|+}ok_as_delegate
+ok_as_delegate establece la bandera ok como delegado en los tickets emitidos con este principal como servicio. Los clientes pueden usar esta bandera como una pista de que las credenciales deben delegarse al autenticarse en el servicio. -ok_as_delegate borra esta bandera.
{-|+}allow_svr
-allow_svr prohíbe la emisión de tickets de servicio para este principal. En las versiones 1.17 y posteriores, los tickets de servicio de usuario a usuario aún están permitidos a menos que la bandera -allow_dup_skey también esté establecida. +allow_svr borra esta bandera.
{-|+}allow_tgs_req
-allow_tgs_req especifica que no se permite una solicitud de Ticket-Granting Service (TGS) para un ticket de servicio para este principal. +allow_tgs_req borra esta bandera.
{-|+}allow_tix
-allow_tix prohíbe la emisión de cualquier ticket para este principal. +allow_tix borra esta bandera.
{-|+}needchange
+needchange fuerza un cambio de contraseña en la próxima autenticación inicial para este principal. -needchange borra esta bandera.
{-|+}password_changing_service
+password_changing_service marca este principal como un principal de servicio de cambio de contraseña.
{-|+}ok_to_auth_as_delegate
+ok_to_auth_as_delegate permite a este principal adquirir tickets reenviables a sí mismo de usuarios arbitrarios, para usar con delegación restringida.
{-|+}no_auth_data_required
+no_auth_data_required evita que se agreguen datos PAC o AD-SIGNEDPATH a los tickets de servicio para el principal.
{-|+}lockdown_keys
+lockdown_keys evita que las claves de este principal salgan del KDC a través de kadmind. Las operaciones chpass y extract se deniegan para un principal con este atributo. La operación chrand está permitida, pero no devolverá las nuevas claves. Las operaciones delete y rename también se deniegan si este atributo está establecido, para evitar que un administrador malintencionado reemplace principales como krbtgt/* o kadmin/* por nuevos principales sin el atributo. Este atributo se puede establecer a través del protocolo de red, pero solo se puede eliminar usando kadmin.local.
-randkey
Establece la clave del principal a un valor aleatorio.
-nokey
Hace que el principal se cree sin clave. Nuevo en la versión 1.12.
-pw contraseña
Establece la contraseña del principal a la cadena especificada y no solicita contraseña. Nota: usar esta opción en un script de shell puede exponer la contraseña a otros usuarios del sistema a través de la lista de procesos.
-e enc:salt,...
Utiliza la lista de claves y sales especificada para establecer las claves del principal. Consulte Keysalt_lists en kdc.conf(5) para ver una lista de valores posibles.
-x db_princ_args
Indica opciones específicas de la base de datos. Las opciones para el módulo de base de datos LDAP son:
-x dn=dn
Especifica el objeto LDAP que contendrá el principal Kerberos que se está creando.
-x linkdn=dn
Especifica el objeto LDAP al que apuntará el objeto principal Kerberos recién creado.
-x containerdn=container_dn
Especifica el objeto contenedor bajo el cual se creará el principal Kerberos.
-x tktpolicy=política
Asocia una política de ticket al principal Kerberos.

NOTA:

  • Las opciones containerdn y linkdn no se pueden especificar con la opción dn.
  • Si las opciones dn o containerdn no se especifican al agregar el principal, los principales se crean bajo el contenedor de principales configurado en el realm o el contenedor del realm.
  • dn y containerdn deben estar dentro de los subárboles o del contenedor de principales configurado en el realm.

NAME

SYNOPSIS

kadmind_port ] [ -w ] [ -q expression ] [ -m ] [ -d kadmind_port ] [ -i ] [ -T kadmind_server ] [ -r realm ] [ -p principal ]

DESCRIPTION

The kadmin program is the command-line interface to the Kerberos administration server, kadmind. It allows an administrator to perform administrative operations on the Kerberos database, such as adding or deleting principals, managing policies, and manipulating keytabs.

When kadmin is invoked, it attempts to connect to the kadmind server. If the connection is successful, it presents a prompt indicating that it is ready to accept commands.

The kadmin program supports interactive use, command-line execution of a single command, and batch processing of commands from a file.

INTERACTIVE USE

When invoked without any command-line arguments (or with only options that don't specify a command), kadmin enters interactive mode. In this mode, commands are entered at the kadmin: prompt. The program reads commands from standard input until it encounters the quit command or an end-of-file.

NON-INTERACTIVE USE

A single command can be executed by providing the command and its arguments as arguments to kadmin. The program will execute the command and then exit. This is useful for scripting.

BATCH MODE

Commands can be read from a file by redirecting standard input. For example:

kadmin < commands.txt

OPTIONS

The following options can be provided to kadmin:

-p principal
Principal name to use for authentication. If not specified, it defaults to the current user's principal name.
-k
Use keytab authentication instead of password authentication. Requires the principal to have a corresponding keytab entry.
-n
Do not prompt for a password or passphrase when using keytab authentication. This option is equivalent to -k.
-T kadmind_server
Connect to the specified kadmind server instead of the default server.
-r realm
Realm to use for authentication. If not specified, the default realm is used.
-w
Print the version number and exit.
-q expression
Execute a single expression and exit. This is useful for scripting.
-m
Use pre-authentication. This option is typically used when the KDC is not configured to allow anonymous principals.
-d kadmind_port
Use the specified port number for connecting to the kadmind server.
-i
Use the default principal for the realm. This option is equivalent to -p when no principal is specified.
-t keytab
Use the specified keytab file for authentication.
-l
Lock the Kerberos database exclusively. Use with extreme caution.
-F
Do not automatically unlock the Kerberos database when exiting.
-P kadmind_port
Use the specified port number for connecting to the kadmind server.
-e enc:salt,...
Specify the key/salt types to use when setting or changing a principal's password or keys. See Keysalt_lists in kdc.conf(5) for a list of accepted values.
-a
Add a principal to the database. This option is typically used in conjunction with other options to specify the principal's attributes.
-S service
Connect to the specified service principal instead of the default kadmind service principal.
-X sectok
Specify a security token for authentication.
-v
Print the version number and exit.
-V
Be verbose.
-4
Use IPv4 addresses only.
-6
Use IPv6 addresses only.
-K cache
Use the specified credential cache.
-H profile_dir
Use the specified directory for Kerberos configuration files.

DATABASE OPTIONS

These options are only relevant when using the DB2 KDC database module:

-lock
Lock the Kerberos database exclusively.
-unlock
Release the exclusive database lock.

COMMANDS

The following commands can be used with kadmin:

add_principal

add_principal [options] principal

Adds a new principal to the Kerberos database. Options include:

-pw password
Sets the principal's password to the specified string.
-maxlife lifetime
(duration or getdate string) Sets the maximum lifetime for tickets issued to this principal.
-minlife lifetime
(duration or getdate string) Sets the minimum lifetime for tickets issued to this principal.
-maxrenewablelife lifetime
(duration or getdate string) Sets the maximum renewable lifetime for tickets issued to this principal.
-kvno kvno
Sets the key version number for the principal.
-policy policy
Assigns the principal to the specified password policy.
-randkey
Generates a random key for the principal.
-keytab keytab
Adds the principal's keys to the specified keytab file.
-e enc:salt,...
Specify the key/salt types to use when setting or changing a principal's password or keys.
-allow_postdated
Allow postdated tickets to be issued to this principal.
-allow_forwardable
Allow forwardable tickets to be issued to this principal.
-allow_renewable
Allow renewable tickets to be issued to this principal.
-allow_proxiable
Allow proxiable tickets to be issued to this principal.
-randkeyaltsalt
Generates a random key and salt for the principal.
-max_successive_logins number
Sets the maximum number of successive failed login attempts allowed for this principal before their account is locked.
-failurecountinterval failuretime
(duration or getdate string) Sets the allowable time between authentication failures. If an authentication failure happens after failuretime has elapsed since the previous failure, the number of authentication failures is reset to 1. A failuretime value of 0 (the default) means forever.
-lockoutduration lockouttime
(duration or getdate string) Sets the duration for which the principal is locked from authenticating if too many authentication failures occur without the specified failure count interval elapsing. A duration of 0 (the default) means the principal remains locked out until it is administratively unlocked with modprinc -unlock.
-allowedkeysalts
Specifies the key/salt tuples supported for long-term keys when setting or changing a principal's password/keys. See Keysalt_lists in kdc.conf(5) for a list of the accepted values, but note that key/salt tuples must be separated with commas (',') only. To clear the allowed key/salt policy use a value of '-'.

Example:

kadmin: add_policy -maxlife "2 days" -minlength 5 guests
kadmin:

modify_policy

modify_policy [options] policy

Modifies the password policy named policy. Options are as described for add_policy.

This command requires the modify privilege.

Alias: modpol

delete_policy

delete_policy [-force] policy

Deletes the password policy named policy. Prompts for confirmation before deletion. The command will fail if the policy is in use by any principals.

This command requires the delete privilege.

Alias: delpol

Example:

kadmin: del_policy guests
Are you sure you want to delete the policy "guests"?
(yes/no): yes
kadmin:

get_policy

get_policy [ -terse ] policy

Displays the values of the password policy named policy. With the -terse flag, outputs the fields as quoted strings separated by tabs.

This command requires the inquire privilege.

Alias: getpol

Examples:

kadmin: get_policy admin
Policy: admin
Maximum password life: 180 days 00:00:00
Minimum password life: 00:00:00
Minimum password length: 6
Minimum number of password character classes: 2
Number of old keys kept: 5
Reference count: 17
kadmin: get_policy -terse admin
admin     15552000  0    6    2    5    17
kadmin:

The "Reference count" is the number of principals using that policy. With the LDAP KDC database module, the reference count field is not meaningful.

list_policies

list_policies [expression]

Retrieves all or some policy names. expression is a shell-style glob expression that can contain the wild-card characters ?, *, and []. All policy names matching the expression are printed. If no expression is provided, all existing policy names are printed.

This command requires the list privilege.

Aliases: listpols, get_policies, getpols.

Examples:

kadmin:  listpols
test-pol
dict-only
once-a-min
test-pol-nopw
kadmin:  listpols t*
test-pol
test-pol-nopw
kadmin:

ktadd

ktadd [options] principal
ktadd [options] -glob princ-exp

Adds a principal, or all principals matching princ-exp, to a keytab file. Each principal's keys are randomized in the process. The rules for princ-exp are described in the list_principals command.

This command requires the inquire and changepw privileges. With the -glob form, it also requires the list privilege.

The options are:

-k[eytab] keytab
Use keytab as the keytab file. Otherwise, the default keytab is used.
-e enc:salt,...
Uses the specified keysalt list for setting the new keys of the principal. See Keysalt_lists in kdc.conf(5) for a list of possible values.
-q
Display less verbose information.
-norandkey
Do not randomize the keys. The keys and their version numbers stay unchanged. This option cannot be specified in combination with the -e option.

An entry for each of the principal's unique encryption types is added, ignoring multiple keys with the same encryption type but different salt types.

Alias: xst

Example:

kadmin: ktadd -k /tmp/foo-new-keytab host/foo.mit.edu
Entry for principal host/foo.mit.edu@ATHENA.MIT.EDU with kvno 3,
     encryption type aes256-cts-hmac-sha1-96 added to keytab
     FILE:/tmp/foo-new-keytab
kadmin:

ktremove

ktremove [options] principal [kvno | all | old]

Removes entries for the specified principal from a keytab. Requires no permissions, since this does not require database access.

If the string "all" is specified, all entries for that principal are removed; if the string "old" is specified, all entries for that principal except those with the highest kvno are removed. Otherwise, the value specified is parsed as an integer, and all entries whose kvno match that integer are removed.

The options are:

-k[eytab] keytab
Use keytab as the keytab file. Otherwise, the default keytab is used.
-q
Display less verbose information.

Alias: ktrem

Example:

kadmin: ktremove kadmin/admin all
Entry for principal kadmin/admin with kvno 3 removed from keytab
     FILE:/etc/krb5.keytab
kadmin:

lock

Lock database exclusively. Use with extreme caution! This command only works with the DB2 KDC database module.

unlock

Release the exclusive database lock.

list_requests

Lists available for kadmin requests.

Aliases: lr, ?

quit

Exit program. If the database was locked, the lock is released.

Aliases: exit, q

NAME

kadmin - database administration tool for the Kerberos key distribution center (KDC)

SYNOPSIS

kadmin [ -a kadmind_server ] [ -k ] [ -p port ] [ -P server_princ ] [ -S kdc_realm ] [ -t ] [ -T keytab ] [ -D ] [ -F ] [ -h ] [ -q command ] [ -r realm ] [ -m ] [ -V ] [ -v ] [ -d ] [ -e ] [ -x extra_options ] [ principal [ password ]]

DESCRIPTION

The kadmin program is an administrative tool for managing the Kerberos principal database. It allows you to add, delete, modify, and list principals and policies in the KDC database.

To use kadmin, you must have administrative privileges on the Kerberos realm. You can connect to the KDC server either locally or remotely.

When invoked without the -q option, kadmin enters an interactive mode where you can issue commands one by one.

COMMANDS

The following commands are available in interactive mode:

  • addprinc [ [ -pw_expire date ] [ -pw_change_date date ] [ -pw_min_life time ] [ -pw_max_life time ] [ -pw_history count ] [ -policy policy ] [ -allow_tgs_req true|false ] [ -allow_tgs_rep true|false ] [ -allow_tkt_rep true|false ] [ -max_renewable_life time ] [ -max_life time ] [ -kvno integer ] [ -e encryption_types ] principal ]
    Adds a new principal to the database.
  • delprinc principal
    Deletes a principal from the database.
  • modprinc [ options ] principal
    Modifies an existing principal. Options include:
    • -upw: Change password.
    • -e: Change encryption types.
    • -max_life: Set maximum ticket life.
    • -max_renewable_life: Set maximum renewable ticket life.
    • -pw_expire: Set password expiration date.
    • -pw_change_date: Set password change date.
    • -pw_min_life: Set minimum password life.
    • -pw_max_life: Set maximum password life.
    • -pw_history: Set password history count.
    • -policy: Set policy for the principal.
    • -allow_tgs_req: Allow TGS requests.
    • -allow_tgs_rep: Allow TGS replies.
    • -allow_tkt_rep: Allow ticket replies.
    • -kvno: Set key version number.
  • listprinc [ -laps ] [ -e ] [ -p ] [ -P ] [ -f ] [ -a ] [ -t ] [ -x ] [ expression ]
    Lists principals matching the given expression.
  • getprinc principal
    Retrieves information about a specific principal.
  • purgekeys principal
    Purges all keys for a principal.
  • renews principal
    Renews a principal's ticket.
  • lock principal
    Locks a principal account.
  • unlock principal
    Unlocks a principal account.
  • quinvalidate principal
    Invalidates all tickets for a principal.
  • checkpin principal
    Checks a principal's PIN.
  • get_policy policy
    Retrieves information about a policy.
  • chg_policy [ options ] policy
    Changes an existing policy. Options include:
    • -max_life: Set maximum ticket life.
    • -max_renewable_life: Set maximum renewable ticket life.
    • -pw_expire: Set password expiration date.
    • -pw_change_date: Set password change date.
    • -pw_min_life: Set minimum password life.
    • -pw_max_life: Set maximum password life.
    • -pw_history: Set password history count.
  • add_policy [ options ] policy
    Adds a new policy. Options are the same as for chg_policy.
  • del_policy policy
    Deletes a policy.
  • list_policies [ -laps ] [ -f ] [ -a ] [ -t ] [ -x ] [ expression ]
    Lists policies matching the given expression.
  • quit or exit
    Exits the kadmin program.

OPTIONS

  • -a kadmind_server: Specifies the KDC administration server to connect to.
  • -k: Use keytab authentication.
  • -p port: Specifies the port for the KDC administration server.
  • -P server_princ: Specifies the KDC administration server principal.
  • -S kdc_realm: Specifies the KDC realm.
  • -t: Use a temporary KDC database.
  • -T keytab: Specifies the keytab file to use for authentication.
  • -D: Enable debugging output.
  • -F: Enable very verbose debugging output.
  • -h: Display help message.
  • -q command: Execute a single command and exit.
  • -r realm: Specifies the realm to administer.
  • -m: Use MD5 encryption.
  • -V: Display version information.
  • -v: Enable verbose output.
  • -d: Dump the KDC database.
  • -e: Enable encryption.
  • -x extra_options: Specify extra options.
