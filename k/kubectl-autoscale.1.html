NOMBRE

kubectl autoscale - Escala automáticamente un deployment, replica set, stateful set o replication controller

SINOPSIS

kubectl autoscale [OPCIONES]

DESCRIPCIÓN

Crea un autoscaler que elige y establece automáticamente el número de pods que se ejecutan en un clúster de Kubernetes. El comando intentará usar primero la API autoscaling/v2; en caso de error, recurrirá a la API autoscaling/v1.

Busca un deployment, replica set, stateful set o replication controller por nombre y crea un autoscaler que utiliza el recurso dado como referencia. Un autoscaler puede aumentar o disminuir automáticamente el número de pods desplegados dentro del sistema según sea necesario.

OPCIONES

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--cpu="" Utilización de CPU objetivo en todos los pods. Cuando se especifica como un porcentaje (por ejemplo, "70%" para el 70% de la CPU solicitada) se dirigirá a la utilización promedio. Cuando se especifica como una cantidad (por ejemplo, "500m" para 500 miliCPU) se dirigirá al valor promedio. El valor sin unidades se trata como una cantidad con miliCPU como unidad (por ejemplo, "500" es "500m").

--cpu-percent=-1 La utilización promedio objetivo de CPU (representada como un porcentaje de la CPU solicitada) en todos los pods. Si no se especifica o es negativo, se utilizará una política de escalado automático predeterminada.

--dry-run="none" Debe ser "none", "server" o "client". Si la estrategia es cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si la estrategia es servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--field-manager="kubectl-autoscale" Nombre del gestor utilizado para rastrear la propiedad de los campos.

-f, --filename=[] Nombre de archivo, directorio o URL a archivos que identifican el recurso a escalar automáticamente.

-k, --kustomize="" Procesa el directorio kustomization. Esta bandera no se puede usar junto con -f o -R.

--max=-1 El límite superior para el número de pods que puede establecer el autoscaler. Requerido.

--memory="" Utilización de memoria objetivo en todos los pods. Cuando se especifica como un porcentaje (por ejemplo, "60%" para el 60% de la memoria solicitada) se dirigirá a la utilización promedio. Cuando se especifica como una cantidad (por ejemplo, "200Mi" para 200 MiB, "1Gi" para 1 GiB) se dirigirá al valor promedio. El valor sin unidades se trata como una cantidad con mebibytes como unidad (por ejemplo, "200" es "200Mi").

--min=-1 El límite inferior para el número de pods que puede establecer el autoscaler. Si no se especifica o es negativo, el servidor aplicará un valor predeterminado.

--name="" El nombre para el objeto recién creado. Si no se especifica, se utilizará el nombre del recurso de entrada.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--record=false Registra el comando kubectl actual en la anotación del recurso. Si se establece en falso, no registra el comando. Si se establece en verdadero, registra el comando. Si no se establece, por defecto actualiza el valor de la anotación existente solo si ya existe una.

-R, --recursive=false Procesa el directorio utilizado en -f, --filename recursivamente. Útil cuando desea administrar manifiestos relacionados organizados dentro del mismo directorio.

--save-config=false Si es verdadero, la configuración del objeto actual se guardará en su anotación. De lo contrario, la anotación no se modificará. Esta bandera es útil cuando desea realizar kubectl apply en este objeto en el futuro.

--show-managed-fields=false Si es verdadero, mantenga los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a un archivo de plantilla para usar cuando -o=go-template, -o=go-template-file. El formato de plantilla son plantillas de Go [http://golang.org/pkg/text/template/#pkg-overview].

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario puede ser un usuario normal o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar varios grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster kubeconfig a usar

--context="" El nombre del contexto kubeconfig a usar

--disable-compression=false Si es verdadero, optar por no participar en la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará para su validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes de CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para las preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funciones KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud de CLI

--password="" Contraseña para autenticación básica al servidor de API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" La duración de tiempo a esperar antes de desistir de una sola solicitud al servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de espera de las solicitudes.

-s, --server="" La dirección y el puerto del servidor de API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor

--token="" Token Bearer para autenticación al servidor de API

--user="" El nombre del usuario kubeconfig a usar

--username="" Nombre de usuario para autenticación básica al servidor de API

--version=false --version, --version=raw imprime información de versión y sale; --version=vX.Y.Z... establece la versión reportada

--warnings-as-errors=false Trata las advertencias recibidas del servidor como errores y sale con un código de salida distinto de cero

EJEMPLO

  # Escala automáticamente un deployment "foo", con el número de pods entre 2 y 10, sin utilización de CPU objetivo especificada, por lo que se utilizará una política de escalado automático predeterminada
  kubectl autoscale deployment foo --min=2 --max=10
  # Escala automáticamente un replication controller "foo", con el número de pods entre 1 y 5, utilización de CPU objetivo al 80%
  kubectl autoscale rc foo --max=5 --cpu=80%
  # Escala automáticamente un deployment "bar", con el número de pods entre 3 y 6, CPU objetivo promedio de 500m y memoria de 200Mi
  kubectl autoscale deployment bar --min=3 --max=6 --cpu=500m --memory=200Mi
  # Escala automáticamente un deployment "bar", con el número de pods entre 2 y 8, utilización de CPU del 60% y utilización de memoria del 70%
  kubectl autoscale deployment bar --min=3 --max=6 --cpu=60% --memory=70%
