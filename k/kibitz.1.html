KIBITZ(1) Manual de Comandos Generales KIBITZ(1)

NOMBRE

kibitz - permite que dos personas interactúen con un shell

SINOPSIS

kibitz [ kibitz-args ] user [ program program-args... ]
kibitz [ kibitz-args ] user@host [ program program-args... ]

INTRODUCCIÓN

kibitz permite que dos (o más) personas interactúen con un shell (o cualquier programa arbitrario). Los usos incluyen:

•
Un usuario novato puede pedir ayuda a un usuario experto. Usando kibitz, el experto puede ver lo que está haciendo el usuario y ofrecer consejos o mostrar cómo hacerlo correctamente.
•
Al ejecutar kibitz y luego iniciar un editor de pantalla completa, las personas pueden mantener una conversación, conservando la capacidad de desplazarse hacia atrás, guardar la conversación completa o incluso editarla mientras está en curso.
•
Las personas pueden colaborar en juegos, edición de documentos u otras tareas cooperativas donde cada persona tiene fortalezas y debilidades que se complementan entre sí.

USO

Para iniciar kibitz, user1 ejecuta kibitz con el argumento del usuario con el que hacer kibitz. Por ejemplo:

kibitz user2

kibitz inicia un nuevo shell (u otro programa, si se indica en la línea de comandos), mientras le pide a user2 que ejecute kibitz. Si user2 ejecuta kibitz según lo indicado, las pulsaciones de teclado de ambos usuarios se convierten en la entrada del shell. Del mismo modo, ambos usuarios reciben la salida del shell.

Para terminar kibitz basta con terminar el shell mismo. Por ejemplo, si cualquiera de los usuarios escribe ^D (y el shell acepta esto como EOF), el shell termina seguido por kibitz.

Normalmente, todos los caracteres se pasan sin interpretar. Sin embargo, si se emite el carácter de escape (descrito cuando kibitz inicia), el usuario puede hablar directamente con el kibitz intérprete. Se pueden dar comandos de Expect(1) o Tcl(3) . Además, se puede usar el control de trabajos mientras se está en el intérprete, para, por ejemplo, suspender o reiniciar kibitz.

Diversos procesos pueden proporcionar diversos efectos. Por ejemplo, se puede emular una sesión bidireccional de write(1) con el comando:

kibitz user2 sleep 1000000

ARGUMENTOS

kibitz toma argumentos, estos también deben estar separados por espacios en blanco.

La opción -noproc ejecuta kibitz sin un proceso debajo. Los caracteres se pasan al otro kibitz. Esto es particularmente útil para conectar múltiples procesos interactivos entre sí. En este modo, los caracteres no se reflejan de vuelta al que escribe.

-noescape desactiva el carácter de escape.

-escape char establece el carácter de escape. El carácter de escape predeterminado es ^].

-silent desactiva los mensajes informativos que describen lo que kibitz está haciendo para iniciar una conexión.

-tty ttyname define el tty al que debe enviarse la invitación.

Si inicia kibitz hacia user2 en un equipo remoto, kibitz realiza un rlogin al equipo remoto con su nombre de usuario actual. La opción -proxy username hace que rlogin use username para el inicio de sesión remoto (p. ej., si su cuenta en el equipo remoto tiene un nombre de usuario diferente). Si no se da la opción -proxy , kibitz intenta determinar su nombre de usuario actual (en ese orden) inspeccionando las variables de entorno USER y LOGNAME, luego usando los comandos whoami y logname.

Los argumentos -noescape y -escape también pueden ser dados por user2 cuando se le pide ejecutar kibitz.

MÁS DE DOS USUARIOS

La implementación actual de kibitz entiende explícitamente solo a dos usuarios, sin embargo, aún es posible tener un kibitz de tres (o más) vías, haciendo kibitz a otro kibitz. Por ejemplo, el siguiente comando ejecuta kibitz con el usuario actual, user2 y user3:

% kibitz user2 kibitz user3

Se pueden agregar usuarios adicionales simplemente añadiendo más comandos "kibitz user".

El script xkibitz es similar a kibitz pero soporta la capacidad de agregar usuarios adicionales (y eliminarlos) dinámicamente.

ADVERTENCIAS

kibitz asume que el 2º usuario tiene el mismo tipo y tamaño de terminal que el 1er usuario. Si esta suposición es incorrecta, los programas gráficos pueden mostrarse de manera extraña.

kibitz maneja gráficos de caracteres, pero no puede manejar gráficos de mapa de bits. Por lo tanto,

% xterm -e kibitz    funcionará
% kibitz xterm       no funcionará
Sin embargo, se puede obtener el efecto del último comando usando xkibitz (véase VÉASE TAMBIÉN más abajo). kibitz usa los mismos permisos que los usados por rlogin, rsh, etc. Por lo tanto, solo puede hacer kibitz a usuarios en hosts para los que puede hacer rlogin. Del mismo modo, kibitz pedirá una contraseña en el host remoto si rlogin lo haría.

Si hace kibitz a usuarios en hosts remotos, kibitz necesita distinguir su prompt de otras cosas que puedan precederlo durante el inicio de sesión. (Idealmente, se prefiere el final, pero cualquier parte debería ser suficiente.) Si tiene un prompt inusual, establezca la variable de entorno EXPECT_PROMPT a una expresión regular de estilo egrep(1). Los corchetes deben ir precedidos por una barra invertida en rangos, y tres barras invertidas para corchetes literales. La expresión regular del prompt predeterminado es "($|%|#) ".

kibitz requiere el programa kibitz en ambos hosts. kibitz requiere expect(1).

En comparación, el script xkibitz usa el mecanismo de autorización de X para la comunicación entre hosts, por lo que no necesita iniciar sesión, reconocer su prompt, ni requerir kibitz en el host remoto. Sin embargo, sí necesita permiso para acceder a los otros servidores X.

ERRORES

Una versión temprana de tmpfs de Sun tenía un error que hacía que kibitz fallara. Si kibitz informa "error flushing ...: Is a directory", pida a Sun el parche #100174.

Si su Expect no está compilado con soporte de múltiples procesos (es decir, no tiene un select o poll funcionando), no podrá ejecutar kibitz.

ENTORNO

La variable de entorno SHELL se usa para determinar el shell a iniciar, si no se da otro programa en la línea de comandos.

Si la variable de entorno EXPECT_PROMPT existe, se toma como una expresión regular que coincide con el final de su prompt de inicio de sesión (pero que no ocurre de otro modo durante el inicio de sesión). Véase también ADVERTENCIAS más arriba.

Si las variables de entorno USER o LOGNAME están definidas, se usan para determinar el nombre de usuario actual para un kibitz a un equipo remoto. Véase la descripción de la opción -proxy en ARGUMENTOS más arriba.
