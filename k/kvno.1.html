NOMBRE

kvno - imprime los números de versión de clave de los principales de Kerberos

SINOPSIS

kvno [-c ccache] [-e etype] [-k keytab] [-q] [-u | -S sname] [-P] [--cached-only] [--no-store] [--out-cache cache] [[{-F cert_file | {-I | -U} for_user} [-P]] | --u2u ccache] servicio1 servicio2 ...

DESCRIPCIÓN

kvno adquiere un ticket de servicio para los principales de Kerberos especificados e imprime los números de versión de clave de cada uno.

OPCIONES

-c ccache
Especifica el nombre de un caché de credenciales a usar (si no es el predeterminado)
-e etype
Especifica el tipo de cifrado que se solicitará para la clave de sesión de todos los servicios nombrados en la línea de comandos. Esto es útil en ciertas situaciones de compatibilidad con versiones anteriores.
-k keytab
Descifra los tickets adquiridos usando keytab para confirmar su validez.
-q
Suprime la impresión de salida cuando tiene éxito. Si no se puede obtener un ticket de servicio, todavía se imprimirá un mensaje de error y kvno saldrá con un estado distinto de cero.
-u
Usa el tipo de nombre desconocido en los nombres de principales de servicio solicitados. Esta opción no se puede usar con -S.
-P
Especifica que los argumentos servicio1 servicio2 ... se tratarán como servicios para los cuales se adquirirán credenciales usando delegación restringida. Esta opción solo es válida cuando se usa junto con la transición de protocolo.
-S sname
Especifica que los argumentos servicio1 servicio2 ... se interpretan como nombres de host, y los principales de servicio se construirán a partir de esos nombres de host y el nombre de servicio sname. Los nombres de host de servicio se canonicen de acuerdo con las reglas habituales para construir principales de servicio.
-I for_user
Especifica que se usará la transición de protocolo (S4U2Self) para adquirir un ticket en nombre de for_user. Si no se solicita la delegación restringida, el nombre del servicio debe coincidir con el principal del cliente del caché de credenciales.
-U for_user
Igual que -I, pero trata for_user como un nombre empresarial.
-F cert_file
Especifica que se utilizará la transición de protocolo, identificando el principal del cliente con el certificado X.509 en cert_file. El archivo del certificado debe estar en formato PEM.
--cached-only
Solo recupera las credenciales ya presentes en el caché, no del KDC. (Añadido en la versión 1.19.)
--no-store
No almacena las credenciales recuperadas en el caché. Si también se especifica --out-cache, las credenciales aún se almacenarán en el caché de credenciales de salida. (Añadido en la versión 1.19.)
--out-cache ccache
Inicializa ccache y almacena todas las credenciales recuperadas en él. No almacena las credenciales adquiridas en el caché de entrada. (Añadido en la versión 1.19.)
--u2u ccache
Solicita un ticket de usuario a usuario. ccache debe contener un ticket krbtgt local para el principal del servidor. El número de versión informado típicamente será 0, ya que el ticket resultante no está cifrado con la clave a largo plazo del servidor.

AMBIENTE

Ver kerberos(7) para una descripción de las variables de entorno de Kerberos.
