NOMBRE

kubectl label - Actualiza las etiquetas de un recurso

SINOPSIS

kubectl label [OPCIONES]

DESCRIPCIÓN

Actualiza las etiquetas de un recurso.

  • Una clave y un valor de etiqueta deben comenzar con una letra o un número, y pueden contener letras, números, guiones, puntos y guiones bajos, hasta 63 caracteres cada uno.
  • Opcionalmente, la clave puede comenzar con un prefijo de subdominio DNS y una única '/', como example.com/my-app.
  • Si --overwrite es verdadero, entonces las etiquetas existentes se pueden sobrescribir, de lo contrario, intentar sobrescribir una etiqueta dará como resultado un error.
  • Si se especifica --resource-version, entonces las actualizaciones utilizarán esta versión del recurso, de lo contrario se utilizará la versión del recurso existente.

OPCIONES

--all=false Selecciona todos los recursos, en el namespace de los tipos de recursos especificados

-A, --all-namespaces=false Si es verdadero, comprueba la acción especificada en todos los namespaces.

--allow-missing-template-keys=true Si es verdadero, ignora cualquier error en las plantillas cuando falta un campo o una clave de mapa en la plantilla. Solo se aplica a los formatos de salida golang y jsonpath.

--dry-run="none" Debe ser "none", "server" o "client". Si es de estrategia de cliente, solo imprime el objeto que se enviaría, sin enviarlo. Si es de estrategia de servidor, envía una solicitud del lado del servidor sin persistir el recurso.

--field-manager="kubectl-label" Nombre del gestor utilizado para rastrear la propiedad de los campos.

--field-selector="" Selector (consulta de campo) para filtrar, soporta '=', '==', y '!='. (por ejemplo, --field-selector clave1=valor1,clave2=valor2). El servidor solo soporta un número limitado de consultas de campo por tipo.

-f, --filename=[] Nombre de archivo, directorio o URL a archivos que identifican el recurso para actualizar las etiquetas

-k, --kustomize="" Procesa el directorio de kustomization. Esta bandera no se puede usar junto con -f o -R.

--list=false Si es verdadero, muestra las etiquetas de un recurso dado.

--local=false Si es verdadero, la etiqueta NO contactará con el api-server sino que se ejecutará localmente.

-o, --output="" Formato de salida. Uno de: (json, yaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).

--overwrite=false Si es verdadero, permite sobrescribir etiquetas, de lo contrario rechaza las actualizaciones de etiquetas que sobrescriban etiquetas existentes.

--record=false Graba el comando kubectl actual en la anotación del recurso. Si se establece en falso, no graba el comando. Si se establece en verdadero, graba el comando. Si no se establece, por defecto se actualiza el valor de la anotación existente solo si ya existe alguna.

-R, --recursive=false Procesa el directorio utilizado en -f, --filename recursivamente. Útil cuando desea administrar manifiestos relacionados organizados dentro del mismo directorio.

--resource-version="" Si no está vacío, la actualización de etiquetas solo tendrá éxito si esta es la versión del recurso actual del objeto. Solo válido cuando se especifica un solo recurso.

-l, --selector="" Selector (consulta de etiqueta) para filtrar, soporta '=', '==', '!=', 'in', 'notin'. (por ejemplo, -l clave1=valor1,clave2=valor2,clave3 in (valor3)). Los objetos coincidentes deben cumplir todas las restricciones de etiquetas especificadas.

--show-managed-fields=false Si es verdadero, conserva los managedFields al imprimir objetos en formato JSON o YAML.

--template="" Cadena de plantilla o ruta a un archivo de plantilla para usar cuando -o=go-template, -o=go-template-file. El formato de plantilla es plantillas de golang [http://golang.org/pkg/text/template/#pkg-overview].

OPCIONES HEREDADAS DE COMANDOS PADRE

--as="" Nombre de usuario a suplantar para la operación. El usuario podría ser un usuario regular o una cuenta de servicio en un namespace.

--as-group=[] Grupo a suplantar para la operación, esta bandera se puede repetir para especificar múltiples grupos.

--as-uid="" UID a suplantar para la operación.

--cache-dir="/home/username/.kube/cache" Directorio de caché predeterminado

--certificate-authority="" Ruta a un archivo de certificado para la autoridad de certificación

--client-certificate="" Ruta a un archivo de certificado de cliente para TLS

--client-key="" Ruta a un archivo de clave de cliente para TLS

--cluster="" El nombre del clúster de kubeconfig a utilizar

--context="" El nombre del contexto de kubeconfig a utilizar

--disable-compression=false Si es verdadero, se excluye la compresión de respuesta para todas las solicitudes al servidor

--insecure-skip-tls-verify=false Si es verdadero, el certificado del servidor no se verificará en busca de validez. Esto hará que sus conexiones HTTPS no sean seguras

--kubeconfig="" Ruta al archivo kubeconfig a utilizar para las solicitudes CLI.

--kuberc="" Ruta al archivo kuberc a utilizar para preferencias. Esto se puede deshabilitar exportando la puerta de enlace de funciones KUBECTL_KUBERC=false o desactivando la función KUBERC=off.

--match-server-version=false Requiere que la versión del servidor coincida con la versión del cliente

-n, --namespace="" Si está presente, el ámbito del namespace para esta solicitud CLI

--password="" Contraseña para la autenticación básica al servidor API

--profile="none" Nombre del perfil a capturar. Uno de (none|cpu|heap|goroutine|threadcreate|block|mutex)

--profile-output="profile.pprof" Nombre del archivo donde escribir el perfil

--request-timeout="0" La longitud de tiempo a esperar antes de renunciar a una única solicitud al servidor. Los valores distintos de cero deben contener una unidad de tiempo correspondiente (por ejemplo, 1s, 2m, 3h). Un valor de cero significa no agotar el tiempo de espera de las solicitudes.

-s, --server="" La dirección y el puerto del servidor API de Kubernetes

--tls-server-name="" Nombre del servidor a utilizar para la validación del certificado del servidor. Si no se proporciona, se utiliza el nombre de host utilizado para contactar al servidor

--token="" Token Bearer para la autenticación al servidor API

--user="" El nombre del usuario de kubeconfig a utilizar

--username="" Nombre de usuario para la autenticación básica al servidor API

--version=false --version, --version=raw imprime la información de la versión y sale; --version=vX.Y.Z... establece la versión reportada

--warnings-as-errors=false Tratar las advertencias recibidas del servidor como errores y salir con un código de salida distinto de cero

EJEMPLO

  # Actualiza el pod 'foo' con la etiqueta 'unhealthy' y el valor 'true'
  kubectl label pods foo unhealthy=true
  # Actualiza el pod 'foo' con la etiqueta 'status' y el valor 'unhealthy', sobrescribiendo cualquier valor existente
  kubectl label --overwrite pods foo status=unhealthy
  # Actualiza todos los pods en el namespace
  kubectl label pods --all status=unhealthy
  # Actualiza un pod identificado por el tipo y el nombre en "pod.json"
  kubectl label -f pod.json status=unhealthy
  # Actualiza el pod 'foo' solo si el recurso no ha cambiado desde la versión 1
  kubectl label pods foo status=unhealthy --resource-version=1
  # Actualiza el pod 'foo' eliminando la etiqueta llamada 'bar' si existe
  # No requiere la bandera --overwrite
  kubectl label pods foo bar-

NOMBRE

kubectl-label - Asigna etiquetas a objetos.

SINOPSIS

kubectl label (<RESOURCE>/<NAME> -o <OUTPUT_FORMAT>) [-o <OUTPUT_FORMAT>] [--overwrite] [(--all | --selector <LABEL_SELECTOR>)] [<KEY>=<VALUE>...] [<KEY>-=<VALUE>...]

DESCRIPCIÓN

Asigna etiquetas a uno o más objetos. Las etiquetas son pares clave-valor que se utilizan para organizar y agrupar recursos de Kubernetes.

OPCIONES

--all

Seleccionar todos los recursos en el namespace actual.

--dry-run

No ejecutar la operación; solo mostrar lo que se haría.

--field-selector <string>

Selector de campos, ofertas de filtros con los valores de campos específicos.

--for=<resource>

Recurso para el que se debe añadir la etiqueta. Debe estar en singular, con guiones o con snake_case.

--from=<path>

El archivo JSON o YAML desde el que obtener el nombre y la etiqueta del objeto.

-o, --output <string>

Formato de salida. Una de: json|yaml|wide|name|custom-columns=...|custom-columns-file=...|go-template=...|go-template-file=...|jsonpath=...|jsonpath-file=....

--record

Grabar el comando actual en la anotación de historial de un objeto.

-R, --recursive

Procesar recursivamente los directorios que contienen archivos.

--selector <string>

Selector de etiquetas para filtrar objetos por etiquetas. Solo se seleccionarán etiquetas que coincidan con el selector.

--show-labels

Mostrar etiquetas junto con otro texto de salida.

-f, --filename <string>

Nombre del archivo, directorio o URL que contiene los recursos a etiquetar.

--windows-fields-selector <string>

Selector de campos de Windows, ofertas de filtros con los valores de campos específicos.

OPCIONES HEREDADAS DE COMANDOS PADRE

--cache-dir "<rootDir>"

Guardar los archivos de caché en el directorio especificado.

--client-certificate <filepath>

El certificado de cliente TLS que se utilizará en la autenticación para el servidor API.

--client-key <filepath>

La clave privada TLS que se utilizará en la autenticación para el servidor API.

--cluster <string>

Nombre del clúster al que dirigirse.

--context <string>

El nombre del contexto del clúster a utilizar.

--insecure-skip-tls-verify

Falseca la verificación de la identidad del servidor. Si es falso, la verificación TLS fallará si la identidad del servidor no coincide con el nombre del servidor o si no se proporciona un certificado de CA de confianza.

-n, --namespace <string>

Si se especifica, el namespace para el ámbito de las operaciones.

--request-timeout <duration>

La caducidad de las solicitudes al servidor de la API (por ejemplo, 5m, 1h)., predeterminado: 0 (sin tiempo de espera).

--server <string>

El URL de descubrimiento de la API del servidor para conectarse a.

--tls-server-name <string>

Si se establece, el nombre del servidor que se utilizará para la verificación del certificado del servidor en lugar del nombre de host del servidor API.

--token <token>

El token de autenticación de la API que se utilizará.

--user <string>

El nombre del usuario a utilizar para la autenticación para el servidor API.

--username <string>

El nombre de usuario a utilizar para la autenticación básica.

EJEMPLO

Asigna la etiqueta `mylabel=mivalue` al pod `mypod`.

kubectl label pod mypod mylabel=mivalue

Añade la etiqueta `environment=production` a todos los pods en el namespace actual.

kubectl label pods --all environment=production

Elimina la etiqueta `mylabel` del pod `mypod`.

kubectl label pod mypod mylabel-

Actualiza la etiqueta `mylabel` del pod `mypod` a `newvalue`.

kubectl label pod mypod mylabel=newvalue --overwrite

Asigna etiquetas de un archivo a los pods.

kubectl label -f labels.txt pods
