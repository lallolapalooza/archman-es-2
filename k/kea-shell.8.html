NOMBRE

kea-shell - Cliente de texto para el proceso del Agente de Control

SINOPSIS

kea-shell [-h] [-v] [--host] [--port] [--path] [--ca] [--cert] [--key] [--auth-user] [--auth-password] [--auth-password-file] [--timeout] [--service] [comando]

DESCRIPCIÓN

El programa kea-shell proporciona un cliente REST para los servidores Kea kea-dhcp4, kea-dhcp6 y kea-dhcp-ddns. Anteriormente estaba destinado al demonio del Agente de Control (CA), el cual está obsoleto. Toma comandos como un parámetro de línea de comandos que se envía al servidor Kea con la encapsulación JSON adecuada. Los argumentos opcionales se pueden especificar en la entrada estándar. La solicitud se envía a través de HTTP y se recupera una respuesta, que se muestra en la salida estándar. Se admite autenticación HTTP básica y HTTPS, es decir, transporte TLS.

ARGUMENTOS

Los argumentos son los siguientes:

-h
Muestra ayuda sobre los parámetros de la línea de comandos.
-v
Muestra la versión de Kea.
--host
Especifica el host al que conectarse. El servidor Kea debe estar en ejecución en el host especificado. Si no se especifica, se usa 127.0.0.1.
--port
Especifica el puerto TCP al que conectarse. El servidor debe estar escuchando en el puerto especificado. Si no se especifica, se usa 8000.
--path
Especifica la ruta en la URL a la que conectarse. Si no se especifica, se usa una ruta vacía. Como los servidores Kea escuchan en la ruta vacía, este parámetro solo es útil con un proxy inverso.
--ca
Especifica el nombre del archivo o directorio de la Autoridad Certificadora. Si no se especifica, no se usa HTTPS.
--cert
Especifica el nombre del archivo del certificado de clave pública del punto final del usuario. Si se especifica, también se debe especificar el nombre del archivo de la clave del usuario.
--key
Especifica el nombre del archivo de clave del usuario. Si se especifica, también se debe especificar el nombre del archivo del certificado del usuario. Los archivos de clave cifrados no son compatibles.
--auth-user
Especifica el ID de usuario para la autenticación HTTP básica. Si no se especifica, o se especifica como una cadena vacía, no se utiliza autenticación.
--auth-password
Especifica la contraseña para la autenticación HTTP básica. Si no se especifica pero se especifica el ID de usuario, se utiliza una contraseña vacía. Si se usa junto con --auth-password-file, se ignora.
--auth-password-file
Especifica un archivo de texto cuya primera línea contiene la contraseña a utilizar para la autenticación HTTP básica. Esta opción tiene prioridad sobre la opción --auth-password.
--timeout
Especifica el tiempo de espera de conexión, en segundos. El valor por defecto es 10.
--service
(Obsoleto) Los servidores Kea kea-dhcp4, kea-dhcp6 y kea-dhcp-ddns ignoran este argumento. Estaba destinado a la comunicación con el demonio obsoleto Agente de Control. Si se usa con la versión de Kea < 2.7.2: especifica el servicio que es el objetivo de un comando. Si no se especifica, el propio Agente de Control es el objetivo. Puede usarse varias veces para especificar múltiples objetivos.
comando
Especifica el comando a enviar al servidor. Si no se especifica, se usa list-commands.

DOCUMENTACIÓN

Kea viene con un extenso Manual de Referencia del Administrador de Kea que cubre todos los aspectos de la ejecución del software Kea: compilación, instalación, configuración, ejemplos de configuración y mucho más. Kea también presenta un Manual de Mensajes de Kea, que enumera todos los mensajes posibles que Kea puede imprimir con una breve descripción para cada uno de ellos. Ambos documentos están disponibles en varios formatos (.txt, .html, .pdf) con la distribución de Kea. La documentación de Kea está disponible en https://kea.readthedocs.io.

El código fuente de Kea está documentado en la Guía del Desarrollador de Kea, disponible en https://reports.kea.isc.org/dev_guide/.

El sitio web del proyecto Kea está disponible en https://kea.isc.org.

LISTAS DE DISTRIBUCIÓN Y SOPORTE

Hay dos listas de distribución públicas disponibles para el proyecto Kea. kea-users (kea-users at lists.isc.org) está destinada a los usuarios de Kea, mientras que kea-dev (kea-dev at lists.isc.org) está destinada a los desarrolladores de Kea, posibles contribuidores y otros usuarios avanzados. Ambas listas están disponibles en https://lists.isc.org. La comunidad proporciona soporte de mejor esfuerzo en ambas listas.

ISC proporciona soporte profesional para servicios Kea. Consulte https://www.isc.org/kea/ para obtener detalles.

HISTORIA

El programa kea-shell fue codificado por primera vez en marzo de 2017 por Tomek Mrugalski.
