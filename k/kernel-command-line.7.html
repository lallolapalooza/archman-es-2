systemd.

volatile=
Este parámetro controla si el sistema debe arrancar en modo volátil. Acepta un argumento booleano, o los valores especiales "state" o "overlay". Si es falso (el valor por defecto), se selecciona el modo de arranque normal, el directorio raíz y /var/ se montan como se especifica en la línea de comandos del kernel o en /etc/fstab, o se configuran de otra manera. Si es verdadero, se selecciona el modo de arranque completamente sin estado (state-less). En este caso, el directorio raíz se monta como sistema de archivos de memoria volátil ("tmpfs"), y solo /usr/ se monta desde el sistema de archivos configurado como dispositivo raíz, en modo de solo lectura. Esto permite arranques completamente sin estado donde el sistema operativo suministrado por el fabricante se usa tal como se distribuye, con solo la configuración por defecto y sin estado almacenado en efecto, ya que /etc/ y /var/ (así como todos los demás recursos distribuidos en el sistema de archivos raíz) se reinician en el arranque y se pierden al apagarse. Si esta configuración se establece en "state" el sistema de archivos raíz se monta de solo lectura, sin embargo /var/ se monta como un sistema de archivos de memoria volátil ("tmpfs"), de modo que el sistema arranca con la configuración normal aplicada, pero todo el estado se reinicia en el arranque y se pierde al apagarse. Si esta configuración se establece en "overlay" el sistema de archivos raíz se configura como un montaje "overlayfs" que combina el directorio raíz de solo lectura con un "tmpfs" escribible, de modo que no se realizan modificaciones en el disco, pero el sistema de archivos puede ser modificado de todos modos, con todos los cambios perdidos al reiniciar. Para más detalles, consulte systemd-volatile-root.service(8) y systemd-fstab-generator(8).

systemd.

random_seed=
Acepta un valor de semilla aleatoria codificado en base64 para acreditar con entropía completa al pool aleatorio del kernel durante la inicialización temprana del gestor de servicios. Esta opción es útil en entornos de prueba donde se desean evitar los retrasos debidos a la inicialización del pool aleatorio en máquinas virtuales con escasez de entropía.

Tenga en cuenta que si se usa esta opción la semilla es accesible para programas no privilegiados desde /proc/cmdline. Esta opción es por lo tanto un riesgo de seguridad cuando se usa fuera de sistemas de prueba, ya que la semilla (posiblemente) única usada para la inicialización del pool de entropía del kernel podría ser adquirida fácilmente por programas no

privilegiados.

Se recomienda pasar 512 bytes de datos aleatorios (ya que eso coincide con el tamaño del pool del kernel de Linux), que pueden generarse con un comando como el

siguiente: 
dd if=/dev/urandom b
s=512 count=1 statu
s=none | base64 -w 0

De nuevo: no use esta opción fuera de entornos de prueba, es un riesgo de seguridad en otros lugares, ya que el material de clave secreta derivado del pool de entropía puede ser posiblemente reconstruido por programas no

privilegiados.
