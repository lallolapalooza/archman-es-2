NOMBRE

kubeadm init phase control-plane all - Generar todos los archivos de manifiesto de Pods estáticos

SINOPSIS

kubeadm init phase control-plane all [OPCIONES]

DESCRIPCIÓN

Generar todos los archivos de manifiesto de Pods estáticos

OPCIONES

--apiserver-advertise-address="" La dirección IP en la que el Servidor API anunciará que está escuchando. Si no se establece, se utilizará la interfaz de red por defecto.

--apiserver-bind-port=6443 Puerto al que se enlazará el Servidor API.

--apiserver-extra-args= Un conjunto de flags adicionales para pasar al Servidor API o para anular los predeterminados en formato =

--cert-dir="/etc/kubernetes/pki" La ruta donde se guardarán y almacenarán los certificados.

--config="" Ruta a un archivo de configuración de kubeadm.

--control-plane-endpoint="" Especificar una dirección IP estable o un nombre DNS para el plano de control.

--controller-manager-extra-args= Un conjunto de flags adicionales para pasar al Gestor de Controladores o para anular los predeterminados en formato =

--dry-run=false No aplicar ningún cambio; solo mostrar lo que se haría.

--feature-gates="" Un conjunto de pares clave=valor que describen las puertas de características para varias funcionalidades. Las opciones son: ControlPlaneKubeletLocalMode=true|false (BETA - por defecto=true) NodeLocalCRISocket=true|false (BETA - por defecto=true) PublicKeysECDSA=true|false (OBSOLETO - por defecto=false) RootlessControlPlane=true|false (ALFA - por defecto=false) WaitForAllControlPlaneComponents=true|false (por defecto=true)

--image-repository="registry.k8s.io" Elegir un registro de contenedores para descargar las imágenes del plano de control.

--kubernetes-version="stable-1" Elegir una versión específica de Kubernetes para el plano de control.

--patches="" Ruta a un directorio que contiene archivos llamados "target[suffix][+patchtype].extension". Por ejemplo, "kube-apiserver0+merge.yaml" o simplemente "etcd.json". "target" puede ser uno de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" puede ser uno de "strategic", "merge" o "json" y coinciden con los formatos de parche admitidos por kubectl. El "patchtype" predeterminado es "strategic". "extension" debe ser "json" o "yaml". "suffix" es una cadena opcional que puede usarse para determinar qué parches se aplican primero alfanuméricamente.

--pod-network-cidr="" Especificar el rango de direcciones IP para la red de pods. Si se establece, el plano de control asignará automáticamente CIDRs para cada nodo.

--scheduler-extra-args= Un conjunto de flags adicionales para pasar al Planificador o para anular los predeterminados en formato =

--service-cidr="10.96.0.0/12" Utilizar un rango alternativo de direcciones IP para los VIP de servicio.

OPCIONES HEREDADAS DE COMANDOS PADRE

--rootfs="" La ruta al sistema de archivos raíz 'real' del host. Esto hará que kubeadm cambie la raíz al path proporcionado.

--version=false --version, --version=raw imprime la información de la versión y sale; --version=vX.Y.Z... establece la versión reportada

EJEMPLO

  # Genera todos los archivos de manifiesto de Pods estáticos para los componentes del plano de control,
  # funcionalmente equivalente a lo que genera kubeadm init.
  kubeadm init phase control-plane all
  # Genera todos los archivos de manifiesto de Pods estáticos utilizando opciones leídas de un archivo de configuración.
  kubeadm init phase control-plane all --config config.yaml
