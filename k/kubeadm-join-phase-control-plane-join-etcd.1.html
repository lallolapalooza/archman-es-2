NOMBRE

kubeadm join phase control-plane-join etcd - Añadir un nuevo miembro etcd local

SINOPSIS

kubeadm join phase control-plane-join etcd [OPCIONES]

DESCRIPCIÓN

Añadir un nuevo miembro etcd local

OPCIONES

--apiserver-advertise-address="" Si el nodo debe alojar una nueva instancia del plano de control, la dirección IP que el servidor de la API anunciará que está escuchando. Si no se establece, se utilizará la interfaz de red predeterminada.

--config="" Ruta a un archivo de configuración de kubeadm.

--control-plane=false Crear una nueva instancia del plano de control en este nodo

--dry-run=false No aplicar ningún cambio; solo mostrar lo que se haría.

--node-name="" Especificar el nombre del nodo.

--patches="" Ruta a un directorio que contiene archivos con nombres como "target[suffix][+patchtype].extension". Por ejemplo, "kube-apiserver0+merge.yaml" o solo "etcd.json". "target" puede ser uno de "kube-apiserver", "kube-controller-manager", "kube-scheduler", "etcd", "kubeletconfiguration", "corednsdeployment". "patchtype" puede ser uno de "strategic", "merge" o "json" y coinciden con los formatos de parche compatibles con kubectl. El "patchtype" predeterminado es "strategic". "extension" debe ser "json" o "yaml". "suffix" es una cadena opcional que se puede utilizar para determinar qué parches se aplican primero alfanuméricamente.

OPCIONES HEREDADAS DE COMANDOS PADRE

--rootfs="" La ruta al sistema de archivos raíz 'real' del host. Esto hará que kubeadm use chroot en la ruta proporcionada.

--version=false --version, --version=raw imprime la información de la versión y sale; --version=vX.Y.Z... establece la versión reportada
