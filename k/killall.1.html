N

killall envía una señal a todos los procesos que ejecutan cualquiera de los comandos especificados. Si no se especifica un nombre de señal, se envía

SIGTERM.

Las señales pueden especificarse por nombre (por ejemplo, -HUP o -SIGHUP) o por número (por ejemplo, -1) o mediante la opción -s

.

Si el nombre del comando no es una expresión regular (opción -r) y contiene una barra (/), se seleccionarán para terminar los procesos que ejecutan ese archivo en particular, independientemente de su

nombre.

killall devuelve un código de retorno cero si al menos un proceso ha sido terminado para cada comando listado, o si no se listaron comandos y al menos un proceso coincide con los criterios de búsqueda -u y -Z. killall devuelve un valor distinto de cero en caso

contrario.

Un proceso killall nunca se termina a sí mismo (pero puede terminar a otros procesos

ERRORES

CONOCIDOS

Terminar por archivo solo funciona para ejecutables que se mantienen abiertos durante la ejecución, es decir, los ejecutables impuros no pueden terminarse de esta

manera.

Advertencia: escribir killall nombre puede no tener el efecto deseado en sistemas que no sean Linux, especialmente cuando lo hace un usuario con

privilegios.

killall -w no detecta si un proceso desaparece y es reemplazado por un nuevo proceso con el mismo PID entre

escaneos.

Si los procesos cambian su nombre, killall puede no ser capaz de hacer coincidirlos

correctamente.

killall tiene un límite de nombres que se pueden especificar en la línea de comando. Esta cifra es el tamaño de un entero sin signo multiplicado

por 8. Para la mayoría de los sistemas de 32 bits el límite es 32 y de
manera similar para un sistema de 64 bits el límite es usualmente 64.

    NAME

    killall - kill processes by name

    SYNOPSIS

    killall [-s] [-o] [-u] [-v] [-I] [-i] [-q] [-w] [-Z] [-SIGNAL] [PATTERN]...

    DESCRIPTION

    killall sends a signal to processes specified by PATTERN. The pattern can be a command name, a user name, or a process ID. If multiple patterns are given, then a process must match at least one of them.

    By default, killall sends the SIGTERM signal. Otherwise, the signal to be sent is specified with the option -SIGNAL.

    OPTIONS

    -s SIGNAL

    Specify the signal to be sent. SIGNAL can be a signal number or name (e.g. -9 or -KILL).

    -o

    Only kill processes owned by the calling user.

    -u USER

    Only kill processes owned by USER.

    -v

    Verify that the specified signal was sent.

    -I

    Ignore case when matching process names.

    -i

    Interactive mode. Ask for confirmation before killing each process.

    -q

    Quiet mode. Do not report errors if no processes were killed.

    -w

    Wait for processes to die. This option is only useful when killing processes by name, as killall will continue to send the signal until it is sure that all matching processes have died.

    -Z

    Kill processes by their SELinux security context.

    FILES

    /proc

    Process information file system.

    KNOWN BUGS

    killall kills processes by name. This can be dangerous if there are multiple processes with the same name and you only want to kill one of them. For example, if you have two instances of firefox running and you want to kill only one, killall firefox will kill both.

    SEE ALSO

    kill(1), pkill(1), pgrep(1)

    NOMBRE

    killall - matar procesos por nombre

    SINOPSIS

    killall [-s] [-o] [-u] [-v] [-I] [-i] [-q] [-w] [-Z] [-SIGNAL] [PATRÓN]...

    DESCRIPCIÓN

    killall envía una señal a los procesos especificados por PATRÓN. El patrón puede ser un nombre de comando, un nombre de usuario o un ID de proceso. Si se proporcionan múltiples patrones, entonces un proceso debe coincidir con al menos uno de ellos.

    Por defecto, killall envía la señal SIGTERM. De lo contrario, la señal a enviar se especifica con la opción -SIGNAL.

    OPCIONES

    -s SIGNAL

    Especifica la señal a enviar. SIGNAL puede ser un número de señal o un nombre (por ejemplo, -9 o -KILL).

    -o

    Solo matar procesos propiedad del usuario que llama.

    -u USUARIO

    Solo matar procesos propiedad de USUARIO.

    -v

    Verificar que se envió la señal especificada.

    -I

    Ignorar mayúsculas y minúsculas al comparar nombres de procesos.

    -i

    Modo interactivo. Preguntar por confirmación antes de matar cada proceso.

    -q

    Modo silencioso. No informar errores si no se mataron procesos.

    -w

    Esperar a que los procesos mueran. Esta opción solo es útil cuando se matan procesos por nombre, ya que killall continuará enviando la señal hasta que esté seguro de que todos los procesos coincidentes han muerto.

    -Z

    Matar procesos por su contexto de seguridad SELinux.

    ARCHIVOS

    /proc

    Sistema de archivos de información de procesos.

    ERRORES CONOCIDOS

    killall mata procesos por nombre. Esto puede ser peligroso si hay múltiples procesos con el mismo nombre y solo quieres matar uno de ellos. Por ejemplo, si tienes dos instancias de firefox en ejecución y quieres matar solo una, killall firefox matará a ambas.

    kill(1), pkill(1), pgrep(1)
