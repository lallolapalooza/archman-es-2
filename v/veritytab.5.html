VERITYTAB(5) veritytab VERITYTAB(5)

NOMBRE

veritytab - Configuración de dispositivos de bloque verity

SINOPSIS

/etc/veritytab

DESCRIPCIÓN

El archivo /etc/veritytab describe los dispositivos de bloque protegidos por verity que se configuran durante el arranque del sistema.

Las líneas vacías y las líneas que comienzan con el carácter "#" se ignoran. Cada una de las líneas restantes describe un dispositivo de bloque protegido por verity. Los campos están delimitados por espacios en blanco.

Cada línea tiene el formato:

nombre-volumen dispositivo-datos dispositivo-hash hash-raíz [opciones]

Los cuatro primeros campos son obligatorios, el último es opcional.

El primer campo contiene el nombre del volumen verity resultante; su dispositivo de bloque se configura en /dev/mapper/.

El segundo campo contiene una ruta al dispositivo de datos de bloque subyacente, o una especificación de un dispositivo de bloque mediante UUID= seguido del UUID.

El tercer campo contiene una ruta al dispositivo de hash de bloque subyacente, o una especificación de un dispositivo de bloque mediante UUID= seguido del UUID.

El cuarto campo es el hash-raíz en hexadecimal. Si este campo se especifica como un guión, se intenta leer el hash raíz de la propiedad udev "ID_DISSECT_PART_ROOTHASH=" (codificado en hexadecimal) del dispositivo de datos.

El quinto campo, si está presente, es una lista de opciones separadas por comas. Se reconocen las siguientes opciones:

superblock=BOOL

Utiliza dm-verity con o sin superbloque permanente en disco.

Añadido en la versión 254.

format=NÚMERO

Especifica el tipo de versión del hash. El tipo de formato "0" es la versión original de Chrome OS. El tipo de formato "1" es la versión moderna.

Añadido en la versión 254.

data-block-size=BYTES

Tamaño de bloque utilizado para el dispositivo de datos. (Nota: el kernel solo admite el tamaño de página como máximo aquí; múltiplos de 512 bytes.)

Añadido en la versión 254.

hash-block-size=BYTES

Tamaño de bloque utilizado para el dispositivo de hash. (Nota: el kernel solo admite el tamaño de página como máximo aquí; múltiplos de 512 bytes.)

Añadido en la versión 254.

data-blocks=BLOQUES

Número de bloques del dispositivo de datos utilizados en la verificación. Si no se especifica, se utiliza todo el dispositivo.

Añadido en la versión 254.

hash-offset=BYTES

Desplazamiento del área de hash/superbloque en "dispositivo-hash". (Múltiplos de 512 bytes.)

Añadido en la versión 254.

salt=HEX

Sal utilizada para el formato o la verificación. El formato es una cadena hexadecimal; máximo 256 bytes de longitud; "-" es el valor especial para vacío.

Añadido en la versión 254.

uuid=UUID

Utiliza el UUID proporcionado en lugar de generar uno nuevo. El UUID debe proporcionarse en formato UUID estándar, por ejemplo, "12345678-1234-1234-1234-123456789abc".

Añadido en la versión 254.

ignore-corruption, restart-on-corruption, panic-on-corruption

Define qué hacer si se detecta un problema de veracidad de datos (corrupción de datos). Sin estas opciones, el kernel falla la operación de E/S con error de E/S. Con la opción --ignore-corruption, la corrupción solo se registra. Con --restart-on-corruption o --panic-on-corruption, el kernel se reinicia (entra en pánico) inmediatamente. (Debes proporcionar una forma de evitar los bucles de reinicio.)

Añadido en la versión 248.

ignore-zero-blocks

Instruye al kernel para que no verifique los bloques que se espera que contengan ceros y que siempre devuelva directamente ceros en su lugar.

Advertencia
Utiliza esta opción solo en casos muy específicos. Esta opción está disponible desde la versión 4.5 del kernel de Linux.
Añadido en la versión 248.

check-at-most-once

Instruye al kernel para que verifique los bloques solo la primera vez que se leen del dispositivo de datos, en lugar de cada vez.

Advertencia
Proporciona un nivel reducido de seguridad porque solo se detectarán las modificaciones fuera de línea del contenido del dispositivo de datos, no las modificaciones en línea. Esta opción está disponible desde la versión 4.17 del kernel de Linux.
Añadido en la versión 248.

hash=HASH

Algoritmo de hash para dm-verity. Debe ser el nombre del algoritmo, como "sha1". Para el valor predeterminado, consulta veritysetup --help.

Añadido en la versión 254.

fec-device=RUTA

Utiliza corrección de errores hacia adelante (FEC) para recuperarse de la corrupción si falla la verificación del hash. Utiliza datos de codificación del dispositivo especificado. El argumento del dispositivo fec puede ser un dispositivo de bloque o una imagen de archivo. Si la ruta del dispositivo fec no existe, se creará como un archivo. Nota: los tamaños de bloque para los dispositivos de datos y hash deben coincidir. Además, si el dispositivo de datos verity está cifrado, el dispositivo fec también debería estarlo.

Añadido en la versión 254.

fec-offset=BYTES

Este es el desplazamiento, en bytes, desde el inicio del dispositivo FEC hasta el principio de los datos de codificación. (Alineado en 512 bytes).

Añadido en la versión 254.

fec-roots=NUM

Número de raíces generadoras. Esto es igual al número de bytes de paridad en los datos de codificación. En la codificación RS(M, N), el número de raíces es M-N. M es 255 y M-N está entre 2 y 24 (inclusive).

Añadido en la versión 254.

root-hash-signature=RUTA|base64:BASE64|auto

Una cadena Base64 que codifica la firma del hash raíz precedida por "base64:", o una ruta absoluta a un archivo de firma del hash raíz utilizado para verificar el hash raíz (en el kernel). Si se especifica la cadena especial "auto", se intenta leer la firma del hash raíz de la propiedad udev "ID_DISSECT_PART_ROOTHASH_SIG=" (en formato Base64) del dispositivo de datos. Esta función requiere una versión del kernel de Linux 5.4 o posterior.

Añadido en la versión 248.

_netdev

Marca este dispositivo veritysetup como que requiere red. Se iniciará después de que la red esté disponible, de forma similar a las unidades de systemd.mount(5) marcadas con _netdev. La unidad de servicio para configurar este dispositivo se ordenará entre remote-fs-pre.target y remote-veritysetup.target, en lugar de veritysetup-pre.target y veritysetup.target.

Sugerencia: si este dispositivo se utiliza para un punto de montaje que se especifica en fstab(5), la opción _netdev también debe utilizarse para el punto de montaje. De lo contrario, podría crearse un bucle de dependencia en el que el punto de montaje será activado por local-fs.target, mientras que el servicio para configurar la red normalmente solo se inicia *después* de que el sistema de archivos local se haya montado.

Añadido en la versión 248.

noauto

Este dispositivo no se añadirá a veritysetup.target. Esto significa que no se habilitará automáticamente al arrancar, a menos que algo más lo active. En particular, si el dispositivo se utiliza para un punto de montaje, se habilitará automáticamente durante el arranque, a menos que el punto de montaje en sí también se deshabilite con noauto.

Añadido en la versión 248.

nofail

Este dispositivo no será una dependencia estricta de veritysetup.target. Aún así se activará y se iniciará, pero el sistema no esperará a que el dispositivo aparezca y se habilite, y el arranque no fallará si esto no tiene éxito. Ten en cuenta que otras unidades que dependen del dispositivo habilitado aún pueden fallar. En particular, si el dispositivo se utiliza para un punto de montaje, el punto de montaje en sí también debe tener la opción nofail, o el arranque fallará si el dispositivo no se habilita correctamente.

Añadido en la versión 248.

x-initrd.attach

Configura este dispositivo de bloque protegido por verity en el initrd, de forma similar a las unidades de systemd.mount(5) marcadas con x-initrd.mount.

Aunque no es necesario marcar la entrada de montaje del sistema de archivos raíz con x-initrd.mount, todavía se recomienda x-initrd.attach con el dispositivo de bloque protegido por verity que contiene el sistema de archivos raíz, ya que de lo contrario systemd intentará desvincular el dispositivo durante el apagado regular del sistema mientras está

NAME

veritytab — Verity device table

SYNOPSIS

/etc/veritytab

DESCRIPTION

The /etc/veritytab file is used to configure Verity protected block devices. It is a simple table format, similar to fstab(5). This file is intended to be used primarily by the early boot process and during system manager configuration reloads.

Each line in the file describes a single Verity device and is expected to contain five fields, separated by whitespace:

device
The block device node that the Verity mapping should be created on. This may be an absolute path like /dev/dm-0 or a device node name like veritysetup-0.
source
The path to the raw block device containing the data. This may be a device node like /dev/sda1, a partition UUID like UUID=..., or a PARTUUID like PARTUUID=....
hash
The path to the raw block device containing the hash tree. This may be a device node like /dev/sdb1, a UUID like UUID=..., or a PARTUUID like PARTUUID=....
uuid
The device UUID of the Verity protected data. This is required for most Verity operations and is usually obtained from the Verity protected device itself.
options
A comma-separated list of Verity options. The following options are supported:

auto

The device is set up automatically during early boot or when system manager configuration is reloaded. If this option is specified, systemd-veritysetup-generator(8) will create a corresponding systemd-veritysetup@.service(8) instance.

lazy-image

When this option is used, the Verity device is set up, but the specified device is not immediately opened. The device will only be opened when it is first accessed. This is useful for devices that are not always available, or that should be detached later.

deferred-detach

When this option is used, the Verity device will be detached later after the root file system is unmounted. This option should be used for all Verity protected block devices that contain file systems mounted in the initrd.

Added in version 248.

At early boot and when the system manager configuration is reloaded, this file is translated into native systemd units by systemd-veritysetup-generator(8).
