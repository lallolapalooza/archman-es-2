NOMBRE

vacuumdb - limpiar y analizar una base de datos de PostgreSQL

SINOPSIS

vacuumdb [opción-conexión...] [opción...] [ -t | --table tabla [( columna [,...] )] ]... [basedatos | -a | --all]

vacuumdb [opción-conexión...] [opción...] [ -n | --schema esquema ]... [basedatos | -a | --all]

vacuumdb [opción-conexión...] [opción...] [ -N | --exclude-schema esquema ]... [basedatos | -a | --all]

DESCRIPCIÓN

vacuumdb es una utilidad para limpiar una base de datos de PostgreSQL. vacuumdb también generará estadísticas internas utilizadas por el optimizador de consultas de PostgreSQL.

vacuumdb es un script de envoltura (wrapper) del comando SQL VACUUM. No hay una diferencia efectiva entre limpiar y analizar bases de datos a través de esta utilidad y otros métodos de acceso al servidor.

OPCIONES

vacuumdb acepta los siguientes argumentos de línea de comandos:

-a
--all

Limpia todas las bases de datos.

--buffer-usage-limit tamaño

Especifica el tamaño del búfer del anillo de la Estrategia de Acceso a Búferes para una invocación dada de vacuumdb. Este tamaño se utiliza para calcular el número de búferes compartidos que se reutilizarán como parte de esta estrategia. Consulte VACUUM(7).

[-d] basedatos
[--dbname=]basedatos

Especifica el nombre de la base de datos a limpiar o analizar, cuando -a/--all no se usa. Si no se especifica, el nombre de la base de datos se lee de la variable de entorno PGDATABASE. Si esta no está configurada, se utiliza el nombre de usuario especificado para la conexión. El parámetro basedatos puede ser una cadena de conexión. Si es así, los parámetros de la cadena de conexión anularán cualquier opción conflictiva de la línea de comandos.

--disable-page-skipping

Desactiva el salto de páginas basado en el contenido del mapa de visibilidad.

-e
--echo

Muestra los comandos que vacuumdb genera y envía al servidor.

-f
--full

Realiza una limpieza "completa".

-F
--freeze

"Congela" agresivamente las tuplas.

--force-index-cleanup

Siempre elimina las entradas de índice que apuntan a tuplas muertas.

-j njobs
--jobs=njobs

Ejecuta los comandos de vacuum o analyze en paralelo ejecutando njobs comandos simultáneamente. Esta opción puede reducir el tiempo de procesamiento pero también aumenta la carga en el servidor de base de datos.

vacuumdb abrirá njobs conexiones a la base de datos, así que asegúrese de que su configuración de max_connections sea lo suficientemente alta para acomodar todas las conexiones.

Tenga en cuenta que el uso de este modo junto con la opción -f (FULL) podría causar fallos de interbloqueo si ciertos catálogos del sistema se procesan en paralelo.

--min-mxid-age edad_mxid

Solo ejecuta los comandos de vacuum o analyze en tablas con una edad de ID multixact de al menos edad_mxid. Esta configuración es útil para priorizar tablas a procesar para prevenir el desbordamiento del ID multixact (ver Sección 24.1.5.1).

Para los propósitos de esta opción, la edad del ID multixact de una relación es la mayor de las edades de la relación principal y su tabla TOAST asociada, si existe. Dado que los comandos emitidos por vacuumdb también procesarán la tabla TOAST para la relación si es necesario, no es necesario considerarla por separado.

--min-xid-age edad_xid

Solo ejecuta los comandos de vacuum o analyze en tablas con una edad de ID de transacción de al menos edad_xid. Esta configuración es útil para priorizar tablas a procesar para prevenir el desbordamiento del ID de transacción (ver Sección 24.1.5).

Para los propósitos de esta opción, la edad del ID de transacción de una relación es la mayor de las edades de la relación principal y su tabla TOAST asociada, si existe. Dado que los comandos emitidos por vacuumdb también procesarán la tabla TOAST para la relación si es necesario, no es necesario considerarla por separado.

--missing-stats-only

Solo analiza relaciones a las que les faltan estadísticas para una columna, expresión de índice u objeto de estadísticas extendidas. Cuando se usa con --analyze-in-stages, esta opción evita que vacuumdb reemplace temporalmente las estadísticas existentes con otras generadas con objetivos de estadísticas más bajos, evitando así elecciones transitoriamente peores del optimizador de consultas.

Esta opción solo se puede usar junto con --analyze-only o --analyze-in-stages.

Tenga en cuenta que --missing-stats-only requiere privilegios SELECT sobre pg_statistic y pg_statistic_ext_data, que están restringidos a superusuarios por defecto.

-n esquema
--schema=esquema

Limpia o analiza solo todas las tablas en esquema. Se pueden limpiar múltiples esquemas escribiendo múltiples interruptores -n.

-N esquema
--exclude-schema=esquema

No limpie ni analice ninguna tabla en esquema. Se pueden excluir múltiples esquemas escribiendo múltiples interruptores -N.

--no-index-cleanup

No elimine las entradas de índice que apuntan a tuplas muertas.

--no-process-main

Omite la relación principal.

--no-process-toast

Omite la tabla TOAST asociada con la tabla a limpiar, si la hay.

--no-truncate

No trunca las páginas vacías al final de la tabla.

-P trabajadores_paralelos
--parallel=trabajadores_paralelos

Especifica el número de trabajadores paralelos para el vacuum paralelo. Esto permite que el vacuum aproveche múltiples CPUs para procesar índices. Consulte VACUUM(7).

-q
--quiet

No muestre mensajes de progreso.

--skip-locked

Omite las relaciones que no se pueden bloquear inmediatamente para su procesamiento.

-t tabla [ (columna [,...]) ]
--table=tabla [ (columna [,...]) ]

Limpia o analiza solo tabla. Los nombres de columna solo se pueden especificar junto con las opciones --analyze o --analyze-only. Se pueden limpiar múltiples tablas escribiendo múltiples interruptores -t.

Consejo
Si especifica columnas, probablemente tenga que escapar los paréntesis del shell. (Ver ejemplos a continuación).

-v
--verbose

Imprima información detallada durante el procesamiento.

-V
--version

Imprima la versión de vacuumdb y salga.

-z
--analyze

También calcule estadísticas para uso del optimizador.

-Z
--analyze-only

Solo calcule estadísticas para uso del optimizador (sin vacuum).

--analyze-in-stages

Solo calcule estadísticas para uso del optimizador (sin vacuum), al igual que --analyze-only. Ejecuta tres etapas de análisis; la primera etapa usa el objetivo de estadísticas más bajo posible (ver default_statistics_target) para producir estadísticas utilizables más rápido, y las etapas subsiguientes construyen las estadísticas completas.

Esta opción solo es útil para analizar una base de datos que actualmente no tiene estadísticas o tiene estadísticas completamente incorrectas, como si se poblara recientemente desde un volcado restaurado o por pg_upgrade. Tenga en cuenta que ejecutar con esta opción en una base de datos con estadísticas existentes puede hacer que el optimizador de consultas c

-?
--help

Mostrar ayuda sobre los argumentos de línea de comandos de vacuumdb y salir.

vacuumdb también acepta los siguientes argumentos de línea de comandos para parámetros de conexión:

-h host
--host=host

Especifica el nombre del host de la máquina en la que se está ejecutando el servidor. Si el valor comienza con una barra, se utiliza como el directorio para el socket de dominio Unix.

-p port
--port=port

Especifica el puerto TCP o la extensión del archivo de socket de dominio Unix local en el que el servidor está escuchando las conexiones.

-U username
--username=username

Nombre de usuario con el que conectar.

-w
--no-password

Nunca solicitar una contraseña. Si el servidor requiere autenticación de contraseña y no se dispone de una contraseña por otros medios, como un archivo .pgpass, el intento de conexión fallará. Esta opción puede ser útil en trabajos por lotes y scripts donde no hay ningún usuario presente para introducir una contraseña.

-W
--password

Obliga a vacuumdb a solicitar una contraseña antes de conectarse a una base de datos.

Esta opción nunca es esencial, ya que vacuumdb solicitará automáticamente una contraseña si el servidor la requiere. Sin embargo, vacuumdb desperdiciará un intento de conexión al descubrir que el servidor necesita una contraseña. En algunos casos, vale la pena escribir -W para evitar el intento de conexión adicional.

--maintenance-db=dbname

Cuando se utiliza -a/--all, se conecta a esta base de datos para recopilar la lista de bases de datos a vaciar. Si no se especifica, se utilizará la base de datos postgres, o si esta no existe, se utilizará template1. Puede ser una cadena de conexión. Si es así, los parámetros de la cadena de conexión anularán cualquier opción de línea de comandos en conflicto. Además, los parámetros de la cadena de conexión distintos del nombre de la base de datos en sí se reutilizarán al conectarse a otras bases de datos.

ENTORNO

PGDATABASE
PGHOST
PGPORT
PGUSER

Parámetros de conexión predeterminados

PG_COLOR

Especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son siempre, auto y nunca.

Esta utilidad, como la mayoría de las otras utilidades de PostgreSQL, también utiliza las variables de entorno admitidas por libpq (ver Sección 32.15).

DIAGNÓSTICO

En caso de dificultad, consulte VACUUM(7) y psql(1) para discutir posibles problemas y mensajes de error. El servidor de bases de datos debe estar ejecutándose en el host de destino. Además, se aplicarán todas las configuraciones de conexión predeterminadas y las variables de entorno utilizadas por la biblioteca de front-end libpq.

EJEMPLOS

Para limpiar la base de datos test:

$ vacuumdb test

Para limpiar y analizar para el optimizador una base de datos llamada bigdb:

$ vacuumdb --analyze bigdb

Para limpiar una sola tabla foo en una base de datos llamada xyzzy, y analizar una sola columna bar de la tabla para el optimizador:

$ vacuumdb --analyze --verbose --table='foo(bar)' xyzzy

Para limpiar todas las tablas en los esquemas foo y bar en una base de datos llamada xyzzy:

$ vacuumdb --schema='foo' --schema='bar' xyzzy
