vsock(7) Miscellaneous Information Manual vsock(7)

NOMBRE

vsock - Familia de direcciones VSOCK de Linux

SINOPSIS

#include <sys/socket.h>
#include <linux/vm_sockets.h>
socket_stream = socket(AF_VSOCK, SOCK_STREAM, 0);
socket_datagrama = socket(AF_VSOCK, SOCK_DGRAM, 0);

DESCRIPCIÓN

La familia de direcciones VSOCK facilita la comunicación entre máquinas virtuales y el host en el que se están ejecutando. Esta familia de direcciones es utilizada por agentes invitados y servicios de hipervisor que necesitan un canal de comunicación independiente de la configuración de red de la máquina virtual.

Los tipos de socket válidos son SOCK_STREAM y SOCK_DGRAM. SOCK_STREAM proporciona flujos de bytes orientados a conexión con entrega garantizada y en orden. SOCK_DGRAM proporciona un servicio de paquetes datagrama sin conexión con entrega y ordenación de mejor esfuerzo. La disponibilidad de estos tipos de socket depende del hipervisor subyacente.

Se crea un nuevo socket con


socket(AF_VSOCK, tipo_socket, 0);

Cuando un proceso quiere establecer una conexión, llama a connect(2) con una dirección de socket de destino dada. El socket se enlaza automáticamente a un puerto libre si no está enlazado.

Un proceso puede escuchar conexiones entrantes enlazándose primero a una dirección de socket usando bind(2) y luego llamando a listen(2).

Los datos se transmiten usando las familias de llamadas al sistema send(2) o write(2) y se reciben usando las familias de llamadas al sistema recv(2) o read(2).

Formato de dirección

Una dirección de socket se define como una combinación de un Identificador de Contexto (CID) de 32 bits y un número de puerto de 32 bits. El CID identifica la fuente o el destino, que es una máquina virtual o el host. El número de puerto diferencia entre múltiples servicios que se ejecutan en una sola máquina.


struct sockaddr_vm {
    sa_family_t    svm_family;    /* Familia de direcciones: AF_VSOCK */
    unsigned short svm_reserved1;
    unsigned int   svm_port;      /* Número de puerto en orden de bytes del host */
    unsigned int   svm_cid;       /* Dirección en orden de bytes del host */
    unsigned char  svm_zero[sizeof(struct sockaddr) -
                            sizeof(sa_family_t) -
                            sizeof(unsigned short) -
                            sizeof(unsigned int) -
                            sizeof(unsigned int)];
};

svm_family siempre se establece en AF_VSOCK. svm_reserved1 siempre se establece en 0. svm_port contiene el número de puerto en orden de bytes del host. Los números de puerto inferiores a 1024 se denominan puertos privilegiados. Solo un proceso con la capacidad CAP_NET_BIND_SERVICE puede bind(2) a estos números de puerto. svm_zero debe rellenarse con ceros.

Existen varias direcciones especiales: VMADDR_CID_ANY (-1U) significa cualquier dirección para enlazar; VMADDR_CID_HYPERVISOR (0) está reservado para servicios integrados en el hipervisor; VMADDR_CID_LOCAL (1) es la dirección conocida para la comunicación local (loopback); VMADDR_CID_HOST (2) es la dirección conocida del host.

La constante especial VMADDR_PORT_ANY (-1U) significa cualquier número de puerto para enlazar.

Migración en vivo

Los sockets se ven afectados por la migración en vivo de las máquinas virtuales. Los sockets SOCK_STREAM conectados se desconectan cuando la máquina virtual migra a un nuevo host. Las aplicaciones deben reconectarse cuando esto ocurra.

El CID local puede cambiar tras la migración en vivo si el CID antiguo no está disponible en el nuevo host. Los sockets enlazados se actualizan automáticamente al nuevo CID.

Ioctls

Los siguientes ioctls están disponibles en el dispositivo /dev/vsock.

IOCTL_VM_SOCKETS_GET_LOCAL_CID
Obtiene el CID de la máquina local. El argumento es un puntero a un unsigned int.

ioctl(fd, IOCTL_VM_SOCKETS_GET_LOCAL_CID, &cid);

Considere usar VMADDR_CID_ANY al enlazar en lugar de obtener el CID local con IOCTL_VM_SOCKETS_GET_LOCAL_CID.

Comunicación local

VMADDR_CID_LOCAL (1) dirige los paquetes al mismo host que los generó. Esto es útil para probar aplicaciones en un solo host y para la depuración.

El CID local obtenido con IOCTL_VM_SOCKETS_GET_LOCAL_CID puede usarse para el mismo propósito, pero es preferible usar VMADDR_CID_LOCAL.

ERRORES

EACCES
No se pudo enlazar a un puerto privilegiado sin la capacidad CAP_NET_BIND_SERVICE.
EADDRINUSE
No se pudo enlazar a un puerto que ya está en uso.
EADDRNOTAVAIL
No se pudo encontrar un puerto libre para enlazar o no se pudo enlazar a un CID no local.
EINVAL
Parámetros inválidos. Esto incluye: intentar enlazar un socket que ya está enlazado, proporcionar una estructura sockaddr_vm inválida y otros errores de validación de entrada.
ENOPROTOOPT
Opción de socket inválida en setsockopt(2) o getsockopt(2).
ENOTCONN
No se pudo realizar la operación en un socket no conectado.
EOPNOTSUPP
Operación no soportada. Esto incluye: la bandera MSG_OOB que no se implementa para la familia de llamadas al sistema send(2) y MSG_PEEK para la familia de llamadas al sistema recv(2).
EPROTONOSUPPORT
Número de protocolo de socket inválido. El protocolo siempre debe ser 0.
ESOCKTNOSUPPORT
Tipo de socket no soportado en socket(2). Solo SOCK_STREAM y SOCK_DGRAM son válidos.

VERSIÓNES

El soporte para VMware (VMCI) ha estado disponible desde Linux 3.9. KVM (virtio) es compatible desde Linux 4.8. Hyper-V es compatible desde Linux 4.14.

VMADDR_CID_LOCAL es compatible desde Linux 5.6. La comunicación local en el invitado y en el host está disponible desde Linux 5.6. Las versiones anteriores solo soportaban comunicación local dentro de un invitado (no en el host), y con solo algunos transportes (VMCI y virtio).
