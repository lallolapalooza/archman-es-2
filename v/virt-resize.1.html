NAME

virt-resize - Redimensionar un disco de máquina virtual

SYNOPSIS

virt-resize [--resize /dev/sdaN=[+/-]<size>[%]]
  [--expand /dev/sdaN] [--shrink /dev/sdaN]
  [--ignore /dev/sdaN] [--delete /dev/sdaN] [...] disco_entrada disco_salida

DESCRIPTION

Virt-resize es una herramienta que puede redimensionar un disco de máquina virtual, haciéndolo más grande o más pequeño en general, y redimensionando o eliminando cualquier partición contenida en él.

Virt-resize no puede redimensionar imágenes de disco in situ. Virt-resize no debe usarse en máquinas virtuales en vivo; para obtener resultados consistentes, apague la máquina virtual antes de redimensionarla.

Si no está familiarizado con las herramientas asociadas: virt-filesystems(1) y virt-df(1), le recomendamos que lea esas páginas del manual primero.

EJEMPLOS

1.
Este ejemplo toma "discoantiguo" y lo redimensiona a "disconuevo", extendiendo una de las particiones del invitado para que ocupe los 5 GB adicionales de espacio: 
virt-filesystems --long -h --all -a discoantiguo

truncate -r discoantiguo disconuevo
truncate -s +5G disconuevo

# Nota: "/dev/sda2" es una partición dentro del archivo "discoantiguo".
virt-resize --expand /dev/sda2 discoantiguo disconuevo
2.
Igual que el anterior, pero haciendo que la partición /boot sea 200 MB más grande, mientras se da el espacio restante a /dev/sda2: 
virt-resize --resize /dev/sda1=+200M --expand /dev/sda2 \
  discoantiguo disconuevo
3.
Como en el primer ejemplo, pero expandiendo un volumen lógico como paso final. Esto es lo que normalmente usaría para invitados de Linux que usan LVM: 
virt-resize --expand /dev/sda2 --LV-expand /dev/vg_guest/lv_root \
  discoantiguo disconuevo
4.
Como en el primer ejemplo, pero el formato de salida será qcow2 en lugar de un disco raw: 
qemu-img create -f qcow2 -o preallocation=metadata disconuevo.qcow2 15G
virt-resize --expand /dev/sda2 discoantiguo disconuevo.qcow2

USO DETALLADO

EXPANDIENDO UN DISCO DE MÁQUINA VIRTUAL

1. Apague la máquina virtual
2. Localice la imagen del disco de entrada
Localice la imagen del disco de entrada (es decir, el archivo o dispositivo en el host que contiene el disco del invitado). Si el invitado es gestionado por libvirt, puede usar "virsh dumpxml" de la siguiente manera para encontrar el nombre de la imagen del disco: 
# virsh dumpxml nombre_invitado | xpath -e /domain/devices/disk/source
Found 1 nodes:
-- NODE --
<source dev="/dev/vg/lv_guest" />
3. Observe el tamaño actual
Use virt-filesystems(1) para mostrar las particiones y tamaños actuales: 
# virt-filesystems --long --parts --blkdevs -h -a /dev/vg/lv_guest
Name       Type       Size  Parent
/dev/sda1  partition  101M  /dev/sda
/dev/sda2  partition  7.9G  /dev/sda
/dev/sda   device     8.0G  -

(Este ejemplo es una máquina virtual con un disco de 8 GB que nos gustaría expandir a 10 GB).

4. Cree el disco de salida
Virt-resize no puede realizar modificaciones de disco in situ. Debe tener espacio para almacenar el disco de salida redimensionado.

Para almacenar la imagen del disco redimensionado en un archivo, cree un archivo de un tamaño adecuado:

# rm -f disco_salida
# truncate -s 10G disco_salida

O use lvcreate(1) para crear un volumen lógico:

# lvcreate -L 10G -n nombre_lv vg_name

O use virsh(1) vol-create-as para crear un volumen de almacenamiento de libvirt:

# virsh pool-list
# virsh vol-create-as nombre_pool nuevovolumen 10G
5. Redimensione
virt-resize toma dos parámetros obligatorios, el disco de entrada y el disco de salida (ambos pueden ser, por ejemplo, un dispositivo, un archivo o una URI a un disco remoto). El disco de salida es el creado en el paso anterior. 
# virt-resize disco_entrada disco_salida

Este comando simplemente copia la imagen de disco "disco_entrada" a la imagen de disco "disco_salida" sin redimensionar ni cambiar ninguna partición existente. Si "disco_salida" es más grande, se crea una partición adicional vacía al final del disco que cubre el espacio extra. Si "disco_salida" es más pequeño, dará un error.

Más realistamente, querrá expandir las particiones existentes en la imagen del disco pasando opciones adicionales (para la lista completa, consulte la sección "OPCIONES" a continuación).

"--expand" es la opción más útil. Expande la partición nombrada dentro del disco para llenar cualquier espacio adicional:

# virt-resize --expand /dev/sda2 disco_entrada disco_salida

(En este caso, no se crea una partición adicional al final del disco, porque no habrá espacio sin usar).

"--resize" es la otra opción comúnmente utilizada. Lo siguiente aumentaría el tamaño de /dev/sda1 en 200M y expandiría /dev/sda2 para llenar el resto del espacio disponible:

# virt-resize --resize /dev/sda1=+200M --expand /dev/sda2 \
    disco_entrada disco_salida

Si la partición expandida en la imagen contiene un sistema de archivos o un PV de LVM, entonces si virt-resize sabe cómo, redimensionará los contenidos, lo equivalente a llamar a un comando como pvresize(8), resize2fs(8), ntfsresize(8), btrfs(8), xfs_growfs(8), o resize.f2fs(8). Sin embargo, virt-resize no sabe cómo redimensionar algunos sistemas de archivos, por lo que tendría que redimensionarlos en línea después de arrancar el invitado.

# virt-resize --expand /dev/sda2 nbd://ejemplo.com disco_salida

El disco de entrada puede ser una URI, para usar un disco remoto como fuente. El formato de URI es compatible con guestfish. Consulte "AÑADIR ALMACENAMIENTO REMOTO" en guestfish(1).

Otras opciones se cubren a continuación.

6. Probar
Pruebe a fondo la nueva imagen de disco antes de descartar la antigua.

Si está utilizando libvirt, edite el XML para que apunte al nuevo disco:

# virsh edit nombre_invitado

Cambie <source ...>, vea http://libvirt.org/formatdomain.html#elementsDisks

Luego inicie el dominio con el nuevo disco redimensionado:

# virsh start nombre_invitado

y compruebe que todavía funciona. Consulte también la sección "NOTAS" a continuación para obtener información adicional.

7. Redimensionar LVs, etc. dentro del invitado
(Esto también se puede hacer sin conexión usando guestfish(1))

Una vez que el invitado haya arrancado, debería ver el nuevo espacio disponible, al menos para los sistemas de archivos que virt-resize sabe cómo redimensionar, y para los PVs. El usuario puede necesitar redimensionar los LVs dentro de los PVs, y también redimensionar los tipos de sistemas de archivos que virt-resize no sabe cómo expandir.

REDUCIENDO UN DISCO DE MÁQUINA VIRTUAL

Reducir es algo más complejo que expandir, y aquí solo se da una visión general.

En primer lugar, virt-resize no intentará reducir ningún contenido de partición (PVs, sistemas de archivos). El usuario tiene que reducir el contenido antes de pasar la imagen del disco a virt-resize, y virt-resize comprobará que el contenido se ha reducido correctamente.

(La reducción también se puede hacer sin conexión usando guestfish(1))

Después de reducir los PVs y sistemas de archivos, apague el invitado y proceda con los pasos 3 y 4 anteriores para asignar una nueva imagen de disco.

Luego ejecute virt-resize con cualquiera de las opciones --shrink y/o --resize.

DESCRIPTION

The virt-resize command resizes a virtual machine disk image.

It creates a new disk image and copies the partitions and filesystems from the old disk image to the new one. During this process, it can resize, move, delete and create partitions.

The command copies partitions from the source disk image to the destination disk image. If you want the destination disk to be smaller than the source disk, you must specify which partitions to delete or omit using the --delete or --ignore options.

If you want the destination disk to be larger than the source disk, then after all partitions have been copied, any remaining space is left unpartitioned at the end of the disk. You can optionally use the --expand option to make one of the partitions use up this spare space.

If you want to change the size of a partition, you must specify which partition and the new size. Note that partitions can only be grown if the target disk image is larger than the source disk image.

If you are shrinking a partition, you must ensure that the partition contains enough free space for the data to fit. If not, then the operation will fail.

You can use virt-filesystems(1) to list the partitions and filesystems within a disk image. You can use virt-image(1) to create the empty destination disk image.

The command can optionally copy the boot loader from the source disk image to the destination disk image. This is usually desired, but can be turned off with --no-copy-boot-loader.

Resizing partitions can be a dangerous operation. Always make a backup of your original disk image before attempting to resize it.

The command tries to be smart about boot loaders, but sometimes it fails. You may need to reinstall the boot loader (e.g. GRUB) after resizing the disk.

For Windows guests, virt-resize can resize the partition and the NTFS filesystem within it. For Linux guests, virt-resize can resize ext2, ext3, ext4, btrfs, xfs, f2fs, and swap partitions.

The operation is performed by creating a temporary disk image, copying the partitions and filesystems into it, and then renaming the temporary image to the final destination name. This minimizes the risk of data corruption if the operation is interrupted.

The operation only works on disk images that do not contain logical partitions, or on disk images where the logical partitions are not being resized.

PARTITION OPERATIONS

When resizing partitions, virt-resize must choose where to place the partitions on the new disk. By default, it places them contiguously at the beginning of the disk. This can lead to poor performance if the disk is an SSD or a network block device, as these often perform best when partitions are aligned on sector boundaries.

The --alignment option allows you to specify an alignment boundary. For example, --alignment 8 aligns partitions on 4K boundaries (assuming 512-byte sectors).

The --align-first option controls whether the first partition is aligned. auto (the default) tries to align it only if it's safe to do so (e.g., for Windows guests where the bootloader can be fixed automatically). never never aligns the first partition, which is the safest option. always always aligns the first partition, which may break the bootloader.

Creating a partition copies the contents of the source partition to the destination partition. Deleting a partition removes it completely, but note that it also renumbers any partitions after the one which is deleted, which can leave some guests unbootable.

QCOW2 AND NON-SPARSE RAW FORMATS

If the input disk is in qcow2 format, then you may prefer that the output is in qcow2 format as well. Alternately, virt-resize can convert the format on the fly. The output format is simply determined by the format of the empty output container that you provide. Thus to create qcow2 output, use:

qemu-img create -f qcow2 -o preallocation=metadata outdisk [size]

instead of the truncate command.

Similarly, to get non-sparse raw output use:

fallocate -l size outdisk

(on older systems that don’t have the fallocate(1) command use "dd if=/dev/zero of=outdisk bs=1M count=..")

LOGICAL PARTITIONS

Logical partitions (a.k.a. /dev/sda5+ on disks using DOS partition tables) cannot be resized.

To understand what is going on, firstly one of the four partitions /dev/sda1-4 will have MBR partition type 05 or "0f". This is called the extended partition. Use virt-filesystems(1) to see the MBR partition type.

Logical partitions live inside the extended partition.

The extended partition can be expanded, but not shrunk (unless you force it, which is not advisable). When the extended partition is copied across, all the logical partitions contained inside are copied over implicitly. Virt-resize does not look inside the extended partition, so it copies the logical partitions blindly.

You cannot specify a logical partition (/dev/sda5+) at all on the command line. Doing so will give an error.

--align-first always
Align the first partition for improved performance (see also the --alignment option).

--expand PART
Expand the named partition so it uses up all extra space (space left over after any other resize changes that you request have been done).

If virt-resize knows how, it will expand the direct content of the partition. For example, if the partition is an LVM PV, it will expand the PV to fit (like calling pvresize(8)). Virt-resize leaves any other content it doesn't know about alone.

Currently virt-resize can resize:

  • ext2, ext3 and ext4 filesystems.
  • NTFS filesystems, if libguestfs was compiled with support for NTFS.

    The filesystem must have been shut down consistently last time it was used. Additionally, ntfsresize(8) marks the resized filesystem as requiring a consistency check, so at the first boot after resizing Windows will check the disk.

  • LVM PVs (physical volumes). virt-resize does not usually resize anything inside the PV, but see the --LV-expand option. The user could also resize LVs as desired after boot.
  • Btrfs filesystems, if libguestfs was compiled with support for btrfs.
  • XFS filesystems, if libguestfs was compiled with support for XFS.
  • Linux swap partitions.

    Please note that libguestfs destroys the existing swap content by recreating it with "mkswap", so this should not be used when the guest is suspended.

  • f2fs filesystems, if libguestfs was compiled with support for f2fs.

This would first expand the partition (and PV), and then expand the root device to fill the extra space in the PV.

You can give this option multiple times, but it doesn't make sense to do this unless the logical volumes you specify are all in different volume groups.

virt-resize(8)
virt-resize resize virtual machine disk images

virt-resize is a utility to resize virtual machine disk images. It supports several formats including qcow2, vmdk, vdi, and raw. It can also resize partitions and logical volumes within the disk image.

virt-resize works by creating a new disk image of the desired size and copying the contents of the old disk image to the new one. During the copy process, it can expand or shrink partitions and filesystems as specified by the user.

It uses libguestfs(3) and can perform operations on a running VM's disk image, provided the VM is suspended and the disk image is accessible.

virt-resize is part of the libguestfs suite.

--resize-force PART=SIZE
This is the same as --resize except that it will let you decrease the size of any partition. Generally this means you will lose any data which was at the end of the partition you shrink, but you may not care about that (eg. if shrinking an unused partition, or if you can easily recreate it such as a swap partition).

--shrink PART
Shrink the named partition until the overall disk image fits in the destination. The named partition must contain a filesystem or PV which has already been shrunk using another tool (eg. guestfish(1) or other online tools). Virt-resize will check this and give an error if it has not been done.

The amount by which the overall disk must be shrunk (after carrying out all other operations requested by the user) is called the "deficit". For example, a straight copy (assume no other operations) from a 5GB disk image to a 4GB disk image results in a 1GB deficit. In this case, virt-resize would give an error unless the user specified a partition to shrink and that partition had more than a gigabyte of free space.

Note that you cannot use --expand and --shrink together.

--unknown-filesystems warn (the default behaviour) will cause virt-resize to warn for each of the filesystem that cannot be expanded, but still continuing to resize the disk.

--unknown-filesystems error will cause virt-resize to error out at the first filesystem that cannot be expanded.

MACHINE READABLE OUTPUT

The --machine-readable option can be used to make the output more machine friendly, which is useful when calling virt-resize from other programs, GUIs etc.

There are two ways to use this option.

Firstly use the option on its own to query the capabilities of the virt-resize binary. Typical output looks like this:

$ virt-resize --machine-readable
virt-resize
ntfsresize-force
32bitok
ntfs
btrfs

A list of features is printed, one per line, and the program exits with status 0.

Secondly use the option in conjunction with other options to make the regular program output more machine friendly.

At the moment this means:

1.
Progress bar messages can be parsed from stdout by looking for this regular expression: 
^[0-9]+/[0-9]+$
2.
The calling program should treat messages sent to stdout (except for progress bar messages) as status messages. They can be logged and/or displayed to the user.
3.
The calling program should treat messages sent to stderr as error messages. In addition, virt-resize exits with a non-zero status code if there was a fatal error.

Versions of the program prior to 1.13.9 did not support the --machine-readable option and will return an error.

It is possible to specify a format string for controlling the output; see "ADVANCED MACHINE READABLE OUTPUT" in guestfs(3).

NOTES

"Partition 1 does not end on cylinder boundary."

Virt-resize aligns partitions to multiples of 128 sectors (see the --alignment parameter). Usually this means the partitions will not be aligned to the ancient CHS geometry. However CHS geometry is meaningless for disks manufactured since the early 1990s, and doubly so for virtual hard drives. Alignment of partitions to cylinders is not required by any modern operating system.

GUEST BOOT STUCK AT "GRUB"

If a Linux guest does not boot after resizing, and the boot is stuck after printing "GRUB" on the console, try reinstalling grub.

guestfish -i -a newdisk
><fs> cat /boot/grub/device.map
# check the contents of this file are sensible or
# edit the file if necessary
><fs> grub-install / /dev/vda
><fs> exit

For more flexible guest reconfiguration, including if you need to specify other parameters to grub-install, use virt-rescue(1).

RESIZING WINDOWS BOOT PARTITIONS

In Windows Vista and later versions, Microsoft switched to using a separate boot partition. In these VMs, typically /dev/sda1 is the boot partition and /dev/sda2 is the main (C:) drive. Resizing the first (boot) partition causes the bootloader to fail with 0xC0000225 error. Resizing the second partition (ie. C: drive) should work.

WINDOWS CHKDSK

Windows disks which use NTFS must be consistent before virt-resize can be used. If the ntfsresize operation fails, try booting the original VM and running "chkdsk /f" on all NTFS partitions, then shut down the VM cleanly. For further information see: https://bugzilla.redhat.com/show_bug.cgi?id=975753

After resize Windows may initiate a lengthy "chkdsk" on first boot if NTFS partitions have been expanded. This is just a safety check and (unless it find errors) is nothing to worry about.

NAME

virt-resize

resize a virtual machine disk image

SYNOPSIS

virt-resize [OPTION]... SOURCE DEST

virt-resize [OPTION]... SOURCE... --expand DEVICE

virt-resize [OPTION]... SOURCE... --expand-volume DEVICE

virt-resize [OPTION]... SOURCE... --shrink DEVICE

virt-resize [OPTION]... SOURCE... --shrink-volume DEVICE

virt-resize [OPTION]... SOURCE... --resize-volume DEVICE

DESCRIPTION

The virt-resize command resizes a virtual machine disk image. It can grow or shrink the disk image, or resize partitions and logical volumes within the disk image.

The command works by copying the source disk image to a new destination disk image, resizing it in the process. It also attempts to resize the filesystem(s) within the partitions on the disk image, if necessary. This is a complex operation and requires the guest operating system to be shut down.

The virt-resize command supports a wide range of disk image formats, including qcow2, raw, vmdk, and vdi. It can also resize host partitions and logical volumes.

EXAMPLES

virt-resize disk.img disk-resized.img --expand-volume sda

Expand the last partition on disk.img by extending the disk image to the maximum possible size, and then expanding the filesystem on the partition.

virt-resize disk.img disk-resized.img --expand-volume sda:1

Expand the first partition on disk.img to the maximum possible size.

virt-resize disk.img disk-resized.img --resize-volume sda:1=20G

Resize the first partition on disk.img to 20 gigabytes.

virt-resize disk.img disk-resized.img --shrink-volume sda:1

Shrink the first partition on disk.img to the minimum possible size.

virt-resize disk.img disk-resized.img --resize-volume sda=10G

Resize the entire disk image (not a partition) to 10 gigabytes.

virt-resize disk.img /dev/vg/lv --expand-volume sda

Resize a disk image and write the result to a logical volume.

DETAILED USAGE

The primary use of virt-resize is to grow or shrink a virtual disk image. This is done by specifying the source and destination disk images, and optionally one or more --expand, --shrink, --expand-volume, --shrink-volume, or --resize-volume options.

The --expand and --shrink options resize the entire disk image. The --expand-volume, --shrink-volume, and --resize-volume options resize specific partitions or logical volumes within the disk image.

Partitions and logical volumes are specified using the format DEVICE:PARTITION, where DEVICE is the name of the disk device (e.g., sda) and PARTITION is the partition number (e.g., 1). If the partition number is omitted, it applies to the entire disk device.

Filesystem resizing is automatic where possible. If virt-resize cannot automatically resize a filesystem, it will report an error. In some cases, you may need to manually resize the filesystem after resizing the partition.

OPTIONS

See virt-resize(1) for a full list of options.

MACHINE READABLE OUTPUT

Use the --machine-readable option to get output in a format suitable for scripting.

NOTES

WINDOWS XP AND SERVER 2003 SYSPREP

If you are resizing a Windows XP or Server 2003 guest which has been sysprepped, you may see the guest fail to boot with an "UNMOUNTABLE_BOOT_VOLUME" BSOD. This error is caused by having "ExtendOemPartition=1" in the sysprep.inf file. Removing this line before sysprepping should fix the problem.

WINDOWS 8

Windows 8 "fast startup" can prevent virt-resize from resizing NTFS partitions. See "WINDOWS HIBERNATION AND WINDOWS 8 FAST STARTUP" in guestfs(3).

SPARSE COPYING

You should create a fresh, zeroed target disk image for virt-resize to use.

Virt-resize by default performs sparse copying. This means that it does not copy blocks from the source disk which are all zeroes. This improves speed and efficiency, but will produce incorrect results if the target disk image contains unzeroed data.

The main time this can be a problem is if the target is a host partition (eg. "virt-resize source.img /dev/sda4") because the usual partitioning tools tend to leave whatever data happened to be on the disk before.

If you have to reuse a target which contains data already, you should use the --no-sparse option. Note this can be much slower.

"unknown/unavailable method for expanding the TYPE filesystem on DEVICE/LV"

Virt-resize was asked to expand a partition or a logical volume containing a filesystem with the type "TYPE", but there is no available nor known expanding method for that filesystem.

This may be due to either of the following:

1.
There corresponding filesystem is not available in libguestfs, because there is no proper package in the host with utilities for it. This is usually the case for "btrfs", "ntfs", "xfs", and "f2fs" filesystems.

Check the results of:

virt-resize --machine-readable
guestfish -a /dev/null run : available
guestfish -a /dev/null run : filesystem_available TYPE

In this case, it is enough to install the proper packages adding support for them. For example, "libguestfs-xfs" on Red Hat Enterprise Linux, CentOS, Debian, Ubuntu, and distributions derived from them, for supporting the "xfs" filesystem.

2.
Virt-resize has no support for expanding that type of filesystem.

In this case, there’s nothing that can be done to let virt-resize expand that type of filesystem.

In both cases, virt-resize will not expand the mentioned filesystem; the result (unless --unknown-filesystems error is specified) is that the partitions containing such filesystems will be actually bigger as requested, but the filesystems will still be usable at their older sizes.

ALTERNATIVE TOOLS

There are several proprietary tools for resizing partitions. We won't mention any here.

parted(8) and its graphical shell gparted can do some types of resizing operations on disk images. They can resize and move partitions, but I don't think they can do anything with the contents, and they certainly don't understand LVM.

guestfish(1) can do everything that virt-resize can do and a lot more, but at a much lower level. You will probably end up hand-calculating sector offsets, which is something that virt-resize was designed to avoid. If you want to see the guestfish-equivalent commands that virt-resize runs, use the --debug flag.

dracut(8) includes a module called "dracut-modules-growroot" which can be used to grow the root partition when the guest first boots up. There is documentation for this module in an associated README file.

EXIT STATUS

This program returns 0 if successful, or non-zero if there was an error.
