DESCRIPCIÓN

El objetivo de este VMOD es proporcionar a los usuarios de VCL y a los autores de VMOD los medios para probar casos límite o alcanzar ciertas condiciones con varnishtest.

VOID barrier_sync(STRING dir, DURATION tiempo_limite=0)

Al escribir casos de prueba, el patrón más común es iniciar una instancia de servidor simulado, una instancia de Varnish y arrancar un cliente simulado. Estas entidades se ejecutan asincrónicamente, y existen otras como procesos en segundo plano (process) o lectores de registros (logexpect). Si bien puedes sincronizarte con entidades individuales y esperar su finalización, debes usar una barrera si necesitas sincronizar dos o más entidades, o esperar hasta un punto determinado en lugar de la finalización.

No solo es posible sincronizar entre entidades de prueba, con la función barrier_sync incluso puedes sincronizar código VCL:

sub vcl_recv {
    # esperar a que una barrera b1 se complete
    vtc.barrier_sync("${b1_sock}");
}

Si la función falla al sincronizarse con la barrera por alguna razón, o si alcanza el tiempo límite opcional, falla la transacción VCL.

MISCELÁNEO

BACKEND no_backend()

Falla en la selección del backend.

STEVEDORE no_stevedore()

Falla en la selección del almacenamiento.

IP no_ip()

Devuelve una dirección IP nula, ni siquiera una bogo_ip.

VOID panic(STRING)

Puede ser útil bloquear el proceso hijo para probar la robustez de un VMOD.

VOID sleep(DURATION)

Bloquea el hilo trabajador actual.

ESPACIOS DE TRABAJO

Puede ser útil poner un espacio de trabajo en un estado determinado al probar casos límite como el agotamiento de recursos para una transacción, especialmente para el desarrollo de VMOD. Todas las funciones disponibles permiten elegir con qué espacio de trabajo necesitas manipular, los valores disponibles son client, backend, session y thread.

VOID workspace_alloc(ENUM, INT tamaño)

VOID workspace_alloc(
   ENUM {client, backend, session, thread},
   INT tamaño
)

Asigna y pone a cero memoria de un espacio de trabajo. Un tamaño negativo asignará tanto como sea necesario para dejar esa cantidad de bytes libres. El tamaño real de la asignación puede ser mayor para cumplir con los requisitos de alineación de memoria de la arquitectura de la CPU. Una asignación fallida falla la transacción.

BYTES workspace_reserve(ENUM, INT tamaño)

BYTES workspace_reserve(
   ENUM {client, backend, session, thread},
   INT tamaño
)

Intenta reservar tamaño bytes, pone esa memoria a cero y libera la reserva de inmediato. Devuelve el tamaño de la reserva.

Ver vtc.workspace_alloc() para la semántica del argumento tamaño.

INT workspace_free(ENUM {client, backend, session, thread})

Encuentra cuánta espacio sin asignar queda en un espacio de trabajo.

VOID workspace_snapshot(ENUM)

VOID workspace_snapshot(ENUM {client, backend, session, thread})

Captura una instantánea de un espacio de trabajo. Solo una instantánea puede estar activa a la vez y cada VCL puede guardar solo una instantánea, por lo que no se admiten tareas concurrentes que requieran instantáneas.

VOID workspace_reset(ENUM)

VOID workspace_reset(ENUM {client, backend, session, thread})

Restablece a la instantánea anterior de un espacio de trabajo, debe ser el mismo espacio de trabajo también.

BOOL workspace_overflowed(ENUM)

BOOL workspace_overflowed(ENUM {client, backend, session, thread})

Determina si la marca de desbordamiento del espacio de trabajo está activada o no.

VOID workspace_overflow(ENUM)

VOID workspace_overflow(ENUM {client, backend, session, thread})

Marca un espacio de trabajo como desbordado.

BLOB workspace_dump(ENUM, ENUM, BYTES off, BYTES len)

BLOB workspace_dump(
   ENUM {client, backend, session, thread},
   ENUM {s, f, r},
   BYTES off=0,
   BYTES len=64
)

Devuelve datos del puntero s, f o r de un espacio de trabajo como un blob. Los datos se copian en el espacio de trabajo principal para evitar que sean sobrescritos posteriormente.

La longitud máxima es de 1 KB.

INT typesize(STRING)

Devuelve el tamaño en bytes de una colección de tipos de datos C:

  • 'p': puntero
  • 'i': int
  • 'd': double
  • 'f': float
  • 'l': long
  • 's': short
  • 'z': size_t
  • 'o': off_t
  • 'j': intmax_t

Esto puede ser útil para los autores de VMOD en conjunto con las operaciones de espacio de trabajo.

BLOB proxy_header(ENUM version, IP cliente, IP servidor, STRING autoridad)

BLOB proxy_header(
   ENUM {v1, v2} version,
   IP cliente,
   IP servidor,
   STRING autoridad=0
)

Formatea una cabecera proxy de la versión dada v1 o v2 y direcciones (El tipo IP de VCL también contiene el número de puerto).

Opcionalmente, también envía un TLV de autoridad con la versión v2 (ignorado para la versión v1).

Candidato para mover a vmod_proxy, pero hubo preocupaciones sobre el diseño de la interfaz.

VSL

Estas funciones son útiles para registrar información en el registro de Varnish (VSL) o para interactuar con él:

VOID vsl(INT vxid, STRING tag, ENUM side, STRING s)

VOID vsl(INT vxid, STRING tag, ENUM {client, backend, sess, work}, STRING s)

Registra una línea en el registro de Varnish con un Varnish Transaction ID (vxid) dado, una etiqueta y el lado (client, backend, sess o work). La cadena s es el mensaje a registrar.

VOID vsl_replay(STRING s)

VOID vsl_replay(STRING s)

Reproduce una cadena (obtenida de una operación VSL previa, por ejemplo) como si fuera una entrada de registro de Varnish.

Páginas del manual de Arch Linux, traducidas por la comunidad.

VSL

Estas funciones permiten generar entradas de registro arbitrarias para probar la implementación de Varnish Shared Log (VSL) y lectores como varnishlog.

VOID vsl(INT vxid, STRING tag, ENUM {c, b} side, STRING s)

Llama a VSLs() con los parámetros dados.

El orden de los argumentos se elige para que coincida con la salida de VSL.

Se activa un error de VCL si la etiqueta (*tag*) no se puede resolver en tiempo de ejecución o si vxid está fuera de los límites.

VOID vsl_replay(STRING s)

Reproduce líneas de registro literales.

El analizador acepta la salida generada por varnishlog -g raw y las líneas vsl| del registro de varnishtest.

Las líneas no analizables se ignoran silenciosamente.
