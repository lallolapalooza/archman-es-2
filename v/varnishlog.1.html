NOMBRE

varnishlog - Muestra los registros de Varnish

SINOPSIS

varnishlog [-a] [-A] [-b] [-c] [-C] [-d] [-D] [-E] [-g <session|request|vxid|raw>] [-h] [-i <taglist>] [-I <[taglist:]regex>] [-k <num>] [-L <limit>] [-n <workdir>] [-P <file>] [-Q <file>] [-q <query>] [-r <filename>] [-R <limit[/duration]>] [-t <seconds|off>] [-T <seconds>] [-u] [-v] [-V] [-w <filename>] [-x <taglist>] [-X <[taglist:]regex>]

OPCIONES

Las siguientes opciones están disponibles:

-a
Al escribir la salida a un archivo con la opción -w, añada al final en lugar de sobrescribir. Esta opción no tiene efecto sin la opción -w.
-A
Al escribir la salida a un archivo con la opción -w, genere la salida en formato ASCII. Esta opción no tiene efecto sin la opción -w.
-b
Muestra solo transacciones y registros de log provenientes de la comunicación con el backend.
-c
Muestra solo transacciones y registros de log provenientes de la comunicación con el cliente.
-C
Ignora mayúsculas y minúsculas en todas las coincidencias de expresiones regulares y cadenas de texto.
-d
Procesa los registros de log al principio del log y sale.
-D
Ejecuta como demonio.
-E
Muestra transacciones ESI y otros tipos de sub-solicitudes. Esto implica la opción -c e incluye otras transacciones del cliente.
-g <session|request|vxid|raw>
La agrupación de los registros de log. El valor por defecto es agrupar por vxid.
-h
Muestra el uso del programa y sale.
-i <taglist>
Incluye registros de log de estas etiquetas en la salida. Taglist es una lista separada por comas de globs de etiquetas. Se pueden dar múltiples opciones -i.

Si una opción de inclusión de etiqueta es la primera de las opciones de selección de etiquetas, todas las etiquetas se marcan primero como excluidas.

-I <[taglist:]regex>
Incluye por coincidencia de expresión regular. Muestra solo registros que coinciden con taglist y expresión regular. Se aplica a cualquier etiqueta si taglist está ausente. Se pueden dar múltiples opciones -I.

Si una opción de inclusión de etiqueta es la primera de las opciones de selección de etiquetas, todas las etiquetas se marcan primero como excluidas.

-k <num>
Procesa este número de transacciones de log coincidentes antes de salir.
-L <limit>
Establece el límite superior de transacciones incompletas mantenidas antes de que la transacción más antigua se complete forzosamente. Se genera un registro de advertencia cuando esto sucede. Esta configuración mantiene un límite superior en el uso de memoria de las consultas en ejecución. El valor por defecto es 1000 transacciones.
-n <workdir>
Especifica el directorio de trabajo de Varnish de la instancia a la que conectarse. Consulte la documentación de la opción -n de varnishd(1) para obtener información adicional y valores por defecto.
-P <file>
Escribe el PID del proceso en el archivo especificado.
-Q <file>
Especifica el archivo que contiene la consulta VSL a utilizar. Cuando se especifican múltiples opciones -Q o -q, todas las consultas se consideran como si se usara el operador 'or' para combinarlas.
-q <query>
Especifica la consulta VSL a utilizar. Cuando se especifican múltiples opciones -q o -Q, todas las consultas se consideran como si se usara el operador 'or' para combinarlas.
-r <filename>
Lee el log en formato de archivo binario desde este archivo. El archivo puede ser creado con varnishlog -w filename. Si el nombre del archivo es -, los logs se leen desde la entrada estándar y no se puede ejecutar como demonio.
-R <limit[/duration]>
Restringe la salida al límite especificado. Se suprimirán las transacciones que excedan el límite. El límite se especifica como el número máximo de transacciones (con respecto al método de agrupación elegido) y un período de tiempo opcional. Si no se especifica duración, se usa un valor por defecto de s. El campo de duración se puede formatear como en VCL (por ejemplo, -R 10/2m) o como un simple período de tiempo sin el prefijo (por ejemplo, -R 5/m). Cuando está en modo de agrupación -g raw, esta configuración no se puede usar junto con -i, -I, -x o -X, y se recomienda usar -q en su lugar.
-t <seconds|off>
Tiempo de espera antes de devolver un error en la conexión VSM inicial. Si se establece, la conexión VSM se reintentará cada 0.5 segundos durante este número de segundos. Si es cero, la conexión se intentará solo una vez y fallará inmediatamente si no tiene éxito. Si se establece en "off", la conexión no fallará, permitiendo que la utilidad comience y espere indefinidamente a que aparezca la instancia de Varnish. El valor por defecto es 5 segundos.
-T <seconds>
Establece el tiempo de espera de la transacción en segundos. Esto define el número máximo de segundos transcurridos entre una etiqueta Begin y la etiqueta End. Si expira el tiempo de espera, se genera un registro de advertencia y la transacción se completa forzosamente. El valor por defecto es 120 segundos.
-u
Al escribir la salida a un archivo con la opción -w, la salida de datos no se almacena en búfer. Esta opción no tiene efecto sin la opción -w.
-v
Utiliza salida detallada en la impresión del conjunto de registros, proporcionando el VXID en cada línea de log. Sin esta opción, el VXID solo se proporcionará en la cabecera de esa transacción.
-V
Muestra la información de la versión y sale.
-w <filename>
Redirige la salida al archivo. El archivo será sobrescrito a menos que se haya especificado la opción -a. Si la aplicación recibe una SIGHUP en modo demonio, el archivo se reabrirá permitiendo que el antiguo sea rotado. El archivo puede ser leído por varnishlog y otras herramientas con la opción -r, a menos que se haya especificado la opción -A. Esta opción es obligatoria al ejecutarse en modo demonio. Si el nombre del archivo es -, varnishlog escribe en la salida estándar y no puede funcionar como demonio.
-x <taglist>
Excluye registros de log de estas etiquetas en la salida. Taglist es una lista separada por comas de globs de etiquetas. Se pueden dar múltiples opciones -x.
-X <[taglist:]regex>
Excluye por coincidencia de expresión regular. No muestres registros que coincidan con taglist y expresión regular. Se aplica a cualquier etiqueta si taglist está ausente. Se pueden dar múltiples opciones -X.
--optstring
Muestra la cadena de opciones (optstring) de getopt(3) para ayudar a escribir scripts de envoltura.

SEÑALES

  • SIGHUP

    Rota el archivo de log (ver opción -w) en modo demonio, aborta el bucle y muere elegantemente al ejecutarse en primer plano.

  • SIGUSR1

    Descarga cualquier transacción pendiente.
