virt-make-fs(1) Soporte de virtualización virt-make-fs(1)

NOMBRE

virt-make-fs - Crear un sistema de archivos a partir de un archivo tar o archivos

SINOPSIS

virt-make-fs [--opciones] input.tar salida.img
virt-make-fs [--opciones] input.tar.gz salida.img
virt-make-fs [--opciones] directorio salida.img

DESCRIPCIÓN

Virt-make-fs es una herramienta de línea de comandos para crear un sistema de archivos a partir de un archivo tar o de algunos archivos en un directorio. Es similar a herramientas como mkisofs(1), genisoimage(1) y mksquashfs(1). A diferencia de esas herramientas, puede crear tipos de sistemas de archivos comunes como ext2/3 o NTFS, lo que puede ser útil si desea adjuntar estos sistemas de archivos a máquinas virtuales existentes (por ejemplo, para importar grandes cantidades de datos de solo lectura a una VM).

Para crear discos en blanco, use virt-format(1). Para crear diseños complejos, use guestfish(1).

Uso básico:

virt-make-fs input salida.img

donde "input" es un directorio que contiene los archivos que desea agregar, o un archivo tar (ya sea tar sin comprimir o tar comprimido con gzip); y salida.img es una imagen de disco. El tipo de entrada se detecta automáticamente. La imagen de disco de salida por defecto es una imagen dispersa ext2 sin formato a menos que especifique opciones adicionales (consulte "OPCIONES" a continuación).

TIPO DE SISTEMA DE ARCHIVOS

El tipo de sistema de archivos predeterminado es "ext2". Casi cualquier tipo de sistema de archivos que libguestfs soporte puede ser utilizado (pero *no* formatos de solo lectura como ISO9660). Aquí hay algunas de las opciones más comunes:

ext3
Tenga en cuenta que los sistemas de archivos ext3 contienen un registro (journal), típicamente de 1-32 MB de tamaño. Si no va a usar el sistema de archivos de una manera que requiera el registro, entonces esto es solo una sobrecarga desperdiciada.
ntfs o vfat
Útil si exporta datos a una máquina virtual Windows.
minix
Menor sobrecarga que "ext2", pero con ciertas limitaciones en la longitud de los nombres de archivo y el tamaño total del sistema de archivos.

EJEMPLO

virt-make-fs --tipo=minix input minixfs.img

¿PARTICIONAR O NO PARTICIONAR?

Opcionalmente, virt-make-fs puede agregar una tabla de particiones al disco de salida.

Agregar una partición puede hacer que la imagen del disco sea más compatible con ciertos sistemas operativos virtualizados que no esperan ver un sistema de archivos directamente en un dispositivo de bloque (a Linux no le importa y manejará ambos tipos felizmente).

Por otro lado, si tiene una tabla de particiones, la imagen de salida ya no es un sistema de archivos directo. Por ejemplo, no puede ejecutar fsck(8) directamente en una imagen de disco particionada. (Sin embargo, las herramientas de libguestfs como guestfish(1) y virt-resize(1) todavía se pueden usar).

EJEMPLO

Agregar una partición MBR:

virt-make-fs --partición -- input disco.img

Si la imagen de disco de salida pudiera ser de terabytes o más grande, es mejor usar una tabla de particiones compatible con EFI/GPT:

virt-make-fs --partición=gpt --tamaño=+4T --formato=qcow2 input disco.img

ESPACIO EXTRA

A diferencia de formatos como tar y squashfs, un sistema de archivos no "cabe" solo los archivos que contiene, sino que puede tener espacio extra. Dependiendo de cómo vaya a usar la salida, puede pensar que este espacio extra está desperdiciado y querer minimizarlo, o puede querer dejar espacio para poder agregar más archivos más tarde. Virt-make-fs por defecto minimiza el espacio extra, pero puede usar la opción --tamaño para dejar espacio en el sistema de archivos si lo desea.

Una forma alternativa de dejar espacio extra pero sin hacer que la imagen de salida sea más grande es usar un formato de imagen de disco alternativo (en lugar del formato predeterminado "raw"). Usar --formato=qcow2 utilizará el formato de imagen qcow2 nativo de qemu/KVM (verifique que su hipervisor lo soporte antes de usarlo). Esto le permite elegir un --tamaño grande, pero el espacio extra no se asignará realmente en la imagen hasta que intente almacenar algo en él.

No olvide que también puede usar comandos locales, incluyendo resize2fs(8) y virt-resize(1) para cambiar el tamaño de sistemas de archivos existentes, o volver a ejecutar virt-make-fs para construir otra imagen desde cero.

EJEMPLO

virt-make-fs --formato=qcow2 --tamaño=+200M input salida.img

OPCIONES

--help
Mostrar ayuda breve.
--blocksize=512
--blocksize=4096
Este parámetro establece el tamaño del sector de la imagen de disco de salida.

El valor predeterminado es 512 bytes.

Consulte también "guestfs_add_drive_opts" en guestfs(3).

--floppy
Crear un disco flexible virtual.

Actualmente, esto preselecciona el tamaño (1440K), el tipo de partición (MBR) y el tipo de sistema de archivos (VFAT). En el futuro, también puede elegir la geometría.

--size=N
--size=+N
-s N
-s +N
Use la opción --tamaño (o -s) para elegir el tamaño de la imagen de salida.

Si esta opción *no* se proporciona, la imagen de salida será lo suficientemente grande como para contener todos los archivos, sin mucho espacio desperdiciado.

Para elegir un disco de salida de tamaño fijo, especifique un número absoluto seguido de b/K/M/G/T/P/E para significar bytes, Kilobytes, Megabytes, Gigabytes, Terabytes, Petabytes o Exabytes. Debe ser lo suficientemente grande como para contener todos los archivos de entrada, de lo contrario obtendrá un error.

Para dejar espacio adicional, especifique "+" (signo más) y un número seguido de b/K/M/G/T/P/E para significar bytes, Kilobytes, Megabytes, Gigabytes, Terabytes, Petabytes o Exabytes. Por ejemplo: --tamaño=+200M significa suficiente espacio para los archivos de entrada y (aproximadamente) 200 MB de espacio libre adicional.

Tenga en cuenta que virt-make-fs estima el espacio libre y, por lo tanto, no producirá sistemas de archivos que contengan precisamente el espacio libre solicitado. (Es mucho más costoso y consume más tiempo producir un sistema de archivos con el espacio libre deseado con precisión).

--format=FMT
-F FMT
Elegir el formato de imagen de disco de salida.

El valor predeterminado es "raw" (imagen de disco dispersa sin formato).

--type=FS
-t FS
Elegir el tipo de sistema de archivos de salida.

El valor predeterminado es "ext2".

Cualquier sistema de archivos que sea compatible de lectura/escritura con libguestfs se puede usar aquí.

--label=ETIQUETA
Establecer la etiqueta del sistema de archivos.
--partition
--partition=TIPO_PARTICION
Si se especifica, esta opción agrega una tabla de particiones MBR a la imagen de disco de salida.

Puede cambiar el tipo de tabla de particiones, por ejemplo, --partición=gpt para discos grandes.

Para MBR, virt-make-fs establece el byte del tipo de partición automáticamente.

-v
--verbos

Estas opciones son específicas de guestfs y se pasan directamente a la biblioteca guestfs. Si se proporciona, virt-make-fs se ejecutará en modo detallado.

ESTADO DE SALIDA

Devuelve 0 si la operación fue exitosa, o un código de error distinto de cero si falla.
