vwait(n)

Paquete: tcl

Licencias: TCL

vwait(n) Comandos integrados de Tcl vwait(n)

NOMBRE

vwait - Procesa eventos hasta que una variable es escrita

SINOPSIS

vwait nombreVar

DESCRIPCIÓN

Este comando entra en el bucle de eventos de Tcl para procesar eventos, bloqueando la aplicación si no hay eventos listos. Continúa procesando eventos hasta que algún manejador de eventos establece el valor de la variable global nombreVar. Una vez que se ha establecido nombreVar, el comando vwait regresará tan pronto como el manejador de eventos que modificó nombreVar se complete. El argumento nombreVar siempre se interpreta como un nombre de variable con respecto al espacio de nombres global, pero puede referirse a las variables de cualquier espacio de nombres si se proporciona el nombre completamente calificado.

En algunos casos, el comando vwait puede no regresar inmediatamente después de que se establezca nombreVar. Esto sucede si el manejador de eventos que establece nombreVar no se completa inmediatamente. Por ejemplo, si un manejador de eventos establece nombreVar y luego llama a vwait para esperar una variable diferente, es posible que no regrese por mucho tiempo. Durante este tiempo, el vwait de nivel superior está bloqueado esperando que el manejador de eventos se complete, por lo que tampoco puede regresar. (Ver los VWAIITS ANIDADOS POR EJEMPLO a continuación).

Para ser claros, múltiples llamadas a vwait se anidarán y no ocurrirán en paralelo. La llamada más externa a vwait no regresará hasta que todas las internas lo hagan. Se recomienda que el código nunca anide llamadas a vwait (evitando colocarlas en callbacks de eventos), pero cuando eso no sea posible, se debe tener cuidado de agregar variables de bloqueo al código para prevenir todas las llamadas reentrantes a vwait que no sean *estrictamente* necesarias. Tenga en cuenta que los modos de operación síncronos de algunos paquetes de Tcl (por ejemplo, http) utilizan vwait internamente; si se utiliza el bucle de eventos, es mejor utilizar los modos de operación asíncronos basados en callbacks de esos paquetes donde estén disponibles.

EJEMPLOS

Ejecuta el bucle de eventos continuamente hasta que algún evento llame a exit. (Puedes usar cualquier variable no mencionada en otro lugar, pero el nombre forever te recuerda la intención de un vistazo).

vwait forever

Espera cinco segundos para conectarse a un socket de servidor, de lo contrario, cierra el socket y continúa ejecutando el script:

# Inicializar el estado
after 5000 set state timeout
set server [socket -server accept 12345]
proc accept {args} {
    global state connectionInfo
    set state accepted
    set connectionInfo $args
}
# Esperar a que algo suceda
vwait state
# Limpiar eventos que podrían haber ocurrido
close $server
after cancel set state timeout
# Hacer algo basado en cómo terminó vwait...
switch $state {
    timeout {
        puts "no connection on port 12345"
    }
    accepted {
       puts "connection: $connectionInfo"
       puts [lindex $connectionInfo 0] "Hello there!"
    }
}

Un comando que esperará un cierto retraso esperando que se establezca una variable de espacio de nombres. Incluye un bloqueo para prevenir esperas anidadas.

namespace eval example {
    variable v done
    proc wait {delay} {
        variable v
        if {$v ne "waiting"} {
            set v waiting
            after $delay [namespace code {set v done}]
            vwait [namespace which -variable v]
        }
        return $v
    }
}

Al ejecutarse dentro de una coroutine, una alternativa a usar vwait es yield a un bucle de eventos externo y ser recomenzado cuando la variable se establece, o en un momento ocioso después de eso.

coroutine task apply {{} {
    # simular [after 1000]
    after 1000 [info coroutine]
    yield
    # programar el establecimiento de una variable global, como normal
    after 2000 {set var 1}
    # simular [vwait var]
    proc updatedVar {task args} {
        after idle $task
        trace remove variable ::var write "updatedVar $task"
    }
    trace add variable ::var write "updatedVar [info coroutine]"
    yield
}}

VWAIITS ANIDADOS POR EJEMPLO

Este ejemplo demuestra lo que puede suceder cuando el comando vwait está anidado. El script nunca terminará porque la espera de la variable a nunca termina; ese comando vwait todavía está esperando que se complete un script programado con after, que resulta estar ejecutando un vwait interno (para b) a pesar de que el evento que el vwait externo estaba esperando (el establecimiento de a) ha ocurrido.

after 500 {
    puts "esperando a b"
    vwait b
    puts "b fue establecido"
}
after 1000 {
    puts "estableciendo a"
    set a 10
}
puts "esperando a a"
vwait a
puts "a fue establecido"
puts "estableciendo b"
set b 42

Si ejecutas el código anterior, obtendrás esta salida:

esperando a a
esperando a b
estableciendo a

El script nunca imprimirá “a fue establecido” hasta después de haber impreso “b fue establecido” debido al anidamiento de los comandos vwait, y sin embargo b no se establecerá hasta después de que el vwait externo regrese, por lo que el script se ha bloqueado. Las únicas formas de evitar esto son estructurar el programa general en estilo de paso de continuación o usar coroutine para hacer que las continuaciones sean implícitas. La primera de estas opciones se escribiría así:

after 500 {
    puts "esperando a b"
    trace add variable b write {apply {args {
        global a b
        trace remove variable ::b write \
                [lrange [info level 0] 0 1]
        puts "b fue establecido"
        set ::done ok
    }}}
}
after 1000 {
    puts "estableciendo a"
    set a 10
}
puts "esperando a a"
trace add variable a write {apply {args {
    global a b
    trace remove variable a write [lrange [info level 0] 0 1]
    puts "a fue establecido"
    puts "estableciendo b"
    set b 42
}}}
vwait done

La segunda opción, con coroutine y algunos procedimientos auxiliares, se hace de esta manera:

# Un comando de espera de variable basado en coroutine
proc waitvar globalVar {
    trace add variable ::$globalVar write \
            [list apply {{v c args} {
        trace remove variable $v write \
                [lrange [info level 0] 0 3]
        after 0 $c
    }} ::$globalVar [info coroutine]]
    yield
}
# Un comando de espera de tiempo basado en coroutine
proc waittime ms {
    after $ms [info coroutine]
    yield
}
coroutine task-1 eval {
    puts "esperando a a"
    waitvar a
    puts "a fue establecido"
    puts "estableciendo b"
    set b 42
}
coroutine task-2 eval {
    waittime 500
    puts "esperando a b"
    waitvar b
    puts "b fue establecido"
    set done ok
}
coroutine task-3 eval {
    waittime 1000
    puts "estableciendo a"
    set a 10
}
vwait done
