V4L2-COMPLIANCE(1) Comandos de usuario V4L2-COMPLIANCE(1)

NOMBRE

v4l2-compliance - Una aplicación para probar drivers de video4linux

SINOPSIS

v4l2-compliance [-h] [-d <dev>] [otras opciones]

DESCRIPCIÓN

La herramienta v4l2-compliance se utiliza para probar dispositivos video4linux, ya sean de vídeo, vbi, radio o swradio, tanto de entrada como de salida. Intenta probar casi todos los aspectos de un dispositivo V4L2 y cubre casi todos los ioctls de V4L2. Tiene muy buen soporte para captura y salida de vídeo, captura y salida VBI y sintonización y transmisión de radio (software).

El soporte para dispositivos de memoria a memoria es limitado en este momento.

Si tiene preguntas sobre v4l2-compliance, envíelas a la lista de correo linux-media@vger.kernel.org.

Al probar un driver, compile siempre la utilidad a partir del último código fuente del repositorio git (http://git.linuxtv.org/cgit.cgi/v4l-utils.git/). La versión suministrada por las distribuciones de Linux es casi seguro demasiado antigua.

Además, si una prueba falla, mostrará el código fuente y la línea donde ocurrió la falla, por lo que a menudo necesitará acceso al código fuente para ver de qué se trata esa prueba.

Tenga en cuenta que v4l2-compliance no solo prueba la conformidad con la API de V4L2, sino también si el driver está utilizando todos los frameworks correctos. Estos frameworks a menudo proporcionan automáticamente ioctls que son estrictamente opcionales, pero que vienen gratis si se usan esos frameworks. Al exigir su presencia, la utilidad v4l2-compliance forzará su uso.

Si desea enviar un nuevo driver V4L2, ese driver debe pasar las pruebas de v4l2-compliance sin fallos. El mejor método para usar esta herramienta para probar su driver es primero probar sin ninguna opción de streaming y corregir cualquier falla, desde la primera falla reportada hasta la última. A veces, las fallas anteriores pueden generar fallas posteriores, así que simplemente comience a corregirlas en orden y pruebe nuevamente después de cada corrección.

A continuación, pruebe su driver con la opción -s para realizar las pruebas básicas de streaming. Esto requiere que haya una entrada o salida válida.

Cada vez que ejecute v4l2-compliance, guardará el estado actual del driver y lo restaurará después de que se realicen todas las pruebas (incluso cuando presione Ctrl-C). Todas las pruebas de streaming se realizan utilizando la configuración guardada. Esto hace posible preparar las pruebas de streaming configurando el dispositivo antes de llamar a v4l2-compliance.

Finalmente, debe probar su driver utilizando las opciones -f y -c para verificar que todos los formatos de píxeles de vídeo se soportan correctamente. Debe realizar las tres pruebas de streaming para todas las entradas y salidas. Puede usar la opción -a para automatizar eso si es posible para su hardware.

Si su driver pasa todas las pruebas, ¡entonces puede estar seguro de que su driver está en muy buena forma!

OPCIONES

-d, --device <dev>
Usa el dispositivo <dev> como dispositivo de vídeo. Si <dev> es un número, entonces se usa /dev/video<dev>. De lo contrario, si se especificó -z anteriormente, <dev> es el nombre de la entidad o ID de interfaz (si está prefijado con 0x) tal como se encuentra en la topología del dispositivo multimedia con la cadena de información del bus especificada por la opción -z.
-V, --vbi-device <dev>
Usa el dispositivo <dev> como dispositivo vbi. Si <dev> es un número, entonces se usa /dev/vbi<dev>. De lo contrario, si se especificó -z anteriormente, <dev> es el nombre de la entidad o ID de interfaz (si está prefijado con 0x) tal como se encuentra en la topología del dispositivo multimedia con la cadena de información del bus especificada por la opción -z.
-r, --radio-device <dev>
Usa el dispositivo <dev> como dispositivo de radio. Si <dev> es un número, entonces se usa /dev/radio<dev>. De lo contrario, si se especificó -z anteriormente, <dev> es el nombre de la entidad o ID de interfaz (si está prefijado con 0x) tal como se encuentra en la topología del dispositivo multimedia con la cadena de información del bus especificada por la opción -z.
-S, --sdr-device <dev>
Usa el dispositivo <dev> como dispositivo SDR. Si <dev> es un número, entonces se usa /dev/swradio<dev>. De lo contrario, si se especificó -z anteriormente, <dev> es el nombre de la entidad o ID de interfaz (si está prefijado con 0x) tal como se encuentra en la topología del dispositivo multimedia con la cadena de información del bus especificada por la opción -z.
-t, --touch-device <dev>
Usa el dispositivo <dev> como dispositivo táctil. Si <dev> es un número, entonces se usa /dev/v4l-touch<dev>. De lo contrario, si se especificó -z anteriormente, <dev> es el nombre de la entidad o ID de interfaz (si está prefijado con 0x) tal como se encuentra en la topología del dispositivo multimedia con la cadena de información del bus especificada por la opción -z.
-u, --subdev-device <dev>
Usa el dispositivo <dev> como dispositivo v4l-subdevX. Si <dev> es un número, entonces se usa /dev/v4l-subdev<dev>. De lo contrario, si se especificó -z anteriormente, <dev> es el nombre de la entidad -e, --exp-buf-device <dev> Usa el dispositivo <dev> como el dispositivo de vídeo utilizado para exportar DMABUFfers para realizar pruebas de streaming DMABUF. Si <dev> es un número, entonces se usa /dev/video<dev>. De lo contrario, si se especificó -z anteriormente, <dev> es el nombre de la entidad o ID de interfaz (si está prefijado con 0x) tal como se encuentra en la topología del dispositivo multimedia con la cadena de información del bus especificada por la opción -z. Si esta opción no se especifica, se omitirán las pruebas de streaming DMABUF.
-z, --media-bus-info <bus-info>
Encuentra el dispositivo multimedia con la cadena de información del bus dada. Si se establece, las opciones anteriores pueden usar el nombre de la entidad o el ID de la interfaz para referirse a los nodos del dispositivo. Ejemplo: v4l2-compliance -z platform:vivid-000 -d vivid-000-vid-cap
-m, --media-device <dev>
Usa el dispositivo <dev> como dispositivo controlador multimedia. Además de este dispositivo, también prueba todas las interfaces que encuentra. Si <dev> comienza con un dígito, entonces se usa /dev/media<dev>. Si <dev> no existe, entonces intenta encontrar un dispositivo multimedia con una cadena de información del bus igual a <dev>. Ejemplo: v4l2-compliance -m platform:vivid-000
-M, --media-device-only <dev>
Usa el dispositivo <dev> como dispositivo controlador multimedia. Solo prueba este dispositivo, no recorre todas las interfaces. Si <dev> comienza con un dígito, entonces se usa /dev/media<dev>. Si <dev> no existe, entonces intenta encontrar un dispositivo multimedia con una cadena de información del bus igual a <dev>. Ejemplo: v4l2-compliance -M platform:vivid-000
--stream-from [<pixelformat>=]<file>, --stream-from-hdr [<pixelformat>=]<file>
Utiliza el contenido del archivo para rellenar los búferes de salida. Si se proporciona el fourcc del formato de píxeles, utiliza el archivo para los búferes de salida utilizando solo ese formato de píxeles. La variante --stream-from-hdr utiliza el formato escrito por v4l2-ctl --stream-to-hdr, donde los tamaños de carga útil de cada búfer se almacenan en una cabecera. Útil para formatos comprimidos.
-s, --streaming <count>
Habilita las pruebas de streaming. Establece <count> al número de fotogramas a transmitir (por defecto 60). Esto requiere que antes de ejecutar v4l2-compliance, el dispositivo se haya configurado con una entrada (o salida) y frecuencia válidas (cuando el dispositivo tiene un sintonizador). Para pruebas DMABUF, también se debe establecer --expbuf-device.

La configuración del driver en el momento en que se llamó a v4l2-compliance se utilizará para las pruebas de streaming.

-f, --stream-all-formats [<count>]
Prueba si todos los formatos disponibles se pueden transmitir. Esto, al igual que la opción -s, requiere que el dispositivo se haya configurado correctamente antes de llamar a v4l2-compliance. El parámetro opcional <count> se utiliza para especificar cuántos fotogramas de cada formato se transmitirán (predeterminado 60).
-c, --stream-all-formats-cpu [<count>]
Similar a --stream-all-formats, pero para formatos que solo se soportan en la CPU. Estos formatos se pueden probar sin necesidad de que el dispositivo de hardware los soporte directamente, ya que la conversión se realiza en la CPU.
-C, --stream-all-formats-gpu [<count>]
Similar a --stream-all-formats, pero para formatos que solo se soportan en la GPU. Estos formatos se prueban utilizando la aceleración por hardware de la GPU. Se requiere que el dispositivo de hardware los soporte directamente.
-F, --stream-all-formats-dma [<count>]
Similar a --stream-all-formats, pero para formatos que se pueden transmitir usando DMA (Acceso Directo a Memoria). Esto permite transferencias de datos de alta velocidad entre la memoria y los periféricos sin intervención de la CPU.
-p, --playback [<count>]
Habilita las pruebas de reproducción (salida de vídeo). Similar a la opción -s, pero enfocado en la salida de datos de vídeo al dispositivo. El parámetro <count> especifica el número de fotogramas a reproducir (predeterminado 60).
-o, --output [<count>]
Habilita las pruebas de salida. Similar a la opción -s, pero enfocado en la salida de datos generales (no necesariamente vídeo) del dispositivo. El parámetro <count> especifica el número de fotogramas a generar (predeterminado 60).
-X, --no-close
No cierre el dispositivo al finalizar. Esto es útil para depurar, ya que permite inspeccionar el estado del dispositivo después de ejecutar la herramienta sin que se cierre automáticamente.
-h, --help
Muestra un mensaje de ayuda y sal.

OPTIONS

-s, --stream-all
Intenta transmitir utilizando el modo MMAP o lectura/escritura (si V4L2_MEMORY_MMAP no está disponible) durante un segundo para todos los formatos, en todos los tamaños, en todos los intervalos y con todos los valores de campo. Además, si el controlador admite escalado, recorte o composición, lo probará también en varias combinaciones. Si el controlador admite muchas combinaciones, esta prueba puede llevar mucho tiempo. Si se proporciona <count>, entonces transmita esa cantidad de fotogramas en lugar de un segundo.

Se utilizará la configuración del controlador en el momento en que se llamó a v4l2-compliance para las pruebas de transmisión.

-c, --stream-all-color color=red|green|blue,skip=<skip>,perc=<perc>
Para todos los formatos no comprimidos soportados, transmita <skip + 1> fotogramas. Para el último fotograma, recorra todos los píxeles y calcule qué componente de color R, G o B de un píxel tiene el valor más alto y cuéntelo como un píxel rojo, verde o azul. La prueba tiene éxito si al menos el perc por ciento del fotograma tiene el color dado. Esto requiere que haya una señal de video válida y predominantemente roja, verde o azul presente en las entradas. Si no se especifica skip, entonces solo capture el primer fotograma. Un valor skip distinto de cero es útil si el dispositivo tarda unos pocos fotogramas en calibrarse. Si no se especifica perc, el valor predeterminado es 90%.

La mayoría de los generadores de señales son capaces de generar video puro rojo, azul o verde. Para las cámaras, puede imprimir una imagen completamente roja, verde o azul y sostenerla frente a la cámara.

El objetivo de esta prueba es determinar si todos los formatos de píxel interpretarán correctamente los colores rojo, verde y azul y si no se intercambian los componentes de color.

Se utilizará la configuración del controlador en el momento en que se llamó a v4l2-compliance para las pruebas de transmisión.

-a, --stream-all-io
Realice las pruebas de transmisión -s, -c y -f para todas las entradas o salidas en lugar de solo la entrada o salida actual. Esto requiere que haya una señal de video válida presente en todas las entradas o que todas las salidas estén conectadas.
-E, --exit-on-fail
Salga de esta aplicación cuando ocurra la primera falla en lugar de continuar con un estado posiblemente inconsistente.
-C, --color <when>
Resalte las cadenas OK/warn/fail/FAIL con colores. OK se marca en verde, warn se marca en negrita, y fail/FAIL se marcan en rojo brillante si están habilitados. <when> puede ser always, never o auto (el valor predeterminado).
-n, --no-warnings
Desactive los mensajes de advertencia. Todavía se cuentan en el resumen, pero no los verá.
-P, --no-progress
Desactive los mensajes de progreso. Útil cuando se redirige la salida a un archivo.
-T, --trace
Rastree todos los ioctls llamados.
-v, --verbose
Habilite la generación de informes detallados.
--version
Mostrar información de la versión.
-w, --wrapper
Utilice la biblioteca de envoltorio libv4l2 para todos los accesos a dispositivos V4L2. Tenga en cuenta que al hacer esto, algunas pruebas fallarán porque la biblioteca libv4l2 no cumple completamente con V4L2. Por defecto, v4l2-compliance omitirá libv4l2 y accederá a los dispositivos V4L2 directamente.
-W, --exit-on-warn
Salga de esta aplicación cuando ocurra la primera advertencia en lugar de continuar.
-h, --help
Imprime el mensaje de ayuda.

ESTADO DE SALIDA

En caso de éxito, devuelve 0. De lo contrario, devolverá el código de error.

ERRORES

Esto es un trabajo en progreso, y cada cierto tiempo resulta que algunas pruebas realizadas por v4l2-compliance son demasiado estrictas o simplemente incorrectas. Si sospecha que este podría ser el caso, informe dichos errores a la lista de correo linux-media@vger.kernel.org.
