VIRT-WHAT(1) Soporte de virtualización VIRT-WHAT(1)

NOMBRE

virt-what - detectar si se está ejecutando en una máquina virtual

RESUMEN

virt-what [opciones]

DESCRIPCIÓN

"virt-what" es un script de shell que puede usarse para detectar si el programa se está ejecutando en una máquina virtual.

El programa imprime una lista de "hechos" sobre la máquina virtual, derivados de heurísticas. Se imprime un hecho por línea.

Si no se imprime nada y el script sale con código 0 (sin error), entonces puede significar *ya sea* que el programa se está ejecutando en bare-metal *o* que el programa se está ejecutando dentro de un tipo de máquina virtual que desconocemos o no podemos detectar.

ESTADO DE SALIDA

Los programas que utilizan o encapsulan "virt-what" deben verificar que el estado de salida sea 0 antes de intentar analizar la salida del comando.

Un estado de salida distinto de cero indica algún error, por ejemplo, un argumento de línea de comandos no reconocido. Si el estado de salida no es cero, entonces los "hechos" de salida (si se imprimieron) no se pueden garantizar y deben ignorarse.

El estado de salida no tiene nada que ver con si el programa se está ejecutando en baremetal o bajo virtualización, ni con si "virt-what" logró la detección "correctamente" (lo cual es básicamente incognoscible dada la gran variedad de sistemas de virtualización que existen y que algunos sistemas emulan deliberadamente a otros).

EJECUCIÓN DE VIRT-WHAT DESDE OTROS PROGRAMAS

"virt-what" está diseñado para que pueda ejecutarlo fácilmente desde otros programas o encapsularlo en una biblioteca.

Su programa debe verificar el estado de salida (ver la sección anterior).

Algunos lenguajes de programación (notablemente Python: issue 1652) enmascaran erróneamente la señal "SIGPIPE" y no la restauran al ejecutar subprocesos. "virt-what" es un script de shell y algunos comandos de shell no funcionan correctamente cuando se hace esto. Puede ver advertencias de "virt-what" similares a esta:

echo: write error: Broken pipe

La solución es restablecer el manejador de la señal "SIGPIPE" a "SIG_DFL" antes de ejecutar "virt-what".

NOTA IMPORTANTE

La mayoría de las veces, usar este programa es lo incorrecto. En su lugar, debería detectar las características específicas que realmente desea utilizar. (Por ejemplo, si quisiera emitir comandos del hipervisor Xen, buscaría el archivo "/proc/xen/privcmd").

Sin embargo, la gente sigue preguntando por esto, así que lo proporcionamos. Hay algunos usos legítimos:

Herramienta de informe de errores
Si cree que la virtualización podría afectar la forma en que se ejecuta su programa, podría usar "virt-what" para informarlo en una herramienta de informe de errores.
Herramientas de visualización de estado y monitoreo
Podría incluir esta información en programas de estado y monitoreo.
Ajuste del sistema (a veces)
Podría usar este programa para ajustar un sistema operativo para que funcione mejor como una máquina virtual de un hipervisor particular. Sin embargo, al instalar controladores paravirtualizados, es mejor verificar las características específicas que sus controladores necesitan (por ejemplo, la presencia de dispositivos PCI).

REPORTE DE ERRORES

Los errores se pueden ver en la página Red Hat Bugzilla: https://bugzilla.redhat.com/.

Si encuentra un error en virt-what, siga estos pasos para informarlo:

1. Verifique si existen informes de errores
Vaya a https://bugzilla.redhat.com/ y busque errores similares. Es posible que alguien ya haya informado del mismo error, e incluso lo haya corregido.
2. Capture mensajes de depuración y error
Ejecute 
virt-what > virt-what.log 2>&1

y conserve virt-what.log. Puede contener mensajes de error que debe enviar con su informe de error.

3. Obtenga la versión de virt-what.
Ejecute 
virt-what --version
4. Envíe un informe de error.
Vaya a https://bugzilla.redhat.com/ e ingrese un nuevo error. Describa el problema con el mayor detalle posible.

Recuerde incluir los números de versión (paso 3) y el archivo de mensajes de depuración (paso 2), y tantos detalles como sea posible.

5. Asigne el error a rjones @ redhat.com
Asigne o reasigne el error a rjones @ redhat.com (sin los espacios). También puede enviarme un correo electrónico con el número de error si desea una respuesta más rápida.
