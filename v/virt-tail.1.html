virt-tail(1) Soporte de Virtualización virt-tail(1)

NOMBRE

virt-tail - Seguir (tail) archivos en una máquina virtual

SINOPSIS

virt-tail [--opciones] -d nombre_dom p | p [...]
virt-tail [--opciones] -a disco.img [-a disco.img ...] p | p [...]

DESCRIPCIÓN

"virt-tail" es una herramienta de línea de comandos para seguir (tail) el contenido de "p" donde "p" existe en la máquina virtual (o imagen de disco) nombrada. Es similar al comando ordinario "tail -f".

Se pueden dar varios nombres de archivo, en cuyo caso cada uno se seguirá por separado. Cada nombre de archivo debe ser una ruta completa, comenzando desde el directorio raíz (comenzando con '/').

El comando continúa ejecutándose hasta que:

  • El usuario presiona ^C o se recibe una señal de interrupción.
  • Ninguno de los archivos listados fue encontrado en el invitado, o todos se eliminan.
  • Hay un error irrecuperable.

EJEMPLO

Seguir /var/log/messages dentro de una máquina virtual llamada "midominio":

virt-tail -d midominio /var/log/messages

OPCIONES

--help
Muestra ayuda breve.
-a archivo
--add archivo
Agrega archivo, que debe ser una imagen de disco de una máquina virtual. Si la máquina virtual tiene varios dispositivos de bloque, debes suministrar todos ellos con opciones -a separadas.

El formato de la imagen de disco se detecta automáticamente. Para anular esto y forzar un formato particular, usa la opción --format=...

-a URI
--add URI
Agrega un disco remoto. Ver "AGREGANDO ALMACENAMIENTO REMOTO" en guestfish(1).
--blocksize=512
--blocksize=4096
--blocksize
Este parámetro establece el tamaño del sector de la imagen de disco. Afecta a todos los discos subsiguientes añadidos explícitamente después de este parámetro. Usar --blocksize sin argumento cambia el tamaño del sector del disco al valor predeterminado que suele ser de 512 bytes. Ver también "guestfs_add_drive_opts" en guestfs(3).
-c URI
--connect URI
Si usa libvirt, conéctese a la URI dada. Si se omite, nos conectaremos al hipervisor libvirt predeterminado.

Si especifica los dispositivos de bloque del invitado directamente (-a), entonces libvirt no se utiliza en absoluto.

-d invitado
--domain invitado
Agrega todos los discos del invitado libvirt nombrado. Se pueden usar UUIDs de dominio en lugar de nombres.
--echo-keys
Al solicitar claves y frases de contraseña, virt-tail normalmente desactiva el eco para que no puedas ver lo que escribes. Si no te preocupan los ataques de Tempest y no hay nadie más en la habitación, puedes especificar esta bandera para ver lo que escribes.
-f
--follow
Esta opción se ignora. virt-tail siempre se comporta como tail(1) -f. No necesitas especificar la opción -f.
--format=raw|qcow2|..
--format
El valor predeterminado para la opción -a es la detección automática del formato de la imagen de disco. Usar esto fuerza el formato del disco para las opciones -a que siguen en la línea de comandos. Usar --format sin argumento revierte a la detección automática para las opciones -a subsiguientes.

Por ejemplo:

virt-tail --format=raw -a disco.img p

fuerza el formato raw (sin detección automática) para disco.img.

virt-tail --format=raw -a disco.img --format -a otro.img p

fuerza el formato raw (sin detección automática) para disco.img y revierte a la detección automática para otro.img.

Si tienes imágenes de disco de invitado sin formato confiables, debes usar esta opción para especificar el formato del disco. Esto evita un posible problema de seguridad con invitados maliciosos (CVE-2010-3851).

--key SELECCIONADOR
Especifica una clave para LUKS, para abrir automáticamente un dispositivo LUKS al usar la inspección.
--key NOMBRE:clave:CADENA_CLAVE
--key UUID:clave:CADENA_CLAVE
--key todo:clave:CADENA_CLAVE
"NOMBRE" es el nombre del dispositivo libguestfs (ej. "/dev/sda1"). "UUID" es el UUID del dispositivo. "todo" significa intentar la clave contra cualquier dispositivo encriptado.

Usa la "CADENA_CLAVE" especificada como frase de contraseña.

--key NOMBRE:archivo:NOMBRE_ARCHIVO
--key UUID:archivo:NOMBRE_ARCHIVO
--key todo:archivo:NOMBRE_ARCHIVO
Lee la frase de contraseña desde NOMBRE_ARCHIVO.
--key NOMBRE:clevis
--key UUID:clevis
--key todo:clevis
Intenta el desbloqueo sin frase de contraseña para el dispositivo con Clevis, a través de la red. Por favor, consulta "DISCOS CIFRADOS" en guestfs(3) para más información sobre cifrado de disco enlazado a la red (NBDE).

Ten en cuenta que si alguna de estas opciones está presente en la línea de comandos, la red de usuario de QEMU se habilitará automáticamente para la aplicación libguestfs.

--keys-from-stdin
Lee parámetros de clave o frase de contraseña desde stdin. El valor predeterminado es intentar leer frases de contraseña del usuario abriendo /dev/tty.

Si hay múltiples dispositivos encriptados, puede que necesites suministrar múltiples claves en stdin, una por línea.

-m dev[:punto-montaje[:opciones[:tipo-fs]]]
--mount dev[:punto-montaje[:opciones[:tipo-fs]]]
Monta la partición o volumen lógico nombrado en el punto de montaje dado.

Si el punto de montaje se omite, el valor predeterminado es /.

Especificar cualquier punto de montaje deshabilita la inspección del invitado y el montaje de su raíz y todos sus puntos de montaje, así que asegúrate de montar todos los puntos de montaje necesarios para trabajar con los archivos dados como argumentos.

Si no sabes qué sistemas de archivos contiene una imagen de disco, puedes ejecutar guestfish sin esta opción, luego listar las particiones, sistemas de archivos y LVs disponibles (ver comandos "list-partitions", "list-filesystems" y "lvs"), o puedes usar el programa virt-filesystems(1).

virt-tail(1) — guestfs-tools

NAME

virt-tail - Display the end of a file from a virtual machine

SYNOPSIS

virt-tail [-a | --all] [-f | --follow] [-h | --help] [-i | --ignorecase] [-l | --log] [-m MOUNT OPTIONS] [-n LINES | --lines LINES] [-v | --verbose] [-V | --version] [-x] guest[:DEVICE] FILE

DESCRIPTION

The virt-tail command displays the last part of a file from a virtual machine. It works similarly to the standard tail command, but operates on files inside a virtual machine image or a running virtual machine.

The guest argument specifies the virtual machine to access. This can be the name of a running virtual machine (if libvirt is installed and configured), or it can be the path to a virtual machine disk image file (eg. /var/lib/libvirt/images/myguest.img).

The optional DEVICE argument specifies which device inside the guest to use. Usually libguestfs can auto-detect this, but sometimes you might need to specify it, e.g. /dev/sda1.

The FILE argument is the path to the file inside the guest that you want to display the end of.

EXAMPLE

Display the last 10 lines of the system log file from the running virtual machine named myvm:

$ virt-tail myvm /var/log/messages

Display the last 5 lines of the file /path/to/file.txt from the disk image disk.img:

$ virt-tail -n 5 disk.img /path/to/file.txt

OPTIONS

-a
--all
Display the entire file, not just the end.
-f
--follow
Append data as the file grows. This works like tail -f.
-h
--help
Display help message and exit.
-i
--ignorecase
Ignore case when matching filenames. This is mainly useful for Windows guests.
-l
--log
Treat the file as a log file and try to interpret it correctly. This is useful for systemd journal files and other binary log formats.
-m
--mount-options MOUNT OPTIONS
Specify mount options for the filesystem. This is a comma-separated list of options. You can specify options per device, e.g. /dev/sda1:rw,/dev/sdb1:ro. If no device is specified, the options apply to the primary filesystem. This is equivalent to using the mount-options command.

By default, libguestfs tries to guess sensible mount options. For example, it mounts all filesystems read-write by default unless certain conditions are met (like the filesystem being journaled and the -n flag1 is used). By specifying the mount options, you override this default choice. Probably the only time you would use this is to enable ACLs and/or extended attributes if the filesystem can support them:

-m /dev/sda1:/:acl,user_xattr

Using this flag is equivalent to using the "mount-options" command.

The fourth part of the parameter is the filesystem driver to use, such as "ext3" or "ntfs". This is rarely needed, but can be useful if multiple drivers are valid for a filesystem (eg: "ext2" and "ext3"), or if libguestfs misidentifies a filesystem.

-n
--lines LINES
Display the last LINES lines of the file. The default is 10.
-v
--verbose
Enable verbose messages for debugging.
-V
--version
Display version number and exit.
-x
Enable tracing of libguestfs API calls.

1 This footnote refers to the `-n` option which is not described in this excerpt. It's likely a typo or refers to an option not present in this specific man page section.

LOG FILES

To list out the log files from guests, see the related tool virt-log(1). It understands binary log formats such as the systemd journal.

WINDOWS PATHS

"virt-tail" has a limited ability to understand Windows drive letters and paths (eg. E:\foo\bar.txt).

If and only if the guest is running Windows then:

  • Drive letter prefixes like "C:" are resolved against the Windows Registry to the correct filesystem.
  • Any backslash ("\") characters in the path are replaced with forward slashes so that libguestfs can process it.
  • The path is resolved case insensitively to locate the file that should be displayed.

There are some known shortcomings:

  • Some NTFS symbolic links may not be followed correctly.
  • NTFS junction points that cross filesystems are not followed.

EXIT STATUS

This program returns 0 if successful, or non-zero if there was an error.
