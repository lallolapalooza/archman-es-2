NOMBRE

veritysetup - utilidad para configurar y gestionar dispositivos dm-verity

SINOPSIS

veritysetup <acción> [<opciones>] <argumentos de acción>

DESCRIPCIÓN

Veritysetup es una utilidad para configurar y gestionar dispositivos dm-verity del kernel.

El objetivo dm-verity del device-mapper del kernel proporciona protección de integridad de datos transparente y de solo lectura para dispositivos de bloques.

Cuando configuras el dispositivo dm-verity, veritysetup crea un nuevo mapeo al que las aplicaciones pueden acceder como cualquier dispositivo de almacenamiento regular. El kernel realiza la verificación de forma transparente comparando cada bloque con hashes criptográficos precalculados. La verificación utiliza un árbol de Merkle y ocurre de forma transparente a nivel del kernel sin afectar a las aplicaciones.

Los dispositivos Verity pueden activarse durante el arranque a través de veritytab(5), que es parte de systemd(1).

ACCIONES BÁSICAS

Veritysetup soporta estas operaciones:

FORMATO

format <dispositivo_datos> <dispositivo_hash>

Calcula y almacena permanentemente datos de verificación de hash para el dispositivo de datos. El área de hash puede estar ubicada en el mismo dispositivo después de los datos, si se especifica mediante la opción --hash-offset.

Necesitas proporcionar la cadena de hash raíz para la verificación o activación del dispositivo. El hash raíz debe ser confiable.

El argumento del dispositivo de datos o hash puede ser un dispositivo de bloques o una imagen de archivo. Si la ruta del dispositivo hash no existe, se creará como un archivo.

<opciones> pueden ser [--hash, --no-superblock, --format, --data-block-size, --hash-block-size, --data-blocks, --hash-offset, --salt, --uuid, --root-hash-file].

Si se utiliza la opción --root-hash-file, el hash raíz se almacena en formato de texto codificado en hexadecimal en <ruta>.

ABRIR

open <dispositivo_datos> <nombre> <dispositivo_hash> <hash_raíz>
open <dispositivo_datos> <nombre> <dispositivo_hash> --root-hash-file <ruta>
create <nombre> <dispositivo_datos> <dispositivo_hash> <hash_raíz> (sintaxis OBSOLETA)

Crea un mapeo con <nombre> respaldado por el dispositivo <dispositivo_datos> y utilizando <dispositivo_hash> para la verificación en el kernel.

El <hash_raíz> es una cadena hexadecimal.

<opciones> pueden ser [--hash-offset, --no-superblock, --ignore-corruption o --restart-on-corruption, --panic-on-corruption, --ignore-zero-blocks, --check-at-most-once, --root-hash-signature, --root-hash-file, --use-tasklets, --shared].

Si se utiliza la opción --root-hash-file, el hash raíz se lee de <ruta> en lugar del parámetro de la línea de comandos. Espera texto codificado en hexadecimal, sin una nueva línea final.

Si se usa --no-superblock, debes usar las mismas opciones que en la operación de formato inicial.

VERIFICAR

verify <dispositivo_datos> <dispositivo_hash> <hash_raíz>
verify <dispositivo_datos> <dispositivo_hash> --root-hash-file <ruta>

Verifica los datos en el dispositivo de datos usando bloques de hash almacenados en el dispositivo de hash.

Este comando realiza la verificación en el espacio de usuario; no se crea ningún dispositivo del kernel.

El <hash_raíz> es una cadena hexadecimal.

Si se utiliza la opción --root-hash-file, el hash raíz se lee de <ruta> en lugar del parámetro de la línea de comandos. Espera texto codificado en hexadecimal, sin una nueva línea final.

<opciones> pueden ser [--hash-offset, --no-superblock, --root-hash-file].

Si se usa --no-superblock, debes usar las mismas opciones que en la operación de formato inicial.

CERRAR

close <nombre>
remove <nombre> (sintaxis OBSOLETA)

Elimina el mapeo existente <nombre>.

<opciones> pueden ser [--deferred] o [--cancel-deferred].

ESTADO

status <nombre>

Reporta el estado del mapeo verity activo <nombre>.

VOLCAR

dump <dispositivo_hash>

Reporta los parámetros del dispositivo verity desde el superbloque almacenado en disco.

<opciones> pueden ser [--hash-offset].

OPCIONES

--batch-mode, -q

No pidas confirmación.

--cancel-deferred

Cancela una eliminación diferida de dispositivo configurada previamente en el comando close.

--check-at-most-once

Instruye al kernel para verificar los bloques solo una vez que sean leídos del dispositivo de datos, en lugar de cada vez.

ADVERTENCIA: Proporciona un nivel de seguridad reducido porque solo se detectarán manipulaciones fuera de línea del contenido del dispositivo de datos, no manipulaciones en línea.

--data-blocks bloques

Tamaño del dispositivo de datos utilizado en la verificación. Si no se especifica, se utiliza todo el dispositivo.

--data-block-size bytes

Tamaño de bloque utilizado para el dispositivo de datos. El máximo es el tamaño de página utilizado por el kernel.

--debug

Ejecutar en modo de depuración con registros de diagnóstico completos. Las líneas de salida de depuración siempre van precedidas por #.

--deferred

Pospone la eliminación del dispositivo en el comando close hasta que el último usuario lo cierre.

--error-as-corruption

Maneja los errores de E/S del dispositivo de la misma manera que la corrupción de datos. Esta opción debe combinarse con --restart-on-corruption o --panic-on-corruption.

--fec-device dispositivo

Utiliza corrección de errores hacia adelante (FEC) para recuperarse de la corrupción si falla la verificación de hash. Utiliza datos de codificación del dispositivo especificado.

El argumento del dispositivo FEC puede ser un dispositivo de bloques o una imagen de archivo. Para formatear, si la ruta del dispositivo FEC no existe, se creará como un archivo.

Los tamaños de bloque para los dispositivos de datos y hash deben coincidir. Además, si el dispositivo de datos verity está cifrado, el dispositivo fec también debería estarlo.

El cálculo de FEC cubre los datos, el área de hash y los metadatos opcionales externos almacenados en el mismo dispositivo que el árbol de hashes (espacio adicional después del área de hash). El tamaño de esta área adicional opcional protegida por FEC se calcula a partir de los tamaños de imagen, por lo que debes usar las mismas imágenes para la activación.

Si el dispositivo hash está en una imagen separada, los metadatos cubren toda la imagen después del área de hash.

Los metadatos terminan en el desplazamiento del área FEC si el hash y el dispositivo FEC están en la imagen.

--fec-offset bytes

Este es el desplazamiento, en bytes, desde el inicio del dispositivo FEC hasta el inicio de los datos de codificación.

--fec-roots número

Número de raíces generadoras. Esto es igual al número de bytes de paridad en los datos de codificación. En la codificación RS(M, N), el número de raíces es M-N. M es 255 y M-N está entre 2 y 24 (inclusive).

--format número

Especifica el tipo de versión de hash. El tipo de formato 0 es la versión original de Chrome OS. El tipo de formato 1 es la versión actual.

--hash hash

Algoritmo de hash para dm-verity. Para el valor predeterminado, consulta la opción --help.

--hash-block-size bytes

Tamaño de bloque utilizado para el dispositivo de hash. El máximo es el tamaño de página utilizado por el kernel.

--hash-offset bytes

Desplazamiento del área de hash/superbloque en el dispositivo_hash. El valor debe estar alineado con el desplazamiento del sector del disco.

--help, -?

Muestra el texto de ayuda y los parámetros predeterminados.

--ignore-corruption, --restart-on-corruption, --panic-on-corruption

Define qué hacer si se detecta un problema de integridad de datos (corrupción de datos).

--ignore-corruption: no se toma ninguna medida adicional, pero el evento de corrupción se registra en el kernel. El dispositivo sigue estando accesible y los datos corruptos se presentan tal cual.

--restart-on-corruption: el dispositivo se volverá a activar automáticamente cuando se detecte la corrupción. Esto puede ser útil si la corrupción es temporal o causada por un problema de hardware transitorio.

--panic-on-corruption: el sistema se detendrá (kernel panic) si se detecta corrupción. Esto proporciona el nivel más alto de seguridad, ya que evita que el sistema continúe operando con datos potencialmente comprometidos.

--ignore-zero-blocks

Omite la verificación de bloques que contienen solo ceros en el dispositivo de datos. Esto puede ser útil para mejorar el rendimiento en dispositivos que a menudo contienen grandes cantidades de bloques vacíos (por ejemplo, imágenes de disco descomprimidas).

--no-superblock

Omite el uso de un superbloque en el dispositivo hash. Esto es útil para dispositivos creados con un formato antiguo o para dispositivos personalizados. Si se utiliza esta opción, se deben proporcionar los mismos parámetros (tamaño de bloque de datos, tamaño de bloque de hash, número de bloques de datos, desplazamiento de hash, sal, etc.) que se utilizaron durante el formato inicial, ya sea en la línea de comandos o a través de un archivo de parámetros.

--prepend-filename

Para cada bloque de datos y hash, se utiliza la misma ruta relativa del archivo de entrada.

--quiet, -q

Suprime la salida de progreso.

--root-hash-file path

Lee el hash raíz del archivo especificado en lugar de la línea de comandos. El archivo debe contener el hash raíz en formato hexadecimal sin una nueva línea final.

--root-hash-signature signature

Firma del hash raíz (cadena hexadecimal).

--salt salt

Valor de sal (cadena hexadecimal) utilizado durante el cálculo del hash. La sal debe ser la misma que se utilizó durante el formato.

--shared

Permite que varias activaciones compartan un solo dispositivo dm-verity. Esto puede ser útil si el mismo dispositivo con el mismo hash raíz necesita ser accedido por múltiples procesos o aplicaciones.

--uuid uuid

El UUID del dispositivo verity.

--use-tasklets

Usa tasklets para el procesamiento de hash en lugar de interrupciones. Puede mejorar el rendimiento en algunos sistemas.

--verbose, -v

Ejecutar en modo detallado con más información.

EJEMPLOS

Para formatear un dispositivo de datos /dev/dm-0 y almacenar los hashes en /dev/dm-1:

# veritysetup format /dev/dm-0 /dev/dm-1

Para abrir un dispositivo verity con el nombre mydevice, usando /dev/dm-0 como dispositivo de datos y /dev/dm-1 como dispositivo de hash, con el hash raíz f7b991d...:

# veritysetup open /dev/dm-0 mydevice /dev/dm-1 f7b991d...

Para abrir un dispositivo verity leyendo el hash raíz de /path/to/root.hash:

# veritysetup open /dev/dm-0 mydevice /dev/dm-1 --root-hash-file /path/to/root.hash

Para verificar los datos en /dev/dm-0 usando hashes en /dev/dm-1 y el hash raíz f7b991d...:

# veritysetup verify /dev/dm-0 /dev/dm-1 f7b991d...

Para cerrar el dispositivo verity mydevice:

# veritysetup close mydevice

OPCIONES

--data-block-size bytes

Tamaño de bloque de datos en bytes. El valor predeterminado es 4096.

--debug

Habilita la salida detallada de depuración.

--fec-block-size bytes

Tamaño de bloque de datos FEC en bytes. El valor predeterminado es 4096.

--fec-device dispositivo

Dispositivo de datos de codificación y corrección de errores (FEC). Este dispositivo contendrá los datos de redundancia para la corrección de errores.

--fec-offsets offsets

Desplazamientos de bloques FEC (formato hex). Ver la especificación del formato de disco dm-verity.

--fec-roots número

Número de bloques raíz FEC. El valor predeterminado es 2.

--hash-algorithm algoritmo

Algoritmo de hash que se utilizará para la creación de hashes. Los algoritmos disponibles dependen de la configuración del kernel. Los algoritmos comunes incluyen sha1, sha256, sha512, md5.

--hash-offset bytes

Desplazamiento en bytes donde se almacenarán los datos de hash. El valor predeterminado es 0.

--hash-size bytes

Tamaño de cada hash en bytes. El valor predeterminado es 20 (para sha1).

--help

Muestra un mensaje de ayuda corto.

--ignore-corruption

Si se encuentra corrupción de datos (hash incorrecto), se registra la corrupción y la operación de E/S continúa. Sin esta opción, la operación de E/S falla con un error de E/S.

--panic-on-corruption

Similar a --ignore-corruption, pero provoca un pánico del kernel en lugar de registrar la corrupción.

--quiet, -q

Suprime la mayor parte de la salida informativa.

--restart-on-corruption

Similar a --ignore-corruption, pero reinicia el dispositivo verity en lugar de registrar la corrupción.

--retry-on-corruption

Si se encuentra corrupción de datos, se intenta volver a leer los datos de un dispositivo FEC (si está presente). Si no hay ningún dispositivo FEC o si la corrección de errores falla, se intenta recuperar de los datos del dispositivo de datos original. Sin estas opciones, el kernel falla la operación de E/S con un error de E/S. Con la opción --ignore-corruption, la corrupción solo se registra. Con --restart-on-corruption o --panic-on-corruption, el kernel se reinicia (entra en pánico) inmediatamente. (Tienes que proporcionar una forma de evitar bucles de reinicio).

Usa estas opciones solo en casos muy específicos.

--ignore-zero-blocks

Indica al kernel que no verifique los bloques que se espera que contengan ceros y que siempre devuelva ceros directamente en su lugar.

Usa esta opción solo en casos muy específicos.

--no-superblock

Crea o usa dm-verity sin un superbloque permanente en disco.

--root-hash-file archivo*

Ruta al archivo con el hash raíz almacenado en texto codificado en hex.

--root-hash-signature archivo*

Una ruta al archivo de firma del hash raíz utilizado para verificar el hash raíz (en el kernel). Esta característica requiere una versión del kernel de Linux 5.4 o más reciente.

--salt=cadena_hex

Sal utilizada para el formateo o la verificación. El formato es una cadena hexadecimal.

--shared

Permite que el dispositivo de datos se utilice en modo compartido. El dispositivo de datos no se verifica en busca de acceso exclusivo antes de la activación del dispositivo y puede mapearse en múltiples mapeos verity.

--usage

Muestra una ayuda de opciones corta.

--use-tasklets

Intenta usar tasklets del kernel en el controlador dm-verity por razones de rendimiento. Esta opción está disponible a partir de la versión 6.0 del kernel de Linux.

--uuid UUID

Usa el UUID proporcionado para el comando format en lugar de generar uno nuevo.

El UUID debe proporcionarse en formato UUID estándar, por ejemplo, 12345678-1234-1234-1234-123456789abc.

--verbose, -v

Imprime más información sobre la ejecución del comando.

--version, -V

Muestra la versión del programa.

CÓDIGOS DE RETORNO

Veritysetup devuelve 0 si tiene éxito y un valor distinto de cero en caso de error.

Los códigos de error son: 1 parámetros incorrectos, 2 permiso denegado, 3 falta de memoria, 4 dispositivo especificado incorrectamente, 5 el dispositivo ya existe o está ocupado.

EJEMPLOS

veritysetup --data-blocks=256 format <dispositivo_datos> <dispositivo_hashes>

Calcula y almacena datos de verificación en hash_device para los primeros 256 bloques (del tamaño de bloque). Si hash_device no existe, se crea (como una imagen de archivo).

veritysetup format --root-hash-file <ruta> <dispositivo_datos> <dispositivo_hashes>

Calcula y almacena datos de verificación en hash_device para todo el data_device, y almacena el hash raíz como texto codificado en hex en <ruta>.

veritysetup --data-blocks=256 --hash-offset=1052672 format <dispositivo> <dispositivo>

Los datos de verificación (hashes) se almacenan en el mismo dispositivo que los datos (comenzando en hash-offset). El desplazamiento del hash debe ser mayor que el número de bloques en el área de datos.

veritysetup --data-blocks=256 --hash-offset=1052672 create test-device <dispositivo> <dispositivo> <hash_raiz>

Activa el dispositivo verity llamado test-device. Las opciones --data-blocks y --hash-offset son las mismas que en el comando format. El <hash_raiz> se calculó en el comando format.

veritysetup --data-blocks=256 --hash-offset=1052672 verify <dispositivo_datos> <dispositivo_hashes> <hash_raiz>

Verifica el dispositivo sin activación (en userspace).

veritysetup --data-blocks=256 --hash-offset=1052672 --root-hash-file <ruta> verify <dispositivo_datos> <dispositivo_hashes>

Verifica el dispositivo sin activación (en userspace). El hash raíz se pasa a través de un archivo en lugar de en línea.

veritysetup --fec-device=<dispositivo_fec> --fec-roots=10 format <dispositivo_datos> <dispositivo_hashes>

Calcula y almacena datos de verificación y codificación para el data_device.
