VGCREATE(8) Manual del Administrador del Sistema VGCREATE(8)

NOMBRE

vgcreate — Crear un grupo de volúmenes

SINOPSIS

vgcreate args_posicionales
[ args_opcionales ]

DESCRIPCIÓN

vgcreate crea un nuevo VG (grupo de volúmenes) en dispositivos de bloque. Si los dispositivos no fueron inicializados previamente como PVs (volúmenes físicos) con pvcreate(8), vgcreate los inicializará, convirtiéndolos en PVs. Las opciones de pvcreate para inicializar dispositivos también están disponibles con vgcreate.

Cuando vgcreate utiliza un PV existente, se utilizan los valores existentes de ese PV para el tamaño de metadatos, inicio de PE, etc., incluso si se especifican valores diferentes en el comando vgcreate. Para cambiar estos valores, primero use pvremove en el dispositivo.

USO

vgcreate NUEVO_VG PV ...

OPCIONES

--addtag Etiqueta
Añade una etiqueta a un PV, VG o LV. Esta opción se puede repetir para añadir varias etiquetas a la vez. Consulte lvm(8) para obtener información sobre las etiquetas.
--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Determina la política de asignación cuando un comando necesita asignar Extents Físicos (PEs) del VG. Cada VG y LV tiene una política de asignación que se puede cambiar con vgchange/lvchange, o anular en la línea de comandos. normal aplica reglas de sentido común como no colocar stripes paralelos en el mismo PV. inherit aplica la política del VG a un LV. contiguous requiere que los nuevos PEs se coloquen adyacentes a los PEs existentes. cling coloca los nuevos PEs en el mismo PV que los PEs existentes en el mismo stripe del LV. Si hay suficientes PEs para una asignación, pero normal no los usa, anywhere los usará incluso si reduce el rendimiento, por ejemplo, al colocar dos stripes en el mismo PV. Los argumentos posicionales opcionales de PV en la línea de comandos también se pueden usar para limitar qué PVs usará el comando para la asignación. Consulte lvm(8) para más información sobre la asignación.
-A|--autobackup y|n
Especifica si se deben hacer copias de seguridad de los metadatos automáticamente después de un cambio. ¡Se recomienda encarecidamente habilitar esto! Consulte vgcfgbackup(8) para obtener más información.
-c|--clustered y|n
Esta opción era específica para clvm y ahora ha sido reemplazada por la opción --shared con lvmlockd(8).
--commandprofile Cadena
El perfil de comando a utilizar para la configuración del comando. Consulte lvm.conf(5) para obtener más información sobre los perfiles.
--config Cadena
Configuraciones para el comando. Estas anulan la configuración de lvm.conf(5). La cadena de argumentos utiliza el mismo formato que lvm.conf(5), o puede utilizar la sintaxis de sección/campo. Consulte lvm.conf(5) para obtener más información sobre la configuración.
--dataalignment Tamaño[k|UNIDAD]
Alinea el inicio de un área de datos de PV con un múltiplo de este número. Para ver la ubicación del primer Extent Físico (PE) de un PV existente, use pvs -o +pe_start. Además, puede desplazarse por un desplazamiento de alineación, consulte --dataalignmentoffset. Especifique también un tamaño de PE apropiado al crear un VG.
--dataalignmentoffset Tamaño[k|UNIDAD]
Desplaza el inicio del área de datos del PV por este desplazamiento adicional.
-d|--debug ...
Establece el nivel de depuración. Repita de 1 a 6 veces para aumentar el nivel de detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción se puede repetir o acepta una lista de dispositivos separados por comas. Esto anula el archivo de dispositivos.
--devicesfile Cadena
Un archivo que lista los dispositivos que LVM debe usar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración de lvm.conf(5) devices/devicesfile y devices/use_devicesfile.
--driverloaded y|n
Si se establece en no, el comando no intentará usar device-mapper. Para pruebas y depuración.
-f|--force ...
Anula varias comprobaciones, confirmaciones y protecciones. Úselo con extrema precaución.
-h|--help
Muestra el texto de ayuda.
--journal Cadena
Registra información en el journal de systemd. Esta información es adicional a la información habilitada por la configuración de registro/journal de lvm.conf. command: registra información sobre el comando. output: registra la salida del comando predeterminada. debug: registra la depuración completa del comando.
--labelsector Número
Por defecto, el PV se etiqueta con un identificador LVM2 en su segundo sector (sector 1). Esto le permite usar un sector diferente cerca del inicio del disco (entre 0 y 3, ambos inclusive; consulte LABEL_SCAN_SECTORS en el código fuente). Úselo con cuidado.
--lockopt Cadena
Se utiliza para pasar opciones para casos especiales a lvmlockd. Consulte lvmlockd(8).
--longhelp
Muestra la ayuda detallada.
-l|--maxlogicalvolumes Número
El número máximo de volúmenes lógicos que se pueden crear en este VG. El valor predeterminado es 0, lo que significa que no hay límite (más allá de los límites del sistema o del formato LVM).
-M|--metadatatype lvm2
El tipo de metadatos que se utilizará para el VG. Actualmente, solo se admite lvm2.
--metadataprofile Cadena
El perfil de metadatos a utilizar para el VG. Consulte lvm.conf(5) para obtener más información sobre los perfiles.
--metadatasize Tamaño[m|UNIDAD]
Establece el tamaño de los metadatos en los PVs. Esto puede ser un valor fijo en MB (el valor predeterminado) o una fracción del tamaño del PV. Si no se especifica, se utiliza el valor predeterminado de lvm.conf(5).
--[vg]metadatacopies all|unmanaged|Número
El número de copias de metadatos que se mantendrán en cada PV. El valor predeterminado es 1. Si se establecen en 2, se mantendrán dos copias de los metadatos en cada PV, lo que proporciona redundancia. Si se establecen en all, se mantendrá el número de copias especificado en la configuración global. Si se establecen en unmanaged, las copias de metadatos no serán gestionadas por LVM. Puede ser necesario establecer esto en 1 para usar dispositivos con metadatos LVM existentes o para usar ciertos dispositivos de bajo nivel.
--nohints
Suprime la visualización de mensajes de "sugerencia".
--nolocking
Desactiva el bloqueo. Para su uso en entornos no distribuidos o cuando se sabe que el bloqueo no es necesario.
--normal
Esta es la política de asignación predeterminada si no se especifica ninguna otra. Consulte --alloc para obtener más información.
-p|--maxphysicalvolumes Número
El número máximo de PVs que se pueden añadir a este VG. El valor predeterminado es 0, lo que significa que no hay límite (más allá de los límites del sistema o del formato LVM).
--persist start
Marca el inicio de un bloque para la construcción de comandos de shell persistentes. Consulte lvm(8) para obtener más información.
--profile Cadena
El perfil a utilizar para la configuración del comando. Consulte lvm.conf(5) para obtener más información sobre los perfiles.
-q|--quiet ...
Suprime algunos mensajes de salida. Repetir el indicador suprimirá aún más mensajes.
--pvmetadatacopies 0|1|2
El número de copias de metadatos que se mantendrán en cada PV. El valor predeterminado es 1. Si se establecen en 2, se mantendrán dos copias de los metadatos en cada PV, lo que proporciona redundancia. Puede ser necesario establecer esto en 1 para usar dispositivos con metadatos LVM existentes o para usar ciertos dispositivos de bajo nivel.
--reportformat basic|json|json_std
Especifica el formato de la salida del informe.
-s|--physicalextentsize Tamaño[m|UNIDAD]
El tamaño de los Extents Físicos (PEs) para este VG. El valor predeterminado es 4 MB. Consulte lvm.conf(5) para ver la lista de unidades disponibles.
--setautoactivation y|n
Indica si los LVs de este VG deben activarse automáticamente al inicio del sistema.
--setlockargs Cadena
Se utiliza para pasar opciones para casos especiales a lvmlockd. Consulte lvmlockd(8).
--setpersist Cadena
Establece un valor para la configuración persistente del comando. Consulte lvm(8) para obtener más información.
--shared
Marca el VG como compartido, lo que significa que puede ser accedido y utilizado por múltiples nodos en un clúster. Esto requiere que se utilice lvmlockd(8).
--systemid Cadena
Este es un identificador específico para un sistema en un clúster. Se utiliza para controlar qué sistemas tienen acceso a qué LVs. Esto es importante para la configuración de lvmlockd(8).
-t|--test
Ejecuta el comando en modo de prueba. Todas las acciones se simulan, pero no se realizan cambios reales.
-v|--verbose ...
Aumenta el nivel de detalle de la salida del comando. Repita el indicador para aumentar el nivel de detalle.
--version
Muestra la información de la versión del programa y sale.
-y|--yes
No solicite confirmación para las acciones que requieren confirmación.
-Z|--zero y|n
Especifica si los metadatos deben ser borrados (a cero) al crear los PVs. El valor predeterminado es 'y' (sí), lo que significa que los metadatos se borran. Establecerlo en 'n' (no) puede ser útil si está recreando un VG a partir de una copia de seguridad de metadatos.

EJEMPLOS

Para crear un nuevo grupo de volúmenes llamado my_volume_group utilizando los dispositivos /dev/sda1 y /dev/sdb1 como volúmenes físicos:

vgcreate my_volume_group /dev/sda1 /dev/sdb1

Para crear un nuevo grupo de volúmenes llamado my_vg con un tamaño de extent físico de 16MB, utilizando los dispositivos /dev/nvme0n1p1 y /dev/nvme0n2p1:

vgcreate -s 16m my_vg /dev/nvme0n1p1 /dev/nvme0n2p1

OPCIONES

-a|--all
Operate on all Volume Groups.
-A|--autobackup boolean
Controls if metadata should be backed up using the default backup location (usually /etc/lvm/backup). Defaults to true. Disabling this can slightly speed up metadata updates but should only be done if you have other mechanisms for backing up LVM metadata.
-c|--checks
Perform checks on Volume Groups.
-d|--debug
Set debug level. Repeat N times to increase the detail of messages sent to stdout and stderr.
-D|--devices String
Filter devices for PVs. See the devices/filter setting in lvm.conf(5) for more information.
-f|--force
Attempt to force the deactivation of all logical volumes in a volume group if they are not active. This option bypasses checks that would normally prevent deactivation (e.g. if a logical volume is still in use).
-g|--globalreport
Report all Volume Groups. This is the default behavior.
-h|--help
Display the help text.
-i|--ignorecase
Make Volume Group and Logical Volume name matching ignore case.
-k|--locktype sanlock|dlm|none
Specify the VG lock type directly in place of using --shared. See lvmlockd(8) for more information.
-l|--maxlogicalvolumes Number
Establece el número máximo de LVs permitidos en un VG.
-M|--metadatatype lvm2
Especifica el tipo de metadatos en disco a usar. lvm2 (o solo 2) es el formato actual y estándar. lvm1 (o solo 1) ya no se usa.
-p|--maxphysicalvolumes Number
Establece el número máximo de PVs que pueden pertenecer al VG. El valor 0 elimina cualquier limitación. Para un gran número de PVs, también vea las opciones --pvmetadatacopies y --vgmetadatacopies para mejorar el rendimiento.
-q|--quiet ...
Suprime la salida y los mensajes de registro. Anula --debug y --verbose. Repita una vez para suprimir también cualquier pregunta con respuesta 'no'.
-s|--physicalextentsize Size[m|UNIT]
Establece el tamaño de los extents físicos de los PVs en el VG. El valor debe ser una potencia de 2 de al menos 1 sector (donde el tamaño del sector es el tamaño del sector más grande de los PVs actualmente utilizados en el VG), o al menos 128 KiB. Una vez establecido este valor, es difícil cambiarlo sin recrear el VG, a menos que no se necesiten mover extents.
-t|--test
Ejecutar en modo de prueba. Los comandos no actualizarán los metadatos. Esto se implementa deshabilitando toda escritura de metadatos pero devolviendo éxito a la función que llama. Esto puede llevar a mensajes de error inusuales en operaciones de múltiples etapas si una herramienta depende de leer metadatos que cree que han cambiado pero no lo han hecho.
-v|--verbose ...
Establece el nivel de verbosidad. Repita de 1 a 4 veces para aumentar el detalle de los mensajes enviados a stdout y stderr.
-y|--yes
No pedir confirmación interactivamente sino asumir siempre la respuesta sí. Usar con extrema precaución. (Para un no automático, ver -qq.)
-Z|--zero y|n
Controla si los primeros 4 sectores (2048 bytes) del dispositivo se borran. Por defecto, se borran estos sectores a menos que se especifique --restorefile o --uuid (o ambos).
--locktype sanlock|dlm|none
Especifica el tipo de bloqueo del VG directamente en lugar de usar --shared. Ver lvmlockd(8) para más información.
--longhelp
Muestra el texto de ayuda detallado.
--metadataprofile String
El perfil de metadatos a usar para la configuración del comando. Ver lvm.conf(5) para más información sobre perfiles.
--metadatasize Size[m|UNIT]
La cantidad aproximada de espacio utilizada para cada área de metadatos del VG. El tamaño puede ser redondeado.
--nohints
No usar el archivo de pistas para localizar dispositivos para PVs. Un comando puede leer más dispositivos para encontrar PVs cuando no se usan pistas. El comando aún realizará la invalidación estándar del archivo de pistas cuando sea apropiado.
--nolocking
Deshabilita el bloqueo. Usar con precaución, comandos concurrentes pueden producir resultados incorrectos.
--persist String
Operación de Reserva Persistente. start: registrar clave local y adquirir reserva. stop: anular registro de clave local, liberando reserva. remove: preemptar y abortar otra clave. clear: eliminar reserva y claves. check: verificar si está iniciado. autostart: iniciar si la bandera de autoarranque del VG está establecida. lvmlocal.conf pr_key o host_id deben estar configurados para usar PR. Para VGs locales, se usa Write Exclusive (WE), y para VGs compartidos Write Exclusive, all registrants (WEAR) se usa. Use --setpersist para automatizar y/o requerir PR.
--profile String
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
--pvmetadatacopies 0|1|2
El número de áreas de metadatos que se reservan en un PV para almacenar metadatos del VG. Cuando es 2, se almacena una copia de los metadatos del VG al principio del PV y una segunda copia se almacena al final. Cuando es 1, se almacena una copia de los metadatos del VG al principio del PV. Cuando es 0, no se almacenan copias de los metadatos del VG en el PV dado. Esto puede ser útil en VGs que contienen muchos PVs (esto impone limitaciones en la capacidad de usar vgsplit posteriormente).
--reportformat basic|json|json_std
Anula el formato de salida actual para los informes, que se define globalmente por la configuración report/output_format en lvm.conf(5). basic es el formato original con columnas y filas. Si hay más de un informe por comando, cada informe va precedido del nombre del informe para su identificación. json produce la salida del informe en formato JSON. json_std produce la salida del informe en formato JSON que es más compatible con el estándar JSON. Ver lvmreport(7) para más información.
--setautoactivation y|n
Establece la propiedad de autoactivación en un VG o LV. Muestra la propiedad con vgs o lvs ""-o autoactivation"". Cuando la propiedad de autoactivación está deshabilitada, el VG o LV no será activado por un comando que realice autoactivación (vgchange, lvchange, o pvscan usando -aay). Si la autoactivación está deshabilitada en un VG, ningún LV será autoactivado en ese VG, y la propiedad de autoactivación del LV no tendrá efecto. Si la autoactivación está habilitada en un VG, la autoactivación puede ser deshabilitada para LVs individuales.
--setlockargs String
Añade o elimina configuraciones de lock_args para un VG compartido. Los lock_args determinan el comportamiento del gestor de bloqueos para el VG. Estas configuraciones solo están permitidas para lock_type sanlock. persist: usa reservas persistentes para la recuperación de bloqueos. lvmlockd preemptará-abortará la reserva persistente de un propietario de bloqueo fallido para que el bloqueo pueda ser adquirido. notimeout: usa bloqueos que no expiran cuando el propietario falla. En este caso, un bloqueo propiedad de un host fallido solo puede ser adquirido usando la característica persist. nopersist: no usa la característica persist. timeout: no usa la característica notimeout. El comportamiento por defecto sin configuraciones es: nopersist y timeout.
--setpersist String
Establece banderas para controlar el comportamiento de reserva persistente. y: establece las banderas require y autostart. require: se requerirá PR para escribir o activar el VG. autostart: PR se iniciará automáticamente. ptpl: usa persistir a través de pérdida de energía en dispositivos. Cuando autostart está habilitado, los comandos de autoactivación y auto-lockstart iniciarán PR primero. lvmlocal.conf pr_key o host_id deben estar configurados para usar PR. Para VGs locales, también se recomienda habilitar system_id.
--shared
Crea un VG compartido usando lvmlockd si LVM está compilado con soporte para lockd. lvmlockd seleccionará el tipo de bloqueo sanlock o dlm dependiendo de qué gestor de bloqueos esté en ejecución. Esto permite que múltiples hosts compartan un VG en dispositivos compartidos. lvmlockd y un gestor de bloqueos deben estar configurados y en ejecución. Ver lvmlockd(8) para más información sobre VGs compartidos.
--systemid String
Especifica el ID del sistema que se dará al nuevo VG, anulando el ID del sistema del host que ejecuta el comando. Normalmente, un VG se crea sin esta opción, en cuyo caso el nuevo VG recibe el ID del sistema del host que lo crea. Usar esta opción requiere precaución porque el ID del sistema del nuevo VG puede no coincidir con el ID del sistema del host que ejecuta el comando, dejando el VG inaccesible para el host. Ver lvmsystemid(7) para más información.
--version
Muestra información de la versión.
--[vg]metadatacopies all|unmanaged|Number
Número de copias de los metadatos del VG que se conservan. Los metadatos del VG se conservan en áreas de metadatos del VG en los PVs del VG, es decir, espacio reservado al principio y/o al final de los PVs. Conservar una copia de los metadatos del VG en cada PV puede reducir el rendimiento en VGs que contienen un gran número de PVs. Cuando este número se establece en un valor distinto de cero, LVM elegirá automáticamente los PVs en los que almacenar los metadatos, utilizando las banderas metadataignore en los PVs para lograr el número especificado. El número también puede ser reemplazado por valores de cadena especiales: unmanaged hace que LVM no administre automáticamente las banderas metadataignore de los PVs. all hace que LVM primero borre las banderas metadataignore en todos los PVs y luego pase a ser no administrado.

VARIABLES

VG
Nombre del Grupo de Volúmenes. Ver lvm(8) para nombres válidos.
PV
Nombre del Volumen Físico, una ruta de dispositivo bajo /dev. Para comandos que gestionan extents físicos, un argumento posicional PV generalmente acepta un sufijo que indica un rango (o múltiples rangos) de extents físicos (PEs). Cuando se omite el primer PE, por defecto es el inicio del dispositivo, y cuando se omite el último PE, por defecto es el final.
Rango de inicio y fin (inclusivo): PV[:PE-PE] ...
Rango de inicio y longitud (contando desde 0): PV[:PE+PE] ...
String
Ver la descripción de la opción para obtener información sobre el contenido de la cadena.
Size[UNIT]
El tamaño es un número de entrada que acepta una unidad opcional. Las unidades de entrada siempre se tratan como valores base dos, independientemente de la capitalización, por ejemplo, 'k' y 'K' se refieren ambos a 1024. La unidad de entrada por defecto se especifica por letra, seguida de |UNIT. UNIT representa otras unidades de entrada posibles: b|B son bytes, s|S son sectores
s de 512 bytes, k|K es KiB, m|M es MiB, g|G es GiB, t|T es TiB, p|P es PiB, e|E es EiB. (Esto no debe confundirse con el control de salida --units, donde las letras mayúsculas significan múltiplos de 1000).

VARIABLES DE ENTORNO

Consulte lvm(8) para obtener información sobre las variables de entorno utilizadas por lvm. Por ejemplo, LVM_VG_NAME generalmente puede ser sustituido por un parámetro VG requerido.

EJEMPLOS

Crear un VG con dos PV, utilizando el tamaño de extensión física por defecto.
vgcreate mi_vg /dev/sdk1 /dev/sdl1
