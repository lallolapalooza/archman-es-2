VLNA(1) Manual de Comandos Generales VLNA(1)

NOMBRE

vlna - añade tilde después de cada preposición no silábica

USO

vlna [opciones] [nombres_de_archivo]

PREFACIO

Existe una regla tipográfica especial checa y eslovaca: no puedes dejar la preposición no silábica al final de una línea y continuar escribiendo texto en la siguiente línea. Por ejemplo, no puedes escribir el texto "v lese" (en un bosque) como "v<nueva-línea>lese". El programa vlna añade el tilde ascii entre dicha preposición y la siguiente palabra, y elimina el/los espacio(s) en ese lugar. Significa que el programa convierte "v lese" a "v~lese". Puedes usar este programa como preprocesador antes de compilar con TeX. Además, puedes establecer otra secuencia para almacenar en lugar del tilde ascii (ver la opción -x).

DESCRIPCIÓN

El programa vlna procesa uno o más archivos, busca las preposiciones no silábicas seguidas de uno o más espacios en estos archivos y convierte dicho/s espacio(s) a tilde ascii para cada ocurrencia.

En el archivo procesado, la actividad del programa puede ser bloqueada por la secuencia %~- y la actividad puede ser restaurada nuevamente por la secuencia %~+. Estas secuencias pueden incluir espacios, lo que significa que % ~- también es una secuencia correcta.

La regla para reconocer una preposición es la siguiente: Un número arbitrario de paréntesis de apertura puede ser escrito antes de la preposición, y antes de estos (opcionales) paréntesis debe haber un espacio, tabulador o nueva línea. La preposición en sí es una palabra de una sola letra, y las letras deben ser del conjunto: {KkSsVvZzOoUuAI}. Ver la opción -v si quieres cambiar este conjunto de letras. Desde la versión 1.2, la secuencia de TeX puede ser escrita antes de la preposición y antes de la llave. Ejemplo: "<nueva-línea>([V lese" se convierte a "<nueva-línea>([V~lese". Otro ejemplo: "\uv{V lese}" se convierte a "\uv{V~lese}".

Se debe incluir uno o más espacios en blanco después de la preposición y antes de la siguiente palabra. El espacio en blanco significa espacio o tabulador. Una nueva línea también puede estar aquí. Todos estos caracteres se eliminan y se reemplazan por un tilde ascii (o por otra cadena, ver opción -x). Si se elimina una nueva línea, se crea otra nueva línea antes de la preposición (y antes de los paréntesis opcionales) para que el número de líneas se mantenga sin cambios. Ejemplo: "... V<nueva-línea><tabulador>lese" se convierte a "...<nueva-línea>V~lese".

El programa verifica la consistencia de los entornos matemáticos de TeX (si la opción -m no se usa). Por ejemplo, la secuencia "$...$$...$" (lo que significa el cambio de modo de visualización dentro del modo matemático de texto) genera una advertencia. Una línea vacía dentro del modo de visualización también genera una advertencia y el programa procesa el texto siguiente como en modo normal (no matemático). La existencia de "$" dentro del modo de visualización es aceptada porque las construcciones como $$..\hbox{..$..$}..$$ están permitidas y son comunes.

La consistencia del modo verbatim se verifica al final del archivo. Si el archivo termina pero el modo verbatim no termina, se imprime una advertencia. Este comportamiento puede ser desactivado por las opciones -n o -w.

El programa suprime el cambio de tilde después de letras que parecen preposiciones pero no lo son, porque la secuencia \TeX o \LaTeX las precede. Ejemplo: "vlastnosti \TeX u jsou" no se convierte a "vlastnosti \TeX u~jsou", porque este texto se imprime (después del procesamiento de TeX) como "vlastnosti TeXu jsou". La letra "u" es un sufijo aquí, no una preposición.

OPCIONES

Las opciones son opcionales y pueden escribirse en cualquier orden, separadas por espacio.

-f
Filtro. Los [nombres_de_archivo] se tratan de la siguiente manera:
vlna -f archivo1 archivo2
La entrada es archivo1, la salida es archivo2.
vlna -f archivo1
La entrada es archivo1, la salida es stdout.
vlna -f
La entrada es stdin, la salida es stdout.
vlna archivo1 [archivo2 [archivo3 ...]]
Si la opción -f se omite, entonces cada archivo se procesa independientemente y se reescribe.
-s
Modo silencioso. No se imprimen mensajes, advertencias ni estadísticas. Solo se imprimen los errores que terminan el programa de forma prematura. Si este parámetro se omite, se imprimen el banner, las advertencias y las estadísticas en stderr.
-r
No crear copias de seguridad. La opción -r es irrelevante si se usa la opción -f. Si las opciones -f y -r no se usan, cada archivo reescrito se guarda con su contenido original en un archivo de copia de seguridad (el nombre del archivo de copia de seguridad es el mismo que el nombre del archivo, solo se usa la tilde en lugar del último carácter).
-v caracteres
El conjunto de caracteres tratados como preposiciones no silábicas se declara con esta opción. Por defecto: -v KkSsVvZzOoUuAI. El espacio entre -v y caracteres es obligatorio.
-x código
El código es una cadena escrita en notación hexadecimal (se requieren números hexadecimales pares). Esta cadena se guardará después de las preposiciones en lugar del tilde ascii que es el valor por defecto. Ejemplo: -x C2A0 se almacenan dos bytes después de cada preposición no silábica, el primer byte tiene el código C2 y el segundo byte tiene el código A0. Este ejemplo significa que se usará un ESPACIO DE NO RUPTURA en codificación UTF8 después de las preposiciones. Otro ejemplo: -x 00A0 el ESPACIO DE NO RUPTURA en codificación UTF16. Otro ejemplo: -x 48454C4C4F se usará la cadena HELLO. El espacio entre -x y código es obligatorio.
-m
Los modos matemáticos ($...$ y $$...$$) se ignoran. Esto significa que las preposiciones no silábicas también se buscan en modo matemático. Por defecto (sin la opción -m): no se realizan cambios en los modos matemáticos porque (por ejemplo) "v" es una variable en modo matemático, no una preposición.
-n
El modo verbatim (\verb<carácter>...<carácter>, \begtt...\endtt) se ignora, lo que significa que el programa puede realizar cambios en el entorno verbatim. Por defecto (sin la opción -n): no se realizan cambios en el modo verbatim.
-l
Modo LaTeX. Los siguientes entornos se tratan como modo de visualización: \begin{display}...\end{display} y \begin{equation}...\end{equation}, y el siguiente entorno se trata como modo verbatim: \begin{verbatim}...\end{verbatim}.
-w
Modo web (web de Knuth, no www:-). Las siguientes secuencias se tratan como verbatim: @<, @d...@*, @espacio o @>|. Esto significa que el código del programa no se modifica en archivos *.w o *.web, solo se procesan los comentarios web.

EJEMPLOS

vlna -m -n -s -r archivo
El programa tiene un comportamiento similar al antiguo programa vlnka.
vlna *.tex
Todos los archivos con la extensión .tex en el directorio actual serán procesados (y posiblemente modificados). (El "*" es una característica del shell de UNIX).
vlna -f archivo > /dev/null
Solo se procesa la verificación de consistencia de los modos matemático y verbatim. No se realizan cambios.
