VIFM(1) Manual de Comandos Generales VIFM(1)

NOMBRE

vifm - gestor de archivos vi

SINOPSIS

vifm [OPCIÓN]...
vifm [OPCIÓN]... ruta
vifm [OPCIÓN]... ruta ruta

DESCRIPCIÓN

Vifm es un gestor de archivos basado en ncurses con atajos de teclado similares a vi. Si usas vi, vifm te da control completo de tu teclado sobre tus archivos sin tener que aprender un nuevo conjunto de comandos.

OPCIONES

vifm se inicia en el directorio actual a menos que se le indique un directorio diferente en la línea de comandos o la opción 'vifminfo' incluya "savedirs" (en cuyo caso se utilizan los últimos directorios visitados como predeterminados).

-
Lee una lista de archivos del flujo de entrada estándar y compone una vista personalizada a partir de ellos (ver sección "Vistas personalizadas"). El directorio de trabajo actual se utiliza como base para las rutas relativas.
<ruta>
Inicia Vifm en la ruta especificada.
<ruta> <ruta>
Inicia Vifm en las rutas especificadas.

Especificar dos directorios activa la vista dividida incluso cuando vifm estaba en modo de vista única al finalizar la ejecución anterior. Para suprimir este comportamiento, el comando :only puede incluirse en el archivo vifmrc.

Cuando solo se encuentra un argumento de ruta en la línea de comandos, el panel izquierdo/superior se establece automáticamente como la vista actual.

También se permiten rutas a archivos en caso de que desees que vifm se inicie con algún archivo comprimido abierto.

--seleccionar <ruta>
Abre el directorio padre de la ruta dada y selecciona el archivo especificado en él.
-f
Hace que vifm, en lugar de abrir archivos, escriba la selección en $VIFM/vimfiles y salga.
--elegir-archivos <ruta>|-
Establece el archivo de salida donde escribir la selección al salir, en lugar de abrir archivos. "-" significa salida estándar. Usa un valor vacío para deshabilitarlo.
--elegir-directorio <ruta>|-
Establece el archivo de salida donde escribir el último directorio visitado al salir. "-" significa salida estándar. Usa un valor vacío para deshabilitarlo.
--delimitador <delimitador>
Establece el separador para la lista de rutas de archivos escritas por vifm. Un valor vacío significa carácter nulo. El valor predeterminado es el carácter de nueva línea.
--al-elegir <comando>
Establece el comando a ejecutar en los archivos seleccionados en lugar de abrirlos. El comando puede usar cualquiera de las macros descritas en la sección "Macros de comandos" a continuación. El comando se ejecuta una vez para toda la selección.
--plugins-dir <ruta>
Directorio de plugins adicional (puede aparecer varias veces). El último agregado tiene la mayor prioridad.
--logging[=<ruta del log de inicio>]
Registra algunos detalles operativos en $XDG_DATA_HOME/vifm/log o $VIFM/log. Si se especifica la ruta opcional del log de inicio y los permisos lo permiten para abrirlo en modo escritura, entonces el registro de la inicialización temprana (antes de que se determinen los directorios de configuración) se coloca allí.
--servidor-lista
Lista los nombres de servidores disponibles y sale.
--nombre-servidor <nombre>
Nombre del servidor de destino o de esta instancia (se agregan números secuenciales en caso de conflicto de nombres).
--remoto
Envía el resto de la línea de comandos a otra instancia de vifm. --nombre-servidor se trata como cualquier otro argumento y debe preceder a --remoto en la línea de comandos. Cuando no hay servidor, sale silenciosamente. No hay límite en la cantidad de argumentos que se pueden procesar. Se puede combinar --remoto con -c <comando> o +<comando> para ejecutar comandos en una instancia de vifm ya en ejecución. Ver también la sección "Cliente-Servidor" a continuación.
--remote-expr
pasa la expresión a un servidor vifm e imprime el resultado. Ver también la sección "Cliente-Servidor" a continuación.
-c <comando> o +<comando>
Ejecuta el modo de línea de comandos <comando> al inicio. Los comandos en tales argumentos se ejecutan en el orden en que aparecen en la línea de comandos. Los comandos con espacios o símbolos especiales deben estar entrecomillados con comillas dobles o simples, o todos los símbolos especiales deben escaparse (la sintaxis exacta depende en gran medida del shell). El argumento "+" es equivalente a "$" y, por lo tanto, selecciona el último elemento de la vista.
--ayuda, -h
Muestra un resumen breve de los comandos y sale de vifm.
--version, -v
Muestra información de la versión y sale.
--sin-configs
Omite la lectura de vifmrc y vifminfo.

Ver la sección "Inicio" a continuación para obtener explicaciones sobre $VIFM.

Marcas

Las marcas se establecen de la misma manera que en vi.

Puedes usar estos caracteres para las marcas [a-z][A-Z][0-9].

m[a-z][A-Z][0-9]
establecer una marca para el archivo en la posición actual del cursor.
'[a-z][A-Z][0-9]
navegar al archivo establecido para la marca.

También hay varias marcas especiales que no se pueden establecer manualmente:

  • ' (comilla simple) - directorio visitado previamente de la vista, por lo tanto, presionar '' permite cambiar entre las dos últimas ubicaciones
  • < - el primer archivo del último bloque seleccionado visualmente
  • > - el último archivo del último bloque seleccionado visualmente

Búsqueda

/expresión regular patrón
buscar archivos que coincidan con la expresión regular en dirección hacia adelante y avanzar el cursor a la siguiente coincidencia.
/
realizar una búsqueda hacia adelante con el elemento superior del historial de patrones de búsqueda.
?expresión regular patrón
buscar archivos que coincidan con la expresión regular en dirección hacia atrás y avanzar el cursor a la coincidencia anterior.
?
realizar una búsqueda hacia atrás con el elemento superior del historial de patrones de búsqueda.
La barra final para directorios se tiene en cuenta, por lo que /\/ busca directorios y enlaces simbólicos a directorios. Por el momento // también funciona, pero esto puede cambiar en el futuro, así que considera escapar la barra si no estás escribiendo el patrón manualmente.
Las coincidencias se seleccionan automáticamente si se establece 'hlsearch'. Habilitar 'incsearch' hace que la búsqueda sea interactiva. Las opciones 'ignorecase' y 'smartcase' afectan la sensibilidad a mayúsculas y minúsculas de las consultas de búsqueda, así como el filtro local y otras cosas detalladas en la descripción de 'caseoptions'.
[count]n
ir al siguiente archivo que coincida con el último patrón de búsqueda. Tiene en cuenta la última dirección de búsqueda.
[count]N
ir al archivo anterior que coincida con el último patrón de búsqueda. Tiene en cuenta la última dirección de búsqueda.
Si la opción 'hlsearch' está establecida, presionar n/N para realizar una búsqueda e ir a un elemento coincidente puede restablecer la selección existente en modo normal. Sucede cuando no hay resultados de búsqueda previos (es decir, ningún archivo con resaltado de la parte coincidente), de lo contrario, la selección se deja como está. Restablecer las coincidencias de búsqueda de cualquier manera (como ejecutar :nohlsearch o presionar Escape) forzará la búsqueda la próxima vez que se presione n/N y hará que se seleccionen los archivos coincidentes.

Ver también la sección "Expresiones regulares".

[count]f[carácter]
buscar hacia adelante el archivo con [carácter] como primer carácter del nombre. La búsqueda rodea el final de la lista.
[count]F[carácter]
buscar hacia atrás el archivo con [carácter] como primer carácter del nombre. La búsqueda rodea el final de la lista.
[count];
encontrar la siguiente coincidencia de f o F.
[count],
encontrar la coincidencia anterior de f o F.

Nota: f, F, ; y , rodean el principio y el final de la lista cuando se usan solos y no rodean cuando se usan como selectores.

Filtros de archivos

Hay tres filtros de archivos básicos:

  • filtro de archivos ocultos (no afecta los directorios especiales "." y "..", cuya apariencia se controla con la opción 'dotdirs'), ver opción 'dotfiles';
  • filtro permanente;
  • filtro local (ver descripción del comando de modo normal "=").

El filtro permanente esencialmente permite definir un grupo de nombres de archivos que no es deseable ver por defecto, como archivos temporales o de copia de seguridad, que podrían crearse junto con los normales. Al igual que normalmente no necesitas ver archivos ocultos (archivos que comienzan con un punto). El filtro local, por otro lado, es para filtrar inmediatamente y temporalmente la lista de archivos actual, para deshacerse de archivos no interesantes en la vista o para permitir el uso del rango % en un :comando.

Para fines de edición más determinista, el filtro permanente se divide en dos partes:

  • una editada explícitamente a través del comando :filter;
  • otra editada implícitamente a través del atajo zf.

Los archivos se prueban contra ambas partes y una coincidencia cuenta si al menos una de las partes coincidió.

Cada lista de archivos tiene su propia copia de cada filtro.
Los archivos filtrados no se comprueban en búsquedas / o :comandos.
Los archivos y directorios se filtran por separado. Esto se hace agregando una barra al nombre de un directorio antes de probar si coincide con el filtro. Ejemplos:
  " filtrar directorios cuyos nombres terminan en '.files'
  :filter /^.*\.files\/$/
  " filtrar archivos cuyos nombres terminan en '.d'
  :filter {*.d}
  " filtrar archivos y directorios cuyos nombres terminan en '.o'
  :filter /^.*\.o\/?$/

Ver también las secciones "Expresiones regulares" y "Patrones".

La semántica es la siguiente:

- si el archivo falta o difiere en la otra vista, se reemplaza
- los pares de archivos se definen por la coincidencia de rutas relativas
La eliminación de archivos obedece la opción 'trash'. Cuando la opción está habilitada, la operación puede ser deshecha/rehecha (aunque los resultados no se mostrarán automáticamente).

Edición de línea de comandos

vifm proporciona una facilidad para editar varios tipos de datos, que normalmente se editan en modo de línea de comandos, en un editor externo (usando el comando especificado por la opción 'vicmd' o 'vixcmd'). Esto tiene al menos dos ventajas sobre el modo de línea de comandos incorporado:
- uno puede usar todo el poder de Vim para editar texto;
- encontrar y reutilizar entradas del historial se vuelve posible.

La facilidad es compatible con cuatro submodos de entrada del modo de línea de comandos

e:
- comando;
- búsqueda hacia adelante;
- búsqueda hacia atrás;
- renombrar archivo (ver descripción de las teclas del modo normal cw y cW).

La edición de la línea de comandos usando un editor externo se activa con el atajo Ctrl-G. También es posible hacer casi lo mismo desde los modos Normal y Visual usando los comandos q:, q/ y q?.

El archivo temporal creado con el propósito de editar la línea tiene la siguiente estructura:

1.
Primera línea, que está vacía o contiene texto ya introducido en la línea de comandos.
2.
La segunda y todas las demás líneas con elementos del historial que comienzan con el más reciente. Alterar estas líneas de cualquier manera no cambiará los elementos del historial almacenados por vifm.

Después de que la aplicación de edición finaliza, la primera línea del archivo se toma como el resultado de la operación, cuando la aplicación devuelve un código de salida cero. Si la aplicación devuelve un error (ver el comando :cquit en Vim), todas las ediciones realizadas en el archivo se ignoran, pero el valor inicial de la primera línea se guarda en el historial correspondiente.

Comandos

Los comandos se ejecutan con :nombre_comando<Enter>

Las líneas comentadas deben comenzar con el símbolo de comilla doble ("), que puede ir precedido de caracteres de espacio en blanco intercalados con dos puntos. Los comentarios en línea se pueden agregar al final de la línea después del símbolo de comilla doble, solo la última línea de un comando multilínea puede contener dicho comentario. No todos los comandos admiten comentarios en línea, ya que no siempre es posible identificarlos sin ambigüedad:

  • la sintaxis entra en conflicto con los nombres de los registros
  • la sintaxis entra en conflicto con la cita de argumentos para comandos
  • los comandos de mapeo/abreviatura pueden expandirse a secuencias arbitrarias que pueden parecer un comentario sin serlo

La mayoría de los comandos tienen dos formas: completa y corta. Ejemplo:

  :noh[lsearch]
Esto significa que el comando completo es nohlsearch, y el corto es noh.

La mayoría de los comandos de línea de comandos restablecen completamente la selección en la vista actual. Sin embargo, hay varias excepciones:

  • `:invert s` muy probablemente deja algunos archivos seleccionados;
  • comando :view;
  • comando :normal (cuando no abandona el modo de línea de comandos);
  • los comandos :if y :else no afectan la selección en caso de ejecución exitosa.

Se puede usar '|' para separar comandos, de modo que pueda ingresar múltiples comandos en una sola línea. Si desea usar '|' en un argumento, prepéndalo con '\'.

:autocmd
:au[tocmd] {evento} {pat} {cmd}
registrar un autocomando para el {evento}, que puede ser:
- DirEnter - activado después de cambiar de directorio
El nombre del evento no distingue entre mayúsculas y minúsculas.

{pat} es una lista separada por comas de patrones globs modificados, que pueden contener variables de entorno o tilde. Todas las rutas usan la barra inclinada ('/') como separador de directorios. El patrón puede comenzar con un '!', lo que lo niega. Los patrones que no contienen barras inclinadas se comparan solo con el último elemento de la ruta (por ejemplo, "dir" en "/path/dir"). Las comas literales se pueden ingresar duplicándolas. Las dos modificaciones en la coincidencia de globs son:
- * - nunca coincide con una barra inclinada (es decir, puede significar un solo nivel de directorio)
- ** - coincide con cualquier carácter (es decir, puede coincidir con una ruta de profundidad arbitraria)

{cmd} es un :comando o varios de ellos separados por '|'.

Ejemplos de patrones:
- conf.d - coincide con el directorio conf.d en cualquier lugar
- *.d - coincide con directorios que terminan en ".d" en cualquier lugar
- **.git - coincide con algo.git, pero no con .git en cualquier lugar
- **/.git/** - coincide con /path/.git/objects, pero no con /path/.git
- **/.git/**/ - coincide solo con /path/.git/ (debido a la barra inclinada final)
- /etc/* - coincide con /etc/conf.d/, /etc/X11, pero no con /etc/X11/fs
- /etc/**/*.d - coincide con /etc/conf.d, /etc/X11/conf.d, etc.
- /etc/**/* - coincide con /etc/ en sí y cualquier archivo debajo de él
- /etc/**/** - coincide con /etc/ en sí y cualquier archivo debajo de él

:au[tocmd] [{evento}] [{pat}]
lista aquellos autocomandos que coinciden con la combinación dada de evento-patrón.
Se pueden omitir {evento} y {pat} para listar todos los autocomandos. Para listar cualquier autocomando para un patrón específico se puede usar el comodín * en lugar de {evento}.
:au[tocmd]! [{evento}] [{pat}]
eliminar autocomandos que coinciden con la combinación dada de evento-patrón. La sintaxis es la misma que para la lista anterior.

  :command mp44 comando

Por ejemplo, considera la siguiente configuración (el orden puede parecer extraño, pero es con fines de demostración):

  filetype *.html,*.htm
          \ {Ver en lynx}
          \ lynx
  filextype *.html,*.htm
          \ {Abrir con dwb}
          \ dwb %f %i &,
  filetype *.html,*.htm
          \ {Ver en links}
          \ links
  filextype *.html,*.htm
          \ {Abrir con firefox}
          \ firefox %f &,
          \ {Abrir con uzbl}
          \ uzbl-browser %f %i &,

1. lynx
2. dwb
3. links
4. firefox
5. uzbl

1. lynx
2. links

Hay dos colores (primer plano y fondo) y un solo atributo de negrita. Por lo tanto, un solo atributo de negrita afecta a ambos colores cuando se utiliza el atributo "reverse" en vifm ejecutándose dentro de un emulador de terminal. Al mismo tiempo, la consola nativa de Linux puede manejar la negrita de los colores de primer plano y fondo de forma independiente, pero para mantener la coherencia con los emuladores de terminal, esto solo está disponible implícitamente mediante el uso de versiones claras de los colores. Este comportamiento podría cambiar en el futuro.

Aunque vifm admite 256 colores en el sentido de que son compatibles con la biblioteca de dibujo de la interfaz de usuario, si podrá usar todos ellos depende en gran medida de su terminal. Para configurar la terminal correctamente, asegúrese de que $TERM en el entorno en el que ejecuta vifm esté establecido en el nombre de una terminal de 256 colores (en *nix también se puede configurar a través de los recursos X), por ejemplo, xterm-256color. Se puede encontrar una lista de nombres de terminales disponibles listando /usr/lib/terminfo/. El número de colores admitidos por la terminal con la configuración actual se puede verificar mediante el comando "tput colors".

Para usar colores de 24 bits, necesita una terminal que los admita, el registro terminfo correspondiente (probablemente termina en "-direct" como en "xterm-direct") y $TERM apuntando a él. Cuando vifm detecta soporte de color directo, los valores "cterm*" se ignoran para los grupos que tienen al menos uno de los valores "gui*" establecidos, de lo contrario se utilizan después de traducirlos a través de una paleta incorporada.

    Rangos

    Los rangos implementados incluyen:
    2,3 - del segundo al tercer archivo de la lista (incluyéndolo)
    % - todo el directorio.
    . - la posición actual en la lista de archivos.
    $ - el final de la lista de archivos.
    't - la posición de la marca t.

    Ejemplos:

      :%delete
    eliminaría todos los archivos del directorio. 
      :2,4delete

    eliminaría los archivos en las posiciones 2 a 4 de la lista.

      :.,$delete

    eliminaría los archivos desde la posición actual hasta el final de la lista de archivos.

      :3delete4

    eliminaría los archivos en las posiciones 3, 4, 5, 6 de la lista.

    Si se proporciona un rango inverso :4,2delete - se muestra un mensaje de consulta y el usuario puede elegir qué hacer a continuación.

    Los comandos incorporados que aceptan un rango son :d[elete] y :y[ank].

    Parámetros de comandos

    Algunos de los comandos de la línea de comandos aceptan parámetros en forma de `-nombre_parametro`. Los argumentos de tales comandos se pueden dividir en dos grupos: parámetros y argumentos posicionales. Los elementos de los dos grupos no se pueden intercalar y los parámetros siempre van primero. La lista de parámetros se termina implícitamente por el primer argumento que no comienza con un guion ("-") o explícitamente mediante el separador "--" (debe ser un argumento separado), que simplemente se descarta. Estas reglas estrictas permiten argumentos posicionales arbitrarios, como nombres de archivo que comienzan con un guion.

    parámetro -skip
    Este parámetro hace que :copy, :move, :alink y :rlink omitan automáticamente los archivos de origen que ya existen en el destino en lugar de negarse a realizar la operación.

    Macros de comandos

    Las macros de comandos se pueden utilizar en comandos de usuario.

    %a
    Argumentos del usuario. Cuando los argumentos del usuario contienen macros, se expanden antes de realizar la sustitución de %a.
    %c %"c
    El archivo actual bajo el cursor.
    %C %"C
    El archivo actual bajo el cursor en el otro directorio.
    %f %"f
    Todos los archivos seleccionados o el archivo actual, pero consulte la sección "Selección" a continuación.
    %F %"F
    Igual que %f, %"f, pero para el panel inactivo.
    %l %"l
    Lista de archivos seleccionados. A diferencia de %f de arriba, esto es solo para selección explícita (es decir, no a través de un rango) y está vacío si no se seleccionan archivos.
    %L %"L
    Igual que %l, %"l, pero para el panel inactivo.
    %b %"b
    Igual que %f %F.
    %d %"d
    Ruta completa al directorio actual.
    %D %"D
    Ruta completa al directorio de la otra lista de archivos.
    %rx %"rx

    Operaciones en segundo plano

    vifm admite la ejecución en segundo plano de operaciones largas y posiblemente bloqueantes como copiar, mover y eliminar archivos. Esto permite continuar usando el editor mientras estas operaciones se ejecutan en segundo plano.

    Para ejecutar comandos como :copy, :move o :delete en segundo plano, simplemente agregue " &" al final del comando.

    Por cada operación en segundo plano se crea un nuevo hilo. La cancelación de trabajos se puede solicitar en el menú :jobs usando el atajo dd.

    Puede verificar si un comando todavía se está ejecutando en el menú :jobs. Los comandos ejecutados en segundo plano muestran el progreso en lugar del ID del proceso al principio de la línea.

    Las operaciones en segundo plano no se pueden deshacer.

    Cancelación

    Tenga en cuenta que la cancelación funciona de manera un poco diferente en la plataforma Windows debido a un mecanismo diferente de propagación de señales de interrupción. Es posible que también necesite usar el atajo Ctrl-Break en lugar de Ctrl-C.

    Hay dos tipos de operaciones que se pueden cancelar:

    • operaciones del sistema de archivos;
    • montaje con FUSE (pero no desmontaje, ya que puede causar pérdida de datos);
    • llamadas a aplicaciones externas.

    Tenga en cuenta que vifm nunca termina aplicaciones, envía la señal SIGINT y deja que la aplicación finalice normalmente.

    Cuando se cancela una de un conjunto de operaciones (por ejemplo, la copia del quinto de 10 archivos), las operaciones posteriores también se cancelan. En este caso, el historial de deshacer contendrá solo las operaciones realmente realizadas.

    Las operaciones canceladas se indican con el sufijo "(cancelled)" agregado al mensaje de información en la barra de estado.

    Operaciones del sistema de archivos

    Actualmente, los siguientes comandos se pueden cancelar: :alink, :chmod, :chown, :clone, :copy, :delete, :mkdir, :move, :restore, :rlink, :touch. La colocación de archivos (con la tecla p/P) también se puede cancelar. No es difícil ver que estas son principalmente operaciones de larga duración.

    Se permite cancelar comandos cuando se repiten para operaciones de deshacer/rehacer para mayor comodidad, pero no se recomienda, ya que las operaciones posteriores de deshacer/rehacer podrían verse bloqueadas por los efectos secundarios de un grupo de operaciones parcialmente cancelado.

    Estos comandos no se pueden cancelar: :empty, :rename, :substitute, :tr.

    Montaje con FUSE

    No se considera un error, por lo que solo se muestra una notificación en la barra de estado.

    Llamadas a aplicaciones externas

    Cada una de estas operaciones se puede cancelar: :apropos, :find, :grep, :locate.

    Selección

    Si hay una selección, se almacena temporalmente antes de proceder, a menos que el archivo bajo el cursor sea parte de esa selección. Esto significa que cuando las macros se expanden para programas :filetype o :filextype, `%f` y `%F` se vuelven equivalentes a `%c` y `%C` respectivamente si el archivo actual no está seleccionado. Por lo tanto, ejecuta la selección ejecutando uno de los archivos seleccionados, de lo contrario, ejecuta un solo archivo, incluso si hay otras entradas seleccionadas.

    Al ejecutar una selección, esta no debe incluir enlaces simbólicos rotos, debe ser consistente y el conjunto de manejadores de archivos debe ser compatible. Consistencia significa que la selección contiene solo directorios (incluidos enlaces a ellos) o solo archivos, pero no una mezcla de ambos.

    La compatibilidad es una verificación más sofisticada, pero está definida de manera natural para que obtenga lo que esperaría. Las siguientes propiedades de la selección se tienen en cuenta al verificar su compatibilidad y decidir cómo manejarla:

    1.
    Si hay archivos para los que no está definido un manejador, entonces todos los archivos se abren usando 'vicmd' o 'vixcmd'.
    2.
    Si todos los manejadores cumplen los siguientes criterios:
    - ejecutados en segundo plano
    - incluyen `%c`/`%"c` y/o `%C`/`%"C`
    - no incluyen `%f`/`%"f` ni `%F`/`%"F`
    entonces cada archivo se ejecuta independientemente de los demás.
    3.
    Si todos los manejadores son iguales, se ejecuta el manejador común. Este manejador podría ignorar la selección y procesar solo el archivo bajo el cursor.
    4.
    De lo contrario, se informa un error, porque los manejadores difieren y no admiten la ejecución paralela.

    Patrones

    :highlight, :filetype, :filextype, :fileviewer y la opción 'classify' admiten globs, expresiones regulares y tipos MIME para hacer coincidir nombres de archivo o sus rutas. A las rutas de directorio se les agrega implícitamente una barra diagonal al final al hacer coincidir un patrón, tenga esto en cuenta para globs o expresiones regulares que terminan con `$`.

    Hay seis formas posibles de escribir un solo patrón:

    1.
    [!]{nombres-separados-por-comas-en-glob}
    2.
    [!]{{rutas-separadas-por-comas-en-glob}}
    3.
    [!]/expresión-regular-de-nombre/[iI]
    4.
    [!]//expresión-regular-de-ruta//[iI]
    5.
    [!]{tipos-mime-separados-por-comas-en-glob}
    6.
    patrón-sin-decorar

    Las cinco primeras formas pueden incluir un signo de exclamación inicial que niega la coincidencia del patrón.

    La última forma se refiere implícitamente a una de las otras. :highlight no acepta la forma sin decorar, mientras que :filetype, :filextype, :fileviewer, :select, :unselect y 'classify' la tratan como una lista de globs de nombres.

    Los patrones de ruta reciben la ruta absoluta del archivo, que incluye su componente de nombre.

    Para combinar varios patrones (AND), asegúrese de utilizar una de las cinco primeras formas y escriba los patrones uno tras otro, de la siguiente manera:

      <text/plain>{*.vifm}
    Tenga en cuenta que si comete un error, toda la cadena se tratará como la sexta forma.

    :filetype, :filextype y :fileviewer aceptan una lista de patrones separados por comas en lugar de un solo patrón, manejando así efectivamente la operación OR sobre ellos:

      <text/plain>{*.vifm},<application/pdf>{*.pdf}
    Las formas que aceptan listas de patrones separadas por comas también las procesan como listas de alternativas.

    Patrones con expresiones regulares

    Los patrones de expresiones regulares no distinguen entre mayúsculas y minúsculas por defecto, consulte la descripción de los comandos, que pueden anular el comportamiento predeterminado.

    Las banderas de las expresiones regulares significan lo siguiente:
    - "i" hace que el filtro no distinga entre mayúsculas y minúsculas;
    - "I" hace que el filtro distinga entre mayúsculas y minúsculas. Se pueden repetir varias veces, pero la última tiene precedencia (por ejemplo, "iiiI" es equivalente a "I" y "IiIi" es lo mismo que "i").

    No hay `^` ni `$` implícitos, así que asegúrese de especificarlos explícitamente si el patrón debe coincidir con el nombre o la ruta completa.

    Patrones con globs

    La sección "Globs" más abajo proporciona una breve descripción de los globs y algunos puntos importantes que se deben conocer sobre ellos.

    Patrones con tipos mime

    La coincidencia de tipos MIME es esencialmente una coincidencia de globs aplicada al tipo MIME de un archivo en lugar de su nombre/ruta. Nota: los tipos MIME no se detectan en Windows.

    Ejemplos

    Asociar `evince` solo a archivos PDF dentro del directorio `/home/user/downloads/` (excluyendo sus subdirectorios):

      :filextype //^/home/user/downloads/[^/]*.pdf$// evince %f

    Expresiones regulares

    Todas las expresiones regulares son modernas/extendidas. Consulte `man 7 regex` para obtener más detalles sobre lo que se admite.

    Las siguientes secuencias especiales se analizan adicionalmente:
    - `\c` fuerza la coincidencia ignorando mayúsculas y minúsculas;
    - `\C` fuerza la coincidencia respetando mayúsculas y minúsculas.

    `\c` y `\C` tienen la máxima prioridad para determinar si la coincidencia distingue entre mayúsculas y minúsculas o no, y existen para anular 'ignorecase', 'smartcase' y las banderas `i`/`I` cuando sea necesario.

    Si hay varias secuencias presentes, la que aparece más tarde tiene precedencia.

    Tenga en cuenta que, a diferencia de Vim, las clases de caracteres se ven afectadas por la configuración y las secuencias que controlan la sensibilidad a mayúsculas y minúsculas en las expresiones regulares.

    Globs

    Los globs no distinguen entre mayúsculas y minúsculas, ya que tiene sentido en el caso general.

    `*`, `?`, `[` y `]` se tratan como símbolos especiales en el patrón. Por ejemplo:

      :filetype * less %c
    coincide con todos los archivos. Se pueden usar clases de caracteres para escapar, por lo que 
      :filetype [*] less %c
    coincide solo con un nombre de archivo, el que contiene solo el símbolo asterisco.

    `*` significa cualquier número de caracteres cualesquiera (posiblemente una subcadena vacía), con una excepción: un asterisco al principio del patrón no coincide con un punto en la primera posición. Por ejemplo:

      :fileviewer *.zip,*.jar zip -sf %c
    asocia el uso del programa `zip` para previsualizar todos los archivos con extensiones `zip` o `jar` como un listado de su contenido, pero `.file.zip` no coincidirá.

    `?` significa cualquier carácter en esa posición. Por ejemplo:

      :fileviewer ?.out file %c
    llama a la herramienta `file` para todos los archivos que tienen exactamente un carácter antes de su extensión (por ejemplo, a.out, b.out).

    Los corchetes designan una clase de caracteres, lo que significa que toda la clase de caracteres coincide con cualquiera de los caracteres listados en ella. Por ejemplo:

      :fileviewer *.[ch] highlight -O xterm256 -s dante --syntax c %c
    hace que vifm llame al programa `highlight` para colorear archivos fuente y de encabezado en lenguaje C para una terminal de 256 colores. Un comando igual sería 
      :fileviewer *.c,*.h highlight -O xterm256 -s dante --syntax c %c

    Dentro de los corchetes, `^` o `!` se pueden usar para negar la clase de símbolos y el símbolo `-` para establecer un rango. `^` y `!` deben aparecer justo después del corchete de apertura. Por ejemplo:

      :filetype *.[!d]/ inspect_dir
    asocia `inspect_dir` como un manejador adicional para todos los directorios que tienen una extensión de un carácter a menos que sea la letra "d". Y

      :filetype [0-9].jpg sxiv
    asocia el visor de imágenes `sxiv` solo para archivos JPEG que contienen un solo dígito en su nombre.

    Si necesita incluir una coma literal, que normalmente separa múltiples globs, duplíquela.

    Opciones locales
    Este es el tipo de opciones que son locales a una vista específica. Por lo tanto, puede establecer un orden de clasificación ascendente para el panel izquierdo y un orden descendente para el panel derecho.

    Además de ser locales a las vistas, cada opción de este tipo también tiene dos valores:

    • local al directorio actual (valor asociado a la ubicación actual);
    • global para el directorio actual (valor asociado al panel).
    La idea es que el directorio actual pueda ser una excepción temporal a la configuración normal de la vista, hasta que cambie el directorio. Usa :setlocal para eso. :setglobal cambia el valor de la vista sin afectar la configuración hasta que cambie el directorio. :set aplica los cambios inmediatamente a todos los valores.

    Mapeos

    Un mapeo de usuario como `nnoremap lhs rhs` define una sustitución del lado izquierdo (LHS) por el lado derecho (RHS) en el flujo de entrada. Un mapeo regular (sin "nore" en el nombre de :command) expande las secuencias reconocidas en el RHS, mientras que un mapeo "noremap" siempre interpreta el RHS como si no se hubieran definido mapeos de usuario y cada tecla tiene su significado incorporado. En la mayoría de los casos, querrá usar la variante noremap y si su RHS incluye LHS, solo la variante noremap funcionará porque la recursión en un mapeo no está permitida.

    Para definir un mapeo, determine en qué modo desea activarlo y use un comando "*noremap" apropiado (por ejemplo, :nnoremap para un mapeo en modo normal). El RHS no tiene que limitarse al modo en el que se inició el mapeo y puede abarcar varios modos.

    Key notation

    In order to simplify the description of keys and their combinations, the following notation is used:

    <key>
    A single key name, like <cr>, <esc>, <space>, <up>, <down>, <left>, <right>, <home>, <end>, <pageup>, <pagedown>, <delete>, <insert>, <tab>, <bs> (backspace).
    <prefix>key
    A key name prefixed with one or more modifier keys: <c-> (Ctrl), <s-> (Shift), <a-> (Alt), <m-> (Meta). Combinations are possible, e.g. <c-s-a-key>.
    <wait>
    Special key that delays mapping evaluation. Used in normal mode mappings only. When <wait> is encountered in a mapping sequence, it causes vifm to wait for the next key to be pressed and then check if it matches any mapping starting with the same sequence. If it does, the mapping is executed. If no mapping matches the sequence after the <wait>, the sequence is discarded and the remaining part of the mapping is executed. This makes it possible to create recursive mappings or mappings that wait for input indefinitely as opposed to default behaviour of triggering the builtin mapping after a delay defined by 'timeoutlen'. Example: 
      nnoremap <wait> tw :set wrap!<cr>
  nnoremap <wait> tn :set number!<cr>
  nnoremap <wait> tr :set relativenumber!<cr>

    <a-s-a>,<a-s-b>,...,<a-s-z> {only for *nix}

    <s-a-a>,<s-a-b>,...,<s-a-z> {only for *nix}
    <m-s-a>,<m-s-b>,...,<m-s-z> {only for *nix}
    <s-m-a>,<s-m-b>,...,<s-m-z> {only for *nix}
    Alt + Shift + some key.
    <a-c-a>,<a-c-b>,...,<a-c-z> {only for *nix}

    <m-c-a>,<m-c-b>,...,<m-c-z> {only for *nix}
    Alt + Ctrl + some key.
    <f0> - <f63>
    functional keys. These also correspond to keys like <c-f1> and can be used in their place.
    <c-f1> - <c-f12>

    functional keys with Control key pressed.
    <a-f1> - <a-f12>, <m-f1> - <m-f12>

    functional keys with Alt key pressed.
    <s-f1> - <s-f12>

    functional keys with Shift key pressed.

    Note that whether and how functional keys work might depend on the terminal and corresponding terminfo record.

    Note that due to the way terminals process their input, several keyboard keys might be mapped to single key code, for example:

    • <cr> and <c-m>;
    • <tab> and <c-i>;
    • <c-h> and <bs> and <del>;
    • etc.

    Most of the time they are defined consistently and don't cause surprises, but <c-h> and <bs> are treated differently in different environments (although they match each other all the time), that's why they correspond to different keys in vifm. As a consequence, if you map <c-h> or <bs> be sure to repeat the mapping with the other one so that it works in all environments. Alternatively, provide your mapping in one form and add one of the following:

      " if mappings with <c-h> in the LHS work
  map <c-h> <bs>
  " if mappings with <bs> in the LHS work
  map <bs> <c-h>

    Also sometimes neither of them might work and it's <del> key which corresponds to your backspace (don't mind the name).

    Whitespace

    vifm removes whitespace characters at the beginning and end of commands. That's why you may want to use <space> at the end of rhs in mappings. For example:

      cmap <f1> man<space>

    will put "man " in line when you hit the <f1> key in the command line mode.

    Expression syntax

    Supported expressions is a subset of what VimL provides.

    Expression syntax summary, from least to most significant:

    expr1 expr2
    expr2 || expr2 .. logical OR

    expr2 expr3
    expr3 && expr3 .. logical AND

    expr3 expr4
    expr4 == expr4 equal
    expr4 != expr4 not equal
    expr4 > expr4 greater than
    expr4 >= expr4 greater than or equal
    expr4 < expr4 smaller than
    expr4 <= expr4 smaller than or equal

    expr4 expr5
    expr5 + expr5 .. number addition
    expr5 - expr5 .. number subtraction

    expr5 expr6
    expr6 . expr6 .. string concatenation

    expr6 expr7
    - expr6 unary minus
    + expr6 unary plus
    ! expr6 logical NOT

    expr7 number number constant
    "string" string constant, \ is special
    'string' string constant, ' is doubled
    &option option value
    $VAR environment variable
    g:var global variable
    v:var builtin variable (read-only)
    function(expr1, ...) function call
    (expr1) nested expression

    ".." indicates that the operations in this level can be concatenated.

    expr1
    -----
    expr2 || expr2

    Arguments are converted to numbers before evaluation.

    Result is non-zero if at least one of arguments is non-zero.

    It's right associative and with short-circuiting, so sub-expressions are evaluated from left to right until result of whole expression is determined (i.e., until first non-zero) or end of the expression.

    expr2
    -----
    expr3 && expr3

    Arguments are converted to numbers before evaluation.

    Result is non-zero only if both arguments are non-zero.

    It's right associative and with short-circuiting, so sub-expressions are evaluated from left to right until result of whole expression is determined (i.e., until first zero) or end of the expression.

    expr3
    -----
    expr4 {cmp} expr4

    Compare two expr4 expressions, resulting in a 0 if it evaluates to false or 1 if it evaluates to true.

    equal ==
    not equal !=
    greater than >
    greater than or equal >=
    smaller than <
    smaller than or equal <=

    Examples:

      'a' ==  'a'         == 1
  'a' >   'b'         == 1
  'a' ==  'b'         == 0
  '2' >   'b'         == 0
   2  >   'b'         == 1
   2  >   '1b'        == 1
   2  >   '9b'        == 0
  -1  == -'1'         == 1
   0  ==  '--1'       == 1

    expr4
    -----
    expr5 + expr5 .. number addition expr5 - expr5 .. number subtraction

    Examples:

      1 + 3 - 3          == 1
  1 + '2'            == 3

    expr5
    -----
    expr6 . expr6 .. string concatenation

    Examples:

      'a' . 'b'           == 'ab'
  'aaa' . '' . 'c'    == 'aaac'

    expr6
    -----

    - expr6 unary minus
    + expr6 unary plus
    ! expr6 logical NOT

    For '-' the sign of the number is changed.
    For '+' the number is unchanged.
    For '!' non-zero becomes zero, zero becomes one.

    A String will be converted to a Number first.

    These operations can be repeated and mixed. Examples:

       --9                == 9
  ---9                == -9
   -+9                == 9
   !-9                == 0
   !''                == 1
  !'x'                == 0
   !!9                == 1

    expr7
    -----

    number number constant
    -----

    Decimal number. Examples:

      0                   == 0
  0000                == 0
  01                  == 1
  123                 == 123
  10000               == 10000

    string
    ------
    "string" string constant

    Note that double quotes are used.

    A string constant accepts these special characters:
    \b backspace <bs>
    \e escape <esc>
    \n newline
    \r return <cr>
    \t tab <tab>
    \\ backslash
    \" double quote

    Examples:

      "\"Hello,\tWorld!\""
  "Hi,\nthere!"

    literal-string
    --------------
    'string' string constant

    Note that single quotes are used.

    This string is taken as it is. No backslashes are removed or have a special meaning. The only exception is that two quotes stand for one quote.

    Examples:

      'All\slashes\are\saved.'
  'This string contains doubled single quotes ''here'''

    option
    ------
    &option option value (local one is preferred, if exists) &g:option global option value &l:option local option value

    Examples:

      echo 'Terminal size: '.&columns.'x'.&lines
  if &columns > 100

    Any valid option name can be used here (note that "all" in ":set all" is a pseudo option). See ":set options" section above.

    environment variable
    --------------------
    $VAR environment variable

    The String value of any environment variable. When it is not defined, the result is an empty string.

    Examples:

      'This is my $PATH env: ' . $PATH
  'vifmrc at ' . $MYVIFMRC . ' is used.'

    global variable
    ---------------
    g:var global variable

    A typed storage of data f

    or use in scripting. Can be created/removed dynamically (via :let and :unlet) and used in expressions.

    variable incorporada
    ----------------
    v:var variable incorporada

    Información expuesta por vifm para su uso en scripting. Dichas variables están predefinidas y son de solo lectura, pero no necesariamente constantes.

    v:count
    count pasado al comando : , 0 por defecto. Se puede usar en mapeos para pasar el count a un comando diferente.
    v:count1
    igual que v:count, pero 1 por defecto.
    v:jobcount
    número de trabajos activos (como se puede ver en el menú :jobs).
    v:session
    nombre de la sesión actual o cadena vacía.
    v:servername
    Ver abajo.
    v:version
    versión de la aplicación como un entero. La versión `x.y.z` se convierte en el número `x*100*100 + y*100 + z`, ejemplos:
    - v0.14 (es decir, v0.14.0) es 1400 (ceros iniciales omitidos)
    - v1.0.2 es 10002
    Los candidatos a lanzamiento no son lanzamientos reales, informan el número del lanzamiento correspondiente.

    llamada a función
    -------------
    function(expr1, ...) llamada a función

    Ver la sección "Funciones" más abajo.

    Ejemplos:

      "'" . filetype('.') . "'"
  filetype('.') == 'reg'

    anidamiento de expresiones
    ------------------
    (expr1) expresión anidada

    Agrupa cualquier otra expresión de complejidad arbitraria, forzando el orden en que se aplican los operadores.

    chooseopt({opt})

    Recupera los valores de las opciones relacionadas con la elección de archivos. {opt} puede ser uno de:
    files devuelve el argumento de --choose-files o una cadena vacía
    dir devuelve el argumento de --choose-dir o una cadena vacía
    cmd devuelve el argumento de --on-choose o una cadena vacía
    delimiter devuelve el argumento de --delimiter o el predeterminado (\n)

    escape({string},{chars})

    Escapa todas las ocurrencias de {chars} en el {string} anteponiendo una barra (``) a ellas. Tenga en cuenta que la barra en sí no se escapa a menos que aparezca en {chars}.

    executable({expr})

    Si {expr} es una ruta absoluta o relativa, comprueba si el destino de la ruta existe y se refiere a un ejecutable; de lo contrario, comprueba si el comando llamado {expr} está presente en los directorios listados en $PATH. Comprueba varias extensiones de ejecutables en Windows. Devuelve un valor booleano que describe el resultado de la comprobación.

    Ejemplo:

      " usa el script visor predeterminado personalizado si está disponible e instalado
  " en un directorio del sistema predefinido, de lo contrario, intenta encontrarlo en otro lugar
  if executable('/usr/local/bin/defviewer')
      fileview * /usr/local/bin/defviewer %c
  else
      if executable('defviewer')
          fileview * defviewer %c
      endif
  endif

    expand({expr})

    Expande variables de entorno y macros en {expr} (en este orden). Devuelve una cadena. Ver la sección "Macros de comandos" más arriba.

    Ejemplos:

      " signo de porcentaje
  :echo expand('%%')
  " la última parte del nombre del directorio del otro panel
  :echo expand('%D:t')
  " variable de entorno $PATH (igual que `:echo $PATH`)
  :echo expand('$PATH')
  " ruta completa al archivo actual con barras invertidas
  :echo expand('%c:p:gs!/!\!')

    extcached({cache}, {path}, {extcmd})

    Almacena en caché el valor del comando externo {extcmd}, actualizándolo automáticamente según sea necesario basándose en la fecha de modificación del monitoreo de una ruta {path}. La caché se invalida cuando el archivo o sus metadatos se actualizan. Una única ruta puede tener múltiples cachés asociadas.

    El valor de {path} se normaliza, pero los enlaces simbólicos en él no se resuelven.

    Ejemplo:

      " muestra el número y el tamaño de los bloques realmente utilizados por un archivo o directorio
  set statusline+=" Uses: %{ extcached('uses',
                                     \ expand('%c'),
                                     \ expand('stat --format=%%bx%%B %c')) }"

    filereadable({path})

    Comprueba si {path} existe y se refiere a una entrada que no es un directorio y si sus permisos permiten la lectura. Devuelve un valor booleano que describe el resultado de la comprobación.

    filetype({file} [, {resolve}])

    Comprueba el tipo de una entrada de vista o de un archivo especificado por su ruta.

    El parámetro {file} puede tener las siguientes formas:
    - '.' para obtener el tipo de archivo sobre el que está el cursor en el panel activo
    - valor numérico en base 1 para obtener el tipo de archivo en el número de línea especificado (solo si no hay caracteres distintos de "+-0123456789")
    - una ruta (añadir "./" para forzar la interpretación de un número o '.' como ruta)

    El parámetro opcional {resolve} se trata como un booleano y especifica si se deben resolver los enlaces simbólicos.

    El resultado es una cadena, que representa el tipo de archivo y es una de las siguientes:
    exe ejecutables
    reg archivos regulares
    link enlaces simbólicos
    broken enlaces simbólicos rotos (aparece solo al resolver)
    dir directorios
    char dispositivos de caracteres
    block dispositivos de bloque
    fifo tuberías
    sock sockets de dominio *nix
    ? tipo de archivo desconocido (normalmente no debería ocurrir) o
    non-file (entradas pseudo en vista de comparación)

    El resultado también puede ser una cadena vacía en caso de argumento inválido.

    fnameescape({expr})

    Escapa el parámetro para que sea adecuado para su uso como argumento de un :comando. La lista de caracteres escapados incluye %, que se duplica.

    Ejemplo de uso:

      " navegar al archivo modificado más recientemente en el directorio actual
  execute 'goto' fnameescape(system('ls -t | head -1'))

    getpanetype()

    Recupera una cadena que describe el tipo del panel actual. Posibles valores de retorno:
    regular listado de archivos regulares de algún directorio
    custom lista de archivos personalizada (%u)
    very-custom lista de archivos muy personalizada (%U)
    tree vista de árbol
    compare vista de comparación

    has({property})

    Permite examinar parámetros internos desde scripts para, por ejemplo, determinar el entorno en el que se está ejecutando la aplicación. Devuelve 1 si la propiedad es verdadera/presente, de lo contrario, se devuelve 0. Actualmente se soportan las siguientes propiedades (cualquier otra cosa dará 0):
    unix se ejecuta en un entorno similar a *nix (incluido Cygwin)
    win se ejecuta en Windows
    #* si existe un manejador de Lua particular

    Ejemplo de uso:

      " omitir usuario/grupo en Windows
  if !has('win')
      let $RIGHTS = '%10u:%-7g '
  endif
  execute 'set' 'statusline="  %t%= %A '.$RIGHTS.'%15E %20d  "'

    input({prompt} [, {initial} [, {completion}]])

    Crea un aviso en la línea de comandos para obtener la entrada del usuario. Se puede proporcionar un valor inicial como segundo parámetro opcional; de lo contrario, se utiliza una cadena vacía.

    El tercer parámetro opcional especifica el tipo de completado, que puede ser uno de:
    dir rutas a directorios
    file rutas a archivos y directorios
    "" (cadena vacía, por defecto) sin completado

    Tenga en cuenta que el comportamiento difiere de Vim, donde la ejecución de un mapeo como

      nnoremap j :echo input('text: ')<cr>input
    lo deja en modo de aviso con "input" escrito. Vifm esperará a que se salga del aviso y luego continuará ejecutando el mapeo.

    Ejemplo de uso:

      nnoremap ,m : let $DIR_NAME = input('mkdir: ', '', 'dir')
             \| if $DIR_NAME != ''
             \|     execute 'mkdir' fnameescape($DIR_NAME)
             \| endif<cr>

    layoutis({type})

    Comprueba si el diseño de la interfaz actual es {type} o no, donde {type} puede ser:
    only modo de panel único
    split modo de panel doble (división vertical u horizontal)
    vsplit división vertical (paneles izquierdo y derecho)
    hsplit división horizontal (paneles superior e inferior)

    Ejemplo de uso:

      " dividir automáticamente verticalmente antes de habilitar la vista previa
  :nnoremap w :if layoutis('only') | vsplit | endif | view!<cr>

    paneisat({loc})

    Comprueba si la posición del panel activo en el diseño actual coincide con una de las siguientes ubicaciones:
    top el panel alcanza el borde superior
    bottom el panel alcanza el borde inferior
    left el panel alcanza el borde izquierdo
    right el panel alcanza el borde derecho

    selected()

    Recupera el número de archivos seleccionados en el panel activo.

    system({command})

    Ejecuta el comando en el shell y devuelve su salida (flujos de salida estándar y error estándar unidos). Se eliminan todos los caracteres de nueva línea finales para permitir una fácil adición a la salida del comando. Ctrl-C debería interrumpir el comando.

    Utilice esta función para consumir la salida de comandos externos que no requieren interacción del usuario y term() para comandos interactivos que utilizan la terminal y son capaces de manejar la redirección de flujos.

    Ejemplo de uso:

      " comando para entrar en el directorio .git/ de un repositorio git (cuando se ejecuta dentro de uno)
  command! cdgit :execute 'cd' fnameescape(system('git rev-parse --git-dir'))

    tabpagenr([{arg}])

    Cuando se llama sin argumentos, devuelve el número de la página de pestañas actual basado en uno.

    Cuando se llama con "$" como argumento, devuelve el número de la última página de pestañas basado en uno, que es lo mismo que el número de pestañas.

    term({command})

    Igual que la función system(),

    pero la interfaz de usuario se apaga durante la ejecución del comando, lo que asegura que las aplicaciones interactivas externas no afectarán la forma en que vifm utiliza la terminal.

    Ejemplo de uso:

      " comando para cambiar de directorio seleccionándolo con fzf
  command! fzfcd :execute 'cd'
                        \ fnameescape(term('find -type d | fzf 2> /dev/tty'))

    Menús y diálogos

    Al navegar a una ruta desde un menú, la ubicación final difiere dependiendo de si la ruta tiene una barra inclinada al final. Los archivos normalmente no tienen barras inclinadas al final, por lo que "archivo/" no funcionará. En el caso de los directorios, hay dos opciones: navegar a un directorio o dentro de él. Para permitir ambos casos de uso, la primera acción se toma para "dir" y la segunda para "dir/".

    Comandos de menú

    :rango navegar a una línea del menú.

    :chistory

    muestra el menú de menús guardados. Ver la sección "Menús y diálogos" para los controles, también ver la sección "Historial de menús".
    :colder
    :col[der]
    carga un menú de navegación anterior si lo hay. Ver también la sección "Historial de menús".
    :cnewer
    :cnew[er]
    carga un menú de navegación más reciente si lo hay. Ver también la sección "Historial de menús".
    :find
    :fin[d]
    el comportamiento coincide con el de :find fuera del menú, excepto que no se acepta ningún rango. Si la vista activa contenía una selección antes de entrar en modo de menú, el comando la tiene en cuenta.
    :grep
    :gr[ep]
    el comportamiento coincide con el de :grep fuera del menú, excepto que no se acepta ningún rango. Si la vista activa contenía una selección antes de entrar en modo de menú, el comando la tiene en cuenta.

    Historial de menús

    Los menús se utilizan a menudo para presentar los resultados de las operaciones (como encontrar o buscar archivos). Una vez cerrados, se pueden recrear repitiendo un comando, pero puede ser inconveniente (requiere cambiar de directorio, encontrar el comando y posiblemente encontrar la posición en un menú) y consumir tiempo volver a ejecutar la operación. Para facilitar la referencia a menús anteriores, vifm almacena hasta los 25 últimos menús de este tipo y proporciona medios para recordarlos utilizando un conjunto familiar de comandos de Vim.

    Como ya se insinuó anteriormente, esto no se aplica a todos los menús, ya que cosas como :version o :commands se basan únicamente en datos internos y no necesitan guardarse. Solo se recuerdan los menús que se derivan de fuentes externas y admiten navegación (como a través de gf).

    Navegando por el historial

    Reabrir el último menú visto de un tipo relevante se hace ejecutando el comando :copen. Una vez abierto, :colder se puede usar para ver menús anteriores y :cnewer para ver menús más recientes.

    Cerrar un menú después de moverse por el historial recuerda la posición de tal manera que ejecutar :copen nuevamente abrirá el último menú visto y permitirá continuar explorando el historial en ambas direcciones.

    El historial siempre contiene menús ordenados de más antiguo a más reciente. Después de abrir más de 25 menús, es probable que el más antiguo se olvide. No se garantiza que esto suceda porque después de ver un menú más antiguo, una nueva entrada reemplaza a todas las más recientes. Por ejemplo, supongamos que el historial se ve así:

     1. :find 1
 2. :find 2
 ...
23. :find 23 (elemento actual)
24. :find 24
25. :find 25

    Ejecutar `:find 11` resulta en:

     1. :find 1
 2. :find 2
 ...
23. :find 23
24. :find 26 (elemento actual)
25. Ninguno

    Para mayor comodidad, :colder y :cnewer se pueden usar en cualquier momento en que te encuentres en un menú, no solo después de :copen. :cnewer funcionará solo si el menú actual no se puede guardar y te has movido hacia atrás en el historial de menús antes. El comportamiento de :colder es el siguiente:
    - si el menú actual se puede almacenar, se comporta como una secuencia :quit, :copen, :colder (el menú actual se almacena de la misma manera que se describe anteriormente)
    - si el menú actual no se puede almacenar, se comporta como una secuencia :quit, :copen

    Visualizando el historial

    Para evitar enumerar menús buscando el que coincide, se puede usar el comando :chistory para obtener una visión general de los menús guardados, quizás buscar uno y luego abrirlo. El comando también está disponible en el modo de menú.

    Vistas personalizadas

    Definición

    Normalmente, las vistas de archivos presentan una lista de archivos de un solo directorio, pero a veces es útil poblarlas con archivos de ubicaciones no relacionadas. Esto es principalmente para lo que sirven las vistas personalizadas.

    Presentación

    Las vistas personalizadas todavía están relacionadas con el directorio en el que estaban antes de que se cargara la lista personalizada. La ruta a ese directorio (directorio original) se puede ver en el título de una vista personalizada.

    Los archivos en el mismo directorio deben tener nombres diferentes, pero las vistas personalizadas están libres de esta restricción, por lo que ver solo los nombres de archivo puede ser bastante confuso. Para dar una idea de dónde provienen los archivos, se utilizan rutas relativas al directorio original de la vista; cuando eso no es posible, se muestran rutas completas.

    Las vistas personalizadas normalmente no contienen archivos inexistentes.

    Navegación/salida

    La navegación en vistas personalizadas difiere un poco en comparación con las vistas regulares.

    gf - actúa de manera similar a gf en enlaces simbólicos y navega al archivo en su ubicación real.

    h - va al nodo padre más cercano en la vista de árbol o termina la vista personalizada, devolviendo al directorio original.

    gh - termina la vista personalizada devolviendo al directorio original.

    Ir al directorio padre de otras maneras (ya sea abriendo la entrada ".." o ejecutando `:cd ..`) también causa la terminación y el regreso a la ubicación original.

    Todas las demás formas de cambiar de ubicación (por ejemplo, marcas, marcadores, :cd, :sync) también causan la terminación de la vista personalizada.

    Historial

    La lista personalizada solo existe mientras es visible; una vez que se abandona, no se puede volver a ella, por lo que no hay rastro de ella en ningún historial.

    Filtros

    Solo el filtro local afecta el contenido de la vista. Esto es intencional. Presumiblemente, si uno carga una lista particular, precisamente esa lista debe mostrarse (excepto por las rutas inexistentes, que se ignoran).

    Búsqueda

    Aunque los nombres de los directorios son visibles en la lista, no son buscables. Solo se tienen en cuenta los nombres de archivo (podría cambiar en el futuro, la búsqueda de líneas completas parece bastante razonable).

    Ordenación

    Contrariamente a la búsqueda, la ordenación por nombre funciona en la parte visible completa de la ruta del archivo.

    Resaltado

    El nombre completo del archivo se resalta como una sola entidad, incluso si hay elementos de directorio.

    Actualizaciones

    Pueden ocurrir recargas, aunque no son automáticas debido a que los archivos están dispersos en diferentes lugares. En una recarga, se eliminan los archivos inexistentes y se actualizan los metadatos de todos los demás archivos.

    Una vez que la vista personalizada olvida un archivo, no lo agregará de nuevo incluso si se crea nuevamente. Por lo tanto, es normal no ver un archivo previamente afectado por una operación que luego fue deshecha.

    Operaciones

    Todas las operaciones que agregan archivos están prohibidas para las vistas personalizadas. Por ejemplo, mover/copiar/poner archivos en una vista personalizada no funciona, porque no es una ubicación real del sistema de archivos.

    Por otro lado, las operaciones que utilizan archivos de una vista personalizada como fuente (por ejemplo, cortar, copiar, mover un archivo de una vista personalizada, eliminar) y las operaciones que modifican nombres están permitidas.

    Comparar vistas

    Clases

    :compare puede producir cuatro resultados diferentes dependiendo de los argumentos:
    - vista de comparación única ("ofone" y ya sea "listall" o "listdups");
    - vista personalizada única ("ofone" y "listunique");
    - dos vistas de comparación ("ofboth" y ya sea "listall" o "listdups");
    - dos vistas personalizadas ("ofboth" y "listunique").

    Los dos primeros muestran archivos de un solo árbol de sistemas de archivos. Aquí, los duplicados son archivos que tienen al menos una copia en el mismo árbol. Los otros dos tipos de operación comparan dos árboles, en los cuales los duplicados son archivos que se encuentran en ambos árboles.

    Las listas de archivos únicos se presentan en vistas personalizadas porque no hay agrupamiento de archivos t

    Comparación

    La comparación de archivos es una característica de vifm que te permite encontrar diferencias entre dos árboles de directorios. La vista de comparación se implementa en la parte superior de las vistas personalizadas. Las vistas personalizadas son vistas que se crean para un propósito específico y son diferentes de las vistas regulares. Las vistas personalizadas se crean con el comando :compare. El comando :compare crea una vista que contiene archivos de ambas vistas, mostrando solo los archivos que son diferentes entre ellas.

    La vista de comparación tiene las siguientes propiedades:

    • Las vistas que se comparan se desplazan sincrónicamente.
    • Los cursores de las vistas se sincronizan.
    • El filtrado local está deshabilitado.
    • La ordenación está deshabilitada permanentemente.
    • Los archivos eliminados ocultan sus pares correspondientes.
    • La salida de una de las vistas termina inmediatamente con la otra.
    • Los archivos que indican la ausencia de un archivo equivalente tienen nombres vacíos y se pueden emparejar como tales.

    La vista de comparación no puede cambiar a una vista similar a ls, ya que es incapaz de mostrar datos tipo diff. La vista de comparación tiene una segunda columna que muestra el ID del archivo, los archivos con el mismo ID se consideran iguales. La configuración de las columnas de la vista está predefinida.

    Los argumentos que se pasan al comando :compare se dividen en siete categorías, cada una con su propio prefijo y responsable de una propiedad particular de la operación.

    Creación

    ¿Qué archivos comparar?:
    - ofboth - compara los archivos de dos paneles entre sí;
    - ofone - compara los archivos del mismo directorio.

    ¿Cómo se comparan los archivos?:
    - byname - solo por su nombre;
    - bysize - solo por su tamaño;
    - bycontents - por los datos que contienen (se utiliza una combinación de tamaño y hash de un pequeño fragmento de contenido como primera aproximación, por lo que no te preocupes demasiado por los archivos grandes; los archivos no regulares como las tuberías se suponen vacíos).

    ¿Qué archivos mostrar?:
    - listall - todos los archivos;
    - listunique - solo archivos únicos;
    - listdups - solo archivos duplicados.

    ¿Cómo se agrupan los resultados? (no tiene efecto si se especifica "ofone"):
    - groupids - los archivos considerados idénticos son siempre adyacentes en la salida;
    - grouppaths - se prefiere el orden del sistema de archivos (esto también permite mostrar archivos con nombres idénticos como desajustes).

    ¿Qué archivos omitir?:
    - skipempty - ignora los archivos vacíos.

    Ajustes de comparación:
    - withicase - ignora mayúsculas/minúsculas al comparar nombres/rutas de archivos;
    - withrcase - respeta mayúsculas/minúsculas al comparar nombres/rutas de archivos.

    ¿Qué resultados mostrar? (no tiene efecto para la comparación de un solo panel):
    - showidentical - controla la visibilidad de archivos idénticos;
    - showedifferent - controla la visibilidad de archivos modificados;
    - showuniqueleft - controla la visibilidad de archivos únicos superiores/izquierdos;
    - showuniqueright - controla la visibilidad de archivos únicos inferiores/derechos.

    Cada argumento puede aparecer varias veces, el último del grupo define el comportamiento. Todos los argumentos alteran el comportamiento predeterminado en lugar de sustituirlo.

    Cuando no se especifica ni "withicase" ni "withrcase", las mayúsculas/minúsculas dependen del sistema operativo en ejecución y del sistema de archivos en el que se encuentran los archivos.

    Salida

    La comparación de dos vistas da como resultado que entren en un estado especial implementado sobre vistas personalizadas. Ambas vistas salen de este estado cuando alguna de ellas deja de ser personalizada. Las vistas personalizadas terminan al cambiar a una ubicación diferente o como resultado de un comando como :regular. Ir al directorio padre (como con la tecla h o el comando :cd ..) devuelve a un estado regular sin cambiar la ubicación. Consulte la sección "Vistas personalizadas" para obtener más detalles.

    Ejemplos

    Los valores predeterminados corresponden probablemente al caso de uso más común de comparar archivos en dos árboles con agrupación por rutas, por lo que los siguientes comandos son equivalentes:

      :compare
  :compare bycontents grouppaths
  :compare bycontents listall ofboth grouppaths
  :compare showidentical showdifferent showuniqueleft showuniqueright

    Otro caso de uso es encontrar duplicados en el subárbol actual:

      :compare listdups ofone

    El siguiente comando lista los archivos que son únicos para cada panel:

      :compare listunique

    Apariencia

    La vista no puede cambiar a una vista similar a ls, ya que no puede mostrar datos tipo diff.

    Las vistas de comparación tienen una segunda columna que muestra el ID del archivo; los archivos con el mismo ID se consideran iguales. La configuración de las columnas de la vista está predefinida.

    La barra de estado solo muestra el resultado inicial de la comparación y puede estar desactualizada.

    Comportamiento

    Cuando dos vistas se comparan entre sí, los siguientes cambios en el comportamiento regular se aplican:
    - las vistas se desplazan sincrónicamente (como si se hubiera establecido 'scrollbind');
    - los cursores de las vistas se sincronizan;
    - el filtrado local está deshabilitado (sus resultados no tendrían sentido);
    - zd excluye grupos de archivos idénticos adyacentes, 1zd devuelve el comportamiento habitual;
    - la ordenación está permanentemente deshabilitada (el orden está fijo);
    - los archivos eliminados ocultan sus pares correspondientes;
    - la salida de una de las vistas termina inmediatamente con la otra;
    - el cambio de nombre de archivos no está bloqueado, pero no se tiene en cuenta y puede requerir la regeneración de la comparación;
    - las entradas que indican la ausencia de un archivo equivalente tienen nombres vacíos y se pueden emparejar como tales;
    - cuando se enumeran los archivos únicos de ambas vistas, las vistas personalizadas pueden estar vacías, esta ausencia de archivos únicos se indica claramente.

    Una vista de comparación tiene propiedades similares (las que son aplicables a un solo panel).

    Los archivos se recopilan de la siguiente manera:
    - recursivamente comenzando en la ubicación actual de la vista;
    - los archivos ocultos (dot files) se excluyen si la vista los oculta en el momento de la comparación, también se respetan los filtros de nombres de archivos, por lo que terminas comparando lo que ves;
    - los directorios no se tienen en cuenta;
    - los enlaces simbólicos a directorios se ignoran.

    Inicio

    Al iniciar, vifm determina varias variables que se utilizan durante la ejecución. Se determinan en el orden en que aparecen a continuación.

    En sistemas *nix, $HOME normalmente está presente y se usa tal cual. En sistemas Windows, vifm intenta encontrar el directorio de inicio correcto en el siguiente orden:
    - variable $HOME;
    - variable $USERPROFILE (solo en Windows);
    - una combinación de las variables $HOMEDRIVE y $HOMEPATH (solo en Windows).

    vifm intenta encontrar el directorio de configuración correcto verificando los siguientes lugares:
    - variable $VIFM;
    - directorio padre del archivo ejecutable (solo en Windows);
    - directorio $HOME/.vifm;
    - directorio $APPDATA/Vifm (solo en Windows);
    - directorio $XDG_CONFIG_HOME/vifm;
    - directorio $HOME/.config/vifm.

    vifm intenta encontrar el archivo de configuración correcto verificando los siguientes lugares:
    - variable $MYVIFMRC;
    - vifmrc en el directorio padre del archivo ejecutable (solo en Windows);
    - archivo $VIFM/vifmrc.

    Configurar

    Consulte la sección "Inicio" anterior para obtener explicaciones sobre $VIFM y $MYVIFMRC.

    El archivo vifmrc contiene comandos que se ejecutarán al iniciar vifm. Hay dos archivos de este tipo: global y local. El global se encuentra en {prefix}/etc/vifm/vifmrc, consulte la descripción de la variable $MYVIFMRC para ver el algoritmo de búsqueda utilizado para encontrar el vifmrc local. El vifmrc global se carga antes que el local, de modo que este último pueda redefinir cualquier cosa configurada globalmente.

    Utilice vifmrc para establecer configuraciones, asignaciones, tipos de archivo, etc. Para usar comandos de varias líneas, preceda cada línea siguiente con una barra (el espacio en blanco antes de la barra se ignora, pero todos los espacios al final de las líneas se guardan). Por ejemplo:

      set
      \smartcase

    equivale a "setsmartcase". Cuando

      set<espacio aquí>
      \ smartcase

    equivale a "set smartcase".

    El archivo $VIFM/vifminfo contiene el estado genérico de la aplicación. Puede controlar qué se almacena en vifminfo estableciendo la opción 'vifminfo'. Vifm siempre escribe este archivo al salir a menos que la opción 'vifminfo' esté vacía. Las marcas, marcadores, comandos, historiales, tipos de archivo, visores de archivos y registros del archivo se fusionan con la configuración de vifm (que tiene mayor prioridad).

    En general, la configuración en tiempo de ejecución tiene mayor prioridad durante la fusión, pero hay algunas excepciones:

    • la pila de directorios almacenada en el archivo no se sobrescribe a menos que algo cambie en la instancia de vifm que realiza la fusión;
    • cada marca o marcador está marcado con una marca de tiempo, de modo que el valor más reciente no se sobrescribe por uno anterior, por lo tanto, no importa de dónde provenga, el más reciente gana;
    • todos los historiales se marcan con marcas de tiempo al almacenarse, esto significa que la última instancia que sale pone sus elementos en la parte superior de la lista;
    • las pestañas solo se fusionan si tanto la instancia actual como el estado almacenado contienen exactamente una pestaña de cualquier tipo.

    El directorio $VIFM/scripts puede contener scripts de shell. vifm modifica su variable de entorno PATH para permitir al usuario ejecutar esos scripts sin especificar la ruta completa. Todos los subdirectorios de $VIFM/scripts se agregarán también a PATH. Un script en un subdirectorio superpone un script con el mismo nombre en todos sus directorios padre.

    Los directorios $VIFM/colors/ y {prefix}/etc/vifm/colors/ contienen esquemas de colores. Los esquemas de colores disponibles se buscan en ese orden, por lo que en caso de conflicto de nombres, el que está en $VIFM/colors/ gana.

    Cada esquema de colores debe tener la extensión ".vifm". Este no fue el caso antes y por esta razón se aplican las siguientes reglas durante la búsqueda:

    • si no hay un archivo con extensión .vifm, se enumeran todos los archivos regulares;
    • de lo contrario, solo se enumeran los archivos con extensión .vifm (con la extensión truncada).

    Sesiones

    Las sesiones proporcionan una forma de tener múltiples configuraciones de tiempo de ejecución persistentes. Piense en ellas como archivos vifminfo de segundo nivel además del archivo de primer nivel utilizado por todas las sesiones. En otras palabras, no son un reemplazo para el archivo vifminfo que existe sin sesiones, sino una adición a él. Uno puede vaciar la opción 'vifminfo' y depender únicamente de las sesiones, pero en la práctica, es posible que desee compartir algún estado entre instancias en diferentes sesiones o tener un estado "fuera de sesión" para tareas que no merecen una sesión propia.

    Esto conduce a una estructura de dos niveles donde los datos en los archivos de sesión tienen mayor prioridad que los datos en los archivos vifminfo (donde esto tiene sentido), siguiendo las mismas reglas que rigen la fusión del archivo vifminfo. Además de eso, los elementos del historial de los archivos de sesión nunca se ordenan antes que los elementos del historial del archivo vifminfo.

    Formato

    Las sesiones tienen el formato de los archivos vifminfo, no consisten en una secuencia de comandos de línea de comandos y no están destinadas a ser cargadas mediante el comando :source.

    Almacenamiento y nombres

    El directorio `$VIFM/sessions/` sirve como almacenamiento para las sesiones. En consecuencia, los nombres deben ser nombres de archivo válidos. La estructura del almacenamiento es plana, lo que significa que no hay subdirectorios, por lo que los nombres de las sesiones no pueden contener barras.

    Modelo de uso

    A diferencia de Vim, vifm automatiza la gestión básica de sesiones. Puede iniciar, cambiar, detener o eliminar una sesión utilizando medios integrados.

    La sesión actual se guarda al mismo tiempo que se guarda vifminfo (en salidas normales o explícitamente con el comando :write) y justo antes de cambiar a otra sesión. Para evitar guardar en estos casos, use el comando :session para desvincularse (sin guardar) de una sesión antes de continuar.

    Montajes automáticos de FUSE

    vifm tiene soporte integrado para montajes automáticos de sistemas de archivos FUSE. Se implementa utilizando el mecanismo de asociaciones de archivos. Para habilitar los montajes automáticos, es necesario utilizar una línea de programa con formato especial en los comandos filetype o filextype. Estos utilizan macros especiales, que difieren de las macros en comandos no relacionados con FUSE. Actualmente se soportan tres formatos:

    1) FUSE_MOUNT Este formato debe usarse en caso de que toda la información necesaria para montar todos los archivos de un tipo particular sea la misma. Por ejemplo, montar archivos tar no requiere ninguna opción específica del archivo.

    Línea de formato:
    FUSE_MOUNT|montador %SOURCE_FILE %DESTINATION_DIR [%FOREGROUND]

    Comando de ejemplo de tipo de archivo:

      :filetype FUSE_MOUNT|fuse-zip %SOURCE_FILE %DESTINATION_DIR

    2) FUSE_MOUNT2 Este formato permite usar archivos con formato especial para realizar el montaje y es útil para montar sistemas remotos, por ejemplo, sistemas de archivos remotos sobre ftp o ssh.

    Línea de formato:
    FUSE_MOUNT2|montador %PARAM %DESTINATION_DIR [%FOREGROUND]

    Comando de ejemplo de tipo de archivo:

      :filetype *.ssh FUSE_MOUNT2|sshfs %PARAM %DESTINATION_DIR

    Contenido de ejemplo del archivo:

      root@127.0.0.1:/

    3) FUSE_MOUNT3

    Este formato es equivalente a FUSE_MOUNT, pero omite el desmontaje. Es útil para casos en los que no se necesita desmontar, como al usar AVFS.

    Comando de ejemplo :filetype:

      :filetype *.tar,*.tar.bz2,*.tbz2,*.tgz,*.tar.gz,*.tar.xz,*.txz,*.deb
       \ {Montar con avfs}
       \ FUSE_MOUNT3|mount-avfs %DESTINATION_DIR %SOURCE_FILE

    Script de ayuda de ejemplo `mount-avfs`:

      #!/bin/sh
  dest=$1
  file=$2
  rmdir "$dest"
  ln -s "$HOME/.avfs$file#/" "$dest"

    Todas las macros % son expandidas por vifm en tiempo de ejecución y tienen el siguiente significado:
    - %SOURCE_FILE se reemplaza por la ruta completa del archivo seleccionado;
    - %DESTINATION_DIR se reemplaza por la ruta completa del directorio de montaje, que es creado por vifm basándose en el valor de la opción 'fusehome';
    - El valor de %PARAM se llena desde la primera línea del archivo (línea completa), aunque en el futuro puede cambiarse al contenido completo del archivo;
    - %FOREGROUND significa que desea ejecutar el comando de montaje como un comando regular (necesario para poder proporcionar entrada para la comunicación con el montador de forma interactiva).

    %FOREGROUND es una macro opcional. Otras macros no son obligatorias, pero los comandos de montaje probablemente no funcionarán sin ellas.

    %CLEAR es el nombre obsoleto de %FOREGROUND, que todavía se admite, pero podría eliminarse en el futuro. Se desaconseja su uso.

    A diferencia de las macros en otros lugares, estas solo se reconocen si aparecen al final de un comando o si van seguidas de un espacio. No hay forma de escapar % tampoco. Estas son limitaciones históricas, que podrían abordarse en el futuro.

    Los sistemas de archivos FUSE montados se desmontarán automáticamente en dos casos:

    • cuando vifm se cierra (con ZZ, :q, etc. o cuando es terminado por una señal);
    • cuando sales explícitamente del punto de montaje subiendo a su directorio padre (con h, Enter en "../" o ":cd ..") y el otro panel no está en el mismo directorio o sus subdirectorios.

    Apariencia de vista

    vifm soporta la visualización de la lista de archivos de dos maneras diferentes:

    • en modo tabla, donde se pueden configurar múltiples columnas usando la opción 'viewcolumns' (ver sección "Vista de columnas" más adelante para más detalles);
    • en una lista multiconlumna que se parece casi a la salida del comando `ls -x` (ver sección "Vista tipo ls" más adelante para más detalles).

    La apariencia es local para cada vista y se puede elegir cambiando el valor de la opción booleana 'lsview'.

    Dependiendo de la apariencia de la vista, algunas teclas cambian su significado para permitir un movimiento del cursor más natural. Esto concierne principalmente a las teclas h, j, k, l y otras similares de navegación.

    Además, algunas opciones pueden ser ignoradas si no afectan la visualización de la vista en la apariencia seleccionada. Por ejemplo, el valor de 'viewcolumns' cuando 'lsview' está activado.

    Vista tipo ls

    Cuando esta apariencia de vista está habilitada al establecer la opción 'lsview', vifm mostrará los archivos en múltiples columnas. El número de columnas depende de la longitud del nombre de archivo más largo presente en el directorio actual de la vista. Toda la lista de archivos se reajusta automáticamente al cambiar de directorio, o al cambiar el tamaño de la terminal o de la vista.

    La apariencia de la vista se acerca a la salida del comando `ls -x`, por lo que los archivos se listan de izquierda a derecha en filas.

    En este modo, los comandos de manipulación de archivos (por ejemplo, d) no funcionan línea por línea como lo hacen en Vim, ya que tales operaciones serían poco comunes para tareas de manipulación de archivos. Por lo tanto, por ejemplo, dd eliminará solo el archivo actual.

    Por defecto, la vista se rellena por líneas, 'lsoptions' se puede usar para obtener el relleno por columnas.

    Tenga en cuenta que la vista de árbol y la vista de comparación inhiben la vista tipo ls.

    Vista de columnas

    Las columnas de la vista se describen mediante una lista separada por comas de descripciones de columnas, cada una de las cuales tiene el siguiente formato
    [ '-' | '*' ] [ fw ( [ '.' tw ] | '%' ) ] '{' tipo | literal '}' '.'{0,3}
    donde fw significa ancho completo, tw significa ancho de texto, bar es o lógico, los corchetes cuadrados denotan partes opcionales y las llaves definen el rango de repeticiones de un símbolo que las precede.

    Así, básicamente consta de cuatro partes:
    1. Especificador de alineación opcional
    2. Especificador de ancho opcional
    3. Nombre de columna obligatorio
    4. Especificador de recorte opcional

    Especificador de alineación

    Es un signo de menos o asterisco opcional como primer símbolo de la cadena.

    Especifica el tipo de alineación del texto dentro de una columna. Se admiten tres tipos:

    • alineación izquierda 
        set viewcolumns=-{name}
    • alineación derecha (por defecto) 
        set viewcolumns={name}
    • alineación central

      Es como la alineación izquierda, pero cuando el texto es más grande que la columna, se corta por la mitad (por lo que siempre son visibles el principio y el final del campo).

        set viewcolumns=^{name}
    • alineación dinámica

      Es como la alineación izquierda, pero cuando el texto es más grande que la columna, la alineación se realiza a la derecha (por lo que siempre es visible parte del campo).

        set viewcolumns=*{name}

    Especificador de ancho

    Es un número seguido de un signo de porcentaje, dos números (el segundo debe ser menor o igual al primero) separados por un punto o un solo número.

    Especifica el ancho de la columna y sus unidades. Hay tres tipos de tamaño:

    • tamaño absoluto - el ancho de la columna se especifica en caracteres 
        set viewcolumns=-100{name},20.15{ext}

      resulta en dos columnas con longitudes de 100 y 20 y un espacio reservado de cinco caracteres a la izquierda de la segunda columna.

    • tamaño relativo (porcentaje) - el ancho de la columna se especifica en porcentajes del ancho de la vista 
        set viewcolumns=-80%{name},15%{ext},5%{mtime}

      resulta en tres columnas con longitudes de 80/100, 15/100 y 5/100 del ancho de la vista.

    • tamaño automático (por defecto) - el ancho de la columna se determina automáticamente 
        set viewcolumns=-{name},{ext},{mtime}

      resulta en tres columnas con una longitud de un tercio del ancho de la vista. No hay ajuste de tamaño al contenido, ya que ralentizaría la representación.

    Las columnas de diferentes tipos de dimensionamiento se pueden mezclar libremente en una sola vista. Sin embargo, a veces algunas de las columnas pueden verse parcialmente o ser completamente invisibles si no hay suficiente espacio para mostrarlas.

    Contenido de las columnas

    Normalmente es una clave de ordenación rodeada de llaves, por ejemplo:

      {name},{ext},{mtime}

    Los tipos {name} e {iname} son iguales y ambos están presentes para compatibilidad con la opción 'sort'.

    Los siguientes tipos de columna no tienen claves de ordenación correspondientes:

    • {root} - muestra el nombre sin extensión (como complemento de {ext})
    • {fileroot} - muestra el nombre sin extensión para cualquier cosa excepto directorios y enlaces simbólicos a directorios (como complemento de {fileext})

    Las llaves vacías ({}) se reemplazan con la columna secundaria predeterminada para la clave de ordenación primaria. Así, después del siguiente comando, la vista se mostrará casi como si 'viewcolumns' estuviera vacío, pero añadiendo puntos suspensivos para nombres de archivo largos:

      set viewcolumns=-{name}..,6{}.

    El último tipo de valor de columna es una cadena literal. El literal se utiliza como valor de columna para cada fila. La sintaxis es "{# literal}", ejemplos:

      " relleno de doble carácter en ambos lados
  set viewcolumns='2{#},*{name}..,{},2{#}'
  " borde simulado entre columnas
  set viewcolumns='*{name}..,{#|},6{}'
  " borde simulado con relleno entre columnas
  set viewcolumns='*{name}..,{# | },6{}'

    Esto se puede usar para dibujar separadores de columnas. Tenga en cuenta que para mayor comodidad, los literales tienen valores predeterminados diferentes: truncamiento y tamaño absoluto determinado automáticamente, que es lo que normalmente desea para ellos. Asegúrese de citar o escapar los espacios, las barras verticales y otros símbolos especiales cuando los use como parte de los literales.

    Especificador de recorte

    Son de uno a tres puntos después de la llave de cierre en el formato de columna.

    Especifica el tipo de truncamiento de texto si no cabe en la columna. Actualmente se admiten tres tipos:

    • truncamiento - el texto se trunca 
        set viewcolumns=-{name}.

      resulta en el truncamiento de nombres que son demasiado largos para caber en la vista.

    • adición de puntos suspensivos - se añaden puntos suspensivos a la izquierda o derecha cuando es necesario 
        set viewcolumns=-{name}..

      resulta en que se añaden puntos suspensivos al final de nombres de archivo demasiado largos.

    • ninguno (por defecto) - el texto puede traspasar los límites de la columna 
        set viewcolumns=-{name}...,{ext}

      resulta en que los nombres de archivo largos pueden escribirse parcialmente en la columna ext.

    Directorio de papelera

    \n

    vifm tiene soporte para el directorio de papelera, que se utiliza como almacenamiento temporal para archivos eliminados o archivos que fueron cortados. El uso de la papelera se controla mediante la opción 'trash', y la ruta exacta a la papelera se puede establecer con la opción 'trashdir'. El directorio de papelera en vifm difiere del sistema global por defecto, debido a posibles incompatibilidades de almacenamiento de archivos eliminados entre diferentes administradores de archivos. Pero se puede establecer 'trashdir' a \"~/.local/share/Trash\" para usar un directorio de papelera \"estándar\".

    \n

    Hay dos escenarios de uso de la papelera en vifm:

    \n
    \n
    \n
    1.
    \n
    Como lugar para almacenar archivos que fueron cortados con \"d\" y pueden ser pegados en algún otro lugar del sistema de archivos.
    \n
    2.
    \n
    Como almacenamiento de archivos que se eliminan pero aún no se purgan.
    \n
    \n
    \n

    El primer escenario utiliza operaciones de eliminación (\"d\") para colocar archivos en la papelera y operaciones de pegar (\"p\") para restaurar archivos desde el directorio de papelera. Tenga en cuenta que tales operaciones mueven archivos hacia y desde el directorio de papelera, lo que puede ser una operación larga en caso de diferentes particiones o unidades remotas montadas localmente.

    \n

    El segundo escenario utiliza operaciones de eliminación (\"d\") para mover archivos al directorio de papelera y el comando de línea de comandos :empty para purgar todos los archivos eliminados previamente.

    \n

    Las operaciones de eliminación y pegado dependen de los registros, que pueden apuntar a archivos en el directorio de papelera. Normalmente, no hay archivos inexistentes en los registros, pero vifm no realiza un seguimiento de las modificaciones en el directorio de papelera, por lo que no se debe esperar que el valor de los registros sea absolutamente correcto si el directorio de papelera se modificó de forma no intencionada. Pero esto no conducirá a ningún problema con las operaciones, ya que ignoran los archivos inexistentes.

    \n

    Cliente-Servidor

    \n

    vifm admite la ejecución remota de comandos en modo de línea de comandos, el cambio remoto de directorios y la evaluación de expresiones. Esto es posible utilizando los argumentos de línea de comandos --remote y --remote-expr.

    \n

    Para ejecutar un comando de forma remota, combine el argumento --remote con -c <comando> o +<comando>. Por ejemplo:

    \n
    \n  vifm --remote -c 'cd /'\n  vifm --remote '+cd /'
    \n

    Para cambiar de directorio sin usar comandos de modo de línea de comandos, puede especificar rutas directamente después del argumento --remote, de esta manera:

    \n
    \n  vifm --remote /\n  vifm --remote ~\n  vifm --remote /usr/bin /tmp
    \n

    Evaluar expresiones de forma remota puede ser útil para consultar información sobre una instancia, por ejemplo, su ubicación:

    \n
    \n  vifm --remote-expr 'expand(\"%d\")'
    \n

    Si hay varias instancias en ejecución, el objetivo se puede especificar con la opción --server-name (de lo contrario, se utiliza la primera lexicográficamente):

    \n
    \n  vifm --server-name work --remote ~/work/project
    \n

    La lista de nombres de instancias en ejecución se puede obtener a través de la opción --server-list. El nombre de la instancia actual está disponible a través de v:servername.

    \n
    \n
    v:servername
    \n
    nombre del servidor de la instancia de vifm en ejecución. Vacío si la función cliente-servidor está deshabilitada.

    Plugin

    This plugin allows to call vifm from Vim.

    To enable the plugin add


    autocmd VimEnter * call vifm#VifmOpen()

    to your ~/.vimrc file. This will open vifm on Vim startup. You can also add it to autocommand group to execute only once:


    augroup vifm
    autocmd! VimEnter * call vifm#VifmOpen()
    augroup END

    If you want to open vifm later, just type :Vifm in Vim command line.

    Plugin settings:


    g:vifm_exec

    This variable is equal to "vifm" by default and specifies the path to vifm's executable. To pass arguments to vifm use g:vifm_exec_args , which is empty by default.

    To use the plugin, copy the vifm.vim file to either the system-wide vim/plugin directory or into ~/.vim/plugin.

    If you would prefer not to use the plugin and it is in the system-wide plugin directory, add


    let loaded_vifm=1

    to your ~/.vimrc file.

    Reserved

    The following command names are reserved and shouldn't be used for user commands.


    g[lobal]
    v[global]

    ENVIRONMENT

    VIFM
    Points to the main configuration directory (usually ~/.config/vifm/).
    MYVIFMRC
    Points to the main configuration file (usually ~/.config/vifm/vifmrc).

    These environment variables are valid inside vifm and can also be used to configure it by setting some of them before running vifm.
