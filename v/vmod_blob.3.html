NOMBRE

vmod_blob - Utilidades para el tipo BLOB de VCL, codificación y decodificación

SINOPSIS

import blob [as name] [from "path"]
BLOB decode(ENUM decodificacion, INT longitud, STRING codificado)
STRING encode(ENUM codificacion, ENUM caso, BLOB blob)
STRING transcode(ENUM decodificacion, ENUM codificacion, ENUM caso, INT longitud, STRING codificado)
BOOL same(BLOB, BLOB)
BOOL equal(BLOB, BLOB)
INT length(BLOB)
BLOB sub(BLOB, BYTES longitud, BYTES offset)
new xblob = blob.blob(ENUM decodificacion, STRING codificado)
    BLOB xblob.get()
    STRING xblob.encode(ENUM codificacion, ENUM caso)

DESCRIPCIÓN

Este VMOD proporciona funciones de utilidad y un objeto para el tipo de datos BLOB de VCL, que puede contener datos arbitrarios de cualquier longitud.

Ejemplos:

sub vcl_init {
    # Crear objetos blob a partir de codificaciones como base64 o hex.
    new myblob   = blob.blob(BASE64, "Zm9vYmFy");
    new yourblob = blob.blob(encoded="666F6F", decodificacion=HEX);
}
sub vcl_deliver {
    # El método .get() recupera el BLOB de un objeto.
    set resp.http.MyBlob-As-Hex
        = blob.encode(codificacion=HEX,
                      blob=myblob.get());
    # El método .encode() recupera eficientemente una codificación.
    set resp.http.YourBlob-As-Base64 = yourblob.encode(BASE64);
    # Las funciones decode() y encode() convierten blobs a texto y
    # viceversa en tiempo de ejecución.
    set resp.http.Base64-Encoded
        = blob.encode(BASE64,
                      blob=blob.decode(HEX,
                                       codificado=req.http.Hex-Encoded));
}
sub vcl_recv {
    # transcode() convierte de una codificación a otra.
    # caso=UPPER especifica dígitos hex mayúsculos A-F.
    set req.http.Hex-Encoded
        = blob.transcode(decodificacion=BASE64, codificacion=HEX,
                         caso=UPPER, codificado="YmF6");
    # transcode() de URL a IDENTITY realiza una decodificación URL.
    set req.url = blob.transcode(codificado=req.url, decodificacion=URL);
    # transcode() de IDENTITY a URL realiza una codificación URL.
    set req.http.url_urlcoded
        = blob.transcode(codificado=req.url, codificacion=URL);
}

ESQUEMAS DE CODIFICACIÓN

Los esquemas de codificación binario a texto se especifican mediante ENUMs en el constructor, métodos y funciones del VMOD. Las decodificaciones convierten una cadena (posiblemente concatenada) en un blob, mientras que las codificaciones convierten un blob en una cadena.

Los valores ENUM para un esquema de codificación pueden ser uno de:

  • IDENTITY
  • BASE64
  • BASE64URL
  • BASE64URLNOPAD
  • BASE64CF
  • HEX
  • URL

Las cadenas vacías se decodifican en un "null blob" (de longitud 0) y, a la inversa, un null blob se codifica como la cadena vacía.

Para las codificaciones con HEX o URL, también puede especificar un ENUM de caso con uno de los valores LOWER, UPPER o DEFAULT para producir una cadena con dígitos hexadecimales en minúsculas o mayúsculas (en [a-f] o [A-F]). El valor predeterminado para caso es DEFAULT, que para HEX y URL significa lo mismo que LOWER.

El ENUM caso no es relevante para las decodificaciones; las cadenas HEX o URL que se decodificarán como BLOBs pueden tener dígitos hexadecimales en cualquier caso, o en caso mixto.

El ENUM caso DEBE establecerse en DEFAULT para las otras codificaciones (BASE64* e IDENTITY). No puede, por ejemplo, producir una cadena en mayúsculas utilizando el esquema IDENTITY con caso=UPPER. Para cambiar el caso de una cadena, utilice las funciones std.toupper() o std.tolower() de vmod_std(3).

IDENTITY

La codificación más simple convierte entre los tipos de datos BLOB y STRING, dejando el contenido byte a byte idéntico.

Tenga en cuenta que un BLOB puede contener un byte nulo en cualquier posición antes de su final; si dicho BLOB se decodifica con IDENTITY, la STRING resultante tendrá un byte nulo en esa posición. Dado que las cadenas VCL, al igual que las cadenas C, se representan con un byte nulo terminador, la cadena se truncará, pareciendo contener menos datos que el blob original. Por ejemplo:

# Decodificar de la codificación hex para "foo\0bar".
# La cabecera se verá como "foo".
set resp.http.Trunced-Foo1
    = blob.encode(IDENTITY, blob=blob.decode(HEX,
                                             codificado="666f6f00626172"));

IDENTITY es la codificación y decodificación predeterminada. Por lo tanto, lo anterior también se puede escribir como:

# Decodificar de la codificación hex para "foo\0bar".
# La cabecera se verá como "foo".
set resp.http.Trunced-Foo2
  = blob.encode(blob=blob.decode(HEX, codificado="666f6f00626172"));

El ENUM caso DEBE establecerse en DEFAULT para las codificaciones IDENTITY.

BASE64*

Los esquemas de codificación base64 utilizan 4 caracteres para codificar 3 bytes. No hay saltos de línea ni longitudes de línea máximas; el espacio en blanco no está permitido.

BASE64 utiliza los caracteres alfanuméricos, + y /; y las cadenas codificadas se rellenan con el carácter = para que su longitud sea siempre un múltiplo de cuatro.

BASE64URL utiliza también los caracteres alfanuméricos, pero - y _ en lugar de + y /, de modo que una cadena codificada se puede utilizar de forma segura en una URL. Este esquema también utiliza el carácter de relleno =.

BASE64URLNOPAD utiliza el mismo alfabeto que BASE6URL, pero omite el relleno. Por lo tanto, la longitud de una codificación con este esquema no es necesariamente un múltiplo de cuatro.

BASE64CF es similar a BASE64URL, con los siguientes cambios respecto a BASE64: + se reemplaza por -, / se reemplaza por ~ y _ como carácter de relleno. Lo utiliza un determinado proveedor de CDN que también inspiró el nombre.

El ENUM caso DEBE establecerse en DEFAULT para todas las codificaciones BASE64*.

HEX

El esquema de codificación HEX convierte cadenas hexadecimales en blobs y viceversa. Para las codificaciones, puede usar el ENUM caso para especificar dígitos hexadecimales en minúsculas o mayúsculas A a f (predeterminado DEFAULT, que significa lo mismo que LOWER). Un prefijo como 0x no se utiliza para una codificación y es ilegal para una decodificación.

Si una cadena hexadecimal que se va a decodificar tiene un número impar de dígitos, se decodifica como si se le antepusiera un 0; es decir, el primer dígito se interpreta como el nibble menos significativo del primer byte. Por ejemplo:

# La cadena concatenada es "abcdef0", y se decodifica como "0abcdef0".
set resp.http.First = "abc";
set resp.http.Second = "def0";
set resp.http.Hex-Decoded
    = blob.encode(HEX, blob=blob.decode(HEX,
                       codificado=resp.http.First + resp.http.Second));

URL

La decodificación URL reemplaza cualquier subcadena %<2-dígitos-hex> con el valor binario del número hexadecimal después del signo %.

La codificación URL implementa la "codificación de porcentaje" según RFC3986. El ENUM caso determina el caso de los dígitos hexadecimales, pero no afecta a los caracteres alfabéticos que no están codificados por porcentaje.

BLOB decode(ENUM decodificacion, INT longitud, STRING codificado)

BLOB decode(
   ENUM {IDENTITY, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} decodificacion=IDENTITY,
   INT longitud=0,
   STRING codificado
)

Devuelve el BLOB derivado de la cadena codificado según el esquema especificado por decodificacion.

Si longitud > 0, decodifica solo los primeros longitud caracteres de la cadena codificada. Si longitud <= 0 o es mayor que la longitud de la cadena, decodifica la cadena completa. El valor predeterminado de longitud es 0.

decodificacion tiene como valor predeterminado IDENTITY.

Ejemplo:

blob.decode(BASE64, encoded="Zm9vYmFyYmF6");
# lo mismo con parámetros con nombre
blob.decode(encoded="Zm9vYmFyYmF6", decoding=BASE64);
# convertir cadena a blob
blob.decode(encoded="foo");

CADENA encode(ENUM codificación, ENUM caso, BLOB blob)

CADENA encode(
   ENUM {IDENTIDAD, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} codificación=IDENTIDAD,
   ENUM {LOWER, UPPER, DEFAULT} caso=DEFAULT,
   BLOB blob
)

Devuelve una representación de cadena del blob BLOB según lo especificado por codificación. caso determina el caso de los dígitos hexadecimales para las codificaciones HEX y URL, y se ignora para las otras codificaciones.

codificación tiene como valor predeterminado IDENTIDAD, y caso tiene como valor predeterminado DEFAULT. DEFAULT se interpreta como LOWER para las codificaciones HEX y URL, y es el valor requerido para las otras codificaciones.

Ejemplo:

establecer resp.http.encode1
    = blob.encode(HEX,
                  blob=blob.decode(BASE64, encoded="Zm9vYmFyYmF6"));
# lo mismo con parámetros con nombre
establecer resp.http.encode2
    = blob.encode(blob=blob.decode(encoded="Zm9vYmFyYmF6",
                                           decoding=BASE64),
                      codificación=HEX);
# convertir blob a cadena
establecer resp.http.encode3
    = blob.encode(blob=blob.decode(encoded="foo"));

CADENA transcode(ENUM decodificación, ENUM codificación, ENUM caso, INT longitud, CADENA codificada)

CADENA transcode(
   ENUM {IDENTIDAD, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} decodificación=IDENTIDAD,
   ENUM {IDENTIDAD, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} codificación=IDENTIDAD,
   ENUM {LOWER, UPPER, DEFAULT} caso=DEFAULT,
   INT longitud=0,
   CADENA codificada
)

Traduce de una codificación a otra, primero decodificando la cadena codificada según el esquema decodificación, y luego devolviendo la codificación del blob resultante según el esquema codificación. caso determina el caso de los dígitos hexadecimales para las codificaciones HEX y URL, y se ignora para otras codificaciones.

Al igual que con blob.decode(): si longitud > 0, solo decodifica los primeros longitud caracteres de la cadena codificada, de lo contrario, decodifica la cadena completa. El valor predeterminado de longitud es 0.

decodificación y codificación tienen como valor predeterminado IDENTIDAD, y caso tiene como valor predeterminado DEFAULT. DEFAULT se interpreta como LOWER para las codificaciones HEX y URL, y es el valor requerido para las otras codificaciones.

Ejemplo:

establecer resp.http.Hex2Base64-1
     = blob.transcode(HEX, BASE64, codificada="666f6f");
 # lo mismo con parámetros con nombre
 establecer resp.http.Hex2Base64-2
    = blob.transcode(codificada="666f6f",
                          codificación=BASE64, decodificación=HEX);
 # decodificar URL -- recordar que IDENTIDAD es la codificación predeterminada.
 establecer resp.http.urldecoded
    = blob.transcode(codificada="foo%20bar", decodificación=URL);
 # codificar URL
 establecer resp.http.urlencoded
     = blob.transcode(codificada="foo bar", codificación=URL);

BOOL igual(BLOB, BLOB)

Devuelve true si y solo si los dos argumentos BLOB son el mismo objeto, es decir, especifican exactamente la misma región de memoria, o ambos están vacíos.

Si los BLOB están ambos vacíos (longitud es 0 y/o el puntero interno es NULL), entonces blob.igual() devuelve true. Si cualquier BLOB no vacío se compara con un BLOB vacío, entonces blob.igual() devuelve false.

BOOL equivalente(BLOB, BLOB)

Devuelve verdadero si y solo si los dos argumentos BLOB tienen contenidos equivalentes (posiblemente en diferentes regiones de memoria).

Al igual que con blob.igual(): si los BLOB están ambos vacíos, entonces blob.equivalente() devuelve true. Si cualquier BLOB no vacío se compara con un BLOB vacío, entonces blob.equivalente() devuelve false.

INT longitud(BLOB)

Devuelve la longitud del BLOB.

BLOB sub(BLOB, BYTES longitud, BYTES desplazamiento=0)

Devuelve un nuevo BLOB formado por longitud bytes del argumento BLOB comenzando en el byte desplazamiento desde el inicio de su región de memoria. El valor predeterminado de desplazamiento es 0B.

blob.sub() falla y devuelve NULL si el argumento BLOB está vacío, o si desplazamiento + longitud requiere más bytes de los que están disponibles en el BLOB.

new xblob = blob.blob(ENUM decodificación, CADENA codificada)

new xblob = blob.blob(
   ENUM {IDENTIDAD, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} decodificación=IDENTIDAD,
   CADENA codificada
)

Crea un objeto que contiene el BLOB derivado de la cadena codificada según el esquema decodificación.

Ejemplo:

new theblob1 = blob.blob(BASE64, codificada="YmxvYg==");
# lo mismo con argumentos con nombre
new theblob2 = blob.blob(codificada="YmxvYg==", decodificación=BASE64);
# cadena como blob
new stringblob = blob.blob(codificada="bazz");

BLOB xblob.get()

Devuelve el BLOB creado por el constructor.

Ejemplo:

establecer resp.http.The-Blob1 =
    blob.encode(blob=theblob1.get());
establecer resp.http.The-Blob2 =
    blob.encode(blob=theblob2.get());
establecer resp.http.The-Stringblob =
    blob.encode(blob=stringblob.get());

CADENA xblob.encode(ENUM codificación, ENUM caso)

CADENA xblob.encode(
      ENUM {IDENTIDAD, BASE64, BASE64URL, BASE64URLNOPAD, BASE64CF, HEX, URL} codificación=IDENTIDAD,
      ENUM {LOWER, UPPER, DEFAULT} caso=DEFAULT
)

Devuelve una codificación del BLOB creado por el constructor, según el esquema codificación. caso determina el caso de los dígitos hexadecimales para las codificaciones HEX y URL, y DEBE establecerse en DEFAULT para las otras codificaciones.

Ejemplo:

# blob como texto
establecer resp.http.The-Blob = theblob1.encode();
# blob como base64
establecer resp.http.The-Blob-b64 = theblob1.encode(BASE64);

Para cualquier objeto blob.blob(), codificación y caso, las codificaciones a través del método xblob.encode() y la función blob.encode() son iguales:

# Siempre verdadero:
blob.encode(ENC, CASE, blob.get()) == blob.encode(ENC, CASE)

Pero el método de objeto xblob.encode() es más eficiente: la codificación se calcula una vez y se almacena en caché (con asignación en memoria heap), y la codificación en caché se recupera en cada llamada subsiguiente. La función blob.encode() calcula la codificación en cada llamada, asignando espacio para la cadena en los espacios de trabajo de Varnish.

Por lo tanto, si los datos en un BLOB son fijos en el momento de la inicialización de VCL, de modo que sus codificaciones siempre serán las mismas, es mejor crear un objeto blob.blob(). Las funciones del VMOD deben utilizarse para datos que no se conocen hasta el tiempo de ejecución.

ERRORES

Los codificadores, decodificadores y blob.sub() pueden fallar si no hay suficiente espacio para crear el nuevo blob o cadena. Los decodificadores también pueden fallar si la cadena codificada es un formato ilegal para el esquema de decodificación. Los codificadores fallarán para los esquemas de codificación IDENTITY y BASE64* si la enumeración caso no está establecida en DEFAULT.

Si alguno de los métodos, funciones o el constructor del VMOD falla, se invoca el fallo de VCL, como si se hubiera llamado a return(fail) en el código fuente de VCL. Esto significa que:

  • Si el constructor del objeto blob.blob() falla, o si algún método o función falla durante vcl_init{}, el programa VCL no se cargará y el compilador VCC emitirá un mensaje de error.
  • Si un método o función falla en cualquier otra subrutina VCL además de vcl_synth{}, el control se dirige a vcl_synth{}. El estado de la respuesta se establece en 503 con la cadena de razón "VCL falló", y se escribirá un mensaje de error en el vsl(7) usando la etiqueta VCL_Error.
  • Si el fallo ocurre durante vcl_synth{}, entonces vcl_synth{} se aborta. Se devuelve la línea de respuesta "503 VCL falló", y el mensaje VCL_Error se escribe en el registro.

LIMITACIONES

El VMOD asigna memoria de diversas maneras para nuevos blobs y cadenas. El objeto blob.blob() y sus métodos asignan memoria del heap, y por lo tanto solo están limitados por la memoria virtual disponible.

Las funciones blob.encode(), blob.decode() y blob.transcode() asignan espacio de trabajo de Varnish, al igual que blob.sub() para el BLOB recién creado. Si estas funciones fallan, como lo indican los mensajes de "sin espacio" en el registro de Varnish (con la etiqueta VCL_Error), deberá aumentar los parámetros de varnishd workspace_client y/o workspace_backend.

La función blob.transcode() también asigna espacio en la pila para un BLOB temporal. Si esta función causa un desbordamiento de pila, es posible que deba aumentar el parámetro de varnishd thread_pool_stack.
