VGMKNODES(8) Manual del Administrador del Sistema VGMKNODES(8)

NOMBRE

vgmknodes — Crea los archivos especiales para los dispositivos de grupo de volúmenes en /dev

SINOPSIS

vgmknodes
[ argumentos_opcionales ]
[ argumentos_posicionales ]

DESCRIPCIÓN

vgmknodes comprueba los nodos de dispositivos LVM en /dev que son necesarios para los LV activos y crea los que faltan y elimina los no utilizados.

Normalmente, este comando no debería ser necesario si todos los componentes del sistema interactúan correctamente.

Consulte también las notas al final de esta página del manual para usar vgmknodes junto con udev.

USO

vgmknodes

[ --ignorelockingfailure ]
[ --refresh ]
[ --reportformat basic|json|json_std ]
[ OPCIONES_COMUNES ]
[ VG|LV|Etiqueta ... ]

OPCIONES

--commandprofile Cadena
El perfil de comando a utilizar para la configuración del comando. Consulte lvm.conf(5) para obtener más información sobre los perfiles.
--config Cadena
Configuración de ajustes para el comando. Estos anulan la configuración de lvm.conf(5). La cadena de argumento utiliza el mismo formato que lvm.conf(5), o puede utilizar la sintaxis de sección/campo. Consulte lvm.conf(5) para obtener más información sobre la configuración.
-d|--debug ...
Establece el nivel de depuración. Repita de 1 a 6 veces para aumentar el nivel de detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados aparecerán como ausentes. Esta opción se puede repetir o acepta una lista de dispositivos separados por comas. Esto anula el archivo de dispositivos.
--devicesfile Cadena
Un archivo que lista los dispositivos que LVM debe utilizar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración devices/devicesfile y devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si se establece en no, el comando no intentará utilizar device-mapper. Para pruebas y depuración.
-h|--help
Muestra el texto de ayuda.
--ignorelockingfailure
Permite que un comando continúe con operaciones de metadatos de solo lectura después de fallos de bloqueo.
--journal Cadena
Registra información en el journal de systemd. Esta información se suma a la información activada por la configuración de registro/journal de lvm.conf. command: registra información sobre el comando. output: registra la salida predeterminada del comando. debug: registra la depuración completa del comando.
--lockopt Cadena
Se utiliza para pasar opciones para casos especiales a lvmlockd. Consulte lvmlockd(8) para obtener más información.
--longhelp
Muestra el texto de ayuda detallado.
--nohints
No utiliza el archivo de pistas para localizar dispositivos para PVs. Un comando puede leer más dispositivos para encontrar PVs cuando no se utilizan pistas. El comando aún realizará una invalidación estándar del archivo de pistas cuando sea apropiado.
--nolocking
Desactiva el bloqueo. Úselo con precaución, los comandos concurrentes pueden producir resultados incorrectos.
--profile Cadena
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
-q|--quiet ...
Suprime la salida y los mensajes de registro. Anula --debug y --verbose. Repita una vez para suprimir también las indicaciones con la respuesta 'no'.
--refresh
Si el LV está activo, recarga sus metadatos. En un entorno donde se utiliza udev para gestionar el contenido de /dev, se recomienda encarecidamente el uso de esta opción. Esto se debe a que refresh también regenera los eventos de udev para un LV basándose en las reglas de udev existentes que se aplican para establecer el contenido y los permisos de /dev. Además, esta operación puede ser útil si algo ha salido mal, o si se está utilizando alguna forma de compartición manual de LV.
--reportformat basic|json|json_std
Anula el formato de salida actual para los informes, que se define globalmente mediante la configuración report/output_format en lvm.conf(5). basic es el formato original con columnas y filas. Si hay más de un informe por comando, cada informe va precedido del nombre del informe para su identificación. json produce la salida del informe en formato JSON. json_std produce la salida del informe en formato JSON que es más compatible con el estándar JSON. Consulte lvmreport(7) para obtener más información.
-t|--test
Ejecuta en modo de prueba. Los comandos no actualizarán los metadatos. Esto se implementa desactivando toda escritura de metadatos y, sin embargo, devolviendo éxito a la función que llama. Esto puede llevar a mensajes de error inusuales en operaciones de múltiples etapas si una herramienta depende de la lectura de metadatos que cree que han cambiado pero no lo han hecho.
-v|--verbose ...
Establece el nivel de verbosidad. Repita de 1 a 4 veces para aumentar el nivel de detalle de los mensajes enviados a stdout y stderr.
--version
Muestra la información de la versión.
-y|--yes
No solicite confirmación interactivamente, sino que asuma siempre la respuesta sí. Úselo con extrema precaución. (Para un no automático, vea -qq.)

VARIABLES

VG
Nombre del Grupo de Volúmenes. Consulte lvm(8) para ver nombres válidos.
LV
Nombre del Volumen Lógico. Consulte lvm(8) para ver nombres válidos. Un argumento posicional LV generalmente incluye el nombre del VG y el nombre del LV, por ejemplo, VG/LV.
Etiqueta
Nombre de la etiqueta. Consulte lvm(8) para obtener información sobre nombres de etiquetas y el uso de etiquetas en lugar de un VG, LV o PV.
Cadena
Consulte la descripción de la opción para obtener información sobre el contenido de la cadena.

UNIT representa otras unidades de entrada posibles: b|B son bytes, s|S son sectores de 512 bytes, k|K son KiB, m|M son MiB, g|G son GiB, t|T son TiB, p|P son PiB, e|E son EiB. (Esto no debe confundirse con el control de salida --units, donde las letras mayúsculas significan múltiplos de 1000.)

VARIABLES DE ENTORNO

Consulta lvm(8) para obtener información sobre las variables de entorno utilizadas por lvm. Por ejemplo, LVM_VG_NAME puede sustituirse generalmente por un parámetro VG requerido.

NOTAS

Al utilizar udev(7) para gestionar el contenido de /dev, también se recomienda encarecidamente utilizar la opción --refresh. De este modo, también se generan los eventos udev necesarios y se aplican correctamente las reglas udev asociadas. Si la opción --refresh no se utiliza en este caso, LVM recrea directamente el contenido de /dev y udev no tendrá registros correctos sobre los enlaces simbólicos y nodos afectados. Además, no se aplican los permisos de nodo definidos por las reglas de udev. Esto, a su vez, puede causar problemas a otros componentes del sistema que dependen de la lectura de la base de datos udev para obtener la lista de enlaces simbólicos y nodos de /dev y que dependen de los permisos basados en las reglas de udev.
