Virt-Viewer(1) Soporte de virtualización Virt-Viewer(1)

NOMBRE

virt-viewer - muestra la consola gráfica de una máquina virtual

SINOPSIS

virt-viewer [OPCIONES] [ID|UUID|NOMBRE-DOMINIO]

DESCRIPCIÓN

virt-viewer es una herramienta mínima para mostrar la consola gráfica de una máquina virtual. Se accede a la consola utilizando el protocolo VNC o SPICE. Se puede hacer referencia a la máquina invitada según su nombre, ID o UUID. Si la máquina invitada aún no se está ejecutando, se puede indicar al visor que espere hasta que se inicie antes de intentar conectarse a la consola. El visor puede conectarse a hosts remotos para buscar información de la consola y luego también conectarse a la consola remota utilizando el mismo transporte de red.

En algunas circunstancias, el visor puede necesitar capturar el puntero del ratón. La secuencia de teclas predeterminada para liberar la captura es "Ctrl_L"+"Alt_L", sin embargo, esto puede ser anulado usando el argumento "--hotkeys" documentado a continuación.

OPCIONES

Se aceptan las siguientes opciones al ejecutar "virt-viewer":

-h, --help
Muestra el resumen de ayuda de la línea de comandos
-V, --version
Muestra el número de versión del programa
-v, --verbose
Muestra información sobre la conexión
-c URI, --connect=URI
Especifica la URI de conexión del hipervisor
-w, --wait
Espera a que el dominio se inicie antes de intentar conectarse a la consola
-r, --reconnect
Reconecta automáticamente al dominio si se apaga y reinicia
-z PCT, --zoom=PCT
Nivel de zoom de la ventana de visualización en porcentaje. Rango 10-400.
-d, --direct
No intentes canalizar la consola a través de SSH, incluso si la URI de conexión principal utilizó SSH.
-a, --attach
En lugar de establecer una conexión directa de socket TCP/UNIX a la pantalla remota, solicita a libvirt que proporcione un socket pre-conectado para la pantalla. Esto evita la necesidad de autenticarse directamente con el servidor de pantalla remoto. Esta opción solo funcionará cuando se conecte a una máquina invitada que se esté ejecutando en el mismo host que el programa virt-viewer. Si la conexión a la máquina invitada a través de libvirt falla, virt-viewer intentará automáticamente una conexión normal directa de socket TCP/UNIX.
-f, --full-screen
Inicia con la ventana maximizada a pantalla completa

Si se admite, la pantalla remota se reconfigurará para que coincida con la configuración de los monitores del cliente físico, habilitando o deshabilitando monitores adicionales según sea necesario. Esto está implementado actualmente solo por el backend de Spice.

Para especificar qué monitores del cliente se utilizan en modo de pantalla completa, consulta la sección CONFIGURACIÓN a continuación.

--auto-resize <siempre|nunca>
Controla si se permite intentar redimensionar el framebuffer remoto para que coincida con el tamaño de la ventana local. Actualmente, esto está activado por defecto, pero ten en cuenta que no todos los servidores soportarán esto.
-s, --shared
Permite una sesión compartida con múltiples clientes
--cursor auto|local
Controla cómo se renderiza el cursor del ratón. "auto" es el comportamiento predeterminado, que respetará el comportamiento solicitado por el servidor remoto. Esto puede implicar que el servidor renderice el cursor de forma remota en el framebuffer, o que envíe los detalles del cursor al cliente para que los renderice. "local" anula este valor predeterminado para solicitar que el cursor del escritorio local se renderice siempre, independientemente de lo que solicite el servidor. Esto último rara vez es necesario, pero se puede usar si el servidor tiene una configuración defectuosa que resulta en que su propio cursor se oculte.
--debug
Muestra información de depuración
-H HOTKEYS, --hotkeys HOTKEYS
Establece los atajos de teclado globales. De forma predeterminada, los atajos de teclado solo funcionan cuando el widget de visualización de la máquina invitada no tiene el foco. Cualquier acción especificada en HOTKEYS será efectiva incluso cuando el widget de visualización de la máquina invitada tenga el foco de entrada. El formato para HOTKEYS es <acción1>=<tecla1>[+<tecla2>][,<acción2>=<tecla3>[+<tecla4>]]. Los nombres de las teclas no distinguen entre mayúsculas y minúsculas. Las acciones válidas son: toggle-fullscreen (cambiar pantalla completa), release-cursor (liberar cursor), zoom-in (acercar), zoom-out (alejar), zoom-reset (restablecer zoom), secure-attention (atención segura), usb-device-reset (restablecer dispositivo USB), smartcard-insert (insertar tarjeta inteligente) y smartcard-remove (retirar tarjeta inteligente). La acción "secure-attention" envía una secuencia de atención segura (Ctrl+Alt+Del) a la máquina invitada. Ejemplos: 
--hotkeys=toggle-fullscreen=shift+f11,release-cursor=shift+f12
--hotkeys=release-cursor=ctrl+alt

Ten en cuenta que los atajos de teclado para los que no se proporciona una vinculación están deshabilitados. Aunque los atajos de teclado especificados aquí son manejados por el cliente, todavía es posible enviar estas combinaciones de teclas a la máquina invitada a través de una opción de menú.

-K, --keymap
Remapea y/o bloquea las pulsaciones de teclas proporcionadas al host. Todos los identificadores de teclas distinguen entre mayúsculas y minúsculas y siguen la convención de nombres definida en gdkkeysyms.h sin el prefijo GDK_KEY_.

Ejecutar la aplicación con --debug mostrará los símbolos de las pulsaciones de teclas de la siguiente manera:
"La tecla presionada fue keycode='0x63', gdk_keyname='c'"
"La tecla presionada fue keycode='0xffeb', gdk_keyname='Super_L'"

El formato para proporcionar un mapa de teclas es: <srcKeySym1>=[<destKeySym1>][+<destKeySym2][,<srckeySym2>=[<destKeySym1]

Para bloquear una pulsación de tecla, simplemente asigna un parámetro vacío a srcKeySym.

Ejemplo:
--keymap=Super_L=,Alt_L=,1=Shift_L+F1,2=Shift_L+F2

Esto bloqueará las pulsaciones de teclas Super_L (normalmente la tecla de Windows) y Alt_L, y remapeará la tecla 1 a Shift F1, 2 a Shift F2.

-k, --kiosk
Inicia en modo quiosco. En este modo, la aplicación se iniciará en pantalla completa con una interfaz mínima. Impedirá al usuario salir o realizar cualquier interacción fuera del uso de la sesión de escritorio remoto.

Ten en cuenta que no puede ofrecer una solución segura completa por sí solo. Tu sistema de quiosco debe tener una configuración y ajustes de seguridad adicionales para bloquear el sistema operativo. En particular, debes configurar o deshabilitar el gestor de ventanas, limitar las capacidades de la sesión, usar algún mecanismo de reinicio/vigilancia, deshabilitar la conmutación VT, etc.

--kiosk-quit <nunca|al-desconectar>
Por defecto, cuando el modo quiosco está habilitado, virt-viewer permanecerá abierto cuando se termine la conexión con el servidor remoto. Al establecer la opción kiosk-quit al valor "al-desconectar", virt-viewer se cerrará en su lugar. Ten en cuenta que --reconnect tiene prioridad sobre esta opción e intentará reconectarse antes de cerrarse.
--id, --uuid, --domain-name
Conéctate a la máquina virtual por su id, uuid o nombre. Estas opciones son mutuamente excluyentes. Por ejemplo, el siguiente comando a veces puede conectarse a una máquina virtual con el id 2 o con el nombre 2 (dependiendo del número de máquinas en ejecución): 
virt-viewer 2

Para conectarte siempre a la máquina virtual con el nombre "2", usa la opción "--domain-name":

virt-viewer --domain-name 2

CONFIGURACIÓN

Se puede controlar un pequeño número de opciones de configuración editando el archivo de configuración ubicado en el directorio de configuración del usuario:

<DIRECTORIO-CONFIG-USUARIO>/virt-viewer/settings

Este archivo es un archivo de texto en formato INI, con opciones de la aplicación en el grupo [virt-viewer] y opciones por máquina invitada en un grupo identificado por el UUID de la máquina invitada. Las opciones de la aplicación no deben editarse manualmente. También hay un grupo especial [fallback] que especifica opciones para todas las máquinas invitadas que no tienen un grupo explícito.

CONFIGURATION

Para cada invitado, la configuración inicial del monitor a pantalla completa se puede especificar usando la clave monitor-mapping. Esta configuración solo surte efecto cuando se especifica la opción -f/--full-screen.

El valor de esta clave es una lista de mapeos entre una pantalla del invitado y un monitor del cliente. Cada mapeo está separado por un punto y coma, y los mapeos tienen el formato <ID-PANTALLA-INVITADO>:<ID-MONITOR-CLIENTE>.

Por ejemplo, para mapear las pantallas de invitado 1 y 2 a los monitores de cliente 2 y 3 para el invitado con un UUID de e4591275-d9d3-4a44-a18b-ef2fbc8ac3e2, use:

[e4591275-d9d3-4a44-a18b-ef2fbc8ac3e2]
monitor-mapping=1:2;2:3

El monitor-mapping debe contener los ID de todas las pantallas desde la 1 hasta el último ID de pantalla deseado, por ejemplo, "monitor-mapping=3:3" es inválido porque no se especifican los mapeos para las pantallas 1 y 2.

EJEMPLOS

Para conectarse al invitado llamado 'demo' que se ejecuta bajo Xen

virt-viewer demo

Para usar la GUI para conectarse a un invitado que se ejecuta bajo QEMU

virt-viewer --connect qemu:///system

Para conectarse al invitado con ID 7 que se ejecuta bajo QEMU

virt-viewer --connect qemu:///system 7

Para esperar a que el invitado con UUID 66ab33c0-6919-a3f7-e659-16c82d248521 se inicie y luego conectarse, también reconectándose al reiniciar la VM

virt-viewer --reconnect --wait 66ab33c0-6919-a3f7-e659-16c82d248521

Para conectarse a una consola remota usando TLS

virt-viewer --connect xen://example.org/ demo

Para conectarse a un host remoto usando SSH, buscar la configuración del invitado y luego establecer una conexión tunelizada de la consola

virt-viewer --connect qemu+ssh://root@example.org/system demo

Al usar un túnel SSH para conectarse a una consola SPICE, se recomienda tener ssh-agent ejecutándose para evitar múltiples solicitudes de autenticación.

Para conectarse a un host remoto usando SSH, buscar la configuración del invitado y luego establecer una conexión directa no tunelizada de la consola

virt-viewer --direct --connect xen+ssh://root@example.org/ demo
