NOMBRE

vnstatd - demonio para la actualización de la base de datos para vnStat

SINOPSIS

vnstatd [-Ddnpstv?] [--alwaysadd [modo]] [--config archivo] [--daemon] [--debug] [-g grupo] [--group grupo] [--help] [--initdb] [--noadd] [--nodaemon] [--noremove] [--pidfile archivo] [--startempty] [--sync] [--timestamp] [--u usuario] [--user usuario] [--version]

DESCRIPCIÓN

El propósito de vnstatd es proporcionar una forma flexible y robusta para recopilar datos para la base de datos que utiliza vnstat(1). La disponibilidad de cada interfaz se rastrea automáticamente, lo que elimina la necesidad de implementar y llamar a scripts adicionales cuando una interfaz se activa o se desactiva.

vnstatd es el comando para iniciar el demonio. El demonio puede bifurcarse para ejecutarse como un proceso en segundo plano o permanecer conectado a la terminal. Admite el registro directamente en la terminal, en un archivo seleccionable por el usuario o mediante syslog.

Una vez iniciado, el demonio leerá vnstat.conf(5) si está disponible y luego verificará si hay una base de datos presente en el directorio de bases de datos que se ha especificado en el archivo de configuración. Por defecto, si no se encuentra ninguna base de datos, se creará una base de datos durante el inicio con entradas para todas las interfaces disponibles, excluyendo las interfaces pseudo lo, lo0 y sit0. Este comportamiento de creación automática de entradas de base de datos se puede deshabilitar utilizando la opción --noadd. Alternativamente, se puede utilizar la opción --alwaysadd para indicar al demonio que cree nuevas entradas de base de datos cada vez que aparezcan interfaces no actualmente en las bases de datos. Por defecto, a menos que se utilice la opción --startempty, el demonio no permanecerá en ejecución si no se descubren interfaces durante el inicio y la base de datos no contiene ninguna interfaz.

El demonio procederá a rastrear la disponibilidad de las interfaces monitoreadas, procesar las estadísticas de tráfico de la interfaz y escribir nuevos valores en la base de datos a un intervalo configurado. Como resultado, el demonio pasa la mayor parte del tiempo durmiendo entre actualizaciones. Las nuevas interfaces añadidas a la base de datos serán capturadas automáticamente para su monitoreo sin necesidad de notificar al demonio.

Cuando la opción de configuración UseUTC no está habilitada, los datos se almacenan en la base de datos utilizando la hora local basada en el entorno de ejecución del demonio cuando la opción de configuración no está habilitada. Cualquier cambio en el reloj del sistema o en la configuración de la zona horaria del sistema dará como resultado que los datos se inserten según la nueva hora local sin realizar ningún recálculo para los datos ya almacenados. El demonio y la base de datos, en esencia, no son conscientes de la zona horaria utilizada o del posible horario de verano y no se pueden configurar para compensar las marcas de tiempo en ninguna dirección. Si un cambio en el reloj del sistema o en la zona horaria del sistema, o el fin de la observación del horario de verano, provoca que un período de tiempo ya visto se repita, los valores existentes de la base de datos se incrementarán con los nuevos datos.

OPCIONES

--alwaysadd [modo]
Habilita la creación automática de nuevas entradas de base de datos para interfaces que no están actualmente en la base de datos, incluso si el archivo de base de datos ya existe cuando se inicia el demonio. También se crearán nuevas entradas de base de datos para las nuevas interfaces que se vean mientras el demonio se está ejecutando. Las interfaces pseudo lo, lo0 y sit0 siempre se excluyen de ser añadidas. El uso de la opción sin modo definido o con modo establecido a 1 habilitará la función. Establecer modo a 0 deshabilitará la función. Esta opción de línea de comandos anula la opción de configuración AlwaysAddNewInterfaces cuando se utiliza.
--config archivo
Usa archivo como archivo de configuración en lugar de utilizar la funcionalidad de búsqueda automática de archivos de configuración.
-d, --daemon
Bifurca el proceso para que se ejecute en segundo plano como un demonio.
-D, --debug
Proporciona salida adicional para fines de depuración. El proceso permanecerá conectado a la terminal para la salida.
-g, --group grupo
Establece el grupo del proceso demonio a grupo durante el inicio. grupo puede ser el nombre del grupo o un ID de grupo numérico. Esta opción solo se puede usar cuando el proceso se inicia como root.
--initdb
Crea una nueva base de datos, importa datos de bases de datos heredadas encontradas si la opción --noadd no se utiliza y sale sin crear entradas de base de datos para las interfaces disponibles si no se importó ningún dato heredado. Si la base de datos ya existe, solo se verifica su acceso. El demonio no permanecerá en ejecución cuando se utilice esta opción. Esta opción no se puede usar en combinación con -d, --daemon, -n, --nodaemon o --startempty.
--noadd
Cuando se usa en combinación con -d, --daemon o -n, --nodaemon, deshabilita la creación automática de nuevas entradas de base de datos para todas las interfaces disponibles actualmente cuando el demonio se inicia sin una base de datos existente o con una base de datos que contiene cero interfaces. El demonio seguirá creando una base de datos vacía si aún no existe. Las interfaces pseudo lo, lo0 y sit0 siempre se excluyen de ser añadidas independientemente de esta opción.
Cuando se usa en combinación con --initdb, crea solo una base de datos vacía si aún no existe, sin importar datos de posibles bases de datos heredadas, y sale.
-n, --nodaemon
Permanece en primer plano conectado a la terminal actual e inicia el proceso de actualización.
--noremove
Deshabilita la eliminación automática de interfaces de la base de datos que actualmente no son visibles y no han visto tráfico.
-p, --pidfile archivo
Escribe el ID del proceso en archivo y úsalo para bloquear, de modo que no se pueda iniciar otra instancia del demonio si se especifica el mismo archivo. Esta opción no tiene efecto si se usa en combinación con -n, --nodaemon.
--startempty
Inicia incluso cuando no se descubrieron interfaces y la base de datos está vacía. Hace que el demonio permanezca en ejecución y espere a que se añadan interfaces a la base de datos o se encuentren si la opción --alwaysadd también se ha utilizado. Esta opción no se puede usar en combinación con --initdb.
-s, --sync
Sincroniza los contadores internos de la base de datos con los contadores de interfaz para todas las interfaces disponibles antes de iniciar el monitoreo de tráfico. Usa esta opción si se debe ignorar el tráfico entre el apagado anterior y el inicio actual del demonio. Esta opción no es necesaria en el uso normal porque el demonio sincronizará automáticamente los contadores internos después de un reinicio del sistema, si ha pasado suficiente tiempo desde la última vez que se ejecutó el demonio o si los contadores internos están claramente desincronizados.
-t, --timestamp
Agrega una marca de tiempo al principio de cada impresión del demonio cuando el proceso se ejecuta en primer plano conectado a una terminal después de haber sido iniciado con la opción -n, --nodaemon.
-u, --user usuario
Establece el usuario del proceso demonio a usuario durante el inicio. usuario puede ser el nombre de inicio del usuario o un ID de usuario numérico. Esta opción solo se puede usar cuando el proceso se inicia como root.
-v, --version
Muestra la versión actual del ejecutable del demonio.
-?, --help
Muestra un resumen de las opciones del comando.

CONFIGURACIÓN

El comportamiento del demonio se configura principalmente utilizando las palabras clave de configuración UpdateInterval, PollInterval y SaveInterval en el archivo de configuración.

UpdateI

vnstatd(8) — vnStat v2.13

NAME

vnstatd

network traffic monitor daemon

SYNOPSIS

vnstatd [-d] [-p] [-q] [-c configfile] [-l pidfile]

DESCRIPTION

The vnstatd daemon is used to collect network traffic statistics. It operates in the background and updates the statistics periodically based on the configuration settings.

The daemon can be started in several modes:

  • -d: Daemonize the process, writing to the specified pid file. This is the default mode.
  • -p: Daemonize the process, writing to the specified pid file. This mode also enables polling for interface changes.
  • -q: Quiet mode. The daemon will not log any information to standard output.

The configuration file can be specified using the -c option, and the pid file location using the -l option. If not specified, the default locations will be used.

OPTIONS

-d
Daemonize the process.
-p
Daemonize and enable polling for interface changes.
-q
Quiet mode (no standard output logging).
-c configfile
Use the specified configuration file.
-l pidfile
Use the specified pid file.

CONFIGURATION

The daemon's behavior is controlled by settings in the configuration file (/etc/vnstat.conf by default).

UpdateInterval defines in seconds how often the interface data is fetched and updated. This is similar to the run interval for alternative cron based updating. However, the difference is that the data doesn't directly get written to disk during updates.

PollInterval defines in seconds how often the list of available interfaces is checked for possible changes. The minimum value is 2 seconds and the maximum 60 seconds. PollInterval also defines the resolution for other intervals.

SaveInterval defines in minutes how often cached interface data is written to disk. A write can only occur during the updating of interface data. Therefore, the value should be a multiple of UpdateInterval with a maximum value of 60 minutes.

The default values of UpdateInterval 30, SaveInterval 5 and PollInterval 5 are usually suitable for most systems and provide a similar behaviour as cron based updating does but with a better resolution for interface changes and fast interfaces.

For embedded and/or low power systems more tuned configurations are possible. In such cases if the interfaces are mostly static the PollInterval can be increased to around 10-30 seconds and UpdateInterval set to 60 seconds. Higher values up to 300 seconds are possible if the interface speed is 10 Mbit or less. SaveInterval can be increased for example to 15, 30 or even 60 minutes depending on how often the data needs to be viewed.

SIGNALS

The daemon is listening to signals SIGHUP, SIGINT and SIGTERM. Sending the SIGHUP signal to the daemon will cause cached data to be written to disk, a rescan of the database directory and a reload of settings from the configuration file. However, the pid file location will not be changed even if it's configuration setting has been modified.

SIGTERM and SIGINT signals will cause the daemon to write all cached data to disk and then exit.

FILES

/var/lib/vnstat/
Default database directory.
/etc/vnstat.conf
Config file that will be used unless $HOME/.vnstatrc exists. See the configuration chapter and vnstat.conf(5) for more information.
/var/log/vnstat/vnstat.log
Log file that will be used if logging to file is enable and no other file is specified in the config file.
/var/run/vnstat/vnstat.pid
File used for storing the process id when running as a background process and if no other file is specified in the configuration file or using the command line parameter.

RESTRICTIONS

Updates need to be executed at least as often as it is possible for the interface to generate enough traffic to overflow the kernel interface traffic counter. Otherwise, it is possible that some traffic won't be seen. With 32-bit interface traffic counters, the maximum time between two updates depends on how fast the interface can transfer 4 GiB. Note that there is no guarantee that a 64-bit kernel has 64-bit interface traffic counters for all interfaces. Calculated theoretical times are:

10 Mbit: 54 minutes
100 Mbit: 5 minutes
1000 Mbit: 30 seconds
Virtual and aliased interfaces cannot be monitored because the kernel doesn't provide traffic information for that type of interfaces. Such interfaces are usually named eth0:0, eth0:1, eth0:2 etc. where eth0 is the actual interface being aliased.
