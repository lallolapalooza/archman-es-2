NOMBRE

virtual - Agente de entrega de correo de dominio virtual de Postfix

SINOPSIS

virtual [opciones genéricas del demonio de Postfix]

DESCRIPCIÓN


El agente de entrega virtual(8) está diseñado para servicios de alojamiento de correo virtual. Originalmente basado en el agente de entrega local(8) de Postfix, este agente busca destinatarios con búsquedas de mapas de su dirección de destinatario completa, en lugar de usar búsquedas de archivos de contraseñas de Unix codificadas en las que solo se considera la parte local de la dirección.

Este agente de entrega solo entrega correo. Otras funcionalidades como el reenvío de correo, notificaciones de ausencia del hogar, etc., deben configurarse a través de mapas de alias virtuales o mecanismos de búsqueda similares.

UBICACIÓN DEL BUZÓN

La ubicación del buzón está controlada por los parámetros de configuración virtual_mailbox_base y virtual_mailbox_maps (ver abajo). La tabla virtual_mailbox_maps se indexa por la dirección del destinatario según se describe en ORDEN DE BÚSQUEDA DE TABLAS a continuación.

El nombre de la ruta del buzón se construye de la siguiente manera:

  $virtual_mailbox_base/$virtual_mailbox_maps(destinatario)

donde destinatario es la dirección completa del destinatario.

FORMATO BUZÓN UNIX

Cuando la ubicación del buzón no termina en /, el mensaje se entrega en formato de buzón UNIX. Este formato almacena múltiples mensajes en un solo archivo de texto.

El agente de entrega virtual(8) antepone un encabezado de sobre "From remitente marca_de_tiempo" a cada mensaje, antepone un encabezado de mensaje Delivered-To: con la dirección del destinatario del sobre, antepone un encabezado X-Original-To: con la dirección del destinatario tal como se le dio a Postfix, antepone un encabezado de mensaje Return-Path: con la dirección del remitente del sobre, antepone un carácter > a las líneas que comienzan con "From ", y agrega una línea vacía.

El buzón se bloquea para acceso exclusivo mientras la entrega está en progreso. En caso de problemas, se intenta truncar el buzón a su longitud original.

FORMATO MAILDIR QMAIL

Cuando la ubicación del buzón termina en /, el mensaje se entrega en formato maildir de qmail. Este formato almacena un mensaje por archivo.

El agente de entrega virtual(8) antepone un encabezado de mensaje Delivered-To: con la dirección final del destinatario del sobre, antepone un encabezado X-Original-To: con la dirección del destinatario tal como se le dio a Postfix, y antepone un encabezado de mensaje Return-Path: con la dirección del remitente del sobre.

Por definición, el formato maildir no requiere bloqueo de archivos a nivel de aplicación durante la entrega o recuperación de correo.

PROPIEDAD DEL BUZÓN

La propiedad del buzón se controla mediante las tablas de búsqueda virtual_uid_maps y virtual_gid_maps, que se indexan con la dirección completa del destinatario. Cada tabla proporciona una cadena con el ID numérico de usuario y grupo, respectivamente.

El parámetro virtual_minimum_uid impone un límite inferior en los valores numéricos de ID de usuario que pueden especificarse en cualquier tabla virtual_uid_maps.

PLEGADO DE CASOS

Todas las decisiones de entrega se toman utilizando la dirección completa del destinatario, plegada a minúsculas. Consulte también la siguiente sección para ver algunas excepciones con extensiones de dirección opcionales.

ORDEN DE BÚSQUEDA DE TABLAS

Normalmente, una tabla de búsqueda se especifica como un archivo de texto que sirve como entrada para el comando postmap(1). El resultado, un archivo indexado en formato dbm o db, se utiliza para búsquedas rápidas por parte del sistema de correo.

El orden de búsqueda es el siguiente. La búsqueda se detiene en la primera coincidencia exitosa.

  • Cuando el destinatario tiene una extensión de dirección opcional, la dirección usuario+extensión@dominio.tld se busca primero.

    Con las versiones de Postfix anteriores a la 2.1, la extensión de dirección opcional siempre se ignora.

  • A continuación, se busca la dirección usuario@dominio.tld, sin extensión de dirección.
  • Finalmente, se busca el destinatario @dominio.

Cuando la tabla se proporciona a través de otros medios como NIS, LDAP o SQL, se realizan las mismas búsquedas que para los archivos indexados ordinarios.

Alternativamente, una tabla puede proporcionarse como un mapa de expresiones regulares donde los patrones se dan como expresiones regulares. En ese caso, solo se proporciona la dirección completa del destinatario al mapa de expresiones regulares.

SEGURIDAD

El agente de entrega virtual(8) no es sensible a la seguridad, siempre que las tablas de búsqueda con información de ID de usuario/grupo del destinatario estén adecuadamente protegidas. Este programa no está diseñado para ejecutarse chrooted.

El agente de entrega virtual(8) no permite la sustitución de expresiones regulares de $1, etc. en tablas de búsqueda de expresiones regulares, ya que eso abriría un agujero de seguridad.

El agente de entrega virtual(8) ignorará silenciosamente las solicitudes para usar el servidor proxymap(8). En su lugar, abrirá la tabla directamente. Antes de la versión 2.2 de Postfix, el agente de entrega virtual terminará con un error fatal.

ESTÁNDARES

RFC 822 (Mensajes de Texto de Internet ARPA)

DIAGNÓSTICOS


El correo se devuelve cuando el destinatario no tiene buzón o cuando el destinatario supera la cuota de disco. En todos los demás casos problemáticos, el correo para un destinatario existente se pospone y se registra una advertencia.

Los problemas y las transacciones se registran en syslogd(8) o postlogd(8). Los archivos de mensajes corruptos se marcan para que el gestor de colas pueda moverlos a la cola corrupt posteriormente.

Dependiendo de la configuración del parámetro notify_classes, se notifica al postmaster sobre las devoluciones y otros problemas.

ERRORES


Este agente de entrega admite extensiones de dirección en direcciones de correo electrónico y en claves de tabla de búsqueda, pero no propaga la información de extensión de dirección al resultado de la búsqueda de tabla.

Postfix debería tener tablas de búsqueda que puedan devolver múltiples atributos de resultado. Para evitar la inconveniencia de mantener tres tablas, utilice una base de datos LDAP o MYSQL.

PARÁMETROS DE CONFIGURACIÓN

Los cambios en main.cf se capturan automáticamente, ya que los procesos de virtual(8) se ejecutan durante un tiempo limitado. Utilice el comando "postfix reload" para acelerar un cambio.

El texto a continuación solo proporciona un resumen de los parámetros. Consulte postconf(5) para obtener más detalles, incluidos ejemplos.

CONTROLES DE ENTREGA DE BUZÓN

virtual_mailbox_base (vacío)
Un prefijo que el agente de entrega virtual(8) antepone a todos los resultados de ruta de nombres de las búsquedas de tablas de $virtual_mailbox_maps.
virtual_mailbox_maps (vacío)
Tablas de búsqueda opcionales con todas las direcciones válidas en los dominios que coinciden con $virtual_mailbox_domains.
virtual_minimum_uid (100)
El valor mínimo de ID de usuario que el agente de entrega virtual(8) acepta como resultado de la búsqueda de tabla de $virtual_uid_maps.

NAME

virtual
- domain-specific mailbox delivery agent

SYNOPSIS

/usr/sbin/postfix virtual [-l] [-P] [-R] [-S] [-v] [-c config_dir] user ...

DESCRIPTION

The virtual(8) delivery agent delivers mail to domain-specific mailboxes. This is used for virtual domain hosting, where one machine handles mail for multiple domains.

The delivery agent is configured with a list of domains for which it is responsible. For each recipient address, it looks up the corresponding local mailbox username or destination.

The virtual(8) delivery agent is typically configured via the Postfix master.cf(5) file and is invoked by the Postfix local(8) delivery agent or the Postfix pipe(8) delivery agent when mail is delivered to a virtual domain.

The default configuration is to deliver mail to the user's home directory (e.g., /home/user/Maildir/ or /home/user/mailbox).

MAILBOX LOCATION

The location of the user's mailbox is determined by the virtual_mailbox_base parameter and the lookup result from the virtual_mailbox_maps lookup table.

The default location for mailboxes is controlled by virtual_mailbox_base. This is the parent directory for all virtual mailboxes. The lookup result from virtual_mailbox_maps is appended to this base directory.

For example, if virtual_mailbox_base is set to /var/mail/vhosts and the lookup result for the recipient user@example.com is example.com/user/, then the final mailbox location will be /var/mail/vhosts/example.com/user/.

UNIX MAILBOX FORMAT

If virtual_mailbox_format is set to mbox (the default), the mail is delivered to a file named mailbox in the user's mail directory. The mail is appended to this file.

If virtual_mailbox_format is set to maildir, the mail is delivered to a subdirectory named Maildir/. This subdirectory must contain the directories tmp/, new/, and cur/. New mail is placed in the new/ directory.

QMAIL MAILDIR FORMAT

The maildir format is based on the qmail maildir format by Daniel Bernstein.

MAILBOX OWNERSHIP

The mailboxes are owned by the user and group specified by virtual_uid_maps and virtual_gid_maps. The delivery agent will change its user and group ID to match the recipient's before writing to the mailbox.

If strict_mailbox_ownership is enabled (the default), delivery will fail if the mailbox file or directory is not owned by the recipient.

CASE FOLDING

The domain part of the recipient address is folded to lower case before lookup in the virtual_mailbox_maps table.

TABLE SEARCH ORDER

When looking up a recipient address in the virtual_mailbox_maps table, the following order is tried:

  1. Recipient address with domain (e.g., user@example.com).
  2. Recipient address local part (e.g., user).

SECURITY

The virtual(8) delivery agent executes as the recipient's user and group ID, after looking up the user and group in the virtual_uid_maps and virtual_gid_maps tables. This ensures that mail is delivered with the correct ownership.

The agent will refuse to deliver mail to destinations outside the domain specified by virtual_mailbox_domains, unless virtual_alias_maps or virtual_mailbox_maps explicitly map to a different transport.

STANDARDS

RFC 5322, RFC 5321.

DIAGNOSTICS

Issues are logged to syslogd(8).

BUGS

The virtual(8) delivery agent supports only a limited set of message header updates. For more advanced features, consider using the procmail(1) delivery agent.

CONFIGURATION PARAMETERS

The following configuration parameters are used by virtual(8):

MAILBOX DELIVERY CONTROLS

virtual_mailbox_maps (see 'postconf -d' output)
Lookup table for the destination mailbox or alias.
virtual_mailbox_base (empty)
The base directory for virtual mailboxes. If non-empty, it is prepended to the lookup result from virtual_mailbox_maps.
virtual_mailbox_format (mbox)
The format of the mail directory: mbox or maildir.
virtual_uid_maps (empty)
Lookup tables with the per-recipient user ID that the virtual(8) delivery agent uses while writing to the recipient's mailbox.
virtual_gid_maps (empty)
Lookup tables with the per-recipient group ID for virtual(8) mailbox delivery.

The default mail delivery transport and next-hop destination for final delivery to domains listed with $virtual_mailbox_domains.

HISTORY



This delivery agent was originally based on the Postfix local delivery agent. Modifications mainly consisted of removing code that either was not applicable or that was not safe in this context: aliases, ~user/.forward files, delivery to "|command" or to /file/name.

The Delivered-To: message header appears in the qmail system by Daniel Bernstein.

The maildir structure appears in the qmail system by Daniel Bernstein.

NAME

virtual - Control de la tabla de rutas virtuales del kernel.

SYNOPSIS

virtual [--help] [--version]

virtual add <dev> <via> [<mtu>]

virtual del <dev> <via>

virtual list

virtual flush

DESCRIPTION

El comando virtual se utiliza para gestionar la tabla de rutas virtuales del kernel. Esta tabla se utiliza para implementar el enrutamiento basado en políticas y otras funcionalidades avanzadas de red.

OPTIONS

--help
Muestra un mensaje de ayuda y sale.
--version
Muestra la información de la versión y sale.

Comandos:

add <dev> <via> [<mtu>]
Añade una ruta virtual. <dev> es la interfaz de red de salida. <via> es la dirección del siguiente salto. <mtu> (opcional) es la Unidad Máxima de Transmisión a utilizar.
del <dev> <via>
Elimina una ruta virtual existente. <dev> es la interfaz de red de salida. <via> es la dirección del siguiente salto.
list
Muestra todas las rutas virtuales configuradas.
flush
Elimina todas las rutas virtuales configuradas.

LOCKING CONTROLS

Este comando no proporciona controles de bloqueo explícitos. La gestión de la tabla de rutas se realiza a través de las operaciones atómicas del kernel.

RESOURCE AND RATE CONTROLS

Este comando no proporciona controles directos sobre recursos o tasas. El uso de la red se ve afectado indirectamente por la configuración de enrutamiento.

MISCELLANEOUS CONTROLS

No hay controles misceláneos específicos para este comando más allá de las opciones y comandos descritos.
