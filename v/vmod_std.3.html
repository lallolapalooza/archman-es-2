DESCRIPCIÓN

vmod_std contiene funciones básicas que son parte integral de Vinyl Cache, pero que por razones de arquitectura encajan mejor en un VMOD.

Funciones numéricas

REAL random(REAL lo, REAL hi)

Devuelve un número real aleatorio de la distribución uniforme entre lo (inclusive) y hi (exclusive), en otras palabras, desde el intervalo semiabierto, semicerrado [lo, hi).

Esta función utiliza el generador aleatorio "testable" en vinyld que permite ejecutar pruebas deterministas (Véase el comando CLI debug.srandom). Esta función no debe usarse para aplicaciones criptográficas.

Tenga en cuenta que, al formatear para la salida, cualquier número REAL se redondea a tres dígitos decimales, véase vcl(7).

Ejemplo:

set beresp.http.random-number = std.random(1, 100);

REAL round(REAL r)

Redondea el real r al entero más cercano, pero los casos de mitad exacta se redondean alejándose de cero (véase round(3)).

Funciones de cadena

VOID collect(HEADER hdr, STRING sep=", ")

Colapsa múltiples cabeceras hdr en una sola cabecera larga. El separador predeterminado sep es el separador de coma estándar que se usa al colapsar cabeceras, con un espacio en blanco adicional para una impresión bonita.

Se debe tener cuidado al colapsar cabeceras. En particular, colapsar Set-Cookie provocará resultados inesperados en el lado del navegador.

Usar hdr de obj.http provoca un fallo de VCL.

Ejemplos:

std.collect(req.http.accept);
std.collect(req.http.cookie, "; ");

VOID collect_all(HTTP where)

Combina todas las cabeceras múltiples en where según las reglas predeterminadas según los RFC de HTTP:

  • Set-Cookie no se combina
  • Cookie se combina con el separador "; " (punto y coma espacio)
  • Todas las demás cabeceras se combinan con el separador ", " (coma espacio)

where puede ser req, resp, bereq o beresp.

Ejemplos:

std.collect_all(req);
std.collect_all(beresp);

STRING querysort(STRING)

Ordena la cadena de consulta con fines de normalización de caché.

Ejemplo:

set req.url = std.querysort(req.url);

STRING toupper(STRING s)

Convierte la cadena s a mayúsculas.

Ejemplo:

set beresp.http.scream = std.toupper("yes!");

STRING tolower(STRING s)

Convierte la cadena s a minúsculas.

Ejemplo:

set beresp.http.nice = std.tolower("VerY");

STRING strstr(STRING s1, STRING s2)

Devuelve una cadena que comienza en la primera aparición de la cadena s2 en la cadena s1, o una cadena vacía si s2 no se encuentra.

Tenga en cuenta que la comparación distingue entre mayúsculas y minúsculas.

Ejemplo:

if (std.strstr(req.url, req.http.restrict)) {
        ...
}

Esto comprobará si el contenido de req.http.restrict aparece en cualquier parte de req.url.

BOOL fnmatch(STRING pattern, STRING subject, BOOL pathname, BOOL noescape, BOOL period)

BOOL fnmatch(
   STRING pattern,
   STRING subject,
   BOOL pathname=1,
   BOOL noescape=0,
   BOOL period=0
)

Coincidencia de patrones al estilo del shell; devuelve true si subject coincide con pattern, donde pattern puede contener caracteres comodín como * o ?.

La coincidencia se ejecuta mediante la implementación de fnmatch(3) en su sistema. Las reglas para la coincidencia de patrones en la mayoría de los sistemas incluyen lo siguiente:

  • * coincide con cualquier secuencia de caracteres
  • ? coincide con un solo carácter
  • una expresión entre corchetes como [abc] o [!0-9] se interpreta como una clase de caracteres según las reglas de las expresiones regulares básicas (no las regex de pcre2(3)), excepto que ! se usa para la negación de clase de caracteres en lugar de ^.

Si pathname es true, entonces el carácter de barra diagonal / solo coincide literalmente, y nunca coincide con *, ? o una expresión entre corchetes. De lo contrario, / puede coincidir con uno de esos patrones. De forma predeterminada, pathname es true.

Si noescape es true, entonces el carácter de barra invertida \ coincide como un carácter ordinario. De lo contrario, \ es un carácter de escape, y coincide con el carácter que lo sigue en el pattern. Por ejemplo, \\ coincide con \ cuando noescape es true, y \\ cuando es false. De forma predeterminada, noescape es false.

Si period es true, entonces un carácter de punto inicial . solo coincide literalmente, y nunca coincide con *, ? o una expresión entre corchetes. Un punto es inicial si es el primer carácter en subject; si pathname también es true, entonces un punto que sigue inmediatamente a un / también es inicial (como en /.). De forma predeterminada, period es false.

std.fnmatch() provoca un fallo de VCL y devuelve false si cualquiera de pattern o subject es NULL -- por ejemplo, si se especifica una cabecera no establecida.

Ejemplos:

# Coincide con URL como /foo/bar y /foo/baz
if (std.fnmatch("/foo/\*", req.url)) { ... }
# Coincide con URL como /foo/bar/baz y /foo/baz/quux
if (std.fnmatch("/foo/\*/\*", bereq.url)) { ... }
# Coincide con /foo/bar/quux, pero no con /foo/bar/baz/quux
if (std.fnmatch("/foo/\*/quux", req.url)) { ... }
# Coincide con /foo/bar/quux y /foo/bar/baz/quux
if (std.fnmatch("/foo/\*/quux", req.url, pathname=false)) { ... }
# Coincide con /foo/bar, /foo/car y /foo/far
if (std.fnmatch("/foo/?ar", req.url)) { ... }
# Coincide con /foo/ seguido de un no dígito
if (std.fnmatch("/foo/[!0-9]", req.url)) { ... }

Funciones de archivo (sistema)

STRING fileread(STRING)

Lee un archivo de texto y devuelve una cadena con el contenido.

El archivo completo se almacena en caché en la primera llamada, y las llamadas posteriores devolverán este contenido en caché, incluso si el archivo ha cambiado mientras tanto.

Para archivos binarios, use std.blobread() en su lugar.

Ejemplo:

set resp.body = "Response was served by " + std.fileread("/etc/hostname");

Tenga en cuenta que el contenido completo del archivo aparece en la cadena que se devuelve, incluidos los saltos de línea que pueden dar lugar a encabezados no válidos si se usa std.fileread() para formar un encabezado. En ese caso, es posible que necesite modificar la cadena, por ejemplo con regsub() (consulte vcl(7)):

set beresp.http.served-by = regsub(std.fileread("/etc/hostname"), "\R$", "");

BLOB blobread(STRING)

Lee cualquier archivo y devuelve un blob con el contenido.

El archivo completo se almacena en caché en la primera llamada, y las llamadas posteriores devolverán este contenido en caché, incluso si el archivo ha cambiado mientras tanto.

BOOL file_exists(STRING path)

Devuelve true si la ruta o el archivo al que apunta la ruta existe, false en caso contrario.

Ejemplo:

if (std.file_exists("/etc/return_503")) {
        return (synth(503, "Vinyl Cache is in maintenance"));
}

Funciones de inspección de tipos

BOOL healthy(BACKEND be)

Devuelve true si el backend be está en buen estado.

INT port(IP ip)

Devuelve el número de puerto de la dirección IP ip. Siempre devuelve 0 para una variable *.ip cuando la dirección es un socket de dominio Unix.

Funciones de conversión de tipos

Todas estas funciones tienen la misma forma:

TIPO tipo([argumentos], [TIPO fallback])

Se debe proporcionar exactamente uno de los argumentos (además del fallback opcional), y se convertirá a TIPO.

Si la conversión falla, se devolverá fallback y si no se especificó ningún fallback, el VCL fallará.

DURATION duration([STRING s], [DURATION fallback], [REAL real], [INT integer])

DURATION duration(
   [STRING s],
   [DURATION fallback],
   [REAL real],
   [INT integer]
)

Devuelve un DURATION a partir de un argumento STRING, REAL o INT.

Para un argumento STRING s, s debe estar cuantificado por unidades ms (milisegundos), s (segundos), m (minutos), h (horas), ``d`` (días), w (semanas) o y (años).

Los argumentos real e integer se toman como segundos.

Si la conversión de un argumento s falla, se devolverá fallback si se proporcionó, o se activará un fallo de VCL.

Las conversiones de argumentos real e integer nunca fallan.

Solo se puede proporcionar uno de los argumentos s, real o integer o se activará un fallo de VCL.

Ejemplos:

set beresp.ttl = std.duration("1w", 3600s);
set beresp.ttl = std.duration(real=1.5);
set beresp.ttl = std.duration(integer=10);

BYTES bytes([STRING s], [BYTES fallback], [REAL real], [INT integer])

BYTES bytes(
   [STRING s],
   [BYTES fallback],
   [REAL real],
   [INT integer]
)

Devuelve BYTES a partir de un argumento STRING, REAL o INT.

Un argumento STRING s puede cuantificarse con un multiplicador (k (kilo), m (mega), g (giga), t (tera) o p (peta)).

Los argumentos real e integer se toman como bytes.

Si la conversión de un argumento s falla, se devolverá fallback si se proporcionó, o se activará un fallo de VCL.

Otras conversiones pueden fallar si el argumento no puede representarse, porque es negativo, demasiado pequeño o demasiado grande. De nuevo, se devolverá fallback si se proporcionó, o se activará un fallo de VCL.

Los argumentos real se redondearán hacia abajo.

Solo se puede proporcionar uno de los argumentos s, real o integer o se activará un fallo de VCL.

Ejemplo:

std.cache_req_body(std.bytes(something.somewhere, 10K));
std.cache_req_body(std.bytes(integer=10*1024));
std.cache_req_body(std.bytes(real=10.0*1024));

INT integer([STRING s], [INT fallback], [BOOL bool], [BYTES bytes], [DURATION duration], [REAL real], [TIME time])

INT integer(
   [STRING s],
   [INT fallback],
   [BOOL bool],
   [BYTES bytes],
   [DURATION duration],
   [REAL real],
   [TIME time]
)

Devuelve un INT a partir de un STRING, BOOL u otra cantidad.

Si la conversión de un argumento s falla, se devolverá fallback si se proporcionó, o se activará un fallo de VCL.

Un argumento bool se devolverá como 0 para false y 1 para true. Esta conversión nunca fallará.

Para un argumento bytes, se devolverá el número de bytes. Esta conversión nunca fallará.

Un argumento duration se redondeará hacia abajo al número de segundos y se devolverá.

Un argumento real se redondeará hacia abajo y se devolverá.

Para un argumento time, se devolverá el número de segundos desde la época UNIX (1970-01-01 00:00:00 UTC).

Las conversiones de duration, real y time pueden fallar si el argumento no puede representarse porque es demasiado pequeño o demasiado grande. Si es así, se devolverá fallback si se proporcionó, o se activará un fallo de VCL.

Solo se puede proporcionar uno de los argumentos s, bool, bytes, duration, real o time o se activará un fallo de VCL.

Ejemplos:

if (std.integer(req.http.foo, 0) > 5) {
        ...
}
set resp.http.answer = std.integer(real=126.42/3);

IP ip(STRING s, [IP fallback], BOOL resolve=1, [STRING p])

Convierte la cadena s al primer número IP devuelto por la función de biblioteca del sistema getaddrinfo(3). Si la conversión falla, se devolverá fallback o se producirá un fallo de VCL.

La dirección IP incluye un número de puerto que se puede encontrar con std.port() que por defecto es 80. El puerto predeterminado se puede establecer en un valor diferente con el argumento p. Se anulará si s contiene tanto una dirección IP como un número de puerto o nombre de servicio.

Cuando s contiene ambos, la sintaxis es dirección:puerto o dirección puerto. Si la dirección es una dirección IPv6 numérica, debe estar entre corchetes, por ejemplo [::1] 80 o [::1]:http. El fallback también puede contener tanto una dirección como un puerto, pero su puerto predeterminado siempre es 80.

Si resolve es falso, se llama a getaddrinfo(3) usando AI_NUMERICHOST y AI_NUMERICSERV para evitar búsquedas de red dependiendo de la configuración de getaddrinfo(3) o nsswitch del sistema. Esto hace que las cadenas IP y servicios "numéricos" sean más económicos de convertir.

Ejemplo:

if (std.ip(req.http.X-forwarded-for, "0.0.0.0") ~ my_acl) {
        ...
}

REAL real([STRING s], [REAL fallback], [INT integer], [BOOL bool], [BYTES bytes], [DURATION duration], [TIME time])

REAL real(
   [STRING s],
   [REAL fallback],
   [INT integer],
   [BOOL bool],
   [BYTES bytes],
   [DURATION duration],
   [TIME time]
)

Devuelve un REAL a partir de un STRING, BOOL u otra cantidad.

Si la conversión de un argumento s falla, se devolverá fallback si se proporcionó, o se activará un fallo de VCL.

Un argumento bool se devolverá como 0.0 para false y 1.0 para true.

Para un argumento bytes, se devolverá el número de bytes.

Para un argumento duration, se devolverá el número de segundos.

Un argumento integer se devolverá como un REAL.

Para un argumento time, se devolverá el número de segundos desde la época UNIX (1970-01-01 00:00:00 UTC).

Ninguna de estas conversiones aparte de s fallará.

Solo se puede proporcionar uno de los argumentos s, integer, bool, bytes, duration o time o se activará un fallo de VCL.

Ejemplo:

if (std.real(req.http.foo, 0.0) > 5.5) {
        ...
}

TIME time([STRING s], [TIME fallback], [REAL real], [INT integer])

TIME time([STRING s], [TIME fallback], [REAL real], [INT integer])

Devuelve un TIME a partir de un argumento STRING, REAL o INT.

Para un argumento STRING s, se admiten los siguientes formatos:

"Sun, 06 Nov 1994 08:49:37 GMT"
"Sunday, 06-Nov-94 08:49:37 GMT"
"Sun Nov  6 08:49:37 1994"
"1994-11-06T08:49:37"
"784111777.00"
"784111777"

Los argumentos real e integer se toman como segundos desde la época.

Si la conversión de un argumento s falla o se proporciona un argumento real o integer negativo, se devolverá fallback si se proporcionó, o se activará un fallo de VCL.

Ejemplos:

if (std.time(resp.http.last-modified, now) < now - 1w) {
        ...
}
if (std.time(int=2147483647) < now - 1w) {
        ...
}

STRING strftime(TIME time, STRING format)

Formatea el argumento time con el argumento format usando strftime(3) y devuelve el resultado para la zona horaria UTC (históricamente GMT).

Se devuelve la cadena vacía si el formateo falla, pero también puede devolverse como un resultado válido.

Ejemplo:

set req.http.iso = std.strftime(now, "%Y%m%dT%H%M%SZ");
# e.g. 20210521T175241Z

Funciones de REGISTRO

VOID log(STRING s)

Registra la cadena s en el registro de memoria compartida, usando la etiqueta SLT_VCL_Log de vsl(7).

Ejemplo:

std.log("Something fishy is going on with the vhost " + req.http.host);

VOID syslog(INT priority, STRING s)

Registra la cadena s en syslog etiquetada con priority. priority se forma aplicando OR a los valores de facility y level. Consulte el archivo syslog.h de su sistema para conocer los valores posibles.

Aviso: A diferencia de VCL y otras funciones del vmod std, esta función no hará fallar el procesamiento de VCL por desbordamientos del espacio de trabajo: En una condición de espacio de trabajo agotado, la función std.syslog() no tiene efecto.

Ejemplo:

std.syslog(9, "Something is wrong");

Esto enviará un mensaje a syslog usando LOG_USER | LOG_ALERT.

VOID timestamp(STRING s)

Introduce una marca de tiempo en el registro con la hora actual, usando la cadena s como etiqueta. Esto es útil para medir el tiempo de ejecución de subrutinas VCL extensas, y hace que las marcas de tiempo insertadas automáticamente por Vinyl Cache sean más precisas.

Ejemplo:

std.timestamp("curl-request");

CONTROL and INFORMATION functions

BOOL syntax(REAL)

Returns true if VCL version is at least REAL.

STRING getenv(STRING name, STRING fallback=0)

Return environment variable name if it is set, or the fallback if it is not.

The default fallback is NULL, which evaluates to the empty sting in most cases.

See getenv(3).

Example:

set req.http.My-Env = std.getenv("MY_ENV");

BOOL cache_req_body(BYTES size)

Caches the request body if it is smaller than size. Returns true if the body was cached, false otherwise.

Normally the request body can only be sent once. Caching it enables retrying backend requests with a request body, as usually the case with POST and PUT.

Example:

if (std.cache_req_body(1KB)) {
        ...
}

Restricted to: vcl_recv.

VOID late_100_continue(BOOL late)

Controls when vinyld reacts to an Expect: 100-continue client request header.

Vinyl Cache always generates a 100 Continue response if requested by the client trough the Expect: 100-continue header when waiting for request body data.

But, by default, the 100 Continue response is already generated immediately after vcl_recv returns to reduce latencies under the assumption that the request body will be read eventually.

Calling std.late_100_continue(true) in vcl_recv will cause the 100 Continue response to only be sent when needed. This may cause additional latencies for processing request bodies, but is the correct behavior by strict interpretation of RFC7231.

This function has no effect outside vcl_recv and after calling std.cache_req_body() or any other function consuming the request body.

Example:

vcl_recv {
        std.late_100_continue(true);
        if (req.method == "POST") {
                std.late_100_continue(false);
                return (pass);
        }
        ...
 }

Restricted to: vcl_recv.

VOID set_ip_tos(INT tos)

Sets the Differentiated Services Codepoint (DSCP) / IPv4 Type of Service (TOS) / IPv6 Traffic Class (TCLASS) byte for the current session to tos. Silently ignored if the listen address is a Unix domain socket.

Please note that setting the traffic class affects all requests on the same http1.1 / http2 TCP connection and, in particular, is not removed at the end of the request.

Example:

if (req.url ~ "^/slow/") {
        std.set_ip_tos(0);
}

Restricted to: client.

VOID rollback(HTTP h=0)

Restores the current task to its original state.

The h argument is obsolete and ignored.

Example:

std.rollback();

Restricted to: backend, vcl_recv, vcl_pass, vcl_hash, vcl_purge, vcl_miss, vcl_hit, vcl_deliver, vcl_synth.

BOOL ban(STRING)

Invalidates all objects in cache that match the given expression with the ban mechanism. Returns true if the ban succeeded and false otherwise. Error details are available via std.ban_error().

The format of STRING is:

<field> <operator> <arg> [&& <field> <oper> <arg> ...]
•
<field>:
•
string fields:
  • req.url: The request url
  • req.http.*: Any request header
  • obj.status: The cache object status
  • obj.http.*: Any cache object header

obj.status is treated as a string despite the fact that it is actually an integer.

•
duration fields:
  • obj.ttl: Remaining ttl
  • obj.age: Object age
  • obj.grace: The grace time of the object
  • obj.keep: The keep time of the object
  • obj.last_hit: Time since the last hit

obj.ttl, obj.age and obj.last_hit are relative to the submission time of the ban, such that they represent a fixed point in time despite being specified as a duration.

•
boolean fields:
  • obj.uncacheable uncacheable object (either HFM or HFP)
  • obj.hfm Hit-For-Miss object
  • obj.hfp Hit-For-Pass object
•
<operator>:
•
for all fields:
  • ==: <field> and <arg> are equal
  • !=: <field> and <arg> are unequal

strings are compared case-sensitively

•
for string fields:
  • ~: <field> matches the regular expression <arg>
  • !~:<field> does not match the regular expression <arg>
•
for duration fields:
  • >: <field> is greater than <arg>
  • >=: <field> is greater than or equal to <arg>
  • <: <field> is less than <arg>
  • <=: <field> is less than or equal to <arg>
•
for boolean fields:
•
Only == and != can be used with boolean fields.
•
<arg>:
  • for string fields:

    Either a literal string or a regular expression. Note that <arg> does not use any of the string delimiters like " or {"..."} or """...""" used elsewhere in Vinyl Cache. To match against strings containing whitespace, regular expressions containing \s can be used.

  • for duration fields:

    A VCL duration like 10s, 5m or 1h, see vcl(7)_durations

  • for boolean fields:

    A boolean field can only be compared to true``or ``false.

Expressions can be chained using the and operator &&. For or semantics, use several bans.

The unset <field> is not equal to any string, such that, for a non-existing header, the operators == and ~ always evaluate as false, while the operators != and !~ always evaluate as true, respectively, for any value of <arg>.

obj.last_hit can be used almost as a "last accessed" time, so, for example, ban obj.last_hit > 1d removes all objects which were last accessed more than one day ago. Also, it can be used to remove objects stuck at request bans by issuing ban obj.last_hit > X, with X being slightly less than the time since the request ban.

obj.last_hit is based on an internal last LRU time, which might not be implemented by all storage engines. Where it is not available, ban expressions using obj.last_hit evaluate to false, which means that the respective ban behaves as if it was not present. Where implemented, the last LRU time might only get updated by the lru_interval parameter, which therefore is the maximum precision of obj.last_hit bans.

STRING ban_error()

Returns a textual error description of the last std.ban() call from the same task or the empty string if there either was no error or no std.ban() call.

TIME now()

Returns the current time. In contrast to the now built-in variable, every call returns a new value.

DURATION timed_call(SUB)

Call the given SUB and return a high precision measurement of the execution time.

VOID rfc_ttl()

Restricted to: vcl_backend_response, vcl_backend_refresh.

Re-calculate the object timers (beresp.ttl, beresp.grace and beresp.keep) based on the current state of beresp as if it had been processed by core code before vcl_backend_response was called. This does not change beresp.uncacheable.

This is useful to get the default ttl calculations after modifications of relevant properties like beresp.status, beresp.http.Date, beresp.http.Age or beresp.http.Cache-Control.
