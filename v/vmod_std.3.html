DESCRIPTION

vmod_std contains basic functions which are part and parcel of Varnish, but which for reasons of architecture fit better in a VMOD.

NUMERIC FUNCTIONS

REAL random(REAL lo, REAL hi)

Returns a random real number between lo and hi.

This function uses the "testable" random generator in varnishd which enables deterministic tests to be run (See debug.srandom CLI command). This function should not be used for cryptographic applications.

Example:

set beresp.http.random-number = std.random(1, 100);

REAL round(REAL r)

Rounds the real r to the nearest integer, but round halfway cases away from zero (see round(3)).

STRING FUNCTIONS

VOID collect(HEADER hdr, STRING sep=", ")

Collapses multiple hdr headers into one long header. The default separator sep is the standard comma separator to use when collapsing headers, with an additional whitespace for pretty printing.

Care should be taken when collapsing headers. In particular collapsing Set-Cookie will lead to unexpected results on the browser side.

Using hdr from obj.http triggers a VCL failure.

Examples:

std.collect(req.http.accept);
std.collect(req.http.cookie, "; ");

STRING querysort(STRING)

Sorts the query string for cache normalization purposes.

Example:

set req.url = std.querysort(req.url);

STRING toupper(STRING s)

Converts the string s to uppercase.

Example:

set beresp.http.scream = std.toupper("yes!");

STRING tolower(STRING s)

Converts the string s to lowercase.

Example:

set beresp.http.nice = std.tolower("VerY");

STRING strstr(STRING s1, STRING s2)

Returns a string beginning at the first occurrence of the string s2 in the string s1, or an empty string if s2 is not found.

Note that the comparison is case-sensitive.

Example:

if (std.strstr(req.url, req.http.restrict)) {
        ...
}

This will check if the content of req.http.restrict occurs anywhere in req.url.

BOOL fnmatch(STRING pattern, STRING subject, BOOL pathname, BOOL noescape, BOOL period)

BOOL fnmatch(
   STRING pattern,
   STRING subject,
   BOOL pathname=1,
   BOOL noescape=0,
   BOOL period=0
)

Shell-style pattern matching; returns true if subject matches pattern, where pattern may contain wildcard characters such as * or ?.

The match is executed by the implementation of fnmatch(3) on your system. The rules for pattern matching on most systems include the following:

  • * matches any sequence of characters
  • ? matches a single character
  • a bracket expression such as [abc] or [!0-9] is interpreted as a character class according to the rules of basic regular expressions (not pcre2(3) regexen), except that ! is used for character class negation instead of ^.

If pathname is true, then the forward slash character / is only matched literally, and never matches *, ? or a bracket expression. Otherwise, / may match one of those patterns. By default, pathname is true.

If noescape is true, then the backslash character \ is matched as an ordinary character. Otherwise, \ is an escape character, and matches the character that follows it in the pattern. For example, \\ matches \ when noescape is true, and \\ when false. By default, noescape is false.

If period is true, then a leading period character . only matches literally, and never matches *, ? or a bracket expression. A period is leading if it is the first character in subject; if pathname is also true, then a period that immediately follows a / is also leading (as in /.). By default, period is false.

std.fnmatch() invokes VCL failure and returns false if either of pattern or subject is NULL -- for example, if an unset header is specified.

Examples:

# Matches URLs such as /foo/bar and /foo/baz
if (std.fnmatch("/foo/*", req.url)) { ... }
# Matches URLs such as /foo/bar/baz and /foo/baz/quux
if (std.fnmatch("/foo/*/ *", bereq.url)) { ... }
# Matches /foo/bar/quux, but not /foo/bar/baz/quux
if (std.fnmatch("/foo/*/quux", req.url)) { ... }
# Matches /foo/bar/quux and /foo/bar/baz/quux
if (std.fnmatch("/foo/*/quux", req.url, pathname=false)) { ... }
# Matches /foo/bar, /foo/car and /foo/far
if (std.fnmatch("/foo/?ar", req.url)) { ... }
# Matches /foo/ followed by a non-digit
if (std.fnmatch("/foo/[!0-9]", req.url)) { ... }

FILE(SYSTEM) FUNCTIONS

STRING fileread(STRING)

Reads a text file and returns a string with the content.

Todo el archivo se almacena en caché en la primera llamada, y las llamadas subsiguientes devolverán estos contenidos cacheados, incluso si el archivo ha cambiado mientras tanto.

Para archivos binarios, use std.blobread() en su lugar.

Ejemplo:

synthetic("Response was served by " + std.fileread("/etc/hostname"));

Considere que todo el contenido del archivo aparece en la cadena que se devuelve, incluidas las nuevas líneas que pueden dar lugar a cabeceras inválidas si std.fileread() se utiliza para formar una cabecera. En ese caso, puede que necesite modificar la cadena, por ejemplo con regsub() (ver vcl(7)):

set beresp.http.served-by = regsub(std.fileread("/etc/hostname"), "\R$", "");

BLOB blobread(STRING)

Lee cualquier archivo y devuelve un blob con el contenido.

Todo el archivo se almacena en caché en la primera llamada, y las llamadas subsiguientes devolverán estos contenidos cacheados, incluso si el archivo ha cambiado mientras tanto.

BOOL file_exists(STRING path)

Devuelve true si la ruta o el archivo al que apunta la ruta existen, false en caso contrario.

Ejemplo:

if (std.file_exists("/etc/return_503")) {
        return (synth(503, "Varnish is in maintenance"));
}

INT port(IP ip)

FUNCIONES DE CONVERSIÓN DE TIPO

Todas estas funciones tienen el mismo formato:

TYPE type([argumentos], [TYPE de respaldo])

Exactamente uno de los argumentos debe ser proporcionado (además del respaldo opcional), y se convertirá a TYPE.

Si la conversión falla, se devolverá el respaldo y si no se especificó ningún respaldo, el VCL fallará.

DURATION duration([STRING s], [DURATION fallback], [REAL real], [INT integer])

DURATION duration(
   [STRING s],
   [DURATION fallback],
   [REAL real],
   [INT integer]
)

Devuelve una DURACIÓN a partir de un argumento STRING, REAL o INT.

Para un argumento STRING s, s debe ser cuantificado con unidades ms (milisegundos), s (segundos), m (minutos), h (horas),``d`` (días), w (semanas) o y (años).

Los argumentos real e integer se toman como segundos.

Si la conversión de un argumento s falla, se devolverá el respaldo si se proporciona, o se activará un fallo de VCL.

Las conversiones de los argumentos real e integer nunca fallan.

Solo uno de los argumentos s, real o integer puede ser proporcionado o se activará un fallo de VCL.

Ejemplos:

set beresp.ttl = std.duration("1w", 3600s);
set beresp.ttl = std.duration(real=1.5);
set beresp.ttl = std.duration(integer=10);

BYTES bytes([STRING s], [BYTES fallback], [REAL real], [INT integer])

BYTES bytes(
   [STRING s],
   [BYTES fallback],
   [REAL real],
   [INT integer]
)

Devuelve BYTES a partir de un argumento STRING, REAL o INT.

Un argumento STRING s puede ser cuantificado con un multiplicador (k (kilo), m (mega), g (giga), t (tera) o p (peta)).

Los argumentos real e integer se toman como bytes.

Si la conversión de un argumento s falla, se devolverá el respaldo si se proporciona, o se activará un fallo de VCL.

Otras conversiones pueden fallar si el argumento no puede ser representado, porque es negativo, demasiado pequeño o demasiado grande. De nuevo, se devolverá el respaldo si se proporciona, o se activará un fallo de VCL.

Los argumentos real se redondearán hacia abajo.

Solo uno de los argumentos s, real o integer puede ser proporcionado o se activará un fallo de VCL.

Ejemplo:

std.cache_req_body(std.bytes(something.somewhere, 10K));
std.cache_req_body(std.bytes(integer=10*1024));
std.cache_req_body(std.bytes(real=10.0*1024));

INT integer([STRING s], [INT fallback], [BOOL bool], [BYTES bytes], [DURATION duration], [REAL real], [TIME time])

INT integer(
   [STRING s],
   [INT fallback],
   [BOOL bool],
   [BYTES bytes],
   [DURATION duration],
   [REAL real],
   [TIME time]
)

Devuelve un INT a partir de un argumento STRING, BOOL u otra cantidad.

Si la conversión de un argumento s falla, se devolverá el respaldo si se proporciona, o se activará un fallo de VCL.

Un argumento bool se devolverá como 0 para false y 1 para true. Esta conversión nunca fallará.

Para un argumento bytes, se devolverá el número de bytes. Esta conversión nunca fallará.

Un argumento duration se redondeará hacia abajo al número de segundos y se devolverá.

Un argumento real se redondeará hacia abajo y se devolverá.

Para un argumento time, se devolverá el número de segundos desde la época UNIX (1970-01-01 00:00:00 UTC).

Las conversiones duration, real y time pueden fallar si el argumento no puede ser representado porque es demasiado pequeño o demasiado grande. En tal caso, se devolverá el respaldo si se proporciona, o se activará un fallo de VCL.

Solo uno de los argumentos s, bool, bytes, duration, real o time puede ser proporcionado o se activará un fallo de VCL.

Ejemplos:

if (std.integer(req.http.foo, 0) > 5) {
        ...
}
set resp.http.answer = std.integer(real=126.42/3);

IP ip(STRING s, [IP fallback], BOOL resolve=1, [STRING p])

Convierte la cadena s al primer número IP devuelto por la función de biblioteca del sistema getaddrinfo(3). Si la conversión falla, se devolverá fallback o ocurrirá un fallo de VCL.

La dirección IP incluye un número de puerto que se puede encontrar con std.port() que por defecto es 80. El puerto por defecto se puede establecer a un valor diferente con el argumento p. Será anulado si s contiene tanto una dirección IP como un número de puerto o nombre de servicio.

Cuando s contiene ambos, la sintaxis es address:port o address port. Si la dirección es una dirección IPv6 numérica debe estar entre corchetes, por ejemplo [::1] 80 o [::1]:http. El respaldo también puede contener tanto una dirección como un puerto, pero su puerto por defecto es siempre 80.

Si resolve es falso, se llama a getaddrinfo(3) usando AI_NUMERICHOST y AI_NUMERICSERV para evitar búsquedas de red dependiendo de la configuración de getaddrinfo(3) o nsswitch del sistema. Esto hace que las cadenas IP y los servicios "numéricos" sean más baratos de convertir.

Ejemplo:

if (std.ip(req.http.X-forwarded-for, "0.0.0.0") ~ my_acl) {
        ...
}

REAL real([STRING s], [REAL fallback], [INT integer], [BOOL bool], [BYTES bytes], [DURATION duration], [TIME time])

REAL real(
   [STRING s],
   [REAL fallback],
   [INT integer],
   [BOOL bool],
   [BYTES bytes],
   [DURATION duration],
   [TIME time]
)

Devuelve un REAL a partir de una cadena, BOOL u otra cantidad.

Si la conversión de un argumento s falla, se devolverá el respaldo si se proporciona, o se activará un fallo de VCL.

Un argumento bool se devolverá como 0.0 para false y 1.0 para true.

Para un argumento bytes, se devolverá el número de bytes.

Para un argumento duration, se devolverá el número de segundos.

Un argumento integer se devolverá como un REAL.

Para un argumento time, se devolverá el número de segundos desde la época UNIX (1970-01-01 00:00:00 UTC).

Ninguna de estas conversiones, excepto la de s, fallará.

Solo uno de los argumentos s, integer, bool, bytes, duration o time puede ser proporcionado o se activará un fallo de VCL.

Ejemplo:

if (std.real(req.http.foo, 0.0) >
gt; 5.5) { ... }

TIME time([STRING s], [TIME fallback], [REAL real], [INT integer])

TIME time([STRING s], [TIME fallback], [REAL real], [INT integer])

Devuelve un TIME a partir de un argumento STRING, REAL o INT.

Para un argumento STRING s, se admiten los siguientes formatos:

"Sun, 06 Nov 1994 08:49:37 GMT"
"Sunday, 06-Nov-94 08:49:37 GMT"
"Sun Nov  6 08:49:37 1994"
"1994-11-06T08:49:37"
"784111777.00"
"784111777"

Los argumentos real e integer se toman como segundos desde la época.

Si la conversión de un argumento s falla o se proporciona un argumento real o integer negativo, se devolverá fallback si se proporciona, o se activará un fallo de VCL.

Ejemplos:

if (std.time(resp.http.last-modified, now) < now - 1w) {
        ...
}
if (std.time(int=2147483647) < now - 1w) {
        ...
}

STRING strftime(TIME time, STRING format)

Formatea el argumento time con el argumento format utilizando strftime(3) y devuelve el resultado para la zona horaria UTC (históricamente GMT).

Se devuelve una cadena vacía si el formateo falla, pero también puede devolverse como un resultado válido.

Ejemplo:

set req.http.iso = std.strftime(now, "%Y%m%dT%H%M%SZ");
# por ejemplo, 20210521T175241Z

FUNCIONES DE REGISTRO

VOID log(STRING s)

Registra la cadena s en el registro de memoria compartida, utilizando la etiqueta vsl(7) SLT_VCL_Log.

Ejemplo:

std.log("Something fishy is going on with the vhost " + req.http.host);

VOID syslog(INT priority, STRING s)

Registra la cadena s en syslog con la etiqueta priority. priority se forma mediante OR de los valores de instalación y nivel. Consulte el archivo syslog.h de su sistema para ver los valores posibles.

Aviso: A diferencia de VCL y otras funciones del módulo std, esta función no fallará el procesamiento de VCL por desbordamientos de memoria: en caso de que la memoria se agote, la función std.syslog() no tendrá ningún efecto.

Ejemplo:

std.syslog(9, "Something is wrong");

Esto enviará un mensaje a syslog usando LOG_USER | LOG_ALERT.

VOID timestamp(STRING s)

Introduce una marca de tiempo en el registro con la hora actual, utilizando la cadena s como etiqueta. Esto es útil para medir el tiempo de ejecución de subrutinas VCL largas y hace que las marcas de tiempo insertadas automáticamente por Varnish sean más precisas.

Ejemplo:

std.timestamp("curl-request");

FUNCIONES DE CONTROL E INFORMACIÓN

BOOL syntax(REAL)

Devuelve true si la versión de VCL es al menos REAL.

STRING getenv(STRING name)

Devuelve la variable de entorno name o una cadena vacía. Consulte getenv(3).

Ejemplo:

set req.http.My-Env = std.getenv("MY_ENV");

BOOL cache_req_body(BYTES size)

Almacena en caché el cuerpo de la solicitud si es menor que size. Devuelve true si el cuerpo se almacenó en caché, false en caso contrario.

Normalmente, el cuerpo de la solicitud solo se puede enviar una vez. Almacenarlo en caché permite reintentar las solicitudes al backend con un cuerpo de solicitud, como suele ser el caso con POST y PUT.

Ejemplo:

if (std.cache_req_body(1KB)) {
        ...
}

Restringido a: vcl_recv.

VOID late_100_continue(BOOL late)

Controla cuándo varnish reacciona a una cabecera de solicitud del cliente Expect: 100-continue.

Varnish siempre genera una respuesta 100 Continue si el cliente la solicita a través de la cabecera Expect: 100-continue mientras espera datos del cuerpo de la solicitud.

Sin embargo, de forma predeterminada, la respuesta 100 Continue ya se genera inmediatamente después de que vcl_recv devuelva para reducir la latencia, asumiendo que el cuerpo de la solicitud se leerá eventualmente.

Llamar a std.late_100_continue(true) en vcl_recv provocará que la respuesta 100 Continue solo se envíe cuando sea necesario. Esto puede causar latencias adicionales para procesar cuerpos de solicitud, pero es el comportamiento correcto según la interpretación estricta de RFC7231.

Esta función no tiene ningún efecto fuera de vcl_recv y después de llamar a std.cache_req_body() o cualquier otra función que consuma el cuerpo de la solicitud.

Ejemplo:

vcl_recv {
        std.late_100_continue(true);
        if (req.method == "POST") {
                std.late_100_continue(false);
                return (pass);
        }
        ...
 }

Restringido a: vcl_recv.

VOID set_ip_tos(INT tos)

Establece el byte Differentiated Services Codepoint (DSCP) / IPv4 Type of Service (TOS) / IPv6 Traffic Class (TCLASS) para la sesión actual a tos. Se ignora silenciosamente si la dirección de escucha es un socket de dominio Unix.

Tenga en cuenta que establecer la clase de tráfico afecta a todas las solicitudes en la misma conexión TCP http1.1 / http2 y, en particular, no se elimina al final de la solicitud.

Ejemplo:

if (req.url ~ "^/slow/") {
        std.set_ip_tos(0);
}

Restringido a: client.

VOID rollback(HTTP h)

Restaura las cabeceras HTTP h a su estado original.

Ejemplo:

std.rollback(bereq);

Restringido a: backend, vcl_recv, vcl_pass, vcl_hash, vcl_purge, vcl_miss, vcl_hit, vcl_deliver, vcl_synth.

BOOL ban(STRING)

Invalida todos los objetos en caché que coincidan con la expresión dada con el mecanismo de prohibición. Devuelve true si la prohibición tuvo éxito y false en caso contrario. Los detalles del error están disponibles a través de std.ban_error().

El formato de STRING es:

<field> <operator> <arg> [&& <field> <oper> <arg> ...]
•
<field>:
•
campos de cadena:
  • req.url: La URL de la solicitud
  • req.http.*: Cualquier cabecera de solicitud
  • obj.status: El estado del objeto de caché
  • obj.http.*: Cualquier cabecera de objeto de caché

obj.status se trata como una cadena a pesar de que en realidad es un entero.

•
campos de duración:
  • obj.ttl: TTL restante
  • obj.age: Edad del objeto
  • obj.grace: El tiempo de gracia del objeto
  • obj.keep: El tiempo de retención del objeto
  • obj.last_hit: Tiempo desde el último hit

obj.ttl, obj.age y obj.last_hit son relativos al momento de envío de la prohibición, de modo que representan un punto fijo en el tiempo a pesar de especificarse como una duración.

•
<operator>:
•
para todos los campos:
  • ==: <field> y <arg> son iguales
  • !=: <field> y <arg> son desiguales

las cadenas se comparan según mayúsculas y minúsculas.

•
para campos de cadena:
  • ~: <field> coincide con la expresión regular <arg>
  • !~: <field> no coincide con la expresión regular <arg>
•
para campos de duración:
  • >: <field> es mayor que <arg>
  • >=: <field> es mayor o igual que <arg>
  • <: <field> es menor que <arg>
  • <=: <field> es menor o igual que <arg>
•
<arg>:
  • para str vmod_std(3) — Arch Linux

    NAME

    vmod_std - Standard Varnish Module (VMOD)

    SYNOPSIS

    std

    DESCRIPTION

    This is a collection of very basic functions that are useful in VCL.

    The module has a number of fields that can be inspected and manipulated. Some of them are of type STRING, some are of type DURATION, and some are of type NUMERIC.

    Numeric fields

    obj.age
    Age of the object in seconds. May be zero for objects that are not in the Varnish cache.
    obj.hits
    Number of times the object has been hit.
    obj.lastuse
    Number of seconds since the object was last used.
    obj.store_len
    The size of the object in bytes. May be zero for objects that are not in the Varnish cache.
    obj.ttl
    Time to live of the object in seconds. May be zero for objects that are not in the Varnish cache.
    req.age
    The age of the object that is being served by the request. This field is only available when the object is already in the cache.
    req.esi_level
    The nesting level of ESI tags.
    req.http
    Returns the HTTP request.
    req.obj
    Returns the HTTP object.

    String fields

    obj.contenttype
    The content type of the object.
    obj.proto
    The protocol of the object (e.g. HTTP/1.1).
    obj.status
    The status code of the object.
    req.method
    The HTTP method of the request.
    req.url
    The URL of the request.

    Duration fields

    obj.last_hit
    The time of the last hit.

    Expression syntax

    All fields may be compared using the following operators:

    • == : equal
    • != : not equal
    • < : less than
    • > : greater than
    • <= : less than or equal
    • >= : greater than or equal
    • ~ : regex match
    • !~ : regex mismatch

    When comparing string fields, the right hand side of the expression is either a literal string or a regular expression.

    When comparing duration fields, the right hand side of the expression is a VCL duration.

    Expressions can be chained using the and operator &&. For or semantics, use several bans.

    The unset <field> is not equal to any string, such that, for a non-existing header, the operators == and ~ always evaluate as false, while the operators != and !~ always evaluate as true, respectively, for any value of <arg>.

    obj.last_hit can be used almost as a "last accessed" time, so, for example, ban obj.last_hit > 1d removes all objects which were last accessed more than one day ago. Also, it can be used to remove objects stuck at request bans by issuing ban obj.last_hit > X, with X being slightly less than the time since the request ban.

    obj.last_hit is based on an internal last LRU time, which might not be implemented by all storage engines. Where it is not available, ban expressions using obj.last_hit evaluate to false, which means that the respective ban behaves as if it was not present. Where implemented, the last LRU time might only get updated by the lru_interval parameter, which therefore is the maximum precision of obj.last_hit bans.

    STRING ban_error()

    Returns a textual error description of the last std.ban() call from the same task or the empty string if there either was no error or no std.ban() call.

    TIME now()

    Returns the current time. In contrast to the now built-in variable, every call returns a new value.

    DURATION timed_call(SUB)

    Call the given SUB and return a high precision measurement of the execution time.
