VIRT-INSTALL(1) Soporte de Virtualización VIRT-INSTALL(1)

NOMBRE

virt-install - aprovisionar nuevas máquinas virtuales

SINOPSIS

virt-install [OPCIÓN]...

DESCRIPCIÓN

virt-install es una herramienta de línea de comandos para crear nuevos huéspedes KVM, Xen o contenedores Linux usando la biblioteca de gestión de hipervisores libvirt. Consulte la sección de EJEMPLOS al final de este documento para empezar rápidamente.

La herramienta virt-install soporta instalaciones gráficas usando (por ejemplo) VNC o SPICE, así como instalaciones en modo texto a través de consola serial. El huésped puede ser configurado para usar uno o más discos virtuales, interfaces de red, dispositivos de audio, dispositivos USB o PCI físicos, entre otros.

El medio de instalación puede ser un medio local ISO o CDROM, o un árbol de instalación de distribución alojado remotamente sobre HTTP, FTP, o en un directorio local. En el caso del árbol de instalación, virt-install obtendrá los archivos mínimos necesarios para iniciar el proceso de instalación, permitiendo al huésped obtener el resto de la distribución del sistema operativo según sea necesario. También se soportan el arranque PXE y la importación de una imagen de disco existente (saltando así la fase de instalación).

Dadas las opciones de línea de comandos adecuadas, virt-install es capaz de ejecutarse completamente sin supervisión, con el huésped haciendo el 'kickstart' de sí mismo. Esto permite la automatización sencilla de las instalaciones de huéspedes. Esto se puede hacer manualmente, o más fácilmente con la opción --unattended.

Muchas opciones tienen sub-opciones, especificadas como opt1=foo,opt2=bar, etc. Pruebe --opción=? para ver una lista completa de sub-opciones asociadas con esa opción, ejemplo: virt-install --disk=?

La mayoría de las opciones no son requeridas. Si se especifica o detecta un valor adecuado para --osinfo, todos los valores predeterminados se completarán y se informarán en la salida de la terminal. De lo contrario, las opciones mínimas requeridas son --memory, el almacenamiento del huésped (--disk o --filesystem), y una elección del método de instalación.

CONECTANDO A LIBVIRT

--connect

Sintaxis: --connect URI

Conéctese a un hipervisor no predeterminado. Si esto no se especifica, libvirt intentará elegir el predeterminado más adecuado.

Algunas opciones válidas aquí son:

qemu:///system
Para crear huéspedes KVM y QEMU que serán ejecutados por la instancia libvirtd del sistema. Este es el modo predeterminado que utiliza virt-manager, y lo que la mayoría de los usuarios de KVM desean.
qemu:///session
Para crear huéspedes KVM y QEMU para libvirtd ejecutándose como usuario regular.
xen:///
Para conectarse a Xen.
lxc:///
Para crear contenedores linux

OPCIONES GENERALES

Parámetros de configuración generales que se aplican a todos los tipos de instalaciones de huéspedes.

-n, --name

Sintaxis: -n, --name NOMBRE

Nombre de la nueva instancia de máquina virtual huésped. Debe ser único entre todos los huéspedes conocidos por el hipervisor en la conexión, incluidos los que no están actualmente activos. Para redefinir un huésped existente, use la herramienta virsh(1) para apagarlo ('virsh shutdown') y eliminarlo ('virsh undefine') antes de ejecutar virt-install.

--memory

Sintaxis: --memory OPCIONES

Memoria a asignar para el huésped, en MiB. Esto reemplaza la opción -r/--ram. Hay sub-opciones disponibles, como 'memory', 'currentMemory', 'maxMemory' y 'maxMemory.slots', que se mapean a los valores XML con el mismo nombre.

Los valores de compatibilidad retroactiva 'memory' se mapean al elemento <currentMemory>, y maxmemory se mapea al elemento <memory>.

Para configurar módulos de memoria que se pueden desconectar en caliente, consulte la descripción de --memdev.

Use --memory=? para ver una lista de todas las sub-opciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#memory-allocation

--memorybacking

Sintaxis: --memorybacking OPCIONES

Esta opción influirá en cómo las páginas de memoria virtual se respaldan con páginas del host.

Use --memorybacking=? para ver una lista de todas las sub-opciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#memory-backing

--arch

Sintaxis: --arch ARCH

Solicita una arquitectura de CPU no nativa para la máquina virtual huésped. Si se omite, se utilizará la arquitectura de la CPU del host en el huésped.

--machine

Sintaxis: --machine MÁQUINA

El tipo de máquina a emular. Normalmente no es necesario especificar esto para Xen o KVM, pero es útil para elegir tipos de máquina de arquitecturas más exóticas.

--metadata

Sintaxis: --metadata OPT=VAL,[...]

Especifica valores de metadatos para el huésped. Las opciones posibles incluyen nombre, uuid, título y descripción. Esta opción reemplaza -u/--uuid y --description.

Use --metadata=? para ver una lista de todas las sub-opciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#general-metadata

--events

Sintaxis: --events OPT=VAL,[...]

Especifica valores de eventos para el huésped. Las opciones posibles incluyen on_poweroff, on_reboot y on_crash.

Use --events=? para ver una lista de todas las sub-opciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#events-configuration

--resource

Sintaxis: --resource OPT=VAL,[...]

Especifica la partición de recursos para el huésped.

Use --resource=? para ver una lista de todas las sub-opciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#resource-partitioning

--sysinfo

Sintaxis: --sysinfo OPT=VAL,[...]

Configura los valores sysinfo/SMBIOS expuestos al SO de la VM. Ejemplos:

--sysinfo host
Tipo especial que expone la información SMBIOS del host en la VM.
--sysinfo emulate
Tipo especial donde el hipervisor generará información SMBIOS en la VM.
--sysinfo bios.vendor=custom o --sysinfo smbios,bios.vendor=custom
El tipo predeterminado es smbios y permite a los usuarios especificar la información SMBIOS manualmente.

Use --sysinfo=? para ver una lista de todas las sub-opciones disponibles.

Detalles completos en
https://libvirt.org/formatdomain.html#operating-system-booting y
https://libvirt.org/formatdomain.html#smbios-system-information para el elemento XML smbios.

--xml

Sintaxis: --xml ARGS

Realiza ediciones directas en el XML generado usando la sintaxis XPath. Tome un ejemplo como

virt-install --xml ./@foo=bar --xml ./newelement/subelement=1

Esto alterará el XML generado para contener:

<domain foo='bar' ...>
  ...
  <newelement>
    <subelement>1</subelement>
  </newelement>
</domain>

La opción --xml tiene 4 sub-opciones:

--xml xpath.set=XP
Establece el valor de un nodo existente en la ruta XPath dada.
--xml xpath.new=XPVAL
Crea un nuevo nodo en la ruta XPath dada y le asigna el valor VAL.
--xml xpath.add=XP
Añade un nodo en la ruta XPath dada. Si la ruta ya existe, será clonada.
--xml xpath.remove=XP
Elimina el nodo en la ruta XPath dada.

INSTALACIÓN DEL SISTEMA OPERATIVO

--cdrom

Sintaxis: --cdrom DEVICE

Para utilizar un CDROM o DVDROM local como medio de instalación. La DEVICE es la ruta al dispositivo de CDROM (por ejemplo, /dev/cdrom). Esto también se puede especificar con --location.

--location

Sintaxis: --location LOCATION

Especifica la ubicación del medio de instalación. Puede ser un directorio local (por ejemplo, /var/lib/libvirt/images/install), un archivo ISO (por ejemplo, /path/to/install.iso), o un URL de red (por ejemplo, http://mirror.example.com/distro/latest/). Esta opción también puede ser utilizada para especificar la ubicación de un CDROM.

Si la ubicación es un árbol de instalación de red (HTTP/FTP), virt-install intentará hacer un arranque mínimo y dejar que el huésped descargue el resto. Si la ubicación es un archivo ISO o un CDROM, será utilizado como la fuente principal de medios de instalación.

--osinfo

Sintaxis: --osinfo OSINFO

Proporciona información sobre el sistema operativo huésped que se está instalando. Esto ayuda a virt-install a configurar el huésped de forma óptima. Las cadenas de OSINFO válidas se pueden encontrar ejecutando osinfo-query os.

Por ejemplo, para instalar Ubuntu 20.04 LTS, usaría:

--osinfo ubuntu20.04

Si esta opción no se especifica, virt-install intentará detectar el sistema operativo basándose en la información del medio de instalación.

--kernel

Sintaxis: --kernel KERNEL

Especifica la ruta al archivo del kernel a utilizar para el arranque de la instalación. Esto es útil para instalaciones personalizadas o para arrancar desde un kernel local.

--initrd

Sintaxis: --initrd INITRD

Especifica la ruta al archivo initrd a utilizar para el arranque de la instalación. Esto se usa junto con la opción --kernel.

--append

Sintaxis: --append APPEND

Especifica los parámetros adicionales de la línea de comandos del kernel para el arranque de la instalación. Esto es útil para pasar opciones específicas al kernel durante el proceso de instalación.

--pxe

Sintaxis: --pxe

Habilita el arranque PXE para la instalación. Esto requiere que el huésped esté configurado para arrancar desde la red y que un servidor TFTP esté disponible para proporcionar el archivo de arranque.

--virt-type

Sintaxis: --virt-type TYPE

Especifica el tipo de virtualización a utilizar. Los valores comunes son 'kvm', 'xen', y 'lxc'. Si se omite, virt-install intentará detectar el tipo de virtualización adecuado.

--graphics

Sintaxis: --graphics OPTIONS

Configura las opciones gráficas para el huésped. Las sub-opciones incluyen 'type' (por ejemplo, vnc, spice, none), 'port', 'listen', etc. Por defecto, se utiliza VNC.

Ejemplo para usar SPICE:

--graphics spice,listen=0.0.0.0

--console

Sintaxis: --console OPTIONS

Configura la consola serial para el huésped. Las sub-opciones incluyen 'type' (por ejemplo, pty, serial, tcp), 'port', 'path', etc. Esto es útil para instalaciones en modo texto o para acceder a la consola del huésped después de la instalación.

Ejemplo para una consola pty:

--console pty,target_type=serial

--noautoconsole

Sintaxis: --noautoconsole

Evita que virt-install intente conectarse automáticamente a la consola del huésped después de la instalación. Esto es útil si desea iniciar la instalación y luego conectarse manualmente más tarde.

--wait

Sintaxis: --wait SECONDS

Espera hasta SECONDS para que el huésped se inicie y esté listo para la instalación. Si el huésped no está listo dentro de este tiempo, virt-install saldrá con un error.

--unattended

Sintaxis: --unattended OPTIONS

Habilita la instalación sin supervisión. Esto requiere proporcionar un archivo de respuesta de instalación (kickstart para Fedora/RHEL, preseed para Debian/Ubuntu, etc.) y configuraciones de red.

Las sub-opciones incluyen 'url' para la ubicación del archivo de respuesta, y 'dsource' para la ubicación de los medios de instalación.

Ejemplo:

--unattended url=http://example.com/my-ks.cfg,dsource=/path/to/iso

--os-variant

Sintaxis: --os-variant VARIANT

Especifica una variante del sistema operativo. Esto proporciona una optimización adicional sobre la opción --osinfo. Las variantes válidas se pueden encontrar ejecutando osinfo-query osvariants.

--network

Sintaxis: --network OPTIONS

Configura la interfaz de red del huésped. Las sub-opciones incluyen 'model' (por ejemplo, virtio, e1000), 'source_type' (por ejemplo, network, bridge), 'source' (el nombre de la red o puente), etc.

Ejemplo para una interfaz virtio conectada a la red 'default':

--network network=default,model=virtio

Ejemplo para una interfaz conectada a un puente 'br0':

--network bridge=br0,model=virtio

Ejemplo para una interfaz NAT:

--network network,model=virtio

--disk

Sintaxis: --disk OPTIONS

Configura un dispositivo de almacenamiento para el huésped. Las sub-opciones incluyen 'size' (en GiB), 'format' (por ejemplo, qcow2, raw), 'sparse' (para habilitar/deshabilitar el aprovisionamiento ligero), 'backing_store', etc.

Ejemplo para un disco de 10 GiB en formato qcow2:

--disk size=10,format=qcow2

Ejemplo para usar una imagen de disco existente como base:

--disk size=0,backing_store=/path/to/base.qcow2

Use --disk=? para ver una lista de todas las sub-opciones disponibles.

--filesystem

Sintaxis: --filesystem OPTIONS

Monta un directorio del host en el huésped como un sistema de archivos. Útil para compartir datos entre el host y el huésped.

Ejemplo para montar el directorio local /srv/data en el huésped como /data:

--filesystem host=/srv/data,target=/data

--import

Sintaxis: --import

Indica que se debe importar una imagen de disco existente en lugar de realizar una instalación desde cero. Esto requiere que se proporcione un dispositivo de almacenamiento (por ejemplo, --disk size=0,path=/path/to/image.qcow2) que contenga el sistema operativo.

--resize

Sintaxis: --resize OPTIONS

Permite redimensionar un disco de máquina virtual existente. Las sub-opciones incluyen 'disk' (el nombre del disco) y 'size' (el nuevo tamaño en GiB).

Ejemplo para redimensionar el disco 'sda' a 20 GiB:

--resize disk=sda,size=20

--graphics

Sintaxis: --graphics OPTIONS

Configura las opciones gráficas para el huésped. Las sub-opciones incluyen 'type' (por ejemplo, vnc, spice, none), 'port', 'listen', etc. Por defecto, se utiliza VNC.

Ejemplo para usar SPICE:

--graphics spice,listen=0.0.0.0

--sound

Sintaxis: --sound OPTIONS

Agrega un dispositivo de sonido al huésped. Las sub-opciones incluyen 'model' (por ejemplo, ich6, ac97).

Ejemplo:

--sound ich6

--autostart

Sintaxis: --autostart

Configura la máquina virtual para que se inicie automáticamente cuando el servicio libvirtd comience.

--import

Sintaxis: --import

Indica que se debe importar una imagen de disco existente en lugar de realizar una instalación desde cero. Esto requiere que se proporcione un dispositivo de almacenamiento (por ejemplo, --disk size=0,path=/path/to/image.qcow2) que contenga el sistema operativo.

--boot

Sintaxis: --boot OPTIONS

Configura las opciones de arranque para el huésped. Las sub-opciones incluyen 'menu', 'order' (por ejemplo, hd, cdrom, network), 'boot.menu.enable' etc.

Ejemplo para arrancar primero desde el disco duro:

--boot order=hd

Use --boot=? para ver una lista de todas las sub-opciones disponibles.

--host-device

Sintaxis: --host-device BUS=VALUE,TYPE=VALUE,
ADDR=VALUE

Permite adjuntar dispositivos PCI o USB del host a la máquina virtual.

Ejemplo para adjuntar un dispositivo PCI:

--host-device pci,host=00:03.0

Ejemplo para adjuntar un dispositivo USB:

--host-device usb,hostbus=1,hostaddr=2

Use --host-device=? para ver una lista de todas las sub-opciones disponibles.

--video

Sintaxis: --video OPTIONS

Configura el dispositivo de video virtual. Las sub-opciones incluyen 'model' (por ejemplo, vga, qxl, vmware).

Ejemplo:

--video qxl

--input

Sintaxis: --input OPTIONS

Configura un dispositivo de entrada virtual. Las sub-opciones incluyen 'type' (por ejemplo, mouse, tablet) y 'bus' (por ejemplo, ps2, usb).

Ejemplo para una tableta Wacom USB:

--input tablet,bus=usb

--memdev

Sintaxis: --memdev OPTIONS

Configura un dispositivo de memoria de acceso aleatorio (RAM) que se puede asignar y desasignar dinámicamente. Las sub-opciones incluyen 'page_size', 'unit' y 'size'.

Ejemplo para asignar 1GiB de RAM en páginas de 2MiB:

--memdev page_size=2048,unit=MiB,size=1024

EJEMPLOS

Para crear una máquina virtual KVM básica con 1GiB de RAM, un disco de 10GiB y arrancar desde una ISO:

virt-install --name MyGuest \
  --ram 1024 \
  --disk size=10 \
  --location /path/to/install.iso \
  --osinfo fedora34

Para crear una máquina virtual KVM con instalación sin supervisión usando un archivo kickstart:

virt-install --name AutoGuest \
  --ram 2048 \
  --disk size=20,format=qcow2 \
  --location http://example.com/centos-stream-8-x86_64-dvd1.iso \
  --osinfo centos8stream \
  --unattended url=http://example.com/ks.cfg

Para importar una imagen de disco existente y arrancarla:

virt-install --name ImportedGuest \
  --disk path=/path/to/existing_image.qcow2,size=0 \
  --import \
  --osinfo ubuntu20.04

Para crear una máquina virtual con SPICE como gráficos y una red bridge:

virt-install --name SpiceVM \
  --ram 1024 \
  --disk size=10 \
  --location /path/to/install.iso \
  --graphics spice,listen=0.0.0.0 \
  --network bridge=br0

El comportamiento predeterminado si no se establece ninguna subopción explícita. Toma la forma XPATH=VALOR a menos que se combine con xpath.value . Vea abajo cómo se interpreta el valor.
--xml xpath.value=VALOR
xpath.set se interpretará solo como la cadena XPath, y xpath.value se usará como el valor a establecer. Puede ayudar a evitar problemas si la cadena que necesita establecer contiene un signo '=' igual.

Si el valor está vacío, se trata como si se anulara la configuración de ese nodo en particular.

--xml xpath.create=XPATH
Cree el nodo como un elemento vacío. Necesario para elementos booleanos como <readonly/>
--xml xpath.delete=XPATH
Elimine el nodo completo especificado por el xpath, y todos sus hijos

Subargumentos de xpath

Similar a la opción --xml, la mayoría de las opciones de nivel superior tienen subopciones xpath.*. Por ejemplo, --disk xpath1.set=./@foo=bar,xpath2.create=./newelement generaría alteraciones XML como

<disk foo="bar">
  <newelements/>
</disk>

Esto es útil para establecer opciones XML por dispositivo, cuando virt-install aún no soporta esas opciones.

--qemu-commandline

Sintaxis: --qemu-commandline ARGS

Pase las opciones directamente al emulador qemu. Solo funciona para el controlador qemu de libvirt. La opción puede tomar una cadena de argumentos, por ejemplo:

--qemu-commandline="-display gtk,gl=on"

Las variables de entorno se especifican con 'env', por ejemplo:

--qemu-commandline=env=DISPLAY=:0.1

Detalles completos sobre la función de libvirt:
https://libvirt.org/drvqemu.html#pass-through-of-arbitrary-qemu-commands

--vcpus

Sintaxis: --vcpus OPCIONES

Número de cpus virtuales a configurar para el invitado. Si se especifica 'maxvcpus', el invitado podrá agregar dinámicamente hasta MAX vcpus mientras se ejecuta, pero se iniciará con VCPUS.

La topología de la CPU se puede especificar además con sockets, dies, cores e hilos. Si se omiten los valores, el resto se autocompletará prefiriendo cores sobre sockets sobre hilos. Se prefieren los cores porque esto coincide con las características del silicio del mundo real moderno y, por lo tanto, se adapta mejor a lo que el sistema operativo invitado esperará.

'cpuset' establece en qué cpus físicos puede operar el invitado. CPUSET es una lista separada por comas de números, que también se pueden especificar en rangos o cpus a excluir. Ejemplo:

0,2,3,5     : Usar procesadores 0,2,3 y 5
1-5,^3,8    : Usar procesadores 1,2,4,5 y 8

Si se pasa el valor 'auto', virt-install intenta determinar automáticamente un anclaje de cpu óptimo usando datos NUMA, si están disponibles.

Use --vcpus=? para ver una lista de todas las subopciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#cpu-allocation

--numatune

Sintaxis: --numatune OPCIONES

Ajustar la política NUMA para el proceso del dominio. Ejemplos de invocación

--numatune 1,2,3,4-7
--numatune 1-3,5,memory.mode=preferred

Especifica los nodos numa de los que se asignará la memoria. Esto tiene la misma sintaxis que la opción --vcpus cpuset=. El modo puede ser uno de 'interleave', 'preferred' o 'strict' (el predeterminado). Vea 'man 8 numactl' para obtener información sobre cada modo.

Use --numatune=? para ver una lista de todas las subopciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#numa-node-tuning

--memtune

Sintaxis: --memtune OPCIONES

Ajustar la política de memoria para el proceso del dominio. Ejemplos de invocación

--memtune 1000
--memtune hard_limit=100,soft_limit=60,swap_hard_limit=150,min_guarantee=80

Use --memtune=? para ver una lista de todas las subopciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#memory-tuning

--blkiotune

Sintaxis: --blkiotune OPCIONES

Ajustar la política blkio para el proceso del dominio. Ejemplos de invocación

--blkiotune 100
--blkiotune weight=100,device.path=/dev/sdc,device.weight=200

Use --blkiotune=? para ver una lista de todas las subopciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#block-i-o-tuning

--cpu

Sintaxis: --cpu MODELO[,+característica][,-característica][,match=COINCIDENCIA][,vendor=PROVEEDOR],...

Configurar el modelo de CPU y las características de CPU expuestas al invitado. El único valor requerido es MODELO, que es un modelo de CPU válido conocido por libvirt.

Los valores de política de características de libvirt son forzar, requerir, opcional, deshabilitar, o prohibir, o con la abreviatura '+característica' y '-característica', que equivalen a 'forzar=característica' y 'deshabilitar=característica' respectivamente.

Si se especifica el modelo exacto de CPU, virt-install copiará automáticamente las características de CPU disponibles en el host para mitigar las recientes vulnerabilidades de seguridad de ejecución especulativa de CPU y datos del búfer de almacenamiento microarquitectónico. Esto, sin embargo, tendrá algún impacto en el rendimiento y romperá la migración a hosts sin parches de seguridad. Para controlar este comportamiento, existe un parámetro seguro. Los valores posibles son on (activado) y off (desactivado), siendo on el predeterminado. Se recomienda encarecidamente dejar esto habilitado y asegurarse de que todos los hosts de virtualización tengan el microcódigo, kernel y software de virtualización completamente actualizados.

Algunos ejemplos:

--cpu core2duo,+x2apic,disable=vmx
Exponer el modelo de CPU core2duo, forzar la habilitación de x2apic, pero no exponer vmx
--cpu host-model
Exponer la configuración de CPU del host al invitado. Esto permite al invitado aprovechar muchas de las características de la CPU del host (mejor rendimiento), pero puede causar problemas si se migra el invitado a un host sin una CPU idéntica.
--cpu numa.cell0.memory=1234,numa.cell0.cpus=0-3,numa.cell1.memory=5678,numa.cell1.cpus=4-7
Ejemplo de especificación de dos celdas NUMA. Esto generará XML como:
<cpu>
  <numa>
    <cell cpus="0-3" memory="1234"/>
    <cell cpus="4-7" memory="5678"/>
  </numa>
</cpu>
--cpu host-passthrough,cache.mode=passthrough
Ejemplo de pasar la información de caché de la CPU del host.
--cpu maximum
Exponer la CPU más rica en características posible. Útil cuando se ejecuta un invitado de arquitectura extranjera, por ejemplo, un invitado riscv64 en un host x86_64. No recomendado cuando se usa KVM para ejecutar un invitado de la misma arquitectura.

Use --cpu=? para ver una lista de todas las subopciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#cpu-model-and-topology

--cputune

Sintaxis: --cputune OPCIONES

Ajustar los parámetros de CPU para el invitado.

Configurar a qué CPUs físicas del host se anclarán los VCPU del dominio. Ejemplo de invocación

--cputune vcpupin0.vcpu=0,vcpupin0.cpuset=0-3,vcpupin1.vcpu=1,vcpupin1.cpuset=4-7

Use --cputune=? para ver una lista de todas las subopciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#cpu-tuning

--security, --seclabel

Sintaxis: --security, --seclabel type=TIPO[,label=ETIQUETA][,relabel=sí|no],...

--install OPTS

bootdev=
Especifica el dispositivo de arranque de instalación (hd, cdrom, floppy, network) desde el cual arrancar para la fase de instalación. Esto se mapea a XML de libvirt <os><boot dev=X>.

Si quieres instalar desde un cdrom o red, probablemente sea más sencillo y compatible con versiones anteriores usar simplemente --cdrom o --pxe, pero esta opción ofrece un control detallado sobre el proceso de instalación si es necesario.

no_install=yes|no
Indica a virt-install que en realidad no hay ninguna instalación en curso y que solo quieres crear la VM. --import es solo un alias para esto, al igual que especificar --boot sin ninguna otra opción de instalación. La opción obsoleta --live es lo mismo que '--cdrom $ISO --install no_install=yes'

--reinstall DOMAIN

Reinstala una VM existente. DOMAIN puede ser un nombre de VM, UUID o número de ID. virt-install obtendrá el XML del dominio de libvirt, aplicará los cambios de configuración de instalación especificados, arrancará la VM para el proceso de instalación y luego revertirá a un XML de inicio aproximadamente igual.

Solo se procesan las opciones relacionadas con la instalación, todas las demás opciones de configuración de VM como --name, --disk, etc., se ignoran por completo.

Si se utiliza --reinstall con --cdrom, se usará un CDROM existente adjunto a la VM si hay uno disponible, de lo contrario se agregará un dispositivo CDROM permanente.

--unattended

Sintaxis: --unattended [OPCIONES]

Realiza una instalación desatendida utilizando el soporte de scripts de instalación de libosinfo. Esta es esencialmente una base de datos de scripts de instalación automática para varias distribuciones: scripts de Red Hat kickstarts, scripts del instalador de Debian, instalaciones desatendidas de Windows y potencialmente otros. La invocación más sencilla es combinarla con --install como:

--install fedora29 --unattended

Una instalación de Windows se verá así

--cdrom /path/to/my/windows.iso --unattended

Las subopciones son:

profile=
Elige qué perfil desatendido de libosinfo usar. La mayoría de las distribuciones tienen un perfil 'desktop' y un perfil 'jeos'. virt-install utilizará 'desktop' por defecto si no se especifica.
admin-password-file=
Un archivo utilizado para establecer la contraseña de administrador/root del SO de la VM. Esta opción se puede usar como "admin-password-file=/path/to/password-file" o como "admin-password-file=/dev/fd/n", siendo n el descriptor de archivo del archivo de contraseña. Tenga en cuenta que solo se considerará la primera línea del archivo, incluidos los caracteres de espacio en blanco y excluyendo el salto de línea.
user-login=
El nombre de usuario a utilizar en la VM. virt-install utilizará tu nombre de usuario de host actual si no se especifica. Tenga en cuenta que al ejecutar virt-install como "root", esta opción debe especificarse.
user-password-file=
Un archivo utilizado para establecer la contraseña del usuario de la VM. Esta opción se puede usar como "user-password-file=/path/to/password-file" o como "user-password-file=/dev/fd/n", siendo n el descriptor de archivo del archivo de contraseña. El nombre de usuario es el especificado en user-login o tu nombre de usuario de host actual. Tenga en cuenta que solo se considerará la primera línea del archivo, incluidos los caracteres de espacio en blanco y excluyendo el salto de línea.
product-key=
Establece una clave de producto de Windows

--cloud-init

Pasa metadatos de cloud-init a la VM. Se genera un archivo ISO NoCloud de cloud-init y se adjunta a la VM como un dispositivo CDROM. El dispositivo solo se adjunta para el primer arranque. Esta opción es particularmente útil para imágenes en la nube de distribuciones, que tienen cuentas de inicio de sesión bloqueadas por defecto; --cloud-init proporciona los medios para inicializar esas cuentas de inicio de sesión, como establecer una contraseña de root.

La invocación más sencilla es simplemente --cloud-init sin subopciones; esto se mapea a --cloud-init root-password-generate=on,disable=on. Consulte esas subopciones para obtener una explicación de cómo funcionan.

Utilice --cloud-init=? para ver una lista de todas las subopciones disponibles.

Las subopciones son:

root-password-generate=on
Genera una nueva contraseña de root para la VM. Cuando se utiliza, virt-install imprimirá la contraseña generada en la consola y hará una pausa durante 10 segundos para dar al usuario la oportunidad de notarla y copiarla.
disable=on
Desactiva cloud-init en la VM para arranques posteriores. Sin esto, cloud-init puede restablecer la autenticación en cada arranque.
root-password-file=
Un archivo utilizado para establecer la contraseña de root de la VM. Esta opción se puede usar como "root-password-file=/path/to/password-file" o como "root-password-file=/dev/fd/n", siendo n el descriptor de archivo del archivo de contraseña. Tenga en cuenta que solo se considerará la primera línea del archivo, incluidos los caracteres de espacio en blanco y excluyendo el salto de línea.
meta-data=
Especifica un archivo de metadatos de cloud-init para añadir directamente al iso. Se ignorarán todas las demás opciones de configuración de metadatos en la línea de comandos --cloud-init. Puede ser la ruta a un archivo local o una URL.
user-data=
Especifica un archivo de datos de usuario de cloud-init para añadir directamente al iso. Se ignorarán todas las demás opciones de configuración de datos de usuario en la línea de comandos --cloud-init. Puede ser la ruta a un archivo local o una URL.
root-ssh-key=
Especifica una clave pública para inyectar en el huésped, proporcionando acceso ssh a la cuenta de root. Ejemplo: root-ssh-key=/home/user/.ssh/id_rsa.pub
clouduser-ssh-key
Especifica una clave pública para inyectar en el huésped, proporcionando acceso ssh a la cuenta de usuario predeterminada de cloud-init. El nombre de la cuenta es diferente para cada imagen de nube de distribución. Algunas comunes se documentan aquí:
https://docs.openstack.org/image-guide/obtain-images.html
network-config=
Especifica un archivo de configuración de red de cloud-init para añadir directamente al iso. Puede ser la ruta a un archivo local o una URL.

--boot

Sintaxis: --boot BOOTOPTS

Opcionalmente, especifica la configuración de arranque de la VM después de la instalación. Esta opción permite especificar el orden de los dispositivos de arranque, arrancar permanentemente desde kernel/initrd con argumentos de kernel opcionales y habilitar un menú de arranque de BIOS (requiere libvirt 0.8.3 o posterior).

--boot se puede especificar además de otras opciones de instalación (como --location, --cdrom, etc.) o se puede especificar por sí solo. En este último caso, el comportamiento es similar a la opción de instalación --import: no hay fase de 'instalación', la VM simplemente se crea y se lanza según lo especificado.

Algunos ejemplos:

--boot cdrom,fd,hd,network
Establece la prioridad del dispositivo de arranque como primer cdrom, primer floppy, primer disco duro, arranque PXE de red. Nota: las VM s390x solo admiten un dispositivo de arranque, por lo que todo excepto el primer tipo de dispositivo se ignorará.
--boot kernel=KERNEL,initrd=INITRD,kernel_args="console=/dev/ttyS0"
Hace que la VM arranque permanentemente desde un par de kernel/initrd local, con las opciones de kernel especificadas.
--boot kernel=KERNEL,initrd=INITRD,dtb=DTB
Hace que la VM arranque permanentemente desde un par de kernel/initrd local con un binario de árbol de dispositivos externo. DTB puede ser necesario para algunas configuraciones no x86 como ARM o PPC.
--boot loader=BIOSPATH
Utiliza BIOSPATH como la BIOS de la máquina virtual.
--boot bootmenu.enable=on,bios.useserial=on
Habilita el menú de arranque de la BIOS y habilita el envío de salida de texto de la BIOS a través de la consola serial.
--boot init=INITPATH
Ruta a un binario que la VM contenedora iniciará. Si se ha especificado un --filesystem root, virt-install utilizará /sbin/init por defecto, de lo contrario, utilizará /bin/sh.
--boot uefi, --boot uefi=on
Configura la VM para arrancar desde UEFI. Para que virt-install conozca los parámetros UEFI correctos, libvirt debe anunciar binarios UEFI conocidos a través del XML domcapabilities, por lo que esto probablemente solo funcionará si se utilizan paquetes de distribución configurados correctamente. Esta es la configuración UEFI recomendada.
--boot uefi=off
No utilice UEFI si la VM lo utilizaría por defecto.
--boot uefi,firmware.feature0.name=secure-boot,firmware.feature0.enabled=yes,firmware.feature1.name=enrolled-keys,firmware.feature1.enabled=yes
Configura la VM para arrancar desde UEFI con el soporte de arranque seguro habilitado. Solo los sistemas operativos firmados podrán arrancar con esta configuración.
--boot uefi,firmware.feature0.name=secure-boot,firmware.feature0.enabled=no
Configura la VM para arrancar desde UEFI con el soporte de arranque seguro deshabilitado. Esta configuración permite que se ejecuten tanto sistemas operativos firmados como no firmados.

Información adicional sobre las características de firmware secure-boot y enrolled-keys y cómo se pueden utilizar para influir en la selección del firmware está disponible en
https://libvirt.org/kbase/secureboot.html

--boot loader=/.../OVMF_CODE.fd,loader.readonly=yes,loader.type=pflash,nvram.template=/.../OVMF_VARS.fd,loader_secure=no
Especifica que la máquina virtual utilice el binario OVMF personalizado como firmware de arranque, mapeado como un chip flash virtual. Además, solicita
libvirt instancia el varstore UEFI específico de la VM a partir de la plantilla de varstore personalizada "/.../OVMF_VARS.fd". Esta configuración no se recomienda y solo debe usarse si --boot uefi no conoce sus binarios UEFI.

Use --boot=? para ver una lista de todas las subopciones disponibles. Detalles completos en
https://libvirt.org/formatdomain.html#operating-system-booting

--idmap

Sintaxis: --idmap OPCIONES

Si la configuración del invitado declara un mapeo UID o GID, se habilitará el espacio de nombres 'user' para aplicarlos. Un mapeo UID/GID adecuadamente configurado es un requisito previo para que los contenedores sean seguros, en ausencia de confinamiento sVirt.

--idmap se puede especificar para habilitar el espacio de nombres de usuario para contenedores LXC. Ejemplo:

--idmap uid.start=0,uid.target=1000,uid.count=10,gid.start=0,gid.target=1000,gid.count=10

Use --idmap=? para ver una lista de todas las subopciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#container-boot

OPCIONES_DEL_SO_INVITADO

--osinfo, --os-variant

Sintaxis: --osinfo [NOMBRE_SO|OPC1=VAL1,...]

Optimiza la configuración del invitado para un sistema operativo específico. Para la mayoría de los casos, se debe especificar un SO o detectarlo desde el medio de instalación para que se puedan habilitar funciones críticas para el rendimiento como virtio.

El uso más simple es --osinfo NOMBRE_SO o --os-variant NOMBRE_SO, por ejemplo --osinfo fedora32. Las subopciones admitidas son:

name=, short-id=
El nombre/ID corto del SO de libosinfo. Ejemplos: fedora32, win10
id=
El ID de libosinfo completo estilo URL. Por ejemplo, name=win10 es lo mismo que id=http://microsoft.com/win/10
detect=on|off
Si virt-install intentará la detección del SO desde el medio de instalación especificado. La detección actualmente solo se intenta para instalaciones URL y CDROM, y no es 100% confiable.
require=on|off
Si está on, virt-install fallará si no se establece o detecta ningún valor de SO.

Algunos ejemplos interesantes:

--osinfo detect=on,require=on
Esto le dice a virt-install que intente la detección desde el medio de instalación, pero que falle explícitamente si no tiene éxito. Esto asegurará que sus invocaciones de virt-install no recurran a una configuración de bajo rendimiento.
--osinfo detect=on,name=NOMBRE_SO
Intenta detectar el SO desde el medio de instalación, pero si falla, usa NOMBRE_SO como respaldo.

Si se especifica algún valor manual de --osinfo, el valor predeterminado es que todas las demás configuraciones estén apagadas o sin establecer.

Por defecto, virt-install siempre intentará --osinfo detect=on para el medio de instalación apropiado. Si no se detecta ningún SO, fallaremos en la mayoría de los casos comunes. Este error fatal se agregó en 2022. Puede solucionarlo utilizando el ejemplo de respaldo anterior o deshabilitando la opción require. Si solo necesita volver al comportamiento anterior no fatal lo antes posible, establezca la variable de entorno VIRTINSTALL_OSINFO_DISABLE_REQUIRE=1.

Use el comando virt-install --osinfo list para obtener la lista de las variantes de SO aceptadas. Consulte osinfo-query os para obtener aún más información.

Nota: --osinfo y --os-variant son alias uno para el otro. --osinfo es el nombre de estilo nuevo preferido.

OPCIONES_DE_ALMACENAMIENTO

--disk

Sintaxis: --disk OPCIONES

Especifica los medios a utilizar como almacenamiento para el invitado, con varias opciones. El formato general de una cadena de disco es

--disk opt1=val1,opt2=val2,...

La invocación más simple para crear una nueva imagen de disco de 10G y el dispositivo de disco asociado:

--disk size=10

virt-install generará un nombre de ruta y lo colocará en la ubicación de imagen predeterminada para el hipervisor. Para especificar medios, el comando puede ser:

--disk /alguna/ruta/de/almacenamiento[,opt1=val1]...

o especificar explícitamente uno de los siguientes argumentos:

path
Una ruta a algún medio de almacenamiento a utilizar, existente o no. Los medios existentes pueden ser un archivo o un dispositivo de bloque.

Especificar una ruta inexistente implica intentar crear el nuevo almacenamiento y requerirá especificar un valor 'size'. Incluso para hosts remotos, virt-install intentará usar las API de almacenamiento de libvirt para crear automáticamente la ruta dada.

Si el hipervisor lo admite, path también puede ser una URL de red, como
https://example.com/some-disk.img. Para rutas de red, el hipervisor accederá directamente al almacenamiento, no se descargará nada localmente.

pool
Un nombre de grupo de almacenamiento de libvirt existente en el que crear nuevo almacenamiento. Requiere especificar un valor 'size'.
vol
Un volumen de almacenamiento de libvirt existente a utilizar. Esto se especifica como 'nombregrupo/nombrevolumen'.

Opciones que se aplican a la creación de almacenamiento:

size
tamaño (en GiB) a utilizar al crear nuevo almacenamiento
sparse
si se debe omitir la asignación completa del almacenamiento recién creado. El valor es 'yes' o 'no'. El valor predeterminado es 'yes' (no asignar completamente) a menos que no sea compatible con el tipo de almacenamiento subyacente.

El tiempo inicial necesario para asignar completamente el disco virtual del invitado (sparse=no) generalmente se compensará con tiempos de instalación más rápidos dentro del invitado. Por lo tanto, se recomienda el uso de esta opción para garantizar un alto rendimiento constante y evitar errores de E/S en el invitado en caso de que el sistema de archivos del host se llene.

format
Formato de imagen de disco. Para volúmenes de archivo, puede ser 'raw', 'qcow2', 'vmdk', etc. Consulte los tipos de formato en https://libvirt.org/storage.html para valores posibles. Esto a menudo se mapea también al valor driver_type.

Si no se especifica al crear imágenes de archivo, el valor predeterminado será 'qcow2'.

Si crea almacenamiento, este será el formato de la nueva imagen. Si utiliza una imagen existente, esto anula la autodetención del formato de libvirt.

backing_store
Ruta a un disco para usar como almacenamiento de respaldo para la imagen recién creada.
backing_format
Formato de imagen de disco de backing_store

Algunas subopciones de configuración de dispositivo de ejemplo:

device
Tipo de dispositivo de disco. Los valores de ejemplo son 'cdrom', 'disk', 'lun' o 'floppy'. El valor predeterminado es 'disk'.
boot.order
La instalación del invitado con múltiples discos necesitará este parámetro para arrancar correctamente después de ser instalado. Un parámetro boot.order tomará valores 1,2,3,... Los dispositivos con un valor más bajo tienen mayor prioridad. Esta opción se aplica también a otros tipos de dispositivos arrancables.
target.bus** o *bus
Tipo de bus de disco. Los valores de ejemplo son 'ide', 'sata', 'scsi', 'usb', 'virtio' o 'xen'. El valor predeterminado depende del hipervisor, ya que no todos los hipervisores admiten todos los tipos de bus.
readonly
Establecer la unidad como de solo lectura (toma 'on' o 'off')
shareable
Establecer la unidad como compartible (toma 'on' o 'off')
cache
El modo de caché a utilizar. La página de caché del host proporciona memoria de caché. El valor de caché puede ser 'none', 'writethrough', 'directsync', 'unsafe' o 'writeback'. 'writethrough' proporciona caché de lectura. 'writeback' proporciona caché de lectura y escritura. 'directsync' omite la caché de páginas del host. 'unsafe' puede almacenar en caché todo el contenido e ignorar las solicitudes de vaciado del invitado.
driver.discard
Si las solicitudes de descarte (también conocidas como "trim" o "unmap") se ignoran o se pasan al sistema de archivos. El valor puede ser "unmap" (permitir que se pase la solicitud de descarte) o "ignore" (ignorar la solicitud de descarte). Desde 1.0.6 (solo QEMU y KVM)
driver.name
Nombre del controlador que el hipervisor debe usar al acceder al almacenamiento especificado. Normalmente, el usuario no necesita establecerlo.
driver.type
Formato/tipo de controlador que el hipervisor debe usar al acceder al almacenamiento especificado. Normalmente, el usuario no necesita establecerlo.
driver.io
Backend de E/S de disco. Puede ser "threads", "native" o "io_uring".
driver.error_policy
Cómo debe reaccionar el invitado si se encuentra un error de escritura. Puede ser uno de "stop", "ignore", o "enospace"
serial
El número de serie del dispositivo de disco. Esto se usa para identificar el dispositivo dentro del invitado y a menudo se usa para el mapeo de dispositivos persistentes (udev en Linux).
Número de serie del dispositivo de disco emulado. Esto se utiliza en invitados de Linux para establecer enlaces simbólicos /dev/disk/by-id. Un número de serie de ejemplo podría ser: WD-WMAP9A966149
source.startupPolicy
Define qué hacer con el disco si el archivo fuente no es accesible.
snapshot
Define el comportamiento predeterminado del disco durante las instantáneas del disco.

Consulte la sección de ejemplos para ver algunos usos. Esta opción desaprueba -f/--file, -s/--file-size, --nonsparse y --nodisks.

Use --disk=? para ver una lista de todas las subopciones disponibles. Detalles completos en
https://libvirt.org/formatdomain.html#hard-drives-floppy-disks-cdroms

--filesystem

Especifica un directorio en el host para exportar al invitado. La invocación más simple es:

--filesystem /fuente/en/host,/punto/destino/en/invitado

Lo que funcionará para QEMU reciente y sistemas operativos invitados Linux o contenedores LXC. Para QEMU, el punto de destino es solo una pista de montaje en sysfs, por lo que no se montará automáticamente.

Algunas subopciones de ejemplo:

type
El tipo o el directorio fuente. Los valores válidos son 'mount' (el predeterminado) o 'template' para plantillas OpenVZ.
accessmode o mode
El modo de acceso para el directorio fuente desde el sistema operativo invitado. Solo se usa con QEMU y type=mount. Los modos válidos son 'mapped' (el predeterminado), 'passthrough' o 'squash'. Consulte la documentación del XML del dominio de libvirt para más información.
source
El directorio en el host para compartir.
target
La ubicación de montaje a usar en el invitado.

Use --filesystem=? para ver una lista de todas las subopciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#filesystems

OPCIONES DE RED

-w, --network

Sintaxis: -w, --network OPCIONES

Conecta el invitado a la red del host. Ejemplos para especificar el tipo de red:

bridge=BRIDGE
Conectar a un dispositivo de puente en el host llamado BRIDGE. Use esta opción si el host tiene una configuración de red estática y el invitado requiere conectividad total de salida y entrada a/desde la LAN. Úselo también si se utilizará migración en vivo con este invitado.
network=NAME
Conectar a una red virtual en el host llamada NAME. Las redes virtuales se pueden listar, crear y eliminar utilizando la herramienta de línea de comandos virsh. En una instalación sin modificar de libvirt, generalmente hay una red virtual con el nombre default. Use una red virtual si el host tiene redes dinámicas (por ejemplo, NetworkManager) o utiliza conexiones inalámbricas. El invitado será NATeado a la LAN por la conexión activa.
type=direct,source=IFACE[,source.mode=MODE]
Conexión directa a la interfaz del host IFACE usando macvtap.
user
Conectar a la LAN usando SLIRP. Úselo solo si está ejecutando un invitado QEMU como usuario no privilegiado. Esto proporciona una forma muy limitada de NAT.
none
Indicar a virt-install que no agregue ninguna interfaz de red predeterminada.

Si se omite --network, se creará una NIC en el invitado. Si hay un dispositivo de puente en el host con una interfaz física adjunta, ese se utilizará para la conectividad. En caso contrario, se utilizará la red virtual llamada default. Esta opción se puede especificar varias veces para configurar más de una NIC.

Algunas subopciones de ejemplo:

model.type o model
Modelo del dispositivo de red visto por el invitado. El valor puede ser cualquier modelo de NIC compatible con el hipervisor, por ejemplo: 'e1000', 'rtl8139', 'virtio', ...
mac.address o mac
Dirección MAC fija para el invitado; Si este parámetro se omite, o se especifica el valor RANDOM, se generará una dirección adecuada aleatoriamente. Para máquinas virtuales Xen, es necesario que los 3 pares primeros de la dirección MAC sean la secuencia '00:16:3e', mientras que para máquinas virtuales QEMU o KVM debe ser '52:54:00'.
filterref.filter
Controlar el firewall y el filtrado de red en libvirt. El valor puede ser cualquier nwfilter definido por los subcomandos 'nwfilter' de virsh. Los filtros disponibles se pueden listar ejecutando 'virsh nwfilter-list', por ejemplo: 'clean-traffic', 'no-mac-spoofing', ...
virtualport.* options
Configurar el perfil del puerto virtual del dispositivo. Esto se utiliza para la configuración de 802.Qbg, 802.Qbh, midonet y openvswitch.

Use --network=? para ver una lista de todas las subopciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#network-interfaces

Esta opción desaprueba -m/--mac, -b/--bridge y --nonetworks

hostdev=HOSTDEV
Utilice el dispositivo nodedev referenciado como fuente para type=hostdev como se describe aquí: https://libvirt.org/formatdomain.html#pci-passthrough

Para el formato HOSTDEV, consulte la documentación de --hostdev

portForward=[ADDRESS:]HOSTPORT[:GUESTPORT][/PROTO]
Opción más simple para especificar el reenvío de puertos con redes --network passt. Coincide aproximadamente con la sintaxis de podman run -p. HOSTPORT puede representarse como un rango como 7000-8000, pero GUESTPORT solo puede ser un puerto único. Si no se proporciona GUESTPORT, se asume que los puertos del host y del invitado coinciden.

Ejemplos:

--network passt,portForward=8080:80 \
--network passt,portForward0=7000-8000/udp,portForward1=127.0.0.1:2222:22 \

OPCIONES GRÁFICAS

Si no se especifica ninguna opción gráfica, virt-install intentará seleccionar los gráficos apropiados si la variable de entorno DISPLAY está establecida, de lo contrario, se usará '--graphics none'.

--graphics

Sintaxis: --graphics TIPO,opt1=arg1,opt2=arg2,...

Especifica la configuración de la pantalla gráfica. Esto no configura ningún hardware virtual, solo cómo se puede acceder a la pantalla gráfica del invitado. Normalmente, el usuario no necesita especificar esta opción, virt-install intentará elegir una opción predeterminada útil y lanzar una conexión adecuada.

El formato general de una cadena gráfica es

--graphics TIPO,opt1=arg1,opt2=arg2,...

Por ejemplo:

--graphics vnc,password=foobar

Algunos valores de TIPO admitidos:

vnc
Configurar una consola virtual en el invitado y exportarla como un servidor VNC en el host. A menos que también se proporcione el parámetro port, el servidor VNC se ejecutará en el primer puerto libre a partir del 5900. La pantalla VNC real asignada se puede obtener utilizando el comando vncdisplay para virsh (o se puede usar virt-viewer(1) que maneja este detalle para el usuario).
spice
Exportar la consola del invitado utilizando el protocolo Spice. Spice permite funciones avanzadas como audio y transmisión de dispositivos USB, así como un rendimiento gráfico mejorado.

El uso del tipo de gráfico spice funcionará como si se hubieran dado estos argumentos:

--video qxl --channel spicevmc
none
No se asignará ninguna consola gráfica para el invitado. Es probable que los invitados necesiten tener una consola de texto configurada en el primer puerto serie del invitado (esto se puede hacer a través de la opción --extra-args). El comando 'virsh console NAME' se puede usar para conectarse al dispositivo serie.

Algunas subopciones admitidas:

port
Solicitar un número de puerto permanente y asignado estáticamente para la consola del invitado. Esto se utiliza para 'vnc' y 'spice'.
tlsPort
Especificar el puerto TLS de spice.
websocket
Solicitar un puerto WebSocket VNC para la consola del invitado.

Si se especifica -1, el puerto WebSocket se asignará automáticamente.

Esto se usa para 'vnc' y 'spice'.

listen
Dirección en la que escuchar las conexiones VNC/Spice. El valor predeterminado suele ser 127.0.0.1 (solo localhost), pero algunos hipervisores permiten cambiar esto globalmente (por ejemplo, el valor predeterminado del controlador qemu se puede cambiar en /etc/libvirt/qemu.conf). Use 0.0.0.0 para permitir el acceso desde otras máquinas.

Use 'none' para especificar que el servidor de pantalla no debe escuchar en ningún puerto. El servidor de pantalla solo se puede acceder localmente a través del socket Unix de libvirt (virt-viewer con --attach, por ejemplo).

Si se omite esta opción, se usará el valor predeterminado.

Utilice 'socket' para que la VM escuche en una ruta de socket unix generada por libvirt en el sistema de archivos del host.

Esto es utilizado por 'vnc' y 'spice'

password
Solicita una contraseña de consola, requerida en el momento de la conexión. Tenga cuidado, esta información puede terminar en los archivos de registro de virt-install, así que no use una contraseña importante. Esto es utilizado por 'vnc' y 'spice'.
gl.enable
Indica si se debe utilizar la renderización acelerada por OpenGL. El valor es 'yes' o 'no'. Esto es utilizado por 'spice'.
gl.rendernode
Ruta del nodo de renderizado DRM a utilizar. Esto se utiliza cuando 'gl' está habilitado.

Utilice --graphics=? para ver una lista de todas las subopciones disponibles. Detalles completos en https://libvirt.org/formatdomain.html#graphical-framebuffers

Esto reemplaza las siguientes opciones: --vnc, --vncport, --vnclisten, -k/--keymap, --sdl, --nographics

--autoconsole

Sintaxis: --autoconsole OPCIONES

Configura qué consola interactiva lanzará virt-install para la VM. Esta opción no es obligatoria; el comportamiento predeterminado es adaptativo y depende de cómo esté configurada la VM. Pero puede usar esta opción para anular la elección predeterminada.

--autoconsole graphical
Utiliza el virt-viewer(1) gráfico como consola interactiva.
--autoconsole text
Utiliza el modo de texto virsh console como consola interactiva.
--autoconsole none
Esto es lo mismo que --noautoconsole.
--noautoconsole
No intente conectarse automáticamente a la consola del invitado. Lo mismo que --autoconsole none.

Nota: virt-install sale rápidamente cuando se especifica esta opción. Si su comando solicitó una instalación de varios pasos, como --cdrom o --location, después de que la fase de instalación se complete, la VM se apagará, independientemente de si se solicitó un reinicio en la VM. Si desea que la VM se reinicie, virt-install debe permanecer en ejecución. Puede usar '--wait' para mantener virt-install activo incluso si se especifica --noautoconsole.

OPCIONES DE VIRTUALIZACIÓN

Opciones para anular las opciones predeterminadas de tipo de virtualización.

-v, --hvm

Solicita el uso de virtualización completa, si tanto la virtualización para como la completa están disponibles en el host. Este parámetro puede no estar disponible si se conecta a un hipervisor Xen en una máquina sin soporte de virtualización de hardware. Este parámetro se implica si se conecta a un hipervisor basado en QEMU.

-p, --paravirt

Este invitado debe ser un invitado paravirtualizado. Si el host soporta tanto la virtualización para como la completa, y ni este parámetro ni el --hvm se especifican, se asumirá este.

--container

Este invitado debe ser un invitado de tipo contenedor. Esta opción solo es necesaria si el hipervisor soporta otros tipos de invitados además (por lo tanto, por ejemplo, esta opción es el comportamiento predeterminado para LXC y OpenVZ, pero se proporciona para completitud).

--virt-type

El hipervisor en el que instalar. Las opciones disponibles incluyen kvm, qemu o xen. Las opciones disponibles se listan a través de 'virsh capabilities' en las etiquetas <domain>.

Esto reemplaza la opción --accelerate, que ahora es el comportamiento predeterminado. Para instalar un invitado QEMU simple, utilice '--virt-type qemu'.

--watchdog

Sintaxis: --watchdog MODELO[,action=ACCION]

Adjunta un dispositivo watchdog de hardware virtual al invitado. Esto requiere un demonio y un controlador de dispositivo en el invitado. El watchdog genera una señal cuando la máquina virtual parece estar colgada. ACCION especifica qué hará libvirt cuando se active el watchdog. Los valores son:

reset
Restablece forzosamente el invitado (el valor predeterminado).
poweroff
Apaga forzosamente el invitado.
pause
Pausa el invitado.
none
No hace nada.
shutdown
Apaga el invitado limpiamente (no recomendado, ya que un invitado colgado probablemente no responderá a un apagado limpio).

MODELO es el modelo de dispositivo emulado: i6300esb (el valor predeterminado) o ib700. Algunos ejemplos:

--watchdog default
Utiliza la configuración recomendada.
--watchdog i6300esb,action=poweroff
Utiliza el i6300esb con la acción 'poweroff'.

Sintaxis: --serial OPCIONES

--serial pty
Pseudo TTY. La pty asignada se listará en la descripción XML de la máquina virtual en ejecución.

Dispositivo host. Para dispositivos serie, esto podría ser /dev/ttyS0. Para dispositivos paralelos, esto podría ser /dev/parport0.

--channel

Especifica un dispositivo de canal de comunicación para conectar la máquina virtual y la máquina host. Esta opción utiliza las mismas opciones que --serial y --parallel para especificar el extremo host/fuente del canal. Se utilizan opciones 'target' adicionales para especificar cómo ve la máquina virtual el canal.

Algunos de los tipos de redirección de dispositivos de caracteres son:

--channel FUENTE,target.type=guestfwd,target.address=HOST:PUERTO
Canal de comunicación usando la pila de red usermode de QEMU. La máquina virtual puede conectarse al canal usando la combinación HOST:PUERTO especificada.
--channel FUENTE,target.type=virtio[,target.name=NOMBRE]
Canal de comunicación usando serie virtio (requiere host y máquina virtual 2.6.34 o posterior). Cada instancia de una línea --channel virtio se expone en la máquina virtual como /dev/vport0p1, /dev/vport0p2, etc. NOMBRE es metadatos opcionales, y puede ser cualquier cadena, como org.linux-kvm.virtioport1. Si se especifica, esto se expondrá en la máquina virtual en /sys/class/virtio-ports/vport0p1/NOMBRE
--channel spicevmc,target.type=virtio[,target.name=NOMBRE]
Canal de comunicación para el agente QEMU spice, usando serie virtio (requiere host y máquina virtual 2.6.34 o posterior). NOMBRE es metadatos opcionales, y puede ser cualquier cadena, como el valor predeterminado com.redhat.spice.0 que especifica cómo verá la máquina virtual el canal.
--channel qemu-vdagent,target.type=virtio[,target.name=NOMBRE]
Canal de comunicación para el agente QEMU vd, usando serie virtio (requiere host y máquina virtual 2.6.34 o posterior). Esto permite la funcionalidad de copiar y pegar con máquinas virtuales VNC. Tenga en cuenta que la integración del portapapeles de la máquina virtual se implementa a través de spice-vdagent, que debe estar ejecutándose incluso cuando la máquina virtual no utiliza gráficos spice. NOMBRE son metadatos opcionales que especifican cómo verá la máquina virtual el canal, y debe dejarse como el valor predeterminado com.redhat.spice.0 a menos que sepa lo que está haciendo.
