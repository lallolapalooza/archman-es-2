VFS_GLUSTERFS(8) Herramientas de administración del sistema VFS_GLUSTERFS(8)

NOMBRE

vfs_glusterfs - Utilizar características proporcionadas por GlusterFS

SINOPSIS

objetos vfs = glusterfs

DESCRIPCIÓN

Este módulo VFS forma parte del conjunto samba(8).

GlusterFS (http://www.gluster.org) es un sistema de archivos agrupado de código abierto capaz de escalar hasta varios peta-bytes. Con su cliente nativo basado en FUSE, GlusterFS está disponible como un sistema de archivos compatible con POSIX y, por lo tanto, puede ser compartido por Samba sin pasos adicionales.

El módulo VFS vfs_glusterfs proporciona una forma alternativa y superior de acceder a un sistema de archivos Gluster desde Samba para compartir. No requiere un montaje Gluster FUSE, sino que accede directamente al demonio GlusterFS a través de su biblioteca libgfapi, omitiendo así los costosos cambios de contexto del kernel-espacio de usuario y aprovechando algunas de las características más avanzadas de GlusterFS.

Este módulo se puede combinar con otros módulos, pero debe ser el último módulo en la lista de objetos vfs. Los módulos añadidos a esta lista a la derecha de la entrada glusterfs pueden no tener ningún efecto.

CONFIGURACIÓN

Una configuración básica se ve así.

[compartir]
objetos vfs = glusterfs
ruta = /ruta/base/relativa
glusterfs:volumen = gv0
modos de compartir del kernel = no

Tenga en cuenta que, dado que vfs_glusterfs no requiere un montaje Gluster, la ruta de la compartición se trata de manera diferente que para otras comparticiones: se interpreta como la ruta base de la compartición relativa al volumen gluster utilizado. Dado que esto generalmente no es una ruta del sistema al mismo tiempo, en una configuración de clúster ctdb donde ctdb gestiona Samba, debe establecer CTDB_SAMBA_SKIP_SHARE_CHECK=yes en el archivo de configuración de ctdb. De lo contrario, ctdb no estará en estado saludable.

Tenga en cuenta que actualmente los modos de compartir del kernel deben estar deshabilitados en una compartición que se ejecute con el módulo vfs glusterfs para que el servicio de archivos funcione correctamente.

OPCIONES

glusterfs:logfile = ruta

Define si se almacena o no un archivo de registro específico de vfs_glusterfs y dónde. Se admite la sustitución de variables del cliente (es decir, %M, %m, %I), por lo que se puede especificar un archivo de registro por cliente.

Ejemplo: glusterfs:logfile = /var/log/samba/glusterfs-vol2.%M.log

glusterfs:loglevel = 0-9

Define el nivel de registro, donde los números más altos corresponden a una mayor verbosidad. 0 - Sin registros; 9 - Nivel de registro de traza; se prefieren 7, que es el nivel de registro de información.

Si esta opción no se define con un loglevel explícito, se utiliza el valor predeterminado de glusterfs (actualmente loglevel 7).

glusterfs:volfile_server = nombre_servidor

Define qué servidor volfile se utilizará, por defecto es localhost. Podría ser una lista de elementos separados por espacios donde cada elemento podría ser

1. unix+/ruta/al/archivo/socket

2. [tcp+]IP|nombre_host|\[IPv6\][:puerto]

Tenga en cuenta la restricción en la denominación de un host IPv6, sigue la misma restricción que se basa en la denominación IPv6 en la URL según la RFC 2732.

glusterfs:volume = nombre_volumen

Define el nombre del volumen glusterfs a utilizar para esta compartición.

ADVERTENCIAS

El traductor de rendimiento de escritura en segundo plano de GlusterFS, cuando se utiliza con Samba, podría ser una fuente de corrupción de datos. El traductor, mientras procesa una llamada de escritura, devuelve inmediatamente el éxito pero continúa escribiendo los datos en el servidor en segundo plano. Esto puede causar corrupción de datos cuando dos clientes que dependen de Samba para proporcionar consistencia de datos operan en el mismo archivo.

El traductor de escritura en segundo plano está habilitado por defecto en GlusterFS. El plugin vfs_glusterfs verificará la presencia del traductor y se negará a conectarse si se detecta. Deshabilite el traductor de escritura en segundo plano para el volumen GlusterFS para permitir que el plugin se conecte al volumen. El traductor de escritura en segundo plano se puede deshabilitar fácilmente llamando

                        gluster volume set <nombre_volumen> performance.write-behind off

en la línea de comandos.

Con versiones de GlusterFS >= 9, omitimos silenciosamente el traductor de escritura en segundo plano durante la conexión inicial y se evita el error.
