DESCRIPCIÓN

Las funciones de la familia printf() producen salida según un formato como se describe a continuación. Las funciones printf() y vprintf() escriben la salida en stdout, el flujo de salida estándar; fprintf() y vfprintf() escriben la salida en el stream de salida dado; sprintf(), snprintf(), vsprintf() y vsnprintf() escriben en la cadena de caracteres str.

La función dprintf() es la misma que fprintf() excepto que produce salida a un descriptor de archivo, fd, en lugar de a un flujo stdio(3).

Las funciones snprintf() y vsnprintf() escriben como máximo size bytes (incluyendo el byte nulo terminador ('\0')) en str.

Las funciones vprintf(), vfprintf(), vdprintf(), vsprintf(), vsnprintf() son equivalentes a las funciones printf(), fprintf(), dprintf(), sprintf(), snprintf(), respectivamente, excepto que se llaman con una va_list en lugar de un número variable de argumentos. Estas funciones no llaman a la macro va_end. Debido a que invocan a la macro va_arg, el valor de ap no está definido después de la llamada. Ver stdarg(3).

Todas estas funciones escriben la salida bajo el control de una cadena de formato que especifica cómo los argumentos subsiguientes (o los argumentos accedidos a través de las facilidades de argumentos de longitud variable de stdarg(3)) se convierten para la salida.

C99 y POSIX.1-2001 especifican que los resultados no están definidos si una llamada a sprintf(), snprintf(), vsprintf(), o vsnprintf() causaría la copia entre objetos que se superponen (por ejemplo, si el array de cadena de destino y uno de los argumentos de entrada suministrados se refieren al mismo buffer). Ver ADVERTENCIAS.

Formato de la cadena de formato

La cadena de formato es una cadena de caracteres, que comienza y termina en su estado de cambio inicial, si lo hay. La cadena de formato se compone de cero o más directivas: caracteres ordinarios (no %), que se copian sin cambios al flujo de salida; y especificaciones de conversión, cada una de las cuales resulta en la obtención de cero o más argumentos subsiguientes. Cada especificación de conversión se introduce con el carácter % y termina con un especificador de conversión. Entre ellos puede haber (en este orden) cero o más flags, una anchura de campo mínima opcional, una precisión opcional y un modificador de longitud opcional.

La sintaxis general de una especificación de conversión es:


%[argumento$][flags][ancho][.precision][modificador de longitud]conversión

Los argumentos deben corresponderse correctamente (después de la promoción de tipo) con el especificador de conversión. Por defecto, los argumentos se utilizan en el orden dado, donde cada '*' (ver Anchura de campo y Precisión a continuación) y cada especificador de conversión solicitan el siguiente argumento (y es un error si se dan insuficientes argumentos). También se puede especificar explícitamente qué argumento se toma, en cada lugar donde se requiere un argumento, escribiendo "%m$" en lugar de '%' y "*m$" en lugar de '*', donde el entero decimal m denota la posición en la lista de argumentos del argumento deseado, indexado comenzando desde 1. Por lo tanto,


printf("%*d", ancho, num);

y


printf("%2$*1$d", ancho, num);

son equivalentes. El segundo estilo permite referencias repetidas al mismo argumento. El estándar C99 no incluye el estilo que usa '$', que proviene de la Single UNIX Specification. Si se utiliza el estilo que usa '$', debe usarse en todo momento para todas las conversiones que toman un argumento y todos los argumentos de anchura y precisión, pero se puede mezclar con formatos "%%", que no consumen un argumento. No puede haber huecos en los números de argumentos especificados usando '$'; por ejemplo, si se especifican los argumentos 1 y 3, el argumento 2 también debe especificarse en algún lugar de la cadena de formato.

Para algunas conversiones numéricas se utiliza un carácter separador de miles o un carácter de punto decimal. El carácter real utilizado depende de la parte LC_NUMERIC de la configuración regional. (Ver setlocale(3).) La configuración regional POSIX usa '.' como carácter decimal, y no tiene un carácter separador de miles. Por lo tanto,


printf("%'.2f", 1234567.89);

resulta en "1234567.89" en la configuración regional POSIX, en "1234567,89" en la configuración regional nl_NL, y en "1.234.567,89" en la configuración regional da_DK.

Caracteres de flags

El carácter % va seguido de cero o más de los siguientes flags:

#
El valor debe convertirse a una "forma alternativa". Para conversiones o, el primer carácter de la cadena de salida se convierte en cero (prefijando un 0 si no era cero previamente). Para conversiones x y X, a un resultado distinto de cero se le antepone la cadena "0x" (o "0X" para conversiones X). Para conversiones a, A, e, E, f, F, g y G, el resultado siempre contendrá un punto decimal, incluso si no le siguen dígitos (normalmente, un punto decimal aparece en los resultados de esas conversiones solo si un dígito le sigue). Para conversiones g y G, los ceros finales no se eliminan del resultado como lo harían de otra manera. Para m, si errno contiene un código de error válido, se imprime la salida de strerrorname_np(errno); de lo contrario, se imprime el valor almacenado en errno como un número decimal. Para otras conversiones, el resultado no está definido.
0
El valor debe rellenarse con ceros. Para conversiones d, i, o, u, x, X, a, A, e, E, f, F, g y G, el valor convertido se rellena a la izquierda con ceros en lugar de espacios en blanco. Si los flags 0 y - aparecen juntos, se ignora el flag 0. Si se da una precisión con una conversión de enteros (d, i, o, u, x, y X), se ignora el flag 0. Para otras conversiones, el comportamiento no está definido.
-

Anchura del campo

Es un número decimal entero opcional que especifica el número mínimo de caracteres que se van a producir. Si el valor convertido tiene menos caracteres que la anchura del campo, se le antepondrán espacios en blanco (o ceros si se especificó el flag 0) hasta alcanzar la anchura. Si la anchura del campo se da como un asterisco (*), se obtiene el ancho de un argumento int. Si el valor del ancho es negativo, se trata como si fuera positivo y el flag - estuviera presente. En el caso de las conversiones s y [...], la anchura es la anchura máxima de los caracteres a imprimir. Cuando se especifica un ancho con el estilo de argumento posicional, como en "%m$", el argumento correspondiente al ancho debe ser el número m en la lista de argumentos.

Precisión

Es un número decimal entero opcional precedido por un punto ('.'). Esto especifica la precisión mínima de los caracteres que se van a producir. La interpretación de la precisión depende del tipo de conversión:

  • Para a, A, e, E, f, y F: es el número de dígitos que deben aparecer después del punto decimal.
  • Para g y G: es el número máximo de dígitos significativos que deben aparecer en total.
  • Para s y [...]: es el número máximo de caracteres que se van a escribir desde la cadena. Si las cadenas son más cortas que la precisión, no se produce nada más.
  • Para o, u, x, X: es el número mínimo de dígitos que deben aparecer para el número. Los ceros se añaden a la izquierda si es necesario.
  • Para d e i: es el número mínimo de dígitos que deben aparecer para el número. Los ceros se añaden a la izquierda si es necesario. Si se especifica una precisión para una conversión entera, el flag 0 se ignora.
  • Para p: es el número de dígitos que deben aparecer.
  • Si la precisión es seguida por una conversión, se le anteponen ceros si la precisión es mayor que el número de dígitos. Si la precisión es cero y el valor es cero, no se produce ninguna cadena.
  • Si se omite la precisión, o si su valor es nulo, se asume una precisión infinita (excepto donde se indique lo contrario). Un valor negativo de precisión se trata como si fuera cero.
  • Si la precisión se da como un asterisco (*), se obtiene la precisión de un argumento int. Cuando se especifica una precisión con el estilo de argumento posicional, como en "%m$", el argumento correspondiente a la precisión debe ser el número m en la lista de argumentos.

Modificador de longitud

Este es un modificador opcional que afecta la interpretación del tipo de argumento.

hh

Para las conversiones d, i, o, u, x, y X, el argumento se interpreta como un argumento de tipo signed char o unsigned char respectivamente.

h

Para las conversiones d, i, o, u, x, y X, el argumento se interpreta como un argumento de tipo short o unsigned short respectivamente.

ll

Para las conversiones d, i, o, u, x, y X, el argumento se interpreta como un argumento de tipo long long o unsigned long long respectivamente.

l

Para las conversiones d, i, o, u, x, y X, el argumento se interpreta como un argumento de tipo long o unsigned long respectivamente. Para las conversiones n, p, c, y s, el argumento se interpreta como un puntero a wchar_t o un argumento wint_t respectivamente.

L

Para las conversiones a, A, e, E, f, F, g, y G, el argumento se interpreta como un argumento de tipo long double.

j

Para las conversiones d, i, o, u, x, y X, el argumento se interpreta como un argumento de tipo intmax_t o uintmax_t respectivamente.

z

Para las conversiones d, i, o, u, x, y X, el argumento se interpreta como un argumento de tipo size_t o ssize_t respectivamente.

t

Para las conversiones d, i, o, u, x, y X, el argumento se interpreta como un argumento de tipo ptrdiff_t o uprtdiff_t respectivamente.

Especificador de conversión

El carácter de especificación de conversión determina si el argumento se trata como un número de punto flotante, un entero, o una cadena, etc. El especificador de conversión es un carácter de una sola letra. Si un especificador de conversión no está listado aquí, el comportamiento está indefinido.

Los especificadores de conversión admitidos son:

%
Para un carácter literal '%'. No se consume ningún argumento, por lo que ningún formato puede ser correcto.
d, i
El argumento int se convierte a decimal (base 10) con signo. (i es un alias de d).
o
El argumento unsigned int se convierte a octal (base 8) sin signo. Los ceros iniciales se omiten, a menos que la precisión sea cero.
u
El argumento unsigned int se convierte a decimal (base 10) sin signo.
x
El argumento unsigned int se convierte a hexadecimal (base 16) con dígitos 0-9 y a-f.
X
El argumento unsigned int se convierte a hexadecimal (base 16) con dígitos 0-9 y A-F.
f, F
El argumento double se convierte a decimal notación con un signo opcional, que siempre contiene un punto decimal y 6 dígitos después de él en el caso de f. El valor se redondea al número más cercano de dígitos especificado por la precisión. Una precisión de 0 produce ningún dígito después del punto decimal. Si la precisión se omite, se asume 6. La forma F produce infinitos en lugar de "inf" y NaN en lugar de "nan".
e, E
El argumento double se convierte en notación científica con un signo opcional, que siempre contiene un dígito antes del punto decimal (que siempre está presente), seguido de un número de dígitos especificado por la precisión (por defecto 6). El exponente siempre tiene dos dígitos; se antepone una 'e' o una 'E' al exponente. Una precisión de 0 produce ningún dígito después del punto decimal. La forma E usa una 'E' mayúscula para el exponente, mientras que e usa una 'e' minúscula.
g, G
El argumento double se convierte a notación decimal (ella f) o científica (ella e). Se elige el estilo que sea más corto y se elimina el punto decimal si no hay dígitos significativos después de él. La precisión especifica el número de dígitos significativos. La forma G usa una 'E' mayúscula si el exponente es grande, y g usa una 'e' minúscula. Los ceros finales se eliminan.
a, A
El argumento double se convierte en notación hexadecimal de punto flotante. La precisión especifica el número de dígitos hexadecimales después del punto de separación hexadecimal (que está prefijado por 0x o 0X). El exponente va precedido de 'p' o 'P'. La forma A usa un 'X' mayúscula y 'P' mayúscula.
c
El argumento int se convierte a un carácter sin signo unsigned char.
s
El argumento debe ser un puntero a char (una cadena terminada en nulo). Los caracteres se imprimen hasta que se encuentra un carácter nulo o hasta que se alcanza el número de caracteres especificado por la precisión. Si el argumento es un puntero nulo, se imprime "(null)".
C
Como c, pero toma un argumento wint_t y lo convierte en un carácter multibyte según la configuración regional actual.
S
Como s, pero toma un puntero a wchar_t y lo convierte en una cadena de caracteres multibyte según la configuración regional actual.
p
El argumento debe ser un puntero a void. La representación es la de un valor de dirección de forma dependiente de la implementación.
n
Nada se imprime. En su lugar, el valor del número de caracteres escritos hasta ahora en el flujo de salida se almacena en la ubicación de memoria apuntada por el argumento int * (puntero a entero). El argumento debe ser un puntero a entero.
m
Imprime el mensaje de error correspondiente al valor actual de errno. Este es un error de extensión de GNU.

ERRORES

Las funciones printf, fprintf, sprintf, vprintf, vfprintf, y vsprintf pueden fallar y establecer errno en caso de que ocurra un error de E/S.

Si la operación de escritura sobre el flujo stream o el descriptor de archivo fd falla, las funciones fprintf, dprintf, vfprintf, y vdprintf devolverán un valor negativo, y un valor negativo se devolverá para snprintf y vsnprintf si el valor del número de caracteres a escribir es mayor o igual que size.

Si ocurre un error de codificación con printf, fprintf, dprintf, vprintf, vfprintf, o vdprintf, estas funciones devuelven un valor negativo. Si ocurre un error de codificación con sprintf, snprintf, vsprintf, o vsnprintf, estas funciones devuelven un valor negativo.

Si el argumento format no es válido, el comportamiento está indefinido.

Si se produce un desbordamiento de búfer para sprintf o vsprintf (es decir, si la cadena de formato es demasiado larga para el búfer de destino), el comportamiento está indefinido.

Para snprintf y vsnprintf, si el número de caracteres a escribir es mayor o igual que el valor de size, entonces se escribe size bytes en el búfer, y los caracteres restantes se descartan. El resultado siempre se termina con un carácter nulo, a menos que size sea cero. Si size es cero, str no necesita ser un puntero válido, y no se escribirá nada en él. Si el número de caracteres a escribir es mayor o igual que size, o si ocurre un error de codificación, las funciones devuelven un valor negativo.

CONFORME A

Las funciones printf, fprintf, sprintf, vprintf, vfprintf, vsprintf cumplen con C99 y POSIX.1-2001. La función snprintf también cumple con C99 y POSIX.1-2001. Las funciones dprintf y vdprintf son extensiones de GNU.

ADVERTENCIAS

El uso de sprintf es peligroso, ya que no hay forma de limitar la cantidad de escritura en la cadena de destino; puede provocar desbordamientos de búfer y escritura fuera de los límites de la memoria si el argumento format contiene cadenas más largas que el búfer de destino. Siempre que sea posible, se debe preferir snprintf.

C99 y POSIX.1-2001 especifican que los resultados no están definidos si una llamada a sprintf, snprintf, vsprintf, o vsnprintf causaría la copia entre objetos que se superponen (por ejemplo, si el array de cadena de destino y uno de los argumentos de entrada suministrados se refieren al mismo búfer).

El uso de la directiva de formato %n es peligroso, ya que permite que un programa escriba en cualquier ubicación de memoria y puede utilizarse para fines maliciosos.

El uso de la directiva de formato %m solo está disponible en glibc.

No se garantiza que la salida de printf sea portátil. Por ejemplo, los caracteres de control no ASCII (como el salto de línea) pueden ser impresos de manera diferente en sistemas diferentes, y los valores numéricos pueden ser representados en diferentes bases. En general, los programas de C que dependen de la salida de texto que no sea ASCII deben hacerlo con cuidado.

Ancho de campo

Una cadena opcional de dígitos decimales (con primer dígito distinto de cero) que especifica un ancho de campo mínimo. Si el valor convertido tiene menos caracteres que el ancho de campo, se rellenará con espacios por la izquierda (o por la derecha, si se ha dado la bandera de ajuste a la izquierda). En lugar de una cadena de dígitos decimales, se puede escribir "*" o "*m$" (para algún entero decimal m) para especificar que el ancho del campo se da en el siguiente argumento, o en el m-ésimo argumento, respectivamente, que debe ser de tipo int. Un ancho de campo negativo se toma como una bandera '-' seguida de un ancho de campo positivo. En ningún caso un ancho de campo inexistente o pequeño provocará la truncación de un campo; si el resultado de una conversión es más ancho que el ancho del campo, el campo se expandirá para contener el resultado de la conversión.

Precisión

Una precisión opcional, en forma de un punto ('.') seguido de una cadena opcional de dígitos decimales. En lugar de una cadena de dígitos decimales, se puede escribir "*" o "*m$" (para algún entero decimal m) para especificar que la precisión se da en el siguiente argumento, o en el m-ésimo argumento, respectivamente, que debe ser de tipo int. Si la precisión se da solo como '.', la precisión se toma como cero. Una precisión negativa se toma como si la precisión se hubiera omitido. Esto da el número mínimo de dígitos que deben aparecer para las conversiones d, i, o, u, x, y X, el número de dígitos que deben aparecer después del carácter de punto decimal para las conversiones a, A, e, E, f, y F, el número máximo de dígitos significativos para las conversiones g y G, o el número máximo de caracteres que se imprimirán de una cadena para las conversiones s y S.

Modificador de longitud

Aquí, "conversión de enteros" significa conversión d, i, o, u, x, o X.

hh
Una conversión de enteros subsiguiente corresponde a un argumento signed char o unsigned char, o una conversión n subsiguiente corresponde a un puntero a un argumento signed char.
h
Una conversión de enteros subsiguiente corresponde a un argumento short o unsigned short, o una conversión n subsiguiente corresponde a un puntero a un argumento short.
l
(ele) Una conversión de enteros subsiguiente corresponde a un argumento long o unsigned long, o una conversión n subsiguiente corresponde a un puntero a un argumento long, o una conversión c subsiguiente corresponde a un argumento wint_t, o una conversión s subsiguiente corresponde a un puntero a un argumento wchar_t. En una conversión a, A, e, E, f, F, g, o G subsiguiente, este modificador de longitud se ignora (C99; no en SUSv2).
ll
(ele-ele). Una conversión de enteros subsiguiente corresponde a un argumento long long o unsigned long long, o una conversión n subsiguiente corresponde a un puntero a un argumento long long.
q
Un sinónimo de ll. Esta es una extensión no estándar, derivada de BSD; evite su uso en código nuevo.
L
Una conversión a, A, e, E, f, F, g, o G subsiguiente corresponde a un argumento long double. (C99 permite %LF, pero SUSv2 no.)
j
Una conversión de enteros subsiguiente corresponde a un argumento intmax_t o uintmax_t, o una conversión n subsiguiente corresponde a un puntero a un argumento intmax_t.
z
Una conversión de enteros subsiguiente corresponde a un argumento size_t o ssize_t, o una conversión n subsiguiente corresponde a un puntero a un argumento size_t.
Z
Un sinónimo no estándar de z que precede a la aparición de z. No usar en código nuevo.
t
Una conversión de enteros subsiguiente corresponde a un argumento ptrdiff_t, o una conversión n subsiguiente corresponde a un puntero a un argumento ptrdiff_t.

SUSv3 especifica todos los anteriores, excepto aquellos modificadores explicitamente señalados como extensiones no estándar. SUSv2 solo especificaba los modificadores de longitud h (en hd, hi, ho, hx, hX, hn) y l (en ld, li, lo, lx, lX, ln, lc, ls) y L (en Le, LE, Lf, Lg, LG).

Como extensión no estándar, las implementaciones de GNU tratan ll y L como sinónimos, de modo que se puede, por ejemplo, escribir llg (como sinónimo de Lg compatible con el estándar) y Ld (como sinónimo de lld compatible con el estándar). Dicho uso no es portable.

Especificadores de conversión

Un carácter que especifica el tipo de conversión a aplicar. Los especificadores de conversión y sus significados son:

d, i
El argumento int se convierte a notación decimal con signo. La precisión, si la hay, da el número mínimo de dígitos que deben aparecer; si el valor convertido requiere menos dígitos, se rellena por la izquierda con ceros. La precisión predeterminada es 1. Cuando se imprime 0 con una precisión explícita de 0, la salida está vacía.
o, u, x, X
El argumento unsigned int se convierte a notación octal sin signo (o), decimal sin signo (u) o hexadecimal sin signo (x y X). Las letras abcdef se usan para las conversiones x; las letras ABCDEF se usan para las conversiones X. La precisión, si la hay, da el número mínimo de dígitos que deben aparecer; si el valor convertido requiere menos dígitos, se rellena por la izquierda con ceros. La precisión predeterminada es 1. Cuando se imprime 0 con una precisión explícita de 0, la salida está vacía.
e, E

EJEMPLOS

Para imprimir Pi con cinco decimales:


#include <math.h>
#include <stdio.h>
fprintf(stdout, "pi = %.5f\n", 4 * atan(1.0));

Para imprimir una fecha y hora con el formato "Domingo, Julio 3, 10:02", donde weekday y month son punteros a cadenas de caracteres:


#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        weekday, month, day, hour, min);

Muchos países utilizan el orden día-mes-año. Por lo tanto, una versión internacionalizada debe ser capaz de imprimir los argumentos en un orden especificado por el formato:


#include <stdio.h>
fprintf(stdout, format,
        weekday, month, day, hour, min);

donde format depende de la configuración regional y puede permutar los argumentos. Con el valor:


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

se podría obtener "Sonntag, 3. Juli, 10:02".

Para asignar una cadena de tamaño suficientemente grande e imprimir en ella (código correcto para glibc 2.0 y glibc 2.1):

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Determinar el tamaño requerido.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un byte extra para '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si se produce truncamiento en versiones de glibc anteriores a glibc 2.0.6, esto se trata como un error en lugar de gestionarse correctamente.
