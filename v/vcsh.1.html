NOMBRE

vcsh - Sistema de Control de Versiones para $HOME - Múltiples repositorios Git en $HOME

SINOPSIS

vcsh [opciones] comando

vcsh clone [-b rama] url [repo]

vcsh delete repo

vcsh enter repo

vcsh foreach [-g] comando git

vcsh help

vcsh init repo

vcsh list

vcsh list-tracked [repo]

vcsh list-untracked [-a] [-r] [repo]

vcsh pull

vcsh push

vcsh rename repo nombre-nuevo

vcsh run repo comando shell

vcsh status [repo]

vcsh upgrade repo

vcsh version

vcsh which subcadena

vcsh write-gitignore [repo]

vcsh repo comando git

vcsh repo

DESCRIPCIÓN

vcsh te permite tener varios repositorios git(1), todos manteniendo sus árboles de trabajo en $HOME sin pisarse entre sí. Eso, a su vez, significa que puedes tener un repositorio por conjunto de configuración (zsh, vim, ssh, etc.), eligiendo qué configuraciones quieres usar en cada máquina.

vcsh utiliza una técnica llamada repositorios Git "bare" falsos, manteniendo $GIT_DIR en un directorio diferente de $GIT_WORK_TREE que apunta a $HOME.

El uso de enlaces simbólicos no es necesario en esta configuración, lo que resulta en una configuración más limpia.

vcsh fue diseñado pensando en mr(1), por lo que es posible que desees instalarlo junto con vcsh. Dicho esto, puedes usar vcsh fácilmente sin mr si lo prefieres.

Una configuración de ejemplo para vcsh y mr se puede encontrar en https://github.com/RichiH/vcsh_mr_template y se puede usar con vcsh clone https://github.com/RichiH/vcsh_mr_template mr.

Ten en cuenta que siempre puedes usar una ruta en lugar de un nombre para repo. Esto es necesario para soportar mr y otros scripts correctamente y no es de preocupación para un usuario interactivo.

OPCIONES

-c
Carga archivo antes que otros archivos de configuración.
-d
Habilita el modo de depuración.
-v
Habilita el modo detallado.

COMANDOS

clone
Clona un repositorio existente.
Si necesitas clonar un paquete de repositorios, mira el hook post-clone-retired.
También puedes usar un solo repositorio git con varias ramas. Usa la opción -b para especificar una rama al clonar, la predeterminada es master.
commit
Hace commit en todos los repositorios.
delete
Elimina un repositorio existente.
enter
Entra en el repositorio; inicia un nuevo $SHELL con $GIT_DIR establecido.
foreach
Ejecuta el comando git para cada repositorio vcsh.
-g: Ejecuta en contexto general.
help
Muestra la ayuda.
init
Inicializa un repositorio vacío.
list
Lista todos los repositorios vcsh locales.
list-tracked
Lista todos los archivos rastreados por vcsh.
Si deseas listar los archivos rastreados por un repositorio específico, simplemente añade el nombre del repositorio al final.
list-tracked-by
Lista los archivos rastreados por un repositorio.
Este es un comando obsoleto; deberías usar list-tracked <repo> en su lugar.
list-untracked
Lista todos los archivos NO rastreados por vcsh.
-a: Muestra todos los archivos. Por defecto, se llama a git ls-files --exclude-standard.
-r: Modo recursivo. Por defecto, la lista de archivos es superficial y se detiene en los niveles de directorio cuando es posible.
$repo: Lista los archivos no rastreados por este repositorio específico.
pull
Descarga de todos los remotos de vcsh.
push
Envía a todos los remotos de vcsh.
rename
Renombra un repositorio.
run
Ejecuta un comando con $GIT_DIR y $GIT_WORK_TREE establecidos. Te permite ejecutar cualquier comando sin restricciones. Úsalo con cuidado.
Ten en cuenta que hay una característica algo mágica para run. En lugar de repo, también acepta path. Cualquier cosa que contenga una barra se asumirá como una ruta. vcsh run operará entonces en este directorio en lugar de en el que se genera normalmente a partir del nombre del repositorio. Esto es necesario para soportar mr y otros scripts correctamente y no es de preocupación para un usuario interactivo.
status
Muestra los estados de todos/un repositorios vcsh.
upgrade
Actualiza el repositorio a la configuración recomendada actualmente.
version
Imprime información de la versión.
which subcadena
Busca subcadena en el nombre de cualquier archivo rastreado.
write-gitignore
Escribe .gitignore.d/repo a través de git ls-files. Si no se especifica repo pero estamos dentro de un repositorio vcsh, usa ese.
repo comando git
Atajo para ejecutar comandos git en un repo. Añadirá git al principio de comando git.
repo
Atajo para ejecutar vcsh enter <repo>.

AMBIENTE

Como se mencionó anteriormente, vcsh establecerá $GIT_DIR y $GIT_WORK_TREE a los valores apropiados para los repositorios Git "bare" falsos.

CONFIGURACIÓN

Hay varias formas de ajustar las diversas opciones de vcsh. En orden de precedencia ascendente, son:

○
VARIABLE=foo vcsh
○
</etc/vcsh/config>
○
<$XDG_CONFIG_HOME/vcsh/config>
○
vcsh -c <archivo>

Ten en cuenta que estos archivos se cargan (sourced). Cualquier comando será ejecutado en el contexto de tu shell.

Opciones interesantes que puedes ajustar:

$VCSH_GITATTRIBUTES
Puede ser none, o cualquier otro valor.
none no mantendrá los atributos de Git en una ubicación especial.
Si se establece en cualquier otro valor, se mantendrán archivos gitattributes específicos del repositorio.
El valor predeterminado es none.
$VCSH_GITIGNORE
Puede ser exact, none, o recursive.
exact inicializará el archivo ignore específico del repositorio con todos los nombres de archivos y directorios que devuelve git ls-files.
none no escribirá ningún archivo ignore.
recursive descenderá a través de todos los director

NAME

vcsh - manage dotfiles in multiple git repositories

SYNOPSIS

vcsh -h | --help

vcsh -V | --version

vcsh COMMAND [ARG ...]

DESCRIPTION

vcsh is a tool to manage dotfiles in multiple git repositories. It is designed for users who want to keep their configuration files under version control, but do not want to rely on symlinks, or a single git repository.

The main idea is to have a set of git repositories, one for each set of configuration files. These repositories are managed by vcsh and their contents are checked out into the user's home directory.

OPTIONS

When invoked with a command, vcsh accepts the following options:

-h, --help
Show help message and exit.
-V, --version
Show version information and exit.

COMMANDS

The following commands are available:

clone [REPOS...])
Clone repositories. If no repositories are specified, all repositories are cloned.
status [REPOS...])
Show status of repositories. If no repositories are specified, all repositories are shown.
pull [REPOS...])
Pull changes from remote repositories. If no repositories are specified, all repositories are pulled.
push [REPOS...])
Push changes to remote repositories. If no repositories are specified, all repositories are pushed.
add FILES...
Add files to the repositories. Files are added to the repository that currently manages them.
commit [OPTIONS] [REPOS...]
Commit changes to repositories. If no repositories are specified, all repositories are committed.
log [REPOS...])
Show commit log of repositories. If no repositories are specified, all repositories are shown.
fetch [REPOS...])
Fetch changes from remote repositories. If no repositories are specified, all repositories are fetched.
reset [OPTIONS] [REPOS...])
Reset repositories to a specific commit. If no repositories are specified, all repositories are reset.
rename OLDNAME NEWNAME
Rename a repository.
rm FILES...
Remove files from repositories. Files are removed from the repository that currently manages them.
run COMMAND [ARGS...]
Run a command in all repositories.
list
List all managed repositories.
init [REPO]
Initialize a new repository. If no repository name is specified, an interactive prompt will appear.
check
Check the integrity of the repositories.
upgrade
Upgrade the configuration files to the latest version.

ENVIRONMENT

vcsh respects the following environment variables:

$VCSH_CONFIG_D
The directory containing the vcsh configuration files. Defaults to $XDG_CONFIG_HOME/vcsh.
$VCSH_HOME
The directory where the repositories are cloned to. Defaults to $HOME/.config/vcsh/repo.d.
$VCSH_GIT_DIR
The directory where the git repositories are stored. Defaults to $VCSH_HOME.
$VCSH_WORKTREE
The directory where the working trees are checked out to. Defaults to $HOME.
$VCSH_DEBUG
Enable debug mode.
$XDG_CONFIG_HOME
See the 'XDG Base Directory Specification'. Defaults to $HOME/.config.
$VCSH_REPO_D
The directory where repositories are read from and stored. Defaults to $XDG_CONFIG_HOME/vcsh/repo.d.
$VCSH_HOOK_D
The directory where hooks are read from. Defaults to $XDG_CONFIG_HOME/vcsh/hooks-enabled.
$VCSH_BASE
The directory where repositories are checked out to. Defaults to $HOME.

CONFIG

vcsh supports configuration files in order to customize its behavior. The configuration files are located in $VCSH_CONFIG_D.

CONFIG
A space separated list of shell scripts to be sourced before vcsh executes any command. These scripts can be used to set environment variables or define functions that vcsh will use. The default value is $VCSH_CONFIG_D/config.
Additionally to the above.
Defaults to exact.
$VCSH_WORKTREE
Can be absolute, or relative.
absolute will set an absolute path; defaulting to $HOME.
relative will set a path relative to $GIT_DIR.
Defaults to absolute.

Less interesting knobs you could turn:

$VCSH_DEBUG
Enter debug mode.
$XDG_CONFIG_HOME
As specified in the 'XDG Base Directory Specification', see http://standards.freedesktop.org/basedir-spec/basedir-spec-latest.html
Defaults to <$HOME/.config>.
$VCSH_REPO_D
The directory where repositories are read from and stored.
Defaults to <$XDG_CONFIG_HOME/vcsh/repo.d>.
$VCSH_HOOK_D
The directory where hooks are read from.
Defaults to <$XDG_CONFIG_HOME/vcsh/hooks-enabled>.
$VCSH_BASE
The directory where repositories are checked out to.
Defaults to $HOME.

HOOK SYSTEM

vcsh provides a hook system. Hook scripts must be executable and should be placed in <$XDG_CONFIG_HOME/vcsh/hooks-available>. From there, they can be soft-linked into <$XDG_CONFIG_HOME/vcsh/hooks-enabled>; vcsh will only execute hooks that are in this directory.

Hooks follow a simple format. pre-run will be run before anything is run. If you want to have more than one script for a certain hook, just append any kind of string to order them. A system of pre-run, <pre-run.10>, <pre-run.20> etc is suggested; other options would be pre-run-10 or <pre-run.sh>. A dot after the hook name is optional.

If you want to create hooks for a specific vcsh repository, simply prepend the repository's name, followed by a dot, i.e. <zsh.pre-run>. Otherwise, the same rules as above apply. The dot between the repository's name and the hook is mandatory, though.

Available hooks are pre-clone, post-clone, post-clone-retired, pre-command, post-command, pre-enter, post-enter, pre-init, post-init, pre-pull, post-pull, pre-push, post-push, pre-run, post-run, pre-upgrade, and post-upgrade. If you need more, vcsh is trivial to patch, but please let upstream know so we can ship them by default.

OVERLAY SYSTEM

vcsh also provides an overlay system. Similar to hooks, the recommended locations are <$XDG_CONFIG_HOME/vcsh/overlays-available> and <$XDG_CONFIG_HOME/vcsh/overlays-enabled>.

Overlays follow the same rules as hooks and you are free to overwrite any and all functions. Same as hooks, you can use global or repository-specific overlays by using either <$VCSH_OVERLAY_D/$VCSH_COMMAND> or <$VCSH_OVERLAY_D/$VCSH_REPO_NAME.$VCSH_COMMAND>.

Please note that nothing stops you from, e.g. overwriting status() in <$VCSH_OVERLAY_D/commit>. As the overlays will be sourced and you are replacing arbitrary functions, any and all features may stop working, or you may even lose data.

You have been warned.

SECURITY CONSIDERATIONS

vcsh allows you to execute arbitrary commands via vcsh run. For example, adding a sudo(8) rule for vcsh would be pretty stupid.

Additionally, vcsh will source, i.e. execute, all files listed in CONFIG. You can put any and all commands into these config files and they will be executed.

BUGS

None are known at this time, but reports and/or patches are more than welcome.

INTEROPERABILITY

If you rely on git submodule use git 1.7.12 or later. Earlier versions do not clean internal variables properly before descending into submodules, resulting in unhappy end users.

HISTORY

Like most people, the author initially made do with a single repository for all config files, all of which were soft-linked into $HOME.

Martin F. Krafft aka madduck came up with the concept of fake bare Git repositories.

vcsh was initially written by madduck. This version is a re-implementation from scratch with a lot more features. madduck graciously agreed to let the author take over the name.
