NOMBRE

virt-alignment-scan - Comprobar la alineación de particiones de máquinas virtuales

SINOPSIS

virt-alignment-scan [--opciones] -d nombre_dominio
virt-alignment-scan [--opciones] -a disco.img [-a disco.img ...]
virt-alignment-scan [--opciones]

DESCRIPCIÓN

Cuando sistemas operativos antiguos se instalan, las herramientas de particionado colocan las particiones en un sector desalineado con el almacenamiento subyacente (comúnmente la primera partición comienza en el sector 63). Las particiones desalineadas pueden provocar que un sistema operativo emita más I/O del que debería ser necesario.

La herramienta virt-alignment-scan comprueba la alineación de las particiones en máquinas virtuales e imágenes de disco y le advierte si hay problemas de alineación.

Actualmente no existe una herramienta de virt para solucionar problemas de alineación. Solo puede reinstalar el sistema operativo invitado. El siguiente documento de NetApp resume el problema y las posibles soluciones: http://media.netapp.com/documents/tr-3747.pdf

SALIDA

Para ejecutar esta herramienta directamente en una imagen de disco, use la opción -a:

$ virt-alignment-scan -a winxp.img
/dev/sda1        32256          512    malo (alineación < 4K)
$ virt-alignment-scan -a fedora16.img
/dev/sda1      1048576         1024K   ok
/dev/sda2      2097152         2048K   ok
/dev/sda3    526385152         2048K   ok

Para ejecutar la herramienta en un invitado conocido por libvirt, use la opción -d y posiblemente la opción -c:

# virt-alignment-scan -d RHEL5
/dev/sda1        32256          512    malo (alineación < 4K)
/dev/sda2    106928640          512    malo (alineación < 4K)
$ virt-alignment-scan -c qemu:///system -d Win7TwoDisks
/dev/sda1      1048576         1024K   ok
/dev/sda2    105906176         1024K   ok
/dev/sdb1        65536           64K   ok

Ejecute virt-alignment-scan sin ninguna opción -a o -d para escanear todos los dominios de libvirt.

# virt-alignment-scan
F16x64:/dev/sda1      1048576         1024K   ok
F16x64:/dev/sda2      2097152         2048K   ok
F16x64:/dev/sda3    526385152         2048K   ok

La salida consta de 4 o más columnas separadas por espacios en blanco. Solo las primeras 4 columnas son significativas si desea analizar esto desde un programa. Las columnas son:

col 1
El nombre del dispositivo y la partición (ej. /dev/sda1 que significa la primera partición en el primer dispositivo de bloque).

Al listar todos los dominios de libvirt (no se proporciona ninguna opción -a o -d), esta columna se prefija con el nombre o UUID del libvirt (si se proporciona --uuid). ej: "WinXP:/dev/sda1"

col 2
el inicio de la partición en bytes
col 3
la alineación en bytes o Kbytes (ej. 512 o "4K")
col 4
"ok" si la alineación es la mejor para el rendimiento, o "malo" si la alineación puede causar problemas de rendimiento
cols 5+
explicación opcional en texto libre.

El código de salida del programa cambia dependiendo de si se encontraron particiones mal alineadas. Consulte "ESTADO DE SALIDA" a continuación.

Si solo desea el código de salida sin ninguna salida, use la opción -q.

OPCIONES

--help
Mostrar ayuda breve.
-a archivo
--add archivo
Añadir archivo que debe ser una imagen de disco de una máquina virtual.

El formato de la imagen de disco se detecta automáticamente. Para anular esto y forzar un formato particular, use la opción --format=...

-a URI
--add URI
Añadir un disco remoto. Consulte "AÑADIR ALMACENAMIENTO REMOTO" en guestfish(1).
--blocksize=512
--blocksize=4096
--blocksize
Este parámetro establece el tamaño del sector de la imagen de disco. Afecta a todos los discos posteriores añadidos explícitamente después de este parámetro. Usar --blocksize sin argumento cambia el tamaño del sector del disco al valor predeterminado, que suele ser de 512 bytes. Consulte también "guestfs_add_drive_opts" en guestfs(3).
-c URI
--connect URI
Si usa libvirt, conéctese a la URI dada. Si se omite, nos conectaremos al hipervisor libvirt por defecto.

Si especifica dispositivos de bloque de invitados directamente (-a), entonces no se utiliza libvirt en absoluto.

-d invitado
--domain invitado
Añadir todos los discos del invitado libvirt nombrado. Se pueden usar UUIDs de dominio en lugar de nombres.
--format=raw|qcow2|..
--format
El valor predeterminado para la opción -a es la detección automática del formato de la imagen de disco. Usar esto fuerza el formato del disco para las opciones -a que siguen en la línea de comandos. Usar --format sin argumento revierte a la detección automática para las opciones -a posteriores.

Por ejemplo:

virt-alignment-scan --format=raw -a disk.img

fuerza el formato raw (sin detección automática) para disk.img.

virt-alignment-scan --format=raw -a disk.img --format -a another.img

fuerza el formato raw (sin detección automática) para disk.img y revierte a la detección automática para another.img.

Si tiene imágenes de disco de invitados de formato raw no confiables, debe usar esta opción para especificar el formato del disco. Esto evita un posible problema de seguridad con invitados maliciosos (CVE-2010-3851).

-P num_hilos
Desde libguestfs 1.22, virt-alignment-scan es multihilo y examina los invitados en paralelo. Por defecto, el número de hilos a usar se elige en función de la cantidad de memoria libre disponible en el momento en que se inicia virt-alignment-scan. Puede forzar a virt-alignment-scan a usar como máximo "num_hilos" usando la opción -P.

Tenga en cuenta que -P 0 significa autodetectar y -P 1 significa usar un solo hilo.

-q
--quiet
No producir ninguna salida. Simplemente establezca el código de salida (consulte "ESTADO DE SALIDA" a continuación).
--uuid
Mostrar UUIDs en lugar de nombres. Esto es útil para seguir a un invitado incluso cuando el invitado se migra o se renombra, o cuando dos invitados tienen el mismo nombre por casualidad.

Esta opción solo se aplica al listar todos los dominios de libvirt (cuando no se especifican las opciones -a o -d).

-v
--verbose
Habilitar mensajes detallados para depuración.
-V
--version
Mostrar el número de versión y salir.
-x
Habilitar el rastreo de llamadas a la API de libguestfs.

ALINEACIÓN RECOMENDADA

Los sistemas operativos anteriores a Windows 2008 y Linux anteriores aproximadamente a 2010 colocan el primer sector de la primera partición en el sector 63, con un tamaño de sector de 512 bytes. Esto significa que la primera partición comienza en el byte 32256. Cuando se utilizan discos de estado sólido (SSD) y algunos sistemas de almacenamiento avanzados, esto puede degradar significativamente el rendimiento. La alineación de 1 MiB (o 4 KiB si el disco tiene un tamaño de sector de 4 KiB) es la preferida.

ESTADO DE SALIDA

0
No se encontraron particiones mal alineadas.
1
Se encontraron particiones mal alineadas.
2
Ocurrió un error.

virt-alignment-scan(1)

virt-alignment-scan - Escanea y reporta la alineación de las particiones de un disco virtual.

SINOPSIS

virt-alignment-scan [OPCIONES] disco-virtual

DESCRIPCIÓN

virt-alignment-scan es una utilidad para escanear un disco virtual (por ejemplo, un archivo qcow2) y reportar la alineación de las particiones. La alineación es importante para el rendimiento de los discos virtuales, especialmente en SSDs.

El programa calcula el desplazamiento de cada partición desde el principio del disco y lo compara con los límites de los sectores lógicos (normalmente 512 bytes) y físicos (normalmente 4096 bytes). Reporta si las particiones están alineadas correctamente o si presentan problemas de alineación.

OPCIONES

-h, --help
Muestra un mensaje de ayuda y sale.
-v, --verbose
Muestra información detallada sobre el escaneo.
-L, --logical-sector-size SECTOR_SIZE
Especifica el tamaño del sector lógico en bytes. El valor predeterminado es 512.
-P, --physical-sector-size SECTOR_SIZE
Especifica el tamaño del sector físico en bytes. El valor predeterminado es 4096.

ESTADO DE SALIDA

0
Escaneo completado correctamente, todas las particiones están alineadas.
1
Escaneo completado, pero se encontraron problemas de alineación.
2
Error al procesar el disco virtual o al analizar las opciones.

ALINEACIÓN RECOMENDADA

Para obtener el mejor rendimiento, especialmente con unidades de estado sólido (SSD), se recomienda que los inicios de las particiones estén alineados con los límites de los sectores físicos. Si el tamaño del sector físico es 4096 bytes, los inicios de las particiones deberían ser múltiplos de 4096. La alineación con el tamaño del sector lógico (512 bytes) es menos crítica, pero sigue siendo una buena práctica.
