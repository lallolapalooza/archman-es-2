virtproxyd(8) Soporte de virtualización virtproxyd(8)

Nombre

virtproxyd - demonio proxy de libvirt

SINOPSIS

virtproxyd [OPCIÓN]...

DESCRIPCIÓN

El programa virtproxyd es un componente de demonio del lado del servidor del sistema de gestión de virtualización libvirt.

Es una de una colección de demonios modulares que reemplazan la funcionalidad proporcionada anteriormente por el demonio monolítico libvirtd.

Este demonio se ejecuta en hosts de virtualización y

  • Escucha en un socket UNIX para proporcionar compatibilidad retroactiva para clientes que anteriormente se conectaban al socket de libvirtd.
  • Opcionalmente escucha en puertos TCP para conexiones de clientes fuera del nodo

Al recibir mensajes RPC de un cliente, virtproxyd los reenviará transparentemente al demonio modular apropiado y, de manera similar, retransmitirá cualquier evento asíncrono.

Por defecto, el demonio virtproxyd escucha solicitudes en un socket de dominio Unix local con la misma ruta utilizada anteriormente por libvirtd. El archivo de configuración se puede usar para indicarle que también escuche en uno o más sockets TCP. También se admite la activación de sockets de systemd para permitirle recibir sockets de escucha preabiertos al iniciar.

Dado que virtproxyd simplemente reenvía mensajes RPC, no tiene estado importante y puede reiniciarse en cualquier momento. Los clientes deben esperar reconectarse después del reinicio.

MODOS DE INICIO DEL DEMONIO

El demonio virtproxyd es capaz de iniciarse en dos modos.

Modo de activación de socket

En hosts con systemd, se inicia en modo de activación de socket y dependerá de systemd para crear y escuchar en los sockets UNIX, y opcionalmente TCP/IP, y pasarlos como descriptores de archivo preabiertos. En este modo, la mayoría de las opciones de configuración relacionadas con sockets en /etc/libvirt/virtproxyd.conf ya no tendrán ningún efecto. Para habilitar sockets TCP o TLS, use:

$ systemctl start virtproxyd-tls.socket

O

$ systemctl start virtproxyd-tcp.socket

Nota: El socket TCP utiliza una conexión TCP simple sin cifrar y, por lo tanto, es inseguro y no debe usarse.

Modo de servicio tradicional

En hosts sin systemd, creará y escuchará en sockets UNIX por sí mismo. También escuchará en sockets TCP/IP, de acuerdo con las opciones listen_tcp y listen_tls en /etc/libvirt/virtproxyd.conf

OPCIONES

-h, --help

Muestra la ayuda de uso de la línea de comandos y luego sale.

-d, --daemon

Ejecuta como demonio y escribe el archivo PID.

-f, --config *ARCHIVO*

Utiliza este archivo de configuración, anulando el valor predeterminado.

-p, --pid-file *ARCHIVO*

Utiliza este nombre para el archivo PID, anulando el valor predeterminado.

-t, --timeout *SEGUNDOS*

Sale después del período de tiempo de espera (en segundos), siempre que no haya conexiones de cliente.

-v, --verbose

Habilita la salida de mensajes detallados.

--version

Muestra la información de la versión y luego sale.

SEÑALES

Al recibir SIGHUP, virtproxyd recargará su configuración.

ARCHIVOS

Cuando se ejecuta como root

•
/etc/libvirt/virtproxyd.conf

El archivo de configuración predeterminado utilizado por virtproxyd, a menos que se anule en la línea de comandos usando la opción -f | --config.

  • /run/libvirt/libvirt-sock
  • /run/libvirt/libvirt-sock-ro

Los sockets que utilizará virtproxyd.

•
/etc/pki/CA/cacert.pem

El certificado de Autoridad Certificadora TLS que utilizará virtproxyd.

•
/etc/pki/libvirt/servercert.pem

El certificado de servidor TLS que utilizará virtproxyd.

•
/etc/pki/libvirt/private/serverkey.pem

La clave privada de servidor TLS que utilizará virtproxyd.

•
/run/virtproxyd.pid

El archivo PID a utilizar, a menos que se anule con la opción -p | --pid-file.

Cuando se ejecuta como no-root

•
$XDG_CONFIG_HOME/libvirt/virtproxyd.conf

El archivo de configuración predeterminado utilizado por virtproxyd, a menos que se anule en la línea de comandos usando la opción -f``|--config``.

•
$XDG_RUNTIME_DIR/libvirt/libvirt-sock

El socket que utilizará virtproxyd.

•
$HOME/.pki/libvirt/cacert.pem

El certificado de Autoridad Certificadora TLS que utilizará virtproxyd.

•
$HOME/.pki/libvirt/servercert.pem

El certificado de servidor TLS que utilizará virtproxyd.

•
$HOME/.pki/libvirt/serverkey.pem

La clave privada de servidor TLS que utilizará virtproxyd.

•
$XDG_RUNTIME_DIR/libvirt/virtproxyd.pid

El archivo PID a utilizar, a menos que se anule con la opción -p``|--pid-file``.

Si $XDG_CONFIG_HOME no está configurado en su entorno, virtproxyd usará $HOME/.config

Si $XDG_RUNTIME_DIR no está configurado en su entorno, virtproxyd usará $HOME/.cache

EJEMPLOS

Para obtener la versión de virtproxyd:

# virtproxyd --version
virtproxyd (libvirt) 11.10.0

Para iniciar virtproxyd, indicándole que se ejecute como demonio y cree un archivo PID:

# virtproxyd -d
# ls -la /run/virtproxyd.pid
-rw-r--r-- 1 root root 6 Jul  9 02:40 /run/virtproxyd.pid

virtproxyd(8)

NAME

virtproxyd, virtproxyd-sock - virtproxyd daemon

SYNOPSIS

virtproxyd [OPTION]...

DESCRIPTION

The virtproxyd daemon is a proxy daemon that forwards requests between libvirt clients and a remote libvirt daemon. This is useful for managing remote virtual machines over an unencrypted network connection, or for managing security policies via a gateway.

The daemon is typically run from systemd service units.

DAEMON STARTUP MODES

The virtproxyd daemon can be started in several ways:

Systemd socket activation
This is the default mode of operation. The daemon is started by systemd in response to a connection on a specific socket. The socket can be a TCP socket or a Unix domain socket. The daemon listens on the socket and forwards connections to the remote libvirt daemon.
Manual startup
The daemon can also be started manually from the command line. In this mode, the daemon listens on a specified address and port, and forwards connections to the remote libvirt daemon.

OPTIONS

The following options are available:

-d, --daemon
Run as a daemon in the background.
-f, --config=FILE
Use configuration file FILE.
-l, --listen=ADDRESS
Listen on ADDRESS. ADDRESS can be a hostname or an IP address. If a port number is specified, it will listen on that port. Otherwise, it will listen on the default port for virtproxyd.
-r, --remote=ADDRESS
Connect to remote libvirt daemon at ADDRESS. ADDRESS can be a hostname or an IP address, optionally followed by a port number. If no port number is specified, the default libvirt port will be used.
-p, --pidfile=FILE
Write PID to FILE.
-v, --verbose
Increase verbosity.
-h, --help
Display help message and exit.

SIGNALS

The following signals are supported:

SIGHUP
Reload configuration.
SIGTERM
Terminate gracefully.

FILES

/etc/libvirt/virtproxyd.conf
Configuration file.
/run/virtproxyd.pid
Default PID file.

EXAMPLES

Start virtproxyd listening on port 1234 and forwarding to remote libvirt daemon at 192.168.1.100:16509:

virtproxyd --listen 1234 --remote 192.168.1.100:16509

Start virtproxyd using a configuration file:

virtproxyd --config /etc/libvirt/virtproxyd.conf
