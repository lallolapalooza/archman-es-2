NOMBRE

VCL - Varnish Configuration Language

DESCRIPCIÓN

El lenguaje VCL es un pequeño lenguaje de dominio específico diseñado para ser utilizado para describir el manejo de solicitudes y las políticas de almacenamiento en caché de documentos para Varnish Cache.

Cuando se carga una nueva configuración, el proceso de gestión de varnishd traduce el código VCL a C y lo compila en un objeto compartido que luego se carga en el proceso del servidor.

Este documento se centra en la sintaxis del lenguaje VCL. Para una descripción completa de la sintaxis y la semántica, con abundantes ejemplos, consulte la documentación en línea en https://www.varnish-cache.org/docs/ .

A partir de Varnish 4.0, cada archivo VCL debe comenzar declarando su versión con el marcador vcl <major>.<minor>; en la parte superior del archivo. Consulte más información sobre esto en Versión a continuación.

Identificadores

Los elementos del lenguaje VCL generalmente se escriben en ASCII.

Los identificadores comienzan con un carácter alfabético ASCII y continúan con cualquier combinación de caracteres alfabéticos o numéricos, - o _.

Para ilustrar, e1xam_p-le es un identificador válido, 1try y a%remainder no lo son.

Conjuntos de caracteres

Mientras que los identificadores solo pueden consistir en este subconjunto de ASCII, las cadenas pueden contener cualquier byte excepto NUL (cero, 0), que marca el final de la cadena. El propio Lenguaje de Configuración de Varnish no se preocupa por la codificación de caracteres de las cadenas. El código VCL que maneja cadenas en diferentes conjuntos de caracteres debe rastrear las codificaciones por sí mismo. Existen VMODs para ayudar con tales tareas (por ejemplo, iconv).

Para ilustrar, "🥬" es una cadena válida que, cuando se interpreta como UTF-8, representa el punto de código U+1F96C (Leafy Green), pero 🥬 no es un identificador válido.

Conjuntos de caracteres en HTTP

No todas las cadenas válidas en VCL son válidas en elementos HTTP distintos del cuerpo (por ejemplo, URLs y encabezados). Por ejemplo, los valores de los campos de encabezado HTTP no pueden contener caracteres de control; véase también la característica ref_param_feature de validate_headers.

Operadores

Los siguientes operadores están disponibles en VCL:

=
Operador de asignación.
+, -, *, /, %
Matemáticas básicas con valores numéricos.
+=, -=, *=, /=
Operador de asignación e incremento/decremento/multiplicación/división.

Para cadenas, += concatena.

(, )
Evaluar por separado.
==, !=, <, >, <=, >=
Comparaciones
~, !~
Coincidencia / no coincidencia. Se puede usar con expresiones regulares o ACL.
!
Negación.
&& / ||
Lógicos y/o.

Condicionales

VCL tiene sentencias if y else. La lógica anidada se puede implementar con la sentencia elseif (elsif/elif/else if son equivalentes).

Tenga en cuenta que no hay bucles ni iteradores de ningún tipo en VCL.

Variables

VCL realiza la mayor parte del trabajo examinando, set'eando y unset'eando variables:

if (req.url == "/mistyped_url.html") {
    set req.url = "/correct_url.html";
    unset req.http.cookie;
}

Existen obvias limitaciones a lo que se puede hacer, por ejemplo, no tiene sentido unset req.url; - una solicitud debe tener algún tipo de URL para ser válida, y de manera similar, intentar manipular una respuesta del backend cuando no hay ninguna (aún) no tiene sentido. El compilador de VCL detectará tales errores.

Las variables tienen tipos. La mayoría son CADENAS (STRINGS), y cualquier cosa en VCL se puede convertir en una CADENA, pero algunas variables tienen tipos como DURATION, IP, etc.

Al establecer dichas variables, el lado derecho del signo igual debe tener el tipo de variable correcto; no puedes asignar una CADENA a una variable de tipo NÚMERO, incluso si la cadena es "42".

Las funciones de conversión explícita están disponibles en vmod_std(3).

Para el álbum completo de variables VCL, consulte: vcl-var(7).

Cadenas

Las cadenas básicas están entre comillas dobles "...", y no pueden contener saltos de línea. Las cadenas largas están entre {"..."} o """...""". Pueden contener cualquier carácter, incluidas comillas dobles simples ", saltos de línea y otros caracteres de control, excepto el carácter NUL (0x00).

Booleanos

Los booleanos pueden ser true o false. Además, en un contexto booleano, algunos tipos de datos se evaluarán como true o false dependiendo de su valor.

Los tipos de cadena se evaluarán como false si no están establecidos. Esto permite comprobaciones del tipo if (req.http.opthdr) {} para probar si existe un encabezado, incluso si está vacío, mientras que if (req.http.opthdr == "") {} no distingue si el encabezado no existe o si está vacío.

Los tipos de backend se evaluarán como false si no tienen un backend asignado; los tipos enteros se evaluarán como false si su valor es cero; los tipos de duración se evaluarán como false si su valor es igual o inferior a cero.

Tiempo

VCL tiene tiempo. Se puede agregar una duración a un tiempo para crear otro tiempo. En contexto de cadena, devuelven una cadena formateada en formato RFC1123, por ejemplo, Sun, 06 Nov 1994 08:49:37 GMT.

La palabra clave now devuelve una noción del tiempo actual, que se mantiene consistente durante las invocaciones de subrutinas VCL, por lo que durante la ejecución de una subrutina de estado VCL (vcl_* {}), incluidas todas las subrutinas definidas por el usuario que se llaman, now siempre devuelve el mismo valor.

Duraciones

Las duraciones se definen por un número seguido de una unidad. El número puede incluir una parte fraccionaria, por ejemplo, 1.5s. Las unidades admitidas son:

ms
milisegundos
s
segundos
m
minutos
h
horas
d
días
w
semanas
y
años

En contexto de cadena, devuelven una cadena con su valor redondeado a 3 decimales y sin la unidad, por ejemplo, 1.500.

Enteros

Ciertos campos son enteros, se usan como se espera. En contexto de cadena, devuelven una cadena, por ejemplo, 1234.

Números reales

VCL entiende los números reales. En contexto de cadena, devuelven una cadena con su valor redondeado a 3 decimales, por ejemplo, 3.142.

Expresiones regulares

Varnish utiliza expresiones regulares compatibles con Perl (PCRE). Para una descripción completa, consulte la página del manual pcre(3).

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Para enviar flags al motor PCRE, como para hacer coincidencia sin distinción entre mayúsculas y minúsculas, agregue el flag entre paréntesis después de un signo de interrogación, de esta manera:

# Si el host NO es example punto com.
if (req.http.host !~ "(?i)example\.com$") {
    ...
}

Declaración include

Para incluir un archivo VCL en otro archivo, use la palabra clave include:

include "foo.vcl";

El archivo incluido puede especificarse de la siguiente manera:

  • Si la ruta comienza con '/', es una ruta absoluta.
  • Si la ruta comienza con './', es relativa al archivo VCL que la incluye.
  • De lo contrario, es una ruta relativa buscada en uno de los directorios vcl_path.

Opcionalmente, la palabra clave include puede tomar un flag +glob para incluir todos los archivos que coincidan con un patrón glob:

include +glob "/etc/varnish/example.org/*.vcl";

Tenga en cuenta que la opción +glob solo se puede usar con rutas absolutas y rutas relativas que comiencen con './', lo que significa que las inclusiones +glob no se pueden buscar en los directorios vcl_path.

Declaración import

La declaración import se utiliza para cargar módulos Varnish (VMODs).

Ejemplo:

import std;
sub vcl_recv {
    std.log("foo");
}

Comentarios

Las líneas individuales de VCL se pueden comentar usando // o #. Los bloques de varias líneas se pueden comentar con /*bloque*/.

Ejemplo:

sub vcl_recv {
    // Línea única de VCL comentada.
    # Otra forma de comentar una línea única.
    /*
        Bloque de varias líneas de VCL comentada.
    */
}

Backends y sondas de salud

Consulte vcl-backend(7) y vcl-probe(7)

Lista de control de acceso (ACL)

Una declaración de Lista de Control de Acceso (ACL) crea e inicializa una lista de control de acceso con nombre que luego puede usarse para coincidir con direcciones de clientes:

acl localnetwork {
    "localhost";    # yo mismo
    "192.0.2.0"/24; # y todos en la red local
    ! "192.0.2.23"; # excepto el router de acceso telefónico
}

Si una entrada de ACL especifica un nombre de host que Varnish no puede resolver, coincidirá con cualquier dirección con la que se compare. En consecuencia, si va precedido por un signo de negación, rechazará cualquier dirección con la que se compare, lo que puede no ser lo que pretendía. Sin embargo, si la entrada está entre paréntesis, simplemente se ignorará si el nombre del host no se puede resolver.

Para comparar una dirección IP con una ACL, simplemente use el operador de coincidencia:

if (client.ip ~ localnetwork) {
    return (pipe);
}

Las ACL tienen flags de características que se pueden establecer o borrar para cada ACL individualmente:

  • +log - Emite un registro Acl en VSL para indicar si se encontró una coincidencia o no.
  • +table - Implementa la ACL con una tabla en lugar de código compilado. Esto se ejecuta un poco más lento, pero compila ACL grandes mucho más rápido.
  • -pedantic - Permite que las máscaras cubran bits de host distintos de cero. Esto permite que lo siguiente funcione:
acl foo -pedantic +log {
    "firewall.example.com" / 24;
}

Sin embargo, si el nombre se resuelve tanto para IPv4 como para IPv6, aún obtendrá un error.

•
-fold - No pliega superredes de ACL ni redes adyacentes.

Con este parámetro establecido en activado (predeterminado), las ACL se optimizan de modo que se omitan las subredes contenidas en otras entradas (por ejemplo, si 1.2.3.0/24 forma parte de la ACL, no se agregará una entrada para 1.2.3.128/25) y las entradas adyacentes se pliegan (por ejemplo, si se agregan tanto 1.2.3.0/25 como 1.2.3.128/25, se pliegan a 1.2.3.0/24).

Los saltos y pliegues en las entradas de VCL se muestran como advertencias durante la compilación de VCL, ya que las entradas de VCL se procesan en orden.

El registro bajo la etiqueta VCL_acl puede cambiar con este parámetro habilitado: Las coincidencias en entradas de subredes omitidas ahora se registran como coincidencias en la entrada de superred correspondiente. Las coincidencias en entradas plegadas se registran con una máscara de red más corta que puede no estar contenida en la ACL original definida en VCL. Dichas entradas de registro se marcan con fixed: folded.

Las entradas de ACL negadas nunca se pliegan.

Objetos VCL

Se puede instanciar un objeto VCL con la palabra clave new:

sub vcl_init {
    new b = directors.round_robin();
    b.add_backend(node1);
}

El nombre del objeto (b en el ejemplo) debe ser un Identificador válido <Identifiers>.

Esto solo está disponible en vcl_init.

Subrutinas

Una subrutina se utiliza para agrupar código para legibilidad o reutilización:

sub pipe_if_local {
    if (client.ip ~ localnetwork) {
        return (pipe);
    }
}

Las subrutinas en VCL no toman argumentos ni devuelven valores. Las subrutinas integradas tienen nombres que comienzan con vcl_, que está reservado.

Para llamar a una subrutina, use la palabra clave call seguida del nombre de la subrutina:

sub vcl_recv {
    call pipe_if_local;
}

Declaraciones return

La ejecución continua de la subrutina vcl_* finaliza cuando se realiza una declaración return(<acción>).

La <acción> especifica cómo debe proceder la ejecución. El contexto define qué acciones están disponibles.

Es posible salir de una subrutina que no forma parte de las integradas usando una simple declaración return sin especificar una acción. Sale de la subrutina sin pasar a un estado diferente:

sub filter_cookies {
    if (!req.http.cookie) {
        return;
    }
    # filtrado complejo de cookies
}

Múltiples subrutinas

Si se definen varias subrutinas con el nombre de una de las integradas, se concatenan en el orden en que aparecen en el código fuente.

La VCL integrada distribuida con Varnish se concatenará implícitamente cuando se compile la VCL.

Funciones

Las siguientes funciones integradas están disponibles:

ban(STRING)

Obsoleto. Consulte std.ban().

La función ban() es idéntica a std.ban(), pero no proporciona informes de errores.

hash_data(input)

Agrega una entrada a la entrada hash. En la VCL integrada, se llama a hash_data() en el host y la URL de la solicitud. Disponible en vcl_hash.

synthetic(STRING)

Prepara un cuerpo de respuesta sintético que contiene la STRING. Disponible en vcl_synth y vcl_backend_error.

Idéntico a set resp.body / set beresp.body.

regsub(str, regex, sub)

Devuelve una copia de str con la primera ocurrencia de la expresión regular regex reemplazada por sub. Dentro de sub, \0 (que también se puede escribir \&) se reemplaza con la cadena completa coincidente, y \n se reemplaza con el contenido del subgrupo n en la cadena coincidente.

regsuball(str, regex, sub)

Igual que regsub(), pero reemplaza todas las ocurrencias.

Para convertir o castear valores VCL entre tipos de datos, utilice las funciones disponibles en el VMOD std.

VERSIONAMIENTO

Varias versiones de la sintaxis VCL pueden coexistir dentro de ciertas limitaciones.

La versión de la sintaxis VCL al principio del archivo VCL especificado con -f establece el límite estricto que no se puede exceder en ninguna parte, y selecciona la versión apropiada de la VCL integrada.

Eso significa que nunca puede incluir vcl 9.1; desde vcl 8.7;, pero lo contrario puede ser posible, en la medida en que el compilador lo soporte.

Los archivos incluidos a través de include no necesitan tener un vcl X.Y;, pero puede ser una buena idea hacerlo de todos modos, para no tener sorpresas en el futuro. La versión de sintaxis establecida en un archivo incluido solo se aplica a ese archivo y a cualquier archivo que incluya, a menos que estos establezcan su propia versión de sintaxis VCL.

La versión de Varnish a la que pertenece este archivo admite la sintaxis 4.0 y 4.1.

NOMBRE

vcl - Varnish Configuration Language

DESCRIPCIÓN

VCL es el lenguaje utilizado para configurar el comportamiento de Varnish Cache. Define cómo Varnish debe manejar las solicitudes entrantes, cómo debe interactuar con los backends y cómo debe construir las respuestas que se enviarán a los clientes.

VCL es un lenguaje de alto nivel diseñado para ser legible y fácil de usar para tareas de proxy y caché. Utiliza una sintaxis similar a C pero con características específicas para el manejo de tráfico web.

Las directivas principales en VCL incluyen:

  • vcl_recv: Se ejecuta cuando Varnish recibe una solicitud del cliente. Aquí se determina la acción a tomar, como buscar en la caché, enviar al backend o rechazar la solicitud.
  • vcl_pipe: Permite que la conexión entre el cliente y el backend se mantenga abierta sin inspección por parte de Varnish.
  • vcl_pass: Envía la solicitud al backend y espera una respuesta, la cual se reenvía al cliente sin ser cacheadable.
  • vcl_hash: Determina la clave de caché para una solicitud dada.
  • vcl_purge: Define cómo manejar las solicitudes de purga (eliminación de objetos de la caché).
  • vcl_backend_fetch: Se ejecuta antes de intentar obtener un objeto de un backend.
  • vcl_backend_response: Se ejecuta después de recibir una respuesta de un backend. Aquí se puede decidir si la respuesta debe ser cacheada o modificada.
  • vcl_deliver: Se ejecuta antes de enviar la respuesta final al cliente.

VCL también soporta:

  • Definición de backends y grupos de backends (directorios).
  • Módulos Varnish (VMODs) que extienden la funcionalidad de VCL.
  • Variables y funciones personalizadas.
  • Manejo de subrutinas y directorios.

VERSIÓN

La versión de VCL está estrechamente ligada a la versión de Varnish Cache. Las características y sintaxis pueden variar entre versiones.
