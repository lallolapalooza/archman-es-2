virt-admin(1) Soporte de Virtualización virt-admin(1)

Nombre

virt-admin - interfaz de administración del demonio

SINOPSIS

virt-admin [OPCIÓN]... [CADENA_COMANDO]

virt-admin [OPCIÓN]... COMANDO [ARG]...

DESCRIPCIÓN

El programa virt-admin es la interfaz principal de administración para modificar la configuración del demonio libvirt en tiempo de ejecución, cambiar el comportamiento del demonio, así como para monitorear y administrar todos los clientes conectados al demonio.

La estructura básica de la mayoría de los usos de virt-admin es:

virt-admin [OPCIÓN]... <comando> [ARG]...

Donde comando es uno de los comandos listados a continuación. Cualquier comando que comience con # se trata como un comentario y se ignora silenciosamente; todos los demás comandos no reconocidos se diagnostican.

El programa virt-admin se puede utilizar para ejecutar un COMANDO proporcionando el comando y sus argumentos en la línea de comandos de la shell, o una CADENA_COMANDO que es un único argumento de shell que consta de múltiples acciones COMANDO y sus argumentos unidos con espacios y separados por puntos y comas o saltos de línea entre comandos, donde los pares de barra invertida-salto de línea sin comillas se omiten. Dentro de CADENA_COMANDO, virt-admin entiende las mismas escapadas simples, dobles y de barra invertida que la shell, aunque debes agregar otra capa de escapada de shell al crear el argumento único de shell, y cualquier palabra que comience con # sin comillas inicia un comentario que termina en un salto de línea. Si no se proporciona ningún comando en la línea de comandos, virt-admin iniciará un intérprete mínimo esperando tus comandos, y el comando quit saldrá del programa.

El programa virt-admin entiende las siguientes OPCIONES.

-c, --connect URI

Conéctate a la URI especificada, como si fuera con el comando connect, en lugar de la conexión predeterminada. Ver NOTAS.

-d, --debug NIVEL

Habilita mensajes de depuración en el NIVEL entero y superiores. NIVEL puede variar de 0 a 4 (predeterminado). Ver la documentación de la variable de entorno VIRT_ADMIN_DEBUG a continuación para la descripción de cada NIVEL.

-h, --help

Ignora todos los demás argumentos y actúa como si se hubiera dado el comando help en su lugar.

-l, --log ARCHIVO

Envía detalles de registro al ARCHIVO.

-q, --quiet

Evita mensajes de información adicionales.

-v, --version[=short]

Ignora todos los demás argumentos e imprime la versión de la biblioteca libvirt de la que proviene virt-admin.

-V, --version=long

Ignora todos los demás argumentos e imprime la versión de la biblioteca libvirt de la que proviene virt-admin.

NOTAS

virt-admin soporta tanto el demonio monolítico libvirtd como los demonios modulares https://libvirt.org/daemons.html#modular-driver-daemons cual sea que esté en uso por tu sistema. El URI de conexión utilizado con -c/--connect o el comando connect se basa en el nombre del demonio controlado, por ejemplo: virtqemud:///system, libvirtd:///system.

Ejecutar virt-admin requiere privilegios de root al comunicarse con la instancia del sistema de un demonio (URI que termina en /system) debido a los canales de comunicación utilizados para hablar con el demonio.

COMANDOS GENÉRICOS

Los siguientes comandos son genéricos.

help

Sintaxis:

help [comando-o-grupo]

Esto lista cada uno de los comandos de virt-admin. Cuando se usa sin opciones, se enumeran todos los comandos, uno por línea, agrupados en categorías relacionadas, mostrando la palabra clave para cada grupo.

Para mostrar información detallada de un comando específico, usa su nombre como opción.

quit, exit

Sintaxis:

quit
exit

sale de esta terminal interactiva

version

Sintaxis:

version

imprimirá la información de la versión sobre de qué biblioteca libvirt se compiló este cliente. A diferencia del cliente virsh, la salida ya incluye la versión del demonio.

Ejemplo:

$ virt-admin version
Compilado contra la biblioteca: libvirt 1.2.21
Usando la biblioteca: libvirt 1.2.21
Ejecutando contra el demonio: 1.2.20

cd

Sintaxis:

cd [directorio]

Cambiará el directorio actual a directorio. El directorio predeterminado para el comando cd es el directorio de inicio o, si no hay una variable HOME en el entorno, el directorio raíz.

Este comando solo está disponible en modo interactivo.

pwd

Sintaxis:

pwd

Imprimirá el directorio actual.

connect

Sintaxis:

connect [URI]

(Re)-Conéctate al servidor de administración de un demonio. El parámetro URI especifica cómo conectarse al servidor de administración. Si se establecieron LIBVIRT_ADMIN_DEFAULT_URI o uri_default (ver abajo), connect se emite automáticamente cada vez que se ejecuta un comando que requiere una conexión activa. Ten en cuenta que esto solo se aplica si no hay conexión en absoluto o si hay una inactiva.

Ver NOTAS sobre cómo elegir la URI correcta correspondiente a un demonio libvirt.

Para encontrar la URI utilizada actualmente, verifica el comando uri documentado a continuación.

uri

Sintaxis:

uri

Imprime la URI canónica del servidor de administración, puede ser útil en modo shell. Si no se especificó ninguna uri, ni se establecieron la variable de entorno LIBVIRT_ADMIN_DEFAULT_URI ni la opción uri_default (libvirt-admin.conf), se usa libvirtd:///system.

COMANDOS DEL DEMONIO

Los siguientes comandos permiten monitorear el estado del demonio así como cambiar directamente su configuración interna.

server-list

Sintaxis:

server-list

Lista todos los servidores administrables contenidos dentro del demonio al que el cliente está actualmente conectado.

daemon-log-filters

Sintaxis:

daemon-log-filters [--filters cadena]

Cuando se ejecuta sin argumentos, esto devuelve el conjunto de filtros de registro definidos actualmente. Proporcionar un argumento hará que el comando defina un nuevo conjunto de filtros de registro.

•
--filters

Define un nuevo conjunto de filtros de registro donde múltiples filtros están delimitados por espacios. Cada filtro debe cumplir con la forma descrita en detalle por /etc/libvirt/libvirtd.conf (sección 'Logging filters').

Ejemplo:

Para definir un filtro que suprima todos los mensajes DEBUG de 'virObjectUnref', por ejemplo, usa lo siguiente:

``` $ virt-admin daemon-log-filters --filters "1:virObjectUnref" ```
"> 
$ virt-admin daemon-log-filters "4:util.object"

(Tenga en cuenta el símbolo '.' que se puede usar para filtros más detallados adaptados a módulos específicos, en contraste, para afectar a todo el directorio que contiene varios módulos, esto se convertiría en "4:util"):

daemon-log-outouts

Sintaxis:

daemon-log-outputs [--outputs string]

Cuando se ejecuta sin argumentos, devuelve el conjunto de salidas de registro actualmente definido. Proporcionar un argumento hará que el comando defina un nuevo conjunto de salidas de registro.

•
--outputs

Define un nuevo conjunto de salidas de registro donde varias salidas están delimitadas por espacios. Cada salida debe cumplir con el formato descrito en detalle por /etc/libvirt/libvirtd.conf (sección 'Logging outputs').

Ejemplo:

Para reemplazar la configuración actual de las salidas de registro con una que escribe en un archivo mientras registra solo errores, se podría usar lo siguiente:

$ virt-admin daemon-log-outputs "4:file:<absolute_path_to_the_file>"

Para definir varias salidas a la vez, deben estar delimitadas por espacios:

$ virt-admin daemon-log-outputs "4:stderr 2:syslog:<msg_ident>"

daemon-timeout

Sintaxis:

daemon-timeout [--timeout] NUM

Establece el tiempo de espera del demonio al valor del argumento '--timeout'. Use --timeout 0 para deshabilitar el apagado automático del demonio.

daemon-shutdown

Sintaxis:

daemon-shutdown [--preserve]

Instruye al demonio para que salga de forma controlada. Si se proporciona la bandera --preserve, guardará el estado de la misma manera que se haría en un apagado del sistema operativo anfitrión (demonios privilegiados) o al salir de una sesión de inicio de sesión (demonios no privilegiados).

COMANDOS DE SERVIDOR

Los siguientes comandos manipulan la configuración interna del servidor del demonio. El servidor se especifica por su nombre.

server-threadpool-info

Sintaxis:

server-threadpool-info server

Recupera los atributos del pool de hilos del servidor. Estos atributos incluyen:

  • minWorkers como el límite inferior para el número de hilos activos,
  • maxWorkers como el límite superior para el número de hilos activos,
  • nWorkers como el número actual de hilos en el pool de hilos,
  • freeWorkers como el número actual de hilos disponibles para una tarea,
  • prioWorkers como el número actual de hilos prioritarios en el pool de hilos, y
  • jobQueueDepth como la profundidad actual de la cola de trabajos del pool de hilos.

Antecedentes

Cada servidor demonio utiliza un pool de hilos para realizar tareas solicitadas por los clientes conectados a él. Cada vez que una solicitud de cliente llega al servidor, comprueba si hay un hilo disponible para realizar la tarea dada o si debe crear un nuevo hilo para el trabajo (en lugar de ser destruido, el hilo queda libre una vez que la tarea finaliza). Sin embargo, la creación de nuevos hilos solo es posible cuando el número actual de hilos está todavía por debajo del límite superior configurado. Además de estos hilos 'estándar', un pool de hilos contiene un conjunto especial de hilos llamados hilos prioritarios. Su propósito es realizar tareas que, a diferencia de las tareas realizadas por los hilos normales, están bajo el control total de libvirt y libvirt garantiza que tal tarea no se cuelgue, por lo que siempre finalizará. Un ejemplo de tal tarea sería destruir un dominio:

$ virsh destroy <domain>.

server-threadpool-set

Sintaxis:

server-threadpool-set server [--min-workers count] [--max-workers count] [--priority-workers count]

Cambia los atributos del pool de hilos en un servidor. Solo una fracción de todos los atributos descritos en server-threadpool-info es compatible con el setter.

  • --min-workers

    El límite inferior para el número de hilos activos en un pool de hilos.

  • --max-workers

    El límite superior para el número de hilos activos en un pool de hilos. Si se utiliza en combinación con la opción --min-workers, el valor del límite superior debe ser mayor que el valor del límite inferior, de lo contrario, el comando resultará en un error.

  • --priority-workers

    El número actual de hilos prioritarios activos en un pool de hilos.

server-clients-info

Sintaxis:

server-clients-info server

Obtiene información sobre la configuración actual de los límites relacionados con las conexiones de nuevos clientes. Esta información incluye los límites para el número máximo de clientes conectados al server, el número máximo de clientes en espera de autenticación, para poder conectarse al servidor, así como los valores actuales en tiempo de ejecución, más específicamente, el número actual de clientes conectados al server y el número actual de clientes en espera de autenticación.

Ejemplo:

# virt-admin server-clients-info libvirtd
nclients_max        : 120
nclients            : 3
nclients_unauth_max : 20
nclients_unauth     : 0

server-clients-set

Sintaxis:

server-clients-set server [--max-clients count] [--max-unauth-clients count]

Establece nuevos límites relacionados con clientes en el server.

  • --max-clients

    Cambia el límite superior del número máximo general de clientes conectados al server al valor count. El valor de este límite siempre debe ser mayor que el valor de --max-unauth-clients.

  • --max-unauth-clients

    Cambia el límite superior del número máximo de clientes en espera de autenticación, para poder conectarse al server, al valor count. El valor de este límite siempre debe ser inferior al valor de --max-clients.

server-update-tls

Sintaxis:

server-update-tls server

Actualiza el contexto tls en el server.

•
server

Servidores disponibles en un demonio. Actualmente solo admite 'libvirtd' o 'virtproxyd'.

COMANDOS DE CLIENTE

Los siguientes comandos proporcionan gestión y monitorización de clientes conectados a uno de los servidores disponibles del demonio. Los clientes se especifican por su ID numérico, que se obtiene listando todos los clientes conectados a un servidor especificado (ver comando client-list).

client-list

Sintaxis:

client-list server

Imprime una tabla que muestra la lista de clientes conectados al <server>, proporcionando también información sobre el tipo de transporte utilizado en la conexión del cliente (los transportes admitidos incluyen unix, tcp y tls), así como información sobre el tiempo de conexión del cliente (se utiliza la hora local del sistema).

client-info

Sintaxis:

client-info server client

Recupera información de identidad sobre el client desde el server. Los atributos devueltos pueden variar dependiendo del transporte de conexión utilizado. Los atributos dependientes del transporte incluyen el PID del proceso cliente local, UID, nombre de usuario y nombre de grupo, así como la dirección del socket del par remoto, ver Ejemplos a continuación.

Por otro lado, los atributos independientes del transporte incluyen el contexto SELinux del cliente (si está habilitado en el host) y el nombre de usuario SASL (si la autenticación SASL está habilitada dentro del demonio).

Ejemplos:

# virt-admin client-info libvirtd 1
id             : 1
connection_time: 2016-05-03 13:27:04+0200
transport      : unix
readonly       : yes
unix_user_id   : 0
unix_user_name : root
unix_group_id  : 0
unix_group_name: root
unix_process_id: 10201
# virt-admin client-info libvirtd 2
id             : 2
connection_time: 2016-05-03 13:30:33+0200
transport      : tcp
readonly       : no
sock_addr      : 127.0.0.1:57060

client-disconnect

Sintaxis:

client-disconnect server client

Cierra una conexión originada por el client. El argumento server especifica el nombre del servidor al que el client está actualmente conectado.

ENTORNO

Las siguientes variables de entorno se pueden establecer para alterar el comportamiento de virt-admin

•
VIRT_

ENVIRONMENT

ADMIN_DEBUG=<0 to 4>

Activa la depuración detallada de los comandos virt-admin. Los niveles válidos son:

  • VIRT_ADMIN_DEBUG=0

    DEBUG - Se registran mensajes de TODOS los niveles.

  • VIRT_ADMIN_DEBUG=1

    INFO - Registra mensajes de los niveles INFO, NOTICE, WARNING y ERROR.

  • VIRT_ADMIN_DEBUG=2

    NOTICE - Registra mensajes de los niveles NOTICE, WARNING y ERROR.

  • VIRT_ADMIN_DEBUG=3

    WARNING - Registra mensajes de los niveles WARNING y ERROR.

  • VIRT_ADMIN_DEBUG=4

    ERROR - Solo se registran mensajes del nivel ERROR.

  • VIRT_ADMIN_LOG_FILE=``LOGFILE``

    El archivo donde se registrarán los mensajes de depuración de virt-admin.

  • LIBVIRT_ADMIN_DEFAULT_URI

    El demonio cuyo servidor de administración se conectará por defecto. Establezca esto a una URI, en el mismo formato que acepta la opción connect. Esto anula la URI predeterminada establecida en cualquier archivo de configuración del cliente.

  • VIRT_ADMIN_HISTSIZE

    El número de comandos que se recordarán en el historial de comandos. El valor predeterminado es 500.

  • LIBVIRT_DEBUG=LEVEL

    Activa la depuración detallada de todas las llamadas a la API de libvirt. Los niveles válidos son:

  • LIBVIRT_DEBUG=1

    Mensajes del nivel DEBUG o superior.

  • LIBVIRT_DEBUG=2

    Mensajes del nivel INFO o superior.

  • LIBVIRT_DEBUG=3

    Mensajes del nivel WARNING o superior.

  • LIBVIRT_DEBUG=4

    Mensajes del nivel ERROR o superior.

Para más información sobre las opciones de depuración, consulte https://libvirt.org/logging.html
