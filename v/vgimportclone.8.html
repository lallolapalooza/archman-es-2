NOMBRE

vgimportclone — Importar un VG desde PVs clonados

SINOPSIS

vgimportclone args_posicionales
[ args_opcionales ]

DESCRIPCIÓN

vgimportclone importa un VG desde PVs duplicados, p.ej. creados por una instantánea de hardware de PVs existentes.

Un VG duplicado no puede ser utilizado hasta que se haga coexistir con el VG original. vgimportclone renombra el VG asociado con los PVs especificados y cambia los UUIDs de VG y PV asociados.

USO

vgimportclone PV ...

[ -i|--import ]
[ -n|--basevgname Cadena ]
[ --importdevices ]
[ OPCIONES_COMUNES ]

OPCIONES

-n|--basevgname Cadena
Por defecto, el VG de la instantánea se renombrará al nombre original más un sufijo numérico para evitar nombres duplicados (p.ej. 'test_vg' se renombraría a 'test_vg1'). Esta opción anulará el nombre base del VG que se usa para todos los renombramientos de VG. Si ya existe un VG con el nombre especificado, se añadirá un sufijo numérico (como en el ejemplo anterior) para hacerlo único.
--commandprofile Cadena
El perfil de comando a usar para la configuración del comando. Ver lvm.conf(5) para más información sobre perfiles.
--config Cadena
Configuraciones para el comando. Estas anulan los ajustes de lvm.conf(5). El argumento Cadena usa el mismo formato que lvm.conf(5), o puede usar la sintaxis de sección/campo. Ver lvm.conf(5) para más información sobre la configuración.
-d|--debug ...
Establece el nivel de depuración. Repetir de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados aparecerán como ausentes. Esta opción puede repetirse, o acepta una lista de dispositivos separada por comas. Esto anula el archivo de dispositivos.
--devicesfile Cadena
Un archivo que lista los dispositivos que LVM debe usar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula los ajustes devices/devicesfile y devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si se establece en no, el comando no intentará usar device-mapper. Para pruebas y depuración.
-h|--help
Muestra el texto de ayuda.
-i|--import
Importar VGs exportados. De lo contrario, los VGs que han sido exportados no serán modificados (ni sus PVs asociados).
--importdevices
Añade dispositivos al archivo de dispositivos.
--journal Cadena
Registra información en el journal de systemd. Esta información es adicional a la habilitada por el ajuste log/journal de lvm.conf. command: registra información sobre el comando. output: registra la salida por defecto del comando. debug: registra la depuración completa del comando.
--lockopt Cadena
Se utiliza para pasar opciones para casos especiales a lvmlockd. Ver lvmlockd(8) para más información.
--longhelp
Muestra el texto de ayuda detallado.
--nohints
No usar el archivo de pistas para localizar dispositivos para PVs. Un comando puede leer más dispositivos para encontrar PVs cuando no se usan pistas. El comando seguirá realizando la invalidación estándar del archivo de pistas donde sea apropiado.
--nolocking
Desactiva el bloqueo. Usar con precaución, comandos concurrentes pueden producir resultados incorrectos.
--profile Cadena
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
-q|--quiet ...
Suprime la salida y los mensajes de registro. Anula --debug y --verbose. Repetir una vez para también suprimir cualquier solicitud con respuesta 'no'.
-t|--test
Ejecuta en modo de prueba. Los comandos no actualizarán los metadatos. Esto se implementa deshabilitando toda escritura de metadatos pero devolviendo éxito a la función que llama. Esto puede llevar a mensajes de error inusuales en operaciones de múltiples etapas si una herramienta depende de leer metadatos que cree que han cambiado pero no lo han hecho.
-v|--verbose ...
Establece el nivel detallado. Repetir de 1 a 4 veces para aumentar el detalle de los mensajes enviados a stdout y stderr.
--version
Muestra la información de la versión.
-y|--yes
No solicitar confirmación interactivamente, sino asumir siempre la respuesta sí. Usar con extrema precaución. (Para un no automático, ver -qq.)

VARIABLES

PV
Nombre del Volumen Físico, una ruta de dispositivo bajo /dev. Para comandos que gestionan extensiones físicas, un argumento posicional PV generalmente acepta un sufijo que indica un rango (o múltiples rangos) de extensiones físicas (PEs). Cuando se omite la primera PE, por defecto es el inicio del dispositivo, y cuando se omite la última PE, por defecto es el final.
Rango de inicio y fin (inclusivo): PV[:PE-PE] ...
Rango de inicio y longitud (contando desde 0): PV[:PE+PE] ...
Cadena
Ver la descripción de la opción para obtener información sobre el contenido de la cadena.
Tamaño[UNIDAD]
Tamaño es un número de entrada que acepta una unidad opcional. Las unidades de entrada siempre se tratan como valores base dos, independientemente de mayúsculas/minúsculas, por ejemplo, 'k' y 'K' se refieren a 1024. La unidad de entrada por defecto se especifica con una letra, seguida de |UNIDAD. UNIDAD representa otras unidades de entrada posibles: b|B es bytes, s|S es sectores de 512 bytes, k|K es KiB, m|M es MiB, g|G es GiB, t|T es TiB, p|P es PiB, e|E es EiB. (Esto no debe confundirse con el control de salida --units, donde las letras mayúsculas significan múltiplos de 1000.)

EJEMPLOS

Un VG original "vg00" tiene PVs "/dev/sda" y "/dev/sdb". Los PVs correspondientes de una instantánea de hardware son "/dev/sdc" y "/dev/sdd". Renombrar el VG asociado con "/dev/sdc" y "/dev/sdd" de "vg00" a "vg00_snap" (y cambiar los UUIDs asociados).
vgimportclone --basevgname vg00_snap /dev/sdc /dev/sdd
