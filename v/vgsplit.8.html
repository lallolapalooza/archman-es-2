VGSPLIT(8) Manual del Administrador del Sistema VGSPLIT(8)

NOMBRE

vgsplit — Mueve volúmenes físicos a un grupo de volúmenes nuevo o existente

SINOPSIS

vgsplit argumentos_opcionales argumentos_posicionales
[ argumentos_opcionales ]

DESCRIPCIÓN

vgsplit mueve uno o más PVs de un VG de origen (el primer argumento VG) a un VG de destino (el segundo argumento VG). Los PV(s) a mover se nombran después de los VG de origen y destino, o se nombra un LV, en cuyo caso se mueven los PVs subyacentes del LV.

Si el VG de destino no existe, se crea un nuevo VG (se pueden usar argumentos de comando para especificar las propiedades del nuevo VG, ver también vgcreate(8)).

Los LVs no se pueden dividir entre VGs; cada LV debe estar completamente en los PVs del VG de origen o destino.

vgsplit solo puede mover PVs completos. (Ver pvmove(8) para mover parte de un PV.)

USO

Divide un VG por PVs especificados.

vgsplit VG VG PV ...

[ OPCIONES_COMUNES ]

—

Divide un VG por PVs en un LV especificado.

vgsplit -n|--nombre LV VG VG

[ OPCIONES_COMUNES ]

—

OPCIONES

--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Determina la política de asignación cuando un comando necesita asignar Extents Físicos (PEs) del VG. Cada VG y LV tiene una política de asignación que puede ser cambiada con vgchange/lvchange, o anulada en la línea de comandos. normal aplica reglas de sentido común, como no colocar franjas paralelas en el mismo PV. inherit aplica la política del VG a un LV. contiguous requiere que los PEs nuevos se coloquen adyacentes a los PEs existentes. cling coloca los PEs nuevos en el mismo PV que los PEs existentes en la misma franja del LV. Si hay PEs suficientes para una asignación, pero normal no los usa, anywhere los usará incluso si reduce el rendimiento, por ejemplo, colocando dos franjas en el mismo PV. Los argumentos posicionales de PV opcionales en la línea de comandos también se pueden usar para limitar los PVs que el comando usará para la asignación. Ver lvm(8) para más información sobre la asignación.
-A|--autobackup s|n
Especifica si los metadatos deben ser respaldados automáticamente después de un cambio. ¡Se recomienda encarecidamente habilitar esto! Ver vgcfgbackup(8) para más información.
--commandprofile String
El perfil de comando a usar para la configuración del comando. Ver lvm.conf(5) para más información sobre los perfiles.
--config String
Configuración para el comando. Estas anulan la configuración de lvm.conf(5). El argumento String usa el mismo formato que lvm.conf(5), o puede usar sintaxis de sección/campo. Ver lvm.conf(5) para más información sobre la configuración.
-d|--debug ...
Establece el nivel de depuración. Repetir de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción puede repetirse, o aceptar una lista de dispositivos separada por comas. Esto anula el archivo de dispositivos.
--devicesfile String
Un archivo que lista los dispositivos que LVM debe usar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración de devices/devicesfile y devices/use_devicesfile de lvm.conf(5).
--driverloaded s|n
Si se establece en no, el comando no intentará usar device-mapper. Para pruebas y depuración.
-h|--help
Muestra el texto de ayuda.
--journal String
Registra información en el journal de systemd. Esta información es adicional a la información habilitada por la configuración de registro/journal de lvm. comando: registra información sobre el comando. salida: registra la salida predeterminada del comando. depuración: registra la depuración completa del comando.
--lockopt String
Se utiliza para pasar opciones para casos especiales a lvmlockd. Ver lvmlockd(8) para más información.
--longhelp
Muestra el texto de ayuda largo.
-l|--maxlogicalvolumes Número
Establece el número máximo de LVs permitidos en un VG.
-p|--maxphysicalvolumes Número
Establece el número máximo de PVs que pueden pertenecer al VG. El valor 0 elimina cualquier limitación. Para un gran número de PVs, ver también las opciones --pvmetadatacopies y --vgmetadatacopies para mejorar el rendimiento.
-M|--metadatatype lvm2
Especifica el tipo de metadatos en disco a usar. lvm2 (o solo 2) es el formato actual y estándar. lvm1 (o solo 1) ya no se usa.
-n|--name String
Mueve solo los PVs utilizados por el LV nombrado.
--nohints
No usar el archivo de pistas para localizar dispositivos para PVs. Un comando puede leer más dispositivos para encontrar PVs cuando no se usan pistas. El comando aún realizará la invalidación estándar del archivo de pistas cuando sea apropiado.
--nolocking
Deshabilita el bloqueo. Usar con precaución, comandos concurrentes pueden producir resultados incorrectos.
--poolmetadataspare s|n
Habilita o deshabilita la creación y gestión automática de un LV de metadatos de repuesto en el VG. Un LV de metadatos de repuesto es espacio reservado que puede usarse al reparar un pool.

vgsplit(8) — LVM Tools

NAME

vgsplit — Splits a Volume Group into two.

SYNOPSIS

vgsplit [--select operand] [-A|—--alloc allocation_policy] [-f|—force] [-v|—verbose] VG_NAME [New_VG_NAME]

DESCRIPTION

The vgsplit command splits an existing Volume Group (VG_NAME) into two Volume Groups. The original Volume Group VG_NAME will contain a subset of the original Physical Volumes (PVs) and all of the original Logical Volumes (LVs). The new Volume Group New_VG_NAME will contain the remaining PVs and none of the original LVs.

This command is useful for dividing up an existing VG in order to better manage storage, or to move PVs from one VG to another.

All original LVs remain in the original VG, VG_NAME. New LVs can be created in New_VG_NAME as needed.

If New_VG_NAME already exists, the command will fail. The command will also fail if VG_NAME contains no LVs or if all PVs in VG_NAME are selected to be moved to New_VG_NAME. All of the original PVs will remain in VG_NAME unless specified otherwise.

The PVs to be moved to the new VG are specified after New_VG_NAME.

USAGE

The following is a list of the arguments and options that vgsplit accepts:

OPTIONS

-A|--alloc allocation_policy
Determines the allocation policy for selecting the Physical Volumes (PV) to be moved to the new Volume Group. The default policy is contiguous. See lvm(8) for a list of available allocation policies.
-f|--force
Forces the split to occur even if a warning is issued. Use with extreme caution.
-v|--verbose ...
Sets the level of verbosity. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--select operand
Selects which Physical Volumes (PV) to move to the new Volume Group. The operand is a comma-separated list of PV tags or PV names. For example: --select 'physical-volumes(my_pv_tag)' or --select 'physical-volumes(my_pv_name)'. If no --select option is provided, all PVs in the Volume Group will be moved to the new VG.
-d|--debug
Enable debugging messages.
-q|--quiet
Suppress output messages. Repeat -q to suppress prompts.
-t|--test
Run in test mode. Commands will not update metadata. This is implemented by disabling all metadata writing but nevertheless returning success to the calling function. This may lead to unusual error messages in multi-stage operations if a tool relies on reading back metadata it believes has changed but hasn't.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
--[vg]metadatacopies all|unmanaged|Number
Number of copies of the VG metadata that are kept. VG metadata is kept in VG metadata areas on PVs in the VG, i.e. reserved space at the start and/or end of the PVs. Keeping a copy of the VG metadata on every PV can reduce performance in VGs containing a large number of PVs. When this number is set to a non-zero value, LVM will automatically choose PVs on which to store metadata, using the metadataignore flags on PVs to achieve the specified number. The number can also be replaced with special string values: unmanaged causes LVM to not automatically manage the PV metadataignore flags. all causes LVM to first clear the metadataignore flags on all PVs, and then to become unmanaged.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

VG
Volume Group name. See lvm(8) for valid names.
PV
Physical Volume name, a device path under /dev. For commands managing physical extents, a PV positional arg generally accepts a suffix indicating a range (or multiple ranges) of physical extents (PEs). When the first PE is omitted, it defaults to the start of the device, and when the last PE is omitted it defaults to end.
Start and end range (inclusive): PV[:PE-PE] ...
Start and length range (counting from 0): PV[:PE+PE] ...
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.
