VGEXTEND(8) Manual del Administrador del Sistema VGEXTEND(8)

NOMBRE

vgextend — Añadir volúmenes físicos a un grupo de volúmenes

SINOPSIS

vgextend argumentos_posicionales
[ argumentos_opcionales ]

DESCRIPCIÓN

vgextend añade uno o más volúmenes físicos (PVs) a un grupo de volúmenes (VG). Esto aumenta el espacio disponible para los volúmenes lógicos (LVs) en el VG.

Además, los PVs que han desaparecido y luego han regresado, por ejemplo, debido a un fallo transitorio del dispositivo, pueden ser añadidos de nuevo al VG sin necesidad de reinicializarlos (ver --restoremissing).

Si los PVs especificados aún no han sido inicializados con pvcreate, vgextend los inicializará. En este caso se pueden usar opciones de pvcreate, por ejemplo, --labelsector, --metadatasize, --metadataignore, --pvmetadatacopies, --dataalignment, --dataalignmentoffset.

USO

vgextend VG PV ...

[ -A|--autobackup y|n ]
[ -f|--force ... ]
[ -M|--metadatatype lvm2 ]
[ -Z|--zero y|n ]
[ --dataalignment Tamaño[k|UNIDAD] ]
[ --dataalignmentoffset Tamaño[k|UNIDAD] ]
[ --labelsector Número ]
[ --metadataignore y|n ]
[ --metadatasize Tamaño[m|UNIDAD] ]
[ --pvmetadatacopies 0|1|2 ]
[ --reportformat basic|json|json_std ]
[ --restoremissing ]
[ OPCIONES_COMUNES ]

OPCIONES

-A|--autobackup y|n
Especifica si las metadatos deben ser respaldados automáticamente después de un cambio. ¡Habilitar esto es muy recomendable! Ver vgcfgbackup(8) para más información.
--commandprofile Cadena
El perfil de comando a usar para la configuración del comando. Ver lvm.conf(5) para más información sobre perfiles.
--config Cadena
Configuraciones para el comando. Estas anulan la configuración de lvm.conf(5). La cadena de argumentos usa el mismo formato que lvm.conf(5), o puede usar la sintaxis de sección/campo. Ver lvm.conf(5) para más información sobre la configuración.
--dataalignment Tamaño[k|UNIDAD]
Alinea el inicio del área de datos de un PV con un múltiplo de este número. Para ver la ubicación del primer Extent Físico (PE) de un PV existente, use pvs -o +pe_start. Además, puede ser desplazado por un desplazamiento de alineación, ver --dataalignmentoffset. También especifique un tamaño de PE apropiado al crear un VG.
--dataalignmentoffset Tamaño[k|UNIDAD]
Desplaza el inicio del área de datos del PV con este desplazamiento adicional.
-d|--debug ...
Establece el nivel de depuración. Repetir de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción puede repetirse o aceptar una lista separada por comas de dispositivos. Esto anula el archivo de dispositivos.
--devicesfile Cadena
Un archivo que lista los dispositivos que LVM debe usar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula los ajustes de devices/devicesfile y devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si se establece en no, el comando no intentará usar device-mapper. Para pruebas y depuración.
-f|--force ...
Anula varias comprobaciones, confirmaciones y protecciones. Usar con extremo cuidado.
-h|--help
Muestra el texto de ayuda.
--journal Cadena
Registra información en el registro del sistema (systemd journal). Esta información es adicional a la información habilitada por la configuración de registro/journal de lvm.conf. command: registra información sobre el comando. output: registra la salida predeterminada del comando. debug: registra la depuración completa del comando.
--labelsector Número
Por defecto, el PV se etiqueta con un identificador LVM2 en su segundo sector (sector 1). Esto le permite usar un sector diferente cerca del inicio del disco (entre 0 y 3 inclusive - ver LABEL_SCAN_SECTORS en el código fuente). Usar con precaución.
--lockopt Cadena
Se utiliza para pasar opciones para casos especiales a lvmlockd. Ver lvmlockd(8) para más información.
--longhelp
Muestra el texto de ayuda largo.
--metadataignore y|n
Especifica la propiedad metadataignore de un PV. Si es sí, se ignoran las áreas de metadatos en el PV, y lvm no almacenará metadatos en las áreas de metadatos del PV. Si es no, lvm almacenará metadatos en el PV.
--metadatasize Tamaño[m|UNIDAD]
La cantidad aproximada de espacio utilizada para cada área de metadatos del VG. El tamaño puede ser redondeado.
-M|--metadatatype lvm2
Especifica el tipo de metadatos en disco a usar. lvm2 (o solo 2) es el formato actual y estándar. lvm1 (o solo 1) ya no se usa.
--nohints
No usar el archivo de sugerencias para localizar dispositivos para PVs. Un comando puede leer más dispositivos para encontrar PVs cuando no se usan sugerencias. El comando aún realizará la invalidación estándar del archivo de sugerencias cuando sea apropiado.
--nolocking
Deshabilita el bloqueo. Usar con precaución, comandos concurrentes pueden producir resultados incorrectos.
--profile Cadena
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
--pvmetadatacopies 0|1|2
El número de áreas de metadatos reservadas en un PV para almacenar los metadatos del VG. Cuando es 2, se almacena una copia de los metadatos del VG al principio del PV y una segunda copia al final. Cuando es 1, se almacena una copia de los metadatos del VG al principio del PV. Cuando es 0, no se almacenan copias de los metadatos del VG en el PV dado. Esto puede ser útil en VGs que contienen muchos PVs (esto impone limitaciones a la capacidad de usar vgsplit más tarde).
-q|--quiet ...
Suprime la salida y los mensajes de registro. Anula --debug y --verbose. Repetir una vez para también suprimir cualquier pregunta

NAME

vgextend — Extend an existing Volume Group

SYNOPSIS

vgextend [-A|--available {y|n}] [--alloc allocation_policy] [--monitor {y|n}] [--restoremissing {y|n}] [-T|--partial] [-t|--test] -v|--verbose [PhysicalVolume[:PE-PE]...] VolumeGroup

vgextend [-A|--available {y|n}] [--alloc allocation_policy] [--monitor {y|n}] [--restoremissing {y|n}] -t|--test -v|--verbose VolumeGroup

DESCRIPTION

Allows you to add one or more Physical Volumes (PVs) to an existing Volume Group (VG). The VG is specified by its name, followed by a list of PVs (and optionally PE ranges) to add.

If the VG name is the only argument, the command looks for PVs marked for automatic activation. If none are found, it displays an error. If the VG is already active, the command adds the PVs. If the VG is inactive, the PVs are added but not activated until the VG is activated with vgchange. This behaviour can be changed with the --available option.

The --partial option allows for extending a VG that has missing PVs. This is useful if you want to add new PVs to replace missing ones, but the VG metadata is not yet updated to reflect the missing PVs. This operation is only possible if the VG metadata is not corrupt.

See lvm(8) for more information about logical volume management.

USAGE

The following options are available for the vgextend command:

OPTIONS

-A|--available y|n
Controls whether the VG is marked for availability. If the VG is inactive, this option is used to determine whether the VG should be activated when PVs are added. A value of y (default) means the VG will be available for activation. A value of n means the VG will not be available for activation until explicitly activated later using vgchange(8).
--alloc allocation_policy
Determines the allocation policy for the PVs. See lvm.conf(5) for valid values. Default is normal.
--monitor { y|n }
Controls if the VG metadata includes the monitoring flag. See vgcreate(8) for more information.
-T|--partial
Allows VG operations on VGs with missing PVs. This option allows commands to operate on a VG even if some PVs are missing. This is useful when replacing a missing PV with a new one, but the VG metadata has not yet been updated to reflect the missing PV. This is only possible if the VG metadata is not corrupt.
--restoremissing
Add a PV back into a VG after the PV was missing and then returned, e.g. due to a transient failure. The PV is not reinitialized.
-t|--test
Run in test mode. Commands will not update metadata. This is implemented by disabling all metadata writing but nevertheless returning success to the calling function. This may lead to unusual error messages in multi-stage operations if a tool relies on reading back metadata it believes has changed but hasn't.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

VG
Volume Group name. See lvm(8) for valid names.
PV
Physical Volume name, a device path under /dev. For commands managing physical extents, a PV positional arg generally accepts a suffix indicating a range (or multiple ranges) of physical extents (PEs). When the first PE is omitted, it defaults to the start of the device, and when the last PE is omitted it defaults to end.
Start and end range (inclusive): PV[:PE-PE] ...
Start and length range (counting from 0): PV[:PE+PE] ...

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.

EXAMPLES

Add two PVs to a VG.
vgextend vg00 /dev/sda4 /dev/sdn1
