NOMBRE

varnishtest - Programa de prueba para Varnish

SINOPSIS

varnishtest [-hikLlqv] [-b tamaño] [-D nombre=valor] [-j trabajos] [-n iter] [-t duracion] archivo [archivo ...]

DESCRIPCIÓN

El programa varnishtest es un programa dirigido por scripts que se utiliza para probar Varnish Cache.

El programa varnishtest, al iniciarse y dársele uno o más archivos de script, puede crear un número de hilos que representan backends, algunos hilos que representan clientes y un proceso varnishd. Esto se utiliza para simular una transacción para provocar un comportamiento específico.

Las siguientes opciones están disponibles:

-b tamaño
Establecer el tamaño del búfer interno (predeterminado: 1M)

-D nombre=valor Definir macro para usar en scripts

-h
Mostrar ayuda
-i
Establecer PATH y vmod_path para encontrar los binarios de varnish en el árbol de compilación
-j trabajos
Ejecutar esta cantidad de pruebas en paralelo
-k
Continuar en caso de fallo de la prueba
-L
Dejar siempre los temporales vtc.*
-l
Dejar los temporales vtc.* si la prueba falla
-n iteraciones
Ejecutar las pruebas este número de veces

-p nombre=valor Pasar parámetros a todas las líneas de comando de varnishd

-q
Modo silencioso: informar solo de los fallos
-t duracion
Tiempo de espera para las pruebas después de este tiempo (predeterminado: 60s)
-v
Modo detallado: informar siempre del registro de la prueba

archivo Archivo a usar como script

Si TMPDIR está configurado en el entorno, varnishtest crea directorios temporales vtc.* para cada prueba en $TMPDIR, de lo contrario, en /tmp.

SCRIPTS

La sintaxis de vtc se documenta extensamente en vtc(7). Si desea más ejemplos que el siguiente, puede consultar el repositorio de código fuente de Varnish, en bin/varnishtest/tests/, donde se guardan todas las pruebas de regresión para Varnish.

Un ejemplo:

varnishtest "#1029"
server s1 {
        rxreq
        expect req.url == "/bar"
        txresp -gzipbody {[bar]}
        rxreq
        expect req.url == "/foo"
        txresp -body {<h1>FOO<esi:include src="/bar"/>BARF</h1>}
} -start
varnish v1 -vcl+backend {
        sub vcl_backend_response {
                set beresp.do_esi = true;
                if (bereq.url == "/foo") {
                        set beresp.ttl = 0s;
                } else {
                        set beresp.ttl = 10m;
                }
        }
} -start
client c1 {
        txreq -url "/bar" -hdr "Accept-Encoding: gzip"
        rxresp
        gunzip
        expect resp.bodylen == 5
        txreq -url "/foo" -hdr "Accept-Encoding: gzip"
        rxresp
        expect resp.bodylen == 21
} -run

Al ejecutarse, el script anterior simulará un servidor (s1) que espera dos solicitudes diferentes. Iniciará un servidor Varnish (v1) y agregará la definición del backend al VCL especificado (-vcl+backend). Finalmente, inicia el cliente c1, que es un único cliente que envía dos solicitudes.

PROBANDO UN ÁRBOL DE COMPILACIÓN

Ya sea que esté compilando un VMOD o intentando usar uno que haya compilado recientemente, puede indicarle a varnishtest que pase un vmod_path a las instancias de varnishd iniciadas usando el comando varnish -start en su caso de prueba:

varnishtest -p vmod_path=... /ruta/a/*.vtc

De esta manera, puede usar los mismos casos de prueba tanto en VMODs instalados como compilados:

server s1 {...} -start
varnish v1 -vcl+backend {
    import wossname;
    ...
} -start
...

No está limitado a vmod_path y puede pasar cualquier parámetro, lo que le permite ejecutar una matriz de compilación sin cambiar el conjunto de pruebas. Puede lograr lo mismo con macros, pero luego deben definirse en cada ejecución.

Puede ver las líneas de comando de varnishd reales en los resultados de las pruebas, se ven más o menos así:

exec varnishd [parámetros de varnishtest -p] [parámetros de prueba] [parámetros de vtc -arg]

Los parámetros que define con varnishtest -p pueden ser anulados por parámetros necesarios para que varnishtest se ejecute correctamente, y estos a su vez pueden ser anulados por parámetros establecidos en los scripts de prueba.

También hay un modo especial en el que varnishtest construye su propio PATH y vmod_path para encontrar los binarios de Varnish (programas y VMODs) en el árbol de compilación que rodea al binario varnishtest. Esto está destinado a probar Varnish en desarrollo y descartará su vmod_path si establece uno.

Si necesita probar su VMOD contra un árbol de compilación de Varnish, primero debe instalarlo, en un directorio temporal por ejemplo. Con la información proporcionada por el pkg-config(1) de la instalación, puede construir un PATH adecuado para acceder a los programas de Varnish y un vmod_path para acceder tanto a su VMOD como a los VMODs integrados:

export PKG_CONFIG_PATH=/ruta/a/instalar/lib/pkgconfig
BINDIR="$(pkg-config --variable=bindir varnishapi)"
SBINDIR="$(pkg-config --variable=sbindir varnishapi)"
PATH="SBINDIR:BINDIR:$PATH"
VMODDIR="$(pkg-config --variable=vmoddir varnishapi)"
VMOD_PATH="/ruta/a/su/vmod/build/dir:$VMODDIR"
varnishtest -p vmod_path="$VMOD_PATH" ...
