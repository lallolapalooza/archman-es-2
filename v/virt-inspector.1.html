NOMBRE

virt-inspector - Muestra la versión del sistema operativo y otra información de una máquina virtual

SINOPSIS

virt-inspector [--opciones] -d nombre_dominio
virt-inspector [--opciones] -a disco.img [-a disco.img ...]

Estilo antiguo:

virt-inspector nombre_dominio
virt-inspector disco.img [disco.img ...]

DESCRIPCIÓN

virt-inspector examina una máquina virtual o una imagen de disco e intenta determinar la versión del sistema operativo y otra información sobre la máquina virtual.

Virt-inspector produce salida XML para ser alimentada a otros programas.

En el uso normal, utilice "virt-inspector -d nombre_dominio" donde "nombre_dominio" es el dominio libvirt (ver: "virsh list --all").

También puede ejecutar virt-inspector directamente en imágenes de disco de una sola máquina virtual. Utilice "virt-inspector -a disco.img". En casos raros, un dominio tiene varios dispositivos de bloque, en cuyo caso debe enumerar varias opciones -a una tras otra, correspondiendo la primera al /dev/sda del invitado, la segunda al /dev/sdb del invitado y así sucesivamente.

También puede ejecutar virt-inspector en discos de instalación, CDs en vivo, unidades USB arrancables y similares.

Virt-inspector solo puede inspeccionar y reportar sobre un dominio a la vez. Para inspeccionar varias máquinas virtuales, debe ejecutar virt-inspector varias veces (por ejemplo, desde un script de shell con un bucle for).

Debido a que virt-inspector necesita acceso directo a las imágenes del invitado, normalmente no funcionará a través de conexiones libvirt remotas.

Toda la información disponible de virt-inspector también está disponible a través de la API de inspección principal de libguestfs (ver "INSPECCIÓN" en guestfs(3)). La misma información también se puede obtener usando guestfish o a través de los enlaces de libguestfs en muchos lenguajes de programación (ver "OBTENCIÓN DE DATOS DE INSPECCIÓN DE LA API LIBGUESTFS").

Información adicional sobre el cargador de arranque, el kernel y los controladores dentro de un invitado se puede encontrar usando virt-drivers(1).

OPCIONES

--help
Muestra ayuda breve.
-a archivo
--add archivo
Agrega archivo, que debe ser una imagen de disco de una máquina virtual. Si la máquina virtual tiene varios dispositivos de bloque, debe proporcionar todos ellos con opciones -a separadas.

El formato de la imagen de disco se detecta automáticamente. Para anular esto y forzar un formato particular, use la opción --format=...

-a URI
--add URI
Agrega un disco remoto. Ver "AGREGAR ALMACENAMIENTO REMOTO" en guestfish(1).
--blocksize=512
--blocksize=4096
--blocksize
Este parámetro establece el tamaño del sector de la imagen de disco. Afecta a todos los discos añadidos explícitamente después de este parámetro. Usar --blocksize sin argumento cambia el tamaño del sector del disco al valor predeterminado, que suele ser de 512 bytes. Ver también "guestfs_add_drive_opts" en guestfs(3).
-c URI
--connect URI
Si se usa libvirt, conéctese a la URI dada. Si se omite, nos conectamos al hipervisor libvirt predeterminado.

Libvirt solo se utiliza si especifica un "nombre_dominio" en la línea de comandos. Si especifica dispositivos de bloque del invitado directamente (-a), entonces libvirt no se utiliza en absoluto.

-d invitado
--domain invitado
Agrega todos los discos del invitado libvirt con el nombre especificado. Se pueden usar UUID de dominio en lugar de nombres.
--echo-keys
Al solicitar claves y contraseñas, virt-inspector normalmente desactiva el eco para que no pueda ver lo que está escribiendo. Si no le preocupan los ataques Tempest y no hay nadie más en la habitación, puede especificar esta opción para ver lo que está escribiendo.
--format=raw|qcow2|..
--format
Especifica el formato de las imágenes de disco proporcionadas en la línea de comandos. Si se omite, el formato se detecta automáticamente del contenido de la imagen de disco.

Si se solicitan imágenes de disco de libvirt, este programa solicita esta información a libvirt. En este caso, el valor del parámetro formato se ignora.

Si trabaja con imágenes de disco de invitado sin formato de confianza, siempre debe especificar el formato.

--key SELECCIONADOR
Especifica una clave para LUKS, para abrir automáticamente un dispositivo LUKS al usar la inspección.
--key NOMBRE:key:CADENA_CLAVE
--key UUID:key:CADENA_CLAVE
--key all:key:CADENA_CLAVE
"NOMBRE" es el nombre del dispositivo libguestfs (ej. "/dev/sda1"). "UUID" es el UUID del dispositivo. "all" significa intentar la clave contra cualquier dispositivo cifrado.

Utilice la "CADENA_CLAVE" especificada como contraseña.

--key NOMBRE:file:NOMBRE_ARCHIVO
--key UUID:file:NOMBRE_ARCHIVO
--key all:file:NOMBRE_ARCHIVO
Lee la contraseña del NOMBRE_ARCHIVO.
--key NOMBRE:clevis
--key UUID:clevis
--key all:clevis
Intenta desbloquear sin contraseña el dispositivo con Clevis, a través de la red. Consulte "DISCOS CIFRADOS" en guestfs(3) para obtener más información sobre el cifrado de disco enlazado a la red (NBDE).

Tenga en cuenta que si hay alguna opción de este tipo en la línea de comandos, la red de usuario QEMU se habilitará automáticamente para la aplicación libguestfs.

--keys-from-stdin
Lee parámetros de clave o contraseña desde stdin. El valor predeterminado es intentar leer contraseñas del usuario abriendo /dev/tty.

Si hay varios dispositivos cifrados, es posible que necesite proporcionar varias claves en stdin, una por línea.

--no-applications
Por defecto, la salida de virt-inspector incluye la lista de todas las aplicaciones instaladas en el invitado, si están disponibles.

Especifique esta opción para deshabilitar esta parte del XML resultante.

--no-icon
Por defecto, la salida de virt-inspector incluye el icono del invitado, si está disponible (ver "icono").

Especifique esta opción para deshabilitar esta parte del XML resultante.

-v
--verbose
Habilita mensajes detallados para depuración.
-V
--version

-v
Muestra el número de versión y sale.
-x
Habilita el rastreo de llamadas a la API de libguestfs.
--xpath query
Realiza una consulta XPath en el XML de la entrada estándar e imprime el resultado en la salida estándar. En este modo, virt-inspector simplemente ejecuta una consulta XPath; todas las demás funciones de inspección están deshabilitadas. Consulte "CONSULTAS XPATH" más abajo para ver algunos ejemplos.

ARGUMENTOS DE LÍNEA DE COMANDOS ESTILO ANTIGUO

Versiones anteriores de virt-inspector permitían escribir:

virt-inspector disk.img [disk.img ...]

o

virt-inspector guestname

mientras que en esta versión debe usar -a o -d respectivamente para evitar el caso confuso en que una imagen de disco pueda tener el mismo nombre que un invitado.

Por compatibilidad, el estilo antiguo todavía se admite.

FORMATO XML

El XML de virt-inspector se describe con precisión en un archivo de esquema RELAX NG virt-inspector.rng que se suministra con libguestfs. Esta sección es solo una visión general.

El elemento de nivel superior es <operatingsystems> y contiene uno o más elementos <operatingsystem>. Solo vería más de un elemento <operatingsystem> si la máquina virtual tuviera arranque múltiple, lo cual es extremadamente raro en VMs del mundo real.

<operatingsystem>

En la etiqueta <operatingsystem> hay varios campos opcionales que describen el sistema operativo, su arquitectura, la cadena descriptiva "nombre del producto", el tipo de SO, etc., como en este ejemplo:

<operatingsystems>
  <operatingsystem>
    <root>/dev/sda2</root>
    <name>windows</name>
    <arch>i386</arch>
    <distro>windows</distro>
    <product_name>Windows 7 Enterprise</product_name>
    <product_variant>Client</product_variant>
    <major_version>6</major_version>
    <minor_version>1</minor_version>
    <windows_systemroot>/Windows</windows_systemroot>

En resumen, <name> es la clase del sistema operativo (algo como "linux" o "windows"), <distro> es la distribución (por ejemplo, "fedora", pero se reconocen muchas otras distribuciones) y <arch> es la arquitectura del invitado. Los otros campos se explican solos, pero dado que estos campos se toman directamente de la API de inspección de libguestfs, puede encontrar información precisa en "INSPECCIÓN" en guestfs(3).

El elemento <root> es el dispositivo del sistema de archivos raíz, pero desde la perspectiva de libguestfs (los dispositivos de bloque pueden tener nombres completamente diferentes dentro de la propia VM).

<mountpoints>

Los invitados tipo Unix* suelen tener varios sistemas de archivos que se montan en varios puntos de montaje, y estos se describen en el elemento <mountpoints>, que se ve así:

<operatingsystems>
  <operatingsystem>
    ...
    <mountpoints>
      <mountpoint dev="/dev/vg_f13x64/lv_root">/</mountpoint>
      <mountpoint dev="/dev/sda1">/boot</mountpoint>
    </mountpoints>

Al igual que con <root>, los dispositivos son desde la perspectiva de libguestfs y pueden tener nombres completamente diferentes dentro del invitado. Solo los sistemas de archivos montables aparecen en esta lista, no elementos como dispositivos de intercambio.

<filesystems>

<filesystems> es como <mountpoints> pero cubre *todos* los sistemas de archivos pertenecientes al invitado, incluidos el intercambio y las particiones vacías. (En el raro caso de un invitado con arranque múltiple, cubre los sistemas de archivos pertenecientes a este SO o compartidos con este SO y otros SO).

Podría ver algo como esto:

<operatingsystems>
  <operatingsystem>
    ...
    <filesystems>
      <filesystem dev="/dev/vg_f13x64/lv_root">
        <type>ext4</type>
        <label>Fedora-13-x86_64</label>
        <uuid>e6a4db1e-15c2-477b-ac2a-699181c396aa</uuid>
      </filesystem>

Los elementos opcionales dentro de <filesystem> son el tipo de sistema de archivos, la etiqueta y el UUID.

<applications>

Los elementos relacionados <package_format>, <package_management> y <applications> describen las aplicaciones instaladas en la máquina virtual.

<package_format>, si está presente, describe el sistema de paquetes utilizado. Los valores típicos serían "rpm" y "deb".

<package_management>, si está presente, describe el gestor de paquetes. Los valores típicos incluyen "yum", "up2date" y "apt"

<applications> enumera los paquetes o aplicaciones instalados.

<operatingsystems>
  <operatingsystem>
    ...
    <applications>
      <application>
        <name>coreutils</name>
        <version>8.5</version>
        <release>1</release>
      </application>

Los campos de versión y lanzamiento pueden no estar disponibles para algunos tipos de invitados. Pueden existir otros campos, consulte "guestfs_inspect_list_applications" en guestfs(3).

<drive_mappings>

Para sistemas operativos como Windows que usan letras de unidad, virt-inspector puede averiguar cómo se mapean las letras de unidad a los sistemas de archivos.

<operatingsystems>
  <operatingsystem>
    ...
    <drive_mappings>
      <drive_mapping name="C">/dev/sda2</drive_mapping>
      <drive_mapping name="E">/dev/sdb1</drive_mapping>
    </drive_mappings>

En el ejemplo anterior, la unidad C se mapea al sistema de archivos en la segunda partición del primer disco, y la unidad E se mapea al sistema de archivos en la primera partición del segundo disco.

Tenga en cuenta que esto solo cubre los mapeos de sistemas de archivos locales permanentes, no elementos como recursos compartidos de red. Además, es posible que los puntos de montaje de volúmenes NTFS no aparezcan aquí.

<icon>

Virt-inspector a veces puede extraer un icono o logotipo para el invitado. El icono se devuelve como datos PNG codificados en base64. Tenga en cuenta que el icono puede ser muy grande y de alta calidad.

<operatingsystems>
  <operatingsystem>
    ...
    <icon>
      iVBORw0KGgoAAAANSUhEUgAAAGAAAABg[.......]
      [... muchas líneas de datos base64 ...]
    </icon>

Para mostrar el icono, debe extraerlo y convertir los datos base64 de nuevo a un archivo binario. Utilice una consulta XPath o simplemente un editor para extraer los datos, luego use el programa base64(1) de coreutils para realizar la conversión de nuevo a un archivo PNG:

base64 -i -d < icon.data > icon.png

CONSULTAS XPATH

Virt-inspector incluye soporte integrado para ejecutar consultas XPath. La razón para incluir el soporte de XPath directamente en virt-inspector es simplemente que no existen programas de línea de comandos buenos y ampliamente disponibles que puedan realizar consultas XPath. El único bueno es xmlstarlet(1) y no está disponible en Red Hat Enterprise Linux.

Para realizar una consulta XPath, use la opción --xpath. Tenga en cuenta que en este modo, virt-inspector simplemente lee XML de la entrada estándar y genera el resultado de la consulta en la salida estándar. Todas las demás funciones de inspección están deshabilitadas en este modo.

Por ejemplo:

$ virt-inspector -d Guest | virt-inspector --xpath '//filesystems'
<filesystems>
     <filesystem dev="/dev/vg_f13x64/lv_root">
       <type>ext4</type>
[...]
$ virt-inspector -d Guest | \
    virt-inspector --xpath "string(//filesystem[@dev='/dev/sda1']/type)"
ext4
$ virt-inspector -d Guest | \
    virt-inspector --xpath 'string(//icon)' | base64 -i -d | display -
[muestra el icono del invitado, si lo hay]

OBTENER DATOS DE INSPECCIÓN DE LA API DE LIBGUESTFS

En las primeras versiones de libguestfs, virt-inspector era un script Perl grande que contenía muchas heurísticas para inspeccionar invitados. Esto tenía varios problemas: para realizar la inspección desde otras herramientas (como guestfish) teníamos que llamar a este script de Perl; y privilegiaba a Perl sobre otros idiomas que admite libguestfs.

Para libguestfs 1.8, habíamos reescrito el código Perl en C y lo habíamos incorporado en la API principal de libguestfs (guestfs(3)). Ahora virt-inspector es simplemente un programa C ligero sobre la API C principal. Toda la información de inspección está disponible desde todos los lenguajes de programación que admite libguestfs, y desde guestfish.

Para una descripción de la API de inspección C, lea "INSPECCIÓN" en guestfs(3).

Para ver código de ejemplo que utiliza la API de inspección C, busque inspect-vm.c que se distribuye con libguestfs.

inspect-vm.c también se ha traducido a otros idiomas. Por ejemplo, inspect_vm.pl es la traducción al Perl, y existen otras traducciones para OCaml, Python, etc. Consulte "USAR LIBGUESTFS CON OTROS LENGUAJES DE PROGRAMACIÓN" en guestfs(3) para obtener una lista de páginas man que contienen este código de ejemplo.

OBTENER DATOS DE INSPECCIÓN DE GUESTFISH

Si utiliza la opción -i de guestfish, se llama a la API de inspección C principal "guestfs_inspect_os" en guestfs(3). Esto es equivalente al comando guestfish "inspect-os". También puede llamar a este comando de guestfish manualmente.

NAME

virt-inspector — inspect virtual machine disk images

SYNOPSIS

virt-inspector [-a disk.img] [-x xpath-query] [--print-system-list] [--print-root-list] [--human] [--version] [--help]

DESCRIPTION

virt-inspector is a tool that inspects virtual machine disk images to find operating systems. It uses the libguestfs library. It can detect the distribution, major version, and product name.

By default, it prints an XML description of the operating systems found. It can also print a simple list of operating systems, or a list of root devices.

The command line options -a, -x, --print-system-list, --print-root-list, and --human are shortcuts for common tasks that would otherwise be done using the guestfish shell.

--print-system-list

This option prints a list of operating systems found. For each operating system, it prints the distribution, major version, and product name.

    $ virt-inspector --print-system-list -a F15x32.img
    Fedora,15,Fedora release 15 (Lovelock)

--print-root-list

This option prints a list of root devices found. For each operating system found, it prints the root device name.

    $ virt-inspector --print-root-list -a F15x32.img
    /dev/vg_f15x32/lv_root

--human

This option prints information in a human-readable format. It is equivalent to using guestfish and running inspect-os, then inspect-get-type, inspect-get-distro, inspect-get-major-version, and inspect-get-product-name for each root device found.

    $ virt-inspector --human -a F15x32.img
    Type: linux
    Distro: fedora
    Major Version: 15
    Product Name: Fedora release 15 (Lovelock)

-x xpath-query

This option allows you to query the XML output directly using an XPath query. This is useful for extracting specific pieces of information.

    $ virt-inspector -x '//operating-system/@distro' -a F15x32.img
    fedora

For more information on XPath, see http://www.w3.org/TR/xpath/.

OPTIONS

-a disk.img
Attach the specified disk image. This option can be used multiple times to attach multiple disk images.
-x xpath-query
Execute the XPath query against the XML output. This option can be used multiple times.
--print-system-list
Print a list of operating systems found.
--print-root-list
Print a list of root devices found.
--human
Print information in a human-readable format.
--version
Print version information and exit.
--help
Print help message and exit.

OLD-STYLE COMMAND LINE ARGUMENTS

The virt-inspector command used to accept old-style command line arguments before libguestfs version 1.29.0.

These arguments are now deprecated and will be removed in a future version.

-r disk.img
Equivalent to -a disk.img.
-q xpath-query
Equivalent to -x xpath-query.
-s
Equivalent to --print-system-list.
-l
Equivalent to --print-root-list.
-h
Equivalent to --human.

XML FORMAT

The default output format is XML. Here is an example:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE ///guestfs/inspect///SYSTEM "inspect.dtd">
<match>
  <operating-system>
    <type>linux</type>
    <distro>fedora</distro>
    <major-version>15</major-version>
    <product-name>Fedora release 15 (Lovelock)</product-name>
    <root>/dev/vg_f15x32/lv_root</root>
  </operating-system>
  <operating-system>
    <type>windows</type>
    <distro>winxp</distro>
    <major-version>5</major-version>
    <product-name>Windows XP Professional</product-name>
    <root>/dev/sda1</root>
  </operating-system>
</match>

The inspect.dtd is available in the libguestfs source code and documentation.

XPATH QUERIES

You can use XPath queries to extract specific information from the XML output. Some common XPath queries:

  • //operating-system/type: Get the type of all operating systems.

  • //operating-system[1]/distro: Get the distribution of the first operating system found.

  • //operating-system[type='linux']/major-version: Get the major version of all Linux operating systems.

  • //operating-system[@root='/dev/sda1']/product-name: Get the product name of the operating system whose root device is /dev/sda1.

GETTING INSPECTION DATA FROM THE LIBGUESTFS API

guestfish --ro -a F15x32.img performs inspection on the current disk image, returning the list of operating systems found. Each OS is represented by its root filesystem device. In the majority of cases, this command prints nothing (no OSes found), or a single root device, but beware that it can print multiple lines if there are multiple OSes or if there is an install CD attached to the guest.

$ guestfish --ro -a F15x32.img
><fs> run
><fs> inspect-os
/dev/vg_f15x32/lv_root

Using the root device, you can fetch further information about the guest:

><fs> inspect-get-type /dev/vg_f15x32/lv_root
linux
><fs> inspect-get-distro /dev/vg_f15x32/lv_root
fedora
><fs> inspect-get-major-version /dev/vg_f15x32/lv_root
15
><fs> inspect-get-product-name /dev/vg_f15x32/lv_root
Fedora release 15 (Lovelock)

Limitations of guestfish make it hard to assign the root device to a variable (since guestfish doesn't have variables), so if you want to do this reproducibly you are better off writing a script using one of the other languages that the libguestfs API supports.

To list applications, you have to first mount up the disks:

><fs> inspect-get-mountpoints /dev/vg_f15x32/lv_root
/: /dev/vg_f15x32/lv_root
/boot: /dev/vda1
><fs> mount-ro /dev/vg_f15x32/lv_root /
><fs> mount-ro /dev/vda1 /boot

and then call the inspect-list-applications API:

><fs> inspect-list-applications /dev/vg_f15x32/lv_root | head -28
[0] = {
  app_name: ConsoleKit
  app_display_name:
  app_epoch: 0
  app_version: 0.4.5
  app_release: 1.fc15
  app_install_path:
  app_trans_path:
  app_publisher:
  app_url:
  app_source_package:
  app_summary:
  app_description:
}
[1] = {
  app_name: ConsoleKit-libs
  app_display_name:
  app_epoch: 0
  app_version: 0.4.5
  app_release: 1.fc15
  app_install_path:
  app_trans_path:
  app_publisher:
  app_url:
  app_source_package:
  app_summary:
  app_description:
}

To display an icon for the guest, note that filesystems must also be mounted as above. You can then do:

><fs> inspect-get-icon /dev/vg_f15x32/lv_root | display -

OLD VERSIONS OF VIRT-INSPECTOR

As described above, early versions of libguestfs shipped with a different virt-inspector program written in Perl (the current version is written in C). The XML output of the Perl virt-inspector was different and it could also output in other formats like text.

The old virt-inspector is no longer supported or shipped with libguestfs.

To confuse matters further, in Red Hat Enterprise Linux 6 we ship two versions of virt-inspector with different names:

virt-inspector     Old Perl version.
virt-inspector2    New C version.

EXIT STATUS

This program returns 0 if successful, or non-zero if there was an error.
