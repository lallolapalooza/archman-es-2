NOMBRE

virt-sysprep - Restablece, desconfigura o personaliza una máquina virtual para que se puedan crear clones

SINOPSIS

virt-sysprep [--opciones] -d nombre_dominio
virt-sysprep [--opciones] -a disco.img [-a disco.img ...]

ADVERTENCIA

Usar "virt-sysprep" en máquinas virtuales en vivo, o concurrentemente con otras herramientas de edición de disco, puede ser peligroso, pudiendo causar corrupción del disco. La máquina virtual debe estar apagada antes de usar este comando, y las imágenes de disco no deben ser editadas concurrentemente.

DESCRIPCIÓN

Virt-sysprep puede restablecer o desconfigurar una máquina virtual para que se puedan crear clones a partir de ella. Los pasos en este proceso incluyen la eliminación de claves de host SSH, la eliminación de la configuración persistente de MAC de red y la eliminación de cuentas de usuario. Virt-sysprep también puede personalizar una máquina virtual, por ejemplo, añadiendo claves SSH, usuarios o logotipos. Cada paso puede ser habilitado o deshabilitado según sea necesario.

Virt-sysprep modifica el huésped o la imagen de disco in situ. El huésped debe estar apagado. Si desea conservar el contenido existente del huésped, debe primero hacer una instantánea, copiar o clonar el disco. Ver "COPIAR Y CLONAR" abajo.

No necesita ejecutar virt-sysprep como root. De hecho, generalmente recomendamos que no lo haga. El momento en que podría querer ejecutarlo como root es cuando necesita root para acceder a la imagen de disco, pero incluso en este caso sería mejor cambiar los permisos de la imagen de disco para que sean escribibles por el usuario no root que ejecuta virt-sysprep.

"Sysprep" significa "herramienta de preparación del sistema". El nombre proviene del programa de Microsoft sysprep.exe que se utiliza para desconfigurar máquinas Windows en preparación para clonarlas. (Virt-sysprep no funciona en huéspedes de Microsoft Windows).

--operation operaciones
--operations operaciones
Elige qué operaciones de sysprep realizar. Da una lista separada por comas de operaciones, por ejemplo: 
--operations ssh-hostkeys,udev-persistent-net

esto habilitaría ÚNICAMENTE las operaciones "ssh-hostkeys" y "udev-persistent-net".

--operations te permite habilitar y deshabilitar cualquier operación, incluyendo las predeterminadas (que se intentarían al especificar ni --operations ni --enable) y todas las disponibles; anteponer un "-" delante de un nombre de operación lo elimina de la lista de operaciones habilitadas, mientras que los meta-nombres "defaults" y "all" representan respectivamente las operaciones habilitadas por defecto y todas las disponibles. Por ejemplo:

--operations firewall-rules,defaults,-tmp-files

habilitaría la operación "firewall-rules" (sin importar si está habilitada por defecto), todas las predeterminadas, y deshabilitaría la operación "tmp-files".

--operations se puede especificar varias veces; la primera vez el conjunto de operaciones habilitadas está vacío, mientras que cualquier --operations posterior afecta a las operaciones habilitadas hasta el momento.

Si la opción --operations no se da, entonces por defecto intentamos la mayoría de las operaciones de sysprep (ver --list-operations para mostrar cuáles están habilitadas).

Independientemente de la opción --operations, las operaciones de sysprep se omiten para algunos tipos de huéspedes.

--echo-keys
Al solicitar claves y contraseñas, virt-sysprep normalmente desactiva el eco para que no puedas ver lo que escribes. Si no te preocupas por los ataques de Tém-peste y no hay nadie más en la habitación, puedes especificar esta bandera para ver lo que escribes.
--format raw|qcow2|..
--format auto
El valor predeterminado para la opción -a es detectar automáticamente el formato de la imagen de disco. Usar esto fuerza el formato del disco para las opciones -a que siguen en la línea de comandos. Usar --format auto vuelve a la detección automática para las opciones -a subsiguientes.

Por ejemplo:

virt-sysprep --format raw -a disco.img

fuerza el formato raw (sin detección automática) para disk.img.

virt-sysprep --format raw -a disco.img --format auto -a another.img

fuerza el formato raw (sin detección automática) para disk.img y revierte a la detección automática para another.img.

Si tienes imágenes de disco de huésped en formato raw no confiables, deberías usar esta opción para especificar el formato del disco. Esto evita un posible problema de seguridad con huéspedes maliciosos (CVE-2010-3851).

COPIAR Y CLONAR

Virt-sysprep modifica la imagen de disco in situ. Si el disco que se está editando es el único disco del huésped, entonces el huésped se modifica permanentemente. Si desea conservar el contenido original de la imagen del disco, debe copiar o clonar la imagen del disco antes de usar virt-sysprep.

Por ejemplo, para crear un clon de un disco llamado "disk.img":

    cp disk.img disk.img.orig
    virt-sysprep -a disk.img.orig

Para clonar una máquina virtual de libvirt llamada "myvm":

    virsh domdiskcopy myvm hda --finish disk.img.new
    virt-sysprep -a disk.img.new

O, si el dominio está apagado:

    virt-clone --original myvm --file disk.img.new
    virt-sysprep -a disk.img.new

DIAGNÓSTICO

Virt-sysprep utiliza el registro de libguestfs para generar mensajes de diagnóstico y advertencia. Estos se envían a stderr de forma predeterminada. Puede redirigir la salida de registro a un archivo usando la opción "--log".

ESTADO DE SALIDA

Este comando devuelve 0 si el comando se completó con éxito, o un valor distinto de cero si ocurrió un error.

--list-operations
Lista las operaciones soportadas por el programa virt-sysprep.

Estas se listan una por línea, con uno o más campos separados por un solo espacio, ej.:

--mount-options mp:opts[;mp:opts;...]

--append-line FICHERO:LINEA (ver "personalizar" abajo)
Añade una sola línea de texto al "FICHERO". Si el archivo no termina ya con un salto de línea, se añade uno antes de la línea añadida. También se añade automáticamente un salto de línea al final de la cadena "LINEA".

Por ejemplo (asumiendo comillas normales del shell) este comando:

--append-line '/etc/hosts:10.0.0.1 foo'

añadirá "10.0.0.1 foo\n" o "\n10.0.0.1 foo\n" al archivo, este último solo si el archivo existente no termina ya con un salto de línea.

"\n" representa un carácter de salto de línea, que se adivina observando el contenido existente del archivo, por lo que este comando hace lo correcto para archivos que usan finales de línea de Unix o Windows. También funciona para archivos vacíos o inexistentes.

Para insertar varias líneas, usa la misma opción varias veces:

--append-line '/etc/hosts:10.0.0.1 foo'
--append-line '/etc/hosts:10.0.0.2 bar'

Para insertar una línea en blanco antes de la línea añadida, haz:

--append-line '/etc/hosts:'
--append-line '/etc/hosts:10.0.0.1 foo'

--password-crypto md5|sha256|sha512 (ver "customize" abajo)
Cuando las herramientas de virt cambian o establecen una contraseña en el invitado, esta opción establece el cifrado de esa contraseña a "md5", "sha256" o "sha512".

"sha256" y "sha512" requieren glibc ≥ 2.7 (consulte crypt(3) dentro del invitado).

"md5" funcionará con Linux invitados relativamente antiguos (ej. RHEL 3), pero no es seguro contra ataques modernos.

El valor predeterminado es "sha512" a menos que libguestfs detecte un invitado antiguo que no tuviera soporte para SHA-512, en cuyo caso usará "md5". Puede anular libguestfs especificando esta opción.

COPYING AND CLONING

The guest should not be considered for cloning and distribution, as it provides multiple parties with the same internal volume key, enabling any one such party to decrypt all the other clones. Refer to the LUKS FAQ for details.

Although virt-sysprep removes some sensitive information from the guest, it does not pretend to remove all of it. You should examine the "OPERATIONS" above and the guest afterwards.

Sensitive files are simply removed. The data they contained may still exist on the disk, easily recovered with a hex editor or undelete tool. The --scrub option can be used to scrub files instead of just deleting them. virt-sparsify(1) is another way to remove this content. See also the scrub(1) command to get rid of deleted content in directory entries and inodes.

RANDOM SEED

(This section applies to Linux guests only)

For supported guests, virt-sysprep writes a few bytes of randomness from the host into the guest’s random seed file.

If this is just done once and the guest is cloned from the same template, then each guest will start with the same entropy, and things like SSH host keys and TCP sequence numbers may be predictable.

Therefore you should arrange to add more randomness after cloning from a template too, which can be done by enabling just the customize module:

cp template.img newguest.img
virt-sysprep --enable customize -a newguest.img
