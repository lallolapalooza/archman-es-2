VAL(1P) Manual del programador de POSIX VAL(1P)

PROLOGO

Esta página del manual forma parte del Manual del Programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual correspondiente de Linux para obtener detalles sobre el comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

val — valida archivos SCCS (DESARROLLO)

SINOPSIS

val -
val [-s] [-m nombre] [-r SID] [-y tipo] archivo...

DESCRIPCION

La utilidad val determinará si el archivo especificado es un archivo SCCS que cumple las características especificadas por las opciones.

OPCIONES

La utilidad val se ajustará al volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidades, excepto que el uso del operando '-' no es estrictamente según lo previsto por las directrices (es decir, leer opciones y operandos de la entrada estándar).

Se admitirán las siguientes opciones:

-m nombre
Especifica un nombre, que se compara con la palabra clave SCCS %M% en archivo; consulte get.
-r SID
Especifica un SID (String de Identificación SCCS), un número de delta SCCS. Se realizará una comprobación para determinar si el SID es ambiguo (por ejemplo, -r 1 es ambiguo porque físicamente no existe pero implica 1.1, 1.2, y así sucesivamente, que pueden existir) o inválido (por ejemplo, -r 1.0 o -r 1.1.0 son inválidos porque ninguno de los casos puede existir como un número de delta válido). Si el SID es válido y no ambiguo, se realizará una comprobación para determinar si realmente existe.
-s
Silencia el mensaje de diagnóstico que normalmente se escribe en la salida estándar para cualquier error que se detecte al procesar cada archivo nombrado en una línea de comandos dada.
-y tipo
Especifica un tipo, que se comparará con la palabra clave SCCS %Y% en archivo; consulte get.

OPERANDOS

Se admitirán los siguientes operandos:

archivo
Una ruta de un archivo SCCS existente. Si aparece exactamente un operando archivo, y es '-', se leerá la entrada estándar: cada línea se procesará de forma independiente como si fuera una lista de argumentos de línea de comandos. (Sin embargo, la línea no se someterá a ninguna de las expansiones de palabras del shell, como la expansión de parámetros o la eliminación de comillas).

ENTRADA ESTÁNDAR

La entrada estándar será un archivo de texto utilizado solo cuando el operando archivo se especifica como '-'.

ARCHIVOS DE ENTRADA

Cualquier archivo SCCS procesado será un archivo de formato no especificado.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de val:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada).
LC_MENSAJES

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar y los mensajes informativos escritos en la salida estándar.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MENSAJES.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTÁNDAR

La salida estándar consistirá en mensajes informativos sobre ya sea:

1.
Cada archivo procesado
2.
Cada línea de comandos leída de la entrada estándar

Si no se utiliza la entrada estándar, para cada operando archivo que genere una discrepancia, la línea de salida tendrá el siguiente formato:

"%s: %s\n", <ruta>, <cadena no especificada>

Si se utiliza la entrada estándar, para cada línea de entrada que genere una discrepancia, la salida tendrá el siguiente formato:

"%s\n\n %s: %s\n", <entrada>, <ruta>, <cadena no especificada>

donde <entrada> es la línea de entrada menos su <salto de línea> final.

SALIDA DE ERROR

No se utiliza.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

El código de 8 bits devuelto por val será una disyunción de los posibles errores; es decir, puede interpretarse como una cadena de bits donde los bits establecidos se interpretan de la siguiente manera:

0x80 = Falta el argumento de archivo.
0x40 = Opción desconocida o duplicada.
0x20 = Archivo SCCS corrupto.
0x10 = No se puede abrir el archivo o no es SCCS.
0x08 = SID es inválido o ambiguo.
0x04 = SID no existe.
0x02 = %Y%, -y incompatibles.
0x01 = %M%, -m incompatibles.

Tenga en cuenta que val puede procesar dos o más archivos en una línea de comandos dada y puede procesar múltiples líneas de comandos (al leer la entrada estándar). En estos casos, se devolverá un código agregado: una OR lógica de los códigos generados para cada línea de comandos y archivo procesado.

CONSECUENCIAS DE LOS ERRORES

Predeterminado.

Las siguientes secciones son informativas.

USO DE APLICACIÓN

Dado que el estado de salida de val establece el bit 0x80, las aplicaciones de shell que comprueban "$?" no pueden saber si terminó debido a un argumento de archivo faltante o a la recepción de una señal.

EJEMPLOS

Si los archivos de SCCS son s.x (un archivo normal), s.y (un archivo normal) y s.z (un archivo corrupto), el siguiente comando podría producir la salida mostrada:

val - <<EOF
-y source s.x
-m y s.y
s.z
EOF
-y source s.x
    s.x: %Y%, -y mismatch
s.z
    s.z: corrupted SCCS file
