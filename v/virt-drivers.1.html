virt-drivers(1) Soporte de virtualización virt-drivers(1)

NOMBRE

virt-drivers - Detecta el cargador de arranque, el kernel y los controladores dentro de un invitado.

SINOPSIS

virt-drivers [--opciones] -d nombre_dominio
virt-drivers [--opciones] -a imagen_disco.img

DESCRIPCIÓN

Esta herramienta puede detectar el cargador de arranque, el kernel y los controladores dentro de algunos invitados a partir de solo la imagen del disco. Puede detectar, por ejemplo, si una imagen de disco necesita BIOS o UEFI para arrancar, y si soporta virtio o requiere dispositivos emulados más lentos.

Notas

Normalmente deberías distribuir metadatos del hipervisor (por ejemplo, XML de libvirt o OVF) junto con las imágenes de disco para indicarle al hipervisor cómo arrancarlas. Esta herramienta se utiliza cuando no se han proporcionado estos metadatos. Trabaja con el proveedor de la imagen de disco para que te proporcione los metadatos adecuados.

FORMATO XML

La salida es un documento XML. En el nivel superior enumera los sistemas operativos encontrados (lo mismo que virt-inspector(1)):

<operatingsystems>
  <operatingsystem>
    <root>/dev/sda2</root>
    <name>linux</name>
    <arch>x86_64</arch>
    <distro>fedora</distro>
    ...
  </operatingsystem>
  <operatingsystem>
    <root>/dev/sdb1</root>
    ...
  </operatingsystem>
</operatingsystems>

<firmware>

El elemento <firmware> enumera el firmware que se requiere para arrancar el invitado. Para UEFI, también mostrará la partición del sistema EFI ("ESP"). Los invitados pueden soportar múltiples firmwares de arranque. Por ejemplo, este invitado se detecta como que utiliza arranque UEFI, y la ESP de UEFI es la primera partición del primer disco:

<operatingsystems>
  <firmware type='uefi'>/dev/sda1</firmware>
  <operatingsystem>
    ...

<bootloader> y <kernel>

El elemento <bootloader> muestra el cargador de arranque encontrado en el invitado Linux. Si se conoce, puede contener información sobre qué kernels de Linux se proporcionan. Por ejemplo:

<operatingsystems>
  <firmware type='bios'/>
  <operatingsystem>
    <root>/dev/sda2</root>
    <name>linux</name>
    ...
    <bootloader type='grub2' config='/boot/grub2/grub.cfg'>
      <kernel>
        <name>kernel</name>
        <version>6.1.0-0.rc6.46.fc38.x86_64</version>
        <vmlinuz>/boot/vmlinuz-6.1.0-0.rc6.46.fc38.x86_64</vmlinuz>
        <modules>
          ...
        </modules>
        <supports_virtio_blk/>
        <supports_virtio_net/>
        ...
      </kernel>
    </bootloader>

Normalmente hay muchos más campos disponibles para invitados Linux, incluida una lista completa de módulos del kernel e información sobre el soporte para virtio. Para un ejemplo completo, consulta: https://github.com/libguestfs/guestfs-tools/tree/master/drivers

<drivers>

El elemento <drivers> enumera información sobre los controladores encontrados en invitados de Windows:

<operatingsystems>
  <firmware type='bios'/>
  <operatingsystem>
    <root>/dev/sda2</root>
    <name>windows</name>
    ...
    <drivers>
      <driver>
        <name>scsidev</name>
        <pci vendor='1077' device='1216' subsystem='8471101E'/>
        <pci vendor='1077' device='1216' subsystem='8493101E'/>
      </driver>
      ...
    </drivers>

El nombre del controlador (por ejemplo, "scsidev") corresponde al archivo .INF del controlador de Windows (por ejemplo, scsidev.inf). La lista de dispositivos PCI, USB, etc., son los dispositivos coincidentes que harían que este controlador se cargue al arrancar.

OPCIONES

--help
Muestra la ayuda.
-a archivo
--add archivo
Añade archivo que debería ser una imagen de disco de una máquina virtual.

El formato de la imagen de disco se detecta automáticamente. Para anular esto y forzar un formato particular, usa la opción --format.

-a URI
--add URI
Añade un disco remoto. El formato URI es compatible con guestfish. Ver "AÑADIENDO ALMACENAMIENTO REMOTO" en guestfish(1).
--blocksize 512
--blocksize 4096
Este parámetro establece el tamaño del sector de la imagen de disco añadida con la opción -a y se ignora para invitados libvirt añadidos con la opción -d. Ver también "guestfs_add_drive_opts" en guestfs(3).
--colors
--colours
Usa secuencias de color ANSI para colorear mensajes. Esto es lo predeterminado cuando la salida es una tty. Si la salida del programa se redirige a un archivo, las secuencias de color ANSI se deshabilitan a menos que uses esta opción.
-c URI
--connect URI
Si se usa libvirt, conéctate a la URI dada. Si se omite, nos conectamos al hipervisor libvirt predeterminado.

Si especificas dispositivos de bloque de invitado directamente (-a), entonces libvirt no se usa en absoluto.

-d invitado
--domain invitado
Añade todos los discos del invitado libvirt nombrado. Se pueden usar UUIDs de dominio en lugar de nombres.
--echo-keys
Al solicitar claves y contraseñas, virt-get-kernel normalmente desactiva la visualización para que no puedas ver lo que escribes. Si no te preocupan los ataques Tempest y no hay nadie más en la habitación, puedes especificar esta bandera para ver lo que escribes.
--format raw|qcow2|..
--format auto
El valor predeterminado para la opción -a es detectar automáticamente el formato de la imagen de disco. Usar esto fuerza el formato del disco para la opción -a en la línea de comandos.

Si tienes imágenes de disco de invitado en formato raw no confiables, deberías usar esta opción para especificar el formato del disco. Esto evita un posible problema de seguridad con invitados maliciosos (CVE-2010-3851).

--key SELECCIONADOR
Especifica una clave para LUKS, para abrir automáticamente un dispositivo LUKS al usar la inspección.
--key NOMBRE:key:CADENA_CLAVE
--key UUID:key:CADENA_CLAVE
--key all:key:CADENA_CLAVE
"NOMBRE" es el nombre del dispositivo libguestfs (por ejemplo, "/dev/sda1"). "UUID" es el UUID del dispositivo. "all" significa probar la clave contra cualquier dispositivo cifrado.

Usa la "CADENA_CLAVE" especificada como contraseña.

--key NOMBRE:file:NOMBRE_ARCHIVO
--key UUID:file:NOMBRE_ARCHIVO
--key all:file:NOMBRE_ARCHIVO
Lee la contraseña desde NOMBRE_ARCHIVO.
-l
--list
Lista los invitados disponibles en el hipervisor libvirt. Esta opción es útil para ver los nombres o UUIDs de los invitados que se pueden usar con la opción -d.
-m montaje
--mount montaje
Monta el sistema de archivos especificado por montaje. El formato del montaje es: <disco>[:<ruta>][:<opciones>].

Ver "MONTANDO SISTEMAS DE ARCHIVOS" en guestfish(1).

-p
--preorder
Inspecciona los invitados en el orden de los nodos preordenados del árbol de dispositivos. Esto es más rápido si el dispositivo que te interesa está cerca de la raíz del árbol de dispositivos.
-r
--read-only
Abre el disco en modo de solo lectura. Esto es el valor predeterminado.
-w
--rw
Abre el disco en modo de lectura/escritura. Ten cuidado al usar esta opción, ya que los cambios realizados en el disco pueden hacer que el sistema invitado no arranque.
--rpc tipo
Selecciona el tipo de RPC a usar. Los tipos válidos son unix y tcp. El valor predeterminado es unix.
--selinux CONTEXTO
Establece el contexto SELinux para cualquier archivo creado.
--timezone ZONA_HORARIA
Establece la zona horaria del invitado. Esto se usa principalmente para darle información al cargador de arranque para que pueda configurar el reloj del sistema.
--timeout SEGUNDOS
Establece el tiempo de espera para operaciones de red o de disco. El valor predeterminado es 120 segundos.
--verbose
--verbose level
Habilita la depuración detallada. Puedes especificar un nivel de 0 a 6. Cuanto mayor sea el nivel, más detallada será la salida. El valor predeterminado es 0.
--version
Muestra la versión del programa e información de licencia y sale.

ESTADO DE SALIDA

En caso de éxito, virt-drivers devuelve 0. En caso de error, devuelve un código de error distinto de cero.
