VFS_SHADOW_COPY2(8) Herramientas de Administración del Sistema VFS_SHADOW_COPY2(8)

NOMBRE

vfs_shadow_copy2 - Exponer instantáneas a clientes de Windows como copias sombra.

SINOPSIS

objetos vfs = shadow_copy2

DESCRIPCIÓN

Este módulo VFS es parte del conjunto samba(7).

El módulo VFS vfs_shadow_copy2 ofrece una funcionalidad similar a los servicios de Sombra de Copia de Microsoft. Cuando se configura correctamente, este módulo permite a los clientes de Sombra de Copia de Microsoft navegar por las instantáneas del sistema de archivos como "copias sombra" en los recursos compartidos de Samba.

Esta es una segunda implementación de un módulo de copia sombra que tiene las siguientes características adicionales (en comparación con el módulo original shadow_copy(8)):

1.Ya no es necesario poblar el directorio raíz del recurso compartido con enlaces simbólicos a las instantáneas si el sistema de archivos almacena las instantáneas en otro lugar. En su lugar, puede configurar el módulo de forma flexible dónde buscar las instantáneas del sistema de archivos. Esto puede ser muy importante cuando se tienen miles de recursos compartidos o se utiliza [homes].
2.Los directorios de instantáneas no necesitan estar en un lugar central fijo, sino que pueden ubicarse en cualquier parte del árbol de directorios. Este modo ayuda a dar soporte a sistemas de archivos que ofrecen instantáneas de subárboles particulares, por ejemplo, los conjuntos de archivos independientes de GPFS.
3.Nombres de fantasía para las instantáneas: las instantáneas pueden nombrarse en cualquier formato compatible con las conversiones de str[fp]time.
4.Las marcas de tiempo se pueden representar en hora local en lugar de UTC.
5.El número de inodo de los archivos puede modificarse opcionalmente para que sea diferente del original. Esto corrige el botón 'restaurar' en la GUI de Windows para que funcione sin una violación de uso compartido al servir desde sistemas de archivos, como GPFS, que devuelven el mismo dispositivo y número de inodo para el archivo de instantánea y el original.
6.Los resultados de la copia sombra se ordenan por defecto antes de enviarlos al cliente. Esto es beneficioso para sistemas de archivos que no leen directorios alfabéticamente (el valor predeterminado de Unix). El orden de clasificación se puede configurar y la clasificación se puede desactivar por completo si el sistema de archivos ordena su lista de directorios.

Este módulo es apilable.

CONFIGURACIÓN

vfs_shadow_copy2 depende de una implementación de instantáneas del sistema de archivos. Muchos sistemas de archivos comunes tienen soporte nativo para esto.

Las instantáneas del sistema de archivos deben estar disponibles en directorios especialmente nombrados para ser reconocidas por vfs_shadow_copy2. Estos directorios de instantáneas suelen ser un subdirectorio directo del punto de montaje de la raíz del recurso compartido, pero existen otros modos que se pueden configurar con los parámetros descritos en detalle a continuación.

Se espera que la instantánea en un momento dado se encuentre en un subdirectorio del directorio de instantáneas, donde se espera que el directorio de la instantánea sea una versión formateada de la hora de la instantánea. El formato predeterminado, que se puede cambiar con la opción shadow:format, es @GMT-YYYY.MM.DD-hh.mm.ss, donde:

•YYYY es el año de 4 dígitos
•MM es el mes de 2 dígitos
•DD es el día de 2 dígitos
•hh es la hora de 2 dígitos
•mm es el minuto de 2 dígitos
•ss es el segundo de 2 dígitos.

La convención de nomenclatura de instantáneas de vfs_shadow_copy2 se puede producir con el siguiente comando date(1):

TZ=GMT date +@GMT-%Y.%m.%d-%H.%M.%S

OPCIONES

shadow:mountpoint = PUNTO_MONTAJE

Con este parámetro, se puede especificar el punto de montaje del sistema de archivos que contiene la ruta del recurso compartido. Normalmente, este punto de montaje se detecta automáticamente. Pero para algunas constelaciones, en particular pruebas, puede ser conveniente poder especificarlo.

Ejemplo: shadow:mountpoint = /ruta/al/sistema/de/archivos

Predeterminado: shadow:mountpoint = NO ESPECIFICADO

shadow:snapdir = DIRECTORIO_INSTANTANEAS

Ruta al directorio donde el sistema de archivos de la compartición mantiene sus instantáneas. Si se especifica una ruta absoluta, se utiliza tal cual. Si se especifica una ruta relativa, entonces se toma relativa al punto de montaje del sistema de archivos de la raíz de la compartición. (Ver shadow:mountpoint).

Tenga en cuenta que shadow:snapdirseverywhere depende de este parámetro y necesita una ruta relativa. Especificar una ruta absoluta deshabilita shadow:snapdirseverywhere.

Tenga en cuenta que la opción shadow:crossmountpoints también requiere un snapdir relativo. Especificar una ruta absoluta deshabilita shadow:crossmountpoints.

Ejemplo: shadow:snapdir = /alguna/ruta/absoluta

Predeterminado: shadow:snapdir = .instantaneas

shadow:basedir = DIRECTORIO_BASE

La opción basedir permite especificar un directorio entre el punto de montaje del recurso compartido y la raíz del recurso compartido, relativo al cual se toman las instantáneas del sistema de archivos.

Por ejemplo, si

•basedir = punto_montaje/basedir_relativo
•raiz_recurso_compartido = basedir_directorio_base/raiz_recurso_compartido_relativo
•ruta_instantanea = punto_montaje/directorio_instantaneas

o ruta_instantanea = directorio_instantaneas si directorio_instantaneas es absoluto

entonces la instantánea de un archivo = punto_montaje/basedir_relativo/raiz_recurso_compartido_relativo/archivo_relativo en un momento TIME se encontrará en ruta_instantanea/TOKEN_GMT_FS(TIME)/raiz_recurso_compartido_relativo/archivo_relativo, donde TOKEN_GMT_FS(TIME) es la cadena de marca de tiempo que pertenece a TIME en el formato requerido por el sistema de archivos. (Ver shadow:format.)

El valor predeterminado para basedir es el punto de montaje del sistema de archivos de la raíz del recurso compartido (ver shadow:mountpoint).

Tenga en cuenta que las opciones shadow:snapdirseverywhere y shadow:crossmountpoints son incompatibles con shadow:basedir y deshabilitan la configuración de basedir.

shadow:snapsharepath = RUTA_COMPARTIR_INSTANTANEA

Con este parámetro, se puede especificar la ruta del directorio raíz del recurso compartido en las instantáneas, relativo al directorio raíz de la instantánea. Es un método alternativo a shadow:basedir, que permite un mayor control.

Por ejemplo, si dentro de cada instantánea los archivos del recurso compartido tienen un prefijo path/to/share/, entonces shadow:snapsharepath se puede establecer en path/to/share.

Con este parámetro, ya no se asume que una instantánea representa una imagen del sistema de archivos original o una parte de él. Por ejemplo, un sistema podría realizar copias de seguridad solo de los archivos contenidos en los recursos compartidos, y luego exponer los archivos de copia de seguridad en una estructura lógica:

•recurso_compartido1/
•recurso_compartido2/
•.../
Tenga en cuenta que las opciones shadow:snapdirseverywhere y shadow:basedir son incompatibles con shadow:snapsharepath y deshabilitan la configuración de shadow:snapsharepath.

Ejemplo: shadow:snapsharepath = ruta/a/compartir

Predeterminado: shadow:snapsharepath = NO ESPECIFICADO

shadow:sort = asc/desc

Por defecto, este módulo ordena los datos de la copia sombra alfabéticamente antes de enviarlos al cliente. Con este parámetro, se puede especificar el orden de clasificación. Los valores conocidos posibles son desc (descendente, el predeterminado) y asc (ascendente). Si el sistema de archivos lista los directorios ordenados alfabéticamente, se puede desactivar la clasificación en este módulo especificando cualquier otro valor.

Ejemplo: shadow:sort = asc

Ejemplo: shadow:sort = none

Predeterminado: shadow:sort = desc

shadow:localtime = yes/no

Este es un parámetro opcional que indica si los nombres de las instantáneas están en UTC/GMT o en hora local. Si está deshabilitado, se espera UTC/GMT.

shadow:localtime = no

shadow:format = especificación de formato para nombres de instantáneas

Este es un parámetro opcional que especifica la especificación de formato para nombrar las instantáneas en el sistema de archivos. El formato debe ser compatible con las especificaciones de conversión reconocidas por str[fp]time.

Predeterminado: shadow:format = "@GMT-%Y.%m.%d-%H.%M.%S"

shadow:sscanf = yes/no

Este parámetro se puede utilizar para especificar que la hora en la cadena de formato se da como un entero sin signo (%lu) en lugar de un tiempo que strptime() pueda analizar. El resultado debe ser un tiempo Unix time_t.

Predeterminado: shadow:sscanf = no

vfs_shadow_copy2(8) — shadow:fixinodes

NAME

vfs_shadow_copy2 — VFS module that provides shadow copies (like Windows VSS)

SYNOPSIS

vfs_shadow_copy2 is a VFS module that can be loaded globally, per-share, or per-VFS module.

Configuration is done in smb.conf.

Example:

        [global]
        vfs objects = shadow_copy2

DESCRIPTION

The vfs_shadow_copy2 module provides support for snapshotting filesystems. It can be used to provide shadow copy functionality similar to that of Windows Volume Shadow Copy Service (VSS). This allows users to browse previous versions of files. The module supports multiple snapshot directories, can be configured to look for snapshots in different locations, and offers options for sorting and filtering snapshots.

CONFIGURATION

The following parameters can be used to configure the behaviour of vfs_shadow_copy2:

OPTIONS

shadow:fixinodes = yes/no

This option is only relevant for specific snapshot systems where the snapshots have the same device:inode number as the original files (such as happens with GPFS snapshots). If you don't set this option then the 'restore' button in the shadow copy UI will fail with a sharing violation.

Default: shadow:fixinodes = no

shadow:snapdirseverywhere = yes/no

If you enable shadow:snapdirseverywhere then this module will look out for snapshot directories in the current working directory and all parent directories, stopping at the mount point by default. But see shadow:crossmountpoints how to change that behaviour.

An example where this is needed are independent filesets in IBM's GPFS, but other filesystems might support snapshotting only particular subtrees of the filesystem as well.

Note that shadow:snapdirseverywhere depends on shadow:snapdir and needs it to be a relative path. Setting an absolute snapdir path disables shadow:snapdirseverywhere.

Note that this option is incompatible with the shadow:basedir option and removes the shadow:basedir setting by itself.

Example: shadow:snapdirseverywhere = yes

Default: shadow:snapdirseverywhere = no

shadow:crossmountpoints = yes/no

This option is effective in the case of shadow:snapdirseverywhere = yes. Setting this option makes the module not stop at the first mount point encountered when looking for snapdirs, but lets it search potentially all through the path instead.

An example where this is needed are independent filesets in IBM's GPFS, but other filesystems might support snapshotting only particular subtrees of the filesystem as well.

Note that shadow:crossmountpoints depends on shadow:snapdir and needs it to be a relative path. Setting an absolute snapdir path disables shadow:crossmountpoints.

Note that this option is incompatible with the shadow:basedir option and removes the shadow:basedir setting by itself.

Example: shadow:crossmountpoints = yes

Default: shadow:crossmountpoints = no

shadow:snapprefix

With growing number of snapshots file-systems need some mechanism to differentiate one set of snapshots from other, e.g. monthly, weekly, manual, special events, etc. Therefore these file-systems provide different ways to tag snapshots, e.g. provide a configurable way to name snapshots, which is not just based on time. With only shadow:format it is very difficult to filter these snapshots. With this optional parameter, one can specify a variable prefix component for names of the snapshot directories in the file-system. If this parameter is set, together with the shadow:format and shadow:delimiter parameters it determines the possible names of snapshot directories in the file-system. The option only supports Basic Regular Expression (BRE).

shadow:delimiter

This optional parameter is used as a delimiter between shadow:snapprefix and shadow:format. This parameter is used only when shadow:snapprefix is set.

Default: shadow:delimiter = "_GMT"

EXAMPLES

Add shadow copy support to user home directories:

        [homes]
	vfs objects = shadow_copy2
	shadow:snapdir = /data/snapshots
	shadow:basedir = /data/home
	shadow:sort = desc

CAVEATS

This is not a backup, archival, or version control solution.

With Samba or Windows servers, vfs_shadow_copy2 is designed to be an end-user tool only. It does not replace or enhance your backup and archival solutions and should in no way be considered as such. Additionally, if you need version control, implement a version control system.
