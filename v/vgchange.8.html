vgchange cambia atributos del VG, cambia la activación de LV en el kernel e incluye otras utilidades para el mantenimiento del VG.

OPTIONS

-a|--activate y|n|ay
Cambia el estado activo de los LV. Un LV activo se puede utilizar a través de un dispositivo de bloque, lo que permite acceder a los datos del LV. y hace que los LV estén activos o disponibles. n hace que los LV estén inactivos o no disponibles. El dispositivo de bloque para el LV se añade o se elimina del sistema utilizando device-mapper en el kernel. También se añade/elimina un enlace simbólico /dev/VGName/LVName que apunta al nodo del dispositivo. Todo el software y los scripts deben acceder al dispositivo a través del enlace simbólico y presentarlo como el nombre del dispositivo. La ubicación y el nombre del nodo del dispositivo subyacente pueden depender de la distribución, la configuración (por ejemplo, udev) o la versión de lanzamiento. ay especifica la autoactivación, que es utilizada por los comandos de activación generados por el sistema. Por defecto, los LV se autoactivan. Se puede establecer una propiedad de autoactivación en un VG o LV para deshabilitar la autoactivación; consulte --setautoactivation y|n en vgchange, lvchange, vgcreate y lvcreate. Muestre la propiedad con vgs o lvs "-o autoactivation". La lista auto_activation_volume_list de lvm.conf(5) incluye los nombres de los VG o LV que deben ser autoactivados, y todo lo que no está en la lista no se autoactiva. Cuando auto_activation_volume_list no está definido (por defecto), no tiene ningún efecto. Si auto_activation_volume_list está definido y vacío, ningún LV se autoactiva. Los elementos incluidos en auto_activation_volume_list no se autoactivarán si la propiedad de autoactivación se ha deshabilitado. Consulte lvmlockd(8) para más información sobre las opciones de activación ey y sy para los VG compartidos.
--activationmode partial|degraded|complete
Determina si se permite la activación de LV cuando faltan PV, por ejemplo, debido a un fallo del dispositivo. complete solo permite activar los LV sin PV faltantes y es el modo más restrictivo. degraded permite activar los LV RAID con PV faltantes. (Esto no incluye el tipo "mirror", consulte "raid1" en su lugar.) partial permite activar cualquier LV con PV faltantes y solo debe usarse para recuperación o reparación. Para obtener el valor predeterminado, consulte lvm.conf(5) activation_mode. Consulte lvmraid(7) para más información.
--addtag Tag
Añade una etiqueta a un PV, VG o LV. Esta opción se puede repetir para añadir varias etiquetas a la vez. Consulte lvm(8) para obtener información sobre las etiquetas.
--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Determina la política de asignación cuando un comando necesita asignar Extensiones Físicas (PE) del VG. Cada VG y LV tiene una política de asignación que se puede cambiar con vgchange/lvchange, o anular en la línea de comandos. normal aplica reglas de sentido común, como no colocar franjas paralelas en el mismo PV. inherit aplica la política del VG a un LV. contiguous requiere que las nuevas PE se coloquen adyacentes a las PE existentes. cling coloca las nuevas PE en el mismo PV que las PE existentes en la misma franja del LV. Si hay suficientes PE para una asignación, pero normal no las utiliza, anywhere las utilizará aunque reduzca el rendimiento, por ejemplo, colocando dos franjas en el mismo PV. Los argumentos opcionales de PV posicionales en la línea de comandos también se pueden utilizar para limitar qué PV utilizará el comando para la asignación. Consulte lvm(8) para más información sobre la asignación.
--autoactivation String
Especifica si se está utilizando la autoactivación desde un evento. Esto permite que el comando aplique configuraciones específicas para la activación basada en eventos, como optimizaciones de escaneo de dispositivos utilizando archivos pvs_online creados por escaneos de PV basados en eventos.
-A|--autobackup y|n
Especifica si los metadatos deben ser respaldados automáticamente después de un cambio. ¡Se recomienda encarecidamente habilitar esto! Consulte vgcfgbackup(8) para más información.
--commandprofile String
El perfil de comando a utilizar para la configuración del comando. Consulte lvm.conf(5) para más información sobre perfiles.
--config String
Configuraciones del comando. Estas anulan la configuración de lvm.conf(5). El argumento String utiliza el mismo formato que lvm.conf(5), o puede usar la sintaxis de sección/campo. Consulte lvm.conf(5) para más información sobre la configuración.
-d|--debug ...
Establece el nivel de depuración. Repetir de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--deltag Tag
Elimina una etiqueta de un PV, VG o LV. Esta opción se puede repetir para eliminar varias etiquetas a la vez. Consulte lvm(8) para obtener información sobre las etiquetas.
--detachprofile
Separa un perfil de metadatos de un VG o LV. Consulte lvm.conf(5) para más información sobre perfiles.
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados aparecerán como faltantes. Esta opción se puede repetir, o acepta una lista de dispositivos separada por comas. Esto anula el archivo de dispositivos.
--devicesfile String
Un archivo que lista los dispositivos que LVM debe usar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración devices/devicesfile y devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si se establece en no, el comando no intentará usar device-mapper. Para pruebas y depuración.
-f|--force ...
Anula varias comprobaciones, confirmaciones y protecciones. Úselo con extrema precaución.
-h|--help
Muestra el texto de ayuda.
-K|--ignoreactivationskip
Ignora el indicador LV "activation skip" durante la activación para permitir la activación de LVs con el indicador establecido.
--ignorelockingfailure
Permite que un comando continúe con operaciones de metadatos de solo lectura después de fallos de bloqueo.
--ignoremonitoring
No interactúa con dmeventd a menos que se especifique --monitor. No use esto si dmeventd ya está monitoreando un dispositivo.
--journal String
Registra información en el diario de systemd. Esta información se suma a la información habilitada por la configuración de registro/diario de lvm.conf. command: registra información sobre el comando. output: registra la salida predeterminada del comando. debug: registra la depuración completa del comando.
--lockopt String
Se utiliza para pasar opciones para casos especiales a lvmlockd. Consulte lvmlockd(8) para más información.
--lockstart
Inicia el espacio de bloqueo de un VG compartido en lvmlockd. Los bloqueos de lvmlockd estarán disponibles para el VG, lo que permitirá a LVM utilizar el VG. Consulte lvmlockd(8) para más información.
--lockstop
Detie
p el espacio de bloqueo de un VG compartido en lvmlockd. Los bloqueos de lvmlockd se vuelven no disponibles para el VG, impidiendo que LVM utilice el VG. Consulte lvmlockd(8) para obtener más información.
--locktype sanlock|dlm|none
Cambia el tipo de bloqueo del VG a o desde un tipo de bloqueo compartido utilizado con lvmlockd. Consulte lvmlockd(8) para obtener más información.
-l|--logicalvolume Número
Establece el número máximo de LVs permitidos en un VG.
--longhelp
Muestra el texto de ayuda largo.
--majoritypvs
Cambia el ID del sistema del VG si la mayoría de los PV en el VG están presentes (uno más de la mitad).
-p|--maxphysicalvolumes Número
Establece el número máximo de PV que pueden pertenecer al VG. El valor 0 elimina cualquier limitación. Para un gran número de PV, consulte también las opciones --pvmetadatacopies y --vgmetadatacopies para mejorar el rendimiento.
--metadataprofile Cadena
El perfil de metadatos a utilizar para la configuración del comando. Consulte lvm.conf(5) para obtener más información sobre los perfiles.
--monitor y|n
Inicia (yes) o detiene (no) el monitoreo de un LV con dmeventd. dmeventd monitorea eventos del kernel para un LV y realiza mantenimiento automatizado para el LV en respuesta a eventos específicos. Consulte dmeventd(8) para obtener más información.
--nohints
No utiliza el archivo de pistas para localizar dispositivos para PV. Un comando puede leer más dispositivos para encontrar PV cuando no se utilizan pistas. El comando aún realizará la invalidación estándar del archivo de pistas cuando sea apropiado.
--nolocking
Deshabilita el bloqueo. Úselo con precaución, los comandos concurrentes pueden producir resultados incorrectos.
--noudevsync
Deshabilita la sincronización de udev. El proceso no esperará la notificación de udev. Continuará independientemente de cualquier posible procesamiento de udev en segundo plano. Utilice esto solo si udev no se está ejecutando o tiene reglas que ignoran los dispositivos que LVM crea.
-P|--partial
Los comandos harán todo lo posible para activar LVs con extents de PV faltantes. Los extents faltantes pueden ser reemplazados con segmentos de error o cero según la configuración de missing_stripe_filler. Los metadatos no se pueden cambiar con esta opción.
--persist Cadena
Operación de Reserva Persistente. start: registrar clave local y adquirir reserva. stop: desregistrar clave local, liberando la reserva. remove: preemptar y abortar otra clave. clear: eliminar reserva y claves. check: verificar si se inició. autostart: iniciar si está configurado el indicador autostart del VG. Se debe configurar lvmlocal.conf pr_key o host_id para usar PR. Para VGs locales, se utiliza Write Exclusive (WE), y para VGs compartidos Write Exclusive, all registrants (WEAR) se utiliza. Use --setpersist para automatizar y/o requerir PR.
-s|--physicalextentsize Tamaño[m|UNIDAD]
Establece el tamaño de extent físico de los PV en el VG. El valor debe ser una potencia de 2 de al menos 1 sector (donde el tamaño del sector es el tamaño de sector más grande de los PV actualmente utilizados en el VG), o al menos 128 KiB. Una vez que este valor se ha establecido, es difícil cambiarlo sin recrear el VG, a menos que no se necesiten mover extents. Antes de aumentar el tamaño del extent físico, es posible que deba usar lvresize, pvresize y/o pvmove para que todo encaje. Por ejemplo, cada rango contiguo de extents utilizados en un LV debe comenzar y terminar en un límite de extent.
--poll y|n
Cuando es sí, inicia la transformación en segundo plano de un LV. Una transformación incompleta, por ejemplo, pvmove o lvconvert interrumpido por reinicio o fallo, puede reiniciarse desde el último punto de control con --poll y. Cuando es no, la transformación en segundo plano de un LV no ocurrirá, y la transformación no se completará. Puede no ser apropiado sondear un LV inmediatamente después de la activación, en cuyo caso --poll n puede usarse para posponer la sondeo hasta un comando posterior --poll y.
--profile Cadena
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
--pvmetadatacopies 0|1|2
El número de áreas de metadatos que se reservan en un PV para almacenar los metadatos del VG. Cuando es 2, una copia de los metadatos del VG se almacena al principio del PV y una segunda copia se almacena al final. Cuando es 1, una copia de los metadatos del VG se almacena al principio del PV. Cuando es 0, no se almacenan copias de los metadatos del VG en el PV dado. Esto puede ser útil en VGs que contienen muchos PVs (esto impone limitaciones a la capacidad de usar vgsplit más tarde).
-q|--quiet ...
Suprime la salida y los mensajes de registro. Anula --debug y --verbose. Repita una vez para suprimir también cualquier solicitud con la respuesta 'no'.
--readonly
Impide que el comando realice cambios, incluyendo la activación y las actualizaciones de metadatos. (Consulte --permission r para LVs de solo lectura).
--refresh
Si el LV está activo, recarga sus metadatos. En un entorno donde udev se utiliza para gestionar el contenido de /dev, se recomienda encarecidamente el uso de esta opción. Esto se debe a que refresh también regenera eventos de udev para un LV basándose en las reglas de udev existentes que se aplican para establecer el contenido y los permisos de /dev. Además, esta operación puede ser útil si algo ha salido mal, o si se está utilizando alguna forma de compartición manual de LVs.
--removekey Cadena
Una clave de reserva persistente para eliminar.
--reportformat basic|json|json_std
Anula el formato de salida actual para los informes, que se define globalmente mediante la configuración report/output_format en lvm.conf(5). basic es el formato original con columnas y filas. Si hay más de un informe por comando, cada informe va precedido del nombre del informe para su identificación. json produce la salida del informe en formato JSON. json_std produce la salida del informe en formato JSON que es más compatible con el estándar JSON. Consulte lvmreport(7) para obtener más información.
-x|--resizeable y|n
Habilita o deshabilita la adición o eliminación de PV a/desde un VG (mediante vgextend/vgreduce).
-S|--select Cadena
Selecciona objetos para procesar y reportar basándose en criterios especificados. La sintaxis de los criterios se describe en --select help y lvmreport(7). Para los comandos de reporte, se muestra una fila por cada objeto que coincida con los criterios. Consulte --options help para ver los campos de objetos seleccionables. Las filas se pueden mostrar con un campo adicional "selected" (-o selected) que muestra 1 si la fila coincide con la selección y 0 en caso contrario. Para comandos que no son de reporte y que procesan entidades LVM, la selección se utiliza para elegir los elementos a procesar.
--setautoactivation y|n
Establece la propiedad de autoactivación en un VG o LV. Muestra la propiedad con vgs o lvs "-o autoactivation". Cuando la propiedad de autoactivación está deshabilitada, el VG o LV no será activado por un comando que realice autoactivación (vgchange, lvchange o pvscan usando -aay). Si la autoactivación está deshabilitada en un VG, ningún LV se autoactivará en ese VG, y la propiedad de autoactivación del LV no tendrá efecto. Si la autoactivación está habilitada en un VG, la autoactivación puede deshabilitarse para LVs individuales.
--setlockargs Cadena
Agrega o elimina configuraciones de lock_args para un VG compartido. Los lock_args determinan el comportamiento del gestor de bloqueos para el VG. Estas configuraciones solo están permitidas para lock_type sanlock. persist: usa reservas persistentes para la recuperación de bloqueos. lvmlockd hará preempt-abort de la reserva persistente de un propietario de bloqueo fallido para que el bloqueo pueda adquirirse. notimeout: usa bloqueos que no caducan cuando el propietario falla. En este caso, un bloqueo propiedad de un host fallido solo se puede adquirir utilizando la función persist. nopersist: no use la función persist. timeout: no use la función notimeout. El comportamiento predeterminado sin configuraciones es: nopersist y timeout.
--setpersist Cadena
Establece o borra indicadores para controlar el comportamiento de la reserva persistente. y: establece los indicadores require y autostart. n: borra los indicadores require y autostart. require: establece el indicador, PR será requerido para escribir o activar el VG. norequire: borra el indicador require. autostart: establece el indicador, PR se iniciará automáticamente. noautostart: borra el indicador autostart. ptpl: establece el indicador, usa persistencia a través de pérdida de energía en los dispositivos. noptpl: borra el indicador ptpl. Cuando autostart está habilitado, los comandos autoactivation y auto-lockstart iniciarán PR primero. lvmlocal.conf pr_key o host_id deben configurarse para usar PR. Para VGs locales, se recomienda también habilitar system_id.
--sysinit
Indica que vgchange/lvchange se está invocando desde scripts de inicialización temprana del sistema (por ejemplo, rc.sysinit o un initrd), antes de que los sistemas de archivos escribibles estén disponibles. Como tales, algunas funcionalidades deben deshabilitarse y esta opción actúa como un atajo que selecciona un conjunto apropiado de opciones. Actualmente, esto equivale a usar --ignorelockingfailure, --ignoremonitoring, --poll n, y establecer la variable de entorno LVM_SUPPRESS_LOCKING_FAILURE_MESSAGES. vgchange/lvchange omiten la autoactivación y la delegan a la autoactivación de pvscan.
--systemid Cadena
Cambia el ID del sistema del VG. El uso de esta opción requiere precaución ya que el VG puede volverse ajeno al host que ejecuta el comando, dejando al host incapaz de acceder a él. Consulte lvmsystemid(7) for more information.
-t|--test
Run in test mode. Commands will not update metadata. This is implemented by disabling all metadata writing but nevertheless returning success to the calling function. This may lead to unusual error messages in multi-stage operations if a tool relies on reading back metadata it believes has changed but hasn't.
-u|--uuid
Generate new random UUID for specified VGs.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
--[vg]metadatacopies all|unmanaged|Number
Number of copies of the VG metadata that are kept. VG metadata is kept in VG metadata areas on PVs in the VG, i.e. reserved space at the start and/or end of the PVs. Keeping a copy of the VG metadata on every PV can reduce performance in VGs containing a large number of PVs. When this number is set to a non-zero value, LVM will automatically choose PVs on which to store metadata, using the metadataignore flags on PVs to achieve the specified number. The number can also be replaced with special string values: unmanaged causes LVM to not automatically manage the PV metadataignore flags. all causes LVM to first clear the metadataignore flags on all PVs, and then to become unmanaged.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

VG
Volume Group name. See lvm(8) for valid names.
Tag
Tag name. See lvm(8) for information about tag names and using tags in place of a VG, LV or PV.
Select
Select indicates that a required positional parameter can be omitted if the --select option is used. No arg appears in this position.
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.

NOTES

If vgchange recognizes COW snapshot LVs that were dropped because they ran out of space, it displays a message informing the administrator that the snapshots should be removed.

EXAMPLES

Activate all LVs in all VGs on all existing devices.
vgchange -a y

Change the maximum number of LVs for an inactive VG.
vgchange -l 128 vg00
