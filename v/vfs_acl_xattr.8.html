VFS_ACL_XATTR(8) Herramientas de administración del sistema VFS_ACL_XATTR(8)

NOMBRE

vfs_acl_xattr - Guarda ACLs de NTFS en Atributos Extendidos (EAs)

SINOPSIS

objetos vfs = acl_xattr

DESCRIPCIÓN

Este módulo VFS forma parte del conjunto de herramientas de samba(7).

Este módulo está hecho para sistemas que no soportan ACLs estandarizadas de NFS4, sino solo una implementación obsoleta del borrador de ACL POSIX. Este es generalmente el caso en sistemas Linux. Los sistemas que lo soportan simplemente usan ACLs de NFSv4 directamente en lugar de este módulo. Dicho soporte generalmente lo proporciona el módulo VFS del sistema de archivos específico del sistema de archivos subyacente que soporta ACLs de NFS4.

El módulo VFS vfs_acl_xattr almacena Listas de Control de Acceso (ACLs) de NTFS en Atributos Extendidos (EAs). Esto permite el mapeo completo de las ACLs de Windows en servidores Samba, incluso si la implementación de ACL no es capaz de hacerlo.

Las ACLs de NT se almacenan en el atributo extendido security.NTACL de los archivos y directorios en un formato que contiene el SID de Windows que representa a los usuarios y grupos de la ACL. Esto es diferente de los uid y gid almacenados en las ACLs del sistema de archivos local, y el mapeo de usuarios y grupos a SIDs de Windows debe ser coherente para mantener el significado de la ACL de NT almacenada. Ese atributo extendido *no* es listado por el comando Linux getfattr -d nombre_archivo. Para mostrar el valor actual, se debe especificar el nombre del EA (por ejemplo, getfattr -n security.NTACL nombre_archivo).

Este módulo fuerza los siguientes parámetros:

•inherit acls = true
•dos filemode = true
•force unknown acl user = true

Este módulo es apilable.

OPCIONES

acl_xattr:security_acl_name = NOMBRE

Esta opción permite redefinir la ubicación predeterminada para el atributo extendido (xattr) de NTACL. Si no se establece, los xattrs NTACL se escriben en security.NTACL, que es una ubicación protegida, lo que significa que el contenido del atributo security.NTACL no es accesible para usuarios normales fuera de Samba. Cuando esta opción se establece para usar un valor definido por el usuario, por ejemplo, user.NTACL, entonces cualquier usuario puede acceder y sobrescribir esta información. El módulo impide el acceso a este xattr a través de SMB, pero el xattr aún puede ser accedido por otros medios (por ejemplo, acceso local, SSH, NFS). Esta opción solo debe utilizarse cuando esta consecuencia se comprende claramente y cuando se toman precauciones específicas para evitar comprometer el contenido de la ACL.

acl_xattr:ignore system acls = [yes|no]

Cuando se establece en yes, este módulo *no* realizará un esfuerzo por mapear desde/hacia la capa de ACL del borrador POSIX. El valor predeterminado es no, lo que significa que Samba sigue estableciendo y evaluando tanto las ACLs del sistema como las ACLs de NT. Esto es mejor si necesita que las ACLs del sistema también se establezcan para acceso a archivos local o NFS. Si solo accede a los datos a través de Samba, podría establecer esto en yes para lograr una mejor compatibilidad con las ACLs de NT.

Si acl_xattr:ignore system acls se establece en yes, se aplicarán las siguientes configuraciones adicionales:

•create mask = 0666
•directory mask = 0777
•map archive = no
•map hidden = no
•map readonly = no
•map system = no
•store dos attributes = yes

acl_xattr:default acl style = [posix|windows|everyone]

Este parámetro determina el tipo de ACL que se sintetiza en caso de que un archivo o directorio carezca de un xattr security.NTACL.

Cuando se establece en posix, se sintetizará una ACL basada en los permisos del modo POSIX para usuario, grupo y otros, con una ACE adicional para NT Authority\SYSTEM con derechos completos.

Cuando se establece en windows, se sintetiza una ACL de la misma manera que lo hace Windows, incluyendo solo permisos para el propietario y NT Authority\SYSTEM.

Cuando se establece en everyone, se sintetiza una ACL que otorga permisos completos a todos (S-1-1-0).

El valor predeterminado para esta opción es posix.
