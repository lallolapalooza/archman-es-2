NOMBRE

virt-what-cvm - detectar si se está ejecutando en una máquina virtual confidencial

RESUMEN

virt-what-cvm [opciones]

DESCRIPCIÓN

"virt-what-cvm" es una herramienta que puede ser utilizada para detectar si el programa se está ejecutando en una máquina virtual confidencial.

El programa imprime una lista de "hechos" sobre la máquina virtual confidencial, derivados de heurísticas. Se imprime un hecho por línea.

Si no se imprime nada y el script sale con código 0 (sin error), entonces puede significar *ya sea* que el programa se está ejecutando en hardware físico *o* que el programa se está ejecutando dentro de una máquina virtual no confidencial, *o* dentro de un tipo de máquina virtual confidencial que no conocemos o no podemos detectar.

HECHOS

amd-sev
Este es un invitado confidencial ejecutándose con tecnología AMD SEV

Estado: probado en Fedora 37 QEMU+KVM

amd-sev-es
Este es un invitado confidencial ejecutándose con tecnología AMD SEV-ES

Estado: probado en Fedora 37 QEMU+KVM

amd-sev-snp
Este es un invitado confidencial ejecutándose con tecnología AMD SEV-SNP

Estado: probado en CVM confidencial de Microsoft Azure SEV-SNP

Estado: probado en Fedora 38 QEMU+KVM SEV-SNP (snapshot de desarrollo)

intel-tdx
Este es un invitado confidencial ejecutándose con tecnología Intel TDX

Estado: probado en CVM confidencial de Microsoft Azure TDX

hyperv-hcl
Este es un invitado confidencial ejecutándose sin iluminación bajo la Capa de Compatibilidad del Host (HCL) de HyperV (Azure). Esto se emparejará con amd-sev-snp.

Estado: probado en CVM confidencial de Microsoft Azure SEV-SNP y TDX

s390-protvirt
Este es un invitado confidencial ejecutándose en s390x con la tecnología de Virtualización Protegida (Ejecución Segura)

ESTADO DE SALIDA

Los programas que usan o envuelven "virt-what-cvm" deben verificar que el estado de salida sea 0 antes de intentar analizar la salida del comando.

Un estado de salida distinto de cero indica algún error, por ejemplo, un argumento de línea de comandos no reconocido. Si el estado de salida es distinto de cero, entonces la salida de "hechos" (si se imprimió alguna) no puede garantizarse y debe ignorarse.

El estado de salida *no* tiene nada que ver con si el programa se está ejecutando en hardware físico o bajo virtualización confidencial, ni con si "virt-what-cvm" logró la detección "correctamente" (lo cual es básicamente incognoscible dada la gran variedad de sistemas de virtualización existentes)

EJECUCIÓN DE VIRT-WHAT-CVM DESDE OTROS PROGRAMAS

"virt-what-cvm" está diseñado para que puedas ejecutarlo fácilmente desde otros programas o encapsularlo en una biblioteca.

Tu programa debe verificar el estado de salida (ver la sección anterior).

NOTA IMPORTANTE

Este programa detecta si es probable que se esté ejecutando dentro de una VM confidencial conocida, pero *NO* prueba que el entorno sea confiable. Para obtener confianza en el entorno se requiere un informe de atestación para la máquina virtual, que luego es verificado por un tercero ya confiable.

Las características de hardware en las que este programa se basa para establecer hechos sobre el entorno de virtualización confidencial son aquellas cuyas características serán demostradas por la verificación de un informe de atestación.

Este programa *PUEDE* tener falsos positivos. Es decir, puede informar que es una VM confidencial cuando en realidad es una VM no confidencial que la simula.

Este programa *NO DEBERÍA* tener falsos negativos. Es decir, no debería fallar al informar la existencia de una VM confidencial. Con la advertencia de que esto solo se aplica a entornos que han sido probados explícitamente.

Si este programa imprime un hecho, esto puede usarse para habilitar o deshabilitar el uso de ciertas características, de acuerdo con si son apropiadas para un entorno confidencial. Sin embargo, la VM *NO DEBE* ser confiada hasta que se verifique un informe de atestación.

Como protección contra falsos negativos de esta herramienta, los entornos que requieren alta seguridad deben tomar una o más de estas medidas:

* Los hechos reportados por este programa *DEBERÍAN* ser medidos
  en uno de los PCRs del TPM
* El informe de atestación *DEBERÍA* cubrir los hechos reportados
  por este programa
* El informe de atestación *DEBERÍA* cubrir el estado de habilitación
  de cualquier característica afectada por decisiones que involucren
  hechos reportados por esta herramienta

REPORTE DE ERRORES

Los errores pueden ser vistos en la página de Red Hat Bugzilla: https://bugzilla.redhat.com/.

Si encuentra un error en virt-what-cvm, por favor siga estos pasos para reportarlo:

1. Verifique si existen reportes de errores existentes
Vaya a https://bugzilla.redhat.com/ y busque errores similares. Es posible que alguien ya haya reportado el mismo error, e incluso que lo hayan corregido.
2. Capture mensajes de depuración y error
Ejecute 
virt-what-cvm -d > virt-what-cvm.log 2>&1

y conserve virt-what-cvm.log. Puede contener mensajes de error que debería enviar con su reporte de error.

3. Obtenga la versión de virt-what-cvm.
Ejecute 
virt-what-cvm --version
4. Envíe un reporte de error.
Vaya a https://bugzilla.redhat.com/ y envíe un nuevo error. Por favor, describa el problema con el mayor detalle posible.

Recuerde incluir los números de versión (paso 3) y el archivo de mensajes de depuración (paso 2) y tantos detalles como sea posible.

5. Asigne el error a rjones @ redhat.com
Asigne o reasigne el error a rjones @ redhat.com (sin los espacios). También puede enviarme un correo electrónico con el número de error si desea una respuesta más rápida.
