VDEQ(1) Manual de comandos generales VDEQ(1)

NOMBRE

vdeq - Envoltorio de Virtual Distributed Ethernet para máquinas virtuales QEMU/KVM

SINOPSIS

vdeq qemu [ --mod modo_octal ] OPCIONES_QEMU -net vde[,vlan=n][,sock=ruta_socket][,port=n] OPCIONES_QEMU
vdeq kvm [ --mod modo_octal ] OPCIONES_KVM -net vde[,vlan=n][,sock=ruta_socket][,port=n] OPCIONES_KVM
vde{nombre_qemu} [ --mod modo_octal ] OPCIONES_QEMU -net vde[,vlan=n][,sock=ruta_socket][,port=n] OPCIONES_QEMU

SINOPSIS ANTIGUA

vdeq qemu [ --mod modo_octal ] [ -sock ruta_socket [ ,ruta_socket [ ,... ] ] ] [ argumentos_qemu ]
vde{nombre_qemu} [ -sock ruta_socket [ ,ruta_socket [ ,... ] ] ] [ argumentos_qemu ]

DESCRIPCION

vdeq es un envoltorio para iniciar una máquina virtual QEMU/KVM conectada a una red VDE. Utiliza el parámetro -tun-fd de qemu/kvm para configurar la conexión con un vde_switch.

El comando


vdeq qemu -b c -hda=sampledisk
inicia una máquina qemu que arranca desde la imagen sampledisk y tiene una interfaz de red ne2000 conectada al vde_switch estándar. El comando

vdeq kvm -b c -hda=sampledisk
inicia una máquina kvm que arranca desde la imagen sampledisk y tiene una interfaz de red ne2000 conectada al vde_switch estándar.

También es posible crear enlaces simbólicos al ejecutable vdeq para tener un comando más simple. Si el enlace tiene un nombre que comienza con vde, la parte restante del nombre se toma como el comando qemu. Por ejemplo, si vdeq está enlazado a vdeqemu:


vdeqemu -b c -hda=sampledisk
inicia qemu como se describió anteriormente. Si vdeq está enlazado a vdekvm:

vdekvm -b c -hda=sampledisk
inicia kvm con los mismos parámetros.

La nueva sintaxis es consistente con los nuevos parámetros de red de Qemu 0.8.0. Usando vdeq es posible especificar una interfaz vde de la misma manera que las interfaces de usuario, tap o socket. El parámetro sock= se puede usar para usar un socket específico. Tenga en cuenta que lo que qemu llama vlan no está relacionado con las VLAN 802.1Q administradas por el vde_switch. port= se puede usar para especificar el puerto del switch, de lo contrario se asigna el primer puerto asignable. El siguiente comando ejecuta una VM qemu con dos interfaces de red conectadas al switch estándar y al switch con socket local "/tmp/my.ctl", puerto 10, respectivamente.


vde qemu -net nic,vlan=0 -net nic,vlan=1 -net vde,vlan=0 -net vde,vlan=1,sock=/tmp/my.ctl,port=10

vdeqemu -net nic,vlan=0 -net nic,vlan=1 -net vde,vlan=0 -net vde,vlan=1,sock=/tmp/my.ctl,port=10
El siguiente comando ejecuta una VM kvm con dos interfaces de red conectadas al switch estándar y al switch con socket local "/tmp/my.ctl", puerto 10, respectivamente.

vde kvm -net nic,vlan=0 -net nic,vlan=1 -net vde,vlan=0 -net vde,vlan=1,sock=/tmp/my.ctl,port=10

vdekvm -net nic,vlan=0 -net nic,vlan=1 -net vde,vlan=0 -net vde,vlan=1,sock=/tmp/my.ctl,port=10

La sintaxis antigua se puede usar con Qemu 0.8.0, pero todas las interfaces vde se asignan a vlan 0.


vdeq qemu -sock /tmp/vde.ctl,/tmp/my.ctl -b c -hda=sampledisk

vdeqemu -sock /tmp/vde.ctl,/tmp/my.ctl -b c -hda=sampledisk
ambos inician qemu con una interfaz de red conectada tanto al switch estándar como al switch con socket local "/tmp/my.ctl".

OPCIONES

--mod
modo_octal, especifica el modo para el socket de comunicación.
-sock
ruta_socket, especifica el socket UNIX que será utilizado por programas locales para unirse a la VDE. El valor predeterminado es "/tmp/vde.ctl". También es posible indicar varias rutas_socket (separadas por comas, sin espacios): en este caso se definen varias interfaces. La primera ruta_socket se conecta a la primera interfaz ne2k y así sucesivamente.
-h, -help, --help
imprime una ayuda de uso.

NOTA

Qemu ha cambiado su sintaxis para redes (cvs 15 de noviembre de 2005). Como solución temporal, use vdeoq y vdeoqemu en lugar de vdeq y vdeqemu si está ejecutando un qemu con la sintaxis antigua.
Por defecto, qemu utiliza la misma dirección MAC para cada máquina virtual, por lo que si planea usar varias instancias de qemu, asegúrese de establecer explícitamente una dirección MAC diferente para cada máquina virtual. Al generar su dirección, tenga cuidado de no utilizar MACs reservadas de broadcast/multicast; las reglas de ethernet dicen: el bit de multidifusión es el bit de orden inferior del primer byte, que es "el primer bit en el cable". Por ejemplo, 34:12:de:ad:be:ef es una dirección unicast, 35:12:de:ad:be:ef es una dirección multicast (ver la sección DIRECCIONES MULTICAST ETHERNET en http://www.iana.org/assignments/ethernet-numbers para más información).
