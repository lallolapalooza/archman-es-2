DESCRIPCIÓN

Las funciones de la familia printf() producen salida de acuerdo con un formato como se describe a continuación. Las funciones printf() y vprintf() escriben la salida en stdout, el flujo de salida estándar; fprintf() y vfprintf() escriben la salida en el stream de salida dado; sprintf(), snprintf(), vsprintf() y vsnprintf() escriben en la cadena de caracteres str.

La función dprintf() es igual a fprintf() excepto que genera salida a un descriptor de archivo, fd, en lugar de a un flujo stdio(3).

Las funciones snprintf() y vsnprintf() escriben como máximo size bytes (incluyendo el byte nulo de terminación ('\0')) en str.

Las funciones vprintf(), vfprintf(), vdprintf(), vsprintf(), vsnprintf() son equivalentes a las funciones printf(), fprintf(), dprintf(), sprintf(), snprintf(), respectivamente, excepto que se llaman con una va_list en lugar de un número variable de argumentos. Estas funciones no llaman a la macro va_end. Como invocan la macro va_arg, el valor de ap no está definido después de la llamada. Ver stdarg(3).

Todas estas funciones escriben la salida bajo el control de una cadena de formato que especifica cómo los argumentos subsiguientes (o los argumentos accedidos a través de las facilidades de argumentos de longitud variable de stdarg(3)) se convierten para la salida.

C99 y POSIX.1-2001 especifican que los resultados no están definidos si una llamada a sprintf(), snprintf(), vsprintf(), o vsnprintf() causara la copia entre objetos que se solapan (por ejemplo, si el array de cadena de destino y uno de los argumentos de entrada suministrados se refieren al mismo buffer). Ver PRECAUCIONES.

Formato de la cadena de formato

La cadena de formato es una cadena de caracteres, que comienza y termina en su estado de desplazamiento inicial, si lo hay. La cadena de formato se compone de cero o más directivas: caracteres ordinarios (no %), que se copian sin cambios al flujo de salida; y especificaciones de conversión, cada una de las cuales resulta en la obtención de cero o más argumentos subsiguientes. Cada especificación de conversión se introduce con el carácter %, y termina con un especificador de conversión. Entre medias puede haber (en este orden) cero o más flags, una anchura de campo opcional, una precisión opcional y un modificador de longitud opcional.

La sintaxis general de una especificación de conversión es:


%[argumento$][flags][ancho][.precision][modificador de longitud]conversión

Los argumentos deben corresponderse adecuadamente (después de la promoción de tipo) con el especificador de conversión. Por defecto, los argumentos se utilizan en el orden dado, donde cada '*' (ver *Anchura de campo* y *Precisión* más abajo) y cada especificador de conversión solicita el siguiente argumento (y es un error si se proporcionan insuficientes argumentos). También se puede especificar explícitamente qué argumento se toma, en cada lugar donde se requiere un argumento, escribiendo "%m$" en lugar de '%' y "*m$" en lugar de '*', donde el entero decimal m denota la posición en la lista de argumentos del argumento deseado, indexado a partir de 1. Por lo tanto,


printf("%*d", ancho, num);

y


printf("%2$*1$d", ancho, num);

son equivalentes. El segundo estilo permite referencias repetidas al mismo argumento. El estándar C99 no incluye el estilo que usa '$', el cual proviene de la Single UNIX Specification. Si se usa el estilo que usa '$', debe usarse en todo momento para todas las conversiones que toman un argumento y todos los argumentos de ancho y precisión, pero puede mezclarse con formatos "%%", los cuales no consumen un argumento. No puede haber huecos en los números de los argumentos especificados usando '$'; por ejemplo, si se especifican los argumentos 1 y 3, el argumento 2 también debe especificarse en algún lugar de la cadena de formato.

Para algunas conversiones numéricas se usa un carácter de radix ("punto decimal") o un carácter de agrupamiento de miles. El carácter real utilizado depende de la parte LC_NUMERIC de la localidad. (Ver setlocale(3).) La localidad POSIX usa '.' como carácter de radix, y no tiene carácter de agrupamiento. Por lo tanto,


printf("%'.2f", 1234567.89);

resulta en "1234567.89" en la localidad POSIX, en "1234567,89" en la localidad nl_NL, y en "1.234.567,89" en la localidad da_DK.

Flag characters

El carácter % va seguido de cero o más de los siguientes flags:

#
El valor debe convertirse a una "forma alternativa". Para las conversiones o, el primer carácter de la cadena de salida se convierte en cero (precediendo con un 0 si no era cero ya). Para las conversiones x y X, un resultado distinto de cero tiene las cadenas "0x" (o "0X" para conversiones X) precediéndolas. Para las conversiones a, A, e, E, f, F, g, y G, el resultado siempre contendrá un punto decimal, incluso si no le siguen dígitos (normalmente, un punto decimal aparece en los resultados de estas conversiones solo si un dígito le sigue). Para las conversiones g y G, los ceros finales no se eliminan del resultado ya que de lo contrario sí lo harían. Para las conversiones m, si errno contiene un código de error válido, se imprime la salida de strerrorname_np(errno); de lo contrario, se imprime el valor almacenado en errno como un número decimal. Para otras conversiones, el comportamiento no está definido.
0
El valor debe rellenarse con ceros. Para las conversiones d, i, o, u, x, X, a, A, e, E, f, F, g, y G, el valor convertido se rellena por la izquierda con ceros en lugar de espacios. Si los flags 0 y - aparecen ambos, el flag 0 se ignora. Si se proporciona una precisión con una conversión de enteros (d, i, o, u, x, y X), el flag 0 se ignora. Para otras conversiones, el comportamiento no está definido.

FLAGS

A flag may appear before the field width. The flags are:

-
The converted value is to be left-adjusted within the field. The default is to pad on the right with blanks, rather than on the left with blanks or zeros. A - overrides a 0 if both are given.
' '
(a space) A blank should be left before a positive number (or empty string) produced by a signed conversion.
+
A sign (+ or -) should always be placed before a number produced by a signed conversion. By default, a sign is used only for negative numbers. A + overrides a space if both are used.

The five flag characters above are defined in the C99 standard. POSIX specifies one further flag character.

'
For decimal conversion (i, d, u, f, F, g, G) the output is to be grouped with thousands' grouping characters as a non-monetary quantity. Misleadingly, this isn't necessarily every thousand: for example Karbi ("mjw_IN"), groups its digits into 3 once, then 2 repeatedly. Compare locale(7) grouping and thousands_sep, contrast with mon_grouping/mon_thousands_sep and strfmon(3). This is a no-op in the default "C" locale.

glibc 2.2 adds one further flag character.

I
For decimal integer conversion (i, d, u) the output uses the locale's alternative output digits, if any. For example, since glibc 2.2.3 this will give Arabic-Indic digits in the Persian ("fa_IR") locale.

Ancho de campo

Un dígito opcional (con el primer dígito distinto de cero) que especifica un ancho mínimo de campo. Si el valor convertido tiene menos caracteres que el ancho de campo, se rellenará con espacios a la izquierda (o a la derecha, si se ha dado el indicador de ajuste a la izquierda). En lugar de una cadena de dígitos decimales se puede escribir "*" o "*m$" (para algún entero decimal m) para especificar que el ancho del campo se proporciona en el siguiente argumento, o en el argumento m-ésimo, respectivamente, el cual debe ser de tipo int. Un ancho de campo negativo se toma como un indicador '-' seguido de un ancho de campo positivo. En ningún caso un ancho de campo inexistente o pequeño provoca la truncación de un campo; si el resultado de una conversión es más ancho que el ancho del campo, el campo se expande para contener el resultado de la conversión.

Precisión

Una precisión opcional, en forma de un punto ('.') seguido de una cadena de dígitos decimales opcional. En lugar de una cadena de dígitos decimales se puede escribir "*" o "*m$" (para algún entero decimal m) para especificar que la precisión se da en el siguiente argumento, o en el argumento m-ésimo, respectivamente, el cual debe ser de tipo int. Si la precisión se da solo como '.', la precisión se toma como cero. Una precisión negativa se toma como si la precisión se hubiera omitido. Esto da el número mínimo de dígitos que deben aparecer para las conversiones d, i, o, u, x y X, el número de dígitos que deben aparecer después del carácter del punto de separación para las conversiones a, A, e, E, f y F, el número máximo de dígitos significativos para las conversiones g y G, o el número máximo de caracteres que se imprimirán de una cadena para las conversiones s y S.

Modificador de longitud

Aquí, "conversión de enteros" significa conversión d, i, o, u, x o X.

hh
Una conversión de enteros subsiguiente corresponde a un argumento de signed char o unsigned char, o una conversión n subsiguiente corresponde a un puntero a un argumento de signed char.
h
Una conversión de enteros subsiguiente corresponde a un argumento de short o unsigned short, o una conversión n subsiguiente corresponde a un puntero a un argumento de short.
l
(ele) Una conversión de enteros subsiguiente corresponde a un argumento de long o unsigned long, o una conversión n subsiguiente corresponde a un puntero a un argumento de long, o una conversión c subsiguiente corresponde a un argumento de wint_t, o una conversión s subsiguiente corresponde a un puntero a un argumento de wchar_t. En una conversión a, A, e, E, f, F, g o G subsiguiente, este modificador de longitud se ignora (C99; no está en SUSv2).
ll
(ele-ele). Una conversión de enteros subsiguiente corresponde a un argumento de long long o unsigned long long, o una conversión n subsiguiente corresponde a un puntero a un argumento de long long.
q
Un sinónimo de ll. Esta es una extensión no estándar, derivada de BSD; evite su uso en código nuevo.
L
Una conversión a, A, e, E, f, F, g o G subsiguiente corresponde a un argumento de long double. (C99 permite %LF, pero SUSv2 no.)
j
Una conversión de enteros subsiguiente corresponde a un argumento de intmax_t o uintmax_t, o una conversión n subsiguiente corresponde a un puntero a un argumento de intmax_t.
z
Una conversión de enteros subsiguiente corresponde a un argumento de size_t o ssize_t, o una conversión n subsiguiente corresponde a un puntero a un argumento de size_t.
Z
Un sinónimo no estándar de z que precede a la aparición de z. No usar en código nuevo.
t
Una conversión de enteros subsiguiente corresponde a un argumento de ptrdiff_t, o una conversión n subsiguiente corresponde a un puntero a un argumento de ptrdiff_t.

SUSv3 especifica todos los anteriores, excepto aquellos modificadores explícitamente anotados como extensiones no estándar. SUSv2 especificó solo los modificadores de longitud h (en hd, hi, ho, hx, hX, hn) y l (en ld, li, lo, lx, lX, ln, lc, ls) y L (en Le, LE, Lf, Lg, LG).

Como una extensión no estándar, las implementaciones de GNU tratan ll y L como sinónimos, de modo que se puede, por ejemplo, escribir llg (como sinónimo de Lg que cumple con el estándar) y Ld (como sinónimo de lld que cumple con el estándar). Dicho uso no es portable.

Especificadores de conversión

Un carácter que especifica el tipo de conversión que se va a aplicar. Los especificadores de conversión y sus significados son:

d, i
El argumento int se convierte a notación decimal con signo. La precisión, si la hay, indica el número mínimo de dígitos que deben aparecer; si el valor convertido requiere menos dígitos, se rellena a la izquierda con ceros. La precisión predeterminada es 1. Cuando se imprime 0 con una precisión explícita de 0, la salida está vacía.
o, u, x, X
El argumento unsigned int se convierte a notación octal sin signo (o), decimal sin signo (u) o hexadecimal sin signo (x y X). Las letras abcdef se utilizan para las conversiones x; las letras ABCDEF se utilizan para las conversiones X. La precisión, si la hay, indica el número mínimo de dígitos que deben aparecer; si el valor convertido requiere menos dígitos, se rellena a la izquierda con ceros. La precisión predeterminada es 1. Cuando se imprime 0 con una precisión explícita de 0, la salida está vacía.
e, E
El argumento double se redondea y se convierte en el estilo [-]d.ddde±dd donde hay un dígito (que es distinto de cero si el argumento es distinto de cero) antes del carácter del punto decimal y el número de dígitos después de él es igual a la precisión; si la precisión falta, se toma como 6; si la precisión es cero, no aparece ningún carácter de punto decimal. Una conversión E utiliza la letra E (en lugar de e) para introducir el exponente. El exponente siempre contiene al menos dos dígitos; si el valor es cero, el exponente es 00.
f, F
El argumento double se redondea y se convierte a notación decimal en el estilo [-]ddd.ddd, donde el número de dígitos después del carácter del punto decimal es igual a la especificación de precisión. Si la precisión falta, se toma como 6; si la precisión es explícitamente cero, no aparece ningún carácter de punto decimal. Si aparece un punto decimal, al menos un dígito aparece antes de él.
(SUSv2 no conoce F y dice que pueden estar disponibles representaciones de cadenas de caracteres para infinito y NaN. SUSv3 añade una especificación para F. El estándar C99 especifica "[-]inf" o "[-]infinity" para infinito, y una cadena que comienza con "nan" para NaN, en el caso de la conversión f, y "[-]INF" o "[-]INFINITY" o "NAN" en el caso de la conversión F.)
g, G
El argumento double se convierte en el estilo f o e (o F o E para las conversiones G). La precisión especifica el número de dígitos significativos. Si la precisión falta, se dan 6 dígitos; si la precisión es cero, se trata como 1. El estilo e se utiliza si el exponente de su conversión es menor que -4 o mayor o igual que la precisión. Los ceros finales se eliminan de la parte fraccionaria del resultado; aparece un punto decimal solo si está seguido de al menos un dígito.

EJEMPLOS

Para imprimir Pi con cinco decimales:


#include <math.h>
#include <stdio.h>
fprintf(stdout, "pi = %.5f\n", 4 * atan(1.0));

Para imprimir una fecha y hora en el formato "Domingo, Julio 3, 10:02", donde weekday y month son punteros a cadenas:


#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        weekday, month, day, hour, min);

Muchos países utilizan el orden día-mes-año. Por lo tanto, una versión internacionalizada debe poder imprimir los argumentos en un orden especificado por el formato:


#include <stdio.h>
fprintf(stdout, format,
        weekday, month, day, hour, min);

donde format depende de la configuración regional y puede permutar los argumentos. Con el valor:


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

se podría obtener "Sonntag, 3. Juli, 10:02".

Para asignar una cadena suficientemente grande e imprimir en ella (código correcto tanto para glibc 2.0 como para glibc 2.1):

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Determinar el tamaño requerido.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un byte extra para '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si ocurre truncamiento en versiones de glibc anteriores a glibc 2.0.6, esto se trata como un error en lugar de manejarse adecuadamente.
