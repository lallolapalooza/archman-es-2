VERIFY(8) Manual del Administrador del Sistema VERIFY(8)

NOMBRE

verify - Servidor de verificación de direcciones de Postfix

SINOPSIS

verify [opciones genéricas de demonio de Postfix]

DESCRIPCIÓN


El servidor de verificación de direcciones verify(8) mantiene un registro de qué direcciones de destinatarios se sabe que son entregables o no entregables.

Las direcciones se verifican inyectando mensajes de sondeo en la cola de Postfix. Los mensajes de sondeo pasan por toda la maquinaria de enrutamiento y reescritura, excepto por la entrega final, y se descartan en lugar de ser aplazados o rebotados.

La verificación de direcciones depende de la respuesta del MTA más cercano para la dirección especificada y, por lo tanto, no detectará todas las direcciones no entregables.

El servidor verify(8) está diseñado para ejecutarse bajo el control del servidor maestro de Postfix. Mantiene una base de datos persistente opcional. Para evitar ser interrumpido por "postfix stop" en medio de una actualización de la base de datos, el proceso se ejecuta en un grupo de procesos separado.

El servidor verify(8) implementa las siguientes solicitudes:

update dirección estado texto
Actualiza el estado y el texto de la dirección especificada.
query dirección
Busca el estado y el texto de la dirección especificada. Si el estado es desconocido, se envía una sonda y se devuelve un estado "en progreso".

SEGURIDAD

El servidor de verificación de direcciones no es sensible a la seguridad. No se comunica con la red ni con usuarios locales. El servidor verify puede ejecutarse chrooted con privilegios bajos fijos.

El servidor de verificación de direcciones puede ser forzado a almacenar cantidades ilimitadas de datos basura. Limitar el tiempo de expiración de la caché intercambia un problema (agotamiento del espacio en disco) por otro (tiempo de respuesta deficiente a las solicitudes del cliente).

Con Postfix versión 2.5 y posteriores, el servidor verify(8) ya no utiliza privilegios de root al abrir el archivo de caché address_verify_map. El archivo ahora debe almacenarse en el directorio de datos propiedad de Postfix (data_directory). Como ayuda para la migración, se redirige un intento de abrir un archivo de caché en un directorio que no pertenece a Postfix al directorio de datos propiedad de Postfix (data_directory), y se registra una advertencia.

DIAGNÓSTICOS


Los problemas y las transacciones se registran en syslogd(8) o postlogd(8).

ERRORES


Los mensajes de sondeo de verificación de direcciones añaden tráfico adicional a la cola de correo. La verificación de destinatarios puede causar una carga aumentada en los servidores posteriores en caso de un ataque de diccionario o una avalancha de rebotes de retroalimentación (backscatter). La verificación de direcciones de remitente puede hacer que su sitio sea denegado por algunos proveedores.

Si la base de datos persistente se corrompe, el mundo se acaba y se necesita intervención humana. Esto viola un principio básico de Postfix.

PARÁMETROS DE CONFIGURACIÓN

Los cambios en main.cf no se detectan automáticamente, ya que los procesos verify(8) son de larga duración. Utilice el comando "postfix reload" después de un cambio de configuración.

El texto a continuación proporciona solo un resumen de los parámetros. Consulte postconf(5) para obtener más detalles, incluidos los ejemplos.

CONTROLES DE MENSAJE DE SONDEO

address_verify_sender ($double_bounce_sender)
La dirección del remitente a utilizar en las sondas de verificación de direcciones; antes de Postfix 2.5, el valor predeterminado era "postmaster".

Disponible con Postfix 2.9 y posteriores:

address_verify_sender_ttl (0s)
El tiempo entre cambios en la porción dependiente del tiempo de las direcciones de remitente de las sondas de verificación de direcciones.

CONTROLES DE CACHÉ

address_verify_map (ver salida de 'postconf -d')
Tabla de búsqueda para el almacenamiento persistente del estado de verificación de direcciones.
address_verify_positive_expire_time (31d)
El tiempo después del cual una sonda exitosa expira de la caché de verificación de direcciones.
address_verify_positive_refresh_time (7d)
El tiempo después del cual una sonda de verificación de direcciones exitosa necesita ser actualizada.
address_verify_negative_cache (yes)
Habilita el almacenamiento en caché de los resultados fallidos de las sondas de verificación de direcciones.
address_verify_negative_expire_time (3d)
El tiempo después del cual una sonda fallida expira de la caché de verificación de direcciones.
address_verify_negative_refresh_time (3h)
El tiempo después del cual una sonda de verificación de direcciones fallida necesita ser actualizada.

Disponible con Postfix 2.7 y posteriores:

address_verify_cache_cleanup_interval (12h)
El tiempo entre ejecuciones de limpieza de la base de datos de verificación de direcciones de verify(8).

CONTROLES DE ENRUTAMIENTO DE MENSAJES DE SONDEO

Por defecto, los mensajes de sondeo se entregan a través de la misma ruta que los mensajes normales. Los siguientes parámetros se pueden utilizar para anular mecanismos de enrutamiento de mensajes específicos.

address_verify_relayhost ($relayhost)
Anula la configuración del parámetro relayhost para las sondas de verificación de direcciones.
address_verify_transport_maps ($transport_maps)
Anula la configuración del parámetro transport_maps para las sondas de verificación de direcciones.
address_verify_local_transport ($local_transport)
Anula la configuración del parámetro local_transport para las sondas de verificación de direcciones.
address_verify_virtual_transport ($virtual_transport)
Anula la configuración del parámetro virtual_transport para las sondas de verificación de direcciones.
address_verify_relay_transport ($relay_transport)
Anula la configuración del parámetro relay_transport para las sondas de verificación de direcciones.
address_verify_default_transport ($default_transport)
Anula la configuración del parámetro default_transport para las sondas de verificación de direcciones.

Disponible en Postfix 2.3 y posteriores:

address_verify_sender_dependent_relayhost_maps ($sender_dependent_relayhost_maps)
Anula la configuración del parámetro sender_dependent_relayhost_maps para las sondas de verificación de direcciones.

Anula la configuración del parámetro sender_dependent_default_transport_maps para las sondas de verificación de direcciones.

CONTROLOS DE SMTPUTF8

El soporte preliminar de SMTPUTF8 se introduce con Postfix 3.0.

smtputf8_autodetect_classes (sendmail, verify)
Detecta que un mensaje requiere soporte SMTPUTF8 para las clases de origen de correo especificadas.

Disponible en la versión 3.2 de Postfix y posteriores:

enable_idna2003_compatibility (no)
Habilita la compatibilidad 'transicional' entre IDNA2003 e IDNA2008, al convertir nombres de dominio UTF-8 a/desde la forma ASCII que se utiliza para las búsquedas de DNS.

CONTROLOS MISCELÁNEOS

config_directory (ver salida de 'postconf -d')
La ubicación predeterminada de los archivos de configuración main.cf y master.cf de Postfix.
daemon_timeout (18000s)
Cuánto tiempo puede tardar un proceso demonio de Postfix en manejar una solicitud antes de ser terminado por un temporizador de vigilancia incorporado.
ipc_timeout (3600s)
El límite de tiempo para enviar o recibir información a través de un canal de comunicación interno.
process_id (solo lectura)
El ID de proceso de un comando o proceso demonio de Postfix.
process_name (solo lectura)
El nombre del proceso de un comando o proceso demonio de Postfix.
queue_directory (ver salida de 'postconf -d')
La ubicación del directorio de colas de nivel superior de Postfix.
syslog_facility (mail)
La instalación de syslog del registro de Postfix.
syslog_name (ver salida de 'postconf -d')
Un prefijo que se antepone al nombre del proceso en los registros de syslog, de modo que, por ejemplo, "smtpd" se convierte en "prefijo/smtpd".

Disponible en Postfix 3.3 y posteriores:

service_name (solo lectura)
El nombre del servicio master.cf de un proceso demonio de Postfix.
