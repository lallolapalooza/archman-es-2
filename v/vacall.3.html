VACALL(3) Manual de Funciones de Biblioteca VACALL(3)

NOMBRE

vacall - Funciones C llamadas con argumentos variables

SINOPSIS

#include <vacall.h>

extern void* vacall_function;

void function (va_alistalist)
{
  va_start_type(alist[, return_type]);
  arg = va_arg_type(alist[, arg_type]);
  va_return_type(alist[[, return_type], return_value]);
}

vacall_function = &function;

val = ((return_type (*) ()) vacall) (arg1,arg2,...);

DESCRIPCIÓN

Este conjunto de macros permite que una función C function sea llamada con argumentos variables y devuelva valores de retorno variables. Esto es muy similar a la utilidad stdarg(3), pero también permite especificar el valor de retorno en tiempo de ejecución.

Las convenciones de llamada a funciones difieren considerablemente en diferentes máquinas, y vacall intenta proporcionar cierto grado de aislamiento de tales dependencias arquitectónicas.

La función que puede ser llamada con cualquier número y tipo de argumentos y que devolverá cualquier tipo de valor de retorno es vacall. Hará alguna magia y llamará a la función almacenada en la variable vacall_function. Si desea hacer más de un uso de vacall, utilice la utilidad trampoline(3) para almacenar &function en vacall_function justo antes de llamar a vacall.

Dentro de function, las siguientes macros se pueden usar para recorrer la lista de argumentos y especificar un valor de retorno:

va_start_type(alist[, return_type]);
inicia el recorrido de la lista de argumentos y especifica el tipo de retorno.
arg = va_arg_type(alist[, arg_type]);
recupera el siguiente argumento de la lista de argumentos.
va_return_type(alist[[, return_type], return_value]);
finaliza el recorrido de la lista de argumentos y especifica el valor de retorno.

El type en va_start_type y va_return_type debe ser uno de void, int, uint, long, ulong, longlong, ulonglong, double, struct, ptr o (solo para convenciones de llamada ANSI C) char, schar, uchar, short, ushort, float, dependiendo de la clase de return_type.

Los especificadores de type en va_start_type y va_return_type deben ser los mismos. Los especificadores de return_type pasados a va_start_type y va_return_type deben ser los mismos.

El type en va_arg_type debe ser uno de int, uint, long, ulong, longlong, ulonglong, double, struct, ptr o (solo para convenciones de llamada ANSI C) char, schar, uchar, short, ushort, float, dependiendo de la clase de arg_type.

En va_start_struct(alist, return_type, splittable); la bandera splittable especifica si la estructura return_type puede ser devuelta en registros de tal manera que cada campo de la estructura encaje completamente en un solo registro. Esto debe especificarse para estructuras de tamaño 2*sizeof(long). Para estructuras de tamaño <= sizeof(long), splittable se ignora y se asume que es 1. Para estructuras de tamaño > 2*sizeof(long), splittable se ignora y se asume que es 0. Hay algunas macros útiles para esto:

va_word_splittable_1 (type1)
va_word_splittable_2 (type1, type2)
va_word_splittable_3 (type1, type2, type3)
va_word_splittable_4 (type1, type2, type3, type4)
Para una estructura con tres ranuras 
struct { type1 id1; type2 id2; type3 id3; }
puede especificar splittable como va_word_splittable_3 (type1, type2, type3).

NOTAS

Las funciones que desean emular funciones al estilo Kernighan & Ritchie (es decir, en C ANSI, funciones sin una lista de argumentos tipada) no pueden usar los valores de type char, schar, uchar, short, ushort, float. Como se prescribe por las promociones de expresiones C K&R por defecto, deben usar int en lugar de char, schar, uchar, short, ushort y double en lugar de float.

Las macros va_start_longlong(), va_start_ulonglong(), va_return_longlong(), va_return_ulonglong(), va_arg_longlong() y va_arg_ulonglong() solo funcionan si el compilador C tiene un tipo de entero de 64 bits long long que funciona.

Los tipos de estructura utilizados en va_start_struct() y va_struct() solo deben contener campos de tipo int, long, long long (con o sin signo) o puntero. Los tipos de estructura que contienen tipos char, short, float, double (con o sin signo) u otras estructuras no son compatibles.

EJEMPLO

Este ejemplo, una posible implementación de execl(3) sobre execv(2) usando stdarg(3),

#include <stdarg.h>
#define MAXARGS 100
/* execl se llama mediante execl(file, arg1, arg2, ..., (char *)0); */
int execl (...)
{
  va_list ap;
  char* file;
  char* args[MAXARGS];
  int argno = 0;
  va_start (ap);
  file = va_arg(ap, char*);
  while ((args[argno] = va_arg(ap, char*)) != (char *)0)
    argno++;
  va_end (ap);
  return execv(file, args);
}

se ve así usando vacall(3):

#include <vacall.h>
#define MAXARGS 100
/* execl se llama mediante vacall(file, arg1, arg2, ..., (char *)0); */
void execl (va_alist ap)
{
  char* file;
  char* args[MAXARGS];
  int argno = 0;
  int retval;
  va_start_int (ap);
  file = va_arg_ptr(ap, char*);
  while ((args[argno] = va_arg_ptr(ap, char*)) != (char *)0)
    argno++;
  retval = execv(file, args);
  va_return_int (ap, retval);
}
vacall_function = &execl;

VER TAMBIÉN

stdarg(3), trampoline(3), callback(3).

ERRORES

Las implementaciones actuales se han probado en una selección de casos comunes, pero probablemente todavía haya muchos errores.

Normalmente existen límites integrados en el tamaño de la lista de argumentos, que también pueden incluir el tamaño de los argumentos de estructura.

La decisión de si una estructura debe devolverse en registros o en memoria considera solo el tamaño y la alineación de la estructura. Esto es impreciso: por ejemplo, gcc en m68k-next devuelve struct { char a,b,c; } en registros y struct { char a[3]; } en memoria, aunque ambos tipos tienen el mismo tamaño y la misma alineación.

La lista de argumentos solo se puede recorrer una vez.

El uso de la variable global vacall_function no es reentrante. Esto se soluciona en el paquete callback(3).

PORTABILIDAD

El conocimiento sobre las convenciones de paso de argumentos se puede encontrar en el código fuente de gcc, archivo gcc-2.6.3/config/cpu/cpu.h, sección "Stack layout; function entry, exit and calling."

La implementación de varargs para gcc se puede encontrar en el código fuente de gcc, archivos gcc-2.6.3/ginclude/va*.h.

La función __builtin_saveregs() de gcc está definida en el código fuente de gcc, archivo gcc-2.6.3/libgcc2.c.
