NOMBRE

virt-sparsify - Hacer que un disco de máquina virtual sea disperso

SINOPSIS

virt-sparsify [--opciones] disco_entrada disco_salida
virt-sparsify [--opciones] --en-sitio disco

ADVERTENCIA

Usar "virt-sparsify" en máquinas virtuales en vivo, o concurrentemente con otras herramientas de edición de discos, puede ser peligroso, causando potencialmente corrupción del disco. La máquina virtual debe ser apagada antes de usar este comando, y las imágenes de disco no deben ser editadas concurrentemente.

DESCRIPCIÓN

Virt-sparsify es una herramienta que puede hacer que un disco de máquina virtual (o cualquier imagen de disco) sea disperso, también conocido como provisionamiento fino (thin-provisioned). Esto significa que el espacio libre dentro de la imagen de disco puede ser convertido de nuevo a espacio libre en el host.

Virt-sparsify puede localizar y hacer dispersos los espacios libres en la mayoría de los sistemas de archivos (ej. ext2/3/4, btrfs, NTFS, etc.), y también en volúmenes físicos LVM.

Virt-sparsify también puede convertir entre algunos formatos de disco, por ejemplo, convertir una imagen de disco raw a una imagen qcow2 con provisionamiento fino.

Virt-sparsify puede operar en cualquier imagen de disco, no solo en las de máquinas virtuales. Sin embargo, si una máquina virtual tiene múltiples discos y usa gestión de volúmenes, entonces virt-sparsify funcionará pero no será muy efectivo (http://bugzilla.redhat.com/887826).

NOTA IMPORTANTE SOBRE LAS IMÁGENES DE SALIDA DISPERSAS

Si la entrada es raw, entonces la salida por defecto es raw dispersa. Usted debe verificar el tamaño de salida usando una herramienta que entienda la dispersión como "du -sh". Puede hacer una gran diferencia:

$ ls -lh test1.img
-rw-rw-r--. 1 rjones rjones 100M Aug  8 08:08 test1.img
$ du -sh test1.img
3.6M   test1.img

(Compare el tamaño aparente 100M vs el tamaño real 3.6M)

LIMITACIONES IMPORTANTES

  • La máquina virtual debe estar apagada antes de usar esta herramienta.
  • Virt-sparsify puede requerir hasta 2 veces el tamaño virtual del disco de origen (1 copia temporal + 1 imagen de destino). Esto es en el peor de los casos y usualmente se requiere mucho menos espacio.

    Si está usando la opción --en-sitio, entonces no se requieren grandes cantidades de espacio temporal.

  • Virt-sparsify no puede redimensionar imágenes de disco. Para hacerlo, use virt-resize(1).
  • Virt-sparsify no puede manejar discos cifrados. Libguestfs soporta discos cifrados, pero los discos cifrados en sí mismos no pueden ser hechos dispersos.
  • Virt-sparsify aún no puede hacer disperso el espacio entre particiones. Note que este espacio a menudo se usa para elementos críticos como bootloaders, así que realmente no está sin usar.
  • En modo de copia, las instantáneas internas de qcow2 no se copian a la imagen de destino.

También puede querer leer las páginas del manual de las herramientas asociadas virt-filesystems(1) y virt-df(1) antes de empezar.

EJEMPLOS

El uso típico es:

virt-sparsify disco_entrada disco_salida

que copia "disco_entrada" a "disco_salida", haciendo la salida dispersa. "disco_salida" es creada, o sobrescrita si ya existe. El formato del disco de entrada se detecta (ej. qcow2) y se usa el mismo formato para el disco de salida.

Para convertir entre formatos, use la opción --convert:

virt-sparsify disk.raw --convert qcow2 disk.qcow2

Virt-sparsify intenta poner a cero y hacer disperso el espacio libre en cada sistema de archivos que pueda encontrar dentro de la imagen de disco fuente. Puede hacer que ignore (no ponga a cero el espacio libre en) ciertos sistemas de archivos haciendo:

virt-sparsify --ignorar /dev/sda1 disco_entrada disco_salida

Vea virt-filesystems(1) para obtener una lista de sistemas de archivos dentro de una imagen de disco.

Desde virt-sparsify ≥ 1.26, ahora puede hacer disperso un disco imagen en el sitio haciendo:

virt-sparsify --en-sitio disco.img

OPCIONES

--help
Muestra la ayuda.
--check-tmpdir ignorar
--check-tmpdir continuar
--check-tmpdir advertir
--check-tmpdir fallar
Verifica si el directorio "TMPDIR" o el directorio --tmp tiene suficiente espacio para completar la operación. Esto es solo una estimación.

Si la verificación indica un problema, entonces puede:

  • ignorarlo,
  • imprimir una advertencia y continuar,
  • advertir y esperar a que el usuario presione la tecla Retorno (esta es la opción por defecto), o:
  • fallar y salir.

No puede usar esta opción y --en-sitio juntas.

--colors
--colours
Usa secuencias de colores ANSI para colorear los mensajes. Esta es la opción por defecto cuando la salida es una tty. Si la salida del programa se redirige a un archivo, las secuencias de colores ANSI se deshabilitan a menos que use esta opción.
--compress
Comprime el archivo de salida. Esto solo funciona si el formato de salida es "qcow2".

No puede usar esta opción y --en-sitio juntas.

--convert raw
--convert qcow2
--convert [otros formatos]
Usa "formato-salida" como el formato para la imagen de destino. Si no se especifica, se usa el formato de entrada.

Los formatos de salida soportados y que funcionan correctamente son: "raw", "qcow2", "vdi".

También puede usar cualquier formato soportado por el programa qemu-img(1), ej. "vmdk", pero el soporte para otros formatos depende de qemu.

Especificar la opción --convert suele ser una buena idea, porque entonces virt-sparsify no necesita intentar adivinar el formato de entrada.

Para ajustar el formato de salida, vea: --compress, -o.

No puede usar esta opción y --en-sitio juntas.

--echo-keys
Al solicitar claves y frases de contraseña, virt-sparsify normalmente desactiva el eco para que no pueda ver lo que está escribiendo. Si no le preocupan los ataques Tempest y no hay nadie más en la habitación, puede especificar esta bandera para ver lo que está escribiendo.
--format raw
--format qcow2
Especifica el formato de la imagen de disco de entrada. Si esta bandera no se da, se detecta automáticamente desde la propia imagen.

Si trabaja con imágenes de disco de invitado en formato raw no confiables, debe asegurarse de que el formato siempre se especifica.

--ignore filesystem
--ignore volgroup
Ignora el sistema de archivos nombrado.

Cuando no se usa --en-sitio: El espacio libre en el sistema de archivos no se pondrá a cero, pero los bloques existentes de ceros seguirán siendo hechos dispersos.

Cuando se usa --en-sitio, el sistema de archivos se ignora por completo.

En la segunda forma, esto ignora el grupo de volúmenes con nombre. Use el nombre del grupo de volúmenes sin el prefijo /dev/, por ejemplo --ignore vg_foo

Puede usar esta opción varias veces.

--in-place
Realiza la esparsificación en el lugar en lugar de la esparsificación por copia. Ver "ESPARSIFICACIÓN EN EL LUGAR" más abajo.
--key SELEECTOR
Especifica una clave para LUKS, para abrir automáticamente un dispositivo LUKS al usar la inspección.
--key NOMBRE:key:CADENA_CLAVE
--key UUID:key:CADENA_CLAVE
--key all:key:CADENA_CLAVE
"NOMBRE" es el nombre del dispositivo libguestfs (p. ej., "/dev/sda1"). "UUID" es el UUID del dispositivo. "all" significa intentar la clave contra cualquier dispositivo cifrado.

Use la "CADENA_CLAVE" especificada como contraseña.

--key NOMBRE:file:NOMBRE_ARCHIVO
--key UUID:file:NOMBRE_ARCHIVO
--key all:file:NOMBRE_ARCHIVO
Lee la contraseña del NOMBRE_ARCHIVO.
--key NOMBRE:clevis
--key UUID:clevis
--key all:clevis
Intenta desbloquear el dispositivo sin contraseña con Clevis, a través de la red. Por favor, consulte "DISCOS CIFRADOS" en guestfs(3) para más información sobre el cifrado de disco enlazado a la red (NBDE).

Tenga en cuenta que si alguna de estas opciones está presente en la línea de comandos, la red de usuario QEMU se habilitará automáticamente para la instancia de libguestfs.

--keys-from-stdin
Lee parámetros de clave o contraseña desde la entrada estándar. El valor predeterminado es intentar leer contraseñas del usuario abriendo /dev/tty.

Si hay varios dispositivos cifrados, es posible que necesite suministrar varias claves en la entrada estándar, una por línea.

--machine-readable
--machine-readable=formato
Esta opción se utiliza para hacer la salida más amigable para máquinas cuando es analizada por otros programas. Ver "SALIDA LEGIBLE POR MÁQUINAS" más abajo.
-o opción[,opción,...]
Pasa la(s) opción(es) -o al comando qemu-img(1) para ajustar el formato de salida. Las opciones disponibles dependen del formato de salida (ver --convert) y de la versión instalada del programa qemu-img.

Debería usar -o como máximo una vez. Para pasar varias opciones, sepárelas con comas, p. ej.:

virt-sparsify --convert qcow2 \
  -o cluster_size=512,preallocation=metadata ...

No puede usar esta opción y --in-place juntas.

-q
--quiet
Esto deshabilita las barras de progreso y otra salida innecesaria.
--tmp dispositivo_bloque
--tmp directorio
Solo en modo de copia, usa el dispositivo o directorio con nombre como ubicación del overlay temporal (ver también "TMPDIR" más abajo).

Si el parámetro dado es un dispositivo de bloque, entonces el dispositivo de bloque se escribe directamente. Tenga en cuenta que esto borra el contenido existente del dispositivo de bloque.

Si el parámetro es un directorio, esto es lo mismo que establecer la variable de entorno "TMPDIR".

No puede usar esta opción y --in-place juntas.

--tmp prebuilt:archivo
Solo en modo de copia, la opción especializada --tmp prebuilt:archivo (donde "prebuilt:" es una cadena literal) hace que virt-sparsify use el qcow2 "archivo" como espacio temporal.
  • El archivo debe estar recién formateado como qcow2, con indisk como el archivo de respaldo.
  • Si vuelve a ejecutar virt-sparsify, debe recrear el archivo antes de cada ejecución.
  • Virt-sparsify no elimina el archivo.

Esta opción es utilizada por oVirt, que requiere un archivo temporal especialmente formateado.

-v
--verbose
Habilita mensajes detallados para depuración.
-V
--version
Muestra el número de versión y sale.
--wrap
Envuelve mensajes de error, advertencia e informativos. Este es el valor predeterminado cuando la salida es una tty. Si la salida del programa se redirige a un archivo, el envoltado se deshabilita a menos que use esta opción.
-x
Habilita el seguimiento de llamadas a la API de libguestfs.
--zero partición
--zero logvol
Pone a cero el contenido de la partición o volumen lógico con nombre en el invitado. Todos los datos del dispositivo se pierden, ¡pero la esparsificación es excelente! Puede usar esta opción varias veces.

ESPARSIFICACIÓN EN EL LUGAR

Desde virt-sparsify ≥ 1.26, la herramienta es capaz de realizar esparsificación en el lugar (en lugar de copiar de un disco de entrada a un disco de salida). Esto es más eficiente. No es capaz de recuperar tanto espacio como la esparsificación por copia.

Para usar este modo, especifique una imagen de disco que se modificará en el lugar:

virt-sparsify --in-place disk.img

Algunas opciones no son compatibles con este modo: --convert, --compress y -o porque requieren cambios de formato de disco completos; --check-tmpdir porque no se requiere una gran cantidad de espacio temporal.

La esparsificación en el lugar funciona utilizando el soporte de descarte (también conocido como trim o unmap).

SALIDA LEGIBLE POR MÁQUINAS

La opción --machine-readable se puede usar para hacer que la salida sea más amigable para las máquinas, lo que es útil cuando se llama a virt-sparsify desde otros programas, interfaces gráficas, etc.

Hay dos formas de usar esta opción.

Primero, use la opción por sí sola para consultar las capacidades del binario virt-sparsify. La salida típica se ve así:

$ virt-sparsify --machine-readable
virt-sparsify
ntfs
btrfs

Se imprime una lista de características, una por línea, y el programa sale con el estado 0.

En segundo lugar, use la opción junto con otras opciones para hacer que la salida regular del programa sea más amigable para las máquinas.

Por el momento, esto significa:

1.
Los mensajes de la barra de progreso se pueden analizar desde stdout buscando esta expresión regular: 
^[0-9]+/[0-9]+$
2.
El programa que llama debe tratar los mensajes enviados a stdout (excepto los mensajes de la barra de progreso) como mensajes de estado. Pueden ser registrados y/o mostrados al usuario.
3.
El programa que llama debe tratar los mensajes enviados a stderr como mensajes de error. Además, virt-sparsify sale con un código de estado distinto de cero si hubo un error fatal.

Todas las versiones de virt-sparsify han admitido la opción --machine-readable.

Es posible especificar una cadena de formato para controlar la salida; ver "SALIDA LEGIBLE POR MÁQUINAS AVANZADA" en guestfs(3).

WINDOWS 8

El "inicio rápido" de Windows 8 puede impedir que virt-sparsify funcione. Ver "HIBERNACIÓN DE WINDOWS Y INICIO RÁPIDO DE WINDOWS 8" en guestfs(3).

VARIABLES DE ENTORNO

TMPDIR
Ubicación del directorio temporal utilizado para el archivo overlay temporal potencialmente grande.

En virt-sparsify ≥ 1.28, puede anular esta variable de entorno utilizando la opción --tmp.

Debe asegurarse de que haya suficiente espacio libre en el peor de los casos para una copia completa del disco de origen (tamaño virtual), o establecer $TMPDIR para que apunte a otro directorio que tenga suficiente espacio.

El valor predeterminado es /tmp.

Tenga en cuenta que si $TMPDIR es un tmpfs (por ejemplo, si /tmp está en tmpfs, o si usa "TMPDIR=/dev/shm"), tmpfs tiene un tamaño máximo predeterminado de la mitad de la RAM física. Si virt-sparsify supera esto, se colgará. La solución es usar un disco real o aumentar el tamaño máximo del punto de montaje tmpfs, por ejemplo:

mount -o remount,size=10G /tmp

Si está utilizando la opción --in-place, entonces no se requiere una gran cantidad de espacio temporal.

Para otras variables de entorno, ver "VARIABLES DE ENTORNO" en guestfs(3).

ESTADO DE SALIDA

Este programa devuelve 0 si la operación se completó sin errores. (Esto no significa necesariamente que se haya podido liberar espacio.)

Un código de salida distinto de cero indica un error.

NAME

virt-sparsify

compact a virtual machine disk image

SYNOPSIS

virt-sparsify [--help] [--version] [--quiet] [--verbose] [--align ALIGN]
[--in-place] [--zero-fill] [--check] [--compress COMPRESS]
[--output-compressible COMPRESSIBLE] [--output-compress COMPRESS]
[--output-zeros ZERO] [--machine-readable] [--convert FORMAT]
[--test-mode TEST_MODE] [--delete-existing] [--no-sparse]
[--detect-allocated DETECT_ALLOCATED] [--discard-discard DISCARD_DISCARD]
[--zero-copy ZERO_COPY] [--grow GROW] [--no-grow NO_GROW]
[--insecure-private-keys] [--keyfile KEYFILE] [--password PASSWORD]
FILE

WARNING

This command can destroy data. Always make a backup before running it.

DESCRIPTION

The virt-sparsify command examines a virtual machine disk image and makes it smaller by discarding unused blocks. This is done by finding blocks that are entirely zero or entirely unallocated and then telling the hypervisor to discard them.

Unused blocks are detected using one of several methods:

  • -d, --discard-discard: Try to discard unused blocks using the hypervisor's discard mechanism. This is the fastest method and is preferred if supported.

  • -z, --zero-fill: Fill unused blocks with zeros. This makes the disk image smaller when used with commands like qemu-img convert -c.

  • -c, --compress: Fill unused blocks with random data. This makes the disk image smaller when used with commands like qemu-img convert -c.

You can combine these methods. For example, you can first discard unused blocks using the hypervisor's discard mechanism, and then fill the remaining unused blocks with zeros. This is the default behavior.

The command works on disk images that are already sparse (like qcow2, vmdk, vdi). It also works on flat disk images (like raw) if the underlying filesystem supports sparse files (like ext4, xfs).

To make the disk image smaller, you must run virt-sparsify on the disk image file itself. This is called "in-place sparsification". If you want to create a new, smaller disk image file, use the qemu-img convert command instead.

The command can also be used to convert disk images between different formats, and to compress them.

EXAMPLES

Compact a qcow2 disk image in place:

virt-sparsify --in-place guest.qcow2

Compact a raw disk image in place (requires the underlying filesystem to support sparse files):

virt-sparsify --in-place guest.raw

Compact a raw disk image and create a new qcow2 disk image:

qemu-img convert -c -f raw -O qcow2 guest.raw guest-compact.qcow2

Compact a qcow2 disk image by discarding blocks (fastest method):

virt-sparsify --discard-discard --in-place guest.qcow2

Compact a qcow2 disk image by filling unused blocks with zeros:

virt-sparsify --zero-fill --in-place guest.qcow2

Compact a qcow2 disk image by filling unused blocks with random data:

virt-sparsify --compress --in-place guest.qcow2

Compact a qcow2 disk image using both discard and zero-fill:

virt-sparsify --discard-discard --zero-fill --in-place guest.qcow2

Convert a raw disk image to qcow2 and compact it:

virt-sparsify --convert qcow2 guest.raw guest-compact.qcow2

OPTIONS

The long and short options are compatible. Any combination of the two may be used.

--help

--version

-q, --quiet

Do not display progress or status messages.

-v, --verbose

Display more detailed information.

-a ALIGN, --align ALIGN

Align the output disk image to the specified alignment in bytes. This is useful for optimizing performance on certain storage devices.

-i, --in-place

Compact the disk image in place. This modifies the original disk image file.

Fill unused blocks with random data. The level of compression can be specified with COMPRESS (0-9).

-d DISCARD_DISCARD, --discard-discard DISCARD_DISCARD

-o COMPRESSIBLE, --output-compressible COMPRESSIBLE

Specifies the file to which information about compressible blocks is written.

-o COMPRESS, --output-compress COMPRESS

Specifies the file to which information about compressed blocks is written.

-o ZERO ZERO, --output-zeros ZERO

Specifies the file to which information about zeroed blocks is written.

-m, --machine-readable

-C FORMAT, --convert FORMAT

Convert the disk image to the specified format. Supported formats include qcow2, qcow, vmdk, vdi, raw.

-t TEST_MODE, --test-mode TEST_MODE

--delete-existing

If the output file already exists, delete it before creating the new file.

--no-sparse

--detect-allocated DETECT_ALLOCATED

Method for detecting allocated blocks. Can be `guest`, `none`, `pattern`, `zero`.

Grow the virtual disk image to the specified size.

--no-grow NO_GROW

Specify the password to use for encryption.

IN-PLACE SPARSIFICATION

When --in-place is used, virt-sparsify tries to make the disk image smaller by discarding unused blocks. This is done by finding blocks that are entirely zero or entirely unallocated and then telling the hypervisor to discard them.

If the disk image is already sparse (e.g., qcow2 format), unused blocks are discarded directly. If the disk image is not sparse (e.g., raw format), and the underlying filesystem supports sparse files (e.g., ext4, xfs), then unused blocks are punched out of the file, making it sparse.

If the underlying filesystem does not support sparse files, or if the disk image is not sparse and the filesystem cannot make it sparse, then virt-sparsify will fail.

Note that some hypervisors may not support discarding blocks. In such cases, you will need to use a different method, such as converting the disk image to a different format or using a different tool.

MACHINE READABLE OUTPUT

When --machine-readable is used, the output is formatted as follows:

OBJECT TYPE VALUE

Where OBJECT is one of:

  • progress: Percentage of completion.
  • free-space: Number of free bytes.
  • discarded-space: Number of discarded bytes.
  • total-space: Total size of the disk image.
  • new-size: New size of the disk image after sparsification.

For example:

progress 10
progress 20
discarded-space 1024000
new-size 2048000

WINDOWS 8

Windows 8 and later have built-in support for TRIM (discard). If you are running Windows 8 or later inside a virtual machine, you can enable TRIM to automatically discard unused blocks. This will make the disk image smaller over time.

To enable TRIM in Windows, run the following command in an administrator command prompt:

fsutil behavior set DisableDeleteNotify 0

Then, run the following command to optimize the disk:

defrag /O /U /V C:

Note that this command only works if the underlying filesystem supports TRIM. For example, NTFS supports TRIM, but FAT32 does not.

ENVIRONMENT VARIABLES

The behavior of virt-sparsify is affected by the following environment variables:

  • LIBGUESTFS_DEBUG: If set to a non-empty string, enable debug messages.
  • LIBGUESTFS_MEMTOTAL: Set the total amount of RAM available to libguestfs.
  • LIBGUESTFS_MAXFILES: Set the maximum number of open files allowed by libguestfs.
  • LIBGUESTFS_NETWORK: If set to no, disable network access for libguestfs.
  • LIBGUESTFS_PTRACE: If set to yes, enable ptrace for debugging.

EXIT STATUS

Returns 0 on success, or a non-zero value on error.

The following exit codes are used:

  • 1: Generic error
  • 2: Invalid command line arguments
  • 3: Disk image format not supported
  • 4: In-place sparsification failed
  • 5: Underlying filesystem does not support sparse files
  • 6: Hypervisor does not support discarding blocks

If the --in-place option was used, and discard support is not available in libguestfs, that indicates that copying mode must be used instead.
