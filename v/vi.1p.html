NOMBRE

vi — editor de pantalla orientado (visual)

SINOPSIS

vi [-rR] [-c comando] [-t etiqueta] [-w tamaño] [archivo...]

DESCRIPCIÓN

Esta utilidad se proporcionará en sistemas que admitan la opción de Utilidades de Portabilidad de Usuario y definan el símbolo POSIX2_CHAR_TERM. En otros sistemas es opcional.

La utilidad vi (visual) es un editor de texto orientado a pantalla. Solo los modos abierto y visual del editor se describen en POSIX.1‐2008; consulte el editor de línea ex para capacidades de edición adicionales utilizadas en vi. El usuario puede alternar entre vi y ex y ejecutar comandos ex desde dentro de vi.

Esta página de referencia utiliza el término buffer de edición para describir el texto de trabajo actual. Ninguna implementación específica se implica con este término. Todos los cambios de edición se realizan en el buffer de edición, y ningún cambio en él afectará a ningún archivo hasta que un comando del editor escriba el archivo.

Al usar vi, la pantalla del terminal actúa como una ventana en el buffer de edición. Los cambios realizados en el buffer de edición se reflejarán en la visualización de la pantalla; la posición del cursor en la pantalla indicará la posición dentro del buffer de edición.

Ciertos terminales no tienen todas las capacidades necesarias para soportar la definición completa de vi. Cuando estos comandos no puedan ser soportados en dichos terminales, esta condición no producirá un mensaje de error como "no es un comando del editor" ni informará de un error de sintaxis. La implementación puede aceptar los comandos y producir resultados en la pantalla que sean el resultado de un intento fallido de cumplir los requisitos de este volumen de POSIX.1‐2017 o informar de un error que describa la deficiencia relacionada con el terminal.

Si se ejecuta algún comando que sobrescribe una porción de la pantalla que no sea la última línea de la pantalla (por ejemplo, los comandos ex suspend o !), que no sea el comando ex shell, se le pedirá al usuario un carácter antes de que la pantalla se actualice y la sesión de edición continúe.

Cursor Position Calculation

The column position of a character in the display is calculated relative to the start of the buffer line that contains the character. This calculation applies regardless of whether the buffer line is displayed on a single screen line or is continued onto additional screen lines due to line folding. The column position in the display shall be calculated for an infinite width display; for example, the column related to a character that is part of a line that has been folded onto additional screen lines will be offset from the display line column where the buffer line begins, not from the beginning of a particular display line.

The display cursor column in the display is based on the value of the current column, as follows, with each rule applied in turn:

1.
If the current column is after the last display line column used by the displayed line, the display cursor column shall be set to the last display line column occupied by the last non-<newline> in the current line; otherwise, the display cursor column shall be set to the current column.
2.
If the character of which some portion is displayed in the display line column specified by the display cursor column requires more than a single display line column:
a.
If in text input mode, the display cursor column shall be adjusted to the first display line column in which any portion of that character is displayed.
b.
Otherwise, the display cursor column shall be adjusted to the last display line column in which any portion of that character is displayed.

The current column shall not be changed by these adjustments to the display cursor column.

If an error occurs during the parsing or execution of a vi command:

*
The terminal shall be alerted. Execution of the vi command shall stop, and the cursor (for example, the current line and column) shall not be further modified.
*
Unless otherwise specified by the following command sections, it is unspecified whether an informational message shall be displayed.
*
Any partially entered vi command shall be discarded.
*
If the vi command resulted from a map expansion, all characters from that map expansion shall be discarded, except as otherwise specified by the map command (see ex).
*
If the vi command resulted from the execution of a buffer, no further commands caused by the execution of the buffer shall be executed.

Search Forward

Synopsis:
[count] /regular expression/
[count] ?regular expression?

Search forward (for /) or backward (for ?) for a regular expression. If the search wraps around the end of the file, the search continues.

If the regular expression is not found, it shall be an error.

The regular expression syntax is the same as that used by egrep. Special characters in the regular expression are: [ . ^ $ * \ / [ ] and optionally \{ \} and |.

If the search wraps around the end of the file, the file is effectively treated as circular for the purpose of this search.

If the regular expression is empty, the previous regular expression is used.

If the command is /

1.
The current line shall be set to the first line in the edit buffer that matches the regular expression at or after the current line.
2.
If the current line is adjusted, the current column shall be set to the column of the first character matching the regular expression in the new current line.

If the command is ?

1.
The current line shall be set to the first line in the edit buffer that matches the regular expression at or before the current line.
2.
If the current line is adjusted, the current column shall be set to the column of the first character matching the regular expression in the new current line.

If the count is specified:

1.
For /, the search shall continue for count - 1 additional matches.
2.
For ?, the search shall continue backward for count - 1 additional matches.

The current line and current column shall be updated to the location of the countth match.

The last used regular expression shall be saved.

[count] <control>-Y

Display the line count lines before the first line currently displayed.

If the first line of the edit buffer is displayed, it shall be an error. If there is no line count lines before the first line currently displayed, the first line of the display shall display some portion of the first line of the edit buffer.

Current line: Unchanged if the previous current character is displayed; otherwise, set to the last line displayed.

Current column: Unchanged.

End of File

Synopsis:
[count] <control>-Z

If the current line is the last line of the edit buffer, it shall be an error.

If the window edit option is less than 3, display a screen where the first line of the display shall be some portion of:

(current last line) +1

otherwise, display a screen where the first line of the display shall be some portion of:

(current first line) + count x ((window edit option) -2)

If this calculation would result in a line that is after the last line of the edit buffer, the last line of the display shall display some portion of the last line of the edit buffer.

Current line: If no lines from the previous display remain on the screen, set to the first line of the display; otherwise, set to (line + the number of new lines displayed on this screen).

Current column: Set to non-<blank>.

End of Line

Synopsis:
[count] <control>-X
[count] $

If there are no characters after the current character on the current line, it shall be an error. If there are less than count characters after the current line, count shall be adjusted to the number of subsequent characters on the line.

If used as a motion command:

1.
The text region shall be from the character after the starting cursor up to and including the countth character after the starting cursor.
2.
Any text copied to a buffer shall be in character mode.

If not used as a motion command:

Current line: Unchanged.

Current column: Set to (column + the number of columns occupied by count characters starting with the next current column).

Add Line Below

Synopsis:
a

Enter input mode. Insert text following the current character. The new text is inserted after the current character, and the cursor is positioned after the inserted text.

Current line: Unchanged.

Current column: Set to (column + number of columns occupied by inserted text).

Append Line Below

Synopsis:
A

Enter input mode. Insert text following the end of the current line. The new text is inserted after the last character of the line, and the cursor is positioned after the inserted text.

Current line: Unchanged.

Current column: Set to (last column + number of columns occupied by inserted text).

Current line: Unchanged.

Current column: Set to the number of columns occupied by inserted text.

u

Current line: Unchanged.

Current column: Unchanged.

Current line: Unchanged.

Current column: Unchanged.

Mover al Carácter Coincidente

Sinopsis:
%

Si el carácter en la posición actual es

no es un paréntesis, corchete o llave, busca hacia adelante en la línea hasta el primer carácter de ese tipo. Si no se encuentra ningún carácter de este tipo, se producirá un error.

El carácter coincidente será el paréntesis, corchete o llave que coincida con el paréntesis, corchete o llave, respectivamente, que se encontraba en la posición actual o que se encontró en la línea actual.

La coincidencia se determinará de la siguiente manera, para un paréntesis abierto:

1.
Establezca un contador en 1.
2.
Busque hacia adelante hasta encontrar un paréntesis o se alcance el final del búfer de edición.
3.
Si se alcanza el final del búfer de edición, se producirá un error.
4.
Si se encuentra un paréntesis abierto, incremente el contador en 1.
5.
Si se encuentra un paréntesis de cierre, decremente el contador en 1.
6.
Si el contador es cero, el carácter actual es el carácter coincidente.

La coincidencia para un paréntesis de cierre será equivalente, excepto que la búsqueda se realizará hacia atrás, desde el carácter inicial hasta el principio del búfer; un paréntesis de cierre incrementará el contador en 1 y un paréntesis abierto lo decrementará en 1.

La coincidencia para corchetes y llaves será equivalente, excepto que la búsqueda se realizará para corchetes abiertos y de cierre o llaves abiertas y de cierre. Está definido por la implementación si se buscan y coinciden también otros caracteres.

Si se utiliza como comando de movimiento:

1.
Si el cursor coincidente estaba después del cursor de inicio en el búfer de edición, y la posición del cursor de inicio estaba en o antes del primer carácter que no es un <espacio> ni un <nueva línea> en la línea de inicio, y la posición del cursor coincidente estaba en o después del último carácter que no es un <espacio> ni un <nueva línea> en la línea coincidente, la región de texto consistirá en la línea actual hasta la línea coincidente, inclusive, y cualquier texto copiado a un búfer estará en modo de línea.
2.
Si el cursor coincidente estaba antes del cursor de inicio en el búfer de edición, y la posición del cursor de inicio estaba en o después del último carácter que no es un <espacio> ni un <nueva línea> en la línea de inicio, y la posición del cursor coincidente estaba en o antes del primer carácter que no es un <espacio> ni un <nueva línea> en la línea coincidente, la región de texto consistirá en la línea actual hasta la línea coincidente, inclusive, y cualquier texto copiado a un búfer estará en modo de línea.
3.
De lo contrario, la región de texto consistirá en el carácter de inicio hasta el carácter coincidente, inclusive, y cualquier texto copiado a un búfer estará en modo de carácter.

Si no se utiliza como comando de movimiento:

Línea actual: Se establece en la línea donde se encuentra el carácter coincidente.

Columna actual: Se establece en la última columna donde se muestra cualquier parte del carácter coincidente.

Comandos del Modo de Entrada en vi

En el modo de entrada de texto, la línea actual consistirá en cero o más de las siguientes categorías, más el <newline> de terminación:

1.
Caracteres precedentes al punto de entrada de texto

Los caracteres de esta categoría no se modificarán durante el modo de entrada de texto.

2.
Caracteres de autoindent

Los caracteres de autoindent se insertarán automáticamente en cada línea que se cree en el modo de entrada de texto, ya sea como resultado de ingresar un <newline> o <carriage-return> mientras se está en modo de entrada de texto, o como efecto del propio comando; por ejemplo, O u o (ver el comando ex autoindent), como si los hubiera ingresado el usuario.

Debería ser posible borrar caracteres de autoindent con el comando <control>-D; no se especifica si se pueden borrar con los caracteres <control>-H, <control>-U y <control>-W. Borrar cualquier carácter de autoindent convierte el glifo en columnas de borrado y elimina el carácter del buffer de edición, pero no cambia su representación en la pantalla.

3.
Caracteres de entrada de texto

Los caracteres de entrada de texto son los caracteres ingresados por el usuario. Borrar cualquier carácter de entrada de texto convierte el glifo en columnas de borrado y elimina el carácter del buffer de edición, pero no cambia su representación en la pantalla.

Cada carácter de entrada de texto ingresado por el usuario (que no tenga un significado especial) se tratará de la siguiente manera:

a.
El carácter de entrada de texto se añadirá al último carácter del buffer de edición de la primera, segunda o tercera categoría.
b.
Si no hay columnas de borrado en la pantalla, el comando de entrada de texto fue el comando R, y caracteres de la quinta categoría de la línea original siguen al cursor, el siguiente carácter de este tipo se eliminará del buffer de edición. Si la opción de edición slowopen no está establecida, el glifo correspondiente en la pantalla se convertirá en columnas de borrado.
c.
Si hay columnas de borrado en la pantalla, tantas columnas como ocupen, o tantas como sean necesarias, se sobrescribirán para mostrar el carácter de entrada de texto. (Si solo una parte de un glifo de múltiples columnas se sobrescribe, el resto permanecerá en la pantalla, y continuará tratándose como columnas de borrado; no se especifica si el resto del glifo se modifica de alguna manera.)
d.

4.
Columnas de borrado

Las columnas de borrado no son parte lógica del buffer de edición, aparecen solo en la pantalla y pueden ser sobrescritas en la pantalla por caracteres de entrada de texto posteriores. Cuando el modo de entrada de texto finaliza, todas las columnas de borrado ya no aparecerán en la pantalla.

Las columnas de borrado son inicialmente la región de texto especificada por el comando c (ver Cambiar); sin embargo, borrar caracteres de autoindent o de entrada de texto hace que los glifos de los caracteres borrados se traten como columnas de borrado.

Los caracteres de esta categoría no se modificarán durante el modo de entrada de texto, excepto según se especifica en la categoría 3.b. para el comando de entrada de texto R, o como caracteres de <espacio en blanco> borrados cuando se ingresa un <newline> o <carriage-return>.

La capacidad de redibujar la pantalla se mantiene si se especifica el nuevo tamaño de ventana opcional, y en los comandos <control>‐L y <control>‐R.

La semántica de z^ es, en el mejor de los casos, confusa. La práctica histórica es que se muestra la pantalla anterior a la pantalla que terminó con la línea especificada. POSIX.1‐2008 requiere la conformidad con la práctica histórica.

Históricamente, el comando z no mostraba una línea parcial en la parte superior o inferior de la pantalla. Si la línea parcial se hubiera mostrado normalmente en la parte inferior de la pantalla, el comando funcionaba, pero la línea parcial se reemplazaba con caracteres '@'. Si la línea parcial se hubiera mostrado normalmente en la parte superior de la pantalla, el comando fallaba. Para consistencia y simplicidad de especificación, POSIX.1‐2008 no permite este comportamiento.

Históricamente, el comando z con una especificación de línea de 1 ignoraba el comando. Para consistencia y simplicidad de especificación, POSIX.1‐2008 no permite este comportamiento.

Históricamente, el comando z no establecía la columna del cursor al primer carácter no-<espacio> si la primera pantalla debía ser mostrada y ya estaba mostrada. Para consistencia y simplicidad de especificación, POSIX.1‐2008 no permite este comportamiento.

Comandos del Modo de Entrada en vi

Las implementaciones históricas de vi no permitían al usuario borrar más de una sola línea de entrada, ni usar caracteres de borrado normales como borrado de línea, borrado de palabra y borrado para borrar caracteres de autoindent. Dado que existen implementaciones de vi que no tienen estas limitaciones, ambos comportamientos están permitidos, pero solo se requiere la práctica histórica. En el caso de estas extensiones, se requiere que vi haga una pausa en los límites de autoindent y de la línea anterior.

Las implementaciones históricas de vi actualizaban solo la porción de la pantalla donde se mostraba el carácter del cursor actual. Por ejemplo, considere las pulsaciones de teclas de entrada de vi:

iabcd<escape>0C<tab>

Históricamente, el <tab> sobrescribiría los caracteres "abcd" cuando se mostraba. Otras implementaciones reemplazan solo el carácter 'a' con el <tab>, y luego empujan el resto de los caracteres hacia adelante del cursor. Ambas implementaciones tienen problemas. La implementación histórica es probablemente visualmente más agradable para el ejemplo anterior; sin embargo, para las pulsaciones de teclas:

iabcd<ESC>0R<tab><ESC>

la implementación histórica resulta en que la cadena "bcd" desaparece y luego reaparece mágicamente cuando se introduce el carácter <ESC>. POSIX.1‐2008 requiere el comportamiento anterior al sobrescribir columnas de borrado —es decir, sobrescribir caracteres que ya no forman parte lógicamente del búfer de edición— y el comportamiento posterior en otros casos.

Las implementaciones históricas de vi descartaban los caracteres <control>‐D y <control>‐T cuando se introducían en lugares donde su funcionalidad de comando no era apropiada. POSIX.1‐2008 requiere que la funcionalidad de <control>‐T siempre esté disponible, y que <control>‐D se trate como cualquier otra tecla cuando no se opera en caracteres de autoindent.

NUL

Algunas implementaciones históricas de vi limitaban el número de caracteres introducidos usando el carácter de entrada NUL a 256 bytes. POSIX.1‐2008 permite esta limitación; sin embargo, se alienta a las implementaciones a eliminar este límite.

<control>‐D

Ver también Rationale para el comando del modo de entrada <newline>. Las suposiciones ocultas en el comando <control>‐D (y en la especificación general de autoindent de vi) son que los caracteres de <espacio> ocupan una sola columna en la pantalla y que los caracteres de <tab> se componen de un número integral de caracteres de <espacio>.

<newline>

Se permite a las implementaciones reescribir caracteres de autoindent en la línea cuando se introducen <newline>, <carriage-return>, <control>‐D, y <control>‐T, o cuando se usan los comandos de shift, porque las implementaciones históricas lo han hecho y lo han encontrado necesario. Por ejemplo, un <control>‐D cuando el cursor está precedido por un solo <tab>, con tabstop establecido en 8, y shiftwidth establecido en 3, resultará en que el <tab> sea reemplazado por varios caracteres de <espacio>.

<control>‐T

Ver también el Rationale para el comando del modo de entrada <newline>. Históricamente, <control>‐T solo funcionaba si no se habían introducido caracteres no-<espacio> en la línea de entrada actual. Además, los caracteres insertados por <control>‐T se trataban como caracteres de autoindent, y no podían borrarse usando caracteres de borrado de usuario normales. Dado que existen implementaciones que no tienen estas limitaciones, y dado que moverse a un límite de columna es generalmente útil, POSIX.1‐2008 requiere que ambas limitaciones se eliminen.

<control>‐V

Históricamente, vi usaba ^V, independientemente del valor del carácter literal siguiente de la terminal. POSIX.1‐2008 requiere conformidad con la práctica histórica.

Los usos descritos para <control>‐V también se pueden lograr con <control>‐Q, lo cual es útil en terminales que usan <control>‐V para la función de flecha hacia abajo. Sin embargo, la mayoría de las implementaciones históricas usan <control>‐Q para el carácter START de termios, por lo que el editor generalmente no recibirá el <control>‐Q a menos que el modo stty ixon esté desactivado. (Además, algunas implementaciones históricas de vi activan explícitamente el modo ixon, por lo que era difícil para el usuario desactivarlo.) Cualquiera de los caracteres de comando descritos en POSIX.1‐2008 puede volverse ineficaz por su selección como caracteres de control de termios, usando la utilidad stty u otros métodos descritos en el volumen de Interfaces del Sistema de POSIX.1‐2017.

<ESC>

Históricamente, SIGINT alertaba a la terminal cuando se usaba para finalizar el modo de entrada. Este comportamiento está permitido, pero no requerido, por POSIX.1‐2008.
