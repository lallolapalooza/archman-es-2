VIM(1) Manual de comandos generales VIM(1)

NOMBRE

vim - Vi IMproved, un editor de texto para programadores

SINOPSIS

vim [opciones] [archivo ..]
vim [opciones] -
vim [opciones] -t etiqueta
vim [opciones] -q [archivo_errores]

ex
view
gvim gview evim eview
rvim rview rgvim rgview

DESCRIPCIÓN

Vim es un editor de texto compatible hacia atrás con Vi. Puede ser usado para editar todo tipo de texto plano. Es especialmente útil para editar programas.

Hay muchas mejoras sobre Vi: deshacer multinivel, ventanas y buffers múltiples, resaltado de sintaxis, edición de línea de comandos, completado de nombres de archivo, ayuda en línea, selección visual, etc. Vea ":help vi_diff.txt" para un resumen de las diferencias entre Vim y Vi.

Mientras se ejecuta Vim se puede obtener mucha ayuda del sistema de ayuda en línea, con el comando ":help". Vea la sección AYUDA EN LÍNEA más abajo.

La mayoría de las veces Vim se inicia para editar un solo archivo con el comando

vim archivo

Más generalmente Vim se inicia con:

vim [opciones] [lista_de_archivos]

Si falta la lista de archivos, el editor se iniciará con un buffer vacío. De lo contrario, exactamente una de las siguientes cuatro opciones puede ser utilizada para elegir uno o más archivos para editar.

archivo ..
Una lista de nombres de archivo. El primero será el archivo actual y se leerá en el buffer. El cursor se posicionará en la primera línea del buffer. Puede ir a los otros archivos con el comando ":next". Para editar un archivo que comience con un guion, preceda la lista de archivos con "--".
-
El archivo a editar se lee desde la entrada estándar. Los comandos se leen desde la salida de error estándar, que debería ser una tty.
-t {etiqueta}
El archivo a editar y la posición inicial del cursor dependen de una "etiqueta", una especie de etiqueta de salto. Se busca {etiqueta} en el archivo de etiquetas, el archivo asociado se convierte en el archivo actual y se ejecuta el comando asociado. Mayormente esto se usa para programas C, en cuyo caso {etiqueta} podría ser el nombre de una función. El efecto es que el archivo que contiene esa función se convierte en el archivo actual y el cursor se posiciona al inicio de la función. Vea ":help tag-commands".
-q [archivo_errores]
Iniciar en modo quickFix. Se lee el archivo [archivo_errores] y se muestra el primer error. Si [archivo_errores] se omite, el nombre del archivo se obtiene de la opción 'errorfile' (por defecto "AztecC.Err" para Amiga, "errors.err" en otros sistemas). Se puede saltar a errores posteriores con el comando ":cn". Vea ":help quickfix".

Vim se comporta de manera diferente, dependiendo del nombre del comando (el ejecutable puede seguir siendo el mismo archivo).

vim
La forma "normal", todo es por defecto.
ex
Iniciar en modo Ex. Ir a modo Normal con el comando ":vi". También se puede hacer con el argumento "-e".
view
Iniciar en modo de solo lectura. Estará protegido contra la escritura de los archivos. También se puede hacer con el argumento "-R".
gvim gview
La versión GUI. Inicia una nueva ventana. También se puede hacer con el argumento "-g".
evim eview
La versión GUI en modo fácil. Inicia una nueva ventana. También se puede hacer con el argumento "-y".
rvim rview rgvim rgview
Igual que los anteriores, pero con restricciones. No será posible iniciar comandos de shell ni suspender Vim. También se puede hacer con el argumento "-Z".

OPCIONES

Las opciones pueden darse en cualquier orden, antes o después de los nombres de archivo. Las opciones sin argumento pueden combinarse después de un solo guion.

+[num]
Para el primer archivo, el cursor se posicionará en la línea "num". Si "num" falta, el cursor se posicionará en la última línea.
+/{pat}
Para el primer archivo, el cursor se posicionará en la línea con la primera ocurrencia de {pat}. Vea ":help search-pattern" para los patrones de búsqueda disponibles.
+{comando}
-c {comando}
{comando} se ejecutará después de que se haya leído el primer archivo. {comando} se interpreta como un comando Ex. Si {comando} contiene espacios, debe ir entre comillas dobles (esto depende del shell que se use). Ejemplo: vim "+set si" main.c
Nota: Puede usar hasta 10 comandos "+" o "-c".
-A
Si Vim ha sido compilado con soporte ARABIC para editar archivos orientados de derecha a izquierda y mapeo de teclado árabe, esta opción inicia Vim en modo árabe, es decir, se establece 'arabic'. De lo contrario, se da un mensaje de error y Vim se aborta.
-b
Modo binario. Se establecerán algunas opciones que permiten editar un archivo binario o ejecutable.
-C
Compatible. Establece la opción 'compatible'. Esto hará que Vim se comporte mayormente como Vi, aunque exista un archivo .vimrc.
-d
Iniciar en modo diff. Debe haber entre dos y ocho argumentos de nombre de archivo. Vim abrirá todos los archivos y mostrará las diferencias entre ellos. Funciona como vimdiff(1).
-d {dispositivo}, -dev {dispositivo}
Abre {dispositivo} para usarlo como terminal. Solo en Amiga. Ejemplo: "-d con:20/30/600/150".
-D
Depuración. Entra en modo de depuración al ejecutar el primer comando de un script.
-e
Inicia Vim en modo Ex, igual que si el ejecutable se hubiera llamado "ex".
-E
Inicia Vim en modo Ex mejorado, igual que si el ejecutable se hubiera llamado "exim".
-f
Primer plano. Para la versión GUI, Vim no se bifurcará ni se desvinculará del shell desde el que se inició. En Amiga, Vim no se reinicia para abrir una nueva ventana. Esta opción debe usarse cuando Vim es ejecutado por un programa que esperará a que termine la sesión de edición (por ejemplo, correo). En Amiga, los comandos ":sh" y ":!" no funcionarán.
-F
Si Vim ha sido compilado con soporte FKMAP para editar archivos orientados de derecha a izquierda y mapeo de teclado farsi, esta opción inicia Vim en modo farsi, es decir, se establecen 'fkmap' y 'rightleft'. De lo contrario, se da un mensaje de error y Vim se aborta.
Nota: El soporte Farsi ha sido eliminado en el parche 8.1.0932.
-g
Si Vim ha sido compilado con soporte GUI, esta opción habilita la GUI. Si no se compiló soporte GUI, se da un mensaje de error y Vim se aborta.
-H
Si Vim ha sido compilado con soporte RIGHTLEFT para editar archivos orientados de derecha a izquierda y mapeo de teclado hebreo, esta opción inicia Vim en modo hebreo, es decir, se establecen 'hkmap' y 'rightleft'. De lo contrario, se da un mensaje de error y Vim se aborta.
-i {viminfo}
Especifica el nombre de archivo a usar al leer o escribir el archivo viminfo, en lugar del predeterminado "~/.viminfo".
Esto también se puede usar para omitir el uso del archivo .viminfo, dando el nombre "NONE".
-l
Modo Lisp. Activa las opciones 'lisp' y 'showmatch'.
-L
Igual que -r.
-m
La modificación de archivos está deshabilitada. Restablece la opción 'write'. Todavía puedes modificar el búfer, pero no es posible escribir un archivo.
-M
No se permiten modificaciones. Las opciones 'modifiable' y 'write' se desactivarán, de modo que no se permitirán cambios y no se podrán escribir archivos. Ten en cuenta que estas opciones se pueden activar para permitir realizar modificaciones.
-n
No se utilizará ningún archivo de intercambio. La recuperación después de un bloqueo será imposible. Útil si quieres editar un archivo en un medio muy lento (por ejemplo, un disquete). También se puede hacer con ":set uc=0". Se puede deshacer con ":set uc=200".
-N
Modo no compatible. Restablece la opción 'compatible'. Esto hará que Vim se comporte un poco mejor, aunque menos compatible con Vi, incluso si no existe un archivo .vimrc.
-nb
Conviértete en un servidor de edición para NetBeans. Consulta la documentación para obtener más detalles.
-o[N]
Abre N ventanas apiladas. Cuando N se omite, abre una ventana para cada archivo.
-O[N]
Abre N ventanas una al lado de la otra. Cuando N se omite, abre una ventana para cada archivo.
-p[N]
Abre N pestañas. Cuando N se omite, abre una pestaña para cada archivo.
-P {título-padre}
Solo GUI de Win32: Especifica el título de la aplicación principal. Cuando sea posible, Vim se ejecutará en una ventana MDI dentro de la aplicación. {título-padre} debe aparecer en el título de la ventana de la aplicación principal. Asegúrate de que sea lo suficientemente específico. Ten en cuenta que la implementación sigue siendo primitiva. No funcionará con todas las aplicaciones y el menú no funciona.
-r
Lista los archivos de intercambio, con información sobre cómo usarlos para la recuperación.
-r {archivo}
Modo de recuperación. El archivo de intercambio se utiliza para recuperar una sesión de edición bloqueada. El archivo de intercambio es un archivo con el mismo nombre que el archivo de texto con ".swp" añadido. Consulta ":help recovery".
-R
Modo de solo lectura. Se activará la opción 'readonly'. Todavía puedes editar el búfer, pero se te impedirá sobrescribir un archivo accidentalmente. Si deseas sobrescribir un archivo, añade un signo de exclamación al comando Ex, como en ":w!". La opción -R también implica la opción -n (ver arriba). La opción 'readonly' se puede restablecer con ":set noro". Consulta ":help 'readonly'".
-s
Modo silencioso. Solo cuando se inicia como "Ex" o cuando la opción "-e" se dio antes que la opción "-s".
-s {scriptin}
Se lee el archivo de script {scriptin}. Los caracteres del archivo se interpretan como si los hubieras escrito. Lo mismo se puede hacer con el comando ":source! {scriptin}". Si se llega al final del archivo antes de que el editor salga, se leerán caracteres adicionales del teclado.
-S {archivo}
Se procesará {archivo} después de leer el primer archivo. Esto es equivalente a -c "source {archivo}". {archivo} no puede empezar con '-'. Si se omite {archivo}, se usará "Session.vim" (solo funciona cuando -S es el último argumento).
-T {terminal}
Indica a Vim el nombre del terminal que estás utilizando. Solo es necesario cuando la forma automática no funciona. Debe ser un terminal conocido por Vim (incorporado) o definido en el archivo termcap o terminfo.
-u {vimrc}
Usa los comandos del archivo {vimrc} para inicializaciones. Se omiten todas las demás inicializaciones. Úsalo para editar un tipo especial de archivos. También se puede usar para omitir todas las inicializaciones dando el nombre "NONE". Consulta ":help initialization" dentro de vim para obtener más detalles.
-U {gvimrc}
Usa los comandos del archivo {gvimrc} para inicializaciones de GUI. Se omiten todas las demás inicializaciones de GUI. También se puede usar para omitir todas las inicializaciones de GUI dando el nombre "NONE". Consulta ":help gui-init" dentro de vim para obtener más detalles.
-v
Inicia Vim en modo Vi, como si el ejecutable se llamara "vi". Esto solo tiene efecto cuando el ejecutable se llama "ex".
-V[N]
Verboso. Muestra mensajes sobre qué archivos se están procesando y sobre la lectura y escritura de un archivo viminfo. El número opcional N es el valor de 'verbose'. El valor predeterminado es 10.
-V[N]{nombre-archivo}
Igual que -V y establece 'verbosefile' a {nombre-archivo}. El resultado es que los mensajes no se muestran, sino que se escriben en el archivo {nombre-archivo}. {nombre-archivo} no debe empezar con un dígito.
-w{número}
Establece la opción 'window' a {número}.
-w {scriptout}
Todos los caracteres que escribas se registrarán en el archivo {scriptout}, hasta que salgas de Vim. Esto es útil si deseas crear un archivo de script para usar con "vim -s" o ":source!". Si el archivo {scriptout} existe, se añadirán caracteres.
-W {scriptout}
Igual que -w, pero se sobrescribe un archivo existente.
-x
Si Vim se ha compilado con soporte de cifrado, utiliza el cifrado al escribir archivos. Pedirá una clave de cifrado.
-X
No conectar al servidor X. Reduce el tiempo de inicio en una terminal, pero el título de la ventana y el portapapeles no se utilizarán.
-Y
No conectar al compositor de Wayland.
-y
Inicia Vim en modo fácil, como si el ejecutable se llamara "evim" o "eview". Hace que Vim se comporte como un editor de hacer clic y escribir.
-Z
Modo restringido. Funciona como si el ejecutable se iniciara con "r".
--
Indica el final de las opciones. Los argumentos posteriores se tratarán como nombres de archivo. Esto se puede usar para editar un nombre de archivo que comience con un '-'.
--clean
No utilices ninguna configuración personal (vimrc, plugins, etc.). Útil para ver si un problema se reproduce con una configuración limpia de Vim.
--cmd {comando}
Similar a usar "-c", pero el comando se ejecuta justo antes de procesar cualquier archivo vimrc. Puedes usar hasta 10 de estos comandos, independientemente de los comandos "-c".
--echo-wid
Solo GUI GTK: Muestra el ID de ventana en la salida estándar.
--gui-dialog-file {nombre}
Cuando se utiliza la GUI, en lugar de mostrar un diálogo, escribe el título y el mensaje del diálogo en el archivo {nombre}. El archivo se crea o se añade. Solo es útil para pruebas, para evitar que la prueba se quede bloqueada en un diálogo que no se puede ver. Sin la GUI, el argumento se ignora.
--help, -h, -?
Proporciona un poco de ayuda sobre los argumentos y opciones de la línea de comandos. Después de esto, Vim saldrá.
--literal
Toma los nombres de archivo como literales, no expande comodines. Esto no tiene ningún efecto en Unix, donde el shell expande los comodines.
--log {nombre-archivo}
Si Vim se ha compilado con las funciones eval y channel, comienza a registrar y escribe entradas en {nombre-archivo}. Esto funciona como llamar a ch_logfile({nombre-archivo}, 'ao') muy temprano durante el inicio.
--nofork
En primer plano. Para la versión GUI, Vim no se bifurcará ni se separará del shell en el que se inició.
--noplugin
Omite la carga de plugins. Implicado por -u NONE.
--not-a-term
Indica a Vim que el usuario sabe que la entrada y/o salida no está conectada a una terminal. Esto evitará la advertencia y el retraso de dos segundos que ocurriría.
--remote
Conéctate a un servidor Vim y haz que edite los archivos proporcionados en el resto de los argumentos. Si no se encuentra ningún servidor, se muestra una advertencia y los archivos se editan en el Vim actual.
--remote-expr {expr}
Conéctate a un servidor Vim, evalúa {expr} en él e imprime el resultado en la salida estándar.
--remote-send {teclas}
Conéctate a un servidor Vim y envíale {teclas}.
--remote-silent
Igual que --remote, pero sin la advertencia cuando no se encuentra ningún servidor.
--remote-wait
Igual que --remote, pero Vim no sale hasta que los archivos se hayan editado.
--remote-wait-silent
Igual que --remote-wait, pero sin la advertencia cuando no se encuentra ningún servidor.
--serverlist
Lista los nombres de todos los servidores Vim que se pueden encontrar.
--servername {nombre}
Usa {nombre} como nombre del servidor. Se utiliza para el Vim actual, a menos que se use con un argumento --remote, en cuyo caso es el nombre del servidor al que conectarse. Si se está utilizando el backend socketserver, si el nombre comienza con "/", "./", o "../", se toma como una ruta absoluta, relativa o relativa al socket.
--clientserver {backend}
Usa {backend} como backend para la funcionalidad de clienteservidor, ya sea "socket" o "x11" respectivamente. Solo disponible cuando se compila con las características de socketserver y X11 presentes.
--socketid {id}
Solo GUI GTK: Usa el mecanismo GtkPlug para ejecutar gVim en otra ventana.
--startuptime {archivo}
Durante el inicio, escribe mensajes de tiempo en el archivo {fname}.

NAME

gvim - Vi IMproved - the graphical version

SYNOPSIS

gvim [option ...] [file ...]

vim [option ...] [file ...]

DESCRIPTION

Vim is a text editor that has been enhanced with many additional features. gVim is the graphical user interface version of Vim. It allows you to use Vim with mouse interaction and menus.

The command vim is often a symbolic link to gvim (or vim), depending on how Vim was configured.

See the Vim documentation for a full explanation of commands and features.

OPTIONS

-a
Start Vim in "safe mode". This means that Vim will not load any plugin- or startup-scripts. This is useful when you suspect a plugin or script is causing problems.
-b
Start Vim in binary mode. Useful for editing binary files.
-c {command}
Execute {command} after the first file has been read. This can be used to modify the file before you start editing it. You can use this option multiple times. You can use -c to start editing at a specific line, e.g. -c "123" to start at line 123.
-d
Start Vim in diff mode. This is equivalent to the command ":diffsplit" with the next argument as the file to compare with.
-E
Start Vim in Ex mode. This is the non-graphical, line-oriented version of Vim.
-f
Start Vim in foreground. This is useful for running Vim from a script, where you don't want Vim to detach itself from the terminal.
-g
Start Vim in GUI mode. This is the default behaviour when you run gvim.
-h
Display a help message and exit.
-l
Start Vim in LaTeX mode. Useful for editing LaTeX documents.
-m
Do not write the file. Useful for viewing files without accidentally modifying them.
-n
Do not use a swap file. This is useful for editing files on a read-only medium, or when you don't have permission to create swap files.
-o [N]
Start Vim with N horizontal split windows. If N is omitted, one split window is created for each file argument.
-p [N]
Start Vim with N vertical split windows. If N is omitted, one split window is created for each file argument.
-R
Start Vim in read-only mode. This is equivalent to setting the 'readonly' option.
-s {scriptin}
Read commands from the file {scriptin} when Vim starts. This is similar to using the :source command, but it can be used before any files are loaded. This can be useful for scripting Vim. For example, to start Vim and edit a file, then save it and exit: 
                 vim -s myscript.vim myfile.txt
where myscript.vim contains commands like "wq".
-t {tag}
Start Vim and edit the file where the tag {tag} is defined. This is useful for quickly jumping to the definition of a function or variable in a programming project.
-T {terminal}
Set the terminal type to {terminal}. This is usually not needed, as Vim will try to detect the terminal type automatically.
-u {vimrc}
Use Vim startup file {vimrc} instead of the default $MYVIMRC. This allows you to specify a custom configuration file for Vim. If {vimrc} is "NONE", then no Vim startup file is loaded.
-v
Start Vim in Vi mode. This is the default behaviour when you run vim.
-V[N]
Set the verbosity level for logging. If N is omitted, it defaults to 100. This is useful for debugging. See :help 'verbose' for more information.
-w {log}
Write the keystrokes to the file {log}. This is useful for recording macros or for debugging. You can later replay the log file using the -s option.
-x
Start Vim in cipher mode. All files will be encrypted. You will be prompted for a key.
-X
Do not start the X11 error handler. This is useful when running Vim in a terminal that does not support X11.
-Z
Suspend Vim. This is equivalent to pressing CTRL-Z.
--icon
Set the icon and window title to the name of the first file. This is only applicable when running in a GUI environment.
--locale {locale}
Set the locale for Vim. This affects language, character encoding, and other locale-specific settings.
--remote
Make gvim connect to a running Vim server and open the specified files there. If no server is running, start a new one.
--servername {name}
Set the server name for gvim. This is used when connecting to a running Vim server.
--role {role}
Set the role of the gvim window. This is used for accessibility purposes, for example, to indicate that the window is a text editor.
--version
Print version information and exit.
--windowid {id}
Win32 GUI only: Make gVim try to use the window {id} as a parent, so that it runs inside that window.

ON-LINE HELP

Type ":help" in Vim to get started. Type ":help subject" to get help on a specific subject. For example: ":help ZZ" to get help for the "ZZ" command. Use <Tab> and CTRL-D to complete subjects (":help cmdline-completion"). Tags are present to jump from one place to another (sort of hypertext links, see ":help"). All documentation files can be viewed in this way, for example ":help syntax.txt".

FILES

/usr/local/share/vim/vim??/doc/*.txt
The Vim documentation files. Use ":help doc-file-list" to get the complete list.
vim?? is short version number, like vim91 for Vim 9.1
/usr/local/share/vim/vim??/doc/tags
The tags file used for finding information in the documentation files.
/usr/local/share/vim/vim??/syntax/syntax.vim
System wide syntax initializations.
/usr/local/share/vim/vim??/syntax/*.vim
Syntax files for various languages.
/usr/local/share/vim/vimrc
System wide Vim initializations.
~/.vimrc, ~/.vim/vimrc, $XDG_CONFIG_HOME/vim/vimrc
Your personal Vim initializations (first one found is used).
/usr/local/share/vim/gvimrc
System wide gvim initializations.
~/.gvimrc, ~/.vim/gvimrc, $XDG_CONFIG_HOME/vim/gvimrc
Your personal gVim initializations (first one found is used).
/usr/local/share/vim/vim??/optwin.vim
Script used for the ":options" command, a nice way to view and set options.
/usr/local/share/vim/vim??/menu.vim
System wide menu initializations for gVim.
/usr/local/share/vim/vim??/bugreport.vim
Script to generate a bug report. See ":help bugs".
/usr/local/share/vim/vim??/filetype.vim
Script to detect the type of a file by its name. See ":help 'filetype'".
/usr/local/share/vim/vim??/scripts.vim
Script to detect the type of a file by its contents. See ":help 'filetype'".
/usr/local/share/vim/vim??/print/*.ps
Files used for PostScript printing.
