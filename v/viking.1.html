check-file-server-time (opcional)

Envía la marca de tiempo de la ficha al servidor, para que el servidor pueda decidir si debe enviar una nueva ficha o no.

El valor predeterminado es falso.

use-etag (opcional)

Utiliza y compara el valor ETag[3] al determinar si se debe descargar una ficha más nueva. El valor predeterminado es falso.

El valor ETag se almacena en un archivo separado en el mismo directorio que la ficha para permitir la verificación del valor en múltiples ejecuciones del programa.

referer (opcional)

Una URL que servirá como referer para la solicitud HTTP (por ejemplo, "http://hostname/")

follow-location (opcional)

El número máximo de redirecciones permitidas. El valor predeterminado es 0, es decir, sin redirección. Utilice -1 para un número ilimitado de redirecciones.

tilesize-x (opcional)

El tamaño x de la ficha. El valor predeterminado es 256 píxeles si no se especifica.

tilesize-y (opcional)

El tamaño y de la ficha. El valor predeterminado es 256 píxeles si no se especifica.

scale (opcional)

La escala de la ficha. La escala es 1 si no se especifica.

Nota
Utilice un valor de 2 para representar fichas de alta resolución. No cambie el tamaño de la ficha, ya que el tamaño de visualización interno todavía se basa en 256 píxeles.

Motores de búsqueda Ir a. Es posible agregar nuevos motores de búsqueda para la función "Ir a". El archivo es goto_tools.xml en la ubicación del archivo de configuración del usuario. Un ejemplo del archivo se encuentra en la distribución doc/examples/goto_tools.xml. Actualmente, hay una sola clase de objeto disponible: VikGotoXmlTool. Esta función permite declarar cualquier motor de búsqueda utilizando un formato XML como resultado. Las propiedades relacionadas son:

label

el texto que se muestra en el diálogo Ir a

url-format

la dirección parametrizada de la consulta, en el espíritu del formato C printf, con un único campo "%s" (reemplazado por la cadena de consulta)

lat-path

ruta XML de la latitud (por ejemplo, /root/parent/elem)

lat-attr (opcional)

nombre del atributo (del elemento anterior) que contiene la latitud

lon-path

ruta XML de la longitud (por ejemplo, /root/parent/elem)

lon-attr (opcional)

nombre del atributo (del elemento anterior) que contiene la longitud
Como una facilidad (o legibilidad), es posible establecer tanto la ruta como el nombre del atributo en una sola propiedad, como una expresión XPath. Para hacerlo, simplemente establezca ambas información en lat-path (o lon-path) en el siguiente formato: /root/parent/elem@attribute.

Herramientas externas. Es posible agregar nuevas herramientas externas. El archivo es external_tools.xml en la ubicación del archivo de configuración del usuario. Un ejemplo del archivo se encuentra en la distribución doc/examples/external_tools.xml. VikWebtoolCenter permite declarar cualquier herramienta web utilizando una lógica basada en las coordenadas del centro y el valor del nivel de zoom. Las propiedades relacionadas son:

label

el texto que se muestra en la entrada del menú

url

la URL parametrizada a abrir, en el espíritu del formato C printf con 2 "%s" y 1 "%d" campos para X, Y y Z (nivel de zoom) (por ejemplo, "http://hostname/?lat=%s&lon=%s&zoom=%d")
El VikWebtoolBounds permite declarar cualquier herramienta web utilizando una lógica basada en las coordenadas de los límites. Las propiedades relacionadas son:

label

el texto que se muestra en la entrada del menú

url

la dirección parametrizada de la ficha, en el espíritu del formato C printf con 4 campos "%s" para izquierda, derecha, inferior y superior (por ejemplo, "http://hostname:8111/load_and_zoom?left=%s&right=%s&bottom=%s&top=%s")

Motor de enrutamiento. Es posible declarar nuevos motores de enrutamiento. El archivo es routing.xml en la ubicación del archivo de configuración del usuario. Un ejemplo del archivo se encuentra en la distribución doc/examples/routing.xml. El VikRoutingWebEngine permite declarar un motor de enrutamiento disponible a través de HTTP. Las propiedades relacionadas son:

id

una cadena, debe ser única ya que se utiliza para identificar el motor de enrutamiento

label

el texto que se muestra en la entrada del menú

format

El código de formato GPSBabel para interpretar la respuesta del servicio. Por defecto, se espera una respuesta GPX y se procesa internamente. Sin embargo, si el servicio devuelve un formato diferente, GPSBabel se utiliza para transformar el texto en algo que Viking pueda entender. Solo se pueden usar los formatos que GPSBabel admite: por ejemplo, 'gpx', 'kml', 'gtrnctr' (para archivos .tcx de Garmin Training Center), etc.

Use gpsbabel --help en la línea de comandos para conocer los tipos de archivo admitidos y sus códigos para procesarlos.

url-base

la URL base del servicio web (por ejemplo, "http://hostname/service?")

url-start-ll

la parte de la URL que establece la ubicación del punto de inicio, parametrizada en el espíritu del formato C printf, con 2 "%s" para las coordenadas (por ejemplo, "&start=%s,%s")

url-stop-ll

la parte de la URL que establece la ubicación del punto de fin, parametrizada en el espíritu del formato C printf, con 2 "%s" para las coordenadas (por ejemplo, "&stop=%s,%s")

url-via-ll (opcional)

la parte de la URL que establece la ubicación del punto de paso, parametrizada en el espíritu del formato C printf, con 2 "%s" para las coordenadas (por ejemplo, "&via=%s,%s")

url-start-dir (opcional)

la parte de la URL que establece la ubicación del punto de inicio para el enrutamiento basado en dirección, parametrizada en el espíritu del formato C printf, con un "%s" para la dirección (por ejemplo, "&start=%s")

url-stop-dir (opcional)

la parte de la URL que establece la ubicación del punto de fin para el enrutamiento basado en dirección, parametrizada en el espíritu del formato C printf, con un "%s" para la dirección (por ejemplo, "&start=%s")

url-ll-lat-first (opcional)

El orden de los términos lat/lon en las configuraciones de URL Start, Stop y Via. Por defecto, esto es VERDADERO.

Por ejemplo, utilizando los servicios de Brouter, la URL utiliza un par de valores que son longitud y luego latitud. Por lo tanto, establecer este valor en FALSO asegura que la sustitución de valores se realiza en el orden necesario.

referer (opcional)

Una URL que servirá como referer para la solicitud HTTP (por ejemplo, "http://hostname/")

follow-location (opcional)

El número máximo de redirecciones permitidas. El valor predeterminado es 0, es decir, sin redirección. Utilice -1 para un número ilimitado de redirecciones.

Fuentes de datos de archivos remotos. Es posible agregar referencias web que se espera que devuelvan un archivo que luego se puede abrir directamente o convertir a través de GPSBabel. El archivo es datasources.xml en su ubicación de archivo de configuración del usuario. Un ejemplo del archivo se encuentra en la distribución de origen doc/examples/datasources.xml. El VikWebtoolDatasource permite declarar cualquier URL utilizando lógica basada en coordenadas. Las propiedades relacionadas son:

label

el texto que se muestra en la entrada del menú

url

la URL parametrizada a abrir en el espíritu del formato C printf, con hasta 7 valores "%s". por ejemplo, http://hostname/getfile?lat=%s&lon=%s

El orden y el significado de estos parámetros se indican en el código url_format_code a continuación

url_format_code

Una cadena que describe los parámetros de sustitución de la URL parametrizada, cada carácter representa cómo traducir cada término.

B = Fondo de la vista actual, es decir, latitud mínima

L = Izquierda de la vista actual, es decir, longitud mínima

T = Parte superior de la vista actual, es decir, latitud máxima

R = Derecha de la vista actual, es decir, longitud máxima

A = Latitud central de la vista actual

O = Longitud central de la vista actual

Z = Valor de zoom OSM de la vista actual. Consulte Niveles de zoom[2]

Pp">S = Un identificador especificado por el usuario que se solicita al usuario a través de un cuadro de diálogo

Por lo tanto, para el ejemplo de URL anterior, el código de formato debería ser AO

tipo_archivo

Este valor se pasa al parámetro -i al interactuar con GPSBabel.

Si no se define, el archivo devuelto se interpreta internamente como un archivo GPX.

Se pueden usar valores posibles como 'kml', 'mapsource', etc. Consulte Formatos de archivo de GPSBabel[6] para obtener la lista completa.

argumentos_filtro_babel

Este valor se pasa a los argumentos del filtro al interactuar con GPSBabel.

Por ejemplo, se puede usar "-x nuketypes,routes" para filtrar todas las rutas de los resultados.

etiqueta_entrada

Este valor se utiliza al solicitar la entrada al usuario.

Es la etiqueta del cuadro de texto.

ARCHIVOS

El directorio de ubicación del archivo de configuración del usuario es ~/.viking para versiones hasta la v1.8. Para instalaciones nuevas, es ~/.config/viking a partir de la v1.9 en adelante. Si existe la ubicación heredada, Viking la usará con preferencia a la nueva ubicación.

Configuración: maps.xml

Archivo que contiene la definición de las fuentes de mapas.

Consulte la sección anterior para obtener más detalles.

Configuración: goto_tools.xml

Archivo que contiene la definición de los servicios de "Ir a".

Consulte la sección anterior para obtener más detalles.

Configuración: external_tools.xml

Archivo que contiene la definición de herramientas externas.

Consulte la sección anterior para obtener más detalles.

Configuración: datasources.xml

Archivo que contiene la definición de las fuentes de datos de archivos remotos.

Consulte la sección anterior para obtener más detalles.

Configuración: routing.xml

Archivo que contiene la definición de las fuentes de enrutamiento.

Consulte la sección anterior para obtener más detalles.

Configuración: viking.prefs

Preferencias para viking.

Configuración: viking_layer_defaults.ini

Valores predeterminados de capa para viking.

Configuración: viking.ini

Valores para viking guardados automáticamente entre sesiones.

Generalmente no está pensado para ser editado manualmente.

Sin embargo, se puede establecer un control más fino de los valores internos predeterminados.

Configuración: keys.rc

Archivo que contiene los aceleradores de teclas de acceso rápido.

Este archivo está en el formato estándar de mapa de aceleradores GTK.

Hasta la v1.8 ~/.viking-maps/, a partir de la v1.9 ~/.cache/viking/

Ubicación predeterminada de la caché de mapas de los mosaicos descargados o creados por viking.

Si existe la ubicación heredada, Viking la usará con preferencia.

Los archivos de extensión (maps.xml, goto_tools.xml, datasources.xml, external_tools.xml, routing.xml) también se buscan en los directorios /etc/viking y /usr/share/viking (o relacionados en su sistema).

ENTORNO

XDG_DATA_HOME

Directorio opcional donde buscar archivos de extensión (maps.xml, goto_tools.xml, datasources.xml, external_tools.xml, routing.xml).

XDG_DATA_DIRS

Ruta utilizada para cambiar los directorios escaneados en busca de archivos de extensión (maps.xml, goto_tools.xml, datasources.xml, external_tools.xml, routing.xml).

VIKING_MAPS

La ruta utilizada para la ubicación raíz predeterminada de los mapas.
