DESCRIPCIÓN

Las funciones de la familia printf() producen salida de acuerdo con un formato como se describe a continuación. Las funciones printf() y vprintf() escriben la salida en stdout, el flujo de salida estándar; fprintf() y vfprintf() escriben la salida en el flujo de salida dado; sprintf(), snprintf(), vsprintf() y vsnprintf() escriben en la cadena de caracteres str.

La función dprintf() es igual que fprintf() excepto que produce salida a un descriptor de archivo, fd, en lugar de a un flujo stdio(3).

Las funciones snprintf() y vsnprintf() escriben como máximo size bytes (incluyendo el byte nulo de terminación ('\0')) en str.

Las funciones vprintf(), vfprintf(), vdprintf(), vsprintf(), vsnprintf() son equivalentes a las funciones printf(), fprintf(), dprintf(), sprintf(), snprintf(), respectivamente, excepto que se llaman con una va_list en lugar de un número variable de argumentos. Estas funciones no llaman a la macro va_end. Como invocan la macro va_arg, el valor de ap no está definido después de la llamada. Ver stdarg(3).

Todas estas funciones escriben la salida bajo el control de una cadena de formato que especifica cómo los argumentos subsiguientes (o los argumentos accedidos a través de las facilidades de argumentos de longitud variable de stdarg(3)) se convierten para la salida.

C99 y POSIX.1-2001 especifican que los resultados no están definidos si una llamada a sprintf(), snprintf(), vsprintf(), o vsnprintf() causara la copia entre objetos que se solapan (por ejemplo, si el array de cadena de destino y uno de los argumentos proporcionados se refieren al mismo buffer). Formato de la cadena de formato

La cadena de formato es una cadena de caracteres, que comienza y termina en su estado de desplazamiento inicial, si lo hay. La cadena de formato se compone de cero o más directivas: caracteres ordinarios (no %), que se copian sin cambios al flujo de salida; y especificaciones de conversión, cada una de las cuales resulta en la obtención de cero o más argumentos subsiguientes. Cada especificación de conversión se introduce con el carácter % y termina con un especificador de conversión. Entre ellos puede haber (en este orden) cero o más flags, una anchura mínima de campo opcional, una precisión opcional y un modificador de longitud opcional.

La sintaxis general de una especificación de conversión es:


%[argumento$][flags][ancho][.precision][modificador de longitud]conversión

Los argumentos deben corresponder adecuadamente (después de la promoción de tipo) con el especificador de conversión. Por defecto, los argumentos se utilizan en el orden dado, donde cada '*' (ver Anchura de campo y Precisión abajo) y cada especificador de conversión solicita el siguiente argumento (y es un error si se dan insuficientes argumentos). También se puede especificar explícitamente qué argumento se toma, en cada lugar donde se requiere un argumento, escribiendo "%m$" en lugar de '%' y "*m$" en lugar de '*', donde el entero decimal m denota la posición en la lista de argumentos del argumento deseado, indexado comenzando desde 1. Por lo tanto,


printf("%*d", ancho, num);

y


printf("%2$*1$d", ancho, num);

son equivalentes. El segundo estilo permite referencias repetidas al mismo argumento. El estándar C99 no incluye el estilo usando '$', que proviene de la Single UNIX Specification. Si se usa el estilo usando '$', debe usarse en todo momento para todas las conversiones que toman un argumento y todos los argumentos de anchura y precisión, pero puede mezclarse con formatos "%%", que no consumen un argumento. No puede haber huecos en los números de argumentos especificados usando '$'; por ejemplo, si se especifican los argumentos 1 y 3, el argumento 2 también debe ser especificado en algún lugar de la cadena de formato.

Para algunas conversiones numéricas se utiliza un carácter radix ("punto decimal") o un carácter de agrupación de miles. El carácter real utilizado depende de la parte LC_NUMERIC de la localidad. (Ver setlocale(3).) La localidad POSIX utiliza '.' como carácter radix, y no tiene un carácter de agrupación. Por lo tanto,


printf("%'.2f", 1234567.89);

resulta en "1234567.89" en la localidad POSIX, en "1234567,89" en la localidad nl_NL, y en "1.234.567,89" en la localidad da_DK.

Caracteres de flag

El carácter % va seguido de cero o más de los siguientes flags:

#
El valor debe convertirse a una "forma alternativa". Para conversiones o, el primer carácter de la cadena de salida se hace cero (prefijando un 0 si no era cero ya). Para conversiones x y X, un resultado distinto de cero tiene la cadena "0x" (o "0X" para conversiones X) antepuesta. Para conversiones a, A, e, E, f, F, g, y G, el resultado siempre contendrá un punto decimal, incluso si no siguen dígitos (normalmente, un punto decimal aparece en los resultados de esas conversiones solo si un dígito le sigue). Para conversiones g y G, los ceros finales no se eliminan del resultado como de lo contrario se haría. Para m, si errno contiene un código de error válido, se imprime la salida de strerrorname_np(errno); de lo contrario, se imprime el valor almacenado en errno como un número decimal. Para otras conversiones, el resultado no está definido.
0
El valor debe rellenarse con ceros. Para conversiones d, i, o, u, x, X, a, A, e, E, f, F, g, y G, el valor convertido se rellena por la izquierda con ceros en lugar de espacios. Si los flags 0 y - aparecen ambos, el flag 0 se ignora. Si se da una precisión con una conversión entera (d, i, o, u, x, y X), el flag 0 se ignora. Para otras conversiones, el comportamiento no está definido.

DESCRIPTION

The sprintf() function is equivalent to fprintf() with the output stream for fprintf() directed to a dynamically allocated string. Return the number of characters written, not counting the terminating null byte.

The functions described in this manual page produce output according to a format string, which specifies the overall structure of the output, and the type, size, and other properties of the arguments that correspond to each conversion specifier. The functions in this family are asprintf, dprintf, fprintf, printf, snprintf, sprintf, and vprintf.

The format string is a character string, beginning with a per-cent (`%') character, that contains zero or more directives. A directive is either an ordinary character (not `%') that is copied to the output stream, or a conversion specification, beginning with a `%'.

A conversion specification is introduced by the character `%', and includes:

  • An optional set of flags (in some order):
    • `-` (minus sign) Left justifies the output of the current conversion within the field.
    • `+` (plus sign) Forces the output of a sign (+ or -) for signed conversions. By default, only negative numbers are preceded by a sign. A `+` flag overrides a space flag if both are given.
    • ` ` (space) A leading space is inserted before a signed conversion if the value is not negative. A space flag is ignored if a `+` flag is also present.
    • `#` (pound sign) This is a "alternate form" modifier. For the conversions `o` `x`, `X`, `a`, `A`, `e`, `E`, `f`, `F`, `g`, `G`, it increases the precision, for `o` the first digit is always 0, for `x`/`X` a non-zero result always begins with `0x` or `0X`, for `a`/`A`/`e`/`E`/`f`/`F` it is a sign that the value is to be written using a decimal point character even if no digits would follow it, for `g`/`G` it is required that the result is always written using a decimal point character (even if it would otherwise be omitted). Alternate form is generally a no-op for all other conversions.
    • `0` (zero) Zeroes are inserted after the sign (if any) but before the digits for signed conversions. On output of integers, the flag specifies zero-padding. The flag specifies that width argument is right-justified, rather than left-justified. Beware that this may affect some conversions differently. For example, it causes padding in the middle of a string for the %s conversion. The flag is ignored if the `-` flag is also present. For the `b`, `B`, `o`, `u`, `d`, `i`, `x`, and `X` conversions, leading zeros are produced. For other conversions, the behavior of the `0` flag is undefined.
  • An optional minimum field width.
  • An optional precision.
  • An optional length modifier.
  • A conversion specifier character.

A missing field width or precision may cause issues as described under each conversion specifier. If the value of a field width or precision is modified by a length modifier, the applicable type is modified accordingly.

A character that is not a valid conversion specifier, or that follows a `%` character but not a valid conversion specification, results in undefined behavior.

The behavior of the sprintf family of functions is undefined if the format string contains null bytes (`\0'`) or if the output buffer is too small. For safe functions, see asprintf(3), snprintf(3) and vsnprintf(3).

FLAGS

The following flags are supported:

'-'
Left justification. The converted value is padded on the right with blanks, rather than on the left with blanks.
'0'
Left padding the result with zeros rather than spaces. A sign character always appears before the string. A - overrides a 0 if both are given.
' '
(a space) A blank should be left before a positive number (or empty string) produced by a signed conversion.
'+'
A sign (+ or -) should always be placed before a number produced by a signed conversion. By default, a sign is used only for negative numbers. A + overrides a space if both are used.

The five flag characters above are defined in the C99 standard. POSIX specifies one further flag character.

'''
(a single quote) For decimal conversion (i, d, u, f, F, g, G) the output is to be grouped with thousands' grouping characters as a non-monetary quantity. Misleadingly, this isn't necessarily every thousand: for example Karbi ("mjw_IN"), groups its digits into 3 once, then 2 repeatedly. Compare locale(7) grouping and thousands_sep, contrast with mon_grouping/mon_thousands_sep and strfmon(3). This is a no-op in the default "C" locale.

glibc 2.2 adds one further flag character.

I
For decimal integer conversion (i, d, u) the output uses the locale's alternative output digits, if any. For example, since glibc 2.2.3 this will give Arabic-Indic digits in the Persian ("fa_IR") locale.

FIELD WIDTH

An optional decimal digit string (with nonzero first digit) specifying a minimum field width. If the converted value has fewer characters than the field width, it will be padded with spaces on the left (or right, if the left-adjustment flag has been given). Instead of a decimal digit string one may write "*" or "*m$" (for some decimal integer m) to specify that the field width is given in the next argument, or in the m-th argument, respectively, which must be of type int. A negative field width is taken as a '-' flag followed by a positive field width. In no case does a nonexistent or small field width cause truncation of a field; if the result of a conversion is wider than the field width, the field is expanded to contain the conversion result.

PRECISION

An optional precision, in the form of a period ('.') followed by an optional decimal digit string. Instead of a decimal digit string one may write "*" or "*m$" (for some decimal integer m) to specify that the precision is given in the next argument, or in the m-th argument, respectively, which must be of type int. If the precision is given as just '.', the precision is taken to be zero. A negative precision is taken as if the precision were omitted. This gives the minimum number of digits to appear for d, i, o, u, x, and X conversions, the number of digits to appear after the radix character for a, A, e, E, f, and F conversions, the maximum number of significant digits for g and G conversions, or the maximum number of characters to be printed from a string for s and S conversions.

As a nonstandard extension, the GNU implementations treats ll and L as synonyms, so that one can, for example, write llg (as a synonym for the standards-compliant Lg) and Ld (as a synonym for the standards compliant lld). Such usage is nonportable.

CONVERSION SPECIFIERS

A character that specifies the type of conversion to be applied. The conversion specifiers and their meanings are:

d, i
The int argument is converted to signed decimal notation. The precision, if any, gives the minimum number of digits that must appear; if the converted value requires fewer digits, it is padded on the left with zeros. The default precision is 1. When 0 is printed with an explicit precision 0, the output is empty.
o, u, x, X
The unsigned int argument is converted to unsigned octal (o), unsigned decimal (u), or unsigned hexadecimal (x and X) notation. The letters abcdef are used for x conversions; the letters ABCDEF are used for X conversions. The precision, if any, gives the minimum number of digits that must appear; if the converted value requires fewer digits, it is padded on the left with zeros. The default precision is 1. When 0 is printed with an explicit precision 0, the output is empty.
e, E
The double argument is rounded and converted in the style [-]d.ddde±dd where there is one digit (which is nonzero if the argument is nonzero) before the decimal-point character and the number of digits after it is equal to the precision; if the precision is missing, it is taken as 6; if the precision is zero, no decimal-point character appears. An E conversion uses the letter E (rather than e) to introduce the exponent. The exponent always contains at least two digits; if the value is zero, the exponent is 00.
f, F
The double argument is rounded and converted to decimal notation in the style [-]ddd.ddd, where the number of digits after the decimal-point character is equal to the precision specification. If the precision is missing, it is taken as 6; if the precision is explicitly zero, no decimal-point character appears. If a decimal point appears, at least one digit appears before it.
(SUSv2 does not know about F and says that character string representations for infinity and NaN may be made available. SUSv3 adds a specification for F. The C99 standard specifies "[-]inf" or "[-]infinity" for infinity, and a string starting with "nan" for NaN, in the case of f conversion, and "[-]INF" or "[-]INFINITY" or "NAN" in the case of F conversion.)
g, G
The double argument is converted in style f or e (or F or E for G conversions). The precision specifies the number of significant digits. If the precision is missing, 6 digits are given; if the precision is zero, it is treated as 1. Style e is used if the exponent from its conversion is less than -4 or greater than or equal to the precision. Trailing zeros are removed from the fractional part of the result; a decimal point appears only if it is followed by at least one digit.

VALOR DE RETORNO

content: | Al regresar con éxito, estas funciones devuelven el número de bytes impresos (excluyendo el byte nulo utilizado para terminar la salida a cadenas).

Las funciones snprintf() y vsnprintf() no escriben más de size bytes (incluyendo el byte nulo terminador ('\0')). Si la salida fue truncada debido a este límite, entonces el valor de retorno es el número de caracteres (excluyendo el byte nulo terminador) que se habrían escrito en la cadena final si hubiera habido suficiente espacio disponible. Por lo tanto, un valor de retorno de size o más significa que la salida fue truncada. (Ver también más abajo en PRECAUCIONES).

En caso de error, se devuelve un valor negativo y se establece errno para indicar el error.

PRECAUCIONES

content: | Algunos programas dependen imprudentemente de código como el siguiente 


sprintf(buf, "%s algún texto adicional", buf);

para añadir texto a buf. Sin embargo, los estándares indican explícitamente que los resultados no están definidos si los buffers de origen y destino se solapan al llamar a sprintf(), snprintf(), vsprintf() y vsnprintf(). Dependiendo de la versión de gcc(1) utilizada y de las opciones del compilador empleadas, llamadas como la anterior **no** producirán los resultados esperados.

La implementación de glibc de las funciones snprintf() y vsnprintf() cumple con el estándar C99, es decir, se comporta como se describe anteriormente, desde glibc 2.1. Hasta glibc 2.0.6, devolvían -1 cuando la salida se truncaba.

ERRORES

content: | Debido a que sprintf() y vsprintf() asumen una cadena de longitud arbitraria, los llamadores deben tener cuidado de no desbordar el espacio real; esto a menudo es imposible de garantizar. Tenga en cuenta que la longitud de las cadenas producidas depende de la configuración regional y es difícil de predecir. Use snprintf() y vsnprintf() en su lugar (o asprintf(3) y vasprintf(3)).

Código como printf(foo); a menudo indica un error, ya que foo puede contener un carácter %. Si foo proviene de una entrada de usuario no confiable, puede contener %n, lo que hará que la llamada a printf() escriba en memoria y cree un agujero de seguridad.

EJEMPLOS

EJEMPLOS

Para imprimir el valor de Pi con cinco decimales:


#include <math.h>
#include <stdio.h>
fprintf(stdout, "pi = %.5f\n", 4 * atan(1.0));

Para imprimir una fecha y hora en el formato "Domingo, Julio 3, 10:02", donde weekday y month son punteros a cadenas:


#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        weekday, month, day, hour, min);

Muchos países utilizan el orden día-mes-año. Por lo tanto, una versión internacionalizada debe ser capaz de imprimir los argumentos en un orden especificado por el formato:


#include <stdio.h>
fprintf(stdout, format,
        weekday, month, day, hour, min);

donde format depende de la configuración regional y puede permutar los argumentos. Con el valor:


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

se podría obtener "Sonntag, 3. Juli, 10:02".

Para asignar una cadena de tamaño suficiente e imprimir en ella (código correcto para glibc 2.0 y glibc 2.1):

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Determinar el tamaño requerido.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un byte extra para '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si se produce truncamiento en versiones de glibc anteriores a glibc 2.0.6, esto se trata como un error en lugar de manejarse de forma adecuada.
