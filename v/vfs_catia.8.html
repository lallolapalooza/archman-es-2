VFS_CATIA(8) Herramientas de administración del sistema VFS_CATIA(8)

NOMBRE

vfs_catia - traduce caracteres ilegales en nombres de archivo de Catia

SINOPSIS

objetos vfs = catia

DESCRIPCIÓN

Este módulo VFS forma parte del conjunto de utilidades samba(7).

El paquete de CAD Catia comúnmente crea nombres de archivo que utilizan caracteres que son ilegales en nombres de archivo CIFS. El módulo VFS vfs_catia implementa una asignación de caracteres para que estos archivos puedan ser compartidos con clientes CIFS.

Este módulo es apilable.

El parámetro "catia:mappings" especifica la asignación carácter por carácter, véase más abajo.

OPCIONES

catia:mappings = CARACTER_HEX_SERVIDOR:CARACTER_HEX_CLIENTE

CARACTER_HEX_SERVIDOR especifica un código de carácter hexadecimal prefijado con 0x que, cuando se incluye en un nombre de archivo del lado del servidor Samba, se mapeará a CARACTER_HEX_CLIENTE para el cliente CIFS.

La misma asignación ocurre en la dirección opuesta. Múltiples asignaciones de caracteres están separadas por una coma.

EJEMPLOS

Mapear comillas (") del lado del servidor a diéresis (&#x00A8;) del lado del cliente en nombres de archivo en el recurso compartido [CAD]:

        [CAD]
	path = /data/cad
	vfs objects = catia
	catia:mappings = 0x22:0xa8

Realizar un mapeo exhaustivo de caracteres comunes en nombres de archivo de Catia:

        [CAD]
	path = /data/cad
	vfs objects = catia
	catia:mappings = 0x22:0xa8,0x2a:0xa4,0x2f:0xf8,0x3a:0xf7,0x3c:0xab,0x3e:0xbb,0x3f:0xbf,0x5c:0xff,0x7c:0xa6

Nombre de archivo del lado del servidor a traducir (Tenga en cuenta que aquí no se utiliza el separador de rutas "/"):

a\a:a*a?a"a<a>a|a

Nombre de archivo resultante, visto por el cliente:

aÿa÷a¤a¿a¨a«a»a¦a

ADVERTENCIAS

La asignación de caracteres debe funcionar en AMBAS direcciones (servidor -> cliente y cliente -> servidor) para obtener nombres de archivo únicos y existentes.

Un ejemplo NO funcional:

        [CAD]
	path = /data/cad
	vfs objects = catia
	catia:mappings = 0x3a:0x5f

Aquí, los dos puntos ":" se mapean al guion bajo "_".

Suponiendo un nombre de archivo del lado del servidor "a:should_work", que se traduce a "a_should_work" para el cliente.

PERO la asignación inversa del cliente "a_should_work" al servidor resultará en "a:should:work" - algo como "archivo no encontrado" será devuelto.
