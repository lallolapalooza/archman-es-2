NOMBRE

version::Internals - Extensión de Perl para objetos de versión

DESCRIPCIÓN

Objetos de versión sobrecargados para todas las versiones modernas de Perl. Esto documenta la representación interna de datos y el código subyacente de version.pm. Consulte version.pod para el uso diario. Este documento solo es útil para los usuarios interesados en los detalles internos.

¿QUÉ ES UNA VERSIÓN?

A efectos de este módulo, un número de versión es una secuencia de valores enteros positivos separados por uno o más puntos decimales y opcionalmente un único guion bajo. Esto se corresponde con lo que Perl mismo utiliza para una versión, además de extender la "versión como número" que se discute en las diversas ediciones del libro del Camello.

En realidad, hay dos tipos distintos de objetos de versión:

Versiones Decimales
Cualquier versión que "parezca un número", véase "Versiones Decimales". Esto incluye también versiones con un único punto decimal y un único guion bajo incrustado, véase "Versiones Alfa", aunque estas deben ir entre comillas para preservar el formato del guion bajo.
Versiones Decimales con Puntos
También conocidas como "Enteros con Puntos", estas contienen más de un punto decimal y pueden tener un guion bajo incrustado opcional, véase Versiones Decimales con Puntos. Esta es la que se utiliza comúnmente en la mayoría del software de código abierto como versión "externa" (la que se utiliza como parte de la etiqueta o el nombre del archivo tar). Ahora se requiere un carácter 'v' inicial y advertirá si falta.

Ambos métodos producirán objetos de versión similares, en el sentido de que la representación de cadena por defecto producirá la "Forma Normal" de la versión solo si es necesario:

$v  = version->new(1.002);     # 1.002, pero compara como 1.2.0
$v  = version->new(1.002003);  # 1.002003
$v2 = version->new("v1.2.3");  # v1.2.3

En concreto, los números de versión inicializados como "Versiones Decimales" se representarán como cadenas tal como se crearon originalmente (es decir, la misma cadena que se pasó a new(). Los números de versión inicializados como "Versiones Decimales con Puntos" se representarán como "Forma Normal".

Versiones Decimales

Estas corresponden a versiones históricas de Perl anteriores a 5.6.0, así como a todos los demás módulos que siguen las reglas del Camello para el escalar $VERSION. Una versión decimal se inicializa con lo que parece un número de punto flotante. Los ceros iniciales **son** significativos y los ceros finales se implican de manera que se mantenga un mínimo de tres lugares entre subversiones. Lo que esto significa es que cualquier subversión (dígitos a la derecha del lugar decimal) que contenga menos de tres dígitos tendrá ceros finales añadidos para cubrir la diferencia, pero solo para fines de comparación con otros objetos de versión. Por ejemplo:

                                 # Imprime     Equivalente a
$v = version->new(      1.2);    # 1.2        v1.200.0
$v = version->new(     1.02);    # 1.02       v1.20.0
$v = version->new(    1.002);    # 1.002      v1.2.0
$v = version->new(   1.0023);    # 1.0023     v1.2.300
$v = version->new(  1.00203);    # 1.00203    v1.2.30
$v = version->new( 1.002003);    # 1.002003   v1.2.3

Todos los ejemplos anteriores son válidos independientemente de si el valor de entrada está entre comillas o no. La característica importante es que el valor de entrada contiene solo un punto decimal. Consulte también "Versiones Alfa".

NOTA IMPORTANTE: Como se muestra arriba, si su versión Decimal contiene más de 3 dígitos significativos después del punto decimal, se dividirá en cada múltiplo de 3, por lo que 1.0003 es equivalente a v1.0.300, debido a la necesidad de mantener la compatibilidad con la interpretación 5.005_03 == 5.5.30 de Perl. Los ceros finales se ignoran para fines de comparación matemática.

Versiones Decimales con Puntos

Estas son la forma más reciente de versiones y corresponden al estilo de versión propio de Perl a partir de 5.6.0. A partir de Perl 5.10.0, y muy probablemente Perl 6, esta será probablemente la forma preferida. Este método normalmente requiere que el parámetro de entrada esté entre comillas, aunque el Perl posterior a 5.8.1 puede usar cadenas v como forma especial de comillas, pero esto está muy desaconsejado.

A diferencia de las "Versiones Decimales", las Versiones Decimales con Puntos tienen más de un punto decimal, por ejemplo:

                                 # Imprime
$v = version->new( "v1.200");    # v1.200.0
$v = version->new("v1.20.0");    # v1.20.0
$v = qv("v1.2.3");               # v1.2.3
$v = qv("1.2.3");                # v1.2.3
$v = qv("1.20");                 # v1.20.0

En general, las Versiones Decimales con Puntos permiten la mayor libertad para especificar una versión, mientras que las Versiones Decimales imponen cierta uniformidad.

Al igual que las "Versiones Decimales", las Versiones Decimales con Puntos se pueden utilizar como "Versiones Alfa".

Versiones Alfa

Para los autores de módulos que utilizan CPAN, la convención ha sido indicar lanzamientos inestables con un guion bajo en la cadena de versión. (Véase CPAN). version.pm sigue esta convención y los lanzamientos alfa se probarán como más nuevos que el lanzamiento estable más reciente, y menos que el próximo lanzamiento estable. Solo el último elemento puede estar separado por un guion bajo:

# Declaración
use version 0.77; our $VERSION = version->declare("v1.2_3");
# Análisis
$v1 = version->parse("v1.2_3");
$v1 = version->parse("1.002_003");

Tenga en cuenta que **debe** entrecomillar la versión al escribir una versión Decimal alfa. La forma representada como cadena de las versiones Decimales será siempre la misma cadena que se utilizó para inicializar el objeto de versión.

Expresiones Regulares para el Análisis de Versiones

Una definición formal de las formas legales para las cadenas de versión se incluye en la clase "version::regex". Se incluyen primitivas para elementos comunes, aunque están limitadas al archivo, por lo que son útiles solo como referencia. Hay dos escalares de acceso público que se pueden usar en otro código (no exportados):

$version::LAX
Esta expresión regular cubre todas las formas legales permitidas bajo el analizador de cadenas de versión actual. Esto no quiere decir que todas estas formas sean recomendadas, y algunas de ellas solo se pueden usar cuando están entre comillas.

Para decimales con puntos:

v1.2
1.2345.6
v1.23_4

La 'v' inicial es opcional si aparecen dos o más puntos decimales. Si solo se incluye un punto decimal, la 'v' inicial es obligatoria para activar el análisis decimal con puntos. Se permite un cero inicial, aunque no se recomienda excepto cuando está entre comillas, debido al riesgo de que Perl trate el número como octal. Un guion bajo final más uno o más dígitos denota una versión alfa o de desarrollo (y debe ir entre comillas para ser analizada correctamente).

Para versiones decimales:

1
1.2345
1.2345_01

Se requiere una parte entera, un punto decimal opcional y, opcionalmente, uno o más dígitos a la derecha del punto decimal. Se permite un guion bajo final y se permite un cero inicial. Al igual que la versión decimal con puntos laxa, entrecomillar los valores es necesario para que las formas alfa/desarrollo se analicen correctamente.

$version::STRICT
Esta expresión regular cubre un conjunto mucho más limitado de formatos y constituye las mejores prácticas para inicializar objetos de versión. Si elije emplear decimal o decimal con puntos es una preferencia personal sin embargo.
v1.234.5
Para versiones decimales con puntos, se requiere una 'v' inicial, con tres o más subversiones de no más de tres dígitos. También se prohíbe un 0 (cero) inicial antes de la primera subversión (en el ejemplo anterior, '1').
2.3456_1
Para versiones decimales, se requiere una parte entera (sin cero inicial), un punto decimal y uno o más dígitos a la derecha del punto decimal.

Ambos escalares proporcionados ya están compilados como expresiones regulares y no contienen anclas ni agrupaciones implícitas, por lo que se pueden incluir libremente en sus propias expresiones regulares. Por ejemplo,

consider the following code:

($pkg, $ver) =~ /
        ^[ \t]*
        use [ \t]+($PKGNAME)
        (?:[ \t]+($version::STRICT))?
        [ \t]*;
/x;

This would match a line of the form:

use Foo::Bar::Baz v1.2.3;       # legal only in Perl 5.8.1+

where $PKGNAME is another regular expression that defines the legal forms for package names.

DETALLES DE IMPLEMENTACIÓN

Equivalencia entre versiones decimales y decimales con puntos

Cuando se lanzó Perl 5.6.0, se tomó la decisión de proporcionar una transformación entre los números de versión de estilo antiguo (decimales) y los de estilo nuevo (decimales con puntos):

5.6.0    == 5.006000
5.005_04 == 5.5.40

Se toma el número de punto flotante y se divide primero en el lugar decimal único, luego cada grupo de tres dígitos a la derecha del decimal compone el siguiente dígito, y así sucesivamente hasta que se agotan los dígitos significativos, **más** los ceros finales necesarios para alcanzar el siguiente múltiplo de tres.

Este fue el método que version.pm adoptó también. Algunos ejemplos pueden ser útiles:

                          equivalente
decimal    con ceros      decimal-con-puntos
-------    -----------    ------------------
1.2        1.200          v1.200.0
1.02       1.020          v1.20.0
1.002      1.002          v1.2.0
1.0023     1.002300       v1.2.300
1.00203    1.002030       v1.2.30
1.002003   1.002003       v1.2.3

Reglas de comillas

Debido a la naturaleza de las rutinas de análisis y tokenización de Perl, ciertos valores de inicialización **deben** ser citados para ser analizados correctamente como la versión deseada, especialmente cuando se usan los métodos "declare" o "qv()". Aunque no tenga que citar números decimales al crear objetos de versión, siempre es seguro citar **todos** los valores iniciales al usar los métodos de version.pm, ya que esto asegurará que lo que escriba es lo que se utiliza.

Además, si cita su inicializador, el valor citado que entra será exactamente lo que sale cuando su $VERSION se imprima (se convierta a cadena). Si no cita su valor, la manipulación numérica normal de Perl entra en juego y es posible que no obtenga lo que esperaba.

Si utiliza una fórmula matemática que se resuelve en un número de punto flotante, dependerá de las rutinas de conversión de Perl para obtener la versión que espera. Está bastante seguro dividiendo por una potencia de 10, por ejemplo, pero es poco probable que otras operaciones sean lo que usted pretende. Por ejemplo:

$VERSION = version->new((qw$Revision: 1.4)[1]/10);
print $VERSION;          # produce 0.14
$V2 = version->new(100/9); # Desbordamiento de enteros en número decimal
print $V2;               # produce algo como 11.111.111.100

Perl 5.8.1 y posteriores son capaces de citar automáticamente v-strings, pero eso no es posible en versiones anteriores de Perl. En otras palabras:

$version = version->new("v2.5.4");  # legal en todas las versiones de Perl
$newvers = version->new(v2.5.4);    # legal solo en Perl >= 5.8.1

¿Qué pasa con las v-strings?

Hay dos formas de introducir v-strings: un número desnudo con dos o más puntos decimales, o un número desnudo con uno o más puntos decimales y un carácter 'v' delante (también desnudo). Por ejemplo:

$vs1 = 1.2.3; # codificado como \1\2\3
$vs2 = v1.2;  # codificado como \1\2

Sin embargo, el uso de v-strings desnudas para inicializar objetos de versión **no se recomienda encarecidamente** en ninguna circunstancia. Además, las v-strings desnudas no son completamente compatibles en ninguna versión de Perl anterior a 5.8.1.

Si insiste en usar v-strings desnudas con Perl > 5.6.0, tenga en cuenta las siguientes limitaciones:

1) Para las versiones de Perl 5.6.0 a 5.8.0, el código de v-string simplemente adivina, basándose en algunas características de las v-strings. **Debe** usar una versión de tres partes, por ejemplo, 1.2.3 o v1.2.3 para que esta heurística tenga éxito.

2) Para las versiones de Perl 5.8.1 y posteriores, las v-strings han cambiado en el núcleo de Perl para ser mágicas, lo que significa que el código de version.pm puede determinar automáticamente si se utilizó la codificación de v-string.

3) En todos los casos, una versión creada usando v-strings tendrá una forma de cadena con un carácter 'v' delante, por la simple razón de que a veces es imposible decir si había una presente inicialmente.

Reemplazo de UNIVERSAL::VERSION

Además de los objetos de versión, este módulo también reemplaza la función principal UNIVERSAL::VERSION con una que utiliza objetos de versión para sus comparaciones. El retorno de este operador es siempre la forma de cadena como un escalar simple (es decir, no un objeto), pero el mensaje de advertencia generado incluye la forma de cadena o la forma normal, dependiendo de cómo se llamó.

Por ejemplo:

package Foo;
$VERSION = 1.2;
package Bar;
$VERSION = "v1.3.5"; # funciona con todos los Perl (ya que está entre comillas)
package main;
use version;
print $Foo::VERSION; # imprime 1.2
print $Bar::VERSION; # imprime 1.003005
eval "use foo 10";
print $@; # imprime "se requiere la versión 10 de foo..."
eval "use foo 1.3.5; # funciona en Perl 5.6.1 o superior
print $@; # imprime "se requiere la versión 1.3.5 de foo..."
eval "use bar 1.3.6";
print $@; # imprime "se requiere la versión 1.3.6 de bar..."
eval "use bar 1.004"; # nota la versión decimal
print $@; # imprime "se requiere la versión 1.004 de bar..."

NOTA IMPORTANTE: Esto puede significar que el código que busca una cadena específica (para determinar si un módulo dado está disponible) puede necesitar ser cambiado. Siempre es mejor usar la comparación incorporada implícita en "use" o "require", en lugar de examinar manualmente "class->VERSION" y luego hacer una comparación usted mismo.

El reemplazo de UNIVERSAL::VERSION, cuando se usa como una función, así:

print $module->VERSION;

también devolverá exclusivamente la forma de cadena. Ver "Stringificación" para más detalles.

DETALLES DE USO

Usando módulos que usan version.pm

En la medida de lo posible, el módulo version.pm se mantiene compatible con todo el código actual. Sin embargo, si su módulo utiliza un módulo que ha definido $VERSION usando la clase version, hay un par de cosas a tener en cuenta. A efectos de discusión, asumiremos que tenemos el siguiente módulo instalado:

package Example;
use version;  $VERSION = qv('1.2.2');
...código del módulo aquí...
1;
Las versiones decimales siempre funcionan
Código de la forma: 
use Example 1.002003;

siempre funcionará correctamente. La llamada "use" realizará una comparación automática de $VERSION utilizando el número de punto flotante proporcionado como primer término después del nombre del módulo (por ejemplo, arriba 1.002.003). En este caso, el módulo instalado es demasiado antiguo para la línea solicitada, por lo que vería un error como:

se requiere la versión 1.002003 (v1.2.3) de Example--esta es solo la versión 1.002002 (v1.2.2)...
Las versiones decimales con puntos funcionan a veces
Con Perl >= 5.6.2, también puede usar una línea como esta: 
use Example 1.2.3;

y volverá a funcionar (es decir, dará el mensaje de error anterior), incluso con versiones de Perl que normalmente no admiten v-strings (ver "¿Qué pasa con las v-strings?" arriba). Esto se debe al hecho de que "use" solo comprueba si el segundo término **parece un número** y se lo pasa al reemplazo de UNIVERSAL::VERSION. Sin embargo, esto no es cierto en Perl 5.005_04, por lo que se le **recomienda encarecidamente** que siempre utilice una versión Decimal en su código, incluso para aquellas versiones de Perl que admiten la versión Decimal con Puntos.

Métodos de objeto

new()
Al igual que muchas interfaces OO, el método new() se utiliza para inicializar objetos de versión. Si se pasan dos argumentos a new(), el **segundo** se utilizará como si tuviera el prefijo "v". Esto es para admitir el uso histórico del operador "qw" con la variable CVS $Revision, que se incrementa automáticamente por CVS cada vez que el archivo se confirma en el repositorio.

Para facilitar esta característica, se puede emplear el siguiente código:

$VERSION = version->new(qw$Revision: 2.7 $);

y el objeto de versión se creará como si se utilizara el siguiente código:

$VERSION = version->new("v2.7");

En otras palabras, la versión se analizará automáticamente a partir de la cadena y se citará para preservar el significado que CVS normalmente conlleva para las versiones. El $Revision de CVS$ se incrementa de manera diferente a las versiones decimales (es decir, 1.10 sigue a 1.9), por lo que debe manejarse como si fuera una versión decimal con puntos.

Se puede crear un nuevo objeto de versión como una copia de un objeto de versión existente, ya sea como un método de clase:

$v1 = version->new(12.3);
$v2 = version->new($v1);

o como un método de objeto:

$v1 = version->new(12.3);
$v2 = $v1->new(12.3);

y en cada caso, $v1 y $v2 serán idénticos. NOTA: si crea un nuevo objeto usando un objeto existente de esta manera:

$v2 = $v1->new();

el nuevo objeto **no** será un clon del objeto existente. En el caso del ejemplo, $v2 será un objeto vacío del mismo tipo que $v1.

NAME

version::Internals - Implementation details and examples of the version package

DESCRIPTION

This manual page is intended to show the internals of the version package, and the examples contained within are thus more complex than those found in the main synopsis page.

WHAT IS A VERSION?

This module allows you to work with software versions (e.g. "1.2.3") in a robust and convenient way. It provides an object-oriented interface to check whether one version is greater than, less than, or equal to another, and to convert between the various formats that versions are often represented.

It is possible to use either decimal (e.g. 1.2) or dotted-decimal (e.g. 1.2.3) notation. Alpha, beta, and release candidate versions are also supported. You can also use the version object as a boolean value to see if it has been initialized.

IMPLEMENTATION DETAILS

The version package is implemented as a blessed reference. The reference is an array containing the version number components as separate elements. For example, the version object for "1.2.3" would be represented internally as:

  bless( [ 1, 2, 3 ], 'version' )

This allows for easy comparison and manipulation of version components.

USAGE DETAILS

The following are examples of how to use the version package:

new
The constructor for the version package is:
  version->new( $string )

It takes a string representation of the version and returns a version object. For example:

$v = version->new("1.2.3.4");
qv()
A new version object is created through the exported qv() sub. This is not strictly like other q? operators (like qq, qw), in that the only delimiters supported are parentheses (or spaces). It is the best way to initialize a short version without triggering the floating point interpretation. For example: 
$v1 = qv(1.2);         # v1.2.0
$v2 = qv("1.2");       # also v1.2.0

As you can see, either a bare number or a quoted string can usually be used interchangeably, except in the case of a trailing zero, which must be quoted to be converted properly. For this reason, it is strongly recommended that all initializers to qv() be quoted strings instead of bare numbers.

To prevent the qv() function from being exported to the caller's namespace, either use version with a null parameter:

use version ();

or just require version, like this:

require version;

Both methods will prevent the import() method from firing and exporting the qv() sub.

For the subsequent examples, the following three objects will be used:

$ver   = version->new("1.2.3.4"); # see "Quoting Rules"
$alpha = version->new("1.2.3_4"); # see "Alpha Versions"
$nver  = version->new(1.002);     # see "Decimal Versions"
Normal Form
For any version object which is initialized with multiple decimal places (either quoted or if possible v-string), or initialized using the qv() operator, the stringified representation is returned in a normalized or reduced form (no extraneous zeros), and with a leading 'v': 
print $ver->normal;         # prints as v1.2.3.4
print $ver->stringify;      # ditto
print $ver;                 # ditto
print $nver->normal;        # prints as v1.2.0
print $nver->stringify;     # prints as 1.002,
                            # see "Stringification"

In order to preserve the meaning of the processed version, the normalized representation will always contain at least three sub terms. In other words, the following is guaranteed to always be true:

my $newver = version->new($ver->stringify);
if ($newver eq $ver ) # always true
  {...}
Numification
Although all mathematical operations on version objects are forbidden by default, it is possible to retrieve a number which corresponds to the version object through the use of the $obj->numify method. For formatting purposes, when displaying a number which corresponds a version object, all sub versions are assumed to have three decimal places. So for example: 
print $ver->numify;         # prints 1.002003004
print $nver->numify;        # prints 1.002

Unlike the stringification operator, there is never any need to append trailing zeros to preserve the correct version value.

Stringification
The default stringification for version objects returns exactly the same string as was used to create it, whether you used new() or qv(), with one exception. The sole exception is if the object was created using qv() and the initializer did not have two decimal places or a leading 'v' (both optional), then the stringified form will have a leading 'v' prepended, in order to support round-trip processing.

For example:

Initialized as          Stringifies to
==============          ==============
version->new("1.2")       1.2
version->new("v1.2")     v1.2
qv("1.2.3")               1.2.3
qv("v1.3.5")             v1.3.5
qv("1.2")                v1.2   ### exceptional case

See also UNIVERSAL::VERSION, as this also returns the stringified form when used as a class method.

IMPORTANT NOTE: There is one exceptional cases shown in the above table where the "initializer" is not stringwise equivalent to the stringified representation. If you use the "qv"() operator on a version without a leading 'v' and with only a single decimal place, the stringified output will have a leading 'v', to preserve the sense. See the "qv()" operator for more details.

IMPORTANT NOTE 2: Attempting to bypass the normal stringification rules by manually applying numify() and normal() will sometimes yield surprising results:

print version->new(version->new("v1.0")->numify)->normal; # v1.0.0

The reason for this is that the numify() operator will turn "v1.0" into the equivalent string "1.000000". Forcing the outer version object to normal() form will display the mathematically equivalent "v1.0.0".

As the example in "new()" shows, you can always create a copy of an existing version object with the same value by the very compact:

$v2 = $v1->new($v1);

and be assured that both $v1 and $v2 will be completely equivalent, down to the same internal representation as well as stringification.

Comparison operators
Both "cmp" and "<=>" operators perform the same comparison between terms (upgrading to a version object automatically). Perl automatically generates all of the other comparison operators based on those two. In addition to the obvious equalities listed below, appending a single trailing 0 term does not change the value of a version for comparison purposes. In other words "v1.2" and "1.2.0" will compare as identical.

For example, the following relations hold:

As Number        As String           Truth Value
-------------    ----------------    -----------
$ver >  1.0      $ver gt "1.0"       true
$ver <  2.5      $ver lt             true
$ver != 1.3      $ver ne "1.3"       true
$ver == 1.2      $ver eq "1.2"       false
$ver == 1.2.3.4  $ver eq "1.2.3.4"   see discussion below

It is probably best to chose either the Decimal notation or the string notation and stick with it, to reduce confusion. Perl6 version objects may only support Decimal comparisons. See also "Quoting Rules".

WARNING: Comparing version with unequal numbers of decimal points (whether explicitly or implicitly initialized), may yield unexpected results at first glance. For example, the following inequalities hold:

version->new(0.96)     > version->new(0.95); # 0.960.0 > 0.950.0
version->new("0.96.1") < version->new(0.95); # 0.096.1 < 0.950.0

For this reason, it is best to use either exclusively "Decimal Versions" or "Dotted-Decimal Versions" with multiple decimal points.

Logical Operators
If you need to test whether a version object has been initialized, you can simply test it directly: 
$vobj = version->new($something);
if ( $vobj )   # true only if $something was non-blank

You can also test whether a version object is an alpha version, for example to prevent the use of some feature not present in the main release:

$vobj = version->new("1.2_3"); # MUST QUOTE
...later...
if ( $vobj->is_alpha )       # True
