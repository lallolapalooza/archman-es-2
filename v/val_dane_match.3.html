val_dane_match(3)

Paquete: dnssec-tools

Licencias: BSD

val_getdaneinfo(3) Manual del Programador val_getdaneinfo(3)

NOMBRE

val_getdaneinfo(3) - Realiza la validación síncrona de registros TLSA

val_dane_submit() - Realiza la validación asíncrona de registros TLSA

val_dane_match() - Valida la información TLSA contra los datos proporcionados.

val_dane_check() - Valida la información TLSA para conexiones SSL (solo OpenSSL)

val_free_dane() - Libera la memoria asociada a la estructura de resultados DANE.

p_dane_error() - Devuelve la cadena de error para el código de error DANE dado.

SINOPSIS

#include <validator/validator.h>
#include <validator/val_dane.h>
int val_getdaneinfo(val_context_t *ctx,
                  const char *name,
                  struct val_daneparams *params,
                  struct val_danestatus **dres);
int val_dane_submit(val_context_t *ctx,
                  const char *name,
                  struct val_daneparams *params,
                  val_dane_callback callback,
                  void *callback_data,
                  val_async_status **status);
int val_dane_match(val_context_t *ctx,
                 struct val_danestatus *dane_cur,
                 const unsigned char *databytes,
                 int databyteslen);
#include <openssl/ssl.h>
int val_dane_check(val_context_t *ctx,
                 SSL *con,
                 struct val_danestatus *danestatus,
                 int *do_pathval);
void val_free_dane(struct val_danestatus *dres);
const char *p_dane_error(int rc);

DESCRIPCIÓN

val_getdaneinfo() realiza una búsqueda síncrona del registro TLSA asociado con un name dado y devuelve una lista enlazada de todos los registros **validados** de este tipo. val_dane_submit() realiza la misma búsqueda de manera asíncrona e invoca la función callback con los argumentos callback_data al completar la búsqueda. La función de devolución de llamada tiene la siguiente definición de tipo:

typedef int (*val_dane_callback)(void *callback_data,
                               int retval,
                               struct val_danestatus **dres);

El argumento status proporciona un manejador para la solicitud asíncrona para habilitar operadores futuros (como cancelar la solicitud). Para más información sobre el objeto val_async_status, consulte el borrador draft-hayatnagarkar-dnsext-validator-api.

El nombre DNS real que posee el registro TLSA en el DNS tiene un prefijo de la forma _<puerto>._<proto>. val_getdaneinfo() construirá el prefijo anterior automáticamente; por lo tanto, el valor de name proporcionado por el usuario no debe contener este prefijo. El

Los parámetros para la búsqueda TLSA deben proporcionarse en el argumento params, que es un puntero a la siguiente estructura:

struct val_daneparams {
  int port;
  int proto;
};

Los campos port y proto se utilizan para construir el prefijo del nombre TLSA descrito anteriormente.

Los resultados de la búsqueda TLSA se devuelven en el argumento dres, que es un puntero a una lista enlazada de estructuras de la siguiente forma:

struct val_danestatus {
  long ttl;
  int usage;
  int selector;
  int type;
  size_t datalen;
  unsigned char *data;
  struct val_danestatus *next;
};

El campo ttl es el tiempo de vida (time-to-live) asociado con el registro TLSA. Una aplicación no debe almacenar en caché (y usar) este registro TLSA más allá de su TTL. Los campos usage, selector y type corresponden a los tres primeros campos de la RDATA TLSA tal como se describen en rfc6698. Los datos de asociación del certificado TLSA se devuelven en el campo data y tienen una longitud de datalen bytes. Puede haber más de un registro TLSA asociado con un nombre dado, y el campo next apunta al siguiente registro en esta lista.

Dada una lista enlazada de estructuras TLSA en dres, val_dane_match() se puede usar para verificar si los datos de asociación del certificado para un elemento dado en esta lista coinciden con los datos codificados en DER proporcionados en databytes con la longitud databyteslen.

La función val_dane_check() simplifica la operación de coincidencia cuando OpenSSL se utiliza para proporcionar soporte SSL/TLS dentro de la aplicación. Esta función itera automáticamente sobre todos los elementos en dres y compara los datos de asociación del certificado con los certificados SSL/TLS asociados con la conexión SSL con. El protocolo DANE permite ciertos casos de uso que introducen nuevas anclas de confianza a través de DNSSEC. El valor de do_pathval indica si la aplicación debe proceder con la validación de ruta X509 para esta conexión de acuerdo con el uso que se codificó en el registro TLSA.

La función val_free_dane() libera la memoria asociada con la lista enlazada apuntada por dres.

El parámetro ctx en todas las funciones anteriores especifica el contexto de validación, que puede establecerse en NULL para valores predeterminados (ver libval(3) y dnsval.conf para más detalles sobre contextos de validación y política de validación).

VALORES DE RETORNO

val_getdaneinfo() y val_dane_submit() devuelven VAL_DANE_NOERROR en caso de éxito, y VAL_DANE_MALFORMED_TLSA o VAL_DANE_INTERNAL_ERROR para condiciones de error. Se devuelve un valor de VAL_DANE_NOTVALIDATED si el registro TLSA no puede validarse a través de DNSSEC. Se devuelve un valor de VAL_DANE_IGNORE_TLSA si el registro TLSA para el nombre dado está providencialmente ausente.

El valor retval devuelto como argumento para val_dane_callback() puede contener uno de VAL_DANE_NOERROR (para éxito), VAL_DANE_INTERNAL_ERROR (para condiciones de error) o VAL_DANE_CANCELLED (cuando la solicitud asíncrona se cancela).

val_dane_match() y val_dane_check() devuelven VAL_DANE_NOERROR en caso de éxito, VAL_DANE_INTERNAL_ERROR para condiciones de error generales y VAL_DANE_CHECK_FAILED si el registro TLSA no se puede hacer coincidir con éxito con los datos de asociación del certificado proporcionados.

La función p_dane_error() se puede utilizar para convertir los códigos de error relacionados con DANE a un valor de cadena de error.
