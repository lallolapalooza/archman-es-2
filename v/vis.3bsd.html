DESCRIPCIÓN

La función vis() copia en dst una cadena que representa el carácter c. Si c no necesita codificación, se copia sin alteración. La cadena se termina con nulo y se devuelve un puntero al final de la cadena. La longitud máxima de cualquier codificación es de cuatro bytes (sin incluir el NUL final); por lo tanto, al codificar un conjunto de caracteres en un búfer, el tamaño del búfer debe ser cuatro veces el número de bytes codificados, más uno para el NUL final. El parámetro flag se utiliza para alterar el rango predeterminado de caracteres considerados para la codificación y para alterar la representación visual. El carácter adicional, nextc, solo se utiliza al seleccionar el formato de codificación VIS_CSTYLE (explicado a continuación).

Las funciones strvis(), stravis(), strnvis(), strvisx(), y strnvisx() copian en dst una representación visual de la cadena src. Las funciones strvis() y strnvis() codifican caracteres de src hasta el primer NUL. Las funciones strvisx() y strnvisx() codifican exactamente len caracteres de src (esto es útil para codificar un bloque de datos que puede contener NULs). Ambas formas terminan con NUL dst. El tamaño de dst debe ser cuatro veces el número de bytes codificados de src (más uno para el NUL). Ambas formas devuelven el número de caracteres en dst (sin incluir el NUL final). Si dlen no es lo suficientemente grande para alojar la cadena convertida, entonces las funciones strnvis() y strnvisx() devuelven -1 y establecen errno a ENOSPC. La función strenvisx() toma un argumento adicional, cerr_ptr, que se utiliza para pasar hacia y desde un indicador de error de conversión multibyte. Esto es útil al procesar caracteres individuales a la vez cuando es posible que la localización se establezca en algo diferente a la localización de los caracteres en los datos de entrada.

Las funciones svis(), snvis(), strsvis(), strsnvis(), strsvisx(), strsnvisx(), y strsenvisx() corresponden a vis(), nvis(), strvis(), strnvis(), strvisx(), strnvisx(), y strenvisx(), pero tienen un argumento adicional extra, que apunta a una lista de caracteres terminada en NUL. Estos caracteres se copiarán codificados o con escape de barra invertida en dst. Estas funciones son útiles, por ejemplo, para eliminar el significado especial de ciertos caracteres para los shells.

La codificación es una representación única e invertible compuesta enteramente de caracteres gráficos; se puede decodificar a su forma original utilizando las funciones unvis(3bsd), strunvis(3bsd) o strnunvis(3bsd).

Hay dos parámetros que se pueden controlar: el rango de caracteres que se codifican (solo se aplica a vis(), nvis(), strvis(), strnvis(), strvisx() y strnvisx()), y el tipo de representación utilizada. Por defecto, todos los caracteres no gráficos, excepto el espacio, la tabulación y la nueva línea, se codifican (ver isgraph(3)). Las siguientes banderas alteran esto:

VIS_DQ
Codifica también las comillas dobles
VIS_GLOB
Codifica también los caracteres mágicos (‘*’, ‘?’, ‘[’, y ‘#’) reconocidos por glob(3).
VIS_SHELL
Codifica también los caracteres meta utilizados por los shells (además de los caracteres de glob): (‘'’, ‘`’, ‘"’, ‘;’, ‘&’, ‘<’, ‘>’, ‘(’, ‘)’, ‘|’, ‘]’, ‘\’, ‘$’, ‘!’, ‘^’, y ‘~’).
VIS_SP
Codifica también el espacio.
VIS_TAB
Codifica también la tabulación.
VIS_NL
Codifica también la nueva línea.
VIS_WHITE
Sinónimo de VIS_SP | VIS_TAB | VIS_NL.
VIS_META
Sinónimo de VIS_WHITE | VIS_GLOB | VIS_SHELL.
VIS_SAFE
Codifica solo los caracteres “inseguros”. Inseguro significa caracteres de control que pueden causar que terminales comunes realicen funciones inesperadas. Actualmente, esta forma permite que el espacio, la tabulación, la nueva línea, el retroceso, la alarma y el retorno de carro —además de todos los caracteres gráficos— no se codifiquen.

(Las banderas anteriores no tienen efecto para svis(), snvis(), strsvis(), strsnvis(), strsvisx(), y strsnvisx(). Al usar estas funciones, coloque todos los caracteres gráficos a codificar en un array apuntado por extra. En general, el carácter de barra invertida debe incluirse en este array, ver la advertencia sobre el uso de la bandera VIS_NOSLASH a continuación).

Hay seis formas de codificación. Todas las formas usan el carácter de barra invertida ‘\’ para introducir una secuencia especial; se usan dos barras invertidas para representar una barra invertida real, excepto VIS_HTTPSTYLE que usa ‘%’, o VIS_MIMESTYLE que usa ‘=’. Estos son los formatos visuales:

(default)
Usa una ‘M’ para representar caracteres meta (caracteres con el 8º bit establecido), y usa un acento circunflejo ‘^’ para representar caracteres de control (ver iscntrl(3)). Se utilizan los siguientes formatos:
\^C
Representa el carácter de control ‘C’. Cubre los caracteres ‘\000’ hasta ‘\037’, y ‘\177’ (como ‘\^?’).
\M-C
Representa el carácter ‘C’ con el 8º bit establecido. Cubre los caracteres ‘\241’ hasta ‘\376’.
\M^C
Representa el carácter de control ‘C’ con el 8º bit establecido. Cubre los caracteres ‘\200’ hasta ‘\237’, y ‘\377’ (como ‘\M^?’).
\040
Representa el espacio ASCII.
\240
Representa el meta-espacio.
VIS_CSTYLE
Usa secuencias de barra invertida estilo C para representar caracteres no imprimibles estándar. Se utilizan las siguientes secuencias para representar los caracteres indicados: 
\a — BEL (007)
\b — BS (010)
\f — NP (014)
\n — NL (012)
\r — CR (015)
\s — SP (040)
\t — HT (011)
\v — VT (013)
\0 — NUL (000)

Al usar este formato, se examina el parámetro nextc para determinar si un carácter NUL se puede codificar como ‘\0’ en lugar de ‘\000’. Si nextc es un dígito octal, se utiliza la última representación para evitar ambigüedades.

Los caracteres no imprimibles sin secuencias de barra invertida estilo C utilizan la representación por defecto.

VIS_OCTAL
Usa una secuencia octal de tres dígitos. El formato es ‘\ddd’ donde d representa un dígito octal.
VIS_CSTYLE | VIS_OCTAL
Igual que VIS_CSTYLE, excepto que los caracteres no imprimibles sin secuencias de barra invertida estilo C utilizan una secuencia octal de tres dígitos.
VIS_HTTPSTYLE
Usa codificación URI como se describe en RFC 1738. El formato es ‘%’.

NAME

vis, strvis, strvisx, svis, strsvis, strsvisx, nvis, snvis, strnvis, strnvisx, strsnvis, strsnvisx ― escape a string for unambiguous representation

char * svis(char * restrict dst, const char * restrict src, int c, int flag);

char * strsvis(char * restrict dst, const char * restrict src, int flag);

char * strvis(char * restrict dst, const char * restrict src, int flag);

char * strvisx(char * restrict dst, const char * restrict src, int flag);

DESCRIPTION

These functions convert the string src into a string that is unambiguous and safe to be interpreted by different shells and programs, storing the result in the buffer pointed to by dst.

The conversion is controlled by the flag argument. The following flags are supported:

VIS_WHITE
Represent whitespace characters, namely space, tab, newline, carriage return, vertical tab, and form feed, by their symbolic names, SPC, TAB, NL, CR, VT, and FF, respectively.
VIS_GLOB
Represent shell globbing characters like *, ?, and [ by their symbolic names, *, ?, and [, respectively. If VIS_GLOB is set, characters that would otherwise be escaped using the VIS_SAFE or VIS_SP flags are also escaped.
VIS_SAFE
Escape characters that might be interpreted or modified by the shell, except for alphanumeric characters and the characters ., /, -, _, and ~. Escaped characters are represented by a backslash followed by the character. For example, # becomes \. Control characters are escaped as ^C, and characters with the high bit set are escaped as M-C.
VIS_SP
Escape spaces in addition to the characters that would be escaped by VIS_SAFE. Spaces are represented by \. This flag is intended for use when generating strings that will be passed to programs that do not treat spaces specially, such as ftp.
VIS_CSTYLE
Escape control characters using C-style backslash notation, e.g., \n for newline, \t for tab, etc. Other characters are escaped as per VIS_SAFE.
VIS_DQ
Escape characters by enclosing them in double quotes. This is useful for generating strings that can be safely interpreted by the shell as single arguments.
VIS_SPNL
Represents spaces as \ and newlines as \n. Other characters are escaped as per VIS_SAFE.
VIS_NOSLASH
Inhibits the doubling of backslashes. This means that backslashes themselves are not escaped, and the backslash used in other escape sequences (like ^C or M-C) is not doubled. This can make the resulting string ambiguous and non-invertible.
VIS_NLVAC
Encodes newlines as v. This is used in some specific contexts where newlines need to be represented differently.
VIS_OCTAL
Encodes non-ASCII characters using octal escape sequences, e.g., \nnn where nnn is the octal representation of the character. This is similar to how some C compilers represent characters.
VIS_MIMESTYLE
Uses MIME Quoted-Printable encoding as described in RFC 2045, but without line breaks and without handling CRLF. The form is =XX where X represents an upper case hexadecimal digit.

There is one additional flag, VIS_NOSLASH, which inhibits the doubling of backslashes and the backslash before the default format (that is, control characters are represented by ^C and meta characters as M-C). With this flag set, the encoding is ambiguous and non-invertible.

MULTIBYTE CHARACTER SUPPORT

These functions support multibyte character input. The encoding conversion is influenced by the setting of the LC_CTYPE environment variable which defines the set of characters that can be copied without encoding.

If VIS_NOLOCALE is set, processing is done assuming the C locale and overriding any other environment settings.

When 8-bit data is present in the input, LC_CTYPE must be set to the correct locale or to the C locale. If the locales of the data and the conversion are mismatched, multibyte character recognition may fail and encoding will be performed byte-by-byte instead.

As noted above, dst must be four times the number of bytes processed from src. But note that each multibyte character can be up to MB_LEN_MAX bytes so in terms of multibyte characters, dst must be four times MB_LEN_MAX times the number of characters processed from src.

ENVIRONMENT

LC_CTYPE
Specify the locale of the input data. Set to C if the input data locale is unknown.

ERRORS

The functions nvis() and snvis() will return NULL and the functions strnvis(), strnvisx(), strsnvis(), and strsnvisx(), will return -1 when the dlen destination buffer size is not enough to perform the conversion while setting errno to:

[ENOSPC]
The destination buffer size is not large enough to perform the conversion.

HISTORY

The vis(), strvis(), and strvisx() functions first appeared in 4.4BSD. The svis(), strsvis(), and strsvisx() functions appeared in NetBSD 1.5. The buffer size limited versions of the functions (nvis(), strnvis(), strnvisx(), snvis(), strsnvis(), and strsnvisx()) appeared in NetBSD 6.0 and FreeBSD 9.2. Multibyte character support was added in NetBSD 7.0 and FreeBSD 9.2.
