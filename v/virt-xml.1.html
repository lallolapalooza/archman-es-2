VIRT-XML(1) Soporte de Virtualización VIRT-XML(1)

NOMBRE

virt-xml - Edita XML de libvirt usando opciones de línea de comandos.

SINOPSIS

virt-xml DOMINIO ACCION-XML OPCION-XML [OPCION-SALIDA] [OPCIONES-VARIAS] ...

DESCRIPCIÓN

virt-xml es una herramienta de línea de comandos para editar XML de libvirt utilizando opciones explícitas de línea de comandos. Consulte la sección EJEMPLOS al final de este documento para empezar.

Cada invocación de virt-xml requiere 3 cosas: el nombre de un dominio existente a modificar (o XML pasado por stdin), una acción sobre el XML y un cambio XML a realizar. Las acciones son una de las siguientes:

  • --add-device: Añade una nueva definición de dispositivo al XML
  • --remove-device: Elimina una definición de dispositivo existente
  • --edit: Edita un bloque XML existente
  • --build-xml: Simplemente construye el bloque XML solicitado y lo imprime. No se requieren dominio o entrada aquí, pero se recomienda proporcionarlos, para que virt-xml pueda rellenar valores predeterminados óptimos.

Un cambio XML es una instancia de cualquiera de las opciones XML proporcionadas por virt-xml, por ejemplo --disk o --boot.

virt-xml solo permite una acción y un par de opciones XML por invocación. Si necesita realizar múltiples ediciones, invoque el comando múltiples veces.

OPCIONES

-c --connect URI
Conéctate a un hipervisor no predeterminado. Consulte virt-install(1) para más detalles
dominio
dominio es el nombre, UUID o ID de la VM existente. Esto puede omitirse si se usa --build-xml, o si se pasa XML por stdin.

Cuando se especifica un dominio, la acción de salida predeterminada es --define, incluso si la VM está en ejecución. Para actualizar la configuración de la VM en ejecución, agregue la opción --update (pero no todas las opciones/dispositivos admiten la actualización de la configuración de la VM en ejecución).

Si se pasa XML por stdin, la salida predeterminada es --print-xml.

ACCIONES XML

--edit [OPCIONES-EDITAR]
Edita el bloque XML especificado. OPCIONES-EDITAR le indica a virt-xml qué bloque editar. El tipo de XML que estamos editando se decide por la opción XML que se pasa a virt-xml. Por lo tanto, si se pasa --disk, OPCIONES-EDITAR selecciona qué bloque <disk> editar.

Ciertas opciones XML solo se mapean a un único bloque XML, como --cpu, --security, --boot, --clock, y algunas otras. En esos casos, virt-xml no se quejará si un bloque XML correspondiente no existe ya, lo creará por usted.

La mayoría de las opciones XML admiten un valor especial 'clearxml=yes'. Cuando se combina con --edit, borrará completamente el bloque XML que se está editando antes de aplicar los cambios solicitados. Esto permite reconstruir completamente un bloque XML. Consulte EJEMPLOS para ver algunos usos.

Ejemplos de OPCIONES-EDITAR:

•
--edit
--edit sin opciones implica 'editar el primer bloque'. Así, '--edit --disk OPCIONES-DISCO' significa 'editar el primer <disk>'.

Para las opciones de bloque XML único mencionadas anteriormente, '--edit' simple sin opciones es lo que siempre querrá usar.

•
--edit #
Selecciona el número de bloque XML especificado. Así, '--edit 2 --disk OPCIONES-DISCO' significa 'editar el segundo <disk>'. Esta opción solo se aplica realmente para XML de dispositivos.
•
--edit all
Modifica cada bloque XML del tipo de opción XML. Así, '--edit all --disk OPCIONES-DISCO' significa 'editar cada bloque <disk>'. Esta opción solo se aplica realmente para XML de dispositivos.
•
--edit OPCIONES-DISPOSITIVO
Modifica cada bloque XML que coincida con las opciones de dispositivo pasadas. Las opciones de dispositivo están en el mismo formato que se pasaría a la opción XML.

Por lo tanto, --edit path=/tmp/foo --disk OPCIONES-DISCO significa 'editar cada <disk> con path=/tmp/foo'. Esta opción solo se aplica realmente para XML de dispositivos.

--add-device
Añade las opciones XML especificadas a la lista <devices> del XML. Ejemplo: '--add-device --disk OPCIONES-DISCO' creará un nuevo bloque <disk> y lo añadirá al XML.

Esta opción dará error si se especifica con una opción XML que no sea de dispositivo (ver sección --edit para una lista parcial).

--remove-device
Elimina el dispositivo especificado del XML. El dispositivo a eliminar se selecciona mediante la opción XML, que toma argumentos en el mismo formato que --edit. Ejemplos:
•
--remove-device --disk 2
Elimina el segundo dispositivo de disco
•
--remove-device --network all
Elimina todos los dispositivos de red
•
--remove-device --sound pcspk
Elimina todos los dispositivos de sonido con model='pcspk'

Esta opción dará error si se especifica con una opción XML que no sea de dispositivo (ver sección --edit para una lista parcial).

--build-xml
Simplemente construye el XML especificado y lo imprime en stdout. No se requiere un dominio de entrada ni XML de entrada. Ejemplo: '--build-xml --disk OPCIONES-DISCO' solo imprimirá el nuevo dispositivo <disk>.

Sin embargo, si el XML generado está dirigido a un dominio específico, se recomienda pasarlo a virt-xml, para que la herramienta pueda establecer valores predeterminados óptimos.

Esta opción dará error si se especifica con una opción XML que no se mapea limpiamente a un bloque XML específico, como --vcpus o --memory.

OPCIONES DE SALIDA

Estas opciones deciden qué acción tomar después de modificar el XML. En el caso común, no es necesario especificarlas, ya que las 'acciones XML' implicarán una acción de salida predeterminada, descrita en detalle anteriormente. Solo son necesarias si desea modificar la salida predeterminada.

--update
Si el dominio especificado está en ejecución, intente modificar la configuración de la VM en ejecución. Si se combina con --edit, es una operación de actualización. Si se combina con --add-device, es un hotplug de dispositivo. Si se combina con --remove-device, es un hotunplug de dispositivo.

Tenga en cuenta que la mayoría de las propiedades XML y dispositivos no admiten operaciones de actualización en vivo, así que no espere que tenga éxito en todos los casos.

Por defecto, esto también implica --define.

--define
Define el cambio XML solicitado. Este es típicamente el valor predeterminado si no se especifica ninguna opción de salida, pero si se especifica una opción --print, se requiere --define para forzar el cambio.
--no-define
No define explícitamente el XML. Por ejemplo, si solo desea modificar el estado en tiempo de ejecución de una VM, combine esto con --update.
--start
Inicia la VM después de realizar los cambios solicitados. Si se combina con --no-define, esto hará que

--print-diff
Imprime el cambio XML generado en formato de diff unificado. Si solo se especifica esta opción de salida, se deshabilitan todas las demás opciones de salida y no se realiza ningún cambio persistente.
--print-xml
Imprime el XML generado en su totalidad. Si solo se especifica esta opción de salida, se deshabilitan todas las demás opciones de salida y no se realiza ningún cambio persistente.
--confirm
Antes de definir o actualizar el dominio, muestra la diferencia XML generada y solicita interactivamente confirmación.

OPCIONES DEL SO INVITADO

--osinfo, --os-variant OS_VARIANT
Optimiza la configuración del invitado para un sistema operativo específico (ej. 'fedora29', 'rhel7', 'win10'). Aunque no es obligatorio, se RECOMIENDA ALTAMENTE especificar esta opción, ya que puede aumentar significativamente el rendimiento al especificar virtio entre otros ajustes del invitado.

Si el invitado se ha instalado utilizando virt-manager versión 2.0.0 o posterior, no debería ser necesario proporcionar esta información, ya que la variante del SO se habrá almacenado en la configuración del invitado durante la instalación y virt-xml la recuperará automáticamente de allí.

Utiliza el comando virt-xml --osinfo list para obtener la lista de las variantes de SO aceptadas. Consulta osinfo-query os para obtener aún más información.

Consulta la documentación de virt-install(1) para obtener más detalles sobre --osinfo/--os-variant

OPCIONES DE CONVERSIÓN

--convert-to-q35

Sintaxis: --convert-to-q35 [OPCIONES]

Convierte una configuración de VM existente de PC/i440FX a tipo de máquina Q35. Esto consiste principalmente en:

  • Convertir la topología del dispositivo de PCI a PCIe
  • Convertir cualquier almacenamiento IDE a SATA

Es posible que necesites realizar cambios de configuración dentro de la VM para manejar esto también. Por ejemplo, Windows 10 podría no encontrar el dispositivo de arranque después de la conversión de IDE a SATA. Pero arrancar en modo seguro una vez podría solucionarlo.

Las subopciones son:

num_pcie_root_ports=NUM
Controla el número de dispositivos de controlador pcie-root-port predeterminados que agregamos a la VM por defecto.

--convert-to-vnc

Sintaxis: --convert-to-vnc [OPCIONES]

Convierte una VM existente para usar exclusivamente un solo dispositivo gráfico VNC.

Intentará eliminar todas las referencias a cualquier configuración gráfica que no sea VNC, como Spice. Por ejemplo:

  • Los dispositivos qxl se reemplazarán
  • se eliminarán todos los dispositivos spicevmc y spiceport
  • Spice GL se convertirá a egl-headless

Las subopciones son:

qemu-vdagent=on|off
Agrega un dispositivo qemu-vdagent si aún no está configurado. Esto reemplaza parte de la funcionalidad del agente vdagent de Spice. Por defecto es off, pero eso podría cambiar en el futuro.

Estas opciones modifican el XML para una sola clase de elementos XML. Encontrarás documentación más completa en virt-install(1).

Generalmente, estas opciones se mapean de forma bastante directa al XML de libvirt, documentado en https://libvirt.org/formatdomain.html

Las cadenas de opciones tienen el formato: --option opt=val,opt2=val2,... ejemplo: --disk path=/tmp/foo,shareable=on. Las propiedades se pueden usar con '--option opt=,', para borrar la configuración de caché de un disco, podrías usar '--disk cache=,'

Para cualquier opción, usa --option=? para ver una lista de todas las subopciones disponibles, ejemplo: --disk=? o --boot=?

La salida de --help también enumera algunos ejemplos generales. Consulta la sección EJEMPLOS a continuación para ver algunos ejemplos comunes.

virt-xml tiene específicamente algunas operaciones que en realidad no se aplican a virt-install Ejemplos:

--boot refresh-machine-type=yes
Actualiza el valor del XML <os><type machine=X></os> al último que proporciona qemu. Por ejemplo, si tu VM tiene un tipo de máquina con valor pc-q35-4.0, esto restablecerá el valor a q35, y funciona de manera similar con otros tipos de máquina versionados. Ocasionalmente, esto es necesario para habilitar correcciones de errores de qemu, o cuando qemu desaprueba y elimina valores de tipos de máquina antiguos.

EJEMPLOS

Ver una lista de todas las subopciones que toman --disk y --network

# virt-xml --disk=? --network=?

Cambia la <description> del dominio 'EXAMPLE':

# virt-xml EXAMPLE --edit --metadata description="mi nueva descripción"

# Habilita el menú de dispositivos de arranque para el dominio 'EXAMPLE':

# virt-xml EXAMPLE --edit --boot menu=on

Borra la definición de <cpu> anterior del dominio 'winxp', la cambia a 'host-model', pero confirma interactivamente la diferencia antes de guardar:

# virt-xml winxp --edit --cpu host-model,clearxml=yes --confirm

Cambia la segunda tarjeta de sonido a model=ich6 en 'fedora19', pero solo muestra la diferencia:

# virt-xml fedora19 --edit 2 --sound model=ich6 --print-diff

Actualiza la contraseña de todos los dispositivos gráficos de la VM en ejecución 'rhel6':

# virt-xml rhel6 --edit all --graphics password=foo --update

Elimina la ruta del disco del dispositivo de disco hdc:

# virt-xml rhel6 --edit target=hdc --disk path=

Cambia todos los dispositivos de disco de tipo 'disk' para usar cache=none, usando el XML de la entrada estándar, e imprime el nuevo XML en la salida estándar.

# cat <xmlfile> | virt-xml --edit device=disk --disk cache=none

Cambia el IO del disco 'hda' a native y usa la política de inicio como 'optional'.

# virt-xml fedora20 --edit target=hda \
           --disk io=native,startup_policy=optional

Cambia todos los dispositivos host para usar driver_name=vfio para la VM 'fedora20' en la conexión remota

# virt-xml --connect qemu+ssh://remotehost/system \
           fedora20 --edit all --hostdev driver_name=vfio

Conecta en caliente el dispositivo USB host 001.003 al dominio en ejecución 'fedora19':

# virt-xml fedora19 --update --add-device --hostdev 001.003

Agrega un canal spicevmc al dominio 'winxp', que estará disponible después del próximo apagado de la VM.

# virt-xml winxp --add-device --channel spicevmc

Crea una imagen de disco qcow2 de 10G y adjúntala a 'fedora18' para el próximo inicio de la VM:

# virt-xml fedora18 --add-device \
  --disk /var/lib/libvirt/images/newimage.qcow2,format=qcow2,size=10

Lo mismo que lo anterior, pero asegura que el disco se adjunte al bus más apropiado para el SO invitado proporcionando información sobre él en la línea de comandos:

# virt-xml fedora18 --osinfo fedora18 --add-device \
  --disk /var/lib/libvirt/images/newimage.qcow2,format=qcow2,size=10

Desconecta en caliente el disco vdb del dominio en ejecución 'rhel7':

# virt-xml rhel7 --update --remove-device --disk target=vdb

Elimina todos los dispositivos gráficos de la VM 'rhel7' después del próximo apagado:

# virt-xml rhel7 --remove-device --graphics all

NOMBRE

virt-xml - Manipular archivos XML de dominio de libvirt

SINOPSIS

virt-xml OPCIONES ...

DESCRIPCIÓN

La utilidad virt-xml permite manipular archivos XML de dominio de libvirt, ya sea a partir de la definición de un dominio existente, un archivo XML, o desde cero.

La mayoría de las operaciones implican añadir o modificar elementos XML dentro de la definición del dominio.

El uso de virt-xml es principalmente para tareas de automatización, pero también puede ser útil para la inspección y el análisis de definiciones de dominio.

OPCIONES

Las opciones se dividen en las siguientes categorías:

--build-xml
Construye un archivo XML desde cero basado en los argumentos proporcionados. Útil para crear definiciones de dominio para VM nuevas.
--edit
Edita un dominio existente. Requiere el nombre del dominio o un archivo XML como entrada.
--confirm
Confirma automáticamente las operaciones que de otro modo requerirían confirmación del usuario. Útil para scripts.
--qemu-commandline
Añade un argumento de línea de comandos qemu a la definición del dominio. Útil para opciones específicas de qemu que no están directamente expuestas por libvirt.
--boot
Especifica el dispositivo de arranque para el dominio. Puede ser un dispositivo de disco, CD-ROM o red.
--network
Configura el dispositivo de red para el dominio.
--graphics
Configura el dispositivo gráfico para el dominio.
--console
Configura un dispositivo de consola para el dominio.
--disk
Configura un dispositivo de disco para el dominio.
--virtio-scsi
Habilita el controlador virtio-scsi para el dominio.
--input
Configura un dispositivo de entrada para el dominio.
--sound
Configura un dispositivo de sonido para el dominio.
--video
Configura un dispositivo de video para el dominio.
--memballoon
Configura un dispositivo de globos de memoria para el dominio.
--controller
Configura un dispositivo controlador para el dominio.
--device
Añade un dispositivo genérico al dominio.
--channel
Configura un canal para el dominio.
--emulator
Especifica la ruta del emulador para el dominio.
--machine
Especifica el tipo de máquina para el dominio.
--cpu
Configura la CPU para el dominio.
--topology
Configura la topología de la CPU para el dominio.
--clock
Configura el reloj para el dominio.
--pm-opts
Configura las opciones de gestión de energía para el dominio.
--rng
Configura un dispositivo de número aleatorio para el dominio.
--hyperv-timer
Habilita el temporizador de Hyper-V para el dominio.
--kvm-hidden-state
Habilita el estado oculto de KVM para el dominio.
--features
Configura las características del hipervisor para el dominio.
--io=THREADS
Establece el número de hilos de E/S para el dominio.
--cputune
Configura el ajuste de CPU para el dominio.
--iothreads
Configura los hilos de E/S para el dominio.
--numatune
Configura el ajuste NUMA para el dominio.
--memorybacking
Configura el respaldo de memoria para el dominio.
--memorymap
Configura el mapa de memoria para el dominio.
--security
Configura las opciones de seguridad para el dominio.
--seclabel
Establece la etiqueta de seguridad para el dominio.
--smbios
Configura la información SMBIOS para el dominio.
--firmware
Configura el firmware para el dominio.
--metadata
Establece metadatos para el dominio.
--os-variant
Establece la variante del sistema operativo para el dominio. Ayuda a optimizar la configuración.
--virt-type
Establece el tipo de virtualización (por ejemplo, kvm, qemu).
--no-define
No define el dominio en libvirt después de la modificación. La salida será solo el XML modificado.
--start
Inicia el dominio después de realizar los cambios. Solo aplicable si no se usa --no-define.
--print-xml
Imprime el XML resultante en stdout. Útil para obtener la definición XML modificada.

ACCIONES XML

Las siguientes acciones se utilizan para construir o modificar la definición XML del dominio:

--build-xml
Construye un archivo XML desde cero. Se debe especificar al menos un dispositivo o característica. Por ejemplo, para crear un dominio básico con una consola:
# virt-xml --build-xml --console pty,target_type=virtio

OPCIONES DE SALIDA

--print-xml
Imprime el XML resultante en la salida estándar. Se puede combinar con otras opciones para obtener el XML modificado.
--no-define
Evita que virt-xml defina el dominio en libvirt después de la modificación. La salida será solo el XML modificado.

OPCIONES DEL SO INVITADO

--os-variant
Especifica la variante del sistema operativo invitado. Esto ayuda a libvirt a optimizar la configuración del dominio para el SO específico. Ejemplos: fedora34, win10.

OPCIONES DE CONVERSIÓN

--machine
Establece el tipo de máquina del dominio. Ejemplos: q35, pc-i440fx-6.0.
--virt-type
Establece el tipo de hipervisor. Ejemplos: kvm, qemu.

OPCIONES XML

Estas opciones se utilizan para añadir o modificar elementos XML específicos dentro de la definición del dominio.

--disk
Define un dispositivo de disco.
  • Ejemplo: --disk /var/lib/libvirt/images/myvm.qcow2,size=20,format=qcow2
--network
Define un dispositivo de red.
  • Ejemplo: --network bridge=br0,model=virtio
--graphics
Define el tipo y la configuración de gráficos.
  • Ejemplo: --graphics spice,listen=0.0.0.0
--console
Define un dispositivo de consola.
  • Ejemplo: --console pty,target_type=virtio
--boot
Define el orden de arranque.
  • Ejemplo: --boot cdrom,hd

OPCIONES VARIAS

--edit
Se utiliza para modificar la definición de un dominio existente. Requiere el nombre del dominio o un archivo XML como entrada.
--confirm
Confirma automáticamente las operaciones que requieren confirmación. Útil en scripts.
--qemu-commandline
Permite pasar argumentos de línea de comandos directamente a qemu.
  • Ejemplo: --qemu-commandline "-device FOO"
--start
Inicia el dominio después de que se apliquen los cambios. Requiere que el dominio ya exista o se esté definiendo.
--no-define
Evita que el dominio se defina en libvirt después de la operación. La salida se imprimirá en stdout.

EJEMPLOS

Genera XML para un dispositivo de consola virtio e imprímelo en la salida estándar:

# virt-xml --build-xml --console pty,target_type=virtio

Añade un paso de línea de comandos qemu:

# virt-xml f25 --edit --confirm --qemu-commandline="-device FOO"

Usa el dispositivo de arranque 'network' para un único arranque transitorio:

# virt-xml myvm --no-define --start --edit --boot network

CAVEATS

Los hosts de virtualización compatibles con libvirt pueden no permitir todos los cambios que parecen posibles. Algunas ediciones realizadas en la definición de una VM pueden ser ignoradas. Por ejemplo, QEMU no permite la eliminación de ciertos dispositivos una vez que han sido definidos.
