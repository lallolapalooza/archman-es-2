Descripción Detallada

Interfaz abstracta para proporcionar soporte para archivos definidos por el usuario.

Advertencia

Esto es material avanzado y complejo. No lo necesitas a menos que realmente sepas lo que estás haciendo. La mayoría de las aplicaciones no lo necesitarán.

Históricamente, PhysicsFS proporcionaba un medio para montar varios formatos de archivo y directorios físicos en el sistema de archivos nativo. Sin embargo, las aplicaciones se han limitado a los formatos de archivo proporcionados por la biblioteca. Esta interfaz permite a una aplicación proporcionar sus propios tipos de archivos de archivador.

Conceptualmente, un PHYSFS_Archiver proporciona entradas de directorio, mientras que PHYSFS_Io proporciona flujos de datos para esas entradas de directorio. El uso más obvio de PHYSFS_Archiver es proporcionar soporte para un tipo de archivo que PhysicsFS no proporciona directamente: tal vez algún formato propietario que solo tu aplicación necesite entender.

Internamente, todo el soporte de archivado incorporado utiliza esta interfaz, por lo que los mejores ejemplos para construir un PHYSFS_Archiver son el código fuente de PhysicsFS.

Un archivador se añade al sistema con PHYSFS_registerArchiver(), y luego estará disponible para su uso automáticamente con PHYSFS_mount(); si un archivo dado puede ser manejado por tu archivador, se le dará el control según corresponda.

Estos métodos tratan con manejadores de directorios. Tienes una instancia de tu archivador, y esta genera un manejador único y opaco para cada archivo abierto en su método openArchive(). Dado que la vida útil de un Archivador (no de un archivo) es generalmente toda la vida del proceso, y se asume que es un singleton, no proporcionamos ningún dato de instancia para el archivador en sí; la aplicación puede usar variables estáticas si es necesario.

Los enlaces simbólicos siempre deben seguirse (excepto en stat()); PhysicsFS utilizará el método stat() para comprobar los enlaces simbólicos y tomar una decisión sobre si continuar llamando a otros métodos basándose en eso.

Los archivadores, cuando sea necesario, deben establecer el estado de error de PhysicsFS con PHYSFS_setErrorCode() antes de devolver. PhysicsFS pasará estos errores a la aplicación sin modificar en la mayoría de los casos.

Seguridad de hilos: No se garantiza que las implementaciones de PHYSFS_Archiver sean seguras para hilos por sí mismas. PhysicsFS proporciona seguridad de hilos cuando llama a un archivador dado dentro de la biblioteca, pero no promete que el uso del mismo PHYSFS_File desde dos hilos a la vez sea seguro para hilos; como tal, tu PHYSFS_Archiver puede asumir que el bloqueo se maneja por ti siempre que el PHYSFS_Io que devuelvas de PHYSFS_open* no cambie ningún estado de tu Archivador, ya que el PHYSFS_Io no estará tan agresivamente protegido.

void(* PHYSFS_Archiver::closeArchive) (void *opaque)

Destruye un archivo previamente abierto. Cierra este archivo y libera cualquier memoria asociada, incluido el PHYSFS_Io original y (opaque) en sí mismo, si aplica. La implementación puede asumir que no se llamará si todavía hay archivos abiertos de este archivo.

PHYSFS_EnumerateCallbackResult(* PHYSFS_Archiver::enumerate) (void *opaque, const char *dirname, PHYSFS_EnumerateCallback cb, const char *origdir, void *callbackdata)

Lista todos los archivos en (dirname). Cada archivo se pasa a (cb), donde se hace una copia si es apropiado, por lo que puedes desecharla al volver de la devolución de llamada. (dirname) está en notación independiente de la plataforma. Si tienes un error, llama a PHYSFS_SetErrorCode() con el código que parezca apropiado y devuelve PHYSFS_ENUM_ERROR. Si la devolución de llamada devuelve PHYSFS_ENUM_ERROR, por favor llama a PHYSFS_SetErrorCode(PHYSFS_ERR_APP_CALLBACK) y luego devuelve también PHYSFS_ENUM_ERROR. No llames a la devolución de llamada de nuevo bajo ninguna circunstancia. Si la devolución de llamada devuelve PHYSFS_ENUM_STOP, deja de enumerar y devuelve también PHYSFS_ENUM_STOP. No llames a la devolución de llamada de nuevo bajo ninguna circunstancia. No establezcas un código de error en este caso. Las devoluciones de llamada solo deben devolver un valor de PHYSFS_EnumerateCallbackResult. Cualquier otro resultado tiene un comportamiento indefinido. Siempre que la devolución de llamada haya devuelto PHYSFS_ENUM_OK y no hayas experimentado ningún error propio, continúa enumerando hasta que termines y luego devuelve PHYSFS_ENUM_OK sin establecer un código de error.

Advertencia

PHYSFS_enumerate devuelve cero o no cero (éxito o fallo), ¡así que ten en cuenta que este puntero de función devuelve valores diferentes!

PHYSFS_ArchiveInfo PHYSFS_Archiver::info

Información básica sobre este archivador. Esto se utiliza para identificar tu archivo y se devuelve en PHYSFS_supportedArchiveTypes().

int(* PHYSFS_Archiver::mkdir) (void *opaque, const char *filename)

Crea un directorio en el archivador. Si la aplicación intenta crear múltiples directorios, PhysicsFS los dividirá en múltiples llamadas antes de pasarlos a tu controlador. Si el archivo es de solo lectura, esta operación debería fallar. Devuelve un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_Io *(* PHYSFS_Archiver::openAppend) (void *opaque, const char *filename)

Abre un archivo en este archivador para añadir. Si el archivo no existe, debe crearse. El desplazamiento de escritura debe ser el final del archivo. Si el archivador es de solo lectura, esta operación debería fallar. Este nombre de archivo está en notación independiente de la plataforma. Devuelve NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Devuelve no NULL en caso de éxito. El puntero devuelto se pasará como parámetro "opaque" para futuras llamadas de archivo.

Abre un archivo en este archivador para escritura. Si el archivo existe, su contenido se trunca. Si el archivo no existe, se crea. Si el archivador es de solo lectura, esta operación debería fallar. El campo `(claimed)` debe establecerse en 1 si este es definitivamente un archivo que tu implementación de archivador puede manejar, incluso si falla. Lo usamos para decidir si debemos intentar con otros archivadores si fallas al abrirlo. Por ejemplo: el archivador `.zip` establecerá esto en 1 para algo que tenga una firma de archivo `.zip`, incluso si falló porque el archivo también estaba truncado. No tiene sentido intentar otros archivadores aquí, ¡ya intentamos manejarlo con la implementación apropiada! Retorna NULL en caso de fallo y establece `(claimed)` apropiadamente. Si ningún archivador abrió el archivo o estableció `(claimed)`, PHYSFS_mount() reportará PHYSFS_ERR_UNSUPPORTED. De lo contrario, reportará el error del archivador que reclamó los datos a través de `(claimed)`. Retorna un puntero no NULL en caso de éxito. El puntero retornado se pasará como el parámetro "opaque" para llamadas posteriores.

PHYSFS_Io *(* PHYSFS_Archiver::openRead) (void *opaque, const char *fnm)

Abre un archivo en este archivo para lectura. Este nombre de archivo, (fnm), está en notación independiente de la plataforma. Falla si el archivo no existe. Retorna NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Retorna un puntero no NULL en caso de éxito. El puntero retornado se pasará como el parámetro "opaque" para llamadas de archivo posteriores.

PHYSFS_Io *(* PHYSFS_Archiver::openWrite) (void *opaque, const char *filename)

Abre un archivo en este archivo para escritura. Si el archivo no existe, debe ser creado. Si existe, debe ser truncado a cero bytes. La posición de escritura debe ser el inicio del archivo. Si el archivo está en modo de solo lectura, esta operación debe fallar. Este nombre de archivo está en notación independiente de la plataforma. Retorna NULL en caso de fallo y llama a PHYSFS_setErrorCode(). Retorna un puntero no NULL en caso de éxito. El puntero retornado se pasará como el parámetro "opaque" para llamadas de archivo posteriores.

int(* PHYSFS_Archiver::remove) (void *opaque, const char *filename)

Elimina un archivo o directorio en el archivo. Esta misma llamada se usa tanto para archivos como para directorios; no hay una llamada `rmdir()` separada. Los directorios solo deben eliminarse si están vacíos. Si el archivo está en modo de solo lectura, esta operación debe fallar.

Retorna un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

int(* PHYSFS_Archiver::stat) (void *opaque, const char *fn, PHYSFS_Stat *stat)

Obtiene metadatos básicos del archivo. En caso de éxito, rellena todos los campos de (stat), utilizando valores predeterminados razonables para los campos que se aplican a tu archivo.

Retorna un valor distinto de cero en caso de éxito, cero en caso de fallo. Este nombre de archivo está en notación independiente de la plataforma. En caso de fallo, llama a PHYSFS_setErrorCode().

PHYSFS_uint32 PHYSFS_Archiver::version

Información de compatibilidad binaria. Debe establecerse en cero en este momento. Versiones futuras de esta estructura incrementarán este campo, para que sepamos qué soporta una implementación dada. Presumiblemente, seguiremos soportando versiones anteriores a medida que ofrezcamos nuevas características, sin embargo.
