VIMB(1) Manual de Vimb VIMB(1)

NOMBRE

Vimb - Vim Browser - Un navegador web modal basado en WebKit, inspirado en Vim: el gran editor.

SINOPSIS

vimb [OPCIONES] [URI|archivo|-]

DESCRIPCIÓN

Vimb es un navegador web basado en WebKit que se comporta como el plugin Vimperator para Firefox y tiene paradigmas de uso del gran editor, Vim. El objetivo de Vimb es construir una experiencia de navegación completamente controlada por teclado, eficiente y placentera.

OPCIONES

Si no se proporciona URI o archivo, Vimb abrirá la página de inicio configurada. Si URI es '-', Vimb leerá el HTML para mostrarlo desde la entrada estándar.

Los argumentos obligatorios para las opciones largas son también obligatorios para las opciones cortas.

-C, --cmd COMANDO
Ejecuta COMANDO como un comando ex justo antes de que se cargue la primera página. Si el flag se usa más de una vez, los comandos se llaman en el orden en que se dan. También puedes pasar varios comandos ex en un solo COMANDO, si están separados por "|". 
vimb --cmd "set dark-mode=on|set header=Referer,DNT=1"
-c, --config ARCHIVO
Usa la configuración personalizada dada como ARCHIVO. Esto también se aplicará a las nuevas instancias creadas.
-e, --embed IDVENTANA
IDVENTANA de una aplicación compatible con XEmbed, que Vimb usará como padre.
-i, --incognito
Inicia una instancia con datos de usuario de solo lectura (ver sección ARCHIVOS).
-h, --help
Muestra las opciones de ayuda.
-p, --profile NOMBRE-PERFIL
Crea o abre el perfil de configuración especificado. Los datos de configuración para el perfil se almacenan en un directorio llamado NOMBRE-PERFIL dentro del directorio predeterminado para los datos de configuración.
-v, --version
Imprime la información de compilación y versión y luego sale.
--no-maximize
No intentes maximizar la ventana.
--bug-info
Imprime información sobre las bibliotecas utilizadas para reportes de errores y luego sale.

MODOS

Vimb es modal y tiene los siguientes modos principales:

Modo Normal
El modo predeterminado. Presionar Escape siempre entra en modo normal.
Modo de Entrada
Se usa para editar elementos de texto en una página web.
Modo de Comando
Ejecuta comandos `ex` desde el cuadro de entrada incorporado (línea de comandos).
Modo de Paso Directo
En el modo de Paso Directo, Vimb solo interpreta las combinaciones de teclas `<Esc>` y `<C-[>`, todas las demás pulsaciones de teclas se envían a la vista web para que las maneje. Esto permite usar las combinaciones de teclas configuradas por un sitio web, que de otro modo podrían ser absorbidas por Vimb.

Indicaciones (Hinting)

El hinting en Vimb es cómo realizas las tareas que harías con el ratón en los navegadores comunes controlados por ratón: abrir una URI, copiar una URI, guardar una página y así sucesivamente. Cuando se inicia el hinting, los elementos relevantes en la página se marcarán con etiquetas generadas a partir de `hint-keys' configurados. Las indicaciones se pueden seleccionar usando <Tab>, <C-I> o <C-Tab>, <C-O>, escribiendo los caracteres de la etiqueta, o filtrando los elementos por algún texto que forma parte del elemento indicado (como URI, texto del enlace, etiqueta del botón) o cualquier combinación de estos métodos. Si se presiona <enter>, la indicación activa actual se ejecutará. Si solo queda una indicación posible, esta se ejecutará automáticamente.

Sintaxis: ;{mode}{hint}

Inicia el modo Hints. Diferentes elementos dependiendo del mode se resaltan y se `numeran'. Los elementos se pueden seleccionar escribiendo su etiqueta, o escribiendo parte de su texto (hint) para acotar el resultado. Cuando se selecciona un elemento, se hace clic o se usa automáticamente (dependiendo del mode) y el modo de indicación finaliza.

El filtrado de indicaciones por texto divide la consulta en ' ' y usa las partes individuales como consultas separadas para filtrar las indicaciones. Esto es útil para indicaciones que tienen muchos caracteres filtrables en común y se requieren muchos caracteres para hacer una selección distinta. Por ejemplo, ';over tw' seleccionará fácilmente la segunda indicación de {'very long link text one', 'very long link text two'}.

MODO COMANDO

Los comandos que se listan a continuación son comandos ex, como en Vim, que se escriben en el cuadro de entrada (la línea de comandos de vimb). Los comandos pueden variar en su sintaxis o en las partes que permiten, pero en general siguen una sintaxis simple.

Sintaxis: :[:| ][N]cmd[name][!][ lhs][ rhs]

Donde lhs (lado izquierdo) no debe contener espacios sin escapar. La sintaxis de rhs (lado derecho) si está disponible depende del comando. Por el momento, se parsean las partes del contador [N] de los comandos, pero actualmente no hay ningún comando que use el contador.

Los comandos que se escriben interactivamente normalmente se graban en el historial de comandos y en el registro. Para evitar esto, los comandos pueden ir precedidos por uno o más ':' adicionales o espacios en blanco.

Se pueden dar múltiples comandos, separados por un '|', en una sola línea de comando y se ejecutarán consecutivamente. El pipe se puede incluir como argumento de un comando escapándolo con una barra invertida.
Los siguientes comandos procesan toda la cadena de la línea de comando literalmente. Estos comandos incluirán cualquier '|' como parte de su cadena de argumentos y, por lo tanto, no pueden ser seguidos por otro comando.

-
autocmd
-
cmap, cnoremap, imap, inoremap, nmap, nnoremap
-
eval
-
normal
-
open, tabopen
-
shellcmd

Mapeo de Teclas

Los mapeos de teclas permiten a los usuarios alterar las acciones de las pulsaciones de teclas. Cada mapeo de teclas está asociado a un modo y solo tiene efecto cuando el modo está activo. Los siguientes comandos permiten al usuario sustituir una secuencia de pulsaciones de teclas por otra.

Sintaxis: :{m}map {lhs} {rhs}

Ten en cuenta que lhs termina con el primer espacio encontrado. Si también quieres usar espacios en {lhs}, debes escaparlos con una sola `\', como se muestra en los ejemplos.

rhs comienza con el primer carácter que no sea un espacio. Si quieres que un rhs comience con un espacio, debes usar "<Space>".

Se proporcionan comandos estándar de mapeo de teclas para estos modos m:

n
Modo Normal: al navegar normalmente.
i
Modo Inserción: al interactuar con campos de texto en un sitio web.
c
Modo Línea de Comandos: al escribir en la línea de comandos de Vimb.

La mayoría de las teclas en secuencias de teclas se representan simplemente por el carácter que ves en la pantalla cuando las escribes. Sin embargo, dado que un número de estos caracteres tienen significados especiales, y un número de teclas no tienen representación visual, se requiere una notación especial.

Los nombres de teclas especiales tienen el formato <...>. Las siguientes teclas especiales se pueden usar: <Left>, <Up>, <Right>, <Down> para las teclas de cursor, <Tab>, <Esc>, <CR>, <Space>, <BS>, <F1>-<F12> y <C-A>-<C-Z>.

:nm[ap] {lhs} {rhs}
:im[ap] {lhs} {rhs}
:cm[ap] {lhs} {rhs}
Mapea la secuencia de teclas lhs a rhs para los modos donde se aplica el comando map. El resultado, incluido rhs, se escanea posteriormente en busca de mapeos. Esto permite el uso anidado y recursivo de mapeos.
:cmap <C-G>h /home/user/downloads/
Agrega un atajo de teclado para insertar una ruta de archivo en el cuadro de entrada. Esto podría ser útil para el comando `:save`, que podría usarse como `":save ^Gh"'.
:nmap <F1> :set scripts=on<CR>:open !glib<Tab><CR>
Esto habilitará los scripts y buscará el primer URI marcado con la etiqueta `glib' y lo abrirá inmediatamente si se presiona la tecla F1.
:nmap \ \ 50G
Ejemplo que mapea dos espacios para ir al 50% de la página.
:nn[oremap] {lhs} {rhs}
:ino[remap] {lhs} {rhs}
:cno[remap] {lhs} {rhs}
Mapea la secuencia de teclas lhs a rhs para el modo donde se aplica el comando map. Deshabilita el mapeo de rhs para evitar mapeos anidados y recursivos. A menudo se usa para redefinir un comando.
:nu[nmap] {lhs}
:iu[nmap] {lhs}
:cu[nmap] {lhs}
Elimina el mapeo de lhs para el modo aplicable.

Guarda el URI abierto actualmente con tags en el archivo de marcadores.

Manejadores

Los manejadores permiten especificar scripts externos para manejar métodos de URI alternativos.

:handler-add handler=cmd
Agrega un manejador para dirigir enlaces handler al cmd externo. El cmd puede contener un marcador de posición `%s` que se rellenará con el URI completo dado cuando se llame al comando.
:handler-add mailto=urxvt -e mutt %s
para iniciar el cliente de correo para enlaces mailto.
:handler-add magnet=xdg-open %s
para abrir enlaces magnet con xdg-open.
:handler-add ftp=urxvt -e wget %s -P ~/ftp-downloads
para manejar descargas ftp a través de wget.
:handler-remove handler
Elimina el manejador para el handler de URI dado.

Atajos

Los atajos permiten la apertura de un URI construido a partir de una plantilla nombrada con parámetros adicionales. Si se define un atajo llamado 'dd', puedes usarlo con `:open dd lista de parámetros` para abrir el URI generado.

Los atajos son convenientes para usar con motores de búsqueda donde el URI está estandarizado y un solo parámetro es definido por el usuario.

:shortcut-add shortcut=URI
Agrega un atajo con el atajo y la plantilla de URI. El URI puede contener múltiples marcadores de posición $0-$9 que se rellenarán con los parámetros dados cuando se llame al atajo. Los parámetros dados cuando se llama al atajo se dividirán en tantos parámetros como el marcador de posición más alto utilizado.

Para usar espacios dentro de los parámetros, estos pueden agruparse rodeándolos con comillas simples o dobles, como se muestra en el ejemplo de atajo `map'.

:shortcut-add dl=https://duckduckgo.com/lite/?q=$0
para configurar un motor de búsqueda. Se puede llamar con `:open dl mi frase de búsqueda'.
:shortcut-add gh=https://github.com/$0/$1
para construir URIs a partir de parámetros dados. Se puede llamar `:open gh fanglingsu vimb'.
:shortcut-add map=https://maps.google.com/maps?saddr=$0&daddr=$1
para buscar una ruta, todos los parámetros excepto el último deben entrecomillarse si contienen espacios, como `:open map "ayuntamiento, Londres" estación de tren, Londres'
:shortcut-remove shortcut
Elimina el motor de búsqueda del atajo dado.
:shortcut-default shortcut
Establece el atajo dado como predeterminado, es decir, el atajo que se utilizará si no se proporciona ningún atajo y la cadena a abrir no es un URI. No importa si el atajo ya está en uso o no para poder configurarlo.

Configuración

:se[t] var=value
Establece valores de configuración nombrados por var. Para establecer una variable booleana debes usar 'on', 'off' o 'true' y 'false'. Los colores se dan como valor hexadecimal como '#f57700'. Los espacios o más signos de igual en value funcionan sin comillas: por ejemplo, `":set sans-serif-font=Some Sans Font"'.
:se[t] var+=value
Agrega el value a una opción numérica, o adjunta el value a una opción de cadena. Cuando la opción es una lista separada por comas, se agrega una coma, a menos que el valor estuviera vacío.
:se[t] var^=value
Multiplica el value por una opción numérica, o antepone el value a una opción de cadena. Cuando la opción es una lista separada por comas, se agrega una coma, a menos que el valor estuviera vacío.
:se[t] var-=value
Resta el value de una opción numérica, o elimina el value de una opción de cadena, si está presente. Cuando la opción es una lista separada por comas, se elimina una coma, a menos que la opción quede vacía.
:se[t] var?
Muestra el valor actual establecido de la variable. VAR.
:se[t] var!
Alterna el valor de la variable booleana var y muestra el nuevo valor establecido.

Comandos automáticos

Un autocomando es un comando que se ejecuta automáticamente en respuesta a algún evento, como la apertura de un URI. Los autocomandos son muy potentes. Úsalos con cuidado y te ayudarán a evitar escribir muchos comandos.

Los autocomandos se construyen con las siguientes propiedades.

grupo
Si no se proporciona el argumento [grupo], Vimb usa el grupo actual como se define con ':augroup', de lo contrario, Vimb usa el grupo definido con [grupo]. Los grupos son útiles para eliminar múltiples autocomandos agrupados.
evento
Puedes especificar una lista de nombres de eventos separados por comas. No se pueden usar espacios en esta lista.
Eventos:
LoadStarting
Se dispara antes de que se abra una nueva página. Aún no se han enviado ni recibido datos, la carga puede fallar por problemas de transporte.
LoadStarted
Se dispara si se va a abrir una nueva página. No se han enviado datos.
que aún no se ha recibido, la carga puede fallar debido a problemas de transporte.
LoadCommitted
Se dispara si ha llegado el primer fragmento de datos, lo que significa que se han establecido los requisitos de transporte necesarios y la carga se está realizando. Este es el evento adecuado para activar configuraciones relacionadas con el contenido como 'scripts', 'plugins', etc.
LoadFinished
Se dispara cuando se ha cargado todo lo necesario para mostrar en la página.
DownloadStarted
Se dispara inmediatamente después de que comienza una descarga.
DownloadFinished
Se dispara si una descarga gestionada por Vimb ha finalizado.
DownloadFailed
Se dispara si una descarga gestionada por Vimb ha fallado.
pat
Lista separada por comas de patrones, que se comparan en orden para verificar si un autocomando se aplica a la URI asociada a un evento. Para usar ',' dentro de los patrones individuales, debe escaparse como '\,'.

Patrones:

*
Coincide con cualquier secuencia de caracteres. Esto incluye también '/', a diferencia de los patrones de shell.
?
Coincide con cualquier carácter individual excepto '/'.
{uno,dos}
Coincide con 'uno' o 'dos'. Cualquier '{', ',' y '}' dentro de este patrón debe escaparse con '\'. '*' y '?' no tienen un significado especial dentro de las llaves.
\
Use la barra invertida para escapar el significado especial de '?*{},' en el patrón o lista de patrones.
cmd
Cualquier comando `ex` que vimb entienda. El prefijo ':' no es necesario. Se pueden separar múltiples comandos con '|'.
:au[tocmd] [group] {event} {pat} {cmd}
Agrega cmd a la lista de comandos que Vimb ejecutará automáticamente en event para una URI que coincida con el patrón de autocomando pat. Vimb siempre agrega cmd después de los autocomandos existentes, para que se ejecuten en el orden en que se proporcionaron.
:au[tocmd]! [group] {event} {pat} {cmd}
Elimina todos los autocomandos asociados con event y que coinciden con el patrón pat, y agrega el comando cmd. Tenga en cuenta que el patrón no se compara literalmente para encontrar los autocomandos a eliminar, como hace Vim. Vimb compara el patrón del autocomando con pat. Si [group] no se proporciona, elimina los autocomandos del grupo actual, como se mencionó anteriormente.
:au[tocmd]! [group] {event} {pat}
Elimina todos los autocomandos asociados con event y que coinciden con el patrón pat en el grupo dado (grupo actual por defecto).
:au[tocmd]! [group] * {pat}
Elimina todos los autocomandos con patrones que coinciden con pat para todos los eventos en el grupo dado (grupo actual por defecto).
:au[tocmd]! [group] {event}
Elimina todos los autocomandos para event en el grupo dado (grupo actual por defecto).
:au[tocmd]! [group]
Elimina todos los autocomandos en el grupo dado (grupo actual por defecto).
:aug[roup] {name}
Define el grupo de autocomandos name para los siguientes comandos ":autocmd". El nombre "end" selecciona el grupo predeterminado.
:aug[roup]! {name}
Elimina el grupo de autocomandos name.

Ejemplo:

:aug github
:  au LoadCommitted * set scripts=off|set cookie-accept=never
:  au LoadCommitted http{s,}://github.com/* set scripts=on
:aug end

COMPLETIONS

Las completaciones se activan pulsando `<Tab>` o `<S-Tab>` en el cuadro de entrada activado. Dependiendo del contenido insertado actualmente, se inician diferentes completaciones. La completación toma caracteres adicionales escritos para filtrar la lista de completaciones que se muestra.

commands
La completación de comandos se inicia cuando al menos `:` se muestra en el cuadro de entrada. Si se pasan caracteres iniciales, la completación buscará los comandos que comienzan con los caracteres dados.
settings
La completación del nombre de configuración se inicia si al menos `:set ` se muestra en el cuadro de entrada y también coincide con configuraciones que comienzan con el prefijo de configuración ya escrito.
history
El historial de URIs se muestra para los comandos `:open ` y `:tabopen `. Esta completación busca cada palabra dada en el historial de URIs y títulos. Solo se muestran los elementos del historial donde el título o la URI contienen todas las etiquetas.
:open foo bar<Tab>
completará solo URIs que contengan las palabras foo y bar.
bookmarks
La completación de marcadores es similar a la completación de historial, pero solo coincide con las etiquetas de los marcadores. La completación de marcadores se inicia con `:open !`, `:tabopen !` o `:bmr ` y realiza una búsqueda de prefijos para todas las palabras dadas en las etiquetas de los marcadores.
:open !foo ba
coincidirá con todos los marcadores cuyas etiquetas comiencen con "foo" y "ba". Si el marcador no tiene etiquetas establecidas, la URL se divide por `.' y `/` en etiquetas.
:bmr tag
coincidirá con todos los marcadores cuyas etiquetas comiencen con "tag".
bookmark tags
La completación de etiquetas de marcadores permite la inserción de marcadores ya utilizados para los comandos `:bma `.
search
La completación de búsqueda permite una lista filtrada de búsquedas ya realizadas. Esta completación se inicia con `/` o `?` en el cuadro de entrada y realiza una comparación de prefijos para los caracteres adicionales escritos.

Si está 'on', vimb no cargará un sitio https no confiable.
stylesheet (bool)
Si está 'on', se utiliza la hoja de estilos definida por el usuario.
tabs-to-links (bool)
Indica si la tecla Tab recorre los elementos de la página.

Si es verdadero, presionar la tecla Tab enfocará el siguiente elemento en la vista web. De lo contrario, la vista web interpretará las pulsaciones de la tecla Tab como pulsaciones normales. Si el elemento seleccionado es editable, la tecla Tab provocará la inserción de un carácter de Tabulación.

timeoutlen (int)
El tiempo en milisegundos que se espera para completar un código de tecla o una secuencia de teclas mapeada.
user-agent (string)
La cadena user-agent utilizada por WebKit.
user-scripts (bool)
Si está 'on', los scripts de usuario se inyectan en cada página.
webaudio (bool)
Habilita o deshabilita el soporte para WebAudio en páginas. WebAudio es una propuesta experimental para permitir que las páginas web generen datos de Audio WAVE a partir de JavaScript.
webgl (bool)
Habilita o deshabilita el soporte para WebGL en páginas.
webinspector (bool)
Determina si las herramientas de desarrollador, como el Inspector Web, están habilitadas o no.
x-hint-command (string)
Comando utilizado si se activa el modo de indicación ;x. El comando puede ser cualquier cadena de comando de vimb. Tenga en cuenta que el comando se ejecuta a través del mecanismo de mapeo de vimb, por lo que podría cambiar el comportamiento agregando o modificando mapeos.
:set x-hint-command=:sh! curl -e <C-R>% <C-R>;
Esto llena el cuadro de entrada con el comando de descarga prellenado y reemplaza `<C-R>%' con la URI actual y `<C-R>;' con la URI del elemento indicado.
xss-auditor (bool)
Indica si se habilita el auditor XSS. Esta característica filtra algunos tipos de ataques XSS reflectantes en sitios web vulnerables.

ARCHIVOS

$XDG_CONFIG_HOME/vimb[/PROFILE]
Directorio para datos de configuración. Si se ejecuta con el parámetro -p PROFILE, la configuración se lee de este subdirectorio.
config
Archivo de configuración para establecer la configuración de WebKit, algunos estilos de GUI y atajos de teclado.
scripts.js
Este archivo se puede utilizar para ejecutar scripts de usuario, que se inyectan en cada página que se abre.
style.css
Archivo para estilos CSS definidos por el usuario. Este archivo se utiliza si la variable de configuración `stylesheet' está habilitada.
$XDG_DATA_HOME/vimb[/PROFILE]
Directorio para datos en tiempo de ejecución. Si se ejecuta con el parámetro -p PROFILE, los archivos de datos se escriben desde este subdirectorio.
cookies.db Almacenamiento de cookies en Sqlite. Este archivo no se tocará si se establece la opción --incognito.
closed
Contiene las URIs de las últimas ventanas del navegador cerradas. Este archivo no se tocará si se establece la opción --incognito.
history
Este archivo contiene el historial de URIs únicas abiertas. Este archivo no se tocará si se establece la opción --incognito.
bookmark
Este archivo contiene la lista de URIs marcadas con etiquetas.
command
Este archivo contiene el historial de comandos y consultas de búsqueda realizadas a través del cuadro de entrada. Este archivo no se tocará si se establece la opción --incognito.
queue
Contiene la cola de leer más tarde llenada por `qpush'.
search
Este archivo contiene el historial de consultas de búsqueda. Este archivo no se tocará si se establece la opción --incognito.
