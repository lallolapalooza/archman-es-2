NOMBRE

vacuumlo - elimina objetos grandes huérfanos de una base de datos PostgreSQL

SINOPSIS

vacuumlo [opción...] nombrebasedatos...

DESCRIPCIÓN

vacuumlo es un programa utilitario simple que eliminará cualquier objeto grande (LO) "huérfano" de una base de datos PostgreSQL. Un objeto grande huérfano se considera cualquier LO cuyo OID no aparezca en ninguna columna de datos oid o lo de la base de datos.

Si utiliza esto, también podría interesarle el disparador lo_manage en el módulo lo. lo_manage es útil para intentar evitar la creación de LO huérfanos en primer lugar.

Se procesan todas las bases de datos nombradas en la línea de comandos.

OPCIONES

vacuumlo acepta los siguientes argumentos de línea de comandos:

-l límite
--límite=límite

Elimina no más de límite objetos grandes por transacción (por defecto 1000). Dado que el servidor adquiere un bloqueo por cada LO eliminado, eliminar demasiados LO en una sola transacción corre el riesgo de exceder max_locks_per_transaction. Establezca el límite a cero si desea que todas las eliminaciones se realicen en una sola transacción.

-n
--ejecución-en-seco

No elimine nada, solo muestre lo que se haría.

-v
--detallado

Escriba muchos mensajes de progreso.

-V
--versión

Imprima la versión de vacuumlo y salga.

-?
--ayuda

Muestre la ayuda sobre los argumentos de la línea de comandos de vacuumlo y salga.

vacuumlo también acepta los siguientes argumentos de línea de comandos para parámetros de conexión:

-h host
--host=host

Host del servidor de base de datos.

-p puerto
--puerto=puerto

Puerto del servidor de base de datos.

-U nombreusuario
--usuario=nombreusuario

Nombre de usuario con el que conectarse.

-w
--sin-contraseña

Nunca solicite una contraseña. Si el servidor requiere autenticación por contraseña y esta no está disponible por otros medios, como un archivo .pgpass, el intento de conexión fallará. Esta opción puede ser útil en trabajos por lotes y scripts donde no hay ningún usuario presente para introducir una contraseña.

-W
--contraseña

Forzar a vacuumlo a solicitar una contraseña antes de conectarse a una base de datos.

Esta opción nunca es esencial, ya que vacuumlo solicitará automáticamente una contraseña si el servidor la exige. Sin embargo, vacuumlo desperdiciará un intento de conexión al descubrir que el servidor requiere una contraseña. En algunos casos, vale la pena escribir -W para evitar el intento de conexión adicional.

ENTORNO

PGHOST
PGPORT
PGUSER

Parámetros de conexión por defecto.

Esta utilidad, al igual que la mayoría de las otras utilidades de PostgreSQL, también utiliza las variables de entorno admitidas por libpq (consulte la Sección 32.15).

La variable de entorno PG_COLOR especifica si se debe usar color en los mensajes de diagnóstico. Los valores posibles son siempre, automático y nunca.

NOTAS

vacuumlo funciona según el siguiente método: Primero, vacuumlo construye una tabla temporal que contiene todos los OIDs de los objetos grandes en la base de datos seleccionada. Luego, escanea todas las columnas de la base de datos que son de tipo oid o lo, y elimina las entradas coincidentes de la tabla temporal. (Nota: Solo se consideran los tipos con estos nombres; en particular, los dominios sobre ellos no se consideran). Las entradas restantes en la tabla temporal identifican los LO huérfanos. Estos se eliminan.
