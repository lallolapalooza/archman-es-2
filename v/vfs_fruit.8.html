VFS_FRUIT(8) Herramientas de administración del sistema VFS_FRUIT(8)

NOMBRE

vfs_fruit - Interoperabilidad mejorada con OS X y Netatalk

SINOPSIS

objetos vfs = fruit

DESCRIPCIÓN

Este módulo VFS forma parte de la suite samba(7).

El módulo vfs_fruit proporciona una compatibilidad mejorada con los clientes SMB de Apple y una interoperabilidad con un servidor de archivos Netatalk 3 AFP.

El módulo debe apilarse con vfs_catia si se habilita la conversión de caracteres y debe apilarse con vfs_streams_xattr, ver la sección de ejemplos para la configuración correcta.

El módulo habilita el soporte de flujos de datos alternativos (ADS) para un recurso compartido, intercepta los flujos especiales de OS X "AFP_AfpInfo" y "AFP_Resource" y los maneja de forma especial. Todos los demás flujos con nombre se delegan a vfs_streams_xattr, que debe cargarse junto con vfs_fruit.

Tenga cuidado al mezclar recursos compartidos con y sin vfs_fruit. Los clientes OS X negocian las extensiones de protocolo SMB2 AAPL en el primer tcon, por lo que mezclar recursos compartidos con y sin fruit deshabilitará globalmente AAPL si el primer tcon es sin fruit.

Tener recursos compartidos con soporte ADS habilitado para clientes OS X merece la pena porque se asemeja al comportamiento de la propia implementación del servidor SMB de Apple y evita ciertas degradaciones severas del rendimiento causadas por la semántica de sensibilidad a mayúsculas y minúsculas de Samba.

La metadata de OS X y el fork de recursos se pueden almacenar de una manera compatible con Netatalk 3 estableciendo fruit:resource = file y fruit:metadata = netatalk.

OS X mapea los caracteres ilegales de NTFS al rango privado de Unicode en las solicitudes SMB. Al establecer fruit:encoding = native, todos los caracteres mapeados se convierten a caracteres ASCII nativos.

Finalmente, los modos de acceso compartido se verifican opcionalmente contra los modos de compartición AFP de Netatalk estableciendo fruit:locking = netatalk.

Este módulo no es apilable más allá de lo descrito en esta página del manual.

OPCIONES GLOBALES

Las siguientes opciones deben configurarse en la sección global smb.conf y no tendrán efecto cuando se configuren por recurso compartido.

fruit:aapl = sí | no

Una opción global para habilitar la extensión SMB2+ de Apple con nombre en clave AAPL. Por defecto sí. Esta extensión mejora varias deficiencias al conectarse desde Macs:
•La enumeración de directorios se enriquece con metadatos del sistema de archivos relevantes para Mac (modo UNIX, FinderInfo, tamaño del fork de recursos y permiso efectivo), como resultado, el cliente Mac no necesita obtener estos metadatos individualmente por entrada de directorio, lo que resulta en un aumento de rendimiento a menudo tremendo.
•La capacidad de consultar y modificar el modo UNIX de las entradas de directorio.
Hay un conjunto de opciones por recurso compartido que entran en juego cuando fruit:aapl está habilitado. Estas opciones, listadas a continuación, se pueden usar para deshabilitar el cálculo de metadatos específicos de Mac en el contexto de enumeración de directorios, todas están habilitadas por defecto:
•readdir_attr:aapl_rsize = sí | no
•readdir_attr:aapl_finder_info = sí | no
•readdir_attr:aapl_max_access = sí | no
Consulte a continuación una descripción de estas opciones.

fruit:nfs_aces = sí | no

Una opción global para habilitar el soporte para consultar y modificar el modo UNIX de las entradas de directorio a través de los ACE de NFS, por defecto sí.

fruit:copyfile = sí | no

Una opción global para habilitar el ioctl específico de OS X copychunk que solicita una copia de un archivo completo junto con todos los metadatos adjuntos.

ADVERTENCIA: la solicitud copyfile bloquea al cliente mientras el servidor realiza la copia.

El valor predeterminado es no.

fruit:model = MacSamba

Esta opción define la cadena del modelo dentro de la extensión AAPL y determinará la apariencia del icono que representa al servidor Samba en la ventana del Finder.

El valor predeterminado es MacSamba.

OPCIONES

Las siguientes opciones se pueden configurar tanto en la sección global smb.conf como por recurso compartido.

fruit:resource = [ file | xattr | stream ]

Controla dónde se almacena el fork de recursos de OS X.

Debido a un error ortográfico en todas las versiones de Samba anteriores a 4.6.0, esta opción también se puede dar como fruit:ressource, es decir, con dos s.

Ajustes:

•file (predeterminado) - usa un archivo ._ AppleDouble compatible con OS X y Netatalk
•xattr - usa un xattr, requiere un sistema de archivos con soporte xattr grande y una API de E/S de archivos compatible con xattrs, esto se reduce a Solaris y sus derivados y ZFS
•stream (experimental) - pasa el flujo al siguiente módulo en la pila VFS. Advertencia: esta opción no debe usarse con el módulo streams_xattr debido a las limitaciones de tamaño de los atributos extendidos de la mayoría de los sistemas de archivos.

fruit:time machine = [ sí | no ]

Controla si el soporte de Time Machine a través de la capacidad de volumen FULLSYNC se anuncia a los clientes.
•sí - Habilita el soporte de Time Machine para este recurso compartido. También registra el recurso compartido con mDNS en caso de que Samba esté compilado con soporte mDNS.
•no (predeterminado) Deshabilita el anuncio de soporte de Time Machine.
Esta opción aplica la siguiente configuración por recurso compartido (o para todos los recursos compartidos si se habilita globalmente):
•durable handles = yes
•kernel oplocks = no
•kernel share modes = no
•posix locking = no

fruit:time machine max size = TAMAÑO [K|M|G|T|P]

Útil para Time Machine: limita el tamaño del disco anunciado, evitando así que Time Machine utilice todo el espacio real del disco para la copia de seguridad. La opción toma un número más una unidad opcional.

IMPORTANTE: Este es un cálculo aproximado que solo tiene en cuenta el contenido de las imágenes sparsebundle de Time Machine. Por lo tanto, NO DEBE usar este volumen para almacenar contenido adicional cuando utilice esta opción, ya que no se contabilizaría.

El cálculo funciona leyendo el tamaño de las bandas del archivo Info.plist XML de la sparsebundle, leyendo el directorio bands/ contando el número de archivos de bandas y luego multiplicando uno con el otro.

fruit:metadata = [ stream | netatalk ]

Controla dónde se almacena el flujo de metadatos de OS X:
•netatalk (predeterminado) - usa xattr compatible con Netatalk
•stream - pasa el flujo al siguiente módulo en la pila VFS

fruit:locking = [ netatalk | none ]

•none (predeterminado) - sin bloqueo entre protocolos
•netatalk - usa bloqueo entre protocolos con Netatalk

fruit:encoding = [ native | private ]

Controla cómo se almacenan en el sistema de archivos el conjunto de caracteres ASCII ilegales de NTFS, comúnmente utilizados por los clientes OS X.

Importante: se sabe que esto no funciona completamente con fruit:metadata=stream o fruit:resource=stream.

•private (predeterminado) - almacena los caracteres tal como los codifica el cliente OS X: mapeados al rango privado de Unicode
•native - almacena los caracteres con su valor ASCII nativo. Importante: esta opción requiere el uso de vfs_catia en la pila del módulo VFS, como se muestra en la sección de ejemplos.

fruit:veto_appledouble = sí | no

Nota: esta opción solo se aplica cuando fruit:resource está configurado como file (el valor predeterminado).

Cuando fruit:resource está configurado como file, vfs_fruit puede crear archivos ._ AppleDouble. Esta opción controla si estos archivos ._ AppleDouble se vetan, lo que impide que el cliente acceda a ellos.

Vetar archivos ._ puede romper algunas aplicaciones, por ejemplo, la extracción de archivos ZIP de Mac desde clientes Mac falla, ya que contienen archivos ._. rsync tampoco podrá sincronizar archivos que comiencen con guiones bajos, ya que los archivos temporales que utiliza para ellos comenzarán con ._ y, por lo tanto, no se podrán crear.

Establecer esta opción en falso solucionará esto, pero la fuga de abstracción de exponer los archivos ._ creados internamente

vfs_fruit(8) — Arch Linux man pages

NAME

vfs_fruit - Samba VFS module

SYNOPSIS

    vfs objects = fruit streams_xattr
    fruit:resource = (anonymous | netatalk | macintosh | auto)
    fruit:metadata = (auto | netatalk | macintosh)
    fruit:locking = (auto | netatalk | macintosh)
    fruit:encoding = (auto | native | fist | off)
    fruit:timecode = yes | no
    fruit:stdclone = yes | no
    fruit:aapl_rsize = yes | no
    fruit:aapl_finder_info = yes | no
    fruit:aapl_max_access = yes | no
    fruit:wipe_intentionally_left_blank_rfork = yes | no
    fruit:delete_empty_adfiles = yes | no
    fruit:zero_file_id = yes | no
    fruit:convert_adouble = yes | no
    fruit:validate_afpinfo = yes | no
    fruit:posix_opens = yes | no
    fruit:ignore_zero_aces = yes | no

DESCRIPTION

The fruit VFS module is designed to provide improved support for Apple macOS and Mac OS X clients. It implements the extensions described in the Samba-CIFS-Mimicry document (available online) to provide features like resource forks, extended metadata, and atomic copy operations.

To enable the fruit module, you must also enable the streams_xattr module. The order is important: 

        vfs objects = fruit streams_xattr
or 
        vfs objects = streams_xattr fruit
The latter is recommended for ensuring the streams_xattr module correctly initializes before fruit. The fruit module relies on streams_xattr for storing AppleDouble data in extended attributes.

This module has a number of parameters that can be set in the [global] section or per-share.

GLOBAL OPTIONS

fruit:resource
This parameter controls how resource forks are handled. Resource forks are a special type of file metadata used by classic Mac OS and early Mac OS X.
anonymous
Resource forks are stored as anonymous extended attributes. This is the default.
netatalk
Resource forks are stored using the Netatalk (Apple Filing Protocol) extended attribute namespace. This is compatible with Netatalk servers and may provide better interoperability with some AFP clients.
macintosh
Resource forks are stored in a special AppleDouble format within the file itself. This is the most compatible option for macOS clients but may not be compatible with other systems.
auto
Automatically detect the resource fork format based on client negotiation. This is generally the recommended setting.
The default is auto.
fruit:metadata
This parameter controls how extended metadata (like Finder comments, icon, etc.) is handled.
auto
Automatically detect the metadata format based on client negotiation. This is the default.
netatalk
Use the Netatalk extended attribute namespace for metadata.
macintosh
Use the AppleDouble format for metadata.
fruit:locking
This parameter controls how file locking is handled. macOS uses a specific locking mechanism that can interfere with standard POSIX or Windows locking.
auto
Automatically enable the macOS compatible locking mechanism if the client supports it. This is the default.
netatalk
Use the Netatalk locking mechanism.
macintosh
Use the macOS locking mechanism directly.
fruit:encoding
This parameter controls the character encoding used for filenames.
auto
Use the encoding negotiated with the client. This is the default.
native
Use the native filesystem encoding (e.g., UTF-8 on most modern systems).
fist
Use the FIST (File System Translation) encoding, which is typically UTF-8.
off
Disable character encoding translation. This can lead to Mojibake if the client and server use different encodings.
fruit:timecode
Set to yes to enable the translation of mtime and ctime to Macintosh timecodes. This can improve compatibility with some Mac applications that rely on specific timestamp semantics.

The default is no.

fruit:stdclone
Set to yes to enable the "atomic copy" extension, which allows macOS clients to perform efficient file copies. This requires the streams_xattr VFS module to be enabled.

The default is yes.

fruit:aapl_rsize
Return resource fork size in SMB2 FIND responses.

The default is yes.

fruit:aapl_finder_info
Return FinderInfo in SMB2 FIND responses.

The default is yes.

fruit:aapl_max_access
Return the user's effective maximum permissions in SMB2 FIND responses. This is an expensive computation, setting this to off pretends the use has maximum effective permissions.

The default is yes.

fruit:wipe_intentionally_left_blank_rfork
Whether to wipe Resource Fork data that matches the special 286 bytes sized placeholder blob that macOS client create on occasion. The blob contains a string “This resource fork intentionally left blank”, the remaining bytes being mostly zero. There being no one use of this data, it is probably safe to discard it. When this option is enabled, this module truncates the Resource Fork stream to 0 bytes.

The default is no.

fruit:delete_empty_adfiles
Whether to delete empty AppleDouble files. Empty means that the resource fork entry in the AppleDouble files is of size 0, or the size is exactly 286 bytes and the content matches a special boilerplate resource fork created my macOS.

The default is no.

fruit:zero_file_id
Whether to return zero to queries of on-disk file identifier if the client has negotiated AAPL.

Mac applications and / or the Mac SMB client code expect the on-disk file identifier to have the semantics of HFS+ Catalog Node Identifier (CNID). Samba provides File-IDs based on a file's inode number which gets recycled across file creation and deletion and can therefore not be used for Mac client. Returning a file identifier of zero causes the Mac client to stop using and trusting the file id returned from the server.

The default is yes.

fruit:convert_adouble
Whether an attempt shall be made to convert ._ AppleDouble sidecar files to native streams (xattrs when using vfs_streams_xattr). The main use case for this conversion is transparent migration from a server config without streams support where the macOS client created those AppleDouble sidecar files.

The default is yes.

fruit:validate_afpinfo
Apple clients use the AFP_AfpInfo stream to store structured file metadata. As part of the marshaled data stored in the stream the first eight bytes contain some header information. Apple's SMB server as well as Samba will validate this header bytes processing a client write request on this stream, and, if the validation fails, fail the write. While this validation is generally correct, in some data migration scenarios clients may try to migrate data from 3rd-party SMB servers to Samba servers where the header information is broken for whatever reason. To allow migration and header fix-up in these scenarios, the validation can be temporarily disabled by setting this option to no.

The default is yes.

fruit:posix_opens
When fruit:posix_opens is set to yes, vfs_fruit will internally translate all filesystem semantics to use POSIX behaviour instead of Windows behaviour. As Macs are closer to POSIX than Windows with regard to filesystem semantics, this improves access semantics for a lot of corner cases.

The default is yes.

fruit:ignore_zero_aces
When fruit:ignore_zero_aces is enabled, attempts to modify filesystem permissions fail if the ACL sent over the wire contains no ACEs. This is completely valid client behaviour, but it means subsequently no further access is possible to the file, unless permissions get fixed by an administrator.

This problematic behaviour has been reported for latest macOS versions and this new option allows to work around it.

The default is yes.

EXAMPLES

        [share]
	vfs objects = catia fruit streams_xattr
	fruit:resource = file
	fruit:metadata = netatalk
	fruit:locking = netatalk
	fruit:encoding = native
