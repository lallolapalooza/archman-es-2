NOMBRE

VCL-BACKENDS(7) - Configuración de Backends

DEFINICIÓN DE BACKEND

Una declaración de backend crea e inicializa un objeto de backend con nombre. Una declaración comienza con la palabra clave backend seguida por el nombre del backend. La declaración real está entre llaves, en formato clave/valor:

backend nombre {
    .atributo1 = valor;
    .atributo2 = valor;
    [...]
}

Si hay un backend llamado default, se utilizará a menos que se especifique explícitamente otro backend. Si no se llama a ningún backend default, el primer backend en el programa VCL se convierte en el predeterminado.

Si solo se utilizan backends dinámicos creados por VMODs, se puede especificar un backend vacío, que siempre falla (503):

backend default none;

Un backend debe especificarse con el atributo .host o .path, pero no ambos. Todos los demás atributos tienen valores predeterminados.

ATRIBUTO .HOST

Para especificar un backend en red, .host acepta una dirección IPv4/IPv6 numérica o un nombre de dominio que se resuelva a como máximo una dirección IPv4 y una IPv6:

.host = "127.0.0.1";
.host = "[::1]:8080";
.host = "example.com:8081";
.host = "example.com:http";

ATRIBUTO .PORT

El número de puerto TCP o el nombre del servicio se puede especificar como parte de .host, como se muestra arriba, o por separado usando el atributo .port:

.port = "8081";
.port = "http";

ATRIBUTO .PATH

La ruta absoluta a un socket de dominio Unix(4) de un backend local:

.path = "/var/run/http.sock";

o, donde esté disponible, @ seguido del nombre de un socket abstracto de un backend local:

.path = "@mybackend";

Se emitirá una advertencia si el socket uds-socket no existe cuando se cargue el VCL. Esto hace posible iniciar el proceso que escucha en UDS, o establecer los permisos del archivo de socket después.

Si el socket uds-socket no existe o los permisos lo deniegan, los intentos de conexión fallarán.

ATRIBUTO .HOST_HEADER

Una cabecera Host para añadir a las sondas y a las solicitudes regulares del backend si no tienen dicha cabecera:

.host_header = "example.com";

ATRIBUTOS DE TIEMPO DE ESPERA

Estos atributos controlan la paciencia de varnishd durante las recuperaciones del backend:

.connect_timeout = 1.4s;
.first_byte_timeout = 20s;
.between_bytes_timeout = 10s;

Los valores predeterminados provienen de parámetros con los mismos nombres, consulte varnishd(1).

ATRIBUTO .MAX_CONNECTIONS

Limita cuántas conexiones simultáneas puede abrir varnish al backend:

.max_connections = 1000;

ATRIBUTO .WAIT_LIMIT

Número máximo de transacciones que pueden ponerse en cola esperando que una conexión de backend esté disponible:

.wait_limit = 1000;

Tenga en cuenta que esta función debe usarse con precaución, ya que puede hacer que los hilos se acumulen y aumenten los tiempos de respuesta.

Por defecto, es el parámetro backend_wait_limit de varnishd(1).

ATRIBUTO .WAIT_TIMEOUT

Cuando una transacción se pone en cola esperando que una conexión de backend esté disponible (ver .wait_limit), este es el tiempo que la transacción esperará antes de rendirse:

.wait_timeout = 1s;

Se recomienda encarecidamente no establecerlo nunca en más de un par de segundos.

Por defecto, es el parámetro backend_wait_timeout de varnishd(1).

ATRIBUTO .PROXY_HEADER

Enviar una cabecera del protocolo PROXY a los clientes con los valores de client.ip y server.ip:

.proxy_header = 2;

Los valores permitidos son uno y dos, dependiendo de la versión del protocolo PROXY que desee.

Nota: esta configuración provocará que las conexiones de backend se utilicen para una sola solicitud. Por lo tanto, se debe tener especial cuidado para evitar fallos en las conexiones de backend con EADDRNOTAVAIL debido a que no hay puertos locales disponibles. Las opciones posibles son:

  • Usar conexiones de backend adicionales a direcciones IP o puertos TCP adicionales
  • Aumentar el número de puertos disponibles (sysctl de Linux net.ipv4.ip_local_port_range)
  • Reutilizar puertos de conexión de backend tempranamente (sysctl de Linux net.ipv4.tcp_tw_reuse)

ATRIBUTO .PREAMBLE

Enviar un BLOB en todas las conexiones recién abiertas al backend:

.preamble = :SGVsbG8gV29ybGRcbgo=:;

ATRIBUTO .VIA

Nombre de otro backend de tipo proxy a través del cual realizar la conexión al backend de destino usando el protocolo PROXY2, por ejemplo:

backend proxy {
  .path = "/path/to/proxy2_endpoint";
}
backend destination {
  .host = "1.2.3.4";
  .via = proxy;
}

El backend proxy también puede usar una definición .host/.port en lugar de .path.

No se admite el uso del atributo .path para el backend de destino.

El atributo .via no está relacionado con .proxy_header. Si se usan ambos, se envía una segunda cabecera según la especificación de .proxy_header.

A menos que se especifique para destino, los atributos connect_timeout, first_byte_timeout y between_bytes_timeout se copian de proxy a destino.

A partir de esta versión, el backend proxy utilizado con .via no puede ser un director, no puede usar él mismo .via (error: Cannot stack .via backends) y el protocolo se fija en PROXY2.

Detalle de implementación:

Si se usa .via = <proxy>, se crea un preámbulo PROXY2 con la información de la dirección del backend de destino como dst_addr/dst_port y, opcionalmente, otros TLV. Luego, se realiza la conexión al punto final del backend proxy (path o host/port). Esto es técnicamente equivalente a especificar un backend destination_via_proxy con un atributo .preamble que contenga el preámbulo PROXY2 apropiado para el backend de destino.

ATRIBUTO .AUTHORITY

La autoridad HTTP a usar al conectarse a este backend. Si no se establece, se utilizan .host_header o .host.

.authority = "" deshabilita el envío de una autoridad.

.authority no puede ser una dirección IP.

Un colon y cualquier cosa que le siga (lo que indica un puerto) es

ATTRIBUTE .VIA

Este atributo se usa para especificar el encabezado Via que se agregará a las solicitudes salientes. El valor del encabezado Via se genera a partir de la cadena proporcionada, agregando información del proxy.

Ejemplo:

backend default {
    .url = "http://localhost:8080";
    .via = "Varnish VCL";
}

Esto dará como resultado un encabezado Via similar a:

Via: 1.1 Varnish (VCL)

ATTRIBUTE .AUTHORITY

Este atributo se usa para especificar el valor del encabezado Authority que se agregará a las solicitudes salientes. El encabezado Authority se utiliza para la autenticación y la identificación del host de destino, especialmente en el contexto de HTTP/2 y proxies.

A partir de esta versión, el atributo solo es utilizado por las conexiones .via como un TLV (Type-Length-Value) PP2_TYPE_AUTHORITY en el preámbulo de PROXY2.

ATTRIBUTE .PROBE

Ver vcl-probe(7).
