VISUDO(8) Manual del Administrador del Sistema VISUDO(8)

NOMBRE

visudo — editar el archivo sudoers

SINOPSIS

visudo [-chIOPqsV] [[-f] sudoers]

DESCRIPCIÓN

visudo edita el archivo sudoers de forma segura, análogo a vipw(8). visudo bloquea el archivo sudoers contra ediciones simultáneas, realiza comprobaciones básicas de validez y verifica la sintaxis antes de instalar el archivo editado. Si el archivo sudoers está siendo editado actualmente, recibirá un mensaje para intentarlo más tarde.

Si el archivo sudoers no existe, se creará a menos que el editor salga sin escribir en el archivo.

visudo analiza el archivo sudoers después de la edición y no guardará los cambios si hay un error de sintaxis. Al encontrar un error, visudo imprimirá un mensaje indicando el(los) número(s) de línea donde ocurrió el error y el usuario recibirá el prompt “¿Ahora qué?”. En este punto, el usuario puede ingresar ‘e’ para re-editar el archivo sudoers, ‘x’ para salir sin guardar los cambios, o ‘Q’ para salir y guardar los cambios. La opción ‘Q’ debe usarse con extrema precaución porque si visudo cree que hay un error de sintaxis, sudo también lo hará. Si se ingresa ‘e’ para editar el archivo sudoers después de que se haya detectado un error de sintaxis, el cursor se colocará en la línea donde ocurrió el error (si el editor soporta esta característica).

Hay dos configuraciones de sudoers que determinan qué editor ejecutará visudo.

editor
Una lista de editores separada por dos puntos (‘:’) permitidos para usarse con visudo. visudo elegirá el editor que coincida con la variable de entorno SUDO_EDITOR, VISUAL o EDITOR del usuario si es posible, o el primer editor en la lista que exista y sea ejecutable. sudo no preserva las variables de entorno SUDO_EDITOR, VISUAL o EDITOR a menos que estén presentes en la lista env_keep o la opción env_reset esté deshabilitada en el archivo sudoers. El editor por defecto es ~, que se puede establecer en tiempo de compilación mediante la opción de configuración --with-editor.
env_editor
Si está configurado, visudo usará el valor de las variables de entorno SUDO_EDITOR, VISUAL o EDITOR antes de recurrir a la lista de editores predeterminada. visudo se ejecuta típicamente como root, por lo que esta opción puede permitir que un usuario con privilegios de visudo ejecute comandos arbitrarios como root sin iniciar sesión. Una alternativa es colocar una lista separada por dos puntos de editores “seguros” en la variable editor. visudo solo usará SUDO_EDITOR, VISUAL o EDITOR si coinciden con un valor especificado en editor. Si el flag env_reset está habilitado, las variables de entorno SUDO_EDITOR, VISUAL y/o EDITOR deben estar presentes en la lista env_keep para que el flag env_editor funcione cuando se invoca visudo a través de sudo. El valor predeterminado es on, que se puede establecer en tiempo de compilación mediante la opción de configuración --with-env-editor.

Las opciones son las siguientes:

-c, --check
Habilita el modo solo comprobar. El archivo sudoers existente (y cualquier otro archivo que incluya) será verificado en busca de errores de sintaxis. Si no se especificó la ruta al archivo sudoers, visudo también verificará la propiedad y los permisos del archivo (ver las opciones -O y -P). Se imprimirá un mensaje en la salida estándar describiendo el estado de sudoers a menos que se haya especificado la opción -q. Si la comprobación se completa con éxito, visudo saldrá con un valor de 0. Si se encuentra un error, visudo saldrá con un valor de 1.
-f sudoers, --file=sudoers
Especifica una ubicación alternativa para el archivo sudoers, ver más abajo. A partir de la versión 1.8.27, la ruta de sudoers se puede especificar sin usar la opción -f.
-h, --help
Muestra un breve mensaje de ayuda en la salida estándar y sale.
-I, --no-includes
Deshabilita la edición de archivos de inclusión a menos que haya un error de sintaxis preexistente. Por defecto, visudo editará el archivo principal sudoers y cualquier archivo incluido mediante directivas @include o #include. Los archivos incluidos mediante @includedir o #includedir nunca se editan a menos que contengan un error de sintaxis.
-O, --owner
Impone la propiedad predeterminada (usuario y grupo) del archivo sudoers. En modo de edición, el propietario del archivo editado se establecerá en el valor predeterminado. En modo de verificación (-c), se informará un error si el propietario es incorrecto. Esta opción está habilitada por defecto si no se especificó el archivo sudoers.
-P, --perms
Impone los permisos predeterminados (modo) del archivo sudoers. En modo de edición, los permisos del archivo editado se establecerán en el valor predeterminado. En modo de verificación (-c), se informará un error si los permisos del archivo son incorrectos. Esta opción está habilitada por defecto si no se especificó el archivo sudoers.
-q, --quiet
Habilita el modo silencioso. En este modo, no se imprimen detalles sobre los errores de sintaxis. Esta opción solo es útil cuando se combina con la opción -c.
-s, --strict
Habilita la comprobación estricta del archivo sudoers. Si se hace referencia a un alias pero no está definido o si hay un ciclo en un alias, visudo lo considerará un error de sintaxis. No es posible diferenciar entre un alias y un nombre de host o nombre de usuario que consista únicamente en letras mayúsculas, dígitos y el carácter de subrayado (‘_’).
-V, --version
Imprime las versiones de la gramática de visudo y sudoers y sale.

Modo de solo verificación y argumentos del plugin de sudoers

En visudo (check-only mode only), ‘-’ puede usarse para indicar que sudoers se leerá desde la entrada estándar. Debido a que la política se evalúa en su totalidad, no es suficiente verificar un archivo de inclusión de sudoers individual en busca de errores de sintaxis.

Depuración y argumentos del plugin sudoers

visudo versiones 1.8.4 y posteriores admiten un marco de depuración flexible que se configura a través de líneas Debug en el archivo sudo.conf(5).

A partir de sudo 1.8.12, visudo también analizará los argumentos del plugin sudoers para anular el nombre de ruta, el ID de usuario, el ID de grupo y el modo de archivo predeterminados de sudoers. Estos argumentos, si están presentes, deben enumerarse después de la ruta al plugin (es decir, después de sudoers.so). Se pueden especificar varios argumentos, separados por espacios en blanco. Por ejemplo:

Plugin sudoers_policy sudoers.so sudoers_mode=0400

Se admiten los siguientes argumentos:

sudoers_file=ruta
El argumento sudoers_file puede usarse para anular la ruta predeterminada al archivo sudoers.
sudoers_uid=id-de-usuario
El argumento sudoers_uid puede usarse para anular el propietario predeterminado del archivo sudoers. Debe especificarse como un ID de usuario numérico.
sudoers_gid=id-de-grupo
El argumento sudoers_gid puede usarse para anular el grupo predeterminado del archivo sudoers. Debe especificarse como un ID de grupo numérico (no un nombre de grupo).
sudoers_mode=modo
El argumento sudoers_mode puede usarse para anular el modo de archivo predeterminado para el archivo sudoers. Debe especificarse como un valor octal.

Para obtener más información sobre la configuración de sudo.conf(5), consulte su manual.

AMBIENTE

Las siguientes variables de entorno pueden ser consultadas según el valor de la configuración de editor y env_editor de sudoers:

SUDO_EDITOR
Invocado por visudo como el editor a usar.
VISUAL
Usado por visudo si SUDO_EDITOR no está configurado.
EDITOR
Usado por visudo si ni SUDO_EDITOR ni VISUAL están configurados.

ARCHIVOS

Configuración del frontend de Sudo.

DIAGNÓSTICOS

Además de informar errores de sintaxis de sudoers, visudo puede generar los siguientes mensajes:

sudoers file busy, try again later.
Alguien más está editando actualmente el archivo sudoers.
/etc/sudoers: Permission denied
No ejecutaste visudo como root.
you do not exist in the passwd database
Tu ID de usuario no aparece en la base de datos passwd del sistema.
Warning: {User,Runas,Host,Cmnd}_Alias referenced but not defined
O estás intentando usar un alias {User,Runas,Host,Cmnd}_Alias no declarado o tienes un nombre de usuario o host listado que consiste únicamente en letras mayúsculas, dígitos y el guion bajo (‘_’). En este último caso, puedes ignorar las advertencias (sudo no se quejará). El mensaje está prefijado con el nombre de ruta del archivo sudoers y el número de línea donde se usó el alias no definido. En el modo -s (estricto), estos son errores, no advertencias.
Warning: unused {User,Runas,Host,Cmnd}_Alias
El alias {User,Runas,Host,Cmnd}_Alias especificado se definió pero nunca se usó. El mensaje está prefijado con el nombre de ruta del archivo sudoers y el número de línea donde se definió el alias no utilizado. Es posible que desees comentar o eliminar el alias no utilizado.
Warning: cycle in {User,Runas,Host,Cmnd}_Alias
El alias {User,Runas,Host,Cmnd}_Alias especificado incluye una referencia a sí mismo, ya sea directa o a través de un alias que incluye. El mensaje está prefijado con el nombre de ruta del archivo sudoers y el número de línea donde se detectó el ciclo. Esto es solo una advertencia, a menos que visudo se ejecute en modo -s (estricto), ya que sudo ignorará los ciclos al analizar el archivo sudoers.
ignoring editor backup file
Al procesar un @includedir o #includedir, se encontró un archivo con un nombre que termina en ‘~’ o .bak. Dichos archivos son omitidos por sudo y visudo.
ignoring file name containing '.'
Al procesar un @includedir o #includedir, se encontró un archivo con un nombre que contiene un carácter ‘.’. Dichos archivos son omitidos por sudo y visudo.
unknown defaults entry "name"
El archivo sudoers contiene una configuración de Defaults no reconocida por visudo.

ERRORES

Si cree que ha encontrado un error en visudo, puede presentar un informe de error en la base de datos de errores de sudo, https://bugzilla.sudo.ws/, o abrir un ticket en https://github.com/sudo-project/sudo/issues. Si prefiere usar correo electrónico, los mensajes se pueden enviar a la lista de correo de sudo-workers, https://www.sudo.ws/mailman/listinfo/sudo-workers (pública) o <sudo@sudo.ws> (privada).

Por favor, no informe de vulnerabilidades de seguridad a través de tickets públicos de GitHub, Bugzilla o listas de correo. En su lugar, infórmelos por correo electrónico a <Todd.Miller@sudo.ws>. Puede cifrar su mensaje con PGP si lo desea, utilizando la clave que se encuentra en https://www.sudo.ws/dist/PGPKEYS.
