NOMBRE

vng - Ejecuta rápidamente kernels dentro de una instantánea virtualizada de tu sistema en vivo

SINOPSIS

vng [-h] [--version] [--run [RUN] | --build | --clean | --dump DUMP | --mcp] [--dry-run] [--skip-config] [--no-virtme-ng-init] [--empty-passwords] [--pin [PIN]] [--gdb] [--snaps] [--debug] [--kconfig] [--skip-modules] [--commit COMMIT] [--config CONFIG] [--configitem CONFIGITEM] [--compiler COMPILER] [--busybox PATH_TO_BUSYBOX] [--qemu QEMU] [--name NAME] [--user USER] [--shell BINARY] [--root ROOT] [--root-release ROOT_RELEASE] [--rw] [--force-9p] [--disable-microvm] [--disable-kvm] [--disable-monitor] [--cwd CWD] [--pwd] [--rodir RODIR] [--rwdir RWDIR] [--overlay-rwdir OVERLAY_RWDIR] [--cpus CPUS] [--memory MEMORY] [--numa MEM[,cpus=FIRST_CPU1[-LAST_CPU1]][,cpus=FIRST_CPU2[-LAST_CPU2]]...] [--numa-distance SRC,DST=VAL] [--balloon] [--network NETWORK] [--no-dhcp] [--net-mac-address NET_MAC_ADDRESS] [--disk PATH] [--exec EXEC] [--append APPEND] [--force-initramfs] [--sound] [--graphics] [--verbose] [--quiet] [--qemu-opts QEMU_OPTS] [--build-host BUILD_HOST] [--build-host-exec-prefix BUILD_HOST_EXEC_PREFIX] [--build-host-vmlinux] [--arch ARCH] [--cross-compile CROSS_COMPILE] [--force] [--nvgpu [GPU PCI Address]] [--console [PORT]] [--console-client [PORT]] [--ssh [PORT]] [--ssh-client [PORT]] [--ssh-tcp] [--remote-cmd COMMAND] [--systemd] [envs ...]

DESCRIPCIÓN

Construye y ejecuta kernels dentro de una instantánea virtualizada de tu sistema en vivo

envs
Variables adicionales de Makefile

OPCIONES

--version, -V
muestra el número de versión del programa y sale
--dry-run
Solo muestra los comandos sin ejecutarlos realmente.
--skip-config, -s
[obsoleto] No regenerar el archivo .config del kernel
--no-virtme-ng-init
Utilizar virtme-init de bash como fallback (útil para depuración/desarrollo)
--empty-passwords
Usar contraseñas vacías para todos los usuarios
--pin [PIN], -P [PIN]
Fija cada hilo de vCPU de QEMU a una CPU del host distinta. Si se proporciona sin argumentos, se usan todas las CPUs del host. Si se proporciona con un argumento, debe ser una lista/rango de CPUs (p. ej., 0,1,3-5,9). NOTA: solo se puede fijar una instancia de virtme-ng a la vez, fijar múltiples instancias de virtme-ng no es compatible aún.
--gdb
Adjunta una sesión de depuración a una instancia en ejecución iniciada con --debug
--snaps
Permitir la ejecución de snaps dentro de virtme-ng
--debug
Inicia la instancia con la depuración habilitada (permite generar volcados de fallos)
--kconfig, -k
Solo anula el archivo .config del kernel sin construir/ejecutar nada
--skip-modules, -S
Realiza una compilación muy rápida omitiendo módulos externos (sin soporte para módulos externos)
--commit COMMIT, -c COMMIT
Usa un kernel identificado por un ID de commit, etiqueta o rama específico
--config CONFIG, --custom CONFIG, -f CONFIG
Usa uno (o más) fragmentos específicos del archivo .config del kernel para anular la configuración predeterminada
--configitem CONFIGITEM
añade un CONFIG_ITEM=val, después de --config <fragmentos>, estos anulan la configuración anterior
--compiler COMPILER
[obsoleto] Compilador a usar como CC al construir el kernel. Por favor, establece las variables CC= y HOSTCC= en la línea de comandos de virtme-ng en su lugar.
--busybox PATH_TO_BUSYBOX
Usa el binario busybox especificado
--qemu QEMU
Usa el binario QEMU especificado
--name NAME
Establece el nombre del host del invitado y la opción -name de qemu
--user USER
Cambia el usuario dentro del invitado (el predeterminado es el mismo usuario que el del host)
--shell BINARY
Anula el shell predeterminado del usuario
--root ROOT
Pasa un chroot específico para usar dentro del kernel virtualizado (útil con --arch)
--root-release ROOT_RELEASE
Usa una versión de Ubuntu objetivo para crear un nuevo chroot (usado con --root)
--rw
Da acceso de lectura/escritura al invitado a su sistema de archivos raíz. ADVERTENCIA: ¡esto puede ser peligroso para el sistema de archivos del host!
--force-9p
Usa el sistema de archivos 9p heredado como rootfs
--disable-microvm
Evita usar la arquitectura QEMU "microvm" (solo en x86_64)
--disable-kvm
Evita usar virtualización de hardware / KVM
--disable-monitor
Deshabilita el monitor STDIO de QEMU
--cwd CWD
Cambia el directorio de trabajo del invitado (el predeterminado es el directorio de trabajo actual cuando sea posible)
--pwd
[obsoleto] --pwd se establece implícitamente por defecto
--rodir RODIR
Suministra un directorio de solo lectura al invitado. Usa --rodir=ruta o --rodir=rutainvitado=rutahuesped
--rwdir RWDIR
Suministra un directorio de lectura/escritura al invitado. Usa --rwdir=ruta o --rwdir=rutainvitado=rutahuesped
--overlay-rwdir OVERLAY_RWDIR
Suministra un directorio que es r/w para el invitado pero de solo lectura en el host. Usa --overlay-rwdir=ruta.
--cpus CPUS, -p CPUS
Establece el número de CPUs del invitado (opción -smp de qemu)
--memory MEMORY, -m MEMORY
Establece el tamaño de memoria del invitado (opción -m de qemu)
--numa MEM[,cpus=FIRST_CPU1[-LAST_CPU1]][,cpus=FIRST_CPU2[-LAST_CPU2]]...
Crea un nodo NUMA en el invitado. Usa esta opción varias veces para crear más nodos NUMA. El tamaño total de memoria asignado a los nodos NUMA debe coincidir con el tamaño de memoria del invitado (especificado con --memory/-m). Esta opción deshabilita implícitamente la arquitectura microvm.
--numa-distance SRC,DST=VAL
Establece una distancia de VAL entre el nodo NUMA SRC_NODE y DST_NODE. Usa esta opción varias veces para definir múltiples distancias entre nodos NUMA. Esta opción solo se usa junto con --numa.
--balloon
Permite al host solicitar al invitado que libere memoria
--network NETWORK, -n NETWORK
Habilita el acceso a la red: user, bridge(=<br>), loop
--no-dhcp
Deshabilita la configuración DHCP para las interfaces de red.
--net-mac-address NET_MAC_ADDRESS
La dirección MAC a asignar a la

OPCIONES

--root ROOT, -r ROOT
Monta el directorio ROOT como el sistema de archivos raíz de la máquina virtual. Si se especifica, se espera un sistema de archivos raíz ya creado.
--netdev NETDEV, -n NETDEV
Añade un dispositivo de red (por ejemplo, eth0) a la VM. El formato es `[mac=,hostip=,hostmac=]`. Por ejemplo: `--netdev tap,mac=52:54:00:12:34:56,hostip=192.168.1.100,hostmac=52:54:00:12:34:57`. Si la MAC no se especifica, se generará una aleatoria. Si se especifican hostip y hostmac, se configurará un puente de red. De lo contrario, se usará un dispositivo de red basado en TAP.
--ssh [IP]
Permite la conexión SSH a la VM. Si se proporciona una IP, intentará conectarse a esa IP. De lo contrario, generará una IP aleatoria y se conectará a ella.
--ssh-port PORT
Especifica el puerto para la conexión SSH.
--ssh-key KEY
Especifica la clave SSH a utilizar para la conexión.
--debug
Habilita el modo de depuración para una mayor salida de información.
--mem SIZE
Establece la cantidad de memoria RAM para la VM en MB.
--cpus NUM
Establece el número de CPUs para la VM.
--kernel KERNEL, -k KERNEL
Especifica la ruta al binario del kernel.
--initrd INITRD, -i INITRD
Especifica la ruta al archivo initrd.
--cmdline CMDLINE
Especifica la línea de comandos del kernel.
--virtio-gpu
Habilita el dispositivo virtio-gpu para una mejor salida gráfica.
--disable-kvm
Deshabilita el uso de KVM (Kernel-based Virtual Machine).
--enable-kvm
Habilita el uso de KVM (Kernel-based Virtual Machine).
--serial SERIAL
Configura el puerto serie. Ej: `tcp::4444,server,nowait` o `pty`.
--mac MAC
Establece la dirección MAC para la interfaz de red de la VM. Por ejemplo, 52:54:00:12:34:56. El último octeto se incrementará para los próximos dispositivos de red.
--disk RUTA, -D RUTA
Añade un archivo como disco virtio-scsi (se puede usar varias veces)
--exec EJEC, -e EJEC
Ejecuta un comando dentro del kernel y sale
--append ADICIONAL, -a ADICIONAL
Opciones adicionales de arranque del kernel (se pueden usar varias veces)
--force-initramfs
Usa un initramfs incluso si no es necesario
--sound
Habilita el dispositivo de audio (si la arquitectura lo soporta)
--graphics, -g
Muestra la salida gráfica en lugar de usar una consola.
--verbose, -v
Aumenta la verbosidad de la salida de la consola.
--quiet, -q
Anula el modo verboso (deshabilita --verbose).
--qemu-opts OPCIONES_QEMU, -o OPCIONES_QEMU
Argumentos adicionales para QEMU (se pueden usar varias veces) o agrupados: --qemu-opts='...'
--build-host SERVIDOR_BUILD
Realiza la compilación del kernel en un servidor remoto (se requiere acceso ssh)
--build-host-exec-prefix PREFIJO_EJEC_SERVIDOR_BUILD
Anteponer un comando (por ejemplo, chroot) al comando make ejecutado en el servidor de compilación remoto
--build-host-vmlinux
Copia vmlinux de vuelta desde el servidor de compilación
--arch ARQUITECTURA
Genera y prueba un kernel para una arquitectura específica (el valor por defecto es la arquitectura del host; si se establece, se usará con --root)
--cross-compile COMPILACION_CRUZADA
Establece el prefijo de compilación cruzada
--force
Fuerza el reinicio del repositorio git a la rama o commit objetivo (advertencia: esto puede descartar cambios no confirmados) y fuerza la anulación de la configuración del kernel
--nvgpu [DIRECCIÓN_PCI_GPU]
Añade una GPU NVIDIA de paso (passthrough)
--systemd
Ejecuta systemd como init (EXPERIMENTAL)

ACCIÓN

--run [EJECUCIÓN], -r [EJECUCIÓN]
Ejecuta un kernel especificado; --run puede aceptar uno de los siguientes argumentos: 1) nada (en este caso intentará arrancar el mismo kernel que se está ejecutando en el host), 2) un binario de kernel (como ./arch/x86/boot/bzImage), 3) un directorio (donde intentará encontrar un archivo binario de kernel válido), 4) una versión upstream, por ejemplo `vng --run v6.6.17` (en este caso vng descargará un kernel upstream precompilado del repositorio mainline de Ubuntu)
--build, -b
Compila el kernel en el directorio actual (o remotamente si se usa con --build-host)
--clean, -x
Limpia el repositorio del kernel (local o remoto si se usa con --build-host)
--dump VOLCADO, -d VOLCADO
Genera un volcado de memoria del kernel en ejecución (la instancia debe iniciarse con --debug)
--mcp
Inicia el servidor MCP (Model Context Protocol) para la integración con agentes de IA

CONSOLA REMOTA

--console [PUERTO]
Habilita un servidor para comunicarse posteriormente desde el host usando '--console-client'. Por defecto, se ofrecerá una consola simple usando una conexión VSOCK y 'socat' para el proxy.
--console-client [PUERTO]
Se conecta a una VM lanzada con la opción '--console' para control remoto.
--ssh [PUERTO]
Habilita el servidor SSH para comunicarse posteriormente desde el host usando '--ssh-client'.
--ssh-client [PUERTO]
Se conecta a una VM lanzada con la opción '--ssh' para control remoto.
--ssh-tcp
Usa TCP para la conexión SSH a la VM invitada
--remote-cmd COMANDO
Para iniciar en la VM un comando diferente al predeterminado (--server), o para lanzar este comando en lugar de un prompt (--client).

COMENTARIOS

virtme-ng es una herramienta que permite recompilar y probar un kernel de Linux de forma fácil y rápida, partiendo del código fuente. Permite recompilar el kernel en pocos minutos (en lugar de horas), luego el kernel se inicia automáticamente en un entorno virtualizado que es una copia exacta copy-on-write de tu sistema en vivo, lo que significa que cualquier cambio realizado en el entorno virtualizado no afecta al sistema host.

Para hacer esto, se produce una configuración mínima (con lo mínimo necesario para probar el kernel dentro de qemu), luego el kernel seleccionado se compila y se inicia automáticamente dentro de qemu, utilizando el sistema de archivos del host como una instantánea copy-on-write.

Esto significa que puedes destruir de forma segura todo el sistema de archivos, colgar el kernel, etc. sin afectar al host.

NOTA: Los kernels producidos con virtme-ng carecen de muchas características, para reducir al mínimo el tiempo de compilación y aun así proporcionarte un kernel utilizable capaz de ejecutar tus pruebas y experimentos.

virtme-ng se basa en virtme, escrito por Andy Lutomirski <luto@kernel.org>.
