NOMBRE

vgimportdevices — Añadir dispositivos para un VG al archivo de dispositivos.

SINOPSIS

vgimportdevices argumentos_opciones argumentos_posicionales
[ argumentos_opciones ]
-a|--all
   --auto
   --commandprofile Cadena
   --config Cadena
-d|--debug ...
   --devices PV
   --devicesfile Cadena
   --driverloaded y|n
   --foreign
-h|--help
   --journal Cadena
   --lockopt Cadena
   --longhelp
   --nohints
   --nolocking
   --profile Cadena
-q|--quiet ...
   --reportformat basic|json|json_std
   --rootvg
-S|--select Cadena
-t|--test
-v|--verbose ...
   --version
-y|--yes

DESCRIPCIÓN

vgimportdevices añade PVs de un VG al archivo de dispositivos. Esto es similar a usar lvmdevices --adddev para añadir cada PV al archivo de dispositivos individualmente. vgimportdevices también actualizará la metadatos del VG para incluir los IDs de dispositivo de cada PV. vgimportdevices creará un nuevo archivo de dispositivos si no existe.

Cuando se utiliza un archivo de dispositivos, el filtro regex se ignora, excepto en el caso de vgimportdevices, que aplicará el filtro regex al buscar los VG para importar al archivo de dispositivos. Usa vgimportdevices -a para importar todos los VG de un sistema al archivo de dispositivos.

USO

Añadir dispositivos de VG específicos al archivo de dispositivos.

vgimportdevices VG|Etiqueta|Select ...

[ -S|--select Cadena ]
[ --foreign ]
[ OPCIONES_COMUNES ]

vgimportdevices -a|--all

[ --foreign ]
[ OPCIONES_COMUNES ]

—

vgimportdevices --rootvg

OPCIONES

-a|--all
--auto
Esta opción se utiliza al importar automáticamente dispositivos para el VG raíz. La importación automática está pensada para hacerse una sola vez, en el primer arranque, para crear un archivo inicial system.devices para el VG raíz. Cuando se usa esta opción, el comando vgimportdevices --rootvg no hace nada si system.devices existe, o si el archivo auto-import-rootvg no existe (ambos en el directorio /etc/lvm/devices/).
--commandprofile Cadena
El perfil de comando a utilizar para la configuración del comando. Consulte lvm.conf(5) para obtener más información sobre los perfiles.
--config Cadena
Configuraciones para el comando. Estas anulan la configuración de lvm.conf(5). La cadena de argumentos utiliza el mismo formato que lvm.conf(5), o puede utilizar la sintaxis sección/campo. Consulte lvm.conf(5) para obtener más información sobre la configuración.
-d|--debug ...
Establece el nivel de depuración. Repetir de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados aparecerán como faltantes. Esta opción se puede repetir, o acepta una lista separada por comas de dispositivos. Esto anula el archivo de dispositivos.
--devicesfile Cadena
Un archivo que lista los dispositivos que LVM debe utilizar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración devices/devicesfile y devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si se establece en no, el comando no intentará utilizar device-mapper. Para pruebas y depuración.
--foreign
Reportar/mostrar VG extranjeros que de otro modo serían omitidos. Consulte lvmsystemid(7) para obtener más información sobre los VG extranjeros.
-h|--help
Muestra el texto de ayuda.
--journal Cadena
Registra información en el journal de systemd. Esta información es adicional a la información habilitada por la configuración de registro/journal de lvm.conf. command: registra información sobre el comando. output: registra la salida predeterminada del comando. debug: registra la depuración completa del comando.
--lockopt Cadena
Se utiliza para pasar opciones para casos especiales a lvmlockd. Consulte lvmlockd(8) para obtener más información.
--longhelp
Muestra el texto de ayuda extenso.
--nohints
No utilizar el archivo de sugerencias para localizar dispositivos para los PV. Un comando puede leer más dispositivos para encontrar PV cuando no se usan sugerencias. El comando aún realizará la invalidación estándar del archivo de sugerencias cuando sea apropiado.
--nolocking
Deshabilita el bloqueo. Úselo con precaución, comandos concurrentes pueden producir resultados incorrectos.
--profile Cadena
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
-q|--quiet ...
Suprime la salida y los mensajes de registro. Anula --debug y --verbose. Repetir una vez para suprimir también cualquier solicitud con la respuesta 'no'.
--reportformat basic|json|json_std
Anula el formato de salida actual para los informes, que se define globalmente por la configuración report/output_format en lvm.conf(5). basic es el formato original con columnas y filas. Si hay más de un informe por comando, cada informe se prefija con el nombre del informe para su identificación. json produce la salida del informe en formato JSON. json_std produce la salida del informe en formato JSON que es más compatible con el estándar JSON

NAME

vgimportdevices — Import devices for a VG

SYNOPSIS

vgimportdevices [-A| --autobackup y|n] [-f| --force] [-h| --help] [-t| --test] [-v| --verbose] [-y| --yes] {VG|-[G]VG} [Device...]

DESCRIPTION

This command imports devices for the specified VG. If no devices are specified, it will try to import all devices that are currently known to be part of the VG. The VG must be already present in the LVM metadata (e.g. via vgscan(8) or vgimport(8)).

This command is used to add VG devices that were previously not imported because they were missing at the time of VG import or scan.

A VG can be specified by name, UUID, or by using --uuid followed by the VG UUID.

The VG devices may be specified explicitly on the command line. If they are not, all known devices are scanned and imported. This is useful if the VG was created on another system and some of its devices are not yet present on the current system.

After a successful import, the VG and its LVs are available for use.

USAGE

The following options are available:

OPTIONS

-A|--autobackup y|n
Enable or disable the automatic backup of metadata after a successful operation. If n (for no), automatic metadata backup is disabled for this command. Default is y (yes), which means metadata is backed up if automatic backup is enabled in lvm.conf(5).
-f|--force
Force usage. For example, force the import of devices that might not be recognized by the system.
-h|--help
Display the help message and exit.
--rootvg
Import devices used for the root VG.
-S|--select String
Select objects for processing and reporting based on specified criteria. The criteria syntax is described by --select help and lvmreport(7). For reporting commands, one row is displayed for each object matching the criteria. See --options help for selectable object fields. Rows can be displayed with an additional "selected" field (-o selected) showing 1 if the row matches the selection and 0 otherwise. For non-reporting commands which process LVM entities, the selection is used to choose items to process.
-t|--test
Run in test mode. Commands will not update metadata. This is implemented by disabling all metadata writing but nevertheless returning success to the calling function. This may lead to unusual error messages in multi-stage operations if a tool relies on reading back metadata it believes has changed but hasn't.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

VG
Volume Group name. See lvm(8) for valid names.
Tag
Tag name. See lvm(8) for information about tag names and using tags in place of a VG, LV or PV.
Select
Select indicates that a required positional parameter can be omitted if the --select option is used. No arg appears in this position.
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.
