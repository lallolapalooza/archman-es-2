vmod_purge(3)

Paquete: varnish

Licencias: BSD-2-Clause

VMOD_PURGE(3) Manual de funciones de biblioteca VMOD_PURGE(3)

NOMBRE

vmod_purge - Módulo de purga de Varnish

SINOPSIS

import purge [as nombre] [from "ruta"]
INT hard()
INT soft(DURATION ttl, DURATION grace, DURATION keep)

DESCRIPCIÓN

vmod_purge contiene funciones que ofrecen un control más detallado que return(purge) de vcl_recv{}. Las funciones solo pueden llamarse desde vcl_hit{} o vcl_miss{} y, en general, deben usarse en ambas para garantizar que todas las variantes del mismo objeto sean atendidas.

EJEMPLO

sub vcl_recv {
    if (req.method == "PURGE") {
        if (client.ip !~ purge_acl) {
            return (synth(405));
        }
        return (hash);
    }
}
sub my_purge {
    set req.http.purged = purge.hard();
    if (req.http.purged == "0") {
        return (synth(404));
    }
    else {
        return (synth(200));
    }
}
sub vcl_hit {
    if (req.method == "PURGE") {
        call my_purge;
    }
}
sub vcl_miss {
    if (req.method == "PURGE") {
        call my_purge;
    }
}
sub vcl_synth {
    if (req.method == "PURGE") {
        if (req.http.purged) {
            set resp.http.purged = req.http.purged;
        }
        return (deliver);
    }
}

INT hard()

Esto es equivalente a return(purge) pero se llama explícitamente desde vcl_hit{} y vcl_miss{}. Devuelve el número de objetos purgados.

Ejemplo:

set req.http.purged = purge.hard();

Restringido a: vcl_hit, vcl_miss.

INT soft(DURATION ttl, DURATION grace, DURATION keep)

INT soft(DURATION ttl=0, DURATION grace=-1, DURATION keep=-1)

Establece el ttl, grace y keep. Por defecto, ttl se establece en 0 y los períodos de grace y keep permanecen sin cambios. Establecer grace o keep en un valor negativo o en algo superior al valor actual del objeto los deja sin cambios. Establecer los tres parámetros en 0 es equivalente a una purga dura. Devuelve el número de objetos purgados suavemente.

Una purga suave solo puede disminuir la vida útil de un objeto. Consideremos un objeto en caché creado con ttl, grace y keep de 60 segundos cada uno:

purge.soft(ttl = 0s, grace = -1s, keep = -1s);

  • Si el objeto está fresco, el ttl se reduce a 0 segundos y el objeto expira después de 120 segundos.
  • Si el objeto está caducado, el tiempo de expiración no se modifica.

purge.soft(ttl = 0s, grace = 10s, keep = 10s);

  • Si el objeto está fresco, el ttl se reduce a 0 segundos, grace y keep se reducen a 10 segundos. El objeto expira después de 20 segundos.
  • Si el objeto ha estado caducado durante 5 segundos, grace se reduce a 5 segundos y keep se reduce a 10 segundos. El objeto expira después de 15 segundos.
  • Si el objeto ha estado caducado durante 15 segundos, grace se reduce a 0 segundos y keep se reduce a 5 segundos. El objeto expira después de 5 segundos.
  • Si el objeto ha estado caducado durante 20 segundos o más, el objeto expira inmediatamente.

purge.soft(ttl = 10s, grace = -1s, keep = -1s);

  • Si el objeto ha estado fresco durante 5 segundos, el ttl se reduce a 10 segundos. El objeto expira después de 130 segundos.
  • Si el objeto ha estado fresco durante 55 segundos, el ttl no se modifica. El objeto expira después de 125 segundos.
  • Si el objeto está caducado, el tiempo de expiración no se modifica.

Cuando el tiempo de expiración de un objeto se reduce debido a una purga suave, se registra una entrada EXP_Reduce bajo la etiqueta VSL ExpKill. Si una purga suave no reduce el tiempo de expiración de un objeto, se registra una entrada EXP_Unchanged en su lugar.

Restringido a: vcl_hit, vcl_miss.
