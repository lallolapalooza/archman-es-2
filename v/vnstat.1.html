NOMBRE

vnstat - monitor de tráfico de red basado en consola

SINOPSIS

vnstat [-5bDedhlmqstvy?] [--95th] [--add] [--alert salida tipo condición límite unidad] [--begin fecha] [--config archivo] [--days [límite]] [--db archivo] [--dbdir directorio] [--dbiflist [modo]] [--debug] [--end fecha] [--fiveminutes [límite]] [--help] [-hg] [--hours [límite]] [--hoursgraph] [-i interfaz] [--iface interfaz] [--iflist [modo]] [--json [modo] [límite]] [--limit límite] [--live [modo]] [--locale localización] [--longhelp] [--merge fuente destino] [--months [límite]] [--oneline [modo]] [--query [modo]] [--rateunit [modo]] [--remove] [--rename nombre] [-ru [modo]] [--setalias alias] [--short] [--showconfig] [--style número] [--top [límite]] [-tr [tiempo]] [--traffic [tiempo]] [--version] [--xml [modo] [límite]] [--years [límite]] [interfaz]

DESCRIPCIÓN

vnStat es un monitor de tráfico de red basado en consola. Mantiene un registro del tráfico de red en intervalos de 5 minutos, por hora, día, mes y año para las interfaces seleccionadas. Sin embargo, no es un analizador de paquetes. La información de tráfico se lee de los archivos proc(5) o del sistema de archivos sys, según disponibilidad, lo que resulta en un uso ligero de los recursos del sistema independientemente de la tasa de tráfico de red. De esta manera, vnStat se puede usar incluso sin permisos de root en la mayoría de los sistemas.

La funcionalidad está dividida en dos comandos. El propósito del comando vnstat es proporcionar una interfaz para consultar la información de tráfico almacenada en la base de datos, mientras que el demonio vnstatd(8) es responsable de la recuperación, el almacenamiento en caché y el almacenamiento de datos. Aunque el proceso del demonio se ejecuta constantemente como un servicio, en realidad pasa la mayor parte de su tiempo durmiendo entre las actualizaciones de datos.

OPCIONES

--95th
Muestra la salida del percentil 95 para el mes en curso. Esta salida utiliza los datos de resolución de 5 minutos del mes en curso para calcular la tasa de tráfico del percentil 95 para recibido, transmitido y total. Además, también se muestran las tasas de tráfico mínima, promedio y máxima para recibido, transmitido y total. Esta salida requiere que la opción de configuración 5MinuteHours tenga un valor de al menos 744 para almacenar todos los datos necesarios; de lo contrario, no es posible una cobertura del 100%.
--add
Crea una entrada en la base de datos para la interfaz especificada con la opción -i o --iface. El demonio puede estar en ejecución durante esta operación y comenzará a monitorizar automáticamente la interfaz sin necesidad de reiniciarla dentro de los minutos de SaveInterval si la opción de configuración RescanDatabaseOnSave está habilitada. De lo contrario, el demonio debe reiniciarse para que la interfaz agregada sea monitorizada.
--alert salida tipo condición límite unidad
Dependiendo de los valores de los parámetros dados, muestra una alerta, usa un estado de salida diferente o una combinación de ambos cuando se cumple la situación configurada.
El parámetro salida toma un número del 0 al 3 y controla cuándo, si es que lo hace, el comando generará una salida. '0' nunca produce salida, '1' siempre produce salida, '2' muestra la salida solo cuando la estimación de uso excede el límite y '3' muestra la salida solo cuando se excede el límite.
El parámetro salida toma un número del 0 al 5 y controla el estado de salida del comando. '0' siempre usa el estado de salida 0, '1' siempre usa el estado de salida 1, '2' usa el estado de salida 1 si la estimación de uso excede el límite pero de lo contrario el estado de salida 0, y '3' usa el estado de salida 1 si se excede el límite pero de lo contrario el estado de salida 0. '4' y '5' son equivalentes a '2' y '3' con la diferencia de que se usa el estado de salida 2 en lugar del estado de salida 1 cuando se cumple la condición. Esto puede ayudar a diferenciar las alertas de los errores, ya que los errores siempre usarán el estado de salida 1.
El parámetro tipo define contra qué tipo de rango de tiempo se compara el uso del límite. Opciones disponibles: 'h', 'hour', 'hourly', 'd', 'day', 'daily', 'm', 'month', 'monthly', 'y', 'year', 'yearly', 'p', '95', '95%'.
El parámetro condición define si el límite se compara con el uso recibido (rx), transmitido (tx), total o estimado de estos tres. Opciones disponibles: 'rx', 'tx', 'total', 'rx_estimate', 'tx_estimate', 'total_estimate'. Las opciones de estimación no están disponibles para el tipo de percentil 95.
límite es un entero mayor que cero sin decimales que define el límite de uso de tráfico usando la unidad definida con el parámetro unidad. unidad acepta las siguientes opciones: 'B', 'KiB', 'MiB', 'GiB', 'TiB', 'PiB', 'EiB', 'KB', 'MB', 'GB', 'TB', 'PB', 'EB'. Para el tipo de percentil 95, las siguientes opciones están disponibles: 'B/s', 'KiB/s', 'MiB/s', 'GiB/s', 'TiB/s', 'PiB/s', 'EiB/s', 'kB/s', 'MB/s', 'GB/s', 'TB/s', 'PB/s', 'EB/s', 'bit/s', 'Kibit/s', 'Mibit/s', 'Gibit/s', 'Tibit/s', 'Pibit/s', 'Eibit/s', 'kbit/s', 'Mbit/s', 'Gbit/s', 'Tbit/s', 'Pbit/s', 'Ebit/s'. El uso debe exceder el límite para que la alarma se active. Un uso exactamente igual al límite no activa la alarma.
El cálculo de la estimación no se limita a las opciones de estimación en el parámetro condición, sino que también se puede lograr utilizando la opción de estimación en los parámetros de salida o salida. Los parámetros o combinaciones de parámetros faltantes o inválidos resultarán en la visualización de la ayuda específica de --alert.
-b, --begin fecha
Comienza la salida de la lista con una fecha/hora específica definida por fecha en lugar de que el inicio se seleccione en función del número de entradas a mostrar. Si fecha no está disponible en la base de datos, se utilizará la fecha posterior más cercana. fecha admite los siguientes formatos: YYYY-MM-DD HH:MM, YYYY-MM-DD y "today". Esta opción solo se puede usar con --json, --xml y salidas de lista.
--config archivo
Utiliza archivo como archivo de configuración en lugar de utilizar la funcionalidad de búsqueda automática de archivos de configuración. Si se usa --config varias veces, la configuración de los archivos posteriores en la línea de comandos anulará la configuración cargada de los archivos anteriores si la configuración definida en los archivos se solapa.
-d, --days [límite]
Muestra estadísticas de tráfico diariamente para los últimos días. La longitud de la lista se limitará a 30 entradas a menos que se configure de otra manera o a menos que se utilice el parámetro opcional límite. Se mostrarán todas las entradas almacenadas en la base de datos si límite se establece en 0.
--db archivo
Utiliza archivo como archivo de base de datos en lugar de buscar una base de datos en el directorio especificado en el archivo de configuración o el valor predeterminado codificado si no hay un archivo de configuración disponible. Esta opción anula --dbdir.
--dbdir directorio
Utiliza directorio como directorio de base de datos en lugar de utilizar el directorio especificado en el archivo de configuración o el valor predeterminado codificado si no hay un archivo de configuración disponible. Esta opción se ignora si también se define --db.
--dbiflist [modo]
Lista las interfaces actualmente en la base de datos. Si modo no está definido o está establecido en 0, la salida utilizará un formato detallado de una línea. Si modo está establecido en 1, la salida contendrá una interfaz por línea y si modo está establecido en 2, solo se mostrará el recuento de interfaces como un solo número. Ver también --iflist.
-D, --debug
Muestra salida de depuración adicional.
-e, --end fecha
Fin del rango de tiempo de la lista al final especificado por fecha. Si fecha no está disponible en la base de datos, se utilizará la fecha anterior más cercana. fecha admite los siguientes formatos: YYYY-MM-DD HH:MM, YYYY-MM-DD y "today". Esta opción solo se puede usar con --json, --xml y salidas de lista.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

Termina la salida de la lista con una fecha/hora específica definida por date en lugar de la fecha/hora más reciente en la base de datos. Si date no está disponible en la base de datos, se utilizará la fecha anterior más cercana. date admite los siguientes formatos: YYYY-MM-DD HH:MM y YYYY-MM-DD. Esta opción solo se puede usar con --json , --xml y salidas de lista. En las salidas de lista, la línea de estimación se reemplaza por una línea de suma con valores que representan las sumas de cada columna. La línea de suma solo se muestra si la salida consta de más de una línea de datos. Esto es aplicable incluso si la date definida es la misma que la fecha actual. La lista superior también requiere que se use --begin al mismo tiempo con esta opción.
-5, --fiveminutes [límite]
Muestra estadísticas de tráfico con una resolución de 5 minutos para las últimas horas. La longitud de la lista se limitará a 24 entradas a menos que se configure lo contrario o a menos que se utilice el parámetro opcional límite. Todas las entradas almacenadas en la base de datos se mostrarán si límite se establece en 0.
-h, --hours [límite]
Muestra estadísticas de tráfico por hora. La longitud de la lista se limitará a 24 entradas a menos que se configure lo contrario o a menos que se utilice el parámetro opcional límite. Todas las entradas almacenadas en la base de datos se mostrarán si el límite se establece en 0.
-hg, --hoursgraph
Muestra estadísticas de tráfico por hora durante las últimas 24 horas utilizando un gráfico de barras seguido de una tabla que representa los datos numéricos.
-i, --iface interfaz
Selecciona una interfaz específica y aplica acciones solo a ella. Para consultas a la base de datos, es posible fusionar la información de dos o más interfaces utilizando la sintaxis interfaz1+interfaz2+.... Todas las interfaces proporcionadas deben ser únicas y deben existir en la base de datos cuando se utiliza la sintaxis de fusión. Opcionalmente, dependiendo de la configuración InterfaceMatchMethod , interfaz puede ser reemplazado por alias establecido previamente usando --setalias. La sintaxis de fusión no es compatible cuando se utiliza alias. La opción -i, --iface es opcional y interfaz puede usarse como parámetro en la línea de comandos para seleccionar la interfaz utilizada incluso sin usar explícitamente la opción.
--iflist [modo]
Lista las interfaces disponibles actualmente. Si modo no está definido o está establecido en 0, la salida utilizará un formato detallado de una línea. Si modo está establecido en 1, la salida contendrá una interfaz por línea y si modo está establecido en 2, solo se mostrará el recuento de interfaces como un solo número. Ver también --dbiflist.
--json [modo] [límite]
Muestra el contenido de la base de datos para la interfaz seleccionada o todas las interfaces en formato json. Todos los valores de tráfico en la salida están en bytes a menos que se indique lo contrario por el nombre de la clave. Se puede usar un parámetro opcional modo para limitar la salida solo a información seleccionada. Todo excepto la salida del percentil 95 se muestra por defecto. Establecer modo a 's' mostrará un resumen que contiene las últimas 2 entradas de datos con resolución de 5 minutos, horaria, diaria, mensual y anual, 'f' mostrará solo entradas de resolución de 5 minutos, 'h' horas, 'd' días, 'm' meses, 'y' años, 't' los días principales y 'p' el percentil 95. Alternativamente o en combinación con modo, se puede usar un parámetro opcional límite para limitar el número de entradas en la salida. La opción --json se puede usar en combinación con las opciones -l, --live y -tr sin que modo o límite tengan ningún efecto en la salida. El campo jsonversion en la salida contiene la información de la versión de la API. Solo se modificará cuando los nombres o las estructuras de contenido existente cambien. En comparación, el campo vnstatversion existe solo como información adicional.
--limit límite
Establece el número máximo de entradas mostradas en las salidas de lista en límite. El uso de --limit anula los valores límite de entrada de lista predeterminados y el parámetro opcional límite proporcionado directamente para una consulta de lista. Todas las entradas almacenadas en la base de datos se mostrarán si límite se establece en 0. --limit también se puede usar para controlar la longitud de las salidas --json y --xml.
-l, --live [modo]
Muestra la tasa de transferencia actual para la interfaz seleccionada en tiempo real hasta que se interrumpe. Las estadísticas se mostrarán después de la interrupción si el tiempo de ejecución fue superior a 10 segundos. Se puede usar un parámetro opcional modo para seleccionar entre la visualización de paquetes por segundo (modo 0) y contadores de transferencia (modo 1) durante la ejecución. --style también se puede usar para afectar el diseño de la salida. La salida estará en formato json si se usa en combinación con la opción --json.
--locale locale
Utiliza locale en lugar de utilizar la configuración de locale especificada en el archivo de configuración o la predeterminada del sistema si no hay un archivo de configuración disponible.
--longhelp
Muestra la lista completa de opciones.
--merge fuente destino
Fusiona datos de interfaz de la base de datos fuente a la base de datos destino. A menos que se especifiquen interfaces, todas las interfaces de fuente se fusionarán a destino. Se creará una nueva base de datos si destino no existe. Si una interfaz con el mismo nombre no existe en destino, se ejecutará una copia directa de los datos de fuente. Si una interfaz con el mismo nombre ya existe en destino, se ejecutará una acción de fusión aditiva. La base de datos fuente siempre se accede en modo de solo lectura y nunca se modificará por las acciones de fusión. Los cambios en la base de datos destino no se pueden deshacer ya que las acciones de resta no son compatibles. La ejecución de la fusión debe ser confirmada con un parámetro adicional. Si este parámetro adicional no se proporciona, se mostrará una vista previa de las acciones con orientación adicional.
Tanto fuente como destino pueden referirse directamente a archivos de base de datos o utilizar una sintaxis alternativa archivo:interfaz donde el archivo de base de datos se sufija con : seguido de un nombre de interfaz. Cuando se utiliza como fuente, la sintaxis alternativa permite especificar una interfaz para fusionar desde fuente a destino en lugar de fusionar todas las interfaces. Adicionalmente, es posible utilizar la sintaxis alternativa en destino para especificar a qué interfaz se fusionarán los datos.
-m, --months [límite]
Muestra estadísticas de tráfico mensuales de los últimos meses. La longitud de la lista se limitará a 12 entradas a menos que se configure lo contrario o a menos que se utilice el parámetro opcional límite. Todas las entradas almacenadas en la base de datos se mostrarán si límite se establece en 0.
--oneline [modo]
Muestra un resumen de tráfico para la interfaz seleccionada en una sola línea con un formato analizable. La salida contiene 15 campos con ; utilizado como delimitador de campo. El primer campo contiene la información de la versión de la API de la salida que solo se modificará en futuras versiones si el contenido o la estructura del campo cambian. Los siguientes campos en orden son 2) nombre de la interfaz, 3) marca de tiempo de hoy, 4) rx de hoy, 5) tx de hoy, 6) total de hoy, 7) tasa de tráfico promedio de hoy, 8) marca de tiempo del mes actual, 9) rx del mes actual, 10) tx del mes actual, 11) total del mes actual, 12) tasa de tráfico promedio del mes actual, 13) total de rx de todos los tiempos, 14) total de tx de todos los tiempos, 15) tráfico total de todos los tiempos. Se puede usar un parámetro opcional modo para forzar la salida de todos los campos en bytes sin mostrar la unidad.
-q, --query [modo]
Fuerza el modo de consulta de la base de datos. Se puede usar un parámetro opcional modo para anular el modo de consulta predeterminado. 'a' resulta en una salida de resumen corto cuando hay más de una interfaz en la base de datos, de lo contrario, se utiliza la salida de resumen regular. 's' resulta en una salida de resumen regular mostrada para una interfaz independientemente del número de interfaces en la base de datos. Cuando el parámetro opcional modo no está definido, se utilizará el QueryMode configurado.
--remove
Elimina la entrada de la base de datos para la interfaz especificada con -i o --iface y deja de monitorearla. El demonio puede estar en ejecución durante esta operación y detectará automáticamente el cambio.
--rename nombre
Renombra la interfaz especificada con -i o --iface en la base de datos con el nuevo nombre nombre. El nuevo nombre no puede existir ya en la base de datos. Esta operación no causa ninguna pérdida de datos. El demonio no debe estar en ejecución durante esta operación.
-ru, --rateunit [modo]
Intercambia la unidad de tasa configurada. Si la tasa se ha configurado para mostrarse en bytes, la tasa se mostrará en bits si esta opción está presente. De la misma manera, si la tasa se ha configurado para mostrarse en bits, la tasa se mostrará en bytes cuando esta opción esté presente. Alternativamente, modo con 0 o 1 se puede usar como parámetro para esta opción para seleccionar entre bytes (0) y bits (1) independientemente de la configuración del archivo de configuración.
--setalias alias
Establece alias como un alias para la interfaz seleccionada que se mostrará en las consultas. El alias establecido se puede eliminar especificando una cadena vacía para alias. El demonio puede estar en ejecución durante esta operación.
-s, --short
Utiliza el modo de salida corto. Este modo también se utiliza cuando hay más de una interfaz disponible en la base de datos y no se selecciona ninguna interfaz específica.
--showconfig
Muestra la configuración actual utilizando el mismo formato que utiliza el propio archivo de configuración.
--style número
Modifica el contenido y el estilo de las salidas. Establece número en 0 para una salida más estrecha, 1 para habilitar la columna de barras, 2 para lo mismo que la anterior pero con la tasa de tráfico promedio visible en la salida de resumen y 3 para habilitar la tasa de tráfico promedio en todas las salidas donde sea compatible. 4 deshabilita el uso de caracteres de control de terminal en los modos -l, --live y -tr, --traffic.
-t, --top [límite]
Muestra los días de mayor tráfico de todos los tiempos. La longitud de la lista se limitará a 10 entradas a menos que se configure de otra manera o a menos que se utilice el parámetro opcional límite. Todas las entradas almacenadas en la base de datos se mostrarán si el límite se establece en 0. Cuando se utiliza con --begin y opcionalmente con --end, la lista se generará utilizando los datos diarios en lugar de entradas separadas de los principales. La disponibilidad de datos diarios define los límites a los que la consulta específica de fecha puede acceder.
-tr, --traffic [tiempo]
Calcula cuánto tráfico pasa por la interfaz seleccionada durante los segundos dados tiempo. El tiempo será de 5 segundos si no se especifica un parámetro numérico. La salida será en formato json si se utiliza en combinación con la opción --json. Sin embargo, en ese caso, la cuenta atrás antes de los resultados no se muestra. --style también se puede utilizar para afectar el diseño de la salida.
-v, --version
Muestra la versión actual.
--xml [modo] [límite]
Muestra el contenido de la base de datos para la interfaz seleccionada o todas las interfaces en formato xml. Todos los valores de tráfico en la salida están en bytes a menos que se indique lo contrario por el nombre de la clave. Se puede usar un parámetro opcional modo para limitar la salida solo a información seleccionada. De forma predeterminada, se muestra todo excepto la salida del percentil 95. Establecer el modo en 's' generará un resumen que contiene las últimas 2 entradas de datos con resolución de 5 minutos, horaria, diaria, mensual y anual; 'f' generará solo entradas de resolución de 5 minutos; 'h' horas; 'd' días; 'm' meses; 'y' años; 't' los días principales y 'p' el percentil 95. Opcionalmente, o en combinación con el modo, se puede usar un parámetro opcional límite para limitar el número de entradas en la salida. El campo xmlversion en la salida contiene información sobre la versión de la API. Solo se cambiará cuando los nombres o las estructuras del contenido existente anteriormente cambien. En comparación, el campo vnstatversion existe solo como información adicional.
-y, --years [límite]
Muestra estadísticas de tráfico anuales de los últimos años. La lista mostrará todas las entradas de forma predeterminada, a menos que se configure de otra manera o a menos que se utilice el parámetro opcional límite. Todas las entradas almacenadas en la base de datos también se mostrarán si el límite se establece en 0.
-?, --help
Muestra un resumen de las opciones de comandos.

ARCHIVOS

/var/lib/vnstat/
Directorio de base de datos predeterminado.
/etc/vnstat.conf
Archivo de configuración que se utilizará a menos que exista $HOME/.vnstatrc. Consulte vnstat.conf(5) para obtener más información.

EJEMPLOS

vnstat
Muestra un resumen del tráfico para la interfaz predeterminada o para múltiples interfaces cuando se monitorea más de una.
vnstat -i eth0+eth1+eth3
Muestra un resumen del tráfico para una combinación de las interfaces eth0, eth1 y eth3.
vnstat -i eth2 --xml
Muestra toda la información sobre la interfaz eth2 en formato xml.
vnstat --json
Muestra toda la información de todas las interfaces monitoreadas en formato json.
vnstat -i eth0 --setalias local
Asigna el alias "local" a la interfaz eth0. Esa información será visible más tarde como una etiqueta cuando se consulte eth0.
vnstat -i eth2 --remove
Elimina las entradas de la base de datos para la interfaz eth2 y deja de monitorearla.

RESTRICCIONES

Las actualizaciones deben ejecutarse al menos con la frecuencia necesaria para que la interfaz pueda generar suficiente tráfico como para desbordar el contador de tráfico de la interfaz del kernel. De lo contrario, es posible que no se vea algo de tráfico. Con contadores de tráfico de interfaz de 32 bits, el tiempo máximo entre dos actualizaciones depende de la rapidez con la que la interfaz pueda transferir 4 GiB. Tenga en cuenta que no hay garantía de que un kernel de 64 bits tenga contadores de tráfico de interfaz de 64 bits para todas las interfaces. Los tiempos teóricos calculados son:

10 Mbit: 54 minutos
100 Mbit: 5 minutos
1000 Mbit: 30 segundos

Las interfaces virtuales y alias no se pueden monitorear porque el kernel no proporciona información de tráfico para este tipo de interfaces. Dichas interfaces suelen llamarse eth0:0, eth0:1, eth0:2, etc., donde eth0 es la interfaz real a la que se le asigna un alias.

El uso de formatos de salida de fecha largos puede causar desalineación en las columnas mostradas si la longitud de la fecha excede la asignación de tamaño fijo.
