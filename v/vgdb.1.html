NOMBRE

vgdb - intermediario entre Valgrind y GDB o un shell

SINOPSIS

vgdb [opciones]

DESCRIPCIÓN

vgdb ("Valgrind to GDB") se utiliza como intermediario entre Valgrind y GDB o un shell. Tiene tres modos de uso:

1.Como utilidad independiente, se utiliza desde la línea de comandos del shell para enviar comandos de monitor a un proceso que se ejecuta bajo Valgrind. Para este uso, las OPCIONES de vgdb deben ir seguidas del comando de monitor a enviar. Para enviar más de un comando, sepárelos con la opción -c.
2.En combinación con el comando GDB "target remote |", se utiliza como aplicación de retransmisión entre GDB y el gdbserver de Valgrind. Para este uso, solo se pueden dar OPCIONES, pero no COMANDOS.
3.En el modo --multi, vgdb utiliza el protocolo remoto extendido para comunicarse con GDB. Esto le permite ver la salida tanto de valgrind como de GDB en la sesión de GDB. Esto se logra a través de "target extended-remote | vgdb --multi". En este modo, ya no necesita iniciar valgrind usted mismo. vgdb iniciará valgrind cuando gdb le indique que ejecute un nuevo programa. Para este uso, las OPCIONES de vgdb también pueden incluir --valgrind y --vargs para describir cómo se debe iniciar valgrind.

OPCIONES

--pid=<número>

Especifica el PID del proceso al que vgdb debe conectarse. Esta opción es útil en caso de que haya más de un gdbserver de Valgrind al que conectarse. Si no se proporciona el argumento --pid y se están ejecutando varios procesos gdbserver de Valgrind, vgdb informará la lista de dichos procesos y luego saldrá.

--vgdb-prefix

Debe proporcionarse tanto a Valgrind como a vgdb si desea cambiar el prefijo predeterminado para las FIFOs (tuberías con nombre) utilizadas para la comunicación entre el gdbserver de Valgrind y vgdb.

--wait=<número>

Instruye a vgdb a buscar gdbservers de Valgrind disponibles durante el número especificado de segundos. Esto hace posible iniciar un proceso vgdb antes de iniciar el gdbserver de Valgrind con el que se desea que vgdb se comunique. Esta opción es útil cuando se usa junto con un --vgdb-prefix que es único para el proceso que se desea esperar. Además, si usa el argumento --wait en el comando GDB "target remote", debe establecer el remotetimeout de GDB a un valor mayor que el valor del argumento --wait. Consulte la opción --max-invoke-ms (justo debajo) para ver un ejemplo de cómo establecer el valor de remotetimeout.

--max-invoke-ms=<número>

Indica el número de milisegundos después de los cuales vgdb forzará la invocación del gdbserver integrado en Valgrind. El valor predeterminado es 100 milisegundos. Un valor de 0 deshabilita la invocación forzada. La invocación forzada se utiliza cuando vgdb está conectado a un gdbserver de Valgrind y el proceso Valgrind tiene todos sus hilos bloqueados en una llamada al sistema.

Si especifica un valor alto, es posible que necesite aumentar el valor de "remotetimeout" de GDB de su valor predeterminado de 2 segundos. Debe asegurarse de que el tiempo de espera (en segundos) sea mayor que el valor de --max-invoke-ms. Por ejemplo, para --max-invoke-ms=5000, el siguiente comando GDB es adecuado:

    (gdb) set remotetimeout 6

--cmd-time-out=<número>

Instruye a un vgdb independiente a salir si el gdbserver de Valgrind al que está conectado no procesa un comando en el número de segundos especificado. El valor predeterminado es nunca agotar el tiempo de espera.

--port=<número de puerto>

Instruye a vgdb a usar tcp/ip y escuchar a GDB en el número de puerto especificado en lugar de usar una tubería para comunicarse con GDB. Usar tcp/ip permite tener GDB ejecutándose en un ordenador y depurando un proceso Valgrind ejecutándose en otro ordenador de destino. Ejemplo: 
# En el ordenador de destino, inicie su programa bajo valgrind usando
valgrind --vgdb-error=0 prog
# y luego en otro shell, ejecute:
vgdb --port=1234

En el ordenador que aloja GDB, ejecute el comando:

gdb prog
(gdb) target remote ip_del_destino:1234

donde ip_del_destino es la dirección ip o el nombre de host del ordenador de destino.

--vgdb-multi

Hace que vgdb se inicie en modo extended-remote y espere a que gdb le diga qué ejecutar.

--valgrind

La ruta a valgrind a usar, en modo extended-remote. Si no se especifica, se lanzará el valgrind del sistema.

--vargs

Opciones para ejecutar valgrind, en modo extended-remote. Por ejemplo -q. Todo lo que siga a --vargs se proporcionará a valgrind tal cual.

-c

Para dar más de un comando a un vgdb independiente, separe los comandos con una opción -c. Ejemplo: 
vgdb v.set log_output -c leak_check any

-l

Instruye a un vgdb independiente a mostrar la lista de los procesos gdbserver de Valgrind en ejecución y luego salir.

-T

Instruye a vgdb a añadir marcas de tiempo a los mensajes de información de vgdb.

-D

Instruye a un vgdb independiente a mostrar el estado de la memoria compartida utilizada por el gdbserver de Valgrind. vgdb saldrá después de mostrar el estado de la memoria compartida del gdbserver de Valgrind.

-d

Instruye a vgdb a producir salida de depuración. Proporcione múltiples argumentos -d para aumentar la verbosidad. Al proporcionar -d a un vgdb de retransmisión, es mejor redirigir el error estándar (stderr) de vgdb a un archivo para evitar la interacción entre la salida de depuración de GDB y vgdb.
