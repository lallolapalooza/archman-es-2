NAME

\n

virt-customize - Customize a virtual machine

\n
\n
\n

SYNOPSIS

\n
virt-customize\n   [ -a disk.img [ -a disk.img ... ] | -d domname ]\n   [--attach ISOFILE] [--attach-format FORMAT]\n   [ -c URI | --connect URI ] [ -n | --dry-run ]\n   [ --format FORMAT] [ -m MB | --memsize MB ]\n   [ --network | --no-network ]\n   [ -q | --quiet ] [--smp N] [ -v | --verbose ] [-x]\n   [--append-line FILE:LINE] [--chmod PERMISSIONS:FILE]\n   [--chown UID:GID:PATH] [--commands-from-file FILENAME]\n   [--copy SOURCE:DEST] [--copy-in LOCALPATH:REMOTEDIR]\n   [--delete PATH] [--edit FILE:EXPR] [--firstboot SCRIPT]\n   [--firstboot-command 'CMD+ARGS'] [--firstboot-install PKG,PKG..]\n   [--hostname HOSTNAME] [--inject-blnsvr METHOD]\n   [--inject-qemu-ga METHOD] [--inject-virtio-win METHOD]\n   [--install PKG,PKG..] [--link TARGET:LINK[:LINK..]] [--mkdir DIR]\n   [--move SOURCE:DEST] [--password USER:SELECTOR]\n   [--root-password SELECTOR] [--run SCRIPT]\n   [--run-command 'CMD+ARGS'] [--scrub FILE] [--sm-attach SELECTOR]\n   [--sm-register] [--sm-remove] [--sm-unregister]        \n   [--ssh-inject USER[:SELECTOR]] [--tar-in TARFILE:REMOTEDIR]\n   [--timezone TIMEZONE] [--touch FILE] [--truncate FILE]\n   [--truncate-recursive PATH] [--uninstall PKG,PKG..] [--update]\n   [--upload FILE:DEST] [--write FILE:CONTENT] [--no-logfile]\n   [--password-crypto md5|sha256|sha512] [--no-selinux-relabel]\n   [--selinux-relabel] [--sm-credentials SELECTOR]\nvirt-customize [ -V | --version ]
\n
\n
\n

WARNING

\n

Using "virt-customize" on live\n virtual machines, or concurrently with other disk editing tools, can be\n dangerous, potentially causing disk corruption. The virtual machine must be\n shut down before you use this command, and disk images must not be edited\n concurrently.

\n
\n
\n

DESCRIPTION

\n

Virt-customize can customize a virtual machine (disk image) by\n installing packages, editing configuration files, and so on.

\n

Virt-customize modifies the guest or disk image in place. \n The guest must be shut down. If you want to preserve the existing contents\n of the guest, you must snapshot, copy or clone the disk first.

\n

You do not need to run virt-customize as root. In fact we'd\n generally recommend that you don't.

\n

Related tools include: virt-sysprep(1) and\n virt-builder(1).

En general, no deberías usar --no-network. Pero aquí hay algunas razones por las que podrías querer hacerlo:

1.
Porque el backend de libguestfs que estás usando no soporta la red. (Ver: "BACKEND" en guestfs(3)).
2.
Cualquier software que necesites instalar proviene de una ISO adjunta, por lo que no necesitas la red.
3.
No quieres que código de invitado no confiable intente acceder a la red de tu host al ejecutar virt-customize. Esto es particularmente un problema cuando no confías en el origen de las plantillas del sistema operativo. (Ver "SECURITY" a continuación).

Opciones de personalización

--append-line ARCHIVO:LÍNEA
Añade una sola línea de texto al "ARCHIVO". Si el archivo no termina ya con un salto de línea, se añade uno antes de la línea añadida. También se añade automáticamente un salto de línea al final de la cadena "LÍNEA".

Por ejemplo (asumiendo el quoting ordinario del shell) este comando:

--append-line '/etc/hosts:10.0.0.1 foo'

añadirá "10.0.0.1 foo⏎" o "⏎10.0.0.1 foo⏎" al archivo, siendo este último solo si el archivo existente no termina ya con un salto de línea.

"⏎" representa un carácter de salto de línea, que se adivina observando el contenido existente del archivo, por lo que este comando hace lo correcto para archivos que usan finales de línea de Unix o Windows. También funciona para archivos vacíos o inexistentes.

Para insertar varias líneas, usa la misma opción varias veces:

--append-line '/etc/hosts:10.0.0.1 foo'
--append-line '/etc/hosts:10.0.0.2 bar'

Para insertar una línea en blanco antes de la línea añadida, haz lo siguiente:

--append-line '/etc/hosts:'
--append-line '/etc/hosts:10.0.0.1 foo'
--chmod PERMISOS:ARCHIVO
Cambia los permisos del "ARCHIVO" a "PERMISOS".

Nota: "PERMISOS" por defecto sería decimal, a menos que lo precedas con 0 para obtener octal, es decir, usa 0700 en lugar de 700.

--chown UID:GID:RUTA
Cambia el propietario (usuario y grupo) de un archivo o directorio en el invitado. Nota:
  • Solo funcionarán los UID y GID numéricos, y estos pueden no ser los mismos dentro del invitado que en el host.
  • Esto no funcionará con invitados de Windows.

Por ejemplo:

virt-customize --chown '0:0:/var/log/audit.log'

Ver también: --upload.

--commands-from-file NOMBRE_ARCHIVO
Lee los comandos de personalización desde un archivo, uno (y sus argumentos) por línea.

Cada línea contiene un único comando de personalización y sus argumentos, por ejemplo:

delete /algún/archivo
install algún-paquete
password algún-usuario:contraseña:su-nueva-contraseña

Las líneas vacías se ignoran, y las líneas que comienzan con "#" son comentarios y también se ignoran. Además, los argumentos pueden distribuirse en varias líneas, añadiendo un "\" (carácter de continuación) al final de una línea, por ejemplo

edit /algún/archivo:\
  s/^OPT=.*/OPT=ok/

Los comandos se manejan en el mismo orden en que aparecen en el archivo, como si se especificaran como --delete /algún/archivo en la línea de comandos.

--copy ORIGEN:DESTINO
Copia archivos o directorios recursivamente dentro del invitado.

No se pueden usar comodines.

--copy-in RUTA_LOCAL:DIRECTORIO_REMOTO
Copia archivos o directorios locales recursivamente en la imagen del disco, colocándolos en el directorio "DIRECTORIO_REMOTO" (que debe existir).

No se pueden usar comodines.

--delete RUTA
Elimina un archivo del invitado. O elimina un directorio (y todo su contenido, recursivamente).

Puedes usar caracteres glob de shell en la ruta especificada. Ten cuidado de escapar los caracteres glob del shell del host, si es necesario. Por ejemplo:

virt-customize --delete '/var/log/*.log'.

Ver también: --upload, --scrub.

--edit ARCHIVO:EXPRESION
Edita "ARCHIVO" usando la expresión Perl "EXPRESION".

Ten cuidado de citar adecuadamente la expresión para evitar que sea alterada por el shell.

Ten en cuenta que esta opción solo está disponible cuando Perl 5 está instalado.

Ver "NON-INTERACTIVE EDITING" en virt-edit(1).

--firstboot SCRIPT
Instala "SCRIPT" dentro del invitado, de modo que cuando el invitado arranque por primera vez, el script se ejecute (como root, al final del proceso de arranque).

El script se convierte automáticamente en chmod +x después de la instalación en el invitado.

La versión alternativa --firstboot-command es la misma, pero convenientemente envuelve el comando en un script de una sola línea para ti.

Puedes tener múltiples opciones de --firstboot. Se ejecutan en el mismo orden en que aparecen en la línea de comandos.

Por favor, echa un vistazo a "FIRST BOOT SCRIPTS" en virt-builder(1) para más información y advertencias sobre los scripts de primer arranque.

Ver también --run.

--firstboot-command 'COMANDO+ARG'
Ejecuta el comando (y sus argumentos) dentro del invitado cuando el invitado arranque por primera vez (como root, al final del proceso de arranque).

Puedes tener múltiples opciones de --firstboot. Se ejecutan en el mismo orden en que aparecen en la línea de comandos.

Por favor, echa un vistazo a "FIRST BOOT SCRIPTS" en virt-builder(1) para más información y advertencias sobre los scripts de primer arranque.

Ver también --run.

--firstboot-install PAQ,PAQ..
Instala los paquetes nombrados (una lista separada por comas). Estos se instalan cuando el invitado arranca por primera vez usando el gestor de paquetes del invitado (por ejemplo, apt, yum, etc.) y la conexión de red del invitado.

Para una visión general de las diferentes formas de instalar paquetes, ver "INSTALLING PACKAGES" en virt-builder(1).

--hostname NOMBRE_HOST
Establece el nombre de host del invitado a "NOMBRE_HOST". Puedes usar un nombre de host.dominio (FQDN) si lo deseas.
--inject-blnsvr METODO
Inyecta el Servidor de Globos (Balloon Server) (
--inject-blnsvr METHOD
Inyecta el servidor Balloon (blnsvr.exe) en un huésped de Windows. Esta operación también inyecta un script de primer arranque para que el servidor Balloon se instale cuando el huésped arranque.

El parámetro es el mismo que el utilizado por la operación --inject-virtio-win.

Tenga en cuenta que para realizar una conversión completa de un huésped de Windows desde un hipervisor externo como VMware (que implica muchas otras operaciones), debe usar la herramienta virt-v2v(1) en lugar de esta.

--inject-qemu-ga METHOD
Inyecta el agente huésped de QEMU en un huésped de Windows. El agente huésped se comunica con qemu a través de un socket para proporcionar funciones mejoradas (ver qemu-ga(8)). Esta operación también inyecta un script de primer arranque para que el agente huésped se instale cuando el huésped arranque.

El parámetro es el mismo que el utilizado por la operación --inject-virtio-win.

Tenga en cuenta que para realizar una conversión completa de un huésped de Windows desde un hipervisor externo como VMware (que implica muchas otras operaciones), debe usar la herramienta virt-v2v(1) en lugar de esta.

--inject-virtio-win METHOD
Inyecta los controladores virtio-win en un huésped de Windows. Estos controladores añaden controladores acelerados virtio adecuados para ejecutarlos sobre un hipervisor que soporta virtio (como qemu/KVM). La operación también ajusta el Registro de Windows para que los controladores se instalen cuando el huésped arranque.

El parámetro puede ser uno de los siguientes:

ISO
La ruta a la imagen ISO que contiene los controladores virtio-win (ej. /usr/share/virtio-win/virtio-win.iso).
DIR
El directorio que contiene los controladores virtio-win desempaquetados (ej. /usr/share/virtio-win).

Tenga en cuenta que para realizar una conversión completa de un huésped de Windows desde un hipervisor externo como VMware (que implica muchas otras operaciones), debe usar la herramienta virt-v2v(1) en lugar de esta.

--install PKG,PKG..
Instala los paquetes nombrados (una lista separada por comas). Estos se instalan durante la construcción de la imagen utilizando el gestor de paquetes del huésped (ej. apt, yum, etc.) y la conexión de red del host.

Para una visión general de las diferentes formas de instalar paquetes, vea "INSTALACIÓN DE PAQUETES" en virt-builder(1).

Ver también --update, --uninstall.

--link TARGET:LINK[:LINK..]
Crea enlaces simbólicos en el huésped, comenzando en "LINK" y apuntando a "TARGET".
--mkdir DIR
Crea un directorio en el huésped.

Usa "mkdir -p" por lo que se crean los directorios intermedios, y también funciona si el directorio ya existe.

--move SOURCE:DEST
Mueve archivos o directorios dentro del huésped.

No se pueden usar comodines.

--no-logfile
Elimina "builder.log" (archivo de registro de los comandos de construcción) de la imagen una vez completada la construcción. Úselo si no desea revelar exactamente cómo se construyó la imagen.

Ver también: "ARCHIVO DE REGISTRO".

--no-selinux-relabel
No intente corregir las etiquetas SELinux de los archivos en el huésped.

En huéspedes que soportan SELinux, la personalización automáticamente vuelve a etiquetar los archivos para que tengan la etiqueta SELinux correcta. (El reetiquetado se realiza de inmediato, pero si la operación falla, la personalización tocará en su lugar /.autorelabel en la imagen para programar una operación de reetiquetado para la próxima vez que la imagen arranque). Esta opción desactiva el reetiquetado automático.

La opción no tiene efecto en huéspedes que no soportan SELinux.

--password USER:SELECTOR
Establece la contraseña para "USER". (Nota: esta opción no crea la cuenta de usuario).

Ver "USUARIOS Y CONTRASEÑAS" en virt-builder(1) para el formato del campo "SELECTOR", y también cómo configurar cuentas de usuario.

--password-crypto md5|sha256|sha512
Cuando las herramientas virt cambian o establecen una contraseña en el huésped, esta opción establece el cifrado de esa contraseña a "md5", "sha256" o "sha512".

"sha256" y "sha512" requieren glibc ≥ 2.7 (verifique crypt(3) dentro del huésped).

"md5" funcionará con huéspedes de Linux relativamente antiguos (ej. RHEL 3), pero no es seguro contra ataques modernos.

El valor predeterminado es "sha512" a menos que libguestfs detecte un huésped antiguo que no tuviera soporte para SHA-512, en cuyo caso utilizará "md5". Puede anular libguestfs especificando esta opción.

Nota: esto no cambia el cifrado de contraseña predeterminado utilizado por el huésped cuando crea nuevas cuentas de usuario dentro del huésped. Si desea hacer eso, debe usar la opción --edit para modificar "/etc/sysconfig/authconfig" (Fedora, RHEL) o "/etc/pam.d/common-password" (Debian, Ubuntu).

--root-password SELECTOR
Establece la contraseña de root.

Ver "USUARIOS Y CONTRASEÑAS" en virt-builder(1) para el formato del campo "SELECTOR", y también cómo configurar cuentas de usuario.

Nota: En virt-builder, si no establece --root-password, el huésped recibe una contraseña de root aleatoria.

--run SCRIPT
Ejecuta el script de shell (o cualquier programa) llamado "SCRIPT" en la imagen de disco. El script se ejecuta virtualizado dentro de un pequeño appliance, en un entorno chrootado en el sistema de archivos del huésped.

El script se convierte automáticamente en ejecutable (chmod +x).

Si libguestfs lo soporta, hay una conexión de red limitada disponible, pero solo permite conexiones de red salientes. También puede adjuntar discos de datos (ej. archivos ISO) como otra forma de proporcionar datos (ej. paquetes de software) al script sin necesidad de una conexión de red (--attach). También puede subir archivos de datos (--upload).

Puede tener múltiples opciones --run. Se ejecutan en el mismo orden en que aparecen en la línea de comandos.

Ver también: --firstboot, --attach, --upload.

--run-command 'CMD+ARGS'
Ejecuta el comando y sus argumentos en la imagen de disco. El comando se ejecuta virtualizado dentro de un pequeño appliance, en un entorno chrootado en el sistema de archivos del huésped.

Si libguestfs lo soporta, hay una conexión de red limitada disponible, pero solo permite conexiones de red salientes. También puede adjuntar discos de datos (ej. archivos ISO) como otra forma de proporcionar datos (ej. paquetes de software) al script sin necesidad de una conexión de red (--attach). También puede subir archivos de datos (--upload).

Puede tener múltiples opciones --run-command. Se ejecutan en el mismo orden en que aparecen en la línea de comandos.

Ver también: --firstboot, --attach, --upload.

--scrub FILE
Limpia un archivo del huésped. Es similar a --delete excepto porque:
  • Limpia los datos de forma que un huésped no pueda recuperarlos.
  • No puede eliminar directorios, solo archivos regulares.
--selinux-relabel
Esta es una opción de compatibilidad que no hace nada.
--sm-attach SELECTOR
Se conecta a un grupo usando "subscription-manager".

Ver "SUBSCRIPTION-MANAGER" en virt-builder(1) para el formato del campo "SELECTOR".

--sm-credentials SELECTOR
Establece las credenciales para "subscription-manager".

Ver "SUBSCRIPTION-MANAGER" en virt-builder(1) para el formato del campo "SELECTOR".

--sm-register
Registra el huésped usando "subscription-manager".

Esto requiere que las credenciales se establezcan usando --sm-credentials.

--sm-remove
Elimina todas las suscripciones del huésped usando "subscription-manager".
--sm-unregister
Anula el registro del huésped usando "subscription-manager".
--ssh-inject USER[:SELECTOR]
Inyecta una clave ssh para que el "USER" dado pueda iniciar sesión por ssh sin proporcionar una contraseña. El "USER" debe existir previamente en el huésped.

Ver "CLAVES SSH" en virt-builder(1) para el formato del campo "SELECTOR".

Puede tener múltiples opciones --ssh-inject, para diferentes usuarios y también para más claves por cada usuario.

virt-customize(1) — Arch manual pages

NAME

virt-customize — customize virtual machine images

SYNOPSIS

virt-customize [OPTIONS] IMAGE [COMMAND...]

WARNING

This tool is EXPERIMENTAL and may change in future releases.

The disk image is modified in-place. Make a backup before using this tool.

DESCRIPTION

virt-customize is a tool for customizing virtual machine disk images. It allows you to make changes to a disk image without booting the virtual machine.

The program works by creating a temporary copy of the disk image, mounting it, performing the requested operations using guestfish, and then saving the modified disk image.

You can pass a list of commands to be executed on the disk image. Alternatively, you can use the --run-command option to run arbitrary commands inside the guest.

If no commands are given on the command line, and --run-command is not used, then virt-customize will start an interactive guestfish shell.

OPTIONS

The following options are supported:

--backup
Create a backup of the original disk image before modifying it. The backup will be named IMAGE.bak.
--clear-in-use
Clear the IN_USE flag in the guest's Windows registry. This is necessary for Windows guests that have been shut down improperly, or cloned from a running system.
--copy-in FILE:DEST
Upload local file "FILE" to destination "DEST" in the disk image. File owner and permissions from the original are preserved, so you should set them to what you want them to be in the disk image.
--copy-out FILE:DEST

--update
Do the equivalent of "yum update", "apt-get upgrade", or whatever command is required to update the packages already installed in the template to their latest versions.

See also --install, --uninstall.

--upload FILE:DEST
Upload local file "FILE" to destination "DEST" in the disk image. File owner and permissions from the original are preserved, so you should set them to what you want them to be in the disk image.

"DEST" could be the final filename. This can be used to rename the file on upload.

If "DEST" is a directory name (which must already exist in the guest) then the file is uploaded into that directory, and it keeps the same name as on the local filesystem.

See also: --mkdir, --delete, --scrub.

ENVIRONMENT VARIABLES

"VIRT_TOOLS_DATA_DIR"
This can point to the directory containing data files used for Windows firstboot installation.

Normally you do not need to set this. If not set, a compiled-in default will be used (something like /usr/share/virt-tools).

This directory may contain the following files:

rhsrvany.exe
This is the RHSrvAny Windows binary, used to install a "firstboot" script in Windows guests. It is required if you intend to use the --firstboot or --firstboot-command options with Windows guests.

See also: "https://github.com/rwmjones/rhsrvany"

pvvxsvc.exe
This is a Windows binary shipped with SUSE VMDP, used to install a "firstboot" script in Windows guests. It is required if you intend to use the --firstboot or --firstboot-command options with Windows guests.

For other environment variables, see "ENVIRONMENT VARIABLES" in guestfs(3).
