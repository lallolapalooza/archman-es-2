NOMBRE

virt-win-reg - Exportar y fusionar entradas del Registro de Windows de un invitado de Windows

SINOPSIS

virt-win-reg domname 'HKLM\Ruta\A\Subclave'
virt-win-reg domname 'HKLM\Ruta\A\Subclave' nombre
virt-win-reg domname 'HKLM\Ruta\A\Subclave' @
virt-win-reg --merge domname [input.reg ...]
virt-win-reg [--opciones] disk.img ... # en lugar de domname

ADVERTENCIA

No debe usar "virt-win-reg" con la opción --merge en máquinas virtuales en vivo. Si lo hace, obtendrá una corrupción irreversible del disco en la VM. "virt-win-reg" intenta detenerle de hacer esto, pero no captura todos los casos.

Modificar el Registro de Windows es una operación intrínsecamente arriesgada. El formato es deliberadamente oscuro y no está documentado, y los cambios en el Registro pueden dejar el sistema inarrancable. Por lo tanto, al usar la opción --merge, asegúrese de tener una copia de seguridad fiable primero.

DESCRIPCIÓN

Este programa puede exportar y fusionar entradas del Registro de Windows desde un invitado de Windows.

El primer parámetro es el nombre del invitado de libvirt o la imagen de disco cruda de un invitado de Windows.

Si --merge *no* se especifica, entonces la clave del registro elegida se muestra/exporta (recursivamente). Por ejemplo:

$ virt-win-reg Windows7 'HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft'

También puede mostrar valores individuales de dentro de las claves del registro, por ejemplo:

$ cvkey='HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion'
$ virt-win-reg Windows7 $cvkey ProductName
Windows 7 Enterprise

Con --merge, puede fusionar un archivo regedit de texto en el Registro de Windows:

$ virt-win-reg --merge Windows7 changes.reg

NOTA

Este programa solo está destinado a un acceso simple al registro. Si desea hacer cosas complicadas con el registro, le sugerimos que descargue los archivos de la colmena del Registro del invitado usando libguestfs(3) o guestfish(1) y acceda a ellos localmente, por ejemplo, usando hivex(3), hivexsh(1) o hivexregedit(1).

OPCIONES

--help
Muestra ayuda breve.
--version
Muestra el número de versión y sale.
--debug
Habilita los mensajes de depuración.
-c URI
--connect URI
Si usa libvirt, conéctese a la URI dada. Si se omite, entonces nos conectamos al hipervisor libvirt predeterminado.

Si especifica dispositivos de bloque de invitados directamente, entonces libvirt no se usa en absoluto.

--format raw
Especifica el formato de las imágenes de disco dadas en la línea de comandos. Si se omite, el formato se detecta automáticamente del contenido de la imagen de disco.

Si se solicitan imágenes de disco de libvirt, este programa le pide a libvirt esta información. En este caso, el valor del parámetro de formato se ignora.

Si trabaja con imágenes de disco de invitados de formato crudo no confiables, siempre debe asegurarse de que el formato se especifique.

--merge
En modo de fusión, fusiona un archivo regedit de texto en el Registro de Windows de la máquina virtual. Si esta bandera *no* se da, entonces virt-win-reg muestra o exporta entradas del Registro.

Tenga en cuenta que --merge es *inseguro* para usar en máquinas virtuales en vivo, y resultará en corrupción del disco. Sin embargo, exportar (sin esta bandera) es siempre seguro.

--encoding UTF-16LE|ASCII
Al fusionar (solo), puede que necesite especificar la codificación para las cadenas que se usarán en el archivo de colmena. Esto se explica en detalle en "ENCODING STRINGS" en Win::Hivex::Regedit(3).

El valor predeterminado es usar UTF-16LE, lo que debería funcionar con versiones recientes de Windows.

--unsafe-printable-strings
Al exportar (solo), asume que las cadenas están en UTF-16LE y las imprime como cadenas en lugar de secuencias hexadecimales. Elimina el punto de código cero final de las cadenas si está presente.

Esto es inseguro y no preserva la fidelidad de las cadenas en el Registro original por varias razones:

  • Asume que la codificación original es UTF-16LE. Las cadenas ASCII y las cadenas en otras codificaciones se corromperán con esta transformación.
  • Asume que todo lo que tiene el tipo 1 o 2 es realmente una cadena y que todo lo demás no es una cadena, pero el campo de tipo en los Registros reales no es fiable.
  • Pierde información sobre si un punto de código cero siguió a la cadena en el Registro o no.

Todo esto sucede porque el propio Registro no contiene información sobre cómo se codifican las cadenas (ver "ENCODING STRINGS" en Win::Hivex::Regedit(3)).

Solo debe usar esta opción para modificaciones y depuración rápidas del contenido del Registro, y nunca debe usarla si la salida se va a pasar a otro programa o a almacenar en otro Registro.

SISTEMAS SOPORTADOS

El programa actualmente soporta invitados derivados de Windows NT, desde Windows XP hasta al menos Windows 8.

Las siguientes claves del Registro son soportadas:

"HKEY_LOCAL_MACHINE\SAM"
"HKEY_LOCAL_MACHINE\SECURITY"
"HKEY_LOCAL_MACHINE\SOFTWARE"
"HKEY_LOCAL_MACHINE\SYSTEM"
"HKEY_USERS\.DEFAULT"
"HKEY_USERS\SID"
donde SID es un SID de usuario de Windows (por ejemplo, "S-1-5-18").
"HKEY_USERS\nombredeusuario"
donde nombredeusuario es un nombre de usuario local (esta es una extensión de libguestfs).

Puede usar "HKLM" como atajo para "HKEY_LOCAL_MACHINE", y "HKU" para "HKEY_USERS".

Las claves literales "HKEY_USERS\$SID" y "HKEY_CURRENT_USER" no son soportadas (no hay un "usuario actual").

WINDOWS 8

El "inicio rápido" de Windows 8 puede impedir que virt-win-reg pueda editar el Registro. Ver "WINDOWS HIBERNATION AND WINDOWS 8 FAST STARTUP" en guestfs(3).

CODIFICACIÓN

"virt-win-reg" espera que los archivos regedit ya hayan sido recodificados a la codificación local. Normalmente en hosts Linux, esto significa UTF-8 con finales de línea estilo Unix. Dado que los archivos regedit de Windows suelen estar en UTF-16LE con finales de línea estilo Windows, es posible que necesite recodificar todo el archivo antes o después de procesarlo.

Para recodificar un archivo del formato de Windows a Linux (antes de procesarlo con la opción --merge), haría algo como esto:

iconv -f utf-16le -t utf-8 < win.reg | dos2unix > linux.reg

Para ir en la dirección opuesta, después de exportar y antes de enviar el archivo a un usuario de Windows, haga algo como esto:

unix2dos linux.reg | iconv -f utf-8 -t utf-16le > win.reg

Para más información sobre codificación, ver Win::Hivex::Regedit(3).

NAME

virt-win-reg

manipulate the Windows registry from the command line

SYNOPSIS

virt-win-reg [OPTIONS] GUEST COMMAND

virt-win-reg [OPTIONS] GUEST --merge REGFILE

virt-win-reg [OPTIONS] GUEST --batch

WARNING

This command manipulates the Windows registry of a virtual machine. Be very careful, as incorrect changes can easily make the virtual machine unbootable.

For safety, you should shut down the virtual machine before running this command.

DESCRIPTION

The virt-win-reg command manipulates the Windows registry of a virtual machine. It can be used to read, write, delete, or merge registry files.

You can inspect registry keys and values, or update the registry using a .reg file.

The command uses libguestfs to access the virtual machine's disk image.

The first form of the command lets you perform a single operation on the registry:

--get-value KEY
Read a registry value.
--set-value KEY [VALUE]
Set a registry value. If VALUE is omitted, the value is deleted. Data types are detected automatically, or can be specified using --type.
--get-key KEY
Read a whole registry key.
--set-key KEY
Create a registry key.
--delete-key KEY
Delete a registry key and all its subkeys and values.
--delete-value KEY
Delete a registry value.

The second form of the command merges a Windows registry file (created by regedit export function) into the virtual machine's registry:

--merge REGFILE
Merge the specified Windows registry file into the guest registry.

The third form of the command executes a batch of registry commands:

--batch
Read commands from standard input.

The GUEST parameter is the name of the virtual machine.

OPTIONS

See guestfish(1) for common options.

The following options are specific to virt-win-reg:

--type TYPE
Specifies the data type when setting a value. Must be one of string, dword, binary, multistring, expand. If not specified, it is auto-detected.
--dry-run
Do not make any changes. Print what would be done.

SUPPORTED SYSTEMS

This command works on Windows NT-based guest operating systems, including Windows XP, Windows Vista, Windows 7, Windows 8, Windows 10, Windows 11, and Windows Server versions.

ENCODING

Windows registry files can be in different encodings. By default, virt-win-reg assumes UTF-16 little-endian encoding, as produced by standard Windows registry export. If you encounter errors, you may need to convert the file first.

Example:
$ file software.reg
software.reg: Little-endian UTF-16 Unicode text, with very long lines,
with CRLF line terminators

This file would need conversion before you could --merge it.

CurrentControlSet etc.

Registry keys like "CurrentControlSet" don’t really exist in the Windows Registry at the level of the hive file, and therefore you cannot modify these.

"CurrentControlSet" is usually an alias for "ControlSet001". In some circumstances it might refer to another control set. The way to find out is to look at the "HKLM\SYSTEM\Select" key:

# virt-win-reg WindowsGuest 'HKLM\SYSTEM\Select'
[HKEY_LOCAL_MACHINE\SYSTEM\Select]
"Current"=dword:00000001
"Default"=dword:00000001
"Failed"=dword:00000000
"LastKnownGood"=dword:00000002

"Current" is the one which Windows will choose when it boots.

Similarly, other "Current..." keys in the path may need to be replaced.

DELETING REGISTRY KEYS AND VALUES

To delete a whole registry key, use the syntax:

[-HKEY_LOCAL_MACHINE\Foo]

To delete a single value within a key, use the syntax:

[HKEY_LOCAL_MACHINE\Foo]
"Value"=-

WINDOWS TIPS

Note that some of these tips modify the guest disk image. The guest must be shut off, else you will get disk corruption.

RUNNING A BATCH SCRIPT WHEN A USER LOGS IN

Prepare a DOS batch script, VBScript or executable. Upload this using guestfish(1). For this example the script is called "test.bat" and it is uploaded into "C:\":

guestfish -i -d WindowsGuest upload test.bat /test.bat

Prepare a regedit file containing the registry change:

cat > test.reg <<'EOF'
[HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce]
"Test"="c:\\test.bat"
EOF

In this example we use the key "RunOnce" which means that the script will run precisely once when the first user logs in. If you want it to run every time a user logs in, replace "RunOnce" with "Run".

Now update the registry:

virt-win-reg --merge WindowsGuest test.reg

INSTALLING A SERVICE

This section assumes you are familiar with Windows services, and you either have a program which handles the Windows Service Control Protocol directly or you want to run any program using a service wrapper like SrvAny or the free RHSrvAny.

First upload the program and optionally the service wrapper. In this case the test program is called "test.exe" and we are using the RHSrvAny wrapper:

guestfish -i -d WindowsGuest <<EOF
  upload rhsrvany.exe /rhsrvany.exe
  upload test.exe /test.exe
EOF

Prepare a regedit file containing the registry changes. In this example, the first registry change is needed for the service itself or the service wrapper (if used). The second registry change is only needed because I am using the RHSrvAny service wrapper.

cat > service.reg <<'EOF'
[HKLM\SYSTEM\ControlSet001\services\RHSrvAny]
"Type"=dword:00000010
"Start"=dword:00000002
"ErrorControl"=dword:00000001
"ImagePath"="c:\\rhsrvany.exe"
"DisplayName"="RHSrvAny"
"ObjectName"="NetworkService"

[HKLM\SYSTEM\ControlSet001\services\RHSrvAny\Parameters]
"CommandLine"="c:\\test.exe"
"PWD"="c:\\Temp"
EOF

Notes:

  • For use of "ControlSet001" see the section above in this manual page. You may need to adjust this according to the control set that is in use by the guest.
  • "ObjectName" controls the privileges that the service will have. An alternative is "ObjectName"="LocalSystem" which would be the most privileged account.
  • For the meaning of the magic numbers, see this Microsoft KB article: http://support.microsoft.com/kb/103000.

Update the registry:

virt-win-reg --merge WindowsGuest service.reg

SHELL QUOTING

Be careful when passing parameters containing "\" (backslash) in the shell. Usually you will have to use 'single quotes' or double backslashes (but not both) to protect them from the shell.

Paths and value names are case-insensitive.
