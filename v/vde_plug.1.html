VDE_PLUG(1) Manual de Comandos Generales VDE_PLUG(1)

NOMBRE

vde_plug - Plug de Ethernet Distribuido Virtual (dos plugs crean un cable vde)

SINOPSIS

vde_plug [ -p num_puerto ] [ -g grupo ] [ -m modo_octal ] [ directorio_socket ]

DESCRIPCIÓN

Un vde_plug es un plug para ser conectado a un switch VDE. Todos los datos que son capturados por el plug se escriben en su salida estándar y todo lo que proviene de la entrada estándar se inyecta en el switch.

Esta herramienta ha sido diseñada para ser utilizada junto con dpipe(1) para interconectar otro vde_plug a otro switch, funcionando como un cable cruzado de Ethernet virtual entre los dos switches.

El comando


dpipe vde_plug = vde_plug /tmp/vde2.ctl
conecta dos switches locales: el primero utiliza el socket de control estándar /tmp/vde.ctl mientras que el segundo utiliza /tmp/vde2.ctl.

El comando


dpipe vde_plug = ssh remote.machine.org vde_plug
conecta dos switches remotos. Si los dos vde_switches se ejecutan como demonios y están conectados a interfaces tap, se establece un túnel cifrado de nivel 2.

vde_plug también puede establecerse como un shell de inicio de sesión para usuarios. El siguiente comando funciona como en el ejemplo anterior


dpipe vde_plug = ssh vdeuser@remote.machine.org vde_plug
donde vdeuser es el usuario con vde_plug como shell estándar. Todos los accesos remotos se registran mediante syslog al principio y al final de cada sesión. Los intentos de inicio de sesión sin el comando vde_plug al final o los intentos de ejecutar algo más son bloqueados y el intento se registra en syslog.

OPCIONES

-p num_puerto
Es posible decidir qué puerto del switch usar. Cuando esta opción no se especifica, el switch asigna el primer puerto no utilizado disponible (si lo hay). Es posible conectar varios cables al mismo puerto del switch: de esta manera, todos estos cables funcionan de forma concurrente. Esto significa que los paquetes pueden resultar duplicados, pero no se generan bucles en la tabla ARP. Es útil cuando se utiliza vde para la movilidad. Se pueden usar varias interfaces físicas a la vez durante las transferencias para evitar interrupciones en la conectividad.
-g grupo
Propiedad del grupo del socket de comunicación. Por seguridad, cuando más personas desean compartir un switch, es mejor usar un grupo de Unix para ser propietario de los sockets de comunicación, de modo que el tráfico de red no pueda ser esnifado.
-m modo_octal
Permisos al estilo de `chmod` octal para los sockets de comunicación.
directorio_socket
(Esta opción también se puede establecer como: -sock directorio_socket) especifica el directorio que contiene el socket UNIX a ser utilizado por programas locales para unirse a VDE. El valor predeterminado es "/tmp/vde.ctl", que corresponde al socket "/tmp/vde.ctl/ctl" (o /var/run/vde.ctl cuando vde_switch se ejecuta como un demonio compartido). Es posible que los usuarios redefinan su switch predeterminado como ".vde-2/stdsock" en su directorio personal. Si existe, este directorio (o enlace simbólico al directorio real) se utiliza como valor predeterminado para el usuario.

AVISO

Virtual Distributed Ethernet no está relacionado de ninguna manera con www.vde.com ("Verband der Elektrotechnik, Elektronik und Informationstechnik", es decir, la "Asociación Alemana de Tecnologías Eléctricas, Electrónicas y de la Información").
