Name

virt-qemu-sev-validate - valida una medición de lanzamiento de dominio AMD SEV

SYNOPSIS

virt-qemu-sev-validate [OPTIONS]

DESCRIPTION

Este programa valida la medición reportada para un dominio lanzado con AMD SEV. Si el programa sale con un estado de cero, el propietario del invitado puede estar seguro de que su sistema operativo invitado se está ejecutando bajo la protección ofrecida por la plataforma SEV / SEV-ES.

Tenga en cuenta que el nivel de protección varía según la generación de la plataforma AMD SEV y la descripción de las diferencias está fuera del alcance de este documento.

Para que los resultados de este programa se consideren confiables, es necesario que se ejecute en una máquina que ya sea confiable para el propietario del invitado. Podría ser una máquina que el propietario del invitado tenga control físico directo, o podría ser otra máquina virtual protegida por AMD SEV cuya medición de lanzamiento ya haya sido validada. Ejecutar este programa en el host de virtualización no producirá una respuesta que pueda ser confiable.

Si se le indica que se conecte a libvirt, se negará a usar una conexión libvirt que sea local a la máquina, ya que no se puede confiar en ella. Sin embargo, para fines de prueba o demostración, se puede forzar su ejecución en este escenario usando la bandera --insecure. El resultado, por supuesto, seguirá sin ser confiable.

OPTIONS

Opciones comunes

-h, --help

Muestra la ayuda de la línea de comandos y sale.

-d, --debug

Muestra información de depuración mientras se ejecuta

-q, --quiet

No imprime información sobre el resultado de la atestación.

Opciones de estado del invitado

Estas opciones proporcionan información sobre el estado del invitado cuya inicialización debe ser atestada.

--measurement BASE64-STRING

La medición de lanzamiento reportada por el hipervisor del dominio a validar. La medición debe ser de 48 bytes de datos binarios codificados como una cadena base64.

--api-major VERSION

La versión mayor de la API SEV del hipervisor en el que se está ejecutando el dominio.

--api-minor VERSION

La versión menor de la API SEV del hipervisor en el que se está ejecutando el dominio.

--build-id ID

El ID de compilación SEV del hipervisor en el que se está ejecutando el dominio.

--policy POLiCY

La máscara de bits de política asociada con los datos de lanzamiento de la sesión del dominio a validar.

Opciones de configuración del invitado

Estas opciones proporcionan los elementos necesarios para calcular la medición de lanzamiento esperada del dominio. Esta se comparará con la medición de lanzamiento reportada.

-f PATH, --firmware=PATH

Ruta al binario del cargador de firmware. Esta es la compilación EDK2 que sabe cómo inicializar AMD SEV. Para que la validación sea confiable, es importante que la compilación de firmware utilizada no tenga soporte para cargar variables no volátiles de NVRAM, incluso si NVRAM está expuesta al invitado.

-k PATH, --kernel=PATH

Ruta al binario del kernel si se está realizando un arranque directo del kernel.

-r PATH, --initrd=PATH

Ruta al binario del initrd si se está realizando un arranque directo del kernel. Por defecto, es contenido de longitud cero si se omite.

-e STRING, --cmdline=STRING

Cadena que contiene los parámetros de la línea de comandos del kernel utilizados durante el arranque del dominio. Por defecto, es una cadena vacía si se omite.

-n COUNT, --num-cpus=COUNT

El número de CPUs virtuales para el dominio. Esto es necesario cuando la política del dominio está configurada para requerir SEV-ES.

-0 PATH, --vmsa-cpu0=PATH

Ruta al estado inicial VMSA para la CPU de arranque. Esto es necesario cuando la política del dominio está configurada para requerir SEV-ES. El contenido del archivo debe tener exactamente 4096 bytes de longitud.

-1 PATH, --vmsa-cpu1=PATH

Ruta al estado inicial VMSA para la CPU que no es de arranque. Esto es necesario cuando la política del dominio está configurada para requerir SEV-ES y el dominio tiene más de una CPU presente. El contenido del archivo debe tener exactamente 4096 bytes de longitud.

--tik PATH

Archivo TIK para el dominio. Este archivo debe tener exactamente 16 bytes de tamaño y contiene la clave de integridad de transporte única asociada con los datos de lanzamiento de la sesión del dominio. Esto es mutuamente excluyente con el argumento --tk.

--tek PATH

Archivo TEK para el dominio. Este archivo debe tener exactamente 16 bytes de tamaño y contiene la clave de cifrado de transporte única asociada con los datos de lanzamiento de la sesión del dominio. Esto es mutuamente excluyente con el argumento --tk.

--tk PATH

Archivo combinado TEK/TIK para el dominio. Este archivo debe tener exactamente 32 bytes de tamaño, con los primeros 16 bytes conteniendo el TEK y los últimos 16 bytes conteniendo el TIK. Esto es mutuamente excluyente con los argumentos --tik y --tek.

Opciones de Libvirt

Estas opciones se utilizan al conectarse a libvirt para obtener automáticamente el estado y la información de configuración del dominio a atestar.

-c, --connect URI

URI de conexión de Libvirt. Para que la validación sea confiable, esta debe ser una URI que resuelva a un host de virtualización remoto. Este requisito puede ser anulado usando el argumento --insecure.

-o, --domain ID|NAME|UUID

ID del dominio, o nombre del dominio o UUID del dominio. Se utiliza para identificar qué dominio de libvirt debe medirse su lanzamiento. El dominio debe estar en ejecución, y generalmente se habría iniciado en un estado pausado, para permitir que la validación se realice antes de que las CPUs del invitado comiencen la ejecución.

-i, --insecure

Continuar incluso si se sabe que el escenario de uso es inseguro. Esto permite que el programa se conecte a un hipervisor libvirt local y confíe en el contenido del archivo del host de virtualización. También permite que la validación continúe incluso si las CPUs de la máquina virtual no están en el estado pausado inicial. El resultado de la validación no debe ser confiable.

-g, --ignore-config

No intente verificar la configuración del dominio. El comportamiento por defecto es mostrar errores si se identifican elementos de configuración en el XML del invitado que invalidarían la medición de lanzamiento. Esto puede ayudar al propietario del invitado a comprender cualquier error de configuración que se haya cometido. Si se proporciona el argumento --ignore-config, se omitirá esta verificación de configuración. El resultado es que es probable que la validación falle.

Opciones de inyección de secretos

Estas opciones proporcionan una forma de inyectar un secreto si la validación de la medición de lanzamiento tiene éxito.

--inject-secret ALIAS-OR-GUID:PATH

Ruta a un archivo que contiene un secreto para inyectar en el sistema operativo invitado. Un uso típico sería proporcionar una contraseña para desbloquear el cifrado completo del disco del sistema de archivos raíz. ALIAS puede ser uno de los secretos conocidos:

•
luks-key - bytes para usar como clave para desbloquear una ranura de clave LUKS. GUID de 736869e5-84f0-4973-92ec-06879ce3da0b.

Alternativamente, GUID se refiere a un UUID arbitrario elegido por el llamador. El contenido de PATH está definido por los requisitos del GUID asociado, y se utilizará tal cual sin modificaciones. En particular, tenga en cuenta:

  • Evite caracteres de nueva línea finales no deseados en PATH a menos que estén exigidos por el GUID.
  • Cualquier byte NUL final debe incluirse explícitamente en PATH si está exigido por el GUID.

Este argumento se puede repetir varias veces, siempre que se proporcione un GUID diferente para cada instancia.

EJEMPLOS

Ejecución completamente offline

Este escenario permite validar de forma segura una medición sin ninguna conexión al host del hipervisor. Todos los elementos de datos requeridos deben proporcionarse como parámetros de línea de comandos. Este modelo de uso se considera seguro, ya que todos los datos de entrada son proporcionados por el usuario.

Validar la medición de un invitado SEV que arranca desde disco:

# virt-qemu-sev-validate \
    --firmware OVMF.sev.fd \
    --tk this-guest-tk.bin \
    --measurement Zs2pf19ubFSafpZ2WKkwquXvACx9Wt/BV+eJwQ/taO8jhyIj/F8swFrybR1fZ2ID \
    --api-major 0 \
    --api-minor 24 \
    --build-id 13 \
    --policy 3

Validar la medición de un invitado SEV con arranque directo del kernel:

# virt-qemu-sev-validate \
    --firmware OVMF.sev.fd \
    --kernel vmlinuz-5.11.12 \
    --initrd initramfs-5.11.12 \
    --cmdline "root=/dev/vda1" \
    --tk this-guest-tk.bin \
    --measurement Zs2pf19ubFSafpZ2WKkwquXvACx9Wt/BV+eJwQ/taO8jhyIj/F8swFrybR1fZ2ID \
    --api-major 0 \
    --api-minor 24 \
    --build-id 13 \
    --policy 3

Validar la medición de un invitado SEV-ES SMP que arranca desde disco:

# virt-qemu-sev-validate \
    --firmware OVMF.sev.fd \
    --num-cpus 2 \
    --vmsa-cpu0 vmsa0.bin \
    --vmsa-cpu1 vmsa1.bin \
    --tk this-guest-tk.bin \
    --measurement Zs2pf19ubFSafpZ2WKkwquXvACx9Wt/BV+eJwQ/taO8jhyIj/F8swFrybR1fZ2ID \
    --api-major 0 \
    --api-minor 24 \
    --build-id 13 \
    --policy 7

Validar la medición de un invitado SEV-ES SMP que arranca desde disco, con VMSA construido automáticamente:

# virt-qemu-sev-validate \
    --firmware OVMF.sev.fd \
    --num-cpus 2 \
    --cpu-family 23 \
    --cpu-model 49 \
    --cpu-stepping 0 \
    --tk this-guest-tk.bin \
    --measurement Zs2pf19ubFSafpZ2WKkwquXvACx9Wt/BV+eJwQ/taO8jhyIj/F8swFrybR1fZ2ID \
    --api-major 0 \
    --api-minor 24 \
    --build-id 13 \
    --policy 7

Validar la medición de un invitado SEV que arranca desde disco e inyectar una contraseña de disco al éxito:

# virt-qemu-sev-validate \
    --firmware OVMF.sev.fd \
    --tk this-guest-tk.bin \
    --measurement Zs2pf19ubFSafpZ2WKkwquXvACx9Wt/BV+eJwQ/taO8jhyIj/F8swFrybR1fZ2ID \
    --api-major 0 \
    --api-minor 24 \
    --build-id 13 \
    --policy 3 \
    --inject-secret 736869e5-84f0-4973-92ec-06879ce3da0b:passwd.txt \
    --secret-header secret-header.b64 \
    --secret-payload secret-payload.b64

Los archivos secret-header.b64 y secret-payload.b64 ahora se pueden enviar al host de virtualización para su inyección.

Obtener desde libvirt remoto

Este escenario permite obtener ciertos datos de un hipervisor remoto a través de una conexión a libvirt. Ayudará en la depuración al analizar la configuración del invitado e informar cualquier cosa que pueda invalidar la medición del invitado. Este modelo de uso se considera seguro, ya que la información limitada obtenida del hipervisor no confiable no se puede utilizar para cambiar el resultado.

Validar la medición de un invitado SEV que arranca desde disco:

# virt-qemu-sev-validate \
    --connect qemu+ssh://root@some.remote.host/system \
    --firmware OVMF.sev.fd \
    --tk this-guest-tk.bin \
    --domain fedora34x86_64

Obtener desde libvirt local

Este escenario permite obtener todos los datos del hipervisor local a través de una conexión a libvirt. Solo debe usarse con el propósito de pruebas, depuración o demostraciones, ya que ejecutarse en el hipervisor local no es un escenario seguro. Para habilitar este uso, se debe especificar la bandera --insecure. Dado un puntero al invitado libvirt a validar, toda la información necesaria para realizar una validación, excepto el par TIK/TEK, se puede adquirir automáticamente.

Validar la medición de un invitado SEV que arranca desde disco:

# virt-qemu-sev-validate \
    --insecure \
    --tk this-guest-tk.bin \
    --domain fedora34x86_64

Validar la medición de un invitado SEV con arranque directo del kernel:

# virt-qemu-sev-validate \
    --insecure \

LISTA DE ERRORES COMUNES

La complejidad de configurar un invitado y validar su medición de arranque hace que sea muy probable ver el siguiente fallo:

ERROR: Measurement does not match, VM is not trustworthy

Este mensaje de error asume lo peor, pero en la mayoría de los casos el fallo será el resultado de una mala configuración del invitado o de pasar información incorrecta al intentar validarlo. La siguiente información es una guía sobre los elementos a verificar para tener la mejor oportunidad de diagnosticar el problema.

  • Verifique la configuración de la VM para el certificado DH y el blob de sesión en el XML del invitado libvirt.

    El contenido de estos campos debe estar en formato base64, que es lo que genera sevctl session. Otras herramientas pueden generar los archivos en formato binario, así que asegúrese de que se haya convertido correctamente a base64.

  • Verifique que el valor de la política de configuración de la VM coincida con el blob de sesión.

    El valor <policy> en el XML del invitado libvirt debe coincidir con el valor pasado al comando sevctl session. Si no coincide, el invitado ni siquiera se iniciará, y QEMU mostrará un error como:

sev_launch_start: LAUNCH_START ret=1 fw_error=11 'Bad measurement'
  • Verifique que se pasen las claves TIK/TEK correctas.

    Las claves TIK/TEK están vinculadas de forma única a cada certificado DH y blob de sesión. Asegúrese de que las claves TIK/TEK pasadas a este programa sean las que coinciden con el certificado DH y el blob de sesión configurados para el XML del invitado libvirt. Este es uno de los errores más comunes. Además, asegúrese de que los archivos TIK y TEK no estén intercambiados.

  • Verifique que el binario del firmware coincida con el utilizado para arrancar.

    El contenido del binario del firmware es parte de los datos cubiertos por la medición de arranque. Asegúrese de que el binario del firmware pasado a este programa coincida con el utilizado para iniciar el invitado. El host del hipervisor recibirá actualizaciones de software periódicamente que introducen una nueva versión del binario del firmware.

  • Verifique que el kernel, initrd y cmdline coincidan con los utilizados para arrancar.

    Si el invitado está configurado para usar arranque directo del kernel, verifique que el kernel, initrd y cmdline pasados a este programa coincidan con los utilizados para iniciar el invitado. En la línea de comandos del kernel, el espacio en blanco debe preservarse exactamente, incluyendo los espacios iniciales o finales.

  • Verifique si la medición del hash del kernel está habilitada.

    La propiedad kernelHashes en el XML del invitado libvirt controla si los hashes del contenido del kernel, initrd y cmdline están cubiertos por la medición de arranque. Si está habilitado, entonces el contenido coincidente debe pasarse a este programa. Si está deshabilitado, el contenido NO debe pasarse.

ESTADO DE SALIDA

Tras la atestación exitosa de la medición de lanzamiento, se establecerá un estado de salida de 0.

Al fallar la atestación de la medición de lanzamiento, se establecerá uno de los siguientes códigos:

  • 1 - La medición del invitado no se validó

    Suponiendo que las entradas para este programa son correctas, el lanzamiento de la máquina virtual ha sido comprometido y no debe confiarse en él a partir de ahora.

  • 2 - El escenario de uso no puede ser compatible

    La forma en que se ha invocado este programa le impide poder validar la medición de lanzamiento.

  • 3 - El escenario de uso no es seguro

    La forma en que se ha invocado este programa significa que el resultado de cualquier validación de la medición de lanzamiento no será seguro.

    El programa puede ser invocado de nuevo con el argumento --insecure para forzar una validación, sin embargo, los resultados de esta no deben ser confiados. Esto solo debe usarse para fines de prueba, depuración o demostración, nunca en un despliegue de producción.

  • 4 - El dominio tiene una configuración incorrecta para ser medido

    La forma en que se ha configurado el invitado impide que este programa pueda validar la medición de lanzamiento. Tenga en cuenta que, en general, la configuración del invitado informada por el hipervisor no es confiable, por lo que es posible que este error sea un falso positivo diseñado para causar una denegación de servicio.

    Este programa puede ser invocado de nuevo con el argumento --ignore-config para omitir las comprobaciones de cordura en el XML del dominio. Esto probablemente resultará en un fallo con un código de salida de 1, lo que indica que la medición no es válida.

  • 5 - El dominio está en un estado incorrecto para ser medido

    El dominio debe estar en ejecución para poder validar una medición de lanzamiento.

  • 6 - Ocurrió un error inesperado en el código

    Un error de lógica en este programa significa que no puede completar la validación de la medición. Este es un error que debe ser reportado a los mantenedores.
