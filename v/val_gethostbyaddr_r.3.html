NOMBRE

val_gethostbyname(), val_gethostbyname2(), val_gethostbyname_r(), val_gethostbyname2_r() - obtener entrada de host de red validada por DNSSEC

SINOPSIS

#include <validator/validator.h>

                         struct hostent *ret,
                         char *buf,

DESCRIPCIÓN

val_gethostbyname(), val_gethostbyname2(), val_gethostbyname_r(), val_gethostbyname2_r(), val_gethostbyaddr() y val_gethostbyaddr_r() realizan la validación DNSSEC de las consultas DNS. Devuelven un valor de entrada de host de red de tipo struct hostent y son versiones conscientes de DNSSEC de las funciones gethostbyname(3), gethostbyname2(3), gethostbyname_r(), gethostbyname2_r(), gethostbyaddr() y gethostbyaddr_r() respectivamente. (Ver gethostbyname(3) para más información sobre el tipo struct hostent).

val_gethostbyname(), val_gethostbyname_r(), val_gethostbyaddr() y val_gethostbyaddr_r() solo soportan direcciones IPv4. val_gethostbyname2() y val_gethostbyname2_r() soportan direcciones IPv4 e IPv6.

Las funciones val_gethostbyname_r(), val_gethostbyname2_r() y val_gethostbyaddr_r() son versiones reentrantes y pueden utilizarse de forma segura en aplicaciones multihilo.

El parámetro ctx especifica el contexto de validación, que puede establecerse a NULL para valores predeterminados (ver libval(3) y dnsval.conf para más detalles sobre contextos de validación y política de validación).

val_gethostbyname(), val_gethostbyname2() y val_gethostbyaddr() establecen la variable global h_errno para devolver el código de error del resolvedor. Las versiones reentrantes val_gethostbyname_r(), val_gethostbyname2_r() y val_gethostbyaddr_r() utilizan el parámetro h_errnop para devolver este valor. Esto asegura la seguridad de los hilos, al evitar la variable global h_errno. h_errnop no debe ser NULL. (Ver la página del manual de gethostbyname(3) para valores posibles de h_errno.)

Los parámetros name, af, ret, buf, buflen y result tienen la misma sintaxis y semántica que los parámetros correspondientes para las funciones originales gethostbyname*() y gethostbyaddr*(). Ver la página del manual de gethostbyname(3) para más detalles sobre estos parámetros.

El parámetro val_status se utiliza para devolver el código de error del validador y no debe ser NULL. val_istrusted() y val_isvalidated() pueden usarse para determinar la fiabilidad de los datos y p_val_status() puede usarse para mostrar el valor de estado al usuario en formato ASCII (Ver libval(3) para más información).

VALORES DE RETORNO

Las funciones val_gethostbyname(), val_gethostbyname2() y val_gethostbyaddr() devuelven un puntero a una estructura hostent cuando pueden resolver el nombre de host dado (con o sin validación DNSSEC), y NULL si los datos no estaban disponibles. La memoria para el valor devuelto es asignada estáticamente por estas dos funciones. Por lo tanto, el llamante no debe liberar la memoria para el valor devuelto.

Las funciones val_gethostbyname_r(), val_gethostbyname2_r() y val_gethostbyaddr_r() devuelven 0 cuando pueden resolver el nombre de host dado (con o sin validación DNSSEC), y un código de error distinto de cero en caso de fallo.

Las funciones val_gethostbyaddr() y val_gethostbyaddr_r() devuelven 0 cuando pueden resolver el nombre de host dado (con o sin validación DNSSEC), y un código de error distinto de cero en caso de fallo.

El parámetro val_status proporciona una indicación de la fiabilidad de los datos. Si la estructura hostent devuelta es NULL, este valor proporciona una indicación de si la no existencia de datos es confiable o no.

EJEMPLO

#include <stdio.h>
#include <stdlib.h>
#include <validator.h>

   int main(int argc, char *argv[])
   {
        int val_status;
        struct hostent *h = NULL;
        if (argc < 2) {
            printf("Uso: %s <nombre_host>\n", argv[0]);
            exit(1);
        }
        h = val_gethostbyname(NULL, argv[1], &val_status);
        printf("h_errno = %d [%s]\n", h_errno,
            hstrerror(h_errno));
        if (h) {
            printf("Estado de Validación = %d [%s]\n", val_status,
                   p_val_status(val_status));
        }
        return 0;
   }

NOTAS

Estas funciones actualmente no leen el orden de búsqueda de /etc/hosts.conf. Por el momento, el orden predeterminado está configurado para consultar primero el archivo /etc/hosts y luego consultar el DNS.

Las versiones actuales de estas funciones no soportan búsquedas NIS.
