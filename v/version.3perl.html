NOMBRE

version - Extensión de Perl para Objetos de Versión

SINOPSIS

# Parsear cadenas de versión (decimal o decimal con puntos)
use version 0.77; # obtener las últimas correcciones de errores y API
$ver = version->parse($string)
# Declarar una $VERSION decimal con puntos (¡mantener en una sola línea!)
use version; our $VERSION = version->declare("v1.2.3"); # formal
use version; our $VERSION = qv("v1.2.3");               # obsoleto
use version; our $VERSION = qv("v1.2_3");               # obsoleto
# Declarar una $VERSION decimal antigua (¡usar comillas!)
our $VERSION = "1.0203";                                # recomendado
use version; our $VERSION = version->parse("1.0203");   # formal
use version; our $VERSION = version->parse("1.02_03");  # alfa
# Comparar estilos de versión mixtos (decimales, decimales con puntos, objetos)
if ( version->parse($v1) == version->parse($v2) ) {
  # hacer algo
}
# Ordenar estilos de versión mixtos
@ordered = sort { version->parse($a) <=> version->parse($b) } @list;

DESCRIPCIÓN

Los objetos de versión se añadieron a Perl en la versión 5.10. Este módulo implementa objetos de versión para versiones anteriores de Perl y proporciona la API de objetos de versión para todas las versiones de Perl. Todas las versiones anteriores a la 0.74 están obsoletas y no deben usarse debido a cambios incompatibles en la API. La versión 0.77 introduce los nuevos métodos 'parse' y 'declare' para estandarizar el uso. Se recomienda encarecidamente establecer 0.77 como mínimo en su código, por ejemplo:

use version 0.77; # incluso para Perl v.5.10.0

TIPOS DE OBJETOS DE VERSIÓN

Hay dos tipos diferentes de objetos de versión, que corresponden a los dos estilos diferentes de versiones en uso:

Versiones Decimales
El clásico número de punto flotante $VERSION. La ventaja de este estilo es que no necesita hacer nada especial, solo escribir un número en su archivo fuente. Se recomienda el uso de comillas, ya que garantiza que los ceros finales ("1.50") se conserven en cualquier advertencia u otra salida.
Versiones Decimales con Puntos
La forma más moderna de asignación de versión, con 3 (o potencialmente más) enteros separados por puntos decimales (por ejemplo, v1.2.3). Esta es la forma que Perl ha utilizado desde que se lanzó la versión 5.6.0. El prefijo 'v' ahora se recomienda encarecidamente para mayor claridad y generará una advertencia en una versión futura si se omite. Se requiere un carácter 'v' inicial para pasar la prueba "is_strict()".

DECLARANDO VERSIONES

Si tiene un módulo que utiliza una $VERSION decimal (punto flotante) y no tiene la intención de cambiarla nunca, este módulo no es para usted. No hay nada que version.pm le gane a una simple asignación de $VERSION:

our $VERSION = "1.02";

Dado que Perl v5.10.0 incluye la lógica de comparación de version.pm de todos modos, no necesita hacer nada en absoluto.

Cómo convertir un módulo de decimal a decimal con puntos

Si ha utilizado una $VERSION decimal en el pasado y desea cambiar a una $VERSION decimal con puntos, necesita realizar una conversión única al nuevo formato.

Nota importante: debe asegurarse de que su nueva $VERSION sea numéricamente mayor que su $VERSION decimal actual; esto no siempre es obvio. Primero, convierta su antigua versión decimal (por ejemplo, 1.02) a una forma decimal con puntos normalizada:

$ perl -Mversion -e 'print version->parse("1.02")->normal'
v1.20.0

Luego, incremente cualquiera de los componentes decimales con puntos (v1.20.1 o v1.21.0).

Cómo declarar() una versión decimal con puntos

use version; our $VERSION = version->declare("v1.2.3");

El método declare() siempre crea objetos de versión decimal con puntos. Cuando se utiliza en un módulo, debe colocarlo en la misma línea que "use version" para garantizar que $VERSION sea leído correctamente por PAUSE y las herramientas de instalación. También debe agregar 'version' a la sección 'configure_requires' de su archivo de metadatos del módulo. Consulte las instrucciones en ExtUtils::MakeMaker o Module::Build para obtener más detalles.

Nota importante: incluso si pasa lo que parece un número decimal ("1.2"), se creará un número decimal con puntos ("v1.200.0"). Para evitar confusiones o errores involuntarios en versiones anteriores de Perl, siga estas directrices:

  • Siempre use un número decimal con puntos con (al menos) tres componentes
  • Siempre use un prefijo 'v'
  • Siempre ponga la versión entre comillas

Si realmente insiste en usar version.pm con una versión decimal ordinaria, use parse() en lugar de declare. Consulte la sección "PARSING AND COMPARING VERSIONS" para obtener más detalles.

Consulte version::Internals para obtener más información sobre la conversión de números de versión, las comillas, los números de versión calculados y la declaración de números de versión de desarrollador o "alfa".

ANÁLISIS Y COMPARACIÓN DE VERSIONES

Si necesita comparar números de versión, pero no puede estar seguro de si están expresados como números, cadenas, v-strings u objetos de versión, entonces debe usar version.pm para analizarlos todos en objetos para su comparación.

Cómo analizar() una versión

El método parse() toma cualquier cosa que pueda ser una versión y devuelve el objeto de versión correspondiente, realizando cualquier conversión necesaria en el proceso.

  • Decimal con puntos: v-strings sin prefijo (v1.2.3) y cadenas con más de un punto decimal y un prefijo 'v' ("v1.2.3"); NOTA, técnicamente puede usar una v-string o cadenas con un prefijo 'v' y solo un punto decimal (v1.2 o "v1.2"), pero se confundirá a sí mismo y a otros.
  • Decimal: números decimales regulares (literales o en una cadena)

Algunos ejemplos:

$variable   version->parse($variable)
---------   -------------------------
1.23        v1.230.0
"1.23"      v1.230.0
v1.23       v1.23.0
"v1.23"     v1.23.0
"1.2.3"     v1.2.3
"v1.2.3"    v1.2.3

Consulte version::Internals para obtener más información sobre la conversión de números de versión.

Cómo verificar una cadena de versión legal

Si no desea crear un objeto de versión completo, pero aún así le gustaría verificar que una cadena dada cumple los criterios para ser analizada como una versión, hay dos funciones auxiliares que se pueden emplear directamente:

is_lax()
Los criterios laxos corresponden a lo que actualmente permite el analizador de versiones. Todos los siguientes formatos son aceptables para cadenas de formato decimal con puntos: 
v1.2
1.2345.6
v1.23_4
1.2345
1.2345_01
is_strict()
Si desea limitarse a una definición mucho más estrecha de lo que constituye una cadena de versión, is_strict() se limita a cadenas de versión como la siguiente lista: 
v1.234.5
2.3456

Consulte version::Internals para obtener detalles sobre las expresiones regulares que definen las formas de cadenas de versión legales, así como sobre cómo usar esas expresiones regulares en su propio código si is_lax() y is_strict() no son suficientes para sus necesidades.

version(3perl)

DESCRIPTION

This module provides a way to handle version numbers. It allows you to compare version numbers in a way that is consistent and unambiguous.

TYPES OF VERSION OBJECTS

There are two main types of version objects:

Dotted-decimal versions
These are the most common type of version numbers, represented as a series of numbers separated by dots. For example, 1.2.3.
Alpha versions
These are versions that include a trailing underscore segment, indicating an alpha or development release. For example, 1.2_3.

DECLARING VERSIONS

You can declare a version object using the version->declare() method. This method takes a string representing the version number as an argument.

my $v = version->declare('v1.0.2');

PARSING AND COMPARING VERSIONS

You can parse a version string into a version object using the version->parse() method. Once you have version objects, you can compare them using the standard comparison operators.

The comparison operators are overloaded to work with version objects. This means that you can compare version objects directly using operators like ==, !=, <, >, <=, and >=.

The module also implements the other comparison operators based on those two so all the normal logical comparisons will work.

if ( version->parse($v1) == version->parse($v2) ) {
  # do stuff
}

If a version object is compared against a non-version object, the non-object term will be converted to a version object using parse(). This may give surprising results:

$v1 = version->parse("v0.95.0");
$bool = $v1 < 0.94; # TRUE since 0.94 is v0.940.0

Always comparing to a version object will help avoid surprises:

$bool = $v1 < version->parse("v0.94.0"); # FALSE

Note that "alpha" version objects (where the version string contains a trailing underscore segment) compare as less than the equivalent version without an underscore:

$bool = version->parse("1.23_45") < version->parse("1.2345"); # TRUE

See version::Internals for more details on "alpha" versions.

OBJECT METHODS

is_alpha()

True if and only if the version object was created with a underscore, e.g.

version->parse('1.002_03')->is_alpha;  # TRUE
version->declare('1.2.3_4')->is_alpha; # TRUE

is_qv()

True only if the version object is a dotted-decimal version, e.g.

version->parse('v1.2.0')->is_qv;       # TRUE
version->declare('v1.2')->is_qv;       # TRUE
qv('1.2')->is_qv;                      # TRUE
version->parse('1.2')->is_qv;          # FALSE

normal()

Returns a string with a standard 'normalized' dotted-decimal form with a leading-v and at least 3 components.

version->declare('v1.2')->normal;  # v1.2.0
version->parse('1.2')->normal;     # v1.200.0

numify()

Returns a value representing the object in a pure decimal.

version->declare('v1.2')->numify;  # 1.002000
version->parse('1.2')->numify;     # 1.200

to_decimal

This returns a new version object for the numified version, much like "version->parse($v->numify)" would.

version->parse('v1.2')->to_decimal; # 1.002000

to_dotted_decimal

This returns a new version object for the normalized version, much like "version->parse($v->normal)" would.

version->parse('1.002')->to_dotted_decimal; # v1.2.0

tuple()

This turns the components of the version into a list. E.g.

version->parse('1.2.3')->tuple; # (1, 2, 3)

from_tuple(...)

This takes a list of components and creates a dotted decimal version out of it. E.g.

version->from_tuple(1, 2, 3) # v1.2.3

stringify()

Returns a string that is as close to the original representation as possible. If the original representation was a numeric literal, it will be returned the way perl would normally represent it in a string. This method is used whenever a version object is interpolated into a string.

version->declare('v1.2')->stringify;    # v1.2
version->parse('1.200')->stringify;     # 1.2
version->parse(1.02_30)->stringify;     # 1.023

tuple

Returns an array of non-negative integers that is used for comparison purposes with other version objects.

EXPORTED FUNCTIONS

qv()

This function is no longer recommended for use, but is maintained for compatibility with existing code. If you do not want to have it exported to your namespace, use this form:

use version 0.77 ();

is_lax()

(Not exported by default)

This function takes a scalar argument and returns a boolean value indicating whether the argument meets the "lax" rules for a version number. Leading and trailing spaces are not allowed.

is_strict()

(Not exported by default)

This function takes a scalar argument and returns a boolean value indicating whether the argument meets the "strict" rules for a version number. Leading and trailing spaces are not allowed.
