NOMBRE

virt-clone - clonar imágenes de máquinas virtuales existentes

SINOPSIS

virt-clone [OPCIÓN]...

DESCRIPCIÓN

virt-clone es una herramienta de línea de comandos para clonar imágenes de máquinas virtuales existentes utilizando la biblioteca de gestión de hipervisores libvirt. Copiará las imágenes de disco de cualquier máquina virtual existente y definirá un nuevo invitado con una configuración de hardware virtual idéntica. Los elementos que requieren unicidad se actualizarán para evitar conflictos entre invitados antiguos y nuevos.

Por defecto, virt-clone mostrará un error si no se proporciona la información necesaria para clonar el invitado. La opción --auto-clone generará toda la entrada necesaria, aparte del invitado de origen a clonar.

Por favor, tenga en cuenta que virt-clone no cambia nada _dentro_ del sistema operativo invitado; solo duplica discos y realiza cambios en el lado del host. Por lo tanto, cosas como cambiar contraseñas, cambiar direcciones IP estáticas, etc., están fuera del alcance de esta herramienta. Para este tipo de cambios, consulte virt-sysprep.

OPCIONES GENERALES

La mayoría de las opciones no son requeridas. Los requisitos mínimos son --original o --original-xml (para especificar el invitado a clonar), --name y las opciones de almacenamiento apropiadas a través de -file.

--connect URI
Conectarse a un hipervisor no predeterminado. Consulte virt-install(1) para más detalles.
-o, --original INVITADO_ORIGINAL
Nombre del invitado original que se clonará. Este invitado debe estar apagado.
--original-xml XML_ORIGINAL
Archivo XML del invitado libvirt para usar como invitado original. El invitado no necesita estar definido en la conexión libvirt. Esto reemplaza el parámetro --original.
--auto-clone
Generar un nuevo nombre de invitado y rutas para el nuevo almacenamiento.

Un ejemplo de posible salida generada:

Nombre original        : MiVM
Nombre del clon generado : MiVM-clon
Ruta del disco original   : /home/usuario/foobar.img
Ruta del disco generada  : /home/usuario/foobar-clon.img

Si los nombres generados entran en conflicto con VMs o almacenamiento existentes, se añadirá un número, como foobar-clon-1.img o MiVM-clon-3.

-n, --name NOMBRE
Nombre de la nueva instancia de máquina virtual invitada. Debe ser único entre todos los invitados conocidos por la conexión del hipervisor, incluyendo los que no están actualmente activos.
-u, --uuid UUID
UUID para el invitado; si no se proporciona, se generará un UUID aleatorio. Si especifica un UUID, debe usar un número hexadecimal de 32 dígitos. Los UUID están destinados a ser únicos en todo el centro de datos, e incluso en el mundo. Tenga esto en cuenta si especifica manualmente un UUID.
-f, --file RUTA
Ruta al archivo, partición de disco o volumen lógico a utilizar como almacenamiento de respaldo para el disco virtual del nuevo invitado. Si el invitado original tiene varios discos, este parámetro debe repetirse varias veces, una por cada disco en la máquina virtual original.
--nvram ARCHIVO_NVRAM
Ruta opcional al nuevo archivo VARS de nvram; si no se especifica una ruta y el invitado tiene nvram, la nueva ruta de nvram se generará automáticamente. Si el invitado no tiene nvram, esta opción se ignorará.
--force-copy OBJETIVO
Forzar la copia del objetivo de disco pasado ('hdc', 'sda', etc.). Por defecto, virt-clone omitirá ciertos discos, como los marcados como 'readonly' o 'shareable'.
--skip-copy OBJETIVO
Omitir la copia del objetivo de disco pasado ('hdc', 'sda', etc.). Por defecto, virt-clone copiará ciertas imágenes de disco, típicamente dispositivos de lectura/escritura. Use esto para omitir la copia de un dispositivo específico, de modo que la nueva VM utilice la misma ruta de almacenamiento que la VM original.
--nonsparse
Asignar completamente el nuevo almacenamiento si la ruta que se está clonando es un archivo disperso (sparse). Consulte virt-install(1) para más detalles sobre disperso vs. no disperso.
--preserve-data
No se clona ningún almacenamiento: las imágenes de disco especificadas por --file se conservan tal cual y se referencian en el nuevo XML del clon. Esto es útil si desea clonar una plantilla XML de VM, pero no el contenido del almacenamiento.
--reflink
Realizar una copia ligera. Esto es mucho más rápido si las imágenes de origen y destino están todas en el mismo sistema de archivos btrfs. Esto solo funciona para imágenes de disco en formato raw; cualquier imagen no raw no intentará usar reflink.
-m, --mac MAC
Dirección MAC fija para el invitado; si este parámetro se omite, o se especifica el valor RANDOM, se generará una dirección adecuada aleatoriamente. Las direcciones se aplican secuencialmente a las redes según se enumeran en el XML del invitado original.
--print-xml
Imprimir el XML del clon generado y salir sin clonar.
--replace
Antes de clonar, intente un simple virsh destroy y virsh undefine en cualquier VM existente con el --name pasado. Si esas operaciones fallan (como cuando virsh undefine requiere el flag --nvram), el clon fallará y deberá eliminar manualmente la VM existente.
-h, --help
Mostrar el mensaje de ayuda y salir.
--version
Mostrar el número de versión del programa y salir.
--check
Habilitar o deshabilitar algunas comprobaciones de validación. Consulte virt-install(1) para más detalles.
-q, --quiet
Suprimir la salida que no sea de error.
-d, --debug
Imprimir información de depuración en la terminal al ejecutar el proceso de instalación. La información de depuración también se almacena en ~/.cache/virt-manager/virt-clone.log incluso si este parámetro se omite.

EJEMPLOS

Clonar el invitado llamado demo en la conexión predeterminada, generando automáticamente un nuevo nombre y ruta de clonación de disco.

# virt-clone \
     --original demo \
     --auto-clone

Clonar el invitado llamado demo que tiene un solo disco para copiar

# virt-clone \
     --original demo \
     --name nuevodemo \
     --file /var/lib/xen/images/nuevodemo.img

Clonar un invitado QEMU con varios discos

# virt-clone \
     --connect qemu:///system \
     --original demo \
     --name nuevodemo \
     --file /var/lib/xen/images/nuevodemo.img \
     --file /var/lib/xen/images/nuevosdatos.img

Clonar un invitado a un dispositivo físico que sea al menos tan grande como los discos del invitado original. Si el dispositivo de destino es más grande, el nuevo invitado puede redimensionar el sistema de archivos al arrancar.

# virt-clone \
     --connect qemu:///system \
     --original demo \
     --name nuevodemo \
     --file /dev/HostVG/DemoVM \
     --mac 52:54:00:34:11:54
