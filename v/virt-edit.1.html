virt-edit(1) Soporte de Virtualización virt-edit(1)

NOMBRE

virt-edit - Editar un archivo en una máquina virtual

SINOPSIS

virt-edit [--opciones] -d nombre-dominio archivo [archivo ...]
virt-edit [--opciones] -a disco.img [-a disco.img ...] archivo [archivo ...]
virt-edit [-d nombre-dominio|-a disco.img] archivo -e 'expresión'

Estilo antiguo:

virt-edit nombre-dominio archivo
virt-edit disco.img [disco.img ...] archivo

ADVERTENCIA

Usar "virt-edit" en máquinas virtuales en vivo, o concurrentemente con otras herramientas de edición de discos, puede ser peligroso, potencialmente causando corrupción del disco. La máquina virtual debe estar apagada antes de usar este comando, y las imágenes de disco no deben editarse concurrentemente.

DESCRIPCIÓN

"virt-edit" es una herramienta de línea de comandos para editar "archivo" donde cada "archivo" existe en la máquina virtual (o imagen de disco) nombrada.

Se pueden proporcionar múltiples nombres de archivo, en cuyo caso cada uno se edita en secuencia. Cada nombre de archivo debe ser una ruta completa, comenzando desde el directorio raíz (comenzando con '/').

Si solo desea ver un archivo, use virt-cat(1).

Para casos más complejos, debería consultar la herramienta guestfish(1) (ver "USANDO GUESTFISH" a continuación).

"virt-edit" no puede usarse para crear un nuevo archivo. guestfish(1) puede hacer eso y mucho más.

EJEMPLOS

Editar los archivos nombrados interactivamente:

virt-edit -d mi-dominio /boot/grub/grub.conf
virt-edit -d mi-dominio /etc/passwd

Para invitados de Windows, se entienden algunas rutas de Windows:

virt-edit -d mi-dominio-windows 'c:\autoexec.bat'

Si Perl está instalado, también puede editar archivos de forma no interactiva (ver "EDICIÓN NO INTERACTIVA" a continuación). Para cambiar el nivel de inicio predeterminado a 5:

virt-edit -d mi-dominio /etc/inittab -e 's/^id:.*/id:5:initdefault:/'

OPCIONES

--help
Mostrar ayuda breve.
-a archivo
--add archivo
Añade archivo que debe ser una imagen de disco de una máquina virtual. Si la máquina virtual tiene múltiples dispositivos de bloque, debe proporcionar todos ellos con opciones -a separadas.

El formato de la imagen de disco se detecta automáticamente. Para anular esto y forzar un formato particular, use la opción --format=..

-a URI
--add URI
Añadir un disco remoto. Ver "AÑADIR ALMACENAMIENTO REMOTO" en guestfish(1).
-b EXTENSIÓN
--backup EXTENSIÓN
Crea una copia de seguridad del archivo original en la imagen de disco del invitado. La copia de seguridad tiene el nombre de archivo original con la "extensión" añadida.

Generalmente, el primer carácter de "extensión" sería un punto "." así que escribiría:

virt-edit -b .orig [etc]

Por defecto, no se crea ningún archivo de copia de seguridad.

--blocksize=512
--blocksize=4096
--blocksize
Este parámetro establece el tamaño del sector de la imagen de disco. Afecta a todos los discos añadidos explícitamente posteriormente a este parámetro. Usar --blocksize sin argumentos cambia el tamaño del sector del disco al valor predeterminado, que suele ser de 512 bytes. Ver también "guestfs_add_drive_opts" en guestfs(3).
-c URI
--connect URI
Si se usa libvirt, conéctese a la URI dada. Si se omite, nos conectamos al hipervisor libvirt predeterminado.

Si especifica dispositivos de bloque de invitado directamente, entonces libvirt no se usa en absoluto.

-d INVITADO
--domain INVITADO
Añade todos los discos del invitado libvirt nombrado. Se pueden usar UUIDs de dominio en lugar de nombres.
--echo-keys
Al solicitar claves y contraseñas, virt-edit normalmente desactiva el eco para que no pueda ver lo que está escribiendo. Si no le preocupan los ataques Tempest y no hay nadie más en la habitación, puede especificar esta bandera para ver lo que está escribiendo.
-e EXPR
--edit EXPR
--expr EXPR
En lugar de lanzar el editor externo, aplicar de forma no interactiva la expresión Perl "EXPR" a cada línea del archivo. Ver "EDICIÓN NO INTERACTIVA" a continuación.

Tenga cuidado de citar correctamente la expresión para evitar que sea alterada por el shell.

Tenga en cuenta que esta opción solo está disponible cuando Perl 5 está instalado.

--format=raw|qcow2|..
--format
El valor predeterminado para la opción -a es detectar automáticamente el formato de la imagen de disco. Usar esto fuerza el formato del disco para las opciones -a que siguen en la línea de comandos. Usar --format sin argumento revierte a la detección automática para las opciones -a subsiguientes.

Por ejemplo:

virt-edit --format=raw -a disco.img archivo

fuerza el formato raw (sin detección automática) para disk.img.

virt-edit --format=raw -a disco.img --format -a otro.img archivo

fuerza el formato raw (sin detección automática) para disk.img y revierte a la detección automática para otro.img.

Si tiene imágenes de disco de invitado en formato raw no confiables, debería usar esta opción para especificar el formato del disco. Esto evita un posible problema de seguridad con invitados maliciosos (CVE-2010-3851).

--key SELECCIONADOR
Especificar una clave para LUKS, para abrir automáticamente un dispositivo LUKS al usar la inspección.
--key NOMBRE:clave:CADENA_CLAVE
--key UUID:clave:CADENA_CLAVE
--key todo:clave:CADENA_CLAVE
"NOMBRE" es el nombre del dispositivo libguestfs (p.ej., "/dev/sda1"). "UUID" es el UUID del dispositivo. "todo" significa intentar la clave contra cualquier dispositivo cifrado.

Use la "CADENA_CLAVE" especificada como contraseña.

--key NOMBRE:archivo:NOMBRE_ARCHIVO
--key UUID:archivo:NOMBRE_ARCHIVO
--key todo:archivo:NOMBRE_ARCHIVO
Leer la contraseña desde NOMBRE_ARCHIVO.
--key NOMBRE:clevis
--key UUID:clevis
--key todo:clevis
Intentar desbloqueo sin contraseña para el dispositivo con Clevis, a través de la red. Por favor, consulte "DISCOS CIFRADOS" en guestfs(3) para más información sobre el cifrado de disco enlazado a la red.

"key..." son opciones para desbloquear dispositivos cifrados de disco. Si tiene un dispositivo de disco cifrado (por ejemplo, usando LUKS), puede usar estas opciones para desbloquearlo.

Las opciones "key" solo tienen sentido si el disco de invitado está cifrado. Si el disco está cifrado, entonces no está permitido usar un editor interactivo; en su lugar, el comando debe tener la opción "-e" o "--expr". Si la opción "key" se proporciona, entonces se usa en lugar de solicitar la contraseña.

Si se especifica "key:", entonces se busca una contraseña en el archivo.

Si se especifica "clevis", entonces se usa la función Clevis para descifrar la unidad. Véase "ENCRYPTED DISKS" en guestfish(1) para más información.

Si se especifica "key:" o "clevis", entonces un solo dispositivo se desbloquea automáticamente y el comando debe tener la opción "-e" o "--expr".

Si se especifican varias opciones "key", entonces se aplican en orden hasta que un dispositivo se desbloquea. Tenga cuidado de no desbloquear accidentalmente un dispositivo que no debería.

-r
--readonly
Abrir el disco en modo de solo lectura.
-i
--interactive
Forzar modo interactivo incluso si el archivo no se puede editar (por ejemplo, si el archivo es un enlace simbólico).
-l
--list
Listar todos los dispositivos disponibles en el invitado y salir.
-m MOUNTPOINT
--mount MOUNTPOINT
--mount-opt MOUNT_OPT
Montar el dispositivo en MOUNTPOINT. La opción "-m" es un alias para "--mount".

Si se usa "-m" o "--mount", entonces se espera que el invitado tenga un sistema de archivos. La opción "-m" también puede tomar opciones de montaje (p.ej. "-m /dev/VolGroup00/LogVol00:/data:ro").

Si se usa "--mount-opt", se añade a las opciones de montaje predeterminadas (que son "rw", "noatime").

-p
--progress
Mostrar barra de progreso para operaciones de copia.
-q
--quiet
No mostrar mensajes informativos.
-t TYPE
--template TYPE
Si se usa "-d", puede especificar el tipo de invitado. Los tipos comunes son "windows", "linux", "solaris", "macos", etc. El tipo por defecto es "linux".
-u
--unsafe
Esta opción deshabilita ciertas comprobaciones de seguridad que pueden ser lentas. Úsela solo si entiende los riesgos y está seguro de que no está en peligro. Consulte la documentación de libguestfs para más detalles.
-v
--verbose
Mostrar mensajes de depuración.
-x
--xattr
No tocar los atributos extendidos del archivo.
-z
--compress
Comprimir el archivo usando gzip durante la transferencia. Útil para archivos grandes o redes lentas. La contraparte para la descompresión es virt-cat(1).

Hay muchas otras opciones disponibles que se pasan directamente a guestfish(1). Puede verlas ejecutando "guestfish --help".

USANDO GUESTFISH

"virt-edit" es en realidad una interfaz simplificada para guestfish(1). Si está haciendo cualquier cosa remotamente compleja, o si desea tener más control sobre el proceso, es mucho mejor usar guestfish(1) directamente.

Por ejemplo, para editar un archivo en una VM llamada "mi-dominio", puede usar:

guestfish --domain=mi-dominio --edit /etc/passwd

Alternativamente, puede usar el modo interactivo:

guestfish --domain=mi-dominio
> edit /etc/passwd
> list-files /
> exit

Puede obtener ayuda sobre todos los comandos de guestfish en guestfish(1).

EDICIÓN NO INTERACTIVA

El uso de la opción "-e" o "--expr" permite editar archivos de forma no interactiva usando expresiones Perl. La expresión se aplica a cada línea del archivo, y el archivo resultante se escribe de nuevo en el disco.

Por ejemplo, para cambiar todas las apariciones de "viejo" a "nuevo" en el archivo "/tmp/archivo":

virt-edit -d mydomain /tmp/archivo -e 's/viejo/nuevo/g'

Tenga cuidado al citar la expresión para evitar que el shell la altere. Las expresiones pueden volverse complejas rápidamente, y es posible que desee usar guestfish(1) y el comando "perl ..." para obtener más control.

Solo se pueden usar expresiones Perl que no devuelvan nada (es decir, expresiones que solo realizan efectos secundarios como la sustitución). Si la expresión Perl produce una salida, esa salida se imprime en la salida estándar y el archivo original no se modifica.

NOTAS DE SEGURIDAD

Nunca edite discos de invitados en producción sin una copia de seguridad. Los discos de invitados pueden corromperse fácilmente.

Si el invitado está en ejecución, "virt-edit" no tiene forma de saber si los archivos se han modificado desde que se cargó la imagen. Si tiene suerte, la VM se bloqueará si intenta escribir en un archivo que ha sido modificado. Si tiene mala suerte, se corromperá el disco.

Siempre apague la VM antes de editar sus discos.

OPTIONS

-a disk.img
Select a disk image file (e.g. disk.img) to inspect. You can use this option multiple times for virtual disk libraries with multiple components (eg. LVM, MD).

If you use this option, then the guest is not inspected. Instead, the disk image is attached directly to the appliance. This is useful for inspecting or modifying disk images which are not currently attached to a running guest.

The root filesystem is mounted read-only by default. Use --mount or -m to override this.

-c CONNECTION
Connect to the given libvirt connection. The default is "/var/run/libvirt/libvirt-sock" (unix:///var/run/libvirt/libvirt-sock).
-d guestname
Select a guest by its libvirt guest name (guestname).

If you use this option, then the guest is inspected by libguestfs. This is the most common way to use virt-edit.

The guest must be running.

-e perl-snippet
Execute a Perl snippet instead of using the interactive editor. See NON-INTERACTIVE EDITING below. This option can be used multiple times.
-i
Turn on automatic guest filesystem inspection. This is the default.

If you use the -a flag, then guest inspection is turned off by default. Use this flag to turn it back on.

-n
Do not automatically mount the guest's filesystems. You will have to mount them manually using the --mount command if you want to access them. This is usually only useful for debugging. See also --mount.
-q
Quiet mode. Suppresses verbose output, but still prints errors.
-r
Mount the guest's root filesystem read-only. This is the default when inspecting a guest, but not when using -a. Use this flag to ensure the root filesystem is mounted read-only.
-v
--verbose
Enable verbose messages for debugging.
-V
--version
Display version number and exit.
-x
Enable tracing of libguestfs API calls.

EXAMPLE USAGE

Edit a file in a running guest named myguest:

virt-edit -d myguest /etc/hosts

Edit a file in a disk image named disk.img. Assume the filesystem is on the first partition (/dev/sda1) and contains the file /etc/sysconfig/network:

virt-edit -a disk.img -m /dev/sda1 /etc/sysconfig/network

Edit a file on a Windows guest named win7. Note that virt-edit can often guess the correct partition automatically:

virt-edit -d win7 C:\\Documents\\ and\\ Settings\\All\\ Users\\Start\\ Menu\\Programs\\Startup\\shortcut.lnk

Edit a file, but make sure the root filesystem is mounted read-only (this is the default when using -d):

virt-edit -d myguest -r /etc/fstab

Perform a non-interactive edit using Perl:

virt-edit -d myguest /etc/inittab -e 's/^id:.\(.*\):.*/id:3:/'

COMMAND LINE ARGUMENTS

--keys-from-stdin
Read key or passphrase parameters from stdin. The default is to try to read passphrases from the user by opening /dev/tty.

If there are multiple encrypted devices then you may need to supply multiple keys on stdin, one per line.

-m dev:mountpoint:options:fstype
--mount dev:mountpoint:options:fstype
Mount the named partition or logical volume on the given mountpoint.

If the mountpoint is omitted, it defaults to /.

Specifying any mountpoint disables the inspection of the guest and the mount of its root and all of its mountpoints, so make sure to mount all the mountpoints needed to work with the filenames given as arguments.

If you don’t know what filesystems a disk image contains, you can either run guestfish without this option, then list the partitions, filesystems and LVs available (see "list-partitions", "list-filesystems" and "lvs" commands), or you can use the virt-filesystems(1) program.

The third (and rarely used) part of the mount parameter is the list of mount options used to mount the underlying filesystem. If this is not given, then the mount options are either the empty string or "ro" (the latter if the --ro flag is used). By specifying the mount options, you override this default choice. Probably the only time you would use this is to enable ACLs and/or extended attributes if the filesystem can support them:

-m /dev/sda1:/:acl,user_xattr

Using this flag is equivalent to using the "mount-options" command.

The fourth part of the parameter is the filesystem driver to use, such as "ext3" or "ntfs". This is rarely needed, but can be useful if multiple drivers are valid for a filesystem (eg: "ext2" and "ext3"), or if libguestfs misidentifies a filesystem.

-v
--verbose
Enable verbose messages for debugging.
-V
--version
Display version number and exit.
-x
Enable tracing of libguestfs API calls.

OLD-STYLE COMMAND LINE ARGUMENTS

Previous versions of virt-edit allowed you to write either:

virt-edit disk.img [disk.img ...] file

or

virt-edit guestname file

whereas in this version you should use -a or -d respectively to avoid the confusing case where a disk image might have the same name as a guest.

For compatibility the old style is still supported.

NON-INTERACTIVE EDITING

"virt-edit" normally calls out to $EDITOR (or vi) so the system administrator can interactively edit the file.

There are two ways also to use "virt-edit" from scripts in order to make automated edits to files. (Note that although you can use "virt-edit" like this, it’s less error-prone to write scripts directly using the libguestfs API and Augeas for configuration file editing.)

The first method is to temporarily set $EDITOR to any script or program you want to run. The script is invoked as "$EDITOR tmpfile" and it should update "tmpfile" in place however it likes.

The second method is to use the -e parameter of "virt-edit" to run a short Perl snippet in the style of sed(1). For example to replace all instances of "foo" with "bar" in a file:

virt-edit -d domname filename -e 's/foo/bar/'

The full power of Perl regular expressions can be used (see perlre(1)). For example to delete root’s password you could do:

virt-edit -d domname /etc/passwd -e 's/^root:.*?:/root::/'

What really happens is that the snippet is evaluated as a Perl expression for each line of the file. The line, including the final "\n", is passed in $_ and the expression should update $_ or leave it unchanged.

To delete a line, set $_ to the empty string. For example, to delete the "apache" user account from the password file you can do:

virt-edit -d mydomain /etc/passwd -e '$_ = "" if /^apache:/'

To insert a line, prepend or append it to $_. However appending lines to the end of the file is rather difficult this way since there is no concept of "last line of the file" - your expression just doesn't get called again. You might want to use the first method (setting $EDITOR) if you want to do this.

The variable $lineno contains the current line number. As is traditional, the first line in the file is number 1.

The return value from the expression is ignored, but the expression may call "die" in order to abort the whole program, leaving the original file untouched.

Remember when matching the end of a line that $_ may contain the final "\n", or (for DOS files) "\r\n", or if the file does not end with a newline then neither of these. Thus to match or substitute some text at the end of a line, use this regular expression:

/some text(\r?\n)?$/

Alternately, use the perl "chomp" function, being careful not to chomp $_ itself (since that would remove all newlines from the file):

my $m = $_; chomp $m; $m =~ /some text$/

WINDOWS PATHS

"virt-edit" has a limited ability to understand Windows drive letters and paths (eg. E:\foo\bar.txt).

If and only if the guest is running Windows then:

  • Drive letter prefixes like "C:" are resolved against the Windows Registry to the correct filesystem.
  • Any backslash ("\") characters in the path are replaced with forward slashes so that libguestfs can process it.
  • The path is resolved case insensitively to locate the file that should be edited.

There are some known shortcomings:

  • Some NTFS symbolic links may not be followed correctly.
  • NTFS junction points that cross filesystems are not followed.

USING GUESTFISH

guestfish(1) is a more powerful, lower level tool which you can use when "virt-edit" doesn't work.

Using "virt-edit" is approximately equivalent to doing:

guestfish --rw -i -d domname edit /file

where "domname" is the name of the libvirt guest, and /file is the full path to the file.

The command above uses libguestfs’s guest inspection feature and so does not work on guests that libguestfs cannot inspect, or on things like arbitrary disk images that don't contain guests. To edit a file on a disk image directly, use:

guestfish --rw -a disk.img -m /dev/sda1 edit /file

where disk.img is the disk image, /dev/sda1 is the filesystem within the disk image to edit, and /file is the full path to the file.

"virt-edit" cannot create new files. Use the guestfish commands "touch", "write" or "upload" instead:

guestfish --rw -i -d domname touch /newfile
guestfish --rw -i -d domname write /newfile "new content"
guestfish --rw -i -d domname upload localfile /newfile
