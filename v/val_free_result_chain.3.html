DESCRIPCIÓN

La función val_resolve_and_check() consulta un conjunto de servidores de nombres para la tupla <domain_name, type, class> y verifica y valida la respuesta. La verificación implica la comprobación de los RRSIGs, y la validación es la verificación de una cadena de autenticación desde un ancla de confianza configurada.

El parámetro flags se puede utilizar para controlar los resultados de la validación. Los siguientes valores, que se pueden combinar con un OR, están definidos actualmente para este campo:

VAL_QUERY_DONT_VALIDATE
Este flag hace que el validador deshabilite la validación para esta consulta.
VAL_QUERY_IGNORE_SKEW
Este flag hace que el validador deshabilite la comprobación de los tiempos de inicio y expiración de las firmas en los RRSIGs.
VAL_QUERY_AC_DETAIL
Este flag hace que el validador copie los detalles de la cadena de autenticación en el miembro val_rc_answer de la estructura val_result_chain devuelta.
VAL_QUERY_ASYNC
Este flag habilita la resolución asíncrona de consultas para esa búsqueda.
VAL_QUERY_NO_DLV
Este flag hace que el validador deshabilite el procesamiento DLV para esta consulta. Esto solo está disponible si la biblioteca libval(3) ha sido compilada con soporte DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
Al consultar varios servidores de nombres, libsres(3) también intentará varios tamaños de EDNS0, terminando con una consulta que tiene EDNS0 deshabilitado (es decir, sin el bit CD establecido). Este flag hace que libval deshabilite el fallback de EDNS0 para la consulta.
VAL_QUERY_ITERATE
Este flag fuerza a libval a buscar iterativamente la consulta consultando varios servidores de nombres en la jerarquía de delegación, en lugar de solicitar esta información a cualquier servidor de nombres en caché que pueda estar configurado en dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Este flag fuerza a libval a solo mirar su caché mientras intenta resolver un nombre.
VAL_QUERY_SKIP_CACHE
Hay dos niveles de caché que ocurren dentro de libval: a nivel de afirmación y a nivel de respuesta. Este flag fuerza a libval a ignorar los datos en ambas cachés mientras intenta resolver un nombre.
VAL_QUERY_SKIP_ANS_CACHE
Hay dos niveles de caché que ocurren dentro de libval: a nivel de afirmación y a nivel de respuesta. Este flag fuerza a libval a ignorar los datos en la caché de respuestas mientras intenta resolver un nombre. Si ya existe una afirmación para el nombre, clase y tipo dados, esa afirmación se reutiliza hasta que expira. Una vez que expira, el nombre se busca a través de una consulta, incluso si un registro más nuevo (obtenido por otra afirmación en el mismo o diferente contexto) está disponible en su caché de respuestas.

El primer parámetro de val_resolve_and_check() es el contexto del validador. Las aplicaciones pueden crear un nuevo contexto de validador utilizando la función val_create_context(). Esta función analiza los archivos de configuración del resolvedor y del validador y crea el manejador newcontext para esta información analizada. La información almacenada como parte del contexto del validador incluye la política del validador y la política del resolvedor.

Las políticas del validador y del resolvedor se leen de los archivos /etc/dnsval.conf y /etc/resolv.conf por defecto. /etc/root.hints proporciona información de arranque para el validador cuando funciona como un resolvedor completo (ver dnsval.conf(3)). Estos valores predeterminados pueden ser diferentes si se especificó algún otro valor en el momento de la configuración de la biblioteca. Si el archivo de configuración del resolvedor predeterminado no se encuentra en la ubicación especificada, libval también intentará recurrir a /etc/resolv.conf como último recurso.

Las aplicaciones también pueden crear un contexto de validador con una política personalizada utilizando la función val_create_context_ex().

El argumento opt en val_create_context_ex() apunta a la siguiente estructura:

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags especifica los flags de consulta predeterminados para las consultas asociadas con el contexto. Este campo es idéntico al argumento flags en la función val_resolve_and_check().

Los campos vc_val_conf, vc_res_conf y vc_root_conf se pueden usar para especificar archivos de configuración alternativos en lugar de los archivos predeterminados utilizados para la información de configuración del validador, el resolvedor y las pistas raíz.

El campo vc_valpol se puede usar para proporcionar un "fragmento" de configuración de validador personalizado al validador. El validador analiza esta información y la aplica a la configuración del validador predeterminada, ya sea como una extensión o como una anulación, según lo especificado por el campo vc_polflags. El campo vc_nslist, de manera similar, se puede usar para proporcionar una lista personalizada de servidores de nombres recursivos a los que enviar consultas, además de (o en lugar de) la lista de servidores de nombres especificada en el archivo resolv.conf. La lista de servidores de nombres en vc_res_conf debe especificarse como una lista de direcciones IP o IPv6 separadas por espacios.

Se puede crear un mapeo personalizado entre una zona y un servidor de nombres utilizando la función val_context_store_ns_for_zone().

vc_polflags puede configurarse con los siguientes valores:

CTX_DYN_POL_VAL_OVR
Cuando este flag está establecido, solo se utiliza la configuración del validador especificada en el campo vc_valpol para la configuración del validador. Las opciones especificadas en el archivo dnsval.conf se ignoran.
CTX_DYN_POL_RES_OVR
Cuando este flag está establecido, solo se utiliza la configuración del resolvedor especificada en el campo vc_res_conf para la configuración del resolvedor. Las opciones especificadas en el archivo resolv.conf se ignoran.

Los flags de contexto que pueden ser configurados mediante val_context_setqflags() son los flags de consulta para el contexto especificado que se usan en lugar de los flags que se le pasan a la función val_resolve_and_check(). Los flags de consulta que se le pasan a val_resolve_and_check() son combinados (mediante OR) con estos flags de contexto para la consulta.

Las funciones p_val_status(), p_ac_status() y p_val_error() pueden usarse para obtener representaciones en cadena de los diversos estados de validación, estados de la cadena de autenticación y códigos de error, respectivamente. Estas funciones son útiles para la depuración y el registro.

La función val_log_add_optarg() se utiliza para controlar la verbosidad y la ubicación de la salida de los mensajes de registro generados por la biblioteca. El argumento args es una cadena que contiene opciones de línea de comandos de estilo get_opt(), y el argumento use_stderr especifica si los mensajes de registro deben dirigirse a stderr (si es distinto de cero) o a un archivo de registro (si es cero).

Es responsabilidad de la aplicación liberar la memoria asignada para la estructura val_result_chain devuelta por val_resolve_and_check() llamando a val_free_result_chain() cuando ya no sea necesaria. Del mismo modo, la memoria asignada para la estructura val_context_t debe liberarse llamando a val_free_context() cuando ya no sea necesaria.

La función val_context_store_ns_for_zone() permite a una aplicación especificar un servidor de nombres en particular para una zona determinada. Por ejemplo, si una aplicación necesita consultar un servidor de nombres específico para una zona interna, puede usar esta función para configurar el validador para que use ese servidor de nombres para las consultas relacionadas con esa zona.

EJEMPLO

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <validator.h>

int
main(int argc, char **argv)
{
    val_context_t *context = NULL;
    val_status_t status;
    struct val_result_chain *results = NULL;
    char *domain;
    char *type_str;
    int type;
    int ret;

    if (argc != 4) {
        fprintf(stderr, "Usage: %s <domain> <type> <class>\n", argv[0]);
        exit(1);
    }

    domain = argv[1];
    type_str = argv[2];
    
    if (val_parse_type(type_str, &type) != 0) {
        fprintf(stderr, "Invalid type: %s\n", type_str);
        exit(1);
    }

    /* Create a validator context */
    ret = val_create_context("MyValidator", &context);
    if (ret != 0) {
        fprintf(stderr, "Failed to create validator context: %d\n", ret);
        exit(1);
    }

    /* Perform the query and validation */
    ret = val_resolve_and_check(context, domain, IN, type, 0, &results);
    if (ret != 0) {
        fprintf(stderr, "Failed to resolve and check domain: %d\n", ret);
        goto cleanup;
    }

    /* Process the results */
    if (results) {
        status = results->vr_status;
        printf("Domain: %s\n", domain);
        printf("Type: %s\n", type_str);
        printf("Status: %s\n", p_val_status(status));
        printf("Is Trusted: %d\n", val_istrusted(status));
        printf("Is Validated: %d\n", val_isvalidated(status));
        printf("Does Not Exist: %d\n", val_does_not_exist(status));

        /* Print the answer (if available) */
        if (results->vr_answer) {
            printf("Answer:\n");
            /* You would typically iterate through results->vr_answer 
               and print the resource records here. */
            /* For simplicity, we'll just print a message */
            printf("  (Records printed here)\n");
        }
    } else {
        printf("No results found for %s (type %s)\n", domain, type_str);
    }

cleanup:
    /* Free the results and context */
    if (results) {
        val_free_result_chain(results);
    }
    if (context) {
        val_free_context(context);
    }

    return 0;
}

DESCRIPCIÓN

La biblioteca libval proporciona un mecanismo para realizar consultas DNS y validar las respuestas utilizando DNSSEC. El validador DNSSEC se configura al crear un contexto de validador, y las opciones de configuración se pueden modificar y consultar utilizando las funciones de la interfaz val_context_*.

Cuando se crea un contexto de validador, se le pueden pasar un conjunto de indicadores de política que definen el comportamiento del validador. Estos indicadores se pasan en el campo flags al llamar a la función val_context_setflags(). Los indicadores válidos son:

CTX_DYN_POL_RES_OVR
Cuando este indicador está establecido, solo los servidores de nombres especificados en el campo vc_nslist se utilizan para la configuración del resolvedor. Las opciones especificadas en el archivo resolv.conf se ignoran.
CTX_DYN_POL_GLO_OVR
Cuando este indicador está establecido, solo se utilizan las opciones globales definidas en el campo gopt. Las opciones globales especificadas en el archivo dnsval.conf se ignoran.
CTX_DYN_POL_RES_NRD
Cuando este indicador está establecido, las consultas salientes tienen el bit Recursion Desired (RD) establecido en 0. Esto es útil si las consultas necesitan enviarse a un servidor de nombres solo autorizado.

El campo gopt apunta a la siguiente estructura:

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

Establecer un valor de 1 para local_is_trusted es equivalente a especificar la opción trust-oob-answers en el archivo dnsval.conf a yes. De manera similar, establecer los miembros closest_ta_only y rec_fallback a 1 es equivalente a establecer las opciones closest-ta-only y rec-fallback a yes en el archivo dnsval.conf. Un valor de 0 es equivalente al ajuste no para estas opciones.

Establecer el miembro edns0_size a un valor particular tiene el mismo efecto que establecer la opción edns0-size en el archivo dnsval.conf.

Establecer el miembro max_refresh a un valor particular tiene el mismo efecto que establecer la opción max-refresh en el archivo dnsval.conf.

Establecer el miembro proto a un valor particular tiene el mismo efecto que establecer la opción proto en el archivo dnsval.conf.

env_policy y app_policy pueden establecerse a uno de los valores VAL_POL_GOPT_DISABLE, VAL_POL_GOPT_ENABLE, o VAL_POL_GOPT_OVERRIDE. Estos valores corresponden directamente a las opciones disable, enable y override para los ajustes env-policy y app-policy en el archivo dnsval.conf.

Los valores de -1 para los campos anteriores se tratan como condiciones de "ignorar", de modo que el validador no incluirá opciones globales suministradas dinámicamente con un valor de -1 al crear su contexto. Esto permite que una aplicación anule un subconjunto de opciones globales mientras utiliza las opciones globales suministradas en el archivo dnsval.conf por defecto.

El campo log_target permite a la aplicación suministrar destinos de registro *además* de los configurados en el archivo de configuración.

Consulte dnsval.conf(3) para más detalles sobre cómo especificar la política del validador.

Los indicadores de consulta por defecto se pueden establecer y desestablecer para un contexto dado utilizando val_context_setqflags(). Esto permite a una aplicación alterar el procesamiento del validador DNSSEC, mientras aún tiene la mayor parte de la configuración predeterminada más granular especificada en su archivo de configuración. El parámetro action puede establecerse a una de las siguientes opciones:

VAL_CTX_FLAG_SET
Esta opción hace que el validador establezca el indicador dado como uno de los indicadores de consulta por defecto.
VAL_CTX_FLAG_RESET
Esta opción hace que el validador restablezca el indicador dado si fue establecido como uno de los indicadores de consulta por defecto para el contexto.

Las respuestas devueltas por val_resolve_and_check() están disponibles en la lista enlazada *results. Cada respuesta corresponde a un RRset distinto; múltiples RRs dentro del RRset forman parte de la misma respuesta. Son posibles múltiples respuestas cuando el type es ns_t_any o ns_t_rrsig.

Los elementos individuales en *results apuntan a listas enlazadas val_authentication_chain. Los elementos de la cadena de autenticación en val_authentication_chain contienen los RRsets reales devueltos por el servidor de nombres en respuesta a la consulta.

Los valores de resultado de validación devueltos en val_result_chain pueden convertirse en formato ASCII utilizando la función p_val_status(). Los valores de estado de la cadena de autenticación devueltos en cada elemento de la lista enlazada val_authentication_chain pueden convertirse en formato ASCII utilizando las funciones p_ac_status().

Mientras que algunas aplicaciones como las utilidades de resolución de problemas DNSSEC y las herramientas de inspección de paquetes pueden examinar los elementos individuales de la cadena de autenticación para identificar las razones reales del error de validación, la mayoría de las aplicaciones solo estarán interesadas en un único código de error para determinar la autenticidad de los datos.

val_isvalidated() identifica si un valor de estado de resultado de validación dado corresponde a una respuesta que fue verificada criptográficamente y validada utilizando un ancla de confianza configurada localmente.

val_istrusted() identifica si un valor de estado del validador dado es de confianza. Una respuesta puede ser de confianza localmente sin ser validada.

val_does_not_exist() identifica si un valor de estado del validador dado corresponde a uno de los tipos de no existencia.

La biblioteca libval asigna memoria internamente para *results y esta debe ser liberada por la aplicación invocante utilizando la interfaz free_result_chain().

ESTRUCTURAS DE DATOS

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
Cadena de autenticación para un RRset dado.
val_rc_next
Puntero al siguiente RRset en el conjunto de respuestas devueltas para una consulta.
val_rc_proofs
Puntero a las cadenas de autenticación para cualquier prueba de no existencia que se haya devuelto para la consulta.
val_rc_proof_count
Número de elementos de prueba almacenados en val_rc_proofs. El número no puede exceder MAX_PROOFS.
val_rc_alias
Para un elemento val_result_chain que apunta a un alias de nombre, este campo contiene el valor de destino.
val_rc_rrset
Para un elemento val_result_chain que contiene un campo val_rc_answer válido (no NULL), el campo val_rc_rrset apunta al elemento val_rrset_rec de nivel superior en la cadena de autenticación val_rc_answer.
val_rc_status
Estado de validación para un RRset dado. Este puede ser uno de los siguientes:
VAL_SUCCESS
Respuesta recibida y validada con éxito.
VAL_NONEXISTENT_NAME
No había nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante (ámbito NSEC o NSEC3). Los componentes de la prueba también se validaron individualmente.
VAL_NONEXISTENT_TYPE
No existía el tipo para el nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante. Los componentes de la prueba también se validaron individualmente.
VAL_NONEXISTENT_NAME_NOCHAIN
No había nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante. Los componentes de la prueba también se identificaron como confiables, pero no se validaron individualmente.
VAL_NONEXISTENT_TYPE_NOCHAIN
No existía el tipo para el nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante (ámbito NSEC o NSEC3). Los componentes de la prueba también se identificaron como confiables, pero no se validaron individualmente.
VAL_PINSECURE
Se sabía que el registro o algún ancestro del registro en la cadena de autenticación hacia el ancla de confianza era demostrablemente inseguro.
VAL_PINSECURE_UNTRUSTED
Se sabía que el registro o algún ancestro del registro en la cadena de autenticación hacia el ancla de confianza era demostrablemente inseguro. Pero la condición demostrablemente insegura se configuró como no confiable.
VAL_BARE_RRSIG
No es posible la validación DNSSEC, la consulta era para un RRSIG.
VAL_IGNORE_VALIDATION
La política local se configuró para ignorar la validación de la zona de la que se recibieron estos datos.
VAL_UNTRUSTED_ZONE
La política local se configuró para rechazar cualquier dato recibido de la zona dada.
VAL_OOB_ANSWER
La respuesta se obtuvo utilizando algún método Fuera de Banda (Out Of Band), como un archivo de configuración local.
VAL_BOGUS
No se pudo validar la respuesta debido a fallos en la verificación de firmas o a la incapacidad de verificar pruebas en la cadena de autenticación.
VAL_DNS_ERROR
Se encontró algún error durante el procesamiento de DNS.
VAL_INDETERMINATE
No se pudo validar la respuesta debido a metadatos DNSSEC faltantes

LOGGING

libval provides the val_log_add_optarg() function for controlling the verbosity and location of log message output.

The val_log_add_optarg() function takes two arguments: the first argument args is a character-string value that specifies the location and verbosity. The second argument, use_stderr, if set to a value greater than 0 allows libval to send log messages to stderr.

The character string that specifies log target location and verbosity has a specific format:

<debug-level>:<dest-type>[:<dest-options>]

where
<debug-level> is 1-7, for increasing levels of verbosity
<dest-type> is one of file, net, syslog, stderr, stdout
<dest-options> depends on <dest-type>
file:<file-name> (opened in append mode)
net[:<host-name>:<host-port>] (127.0.0.1:1053)
syslog[:facility] (0-23 (default 1 USER))

The log levels can be roughly translated into different types of log messages as follows (the messages returned for each level in this list subsumes the messages returned for the level above it):

3 : Error   : error encountered
4 : Warning : recovering from error
5 : Notice  : gives final validation results for a query
              and details on policy files and labels used
6 : Info    : gives details about the validation process
              and DNS data encountered
7 : Debug   : gives very detailed information about the
              validation process, data, and state.
