VFS_FILEID(8) Herramientas de administración del sistema VFS_FILEID(8)

NOMBRE

vfs_fileid - Genera estructuras file_id con valores únicos de ID de dispositivo para configuraciones de clúster. También agrega formas de romper deliberadamente la coherencia de bloqueo para inodos específicos.

SINOPSIS

objetos vfs = fileid

DESCRIPCIÓN

Este módulo VFS forma parte del conjunto samba(7).

Samba utiliza estructuras file_id para identificar archivos de forma única a efectos de bloqueo. Por defecto, file_id contiene el dispositivo y el número de inodo devueltos por la llamada al sistema stat(). Dado que file_id es un identificador único de un archivo, debe ser el mismo en todos los nodos en una configuración de clúster. Este módulo sobrecarga la operación SMB_VFS_FILE_ID_CREATE() y genera el número de dispositivo basándose en el algoritmo configurado (ver la opción "fileid:algorithm").

Al utilizar el algoritmo fsname o fsid, se requiere una llamada a stat() y statfs() para todos los sistemas de archivos montados para generar el file_id. Si, por ejemplo, un sistema de archivos NFS no responde, dicha llamada podría bloquearse y el proceso smbd quedaría sin respuesta. Utilice las opciones "fileid:fstype deny", "fileid:fstype allow", "fileid:mntdir deny" o "fileid:mntdir allow" para ignorar sistemas de archivos potencialmente no respondientes.

OPCIONES

fileid:algorithm = ALGORITMO

Los algoritmos disponibles son fsname, fsid, next_module. El valor predeterminado es fsname. Así como los siguientes algoritmos heredados: fsname_nodirs, fsname_norootdir, fsname_norootdir_ext y hostname.

El algoritmo fsname genera el ID del dispositivo hasheando el nombre del dispositivo del kernel.

El algoritmo fsid genera el ID del dispositivo a partir del f_fsid devuelto por la llamada al sistema statfs().

El algoritmo next_module permite que el siguiente módulo vfs en la cadena de módulos genere el ID. Esto se utiliza principalmente en combinación con las diversas características 'nolock' que proporciona el módulo fileid.

El algoritmo heredado hostname genera un devid único hasheando el nombre del host y el ID del dispositivo de bajo nivel. También implica fileid:nolock_all_inodes=yes. Esto se puede usar para romper deliberadamente la coherencia de bloqueo en un clúster y con fileid:nolock_max_slots también entre procesos locales dentro de un nodo. NOTA: ¡No lo use sin saber lo que está haciendo! Rompe la semántica de SMB y puede provocar corrupción de datos. Esto implica fileid:nolock_all_inodes=yes.

El algoritmo heredado fsname_nodirs es un alias para usar el algoritmo fsname junto con fileid:nolock_all_dirs=yes. NOTA: ¡No lo use sin saber lo que está haciendo! Rompe la semántica de SMB. Consulte fileid:nolock_paths para un enfoque más detallado.

El algoritmo heredado fsname_norootdir es un alias para usar el algoritmo fsname junto con fileid:nolock_paths = ".". Significa que esto se puede usar para romper deliberadamente la coherencia de bloqueo para el directorio raíz de un recurso compartido.

El algoritmo heredado fsname_norootdir_ext es un alias para usar el algoritmo fsname junto con fileid:nolock_paths = "." y fileid:nolock_max_slots = 18446744073709551615. Significa que esto se puede usar para romper completamente la coherencia de bloqueo para el directorio raíz de un recurso compartido. Incluso los procesos locales ya no son coherentes en el bloqueo.

fileid:mapping = ALGORITMO

Esta opción es la versión heredada de la opción fileid:algorithm, que se utilizaba en versiones anteriores de la característica de mapeo fileid en versiones personalizadas de Samba 3.0.

fileid:fstype deny = LISTA

Lista de tipos de sistemas de archivos que se ignorarán para la generación de file_id.

fileid:fstype allow = LISTA

Lista de tipos de sistemas de archivos que se permitirán para la generación de file_id. Si se establece esta opción, se ignorarán los tipos de sistemas de archivos que no figuren aquí.

fileid:mntdir deny = LISTA

Lista de puntos de montaje de sistemas de archivos que se ignorarán para la generación de file_id.

fileid:mntdir allow = LISTA

Lista de puntos de montaje de sistemas de archivos que se permitirán para la generación de file_id. Si se establece esta opción, se ignorarán los puntos de montaje de sistemas de archivos que no figuren aquí.

fileid:nolock_max_slots = NÚMERO(1-18446744073709551615)

Esta opción altera el comportamiento del algoritmo nolock de forma que también rompe la coherencia de bloqueo entre procesos individuales en el mismo host. El valor predeterminado es tener solo 1 ranura concurrente disponible por host. Al aumentar el número de ranuras, puede especificar cuántos procesos concurrentes pueden trabajar en un inodo dado sin contención; el número debe ser típicamente mayor que el número de núcleos de CPU lógicos, quizás 2 veces el número de núcleos de CPU.

fileid:nolock_all_dirs = BOOL

Esta opción activa el uso del comportamiento de bloqueo nulo (nolock) de fileid para todos los inodos de directorio, lo que puede usarse para romper deliberadamente la coherencia de bloqueo para todos los directorios. NOTA: ¡No lo use sin saber lo que está haciendo! Rompe la semántica de SMB. Consulte fileid:nolock_paths para un enfoque más detallado.

fileid:nolock_all_inodes = BOOL

Esta opción activa el uso del algoritmo de bloqueo nulo (nolock) de fileid para todos los inodos de directorio, lo que puede usarse para romper deliberadamente la coherencia de bloqueo para todos los directorios. NOTA: ¡No lo use sin saber lo que está haciendo! Rompe la semántica de SMB y puede provocar corrupción de datos. Consulte fileid:nolock_paths para un enfoque más detallado.

fileid:nolock_paths = LISTA

Esta opción especifica una lista de rutas que hacen referencia a archivos y/o directorios, que deben utilizar el algoritmo de bloqueo nulo (nolock) de fileid para romper deliberadamente la coherencia de bloqueo para ellos. Las rutas especificadas pueden ser relativas a la raíz del recurso compartido o absolutas. ¡Los nombres son nombres de ruta de Unix que distinguen entre mayúsculas y minúsculas! Tenga en cuenta que todas las rutas solo se evalúan en el momento de la conexión del árbol (tree connect), cuando se está conectando el recurso compartido, a partir de ahí solo se comparan los números de dispositivo e inodo relacionados de la llamada al sistema stat(). Las rutas inexistentes generarán un mensaje de nivel de registro 0. NOTA: ¡Esta opción debe usarse con cuidado ya que rompe la semántica de SMB! Pero puede ayudar en situaciones donde un inodo específico (comúnmente de solo lectura) está muy disputado.

fileid:nolockinode = NÚMERO

Esta opción heredada activa el uso del comportamiento de bloqueo nulo (nolock) de fileid para el inodo configurado, ignorando cualquier ID de dispositivo. Esto se puede usar para romper deliberadamente la coherencia de bloqueo para el archivo o directorio correspondiente en un clúster. El uso de la opción fileid:nolock_paths es mucho más flexible y sencillo de usar.

EJEMPLOS

Uso del módulo fileid con el algoritmo fsid:

        [global]
	vfs objects = fileid
	fileid:algorithm = fsid

Uso del módulo fileid para evitar la carga en inodos muy disputados (lo más probable es que sean de solo lectura).

        [global]
	vfs objects = fileid
	fileid:algorithm = next_module
	fileid:nolock_paths = . ContendedFolder1 /path/to/contended.exe
	fileid:nolock_max_slots = 256
