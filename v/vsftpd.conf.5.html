NOMBRE

vsftpd.conf - archivo de configuración para vsftpd

DESCRIPCIÓN

vsftpd.conf se puede utilizar para controlar diversos aspectos del comportamiento de vsftpd. Por defecto, vsftpd busca este archivo en la ubicación /etc/vsftpd.conf. Sin embargo, puede anular esto especificando un argumento de línea de comandos a vsftpd. El argumento de línea de comandos es la ruta del archivo de configuración para vsftpd. Este comportamiento es útil porque es posible que desee utilizar un inetd avanzado como xinetd para lanzar vsftpd con diferentes archivos de configuración por host virtual.

FORMATO

El formato de vsftpd.conf es muy simple. Cada línea es un comentario o una directiva. Las líneas de comentario comienzan con un # y se ignoran. Una línea de directiva tiene el formato:

opción=valor

Es importante tener en cuenta que es un error poner cualquier espacio entre la opción, = y el valor.

Cada configuración tiene un valor predeterminado compilado que puede modificarse en el archivo de configuración.

OPCIONES BOOLEANAS

A continuación se muestra una lista de opciones booleanas. El valor de una opción booleana puede establecerse en YES o NO.

allow_anon_ssl
Solo se aplica si ssl_enable está activo. Si se establece en YES, se permitirá a los usuarios anónimos utilizar conexiones SSL seguras.

Por defecto: NO

anon_mkdir_write_enable
Si se establece en YES, se permitirá a los usuarios anónimos crear nuevos directorios bajo ciertas condiciones. Para que esto funcione, la opción write_enable debe estar activada, y el usuario ftp anónimo debe tener permiso de escritura en el directorio padre.

Por defecto: NO

anon_other_write_enable
Si se establece en YES, se permitirá a los usuarios anónimos realizar operaciones de escritura distintas de la carga y la creación de directorios, como la eliminación y el cambio de nombre. Generalmente no se recomienda, pero se incluye por completitud.

Por defecto: NO

anon_upload_enable
Si se establece en YES, se permitirá a los usuarios anónimos cargar archivos bajo ciertas condiciones. Para que esto funcione, la opción write_enable debe estar activada, y el usuario ftp anónimo debe tener permiso de escritura en las ubicaciones de carga deseadas. Esta configuración también es necesaria para que los usuarios virtuales carguen; por defecto, los usuarios virtuales se tratan con privilegios anónimos (es decir, máximamente restringidos).

Por defecto: NO

anon_world_readable_only
Cuando está activado, los usuarios anónimos solo podrán descargar archivos que sean legibles por todos. Esto reconoce que el usuario ftp puede ser propietario de archivos, especialmente en presencia de cargas.

Por defecto: YES

anonymous_enable
Controla si se permiten o no los inicios de sesión anónimos. Si está activado, tanto los nombres de usuario ftp como anonymous se reconocen como inicios de sesión anónimos.

Por defecto: YES

ascii_download_enable
Cuando está activado, se respetarán las transferencias de datos en modo ASCII en las descargas.

Por defecto: NO

ascii_upload_enable
Cuando está activado, se respetarán las transferencias de datos en modo ASCII en las cargas.

Por defecto: NO

async_abor_enable
Cuando está activado, se habilitará un comando FTP especial conocido como "async ABOR". Solo los clientes FTP poco recomendables utilizarán esta función. Además, esta función es difícil de manejar, por lo que está desactivada por defecto. Desafortunadamente, algunos clientes FTP se bloquean al cancelar una transferencia a menos que esta función esté disponible, por lo que es posible que desee habilitarla.

Por defecto: NO

background
Cuando está activado, y vsftpd se inicia en modo "listen", vsftpd ejecutará el proceso de escucha en segundo plano. Es decir, el control se devolverá inmediatamente a la shell que lanzó vsftpd.

Por defecto: NO

check_shell
¡Nota! Esta opción solo tiene efecto para compilaciones de vsftpd que no usan PAM. Si está desactivada, vsftpd no verificará /etc/shells en busca de un shell de usuario válido para los inicios de sesión locales.

Por defecto: YES

chmod_enable
Cuando está activado, permite el uso del comando SITE CHMOD. ¡NOTA! Esto solo se aplica a los usuarios locales. Los usuarios anónimos nunca pueden usar SITE CHMOD.

Por defecto: YES

chown_uploads
Si está activado, todos los archivos cargados de forma anónima tendrán la propiedad cambiada al usuario especificado en la configuración chown_username. Esto es útil desde un punto de vista administrativo, y quizás de seguridad.

Por defecto: NO

chroot_list_enable
Si está activado, puede proporcionar una lista de usuarios locales que se colocarán en una jaula chroot() en su directorio de inicio al iniciar sesión. El significado es ligeramente diferente si chroot_local_user se establece en YES. En este caso, la lista se convierte en una lista de usuarios que NO deben colocarse en una jaula chroot(). Por defecto, el archivo que contiene esta lista es /etc/vsftpd.chroot_list, pero puede anularlo con la configuración chroot_list_file.

Por defecto: NO

chroot_local_user
Si se establece en YES, los usuarios locales (por defecto) se colocarán en una jaula chroot() en su directorio de inicio después de iniciar sesión. Advertencia: Esta opción tiene implicaciones de seguridad, especialmente si los usuarios tienen permiso de carga o acceso a shell. Habilite solo si sabe lo que está haciendo. Tenga en cuenta que estas implicaciones de seguridad no son específicas de vsftpd. Se aplican a todos los demonios FTP que ofrecen poner a los usuarios locales en jaulas chroot().

Por defecto: NO

connect_from_port_20
Esto controla si las conexiones de datos de estilo PORT utilizan el puerto 20 (ftp-data) en la máquina del servidor. Por razones de seguridad, algunos clientes pueden insistir en que este sea el caso. Por el contrario, desactivar esta opción permite que vsftpd se ejecute con menos privilegios.

Por defecto: NO (pero el archivo de configuración de ejemplo lo activa)

debug_ssl
Si es verdadero, los diagnósticos de conexión OpenSSL se volcarán en el archivo de registro de vsftpd. (Añadido en v2.0.6).

Por defecto: NO

delete_failed_uploads
Si es verdadero, se eliminarán los archivos de carga fallidos. (Añadido en v2.0.7).

Por defecto: NO

deny_email_enable
Si está activado, puede proporcionar una lista de respuestas de correo electrónico de contraseña anónima que provoquen la denegación del inicio de sesión. Por defecto, el archivo que contiene esta lista es /etc/vsftpd.banned_emails, pero puede anularlo con la configuración banned_email_file.

Por defecto: NO

dirlist_enable
Si se establece en NO, todos los comandos de listado de directorios darán un error de permiso denegado.

Por defecto: YES

dirmessage_enable
Si está activado, se pueden mostrar mensajes a los usuarios del servidor FTP cuando ingresan por primera vez a un nuevo directorio. Por defecto, se escanea un directorio en busca del archivo .message, pero eso puede ser anulado con la configuración message_file.

Por defecto: NO (pero el archivo de configuración de ejemplo lo activa)

download_enable
Si se establece en NO, todas las solicitudes de descarga darán un error de permiso denegado.

Por defecto: YES

"#dual_log_enable">dual_log_enable
Si está habilitado, se generan dos archivos de registro en paralelo, que por defecto van a /var/log/xferlog y /var/log/vsftpd.log. El primero es un registro de transferencias estilo wu-ftpd, que se puede analizar con herramientas estándar. El segundo es un registro estilo propio de vsftpd.

Por defecto: NO

force_dot_files
Si se activa, los archivos y directorios que comiencen con un punto se mostrarán en los listados de directorios incluso si el cliente no usó el indicador "a". Esto anula la exclusión de las entradas "." y "..".

Por defecto: NO

force_anon_data_ssl
Solo se aplica si ssl_enable está activado. Si está activado, todos los inicios de sesión anónimos se ven obligados a usar una conexión SSL segura para enviar y recibir datos en las conexiones de datos.

Por defecto: NO

force_anon_logins_ssl
Solo se aplica si ssl_enable está activado. Si está activado, todos los inicios de sesión anónimos se ven obligados a usar una conexión SSL segura para enviar la contraseña.

Por defecto: NO

force_local_data_ssl
Solo se aplica si ssl_enable está activado. Si está activado, todos los inicios de sesión no anónimos se ven obligados a usar una conexión SSL segura para enviar y recibir datos en las conexiones de datos.

Por defecto: SÍ

force_local_logins_ssl
Solo se aplica si ssl_enable está activado. Si está activado, todos los inicios de sesión no anónimos se ven obligados a usar una conexión SSL segura para enviar la contraseña.

Por defecto: SÍ

guest_enable
Si está habilitado, todos los inicios de sesión no anónimos se clasifican como inicios de sesión de "invitado". Un inicio de sesión de invitado se reasigna al usuario especificado en la configuración guest_username.

Por defecto: NO

hide_ids
Si está habilitado, toda la información de usuario y grupo en los listados de directorios se mostrará como "ftp".

Por defecto: NO

implicit_ssl
Si está habilitado, se espera un handshake SSL como primera acción en todas las conexiones (el protocolo FTPS). Para admitir SSL explícito y/o texto plano, se debe ejecutar un proceso de escucha de vsftpd separado.

Por defecto: NO

listen
Si está habilitado, vsftpd se ejecutará en modo independiente. Esto significa que vsftpd no debe ejecutarse desde ningún tipo de inetd. En su lugar, el ejecutable de vsftpd se ejecuta una vez directamente. vsftpd se encargará de escuchar y manejar las conexiones entrantes.

Por defecto: NO

listen_ipv6
Similar al parámetro listen, excepto que vsftpd escuchará en un socket IPv6 en lugar de uno IPv4. Este parámetro y el parámetro listen son mutuamente excluyentes.

Por defecto: NO

local_enable
Controla si se permiten o no los inicios de sesión locales. Si está habilitado, se pueden utilizar las cuentas de usuario normales en /etc/passwd (o donde sea que referencie su configuración de PAM) para iniciar sesión. Esto debe estar habilitado para que funcione cualquier inicio de sesión no anónimo, incluidos los usuarios virtuales.

Por defecto: NO

lock_upload_files
Cuando está habilitado, todas las cargas proceden con un bloqueo de escritura en el archivo de carga. Todas las descargas proceden con un bloqueo de lectura compartido en el archivo de descarga. ¡ADVERTENCIA! Antes de habilitar esto, tenga en cuenta que los lectores maliciosos podrían agotar los recursos de un escritor que desee, por ejemplo, anexar un archivo.

Por defecto: SÍ

log_ftp_protocol
Cuando está habilitado, se registran todas las solicitudes y respuestas FTP, siempre que la opción xferlog_std_format no esté habilitada. Útil para depuración.

Por defecto: NO

ls_recurse_enable
Cuando está habilitado, esta configuración permitirá el uso de "ls -R". Este es un riesgo de seguridad menor, ya que un ls -R en el nivel superior de un sitio grande puede consumir muchos recursos.

Por defecto: NO

mdtm_write
Cuando está habilitado, esta configuración permitirá a MDTM establecer las horas de modificación de archivos (sujeto a las comprobaciones de acceso habituales).

Por defecto: SÍ

no_anon_password
Cuando está habilitado, esto evita que vsftpd solicite una contraseña anónima; el usuario anónimo iniciará sesión directamente.

Por defecto: NO

no_log_lock
Cuando está habilitado, esto evita que vsftpd tome un bloqueo de archivo al escribir en los archivos de registro. Generalmente, esta opción no debe habilitarse. Existe para solucionar errores del sistema operativo, como la combinación de sistemas de archivos Solaris / Veritas que se ha observado que a veces presenta bloqueos al intentar bloquear archivos de registro.

Por defecto: NO

one_process_model
Si tiene un kernel de Linux 2.4, es posible utilizar un modelo de seguridad diferente que solo utiliza un proceso por conexión. Es un modelo de seguridad menos puro, pero le da más rendimiento. Realmente no querrá habilitar esto a menos que sepa lo que está haciendo y su sitio admita un gran número de usuarios conectados simultáneamente.

Por defecto: NO

passwd_chroot_enable
Si está habilitado, junto con chroot_local_user, entonces se puede especificar una ubicación de "jail" chroot() por usuario. La "jail" de cada usuario se deriva de su directorio principal en /etc/passwd. La aparición de /./ en la cadena del directorio principal indica que la "jail" está en esa ubicación particular del camino.

Por defecto: NO

pasv_addr_resolve
Establecer en SÍ si desea utilizar un nombre de host (en lugar de una dirección IP) en la opción pasv_address.

Por defecto: NO

pasv_enable
Establecer en NO si desea prohibir el método PASV para obtener una conexión de datos.

Por defecto: SÍ

pasv_promiscuous
Establecer en SÍ si desea deshabilitar la verificación de seguridad PASV que garantiza que la conexión de datos se origina en la misma dirección IP que la conexión de control. ¡Solo habilite si sabe lo que está haciendo! El único uso legítimo para esto es en alguna forma de esquema de túnel seguro, o quizás para facilitar el soporte FXP.

Por defecto: NO

port_enable
Establecer en NO si desea prohibir el método PORT para obtener una conexión de datos.

Por defecto: SÍ

port_promiscuous
Establecer en SÍ si desea deshabilitar la verificación de seguridad PORT que garantiza que las conexiones de datos salientes solo pueden conectarse al cliente. ¡Solo habilite si sabe lo que está haciendo!

Por defecto: NO

require_cert
Si se establece en sí, se requerirá que todas las conexiones de clientes SSL presenten un certificado de cliente. El grado de validación aplicado a este certificado está controlado por validate_cert (Agregado en v2.0.6).

Por defecto: NO

require_ssl_reuse
Si se establece en sí, se requerirá que todas las conexiones de datos SSL muestren reutilización de sesión SSL (lo que demuestra que conocen el mismo secreto maestro que el canal de control). Aunque este es un valor predeterminado seguro, puede romper muchos clientes FTP, por lo que es posible que desee deshabilitarlo. Para una discusión de las consecuencias, vea http://scarybeastsecurity.blogspot.com/2009/02/vsftpd-210-released.html (Agregado en v2.1.0).

Por defecto: SÍ

run_as_launching_user
Establecer en SÍ si desea que vsftpd se ejecute como el usuario que lanzó vsftpd. Esto es útil cuando no se dispone de acceso root. ¡ADVERTENCIA MASIVA! NO habilite esta opción a menos que sepa completamente lo que está haciendo, ya que el uso ingenuo de esta opción puede crear problemas de seguridad masivos. Específicamente, vsftpd no utiliza / no puede utilizar la tecnología chroot para restringir el acceso a archivos cuando esta opción está configurada (incluso si la inició root). Una sustitución pobre podría ser usar una configuración de deny_file como {/*,*..*}, pero la fiabilidad de esto no puede compararse con chroot y no debe confiarse en ella. Si usa esta opción, se aplican muchas restricciones en otras opciones. Por ejemplo, no se espera que funcionen las opciones que requieren privilegios, como los inicios de sesión no anónimos, el cambio de propiedad de carga, la conexión desde el puerto 20 y los puertos de escucha menores a 1024. Otras opciones pueden verse afectadas.

Por defecto: NO

secure_email_list_enable
Establecer en SÍ si desea que solo se acepten contraseñas de correo electrónico de una lista especificada para inicios de sesión anónimos. Esto es útil como una forma sencilla de restringir el acceso a contenido de baja seguridad sin necesidad de usuarios virtuales. Cuando está habilitado, se prohíben los inicios de sesión anónimos a menos que la contraseña proporcionada esté en la lista del archivo especificado por la configuración email_password_file. El formato del archivo es una contraseña por línea, sin espacios adicionales. El nombre de archivo predeterminado es /etc/vsftpd.email_passwords.

Por defecto: NO

session_support
Esto controla si vsftpd intenta mantener sesiones para los inicios de sesión. Si vsftpd mantiene sesiones, intentará y actualizará utmp y wtmp. También abrirá una sesión pam si usa PAM para la autenticación, y solo la cerrará al cerrar sesión. Es posible que desee deshabilitar esto si no necesita el registro de sesiones y desea

OPCIONES MISCELÁNEAS

secure_chroot
Si está habilitado, vsftpd intentará hacer un chroot al directorio del usuario después de que se haya realizado la autenticación. Esto está diseñado para dar a vsftpd más oportunidad de ejecutarse con menos procesos y/o menos privilegios. NOTA: el soporte para utmp y wtmp solo se proporciona con compilaciones con PAM habilitado.

Predeterminado: NO

setproctitle_enable
Si está habilitado, vsftpd intentará mostrar información de estado de la sesión en la lista de procesos del sistema. En otras palabras, el nombre reportado del proceso cambiará para reflejar lo que está haciendo una sesión de vsftpd (inactivo, descargando, etc.). Probablemente querrá dejar esto desactivado por motivos de seguridad.

Predeterminado: NO

ssl_enable
Si está habilitado, y vsftpd se compiló contra OpenSSL, vsftpd soportará conexiones seguras a través de SSL. Esto se aplica a la conexión de control (incluido el inicio de sesión) y también a las conexiones de datos. También necesitará un cliente con soporte SSL. ¡¡NOTA!! Tenga cuidado al habilitar esta opción. Habilítela solo si la necesita. vsftpd no puede garantizar la seguridad de las bibliotecas OpenSSL. Al habilitar esta opción, usted declara que confía en la seguridad de su biblioteca OpenSSL instalada.

Predeterminado: NO

ssl_request_cert
Si está habilitado, vsftpd solicitará (pero no necesariamente requerirá; ver require_cert) uncertificadoenconexionesSSLentrantes.Normalmenteesto no debería causar ningún problema, pero IBM zOS parece tener problemas. (Nuevo en v2.0.7).

Predeterminado: SÍ

ssl_sslv2
Solo se aplica si ssl_enable está activado. Si está habilitado, esta opción permitirá conexiones con el protocolo SSL v2. Se prefieren las conexiones TLS v1.2+.

Predeterminado: NO

ssl_sslv3
Solo se aplica si ssl_enable está activado. Si está habilitado, esta opción permitirá conexiones con el protocolo SSL v3. Se prefieren las conexiones TLS v1.2+.

Predeterminado: NO

ssl_tlsv1
Solo se aplica si ssl_enable está activado. Si está habilitado, esta opción permitirá conexiones con el protocolo TLS v1.0. Se prefieren las conexiones TLS v1.2+.

Predeterminado: NO

ssl_tlsv11
Solo se aplica si ssl_enable está activado. Si está habilitado, esta opción permitirá conexiones con el protocolo TLS v1.1. Se prefieren las conexiones TLS v1.2+.

Predeterminado: NO

ssl_tlsv12
Solo se aplica si ssl_enable está activado. Si está habilitado, esta opción permitirá conexiones con el protocolo TLS v1.2. Se prefieren las conexiones TLS v1.2+.

Predeterminado: SÍ

ssl_tlsv13
Solo se aplica si ssl_enable está activado. Si está habilitado, esta opción permitirá conexiones con el protocolo TLS v1.3. Se prefieren las conexiones TLS v1.2+.

Predeterminado: SÍ

strict_ssl_read_eof
Si está habilitado, las cargas de datos SSL deben terminar a través de SSL, no con un EOF en el socket. Esta opción es necesaria para asegurarse de que un atacante no haya terminado una carga prematuramente con un FIN de TCP falsificado. Desafortunadamente, no está habilitada por defecto porque muy pocos clientes la implementan correctamente. (Nuevo en v2.0.7).

Predeterminado: NO

strict_ssl_write_shutdown
Si está habilitado, las descargas de datos SSL deben terminar a través de SSL, no con un EOF en el socket. Esto está desactivado por defecto ya que no pude encontrar un solo cliente FTP que haga esto. Es menor. Lo único que afecta es nuestra capacidad para determinar si el cliente confirmó la recepción completa del archivo. Incluso sin esta opción, el cliente puede verificar la integridad de la descarga. (Nuevo en v2.0.7).

Predeterminado: NO

syslog_enable
Si está habilitado, cualquier salida de registro que de otro modo iría a /var/log/vsftpd.log irá al registro del sistema en su lugar. El registro se realiza bajo la instalación FTPD.

Predeterminado: NO

tcp_wrappers
Si está habilitado, y vsftpd se compiló con soporte para tcp_wrappers, las conexiones entrantes se procesarán a través del control de acceso tcp_wrappers. Además, existe un mecanismo para la configuración basada en IP por cada conexión. Si tcp_wrappers establece la variable de entorno VSFTPD_LOAD_CONF, la sesión de vsftpd intentará cargar el archivo de configuración de vsftpd especificado en esta variable.

Predeterminado: NO

text_userdb_names
Por defecto, se muestran los IDs numéricos en los campos de usuario y grupo de los listados de directorios. Puede obtener nombres textuales habilitando este parámetro. Está desactivado por defecto por razones de rendimiento.

Predeterminado: NO

tilde_user_enable
Si está habilitado, vsftpd intentará resolver nombres de ruta como ~chris/pics, es decir, una tilde seguida de un nombre de usuario. Tenga en cuenta que vsftpd siempre resolverá los nombres de ruta ~ y ~/algo (en este caso, la ~ se resuelve en el directorio de inicio de sesión inicial). Tenga en cuenta que las rutas ~usuario solo se resolverán si el archivo /etc/passwdse puede encontrar dentro de la jail actual de _chroot().

Predeterminado: NO

use_localtime
Si está habilitado, vsftpd mostrará los listados de directorios con la hora en su zona horaria local. El valor predeterminado es mostrar la hora GMT. Las horas devueltas por el comando FTP MDTM también se ven afectadas por esta opción.

Predeterminado: NO

use_sendfile
Una configuración interna utilizada para probar el beneficio relativo de usar la llamada al sistema sendfile() en su plataforma.

Predeterminado: SÍ

userlist_deny
Esta opción se examina si userlist_enable está activado. Si establece esta configuración en NO, se denegará el inicio de sesión a los usuarios a menos que estén explícitamente listados en el archivo especificado por userlist_file. Cuando se deniega el inicio de sesión, la denegación se emite antes de que se solicite la contraseña al usuario.

Predeterminado: SÍ

userlist_enable
Si está habilitado, vsftpd cargará una lista de nombres de usuario, del nombre de archivo dado por userlist_file. Si un usuario intenta iniciar sesión usando un nombre en este archivo, se le denegará antes de que se le solicite la contraseña. Esto puede ser útil para evitar que se transmitan contraseñas en texto plano. Ver también userlist_deny.

Predeterminado: NO

validate_cert
Si se establece en sí, todos los certificados de cliente SSL recibidos deben validarse correctamente. Los certificados autofirmados no constituyen una validación correcta. (Nuevo en v2.0.6).

Predeterminado: NO

virtual_use_local_privs
Si está habilitado, los usuarios virtuales utilizarán los mismos privilegios que los usuarios locales. Por defecto, los usuarios virtuales utilizarán los mismos privilegios que los usuarios anónimos, que tienden a ser más restrictivos (especialmente en términos de acceso de escritura).

Predeterminado: NO

write_enable
Esto controla si se permiten o no los comandos FTP que modifican el sistema de archivos. Estos comandos son: STOR, DELE, RNFR, RNTO, MKD, RMD, APPE y SITE.

Predeterminado: NO

xferlog_enable
Si está habilitado, se mantendrá un archivo de registro detallando las cargas y descargas. Por defecto, este archivo se colocará en /var/log/vsftpd.log, pero esta ubicación puede ser anulada usando la configuración vsftpd_log_file.

Predeterminado: NO (pero el archivo de configuración de ejemplo lo habilita)

xferlog_std_format
Si está habilitado, el archivo de registro de transferencias se escribirá en el formato xferlog estándar, tal como lo usa wu-ftpd. Esto es útil porque puede reutilizar los generadores de estadísticas de transferencias existentes. Sin embargo, el formato predeterminado es más legible. La ubicación predeterminada para este estilo de archivo de registro es /var/log/xferlog, pero puede cambiarlo con la configuración xferlog_file.

Predeterminado: NO

OPCIONES NUMÉRICAS

A continuación se muestra una lista de opciones numéricas. Una opción numérica debe establecerse en un entero no negativo. Se admiten números octales, para conveniencia de las opciones umask. Para especificar un número octal, use 0 como primer dígito del número.

accept_timeout
El tiempo de espera, en segundos, para que un cliente remoto establezca conexión con una conexión de datos de estilo PASV.

Predeterminado: 60

deny_file
Esta opción se puede utilizar para establecer un patrón para nombres de archivo (y nombres de directorio etc.) a los que no se debe poder acceder de ninguna manera. Los elementos afectados no se ocultan, pero cualquier intento de hacer algo con ellos (descargar, cambiarse a un directorio, afectar algo dentro del directorio, etc.) será denegado. Esta opción es muy simple y no debe usarse para control de acceso serio: las permisos del sistema de archivos deben usarse en preferencia. Sin embargo, esta opción puede ser útil en ciertas configuraciones de usuarios virtuales. En particular, tenga en cuenta que si un nombre de archivo es accesible por una variedad de nombres (quizás debido a enlaces simbólicos o duros), entonces se debe tener cuidado para denegar el acceso a todos los nombres. Se denegará el acceso a elementos si su nombre contiene la cadena dada por hide_file, o si coinciden con la expresión regular especificada por hide_file. Tenga en cuenta que el código de coincidencia de expresiones regulares de vsftpd es una implementación simple que es un subconjunto de la funcionalidad completa de expresiones regulares. Debido a esto, deberá probar cuidadosa y exhaustivamente cualquier aplicación de esta opción. Y se recomienda utilizar los permisos del sistema de archivos para cualquier política de seguridad importante debido a su mayor fiabilidad. La sintaxis de expresiones regulares admitida es cualquier número de operadores *, ? y {,} no anidados. La coincidencia de expresiones regulares solo se admite en el último componente de una ruta, por ejemplo, a/b/? es compatible pero a/?/c no lo es. Ejemplo: deny_file={*.mp3,*.mov,.private}
