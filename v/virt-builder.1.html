NOMBRE

virt-builder - Construye imágenes de máquinas virtuales rápidamente

SINOPSIS

virt-builder os-version
   [-o|--output DISKIMAGE] [--size SIZE] [--format raw|qcow2]
   [--arch ARCHITECTURE] [--attach ISOFILE]
   [--append-line FILE:LINE] [--chmod PERMISSIONS:FILE]
   [--chown UID:GID:PATH] [--commands-from-file FILENAME]
   [--copy SOURCE:DEST] [--copy-in LOCALPATH:REMOTEDIR]
   [--delete PATH] [--edit FILE:EXPR] [--firstboot SCRIPT]
   [--firstboot-command 'CMD+ARGS'] [--firstboot-install PKG,PKG..]
   [--hostname HOSTNAME] [--inject-blnsvr METHOD]
   [--inject-qemu-ga METHOD] [--inject-virtio-win METHOD]
   [--install PKG,PKG..] [--link TARGET:LINK[:LINK..]] [--mkdir DIR]
   [--move SOURCE:DEST] [--password USER:SELECTOR]
   [--root-password SELECTOR] [--run SCRIPT]
   [--run-command 'CMD+ARGS'] [--scrub FILE] [--sm-attach SELECTOR]
   [--sm-register] [--sm-remove] [--sm-unregister]
   [--ssh-inject USER[:SELECTOR]] [--tar-in TARFILE:REMOTEDIR]
   [--timezone TIMEZONE] [--touch FILE] [--truncate FILE]
   [--truncate-recursive PATH] [--uninstall PKG,PKG..] [--update]
   [--upload FILE:DEST] [--write FILE:CONTENT] [--no-logfile]
   [--password-crypto md5|sha256|sha512] [--no-selinux-relabel]
   [--selinux-relabel] [--sm-credentials SELECTOR]
virt-builder -l|--list [--long] [--list-format short|long|json] [os-version]
virt-builder --notes os-version
virt-builder --print-cache
virt-builder --cache-all-templates
virt-builder --delete-cache
virt-builder --get-kernel DISKIMAGE
   [--format raw|qcow2] [--output OUTPUTDIR]

DESCRIPCIÓN

Virt-builder es una herramienta para construir rápidamente nuevas máquinas virtuales. Puede construir una variedad de VMs para uso local o en la nube, generalmente en unos pocos minutos o menos. Virt-builder también tiene muchas formas de personalizar estas VMs. Todo se ejecuta desde la línea de comandos y nada requiere privilegios de root, por lo que la automatización y la creación de scripts son sencillas.

Tenga en cuenta que virt-builder no instala clientes desde cero. Toma plantillas de SO preparadas limpiamente y firmadas digitalmente y las personaliza. Este enfoque se utiliza porque es mucho más rápido, pero si necesita hacer instalaciones limpias, puede consultar virt-install(1) y oz-install(1).

La forma más fácil de empezar es mirando los ejemplos en la siguiente sección.

EJEMPLOS

Listar las máquinas virtuales disponibles

virt-builder --list

listará los sistemas operativos disponibles para instalar. Una selección de sistemas operativos redistribuibles libremente está disponible como estándar. También puede añadir los suyos propios (ver más abajo).

Después de elegir un invitado de la lista, puede que desee ver si hay alguna nota de instalación:

virt-builder --notes fedora-41

Construir una máquina virtual

virt-builder fedora-41

construirá una imagen de Fedora 41 para la misma arquitectura que virt-builder (así que ejecutarlo desde una instalación i686 intentará construir una imagen i686, si está disponible). Esto tendrá toda la configuración por defecto (tamaño mínimo, sin cuentas de usuario, contraseña de root aleatoria, solo el software mínimo instalado, etc.).

NO necesita ejecutar este comando como root.

La primera vez que se ejecuta, tiene que descargar la plantilla a través de la red, pero esto se almacena en caché (ver "CACHING").

El nombre del archivo de salida se deriva del nombre de la plantilla, así que arriba será fedora-41.img. Puede cambiar el nombre del archivo de salida usando la opción -o:

virt-builder fedora-41 -o mydisk.img

También puede usar la opción -o para escribir en dispositivos existentes o volúmenes lógicos.

virt-builder fedora-41 --format qcow2

Como lo anterior, pero escribe la salida en formato qcow2 en fedora-41.qcow2.

virt-builder fedora-41 --size 20G

Como lo anterior, pero el tamaño de la salida será de 20 GB. El SO invitado se redimensiona al copiarse a la salida (automáticamente, usando virt-resize(1)).

virt-builder fedora-41 --arch i686

Como lo anterior, pero usando una plantilla i686, si está disponible.

Establecer la contraseña de root

virt-builder fedora-41 --root-password file:/tmp/rootpw

Crea una imagen de Fedora 41. La contraseña de root se toma del archivo /tmp/rootpw.

Tenga en cuenta que si no establece --root-password, entonces al invitado se le da una contraseña de root aleatoria que se imprime en la salida estándar.

También puede crear cuentas de usuario. Ver "USUARIOS Y CONTRASEÑAS" a continuación.

Establecer el nombre de host

virt-builder fedora-41 --hostname virt.example.com

Establece el nombre de host a "virt.example.com".

Instalar software

Para instalar paquetes del repositorio de software ordinario (invitado) (por ejemplo, dnf o apt):

virt-builder fedora-41 --install "inkscape,@Xfce Desktop"

(En Fedora, "@" se usa para instalar grupos de paquetes. En Debian se instalaría un metapackete en su lugar.)

Para actualizar los paquetes instalados a la última versión:

virt-builder debian-7 --update

Personalizar la instalación

Hay muchas opciones que le permiten personalizar la instalación. Estas incluyen: --run/--run-command, que ejecutan un script de shell o un comando mientras se está generando la imagen del disco y le permiten añadir o editar archivos que van en la imagen del disco. --firstboot/--firstboot-command, que le permiten añadir scripts/comandos que se ejecutan la primera vez que arranca el invitado. --edit para editar archivos. --upload para subir archivos.

Por ejemplo:

cat <<'EOF' > /tmp/dnf-update.sh
dnf -y --best update
EOF

virt-builder fedora-41 --firstboot /tmp/dnf-update.sh

o simplemente:

virt-builder fedora-41 --firstboot-command 'dnf -y --best update'

que hace que el comando dnf(8) "update" se ejecute una vez la primera vez que arranca el invitado.

O:

virt-builder fedora-41 \
  --edit '/etc/dnf/dnf.conf:
            s/gpgcheck=1/gpgcheck=0/'

que edita /etc/dnf/dnf.conf dentro de la imagen del disco (durante la creación de la imagen del disco, mucho antes del arranque).

Puede combinar estas opciones y tener múltiples opciones de todos los tipos.

OPCIONES

--help
Muestra la ayuda.
--arch ARQUITECTURA
Usa la arquitectura especificada para la imagen de salida. Esto significa que debe haber fuentes que proporcionen la plantilla solicitada para la arquitectura solicitada.

Ver también "ARCHITECTURE".

--attach ISOFILE
Durante la fase de personalización, el disco dado se adjunta a la aplicación libguestfs. Esto se utiliza para proporcionar repositorios de software adicionales u otros datos para la personalización.

Probablemente querrá asegurarse de que los volúmenes o sistemas de archivos en los discos adjuntos estén etiquetados (o usar un nombre de volumen ISO) para que pueda montarlos por etiqueta en sus scripts de ejecución:

mkdir /tmp/mount
mount LABEL=EXTRA /tmp/mount

Puede tener múltiples opciones de --attach, y el formato puede ser cualquier formato de disco (no solo un ISO).

Ver también: --run, "Instalación de paquetes en tiempo de construcción desde un repositorio lateral", genisoimage(1), virt-make-fs(1).

--attach-format FORMATO
Especifica el formato del disco para la siguiente opción --attach. El "FORMATO" suele ser "raw" o "qcow2". Use "raw" para ISOs.
--cache DIR
--no-cache
--cache DIR establece el directorio a usar/verificar para archivos de plantilla cacheados. Si no se establece, por defecto es $XDG_CACHE_HOME/virt-builder/ o $HOME/.cache/virt-builder/.

--no-cache deshabilita el cacheo de plantillas.

--cache-all-templates
Descarga todas las plantillas al cache y luego sale. Ver "CACHING".

Nota: esto no cachea todo. Podrían subirse más plantillas. Además, esto no cachea paquetes (las opciones --install, --update).

--check-signature
--no-check-signature
Verifica/no verifica la firma digital de la plantilla del SO. Por defecto, se verifica la firma y se sale si no es correcta. Usar --no-check-signature omite esta verificación.

Ver también --fingerprint.

--colors
--colours
Usa secuencias de colores ANSI para colorear mensajes. Este es el valor por defecto cuando la salida es una tty. Si la salida del programa se redirige a un archivo, las secuencias de colores ANSI se deshabilitan a menos que uses esta opción.
--curl CURL
Especifica un binario alternativo de curl(1). También puedes usar esto para añadir parámetros de curl, por ejemplo para deshabilitar la verificación de certificados https: 
virt-builder --curl "curl --insecure" [...]
--delete-cache
Elimina el cache de plantillas. Ver "CACHING".
--no-delete-on-failure
No elimines el archivo de salida en caso de fallo en la construcción. Puedes usar esto para depurar fallos al ejecutar scripts. Ver "DEBUGGING BUILDS" para formas de depurar imágenes.

Por defecto, el archivo de salida se elimina si virt-builder falla (o, por ejemplo, falla algún script que ejecuta).

--fingerprint 'AAAA BBBB ...'
Verifica que el índice y las plantillas estén firmados por la clave con la huella digital dada. (La huella digital es una cadena larga, generalmente escrita como 10 grupos de 4 dígitos hexadecimales).

Puedes dar esta opción varias veces. Si tienes múltiples URLs de origen, puedes tener ninguna huella digital, una huella digital o múltiples huellas digitales. Si tienes múltiples, cada una debe corresponder 1 a 1 con una URL de origen.

--format qcow2
--format raw
Para construcciones ordinarias, esto selecciona el formato de salida. El valor por defecto es raw.

Con --get-kernel esto especifica el formato de entrada.

Para crear un archivo qcow2 de estilo antiguo (para compatibilidad con RHEL 6 o qemu muy antiguo < 1.1), después de ejecutar virt-builder, usa este comando:

qemu-img amend -f qcow2 -o compat=0.10 output.qcow2
--get-kernel IMAGE
Esta opción extrae el kernel y el initramfs de una imagen de disco previamente construida llamada "IMAGE" (de hecho, funciona para cualquier imagen de disco de VM, no solo las construidas usando virt-builder).

Nota: este método está obsoleto: hay una herramienta separada para esto, virt-get-kernel(1), que tiene más opciones para la extracción de archivos.

El kernel y el initramfs se escriben en el directorio actual, a menos que también especifiques el directorio --output "outputdir".

El formato de la imagen de disco se detecta automáticamente a menos que lo especifiques usando la opción --format.

En el caso de que el invitado contenga múltiples kernels, se elige el que tenga el número de versión más alto. Para extraer kernels arbitrarios de la imagen de disco, ver guestfish(1). Para extraer todo el directorio /boot de un invitado, ver virt-copy-out(1).

--gpg GPG
Especifica un binario alternativo de gpg(1) (GNU Privacy Guard). Por defecto, virt-builder busca "gpg2" o "gpg" en $PATH.

También puedes usar esto para añadir parámetros de gpg, por ejemplo para especificar un directorio home alternativo:

virt-builder --gpg "gpg --homedir /tmp" [...]
-l [versión-so]
--list [versión-so]
--list --list-format formato [versión-so]
--list --long [versión-so]
Lista todas las plantillas disponibles si no se especifica ningún invitado, o solo para el especificado.

Es posible elegir con --list-format el formato de salida para las plantillas de la lista:

short
El formato por defecto, imprime solo el identificador de la plantilla y, junto a él, su descripción corta.
long
Imprime una lista textual con los detalles de las fuentes disponibles, seguida de los detalles de las plantillas disponibles.
json
Imprime un objeto JSON con los detalles de las fuentes disponibles y los detalles de las plantillas disponibles.

La clave "version" en el objeto principal representa la "versión de compatibilidad", y se incrementa cada vez que la salida JSON resultante es incompatible con las versiones anteriores (por ejemplo, la estructura ha cambiado o las claves no opcionales ya no están presentes).

--long es un atajo para el formato "long".

Ver también: --source, --notes, "SOURCES OF TEMPLATES".

--machine-readable
--machine-readable=formato
Esta opción se utiliza para hacer la salida más amigable para máquinas cuando está siendo parseada por otros programas. Ver "MACHINE READABLE OUTPUT" abajo.
-m MB
--memsize MB
Cambia la cantidad de memoria asignada a los scripts --run. Aumenta esto si encuentras que los scripts --run o la opción --install se quedan sin memoria.

El valor por defecto se puede encontrar con este comando:

guestfish get-memsize
--network
--no-network
Habilita o deshabilita el acceso a la red desde el invitado durante la instalación.

Habilitado es el valor por defecto. Usa --no-network para deshabilitar el acceso.

La red solo permite conexiones salientes y tiene otras limitaciones menores. Ver "NETWORK" en virt-rescue(1).

Si usas --no-network entonces ciertas otras opciones como --install no funcionarán.

Esto no afecta si el invitado puede acceder a la red una vez que ha sido arrancado, porque eso está controlado por tu hipervisor o entorno cloud y no tiene nada que ver con virt-builder.

En general, no deberías usar --no-network. Pero aquí hay algunas razones por las que podrías querer hacerlo:

1.
Porque el backend libguestfs que estás usando no soporta la red. (Ver: "BACKEND" en guestfs(3)).
2.
Cualquier software que necesites instalar viene de una ISO adjunta, así que no necesitas la red.
3.
No quieres que código de invitado no confiable intente acceder a tu red host al ejecutar virt-builder. Esto es particularmente un problema cuando no confías en la fuente de las plantillas del sistema operativo. (Ver "SECURITY" abajo).
4.
No tienes una red host (ej. en entornos seguros/restringidos).
--no-sync
No sincronices el archivo de salida al salir.

Virt-builder realiza "fsync" al archivo de salida o imagen de disco al salir.

La razón es que el modo de cacheo por defecto de qemu/KVM es "none" o "directsync", ambos los cuales omiten la caché de página del host. Por lo tanto, estos no funcionarían correctamente si arrancas inmediatamente el invitado después de ejecutar virt-builder - no verían el archivo de salida completo. (Ten en cuenta que no deberías usar estos modos de cacheo - son fundamentalmente defectuosos para estas y otras razones).

Si no estás usando estos modos de cacheo defectuosos, puedes usar --no-sync para evitar esta sincronización innecesaria y obtener un rendimiento considerablemente mayor.

--notes versión-so
Lista cualquier nota asociada con este invitado, y luego sal (esto no realiza la instalación).
-o nombre-archivo
--output nombre-archivo
Escribe la salida a nombre-archivo. Si no especificas esta opción, el nombre del archivo de salida se genera tomando la cadena "os-version" y añadiendo ".img" (para formato raw) o ".qcow2" (para qcow2 fo
rmat).

Tenga en cuenta que el nombre del archivo de salida podría ser un dispositivo, partición o volumen lógico.

Cuando se utiliza con --get-kernel, esta opción especifica el directorio de salida.

--print-cache
Imprime información sobre la caché de plantillas. Ver "CACHING".
-q
--quiet
No imprima mensajes de progreso ordinarios.
--size SIZE
Seleccione el tamaño del disco de salida, donde el tamaño se puede especificar utilizando nombres comunes como "32G" (32 gigabytes), etc.

Virt-builder redimensionará automáticamente los sistemas de archivos dentro de la imagen del disco.

Si no se especifica el tamaño, ocurre una de dos cosas. Si la salida es un archivo, entonces el tamaño es el mismo que el de la plantilla. Si la salida es un dispositivo, partición, etc., entonces se utiliza el tamaño de ese dispositivo.

Para especificar el tamaño en bytes, el número debe ir seguido de la letra minúscula b, por ejemplo: "--size 10737418240b".

--smp N
Habilita N ≥ 2 CPUs virtuales para que los scripts de --run las utilicen.
--source URL
Establece la URL de origen para buscar índices.

Puede proporcionar esta opción varias veces para especificar múltiples fuentes.

Vea también "FUENTES DE PLANTILLAS" a continuación.

Tenga en cuenta que no debe apuntar --source a fuentes en las que no confíe (a menos que la fuente esté firmada por alguien en quien confíe). Vea también la opción --no-network.

--no-warn-if-partition
No emita una advertencia si el dispositivo de salida es una partición. Esta advertencia evita un error común del usuario al escribir en una clave USB o en un disco externo, cuando normalmente debería escribir en todo el dispositivo (--output /dev/sdX), no en una partición del dispositivo (--output /dev/sdX1). Utilice esta opción para suprimir esta advertencia.
-v
--verbose
Habilita mensajes de depuración y/o produce una salida detallada.

Al informar de errores, utilice esta opción y adjunte la salida completa a su informe de error.

-V
--version
Muestra el número de versión y sale.
--wrap
Ajusta los mensajes de error, advertencia e informativos. Este es el comportamiento predeterminado cuando la salida es una tty. Si la salida del programa se redirige a un archivo, el ajuste se deshabilita a menos que utilice esta opción.
-x
Habilita el rastreo de las llamadas a la API de libguestfs.

Opciones de personalización

--append-line FILE:LINE
Añade una sola línea de texto al "FILE". Si el archivo no termina ya con un salto de línea, se añade uno antes de la línea añadida. También se añade automáticamente un salto de línea al final de la cadena "LINE".

Por ejemplo (asumiendo comillas normales del shell) este comando:

--append-line '/etc/hosts:10.0.0.1 foo'

añadirá ya sea "10.0.0.1 foo⏎" o "⏎10.0.0.1 foo⏎" al archivo, siendo este último solo si el archivo existente no termina ya con un salto de línea.

"⏎" representa un carácter de nueva línea, que se adivina observando el contenido existente del archivo, por lo que este comando hace lo correcto para archivos que utilizan saltos de línea de Unix o Windows. También funciona para archivos vacíos o inexistentes.

Para insertar varias líneas, use la misma opción varias veces:

--append-line '/etc/hosts:10.0.0.1 foo'
--append-line '/etc/hosts:10.0.0.2 bar'

Para insertar una línea en blanco antes de la línea añadida, haga:

--append-line '/etc/hosts:'
--append-line '/etc/hosts:10.0.0.1 foo'
--chmod PERMISSIONS:FILE
Cambia los permisos de "FILE" a "PERMISSIONS".

Nota: "PERMISSIONS" por defecto será decimal, a menos que lo prefije con 0 para obtener octal, es decir, use 0700 en lugar de 700.

--chown UID:GID:PATH
Cambia el propietario del usuario y el ID del grupo de un archivo o directorio en el invitado. Nota:
  • Solo los UID y GID numéricos funcionarán, y estos pueden no ser los mismos dentro del invitado que en el anfitrión.
  • Esto no funcionará con invitados de Windows.

Por ejemplo:

virt-customize --chown '0:0:/var/log/audit.log'

Ver también: --upload.

--commands-from-file FILENAME
Lee los comandos de personalización desde un archivo, uno (y sus argumentos) por línea.

Cada línea contiene un único comando de personalización y sus argumentos, por ejemplo:

delete /some/file
install some-package
password some-user:password:its-new-password

Las líneas vacías se ignoran, y las líneas que comienzan con "#" son comentarios y también se ignoran. Además, los argumentos se pueden repartir en varias líneas, añadiendo una "\" (carácter de continuación) al final de una línea, por ejemplo

edit /some/file:\
  s/^OPT=.*/OPT=ok/

Los comandos se manejan en el mismo orden en que están en el archivo, como si se hubieran especificado como --delete /some/file en la línea de comandos.

--copy SOURCE:DEST
Copia archivos o directorios recursivamente dentro del invitado.

No se pueden usar comodines.

--copy-in LOCALPATH:REMOTEDIR
Copia archivos o directorios locales recursivamente en la imagen del disco, colocándolos en el directorio "REMOTEDIR" (que debe existir).

No se pueden usar comodines.

--delete PATH
Elimina un archivo del invitado. O elimina un directorio (y todo su contenido, recursivamente).

Puede usar caracteres comodín de shell en la ruta especificada. Tenga cuidado de escapar los caracteres comodín del shell del host, si eso es necesario. Por ejemplo:

virt-customize --delete '/var/log/*.log'.

Ver también: --upload, --scrub.

--edit FILE:EXPR
Edita "FILE" usando la expresión Perl "EXPR".

Tenga cuidado de citar correctamente la expresión para evitar que sea alterada por el shell.

Tenga en cuenta que esta opción solo está disponible cuando Perl 5 está instalado.

Ver "EDICIÓN NO INTERACTIVA" en virt-edit(1).

--firstboot SCRIPT
Instala "SCRIPT" dentro del invitado, de modo que cuando el invitado arranque por primera vez, el script se ejecute (como root, al final del proceso de arranque).

El script se pone automáticamente en modo ejecutable (+x) después de la instalación en el invitado.

La versión alternativa --firstboot-command es la misma, pero convenientemente envuelve el comando en un script de una sola línea para usted.

Puede tener múltiples opciones --firstboot. Se ejecutan en el mismo orden en que aparecen en la línea de comandos.

Por favor, eche un vistazo a "SCRIPTS DE PRIMER ARRANQUE" para más información y advertencias sobre los scripts de primer arranque.

Ver también --run.

--firstboot-command 'CMD+ARGS'
Ejecuta un comando (y sus argumentos) dentro del invitado cuando el invitado arranque por primera vez (como root, al final del proceso de arranque).

Puede tener múltiples opciones --firstboot. Se ejecutan en el mismo orden en que aparecen en la línea de comandos.

Por favor, eche un vistazo a "SCRIPTS DE PRIMER ARRANQUE" para más información y advertencias sobre los scripts de primer arranque.

Ver también --run.

--firstboot-install PKG,PKG..
Instala los paquetes con nombre (una lista separada por comas). Estos se instalan cuando el invitado arranca por primera vez utilizando el gestor de paquetes del invitado (por ejemplo, apt, yum, etc.) y la conexión de red del invitado.

Para una visión general de las diferentes formas de instalar paquetes, ver "INSTALACIÓN DE PAQUETES".

--hostname HOSTNAME
Establece el nombre de host del invitado a "HOSTNAME". Puede usar un nombre de host punto-dominio (FQDN) si lo desea.
--inject-blnsvr METHOD
Inyecta el servidor Balloon (blnsvr.exe) en un invitado de Windows. Esta operación también inyecta un script de primer arranque para que el servidor Balloon se instale cuando el invitado arranque.

El parámetro es el mismo que el utilizado por la operación --inject-virtio-win.

Tenga en cuenta que para realizar una conversión completa de un invitado de Windows desde un hipervisor externo como VMware (que implica muchas otras operaciones) debería usar la herramienta virt-v2v(1) en lugar de esta.

--inject-qemu-ga METHOD
Inyecta el Agente de Invitado QEMU en un invitado de Windows. El agente de invitado se comunica con qemu a través de un socket para
proporciona características mejoradas (ver qemu-ga(8)). Esta operación también inyecta un script de primer arranque para que el Agente de Invitado se instale cuando el invitado arranque.

El parámetro es el mismo que se usa en la operación --inject-virtio-win.

Tenga en cuenta que para hacer una conversión completa de un invitado de Windows desde un hipervisor externo como VMware (que implica muchas otras operaciones) debería usar la herramienta virt-v2v(1) en su lugar.

--inject-virtio-win METHOD
Inyecta controladores virtio-win en un invitado de Windows. Estos controladores añaden controladores acelerados virtio adecuados cuando se ejecutan sobre un hipervisor que soporta virtio (como qemu/KVM). La operación también ajusta el Registro de Windows para que los controladores se instalen cuando el invitado arranque.

El parámetro puede ser uno de:

ISO
La ruta a la imagen ISO que contiene los controladores virtio-win (ej. /usr/share/virtio-win/virtio-win.iso).
DIR
El directorio que contiene los controladores virtio-win desempaquetados (ej. /usr/share/virtio-win).

Tenga en cuenta que para hacer una conversión completa de un invitado de Windows desde un hipervisor externo como VMware (que implica muchas otras operaciones) debería usar la herramienta virt-v2v(1) en su lugar.

--install PKG,PKG..

--clone SRC:DST
Clone the disk image file "SRC" to "DST". This operation happens within the guest OS, so it is only possible if the guest is running and the disk image is accessible to the guest OS. The source disk image must exist already.
--copy SRC:DST
Copy the disk image file "SRC" to "DST". This operation happens within the guest OS, so it is only possible if the guest is running and the disk image is accessible to the guest OS. The source disk image must exist already.

Delete the file "FILE" from the disk image.
--download URL:DEST
Download the file from "URL" and save it as "DEST" in the disk image.
--edit FILE:EDIT
Edit the file "FILE" using the specified edit "EDIT".

The edit string is of the form "s/REGEXP/REPLACEMENT/FLAGS" similar to the syntax used by sed(1).

This command is useful for editing configuration files. For example, to change the hostname in a Linux guest:

--edit '/etc/hostname:s/^.*$/myhostname/'

Or to change the root password in a Linux guest (requires the root account to exist first):

--edit '/etc/shadow:s/^root:.*$/root:$1$abcdefgh$i4X.E/Xn9Jk.f7k2R7z6.:18443:0:99999:7:::/

Or to change the password of user 'foo' in a Linux guest:

--edit '/etc/shadow:s/^foo:.*$/foo:$1$abcdefgh$i4X.E/Xn9Jk.f7k2R7z6.:18443:0:99999:7:::/'

Note that the password string must be correctly formatted. It is unlikely that you can guess a correct password hash. It is better to use chpasswd(8) or passwd(1) if possible.

The "FLAGS" can include "g" to replace all occurrences, not just the first.

You can use multiple "--edit" options.

INSTALLING PACKAGES

There are several approaches to installing packages or applications in the guest which have different trade-offs.

Installing packages at build time

If the guest OS you are installing is similar to the host OS (eg. both are Linux), and if libguestfs supports network connections, then you can use --install to install packages like this:

virt-builder fedora-41 --install inkscape

This uses the guest’s package manager and the host’s network connection.

Updating packages at build time

To update the installed packages in the template at build time:

virt-builder fedora-41 --update

Most of the templates that ship with virt-builder come with a very minimal selection of packages (known as a "JEOS" or "Just Enough Operating System"), which are up to date at the time the template is created, but could be out of date by the time you come to install an OS from the template. This option updates those template packages.

Installing packages at first boot

Another option is to install the packages when the guest first boots:

virt-builder fedora-41 --firstboot-install inkscape

This uses the guest’s package manager and the guest’s network connection.

The downsides are that it will take the guest a lot longer to boot first time, and there’s nothing much you can do if package installation fails (eg. if a network problem means the guest can't reach the package repositories).

Installing packages at build time from a side repository

If the software you want to install is not available in the main package repository of the guest, then you can add a side repository. Usually this is presented as an ISO (CD disk image) file containing extra packages.

You can create the disk image using either genisoimage(1) or virt-make-fs(1). For genisoimage, use a command like this:

genisoimage -o extra-packages.iso -R -J -V EXTRA cdcontents/

Create a script that mounts the ISO and sets up the repository. For dnf, create /tmp/install.sh containing:

mkdir /tmp/mount
mount LABEL=EXTRA /tmp/mount

cat <<'EOF' > /etc/yum.repos.d/extra.repo
[extra]
name=extra
baseurl=file:///tmp/mount
enabled=1
EOF

dnf -y install famousdatabase

For apt, create /tmp/install.sh containing:

mkdir /tmp/mount
mount LABEL=EXTRA /tmp/mount

apt-cdrom -d=/tmp/mount add
apt-get -y install famousdatabase

Use the --attach option to attach the CD / disk image and the --run option to run the script:

virt-builder fedora-41 \
  --attach extra-packages.iso \
  --run /tmp/install.sh

KEYBOARD LAYOUT

Because there are so many different ways to set the keyboard layout in Linux distributions, virt-builder does not yet attempt to have a simple command line option. This section describes how to set the keyboard for some common Linux distributions.

Keyboard layout with systemd

For distros that use systemd "localectl", use a command like this:

virt-builder fedora-41 \
  --firstboot-command 'localectl set-keymap uk'

See localectl(1) and https://www.happyassassin.net/2013/11/23/keyboard-layouts-in-fedora-20-and-previously/ for more details.

Keyboard layout using /etc/sysconfig/keyboard

For RHEL ≤ 6, Fedora ≤ 18 and similar, upload or modify the keyboard configuration file using the --upload, --write or --edit options. For example:

virt-builder centos-6 \
  --edit '/etc/sysconfig/keyboard: s/^KEYTABLE=.*/KEYTABLE="uk"/'

The format of this file can be found documented in many places online.

Keyboard layout with Debian-derived distros

For Debian-derived distros using /etc/default/keyboard, upload or modify the keyboard file using the --upload, --write or --edit options. For example:

virt-builder debian-8 \
  --edit '/etc/default/keyboard: s/^XKBLAYOUT=.*/XKBLAYOUT="gb"/'

See https://wiki.debian.org/Keyboard.

El programa virt-builder puede ser llamado de varias formas. La forma más básica es:

virt-builder DISK-IMAGE-NAME

Esto descarga la imagen de plantilla Debian 11 (bullseye) desde el caché de libguestfs, la desempaqueta en un archivo temporal, y luego la redimensiona al tamaño especificado. El resultado es un archivo llamado disk-image-name.img en el directorio actual.

virt-builder --output my-image.img debian-11

Puede especificar un sistema operativo diferente o versión usando la opción --image:

virt-builder --image fedora-41 fedora-41

La imagen de plantilla se puede descargar desde cualquier URL en lugar de usar la imagen predeterminada en caché. Por ejemplo, para crear una imagen de Debian 11 desde una URL de descarga:

virt-builder --image http://ftp.debian.org/debian/dists/bullseye/main/installer-amd64/debian-11-nonguix-amd64.iso \
    debian-11

El tamaño de la imagen se puede especificar con --size:

virt-builder --size 20G debian-11

Si el tamaño especificado es menor que el tamaño de la imagen de plantilla, la imagen se reducirá. Si es mayor, se redimensionará.

Puede instalar paquetes adicionales en la imagen resultante con la opción --install. Esto es útil para instalar paquetes que no están en la imagen de plantilla. Por ejemplo, para instalar Xfce y los paquetes de localización japoneses en una imagen de Debian 8:

pkgs=locales,xfce4,\

iceweasel-l10n-ja,manpages-ja

virt-builder debian-8 \
  --size 20G \
  --install $pkgs \
  --edit '/etc/locale.gen: s,^#\s*ja,ja,' \

CLAVES SSH

La opción --ssh-inject se utiliza para inyectar claves ssh para usuarios en el invitado, de modo que puedan iniciar sesión sin proporcionar una contraseña.

La parte "SELECTOR" del valor de la opción es opcional; en este caso, --ssh-inject "USUARIO" significa que buscamos en el directorio ~/.ssh del usuario actual para encontrar el archivo de ID público predeterminado. Esa clave se carga. "ID público predeterminado" es el archivo default_ID_file descrito en ssh-copy-id(1).

Si se especifica, el "SELECTOR" puede estar en uno de los siguientes formatos:

--ssh-inject USUARIO:archivo:NOMBRE_ARCHIVO
Lee la clave ssh desde NOMBRE_ARCHIVO. NOMBRE_ARCHIVO suele ser un archivo .pub.
--ssh-inject USUARIO:cadena:CADENA_CLAVE
Utiliza la "CADENA_CLAVE" especificada. "CADENA_CLAVE" suele ser una cadena pública como ssh-rsa AAAA.... user@localhost.

En cualquier caso, el directorio ~USUARIO/.ssh y el archivo ~USUARIO/.ssh/authorized_keys se crearán si no existen ya.

SCRIPTS DE PRIMER ARRANQUE

Las opciones --firstboot y --firstboot-command permiten ejecutar comandos en el primer arranque del invitado. Para ello, se instala un script de inicio para el sistema de inicio del invitado, que se encarga de ejecutar todos los scripts y comandos añadidos.

Los sistemas operativos compatibles son:

Linux
Los sistemas de inicio compatibles son: systemd, System-V init (también conocido como sysvinit) y Upstart (usando los scripts de System-V).

Tenga en cuenta que normalmente los scripts de inicio se ejecutan como root, pero con un entorno más limitado que el que podría estar disponible en un shell normal: por ejemplo, $HOME puede no estar definido o estar vacío.

La salida de los scripts de primer arranque está disponible en el invitado como ~root/virt-sysprep-firstboot.log.

Windows
Se instala rhsrvany.exe, disponible en las fuentes en https://github.com/rwmjones/rhsrvany, o pvvxsvc.exe, disponible con SUSE VMDP, para ejecutar los scripts de primer arranque. Es obligatorio, y la configuración de los scripts de primer arranque fallará si no está presente.

rhsrvany.exe o pvvxsvc.exe se copia desde la ubicación apuntada por la variable de entorno "VIRT_TOOLS_DATA_DIR"; si no está establecida, se utilizará un valor predeterminado compilado (algo como /usr/share/virt-tools).

La salida de los scripts de primer arranque está disponible en el invitado como C:\Program Files\Guestfs\Firstboot\log.txt.

SUBSCRIPTION-MANAGER

Es posible automatizar el registro y la adjunción del sistema usando "subscription-manager". Esto es típico en invitados Red Hat Enterprise Linux. Hay pocas opciones que faciliten este proceso, eviten ejecutar comandos manualmente y expongan contraseñas en la línea de comandos.

--sm-register inicia el proceso de registro y requiere que se especifique --sm-credentials; el formato del "SELECTOR" de --sm-credentials es uno de los siguientes formatos:

--sm-credentials USUARIO:archivo:NOMBRE_ARCHIVO
Lee la contraseña para el "USUARIO" especificado desde NOMBRE_ARCHIVO.
--sm-credentials USUARIO:contraseña:CONTRASEÑA
Utiliza la cadena literal "CONTRASEÑA" para el "USUARIO" especificado.

--sm-attach adjunta el sistema a las suscripciones; el formato de su "SELECTOR" es uno de los siguientes:

--sm-attach auto
"subscription-manager" se adjunta a las suscripciones que mejor se ajustan al sistema.
--sm-attach archivo:NOMBRE_ARCHIVO
Lee el ID del pool desde NOMBRE_ARCHIVO.
--sm-attach pool:POOL
Utiliza la cadena literal "POOL" como ID de pool.

--sm-remove elimina todas las suscripciones del invitado, mientras que --sm-unregister desregistra completamente el sistema.

PROCESO DE INSTALACIÓN

Cuando invoca virt-builder, la instalación procede de la siguiente manera:

  • Se descarga la imagen de plantilla.

    Si la imagen de plantilla está presente en la caché, se utiliza la versión en caché en su lugar. (Ver "CACHÉ").

  • Se comprueba la firma de la plantilla.
  • La plantilla se desempaqueta en un archivo temporal.
  • La imagen de plantilla se redimensiona al destino, utilizando virt-resize(1).
  • Se adjuntan discos adicionales (--attach).
  • Se genera una nueva semilla aleatoria para el invitado.
  • Se realiza la personalización del invitado, en el orden especificado en la línea de comandos.
  • Se realiza el etiquetado SELinux a menos que se deshabilite con --no-selinux-relabel.

IMPORTACIÓN DE LA IMAGEN DE DISCO

Importación a libvirt

Importe la imagen de disco a libvirt usando la opción --import de virt-install(1).

virt-install --import \
  --name guest --ram 2048 \
  --disk path=disk.img,format=raw --os-variant fedora27

Notas:

1.
Debe especificar el formato correcto. El formato es "raw" a menos que haya utilizado la opción --format de virt-builder.
2.
Se recomienda encarecidamente --os-variant, ya que presentará los dispositivos óptimos para que el invitado funcione de la manera más eficiente. Para obtener una lista de todas las variantes, haga: 
osinfo-query os

La herramienta anterior la proporciona el paquete libosinfo.

3.
Puede ejecutar virt-install como root o como usuario normal. Cada uno funciona de manera ligeramente diferente porque libvirt gestiona un conjunto diferente de máquinas virtuales para cada usuario. En particular, virt-manager normalmente muestra las VMs propiedad de root, mientras que Boxes muestra las VMs propiedad del usuario, y otras herramientas probablemente funcionen de manera diferente también.

Importación a OpenStack

Importe la imagen a Glance (el almacén de imágenes de OpenStack) haciendo:

glance image-create --name fedora-41-image --file fedora-41.img \
  --disk-format raw --container-format bare \
  --is-public True

El parámetro --file es la imagen de disco generada por virt-builder. Debe coincidir con la opción --output de virt-builder. El parámetro --disk-format debe coincidir con la opción --format de virt-builder (o "raw" si no utilizó esa opción). El --container-format siempre debe ser "bare" ya que virt-builder no coloca las imágenes en contenedores.

Puede utilizar el comando "glance image-show fedora-41-image" para mostrar las propiedades de la imagen.

Para iniciar una instancia de su imagen en un nodo de cómputo Nova, haga:

nova boot fedora-41-server --image fedora-41-image \
  --flavor m1.medium

Utilice "nova flavor-list" para listar los sabores de máquina posibles. Utilice "nova list" para listar las instancias en ejecución.

Arranque directo usando qemu o KVM

La línea de comandos de qemu no es muy estable ni fácil de usar, por lo que se debe usar libvirt si es posible. Sin embargo, se podría usar una línea de comandos similar a la siguiente para arrancar la máquina virtual:

qemu-system-x86_64 \
  -machine accel=kvm:tcg \
  -cpu host \
  -m 2048 \
  -drive file=disk.img,format=raw,if=virtio

Al igual que con libvirt, es muy importante que se elija el formato correcto. Será "raw" a menos que se haya utilizado la opción --format.

Si el propio virt-builder falla, activa la depuración (-v) y reporta un error (consulta la sección "ERRORES" más abajo).

Si virt-builder falla porque algún script o paquete que está instalando falla, intenta usar --no-delete-on-failure para conservar el archivo de salida y continúa leyendo esta sección.

Si virt-builder es exitoso pero la imagen no funciona, aquí hay algunas cosas que puedes intentar:

Usar virt-rescue
Ejecuta virt-rescue(1) sobre la imagen de disco: 
virt-rescue -a disk.img

Esto te proporciona un shell de rescate. Puedes montar los sistemas de archivos de la imagen de disco en /sysroot y examinarlos usando comandos ordinarios de Linux. También puedes usar chroot en el invitado para reinstalar el gestor de arranque. El manual de virt-rescue tiene mucha más información y ejemplos.

Usar guestfish
Ejecuta guestfish(1) sobre la imagen de disco: 
guestfish -a disk.img -i

Usa comandos de guestfish como "ll /directorio" y "cat /archivo" para examinar directorios y archivos.

Monta la imagen de disco de forma segura en el host usando FUSE y guestmount(1): 
mkdir /tmp/mp
guestmount -a disk.img -i /tmp/mp
cd /tmp/mp

Para desmontar la imagen de disco haz:

fusermount -u /tmp/mp

Si el invitado se cuelga durante el arranque, puede ser útil añadir una consola serie al invitado y dirigir los mensajes del kernel a la consola serie. Añadir la consola serie implicará consultar la documentación de tu hipervisor. Para dirigir los mensajes del kernel a la consola serie, añade lo siguiente en la línea de comandos del kernel: 
console=tty0 console=ttyS0,115200

FUENTES DE PLANTILLAS

virt-builder lee las fuentes disponibles de los archivos de configuración, con la extensión .conf y ubicados en las siguientes rutas:

  • $XDG_CONFIG_HOME/virt-builder/repos.d/ (si $XDG_CONFIG_HOME no está definido, es $HOME/.config).
  • $VIRT_BUILDER_DIRS/virt-builder/repos.d/ (donde $VIRT_BUILDER_DIRS significa cualquiera de los directorios de esa variable de entorno, o solo /etc si no está definido).

Cada archivo .conf en esas rutas tiene un formato de texto simple como el siguiente:

[libguestfs.org]
uri=http://libguestfs.org/download/builder/index.asc
gpgkey=file:///etc/xdg/virt-builder/repos.d/libguestfs.gpg

La parte entre corchetes es el identificador del repositorio, que se utiliza como identificador único.

Los siguientes campos pueden aparecer:

"uri=URI"
La URI del archivo de índice al que se refiere este repositorio.

Este campo es obligatorio.

"gpgkey=URI"
Este campo opcional representa la URI (aunque solo se aceptan URIs file://) de la clave utilizada para firmar el archivo de índice. Si no está presente, el archivo de índice al que se refiere uri=.. no está firmado.
"proxy=MODO"
Este campo opcional especifica el modo proxy, que se utilizará al descargar el archivo de índice de este repositorio. Los valores posibles son:
no, off
No se está utilizando ningún proxy, lo que anula la configuración del sistema.
system
El proxy utilizado es el del sistema.
cualquier otro
Especifica la configuración de proxy real que se utilizará, anulando la configuración del sistema.

Si no está presente, el valor asumido es respetar la configuración proxy del sistema (es decir, como si se especificara system).

"format=FORMAT"
Este campo opcional especifica el formato del repositorio. Los valores posibles son:
native
El formato nativo del repositorio "virt-builder". Consulta también "Creación y firma del archivo de índice" más abajo.
simplestreams
La URI representa la raíz de un árbol de metadatos de Simple Streams v1.0.

Para más información sobre Simple Streams, consulta también https://launchpad.net/simplestreams.

Si no está presente, el valor asumido es "native".

Para un uso serio de virt-builder, puede que desees crear tu propio repositorio de plantillas.

Repositorio de Libguestfs.org

Por defecto, virt-builder descarga el archivo http://libguestfs.org/download/builder/index.asc que es un índice de las plantillas disponibles más información sobre cada una, envuelto en una firma digital. El comando "virt-builder --list" lista la información de este archivo de índice.

Las plantillas alojadas en libguestfs.org se crearon usando scripts de shell, archivos kickstart y archivos preseed que se pueden encontrar en el árbol de fuentes de libguestfs, en "builder/templates".

Configuración del repositorio

Puedes configurar tu propio sitio que contenga un archivo de índice y algunas plantillas, y luego apuntar virt-builder a ese sitio creando un archivo .conf que apunte a él.

Ten en cuenta que si tu índice está firmado, necesitarás completar correctamente gpgkey=.. en tu archivo .conf, asegurándote de desplegar también el archivo de clave GPG.

virt-builder --source https://example.com/builder/index.asc \
   --fingerprint 'AAAA BBBB ...' \
   --list

Puedes alojar esto en cualquier servidor web o FTP, o en un sistema de archivos local o de red.

Configuración de una clave GPG

Si no tienes una clave GnuPG, necesitarás configurar una. (Estrictamente hablando, esto es opcional, pero si tus archivos de índice y plantilla no están firmados, los usuarios de virt-builder tendrán que usar la opción --no-check-signature cada vez que usen virt-builder).

Para crear una clave, consulta el manual de GPG http://www.gnupg.org/gph/en/manual.html.

Exporta tu clave pública GPG:

gpg --export -a "tu@ejemplo.com" > pubkey

Creación de las plantillas

Hay muchas maneras de crear las plantillas. Por ejemplo, podrías clonar invitados existentes (ver virt-sysprep(1)), o podrías instalar un invitado manualmente (virt-install(1)). Para ver cómo se crearon las plantillas para virt-builder, mira los scripts en "builder/templates".

virt-builder soporta cualquier formato de imagen (p. ej., raw, qcow2, etc.) como plantilla, tanto tal cual, como comprimido en XZ. De esta manera, las imágenes existentes (p. ej., limpiadas usando virt-sysprep(1)) se pueden usar como plantillas.

Para obtener mejores resultados al comprimir las plantillas, usa las siguientes opciones de xz (ver nbdkit-xz-plugin(1) para más explicaciones):

xz --best --block-size=16777216 disk

Creación y firma del archivo de índice

El archivo de índice tiene un formato de texto simple (mostrado aquí sin la firma digital):

[fedora-41]
name=Fedora® 41
osinfo=fedora41
arch=x86_64
file=fedora-41.xz
checksum[sha512]=...
format=raw
size=6442450944
compressed_size=148947524
expand=/dev/sda3

[fedora-42]
name=Fedora® 42
osinfo=fedora42
arch=x86_64
file=fedora-42.xz
checksum[sha512]=...
revision=3
format=raw
size=4294967296
compressed_size=172190964
expand=/dev/sda3

La parte entre corchetes es la "os-version", que es la misma cadena que se usa en la línea de comandos de virt-builder para compilar ese SO.

La creación y firma del archivo de índice se puede facilitar con la herramienta virt-builder-repository(1).

Después de preparar el archivo "index" en el formato correcto, fírmalo con la siguiente orden:

gpg --clearsign --armor index

Esto creará el archivo final llamado index.asc que se puede subir al servidor (y es la URL uri=..). Como se mencionó anteriormente, firmar el archivo de índice es opcional, pero recomendado.

Los siguientes campos pueden aparecer:

"name=NOMBRE"
El nombre fácil de usar de esta plantilla. Se muestra en la salida de --list pero por lo demás no es significativo.
"osinfo=ID"
Este campo opcional mapea el sistema operativo con el ID de libosinfo asociado. virt-builder no lo usa (todavía).
"arch=ARQUITECTURA"
La arquitectura del sistema operativo instalado dentro de la plantilla. Este campo es obligatorio.
"file=RUTA"
La ruta (relativa al índice) de la plantilla comprimida en xz.

Ten en cuenta que las rutas absolutas o las URIs **no** están permitidas aquí. Esto se debe a que virt-builder tiene una política de "mismo origen" para las plantillas, por lo que no pueden provenir de otros servidores.

"sig=RUTA"
Esta opción está obsoleta. Usa el campo checksum en su lugar.

La ruta (relativa al índice) de la firma adjunta GPG del archivo xz.

Ten en cuenta que las rutas absolutas o las URIs **no** están permitidas aquí. Esto se debe a que virt-builder tiene una política de "mismo origen" para las plantillas, por lo que no pueden provenir de otros servidores.

El archivo se puede crear de la siguiente manera:

gpg --detach-sign --armor -o disk.xz.sig disk.xz
"checksum[sha512]=7b882fe9b82eb0fef..."
El checksum SHA-512 del archivo especificado en file=.. se comprueba después de su descarga.
ed. Para calcular la firma, haz: 
sha512sum disk.xz

Nota: si usas esto, no necesitas firmar el archivo, es decir, no uses "sig". Esta opción anula "sig".

"checksum=7b882fe9b82eb0fef..."
"checksum" es un alias para "checksum[sha512]".

Si necesitas interoperar con virt-builder = 1.24.0, debes usar "checksum" porque esa versión daría un error de análisis con corchetes y números en la clave de un campo. Esto se soluciona en virt-builder ≥ 1.24.1.

"revision=N"
La revisión es un número entero que se utiliza para controlar la caché de plantillas. Aumentar el número de revisión hace que los clientes vuelvan a descargar la plantilla aunque tengan una copia en la caché.

El número de revisión es opcional. Si se omite, por defecto es 1.

"format=raw"
"format=qcow2"
Especifica el formato de la imagen de disco; en caso de que esté comprimida, ese es el formato antes de la compresión. Si no se proporciona, el formato se detecta automáticamente, pero generalmente es mejor ser explícito sobre el formato deseado.

Nota: este es el formato de origen, que es diferente de la opción --format (formato de salida solicitado). Virt-builder realiza conversiones sobre la marcha del formato de origen al formato de salida solicitado.

"size=NNN"
El tamaño virtual de la imagen en bytes. Este es el tamaño de la imagen sin comprimir. Si se utiliza un formato no raw como qcow2, significa el tamaño virtual del disco, no el tamaño del archivo qcow2.

Este campo es obligatorio.

Virt-builder también utiliza esto como el tamaño mínimo que los usuarios pueden solicitar a través de la opción --size, o como el tamaño predeterminado si no hay opción --size.

"compressed_size=NNN"
El tamaño real de la imagen de disco en bytes, es decir, lo que se especificó en file=... Esto se utiliza solo para información (cuando se utilizan los formatos "long" y "json" de --list).
"expand=/dev/sdaX"
Al expandir la imagen a su tamaño final, indica a virt-resize(1) que expanda la partición nombrada en la imagen del invitado para llenar todo el espacio disponible. Esto funciona como la opción --expand de virt-resize.

Normalmente deberías poner aquí el nombre del dispositivo del sistema de archivos raíz del invitado.

Es una buena idea usar esto, pero no es obligatorio. Si se omite el campo, virt-resize creará una partición adicional al final del disco para cubrir el espacio libre, lo cual es mucho menos amigable para el usuario.

"lvexpand=/dev/VolGroup/LogVol"
Al expandir la imagen a su tamaño final, indica a virt-resize(1) que expanda el volumen lógico nombrado en la imagen del invitado para llenar todo el espacio disponible. Esto funciona como la opción --lv-expand de virt-resize.

Si el invitado utiliza LVM2, normalmente deberías poner aquí el LV del sistema de archivos raíz del invitado. Si el invitado no utiliza LVM2 o su sistema de archivos raíz no está en un LV, no uses esta opción.

"notes=NOTAS"
Cualquier nota que acompañe a esta imagen, especialmente notas que describan qué paquetes contiene la imagen, cómo se preparó la imagen e información de licencia.

Esta información se muestra en los modos --notes y --list --long.

Puedes usar notas de varias líneas aquí indentando cada nueva línea con al menos un carácter de espacio en blanco (incluso en líneas en blanco):

notes=Esta imagen se preparó usando
 el siguiente script kickstart:
                               <-- un espacio al principio de la línea
 part /boot --fstype ext3
 ...
"hidden=true"
Usar el indicador hidden evita que la plantilla sea listada por la opción --list (pero todavía es instalable). Esto se usa para imágenes de prueba.
"aliases=ALIAS1 ALIAS2 ..."
Este campo opcional especifica una lista de alias, separados por espacios, para la imagen. Por ejemplo, un alias podría usarse para apuntar siempre a la última versión de una determinada imagen, dejando las versiones antiguas disponibles en el índice en lugar de actualizar la misma imagen (ver el campo "revision").

Ejecución de virt-builder contra múltiples fuentes

Es posible usar múltiples fuentes con virt-builder. La forma recomendada es desplegar archivos .conf que apunten a los archivos de índice. Otra forma es especificar las fuentes usando múltiples opciones --source y/o --fingerprint:

virt-builder \
  --source http://example.com/s1/index.asc \
  --source http://example.com/s2/index.asc

Puedes proporcionar N o 1 huellas dactilares. En el caso de que proporciones N huellas dactilares, N = número de fuentes y hay una correspondencia uno a uno entre cada fuente y cada huella dactilar:

virt-builder \
  --source http://example.com/s1/index.asc --fingerprint '0123 ...' \
  --source http://example.com/s2/index.asc --fingerprint '9876 ...'

En el caso de que proporciones 1 huella dactilar, la misma huella dactilar se utiliza para todas las fuentes.

Debes "obligatoriamente" proporcionar al menos 1 huella dactilar.

Licencia de las plantillas

Debes tener en cuenta la licencia de las imágenes que distribuyes. Para invitados de código abierto, proporciona un enlace al código fuente en el campo "notes" y cumple con otros requisitos (por ejemplo, en cuanto a marcas registradas).

Especificación formal del archivo de índice

El formato del archivo de índice tiene una especificación formal definida por el escáner flex y el analizador bison utilizados para analizar el archivo. Esto se puede encontrar en los siguientes archivos en el árbol de fuentes de libguestfs:

builder/index-scan.l
builder/index-parse.y

Una herramienta llamada virt-index-validate(1) está disponible para validar el archivo de índice y asegurar que es correcto.

Nota que el analizador y la herramienta pueden funcionar tanto con el archivo de índice firmado como sin firmar (es decir, index o index.asc).

El índice siempre está codificado en UTF-8.

CACHÉ

Caché de plantillas

Dado que las plantillas suelen ser muy grandes, las plantillas descargadas se almacenan en caché en el directorio de inicio del usuario.

La ubicación de la caché es $XDG_CACHE_HOME/virt-builder/ o $HOME/.cache/virt-builder.

Puedes imprimir información sobre el directorio de caché, incluyendo qué invitados están actualmente en caché, haciendo:

virt-builder --print-cache

La caché se puede eliminar si deseas ahorrar espacio haciendo:

virt-builder --delete-cache

Puedes descargar todas las plantillas (actuales) a la caché local haciendo:

virt-builder --cache-all-templates

Para deshabilitar la caché de plantillas, usa --no-cache.

Solo las plantillas se almacenan en caché. El índice y las firmas digitales desvinculadas no se almacenan en caché.

Caché de paquetes

Virt-builder usa curl(1) para descargar archivos y también usa la configuración actual de "http_proxy" (etc) al instalar paquetes (--install, --update).

Por lo tanto, es posible que desees configurar esas variables de entorno para maximizar la cantidad de caché local que ocurre. Consulta "VARIABLES DE ENTORNO" y curl(1).

Espejos locales

Para aumentar la velocidad y la fiabilidad de la instalación de paquetes, puedes configurar un espejo local de la distribución de destino y apuntar el gestor de paquetes del invitado a él.

Uso de un espejo local con Fedora

Para instalar un invitado de Fedora usando un espejo local:

virt-builder fedora-41 \
  --edit '/etc/yum.repos.d/fedora.repo:
      s{.*baseurl=.*}{baseurl=http://example.com/mirror/};
      s{.*metalink=.*}{};
  ' \
  --edit '/etc/yum.repos.d/fedora-updates.repo:
      s{.*baseurl=.*}{baseurl=http://example.com/mirror-updates/};
      s{.*metalink=.*}{};
  ' \
  --run-command 'dnf -y update' \
  --install 'pkg1,pkg2,...'

Uso de un espejo local con Debian

Suponiendo que estás utilizando "apt-proxy" para duplicar el repositorio, deberías crear un nuevo archivo sources.list para apuntar a tu proxy (ver https://help.ubuntu.com/community/AptProxy) y luego hacer:

virt-builder debian-8 \
  --upload sources.list:/etc/apt/sources.list \
  --run-command 'apt-get -y update' \
  --install 'pkg1,pkg2,...'

SIGNATURAS DIGITALES

Virt-builder utiliza GNU Privacy Guard (GnuPG o gpg) para verificar que el índice y las plantillas no han sido manipulados.

La fuente apunta a un archivo de índice, que opcionalmente está firmado.

Virt-builder descarga el índice y comprueba que la firma es válida y que la huella dactilar del firmante coincide con la huella dactilar especificada (es decir, la especificada en gpgkey=.. en el .conf, o con --fingerprint, en ese orden).

Para verificar contra la clave pública/huella dactilar incorporada, esto requiere importar la clave pública al keyring gpg local del usuario (así es como funciona gpg).

Cuando se descarga una plantilla, su firma se comprueba de la misma manera.

Aunque las firmas son opcionales, si no las tienes, los usuarios de virt-builder tendrán que usar --no-check-signature en la línea de comandos. Esto evita que un atacante reemplace el archivo de índice firmado con un archivo de índice sin firmar y que virt-builder funcione silenciosamente sin verificar la firma. En cualquier caso, se recomienda encarecidamente que siempre crees índices y plantillas firmados.
