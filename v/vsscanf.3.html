vsscanf(3)

sscanf(3) Manual de funciones de biblioteca sscanf(3)

NOMBRE

sscanf, vsscanf - conversión de formato de entrada de cadena

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <stdio.h>
int sscanf(const char *restrict str,
           const char *restrict format, ...);
#include <stdarg.h>
int vsscanf(const char *restrict str,
           const char *restrict format, va_list ap);
Requisitos de macros de prueba de características para glibc (ver feature_test_macros(7)):

vsscanf():

    _ISOC99_SOURCE || _POSIX_C_SOURCE >= 200112L

DESCRIPCIÓN

La familia de funciones sscanf() lee datos de formato según format como se describe a continuación. Este formato puede contener especificaciones de conversión; los resultados de dichas conversiones, si los hay, se almacenan en las ubicaciones apuntadas por los argumentos puntero que siguen a format. Cada argumento puntero debe ser de un tipo apropiado para el valor devuelto por la especificación de conversión correspondiente.

Si el número de especificaciones de conversión en format supera el número de argumentos puntero, los resultados son indefinidos. Si el número de argumentos puntero supera el número de especificaciones de conversión, entonces los argumentos puntero excedentes se evalúan, pero por lo demás se ignoran.

sscanf() Estas funciones leen su entrada de la cadena apuntada por str.

La función vsscanf() es análoga a vsprintf(3).

La cadena format consiste en una secuencia de directivas que describen cómo procesar la secuencia de caracteres de entrada. Si el procesamiento de una directiva falla, no se lee más entrada y sscanf() retorna. Un "fallo" puede ser cualquiera de los siguientes: fallo de entrada, que significa que los caracteres de entrada no estaban disponibles, o fallo de coincidencia, que significa que la entrada era inapropiada (ver abajo).

Una directiva es una de las siguientes:

•
Una secuencia de caracteres de espacio en blanco (espacio, tabulador, nueva línea, etc.; ver isspace(3)). Esta directiva coincide con cualquier cantidad de espacio en blanco, incluyendo ninguna, en la entrada.
•
Un carácter ordinario (es decir, uno que no sea espacio en blanco ni '%'). Este carácter debe coincidir exactamente con el siguiente carácter de entrada.
•
Una especificación de conversión, que comienza con un carácter '%' (porcentaje) o la secuencia de caracteres "%n$" (ver abajo para la distinción) seguida de:

Cada especificación de conversión en format comienza ya sea con el carácter '%' o con la secuencia de caracteres "%n$" seguida de:

•
Un carácter opcional de supresión de asignación '*' : sscanf() lee la entrada según lo dirigido por la especificación de conversión, pero descarta la entrada. No se requiere ningún argumento puntero correspondiente, y esta especificación no se incluye en el recuento de asignaciones exitosas devueltas por sscanf().
•
Para conversiones decimales, un carácter de comilla opcional ('). Esto especifica que el número de entrada puede incluir separadores de miles según lo definido por la categoría LC_NUMERIC de la configuración regional actual. (Ver setlocale(3).) El carácter de comilla puede preceder o seguir al carácter de supresión de asignación '*'.
•
Un carácter opcional 'm'. Esto se usa con conversiones de cadena (%s, %c, %[), y exime a la llamada de la necesidad de asignar un búfer correspondiente para mantener la entrada: en su lugar, sscanf() asigna un búfer de tamaño suficiente y asigna la dirección de este búfer al argumento puntero correspondiente, que debe ser un puntero a una variable char * (esta variable no necesita inicializarse antes de la llamada). La llamada posteriormente debería free(3) este búfer cuando ya no se necesite.
•
Un entero decimal opcional que especifica el ancho máximo del campo. La lectura de caracteres se detiene ya sea cuando se alcanza este máximo o cuando se encuentra un carácter no coincidente, lo que ocurra primero. La mayoría de las conversiones descartan los caracteres iniciales de espacio en blanco (las excepciones se señalan a continuación), y estos caracteres descartados no cuentan para el ancho máximo del campo. Las conversiones de entrada de cadena almacenan un byte nulo terminador ('\0') para marcar el final de la entrada; el ancho máximo del campo no incluye este terminador.
•
Un carácter modificador de tipo opcional. Por ejemplo, el modificador de tipo l se usa con conversiones enteras como %d para especificar que el argumento puntero correspondiente se refiere a un long en lugar de a un puntero a un int.
•
Un especificador de conversión que especifica el tipo de conversión de entrada que se realizará.

Las especificaciones de conversión en format son de dos formas, ya sea comenzando con '%' o comenzando con la secuencia "%n$". Las dos formas no deben mezclarse en la misma cadena format, excepto que una cadena que contenga especificaciones "%n$" puede incluir %% y %*. Si format contiene especificaciones '%', entonces estas corresponden en orden con los argumentos puntero sucesivos. En la forma "%n$" (que se especifica en POSIX.1-2001, pero no en C99), n es un entero decimal que especifica que la entrada convertida debe colocarse en la ubicación referida por el n-ésimo argumento puntero después de format.

Conversiones

Los siguientes caracteres modificadores de tipo pueden aparecer en una especificación de conversión:

h
Indica que la conversión será una de d, i, o, u, x, X, o n, y el siguiente puntero es un puntero a un short o unsigned short (en lugar de int).
hh
Igual que para h, pero el siguiente puntero es un puntero a un signed char o unsigned char.
j
Igual que para h, pero el siguiente puntero es un puntero a un intmax_t o un uintmax_t. Este modificador se introdujo en C99.
l
Indica que la conversión será una de d, i, o, u, x, X, o n, y el siguiente puntero es un puntero a un long o unsigned long (en lugar de int), o que la conversión será una de e, f, o g, y el siguiente puntero es un puntero a double (en lugar de float). Si se usa con %c o %s, el parámetro correspondiente se considera como un puntero a un carácter ancho o a una cadena de caracteres anchos, respectivamente.
ll
(elle-elle) Indica que la conversión será una de b, d, i, o, u, x, X, o n, y el siguiente puntero es un puntero a un long long o unsigned long long (en lugar de int).

Indica que la conversión será e, f, o g, y el siguiente puntero es un puntero a long double o (como extensión GNU) la conversión será d, i, o, u, o x, y el siguiente puntero es un puntero a long long.

DESCRIPCIÓN

Las funciones scanf, fscanf, sscanf, vscanf, vfscanf, y vsscanf leen datos de la ubicación de entrada apropiada y los colocan en las ubicaciones de memoria apuntadas por los argumentos subsiguientes, de acuerdo con las reglas especificadas por el argumento format.

Las tres primeras funciones (scanf, fscanf, sscanf) son variantes principales. Las tres últimas (vscanf, vfscanf, vsscanf) son equivalentes, pero donde los argumentos de lista de variable se pasan como un puntero a una estructura va_list, que se obtiene mediante la macro va_start(3).

Las funciones scanf, vscanf leen de la entrada estándar (stdin(3)).

Las funciones fscanf, vfscanf leen del flujo especificado por stream.

Las funciones sscanf, vsscanf leen de la cadena de caracteres (str).

Cada uno de estos argumentos format es una cadena de caracteres que especifica la conversión de un argumento de entrada subsiguiente. El argumento format puede contener secuencias de escape, como se describe a continuación.

Las funciones scanf y sus variantes devuelven el número de elementos de entrada asignados con éxito. Si la entrada termina antes de la primera conversión, o si ocurre una falla de coincidencia en la primera conversión, se devuelve EOF. En caso de éxito, este valor puede ser menor que el número de elementos de entrada que se esperaban si algunos de ellos no se pudieron convertir.

Se espera que el argumento format sea una cadena de caracteres que contenga cero o más directivas, las cuales pueden ser:

Un espacio en blanco
Uno o más caracteres de espacio en blanco en el formato coinciden con uno o más caracteres de espacio en blanco en la entrada. Los caracteres de espacio en blanco de entrada se descartan. Un carácter de espacio en blanco en el formato no coincide con ningún carácter de espacio en blanco en la entrada.
Un carácter que no sea un carácter de espacio en blanco
Un carácter que no sea un carácter de espacio en blanco en el formato coincide con el carácter correspondiente en la entrada. Si no hay coincidencia, la función termina.
Una especificación de conversión
Comienza con el carácter %, seguido de uno o más caracteres que especifican la interpretación del campo de entrada. Si un carácter después de un % no es un carácter de espacio en blanco o no está dentro de las especificaciones de conversión válidas, el comportamiento no está definido.

Las especificaciones de conversión tienen la siguiente forma general:

%[assignment-suppression][flags]{width}[h|hh|l|ll|j|z|t|L|q}type

assignment-suppression
Un asterisco (*) suprime la asignación del campo de entrada correspondiente. El campo se lee de la entrada, pero no se almacena en ninguna parte. El número de caracteres consumidos se cuenta, pero no se devuelve en el recuento de elementos asignados.
flags
Esta sección describe el comportamiento de las diferentes especificaciones de conversión.
width
Un entero decimal que especifica el ancho máximo del campo que se va a leer. Los caracteres de espacio en blanco de entrada se descartan antes de leer el campo, a menos que el especificador de tipo sea c, s o [. La lectura de un campo se detiene en el primer carácter que no se puede convertir o cuando se ha leído el número de caracteres especificado por width, lo que ocurra primero.
h, hh, l, ll, j, z, t, L, q
Estos son modificadores de longitud que indican el tamaño del tipo del argumento de puntero esperado.
h
Indica que el argumento es un puntero a short int. Para los especificadores de conversión n, indica un puntero a short int.
hh
Indica que el argumento es un puntero a signed char. Para los especificadores de conversión n, indica un puntero a unsigned char.
l
Indica que el argumento es un puntero a long int. Para los especificadores de conversión n, indica un puntero a long int.
ll
Indica que el argumento es un puntero a long long int. Para los especificadores de conversión n, indica un puntero a long long int. Este modificador se introdujo en C99.
j
Indica que el argumento es un puntero a intmax_t. Este modificador se introdujo en C99.
z
Indica que el argumento es un puntero a size_t. Este modificador se introdujo en C99.
t
Indica que el argumento es un puntero a ptrdiff_t. Este modificador se introdujo en C99.
L
Indica que el argumento es un puntero a long double. Se usa con los especificadores de conversión de punto flotante a, e, f, g, A, E, F, G.
q
Este es un modificador no estándar, pero común, de GNU y BSD. Equivalente a ll para enteros y a L para punto flotante.
type
El carácter que especifica el tipo de conversión a realizar. Los siguientes especificadores de conversión están disponibles:
%
Coincide con un literal '%'. Es decir, %% en la cadena de formato coincide con un solo carácter '%' de entrada. No se realiza ninguna conversión (pero se descartan los caracteres de espacio en blanco iniciales) y no se realiza ninguna asignación.
d
Coincide con un entero decimal opcionalmente con signo; el siguiente puntero debe ser un puntero a int.
i
Coincide con un entero opcionalmente con signo; el siguiente puntero debe ser un puntero a int. El entero se lee en base 16 si comienza con 0x o 0X, en base 8 si comienza con 0, y en base 10 en caso contrario. Solo se utilizan los caracteres que corresponden a la base.
o
Coincide con un entero octal sin signo; el siguiente puntero debe ser un puntero a unsigned int.
u
Coincide con un entero decimal sin signo; el siguiente puntero debe ser un puntero a unsigned int.
x
Coincide con un entero hexadecimal sin signo (que opcionalmente puede comenzar con un prefijo 0x o 0X, que se descarta); el siguiente puntero debe ser un puntero a unsigned int.
X
Equivalente a x.
f
Coincide con un número de punto flotante opcionalmente con signo; el siguiente puntero debe ser un puntero a float.
e
Equivalente a f.
g
Equivalente a f.
E
Equivalente a f.
a
(C99) Equivalente a f.
s
Coincide con una secuencia de caracteres que no son de espacio en blanco; el siguiente puntero debe ser un puntero al elemento inicial de una matriz de caracteres que sea lo suficientemente larga como para contener la secuencia de entrada y el byte nulo terminador ('\0'), que se agrega automáticamente. La cadena de entrada se detiene en un carácter de espacio en blanco o en el ancho máximo del campo, lo que ocurra primero.
c
Coincide con una secuencia de caracteres cuya longitud está especificada por el ancho máximo del campo (predeterminado 1); el siguiente puntero debe ser un puntero a char, y debe haber suficiente espacio para todos los caracteres (no se agrega ningún byte nulo terminador). Se suprime el salto habitual de los caracteres de espacio en blanco iniciales. Para omitir primero los caracteres de espacio en blanco, use un espacio explícito en el formato.
[
Coincide con una secuencia no vacía de caracteres del conjunto especificado de caracteres aceptados; el siguiente puntero debe ser un puntero a char, y debe haber suficiente espacio para todos los caracteres de la cadena, más un byte nulo terminador. Se suprime el salto habitual de los caracteres de espacio en blanco iniciales. La cadena debe estar compuesta por caracteres en (o no en) un conjunto particular; el conjunto se define por los caracteres entre el carácter de corchete abierto [ y un carácter de corchete cerrado ]. El conjunto excluye esos caracteres si el primer carácter después del corchete abierto es un circunflejo (^). Para incluir un corchete cerrado en el conjunto, conviértelo en el primer carácter después del corchete abierto o del circunflejo; cualquier otra posición finalizará el conjunto. El carácter guion - también es especial; cuando se coloca entre otros dos caracteres, agrega todos los caracteres intermedios al conjunto. Para incluir un guion, hazlo el último carácter antes del corchete cerrado final. Por ejemplo, [^]0-9-] significa el conjunto "todo excepto corchete cerrado, cero a nueve y guion". La cadena termina con la aparición de un carácter que no está en el conjunto (o, con un circunflejo, en él) o cuando se agota el ancho del campo.
p
Coincide con un valor de puntero (como se imprime con %p en printf(3)); el siguiente puntero debe ser un puntero a un puntero a void.
n
No se espera nada; en su lugar, el número de caracteres consumidos hasta el momento de la entrada se almacena a través del siguiente puntero, que debe ser un puntero a int, o una variante cuyo tamaño coincida con el modificador de longitud de entero (opcionalmente) proporcionado. Esto no es una conversión y no aumenta el recuento devuelto por la función. La asignación se puede suprimir con el carácter de supresión de asignación *, pero el efecto en el valor de retorno no está definido. Por lo tanto, las conversiones %*n no deben usarse.

VALOR DE RETORNO

En caso de éxito, estas funciones devuelven el número de elementos de entrada que se han emparejado y asignado con éxito; este número puede ser menor que el proporcionado, o incluso cero, en caso de una falla temprana de emparejamiento.

El valor EOF se devuelve si se alcanza el final de la entrada antes de que ocurra la primera conversión exitosa o una falla de emparejamiento.

ERRORES

EILSEQ
La secuencia de bytes de entrada no forma un carácter válido.
EINVAL
No hay suficientes argumentos; o format es NULL.
ENOMEM
Sin memoria.

NOTAS

El modificador de asignación-asignación 'a'

Originalmente, la biblioteca C de GNU admitía la asignación dinámica para entradas de cadenas (como una extensión no estándar) a través del carácter a. (Esta característica está presente al menos desde glibc 2.0). Por lo tanto, se podría escribir lo siguiente para que sscanf() asigne un búfer para una cadena, con un puntero a ese búfer que se devuelve en *buf:


char *buf;
sscanf(str, "%as", &buf);

El uso de la letra a para este propósito era problemático, ya que a también está especificado por el estándar C de ISO como un sinónimo de f (entrada de punto flotante). POSIX.1-2008 especifica en su lugar el modificador m para la asignación de asignación (como se documenta en DESCRIPCIÓN, anteriormente).

Tenga en cuenta que el modificador a no está disponible si el programa se compila con gcc -std=c99 o gcc -D_ISOC99_SOURCE (a menos que también se especifique _GNU_SOURCE), en cuyo caso la a se interpreta como un especificador para números de punto flotante (ver arriba).

El soporte para el modificador m se agregó a glibc 2.7, y los programas nuevos deberían usar ese modificador en lugar de a.

Además de estar estandarizado por POSIX, el modificador m tiene las siguientes ventajas adicionales sobre el uso de a:

•
También se puede aplicar a los especificadores de conversión %c (por ejemplo, %3mc).
•
Evita la ambigüedad con respecto al especificador de conversión de punto flotante %a (y no se ve afectado por gcc -std=c99 etc.).

ERRORES

Especificadores de conversión numérica

El uso de los especificadores de conversión numérica produce un comportamiento indefinido para la entrada no válida. Consulte C11 7.21.6.2/10. Este es un error en el estándar ISO C, y no un problema de diseño inherente de la API. Sin embargo, las implementaciones actuales no son inmunes a ese error, por lo que no se recomienda su uso. En su lugar, los programas deben utilizar funciones como strtol(3) para analizar la entrada numérica. Alternativamente, mitíguelo especificando un ancho de campo máximo.

Modificadores no estándar

Estas funciones cumplen totalmente con C99, pero proporcionan los modificadores adicionales q y a, así como un comportamiento adicional de los modificadores L y ll. Este último puede considerarse un error, ya que cambia el comportamiento de los modificadores definidos en C99.

Algunas combinaciones de los modificadores de tipo y los especificadores de conversión definidos por C99 no tienen sentido (por ejemplo, %Ld). Aunque pueden tener un comportamiento bien definido en Linux, esto no tiene por qué ser así en otros sistemas. Por lo tanto, generalmente es mejor utilizar modificadores que no están definidos por C99 en absoluto, es decir, usar q en lugar de L en combinación con las conversiones d, i, o, u, x y X o ll.

El uso de q no es el mismo que en 4.4BSD, ya que puede usarse en conversiones de punto flotante de manera equivalente a L.

NOTAS

La especificación POSIX.1-2001 para sscanf(3) especifica que los marcadores de conversión `%m[...]` solo están permitidos si el marcador de conversión `m` está disponible. Este marcador de conversión se introdujo en POSIX.1-2008.

El uso de `%m` para asignar memoria es una extensión de GNU y no está disponible en todos los sistemas.

Cuando se utiliza el marcador de conversión `%m[...]`, el comportamiento en la asignación de memoria es el siguiente:

  • Si la asignación de memoria falla, sscanf() devuelve el valor EOF y establece errno a ENOMEM.
  • Si la asignación de memoria tiene éxito, pero no se lee ningún carácter, sscanf() devuelve 0 y la cadena apuntada por *ptr se establece en NULL.
  • Si la asignación de memoria tiene éxito y se leen uno o más caracteres, sscanf() devuelve el número de elementos de entrada asignados (en este caso, 1) y la cadena apuntada por *ptr apunta a la cadena leída. La memoria asignada debe ser liberada por el llamante utilizando free(3).

A continuación se muestra un ejemplo de uso de %m[a-z]:


char *p;
int n;
errno = 0;
n = sscanf(str, "%m[a-z]", &p);
if (n == 1) {
    printf("read: %s\n", p);
    free(p);
} else if (errno != 0) {
    perror("sscanf");
} else {
    fprintf(stderr, "No matching characters\n");
}

Como se muestra en el ejemplo anterior, es necesario llamar a free(3) solo si la llamada a sscanf() leyó correctamente una cadena.
