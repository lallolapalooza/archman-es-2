VARIABLES(5) Net-SNMP VARIABLES(5)

NOMBRE


variables - Formato para especificar nombres de variables para herramientas SNMP.

DESCRIPCIÓN

La sintaxis y semántica de la información de gestión en SNMP se proporciona mediante las definiciones de objetos MIB, cargadas desde uno o más archivos MIB (o "módulos MIB"). Estas definiciones no son estrictamente necesarias para que el protocolo SNMP funcione correctamente, pero normalmente son necesarias para las aplicaciones cliente SNMP para mostrar la información de manera significativa.

El archivo MIB también sirve como documento de diseño al desarrollar un agente SNMP (o subagente) que proporciona esta información, y asegura que el cliente y el servidor compartan una comprensión común sobre lo que representa la información de gestión.

OIDS

Los objetos MIB se especifican utilizando Identificadores de Objeto (OIDs), que pueden tomar varias formas. Tenga en cuenta que todos los ejemplos de esta sección se refieren al mismo objeto MIB.

OIDs numéricos

El formato fundamental de un OID es una secuencia de valores enteros (o "subidentificadores"), típicamente escritos con puntos para separar los subidentificadores individuales.


.1.3.6.1.2.1.1.1
Este es el formato que se utiliza dentro del propio protocolo SNMP, en los paquetes que se envían por la red.

Esta forma de representar un OID no requiere que los archivos MIB o las definiciones de objetos MIB estén disponibles. Sin embargo, depende de que la aplicación cliente y/o el administrador de red sepan a qué se refiere un OID numérico dado. Como tal, no es una representación particularmente útil para nadie que esté empezando con SNMP.

Este formato se puede obtener proporcionando la opción de línea de comandos -On a la mayoría de los comandos Net-SNMP.

Ruta OID completa

Un formato similar (pero algo más informativo) utiliza la misma representación de lista de puntos, pero con los subidentificadores numéricos reemplazados por nombres, tomados del archivo(s) MIB(s) relevante(s).


.iso.org.dod.internet.mgmt.mib-2.system.sysDescr
Esto identifica de forma única un objeto MIB particular (como con el OID numérico), pero se espera que la lista de nombres dé alguna indicación sobre qué información representa este objeto. Sin embargo, depende de que los archivos MIB relevantes estén disponibles (al igual que todos los formatos distintos del OID puramente numérico). Dichos OIDs también tienden a ser bastante largos.

Este formato se puede obtener proporcionando la opción de línea de comandos -Of a la mayoría de los comandos Net-SNMP.

Una variante de esto (típicamente utilizada al escribir OIDs en texto descriptivo, en lugar de ejecutar programas), es combinar el nombre y el subidentificador numérico:


.iso(1).org(3).dod(6).internet(1).mgmt(2).mib-2(1).system(1)
.sysDescr(1)

OIDs cualificados por módulo

Una forma alternativa de especificar (más o menos) de forma única un OID, es dar el nombre del objeto MIB, junto con el módulo MIB donde se define.

SNMPv2-MIB::sysDescr
Los nombres de los objetos MIB son únicos dentro de un módulo dado, por lo que mientras no haya dos módulos MIB con el mismo nombre (lo cual es inusual, aunque no inaudito), este formato especifica el objeto deseado de forma razonablemente compacta. También facilita relativamente encontrar la definición del objeto MIB.

Este es el formato predeterminado para mostrar OIDs en las aplicaciones Net-SNMP. También se puede especificar explícitamente proporcionando la opción de línea de comandos -OS a la mayoría de los comandos Net-SNMP.

Nombre del objeto

Posiblemente la forma más común de especificar objetos MIB es usar el nombre del objeto solo, sin la ruta completa o el nombre del módulo que lo define.

sysDescr
Esta es, con mucho, la forma más corta y conveniente de referirse a un objeto MIB. Sin embargo, el peligro es que si dos módulos MIB definen cada uno un objeto MIB con el mismo nombre (lo cual es perfectamente legal en algunas circunstancias), entonces no está necesariamente claro a qué objeto MIB se refiere realmente. Para el uso diario, especialmente cuando se utilizan objetos MIB estándar, esto es *probablemente* seguro. Pero es importante ser consciente de las posibles ambigüedades.

Este formato se puede obtener proporcionando la opción de línea de comandos -Os a la mayoría de los comandos Net-SNMP.

Formato UCD

Las versiones anteriores del código (UCD v4.x y anteriores) utilizaron un enfoque simple para acortar la forma en que se especificaban los OIDs. Si la ruta completa del OID comenzaba con .iso.org.dod.internet.mgmt.mib-2, entonces este prefijo se eliminaba del OID antes de mostrarlo. Todos los demás OIDs se mostraban completos.

De manera similar, si un OID se pasaba a la biblioteca UCD que no comenzaba con un punto (y no estaba en el formato módulo::nombre), entonces se anteponía el mismo prefijo. Por lo tanto, el OID de ejemplo de los formatos enumerados anteriormente se daría o mostraría como:

system.sysDescr
El manejo inconsistente de los OIDs, dependiendo de su ubicación dentro del árbol de OIDs, resultó ser más problemático de lo que valía, y este formato ya no se recomienda.

El comportamiento anterior se puede obtener proporcionando la opción de línea de comandos -Ou (para mostrar la salida) o -Iu (para interpretar OIDs de entrada sin un punto inicial) a la mayoría de los comandos Net-SNMP.
