NOMBRE

vgremove — Eliminar grupo(s) de volúmenes

SINOPSIS

vgremove args_posicionales
[ args_opcionales ]

DESCRIPCIÓN

vgremove elimina uno o más VGs. Si existen LVs en el VG, se utiliza una solicitud para confirmar la eliminación del LV.

Si uno o más PVs en el VG se pierden, considera usar vgreduce --removemissing para que los metadatos del VG vuelvan a ser consistentes.

Repite la opción de forzar (-ff) para eliminar forzosamente los LVs en el VG sin confirmación.

USO

vgremove VG|Tag|Select ...

[ -f|--force ... ]
[ -S|--select Cadena ]
[ --noudevsync ]
[ --reportformat basic|json|json_std ]
[ OPCIONES_COMUNES ]

OPCIONES

--commandprofile Cadena
El perfil de comando a utilizar para la configuración del comando. Ver lvm.conf(5) para más información sobre perfiles.
--config Cadena
Configuraciones de comando para el comando. Estas anulan la configuración de lvm.conf(5). La cadena de argumento utiliza el mismo formato que lvm.conf(5), o puede utilizar sintaxis de sección/campo. Ver lvm.conf(5) para más información sobre la configuración.
-d|--debug ...
Establecer el nivel de depuración. Repetir de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción puede repetirse, o aceptar una lista de dispositivos separada por comas. Esto anula el archivo de dispositivos.
--devicesfile Cadena
Un archivo que lista los dispositivos que LVM debe utilizar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración devices/devicesfile y devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si se establece en no, el comando no intentará utilizar device-mapper. Para pruebas y depuración.
-f|--force ...
Anula varias comprobaciones, confirmaciones y protecciones. Usar con extrema precaución.
-h|--help
Muestra el texto de ayuda.
--journal Cadena
Registra información en el journal de systemd. Esta información es adicional a la información habilitada por la configuración de registro/journal de lvm.conf. command: registra información sobre el comando. output: registra la salida predeterminada del comando. debug: registra la depuración completa del comando.
--lockopt Cadena
Se utiliza para pasar opciones para casos especiales a lvmlockd. Ver lvmlockd(8) para más información.
--longhelp
Muestra el texto de ayuda largo.
--nohints
No utilizar el archivo de pistas para localizar dispositivos para PVs. Un comando puede leer más dispositivos para encontrar PVs cuando no se usan pistas. El comando aún realizará la invalidación estándar del archivo de pistas cuando sea apropiado.
--nolocking
Desactivar el bloqueo. Usar con precaución, los comandos concurrentes pueden producir resultados incorrectos.
--noudevsync
Desactiva la sincronización de udev. El proceso no esperará la notificación de udev. Continuará independientemente de cualquier posible procesamiento de udev en segundo plano. Solo usar esto si udev no se está ejecutando o tiene reglas que ignoran los dispositivos que LVM crea.
--profile Cadena
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
-q|--quiet ...
Suprimir la salida y los mensajes de registro. Anula --debug y --verbose. Repetir una vez para suprimir también cualquier solicitud con respuesta "no".
--reportformat basic|json|json_std
Anula el formato de salida actual para los informes, que se define globalmente por la configuración report/output_format en lvm.conf(5). basic es el formato original con columnas y filas. Si hay más de un informe por comando, cada informe se precede del nombre del informe para su identificación. json produce la salida del informe en formato JSON. json_std produce la salida del informe en formato JSON que es más compatible con el estándar JSON. Ver lvmreport(7) para más información.
-S|--select Cadena
Seleccionar objetos para procesar y reportar basándose en criterios especificados. La sintaxis de los criterios se describe con --select help y lvmreport(7). Para los comandos de reporte, se muestra una fila por cada objeto que coincida con los criterios. Ver --options help para los campos de objetos seleccionables. Las filas pueden mostrarse con un campo adicional "selected" (-o selected) que muestra 1 si la fila coincide con la selección y 0 en caso contrario. Para comandos no de reporte que procesan entidades LVM, la selección se utiliza para elegir los elementos a procesar.
-t|--test
Ejecutar en modo de prueba. Los comandos no actualizarán metadatos. Esto se implementa deshabilitando toda escritura de metadatos pero devolviendo éxito a la función llamante. Esto puede llevar a mensajes de error inusuales en operaciones de múltiples etapas si una herramienta depende de leer metadatos que cree que ha cambiado pero no lo ha hecho.
-v|--verbose ...
Establecer el nivel detallado. Repetir de 1 a 4 veces para aumentar el detalle de los mensajes enviados a stdout y stderr.
--version
Muestra la información de la versión.
-y|--yes
No solicitar confirmación interactivamente, sino asumir siempre la respuesta sí. Usar con extrema precaución. (Para un no automático, ver -qq).

vgremove(8) - Arch Linux

NAME

vgremove — remove a volume group

SYNOPSIS

vgremove [--force] [--removemissing] LogicalVolumePath... | LogicalVolumeName...

vgremove [--force] [--removemissing] VolumeGroupName...

DESCRIPTION

The vgremove command removes one or more volume groups. The volume group metadata is removed, and if the volume group is associated with a device mapper (DM) multipath device, that device is removed.

All logical volumes in the volume group must be removed first using lvremove (8). If the volume group is still active, it must be deactivated using vgchange (8) -a n.

OPTIONS

--force
Force the removal of the volume group. This option should be used with caution, as it can lead to data loss if not used correctly.
--removemissing
Remove missing physical volumes from the volume group. This option should be used with caution, as it can lead to data loss if not used correctly.

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.
