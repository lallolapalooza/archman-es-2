Paquete: dnssec-tools

NOMBRE

val_create_context() val_free_context() - gestiona el contexto del validador

val_context_setqflags() - gestiona las banderas del contexto del validador

val_resolve_and_check(), val_free_result_chain() - consulta y valida respuestas de un servidor de nombres DNS

val_istrusted() - comprueba si el valor de estado corresponde al de una respuesta confiable

val_isvalidated() - comprueba si el valor de estado representa una respuesta que encadena criptográficamente desde un ancla de confianza configurada

val_does_not_exist() - comprueba si el valor de estado representa uno de los tipos de no existencia

p_val_status(), p_ac_status(), p_val_error() - muestra el estado de validación, el estado de la cadena de autenticación y la información de errores

val_log_add_optarg - controla la verbosidad de los mensajes de registro y la ubicación de la salida

DESCRIPCIÓN

La función val_resolve_and_check() consulta un conjunto de servidores de nombres para la tupla <nombre_dominio, tipo, clase> y verifica y valida la respuesta. La verificación implica comprobar los RRSIGs, y la validación es la verificación de una cadena de autenticación desde un ancla de confianza configurada.

El parámetro flags se puede utilizar para controlar los resultados de la validación. Los siguientes valores, que se pueden ORar juntos, están actualmente definidos para este campo:

VAL_QUERY_DONT_VALIDATE
Esta bandera hace que el validador desactive la validación para esta consulta.
VAL_QUERY_IGNORE_SKEW
Esta bandera hace que el validador desactive la comprobación de los tiempos de inicio y expiración de las firmas en los RRSIGs.
VAL_QUERY_AC_DETAIL
Esta bandera hace que el validador copie los detalles de la cadena de autenticación en el miembro val_rc_answer dentro de la estructura devuelta val_result_chain.
VAL_QUERY_ASYNC
Esta bandera habilita la resolución de consultas asíncrona para esa búsqueda.
VAL_QUERY_NO_DLV
Esta bandera hace que el validador desactive el procesamiento DLV para esta consulta. Esto solo está disponible si la biblioteca libval(3) ha sido compilada con soporte DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
Al consultar varios servidores de nombres, libsres(3) también intentará varios tamaños de EDNS0, terminando con una consulta que tiene EDNS0 deshabilitado (es decir, sin el bit CD establecido). Esta bandera hace que libval desactive la recuperación automática de EDNS0 para la consulta.
VAL_QUERY_ITERATE
Esta bandera fuerza a libval a realizar una búsqueda iterativa consultando varios servidores de nombres en la jerarquía de delegación, en lugar de solicitar esta información a cualquier servidor de nombres en caché que pueda estar configurado en dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Esta bandera fuerza a libval a mirar solo su caché al intentar resolver un nombre.
VAL_QUERY_SKIP_CACHE
Hay dos niveles de caché que ocurren dentro de libval: en el nivel de afirmación y en el nivel de respuesta. Esta bandera fuerza a libval a ignorar los datos en ambas cachés al intentar resolver un nombre.
VAL_QUERY_SKIP_ANS_CACHE
Hay dos niveles de caché que ocurren dentro de libval: en el nivel de afirmación y en el nivel de respuesta. Esta bandera fuerza a libval a ignorar los datos en la caché de respuestas al intentar resolver un nombre. Si ya existe una afirmación para el nombre, clase y tipo dados, esa afirmación se reutiliza hasta que expira. Una vez que expira, el nombre se busca a través de una consulta incluso si un registro más nuevo (obtenido por otra afirmación en el mismo o diferente contexto) está disponible en su caché de respuestas.

El primer parámetro de val_resolve_and_check() es el contexto del validador. Las aplicaciones pueden crear un nuevo contexto de validador utilizando la función val_create_context(). Esta función analiza los archivos de configuración del resolvedor y validador y crea el manejador newcontext para esta información analizada. La información almacenada como parte del contexto del validador incluye la política de validación y la política del resolvedor.

Las políticas del validador y del resolvedor se leen de los archivos /etc/dnsval.conf y /etc/resolv.conf por defecto. /etc/root.hints proporciona información de arranque para el validador cuando funciona como un resolvedor completo (ver dnsval.conf(3)). Estos valores por defecto pueden ser diferentes si se especificó algún otro valor en el momento de la configuración de la biblioteca. Si el archivo de configuración del resolvedor por defecto no se encuentra en la ubicación especificada, libval también intentará recurrir a /etc/resolv.conf como último recurso.

Las aplicaciones también pueden crear un contexto de validador con una política personalizada utilizando la función val_create_context_ex().

El argumento opt en val_create_context_ex() apunta a la siguiente estructura:

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags especifica las banderas de consulta por defecto para las consultas asociadas con el contexto. Este campo es idéntico al argumento flags en la función val_resolve_and_check().

Los campos vc_val_conf, vc_res_conf y vc_root_conf se pueden utilizar para especificar archivos de configuración alternativos en lugar de los archivos por defecto utilizados para la información de configuración del validador, resolvedor y pistas raíz.

El campo vc_valpol se puede utilizar para proporcionar un "fragmento" de configuración de validador personalizado al validador. El validador analiza esta información y la aplica a la configuración del validador por defecto, ya sea como una extensión o como una anulación, según lo especificado por el campo vc_polflags. El campo vc_nslist, de manera similar, se puede utilizar para proporcionar una lista personalizada de servidores de nombres recursivos a los que enviar consultas, además (o en lugar) de la lista de servidores de nombres especificada en el archivo resolv.conf. La lista de servidores de nombres en vc_res_conf debe especificarse como una lista de direcciones IP o IPv6 separadas por espacios.

Se puede crear una asignación personalizada entre una zona y un servidor de nombres utilizando la función val_context_store_ns_for_zone().

vc_polflags se puede configurar con los siguientes valores:

CTX_DYN_POL_VAL_OVR
Cuando esta bandera está activada, solo se utiliza la configuración del validador especificada en el campo vc_valpol para la configuración del validador. Las opciones especificadas en el archivo dnsval.conf se ignoran.
CTX_DYN_POL_RES_OVR
Similarmente, cuando esta bandera está activada, la configuración del resolvedor especificada en el campo vc_res_conf se utiliza como la única configuración del resolvedor. Las opciones especificadas en el archivo resolv.conf se ignoran.
CTX_DYN_POL_ADD_NS
Cuando esta bandera está activada, la lista de servidores de nombres especificada en el campo vc_nslist se añade a la lista de servidores de nombres configurados en el archivo resolv.conf.
CTX_DYN_POL_ADD_VAL
Cuando esta bandera está activada, la configuración del validador especificada en el campo vc_valpol se añade a la configuración del validador existente, en lugar de anularla.

Si no se proporcionan opciones personalizadas (es decir, si opt es NULL), la función val_create_context_ex() se comportará de manera idéntica a val_create_context().

La función val_context_setqflags() permite establecer o anular las banderas de consulta para un contexto de validador existente. El parámetro action puede ser establecido a VAL_CTXT_SET_FLAGS, VAL_CTXT_ADD_FLAGS o VAL_CTXT_REM_FLAGS para definir, añadir o eliminar banderas respectivamente del conjunto de banderas de consulta existentes para el contexto.

La función val_context_store_ns_for_zone() permite a las aplicaciones especificar el servidor de nombres preferido para una zona específica y si las consultas deben ser recursivas o no. Esto es útil cuando se está configurando una vista específica de DNS.

El resultado de la consulta y verificación se devuelve en la estructura val_result_chain. Esta estructura contiene un puntero a la respuesta DNS real (dentro de la subestructura val_rc_answer), así como información sobre el estado de la validación. Las aplicaciones deben liberar la memoria asignada para esta estructura utilizando val_free_result_chain() cuando ya no se necesite.

Las funciones p_val_status(), p_ac_status() y p_val_error() se utilizan para convertir los códigos de estado numéricos devueltos por las funciones de libval en cadenas legibles por humanos.

Las funciones val_istrusted(), val_isvalidated() y val_does_not_exist() proporcionan una forma conveniente para que las aplicaciones interpreten el estado de validación devuelto por val_resolve_and_check().

La función val_log_add_optarg() permite a las aplicaciones configurar el registro de libval. El argumento args se pasa a la función syslog() si use_stderr es 0, o se utiliza como argumento para stderr si use_stderr es distinto de cero. Consulte la página del manual de syslog() para obtener más detalles sobre el formato de los argumentos.

Finalmente, la función val_free_context() libera la memoria asignada para un contexto de validador.

VER TAMBIÉN

dnsval.conf(3), resolv.conf(5), syslog(3)

DESCRIPCIÓN

El propósito de estas rutinas es establecer y obtener las políticas de validación de DNSSEC para un contexto de validación dado. Estas rutinas permiten anular o establecer las opciones de configuración predeterminadas que se encuentran en el archivo de configuración dnsval.conf.

La política de validación se configura principalmente a través del campo flags. Estos son un conjunto de indicadores que configuran el comportamiento del validador. Los indicadores se pueden combinar usando el operador OR bit a bit.

CTX_DYN_POL_RES_OVR
Cuando este indicador está activado, solo se utilizan los servidores de nombres especificados en el campo vc_nslist para la configuración del resolvedor. Las opciones especificadas en el archivo resolv.conf se ignoran.
CTX_DYN_POL_GLO_OVR
Cuando este indicador está activado, solo se utilizan las opciones globales establecidas en el campo gopt. Las opciones globales especificadas en el archivo dnsval.conf se ignoran.
CTX_DYN_POL_RES_NRD
Cuando este indicador está activado, las consultas salientes tienen el bit Recursion Desired (RD) establecido en 0. Esto es útil si las consultas deben enviarse a un servidor de nombres solo autoritativo.

El campo gopt apunta a la siguiente estructura:

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

Establecer un valor de 1 para local_is_trusted es equivalente a especificar la opción trust-oob-answers en el archivo dnsval.conf a yes. De manera similar, establecer los miembros closest_ta_only y rec_fallback en 1 es equivalente a establecer las opciones closest-ta-only y rec-fallback a yes en el archivo dnsval.conf. Un valor de 0 es equivalente a la configuración no para estas opciones.

Establecer el miembro edns0_size a un valor particular tiene el mismo efecto que establecer la opción edns0-size en el archivo dnsval.conf.

Establecer el miembro max_refresh a un valor particular tiene el mismo efecto que establecer la opción max-refresh en el archivo dnsval.conf.

Establecer el miembro proto a un valor particular tiene el mismo efecto que establecer la opción proto en el archivo dnsval.conf.

env_policy y app_policy se pueden establecer en uno de VAL_POL_GOPT_DISABLE, VAL_POL_GOPT_ENABLE o VAL_POL_GOPT_OVERRIDE. Estos valores corresponden directamente a las opciones disable, enable y override para las configuraciones env-policy y app-policy en el archivo dnsval.conf.

Los valores de -1 para los campos anteriores se tratan como condiciones de "ignorar", de modo que el validador no incluirá las opciones globales suministradas dinámicamente con un valor de -1 al crear su contexto. Esto permite que una aplicación anule un subconjunto de opciones globales mientras utiliza las opciones globales suministradas en el archivo dnsval.conf por defecto.

El campo log_target permite a la aplicación proporcionar destinos de registro *además* de los configurados en el archivo de configuración.

Consulte dnsval.conf(3) para obtener más detalles sobre la especificación de la política del validador.

Las marcas de consulta predeterminadas se pueden establecer y desestablecer para un contexto dado utilizando val_context_setqflags(). Esto permite que una aplicación altere el procesamiento del validador DNSSEC, mientras aún tiene la mayor parte de la configuración predeterminada más granular especificada en su archivo de configuración. El parámetro action se puede establecer en una de las siguientes opciones.

VAL_CTX_FLAG_SET
Esta opción hace que el validador establezca la marca dada como una de las marcas de consulta predeterminadas.
VAL_CTX_FLAG_RESET
Esta opción hace que el validador restablezca la marca dada si se estableció como una de las marcas de consulta predeterminadas para el contexto.

Las respuestas devueltas por val_resolve_and_check() están disponibles en la lista enlazada *results. Cada respuesta corresponde a un RRset distinto; múltiples RRs dentro del RRset forman parte de la misma respuesta. Son posibles múltiples respuestas cuando type es ns_t_any o ns_t_rrsig.

Los elementos individuales en *results apuntan a listas enlazadas val_authentication_chain. Los elementos de la cadena de autenticación en val_authentication_chain contienen los RRsets reales devueltos por el servidor de nombres en respuesta a la consulta.

Los valores de resultado de validación devueltos en val_result_chain se pueden convertir a formato ASCII utilizando la función p_val_status(). Los valores de estado de la cadena de autenticación devueltos en cada elemento de la lista enlazada val_authentication_chain se pueden convertir a formato ASCII utilizando las funciones p_ac_status().

Mientras que algunas aplicaciones, como las utilidades de resolución de problemas de DNSSEC y las herramientas de inspección de paquetes, pueden examinar elementos individuales de la cadena de autenticación para identificar las razones reales del error de validación, la mayoría de las aplicaciones solo estarán interesadas en un único código de error para determinar la autenticidad de los datos.

val_isvalidated() identifica si un valor de estado de resultado de validación dado corresponde a una respuesta que fue verificada criptográficamente y validada utilizando un ancla de confianza configurada localmente.

val_istrusted() identifica si un valor de estado del validador dado es de confianza. Una respuesta puede ser confiable localmente sin ser validada.

val_does_not_exist() identifica si un valor de estado del validador dado corresponde a uno de los tipos de no existencia.

La biblioteca libval asigna memoria internamente para *results y la aplicación invocante debe liberarla utilizando la interfaz free_result_chain().

ESTRUCTURAS DE DATOS

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
Cadena de autenticación para un RRset dado.
val_rc_next
Puntero al siguiente RRset en el conjunto de respuestas devueltas para una consulta.
val_rc_proofs
Puntero a las cadenas de autenticación para cualquier prueba de no existencia que se haya devuelto para la consulta.
val_rc_proof_count
Número de elementos de prueba almacenados en val_rc_proofs. El número no puede exceder MAX_PROOFS.
val_rc_alias
Para un elemento val_result_chain que apunta a un alias de nombre, este campo contiene el valor de destino.
val_rc_rrset
Para un elemento val_result_chain que contiene un campo val_rc_answer válido (no NULL), el campo val_rc_rrset apunta al elemento val_rrset_rec de nivel superior en la cadena de autenticación val_rc_answer.
val_rc_status
Estado de validación para un RRset dado. Este puede ser uno de los siguientes:
VAL_SUCCESS
Respuesta recibida y validada con éxito.
VAL_NONEXISTENT_NAME
No existía el nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante (intervalo NSEC o NSEC3). Los componentes de la prueba también se validaron individualmente.
VAL_NONEXISTENT_TYPE
No existía el tipo para el nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante. Los componentes de la prueba también se validaron individualmente.
VAL_NONEXISTENT_NAME_NOCHAIN
No existía el nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante. Los componentes de la prueba también se identificaron como confiables, pero no se validaron individualmente.
VAL_NONEXISTENT_TYPE_NOCHAIN
No existía el tipo para el nombre y se devolvió una prueba válida de no existencia que confirmaba el nombre faltante (intervalo NSEC o NSEC3). Los componentes de la prueba también se identificaron como confiables, pero no se validaron individualmente.
VAL_PINSECURE
Se sabía que el registro o algún antecesor del registro en la cadena de autenticación hacia el ancla de confianza era demostrablemente inseguro.
VAL_PINSECURE_UNTRUSTED
Se sabía que el registro o algún antecesor del registro en la cadena de autenticación hacia el ancla de confianza era demostrablemente inseguro. Pero la condición demostrablemente insegura se configuró como no confiable.
VAL_BARE_RRSIG
No es posible la validación DNSSEC, la consulta era para un RRSIG.
VAL_IGNORE_VALIDATION
La política local se configuró para ignorar la validación de la zona de la cual se recibieron estos datos.
VAL_UNTRUSTED_ZONE
La política local se configuró para rechazar cualquier dato recibido de la zona dada.
VAL_OOB_ANSWER
La respuesta se obtuvo utilizando algún método Out Of Band, como un archivo de configuración local.
VAL_BOGUS
La respuesta no pudo ser validada debido a fallos en la verificación de firmas o a la incapacidad de verificar las pruebas en la cadena de autenticación.
VAL_DNS_ERROR
Se encontró algún error durante el procesamiento de DNS.
VAL_INDETERMINATE
La respuesta no pudo ser validada debido a la falta de metadatos DNSSEC
VAL_UNKNOWN
The validation status is unknown.
VAL_UNSET
The validation status has not been set.
VAL_SUCCESS
Validation passed.
VAL_FAIL
Validation failed.
VAL_ERROR
An error occurred during validation.
VAL_NO_DATA
No data was returned for the query and no error was indicated.
VAL_NO_respuesta
No response was received from the DNS server.
VAL_NXDOMAIN
The domain name does not exist.
VAL_SERVFAIL
The server failed to process the request due to an internal error.
VAL_TIMEOUT
The query timed out.
VAL_REFUSED
The DNS server refused to answer the query.
VAL_BADQUERY

The response was malformed.
VAL_BADTIME

VAL_BADRRSIG
The RRSIG is invalid.
VAL_NODATA_EXPECTED
No data was expected, but data was returned.
VAL_DATA_EXPECTED
Data was expected, but no data was returned.
VAL_BOGUS
The data is considered bogus.
VAL_INSECURE
The data is not secure.
VAL_NO_ANCHOR

VAL_NO_KEYS

VAL_NOT_IMPLEMENTED

Los valores de estado en val_status_t devueltos por el validador pueden mostrarse en formato ASCII usando p_val_status().

struct val_authentication_chain
struct val_authentication_chain
{
    val_astatus_t                    val_ac_status;
    struct val_rrset_rec                *val_ac_rrset;
    struct val_authentication_chain *val_ac_trust;
};
val_ac_status
Estado de validación del elemento de la cadena de autenticación. Este campo contendrá el código de estado para el componente dado en la cadena de autenticación. Este campo puede contener uno de los siguientes valores:
VAL_AC_UNSET
No se pudo determinar el estado.
VAL_AC_IGNORE_VALIDATION
Se ignoró la validación del registro de recursos dado, ya sea debido a alguna directiva de política local o a algún comportamiento específico del protocolo.
VAL_AC_UNTRUSTED_ZONE
La política local definió una zona dada como no confiable, sin que se considerara necesaria ninguna validación adicional.
VAL_AC_PINSECURE
No se pudo construir la cadena de autenticación desde un ancla de confianza a una zona dada debido a la ausencia demostrable de un registro DS para esta zona en el padre.
VAL_AC_BARE_RRSIG
La respuesta fue para una consulta de tipo RRSIG. Los RRSIG contienen las firmas criptográficas para otros datos DNS y no pueden ser validados por sí mismos.
VAL_AC_NO_LINK
No se configuró ningún ancla de confianza para una cadena de autenticación dada o la cadena no se enlazó.
VAL_AC_TRUST
Al menos una de las firmas que cubren el conjunto de registros DNSKEY dado se verificó directamente utilizando una clave configurada como un ancla de confianza DNSSEC.
VAL_AC_RRSIG_MISSING
No se pudieron recuperar los datos RRSIG para un registro de recursos.
VAL_AC_DNSKEY_MISSING
No se pudo recuperar el DNSKEY de un RRSIG que cubre un registro de recursos.
VAL_AC_DS_MISSING
No estuvo disponible el registro DS que cubre un registro DNSKEY.
VAL_AC_DATA_MISSING
No se devolvieron datos para una consulta y el DNS no indicó un error.
VAL_AC_DNS_ERROR
Se encontró algún error durante el procesamiento de DNS.
VAL_AC_NOT_VERIFIED
No se pudieron verificar todos los RRSIG que cubren el conjunto de registros.
VAL_AC_VERIFIED
Al menos un RRSIG que cubre un registro de recursos tuvo un estado de VAL_AC_RRSIG_VERIFIED.

REGISTRO

libval proporciona la función val_log_add_optarg() para controlar la verbosidad y la ubicación de la salida de los mensajes de registro.

La función val_log_add_optarg() toma dos argumentos: el primer argumento args es un valor de cadena de caracteres que especifica la ubicación y la verbosidad. El segundo argumento, use_stderr, si se establece en un valor mayor que 0, permite que libval envíe mensajes de registro a stderr.

La cadena de caracteres que especifica la ubicación y la verbosidad del destino del registro tiene un formato específico:

<debug-level>:<dest-type>[:<dest-options>]

donde
<debug-level> es 1-7, para niveles crecientes de verbosidad
<dest-type> es uno de file, net, syslog, stderr, stdout
<dest-options> depende de <dest-type>
file:<nombre-archivo> (abierto en modo de adjuntar)
net[:<nombre-host>:<puerto-host>] (127.0.0.1:1053)
syslog[:facility] (0-23 (predeterminado 1 USER))

Los niveles de registro se pueden traducir aproximadamente en diferentes tipos de mensajes de registro de la siguiente manera (los mensajes devueltos para cada nivel en esta lista subsumen los mensajes devueltos para el nivel anterior):

3 : Error   : error encontrado
4 : Warning : recuperación de error
5 : Notice  : proporciona resultados de validación finales para una consulta
              y detalles sobre archivos de políticas y etiquetas utilizadas
6 : Info

The validator library is intended to be used by DNSSEC-aware applications to validate DNS records. This library is not intended to be a full DNSSEC validation solution by itself.

The validator library supports the following flags:

The validator library supports the following logging levels:

    1 : Error : Gives error level information
    2 : Warn  : Gives warning level information
    3 : Info  : Gives informational messages
    4 : Parse : Gives parsing information
    5 : Chain : gives details on authentication chains
    6 : Debug : gives debug level information
