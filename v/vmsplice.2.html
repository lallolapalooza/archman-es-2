vmsplice(2) Manual de llamadas al sistema vmsplice(2)

NOMBRE

vmsplice - acopla páginas de usuario a/desde una tubería

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#define _GNU_SOURCE         /* Ver feature_test_macros(7) */
#include <fcntl.h>
ssize_t vmsplice(int fd, const struct iovec *iov,
                 size_t nr_segs, unsigned int flags);

DESCRIPCIÓN

Si fd está abierto para escritura, la llamada al sistema vmsplice() mapea nr_segs rangos de memoria de usuario descritos por iov en una tubería. Si fd está abierto para lectura, la llamada al sistema vmsplice() rellena nr_segs rangos de memoria de usuario descritos por iov desde una tubería. El descriptor de archivo fd debe referirse a una tubería.

El puntero iov apunta a un array de estructuras iovec como se describe en iovec(3type).

El argumento flags es una máscara de bits que se compone ORando cero o más de los siguientes valores:

SPLICE_F_MOVE
No utilizado para vmsplice(); ver splice(2).
SPLICE_F_NONBLOCK
No bloquear en I/O; ver splice(2) para más detalles.
SPLICE_F_MORE
Actualmente no tiene efecto para vmsplice(), pero puede implementarse en el futuro; ver splice(2).
SPLICE_F_GIFT
Las páginas de usuario son un regalo para el kernel. La aplicación no puede modificar esta memoria nunca, de lo contrario, la caché de páginas y los datos en disco pueden diferir. Regalar páginas al kernel significa que un splice(2) posterior con SPLICE_F_MOVE puede mover las páginas con éxito; si esta bandera no se especifica, entonces un splice(2) posterior con SPLICE_F_MOVE debe copiar las páginas. Los datos también deben estar adecuadamente alineados por página, tanto en memoria como en longitud.

VALOR DE RETORNO

Tras una finalización exitosa, vmsplice() devuelve el número de bytes transferidos a la tubería. En caso de error, vmsplice() devuelve -1 y errno se establece para indicar el error.

ERRORES

EAGAIN
Se especificó SPLICE_F_NONBLOCK en flags, y la operación bloquearía.
EBADF
fd no es válido, o no se refiere a una tubería.
EINVAL
nr_segs es mayor que IOV_MAX; o la memoria no está alineada si se estableció SPLICE_F_GIFT.
ENOMEM
Sin memoria.

ESTÁNDARES

Linux.

HISTORIA

Linux 2.6.17, glibc 2.5.

NOTAS

vmsplice() sigue a las otras funciones de tipo de lectura/escritura vectorizadas en cuanto a las limitaciones en el número de segmentos que se pasan. Este límite es IOV_MAX tal como se define en <limits.h>. Actualmente, este límite es 1024.

vmsplice() realmente solo admite el acoplamiento real desde memoria de usuario a una tubería. En la dirección opuesta, en realidad solo copia los datos al espacio de usuario. Pero esto hace que la interfaz sea agradable y simétrica, y permite a las personas construir sobre vmsplice() con espacio para mejoras futuras en el rendimiento.

VER TAMBIÉN

splice(2), tee(2), pipe(7)
