NOMBRE

vvp - Motor de ejecución en tiempo de ejecución de Icarus Verilog

SINOPSIS

vvp [-inNsvV] [-Mruta] [-mdel_modulo] [-larchivo_registro] archivo_entrada [argumentos_extendidos...]

DESCRIPCIÓN

vvp es el motor de ejecución en tiempo de ejecución que ejecuta la forma compilada predeterminada generada por Icarus Verilog. La salida del comando iverilog no es ejecutable por sí sola en ninguna plataforma. En cambio, se invoca el programa vvp para ejecutar el archivo de salida generado.

OPCIONES

vvp acepta las siguientes opciones:

-i
Este indicador hace que toda la salida a <stdout> no tenga búfer.
-larchivo_registro
Este indicador especifica un archivo de registro donde va toda la salida de MCI <stdlog>. Especifique archivo_registro como '-' para enviar la salida del registro a <stderr>. $display y similares envían su salida tanto a <stdout> como a <stdlog>.
-Mruta
Este indicador agrega un directorio a la lista de rutas utilizada para localizar módulos VPI. La ruta predeterminada incluye solo el directorio de instalación para el módulo system.vpi, pero este indicador puede agregar otros directorios. Se permiten múltiples rutas y los módulos se buscarán en orden.
-mdel_modulo
Indica al motor de ejecución vvp que cargue el módulo nombrado antes de ejecutar la simulación. El módulo system.vpi se carga por defecto, pero se pueden especificar módulos adicionales, incluidos módulos que compiló localmente, con este indicador. Se pueden cargar cualquier número de módulos y se enlazarán en el orden en que aparecen en la línea de comandos.

Normalmente, solo necesita especificar el nombre del módulo, sin ninguna ruta de directorio o sufijo .vpi, y la ruta de búsqueda se escanea para encontrar el módulo. Sin embargo, si el nombre incluye al menos un carácter de directorio, la ruta de búsqueda no se escanea y se asume que el nombre es un nombre de archivo completo.

-n
Este indicador hace que $stop o <Control-C> sean sinónimos de $finish. Se puede usar para dar al programa una interfaz más significativa cuando se ejecuta en un entorno no interactivo.
-N
Este indicador hace lo mismo que -n, pero da como resultado un código de salida de 1 si la simulación llama a $stop. Se puede usar para indicar un fallo de simulación al ejecutar un banco de pruebas.
-s
Stop (Detener). Esto hará que la simulación se detenga al principio, antes de que se programen eventos. Esto permite al usuario interactivo controlar la simulación justo antes de que comience.
-v
Activar mensajes detallados. Esto hará que se imprima información sobre el progreso en tiempo de ejecución en la salida estándar.
-V
Imprimir la versión del tiempo de ejecución y salir.

ARGUMENTOS EXTENDIDOS

Las opciones de vvp descritas anteriormente deben aparecer antes del nombre del archivo de diseño. Sin embargo, después del nombre del archivo de diseño, puede haber cualquier número de argumentos no especificados. Estos argumentos no son interpretados por vvp, sino que se pasan al diseño ejecutado y están disponibles a través de las funciones del sistema $test$plusargs y $value$plusargs.

Los argumentos que no comienzan con el carácter de signo más (+) no están disponibles para las tareas del sistema $plusargs, pero aún se pueden acceder a través del código PLI mediante la función vpi_get_vlog_info. Esto significa que los módulos vpi pueden usar argumentos que no comienzan con + y asegurarse de que no interfieran con los plus-args definidos por el usuario.

Hay algunos argumentos extendidos que son interpretados por el módulo system.vpi estándar, que implementa las tareas del sistema estándar y siempre se incluye. Estos argumentos se describen aquí.

-vcd
Este argumento extendido establece el formato de volcado de ondas en VCD. Este es el predeterminado en ausencia de cualquier variable de entorno IVERILOG_DUMPER. Los archivos de volcado VCD son grandes y lentos, pero también son máximamente compatibles con herramientas de terceros que leen volcados de ondas.
-lxt|-lxt-speed|-lxt-space
Estos argumentos extendidos establecen el formato de volcado de ondas en lxt, posiblemente con optimizaciones de formato. El indicador -lxt-space establece el formato de salida en lxt con compresión completa habilitada. Los archivos resultantes son bastante pequeños. El -lxt-speed elige el modo de compresión lxt que conduce al mejor tiempo de ejecución y al tiempo de lectura más rápido, a expensas de un cierto tamaño de archivo.
-lxt2|-lxt2-speed|-lxt2-space

-lx2|-lx2-speed|-lx2-space
El formato LXT2 es más lento que LXT pero generalmente ocupa menos espacio y se escribe incrementalmente. Por lo tanto, puede ver archivos lxt2 mientras una simulación aún se está ejecutando (o pausada) o si su simulación falla o se interrumpe, aún tiene un volcado útil. Los argumentos -lxt2-speed o -lx2-speed son los mismos que -lxt2 o -lx2. Los argumentos -lxt2-space o -lx2-space habilitan una mejor compresión y desactivan la escritura incremental.
-fst|-fst-speed|-fst-space

-fst-space-speed|-fst-speed-space
Este es un formato de volcado moderno que es más rápido y más compacto que los otros formatos de volcado. Admite volcado incremental al igual que -lxt2. El argumento -fst-speed utiliza métodos de compresión más rápidos que crean un archivo de salida notablemente más grande. El argumento -fst-space realiza un reempaquetado del archivo al cerrarlo para producir el archivo de volcado más pequeño posible. Los argumentos -fst-space-speed o -fst-speed-space utilizan el método de compresión más rápido y reempaquetan el archivo al cerrarlo.
-none
Este indicador se puede usar solo o adjunto al final de los volcadores anteriores (vcd/lxt/lxt2/lx2/fst) para suprimir toda la salida de ondas. Esto puede hacer que las simulaciones largas se ejecuten más rápido.
-sdf-warn
Al cargar un archivo de anotación SDF, esta opción hace que el anotador imprima advertencias sobre problemas cuestionables pero no fatales.
-sdf-info
Al cargar un archivo de anotación SDF, esta opción hace que el anotador imprima información sobre la anotación.
-sdf-verbose
Esta es una abreviatura de -sdf-info -sdf-warn.
-compatible
Este argumento extendido mejora la compatibilidad con otros simuladores. Actualmente, esto solo afecta el formato de visualización de números reales cuando no se proporciona una cadena de formato.

AMBIENTE

El comando vvp también acepta algunas variables de entorno que controlan su comportamiento. Estas se pueden usar para realizar cambios semipermanentes.

IVERILOG_DUMPER=fst|lxt|lxt2|lx2|vcd|none
Esto selecciona el formato de salida para la salida de ondas. Normalmente, las ondas se vuelcan en formato vcd, pero esta variable se puede usar para seleccionar el formato lxt, que es mucho más compacto, aunque limitado a GTKWave o visores compatibles. También se puede utilizar para suprimir la salida VCD, un ahorrador de tiempo para pruebas de regresión.
IVERILOG_VPI_MODULE_PATH=/alguna/ruta:/otra/ruta
Esto agrega componentes adicionales a la ruta de búsqueda de módulos VPI. Las rutas especificadas de esta manera se buscan después de las rutas especificadas con -M, pero antes de la ruta de búsqueda predeterminada. Se pueden separar múltiples rutas con dos puntos (punto y coma si se usa Windows).

NAME

vvp - Icarus Verilog simulation runner

SYNOPSIS

vvp [-M<path>] [-m<module>] [-d] [-q] [-n] [-l] [-V] [-?] [-v] [simfile] [arguments...]

DESCRIPTION

The vvp command is used to run the simulation output of the iverilog compiler. The simulation output is typically a file ending in .vvp, but can be any executable file.

The simulation runner will load the specified simulation file, and then load any dynamically loadable Verilog Procedure Interface (VPI) modules that are specified either on the command line or in the simulation file. It will then run the simulation from time zero until the simulation completes. All standard Verilog output, such as display, $strobe, and $monitor, will be printed to standard output.

OPTIONS

-M<path>
Adds the specified <path> to the list of directories in which to search for loadable VPI modules. This option may be repeated to specify multiple directories.
-m<module>
Loads the specified VPI module. This option may be repeated to load multiple modules. If the module name contains a comma, it is treated as a comma-separated list of modules. This option is often used to load debugging or simulation control modules.
-d
Enables debugging output from the simulation runner. This is primarily useful for debugging the simulation runner itself.
-q
Quiet mode. Suppresses the printing of the simulation banner.
-n
No-init mode. Suppresses the initialization of memories and registers to unknown values. This is useful for simulating designs that do not explicitly initialize memory or registers.
-l
Loads VPI modules specified on the command line before any VPI modules specified in the simulation file. This can be used to override modules specified in the simulation file.
-V
Prints the version of the simulation runner and exits.
-?
Prints a help message and exits.
-v
Verbose mode. Prints more detailed information about the simulation process.

EXTENDED ARGUMENTS

Any arguments that follow the simulation file name are passed to the simulation as command-line arguments. These arguments are accessible within the simulation through the Verilog system task $test$plusargs and $plusargs.

ENVIRONMENT

The following environment variables affect the execution of vvp:

IVERILOG_LIB_DIRS
A colon-separated list of directories in which to search for loadable VPI modules. This is equivalent to using the -M option for each directory.
VVP_OPTIONS
A string containing command-line options to be passed to vvp. This is useful for setting default options that you always want to use.

INTERACTIVE MODE

The simulation runner supports an interactive mode. The user may interrupt the simulation (typically by typing <Control-C>) to get to the interactive prompt. From that prompt, the help command prints a brief summary of the available commands.

The interactive mode may also be entered by a call to the $stop system task from within the simulation, or by a call to the vpi_control VPI function with the vpiStop control argument. These means of entering interactive mode are equivalent.
