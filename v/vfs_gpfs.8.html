VFS_GPFS(8) Herramientas de Administración del Sistema VFS_GPFS(8)

NOMBRE

vfs_gpfs - extensiones específicas de samba para gpfs como acls

SINOPSIS

objetos vfs = gpfs

DESCRIPCIÓN

Este módulo VFS forma parte del conjunto samba(7).

El módulo VFS gpfs es el hogar de todas las extensiones gpfs que Samba requiere para una integración adecuada con GPFS. Utiliza las interfaces de la biblioteca GPL proporcionadas por GPFS.

Actualmente, el módulo vfs gpfs proporciona extensiones en las siguientes áreas:

•Interfaces ACL NFSv4 con opciones configurables para GPFS
•Soporte de oplocks del kernel en GPFS
•Soporte de leases en GPFS

NOTA: Este módulo sigue el comportamiento de las ACL posix y, por lo tanto, permite el robo de permisos a través de chown. Samba puede permitir en un momento posterior restringir el chown a través de este módulo, ya que tales restricciones son responsabilidad del sistema de archivos subyacente y no de Samba.

Este módulo utiliza el parámetro smb.conf acl map full control. Cuando se establece en sí (el valor predeterminado), este parámetro agregará el bit FILE_DELETE_CHILD a una entrada ACE devuelta para un archivo (no un directorio) que ya contiene todos los permisos de archivo, excepto FILE_DELETE y FILE_DELETE_CHILD. Esto puede evitar que las aplicaciones de Windows que solicitan acceso GENERIC_ALL obtengan errores ACCESS_DENIED al ejecutarse contra un sistema de archivos con ACL compatibles con NFSv4.

Este módulo es apilable.

Desde Samba 4.0, todas las opciones son opciones por recurso compartido.

OPCIONES

nfs4:mode = [ simple | special ]

Controla la sustitución de IDs especiales (OWNER@ y GROUP@) en las ACL NFS4. Se recomienda el uso del modo simple. En este modo, solo las ACL que no heredan para el propietario y el grupo del archivo se mapean a IDs especiales.

El módulo entiende los siguientes MODOS:

•simple (predeterminado) - usa IDs especiales OWNER@ y GROUP@ solo para ACEs que no heredan.
•special (obsoleto) - usa IDs especiales OWNER@ y GROUP@ en ACEs para todos los ACEs de propietario y grupo de archivos.

nfs4:acedup = [dontcare|reject|ignore|merge]

Este parámetro configura cómo Samba maneja los ACEs duplicados encontrados en las ACL NFS4. Permiten la creación de ACEs duplicados con bits diferentes para el mismo ID, lo que puede confundir a los clientes de Windows.

El siguiente es el comportamiento de Samba para los diferentes valores:

•dontcare - copia los ACEs tal como vienen
•reject (obsoleto) - detiene la operación y sale con un error en la operación de conjunto de ACL
•ignore (obsoleto) - no incluye el segundo ACE coincidente
•merge (predeterminado) - realiza un OR a nivel de bits de los 2 campos ace.flag y los 2 campos ace.mask de los 2 ACEs duplicados en 1 ACE

nfs4:chown = [yes|no]

Este parámetro permite habilitar o deshabilitar el chown soportado por el sistema de archivos subyacente. Este parámetro debe habilitarse con cuidado, ya que podría dejar su sistema inseguro.

Algunos sistemas de archivos permiten el chown como a) dar b) robar. Es este último el que se considera un riesgo.

El siguiente es el comportamiento de Samba para los diferentes valores:

•yes - Habilita chown si es soportado por el sistema de archivos subyacente
•no (predeterminado) - Deshabilita chown

gpfs:sharemodes = [ yes | no ]

Habilita/deshabilita el manejo de sharemodes entre nodos para GPFS.
•yes (predeterminado) - propaga los sharemodes a través de todos los nodos GPFS.
•no - no propaga los sharemodes a través de todos los nodos GPFS. Esto solo debe usarse si el sistema de archivos GPFS es exportado exclusivamente por Samba. El acceso por aplicaciones locales de unix o exportaciones NFS podría provocar archivos corruptos.

gpfs:leases = [ yes | no ]

Habilita/deshabilita leases (oplocks) entre nodos para GPFS. También debes establecer las opciones oplocks y kernel oplocks al mismo valor.
•yes (predeterminado) - propaga los leases a través de todos los nodos GPFS.
•no - no propaga los leases a través de todos los nodos GPFS. Esto solo debe usarse si el sistema de archivos GPFS es exportado exclusivamente por Samba. El acceso por aplicaciones locales de unix o exportaciones NFS podría provocar archivos corruptos.

gpfs:hsm = [ yes | no ]

Habilita/deshabilita el anuncio si este FS tiene HSM habilitado.
•no (predeterminado) - No anuncia HSM.
•yes - Anuncia HSM.

gpfs:recalls = [ yes | no ]

Cuando esta opción se establece en no, se rechazará el acceso a un intento de abrir un archivo sin conexión, con acceso denegado. Esto ayuda a prevenir tormentas de recuperación activadas por aplicaciones descuidadas como Finder y Explorer.
•yes (predeterminado) - Abre archivos que están sin conexión. Esto recuperará los archivos de HSM.
•no - Rechaza el acceso a archivos sin conexión con acceso denegado. Esto evitará la recuperación de archivos desde HSM. Usar esta configuración también requiere que gpfs:hsm esté establecido en yes.

gpfs:getrealfilename = [ yes | no ]

Habilita/deshabilita el uso de la función gpfs_get_realfilename_path(). Esto mejora el acceso a nombres de archivo con comodines sensibles a mayúsculas y minúsculas.
•yes (predeterminado) - usa gpfs_get_realfilename_path().
•no - no usa gpfs_get_realfilename_path(). Parece que gpfs_get_realfilename_path() no funciona en AIX.

gpfs:winattr = [ yes | no ]

Habilita/deshabilita el uso de atributos de Windows en GPFS. GPFS es capaz de almacenar atributos de archivos de Windows, por ejemplo, HIDDEN, READONLY, SYSTEM y otros de forma nativa. Eso significa que Samba no necesita mapearlos a bits de permisos o atributos extendidos.
•no (predeterminado) - no usa atributos de Windows de GPFS.
•yes - usa atributos de Windows de GPFS.

gpfs:acl = [ yes | no ]

Esta opción permite a Samba usar o ignorar las ACL de GPFS.
•yes (predeterminado) - usa ACL de GPFS.
•no - no usa ACL de GPFS y pasa todo al siguiente módulo SMB_VFS.

gpfs:check_fstype = [ yes | no ]

Comprueba si hay un sistema de archivos GPFS montado al acceder a un recurso compartido SMB.
•yes (predeterminado) - Comprueba que la ruta del recurso compartido SMB está en un sistema de archivos GPFS. Se denegará el acceso al recurso compartido cuando se encuentre un sistema de archivos diferente.
•no - omite la comprobación del sistema de archivos GPFS en la ruta del recurso compartido SMB.

gpfs:dfreequota = [ yes | no ]

Ajusta la notificación del tamaño y el espacio libre de un recurso compartido según las cuotas. Si esta configuración es "yes", una solicitud de tamaño y espacio libre también evaluará la cuota del usuario del usuario que solicita los datos y la cuota del grupo del grupo principal del usuario. Las cuotas de fileset no se consultan, ya que GPFS ya proporciona la opción --dfreequota para reflejar la cuota de fileset en la consulta de espacio libre. Utilice esa opción para incluir las cuotas de fileset en el espacio en disco notificado.

Si se ha alcanzado alguno de los límites de cuota blanda o dura, el espacio libre se notificará como 0. Si hay una cuota, pero no se han alcanzado los límites, el espacio libre se notificará según el espacio restante en la cuota. Si se aplica más de una cuota, el espacio libre se notificará como el espacio más pequeño restante en esas cuotas. El tamaño del recurso compartido se notificará según el uso de la cuota. Si se aplica más de una cuota, el tamaño más pequeño se notificará para el tamaño del recurso compartido según estas cuotas.

•yes - incluye las cuotas al notificar el tamaño y el espacio libre del recurso compartido
•no (predeterminado) - no incluye cuotas, simplemente notifica el tamaño y el espacio libre del sistema de archivos

gpfs:settimes = [ yes | no ]

Utiliza la API gpfs_set_times al cambiar las marcas de tiempo de un archivo o directorio. Si la API de GPFS no está disponible, se utilizará el método antiguo de usar utime y la llamada winattr de GPFS en su lugar.
•yes (predeterminado) - Usa gpfs_set_times. Retrocede a utime y winattr cuando no esté disponible.

•no - No utilice gpfs_set_times.

gpfs:clamp_invalid_times = [ yes | no ]

GPFS almacena marcas de tiempo utilizando enteros sin signo de 32 bits para el componente de segundos. Cuando se utiliza gpfs:settimes = yes, este módulo valida que las marcas de tiempo que los clientes intentan establecer estén dentro del rango soportado por GPFS entre 0 y UINT32_MAX. Si una marca de tiempo está fuera de este rango, la solicitud del cliente se rechaza. Para hacer frente a los clientes que establecen, por ejemplo, marcas de tiempo temporales fuera del rango válido, este parámetro se puede utilizar para ajustar la marca de tiempo del cliente al rango permitido. Las marcas de tiempo anteriores a Thu Jan 1 12:00:00 AM UTC 1970 (el epoch de UNIX) se establecerán en Thu Jan 1 12:00:00 AM UTC 1970, y las marcas de tiempo posteriores a Sun Feb 7 06:28:15 AM UTC 2106 se establecerán en Sun Feb 7 06:28:15 AM UTC 2106.
•no (por defecto) - Rechazar solicitud con tiempo no válido.
•yes - Ajustar tiempos no válidos a 0 o UINT32_MAX.

gpfs:syncio = [yes|no]

Este parámetro hace que Samba abra todos los archivos con O_SYNC. Esto activa optimizaciones en GPFS para cargas de trabajo que comparten archivos intensivamente.

A continuación se muestra el comportamiento de Samba para diferentes valores:

•yes - Abrir archivos con O_SYNC
•no (por defecto) - Abrir archivos como lo haría Samba normalmente

EJEMPLOS

Se puede exportar un montaje GPFS a través de Samba de la siguiente manera:

        [samba_gpfs_share]
	vfs objects = gpfs
	path = /test/gpfs_mount
	nfs4: mode = special
	nfs4: acedup = merge

CUIDADOS

Dependiendo de la versión de gpfs, la biblioteca libgpfs_gpl o la biblioteca libgpfs es necesaria en tiempo de ejecución por el módulo VFS de gpfs: A partir de gpfs 3.2.1 PTF8, la libgpfs completa está disponible como código abierto y libgpfs_gpl ya no existe. Con versiones anteriores de gpfs, solo la biblioteca libgpfs_gpl era de código abierto y podía utilizarse en tiempo de ejecución.

En tiempo de compilación, solo se requiere el archivo de cabecera gpfs_gpl.h, que es un enlace simbólico a gpfs.h en versiones de gpfs posteriores a 3.2.1 PTF8.
