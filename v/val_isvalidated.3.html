val_isvalidated(3)

Paquete: dnssec-tools

Licencias: BSD

libval(3) Manual del Programador libval(3)

NOMBRE

val_create_context() val_free_context() - gestionar el contexto del validador

val_context_setqflags() - gestionar las banderas del contexto del validador

val_resolve_and_check(), val_free_result_chain() - consultar y validar respuestas de un servidor de nombres DNS

val_istrusted() - comprobar si el valor de estado corresponde al de una respuesta de confianza

val_isvalidated() - comprobar si el valor de estado representa una respuesta que se encadena criptográficamente desde un ancla de confianza configurada

val_does_not_exist() - comprobar si el valor de estado representa uno de los tipos de no existencia

p_val_status(), p_ac_status(), p_val_error() - mostrar el estado de validación, el estado de la cadena de autenticación y la información de errores

val_log_add_optarg - controlar la verbosidad de los mensajes de registro y la ubicación de la salida

DESCRIPCIÓN

La función val_resolve_and_check() consulta un conjunto de servidores de nombres para la tupla <nombre_dominio, tipo, clase> y verifica y valida la respuesta. La verificación implica comprobar las RRSIGs, y la validación es la verificación de una cadena de autenticación desde un ancla de confianza configurada.

El parámetro flags se puede usar para controlar los resultados de la validación. Los siguientes valores, que pueden combinarse con OR, están definidos actualmente para este campo:

VAL_QUERY_DONT_VALIDATE
Esta bandera hace que el validador desactive la validación para esta consulta.
VAL_QUERY_IGNORE_SKEW
Esta bandera hace que el validador desactive la comprobación de los tiempos de inicio y expiración de las firmas en las RRSIGs.
VAL_QUERY_AC_DETAIL
Esta bandera hace que el validador copie los detalles de la cadena de autenticación en el miembro val_rc_answer dentro de la estructura val_result_chain devuelta.
VAL_QUERY_ASYNC
Esta bandera habilita la resolución de consulta asíncrona para esa búsqueda.
VAL_QUERY_NO_DLV
Esta bandera hace que el validador desactive el procesamiento de DLV para esta consulta. Esto solo está disponible si la biblioteca libval(3) ha sido compilada con soporte DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
Al consultar varios servidores de nombres, libsres(3) también intentará con varios tamaños de EDNS0, terminando con una consulta que tiene EDNS0 deshabilitado (es decir, sin el bit CD activado). Esta bandera hace que libval desactive la recuperación automática de EDNS0 para la consulta.
VAL_QUERY_ITERATE
Esta bandera fuerza a libval a realizar una búsqueda iterativa de la consulta consultando varios servidores de nombres en la jerarquía de delegación, en lugar de solicitar esta información a cualquier servidor de nombres en caché que pueda estar configurado en dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Esta bandera fuerza a libval a mirar solo su caché mientras intenta resolver un nombre.
VAL_QUERY_SKIP_CACHE
Hay dos niveles de caché dentro de libval: a nivel de afirmación y a nivel de respuesta. Esta bandera fuerza a libval a ignorar los datos en ambas cachés mientras intenta resolver un nombre.
VAL_QUERY_SKIP_ANS_CACHE
Hay dos niveles de caché dentro de libval: a nivel de afirmación y a nivel de respuesta. Esta bandera fuerza a libval a ignorar los datos en la caché de respuestas mientras intenta resolver un nombre. Si ya existe una afirmación para el nombre, clase y tipo dados, esa afirmación se reutiliza hasta que expira. Una vez que expira, el nombre se busca a través de una consulta incluso si un registro más nuevo (obtenido por otra afirmación en el mismo o diferente contexto) está disponible en su caché de respuestas.

El primer parámetro de val_resolve_and_check() es el contexto del validador. Las aplicaciones pueden crear un nuevo contexto de validador usando la función val_create_context(). Esta función analiza los archivos de configuración del resolvedor y del validador y crea el manejador newcontext para esta información analizada. La información almacenada como parte del contexto del validador incluye la política de validación y la política del resolvedor.

Las políticas del validador y del resolvedor se leen de los archivos /etc/dnsval.conf y /etc/resolv.conf por defecto. /etc/root.hints proporciona información de arranque para el validador cuando funciona como un resolvedor completo (ver dnsval.conf(3)). Estos valores predeterminados pueden ser diferentes si se especificó algún otro valor en el momento de la configuración de la biblioteca. Si no se encuentra el archivo de configuración del resolvedor por defecto en la ubicación especificada, libval también intentará recurrir a /etc/resolv.conf como último recurso.

Las aplicaciones también pueden crear un contexto de validador con una política personalizada usando la función val_create_context_ex().

El argumento opt en val_create_context_ex() apunta a la siguiente estructura:

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags especifica las banderas de consulta por defecto para las consultas asociadas con el contexto. Este campo es idéntico al argumento flags en la función val_resolve_and_check().

Los campos vc_val_conf, vc_res_conf y vc_root_conf se pueden usar para especificar archivos de configuración alternativos en lugar de los archivos por defecto utilizados para la información de configuración del validador, el resolvedor y las pistas raíz.

El campo vc_valpol se puede usar para proporcionar un "fragmento" de configuración personalizada del validador al validador. El validador analiza esta información y la aplica a la configuración del validador por defecto, ya sea como una extensión o como una anulación, según lo especificado por el campo vc_polflags. El campo vc_nslist, de manera similar, se puede usar para proporcionar una lista personalizada de servidores de nombres recursivos a los que enviar las consultas, además (o en lugar) de la lista de servidores de nombres especificada en el archivo resolv.conf. La lista de servidores de nombres en vc_res_conf debe especificarse como una lista de direcciones IP o IPv6 separadas por espacios en blanco.

Se puede crear una asignación personalizada entre una zona y un servidor de nombres utilizando la función val_context_store_ns_for_zone().

vc_polflags se puede configurar con los siguientes valores:

CTX_DYN_POL_VAL_OVR
Cuando esta bandera está activada, solo se utiliza la configuración del validador especificada en el campo vc_valpol para la configuración del validador. Las opciones especificadas en el archivo dnsval.conf se ignoran.
CTX_DYN_POL_RES_OVR
Cuando esta bandera está activada, solo se utiliza la configuración del resolvedor especificada en el campo vc_res_conf para la configuración del resolvedor. Las opciones especificadas en el archivo resolv.conf se ignoran.
CTX_DYN_POL_ROOT_OVR
Cuando esta bandera está activada, solo se utiliza la configuración de las pistas raíz especificada en el campo vc_root_conf para las pistas raíz. Las opciones especificadas en el archivo root.hints se ignoran.
CTX_DYN_POL_NSLIST_OVR
Cuando esta bandera está activada, solo se utiliza la lista de servidores de nombres recursivos especificada en el campo vc_nslist para resolver nombres. La lista de servidores de nombres en el archivo resolv.conf se ignora.
CTX_DYN_POL_VAL_EXT
Cuando esta bandera está activada, la configuración del validador especificada en el campo vc_valpol se aplica como una extensión a la configuración del validador por defecto leída del archivo dnsval.conf.
CTX_DYN_POL_RES_EXT
Cuando esta bandera está activada, la configuración del resolvedor especificada en el campo vc_res_conf se aplica como una extensión a la configuración del resolvedor por defecto leída del archivo resolv.conf.
CTX_DYN_POL_ROOT_EXT
Cuando esta bandera está activada, la configuración de las pistas raíz especificada en el campo vc_root_conf se aplica como una extensión a la configuración de las pistas raíz por defecto leída del archivo root.hints.
CTX_DYN_POL_NSLIST_EXT
Cuando esta bandera está activada, la lista de servidores de nombres recursivos especificada en el campo vc_nslist se añade a la lista de servidores de nombres por defecto leída del archivo resolv.conf.

El campo vc_polflags también admite la combinación de opciones de anulación y extensión. Si se especifica una opción de anulación (por ejemplo, CTX_DYN_POL_VAL_OVR) y una opción de extensión (por ejemplo, CTX_DYN_POL_VAL_EXT) para el mismo componente (por ejemplo, validador), la opción de anulación tiene prioridad y la opción de extensión se ignora.

El parámetro label en val_create_context() y val_create_context_ex() se utiliza para especificar un nombre para el contexto del validador. Este nombre se utiliza principalmente con fines de registro y depuración.

Una vez que se crea un contexto de validador, se puede utilizar en varias llamadas a la función val_resolve_and_check(). Cuando ya no se necesita el contexto del validador, debe liberarse llamando a la función val_free_context().

La función val_context_setqflags() permite modificar las banderas de consulta por defecto asociadas con un contexto de validador existente. El parámetro action puede ser VAL_QFLAGS_SET para establecer las banderas, VAL_QFLAGS_ADD para añadir banderas o VAL_QFLAGS_REMOVE para eliminar banderas.

Después de que val_resolve_and_check() haya completado su ejecución, devuelve un puntero a una estructura val_result_chain que contiene la información de la respuesta del servidor de nombres, así como la información de verificación y validación. Cuando ya no se necesita la cadena de resultados, debe liberarse llamando a la función val_free_result_chain().

Las funciones p_val_status(), p_ac_status() y p_val_error() son utilidades para convertir los valores de estado de validación, estado de cadena de autenticación y códigos de error en cadenas legibles por humanos.

Las funciones val_istrusted(), val_isvalidated() y val_does_not_exist() son predicados booleanos que devuelven verdadero (1) o falso (0) según el valor de estado de validación proporcionado.

La función val_log_add_optarg() se utiliza para controlar la cantidad de información de depuración que genera libval y dónde se escribe esa información. El argumento args es una cadena que contiene una lista de opciones separadas por comas, similar a las que se pasarían a la línea de comandos de una utilidad de línea de comandos. El argumento use_stderr especifica si la salida de registro debe enviarse a stderr.

EJEMPLOS

Para consultar y validar un registro A para ejemplo.com:

val_context_t *context;
struct val_result_chain *results;
int status;

status = val_create_context("mi_app", &context);
if (status != VAL_SUCCESS) {
    /* manejar error */
}

status = val_resolve_and_check(context, "ejemplo.com", QUERY_CLASS_IN,
                               QUERY_TYPE_A, 0, &results);

if (status == VAL_SUCCESS && results != NULL &&
    val_isvalidated(results->val_rc_status)) {
    /* La respuesta es válida y proviene de una fuente de confianza */
    /* Procesar los resultados */
} else {
    /* Manejar el error o una respuesta no válida */
    fprintf(stderr, "Error/Estado: %s\n", p_val_status(results->val_rc_status));
}

val_free_result_chain(results);
val_free_context(context);

VER TAMBIÉN

dnsval.conf(5)

FALLOS

Si se utilizan las opciones VAL_QUERY_ASYNC o VAL_QUERY_ITERATE, es posible que la función devuelva más de una vez.

En Linux, la llamada a val_create_context() requiere que el archivo /etc/resolv.conf contenga al menos un servidor de nombres válido. Si no es así, la llamada fallará y devolverá VAL_FAILURE.

FLAGS

The flags parameter is a bitmask that can be used to override the default behavior of the validator. The following flags are available:

CTX_DYN_POL_RES_OVR
Cuando esta bandera está activada, solo los servidores de nombres especificados en el campo vc_nslist se utilizan para la configuración del resolvedor. Las opciones especificadas en el archivo resolv.conf se ignoran.
CTX_DYN_POL_GLO_OVR
Cuando esta bandera está activada, solo se utilizan las opciones globales establecidas en el campo gopt. Las opciones globales especificadas en el archivo dnsval.conf se ignoran.
CTX_DYN_POL_RES_NRD
Cuando esta bandera está activada, las consultas salientes tienen el bit de Deseo de Recursión (RD) establecido en 0. Esto es útil si las consultas deben enviarse a un servidor de nombres solo autoritativo.

El campo gopt apunta a la siguiente estructura:

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

Establecer un valor de 1 para local_is_trusted es equivalente a especificar la opción trust-oob-answers en el archivo dnsval.conf a yes. De manera similar, establecer los miembros closest_ta_only y rec_fallback a 1 es equivalente a establecer las opciones closest-ta-only y rec-fallback a yes en el archivo dnsval.conf. Un valor de 0 es equivalente a la configuración no para estas opciones.

Establecer el miembro edns0_size a un valor particular tiene el mismo efecto que establecer la opción edns0-size en el archivo dnsval.conf.

Establecer el miembro max_refresh a un valor particular tiene el mismo efecto que establecer la opción max-refresh en el archivo dnsval.conf.

Establecer el miembro proto a un valor particular tiene el mismo efecto que establecer la opción proto en el archivo dnsval.conf.

env_policy y app_policy pueden establecerse en uno de VAL_POL_GOPT_DISABLE, VAL_POL_GOPT_ENABLE o VAL_POL_GOPT_OVERRIDE. Estos valores corresponden directamente a las opciones disable, enable y override para la configuración de env-policy y app-policy en el archivo dnsval.conf.

Los valores de -1 para los campos anteriores se tratan como condiciones de "ignorar", en el sentido de que el validador no incluirá opciones globales suministradas dinámicamente con un valor de -1 al crear su contexto. Esto permite a una aplicación anular un subconjunto de opciones globales mientras utiliza las opciones globales suministradas en el archivo dnsval.conf por defecto.

El campo log_target permite a la aplicación suministrar objetivos de registro *además* de los configurados en el archivo de configuración.

Consulte dnsval.conf(3) para obtener más detalles sobre cómo especificar la política del validador.

Las banderas de consulta predeterminadas se pueden establecer y desactivar para un contexto dado utilizando val_context_setqflags(). Esto permite a una aplicación alterar el procesamiento del validador DNSSEC, mientras todavía tiene la mayor parte de la configuración predeterminada más granular especificada en su archivo de configuración. El parámetro action puede establecerse en una de las siguientes opciones.

VAL_CTX_FLAG_SET
Esta opción hace que el validador establezca la bandera dada como una de las banderas de consulta predeterminadas.
VAL_CTX_FLAG_RESET
Esta opción hace que el validador restablezca la bandera dada si se estableció como una de las banderas de consulta predeterminadas para el contexto.

Las respuestas devueltas por val_resolve_and_check() están disponibles en la lista enlazada *results. Cada respuesta corresponde a un RRset distinto; múltiples RRs dentro del RRset forman parte de la misma respuesta. Son posibles múltiples respuestas cuando type es ns_t_any o ns_t_rrsig.

Los elementos individuales en *results apuntan a listas enlazadas val_authentication_chain. Los elementos de la cadena de autenticación en val_authentication_chain contienen los RRsets reales devueltos por el servidor de nombres en respuesta a la consulta.

Los valores de resultado de validación devueltos en val_result_chain pueden convertirse a formato ASCII utilizando p_val_status(). Los valores de estado de la cadena de autenticación devueltos en cada elemento de la lista enlazada val_authentication_chain pueden convertirse a formato ASCII utilizando las funciones p_ac_status().

Si bien algunas aplicaciones, como las utilidades de solución de problemas de DNSSEC y las herramientas de inspección de paquetes, pueden examinar elementos individuales de la cadena de autenticación para identificar las razones reales del error de validación, la mayoría de las aplicaciones solo estarán interesadas en un único código de error para determinar la autenticidad de los datos.

val_isvalidated() identifica si un valor de estado de resultado de validación dado corresponde a una respuesta que fue verificada criptográficamente y validada utilizando un ancla de confianza configurada localmente.

val_istrusted() identifica si un valor de estado del validador dado es de confianza. Una respuesta puede ser de confianza localmente sin ser validada.

val_does_not_exist() identifica si un valor de estado del validador dado corresponde a uno de los tipos de no existencia.

La biblioteca libval asigna memoria internamente para *results y esta debe ser liberada por la aplicación invocadora utilizando la interfaz free_result_chain().

ESTRUCTURAS DE DATOS

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
Cadena de autenticación para un RRset dado.
val_rc_next
Puntero al siguiente RRset en el conjunto de respuestas devueltas para una consulta.
val_rc_proofs
Puntero a las cadenas de autenticación para cualquier prueba de no existencia que se haya devuelto para la consulta.
val_rc_proof_count
Número de elementos de prueba almacenados en val_rc_proofs. El número no puede exceder MAX_PROOFS.
val_rc_alias
Para un elemento val_result_chain que apunta a un alias de nombre, este campo contiene el valor de destino.
val_rc_rrset
Para un elemento val_result_chain que contiene un campo val_rc_answer válido (no NULL), el campo val_rc_rrset apunta al elemento val_rrset_rec de nivel superior en la cadena de autenticación val_rc_answer.
val_rc_status
Estado de validación para un RRset dado. Puede ser uno de los siguientes:
VAL_SUCCESS
Respuesta recibida y validada con éxito.
VAL_NONEXISTENT_NAME
No se encontró ningún nombre y se devolvió una prueba válida de no existencia que confirma el nombre faltante (intervalo NSEC o NSEC3). Los componentes de la prueba también se validaron individualmente.
VAL_NONEXISTENT_TYPE
No existe ningún tipo para el nombre y se devolvió una prueba válida de no existencia que confirma el nombre faltante. Los componentes de la prueba también se validaron individualmente.
VAL_NONEXISTENT_NAME_NOCHAIN
No se encontró ningún nombre y se devolvió una prueba válida de no existencia que confirma el nombre faltante. Los componentes de la prueba también se identificaron como confiables, pero no se validaron individualmente.
VAL_NONEXISTENT_TYPE_NOCHAIN
No existe ningún tipo para el nombre y se devolvió una prueba válida de no existencia que confirma el nombre faltante (intervalo NSEC o NSEC3). Los componentes de la prueba también se identificaron como confiables, pero no se validaron individualmente.
VAL_PINSECURE
Se sabía que el registro o algún ancestro del registro en la cadena de autenticación hacia el ancla de confianza era demostrablemente inseguro.
VAL_PINSECURE_UNTRUSTED
Se sabía que el registro o algún ancestro del registro en la cadena de autenticación hacia el ancla de confianza era demostrablemente inseguro. Pero la condición demostrablemente insegura se configuró como no confiable.
VAL_BARE_RRSIG
No es posible la validación DNSSEC, la consulta era para un RRSIG.
VAL_IGNORE_VALIDATION
La política local se configuró para ignorar la validación de la zona de la que se recibieron estos datos.
VAL_UNTRUSTED_ZONE
La política local se configuró para rechazar cualquier dato recibido de la zona dada.
VAL_OOB_ANSWER
La respuesta se obtuvo utilizando algún método fuera de banda (Out Of Band), como un archivo de configuración local.
VAL_BOGUS
La respuesta no pudo ser validada debido a fallos en la verificación de firmas o la incapacidad de verificar pruebas en la cadena de autenticación.
VAL_DNS_ERROR
Se encontró algún error durante el procesamiento de DNS.
VAL_INDETERMINATE
La respuesta no pudo ser validada debido a metadatos DNSSEC faltantes.

VAL_STATUS_T

The validation status for a given query is returned in the val_status_t structure. The values returned in this structure indicate the validation status of the authenticated chain.

VAL_UNSET
The status could not be determined.
VAL_INSECURE
The name was not validated, but no DS records were found for the name or any of its ancestors. This means that the name can be considered secure in the absence of a DS record. This is the default status for any name not explicitly validated.
VAL_BOGUS
The name was validated, but the validation failed. This could be due to an unverifiable signature, a mismatch in keys, or some other error during the validation process.
VAL_NEVER_VALIDATED
The name was never validated. This can occur if the validation process was interrupted or could not be completed for some reason.
VAL_USER_SECURE
The name was validated and is considered secure. This status is set by the user, indicating that the name is trusted based on user policy or configuration.
VAL_DNSSEC_SECURE
The name was validated using DNSSEC and is considered secure. This means that all signatures along the authentication chain are valid and verifiable.
VAL_INDETERMINATE
The validation status is indeterminate. This can happen when there is insufficient information to determine the security status of the name, or if there are conflicting security policies.
VAL_NOTRUST
Todos los componentes disponibles en la cadena de autenticación se verificaron correctamente, pero no había ninguna ancla de confianza disponible.

Los valores de estado en val_status_t devueltos por el validador pueden mostrarse en formato ASCII usando p_val_status().

struct val_authentication_chain
struct val_authentication_chain
{
    val_astatus_t                    val_ac_status;
    struct val_rrset_rec                *val_ac_rrset;
    struct val_authentication_chain *val_ac_trust;
};
val_ac_status
Estado de validación del elemento de la cadena de autenticación. Este campo contendrá el código de estado para el componente dado en la cadena de autenticación. Este campo puede contener uno de los siguientes valores:
VAL_AC_UNSET
No se pudo determinar el estado.
VAL_AC_IGNORE_VALIDATION
La validación para el registro de recursos dado se ignoró, ya sea debido a alguna directiva de política local o debido a algún comportamiento específico del protocolo.
VAL_AC_UNTRUSTED_ZONE
La política local definió una zona dada como no confiable, sin que se considerara necesaria ninguna validación adicional.
VAL_AC_PINSECURE
No se pudo construir la cadena de autenticación desde un ancla de confianza hasta una zona dada debido a la ausencia demostrable de un registro DS para esta zona en el padre.
VAL_AC_BARE_RRSIG
La respuesta fue para una consulta de tipo RRSIG. Los RRSIG contienen las firmas criptográficas para otros datos DNS y no pueden ser validados por sí mismos.
VAL_AC_NO_LINK
No había ninguna ancla de confianza configurada para una cadena de autenticación dada o la cadena no se conectó.
VAL_AC_TRUST
Al menos una de las firmas que cubren el conjunto de registros DNSKEY dado se verificó directamente usando una clave configurada como ancla de confianza DNSSEC.
VAL_AC_RRSIG_MISSING
No se pudieron recuperar los datos RRSIG para un registro de recursos.
VAL_AC_DNSKEY_MISSING
No se pudo recuperar el DNSKEY de un RRSIG que cubre un registro de recursos.
VAL_AC_DS_MISSING
No estuvo disponible el registro DS que cubre un registro DNSKEY.
VAL_AC_DATA_MISSING

LOGGING

libval proporciona la función val_log_add_optarg() para controlar la verbosidad y la ubicación de la salida de los mensajes de registro.

La función val_log_add_optarg() toma dos argumentos: el primer argumento args es un valor de cadena de caracteres que especifica la ubicación y la verbosidad. El segundo argumento, use_stderr, si se establece en un valor mayor que 0, permite que libval envíe mensajes de registro a stderr.

La cadena de caracteres que especifica la ubicación y la verbosidad del destino del registro tiene un formato específico:

<debug-level>:<dest-type>[:<dest-options>]

donde
<debug-level> es 1-7, para niveles crecientes de verbosidad
<dest-type> es uno de file, net, syslog, stderr, stdout
<dest-options> depende de <dest-type>
file:<file-name> (abierto en modo de adjuntar)
net[:<host-name>:<host-port>] (127.0.0.1:1053)
syslog[:facility] (0-23 (predeterminado 1 USER))

Los niveles de registro se pueden traducir aproximadamente a diferentes tipos de mensajes de registro de la siguiente manera (los mensajes devueltos para cada nivel en esta lista subsumen los mensajes devueltos para el nivel superior):

3 : Error   : error encontrado
4 : Warning : recuperándose de un error
5 : Notice  : da los resultados de validación finales para una consulta
              y detalles sobre archivos de políticas y etiquetas utilizadas
6 : Info
: describe las cadenas de autenticación 7 : Debug : proporciona información del nivel de depuración
