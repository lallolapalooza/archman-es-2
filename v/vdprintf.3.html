DESCRIPCIÓN

Las funciones de la familia printf() producen salida según un formato como se describe a continuación. Las funciones printf() y vprintf() escriben la salida en stdout, el flujo de salida estándar; fprintf() y vfprintf() escriben la salida en el flujo de salida dado; sprintf(), snprintf(), vsprintf() y vsnprintf() escriben en la cadena de caracteres str.

La función dprintf() es igual que fprintf() excepto que genera salida a un descriptor de archivo, fd, en lugar de a un flujo de stdio(3).

Las funciones snprintf() y vsnprintf() escriben como máximo size bytes (incluyendo el byte nulo de terminación ('\0')) en str.

Las funciones vprintf(), vfprintf(), vdprintf(), vsprintf(), vsnprintf() son equivalentes a las funciones printf(), fprintf(), dprintf(), sprintf(), snprintf(), respectivamente, excepto que se llaman con una va_list en lugar de un número variable de argumentos. Estas funciones no invocan la macro va_end. Como invocan la macro va_arg, el valor de ap no está definido después de la llamada. Ver stdarg(3).

Todas estas funciones escriben la salida bajo el control de una cadena de formato que especifica cómo los argumentos subsiguientes (o los argumentos accedidos a través de las facilidades de argumentos de longitud variable de stdarg(3)) se convierten para su salida.

C99 y POSIX.1-2001 especifican que los resultados no están definidos si una llamada a sprintf(), snprintf(), vsprintf() o vsnprintf() causara la copia entre objetos que se solapan (por ejemplo, si el array de cadenas de destino y uno de los argumentos de entrada suministrados se refieren al mismo buffer). Ver PRECAUCIONES.

Formato de la cadena de formato

La cadena de formato es una cadena de caracteres, que comienza y termina en su estado de desplazamiento inicial, si lo hubiera. La cadena de formato se compone de cero o más directivas: caracteres ordinarios (no %), que se copian sin cambios al flujo de salida; y especificaciones de conversión, cada una de las cuales resulta en la obtención de cero o más argumentos subsiguientes. Cada especificación de conversión se introduce con el carácter % y termina con un especificador de conversión. Entremedias puede haber (en este orden) cero o más flags, una anchura de campo mínima opcional, una precisión opcional y un modificador de longitud opcional.

La sintaxis general de una especificación de conversión es:


%[argumento$][flags][ancho][.precisión][modificador de longitud]conversión

Los argumentos deben corresponder adecuadamente (después de la promoción de tipo) con el especificador de conversión. Por defecto, los argumentos se usan en el orden dado, donde cada '*' (ver Anchura de campo y Precisión abajo) y cada especificador de conversión piden el siguiente argumento (y es un error si se dan insuficientes argumentos). También se puede especificar explícitamente qué argumento se toma, en cada lugar donde se requiere un argumento, escribiendo "%m$" en lugar de '%' y "*m$" en lugar de '*', donde el entero decimal m denota la posición en la lista de argumentos del argumento deseado, indexado comenzando desde 1. Por lo tanto,


printf("%*d", ancho, num);

y


printf("%2$*1$d", ancho, num);

son equivalentes. El segundo estilo permite referencias repetidas al mismo argumento. El estándar C99 no incluye el estilo que usa '$', que proviene de la Single UNIX Specification. Si se usa el estilo que usa '$', debe usarse en todo momento para todas las conversiones que toman un argumento y todos los argumentos de anchura y precisión, pero puede mezclarse con formatos "%%", que no consumen un argumento. No puede haber huecos en los números de argumentos especificados usando '$'; por ejemplo, si los argumentos 1 y 3 se especifican, el argumento 2 también debe especificarse en algún lugar de la cadena de formato.

Para algunas conversiones numéricas se utiliza un carácter de punto decimal ("radix") o un carácter de agrupación de miles. El carácter real utilizado depende de la parte LC_NUMERIC de la localidad. (Ver setlocale(3).) La localidad POSIX usa '.' como carácter de punto decimal, y no tiene un carácter de agrupación. Por lo tanto,


printf("%'.2f", 1234567.89);

resulta en "1234567.89" en la localidad POSIX, en "1234567,89" en la localidad nl_NL, y en "1.234.567,89" en la localidad da_DK.

Caracteres flag

El carácter % va seguido de cero o más de los siguientes flags:

#
El valor debe convertirse a una forma "alternativa". Para las conversiones o, el primer carácter de la cadena de salida se hace cero (prefijando un 0 si no era cero ya). Para las conversiones x y X, un resultado distinto de cero tiene las cadenas "0x" (o "0X" para conversiones X) antepuestas. Para las conversiones a, A, e, E, f, F, g y G, el resultado siempre contendrá un punto decimal, incluso si no le siguen dígitos (normalmente, un punto decimal aparece en los resultados de esas conversiones solo si le sigue un dígito). Para las conversiones g y G, los ceros finales no se eliminan del resultado como se haría de otra manera. Para m, si errno contiene un código de error válido, se imprime la salida de strerrorname_np(errno); de lo contrario, se imprime el valor almacenado en errno como un número decimal. Para otras conversiones, el resultado no está definido.
0
El valor debe rellenarse con ceros. Para las conversiones d, i, o, u, x, X, a, A, e, E, f, F, g y G, el valor convertido se rellena por la izquierda con ceros en lugar de espacios. Si los flags 0 y - aparecen ambos, el flag 0 se ignora. Si se proporciona una precisión con una conversión entera (d, i, o, u, x y X), el flag 0 se ignora. Para otras conversiones, el comportamiento no está definido.
-
El valor convertido debe ajustarse a la izquierda en el límite del campo. (El valor por defecto es la justificación a la derecha). El valor convertido va

Para la conversión de enteros decimales (i, d, u) la salida utiliza los dígitos de salida alternativos de la configuración regional, si los hay. Por ejemplo, desde glibc 2.2.3 esto producirá dígitos arábigo-indios en la configuración regional persa ("fa_IR").

Ancho de campo

Una cadena opcional de dígitos decimales (con primer dígito distinto de cero) que especifica un ancho de campo mínimo. Si el valor convertido tiene menos caracteres que el ancho del campo, se rellenará con espacios a la izquierda (o a la derecha, si se ha especificado la bandera de ajuste a la izquierda). En lugar de una cadena de dígitos decimales se puede escribir "*" o "*m$" (para algún entero decimal m) para especificar que el ancho del campo se proporciona en el siguiente argumento, o en el m-ésimo argumento, respectivamente, que debe ser de tipo int. Un ancho de campo negativo se toma como una bandera '-' seguida de un ancho de campo positivo. En ningún caso un ancho de campo inexistente o pequeño causará truncamiento de un campo; si el resultado de una conversión es más ancho que el ancho del campo, el campo se expandirá para contener el resultado de la conversión.

Precisión

Una precisión opcional, en forma de un punto ('.') seguido de una cadena opcional de dígitos decimales. En lugar de una cadena de dígitos decimales se puede escribir "*" o "*m$" (para algún entero decimal m) para especificar que la precisión se proporciona en el siguiente argumento, o en el m-ésimo argumento, respectivamente, que debe ser de tipo int. Si la precisión se proporciona solo como '.', la precisión se toma como cero. Una precisión negativa se toma como si la precisión se omitiera. Esto da el número mínimo de dígitos que deben aparecer para las conversiones d, i, o, u, x y X, el número de dígitos que deben aparecer después del carácter de punto de separación decimal para las conversiones a, A, e, E, f y F, el número máximo de dígitos significativos para las conversiones g y G, o el número máximo de caracteres que se imprimirán de una cadena para las conversiones s y S.

Modificador de longitud

Aquí, "conversión de enteros" se refiere a la conversión d, i, o, u, x o X.

hh
Una conversión de enteros subsiguiente corresponde a un argumento de signed char o unsigned char, o una conversión n subsiguiente corresponde a un puntero a un argumento de signed char.
h
Una conversión de enteros subsiguiente corresponde a un argumento de short o unsigned short, o una conversión n subsiguiente corresponde a un puntero a un argumento de short.
l
(ele) Una conversión de enteros subsiguiente corresponde a un argumento de long o unsigned long, o una conversión n subsiguiente corresponde a un puntero a un argumento de long, o una conversión c subsiguiente corresponde a un argumento wint_t, o una conversión s subsiguiente corresponde a un puntero a un argumento wchar_t. En una conversión a, A, e, E, f, F, g o G subsiguiente, este modificador de longitud se ignora (C99; no en SUSv2).
ll
(ele-ele). Una conversión de enteros subsiguiente corresponde a un argumento de long long o unsigned long long, o una conversión n subsiguiente corresponde a un puntero a un argumento de long long.
q
Un sinónimo de ll. Esta es una extensión no estándar, derivada de BSD; evite su uso en código nuevo.
L
Una conversión a, A, e, E, f, F, g o G subsiguiente corresponde a un argumento long double. (C99 permite %LF, pero SUSv2 no).
j
Una conversión de enteros subsiguiente corresponde a un argumento intmax_t o uintmax_t, o una conversión n subsiguiente corresponde a un puntero a un argumento intmax_t.
z
Una conversión de enteros subsiguiente corresponde a un argumento size_t o ssize_t, o una conversión n subsiguiente corresponde a un puntero a un argumento size_t.
Z
Un sinónimo no estándar de z que precede a la aparición de z. No usar en código nuevo.
t
Una conversión de enteros subsiguiente corresponde a un argumento ptrdiff_t, o una conversión n subsiguiente corresponde a un puntero a un argumento ptrdiff_t.

SUSv3 especifica todos los anteriores, excepto aquellos modificadores que se notan explícitamente como extensiones no estándar. SUSv2 especificó solo los modificadores de longitud h (en hd, hi, ho, hx, hX, hn) y l (en ld, li, lo, lx, lX, ln, lc, ls) y L (en Le, LE, Lf, Lg, LG).

Como extensión no estándar, las implementaciones de GNU tratan ll y L como sinónimos, de modo que se puede, por ejemplo, escribir llg (como sinónimo de Lg compatible con el estándar) y Ld (como sinónimo de lld compatible con el estándar). Dicho uso no es portable.

Especificadores de conversión

Un carácter que especifica el tipo de conversión que se aplicará. Los especificadores de conversión y sus significados son:

d, i
El argumento int se convierte a notación decimal con signo. La precisión, si la hay, indica el número mínimo de dígitos que deben aparecer; si el valor convertido requiere menos dígitos, se rellena a la izquierda con ceros. La precisión predeterminada es 1. Cuando se imprime 0 con una precisión explícita de 0, la salida está vacía.
o, u, x, X
El argumento unsigned int se convierte a notación octal sin signo (o), decimal sin signo (u) o hexadecimal sin signo (x y X). Las letras abcdef se usan para las conversiones x; las letras ABCDEF se usan para las conversiones X. La precisión, si la hay, indica el número mínimo de dígitos que deben aparecer; si el valor convertido requiere menos dígitos, se rellena a la izquierda con ceros. La precisión predeterminada es 1. Cuando se imprime 0 con una precisión explícita de 0, la salida está vacía.
e, E
El argumento double se redondea y se convierte en el estilo [-]d.ddde±dd donde hay un dígito (que es distinto de cero si el argumento es distinto de cero) antes del carácter del punto de separación decimal y el número de dígitos después de él es igual a la precisión; si la precisión falta, se toma como 6; si la precisión es cero, no aparece ningún carácter de punto de separación decimal. Una conversión E usa la letra E (en lugar de e) para introducir el exponente. El exponente siempre contiene al menos dos dígitos; si el valor es cero, el exponente es 00.
f, F
El argumento double se redondea y se convierte a notación decimal en el estilo [-]ddd.ddd, donde el número de dígitos después del carácter del punto de separación decimal es igual a la especificación de precisión. Si la precisión falta, se toma como 6; si la precisión es explícitamente cero, no aparece ningún carácter de punto de separación decimal. Si aparece un punto de separación decimal, al menos un dígito aparece antes de él.
(SUSv2 no conoce F y dice que se pueden poner a disposición representaciones en cadena de caracteres para infinito y NaN. SUSv3 añade una especificación para F. El estándar C99 especifica "[-]inf" o "[-]infinity" para infinito, y una cadena que comienza con "nan" para NaN, en el caso de la conversión f, y "[-]INF" o "[-]INFINITY" o "NAN" en el caso de la conversión F.)
g, G
El argumento double se convierte en el estilo f o e (o F o E para las conversiones G). La precisión especifica el número de dígitos significativos. Si la precisión falta, se dan 6 dígitos; si la precisión es cero, se trata como 1. Se usa el estilo e si el exponente de su conversión es menor que -4 o mayor o igual a la precisión. Los ceros finales se eliminan de la parte fraccionaria del resultado; un punto de separación decimal aparece solo si está seguido por al menos un dígito.

DESCRIPTION

These functions implement the standard C library functions for printing formatted output. The function dprintf(3) is an extension that writes to a file descriptor.

The format string is a character string, beginning with any combination of characters, except for a percent sign ('%'), which may be followed by an octet sequence and then by any combination of **flags**, **field width**, and **precision** and **length modifiers** that specify the type of subsequent unconverted characters and how they should be converted for output. When a conversion is done, the appropriate argument is converted. The result is written to the stream, or assigned to the string, or written to the file descriptor.

A conversion specification is introduced by the character '%' and ends with one of the following conversion characters:

d, i
The int argument is converted to signed decimal notation. i is equivalent to d. If the precision is 0 and the argument is 0, then no characters are written.
o, u, x, X
The unsigned int argument is converted to unsigned octal (o), unsigned decimal (u), or unsigned hexadecimal (x, X) notation. If the precision is 0 and the argument is 0, then no characters are written.

The letters abcdef are used for x conversions, and the letters ABCDEF are used for X conversions.

e, E
A floating-point argument except long double under the IEEE 754 standard, is converted to decimal notation in the style "[-]d.ddde±dd", where there is one digit before the decimal-point character and exactly precision digits after the decimal-point character (which is the radix character in the current locale). Behavior with respect to a radix point character is undefined in this locale. Except when the precision is 0, a decimal-point character appears in the output. The exponent always contains at least two digits; if the value is zero, the exponent is 0.
f, F
A floating-point argument except long double under the IEEE 754 standard, is converted to decimal notation in the style "[-]d.ddd", where there is exactly one digit before the radix point character and the number of digits after it is equal to the precision. Precision is the number of digits to appear after the radix point (which is the radix character in the current locale). In this, and without needing a decimal character in the output, the values are zero. If precision is 0, then no radix character appears. Behavior with respect to the radix point character is undefined in this locale.
g, G
A floating-point argument except long double under the IEEE 754 standard, is converted in the style of %e (%E for %G) or %f. The precision is the number of significant digits (from and including the first digit of the number). The style is that of %e if the exponent is less than 4, and that of %f otherwise. Trailing zeros are removed from the fractional part of the result. A radix point character appears in the output if and only if it is followed by an actual digit.
a, A
A floating-point argument is the hexadecimal representation of the floating-point value. For a, lowercase letters are used for the hexadecimal digits and the exponent separator is 'p'. For A, uppercase letters are used for the hexadecimal digits and the exponent separator is 'P'. There is one hexadecimal digit before the radix point. The number of digits after it is equal to the precision. The default precision is sufficient to represent the value exactly in base 2. The exponent, d, is the appropriate exponent of 2. It always contains at least one digit. If the value is zero, the exponent is 0.
E, e, G, g, f, F, a, A
A double argument is converted to double. A long double argument is converted to long double. A long double argument is converted as if it were a double if the implementation does not natively support long double wider than double.
LeE, Le, LG, Lg, Lf, LF, La, LA
A long double argument is converted to long double. (This is the default behavior if no length modifier is used for floating-point types).
LEe, LE, LG, Lg, Lf, LF, La, LA
A long double argument is converted to long double.
hd, hi, ho, hx, hX, hu
An int argument is converted to int.
hd, hi, ho, hx, hX, hu
A short int argument is converted to short int.
d, i
The long int argument is converted to long int.
o, u, x, X
The long int argument is converted to unsigned long int.
d, i
The long long int argument is converted to long long int.
o, u, x, X
The long long int argument is converted to unsigned long long int.
d, i
The intmax_t argument is converted to intmax_t.
o, u, x, X
The uintmax_t argument is converted to uintmax_t.
d, i
The ptrdiff_t argument is converted to ptrdiff_t.
o, u, x, X
The ptrdiff_t argument is converted to ptrdiff_t.
LeE, Le, Lg, LG, La, LA
The long double argument is converted to long double.
a
A floating-point argument is converted to hexadecimal notation (..., 16d, ...). For a, lowercase letters are used for the hexadecimal digits and the exponent separator is 'p'. There is one hexadecimal digit before the radix point. The number of digits after the radix point is equal to the precision. The default precision suffices for an exact representation of the value if an exact representation in base 2 exists and otherwise is sufficiently large to distinguish values of type double. The digit before the radix point is unspecified for nonnormalized numbers, and nonzero but otherwise unspecified for normalized numbers. The exponent, d, is the appropriate exponent of 2 expressed as a decimal integer; it always contains at least one digit; if the value is zero, the exponent is 0.
c
If no l modifier is present, the int argument is converted to an unsigned char, and the resulting character is written. If an l modifier is present, the wint_t (wide character) argument is converted to a multibyte sequence by a call to the wcrtomb(3) function, with a conversion state starting in the initial state, and the resulting multibyte string is written.
s
If no l modifier is present: the const char * argument is expected to be a pointer to an array of character type (pointer to a string). Characters from the array are written up to (but not including) a terminating null byte ('\0'); if a precision is specified, no more than the number specified are written. If a precision is given, no null byte need be present; if the precision is not specified, or is greater than the size of the array, the array must contain a terminating null byte.
If an l modifier is present: the const wchar_t * argument is expected to be a pointer to an array of wide characters. Wide characters from the array are converted to multibyte characters (each by a call to the wcrtomb(3) function, with a conversion state starting in the initial state before the first wide character), up to and including a terminating null wide character. The resulting multibyte characters are written up to (but not including) the terminating null byte. If a precision is specified, no more bytes than the number specified are written, but no partial multibyte characters are written. Note that the precision determines the number of bytes written, not the number of wide characters or screen positions. The array must contain a terminating null wide character, unless a precision is given and it is so small that the number of bytes written exceeds it before the end of the array is reached.
C
(Not in C99 or C11, but in SUSv2, SUSv3, and SUSv4.) Synonym for lc. Don't use.
S
(Not in C99 or C11, but in SUSv2, SUSv3, and SUSv4.) Synonym for ls. Don't use.
p
The void * pointer argument is printed in hexadecimal (as if by %#x or %#lx).
n
The number of characters written so far is stored into the integer pointed to by the corresponding argument. That argument shall be an int *, or variant whose size matches the (optionally) supplied integer length modifier. No argument is converted. (This specifier is not supported by the bionic C library.) The behavior is undefined if the conversion specification includes any flags, a field width, or a precision.
m
(glibc extension; supported by uClibc and musl, and on Android from API level 29.) Print output of strerror(errno) (or strerrorname_np(errno) in the alternate form). No argument is required.
%
A '%' is written. No argument is converted. The complete conversion specification is '%%'.

RETURN VALUE

Upon successful return, these functions return the number of bytes printed (excluding the null byte used to end output to strings).

The functions snprintf() and vsnprintf() do not write more than size bytes (including the terminating null byte ('\0')). If the output was truncated due to this limit, then the return value is the number of characters (excluding the terminating null byte) which would have been written to the final string if enough space had been available. Thus, a return value of size or more means that the output was truncated. (See also below under CAVEATS.)

On error, a negative value is returned, and errno is set to indicate the error.

ERRORS

See write(2) and putwc(3). In addition, the following error may occur:

EOVERFLOW
The value to be returned is greater than INT_MAX.

The dprintf() function may fail additionally if:

EBADF
The fd argument is not a valid file descriptor.

glibc 2.1 adds length modifiers hh, j, t, and z and conversion characters a and A.

glibc 2.2 adds the conversion character F with C99 semantics, and the flag character I.

glibc 2.35 gives a meaning to the alternate form (#) of the m conversion specifier, that is %#m.

CAVEATS

Some programs imprudently rely on code such as the following


sprintf(buf, "%s some further text", buf);

to append text to buf. However, the standards explicitly note that the results are undefined if source and destination buffers overlap when calling sprintf(), snprintf(), vsprintf(), and vsnprintf(). Depending on the version of gcc(1) used, and the compiler options employed, calls such as the above will not produce the expected results.

The glibc implementation of the functions snprintf() and vsnprintf() conforms to the C99 standard, that is, behaves as described above, since glibc 2.1. Until glibc 2.0.6, they would return -1 when the output was truncated.

BUGS

Because sprintf() and vsprintf() assume an arbitrarily long string, callers must be careful not to overflow the actual space; this is often impossible to assure. Note that the length of the strings produced is locale-dependent and difficult to predict. Use snprintf() and vsnprintf() instead (or asprintf(3) and vasprintf(3)).

Code such as printf(foo); often indicates a bug, since foo may contain a % character. If foo comes from untrusted user input, it may contain %n, causing the printf() call to write to memory and creating a security hole.

EXAMPLE

See printf(3).

EJEMPLOS

Para imprimir Pi con cinco decimales:


#include <math.h>
#include <stdio.h>
fprintf(stdout, "pi = %.5f\n", 4 * atan(1.0));

Para imprimir una fecha y hora en el formato "Domingo, Julio 3, 10:02", donde weekday y month son punteros a cadenas:


#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        weekday, month, day, hour, min);

Muchos países utilizan el orden día-mes-año. Por lo tanto, una versión internacionalizada debe poder imprimir los argumentos en un orden especificado por el formato:


#include <stdio.h>
fprintf(stdout, format,
        weekday, month, day, hour, min);

donde format depende de la configuración regional y puede permutar los argumentos. Con el valor:


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

se podría obtener "Sonntag, 3. Juli, 10:02".

Para asignar una cadena suficientemente grande e imprimir en ella (código correcto tanto para glibc 2.0 como para glibc 2.1):

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Determinar el tamaño requerido.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un byte extra para '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si se produce truncamiento en versiones de glibc anteriores a glibc 2.0.6, esto se trata como un error en lugar de manejarse correctamente.
