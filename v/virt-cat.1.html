virt-cat(1) Virtualization Support virt-cat(1)

NOMBRE

virt-cat - Muestra archivos en una máquina virtual

SINOPSIS

virt-cat [--options] -d nombre_dom host [host ...]
virt-cat [--options] -a disco.img [-a disco.img ...] host [host ...]

Estilo antiguo:

virt-cat nombre_dom host
virt-cat disco.img host

DESCRIPCIÓN

"virt-cat" es una herramienta de línea de comandos para mostrar el contenido de "host" donde "host" existe en la máquina virtual (o imagen de disco) nombrada.

Se pueden dar varios nombres de archivo, en cuyo caso se concatenan. Cada nombre de archivo debe ser una ruta completa, comenzando desde el directorio raíz (comenzando con '/').

"virt-cat" se puede usar para ver rápidamente un archivo. Para editar un archivo, usa "virt-edit". Para casos más complejos, deberías consultar la herramienta guestfish(1) (ver "USANDO GUESTFISH" abajo).

EJEMPLOS

Muestra el archivo /etc/fstab dentro de la VM de libvirt llamada "midominio":

virt-cat -d midominio /etc/fstab

Averigua qué paquetes se instalaron recientemente:

virt-cat -d midominio /var/log/yum.log | tail

Averigua quién está conectado dentro de una máquina virtual:

virt-cat -d midominio /var/run/utmp > /tmp/utmp
who /tmp/utmp

o quién estaba conectado:

virt-cat -d midominio /var/log/wtmp > /tmp/wtmp
last -f /tmp/wtmp

OPCIONES

--help
Muestra ayuda breve.
-a archivo
--add archivo
Añade archivo que debe ser una imagen de disco de una máquina virtual. Si la máquina virtual tiene varios dispositivos de bloque, debes proporcionar todos ellos con opciones -a separadas.

El formato de la imagen de disco se detecta automáticamente. Para anular esto y forzar un formato particular, usa la opción --format=...

-a URI
--add URI
Añade un disco remoto. Ver "AÑADIENDO ALMACENAMIENTO REMOTO" en guestfish(1).
--blocksize=512
--blocksize=4096
--blocksize
Este parámetro establece el tamaño del sector de la imagen de disco. Afecta a todos los discos añadidos explícitamente después de este parámetro. Usar --blocksize sin argumento cambia el tamaño del sector del disco al valor predeterminado, que suele ser de 512 bytes. Ver también "guestfs_add_drive_opts" en guestfs(3).
-c URI
--connect URI
Si usas libvirt, conéctate a la URI dada. Si se omite, nos conectamos al hipervisor libvirt predeterminado.

Si especificas los dispositivos de bloque del invitado directamente (-a), entonces libvirt no se usa en absoluto.

-d invitado
--domain invitado
Añade todos los discos del invitado libvirt con nombre. Los UUIDs de dominio pueden usarse en lugar de nombres.
--echo-keys
Al solicitar claves y contraseñas, virt-cat normalmente desactiva el eco para que no veas lo que escribes. Si no te preocupan los ataques Tempest y no hay nadie más en la habitación, puedes especificar esta bandera para ver lo que escribes.
--format=raw|qcow2|..
--format
El valor predeterminado para la opción -a es detectar automáticamente el formato de la imagen de disco. Usar esto fuerza el formato del disco para las opciones -a que siguen en la línea de comandos. Usar --format sin argumento revierte a la detección automática para las opciones -a subsiguientes.

Por ejemplo:

virt-cat --format=raw -a disco.img host

fuerza el formato raw (sin detección automática) para disco.img.

virt-cat --format=raw -a disco.img --format -a otro.img host

fuerza el formato raw (sin detección automática) para disco.img y revierte a la detección automática para otro.img.

Si tienes imágenes de disco de invitados en formato raw no confiables, deberías usar esta opción para especificar el formato del disco. Esto evita un posible problema de seguridad con invitados maliciosos (CVE-2010-3851).

--key SELECCIONADOR
Especifica una clave para LUKS, para abrir automáticamente un dispositivo LUKS al usar la inspección.
--key NOMBRE:clave:CADENA_CLAVE
--key UUID:clave:CADENA_CLAVE
--key todo:clave:CADENA_CLAVE
"NOMBRE" es el nombre del dispositivo libguestfs (ej. "/dev/sda1"). "UUID" es el UUID del dispositivo. "todo" significa intentar la clave contra cualquier dispositivo cifrado.

Usa la "CADENA_CLAVE" especificada como contraseña.

--key NOMBRE:archivo:NOMBRE_ARCHIVO
--key UUID:archivo:NOMBRE_ARCHIVO
--key todo:archivo:NOMBRE_ARCHIVO
Lee la contraseña desde NOMBRE_ARCHIVO.
--key NOMBRE:clevis
--key UUID:clevis
--key todo:clevis
Intenta el desbloqueo sin contraseña para el dispositivo con Clevis, a través de la red. Por favor, consulta "DISCOS CIFRADOS" en guestfs(3) para más información sobre el cifrado de disco enlazado a la red (NBDE).

Ten en cuenta que si alguna de estas opciones está presente en la línea de comandos, la red de usuario de QEMU se habilitará automáticamente para el appliance libguestfs.

--keys-from-stdin
Lee parámetros de clave o contraseña desde stdin. El valor predeterminado es intentar leer contraseñas del usuario abriendo /dev/tty.

Si hay varios dispositivos cifrados, es posible que necesites proporcionar varias claves en stdin, una por línea.

-m dev[:punto_montaje[:opciones[:tipo_fs]]]
--mount dev[:punto_montaje[:opciones[:tipo_fs]]]
Monta la partición o volumen lógico nombrado en el punto de montaje dado.

Si se omite el punto de montaje, el valor predeterminado es /.

Especificar cualquier punto de montaje deshabilita la inspección del invitado y el montaje de su raíz y todos sus puntos de montaje, así que asegúrate de montar todos los puntos de montaje necesarios para trabajar con los nombres de archivo dados como argumentos.

Si no sabes qué sistemas de archivos contiene una imagen de disco, puedes ejecutar guestfish sin esta opción, luego listar las particiones, sistemas de archivos y LVs disponibles (ver comandos "list-partitions", "list-filesystems" y "lvs"), o puedes usar el programa virt-filesystems(1).

OPTIONS

-a, --attach-disk disk, -d, --attach-disk-image disk
Attach a disk image. You can use this option multiple times to attach multiple disk images. The disks are available as entries in /dev/ inside the guest. This option is only available if the guest is not running (eg. a disk image file, not a running VM). If you specify this option, then virt-cat will not try to connect to a libvirt guest at all. This is the most flexible way to use virt-cat.
-h, --help
Display help message and exit.
-i, --inspect
Use guest inspection to find guest operating system, kernel and root filesystem. This is the default. This option requires that the guest is running and that libguestfs can inspect it (see guestfs-inspect(1)).
-m, --mount-options mountinfo
Specify mount options for filesystems. The mountinfo parameter is a comma-separated list of filesystem specifications. Each specification has the form: device=device,mountpoint=mountpoint,mountoptions=options. If the mountoptions part is omitted, it defaults to the options used by the system automatically (e.g. ro for read-only access if the --ro flag is used). By specifying the mount options, you override this default choice. Probably the only time you would use this is to enable ACLs and/or extended attributes if the filesystem can support them:
-m /dev/sda1:/:acl,user_xattr
Using this flag is equivalent to using the "mount-options" command.
The fourth part of the parameter is the filesystem driver to use, such as "ext3" or "ntfs". This is rarely needed, but can be useful if multiple drivers are valid for a filesystem (eg: "ext2" and "ext3"), or if libguestfs misidentifies a filesystem.
-v, --verbose
Enable verbose messages for debugging.
-V, --version
Display version number and exit.
-x
Enable tracing of libguestfs API calls.

OLD-STYLE COMMAND LINE ARGUMENTS

Previous versions of virt-cat allowed you to write either:

virt-cat disk.img [disk.img ...] file

or

virt-cat guestname file

whereas in this version you should use -a or -d respectively to avoid the confusing case where a disk image might have the same name as a guest.

For compatibility the old style is still supported.

LOG FILES

To list out the log files from guests, see the related tool virt-log(1). It understands binary log formats such as the systemd journal.

To follow (tail) text log files, use virt-tail(1).

WINDOWS PATHS

"virt-cat" has a limited ability to understand Windows drive letters and paths (eg. E:\foo\bar.txt).

If and only if the guest is running Windows then:

  • Drive letter prefixes like "C:" are resolved against the Windows Registry to the correct filesystem.
  • Any backslash ("\") characters in the path are replaced with forward slashes so that libguestfs can process it.
  • The path is resolved case insensitively to locate the file that should be displayed.

There are some known shortcomings:

  • Some NTFS symbolic links may not be followed correctly.
  • NTFS junction points that cross filesystems are not followed.

USING GUESTFISH

guestfish(1) is a more powerful, lower level tool which you can use when "virt-cat" doesn't work.

Using "virt-cat" is approximately equivalent to doing:

guestfish --ro -i -d domname download file -

where "domname" is the name of the libvirt guest, and "file" is the full path to the file. Note the final "-" (meaning "output to stdout").

The command above uses libguestfs’s guest inspection feature and so does not work on guests that libguestfs cannot inspect, or on things like arbitrary disk images that don't contain guests. To display a file from a disk image directly, use:

guestfish --ro -a disk.img -m /dev/sda1 download file -

where disk.img is the disk image, /dev/sda1 is the filesystem within the disk image, and "file" is the full path to the file.

EXIT STATUS

This program returns 0 if successful, or non-zero if there was an error.
