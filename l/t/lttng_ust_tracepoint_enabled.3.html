DESCRIPCIÓN

El Linux Trace Toolkit: next generation es un paquete de software de código abierto utilizado para el trazado correlacionado del kernel de Linux, aplicaciones de usuario y bibliotecas de usuario.

LTTng-UST es el componente de trazado del espacio de usuario del proyecto LTTng. Es una portabilidad al espacio de usuario de las capacidades de trazado de baja sobrecarga del trazador del kernel de Linux LTTng. La biblioteca liblttng-ust se utiliza para trazar aplicaciones y bibliotecas de usuario.


Nota

Esta página del manual trata sobre la biblioteca liblttng-ust. El proyecto LTTng-UST también proporciona paquetes Java y Python para trazar aplicaciones escritas en esos lenguajes. Cómo instrumentar y trazar aplicaciones Java y Python se documenta en la documentación en línea de LTTng http://lttng.org/docs/.

Hay tres formas de usar liblttng-ust:

•Usando la API de lttng_ust_tracef(3), que es similar a printf(3).
•Usando la API de lttng_ust_tracelog(3), que es lttng_ust_tracef(3) con un parámetro de nivel de registro.
•Definiendo tus propios puntos de trazado. Vea la sección Creación de un proveedor de puntos de trazado más abajo.

Compatibilidad con APIs anteriores

Desde LTTng-UST 2.13, la definición LTTNG_UST_COMPAT_API_VERSION controla qué APIs de LTTng-UST están disponibles (compiladas):

Indefinido

Todas las APIs están disponibles.

N (0 o entero positivo)

La versión de API N, y todas las APIs existentes siguientes, están disponibles. Las APIs anteriores no están disponibles (no compiladas).

NAME

lttng-ust-tracepoints - LTTng User Space tracepoint definition

DESCRIPTION

This document describes how to define and use LTTng-UST tracepoints in your C/C++ applications.

Tracepoints are defined by tracepoint providers. A tracepoint provider is a set of tracepoint definitions that your application will support, either statically or dynamically.

A tracepoint provider is a compiled object containing the event probes corresponding to your custom tracepoint definitions. A tracepoint provider contains the code to get the size of an event and to serialize it, amongst other things.

To create a tracepoint provider, start with the following tracepoint provider header template:

#undef LTTNG_UST_TRACEPOINT_PROVIDER
#define LTTNG_UST_TRACEPOINT_PROVIDER my_provider
#undef LTTNG_UST_TRACEPOINT_INCLUDE
#define LTTNG_UST_TRACEPOINT_INCLUDE "./tp.h"
#if !defined(_TP_H) || \
    defined(LTTNG_UST_TRACEPOINT_HEADER_MULTI_READ)
#define _TP_H
#include <lttng/tracepoint.h>
/*
 * LTTNG_UST_TRACEPOINT_EVENT(), LTTNG_UST_TRACEPOINT_EVENT_CLASS(),
 * LTTNG_UST_TRACEPOINT_EVENT_INSTANCE(),
 * LTTNG_UST_TRACEPOINT_LOGLEVEL(), and `LTTNG_UST_TRACEPOINT_ENUM()`
 * are used here.
 */
#endif /* _TP_H */
#include <lttng/tracepoint-event.h>

In this template, the tracepoint provider is named my_provider (LTTNG_UST_TRACEPOINT_PROVIDER definition). The file needs to bear the name of the LTTNG_UST_TRACEPOINT_INCLUDE definition (tp.h in this case). Between #include <lttng/tracepoint.h> and #endif go the invocations of the LTTNG_UST_TRACEPOINT_EVENT(), LTTNG_UST_TRACEPOINT_EVENT_CLASS(), LTTNG_UST_TRACEPOINT_EVENT_INSTANCE(), LTTNG_UST_TRACEPOINT_LOGLEVEL(), and LTTNG_UST_TRACEPOINT_ENUM() macros.


Note

You can avoid writing the prologue and epilogue boilerplate in the template file above by using the lttng-gen-tp(1) tool shipped with LTTng-UST.

The tracepoint provider header file needs to be included in a source file which looks like this:

#define LTTNG_UST_TRACEPOINT_CREATE_PROBES
#include "tp.h"

Together, those two files (let’s call them tp.h and tp.c) form the tracepoint provider sources, ready to be compiled.

You can create multiple tracepoint providers to be used in a single application, but each one must have its own header file.

The LTTNG_UST_TRACEPOINT_EVENT() usage section below shows how to use the LTTNG_UST_TRACEPOINT_EVENT() macro to define the actual tracepoints in the tracepoint provider header file.

See the EXAMPLE section below for a complete example.

LTTNG_UST_TRACEPOINT_EVENT() usage

The LTTNG_UST_TRACEPOINT_EVENT() macro is used in a template provider header file (see the Creating a tracepoint provider section above) to define LTTng-UST tracepoints.

The LTTNG_UST_TRACEPOINT_EVENT() usage template is as follows:

LTTNG_UST_TRACEPOINT_EVENT(
    /* Tracepoint provider name */
    my_provider,
    /* Tracepoint/event name */
    my_tracepoint,
    /* List of tracepoint arguments (input) */
    LTTNG_UST_TP_ARGS(
        ...
    ),
    /* List of fields of eventual event (output) */
    LTTNG_UST_TP_FIELDS(
        ...
    )
)

The LTTNG_UST_TP_ARGS() macro contains the input arguments of the tracepoint. Those arguments can be used in the argument expressions of the output fields defined in LTTNG_UST_TP_FIELDS().

The format of the LTTNG_UST_TP_ARGS() parameters is: C type, then argument name; repeat as needed, up to ten times. For example:

LTTNG_UST_TP_ARGS(
    int, my_int,
    const char *, my_string,
    FILE *, my_file,
    double, my_float,
    struct my_data *, my_data
)

The LTTNG_UST_TP_FIELDS() macro contains the output fields of the tracepoint, that is, the actual data that can be recorded in the payload of an event emitted by this tracepoint.

The LTTNG_UST_TP_FIELDS() macro contains a list of lttng_ust_field_*() macros NOT separated by commas. The available macros are documented in the Available lttng_ust_field_*() field type macros section below.

Available field macros

This section documents the available lttng_ust_field_*() macros that can be inserted in the LTTNG_UST_TP_FIELDS() macro of the LTTNG_UST_TRACEPOINT_EVENT() macro.

Standard integer, displayed in base 10:

lttng_ust_field_integer(int_type, field_name, expr)
lttng_ust_field_integer_nowrite(int_type, field_name, expr)

Standard integer, displayed in base 16:

lttng_ust_field_integer_hex(int_type, field_name, expr)

Integer in network byte order (big endian), displayed in base 10:

lttng_ust_field_integer_network(int_type, field_name, expr)

Integer in network byte order, displayed in base 16:

lttng_ust_field_integer_network_hex(int_type, field_name, expr)

Floating point number:

lttng_ust_field_float(float_type, field_name, expr)
lttng_ust_field_float_nowrite(float_type, field_name, expr)

Null-terminated string:

lttng_ust_field_string(field_name, expr)
lttng_ust_field_string_nowrite(field_name, expr)

Statically-sized array of integers (_hex versions displayed in hexadecimal, _network versions in network byte order):

lttng_ust_field_array(int_type, field_name, expr, count)
lttng_ust_field_array_nowrite(int_type, field_name, expr, count)
lttng_ust_field_array_hex(int_type, field_name, expr, count)
lttng_ust_field_array_nowrite_hex(int_type, field_name, expr, count)
lttng_ust_field_array_network(int_type, field_name, expr, count)
lttng_ust_field_array_network_nowrite(int_type, field_name, expr,

lttng_ust_field_array_network_hex(int_type, field_name, expr, count)
lttng_ust_field_array_network_nowrite_hex(int_type, field_name,

Statically-sized array, printed as text; no need to be null-terminated:

lttng_ust_field_array_text(char, field_name, expr, count)
lttng_ust_field_array_text_nowrite(char, field_name, expr, count)

Dynamically-sized array of integers (_hex versions displayed in hexadecimal, _network versions in network byte order):

lttng_ust_field_sequence(int_type, field_name, expr, len_type,
                         len_expr)
lttng_ust_field_sequence_nowrite(int_type, field_name, expr,
                                 len_type, len_expr)
lttng_ust_field_sequence_hex(int_type, field_name, expr, len_type,
                             len_expr)
lttng_ust_field_sequence_nowrite_hex(int_type, field_name, expr,
                                     len_type, len_expr)
lttng_ust_field_sequence_network(int_type, field_name, expr,
                                 len_type, len_expr)
lttng_ust_field_sequence_network_nowrite(int_type, field_name, expr,
                                         len_type, len_expr)
lttng_ust_field_sequence_network_hex(int_type, field_name, expr,
                                     len_type, len_expr)
lttng_ust_field_sequence_network_nowrite_hex(int_type, field_name,
                                             expr, len_type,
                                             len_expr)

Dynamically-sized array, displayed as text; no need to be null-terminated:

lttng_ust_field_sequence_text(char, field_name, expr, len_type,
                              len_expr)
lttng_ust_field_sequence_text_nowrite(char, field_name, expr,
                                      len_type, len_expr)

Enumeration. The enumeration field must be defined before using this macro with the LTTNG_UST_TRACEPOINT_ENUM() macro. See the LTTNG_UST_TRACEPOINT_ENUM() usage section for more information.

lttng_ust_field_enum(prov_name, enum_name, int_type, field_name,
                     expr)
lttng_ust_field_enum_nowrite(prov_name, enum_name, int_type,
                             field_name, expr)

The parameters are:

count

Number of elements in array/sequence. This must be known at compile time.

enum_name

Name of an enumeration field previously defined with the LTTNG_UST_TRACEPOINT_ENUM() macro. See the LTTNG_UST_TRACEPOINT_ENUM() usage section for more information.

expr

C expression resulting in the field value. This expression can use one or more arguments passed to the tracepoint. The arguments of a given tracepoint are defined in the LTTNG_UST_TP_ARGS() macro (see the Creating a tracepoint provider section above).

field_name

Event field name (C identifier syntax, NOT a literal string).

float_type

Float C type (float or double). The size of this type determines the size of the floating point number field.

int_type

Integer C type. The size of this type determines the size of the integer/enumeration field.

len_expr

C expression resulting in the sequence length. This expression can use one or more arguments passed to the tracepoint.

len_type

Unsigned integer C type of sequence length.

prov_name

Tracepoint provider name. This must be the same as the tracepoint provider name used in a previous field definition.

The _nowrite versions omit themselves from the recorded event's payload. This is useful for tracepoints that are only meant to increment a counter or to provide a synchronization point in the trace.

The tracepoint provider header file can also define enumerations for event fields using the LTTNG_UST_TRACEPOINT_ENUM() macro.

LTTNG_UST_TRACEPOINT_ENUM(
    /* Tracepoint provider name */
    my_provider,
    /* Enumeration name */
    my_enum,
    /* Base integer type */
    int,
    /* List of enumeration values */
    LTTNG_UST_TP_ENUM_VALUES(
        my_enum_value_1,
        my_enum_value_2,
        ...
    )
)

This macro defines an enumeration named my_enum, associated with the provider my_provider. The enumeration values are defined using the LTTNG_UST_TP_ENUM_VALUES() macro. All values in the enumeration are assigned integers starting from 0 and incrementing by 1.

For example, the following definition:

LTTNG_UST_TRACEPOINT_ENUM(
    my_provider,
    my_enum,
    uint32_t,
    LTTNG_UST_TP_ENUM_VALUES(
        MY_ENUM_VALUE_A,
        MY_ENUM_VALUE_B,
        MY_ENUM_VALUE_C
    )
)

results in the following C structure being defined:

enum my_provider_my_enum {
    MY_ENUM_VALUE_A = 0,
    MY_ENUM_VALUE_B = 1,
    MY_ENUM_VALUE_C = 2
};

The tracepoint provider header file can also define log level tracepoints using the LTTNG_UST_TRACEPOINT_LOGLEVEL() macro.

LTTNG_UST_TRACEPOINT_LOGLEVEL(
    /* Tracepoint provider name */
    my_provider,
    /* Tracepoint/event name */
    my_logpoint,
    /* Log level name */
    my_log_level,
    /* List of tracepoint arguments (input) */
    LTTNG_UST_TP_ARGS(
        ...
    ),
    /* List of fields of eventual event (output) */
    LTTNG_UST_TP_FIELDS(
        ...
    )
)

The LTTNG_UST_TRACEPOINT_LOGLEVEL() macro is identical to the LTTNG_UST_TRACEPOINT_EVENT() macro, except that it adds a my_log_level string descriptor to the event. This descriptor is used to map the event to a specific log level (e.g., TRACE_DEBUG, TRACE_INFO, TRACE_WARNING, TRACE_ERROR, TRACE_FATAL).

The tracepoint provider header file can also define event class tracepoints using the LTTNG_UST_TRACEPOINT_EVENT_CLASS() macro.

LTTNG_UST_TRACEPOINT_EVENT_CLASS(
    /* Tracepoint provider name */
    my_provider,
    /* Event class name */
    my_event_class,
    /* List of event class fields */
    LTTNG_UST_TP_FIELDS(
        ...
    )
)

This macro defines an event class named my_event_class, associated with the provider my_provider. The event class defines a set of fields that can be reused by multiple tracepoints.

Tracepoints can then reference this event class using the LTTNG_UST_TRACEPOINT_EVENT_INSTANCE() macro.

LTTNG_UST_TRACEPOINT_EVENT_INSTANCE(
    /* Tracepoint provider name */
    my_provider,
    /* Event class name */
    my_event_class,
    /* Tracepoint/event name */
    my_event_instance,
    /* List of tracepoint arguments (input) */
    LTTNG_UST_TP_ARGS(
        ...
    ),
    /* List of fields of eventual event (output) */
    LTTNG_UST_TP_FIELDS(
        ...
    )
)

The LTTNG_UST_TRACEPOINT_EVENT_INSTANCE() macro is similar to LTTNG_UST_TRACEPOINT_EVENT(), but it references an event class defined previously with LTTNG_UST_TRACEPOINT_EVENT_CLASS().

EXAMPLE

This example demonstrates how to define and use a simple tracepoint provider.

First, create the tracepoint provider header file (tp.h):

#undef LTTNG_UST_TRACEPOINT_PROVIDER
#define LTTNG_UST_TRACEPOINT_PROVIDER my_provider
#undef LTTNG_UST_TRACEPOINT_INCLUDE
#define LTTNG_UST_TRACEPOINT_INCLUDE "./tp.h"
#if !defined(_TP_H) || \
    defined(LTTNG_UST_TRACEPOINT_HEADER_MULTI_READ)
#define _TP_H
#include <lttng/tracepoint.h>
LTTNG_UST_TRACEPOINT_ENUM(
    my_provider,
    my_enum,
    uint32_t,
    LTTNG_UST_TP_ENUM_VALUES(
        MY_ENUM_VALUE_A,
        MY_ENUM_VALUE_B,
        MY_ENUM_VALUE_C
    )
)
LTTNG_UST_TRACEPOINT_EVENT(
    my_provider,
    my_tracepoint,
    LTTNG_UST_TP_ARGS(
        int, level,
        const char *, msg
    ),
    LTTNG_UST_TP_FIELDS(
        lttng_ust_field_integer(int, level, level),
        lttng_ust_field_string(msg, msg),
        lttng_ust_field_enum(my_provider, my_enum, uint32_t, enum_val, level)
    )
)
#endif /* _TP_H */
#include <lttng/tracepoint-event.h>

Next, create the tracepoint provider source file (tp.c):

#define LTTNG_UST_TRACEPOINT_CREATE_PROBES
#include "tp.h"

Finally, use the tracepoint in your application:

#include "tp.h"
#include <stdio.h>
int main(int argc, char **argv)
{
    int level = 1;
    const char *msg = "Hello LTTng";
    /*
     * Emit the tracepoint event.
     * This will write the event in the trace stream if the tracepoint is
     * enabled.
     */
    my_provider_my_tracepoint(level, msg);
    return 0;
}

Uso de LTTNG_UST_TRACEPOINT_ENUM()

Un campo de enumeración es una lista de mapeos entre enteros, o un rango de enteros, y cadenas de texto (a veces llamadas etiquetas o enumeradores). Los campos de enumeración pueden usarse para tener un trazo más compacto cuando los valores posibles para un campo son limitados.

Un campo de enumeración se define con la macro LTTNG_UST_TRACEPOINT_ENUM():

LTTNG_UST_TRACEPOINT_ENUM(
    /* Nombre del proveedor de puntos de traza */
    mi_proveedor,
    /* Nombre de la enumeración (único en todo el proveedor de puntos de traza) */
    mi_enum,
    /* Mapeos de enumeración */
    LTTNG_UST_TP_ENUM_VALUES(
        ...
    )
)

LTTNG_UST_TP_ENUM_VALUES() contiene una lista de mapeos de enumeración, NO separados por comas. Se pueden usar dos macros en LTTNG_UST_TP_ENUM_VALUES(): lttng_ust_field_enum_value() y lttng_ust_field_enum_range().

lttng_ust_field_enum_value() es un mapeo de valor único:

lttng_ust_field_enum_value(etiqueta, valor)

Esta macro mapea la cadena de etiqueta dada al valor especificado.

lttng_ust_field_enum_range() es un mapeo de rango:

lttng_ust_field_enum_range(etiqueta, inicio, fin)

Esta macro mapea la cadena de etiqueta dada al rango de enteros desde inicio hasta fin, inclusivamente. Los mapeos de rango pueden solaparse, pero el comportamiento está definido por la implementación: cada lector de trazas maneja los rangos solapados como considere oportuno.

Consulta la sección EJEMPLO a continuación para ver un ejemplo completo.

Uso de LTTNG_UST_TRACEPOINT_EVENT_CLASS()

Una clase de punto de traza es una clase de puntos de traza que comparten los mismos tipos y nombres de campo. Una instancia de punto de traza es una instancia de dicha clase de punto de traza declarada, con su propio nombre de evento.

LTTng-UST crea una función de serialización de eventos por clase de punto de traza. Usar LTTNG_UST_TRACEPOINT_EVENT() crea una clase de punto de traza por definición de punto de traza, mientras que usar LTTNG_UST_TRACEPOINT_EVENT_CLASS() y LTTNG_UST_TRACEPOINT_EVENT_INSTANCE() crea una clase de punto de traza y una o más instancias de punto de traza de esta clase. En otras palabras, muchos puntos de traza pueden reutilizar el mismo código de serialización. Reutilizar el mismo código, cuando sea posible, puede reducir la contaminación de la caché, mejorando así el rendimiento.

La macro LTTNG_UST_TRACEPOINT_EVENT_CLASS() acepta los mismos parámetros que la macro LTTNG_UST_TRACEPOINT_EVENT(), excepto que en lugar de un nombre de evento, su segundo parámetro es el nombre de la clase de punto de traza:

#define LTTNG_UST_TRACEPOINT_PROVIDER mi_proveedor
/* ... */
LTTNG_UST_TRACEPOINT_EVENT_CLASS(
    /* Nombre del proveedor de la clase de punto de traza */
    mi_proveedor,
    /* Nombre de la clase de punto de traza */
    mi_clase_punto_traza,
    /* Lista de argumentos del punto de traza (entrada) */
    LTTNG_UST_TP_ARGS(
        ...
    ),
    /* Lista de campos del evento eventual (salida) */
    LTTNG_UST_TP_FIELDS(
        ...
    )
)

Una vez definida la clase de punto de traza, puedes crear tantas instancias de punto de traza como necesites:

#define LTTNG_UST_TRACEPOINT_PROVIDER natality
/* ... */
LTTNG_UST_TRACEPOINT_EVENT_INSTANCE(
    /* Nombre del proveedor de la clase de punto de traza */
    mi_proveedor,
    /* Nombre de la clase de punto de traza */
    mi_clase_punto_traza,
    /* Nombre del proveedor local (de instancia) */
    natality,
    /* Nombre del punto de traza/evento */
    mi_punto_traza,
    /* Lista de argumentos del punto de traza (entrada) */
    LTTNG_UST_TP_ARGS(
        ...
    )
)

Como puedes ver, LTTNG_UST_TRACEPOINT_EVENT_INSTANCE() no contiene la macro LTTNG_UST_TP_FIELDS(), ya que se definen a nivel de LTTNG_UST_TRACEPOINT_EVENT_CLASS().

Ten en cuenta que la macro LTTNG_UST_TRACEPOINT_EVENT_INSTANCE() requiere dos nombres de proveedor:

•El nombre del proveedor de la clase de punto de traza (mi_proveedor en el ejemplo anterior).

Este es el mismo que el primer argumento de la expansión de LTTNG_UST_TRACEPOINT_EVENT_CLASS() al que se hace referencia.

•El nombre del proveedor local, o de instancia (natality en el ejemplo anterior).

Este es el nombre del proveedor que se convierte en la parte prefijo del nombre de los eventos que crea dicho punto de traza.

Los dos nombres de proveedor pueden ser diferentes si la clase de punto de traza y las macros de instancia de punto de traza están en dos unidades de traducción distintas.

Instrumentando tu aplicación

Una vez que se ha creado el proveedor de puntos de traza (consulta la sección Creación de un proveedor de puntos de traza), puedes instrumentar tu aplicación con los puntos de traza definidos gracias a la macro lttng_ust_tracepoint():

#define lttng_ust_tracepoint(nombre_prov, nombre_t, ...)

Con:

nombre_prov

Nombre del proveedor de puntos de traza.

nombre_t

Nombre del punto de traza/evento.

...

Argumentos del punto de traza, si los hay.

Asegúrate de incluir el archivo de cabecera del proveedor de puntos de traza en cualquier lugar donde uses lttng_ust_tracepoint() para este proveedor.


Nota

Aunque LTTng-UST admite duplicados en el sitio de llamada de lttng_ust_tracepoint() con los mismos nombres de proveedor y punto de traza, se recomienda usar un par proveedor/punto de traza solo una vez dentro del código fuente de la aplicación para ayudar a mapear los eventos a sus sitios de llamada al analizar la traza.

A veces, los argumentos del punto de traza son costosos de calcular (por ejemplo, tomar la pila de llamadas). Para evitar el cálculo cuando el punto de traza está deshabilitado, puedes usar las macros lttng_ust_tracepoint_enabled() y lttng_ust_do_tracepoint():

#define lttng_ust_tracepoint_enabled(nombre_prov, nombre_t)
#define lttng_ust_do_tracepoint(nombre_prov, nombre_t, ...)

lttng_ust_tracepoint_enabled() devuelve un valor distinto de cero si el punto de traza llamado nombre_t del proveedor llamado nombre_prov está habilitado en tiempo de ejecución.

lttng_ust_do_tracepoint() es como lttng_ust_tracepoint(), excepto que no comprueba si el punto de traza está habilitado. Usar lttng_ust_tracepoint() con lttng_ust_tracepoint_enabled() es peligroso, ya que lttng_ust_tracepoint() también contiene la comprobación de lttng_ust_tracepoint_enabled(), por lo que es posible una condición de carrera en esta situación:

if (lttng_ust_tracepoint_enabled(mi_proveedor, mi_punto_traza)) {
    cosas = preparar_cosas();
}
lttng_ust_tracepoint(mi_proveedor, mi_punto_traza, cosas);

Si el punto de traza se habilita después de la condición, entonces cosas no se preparan: el evento emitido contendrá datos incorrectos o la aplicación completa podría fallar (por ejemplo, error de segmentación).


Nota

Ni lttng_ust_tracepoint_enabled() ni lttng_ust_do_tracepoint() tienen una llamada STAP_PROBEV(), por lo que si la necesitas, debes emitir esta llamada tú mismo.

Trazado de constructores y destructores de C/C++

Si se cumple alguna de las siguientes condiciones:

•Compilas tu aplicación C++ con GCC ≤ 4.8.
•Compilas tu aplicación C/C++ con un compilador C++ y defines LTTNG_UST_ALLOCATE_COMPOUND_LITERAL_ON_HEAP.

Entonces LTTng no trazará:

•Constructores y destructores de C en la propia aplicación o en archivos enlazados estáticamente.
•Algunos constructores y destructores de C++ en la propia aplicación o en archivos enlazados estáticamente.

En este caso, qué constructores y destructores exactos de C++ no serán trazados depende del orden de inicialización dentro de cada unidad de traducción y entre todas las unidades de traducción cuando se enlazan juntas.

Enlazado estático del proveedor de tracepoint

Con el método de enlace estático, los proveedores de tracepoint compilados se copian en la aplicación de destino.

Define la definición LTTNG_UST_TRACEPOINT_DEFINE debajo de la definición LTTNG_UST_TRACEPOINT_CREATE_PROBES en el código fuente del proveedor de tracepoint:

#define LTTNG_UST_TRACEPOINT_CREATE_PROBES
#define LTTNG_UST_TRACEPOINT_DEFINE
#include "tp.h"

Crea el archivo objeto del proveedor de tracepoint:

$ cc -c -I. tp.c

Nota

Aunque una aplicación instrumentada con tracepoints LTTng-UST puede ser compilada con un compilador C++, las sondas de tracepoint deben ser compiladas con un compilador C.

En este punto, *puedes* archivar este archivo objeto del proveedor de tracepoint, posiblemente con otros archivos objeto de tu aplicación o con otros archivos objeto de proveedores de tracepoint, como una biblioteca estática:

$ ar rc tp.a tp.o

El uso de una biblioteca estática tiene la ventaja de centralizar los objetos del proveedor de tracepoint para que puedan ser compartidos entre múltiples aplicaciones. De esta manera, cuando se modifica el proveedor de tracepoint, los cambios en el código fuente no tienen que ser parcheados en el árbol de código fuente de cada aplicación. Las aplicaciones necesitan ser enlazadas de nuevo después de cada cambio, pero no necesitan ser recompiladas de otra manera (a menos que la API del proveedor de tracepoint cambie).

Luego, enlaza tu aplicación con este archivo objeto (o con la biblioteca estática que lo contiene) y con liblttng-ust y libdl (libc en un sistema BSD):

$ cc -o app tp.o app.o -llttng-ust -ldl

Carga dinámica del proveedor de tracepoint

El segundo enfoque para empaquetar el proveedor de tracepoint es usar el cargador dinámico: la biblioteca y sus funciones miembro se buscan explícitamente, se cargan en tiempo de ejecución.

En este escenario, el proveedor de tracepoint se compila como un objeto compartido.

El proceso para crear el objeto compartido del proveedor de tracepoint es muy similar al del *método de enlace estático*, excepto que:

•Dado que el proveedor de tracepoint no es parte de la aplicación, LTTNG_UST_TRACEPOINT_DEFINE debe definirse, para cada proveedor de tracepoint, en exactamente un archivo fuente de la *aplicación*.
•LTTNG_UST_TRACEPOINT_PROBE_DYNAMIC_LINKAGE debe definirse junto a LTTNG_UST_TRACEPOINT_DEFINE.

Con respecto a LTTNG_UST_TRACEPOINT_DEFINE y LTTNG_UST_TRACEPOINT_PROBE_DYNAMIC_LINKAGE, la práctica recomendada es usar un archivo fuente C separado en tu aplicación para definirlos, y luego incluir los archivos de cabecera del proveedor de tracepoint después. Por ejemplo, como tp-define.c:

#define LTTNG_UST_TRACEPOINT_DEFINE
#define LTTNG_UST_TRACEPOINT_PROBE_DYNAMIC_LINKAGE
#include "tp.h"

El archivo objeto del proveedor de tracepoint utilizado para crear la biblioteca compartida se construye como se hace usando el método de enlace estático, pero con la opción -fpic:

$ cc -c -fpic -I. tp.c

Luego se enlaza como una biblioteca compartida de la siguiente manera:

$ cc -shared -Wl,--no-as-needed -o tp.so tp.o -llttng-ust

Este objeto compartido del proveedor de tracepoint no se enlaza con la aplicación de usuario: debe cargarse manualmente. Es por eso que la aplicación se construye sin mención de este proveedor de tracepoint, pero aún necesita libdl:

$ cc -o app app.o tp-define.o -ldl

Hay dos formas de cargar dinámicamente el objeto compartido del proveedor de tracepoint:

•Cargarlo manualmente desde la aplicación usando dlopen(3)
•Hacer que el cargador dinámico lo cargue con la variable de entorno LD_PRELOAD (ver ld.so(8))

Si la aplicación no carga dinámicamente el objeto compartido del proveedor de tracepoint usando uno de los métodos anteriores, el trazado se deshabilita para esta aplicación, y los eventos no se listan en la salida de lttng-list(1).

Ten en cuenta que no es seguro usar dlclose(3) en un objeto compartido de proveedor de tracepoint que se está utilizando activamente para el trazado, debido a la falta de conteo de referencias de LTTng-UST al objeto compartido.

Por ejemplo, enlazar estáticamente un proveedor de tracepoint a un objeto compartido que será cargado dinámicamente por una aplicación (un plugin, por ejemplo) no es seguro: el objeto compartido, que contiene el proveedor de tracepoint, podría ser cerrado dinámicamente (dlclose(3)) en cualquier momento por la aplicación.

Para instrumentar un objeto compartido, haz una de las siguientes:

•Enlaza estáticamente el proveedor de tracepoint a la aplicación, o
•Construye el proveedor de tracepoint como un objeto compartido (siguiendo el procedimiento que se muestra en esta sección), y cárgalo previamente cuando se necesite el trazado usando la variable de entorno LD_PRELOAD.

Uso de LTTng-UST con demonios

Se necesita un cuidado adicional al usar liblttng-ust con aplicaciones demonio que llaman a fork(2), clone(2), o rfork(2) de BSD sin una llamada de sistema posterior de la familia exec(3). La biblioteca liblttng-ust-fork.so necesita ser precargada antes de iniciar la aplicación con la variable de entorno LD_PRELOAD (ver ld.so(8)).

Para usar liblttng-ust con una aplicación demonio que cierra descriptores de archivo que no fueron abiertos por ella, precarga la biblioteca liblttng-ust-fd.so antes de iniciar la aplicación. Los casos de uso típicos incluyen demonios que cierran todos los descriptores de archivo después de fork(2), y aplicaciones defectuosas que realizan "cierres dobles".

NAME

lttng-ust - LTTng user space tracer

SYNOPSIS

#include <lttng/tracepoint.h>

“User space tracepoint providers” are used to emit events from user space applications.

The definition of a tracepoint provider is done by including the <lttng/tracepoint-event.h> header file after having defined the following pre-processor symbols:

LTTNG_UST_TRACEPOINT_PROVIDER
The name of the tracepoint provider.
LTTNG_USTTRACEPOINT_INCLUDE
The path to the tracepoint provider header file.

In order to define the probes for the user space tracepoint provider, you must include the <lttng/tracepoint-event.h> header file after having defined the following pre-processor symbols:

LTTNG_UST_TRACEPOINT_CREATE_PROBES
Macro to define the probe creation.
LTTNG_UST_TRACEPOINT_DEFINE
Macro to define the probe implementation.

Example:

#define LTTNG_UST_TRACEPOINT_CREATE_PROBES
#define LTTNG_UST_TRACEPOINT_DEFINE
#include <lttng/tracepoint-event.h>

In order to use the user space tracepoint provider in an application, you must include the tracepoint provider header file that you defined earlier.

Then, you can emit events using the lttng_ust_tracepoint() macro:

lttng_ust_tracepoint(provider_name, event_name, arg1, arg2, ...);

TRACEPOINT DEFINITION

A tracepoint event is defined using the LTTNG_UST_TRACEPOINT_EVENT() macro:

LTTNG_UST_TRACEPOINT_EVENT(provider, event, arg_list, field_list)
provider
Tracepoint provider name.
event
Tracepoint event name.
arg_list
Comma separated list of arguments to the tracepoint event. Arguments are specified as 
type name
pairs. Example: 
int my_int, const char *my_str
This list can be empty. Note that you must use LTTNG_UST_TP_ARGS() to wrap this list.

Example:

LTTNG_UST_TP_ARGS(int, my_integer_arg, const char *, my_string_arg)
field_list
Comma separated list of fields to be recorded in the trace event. Fields are specified using macros such as lttng_ust_field_integer(), lttng_ust_field_string(), etc. Note that you must use LTTNG_UST_TP_FIELDS() to wrap this list.

Example:

LTTNG_UST_TP_FIELDS(
        lttng_ust_field_integer(int, my_int_field, my_integer_arg)
        lttng_ust_field_string(my_str_field, my_string_arg)
    )

A tracepoint event can also be defined from a class of tracepoint events using the LTTNG_UST_TRACEPOINT_EVENT_INSTANCE() macro:

LTTNG_UST_TRACEPOINT_EVENT_INSTANCE(provider, class, provider, event, arg_list)
provider
Tracepoint provider name.
class
Tracepoint class name.
event
Tracepoint event name.
arg_list
Comma separated list of arguments to the tracepoint event. Arguments are specified as 
type name
pairs. Example: 
int my_int, const char *my_str
This list can be empty. Note that you must use LTTNG_UST_TP_ARGS() to wrap this list.

Example:

LTTNG_UST_TP_ARGS(int, my_integer_arg, const char *, my_string_arg)

The fields of an event instance are inherited from its class.

Tracepoint classes are defined using the LTTNG_UST_TRACEPOINT_EVENT_CLASS() macro:

LTTNG_UST_TRACEPOINT_EVENT_CLASS(provider, class, arg_list, field_list)
provider
Tracepoint provider name.
class
Tracepoint class name.
arg_list
Same as for LTTNG_UST_TRACEPOINT_EVENT().

Example:

LTTNG_UST_TP_ARGS(int, my_integer_arg, struct app_struct *, app_struct_arg)
field_list
Same as for LTTNG_UST_TRACEPOINT_EVENT().

Example:

LTTNG_UST_TP_FIELDS(
        lttng_ust_field_integer(int, a, my_integer_arg)
        lttng_ust_field_integer(unsigned long, b, app_struct_arg->b)
        lttng_ust_field_string(c, app_struct_arg->c)
    )

The following field types are available:

lttng_ust_field_integer()
Record an integer value.
lttng_ust_field_integer_hex()
Record an integer value in hexadecimal format.
lttng_ust_field_float()
Record a float value.
lttng_ust_field_string()
Record a string value.
lttng_ust_field_array()
Record an array of integers.
lttng_ust_field_array_text()
Record an array of characters interpreted as text.
lttng_ust_field_sequence()
Record a sequence of integers.
lttng_ust_field_sequence_text()
Record a sequence of characters interpreted as text.
lttng_ust_field_enum()
Record an integer value which is a member of a defined enumeration.

The format for each field is: 

macro(type, name, value)
or 
macro(type, name, array, size)
for arrays, or 
macro(type, name, sequence, size_type, size_value)
for sequences.

Enumerations are defined using the LTTNG_UST_TRACEPOINT_ENUM() macro:

LTTNG_UST_TRACEPOINT_ENUM(provider, enum_name, value_list)
provider
Tracepoint provider name.
enum_name
Enumeration name.
value_list
Comma separated list of enumeration values. Note that you must use LTTNG_UST_TP_ENUM_VALUES() to wrap this list.

Example:

LTTNG_UST_TP_ENUM_VALUES(
        lttng_ust_field_enum_value("ZERO", 0)
        lttng_ust_field_enum_value("ONE", 1)
        lttng_ust_field_enum_value("TWO", 2)
        lttng_ust_field_enum_range("A RANGE", 52, 125)
        lttng_ust_field_enum_value("ONE THOUSAND", 1000)
    )

LTTNG_UST_TRACEPOINT_LOGLEVEL(provider, event, loglevel)
provider
Tracepoint provider name.
event
Tracepoint event name.
loglevel
Log level. Possible values are: LTTNG_UST_TRACEPOINT_LOGLEVEL_EMERGENCY, LTTNG_UST_TRACEPOINT_LOGLEVEL_ALERT, LTTNG_UST_TRACEPOINT_LOGLEVEL_CRITICAL, LTTNG_UST_TRACEPOINT_LOGLEVEL_ERROR, LTTNG_UST_TRACEPOINT_LOGLEVEL_WARNING, LTTNG_UST_TRACEPOINT_LOGLEVEL_NOTICE, LTTNG_UST_TRACEPOINT_LOGLEVEL_INFO, LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_SYSTEM, LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_MODULE, LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_USER, LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_FILE, LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_FUNCTIONS, LTTNG_UST_TRACEPOINT_LOGLEVEL_DEBUG_ALL.

Detect if LTTng-UST is loaded

To detect if liblttng-ust is loaded from an application:

1.Define the lttng_ust_loaded weak symbol globally: 
int lttng_ust_loaded __attribute__((weak));

This weak symbol is set by the constructor of liblttng-ust.

2.Test lttng_ust_loaded where needed: 
/* ... */
if (lttng_ust_loaded) {
    /* LTTng-UST is loaded */
} else {
    /* LTTng-UST is NOT loaded */
}
/* ... */

EXAMPLE


Note

A few examples are available in the doc/examples directory of LTTng-UST’s source tree.

This example shows all the features documented in the previous sections. The static linking method is chosen here to link the application with the tracepoint provider.

You can compile the source files and link them together statically like this:

$ cc -c -I. tp.c
$ cc -c app.c
$ cc -o app tp.o app.o -llttng-ust -ldl

Using the lttng(1) tool, create an LTTng tracing session, enable all the events of this tracepoint provider, and start tracing:

$ lttng create my-session
$ lttng enable-event --userspace 'my_provider:*'
$ lttng start

You may also enable specific events:

$ lttng enable-event --userspace my_provider:big_event
$ lttng enable-event --userspace my_provider:event_instance2

Run the application:

$ ./app some arguments

Stop the current tracing session and inspect the recorded events:

$ lttng stop
$ lttng view

                "Error: Cannot open /tmp/app.txt for writing\n");
        return EXIT_FAILURE;
    }

        return EXIT_FAILURE;
    }
    lttng_ust_tracepoint(my_provider, big_event, 35,
                         "hello tracepoint", stream, -3.14,
                         array_of_ints);
    fclose(stream);

    app_struct.c = "[the string]";

    return EXIT_SUCCESS;
}

ENVIRONMENT VARIABLES

LTTNG_HOME

Alternative user’s home directory. This variable is useful when the user running the instrumented application has a non-writable home directory. This path is where Unix sockets for communication with the per-user session daemon are located.

LTTNG_UST_ABORT_ON_CRITICAL

If set, abort the instrumented application on a critical error message.

LTTNG_UST_ALLOW_BLOCKING

If set, allow the application to retry event tracing when there’s no space left for the event record in the sub-buffer, therefore effectively blocking the application until space is made available or the configured timeout is reached.

To allow an application to block during tracing, you also need to specify a blocking timeout when you create a channel with the --blocking-timeout option of the lttng-enable-channel(1) command.

This option can be useful in workloads generating very large trace data throughput, where blocking the application is an acceptable trade-off to prevent discarding event records.


Warning
Setting this environment variable may significantly affect application timings.

LTTNG_UST_APP_PATH

Path of the directory where to expect the LTTng session daemon to place the following files to receive instrumented application connection requests:
•The application registration Unix socket.
•The "wait" shared memory files to wake up instrumented applications that are waiting for a session daemon to start.
•The agent port file.

This file contains the TCP port the agents must connect to in order to enable LTTng tracing.

This directory must exist when you start the application for LTTng tracing to be enabled.

When LTTNG_UST_APP_PATH is set, liblttng-ust:

•Only considers this path to connect to a session daemon.
•Won’t connect to root and/or user session daemons as usual.

See the corresponding LTTNG_UST_CTL_PATH environment variable of lttng-sessiond(8).

LTTNG_UST_CLOCK_PLUGIN

Path to the shared object which acts as the clock override plugin. An example of such a plugin can be found in the LTTng-UST documentation under examples/clock-override.
.

LTTNG_UST_DEBUG

Si está configurada, habilita la salida de depuración y errores de liblttng-ust.

LTTNG_UST_GETCPU_PLUGIN

Ruta al objeto compartido que actúa como plugin de anulación de la función getcpu(). Un ejemplo de dicho plugin se puede encontrar en la documentación de LTTng-UST bajo examples/getcpu-override https://github.com/lttng/lttng-ust/tree/stable-2.14/doc/examples/getcpu-override.

LTTNG_UST_MAP_POPULATE_POLICY

Si está configurada, anula la política utilizada para poblar las páginas de memoria compartida dentro de la aplicación.

Los valores posibles son:

none (predeterminado)

No pre-poblar ninguna página: tomar faltas menores en el primer acceso mientras se rastrea.

cpu_possible

Pre-poblar páginas para todas las CPU posibles en el sistema, como se muestra en /sys/devices/system/cpu/possible.

LTTNG_UST_REGISTER_TIMEOUT

Tiempo de espera para el comando del demonio de sesión registration done antes de proceder a ejecutar el programa principal (milisegundos).

El valor 0 significa no esperar. El valor -1 significa esperar para siempre. Se recomienda establecer esta variable de entorno a 0 para aplicaciones con restricciones de tiempo en el tiempo de inicio del proceso.

Predeterminado: 3000.

LTTNG_UST_WITHOUT_BADDR_STATEDUMP

Si está configurada, evita que liblttng-ust realice un volcado de estado de dirección base (ver la sección Volcado de estado de LTTng-UST anterior).

LTTNG_UST_WITHOUT_PROCNAME_STATEDUMP

Si está configurada, evita que liblttng-ust realice un volcado de estado de nombre de proceso (ver la sección Volcado de estado de LTTng-UST anterior).
