ltx2crossrefxml(1) REFERENCIAS CRUZADAS LATEXWARE ltx2crossrefxml(1)

NOMBRE

ltx2crossrefxml.pl - crear archivos XML para enviar a crossref.org

SINOPSIS

ltx2crossrefxml [-c archivo_config] [-o archivo_salida] [-entrada-es-xml]
archivo_latex1 archivo_latex2 ...

OPCIONES

-c archivo_config
Archivo de configuración. Si este archivo está ausente, se utilizan los valores predeterminados. Véase más abajo para conocer su formato.
-o archivo_salida
Archivo de salida. Si no se utiliza esta opción, el XML se muestra en la salida estándar (stdout).
-entrada-es-xml
No transformar las cadenas de autor y título de entrada, asumir que son XML válido.

También se admiten las opciones habituales "--help" y "--version". Las opciones pueden empezar con "-" o "--", y ordenarse arbitrariamente.

DESCRIPCIÓN

Para cada archivo_latex dado, este script lee los archivos ".rpi" y (si existen) ".bbl" y genera un XML correspondiente que puede ser subido a Crossref (https://crossref.org). Se ignora cualquier extensión de archivo_latex, y el propio archivo_latex no se lee (y ni siquiera necesita existir).

Cada archivo ".rpi" especifica los metadatos de un solo artículo para ser subido a Crossref (un elemento "journal_article" en su esquema); un ejemplo se muestra a continuación. Estos archivos son generados por el paquete "resphilosophica" (https://ctan.org/pkg/resphilosophica) y el procedimiento de publicación de TUGboat (https://tug.org/TUGboat/repository.html), pero (como siempre) también pueden ser creados manualmente o mediante cualquier otro método que implemente.

Cualquier archivo ".bbl" presente se utiliza para la información de citación en el XML de salida. Consulte la sección CITAS más abajo.

A menos que se especifique "--entrada-es-xml", para todo el texto (autores, título, citas), las secuencias de control estándar de TeX se reemplazan por texto plano o UTF-8, o se eliminan, según corresponda. Se utiliza la rutina "LaTeX::ToUnicode::convert" para ello (https://ctan.org/pkg/bibtexperllibs). Es casi seguro que las secuencias de control de TeX complicadas no se manejarán correctamente.

Si se proporciona "--entrada-es-xml", las cadenas de autor y título de los archivos rpi se generan tal cual, asumiendo que son XML válidos; no se realiza ninguna comprobación.

El texto de las citas de los archivos ".bbl" siempre se convierte de LaTeX a texto plano.

Este script solo escribe un archivo XML. Depende de usted realizar la subida a Crossref; por ejemplo, puede utilizar su herramienta Java "crossref-upload-tool.jar" (https://www.crossref.org/education/member-setup/direct-deposit-xml/https-post).

Para la definición del esquema Crossref que genera actualmente este script, consulte https://data.crossref.org/reports/help/schema_doc/5.3.1/index.html con enlaces e información adicional en https://www.crossref.org/documentation/schema-library/metadata-deposit-schema-5-3-1/.

FORMATO DEL ARCHIVO DE CONFIGURACIÓN

El archivo de configuración se lee como código Perl. Por lo tanto, las líneas de comentario que comienzan con "#" y las líneas en blanco se ignoran. Las otras líneas son típicamente asignaciones con la forma (los espacios son opcionales):

$variable = valor ;

Generalmente, el valor es una "cadena" entre comillas dobles o simples ASCII, según la sintaxis de Perl. La idea es especificar los valores específicos del usuario y de la revista necesarios para la carga en Crossref. Las variables que se utilizan son las siguientes:

$depositorName = "Nombre del Depositante";
$depositorEmail = 'depositante@ejemplo.org';
$registrant = 'Entidad Registrante';  # nombre de la organización
$fullTitle = "TÍTULO COMPLETO";   # nombre de la revista
$issn = "1234-5678";         # requerido
$abbrevTitle = "TÍTULO ABREVIADO"; # opcional
$coden = "CODEN";            # opcional

Para una ejecución dada, todos los datos ".rpi" leídos se asumen que pertenecen a la revista especificada en el archivo de configuración. Más precisamente, los datos de configuración se escriben como un elemento "journal_metadata", con el "full_title", "issn", etc., dados, y luego cada ".rpi" se escribe como elementos "journal_issue" más "journal_article".

El archivo de configuración también puede definir una función Perl: "LaTeX_ToUnicode_convert_hook". Si está definida, se llama al principio del procedimiento que convierte texto LaTeX a Unicode, que se realiza con el módulo LaTeX::ToUnicode, del paquete "bibtexperllibs" (https://ctan.org/pkg/bibtexperllibs). La función debe aceptar una cadena (el texto LaTeX) y devolver una cadena (presumiblemente la cadena transformada). Las conversiones estándar se aplican luego a la cadena devuelta, por lo que la función configurada solo necesita manejar casos especiales, como secuencias de control particulares de la revista en cuestión.

FORMATO DEL ARCHIVO RPI

Aquí está (la parte relevante del) archivo ".rpi" correspondiente al ejemplo "rpsample.tex" en el paquete "resphilosophica" (https://ctan.org/pkg/resphilosophica):

%authors=Boris Veytsman\and A. U. Th{\o }r\and C. O. R\"espondent
%title=A Sample Paper:\\ \emph  {A Template}
%year=2012
%volume=90
%issue=1--2
%startpage=1
%endpage=1
%doi=10.11612/resphil.A31245
%paperUrl=http://borisv.lk.net/paper12
%publicationType=full_text

Otras líneas, algunas que no comienzan con %, se ignoran (y no se muestran). Para más detalles sobre el procesamiento, consulte el código.

El valor de %paperUrl es lo que se asociará con el %doi dado (generado como elemento "resource"). Crossref recomienda encarecidamente que la URL sea para una página de destino (landing page) y no directamente para un pdf (https://www.crossref.org/education/member-setup/creating-a-landing-page/). Caso especial: si la URL no se especifica y la revista es Res Philosophica, se devuelve una URL de búsqueda especial para pdcnet.org. Cualquier otra revista debe especificar esto siempre.

El campo %authors se divide en "\and" (ignorando el espacio en blanco antes y después), y se genera como el elemento "contributors", utilizando "sequence="first"" para el primer autor listado, "sequence="additional"" para los restantes. Los autores se analizan utilizando "BibTeX::Parser::Author" (https://ctan.org/pkg/bibtexperllibs).

Si no se especifica %publicationType, se establece por defecto en "full_text", ya que históricamente ha sido así; "full_text" también puede especificarse explícitamente. ltx2crossrefxml.pl(1)

NAME

ltx2crossrefxml.pl - converter of LaTeX documents to crossref XML format

SYNOPSIS

ltx2crossrefxml.pl [ options ] input.tex ...

OPTIONS

-h, --help
Print usage information and exit.
-v, --version
Print version information and exit.
-o, --output output.xml
Write output to the specified file instead of standard output.
-c, --config config.cfg
Read configuration options from the specified file.
-p, --package pkgname
Print package name instead of standard XML output. Useful for Arch Linux package scripts.

DESCRIPTION

The ltx2crossrefxml.pl script converts LaTeX documents to the XML format required by Crossref. It handles basic document metadata, author information, and citations.

The script expects a list of LaTeX files as input. For each input file, it attempts to find a corresponding configuration file (named input_base.rpi) and bibliography file (named input_base.bbl). These files are used to extract metadata for the Crossref submission.

The primary input is a LaTeX file, which is parsed to extract the main content. The script focuses on extracting information relevant to Crossref's XML schema for journal articles.

CONFIGURATION FILE FORMAT

The configuration file (with extension .rpi) contains metadata for a single article. It uses a simple key-value format, where keys start with a percentage sign (%). Recognized keys include:

%journal
Journal title.
%year
Publication year.
%volume
Journal volume.
%issue
Journal issue.
%pages
Page numbers.
%doi
Digital Object Identifier.
%publisher
Publisher name.
%issn
International Standard Serial Number.
%eissn
Electronic International Standard Serial Number.
%url
URL of the article.
%title
Article title.
%authors
Author list. See the MORE ABOUT AUTHOR NAMES section for details.
%abstract
Article abstract.
%keywords
Article keywords.
%license-url
URL of the article license.
%license-text
Text of the article license.
%license-type
Type of the article license (e.g., CC-BY).

All other keys are ignored. If an attribute is omitted entirely from the given "journal_article" element.

Each ".rpi" must contain information for only one article, but multiple files can be read in a single run. It would not be difficult to support multiple articles in a single ".rpi" file, but it makes debugging and error correction easier to keep the input to one article per file.

MORE ABOUT AUTHOR NAMES

The three formats for names recognized are (not coincidentally) the same as BibTeX:

First von Last
von Last, First
von Last, Jr., First

The forms can be freely intermixed within a single %authors line, separated with "\and" (including the backslash). Commas as name separators are not supported, unlike BibTeX.

In short, you may almost always use the first form; you shouldn't if either there's a Jr part, or the Last part has multiple tokens but there's no von part. See the "btxdoc" (``BibTeXing'' by Oren Patashnik) document for details. The authors are parsed using "BibTeX::Parser::Author" (https://ctan.org/pkg/bibtexperllibs).

In the %authors line of a ".rpi" file, some secondary directives are recognized, indicated by "|" characters. Easiest to explain with an example:

%authors=|organization|\LaTeX Project Team \and Alex Brown|orcid=123

Thus: 1) if "|organization|" is specified, the author name will be output as an "organization" contributor, instead of the usual "person_name", as the Crossref schema requires.

2) If "| orcid=value|" is specified, the value is output as an "ORCID" element for that "person_name".

These two directives, "|organization"| and "| orcid|" are mutually exclusive, because that's how the Crossref schema defines them. The "=" sign after " orcid" is required, while all spaces after the " orcid" keyword are ignored. Other than that, the ORCID value is output literally. (E.g., the ORCID value of 123 above is clearly invalid, but it would be output anyway, with no warning.)

Extra "|" characters, at the beginning or end of the entire %authors string, or doubled in the middle, are accepted and ignored. Whitespace is ignored around all "|" characters.

CITATIONS

Each ".bbl" file corresponding to an input ".rpi" file is read and used to output a "citation_list" element for that "journal_article" in the output XML. If no ".bbl" file exists for a given ".rpi", no "citation_list" is output for that article.

The ".bbl" processing is rudimentary: only so-called "unstructured_citation" references are produced for Crossref, that is, the contents of the citation (each paragraph in the ".bbl") is dumped as a single flat string without markup.

Bibliography text is unconditionally converted from TeX to XML, via the method described above. It is not unusual for the conversion to be incomplete or incorrect. It is up to you to check for this; e.g., if any backslashes remain in the output, it is most likely an error.

Furthermore, it is assumed that the ".bbl" file contains a sequence of references, each starting with "\bibitem{KEY}" (which itself must be at the beginning of a line, preceded only by whitespace), and the whole bibliography ending with "\end{thebibliography}" (similarly at the beginning of a line). A bibliography not following this format will not produce useful results. Bibliographies can be created by hand, or with BibTeX, or any other method.

The "key" attribute for the "citation" element is taken as the KEY argument to the "\bibitem" command. The sequential number of the citation (1, 2, ...) is appended. The argument to "\bibitem" can be empty ("\bibitem{}", and the sequence number will be used on its own. Although TeX will not handle empty "\bibitem" keys, it can be convenient when creating a ".bbl" purely for Crossref.

The ".rpi" file is also checked for the bibliography information, in this same format.

Feature request: if anyone is interested in figuring out how to generate structured citations (https://data.crossref.org/reports/help/schema_doc/5.3.1/common5_3_1_xsd.html#citation), that would be great. The schema does not support many useful fields, so we also want to keep the unstructured text output.

Norman Gray's beastie program (https://heptapod.host/nxg/beastie) supports this, via "beastie extract-bib.scm -O crossref $(doc).aux", as invoked in the TUGboat "Common.mak" file. Work in progress.

By the way, if for some reason we have to switch away from using beastie, the most viable approach is probably to change "tugboat.bst" to output no-op TeX commands like \tubibauthor, \tubibtitle, etc. (a la biblatex), and use those commands to discern the various crossref field values. We can't start from the .bib because then we'd have to reimplement Bib(La)TeX.

EXAMPLES

ltx2crossrefxml.pl ../paper1/paper1.tex ../paper2/paper2.tex \
                    -o result.xml
ltx2crossrefxml.pl -c myconfig.cfg paper.tex -o paper.xml
