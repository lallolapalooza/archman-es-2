ltrace.conf(5) Archivo de configuración de ltrace ltrace.conf(5)

NOMBRE

ltrace.conf - Archivo de configuración para ltrace(1).

DESCRIPCIÓN

Esta página del manual describe ltrace.conf, un archivo que describe prototipos de funciones en binarios para que ltrace(1) los utilice. Ltrace necesita esta información para mostrar los argumentos de las llamadas a funciones.

Cada línea de un archivo de configuración describe como máximo un elemento. Las líneas compuestas enteramente de espacios en blanco se ignoran, al igual que las líneas que comienzan con el carácter de punto y coma (líneas de comentario). Los elementos descritos pueden ser prototipos de funciones o definiciones de alias de tipos.

PROTOTIPOS

Un prototipo describe el tipo de retorno y los tipos de parámetro de una única función. La sintaxis es la siguiente:

LENS NOMBRE ([LENS{,LENS}]);

NOMBRE es el nombre (mangled) de un símbolo. En el caso elemental, LENS es simplemente un tipo. Tanto las lentes como los tipos se describen a continuación. Por ejemplo, un prototipo de función simple podría tener este aspecto:

int kill(int,int);

A pesar de la aparente similitud con C, ltrace.conf es en realidad su propio lenguaje que solo está algo inspirado en C.

TIPOS

Ltrace comprende una gama de tipos primitivos. Estos se interpretan según la convención de C nativa en la arquitectura dada. Por ejemplo, ulong se interpreta como un entero sin signo de 4 bytes en una máquina GNU/Linux de 32 bits, pero como un entero sin signo de 8 bytes en una máquina GNU/Linux de 64 bits.

void
Indica que una función no devuelve nada. También se puede utilizar para construir un puntero genérico, es decir, un número del tamaño de un puntero formateado en hexadecimal.
char
Cantidad de 8 bits representada como un carácter.
ushort,short
Indica entero corto sin signo o con signo.
uint,int
Indica entero sin signo o con signo.
ulong,long
Indica entero largo sin signo o con signo.
float
Indica un número de punto flotante con precisión simple.
double
Indica un número de punto flotante con precisión doble.

Además de los tipos primitivos, son posibles los siguientes tipos compuestos:

struct([LENS{,LENS}])
Describe una estructura con los tipos dados como campos, por ejemplo, struct(int,int,float).

La alineación se calcula como es habitual en la arquitectura. La alineación personalizada (por ejemplo, estructuras empaquetadas) y los campos de bits no son compatibles. Tampoco es posible diferenciar entre estructuras y clases C++ no POD, para las arquitecturas donde esto importa.

array(LENS,EXPR)
Describe un array de longitud EXPR, que se compone de tipos descritos por LENS, por ejemplo, array(int, 6 ).

Tenga en cuenta que en C, los arrays en el rol de argumento de función se desvanecen en punteros. Ltrace actualmente maneja esto automáticamente, pero para una corrección formal completa, dichos argumentos deberían describirse como punteros a arrays.

LENS*
Describe un puntero a un tipo dado, por ejemplo, char* o int***. Tenga en cuenta que el primer ejemplo describe en realidad un puntero a un carácter, no a una cadena. Consulte a continuación la lente string, que es aplicable a estos casos.

LENTES

Las lentes cambian la forma en que se describen los tipos. En el caso más simple, una lente es directamente un tipo. De lo contrario, un tipo está decorado por la lente. Ltrace comprende las siguientes lentes:

oct(TYPE)
El argumento, que debe ser un tipo entero, se formatea en base 8.
hex(TYPE)
El argumento, que debe ser un tipo entero o de punto flotante, se formatea en base 16. Los argumentos de punto flotante se convierten a double y luego se muestran utilizando el modificador %a de fprintf.
hide(TYPE)
El argumento no se muestra en la lista de argumentos.
bool(TYPE)
Los argumentos con valor cero se muestran como "false", los demás se muestran como "true".
bitvec(TYPE)
El argumento subyacente se interpreta como un vector de bits y se muestra un resumen de los bits establecidos en el vector. Por ejemplo, si los bits 3, 4, 5 y 7 del vector de bits están establecidos, ltrace muestra <3-5,7>. El vector de bits vacío se muestra como <>. Si hay más bits establecidos que no establecidos, se muestra lo inverso; por ejemplo, ~<> cuando se muestra un número 0xfffffffe. El conjunto completo se muestra, por lo tanto, como ~<>.

Si el tipo subyacente es integral, los bits se muestran en su orden natural big-endian, con el LSB siendo el bit 0. Por ejemplo, bitvec(ushort) con el valor 0x0102 se mostraría como <1,8>, independientemente del orden de bytes subyacente.

Para otros tipos de datos (en particular estructuras y arrays), los datos subyacentes se interpretan byte a byte. El bit 0 del primer byte tiene el número 0, el bit 0 del segundo byte el número 8, y así sucesivamente. Por lo tanto, bitvec(struct(int)) es sensible a endianidad y mostrará los bytes que componen el entero en su orden de memoria. Los punteros se desreferencian primero, por lo tanto bitvec(array(char,32)*) es en realidad un puntero a un vector de bits de 256 bits.

string(TYPE)
string[EXPR]
string

La primera forma del argumento es canónica, las dos últimas son azúcar sintáctico. En la forma canónica, el argumento de la función se formatea como una cadena. TYPE debe ser char*, o array(char,EXPR), o array(char,EXPR)*. Si se proporciona un array, la longitud será típicamente una expresión zero (pero no tiene por qué serlo). Usar un argumento que es un array simple (es decir, no un puntero a un array) tiene sentido, por ejemplo, en estructuras C, en casos como struct(string(array(char,6))), que describe el tipo C struct {chars[6];}.

Dado que las cadenas simples tipo C son bastante comunes, existen dos formas abreviadas. La primera forma abreviada (con corchetes) significa lo mismo que string(array(char,EXPR)*). La representación string simple sin argumento se toma entonces como equivalente a string[zero].

Tenga en cuenta que char* por sí solo describe un puntero a un carácter. Ltrace desreferenciará el puntero, leerá y mostrará el único carácter al que apunta.

enum(NOMBRE[=VALOR]{,NOMBRE[=VALOR]})
enum[TYPE](NOMBRE[=VALOR]{,NOMBRE[=VALOR]})

Esto describe una lente de enumeración. Si un argumento tiene alguno de los valores dados, se mostrará en su lugar como el NOMBRE correspondiente. Si se omite un VALOR, se toma el siguiente valor consecutivo después del VALOR anterior. Si se omite el primer VALOR, por defecto es 0.

TYPE, si se proporciona, es el tipo subyacente. Por lo tanto, es posible crear enumeraciones sobre shorts o longs —argumentos que son en sí mismos tipos simples, no enumerados, en C, pero cuyos valores pueden describirse significativamente como enumeraciones. Si se omite, TYPE se toma como int.

ALIAS DE TIPOS

Una línea en el archivo de configuración puede, en lugar de describir un prototipo, crear un alias de tipo. En lugar de escribir la misma enumeración o estructura en muchos lugares (y posiblemente actualizarla cuando cambie), se puede introducir un nombre para dicho tipo y luego simplemente usar ese nombre:

typedef NOMBRE = LENS;

ESTRUCTURAS RECURSIVAS

Ltrace permite expresar estructuras recursivas. Dichas estructuras se expanden a la profundidad descrita por el parámetro -A. Para declarar un tipo recursivo, primero debes introducir el tipo a ltrace usando una declaración adelantada. Luego puedes usar el tipo en otras definiciones de tipo de la manera habitual:

typedef NOMBRE = struct;
typedef NOMBRE = struct(NOMBRE se puede usar aquí)

Por ejemplo, considera la siguiente estructura de lista enlazada simple y una función que toma dicha lista como argumento:

typedef int_list = struct;
typedef int_list = struct(int, int_list*);
void ll(int_list*);

Tales declaraciones pueden llevar a una salida como la siguiente:

ll({ 9, { 8, { 7, { 6, ... } } } }) = <void>

Ltrace detecta la recursión y no expandirá estructuras ya expandidas. Por lo tanto, una lista doblemente enlazada se vería así:

typedef int_list = struct;
typedef int_list = struct(int, int_list*, int_list*);

Con una salida, por ejemplo, como:

ll({ 9, { 8, { 7, { 6, ..., ... }, recurse^ }, recurse^ }, nil })

Los tokens "recurse^" significan que el puntero dado apunta a una estructura que fue expandida en la capa anterior. Un simple "recurse" significaría que apunta de vuelta a este objeto. Por ejemplo, "recurse^^^" significa que apunta a una estructura tres capas más arriba. Para una lista doblemente enlazada, el puntero al elemento anterior es, por supuesto, el que se acaba de expandir en la ronda anterior, y por lo tanto, todos son `recurse^` o `nil`. Si los punteros siguiente y anterior están intercambiados, la salida se ajusta correspondientemente:

ll({ 9, nil, { 8, recurse^, { 7, recurse^, { 6, ..., ... } } } })

EXPRESIONES

Ltrace admite algunas expresiones elementales. Cada expresión puede ser una de las siguientes:

NUM
Un número entero.
argNUM
Valor del argumento NUM. La expresión tiene el mismo valor que el argumento correspondiente. arg1 se refiere al primer argumento, arg0 al valor de retorno de la función dada.
retval
Valor de retorno de la función, igual que arg0.
eltNUM
Valor del elemento NUM del tipo de estructura circundante. Por ejemplo, struct(ulong,array(int,elt1)) describe una estructura cuyo primer elemento es una longitud, y el segundo elemento es un array de enteros de esa longitud.

zero
zero(EXPR)

Describe un array que se extiende hasta el primer elemento, donde cada byte es 0. Si se proporciona una expresión, esa es la longitud máxima del array. Si no se encuentra el terminador NUL antes, ahí es donde termina el array.

PAQUETES DE PARÁMETROS

A veces, el prototipo de función real varía ligeramente dependiendo de los parámetros dados. Por ejemplo, el número y los tipos de los parámetros de printf no se conocen de antemano, pero ltrace puede determinarlos en tiempo de ejecución. Esta característica tiene una aplicabilidad más amplia, pero actualmente el único paquete de parámetros que ltrace admite es la propia cadena de formato de estilo printf:

format
Cuando se ve format en la lista de parámetros, se analiza el argumento de cadena subyacente y se utilizan especificadores de formato estilo GNU para determinar cuáles son los argumentos reales siguientes. Por ejemplo, si la cadena de formato es "%s %d\n", es como si format se hubiera reemplazado por string, string, int.

ARGUMENTOS DE RETORNO

Las funciones C a menudo usan uno o más argumentos para devolver valores al llamador. El llamador proporciona un puntero al almacenamiento, que la función llamada inicializa. Ltrace tiene cierto soporte para este modismo.

Cuando un binario rastreado alcanza una llamada a función, ltrace primero obtiene todos los argumentos. Luego muestra la porción izquierda de la lista de argumentos. Solo cuando la función retorna, ltrace muestra también la porción derecha. Típicamente, la porción izquierda ocupa todos los argumentos, y la porción derecha solo contiene el valor de retorno. Pero ltrace te permite configurar dónde exactamente poner la línea divisoria mediante un operador + colocado delante de un argumento:

int asprintf(+string*, format);

Aquí, el primer argumento de asprintf se denota como argumento de retorno, lo que significa que la visualización de toda la lista de argumentos se retrasa hasta que la función retorna:

a.out->asprintf( <unfinished ...>
libc.so.6->malloc(100) = 0x245b010
[... más llamadas aquí ...]
<... asprintf reanudado> "X=1", "X=%d", 1) = 5

Actualmente no es posible tener un argumento "in-out" que pase información en ambas direcciones.

EJEMPLOS

A continuación, el primero es el prototipo C, y después de él está la línea de configuración de ltrace.

void func_charp_string(char str[]);
void func_charp_string(string);

enum e_foo {RED, GREEN, BLUE};
void func_enum(enum e_foo bar);

void func_enum(enum(RED,GREEN,BLUE));
- o -
typedef e_foo = enum(RED,GREEN,BLUE);
void func_enum(e_foo);
void func_arrayi(int arr[], int len);
void func_arrayi(array(int,arg2)*,int);

struct S1 {float f; char a; char b;};
struct S2 {char str[6]; float f;};
struct S1 func_struct(int a, struct S2, double d);

struct(float,char,char) func_struct_2(int, struct(string(array(char, 6)),float), double);
