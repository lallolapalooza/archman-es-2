Descripción Detallada

libltc - codificar+decodificar código de tiempo lineal

El Código de Tiempo Lineal (LTC) es una codificación de datos de código de tiempo como una señal de audio codificada en Manchester-Biphase. La señal de audio se graba comúnmente en una pista de VTR u otro medio de almacenamiento.

libltc facilita la decodificación y codificación de LTC desde/hacia código de tiempo, incluyendo soporte para fechas SMPTE.

Documentación de Estructuras de Datos

struct LTCFrame

Marco LTC de 80 bits sin procesar

La secuencia de datos para cada fotograma de video del Código de Tiempo Longitudinal consta de ochenta periodos de bit.

A una velocidad de fotogramas de 30 fps, la tasa de bits corresponde a 30 [fps] * 80 [bits/f] = 2400 bits por segundo. La frecuencia para una secuencia de ceros sería de 1.2 kHz y para una secuencia de unos sería de 2.4 kHz. Con todas las velocidades de fotogramas de video y tasas de muestreo de audio comúnmente utilizadas, el código de tiempo LTC se puede grabar fácilmente en una pista de audio.

En cada fotograma, 26 de los ochenta bits transportan el tiempo SMPTE en código binario decimal (BCD).

Estos bits son UNIDADES_DE_FOTOGRAMA, DECENAS_DE_FOTOGRAMA, UNIDADES_DE_SEGUNDO, DECENAS_DE_SEGUNDO, UNIDADES_DE_MINUTO, DECENAS_DE_MINUTO, UNIDADES_DE_HORA y DECENAS_DE_HORA. Los dígitos BCD se cargan 'primer bit menos significativo' (libltc se encarga de la alineación específica de la arquitectura).

32 bits se asignan como ocho grupos de cuatro USER_BITS (también conocidos como 'Binary Groups'). Esta capacidad se utiliza generalmente para transportar información adicional como el número de carrete y/o la fecha. Los User Bits pueden asignarse como se desee, siempre que se borren ambos bits de indicación de Grupo Binario.

La función ltc_frame_to_time puede interpretar los user-bits como Fecha+Zona horaria SMPTE según SMPTE 309M-1999. De manera similar, ltc_time_to_frame

Los últimos 16 bits componen la PALABRA DE SINCRONIZACIÓN (SYNC WORD). Estos bits indican el límite del trama, la dirección de la cinta y la velocidad de bits del tono de sincronización. Los valores de estos bits son fijos como 0011 1111 1111 1101

El bit de corrección de fase de marca Biphasic (Bit 27 o 59) puede establecerse o borrarse para que cada palabra de 80 bits contenga un número par de ceros. Esto significa que la fase del tren de pulsos en cada Palabra de Sincronización será la misma.

El Bit 10 indica el código de tiempo de caída de trama (drop-frame). El indicador de trama de color (col.frm) es el Bit 11; si el código de tiempo se sincronizó intencionalmente con una secuencia de campo de TV en color, este bit se establece.

El Bit 58 no es necesario para el conteo BCD de HORAS-DECENAS (que tiene un valor máximo de dos) y no se le ha dado ningún otro propósito especial, por lo que permanece sin asignar. Este bit ha sido RESERVADO para asignación futura.

Los bits indicadores de Grupo Binario (bits 43 y 59) son dos bits que indican el formato de los datos de Bits de Usuario. SMPTE 12M-1999 define el bit 58 previamente reservado para señalar que la hora está bloqueada a la hora del reloj de pared dentro de una tolerancia de ± 0.5 segundos.

SMPTE 12M-1999 también cambia el esquema de numeración de BGF. (BGF1 fue renombrado a BGF2 y el bit 58 se convierte en BGFB1)

Para complicar aún más las cosas, la asignación de BGFB, así como el bit de corrección de fase de marca biphasic (también conocido como paridad), dependen del formato de código de tiempo utilizado.

         25 fps   24, 30 fps
 BGF0      27        43
 BGF1      58        58
 BGF2      43        59
 Paridad    59        27

Los nombres de variables elegidos para la estructura LTCFrame se basan en el estándar de 24,30 fps.

Los bits indicadores de Grupo Binario solo deben usarse como se muestra en la tabla de verdad a continuación. Las entradas sin asignar en la tabla no deben usarse, ya que pueden asignarse significados específicos en el futuro.

(1) Conjunto de caracteres ISO/IEC 646 o ISO/IEC 2022. Si se están utilizando códigos ISO de siete bits, se convertirán a códigos de ocho bits estableciendo el octavo bit a cero. Se pueden codificar 4 códigos ISO, user7 y user8 se utilizarán para el primer código con LSB 7 y MSB en 8. Los códigos ISO restantes se distribuirán de la misma manera a user5/6, user3/4 y user1/2 respectivamente.

(2) Page/Line indica que ANSI/SMPTE-262M se utiliza para los bits de usuario. Es un sistema de multiplexación que puede utilizarse para codificar grandes cantidades de datos en los grupos binarios mediante la multiplexación en el tiempo.

libltc no utiliza ninguno de los BGF, excepto el bit de paridad, que se puede calcular y establecer con ltc_frame_set_parity. El establecimiento e interpretación de BGF se deja a la aplicación que utiliza libltc. Sin embargo, libltc proporciona funcionalidad para analizar o establecer la fecha y la zona horaria según SMPTE 309M-1999.

struct LTCFrameExt

Trama LTC extendida - incluye desplazamientos de posición de muestra de audio, volumen, etc.

Nota: Para sistemas de TV, la muestra en el flujo de datos de audio LTC donde comienza la trama LTC no está necesariamente al mismo tiempo que la trama de video que se describe en la trama LTC.

off_start denota el tiempo de la primera transición del bit 0 en la trama LTC.

Para sistemas de Televisión 525/60, la primera transición ocurrirá al principio de la línea 5 de la trama con la que está asociada. La tolerancia es ± 1.5 líneas.

Para sistemas 625/50, la primera transición ocurrirá al principio de la línea 2 ± 1.5 líneas de la trama con la que está asociada.

Solo para sistemas 1125/60, la primera transición ocurre exactamente en la referencia de sincronización vertical de la trama. ± 1 línea.

Ejemplos
ltcdecode.c.

Campos de datos:

float biphase_tics[LTC_FRAME_BIT_COUNT] información detallada de temporización: fase de la señal LTC; el tiempo entre cada bit en el cuadro LTC en cuadros de audio. La suma de los 80 valores en la matriz dará audio-frames/LTC-frame = (off_end - off_start + 1).

LTCFrame ltc la trama LTC real. ver LTCFrame

ltc_off_t off_end la muestra en el flujo correspondiente al final de la trama LTC.

ltc_off_t off_start la muestra aproximada en el flujo correspondiente al inicio de la trama LTC.

int reverse si no es cero, se detectó una trama LTC reproducida al revés. Dado que la trama se invirtió, comenzó en off_end y termina en off_start (off_end > off_start). (Nota: en reproducción inversa, se detecta la palabra de sincronización (invertida) del siguiente/anterior cuadro, este desplazamiento se corrige).

ltcsnd_sample_t sample_max la muestra de entrada máxima para esta trama (0..255)

ltcsnd_sample_t sample_min la muestra de entrada mínima para esta trama (0..255)

double volume el volumen de la señal de entrada en dbFS

int ltc_encoder_encode_byte (LTCEncoder * e, int byte, double speed)

Genera audio LTC para un byte dado del fotograma LTC y lo coloca en el búfer interno.

ver ltc_encoder_copy_buffer y ltc_encoder_get_bufferptr

LTC tiene 10 bytes por fotograma: 0 <= bytecnt < 10. Usa SMPTESetTime(..) para establecer el fotograma actual antes de codificar. Ver tests/encoder.c para un ejemplo.

La señal de salida predeterminada es @ -3dBFS (38..218 en 8 bits sin signo). Ver también ltc_encoder_set_volume

Si speed es < 0, los bits se codifican en reversa. slowdown > 10.0 requiere tamaños de búfer personalizados; ver ltc_encoder_set_buffersize

Parámetros

e manejador del codificador
byte byte del fotograma LTC a codificar 0..9
speed velocidad variable, < 1.0 más rápido, > 1.0 más lento; debe ser != 0

Devoluciones

0 si tiene éxito, -1 si el byte no es válido o hay desbordamiento del búfer (speed > 10.0)

void ltc_encoder_encode_frame (LTCEncoder * e)

Codifica un fotograma LTC completo a velocidad fija. Esto es equivalente a llamar a ltc_encoder_encode_byte 10 veces para los bytes 0..9 con velocidad 1.0.

Nota: El búfer interno debe estar vacío antes de llamar a esta función. De lo contrario, podría desbordarse. Esto suele ser el caso si se lee con ltc_encoder_copy_buffer después de llamar a esta función.

El tamaño de búfer interno predeterminado es exactamente un fotograma LTC completo a velocidad 1.0.

int ltc_encoder_end_encode (LTCEncoder * e)

Termina la codificación y agrega la transición final.

Consulte la imagen en LTCFrame. En este ejemplo, los datos codificados comienzan y terminan con un borde ascendente. La transición al inicio del siguiente fotograma marca el final del fotograma anterior. Esta transición se codifica al principio de un fotograma. Sin embargo, si no hay un fotograma adicional que codificar, se debe agregar una transición final de terminación.

Dado que LTC generalmente se envía como un flujo continuo, esto no es una preocupación. Sin embargo, para una duración fija y finita que se va a codificar, este método agrega una transición de terminación al búfer.

Después de esto, se debe llamar a ltc_encoder_reset() o ltc_encoder_free.

Parámetros

e manejador del codificador

Devoluciones

0 si tiene éxito, -1 si el byte no es válido o hay desbordamiento del búfer (speed > 10.0)

int ltc_encoder_reinit (LTCEncoder * e, double sample_rate, double fps, enum LTC_TV_STANDARD standard, int flags)

Cambia la configuración del codificador sin reasignar ninguna estructura de datos interna de la biblioteca (seguro en tiempo real). Cambiar la velocidad de fotogramas y/o la frecuencia de muestreo implica un vaciado de búfer y un reinicio del estado bifásico.

Esta llamada fallará si el búfer interno es demasiado pequeño para contener un fotograma LTC completo. Usa ltc_encoder_set_buffersize para preparar un búfer interno lo suficientemente grande como para acomodar todas las combinaciones de frecuencia de muestreo y fps a las que te gustaría reinicializar.

Los datos de la carga útil del fotograma LTC no se modifican con esta llamada; sin embargo, los bits de bandera del fotograma LTC se actualizan: si fps es igual a 29.97 o 30000.0/1001.0, el bit 'dfbit' de LTCFrame se establece en 1 para indicar el código de tiempo de fotograma omitido.

A menos que se establezca la bandera LTC_BGF_DONT_TOUCH, BGF1 se establece o se borra según LTC_TC_CLOCK y BGF0,2 de acuerdo con LTC_USE_DATE y el estándar dado. col_frame se borra y la paridad se recalcula (a menos que se proporcione LTC_NO_PARITY).

Parámetros

e manejador del codificador
sample_rate frecuencia de muestreo de audio (p. ej., 48000)
fps fotogramas de video por segundo (p. ej., 25.0)
standard el estándar de TV a usar para la posición del bit de bandera de grupo binario
flags combinación binaria de LTC_BG_FLAGS

Ejemplos
ltcencode.c.

void ltc_encoder_set_filter (LTCEncoder * e, double rise_time)

Establece el tiempo de subida de la señal del codificador / filtrado de la señal

La señal LTC debe tener un tiempo de subida de 40us +/- 10 us. Por defecto, el codificador respeta esto y filtra pasa-bajos la salida dependiendo de la frecuencia de muestreo.

Si deseas una onda cuadrada perfecta, establece 'rise_time' a 0.

Nota: ltc_encoder_reinit restablece la constante de tiempo del filtro para usar el valor por defecto de 40us para la frecuencia de muestreo dada, reemplazando cualquier valor previamente establecido con ltc_encoder_set_filter

Parámetros

e manejador del codificador
rise_time el tiempo de subida de la señal en us (10^(-6) seg), establecido a 0 para onda cuadrada perfecta, por defecto 40.0

Ejemplos

int ltc_encoder_set_volume (LTCEncoder * e, double dBFS)

Establece el volumen de la señal LTC generada

Típicamente, LTC se envía a 0dBu; en sistemas calibrados EBU, eso corresponde a -18dBFS. - Por defecto, libltc crea -3dBFS

Dado que libltc generó datos de audio de 8 bits, el dBFS mínimo es de aproximadamente -42dB, lo que corresponde a 1 bit.

0dB corresponde a un rango de señal de 127 1..255 con 128 en el centro.

Parámetros

e manejador del codificador

Devuelve

0 en caso de éxito, -1 si el valor estaba fuera de rango

ltc_off_t ltc_frame_alignment (double samples_per_frame, enum LTC_TV_STANDARD standard)

Desplazamiento de alineación de muestra de LTCFrame.

Existe un desplazamiento relativo entre el inicio del fotograma LTC y el fotograma de TV. El primer bit de un fotograma LTC corresponde a una línea específica en el fotograma de video real. Al decodificar, este desplazamiento debe restarse del tiempo de muestra de audio del fotograma LTC para que coincida con la posición de inicio del fotograma de TV.

Para fotogramas de película o HDV, el desplazamiento es cero.

Parámetros

samples_per_frame muestras de audio por fotograma de código de tiempo (p. ej., 1920 = 48000/25)
standard el estándar de TV

Devuelve

desplazamiento en muestras

int ltc_frame_decrement (LTCFrame * frame, int fps, enum LTC_TV_STANDARD standard, int flags)

Decrementa el código de tiempo en un fotograma (1/tasa de fotogramas por segundo) y establece el bit de paridad del fotograma en consecuencia (ver ltc_frame_set_parity)

Parámetros

frame el código de tiempo LTC a decrementar
fps tasa de fotogramas entera (para código de tiempo de fotograma omitido, establece frame->dfbit y redondea hacia arriba la tasa de fotogramas).
standard el estándar de TV a usar para la asignación del bit de paridad si se establece en 1, se habilita el estándar de 25 fps y se utiliza el bit 59 del fotograma LTC en lugar del 27 para la paridad. Solo tiene efecto si el bit 4 (LTC_NO_PARITY) está despejado.
flags combinación binaria de LTC_BG_FLAGS - aquí solo LTC_USE_DATE y LTC_NO_PARITY son relevantes. si el bit 0 está establecido (1), interpreta los datos de usuario como fecha y decrementa la fecha si el código de tiempo se envuelve a las 24h. (Nota: se tienen en cuenta los años bisiestos, pero dado que el año tiene solo dos dígitos, se ignoran las reglas de los años 100 y 400. Se asume que '00' es el año 2000, que fue un año bisiesto). el bit 3 (8) indica que el bit de paridad no debe ser modificado

Devuelve

1 si el código de tiempo se envolvió en 23:59:59:ff, 0 de lo contrario

int ltc_frame_increment (LTCFrame * frame, int fps, enum LTC_TV_STANDARD standard, int flags)

Incrementa el código de tiempo en un fotograma (1/framerate segundos) y establece el bit de paridad del fotograma en consecuencia (ver ltc_frame_set_parity)

Parámetros

frame el código de tiempo LTC a incrementar
fps velocidad de fotogramas entera (para código de tiempo drop-frame, establezca frame->dfbit y redondee fps hacia arriba).
standard el estándar de TV a utilizar para la asignación del bit de paridad. Si se establece en 1, se habilita el estándar de 25 fps y se utiliza el bit 59 del fotograma LTC en lugar del bit 27 para la paridad. Solo tiene efecto si el bit 4 (LTC_NO_PARITY) está borrado.
flags combinación binaria de LTC_BG_FLAGS - aquí solo LTC_USE_DATE y LTC_NO_PARITY son relevantes. (Nota: se tienen en cuenta los años bisiestos, pero como el año es de dos dígitos solamente, se ignoran las reglas de los años 100 y 400. Se asume que '00' es el año 2000, que fue un año bisiesto).

Restablece todos los valores de un MARCO LTC a cero, excepto por la palabra de sincronización (0x3FFD) al final. La palabra de sincronización se establece según la arquitectura (big/little endian). También establece el bit de paridad del marco en consecuencia (ver ltc_frame_set_parity).

Parámetros

void ltc_frame_set_parity (LTCFrame * frame, enum LTC_TV_STANDARD standard)

Establece la paridad del marco LTC.

El bit de corrección de fase de Marca Bi-Fase (bit 27 - o 59) puede establecerse o borrarse para que cada palabra de 80 bits contenga un número par de ceros. Esto significa que la fase en cada Palabra de Sincronización será la misma.

Esto es meramente cosmético; la motivación para mantener la polaridad de la forma de onda constante es facilitar la búsqueda de la Palabra de Sincronización visualmente (en un osciloscopio).

Normalmente no hay necesidad de llamar a esta función directamente. Las funciones de utilidad del codificador ltc_time_to_frame, ltc_frame_increment y ltc_frame_decrement incluyen una llamada a ella.

Parámetros

frame el LTC a analizar y establecer o borrar el bit de corrección_de_fase_marca_bi.
standard Si es 1 (también conocido como LTC_TV_625_50), se utiliza el modo de 25 fps (bit 59 - también conocido como binary_group_flag_bit2), de lo contrario, se establece o borra el modo de 30 fps, 24 fps (bit 27 -- biphase_mark_phase_correction).
