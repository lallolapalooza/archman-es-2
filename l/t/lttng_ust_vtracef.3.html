Paquete: lttng-ust

LTTNG_UST_TRACEF(3) Manual de LTTng LTTNG_UST_TRACEF(3)

NOMBRE

lttng_ust_tracef, lttng_ust_vtracef - Interfaz tipo printf(3) de LTTng-UST

SINOPSIS

#include <lttng/tracef.h>
#define lttng_ust_tracef(fmt, ...)
#define lttng_ust_vtracef(fmt, ap)

Enlazar con:

•-llttng-ust
•Si define _LGPL_SOURCE antes de incluir <lttng/tracef.h> (directa o indirectamente): -llttng-ust-common

DESCRIPCIÓN

La API de LTTng-UST lttng_ust_tracef() y lttng_ust_vtracef() le permite rastrear su aplicación con la ayuda de macros simples similares a printf(3) y vprintf(3).

El argumento fmt se pasa directamente como el parámetro fmt de vasprintf(3), así como:

Para lttng_ust_tracef()

Los parámetros opcionales que siguen a fmt.

Para lttng_ust_vtracef()

El parámetro ap como el parámetro ap de vasprintf(3) (tipo va_list).

Para usar lttng_ust_tracef() o lttng_ust_vtracef(), incluya <lttng/tracef.h> donde lo necesite, y enlace su aplicación con liblttng-ust y liblttng-ust-common. Consulte la sección EJEMPLO más abajo para ver un ejemplo de uso completo.

Una vez que su aplicación esté instrumentada con llamadas lttng_ust_tracef() y/o lttng_ust_vtracef() y lista para ejecutarse, use lttng-enable-event(1) para habilitar el evento lttng_ust_tracef:*.

Los eventos lttng_ust_tracef() y lttng_ust_vtracef() contienen un único campo, llamado msg, que es la cadena formateada de salida.

Si necesita adjuntar un nivel de registro específico a una llamada lttng_ust_tracef()/lttng_ust_vtracef(), use lttng_ust_tracelog(3) y lttng_ust_vtracelog(3) en su lugar.

Vea también la sección LIMITACIONES más abajo para conocer las limitaciones importantes a considerar al usar lttng_ust_tracef() o lttng_ust_vtracef().

EJEMPLO

Aquí hay un ejemplo de uso de lttng_ust_tracef():

#include <stdlib.h>
#include <lttng/tracef.h>
int main(void)
{
    int i;
    for (i = 0; i < 25; i++) {
        lttng_ust_tracef("mi mensaje: %s, este entero: %d",
                         "un mensaje", i);
    }
    return EXIT_SUCCESS;
}

Este archivo fuente C, guardado como app.c, se puede compilar en un programa de la siguiente manera:

$ cc -o app app.c -llttng-ust -llttng-ust-common

Puede crear una sesión de rastreo LTTng, habilitar los eventos lttng_ust_tracef() y iniciar la sesión de rastreo creada de esta manera:

$ lttng create my-session
$ lttng enable-event --userspace 'lttng_ust_tracef:*'
$ lttng start

A continuación, inicie el programa que se rastreará:

$ ./app

Finalmente, detenga la sesión de rastreo e inspeccione los eventos grabados:

$ lttng stop
$ lttng view

LIMITACIONES

Las macros de utilidad lttng_ust_tracef() y lttng_ust_vtracef() se desarrollaron para hacer que el rastreo del espacio de usuario sea muy simple, aunque con desventajas notables en comparación con los proveedores de puntos de traza personalizados y completos:

•Todos los eventos generados tienen los mismos nombres de proveedor/evento.
•No hay verificación de tipos estática.
•El único campo de evento con datos de usuario que realmente obtiene, llamado msg, es una cadena que potencialmente contiene los valores que pasó a la macro usando su propio formato. Esto también significa que no puede usar el filtrado con una expresión personalizada en tiempo de ejecución porque no hay campos aislados.
•Dado que lttng_ust_tracef() y lttng_ust_vtracef() usan la función vasprintf(3) de la biblioteca estándar de C en segundo plano para formatear las cadenas en tiempo de ejecución, su rendimiento esperado es menor que el uso de proveedores de puntos de traza personalizados con campos tipados, que no requieren una conversión a cadena.
•En general, una cadena que contiene la representación textual de los campos de datos de usuario no es tan compacta como los campos binarios en el rastreo resultante.

Por lo tanto, lttng_ust_tracef()/lttng_ust_vtracef() son útiles para la creación rápida de prototipos y la depuración, pero no deben considerarse para ninguna instrumentación de aplicación permanente/seria.

lttng_ust_vtracef() no tiene una llamada STAP_PROBEV(), porque STAP_PROBEV() no soporta va_list. Si lo necesita, debería emitir esta llamada usted mismo.

Vea lttng-ust(3) para obtener más información sobre los proveedores de puntos de traza personalizados.
