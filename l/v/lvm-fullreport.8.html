NOMBRE

lvm fullreport — Muestra un informe completo

SINOPSIS

lvm fullreport
[ argumentos_opciones ]
[ argumentos_posicionales ]

DESCRIPCIÓN

lvm fullreport produce una salida formateada sobre PVs, segmentos de PV, VGs, LVs y segmentos de LV. La información se recopila junta para cada VG (bajo un bloqueo por VG) para que sea consistente. La información recopilada de llamadas separadas a vgs, pvs y lvs puede ser inconsistente si la información cambia entre comandos.

OPCIONES

--aligned
Usar con --separator para alinear las columnas de salida.
-a|--all
Mostrar información sobre LVs internos. Estos son componentes de LVs normales, como espejos, que no son accesibles de forma independiente, por ejemplo, no montables. Listar todos los VGs. Equivalente a no especificar ningún VG. Mostrar información sobre dispositivos que no han sido inicializados por LVM, es decir, no son PVs.
--binary
Usar valores binarios "0" o "1" en lugar de valores literales descriptivos para las columnas que tienen exactamente dos valores válidos para informar (sin contar el valor "desconocido" que denota que el valor no pudo ser determinado).
--commandprofile String
El perfil de comando a utilizar para la configuración del comando. Ver lvm.conf(5) para más información sobre perfiles.
--config String
Configuración del comando. Estas anulan los ajustes de lvm.conf(5). El argumento String utiliza el mismo formato que lvm.conf(5), o puede usar la sintaxis de sección/campo. Ver lvm.conf(5) para más información sobre la configuración.
--configreport log|vg|lv|pv|pvseg|seg
Ver lvmreport(7).
-d|--debug ...
Establecer el nivel de depuración. Repetir de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción se puede repetir, o acepta una lista de dispositivos separada por comas. Esto anula el archivo de dispositivos.
--devicesfile String
Un archivo que lista los dispositivos que LVM debe usar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración de lvm.conf(5) devices/devicesfile y devices/use_devicesfile.
--driverloaded y|n
Si se establece en no, el comando no intentará usar el mapeador de dispositivos. Para pruebas y depuración.
--foreign
Informar/mostrar VGs extranjeros que de otro modo se omitirían. Ver lvmsystemid(7) para más información sobre VGs extranjeros.
--headings none|abbrev|full|0|1|2
Tipo de encabezados a utilizar en la salida del informe. none o 0: Sin encabezados. abbrev o 1: Abreviaturas de nombres de columna. full o 2: Nombres completos de columna.
-h|--help
Mostrar texto de ayuda.
--ignorelockingfailure
Permite que un comando continúe con operaciones de metadatos de solo lectura después de fallos de bloqueo.
--journal String
Registrar información en el journal de systemd. Esta información es adicional a la información habilitada por la configuración de registro/journal de lvm.conf. command: registrar información sobre el comando. output: registrar la salida predeterminada del comando. debug: registrar la depuración completa del comando.
--lockopt String
Se utiliza para pasar opciones para casos especiales a lvmlockd. Ver lvmlockd(8) para más información.
--logonly
Suprimir el informe del comando y mostrar solo el informe del registro.
--longhelp
Mostrar texto de ayuda largo.
--nameprefixes
Añadir un prefijo "LVM2_" junto con el nombre del campo a la salida. Útil con --noheadings para producir una lista de pares campo=valor que se pueden usar para establecer variables de entorno (por ejemplo, en reglas udev).
--noheadings
Suprimir la línea de encabezados que normalmente es la primera línea de salida. Útil si se busca la salida con grep.
--nohints
No utilizar el archivo de pistas para localizar dispositivos para PVs. Un comando puede leer más dispositivos para encontrar PVs cuando no se utilizan pistas. El comando aún realizará la invalidación estándar del archivo de pistas según corresponda.
--nolocking
Desactivar el bloqueo. Usar con precaución, comandos concurrentes pueden producir resultados incorrectos.
--nosuffix
Suprimir el sufijo en los tamaños de salida. Usar con --units (excepto h y H) si se procesa la salida.
-o|--options String
Lista de campos separados por comas y ordenados para mostrar en columnas. La sintaxis del argumento String es: [+|-|#]Campo1[,Campo2 ...] El prefijo + añadirá los campos especificados a los campos predeterminados, -

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

> eliminará los campos especificados de los campos predeterminados, y # compactará los campos especificados (eliminándolos cuando estén vacíos para todas las filas.) Usa -o help para ver la lista de todos los campos disponibles. Usa listas separadas de campos para agregar, eliminar o compactar repitiendo la opción -o: -o+campo1,campo2 -o-campo3,campo4 -o#campo5. Estas listas se evalúan de izquierda a derecha. Usa el nombre de campo lv_all para ver todos los campos de LV, vg_all todos los campos de VG, pv_all todos los campos de PV, seg_all todos los campos de segmento de LV, y pvseg_all todos los campos de segmento de PV. Consulta el informe lvm.conf(5) para ver más opciones de configuración. Consulta lvmreport(7) para más información sobre informes.
--profile Cadena
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
-q|--quiet ...
Suprimir la salida y los mensajes de registro. Anula --debug y --verbose. Repite una vez para suprimir también cualquier solicitud con la respuesta 'no'.
--readonly
Evitar que el comando realice cambios, incluyendo la activación y las actualizaciones de metadatos. (Ver --permission r para LVs de solo lectura.)
--reportformat basic|json|json_std
Anula el formato de salida actual para los informes, que se define globalmente mediante la configuración report/output_format en lvm.conf(5). basic es el formato original con columnas y filas. Si hay más de un informe por comando, cada informe va precedido del nombre del informe para su identificación. json produce la salida del informe en formato JSON. json_std produce la salida del informe en formato JSON que es más compatible con el estándar JSON. Consulta lvmreport(7) para más información.
--rows
Mostrar columnas como filas.
-S|--select Cadena
Seleccionar objetos para su procesamiento y generación de informes basándose en criterios especificados. La sintaxis del criterio se describe en --select help y lvmreport(7). Para los comandos de generación de informes, se muestra una fila por cada objeto que coincida con el criterio. Consulta --options help para ver los campos de objeto seleccionables. Las filas pueden mostrarse con un campo adicional "selected" (-o selected) que muestra 1 si la fila coincide con la selección y 0 en caso contrario. Para los comandos que no generan informes y procesan entidades LVM, la selección se utiliza para elegir los elementos a procesar.
--separator Cadena
Cadena a utilizar para separar cada columna. Útil si se busca la salida.
--shared
Informar/mostrar VGs compartidos que de otro modo se omitirían cuando no se utiliza lvmlockd en el host. Consulta lvmlockd(8) para más información sobre VGs compartidos.
-O|--sort Cadena
Lista ordenada separada por comas de las columnas por las que ordenar. Reemplaza la selección predeterminada. Antecede cualquier columna con - para una ordenación inversa en esa columna.
-t|--test
Ejecutar en modo de prueba. Los comandos no actualizarán los metadatos. Esto se implementa desactivando toda escritura de metadatos y, sin embargo, devolviendo éxito a la función de llamada. Esto puede dar lugar a mensajes de error inusuales en operaciones de varias etapas si una herramienta depende de leer metadatos que cree que han cambiado pero no lo han hecho.
--unbuffered
Producir la salida inmediatamente sin ordenar ni alinear las columnas correctamente.
--units [Número]r|R|h|H|b|B|s|S|k|K|m|M|g|G|t|T|p|P|e|E
Todos los tamaños se muestran en estas unidades: legible por humanos (r) con indicador de redondeo '<', legible (h) por humanos, (b)ytes, (s)ectores, (k)ilobytes, (m)egabytes, (g)igabytes, (t)erabytes, (p)etabytes, (e)xabytes. Poner en mayúscula para usar múltiplos de 1000 (S.I.) en lugar de 1024. Se pueden especificar unidades personalizadas, por ejemplo, --units 3M.
--unquoted
Cuando se usa con --nameprefixes, los valores de salida en los pares campo=valor no se citan.
-v|--verbose ...
Establecer el nivel de verbosidad. Repite de 1 a 4 veces para aumentar el detalle de los mensajes enviados a stdout y stderr.
--version
Mostrar información de la versión.
-y|--yes
No solicitar confirmación interactivamente, sino asumir siempre la respuesta sí. Usar con extrema precaución. (Para un no automático, ver -qq.)

VARIABLES

VG
Nombre del Grupo de Volumen. Consulta lvm(8) para ver nombres válidos.
Cadena
Consulta la descripción de la opción para obtener información sobre el contenido de la cadena.
Tamaño[UNIDAD]
El tamaño es un número de entrada que acepta una unidad opcional. Las unidades de entrada siempre se tratan como valores base dos, independientemente de la capitalización, por ejemplo, 'k' y 'K' se refieren a 1024. La unidad de entrada predeterminada se especifica por letra, seguida de |UNIDAD. UNIDAD representa otras unidades de entrada posibles: b|B son bytes, s|S son sectores de 512 bytes, k|K son KiB, m|M son MiB, g|G son GiB, t|T son TiB, p|P son PiB, e|E son EiB. (Esto no debe confundirse con el control de salida --units, donde las letras mayúsculas significan múltiplos de 1000.)

VARIABLES DE ENTORNO

Consulta lvm(8) para obtener información sobre las variables de entorno utilizadas por lvm. Por ejemplo, LVM_VG_NAME puede sustituirse generalmente por un parámetro de VG requerido.
