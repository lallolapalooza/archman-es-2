NOMBRE

lvs — Muestra información sobre volúmenes lógicos

SINOPSIS

lvs
[ argumentos_opcionales ]
[ argumentos_posicionales ]

DESCRIPCIÓN

lvs produce una salida formateada sobre los LVs.

USO

lvs

OPCIONES

--aligned
Usar con --separator para alinear las columnas de salida.
-a|--all
Muestra información sobre LVs internos. Estos son componentes de LVs normales, como los espejos, que no son accesibles independientemente, p.ej. no montables.
--binary
Usa valores binarios "0" o "1" en lugar de valores literales descriptivos para las columnas que tienen exactamente dos valores válidos para reportar (sin contar el valor "unknown" que denota que el valor no pudo ser determinado).
--commandprofile Cadena
El perfil de comando a usar para la configuración del comando. Ver lvm.conf(5) para más información sobre perfiles.
--config Cadena
Configuraciones para el comando. Estas anulan la configuración de lvm.conf(5). El argumento Cadena usa el mismo formato que lvm.conf(5), o puede usar sintaxis de sección/campo. Ver lvm.conf(5) para más información sobre la configuración.
--configreport log|vg|lv|pv|pvseg|seg
Ver lvmreport(7).
-d|--debug ...
Establece el nivel de depuración. Repite de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción puede repetirse, o aceptar una lista de dispositivos separada por comas. Esto anula el archivo de dispositivos.
--devicesfile Cadena
Un archivo que lista los dispositivos que LVM debe usar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración devices/devicesfile y devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si se establece en no, el comando no intentará usar device-mapper. Para pruebas y depuración.
--foreign
Reporta/muestra VGs extranjeros que de otro modo serían omitidos. Ver lvmsystemid(7) para más información sobre VGs extranjeros.
--headings none|abbrev|full|0|1|2
Tipo de encabezados a usar en la salida del informe. none o 0: Sin encabezados. abbrev o 1: Abreviaturas de nombres de columna. full o 2: Nombres completos de columna.
-h|--help
Muestra el texto de ayuda.
-H|--history
Incluye LVs históricos en la salida. (Esto no tiene efecto a menos que los LVs fueran eliminados mientras lvm.conf(5) metadata/record_lvs_history estaba habilitado.
--ignorelockingfailure
Permite que un comando continúe con operaciones de metadatos de solo lectura después de fallos de bloqueo.
--journal Cadena
Registra información en el journal de systemd. Esta información es adicional a la información habilitada por la configuración de registro/journal de lvm.conf. command: registra información sobre el comando. output: registra la salida predeterminada del comando. debug: registra la depuración completa del comando.
--lockopt Cadena
Se utiliza para pasar opciones para casos especiales a lvmlockd. Ver lvmlockd(8) para más información.
--logonly
Suprime el informe del comando y muestra solo el informe de registro.
--longhelp
Muestra el texto de ayuda largo.
--nameprefixes
Agrega un prefijo "LVM2_" más el nombre del campo a la salida. Útil con --noheadings para producir una lista de pares campo=valor que pueden ser usados para establecer variables de entorno (por ejemplo, en reglas udev).
--noheadings
Suprime la línea de encabezados que normalmente es la primera línea de salida. Útil si se busca en la salida.
--nohints
No usar el archivo hints para localizar dispositivos para PVs. Un comando puede leer más dispositivos para encontrar PVs cuando no se usan hints. El comando aún realizará la invalidación estándar del archivo hints cuando sea apropiado.
--nolocking
Deshabilita el bloqueo. Usar con precaución, comandos concurrentes pueden producir resultados incorrectos.
--nosuffix
Suprime el sufijo en los tamaños de salida. Usar con --units (excepto h y H) si se procesa la salida.
-o|--options Cadena
Lista ordenada y separada por comas de campos a mostrar en columnas. La sintaxis del argumento Cadena es: [+|-|#]Campo1[,Campo2 ...] El prefijo + agregará los campos especificados a los campos predeterminados, - eliminará los campos especificados de los campos predeterminados, y # compactará los campos especificados (eliminando t

OPCIONES

-o|--options Fields
Especifica los campos que se incluirán en el informe. Los campos se especifican como una lista separada por comas. Use -o help para ver la lista de todos los campos disponibles. Use listas separadas de campos para agregar, eliminar o compactar repitiendo la opción -o: -o+campo1,campo2 -o-campo3,campo4 -o#campo5. Estas listas se evalúan de izquierda a derecha. Use el nombre del campo lv_all para ver todos los campos de LV, vg_all todos los campos de VG, pv_all todos los campos de PV, seg_all todos los campos de segmento de LV y pvseg_all todos los campos de segmento de PV. Consulte el informe lvm.conf(5) para ver más opciones de configuración. Consulte lvmreport(7) para obtener más información sobre los informes.
--profile String
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
-q|--quiet ...
Suprime la salida y los mensajes de registro. Anula --debug y --verbose. Repita una vez para suprimir también cualquier solicitud con la respuesta 'no'.
--readonly
Evita que el comando realice cambios, incluida la activación y las actualizaciones de metadatos. (Consulte --permission r para LVs de solo lectura).
--reportformat basic|json|json_std
Anula el formato de salida actual para los informes, que se define globalmente mediante la configuración report/output_format en lvm.conf(5). basic es el formato original con columnas y filas. Si hay más de un informe por comando, cada informe va precedido del nombre del informe para su identificación. json produce la salida del informe en formato JSON. json_std produce la salida del informe en formato JSON que es más compatible con el estándar JSON. Consulte lvmreport(7) para obtener más información.
--rows
Muestra las columnas como filas.
--segments
Utiliza columnas predeterminadas que enfatizan la información del segmento.
-S|--select String
Selecciona objetos para procesamiento e informes basándose en criterios especificados. La sintaxis de los criterios se describe en --select help y lvmreport(7). Para los comandos de informes, se muestra una fila por cada objeto que coincida con los criterios. Consulte --options help para ver los campos de objetos seleccionables. Las filas se pueden mostrar con un campo adicional "selected" (-o selected) que muestra 1 si la fila coincide con la selección y 0 en caso contrario. Para los comandos que no son de informes y que procesan entidades LVM, la selección se utiliza para elegir los elementos a procesar.
--separator String
Cadena a utilizar para separar cada columna. Útil si se utiliza grep en la salida.
--shared
Informa/muestra VGs compartidos que de otro modo se omitirían cuando no se está utilizando lvmlockd en el host. Consulte lvmlockd(8) para obtener más información sobre VGs compartidos.
-O|--sort String
Lista ordenada separada por comas de las columnas por las que ordenar. Reemplaza la selección predeterminada. Anteponga un "-" a cualquier columna para ordenar en orden inverso en esa columna.
-t|--test
Ejecutar en modo de prueba. Los comandos no actualizarán los metadatos. Esto se implementa deshabilitando toda escritura de metadatos pero devolviendo éxito a la función de llamada. Esto puede generar mensajes de error inusuales en operaciones de varias etapas si una herramienta depende de leer metadatos que cree que han cambiado pero no lo han hecho.
--unbuffered
Produce la salida inmediatamente sin ordenar ni alinear correctamente las columnas.
--units [Number]r|R|h|H|b|B|s|S|k|K|m|M|g|G|t|T|p|P|e|E
Todos los tamaños se muestran en estas unidades: legible por humanos (r) con indicador de redondeo '<', legible por humanos (h), bytes (b), sectores (s), kilobytes (k), megabytes (m), gigabytes (g), terabytes (t), petabytes (p), exabytes (e). Ponga en mayúscula para usar múltiplos de 1000 (S.I.) en lugar de 1024. Se pueden especificar unidades personalizadas, por ejemplo, --units 3M.
--unquoted
Cuando se usa con --nameprefixes, los valores de salida en los pares campo=valor no se citan.
-v|--verbose ...
Establece el nivel de verbosidad. Repita de 1 a 4 veces para aumentar el detalle de los mensajes enviados a stdout y stderr.
--version
Muestra la información de la versión.
-y|--yes
No solicitar confirmación interactivamente, sino asumir siempre la respuesta sí. Úselo con extrema precaución. (Para un no automático, consulte -qq).

VARIABLES

VG
Nombre del Grupo de Volúmenes. Consulte lvm(8) para ver los nombres válidos.
LV
Nombre del Volumen Lógico. Consulte lvm(8) para ver los nombres válidos. Un argumento posicional LV generalmente incluye el nombre del VG y el nombre del LV, por ejemplo, VG/LV.
Tag
Nombre de la etiqueta. Consulte lvm(8) para obtener información sobre los nombres de etiquetas y el uso de etiquetas en lugar de un VG, LV o PV.
String
Consulte la descripción de la opción para obtener información sobre el contenido de la cadena.
Size[UNIT]
Tamaño es un número de entrada que acepta una unidad opcional. Las unidades de entrada siempre se tratan como valores base dos, independientemente de la capitalización, por ejemplo, 'k' y 'K' se refieren a 1024. La unidad de entrada predeterminada se especifica con una letra, seguida de |UNIT. UNIT representa otras unidades de entrada posibles: b|B es bytes, s|S es sectores de 512 bytes, k|K es KiB, m|M es MiB, g|G es GiB, t|T es TiB, p|P es PiB, e|E es EiB. (Esto no debe confundirse con el control de salida --units, donde las letras mayúsculas significan múltiplos de 1000).

VARIABLES DE ENTORNO

Consulte lvm(8) para obtener información sobre las variables de entorno utilizadas por lvm. Por ejemplo, LVM_VG_NAME generalmente puede sustituirse por un parámetro VG requerido.

NOTAS

Los bits de lv_attr son:

1
Tipo de volumen: (C)aché, (m)irrored, (M)irrored sin sincronización inicial, (o)rigin, (O)rigin con instantánea combinada, (g) integridad, (r)aid, (R)aid sin sincronización inicial, (s)napshot, (S)napshot combinada, (p)pvmove, (v)irtual, imagen de espejo o raid (i), imagen de espejo o raid (I) fuera de sincronización, dispositivo de registro de espejo (l), en (c)onversión, Volumen delgado (V), pool delgado (t), datos de pool delgado (T), pool vdo (d), datos de pool vdo (D), metadatos de raid o pool o repuesto de metadatos de pool.
2
Permisos: (w)ritable, (r)olo de solo lectura, activación de solo lectura (R) de volumen no de solo lectura.
3
Política de asignación: (a)nywhere, (c)ontiguous, (i)nherited, c(l)ing, (n)ormal. Esto está en mayúscula si el volumen está actualmente bloqueado contra cambios de asignación, por ejemplo, durante pvmove(8).
4
Menor (m)inúsculo fijo.
5
Estado: (a)ctivo, (h)istórico, (s)uspendido, instantánea (I)nválida, instantánea suspendida inválida (S), falla de fusión de instantánea (m), falla de fusión de instantánea suspendida (M), dispositivo mapeado ( d)ispositivo presente sin tablas, dispositivo mapeado presente con tabla inactiva (i), pool delgado (c)heck necesario, pool delgado suspendido (C)heck necesario, (X) desconocido.
6
dispositivo (o)pen, (X) desconocido.
7
Tipo de destino: (C)aché, (m)irror, (r)aid, (s)napshot, (t)hin, (u)nknown, (v)irtual. Esto agrupa volúmenes lógicos relacionados con el mismo destino del kernel. Por ejemplo, las imágenes de espejo, los registros de espejo, así como los propios espejos aparecen como (m) si utilizan el controlador del kernel de espejo device-mapper original; mientras que los equivalentes de raid que utilizan el controlador del kernel de raid md aparecen todos como (r). Las instantáneas que utilizan el controlador original device-mapper aparecen como (s); mientras que las instantáneas de volúmenes delgados que utilizan el nuevo controlador de aprovisionamiento delgado aparecen como (t).
8
Los bloques de datos recién asignados se sobrescriben con bloques de (z)eros antes de su uso.
9
Estado de Salud del Volumen, donde actualmente hay tres grupos de atributos identificados:
Comunes para todos los Volúmenes Lógicos: (p)arcial, (X) desconocido. (p)arcial significa que uno o más de los Volúmenes Físicos que utiliza este Volumen Lógico faltan en el sistema. (X) desconocido significa que el estado es desconocido.
Relacionado con Volúmenes Lógicos RAID: (r)efresh necesario, (m)ismatches existen, (w)ritemostly. (r)efresh significa que uno o más de los Volúmenes Físicos que utiliza este Volumen Lógico RAID han sufrido un error de escritura. El error de escritura puede deberse a una falla temporal de ese Volumen Físico o a una indicación de que está fallando. El dispositivo debe actualizarse o reemplazarse. (m)ismatches significa que el volumen lógico RAID tiene partes de la matriz que no son coherentes. Las inconsistencias se detectan iniciando un "chequeo" en un volumen lógico RAID. (Las operaciones de scrubbing, "chequeo" y "reparación", se pueden realizar en un volumen lógico RAID a través del comando 'lvchange'.) (w)ritemostly significa que los dispositivos en un volumen lógico RAID 1 han sido marcados como write-mostly. (s)haping de Re significa que un Volumen Lógico RAID está actualmente sufriendo la adición/eliminación de una franja, o un cambio en el tamaño de la franja o el algoritmo RAID. (R)emove después del reshape significa que las imágenes de raid rayadas liberadas deben ser eliminadas.
Relacionado con Volúmenes Lógicos de pool delgado: (
F)allido, sin espacio de (D)atos, metadatos en modo de solo lectura (M).
(F)allido se activa si el pool delgado encuentra fallos graves y, por lo tanto, no se permite E/S adicional. Sin espacio de (D)atos se activa si el pool delgado se ha quedado sin espacio de datos. Metadatos en modo de solo lectura (M) indica que el pool delgado encuentra ciertos tipos de fallos, pero aún es posible realizar lecturas al menos, aunque no se permiten cambios en los metadatos.
Relacionado con Volúmenes Lógicos Delgados: (F)allido.
(F)allido se activa cuando el pool delgado relacionado entra en estado de Fallido y no se permite ninguna E/S adicional.
Relacionado con volúmenes de caché de escritura: (E)rror.
(E)rror se activa cuando dm-writecache informa de un error.
10
s(k)ip activation (omitir activación): este volumen está marcado para ser omitido durante la activación.
