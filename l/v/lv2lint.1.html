LV2LINT(1) Manual de comandos generales LV2LINT(1)

NOMBRE

lv2lint - un verificador de LV2 (lintian)

SINOPSIS

lv2lint [OPCIONES] {URI_DEL_PLUGIN}*

DESCRIPCIÓN

lv2lint comprueba si los plugins LV2 dados cumplen con la especificación.

No solo comprueba los archivos *.ttl, sino que realmente carga los plugins (y sus interfaces de usuario) y verifica si las características requeridas y las extensiones expuestas coinciden entre el binario y el *.ttl.

Por lo tanto, encuentra errores que no se pueden encontrar fácilmente simplemente verificando la validez del *.ttl.

Es una buena práctica ejecutarlo sobre tus plugins como parte de tu integración continua después de verificarlos con sord_validate y antes de publicarlos.

OPCIONES

-v

Muestra información de versión y licencia.

-h

Muestra información de uso.

-q

Modo silencioso, solo muestra un resumen.

-d

Muestra documentación detallada de los elementos de prueba.

-o

Ejecuta elementos de prueba en línea.

-m

Crea un correo para el autor del plugin.

-g GREETER

Saludo personalizado para el correo.

-s PATRÓN_SÍMBOLO

Patrón de símbolo (comodín de shell) para incluir en la lista blanca (se puede usar varias veces).

-l PATRÓN_BIBLIOTECA

Patrón de biblioteca (comodín de shell) para incluir en la lista blanca (se puede usar varias veces).

-u PATRÓN_URI

Patrón de URI (comodines de shell) que se antepondrá a los patrones de lista blanca de pruebas, símbolos y bibliotecas (se puede usar varias veces). El patrón de lista blanca de este último solo será efectivo cuando también coincida el patrón de URI actual (por ejemplo, para el propio plugin o una de sus interfaces de usuario).

-t PATRÓN_PRUEBA

Patrón de nombre de prueba (comodín de shell) para incluir en la lista blanca (se puede usar varias veces).

-I DIRECTORIO_INCLUSION

Además de las rutas de instalación predeterminadas de plugins LV2, usa el directorio de inclusión para buscar plugins (se puede usar varias veces).

-M (no)pack (Por defecto: pack)

Modos a habilitar/deshabilitar, por ejemplo, el modo (pack)ager omite algunas pruebas fatales para los empaquetadores de distribución que solo son importantes para binarios distribuidos libremente.

Si eres un empaquetador de distribución, prefiere ejecutar con '-M pack' (por defecto). Si deseas compilar binarios para distribución, prefiere ejecutar con -M nopack.

-S (no)warn|note|pass|all (Por defecto: fail|warn)

Además de solo errores (fail), también muestra advertencias (warn), notas (note), pases (pass) o todo (all) en la consola. El prefijo no- invierte el significado.

-E (no)warn|note|all (Por defecto: fail)

Además de solo errores (fail), también trata las advertencias (warn), notas (note) o todo (all) como errores. El prefijo no- invierte el significado.
