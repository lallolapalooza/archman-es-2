NOMBRE

lvmpersist - gestiona reservas persistentes en un grupo de dispositivos de bloque

DESCRIPCIÓN

Las reservas persistentes (PR) proporcionan un mecanismo para controlar el acceso a dispositivos de almacenamiento compartidos, típicamente para proteger los dispositivos de ser modificados por hosts que no deberían escribir en los dispositivos compartidos. Esto es usualmente una preocupación en entornos SAN o agrupados, donde múltiples hosts tienen acceso a los mismos dispositivos de almacenamiento.

Si un Grupo de Volúmenes LVM (VG) contiene dispositivos capaces de PR, entonces los comandos LVM pueden ser utilizados para gestionar PR a nivel del VG, aplicando PR a cada Volumen Físico (PV) en el VG. (Todos los PV en el VG deben soportar PR.)

lvmpersist es una utilidad de bajo nivel utilizada para realizar operaciones de PR en dispositivos de bloque individuales. LVM también proporciona una interfaz de gestión de PR de nivel superior a través de una interfaz de comandos LVM estándar:
vgchange --setpersist, vgchange --persist

lvmpersist es un script que no implementa las opciones o capacidades comunes de la línea de comandos de LVM. El script utiliza los comandos sg_persist, mpathpersist y nvme para realizar operaciones de PR en dispositivos de bloque. Los comandos LVM de nivel superior (ej. vgchange) ejecutan el script lvmpersist.

Tipos de dispositivos

Se admiten dispositivos SCSI o similares a SCSI (ej. iSCSI, SAS, Fibre Channel), dm-multipath y NVME. Las PR se introdujeron con el estándar SCSI Primary Commands Version 3 (SPC-3).

Cuando se utilizan dispositivos multipath, multipath.conf debe estar configurado con "reservation_key file". (Ejecute mpathconf --option reservation_key:file, y reinicie multipathd.)

Tipos de reserva persistente

LVM utiliza el tipo PR "Write Exclusive" (WE) para dispositivos en un VG local, y "Write Exclusive - all registrants" (WEAR) para dispositivos en un VG compartido. Una excepción son los dispositivos dm-multipath, para los cuales se utiliza WEAR tanto en VGs locales como compartidos (esto es necesario para que todas las rutas permanezcan utilizables).

El comando lvmpersist tiene dos opciones para especificar el tipo de PR:

--access ex|sh

Establecer el acceso a "ex" (exclusivo) si los dispositivos solo deben ser accedidos por un host (es decir, los dispositivos forman parte de un VG local). Establecer el acceso a "sh" (compartido) si los dispositivos están destinados a ser accedidos concurrentemente por múltiples hosts (es decir, los dispositivos forman parte de un VG compartido). lvmpersist elegirá el tipo de PR apropiado para cada dispositivo (generalmente WE para "ex", y WEAR para "sh").
--prtype TIPO_PR
Cuando se especifica un valor TIPO_PR, lvmpersist solo usará ese tipo para todos los dispositivos.

Tipos de PR y las abreviaturas utilizadas en interfaces/mensajes:

WE Write Exclusive
EA Exclusive Access
WERO Write Exclusive - registrants only
EARO Exclusive Access - registrants only
WEAR Write Exclusive - all registrants
EAAR Exclusive Access - all registrants

(Los tipos WERO y EARO aún no son compatibles.)

Claves de reserva persistente

Las claves PR pueden tener hasta 8 bytes de longitud, y se representan con hasta 16 caracteres hexadecimales con un prefijo "0x". No se permiten ceros a la izquierda, por ejemplo, use 0x1234abcd, no 0x000000001234abcd. Se acepta un valor de clave decimal (sin prefijo 0x) como entrada, pero aparecerá como hexadecimal en la salida.

Cada host que utiliza dispositivos compartidos debe utilizar una clave PR única.

Las claves PR deben configurarse en cada host en /etc/lvm/lvmlocal.conf (ver Configuración Local abajo.)

USO

El conjunto básico de comandos y opciones para gestionar PR:

Utilidad de PR a nivel de dispositivo:
lvmpersist start|stop|remove|clear|read [OPCIONES] DEST

Configuración de PR de VG:
vgchange --setpersist y|n VG

Operaciones de PR de VG:
vgchange --persist start|stop|remove|clear|read|check VG

comandos lvmpersist

lvmpersist start --ourkey CLAVE DEST

"start" registra la clave local y reserva dispositivos. Si una clave diferente del mismo host todavía está registrada, será reemplazada por la clave especificada. Cuando --access o --prtype no se especifican, se utiliza el acceso "ex".

lvmpersist stop --ourkey CLAVE DEST

"stop" anula el registro de la clave local, lo que también elimina una reserva local.

lvmpersist remove --ourkey CLAVE --removekey CLAVE_A_ELIMINAR DEST

"remove" elimina la clave de otro host registrado. El host con la clave eliminada pierde la capacidad de escribir en los dispositivos. (Este comando se aplica a VGs compartidos, donde múltiples hosts se inician a la vez.)

lvmpersist start --ourkey CLAVE --removekey CLAVE_A_ELIMINAR DEST

"start" con removekey registra la clave local y toma la reserva de otro host (usando preempt-abort). El otro host pierde la capacidad de escribir en los dispositivos. (Este comando se aplica a VGs locales, para los cuales un solo host puede iniciarse a la vez.)

lvmpersist clear --ourkey CLAVE DEST

"clear" elimina todas las claves y reservas de los dispositivos.

lvmpersist devtest|read|read-keys|read-reservation DEST

Estos comandos se utilizan para probar si los dispositivos soportan PR, y para mostrar las claves y reservas PR actuales.

lvmpersist check-key --key CLAVE DEST

Verifica si una clave especificada está registrada.

OPCIONES:

--ourkey CLAVE

La clave PR local, por ejemplo, 0x123abc
--removekey CLAVE_A_ELIMINAR

La clave de otro host.
--key CLAVE

Cualquier clave para verificar.
--access ex|sh

Usar un tipo PR para acceso exclusivo o compartido al dispositivo.
--prtype TIPO_PR

Usar el tipo de reserva especificado (alternativa a --access).
--ptpl

Habilitar persistencia a través de pérdida de energía durante el inicio (registro).

DEST:

--device RUTA ...

Uno o más dispositivos sobre los que operar.
--vg NOMBRE_VG

Un VG sobre el que operar (todos los PV en el VG.)
--vg NOMBRE_VG --device RUTA ...

Uno o más dispositivos sobre los que operar, y un nombre de VG para usar como identificador para el conjunto de dispositivos.

lvmpersist requiere ya sea los nombres de dispositivos específicos, cada uno especificado como --device /dev/nombre, o el nombre de un VG, especificado con --vg NOMBRE_VG. Cuando se especifica un VG, sin dispositivos de bloque individuales, lvmpersist ejecuta comandos PR en cada PV del VG. Cuando se especifican dispositivos, y también se proporciona un VG con --vg, entonces el nombre del VG simplemente se usa en los mensajes de registro para identificar el conjunto de dispositivos en su totalidad. Cuando lvmpersist es ejecutado por comandos LVM de nivel superior, cada dispositivo se especifica con --device, y el nombre del VG se especifica con --vg.

comandos de metadatos del VG

vgchange --setpersist se utiliza para configurar la automatización y la aplicación de PR en relación con el uso más amplio del VG

. La configuración se almacena en la metadata del VG.

vgchange --setpersist y|n VG

Habilita o deshabilita la automatización y la aplicación por defecto de PR para el VG, estableciendo o borrando ambas configuraciones de PR "autostart" y "require" (y potencialmente otras configuraciones futuras).

vgchange --setpersist autostart|noautostart|require|norequire VG

Establece o borra individualmente las configuraciones de autostart y require.

Cuando se establece "autostart", los comandos de autoactivación y auto-lockstart (vgchange -aay, vgchange --lockstart --lockopt auto) iniciarán primero PR en el VG. Si el inicio de PR falla, estos comandos se detendrán y no intentarán la activación o el lockstart.

Cuando se establece "require", los comandos de lvm que escriban o activen un VG requerirán que PR se inicie antes de intentar escribir o activar.

vgs -o persist VG

Muestra la configuración.

Comandos VG PR

vgchange --persist se utiliza para realizar operaciones PR en los dispositivos del VG.

vgchange --persist start VG

Inicia PR en los dispositivos del VG. Registra la clave local y adquiere una reserva.

vgchange --persist stop VG

Detiene PR en los dispositivos del VG. Anula el registro de la clave local, lo que libera una reserva si la tiene la clave.

vgchange --persist remove --removekey remkey VG

Elimina la clave PR de otro host de los dispositivos de un VG compartido, deshabilitando inmediatamente la capacidad del otro host para escribir en los dispositivos. (Este comando se aplica a VGs compartidos, para los cuales varios hosts se inician a la vez).

vgchange --persist start --removekey remkey VG

Inicia PR en los dispositivos del VG, y al mismo tiempo elimina la clave y la reserva de otro host de los dispositivos del VG, deshabilitando la capacidad del otro host para escribir en los dispositivos. (Este comando se aplica a VGs locales, para los cuales un solo host puede iniciarse a la vez).

vgchange --persist check VG

Comprueba si PR está iniciado (la clave local y la reserva existen en todos los dispositivos). El comando finaliza con éxito si PR está iniciado en todos los dispositivos del VG.

vgchange --persist read VG

Muestra los registros y reservas PR en cada uno de los dispositivos del VG.

vgchange --persist clear VG

Borra todas las claves y reservas PR en los dispositivos del VG.

vgchange --persist autostart VG

Inicia PR en los dispositivos del VG si autostart está configurado. Esto está pensado para ser utilizado por la automatización del sistema, como la autoactivación y el auto-lockstart.

Inicio suplementario de PR

La opción --persist start se puede agregar a otros comandos para que estos intenten iniciar PR primero (independientemente de la configuración de autostart).

vgchange -ay --persist start
vgchange -aay --persist start
vgchange --lockstart --persist start
vgchange --setpersist y|require|autostart --persist start
vgimport --persist start
vgchange --systemid <local_id> --persist start

Uso de VG local

Al utilizar un VG local, solo un host se inicia a la vez, y normalmente se mantiene una reserva WE (Write Exclusive) en los dispositivos.

El uso de PR con VGs locales protege los dispositivos del VG de ser escritos por error por otro host con acceso a los mismos dispositivos. Es complementario al uso del ID de sistema del VG para controlar el propietario previsto de un VG, pero agrega protección reforzada a nivel de dispositivo, en caso de que otro host no utilice la función de ID de sistema de LVM.

Si un host desea tomar posesión forzosamente de un VG local que está actualmente en uso por otro host, puede usar vgchange --persist start --removekey remkey VG, donde "remkey" es la clave PR del host actualmente iniciado.

Uso de VG compartido

Al utilizar un VG compartido, todos los hosts que utilizan el VG se inician, y se mantiene una reserva WEAR (Write Exclusive - all registrants) en los dispositivos.

PR debe iniciarse antes de que se inicie el bloqueo (vgchange --persist start seguido de vgchange --lockstart, o un combinado vgchange --persist start --lockstart).

Si un host desea impedir forzosamente que otro host escriba en los dispositivos del VG compartido, puede usar vgchange --persist remove --removekey remkey, donde "remkey" es la clave PR del otro host.

Configuraciones locales

Cada host que utiliza PR debe tener una clave PR que sea única entre todos los hosts que utilizan el mismo VG. Hay dos enfoques para establecer un valor de clave, que se configuran en /etc/lvm/lvmlocal.conf:

local/pr_key

El valor establecido en pr_key se utilizará directamente. Es una cadena hexadecimal de hasta 16 caracteres de longitud. pr_key no se utilizará para VGs compartidos de sanlock.

local/host_id

Para un VG compartido de sanlock, o si no se establece pr_key, se creará una clave utilizando host_id. Este es un entero decimal entre 1 y 2000.

Para un VG local, o un VG compartido de dlm, una clave que utiliza host_id tiene el formato:

0x100000000000XXXX donde XXXX son los dígitos hexadecimales del valor de host_id.

Para un VG compartido de sanlock, la clave se basa en host_id y un número de generación (tomado del lease de sanlock), y tiene el formato:

0x100000YYYYYYXXXX donde XXXX son los dígitos hexadecimales del valor de host_id, e YYYYYY son los dígitos hexadecimales del número de generación.

El número de generación de sanlock aumenta de valor cada vez que el host inicia el VG, por lo que un host utilizará una nueva clave cada vez que se inicie. En algunos casos, PR puede iniciarse con una clave que incluye el número de generación incorrecto, en cuyo caso el comando lockstart actualizará la clave con el valor correcto (la generación se determina oficialmente durante el lockstart).

vgcreate

Las funciones PR se pueden habilitar al crear un nuevo VG:

vgcreate --setpersist y VG PVs

Para VGs locales, se puede incluir --persist start para iniciar PR también en el nuevo VG.

La creación de nuevos VGs compartidos con --setpersist funciona de manera diferente. PR siempre se inicia para un nuevo VG compartido, incluso sin --persist start. Primero, se adquiere un PR exclusivo (normalmente modo WE) para los nuevos dispositivos del VG. Luego, se inicializan los dispositivos y se escribe la nueva metadata del VG. El PR exclusivo se elimina y se adquiere un PR compartido (normalmente modo WEAR) para el uso compartido normal del VG. Finalmente, se inicia el espacio de bloqueo del VG.

vgextend

Para VGs locales, vgextend inicia PR en los nuevos dispositivos antes de agregarlos al VG (la configuración require o autostart debe estar habilitada). Para VGs compartidos, el usuario debe usar lvmpersist para iniciar PR en los nuevos dispositivos, desde todos los hosts, antes de ejecutar vgextend. vgextend verifica que la reserva y las claves en los nuevos dispositivos coincidan con los dispositivos existentes.

vgremove

El comando vgremove detiene PR en los dispositivos del VG solo si las configuraciones "require" o "autostart" se han establecido utilizando vgchange --setpersist. Si PR se ha iniciado independientemente de cualquier configuración de setpersist, entonces vgremove no detendrá PR automáticamente en los dispositivos.

vgexport/vgimport

vgexport --persist stop detiene PR después de exportar el VG, y vgimport --persist start inicia PR antes de importar el VG. La escritura de la metadata del VG para la exportación ocurre antes de detener PR, y la escritura de la metadata del VG para la importación ocurre después de iniciar PR.

vgchange --systemid

PR se puede iniciar junto con la toma de posesión del ID de sistema de un VG, o PR se puede detener junto con la renuncia a la posesión del ID de sistema de un VG (ver lvmsystemid(7) para más información).

vgchange --systemid local_system_id --persist start VG

Este comando se utiliza para tomar posesión de un VG de propiedad externa. PR se inicia y, si tiene éxito, el ID del sistema del VG se establecerá al ID del sistema local. (Nota: el ID del sistema externo del VG debe incluirse en extra_system_ids locales para acceder a un VG externo.) Para eliminar forzosamente (preempt-abort) el PR en poder de otro host en el VG, se puede incluir --removekey remkey, donde remkey es la clave PR del titular actual de PR.

vgchange --systemid foreign_system_id --persist stop VG

Este comando se utiliza para renunciar a la posesión de un VG de propiedad local. El ID del sistema del VG se actualiza al nuevo valor y luego se detiene PR.

Persistir a través de pérdida de energía

Para habilitar el uso de "persistir a través de pérdida de energía", en el que el estado PR se conserva en un dispositivo si se reinicia, active la configuración ptpl:

vgchange --setpersist ptpl VG

La configuración PTPL se aplica durante el registro de claves (parte del inicio de PR), por lo que surtirá efecto para cada host en el próximo inicio. Se aplica a todos los PV en el VG, por lo que cada dispositivo debe soportar PTPL. La configuración PTPL no está habilitada por "--setpersist y".

Cualquiera de las siguientes opciones borrará la configuración PTPL:

vgchange --setpersist noptpl VG
vgchange --setpersist n VG
