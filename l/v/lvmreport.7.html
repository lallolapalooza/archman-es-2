NOMBRE

lvmreport — Informe de LVM y funciones relacionadas

DESCRIPCIÓN

LVM utiliza una única infraestructura de informes que establece estándares en la salida de los comandos de LVM y proporciona una amplia gama de configuraciones y opciones de línea de comandos para personalizar el informe y filtrar su salida.

USO

Categorización basada en la funcionalidad de informes

Basados en la funcionalidad, los comandos que utilizan la infraestructura de informes se dividen en dos grupos:

Comandos orientados a informes
Estos comandos informan sobre el estado actual de LVM y su función principal es mostrar esta información de manera concisa. Para hacer una distinción, llamaremos a este informe informe principal. El conjunto de comandos solo de informes incluye: pvs, vgs, lvs, pvdisplay, vgdisplay, lvdisplay, lvm devtypes, lvm fullreport. Para más información sobre el informe principal, consulte Especificaciones del informe principal.
Comandos orientados al procesamiento
Estos comandos son responsables de cambiar el estado de LVM y no contienen ningún informe principal como se identifica para los comandos orientados a informes, solo realizan algún tipo de procesamiento. El conjunto de comandos orientados al procesamiento incluye: pvcreate, vgcreate, lvcreate, pvchange, vgchange, lvchange, pvremove, vgremove, lvremove, pvresize, vgextend, vgreduce, lvextend, lvreduce, lvresize, lvrename, pvscan, vgscan, lvscan, pvmove, vgcfgbackup, vgck, vgconvert, vgexport, vgimport, vgmknodes.

Si está habilitado, el llamado informe de registro se muestra ya sea solo (para comandos orientados al procesamiento) o además del informe principal (para comandos orientados a informes). El informe de registro contiene un registro de operaciones, mensajes y el estado por objeto con identificación completa del objeto recopilada durante la ejecución del comando LVM. Consulte Especificaciones del informe de registro para obtener más información sobre este tipo de informe.

Términos

Al describir la funcionalidad y las características de los informes en este texto, utilizaremos los términos fila y columna. Por fila nos referimos a una serie de valores informados para una sola entidad (por ejemplo, un solo PV, VG o LV). Cada valor de la fila pertenece entonces a una columna de cierto tipo. Las columnas tienen encabezados de columna que son descripciones cortas para las columnas. Las columnas se referencian por nombres de columna. Tenga en cuenta que este texto también utiliza el término campo indistintamente con el término columna. La mayoría de las veces, el término columnas se abrevia como col en la configuración.

Especificaciones del reporte de registro

Puede habilitar el reporte de registro con la configuración log/report_command_log – esta funcionalidad está deshabilitada por defecto. El reporte de registro contiene un registro recopilado durante la ejecución del comando LVM y luego el registro se muestra como cualquier otro reporte conocido del reporte principal. Solo hay un subtipo de reporte de registro, como se muestra a continuación junto con la configuración relacionada para campos, ordenación y selección:

log
representa el reporte de registro
– log/command_log_cols
– log/command_log_sort
– log/command_log_selection

Siempre debe usar --configreport log junto con -o|--options, -O|--sort o -S|--selection para anular la configuración directamente en la línea de comandos para el reporte de registro. En comparación con el reporte principal, además de la configuración habitual para los campos del reporte y la ordenación, el reporte de registro también tiene una opción de configuración para la selección – report/command_log_selection. Esta configuración se proporciona por comodidad, por lo que no es necesario utilizar -S|--select en la línea de comandos cada vez que se ejecuta un comando LVM y necesitamos que se apliquen los mismos criterios de selección para el reporte de registro. Los criterios de selección por defecto utilizados para el reporte de registro son log/command_log_selection="!(log_type=status && message=success)". Esto significa que, por defecto, el reporte de registro no muestra mensajes de estado sobre operaciones exitosas y solo muestra filas con mensajes de tipo error, advertencia, impresión y mensajes sobre estados de fallo. Para ver el registro de comandos sin filtrar, utilice el valor "all" para la selección. Para más información, consulte el contenido del reporte de registro más abajo.

Cobertura del reporte de registro
Actualmente, al ejecutar comandos LVM directamente (no en el shell de LVM), el reporte de registro cubre la etapa de procesamiento del comando, que es el momento en que las entidades LVM se iteran y procesan una por una. No cubre la inicialización ni la finalización del comando. Si se emite algún mensaje fuera del rango de cobertura del reporte de registro, dicho mensaje va directamente a la salida, eludiendo el reporte de registro. Por defecto, esa es la salida estándar de error para mensajes de error y advertencia, y la salida estándar para mensajes comunes de tipo impresión.

Al ejecutar comandos LVM en el shell de LVM, el reporte de registro cubre toda la ejecución del comando LVM, incluyendo el procesamiento del comando, así como las etapas de inicialización y finalización. Por lo tanto, desde este punto de vista, la cobertura del reporte de registro es completa para los comandos LVM ejecutados. Tenga en cuenta que todavía hay algunos momentos en los que el shell de LVM necesita inicializarse antes de entrar en el bucle principal en el que ejecuta comandos LVM. Además, hay un momento en el que el shell de LVM necesita preparar adecuadamente el reporte de registro para el siguiente comando ejecutado en el shell y luego, después de la ejecución del comando, el shell necesita mostrar el reporte de registro para ese comando ejecutado recientemente. Si ocurre un fallo o cualquier otro mensaje durante este tiempo, LVM omitirá el reporte de registro y mostrará los mensajes directamente en la salida.

Por estas razones y para mayor completitud, no es posible depender totalmente del reporte de registro como el único indicador del estado del comando LVM y el único lugar donde se recopilan todos los mensajes emitidos durante la ejecución del comando LVM. Siempre debe verificar si el comando no ha fallado fuera del rango del reporte de registro comprobando también la salida no de reporte.

Para ayudar con esto, LVM puede separar la salida, que luego puede redirigir a cualquier descriptor de archivo personalizado que prepare antes de ejecutar un comando LVM o el shell de LVM, y luego hacer que LVM utilice estos descriptores de archivo para diferentes tipos de salida definiendo variables de entorno con números de descriptor de archivo. Consulte también la descripción de las variables de entorno LVM_OUT_FD, LVM_ERR_FD y LVM_REPORT_FD en la página del manual de lvm(8).

También tenga en cuenta que, por defecto, los reportes utilizan el mismo descriptor de archivo que los mensajes comunes de tipo impresión, que es la salida estándar. Si planea utilizar el reporte de registro en sus scripts o cualquier herramienta externa, debería utilizar LVM_OUT_FD, LVM_ERR_FD y LVM_REPORT_FD para separar todos los tipos de salida a diferentes descriptores de archivo. Por ejemplo, con bash, sería:

LVM_OUT_FD=3 LVM_ERR_FD=4 LVM_REPORT_FD=5 <comando lvm> 3>archivo_salida 4>archivo_error 5>archivo_reporte

Donde <comando lvm> es un comando LVM directo o el shell de LVM. Luego puede recopilar los tres tipos de salida en archivos específicos.

Selección

La selección se utiliza para un informe para mostrar solo las filas que coinciden con los criterios de selección. Todas las filas se muestran con el campo adicional seleccionado (-o selected) que muestra 1 si la fila coincide con la Selección y 0 en caso contrario. Los criterios de selección son un conjunto de sentencias combinadas por operadores lógicos y de agrupación. La sentencia consiste en un nombre de campo para el cual se define un conjunto de valores válidos utilizando operadores de comparación. Para obtener la lista completa de nombres de campos que puede utilizar en la selección, consulte la salida de lvm -S help. La ayuda también contiene el tipo de valores que muestra cada campo entre corchetes.

–

•
Coincidencia de un subconjunto de elementos en el campo de lista de cadenas:
–
y todos los elementos de la selección, utilice { } con "," (o "&&"), por ejemplo, {"a","b","c"},
–

OPCIONES DE REPORTE

Los comandos de LVM pueden generar informes con diferentes niveles de detalle y formato. Los informes se pueden generar en una variedad de formatos, desde básico y legible por humanos hasta XML. Los detalles del informe, como las columnas que se muestran y cómo se ordenan, se pueden controlar mediante opciones de línea de comandos y la configuración del sistema de archivos de LVM. Vea también lvm.conf(5).

Especificidades del reporte

La configuración de LVM se puede ver utilizando el comando lvmconfig(8). La salida del comando lvmconfig(8) se puede ver en dos formatos:

–
full: Muestra toda la configuración, incluyendo los valores predeterminados si no se han modificado.
–
effective: Muestra solo los valores que se están utilizando actualmente. Esto incluye los valores predeterminados si no se han modificado y los valores configurados por el usuario si se han modificado.

Además, los valores de configuración se pueden ver de forma selectiva utilizando el argumento de ruta completa del parámetro de configuración. Por ejemplo, para ver la configuración del formato de salida de los informes, utilice:

# lvmconfig report/output_format
output_format="basic"

Para ver toda la configuración de la sección de informes de LVM:

report/separator=" "
report/list_item_separator=","
report/prefixes=0
report/quoted=1
report/columns_as_rows=0
report/binary_values_as_numeric=0
report/time_format="%Y-%m-%d %T %z"
report/mark_hidden_devices=1
report/two_word_unknown_device=0
report/buffered=1

Formatos de salida

Los informes se pueden generar en varios formatos. Los formatos disponibles se establecen con la configuración de report/output_format o con la opción de línea de comandos --outputformat.

–
basic: Formato de salida básico legible por humanos. Este es el formato predeterminado.
–
json: Formato de salida JSON. Ver lvm.conf(5) para más detalles.
–
xml: Formato de salida XML. Ver lvm.conf(5) para más detalles.
–
yaml: Formato de salida YAML. Ver lvm.conf(5) para más detalles.
–
list: Formato de salida de lista. Ver lvm.conf(5) para más detalles.
–
wide: Formato de salida ancho. Similar a basic, pero con más columnas mostradas.
–
single: Formato de salida de una sola línea. Cada línea de salida contiene información sobre un solo objeto.
–
tree: Formato de salida en árbol. Muestra las relaciones entre los objetos.

Formato de tiempo libre

El formato de tiempo libre permite especificar fechas y horas de una manera más flexible. Se pueden usar los siguientes formatos:

–
Formatos estándar de fecha y hora (por ejemplo, "YYYY-MM-DD HH:MM:SS").
–
Marcas de tiempo Unix.
–
Formatos de hora con sufijos AM/PM.
–
Nombres de días de la semana (por ejemplo, "Sunday", "Sun").
–
Etiquetas de puntos en el tiempo (por ejemplo, "noon", "midnight").
–
Etiquetas de días relativos (por ejemplo, "today", "yesterday").
–
Puntos en el tiempo relativos con un desplazamiento desde hoy (N es un número):
"N" "seconds" / "minutes" / "hours" / "days" / "weeks" / "years" "ago"
"N" "secs" / "mins" / "hrs" ... "ago"
"N" "s" / "m" / "h" ... "ago"
–
Nombres de meses (por ejemplo, "January", "Jan").

Especificación gramatical informal

–
STATEMENT = column cmp_op VALUE | STATEMENT log_op STATEMENT | (STATEMENT) | !(STATEMENT)
–
VALUE = [VALUE log_op VALUE]
Para tipos basados en listas: lista de cadenas. Coincide con todos los elementos de la lista. El log_op debe ser siempre de un tipo dentro de todo el valor de la lista.
–
VALUE = {VALUE log_op VALUE}
Para tipos basados en listas: lista de cadenas. Coincide con un subconjunto de elementos de la lista. El log_op debe ser siempre de un tipo dentro de todo el valor de la lista.
–
VALUE = value
Para tipos escalares: número, tamaño, porcentaje, cadena (o expresión regular de cadena). También para tipos basados en listas: lista de cadenas (en este caso el valor es una forma corta de {value}).

Compaction automática de salida

Si observa la salida de lvs anterior, puede ver que el informe también contiene campos para los cuales no hay información que mostrar (por ejemplo, las columnas bajo el encabezado "Origin" y "Pool" - los campos "origin" y "pool_lv"). LVM puede compactar automáticamente la salida del informe para que dichos campos no se incluyan en la salida final. Para habilitar esta función y compactar todos los campos, use report/compact_output=1 en su configuración.

# lvmconfig --type full report/compact_output
compact_output=1
# lvs
  LV    LSize Cpy%Sync
  lvol1 4.00m 100.00
  lvol0 4.00m
# lvs vg/lvol0
  LV    LSize
  lvol0 4.00m

Alternativamente, puede definir qué campos deben compactarse configurando el ajuste de configuración report/compact_output_cols (o la opción de línea de comandos -o|--options #).

# lvmconfig --type full report/compact_output report/compact_output_cols
compact_output=0
compact_output_cols="origin"
# lvs
  LV    LSize Pool Cpy%Sync
  lvol1 4.00m      100.00
  lvol0 4.00m
# lvs vg/lvol0
  LV    LSize Pool
  lvol0 4.00m
# lvs -o#pool_lv
  LV    LSize Origin Cpy%Sync
  lvol1 4.00m        100.00
  lvol0 4.00m

Usaremos report/compact_output=1 para los ejemplos subsiguientes.

Opciones adicionales de formato

Por defecto, LVM muestra los tamaños en los informes en formato legible por humanos, lo que significa que se usa la unidad más adecuada para que sea fácil de leer. Puede usar el ajuste de configuración report/units (o la opción --units directamente en la línea de comandos) y el ajuste de configuración report/suffix (o

>--nosuffix opción de línea de comandos) para cambiar esto.

# lvs --units b --nosuffix
  LV    LSize   Cpy%Sync
  lvol1 4194304 100.00
  lvol0 4194304

Si desea configurar si se muestran o no los encabezados del informe, utilice la configuración de report/headings (o la opción de línea de comandos --noheadings).

# lvs --noheadings
  lvol1 4.00m 100.00
  lvol0 4.00m

En algunos casos, puede ser útil mostrar el contenido del informe como pares clave=valor, donde la clave es en realidad el nombre del campo. Utilice la configuración de report/prefixes (o la opción de línea de comandos --nameprefixes) para cambiar entre la salida estándar y la salida clave=valor. El par clave=valor es la salida adecuada para usar en scripts y para que otras herramientas la analicen fácilmente. Por lo general, tampoco querrá mostrar encabezados con la salida que tiene estos pares clave=valor.

# lvs --noheadings --nameprefixes
  LVM2_LV_NAME='lvol1' LVM2_LV_SIZE='4.00m' LVM2_COPY_PERCENT='100.00'
  LVM2_LV_NAME='lvol0' LVM2_LV_SIZE='4.00m' LVM2_COPY_PERCENT=''

Para definir si se utilizan o no comillas en los pares clave=valor, utilice la configuración report/quoted (o la opción de línea de comandos --unquoted).

# lvs --noheadings --nameprefixes --unquoted
  LVM2_LV_NAME=lvol1 LVM2_LV_SIZE=4.00m LVM2_COPY_PERCENT=100.00
  LVM2_LV_NAME=lvol0 LVM2_LV_SIZE=4.00m LVM2_COPY_PERCENT=

Para facilitar el análisis, incluso puede transponer el informe para que cada columna se convierta en una fila en la salida. Esto se hace con la configuración report/output_as_rows (o la opción de línea de comandos --rows).

# lvs --noheadings --nameprefixes --unquoted --rows
  LVM2_LV_NAME=lvol1 LVM2_LV_NAME=lvol0
  LVM2_LV_SIZE=4.00m LVM2_LV_SIZE=4.00m
  LVM2_COPY_PERCENT=100.00 LVM2_COPY_PERCENT=

Utilice la configuración report/separator (o la opción de línea de comandos --separator) para definir su propio separador de campos.

# lvs --noheadings --nameprefixes --unquoted --separator " | "
  LVM2_LV_NAME=lvol1 | LVM2_LV_SIZE=4.00m | LVM2_COPY_PERCENT=100.00
  LVM2_LV_NAME=lvol0 | LVM2_LV_SIZE=4.00m | LVM2_COPY_PERCENT=

Si está utilizando su propio separador, las columnas en la salida no están alineadas por defecto. Utilice la configuración report/aligned (o la opción de línea de comandos --aligned) para que LVM agregue espacios adicionales en el informe y alinee la salida correctamente.

# lvs --separator " | "
  LV | LSize | Cpy%Sync
  lvol1 | 4.00m | 100.00
  lvol0 | 4.00m |
# lvs --separator " | " --aligned
  LV    | LSize | Cpy%Sync
  lvol1 | 4.00m | 100.00
  lvol0 | 4.00m |

Mostremos un campo más además ("lv_tags" en este ejemplo) para la salida del informe lvs.

# lvs -o+lv_tags
  LV    LSize Cpy%Sync LV Tags
  lvol1 4.00m 100.00
  lvol0 4.00m          tagA,tagB

La columna "LV Tags" en el ejemplo anterior muestra dos valores de lista, separados por el carácter "," para LV lvol0. Si necesita un separador diferente para los elementos de la lista, utilice la configuración report/list_item_separator y su definición.

# lvmconfig --type full report/list_item_separator
list_item_separator=";"
# lvs -o+tags
  LV    LSize Cpy%Sync LV Tags
  lvol1 4.00m 100.00
  lvol0 4.00m          tagA;tagB

Pero sigamos utilizando el carácter "," original para list_item_separator para los siguientes ejemplos.

El formato para cualquiera de los valores de tiempo que se muestran en los informes se puede configurar con la configuración report/time_format. Por defecto, se muestra la fecha y hora completas, incluida la zona horaria.

# lvmconfig --type full report/time_format
time_format="%Y-%m-%d %T %z"
# lvs -o+time
  LV    LSize Cpy%Sync CTime
  lvol1 4.00m 100.00   2016-08-29 12:53:36 +0200
  lvol0 4.00m          2016-08-29 10:15:17 +0200

Podemos cambiar el formato de tiempo de manera similar a como lo hacemos al usar el comando date(1) o la función strftime(3) ( lvmconfig --type default --withcomments report/time_format le dará la lista completa de opciones de formato disponibles). En el siguiente ejemplo, decidimos usar %s para el número de segundos desde la Época (1970-01-01 UTC).

# lvmconfig --type full report/time_format
time_format="%s"
# lvs
  LV    Attr       LSize Cpy%Sync LV Tags   CTime
  lvol1 rwi-a-r--- 4.00m 100.00             1472468016
  lvol0 -wi-a----- 4.00m          tagA,tagB 1472458517

El comando lvs no muestra LVs ocultos por defecto; para incluir estos LVs en la salida, necesita usar la opción de línea de comandos -a|--all. Los nombres de estos LVs ocultos se muestran entre corchetes.

# lvs -a
  LV               LSize Cpy%Sync
  lvol1            4.00m 100.00
  [lvol1_rimage_0] 4.00m
  [lvol1_rmeta_0]  4.00m
  [lvol1_rimage_1] 4.00m
  [lvol1_rmeta_1]  4.00m
  lvol0            4.00m

Puede configurar LVM para que muestre corchetes para LVs ocultos o no con la configuración report/mark_hidden_devices.

# lvmconfig --type full report/mark_hidden_devices
mark_hidden_devices=0
# lvs -a
  LV             LSize Cpy%Sync
  lvol1          4.00m 100.00
  lvol1_rimage_0 4.00m
  lvol1_rmeta_0  4.00m
  lvol1_rimage_1 4.00m
  lvol1_rmeta_1  4.00m
  lvol0          4.00m

No se recomienda usar marcas de LV para dispositivos ocultos para decidir si el LV es el que deben usar los usuarios finales o no. Por favor, utilice el campo "lv_role" en su lugar, que puede informar si el LV es "público" o "privado". Los LVs privados son utilizados solo por LVM y no deben ser accedidos directamente por los usuarios finales.

# lvs -a -o+lv_role
  LV             LSize Cpy%Sync Role
  lvol1          4.00m 100.00   public
  lvol1_rimage_0 4.00m          private,raid,image
  lvol1_rmeta_0  4.00m          private,raid,metadata
  lvol1_rimage_1 4.00m          private,raid,image
  lvol1_rmeta_1  4.00m          private,raid,metadata
  lvol0          4.00m          public

Algunos de los campos de informe que LVM presenta son de naturaleza binaria. Para dichos campos, es posible mostrar la representación en palabras del valor (esto se usa por defecto) o el valor numérico (0/1 o -1 en caso de que el valor no esté definido).

# lvs -o+lv_active_locally
  LV    LSize Cpy%Sync ActLocal
  lvol1 4.00m 100.00   active locally
  lvol0 4.00m          active locally

Podemos cambiar la forma en que se muestran estos valores binarios con la configuración report/binary_values_as_numeric.

# lvmconfig --type full report/binary_values_as_numeric
binary_values_as_numeric=1
# lvs -o+lv_active_locally
  LV    LSize Cpy%Sync ActLocal
  lvol1 4.00m 100.00            1
  lvol0 4.00m                   1

En ciertos casos, puede resultar más útil informar los nombres completos de las columnas en lugar de los nombres abreviados de las columnas en los encabezados del informe. Para hacer esto, use la configuración report/headings=2 (o la opción de línea de comandos --headings full o --headings 2). Los nombres completos de las columnas son los nombres exactos que también usa en FieldSet para -o|--options. Estos nombres no son ambiguos, sin espacios (una sola palabra) y también hacen que sea más fácil hacer coincidir la salida con el FieldSet solicitado:

# lvs -o+seg_start,seg_start_pe
  LV    VG LSize Cpy%Sync Start Start
  lvol0 vg 4.00m             0      0
  lvol1 vg 4.00m 100.00      0      0
# lvs --headings full -o+seg_start,seg_start_pe
  lv_name vg_name lv_size copy_percent seg_start seg_start_pe
  lvol0   vg        4.00m                     0             0
  lvol1   vg        4.00m 100.00              0             0

Cambiar el formato de salida

LVM puede generar informes en diferentes formatos; utilice la configuración report/output_format (o la opción de línea de comandos --reportformat) para cambiar el formato de salida del informe.

Actualmente, LVM soporta estos formatos de salida:

– "basic" (todos los ejemplos que usamos anteriormente usaron este formato),
– "json",
– "json_std".

Por ejemplo:

# lvs -o lv_name,lv_size --reportformat json
  {
      "report": [
          {
              "lv": [
                  {"lv_name":"lvol1", "lv_size":"4.00m"},
                  {"lv_name":"lvol0", "lv_size":"4.00m"}
              ]
          }
      ]
  }

El formato de salida json_std es más compatible con el estándar JSON y, en comparación con el formato json original:

–
no usa comillas dobles alrededor de los valores numéricos,
–
los valores numéricos siempre se expresan como números, no como cadenas reservadas que los representan (esto también significa que la configuración report/binary_values_as_numeric=1 se fuerza)
–
usa 'null' para valores numéricos indefinidos,
–
imprime listas de cadenas como un arreglo JSON adecuado de cadenas en lugar de una sola cadena.

Tenga en cuenta que algunas configuraciones y opciones de línea de comandos no tienen efecto con ciertos formatos de informe. Por ejemplo, con la salida json o json_std, no tiene sentido usar report/aligned (--aligned), report/noheadings (--noheadings), report/columns_as_rows (--rows) o report/buffered (--unbuffered). Todas estas configuraciones y opciones de línea de comandos se ignoran si se utiliza el formato de salida de informe json o json_std.

Selección

Si necesita seleccionar solo filas específicas del informe, puede utilizar la función de selección de informes de LVM. Si llama a lvm -S help, obtendrá ayuda rápida sobre la selección. La ayuda contiene una lista de todos los campos que LVM puede usar en los informes junto con su tipo entre corchetes. El siguiente ejemplo contiene una línea de la ayuda de lvs -S.

Para demostrar la funcionalidad de selección en LVM, crearemos más LVs además de lvol0 y lvol1 que usamos en nuestros ejemplos anteriores.

# lvs -o name,size,origin,snap_percent,tags,time

  lvol0 4.00m               tagA,tagB      2016-08-29 10:15:17 +0200

Al seleccionar campos de tamaño y porcentaje, no necesitamos usar unidades. Para tamaños, se utiliza por defecto "m" (para MiB) – este es el mismo comportamiento que ya se usa para los comandos LVM al especificar tamaños (por ejemplo, lvcreate -L). Para los campos de porcentaje, se asume automáticamente "%" si no se especifica. El siguiente ejemplo también demuestra cómo se pueden combinar varios criterios.

# lvs -o name,size,snap_percent -S 'size=8m'

  lvol2 8.00m

  LV    LSize

LVM puede reconocer valores más complejos utilizados en criterios de selección para los tipos de campo de lista de cadenas y tiempo. Para listas de cadenas, puedes comparar una lista completa estrictamente, un subconjunto o una intersección. Tomemos el campo "lv_tags" como ejemplo: seleccionamos solo las filas que contienen "tagA" en el campo de etiquetas. Usamos { } para indicar que estamos interesados en un subconjunto que coincida. Si el subconjunto tiene solo un elemento, podemos omitir { }.

# lvs -o name,tags -S 'tags={tagA}'
  LV    LV Tags
  lvol2 tagA,tagC,tagD
  lvol0 tagA,tagB
# lvs -o name,tags -S 'tags=tagA'
  LV    LV Tags
  lvol2 tagA,tagC,tagD
  lvol0 tagA,tagB

Para valores de lista de cadenas, podemos comparar todos los elementos en el valor de la lista de cadenas (usando [ ]) o solo un subconjunto de elementos en el valor de la lista de cadenas (usando { }). Además, podemos comparar si todos los elementos en el criterio de selección de la lista de cadenas coinciden (usando "," o "&&" como delimitador de elementos) o si solo un subconjunto de elementos en el criterio de selección de la lista de cadenas coincide (usando "#" o "||" como delimitador de elementos).

# lvs -o name,tags -S 'tags={tagA}'
  LV    LV Tags
  lvol0 tagA,tagB
  lvol2 tagA,tagC,tagD
# lvs -o name,tags -S 'tags={tagA || tagB}'
  LV    LV Tags
  lvol0 tagA,tagB
  lvol2 tagA,tagC,tagD
# lvs -o name,tags -S 'tags={tagA && tagB}'
  LV    LV Tags
  lvol0 tagA,tagB
# lvs -o name,tags -S 'tags={tagA || tagB || tagC}'
  LV    LV Tags
  lvol0 tagA,tagB
  lvol2 tagA,tagC,tagD
# lvs -o name,tags -S 'tags={tagA && tagB && tagC}'
# lvs -o name,tags -S 'tags=[tagA]'
# lvs -o name,tags -S 'tags=[tagA || tagB]'
  LV    LV Tags
  lvol0 tagA,tagB
# lvs -o name,tags -S 'tags=[tagA && tagB]'
  LV    LV Tags
  lvol0 tagA,tagB
# lvs -o name,tags -S 'tags=[tagA || tagB || tagC]'
  LV    LV Tags
  lvol0 tagA,tagB
# lvs -o name,tags -S 'tags=[tagA && tagB && tagC]'

También puedes usar expresiones regulares en lugar de cadenas simples dentro de los criterios de selección de lista de cadenas. En ese caso, se utiliza el operador "=~" en lugar de "=". Los operadores de agrupación de listas de cadenas { } y [ ] también se reconocen.

# lvs -o name,tags -S 'tags=~^t.*[ACD]$'
  LV    LV Tags
  lvol0 tagA,tagB
  lvol2 tagA,tagC,tagD
# lvs -o name,tags -S 'tags=~{"^t.*[ACD]$"}'
  LV    LV Tags
  lvol0 tagA,tagB
  lvol2 tagA,tagC,tagD
# lvs -o name,tags -S 'tags=~["^t.*[ACD]$"]'
  LV    LV Tags
  lvol2 tagA,tagC,tagD
# lvs -o name,tags -S 'tags=~{"^t.*[AC]$" || "^tag[D]$" }'
  LV    LV Tags
  lvol0 tagA,tagB
  lvol2 tagA,tagC,tagD
# lvs -o name,tags -S 'tags=~["^t.*[AC]$" || "^tag[D]$" ]'
  LV    LV Tags
  lvol2 tagA,tagC,tagD
# lvs -o name,tags -S 'tags=~["^t.*A$" && "^t.*B$" ]'
  LV    LV Tags
  lvol0 tagA,tagB
# lvs -o name,tags -S 'tags!~["^t.*A$" && "^t.*B$" ]'
  LV    LV Tags
  lvol1
  lvol2 tagA,tagC,tagD
  lvol3
  lvol4

Para comparar un conjunto sin elementos, usa "" para denotarlo (ten en cuenta que tenemos la compactación de salida habilitada, por lo que la columna "LV Tags" no se muestra en el ejemplo siguiente porque está en blanco y, por lo tanto, se compacta).

  lvol4

Registro de comandos

Como se describe en la sección categorización basada en el mecanismo de reporte al principio de este documento, tanto los comandos LVM **orientados al reporte** como los **orientados al procesamiento** pueden reportar el registro del comando si esto está habilitado con la configuración **log/report_command_log**. Al igual que cualquier otro

NAME

lvmreport - LVM report configuration

DESCRIPTION

The LVM command line interface offers a way to manage LVM metadata and configuration. This includes the ability to generate various reports based on LVM objects such as Logical Volumes (LVs), Volume Groups (VGs), and Physical Volumes (PVs).

The lvmreport feature allows fine-grained control over the content and presentation of these reports. Specifically, it enables users to configure:

  • The set of fields to display in a report.
  • The criteria used to sort the data within a report.
  • The conditions used to filter the data shown in a report.

These configurations can be applied globally using lvmconfig or on a per-command basis using command-line options.

USAGE

LVM reports can be configured using the lvmconfig command to set persistent configurations or directly on the command line when invoking LVM commands.

The key configuration parameters for reports are:

log/command_log_cols
Defines the columns (fields) to be displayed in the command log report.
log/command_log_sort
Specifies the field(s) by which the command log report should be sorted.
log/command_log_selection
Sets the filter criteria for the command log report. Only log entries matching the selection will be displayed.

When invoking LVM commands directly, options like -o (or --options), -O (or --sort), and -S (or --select) can be used to configure reports. For sub-reports within a larger report (like those generated by lvm fullreport), the --configreport option is used to target specific reports.

EXAMPLES

This section provides practical examples of how to configure and use LVM reports.

Configuring the command log report

Here, we configure the command log report using lvmconfig. We specify which columns to display, how to sort them, and apply a selection filter. The example shows setting the report to display various details about logged commands, sort by sequence number, and exclude successful status messages for non-status operations.

# lvmconfig --type full log/report_command_log log/command_log_cols \
   log/command_log_sort log/command_log_selection
report_command_log=1
command_log_cols="log_seq_num,log_type,log_context,log_object_type,
                  log_object_name,log_object_group,log_message,
                  log_errno,log_ret_code"
command_log_sort="log_seq_num"
command_log_selection="!(log_type=status && message=success)"

Initially, when the command log is empty or no entries match the default selection, running lvs might show no command log entries (other than headers).

# lvs
  Logical Volume
  ==============
  LV    LSize Cpy%Sync
  lvol1 4.00m 100.00
  lvol0 4.00m
  Command Log
  ===========
  Seq LogType Context ObjType ObjName ObjGrp  Msg     Errno RetCode

To see the actual logged entries, we can adjust the selection criteria. By setting `command_log_selection` to "all", we ensure all log entries are displayed. This example shows successful processing of logical volumes and the volume group.

# lvmconfig --type full log/command_log_selection

  lvol1 4.00m 100.00

    1 status  processing lv      lvol0   vg      success     0       1
    2 status  processing lv      lvol1   vg      success     0       1
