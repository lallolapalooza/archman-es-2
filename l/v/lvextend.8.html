DESCRIPCIÓN

lvextend extiende el tamaño de un LV. Esto requiere la asignación de extents lógicos desde los extents físicos libres del VG. Si la extensión añade un nuevo segmento LV, el nuevo segmento utilizará el tipo de segmento existente del LV.

Extender un LV de snapshot de copia en escritura añade espacio para bloques COW.

Utilice lvconvert(8) para cambiar el número de imágenes de datos en un LV RAID o espejado.

En la sección de uso a continuación, --size Tamaño puede reemplazarse con --extents Número. Consulte ambas descripciones en la sección de opciones.

USO

Extender un LV por un tamaño especificado.

lvextend -L|--size [+]Tamaño[m|UNIDAD] LV

OPCIONES

--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Determina la política de asignación cuando un comando necesita asignar Extents Físicos (PEs) del VG. Cada VG y LV tiene una política de asignación que puede cambiarse con vgchange/lvchange, o anularse en la línea de comandos. normal aplica reglas de sentido común, como no colocar stripes paralelos en el mismo PV. inherit aplica la política del VG a un LV. contiguous requiere que los PEs nuevos se coloquen adyacentes a los PEs existentes. cling coloca los PEs nuevos en el mismo PV que los PEs existentes en el mismo stripe del LV. Si hay suficientes PEs para una asignación, pero normal no los usa, anywhere los usará incluso si reduce el rendimiento, por ejemplo, al colocar dos stripes en el mismo PV. Los argumentos de PV posicionales opcionales en la línea de comandos también se pueden usar para limitar qué PVs usará el comando para la asignación. Consulte lvm(8) para más información sobre la asignación.
-A|--autobackup y|n
Especifica si los metadatos deben copiarse de seguridad automáticamente después de un cambio. ¡Se recomienda encarecidamente habilitar esto! Consulte vgcfgbackup(8) para más información.
--commandprofile Cadena
El perfil de comando a utilizar para la configuración del comando. Consulte lvm.conf(5) para más información sobre perfiles.
--config Cadena
Configuración del comando. Estas anulan la configuración de lvm.conf(5). El argumento de Cadena utiliza el mismo formato que lvm.conf(5), o puede usar la sintaxis de sección/campo. Consulte lvm.conf(5) para más información sobre la configuración.
-d|--debug ...
Establecer el nivel de depuración. Repita de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o a la salida estándar.
--vgsync String
Sync LV data to a different VG. See vgimportclone(8) for more information.
-w|--writecachesize Size[m|UNIT]
Specifies the size of the write cache for a cache pool. For pool sizes that are not specified with --poolmetadatasize, this option implies --poolmetadatasize as well. If the write cache size is larger than the pool metadata size, the pool metadata size will be automatically increased to match the write cache size.
-y|--yes
Assume 'yes' to all prompts that would normally be prompted for. If the command requires confirmation, then this option will override the check and proceed. Using this option with --test is not recommended.

OPTIONS

--alloc <allocation_profile>
Determines the allocation policy for Physical Extents (PEs). See lvm.conf(5) for the list of available allocation policies. If not specified, the default allocation policy is used. The default policy may be overridden by the --usepolicies option.
--cache
Creates a cache logical volume. See lvmcache(7). This option is a shortcut for --type cache.
--cache-pool
Creates a cache pool logical volume. See lvmcache(7). This option is a shortcut for --type cache-pool.
--config <config>
Suppresses the use of any system-wide lvm.conf files. The config parameter is a string that can contain LVM configuration. See lvm.conf(5) for the format of the string.
--commandprofile <profile>
Sets a command profile to use for the current command. See lvm.conf(5) for more information about profiles.
--dmetarget <target_type>
Specifies the DM (Device Mapper) target type for the new logical volume. Default is `linear`. It can be `striped`, `mirror`, `snapshot`, `thin`, `cache`, `raid`, `vdo`, `e-pool`, `writecache`.
--globalr
Used to specify PVs that are not part of any volume group or that are part of a different volume group than the one specified with the LV argument. This can also be specified in lvm.conf(5).
--ignoremonitoring
Disable monitoring for command execution.
--monitor monitor_args
Enable monitoring for command execution. See lvm.conf(5) for more information. This option is a shortcut for --enablemonitoring.
--notruncate
If the logical volume is being extended, do not truncate it to zero size if it already exists.
--nouuid
Disable the use of UUIDs in the configuration file. LVM will fall back to using device names. This is not recommended and can lead to data loss.
--poolmetadatasize <Size>[UNIT]
Set the metadata size for a thin pool or snapshot. This limits the amount of metadata that can be used by the pool or snapshot. See lvmthin(7).
--poolmetadatawarning <Size>[UNIT]
Set the metadata warning threshold for a thin pool or snapshot. When the metadata usage reaches this threshold, a warning message will be logged. See lvmthin(7).
--poolsize <Size>[UNIT]
Set the total size of a thin pool or snapshot. See lvmthin(7).
--printmetadata
Print the metadata of the specified logical volume. This is useful for debugging purposes.
-q|--quiet
Suppress output and only print error messages.
--raid <N>
Creates a raid logical volume of raid<N> type. See lvmraid(7). This option is a shortcut for --type raid<N>.
--raisewarning
Raise a warning message if the operation is not successful. This is useful for scripting.
--readahead <Size>[UNIT]
Set the read-ahead value for the logical volume. The value is in KiB by default. If UNIT is not specified, a default unit (based on the value) is used. See also lvm.conf(5).
--reportformat <format>
Determines the output format for reports. See lvm.conf(5) for a list of formats.
--splitcache
Split a cache logical volume from its cache pool. See lvmcache(7). This option is a shortcut for --type split-cache.
--snapshot
Creates a snapshot logical volume. See usage descriptions. This option is a shortcut for --type snapshot.
--test
Perform a simulation of the command without making any actual changes. This is useful for testing your commands and verifying the expected outcome.
--thin
Creates a thin logical volume. See lvmthin(7). This option is a shortcut for --type thin.
--thin-pool
Creates a thin pool logical volume. See lvmthin(7). This option is a shortcut for --type thin-pool.
--type <type>
Sets the LV type, also known as "segment type" or "segtype". See usage descriptions for the specific ways to use these types. For more information about redundancy and performance (raid<N>, mirror, striped, linear) see lvmraid(7). For thin provisioning (thin, thin-pool) see lvmthin(7). For performance caching (cache, cache-pool) see lvmcache(7). For copy-on-write snapshots (snapshot) see usage definitions. For VDO (vdo) see lvmvdo(7). Several commands omit an explicit type option because the type is inferred from other options or shortcuts (e.g. --stripes, --mirrors, --snapshot, --virtualsize, --thin, --cache, --vdo). Use inferred types with care because it can lead to unexpected results.
--usepolicies
Perform an operation according to the policy configured in lvm.conf(5) or a profile.
-v|--verbose ...
Set verbose level. Repeat from 1 to 4 times to increase the detail of messages sent to stdout and stderr.
--version
Display version information.
--vdo
Creates a VDO logical volume. See lvmvdo(7). This option is a shortcut for --type vdo.
--writecache
Creates a writecache logical volume. See lvmcache(7). This option is a shortcut for --type writecache.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

LV
Logical Volume name. See lvm(8) for valid names. An LV positional arg generally includes the VG name and LV name, e.g. VG/LV. LV1 indicates the LV must have a specific type, where the accepted LV types are listed. (raid represents raid<N> type).
PV
Physical Volume name, a device path under /dev. For commands managing physical extents, a PV positional arg generally accepts a suffix indicating a range (or multiple ranges) of physical extents (PEs). When the first PE is omitted, it defaults to the start of the device, and when the last PE is omitted it defaults to end.
Start and end range (inclusive): PV[:PE-PE] ...
Start and length range (counting from 0): PV[:PE+PE] ...
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.

EXAMPLES

Extend the size of an LV by 54MiB, using a specific PV.
lvextend -L +54 vg01/lvol10 /dev/sdk3

Extend the size of an LV by the amount of free space on PV /dev/sdk3. This is equivalent to specifying "-l +100%PVS" on the command line.
lvextend vg01/lvol01 /dev/sdk3

Extend an LV by 16MiB using specific physical extents.
lvextend -L+16m vg01/lvol01 /dev/sda:8-9 /dev/sdb:8-9

Extend an LV to use all remaining free space in volume group and all resize its filesystem with fsadm(8).
lvextend -l+100%FREE -r vg01/lvol01
