NOMBRE

lvmvdo — Soporte para Virtual Data Optimizer en LVM

DESCRIPCIÓN

VDO es un software que proporciona deduplicación en línea a nivel de bloque, compresión y capacidades de aprovisionamiento fino para almacenamiento primario.

La deduplicación es una técnica para reducir el consumo de recursos de almacenamiento eliminando copias múltiples de bloques duplicados. La compresión toma los bloques únicos individuales y los reduce. Estos bloques reducidos se empaquetan eficientemente en bloques físicos.

Con la deduplicación, en lugar de escribir los mismos datos más de una vez, VDO detecta y registra cada bloque duplicado como una referencia al bloque original. VDO mantiene un mapeo de Direcciones de Bloque Lógicas (LBA) (utilizadas por la capa de almacenamiento por encima de VDO) a direcciones de bloque físicas (utilizadas por la capa de almacenamiento por debajo de VDO). Después de la deduplicación, múltiples direcciones de bloque lógicas pueden mapearse a la misma dirección de bloque física; estos se llaman bloques compartidos y son contados por referencia por el software.

Con la compresión, VDO comprime múltiples bloques (o bloques compartidos) con el algoritmo rápido LZ4, y los agrupa donde sea posible para que múltiples bloques comprimidos quepan dentro de un bloque de 4 KB en el almacenamiento subyacente. El mapeo de LBA es a una dirección de bloque física y un índice dentro de él para los datos comprimidos deseados. Todos los bloques comprimidos se cuentan individualmente por referencia para garantizar la corrección.

El compartir bloques y la compresión de bloques son invisibles para las aplicaciones que usan el almacenamiento, que leen y escriben bloques como lo harían si VDO no estuviera presente. Cuando se sobrescribe un bloque compartido, se asigna un nuevo bloque físico para almacenar los nuevos datos del bloque, asegurando que otras direcciones de bloque lógicas que se mapean al bloque físico compartido no se modifiquen.

Para usar VDO con lvm(8), debes instalar las herramientas estándar de espacio de usuario de VDO vdoformat(8) y el módulo del kernel "dm_vdo" (Para kernels más antiguos <6.9 es necesario el módulo VDO externo al árbol del kernel "kvdo").

El módulo del kernel implementa virtualización de almacenamiento de grano fino, aprovisionamiento fino, compartir bloques, compresión e identificación de duplicados eficiente en memoria. Las herramientas de espacio de usuario incluyen vdostats(8) para extraer estadísticas de los volúmenes VDO.

TÉRMINOS VDO

VDODataLV
El LV de datos de VDO es un LV oculto grande con el sufijo _vdata. Se crea en un VG utilizado por el destino del kernel VDO para almacenar todos los bloques de datos y metadatos.
VDOPoolLV
El LV de pool de VDO es un pool para VDOLV(s) virtuales, que tienen el tamaño de VDODataLV utilizado. Actualmente solo se admite un VDOLV.
VDOLV
El LV de VDO es un LV virtual creado a partir de VDOPoolLV. Aparece vacío después de la creación.

USO VDO

Los métodos principales para usar VDO con lvm2:

1. Crear un VDOPoolLV y un VDOLV

Crea un VDOPoolLV que contendrá datos VDO, y un VDOLV de tamaño virtual que el usuario puede usar. Si no especificas el tamaño virtual, el VDOLV se crea con el tamaño máximo que siempre cabe en el volumen de datos, incluso si no se puede realizar deduplicación o compresión (es decir, puede contener el contenido incompresible de /dev/urandom). Si no especificas el nombre de VDOPoolLV, se toma de la secuencia vpool0, vpool1, ...

Nota: El rendimiento de las operaciones TRIM/Discard es lento para volúmenes grandes de tipo VDO. Por favor, intente evitar enviar solicitudes de descarga a menos que sea necesario, ya que puede llevar una cantidad considerable de tiempo completar la operación de descarga.

lvcreate --type vdo -n VDOLV -L TamañoDatos -V TamañoVirtualGrande VG/VDOPoolLV
lvcreate --vdo -L TamañoDatos VG

Ejemplo

# lvcreate --type vdo -n vdo0 -L 10G -V 100G vg/vdopool0
# mkfs.ext4 -E nodiscard /dev/vg/vdo0

2. Convertir un LV existente en VDOPoolLV

Convierte un LV ya creado o existente en un VDOPoolLV, que es un volumen que puede contener datos y metadatos. Se le pedirá que confirme dicha conversión ya que DESTRUYE IRREVERSIBLEMENTE el contenido de dicho volumen y el volumen se formatea inmediatamente con vdoformat(8) como un volumen de datos de pool VDO. Puede especificar el tamaño virtual del VDOLV asociado con este VDOPoolLV. Si no especifica el tamaño virtual, se establecerá al tamaño máximo que pueda contener datos incompresibles al 100%.

lvconvert --type vdo-pool -n VDOLV -V TamañoVirtual VG/VDOPoolLV
lvconvert --vdopool VG/VDOPoolLV

Ejemplo

# lvconvert --type vdo-pool -n vdo0 -V10G vg/ExistingLV

3. Cambiar la compresión y deduplicación de un VDOPoolLV

Desactiva o activa la compresión y deduplicación para VDOPoolLV (el volumen que mantiene todos los VDO LV asociados a él).

lvchange --compression s|n --deduplication s|n VG/VDOPoolLV

Ejemplo

# lvchange --compression n  vg/vdopool0
# lvchange --deduplication s vg/vdopool1

4. Cambiar la configuración predeterminada usada para crear un VDOPoolLV

VDO permite establecer una gran variedad de opciones. Muchas de estas configuraciones se pueden especificar en lvm.conf o en la configuración de perfiles. Puede preparar una serie de perfiles diferentes en el directorio /etc/lvm/profile y simplemente especificar el nombre del archivo de perfil. Consulte la salida de lvmconfig --type default --withcomments para obtener una descripción detallada de cada configuración individual de VDO.

Ejemplo

# cat <<EOF > /etc/lvm/profile/vdo_create.profile
allocation {
vdo_use_compression=1
vdo_use_deduplication=1
vdo_minimum_io_size=4096
vdo_block_map_cache_size_mb=128
vdo_block_map_period=16380
vdo_use_sparse_index=0
vdo_index_memory_size_mb=256
vdo_slab_size_mb=2048
vdo_ack_threads=1
vdo_bio_threads=1
vdo_bio_rotation=64
vdo_cpu_threads=2
vdo_hash_zone_threads=1
vdo_logical_threads=1
vdo_physical_threads=1
vdo_max_discard=1
}
EOF
# lvcreate --vdo -L10G --metadataprofile vdo_create vg/vdopool0
# lvcreate --vdo -L10G --config 'allocation/vdo_cpu_threads=4' vg/vdopool1

5. Establecer o cambiar configuraciones de VDO con la opción --vdosettings

Utilice el formato 'opción=valor' o 'opción1=valor opción2=valor', o repita --vdosettings para cada opción que se va a establecer. Las opciones se enumeran en la sección de Ejemplo anterior, para obtener la descripción completa consulte lvm.conf(5). Las opciones pueden omitir los prefijos 'vdo_' y 'vdo_use_' y todos sus guiones bajos. Así, por ejemplo, vdo_use_deduplication=1 y deduplication=1 son equivalentes. Para cambiar la opción de un VDOPoolLV ya existente, utilice el comando lvchange(8). Sin embargo, no todas las opciones se pueden cambiar. Solo las opciones de compresión y deduplicación se pueden cambiar también para un LV VDO activo. Las opciones de menor prioridad se especifican con el archivo de configuración, luego con --vdosettings y las más altas son las opciones explícitas --compression y --deduplication.

Ejemplo

# lvcreate --vdo -L10G --vdosettings 'ack_threads=1 hash_zone_threads=2' vg/vdopool0
# lvchange --vdosettings 'bio_threads=2 deduplication=1' vg/vdopool0

6. Verificar el uso de VDOPoolLV

Para verificar rápidamente cuántos datos en un VDOPoolLV ya se han consumido, use lvs(8)

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

. El campo % de Datos informa cuántos datos están ocupados en el contenido de los datos virtuales para VDOLV y cuánto espacio ya se ha consumido con todos los bloques de datos y metadatos en VDOPoolLV. Para una descripción detallada, utilice el comando vdostats(8).

Nota: vdostats(8) actualmente solo entiende los nombres de dispositivo de /dev/mapper.

Ejemplo

# lvcreate --type vdo -L10G -V20G -n vdo0 vg/vdopool0
# mkfs.ext4 -E nodiscard /dev/vg/vdo0
# lvs -a vg
  LV               VG Attr       LSize  Pool     Origin Data%
  vdo0             vg vwi-a-v--- 20.00g vdopool0        0.01
  vdopool0         vg dwi-ao---- 10.00g                 30.16
  [vdopool0_vdata] vg Dwi-ao---- 10.00g
# vdostats --all /dev/mapper/vg-vdopool0-vpool
/dev/mapper/vg-vdopool0 :
  version                             : 30
  release version                     : 133524
  data blocks used                    : 79
  ...

7. Ampliación del tamaño de VDOPoolLV

Puede añadir más espacio para almacenar datos y metadatos de VDO ampliando VDODataLV utilizando los comandos lvresize(8) y lvextend(8). La ampliación debe añadir al menos una nueva losa de VDO. Puede configurar el tamaño de la losa con el ajuste allocation/vdo_slab_size_mb.

También puede habilitar la ampliación automática del tamaño de un VDOPoolLV supervisado con los ajustes activation/vdo_pool_autoextend_percent y activation/vdo_pool_autoextend_threshold.

Nota: No puede reducir el tamaño de un VDOPoolLV.

lvextend -L+TamañoAMás VG/VDOPoolLV

Ejemplo

# lvextend -L+50G vg/vdopool0
# lvresize -L300G vg/vdopool1

8. Ampliación o reducción del tamaño de VDOLV

Puede ampliar o reducir un VDO LV virtual como un LV estándar con los comandos lvresize(8), lvextend(8) y lvreduce(8).

Nota: La reducción necesita procesar TRIM para que el área de disco reducida desmapee los bloques de datos utilizados de VDOPoolLV, lo que puede llevar mucho tiempo.

lvextend -L+TamañoAMás VG/VDOLV
lvreduce -L-TamañoAMenos VG/VDOLV

Ejemplo

# lvextend -L+50G vg/vdo0
# lvreduce -L-50G vg/vdo1
# lvresize -L200G vg/vdo2

9. Activación de componentes de un VDODataLV

Puede activar un VDODataLV por separado como un LV de componente para fines de examen. La activación del VDODataLV activa el LV de datos en modo de solo lectura, y el LV de datos no se puede modificar. Si el VDODataLV está activo como componente, cualquier LV superior que utilice este volumen NO podrá activarse. Debe desactivar primero el VDODataLV para continuar utilizando el VDOPoolLV.

Ejemplo

# lvchange -ay vg/vpool0_vdata
# lvchange -an vg/vpool0_vdata

TEMAS DE VDO

1. Apilamiento de VDO

Puede convertir o apilar un VDOPooLV con los siguientes tipos de volumen actualmente soportados: lineal, stripe, raid y caché con cachépool.

1. Uso de varios volúmenes utilizando el mismo VDOPoolLV

Puede convertir un LV VDO existente en un volumen thin. Después de esta conversión, puede crear una instantánea thin o añadir más volúmenes thin con un pool thin cuyo nombre sea el mismo que el nombre del LV original, LV_tpool0. Consulte lvmthin(7) para más detalles.

Ejemplo

# lvcreate --type vdo -L 5G -V 10G -n vdo1 vg/vdopool
# lvconvert --type thin vg/vdo1
# lvcreate -V20 vg/vdo1_tpool0

2. VDOPoolLV sobre raid

Uso de un LV de tipo raid para un VDODataLV.

Ejemplo

# lvcreate --type raid1 -L 5G -n vdopool vg
# lvconvert --type vdo-pool -V 10G vg/vdopool

3. Caché de un VDOPoolLV

El caché de VDOPoolLV (acepta también el nombre de volumen VDODataLV) proporciona un mecanismo para acelerar las lecturas y escrituras de bloques ya comprimidos y deduplicados junto con los metadatos de VDO.

Ejemplo

# lvcreate --type vdo -L 5G -V 10G -n vdo1 vg/vdopool
# lvcreate --type cache-pool -L 1G -n cachepool vg
# lvconvert --cache --cachepool vg/cachepool vg/vdopool
# lvconvert --uncache vg/vdopool

4. Caché de un VDOLV

El caché de LV VDO le permite "cachéar" un dispositivo para un mejor rendimiento antes de que llegue al procesamiento de la capa VDO Pool LV.

Ejemplo

# lvcreate --type vdo -L 5G -V 10G -n vdo1 vg/vdopool
# lvcreate --type cache-pool -L 1G -n cachepool vg
# lvconvert --cache --cachepool vg/cachepool vg/vdo1
# lvconvert --uncache vg/vdo1

5. Uso de Descarte/TRIM con un VDOLV

Puede descartar datos en un VDO LV y reducir los bloques utilizados en un VDOPoolLV. Sin embargo, el rendimiento actual de las operaciones de descarte todavía no es óptimo y lleva una cantidad considerable de tiempo y CPU. A menos que realmente lo necesite, debe evitar el uso del descarte.

Cuando un dispositivo de bloques va a ser reescrito, sus bloques se reutilizarán automáticamente para nuevos datos. El descarte es útil en situaciones en las que el usuario sabe que la porción dada de un VDO LV no se va a utilizar y el espacio descartado se puede utilizar para el aprovisionamiento de bloques en otras regiones del VDO LV. Por la misma razón, debe evitar usar mkfs con descarte para un VDO LV recién creado para ahorrar mucho tiempo que esta operación llevaría de lo contrario, ya que se espera que el dispositivo ya esté vacío.

6. Uso de memoria

El destino VDO requiere 38 MiB de RAM y varias cantidades variables:

  • 1.15 MiB de RAM por cada 1 MiB de tamaño de caché de mapa de bloques configurado. La caché de mapa de bloques requiere un mínimo de 150 MiB de RAM.
  • 1.6 MiB de RAM por cada 1 TiB de espacio lógico.
  • 268 MiB de RAM por cada 1 TiB de almacenamiento físico gestionado por el volumen.

UDS requiere un mínimo de 250 MiB de RAM, que también es la cantidad predeterminada que utiliza la deduplicación.

La memoria requerida para el índice UDS viene determinada por el tipo de índice y el tamaño requerido de la ventana de deduplicación y está controlada por el ajuste allocation/vdo_use_sparse_index.

Con la indexación dispersa UDS habilitada, se basa en la localidad temporal de los datos e intenta retener solo las entradas de índice más relevantes en memoria y puede mantener una ventana de deduplicación que es diez veces mayor que con la dispersa, utilizando la misma cantidad de memoria.

Aunque el índice disperso proporciona la mayor cobertura, el índice denso proporciona más asesoramiento de deduplicación. Para la mayoría de las cargas de trabajo, dada la misma cantidad de memoria, la diferencia en las tasas de deduplicación entre los índices denso y disperso es insignificante.

Un índice denso con 1 GiB de RAM mantiene una ventana de deduplicación de 1 TiB, mientras que un índice disperso con 1 GiB de RAM mantiene una ventana de deduplicación de 10 TiB. En general, 1 GiB es suficiente para 4 TiB de almacenamiento físico con un índice denso y 40 TiB con un índice disperso.

7. Requisitos de espacio de almacenamiento

Puede configurar un VDOPoolLV para que utilice hasta 256 TiB de almacenamiento físico. Solo una parte del almacenamiento físico es utilizable para almacenar datos. Esta sección proporciona los cálculos para determinar el tamaño utilizable de un volumen gestionado por VDO.

El destino VDO requiere almacenamiento para dos tipos de metadatos de VDO y para el índice UDS:

  • El primer tipo de metadatos de VDO utiliza aproximadamente 1 MiB por cada 4 GiB de almacenamiento físico más 1 MiB adicional por losa.
  • El segundo tipo de metadatos de VDO consume aproximadamente 1.25 MiB por cada 1 GiB de almacenamiento lógico, redondeado al alza a la losa más cercana.
  • La cantidad de almacenamiento requerida para el índice UDS depende del tipo de índice y la cantidad de RAM asignada al índice. Por cada 1 GiB de RAM, un índice UDS denso utiliza 17 GiB de almacenamiento y un índice UDS disperso utilizará 170 GiB de almacenamiento.

NAME

lvmvdo — Virtual Data Optimizer (VDO) concepts

DESCRIPTION

Virtual Data Optimizer (VDO) is a software-based data deduplication and compression system for Linux. It can be used to reduce the amount of disk space required to store data. VDO works by taking a block device (like a hard drive or SSD) and presenting a larger block device to the operating system. It then intercepts writes to the larger device, checks if the data has already been stored, and if not, compresses and stores it. Reads are similarly intercepted to retrieve the original, uncompressed data.

LVM provides commands to create, manage, and monitor VDO volumes. These commands are part of the LVM toolset and integrate VDO functionality into the LVM volume management framework.

VDO volumes can be created on top of LVM logical volumes or directly on raw devices. They can be used for various purposes, including storing virtual machine images, backups, and general file systems.

VDO TERMS

VDO Volume:
A block device managed by VDO. It appears larger than the underlying physical storage and provides deduplication and compression.
Underlying Device:
The physical storage (e.g., a logical volume, a partition, a whole disk) on which the VDO volume is built.
Deduplication:
The process of identifying and eliminating redundant copies of data. VDO stores only unique blocks of data, saving space.
Compression:
The process of reducing the size of data by encoding it using fewer bits. VDO can compress data before storing it.
Block Lander:
A virtual block device driver that VDO uses to present the virtual device to the operating system.
Metadata:
Information that VDO uses to manage the deduplication and compression process, such as block mappings and checksums.

VDO USAGE

To use VDO with LVM, you typically perform the following steps:

  1. Create an underlying logical volume or use an existing raw device. This will be the storage for your VDO volume.

  2. Create a VDO volume using lvmvdo create. This command will format the underlying device with VDO metadata and make it available as a VDO block device.

    Example: 

    lvmvdo create --name my_vdo_volume --size 100G --virtualsize 500G /dev/my_vg/my_lv
    This creates a VDO volume named "my_vdo_volume" on the LVM logical volume "/dev/my_vg/my_lv". The VDO volume will have a virtual size of 500GB, but will use up to 100GB of physical storage.

  3. Create a file system on the VDO volume or use it as a block device. You can format the VDO volume with a file system like XFS or ext4, or use it directly for applications that require block devices.

    Example: 

    mkfs.xfs /dev/mapper/my_vdo_volume

  4. Mount the file system or access the block device.

    Example: 

    mount /dev/mapper/my_vdo_volume /mnt/vdo_data

Other LVM VDO commands include:

  • lvmvdo status: Show the status of VDO volumes.

  • lvmvdo resize: Resize a VDO volume.

  • lvmvdo remove: Remove a VDO volume.

  • lvmvdo suspend and lvmvdo resume: Suspend and resume VDO operations.
