DESCRIPCIÓN

lvcreate crea un nuevo LV en un VG. Para LVs estándar, esto requiere asignar extensiones lógicas de las extensiones físicas libres del VG. Si no hay suficiente espacio libre, el VG puede extenderse con otros PVs (vgextend(8)), o LVs existentes pueden reducirse o eliminarse (lvremove(8), lvreduce(8)).

Para controlar qué PVs usará un nuevo LV, especifique uno o más PVs como argumentos posicionales al final de la línea de comandos. lvcreate asignará extensiones físicas solo desde los PVs especificados.

lvcreate también puede crear instantáneas de LVs existentes, por ejemplo para propósitos de respaldo. Los datos en una nueva LV de instantánea representan el contenido del LV original desde el momento en que se creó la instantánea.

Los LVs RAID pueden crearse especificando un tipo de LV al crear el LV (ver lvmraid(7)). Diferentes niveles RAID requieren diferentes números de PVs únicos disponibles en el VG para su asignación.

Los pools delgados (para aprovisionamiento delgado) y los pools de caché (para caché) se representan mediante LVs especiales con tipos thin-pool y cache-pool (ver lvmthin(7) y lvmcache(7)). Los LVs de pool no son utilizables como dispositivos de bloque estándar, pero los nombres de LV actúan como referencias a los pools.

Los LVs delgados se aprovisionan de forma delgada desde un pool delgado y se crean con un tamaño virtual en lugar de un tamaño físico. Un LV de caché es la combinación de un LV estándar con un pool de caché, utilizado para almacenar en caché porciones activas del LV para mejorar el rendimiento.

Los LVs VDO también son volúmenes aprovisionados desde un pool VDO y se crean con un tamaño virtual en lugar de un tamaño físico (ver lvmvdo(7)).

Notas de uso

En la sección de uso a continuación, --size Tamaño puede ser reemplazado con --extents Número. Ver las descripciones en la sección de opciones.

En la sección de uso a continuación, se omite --name de las opciones requeridas, aunque típicamente se usa. Cuando no se especifica el nombre, se genera un nuevo nombre de LV con el prefijo "lvol" y un sufijo numérico único.

En la sección de uso a continuación, al crear un pool y omitir el nombre, se genera el nuevo nombre de LV del pool con el prefijo "vpool" para vdo-pools y un sufijo numérico único.

El nombre del pool puede especificarse junto con el nombre del VG, es decir: vg00/mi_pool_delgado.

OPCIONES

-a|--activate y|n|ay
Controla el estado activo del nuevo LV. y activa el LV, haciéndolo disponible. Los nuevos LVs se activan por defecto. n desactiva el LV, haciéndolo no disponible, solo cuando sea posible. En algunos casos, crear un LV requiere que esté activo. Por ejemplo, las instantáneas COW de un LV de origen activo solo se pueden crear en estado activo (esto no se aplica a las instantáneas thin). La opción --zero normalmente requiere que el LV esté activo. Si se utiliza la autoactivación ay, el LV solo se activará si coincide con un elemento en la lista lvm.conf(5) activation/auto_activation_volume_list. ay implica --zero n y --wipesignatures n. Consulte lvmlockd(8) para obtener más información sobre las opciones de activación para VGs compartidos.
--addtag Etiqueta
Añade una etiqueta a un PV, VG o LV. Esta opción se puede repetir para añadir varias etiquetas a la vez. Consulte lvm(8) para obtener información sobre etiquetas.
--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Determina la política de asignación cuando un comando necesita asignar Extensiones Físicas (PEs) del VG. Cada VG y LV tiene una política de asignación que se puede cambiar con vgchange/lvchange, o anular en la línea de comandos. normal aplica reglas de sentido común, como no colocar franjas paralelas en el mismo PV. inherit aplica la política del VG a un LV. contiguous requiere que las nuevas PEs se coloquen adyacentes a las PEs existentes. cling coloca las nuevas PEs en el mismo PV que las PEs existentes en la misma franja del LV. Si hay suficientes PEs para una asignación, pero normal no las utiliza, anywhere las utilizará incluso si reduce el rendimiento, por ejemplo, colocando dos franjas en el mismo PV. Los argumentos posicionales opcionales de PV en la línea de comandos también se pueden usar para limitar qué PVs utilizará el comando para la asignación. Consulte lvm(8) para obtener más información sobre la asignación.
-A|--autobackup y|n
Especifica si los metadatos deben ser respaldados automáticamente después de un cambio. ¡Habilitar esto es muy recomendable! Consulte vgcfgbackup(8) para obtener más información.
-H|--cache
Especifica que el comando maneja un LV de caché o un pool de caché. Ver --type cache y --type cache-pool. Consulte lvmcache(7) para obtener más información sobre el caché de LVM.
--cachedevice PV
El nombre de un dispositivo para usar en un caché.
--cachemetadataformat auto|1|2
Especifica el formato de metadatos de caché utilizado por el destino de caché.
--cachemode writethrough|writeback|passthrough
Especifica cuándo se deben considerar completas las escrituras en un LV de caché. writeback considera una escritura completa tan pronto como se almacena en el pool de caché. writethrough considera una escritura completa solo cuando se ha almacenado tanto en el pool de caché como en el LV de origen. Si bien writethrough puede ser más lento para las escrituras, es más resistente si algo le sucede a un dispositivo asociado con el LV de pool de caché. Con passthrough, todas las lecturas se sirven desde el LV de origen (todas las lecturas fallan en el caché) y todas las escrituras se reenvían al LV de origen; además, los aciertos de escritura causan la invalidación de bloques de caché. Consulte lvmcache(7) para obtener más información.
--cachepolicy Cadena
Especifica la política de caché para un LV de caché. Consulte lvmcache(7) para obtener más información.
--cachepool LV
El nombre de un pool de caché.
--cachesettings Cadena
Especifica opciones de kernel sintonizables para los LVs de caché dm-cache o dm-writecache. Utilice el formato 'opción=valor' o 'opción1=valor opción2=valor', o repita --cachesettings para cada opción que se establezca. Estas configuraciones anulan los comportamientos predeterminados del kernel que suelen ser adecuados. Para eliminar la configuración de caché y volver a los comportamientos predeterminados del kernel, use --cachesettings 'default' para dm-cache o una cadena vacía --cachesettings '' para dm-writecache. Consulte lvmcache(7) para obtener más información.
--cachesize Tamaño[m|UNIDAD]
El tamaño del caché a utilizar.
--cachevol LV
El nombre de un volumen de caché.
-c|--chunksize Tamaño[k|UNIDAD]
El tamaño de los fragmentos en una instantánea, pool de caché o pool thin. Para las instantáneas, el valor debe ser una potencia de 2 entre 4 KiB y 512 KiB y el valor predeterminado es 4. Para un pool de caché, el valor debe estar entre 32 KiB y 1 GiB y el valor predeterminado es 64. Para un pool thin, el valor debe estar entre 64 KiB y 1 GiB y el valor predeterminado comienza en 64 y aumenta hasta que el tamaño de los metadatos del pool encaje dentro de 128 MiB, si el tamaño de los metadatos del pool no se especifica. El valor debe ser un múltiplo de 64 KiB. Consulte lvmthin(7) y lvmcache(7) para obtener más información.
--commandprofile Cadena
El perfil de comando a utilizar para la configuración del comando. Consulte lvm.conf(5) para obtener más información sobre los perfiles.
--compression y|n
Controla si la compresión está habilitada o deshabilitada para el volumen VDO. Consulte lvmvdo(7) para obtener más información sobre el uso de VDO.
--config Cadena
Configuración del comando. Estas anulan la configuración de lvm.conf(5). La cadena de argumento utiliza el mismo formato que lvm.conf(5), o puede usar la sintaxis de sección/campo. Consulte lvm.conf(5) para obtener más información sobre la configuración.
-C|--contiguous y|n
Establece o restablece la política de asignación contigua para LVs. El valor predeterminado es no asignación contigua basada en un principio de siguiente libre. Solo es posible cambiar una política de asignación no continua a continua si todas las extensiones físicas asignadas en el LV son ya contiguas.
-d|--debug ...
Establece el nivel de depuración. Repita de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--deduplication y|n
Controla si la deduplicación está habilitada o deshabilitada para el volumen VDO. Consulte lvmvdo(7) para obtener más información sobre el uso de VDO.
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción se puede repetir, o acepta una lista de dispositivos separados por comas. Esto anula el archivo de dispositivos.
--devicesfile Cadena
Un archivo que enumera los dispositivos que LVM debe utilizar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración de lvm.conf(5) devices/devicesfile y devices/use_devicesfile.
--discards passdown|nopassdown|ignore
Especifica cómo la capa del pool thin del mapeador de dispositivos en el kernel debe manejar los descartes. ignore hace que el pool thin ignore los descartes. nopassdown hace que el pool thin procese los descartes por sí mismo para permitir la reutilización de extensiones innecesarias en el pool thin. passdown hace que el pool thin procese los descartes i
tself (como nopassdown) y pasa los descartes al dispositivo subyacente. Ver lvmthin(7) para más información.
--driverloaded s|n
Si se establece en no, el comando no intentará usar device-mapper. Para pruebas y depuración.
--errorwhenfull s|n
Especifica el comportamiento del pool delgado cuando el espacio de datos se agota. Cuando es sí, device-mapper devolverá un error inmediatamente cuando un pool delgado esté lleno y una solicitud de E/S requiera espacio. Cuando es no, device-mapper pondrá en cola estas solicitudes de E/S durante un período de tiempo para permitir que el pool delgado se extienda. Se devolverán errores si no hay espacio disponible después del tiempo de espera. (Ver también la opción del módulo del kernel "dm_thin_pool" no_space_timeout.) Ver lvmthin(7) para más información.
-l|--extents Número[PORCENTAJE]
Especifica el tamaño del nuevo LV en extents lógicos. Las opciones --size y --extents son métodos alternativos para especificar el tamaño. El número total de extents físicos utilizados será mayor cuando se necesiten datos redundantes para niveles de RAID. Una sintaxis alternativa permite que el tamaño se determine indirectamente como un porcentaje del tamaño de un VG, LV o conjunto de PV relacionados. El sufijo %VG denota el tamaño total del VG, el sufijo %FREE el espacio libre restante en el VG, y el sufijo %PVS el espacio libre en los PV especificados. Para una instantánea, el tamaño puede expresarse como un porcentaje del tamaño total del LV de origen con el sufijo %ORIGIN (100%ORIGIN proporciona espacio para todo el origen). Cuando se expresa como un porcentaje, el tamaño define un límite superior para el número de extents lógicos en el nuevo LV. El número preciso de extents lógicos en el nuevo LV no se determina hasta que el comando se completa.

--mirrorlog core|disk
Especifica el tipo de log de espejo para LVs de tipo "mirror" (no se aplica al tipo "raid1"). disk es un log persistente y requiere una pequeña cantidad de espacio de almacenamiento, generalmente en un dispositivo separado de los datos que se espejan. core no es persistente; el log se mantiene solo en memoria. -m|--mirrors Número

--nosync
Hace que la creación de espejo, raid1, raid4, raid5 y raid10 omita la sincronización inicial. En el caso de espejo, raid1 y raid10, cualquier dato escrito posteriormente se duplicará, pero el contenido original no se copiará. En el caso de raid4 y raid5, no se escribirán bloques de paridad, aunque cualquier dato escrito posteriormente provocará que se almacenen bloques de paridad. Esto es útil para omitir una sincronización inicial potencialmente larga y que consume recursos de un LV de espejo/raid1/raid4/raid5 y raid10 vacío. Esta opción no es válida para raid6, ya que raid6 depende de una paridad correcta (síndromes P y Q) creada durante la sincronización inicial para poder reconstruir datos de usuario correctos en caso de fallos de dispositivo. raid0 y raid0_meta no proporcionan copias de datos ni soporte de paridad y, por lo tanto, no admiten la sincronización inicial.
--noudevsync
Deshabilita la sincronización de udev. El proceso no esperará la notificación de udev. Continuará independientemente de cualquier posible procesamiento de udev en segundo plano. Utilice esto solo si udev no se está ejecutando o tiene reglas que ignoran los dispositivos que LVM crea.

Utiliza un journal (predeterminado) o un bitmap para mantener consistentes las sumas de verificación de integridad en caso de un fallo. El modo bitmap, en teoría, puede lograr escritura completa

OPCIONES

-o|--contiguous 
Intenta crear el LV de forma contigua. Para LVs de tipo raid, esto puede afectar el rendimiento del dispositivo, pero no se beneficiará de la posible optimización de escritura dispersa.
-r|--readahead auto|none|Número
Establece el recuento de sectores de prelectura de un LV. auto es el valor predeterminado, que permite al kernel elegir un valor adecuado automáticamente. none es equivalente a cero.
-R|--regionsize Tamaño[m|UNIDAD]
Tamaño de cada región de sincronización de raid o espejo. lvm.conf(5) activation/raid_region_size puede usarse para configurar un valor predeterminado.
--reportformat basic|json|json_std
Anula el formato de salida actual para los informes, que se define globalmente mediante la configuración report/output_format en lvm.conf(5). basic es el formato original con columnas y filas. Si hay más de un informe por comando, cada informe va precedido del nombre del informe para su identificación. json produce la salida del informe en formato JSON. json_std produce la salida del informe en formato JSON que cumple más con el estándar JSON. Consulte lvmreport(7) para obtener más información.
-k|--setactivationskip y|n
Establece persistentemente (yes) o borra (no) la bandera "activation skip" en un LV. Un LV con esta bandera activada no se activará a menos que se utilice la opción --ignoreactivationskip con el comando de activación. Esta bandera se establece por defecto en los nuevos LV de instantánea thin. La bandera no se aplica a la desactivación. El valor actual de la bandera se indica en los bits lv_attr de lvs.
--setautoactivation y|n
Establece la propiedad de autoactivación en un VG o LV. Muestra la propiedad con vgs o lvs con "-o autoactivation". Cuando la propiedad de autoactivación está desactivada, el VG o LV no será activado por un comando que realice autoactivación (vgchange, lvchange o pvscan usando -aay). Si la autoactivación está desactivada en un VG, ningún LV se autoactivará en ese VG, y la propiedad de autoactivación del LV no tendrá efecto. Si la autoactivación está activada en un VG, la autoactivación puede ser desactivada para LVs individuales.
-L|--size Tamaño[m|UNIDAD]
Especifica el tamaño del nuevo LV. Las opciones --size y --extents son métodos alternativos para especificar el tamaño. El número total de extents físicos utilizados será mayor cuando se necesiten datos redundantes para los niveles de RAID.
-s|--snapshot
Crea una instantánea. Las instantáneas proporcionan una "imagen congelada" de un LV de origen. El LV de instantánea puede usarse, por ejemplo, para copias de seguridad, mientras que el LV de origen continúa usándose. Esta opción puede crear una instantánea de COW (copia en escritura), o una instantánea thin (en un pool thin). Las instantáneas thin se crean cuando el origen es un LV thin y la opción size NO se especifica. Las instantáneas thin comparten los mismos bloques en el pool thin y no asignan nuevo espacio del VG. Las instantáneas thin se crean con la bandera "activation skip", consulte --setactivationskip. Se crea una instantánea thin de un LV "external origin" no thin cuando se especifica un pool thin. Los bloques no aprovisionados en el LV de instantánea thin se leen del LV de origen externo. El LV de origen externo debe ser de solo lectura. Consulte lvmthin(7) para obtener más información sobre el aprovisionamiento thin de LVM. Las instantáneas COW se crean cuando se especifica un tamaño. El tamaño se asigna del espacio en el VG y es la cantidad de espacio que se puede utilizar para guardar bloques COW a medida que ocurren escrituras en el origen o la instantánea. El tamaño elegido debe depender de la cantidad de escrituras que se esperan; a menudo, el 20% del LV de origen es suficiente. Si el espacio COW se agota, se puede ampliar con lvextend (también se permite reducir con lvreduce). Una pequeña cantidad del tamaño del LV de instantánea COW se utiliza para rastrear las ubicaciones de los bloques COW, por lo que el tamaño completo no está disponible para los bloques de datos COW. Use lvs para verificar cuánto espacio se utiliza y consulte --monitor para extender automáticamente el tamaño y evitar quedarse sin espacio.
-i|--stripes Número
Especifica el número de franjas en un LV con franjas. Este es el número de PVs (dispositivos) en los que se distribuye un LV con franjas. Los datos que aparecen secuencialmente en el LV se distribuyen en varios dispositivos en unidades del tamaño de la franja (ver --stripesize). Esto no cambia el espacio asignado existente, sino que solo se aplica al espacio que está siendo asignado por el comando. Al crear un LV de tipo RAID 4/5/6, este número no incluye los dispositivos adicionales que se requieren para la paridad. El número más grande depende del tipo de RAID (raid0: 64, raid10: 32, raid4/5: 63, raid6: 62), y cuando no se especifica, el valor predeterminado depende del tipo de RAID (raid0: 2, raid10: 2, raid4/5: 3, raid6: 5). Para fraccionar un nuevo LV raid en todos los PV por defecto, consulte lvm.conf(5) allocation/raid_stripe_all_devices.
-I|--stripesize Tamaño[k|UNIDAD]
La cantidad de datos que se escribe en un dispositivo antes de pasar al siguiente en un LV con franjas.
-t|--test
Ejecutar en modo de prueba. Los comandos no actualizarán metadatos. Esto se implementa desactivando toda escritura de metadatos, pero devolviendo éxito a la función llamadora. Esto puede llevar a mensajes de error inusuales en operaciones de múltiples etapas si una herramienta depende de leer metadatos que cree que han cambiado, pero no lo han hecho.

El tamaño virtual de un nuevo LV thin. Consulte lvmthin(7) para obtener más información sobre el aprovisionamiento thin de LVM. El uso conjunto de tamaño virtual (-V) y tamaño real (-L) crea un LV disperso (sparse). lvm.conf(5) global/sparse_segtype_default determina el tipo de segmento predeterminado utilizado para crear un LV disperso. VARIABLES

TYPE DEFINITIONS

VG
Nombre del Grupo de Volúmenes. Consulte lvm(8) para nombres válidos. Para lvcreate, el argumento posicional requerido VG puede omitirse cuando el nombre del VG se incluye en otra opción, por ejemplo, --name VG/LV.
LV
Nombre del Volumen Lógico. Consulte lvm(8) para nombres válidos. Un argumento posicional LV generalmente incluye el nombre del VG y el nombre del LV, por ejemplo, VG/LV. LV1 indica que el LV debe tener un tipo específico, donde se enumeran los tipos de LV aceptados. (raid representa el tipo raid<N>).
PV
Nombre del Volumen Físico, una ruta de dispositivo bajo /dev. Para comandos que gestionan extents físicos, un argumento posicional PV generalmente acepta un sufijo que indica un rango (o varios rangos) de extents físicos (PE). Cuando se omite el primer PE, se asume el inicio del dispositivo, y cuando se omite el último PE, se asume el final.
Rango de inicio y fin (inclusive): PV[:PE-PE] ...
Rango de inicio y longitud (contando desde 0): PV[:PE+PE] ...
String
Consulte la descripción de la opción para obtener información sobre el contenido de la cadena.
Size[UNIT]
Tamaño es un número de entrada que acepta una unidad opcional. Las unidades de entrada se tratan siempre como valores base dos, independientemente de las mayúsculas, por ejemplo, 'k' y 'K' se refieren ambos a 1024. La unidad de entrada predeterminada se especifica por letra, seguida de |UNIT. UNIT representa otras unidades de entrada posibles: b|B es bytes, s|S son sectores de 512 bytes, k|K es KiB, m|M es MiB, g|G es GiB, t|T es TiB, p|P es PiB, e|E es EiB. (Esto no debe confundirse con el control de salida --units, donde las letras mayúsculas significan múltiplo de 1000.)

Consulte lvm(8) para obtener información sobre las variables de entorno utilizadas por lvm. Por ejemplo, LVM_VG_NAME generalmente puede sustituirse por un parámetro VG requerido.

EJEMPLOS

Crear un LV rayado con 3 rayaduras, un tamaño de rayadura de 8 KiB y un tamaño de 100 MiB. El nombre del LV es elegido por lvcreate.
lvcreate -i 3 -I 8 -L 100m vg00

Crear un LV raid1 con dos imágenes y un tamaño utilizable de 500 MiB. Esta operación requiere dos dispositivos, uno para cada imagen de espejo. Los metadatos RAID (superbloque y mapa de bits) también están incluidos en los dos dispositivos.
lvcreate --type raid1 -m1 -L 500m -n mylv vg00

Crear un LV espejo con dos imágenes y un tamaño utilizable de 500 MiB. Esta operación requiere tres dispositivos: dos para las imágenes del espejo y uno para un registro de disco.
lvcreate --type mirro

EJEMPLOS

Crear un LV de espejo con 2 imágenes y un tamaño utilizable de 500 MiB. Esta operación requiere 2 dispositivos porque el registro está en memoria.
lvcreate --type mirror -m1 --mirrorlog core -L 500m -n mylv vg00

Crear una instantánea de copia en escritura de un LV:
lvcreate --snapshot --size 100m --name mysnap vg00/mylv

Crear una instantánea de copia en escritura con un tamaño suficiente para sobrescribir el 20% del tamaño del LV original.
lvcreate -s -l 20%ORIGIN -n mysnap vg00/mylv

Crear un LV disperso con 1 TiB de espacio virtual y espacio real inferior a 100 MiB.
lvcreate --snapshot --virtualsize 1t --size 100m --name mylv vg00

Crear un LV lineal con un tamaño utilizable de 64 MiB en extensiones físicas específicas.
lvcreate -L 64m -n mylv vg00 /dev/sda:0-7 /dev/sdb:0-7

Crear un LV RAID5 con un tamaño utilizable de 5 GiB, 3 franjas, un tamaño de franja de 64 KiB, utilizando un total de 4 dispositivos (incluido uno para paridad).
lvcreate --type raid5 -L 5G -i 3 -I 64 -n mylv vg00

Crear un LV RAID5 utilizando todo el espacio libre en el VG y extendiendo todos los PV en el VG (tenga en cuenta que el comando fallará si hay más de 8 PV en el VG, en cuyo caso se debe usar -i 7 para llegar al máximo actual de 8 dispositivos, incluida la paridad para RaidLVs).
lvcreate --config allocation/raid_stripe_all_devices=1 --type raid5 -l 100%FREE -n mylv vg00

Crear un LV RAID10 con un tamaño utilizable de 5 GiB, utilizando 2 franjas, cada una en un espejo de dos imágenes. (Tenga en cuenta que los argumentos -i y -m se comportan de manera diferente: -i especifica el número total de franjas, pero -m especifica el número de imágenes además de la primera imagen).
lvcreate --type raid10 -L 5G -i 2 -m 1 -n mylv vg00

Crear un LV fino de 1 TiB mythin, con un thinpool tpool0 de 256 GiB en vg00.
lvcreate -T -V 1T --size 256G --name mythin vg00/tpool0

Crear un LV fino de 1 TiB, creando primero un nuevo thin pool para él, donde el thin pool tiene 100 MiB de espacio, utiliza 2 franjas, tiene un tamaño de franja de 64 KiB y un tamaño de bloque de 256 KiB.
lvcreate --type thin --name mylv --thinpool mypool -V 1t -L 100m -i 2 -I 64 -c 256 vg00

Crear una instantánea fina de un LV fino (no se debe usar la opción size, de lo contrario se crearía una instantánea de copia en escritura).
lvcreate --snapshot --name mysnap vg00/thinvol

Crear una instantánea fina del LV inactivo de solo lectura llamado "origin", que se convierte en un origen externo para el LV de instantánea fina.
lvcreate --snapshot --name mysnap --thinpool mypool vg00/origin

Crear un pool de caché a partir de un dispositivo físico rápido. El pool de caché se puede usar para almacenar en caché un LV.
lvcreate --type cache-pool -L 1G -n my_cpool vg00 /dev/fast1

Crear un LV de caché, creando primero un nuevo LV de origen en un dispositivo físico lento y luego combinando el nuevo LV de origen con un pool de caché existente.
lvcreate --type cache --cachepool my_cpool -L 100G -n mylv vg00 /dev/slow1

Crear un LV VDO vdo0 con un tamaño de VDOPoolLV de 10 GiB y un nombre vpool1.
lvcreate --vdo --size 10G --name vdo0 vg00/vpool1
