DESCRIPCIÓN

lvchange cambia los atributos de LV en el VG, cambia la activación de LV en el kernel e incluye otras utilidades para el mantenimiento de LV.

OPTIONS

-a|--activate y|n|ay
Cambia el estado activo de los LV. Un LV activo puede ser utilizado a través de un dispositivo de bloques, permitiendo el acceso a los datos del LV. y hace que los LV estén activos o disponibles. n hace que los LV estén inactivos o no disponibles. El dispositivo de bloques para el LV se añade o elimina del sistema utilizando el device-mapper en el kernel. También se añade/elimina un enlace simbólico /VGName/LVName que apunta al nodo del dispositivo. Todo el software y los scripts deben acceder al dispositivo a través del enlace simbólico y presentarlo como el nombre del dispositivo. La ubicación y el nombre del nodo del dispositivo subyacente pueden depender de la distribución, la configuración (por ejemplo, udev) o la versión de la publicación. ay especifica la autoactivación, que es utilizada por los comandos de activación generados por el sistema. Por defecto, los LV se autoactivan. Se puede establecer una propiedad de autoactivación en un VG o LV para deshabilitar la autoactivación, ver --setautoactivation y|n en vgchange, lvchange, vgcreate y lvcreate. Muestra la propiedad con vgs o lvs ""-o autoactivation"". La lista auto_activation_volume_list de lvm.conf(5) incluye nombres de VGs o LVs que deben ser autoactivados, y todo lo que no está en la lista no se autoactiva. Cuando auto_activation_volume_list no está definida (por defecto), no tiene ningún efecto. Si auto_activation_volume_list está definida y vacía, no se autoactiva ningún LV. Los elementos incluidos en auto_activation_volume_list no se autoactivarán si la propiedad de autoactivación ha sido deshabilitada. Ver lvmlockd(8) para más información sobre las opciones de activación ey y sy para VGs compartidos.
--activationmode partial|degraded|complete
Determina si se permite la activación del LV cuando faltan PVs, por ejemplo, debido a un fallo de dispositivo. complete solo permite la activación de LVs sin PVs faltantes, y es el modo más restrictivo. degraded permite la activación de LVs RAID con PVs faltantes. (Esto no incluye el tipo "mirror", ver "raid1" en su lugar.) partial permite la activación de cualquier LV con PVs faltantes, y solo debe usarse para recuperación o reparación. Para el valor por defecto, ver lvm.conf(5) activation_mode. Ver lvmraid(7) para más información.
--addtag Tag
Añade una etiqueta a un PV, VG o LV. Esta opción se puede repetir para añadir varias etiquetas a la vez. Ver lvm(8) para información sobre etiquetas.
--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Determina la política de asignación cuando un comando necesita asignar Extensiones Físicas (PEs) del VG. Cada VG y LV tiene una política de asignación que puede ser cambiada con vgchange/lvchange, o anulada en la línea de comandos. normal aplica reglas de sentido común, como no colocar franjas paralelas en el mismo PV. inherit aplica la política del VG a un LV. contiguous requiere que las nuevas PEs se coloquen adyacentes a las PEs existentes. cling coloca las nuevas PEs en el mismo PV que las PEs existentes en la misma franja del LV. Si hay PEs suficientes para una asignación, pero normal no las utiliza, anywhere las utilizará aunque reduzca el rendimiento, por ejemplo, colocando dos franjas en el mismo PV. Los argumentos posicionales opcionales de PV en la línea de comandos también pueden usarse para limitar qué PVs utilizará el comando para la asignación. Ver lvm(8) para más información sobre asignación.
-A|--autobackup y|n
Especifica si los metadatos deben ser respaldados automáticamente después de un cambio. ¡Se recomienda encarecidamente habilitar esto! Ver vgcfgbackup(8) para más información.
--cachemode writethrough|writeback|passthrough
Especifica cuándo se consideran completas las escrituras en un LV de caché. writeback considera una escritura completa tan pronto como se almacena en el pool de caché. writethrough considera una escritura completa solo cuando se ha almacenado tanto en el pool de caché como en el LV de origen. Mientras que writethrough puede ser más lento para las escrituras, es más resistente si algo le sucede a un dispositivo asociado con el LV de caché. Con passthrough, todas las lecturas se atienden desde el LV de origen (todas las lecturas fallan en la caché) y todas las escrituras se reenvían al LV de origen; además, las escrituras que aciertan provocan invalidez de bloques de caché. Ver lvmcache(7) para más información.
--cachepolicy String
Especifica la política de caché para un LV de caché. Ver lvmcache(7) para más información.
--cachesettings String
Especifica opciones ajustables del kernel para LVs de caché dm-cache o dm-writecache. Utiliza el formato 'opción=valor' o 'opción1=valor opción2=valor', o repite --cachesettings para cada opción que se esté estableciendo. Estas configuraciones anulan los comportanientos predeterminados del kernel que suelen ser adecuados. Para eliminar cachesettings y volver a los comportamientos predeterminados del kernel, usa --cachesettings 'default' para dm-cache o una cadena vacía --cachesettings '' para dm-writecache. Ver lvmcache(7) para más información.
--commandprofile String
El perfil de comando a utilizar para la configuración del comando. Ver lvm.conf(5) para más información sobre perfiles.
--compression y|n
Controla si la compresión está habilitada o deshabilitada para el volumen VDO. Ver lvmvdo(7) para más información sobre el uso de VDO.
--config String
Configuraciones de comando para el comando. Estas anulan los ajustes de lvm.conf(5). El argumento String usa el mismo formato que lvm.conf(5), o puede usar la sintaxis de sección/campo. Ver lvm.conf(5) para más información sobre la configuración.
-C|--contiguous y|n
Establece o restablece la política de asignación contigua para LVs. El valor predeterminado es la no asignación contigua basada en un principio de siguiente disponible. Solo es posible cambiar una política de asignación no contigua a contigua si todas las extensiones físicas asignadas en el LV son ya contiguas.
-d|--debug ...
Establece el nivel de depuración. Repite de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o syslog (si está configurado).
--deduplication y|n
Controla si la deduplicación está habilitada o deshabilitada para el volumen VDO. Ver lvmvdo(7) para más información sobre el uso de VDO.
--deltag Tag
Elimina una etiqueta de un PV, VG o LV. Esta opción se puede repetir para eliminar varias etiquetas a la vez. Ver lvm(8) para información sobre etiquetas.
--detachprofile
Desvincula un perfil de metadatos de un VG o LV. Ver lvm.conf(5) para más información sobre perfiles.
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción se puede repetir, o acepta una lista de dispositivos separada por comas. Esto anula el archivo de dispositivos.
--devicesfile String
Un archivo que lista los dispositivos que LVM debe usar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración devices/devicesfile y devices/use_devicesfile de lvm.conf(5).
--discards passdown|nopassdown|ignore
Especifica cómo debe manejar los descartes la capa de pool delgado del device-mapper en el kernel. ignore hace que el pool delgado ignore los descartes. nopassdown hace que el pool delgado procese los descartes por sí mismo para permitir la reutilización de extensiones no utilizadas en el pool delgado. passdown hace que el pool delgado procese los descartes
