DESCRIPCIÓN

lvresize redimensiona un LV de la misma manera que lvextend y lvreduce. Consulte lvextend(8) y lvreduce(8) para más información.

En la sección de uso a continuación, --size Tamaño puede ser reemplazado con --extents Número. Consulte la descripción de ambas opciones en la sección de opciones.

USO

Redimensionar un LV por un tamaño especificado.

lvresize -L|--size [+|-]Tamaño[m|UNIT] LV

[ -l|--extents [+|-]Número[PERCENT] ]
[ -r|--resizefs ]
[ --fs String ]
[ --fsmode String ]
[ --poolmetadatasize [+]Tamaño[m|UNIT] ]
[ OPCIONES_COMUNES ]
[ PV ... ]

—

Redimensionar un LV por extensiones de PV especificadas.

lvresize LV PV ...

[ -r|--resizefs ]
[ --fs String ]
[ --fsmode String ]
[ OPCIONES_COMUNES ]

—

Redimensionar un SubLV de metadatos de pool por un tamaño especificado.

lvresize --poolmetadatasize [+]Tamaño[m|UNIT] LV1

[ OPCIONES_COMUNES ]
[ PV ... ]

OPCIONES

--alloc contiguous|cling|cling_by_tags|normal|anywhere|inherit
Determina la política de asignación cuando un comando necesita asignar Extensiones Físicas (PEs) del VG. Cada VG y LV tiene una política de asignación que puede ser cambiada con vgchange/lvchange, o anulada en la línea de comandos. normal aplica reglas de sentido común como no colocar franjas paralelas en el mismo PV. inherit aplica la política del VG a un LV. contiguous requiere que las nuevas PEs se coloquen adyacentes a las PEs existentes. cling coloca las nuevas PEs en el mismo PV que las PEs existentes en la misma franja del LV. Si hay suficientes PEs para una asignación, pero normal no las usa, anywhere las usará incluso si reduce el rendimiento, por ejemplo, al colocar dos franjas en el mismo PV. Los argumentos posicionales opcionales de PV en la línea de comandos también pueden usarse para limitar qué PVs usará el comando para la asignación. Consulte lvm(8) para más información sobre la asignación.
-A|--autobackup y|n
Especifica si los metadatos deben ser respaldados automáticamente después de un cambio. ¡Habilitar esto es muy recomendable! Consulte vgcfgbackup(8) para más información.
--commandprofile String
El perfil de comando a usar para la configuración del comando. Consulte lvm.conf(5) para más información sobre perfiles.
--config String
Configuración del comando. Estas anulan la configuración de lvm.conf(5). El argumento String usa el mismo formato que lvm.conf(5), o puede usar sintaxis de sección/campo. Consulte lvm.conf(5) para más información sobre la configuración.
-d|--debug ...
Establece el nivel de depuración. Repetir de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción puede repetirse, o acepta una lista de dispositivos separada por comas. Esto anula el archivo de dispositivos.
--devicesfile String
Un archivo que lista los dispositivos que LVM debe usar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración devices/devicesfile y devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si se establece en no, el comando no intentará usar device-mapper. Para pruebas y depuración.
s="permalink" href="#l">-l|--extents [+|-]Número[PORCENTAJE]
Especifica el nuevo tamaño del LV en extensiones lógicas. Las opciones --size y --extents son métodos alternativos para especificar el tamaño. El número total de extensiones físicas utilizadas será mayor cuando se necesiten datos redundantes para niveles RAID. Una sintaxis alternativa permite que el tamaño se determine indirectamente como un porcentaje del tamaño de un VG, LV o conjunto de PV relacionados. El sufijo %VG denota el tamaño total del VG, el sufijo %FREE el espacio libre restante en el VG y el sufijo %PVS el espacio libre en los PV especificados. Para una instantánea, el tamaño se puede expresar como un porcentaje del tamaño total del LV de origen con el sufijo %ORIGIN (100%ORIGIN proporciona espacio para todo el origen). Cuando se expresa como un porcentaje, el tamaño define un límite superior para el número de extensiones lógicas en el nuevo LV. El número preciso de extensiones lógicas en el nuevo LV no se determina hasta que el comando se ha completado. Cuando se utiliza el prefijo más + o menos -, el valor no es un tamaño absoluto, sino que es relativo y se suma o resta del tamaño actual.
-f|--force ...
Anula varias comprobaciones, confirmaciones y protecciones. Usar con extrema precaución.
--fs Cadena
Controla el redimensionamiento del sistema de archivos al redimensionar un LV. checksize: Comprueba el tamaño del fs y reduce el LV si el fs no está utilizando el espacio reducido (no se necesita reducir el fs). Si el espacio reducido está siendo utilizado por el fs, entonces no se reduce el fs ni el LV, y se devuelve un error. (checksize solo se aplica al reducir, y no hace nada al extender). resize: Redimensiona el fs llamando al comando de redimensionamiento específico del fs. Esto también puede incluir el montaje, desmontaje o ejecución de fsck. Consulte --fsmode para controlar el comportamiento de montaje y --nofsck para desactivar fsck. resize_fsadm: Utiliza el método antiguo de llamar a fsadm para manejar el fs (obsoleto). Advertencia: esta opción no evita que lvreduce destruya sistemas de archivos que no están montados (o que lo están si se omiten las indicaciones). ignore: Redimensiona el LV sin comprobar ni manejar un sistema de archivos. Advertencia: usar ignore al reducir el tamaño del LV puede destruir el sistema de archivos.

Nota: Si se redimensiona un LV sin un sistema de archivos y el nuevo tamaño del LV coincide con el tamaño existente, el comando devuelve un código de estado distinto de cero (fallo). Sin embargo, si también se solicita redimensionar un sistema de archivos junto con el redimensionamiento del LV, y los tamaños ya coinciden, el comando devuelve un código de estado cero (éxito). Esto ocurre porque los comandos externos llamados para redimensionar el sistema de archivos devuelven éxito incluso si los tamaños del sistema de archivos nuevo y antiguo son idénticos. LVM sigue el comportamiento del código de estado del comando en este escenario.

--fsmode Cadena
Controla el comportamiento de montaje del sistema de archivos para el redimensionamiento del fs. manage: Monta o desmonta el fs según sea necesario para redimensionar el fs, e intenta restaurar el estado de montaje original al final. nochange: No monta ni desmonta el fs. Si se requiere montar o desmontar para redimensionar el fs, entonces no se redimensiona el fs ni el LV y el comando falla. offline: Desmonta el fs si está montado, y redimensiona el fs mientras está desmontado. Si se requiere montar para redimensionar el fs, entonces no se redimensiona el fs ni el LV y el comando falla.
-h|--help
Muestra el texto de ayuda.
--journal Cadena
Registra información en el journal de systemd. Esta información es adicional a la información habilitada por la configuración de registro/journal de lvm.conf. command: registra información sobre el comando. output: registra la salida predeterminada del comando. debug: registra la depuración completa del comando.
--lockopt Cadena
Se utiliza para pasar opciones para casos especiales a lvmlockd. Consulte lvmlockd(8) para obtener más información.
--longhelp
Muestra el texto de ayuda extendido.
-n|--nofsck
No realiza fsck al redimensionar el sistema de archivos con --resizefs.
--nohints
No utiliza el archivo de sugerencias para localizar dispositivos para los PV. Un comando puede leer más dispositivos para encontrar PVs cuando no se utilizan sugerencias. El comando aún realizará la invalidación estándar del archivo de sugerencias cuando sea apropiado.
--nolocking
Deshabilita el bloqueo. Usar con precaución, comandos concurrentes pueden producir resultados incorrectos.
--nosync
Hace que la creación de mirror, raid1, raid4, raid5 y raid10 omita la sincronización inicial. En el caso de mirror, raid1 y raid10, cualquier dato escrito posteriormente se duplicará, pero el contenido original no se copiará. En el caso de raid4 y raid5, no se escribirán bloques de paridad, aunque cualquier dato escrito posteriormente provocará que se almacenen bloques de paridad. Esto es útil para omitir una sincronización inicial potencialmente larga y que consume recursos de un LV de espejo/raid1/raid4/raid5 y raid10 vacío. Esta opción no es válida para raid6, ya que raid6 depende de que la paridad correcta (Síndromes P y Q) se cree durante la sincronización inicial para poder reconstruir los datos de usuario correctos en caso de fallos de dispositivos. raid0 y raid0_meta no proporcionan copias de datos ni soporte de paridad y, por lo tanto, no admiten la sincronización inicial.
--noudevsync
Deshabilita la sincronización de udev. El proceso no esperará la notificación de udev. Continuará independientemente de cualquier posible procesamiento de udev en segundo plano. Utilice esto solo si udev no se está ejecutando o tiene reglas que ignoran los dispositivos que LVM crea.
--poolmetadatasize [+]Tamaño[m|UNIDAD]
Especifica el nuevo tamaño del LV de metadatos del pool. El prefijo más + puede usarse, en cuyo caso el valor se suma al tamaño actual.
--profile Cadena
Un alias para --commandprofile o --metadataprofile, dependiendo del comando.
-q|--quiet ...
Suprime la salida y los mensajes de registro. Anula --debug y --verbose. Repetir una vez para suprimir también cualquier indicación con la respuesta 'no'.
--reportformat basic|json|json_std
Anula el formato de salida actual para los informes, que se define globalmente mediante la configuración report/output_format en lvm.conf(5). basic es el formato original con columnas y filas. Si hay más de un informe por comando, cada informe se prefija con el nombre del informe para su identificación. json produce la salida del informe en formato JSON. json_std produce la salida del informe en formato JSON que es más compatible con el estándar JSON. Consulte lvmreport(7) para obtener más información.
-r|--resizefs
Redimensiona el fs utilizando el comando de redimensionamiento específico del fs. Puede incluir montaje, desmontaje o ejecución de fsck. Consulte --fsmode para controlar el comportamiento de montaje y --nofsck para desactivar fsck. Consulte --fs para más opciones (--resizefs es equivalente a --fs resize).
-L|--size [+|-]Tamaño[m|UNIDAD]
Especifica el nuevo tamaño del LV. Las opciones --size y --extents son métodos alternativos para especificar el tamaño. El número total de extensiones físicas utilizadas será mayor cuando se necesiten datos redundantes para niveles RAID. Cuando se utiliza el prefijo más + o menos -, el valor no es un tamaño absoluto, sino que es relativo y se suma o resta del tamaño actual.
-i|--stripes Número
Especifica el número de franjas en un LV rayado. Este es el número de PV (dispositivos) en los que se distribuye un LV rayado. Los datos que parecen secuenciales en el LV se distribuyen en múltiples dispositivos en unidades del tamaño de la franja (ver --stripesize). Esto no cambia el espacio ya asignado, sino que solo se aplica al espacio que se está asignando por el comando. Al crear un LV RAID 4/5/6, este número no incluye los dispositivos adicionales que se requieren para la paridad. El número máximo depende del tipo de RAID (raid0: 64, raid10: 32, raid4/5: 63, raid6: 62), y cuando no se especifica, el valor predeterminado depende del tipo de RAID (raid0: 2, raid10: 2, raid4/5: 3, raid6: 5). Para rayar un nuevo LV RAID en todos los PV de forma predeterminada, consulte lvm.conf(5) allocation/raid_stripe_all_devices.
-I|--stripesize Tamaño[k|UNIDAD]
La cantidad de datos que se escribe en un dispositivo antes de pasar al siguiente en un LV rayado.
-t|--test
Ejecutar en modo de prueba. Los comandos no actualizarán los metadatos. Esto se implementa deshabilitando toda escritura de metadatos pero devolviendo éxito a la función llamante. Esto puede llevar a mensajes de error inusuales en operaciones de varias etapas si una herramienta depende de leer metadatos que cree que han cambiado pero no lo han hecho.
--type linear|striped|snapshot|raid|mirror|thin|thin-pool|vdo|vdo-pool|cache|cache-pool|writecache
El tipo de LV, también conocido como "tipo de segmento" o "segtype". Consulte las descripciones de uso para las formas específicas de utilizar estos tipos. Para más información sobre redundancia y rendimiento (raid<N>, mirror, striped, linear), consulte lvmraid(7). Para aprovisionamiento ligero (thin, thin-pool), consulte lvmthin(7). Para caché de rendimiento (cache, cache-pool), consulte lvmcache(7). Para instantáneas de copia en escritura (snapshot), consulte las definiciones de uso. Para VDO (vdo), consulte lvmvdo(7). Varios comandos omiten una opción de tipo explícita porque el tipo se infiere de otras opciones o atajos (por ejemplo, --stripes, --mirrors, --snapshot, --virtualsize, --thin, --cache, --vdo). Utilice tipos inferidos con cuidado, ya que pueden conducir a resultados inesperados.
-v|--verbose ...
Establece el nivel de verbosidad. Repetir de 1 a 4 veces para aumentar la depuración

OPTIONS

-f|--force
Force the use of the specified number of extents.
-l|--logicalvolumes LogicalVolumes
Specify the number of logical volumes and the algorithm to use to select them. See lvm(8) for description of algorithms.
The number of extents can be specified in absolute values, or as a percentage of the total space in the volume group, or as a percentage of the space available in the volume group.
-l|--logicalvolumes LogicalVolumes[%VG|%FREE|%LVM]
The number of extents in absolute values. Use -L for this.
The number of extents as a percentage of the total size of the Volume Group.
The number of extents as a percentage of the free space in the Volume Group.
The number of extents as a percentage of the number of logical volumes in the Volume Group.
This option replaces -L for the size specification.
The %VG, %FREE, and %LVM keywords represent the percentage of the Volume Group, free space in the Volume Group, and the average size of logical volumes in the Volume Group respectively.
-L|--size Size[UNIT]
Specify the size of the logical volume. See Size section below for details. Use + or - to add or remove size.
-M|--monitor
Enable volume monitoring.
-m|--contiguous
Try to allocate contiguous physical extents for the logical volume. If this is not possible, the command fails.
Use with caution: This option may fail to allocate extents even if the total amount of free space is sufficient.
-t|--test
Perform a trial run with no changes made.
-u|--uuid
Enable volume monitoring.
-v|--verbose
Enable verbose mode.
-w|--wait
Wait for the process to complete.
-a|--all
Process all Volume Groups.
-g|--grow
Add Size to the end of the specified Logical Volume(s) in the specified Volume Group(s).
NOTE: The size is added to the end of the specified Logical Volume(s). If the size is not specified, the Logical Volume(s) will be grown to use all available extents from the Volume Group.
Use with caution: This command can result in a very large Logical Volume.
-r|--reduce
Remove Size from the end of the specified Logical Volume(s) in the specified Volume Group(s).
NOTE: The size is removed from the end of the specified Logical Volume(s). If the size is not specified, the Logical Volume(s) will be shrunk to the minimum size possible.
Use with caution: This command can result in a very small Logical Volume.
-s|--shrink
Shrink the specified Logical Volume(s) in the specified Volume Group(s).
NOTE: The size is removed from the end of the specified Logical Volume(s). If the size is not specified, the Logical Volume(s) will be shrunk to the minimum size possible.
Use with caution: This command can result in a very small Logical Volume.
-T|--type Type
Set the LV type to Type. See lvm.conf(5) for possible types.
-Z|--zero[=y|n]
Zero the data on the logical volume when shrinking. This is the default for shrinking operations. Use -Zn to disable zeroing. This is only possible when the LV is not active.
-i|--interval
Specify the interval at which to tail the log file. The default is 5 seconds. tail of messages sent to stdout and stderr.
--version
Display version information.
-y|--yes
Do not prompt for confirmation interactively but always assume the answer yes. Use with extreme caution. (For automatic no, see -qq.)

VARIABLES

LV
Logical Volume name. See lvm(8) for valid names. An LV positional arg generally includes the VG name and LV name, e.g. VG/LV. LV1 indicates the LV must have a specific type, where the accepted LV types are listed. (raid represents raid<N> type).
PV
Physical Volume name, a device path under /dev. For commands managing physical extents, a PV positional arg generally accepts a suffix indicating a range (or multiple ranges) of physical extents (PEs). When the first PE is omitted, it defaults to the start of the device, and when the last PE is omitted it defaults to end.
Start and end range (inclusive): PV[:PE-PE] ...
Start and length range (counting from 0): PV[:PE+PE] ...
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.

EXAMPLES

Extend an LV by 16MB using specific physical extents.
lvresize -L+16M vg1/lv1 /dev/sda:0-1 /dev/sdb:0-1

Resize an LV to use 50% of the size volume group.
lvresize -l50%VG vg1/lv1
