DESCRIPCIÓN

El archivo de dispositivos LVM es la lista de dispositivos que los comandos lvm utilizarán. Se encuentra en /etc/lvm/devices/system.devices. El comando lvmdevices(8) administra el archivo y se utiliza para agregar, eliminar y listar dispositivos.

Listar dispositivos

Ejecute el comando lvmdevices sin opciones ni argumentos para mostrar las entradas en system.devices:
lvmdevices

Cada línea comienza con un nombre de dispositivo actual del sistema, seguido de su ID de dispositivo del archivo de dispositivos, seguido de otros detalles del dispositivo utilizados por lvm. Una línea comienza con "Device none" si ningún dispositivo en el sistema coincide con el ID del dispositivo. (Ver el archivo system.devices directamente no indica si un dispositivo está presente en el sistema).

Agregar dispositivos

Para usar un dispositivo con lvm, agréguelo al archivo de dispositivos con uno de los siguientes comandos.

Agregar un dispositivo haciendo referencia a su ruta de dispositivo:
lvmdevices --adddev dispositivo

Agregar un dispositivo haciendo referencia a su PVID:
lvmdevices --addpvid PVID

Agregar un dispositivo haciendo referencia a su ID de dispositivo:
lvmdevices --addid NOMBRE_ID --deviceidtype TIPO_ID

Agregar todos los PV de un VG:
vgimportdevices VG

Agregar todos los PV de todos los VG visibles:
vgimportdevices -a

pvcreate, vgcreate, y vgextend también buscan fuera del archivo de dispositivos existente para encontrar el dispositivo de destino, y lo agregan automáticamente al archivo de dispositivos.

Eliminar dispositivos

Eliminar un dispositivo del archivo de dispositivos impedirá que lvm vea o utilice ese dispositivo. Elimine un dispositivo con uno de los siguientes comandos.

Eliminar un dispositivo haciendo referencia a su ruta de dispositivo:
lvmdevices --deldev dispositivo

Eliminar un dispositivo haciendo referencia a su PVID:
lvmdevices --delpvid PVID

Eliminar un dispositivo haciendo referencia a su ID de dispositivo:
lvmdevices --delid NOMBRE_ID --deviceidtype TIPO_ID

IDs de dispositivo

LVM identifica los dispositivos en el archivo de dispositivos utilizando IDs específicos del hardware, como WWID o número de serie. Se utilizan IDs específicos del subsistema para tipos de dispositivos virtuales, que también intentan ser únicos y estables. Cuando no hay un ID de hardware o subsistema disponible, lvm recurre a usar el nombre del dispositivo como ID del dispositivo. El uso de nombres de dispositivos como IDs no es óptimo porque no son estables y a menudo cambian después de reiniciar. Cuando se utilizan nombres de dispositivos como IDs, lvm debe realizar escaneos de dispositivos adicionales para localizar dispositivos si el nombre del dispositivo cambia.

Cuando se utilizan IDs de dispositivos estables, lvm no accederá a dispositivos fuera de los listados en el archivo de dispositivos. Cuando se utilizan nombres de dispositivos como IDs, lvm escaneará dispositivos fuera del archivo de dispositivos para localizar PV en dispositivos cuyos nombres cambiaron. La configuración search_for_devnames se puede usar para controlar el comportamiento de lvm al localizar entradas de nombres de dispositivos renombrados.

Un ID de dispositivo tiene dos partes: un TIPO_ID y un NOMBRE_ID.

El TIPO_ID especifica el origen del ID, y el NOMBRE_ID es el identificador real. Hay un conjunto predefinido de TIPO_ID listados en la siguiente sección. Una entrada de archivo de dispositivos debe tener uno de estos tipos de ID. Al agregar un dispositivo al archivo de dispositivos, lvm elige automáticamente el mejor TIPO_ID, que puede ser anulado con la opción --deviceidtype (esto generalmente no se recomienda).

Para mostrar todos los IDs de dispositivos posibles para un dispositivo, o el valor de un tipo específico, use los comandos:

lvmdevices --listids dispositivo
lvmdevices --listids dispositivo --deviceidtype TIPO_ID

tipos de ID de dispositivo

Los tipos de ID de dispositivo disponibles son:

•
sys_wwid usa el wwid reportado por el archivo sysfs wwid. Esta es la primera opción.
•
wwid_naa usa el wwid naa decodificado del archivo sysfs vpd_pg83.
•
wwid_eui usa el wwid eui decodificado del archivo sysfs vpd_pg83.
•
wwid_t10 usa el wwid t10 decodificado del archivo sysfs vpd_pg83.
•
sys_serial usa el número de serie reportado por el archivo sysfs serial o el archivo vpd_pg80. Se usa un número de serie si no hay wwid disponible.
•
mpath_uuid se usa para dispositivos dm multipath, reportado por sysfs.
•
crypt_uuid se usa para dispositivos dm crypt, reportado por sysfs.
•
md_uuid se usa para dispositivos md, reportado por sysfs.
•
lvmlv_uuid se usa si un PV se coloca encima de un LV lvm, reportado por sysfs.
•
loop_file se usa para dispositivos loop, el nombre del archivo de respaldo reportado por sysfs.
•
devname el nombre del dispositivo se usa si ningún otro tipo aplica.
•
nvme_uuid, nvme_nguid, nvme_eui64 no se usan generalmente, pero pueden aparecer para dispositivos nvme que reportan valores wwid inválidos.

archivos sysfs

La mayoría de los tipos de ID de dispositivo leen el valor del ID del dispositivo de sysfs. Esos valores de sysfs también se pueden leer directamente de las siguientes rutas:

/sys/dev/block/major:minor/device/wwid
/sys/dev/block/major:minor/device/serial
/sys/dev/block/major:minor/wwid
/sys/dev/block/major:minor/device/vpd_pg83 (binario)
/sys/dev/block/major:minor/device/vpd_pg80 (binario)
/sys/dev/block/major:minor/dm/uuid (lvm lee vía ioctl)
/sys/dev/block/major:minor/md/uuid
/sys/dev/block/major:minor/loop/backing_file

(Algunos valores de sysfs se modifican antes de usarse como el ID del dispositivo, por ejemplo, se omiten los espacios o se reemplazan con guiones bajos).

contenido del archivo devices

LVM escribe información adicional en el archivo de dispositivos, además de los IDs de dispositivo. Los comandos LVM actualizan automáticamente esta información si cambia. Esto incluye el último nombre de dispositivo conocido y el UUID del PV (PVID) del encabezado del disco LVM.

DESCRIPCIÓN

El comando lvmdevices lee y escribe en el archivo de dispositivos de LVM, que se utiliza para hacer coincidir los identificadores de dispositivo con los nombres de dispositivo más recientes.

El archivo de dispositivos se puede usar para detectar la copia o restauración de un sistema a otro, o para mantener la lista de dispositivos que LVM debería considerar para un sistema específico.

El archivo de dispositivos predeterminado es /etc/lvm/devices/system.devices.

Gestión del archivo de dispositivos

Compruebe si el archivo de dispositivos está actualizado:

lvmdevices --check

Actualice los campos del archivo de dispositivos que estén obsoletos:

lvmdevices --update

El archivo de dispositivos está diseñado para ser editado por comandos de LVM, no por el usuario. El archivo de dispositivos contiene un valor HASH que LVM utiliza para detectar si el archivo ha sido modificado desde la última vez que LVM lo escribió. Cuando LVM actualiza el archivo de dispositivos, la versión anterior se mueve a /etc/lvm/devices/backup/.

Los siguientes campos se pueden encontrar en el archivo de dispositivos:

VERSION: se incrementa por cada actualización del archivo.

PRODUCT_UUID: una ID de máquina única utilizada para detectar si el archivo system.devices se ha movido a una nueva máquina y puede requerir actualización. Cuando no está disponible, se utiliza HOSTNAME.

Campos de entrada de dispositivo:

IDTYPE: indica la fuente del valor de la ID del dispositivo en IDNAME.

IDNAME: el valor único de la ID del dispositivo.

DEVNAME: el nombre de dispositivo más reciente asociado con la ID del dispositivo.

PVID: la ID única del PV de LVM del encabezado del disco de LVM.

PART: el número de partición si existe un PV en una partición.

Actualización de la ID del dispositivo

Cuando LVM escribe system.devices, incluye una ID de máquina local en el archivo system.devices (como PRODUCT_UUID o HOSTNAME). Cuando LVM lee system.devices, compara esta ID de máquina guardada con la máquina actual, lo que permite a LVM detectar cuándo system.devices ha sido copiado o restaurado en una máquina diferente. Cuando se detecta un cambio de máquina, LVM habilita un modo de "actualización de ID de dispositivo" (configurado por lvm.conf device_ids_refresh y device_ids_refresh_checks).

En modo de actualización, un dispositivo en system.devices que no se encuentra por su ID de dispositivo se localizará utilizando su PVID. LVM escaneará todos los dispositivos del sistema para buscar los PVID faltantes en system.devices. Si se encuentra un PVID en un nuevo dispositivo, la entrada de system.devices se actualizará con una nueva ID de dispositivo que coincida con el nuevo dispositivo en el que se encontró el PVID. El modo de actualización se puede configurar para que se ejecute una vez, cuando se detecta por primera vez el cambio de máquina, o se puede habilitar durante un período de tiempo después de la primera actualización, o se puede deshabilitar por completo.

device_ids_refresh = 0

Deshabilita el modo de actualización.

device_ids_refresh = 1

Habilita un intento de actualizar las ID de dispositivo cuando se detecta por primera vez un cambio de máquina.

device_ids_refresh = segundos

El modo de actualización está habilitado durante este número de segundos después del intento de actualización inicial, o hasta que se encuentren todos los PV en system.devices. Durante este período, aparece una línea REFRESH_UNTIL en system.devices. Los valores aceptados son de 10 a 600 segundos.

Además del modo automatizado de actualización de ID de dispositivo, la actualización se puede realizar manualmente:

Compruebe si system.devices se actualizaría con nuevas ID de dispositivo:

lvmdevices --check --refresh

Actualice system.devices con nuevas ID de dispositivo si se encuentran PV en nuevos dispositivos:

lvmdevices --update --refresh

La ID de máquina utilizada en system.devices será la DMI product_uuid de /sys/devices/virtual/dmi/id/product_uuid, o el nombre de host de uname(2). Consulte lvm.conf(5) device_ids_refresh_checks para configurar esto.

Archivos de dispositivos personalizados

Se pueden mantener múltiples archivos de dispositivos en /etc/lvm/devices, lo que permite usar LVM con diferentes conjuntos de dispositivos. Por ejemplo, una aplicación determinada puede no necesitar acceder a los dispositivos del sistema, y el sistema puede no necesitar acceder a los dispositivos de la aplicación. En este caso, system.devices podría listar solo los dispositivos del sistema y un archivo <aplicación>.devices podría listar solo los dispositivos de la aplicación. La opción --devicesfile <nombre de archivo> se utiliza para seleccionar el archivo de dispositivos a usar con el comando. Sin la opción establecida, se utiliza el archivo system.devices predeterminado.

Si existe el archivo de dispositivos especial /etc/lvm/devices/dmeventd.devices, entonces dmeventd usa dmeventd.devices en lugar de system.devices. Usar dmeventd.devices es necesario si los VG de archivos de dispositivos separados requieren los servicios de dmeventd. En este caso, dmeventd.devices debería listar los dispositivos de todos los VG que requieren dmeventd.

Deshabilitación y anulación

Hay varias formas en que la función de archivo de dispositivos puede ser deshabilitada o anulada:

•
no system.devices
Si el archivo system.devices no existe, entonces la función de archivo de dispositivos está deshabilitada.
•
use_devicesfile=0
Si use_devicesfile de lvm.conf se establece en 0, entonces la función de archivo de dispositivos está deshabilitada, incluso si el archivo system.devices existe.
•
--devicesfile ""
Si se especifica un nombre de archivo de dispositivos vacío en la línea de comandos, entonces ese comando no usará un archivo de dispositivos.
•
--devices dispositivo
Si se nombran dispositivos específicos en la línea de comandos con --devices, entonces el comando no usará un archivo de dispositivos y solo accederá a los dispositivos nombrados.
•
pvs -A
Si se le da la opción -A o --allpvs, el comando pvs(8) no usará un archivo de dispositivos.

Cuando el archivo de dispositivos está deshabilitado, los comandos de LVM vuelven a utilizar el filtro de lvm.conf. Cuando se utiliza el archivo de dispositivos, los comandos de LVM ignoran la configuración del filtro de lvm.conf, excepto para vgimportdevices que aplica el filtro regex al conjunto de dispositivos en el sistema al buscar VG para importar al archivo de dispositivos.

Metadatos del VG

Los comandos de LVM que escriben metadatos del VG incluirán la ID del dispositivo de cada PV en los metadatos del VG. La ID del dispositivo se puede mostrar con las opciones:

pvs -o deviceidtype,deviceid

(Tenga en cuenta que el comando lvmdevices no actualiza los metadatos del VG, pero los comandos posteriores de LVM que modifican los metadatos incluirán la ID del dispositivo).

Creación del archivo de dispositivos

Si el archivo system.devices aún no existe, los comandos pvcreate o vgcreate lo crearán solo si no ven VG existentes en el sistema. lvmdevices --adddev y vgimportdevices siempre crearán un nuevo archivo de dispositivos si aún no existe.

VARIABLES

String
Consulte la descripción de la opción para obtener información sobre el contenido de la cadena.
Size[UNIT]
Size es un número de entrada que acepta una unidad opcional. Las unidades de entrada siempre se tratan como valores de base dos, independientemente de las mayúsculas, por ejemplo, 'k' y 'K' se refieren a 1024. La unidad de entrada predeterminada se especifica con una letra, seguida de |UNIT. UNIT representa otras unidades de entrada posibles: b|B son bytes, s|S son sectores de 512 bytes, k|K son KiB, m|M son MiB, g|G son GiB, t|T son TiB, p|P son PiB, e|E son EiB. (Esto no debe confundirse con el control de salida --units, donde las letras mayúsculas significan un múltiplo de 1000).

VARIABLES DE ENTORNO

Consulte lvm(8) para obtener información sobre las variables de entorno utilizadas por lvm. Por ejemplo, LVM_VG_NAME generalmente puede sustituir a un parámetro VG requerido.
