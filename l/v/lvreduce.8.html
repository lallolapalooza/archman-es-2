NOMBRE

lvreduce — Reduce el tamaño de un volumen lógico

SINOPSIS

lvreduce opciones_argumentos argumentos_posicionales
[ opciones_argumentos ]

DESCRIPCIÓN

lvreduce reduce el tamaño de un LV. Las extensiones lógicas liberadas se devuelven al VG para ser utilizadas por otros LVs. Un LV snapshot con copia en escritura también puede ser reducido si se necesita menos espacio para almacenar bloques COW. Utilice lvconvert(8) para cambiar el número de imágenes de datos en un LV con RAID o espejado.

Tenga cuidado al reducir el tamaño de un LV, ya que los datos en el área reducida se pierden. Asegúrese de que cualquier sistema de archivos en el LV se redimensione antes de ejecutar lvreduce para que las extensiones eliminadas no estén en uso por el sistema de archivos.

Los tamaños se redondearán si es necesario. Por ejemplo, el tamaño del LV debe ser un número exacto de extensiones, y el tamaño de un segmento entrelazado debe ser un múltiplo del número de entrelazados.

En la sección de uso a continuación, --size Tamaño puede ser reemplazado con --extents Número. Consulte ambas descripciones en la sección de opciones.

OPCIONES

-A|--autobackup s|n
Especifica si los metadatos deben respaldarse automáticamente después de un cambio. ¡Se recomienda encarecidamente habilitar esto! Consulte vgcfgbackup(8) para más información.
--commandprofile Cadena
El perfil de comando a utilizar para la configuración de comandos. Consulte lvm.conf(5) para más información sobre perfiles.
--config Cadena
Configuración de comandos para el comando. Estas anulan la configuración de lvm.conf(5). El argumento Cadena utiliza el mismo formato que lvm.conf(5), o puede usar la sintaxis de sección/campo. Consulte lvm.conf(5) para más información sobre la configuración.
-d|--debug ...
Establece el nivel de depuración. Repetir de 1 a 6 veces para aumentar el detalle de los mensajes enviados al archivo de registro y/o a syslog (si está configurado).
--devices PV
Restringe los dispositivos que son visibles y accesibles para el comando. Los dispositivos no listados parecerán faltar. Esta opción puede repetirse, o aceptar una lista de dispositivos separada por comas. Esto anula el archivo de dispositivos.
--devicesfile Cadena
Un archivo que lista los dispositivos que LVM debe usar. El archivo debe existir en /etc/lvm/devices/ y se gestiona con el comando lvmdevices(8). Esto anula la configuración de lvm.conf(5) devices/devicesfile y devices/use_devicesfile.
--driverloaded s|n
Si se establece en no, el comando no intentará usar device-mapper. Para pruebas y depuración.
-l|--extents [-]Número[PORCENTAJE]
Especifica el nuevo tamaño del LV en extensiones lógicas. Las opciones --size y --extents son métodos alternativos para especificar el tamaño. El número total de extensiones físicas utilizadas será mayor cuando se necesiten datos redundantes para los niveles RAID. Una sintaxis alternativa permite determinar el tamaño indirectamente como un porcentaje del tamaño de un VG, LV o conjunto de PVs relacionados. El sufijo %VG denota el tamaño total del VG, el sufijo %FREE el espacio libre restante en el VG, y el sufijo %PVS el espacio libre en los PVs especificados. Para un snapshot, el tamaño puede expresarse como un porcentaje del tamaño total del LV de origen con el sufijo %ORIGIN (100%ORIGIN proporciona espacio para todo el origen). Cuando se expresa como un porcentaje, el tamaño define un límite superior para el número de extensiones lógicas en el nuevo LV. El número preciso de extensiones lógicas en el nuevo LV no se determina hasta que el comando se complete. Cuando se usa el prefijo más + o menos -, el valor no es un tamaño absoluto, sino que es relativo y se suma o resta del tamaño actual.
-f|--force ...
Anula varias comprobaciones, confirmaciones y protecciones. Usar con extrema precaución.
--fs Cadena
Controla el redimensionamiento del sistema de archivos al redimensionar un LV. checksize: Comprueba el tamaño del fs y reduce el LV si el fs no está usando el espacio reducido (no se necesita reducir el fs). Si el espacio reducido es utilizado por el fs, entonces no redimensione el fs ni el LV, y devuelva un error. (checksize solo se aplica al reducir, y no hace nada para extender.) resize: Redimensiona el fs llamando al comando de redimensionamiento específico del fs. Esto también puede incluir montar, desmontar o ejecutar fsck. Consulte --fsmode para controlar el comportamiento de montaje, y --nofsck para deshabilitar fsck. resize_fsadm: Utiliza el método antiguo de llamar a fsadm para manejar el fs (obsoleto). Advertencia: esta opción no impide que lvreduce destruya sistemas de archivos que están desmontados (o montados si se omiten las indicaciones). ignore: Redimensiona el LV sin comprobar ni manejar un sistema de archivos. Advertencia: usar ignore al reducir el tamaño del LV puede destruir el sistema de archivos.

Nota: Si se redimensiona un LV sin un sistema de archivos y el nuevo tamaño del LV coincide con el tamaño existente, el comando devuelve un código de estado distinto de cero (fallo). Sin embargo, si también se solicita un redimensionamiento del sistema de archivos junto con el redimensionamiento del LV, y los tamaños ya coinciden, el comando devuelve un código de estado cero (éxito). Esto ocurre porque los comandos externos llamados para redimensionar el sistema de archivos devuelven éxito incluso si los tamaños de los sistemas de archivos nuevo y antiguo son idénticos. LVM sigue el comportamiento del código de estado del comando en este escenario.

--fsmode Cadena
Controla el comportamiento de montaje del sistema de archivos para el redimensionamiento del fs. manage: Monta o desmonta el fs según sea necesario para redimensionar el fs, e intenta restaurar el estado de montaje original al final. nochange: No monta ni desmonta el fs. Si se requiere montar o desmontar para redimensionar el fs, entonces no redimensione el fs ni el LV y falle el comando. offline: Desmonta el fs si está montado, y redimensiona el fs mientras está desmontado. Si se requiere montar para redimensionar el fs, entonces no redimensione el fs ni el LV y falle el comando.

Muestra el texto de ayuda.

Registra información en el journal de systemd. Esta información es además de la información habilitada por la configuración de registro/journal de lvm.conf. command: registra información sobre el comando. output: r

-i|--stripes Integer
Specifies the number of stripes for a striped volume. This is the number of data segments on the physical volumes. For example, -i 2 on two PVs creates a stripe with two segments, one on each PV. For RAID 0, 1 and 10, this means number of data disks. For RAID 5 and 6, this specifies the number of data disks in a stripe, so the total number of PVs used will be this number plus the number of parity disks (1 for RAID 5, 2 for RAID 6).
-I|--interval Integer

-k|--keepactive

-l|--extents [ [-] ]LogicalExtents[%VG|%FREE|%LVM]
Specifies the number of logical extents to use for the LV. This is the alternate method of specifying size.

The number of logical extents can be specified as an absolute number, or as a percentage of the Volume Group's total capacity (%VG), the remaining free space in the Volume Group (%FREE), or the amount of space that would be created by this command (%LVM). If the plus + or minus - prefix is used, the value is not an absolute size, but is relative and added or subtracted from the current size.

The default behaviour is to use the number of extents specified and allocate all the space to the LV from the VG free space. This is equivalent to %FREE.

For example, -l 100 specifies 100 extents. -l +100 adds 100 extents. -l 50%VG uses 50% of the VG. -l 100%FREE uses all free space in the VG.

The default unit is logical extents, which are typically 4 MiB in size, but can be changed with --alloc.

See also lvm(8) for the default number of logical extents.

VARIABLES

LV
Logical Volume name. See lvm(8) for valid names. An LV positional arg generally includes the VG name and LV name, e.g. VG/LV.
String
See the option description for information about the string content.
Size[UNIT]
Size is an input number that accepts an optional unit. Input units are always treated as base two values, regardless of capitalization, e.g. 'k' and 'K' both refer to 1024. The default input unit is specified by letter, followed by |UNIT. UNIT represents other possible input units: b|B is bytes, s|S is sectors of 512 bytes, k|K is KiB, m|M is MiB, g|G is GiB, t|T is TiB, p|P is PiB, e|E is EiB. (This should not be confused with the output control --units, where capital letters mean multiple of 1000.)

ENVIRONMENT VARIABLES

See lvm(8) for information about environment variables used by lvm. For example, LVM_VG_NAME can generally be substituted for a required VG parameter.

EXAMPLES

Reduce the size of an LV by 3 logical extents:
lvreduce -l -3 vg00/lvol1
