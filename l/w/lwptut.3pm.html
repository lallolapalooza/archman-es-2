NOMBRE

lwptut -- Un tutorial de LWP

DESCRIPCIÓN

LWP (abreviatura de "Library for WWW in Perl") es un grupo muy popular de módulos de Perl para acceder a datos en la Web. Como la mayoría de las distribuciones de módulos de Perl, cada uno de los módulos componentes de LWP viene con documentación que es una referencia completa de su interfaz. Sin embargo, hay tantos módulos en LWP que es difícil saber por dónde empezar a buscar información sobre cómo realizar incluso las tareas más simples y comunes.

Realmente, introducirte al uso de LWP requeriría un libro entero, un libro que casualmente existe, llamado Perl & LWP. Pero este artículo debería darte una idea de cómo puedes abordar algunas tareas comunes con LWP.

Obtener documentos con LWP::Simple

Si solo quieres obtener lo que hay en una URL particular, la forma más simple es usar las funciones de LWP::Simple.

En un programa de Perl, puedes llamar a su función get($url). Intentará obtener el contenido de esa URL. Si funciona, devolverá el contenido; pero si hay algún error, devolverá undef.

my $url = 'http://www.npr.org/programs/fa/?todayDate=current';
  # Solo un ejemplo: la URL del programa más reciente de /Fresh Air/
use LWP::Simple;
my $content = get $url;
die "No pude obtener $url" unless defined $content;
# Luego haz cosas con $content, como esto:
if($content =~ m/jazz/i) {
  print "¡Hoy hablan de jazz en Fresh Air!\n";
}
else {
  print "Parece que Fresh Air está sin jazz hoy.\n";
}

La variante más útil de "get" es "getprint", que es útil en one-liners de Perl. Si puede obtener la página cuya URL le proporcionas, la envía a STDOUT; de lo contrario, se queja a STDERR.

% perl -MLWP::Simple -e "getprint 'http://www.cpan.org/RECENT'"

Esa es la URL de un archivo de texto plano que lista los nuevos archivos en CPAN en las últimas dos semanas. Puedes hacerlo fácilmente parte de un comando de shell ordenado, como este que te envía por correo la lista de nuevos módulos "Acme::":

% perl -MLWP::Simple -e "getprint 'http://www.cpan.org/RECENT'"  \
   | grep "/by-module/Acme" | mail -s "¡Nuevos módulos Acme! ¡Alegría!" $USER

Hay otras funciones útiles en LWP::Simple, incluida una función para realizar una solicitud HEAD a una URL (útil para verificar enlaces o obtener la hora de la última revisión de una URL) y dos funciones para guardar/reflejar una URL en un archivo local. Consulte la documentación de LWP::Simple para obtener todos los detalles, o el capítulo 2 de Perl & LWP para ver más ejemplos.

Los conceptos básicos del modelo de clases de LWP

Las funciones de LWP::Simple son útiles para casos sencillos, pero sus funciones no admiten cookies ni autorización, no admiten la configuración de líneas de encabezado en la solicitud HTTP, y generalmente no admiten la lectura de líneas de encabezado en la respuesta HTTP (notablemente el mensaje de error HTTP completo, en caso de error). Para acceder a todas esas características, tendrás que usar el modelo de clases completo de LWP.

Aunque LWP consta de docenas de clases, las dos principales que debes entender son LWP::UserAgent y HTTP::Response. LWP::UserAgent es una clase para "navegadores virtuales" que utilizas para realizar solicitudes, y HTTP::Response es una clase para las respuestas (o mensajes de error) que recibes de esas solicitudes.

El idioma básico es "$response = $browser->get($url)", o ilustrado de forma más completa:

# Al principio de tu programa:

use LWP 5.64; # Carga todas las clases importantes de LWP y se
              # asegura de que tu versión sea razonablemente reciente.
my $browser = LWP::UserAgent->new;

...

# Luego, más tarde, siempre que necesites hacer una solicitud get:
my $url = 'http://www.npr.org/programs/fa/?todayDate=current';

my $response = $browser->get( $url );
die "No puedo obtener $url -- ", $response->status_line
 unless $response->is_success;
die "Oye, esperaba HTML, no ", $response->content_type
 unless $response->content_type eq 'text/html';
   # o el tipo de contenido que puedas manejar
# De lo contrario, procesa el contenido de alguna manera:

if($response->decoded_content =~ m/jazz/i) {
  print "¡Hoy hablan de jazz en Fresh Air!\n";
}
else {
  print "Parece que Fresh Air está sin jazz hoy.\n";
}

Hay dos objetos involucrados: $browser, que contiene un objeto de la clase LWP::UserAgent, y luego el objeto $response, que es de la clase HTTP::Response. Realmente solo necesitas un objeto de navegador por programa; pero cada vez que haces una solicitud, obtienes un nuevo objeto HTTP::Response, que tendrá algunos atributos interesantes:

  • Un código de estado que indica éxito o fracaso (que puedes probar con "$response->is_success").
  • Una línea de estado HTTP que es, con suerte, informativa si hay un error (que puedes ver con "$response->status_line", que devuelve algo como "404 Not Found").
  • Un tipo de contenido MIME como "text/html", "image/gif", "application/xml", etc., que puedes ver con "$response->content_type"
  • El contenido real de la respuesta, en "$response->decoded_content". Si la respuesta es HTML, ahí estará el código fuente HTML; si es un GIF, entonces "$response->decoded_content" serán los datos binarios del GIF.
  • Y docenas de otros métodos convenientes y más específicos que se documentan en la documentación de HTTP::Response y sus superclases HTTP::Message y HTTP::Headers.

Agregar otras cabeceras de solicitud HTTP

La sintaxis más utilizada para las solicitudes es "$response = $browser->get($url)", pero en realidad, puedes agregar líneas de encabezado HTTP adicionales a la solicitud agregando una lista de pares clave-valor después de la URL, así:

$response = $browser->get( $url, $key1, $value1, $key2, $value2, ... );

Por ejemplo, aquí se muestran cómo enviar algunas cabeceras de uso común, en caso de que estés tratando con un sitio que de lo contrario rechazaría tu solicitud:

my @ns_headers = (
 'User-Agent' => 'Mozilla/4.76 [en] (Win98; U)',
 'Accept' => 'image/gif, image/x-xbitmap, image/jpeg, image/pjpeg, image/png, */*',
 'Accept-Charset' => 'iso-8859-1,*,utf-8',
 'Accept-Language' => 'en-US',
);
...

$response = $browser->get($url, @ns_headers);

Si no estuvieras reutilizando esa matriz, podrías simplemente hacer esto:

$response = $browser->get($url,
 'User-Agent' => 'Mozilla/4.76 [en] (Win98; U)',
 'Accept' => 'image/gif, image/x-xbitmap, image/jpeg, image/pjpeg, image/png, */*',
 'Accept-Charset' => 'iso-8859-1,*,utf-8',
 'Accept-Language' => 'en-US',
);

Si solo cambiaras la línea 'User-Agent', podrías simplemente cambiar la línea predeterminada del objeto $browser de "libwww-perl/5.65" (o similar) a lo que prefieras, usando el método "agent" de LWP::UserAgent:

$browser->agent('Mozilla/4.76 [en] (Win98; U)');

Habilitar las cookies

Un objeto LWP::UserAgent predeterminado actúa como un navegador con su soporte de cookies desactivado. Hay varias maneras de activarlo, estableciendo su atributo "cookie_jar". Un "cookie jar" es un objeto que representa una pequeña base de datos de todas las cookies HTTP que un navegador conoce. Puede corresponder a un archivo en disco o a un objeto en memoria que comienza vacío, y cuya colección de cookies desaparecerá una vez que el programa termine de ejecutarse.

Para darle a un navegador un "cookie jar" en memoria vacío, establece su atributo "cookie_jar" así:

use HTTP::CookieJar::LWP;
$browser->cookie_jar( HTTP::CookieJar::LWP->new );

Para guardar un "cookie jar" en disco, consulta "dump_cookies" en HTTP::CookieJar. Para cargar cookies desde disco a un "jar", consulta "load_cookies" en HTTP::CookieJar.

$response = $browser->post( $url, [ formkey1 => value1, formkey2 => value2, ... ], ); ```

O si necesitas enviar cabeceras HTTP:

Por ejemplo, el siguiente programa realiza una solicitud de búsqueda a AltaVista (enviando datos de formulario a través de una solicitud HTTP POST) y extrae del HTML el informe del número de coincidencias:

```perl use strict; use warnings; use LWP 5.64; my $browser = LWP::UserAgent->new; my $word = 'tarragon'; my $url = 'http://search.yahoo.com/yhs/search'; my $response = $browser->post( $url, [ 'q' => $word, # la cadena de consulta de Altavista 'fr' => 'altavista', 'pg' => 'q', 'avkw' => 'tgz', 'kl' => 'XX', ] ); die "$url error: ", $response->status_line unless $response->is_success; die "Tipo de contenido extraño en $url -- ", $response->content_type unless $response->content_is_html; if( $response->decoded_content =~ m{([0-9,]+)(?:<.*? >)? resultados para} ) { # La subcadena será como "996,000 resultados para" print "$word: $1\n"; } else { print "No se pudo encontrar la cadena de coincidencia en la respuesta\n"; } ```

Enviar datos de formulario GET

Algunos formularios HTML transmiten sus datos no enviándolos en una solicitud HTTP POST, sino realizando una solicitud GET normal con los datos adjuntos al final de la URL. Por ejemplo, si fueras a "www.imdb.com" y buscaras "Blade Runner", la URL que verías en la ventana de tu navegador sería:

``` http://www.imdb.com/find?s=all&q=Blade+Runner ```

Para realizar la misma búsqueda con LWP, usarías este modismo, que involucra la clase URI:

```perl use URI; my $url = URI->new( 'http://www.imdb.com/find' ); # crea un objeto que representa la URL $url->query_form( # Y aquí los pares de datos del formulario: 'q' => 'Blade Runner', 's' => 'all', ); my $response = $browser->get($url); ```

Consulta el capítulo 5 de Perl & LWP para obtener una discusión más detallada sobre formularios HTML y datos de formulario, y los capítulos 6 al 9 para una discusión más detallada sobre la extracción de datos de HTML.

Absolutizar URLs

La clase URI que mencionamos anteriormente proporciona todo tipo de métodos para acceder y modificar partes de las URLs (como preguntar qué tipo de URL es con "$url->scheme", y preguntar a qué host se refiere con "$url->host", y así sucesivamente, como se describe en la documentación de la clase URI. Sin embargo, los métodos de mayor interés inmediato son el método "query_form" visto anteriormente, y ahora el método "new_abs" para tomar una cadena de URL probablemente relativa (como "../foo.html") y obtener una URL absoluta (como http://www.perl.com/stuff/foo.html), como se muestra aquí:

```perl use URI; $abs = URI->new_abs($maybe_relative, $base); ```

Por ejemplo, considera este programa que coincide con las URLs en la lista HTML de nuevos módulos en CPAN:

```perl use strict; use warnings; use LWP; my $browser = LWP::UserAgent->new; my $url = 'http://www.cpan.org/RECENT.html'; my $response = $browser->get($url); die "No se puede obtener $url -- ", $response->status_line unless $response->is_success; my $html = $response->decoded_content; while( $html =~ m/Al ejecutarse, emite una salida que comienza algo así:

``` MIRRORING.FROM RECENT RECENT.html authors/00whois.html authors/01mailrc.txt.gz authors/id/A/AA/AASSAD/CHECKSUMS ... ```

Sin embargo, si realmente quieres que sean URLs absolutas, puedes usar el método "new_abs" del módulo URI, cambiando el bucle "while" a esto:

```perl while( $html =~ m/new_abs( $1, $response->base ) ,"\n"; } ```

(El método "$response->base" de HTTP::Message es para devolver qué URL debe usarse para resolver URLs relativas -- normalmente es lo mismo que la URL que solicitaste.)

Ese programa emite entonces URLs absolutas y bien formadas:

``` http://www.cpan.org/MIRRORING.FROM http://www.cpan.org/RECENT http://www.cpan.org/RECENT.html http://www.cpan.org/authors/00whois.html http://www.cpan.org/authors/01mailrc.txt.gz http://www.cpan.org/authors/id/A/AA/AASSAD/CHECKSUMS ... ```

Consulta el capítulo 4 de Perl & LWP para una discusión más detallada sobre objetos URI.

Por supuesto, usar una expresión regular para buscar hrefs es un poco simplista, y para programas más robustos, probablemente querrás usar un módulo de análisis de HTML como HTML::LinkExtor o HTML::TokeParser o incluso quizás HTML::TreeBuilder.

Otros atributos del navegador

Los objetos LWP::UserAgent tienen muchos atributos para controlar cómo funcionan. Aquí hay algunos notables:

  • "$browser->timeout(15);"

    Esto establece que este objeto navegador renuncie a las solicitudes que no respondan dentro de los 15 segundos.

  • "$browser->protocols_allowed( [ 'http', 'gopher'] );"

    Esto establece que este objeto navegador no hable ningún protocolo que no sea HTTP y gopher. Si intenta acceder a cualquier otro tipo de URL (como una URL "ftp:" o "mailto:" o "news:"), entonces no intentará conectarse, sino que devolverá inmediatamente un código de error 500, con un mensaje como "El acceso a las URI 'ftp' ha sido deshabilitado".

  • "use LWP::ConnCache; $browser->conn_cache(LWP::ConnCache->new());"

    Esto indica al objeto navegador que intente usar la función "Keep-Alive" de HTTP/1.1, que acelera las solicitudes reutilizando la misma conexión de socket para múltiples solicitudes al mismo servidor.

  • "$browser->agent( 'SomeName/1.23 (más información aquí quizás)' )"

    Esto cambia cómo se identificará el objeto navegador en la línea predeterminada "User-Agent" de sus solicitudes HTTP. Por defecto, enviará "libwww-perl/versionnumber", como "libwww-perl/5.65". Puedes cambiarlo a algo más descriptivo como esto:

    $browser->agent( 'SomeName/3.14 (contact@robotplexus.int)' );

    O si es necesario, puedes ir de incógnito, así:

    $browser->agent( 'Mozilla/4.0 (compatible; MSIE 5.12; Mac_PowerPC)' );
  • "push @{ $ua->requests_redirectable }, 'POST';"

    Esto indica a este navegador que obedezca las respuestas de redirección a las solicitudes POST (como la mayoría de los navegadores interactivos modernos), aunque la RFC de HTTP dice que eso normalmente no debería hacerse.

Para más opciones e información, consulta la documentación completa de LWP::UserAgent.

Escribir robots educados

Si quieres asegurarte de que tu programa basado en LWP respete los archivos robots.txt y no realice demasiadas solicitudes demasiado rápido, puedes usar la clase LWP::RobotUA en lugar de la clase LWP::UserAgent.

La clase LWP::RobotUA es igual que LWP::UserAgent, y puedes usarla así:

```perl use LWP::RobotUA; my $browser = LWP::RobotUA->new('YourSuperBot/1.34', 'you@yoursite.com'); # El nombre de tu bot y tu dirección de correo electrónico my $response = $browser->get($url); ```

Pero HTTP::RobotUA añade estas características:

  • Si el robots.txt del servidor de $url te prohíbe el acceso a $url, entonces el objeto $browser (asumiendo que es de la clase LWP::RobotUA) no lo solicitará, sino que te devolverá (en $response) un error 403 con el mensaje "Forbidden by robots.txt". Es decir, si tienes esta línea: 
    die "$url -- ", $response->status_line, "\nAborted"
 unless $response->is_success;

    entonces el programa fallará con un mensaje de error como este:

    http://whatever.site.int/pith/x.html -- 403 Forbidden by robots.txt
Aborted at whateverprogram.pl line 1234
  • Si este objeto $browser detecta que la última vez que habló con el servidor de $url fue demasiado reciente, entonces pausará (a través de "sleep") para evitar realizar demasiadas solicitudes con demasiada frecuencia. Cuánto pausará es, por defecto, un minuto, pero puedes controlarlo con el atributo "$browser->delay( minutes )".

    Por ejemplo, este código:

    $browser->delay( 7/60 );

    ... significa que este navegador pausará cuando sea necesario para evitar hablar con cualquier servidor dado más de una vez cada 7 segundos.

Para más opciones e información, consulta la documentación completa de LWP::RobotUA.

Usar proxies

En algunos casos, querrás (o tendrás que) usar proxies para acceder a ciertos sitios y/o usar ciertos protocolos. Este es el caso más común cuando tu programa LWP se está ejecutando (o podría ejecutarse) en una máquina que está detrás de un firewall.

Para hacer que un objeto navegador use proxies que están definidos en las variables de entorno habituales ("HTTP_PROXY", etc.), simplemente llama a "env_proxy" en un objeto user-agent antes de realizar cualquier solicitud en él. Específicamente:

```perl use LWP::UserAgent; my $browser = LWP::UserAgent->new; # Y antes de realizar cualquier solicitud: $browser->env_proxy; ```

Para más información sobre parámetros de proxy, consulta la documentación de LWP::UserAgent, específicamente los métodos "proxy", "env_proxy" y "no_proxy".

NAME

lwptut — A Tutorial Introduction to LWP

DESCRIPTION

This is a tutorial introduction to the libwww-perl modules. It assumes that you have a working installation of libwww-perl, and that you know some basic Perl.

We'll be using the LWP::UserAgent class to do our work. So, in order to begin, we'll want to make sure that our program can find it, and then we'll want to create an object of the class:

    use LWP;
    my $browser = LWP::UserAgent->new;

The object, $browser, is now ready to be used to retrieve documents from the World Wide Web.

Getting a Document

The simplest way to get a document is to use the get method:

    my $url = 'http://www.perl.com/';
    my $response = $browser->get($url);

The $response object is an instance of the HTTP::Response class. It contains the server's response to our request.

We can check to see if the request was successful:

    if ($response->is_success) {
        print "It worked! We got the document.\n";
        # do something with $response->content
    } else {
        die "Failed to get document: ", $response->status_line, "\n";
    }

If you want to see the content of the document:

    print $response->content;

To see the HTTP status line (like "200 OK" or "404 Not Found"):

    print $response->status_line;

To see the HTTP headers:

    print $response->headers_as_string;

To see just a specific header, like the content type:

    print $response->header('Content-Type');

If you want to get a document, but only if it hasn't changed since the last time you fetched it, use the \"If-Modified-Since\" header. This is useful for caching.

    use HTTP::Date;
    my $url = 'http://www.perl.com/';
    my $last_modified = 'Mon, 23 Oct 2025 14:31:01 GMT'; # From a previous request
    my $response = $browser->get($url,
                                'If-Modified-Since' => $last_modified);
    if ($response->code == 304) {
        print "Document hasn't changed since $last_modified\n";
    } elsif ($response->is_success) {
        print "Got updated document.\n";
        # Update $last_modified to the value in the new response's
        # 'Last-Modified' header
    } else {
        die "Failed: ", $response->status_line, "\n";
    }

HTTP Authentication

HTTP Authentication is a mechanism where the HTTP server sends the browser an HTTP code that says "That document is part of a protected 'realm', and you can access it only if you re-request it and add some special authorization headers to your request".

For example, the Unicode.org admins stop email-harvesting bots from harvesting the contents of their mailing list archives, by protecting them with HTTP Authentication, and then publicly stating the username and password (at "http://www.unicode.org/mail-arch/") — namely username "unicode-ml" and password "unicode".

For example, consider this URL, which is part of the protected area of the web site:

http://www.unicode.org/mail-arch/unicode-ml/y2002-m08/0067.html

If you access that with a browser, you'll get a prompt like "Enter username and password for 'Unicode-MailList-Archives' at server 'www.unicode.org'".

In LWP, if you just request that URL, like this:

use LWP;
my $browser = LWP::UserAgent->new;
my $url =
 'http://www.unicode.org/mail-arch/unicode-ml/y2002-m08/0067.html';
my $response = $browser->get($url);
die "Error: ", $response->header('WWW-Authenticate') || 'Error accessing',
  #  ('WWW-Authenticate' is the realm-name)
  "\n ", $response->status_line, "\n at $url\n Aborting"
 unless $response->is_success;

Then you'll get this error:

Error: Basic realm="Unicode-MailList-Archives"
 401 Authorization Required
 at http://www.unicode.org/mail-arch/unicode-ml/y2002-m08/0067.html
 Aborting at auth1.pl line 9.  [or wherever]

...because the $browser doesn't know any of the username and password for that realm ("Unicode-MailList-Archives") at that host ("www.unicode.org"). The simplest way to let the browser know about this is to use the "credentials" method to let it know about a username and password that it can try using for that realm at that host. The syntax is:

$browser->credentials(
  'servername:portnumber',
  'realm-name',
 'username' => 'password'
);

In most cases, the port number is 80, the default TCP/IP port for HTTP; and you usually call the "credentials" method before you make any requests. For example:

$browser->credentials(
  'reports.mybazouki.com:80',
  'web_server_usage_reports',
  'plinky' => 'banjo123'
);

So if we add the following to the program above, right after the "$browser = LWP::UserAgent->new;" line...

$browser->credentials(  # add this to our $browser 's "key ring"
  'www.unicode.org:80',
  'Unicode-MailList-Archives',
  'unicode-ml' => 'unicode'
);

...then when we run it, the request succeeds, instead of causing the "die" to be called.

Accessing HTTPS URLs

When you access an HTTPS URL, it'll work for you just like an HTTP URL would — if your LWP installation has HTTPS support (via an appropriate Secure Sockets Layer library). For example:

use LWP;
my $url = 'https://www.paypal.com/';   # Yes, HTTPS!
my $browser = LWP::UserAgent->new;
my $response = $browser->get($url);
die "Error at $url\n ", $response->status_line, "\n Aborting"
 unless $response->is_success;
print "Whee, it worked!  I got that ",
 $response->content_type, " document!\n";

If your LWP installation doesn't have HTTPS support set up, then the response will be unsuccessful, and you'll get this error message:

Error at https://www.paypal.com/
 501 Protocol scheme 'https' is not supported
 Aborting at paypal.pl line 7.   [or whatever program and line]

If your LWP installation does have HTTPS support installed, then the response should be successful, and you should be able to consult $response just like with any normal HTTP response.

For information about installing HTTPS support for your LWP installation, see the helpful README.SSL file that comes in the libwww-perl distribution.

Getting Large Documents

When you're requesting a large (or at least potentially large) document, a problem with the normal way of using the request methods (like "$response = $browser->get($url)") is that the response object in memory will have to hold the whole document — in memory. If the response is a thirty megabyte file, this is likely to be quite an imposition on this process's memory usage.

A notable alternative is to have LWP save the content to a file on disk, instead of saving it up in memory. This is the syntax to use:

$response = $ua->get($url,
                       ':content_file' => $filespec,
                    );

For example,

$response = $ua->get('http://search.cpan.org/',
                       ':content_file' => '/tmp/sco.html'
                    );

When you use this ":content_file" option, the $response will have all the normal header lines, but "$response->content" will be empty. Errors writing to the content file (for example due to permission denied or the filesystem being full) will be reported via the "Client-Aborted" or "X-Died" response headers, and not the "is_success" method:

if ($response->header('Client-Aborted') eq 'die') {
  # handle error ...

Note that this ":content_file" option isn't supported under older versions of LWP, so you should consider adding "use LWP 5.66;" to check the LWP version, if you think your program might run on systems with older versions.

If you need to be compatible with older LWP versions, then use this syntax, which does the same thing:

use HTTP::Request::Common;
$response = $ua->request( GET($url), $filespec );

  • URI — class for objects that represent absolute or relative URLs
  • URI::Escape — functions for URL-escaping and URL-unescaping strings (like turning "this & that" to and from "this%20%26%20that").
  • HTML::Entities — functions for HTML-escaping and HTML-unescaping strings (like turning "C. & E. Brontë" to and from "C. &amp; E. Bront&euml;")
  • HTML::TokeParser and HTML::TreeBuilder — classes for parsing HTML
  • HTML::LinkExtor — class for finding links in HTML documents
