LS(1P) Manual del programador POSIX LS(1P)

PROLOGO

Esta página del manual es parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

ls — listar contenido de directorios

SINOPSIS

ls [-ikqrs] [-glno] [-A|-a] [-C|-m|-x|-1] \
    [-F|-p] [-H|-L] [-R|-d] [-S|-f|-t] [-c|-u] [archivo...]

DESCRIPCION

Para cada operando que nombra un archivo de un tipo diferente de directorio o enlace simbólico a un directorio, ls escribirá el nombre del archivo, así como cualquier información solicitada asociada. Para cada operando que nombra un archivo de tipo directorio, ls escribirá los nombres de los archivos contenidos en el directorio, así como cualquier información solicitada asociada. Los nombres de archivo que comienzan con un <punto> ('.') y cualquier información asociada no se escribirán a menos que se referencien explícitamente, se proporcione la opción -A o -a, o una condición definida por la implementación cause que se escriban. Si se especifican una o más de las opciones -d, -F o -l, y no se especifica la opción -H ni la opción -L, para cada operando que nombra un archivo de tipo enlace simbólico a un directorio, ls escribirá el nombre del archivo, así como cualquier información solicitada asociada. Si no se especifican ninguna de las opciones -d, -F o -l, o se especifican las opciones -H o -L, para cada operando que nombra un archivo de tipo enlace simbólico a un directorio, ls escribirá los nombres de los archivos contenidos dentro del directorio, así como cualquier información solicitada asociada. En cada caso en que se escriban los nombres de los archivos contenidos dentro de un directorio, si el directorio contiene enlaces simbólicos, ls evaluará la información del archivo y el tipo de archivo para que sean los del propio enlace simbólico, a menos que se especifique la opción -L.

Si no se especifican operandos, ls se comportará como si se hubiera especificado un único operando de punto ('.'). Si se especifica más de un operando, ls escribirá primero los operandos que no son directorios; ordenará los operandos de directorio y no directorio por separado de acuerdo con la secuencia de ordenación en la configuración regional actual.

Siempre que ls ordene nombres de archivo o ruta de acceso según la secuencia de ordenación en la configuración regional actual, si esta secuencia de ordenación no tiene un orden total de todos los caracteres (consulte el volumen Definiciones básicas de POSIX.1‐2017, Sección 7.3.2, LC_COLLATE), entonces cualquier nombre de archivo o ruta de acceso que ordene por igual se comparará posteriormente carácter por carácter utilizando la secuencia de ordenación para la configuración regional POSIX.

La utilidad ls detectará bucles infinitos; es decir, la entrada a un directorio previamente visitado que es un ancestro del último archivo encontrado. Cuando detecta un bucle infinito, ls escribirá un mensaje de diagnóstico en la salida de error estándar y recuperará su posición en la jerarquía o terminará.

OPCIONES

La utilidad ls cumplirá con el volumen de Definiciones básicas de POSIX.1‐2017, Sección 12.2, Pautas de sintaxis de utilidad.

Se admitirán las siguientes opciones:

-A
Escribir todas las entradas del directorio, incluidas aquellas cuyos nombres comienzan con un <punto> ('.'), pero excluyendo las entradas punto y punto-punto (si existen).
-C
Escribir salida en varias columnas de texto con las entradas ordenadas hacia abajo en las columnas, de acuerdo con la secuencia de ordenación. El número de columnas de texto y los caracteres separadores de columna no se especifican, pero deben adaptarse a la naturaleza del dispositivo de salida. Esta opción deshabilita la salida en formato largo.
-F
No seguir los enlaces simbólicos nombrados como operandos a menos que se especifiquen las opciones -H o -L. Escribir una <barra inclinada> ('/') inmediatamente después de cada ruta que sea un directorio, un <asterisco> ('*') después de cada uno que sea ejecutable, una <barra vertical> ('|') después de cada uno que sea un FIFO, y un arroba ('@') después de cada uno que sea un enlace simbólico. Para otros tipos de archivo, se pueden escribir otros símbolos.
-H
Evaluar la información del archivo y el tipo de archivo para los enlaces simbólicos especificados en la línea de comandos para que sean los del archivo al que hace referencia el enlace, y no el enlace mismo; sin embargo, ls escribirá el nombre del enlace mismo y no el archivo al que hace referencia el enlace.
-L
Evaluar la información del archivo y el tipo de archivo para todos los enlaces simbólicos (ya sean nombrados en la línea de comandos o encontrados en una jerarquía de archivos) para que sean los del archivo al que hace referencia el enlace, y no el enlace mismo; sin embargo, ls escribirá el nombre del enlace mismo y no el archivo al que hace referencia el enlace. Cuando se usa -L con -l, escribir el contenido de los enlaces simbólicos en formato largo (consulte la sección STDOUT).
-R
Listar recursivamente los subdirectorios encontrados. Cuando se encuentra un enlace simbólico a un directorio, el directorio no se listará recursivamente a menos que se especifique la opción -L. El uso de -R con -d o -f produce resultados no especificados.
-S
Ordenar con la clave principal siendo el tamaño del archivo (en orden decreciente) y la clave secundaria siendo el nombre del archivo en la secuencia de ordenación (en orden creciente).
-a
Escribir todas las entradas del directorio, incluidas aquellas cuyos nombres comienzan con un <punto> ('.').
-c
Usar la hora de la última modificación de la información de estado del archivo (consulte el volumen Definiciones básicas de POSIX.1‐2017, <sys_stat.h>) en lugar de la última modificación del archivo en sí para ordenar (-t) o escribir (-l).
-d
No seguir los enlaces simbólicos nombrados como operandos a menos que se especifiquen las opciones -H o -L. No tratar los directorios de manera diferente a otros tipos de archivos. El uso de -d con -R o -f produce resultados no especificados.
-f
Listar las entradas en los operandos de directorio en el orden en que aparecen en el directorio. El comportamiento para los operandos que no son directorios no se especifica. Esta opción activará -a. Cuando se especifica -f, se ignorarán las ocurrencias de las opciones -r, -S y -t, y se podrán ignorar las ocurrencias de las opciones -A, -g, -l, -n, -o y -s. El uso de -f con -R o -d produce resultados no especificados.
-g
Activar la opción -l (ele), pero deshabilitar la escritura del nombre o número del propietario del archivo. Deshabilitar las opciones -C, -m y -x.
-i
Para cada archivo, escribir el número de serie del archivo (consulte stat() en el volumen de Interfaces del sistema de POSIX.1‐2017).
-k
Establecer el tamaño del bloque para la opción -s y el recuento de bloques por directorio escrito para las opciones -l, -n, -s, -g y -o (consulte la sección STDOUT) a 1024 bytes.
-l
(La letra ele.) No seguir los enlaces simbólicos nombrados como operandos a menos que se especifiquen las opciones -H o -L. Escribir en formato largo (consulte la sección STDOUT). Deshabilitar las opciones -C, -m y -x.
-m
Formato de salida en flujo; listar las rutas de acceso a través de la página, separadas por un carácter de <coma> seguido de un carácter de <espacio>. Usar un carácter de <nueva línea> como terminador de lista y después de la secuencia separadora cuando no hay espacio en una línea para la siguiente entrada de lista. Esta opción deshabilita la salida en formato largo.
-n
Activar la opción -l (ele), pero al escribir el propietario o grupo del archivo, escribir el UID o GID numérico del archivo en lugar del usuario

ESTANDARDE SALIDA

Cuando se utilizan las opciones -l, -g o -o, la salida para cada archivo contendrá la siguiente información, separada por espacios en blanco:

tipo-de-archivo y permisos
Los permisos del archivo, como se describe en la descripción de la opción -l, seguido de un carácter que indica el tipo de archivo.
número-de-enlaces-duros-al-archivo
El número de enlaces duros al archivo.
nombre-de-usuario o ID-de-usuario-numérico (propietario)
El nombre del propietario del archivo o su ID numérico si el nombre no se puede determinar.
nombre-de-grupo o ID-de-grupo-numérico (grupo)
El nombre del grupo propietario del archivo o su ID numérico si el nombre no se puede determinar. Cuando se utiliza la opción -g, esta columna se omite.
tamaño-en-bytes
El tamaño del archivo en bytes.
hora-de-última-modificación
La fecha y hora de la última modificación del archivo o de su información de estado, según lo determinen las opciones -c y -u. El formato de fecha y hora será el mismo que el especificado por la variable de entorno TZ (consulte Section 7.1.3, Environment Variables) o, en su defecto, el especificado por la configuración regional por defecto.
nombre-de-archivo
El nombre del archivo.

Cuando se utiliza la opción -s, la salida para cada archivo contendrá la siguiente información, separada por espacios en blanco:

bloques-asignados
El número de bloques asignados al archivo en la unidad especificada por la opción -k, redondeado hacia arriba. Si se usa -k, la unidad es de 1024 bytes. De lo contrario, la unidad no se especifica, pero normalmente es de 512 bytes.
nombre-de-archivo
El nombre del archivo.

Si se especifica la opción -i, se imprimirá el número de serie del archivo y un espacio antes de cada nombre de archivo.

Si se especifican las opciones -l, -g, -n o -o, se imprimirá el número total de bloques para el directorio. Si se especifica la opción -k, el tamaño del bloque se establecerá en 1024 bytes. De lo contrario, la unidad no se especifica, pero normalmente es de 512 bytes.

La salida de la opción -m se compone de una lista de nombres de archivo separados por una coma y un espacio. Si no cabe un nombre de archivo en la línea actual, se escribe en la siguiente línea.

Si la salida no es una terminal, se suprimirán los indicadores de tipo de archivo de la opción -F, excepto para los enlaces simbólicos.

Si la salida es una terminal, y la opción -l no está especificada, los nombres de archivo se escribirán en formato de varias columnas (consulte la opción -C) o en formato de flujo (consulte la opción -m) o en formato de una sola columna (consulte la opción -1), según lo que sea más apropiado para la terminal.

La salida estándar para las entradas de directorio se ordenará según la secuencia de ordenación en la configuración regional actual.

ESTADO DE SALIDA

Se producirán los siguientes valores de salida:

0
Se ha ejecutado correctamente.
1-125
Ocurrió un error.
126
El comando especificado en un operando no se pudo ejecutar porque se encontró, pero no se pudo invocar. Ocurrió un error en la ejecución del comando.
127
El comando especificado en un operando no se pudo ejecutar porque no se encontró. Ocurrió un error en la ejecución del comando.
más de 127
Se produjo un error al detectar un bucle infinito.

INTERACCIÓN DE OPCIONES

El orden de las opciones no importa. Las opciones -C, -m y -x son mutuamente excluyentes; si se especifican varias, solo se aplicará la última encontrada.

La opción -l (o las opciones -g, -n, -o, que la implican) deshabilita las opciones -C, -m y -x. La opción -1 deshabilita las opciones -C y -x.

El comportamiento de ls cuando se especifican simultáneamente las opciones -d o -f con -R no está definido.

Si se especifican las opciones -t, -S y -f, se ignoran las opciones -t y -S. Si se especifican las opciones -t y -S, se ordena primero por tiempo de modificación y luego por tamaño de archivo, ambas en orden decreciente.

La opción -c afecta a la operación de -t al cambiar el orden de clasificación a la hora de modificar el estado del archivo en lugar de la hora de modificar el archivo. La opción -c también afecta a la operación de -l al cambiar el tiempo de modificación que se muestra y se utiliza para determinar el orden de clasificación si también se especifica -t o -S.

Las opciones -g, -n y -o son similares a -l pero modifican las columnas de salida del propietario y/o del grupo.

La opción -H afecta a la interpretación de los enlaces simbólicos dados como operandos. La opción -L afecta a la interpretación de todos los enlaces simbólicos.

La opción -p escribe un indicador después de cada nombre de directorio.

La opción -F escribe varios indicadores después de los nombres de archivo si son directorios, ejecutables, FIFOs o enlaces simbólicos.

La opción -r invierte el orden de clasificación.

La opción -s imprime el tamaño asignado de cada archivo en bloques, seguido del nombre del archivo.

La opción -u afecta a la operación de -t al cambiar el orden de clasificación a la hora de último acceso en lugar de la hora de modificación.

RUTAS DE ACCESO DE ENTRADA

Las rutas de acceso de entrada se procesan en el orden en que aparecen en la línea de comandos. Si no se especifican operandos, se utiliza el archivo actual (un punto).

EJEMPLOS

Para listar los archivos en el directorio actual, omitiendo los que empiezan por un punto, y mostrando el nombre de cada archivo y su recuento de bloques:

ls -s

Para listar todos los archivos en el directorio actual, incluidos los que empiezan por un punto, en formato largo, ordenados por fecha de modificación (los más recientes primero):

ls -lat

Para listar el contenido del directorio 'dir1', seguido del contenido del directorio 'dir2', ordenados por tamaño de archivo (los más grandes primero):

ls -lS dir1 dir2

Para listar de forma recursiva los archivos del directorio actual y de todos sus subdirectorios:

ls -R

Para listar los archivos en formato largo, mostrando los UID y GIDs numéricos en lugar de los nombres de usuario y grupo:

ls -ln

Para listar los archivos en formato de varias columnas, mostrando los archivos y directorios con un indicador al final (/ para directorios, * para ejecutables, etc.):

ls -FC

Para listar los archivos en formato de flujo, separados por comas y espacios:

ls -m

TRANSICIÓN A LOS FORMATOS ANTERIORES

Las opciones -s y -x se proporcionan por compatibilidad con versiones anteriores y pueden ser ignoradas en implementaciones futuras. La opción -f se proporciona por compatibilidad con versiones anteriores y solo se garantiza que funcione para operandos de directorio; su comportamiento para operandos que no son directorios no está especificado.

SEGUIR ENLACES SIMBÓLICOS

Las acciones de ls con respecto a los enlaces simbólicos se determinan mediante una combinación de las opciones -H, -L, -d, -F y -l.

El comportamiento por defecto (sin -H ni -L) es que ls sigue los enlaces simbólicos que se dan como operandos si no se especifica -d y no se especifica -F o -l. Si se especifica -d, los enlaces simbólicos que se dan como operandos se tratan como archivos regulares. Si se especifican -F o -l (sin -H ni -L), los enlaces simbólicos que se dan como operandos se tratan como enlaces simbólicos.

Cuando se recorre una jerarquía de directorios (con -R), el comportamiento por defecto es que ls no sigue los enlaces simbólicos a directorios. Si se especifica -L, ls sigue todos los enlaces simbólicos.

La opción -H se aplica solo a los enlaces simbólicos dados como operandos en la línea de comandos. La opción -L se aplica a todos los enlaces simbólicos encontrados.

-p

Fuerza a que cada instancia de caracteres de nombre de archivo no imprimibles y caracteres de tabulación se escriba como el carácter de signo de interrogación ('?'). Las implementaciones pueden proporcionar esta opción por defecto si la salida es a un dispositivo terminal.

-s

-t
Ordena usando como clave principal el tiempo de modificación (primero el más recientemente modificado) y como clave secundaria el nombre del archivo en la secuencia de colación. -u
Utiliza el tiempo del último acceso (ver el volumen de Definiciones Base de POSIX.1-2017, <sys_stat.h>) en lugar de la última modificación del archivo para la ordenación (-t) o la escritura (-l).
-x
Lo mismo que -C, excepto que la salida en múltiples columnas de texto se produce con las entradas ordenadas horizontalmente, en lugar de verticalmente, a través de las columnas. Esta opción deshabilita la salida en formato largo.
-1
(El dígito numérico uno.) Fuerza la salida a ser una entrada por línea. Esta opción no deshabilita la salida en formato largo. (La salida en formato largo está habilitada por -g, -l (ele), -n y -o; y deshabilitada por -C, -m y -x.)

Si se proporciona una opción que habilita la salida en formato largo (-g, -l (ele), -n y -o) junto con una opción que deshabilita la salida en formato largo (-C, -m y -x), esto no se considerará un error. La última de estas opciones especificadas determinará si se escribe la salida en formato largo.

Si se especifican -R, -d o -f, los resultados de especificar estas opciones mutuamente excluyentes se detallan en las descripciones de estas opciones anteriores. Si se especifican más de una opción de los conjuntos de opciones mutuamente excluyentes que se muestran en la sección SYNOPSIS, esto no se considerará un error; la última opción especificada en cada conjunto determinará la salida.

Tenga en cuenta que si se especifica -t, -c y -u no solo son mutuamente excluyentes entre sí, sino que también son mutuamente excluyentes con -S al determinar el orden de ordenación. Pero incluso si se especifica -S después de todas las ocurrencias de -c, -t y -u, el último uso de -c o -u determina la marca de tiempo impresa al producir la salida en formato largo.

archivo
Una ruta de un archivo que se escribirá. Si el archivo especificado no se encuentra, se emitirá un mensaje de diagnóstico en el error estándar.

ENTRADA ESTÁNDAR

No utilizado.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de ls:

COLUMNAS
Determina el ancho preferido del usuario para la posición de la columna al escribir la salida en múltiples columnas de texto. Si esta variable contiene una cadena que representa un entero decimal, la utilidad ls calculará cuántas columnas de texto de nombres de ruta escribir (ver -C) basándose en el ancho proporcionado. Si COLUMNAS no está configurada o es inválida, se asumirá un número de posiciones de columna definido por la implementación, basándose en el conocimiento de la implementación del dispositivo de salida. El ancho de columna elegido para escribir los nombres de los archivos en cualquier directorio dado será constante. Los nombres de archivo no se truncarán para que quepan en la salida de múltiples columnas de texto.
LANG
Proporciona un valor por defecto para las variables de internacionalización que no están establecidas o están vacías. (Ver la sección 8.2, Variables de internacionalización, del volumen de Definiciones Base de POSIX.1-2017 para la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localidad.)
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_COLLATE

Determina la localidad para la información de colación de caracteres al determinar la secuencia de colación de nombres de ruta.
LC_CTYPE
Determina la localidad para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte en lugar de caracteres multibyte en los argumentos) y qué caracteres se definen como imprimibles (clase de caracteres print).
LC_MESSAGES

Determina la localidad que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en el error estándar.
LC_TIME
Determina el formato y el contenido de las cadenas de fecha y hora escritas por ls.
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
TZ
Determina la zona horaria para las cadenas de fecha y hora escritas por ls. Si TZ no está establecida o está vacía, se utilizará una zona horaria por defecto no especificada.

EVENTOS ASINCRONOS

Por defecto.

SALIDA ESTÁNDAR

El formato por defecto será listar una entrada por línea en la salida estándar; las excepciones son para terminales o cuando se especifica una de las opciones -C, -m o -x. Si la salida es a un terminal, el formato es definido por la implementación.

Cuando se especifica -m, el formato utilizado para el último elemento de la lista será:

"%s\n", <nombre de archivo>

El formato utilizado para cada otro elemento de la lista será:

"%s,%s", <nombre de archivo>, <separador>

donde, si no hay espacio para que el siguiente elemento de la lista quepa dentro de la longitud de línea actual, <separador> es una cadena que contiene un carácter de espacio opcional y un carácter de nueva línea obligatorio; de lo contrario, es un único carácter de espacio.

Si se especifica la opción -i, el número de serie del archivo (ver el volumen de Definiciones Base de POSIX.1-2017, <sys_stat.h>) se escribirá en el siguiente formato antes de cualquier otra salida para la entrada correspondiente:

%u ", <número de serie del archivo>

Si se especifica la opción -l, la siguiente información se escribirá para archivos distintos de archivos especiales de carácter y archivos especiales de bloque:

"%s %u %s %s %u %s %s\n", <modo del archivo>, <número de enlaces>,
    <nombre del propietario>, <nombre del grupo>, <tamaño>, <fecha y hora>,
    <ruta del archivo>

Si se especifica la opción -l, la siguiente información se escribirá para archivos especiales de carácter y archivos especiales de bloque:

"%s %u %s %s %s %s %s\n", <modo del archivo>, <número de enlaces>,
    <nombre del propietario>, <nombre del grupo>, <información del dispositivo>, <fecha y hora>,
    <ruta del archivo>

En ambos casos, si el archivo es un enlace simbólico y también se especifica la opción -L, esta información será para el archivo resuelto desde el enlace simbólico, excepto que el campo <ruta del archivo> contendrá la ruta del propio enlace simbólico. Si el archivo es un enlace simbólico y la opción -L no se especifica, esta información será sobre el propio enlace y el campo <ruta del archivo> tendrá el formato:

"%s -> %s", <ruta del enlace>, <contenido del enlace>

Las opciones -n, -g y -o utilizan el mismo formato que -l, pero con elementos omitidos y sus caracteres de espacio asociados. Ver la sección OPCIONES.

En ambas formas anteriores de -l, si no se puede determinar el <nombre del propietario> o el <nombre del grupo>, o si se da -n, se reemplazarán por sus valores numéricos asociados utilizando el formato %u.

El campo <tamaño> contendrá el valor que se devolvería para el archivo en el campo st_size de struct stat (ver el volumen de Definiciones Base de POSIX.1-2017, <sys_stat.h>). Tenga en cuenta que para algunos tipos de archivo este valor no está especificado.

El campo <información del dispositivo> contendrá información definida por la implementación asociada con el dispositivo en cuestión.

El campo <fecha y hora> contendrá la fecha y marca de tiempo apropiada de cuándo se modificó por última vez el archivo. En la localidad POSIX, el campo será el equivalente a la salida del siguiente comando date:

ls - list directory contents

ls −l, ls −n, ls −s, ls −g, ls −o

SYNOPSIS

ls [<option>...] [<file>]...
ls [<option>...]

DESCRIPTION

The ls utility shall list information about the files specified by the operands. If no operands are specified, the information displayed shall be that of the current directory, or in the case of the standard input being redirected to be a directory, that of the directory read from standard input.

If the output is directed to a terminal, it shall be formatted line by line.

If the output is not directed to a terminal, it shall be formatted one entry per line.

The following options shall be supported:

-1
List one file per line.
-a
List all entries except for . and ... If -a is specified, all entries including file names starting with a period, for example, .profile, shall be listed, except for . and ... However, if the -a option is specified, all entries including . and .. shall be listed.
-A
List all entries except for . and ...
-C
List entries by columns.
-d
List directories themselves, not their contents. This option shall affect only the format of the output when a directory is specified as an operand. The default action is to list the contents of the directory.
-f
List files in the order that they appear in the directory, that is, no sorting.
-F
Append a brief summary of the type of each file to the end of the name. The following suffixes shall be added to the names:
'/'
Directory.
'@'
Symbolic link.
'*'
Executable file.
'='
Socket.
'|'
FIFO.
Implementations may add other suffixes to indicate other file types.
-g
Display the group, or username of the file's owner if the -n option is also specified, in the long listing format. This option shall imply the -l option.
-G
Do not list the group owner.
-i
For each file, list the index node number (for example, inode number) used by that file in the file system.
-k
Display the size of files in 1024-byte blocks.
-l
Use a long listing format. The following information shall be displayed for each file:
File mode

The type of the file and the permissions.
Number of hard links

The number of times this file is referenced in the file system.
Owner name

The user name of the file's owner.
Group name

The group name of the file's group.
Total size

The size of the file in bytes. If the file is a character special or block special file, the size of the file is implementation-defined.
Last modification time

The time the file was last modified. The format of the time displayed is implementation-defined, but it shall be one of the following:
If the file has been modified in the last six months, or if the modification date is in the future, the time shall be written in the format: 
date "+%b %e %H:%M"
If the file has not been modified in the last six months, or if the modification date is in the future, the time shall be written in the format: 
date "+%b %e %Y"
(where two <space> characters are used between %e and %Y) if the file has not been modified in the last six months or if the modification date is in the future, except that, in both cases, the final <newline> produced by date shall not be included and the output shall be as if the date command were executed at the time of the last modification date of the file rather than the current time. When the LC_TIME locale category is not set to the POSIX locale, a different format and order of presentation of this field may be used.

If the pathname was specified as a file operand, it shall be written as specified.

The file mode written under the -l, -n, -g, and -o options shall consist of the following format: 
"%c%s%s%s%s", <entry type>, <owner permissions>,
    <group permissions>, <other permissions>,
    <optional alternate access method flag>
The <optional alternate access method flag> shall be the empty string if there is no alternate or additional access control method associated with the file; otherwise, it shall be a string containing a single printable character that is not a <blank>.

The <entry type> character shall describe the type of file, as follows:

d
Directory.
b
Block special file.
c
Character special file.
l (ell)
Symbolic link.
p
FIFO.
-
Regular file.
Implementations may add other characters to this list to represent other implementation-defined file types.

The next three fields shall be three characters each:

<owner permissions>

Permissions for the file owner class (see the Base Definitions volume of POSIX.1‐2017, Section 4.5, File Access Permissions).
<group permissions>

Permissions for the file group class.
<other permissions>

Permissions for the file other class.
Each field shall have three character positions:
1.
If 'r', the file is readable; if '-', the file is not readable.
2.
If 'w', the file is writable; if '-', the file is not writable.
3.
The first of the following that applies:
S
If in <owner permission>, the file is not executable and set-user-ID mode is set. If in <group permissions>, the file is not executable and set-group-ID mode is set.
s
If in <owner permissions>, the file is executable and set-user-ID mode is set. If in <group permissions>, the file is executable and set-group-ID mode is set.
T
If in <other permissions> and the file is a directory, search permission is not granted to others, and the restricted deletion flag is set.
t
If in <other permissions> and the file is a directory, search permission is granted to others, and the restricted deletion flag is set.
x
The file is executable or the directory is searchable.
-
None of the attributes of 'S', 's', 'T', 't', or 'x' applies.
Implementations may add other characters to this list for the third character position. Such additions shall, however, be written in lowercase if the file is executable or searchable, and in uppercase if it is not.

If any of the -l, -n, -s, -g, or -o options is specified, each list of files within the directory shall be preceded by a status line indicating the number of file system blocks occupied by files in the directory in 512-byte units if the -k option is not specified, or 1024-byte units if the -k option is specified, rounded up to the next integral number of units, if necessary. In the POSIX locale, the format shall be:

"total %u\n", <number of units in the directory>

If more than one directory, or a combination of non-directory files and directories are written, either as a result of specifying multiple operands, or the -R option, each list of files within a directory shall be preceded by:

"\n%s:\n", <directory name>

If this string is the first thing to be written, the first <newline> shall not be written. This output shall precede the number of units in the directory.

If the -s option is given, each file shall be written with the number of blocks used by the file. Along with -C, -1, -m, or -x, the number and a <space> shall precede the filename; with -l, -n, -g, or -o, they shall precede each line describing a file.

STDERR

The following sections are informative.

APPLICATION USAGE

Many implementations use the <equals-sign> ('=') to denote sockets bound to the file system for the -F option. Similarly, many historical implementations use the 's' character to denote sockets as the entry type characters for the -l option.

It is difficult for an application to use every part of the file modes field of ls -l in a portable manner. Certain file types and executable bits are not guaranteed to be exactly as shown, as implementations may have extensions. Applications can use this field to pass directly to a user printout or prompt, but actions based on its contents should generally be deferred, instead, to the test utility.

The output of ls (with the -l and related options) contains information that logically could be used by utilities such as chmod and touch to restore files to a known state. However, this information is presented in a format that cannot be used directly by those utilities or be easily translated into a format that can be used. A character has been added to the end of the permissions string so that applications at least have an indication that they may be working in an area they do not understand instead of assuming that they can translate the permissions string into something that can be used. Future versions or related documents may define one or more specific characters to be used based on different standard additional or alternative access control mechanisms.

As with many of the utilities that deal with filenames, the output of ls for multiple files or in one of the long listing formats must be used carefully on systems where filenames can contain embedded white space. Systems and system administrators should institute policies and user training to limit the use of such filenames.

The number of disk blocks occupied by the file that it reports varies depending on underlying file system type, block size units reported, and the method of calculating the number of blocks. On some file system types, the number is the actual number of blocks occupied by the file (counting indirect blocks and ignoring holes in the file); on others it is calculated based on the file size (usually making an allowance for indirect blocks, but ignoring holes).

EXAMPLES

An example of a small directory tree being fully listed with ls -laRF a in the POSIX locale:

total 11
drwxr-xr-x   3 fox      prog          64 Jul  4 12:07 ./
drwxrwxrwx   4 fox      prog        3264 Jul  4 12:09 ../
drwxr-xr-x   2 fox      prog          48 Jul  4 12:07 b/
-rwxr--r--   1 fox      prog         572 Jul  4 12:07 foo*
a/b:
total 4
drwxr-xr-x   2 fox      prog          48 Jul  4 12:07 ./
drwxr-xr-x   3 fox      prog          64 Jul  4 12:07 ../
-rw-r--r--   1 fox      prog         700 Jul  4 12:07 bar

RATIONALE

Some historical implementations of the ls utility show all entries in a directory except dot and dot-dot when a superuser invokes ls without specifying the -a option. When ``normal'' users invoke ls without specifying -a, they should not see information about any files with names beginning with a <period> unless they were named as file operands.

Implementations are expected to traverse arbitrary depths when processing the -R option. The only limitation on depth should be based on running out of physical storage for keeping track of untraversed directories.

The -1 (one) option was historically found in BSD and BSD-derived implementations only. It is required in this volume of POSIX.1‐2017 so that conforming applications might ensure that output is one entry per line, even if the output is to a terminal.

The -F option was added to provide a simple, visual way for users to distinguish file types without having to invoke other utilities. The characters chosen are common across many historical implementations.

The -G option was added because some sites have very long group names, which can make the default output of ls -l difficult to read. Allowing the group name to be omitted simplifies the output.

The -n option, which displays the numeric user ID and group ID instead of the user and group names, was added for compatibility with BSD systems. It is useful for system administrators who may not have access to the user and group name databases.

The behavior of the -l option regarding the timestamp format is based on the requirements of the find utility. The intent is to display times in a way that is easily parsable and human-readable, while also distinguishing between recent and older files.

The specification of the file mode format for the -l option is quite detailed. This is because the file mode field is often used by applications to determine file types and permissions. The standardizes this field across implementations, ensuring greater portability for applications that rely on it. The inclusion of the optional alternate access method flag is a nod to future extensions and security mechanisms.

The inclusion of the block count information (with options like -s and -k) is intended to provide users with information about disk space usage. The specification of the block size units (512 or 1024 bytes) allows for flexibility based on system configuration.

The handling of directory entries and the formatting of output for multiple directories or recursive listings (with -R) are designed to be clear and consistent, with appropriate separators and headers.

RATIONALE

La opción -S se añadió en el Número 7, pero ya había sido proporcionada por varias implementaciones durante muchos años. La descripción dada en los documentos estándar refleja la práctica histórica, pero no coincide con mucha de la documentación que describía su comportamiento. La documentación histórica típicamente la describía como algo así:

-S
Ordenar por tamaño (el tamaño más grande primero) en lugar de por nombre. Los dispositivos de caracteres especiales (listados al final) se ordenan por nombre.

aunque el tipo de archivo nunca se consideró al ordenar la salida. Los archivos de caracteres especiales suelen clasificarse cerca del final de la lista porque su tamaño de archivo en la mayoría de las implementaciones es cero. Pero se ordenan alfabéticamente con cualquier otro archivo que tenga el mismo tamaño de archivo (cero), no se ordenan por separado y se añaden al final.

Este volumen de POSIX.1‐2017 a menudo guarda silencio sobre lo que sucede cuando se especifican opciones mutuamente excluyentes. Excepto por -R, -d y -f, se requiere que la utilidad ls acepte múltiples opciones de cada conjunto de opciones mutuamente excluyentes sin tratarlas como errores y que utilice el comportamiento especificado por la última opción dada en cada conjunto mutuamente excluyente. Dado que ls es uno de los comandos con más alias, es importante que la implementación se comporte de manera intuitiva. Por ejemplo, si el alias fuera:

alias ls="ls -C"

y el usuario escribiera ls -1 (uno), se debería producir una salida de columna de texto única, no un error.

Las opciones -g, -l (ele), -n y -o no son opciones mutuamente excluyentes. Todas ellas habilitan la salida en formato largo. Trabajan juntas para determinar si se escribe el propietario del archivo (no si está presente -g), si se escribe el grupo del archivo (no si está presente -o), y si se escribe el grupo o el propietario del archivo, si se escribe como nombre (por defecto) o una representación en cadena del número UID o GID (si está presente -n). Las opciones -C, -m, -x y -1 (uno) son opciones mutuamente excluyentes y las tres primeras de estas deshabilitan la salida en formato largo. La opción -1 (uno) no cambia directamente si la salida en formato largo está habilitada o no, pero al anular -C, -m y -x, puede volver a habilitar el formato largo que había sido deshabilitado por una de estas opciones.

Las versiones anteriores de este estándar no describían la opción -A de BSD (similar a -a, pero no se escriben punto y punto-punto). Se ha añadido debido a su amplia implementación.

Las implementaciones pueden hacer que -q sea el valor predeterminado para terminales para prevenir ataques de caballo de Troya en terminales con secuencias de escape especiales. Esto no es necesario porque:

*
Algunos caracteres de control pueden ser útiles en algunas terminales; por ejemplo, un sistema podría escribirlos como "\001" o "^A".
*
El comportamiento especial para las terminales no es relevante para la portabilidad de las aplicaciones.

Una propuesta temprana especificó que el indicador <método de acceso alternativo opcional> debía ser '+' si había un método de acceso alternativo utilizado en el archivo o <espacio> si no lo había. Esto se cambió a <espacio> si no lo hay y un solo carácter imprimible si lo hay. Esto se hizo por tres razones:

1.
Existen implementaciones históricas que utilizan caracteres distintos de '+'.
2.
Existen implementaciones que varían este carácter utilizado en esa posición para distinguir entre varios métodos de acceso alternativos en uso.
3.
Los desarrolladores del estándar no querían excluir futuras especificaciones que pudieran necesitar una forma de especificar más de un método de acceso alternativo.

No obstante, se anima a las implementaciones que proporcionan un único método de acceso alternativo a utilizar '+'.

Las versiones anteriores de este estándar no incluían la opción -k, lo que significaba que la opción -s no se podía usar de forma portable ya que su tamaño de bloque era indefinido por la implementación, y las unidades utilizadas para especificar el número de bloques ocupados por archivos en un directorio en un listado de ls -l estaban fijadas en unidades de 512 bytes. La opción -k se ha añadido para proporcionar una forma de usar la opción -s de forma portable, y por consistencia también cambia las unidades mencionadas de 512 bytes a 1024 bytes.

El campo <fecha y hora> en el formato -l solo se especifica para la localización POSIX. Como se señaló, el formato puede ser diferente en otras localizaciones. No hay ningún mecanismo para definir esto en este volumen de POSIX.1‐2017, ya que el vehículo apropiado es un sistema de mensajería; es decir, el formato debe especificarse como un "mensaje".

DIRECCIONES FUTURAS

La posibilidad de que -f ignore las opciones -A, -g, -l, -n, -o y -s podría eliminarse en una versión futura.

Una versión futura de este estándar puede requerir que si la secuencia de ordenación de la localización actual no tiene un orden total de todos los caracteres, los nombres de archivo o ruta que ordenen igual se comparen adicionalmente byte a byte utilizando la secuencia de ordenación para la localización POSIX.
