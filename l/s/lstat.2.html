stat(2) Manual de llamadas al sistema stat(2)

NOMBRE

stat, fstat, lstat, fstatat - obtener estado del archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/stat.h>
int stat(const char *restrict path,
         struct stat *restrict statbuf);
int fstat(int fd, struct stat *statbuf);
int lstat(const char *restrict path,
         struct stat *restrict statbuf);
#include <fcntl.h>           /* Definición de las constantes AT_* */
#include <sys/stat.h>
int fstatat(int dirfd, const char *restrict path,
         struct stat *restrict statbuf, int flags);

DESCRIPCIÓN

Estas funciones devuelven información sobre un archivo, en el búfer apuntado por statbuf. No se requieren permisos sobre el archivo en sí, pero —en el caso de stat(), fstatat() y lstat()— se requieren permisos de ejecución (búsqueda) en todos los directorios en path que conducen al archivo.

stat() y fstatat() recuperan información sobre el archivo al que apunta path; las diferencias para fstatat() se describen a continuación.

lstat() es idéntica a stat(), excepto que si path es un enlace simbólico, entonces devuelve información sobre el propio enlace, no sobre el archivo al que se refiere el enlace.

fstat() es idéntica a stat(), excepto que el archivo sobre el cual se debe obtener información se especifica mediante el descriptor de archivo fd.

La estructura stat

Todas estas llamadas al sistema devuelven una estructura stat (ver stat(3type)).

Nota: por razones de rendimiento y simplicidad, diferentes campos en la estructura stat pueden contener información de estado de diferentes momentos durante la ejecución de la llamada al sistema. Por ejemplo, si st_mode o st_uid son cambiados por otro proceso llamando a chmod(2) o chown(2), stat() podría devolver el st_mode antiguo junto con el st_uid nuevo, o el st_uid antiguo junto con el st_mode nuevo.

fstatat()

La llamada al sistema fstatat() es una interfaz más general para acceder a la información del archivo que aún puede proporcionar exactamente el comportamiento de cada una de stat(), lstat() y fstat().

Si path es relativo, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como lo hacen stat() y lstat() para un nombre de ruta relativo).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso que llama (como stat() y lstat()).

Si path es absoluto, entonces dirfd se ignora.

flags puede ser 0, o incluir una o más de las siguientes banderas ORadas:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si path es una cadena vacía (o NULL, desde Linux 6.11) opera sobre el archivo al que se refiere dirfd (que puede haber sido obtenido usando la bandera open(2) O_PATH). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio, y el comportamiento de fstatat() es similar al de fstat(). Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; define _GNU_SOURCE para obtener su definición.
AT_NO_AUTOMOUNT (desde Linux 2.6.38)
No montar automáticamente el componente terminal ("nombre base") de path. Desde Linux 3.1 esta bandera se ignora. Desde Linux 4.11 esta bandera está implícita.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo desreferencies: en su lugar, devuelve información sobre el propio enlace, como lstat(). (Por defecto, fstatat() desreferencia los enlaces simbólicos, como stat().)

Ver openat(2) para una explicación de la necesidad de fstatat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se deniega el permiso de búsqueda en uno de los directorios del prefijo de ruta de path. (Ver también path_resolution(7)).
EBADF
fd no es un descriptor de archivo abierto válido.
EBADF
(fstatat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
Dirección incorrecta.
EINVAL
(fstatat()) Se especificó una bandera inválida en flags.
ELOOP
Se encontraron demasiados enlaces simbólicos al recorrer la ruta.
ENAMETOOLONG
path es demasiado largo.
ENOENT
Un componente de path no existe o es un enlace simbólico colgante.
ENOENT
path es una cadena vacía y no se especificó AT_EMPTY_PATH en flags.
ENOMEM
Memoria agotada (es decir, memoria del kernel).
ENOTDIR
Un componente del prefijo de ruta de path no es un directorio.
ENOTDIR
(fstatat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EOVERFLOW
path o fd se refieren a un archivo cuyo tamaño, número de inodo o número de bloques no se pueden representar en, respectivamente, los tipos off_t, ino_t o blkcnt_t. Este error puede ocurrir cuando, por ejemplo, una aplicación compilada en una plataforma de 32 bits sin -D_FILE_OFFSET_BITS=64 llama a stat() en un archivo cuyo tamaño excede los (1<<31)-1 bytes.

lstat(2) — Arch manual pages

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/types.h>
#include <sys/stat.h>

int lstat(const char *pathname, struct stat *statbuf);

#include <sys/types.h>
#include <sys/stat.h>

int lstat64(const char *pathname, struct stat64 *statbuf);

DESCRIPTION

The lstat() function is similar to stat(2), but if pathname is a symbolic link, then it returns information about the link itself rather than the file it refers to.

lstat64() is equivalent to lstat(), but uses the struct stat64 structure, which provides larger fields for file sizes and offsets. This is intended to allow the handling of very large files (on 32-bit systems). On systems that do not require this larger structure (e.g., 64-bit systems), lstat64() may be a synonym for lstat().

The struct stat structure (and struct stat64) contains at least the following fields:

st_dev
ID of the device containing the file.
st_ino
Inode number.
st_mode
Protection bits and file type. See the stat(2) manual page for details.
st_nlink
Number of hard links to the file.
st_uid
User ID of the owner.
st_gid
Group ID of the owner.
st_rdev
Device ID if the file is a device file.
st_size
Total size, in bytes, of the file. For regular files, this is the updated size of the file. For symbolic links, this is the length of the pathname stored in the symbolic link.
st_blksize
Preferred block size for file I/O. This may be smaller than st_blocks, for example if the file is sparse.
st_blocks
Number of blocks allocated for this file, 512-byte blocks (this might not be st_blksize blocks).
st_atime
Time of last access.
st_mtime
Time of last modification.
st_ctime
Time of last status change.

The timestamp fields (st_atime, st_mtime, st_ctime) are struct timespec structures, which contain at least the following fields:

tv_sec
Seconds since the Epoch.
tv_nsec
Nanoseconds after the seconds.

The st_mode field describes the type of the file (regular file, directory, symbolic link, etc.) and the permissions for owner, group, and others. The file type bits are encoded in the lower bits of st_mode, using the following masks:

S_IFMT
000170000
S_IFSOCK
000000000
S_IFLNK
000120000
S_IFREG
000100000
S_IFBLK
000060000
S_IFDIR
000040000
S_IFCHR
000020000
S_IFIFO
000010000

The value of st_mode is returned in octal. (These values are symbolic constants defined in <sys/stat.h>.)

For symbolic links, the st_size field contains the length of the symbolic link string.

The fields st_blocks and st_blksize are based on 512-byte blocks and may not be portable.

C library/kernel differences

Historically, the size of the stat structure has increased over time. On 32-bit platforms such as i386, there have been three successive versions of the stat() system call: sys_stat() (system call number __NR_oldstat), sys_newstat() (system call number __NR_stat), and sys_stat64() (system call number __NR_stat64). The first two were present in Linux 1.0; the last was added in Linux 2.4. Similar remarks apply to fstat() and lstat().

The kernel-internal versions of the stat structure are, respectively:

__old_kernel_stat
The original structure, with narrow fields and no padding.
stat
A larger st_ino field and padding added to allow future expansion.
stat64
An even larger st_ino field, larger st_uid and st_gid fields to accommodate the 32-bit UIDs and GIDs introduced in Linux 2.4, and various other enlarged fields and further padding. (Various padding bytes were eventually consumed in Linux 2.6 with the advent of 32-bit device IDs and nanosecond timestamp components.)

The glibc wrapper function stat() hides these details from applications. It invokes the most recent version of the system call provided by the kernel and repacks the returned information if necessary for older binaries.

On modern 64-bit systems, life is simpler: there is a single stat() system call, and the kernel deals with a stat structure whose fields are sufficiently large.

The underlying system call used by the glibc wrapper function fstatat() is actually fstatat64() or, on some architectures, newfstatat().

RETURN VALUE

On success, lstat() and lstat64() return 0. On failure, they return -1, and errno is set to indicate the error.

ERRORS

The lstat() call can fail for the following reasons:

EACCES
Search permission is denied for any component of the prefix of a path prefix of pathname.
EBADF
pathname was invalid (e.g. NULL).
EFAULT
pathname is not a valid user address.
EINVAL
pathname is not a valid path name.
EIO
An I/O error occurred while reading from the filesystem.
ELOOP
Too many symbolic links were encountered while resolving pathname.
ENAMETOOLONG
pathname is too long.
ENOENT
A component of pathname does not exist (e.g. a non-existent file or a non-existent directory component of the path).
ENOMEM
Out of memory.
ENOTDIR
A component of the path prefix of pathname is not a directory.
ENOSYS
The filesystem on which pathname resides is not supported by the kernel.
ENOTSUP
pathname refers to a file on a filesystem that does not support the lstat() operation.
EOVERFLOW
The file contains a value than cannot be represented in struct stat; see statx(2).
EROFS
pathname refers to a file on a read-only filesystem, and too many symbolic links were encountered in resolving pathname.
ETXTBSY
A text file busy. (This error is not specified by POSIX.1-2001, and is not generated by Linux.)

STANDARDS

POSIX.1-2008 requires that lstat() returns valid information in all fields of the struct stat structure, except that the value of st_mode field may not be specified if it refers to a symbolic link. Linux returns the correct st_mode value for symbolic links.

Use of the st_blocks and st_blksize fields may be less portable. (They were introduced in BSD. The interpretation differs between systems, and possibly on a single system when NFS mounts are involved.)

C library/kernel differences

Over time, increases in the size of the stat structure have led to three successive versions of stat(): sys_stat() (slot __NR_oldstat), sys_newstat() (slot __NR_stat), and sys_stat64() (slot __NR_stat64) on 32-bit platforms such as i386. The first two versions were already present in Linux 1.0 (albeit with different names); the last was added in Linux 2.4. Similar remarks apply for fstat() and lstat().

The kernel-internal versions of the stat structure dealt with by the different versions are, respectively:

__old_kernel_stat
The original structure, with rather narrow fields, and no padding.
stat
Larger st_ino field and padding added to various parts of the structure to allow for future expansion.
stat64
Even larger st_ino field, larger st_uid and st_gid fields to accommodate the Linux-2.4 expansion of UIDs and GIDs to 32 bits, and various other enlarged fields and further padding in the structure. (Various padding bytes were eventually consumed in Linux 2.6, with the advent of 32-bit device IDs and nanosecond components for the timestamp fields.)

The glibc stat() wrapper function hides these details from applications, invoking the most recent version of the system call provided by the kernel, and repacking the returned information if required for old binaries.

On modern 64-bit systems, life is simpler: there is a single stat() system call and the kernel deals with a stat structure that contains fields of a sufficient size.

The underlying system call employed by the glibc fstatat() wrapper function is actually called fstatat64() or, on some architectures, newfstatat().

EXAMPLES

The following program calls lstat() and displays selected fields in the returned stat structure.

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <time.h>
int
main(int argc, char *argv[])
{
    struct stat sb;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <path>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (lstat(argv[1], &sb) == -1) {
        perror("lstat");
        exit(EXIT_FAILURE);
    }
    printf("ID of containing device:  [%x,%x]\n",
           major(sb.st_dev),
           minor(sb.st_dev));
    printf("File type:                ");
    switch (sb.st_mode & S_IFMT) {
    case S_IFBLK:  printf("block device\n");            break;
    case S_IFCHR:  printf("character device\n");        break;
    case S_IFDIR:  printf("directory\n");               break;
    case S_IFIFO:  printf("FIFO/pipe\n");               break;
    case S_IFLNK:  printf("symlink\n");                 break;
    case S_IFREG:  printf("regular file\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("unknown?\n");                break;
    }
    printf("I-node number:            %ju\n", (uintmax_t) sb.st_ino);
    printf("Mode:                     %jo (octal)\n",
           (uintmax_t) sb.st_mode);
    printf("Link count:               %ju\n", (uintmax_t) sb.st_nlink);
    printf("Ownership:                UID=%ju   GID=%ju\n",
           (uintmax_t) sb.st_uid, (uintmax_t) sb.st_gid);
    printf("Preferred I/O block size: %jd bytes\n",
           (intmax_t) sb.st_blksize);
    printf("File size:                %jd bytes\n",
           (intmax_t) sb.st_size);
    printf("Blocks allocated:         %jd\n",
           (intmax_t) sb.st_blocks);
    printf("Last status change:       %s", ctime(&sb.st_ctime));
    printf("Last file access:         %s", ctime(&sb.st_atime));
    printf("Last file modification:   %s", ctime(&sb.st_mtime));
    exit(EXIT_SUCCESS);
}
