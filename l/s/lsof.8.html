NOMBRE

lsof - listar archivos abiertos

SINOPSIS

lsof [ -?abChHlnNOPQRtUvVX ] [ -A A ] [ -c c ] [ +c c ] [ +|-d d ] [ +|-D D ] [ +|-e s ] [ +|-E ] [ +|-f [cfgGn] ] [ -F [f] ] [ -g [s] ] [ -i [i] ] [ -k k ] [ -K k ] [ +|-L [l] ] [ +|-m m ] [ +|-M ] [ -o [o] ] [ -p s ] [ +|-r [t[m<fmt>]] ] [ -s [p:s] ] [ -S [t] ] [ -T [t] ] [ -u s ] [ +|-w ] [ -x [fl] ] [ -z [z] ] [ -Z [Z] ] [ -- ] [nombres]

DESCRIPCIÓN

Lsof revisión 4.99.5 lista en su salida estándar información de archivos sobre archivos abiertos por procesos para los siguientes dialectos de UNIX:

Apple Darwin 9, Mac OS X 10, macOS 11 y superior
FreeBSD 8.2 y superior
Linux 2.1.72 y superior
NetBSD 1.2 y superior
OpenBSD 7.2 y superior
Solaris 9, 10 y 11 y superior
OpenIndiana 5.11 y superior

(Consulte la sección DISTRIBUTION de esta página del manual para obtener información sobre cómo obtener la última revisión de lsof.)

Un archivo abierto puede ser un archivo regular, un directorio, un archivo especial de bloque, un archivo especial de carácter, una referencia de texto ejecutando, una biblioteca, un stream o un archivo de red (socket de Internet, archivo NFS o socket de dominio UNIX). Se puede seleccionar un archivo específico o todos los archivos en un sistema de archivos por ruta.

En lugar de una visualización formateada, lsof producirá una salida que puede ser analizada por otros programas. Consulte la opción -F y la sección SALIDA PARA OTROS PROGRAMAS para más información.

Además de producir una lista de salida única, lsof se ejecutará en modo repetido. En modo repetido, producirá una salida, se detendrá y repetirá la operación de salida hasta que se detenga con una señal de interrupción o de salida. Consulte la descripción de la opción +|-r [t[m<fmt>]] para más información.

OPCIONES

En ausencia de cualquier opción, lsof lista todos los archivos abiertos pertenecientes a todos los procesos activos.

Si se especifica alguna opción de solicitud de lista, se deben solicitar explícitamente otras solicitudes de lista; por ejemplo, si se especifica -U para la lista de archivos de socket UNIX, los archivos NFS no se listarán a menos que también se especifique -N; o si se especifica una lista de usuarios con la opción -u, los archivos de socket de dominio UNIX, pertenecientes a usuarios que no están en la lista, no se listarán a menos que también se especifique la opción -U.

Normalmente, las opciones de lista que se especifican se combinan con OR (O) — es decir, especificar la opción -i sin una dirección y la opción -ufoo produce una lista de todos los archivos de red O archivos pertenecientes a procesos propiedad del usuario ``foo''. Las excepciones son:

1)
el nombre de inicio o ID de usuario (UID) `^' (negado), especificado con la opción -u;
2)
el PID (ID de proceso) `^' (negado), especificado con la opción -p;
3)
el PGID (ID de grupo de procesos) `^' (negado), especificado con la opción -g;
4)
el comando `^' (negado), especificado con la opción -c;
5)
los nombres de estado de protocolo TCP o UDP `^' (negados), especificados con la opción -s [p:s].

Dado que representan exclusiones, se aplican sin OR ni AND y surten efecto antes de que se apliquen otros criterios de selección.

La opción -a puede usarse para combinar (AND) las selecciones. Por ejemplo, especificar -a, -U y -ufoo produce una lista solo de archivos de socket UNIX que pertenecen a procesos propiedad del usuario ``foo''.

Precaución: la opción -a hace que todas las opciones de selección de lista se combinen con AND; no se puede usar para combinar pares seleccionados de opciones de selección colocando la opción entre ellos, aunque su colocación allí es aceptable. Dondequiera que se coloque -a, causa la combinación AND de todas las opciones de selección.

Los elementos del mismo conjunto de selección (nombres de comando, descriptores de archivo, direcciones de red, identificadores de proceso, identificadores de usuario, nombres de zona, contextos de seguridad) se unen en un único conjunto ORed y se aplican antes de que el resultado participe en el ANDing. Por lo tanto, por ejemplo, especificar -i@aaa.bbb, -i@ccc.ddd, -a, y -ufff,ggg seleccionará la lista de archivos que pertenecen a cualquiera de los nombres de inicio ``fff'' O ``ggg'' Y tienen conexiones de red a cualquiera de los hosts aaa.bbb O ccc.ddd.

Las opciones pueden agruparse juntas después de un solo prefijo; por ejemplo, el conjunto de opciones ``-a -b -C'' puede indicarse como -abC. Sin embargo, dado que los valores son opcionales después de +|-f, -F, -g, -i, +|-L, -o, +|-r, -s, -S, -T, -x y -z, cuando no tienes valores para ellos, ten cuidado de que el siguiente carácter no sea ambiguo. Por ejemplo, -Fn podría representar las opciones -F y -n, o podría representar el carácter identificador de campo n después de la opción -F. Cuando la ambigüedad es posible, inicie una nueva opción con un carácter `-'; por ejemplo, ``-F -n''. Si la siguiente opción es un nombre de archivo, siga la opción posiblemente ambigua con ``--''; por ejemplo, ``-F -- nombre''.

Se puede aplicar el prefijo `+' o `-' a un grupo de opciones. Las opciones que no tienen significados separados para cada prefijo (por ejemplo, -i) pueden agruparse bajo cualquiera de los prefijos. Por lo tanto, por ejemplo, ``+M -i'' puede indicarse como ``-iM'' y el grupo significa lo mismo que las opciones separadas. Tenga cuidado con la agrupación de prefijos cuando una o más opciones del grupo tengan significados separados bajo prefijos diferentes (por ejemplo, +|-M); ``-iM'' no es la misma solicitud que ``-i +M''. En caso de duda, utilice opciones separadas con los prefijos apropiados.

-? -h
Estas dos opciones equivalentes seleccionan una lista de salida de uso (ayuda). Lsof muestra una forma abreviada de esta salida cuando detecta un error en las opciones proporcionadas, después de mostrar mensajes que explican cada error. (Escapa el carácter `?' como requiera tu shell.)
-a
hace que las opciones de selección de lista se combinen con AND, como se describe anteriormente.
-A A
está disponible en sistemas configurados para AFS cuyo código de kernel de AFS está implementado a través de módulos dinámicos. Permite al usuario de lsof especificar A como un archivo de lista de nombres alternativo donde se pueden encontrar las direcciones del kernel de los módulos dinámicos. Consulte el FAQ de lsof (La sección FAQ indica su ubicación) para obtener más información sobre módulos dinámicos, sus símbolos y cómo afectan a lsof.
-b
hace que lsof evite las funciones del kernel que podrían bloquearse (como lstat(2), readlink(2) y stat(2)).
Consulte las secciones BLOQUEOS Y TIEMPO DE ESPERA y EVITAR BLOQUEOS DEL KERNEL para obtener información sobre el uso de esta opción.
-c c
selecciona la lista de archivos para procesos que ejecutan el comando que comienza con los caracteres de c. Se pueden especificar múltiples comandos, utilizando múltiples opciones -c. Se combinan en un único conjunto ORed antes de participar en la selección de opciones AND.
Si c comienza con un `^', entonces los caracteres siguientes especifican un nombre de comando cuyos procesos deben ser ignorados (excluidos).
Si c comienza y termina con una barra ('/'), los caracteres entre las barras se interpretan como una expresión regular. Los meta-caracteres del shell en la expresión regular deben ser citados para evitar su interpretación por el shell. La barra de cierre puede ir seguida de estos modificadores:
	b	la expresión regular es básica.
	i	ignora la capitalización de letras.
	x	la expresión regular es extendida
		(por defecto).
Consulte el FAQ de lsof (La sección FAQ indica su ubicación) para obtener más información sobre expresiones regulares básicas y extendidas.
La especificación simple del comando se prueba primero. Si esa prueba falla, se aplica la expresión regular del comando. Si la prueba simple del comando tiene éxito, no se realiza la prueba de la expresión regular del comando. Esto puede resultar en mensajes de ``no se encontró comando para regex:'' cuando se especifica la opción -V de lsof.
+c w
define el número máximo de caracteres iniciales del nombre, suministrado por el dialecto UNIX, del comando UNIX asociado a un proceso que se imprimirá en la columna COMMAND. (El valor predeterminado de lsof es nueve).
Tenga en cuenta que muchos dialectos UNIX no suministran todos los caracteres del nombre del comando a lsof en los archivos y estructuras desde los que lsof obtiene el nombre del comando. A menudo, los dialectos limitan el número de caracteres suministrados en esas fuentes. Por ejemplo, Linux 2.4.27 y Solaris 9 limitan la longitud del nombre del comando a 16 caracteres.
Si w es cero ('0'), se imprimirán todos los caracteres del comando suministrados a lsof por el dialecto UNIX.
Si w es menor que la longitud del título de la columna, ``COMMAND'', se aumentará a esa longitud.
-C
deshabilita el informe de cualquier componente de nombre de ruta de la caché de nombres del kernel. Consulte la sección KERNEL NAME CACHE para obtener más información.
+d s
hace que lsof busque todas las instancias abiertas del directorio s y los archivos y directorios que contiene en su nivel superior. +d NO desciende por el árbol de directorios, con raíz en s. La opción +D D se puede usar para solicitar una búsqueda completa en el árbol de directorios, con raíz en el directorio D.
El procesamiento de la opción +d no sigue enlaces simbólicos dentro de s a menos que también se especifique la opción -x o -x l. Tampoco busca archivos abiertos en puntos de montaje de sistemas de archivos en subdirectorios de s a menos que también se especifique la opción -x o -x f.
Nota: la autoridad del usuario de esta opción lo limita a buscar archivos que el usuario tiene permiso para examinar con la función stat(2) del sistema.
-d s
especifica una lista de descriptores de archivo (FD) para excluir o incluir en el listado de salida. Los descriptores de archivo se especifican en el conjunto separado por comas s, por ejemplo, ``cwd,1,3'', ``^6,^2''. (No debe haber espacios en el conjunto).
La lista es una lista de exclusión si todas las entradas del conjunto comienzan con `^'. Es una lista de inclusión si ninguna entrada comienza con `^'. No se permiten listas mixtas.
Un rango de números de descriptores de archivo puede estar en el conjunto siempre que ninguno de los miembros esté vacío, ambos miembros sean números y el miembro final sea mayor que el inicial, por ejemplo, ``0-7'' o ``3-10''. Los rangos se pueden especificar para exclusión si tienen el prefijo `^', por ejemplo, ``^0-7'' excluye todos los descriptores de archivo del 0 al 7.
Múltiples números de descriptores de archivo se unen en un único conjunto OR antes de participar en la selección de opciones AND.
Cuando hay miembros de exclusión e inclusión en el conjunto, lsof los informa como errores y sale con un código de retorno distinto de cero.
Consulte la descripción de los valores de salida del Descriptor de Archivo (FD) en la sección SALIDA para obtener más información sobre los nombres de los descriptores de archivo.
fd es un nombre de descriptor de archivo pseudo para especificar todo el rango de números de descriptores de archivo posibles. fd no aparece en la columna FD de la salida.
+D D
hace que lsof busque todas las instancias abiertas del directorio D y todos los archivos y directorios que contiene hasta su profundidad completa.
El procesamiento de la opción +D no sigue enlaces simbólicos dentro de D a menos que también se especifique la opción -x o -x l. Tampoco busca archivos abiertos en puntos de montaje de sistemas de archivos en subdirectorios de D a menos que también se especifique la opción -x o -x f.
Nota: la autoridad del usuario de esta opción lo limita a buscar archivos que el usuario tiene permiso para examinar con la función stat(2) del sistema.
Nota adicional: lsof puede procesar esta opción lentamente y requerir una gran cantidad de memoria dinámica para hacerlo. Esto se debe a que debe descender por todo el árbol de directorios, con raíz en D, llamando a stat(2) para cada archivo y directorio, construyendo una lista de todos los archivos que encuentra y buscando en esa lista una coincidencia con cada archivo abierto. Cuando el directorio D es grande, estos pasos pueden llevar mucho tiempo, así que use esta opción con prudencia.
-D D
dirige el uso de lsof del archivo de caché de dispositivos. El uso de esta opción está restringido en ocasiones. Consulte la sección ARCHIVO DE CACHÉ DE DISPOSITIVOS y las secciones posteriores para obtener más información sobre esta opción.
A -D le debe seguir una letra de función; la letra de función puede ir seguida opcionalmente de un nombre de ruta. Lsof reconoce las siguientes letras de función:
? - informa las rutas del archivo de caché de dispositivos
b - crea el archivo de caché de dispositivos
i - ignora el archivo de caché de dispositivos
r - lee el archivo de caché de dispositivos
u - lee y actualiza el archivo de caché de dispositivos
Las funciones b, r y u, acompañadas de un nombre de ruta, a veces están restringidas. Cuando estas funciones están restringidas, no aparecerán en la descripción de la opción -D que acompaña a la salida de las opciones -h o -?. Consulte la sección ARCHIVO DE CACHÉ DE DISPOSITIVOS y las secciones posteriores para obtener más información sobre estas funciones y cuándo están restringidas.
La función ? informa las rutas de solo lectura y escritura que lsof puede usar para el archivo de caché de dispositivos, los nombres de las variables de entorno cuyos valores lsof examinará al formar la ruta del archivo de caché de dispositivos y el formato de la ruta del archivo de caché de dispositivos personal. (Escápese el carácter `?' como requiera su shell.)
Cuando estén disponibles, las funciones b, r y u pueden ir seguidas de la ruta del archivo de caché de dispositivos. El valor predeterminado estándar es .lsof_hostname en el directorio principal del ID de usuario real que ejecuta lsof, pero esto podría haber cambiado cuando lsof se configuró y compiló. (La salida de las opciones -h y -? muestra el prefijo predeterminado actual, por ejemplo, ``.lsof''.) El sufijo, hostname, es el primer componente del nombre del host devuelto por gethostname(2).
Cuando esté disponible, la función b dirige lsof a crear un nuevo archivo de caché de dispositivos en la ruta predeterminada o especificada.
La función i dirige lsof a ignorar el archivo de caché de dispositivos predeterminado y obtener su información sobre dispositivos a través de llamadas directas al kernel.
La función r dirige lsof a leer la caché de dispositivos en la ruta predeterminada o especificada, pero le impide crear un nuevo archivo de caché de dispositivos cuando no existe o el existente tiene una estructura incorrecta. La función r, cuando se especifica sin un nombre de ruta, impide que lsof actualice un archivo de caché de dispositivos incorrecto o desactualizado, o que cree uno nuevo en su lugar. La función r siempre está disponible cuando se especifica sin argumento de nombre de ruta; puede estar restringida por los permisos del proceso lsof.
Cuando esté disponible, la función u dirige lsof a leer el archivo de caché de dispositivos en la ruta predeterminada o especificada, si es posible, y a reconstruirlo, si es necesario. Esta es la función de archivo de caché de dispositivos predeterminada cuando no se ha especificado ninguna opción -D.
+|-e s
exime al sistema de archivos cuya ruta es s de ser sometido a llamadas de funciones del kernel que podrían bloquearse. La opción +e exime las llamadas de funciones del kernel stat(2), lstat(2) y la mayoría de readlink(2). La opción -e exime solo las llamadas de funciones del kernel stat(2) y lstat(2). Se pueden especificar varios sistemas de archivos con especificaciones separadas de +|-e y cada uno puede tener eximidas o no las llamadas a readlink(2).
Esta opción solo está implementada actualmente para Linux.
PRECAUCIÓN: esta opción se puede aplicar erróneamente fácilmente a otros sistemas de archivos que no son el de interés, ya que utiliza el nombre de ruta en lugar de los números de dispositivo e inodo más fiables. (Los números de dispositivo e inodo se obtienen a través de la llamada al kernel stat(2), que puede bloquearse, por lo que no están disponibles, pero consulte la opción +|-m m como posible forma alternativa de suministrar números de dispositivo.) Use esta opción con gran cuidado y especifique completamente el nombre de ruta del sistema de archivos a eximir.
Cuando se informan archivos abiertos en sistemas de archivos eximidos, es posible que no se pueda obtener toda su información. Por lo tanto, algunas columnas de información estarán en blanco, los caracteres ``UNKN'' precederán a los valores en la columna TIPO y la opción de exención aplicable se agregará entre paréntesis al final de la columna NOMBRE. (Se podría obtener información sobre el número de dispositivo a través de la opción +|-m m.)
+|-E
+E especifica que las tuberías de Linux, los sockets UNIX de Linux, los sockets INET(6) de Linux cerrados en un host local, los archivos de pseudoterminal de Linux, la implementación de colas de mensajes POSIX en Linux y eventfd de Linux se mostrarán con información de punto final y también se mostrarán los archivos de los puntos finales.
Nota 1: La información del punto final del archivo de socket UNIX solo está disponible cuando la línea de características habilitadas de la salida -v contiene uxsockept, y la información del punto final del pseudoterminal solo está disponible cuando la línea de características habilitadas contiene ptyept.
Nota 2: La información del punto final del archivo de cola de mensajes POSIX solo está disponible cuando el sistema de archivos de cola de mensajes está montado.
La información del punto final de la tubería se muestra en la columna NOMBRE en el formato ``PID,cmd,FDmode'', donde PID es el ID del proceso del punto final; cmd es el comando del proceso del punto final; FD es el descriptor del archivo del punto final; y mode es el modo de acceso del archivo del punto final.
La información del punto final del pseudoterminal se muestra en la columna NOMBRE como ``->/dev/ptsmin PID,cmd,FDmode'' o ``PID,cmd,FDmode''. La primera forma es para un dispositivo maestro; la segunda, para un dispositivo esclavo. min es el número de dispositivo menor de un dispositivo esclavo; y PID, cmd, FD y mode son los mismos que con la información del punto final de la tubería. Nota: la información del punto final del pseudoterminal i
La información solo está disponible cuando la línea de características habilitadas de la salida de -v contiene ptyept. Además, esta característica funciona en kernels de Linux superiores a 4.13.0.
La información del extremo del archivo de socket UNIX se muestra en la columna NOMBRE con el formato
``type=TIPO ->INO=INODO PID,cmd,FDmodo'', donde TIPO es el tipo de socket; INODO es el número i del socket conectado; y PID, cmd, FD y modo son los mismos que con la información del extremo del pipe. Nota: la información del extremo del archivo de socket UNIX solo está disponible cuando la línea de características habilitadas de la salida de -v contiene uxsockept.
La información del extremo del archivo de socket INET se inserta en el valor de la columna NOMBRE con el formato
`` -> PID,cmd,FDmodo'', donde PID, cmd, FD y modo son los mismos que con la información del extremo del pipe. La información del extremo solo está disponible si el socket se utiliza para IPC local; ambos extremos se enlazan a la misma dirección local IPv4 o IPv6.
La información del extremo del archivo de cola de mensajes POSIX se muestra en la columna NOMBRE con el mismo formato que la del pipe.
La información del extremo eventfd se muestra en la columna NOMBRE con el mismo formato que la del pipe. Esta característica funciona en kernels de Linux superiores a 5.2.0.
Pueden aparecer múltiples ocurrencias de esta información en la columna NOMBRE de un archivo.
-E especifica que los archivos compatibles con extremos se muestren con información de extremos, pero no los archivos de los extremos.
+|-f [cfgGn]
f por sí sola aclara cómo se deben interpretar los argumentos de nombre de ruta. Cuando va seguida de c, f, g, G o n en cualquier combinación, especifica que la visualización de información de la estructura de archivos del kernel se habilitará (`+') o se inhibirá (`-').
Normalmente, un argumento de nombre de ruta se toma como nombre de sistema de archivos si coincide con un directorio montado informado por mount(8), o si representa un dispositivo de bloque, nombrado en la salida de mount y asociado con un nombre de directorio montado. Cuando se especifica +f, todos los argumentos de nombre de ruta se tomarán como nombres de sistemas de archivos, y lsof se quejará si alguno no lo es. Esto puede ser útil, por ejemplo, cuando el nombre del sistema de archivos (dispositivo montado) no es un dispositivo de bloque. Esto ocurre para algunos sistemas de archivos de CD-ROM.
Cuando se especifica -f por sí solo, todos los argumentos de nombre de ruta se tomarán como archivos simples. Por lo tanto, por ejemplo, los argumentos ``-f -- /'' indican a lsof que busque archivos abiertos con un nombre de ruta `/`, no todos los archivos abiertos en el sistema de archivos `/` (raíz).
Tenga cuidado de asegurarse de que +f y -f estén debidamente terminados y no seguidos por un carácter (por ejemplo, del nombre del archivo o sistema de archivos) que pueda tomarse como parámetro. Por ejemplo, use ``--'' después de +f y -f como en estos ejemplos.
$ lsof +f -- /nombre/sistema/de/archivos
$ lsof -f -- /nombre/archivo
La visualización de información de las estructuras de archivos del kernel, solicitada con la forma de opción +f [cfgGn], normalmente se inhibe, y no está disponible en su totalidad o en parte para algunos dialectos, por ejemplo, kernels de Linux basados en /proc anteriores a 2.6.22. Cuando el prefijo de f es un signo más (`+'), estos caracteres solicitan información de la estructura de archivos:
c	recuento de uso de la estructura de archivos (no Linux)
f	dirección de la estructura de archivos (no Linux)
g	abreviaturas de banderas de archivo (Linux 2.6.22 y posteriores)
	Abrev.	Bandera en código C (ver open(2))
	W		O_WRONLY
	RW		O_RDWR
	CR		O_CREAT
	EXCL		O_EXCL
	NTTY		O_NOCTTY
	TR		O_TRUNC
	AP		O_APPEND
	ND		O_NDELAY
	SYN		O_SYNC
	ASYN		O_ASYNC
	DIR		O_DIRECT
	DTY		O_DIRECTORY
	NFLK		O_NOFOLLOW
	NATM		O_NOATIME
	DSYN		O_DSYNC
	RSYN		O_RSYNC
	LG		O_LARGEFILE
	CX		O_CLOEXEC
	TMPF		O_TMPFILE
G	banderas de archivo en hexadecimal (Linux 2.6.22 y posteriores)
n	dirección del nodo de la estructura de archivos (no Linux)
Cuando el prefijo es un signo menos (`-'), los mismos caracteres deshabilitan la visualización de los valores indicados.
Las direcciones de las estructuras de archivos, los recuentos de uso, las banderas y las direcciones de nodo pueden usarse para detectar más fácilmente archivos idénticos heredados por procesos hijos y archivos idénticos en uso por diferentes procesos. La salida de columnas de lsof puede ordenarse por las columnas de salida que contienen los valores y listarse para identificar el uso idéntico de archivos, o la salida de campos de lsof puede ser procesada por un script de post-filtrado de AWK o Perl, o por un programa C.
-F f
especifica una lista de caracteres, f, que selecciona los campos a emitir para su procesamiento por otro programa, y el carácter que termina cada campo de salida. Cada campo a emitir se especifica con un solo carácter en f. El terminador de campo por defecto es NL, pero puede cambiarse a NUL (000). Consulte la sección SALIDA PARA OTROS PROGRAMAS para obtener una descripción de los caracteres de identificación de campo y el proceso de salida de campo.
Cuando la lista de caracteres de selección de campo está vacía, se seleccionan todos los campos estándar (excepto el campo de dispositivo bruto, el contexto de seguridad y el campo de zona por razones de compatibilidad) y se utiliza el terminador de campo NL.
Cuando la lista de caracteres de selección de campo contiene solo un cero (`0'), se seleccionan todos los campos (excepto el campo de dispositivo bruto por razones de compatibilidad) y se utiliza el carácter terminador NUL.
Otras combinaciones de campos y su carácter terminador de campo asociado deben configurarse con entradas explícitas en f, como se describe en la sección SALIDA PARA OTROS PROGRAMAS.

-t
produce una salida concisa que consta solo de identificadores de proceso (sin encabezado), para que sea fácil de usar programáticamente
-t
Prints only the process IDs (PIDs) of the selected processes. The output is a blank-separated list of PIDs, or one PID per line, or a blank-separated list of PIDs, each on a line of its own, depending on the options that accompany the -t option.
# reload anything using old SSL
lsof -t /lib/*/libssl.so.* | xargs -r kill -HUP
# get list of processes and then iterate over them (Bash only)
mapfile -t pids < <(
    lsof -wt /var/log/your.log
)
for pid in "${pids[@]}" ; do
    your_command -p "$pid"
done
The -t option implies the -w option.
-u s
selecciona la lista de archivos para el usuario cuyos nombres de inicio de sesión o números de identificación de usuario se encuentran en el conjunto separado por comas s, por ejemplo, ``abe'', o ``548,root''. (No debería haber espacios en el conjunto).
Se unen múltiples nombres de inicio de sesión o números de identificación de usuario en un solo conjunto OR antes de participar en la selección de opciones AND.
Si a un nombre de inicio de sesión o ID de usuario le precede un `^', se convierte en una negación, es decir, los archivos de procesos propiedad del nombre de inicio de sesión o ID de usuario nunca se listarán. Una selección negada de nombre de inicio de sesión o ID de usuario no se une ni se combina con otras selecciones; se aplica antes que todas las demás selecciones y excluye absolutamente la lista de archivos del proceso. Por ejemplo, para indicar a lsof que excluya la lista de archivos pertenecientes a procesos root, especifique ``-u^root'' o ``-u^0''.
-U
selecciona la lista de archivos de socket de dominio UNIX.
-v
selecciona la lista de información de la versión de lsof, incluyendo: número de revisión; cuándo se construyó el binario de lsof; quién construyó el binario y dónde; el nombre del compilador utilizado para construir el binario de lsof; el número de versión del compilador cuando esté fácilmente disponible; las marcas del compilador y el enlazador utilizadas para construir el binario de lsof; e información del sistema, típicamente la salida de la opción -a de uname.
-V
indica a lsof que muestre los elementos que se le pidió listar y que no encontró: nombres de comandos, nombres de archivos, direcciones o archivos de Internet, nombres de inicio de sesión, archivos NFS, PID, PGID y UID.
Cuando se combinan otras opciones con las opciones de búsqueda, o las opciones de tiempo de compilación restringen la lista de algunos archivos, lsof puede no informar que no encontró un elemento de búsqueda cuando una opción combinada o una opción de tiempo de compilación evita listar el archivo abierto que contiene el elemento de búsqueda encontrado.
Por ejemplo, ``lsof -V -iTCP@foobar -a -d 999'' puede no informar de un fallo al localizar archivos abiertos en ``TCP@foobar'' y puede no listar ninguno, si ninguno tiene un número de descriptor de archivo de 999. Una situación similar surge cuando HASSECURITY y HASNOSOCKSECURITY se definen en el tiempo de compilación y restringen la lista de archivos abiertos.
+|-w
Habilita (+) o deshabilita (-) la supresión de mensajes de advertencia.
El creador de lsof puede elegir tener los mensajes de advertencia deshabilitados o habilitados por defecto. El estado por defecto de los mensajes de advertencia se indica en la salida de la opción -h o -?. Deshabilitar los mensajes de advertencia cuando ya están deshabilitados o habilitarlos cuando ya están habilitados es aceptable.
La opción -t implica la opción -w.
-x [fl]
puede acompañar a las opciones +d y +D para dirigir su procesamiento a cruzar enlaces simbólicos y/o puntos de montaje de sistema de archivos encontrados al escanear el directorio (+d) o el árbol de directorios (+D).
Si se especifica -x por sí sola sin un parámetro siguiente, se habilita el procesamiento de cruce de enlaces simbólicos y puntos de montaje de sistema de archivos. Tenga en cuenta que cuando se especifica -x sin un parámetro, el siguiente argumento debe comenzar con '-' o '+'.
El parámetro opcional 'f' habilita el procesamiento de cruce de puntos de montaje de sistema de archivos; 'l', el procesamiento de cruce de enlaces simbólicos.
La opción -x no puede suministrarse sin suministrar también una opción +d o +D.
-X
Esta es una opción específica del dialecto.

    AIX:
Esta opción de IBM AIX RISC/System 6000 solicita la notificación de referencias de archivos de texto y bibliotecas compartidas ejecutados.

ADVERTENCIA: debido a que esta opción utiliza la función readx() del kernel, su uso en un sistema AIX ocupado podría causar que un proceso aplicación se cuelgue de tal manera que no pueda ser ni terminado ni detenido. Nunca he visto que esto suceda ni he tenido informes de que haya sucedido, pero creo que existe una posibilidad remota de que pueda suceder.
Por defecto, el uso de readx() está deshabilitado. En AIX 5L y superior, lsof puede necesitar permisos setuid-root para realizar las acciones que solicita esta opción.
El creador de lsof puede especificar que la opción -X se restrinja a procesos cuyo UID real sea root. Si eso se ha hecho, la opción -X no aparecerá en la salida de ayuda de -h o -? a menos que el UID real del proceso lsof sea root. La distribución por defecto de lsof permite a cualquier UID especificar -X, por lo que por defecto aparecerá en la salida de ayuda.
Cuando el uso de AIX readx() está deshabilitado, lsof puede no ser capaz de informar información para todas las referencias de archivos de texto y cargador, pero también puede evitar exacerbar un error del kernel de búsqueda de directorios del kernel de AIX, conocido como el error Stale Segment ID.
La función readx(), utilizada por lsof o cualquier otro programa para acceder a algunas secciones de la memoria virtual del kernel, puede activar el error Stale Segment ID. Puede hacer que la función dir_search() del kernel crea erróneamente que parte de una copia en memoria de un directorio del sistema de archivos ha sido puesta a cero. Otro proceso aplicación, distinto de lsof, que solicite al kernel que busque en el directorio - por ejemplo, usando open(2) - puede hacer que dir_search() entre en un bucle infinito, colgando así el proceso aplicación.
Consulte el FAQ de lsof (La sección FAQ indica su ubicación) y el archivo 00README de la distribución de lsof para obtener una descripción más completa del error Stale Segment ID, su APAR y los métodos para definir el uso de readx() al compilar lsof.

    Linux:
Esta opción de Linux solicita que lsof omita la notificación de información sobre todos los archivos abiertos TCP, UDP y UDPLITE IPv4 e IPv6.

Esta opción de Linux es más útil cuando el sistema tiene un número extremadamente grande de archivos TCP, UDP y UDPLITE abiertos, cuyo procesamiento de información en los archivos /proc/net/tcp* y /proc/net/udp* llevaría mucho tiempo a lsof, y cuya notificación no es de interés.
Utilice esta opción con cuidado y solo cuando esté seguro de que la información que desea que muestre lsof no está asociada con archivos de socket TCP, UDP o UDPLITE abiertos.

    Solaris 10 y superior:
Esta opción de Solaris 10 y superior solicita la notificación de rutas en caché de archivos que han sido eliminados, es decir, eliminados con rm(1) o unlink(2).

La ruta en caché va seguida de la cadena `` (eliminado)'' para indicar que la ruta por la que se abrió el archivo ha sido eliminada.
Debido a que los cambios intermedios realizados en la ruta, es decir, renombres con mv(1) o rename(2), no se registran en la ruta en caché, lo que lsof informa es solo la ruta por la que se abrió el archivo, no su ruta final posiblemente diferente.
-z [z]
especifica cómo se deben manejar la información de las zonas de Solaris 10 y superiores.
Sin un argumento siguiente, por ejemplo, SIN z, la opción especifica que los nombres de zona se listarán en la columna de salida ZONE.
La opción -z puede ir seguida de un nombre de zona, z. Eso hace que lsof liste solo los archivos abiertos para procesos en esa zona. Se pueden especificar múltiples pares de opciones -z z para formar una lista de zonas con nombre. Se listará cualquier archivo abierto de cualquier proceso en cualquiera de las zonas, sujeto a otras condiciones especificadas por otras opciones y argumentos.
-Z [Z]
especifica cómo se deben manejar los contextos de seguridad SELinux. Esta y la soporte del carácter de salida del campo 'Z' se inhiben cuando SELinux está deshabilitado en el kernel de Linux en ejecución. Consulte SALIDA PARA OTROS PROGRAMAS para obtener más información sobre el carácter de salida del campo 'Z'.
Sin un argumento siguiente, por ejemplo, SIN Z, la opción especifica que los contextos de seguridad se listarán en la columna de salida SECURITY-CONTEXT.
La opción -Z puede ir seguida de un nombre de contexto de seguridad comodín, Z. Eso hace que lsof liste solo los archivos abiertos para procesos en ese contexto de seguridad. Se pueden especificar múltiples pares de opciones -Z Z para formar una lista de contextos de seguridad. Se listará cualquier archivo abierto de cualquier proceso en cualquiera de los contextos de seguridad, sujeto a otras condiciones especificadas por otras opciones y argumentos. Tenga en cuenta que Z puede ser A:B:C o *:B:C o A:B:* o *:*:C para coincidir con el contexto A:B:C.
--
La opción de doble guion es un marcador que indica el final de las opciones con clave. Se puede utilizar, por ejemplo, cuando el primer nombre de archivo comienza con un guion. También se puede utilizar cuando la ausencia de un valor para la última opción con clave debe significarse por la presencia de un guion en la opción siguiente y antes del inicio de los nombres de archivo.
nombres
Estos son nombres de ruta de archivos específicos a listar. Los enlaces simbólicos se resuelven antes de usarlos. El primer nombre puede separarse de las opciones anteriores con la opción ``--''.
Si un nombre es el directorio montado de un sistema de archivos o el dispositivo del sistema de archivos, lsof listará todos los archivos abiertos en el sistema de archivos. Para ser considerado un sistema de archivos, el nombre debe coincidir con un nombre de directorio montado en la salida de mount(8), o coincidir con el nombre de un dispositivo de bloque asociado con un nombre de directorio montado. La opción +|-f se puede utilizar para forzar a lsof a considerar un nombre como identificador de sistema de archivos (+f) o como archivo simple (-f).
Si name es una ruta a un directorio que no es el nombre del directorio montado de un sistema de archivos, se trata como un archivo regular; es decir, su listado se restringe a los procesos que lo tienen abierto como archivo o como directorio específico del proceso, como la raíz o el directorio de trabajo actual. Para solicitar que lsof busque archivos abiertos dentro del nombre de un directorio, use las opciones +d s y +D D.
Si un name es el nombre base de una familia de archivos multiplexados, por ejemplo, /dev/pt[cs] de AIX, lsof listará todos los archivos multiplexados asociados en el dispositivo que estén abiertos, por ejemplo, /dev/pt[cs]/1, /dev/pt[cs]/2, etc.
Si name es un nombre de socket de dominio UNIX, lsof generalmente lo buscará solo por los caracteres del nombre, exactamente como se especifica y se registra en la estructura del socket del kernel. (Consulte el siguiente párrafo para una excepción a esta regla para Linux). Especificar una ruta relativa, por ejemplo, ./file, en lugar de la ruta absoluta del archivo, por ejemplo, /tmp/file, no funcionará porque lsof debe hacer coincidir los caracteres que especifique con lo que encuentra en las estructuras de sockets de dominio UNIX del kernel.
Si name es un nombre de socket de dominio UNIX de Linux, en un caso lsof puede buscarlo por su dispositivo y número de inodo, lo que permite que name sea una ruta relativa. El caso requiere que la ruta absoluta, es decir, una que comience con una barra ('/'), sea utilizada por el proceso que creó el socket y, por lo tanto, se almacene en el archivo /proc/net/unix; y requiere que lsof pueda obtener los números de dispositivo e inodo tanto de la ruta absoluta en /proc/net/unix como de name a través de llamadas al sistema stat(2) exitosas. Cuando se cumplen esas condiciones, lsof podrá buscar el socket de dominio UNIX cuando alguna ruta a él se especifique en name. Por lo tanto, por ejemplo, si la ruta es /dev/log y se inicia una búsqueda de lsof cuando el directorio de trabajo es /dev, entonces name podría ser ./log.
Si name no es ninguno de los anteriores, lsof listará todos los archivos abiertos cuyos dispositivo e inodo coincidan con los de la ruta especificada name.
Si también ha especificado la opción -b, los únicos names que puede especificar de forma segura son los sistemas de archivos para los que su tabla de montaje proporciona números de dispositivo alternativos. Consulte las secciones EVITAR BLOQUEOS DEL KERNEL y NÚMEROS DE DISPOSITIVO ALTERNATIVOS para obtener más información.
Múltiples nombres de archivo se unen en un único conjunto OR antes de participar en la selección de opciones AND.

AFS

Lsof admite el reconocimiento de archivos AFS para estos dialectos (y versiones de AFS):

AIX 4.1.4 (AFS 3.4a)
HP-UX 9.0.5 (AFS 3.4a)
Linux 1.2.13 (AFS 3.3)
Solaris 2.[56] (AFS 3.4a)

Puede reconocer archivos AFS en otras versiones de estos dialectos, pero no se ha probado allí. Dependiendo de cómo se implemente AFS, lsof puede reconocer archivos AFS en otros dialectos o puede tener dificultades para reconocer archivos AFS en los dialectos compatibles.

Lsof puede tener problemas para identificar todos los aspectos de los archivos AFS en los dialectos compatibles cuando el soporte del kernel de AFS se implementa a través de módulos dinámicos cuyas direcciones no aparecen en la lista de nombres de variables del kernel. En ese caso, lsof puede tener que adivinar la identidad de los archivos AFS y es posible que no pueda obtener información de volumen del kernel necesaria para calcular los números de nodo de volumen AFS. Cuando lsof no puede calcular los números de nodo de volumen, informa en blanco en la columna NODE.

La opción -A A está disponible en algunas implementaciones de dialectos de lsof para especificar el archivo de lista de nombres donde se pueden encontrar las direcciones del kernel de módulos dinámicos. Cuando esta opción esté disponible, se listará en la salida de ayuda de lsof, presentada en respuesta a las opciones -h o -?

Consulte las preguntas frecuentes de lsof (la sección FAQ indica su ubicación) para obtener más información sobre módulos dinámicos, sus símbolos y cómo afectan a las opciones de lsof.

Dado que las búsquedas de rutas AFS no parecen participar en las operaciones de caché de nombres del kernel, lsof no puede identificar los componentes del nombre de ruta para los archivos AFS.

SEGURIDAD

Lsof tiene tres características que pueden causar preocupaciones de seguridad. Primero, su modo de compilación predeterminado permite que cualquier persona liste todos los archivos abiertos con él. Segundo, por defecto crea un archivo de caché de dispositivos legible y escribible por el usuario en el directorio principal del ID de usuario real que ejecuta lsof. (El listado de todos los archivos abiertos y las características de caché de dispositivos se pueden deshabilitar cuando se compila lsof). Tercero, sus opciones -k y -m nombran archivos alternativos de lista de nombres del kernel o archivos de memoria.

La restricción del listado de todos los archivos abiertos se controla mediante las opciones de tiempo de compilación HASSECURITY y HASNOSOCKSECURITY. Cuando HASSECURITY está definido, lsof solo permitirá que el usuario root liste todos los archivos abiertos. El usuario no root solo puede listar los archivos abiertos de procesos con el mismo número de identificación de usuario que el número de ID de usuario real del proceso lsof (el con el que se inició sesión su usuario).

Sin embargo, si tanto HASSECURITY como HASNOSOCKSECURITY están definidos, cualquier persona puede listar los archivos de socket abiertos, siempre que se seleccionen con la opción -i.

Cuando HASSECURITY no está definido, cualquier persona puede listar todos los archivos abiertos.

La salida de ayuda, presentada en respuesta a la opción -h o -?, indica el estado de las definiciones de HASSECURITY y HASNOSOCKSECURITY.

Consulte la sección Security del archivo 00README de la distribución lsof para obtener información sobre la compilación de lsof con las opciones HASSECURITY y HASNOSOCKSECURITY habilitadas.

La creación y el uso de un archivo de caché de dispositivos legible y escribible por el usuario se controlan mediante la opción de tiempo de compilación HASDCACHE. Consulte la sección ARCHIVO DE CACHÉ DE DISPOSITIVOS y las secciones posteriores para obtener detalles sobre cómo se forma su ruta. Por consideraciones de seguridad, es importante tener en cuenta que en la distribución lsof predeterminada, si el ID de usuario real bajo el cual se ejecuta lsof es root, el archivo de caché de dispositivos se escribirá en el directorio principal de root, por ejemplo, / o /root. Cuando HASDCACHE no está definido, lsof no escribe ni intenta leer un archivo de caché de dispositivos.

Cuando HASDCACHE está definido, la salida de ayuda de lsof, presentada en respuesta a las opciones -h, -D? o -?, proporcionará información sobre el manejo del archivo de caché de dispositivos. Cuando HASDCACHE no está definido, la salida de -h o -? no tendrá una descripción de la opción -D.

Antes de decidir deshabilitar la característica del archivo de caché de dispositivos, habilitarla mejora el rendimiento de lsof al reducir la sobrecarga de inicio del examen de todos los nodos en /dev (o /devices), lea la discusión sobre ello en el archivo 00DCACHE de la distribución lsof y en las preguntas frecuentes de lsof (la sección FAQ indica su ubicación).

CUANDO TENGA DUDAS, PUEDE DESHABILITAR TEMPORALMENTE EL USO DEL ARCHIVO DE CACHÉ DE DISPOSITIVOS CON LA OPCIÓN -Di.

Cuando el usuario de lsof declara archivos alternativos de lista de nombres del kernel o archivos de memoria con las opciones -k y -m, lsof verifica la autoridad del usuario para leerlos con access(2). Esto tiene la intención de evitar que cualquier poder especial que los modos de lsof puedan conferirle le permita leer archivos que normalmente no son accesibles a través de la autoridad del ID de usuario real.

SALIDA

Esta sección describe la información que lsof lista para cada archivo abierto. Consulte la sección SALIDA PARA OTROS PROGRAMAS para obtener información adicional sobre la salida que puede ser procesada por otro programa.

Lsof solo produce caracteres de 8 bits imprimibles (declarados como tales por isprint(3)). Los caracteres no imprimibles se imprimen en una de las tres formas: la forma C ``\[bfrnt]'' ; la forma de carácter de control `^' (por ejemplo, ``^@''); o la forma hexadecimal de prefijo ``\x'' (por ejemplo, ``\xab''). El espacio es no imprimible en la columna COMMAND (``\x20'') e imprimible en otros lugares.

Para algunos dialectos, si HASSETLOCALE está definido en el archivo de encabezado machine.h del dialecto, lsof imprimirá los caracteres extendidos de 8 bits de una configuración regional de idioma. Al proceso lsof se le debe proporcionar una variable de entorno de configuración regional de idioma (por ejemplo, LANG) cuyo valor represente una configuración regional de idioma conocida en la que los caracteres extendidos se consideran imprimibles por isprint(3). De lo contrario, lsof considera que los caracteres extendidos no son imprimibles y los imprime de acuerdo con sus reglas para caracteres no imprimibles, indicadas anteriormente. Consulte la página man setlocale(3) de su dialecto para conocer los nombres de otras variables de entorno que se pueden usar en lugar de LANG, por ejemplo, LC_ALL, LC_CTYPE, etc.

El soporte de configuración regional de idioma de lsof para un dialecto también cubre caracteres anchos, por ejemplo, UTF-8, cuando HASSETLOCALE y HASWIDECHAR están definidos en el archivo de encabezado machine.h del dialecto, y cuando se ha definido una configuración regional de idioma adecuada en la variable de entorno apropiada para el proceso lsof. Los caracteres anchos son imprimibles bajo esas condiciones si iswprint(3) los informa como tales. Si no están definidos HASSETLOCALE, HASWIDECHAR y una configuración regional de idioma adecuada, o si iswprint(3) informa caracteres anchos que no son imprimibles, lsof considera que los caracteres anchos no son imprimibles e imprime cada uno de sus 8 bits de acuerdo con sus reglas para caracteres no imprimibles, indicadas anteriormente.

Consulte las respuestas a las preguntas sobre "Soporte de configuración regional de idioma" en las preguntas frecuentes de lsof (la sección FAQ indica su ubicación) para obtener más información.

Lsof dimensiona dinámicamente las columnas de salida cada vez que se ejecuta, garantizando que cada columna tenga un tamaño mínimo. También garantiza que cada columna esté separada de su predecesora por al menos un espacio.

COMMAND
contiene los primeros nueve caracteres del nombre del comando UNIX asociado con el proceso. Si se especifica un valor w distinto de cero para la opción +c w, la columna contiene los primeros w caracteres del nombre del comando UNIX asociado con el proceso hasta el límite de caracteres proporcionados a lsof por el dialecto UNIX. (Consulte la descripción del comando +c w o las preguntas frecuentes de lsof para obtener más información. La sección FAQ indica su ubicación).
Si w es menor que la longitud del título de la columna, ``COMMAND'', se aumentará a esa longitud.
Si se especifica un valor cero w para la opción +c w, la columna contendrá todos los caracteres del nombre del comando UNIX asociado al proceso.
Todos los caracteres del nombre del comando mantenidos por el kernel en sus estructuras se muestran en la salida de campo cuando se especifica el descriptor del nombre del comando (`c'). Consulte la sección SALIDA PARA OTROS COMANDOS para obtener información sobre la selección de la salida de campo y el descriptor del nombre del comando asociado.
PID
es el número de Identificación de Proceso (PID) del proceso.
TID
es el número de Identificación de Tarea (hilo), si el informe de tareas (hilos) es soportado por el dialecto y se está listando una tarea (hilo). (Si la ayuda de salida - es decir, la salida de las opciones -h o -? - muestra esta opción, entonces el informe de tareas (hilos) es soportado por el dialecto.)
Una columna TID en blanco en Linux indica un proceso, es decir, no una tarea.
TASKCMD
es el nombre del comando de la tarea. Generalmente será el mismo que el proceso nombrado en la columna COMMAND, pero algunas implementaciones de tareas (por ejemplo, Linux) permiten que una tarea cambie su nombre de comando.
El ancho de la columna TASKCMD está sujeto a la misma limitación de tamaño que la columna COMMAND.
ZONE
es el nombre de la zona de Solaris 10 y superior. Esta columna debe seleccionarse con la opción -z.
SECURITY-CONTEXT
es el contexto de seguridad SELinux. Esta columna debe seleccionarse con la opción -Z. Tenga en cuenta que la opción -Z está inhibida cuando SELinux está deshabilitado en el kernel de Linux en ejecución.
PPID
es el número de Identificación de Proceso Padre (PPID) del proceso. Solo se muestra cuando se ha especificado la opción -R.
PGID
es el número de Identificación de grupo de procesos (PGID) asociado al proceso. Solo se muestra cuando se ha especificado la opción -g.
USER
es el número de ID de usuario o nombre de inicio de sesión del usuario al que pertenece el proceso, generalmente el mismo que el informado por ps(1). Sin embargo, en Linux USER es el número de ID de usuario o nombre de inicio de sesión que posee el directorio en /proc donde lsof encuentra información sobre el proceso. Por lo general, es el mismo valor informado por ps(1), pero puede diferir cuando el proceso ha cambiado su ID de usuario efectivo. (Consulte la descripción de la opción -l para obtener información sobre cuándo se muestra un número de ID de usuario o nombre de inicio de sesión.)
FD
es el número de Descriptor de Archivo (FD) del archivo o:
	cwd	directorio de trabajo actual;

TAMAÑO, TAMAÑO/DESPLAZAMIENTO, o DESPLAZAMIENTO
es el tamaño del archivo o el desplazamiento del archivo en bytes. Se muestra un valor en esta columna solo si está disponible. Lsof muestra el valor que sea (tamaño o desplazamiento) apropiado para el tipo de archivo y la versión de lsof.
en algunos dialectos de UNIX, lsof no puede obtener información precisa o consistente del desplazamiento del archivo de sus fuentes de datos del kernel, a veces solo para tipos particulares de archivos (por ejemplo, archivos de socket). En otros casos, los archivos no tienen tamaños reales (por ejemplo, sockets, FIFOs, tuberías), por lo que lsof muestra para sus tamaños las cantidades de contenido que encuentra en sus descriptores de búfer del kernel (por ejemplo, recuentos de tamaño de búfer de socket o tamaños de ventana TCP/IP). Consulte el FAQ de lsof (la sección FAQ indica su ubicación) para más información.
el tamaño del archivo se muestra en decimal; el desplazamiento se muestra normalmente en decimal con un prefijo ``0t'' si contiene 8 dígitos o menos; en hexadecimal con un prefijo ``0x'' si tiene más de 8 dígitos. (Consulte la descripción de la opción -o o para obtener información sobre cuándo 8 podría ser reemplazado por algún otro valor.)
por lo tanto, el prefijo ``0t'' y ``0x'' identifican un desplazamiento cuando la columna puede contener tanto un tamaño como un desplazamiento (es decir, su título es TAMAÑO/DESPLAZAMIENTO).
Si se especifica la opción -o, lsof muestra siempre el desplazamiento del archivo (o nada si no hay desplazamiento disponible) y etiqueta la columna DESPLAZAMIENTO. El desplazamiento siempre comienza con ``0t'' o ``0x'' como se describe arriba.
el usuario de lsof puede controlar el cambio de ``0t'' a ``0x'' con la opción -o o. Consulte su descripción para obtener más información.
Si se especifica la opción -s, lsof muestra siempre el tamaño del archivo (o nada si no hay tamaño disponible) y etiqueta la columna TAMAÑO. Las opciones -o y -s son mutuamente excluyentes; no se pueden especificar ambas.
Si se especifica la opción -H, lsof muestra el tamaño del archivo en formato legible por humanos.
para archivos que no tienen un tamaño fijo (por ejemplo, que no residen en un dispositivo de disco), lsof mostrará información apropiada sobre el tamaño o posición actual del archivo si está disponible en las estructuras del kernel que definen el archivo.

EVITAR BLOQUEOS DEL KERNEL

Puede usar la opción -b para indicar a lsof que evite utilizar funciones del kernel que se bloquearían. Se aplican algunas advertencias.

Primero, usar esta opción generalmente requiere que su sistema proporcione números de dispositivo alternativos en lugar de los números de dispositivo que lsof obtendría normalmente con las funciones del kernel lstat(2) y stat(2). Consulte la sección NÚMEROS DE DISPOSITIVO ALTERNATIVOS para obtener más información sobre los números de dispositivo alternativos.

Segundo, no puede especificar nombres para que lsof los localice a menos que sean nombres de sistemas de archivos. Esto se debe a que lsof necesita conocer los números de dispositivo e inode de los archivos listados con nombres en las opciones de lsof, y la opción -b impide que lsof los obtenga. Además, dado que lsof solo tiene números de dispositivo para los sistemas de archivos que tienen alternativas, su capacidad para localizar archivos en los sistemas de archivos depende completamente de la disponibilidad y precisión de las alternativas. Si no hay alternativas disponibles, o si son incorrectas, lsof no podrá localizar archivos en los sistemas de archivos nombrados.

Tercero, si los nombres de los directorios de sus sistemas de archivos que lsof obtiene de la tabla de montaje de su sistema son enlaces simbólicos, lsof no podrá resolver los enlaces. Esto se debe a que la opción -b hace que lsof evite la función del kernel readlink(2) que utiliza para resolver enlaces simbólicos.

Finalmente, el uso de la opción -b hace que lsof emita mensajes de advertencia cuando necesita usar las funciones del kernel que la opción -b le indica que evite. Puede suprimir estos mensajes especificando la opción -w, pero si lo hace, no verá los números de dispositivo alternativos reportados en los mensajes de advertencia.

NÚMEROS DE DISPOSITIVO ALTERNATIVOS

En algunos dialectos, cuando lsof tiene que romper un bloqueo porque no puede obtener información sobre un sistema de archivos montado a través de las funciones del kernel lstat(2) y stat(2), o porque especificó la opción -b, lsof puede obtener parte de la información que necesita - el número de dispositivo y posiblemente el tipo de sistema de archivos - de la tabla de montaje del sistema. Cuando eso es posible, lsof informará el número de dispositivo que obtuvo. (Puede suprimir el informe especificando la opción -w.)

Puede ayudar a este proceso si su tabla de montaje se apoya en un archivo /etc/mtab o /etc/mnttab que contiene un campo de opciones agregando un campo ``dev=xxxx'' para los puntos de montaje que no tienen uno en sus cadenas de opciones. Nota: debe poder editar el archivo; es decir, algunas tablas de montaje como el reciente /etc/mnttab de Solaris o el /proc/mounts de Linux son de solo lectura y no se pueden modificar.

También puede ser capaz de proporcionar números de dispositivo utilizando las opciones +m y +m m, siempre que sean compatibles con su dialecto. Consulte la salida de las opciones -h o -? de lsof para ver si las opciones +m y +m m están disponibles.

La porción ``xxxx'' del campo es el valor hexadecimal del número de dispositivo del sistema de archivos. (Consulte el campo st_dev de la salida de las funciones lstat(2) y stat(2) para los valores apropiados para sus sistemas de archivos.) Aquí hay un ejemplo de un /etc/mnttab de Sun Solaris 2.6 para un sistema de archivos montado remotamente a través de NFS:

nfs  ignore,noquota,dev=2a40001

Existe una ventaja en tener entradas ``dev=xxxx'' en su archivo de tabla de montaje, especialmente para sistemas de archivos que se montan desde servidores NFS remotos. Cuando un servidor remoto falla y desea identificar a sus usuarios ejecutando lsof en uno de sus clientes, lsof probablemente no podrá obtener información de las funciones lstat(2) y stat(2) para el sistema de archivos. Si puede obtener el número de dispositivo del sistema de archivos de la tabla de montaje, podrá mostrar los archivos abiertos en el servidor NFS fallido.

Algunos dialectos que no utilizan un archivo ASCII /etc/mtab o /etc/mnttab para la tabla de montaje aún pueden proporcionar un número de dispositivo alternativo en sus tablas de montaje internas. Esto incluye AIX, Apple Darwin, FreeBSD, NetBSD, OpenBSD y Tru64 UNIX. Lsof sabe cómo obtener el número de dispositivo alternativo para estos dialectos y lo utiliza cuando su intento de lstat(2) o stat(2) el sistema de archivos está bloqueado.

Si no está seguro de si su dialecto proporciona números de dispositivo alternativos para los sistemas de archivos de su tabla de montaje, utilice esta invocación de lsof para ver si informa de algún número de dispositivo alternativo:

lsof -b

Busque mensajes de advertencia del archivo de error estándar que comienzan con ``asumiendo "dev=xxxx" desde ...''.

CACHÉ DE NOMBRES DEL KERNEL

Lsof puede examinar la caché de nombres del kernel o utilizar otras instalaciones del kernel (por ejemplo, la función tag_to_path() de ADVFS 4.x en Tru64 UNIX) en algunos dialectos para la mayoría de los tipos de sistemas de archivos, excluyendo AFS, y extraer de ella componentes de nombres de ruta usados recientemente. (Las búsquedas de rutas de sistemas de archivos AFS no utilizan la caché de nombres del kernel; algunas operaciones de sistemas de archivos VxFS de Solaris aparentemente tampoco la utilizan.)

Lsof informa las rutas completas que encuentra en la columna NAME. Si lsof no puede informar de todos los componentes de una ruta, informa en la columna NAME el nombre del sistema de archivos, seguido de un espacio, dos caracteres `-', otro espacio y los componentes del nombre que ha localizado, separados por el carácter `/'.

Cuando lsof se ejecuta en modo repetido, es decir, con la opción -r especificada, la medida en que puede informar de los componentes del nombre de la ruta para el mismo archivo puede variar de un ciclo a otro. Esto se debe a que otros procesos en ejecución pueden hacer que el kernel elimine entradas de su caché de nombres y las reemplace por otras.

El uso de la caché de nombres del kernel por parte de lsof para identificar las rutas de los archivos puede llevarlo a informar componentes incorrectos en algunas circunstancias. Esto puede ocurrir cuando la caché de nombres del kernel utiliza el dispositivo y el número de nodo como clave (por ejemplo, SCO OpenServer) y se reutiliza una clave en un sistema de archivos que cambia rápidamente. Si el kernel del dialecto UNIX no purga la entrada de la caché de nombres de un archivo cuando se elimina, lsof puede encontrar una referencia a la entrada incorrecta en la caché. En consecuencia, lsof normalmente mantiene un archivo de texto ASCII de información cacheada de /dev (o /devices) (excepción: el lsof de Linux basado en /proc, donde no es necesario). El administrador del sistema local que compila lsof puede controlar la forma en que se forma la ruta del archivo de caché de dispositivos, eligiendo entre estas opciones:

Ruta de la opción -D;
Ruta de una variable de entorno;
Ruta a nivel de sistema;
Ruta personal (la predeterminada);
Ruta personal, modificada por una variable de entorno.

Consulte la salida de las opciones de ayuda -h, -D? o -? para conocer el estado actual del soporte de caché de dispositivos. La salida de ayuda enumera la ruta del archivo de caché de dispositivos en modo de lectura predeterminado que está en vigor para la invocación actual de lsof. La salida de la opción -D? enumera las rutas del archivo de caché de dispositivos de solo lectura y de escritura, los nombres de las variables de entorno aplicables y el formato de la ruta personal del archivo de caché de dispositivos.

Lsof puede detectar que el archivo de caché de dispositivos actual ha sido modificado accidental o maliciosamente mediante comprobaciones de integridad, incluyendo el cálculo y la verificación de una suma de verificación de redundancia cíclica (CRC) de dieciséis bits sobre el contenido del archivo. Cuando lsof detecta algo incorrecto en el archivo, emite una advertencia e intenta eliminar el archivo de caché actual y crear una nueva copia, pero solo en una ruta en la que el proceso pueda escribir legítimamente.

La ruta desde la cual un proceso lsof puede intentar leer un archivo de caché de dispositivos puede no ser la misma que la ruta a la que puede escribir legítimamente. Por lo tanto, cuando lsof detecta que necesita actualizar el archivo de caché de dispositivos, puede elegir una ruta diferente para escribirlo de la ruta desde la cual leyó una versión incorrecta o desactualizada.

Si está disponible, la opción -Dr inhibirá la escritura de un nuevo archivo de caché de dispositivos. (Siempre está disponible cuando se especifica sin argumento de nombre de ruta.)

PERMISOS DE LSOF QUE AFECTAN EL ACCESO AL ARCHIVO DE CACHÉ DE DISPOSITIVOS

Cuando se agrega un nuevo dispositivo al sistema, es posible que el archivo de caché de dispositivos deba ser recreado. Dado que lsof compara la mtime del archivo de caché de dispositivos con la mtime y ctime del directorio /dev (o /devices), generalmente detecta que se ha agregado un nuevo dispositivo; en ese caso, lsof emite un mensaje de advertencia e intenta reconstruir el archivo de caché de dispositivos.

Siempre que lsof escribe un archivo de caché de dispositivos, establece su propiedad al UID real del proceso en ejecución y sus modos de permiso a 0600, lo que restringe su lectura y escritura al propietario del archivo.

PERMISOS DE LSOF QUE AFECTAN EL ACCESO AL ARCHIVO DE CACHÉ DE DISPOSITIVOS

Dos permisos del ejecutable lsof afectan su capacidad para acceder a los archivos de caché de dispositivos. Los permisos son establecidos por el administrador del sistema local cuando se instala lsof.

El primer y más raro permiso es setuid-root. Entra en vigor cuando se ejecuta lsof; su UID efectivo es entonces root, mientras que su UID real (es decir, el del usuario conectado) no lo es. La distribución de lsof recomienda que las versiones para estos dialectos se ejecuten con setuid-root.

HP-UX 11.11 y 11.23
Linux

El segundo y más común permiso es setgid. Entra en vigor cuando el número de identificación de grupo efectivo (GID) del proceso lsof se establece en uno que puede acceder a los dispositivos de memoria del kernel, por ejemplo, ``kmem'', ``sys'' o ``system''.

Un proceso lsof que tiene permiso setgid generalmente renuncia al permiso después de haber accedido a los dispositivos de memoria del kernel. Cuando lo hace, lsof puede permitir formaciones de ruta de caché de dispositivos más liberales. La distribución de lsof recomienda que las versiones para estos dialectos se ejecuten con setgid y se les permita renunciar al permiso setgid.

RUTA DEL ARCHIVO DE CACHÉ DE DISPOSITIVOS DESDE LA OPCIÓN -D

La opción -D proporciona medios limitados para especificar la ruta del archivo de caché de dispositivos. Su función ? informará las rutas de archivo de caché de dispositivos de solo lectura y de escritura que lsof utilizará.

Cuando las funciones b, r y u de -D están disponibles, puede usarlas para solicitar que el archivo de caché se construya en una ubicación específica (b[ruta]); leerlo pero no reconstruirlo (r[ruta]); o leerlo y reconstruirlo (u[ruta]). Las funciones b, r y u están restringidas bajo algunas condiciones. Están restringidas cuando el proceso lsof es setuid-root. La ruta especificada con la función r es siempre de solo lectura, incluso cuando está disponible.

Las funciones b, r y u también están restringidas cuando el proceso lsof se ejecuta con setgid y lsof no renuncia al permiso setgid. (Consulte la sección PERMISOS DE LSOF QUE AFECTAN EL ACCESO AL ARCHIVO DE CACHÉ DE DISPOSITIVOS para obtener una lista de implementaciones que normalmente no renuncian a su permiso setgid).

Una función adicional de -D, i (de ignorar), siempre está disponible.

Cuando está disponible, la función b le indica a lsof que lea la información del dispositivo del kernel con la función stat(2) y construya un archivo de caché de dispositivos en la ruta indicada.

Cuando está disponible, la función r le indica a lsof que lea el archivo de caché de dispositivos, pero que no lo actualice. Cuando un argumento de ruta acompaña a -Dr, nombra la ruta del archivo de caché de dispositivos. La función r siempre está disponible cuando se especifica sin un nombre de ruta. Si lsof no se ejecuta como setuid-root y renuncia a su permiso setgid, un nombre de ruta puede acompañar a la función r.

Cuando está disponible, la función u le indica a lsof que intente leer y usar el archivo de caché de dispositivos. Si no puede leer el archivo, o si encuentra que el contenido del archivo es incorrecto o está desactualizado, leerá la información del kernel e intentará escribir una versión actualizada del archivo de caché de dispositivos, pero solo en una ruta que considere legítima para los UID efectivos y reales del proceso lsof.

RUTA DEL ARCHIVO DE CACHÉ DE DISPOSITIVOS DESDE UNA VARIABLE DE ENTORNO

La segunda opción de lsof para el archivo de caché de dispositivos es el contenido de la variable de entorno LSOFDEVCACHE. Evita esta opción si el proceso lsof es setuid-root, o si el UID real del proceso es root.

Se aplica una restricción adicional a una ruta de archivo de caché de dispositivos tomada de la variable de entorno LSOFDEVCACHE: lsof no escribirá un archivo de caché de dispositivos en la ruta si el proceso lsof no renuncia a su permiso setgid. (Consulte la sección PERMISOS DE LSOF QUE AFECTAN EL ACCESO AL ARCHIVO DE CACHÉ DE DISPOSITIVOS para obtener información sobre implementaciones que no renuncian a su permiso setgid).

El administrador del sistema local puede deshabilitar el uso de la variable de entorno LSOFDEVCACHE o cambiar su nombre al compilar lsof. Consulte la salida de -D? para conocer el nombre de la variable de entorno.

RUTA DEL ARCHIVO DE CACHÉ DE DISPOSITIVOS EN TODO EL SISTEMA

El administrador del sistema local puede optar por tener un archivo de caché de dispositivos en todo el sistema al compilar lsof. Ese archivo generalmente será construido por un procedimiento especial de administración del sistema cuando el sistema se inicia o cuando cambia el contenido de /dev o /devices). Si se define, es la tercera opción de ruta de archivo de caché de dispositivos de lsof.

Puede saber que un archivo de caché de dispositivos en todo el sistema está en vigor para su instalación local examinando la salida de la opción de ayuda de lsof, es decir, la salida de la opción -h o -?.

Lsof nunca escribirá en la ruta del archivo de caché de dispositivos en todo el sistema por defecto. Debe ser nombrado explícitamente con una función -D en un procedimiento propiedad de root. Una vez que el archivo ha sido escrito, el procedimiento debe cambiar sus modos de permiso a 0644 (lectura y escritura del propietario, lectura del grupo y lectura de otros).

RUTA PERSONAL DEL ARCHIVO DE CACHÉ DE DISPOSITIVOS (POR DEFECTO)

La ruta predeterminada del archivo de caché de dispositivos de la distribución lsof se registra en el directorio principal del UID real que ejecuta lsof. Al directorio principal se le agrega un segundo componente de ruta de la forma .lsof_nombrehost.

Esta es la cuarta opción de ruta de archivo de caché de dispositivos de lsof, y suele ser la predeterminada. Si se definió una ruta de archivo de caché de dispositivos en todo el sistema cuando se compiló lsof, esta cuarta opción se aplicará cuando lsof no pueda encontrar el archivo de caché de dispositivos en todo el sistema. Esta es la única vez que lsof utiliza dos rutas al leer el archivo de caché de dispositivos.

La parte nombrehost del segundo componente es el nombre base del host en ejecución, tal como lo devuelve gethostname(2). El nombre base se define como los caracteres que preceden al primer `.' en la salida de gethostname(2), o toda la salida de gethostname(2) si no contiene ningún `.'.

El archivo de caché de dispositivos pertenece al ID de usuario y es legible y escribible solo por el ID de usuario, es decir, sus modos son 0600. Cada ID de usuario real distinto en un host dado que ejecuta lsof tiene un archivo de caché de dispositivos distinto. La parte nombrehost de la ruta distingue los archivos de caché de dispositivos en un directorio principal montado por NFS en el que se escriben archivos de caché de dispositivos de varios hosts diferentes.

La ruta personal del archivo de caché de dispositivos formada por este método representa un archivo de caché de dispositivos que lsof intentará leer y que intentará escribir si no existe o si su contenido es incorrecto o está desactualizado.

La opción -Dr sin un argumento de nombre de ruta inhibirá la escritura de un nuevo archivo de caché de dispositivos.

La opción -D? enumerará la especificación de formato para construir el archivo de caché de dispositivos personal. Las conversiones utilizadas en la especificación de formato se describen en el archivo 00DCACHE de la distribución lsof.

RUTA PERSONAL MODIFICADA DEL ARCHIVO DE CACHÉ DE DISPOSITIVOS

Si esta opción es definida por el administrador del sistema local al compilar lsof, el contenido de la variable de entorno LSOFPERSDCPATH puede usarse para agregar un componente a la ruta del archivo de caché de dispositivos personal.

El contenido de la variable LSOFPERSDCPATH se inserta en la ruta en el lugar marcado por el administrador del sistema local con la conversión ``%p'' en la especificación de formato HASPERSDC del archivo de encabezado machine.h del dialecto. (Se coloca justo después del directorio principal en la distribución lsof predeterminada).

Por lo tanto, por ejemplo, si LSOFPERSDCPATH contiene ``LSOF'', el directorio principal es ``/Homes/abe'', el nombre del host es ``lsof.itap.purdue.edu'', y el formato HASPERSDC es el predeterminado (``%h/%p.lsof_%L''), la ruta personal modificada del archivo de caché de dispositivos es:

/Homes/abe/LSOF/.lsof_vic

La variable de entorno LSOFPERSDCPATH se ignora cuando el proceso lsof es setuid-root o cuando el UID real del proceso es root.

Lsof no escribirá en una ruta de archivo de caché de dispositivos personal modificada si el proceso lsof no renuncia al permiso setgid. (Consulte la sección PERMISOS DE LSOF QUE AFECTAN EL ACCESO AL ARCHIVO DE CACHÉ DE DISPOSITIVOS para obtener una lista de implementaciones que normalmente no renuncian a su permiso setgid).

Si, por ejemplo, desea crear un subdirectorio de rutas de archivos de caché de dispositivos personales utilizando la variable de entorno LSOFPERSDCPATH para nombrarlo, y lsof no renuncia a su permiso setgid, deberá permitir que lsof cree archivos de caché de dispositivos en la ruta personal estándar y moverlos a su subdi

DIAGNÓSTICOS

Los errores se identifican con mensajes en el archivo de error estándar.

lsof devuelve un uno (1) si se detectó algún error, incluida la falla al localizar nombres de comandos, nombres de archivos, direcciones o archivos de Internet, nombres de inicio de sesión, archivos NFS, PID, PGID o UID que se le solicitó listar. Si se especifica la opción -V, lsof indicará los elementos de búsqueda que no pudo listar. Si se especifica la opción -Q, lsof ignorará las fallas de los elementos de búsqueda y solo devolverá un error si ocurrió algo inusual e irrecuperable.

Devuelve un cero (0) si no se detectaron errores y si se especificó la opción -Q o si pudo listar alguna información sobre todos los argumentos de búsqueda especificados.

Cuando lsof no puede abrir el acceso a /dev (o /devices) o a uno de sus subdirectorios, o no puede obtener información sobre un archivo en ellos con stat(2), emite un mensaje de advertencia y continúa. Que lsof emitirá mensajes de advertencia sobre archivos inaccesibles en /dev (o /devices) se indica en su salida de ayuda - solicitada con las opciones -h o >B -? - con el mensaje:

Las advertencias de /dev inaccesible están habilitadas.

El mensaje de advertencia puede suprimirse con la opción -w. También puede haber sido suprimido por el administrador del sistema cuando se compiló lsof al establecer la definición WARNDEVACCESS. En este caso, la salida de las opciones de ayuda incluirá el mensaje:

Las advertencias de /dev inaccesible están deshabilitadas.

Los mensajes de advertencia de dispositivo inaccesible generalmente desaparecen después de que lsof ha creado un archivo de caché de dispositivos funcional.

EJEMPLOS

Para un conjunto más extenso de ejemplos, documentados con mayor detalle, consulte el archivo 00QUICKSTART de la distribución lsof.

Para listar todos los archivos abiertos, use:

lsof

Para listar todos los archivos de Internet, x.25 (HP-UX) y de dominio UNIX abiertos, use:

lsof -i -U

Para listar todos los archivos de red IPv4 abiertos en uso por el proceso cuyo PID es 1234, use:

lsof -i 4 -a -p 1234

Si no importa que el PID 1234 no exista, o que el PID 1234 no tenga ningún archivo de red IPv4 abierto, agregue -Q:

lsof -Q -i 4 -a -p 1234

Suponiendo que el dialecto UNIX soporta IPv6, para listar solo los archivos de red IPv6 abiertos, use:

lsof -i 6

Para listar todos los archivos que usan cualquier protocolo en los puertos 513, 514 o 515 del host wonderland.cc.purdue.edu, use:

lsof -i @wonderland.cc.purdue.edu:513-515

Para listar todos los archivos que usan cualquier protocolo en cualquier puerto de mace.cc.purdue.edu (cc.purdue.edu es el dominio predeterminado), use:

lsof -i @mace

Para listar todos los archivos abiertos para el nombre de inicio de sesión ``abe'', o el ID de usuario 1234, o el proceso 456, o el proceso 123, o el proceso 789, use:

lsof -p 456,123,789 -u 1234,abe

Para listar todos los archivos abiertos en el dispositivo /dev/hd4, use:

lsof /dev/hd4

Para encontrar el proceso que tiene /u/abe/foo abierto sin preocuparse si no hay ninguno, use:

lsof -Q /u/abe/foo

Para tomar acción solo si un proceso tiene /u/abe/foo abierto, use:

lsof /u/abe/foo echo "todavía en uso"

Para enviar un SIGHUP a los procesos que tienen /u/abe/bar abierto, use:

kill -HUP `lsof -t /u/abe/bar`

Para encontrar cualquier archivo abierto, incluido un archivo de socket de dominio UNIX abierto, con el nombre /dev/log, use:

lsof /dev/log

Para encontrar procesos con archivos abiertos en el sistema de archivos NFS llamado /nfs/mount/point cuyo servidor es inaccesible, y suponiendo que su tabla de montaje proporciona el número de dispositivo para /nfs/mount/point, use:

lsof -b /nfs/mount/point

Para realizar la búsqueda anterior suprimiendo los mensajes de advertencia, use:

lsof -bw /nfs/mount/point

Para ignorar el archivo de caché de dispositivos, use:

lsof -Di

Para obtener la salida de los campos PID y nombre de comando para cada proceso, descriptor de archivo, número de dispositivo de archivo y número de inodo de archivo para cada archivo de cada proceso, use:

lsof -FpcfDi

Para listar los archivos en los descriptores 1 y 3 de cada proceso que ejecuta el comando lsof para el ID de inicio de sesión ``abe'' cada 10 segundos, use:

lsof -c lsof -a -d 1 -d 3 -u abe -r10

Para listar el directorio de trabajo actual de los procesos que ejecutan un comando que tiene exactamente cuatro caracteres de longitud y tiene una 'o' o 'O' en el tercer carácter, use esta forma de expresión regular de la opción -cc:

lsof -c /^..o.$/i -a -d cwd

Para encontrar un archivo de socket de la versión IP 4 por su dirección numérica en formato de puntos asociada, use:

lsof -i@128.210.15.17

Para encontrar un archivo de socket de la versión IP 6 (cuando el dialecto UNIX soporta IPv6) por su dirección numérica en formato de dos puntos asociada, use:

lsof -i@[0:1:2:3:4:5:6:7]

Para encontrar un archivo de socket de la versión IP 6 (cuando el dialecto UNIX soporta IPv6) por una dirección numérica en formato de dos puntos asociada que tiene una secuencia de ceros en ella - por ejemplo, la dirección de loopback - use:

lsof -i@[::1]

Para obtener una línea de marcador de modo de repetición que contenga la hora actual, use:

lsof -rm====%T====

Para agregar espacios a la línea de marcador anterior, use:

lsof -r "m==== %T ===="

ERRORES

Dado que lsof lee la memoria del kernel en su búsqueda de archivos abiertos, los cambios rápidos en la memoria del kernel pueden producir resultados impredecibles.

Cuando un archivo tiene múltiples bloqueos de registro, el carácter de estado del bloqueo (que sigue al descriptor de archivo) se deriva de una prueba de la primera estructura de bloqueo, no de una combinación de los bloqueos de registro individuales que podrían ser descritos por múltiples estructuras de bloqueo.

Lsof no puede buscar archivos con permisos de acceso restrictivos por nombre a menos que esté instalado con permisos root set-UID. De lo contrario, se limita a buscar archivos a los que su usuario o su grupo set-GID (si lo hay) tiene permiso de acceso.

La visualización de la dirección de destino de un socket en bruto (por ejemplo, para ping) depende del sistema operativo UNIX. Algunos dialectos almacenan la dirección de destino en el bloque de control de protocolo del socket en bruto, otros no.

Lsof no siempre puede representar los números de dispositivo de Solaris de la misma manera que lo hace ls(1). Por ejemplo, los números de dispositivo principales y secundarios que las funciones lstat(2) y stat(2) informan para el directorio en el que se montan los archivos CD-ROM (típicamente /cdrom) no son los mismos que los que informan para el dispositivo en el que se montan los archivos CD-ROM (típicamente /dev/sr0). (Lsof informa los números del directorio).

El soporte para sistemas de archivos /proc solo está disponible para dialectos BSD y Tru64 UNIX, Linux y dialectos derivados de SYSV R4 - por ejemplo, FreeBSD, NetBSD, OpenBSD, Solaris, UnixWare.

Algunos elementos de /proc - número de dispositivo, número de inodo y tamaño de archivo - no están disponibles en algunos dialectos. La búsqueda de archivos en un sistema de archivos /proc puede requerir que se especifique el nombre de ruta completo.

No se muestran descriptores de archivo de texto (txt) para procesos de Linux. Todas las entradas de archivos que no sean el directorio de trabajo actual, el directorio raíz y los descriptores de archivo numéricos se etiquetan como descriptores mem.

Lsof no puede buscar tuberías con nombre de Tru64 UNIX por nombre, porque su implementación del kernel de lstat(2) devuelve un número de dispositivo incorrecto para una tubería con nombre.

Lsof no puede informar completa o correctamente sobre los bloqueos de HP-UX 9.01, 10.20 y 11.00 debido a un acceso insuficiente a los datos del kernel o errores en los datos del kernel. Consulte el FAQ de lsof (la sección FAQ indica su ubicación) para obtener detalles.

El tipo de archivo SMT de AIX es una invención. Está hecho para estructuras de archivo cuyo tipo (15) no está definido en el archivo de encabezado de AIX /usr/include/sys/file.h. Una forma de crear dichas estructuras de archivo es ejecutar clientes X con la variable DISPLAY establecida en ``:0.0''.

La opción +|-f[cfn] no es compatible con lsof basado en /proc en Linux, ya que no lee las estructuras del kernel desde la memoria del kernel.
