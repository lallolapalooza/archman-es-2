lspci(8) Las Utilidades PCI lspci(8)

NOMBRE

lspci - lista todos los dispositivos PCI

SINOPSIS

lspci [opciones]

DESCRIPCIÓN

lspci es una utilidad para mostrar información sobre los buses PCI en el sistema y los dispositivos conectados a ellos.

Por defecto, muestra una lista breve de dispositivos. Usa las opciones descritas a continuación para solicitar una salida más detallada o una salida destinada a ser procesada por otros programas.

Si vas a reportar errores en los controladores de dispositivos PCI o en lspci mismo, por favor incluye la salida de "lspci -vvx" o, aún mejor, "lspci -vvxxx" (sin embargo, consulta abajo las posibles precauciones).

Algunas partes de la salida, especialmente en los modos de alta verbosidad, probablemente solo sean comprensibles para hackers experimentados de PCI. Para definiciones exactas de los campos, por favor consulta las especificaciones PCI o los archivos de inclusión header.h y /usr/include/linux/pci.h.

El acceso a algunas partes del espacio de configuración PCI está restringido a root en muchos sistemas operativos, por lo que las funciones de lspci disponibles para usuarios normales son limitadas. Sin embargo, lspci hace todo lo posible para mostrar tanta información como esté disponible y marca toda la información restante con el texto <acceso denegado>.

OPCIONES

Modos básicos de visualización

-m
Muestra los datos de los dispositivos PCI en un formato legible por máquina, compatible con versiones anteriores. Consulta abajo para más detalles.
-mm
Muestra los datos de los dispositivos PCI en un formato legible por máquina para facilitar el análisis por scripts. Consulta abajo para más detalles.
-t
Muestra un diagrama en forma de árbol que contiene todos los buses, puentes, dispositivos y las conexiones entre ellos.

Opciones de visualización

-v
Sé verboso y muestra información detallada sobre todos los dispositivos.
-vv
Sé muy verboso y muestra más detalles. Este nivel incluye todo lo que se considera útil.
-vvv
Sé aún más verboso y muestra todo lo que podemos analizar, incluso si no parece interesante en absoluto (por ejemplo, regiones de memoria no definidas).
-k
Muestra los controladores del kernel que manejan cada dispositivo y también los módulos del kernel capaces de manejarlo. Se activa por defecto cuando se proporciona -v en el modo de salida normal. (Actualmente solo funciona en Linux con kernel 2.6 o más reciente.)
-x
Muestra un volcado hexadecimal de la parte estándar del espacio de configuración (los primeros 64 bytes o 128 bytes para puentes CardBus).
-xxx
Muestra un volcado hexadecimal de todo el espacio de configuración PCI. Solo está disponible para root, ya que varios dispositivos PCI se **bloquean** cuando intentas leer algunas partes del espacio de configuración (este comportamiento probablemente no viola el estándar PCI, pero es al menos muy tonto). Sin embargo, tales dispositivos son raros, por lo que no deberías preocuparte mucho.
-xxxx
Muestra un volcado hexadecimal del espacio de configuración PCI extendido (de 4096 bytes) disponible en buses PCI-X 2.0 y PCI Express.
-b
Vista centrada en el bus. Muestra todos los números de IRQ y direcciones tal como los ven las tarjetas en el bus PCI en lugar de como los ve el kernel.
-D
Muestra siempre los números de dominio PCI. Por defecto, lspci los suprime en máquinas que solo tienen el dominio 0.
-P
Identifica los dispositivos PCI por su ruta a través de cada puente, en lugar de por su número de bus.
-PP
Identifica los dispositivos PCI por su ruta a través de cada puente, mostrando tanto el número de bus como el número de dispositivo.

Opciones para controlar la resolución de IDs a nombres

-n
Muestra los códigos de vendedor y dispositivo PCI como números en lugar de buscarlos en la lista de IDs PCI.
-nn
Muestra los códigos de vendedor y dispositivo PCI tanto como números como nombres.
-q
Utiliza DNS para consultar la base de datos central de IDs PCI si un dispositivo no se encuentra en el archivo local pci.ids. Si la consulta DNS tiene éxito, el resultado se almacena en caché en $XDG_CACHE_HOME/pci-ids y se reconoce en ejecuciones posteriores incluso si -q no se proporciona de nuevo. Utiliza este interruptor dentro de scripts automatizados solo con precaución para evitar sobrecargar los servidores de la base de datos.
-qq
Igual que -q, pero la caché local se restablece.
-Q
Consulta la base de datos central incluso para entradas que se reconocen localmente. Utiliza esto si sospechas que la entrada mostrada es incorrecta.

Opciones para la selección de dispositivos

-s [[[[<dominio>]:]<bus>]:][<dispositivo>][.[<func>]]
Muestra solo los dispositivos en el dominio especificado (en caso de que tu máquina tenga varios puentes de host, pueden compartir un espacio de números de bus común o cada uno de ellos puede direccionar un dominio PCI propio; los dominios se numeran de 0 a ffff), bus (0 a ff), dispositivo (0 a 1f) y función (0 a 7). Cada componente de la dirección del dispositivo puede omitirse o establecerse en "*", significando ambos "cualquier valor". Todos los números son hexadecimales. Por ejemplo, "0:" significa todos los dispositivos en el bus 0, "0" significa todas las funciones del dispositivo 0 en cualquier bus, "0.3" selecciona la tercera función del dispositivo 0 en todos los buses y ".4" muestra solo la cuarta función de cada dispositivo.
-d [<vendedor>]:[<dispositivo>][:<clase>[:<prog-if>]]
Muestra solo los dispositivos con el vendedor, dispositivo, ID de clase y interfaz de programación especificados. Los IDs se dan en hexadecimal y pueden omitirse o darse como "*", significando ambos "cualquier valor". El ID de clase puede contener caracteres "x" que significan "cualquier dígito".

Otras opciones

-i <archivo>
Utiliza <archivo> como la lista de IDs PCI en lugar de /usr/share/hwdata/pci.ids.
-p <archivo>
Utiliza <archivo> como el mapa de IDs PCI manejados por módulos del kernel. Por defecto, lspci usa /lib/modules/kernel_version/modules.pcimap. Solo se aplica a sistemas Linux con herramientas de módulos suficientemente recientes.
-M
Invoca el modo de mapeo de bus que realiza un escaneo exhaustivo de todos los dispositivos PCI, incluidos los que están detrás de puentes mal configurados, etc. Esta opción produce resultados significativos solo con un modo de acceso directo al hardware, que normalmente requiere privilegios de root. Por defecto, el mapeador de bus escanea el dominio. Puedes usar la opción -s para seleccionar un dominio diferente.
--version
Muestra la versión de lspci. Esta opción debe usarse de forma independiente.

Opciones de acceso PCI

Las utilidades PCI utilizan la biblioteca PCI para comunicarse con los dispositivos PCI (consulta pcilib(7) para más detalles). Puedes usar las siguientes

OPTIONS

lspci understands the following options which can be used to influence its behavior:

-A <método>
La biblioteca admite una variedad de métodos para acceder al hardware PCI. Por defecto, utiliza el primer método de acceso disponible, pero puedes usar esta opción para anular esta decisión. Consulta -A ayuda para obtener una lista de los métodos disponibles y sus descripciones.
-O <param>=<valor>
El comportamiento de la biblioteca se controla mediante varios parámetros con nombre. Esta opción permite establecer el valor de cualquiera de los parámetros. Usa -O ayuda para obtener una lista de los parámetros conocidos y sus valores predeterminados.
-H1
Utiliza acceso directo al hardware a través del mecanismo de configuración 1 de Intel. (Esto es un atajo para -A intel-conf1).
-H2
Utiliza acceso directo al hardware a través del mecanismo de configuración 2 de Intel. (Esto es un atajo para -A intel-conf2).
-F <archivo>
En lugar de acceder al hardware real, lee la lista de dispositivos y los valores de sus registros de configuración del archivo proporcionado, producido por una ejecución anterior de lspci -x. Esto es muy útil para el análisis de informes de errores proporcionados por el usuario, ya que puedes mostrar la configuración del hardware de la forma que desees sin molestar al usuario con solicitudes de más volcados.
-G
Aumenta el nivel de depuración de la biblioteca.

SALIDA LEGIBLE POR MÁQUINA

Si tienes la intención de procesar la salida de lspci automáticamente, utiliza uno de los formatos de salida legibles por máquina (-m, -vm, -vmm) descritos en esta sección. Es probable que todos los demás formatos cambien entre versiones de lspci.

Todos los números se imprimen siempre en hexadecimal. Si deseas procesar identificadores numéricos en lugar de nombres, añade el modificador -n.

Formato simple (-m)

En el formato simple, cada dispositivo se describe en una sola línea, que se formatea como parámetros adecuados para pasar a un script de shell, es decir, valores separados por espacios en blanco, entre comillas y escapados si es necesario. Algunos de los argumentos son posicionales: ranura, clase, nombre del vendedor, nombre del dispositivo, nombre del vendedor subdispositivo y nombre del subdispositivo (los dos últimos están vacíos si el dispositivo no tiene subdispositivo); los argumentos restantes son similares a opciones:

-rrev
Número de revisión.
-pprogif
Interfaz de programación.

El orden relativo de los argumentos posicionales y las opciones no está definido. Se pueden añadir nuevas opciones en versiones futuras, pero siempre tendrán un solo argumento no separado de la opción por ningún espacio, por lo que se pueden ignorar fácilmente si no se reconocen.

Formato detallado (-vmm)

La salida detallada es una secuencia de registros separados por líneas en blanco. Cada registro describe un solo dispositivo mediante una secuencia de líneas, cada línea que contiene un solo par `etiqueta: valor'. La etiqueta y el valor están separados por un solo carácter de tabulación. Ni los registros ni las líneas dentro de un registro están en ningún orden particular. Las etiquetas distinguen entre mayúsculas y minúsculas.

Las siguientes etiquetas están definidas:

Slot
El nombre de la ranura donde reside el dispositivo ([dominio:]bus:dispositivo.función). Esta etiqueta es siempre la primera en un registro.
Class
Nombre de la clase.
Vendor
Nombre del vendedor.
Device
Nombre del dispositivo.
SVendor
Nombre del vendedor del subsistema (opcional).
SDevice
Nombre del subsistema (opcional).
PhySlot
La ranura física donde reside el dispositivo (opcional, solo Linux).
Rev
Número de revisión (opcional).
ProgIf
Interfaz de programación (opcional).
Driver
Controlador del kernel que actualmente maneja el dispositivo (opcional, solo Linux).
Module
Módulo del kernel que informa que es capaz de manejar el dispositivo (opcional, solo Linux). Puede haber varias líneas con esta etiqueta.
NUMANode
Nodo NUMA al que está conectado este dispositivo (opcional, solo Linux).
IOMMUGroup
Grupo IOMMU del que forma parte este dispositivo (opcional, solo Linux).

Se pueden añadir nuevas etiquetas en versiones futuras, por lo que debes ignorar silenciosamente cualquier etiqueta que no reconozcas.

Formato detallado compatible con versiones anteriores (-vm)

En este modo, lspci intenta ser perfectamente compatible con sus versiones anteriores. Es casi lo mismo que el formato detallado normal, pero la etiqueta Device se usa tanto para la ranura como para el nombre del dispositivo, por lo que aparece dos veces en un solo registro. Por favor, evita usar este formato en cualquier código nuevo.

ARCHIVOS

/usr/share/hwdata/pci.ids
Una lista de todos los ID's PCI conocidos (vendedores, dispositivos, clases y subclases). Mantenido en https://pci-ids.ucw.cz/, usa la utilidad update-pciids para descargar la versión más reciente.
/usr/share/hwdata/pci.ids.gz
Si lspci está compilado con soporte para compresión, este archivo se intenta antes que pci.ids.
$XDG_CACHE_HOME/pci-ids
Todos los ID's encontrados en el modo de consulta DNS se almacenan en caché en este archivo.

ERRORES

A veces, lspci no puede decodificar completamente los registros de configuración. Esto suele ocurrir cuando no había suficiente documentación disponible para los autores. En tales casos, al menos imprime la marca <?> para indicar que potencialmente hay algo más que decir. Si conoces los detalles, los parches serán bienvenidos, por supuesto.

El acceso al espacio de configuración extendido solo es compatible actualmente con el backend linux_sysfs.
