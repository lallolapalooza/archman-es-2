lseek(2) Manual de Llamadas al Sistema lseek(2)

NOMBRE

lseek - reposiciona el desplazamiento de archivo de lectura/escritura

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
off_t lseek(int fd, off_t offset, int whence);

DESCRIPCIÓN

lseek() reposiciona el desplazamiento del archivo de la descripción de archivo abierta asociada con el descriptor de archivo fd al argumento offset según la directiva whence de la siguiente manera:

SEEK_SET
El desplazamiento del archivo se establece en offset bytes.
SEEK_CUR
El desplazamiento del archivo se establece en su ubicación actual más offset bytes.
SEEK_END
El desplazamiento del archivo se establece en el tamaño del archivo más offset bytes.

lseek() permite que el desplazamiento del archivo se establezca más allá del final del archivo (pero esto no cambia el tamaño del archivo). Si posteriormente se escriben datos en este punto, las lecturas posteriores de los datos en el hueco (un "agujero") devuelven bytes nulos ('�') hasta que se escriben datos realmente en el hueco.

Buscar datos de archivo y agujeros

Desde Linux 3.1, Linux admite los siguientes valores adicionales para whence:

SEEK_DATA
Ajusta el desplazamiento del archivo a la siguiente ubicación en el archivo mayor o igual a offset que contenga datos. Si offset apunta a datos, entonces el desplazamiento del archivo se establece en offset.
SEEK_HOLE
Ajusta el desplazamiento del archivo al siguiente agujero en el archivo mayor o igual a offset. Si offset apunta en medio de un agujero, entonces el desplazamiento del archivo se establece en offset. Si no hay ningún agujero después de offset, entonces el desplazamiento del archivo se ajusta al final del archivo (es decir, hay un agujero implícito al final de cualquier archivo).

En ambos casos anteriores, lseek() falla si offset apunta más allá del final del archivo.

Estas operaciones permiten a las aplicaciones mapear agujeros en un archivo asignado de forma dispersa. Esto puede ser útil para aplicaciones como herramientas de copia de seguridad de archivos, que pueden ahorrar espacio al crear copias de seguridad y preservar agujeros, si tienen un mecanismo para descubrir agujeros.

A efectos de estas operaciones, un agujero es una secuencia de ceros que (normalmente) no se ha asignado en el almacenamiento de archivos subyacente. Sin embargo, un sistema de archivos no está obligado a informar de los agujeros, por lo que estas operaciones no son un mecanismo garantizado para mapear el espacio de almacenamiento realmente asignado a un archivo. (Además, es posible que una secuencia de ceros que realmente se haya escrito en el almacenamiento subyacente no se informe como un agujero). En la implementación más simple, un sistema de archivos puede admitir las operaciones haciendo que SEEK_HOLE siempre devuelva el desplazamiento del final del archivo, y haciendo que SEEK_DATA siempre devuelva offset (es decir, incluso si la ubicación a la que se refiere offset es un agujero, puede considerarse que consta de datos que son una secuencia de ceros).

Debe definirse la macro de prueba de características _GNU_SOURCE para obtener las definiciones de SEEK_DATA y SEEK_HOLE de <unistd.h>.

Las operaciones SEEK_HOLE y SEEK_DATA son compatibles con los siguientes sistemas de archivos:

•
Btrfs (desde Linux 3.1)
•
OCFS (desde Linux 3.2)
•
XFS (desde Linux 3.5)
•
ext4 (desde Linux 3.8)
•
tmpfs(5) (desde Linux 3.8)
•
NFS (desde Linux 3.18)
•
FUSE (desde Linux 4.5)
•
GFS2 (desde Linux 4.15)

VALOR DE RETORNO

En caso de éxito, lseek() devuelve la ubicación del desplazamiento resultante medida en bytes desde el principio del archivo. En caso de error, se devuelve el valor (off_t) -1 y se establece errno para indicar el error.

ERRORES

EBADF
fd no es un descriptor de archivo abierto.
EINVAL
whence no es válido. O: el desplazamiento del archivo resultante sería negativo, o más allá del final de un dispositivo buscable.
ENXIO
whence es SEEK_DATA o SEEK_HOLE, y offset está más allá del final del archivo, o whence es SEEK_DATA y offset está dentro de un agujero al final del archivo.
EOVERFLOW
El desplazamiento del archivo resultante no se puede representar en un off_t.
ESPIPE
fd está asociado con una tubería, socket o FIFO.

VERSIÓNES

En Linux, usar lseek() en un dispositivo de terminal falla con el error ESPIPE.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

NOTAS

Vea open(2) para una discusión de la relación entre descriptores de archivo, descripciones de archivo abiertas y archivos.

Si la bandera de estado de archivo O_APPEND está establecida en la descripción de archivo abierta, entonces una write(2) mueve el desplazamiento del archivo al final del archivo *siempre*, independientemente del uso de lseek().

Algunos dispositivos no son capaces de buscar y POSIX no especifica qué dispositivos deben admitir lseek().
