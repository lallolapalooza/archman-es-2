lstopo-no-graphics(1)

Paquete: hwloc

Licencias: BSD-3-Clause

LSTOPO(1) hwloc LSTOPO(1)

NOMBRE

lstopo, lstopo-no-graphics, hwloc-ls - Muestra la topología del sistema

SINOPSIS

lstopo [ opciones ]... [ nombre_archivo ]

lstopo-no-graphics [ opciones ]... [ nombre_archivo ]

hwloc-ls [ opciones ]... [ nombre_archivo ]

Tenga en cuenta que hwloc(7) proporciona una explicación detallada del sistema hwloc; debe leerse antes de leer esta página del manual.

OPCIONES

--of <formato>, --output-format <formato>
Fuerza la salida en el formato dado. Consulte la sección FORMATOS DE SALIDA más abajo.
-i <ruta>, --input <ruta>
Lee la topología desde <ruta> en lugar de descubrir la topología de la máquina local.

Si <ruta> es un archivo, puede ser un archivo XML exportado por un programa hwloc anterior. Si <ruta> es "-", la entrada estándar puede usarse como archivo XML.

En Linux, <ruta> puede ser un directorio que contenga los archivos de topología recopilados de la topología de otra máquina con hwloc-gather-topology.

En x86, <ruta> puede ser un directorio que contenga un volcado de cpuid recopilado con hwloc-gather-cpuid.

Cuando el programa archivemount está disponible, <ruta> también puede ser un archivo tar que contenga dichos archivos de topología de Linux o x86.

-i <especificación>, --input <especificación>
Simula una jerarquía ficticia (en lugar de descubrir la topología en la máquina local). Si <especificación> es "node:2 pu:3", la topología contendrá dos nodos NUMA con 3 unidades de procesamiento en cada uno. La cadena <especificación> debe terminar con un número de PUs.
--if <formato>, --input-format <formato>
Fuerza la entrada en el formato dado, entre xml, fsroot, cpuid y synthetic.
--export-xml-flags <flags>
Fuerza las flags al exportar al formato XML. Las flags pueden darse como valores numéricos o como una lista separada por comas de nombres de flags que se pasan a hwloc_topology_export_xml(). Estos nombres pueden ser subcadenas de nombres de flags reales siempre que coincida uno solo. Un valor de 1 (o v1) revierte al formato de hwloc v1.x. El valor predeterminado es 0 (o none).
--export-synthetic-flags <flags>
Fuerza las flags al exportar al formato sintético. Las flags pueden darse como valores numéricos o como una lista separada por comas de nombres de flags que se pasan a hwloc_topology_export_synthetic(). Estos nombres pueden ser subcadenas de nombres de flags reales siempre que coincida uno solo. Un valor de 2 (o no_attr) revierte al formato de hwloc v1.9. Un valor de 3 (o no_ext,no_attr) revierte al formato minimalista original (antes de v1.9). El valor predeterminado es 0 (o none).
-v --verbose
Incluye detalles adicionales. La herramienta hwloc-info puede usarse para mostrar aún más información sobre objetos específicos.
-q --quiet -s --silent
Reduce la cantidad de detalles a mostrar.
--distances
Solo muestra matrices de distancias.
--distances-transform <links|merge-switch-ports|transitive-closure>
Intenta aplicar una transformación a las estructuras de distancias antes de mostrarlas. Consulte hwloc_distances_transform() para más detalles. Se pueden aplicar más transformaciones usando hwloc-annotate(1) (y puede guardar sus salidas en XML).
--memattrs
Solo muestra atributos de memoria. Se muestran todos (mientras que la salida textual predeterminada selecciona detalles de atributos de memoria dependiendo del nivel de verbosidad).
--cpukinds
Solo muestra tipos de CPU. Los tipos de CPU se muestran en orden, comenzando por los más eficientes energéticamente hasta los que consumen más energía y rendimiento.
--windows-processor-groups
En Windows, solo muestra información sobre grupos de procesadores. Se muestran todos, mientras que la salida detallada predeterminada solo los muestra si hay más de uno.
-f --force
Si el archivo de destino ya existe, lo sobrescribe.
-l --logical
Muestra los índices lógicos de hwloc de todos los objetos, con el prefijo "L#". Por defecto, se muestran tanto los índices lógicos como los físicos/del sistema operativo para PUs y nodos NUMA, solo lógicos para cores, dies y paquetes, y ningún índice para otros tipos.
-p --physical
Muestra los índices del sistema operativo/físicos de todos los objetos, con el prefijo "P#". Por defecto, se muestran tanto los índices lógicos como los físicos/del sistema operativo para PUs y nodos NUMA, solo lógicos para cores, dies y paquetes, y ningún índice para otros tipos.
--logical-index-prefix <prefijo>
Reemplaza " L#" con el prefijo dado para los índices lógicos.
--os-index-prefix <prefijo>
Reemplaza " P#" con el prefijo dado para los índices físicos/del sistema operativo.
-c --cpuset
Muestra el conjunto de CPUs de cada objeto.
-C --cpuset-only
Solo muestra el conjunto de CPUs de cada objeto; no muestra nada más sobre el objeto.
--cpuset-output-format <hwloc|list|taskset> --cof <hwloc|list|taskset>
Cambia el formato de las cadenas de conjunto de CPUs mostradas. Por defecto, se utiliza el formato específico de hwloc. Si se da list, la salida es una lista separada por comas de números o rangos, por ejemplo, 2,4-5,8. Si se da taskset, los conjuntos de CPUs de salida son compatibles con el programa taskset (reemplaza la opción anterior --taskset).

Esta opción debe combinarse con --cpuset o --cpuset-only, de lo contrario implicará --cpuset.

--only <tipo>
Solo muestra objetos del tipo dado en la salida textual.

<tipo> puede contener un filtro para seleccionar objetos específicos dentro del tipo. Por ejemplo, --only NUMA[HBM] solo muestra nodos NUMA marcados con el subtipo "HBM", mientras que --only "numa[mcdram]" solo muestra nodos NUMA MCDRAM en KNL.

--filter <tipo>:<clase>, --filter <tipo>
Filtra objetos del tipo <tipo>, o de cualquier tipo si <tipo> es "all". También se admiten "io", "cache" y "icache".

<clase> especifica el comportamiento del filtrado. Si "none" o no se especifica, se eliminan todos los objetos del tipo dado. Si "all", se conservan todos los objetos como normalmente. Si "structure", se conservan los objetos cuando aportan estructura a la topología. Si "important" (solo aplicable a E/S), solo se conservan los objetos importantes. Consulte hwloc_topology_set_type_filter() para más detalles.

hwloc admite el filtrado de cualquier tipo excepto PUs y nodos NUMA. lstopo también ofrece filtrado de PU y nodos NUMA ocultándolos en las salidas gráfica y textual, pero cualquier objeto incluido en ellos (por ejemplo, Misc) también se ocultará. Tenga en cuenta que los PUs y los nodos NUMA no pueden ignorarse en la salida XML. Tenga en cuenta también que el tipo de objeto de nivel superior no puede ignorarse (generalmente Machine o System).

--ignore <tipo>
Esta es la forma antigua de especificar --filter <tipo>:none.
--no-smt
Ignorar PUs. Esto es idéntico a --filter PU:none.
--no-caches
No mostrar cachés. Esto es idéntico

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

al to --filter cache:none.
--no-useless-caches
Esto es idéntico a --filter cache:structure.
--no-icaches
Esto es idéntico a --filter icache:none.
--disallowed
Incluye objetos desautorizados por limitaciones administrativas (ej. Cgroups en Linux). Las PU y los nodos NUMA desconectados todavía se ignoran.
--allow <all|local|0xff|nodeset=0xf0>
Incluye objetos desautorizados por limitaciones administrativas (implica --disallowed) y también cambia el conjunto de los autorizados.

Si se especifica local, solo se autorizan los objetos disponibles para el proceso actual (comportamiento predeterminado al cargar desde el backend del sistema operativo nativo). Puede ser útil si la topología fue creada por otro proceso (con diferentes restricciones administrativas como los Cgroups de Linux) y se carga aquí desde XML o sintéticamente. Este caso implica --thissystem.

Si se especifica all, se autorizan todos los objetos.

Si se proporciona un mapa de bits como cadena hexadecimal, se utiliza como conjunto de las PU autorizadas.

Si se proporciona un mapa de bits después del prefijo nodeset=, este es el conjunto de los nodos NUMA autorizados.

--flags <flags>
Impone las banderas de la topología. Las banderas pueden proporcionarse como valores numéricos o como una lista separada por comas de nombres de banderas que se pasan a hwloc_topology_set_flags(). Estos nombres pueden ser subcadenas de los nombres reales de las banderas siempre que coincida una sola, por ejemplo disallowed,thissystem_allowed. El valor predeterminado es 8 (o import).
--merge
No muestra niveles que no tienen impacto jerárquico. Esto establece HWLOC_TYPE_FILTER_KEEP_STRUCTURE para todos los tipos de objetos. Esto es idéntico a --filter all:structure.
--no-factorize --no-factorize=<type>
Nunca factoriza objetos idénticos en la salida gráfica.

Si se proporciona un tipo de objeto, solo se deshabilita la factorización de estos objetos. Esto solo se aplica a los objetos normales del lado de la CPU, es independiente del colapso PCI.

--factorize --factorize=[<type>,]<N>[,<F>[,<L>]]
Factoriza hijos idénticos en la salida gráfica (habilitado por defecto).

Si se especifica <N> (4 por defecto), la factorización solo ocurre cuando hay estrictamente más de N hijos idénticos. Si se especifican <F> y <L>, estos establecen los números de los primeros y últimos hijos a mantener después de factorizar.

Si se proporciona un tipo de objeto, solo se configura la factorización de estos objetos. Esto solo se aplica a los objetos normales del lado de la CPU, es independiente del colapso PCI.

--no-collapse
No colapsa dispositivos PCI idénticos. Por defecto, los dispositivos PCI hermanos idénticos (como muchas funciones virtuales dentro de un único dispositivo físico) se colapsan.
--no-cpukinds
No muestra diferentes tipos de CPUs en la salida gráfica. Por defecto, cuando es compatible, se pueden usar diferentes tipos de líneas, grosor y fuente en negrita para mostrar cuadros de PU de diferentes tipos.
--restrict <cpuset>
Restringe la topología al conjunto de CPUs dado. Esto elimina algunas PUs y sus padres ahora sin hijos.

Tenga en cuenta que restringir las PUs en una topología puede cambiar los índices lógicos de muchos objetos, incluidos los nodos NUMA.

--restrict nodeset=<nodeset>
Restringe la topología al conjunto de nodos dado. (a menos que --restrict-flags especifique algo diferente). Esto elimina algunos nodos NUMA y sus padres ahora sin hijos.

Tenga en cuenta que restringir los nodos NUMA en una topología puede cambiar los índices lógicos de muchos objetos, incluidas las PUs.

--restrict binding
Restringe la topología a la vinculación del proceso actual. Esta opción requiere el uso de la topología de la máquina actual (o cualquier otra topología con --thissystem o con HWLOC_THISSYSTEM establecido en 1 en el entorno).

Tenga en cuenta que restringir la topología puede cambiar los índices lógicos de muchos objetos, incluidas las PUs y los nodos NUMA.

--restrict-flags <flags>
Impone banderas al restringir la topología. Las banderas pueden proporcionarse como valores numéricos o como una lista separada por comas de nombres de banderas que se pasan a hwloc_topology_restrict(). Estos nombres pueden ser subcadenas de los nombres reales de las banderas siempre que coincida una sola, por ejemplo bynodeset,memless. El valor predeterminado es 0 (o none).
--no-io
No muestra ningún dispositivo de E/S ni puente. Esto es idéntico a --filter io:none. Por defecto, se muestran dispositivos comunes (GPUs, NICs, dispositivos de bloque, ...) y puentes/conmutadores interesantes.
--no-bridges
No muestra ningún puente de E/S excepto los puentes de host. Esto es idéntico a --filter bridge:none. Por defecto, se muestran dispositivos comunes (GPUs, NICs, dispositivos de bloque, ...) y puentes/conmutadores interesantes.
--whole-io
Muestra todos los dispositivos y puentes de E/S. Esto es idéntico a --filter io:all. Por defecto, solo se muestran dispositivos comunes (GPUs, NICs, dispositivos de bloque, ...) y puentes/conmutadores interesantes.
--thissystem
Asume que el backend seleccionado proporciona la topología del sistema en el que estamos ejecutando. Esto es útil al cargar una topología personalizada como un archivo XML y usar --restrict binding o --allow all.
--pid <pid>
Detecta la topología tal como la ve el proceso <pid>, es decir, como si el proceso <pid> hubiera realizado el descubrimiento por sí mismo. Tenga en cuenta que esto puede, por ejemplo, cambiar el conjunto de procesadores permitidos. También muestra la vinculación de CPU y memoria actual de este proceso marcando las PU y los nodos NUMA correspondientes (en verde en la salida gráfica, ver la sección COLORES a continuación, o añadiendo (binding) a la salida de texto detallada). Si se proporciona 0 como pid, se mostrará la vinculación actual del proceso lstopo.
--ps --top
Muestra los procesos existentes como objetos misceláneos en la salida. Para evitar saturar inútilmente la salida, solo se muestran los procesos que están restringidos a una parte de la máquina. En Linux, los hilos del kernel no se muestran. Si aparecen muchos procesos, la salida puede ser difícil de leer de todos modos, lo que hace que el programa hwloc-ps sea más práctico.

Consulte --misc-from para ver una variante personalizable que utiliza hwloc-ps.

--misc-from <file>
Agrega objetos Misceláneos según se describe en <file> que contiene entradas como:


name=myMisc1
cpuset=0x5


name=myMisc2
cpuset=0x7
subtype=myOptionalSubtype

Esto es útil para combinar con hwloc-ps --lstopo-misc (ver EJEMPLOS a continuación) ya que hwloc-ps es mucho más personalizable que la opción --top de lstopo.

--children-order <order>
Cambia el orden de los diferentes tipos de hijos con respecto a su padre en la salida gráfica. <order> puede ser una lista separada por comas de palabras clave entre:

memory:above muestra los hijos de memoria por encima de los otros hijos (y por encima del padre si es una caché). Las PUs están, por lo tanto, debajo de sus nodos NUMA locales, como lo hacía hwloc 1.x.

io:right y misc:right colocan los hijos de E/S o Misceláneos a la derecha de los hijos de CPU.

io:below y misc:below colocan los hijos de E/S o Misceláneos debajo de los hijos de CPU.

plain coloca todo lo que no se especifica junto con los hijos de CPU normales.

Si solo se especifica plain, lstopo muestra la topología de manera básica que coincide estrictamente con el árbol real: los hijos de Memoria, E/S y Misceláneos se enumeran debajo de su padre al igual que cualquier otro hijo. Por lo tanto, las PUs están al lado de sus nodos NUMA locales, debajo de un ancestro común. Esta salida puede resultar en diseños extraños ya que el tamaño de los hijos de Memoria, CPU y E/S puede ser muy diferente, lo que provoca que el algoritmo de colocación los organice mal en filas.

El orden predeterminado es memory:above,io:right,misc:right que significa que los hijos de Memoria están encima de los hijos de CPU mientras que E/S y Misceláneos están juntos a la derecha.

Hasta hwloc 2.5, el valor predeterminado era más bien memory:above,plain.

Además, memory:above, io:right, io:below, misc:right y misc:below pueden ir seguidos de :horiz, :vert o :rect para forzar la disposición horizontal, vertical o rectangular de los hijos dentro de estas secciones.

Ver también las secciones SALIDA GRÁFICA y DISPOSICIÓN a continuación.

--fontsize <size>
Establece el tamaño de la fuente de texto en la salida gráfica.

El valor predeterminado es 10.

Los cuadros se escalan según el tamaño del texto. La variable de entorno LSTOPO_TEXT_XSCALE se puede usar para escalar aún más el ancho de los cuadros (su valor predeterminado es 1.0).

La opción --fontsize se ignora en el backend ASCII.

--gridsize <size>
Establece el margen entre elementos en la salida gráfica.

El valor predeterminado es 7. Era 10 antes de hwloc 2.1.

Esta opción se ignora en el backend ASCII.

--linespacing <size>
Establece el espaciado entre líneas de texto en la salida gráfica.

El valor predeterminado es 4.

La opción se incluyó en --gridsize antes de hwloc 2.1 (y su valor predeterminado era 10).

Esta opción se ignora en el backend ASCII.

synthetic
Si la topología es simétrica (lo que requiere que el objeto raíz tenga su campo symmetric_subtree configurado), lstopo genera una cadena de descripción sintética. Esta salida puede ser reutilizada más tarde como descripción de topología sintética de entrada. Ver también la sección Topologías sintéticas en la documentación. Tenga en cuenta que los dispositivos Varios y de E/S se ignoran durante esta exportación.
xml
lstopo genera una representación XML del mapa. Puede ser reutilizada más tarde, incluso en otra máquina, con lstopo --input, la variable de entorno HWLOC_XMLFILE, o la función hwloc_topology_set_xml().

Los siguientes nombres especiales pueden ser utilizados:

-

SALIDA GRÁFICA

La salida gráfica consta de cuadros anidados que representan la inclusión de objetos en la jerarquía de recursos. Normalmente, un cuadro de Máquina contiene uno o varios cuadros de Paquete, que a su vez contienen múltiples cuadros de Núcleo, cada uno con uno o varios PUs.

Cachés

Los cachés se muestran de una manera ligeramente diferente porque en realidad no incluyen recursos de cómputo como núcleos. Por ejemplo, un caché L2 compartido por un par de núcleos se dibuja como un cuadro de Caché encima de dos cuadros de Núcleo (en lugar de tener cuadros de Núcleo dentro del cuadro de Caché).

Nodos NUMA y Cachés en lado de memoria

Por defecto, los cuadros de nodos NUMA se dibujan encima de sus recursos de cómputo locales. Por ejemplo, un Paquete de procesador que contiene un nodo NUMA y cuatro Núcleos se muestra como un cuadro de Paquete que contiene el cuadro del nodo NUMA encima de cuatro cuadros de Núcleo. Si un nodo NUMA es local al Caché L3, el nodo NUMA se muestra encima de ese cuadro de Caché. Toda esta estrategia de dibujo específica para objetos de memoria puede ser deshabilitada al pasar la opción de línea de comandos --children-order plain.

Si múltiples nodos NUMA están conectados al mismo objeto padre, se muestran dentro de un cuadro de memoria adicional sin nombre.

Si existen cachés en el lado de la memoria delante de algunos nodos NUMA, se dibujan como cuadros inmediatamente encima de ellos.

Puentes PCI, dispositivos PCI y dispositivos del SO

La jerarquía PCI no se dibuja como un conjunto de cuadros incluidos, sino más bien como un árbol de puentes (que pueden ser en realidad conmutadores) con enlaces entre ellos. El árbol comienza con un pequeño cuadrado a la izquierda para el hostbridge o el complejo raíz. Termina con cuadros de dispositivos PCI a la derecha. Los puentes/conmutadores PCI intermedios pueden aparecer como cuadrados pequeños adicionales en el medio.

Los dispositivos PCI a la derecha del árbol son cuadros que contienen su ID de bus PCI (como 00:02.3). También pueden contener subcuadros para objetos de dispositivo del SO, como una interfaz de red eth0 o una GPU CUDA cuda0.

Cuando hay un solo enlace (línea horizontal) a la derecha de un puente PCI, significa que un solo dispositivo o puente está conectado en el bus PCI secundario detrás de ese puente. Cuando hay una línea vertical, significa que múltiples dispositivos y/o puentes están conectados al mismo bus PCI secundario.

La tasa de transferencia de un enlace PCI puede ser escrita (en GB/s) justo debajo de su línea dibujada (si el sistema operativo y/o las bibliotecas son capaces de informar esa información). Esta tasa de transferencia es la velocidad actualmente configurada de todo el enlace PCI (suma del ancho de banda de todos los carriles PCI en ese enlace). Puede cambiar durante la ejecución, ya que algunos dispositivos pueden reducir la velocidad de sus enlaces PCI cuando están inactivos.

DISEÑO

En su salida gráfica, lstopo utiliza heurísticas simples de rectángulos para intentar lograr una relación de 4/3 entre ancho y alto. Aunque la jerarquía de recursos se refleja adecuadamente, la organización física exacta (distancias NUMA, anillos, grafos completos, etc.) se ignora actualmente.

El diseño de un nivel puede cambiarse con --vert, --horiz y --rect para forzar a un objeto padre a organizar a sus hijos de manera vertical, horizontal o rectangular, respectivamente.

La posición de los hijos de Memoria, E/S y Varios con respecto a otros objetos hijos puede cambiarse usando --children-order. Esto divide efectivamente a los hijos en múltiples secciones. El diseño de los hijos se calcula primero dentro de cada sección, antes de que las secciones se coloquen dentro (o debajo) del cuadro padre.

El diseño vertical/horizontal/rectangular de estas secciones adicionales también puede configurarse a través de --children-order.

COLORES

Los cuadros en los formatos de salida gráfica se colorean según el tipo de objeto hwloc, por ejemplo, los paquetes de CPU son verdes o los nodos NUMA son rosas. Esto se puede configurar con --palette, ver también COLORES PERSONALIZADOS a continuación. Además de estos colores predeterminados, las CPUs individuales y los nodos NUMA pueden ser coloreados para indicar diferentes características:

Verde
La topología es reportada tal como la ve un proceso específico (ver --pid), y la CPU o nodo NUMA dada está en la máscara de enlace de CPU o Memoria de este proceso. Este color puede cambiarse con --binding-color.
Blanco
La CPU o nodo NUMA está en el conjunto permitido (ver abajo). Si la topología es reportada tal como la ve un proceso específico (ver --pid), el objeto tampoco está en la máscara de enlace de este proceso.
Rojo
La CPU o nodo NUMA no está en el conjunto permitido (ver abajo). Este color puede cambiarse con --disallowed-color.

El "conjunto permitido" es el conjunto de CPUs o nodos NUMA a los que el proceso actual tiene permitido vincularse. El conjunto permitido generalmente se hereda del proceso padre o se establece por políticas administrativas en el sistema. Los cpusets de Linux son un ejemplo de limitación del conjunto permitido para un proceso y sus hijos a ser menor que el conjunto completo de CPUs o nodos NUMA en el sistema.

Por lo tanto, diferentes procesos pueden tener diferentes CPUs o nodos NUMA en el conjunto permitido. En consecuencia, invocar lstopo en diferentes contextos y/o como diferentes usuarios puede mostrar diferentes colores para las mismas CPUs individuales (por ejemplo, ejecutar lstopo en un contexto puede mostrar una CPU específica como roja, pero ejecutar lstopo en un contexto diferente puede mostrar la misma CPU como blanca).

Algunos modos de salida de lstopo, por ejemplo, el modo de consola (salida no gráfica predeterminada), no admiten colores en absoluto. El modo de consola muestra las características anteriores agregando texto a cada línea de PU si los mensajes detallados están habilitados.

COLORES PERSONALIZADOS

Los colores de los diferentes tipos de cuadros pueden configurarse con --palette.

El color de cada objeto en la salida gráfica también puede ser forzado especificando un atributo de información "lstopoStyle" en ese objeto. Su valor debe ser una lista separada por punto y coma de "<atributo>=#rrggbb", donde rr, gg y bb son los componentes RGB de un color, cada uno entre 0 y 255, en hexadecimal (00 a ff). <atributo> puede ser

Fondo
Establece el color de fondo del cuadro del objeto principal.
Texto
Establece el color del texto que muestra el nombre, tipo, índice, etc. del objeto.
Texto2
Establece el color del texto adicional cerca del objeto, por ejemplo, la velocidad del enlace detrás de un puente PCI.

La información "lstopoStyle" puede agregarse a topologías XML guardadas temporalmente con hwloc-annotate, o con hwloc_obj_add_info(). Por ejemplo, para mostrar todos los objetos de núcleo en azul (con nombres blancos):


$ lstopo save.xml
$ hwloc-annotate save.xml save.xml core:all info lstopoStyle "Background=#0000ff;Text=#ffffff"
$ lstopo -i save.xml

EJEMPLOS

Para mostrar la topología de la máquina en modo texto:


$ lstopo-no-graphics

Para mostrar la topología de la máquina en modo arte ASCII:


$ lstopo-no-graphics -.ascii

Para mostrar en modo gráfico (suponiendo que la variable de entorno DISPLAY esté configurada correctamente):


$ lstopo

Para exportar la topología a un archivo PNG:


$ lstopo file.png

Ejemplos con intercambio y modificación de XML

Para exportar un archivo XML en una máquina y luego mostrar la salida gráfica correspondiente en otra máquina:


$ machine1$ lstopo file.xml
<transferir file.xml de machine1 a machine2>
$ machine2$ lstopo --input file.xml

Para guardar la topología de la máquina actual en XML y luego recargarla más rápido, considerándola todavía como la máquina actual:


$ lstopo file.xml
<...>
$ lstopo --input file.xml --thissystem

Para restringir una topología XML solo a los procesadores físicos 0, 1, 4 y 5:


$ lstopo --input file.xml --restrict 0x33 newfile.xml

Para restringir una topología XML solo al nodo numa cuyo índice lógico es 1:


$ lstopo --input file.xml --restrict $(hwloc-calc --input file.xml node:1) newfile.xml

EXAMPLES

Para obtener más detalles sobre la topología:


$ lstopo -v

Para mostrar solo los núcleos:


$ lstopo --only core

Para mostrar cpusets:


$ lstopo --cpuset

Para mostrar solo los cpusets de un paquete:


$ lstopo --only package --cpuset-only

Examples with XML exchange and modification

Simular una jerarquía falsa; este ejemplo muestra 2 nodos NUMA de 2 unidades de procesador:


$ lstopo --input "node:2 2"

Para añadir la versión y liberación del kernel a la leyenda gráfica:


$ lstopo --append-legend "Kernel release: $(uname -r)" --append-legend "Kernel version: $(uname -v)"

Para mostrar dónde está enlazado un proceso y sus hijos, combinando con hwloc-ps:


$ hwloc-ps --pid-children 23 --lstopo-misc - | lstopo --misc-from -
