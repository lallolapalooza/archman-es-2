NOMBRE

lxc-usernsexec - Ejecutar una tarea como root en un nuevo espacio de nombres de usuario.

SINOPSIS


lxc-usernsexec
[-m mapa-uid] {-- comando}

DESCRIPCIÓN

lxc-usernsexec puede usarse para ejecutar una tarea como root en un nuevo espacio de nombres de usuario.

OPCIONES

-m mapa-uid
El mapa de ids de usuario a usar en el espacio de nombres de usuario. Cada mapa consiste en cuatro valores separados por dos puntos. Primero un carácter 'u', 'g' o 'b' para especificar si este mapa pertenece a ids de usuario, ids de grupo o ambos; luego el primer id de usuario en el espacio de nombres de usuario; luego el primer id de usuario tal como se ve en el host; y finalmente el número de ids a mapear.

Se puede especificar más de un mapa. Si no se especifica ningún mapa, entonces por defecto se mapearán los rangos completos de uid y gid concedidos por /etc/subuid y /etc/subgid a los uids y gids a partir de 0 en el contenedor.

Tenga en cuenta que lxc-usernsexec siempre intenta realizar setuid y setgid a 0 en el espacio de nombres. Por lo tanto, el id de usuario 0 en el espacio de nombres debe estar mapeado.

EJEMPLOS

Para iniciar un shell con los subuids completos asignados mapeados en el contenedor, use

	  lxc-usernsexec

Para ejecutar un shell diferente a /bin/sh, use

	  lxc-usernsexec -- /bin/bash

Si su id de usuario es 1000, root en un contenedor se mapea a 190000, y desea cambiar el propietario de un archivo que usted posee a root en el contenedor, puede usar:

	  lxc-usernsexec -m b:0:1000:1 -m b:1:190000:1 -- /bin/chown 1:1 $archivo

Esto mapea su id de usuario a root en el espacio de nombres de usuario, y 190000 a uid 1. Dado que root en el espacio de nombres de usuario tiene privilegios sobre todos los ids de usuario mapeados en el espacio de nombres, se le permite cambiar la propiedad del archivo, lo que no podría hacer en el host usando un simple chown.
