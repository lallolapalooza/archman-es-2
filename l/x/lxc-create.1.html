NOMBRE

lxc-create - crea un contenedor

SINOPSIS


lxc-create
{-n nombre} [-f archivo_config] {-t plantilla} [-B almacenamiento_respaldo] [-- opciones_plantilla]

DESCRIPCIÓN

lxc-create crea un objeto del sistema donde se almacena la información de configuración y donde se puede almacenar la información del usuario. El identificador nombre se utiliza para especificar el contenedor a utilizar con los diferentes comandos de lxc.

El objeto es un directorio creado en /var/lib/lxc e identificado por su nombre.

El objeto es la definición de los diferentes recursos que una aplicación puede utilizar o ver. Cuanta más información contenga el archivo de configuración, más aislado estará el contenedor y más encerrada estará la aplicación.

Si no se especifica el archivo de configuración archivo_config, el contenedor se creará con el aislamiento por defecto: procesos, sysv ipc y puntos de montaje.

OPCIONES

-f, --config archivo_config
Especifica el archivo de configuración para configurar las funcionalidades de virtualización y aislamiento para el contenedor.
-t, --template plantilla
'plantilla' es el nombre corto de un script 'lxc-template' existente que es llamado por lxc-create, por ejemplo: busybox, debian, fedora, ubuntu o sshd. Consulte los ejemplos en /usr/share/lxc/templates para obtener detalles sobre la estructura esperada del script. Alternativamente, la ruta completa a un script de plantilla ejecutable también se puede pasar como parámetro. Se puede usar "none" para forzar a lxc-create a omitir la creación de rootfs.
-B, --bdev almacenamiento_respaldo
'almacenamiento_respaldo' es uno de 'dir', 'lvm', 'loop', 'btrfs', 'zfs', 'rbd' o 'best'. El valor predeterminado es 'dir', lo que significa que el sistema de archivos raíz del contenedor será un directorio bajo /var/lib/lxc/contenedor/rootfs. Este tipo de almacenamiento de respaldo permite especificar opcionalmente --dir ROOTFS, lo que significa que el rootfs del contenedor se colocará bajo la ruta especificada, en lugar de la predeterminada. (El tipo de almacenamiento de respaldo 'none' es un alias de 'dir'.) Si se especifica 'btrfs', el sistema de archivos de destino debe ser btrfs, y el rootfs del contenedor se creará como un nuevo subvolumen. Esto permite crear clones con instantáneas, pero también hace que rsync --one-filesystem lo trate como un sistema de archivos separado. Si almacenamiento_respaldo es 'lvm', se utilizará un dispositivo de bloque lvm y las siguientes opciones adicionales estarán disponibles: --lvname lvname1 creará un LV llamado lvname1 en lugar del predeterminado, que es el nombre del contenedor. --vgname vgname1 creará el LV en el grupo de volúmenes vgname1 en lugar del predeterminado, lxc. --thinpool thinpool1 creará el LV como un volumen aprovisionado delgado en el pool llamado thinpool1 en lugar del predeterminado, lxc. --fstype FSTYPE creará un sistema de archivos FSTYPE en el LV, en lugar del predeterminado, que es ext4. --fssize SIZE creará un LV (y sistema de archivos) de tamaño SIZE en lugar del predeterminado, que es 1G.

Si almacenamiento_respaldo es 'loop', puede usar --fstype FSTYPE y --fssize SIZE como con 'lvm'. Los valores predeterminados para estas opciones son los mismos que para 'lvm'.

Si almacenamiento_respaldo es 'rbd', necesitará tener una configuración válida en ceph.conf y definido un ceph.client.admin.keyring. Puede especificar las siguientes opciones: --rbdname RBDNAME creará un dispositivo de bloque llamado RBDNAME en lugar del predeterminado, que es el nombre del contenedor. --rbdpool POOL creará el dispositivo de bloque en el pool llamado POOL, en lugar del predeterminado, que es 'lxc'.

Si almacenamiento_respaldo es 'best', lxc intentará, en orden, btrfs, zfs, lvm y finalmente un almacenamiento de respaldo en directorio.

-- opciones_plantilla
Esto pasará opciones_plantilla a la plantilla como argumentos. Para ver la lista de opciones admitidas por la plantilla, puede ejecutar lxc-create -t PLANTILLA -h.

OPCIONES COMUNES

Estas opciones son comunes a la mayoría de los comandos de lxc.

-?, -h, --help
Imprime un mensaje de uso más largo de lo normal.
--usage
Muestra el mensaje de uso
-q, --quiet
silenciar activado
-P, --lxcpath=RUTA
Usar una ruta alternativa para el contenedor. El valor predeterminado es /var/lib/lxc.
-o, --logfile=ARCHIVO
Salida a un ARCHIVO de registro alternativo. El valor predeterminado es sin registro.
-l, --logpriority=NIVEL
Establece la prioridad del registro a NIVEL. La prioridad de registro predeterminada es ERROR. Los valores posibles son: FATAL, ALERT, CRIT, WARN, ERROR, NOTICE, INFO, DEBUG, TRACE.

Tenga en cuenta que esta opción establece la prioridad de los eventos registrados en el archivo de registro alternativo. No tiene efecto en los eventos ERROR registrados en stderr.

-n, --name=NOMBRE
Usa el identificador de contenedor NOMBRE. El formato del identificador de contenedor es una cadena alfanumérica.
--rcfile=ARCHIVO
Especifica el archivo de configuración para configurar las funcionalidades de virtualización y aislamiento para el contenedor.

Este archivo de configuración, si está presente, se utilizará incluso si ya existe un archivo de configuración en el contenedor creado previamente (a través de lxc-create).

--version
Muestra el número de versión.

DIAGNÓSTICO

El contenedor ya existe
Como indica el mensaje, está intentando crear un contenedor pero ya existe un contenedor con el mismo nombre. Puede usar el comando lxc-ls para listar los contenedores disponibles en el sistema.

NOMBRE

lxc-create - crear un nuevo contenedor LXC

SINOPSIS

lxc-create [-f config_file] [-R] [-B backingstore] [-L log_level] [-o log_file] [-P pid_file] [-r rootfs_size] [-n name] template [template_options...]

DESCRIPCIÓN

lxc-create crea un nuevo contenedor LXC a partir de una plantilla especificada.

La plantilla es un script que se encarga de la creación del sistema de archivos raíz para el nuevo contenedor y, opcionalmente, la instalación de paquetes.

Los argumentos template_options son específicos de cada plantilla y se pasan directamente al script de la plantilla.

El nombre del contenedor debe ser único en el host. Si no se especifica, se generará un nombre aleatorio.

El sistema de archivos raíz del contenedor se creará en el directorio especificado por la opción lxc.lxcpath en la configuración de LXC (/var/lib/lxc por defecto).

OPCIONES

-f, --config-file config_file
Especifica un archivo de configuración alternativo para LXC. Si no se especifica, se utilizará la configuración por defecto (/etc/lxc/default.conf y archivos en /etc/lxc/default.conf.d/).
-R, --recursive-cloning
Cuando se utiliza con plantillas que admiten clonación recursiva (por ejemplo, ubuntu, debian), crea un clon de un sistema de archivos existente en lugar de descargar una imagen nueva. Esto puede ser mucho más rápido.
-B, --backing-store backingstore
Especifica el tipo de sistema de archivos de respaldo a utilizar para el contenedor. Los valores posibles son dir (por defecto), lvm, zfs, btrfs.
-L, --log-level log_level
Establece el nivel de registro para la creación del contenedor. Los niveles posibles son TRACE, DEBUG, INFO, WARNING, ERROR, FATAL, ALWAYS.
-o, --log-file log_file
Especifica un archivo para escribir los mensajes de registro.
-P, --pid-file pid_file
Especifica un archivo para escribir el ID del proceso del contenedor recién creado.
-r, --rootfs-size rootfs_size
Especifica el tamaño del sistema de archivos raíz para el contenedor. Esto solo es aplicable para sistemas de archivos de respaldo como LVM o ZFS.
-n, --name name
Especifica el nombre del nuevo contenedor. Si no se proporciona, se generará un nombre único.

OPCIONES COMUNES

La mayoría de las plantillas aceptan un conjunto común de opciones, incluyendo:

  • --template-var key=value: Pasa una variable adicional a la plantilla.
  • --user-data url: Especifica una URL para los datos del usuario (a menudo utilizada para la configuración de cloud-init).
  • --ssh-key-file path: Especifica un archivo de clave SSH pública para añadir al usuario root del contenedor.

Consulte la documentación de la plantilla específica para obtener más detalles.

DIAGNÓSTICO

lxc-create devolverá un código de salida distinto de cero en caso de error. Los mensajes de error se imprimirán en la salida de error estándar o en el archivo de registro especificado.
