NOMBRE

lxc-copy - copiar un contenedor existente.

SINOPSIS


lxc-copy
{-n, --name nombre} [-P, --lxcpath ruta] {-N, --newname nuevonombre} [-p, --newpath nuevaruta] [-B, --backingstorage almacenamiento_respaldo] [-s, --snapshot] [-a, --allowrunning] [-K, --keepname] [-D, --keepdata] [-M, --keepmac] [-L, --fssize tamaño [unidad]] [-- argumentos_hook]

lxc-copy
{-n, --name nombre} [-P, --lxcpath ruta] [-N, --newname nuevonombre] [-p, --newpath nuevaruta] {-e, --ephemeral} [-B, --backingstorage almacenamiento_respaldo] [-s, --snapshot] [-a, --allowrunning] [-K, --keepname] [-D, --keepdata] [-M, --keepmac] [-L, --fssize tamaño [unidad]] [-- argumentos_hook]

lxc-copy
{-n, --name nombre} [-P, --lxcpath ruta] [-N, --newname nuevonombre] [-p, --newpath nuevaruta] {-e, --ephemeral} [-B, --backingstorage almacenamiento_respaldo] [-s, --snapshot] [-t, --tmpfs] [-K, --keepname] [-M, --keepmac] [-- argumentos_hook]

lxc-copy
{-n, --name nombre} [-P, --lxcpath ruta] {-N, --newname nuevonombre} [-p, --newpath nuevaruta] {-R, --rename}

DESCRIPCIÓN

lxc-copy crea y opcionalmente inicia (efímeros o no efímeros) copias de contenedores existentes.

lxc-copy crea copias de contenedores existentes. Las copias pueden ser clones completos del contenedor original. En este caso, todo el sistema de archivos raíz del contenedor se copia simplemente al nuevo contenedor. O pueden ser instantáneas (snapshots), es decir, copias pequeñas de tipo 'copiar al escribir' (copy-on-write) del contenedor original. En este caso, el almacenamiento de respaldo especificado para la copia debe soportar instantáneas. Actualmente esto incluye btrfs, lvm (los dispositivos lvm no soportan instantáneas de instantáneas.), overlay y zfs.

El almacenamiento de respaldo de la copia será del mismo tipo que el contenedor original. Las instantáneas overlay de contenedores respaldados por directorio están exentas de esta regla.

Cuando se especifica la bandera -e, se crea y se inicia una instantánea efímera del contenedor original. Los contenedores efímeros tendrán lxc.ephemeral = 1 configurado en su archivo de configuración y serán destruidos al apagarse. Cuando se usa -e en combinación con -D, se crea y se inicia una instantánea no efímera del contenedor original. Los contenedores efímeros también pueden colocarse en un tmpfs con la bandera -t. NOTA: ¡Si un contenedor efímero que se coloca en un tmpfs se reinicia, todos los cambios realizados en él se perderán actualmente!

Cuando se especifica -e y no se proporciona un nuevo nombre con -N, se elegirá un nombre aleatorio para la instantánea.

Los contenedores creados e iniciados con -e pueden tener montajes personalizados. Estos se especifican con la bandera -m. Actualmente se soportan dos tipos de montajes: bind y overlay. Los tipos de montaje se especifican como subopciones de la bandera -m y pueden especificarse varias veces separadas por comas. Los montajes overlay se especifican actualmente en el formato -m overlay=/src:/dest. Cuando no se especifica un destino dest, dest será idéntico a src. Los montajes bind de solo lectura se especifican como -m bind=/src:/dest:ro y los montajes bind de lectura/escritura como -m bind=/src:/dest:rw. Los montajes bind de lectura/escritura son los predeterminados y rw puede omitirse cuando se desea un montaje de lectura/escritura. Cuando se omite dest, dest será idéntico a src. Un ejemplo para montajes múltiples sería -m bind=/src1:/dest1:ro,bind=/src2:ro,overlay=/src3:/dest3.

Los montajes, sus opciones y formatos soportados a través de la bandera -m están sujetos a cambios.

OPCIONES

-N,--newname nuevonombre
El nombre para la copia.
-p,--newpath nuevaruta
La ruta para la copia.
-R,--rename
Renombrar el contenedor original.
-s,--snapshot
Crear una instantánea del contenedor original. El almacenamiento de respaldo para la copia debe soportar instantáneas. Actualmente esto incluye btrfs, lvm, overlay y zfs.
-a,--allowrunning
Permitir la creación de una instantánea de un contenedor ya en ejecución. Esto puede causar corrupción de datos o pérdida de datos dependiendo del sistema de archivos y las aplicaciones utilizadas. Usar con precaución.
-F,--foreground
Ejecutar la instantánea en primer plano. La consola de la instantánea se conectará al tty actual. (Esta opción solo puede especificarse en conjunción con -e).
-d, --daemon
Ejecutar la instantánea como un demonio (Este es el modo predeterminado para contenedores efímeros). Como el contenedor ya no tiene tty, si ocurre un error, no se mostrará nada; el archivo de registro se puede usar para verificar el error. (Esta opción solo puede especificarse en conjunción con -e).
-m, --mount tipo_montaje
Especificar un montaje para una instantánea. Los opts para el tipo de montaje pueden ser de tipo {bind, overlay}. Por ejemplo: -m bind=/src:/dest:ro,overlay=/src:/dest (Actualmente, esta opción solo puede especificarse en conjunción con -e).
-t, --tmpfs
Cuando se especifica esta opción, el contenedor efímero se colocará en un tmpfs. NOTA: Reiniciar un contenedor efímero que se encuentra en un tmpfs actualmente causará que todos los cambios realizados en él se pierdan. Esta bandera solo funcionará para contenedores efímeros creados con la bandera -e. El contenedor original, del cual se crea la instantánea efímera, debe almacenarse como un simple directorio.
-B, --backingstorage almacenamiento_respaldo
Especificar el tipo de almacenamiento de respaldo a utilizar para la copia, donde 'almacenamiento_respaldo' es de tipo 'btrfs', 'dir', 'lvm', 'loop', 'overlay', o 'zfs'.
-L, --fssize tamaño [unidad]
Especificar el tamaño para un sistema de archivos 'lvm'.
-K, --keepname
Cuando se especifica esta opción, el nombre de host del contenedor original se conservará para la copia.
-D, --keepdata
Cuando se especifica esta opción con -e, se crea y se inicia un contenedor no efímero.
-M, --keepmac
Cuando se especifica esta opción, la dirección MAC del contenedor original se conservará para la copia.

HOOK DE COPIA

Si el contenedor que se está copiando tiene uno o más lxc.hook.clone especificados, entonces los hooks especificados se llamarán para el nuevo contenedor. Los primeros 3 argumentos pasados al hook de clonación serán el nombre del contenedor, una sección ('lxc') y el tipo de hook ('clone'). Los argumentos adicionales pasados a lxc-copy se pasarán al programa hook comenzando en el argumento 4. La variable de entorno LXC_ROOTFS_MOUNT proporciona la ruta bajo la cual se monta el sistema de archivos raíz del contenedor. La ruta del archivo de configuración se almacena en LXC_CONFIG_FILE, el nuevo nombre del contenedor en LXC_NAME, el nombre del contenedor antiguo en LXC_SRC_NAME, y la ruta o el dispositivo en el que se encuentra el rootfs está en LXC_ROOTFS_PATH.

OPCIONES COMUNES

Estas opciones son comunes a la mayoría de los comandos de lxc.

-?, -h, --help
Mostrar un mensaje de uso más largo de lo normal.
--usage
Mostrar el mensaje de uso
-q, --quiet
silenciar
-P, --lxcpath=RUTA
Usar una ruta alternativa para los contenedores. El valor predeterminado es /var/lib/lxc.
-o, --logfile=ARCHIVO
Salida a un ARCHIVO de registro alternativo. El valor predeterminado es sin registro.
-l, --logpriority=NIVEL

OPCIONES COMUNES

-l, --logpriority=LEVEL
Establece la prioridad de registro en LEVEL. La prioridad de registro predeterminada es ERROR.

Los valores posibles son: FATAL, ALERT, CRIT, WARN, ERROR, NOTICE, INFO, DEBUG, TRACE.

Tenga en cuenta que esta opción establece la prioridad de los eventos que se registran en el archivo de registro alternativo. No tiene efecto en los eventos ERROR que se registran en stderr.

-n, --name=NAME
Utiliza el identificador de contenedor NAME. El formato del identificador de contenedor es una cadena alfanumérica.
--rcfile=FILE
Especifica el archivo de configuración para configurar las funcionalidades de virtualización y aislamiento del contenedor.

Este archivo de configuración, si está presente, se utilizará incluso si ya existe un archivo de configuración en el contenedor creado previamente (a través de lxc-create).

--version
Muestra el número de versión.
