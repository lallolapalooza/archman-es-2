Paquete: lxc

NOMBRE

lxc-stop - detener la aplicación que se ejecuta dentro de un contenedor

SINOPSIS


lxc-stop
{-n nombre} [-W] [-r] [-t tiempo_espera] [-k] [--nokill] [--nolock]

DESCRIPCIÓN

lxc-stop reinicia, apaga limpiamente o mata todos los procesos dentro del contenedor. Por defecto, solicitará un apagado limpio del contenedor enviando lxc.signal.halt (por defecto SIGPWR) al proceso init del contenedor, esperando hasta 60 segundos a que el contenedor se cierre, y luego regresando. Si el contenedor no logra cerrarse limpiamente en 60 segundos, se le enviará lxc.signal.stop (por defecto SIGKILL) para forzar su apagado. Una solicitud de reinicio enviará lxc.signal.reboot (por defecto SIGINT) al proceso init del contenedor.

Las opciones [-W], [-r], [-k] y [--nokill] especifican la acción a realizar. [-W] indica que después de realizar la acción especificada, lxc-stop debe salir inmediatamente, mientras que [-t TIEMPO_ESPERA] especifica la cantidad máxima de tiempo a esperar para que el contenedor complete el apagado o reinicio.

OPCIONES

-r,--reboot
Solicitar un reinicio del contenedor.
-k,--kill
En lugar de solicitar un apagado limpio del contenedor, matar explícitamente todas las tareas en el contenedor. Este es el comportamiento heredado de lxc-stop.
--nokill
Solo solicitar un apagado limpio, no matar las tareas del contenedor si el apagado limpio falla.
--nolock
Esta opción evita el uso de cualquier bloqueo de API de lxc, y solo debe usarse si lxc-stop se cuelga debido a un estado defectuoso del sistema.
-W,--nowait
Simplemente realizar la acción solicitada (reinicio, apagado o matar forzado) y salir.
-t,--timeout TIEMPO_ESPERA
Esperar TIEMPO_ESPERA segundos antes de detener forzosamente el contenedor.

VALOR DE SALIDA

0
El contenedor se detuvo correctamente.
1
Ocurrió un error al detener el contenedor.
2
El contenedor especificado existe pero no estaba en ejecución.

DIAGNÓSTICO

El contenedor no fue encontrado
El contenedor especificado no fue creado previamente con el comando lxc-create.
