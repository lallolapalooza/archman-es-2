NOMBRE

lxc-attach - inicia un proceso dentro de un contenedor en ejecución.

SINOPSIS


lxc-attach
{-n, --name nombre} [-f, --rcfile archivo_config] [-a, --arch arquitectura] [-e, --elevated-privileges privilegios] [-s, --namespaces espacios_de_nombres] [-R, --remount-sys-proc] [--keep-env] [--clear-env] [-v, --set-var variable] [--keep-var variable] [-u, --uid uid] [-g, --gid gid] [-- comando]

DESCRIPCIÓN

lxc-attach ejecuta el comando especificado dentro del contenedor especificado por nombre. El contenedor ya debe estar en ejecución.

Si no se especifica ningún comando, se buscará y ejecutará el shell predeterminado del usuario que ejecuta lxc-attach dentro del contenedor. Esto fallará si no existe dicho usuario dentro del contenedor o si el contenedor no tiene un mecanismo nsswitch que funcione.

Versiones anteriores de lxc-attach simplemente se adjuntaban a los espacios de nombres especificados de un contenedor y ejecutaban un shell o el comando especificado sin asignar previamente un pseudo-terminal. Esto los hacía vulnerables a la falsificación de entrada a través de una llamada ioctl TIOCSTI después de cambiar entre contextos de ejecución de espacio de usuario con diferentes niveles de privilegios. Las versiones más recientes de lxc-attach intentarán asignar un par de descriptores de archivo de pseudo-terminal en el host y adjuntar cualquier descriptor de archivo estándar que se refiera a una terminal al lado del contenedor del pseudo-terminal antes de ejecutar un shell o comando. Tenga en cuenta que si ninguno de los descriptores de archivo estándar se refiere a una terminal, lxc-attach no intentará asignar un pseudo-terminal. En su lugar, simplemente se adjuntará a los espacios de nombres del contenedor y ejecutará un shell o el comando especificado.

OPCIONES

-f, --rcfile archivo_config
Especifica el archivo de configuración para configurar las funcionalidades de virtualización y aislamiento del contenedor.

Este archivo de configuración, si está presente, se utilizará incluso si ya existe un archivo de configuración en el contenedor creado previamente (a través de lxc-create).

-a, --arch arquitectura
Especifica la arquitectura que el kernel debe aparentar tener para el comando ejecutado. Esta opción aceptará la misma configuración que la opción lxc.arch en los archivos de configuración del contenedor, consulte lxc.conf(5). Por predeterminado, se utilizará la arquitectura actual del contenedor en ejecución.
-e, --elevated-privileges privilegios
No reducir privilegios al ejecutar comando dentro del contenedor. Si se especifica esta opción, el nuevo proceso *no* se añadirá a los cgroup(s) del contenedor y no reducirá sus capacidades antes de ejecutarse.

Puede especificar privilegios, en caso de que no desee elevar todos ellos, como una lista separada por barras verticales, por ejemplo CGROUP|LSM. Los valores permitidos son CGROUP, CAP y LSM representando privilegios de cgroup, capacidades y restricciones respectivamente. (El símbolo de barra vertical necesita ser escapado, por ejemplo CGROUP\|LSM o entre comillas, por ejemplo "CGROUP|LSM".)

Advertencia: Esto puede filtrar privilegios al contenedor si el comando inicia subprocesos que permanecen activos después de que el proceso principal que se adjuntó se termina. El (re) inicio de demonios dentro del contenedor es problemático, especialmente si el demonio inicia muchos subprocesos como cron o sshd. Úselo con gran cuidado.

-s, --namespaces espacios_de_nombres
Especifica los espacios de nombres a los que adjuntarse, como una lista separada por barras verticales, por ejemplo NETWORK|IPC. Los valores permitidos son MOUNT, PID, UTSNAME, IPC, USER y NETWORK. Esto permite cambiar el contexto del proceso a, por ejemplo, el espacio de nombres de red del contenedor mientras se conservan los otros espacios de nombres como los del host. (El símbolo de barra vertical necesita ser escapado, por ejemplo MOUNT\|PID o entre comillas, por ejemplo "MOUNT|PID".)

Importante: Esta opción implica -e.

-R, --remount-sys-proc
Cuando se usa -s y no se incluye el espacio de nombres de montaje, esta bandera hará que lxc-attach remonte /proc y /sys para reflejar los contextos de otros espacios de nombres actuales.

Por favor, consulte la sección de Notas para más detalles.

Esta opción se ignorará si se intenta adjuntarse de todos modos al espacio de nombres de montaje.

--keep-env
Mantener el entorno actual para los programas adjuntos. Este es el comportamiento predeterminado actual (a partir de la versión 0.9), pero es probable que cambie en el futuro, ya que esto puede filtrar información indeseable al contenedor. Si confía en que el entorno estará disponible para el programa adjunto, utilice esta opción para asegurar la compatibilidad futura. Además de las variables de entorno actuales, se establecerá container=lxc.
--clear-env
Limpiar el entorno antes de adjuntarse, de modo que ninguna variable de entorno no deseada se filtre al contenedor. La variable container=lxc será el único entorno con el que comenzará el programa adjunto.
-v, --set-var variable
Establece una variable de entorno adicional que es vista por el programa adjunto en el contenedor. Se especifica en el formato "VAR=VALOR", y puede especificarse varias veces.
--keep-var variable
Mantener una variable de entorno especificada. Solo se puede especificar en conjunción con --clear-env, y puede especificarse varias veces.
-u, --uid uid
Ejecuta el comando con el ID de usuario (use valor numérico) uid dentro del contenedor.
--g, --gid gid
Ejecuta el comando con el ID de grupo (use valor numérico) gid dentro del contenedor.

OPCIONES COMUNES

Estas opciones son comunes a la mayoría de los comandos de lxc.

-?, -h, --help
Imprime un mensaje de uso más largo de lo normal.
--usage
Da el mensaje de uso
-q, --quiet
silenciar
-P, --lxcpath=RUTA
Usar una ruta alternativa para el contenedor. La predeterminada es /var/lib/lxc.
-o, --logfile=ARCHIVO
Salida a un ARCHIVO de registro alternativo. La predeterminada es sin registro.
-l, --logpriority=NIVEL
Establece la prioridad del registro a NIVEL. La prioridad de registro predeterminada es ERROR. Los valores posibles son: FATAL, ALERT, CRIT, WARN, ERROR, NOTICE, INFO, DEBUG, TRACE.

Tenga en cuenta que esta opción establece la prioridad de los eventos registrados en el archivo de registro alternativo. No tiene efecto en los eventos de ERROR registrados en stderr.

-n, --name=NOMBRE
Usar el identificador de contenedor NOMBRE. El formato del identificador de contenedor es una cadena alfanumérica.
--rcfile=ARCHIVO
Especifica el archivo de configuración para configurar las funcionalidades de virtualización y aislamiento del contenedor.

Este archivo de configuración, si está presente, se utilizará incluso si ya existe un archivo de configuración en el contenedor creado previamente (a través de lxc-create).

--version
Mostrar el número de versión.

          lxc-attach -n contenedor

lxc-attach(1) — Arch Linux

NAME

lxc-attach

execute a command in a container

SYNOPSIS

lxc-attach [-1234dfpReEghR] [-n container] [-o logfile] [-L logpriority] [-d daemon_timeout] [-s namespace] [-W daemon_path] [-c daemon_timeout_path] [-u uid] [-g gid] [-C chroot_dir] [-r rootfs_to_mount] [-t attach_timeout] [-f config_file] [-a daemon_args] [-w working_dir] [--] [command …]

DESCRIPTION

lxc-attach can be used to execute a command in the namespace(s) of an existing container. This is useful for debugging a container or performing administrative tasks within the context of the container.

By default, lxc-attach attaches to all namespaces associated with the container. This includes the PID, mount, network, UTS, IPC, and Cgroup namespaces.

If no command is specified, lxc-attach will typically spawn a shell within the container's namespace(s).

OPTIONS

-1
Attach to the first available namespace. This is not commonly used.
-2
Attach to the second available namespace. This is not commonly used.
-3
Attach to the third available namespace. This is not commonly used.
-4
Attach to the fourth available namespace. This is not commonly used.
-d
Detach from the terminal after executing the command.
-f config_file
Use the specified config_file for the container.
-g gid
Run the command with the specified group ID. Defaults to the group ID of the container's init process.
-h
Display help information.
-p
Run the command with the same priority as the container's init process.
-R
Remount /proc and /sys to reflect the container's context. This option implies -m and effectively unshares the mount namespace.
-e
Increase capabilities to allow actions that normally require NET_ADMIN.
-E
Do not propagate environment variables into the executed command.
-C chroot_dir
Chroot the command into the specified directory.
-r rootfs_to_mount
Mount the specified rootfs_to_mount as the container's root filesystem.
-t attach_timeout
Set a timeout for the attachment in seconds.
-w working_dir
Set the working directory for the command.
-n container
Attach to the specified container.
-o logfile
Write logs to the specified logfile.
-L logpriority
Set the log priority for logging.
-d daemon_timeout
Set a timeout for the daemon process.
-s namespace
Attach only to the specified namespace (e.g., NETWORK, PID, IPC, UTS, CGROUP).
-W daemon_path
Specify the path to the LXC daemon.
-c daemon_timeout_path
Specify the path for the daemon timeout.
-u uid
Run the command with the specified user ID. Defaults to the UID of the container's init process.
-a daemon_args
Pass additional arguments to the LXC daemon.
--
Marks the end of options, allowing commands with leading hyphens.

COMMON OPTIONS

The following options are common to most lxc commands:

-f config_file
Use the specified config_file for the container.
-o logfile
Write logs to the specified logfile.
-L logpriority
Set the log priority for logging.

EXAMPLES

To restart the cron service of a running Debian container, use

          lxc-attach -n container -- /etc/init.d/cron restart

To deactivate the network link eth1 of a running container that does not have the NET_ADMIN capability, use either the -e option to use increased capabilities, assuming the ip tool is installed:

          lxc-attach -n container -e -- /sbin/ip link delete eth1

Or, alternatively, use the -s to use the tools installed on the host outside the container:

          lxc-attach -n container -s NETWORK -- /sbin/ip link delete eth1

COMPATIBILITY

Attaching completely (including the pid and mount namespaces) to a container requires a kernel of version 3.8 or higher, or a patched kernel, please see the lxc website for details. lxc-attach will fail in that case if used with an unpatched kernel of version 3.7 and prior.

Nevertheless, it will succeed on an unpatched kernel of version 3.0 or higher if the -s option is used to restrict the namespaces that the process is to be attached to to one or more of NETWORK, IPC and UTSNAME.

Attaching to user namespaces is supported by kernel 3.8 or higher with enabling user namespace.

NOTES

The Linux /proc and /sys filesystems contain information about some quantities that are affected by namespaces, such as the directories named after process ids in /proc or the network interface information in /sys/class/net. The namespace of the process mounting the pseudo-filesystems determines what information is shown, not the namespace of the process accessing /proc or /sys.

If one uses the -s option to only attach to the pid namespace of a container, but not its mount namespace (which will contain the /proc of the container and not the host), the contents of /proc will reflect that of the host and not the container. Analogously, the same issue occurs when reading the contents of /sys/class/net and attaching to just the network namespace.

To work around this problem, the -R flag provides the option to remount /proc and /sys in order for them to reflect the network/pid namespace context of the attached process. In order not to interfere with the host's actual filesystem, the mount namespace will be unshared (like lxc-unshare does) before this is done, essentially giving the process a new mount namespace, which is identical to the hosts's mount namespace except for the /proc and /sys filesystems.

Previous versions of lxc-attach suffered a bug whereby a user could attach to a containers namespace without being placed in a writeable cgroup for some critical subsystems. Newer versions of lxc-attach will check whether a user is in a writeable cgroup for those critical subsystems. lxc-attach might thus fail unexpectedly for some users (E.g. on systems where an unprivileged user is not placed in a writeable cgroup in critical subsystems on login.). However, this behavior is correct and more secure.

SECURITY

The -e and -s options should be used with care, as it may break the isolation of the containers if used improperly.
