NOMBRE

luaotfload.conf - Archivo de configuración de Luaotfload

SINOPSIS

  • ./luaotfload{.conf,rc}
  • XDG_CONFIG_HOME/luaotfload/luaotfload{.conf,rc}
  • ~/.luaotfloadrc

DESCRIPCIÓN

El archivo luaotfload.conf contiene opciones de configuración para Luaotfload, un componente de carga y gestión de fuentes para LuaTeX.

EJEMPLO

Un pequeño archivo de configuración de Luaotfload con pocas personalizaciones podría verse así:

[db]
    formats = afm,ttf
    compress = false
[misc]
    termwidth = 60
[run]
    log-level = 6

Esto hará que Luaotfload ignore todos los archivos de fuentes excepto los archivos de fuentes binarias PostScript con un archivo AFM coincidente y las fuentes Truetype. Además, se volcará un archivo de índice sin comprimir, que será mucho más grande que el índice predeterminado comprimido con gzip. El ancho del terminal se trunca a 60 caracteres, lo que influye en la salida detallada durante la indexación. Finalmente, la verbosidad aumenta enormemente: cada archivo de fuente que se procesa se imprimirá en la salida estándar en una línea separada, junto con mucha otra información.

Para observar la diferencia en el comportamiento, guarda el fragmento anterior en ./luaotfload.conf y actualiza el índice de fuentes:

luaotfload-tool --update --force

La configuración actual se puede escribir en disco usando luaotfload-tool:

luaotfload-tool --dumpconf > luaotfload.conf

El resultado puede usarse como archivo de configuración.

SINTAXIS

La sintaxis del archivo de configuración sigue el formato INI común. Para una descripción más detallada, consulta la sección “ARCHIVO DE CONFIGURACIÓN” de git-config(1). A continuación se presenta una breve lista de reglas:

  • Las líneas en blanco y las líneas que comienzan con un punto y coma (;) se ignoran.
  • Un archivo de configuración se divide en secciones que se declaran especificando el título de la sección entre corchetes en una línea separada:
[nombre-de-seccion]
... contenido de la sección ...
•
Las secciones consisten en una o más asignaciones de variables de la forma nombre-variable = valor Por ejemplo:
[foo]
    bar = baz
    quux = xyzzy
    ...
•
Los nombres de sección y variable solo pueden contener letras mayúsculas y minúsculas, así como guiones (-).

VARIABLES

Las variables pertenecen a una sección de configuración y sus valores deben ser de un tipo específico. Algunas tienen restricciones adicionales. Por ejemplo, la “función de retorno de llamada de color” debe ser una cadena de uno de los valores post_linebreak_filter, pre_linebreak_filter o pre_output_filter, definidos en la sección run del archivo de configuración.

Actualmente, la configuración se organiza en cuatro secciones:

db
Opciones relacionadas con el índice de fuentes.
misc
Opciones sin una categoría claramente definida.
paths
Configuración de rutas y nombres de archivo.
run
Opciones que controlan el comportamiento en tiempo de ejecución de Luaotfload.

La lista de variables válidas, las secciones a las que pertenecen y su tipo se detallan a continuación. Los tipos representan los tipos de Lua a los que deben poder convertirse los valores; se abrevian de la siguiente manera: s para el tipo string (cadena), n para number (número), b para boolean (booleano). Un valor de nil significa que la variable no está establecida.

Sección db

variable tipo predeterminado
compress b true
designsize-dimen b bp
formats s "otf,ttf,ttc"
location-precedence s "system,texmf,local
max-fonts n 2^51
scan-local b false
skip-read b false
strip b true
update-live b true

El indicador compress determina si el índice de fuentes (generalmente luaotfload-names.lua[.gz] se almacenará en formato comprimido. Si no se establece, es equivalente a pasar --no-compress a luaotfload-tool. Dado que el archivo se crea solo por conveniencia y no tiene ningún efecto en el comportamiento en tiempo de ejecución de Luaotfload, el indicador debe permanecer establecido. La mayoría de los editores vienen con soporte zlib de todos modos.

La configuración designsize-dimen se aplica al buscar fuentes de familias con tamaños de diseño. En Opentype, estos se especifican como "decipuntos", donde un decipunto equivale a diez "big points" de estilo DTP. Al indexar fuentes, estos valores se convierten a sp. Para tratar los valores como si hubieran sido especificados en puntos TeX o puntos Didot, establezca designsize-dimen en pt o dd.

La lista de formats debe ser una secuencia separada por comas de cadenas que contengan uno o más de estos elementos:

  • otf (formato OpenType),
  • ttf y ttc (formato TrueType),
  • afm (Adobe Font Metrics),

Corresponde aproximadamente a la opción --formats de luaotfload-tool. Los miembros inválidos o duplicados se ignoran; si la lista no contiene identificadores útiles, se utilizará la lista predeterminada "otf,ttf,ttc".

La variable location-precedence selecciona dónde y en qué orden luaotfload busca fuentes. Las fuentes en ubicaciones anteriores tienen preferencia. Las tres ubicaciones admitidas son system para directorios de fuentes específicos del sistema, texmf para fuentes que forman parte de la distribución TeX y local para fuentes locales.

La variable max-fonts determina después de procesar cuántos archivos de fuentes finalizará la búsqueda el escáner de fuentes. Esto es útil para depurar problemas con el índice de fuentes y tiene el mismo efecto que la opción --max

-fuentes a luaotfload-tools.

El indicador scan-local, si está establecido, incorporará el directorio de trabajo actual como una ubicación de búsqueda de fuentes. Nota: Esto potencialmente ralentizará el procesamiento del documento porque un índice de fuentes con fuentes locales no se guardará en disco, por lo que estas fuentes tendrán que ser reindexadas cada vez que se genere el documento. Establecer scan_local a false es lo mismo que eliminar local de location-precedence.

El indicador skip-read solo es útil para depuración: hace que Luaotfload omita la lectura de fuentes. La información de la fuente para reconstruir el índice se toma del existente en ese momento.

Anular el indicador strip evita que Luaotfload elimine datos del índice que solo son útiles al procesar archivos de fuentes. Nota: esto puede aumentar significativamente el tamaño de los archivos de índice y no tiene efecto en el comportamiento en tiempo de ejecución.

Si update-live está establecido, Luaotfload recargará la base de datos si no puede encontrar una fuente solicitada. Aquellos que prefieren actualizar manualmente usando luaotfload-tool deberían anular este indicador. Esta opción no afecta a las reconstrucciones debidas a discrepancias de versión.

Sección default-features

Por defecto, Luaotfload habilita el modo node y elige las características de fuente predeterminadas que se prescriben en el estándar OpenType. Este comportamiento puede ser anulado en la sección default-features. Los valores predeterminados globales que se aplicarán para todos los scripts se pueden establecer a través de la opción global, y otros por el script al que se aplicarán. Por ejemplo, una configuración de

[default-features]
    global = mode=base,color=0000FF
    dflt   = smcp,onum

forzaría el modo *base*, teñiría todas las fuentes de azul y activaría las mayúsculas pequeñas y las cifras de texto globalmente. Las características se especifican como una lista separada por comas de variables o pares de variable-valor. Las variables sin un valor explícito se establecen en true.

Sección misc

variable tipo por defecto
statistics b false
termwidth n nil
version s <versión de Luaotfload>
keepnames b true

Con statistics habilitado, se recopilarán estadísticas adicionales durante la creación del índice y se adjuntarán al archivo de índice. Luego, se podrá consultar en el extremo de Lua o inspeccionar leyendo el propio archivo.

El valor de termwidth, si está establecido, anula el valor obtenido al consultar las propiedades de la terminal en la que se ejecuta Luatex. Esto es útil si el motor se ejecuta con shell_escape deshabilitado y no se pueden recuperar las dimensiones reales de la terminal.

El valor de version se deriva de la cadena de versión codificada en el código fuente de Luaotfload. Anule bajo su propio riesgo.

La opción keepnames decide si el cargador de fuentes de ConTeXt debe conservar los nombres que considera inútiles o si deben ser descartados. Esta opción solo tiene efecto después de que las cachés de fuentes se regeneren.

Sección paths

variable tipo por defecto
cache-dir s "fonts"
names-dir s "names"
index-file s "luaotfload-names.lua"
lookups-file s "luaotfload-lookup-cache.lua"

Las rutas cache-dir y names-dir determinan el subdirectorio dentro del subárbol de Luaotfload del directorio luatex-cache donde se almacenarán la caché de fuentes y el índice de fuentes, respectivamente.

Dentro del directorio de índice, los nombres del archivo de índice y la caché de búsqueda de fuentes se derivarán de los valores respectivos de index-file y lookups-file. Esta es la base del nombre de archivo para la versión compilada en bytecode, así como, para el índice, la versión comprimida con gzip.

Sección run

variable tipo por defecto
anon-sequence s "tex,path,name"
color-callback s "post_linebreak_filter"
definer s "patch"
log-level n 0
resolver s "cached"
fontloader s "default"
default_dvi_driver s "dvisvgm"

Las búsquedas de fuentes no calificadas se tratan con el mecanismo flexible "anónimo". Esto implica una cadena de búsquedas aplicadas sucesivamente hasta que la primera arroje una coincidencia. Por defecto, la búsqueda primero buscará fuentes TFM utilizando la biblioteca Kpathsea. Si esto no tuvo éxito, se intenta interpretar la solicitud como una ruta absoluta (como la sintaxis [/ruta/a/fuente/foo.ttf]) o un nombre de archivo (file:foo.ttf). Finalmente, la solicitud se interpreta como un nombre de fuente y se recupera del índice (name:Foo Regular). Este comportamiento se puede configurar especificando una lista como valor para anon-sequence. Los elementos disponibles son tex, path, name —que representan las búsquedas descritas anteriormente, respectivamente— y file para buscar un nombre de archivo pero no una ruta absoluta. Además, las búsquedas my son valores válidos, pero solo deben usarse desde dentro de documentos TeX, ya que no hay forma de personalizar una búsqueda my en la línea de comandos.

La opción color-callback determina la etapa en la que se colorearán las fuentes definidas con una característica color=xxyyzz. Por defecto, esto ocurre en un post_linebreak_filter, pero alternativamente se pueden elegir pre_linebreak_filter o pre_output_filter, lo que es más rápido pero puede producir resultados inconsistentes. El pre_output_filter solía ser el predeterminado en la serie 1.x de Luaotfload, mientras que las versiones posteriores hasta la 2.5 inclusive se conectaban al pre_linebreak_filter, lo que naturalmente no afectaba a ningún glifo insertado durante la guionización. Ambos se conservan como opciones para restaurar el comportamiento anterior si es necesario.

El definer permite cambiar la devolución de llamada define_font. Aparte del patch predeterminado, también se puede elegir el generic que viene con el cargador de fuentes normal. Tenga en cuenta que esto podría romper herramientas como Fontspec que dependen de la devolución de llamada patch_font proporcionada por Luaotfload para realizar correcciones importantes en los datos de la fuente.

El backend del cargador de fuentes se puede seleccionar estableciendo el valor de fontloader. Las opciones más importantes son default, que cargará el cargador de fuentes dedicado de Luaotfload, y reference, el paquete original enviado con Luaotfload. Aparte de esos, se puede especificar un nombre de archivo accesible a través de kpathsea.

Alternativamente, los archivos individuales que componen el cargador de fuentes se pueden cargar directamente. Aunque menos eficiente, esto ayuda en gran medida a la depuración, ya que los mensajes de error harán referencia a los números de línea reales de los archivos fuente y los comentarios explicativos no se eliminarán. Actualmente, hay tres estrategias de carga distintas disponibles: unpackaged cargará el lote que forma parte de Luaotfload. Estos contienen el mismo código fuente a partir del cual se ha compilado el cargador de fuentes de referencia. Otra opción, context, intentará cargar los mismos archivos por sus nombres en el formato Contexto desde la ruta de búsqueda. NAME

luaotfload.conf - configuration file for luaotfload

SYNOPSIS

luaotfload.conf, luaotfloadrc

DESCRIPTION

Luaotfload uses configuration files to set internal variables. This man page describes the syntax of these files and the available variables.

A configuration file is a sequence of assignments like variable = value, comments, or directives. Comments start with a hash character (#) and run until the end of the line. Whitespace around assignments is ignored.

The value of the main_font directive can be a string or a list of strings, in which case the first one that can be found is used. This directive is useful when the system font configuration is not enough or when you want to ensure that a certain font is loaded.

The fontdir directive may be used to add directories to the search path for fonts. If the argument is a list of strings, each string is added to the search path.

The modules directive takes a list of module names that are loaded when the configuration file is processed. This is useful for enabling features of luaotfload that are not enabled by default. Luaotfload also loads some modules automatically, depending on the context it is used in. See the Luaotfload manual for details.

The scripts directive takes a list of file names. These files are loaded and executed by Luaotfload in the given order. This can be used to implement custom font loading logic or to tweak the behavior of luaotfload.

The pattern directive is a convenient way to load other configuration files that match a given shell-style pattern. For example, pattern = {"conf.d/*.conf"} will load all files ending in .conf in the conf.d subdirectory.

The texmf directive can be used to specify additional directories where luaotfload should look for font files. Luaotfload uses the kpathsea library to search for files in these directories. This is useful when fonts are installed in non-standard locations. The value can be a single string or a list of strings. Note that this directive is less flexible than the context directive, because it relies on kpathsea's internal mechanism of searching for files. For more fine-grained control over the search path, consider using the context directive instead.
A third option is to use context with a colon to specify a directory prefix where the TEXMF is located that the files should be loaded from, e. g. context:~/context/tex/texmf-context. This can be used when referencing another distribution like the Context minimals that is installed under a different path not indexed by kpathsea.

The value of log-level sets the default verbosity of messages printed by Luaotfload. Only messages defined with a verbosity of less than or equal to the supplied value will be output on the terminal. At a log level of five Luaotfload can be very noisy. Also, printing too many messages will slow down the interpreter due to line buffering being disabled (see setbuf(3)).

The resolver setting allows choosing the font name resolution function: With the default value cached Luaotfload saves the result of a successful font name request to a cache file to speed up subsequent lookups. The alternative, normal circumvents the cache and resolves every request individually. (Since to the restructuring of the font name index in Luaotfload 2.4 the performance difference between the cached and uncached lookups should be marginal.)

When luaotfload is used in DVI mode, the default_dvi_driver option determines how OpenType fonts are represented in the DVI output. In most cases the default value dvisvgm should be set, it uses a format supported by multiple backends including dvipdfmx and dvisvgm which uses GIDs to identify characters. Setting this to xdvipsk uses an unstable internal format instead which will change depending on the luaotfload, engine, or font version. No one should rely on the mapping between DVI character codes and font glyphs in this mode unless they tightly control all involved versions and are deeply familiar with the implementation.

EXAMPLE

A simple configuration file:

# Load specific fonts
main_font = "Latin Modern Roman"
fontdir = "/usr/local/share/fonts"

# Load additional modules
modules = { "features.default", "opentype.russian" }

# Set log level
log-level = 3

SYNTAX

The configuration file is parsed by the Lua interpreter. The syntax is essentially Lua syntax, but with some simplifications. Assignments are made using the equals sign (=). Lists are enclosed in curly braces ({}) and separated by commas (,). Strings are enclosed in double quotes ("").

variable
The name of the variable to set. Currently supported variables are: main_font, fontdir, modules, scripts, pattern, texmf, context, log-level, resolver, default_dvi_driver.
=
The assignment operator.
value
The value to assign to the variable. This can be a string, a list of strings, or a number, depending on the variable.
#
Start of a comment. The rest of the line is ignored.

VARIABLES

main_font
Specifies the main font to be used. Can be a string or a list of strings.
fontdir
Adds directories to the font search path. Can be a string or a list of strings.
modules
Loads additional modules. Expects a list of strings.
scripts
Executes Lua scripts. Expects a list of file names (strings).
pattern
Loads other configuration files matching a pattern. Expects a list of strings.
texmf
Specifies additional directories for TEXMF. Can be a string or a list of strings.
context
Specifies a directory prefix for TEXMF. Can be a string.
log-level
Sets the log verbosity level. Expects a number.
resolver
Sets the font name resolver. Can be cached or normal.
default_dvi_driver
Sets the default DVI driver. Can be dvisvgm or xdvipsk.

FILES

Luaotfload only processes the first configuration file it encounters at one of the search locations. The file name may be either luaotfload.conf or luaotfloadrc, except for the dotfile in the user’s home directory which is expected at ~/.luaotfloadrc.

Configuration files are located following a series of steps. The search terminates as soon as a suitable file is encountered. The sequence of locations that Luaotfload looks at is

i.
The current working directory of the LuaTeX process.
ii.
The subdirectory luaotfload/ inside the XDG configuration tree, e. g. /home/oenothea/config/luaotfload/.
iii.
The dotfile.
iv.
The TEXMF (using kpathsea).
