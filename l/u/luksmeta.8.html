NOMBRE

luksmeta - Utilidad para almacenar metadatos en una cabecera LUKSv1

SINOPSIS

luksmeta test -d DISPOSITIVO

luksmeta nuke -d DISPOSITIVO [-f]

luksmeta init -d DISPOSITIVO [-f] [-n]

luksmeta show -d DISPOSITIVO [-s RANURA]

luksmeta save -d DISPOSITIVO [-s RANURA] -u UUID < DATOS

luksmeta load -d DISPOSITIVO -s RANURA [-u UUID] > DATOS

luksmeta wipe -d DISPOSITIVO -s RANURA [-u UUID] [-f]

DESCRIPCIÓN

La utilidad luksmeta permite a un administrador almacenar metadatos en el espacio entre el final de la cabecera LUKSv1 y el inicio de los datos cifrados. Esto es útil para almacenar datos que están disponibles antes de que el volumen sea desbloqueado, generalmente para su uso durante el proceso de desbloqueo del volumen.

Los metadatos se almacenan en una serie de ranuras de tipo UUID, permitiendo múltiples bloques de metadatos. Aunque las ranuras de luksmeta están inspiradas en las ranuras LUKS, son funcionalmente independientes y comparten solo una relación casual. Las ranuras simplemente proporcionan una pista de que un bloque de metadatos dado está asociado con una contraseña LUKSv1 específica (en una ranura con el mismo número). Sin embargo, luksmeta en sí mismo es indiferente a la relación entre una ranura LUKSv1 y la ranura luksmeta con número correspondiente, con una excepción (detallada a continuación).

Después de inicializar un volumen LUKSv1 usando cryptsetup(8), también debe ser inicializado para el almacenamiento de metadatos por luksmeta init. Una vez completado esto, el dispositivo está listo para almacenar metadatos.

Los datos se pueden escribir en una ranura usando luksmeta save o leer de una ranura usando luksmeta load. También puedes borrar los datos en una ranura existente usando luksmeta wipe o consultar las ranuras usando luksmeta show.

GENERACIÓN DE UUID

A menudo se asume que guardar metadatos en una ranura requiere un UUID específico o que existe un registro oficial de tipos de UUID. Esto es incorrecto.

UUID significa Identificador Único Universal (Universally Unique IDentifier). Los UUID son un tipo de dato estandarizado y ampliamente utilizado para la identificación sin un registro central. Para los estándares relevantes, consulta ISO 9834-8:2005 y RFC 4122.

Los UUID son lo suficientemente grandes como para que la colisión sea prácticamente imposible. Así que si tu aplicación quiere almacenar datos en una ranura luksmeta, simplemente genera tu propio UUID y úsalo consistentemente para referirte a tu tipo de datos. Si tienes múltiples tipos de datos, siéntete libre de generar múltiples UUID.

La forma más fácil de generar un UUID es usar uuidgen(1). Sin embargo, cualquier generador de UUID compatible será suficiente.

INICIALIZACIÓN

Antes de leer o escribir metadatos, el dispositivo de bloque LUKSv1 debe ser inicializado para el almacenamiento de metadatos. Tres comandos ayudan en este proceso: luksmeta test, luksmeta nuke y luksmeta init.

El comando luksmeta test simplemente comprueba un dispositivo de bloque existente para ver si está inicializado para el almacenamiento de metadatos. Este comando no proporciona ninguna salida, así que asegúrate de comprobar su código de retorno (ver abajo).

El comando luksmeta nuke pondrá a cero (borrará) todo el espacio de la cabecera LUKSv1. Dado que esta operación es destructiva, se requerirá la confirmación del usuario antes de borrar el espacio, a menos que se proporcione la opción -f.

El comando luksmeta init inicializa el dispositivo de bloque LUKSv1 para el almacenamiento de metadatos. Este proceso borrará cualquier dato en el espacio de la cabecera LUKSv1. Por esta razón, este comando requerirá la confirmación del usuario antes de escribir cualquier dato, a menos que se proporcione la opción -f. Nota que este comando tiene éxito sin ninguna modificación si el dispositivo ya está inicializado. Si deseas forzar la creación de un estado de inicialización limpio, puedes especificar la opción -n para borrar el espacio de la cabecera LUKSv1 antes de la inicialización (pero después de la confirmación del usuario).

ESTADO DE LOS METADATOS

El comando luksmeta show muestra el estado actual de las ranuras en el dispositivo de bloque LUKSv1. Si no se especifica ninguna ranura, imprime una tabla que consta del número de ranura, el estado de la ranura LUKSv1 correspondiente y el UUID de los datos almacenados en la ranura luksmeta (o "vacío" si no hay datos almacenados). Si se especifica una ranura, este comando simplemente imprime el UUID de los datos en la ranura. Si la ranura no contiene datos, no imprime nada.

GESTIÓN DE METADATOS

La gestión de los metadatos en las ranuras se realiza con tres comandos: luksmeta save, luksmeta load y luksmeta wipe. Estos comandos escriben metadatos en una ranura, leen metadatos de una ranura y borran metadatos en una ranura, respectivamente.

El comando luksmeta save lee metadatos de la entrada estándar y los escribe en la ranura especificada usando el UUID especificado. Si no se especifica ninguna ranura, luksmeta buscará el primer número de ranura para el cual la ranura LUKSv1 está inactiva y la ranura luksmeta está vacía. Esto representa la única correlación oficial entre las ranuras LUKSv1 y las ranuras luksmeta. En este caso, los metadatos se escriben en la primera ranura aplicable usando el UUID especificado y el número de ranura se imprime en la salida estándar. En cualquier caso, este comando nunca sobrescribirá datos existentes. Para reemplazar datos en una ranura, necesitarás ejecutar luksmeta wipe antes de luksmeta save.

El comando luksmeta load lee datos de la ranura especificada y los escribe en la salida estándar. Si se especifica un UUID, el comando verificará que el UUID asociado con los metadatos en la ranura coincida con el UUID especificado. Esta verificación de tipo ayuda a asegurar que siempre recibas el tipo de datos que esperas como salida. Si los UUID no coinciden, el comando fallará.

El comando luksmeta wipe borra los datos de la ranura dada. Si se especifica un UUID, el comando verificará que el UUID asociado con los metadatos en la ranura coincida con el UUID especificado. Esta verificación de tipo ayuda a asegurar que solo borras los datos que tenías la intención de borrar. Debido a que esta es una operación destructiva, este comando requerirá la confirmación del usuario antes de borrar cualquier dato, a menos que se proporcione la opción -f. Nota que este comando tiene éxito si intentas borrar una ranura que ya está vacía.

ADVERTENCIAS

La cantidad de almacenamiento en el espacio de la cabecera LUKSv1 es extremadamente limitada. También varía según la configuración utilizada por LUKSv1 en el momento de la inicialización del dispositivo. En algunas configuraciones LUKSv1, no hay suficiente espacio ni siquiera para todas las ranuras de metadatos, incluso en el tamaño de ranura más pequeño posible.

Durante el diseño de esta utilidad, consideramos probable que los usuarios quisieran reducir el número de ranuras utilizables a cambio de más espacio de almacenamiento en las ranuras utilizadas. Para proporcionar esta flexibilidad, la cantidad de almacenamiento disponible por ranura es dinámica. Dicho simplemente, las ranuras no tienen un tamaño fijo. Esto significa que es posible (e incluso bastante probable) encontrar un error durante luksmeta save indicando que no hay espacio suficiente.

Este error no es un error de programación. Si encuentras este error, probablemente significa que todo el espacio está siendo consumido por las ranuras ya escritas o que los metadatos que intentas escribir simplemente no caben.

Puedes intentar resolver este problema llamando a luksmeta wipe en ranuras que ya no estén en uso. Esto liberará el espacio de almacenamiento para ser utilizado por otras ranuras. Ten en cuenta que luksmeta no realiza desfragmentación actualmente, ya que el número de bloques utilizables es bastante limitado. Puedes intentar evitar esto manualmente extrayendo todos los datos de las ranuras, borrando las ranuras y volviéndolas a cargar en orden. Sin embargo, esta operación es potencialmente peligrosa y debe realizarse con mucho cuidado.

OPCIONES

•-d DISPOSITIVO, --device=DISPOSITIVO : El dispositivo en el que realizar la operación.
•-s RANURA, --slot=RANURA : El número de ranura en el que realizar la operación.
•-u UUID, --uuid=UUID : El UUID a asociar con la operación.
•-f, --force : Suprime forzadamente la

VALORES DE RETORNO

Este comando utiliza los valores de retorno definidos por sysexit.h. Los siguientes son errores generales cuyo significado es compartido por todos los comandos luksmeta:

•EX_OK : La operación fue exitosa.
•EX_OSERR : Ocurrió un error indefinido del sistema operativo.
•EX_USAGE : El programa fue llamado con parámetros inválidos.
•EX_IOERR : Ocurrió un error de E/S al escribir en el dispositivo.
•EX_OSFILE : El dispositivo no está inicializado o está corrupto.
•EX_NOPERM : El usuario no concedió permiso durante la confirmación.
•EX_NOINPUT : Ocurrió un error al leer de la entrada estándar.
•EX_DATAERR : El UUID especificado no coincide con el UUID de la ranura.
•EX_CANTCREAT : No hay suficiente espacio en la cabecera LUKSv1.

Además, luksmeta save devolverá EX_UNAVAILABLE cuando intentes guardar datos en una ranura que ya esté en uso. De manera similar, luksmeta load devolverá EX_UNAVAILABLE cuando intentes leer de una ranura vacía.

EJEMPLOS

Destruye todos los datos (incluidos los datos LUKSMeta) en el espacio de la cabecera LUKSv1 y la inicializa para el almacenamiento de LUKSMeta:

$ luksmeta init -n -f -d /dev/sdz

Si ya está inicializado, no hace nada. De lo contrario, destruye todos los datos que no sean LUKSMeta en el espacio de la cabecera LUKSv1 y la inicializa para el almacenamiento de LUKSMeta:

$ luksmeta init -f -d /dev/sdz

Escribe algunos datos en una ranura:

$ UUID=*uuidgen*
$ echo $UUID
31c25e3b-b8e2-4eaa-a427-23aa882feef2
$ echo "Hola, Mundo" | luksmeta save -d /dev/sdz -s 0 -u $UUID

Lee los datos de vuelta:

$ luksmeta load -d /dev/sdz -s 0 -u $UUID
Hola, Mundo

Borra los datos de la ranura:

$ luksmeta wipe -d /dev/sdz -s 0 -u $UUID

Borra todo rastro de LUKSMeta:

$ luksmeta nuke -f -d /dev/sdz
