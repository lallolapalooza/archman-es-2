NOMBRE

lf - gestor de archivos de terminal

SINOPSIS

lf [-comando comando] [-config ruta] [-cpuprofile ruta] [-doc] [-help] [-last-dir-path ruta] [-log ruta] [-memprofile ruta] [-print-last-dir] [-print-selection] [-remote comando] [-selection-path ruta] [-server] [-single] [-version] [ruta-cd-o-seleccionar]

DESCRIPCIÓN

lf es un gestor de archivos de terminal.

El código fuente se puede encontrar en el repositorio en https://github.com/gokcehan/lf

Esta documentación se puede leer desde la terminal usando lf -doc o en línea en https://github.com/gokcehan/lf/blob/master/doc.md También puedes usar el comando help (por defecto <f-1>) dentro de lf para ver la documentación en un paginador. Una página man con el mismo contenido también está disponible en el repositorio en https://github.com/gokcehan/lf/blob/master/lf.1

OPCIONES

ARGUMENTOS POSICIONALES

ruta-cd-o-seleccionar
Establece la ubicación de inicio. Si ruta es un directorio, comienza allí. Si es un archivo, comienza en el directorio padre del archivo y selecciona el archivo. Cuando no se proporciona ninguna ruta, lf usa el directorio actual. Solo acepta un argumento.

OPCIONES META

-doc
Muestra la documentación de lf (mismo contenido que este archivo) y sale.
-help
Muestra el uso de la línea de comandos y sale.
-version
Muestra información de la versión y sale.

INICIO Y CONFIGURACIÓN

-comando comando
Ejecuta comando durante la inicialización del cliente (es decir, después de leer la configuración, antes de on-init). Para ejecutar más de un comando, puedes usar la bandera -comando varias veces o pasar varios comandos a la vez uniéndolos con ";".
-config ruta
Usa el archivo de configuración en ruta en lugar de las ubicaciones de búsqueda normales. Esto solo afecta a qué lfrc se lee al inicio.

INTEGRACIÓN DE SHELL

-print-last-dir
Imprime el último directorio en la salida estándar cuando lf sale. Esto se puede usar para que lf cambie el directorio de trabajo de tu shell. Ver CAMBIO DE DIRECTORIO para más detalles.
-last-dir-path ruta
Igual que -print-last-dir, pero escribe el directorio en ruta en lugar de la salida estándar.
-print-selection
Imprime los archivos seleccionados en la salida estándar al abrir un archivo en lf. Esto se puede usar para usar lf como un diálogo de "abrir archivo". Primero, selecciona los archivos que deseas pasar a otro programa. Luego, confirma la selección abriendo un archivo. Esto hace que lf se cierre y imprima la selección. Cerrar lf prematuramente descarta la selección.
-selection-path ruta
Igual que -print-selection, pero escribe la lista separada por saltos de línea en ruta en lugar de la salida estándar.

SERVIDOR

-remote comando
Envía comando al servidor en ejecución (por ejemplo, send, query o quit). Ver COMANDOS REMOTOS para más detalles.
-server
Inicia explícitamente el proceso del servidor (sin interfaz gráfica). Se ejecuta en primer plano y escribe los registros del servidor en la salida de error estándar (o el archivo establecido con -log). Los clientes inician automáticamente un servidor si no hay ninguno en ejecución, a menos que se use -single.
-single
Inicia un cliente independiente sin servidor. Deshabilita el control remoto.

DIAGNÓSTICOS

-log ruta
Añade mensajes de registro en tiempo de ejecución a ruta.
-cpuprofile ruta
Escribe un perfil de CPU en ruta. El perfil puede ser usado por go tool pprof.
-memprofile ruta
Escribe un perfil de memoria en ruta. El perfil puede ser usado por go tool pprof.

EJEMPLOS

Usa lf para seleccionar archivos (ocultando ciertos tipos de archivo):

lf -command 'set nohidden' -command 'set hiddenfiles "*mp4:*pdf:*txt"' -print-selection

Otro sofisticado diálogo de "abrir archivo" centrado en el diseño:

lf -command 'set nopreview; set ratios 1; set drawbox; set promptfmt "Seleccionar archivos [%w] %S q: cancelar, l: confirmar"' -print-selection

Abre Descargas y establece sortby e info a la fecha de creación:

lf -command 'set sortby btime; set info btime' ~/Downloads

Evita temporalmente que lf modifique el historial de comandos:

lf -command 'set nohistory'

Usa la configuración predeterminada y registra la sesión actual:

lf -config /dev/null -log /tmp/lf.log

Forzar el cierre del servidor:

lf -remote 'quit!'

Hereda el directorio de trabajo de lf en tu shell:

cd "$(lf -print-last-dir)"

CONFIGURACIÓN

Esta sección muestra información sobre opciones para personalizar el comportamiento. El carácter : se usa como separador para las opciones de lista []int y []string.

anchorfind (bool) (predeterminado true)

Cuando esta opción está habilitada, el comando find comienza a coincidir patrones desde el principio de los nombres de archivo, de lo contrario, puede coincidir en una posición arbitraria.

autoquit (bool) (predeterminado true)

Sale automáticamente del servidor cuando no quedan clientes conectados.

borderfmt (string) (predeterminado \033[0m)

Cadena de formato de los caracteres de dibujo de cajas habilitados por la opción drawbox.

cleaner (string) (predeterminado ``) (no se llama si está vacío)

Establece la ruta de un archivo de limpieza. El archivo debe ser ejecutable. Este archivo se llama si la vista previa está habilitada, el previsualizador está configurado y el archivo seleccionado previamente tiene la caché de vista previa deshabilitada. Los siguientes argumentos se pasan al archivo: (1) nombre de archivo actual, (2) ancho, (3) alto, (4) posición horizontal, (5) posición vertical del panel de vista previa y (6) nombre del siguiente archivo a previsualizar, respectivamente. La limpieza de vista previa se deshabilita cuando el valor de esta opción se deja vacío.

copyfmt (string) (predeterminado \033[7;33m)

Cadena de formato del indicador para archivos que se copiarán.

cursoractivefmt (string) (predeterminado \033[7m), cursorparentfmt (string) (predeterminado \033[7m), cursorpreviewfmt (string) (predeterminado \033[4m)

Cadenas de formato para resaltar el cursor. cursoractivefmt se aplica en el panel del directorio actual, cursorparentfmt se aplica en paneles que muestran los padres del directorio actual, y cursorpreviewfmt se aplica en paneles que previsualizan directorios.

El valor predeterminado es hacer que el cursor activo y el cursor del directorio padre sean invertidos. El cursor de vista previa está subrayado.

Algunas otras posibilidades a considerar para los cursores de vista previa o padre: una cadena vacía para no tener cursor, \033[7;2m para texto invertido atenuado (la visibilidad varía según la terminal), \033[7;90m para texto invertido con fondo gris (también conocido como "negro brillante").

Si la cadena de formato contiene los caracteres %s, se interpreta como una cadena de formato para fmt.Sprintf. Dicha cadena debe terminar con la secuencia de reinicio de la terminal. Por ejemplo, \033[4m%s\033[0m tiene el mismo efecto que \033[4m.

cutfmt (string) (predeterminado \033[7;31m)

Cadena de formato del indicador para archivos que se cortarán.

dircounts (bool) (predeterminado false)

Cuando esta opción está habilitada, los tamaños de los directorios muestran el número de elementos dentro en lugar del tamaño total del directorio, lo que requiere ser calculado para cada directorio usando calcdirsize. Esta información necesita ser calculada leyendo el directorio y contando los elementos internos. Por lo tanto, esta opción está deshabilitada por defecto por razones de rendimiento. Esta opción solo tiene efecto cuando info tiene un campo size y el panel es lo suficientemente ancho como para mostrar la información. Se cuentan como máximo 999 elementos por directorio, y los directorios más grandes se muestran como 999+.

dirfirst (bool) (predeterminado true)

Muestra los directorios primero antes que los archivos regulares. Con dircounts habilitado, la ordenación por size siempre separa los directorios y los archivos, independientemente de dirfirst.

dironly (bool) (predeterminado false)

Muestra solo directorios.

dirpreviews (bool) (predeterminado false)

Si está habilitado, los directorios también se pasarán al script de vista previa. Esto permite vistas previas personalizadas para directorios.

drawbox (bool) (predeterminado false)

Dibuja cuadros alrededor de los paneles con caracteres de dibujo de caja.

dupfilefmt (string) (predeterminado %f.~%n~)

Cadena de formato del nombre del archivo al crear archivos duplicados. Con el formato predeterminado, copiar un archivo abc.txt al mismo directorio resultará en un archivo duplicado llamado abc.txt.~1~. Se proporcionan expansiones especiales: %f como el nombre del archivo, %b para el nombre base (nombre del archivo sin extensión), %e como la extensión (incluido el punto) y %n como el número de duplicados.

errorfmt (string) (predeterminado \033[7;31;47m)

Cadena de formato de los mensajes de error que se muestran en la línea de mensajes inferior.

Si la cadena de formato contiene los caracteres %s, se interpreta como una cadena de formato para fmt.Sprintf. Dicha cadena debe terminar con la secuencia de reinicio del terminal. Por ejemplo, \033[4m%s\033[0m tiene el mismo efecto que \033[4m.

filesep (string) (predeterminado \n)

Separador de archivos utilizado en las variables de entorno fs, fv y fx.

filtermethod (string) (predeterminado text)

Cómo se tratan los patrones de comandos de filtro. Los métodos actualmente compatibles son text (es decir, literales de cadena), glob (es decir, globs de shell) y regex (es decir, expresiones regulares). Consulte BÚSQUEDA DE ARCHIVOS para obtener más detalles.

findlen (int) (predeterminado 1)

Número de caracteres solicitados para el comando find. Cuando este valor se establece en 0, el comando find solicita hasta que solo quede una coincidencia.

hidden (bool) (predeterminado false)

Mostrar archivos ocultos. En los sistemas Unix, los archivos ocultos se determinan por el valor de hiddenfiles. En Windows, los archivos con atributos ocultos también se consideran archivos ocultos.

hiddenfiles ([]string) (predeterminado .* para Unix y `` para Windows)

Lista de patrones de glob de archivos ocultos. Los patrones se pueden proporcionar como rutas relativas o absolutas. Globbing admite los caracteres especiales habituales: * para coincidir con cualquier secuencia, ? para coincidir con cualquier carácter y [...] o [^...] para coincidir con conjuntos de caracteres o rangos. Además, si un patrón comienza con !, sus coincidencias se excluyen de los archivos ocultos. Para agregar varios patrones, use : como separador. Ejemplo: .*:lost+found:*.bak

history (bool) (predeterminado true)

Guardar historial de comandos.

icons (bool) (predeterminado false)

Mostrar iconos antes de cada elemento en la lista.

ifs (string) (predeterminado ``)

Establece la variable IFS en los comandos del shell. Funciona añadiendo la asignación al principio de la cadena de comando como IFS=...; .... La razón es que la variable IFS no es heredada por el shell por motivos de seguridad. Este método asume una sintaxis de shell POSIX, por lo que puede fallar para shells no POSIX. Esta opción no tiene ningún efecto cuando el valor se deja vacío. Esta opción no tiene ningún efecto en Windows.

ignorecase (bool) (predeterminado true)

Ignorar mayúsculas y minúsculas en patrones de ordenación y búsqueda.

ignoredia (bool) (predeterminado true)

Ignorar diacríticos en patrones de ordenación y búsqueda.

incfilter (bool) (predeterminado false)

Aplicar el patrón de filtro después de cada pulsación de tecla durante el filtrado.

incsearch (bool) (predeterminado false)

Saltar a la primera coincidencia después de cada pulsación de tecla durante la búsqueda.

info ([]string) (predeterminado ``)

Una lista de información que se muestra para los elementos del directorio en el lado derecho del panel.

Los siguientes tipos de información son compatibles:

perm      permiso del archivo
user      nombre de usuario
group     nombre del grupo
size      tamaño del archivo
time      hora de la última modificación de datos
atime     hora del último acceso
btime     hora de creación del archivo
ctime     hora del último cambio de estado (inodo)
custom    propiedad definida a través de `addcustominfo` (vacío por defecto)

La información solo se muestra cuando el ancho del panel es más del doble del ancho de la información.

infotimefmtnew (string) (predeterminado Jan _2 15:04)

Cadena de formato de la hora del archivo que se muestra en la columna de información cuando coincide con este año.

infotimefmtold (string) (predeterminado Jan _2 2006)

Cadena de formato de la hora del archivo que se muestra en la columna de información cuando no coincide con este año.

menufmt (string) (predeterminado \033[0m)

Cadena de formato del menú.

menuheaderfmt (string) (predeterminado \033[1m)

Cadena de formato de la fila de encabezado en el menú.

menuselectfmt (string) (predeterminado \033[7m)

Cadena de formato del elemento seleccionado actualmente en el menú.

mouse (bool) (predeterminado false)

Enviar eventos del ratón como entrada.

number (bool) (predeterminado false)

Mostrar el número de posición de los elementos del directorio en el lado izquierdo del panel. Cuando la opción relativenumber está habilitada, solo la línea actual muestra la posición absoluta y se muestran las posiciones relativas para el resto.

numberfmt (string) (predeterminado \033[33m)

Cadena de formato del número de posición para cada línea.

period (int) (predeterminado 0)

Establece el intervalo en segundos para las comprobaciones periódicas de actualizaciones de directorios. Esto funciona llamando periódicamente al comando load. Tenga en cuenta que los director ya se han actualizado automáticamente en muchos casos. Esta opción puede ser útil cuando un proceso externo está cambiando el directorio mostrado y tú no estás haciendo nada en lf. Las revisiones periódicas se deshabilitan cuando el valor de esta opción se establece en cero.

preload (booleano) (por defecto falso)

Permite que las previsualizaciones se generen por adelantado usando el script previewer mientras el usuario navega por el sistema de archivos.

preserve ([]string) (por defecto mode)

Lista de atributos que se conservan al copiar archivos. Actualmente, los atributos compatibles son mode (es decir, modo de acceso) y timestamps (es decir, tiempo de modificación y tiempo de acceso). Ten en cuenta que conservar otros atributos como la propiedad del cambio/marca de tiempo de nacimiento es deseable, pero no es compatible de forma portátil en Go.

preview (booleano) (por defecto verdadero)

Muestra previsualizaciones de archivos y directorios en el panel más a la derecha. Si el archivo tiene más líneas que el panel de previsualización, el resto de las líneas no se leen. Los archivos que contienen el carácter nulo (U+0000) en la porción leída se consideran archivos binarios y se muestran como binario.

previewer (cadena) (por defecto ``) (no se filtra si está vacío)

Establece la ruta de un archivo previsualizador para filtrar el contenido de los archivos regulares para la previsualización. El archivo debe ser ejecutable. Los siguientes argumentos se pasan al archivo: (1) nombre del archivo actual, (2) ancho, (3) alto, (4) posición horizontal, (5) posición vertical y (6) modo ("preview" o "preload"). La señal SIGPIPE se envía cuando se leen suficientes líneas. Si el previsualizador devuelve un código de salida distinto de cero, entonces la caché de previsualización para el archivo dado se deshabilita. Esto significa que si el archivo se selecciona en el futuro, el previsualizador se llamará una vez más. El filtrado de previsualización se deshabilita y los archivos se muestran tal como son cuando el valor de esta opción se deja vacío. Si la opción preload está habilitada, entonces se llamará con preload como modo al pre-cargar las previsualizaciones de archivos. Consulta la sección PREVISUALIZACIÓN DE ARCHIVOS para obtener más información sobre cómo configurar previsualizaciones personalizadas.

promptfmt (cadena) (por defecto \033[32;1m%u@%h\033[0m:\033[34;1m%d\033[0m\033[1m%f\033[0m)

Cadena de formato del prompt que se muestra en la línea superior.

Las siguientes expansiones especiales son compatibles:

%f        nombre del archivo
%h        nombre del host
%u        nombre de usuario
%w        directorio de trabajo
%d        directorio de trabajo (con separador de ruta final)
%F        filtro actual
%S        espaciador para alinear a la derecha las siguientes partes (se puede usar una vez)

La carpeta principal se muestra como ~ en la expansión del directorio de trabajo. Los nombres de los directorios se acortan automáticamente a un solo carácter comenzando desde el padre más a la izquierda cuando el prompt no cabe en la pantalla.

ratios ([]int) (por defecto 1:2:3)

Lista de relaciones de anchos de panel. El número de elementos en la lista determina el número de paneles en la interfaz de usuario. Cuando la opción preview está habilitada, el número más a la derecha se utiliza para el ancho del panel de previsualización.

Muestra el número de posición relativo a la línea actual. Cuando number está habilitado, la línea actual muestra la posición absoluta, de lo contrario, no se muestra nada.

reverse (booleano) (por defecto falso)

Invierte la dirección de ordenación.

roundbox (booleano) (por defecto falso)

Dibuja esquinas exteriores redondeadas cuando la opción drawbox está habilitada.

CONFIGURATION OPTIONS

The set command is used to set an option which can be a boolean, integer, or string:

set hidden         # boolean enable
set hidden true    # boolean enable
set nohidden       # boolean disable
set hidden false   # boolean disable
set hidden!        # boolean toggle
set scrolloff 10   # integer value
set sortby time    # string value without quotes
set sortby 'time'  # string value with single quotes (whitespace)
set sortby "time"  # string value with double quotes (backslash escapes)

The setlocal command is used to set a local option for a directory which can be a boolean or string. Currently supported local options are dircounts, dirfirst, dironly, hidden, info, reverse and sortby. Adding a trailing path separator (i.e. / for Unix and \ for Windows) sets the option for the given directory along with its subdirectories:

setlocal /foo/bar hidden         # boolean enable
setlocal /foo/bar hidden true    # boolean enable
setlocal /foo/bar nohidden       # boolean disable
setlocal /foo/bar hidden false   # boolean disable
setlocal /foo/bar hidden!        # boolean toggle
setlocal /foo/bar sortby time    # string value without quotes
setlocal /foo/bar sortby 'time'  # string value with single quotes (whitespace)
setlocal /foo/bar sortby "time"  # string value with double quotes (backslash escapes)
setlocal /foo/bar  hidden        # for only '/foo/bar' directory
setlocal /foo/bar/ hidden        # for '/foo/bar' and its subdirectories (e.g. '/foo/bar/baz')

The map command is used to bind a key in Normal and Visual mode to a command which can be a built-in command, custom command, or shell command:

map gh cd ~        # built-in command
map D trash        # custom command
map i $less $f     # shell command
map U !du -csh *   # waiting shell command

The nmap command does the same but for Normal mode only.

The vmap command does the same but for Visual mode only.

Overview of which map command works in which mode:

map                Normal, Visual
nmap               Normal
vmap               Visual
cmap               Command-line

The cmap command is used to bind a key on the command line to a command line command or any other command:

cmap <c-g> cmd-escape
cmap <a-i> set incsearch!

You can delete an existing binding by leaving the expression empty:

map gh             # deletes 'gh' mapping in Normal and Visual mode
nmap v             # deletes 'v' mapping in Normal mode
vmap o             # deletes 'o' mapping in Visual mode
cmap <c-g>         # deletes '<c-g>' mapping

The cmd command is used to define a custom command:

cmd usage $du -h -d1 | less

You can delete an existing command by leaving the expression empty:

cmd trash          # deletes 'trash' command

If there is no prefix then : is assumed:

map zt set info time

An explicit : can be provided to group statements until a newline which is especially useful for map and cmd commands:

map st :set sortby time; set info time

If you need multiline you can wrap statements in {{ and }} after the proper prefix.

map st :{{
    set sortby time
    set info time
}}

Mapeos de Teclas

Las teclas normales se asignan a un comando con la sintaxis habitual:

map a down

Las teclas combinadas con la tecla Shift usan simplemente la letra mayúscula:

map A down

Las teclas especiales se escriben entre los caracteres < y > y siempre usan letras minúsculas:

map <enter> down

Los corchetes angulares se pueden asignar con sus nombres especiales:

map <lt> down
map <gt> down

Las teclas de función van precedidas del carácter f:

map <f-1> down

Las teclas combinadas con la tecla Ctrl van precedidas del carácter c:

map <c-a> down

Las teclas combinadas con la tecla Alt se asignan de dos maneras diferentes dependiendo del comportamiento de tu terminal. Las terminales más antiguas (por ejemplo, xterm) pueden establecer el octavo bit de un carácter cuando se presiona la tecla Alt. En estas terminales, puedes usar el byte correspondiente para el mapeo:

map á down

Las terminales más nuevas (por ejemplo, gnome-terminal) pueden anteponer un carácter de escape a la tecla cuando se presiona la tecla Alt. lf utiliza el mecanismo de retardo de escape para reconocer las teclas Alt en estas terminales (el retardo es de 100 ms). En estas terminales, las teclas combinadas con la tecla Alt van precedidas del carácter a:

map <a-a> down

Es posible combinar teclas especiales con modificadores:

map <a-enter> down

ADVERTENCIA: Es muy probable que combinaciones de teclas específicas sean interceptadas por tu sistema operativo, gestor de ventanas o terminal. Otras combinaciones de teclas no pueden ser reconocidas por lf debido a la forma en que funcionan las terminales (por ejemplo, la combinación Ctrl+h envía una tecla de retroceso en su lugar). La forma más fácil de averiguar el nombre de una combinación de teclas y si funcionará en tu sistema es presionar la tecla mientras lf está en ejecución y leer el nombre del error de mapeo desconocido.

Los botones del ratón van precedidos del carácter m:

map <m-1> down  # primario
map <m-2> down  # secundario
map <m-3> down  # medio
map <m-4> down
map <m-5> down
map <m-6> down
map <m-7> down
map <m-8> down

Los eventos de la rueda del ratón también van precedidos del carácter m:

map <m-up>    down
map <m-down>  down
map <m-left>  down
map <m-right> down

Mapeos PUSH

La forma habitual de mapear una secuencia de teclas es asignarla a un comando con nombre o sin nombre. Si bien esto proporciona una forma limpia de reasignar teclas integradas, así como otros comandos, puede ser limitante en ocasiones. Por esta razón, lf proporciona el comando push. Este comando se utiliza para simular pulsaciones de teclas dadas como sus argumentos. Puedes mapear una tecla a un comando push con un argumento para crear varios enlaces de teclas.

Esto es útil principalmente para dos propósitos. Primero, se puede usar para mapear un comando con un recuento de comandos:

map <c-j> push 10j

Segundo, se puede usar para evitar escribir el nombre cuando un comando toma argumentos:

map r push :rename<space>

Una cosa a tener en cuenta es que dado que el comando push funciona con teclas en lugar de comandos, es posible crear accidentalmente enlaces recursivos:

map j push 2j

Estos tipos de enlaces crean un punto muerto cuando se ejecutan.

Comandos Shell

Los comandos shell regulares son el tipo de comando más básico que es útil para muchos propósitos. Por ejemplo, podemos escribir un comando shell para mover el(los) archivo(s) seleccionado(s) a la papelera. Un primer intento de escribir un comando de este tipo podría verse así:

cmd trash ${{
    mkdir -p ~/.trash
    if [ -z "$fs" ]; then
        mv "$f" ~/.trash
    else
        IFS="$(printf '\n\t')"; mv $fs ~/.trash
    fi
}}

Comprobamos $fs para ver si hay archivos seleccionados. De lo contrario, simplemente eliminamos el archivo actual. Dado que este es un patrón tan común, se proporciona una variable separada $fx. Podemos usar esta variable para eliminar la condición:

cmd trash ${{
    mkdir -p ~/.trash
    IFS="$(printf '\n\t')"; mv $fx ~/.trash
}}

El directorio de la papelera se comprueba cada vez que se ejecuta el comando. Podemos moverlo fuera del comando para que solo se ejecute una vez al inicio:

${{ mkdir -p ~/.trash }}
cmd trash ${{ IFS="$(printf '\n\t')"; mv $fx ~/.trash }}

Dado que estas son líneas únicas, podemos omitir {{ y }}:

$mkdir -p ~/.trash
cmd trash $IFS="$(printf '\n\t')"; mv $fx ~/.trash

Finalmente, tenga en cuenta que establecemos la variable IFS manualmente en estos comandos. En su lugar, podríamos usar la opción ifs para establecerla para todos los comandos shell (es decir, set ifs "\n"). Esto puede ser especialmente útil para uso interactivo (por ejemplo, $rm $f o $rm $fs simplemente funcionarían). Esta opción no está establecida por defecto ya que puede comportarse de forma inesperada para nuevos usuarios. Sin embargo, se recomienda encarecidamente el uso de esta opción y se asume en el resto de la documentación.

Y LAS

Los comandos de shell regulares tienen algunas limitaciones en algunos casos. Cuando se proporciona una salida o un mensaje de error y el comando finaliza, la interfaz de usuario se reanuda inmediatamente y no hay forma de ver el mensaje sin volver a la shell. Además, incluso cuando no hay salida ni error, la interfaz de usuario todavía necesita pausarse mientras se ejecuta el comando. Esto puede causar parpadeos en la pantalla para comandos cortos y distracciones similares para comandos más largos.

En lugar de pausar la interfaz de usuario, los comandos de shell de tubería conectan stdin, stdout y stderr del comando a la línea de estado en la parte inferior de la interfaz de usuario. Esto puede ser útil para programas que siguen la filosofía Unix de no producir ninguna salida en caso de éxito, y mensajes de error o indicaciones breves en otros casos.

Por ejemplo, el siguiente comando de renombrado solicita la sobrescritura en la línea de estado si existe un archivo con el nombre dado:

cmd rename %mv -i $f $1

También puede generar mensajes de error en el comando y aparecerán en la línea de estado. Por ejemplo, un comando de renombrado alternativo podría verse así:

cmd rename %[ -e $1 ] && printf "el archivo existe" || mv $f $1

Tenga en cuenta que la entrada es con búfer de línea y la salida y los errores son con búfer de bytes.

COMANDOS DE SHELL DE ESPERA

Los comandos de shell de espera son similares a los comandos de shell regulares, excepto que esperan que se presione una tecla cuando el comando finaliza. Estos pueden ser útiles para ver la salida de un programa antes de que se reanude la interfaz de usuario. Los comandos de shell de espera son más apropiados que los comandos de shell de tubería cuando el comando es verboso y la salida se muestra mejor como varias líneas.

COMANDOS DE SHELL ASÍNCRONOS

Los comandos de shell asíncronos se utilizan para iniciar un comando en segundo plano y luego reanudar la operación sin esperar a que el comando finalice. Stdin, stdout y stderr del comando no están conectados ni al terminal ni a la interfaz de usuario.

COMANDOS REMOTOS

Una de las características más avanzadas de lf son los comandos remotos. Todos los clientes se conectan a un servidor al inicio. Es posible enviar comandos a todos o a cualquiera de los clientes conectados a través del servidor común. Esto se utiliza internamente para notificar los cambios de selección de archivos a otros clientes.

Para utilizar esta función, necesita usar un cliente que admita la comunicación con un socket de dominio Unix. La implementación de OpenBSD de netcat (nc) es un ejemplo de este tipo. Puede usarla para enviar un comando al archivo de socket:

echo 'send echo hello world' | nc -U ${XDG_RUNTIME_DIR:-/tmp}/lf.${USER}.sock

Dado que dicho cliente puede no estar disponible en todas partes, lf viene con una bandera de línea de comandos para usarla de esta manera. Al usar lf, no necesita especificar la dirección del archivo de socket. Esta es la forma recomendada de usar comandos remotos, ya que es más corta e inmune a los cambios en la dirección del archivo de socket:

lf -remote 'send echo hello world'

En este comando, send se utiliza para enviar el resto de la cadena como un comando a todos los clientes conectados. Opcionalmente, puede darle un número de ID para enviar un comando a un solo cliente:

lf -remote 'send 1234 echo hello world'

Todos los clientes tienen un número de ID único, pero es posible que no conozca el número de ID cuando esté escribiendo un comando. Para este propósito, se exporta una variable $id al entorno para los comandos de shell. El valor de esta variable se establece en el ID del proceso del cliente. Puede usarlo para enviar un comando remoto desde un cliente al servidor, que a su vez envía un comando de vuelta a sí mismo. Así que ahora puede mostrar un mensaje en el cliente actual llamando a lo siguiente en un comando de shell:

lf -remote "send $id echo hello world"

Dado que lf no tiene sintaxis de control de flujo, los comandos remotos se utilizan para tales necesidades. Por ejemplo, puede configurar el número de columnas en la interfaz de usuario con respecto al ancho del terminal de la siguiente manera:

cmd recol %{{
    if [ $lf_width -le 80 ]; then
        lf -remote "send $id set ratios 1:2"
    elif [ $lf_width -le 160 ]; then
        lf -remote "send $id set ratios 1:2:3"
    else
        lf -remote "send $id set ratios 1:2:3:5"
    fi
}}

Además, se puede usar el comando query para obtener información sobre una instancia específica de lf proporcionando su ID:

lf -remote "query $id maps"

Los siguientes tipos de información son compatibles:

maps     lista de asignaciones creadas por el comando 'map', 'nmap' y 'vmap'
nmaps    lista de asignaciones creadas por el comando 'nmap' y 'map'
vmaps    lista de asignaciones creadas por el comando 'vmap' y 'map'
cmaps    lista de asignaciones creadas por el comando 'cmap'
cmds     lista de comandos creados por el comando 'cmd'
jumps    contenido de la lista de saltos, mostrando ubicaciones visitadas previamente
history  lista de comandos ejecutados previamente en la línea de comandos
files    lista de archivos en el directorio actualmente abierto según lo muestra lf, vacía si el directorio aún se está cargando

Al listar asignaciones, los caracteres en la primera columna son:

n  Normal
v  Visual
c  Línea de comandos

Esto es útil para escribir scripts de acciones basadas en el estado interno de lf. Por ejemplo, para seleccionar un comando anterior usando fzf y ejecutarlo:

map <a-h> ${{
    clear
    cmd=$(
        lf -remote "query $id history" |
        awk -F'\t' 'NR > 1 { print $NF}' |
        sort -u |
        fzf --reverse --prompt='Ejecutar comando: '
    )
    lf -remote "send $id $cmd"
}}

También hay un comando quit para salir del servidor cuando no quedan clientes conectados, y un comando quit! para forzar la salida del servidor cerrando primero las conexiones de los clientes:

lf -remote 'quit'
lf -remote 'quit!'

Por último, los comandos conn y drop conectan o desconectan el ID del servidor:

lf -remote 'conn $id'
lf -remote 'drop $id'

Estos son internos y generalmente no son necesarios para los usuarios.

OPERACIONES DE ARCHIVO

lf utiliza sus propias operaciones de copia y movimiento integradas por defecto. Estas se implementan como operaciones asíncronas y el progreso se muestra en la regla inferior. Estos comandos no sobrescriben archivos o directorios existentes con el mismo nombre. En su lugar, se agrega un sufijo compatible con la opción --backup=numbered de GNU cp a los nuevos archivos o directorios. Solo se pueden conservar los modos de archivo y (algunas) marcas de tiempo (ver opción preserve), se ignoran todos los demás atributos, incluida la propiedad, el contexto y xattr. Los archivos especiales como dispositivos de caracteres y bloques, tuberías con nombre y sockets se omiten y los enlaces no se siguen. El movimiento se realiza utilizando la operación de renombrado del sistema operativo subyacente. Para mover entre dispositivos, lf recurre a la copia y luego elimina los archivos originales si no hay errores. Los errores de operación se muestran en la línea de mensajes, así como en el archivo de registro, y no terminan prematuramente la operación de archivo correspondiente.

Las operaciones de archivo se pueden realizar en el archivo actualmente seleccionado o en varios archivos seleccionándolos primero. Cuando copia un archivo, lf en realidad no copia el archivo en el disco, sino que solo registra su nombre en un archivo. La copia real del archivo tiene lugar cuando pega. De manera similar, pega después de una operación de corte mueve el archivo.

Puede personalizar las operaciones de copia y movimiento definiendo un comando paste. Este es un comando especial que se llama cuando se define en lugar de la implementación integrada. Puede usar el siguiente ejemplo como punto de partida:

cmd paste %{{
    load=$(cat ~/.local/share/lf/files)
    mode=$(echo "$load" | sed -n '1p')
    list=$(echo "$load" | sed '1d')
    if [ $mode = 'copy' ]; then
        cp -R $list .
    elif [ $mode = 'move' ]; then
        mv $list .
        rm ~/.local/share/lf/files
        lf -remote 'send clear'
    fi
}}

Algunas cosas útiles a considerar son usar las opciones de copia de seguridad (--backup) y/o conservar atributos (-a) con los comandos cp y mv si los admiten (es decir, implementación GNU), cambiar el tipo de comando a asíncrono, o usar el comando rsync con la opción de barra de progreso para copiar y alimentar el progreso al cliente periódicamente con llamadas remotas echo.

Por defecto, lf no asigna el comando delete a una tecla para proteger a los nuevos usuarios. Puede personalizar la eliminación de archivos definiendo un comando delete. También puede asignar una tecla a este comando si lo desea. En el archivo de configuración de ejemplo se proporciona un comando de ejemplo para mover los archivos seleccionados a una carpeta de basura y eliminar los archivos por completo después de una solicitud.

En este modo, puedes usar cmd-enter para aceptar la búsqueda o usar cmd-escape para cancelar la búsqueda. También puedes mapear algunos otros comandos con cmap para aceptar la búsqueda y ejecutar el comando inmediatamente después. Por ejemplo, puedes usar la tecla de flecha derecha para finalizar la búsqueda y abrir el archivo seleccionado con el siguiente mapeo:

cmap <right> :cmd-enter; open

El mecanismo de búsqueda se implementa con los comandos find (por defecto f), find-back (por defecto F), find-next (por defecto ;), find-prev (por defecto ,). Puedes deshabilitar la opción anchorfind para coincidir un patrón en una posición arbitraria del nombre de archivo en lugar del principio. Puedes establecer el número de teclas para coincidir usando la opción findlen. Si estableces este valor a cero, las teclas se leerán hasta que solo haya una única coincidencia. Los valores por defecto de estas dos opciones se establecen para saltar al primer archivo con la inicial dada.

Algunas opciones afectan tanto a la búsqueda como a la localización. Puedes deshabilitar la opción wrapscan para evitar que las búsquedas den la vuelta al final de la lista de archivos. Puedes deshabilitar la opción ignorecase para hacer coincidir mayúsculas y minúsculas en el patrón y el nombre de archivo. Esta opción ya se anula automáticamente si el patrón contiene caracteres en mayúsculas. Puedes deshabilitar la opción smartcase para deshabilitar este comportamiento. Se proporcionan dos opciones similares, ignoredia y smartdia, para controlar la coincidencia de diacríticos en letras latinas.

ABRIENDO ARCHIVOS

Puedes definir un comando open (por defecto l y <right>) para configurar la apertura de archivos. Este comando solo se llama cuando el archivo actual no es un directorio; de lo contrario, se entra en el directorio. Puedes definirlo como cualquier otro comando:

cmd open $vi $fx

Es posible usar diferentes tipos de comandos:

cmd open &xdg-open $f

Puede que quieras usar extensiones de archivo o tipos MIME del comando file:

cmd open ${{
    case $(file --mime-type -Lb $f) in
        text/*) vi $fx;;
        *) for f in $fx; do xdg-open $f > /dev/null 2> /dev/null & done;;
    esac
}}

Es posible que quieras usar setsid antes de tu comando abridor para tener procesos persistentes que sigan ejecutándose después de que lf finalice.

Los comandos de shell regulares (es decir, $) descienden a la terminal, lo que resulta en un parpadeo para los comandos que finalizan inmediatamente (por ejemplo, xdg-open en el ejemplo anterior). Si quieres usar comandos de shell asíncronos (es decir, &) pero también quieres usar la terminal cuando sea necesario (por ejemplo, vi en el ejemplo anterior), puedes usar un comando remoto:

cmd open &{{
    case $(file --mime-type -Lb $f) in
        text/*) lf -remote "send $id \$vi \$fx";;
        *) for f in $fx; do xdg-open $f > /dev/null 2> /dev/null & done;;
    esac
}}

Ten en cuenta que los comandos de shell asíncronos se ejecutan en su propio grupo de procesos por defecto, por lo que no requieren el uso manual de setsid.

El siguiente comando se proporciona por defecto:

cmd open &$OPENER $f

También puedes usar cualquier otro abridor de archivos existente como desees. Las opciones posibles son libfile-mimeinfo-perl (nombre de ejecutable mimeopen), rifle (abridor de archivos por defecto de ranger), o mimeo, por nombrar algunos.

PREVISUALIZANDO ARCHIVOS

lf previsualiza los archivos en el panel de vista previa imprimiendo el archivo hasta el final o hasta que el panel de vista previa se llene. Esta salida se puede mejorar proporcionando un script de vista previa personalizado para filtrar. Esto se puede usar para resaltar código fuente, listar el contenido de archivos de archivo o ver archivos PDF o de imagen, entre otros. Para colorear, lf reconoce códigos de escape ANSI.

Para usar esta función, necesitas establecer el valor de la opción previewer a la ruta de un archivo ejecutable. Los siguientes argumentos se pasan al archivo: (1) nombre de archivo actual, (2) ancho, (3) alto, (4) posición horizontal, (5) posición vertical, y (6) modo ("preview" o "preload"). La salida de la ejecución se imprime en el panel de vista previa.

Se pueden manejar diferentes tipos de archivos coincidiendo por extensión (o tipo MIME del comando file):

#!/bin/sh
case "$1" in
    *.tar*) tar tf "$1";;
    *.zip) unzip -l "$1";;
    *.rar) unrar l "$1";;
    *.7z) 7z l "$1";;
    *.pdf) pdftotext "$1" -;;
    *) highlight -O ansi "$1";;
esac

Dado que los archivos pueden ser grandes, lf cierra automáticamente la tubería de salida del script de vista previa con una SIGPIPE cuando se leen suficientes líneas. Ten en cuenta que algunos programas pueden no responder bien a SIGPIPE y saldrán con un código de retorno distinto de cero, lo que evita el almacenamiento en caché. Puedes añadir un comando || true al final para evitar tales errores:

highlight -O ansi "$1" || true

También puede que quieras usar el mismo script en el mapeo de tu paginador:

set previewer ~/.config/lf/pv.sh
map i $~/.config/lf/pv.sh $f | less -R

Para el paginador less, puedes utilizar en su lugar el mecanismo LESSOPEN para que la información útil sobre el archivo, como la ruta completa del archivo, todavía se pueda mostrar en la barra de estado inferior:

set previewer ~/.config/lf/pv.sh
map i $LESSOPEN='| ~/.config/lf/pv.sh %s' less -R $f

Dado que el script de vista previa se llama para cada cambio de selección de archivo, puede que no genere vistas previas lo suficientemente rápido si el usuario se desplaza por los archivos rápidamente. Para abordar esto, la opción preload puede establecerse para habilitar que las vistas previas de archivos se pre-carguen con anticipación. Si está habilitado, el script de vista previa se ejecutará en archivos con antelación a medida que el usuario navega por ellos. En este caso, si el código de salida del script de vista previa es cero, la salida se almacenará en caché en memoria y será mostrada por lf (útil para vistas previas de texto o sixel). De lo contrario, volverá a llamar al script de vista previa cuando el archivo sea realmente seleccionado (útil para vistas previas gestionadas por un programa externo).

CAMBIANDO DE DIRECTORIO

lf cambia el directorio de trabajo del proceso al directorio actual para que los comandos de shell siempre funcionen en el directorio mostrado. Después de salir, regresa al directorio original donde se lanzó inicialmente, como todos los programas de shell. Si quieres permanecer en el directorio actual después de salir, puedes usar uno de los scripts wrapper de shell ejemplo de lfcd proporcionados en el repositorio en https://github.com/gokcehan/lf/tree/master/etc

Hay un comando especial on-cd que ejecuta un comando de shell cuando está definido y el directorio se cambia. Puedes definirlo como cualquier otro comando:

cmd on-cd &{{
    bash -c '
    # display git repository status in your prompt
    source /usr/share/git/completion/git-prompt.sh
    GIT_PS1_SHOWDIRTYSTATE=auto
    GIT_PS1_SHOWSTASHSTATE=auto
    GIT_PS1_SHOWUNTRACKEDFILES=auto
    GIT_PS1_SHOWUPSTREAM=auto
    git=$(__git_ps1 " (%s)")
    fmt="\033[32;1m%u@%h\033[0m:\033[34;1m%d\033[0m\033[1m%f$git\033[0m"
    lf -remote "send $id set promptfmt \"$fmt\""
    '
}}

Si quieres enviar secuencias de escape a la terminal, puedes usar el comando tty-write para hacerlo. La siguiente secuencia de escape específica de xterm establece el título de la terminal al directorio de trabajo:

cmd on-cd &{{
    lf -remote "send $id tty-write \"\033]0;$PWD\007\""
}}

Este comando se ejecuta cada vez que cambias de directorio, pero no al inicio. Puedes añadir una llamada adicional para que se ejecute también al inicio:

cmd on-cd &{{ ... }}
on-cd

Ten en cuenta que todos los comandos de shell son posibles, pero % y & suelen ser más apropiados, ya que $ y ! provocan parpadeos y pausas respectivamente.

También existe el comando pre-cd, que funciona como on-cd, pero se ejecuta antes de que el directorio se cambie realmente. Otro comando relacionado es on-load, que se ejecuta al cargar un directorio.

RULER

Configurable ruler string

The ruler is a string that is displayed at the bottom of the terminal. It can be configured using a template which is then rendered to create the actual output (refer to https://pkg.go.dev/text/template for more details on the syntax). This feature is currently experimental and must be enabled via the rulerfile option.

The following data fields are exported:

.Message          string              Includes internal messages, errors, and messages generated by the `echo`/`echomsg`/`echoerr` commands
.Keys             string              Keys pressed by the user
.Progress         []string            Progress indicators for copied, moved and deleted files
.Copy             []string            List of files in the clipboard to be copied
.Cut              []string            List of files in the clipboard to be moved
.Select           []string            Selection list
.Visual           []string            Visual selection
.Index            int                 Index of the cursor
.Total            int                 Number of visible files in the current directory
.Hidden           int                 Number of hidden files in the current directory
.LinePercentage   string              Line percentage (analogous to `%p` for the `statusline` option in Vim)
.ScrollPercentage string              Scroll percentage (analogous to `%P` for the `statusline` option in Vim)
.Filter           []string            Filter currently being applied
.Mode             string              Current mode ("NORMAL" for Normal mode, and "VISUAL" for Visual mode)
.Options          map[string]string   The value of options (e.g. `{{.Options.hidden}}`)
.UserOptions      map[string]string   The value of user-defined options (e.g. `{{.UserOptions.foo}}`)
.Stat.Path        string              Path of the current file
.Stat.Name        string              Name of the current file
.Stat.Size        uint64              Size of the current file
.Stat.Permissions string              Permissions of the current file
.Stat.ModTime     string              Last modified time of the current file (formatted based on the `timefmt` option)
.Stat.LinkCount   string              Number of hard links for the current file
.Stat.User        string              User of the current file
.Stat.Group       string              Group of the current file
.Stat.Target      string              Target if the current file is a symbolic link, otherwise a blank string

The following functions are exported:

df       func() string                   Get an indicator representing the amount of free disk space available
env      func(string) string             Get the value of an environment variable
humanize func(uint64) string             Express a file size in a human-readable format
join     func([]string, string) string   Join a string array by a separator
lower    func(string) string             Convert a string to lowercase
substr   func(string, int, int) string   Get a substring based on starting index and length
upper    func(string) string             Convert a string to uppercase

The special identifier {{.SPACER}} can be used to divide the ruler into sections that are spaced evenly from each other.

The default ruler file can be found at https://github.com/gokcehan/lf/blob/master/etc/ruler.default
