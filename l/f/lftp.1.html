lftp(1) Manual de Comandos Generales lftp(1)

NOMBRE

lftp - Programa de transferencia de archivos sofisticado

SINTAXIS

lftp [-d] [-e cmd] [-p puerto] [-u usuario[,contraseña]] [sitio]
lftp -f archivo_script
lftp -c comandos
lftp --version
lftp --help

VERSIÓN

Esta página del manual documenta la versión 4.8.1 de lftp.

DESCRIPCIÓN

lftp es un programa de transferencia de archivos que permite conexiones FTP, HTTP y otras sofisticadas a otros hosts. Si se especifica sitio, lftp se conectará a ese sitio; de lo contrario, la conexión deberá establecerse con el comando open.

lftp puede manejar varios métodos de acceso a archivos: FTP, FTPS, HTTP, HTTPS, HFTP, FISH, SFTP y file (HTTPS y FTPS solo están disponibles cuando lftp se compila con la biblioteca GNU TLS u OpenSSL). Puedes especificar el método a usar en el comando `open URL', por ejemplo, `open http://www.us.kernel.org/pub/linux'. HFTP es un protocolo ftp sobre proxy http. Puede usarse automáticamente en lugar de FTP si ftp:proxy está configurado a `http://proxy[:puerto]'. Fish es un protocolo que funciona sobre una conexión ssh a una cuenta unix. SFtp es un protocolo implementado en SSH2 como sub-sistema SFTP.

Además de los protocolos tipo FTP, lftp tiene soporte para el protocolo BitTorrent como comando `torrent'. También se soporta el seeding.

Cada operación en lftp es fiable, es decir, cualquier error no fatal se maneja adecuadamente y la operación se repite. Así, si la descarga se interrumpe, se reiniciará automáticamente desde el punto donde se quedó. Incluso si el servidor FTP no soporta el comando REST, lftp intentará recuperar el archivo desde el principio hasta que el archivo se transfiera completamente.

lftp tiene una sintaxis de comandos similar a la shell, que te permite lanzar varios comandos en paralelo en segundo plano (&). También es posible agrupar comandos dentro de () y ejecutarlos en segundo plano. Todos los trabajos en segundo plano se ejecutan en el mismo proceso único. Puedes pasar un trabajo en primer plano a segundo plano con ^Z (c-z) y recuperarlo con el comando `wait' (o `fg', que es un alias de `wait'). Para listar los trabajos en ejecución, usa el comando `jobs'. Algunos comandos permiten redirigir su salida (cat, ls, ...) a un archivo o a través de una tubería a un comando externo. Los comandos pueden ejecutarse condicionalmente según el estado de terminación del comando anterior (&&, ||).

Si sales de lftp antes de que todos los trabajos hayan terminado, lftp se moverá a modo nohup en segundo plano. Lo mismo ocurre con una desconexión real del módem o cuando cierras un xterm.

lftp tiene una función de espejo incorporada que puede descargar o actualizar un árbol de directorios completo. También existe un espejo inverso (mirror -R) que sube o actualiza un árbol de directorios en el servidor. El espejo también puede sincronizar directorios entre dos servidores remotos, usando FXP si está disponible.

Hay un comando `at' para lanzar un trabajo a una hora especificada en el contexto actual, un comando `queue' para poner comandos en cola para ejecución secuencial para el servidor actual, y mucho más.

Al iniciar, lftp ejecuta /etc/lftp.conf y luego ~/.lftprc y ~/.lftp/rc (o ~/.config/lftp/rc si ~/.lftp no existe). Puedes colocar alias y comandos `set' allí. Algunas personas prefieren ver la depuración completa del protocolo, usa `debug' para activarla. Usa `debug 3' para ver solo los mensajes de saludo y de error.

lftp tiene una serie de variables configurables. Puedes usar `set -a' para ver todas las variables y sus valores o `set -d' para ver la lista de valores predeterminados. Los nombres de las variables pueden abreviarse y el prefijo puede omitirse a menos que el resto se vuelva ambiguo.

Si lftp se compiló con OpenSSL (configure --with-openssl), incluye software desarrollado por el Proyecto OpenSSL para su uso en el Kit de Herramientas OpenSSL. (http://www.openssl.org/)

Cambia el directorio remoto actual. El directorio remoto anterior se almacena como `-'. Puedes hacer `cd -' para cambiar de directorio hacia atrás. El directorio anterior para cada sitio también se almacena en disco, por lo que puedes hacer `open sitio; cd -' incluso después de reiniciar lftp.

close [-a]

Cierra las conexiones inactivas. Por defecto solo con el servidor actual, usa -a para cerrar todas las conexiones inactivas.

`cls' intenta recuperar información sobre los archivos o directorios especificados y muestra la información según las opciones de formato. La diferencia entre `ls' y `cls' es que `ls' solicita al servidor que formatee la lista de archivos, y `cls' la formatea por sí mismo, después de recuperar toda la información necesaria.

exit [bg] [top] [parent] [kill] [code]

exit saldrá de lftp o se moverá al fondo si hay trabajos activos. Si no hay ningún trabajo activo, code se pasará al sistema operativo como estado de terminación de lftp. Si se omite code, se usará el código de salida del último comando.

`exit bg' fuerza el movimiento al fondo cuando cmd:move-background es false. `exit top' hace que el ejecutor de comandos `shell' de nivel superior (interno de lftp) termine. `exit parent' termina el shell padre al ejecutar un script anidado. `exit kill' mata todos los trabajos numerados antes de salir. Las opciones se pueden combinar, por ejemplo, `at 08:00 -- exit top kill &' mata todos los trabajos y hace que lftp salga a la hora especificada.

mirror [OPTS] [source [target]]

Duplica el directorio fuente especificado en el directorio destino.

Por defecto, la fuente es remota y el destino es un directorio local. Cuando se usa -R, el directorio fuente es local y el destino es remoto. Si se omite el directorio destino, se utiliza el nombre base del directorio fuente. Si se omiten ambos directorios, se utilizan los directorios locales y remotos actuales.

La fuente y/o el destino pueden ser URLs que apunten a directorios.

Si el directorio destino termina con una barra (excepto el directorio raíz), se le añade el nombre base del directorio fuente.

-c, --continue continúa un trabajo de espejo si es posible
-e, --delete elimina archivos no presentes en la fuente
--delete-excluded elimina archivos excluidos en el destino
--delete-first elimina archivos antiguos antes de transferir los nuevos
--depth-first desciende a los subdirectorios antes de transferir archivos
--scan-all-first escanea todos los directorios recursivamente antes de transferir archivos
-s, --allow-suid establece bits suid/sgid según la fuente
--allow-chown intenta establecer propietario y grupo en los archivos
--ascii transferencias en modo ascii (implica --ignore-size)
--ignore-time ignora la hora al decidir si descargar
--ignore-size ignora el tamaño al decidir si descargar
--only-missing descarga solo archivos faltantes
--only-existing descarga solo archivos que ya existen en el destino
-n, --only-newer descarga solo archivos más nuevos (-c no funcionará)
--upload-older carga archivos incluso más antiguos que los del destino
--transfer-all transfiere todos los archivos, incluso los que parecen iguales en el sitio de destino
--no-empty-dirs no crea directorios vacíos (implica --depth-first)
-r, --no-recursion no entra en subdirectorios
--recursion=MODE entra en subdirectorios según una condición

--overwrite sobrescribe archivos planos sin eliminarlos primero

-N, --newer-than=SPEC descarga solo archivos más nuevos que la hora especificada, o la hora de modificación del archivo local especificado.
--older-than=SPEC descarga solo archivos más antiguos que la hora especificada, o la hora de modificación del archivo local especificado.
--size-range=RANGE descarga solo archivos con tamaño dentro del rango especificado
-P, --parallel[=N] descarga N archivos en paralelo
--use-pget[-n=N] usa pget para transferir cada archivo individualmente
--on-change=CMD ejecuta el comando si algo ha cambiado
--loop repite el espejo hasta que no se encuentren cambios
-i RX, --include=RX incluye archivos que coincidan
-x RX, --exclude=RX excluye archivos que coincidan
-I GP, --include-glob=GP incluye archivos que coincidan
-X GP, --exclude-glob=GP excluye archivos que coincidan
--include-rx-from=FILE
--exclude-rx-from=FILE
--include-glob-from=FILE
--exclude-glob-from=FILE carga patrones de inclusión/exclusión desde el archivo, uno por línea
-f FILE, --file=FILE duplica un solo archivo o grupo de archivos con comodines (ej. /ruta/a/*.txt)
-F DIR, --directory=DIR duplica un solo directorio o grupo de directorios con comodines (ej. /ruta/a/dir*)
-O DIR, --target-directory=DIR ruta base o URL de destino
-v, --verbose[=level] operación detallada
--log=FILE escribe los comandos de lftp que se están ejecutando en FILE
--script=FILE escribe los comandos de lftp en FILE, pero no los ejecuta
--just-print, --dry-run igual que --script=-
--max-errors=N detenerse después de este número de errores
--skip-noaccess no intentar transferir archivos sin acceso de lectura.
--use-cache usa listados de directorios cacheados
--Remove-source-files elimina archivos fuente después de la transferencia (usar con precaución)
--Remove-source-dirs elimina archivos y directorios fuente después de la transferencia (usar con precaución). El directorio de nivel superior no se elimina si su nombre termina con una barra.
--Move igual que --Remove-source-dirs
-a igual que --allow-chown --allow-suid --no-umask

RX es una expresión regular extendida, igual que en egrep(1).

GP es un patrón glob, ej. `*.zip'.

Las opciones de inclusión y exclusión se pueden especificar varias veces. Esto significa que un archivo o directorio se duplicará si coincide con una inclusión y no coincide con ninguna exclusión posterior a la inclusión, o si no coincide con nada y la primera comprobación es una exclusión. Los directorios se comparan con una barra añadida.

Tenga en cuenta que los enlaces simbólicos no se crean al cargar en un servidor remoto, porque el protocolo FTP no puede hacerlo. Para cargar los archivos a los que se refieren los enlaces, use el comando `mirror -RL' (trata los enlaces simbólicos como archivos).

Para las opciones --newer-than y --older-than puede especificar un archivo local o una especificación de tiempo como la usada por el comando at(1), ej. `now-7days' o `week ago'. Si especifica un archivo, se usará la hora de modificación de ese archivo.

El nivel de detalle se puede seleccionar usando la opción --verbose=level o varias opciones -v, ej. -vvv. Los niveles son:

0 - sin salida (predeterminado)
1 - imprime acciones
2 - +imprime nombres de archivos no eliminados (cuando no se especifica -e)
3 - +imprime nombres de directorios que se están duplicando

--only-newer desactiva la comparación de tamaño de archivo y carga/descarga solo archivos más nuevos, incluso si el tamaño es diferente. Por defecto, se transfieren archivos más antiguos y reemplazan a los más nuevos.

--upload-older permite reemplazar archivos remotos más nuevos por unos más antiguos (cuando el lado destino es remoto). Algunos back-ends remotos no pueden conservar las marcas de tiempo, por lo que el valor predeterminado es mantener los archivos más nuevos.

El modo de recursión puede ser `always', `never', `missing', `newer'. Con la opción `newer' el espejo compara las marcas de tiempo de los directorios y entra en un directorio solo si es más antiguo o falta en el lado destino. Tenga en cuenta que cuando un archivo cambia, la marca de tiempo del directorio puede permanecer igual, por lo que el espejo no procesará ese directorio.

Las opciones --file y --directory se pueden usar varias veces e incluso mezcladas siempre que las rutas base de los caminos sean las mismas.

Puede duplicar entre dos servidores si especifica URLs en lugar de directorios. FXP se utiliza automáticamente para transferencias entre servidores FTP, si es posible.

Algunos servidores FTP ocultan los archivos que comienzan con punto por defecto (ej. .htaccess), y solo los muestran cuando se usa el comando LIST con la opción -a. En ese caso, intente usar `set ftp:list-options -a'.

Los modos de recursión `newer' y `missing' entran en conflicto con --scan-all-first, --depth-first, --no-empty-dirs y el ajuste mirror:no-empty-dirs=true.

open [OPTS] sitio

Selecciona un servidor por nombre de host, URL o marcador. Cuando se proporciona una URL o un marcador, cambia automáticamente el directorio de trabajo actual al directorio de la URL. Opciones:

-e cmd ejecuta el comando inmediatamente después de seleccionar el servidor
-u usuario[,contraseña] usa el usuario/contraseña para la autenticación. También se puede usar dos puntos para separar el usuario y la contraseña.
-p puerto usa el puerto para la conexión
-s ranura asigna la conexión a esta ranura
-d habilita la depuración
-B no busca marcadores
--user usuario usa el usuario para la autenticación
--password contraseña usa la contraseña para la autenticación
--env-password toma la contraseña de la variable de entorno LFTP_PASSWORD
sitio nombre de host, URL o nombre de marcador
Si el nombre de usuario contiene caracteres especiales (coma o dos puntos), no use la opción -u, especifíquelo con la opción --user o cítelo en la URL usando la notación de porcentaje %AB.

pget [OPTS] archivo_remoto [-o archivo_local]

Obtiene el archivo especificado utilizando varias conexiones. Esto puede acelerar la transferencia, pero carga mucho la red y el servidor, afectando a otros usuarios. Úselo solo si realmente necesita transferir el archivo lo antes posible. Opciones:

-c continúa la transferencia. Requiere el archivo archivo_local.lftp-pget-status.
-n maxconex establece el número máximo de conexiones (el valor predeterminado se toma de la configuración pget:default-n)

put [-E] [-a] [-c] [-e] [-P N] [-O base] archivo_local [-o archivo_remoto]

Carga archivo_local con el nombre remoto archivo_remoto. Si se omite -o, se utiliza el nombre base de archivo_local como nombre remoto. No expande comodines, use mput para eso.

-o <archivo_remoto> especifica el nombre del archivo remoto (predeterminado: nombre base de archivo_local)
-c continuar, reputar. Requiere permiso para sobrescribir archivos remotos
-E eliminar archivos fuente después de una transferencia exitosa (peligroso)
-e eliminar el archivo de destino antes de la transferencia
-a usar modo ascii (binario es el predeterminado)
-P N cargar N archivos en paralelo
-O <base> especifica el directorio base o URL donde se colocarán los archivos

pwd [-p]

Imprime la URL remota actual. Usa la opción `-p` para mostrar la contraseña en la URL.

queue [-n num ] cmd

Agrega el comando dado a la cola para ejecución secuencial. Cada sitio tiene su propia cola. `-n` agrega el comando antes del elemento dado en la cola. No intente poner en cola los comandos `cd` o `lcd`, puede confundir a lftp. En su lugar, haga el cd/lcd antes del comando `queue`, y recordará el lugar en el que se debe realizar el comando. Es posible poner en cola un trabajo que ya se está ejecutando con `queue wait <jobno>', pero el trabajo continuará su ejecución incluso si no es el primero en la cola.

`queue stop` detendrá la cola, no ejecutará ningún comando nuevo, pero los trabajos que ya se estén ejecutando continuarán ejecutándose. Puede usar `queue stop` para crear una cola vacía y detenida. `queue start` reanudará la ejecución de la cola. Al salir de lftp, iniciará automáticamente todas las colas detenidas.

`queue` sin argumentos creará una cola detenida o imprimirá el estado de la cola.

queue --delete|-d [índice o expresión comodín]

Elimina uno o más elementos de la cola. Si no se proporciona ningún argumento, se elimina la última entrada de la cola.

queue --move|-m <índice o expresión comodín> [índice]

Mueve los elementos dados antes del índice de cola dado, o al final si no se proporciona destino.

-q Silencioso.
-v Verborrea.
-Q Salida en un formato que se puede usar para volver a poner en cola. Útil con --delete.

Ejemplos:

> get file &
[1] get file
> queue wait 1
> queue get another_file
> cd a_directory
> queue get yet_another_file
queue -d 3 Elimina el tercer elemento de la cola.
queue -m 6 4 Mueve el sexto elemento de la cola antes del cuarto.
queue -m "get*zip" 1 Mueve todos los comandos que coincidan con "get*zip" al principio de la cola. (El orden de los elementos se conserva).
queue -d "get*zip" Elimina todos los comandos que coincidan con "get*zip".

quote cmd

Para FTP - envía el comando sin interpretar. Úselo con precaución: puede llevar a un estado remoto desconocido y, por lo tanto, provocará una reconexión. No puede estar seguro de que cualquier cambio en el estado remoto debido a un comando citado sea sólido; puede restablecerse con una reconexión en cualquier momento.

Para HTTP - específico para la acción HTTP. Sintaxis: ``quote <comando> [<args>]''. El comando puede ser ``set-cookie'' o ``post''.

open http://www.site.net
quote set-cookie "variable=value; othervar=othervalue"
set http:post-content-type application/x-www-form-urlencoded
quote post /cgi-bin/script.cgi "var=value&othervar=othervalue" > archivo_local

Para FISH - envía el comando sin interpretar. Esto se puede usar para ejecutar comandos arbitrarios en el servidor. El comando no debe tomar entrada ni imprimir ### al principio de una nueva línea. Si lo hace, el protocolo se desincronizará.

open fish://servidor
quote find -name \*.zip

reget archivo_remoto [-o archivo_local]

Igual que `get -c'.

rels [args]

Igual que `ls', pero ignora la caché.

renlist [args]

Igual que `nlist', pero ignora la caché.

repeat [OPTS] [[-d] retraso] [comando]

Repite el comando especificado con un retraso entre iteraciones. El retraso predeterminado es de un segundo, el comando predeterminado está vacío.

-c <conteo> número máximo de iteraciones
-d <retraso> retraso entre iteraciones
--while-ok detener cuando el comando sale con un código distinto de cero
--until-ok detener cuando el comando sale con un código cero
--weak detener cuando lftp pasa a segundo plano.

Ejemplos:

repeat at tomorrow -- mirror
repeat 1d mirror

reput archivo_local [-o archivo_remoto]

Igual que `put -c'.

rm [-r] [-f] archivos

Elimina archivos remotos. No expande comodines, usa mrm para eso. -r es para eliminar directorios recursivamente. Tenga cuidado, si algo sale mal puede perder archivos. -f suprime mensajes de error.

rmdir dir(s)

Elimina directorios remotos.

scache [sesión]

Lista las sesiones en caché o cambia a la sesión especificada.

set [var [val]]

Establece una variable a un valor dado. Si se omite el valor, anula la configuración de la variable. El nombre de la variable tiene el formato ``nombre/cierre'', donde el cierre puede especificar la aplicación exacta de la configuración. Consulte a continuación para obtener más detalles. Si se llama a set sin una variable, solo se enumeran la configuración modificada. Se puede cambiar mediante opciones:

-a lista todas las configuraciones, incluidos los valores predeterminados
-d lista solo los valores predeterminados, no necesariamente los actuales

site cmd_sitio

Ejecuta el comando site cmd_sitio y muestra el resultado. Puede redirigir su salida.

sleep intervalo

Espera el intervalo de tiempo dado y sale. El intervalo está en segundos de forma predeterminada, pero se puede sufijar con 'm', 'h', 'd' para minutos, horas y días respectivamente. Consulte también at.

slot [nombre]

Selecciona la ranura especificada o lista todas las ranuras asignadas. Una ranura es una conexión a un servidor, similar a una consola virtual. Puede crear varias ranuras conectadas a diferentes servidores y cambiar entre ellas. También puede usar slot:nombre como una pseudo-URL que se evalúa a la ubicación de esa ranura.

La vinculación predeterminada de readline permite cambiar rápidamente entre las ranuras numeradas del 0 al 9 usando las teclas Meta-0 - Meta-9 (a menudo puede usar Alt en lugar de Meta).

cmd:queue-parallel (número)
Número de trabajos que se ejecutan en paralelo en una cola.
cmd:remote-completion (booleano)
un booleano para controlar si lftp utiliza o no la autocompletación remota. Cuando es verdadero, la tecla Tab adivina si la palabra que se está completando debe ser un nombre de archivo remoto. Meta-Tab realiza siempre la autocompletación remota. Así que puedes forzar la autocompletación remota con Meta-Tab cuando cmd:remote-completion es falso o cuando la suposición es incorrecta.
cmd:save-cwd-history (booleano)
cuando es verdadero, lftp guarda el último CWD de cada sitio en ~/.local/share/lftp/cwd_history o ~/.lftp/cwd_history, permitiendo hacer ``cd -'' después de reiniciar lftp. El valor por defecto es verdadero.
cmd:save-rl-history (booleano)
cuando es verdadero, lftp guarda el historial de readline en ~/.local/share/lftp/rl_history o ~/.lftp/rl_history al salir. El valor por defecto es verdadero.
cmd:show-status (booleano)
cuando es falso, lftp no muestra la línea de estado en la terminal. El valor por defecto es verdadero.
cmd:set-term-status (booleano)
cuando es verdadero, lftp actualiza el estado de la terminal si es compatible (por ejemplo, xterm). La clausura para esta configuración es el tipo de terminal de la variable de entorno TERM.
cmd:status-interval (intervalo detiempo)
el intervalo de tiempo entre las actualizaciones de estado.
cmd:stifle-rl-history (número)
el número de líneas a mantener en el historial de readline.
cmd:term-status (cadena)
la cadena de formato a utilizar para mostrar el estado de la terminal. La clausura para esta configuración es el tipo de terminal de la variable de entorno TERM. El valor por defecto utiliza los valores termcap ``tsl'' y ``fsl''.

Los siguientes escapes son compatibles:

\a timbre
\e escape
\n nueva línea
\s "lftp"
\v versión de lftp
\T la cadena de estado
cmd:time-style (cadena)
Esta configuración es el valor por defecto para la opción cls --time-style.
cmd:trace (booleano)
cuando es verdadero, lftp imprime los comandos que ejecuta (como sh -x).
cmd:verify-host (booleano)
si es verdadero, lftp resuelve el nombre del host inmediatamente en el comando `open'. También es posible omitir la verificación para un solo comando `open' si se proporciona `&' o si se presiona ^Z durante la verificación.
cmd:verify-path (booleano)
si es verdadero, lftp verifica la ruta proporcionada en el comando `cd'. También es posible omitir la verificación para un solo comando `cd' si se proporciona `&' o si se presiona ^Z durante la verificación. Ejemplos: 
set cmd:verify-path/hftp://* false
cd directory &
cmd:verify-path-cached (booleano)
Cuando es falso, `cd' a un directorio conocido por la caché como existente tendrá éxito inmediatamente. De lo contrario, la verificación dependerá de la configuración de cmd:verify-path .
color:use-color (tri-booleano)
cuando es verdadero, el comando cls y la salida de autocompletación listan archivos coloreados según la configuración color:dir-colors. Cuando se establece en auto, los colores se utilizan cuando la salida es una terminal.
color:dir-colors (cadena)
descripción del color para la lista de archivos. Por defecto se utiliza el valor de la variable de entorno LS_COLORS. Ver dircolors(1).
dns:SRV-query (booleano)
consulta registros SRV y los utiliza antes de gethostbyname. Los registros SRV solo se utilizan si no se especifica explícitamente el puerto. Ver RFC2052 para detalles.
dns:cache-enable (booleano)
habilita la caché de DNS. Si está desactivada, lftp resuelve el nombre del host cada vez que se reconecta.
dns:cache-expire (intervalo de tiempo)
tiempo de vida de las entradas de la caché de DNS. Tiene el formato <número><unidad>+, por ejemplo, 1d12h30m5s o simplemente 36h. Para deshabilitar la expiración, configúralo a `inf' o `never'.
dns:cache-size (número)
número máximo de entradas en la caché de DNS.
dns:fatal-timeout (intervalo de tiempo)
limita el tiempo para las consultas de DNS. Si el servidor DNS no está disponible durante demasiado tiempo, lftp fallará al resolver un nombre de host dado. Configúralo a `never' para deshabilitarlo.
dns:order (lista de nombres de protocolo)
establece el orden de las consultas de DNS. El valor por defecto es ``inet6 inet'', lo que significa que primero busca la dirección en la familia inet6, luego en la inet y las utiliza en ese orden. Para deshabilitar la consulta inet6 (AAAA), establece esta variable a ``inet''.
dns:use-fork (booleano)
si es verdadero, lftp hará un fork antes de resolver la dirección del host. El valor por defecto es verdadero.
dns:max-retries (número)
Si es cero, no hay límite en el número de veces que lftp intentará buscar una dirección. Si es > 0, lftp intentará solo este número de veces para buscar una dirección de cada familia de direcciones en dns:order.
dns:name (cadena)
Esta configuración se puede utilizar para sustituir un alias de nombre de host por otro nombre o dirección IP. El alias del nombre del host se utiliza como la clausura de la configuración, el nombre o la dirección IP sustituida está en el valor. Se pueden separar varios nombres o direcciones IP por comas.
file:charset (cadena)
conjunto de caracteres local. Se establece a partir de la configuración regional actual inicialmente.
file:use-lock (booleano)
cuando es verdadero, lftp utiliza bloqueos consultivos en archivos locales al abrirlos.
file:use-fallocate (booleano)
cuando es verdadero, lftp utiliza fallocate(2) o posix_fallocate(3) para preasignar espacio de almacenamiento y reducir la fragmentación de archivos en los comandos pget y torrent.
fish:auto-confirm (booleano)
cuando es verdadero, lftp responde ``sí'' a todas las preguntas de ssh, en particular a la pregunta sobre una nueva clave de host. De lo contrario, responde ``no''.
fish:charset (cadena)
el conjunto de caracteres utilizado por el servidor fish en las solicitudes, respuestas y listas de archivos. El valor por defecto es vacío, lo que significa lo mismo que el local.
fish:connect-program (cadena)
el programa a utilizar para conectarse al servidor remoto. Debe admitir la opción `-l' para el nombre de usuario, `-p' para el número de puerto. El valor por defecto es `ssh -a -x'. Puedes establecerlo a `rsh', por ejemplo. Para la autenticación con clave privada, añade la opción `-i' con el archivo de clave.
fish:shell (cadena)
utiliza el shell especificado en el lado del servidor. El valor por defecto es /bin/sh. En algunos sistemas, /bin/sh se cierra al hacer cd a un directorio inexistente. lftp puede manejar eso pero tiene que reconectarse. Establece a /bin/bash para tales sistemas si bash está instalado.
ftp:acct (cadena)
Envía esta cadena en el comando ACCT después de iniciar sesión. El resultado se ignora. La clausura para esta configuración tiene el formato user@host.

el comando para validar la integridad del archivo. El único argumento es la ruta al archivo.

El nombre de una variable puede abreviarse a menos que se vuelva ambiguo. El prefijo antes de `:` también se puede omitir. Puedes establecer una variable varias veces para diferentes cierres, y así obtener una configuración particular para un estado particular. El cierre se especifica después del nombre de la variable separado por una barra `/'.

El cierre para las variables de dominio `dns:', `net:', `ftp:', `http:', `hftp:' es actualmente solo el nombre del host tal como lo especificas en el comando `open' (con algunas excepciones donde el cierre no tiene sentido, por ejemplo, dns:cache-size). Para algunas variables del dominio `cmd:' el cierre es la URL actual sin la ruta. Para las variables del dominio `log:' el cierre es `debug' o `xfer'. Para otras variables actualmente no se usa. Ver ejemplos en el archivo de ejemplo lftp.conf.

Ciertos comandos y configuraciones toman un parámetro de intervalo de tiempo. Tiene el formato Nx[Nx...], donde N es la cantidad de tiempo (punto flotante) y x es la unidad de tiempo: d - días, h - horas, m - minutos, s - segundos. La unidad predeterminada es segundo. Por ejemplo, 5h30m o 5.5h. El intervalo también puede ser `infinity', `inf', `never', `forever' - esto significa un intervalo infinito. Por ejemplo, `sleep forever' o `set dns:cache-expire never'.

Las configuraciones booleanas pueden ser una de (true, on, yes, 1, +) para un valor Verdadero o una de (false, off, no, 0, -) para un valor Falso.

Las configuraciones tri-booleanas tienen un valor booleano o `auto'.

Las configuraciones enteras pueden tener un sufijo: k - kibi, m - mebi, g - gigi, etc. También pueden tener un prefijo: 0 - octal, 0x - hexadecimal.

MODO ASÍNCRONO DE FTP (PIPELINING)

Lftp puede acelerar las operaciones FTP enviando varios comandos a la vez y luego comprobando todas las respuestas. Ver la variable ftp:sync-mode. A veces esto no funciona, por lo tanto, el modo síncrono es el predeterminado. Puedes intentar desactivar el modo síncrono y ver si te funciona. Se sabe que algunos programas de red que manejan la traducción de direcciones funcionan incorrectamente en el caso de varios comandos FTP en un solo paquete de red.

RFC959 dice: ``El proceso de usuario que envía otro comando antes de la respuesta de finalización estaría en violación del protocolo; pero los procesos de servidor-FTP deberían poner en cola cualquier comando que llegue mientras un comando anterior está en progreso''. Además, RFC1123 dice: ``Los implementadores NO DEBEN asumir ninguna correspondencia entre los límites de LECTURA en la conexión de control y las secuencias EOL de Telnet (CR LF).'' y ``una sola LECTURA de la conexión de control puede incluir más de un comando FTP''.

Por lo tanto, debe ser seguro enviar varios comandos a la vez, lo que acelera mucho la operación y parece funcionar con todos los servidores ftp basados en Unix y VMS. Desafortunadamente, los servidores basados en Windows a menudo no pueden manejar varios comandos en un solo paquete, y tampoco algunos enrutadores defectuosos.

-d
Activa el modo de depuración.
-e comandos
Ejecuta los comandos dados y no salgas.
