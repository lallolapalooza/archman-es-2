LZ4(1) Comandos de usuario LZ4(1)

NOMBRE

lz4 - lz4, unlz4, lz4cat - Comprimir o descomprimir archivos .lz4

SINOPSIS

lz4 [OPCIONES] [-|ARCHIVO-ENTRADA] ARCHIVO-SALIDA

unlz4 es equivalente a lz4 -d

lz4cat es equivalente a lz4 -dcfm

Al escribir scripts que necesiten descomprimir archivos, se recomienda utilizar siempre el nombre lz4 con los argumentos apropiados (lz4 -d o lz4 -dc) en lugar de los nombres unlz4 y lz4cat.

DESCRIPCIÓN

lz4 es una CLI basada en liblz4, una implementación extremadamente rápida del algoritmo de compresión sin pérdidas. Ofrece una velocidad de compresión por defecto típicamente superior a 500 MB/s por núcleo. La velocidad puede intercambiarse por una mayor relación de compresión, incrementando el parámetro de nivel de compresión. Mientras que la descompresión es de un solo hilo, alcanza múltiples GB/s, generalmente lo suficientemente rápido como para estar limitado por la E/S. El formato de archivo nativo de lz4 es el formato .lz4.

Diferencia entre lz4 y gzip

lz4 soporta una sintaxis de línea de comandos similar pero no idéntica a la de gzip(1). Las diferencias son:

  • lz4 comprime un solo archivo por defecto (ver -m para múltiples archivos)
  • lz4 archivo1 archivo2 significa: comprimir archivo1 en archivo2
  • lz4 archivo.lz4 por defecto descomprimirá (usar -z para forzar la compresión)
  • lz4 preserva los archivos originales (ver --rm para borrar el archivo fuente al completarse)
  • lz4 muestra estadísticas de notificación en tiempo real durante la compresión o descompresión de un solo archivo (usar -q para silenciarlas)
  • Cuando no se especifica un destino, el resultado se envía a la salida implícita, que depende del estado de stdout. Cuando stdout *no es* la consola, se convierte en la salida implícita. De lo contrario, si stdout es la consola, la salida implícita es nombre_archivo.lz4.
  • Se considera una mala práctica depender de la salida implícita en scripts, porque el entorno del script puede cambiar. Utilizar siempre la salida explícita en scripts. -c asegura que la salida será stdout. Por el contrario, proporcionar un nombre de destino o usar -m asegura que la salida será el nombre especificado o nombre_archivo.lz4 respectivamente.

Los comportamientos por defecto pueden modificarse mediante comandos opt-in, detallados a continuación.

  • lz4 -m hace posible proporcionar múltiples nombres de archivo de entrada, que se comprimirán en archivos usando el sufijo .lz4. Las notificaciones de progreso se deshabilitan por defecto (usar -v para habilitarlas). Este modo tiene un comportamiento que imita más de cerca la línea de comandos de gzip, siendo la principal diferencia restante que los archivos fuente se preservan por defecto.
  • De manera similar, lz4 -m -d puede descomprimir múltiples archivos *.lz4.
  • Es posible optar por borrar los archivos fuente tras una compresión o descompresión exitosa, usando el comando --rm.
  • En consecuencia, lz4 -m --rm presenta un comportamiento más cercano al de gzip.

Concatenación de archivos .lz4

Es posible concatenar archivos .lz4 tal cual. lz4 descomprimirá dichos archivos como si fueran un único archivo .lz4. Por ejemplo:

lz4 archivo1  > foo.lz4
lz4 archivo2 >> foo.lz4

Entonces lz4cat foo.lz4 es equivalente a cat archivo1 archivo2.

OPCIONES

Concatenación de comandos cortos

En algunos casos, algunas opciones pueden expresarse usando comandos cortos -x o comandos largos --palabra-larga. Los comandos cortos pueden concatenarse. Por ejemplo, -d -c es equivalente a -dc. Los comandos largos no pueden concatenarse. Deben estar claramente separados por un espacio.

Comandos múltiples

Cuando se emiten múltiples comandos contradictorios en la misma línea de comandos, solo se aplicará el último.

Modo de operación

-z --compress
Comprimir. Este es el modo de operación por defecto cuando no se especifica ninguna opción de modo de operación, no se infiere ningún otro modo de operación del nombre del comando (por ejemplo, unlz4 implica --decompress), ni de el nombre del archivo de entrada (por ejemplo, una extensión de archivo .lz4 implica --decompress por defecto). -z también puede usarse para forzar la compresión de un archivo .lz4 ya comprimido.
-d --decompress --uncompress
Descomprimir. --decompress es también el modo por defecto cuando el nombre de archivo de entrada tiene una extensión .lz4.
-t --test
Probar la integridad de los archivos .lz4 comprimidos. Los datos descomprimidos se descartan. No se crean ni eliminan archivos.
-b#
Modo de benchmark, usando el nivel de compresión #.
--list
Listar información sobre archivos .lz4. Para información detallada sobre archivos con múltiples tramas, usar -v. --list activa automáticamente el modificador -m.

Modificadores de operación

-#
Nivel de compresión, con # siendo cualquier valor de 1 a 12. Valores más altos intercambian velocidad de compresión por relación de compresión. Los valores superiores a 12 se consideran iguales a 12. Los valores recomendados son 1 para compresión rápida (por defecto), y 9 para alta compresión. La relación velocidad/compresión variará dependiendo de los datos a comprimir. La velocidad de descompresión sigue siendo rápida en todas las configuraciones.
--fast[=#]
Cambiar a niveles de compresión ultrarrápidos. Cuanto mayor sea el valor, más rápida será la velocidad de compresión, a costa de cierta relación de compresión. Si no está presente =#, por defecto es 1. Esta configuración anula el nivel de compresión si se estableció previamente. De manera similar, si se establece un nivel de compresión después de --fast, lo anula.
--best
Establecer el nivel de compresión más alto. Igual que -12.
-T#, --threads=#
Usar # hilos para la compresión. Cuando es 0 o no se proporciona ninguno: determinado automáticamente por el número de núcleos detectados.
--favor-decSpeed
Generar datos comprimidos optimizados para la velocidad de descompresión. Los datos comprimidos serán más grandes como consecuencia (típicamente un ~0.5%), mientras que la velocidad de descompresión mejorará entre un 5-20%, dependiendo de los casos de uso. Esta opción solo funciona en combinación con niveles de compresión muy altos (>=10).
-D diccionarioNombre
Comprimir, descomprimir o realizar benchmark usando el diccionario diccionarioNombre. La compresión y descompresión deben usar el mismo diccionario para ser compatibles. Usar un diccionario diferente durante la descompresión abortará debido a un error de descompresión o generará un error de suma de verificación.
-f --[no-]force
Esta opción tiene varios efectos:
Si el archivo de destino ya existe, sobrescribirlo sin preguntar.
Cuando se usa con --decompress y lz4 no puede reconocer el tipo del archivo fuente, copia el archivo fuente tal cual a la salida estándar. Esto permite usar lz4cat --force como cat (1) para archivos que no han sido comprimidos con lz4.
-c --stdout --to-stdout
Forzar la escritura a la salida estándar, e lz4(1) - Manual Arch Linux

NAME

lz4 - lz4 command line interface

SYNOPSIS

lz4 [OPTIONS] [INPUT [OUTPUT]]

lz4 [OPTIONS] - [OUTPUT]

lz4 [OPTIONS] -z [INPUT [OUTPUT]]

lz4 [OPTIONS] -d [INPUT [OUTPUT]]

lz4 [OPTIONS] --

DESCRIPTION

lz4 is a very fast lossless compression algorithm, with compression ratios close to zlib.

This man page documents the lz4 command-line utility.

lz4 offers the following compression features:

-z, --compress
Compress.
-d, --decompress
Decompress.
-f, --force
Force overwrite of output file and potentially ignore data validity checks.
-N, --no-frame
Disable frame end marks. Useful for stream compression, but may corrupt data if it is not a stream.
-a, --[no-]auto-lzfse
Automatically switch to lzfse compression on macOS.
-c, --stdout
Write to standard output and bypass file system.
-b
Perform benchmark. This is usually done using a test file.
-B#
Block size [4-7](default : 7)
-B4= 64KB ; -B5= 256KB ; -B6= 1MB ; -B7= 4MB
-BI
Produce independent blocks (default)
-BD
Blocks depend on predecessors (improves compression ratio, more noticeable on small blocks)
-BX
Generate block checksums (default:disabled)
--[no-]frame-crc
Select frame checksum (default:enabled)
--no-crc
Disable both frame and block checksums
--[no-]content-size
Header includes original size (default:not present)
Note : this option can only be activated when the original size can be determined, hence for a file. It won´t work with unknown source size, such as stdin or pipe.
--[no-]sparse
Sparse mode support (default:enabled on file, disabled on stdout)
-l
Use Legacy format (typically for Linux Kernel compression)
Note : -l is not compatible with -m (--multiple) nor -r

Other options

-v --verbose
Verbose mode
-q --quiet
Suppress warnings and real-time statistics; specify twice to suppress errors too
-h -H --help
Display help/long help and exit
-V --version
Display Version number and exit
-k --keep
Preserve source files (default behavior)
--rm
Delete source files on successful compression or decompression
--
Treat all subsequent arguments as files

Benchmark mode

-b#
Benchmark file(s), using # compression level
-e#
Benchmark multiple compression levels, from b# to e# (included)
-i#
Minimum evaluation time in seconds [1-9] (default : 3)

Environment Variables

It´s possible to pass some parameters to lz4 via environment variables. This can be useful in situations where lz4 is known to be invoked (from a script for example) but there is no way to pass lz4 parameters to influence the compression session. The environment variable has higher priority than executable default, but lower priority than corresponding runtime command. When set as global environment variables, it can be a way to enforce personalized defaults different from the executable set ones.

LZ4_CLEVEL
specify a default compression level that lz4 employs for compression when no other compression level is specified on command line. Executable default is generally 1.
LZ4_NBWORKERS
specify a default number of threads that lz4 will employ for compression. Executable default is generally 0, which means auto-determined based on local cpu. This functionality is only relevant when lz4 is compiled with multithreading support. The maximum number of workers is capped at LZ4_NBWORKERS_MAX (200 by default).
