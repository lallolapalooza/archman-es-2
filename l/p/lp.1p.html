LP(1P) Manual del Programador POSIX LP(1P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

lp — enviar archivos a una impresora

SINOPSIS

lp [-c] [-d destino] [-n copias] [-msw] [-o opción]... [-t título] [archivo...]

DESCRIPCIÓN

La utilidad lp copiará los archivos de entrada a un destino de salida de una manera no especificada. El destino de salida por defecto debe ser un dispositivo de copia impresa, como una impresora o una microfilmadora, que produzca documentos no volátiles y legibles por humanos. Si dicha dispositivo no está disponible para la aplicación, o si el sistema no proporciona dicho dispositivo, la utilidad lp saldrá con un estado de salida distinto de cero.

La escritura real en el dispositivo de salida puede ocurrir algún tiempo después de que la utilidad lp salga correctamente. Durante la porción de la escritura que corresponde a cada archivo de entrada, la implementación garantizará acceso exclusivo al dispositivo.

La utilidad lp asociará un ID de solicitud único con cada solicitud.

Normalmente, se produce una página de encabezado para separar e identificar cada trabajo de impresión. Esta página puede suprimirse bajo condiciones definidas por la implementación, como un comando del operador o uno de los valores de la opción -o.

OPCIONES

La utilidad lp cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de Sintaxis de Utilidades.

Se admitirán las siguientes opciones:

-c
Salir solo después de que ya no se requiera acceso adicional a ninguno de los archivos de entrada. La aplicación puede entonces eliminar o modificar los archivos de forma segura sin afectar la operación de salida. Normalmente, los archivos no se copian, sino que se enlazan siempre que sea posible. Si la opción -c no se proporciona, el usuario debe tener cuidado de no eliminar ninguno de los archivos antes de que se imprima la solicitud en su totalidad. También debe notarse que, en ausencia de la opción -c, cualquier cambio realizado en los archivos con nombre después de que se realice la solicitud pero antes de que se imprima puede reflejarse en la salida impresa. En algunas implementaciones, -c puede estar activado por defecto.
-d destino
Especificar una cadena que nombre el destino (destino). Si destino es una impresora, la solicitud se imprimirá solo en esa impresora específica. Si destino es una clase de impresoras, la solicitud se imprimirá en la primera impresora disponible que sea miembro de la clase. Bajo ciertas condiciones (no disponibilidad de la impresora, limitación de espacio de archivos, etc.), las solicitudes para destinos específicos no necesitan ser aceptadas. Los nombres de destino varían entre sistemas.

Si no se especifica -d, y ni la variable de entorno LPDEST ni PRINTER están establecidas, se usa un destino no especificado. La opción -d destino tendrá prioridad sobre LPDEST, que a su vez tendrá prioridad sobre PRINTER. Los resultados no están definidos cuando destino contiene un valor que no es un nombre de destino válido.

-m
Enviar correo (ver mailx) después de que los archivos se hayan impreso. Por defecto, no se envía correo al finalizar correctamente la solicitud de impresión.
-n copias
Escribir copias número de copias de los archivos, donde copias es un entero decimal positivo. Los métodos para producir copias múltiples y para organizar las copias múltiples cuando se usan múltiples operandos archivo no están especificados, excepto que cada archivo se presentará como una unidad integral, no intercalado con porciones de otros archivos.
-o opción
Especificar opciones dependientes de la impresora o de la clase. Varias de estas opciones pueden recopilarse especificando la opción -o más de una vez.
-s
Suprimir mensajes de lp.
-t título
Escribir título en la página de encabezado de la salida.
-w
Escribir un mensaje en la terminal del usuario después de que los archivos se hayan impreso. Si el usuario no ha iniciado sesión, se enviará correo en su lugar.

OPERANDOS

Se admitirá el siguiente operando:

archivo
Una ruta de un archivo que se va a enviar a salida. Si no se especifican operandos archivo, o si un operando archivo es '-', se usará la entrada estándar. Si se utiliza un operando archivo, pero no se especifica la opción -c, el proceso que realiza la escritura en el dispositivo de salida puede tener permisos de usuario y grupo diferentes a los del proceso que invoca lp.

STDIN

La entrada estándar solo se usará si no se especifican operandos archivo, o si un operando archivo es '-'. Consulte la sección ARCHIVOS DE ENTRADA.

ARCHIVOS DE ENTRADA

Los archivos de entrada serán archivos de texto.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de lp:

LANG
Proporcionar un valor por defecto para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de Internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización.)
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determinar la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida estándar de error y los mensajes informativos escritos en la salida estándar.
LC_TIME
Determinar el formato y el contenido de las cadenas de fecha y hora mostradas en la página de encabezado de lp, si la hay.
LPDEST
Determinar el destino. Si la variable de entorno LPDEST no está establecida, se utilizará la variable de entorno PRINTER. La opción -d destino tiene prioridad sobre LPDEST. Los resultados no están definidos cuando destino contiene un valor que no es un nombre de destino válido.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.
PRINTER
Determinar el dispositivo o destino de salida. Si las variables de entorno LPDEST y PRINTER no están establecidas, se utiliza un dispositivo de salida no especificado. La opción -d destino y la variable de entorno LPDEST tendrán prioridad sobre PRINTER. Los resultados no están definidos cuando -d no se especifica, LPDEST no está establecida y PRINTER contiene un valor que no es un nombre de dispositivo o destino válido.

EVENTOS ASÍNCRONOS

Por defecto.

STDOUT

La utilidad lp escribirá un ID de solicitud en la salida estándar, a menos que se especifique -s. El formato del mensaje no se especifica. El ID de solicitud se puede usar en sistemas que admitan las utilidades históricas cancel y lpstat.

STDERR

La salida de error estándar se utilizará solo para mensajes diagnósticos.

ARCHIVOS DE SALIDA

Ninguno.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

0
Todos los archivos de entrada se procesaron correctamente.
>0
No había ningún dispositivo de salida disponible o se produjo un error.

CONSECUENCIAS DE LOS ERRORES

Por defecto.

USO DE LA APLICACIÓN

Las utilidades pr y fold se pueden utilizar para lograr un formato razonable para el tamaño de página predeterminado de la implementación.

Una aplicación compatible puede usar uno de los operandos de archivo solo con la opción -c o si el archivo es legible públicamente y se garantiza que estará disponible en el momento de la impresión. Esto se debe a que POSIX.1-2008 otorga a la implementación la libertad de poner en cola la solicitud para su impresión en un momento posterior por un proceso diferente que podría no poder acceder al archivo.

EJEMPLOS

1.
Para imprimir el archivo archivo:
lp -c archivo
2.
Para imprimir varios archivos con encabezados:
pr archivo1 archivo2 | lp

FUNDAMENTACIÓN

La utilidad lp fue diseñada para ser una versión básica de una utilidad que ya está disponible en muchas implementaciones históricas. Los desarrolladores del estándar consideraron que debería ser implementable simplemente como:

cat "$@" > /dev/lp

después del procesamiento adecuado de las opciones, si esa fuera la forma en que la implementación eligiera hacerlo y si se pudiera otorgar acceso exclusivo (para que dos usuarios no escribieran en el dispositivo simultáneamente). Aunque en el futuro los desarrolladores del estándar puedan agregar otras opciones a esta utilidad, siempre debería poder ejecutarse sin opciones ni operandos y enviar la entrada estándar a un dispositivo de salida no especificado.

Este volumen de POSIX.1-2017 no hace representaciones sobre el formato de la salida impresa, excepto que debe ser "legible por humanos" y "no volátil". Por lo tanto, escribir por defecto a una unidad de disco o cinta o a una terminal de pantalla no calificaría. (Sin embargo, dichos destinos no están prohibidos cuando se utilizan -d dest, LPDEST o PRINTER).

Este volumen de POSIX.1-2017 está redactado de tal manera que un "trabajo de impresión" que consta de múltiples archivos de entrada, posiblemente en múltiples copias, está garantizado para imprimirse de modo que ningún archivo se mezcle con otro, pero no hay ninguna declaración de que todos los archivos o copias deban imprimirse juntos.

La opción -c puede implicar una operación de puesta en cola, pero esto no es obligatorio. La utilidad se puede implementar para esperar hasta que la impresora esté lista y luego esperar hasta que termine. Debido a eso, no hay ningún intento de definir un mecanismo de cola (prioridades, clases de salida, etc.).

En algunos sistemas históricos, el ID de solicitud informado en STDOUT se puede utilizar para cancelar o encontrar el estado de una solicitud posteriormente utilizando utilidades no definidas en este volumen de POSIX.1-2017.

Aunque las utilidades históricas lp de System V y lpr de BSD proporcionaban una funcionalidad similar, utilizaban nombres diferentes para la variable de entorno que especificaba la impresora de destino. Dado que el nombre de la utilidad aquí es lp, se le dio prioridad a LPDEST (utilizado por la utilidad lp de System V) sobre PRINTER (utilizado por la utilidad lpr de BSD). Dado que los entornos de los usuarios a menudo contienen una u otra variable de entorno, se requiere que la utilidad lp reconozca ambas. Si no se hiciera esto, muchas aplicaciones enviarían la salida a dispositivos de salida inesperados cuando los usuarios se mudaran de un sistema a otro.

Algunos han comentado que lp tiene muy poca funcionalidad para que valga la pena. Las solicitudes han propuesto opciones o operandos adicionales o ambos que agregaban funcionalidad. Las solicitudes incluían:

*
Redactar exigiendo que la salida sea "impresión física"
*
Un requisito para múltiples impresoras
*
Opciones para admitir varios lenguajes de descripción de página

Dado que un sistema compatible no está obligado a tener siquiera una impresora, imponer más restricciones al comportamiento de la impresora no es útil. Dado que el formato de impresión física depende tanto de la aplicación, es difícil, si no imposible, seleccionar un subconjunto razonable de funcionalidades que deba requerirse en todos los sistemas compatibles.

El término no especificado se utiliza en esta sección en lugar de definido por la implementación, ya que la mayoría de las implementaciones conocidas no podrían hacer declaraciones definitivas en sus documentos de conformidad; la existencia y el uso de impresoras dependen mucho de cómo el administrador del sistema configure cada sistema individual.

Dado que el destino predeterminado, el tipo de dispositivo, los mecanismos de cola y las formas de entrada aceptables no se especifican, las guías de uso sobre lo que una aplicación compatible puede hacer son las siguientes:

*
Utilice el comando en una tubería, o con -c, para que no haya problemas de permisos y los archivos se puedan eliminar o modificar de forma segura.
*
Limite la salida a archivos de texto con longitudes de línea razonables y caracteres imprimibles, y no incluya información de formato específica del dispositivo, como un lenguaje de descripción de página. El significado de "razonable" en este contexto solo puede responderse como una cuestión de calidad de implementación, pero debería ser evidente por los patrones de uso histórico en la industria y la configuración regional. Las utilidades pr y fold se pueden utilizar para lograr un formato razonable para el tamaño de página predeterminado de la implementación.

Alternativamente, la aplicación puede organizar su instalación de tal manera que requiera que el administrador del sistema o el operador proporcione la información apropiada sobre las opciones de lp y los valores de las variables de entorno.

Como mínimo, tener esta utilidad en este volumen de POSIX.1-2017 le dice a la industria que las aplicaciones compatibles requieren un medio para imprimir la salida y proporciona al menos un nombre de comando y un mecanismo de enrutamiento LPDEST que se pueden utilizar para discusiones entre vendedores, desarrolladores de aplicaciones y usuarios. El uso de "debería" en la DESCRIPCIÓN de lp muestra claramente la intención de los desarrolladores del estándar, incluso si no pueden exigir que todos los sistemas (como las computadoras portátiles) tengan impresoras.

Este volumen de POSIX.1-2017 no especifica cuál será la propiedad del proceso que realiza la escritura en el dispositivo de salida. Si no se usa -c, no se especifica si el proceso que realiza la escritura en el dispositivo de salida tiene permiso para leer archivo si existen restricciones sobre quién puede leer archivo hasta después de que se imprima. Además, si no se usa -c, los resultados de eliminar archivo antes de que se imprima no se especifican.
