l2cap(7) Administración del sistema Linux l2cap(7)

Nombre

l2cap - Protocolo L2CAP

SINOPSIS

#include <sys/socket.h>
#include <bluetooth/bluetooth.h>
#include <bluetooth/l2cap.h>
l2cap_socket = socket(PF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_L2CAP);

DESCRIPCIÓN

L2CAP es un protocolo que proporciona una interfaz para que los protocolos de nivel superior envíen y reciban datos a través de una conexión Bluetooth. L2CAP se sitúa sobre la Interfaz del Controlador Host Bluetooth (HCI) y proporciona un conjunto de canales que pueden ser utilizados por protocolos de nivel superior para transmitir datos.

L2CAP proporciona una serie de servicios a los protocolos de nivel superior, incluyendo la segmentación y reensamblaje de paquetes de datos grandes y el control de flujo para evitar la sobrecarga del receptor. L2CAP también soporta múltiples canales por conexión, permitiendo la transmisión concurrente de datos utilizando diferentes protocolos.

DIRECCIÓN DEL SOCKET

struct sockaddr_l2 {
    sa_family_t     l2_family;
    unsigned short  l2_psm;
    bdaddr_t        l2_bdaddr;
    unsigned short  l2_cid;
    uint8_t         l2_bdaddr_type;
};

Ejemplo:

struct sockaddr_l2 addr;
memset(&addr, 0, sizeof(addr));
addr.l2_family = AF_BLUETOOTH;
bacpy(&addr.l2_bdaddr, bdaddr);
if (cid)
    addr.l2_cid = htobs(cid);
else
    addr.l2_psm = htobs(psm);
addr.l2_bdaddr_type = bdaddr_type;

OPCIONES DEL SOCKET (SOL_BLUETOOTH)

Las opciones de socket listadas a continuación se pueden establecer usando setsockopt(2) y leer con getsockopt(2) con el nivel de socket establecido en SOL_BLUETOOTH.

BT_SEGURIDAD (desde Linux 2.6.30)

Nivel de seguridad del canal, valores posibles:

Valor Nivel de Seguridad Tipo de Clave de Enlace Cifrado
BT_SECURITY_SDP 0 (Solo SDP) Ninguno No requerido
BT_SECURITY_LOW 1 (Bajo) No autenticado No requerido
BT_SECURITY_MEDIUM 2 (Medio - por defecto) No autenticado Deseado
BT_SECURITY_HIGH 3 (Alto) Autenticado Requerido
BT_SECURITY_FIPS (desde Linux 3.15) 4 (Solo Seguro) Autenticado (Emparejamiento Simple Seguro basado en P-256 y Autenticación Segura) Requerido

Ejemplo:

int level = BT_SECURITY_HIGH;
int err = setsockopt(l2cap_socket, SOL_BLUETOOTH, BT_SECURITY, &level,
                     sizeof(level));
if (err == -1) {
    perror("setsockopt");
    return 1;
}

BT_APLAZAR_CONFIGURACIÓN (desde Linux 2.6.30)

Configuración aplazada de la conexión del canal, esto controla si el procedimiento de conexión necesita ser autorizado por el espacio de usuario antes de responder, lo que permite la autorización a nivel de perfil, valores posibles:

Valor Descripción Autorización
0 Deshabilitar (por defecto) No requerido
1 Habilitar Requerido

Ejemplo:

int defer_setup = 1;
int err = setsockopt(l2cap_socket, SOL_BLUETOOTH, BT_DEFER_SETUP,
                     &defer_setup, sizeof(defer_setup));
if (err == -1) {
    perror("setsockopt");
    return err;
}
err = listen(l2cap_socket, 5);
if (err) {
    perror("listen");
    return err;
}
struct sockaddr_l2 remote_addr = {0};
socklen_t addr_len = sizeof(remote_addr);
int new_socket = accept(l2cap_socket, (struct sockaddr*)&remote_addr,
                        &addr_len);
if (new_socket < 0) {
    perror("accept");
    return new_socket;
}
/* Para completar la configuración de la conexión de new_socket, lee 1 byte */
char c;
struct pollfd pfd;
memset(&pfd, 0, sizeof(pfd));
pfd.fd = new_socket;
pfd.events = POLLOUT;
err = poll(&pfd, 1, 0);
if (err) {
    perror("poll");
    return err;
}
if (!(pfd.revents & POLLOUT)) {
    err = read(sk, &c, 1);
    if (err < 0) {
        perror("read");
        return err;
    }
}

BT_DESECHABLE (desde Linux 2.6.39)

Bandera de desechabilidad del canal, esto controla si los datos del canal pueden ser desechados o no, valores posibles:

Definición Valor Descripción
BT_FLUSHABLE_OFF 0x00 (por defecto) No desechar datos
BT_FLUSHABLE_ON 0x01 Desechar datos

BT_ENERGÍA (desde Linux 3.1)

Política de energía del canal, esto controla si el canal debe forzar la salida del modo de espera (sniff) o no, valores posibles:

Definición Valor Descripción
BT_POWER_FORCE_ACTIVE_OFF 0x00 No forzar salida del modo de espera
BT_POWER_FORCE_ACTIVE_ON 0x01 (por defecto) Forzar salida del modo de espera

BT_POLÍTICA_CANAL (desde Linux 3.10)

Política de canal de alta velocidad (AMP), valores posibles:

Definición Valor Descripción
BT_CHANNEL_POLICY_BREDR_ONLY 0 (por defecto) Solo BR/EDR
BT_CHANNEL_POLICY_BREDR_PREFERRED 1 BR/EDR Preferido
BT_CHANNEL_POLICY_BREDR_PREFERRED 2 AMP Preferido

BT_PHY (desde Linux 5.10)

PHY(s) compatibles con el canal, valores posibles:

Define Valor Descripción
BT_PHY_BR_1M_1SLOT BIT 0 BR 1Mbps 1SLOT
BT_PHY_BR_1M_3SLOT BIT 1 BR 1Mbps 3SLOT
BT_PHY_BR_1M_5SLOT BIT 2 BR 1Mbps 5SLOT
BT_PHY_BR_2M_1SLOT BIT 3 EDR 2Mbps 1SLOT
BT_PHY_BR_2M_3SLOT BIT 4 EDR 2Mbps 3SLOT
BT_PHY_BR_2M_5SLOT BIT 5 EDR 2Mbps 5SLOT
BT_PHY_BR_3M_1SLOT BIT 6 EDR 3Mbps 1SLOT
BT_PHY_BR_3M_3SLOT BIT 7 EDR 3Mbps 3SLOT
BT_PHY_BR_3M_5SLOT BIT 8 EDR 3Mbps 5SLOT
BT_PHY_LE_1M_TX BIT 9 LE 1Mbps TX
BT_PHY_LE_1M_RX BIT 10 LE 1Mbps RX
BT_PHY_LE_2M_TX BIT 11 LE 2Mbps TX
BT_PHY_LE_2M_RX BIT 12 LE 2Mbps RX
BT_PHY_LE_CODED_TX BIT 13 LE Coded TX
BT_PHY_LE_CODED_RX BIT 14 LE Coded RX

BT_MODE (desde Linux 5.10)

Modo del canal, valores posibles:

Define Valor Descripción Enlace
BT_MODE_BASIC 0x00 (predeterminado) Modo básico Cualquiera
BT_MODE_ERTM 0x01 Modo de retransmisión mejorada BR/EDR
BT_MODE_STREAM 0x02 Modo de flujo BR/EDR
BT_MODE_LE_FLOWCTL 0x03 Modo de control de flujo basado en créditos LE
BT_MODE_EXT_FLOWCTL 0x04 Modo de control de flujo extendido basado en créditos Cualquiera

OPCIONES DE SOCKET (SOL_SOCKET)

Las opciones de socket de nivel SOL_SOCKET que modifican las características genéricas del socket (SO_SNDBUF, SO_RCVBUF, etc.) tienen su significado habitual, véase socket(7).

Las opciones de socket L2CAP de nivel SOL_SOCKET que tienen manejo específico de Bluetooth en el kernel se enumeran a continuación.

SO_TIMESTAMPING, SO_TIMESTAMP, SO_TIMESTAMPNS

Véase https://docs.kernel.org/networking/timestamping.html

Para sockets L2CAP, se admiten las marcas de tiempo de recepción de software. Las marcas de tiempo de transmisión de software (SOF_TIMESTAMPING_TX_SOFTWARE, SOF_TIMESTAMPING_TX_COMPLETION) son compatibles desde Linux 6.15.

La marca de tiempo de recepción de software es el momento en que el kernel recibió el paquete del controlador del controlador.

La marca de tiempo SCM_TSTAMP_SND se emite cuando el paquete se envía al controlador del controlador. La marca de tiempo SCM_TSTAMP_COMPLETION se emite cuando el controlador informa que el paquete se ha completado. Otros tipos de marcas de tiempo de transmisión no son compatibles.

Puede utilizar SIOCETHTOOL para consultar las banderas soportadas.

Las marcas de tiempo están en el tiempo CLOCK_REALTIME.

Ejemplo (Habilitar marcas de tiempo de recepción):

int flags = SOF_TIMESTAMPING_SOFTWARE |
    SOF_TIMESTAMPING_RX_SOFTWARE;
setsockopt(fd, SOL_SOCKET, SO_TIMESTAMPING, &flags, sizeof(flags));

Ejemplo (Leer paquete y su marca de tiempo de recepción):

char data_buf[256];
union {
    char buf[CMSG_SPACE(sizeof(struct scm_timestamping))];
    struct cmsghdr align;
} control;
struct iovec data = {
    .iov_base = data_buf,
    .iov_len = sizeof(data_buf),
};
struct msghdr msg = {
    .msg_iov = &data,
    .msg_iovlen = 1,
    .msg_control = control.buf,
    .msg_controllen = sizeof(control.buf),
};
struct scm_timestamping tss;
res = recvmsg(fd, &msg, MSG_ERRQUEUE | MSG_DONTWAIT);
if (res < 0)
    goto error;
for (cmsg = CMSG_FIRSTHDR(&msg); cmsg; cmsg = CMSG_NXTHDR(&msg, cmsg)) {
    if (cmsg->cmsg_level == SOL_SOCKET && cmsg->cmsg_type == SCM_TIMESTAMPING)
        memcpy(&tss, CMSG_DATA(cmsg), sizeof(tss));
}
tstamp_clock_realtime = tss.ts[0];

Ejemplo (Habilitar marcas de tiempo de transmisión):

int flags = SOF_TIMESTAMPING_SOFTWARE |
    SOF_TIMESTAMPING_TX_SOFTWARE |
    SOF_TIMESTAMPING_TX_COMPLETION |
    SOF_TIMESTAMPING_OPT_ID;
setsockopt(fd, SOL_SOCKET, SO_TIMESTAMPING, &flags, sizeof(flags));

Ejemplo (Leer marcas de tiempo de transmisión):

union {
    char buf[2 * CMSG_SPACE(sizeof(struct scm_timestamping))];
    struct cmsghdr align;
} control;
struct iovec data = {
    .iov_base = NULL,
    .iov_len = 0
};
struct msghdr msg = {
    .msg_iov = &data,
    .msg_iovlen = 1,
    .msg_control = control.buf,
    .msg_controllen = sizeof(control.buf),
};
struct cmsghdr *cmsg;
struct scm_timestamping tss;
struct sock_extended_err serr;
int res;
res = recvmsg(fd, &msg, MSG_ERRQUEUE | MSG_DONTWAIT);
if (res < 0)
    goto error;
for (cmsg = CMSG_FIRSTHDR(&msg); cmsg; cmsg = CMSG_NXTHDR(&msg, cmsg)) {
    if (cmsg->cmsg_level == SOL_SOCKET && cmsg->cmsg_type == SCM_TIMESTAMPING)
        memcpy(&tss, CMSG_DATA(cmsg), sizeof(tss));
    else if (cmsg->cmsg_level == SOL_BLUETOOTH && cmsg->cmsg_type == BT_SCM_ERROR)
        memcpy(&serr, CMSG_DATA(cmsg), sizeof(serr));
}
tstamp_clock_realtime = tss.ts[0];
tstamp_type = serr->ee_info;      /* SCM_TSTAMP_SND o SCM_TSTAMP_COMPLETION */
tstamp_seqnum = serr->ee_data;

IOCTLS

Los siguientes ioctls con operaciones específicas para sockets L2CAP están disponibles.

SIOCETHTOOL (desde Linux 6.16-rc1)

Solo soporta el comando ETHTOOL_GET_TS_INFO, que puede ser utilizado para consultar las banderas SOF_TIMESTAMPING_* soportadas. Las banderas SOF_TIMESTAMPING_OPT_* siempre están disponibles según corresponda.

Ejemplo:

#include <linux/ethtool.h>
#include <linux/sockios.h>
#include <net/if.h>
#include <sys/socket.h>
#include <sys/ioctl.h>
...
struct ifreq ifr = {};
struct ethtool_ts_info cmd = {};
int sk;
snprintf(ifr.ifr_name, sizeof(ifr.ifr_name), "hci0");
ifr.ifr_data = (void *)&cmd;
cmd.cmd = ETHTOOL_GET_TS_INFO;
sk = socket(PF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_L2CAP);
if (sk < 0)
    goto error;
if (ioctl(sk, SIOCETHTOOL, &ifr))
    goto error;
sof_available = cmd.so_timestamping;

l2cap(7)

Nombre

l2cap — Interfaz del protocolo de nivel de retransmisión de línea de comandos de Bluetooth

SINÓPSIS

#include <sys/socket.h>
#include <bluetooth/bluetooth.h>
#include <bluetooth/l2cap.h>

int socket(AF_BLUETOOTH, SOCK_RAW, BTPROTO_L2CAP);

int socket(AF_BLUETOOTH, SOCK_SEQPACKET, 0);

DESCRIPCIÓN

El protocolo L2CAP (Protocolo de Relevancia de Nivel de Comandos) es un protocolo de red sobre el enlace de datos de Bluetooth. Proporciona una conexión orientada a la conexión y un servicio de datagramas sin conexión para las aplicaciones de capa superior.

Las aplicaciones pueden usar L2CAP mediante dos tipos de sockets:

SOCK_RAW
Permite a las aplicaciones enviar y recibir paquetes L2CAP sin procesar. Esto es principalmente para el control de la máquina de estados L2CAP. Se requiere que el programador de la aplicación maneje la creación y el desmontaje de canales L2CAP.
SOCK_SEQPACKET
Proporciona una interfaz de socket más amigable para aplicaciones que usan canales L2CAP orientados a la conexión. El sistema operativo se encarga de la creación y el desmontaje de canales L2CAP.

El socket debe crearse con la familia de direcciones AF_BLUETOOTH.

DIRECCIÓN DEL SOCKET

La estructura del socket L2CAP es la misma que la estructura del socket Bluetooth genérica:

struct sockaddr_rc {
    sa_family_t    rc_family;
    bdaddr_t       rc_bdaddr;
    uan_t          rc_unit;
};

donde

rc_family
Debe ser AF_BLUETOOTH.
rc_bdaddr
La dirección del dispositivo Bluetooth local o remoto. Si es BDADDR_ANY, se utilizará la primera interfaz Bluetooth disponible.
rc_unit
El identificador de la unidad L2CAP.

Para los sockets SOCK_SEQPACKET, la dirección se utiliza para la operación connect() y bind().

La dirección del socket para los sockets SOCK_RAW se utiliza para las operaciones bind() y connect(). El campo rc_unit se utiliza para especificar el canal L2CAP. El canal 0 está reservado para el canal de control.

OPCIONES DEL SOCKET (SOL_BLUETOOTH)

Las siguientes opciones de socket están disponibles en el nivel SOL_BLUETOOTH:

BTPROTO_TRANSPORT
Establece el tipo de transporte Bluetooth que se utilizará. Los valores posibles son BT_TRANSPORT_BREDR (para clásico) y BT_TRANSPORT_LE (para bajo consumo).

OPCIONES DEL SOCKET (SOL_SOCKET)

Las siguientes opciones de socket están disponibles en el nivel SOL_SOCKET:

SO_RCVBUF
Establece el tamaño del búfer de recepción. Para los sockets L2CAP, esto corresponde al tamaño máximo de un paquete que se puede recibir.
SO_SNDBUF
Establece el tamaño del búfer de transmisión. Para los sockets L2CAP, esto corresponde al tamaño máximo de un paquete que se puede enviar.

IOCTLS

Los siguientes IOCTL están disponibles para los sockets L2CAP:

SIOC*
La interfaz ioctl() no está implementada para sockets L2CAP.
