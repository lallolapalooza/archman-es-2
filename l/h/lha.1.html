lha(1) Manual de Comandos Generales lha(1)

NOMBRE

lha - herramienta de compresión para archivos .lzh.

SINOPSIS

lha [-]{lvtxep[q{num}][finv]}[w=<dir>] archivo_archivado [archivo ...]

DESCRIPCIÓN

lha es una herramienta para extraer archivos .lzh. También soporta variantes del archivo .lzh, como .lzs y .pma.

Esta versión de la herramienta lha es parte de Lhasa, una implementación libre del formato .lzh.

SINTAXIS DE COMANDOS

La herramienta lha tiene una sintaxis de comando inusual, en comparación con la mayoría de los otros comandos de Unix. El primer parámetro del programa especifica el comando a realizar y todas las opciones adicionales. El segundo parámetro especifica la ruta al archivo de archivo sobre el que operar. A esto le sigue una lista de patrones comodín para hacer coincidir con los nombres de los archivos archivados.

El primer carácter del parámetro de comando especifica el comando a realizar, que es uno de los siguientes:

-l
Listar el contenido del archivo especificado.
-v
Listar de forma detallada el contenido del archivo especificado.
-t
Probar la integridad del archivo especificado: descomprimir su contenido y verificar la CRC.
-e o -x
Extraer archivo. Los archivos se extraen al directorio de trabajo actual a menos que se especifique la opción 'w'.
-p
Extraer archivo, enviando los archivos descomprimidos a stdout en lugar de escribirlos en el sistema de archivos como archivos reales. Esto es útil cuando se utiliza como parte de una tubería de shell.

OPCIONES

El resto del parámetro de comando se utiliza para especificar opciones adicionales:

q[012]
Modo silencioso. Números más altos suprimen más salida. El nivel 0 es la operación normal. Si no se especifica ningún número, se utiliza la supresión total (nivel 2). La opción silenciosa también activa la opción de sobrescritura forzada ('f').
f
Sobrescribir forzadamente archivos existentes: no preguntar.
i
Ignorar rutas de archivos archivados: extraer todos los archivos archivados al mismo directorio, ignorando subdirectorios.
n
No realizar ninguna operación real: en su lugar, realizar una ejecución de prueba de la operación solicitada y describir lo que se habría hecho en la salida estándar.
v
Modo detallado: provoca que se escriba información adicional en la salida estándar.
w=dir
Especificar el directorio de destino para la extracción de archivos. Esta debe ser la última opción del primer parámetro.

FORMATOS DE COMPRESIÓN

Lo siguiente proporciona una descripción básica de los diversos formatos de compresión admitidos (como se indica al usar el comando de lista documentado anteriormente). Todos los formatos son variantes del algoritmo de compresión LZSS.

-lz4-
Datos sin comprimir (almacenados), como los utiliza la herramienta original LArc. No está relacionado con el algoritmo de compresión LZ4 del mismo nombre.
-lz5-, -lzs-
Formatos de compresión introducidos con la herramienta original LArc. -lzs- utiliza una ventana deslizante de 2KiB mientras que -lz5- utiliza una ventana de 4KiB.
-lhd-
Entrada de directorio. No se almacenan datos, solo cabeceras.
-lh0-
Datos sin comprimir (almacenados), como se utiliza en LHarc y LHa.
-lh1-
Algoritmo de compresión introducido con LHarc. Utiliza una ventana deslizante de 4KiB con codificación Huffman dinámica.
-lh4-, -lh5-, -lh6-, -lh7-
Nuevo algoritmo introducido con LHa (también conocido como LHarc v2.0). Las versiones originales (-lh4- y -lh5-) utilizaron tamaños de ventana deslizante de 8KiB y 16KiB, respectivamente. Versiones posteriores introdujeron nuevas variantes con ventanas de mayor tamaño: -lh6- (64KiB) y -lh7- (128KiB).
-lhx-
Variante del formato -lh4- mencionado anteriormente introducida por UNLHA32.dll que amplía el tamaño de la ventana a 1MiB.
-lk7-
Variante del formato -lh4- mencionado anteriormente que fue introducida por la herramienta LHark (una bifurcación de LHa). En realidad, se llama -lh7- dentro de los archivos, pero Lhasa la renombra internamente para evitar conflictos con el otro algoritmo del mismo nombre. Utiliza una ventana deslizante de 128KiB, con alguna mejora menor en el algoritmo.
-pm0-
Datos sin comprimir (almacenados), como los utiliza la herramienta PMarc.
-pm1-
Algoritmo utilizado por la versión 1 de la herramienta PMarc.
-pm2-
Algoritmo utilizado por la versión 2 de la herramienta PMarc.

FORMATOS NO SOPORTADOS

Los siguientes formatos no son actualmente compatibles con Lhasa (pero posiblemente lo serán en el futuro):

-lh2-, -lh3-
Estos formatos pueden ser descomprimidos por LHa v2.0, pero la herramienta no pudo generar archivos con estos formatos; parecen haber sido solo soportados en versiones beta antes del lanzamiento de la v2.0. Como resultado, existen pocos o ningún ejemplo en circulación.
-lh8-, -lh9-, -lha-2, -lhb-, -lhc-, -lhe-
Extensiones del formato -lh4- a tamaños de ventana aún mayores.
-pc1-
Formato generado por la utilidad de compresión PopCom! para CP/M.

Si encuentra ejemplos de estos en circulación, póngase en contacto.

EJEMPLOS

Aquí hay algunos ejemplos de cómo invocar el programa:

lha -v foobar.lzs
Listar el contenido del archivo foobar.lzs (produciendo salida detallada).
lha -xf foobar.exe
Extraer el contenido de un archivo autoextraíble llamado foobar.exe al directorio actual, sobrescribiendo los archivos existentes con los mismos nombres si existen.
lha -xqw=/tmp foobar.lzh
Extraer el contenido de foobar.lzh a /tmp, sobrescribiendo cualquier archivo existente encontrado allí, y suprimiendo la salida normal (similar a cómo otras herramientas de Unix como cp(1) o tar(1) actúan silenciosamente por defecto).

HISTORIA

El formato .lzh se originó con la herramienta de archivo MS-DOS de Kazuhiko Miki, LArc, utilizando el algoritmo LZSS desarrollado por Haruhiko Okumura, y la extensión de nombre de archivo .lzs. El formato contenedor se reutilizó para LHarc, por Haruyasu Yoshizaki (Yoshi), que utilizó un nuevo algoritmo llamado LZHUF y la extensión .lzh. En versiones posteriores, LHarc se renombró a LHA y se amplió con algoritmos de compresión más efectivos.

Versiones de la herramienta LHA se portaron posteriormente a varios sistemas operativos diferentes, incluyendo Amiga, Atari, MacOS, OS/2 y Unix. Una herramienta para MSX-DOS llamada PMarc reutilizó el formato contenedor con un nuevo algoritmo de compresión (extensión .pma).

La versión de Unix de la herramienta fue desarrollada por Masaru Oki, Nobutaka Watazaki y Tsugio Okamoto, pero fue lanzada bajo una licencia de software que no se ajusta a las Definiciones de Software Libre u Open Source. Lhasa fue desarrollado como un reemplazo directo que es Software Libre y Open Source.

BUGS

La versión actual no permite la creación de nuevos archivos de archivo.

Algunos algoritmos de compresión oscuros no son compatibles actualmente (ver la sección FORMATOS NO SOPORTADOS más arriba).

La herramienta actualmente no realiza la conversión de formato de texto para nombres de archivo no ASCII al listar el contenido de los archivos. Los caracteres no ASCII se reemplazan por un signo de interrogación.
