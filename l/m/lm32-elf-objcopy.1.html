DESCRIPCIÓN

La utilidad GNU objcopy copia el contenido de un archivo objeto a otro. objcopy utiliza la Biblioteca GNU BFD para leer y escribir archivos objeto. Puede escribir el archivo objeto de destino en un formato diferente al del archivo objeto de origen. El comportamiento exacto de objcopy se controla mediante opciones de línea de comandos. Tenga en cuenta que objcopy debería poder copiar un archivo completamente enlazado entre dos formatos cualesquiera. Sin embargo, copiar un archivo objeto relocable entre dos formatos cualesquiera puede no funcionar como se espera.

objcopy crea archivos temporales para realizar sus traducciones y los elimina después. objcopy utiliza BFD para realizar todo su trabajo de traducción; tiene acceso a todos los formatos descritos en BFD y, por lo tanto, puede reconocer la mayoría de los formatos sin que se le indique explícitamente.

objcopy se puede utilizar para generar registros S utilizando un destino de salida srec (por ejemplo, use -O srec).

objcopy se puede utilizar para generar un archivo binario en bruto utilizando un destino de salida binary (por ejemplo, use -O binary). Cuando objcopy genera un archivo binario en bruto, esencialmente producirá un volcado de memoria del contenido del archivo objeto de entrada. Se descartará toda la información de símbolos y relocalización. El volcado de memoria comenzará en la dirección de carga de la sección más baja copiada al archivo de salida.

Al generar un archivo S-record o un archivo binario en bruto, puede ser útil usar -S para eliminar secciones que contienen información de depuración. En algunos casos, -R será útil para eliminar secciones que contienen información que no es necesaria para el archivo binario.

Nota: objcopy no puede cambiar la endianness (orden de bytes) de sus archivos de entrada. Si el formato de entrada tiene una endianness (algunos formatos no la tienen), objcopy solo puede copiar las entradas a formatos de archivo que tengan la misma endianness o que no tengan ninguna (por ejemplo, srec). (Sin embargo, vea la opción --reverse-bytes).

-j patrón_sección
--only-section=patrón_sección
Copiar solo las secciones indicadas del archivo de entrada al archivo de salida. Esta opción puede darse varias veces. Tenga en cuenta que usar esta opción de forma inapropiada puede hacer que el archivo de salida no sea utilizable. Se aceptan caracteres comodín en patrón_sección.

Si el primer carácter de patrón_sección es un signo de exclamación (!) entonces las secciones que coincidan no se copiarán, incluso si un uso anterior de --only-section en la misma línea de comandos las copiaría de otro modo. Por ejemplo:

--only-section=.text.* --only-section=!.text.foo

copiará todas las secciones que coincidan con '.text.*' pero no la sección '.text.foo'.

-R patrón_sección
--remove-section=patrón_sección
Eliminar cualquier sección que coincida con patrón_sección del archivo de salida. Esta opción puede darse varias veces. Tenga en cuenta que usar esta opción de forma inapropiada puede hacer que el archivo de salida no sea utilizable. Se aceptan caracteres comodín en patrón_sección. El uso conjunto de las opciones -j y -R produce un comportamiento indefinido.

Si el primer carácter de patrón_sección es un signo de exclamación (!) entonces las secciones que coincidan no se eliminarán, incluso si un uso anterior de --remove-section en la misma línea de comandos las eliminara de otro modo. Por ejemplo:

--remove-section=.text.* --remove-section=!.text.foo

eliminará todas las secciones que coincidan con el patrón '.text.*', pero no eliminará la sección '.text.foo'.

--keep-section=patrón_sección
Al eliminar secciones del archivo de salida, conservar las secciones que coincidan con patrón_sección.
--remove-relocations=patrón_sección
Eliminar las reubicaciones no dinámicas del archivo de salida para cualquier sección que coincida con patrón_sección. Esta opción puede darse varias veces. Tenga en cuenta que usar esta opción de forma inapropiada puede hacer que el archivo de salida no sea utilizable, e intentar eliminar una sección de reubicaciones dinámicas como .rela.plt de un ejecutable o biblioteca compartida con --remove-relocations=.plt no funcionará. Se aceptan caracteres comodín en patrón_sección. Por ejemplo: 
--remove-relocations=.text.*

eliminará las reubicaciones de todas las secciones que coincidan con el patrón '.text.*'.

Si el primer carácter de patrón_sección es un signo de exclamación (!) entonces a las secciones que coincidan no se les eliminarán sus reubicaciones, incluso si un uso anterior de --remove-relocations en la misma línea de comandos causara que las reubicaciones fueran eliminadas de otro modo. Por ejemplo:

--remove-relocations=.text.* --remove-relocations=!.text.foo

eliminará todas las reubicaciones de las secciones que coincidan con el patrón '.text.*', pero no eliminará las reubicaciones de la sección '.text.foo'.

--strip-section-headers
Eliminar cabeceras de sección. Esta opción es específica para archivos ELF. Implica --strip-all y --merge-notes.
-S
--strip-all
No copiar información de reubicación y símbolos del archivo fuente. También elimina secciones de depuración.
-g
--strip-debug
No copiar símbolos o secciones de depuración del archivo fuente.
--strip-unneeded
Eliminar todos los símbolos que no son necesarios para el procesamiento de reubicaciones, además de los símbolos y secciones de depuración eliminados por --strip-debug.
-K nombre_símbolo
--keep-symbol=nombre_símbolo
Al eliminar símbolos, conservar el símbolo nombre_símbolo incluso si normalmente se eliminaría. Esta opción puede darse varias veces.
-N nombre_símbolo
--strip-symbol=nombre_símbolo
No copiar el símbolo nombre_símbolo del archivo fuente. Esta opción puede darse varias veces.
--strip-unneeded-symbol=nombre_símbolo
No copiar el símbolo nombre_símbolo del archivo fuente a menos que sea necesario para una reubicación. Esta opción puede darse varias veces.
-G nombre_símbolo
--keep-global-symbol=nombre_símbolo
Mantener solo el símbolo nombre_símbolo como global. Hacer que todos los demás símbolos sean locales al archivo, de modo que no sean visibles externamente. Esta opción puede darse varias veces. Nota: esta opción no se puede usar junto con las opciones --globalize-symbol o --globalize-symbols.
--localize-hidden
En un objeto ELF, marcar todos los símbolos con visibilidad oculta o interna como locales. Esta opción se aplica además de las opciones de localización específicas de símbolos como -L.
-L nombre_símbolo
--localize-symbol=nombre_símbolo
Convertir un símbolo global o débil llamado nombre_símbolo en un símbolo local, de modo que no sea visible externamente. Esta opción puede darse varias veces. Nota: los símbolos únicos no se convierten.
-W nombre_símbolo
--weaken-symbol=nombre_símbolo
Hacer que el símbolo nombre_símbolo sea débil. Esta opción puede darse varias veces.
--globalize-symbol=nombre_símbolo
Dar al símbolo nombre_símbolo un ámbito global para que sea visible fuera del archivo en el que está definido. Esta opción puede darse varias veces. Nota: esta opción no se puede usar junto con las opciones -G o --keep-global-symbol.
-w
--wildcard
Permitir expresiones regulares en los nombre_símbolo utilizados en otras opciones de línea de comandos. Los operadores de signo de interrogación (?), asterisco (*), barra invertida (\) y corchetes ([]) pueden usarse en cualquier lugar del nombre del símbolo. Si el primer carácter del nombre del símbolo es el signo de exclamación (!) entonces el sentido del interruptor se invierte para ese símbolo. Por ejemplo: 
-w -W !foo -W fo*

haría que objcopy debilitara todos los símbolos que comienzan con "fo" excepto el símbolo "foo".

-x
--discard-all
No copiar símbolos no globales del archivo fuente.
-X
--discard-locals
No copiar símbolos locales generados por el compilador. (Estos suelen empezar por L o .).
-b byte
--byte=byte
Si se ha habilitado el intercalado mediante la opción --interleave entonces iniciar el rango de bytes a conservar en el byte-ésimo byte. byte puede estar en el rango de 0 a amplitud-1, donde amplitud es el valor dado por la opción --interleave.
-i [amplitud]
--interleave[=amplitud]
Copiar solo un rango de cada amplitud bytes. (Los datos de cabecera no se ven afectados). Seleccionar qué byte del rango inicia la copia con la opción --byte. Seleccionar el ancho del rango con la opción --interleave-width.

Esta opción es útil para crear archivos para programar ROM. Normalmente se utiliza con un destino de salida de tipo "srec". Tenga en cuenta que objcopy se quejará si no especifica también la opción --byte.

La amplitud de intercalado por defecto es 4, por lo que con --byte establecido en 0, objcopy copiaría el primer byte de cada cuatro bytes de la entrada a la salida.

--interleave-width=amplitud
Cuando se usa con la opción --interleave, copiar amplitud bytes a la vez. El inicio del rango de bytes a copiar se establece con la opción --byte, y la extensión del rango se establece con la opción --interleave.

El valor por defecto para esta opción es 1. El valor de amplitud más el valor de byte establecido por la opción --byte no debe exceder la amplitud de intercalado establecida por la opción --interleave.

Esta opción se puede usar para crear imágenes para dos flashes de 16 bits intercalados en un bus de 32 bits pasando -b 0 -i 4 --interleave-width=2 y -b 2 -i 4 --interleave-width=2 a dos comandos objcopy. Si la entrada fuera '12345678' las salidas serían '1256' y '3478' respectivamente.

-p
--preserve-dates
Establecer las fechas de acceso y modificación del archivo de salida para que sean las mismas que las del archivo de entrada.

Esta opción también copia la fecha almacenada en la cabecera de un archivo en formato PE, a menos que la variable de entorno SOURCE_DATE_EPOCH esté definida. Si está definida, entonces esta variable se utilizará como la fecha almacenada en la cabecera, interpretada como el número de segundos desde la época Unix.

-D
--enable-deterministic-archives
Operar en modo determinista. Al copiar miembros de archivo y escribir el archivo
-D
Operate in deterministic mode. When copying archive members and writing the archive index, use zero for UIDs, GIDs, timestamps, and use consistent file modes for all files.

If binutils was configured with --enable-deterministic-archives, then this mode is on by default. It can be disabled with the -U option, below.

-U
--disable-deterministic-archives
Do not operate in deterministic mode. This is the inverse of the -D option, above: when copying archive members and writing the archive index, use their actual UID, GID, timestamp, and file mode values.

This is the default unless binutils was configured with --enable-deterministic-archives.

--debugging
Convert debugging information, if possible. This is not the default because only certain debugging formats are supported, and the conversion process can be time consuming.
--gap-fill val
Fill gaps between sections with val. This operation applies to the load address (LMA) of the sections. It is done by increasing the size of the section with the lower address, and filling in the extra space created with val.
--pad-to address
Pad the output file up to the load address address. This is done by increasing the size of the last section. The extra space is filled in with the value specified by --gap-fill (default zero).
--set-start val
Set the start address (also known as the entry address) of the new file to val. Not all object file formats support setting the start address.
--change-start incr
--adjust-start incr
Change the start address (also known as the entry address) by adding incr. Not all object file formats support setting the start address.
--change-addresses incr
--adjust-vma incr
Change the VMA and LMA addresses of all sections, as well as the start address, by adding incr. Some object file formats do not permit section addresses to be changed arbitrarily. Note that this does not relocate the sections; if the program expects sections to be loaded at a certain address, and this option is used to change the sections such that they are loaded at a different address, the program may fail.
--change-section-address sectionpattern{=,+,-}val
--adjust-section-vma sectionpattern{=,+,-}val
Set or change both the VMA address and the LMA address of any section matching sectionpattern. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-section-lma sectionpattern{=,+,-}val
Set or change the LMA address of any sections matching sectionpattern. The LMA address is the address where the section will be loaded into memory at program load time. Normally this is the same as the VMA address, which is the address of the section at program run time, but on some systems, especially those where a program is held in ROM, the two can be different. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-section-vma sectionpattern{=,+,-}val
Set or change the VMA address of any section matching sectionpattern. The VMA address is the address where the section will be located once the program has started executing. Normally this is the same as the LMA address, which is the address where the section will be loaded into memory, but on some systems, especially those where a program is held in ROM, the two can be different. If = is used, the section address is set to val. Otherwise, val is added to or subtracted from the section address. See the comments under --change-addresses, above. If sectionpattern does not match any sections in the input file, a warning will be issued, unless --no-change-warnings is used.
--change-warnings
--adjust-warnings
If --change-section-address or --change-section-lma or --change-section-vma is used, and the section pattern does not match any sections, issue a warning. This is the default.
--no-change-warnings
--no-adjust-warnings
Do not issue a warning if --change-section-address or --adjust-section-lma or --adjust-section-vma is used, even if the section pattern does not match any sections.
--set-section-flags sectionpattern=flags
Set the flags for any sections matching sectionpattern. The flags argument is a comma separated string of flag names. The recognized names are alloc, contents, load, noload, readonly, code, data, rom, exclude, share, debug, and large. You can set the contents flag for a section which does not have contents, but it is not meaningful to clear the contents flag of a section which does have contents--just remove the section instead. Not all flags are meaningful for all object file formats. In particular the share flag is only meaningful for COFF format files and not for ELF format files. The ELF x86-64 specific flag large corresponds to SHF_X86_64_LARGE.
--set-section-alignment sectionpattern=align
Set the alignment for any sections matching sectionpattern. align specifies the alignment in bytes and must be a power of two, i.e. 1, 2, 4, 8....
--add-section sectionname=filename
Add a new section named sectionname while copying the file. The contents of the new section are taken from the file filename. The size of the section will be the size of the file. This option only works on file formats which can support sections with arbitrary names. Note - it may be necessary to use the --set-section-flags option to set the attributes of the newly created section.
--dump-section sectionname=filename
Place the contents of section named sectionname into the file filename, overwriting any contents that may have been there previously. This option is the inverse of --add-section. This option is similar to the --only-section option except that it does not create a formatted file, it just dumps the contents as raw binary data, without applying any relocations. The option can be specified more than once.
--update-section sectionname=filename
Replace the existing contents of a section named sectionname with the contents of file filename. The size of the section will be adjusted to the size of the file. The section flags for sectionname will be unchanged. For ELF format files the section to segment mapping will also remain unchanged, something which is not possible using --remove-section followed by --add-section. The option can be specified more than once.

Note - it is possible to use --rename-section and --update-section to both update and rename a section from one command line. In this case, pass the original section name to --update-section, and the original and new section names to --rename-section.

--add-symbol name=[section:]value[,flags]
Add a new symbol named name while copying the file. This option may be specified multiple times. If the section is given, the symbol will be associated with and relative to that section, otherwise it will be an ABS symbol. Specifying an undefined section will result in a fatal error. There is no check for the value, it will be taken as specified. Symbol flags can be specified and not all flags will be meaningful for all object file formats. By default, the symbol will be global. The special flag 'before=othersym' will insert the new symbol in front of the specified othersym, otherwise the symbol(s) will be added at the end of the symbol table in the order they appear.
--rename-section oldname=newname[,flags]
Rename a section from oldname to newname, optionally changing the section's flags to flags in the process. This has the advantage over using a linker script to perform the rename in that the output stays as an object file and does not become a linked executable. This option accepts the same set of flags as the --set-section-flags option.

This option is particularly helpful when the input format is binary, since this will always create a section called .data. If for example, you wanted instead to create a section called .rodata containing binary data you could use the following command line to achieve it:

objcopy -I binary -O <output_format> -B <architecture> \
 --rename-section .data=.rodata,alloc,load,readonly,data,contents \
 <input_binary_file>
--long-section-names {enable,disable,keep}
Controla el manejo de nombres de sección largos al procesar los formatos de objetos "COFF" y "PE-COFF". El comportamiento predeterminado, keep, es preservar los nombres de sección largos si están presentes en el archivo de entrada. Las opciones enable y disable habilitan o deshabilitan forzosamente el uso de nombres de sección largos en el objeto de salida; cuando disable está activo, los nombres de sección largos en el objeto de entrada se truncarán. La opción enable solo emitirá nombres de sección largos si están presentes en las entradas; esto es en gran medida lo mismo que keep, pero no se define si la opción enable podría forzar la creación de una tabla de cadenas vacía en el archivo de salida.
--change-leading-char
Algunos formatos de archivo de objeto utilizan caracteres especiales al principio de los símbolos. El carácter más común es el guion bajo, que los compiladores a menudo agregan antes de cada símbolo. Esta opción le indica a objcopy que cambie el carácter inicial de cada símbolo al convertir entre formatos de archivo de objeto. Si los formatos de archivo de objeto utilizan el mismo carácter inicial, esta opción no tiene ningún efecto. De lo contrario, agregará, eliminará o cambiará un carácter, según corresponda.
--remove-leading-char
Si el primer carácter de un símbolo global es un carácter inicial especial utilizado por el formato del archivo de objeto, elimine el carácter. El carácter inicial de símbolo más común es el guion bajo. Esta opción eliminará un guion bajo inicial de todos los símbolos globales. Esto puede ser útil si desea vincular objetos de diferentes formatos de archivo con diferentes convenciones para los nombres de símbolos. Esto es diferente de --change-leading-char porque siempre cambia el nombre del símbolo cuando es apropiado, independientemente del formato del archivo de objeto del archivo de salida.
--reverse-bytes=num
Invierte los bytes en una sección con contenido de salida. La longitud de una sección debe ser divisible por el valor proporcionado para que la inversión pueda llevarse a cabo. La inversión se realiza antes de que se realice el entrelazado.

Esta opción se utiliza típicamente en la generación de imágenes ROM para sistemas de destino problemáticos. Por ejemplo, en algunas placas de destino, las palabras de 32 bits obtenidas de ROMs de 8 bits se vuelven a ensamblar en orden de bytes little-endian independientemente del orden de bytes de la CPU. Dependiendo del modelo de programación, es posible que sea necesario modificar la distribución de bytes (endianness) de la ROM.

Considere un archivo simple con una sección que contiene los siguientes ocho bytes: 12345678.

Usando --reverse-bytes=2 para el ejemplo anterior, los bytes en el archivo de salida se ordenarían 21436587.

Usando --reverse-bytes=4 para el ejemplo anterior, los bytes en el archivo de salida se ordenarían 43218765.

Al usar --reverse-bytes=2 para el ejemplo anterior, seguido de --reverse-bytes=4 en el archivo de salida, los bytes en el segundo archivo de salida se ordenarían 34127856.

--srec-len=ival
Solo significativo para la salida srec. Establece la longitud máxima de los Srecords que se producen en ival. Esta longitud cubre los campos de dirección, datos y crc.
--srec-forceS3
Solo significativo para la salida srec. Evita la generación de registros S1/S2, creando un formato de registro solo S3.
--redefine-sym old=new
Cambia el nombre de un símbolo old a new. Esto puede ser útil cuando se intenta vincular dos cosas para las que no se tiene el código fuente, y hay colisiones de nombres.
--redefine-syms=filename
Aplica --redefine-sym a cada par de símbolos "old new" listado en el archivo filename. filename es simplemente un archivo plano, con un par de símbolos por línea. Los comentarios de línea pueden introducirse con el carácter de almohadilla (#). Esta opción puede darse más de una vez.
--weaken
Cambia todos los símbolos globales en el archivo a débiles (weak). Esto puede ser útil al construir un objeto que se vinculará con otros objetos usando la opción -R del enlazador. Esta opción solo es efectiva cuando se usa un formato de archivo de objeto que admite símbolos débiles.
--keep-symbols=filename
Aplica la opción --keep-symbol a cada símbolo listado en el archivo filename. filename es simplemente un archivo plano, con un nombre de símbolo por línea. Los comentarios de línea pueden introducirse con el carácter de almohadilla (#). Esta opción puede darse más de una vez.
--strip-symbols=filename
Aplica la opción --strip-symbol a cada símbolo listado en el archivo filename. filename es simplemente un archivo plano, con un nombre de símbolo por línea. Los comentarios de línea pueden introducirse con el carácter de almohadilla (#). Esta opción puede darse más de una vez.
--strip-unneeded-symbols=filename
Aplica la opción --strip-unneeded-symbol a cada símbolo listado en el archivo filename. filename es simplemente un archivo plano, con un nombre de símbolo por línea. Los comentarios de línea pueden introducirse con el carácter de almohadilla (#). Esta opción puede darse más de una vez.
--keep-global-symbols=filename
Aplica la opción --keep-global-symbol a cada símbolo listado en el archivo filename. filename es simplemente un archivo plano, con un nombre de símbolo por línea. Los comentarios de línea pueden introducirse con el carácter de almohadilla (#). Esta opción puede darse más de una vez.
--localize-symbols=filename
Aplica la opción --localize-symbol a cada símbolo listado en el archivo filename. filename es simplemente un archivo plano, con un nombre de símbolo por línea. Los comentarios de línea pueden introducirse con el carácter de almohadilla (#). Esta opción puede darse más de una vez.
--globalize-symbols=filename
Aplica la opción --globalize-symbol a cada símbolo listado en el archivo filename. filename es simplemente un archivo plano, con un nombre de símbolo por línea. Los comentarios de línea pueden introducirse con el carácter de almohadilla (#). Esta opción puede darse más de una vez. Nota: esta opción no puede usarse junto con las opciones -G o --keep-global-symbol.
--weaken-symbols=filename
Aplica la opción --weaken-symbol a cada símbolo listado en el archivo filename. filename es simplemente un archivo plano, con un nombre de símbolo por línea. Los comentarios de línea pueden introducirse con el carácter de almohadilla (#). Esta opción puede darse más de una vez.
--alt-machine-code=index
Si la arquitectura de salida tiene códigos de máquina alternativos, usa el index-ésimo código en lugar del predeterminado. Esto es útil en caso de que una máquina reciba un código oficial y la cadena de herramientas adopte el nuevo código, pero otras aplicaciones sigan dependiendo del código original. Para arquitecturas basadas en ELF, si la alternativa index no existe, el valor se trata como un número absoluto que se almacenará en el campo e_machine de la cabecera ELF.
--writable-text
Marca el texto de salida como escribible. Esta opción no es significativa para todos los formatos de archivo de objeto.
--readonly-text
Hace que el texto de salida esté protegido contra escritura. Esta opción no es significativa para todos los formatos de archivo de objeto.
--pure
Marca el archivo de salida como paginable a demanda (demand paged). Esta opción no es significativa para todos los formatos de archivo de objeto.
--impure
Marca el archivo de salida como impuro. Esta opción no es significativa para todos los formatos de archivo de objeto.
--prefix-symbols=string
Prefija todos los símbolos en el archivo de salida con string.
--prefix-sections=string
Prefija todos los nombres de sección en el archivo de salida con string.
--prefix-alloc-sections=string
Prefija todos los nombres de todas las secciones asignadas (allocated sections) en el archivo de salida con string.
--add-gnu-debuglink=path-to-file
Crea una sección .gnu_debuglink que contiene una referencia a path-to-file y la agrega al archivo de salida. Nota: el archivo en path-to-file debe existir. Parte del proceso de agregar la sección .gnu_debuglink implica incrustar una suma de verificación (checksum) del contenido del archivo de información de depuración en la sección.

Si el archivo de información de depuración se construye en una ubicación pero se instalará más tarde en una ubicación diferente, no use la ruta a la ubicación instalada. La opción --add-gnu-debuglink fallará porque el archivo instalado aún no existe. En su lugar, coloque el archivo de información de depuración en el directorio actual y use la opción --add-gnu-debuglink sin componentes de directorio, de la siguiente manera:

objcopy --add-gnu-debuglink=foo.debug

En tiempo de depuración, el depurador intentará buscar el archivo de información de depuración separado en un conjunto de ubicaciones conocidas. El conjunto exacto de estas ubicaciones varía según la distribución utilizada, pero generalmente incluye:

"* El mismo directorio que el ejecutable."
"* Un subdirectorio del directorio que contiene el ejecutable"
llamado .debug
"* Un directorio de depuración global como /usr/lib/debug."

Siempre que el archivo de información de depuración se haya instalado en una de estas ubicaciones antes de que se ejecute el depurador, todo debería funcionar correctamente.

--keep-section-symbils
/a>
Al depurar un archivo, quizás con --strip-debug o --strip-unneeded, conservar cualquier símbolo que especifique nombres de sección, que de otro modo se eliminarían.
--keep-file-symbols
Al depurar un archivo, quizás con --strip-debug o --strip-unneeded, conservar cualquier símbolo que especifique nombres de archivos fuente, que de otro modo se eliminarían.
--only-keep-debug
Depura un archivo, eliminando el contenido de cualquier sección que no se eliminaría con --strip-debug y dejando intactas las secciones de depuración. En archivos ELF, esto preserva todas las secciones de notas en la salida.

Nota: las cabeceras de las secciones eliminadas se preservan, incluidos sus tamaños, pero el contenido de la sección se descarta. Las cabeceras de las secciones se conservan para que otras herramientas puedan hacer coincidir el archivo debuginfo con el ejecutable real, incluso si ese ejecutable se ha reubicado en un espacio de direcciones diferente.

La intención es que esta opción se utilice junto con --add-gnu-debuglink para crear un ejecutable de dos partes. Una, un binario depurado que ocupará menos espacio en RAM y en una distribución, y la segunda, un archivo de información de depuración que solo es necesario si se requieren capacidades de depuración. El procedimiento sugerido para crear estos archivos es el siguiente:

1.<Enlaza el ejecutable como de costumbre. Suponiendo que se llama>
"foo" entonces...
1.<Ejecuta "objcopy --only-keep-debug foo foo.dbg" para>
crear un archivo que contenga la información de depuración.
1.<Ejecuta "objcopy --strip-debug foo" para crear un>
ejecutable depurado.
1.<Ejecuta "objcopy --add-gnu-debuglink=foo.dbg foo">
para añadir un enlace a la información de depuración en el ejecutable depurado.

Nota: la elección de ".dbg" como extensión para el archivo de información de depuración es arbitraria. También el paso de "--only-keep-debug" es opcional. En su lugar, puedes hacer esto:

1.<Enlaza el ejecutable como de costumbre.>
1.<Copia "foo" a "foo.full">
1.<Ejecuta "objcopy --strip-debug foo">
1.<Ejecuta "objcopy --add-gnu-debuglink=foo.full foo">

es decir, el archivo al que apunta --add-gnu-debuglink puede ser el ejecutable completo. No tiene por qué ser un archivo creado con el modificador --only-keep-debug.

Nota: este modificador solo está pensado para usarse en archivos completamente enlazados. No tiene sentido usarlo en archivos objeto donde la información de depuración puede ser incompleta. Además, la característica gnu_debuglink actualmente solo admite la presencia de un nombre de archivo que contenga información de depuración, no varios nombres de archivo sobre una base de uno por archivo objeto.

--strip-dwo
Elimina el contenido de todas las secciones DWARF .dwo, dejando las secciones de depuración restantes y todos los símbolos intactos. Esta opción está destinada a ser utilizada por el compilador como parte de la opción -gsplit-dwarf, que divide la información de depuración entre el archivo .o y un archivo .dwo separado. El compilador genera toda la información de depuración en el mismo archivo, luego usa la opción --extract-dwo para copiar las secciones .dwo al archivo .dwo, y luego la opción --strip-dwo para eliminar esas secciones del archivo .o original.
--extract-dwo
Extrae el contenido de todas las secciones DWARF .dwo. Consulte la opción --strip-dwo para obtener más información.
--file-alignment num
Especifica la alineación de archivo. Las secciones en el archivo siempre comenzarán en desplazamientos de archivo que sean múltiplos de este número. El valor predeterminado es 512. [Esta opción es específica para objetivos PE.]
--heap reserve
--heap reserve,commit
Especifica el número de bytes de memoria a reservar (y opcionalmente confirmar) que se utilizarán como heap para este programa. [Esta opción es específica para objetivos PE.]
--image-base value
Utiliza value como la dirección base de tu programa o dll. Esta es la ubicación de memoria más baja que se utilizará cuando se cargue tu programa o dll. Para reducir la necesidad de reubicación y mejorar el rendimiento de tus dlls, cada una debe tener una dirección base única y no superponerse con otras dlls. El valor predeterminado es 0x400000 para ejecutables y 0x10000000 para dlls. [Esta opción es específica para objetivos PE.]
--section-alignment num
Establece el campo de alineación de sección en la cabecera PE. Las secciones en memoria siempre comenzarán en direcciones que sean múltiplos de este número. El valor predeterminado es 0x1000. [Esta opción es específica para objetivos PE.]
--stack reserve
--stack reserve,commit
Especifica el número de bytes de memoria a reservar (y opcionalmente confirmar) que se utilizarán como pila para este programa. [Esta opción es específica para objetivos PE.]
--subsystem which
--subsystem which:major
--subsystem which:major.minor
Especifica el subsistema bajo el cual se ejecutará tu programa. Los valores legales para which son "native", "windows", "console", "posix", "efi-app", "efi-bsd", "efi-rtd", "sal-rtd" y "xbox". Opcionalmente, también puedes establecer la versión del subsistema. También se aceptan valores numéricos para which. [Esta opción es específica para objetivos PE.]
--extract-symbol
Conserva las banderas de sección y los símbolos del archivo, pero elimina todos los datos de la sección. Específicamente, la opción:
*<elimina el contenido de todas las secciones;>
*<establece el tamaño de cada sección a cero; y>
*<establece la dirección de inicio del archivo a cero.>

Esta opción se utiliza para construir un archivo .sym para un kernel VxWorks. También puede ser una forma útil de reducir el tamaño de un archivo de entrada del enlazador --just-symbols.

--compress-debug-sections
Comprime las secciones de depuración DWARF utilizando zlib con SHF_COMPRESSED de la ABI ELF. Nota: si la compresión realmente hiciera una sección más grande, entonces no se comprime.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Para archivos ELF, estas opciones controlan cómo se comprimen las secciones de depuración DWARF. --compress-debug-sections=none es equivalente a --decompress-debug-sections. --compress-debug-sections=zlib y --compress-debug-sections=zlib-gabi son equivalentes a --compress-debug-sections. --compress-debug-sections=zlib-gnu comprime las secciones de depuración DWARF utilizando el formato obsoleto zlib-gnu. Las secciones de depuración se renombran para que comiencen con .zdebug. --compress-debug-sections=zstd comprime las secciones de depuración DWARF utilizando zstd. Nota: si la compresión realmente hiciera una sección más grande, entonces no se comprime ni se renombra.
--decompress-debug-sections
Descomprime las secciones de depuración DWARF. Para una sección .zdebug, se restaura el nombre original.
--elf-stt-common=yes
--elf-stt-common=no
Para archivos ELF, estas opciones controlan si los símbolos comunes deben convertirse al tipo "STT_COMMON" o "STT_OBJECT". --elf-stt-common=yes convierte el tipo de símbolo común a "STT_COMMON". --elf-stt-common=no convierte el tipo de símbolo común a "STT_OBJECT".
--merge-notes
--no-merge-notes
Para archivos ELF, intenta (o no intenta) reducir el tamaño de cualquier sección de tipo SHT_NOTE eliminando notas duplicadas.

Muestra el número de versión de objcopy.
--verilog-data-width=bytes
Para la salida Verilog, esta opción controla el número de bytes convertidos para cada elemento de datos de salida. El objetivo de entrada controla el orden de bytes de la conversión.

DESCRIPTION

lm32-elf-objcopy is a utility used to copy object files. It can be used to change the size of the symbols, the format of the object file, and the target specific information. It can also be used to remove symbols or sections from an object file.

OPTIONS

-@ file
Read options from file. The options read are inserted in place of the original @file option. If file does not exist, or cannot be read, then the option will be treated literally, and not removed.

Options in file are separated by whitespace. A whitespace character may be included in an option by surrounding the entire option in either single or double quotes. Any character (including a backslash) may be included by prefixing the character to be included with a backslash. The file may itself contain additional @file options; any such options will be processed recursively.
