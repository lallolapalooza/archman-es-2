SMTP(8) Manual del Administrador del Sistema SMTP(8)

NOMBRE

smtp, lmtp - Cliente Postfix SMTP+LMTP

SINOPSIS

smtp [opciones genéricas del demonio Postfix] [flags=DORX]
lmtp [opciones genéricas del demonio Postfix] [flags=DORX]

DESCRIPCIÓN


El cliente SMTP+LMTP de Postfix implementa los protocolos de correo SMTP y LMTP. Procesa las solicitudes de entrega de mensajes del gestor de colas. Cada solicitud especifica un archivo de cola, una dirección de remitente, un dominio o host al que entregar, y la información del destinatario. Este programa espera ser ejecutado por el gestor de demonios master(8). El nombre del proceso, smtp o lmtp, controla el protocolo y los nombres de los parámetros de configuración que se utilizarán.

El cliente SMTP+LMTP actualiza el archivo de cola y marca a los destinatarios como finalizados, o informa al gestor de colas que la entrega debe intentarse de nuevo más tarde. Los informes de estado de entrega se envían al demonio bounce(8), defer(8) o trace(8) según corresponda.

La estrategia de búsqueda de servidores es diferente para SMTP y LMTP, como se describe en las secciones "BÚSQUEDA DE SERVIDOR SMTP" y "BÚSQUEDA DE SERVIDOR LMTP".

Después de una transacción de correo exitosa, una conexión puede guardarse en el servidor de caché de conexiones scache(8), para que pueda ser utilizada por cualquier cliente SMTP+LMTP para una transacción posterior.

Por defecto, el almacenamiento en caché de conexiones está habilitado temporalmente para destinos que tienen un alto volumen de correo en la cola activa. El almacenamiento en caché de conexiones se puede habilitar permanentemente para destinos específicos.

BÚSQUEDA DE SERVIDOR SMTP

El cliente SMTP de Postfix soporta múltiples destinos separados por coma o espacio en blanco (Postfix 3.5 y posterior). Cada destino se prueba en el orden especificado.

Los destinos SMTP tienen el siguiente formato:

nombredominio
nombredominio:servicio
Busca los intercambiadores de correo para el dominio especificado y se conecta al servicio especificado (predeterminado: smtp). Opcionalmente, los intercambiadores de correo pueden buscarse con consultas SRV en lugar de MX; esto requiere que se proporcione el servicio en forma simbólica.
[nombrehost]
[nombrehost]:servicio
Busca las direcciones del host especificado y se conecta al servicio especificado (predeterminado: smtp).
[direccion]
[direccion]:servicio
Se conecta al host en la dirección especificada y al servicio especificado (predeterminado: smtp). Una dirección IPv6 debe tener el formato [ipv6:direccion].

BÚSQUEDA DE SERVIDOR LMTP

El cliente LMTP de Postfix soporta múltiples destinos separados por coma o espacio en blanco (Postfix 3.5 y posterior). Cada destino se prueba en el orden especificado.

Los destinos LMTP tienen el siguiente formato:

unix:rutaarchivo
Se conecta al servidor local de dominio UNIX enlazado a la rutaarchivo especificada. Si el proceso se ejecuta en chroot, una ruta de archivo absoluta se interpreta en relación con el directorio de colas de Postfix.
inet:nombredominio
inet:nombredominio:servicio
Busca los servidores LMTP para el dominio y servicio especificados (predeterminado: lmtp). Esta forma es compatible cuando las búsquedas SRV están habilitadas y requiere que el servicio esté en forma simbólica.
inet:nombrehost
inet:nombrehost:servicio
Busca las direcciones del host especificado y se conecta al servicio especificado (predeterminado: lmtp). Cuando las búsquedas SRV están habilitadas, use la forma [nombrehost] para forzar búsquedas de direcciones.
inet:[direccion]
inet:[direccion]:servicio
Se conecta al host y servicio local o remoto especificado (predeterminado: lmtp). Una dirección IPv6 debe tener el formato [ipv6:direccion].

ENTREGA DE DESTINATARIO ÚNICO

Por defecto, el cliente SMTP+LMTP de Postfix entrega correo a múltiples destinatarios por solicitud de entrega. Esto es indeseable al anteponer una cabecera de mensaje Delivered-to: o X-Original-To:. Para evitar que Postfix envíe múltiples destinatarios por solicitud de entrega, especifique

    transporte_destination_recipient_limit = 1

en el archivo main.cf de Postfix, donde transporte es el nombre en la primera columna de la entrada master.cf de Postfix para este servicio de entrega de correo.

SINTAXIS DE ATRIBUTOS DE COMANDO

flags=DORX (opcional)
Banderas opcionales de procesamiento de mensajes.
D
Anteponer una cabecera de mensaje "Delivered-To: destinatario" con la dirección del destinatario del sobre. Nota: para que esto funcione, el transporte_destination_recipient_limit debe ser 1 (ver ENTREGA DE DESTINATARIO ÚNICO más arriba para más detalles).

La bandera D también impone la detección de bucles: si un mensaje ya contiene una cabecera Delivered-To: con la misma dirección de destinatario, el mensaje se devuelve como intransmisible. La comparación de direcciones no distingue entre mayúsculas y minúsculas.

Esta característica está disponible a partir de Postfix 3.5.

O
Anteponer una cabecera de mensaje "X-Original-To: destinatario" con la dirección del destinatario tal como se proporcionó a Postfix. Nota: para que esto funcione, el transporte_destination_recipient_limit debe ser 1 (ver ENTREGA DE DESTINATARIO ÚNICO más arriba para más detalles).

Esta característica está disponible a partir de Postfix 3.5.

R
Anteponer una cabecera de mensaje "Return-Path: <remitente>" con la dirección del remitente del sobre.

Esta característica está disponible a partir de Postfix 3.5.

X
Indica que la entrega es final. Esta bandera afecta al estado reportado en los mensajes DSN (notificación de estado de entrega) de "éxito", y lo cambia de "retransmitido" a "entregado".

Esta característica está disponible a partir de Postfix 3.5.

SEGURIDAD

El cliente SMTP+LMTP es moderadamente sensible a la seguridad. Habla con servidores SMTP o LMTP y con servidores DNS en la red. El cliente SMTP+LMTP puede ejecutarse en chroot con privilegios bajos fijos.

ERRORES


La reutilización de conexiones SMTP y LMTP para TLS (sin cerrar la conexión SMTP o LMTP) no es compatible antes de Postfix 3.4.

La reutilización de conexiones SMTP y LMTP asume que las credenciales SASL son válidas para todos los destinos que se mapean a la misma dirección IP y puerto TCP.

PARÁMETROS DE CONFIGURACIÓN

Las versiones de Postfix 2.3 y posteriores implementan el cliente SMTP y LMTP con el mismo programa, y eligen el protocolo y los parámetros de configuración según el nombre del proceso, smtp o lmtp.

La mayoría de los parámetros de configuración smtp_xxx tienen un parámetro "espejo" lmtp_xxx para la característica LMTP equivalente. Este documento describe solo aquellos parámetros relacionados con LMTP que no son simplemente parámetros "espejo".

Los cambios en main.cf se aplican automáticamente, ya que los procesos de smtp(8) se ejecutan solo durante un tiempo limitado. Utilice el comando "postfix reload" para acelerar un cambio.

El texto a continuación proporciona solo un resumen de los parámetros. Consulte postconf(5) para obtener más detalles, incluidos ejemplos.

NAME

lmtp - Postfix Local Mail Transfer Protocol server

SYNOPSIS 

       lmtp [-4] [-6] [-F] [-v] [-V] [-c
           config_dir] [-C session_config] [-i] [-n] [-o
           parameter=value]

DESCRIPTION

The LMTP server (lmtp) is intended to be run as a user-level, daemon process that accepts LMTP mail delivery requests from a network client. It is typically run under the control of the Postfix mail server's master process (master.cf).

LMTP is a simplified version of the SMTP protocol, designed for mail delivery from a central mail server to one or more destination mail servers.

The LMTP server accepts mail from clients via the LMTP protocol. It then looks up the mail destination(s) using the `transport` table (the same mechanism as the `smtp` client).

It is primarily used for "virtual" mail hosting, where a single mailbox on the LMTP server holds mail for multiple recipients.

The LMTP server supports the following features:

  • TLS/SSL encryption.
  • SASL authentication.
  • SMTPUTF8 support for internationalized email addresses.
  • Extended SMTP protocol extensions.
  • Delivery status notifications (DSN).
  • Content inspection via external services.
  • Connection caching.
  • LMTP server commands.
  • LMTP client commands.

SMTP SERVER LOOKUP

The LMTP server looks up the mail destination(s) using the `transport` table. The format of entries in the `transport` table is: 

       domain   transport:next_hop

where:

  • domain is the domain name for which mail is being delivered.
  • transport is the delivery agent to use (e.g., `lmtp`, `smtp`).
  • next_hop is the destination server or mailbox.

For example, an entry like: 

       example.com   lmtp:mail.example.com

would cause mail for `example.com` to be delivered via LMTP to `mail.example.com`.

For example, an entry like: 

        example.com   lmtp:mail.example.com

would cause mail for `example.com` to be delivered via LMTP to `mail.example.com`.

SINGLE-RECIPIENT DELIVERY

The LMTP server supports single-recipient delivery, where each recipient is delivered to separately. This is typically used for mailboxes that contain multiple recipients.

COMMAND ATTRIBUTE SYNTAX

The LMTP server supports command attributes, which are used to control delivery options. The syntax for command attributes is: 

        command [attribute=value] ...

For example, the `RCPT TO:` command can be used with the `NOTIFY` attribute to request delivery status notifications: 

        RCPT TO:<user@example.com> NOTIFY=SUCCESS,FAILURE

SECURITY

The LMTP server supports TLS/SSL encryption and SASL authentication to secure LMTP connections. These features are configured via Postfix configuration parameters.

STANDARDS

The LMTP server implements the following standards:

  • RFC 1869 (Extended SMTP)
  • RFC 2045 (MIME Part One)
  • RFC 2046 (MIME Part Two)
  • RFC 2047 (MIME Part Three)
  • RFC 2048 (MIME Part Four)
  • RFC 2049 (MIME Part Five)
  • RFC 2821 (Simple Mail Transfer Protocol)
  • RFC 2822 (Internet Message Format)
  • RFC 3461 (Simple Mail Transfer Protocol (SMTP) Service Extensions for Delivery Status Notifications (DSNs))
  • RFC 3463 (Enhanced Delivery Status Notifications)
  • RFC 3464 (An extensible mechanism for the content type "message/delivery-status")
  • RFC 3798 (Message Disposition Notification)
  • RFC 4343 (Domain Context: Application Context for DNS)
  • RFC 5321 (Simple Mail Transfer Protocol)
  • RFC 5322 (Internet Message Format)
  • RFC 5877 (Resource Directory (RD) to help locate services that use SRV records)
  • RFC 6531 (SMTP Extension for Internationalized Email)
  • RFC 6532 (Internationalized Email: Representing Mail Addresses and Message Content in UTF-8)

DIAGNOSTICS

The LMTP server logs diagnostic information to the Postfix mail log (typically `/var/log/mail.log` or `/var/log/maillog`). The logging level can be controlled via the `verbose_level` parameter in `main.cf`.

BUGS

None known.

CONFIGURATION PARAMETERS

The LMTP server's behavior is controlled by parameters in the Postfix `main.cf` and `master.cf` files. Key parameters include:

  • `lmtp_destination_recipient_limit`: The maximum number of recipients that can be delivered to in a single LMTP session.
  • `lmtp_lazy_destinations`: Whether to defer recipient lookups until after the mail is sent.
  • `lmtp_skip_deliver_temp_failures`: Whether to skip delivery of messages that resulted in temporary delivery failures.
  • `lmtp_skip_quit_socket`: Whether to close the LMTP connection immediately after a successful delivery.
  • `lmtp_tls_CAfile`: The CA certificate file for verifying TLS/SSL certificates.
  • `lmtp_tls_CApath`: The CA certificate directory for verifying TLS/SSL certificates.
  • `lmtp_tls_cert_file`: The TLS/SSL certificate file.
  • `lmtp_tls_key_file`: The TLS/SSL private key file.
  • `lmtp_tls_loglevel`: The logging level for TLS/SSL operations.
  • `lmtp_tls_session_cache_database`: The TLS/SSL session cache database.
  • `lmtp_tls_session_cache_timeout`: The TLS/SSL session cache timeout.
  • `lmtp_tls_verify_cert`: Whether to verify TLS/SSL certificates.
  • `lmtp_use_tls`: Whether to use TLS/SSL encryption for LMTP connections.
  • `lmtp_sasl_auth_enable`: Whether to enable SASL authentication for LMTP clients.
  • `lmtp_sasl_password_maps`: The SASL password map file.
  • `lmtp_sasl_security_options`: The SASL security options.
  • `lmtp_sasl_tls_security_options`: The SASL security options for TLS connections.
  • `lmtp_sasl_mechanism_filter`: The SASL mechanisms to use.

COMPATIBILITY CONTROLS

The LMTP server supports several compatibility controls to ensure interoperability with older systems. These include:

  • `lmtp_mime_boundary_length`: The maximum length of MIME boundaries.
  • `lmtp_mime_en_header_length`: The maximum length of MIME header fields.
  • `lmtp_mime_fragment_length`: The maximum length of MIME fragments.

MIME PROCESSING CONTROLS

The LMTP server supports several MIME processing controls to handle MIME messages. These include:

  • `lmtp_mime_process_headers`: Whether to process MIME headers.
  • `lmtp_mime_header_folding`: Whether to fold MIME headers.
  • `lmtp_mime_header_folding_level`: The MIME header folding level.

EXTERNAL CONTENT INSPECTION CONTROLS

The LMTP server supports external content inspection controls to allow integration with content filtering services. These include:

  • `lmtp_content_filter`: The content filter service.
  • `lmtp_content_filter_interfaces`: The interfaces for the content filter service.
  • `lmtp_content_filter_timeout`: The timeout for the content filter service.

SASL AUTHENTICATION CONTROLS

The LMTP server supports SASL authentication controls to enable secure client authentication. These include:

  • `lmtp_sasl_auth_enable`: Whether to enable SASL authentication.
  • `lmtp_sasl_password_maps`: The SASL password map file.
  • `lmtp_sasl_security_options`: The SASL security options.
  • `lmtp_sasl_tls_security_options`: The SASL security options for TLS connections.
  • `lmtp_sasl_mechanism_filter`: The SASL mechanisms to use.

STARTTLS SUPPORT CONTROLS

The LMTP server supports StartTLS support controls to enable encrypted LMTP connections. These include:

  • `lmtp_use_tls`: Whether to use TLS/SSL encryption.
  • `lmtp_tls_CAfile`: The CA certificate file for verifying TLS/SSL certificates.
  • `lmtp_tls_CApath`: The CA certificate directory for verifying TLS/SSL certificates.
  • `lmtp_tls_cert_file`: The TLS/SSL certificate file.
  • `lmtp_tls_key_file`: The TLS/SSL private key file.
  • `lmtp_tls_loglevel`: The logging level for TLS/SSL operations.
  • `lmtp_tls_session_cache_database`: The TLS/SSL session cache database.
  • `lmtp_tls_session_cache_timeout`: The TLS/SSL session cache timeout.
  • `lmtp_tls_verify_cert`: Whether to verify TLS/SSL certificates.

OBSOLETE STARTTLS CONTROLS

The following StartTLS controls are obsolete and should not be used:

  • `lmtp_tls_allow_downgrade`: Obsolete. Use `lmtp_tls_security_level` instead.
  • `lmtp_tls_disable_symmetry`: Obsolete. Use `lmtp_tls_security_level` instead.
  • `lmtp_tls_enforce_ccacert`: Obsolete. Use `lmtp_tls_verify_cert` instead.
  • `lmtp_tls_helo_needs_tls`: Obsolete. Use `lmtp_tls_security_level` instead.
  • `lmtp_tls_per_site_cert`: Obsolete. Use `lmtp_tls_cert_file` and `lmtp_tls_key_file` instead.
  • `lmtp_tls_per_site_key`: Obsolete. Use `lmtp_tls_cert_file` and `lmtp_tls_key_file` instead.
  • `lmtp_tls_per_site_defaults`: Obsolete. Use `lmtp_tls_cert_file` and `lmtp_tls_key_file` instead.

RESOURCE AND RATE CONTROLS

The LMTP server supports resource and rate controls to limit the resources consumed by LMTP clients. These include:

  • `lmtp_destination_concurrency_limit`: The maximum number of concurrent LMTP deliveries to a destination.
  • `lmtp_destination_recipient_limit`: The maximum number of recipients that can be delivered to in a single LMTP session.
  • `lmtp_oversize_message_reject_threshold`: The message size threshold for rejecting oversized messages.

SMTPUTF8 CONTROLS

The LMTP server supports SMTPUTF8 controls to enable support for internationalized email addresses. These include:

  • `lmtp_smtp_utf8_enable`: Whether to enable SMTPUTF8 support.
  • `lmtp_smtp_utf8_auto_local`: Whether to automatically convert local addresses to UTF8.
  • `lmtp_smtp_utf8_auto_domain`: Whether to automatically convert domain names to UTF8.

TROUBLE SHOOTING CONTROLS

The LMTP server supports troubleshooting controls to aid in diagnosing delivery problems. These include:

  • `lmtp_debug_peer`: Whether to enable debugging for a specific peer.
  • `lmtp_trace_peer`: Whether to enable tracing for a specific peer.
  • `lmtp_verbose_counter_enable`: Whether to enable verbose counters.

MISCELLANEOUS CONTROLS

The LMTP server supports several miscellaneous controls, including:

  • `lmtp_single_recipient_limit`: The maximum number of recipients that can be delivered to in a single LMTP session when using single-recipient delivery.
  • `lmtp_skip_deliver_temp_failures`: Whether to skip delivery of messages that resulted in temporary delivery failures.
  • `lmtp_skip_quit_socket`: Whether to close the LMTP connection immediately after a successful delivery.
