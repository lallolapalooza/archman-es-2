NOMBRE

gprof - muestra datos de perfil de grafo de llamadas

SINOPSIS

gprof [ -[abcDhilLrsTvwxyz] ] [ -[ABCeEfFJnNOpPqQRStZ][nombre] ]
[ -I directorios ] [ -d[num] ] [ -k desde/hasta ]
[ -m min-num ] [ -R archivo_mapa ] [ -t longitud_tabla ]
[ --[no-]fuente-anotada[=nombre] ]
[ --[no-]conteo-ejecuciones[=nombre] ]
[ --[no-]perfil-plano[=nombre] ] [ --[no-]grafo[=nombre] ]
[ --[no-]tiempo=nombre] [ --todas-lineas ] [ --breve ]
[ --depuracion[=nivel] ] [ --ordenacion-funciones ]
[ --ordenacion-archivos archivo_mapa ] [ --ruta-directorio=directorios ]
[ --mostrar-funciones-no-usadas ] [ --formato-archivo=nombre ]
[ --info-archivo ] [ --ayuda ] [ --linea ] [ --nombres-archivos-inline ]
[ --min-num=n ] [ --no-estatico ] [ --imprimir-ruta ]
[ --archivos-separados ] [ --grafo-estatico ] [ --suma ]
[ --longitud-tabla=longitud ] [ --tradicional ] [ --version ]
[ --ancho=n ] [ --ignorar-no-funciones ]
[ --desenredar[=ESTILO] ] [ --no-desenredar ]
[--tabla-simbolos-externos=nombre]
[ archivo_imagen ] [ archivo_perfil ... ]

DESCRIPCIÓN

"gprof" produce un perfil de ejecución de programas C, Pascal o Fortran77. El efecto de las rutinas llamadas se incorpora en el perfil de cada llamador. Los datos del perfil se toman del archivo de perfil del grafo de llamadas (gmon.out por defecto), que se crea con programas compilados con la opción -pg de "cc", "pc" y "f77". La opción -pg también enlaza versiones de las rutinas de biblioteca compiladas para perfilado. "Gprof" lee el archivo objeto dado (el valor por defecto es "a.out") y establece la relación entre su tabla de símbolos y el perfil del grafo de llamadas de gmon.out. Si se especifican varios archivos de perfil, la salida de "gprof" muestra la suma de la información del perfil en los archivos de perfil dados.

"Gprof" calcula la cantidad de tiempo dedicado a cada rutina. A continuación, estos tiempos se propagan a lo largo de los bordes del grafo de llamadas. Se descubren ciclos y las llamadas a un ciclo comparten el tiempo del ciclo.

Varias formas de salida están disponibles a partir del análisis.

El perfil plano muestra cuánto tiempo pasó tu programa en cada función y cuántas veces se llamó a esa función. Si simplemente deseas saber qué funciones consumen la mayor parte del tiempo, aquí se indica concisamente.

El grafo de llamadas muestra, para cada función, qué funciones la llamaron, qué otras funciones llamó y cuántas veces. También hay una estimación de cuánto tiempo se dedicó a las subrutinas de cada función. Esto puede sugerir lugares donde podrías intentar eliminar llamadas a funciones que consumen mucho tiempo.

La anotación de código fuente es una copia del código fuente del programa, etiquetada con el número de veces que se ejecutó cada línea del programa.

OPCIONES

Estas opciones especifican cuál de varios formatos de salida debe producir "gprof".

Muchas de estas opciones toman un symspec opcional para especificar funciones a incluir o excluir. Estas opciones se pueden especificar múltiples veces, con diferentes symspecs, para incluir o excluir conjuntos de símbolos.

Especificar cualquiera de estas opciones anula el valor por defecto (-p -q), que imprime un perfil plano y un análisis del grafo de llamadas para todas las funciones.

"-A[symspec]"
"--fuente-anotada[=symspec]"
La opción -A hace que "gprof" imprima código fuente anotado. Si se especifica symspec, imprime la salida solo para los símbolos coincidentes.
"-b"
"--breve"
Si se proporciona la opción -b, "gprof" no imprime los textos explicativos que intentan explicar el significado de todos los campos en las tablas. Esto es útil si tienes la intención de imprimir la salida, o estás cansado de ver los textos explicativos.
"-B"
La opción -B hace que "gprof" imprima el análisis del grafo de llamadas.
"-C[symspec]"
"--conteo-ejecuciones[=symspec]"
La opción -C hace que "gprof" imprima un recuento de funciones y el número de veces que cada una fue llamada. Si se especifica symspec, imprime el recuento solo para los símbolos coincidentes.

Si el archivo de datos de perfil contiene registros de recuento de bloques básicos, la especificación de la opción -l, junto con -C, hará que los recuentos de ejecución de bloques básicos se cuenten y muestren.

"-i"
"--info-archivo"
La opción -i hace que "gprof" muestre información resumida sobre los archivos de datos de perfil y luego salga. Se muestra el número de registros de histograma, grafo de llamadas y recuento de bloques básicos.
"-I directorios"
"--ruta-directorio=directorios"
La opción -I especifica una lista de directorios de búsqueda en los que encontrar archivos fuente. La variable de entorno GPROF_PATH también puede usarse para transmitir esta información. Se utiliza principalmente para la salida de código fuente anotado.
"-J[symspec]"
"--no-fuente-anotada[=symspec]"
La opción -J hace que "gprof" no imprima código fuente anotado. Si se especifica symspec, "gprof" imprime código fuente anotado, pero excluye los símbolos coincidentes.
"-L"
"--imprimir-ruta"
Normalmente, los nombres de archivo fuente se imprimen suprimiendo el componente de ruta. La opción -L hace que "gprof" imprima la ruta completa de los nombres de archivo fuente, que se determina a partir de la información de depuración simbólica en el archivo de imagen y es relativa al directorio en el que se invocó el compilador.
"-p[symspec]"
"--perfil-plano[=symspec]"
La opción -p hace que "gprof" imprima un perfil plano. Si se especifica symspec, imprime el perfil plano solo para los símbolos coincidentes.
"-P[symspec]"
"--no-perfil-plano[=symspec]"
La opción -P hace que "gprof" suprima la impresión de un perfil plano. Si se especifica symspec, "gprof" imprime un perfil plano, pero excluye los símbolos coincidentes.
"-q[symspec]"
"--grafo[=symspec]"
La opción -q hace que "gprof" imprima el análisis del grafo de llamadas. Si se especifica symspec, imprime el grafo de llamadas solo para los símbolos coincidentes y sus descendientes.
"-Q[symspec]"
"--no-grafo[=symspec]"
La opción -Q hace que "gprof" suprima la impresión del grafo de llamadas. Si se especifica symspec, "gprof" imprime un grafo de llamadas, pero excluye los símbolos coincidentes.
"-t"
"--longitud-tabla=num"
La opción -t hace que las num líneas de código fuente más activas en cada archivo fuente se listen cuando la anotación de código fuente está habilitada. El valor por defecto es 10.
"-y"
"--archivos-separados"
Esta opción solo afecta a la salida de código fuente anotado. Normalmente, "gprof" imprime los archivos fuente anotados en la salida estándar. Si se especifica esta opción, el código fuente anotado para un archivo llamado ruta/nombrearchivo se genera en el archivo nombrearchivo-ann. Si el sistema de archivos subyacente truncara nombrearchivo-ann de manera que sobrescribiera el nombrearchivo original, "gprof" generará el código fuente anotado en el archivo nombrearchivo.ann en su lugar (si el nombre de archivo original tiene una extensión, esa extensión se reemplaza por .ann).

Opciones de salida

"-a"
"--no-graph"
La opción -a le dice a "gprof" que no imprima un recuento de funciones y el número de veces que se llamó a cada una. Si se especifica symspec, imprima el recuento, pero excluya los símbolos coincidentes.
"-r"
"--function-ordering"
La opción --function-ordering hace que "gprof" imprima un orden de funciones sugerido para el programa basado en datos de perfilado. Esta opción sugiere un orden que puede mejorar el comportamiento de paginación, tlb y caché para el programa en sistemas que admiten el orden arbitrario de funciones en un ejecutable.

Los detalles exactos de cómo forzar al enlazador a colocar las funciones en un orden particular dependen del sistema y están fuera del alcance de este manual.

"-R map_file"
"--file-ordering map_file"
La opción --file-ordering hace que "gprof" imprima un orden sugerido de línea de enlace .o para el programa basado en datos de perfilado. Esta opción sugiere un orden que puede mejorar el comportamiento de paginación, tlb y caché para el programa en sistemas que no admiten el orden arbitrario de funciones en un ejecutable.

Se recomienda encarecidamente el uso del argumento -a con esta opción.

El argumento map_file es una ruta de acceso a un archivo que proporciona mapeos de nombres de funciones a archivos objeto. El formato del archivo es similar a la salida del programa "nm".

c-parse.o:00000000 T yyparse
c-parse.o:00000004 C yyerrflag
c-lang.o:00000000 T maybe_objc_method_name
c-lang.o:00000000 T print_lang_statistics
c-lang.o:00000000 T recognize_objc_keyword
c-decl.o:00000000 T print_lang_identifier
c-decl.o:00000000 T print_lang_type
...

Para crear un map_file con "nm" de GNU, escriba un comando como "nm --extern-only --defined-only -v --print-file-name program-name".

"-T"
"--traditional"
La opción -T hace que "gprof" imprima su salida en el estilo tradicional de BSD.
"-w width"
"--width=width"
Establece el ancho de las líneas de salida a width. Actualmente solo se utiliza al imprimir el índice de funciones en la parte inferior del gráfico de llamadas.
"-x"
"--all-lines"
Esta opción solo afecta la salida de código fuente anotado. Por defecto, solo se anotan las líneas al principio de un bloque básico. Si se especifica esta opción, cada línea de un bloque básico se anota repitiendo la anotación de la primera línea. Este comportamiento es similar al -a de "tcov".
"--demangle[=style]"
"--no-demangle"
Estas opciones controlan si los nombres de símbolos de C++ deben ser "demangled" (devueltos a su forma original) al imprimir la salida. La opción por defecto es "demanglear" símbolos. La opción "--no-demangle" puede usarse para desactivar el "demangling". Diferentes compiladores tienen diferentes estilos de "mangling". El argumento opcional de estilo de "demangling" se puede usar para elegir un estilo de "demangling" apropiado para su compilador.

Opciones de análisis

"-a"
"--no-static"
La opción -a hace que "gprof" suprima la impresión de funciones declaradas estáticamente (privadas). (Estas son funciones cuyos nombres no figuran como globales y que no son visibles fuera del archivo/función/bloque donde se definieron). El tiempo dedicado a estas funciones, las llamadas desde/hacia ellas, etc., se atribuirán a la función que se cargó directamente antes que ella en el archivo ejecutable. Esta opción afecta tanto al perfil plano como al gráfico de llamadas.
"-c"
"--static-call-graph"
La opción -c hace que el gráfico de llamadas del programa se aumente con una heurística que examina el espacio de texto del archivo objeto e identifica las llamadas a funciones en el código máquina binario. Dado que los registros normales del gráfico de llamadas solo se generan cuando se ingresan las funciones, esta opción identifica hijos que podrían haber sido llamados, pero nunca lo fueron. Las llamadas a funciones que no fueron compiladas con perfilado habilitado también se identifican, pero solo si existen entradas de tabla de símbolos para ellas. Las llamadas a rutinas de bibliotecas dinámicas generalmente *no* se encuentran con esta opción. Los padres o hijos identificados a través de esta heurística se indican en el gráfico de llamadas con recuentos de llamadas de 0.
"-D"
"--ignore-non-functions"
La opción -D hace que "gprof" ignore los símbolos que no se sabe que son funciones. Esta opción proporcionará datos de perfil más precisos en sistemas donde sea compatible (Solaris y HPUX, por ejemplo).
"-k from/to"
La opción -k le permite eliminar del gráfico de llamadas cualquier arco desde símbolos que coincidan con from a los que coincidan con to.
"-l"
"--line"
La opción -l habilita el perfilado línea por línea, lo que hace que los aciertos del histograma se carguen en líneas de código fuente individuales, en lugar de funciones. Esta característica solo funciona con programas compilados por versiones antiguas del compilador "gcc". Las versiones más nuevas de "gcc" están diseñadas para funcionar con la herramienta "gcov" en su lugar.

Si el programa se compiló con el conteo de bloques básicos habilitado, esta opción también identificará cuántas veces se ejecutó cada línea de código. Si bien el perfilado línea por línea puede ayudar a aislar dónde pasa el tiempo un programa en una función grande, también aumenta significativamente el tiempo de ejecución de "gprof" y magnifica las imprecisiones estadísticas.

"--inline-file-names"
Esta opción hace que "gprof" imprima el archivo fuente después de cada símbolo tanto en el perfil plano como en el gráfico de llamadas. Se imprime la ruta completa al archivo si se usa con la opción -L.
"-m num"
"--min-count=num"
Esta opción solo afecta la salida del recuento de ejecución. Se suprimen los símbolos que se ejecutan menos de num veces.
"-nsymspec"
"--time=symspec"
La opción -n hace que "gprof", en su análisis de gráfico de llamadas, solo propague los tiempos para los símbolos que coincidan con symspec.
"-Nsymspec"
"--no-time=symspec"
La opción -n hace que "gprof", en su análisis de gráfico de llamadas, no propague los tiempos para los símbolos que coincidan con symspec.
"-Sfilename"
"--external-symbol-table=filename"
La opción -S hace que "gprof" lea un archivo de tabla de símbolos externo, como /proc/kallsyms, en lugar de leer la tabla de símbolos del archivo objeto dado (el valor predeterminado es "a.out"). Esto es útil para perfilar módulos del kernel.
"-z"
"--display-unused-functions"
Si proporciona la opción -z, "gprof" mencionará todas las funciones en el perfil plano, incluso aquellas que nunca fueron llamadas y en las que no se gastó tiempo. Esto es útil junto con la opción -c para descubrir qué rutinas nunca fueron llamadas.

Opciones misceláneas

"-d[num]"
"--debug[=num]"
La opción -d num especifica opciones de depuración. Si no se especifica num, habilite toda la depuración.
"-h"
"--help"
La opción -h imprime el uso de la línea de comandos.
"-Oname"
"--file-format=name"
Selecciona el formato de los archivos de datos de perfilado. Los formatos reconocidos son auto (el predeterminado), bsd, 4.4bsd, magic y prof (aún no compatible).
"-s"
"--sum"
La opción -s hace que "gprof" resuma la información en los archivos de datos de perfilado que leyó y escriba un archivo de datos de perfilado llamado gmon.sum, que contiene toda la información de los archivos de datos de perfilado que "gprof" leyó. El archivo gmon.sum puede ser uno de los archivos de entrada especificados; el efecto de esto es fusionar los datos de los otros archivos de entrada en gmon.sum.

Eventualmente, puede volver a ejecutar "gprof" sin -s para analizar los datos acumulativos en el archivo gmon.sum.

"-v"
"--version"
La opción -v hace que "gprof" imprima el número de versión actual y luego salga.

Opciones obsoletas

Estas opciones han sido reemplazadas por versiones más nuevas que utilizan "symspecs".

"-e function_name"
La opción -e function le indica a "gprof" que no imprima información sobre la función function_name (y sus hijos...) en el gráfico de llamadas. La función todavía se listará como un hijo de cualquier función que la llame, pero su número de índice se mostrará como [no impreso]. Se puede dar más de una opción -e; solo se puede indicar un function_name con cada opción -e.
"-E function_name"
La opción "-E function" funciona como la opción "-e", pero el tiempo dedicado a la función (y a los hijos que no fueron llamados desde ningún otro lugar) no se utilizará para calcular los porcentajes de tiempo para el gráfico de llamadas. Se puede dar más de una opción -E; solo se puede indicar un function_name con cada opción -E.
"-f function_name"
La opción -f function hace que "gprof" para limitar el grafo de llamadas a la función nombre_funcion y sus hijos (y los hijos de sus hijos...). Se puede dar más de una opción -f; solo se puede indicar un nombre_funcion con cada opción -f.
"-F nombre_funcion"
La opción -F funcion funciona como la opción "-f", pero solo el tiempo dedicado a la función y sus hijos (y los hijos de sus hijos...) se utilizará para determinar el tiempo total y los porcentajes de tiempo para el grafo de llamadas. Se puede dar más de una opción -F; solo se puede indicar un nombre_funcion con cada opción -F. La opción -F anula la opción -E.

ARCHIVOS

"a.out"
el espacio de nombres y texto.
"gmon.out"
grafo de llamadas dinámicas y perfil.
"gmon.sum"
grafo de llamadas dinámicas y perfil resumidos.

ERRORES

Se muestra la granularidad del muestreo, pero sigue siendo, en el mejor de los casos, estadística. Suponemos que el tiempo de cada ejecución de una función se puede expresar por el tiempo total de la función dividido por el número de veces que se llama a la función. Por lo tanto, el tiempo propagado a lo largo de los arcos del grafo de llamadas a los padres de la función es directamente proporcional al número de veces que se atraviesa ese arco.

Los padres que no son perfilados tendrán el tiempo de sus hijos perfilados propagado a ellos, pero aparecerán como invocados espontáneamente en la lista del grafo de llamadas y no propagarán su tiempo más allá. De manera similar, los capturadores de señales, aunque perfilados, aparecerán como espontáneos (aunque por razones más oscuras). Los hijos perfilados de los capturadores de señales deberían tener su tiempo propagado correctamente, a menos que el capturador de señales se invocara durante la ejecución de la rutina de perfilado, en cuyo caso todo está perdido.

El programa perfilado debe llamar a "exit"(2) o retornar normalmente para que la información de perfilado se guarde en el archivo gmon.out.
