DESCRIPCIÓN

objdump muestra información sobre uno o más archivos objeto. Las opciones controlan qué información específica se muestra. Esta información es principalmente útil para programadores que trabajan en las herramientas de compilación, en contraposición a los programadores que solo quieren que su programa compile y funcione.

archivoobjeto... son los archivos objeto a examinar. Cuando especifica archivos (archives), objdump muestra información sobre cada uno de los archivos objeto miembro.

OPCIONES

Las formas largas y cortas de las opciones, que se muestran aquí como alternativas, son equivalentes. Se debe proporcionar al menos una opción de la lista -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x.

-a
--archive-headers
Si alguno de los archivos archivoobjeto son archivos (archives), muestra la información de cabecera del archivo (en un formato similar a ls -l). Además de la información que podría listar con ar tv, objdump -a muestra el formato del archivo objeto de cada miembro del archivo.
--adjust-vma=offset
Al mostrar información, primero suma offset a todas las direcciones de sección. Esto es útil si las direcciones de sección no se corresponden con la tabla de símbolos, lo que puede ocurrir al colocar secciones en direcciones específicas cuando se usa un formato que no puede representar direcciones de sección, como a.out.
-b nombrebfd
--target=nombrebfd
Especifica que el formato del código objeto para los archivos objeto es nombrebfd. Es posible que esta opción no sea necesaria; objdump puede reconocer muchos formatos automáticamente.

Por ejemplo,

objdump -b oasys -m vax -h fu.o

muestra información resumida de las cabeceras de sección (-h) de fu.o, que se identifica explícitamente (-m) como un archivo objeto VAX en el formato producido por los compiladores Oasys. Puede listar los formatos disponibles con la opción -i.

-C
--demangle[=estilo]
Decodifica (demangle) nombres de símbolos de bajo nivel en nombres de nivel de usuario. Además de eliminar el guion bajo inicial agregado por el sistema, esto hace que los nombres de funciones C++ sean legibles. Diferentes compiladores tienen diferentes estilos de mangling. El argumento opcional del estilo de demangling puede usarse para elegir un estilo de demangling apropiado para su compilador.
--recursion-limit
--no-recursion-limit
--recursion
--no-recursion
Habilita o deshabilita un límite en la cantidad de recursión realizada al demangling cadenas. Dado que los formatos de mangling de nombres permiten un nivel infinito de recursión, es posible crear cadenas cuya decodificación agote el espacio de pila disponible en la máquina anfitriona, provocando un fallo de memoria. El límite intenta evitar que esto suceda restringiendo la recursión a 2048 niveles de anidamiento.

El valor predeterminado es que este límite esté habilitado, pero deshabilitarlo puede ser necesario para demangling nombres verdaderamente complicados. Tenga en cuenta, sin embargo, que si el límite de recursión está deshabilitado, es posible agotar la pila y cualquier informe de error sobre tal evento será rechazado.

-g
--debugging
Muestra información de depuración. Esto intenta analizar la información del formato de depuración STABS almacenada en el archivo y la imprime usando una sintaxis similar a C. Si no se encontró depuración STABS, esta opción recurre a la opción -W para imprimir cualquier información DWARF en el archivo.
-e
--debugging-tags
Al igual que -g, pero la información se genera en un formato compatible con la herramienta ctags.
-d
--disassemble=simbolo
Muestra las mnemónicas del ensamblador para las instrucciones de máquina del archivo de entrada. Esta opción solo desensambla las secciones que se espera que contengan instrucciones. Si se proporciona el argumento opcional simbolo, entonces muestra las mnemónicas del ensamblador comenzando en simbolo. Si simbolo es un nombre de función, el desensamblado se detendrá al final de la función; de lo contrario, se detendrá cuando se encuentre el siguiente símbolo. Si no hay coincidencias para simbolo, no se mostrará nada.

Tenga en cuenta que si la opción --dwarf=follow-links está habilitada, entonces se leerán las tablas de símbolos en los archivos de información de depuración enlazados y se utilizarán al desensamblar.

-D
--disassemble-all
Al igual que -d, pero desensambla
OBJFDUMP(1) February 2023 objdump
DESCRIPTION

objdump is a generic filter for object-code.

It can be used to display information from object files, and to translate native<< abstract machine-code to readable output. objdump may be used to display information in your object files that is in standard UNIX COFF, ELF, a.out, or SOM format. The information displayed is of use to compiler writers and software maintainers, for understanding the compiled code. objdump may be used on archive files when the archive manager has been run on them.

The exact command line interface to objdump is unstable and may change in future versions.

OPTIONS

You can send input to objdump via standard input instead of as a file argument.

-d
--disassemble
Disassemble the contents of the executable sections of each object file. By default objdump only disassembles compiler generated code. It will refuse to disassemble functions containing error reporting code, as that may be very large and it may not be useful to disassemble it.
-D
--disassemble-all
Disassemble the contents of all sections of each object file, not just executable sections. This includes sections that might contain data. This option is used to assemble the contents of all non-empty non-bss sections, not just those expected to contain instructions. -j may be used to select specific sections.

This option also has a subtle effect on the disassembly of instructions in code sections. When option -d is in effect objdump will assume that any symbols present in a code section occur on the boundary between instructions and it will refuse to disassemble across such a boundary. When option -D is in effect however this assumption is supressed. This means that it is possible for the output of -d and -D to differ if, for example, data is stored in code sections.

If the target is an ARM architecture this switch also has the effect of forcing the disassembler to decode pieces of data found in code sections as if they were instructions.

Note if the --dwarf=follow-links option is enabled then any symbol tables in linked debug info files will be read in and used when disassembling.

--no-addresses
When disassembling, don't print addresses on each line or for symbols and relocation offsets. In combination with --no-show-raw-insn this may be useful for comparing compiler output.
--prefix-addresses
When disassembling, print the complete address on each line. This is the older disassembly format.
-EB
-EL
--endian={big|little}
Specify the endianness of the object files. This only affects disassembly. This can be useful when disassembling a file format which does not describe endianness information, such as S-records.
-f
--file-headers
Display summary information from the overall header of each of the objfile files.
-F
--file-offsets
When disassembling sections, whenever a symbol is displayed, also display the file offset of the region of data that is about to be dumped. If zeroes are being skipped, then when disassembly resumes, tell the user how many zeroes were skipped and the file offset of the location from where the disassembly resumes. When dumping sections, display the file offset of the location from where the dump starts.
--file-start-context
Specify that when displaying interlisted source code/disassembly (assumes -S) from a file that has not yet been displayed, extend the context to the start of the file.
-h
--section-headers
--headers
Display summary information from the section headers of the object file.

File segments may be relocated to nonstandard addresses, for example by using the -Ttext, -Tdata, or -Tbss options to ld. However, some object file formats, such as a.out, do not store the starting address of the file segments. In those situations, although ld relocates the sections correctly, using objdump -h to list the file section headers cannot show the correct addresses. Instead, it shows the usual addresses, which are implicit for the target.

Note, in some cases it is possible for a section to have both the READONLY and the NOREAD attributes set. In such cases the NOREAD attribute takes precedence, but objdump will report both since the exact setting of the flag bits might be important.

-H
--help
Print a summary of the options to objdump and exit.
-i
--info
Display a list showing all architectures and object formats available for specification with -b or -m.
-j name
--section=name
Display information for section name. This option may be specified multiple times.
-L
--process-links
Display the contents of non-debug sections found in separate debuginfo files that are linked to the main file. This option automatically implies the -WK option, and only sections requested by other command line options will be displayed.
-l
--line-numbers
Label the display (using debugging information) with the filename and source line numbers corresponding to the object code or relocs shown. Only useful with -d, -D, or -r.
-m machine
--architecture=machine
Specify the architecture to use when disassembling object files. This can be useful when disassembling object files which do not describe architecture information, such as S-records. You can list the available architectures with the -i option.

For most architectures it is possible to supply an architecture name and a machine name, separated by a colon. For example foo:bar would refer to the bar machine type in the foo architecture. This can be helpful if objdump has been configured to support multiple architectures.

If the target is an ARM architecture then this switch has an additional effect. It restricts the disassembly to only those instructions supported by the architecture specified by machine. If it is necessary to use this switch because the input file does not contain any architecture information, but it is also desired to disassemble all the instructions use -marm.

-M options
--disassembler-options=options
Pass target specific information to the disassembler. Only supported on some targets. If it is necessary to specify more than one disassembler option then multiple -M options can be used or can be placed together into a comma separated list.

For ARC, dsp controls the printing of DSP instructions, spfp selects the printing of FPX single precision FP instructions, dpfp selects the printing of FPX double precision FP instructions, quarkse_em selects the printing of special QuarkSE-EM instructions, fpuda selects the printing of double precision assist instructions, fpus selects the printing of FPU single precision FP instructions, while fpud selects the printing of FPU double precision FP instructions. Additionally, one can choose to have all the immediates printed in hexadecimal using hex. By default, the short immediates are printed using the decimal representation, while the long immediate values are printed as hexadecimal.

cpu=... allows one to enforce a particular ISA when disassembling instructions, overriding the -m value or whatever is in the ELF file. This might be useful to select ARC EM or HS ISA, because architecture is same for those and disassembler relies on private ELF header data to decide if code is for EM or HS. This option might be specified multiple times - only the latest value will be used. Valid values are same as for the assembler -mcpu=... option.

If the target is an ARM architecture then this switch can be used to select which register name set is used during disassembler. Specifying -M reg-names-std (the default) will select the register names as used in ARM's instruction set documentation, but with register 13 called 'sp', register 14 called 'lr' and register 15 called 'pc'. Specifying -M reg-names-apcs will select the name set used by the ARM Procedure Call Standard, whilst specifying -M reg-names-raw will just use r followed by the register number.

There are also two variants on the APCS register naming scheme enabled by -M reg-names-atpcs and -M reg-names-special-atpcs which use the ARM/Thumb Procedure Call Standard naming conventions. (Either with the normal register names or the special register names).

This option can also be used for ARM architectures to force the disassembler to interpret all instructions as Thumb instructions by using the switch --disassembler-options=force-thumb. This can be useful when attempting to disassemble thumb code produced by other compilers.

For AArch64 targets this switch can be used to set whether instructions are disassembled as the most general instruction using the -M no-aliases option or whether instruction notes should be generated as comments in the disasssembly using -M notes.

For the x86, some of the options duplicate functions of the -m switch, but allow finer grained control.

"x86-64"
"i386"
"i8086"
Select disassembly for the given architecture.
"intel"
"att"
Select between intel syntax mode and AT&T syntax mode.
"amd64"
"intel64"
Select between AMD64 ISA and Intel64 ISA.
"intel-mnemonic"
"att-mnemonic"
Select between intel mnemonic mode and AT&T mnemonic mode. Note: "intel-mnemonic" implies "intel" and "att-mnemonic" implies "att".
"addr64"
"addr32"
"addr16"
"data32"
"data16"
Especifica el tamaño de dirección y el tamaño de operando predeterminados. Estas cinco opciones serán anuladas si "x86-64", "i386" o "i8086" aparecen más tarde en la cadena de opciones.
"suffix"
Cuando está en modo AT&T y también para un conjunto limitado de instrucciones en modo Intel, indica al desensamblador que imprima un sufijo de mnemotecnia incluso cuando el sufijo podría ser inferido por los operandos o, para ciertas instrucciones, por los valores predeterminados del modo de ejecución.

Para PowerPC, el argumento -M raw selecciona el desensamblado de instrucciones de hardware en lugar de alias. Por ejemplo, verá "rlwinm" en lugar de "clrlwi", y "addi" en lugar de "li". Todos los argumentos -m para gas que seleccionan una CPU son compatibles. Estos son: 403, 405, 440, 464, 476, 601, 603, 604, 620, 7400, 7410, 7450, 7455, 750cl, 821, 850, 860, a2, booke, booke32, cell, com, e200z2, e200z4, e300, e500, e500mc, e500mc64, e500x2, e5500, e6500, efs, power4, power5, power6, power7, power8, power9, power10, ppc, ppc32, ppc64, ppc64bridge, ppcps, pwr, pwr2, pwr4, pwr5, pwr5x, pwr6, pwr7, pwr8, pwr9, pwr10, pwrx, titan, vle y future. 32 y 64 modifican la selección de CPU predeterminada o anterior, deshabilitando y habilitando respectivamente las instrucciones de 64 bits. Además, altivec, any, lsp, htm, vsx, spe y spe2 agregan capacidades a una selección de CPU anterior o posterior. any desensamblará cualquier opcode conocido por binutils, pero en casos donde un opcode tiene dos significados diferentes o argumentos diferentes, es posible que no vea el desensamblado que espera. Si desensambla sin proporcionar una selección de CPU, se elegirá una predeterminada a partir de la información obtenida por BFD de las cabeceras de los archivos objeto, pero el resultado nuevamente puede no ser el que espera.

Para MIPS, esta opción controla la impresión de nombres de mnemotecnia de instrucciones y nombres de registros en instrucciones desensambladas. Se pueden especificar múltiples selecciones de las siguientes opciones como una cadena separada por comas, y las opciones inválidas se ignoran:

"no-aliases"
Imprime la mnemotecnia de instrucción 'raw' en lugar de algunas mnemotecnias de instrucción pseudo. Es decir, imprime 'daddu' u 'or' en lugar de 'move', 'sll' en lugar de 'nop', etc.
"msa"
Desensambla instrucciones MSA.
"virt"
Desensambla las instrucciones ASE de virtualización.
"xpa"
Desensambla las instrucciones ASE de eXtended Physical Address (XPA).
"gpr-names=ABI"
Imprime los nombres de GPR (registro de propósito general) según corresponda a la ABI especificada. Por defecto, los nombres de GPR se seleccionan de acuerdo con la ABI del binario que se está desensamblando.
"fpr-names=ABI"
Imprime los nombres de FPR (registro de punto flotante) según corresponda a la ABI especificada. Por defecto, se imprimen números de FPR en lugar de nombres.
"cp0-names=ARCH"
Imprime los nombres de registros CP0 (coprocesador de control del sistema; coprocesador 0) según corresponda a la CPU o arquitectura especificada por ARCH. Por defecto, los nombres de registros CP0 se seleccionan de acuerdo con la arquitectura y CPU del binario que se está desensamblando.
"hwr-names=ARCH"
Imprime los nombres de HWR (registro de hardware, utilizado por la instrucción "rdhwr") según corresponda a la CPU o arquitectura especificada por ARCH. Por defecto, los nombres de HWR se seleccionan de acuerdo con la arquitectura y CPU del binario que se está desensamblando.
"reg-names=ABI"
Imprime los nombres de GPR y FPR según corresponda a la ABI seleccionada.
"reg-names=ARCH"
Imprime los nombres de registros específicos de la CPU (nombres de registros CP0 y HWR) según corresponda a la CPU o arquitectura seleccionada.

Para cualquiera de las opciones enumeradas anteriormente, ABI o ARCH pueden especificarse como numeric para que se impriman números en lugar de nombres, para los tipos de registros seleccionados. Puede enumerar los valores disponibles de ABI y ARCH utilizando la opción --help.

Para VAX, puede especificar direcciones de entrada de funciones con -M entry:0xf00ba. Puede usar esto varias veces para desensamblar correctamente archivos binarios VAX que no contienen tablas de símbolos (como volcados de ROM). En estos casos, la máscara de entrada de función se decodificaría de lo contrario como instrucciones VAX, lo que probablemente provocaría que el resto de la función se desensamblara incorrectamente.

-p
--private-headers
Imprime información específica del formato del archivo objeto. La información exacta impresa depende del formato del archivo objeto. Para algunos formatos de archivo objeto, no se imprime información adicional.
-P options
--private=options
Imprime información específica del formato del archivo objeto. El argumento options es una lista separada por comas que depende del formato (la lista de opciones se muestra con la ayuda).

Para XCOFF, las opciones disponibles son:

"header"
"aout"
"sections"
"syms"
"relocs"
"lineno,"
"loader"
"except"
"typchk"
"traceback"
"toc"
"ldinfo"

Para PE, las opciones disponibles son:

"header"
"sections"

No todos los formatos de objeto admiten esta opción. En particular, el formato ELF no la utiliza.

-r
--reloc
Imprime las entradas de reubicación del archivo. Si se usa con -d o -D, las reubicaciones se imprimen intercaladas con el desensamblado.
-R
--dynamic-reloc
Imprime las entradas de reubicación dinámicas del archivo. Esto solo es significativo para objetos dinámicos, como ciertos tipos de bibliotecas compartidas. Al igual que con -r, si se usa con -d o -D, las reubicaciones se imprimen intercaladas con el desensamblado.
-s
--full-contents
Muestra el contenido completo de las secciones, a menudo se usa en combinación con -j para solicitar secciones específicas. Por defecto, se muestran todas las secciones no vacías que no son bss. Por defecto, cualquier sección comprimida se mostrará en su forma comprimida. Para ver el contenido en forma descomprimida, agregue la opción -Z a la línea de comandos.
-S
--source
Muestra el código fuente intercalado con el desensamblado, si es posible. Implica -d.
--show-all-symbols
Al desensamblar, muestra todos los símbolos que coinciden con una dirección dada, no solo el primero.
--source-comment[=txt]
Al igual que la opción -S, pero todas las líneas de código fuente se muestran con un prefijo de txt. Típicamente txt será una cadena de comentario que se puede usar para distinguir el código ensamblador del código fuente. Si no se proporciona txt, se usará una cadena predeterminada de "# " (hash seguido de un espacio).
--prefix=prefix
Especifica prefix para agregar a las rutas absolutas cuando se usa con -S.
--prefix-strip=level
Indica cuántos nombres de directorio iniciales se eliminarán de las rutas absolutas codificadas. No tiene efecto sin --prefix=prefix.
--show-raw-insn
Al desensamblar instrucciones, imprime la instrucción en hexadecimal, así como en forma simbólica. Esto es el valor predeterminado, excepto cuando se usa --prefix-addresses.
--no-show-raw-insn
Al desensamblar instrucciones, no imprime los bytes de la instrucción. Este es el valor predeterminado cuando se usa --prefix-addresses.
--insn-width=width
Muestra width bytes en una sola línea al desensamblar instrucciones.
--visualize-jumps[=color|=extended-color|=off]
Visualiza los saltos que permanecen dentro de una función dibujando arte ASCII entre las direcciones de inicio y destino. El argumento opcional =color agrega color a la salida utilizando colores de terminal simples. Alternativamente, el argumento =extended-color agregará color utilizando colores de 8 bits, pero es posible que estos no funcionen en todos los terminales.

Si es necesario deshabilitar la opción visualize-jumps después de haberla habilitado previamente, use visualize-jumps=off.

--disassembler-color=off
--disassembler-color=terminal
--disassembler-color=on|color|colour
--disassembler-color=extened|extended-color|extened-colour
Habilita o deshabilita el uso de resaltado de sintaxis en color en la salida de desensamblado. El valor predeterminado
el comportamiento se determina mediante una opción de configuración. Tenga en cuenta que no todas las arquitecturas admiten el resaltado de sintaxis en color y, dependiendo del terminal utilizado, la salida en color puede no ser legible.

El argumento on añade colores utilizando colores de terminal simples.

El argumento terminal hace lo mismo, pero solo si el dispositivo de salida es un terminal.

El argumento extended-color es similar al argumento on, pero utiliza colores de 8 bits. Estos pueden no funcionar en todos los terminales.

El argumento off deshabilita el desmontaje en color.

-W[lLiaprmfFsoORtUuTgAckK]
--dwarf[=rawline,=decodedline,=info,=abbrev,=pubnames,=aranges,=macro,=frames,=frames-interp,=str,=str-offsets,=loc,=Ranges,=pubtypes,=trace_info,=trace_abbrev,=trace_aranges,=gdb_index,=addr,=cu_index,=links,=follow-links]
Muestra el contenido de las secciones de depuración DWARF en el archivo, si las hay. Las secciones de depuración comprimidas se descomprimen automáticamente (temporalmente) antes de mostrarlas. Si una o más de las letras o palabras opcionales siguen al conmutador, solo se volcarán esos tipos de datos. Las letras y palabras se refieren a la siguiente información:
"a"
"=abbrev"
Muestra el contenido de la sección .debug_abbrev.
"A"
"=addr"
Muestra el contenido de la sección .debug_addr.
"c"
"=cu_index"
Muestra el contenido de las secciones .debug_cu_index y/o .debug_tu_index.
"f"
"=frames"
Muestra el contenido sin procesar de una sección .debug_frame.
"F"
"=frames-interp"
Muestra el contenido interpretado de una sección .debug_frame.
"g"
"=gdb_index"
Muestra el contenido de las secciones .gdb_index y/o .debug_names.
"i"
"=info"
Muestra el contenido de la sección .debug_info. Nota: la salida de esta opción también puede restringirse mediante las opciones --dwarf-depth y --dwarf-start.
"k"
"=links"
Muestra el contenido de las secciones .gnu_debuglink, .gnu_debugaltlink y .debug_sup, si alguna de ellas está presente. También muestra enlaces a archivos de objetos de depuración separados (dwo), si están especificados por los atributos DW_AT_GNU_dwo_name o DW_AT_dwo_name en la sección .debug_info.
"K"
"=follow-links"
Muestra el contenido de cualquier sección de depuración seleccionada que se encuentre en archivos de información de depuración separados y enlazados. Esto puede resultar en que se muestren varias versiones de la misma sección de depuración si existe en más de un archivo.

Además, al mostrar atributos DWARF, si se encuentra un formulario que hace referencia al archivo de información de depuración separado, se mostrará también el contenido referenciado.

Nota: en algunas distribuciones, esta opción está habilitada por defecto. Se puede deshabilitar mediante la opción de depuración N. La opción por defecto se puede elegir al configurar las binutils mediante las opciones --enable-follow-debug-links=yes o --enable-follow-debug-links=no. Si estas no se utilizan, la opción por defecto es habilitar el seguimiento de los enlaces de depuración.

Nota: si el soporte para el protocolo debuginfod se habilitó al compilar las binutils, esta opción también incluirá un intento de contactar a cualquier servidor debuginfod mencionado en la variable de entorno DEBUGINFOD_URLS. Esto puede llevar tiempo en resolverse. Este comportamiento se puede deshabilitar mediante la opción de depuración =do-not-use-debuginfod.

"N"
"=no-follow-links"
Deshabilita el seguimiento de enlaces a archivos de información de depuración separados.
"D"
"=use-debuginfod"
Habilita el contacto con servidores debuginfod si es necesario seguir los enlaces de depuración. Este es el comportamiento por defecto.
"E"
"=do-not-use-debuginfod"
Deshabilita el contacto con servidores debuginfod cuando es necesario seguir los enlaces de depuración.

--dwarf-depth=n
Limita la visualización de la sección ".debug_info" a n hijos. Esto solo es útil con --debug-dump=info. El valor predeterminado es imprimir todas las DIE; el valor especial 0 para n tendrá también este efecto.

Con un valor distinto de cero para n, las DIE en o por debajo del nivel n no se imprimirán. El rango para n se basa en cero.

--dwarf-start=n
Imprime solo las DIE a partir de la DIE número n. Esto solo es útil con --debug-dump=info.

Si se especifica, esta opción suprimirá la impresión de cualquier información de encabezado y de todas las DIE anteriores a la DIE número n. Solo se imprimirán los hermanos e hijos de la DIE especificada.

Esto se puede usar junto con --dwarf-depth.

--dwarf-check
Habilita comprobaciones adicionales de consistencia de la información Dwarf.
--ctf[=sección]
Muestra el contenido de la sección CTF especificada. Las secciones CTF contienen muchos sub-elementos, todos los cuales se muestran en orden.

Por defecto, muestra el nombre de la sección llamada .ctf, que es el nombre emitido por ld.

--ctf-parent=miembro
Si la sección CTF contiene tipos definidos de forma ambigua, consistirá en un archivo de muchos diccionarios CTF, todos heredando de un diccionario que contiene tipos no ambiguos. Este miembro se llama por defecto .ctf, como la sección que lo contiene, pero es posible cambiar este nombre utilizando la función "ctf_link_set_memb_name_changer" en tiempo de enlace. Al examinar archivos CTF que han sido creados por un enlazador que utiliza el cambiador de nombres para renombrar el miembro del archivo principal, --ctf-parent se puede utilizar para especificar el nombre utilizado para el principal.
--sframe[=sección]
Muestra el contenido de la sección SFrame especificada.

Por defecto, muestra el nombre de la sección llamada .sframe, que es el nombre emitido por ld.

-G
--stabs
Muestra el contenido completo de cualquier sección solicitada. Muestra el contenido de las secciones .stab y .stab.index y .stab.excl de un archivo ELF. Esto solo es útil en sistemas (como Solaris 2.0) en los que las entradas de tabla de símbolos de depuración ".stab" se transportan en una sección ELF. En la mayoría de los demás formatos de archivo, las entradas de tabla de símbolos de depuración se intercalan con símbolos de enlace y son visibles en la salida de --syms.
--start-address=dirección
Comienza a mostrar datos en la dirección especificada. Esto afecta la salida de las opciones -d, -r y -s.
--stop-address=dirección
Detiene la visualización de datos en la dirección especificada. Esto afecta la salida de las opciones -d, -r y -s.
-t
--syms
Imprime las entradas de la tabla de símbolos del archivo. Esto es similar a la información proporcionada por el programa nm, aunque el formato de visualización es diferente. El formato de la salida depende del formato del archivo que se está volcando, pero hay dos tipos principales. Uno se ve así:

OPTIONS

-T
--dynamic-syms
Imprime las entradas de la tabla de símbolos dinámicos del archivo. Esto solo es significativo para objetos dinámicos, como ciertos tipos de bibliotecas compartidas. Es similar a la información proporcionada por el programa nm cuando se le da la opción -D (--dynamic).

El formato de salida es similar al producido por la opción --syms, excepto que se inserta un campo adicional antes del nombre del símbolo, que proporciona la información de versión asociada con el símbolo. Si la versión es la versión predeterminada que se utilizará al resolver referencias no versionadas al símbolo, se muestra tal cual; de lo contrario, se pone entre paréntesis.

--special-syms
Al mostrar símbolos, incluya aquellos que el objetivo considera especiales de alguna manera y que normalmente no serían de interés para el usuario.
-U [d|i|l|e|x|h]
--unicode=[default|invalid|locale|escape|hex|highlight]
Controla la visualización de caracteres multibyte codificados en UTF-8 en cadenas. El valor predeterminado (--unicode=default) es no darles ningún tratamiento especial. La opción --unicode=locale muestra la secuencia en la configuración regional actual, que puede admitirla o no. Las opciones --unicode=hex y --unicode=invalid las muestran como secuencias de bytes hexadecimales encerradas entre corchetes angulares o llaves.

La opción --unicode=escape las muestra como secuencias de escape (\uxxxx) y la opción --unicode=highlight las muestra como secuencias de escape resaltadas en rojo (si el dispositivo de salida lo admite). El coloreado pretende llamar la atención sobre la presencia de secuencias unicode donde no se esperarían.

-V
--version
Imprime el número de versión de objdump y sale.
-x
--all-headers
Muestra toda la información de encabezado disponible, incluidas la tabla de símbolos y las entradas de reubicación. Usar -x equivale a especificar todos los -a -f -h -p -r -t.
-w
--wide
Formatea algunas líneas para dispositivos de salida que tienen más de 80 columnas. Tampoco trunca los nombres de los símbolos cuando se muestran.
-z
--disassemble-zeroes
Normalmente, la salida del desmontaje omitirá los bloques de ceros. Esta opción indica al desensamblador que desensamble esos bloques, al igual que cualquier otro dato.
-Z
--decompress
La opción -Z está pensada para usarse junto con la opción -s. Le indica a objdump que descomprima cualquier sección comprimida antes de mostrar su contenido.
@file
Lee las opciones de línea de comandos de file. Las opciones leídas se insertan en lugar de la opción original @file. Si file no existe o no se puede leer, la opción se tratará literalmente y no se eliminará.

Las opciones en file están separadas por espacios en blanco. Se puede incluir un carácter de espacio en blanco en una opción rodeando la opción completa con comillas simples o dobles. Se puede incluir cualquier carácter (incluido una barra invertida) anteponiendo el carácter a incluir con una barra invertida. El file puede contener a su vez opciones adicionales @file; dichas opciones se procesarán recursivamente.
