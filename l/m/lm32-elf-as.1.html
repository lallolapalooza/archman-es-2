DESCRIPCIÓN

GNU as es realmente una familia de ensambladores. Si has usado (o has usado) el ensamblador GNU en una arquitectura, deberías encontrar un entorno bastante similar cuando lo uses en otra arquitectura. Cada versión tiene mucho en común con las otras, incluyendo los formatos de archivo objeto, la mayoría de las directivas del ensamblador (a menudo llamadas pseudo-ops) y la sintaxis del ensamblador.

as está diseñado principalmente para ensamblar la salida del compilador C de GNU "gcc" para ser usada por el enlazador "ld". Sin embargo, hemos intentado que as ensamble correctamente todo lo que otros ensambladores para la misma máquina ensamblarían. Cualquier excepción se documenta explícitamente. Esto no significa que as siempre use la misma sintaxis que otro ensamblador para la misma arquitectura; por ejemplo, conocemos varias versiones incompatibles de la sintaxis del lenguaje ensamblador 680x0.

Cada vez que ejecutas as ensambla exactamente un programa fuente. El programa fuente consta de uno o más archivos. (La entrada estándar también es un archivo.)

Le proporcionas a as una línea de comandos que tiene cero o más nombres de archivo de entrada. Los archivos de entrada se leen (de izquierda a derecha). Un argumento de línea de comandos (en cualquier posición) que no tenga un significado especial se considera un nombre de archivo de entrada.

Si le das a as ningún nombre de archivo, intentará leer un archivo de entrada de la entrada estándar de as, que normalmente es tu terminal. Puede que tengas que escribir ctl-D para indicarle a as que no hay más programa que ensamblar.

Usa -- si necesitas nombrar explícitamente el archivo de entrada estándar en tu línea de comandos.

Si la fuente está vacía, as produce un archivo objeto pequeño y vacío.

as puede escribir advertencias y mensajes de error en el archivo de error estándar (normalmente tu terminal). Esto no debería suceder cuando un compilador ejecuta as automáticamente. Las advertencias informan de una suposición hecha para que as pudiera seguir ensamblando un programa defectuoso; los errores informan de un problema grave que detiene el ensamblaje.

Si invocas as a través del compilador C de GNU, puedes usar la opción -Wa para pasar argumentos al ensamblador. Los argumentos del ensamblador deben estar separados entre sí (y de -Wa) por comas. Por ejemplo:

gcc -c -g -O -Wa,-alh,-L file.c

Esto pasa dos opciones al ensamblador: -alh (emitir una lista en la salida estándar con código fuente de alto nivel y ensamblado) y -L (mantener los símbolos locales en la tabla de símbolos).

Normalmente no necesitas usar este mecanismo -Wa, ya que el compilador pasa automáticamente muchas opciones de línea de comandos al ensamblador. (Puedes llamar al controlador del compilador GNU con la opción -v para ver exactamente qué opciones pasa a cada fase de compilación, incluyendo el ensamblador.)

OPCIONES

@archivo
Lee las opciones de la línea de comandos de archivo. Las opciones leídas se insertan en lugar de la opción @archivo original. Si archivo no existe o no se puede leer, la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter de espacio en blanco puede incluirse en una opción rodeando la opción completa con comillas simples o dobles. Cualquier carácter (incluyendo una barra invertida) puede incluirse anteponiendo el carácter a incluir con una barra invertida. El archivo puede contener él mismo opciones adicionales de @archivo; dichas opciones se procesarán recursivamente.

-a[cdghilmns]
Activa las listas, de diversas maneras:
-ac
omitir condicionales falsos
-ad
omitir directivas de depuración
-ag
incluir información general, como la versión de as y las opciones pasadas
-ah
incluir código fuente de alto nivel y ensamblado
-ai
incluir directivas de ensamblado
-al
incluir líneas de código fuente de alto nivel
-am
incluir información de macros
-an
no incluir líneas de código fuente
-as
incluir código fuente de ensamblado

La opción -a sin argumentos activa todas las opciones de listado anteriores.

Todas las opciones de listado generan la lista en la salida estándar. Normalmente querrás redirigir esto a un archivo. Por ejemplo, para obtener un listado que incluya el código fuente de alto nivel y las líneas de macro, puedes usar:

as -a -am -al file.s -o file.o

--alternate-syntax

Usa la sintaxis alternativa de Intel para el ensamblador x86.

-Bdest

El nombre del directorio donde se encuentran los archivos de soporte de salida. El valor predeterminado es la ubicación del compilador.

-b

Especifique -b para el destino picoJava (byte-code).

-c

No eliminar los símbolos de línea de comandos de la tabla de símbolos al generar un archivo de objeto.

-D

Por defecto, el ensamblador genera un archivo objeto con un solo segmento de datos. La opción -D genera un archivo objeto con múltiples segmentos de datos.

-d

Por defecto, el ensamblador genera un archivo objeto con un solo segmento de código. La opción -d genera un archivo objeto con múltiples segmentos de código.

-EB

Big-endian. El orden de bytes predeterminado de la arquitectura.

-EL

Little-endian. El orden de bytes predeterminado de la arquitectura.

-f

Por defecto, el ensamblador genera un archivo objeto con un solo segmento de datos. La opción -f genera un archivo objeto con múltiples segmentos de datos.

-g

Esta opción está obsoleta y ya no se utiliza.

-G num

Para la arquitectura s390, la opción -G num indica el tamaño de los datos globales. El valor predeterminado es 8. (No se utiliza con la arquitectura x86)

-h

Incluir información de alto nivel en la tabla de símbolos.

-I dir

Añade el directorio dir a la ruta de búsqueda de los archivos de inclusión (directivas .include).

-i

Por defecto, el ensamblador genera un archivo objeto con un solo segmento de código. La opción -i genera un archivo objeto con múltiples segmentos de código.

-L

No eliminar los símbolos locales (aquellos cuyos nombres comienzan con L) de la tabla de símbolos al generar un archivo de objeto. Normalmente, el enlazador los elimina.

-l

Genera un archivo de listado de ensamblado para su procesamiento posterior por el programa GNUpretty.

-m macchina

Ensambla para la máquina macchina. Las máquinas admitidas dependen de la versión de as.

-march=arch

Ensambla para la arquitectura arch.

-N

No eliminar los símbolos globales de la tabla de símbolos al generar un archivo de objeto.

-n

Omite el tratamiento de los símbolos locales.

--no-warn

Suprime la generación de mensajes de advertencia. Por ejemplo, no advertir sobre el uso de un nombre de símbolo que comience con un carácter que no sea letra.

-o obj-file

Use obj-file como el nombre del archivo de salida. Si no se especifica, el nombre predeterminado es a.out. Si el nombre del archivo de salida es -, la salida se envía a la salida estándar.

-R

Crea un archivo de objeto que contiene solo las secciones de datos para enlazarlos en un módulo de solo código.

-r

Produce un archivo objeto que puede ser reubicado. Esto es lo mismo que la opción --relocatable.

-s

No incluir la tabla de símbolos en el archivo de objeto de salida.

-S

No eliminar los símbolos locales de la tabla de símbolos. Esto es lo mismo que la opción -L.

--strip-debug

No incluir la información de depuración en el archivo de objeto de salida. Esto es lo mismo que la opción -s.

-v

Mostrar el número de versión de as y las opciones que se pasaron a él.

-version

Mostrar la información de la versión de as y salir.

-W

Hacer que as imprima advertencias sobre construcciones dudosas.

-w

Suprimir la generación de mensajes de advertencia.

Esta opción controla cómo el ensamblador debe alinear saltos con prefijos de segmento o NOP. NUM debe ser una potencia de 2. Debe ser 0 o no menos de 16. Los saltos se alinearán dentro de un límite de NUM bytes. -malign-branch-boundary=0, que es el valor predeterminado, no alinea los saltos.

Esta opción especifica los tipos de saltos a alinear. Optimiza la codificación de instrucciones con un tamaño de instrucción menor. -O y -O1 codifican instrucciones de carga de registro de 64 bits con inmediatos de 64 bits como instrucciones de carga de registro de 32 bits con inmediatos de 31 o 32 bits, codifican instrucciones de borrado de registro de 64 bits con instrucciones de borrado de registro de 32 bits, codifican instrucciones de borrado de registro de vectores VEX/EVEX de 256/512 bits con instrucciones de borrado de registro de vectores VEX de 128 bits, codifican instrucciones de carga/almacenamiento de registro de vectores EVEX de 128/256 bits con instrucciones de carga/almacenamiento de registro VEX, y codifican instrucciones lógicas de enteros empaquetados VEX de 128/256 bits con instrucciones lógicas de enteros empaquetados VEX de 128/256 bits.

-O2 incluye la optimización de -O1 además de codificar instrucciones de borrado de registro de vectores EVEX de 256/512 bits con instrucciones de borrado de registro de vectores EVEX de 128 bits. -Os incluye la optimización de -O2 además de codificar pruebas de registro de 16, 32 y 64 bits con un inmediato como prueba de registro de 8 bits con un inmediato. -O0 desactiva esta optimización.
