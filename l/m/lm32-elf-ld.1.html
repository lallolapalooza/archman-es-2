LD(1) Herramientas de desarrollo GNU LD(1)

NOMBRE

ld - El enlazador GNU

SINOPSIS

ld [opciones] archivo-objeto ...

DESCRIPCIÓN

ld combina un número de archivos objeto y de archivo, reubica sus datos y resuelve las referencias de símbolos. Generalmente el último paso al compilar un programa es ejecutar ld.

ld acepta archivos de lenguaje de comandos del enlazador escritos en un superconjunto de la sintaxis del Lenguaje de Comandos del Editor de Enlace de AT&T, para proporcionar control explícito y total sobre el proceso de enlazado.

Esta página del manual no describe el lenguaje de comandos; consulte la entrada de ld en "info" para obtener detalles completos sobre el lenguaje de comandos y sobre otros aspectos del enlazador GNU.

Esta versión de ld utiliza las bibliotecas BFD de propósito general para operar sobre archivos objeto. Esto permite a ld leer, combinar y escribir archivos objeto en muchos formatos diferentes, por ejemplo, COFF o "a.out". Diferentes formatos pueden ser enlazados juntos para producir cualquier tipo de archivo objeto disponible.

Además de su flexibilidad, el enlazador GNU es más útil que otros enlazadores al proporcionar información de diagnóstico. Muchos enlazadores abandonan la ejecución inmediatamente al encontrar un error; siempre que sea posible, ld continúa la ejecución, permitiéndole identificar otros errores (o, en algunos casos, obtener un archivo de salida a pesar del error).

El enlazador GNU ld está diseñado para cubrir una amplia gama de situaciones y ser lo más compatible posible con otros enlazadores. Como resultado, usted tiene muchas opciones para controlar su comportamiento.

OPCIONES

El enlazador soporta una gran cantidad de opciones de línea de comandos, pero en la práctica, pocas se usan en un contexto particular. Por ejemplo, un uso frecuente de ld es enlazar archivos objeto estándar de Unix en un sistema Unix estándar y compatible. En tal sistema, para enlazar un archivo "hola.o":

ld -o <salida> /lib/crt0.o hola.o -lc

Esto le dice a ld que produzca un archivo llamado salida como resultado de enlazar el archivo "/lib/crt0.o" con "hola.o" y la biblioteca "libc.a", que provendrá de los directorios de búsqueda estándar. (Ver la discusión de la opción -l abajo.)

Algunas de las opciones de línea de comandos para ld pueden especificarse en cualquier punto de la línea de comandos. Sin embargo, las opciones que se refieren a archivos, como -l o -T, hacen que el archivo se lea en el punto en que la opción aparece en la línea de comandos, en relación con los archivos objeto y otras opciones de archivo. Repetir opciones no relacionadas con archivos con un argumento diferente o no tendrá ningún efecto adicional, o anulará las ocurrencias previas (las que están más a la izquierda en la línea de comandos) de esa opción. Las opciones que pueden ser especificadas significativamente más de una vez se anotan en las descripciones a continuación.

Los argumentos que no son opciones son archivos objeto o archivos que deben ser enlazados juntos. Pueden seguir, preceder o mezclarse con las opciones de línea de comandos, excepto que un argumento de archivo objeto no puede colocarse entre una opción y su argumento.

Generalmente el enlazador se invoca con al menos un archivo objeto, pero puede especificar otras formas de archivos de entrada binaria usando -l, -R, y el lenguaje de comandos de script. Si *no* se especifican archivos de entrada binaria, el enlazador no produce ninguna salida y muestra el mensaje No input files (No hay archivos de entrada).

Si el enlazador no puede reconocer el formato de un archivo objeto, asumirá que es un script del enlazador. Un script especificado de esta manera aumenta el script principal del enlazador utilizado para el enlace (ya sea el script principal predeterminado o el especificado usando -T). Esta característica permite al enlazador enlazar contra un archivo que parece ser un objeto o un archivo, pero que en realidad solo define algunos valores de símbolos, o usa "INPUT" o "GROUP" para cargar otros objetos. Especificar un script de esta manera simplemente aumenta el script principal del enlazador, con los comandos adicionales colocados después del script principal; use la opción -T para reemplazar completamente el script principal predeterminado, pero tenga en cuenta el efecto del comando "INSERT".

Para opciones cuyos nombres son una sola letra, los argumentos de opción deben seguir la letra de opción sin espacios intermedios, o ser dados como argumentos separados inmediatamente después de la opción que los requiere.

Para opciones cuyos nombres son múltiples letras, uno o dos guiones pueden preceder al nombre de la opción; por ejemplo, -trace-symbol y --trace-symbol son equivalentes. Nota: existe una excepción a esta regla. Las opciones de múltiples letras que comienzan con una 'o' minúscula solo pueden ir precedidas por dos guiones. Esto es para reducir la confusión con la opción -o. Así, por ejemplo, -omagic establece el nombre del archivo de salida a magic, mientras que --omagic establece la bandera NMAGIC en la salida.

Los argumentos para opciones de múltiples letras deben estar separados del nombre de la opción por un signo igual, o ser dados como argumentos separados inmediatamente después de la opción que los requiere. Por ejemplo, --trace-symbol foo y --trace-symbol=foo son equivalentes. Se aceptan abreviaturas únicas de los nombres de las opciones de múltiples letras.

Nota: si el enlazador se invoca indirectamente, a través de un controlador de compilador (por ejemplo, gcc) entonces todas las opciones de línea de comandos del enlazador deben ir precedidas por -Wl, (o lo que sea apropiado para el controlador de compilador en particular) de esta manera:

gcc -Wl,--start-group foo.o bar.o -Wl,--end-group

Esto es importante, ya que de lo contrario el programa controlador de compilador puede omitir silenciosamente las opciones del enlazador, resultando en un enlace incorrecto. La confusión también puede surgir al pasar opciones que requieren valores a través de un controlador, ya que el uso de un espacio entre la opción y el argumento actúa como un separador, y hace que el controlador pase solo la opción al enlazador y el argumento al compilador. En este caso, es más sencillo usar las formas unidas tanto de opciones de una sola letra como de múltiples letras, tales como:

gcc foo.o bar.o -Wl,-eENTRY -Wl,-Map=a.map

Aquí hay una tabla de los conmutadores genéricos de línea de comandos aceptados por el enlazador GNU:

@archivo
Lee las opciones de línea de comandos desde archivo. Las opciones leídas se insertan en lugar de la opción @archivo original. Si archivo no existe, o no se puede leer, entonces la opción se tratará literalmente y no se eliminará.

Las opciones en archivo están separadas por espacios en blanco. Un carácter de espacio en blanco puede incluirse en una opción al rodear toda la opción con comillas simples o dobles. Cualquier carácter (incluido una barra invertida) puede incluirse anteponiendo el carácter que se va a incluir con una barra invertida. El archivo puede contener a su vez opciones @archivo adicionales; tales opciones se procesarán recursivamente.

-a palabra_clave
Esta opción se soporta para compatibilidad con HP/UX. El argumento palabra_clave debe ser una de las cadenas archive, shared, o default. -aarchive es funcionalmente equivalente a -Bstatic, y las otras dos palabras clave son funcionalmente equivalentes a -Bdynamic. Esta opción se puede usar cualquier número de veces.
--audit AUDITLIB
Añade AUDITLIB a la entrada "DT_AUDIT" de la sección dinámica. AUDITLIB no se verifica su existencia, ni utilizará la DT_SONAME especificada en la biblioteca. Si se especifica varias veces, "DT_AUDIT" contendrá una lista separada por dos puntos de interfaces de auditoría a usar. Si el enlazador encuentra un objeto con una entrada de auditoría mientras busca bibliotecas compartidas, añadirá una entrada "DT_DEPAUDIT" correspondiente en el archivo de salida. Esta opción solo es significativa en plataformas ELF que soportan la interfaz rtld-audit.
-b formato-entrada
--format=formato-entrada
ld puede configurarse para soportar más de un tipo de archivo objeto. Si su ld está configurado de esta manera, puede usar la opción -b para especificar el formato binario para los archivos objeto que siguen a esta opción en la línea de comandos. Incluso cuando ld está configurado para soportar formatos de objeto alternativos, generalmente no necesita especificar esto, ya que ld debería estar configurado para esperar como formato predeterminado el más común para el sistema.
-i input-format
El formato de entrada input-format es una cadena de texto, el nombre de un formato particular soportado por las bibliotecas BFD. (Puedes listar los formatos binarios disponibles con objdump -i).

Puede que desees usar esta opción si estás enlazando archivos con un formato binario inusual. También puedes usar -b para cambiar explícitamente formatos (al enlazar archivos objeto de diferentes formatos), incluyendo -b input-format antes de cada grupo de archivos objeto en un formato particular.

El formato por defecto se toma de la variable de entorno "GNUTARGET".

También puedes definir el formato de entrada desde un script, usando el comando "TARGET";

-c MRI-commandfile
--mri-script=MRI-commandfile
Por compatibilidad con enlazadores producidos por MRI, ld acepta archivos de script escritos en un lenguaje de comandos alternativo y restringido, descrito en la sección "MRI Compatible Script Files" de la documentación de GNU ld. Introduce los archivos de script MRI con la opción -c; usa la opción -T para ejecutar scripts de enlazador escritos en el lenguaje de scripting de propósito general de ld. Si MRI-cmdfile no existe, ld lo busca en los directorios especificados por cualquier opción -L.
-d
-dc
-dp
Estas tres opciones son equivalentes; se soportan múltiples formas para compatibilidad con otros enlazadores. Asignan espacio a símbolos comunes incluso si se especifica un archivo de salida reubicable (con -r). El comando de script "FORCE_COMMON_ALLOCATION" tiene el mismo efecto.
--depaudit AUDITLIB
-P AUDITLIB
Añade AUDITLIB a la entrada "DT_DEPAUDIT" de la sección dinámica. No se comprueba la existencia de AUDITLIB, ni usará el DT_SONAME especificado en la biblioteca. Si se especifica varias veces, "DT_DEPAUDIT" contendrá una lista de interfaces de auditoría separadas por dos puntos a usar. Esta opción solo es significativa en plataformas ELF que soporten la interfaz rtld-audit. La opción -P se proporciona para compatibilidad con Solaris.
--enable-linker-version
Habilita la directiva de script de enlazador "LINKER_VERSION", descrita en Output Section Data. Si esta directiva se usa en un script de enlazador y esta opción ha sido habilitada, se insertará una cadena que contiene la versión del enlazador en el punto actual.

Nota: la ubicación de esta opción en la línea de comandos del enlazador es significativa. Solo afectará a los scripts de enlazador que vengan después de ella en la línea de comandos, o que estén incorporados en el enlazador.

--disable-linker-version
Deshabilita la directiva de script de enlazador "LINKER_VERSION", de modo que no inserte una cadena de versión. Este es el valor por defecto.
--enable-non-contiguous-regions
Esta opción evita generar un error si una sección de entrada no encaja en una sección de salida coincidente. El enlazador intenta asignar la sección de entrada a secciones de salida coincidentes posteriores, y solo genera un error si ninguna sección de salida es lo suficientemente grande. Esto es útil cuando hay varias regiones de memoria no contiguas disponibles y la sección de entrada no requiere una en particular. El orden en que se evalúan las secciones de entrada no cambia, por ejemplo: 
MEMORY {
  MEM1 (rwx) : ORIGIN = 0x1000, LENGTH = 0x14
  MEM2 (rwx) : ORIGIN = 0x1000, LENGTH = 0x40
  MEM3 (rwx) : ORIGIN = 0x2000, LENGTH = 0x40
}
SECTIONS {
  mem1 : { *(.data.*); } > MEM1
  mem2 : { *(.data.*); } > MEM2
  mem3 : { *(.data.*); } > MEM3
}

con secciones de entrada:
.data.1: tamaño 8
.data.2: tamaño 0x10
.data.3: tamaño 4

resulta en .data.1 asignada a mem1, y .data.2 y .data.3
asignadas a mem2, aunque .data.3 cabría en mem3.

Esta opción es incompatible con las sentencias INSERT porque cambia la forma en que las secciones de entrada se mapean a las secciones de salida.

--enable-non-contiguous-regions-warnings
Esta opción habilita advertencias cuando "--enable-non-contiguous-regions" permite coincidencias posiblemente inesperadas en el mapeo de secciones, lo que podría llevar a descartar silenciosamente una sección en lugar de fallar porque no encaja en ninguna región de salida.
-e entry
--entry=entry
Usa entry como el símbolo explícito para comenzar la ejecución de tu programa, en lugar del punto de entrada por defecto. Si no existe un símbolo llamado entry, el enlazador intentará analizar entry como un número, y lo usará como la dirección de entrada (el número se interpretará en base 10; puedes usar un prefijo 0x para base 16, o un prefijo 0 para base 8).
--exclude-libs lib,lib,...
Especifica una lista de bibliotecas de archivo de las cuales los símbolos no deben ser exportados automáticamente. Los nombres de las bibliotecas pueden estar delimitados por comas o dos puntos. Especificar "--exclude-libs ALL" excluye los símbolos de todas las bibliotecas de archivo de la exportación automática. Esta opción solo está disponible para el puerto PE de i386 del enlazador y para los puertos ELF. Para PE de i386, los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción. Para los puertos ELF, los símbolos afectados por esta opción se tratarán como ocultos.
--exclude-modules-for-implib module,module,...
Especifica una lista de archivos objeto o miembros de archivo, de los cuales los símbolos no deben ser exportados automáticamente, pero que deben copiarse enteros a la biblioteca de importación que se está generando durante el enlace. Los nombres de los módulos pueden estar delimitados por comas o dos puntos, y deben coincidir exactamente con los nombres de archivo utilizados por ld para abrir los archivos; para los miembros de archivo, es simplemente el nombre del miembro, pero para los archivos objeto el nombre listado debe incluir y coincidir precisamente con cualquier ruta utilizada para especificar el archivo de entrada en la línea de comandos del enlazador. Esta opción solo está disponible para el puerto PE de i386 del enlazador. Los símbolos listados explícitamente en un archivo .def todavía se exportan, independientemente de esta opción.
-E
--export-dynamic
--no-export-dynamic
Al crear un ejecutable enlazado dinámicamente, usar la opción -E o la opción --export-dynamic hace que el enlazador añada todos los símbolos a la tabla de símbolos dinámicos. La tabla de símbolos dinámicos es el conjunto de símbolos que son visibles desde objetos dinámicos en tiempo de ejecución.

Si no usas ninguna de estas opciones (o usas la opción --no-export-dynamic para restaurar el comportamiento por defecto), la tabla de símbolos dinámicos contendrá normalmente solo aquellos símbolos que son referenciados por algún objeto dinámico mencionado en el enlace.

Si usas "dlopen" para cargar un objeto dinámico que necesita hacer referencia a los símbolos definidos por el programa, en lugar de algún otro objeto dinámico, entonces probablemente necesitarás usar esta opción al enlazar el programa en sí.

También puedes usar la lista dinámica para controlar qué símbolos deben añadirse a la tabla de símbolos dinámicos si el formato de salida lo soporta. Consulta la descripción de --dynamic-list.

Ten en cuenta que esta opción es específica para los puertos ELF. Los destinos PE soportan una función similar para exportar todos los símbolos desde una DLL o EXE; consulta la descripción de --export-all-symbols a continuación.

--export-dynamic-symbol=glob
Al crear un ejecutable enlazado dinámicamente, los símbolos que coincidan con glob se añadirán a la tabla de símbolos dinámicos. Al crear una biblioteca compartida, las referencias a símbolos que coincidan con glob no se enlazarán a las definiciones dentro de la biblioteca compartida. Esta opción no hace nada al crear una biblioteca compartida y no se especifican -Bsymbolic o --dynamic-list. Esta opción solo es significativa en plataformas ELF que soportan bibliotecas compartidas.
--export-dynamic-symbol-list=file
Especifica un --export-dynamic-symbol para cada patrón en el archivo. El formato del archivo es el mismo que el nodo de versión sin ámbito ni nombre de nodo. Consulta VERSION para más información.
-EB
Enlaza objetos big-endian. Esto afecta al formato de salida por defecto.
-EL
Enlaza objetos little-endian. Esto afecta al formato de salida por defecto.
-f name
--auxiliary=name
Al crear un objeto compartido ELF, establece el campo interno DT_AUXILIARY al nombre especificado. Esto indica al enlazador dinámico que la tabla de símbolos del objeto compartido debe usarse como un filtro auxiliar en la tabla de símbolos del objeto compartido name.

Si más tarde enlazas un programa contra este objeto filtro, entonces, al ejecutar el programa, el enlazador dinámico verá el campo DT_AUXILIARY. Si el enlazador dinámico resuelve algún símbolo del objeto filtro, primero comprobará si existe una definición en el objeto compartido name. Si existe una, se usará en lugar de la definición en el objeto filtro. El objeto compartido name no necesita existir. Por lo tanto, el objeto compartido name puede usarse para proporcionar una implementación alternativa de ciertas funciones, quizás para depuración o para rendimiento específico de la máquina.

Esta opción puede especificarse varias veces. Las entradas DT_AUXILIARY se crearán en el orden en que aparecen en la línea de comandos.

-F name
--filter=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_FILTER con el nombre especificado. Esto indica al enlazador dinámico que la tabla de símbolos del objeto compartido que se está creando debe usarse como filtro para la tabla de símbolos del objeto compartido nombre.

Si posteriormente enlazas un programa contra este objeto filtro, entonces, al ejecutar el programa, el enlazador dinámico verá el campo DT_FILTER. El enlazador dinámico resolverá los símbolos según la tabla de símbolos del objeto filtro como de costumbre, pero enlazará realmente con las definiciones encontradas en el objeto compartido nombre. Por lo tanto, el objeto filtro puede usarse para seleccionar un subconjunto de los símbolos proporcionados por el objeto nombre.

Algunos enlazadores antiguos utilizaban la opción -F en toda la cadena de herramientas de compilación para especificar el formato del archivo objeto tanto para los archivos objeto de entrada como de salida. El enlazador GNU utiliza otros mecanismos para este propósito: las opciones -b, --format, --oformat, el comando "TARGET" en los scripts de enlazador y la variable de entorno "GNUTARGET". El enlazador GNU ignorará la opción -F cuando no esté creando un objeto compartido ELF.

-fini=nombre
Al crear un ejecutable o un objeto compartido ELF, llama a NOMBRE cuando el ejecutable o el objeto compartido se descarguen, estableciendo DT_FINI a la dirección de la función. Por defecto, el enlazador usa "_fini" como la función a llamar.
-g
Ignorado. Proporcionado para compatibilidad con otras herramientas.
-G valor
--gpsize=valor
Establece el tamaño máximo de los objetos a optimizar usando el registro GP a tamaño. Esto solo es significativo para formatos de archivo objeto como MIPS ELF que admiten la colocación de objetos grandes y pequeños en secciones diferentes. Se ignora para otros formatos de archivo objeto.
-h nombre
-soname=nombre
Al crear un objeto compartido ELF, establece el campo interno DT_SONAME con el nombre especificado. Cuando un ejecutable se enlaza con un objeto compartido que tiene un campo DT_SONAME, al ejecutar el ejecutable, el enlazador dinámico intentará cargar el objeto compartido especificado por el campo DT_SONAME en lugar de usar el nombre de archivo proporcionado al enlazador.
-i
Realiza un enlace incremental (igual que la opción -r).
-init=nombre
Al crear un ejecutable o un objeto compartido ELF, llama a NOMBRE cuando el ejecutable o el objeto compartido se carguen, estableciendo DT_INIT a la dirección de la función. Por defecto, el enlazador usa "_init" como la función a llamar.
-l especnombredearchivo
--library=especnombredearchivo
Añade el archivo de biblioteca o objeto especificado por especnombredearchivo a la lista de archivos a enlazar. Esta opción se puede usar un número ilimitado de veces. Si especnombredearchivo tiene la forma :nombrearchivo, ld buscará en la ruta de bibliotecas un archivo llamado nombrearchivo, de lo contrario buscará en la ruta de bibliotecas un archivo llamado libespecnombredearchivo.a.

En sistemas que soportan bibliotecas compartidas, ld también puede buscar archivos distintos de libespecnombredearchivo.a. Específicamente, en sistemas ELF y SunOS, ld buscará en un directorio una biblioteca llamada libespecnombredearchivo.so antes de buscar una llamada libespecnombredearchivo.a. (Por convención, una extensión ".so" indica una biblioteca compartida). Tenga en cuenta que este comportamiento no se aplica a :nombrearchivo, que siempre especifica un archivo llamado nombrearchivo.

El enlazador buscará en un archivo solo una vez, en la ubicación en la que se especifica en la línea de comandos. Si el archivo define un símbolo que no estaba definido en algún objeto que apareció antes que el archivo en la línea de comandos, el enlazador incluirá los archivos apropiados del archivo. Sin embargo, un símbolo no definido en un objeto que aparece más tarde en la línea de comandos no hará que el enlazador busque el archivo nuevamente.

Consulte la opción -( para saber cómo forzar al enlazador a buscar archivos varias veces.

Puede listar el mismo archivo varias veces en la línea de comandos.

Este tipo de búsqueda de archivos es estándar para los enlazadores Unix. Sin embargo, si está utilizando ld en AIX, tenga en cuenta que es diferente del comportamiento del enlazador AIX.

-L dirbusqueda
--library-path=dirbusqueda
Añade la ruta dirbusqueda a la lista de rutas que ld buscará para bibliotecas de archivos y scripts de control de ld. Puede usar esta opción un número ilimitado de veces. Los directorios se buscan en el orden en que se especifican en la línea de comandos. Los directorios especificados en la línea de comandos se buscan antes que los directorios por defecto. Todas las opciones -L se aplican a todas las opciones -l, independientemente del orden en que aparezcan las opciones. Las opciones -L no afectan a cómo ld busca un script de enlazador a menos que se especifique la opción -T.

Si dirbusqueda comienza con "=" o $SYSROOT, entonces este prefijo será reemplazado por el prefijo sysroot, controlado por la opción --sysroot, o especificado cuando se configuró el enlazador.

El conjunto por defecto de rutas buscadas (sin ser especificadas con -L) depende de qué modo de emulación esté usando ld, y en algunos casos también de cómo fue configurado.

Las rutas también se pueden especificar en un script de enlace con el comando "SEARCH_DIR". Los directorios especificados de esta manera se buscan en el punto en que aparece el script de enlace en la línea de comandos.

-m emulacion
Emula el enlazador de emulacion. Puede listar las emulaciones disponibles con las opciones --verbose o -V.

Si no se usa la opción -m, la emulación se toma de la variable de entorno "LDEMULATION", si está definida.

De lo contrario, la emulación por defecto depende de cómo se configuró el enlazador.

--remap-inputs=patron=nombrearchivo
--remap-inputs-file=archivo
Estas opciones permiten cambiar los nombres de los archivos de entrada antes de que el enlazador intente abrirlos. La opción --remap-inputs=foo.o=bar.o hará que cualquier intento de cargar un archivo llamado foo.o intente cargar en su lugar un archivo llamado bar.o. Se permiten patrones comodín en el primer nombre de archivo, por lo que --remap-inputs=foo*.o=bar.o renombrará cualquier archivo de entrada que coincida con foo*.o a bar.o.

Una forma alternativa de la opción --remap-inputs-file=nombrearchivo permite leer las reasignaciones de un archivo. Cada línea en el archivo puede contener una única reasignación. Las líneas en blanco se ignoran. Cualquier cosa desde un carácter de almohadilla (#) hasta el final de una línea se considera un comentario y también se ignora. El patrón de reasignación se puede separar del nombre de archivo por espacios en blanco o un carácter de igual (=).

Las opciones se pueden especificar varias veces. Sus contenidos se acumulan. Las reasignaciones se procesarán en el orden en que ocurran en la línea de comandos, y si provienen de un archivo, en el orden en que ocurran en el archivo. Si se produce una coincidencia, no se realizará ninguna comprobación adicional para ese nombre de archivo.

Si el nombre de archivo de reemplazo es /dev/null o simplemente NUL, la reasignación hará que el archivo de entrada se ignore. Esta puede ser una forma conveniente de experimentar eliminando archivos de entrada de un entorno de compilación complicado.

Tenga en cuenta que esta opción depende de la posición y solo afecta a los nombres de archivo que aparecen después de ella en la línea de comandos. Por lo tanto:

ld foo.o --remap-inputs=foo.o=bar.o

No tendrá ningún efecto, mientras que:

ld --remap-inputs=foo.o=bar.o foo.o

Renombrará el archivo de entrada foo.o a bar.o.

Nota: estas opciones también afectan a los archivos referenciados por las declaraciones INPUT en los scripts del enlazador. Pero dado que los scripts del enlazador se procesan después de que se lee toda la línea de comandos, la posición de las opciones de reasignación en la línea de comandos no es significativa.

Si la opción verbose está habilitada, se informarán las reasignaciones que coincidan, aunque de nuevo la opción verbose debe estar habilitada en la línea de comandos antes de que aparezcan los nombres de archivo reasignados.

Si las opciones -Map o --print-map están habilitadas, la lista de reasignaciones se incluirá en la salida del mapa.

-M
--print-map
Imprime un mapa de enlace en la salida estándar. Un mapa de enlace proporciona información sobre el enlace, incluyendo lo siguiente:
  • Dónde se mapean los archivos objeto en memoria.
  • Cómo se asignan los símbolos comunes.
  • Todos los miembros del archivo incluidos en el enlace, con una mención del símbolo que causó que se incluyera el miembro del archivo.
  • Los valores asignados a los símbolos.

    Nota: es posible que los símbolos cuyos valores se calculan mediante una expresión que implica una referencia a un valor anterior del mismo símbolo no muestren el resultado correcto en el mapa de enlace. Esto se debe a que el enlazador descarta los resultados intermedios y solo conserva el valor final de una expresión. En tales circunstancias, el enlazador mostrará el valor final entre corchetes. Por lo tanto, por ejemplo, un script de enlazador que contenga:

    foo = 1
foo = foo * 4
foo = foo + 8

    producirá la siguiente salida en el mapa de enlace si se utiliza la opción -M:

    0x00000001                foo = 0x1
[0x0000000c]                foo = (foo * 0x4)
[0x0000000c]                foo = (foo + 0x8)

    Consulte Expressions para más información.

Some linker options affect the information produced in the link map. These options are described below.

  • How GNU properties are merged.

    When the linker merges input .note.gnu.property sections into one output .note.gnu.property section, some properties are removed or updated. These actions are reported in the link map. For example:

    Removed property 0xc0000002 to merge foo.o (0x1) and bar.o (not found)

    This indicates that property 0xc0000002 is removed from output when merging properties in foo.o, whose property 0xc0000002 value is 0x1, and bar.o, which doesn't have property 0xc0000002.

    Updated property 0xc0010001 (0x1) to merge foo.o (0x1) and bar.o (0x1)

    This indicates that property 0xc0010001 value is updated to 0x1 in output when merging properties in foo.o, whose 0xc0010001 property value is 0x1, and bar.o, whose 0xc0010001 property value is 0x1.

  • On some ELF targets, a list of fixups inserted by --relax 
    foo.o: Adjusting branch at 0x00000008 towards "far" in section .text

    This indicates that the branch at 0x00000008 in foo.o, targeting the symbol "far" in section .text, has been replaced by a trampoline.

Busca solo en los directorios de bibliotecas especificados explícitamente en la línea de comandos. Se ignoran los directorios de bibliotecas especificados en los scripts del enlazador (incluidos los scripts del enlazador especificados en la línea de comandos).
--oformat=formato-salida
ld puede configurarse para admitir más de un tipo de archivo objeto. Si tu ld está configurado de esta manera, puedes usar la opción --oformat para especificar el formato binario para el archivo objeto de salida. Incluso cuando ld está configurado para admitir formatos de objeto alternativos, normalmente no necesitas especificar esto, ya que ld debería estar configurado para producir como formato de salida predeterminado el formato más común en cada máquina. formato-salida es una cadena de texto, el nombre de un formato particular compatible con las bibliotecas BFD. (Puedes listar los formatos binarios disponibles con objdump -i.) El comando del script "OUTPUT_FORMAT" también puede especificar el formato de salida, pero esta opción lo anula.
--out-implib archivo
Crea una biblioteca de importación en archivo correspondiente al ejecutable que está generando el enlazador (por ejemplo, un DLL o un programa ELF). Esta biblioteca de importación (que debería llamarse "*.dll.a" o "*.a" para DLLs) puede usarse para enlazar clientes contra el ejecutable generado; este comportamiento hace posible omitir un paso de creación de biblioteca de importación separado (por ejemplo, "dlltool" para DLLs). Esta opción solo está disponible para los puertos i386 PE y ELF del enlazador.
-pie
--pic-executable
Crea un ejecutable independiente de la posición. Esto actualmente solo se admite en plataformas ELF. Los ejecutables independientes de la posición son similares a las bibliotecas compartidas en que el enlazador dinámico los reubica en la dirección virtual que el sistema operativo elija para ellos (que puede variar entre invocaciones). Al igual que los ejecutables enlazados dinámicamente normales, pueden ejecutarse y los símbolos definidos en el ejecutable no pueden ser anulados por bibliotecas compartidas.
-no-pie
Crea un ejecutable dependiente de la posición. Este es el valor predeterminado.
-qmagic
Esta opción se ignora por compatibilidad con Linux.
-Qy
Esta opción se ignora por compatibilidad con SVR4.
--relax
--no-relax
Una opción con efectos dependientes de la máquina. Esta opción solo se admite en algunos destinos.

En algunas plataformas, la opción --relax realiza optimizaciones globales específicas del destino que son posibles cuando el enlazador resuelve el direccionamiento en el programa, como relajar modos de direccionamiento, sintetizar nuevas instrucciones, seleccionar versiones más cortas de instrucciones actuales y combinar valores constantes.

En algunas plataformas, estas optimizaciones globales en tiempo de enlace pueden hacer que la depuración simbólica del ejecutable resultante sea imposible. Esto se sabe que es el caso de la familia de procesadores Matsushita MN10200 y MN10300.

En plataformas donde la característica es compatible, la opción --no-relax la deshabilitará.

En plataformas donde la característica no es compatible, tanto --relax como --no-relax se aceptan, pero se ignoran.

--retain-symbols-file=nombre-archivo
Conserva solo los símbolos listados en el archivo nombre-archivo, descartando todos los demás. nombre-archivo es simplemente un archivo plano, con un nombre de símbolo por línea. Esta opción es especialmente útil en entornos (como VxWorks) donde se acumula gradualmente una gran tabla de símbolos global, para conservar memoria en tiempo de ejecución.

--retain-symbols-file no descarta símbolos indefinidos ni símbolos necesarios para reubicaciones.

Solo puedes especificar --retain-symbols-file una vez en la línea de comandos. Anula -s y -S.

-rpath=dir
Agrega un directorio a la ruta de búsqueda de bibliotecas en tiempo de ejecución. Esto se utiliza al enlazar un ejecutable ELF con objetos compartidos. Todos los argumentos de -rpath se concatenan y se pasan al enlazador en tiempo de ejecución, que los utiliza para localizar objetos compartidos en tiempo de ejecución.

La opción -rpath también se usa al localizar objetos compartidos que son necesarios para objetos compartidos incluidos explícitamente en el enlace; consulta la descripción de la opción -rpath-link. La búsqueda de -rpath de esta manera solo es compatible con enlazadores nativos y enlazadores cruzados que se han configurado con la opción --with-sysroot.

Si no se usa -rpath al enlazar un ejecutable ELF, se utilizará el contenido de la variable de entorno "LD_RUN_PATH" si está definido.

La opción -rpath también se puede usar en SunOS. Por defecto, en SunOS, el enlazador formará una ruta de búsqueda en tiempo de ejecución a partir de todas las opciones -L que se le dan. Si se utiliza una opción -rpath, la ruta de búsqueda en tiempo de ejecución se formará exclusivamente utilizando las opciones -rpath, ignorando las opciones -L. Esto puede ser útil cuando se utiliza gcc, que agrega muchas opciones -L que pueden estar en sistemas de archivos montados en NFS.

Para compatibilidad con otros enlazadores ELF, si la opción -R va seguida de un nombre de directorio, en lugar de un nombre de archivo, se trata como la opción -rpath.

-rpath-link=dir
Al usar ELF o SunOS, una biblioteca compartida puede requerir otra. Esto ocurre cuando un enlace "ld -shared" incluye una biblioteca compartida como uno de los archivos de entrada.

Cuando el enlazador encuentra tal dependencia al realizar un enlace no compartido ni relocable, intentará automáticamente localizar la biblioteca compartida requerida e incluirla en el enlace, si no está incluida explícitamente. En tal caso, la opción -rpath-link especifica el primer conjunto de directorios a buscar. La opción -rpath-link puede especificar una secuencia de nombres de directorio, ya sea especificando una lista de nombres separados por dos puntos o apareciendo varias veces.

Los tokens $ORIGIN y $LIB pueden aparecer en estos directorios de búsqueda. Se reemplazarán por la ruta completa al directorio que contiene el programa o el objeto compartido en el caso de $ORIGIN y lib - para binarios de 32 bits - o lib64 - para binarios de 64 bits - en el caso de $LIB.

La forma alternativa de estos tokens - ${ORIGIN} y ${LIB} - también se puede usar. El token $PLATFORM no es compatible.

Esta opción debe usarse con precaución, ya que anula la ruta de búsqueda que puede haber sido compilada de forma fija en una biblioteca compartida. En tal caso, es posible utilizar involuntariamente una ruta de búsqueda diferente a la que el enlazador en tiempo de ejecución haría.

El enlazador utiliza las siguientes rutas de búsqueda para localizar las bibliotecas compartidas requeridas:

1.
Cualquier directorio especificado por las opciones -rpath-link.
2.
Cualquier directorio especificado por las opciones -rpath. La diferencia entre -rpath y -rpath-link es que los directorios especificados por las opciones -rpath se incluyen en el ejecutable y se usan en tiempo de ejecución, mientras que la opción -rpath-link solo es efectiva en tiempo de enlace. La búsqueda de -rpath de esta manera solo es compatible con enlazadores nativos y enlazadores cruzados que se han configurado con la opción --with-sysroot.
3.
En un sistema ELF, para enlazadores nativos, si no se utilizaron las opciones -rpath y -rpath-link, busca el contenido de la variable de entorno "LD_RUN_PATH".
4.
En SunOS, si no se utilizó la opción -rpath, busca cualquier directorio especificado usando las opciones -L.
5.
Para un enlazador nativo, busca el contenido de la variable de entorno "LD_LIBRARY_PATH".
6.
Para un enlazador ELF nativo, se buscan en los directorios de "DT_RUNPATH" o "DT_RPATH" de una biblioteca compartida las bibliotecas compartidas que necesita. Las entradas de "DT_RPATH" se ignoran si existen entradas de "DT_RUNPATH".
7.
Para un enlazador de un sistema Linux, si el archivo /etc/ld.so.conf existe, la lista de directorios encontrada en ese archivo. Nota: la ruta a este archivo se antepone al valor de "sysroot", si está definido, y luego a cualquier cadena de "prefix" si el enlazador se configuró con la opción
>opción --prefix=<ruta>.
8.
Para un enlazador nativo en un sistema FreeBSD, cualquier directorio especificado por la macro "_PATH_ELF_HINTS" definida en el archivo de cabecera elf-hints.h.
9.
Cualquier directorio especificado por un comando "SEARCH_DIR" en un script del enlazador dado en la línea de comandos, incluyendo scripts especificados por -T (pero no por -dT).
10.
Los directorios por defecto, normalmente /lib y /usr/lib.
11.
Cualquier directorio especificado por un plugin LDPT_SET_EXTRA_LIBRARY_PATH.
12.
Cualquier directorio especificado por un comando "SEARCH_DIR" en un script del enlazador por defecto.

Sin embargo, ten en cuenta que en los sistemas basados en Linux hay una advertencia adicional: si la opción --as-needed está activa *y* se encuentra una biblioteca compartida que normalmente satisfaría la búsqueda *y* esta biblioteca no tiene la etiqueta DT_NEEDED para libc.so *y* hay una biblioteca compartida más adelante en el conjunto de directorios de búsqueda que también satisface la búsqueda *y* esta segunda biblioteca compartida tiene una etiqueta DT_NEEDED para libc.so, *entonces* se seleccionará la segunda biblioteca en lugar de la primera.

Si la biblioteca compartida requerida no se encuentra, el enlazador emitirá una advertencia y continuará con el enlace.

-shared
-Bshareable
Crea una biblioteca compartida. Esto solo se admite actualmente en plataformas ELF, XCOFF y SunOS. En SunOS, el enlazador creará automáticamente una biblioteca compartida si la opción -e no se usa y hay símbolos indefinidos en el enlace.
--sort-common
--sort-common=ascending
--sort-common=descending
Esta opción indica a ld que ordene los símbolos comunes por alineación en orden ascendente o descendente al colocarlos en las secciones de salida apropiadas. Las alineaciones de símbolos consideradas son de dieciséis bytes o más, ocho bytes, cuatro bytes, dos bytes y un byte. Esto es para evitar huecos entre símbolos debido a restricciones de alineación. Si no se especifica ningún orden de ordenación, se asume el orden descendente.
--sort-section=name
Esta opción aplicará "SORT_BY_NAME" a todos los patrones de sección comodín en el script del enlazador.
--sort-section=alignment
Esta opción aplicará "SORT_BY_ALIGNMENT" a todos los patrones de sección comodín en el script del enlazador.
--spare-dynamic-tags=contador
Esta opción especifica el número de espacios vacíos que se dejarán en la sección .dynamic de los objetos compartidos ELF. Los espacios vacíos pueden ser necesarios para herramientas de postprocesamiento, como el preenlazador. El valor predeterminado es 5.
--split-by-file[=tamaño]
Similar a --split-by-reloc pero crea una nueva sección de salida para cada archivo de entrada cuando se alcanza tamaño. tamaño tiene un valor predeterminado de 1 si no se proporciona.
--split-by-reloc[=contador]
Intenta crear secciones adicionales en el archivo de salida de modo que ninguna sección de salida individual en el archivo contenga más de contador reubicaciones. Esto es útil al generar archivos reubicables enormes para descargar en ciertos kernels en tiempo real con el formato de objeto COFF; dado que COFF no puede representar más de 65535 reubicaciones en una sola sección. Tenga en cuenta que esto fallará con formatos de archivo objeto que no admiten secciones arbitrarias. El enlazador no dividirá secciones de entrada individuales para su redistribución, por lo que si una sola sección de entrada contiene más de contador reubicaciones, una sección de salida contendrá esa cantidad de reubicaciones. contador tiene un valor predeterminado de 32768.
--stats
Calcula y muestra estadísticas sobre la operación del enlazador, como el tiempo de ejecución y el uso de memoria.
--sysroot=directorio
Utiliza directorio como la ubicación del sysroot, anulando el valor predeterminado en tiempo de configuración. Esta opción solo es compatible con enlazadores que se configuraron usando --with-sysroot.
--task-link
Esto es utilizado por objetivos basados en COFF/PE para crear un archivo objeto enlazado a tareas donde todos los símbolos globales se han convertido en estáticos.
--traditional-format
Para algunos objetivos, la salida de ld difiere en algunos aspectos de la salida de algunos enlazadores existentes. Este interruptor solicita a ld que utilice el formato tradicional en su lugar.

Por ejemplo, en SunOS, ld combina entradas duplicadas en la tabla de cadenas de símbolos. Esto puede reducir el tamaño de un archivo de salida con información de depuración completa en más del 30 por ciento. Desafortunadamente, el programa "dbx" de SunOS no puede leer el programa resultante ("gdb" no tiene problemas). El interruptor --traditional-format indica a ld que no combine entradas duplicadas.

--section-start=nombre_seccion=org
Ubica una sección en el archivo de salida en la dirección absoluta dada por org. Puede usar esta opción tantas veces como sea necesario para ubicar múltiples secciones en la línea de comandos. org debe ser un solo entero hexadecimal; para compatibilidad con otros enlazadores, puede omitir el prefijo 0x usualmente asociado con valores hexadecimales. Nota: no debe haber espacios en blanco entre nombre_seccion, el signo igual ("=") y org.
-Tbss=org
-Tdata=org
-Ttext=org
Igual que --section-start, con ".bss", ".data" o ".text" como nombre_seccion.

-Trodata-segment=org
Al crear un ejecutable ELF u objeto compartido para un objetivo donde los datos de solo lectura se encuentran en su propio segmento separado del texto ejecutable, establecerá la dirección del primer byte del segmento de datos de solo lectura.

Determina cómo manejar los símbolos no resueltos. Hay cuatro valores posibles para método:
ignore-all

report-all

ignore-in-object-files
Informar sobre los símbolos no resueltos que se encuentran en bibliotecas compartidas, pero ignorarlos si provienen de archivos objeto regulares.

Informar sobre los símbolos no resueltos que provienen de archivos objeto regulares, pero ignorarlos si provienen de bibliotecas compartidas. Esto puede ser útil al crear un binario dinámico y se sabe que todas las bibliotecas compartidas a las que debe hacer referencia se incluyen en la línea de comandos del enlazador.

--dll-verbose
--verbose[=NÚMERO]
Muestra el número de versión de ld y enumera las emulaciones de enlazador compatibles. Muestra qué archivos de entrada se pueden abrir y cuáles no. Muestra el script del enlazador que está utilizando el enlazador. Si el argumento opcional NÚMERO es > 1, también se mostrará el estado de los símbolos del plugin.
--version-script=archivo-script-versiones
Especifica el nombre de un script de versiones al enlazador. Esto se usa típicamente al crear bibliotecas compartidas para especificar información adicional sobre la jerarquía de versiones de la biblioteca que se está creando. Esta opción solo es totalmente compatible con plataformas ELF que admiten bibliotecas compartidas; consulte VERSION. Es parcialmente compatible con plataformas PE, que pueden usar scripts de versiones para filtrar la visibilidad de los símbolos en el modo de exportación automática: cualquier símbolo marcado como local en el script de versiones no se exportará.
--warn-common
Advierte cuando un símbolo común se combina con otro símbolo común o con una definición de símbolo. Los enlazadores de Unix permiten esta práctica algo descuidada, pero los enlazadores en algunos otros sistemas operativos no. Esta opción le permite encontrar posibles problemas al combinar símbolos globales. Desafortunadamente, algunas bibliotecas C usan esta práctica, por lo que puede recibir algunas advertencias sobre símbolos en las bibliotecas, así como en sus programas.

Hay tres tipos de símbolos globales, ilustrados aquí con ejemplos de C:

int i = 1;
Una definición, que va en la sección de datos inicializados del archivo de salida.
extern int i;
Una referencia indefinida, que dno asigna espacio. Debe haber una definición o un símbolo común para la variable en algún lugar.
int i;
Un símbolo común. Si solo hay uno o más símbolos comunes para una variable, va al área de datos no inicializados del archivo de salida. El enlazador fusiona múltiples símbolos comunes para la misma variable en un solo símbolo. Si son de diferentes tamaños, elige el tamaño más grande. El enlazador convierte un símbolo común en una declaración si hay una definición de la misma variable.

La opción --warn-common puede producir cinco tipos de advertencias. Cada advertencia consiste en un par de líneas: la primera describe el símbolo recién encontrado y la segunda describe el símbolo anterior encontrado con el mismo nombre. Uno o ambos de los dos símbolos será un símbolo común.

1.
Convertir un símbolo común en una referencia, porque ya existe una definición para el símbolo. 
<archivo>(<sección>): advertencia: común de `<símbolo>'
   sobrescrito por definición
<archivo>(<sección>): advertencia: definido aquí
2.
Convertir un símbolo común en una referencia, porque se encuentra una definición posterior para el símbolo. Esto es lo mismo que el caso anterior, excepto que los símbolos se encuentran en un orden diferente. 
<archivo>(<sección>): advertencia: definición de `<símbolo>'
   sobrescribiendo común
<archivo>(<sección>): advertencia: el común está aquí
3.
Fusionar un símbolo común con un símbolo común anterior del mismo tamaño. 
<archivo>(<sección>): advertencia: múltiples comunes
   de `<símbolo>'
<archivo>(<sección>): advertencia: el común anterior está aquí
4.
Fusionar un símbolo común con un símbolo común anterior más grande. 
<archivo>(<sección>): advertencia: común de `<símbolo>'
   sobrescrito por común más grande
<archivo>(<sección>): advertencia: el común más grande está aquí
5.
Fusionar un símbolo común con un símbolo común anterior más pequeño. Esto es lo mismo que el caso anterior, excepto que los símbolos se encuentran en un orden diferente.

   sobrescribiendo común más pequeño

Advertir si se utilizan constructores globales. Esto solo es útil para algunos formatos de archivos objeto. Para formatos como COFF o ELF, el enlazador no puede detectar el uso de constructores globales.
--warn-execstack
--warn-execstack-objects
--no-warn-execstack
En plataformas ELF, el enlazador puede generar mensajes de advertencia si se le solicita crear un archivo de salida que contenga una pila ejecutable. Hay tres estados posibles:
1.
No generar ninguna advertencia.
2.
Generar siempre advertencias, incluso si la pila ejecutable se solicita a través de la opción de línea de comandos -z execstack.
3.
Solo generar una advertencia si un archivo objeto solicita una pila ejecutable, pero no si se utiliza la opción -z execstack.

El estado predeterminado depende de cómo se configuró el enlazador cuando se compiló. La opción --no-warn-execstack pone siempre el enlazador en el estado de no advertencias. La opción --warn-execstack pone el enlazador en el estado de advertir siempre. La opción --warn-execstack-objects pone el enlazador en el estado de advertir solo para archivos objeto.

Nota: Los archivos de entrada en formato ELF pueden especificar que necesitan una pila ejecutable teniendo una sección .note.GNU-stack con el bit ejecutable establecido en sus indicadores de sección. Pueden especificar que no necesitan una pila ejecutable teniendo la misma sección, pero sin el bit ejecutable establecido. Si un archivo de entrada no tiene una sección .note.GNU-stack, el comportamiento predeterminado es específico del destino. Para algunos destinos, la ausencia de dicha sección implica que se *requiere* una pila ejecutable. Esto a menudo es un problema para archivos ensambladores creados manualmente.

--error-execstack
--no-error-execstack
Si el enlazador va a generar un mensaje de advertencia sobre una pila ejecutable, la opción --error-execstack lo cambiará en lugar de eso de advertencia a error. Nota: esta opción no cambia el estado de generación de advertencias de execstack del enlazador. Use --warn-execstack o --warn-execstack-objects para establecer un estado de advertencia específico.

La opción --no-error-execstack restaurará el comportamiento predeterminado de generar mensajes de advertencia.

--warn-multiple-gp
Advertir si se requieren múltiples valores de puntero global en el archivo de salida. Esto solo es significativo para ciertos procesadores, como Alpha. Específicamente, algunos procesadores colocan constantes de gran valor en una sección especial. Un registro especial (el puntero global) apunta al medio de esta sección, de modo que las constantes puedan cargarse eficientemente a través de un modo de direccionamiento relativo al registro base. Dado que el desplazamiento en el modo relativo al registro base es fijo y relativamente pequeño (por ejemplo, 16 bits), esto limita el tamaño máximo del conjunto de constantes. Por lo tanto, en programas grandes, a menudo es necesario utilizar múltiples valores de puntero global para poder direccionar todas las constantes posibles. Esta opción causa una advertencia cuando ocurre este caso.
--warn-once
Advertir solo una vez por cada símbolo no definido, en lugar de una vez por módulo que se refiera a él.
--warn-rwx-segments
--no-warn-rwx-segments
Advertir si el enlazador crea un segmento cargable y de tamaño distinto de cero que tenga los tres indicadores de permisos de lectura, escritura y ejecución establecidos. Dicho segmento representa una posible vulnerabilidad de seguridad. Además, se generarán advertencias si se crea un segmento de almacenamiento local de hilos con el indicador de permiso de ejecución establecido, independientemente de si tiene o no los indicadores de lectura y/o escritura establecidos.

Estas advertencias están habilitadas por defecto. Pueden deshabilitarse mediante la opción --no-warn-rwx-segments y volver a habilitarse mediante la opción --warn-rwx-segments.

--no-error-rwx-segments

La opción --no-error-rwx-segments restaurará el comportamiento predeterminado de generar solo un mensaje de advertencia.

Nota: La opción --error-rwx-segments no habilita por sí misma las advertencias sobre estos segmentos. Estas advertencias se habilitan por defecto, si el enlazador fue configurado así, o mediante la opción de línea de comandos --warn-rwx-segments.

--warn-section-align
Advertir si la dirección de una sección de salida se cambia debido a la alineación. Típicamente, la alineación será establecida por una sección de entrada. La dirección solo se cambiará si no se especifica explícitamente; es decir, si el comando "SECTIONS" no especifica una dirección de inicio para la sección.
--warn-textrel
Advertir si el enlazador agrega DT_TEXTREL a un ejecutable o biblioteca compartida independiente de la posición.
--warn-alternate-em
Advertir si un objeto tiene código de máquina ELF alternativo.
--warn-unresolved-symbols
Si el enlazador va a informar un símbolo no resuelto (ver la opción --unresolved-symbols), normalmente generará un error. Esta opción hace que genere una advertencia en su lugar.
--error-unresolved-symbols
Esto restaura el comportamiento predeterminado del enlazador de generar errores cuando informa símbolos no resueltos.
--whole-archive
Para cada archivo de biblioteca mencionado en la línea de comandos después de la opción --whole-archive, incluya cada archivo objeto en el archivo de biblioteca en el enlace, en lugar de buscar en el archivo de biblioteca los archivos objeto requeridos. Esto se usa normalmente para convertir un archivo de biblioteca en una biblioteca compartida, forzando la inclusión de cada objeto en la biblioteca compartida resultante. Esta opción puede usarse más de una vez.

Dos notas al usar esta opción desde gcc: Primero, gcc no conoce esta opción, por lo que debe usar -Wl,-whole-archive. Segundo, no olvide usar -Wl,-no-whole-archive después de su lista de archivos de biblioteca, porque gcc agregará su propia lista de archivos de biblioteca a su enlace y es posible que no desee que esta bandera afecte a esos también.

--wrap=símbolo
Utilizar una función envoltorio para símbolo. Cualquier referencia no definida a símbolo se resolverá a "__wrap_símbolo". Cualquier referencia no definida a "__real_símbolo" se resolverá a símbolo.

Esto se puede utilizar para proporcionar un envoltorio para una función del sistema. La función envoltorio debe llamarse "__wrap_símbolo". Si desea llamar a la función del sistema, debe llamar a "__real_símbolo".

Aquí hay un ejemplo trivial:

void *
__wrap_malloc (size_t c)
{
  printf ("malloc llamado con %zu\n", c);
  return __real_malloc (c);
}

Si enlaza otro código con este archivo usando --wrap malloc, todas las llamadas a "malloc" llamarán a la función "__wrap_malloc" en su lugar. La llamada a "__real_malloc" en "__wrap_malloc"

--wrap=symbol
This option specifies that all references to symbol should be replaced with references to "__wrap_symbol" and all references to "__real_symbol" should be replaced by references to symbol. This is used to effectively wrap a library function with your own code. For example, "--wrap=malloc" will cause all calls to "malloc" to be replaced by calls to "__wrap_malloc". You must also provide a function named "__wrap_malloc" which will call the real "malloc" function.

You may wish to provide a "__real_malloc" function as well, so that links without the --wrap option will succeed. If you do this, you should not put the definition of "__real_malloc" in the same file as "__wrap_malloc"; if you do, the assembler may resolve the call before the linker has a chance to wrap it to "malloc".

Only undefined references are replaced by the linker. So, translation unit internal references to symbol are not resolved to "__wrap_symbol". In the next example, the call to "f" in "g" is not resolved to "__wrap_f".

int
f (void)
{
  return 123;
}

int
g (void)
{
  return f();
}

Las siguientes observaciones se refieren a la implementación original de la característica y están obsoletas hoy en día para los destinos Cygwin y MinGW.

Nota: El uso de la extensión 'auto-import' hará que la sección de texto del archivo de imagen se vuelva escribible. Esto no se ajusta a la especificación del formato PE-COFF publicada por Microsoft.

Nota: el uso de la extensión 'auto-import' también hará que los datos de solo lectura que normalmente se colocarían en la sección .rdata se coloquen en la sección .data en su lugar. Esto es para solucionar un problema con las constantes que se describe aquí: http://www.cygwin.com/ml/cygwin/2004-09/msg01101.html

Usar 'auto-import' generalmente "simplemente funciona", pero a veces puedes ver este mensaje:

"variable '<var>' no se puede autoimportar. Por favor, lee la documentación de "--enable-auto-import" de ld para más detalles."

Este mensaje ocurre cuando alguna (sub)expresión accede a una dirección dada en última instancia por la suma de dos constantes (las tablas de importación de Win32 solo permiten una). Las instancias donde esto puede ocurrir incluyen accesos a campos miembro de variables de estructura importadas de una DLL, así como el uso de un índice constante en una variable de matriz importada de una DLL. Cualquier variable de múltiples palabras (matrices, estructuras, long long, etc.) puede desencadenar esta condición de error. Sin embargo, independientemente del tipo de datos exacto de la variable exportada ofensiva, ld siempre la detectará, emitirá la advertencia y saldrá.

Hay varias formas de abordar esta dificultad, independientemente del tipo de datos de la variable exportada:

Una forma es usar el interruptor --enable-runtime-pseudo-reloc. Esto deja la tarea de ajustar las referencias en el código del cliente para el entorno de ejecución, por lo que este método solo funciona cuando el entorno de ejecución admite esta característica.

Una segunda solución es forzar que una de las 'constantes' sea una variable, es decir, desconocida y no optimizable en tiempo de compilación. Para matrices, hay dos posibilidades: a) hacer del índice (la dirección de la matriz) una variable, o b) hacer de la constante índice una variable. Así:

extern type extern_array[];
extern_array[1] -->
   { volatile type *t=extern_array; t[1] }

o

extern type extern_array[];
extern_array[1] -->
   { volatile int t=1; extern_array[t] }

Para estructuras (y la mayoría de los demás tipos de datos de múltiples palabras) la única opción es hacer que la estructura misma (o el long long, o el ...) sea una variable:

extern struct s extern_struct;
extern_struct.field -->
   { volatile struct s *t=&extern_struct; t->field }

o

extern long long extern_ll;
extern_ll -->
  { volatile long long * local_ll=&extern_ll; *local_ll }

Un tercer método para lidiar con esta dificultad es abandonar 'auto-import' para el símbolo ofensivo y marcarlo con . Sin embargo, en la práctica, esto requiere el uso de #defines en tiempo de compilación para indicar si estás creando una DLL, creando código cliente que se enlazará a la DLL, o simplemente creando/enlazando a una biblioteca estática. Al elegir entre los diversos métodos para resolver el problema de 'dirección directa con desplazamiento constante', debes considerar el uso típico en el mundo real:

Original:

--foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

Solución 1:

--foo.h
extern int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  /* Este workaround es para win32 y cygwin; no "optimizar" */
  volatile int *parr = arr;
  printf("%d\n",parr[1]);
}

Solución 2:

--foo.h
/* Nota: se asume auto-export (sin __declspec(dllexport)) */
#if (defined(_WIN32) || defined(__CYGWIN__)) && \
  !(defined(FOO_BUILD_DLL) || defined(FOO_STATIC))
#define FOO_IMPORT __declspec(dllimport)
#else
#define FOO_IMPORT
#endif
extern FOO_IMPORT int arr[];
--foo.c
#include "foo.h"
void main(int argc, char **argv){
  printf("%d\n",arr[1]);
}

Una cuarta forma de evitar este problema es reestructurar su biblioteca para usar una interfaz funcional en lugar de una interfaz de datos para las variables ofensivas (por ejemplo, funciones accesoras set_foo() y get_foo()).

ENVIRONMENT

If the environment variable LD_DEMANGLE is set, then it will default to not demangling symbols. This environment variable is used in a similar fashion by the gcc linker wrapper program. The default may be overridden by the --demangle and --no-demangle options.
