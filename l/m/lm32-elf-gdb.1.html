GDB(1) Herramientas de desarrollo GNU GDB(1)

NOMBRE

gdb - El Depurador GNU

SINOPSIS

gdb [OPCIONES] [programa|programa ID_proceso|programa core]

DESCRIPCIÓN

El propósito de un depurador como GDB es permitirle ver qué está sucediendo "dentro" de otro programa mientras se ejecuta -- o qué estaba haciendo otro programa en el momento en que falló.

GDB puede hacer cuatro tipos principales de cosas (además de otras cosas en apoyo de estas) para ayudarle a detectar errores en el acto:

  • Iniciar su programa, especificando cualquier cosa que pueda afectar su comportamiento.
  • Hacer que su programa se detenga bajo condiciones especificadas.
  • Examinar qué ha sucedido, cuando su programa se ha detenido.
  • Cambiar cosas en su programa, para que pueda experimentar corrigiendo los efectos de un error y seguir aprendiendo sobre otro.

Puede usar GDB para depurar programas escritos en C, C++, Fortran y Modula-2.

GDB se invoca con el comando de shell "gdb". Una vez iniciado, lee comandos del terminal hasta que le indica que salga con el comando GDB "quit" o "exit". Puede obtener ayuda en línea desde el propio GDB utilizando el comando "help".

Puede ejecutar "gdb" sin argumentos ni opciones; pero la forma más común de iniciar GDB es con un argumento o dos, especificando un archivo ejecutable como argumento:

gdb programa

También puede iniciar con un archivo ejecutable y un archivo core especificados:

gdb programa core

Puede, en su lugar, especificar un ID de proceso como segundo argumento o usar la opción "-p", si desea depurar un proceso en ejecución:

gdb programa 1234
gdb -p 1234

conectaría GDB al proceso 1234. Con la opción -p puede omitir el nombre de archivo programa.

Aquí hay algunos de los comandos GDB más frecuentemente necesarios:

break [archivo:][función|línea]
Establece un punto de interrupción en función o línea (en archivo).
run [lista_args]
Inicia su programa (con lista_args, si se especifica).
bt
Backtrace: muestra la pila del programa.
print expresión
Muestra el valor de una expresión.
c
Continúa ejecutando su programa (después de detenerse, p. ej. en un punto de interrupción).
next
Ejecuta la siguiente línea del programa (después de detenerse); avanza *sobre* cualquier llamada a función en la línea.
edit [archivo:]función
mira la línea del programa donde se detiene actualmente.
list [archivo:]función
escribe el texto del programa en las proximidades de donde se detiene actualmente.
step
Ejecuta la siguiente línea del programa (después de detenerse); avanza *dentro* de cualquier llamada a función en la línea.
help [nombre]
Muestra información sobre el comando GDB nombre, o información general sobre el uso de GDB.
quit
exit
Sale de GDB.

Para obtener detalles completos sobre GDB, consulte Using GDB: A Guide to the GNU Source-Level Debugger, por Richard M. Stallman y Roland H. Pesch. El mismo texto está disponible en línea como la entrada "gdb" en el programa "info".

OPCIONES

Cualquier argumento que no sean opciones especifica un archivo ejecutable y un archivo core (o ID de proceso); es decir, el primer argumento encontrado sin un indicador de opción asociado es equivalente a una opción --se, y el segundo, si lo hay, es equivalente a una opción -c si es el nombre de un archivo. Muchas opciones tienen formas largas y abreviadas; ambas se muestran aquí. Las formas largas también se reconocen si las trunca, siempre que sea suficiente parte de la opción para ser inequívoca.

Las formas abreviadas se muestran aquí con - y las formas largas se muestran con -- para reflejar cómo se muestran en --help. Sin embargo, GDB reconoce todas las siguientes convenciones para la mayoría de las opciones:

"--opción=valor"
"--opción valor"
"-opción=valor"
"-opción valor"
"--o=valor"
"--o valor"
"-o=valor"
"-o valor"

Todas las opciones y argumentos de la línea de comandos que proporcione se procesan en orden secuencial. El orden marca la diferencia cuando se usa la opción -x.

--help
-h
Lista todas las opciones, con explicaciones breves.
--symbols=archivo
-s archivo
Lee la tabla de símbolos del archivo.
--write
Habilita la escritura en archivos ejecutables y core.
--exec=archivo
-e archivo
Usa archivo como el archivo ejecutable para ejecutar cuando sea apropiado, y para examinar datos puros en conjunción con un volcado de memoria (core dump).
--se=archivo
Lee la tabla de símbolos del archivo y úsalo como archivo ejecutable.
--core=archivo
-c archivo
Usa archivo como un volcado de memoria (core dump) para examinar.
--command=archivo
-x archivo
Ejecuta comandos GDB desde archivo.
--eval-command=comando
-ex comando
Ejecuta el comando GDB dado.
--init-eval-command=comando
-iex
Ejecuta el comando GDB antes de cargar el inferior.
--directory=directorio
-d directorio
Añade directorio a la ruta para buscar archivos fuente.
--nh
No ejecutar comandos de ~/.config/gdb/gdbinit, ~/.gdbinit, ~/.config/gdb/gdbearlyinit, o ~/.gdbearlyinit
--nx
-n
No ejecutar comandos de ningún archivo de inicialización .gdbinit o .gdbearlyinit.
--quiet
--silent
-q
"Silencioso". No imprime los mensajes introductorios y de copyright. Estos mensajes también se suprimen en modo batch.
--batch
Ejecutar en modo batch. Salir con estado 0 después de procesar todos los archivos de comando especificados con -x (y .gdbinit, si no está inhibido). Salir con estado no cero si ocurre un error al ejecutar los comandos GDB en los archivos de comando.

DESCRIPCIÃN

GDB es un depurador interactivo de nivel fuente para muchos lenguajes de programación.

GDB le permite hacer cosas como:

  • Iniciar su programa, especificando toda clase de pre-almacenamientos y argumentos que afecten a su comportamiento.
  • Hacer que su programa termine antes de que alcance el punto especificado.
  • Examinar el estado de su programa cuando ha terminado o ha sido interrumpido.
  • Cambiar cualquier cosa en su programa mientras está ejecutándose.

GDB es particularmente útil para depurar programas que fallan inesperadamente, y para encontrar la causa de fallos que ocurren ocasionalmente.

SINOPSIS

gdb [ -help ] [ -nx ] [ -q | --silent ] [ -batch ] [ --batch-silent ] [ --args prog [ arglist ] ] [ --pid=pid ] [ -tui ] [ --readnow ] [ --readnever ] [ --return-child-result ] [ --configuration ] [ --version ] [ --cd=directory ] [ --data-directory=directory ] [ -D ] [ --fullname ] [ -f ] [ -b baudrate ] [ -l timeout ] [ --tty=device ] [ file

OPCIONES

-help
Imprimir un resumen de las opciones de línea de comandos de GDB y salir.
-nx
No leer los comandos del archivo de inicialización `.gdbinit`.
-q, --silent
Modo silencioso. No imprime los mensajes de bienvenida e información adicional que GDB normalmente imprime al inicio. Esto es útil para ejecutar GDB en segundo plano (por ejemplo, usando un script).
--batch
Ejecutar en modo batch. GDB saldrá después de procesar todos los comandos de los scripts y del archivo de comandos. Esto es útil para ejecutar GDB como parte de un script de automatización, por ejemplo, para descargar y ejecutar un programa en otra computadora; para hacerlo más útil, el mensaje

Program exited normally.
(que normalmente se emite cada vez que un programa que se ejecuta bajo el control de GDB termina) no se emite en modo batch.
--batch-silent
Ejecutar en modo batch, igual que --batch, pero totalmente silencioso. Se suprimen todas las salidas de GDB (stderr no se ve afectado). Esto es mucho más silencioso que --silent y sería inútil para una sesión interactiva.

Esto es particularmente útil cuando se utilizan targets que proporcionan mensajes de Loading section, por ejemplo.

Tenga en cuenta que los targets que emiten su salida a través de GDB, en contraposición a escribir directamente en "stdout", también se silenciarán.

--args prog [arglist]
Cambiar la interpretación de la línea de comandos para que los argumentos que siguen a esta opción se pasen como argumentos al inferior. Como ejemplo, tome el siguiente comando: 
gdb ./a.out -q
Esto iniciaría GDB con -q, sin imprimir el mensaje introductorio. Por otro lado, usando: 
gdb --args ./a.out -q
inicia GDB con el mensaje introductorio y pasa la opción al inferior.
--pid=pid
Adjuntar GDB a un programa ya en ejecución, con el PID pid.
--tui
Abrir la interfaz de usuario de terminal.
--readnow
Leer todos los símbolos del symfile dado en el primer acceso.
--readnever
No leer archivos de símbolos.
--return-child-result
El código de salida de GDB será el mismo que el código de salida del hijo.
--configuration
Imprimir detalles sobre la configuración de GDB y luego salir.
--version
Imprimir información de la versión y luego salir.
--cd=directory
Ejecutar GDB usando directory como su directorio de trabajo, en lugar del directorio actual.
--data-directory=directory
-D
Ejecutar GDB usando directory como su directorio de datos. El directorio de datos es donde GDB busca sus archivos auxiliares.
--fullname
-f
Emacs establece esta opción cuando ejecuta GDB como un subproceso. Le indica a GDB que imprima el nombre de archivo completo y el número de línea en un formato estándar y reconocible cada vez que se muestra un marco de pila (lo que incluye cada vez que el programa se detiene). Este formato reconocible se ve como dos caracteres \032, seguidos del nombre del archivo, el número de línea y la posición del carácter separados por dos puntos, y un salto de línea. El programa de interfaz Emacs-a-GDB utiliza los dos caracteres \032 como señal para mostrar el código fuente del marco.
-b baudrate
Establecer la velocidad de línea (baud rate o bits por segundo) de cualquier interfaz serie utilizada por GDB para depuración remota.
-l timeout
Establecer el tiempo de espera, en segundos, para la depuración remota.
--tty=device
Ejecutar usando device para la entrada y salida estándar de su programa.
