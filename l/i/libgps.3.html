NOMBRE

libgps - biblioteca de servicio C para comunicarse con el demonio GPS

SINOPSIS

C:

#include <gps.h>
int gps_open(char * servidor, char * puerto, struct gps_data_t * gpsdata)
int gps_send(struct gps_data_t * gpsdata, char * fmt, ...)
int gps_read(struct gps_data_t * gpsdata, char * mensaje,
             int tamano_mensaje)
bool gps_waiting(const struct gps_data_t * gpsdata, int tiempo_espera)
char * gps_data(const struct gps_data_t * gpsdata)
int gps_unpack(char * buf, struct gps_data_t * gpsdata)
int gps_close(struct gps_data_t * gpsdata)
int gps_stream(struct gps_data_t * gpsdata, unsigned int flags,
               void * data)
int gps_mainloop(struct gps_data_t * gpsdata, int tiempo_espera,
                 void (* hook)(struct gps_data_t *gpsdata))
const char * gps_errstr(int err)

Python:

import gps
sesion = gps.gps(host="localhost", port="2947")
sesion.stream(flags=gps.WATCH_JSON)
while 0 == sesion.read():
    procesar(sesion)
del sesion

DESCRIPCIÓN

C

libgps es una biblioteca de servicio que soporta la comunicación con una instancia de gpsd(8), vincúlala con la opción del enlazador -lgps. Algunos sistemas también pueden requerir -lm.


Advertencia

Tenga cuidado de condicionalizar su código según las versiones de la API mayor y menor
símbolos en gps.h; idealmente, fuerce un fallo de compilación si GPSD_API_MAJOR_VERSION no es una versión que reconozca. Consulte el sitio web del proyecto GPSD para obtener más información sobre los cambios en el protocolo y la API.

Todas las funciones descritas aquí utilizan la estructura gps_data_t. Consulte gps.h para obtener más información sobre gps_data_t, sus miembros de datos, estructuras asociadas. marcas de tiempo asociadas. Tenga en cuenta que la información se acumulará en la estructura de sesión con el tiempo, y el campo 'valid' no se pone a cero automáticamente en cada gps_read(). Corresponde al cliente poner a cero ese campo cuando sea apropiado y vigilar las marcas de tiempo de la corrección y las sentencias.


Advertencia

gps_data_t establece variables de punto flotante a NaN cuando el valor
real de la variable es desconocido. Verifique todos los flotantes y dobles con isfinite() antes de usarlos. ¡isnan() no es suficiente!

gps_open()

Llamar a gps_open() inicializa una estructura gps_data_t para contener los datos recopilados por el GPS, y establece el acceso a gpsd(8) a través de la exportación de memoria compartida o de socket. La exportación de memoria compartida es más rápida, pero no transporta información sobre eventos de activación y desactivación de dispositivos y no le permitirá monitorizar el tráfico de paquetes del dispositivo.

gps_open() devuelve 0 en caso de éxito, -1 en caso de error y es reentrante. errno se establece según el error devuelto por la interfaz de socket o de memoria compartida; consulte gps.h para ver los valores y explicaciones; consulte también gps_errstr(). La dirección del host puede ser un nombre DNS, una cuadrupleta punteada IPv4, una dirección IPv6, o el valor especial GPSD_SHARED_MEMORY refiriéndose a la exportación de memoria compartida; la biblioteca hará lo correcto para cualquiera de ellos.

gps_close()

gps_close() finaliza la sesión y solo debe llamarse después de un gps_open() exitoso. Devuelve 0 en caso de éxito, -1 en caso de error. El cierre de la interfaz de memoria compartida siempre devuelve 0, mientras que el cierre de un socket puede resultar en un error. Para un error de cierre de socket, habrá establecido un errno de la llamada a la función close() del sistema.

gps_send()

gps_send() escribe un comando al demonio gpsd. No hace nada cuando se utiliza la exportación de memoria compartida. El segundo argumento debe ser una cadena de formato que contenga elementos del conjunto de comandos documentado en gpsd(8). Puede tener elementos % como para sprintf(3), que se rellenarán a partir de los argumentos siguientes. Esta función devuelve -1 si hubo un error de escritura a nivel de Unix, de lo contrario 0. Lea la sección LIMITACIONES para obtener información y precauciones adicionales. Consulte gps_stream() como posible alternativa.

gps_read()

gps_read() acepta una respuesta, o una secuencia de respuestas, del demonio gpsd y decodifica la respuesta en un gps_data_t. Por defecto, esta función realiza una lectura bloqueante de datos del demonio gpsd o una recuperación de memoria compartida; devuelve el número de bytes leídos en caso de éxito, -1 con errno establecido en caso de error de lectura a nivel de Unix, -1 sin errno establecido si el socket a gpsd se ha cerrado o si el segmento de memoria compartida no estaba disponible, y 0 si no hay datos disponibles.

El segundo argumento de gps_read() suele ser NULL, y el tercer argumento es cero. Si su aplicación desea ver los datos brutos del demonio gpsd, establezca el segundo argumento a la dirección de su búfer de mensajes, y el tercer argumento es el tamaño de su búfer. Úselo con cuidado; es posible que no sea una cadena terminada en NUL si WATCH_RAW está habilitado.

gps_waiting()

gps_waiting() se puede usar para verificar si hay nuevos datos del demonio gpsd. El segundo argumento es el tiempo máximo a esperar (en microsegundos) por entrada antes de devolver. Devuelve verdadero si hay entrada esperando, falso en caso de tiempo de espera (ningún dato esperando) o condición de error. Cuando se utiliza la exportación de socket, esta función es un envoltorio de conveniencia alrededor de una llamada select(2), y pone a cero errno al entrar; puede verificar errno después de salir para obtener más información sobre condiciones de error.

Advertencia: bajo la interfaz de memoria compartida hay una pequeña ventana de carrera entre gps_waiting() y un siguiente gps_read(); en ese contexto, dado que este último no se bloquea, es probablemente mejor escribir un bucle de lectura simple.

gps_mainloop()

gps_mainloop() permite que la función de gancho proporcionada se llame continuamente siempre que haya datos de gpsd. El segundo argumento es el tiempo máximo a esperar (en microsegundos) por entrada antes de salir del bucle (y devolver un valor de -1). También devolverá un valor negativo en varios errores.

gps_unpack()

gps_unpack() analiza JSON del búfer de argumentos en el destino del argumento puntero de la estructura de sesión. Incluido en caso de que su aplicación desee gestionar la E/S de socket por sí misma.

gps_data()

gps_data() devuelve el contenido del búfer de datos del cliente (devuelve NULL cuando se utiliza la exportación de memoria compartida). Úselo con cuidado; es posible que no sea una cadena terminada en NUL si WATCH_RAW está habilitado.

gps_stream()

gps_stream() solicita a gpsd que le envíe los informes que tiene, para que estén disponibles cuando consulte (no disponible cuando se utiliza la exportación de memoria compartida). El segundo argumento es una máscara de banderas que establece varios bits de política; consulte la lista a continuación. Se permite llamar a gps_stream() más de una vez con diferentes máscaras de banderas.

WATCH_DEVICE

Restringe la vigilancia a un dispositivo específico. La cadena de la ruta del dispositivo se proporciona como tercer argumento (datos).

WATCH_DISABLE

Deshabilita los modos de reporte especificados por las otras banderas WATCH_.

WATCH_ENABLE

Habilita los modos de reporte especificados por las otras banderas WATCH_. Este es el valor predeterminado.

WATCH_JSON

Habilita el reporte de datos en formato JSON. Si se establece WATCH_ENABLE, y no se establecen otras banderas WATCH, este es el valor predeterminado.

WATCH_NEWSTYLE

Fuerza la emisión de una inicialización JSON y la obtención de respuestas de estilo nuevo. Este es el valor predeterminado.

WATCH_NMEA

Habilita el reporte de pseudo-NMEA generado en dispositivos binarios.

WATCH_OLDSTYLE

Fuerza la emisión de un comando W o R y la obtención de respuestas de estilo antiguo. Advertencia: esta bandera (y la capacidad) se eliminarán en una futura versión.

WATCH_RARE

Habilita el reporte de paquetes binarios en formato hexadecimal codificado.

WATCH_RAW

Habilita el paso literal de paquetes binarios.

WATCH_SCALED

Al reportar datos AIS o Subframe, escala las cantidades enteras a flotantes si tienen un divisor o una fórmula de renderizado asociado.

gps_errstr()

gps_errstr() devuelve una cadena ASCII (en inglés) que describe el error indicado por un valor distinto de cero devuelto por gps_op

libgps(3) — Arch Linux manual pages

NAME

libgps - GPSD client library

SYNOPSIS

#include <gps.h>
struct gps_data_t gpsdata;
int gps_open(const char *host, const char *port, struct gps_data_t *gpsdata);
int gps_stream(struct gps_data_t *gpsdata, unsigned int flags,
    const char *device);
bool gps_waiting(struct gps_data_t *gpsdata, int timeout);
int gps_read(struct gps_data_t *gpsdata, char **buf, size_t *buflen);
int gps_poll(struct gps_data_t *gpsdata);
int gps_send(struct gps_data_t *gpsdata, const char *fmt, ...);
int gps_close(struct gps_data_t *gpsdata);

Python bindings are available as the gps module.

DESCRIPTION

The gpsd(8) daemon aggregates data from a GPS device and makes it available to clients on a TCP/IP port, traditionally port 2947. The libgps library provides a convenient way for clients to access this data.

The primary interface is the gps(3) structure, which holds the client's state and the data received from gpsd(8). A new client typically opens a session by calling gps_open().

gps_open(3)

Connects to the specified host and port. If successful, it initializes the gps(3) structure pointed to by gpsdata. On failure, it returns -1 and sets errno.

gps_stream(3)

This is the call that tells gpsd what you want to receive. flags can be a bitmask of:

WATCH_ENABLE
Enable streaming of data.
WATCH_DISABLE
Disable streaming of data.
WATCH_NMEA
Request NMEA sentences.
WATCH_RAUB
Request raw NMEA data.
WATCH_BINARY
Request binary data (not usually useful).
WATCH_JSON
Request JSON objects (default).
WATCH_ACTIVATION
Report when devices are activated or deactivated.
WATCH_DEVICE
Report device name and driver.
WATCH_SCIMARKER
Report SCI (System Clock Integrity) marker data.

If device is not NULL, it requests data from that specific device. Otherwise, data is requested from the default device.

gps_waiting(3)

Returns true if gpsd has data available, false otherwise. The optional timeout specifies how long to wait (in seconds). A timeout of 0 returns immediately. A negative timeout means wait forever.

gps_read(3)

Reads data from gpsd. If buf is NULL, it populates the internal buffer in the gps(3) structure. If buf is not NULL, it reads into the provided buffer, up to buflen bytes. On success, it returns the number of bytes read. On failure, it returns -1.

This function populates the gps(3) structure with the latest available data. You can check the set field of the gps(3) structure to see which data fields are valid. For example, TIME_SET indicates that the time is valid.

gps_poll(3)

This function reads any waiting data, up to the point where a full report has been received, or a timeout occurs. It is the preferred way to poll for data.

gps_send(3)

Sends a command to gpsd. The fmt argument is a format string, similar to printf, followed by arguments. This is intended for sending commands, not for general data transmission.

gps_close(3)

Closes the connection to gpsd and frees any associated resources.

Python

The Python implementation supports the same facilities as the the C library. gps_open() is replaced by the initialization of a gps session object: session = gps.gps(...). The other calls are methods of that object, and have the same names as the corresponding C functions.

In addition to using gps.read() to read messages from gpsd, you can use the session object as an iterator, as in the code fragment given below. Python iterators implicitly call the function gps.\_\_next() which is just a shim over gps.read(). There is other advantage to using the implicit iterator and it does not allow the options that gps.read() does.

import gps
session = gps.gps(host="localhost", port="2947")
session.stream(flags=gps.WATCH_JSON)
for report in session:
    process(report)
del session

Resources within the session object will be properly released when it is garbage-collected.

For further information on the Python gps module, read the comments in the modules files. There is a complete Python example in the file www/gpsd-client-example-code.adoc.

ENVIRONMENT VARIABLES

By setting the environment variable GPSD_SHM_KEY, you can control the key value used to create shared-memory segment used for communication with gpsd. This will be useful mainly when isolating test instances of gpsd from production ones.

EXAMPLES

The following is a fully functional minimal C client. Check the C source for the other gpsd clients for more ideas.

// example  gpsd client
// compile this way:
//    gcc example1.c -o example1 -lgps -lm
#include <gps.h>         // for gps_*()
#include <math.h>        // for isfinite()
#define MODE_STR_NUM 4
static char *mode_str[MODE_STR_NUM] = {
    "n/a",
    "None",
    "2D",
    "3D"
};
int main(int argc, char *argv[])
{
    struct gps_data_t gps_data;
    if (0 != gps_open("localhost", "2947", &gps_data)) {
        printf("Open error.  Bye, bye\n");
        return 1;
    }
    (void)gps_stream(&gps_data, WATCH_ENABLE | WATCH_JSON, NULL);
    while (gps_waiting(&gps_data, 5000000)) {
        if (-1 == gps_read(&gps_data, NULL, 0)) {
            printf("Read error.  Bye, bye\n");
            break;
        }
        if (MODE_SET != (MODE_SET & gps_data.set)) {
            // did not even get mode, nothing to see here
            continue;
        }
        if (0 > gps_data.fix.mode ||
            MODE_STR_NUM <= gps_data.fix.mode) {
            gps_data.fix.mode = 0;
        }
        printf("Fix mode: %s (%d) Time: ",
               mode_str[gps_data.fix.mode],
               gps_data.fix.mode);
        if (TIME_SET == (TIME_SET & gps_data.set)) {
            // not 32 bit safe
            printf("%ld.%09ld ", gps_data.fix.time.tv_sec,
                   gps_data.fix.time.tv_nsec);
        } else {
            puts("n/a ");
        }
        if (isfinite(gps_data.fix.latitude) &&
            isfinite(gps_data.fix.longitude)) {
            // Display data from the GPS receiver if valid.
            printf("Lat %.6f Lon %.6f\n",
                   gps_data.fix.latitude, gps_data.fix.longitude);
        } else {
            printf("Lat n/a Lon n/a\n");
        }
    }
    // When you are done...
    (void)gps_stream(&gps_data, WATCH_DISABLE, NULL);
    (void)gps_close(&gps_data);
    return 0;
}

LIMITATIONS

On some systems (those which do not support implicit linking in libraries) you may need to add -lm to your link line when you link libgps. It is always safe to do this.

In the C API, incautious use of gps_send() may lead to subtle bugs. In order to not bloat struct gps_data_t with space used by responses that are not expected to be shipped in close sequence with each other, the storage for fields associated with certain responses are combined in a union.

The risky set of responses includes VERSION, DEVICELIST, RTCM2, RTCM3, SUBFRAME, AIS, GST, and ERROR; it may not be limited to that set. The logic of the gpsd daemon’s watcher mode is careful to avoid dangerous sequences, but you should read and understand the layout of struct gps_data_t before using gps_send() to request any of these responses.

COMPATIBILITY

The gps_query() supported in major versions 1 and 2 of this library has been removed. With the new streaming-oriented wire protocol behind this library, it is extremely unwise to assume that the first transmission from the gpsd daemon after a command is shipped to it will be the response to command.

If you must send commands to the gpsd daemon explicitly, use gps_send() but beware that this ties your code to the GPSD wire protocol. It is not recommended.

In some versions of the API gps_read() is a blocking call and there was a POLL_NONBLOCK option to make it nonblocking. gps_waiting() was added to reduce the number of wrong ways to code a polling loop.

See the comment above the symbol GPSD_API_MAJOR_VERSION in gps.h for recent changes.
