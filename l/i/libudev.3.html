NOMBRE

libudev - API para enumerar e inspeccionar dispositivos locales

SINOPSIS

#include <libudev.h>

pkg-config --cflags --libs libudev

DESCRIPCIÓN

libudev.h proporciona una API para inspeccionar y enumerar dispositivos en el sistema local. Esta biblioteca es compatible, pero no debe usarse en proyectos nuevos. Consulte sd-device(3) para un reemplazo equivalente con una API más moderna.

Todas las funciones requieren un contexto libudev para operar. Este contexto se puede crear a través de udev_new(3). Se utiliza para rastrear el estado de la biblioteca y vincular objetos. libudev no utiliza estado global, todo está siempre vinculado a un contexto udev.

Todas las funciones enumeradas aquí no dependen de hilos y solo un hilo puede operar en un objeto dado en un momento dado. Diferentes hilos pueden acceder al mismo objeto en diferentes momentos. Múltiples objetos independientes pueden usarse desde diferentes hilos en paralelo.

El código descrito aquí utiliza getenv(3), que se declara como no seguro para múltiples hilos. Esto significa que el código que llama a las funciones aquí descritas no debe llamar a setenv(3) desde un hilo paralelo. Se recomienda realizar llamadas a setenv() solo desde una fase temprana del programa cuando no se hayan iniciado otros hilos.

Para inspeccionar un dispositivo local en un sistema, se puede crear un objeto de dispositivo udev a través de udev_device_new_from_syspath(3) y similares. El objeto del dispositivo permite consultar el estado actual, leer y escribir atributos, y buscar propiedades del dispositivo en cuestión.

Para enumerar dispositivos locales en el sistema, se puede crear un objeto de enumeración a través de udev_enumerate_new(3).

Para monitorear el sistema local en busca de dispositivos conectados o desconectados en caliente, se puede crear un monitor a través de udev_monitor_new_from_netlink(3).

Cada vez que libudev devuelve una lista de objetos, se debe usar la API de udev_list_entry(3) para iterar, acceder y modificar esas listas.

Además, libudev también exporta APIs heredadas que no deben ser utilizadas por software nuevo (y por lo tanto no se documentan como parte de este manual). Esto incluye la base de datos de hardware conocida como udev_hwdb (por favor, use la nueva API sd-hwdb(3) en su lugar) y el objeto udev_queue para consultar el demonio udev (que no debe ser utilizado por software nuevo en absoluto).
