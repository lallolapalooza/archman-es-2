libressl-EVP_SealInit(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

EVP_SEALINIT(3) Manual de funciones de biblioteca EVP_SEALINIT(3)

NOMBRE

EVP_SealInit, EVP_SealUpdate, EVP_SealFinal — Cifrado de sobre EVP

SINOPSIS

biblioteca “libcrypto”
#include <openssl/evp.h>

int
EVP_SealInit(EVP_CIPHER_CTX *ctx, const EVP_CIPHER *type, unsigned char **ek, int *ekl, unsigned char *iv, EVP_PKEY **pubk, int npubk);

int
EVP_SealUpdate(EVP_CIPHER_CTX *ctx, unsigned char *out, int *outl, unsigned char *in, int inl);

int
EVP_SealFinal(EVP_CIPHER_CTX *ctx, unsigned char *out, int *outl);

DESCRIPCIÓN

Las rutinas de cifrado de sobre de EVP son una interfaz de alto nivel para el cifrado de sobre. Generan una clave y un IV aleatorios (si son necesarios) y luego los "envuelven" utilizando cifrado de clave pública. Los datos se pueden cifrar utilizando esta clave.

EVP_SealInit() inicializa un contexto de cifrado ctx para cifrado con el cifrado type utilizando una clave secreta y un IV aleatorios. type normalmente lo proporciona una función como EVP_aes_256_cbc(3); consulte EVP_EncryptInit(3) para obtener detalles. La clave secreta se cifra utilizando una o más claves públicas. Esto permite que los mismos datos cifrados se descifren utilizando cualquiera de las claves privadas correspondientes. ek es una matriz de búferes donde se escribirá la clave secreta cifrada con clave pública. Cada búfer debe contener suficiente espacio para la clave secreta cifrada correspondiente: es decir, ek[i] debe tener espacio para EVP_PKEY_size(pubk[i]) bytes. El tamaño real de cada clave secreta cifrada se escribe en la matriz ekl. pubk es una matriz de npubk claves públicas.

El parámetro iv es un búfer donde se escribe el IV generado. Debe contener suficiente espacio para el IV del cifrado correspondiente, según lo determinado por (por ejemplo) EVP_CIPHER_iv_length(type).

Si el cifrado no requiere un IV, el parámetro iv se ignora y puede ser NULL.

EVP_SealUpdate() y EVP_SealFinal() tienen exactamente las mismas propiedades que las rutinas EVP_EncryptUpdate(3) y EVP_EncryptFinal(3).

La clave pública debe ser RSA porque es el único algoritmo de clave pública de OpenSSL que admite el transporte de claves.

El cifrado de sobre es el método habitual de utilizar el cifrado de clave pública en grandes cantidades de datos. Esto se debe a que el cifrado de clave pública es lento, pero el cifrado simétrico es rápido. Por lo tanto, el cifrado simétrico se utiliza para el cifrado masivo y la pequeña clave simétrica aleatoria utilizada se transfiere mediante cifrado de clave pública.

Es posible llamar a EVP_SealInit() dos veces de la misma manera que a EVP_EncryptInit(3). La primera llamada debe tener npubk establecido en 0 y (después de establecer cualquier parámetro de cifrado) se debe llamar de nuevo con type establecido en NULL.

EVP_SealUpdate() se implementa como una macro.

VALORES DE RETORNO

EVP_SealInit() devuelve 0 en caso de error o npubk si tiene éxito.

EVP_SealUpdate() y EVP_SealFinal() devuelven 1 para éxito y 0 para fallo.

VER TAMBIÉN

evp(3), EVP_EncryptInit(3), EVP_OpenInit(3)

HISTORIA

EVP_SealInit(), EVP_SealUpdate(), y EVP_SealFinal() aparecieron por primera vez en SSLeay 0.5.1 y han estado disponibles desde OpenBSD 2.4.

EVP_SealFinal() no devolvía un valor antes de OpenSSL 0.9.7.
