NOMBRE

long
SSL_CTX_get_tlsext_status_arg(SSL_CTX *ctx, void **arg);

long
SSL_set_tlsext_status_type(SSL *s, int type);

long
SSL_get_tlsext_status_type(SSL *s);

long
SSL_get_tlsext_status_ocsp_resp(ssl, unsigned char **resp);

long
SSL_set_tlsext_status_ocsp_resp(ssl, unsigned char *resp, int len);

DESCRIPCIÓN

Una aplicación cliente puede solicitar que un servidor envíe una respuesta de estado OCSP (también conocida como OCSP stapling). Para hacerlo, el cliente debe llamar a la función SSL_set_tlsext_status_type() en un objeto SSL individual antes del inicio del handshake. Actualmente, el único tipo soportado es TLSEXT_STATUSTYPE_ocsp. Este valor debe pasarse en el argumento type.

El cliente también debe proporcionar una función de callback para decidir qué hacer con la respuesta OCSP devuelta, llamando a SSL_CTX_set_tlsext_status_cb(). La función de callback debe determinar si la respuesta OCSP devuelta es aceptable o no. A la función de callback se le pasará como argumento el valor establecido previamente mediante una llamada a SSL_CTX_set_tlsext_status_arg(). Tenga en cuenta que el callback no se llamará en caso de un handshake en el que se reanude la sesión (porque no se intercambian certificados en dicho handshake).

La función de callback establecida previamente mediante SSL_CTX_set_tlsext_status_cb() puede recuperarse llamando a SSL_CTX_get_tlsext_status_cb(), y el argumento llamando a SSL_CTX_get_tlsext_status_arg().

En el lado del cliente, SSL_get_tlsext_status_type() puede utilizarse para determinar si el cliente ha llamado previamente a SSL_set_tlsext_status_type(). Devolverá TLSEXT_STATUSTYPE_ocsp si se ha llamado o -1 en caso contrario. En el lado del servidor, SSL_get_tlsext_status_type() puede utilizarse para determinar si el cliente solicitó OCSP stapling. Si el cliente lo solicitó, esta función devolverá TLSEXT_STATUSTYPE_ocsp, o -1 en caso contrario.

La respuesta devuelta por el servidor puede obtenerse mediante una llamada a SSL_get_tlsext_status_ocsp_resp(). El valor *resp se actualizará para apuntar a los datos de la respuesta OCSP y el valor de retorno será la longitud de dichos datos. Si el servidor no ha proporcionado ningún dato de respuesta, entonces *resp será NULL y el valor de retorno de SSL_get_tlsext_status_ocsp_resp() será -1.

Una aplicación de servidor también debe llamar a la función SSL_CTX_set_tlsext_status_cb() si desea poder proporcionar a los clientes respuestas de estado de certificado OCSP. Típicamente, la función de callback del servidor obtendría el certificado del servidor que se está enviando de vuelta al cliente mediante una llamada a SSL_get_certificate(3), obtendría la respuesta OCSP a enviar de vuelta y luego establecería esos datos de respuesta llamando a SSL_set_tlsext_status_ocsp_resp(). Se debe proporcionar un puntero a los datos de respuesta en el argumento resp, y la longitud de dichos datos debe estar en el argumento len.

VALORES DE RETORNO

La función de callback, cuando se usa en el lado del cliente, debe devolver un valor negativo en caso de error, 0 si la respuesta no es aceptable (en cuyo caso el handshake fallará), o un valor positivo si es aceptable.

La función de callback, cuando se usa en el lado del servidor, debe devolver SSL_TLSEXT_ERR_OK (lo que significa que la respuesta OCSP establecida debe ser devuelta), SSL_TLSEXT_ERR_NOACK (lo que significa que no se debe devolver ninguna respuesta OCSP), o SSL_TLSEXT_ERR_ALERT_FATAL (lo que significa que ha ocurrido un error fatal).

SSL_CTX_set_tlsext_status_cb(), SSL_CTX_get_tlsext_status_cb(), SSL_CTX_set_tlsext_status_arg(), SSL_CTX_get_tlsext_status_arg(), SSL_set_tlsext_status_type(), y SSL_set_tlsext_status_ocsp_resp() siempre devuelven 1, indicando éxito.

SSL_get_tlsext_status_type() devuelve TLSEXT_STATUSTYPE_ocsp en el lado del cliente si SSL_set_tlsext_status_type() se llamó previamente, o en el lado del servidor si el cliente solicitó OCSP stapling. De lo contrario, devuelve -1.

SSL_get_tlsext_status_ocsp_resp() devuelve la longitud de los datos de la respuesta OCSP o -1 si no hay datos de respuesta OCSP.

VER TAMBIÉN

HISTORIA

SSL_CTX_set_tlsext_status_cb(), SSL_CTX_set_tlsext_status_arg(), SSL_set_tlsext_status_type(), SSL_get_tlsext_status_ocsp_resp(), y SSL_set_tlsext_status_ocsp_resp() aparecieron por primera vez en OpenSSL 0.9.8h y han estado disponibles desde OpenBSD 4.5.

SSL_CTX_get_tlsext_status_cb() y SSL_CTX_get_tlsext_status_arg() aparecieron por primera vez en OpenSSL 1.1.0 y han estado disponibles desde OpenBSD 6.3.

SSL_get_tlsext_status_type() apareció por primera vez en OpenSSL 1.1.0 y ha estado disponible desde OpenBSD 7.0.
