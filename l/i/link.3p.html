LINK(3P) Manual del programador POSIX LINK(3P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

link, linkat — enlazar un archivo a otro archivo

SINOPSIS

#include <unistd.h>
int link(const char *path1, const char *path2);
#include <fcntl.h>
int linkat(int fd1, const char *path1, int fd2,
    const char *path2, int flag);

DESCRIPCIÓN

La función link() creará un nuevo enlace (entrada de directorio) para el archivo existente, path1.

El argumento path1 apunta a un nombre de ruta que nombra un archivo existente. El argumento path2 apunta a un nombre de ruta que nombra la nueva entrada de directorio que se creará. La función link() creará atómicamente un nuevo enlace para el archivo existente y el contador de enlaces del archivo se incrementará en uno.

Si path1 nombra un directorio, link() fallará a menos que el proceso tenga los privilegios apropiados y la implementación soporte el uso de link() en directorios.

Si path1 nombra un enlace simbólico, el seguimiento del enlace simbólico por parte de link() o la creación de un nuevo enlace al propio enlace simbólico es definido por la implementación.

Al completarse con éxito, link() marcará para actualización la última marca de tiempo de cambio de estado del archivo. Además, las últimas marcas de tiempo de modificación de datos y de cambio de estado del directorio que contiene la nueva entrada se marcarán para actualización.

Si link() falla, no se creará ningún enlace y el contador de enlaces del archivo permanecerá sin cambios.

La implementación puede requerir que el proceso que llama tenga permiso para acceder al archivo existente.

La función linkat() será equivalente a la función link() excepto que los enlaces simbólicos se manejarán como se especifica por el valor de flag (ver más abajo) y excepto en el caso en que path1 o path2 o ambos sean rutas relativas. En este caso, una ruta relativa path1 se interpreta en relación con el directorio asociado con el descriptor de archivo fd1 en lugar del directorio de trabajo actual y de manera similar para path2 y el descriptor de archivo fd2. Si el modo de acceso de la descripción del archivo abierto asociado con el descriptor de archivo no es O_SEARCH, la función verificará si se permiten búsquedas en directorios utilizando los permisos actuales del directorio subyacente al descriptor de archivo. Si el modo de acceso es O_SEARCH, la función no realizará la verificación.

Los valores para flag se construyen mediante una OR inclusiva a nivel de bits de banderas de la siguiente lista, definidas en <fcntl.h>:

AT_SYMLINK_FOLLOW

Si path1 nombra un enlace simbólico, se crea un nuevo enlace para el destino del enlace simbólico.

Si linkat() recibe el valor especial AT_FDCWD en el parámetro fd1 o fd2, se utilizará el directorio de trabajo actual para el argumento path respectivo. Si tanto fd1 como fd2 tienen el valor AT_FDCWD, el comportamiento será idéntico a una llamada a link(), excepto que los enlaces simbólicos se manejarán como se especifica por el valor de flag.

Si la bandera AT_SYMLINK_FOLLOW está despejada en el argumento flag y el argumento path1 nombra un enlace simbólico, se crea un nuevo enlace para el enlace simbólico path1 y no para su destino.

VALOR DE RETORNO

Al completarse con éxito, estas funciones devolverán 0. De lo contrario, estas funciones devolverán -1 y establecerán errno para indicar el error.

ERRORES

Estas funciones fallarán si:

EACCES
Un componente de cualquier prefijo de ruta deniega el permiso de búsqueda, o el enlace solicitado requiere escritura en un directorio que deniega el permiso de escritura, o el proceso que llama no tiene permiso para acceder al archivo existente y esto es requerido por la implementación.
EEXIST
El argumento path2 se resuelve a una entrada de directorio existente o se refiere a un enlace simbólico.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path1 o path2.
EMLINK
El número de enlaces al archivo nombrado por path1 excedería {LINK_MAX}.
ENAMETOOLONG

La longitud de un componente de una ruta es mayor que {NAME_MAX}.
ENOENT
Un componente de cualquier prefijo de ruta no existe; el archivo nombrado por path1 no existe; o path1 o path2 apunta a una cadena vacía.
ENOENT o ENOTDIR

El argumento path1 nombra un archivo existente que no es un directorio, y el argumento path2 contiene al menos un carácter que no es <barra> y termina con uno o más caracteres de <barra> finales. Si path2 sin los caracteres de <barra> finales nombrara un archivo existente, no ocurrirá un error [ENOENT].
ENOSPC
El directorio que contendrá el enlace no puede ser extendido.
ENOTDIR
Un componente de cualquier prefijo de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o el argumento path1 contiene al menos un carácter que no es <barra> y termina con uno o más caracteres de <barra> finales y el último componente de la ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o el argumento path1 nombra un archivo existente que no es un directorio y el argumento path2 nombra un archivo inexistente, contiene al menos un carácter que no es <barra> y termina con uno o más caracteres de <barra> finales.
EPERM
El archivo nombrado por path1 es un directorio y, o bien el proceso que llama no tiene los privilegios apropiados o la implementación prohíbe el uso de link() en directorios.
EROFS
El enlace solicitado requiere escritura en un directorio en un sistema de archivos de solo lectura.
EXDEV
El enlace nombrado por path2 y el archivo nombrado por path1 están en sistemas de archivos diferentes y la implementación no soporta enlaces entre sistemas de archivos.
EXDEV
path1 se refiere a un STREAM con nombre.

La función linkat() fallará si:

EACCES
El modo de acceso de la descripción del archivo abierto asociada con fd1 o fd2 no es O_SEARCH y los permisos del directorio subyacente a fd1 o fd2, respectivamente, no permiten búsquedas en directorios.
EBADF
El argumento path1 o path2 no especifica una ruta absoluta y el argumento fd1 o fd2, respectivamente, no es ni AT_FDCWD ni un descriptor de archivo válido abierto para lectura o búsqueda.
ENOTDIR
El argumento path1 o path2 no es una ruta absoluta y fd1 o fd2, respectivamente, es un descriptor de archivo asociado con un archivo que no es un directorio.

Estas funciones pueden fallar si:

ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path1 o path2.
ENAMETOOLONG

ERRORS

The link() function may fail if:

EACCES
A component of either path1 or path2 is not searchable, or write access to the directory of the file named by path2 is denied.
EEXIST
The file named by path2 already exists.
EINLINK
The directory referred to by path2 has too many links.
ELOOP
Too many symbolic links were encountered in resolving path1 or path2.
EMLINK
The file named by path1 has too many links.
ENAMETOOLONG

The length of a pathname exceeds {PATH_MAX}, or pathname resolution of a symbolic link produced an intermediate result with a length that exceeds {PATH_MAX}.

ENOENT
A component of either path1 or path2 does not exist, or path1 is an empty string.
ENOSPC
The directory referred to by path2 has no space left for the new directory entry.
ENOTDIR
A component of either path1 or path2 is not a directory, or the path1 argument was not specified relative to the current working directory and the file descriptor used to open it was not opened with the O_SEARCH flag.
EROFS
The file or directory named by a component of path2 resides on a read-only file system.
ETXTBSY
The file named by path1 is a text file that is being executed.

The linkat() function may fail if:

EINVAL
The value of the flag argument is not valid.

EXAMPLES

Creación de un enlace a un archivo

El siguiente ejemplo muestra cómo crear un enlace al archivo /home/cnd/mod1 creando una nueva entrada de directorio llamada /modules/pass1.

#include <unistd.h>
char *path1 = "/home/cnd/mod1";
char *path2 = "/modules/pass1";
int   status;
...
status = link (path1, path2);

Creación de un enlace a un archivo dentro de un programa

En el siguiente ejemplo de programa, la función link() enlaza el archivo /etc/passwd (definido como PASSWDFILE) a un archivo llamado /etc/opasswd (definido como SAVEFILE), que se utiliza para guardar el archivo de contraseñas actual. Luego, después de eliminar el archivo de contraseñas actual (definido como PASSWDFILE), el nuevo archivo de contraseñas se guarda como el archivo de contraseñas actual utilizando nuevamente la función link().

#include <unistd.h>
#define LOCKFILE "/etc/ptmp"
#define PASSWDFILE "/etc/passwd"
#define SAVEFILE "/etc/opasswd"
...
/* Guardar el archivo de contraseñas actual */
link (PASSWDFILE, SAVEFILE);
/* Eliminar el archivo de contraseñas actual. */
unlink (PASSWDFILE);
/* Guardar el nuevo archivo de contraseñas como el archivo de contraseñas actual. */
link (LOCKFILE,PASSWDFILE);

USO DE LA APLICACIÓN

Algunas implementaciones permiten enlaces entre sistemas de archivos.

Si path1 se refiere a un enlace simbólico, los desarrolladores de aplicaciones deben usar linkat() con las banderas apropiadas para seleccionar si el enlace simbólico debe resolverse o no.

FUNDAMENTO

El enlace a un directorio está restringido al superusuario en la mayoría de las implementaciones históricas, ya que esta capacidad puede producir bucles en la jerarquía de archivos o corromper de otra manera el sistema de archivos. Este volumen de POSIX.1‐2017 continúa esa filosofía al prohibir que link() y unlink() hagan esto. Otras funciones podrían hacerlo si el implementador diseñara tal extensión.

Algunas implementaciones históricas permiten enlazar archivos en diferentes sistemas de archivos. Se añadió texto para permitir explícitamente este comportamiento opcional.

La excepción para los enlaces entre sistemas de archivos está destinada a aplicarse únicamente a los enlaces que son indistinguibles programáticamente de los enlaces "duros".

El propósito de la función linkat() es enlazar archivos en directorios distintos del directorio de trabajo actual sin exposición a condiciones de carrera. Cualquier parte de la ruta de un archivo podría cambiarse en paralelo a una llamada a link(), resultando en un comportamiento no especificado. Al abrir un descriptor de archivo para el directorio de ambos archivos, el existente y la ubicación de destino, y utilizar la función linkat(), se puede garantizar que ambos nombres de archivo están en los directorios deseados.

La bandera AT_SYMLINK_FOLLOW permite implementar ambos comportamientos comunes de la función link(). La especificación POSIX requiere que si path1 es un enlace simbólico, se cree un nuevo enlace para el destino del enlace simbólico. Muchos sistemas, por defecto o como alternativa, proporcionan un mecanismo para evitar la búsqueda implícita de enlaces simbólicos y crear un nuevo enlace para el propio enlace simbólico.

Las versiones anteriores de este estándar especificaban solo la función link(), y requerían que se comportara como linkat() con la bandera AT_SYMLINK_FOLLOW. Sin embargo, la práctica histórica de los kernels SVR4 y Linux hacía que link() se comportara como linkat() sin banderas, y muchos sistemas que intentaban proporcionar una función link() conforme lo hacían de una manera que rara vez se usaba, y cuando se usaba no cumplía con el estándar (por ejemplo, al no ser atómica, o al desreferenciar incorrectamente el enlace simbólico). Dado que las aplicaciones no podían depender de que link() siguiera los enlaces en la práctica, se añadió la función linkat() con una bandera para especificar el comportamiento deseado para la aplicación.
