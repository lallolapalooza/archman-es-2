Paquete: dnssec-tools

libval(3) Manual del programador libval(3)

NOMBRE

val_create_context() val_free_context() - gestionar el contexto del validador

val_context_setqflags() - gestionar las banderas del contexto del validador

val_resolve_and_check(), val_free_result_chain() - consultar y validar respuestas de un servidor de nombres DNS

val_istrusted() - comprobar si el valor de estado corresponde al de una respuesta confiable

val_isvalidated() - comprobar si el valor de estado representa una respuesta que se encadena criptográficamente desde un ancla de confianza configurada

val_does_not_exist() - comprobar si el valor de estado representa uno de los tipos de no existencia

p_val_status(), p_ac_status(), p_val_error() - mostrar el estado de validación, el estado de la cadena de autenticación y la información de error

val_log_add_optarg - controlar la verbosidad y la ubicación de la salida de los mensajes de registro

DESCRIPCIÓN

La función val_resolve_and_check() consulta un conjunto de servidores de nombres para la tupla <domain_name, type, class> y verifica y valida la respuesta. La verificación implica comprobar las RRSIGs, y la validación es la verificación de una cadena de autenticación desde un ancla de confianza configurada.

El parámetro flags se puede utilizar para controlar los resultados de la validación. Los siguientes valores, que pueden combinarse con un OR, están definidos actualmente para este campo:

VAL_QUERY_DONT_VALIDATE
Esta bandera hace que el validador deshabilite la validación para esta consulta.
VAL_QUERY_IGNORE_SKEW
Esta bandera hace que el validador deshabilite la comprobación de los tiempos de inicio y expiración de las firmas en las RRSIGs.
VAL_QUERY_AC_DETAIL
Esta bandera hace que el validador copie los detalles de la cadena de autenticación en el miembro val_rc_answer dentro de la estructura val_result_chain devuelta.
VAL_QUERY_ASYNC
Esta bandera habilita la resolución asíncrona de consultas para esa búsqueda.
VAL_QUERY_NO_DLV
Esta bandera hace que el validador deshabilite el procesamiento DLV para esta consulta. Esto solo está disponible si la biblioteca libval(3) se ha compilado con soporte DLV.
VAL_QUERY_NO_EDNS0_FALLBACK
Al consultar varios servidores de nombres, libsres(3) también intentará varios tamaños EDNS0, terminando con una consulta que tiene EDNS0 deshabilitado (es decir, sin bit CD establecido). Esta bandera hace que libval deshabilite la recuperación EDNS0 para la consulta.
VAL_QUERY_ITERATE
Esta bandera fuerza a libval a buscar iterativamente el nombre consultando varios servidores de nombres en la jerarquía de delegación, en lugar de solicitar esta información a cualquier servidor de nombres en caché que pueda estar configurado en dnsval.conf.
VAL_QUERY_SKIP_RESOLVER
Esta bandera fuerza a libval a mirar solo su caché mientras intenta resolver un nombre.
VAL_QUERY_SKIP_CACHE
Hay dos niveles de almacenamiento en caché que ocurren dentro de libval: en el nivel de aserción y en el nivel de respuesta. Esta bandera fuerza a libval a ignorar los datos en ambas cachés mientras intenta resolver un nombre.
VAL_QUERY_SKIP_ANS_CACHE
Hay dos niveles de almacenamiento en caché que ocurren dentro de libval: en el nivel de aserción y en el nivel de respuesta. Esta bandera fuerza a libval a ignorar los datos en la caché de respuestas mientras intenta resolver un nombre. Si ya existe una aserción para el nombre, clase y tipo dados, se reutiliza esa aserción hasta que expira. Una vez que expira, el nombre se busca a través de una consulta incluso si un registro más nuevo (obtenido por otra aserción en el mismo u otro contexto) está disponible en su caché de respuestas.

El primer parámetro de val_resolve_and_check() es el contexto del validador. Las aplicaciones pueden crear un nuevo contexto de validador usando la función val_create_context(). Esta función analiza los archivos de configuración del resolvedor y del validador y crea el manejador newcontext para esta información analizada. La información almacenada como parte del contexto del validador incluye la política de validación y la política del resolvedor.

Las políticas del validador y del resolvedor se leen de los archivos /etc/dnsval.conf y /etc/resolv.conf por defecto. /etc/root.hints proporciona información de arranque para el validador cuando funciona como un resolvedor completo (ver dnsval.conf(3)). Estos valores predeterminados pueden ser diferentes si se especificó algún otro valor en el momento de la configuración de la biblioteca. Si el archivo de configuración del resolvedor predeterminado no se encuentra en la ubicación especificada, libval también intentará recurrir a /etc/resolv.conf como último recurso.

Las aplicaciones también pueden crear un contexto de validador con una política personalizada utilizando la función val_create_context_ex().

El argumento opt en val_create_context_ex() apunta a la siguiente estructura:

typedef struct val_context_opt {
    unsigned int vc_qflags;
    unsigned int vc_polflags;
    char *vc_valpol;
    char *vc_nslist;
    char *vc_val_conf;
    char *vc_res_conf;
    char *vc_root_conf;
    val_global_opt_t *gopt, 
} val_context_opt_t;

vc_qflags especifica las banderas de consulta predeterminadas para las consultas asociadas con el contexto. Este campo es idéntico al argumento flags en la función val_resolve_and_check().

Los campos vc_val_conf, vc_res_conf y vc_root_conf se pueden usar para especificar archivos de configuración alternativos en lugar de los archivos predeterminados usados para la información de configuración del validador, del resolvedor y de las pistas raíz.

El campo vc_valpol se puede usar para proporcionar un "fragmento" de configuración del validador personalizado al validador. El validador analiza esta información y la aplica a la configuración del validador predeterminada, ya sea como una extensión o como una anulación, según lo especificado por el campo vc_polflags. El campo vc_nslist, de manera similar, se puede usar para proporcionar una lista personalizada de servidores de nombres recursivos a los que enviar consultas, además de (o en lugar de) la lista de servidores de nombres especificada en el archivo resolv.conf. La lista de servidores de nombres en vc_res_conf debe especificarse como una lista separada por espacios en blanco de direcciones IP o IPv6.

Se puede crear un mapeo personalizado entre una zona y un servidor de nombres usando la función val_context_store_ns_for_zone().

vc_polflags se puede configurar con los siguientes valores:

CTX_DYN_POL_VAL_OVR
Cuando esta bandera está establecida, solo la configuración del validador especificada en el campo vc_valpol se utiliza para la configuración del validador. Las opciones especificadas en el archivo dnsval.conf se ignoran.
CTX_DYN_POL_RES_OVR
Similar a la anterior, solo se utiliza la configuración del resolvedor especificada en el campo vc_res_conf.

La función val_context_setqflags() se puede usar para modificar las banderas de consulta para un contexto de validador existente.

La función val_free_context() libera el contexto del validador creado previamente por val_create_context() o val_create_context_ex().

La función val_free_result_chain() libera la cadena de resultados creada por val_resolve_and_check().

Las funciones p_val_status(), p_ac_status() y p_val_error() convierten los códigos de estado de validación, estado de la cadena de autenticación y códigos de error, respectivamente, en cadenas legibles por humanos.

Las funciones val_istrusted(), val_isvalidated() y val_does_not_exist() son utilidades para comprobar el significado de un valor de estado de validación devuelto por val_resolve_and_check().

La función val_log_add_optarg() controla la salida de los mensajes de registro y su nivel de detalle. Los argumentos en args se analizan de manera similar a los argumentos de línea de comandos de las utilidades DNSSEC. Por ejemplo, -d 2 aumentaría la verbosidad en 2 niveles. Si use_stderr es distinto de cero, la salida de registro se dirige a stderr.

VALOR DE RETORNO

Todas las funciones de creación de contexto y consulta devuelven 0 en caso de éxito, o un código de error negativo en caso de fallo. Las funciones de consulta de estado devuelven distinto de cero si la condición es verdadera, y 0 en caso contrario.

En caso de error, p_val_status(), p_ac_status() y p_val_error() devuelven un puntero a una cadena de error estática.

Cuando esta bandera está establecida, solo se utilizan los servidores de nombres especificados en el campo vc_nslist para la configuración del resolvedor. Las opciones especificadas en el archivo resolv.conf se ignoran.

El campo gopt apunta a la siguiente estructura:

typedef struct val_global_opt {
    int local_is_trusted;
    long edns0_size;
    int env_policy;
    int app_policy;
    char *log_target;
    int closest_ta_only;
    int rec_fallback;
    long max_refresh;
    int proto;
} val_global_opt_t;

Establecer un valor de 1 para local_is_trusted es equivalente a especificar la opción trust-oob-answers en el archivo dnsval.conf a yes. De manera similar, establecer los miembros closest_ta_only y rec_fallback a 1 es equivalente a establecer las opciones closest-ta-only y rec-fallback a yes en el archivo dnsval.conf. Un valor de 0 es equivalente a la configuración no para estas opciones.

Establecer el miembro edns0_size a un valor particular tiene el mismo efecto que establecer la opción edns0-size en el archivo dnsval.conf.

Establecer el miembro max_refresh a un valor particular tiene el mismo efecto que establecer la opción max-refresh en el archivo dnsval.conf.

Establecer el miembro proto a un valor particular tiene el mismo efecto que establecer la opción proto en el archivo dnsval.conf.

env_policy y app_policy se pueden establecer en uno de los valores VAL_POL_GOPT_DISABLE, VAL_POL_GOPT_ENABLE, o VAL_POL_GOPT_OVERRIDE. Estos valores corresponden directamente a las opciones disable, enable y override para los ajustes de env-policy y app-policy en el archivo dnsval.conf.

Los valores de -1 para los campos anteriores se tratan como condiciones de "ignorar", de modo que el validador no incluirá las opciones globales proporcionadas dinámicamente con un valor de -1 al crear su contexto. Esto permite que una aplicación anule un subconjunto de opciones globales mientras utiliza las opciones globales proporcionadas en el archivo dnsval.conf por defecto.

El campo log_target permite a la aplicación proporcionar destinos de registro *además* de los configurados en el archivo de configuración.

Consulte dnsval.conf(3) para obtener más detalles sobre cómo especificar la política del validador.

Las banderas de consulta predeterminadas se pueden establecer y restablecer para un contexto dado utilizando val_context_setqflags(). Esto permite a una aplicación alterar el procesamiento del validador DNSSEC, mientras sigue teniendo la mayoría de la configuración predeterminada más granular especificada en su archivo de configuración. El parámetro action se puede establecer en una de las siguientes opciones.

VAL_CTX_FLAG_SET
Esta opción hace que el validador establezca la bandera dada como una de las banderas de consulta predeterminadas.
VAL_CTX_FLAG_RESET
Esta opción hace que el validador restablezca la bandera dada si se estableció como una de las banderas de consulta predeterminadas para el contexto.

Las respuestas devueltas por val_resolve_and_check() están disponibles en la lista enlazada *results. Cada respuesta corresponde a un RRset distinto; múltiples RR dentro del RRset forman parte de la misma respuesta. Son posibles múltiples respuestas cuando el type es ns_t_any o ns_t_rrsig.

Los elementos individuales en *results apuntan a listas enlazadas de val_authentication_chain. Los elementos de la cadena de autenticación en val_authentication_chain contienen los RRsets reales devueltos por el servidor de nombres en respuesta a la consulta.

Los valores de resultado de validación devueltos en val_result_chain se pueden convertir a formato ASCII utilizando p_val_status(). Los valores de estado de la cadena de autenticación devueltos en cada elemento de la lista enlazada val_authentication_chain se pueden convertir a formato ASCII utilizando las funciones p_ac_status().

Mientras que algunas aplicaciones como utilidades de solución de problemas de DNSSEC y herramientas de inspección de paquetes pueden examinar elementos individuales de la cadena de autenticación para identificar las razones reales del error de validación, la mayoría de las aplicaciones solo estarán interesadas en un único código de error para determinar la autenticidad de los datos.

val_isvalidated() identifica si un valor de estado de resultado de validación dado corresponde a una respuesta que fue verificada y validada criptográficamente utilizando un ancla de confianza configurada localmente.

val_istrusted() identifica si un valor de estado del validador dado es confiable. Una respuesta puede ser confiable localmente sin ser validada.

val_does_not_exist() identifica si un valor de estado del validador dado corresponde a uno de los tipos de no existencia.

La biblioteca libval asigna memoria internamente para *results y esta debe ser liberada por la aplicación que la invoca utilizando la interfaz free_result_chain().

ESTRUCTURAS DE DATOS

struct val_result_chain
struct val_result_chain
{
    val_status_t                     val_rc_status;
    char                            *val_rc_alias;
    struct val_rrset_rec            *val_rc_rrset;
    struct val_authentication_chain *val_rc_answer;
    int                              val_rc_proof_count;
    struct val_authentication_chain *val_rc_proofs[MAX_PROOFS];
    struct val_result_chain         *val_rc_next;
};
val_rc_answer
Cadena de autenticación para un RRset dado.
val_rc_next
Puntero al siguiente RRset en el conjunto de respuestas devueltas para una consulta.
val_rc_proofs
Puntero a las cadenas de autenticación para cualquier prueba de no existencia que se haya devuelto para la consulta.
val_rc_proof_count
Número de elementos de prueba almacenados en val_rc_proofs. El número no puede exceder MAX_PROOFS.
val_rc_alias
Para un elemento val_result_chain que apunta a un alias de nombre, este campo contiene el valor de destino.
val_rc_rrset
Para un elemento val_result_chain que contiene un campo val_rc_answer válido (no NULL), el campo val_rc_rrset apunta al elemento val_rrset_rec de nivel superior en la cadena de autenticación val_rc_answer.
val_rc_status
Estado de validación para un RRset dado. Puede ser uno de los siguientes:
VAL_SUCCESS
Respuesta recibida y validada con éxito.
VAL_NONEXISTENT_NAME
El nombre no estaba presente y se devolvió una prueba válida de no existencia que confirma el nombre faltante (alcance NSEC o NSEC3). Los componentes de la prueba también se validaron individualmente.
VAL_NONEXISTENT_TYPE
El tipo no existe para el nombre y se devolvió una prueba válida de no existencia que confirma el nombre faltante. Los componentes de la prueba también se validaron individualmente.
VAL_NONEXISTENT_NAME_NOCHAIN
El nombre no estaba presente y se devolvió una prueba válida de no existencia que confirma el nombre faltante. Los componentes de la prueba también se identificaron como confiables, pero no se validaron individualmente.
VAL_NONEXISTENT_TYPE_NOCHAIN
El tipo no existe para el nombre y se devolvió una prueba válida de no existencia que confirma el nombre faltante (alcance NSEC o NSEC3). Los componentes de la prueba también se identificaron como confiables, pero no se validaron individualmente.
VAL_PINSECURE
Se sabía que el registro o algún ancestro del registro en la cadena de autenticación hacia el ancla de confianza era demostrablemente inseguro.
VAL_PINSECURE_UNTRUSTED
Se sabía que el registro o algún ancestro del registro en la cadena de autenticación hacia el ancla de confianza era demostrablemente inseguro. Pero la condición demostrablemente insegura se configuró como no confiable.
VAL_BARE_RRSIG
No se pudo realizar la validación DNSSEC, la consulta era para un RRSIG.
VAL_IGNORE_VALIDATION
La política local se configuró para ignorar la validación para la zona de la que se recibieron estos datos.
VAL_UNTRUSTED_ZONE
La política local se configuró para rechazar cualquier dato recibido de la zona dada.
VAL_OOB_ANSWER
La respuesta se obtuvo utilizando algún método fuera de banda (Out Of Band), como un archivo de configuración local.
VAL_BOGUS
La respuesta no pudo ser validada debido a fallos en la verificación de firmas o a la incapacidad de verificar pruebas en la cadena de autenticación.
VAL_DNS_ERROR
Se encontró algún error durante el procesamiento de DNS.
VAL_INDETERMINATE
La respuesta no pudo ser validada debido a metadatos DNSSEC faltantes.
VAL_NOTRUST
Todos los componentes disponibles en la cadena de autenticación se verificaron correctamente, pero no hubo un ancla de confianza disponible.

Los valores de estado en val_status_t devueltos por el validador se pueden mostrar en formato ASCII usando p_val_status().

struct val_authentication_chain
struct val_authentication_chain
{
    val_astatus_t                    val_ac_status;
    struct val_rrset_rec                *val_ac_rrset;
    struct val_authentication_chain *val_ac_trust;
};
val_ac_status
Estado de validación del elemento de la cadena de autenticación. Este campo contendrá el código de estado para el componente dado en la cadena de autenticación. Este campo puede contener uno de los siguientes valores:
VAL_AC_UNSET
El estado no pudo ser determinado.
VAL_AC_IGNORE_VALIDATION
La validación del registro de recursos dado fue ignorada, ya sea debido a alguna directiva de política local o debido a algún comportamiento específico del protocolo.
VAL_AC_UNTRUSTED_ZONE
La política local definió una zona dada como no confiable, sin que se considerara necesaria ninguna validación adicional.
VAL_AC_PINSECURE
La cadena de autenticación desde un ancla de confianza hasta una zona dada no pudo ser construida debido a la ausencia demostrable de un registro DS para esta zona en el padre.
VAL_AC_BARE_RRSIG
La respuesta fue para una consulta de tipo RRSIG. Los RRSIGs contienen las firmas criptográficas para otros datos DNS y no pueden ser validados por sí mismos.
VAL_AC_NO_LINK
No había un ancla de confianza configurada para una cadena de autenticación dada o la cadena no se enlazó.
VAL_AC_TRUST
Al menos una de las firmas que cubrían el conjunto de registros DNSKEY dado se verificó directamente usando una clave configurada como ancla de confianza DNSSEC.
VAL_AC_RRSIG_MISSING
No se pudieron recuperar los datos RRSIG para un registro de recursos.
VAL_AC_DNSKEY_MISSING
No se pudo recuperar el DNSKEY para un RRSIG que cubría un registro de recursos.
VAL_AC_DS_MISSING
No estaba disponible el registro DS que cubría un registro DNSKEY.
VAL_AC_DATA_MISSING
No se devolvieron datos para una consulta y el DNS no indicó un error.
VAL_AC_DNS_ERROR
Se encontró algún error durante el procesamiento de DNS.
VAL_AC_NOT_VERIFIED
No se pudieron verificar todos los RRSIG que cubrían el conjunto de registros.
VAL_AC_VERIFIED
Al menos un RRSIG que cubría un registro de recursos tenía un estado de VAL_AC_RRSIG_VERIFIED.
val_ac_rrset
Puntero a un conjunto de registros de tipo struct val_rrset_rec obtenido de la respuesta DNS.
val_ac_trust
Puntero a un elemento de la cadena de autenticación que contiene un conjunto de registros DNSKEY que se puede usar para verificar RRSIGs sobre el registro actual, o contiene un conjunto de registros DS que se puede usar para construir la cadena de confianza hacia un ancla de confianza.

val_rrset_rcode
El rcode en la cabecera de respuesta para este conjunto de registros.
val_rrset_name
Nombre del propietario del conjunto de registros.
val_rrset_class
Clase del conjunto de registros.

TTL del conjunto de registros.

Sección en la que se recibió el conjunto de registros. Este valor puede ser VAL_FROM_ANSWER, VAL_FROM_AUTHORITY, o VAL_FROM_ADDITIONAL.

struct val_rr_rec
struct val_rr_rec
{
    size_t            rr_rdata_length;
    unsigned char     *rr_rdata;
    struct val_rr_rec *rr_next;
    val_astatus_t     rr_status;
};
rr_rdata_length_h
Longitud de los datos almacenados en rr_rdata.
rr_rdata
Bytes RDATA.
rr_status
Para cada miembro val_rr_rec de firma dentro del conjunto de registros de autenticación val_ac_rrset, el estado de validación almacenado en la variable rr_status puede devolver uno de los siguientes valores: 
VAL_AC_RRSIG_VERIFIED
    El RRSIG se verificó correctamente.
VAL_AC_WCARD_VERIFIED
    Un RRSIG dado que cubre un registro de recursos muestra
    que el registro fue expandido por comodín.
VAL_AC_RRSIG_VERIFIED_SKEW
    El RRSIG se verificó correctamente después de tener en cuenta
    el desfase horario.
VAL_AC_WCARD_VERIFIED_SKEW
    Un RRSIG dado que cubre un registro de recursos muestra que
    el registro fue expandido por comodín, pero solo se verificó
    después de tener en cuenta el desfase horario.
VAL_AC_WRONG_LABEL_COUNT
    El número de etiquetas en la firma fue mayor
    que el recuento dado en el RDATA del RRSIG.
VAL_AC_INVALID_RRSIG
    El RRSIG no pudo ser analizado.
VAL_AC_RRSIG_NOTYETACTIVE

REGISTRO

libval proporciona la función val_log_add_optarg() para controlar la verbosidad y la ubicación de la salida de los mensajes de registro.

La función val_log_add_optarg() toma dos argumentos: el primer argumento args es un valor de cadena de caracteres que especifica la ubicación y la verbosidad. El segundo argumento, use_stderr, si se establece en un valor mayor que 0, permite a libval enviar mensajes de registro a stderr.

La cadena de caracteres que especifica la ubicación y la verbosidad del destino del registro tiene un formato específico:

<nivel-depuracion>:<tipo-destino>[:<opciones-destino>]

donde
<nivel-depuracion> es 1-7, para niveles crecientes de verbosidad
<tipo-destino> es uno de file, net, syslog, stderr, stdout
<opciones-destino> depende de <tipo-destino>
file:<nombre-archivo> (abierto en modo de adición)
net[:<nombre-host>:<puerto-host>] (127.0.0.1:1053)
syslog[:facility] (0-23 (predeterminado 1 USER))

Los niveles de registro se pueden traducir aproximadamente en diferentes tipos de mensajes de registro de la siguiente manera (los mensajes devueltos para cada nivel en esta lista subsumen los mensajes devueltos para el nivel superior):

3 : Error   : error encontrado
4 : Warning : recuperándose de un error
5 : Notice  : proporciona resultados de validación finales para una consulta
              y detalles sobre archivos de políticas y etiquetas utilizadas
6 : Info    : proporciona d

NAME

libval - validation library for DNSSEC

SYNOPSIS

#include <libval/libval.h>
#include <libval/log.h>
#include <libval/val.h>

DESCRIPTION

The libval library provides a framework for validating DNSSEC information.

It supports various validation mechanisms and data structures.

DATA STRUCTURES

The library defines structures for handling validation context, policies, and results.

Key structures include:

val_context
Represents the validation context, holding configuration and state.
val_policy
Defines a validation policy.
val_result
Stores the outcome of a validation operation.

LOGGING

The library provides a logging mechanism with different severity levels. Log messages can be directed to standard output, standard error, or syslog.

The following logging levels are available:

VAL_LOG_EMERG
Emergency: system is unusable.
VAL_LOG_ALERT
Alert: action must be taken immediately.
VAL_LOG_CRIT
Critical: critical conditions.
VAL_LOG_ERR
Error: error conditions.
VAL_LOG_WARNING
Warning: warning conditions.
VAL_LOG_NOTICE
Notice: normal but significant condition.
VAL_LOG_INFO
Informational: informational messages.
VAL_LOG_DEBUG
Debug: debug-level information.

Functions like val_log_init(), val_log_set_level(), and val_log() can be used to manage and generate log messages.

The validation library reads configuration information from two files, resolv.conf and dnsval.conf.

See dnsval.conf(5) for a description of the syntax for these files.

Details on authentication chains:

7 : Debug   : gives debug level information

RETURN VALUES

Return values for various functions are given below. These values can be displayed in ASCII format using the p_val_error() function.

VAL_NO_ERROR
No error was encountered.
VAL_NOT_IMPLEMENTED
Functionality not yet implemented.
VAL_RESOURCE_UNAVAILABLE
Some resource (crypto possibly) was unavailable. Currently not implemented.
VAL_BAD_ARGUMENT
Bad arguments passed as parameters.
VAL_INTERNAL_ERROR
Encountered some internal error.
VAL_NO_PERMISSION
No permission to perform operation. Currently not implemented.
VAL_CONF_PARSE_ERROR
Error in parsing some configuration file.
VAL_CONF_NOT_FOUND
A configuration file was not available.
VAL_NO_POLICY
The policy identifier being referenced was invalid.
