DESCRIPCIÓN

BIO_ctrl(), BIO_callback_ctrl(), BIO_ptr_ctrl(), y BIO_int_ctrl() son operaciones de "control" de BIO que toman argumentos de varios tipos. Estas funciones normalmente no se llaman directamente; en su lugar, se utilizan varias macros. Las macros estándar se describen a continuación. Las macros específicas de un tipo de BIO determinado se describen en la página del manual del BIO específico, así como cualquier característica especial de las llamadas estándar.

Dependiendo del cmd y del tipo de b, BIO_ctrl() puede tener un efecto de solo lectura en b o cambiar datos en b o en sus subestructuras. También puede tener un efecto secundario de cambiar la memoria a la que apunta parg.

BIO_callback_ctrl() no llama a BIO_ctrl() sino que requiere que el tipo de BIO de b proporcione un puntero de función callback_ctrl dedicado, que está integrado en la biblioteca para algunos tipos de BIO estándar y puede proporcionarse con BIO_meth_set_callback_ctrl(3) para tipos de BIO definidos por la aplicación. El único cmd soportado por BIO_callback_ctrl() es BIO_CTRL_SET_CALLBACK.

BIO_ptr_ctrl() llama a BIO_ctrl() con parg apuntando a la ubicación de una variable de puntero temporal inicializada a NULL.

BIO_int_ctrl() llama a BIO_ctrl() con parg apuntando a la ubicación de una variable temporal int inicializada a iarg. Si BIO_ctrl() cambia el valor almacenado en *parg, el nuevo valor se ignora.

BIO_reset() normalmente reinicia un BIO a un estado inicial. En el caso de BIOs relacionados con archivos, por ejemplo, rebobina el puntero de archivo al inicio del archivo.

BIO_seek() restablece el puntero de posición de archivo de un BIO relacionado con archivos (es decir, BIOs de descriptor de archivo y FILE) a ofs bytes desde el inicio del archivo.

BIO_tell() devuelve la posición actual del archivo de un BIO relacionado con archivos.

BIO_flush() normalmente escribe cualquier dato almacenado en búfer interno. En algunos casos, se utiliza para señalar EOF (fin de archivo) y que no se escribirán más datos.

BIO_eof() devuelve 1 si el BIO ha leído EOF. El significado preciso de "EOF" varía según el tipo de BIO.

BIO_set_close() establece la bandera de cierre del BIO b a flag. flag puede tomar el valor BIO_CLOSE o BIO_NOCLOSE. Típicamente, BIO_CLOSE se utiliza en un BIO de origen/destino para indicar que el flujo de E/S subyacente debe cerrarse cuando se libera el BIO.

BIO_get_close() devuelve la bandera de cierre del BIO.

BIO_pending(), BIO_ctrl_pending(), BIO_wpending(), y BIO_ctrl_wpending() devuelven el número de caracteres pendientes en los búferes de lectura y escritura del BIO. No todos los BIOs soportan estas llamadas. BIO_ctrl_pending() y BIO_ctrl_wpending() devuelven un tipo size_t y son funciones.

BIO_set_info_callback() instala el puntero de función cb como una devolución de llamada de información en b llamando a BIO_callback_ctrl() con un comando de BIO_CTRL_SET_CALLBACK. Entre los tipos de BIO integrados en la biblioteca, solo BIO_s_c

onnect(3) y BIO_f_ssl(3) dan soporte a esta funcionalidad. Algunos tipos de BIO de filtro reenvían esta llamada de control al siguiente BIO en la cadena en lugar de procesarla ellos mismos.

BIO_get_info_callback() coloca el puntero de función al callback de información en *cbp si se instaló alguno usando BIO_set_info_callback() o BIO_callback_ctrl(). Si el tipo de b soporta la configuración de un callback de información pero no se instaló ninguno, almacena un puntero NULL en *cbp.

El nombre del tipo de función bio_info_cb es un sinónimo obsoleto de BIO_info_cb proporcionado para compatibilidad con versiones anteriores con cierto software de aplicación existente.

DESCRIPTION

The BIO interface provides functions to perform I/O operations. There are various types of BIOs, each performing a different kind of I/O. The functions described here are control operations that can be performed on many of these BIO types. The BIO_ctrl() function is the most general of these.

The cmd argument specifies the control operation to perform. The larg and parg arguments are arguments for the control operation, and their type and meaning depend on the specific cmd.

RETURN VALUES

The meaning of the return values of BIO_ctrl(), BIO_callback_ctrl(), and BIO_int_ctrl() depends on both the type of b and on the cmd. If b is a NULL pointer, no action occurs and 0 is returned. The return value -2 usually indicates a fatal error. In particular, it is returned if the cmd is unsupported by the type of b.

BIO_callback_ctrl() and BIO_set_info_callback() return 1 on success, 0 if b is NULL or to indicate failure of a valid cmd, or -2 if the cmd is not supported by b.

BIO_ptr_ctrl() returns NULL if the BIO_ctrl() call returns a negative value or does not change *parg, or the pointer it puts into *parg otherwise.

BIO_int_ctrl() returns the return value of BIO_ctrl().

BIO_reset() normally returns 1 for success and 0 or -1 for failure. File BIOs are an exception, returning 0 for success and -1 for failure.

BIO_seek() and BIO_tell() both return the current file position on success and -1 for failure, except file BIOs which for BIO_seek() always return 0 for success and -1 for failure.

BIO_flush() returns 1 for success and 0 or -1 for failure.

BIO_eof() returns 1 if EOF has been reached or 0 otherwise.

BIO_set_close() always returns 1.

BIO_get_close() returns the close flag value BIO_CLOSE or BIO_NOCLOSE.

BIO_pending(), BIO_ctrl_pending(), BIO_wpending(), and BIO_ctrl_wpending() return the amount of pending data.

BIO_get_info_callback() returns 1 on success, including when the type of b supports an info callback but none is installed, 0 if b is NULL or -2 if the type of b does not support an info callback.

If a callback was installed in b using BIO_set_callback_ex(3) or BIO_set_callback(3), it can modify the return values of all these functions.

NOTES

Because it can write data, BIO_flush() may return 0 or -1 indicating that the call should be retried later in a similar manner to BIO_write(3). The BIO_should_retry(3) call should be used and appropriate action taken if the call fails.

The return values of BIO_pending() and BIO_wpending() may not reliably determine the amount of pending data in all cases. For example in the case of a file BIO some data may be available in the FILE structure's internal buffers but it is not possible to determine this in a portable way. For other types of BIO they may not be supported.

If they do not internally handle a particular BIO_ctrl() operation, filter BIOs usually pass the operation to the next BIO in the chain. This often means there is no need to locate the required BIO for a particular operation: it can be called on a chain and it will be automatically passed to the relevant BIO. However, this can cause unexpected results. For example no current filter BIOs implement BIO_seek(), but this may still succeed if the chain ends in a FILE or file descriptor BIO.

Source/sink BIOs return a 0 if they do not recognize the BIO_ctrl() operation.

HISTORY

BIO_ctrl(), BIO_reset(), BIO_flush(), BIO_eof(), BIO_set_close(), BIO_get_close(), BIO_pending(), and BIO_wpending() were first introduced in OpenSSL 0.9.7.

BIO_seek() and BIO_tell() were added in OpenSSL 1.0.0.

BIO_callback_ctrl(), BIO_ptr_ctrl(), and BIO_int_ctrl() were added in OpenSSL 1.1.0.

BIO_set_callback(), BIO_get_callback(), BIO_set_callback_ex(), BIO_get_callback_ex(), BIO_set_info_callback(), and BIO_get_info_callback() were added in OpenSSL 1.1.0.

BIO_reset_ex() and BIO_truncate() were added in OpenSSL 3.0.

e>(), y BIO_pending() aparecieron por primera vez en SSLeay 0.6.0. BIO_wpending() apareció por primera vez en SSLeay 0.8.1. BIO_ptr_ctrl(), BIO_int_ctrl(), BIO_get_info_callback() y BIO_set_info_callback() aparecieron por primera vez en SSLeay 0.9.0. Todas estas funciones han estado disponibles desde OpenBSD 2.4.

BIO_seek() y BIO_tell() aparecieron por primera vez en SSLeay 0.9.1. BIO_ctrl_pending() y BIO_ctrl_wpending() aparecieron por primera vez en OpenSSL 0.9.4. Estas funciones han estado disponibles desde OpenBSD 2.6.

BIO_callback_ctrl() apareció por primera vez en OpenSSL 0.9.5 y ha estado disponible desde OpenBSD 2.7.

bio_info_cb() apareció por primera vez con un prototipo más complicado en OpenSSL 0.9.6 y ha estado disponible desde OpenBSD 2.9.

BIO_info_cb() apareció por primera vez en OpenSSL 1.1.0h y ha estado disponible desde OpenBSD 6.3.

BUGS

Algunos de los valores de retorno son ambiguos y se debe tener cuidado. En particular, un valor de retorno de 0 puede ser devuelto si una operación no es soportada, si ocurrió un error, si no se alcanzó el final del archivo y en el caso de BIO_seek() en un BIO de archivo para una operación exitosa.
