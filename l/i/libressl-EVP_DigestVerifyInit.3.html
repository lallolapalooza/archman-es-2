EVP_DIGESTVERIFYINIT(3) Manual de Funciones de Biblioteca EVP_DIGESTVERIFYINIT(3)

NOMBRE

EVP_DigestVerifyInit, EVP_DigestVerifyUpdate, EVP_DigestVerifyFinal, EVP_DigestVerify — funciones de verificación de firmas EVP

SINOPSIS

biblioteca “libcrypto”;
#include <openssl/evp.h>

int
EVP_DigestVerifyInit(EVP_MD_CTX *ctx, EVP_PKEY_CTX **pctx, const EVP_MD *type, ENGINE *engine, EVP_PKEY *pkey);

int
EVP_DigestVerifyUpdate(EVP_MD_CTX *ctx, const void *d, size_t cnt);

int
EVP_DigestVerifyFinal(EVP_MD_CTX *ctx, const unsigned char *sig, size_t siglen);

int
EVP_DigestVerify(EVP_MD_CTX *ctx, const unsigned char *sig, size_t siglen, const unsigned char *tbs, size_t *tbslen);

DESCRIPCIÓN

Las rutinas de firma EVP son una interfaz de alto nivel para firmas digitales.

EVP_DigestVerifyInit() configura el contexto de verificación ctx para usar el resumen type y la clave pública pkey. Antes de llamar a esta función, obtenga ctx de EVP_MD_CTX_new(3) o llame a EVP_MD_CTX_reset(3) en él. El argumento engine se ignora siempre y se recomienda pasar NULL.

Si pctx no es NULL, cualquier puntero pasado como *pctx se ignora y se sobrescribe con un puntero interno al EVP_PKEY_CTX utilizado por la operación de verificación: esto se puede usar para establecer opciones de firma alternativas. La EVP_PKEY_CTX devuelta no debe ser liberada por la aplicación. Se libera automáticamente cuando se libera la EVP_MD_CTX.

EVP_DigestVerifyUpdate() resume cnt bytes de datos en d en el contexto de verificación ctx. Esta función se puede llamar varias veces en la misma ctx para incluir datos adicionales. Esta función está implementada actualmente usando una macro.

EVP_DigestVerifyFinal() verifica los datos en ctx contra la firma en sig de longitud siglen.

EVP_DigestVerify() verifica tbslen bytes en tbs contra la firma en sig de longitud siglen. EVP_DigestVerify() es una operación de un solo uso que verifica un solo bloque de datos en una llamada a función. Para algoritmos que soportan streaming, es equivalente a llamar a EVP_DigestVerifyUpdate() y EVP_DigestVerifyFinal().

La interfaz EVP para firmas digitales casi siempre debería usarse en lugar de las interfaces de bajo nivel. Esto se debe a que el código se vuelve transparente al algoritmo utilizado y mucho más flexible.

La llamada a EVP_DigestVerifyFinal() finaliza internamente una copia del contexto de resumen. Esto significa que EVP_VerifyUpdate(3) y EVP_VerifyFinal(3) se pueden llamar más tarde para resumir y verificar datos adicionales.

Dado que solo se finaliza una copia del contexto de resumen, el contexto debe limpiarse después de su uso llamando a EVP_MD_CTX_free(3) o se producirá una fuga de memoria.

VALORES DE RETORNO

EVP_DigestVerifyInit() y EVP_DigestVerifyUpdate() devuelven 1 en caso de éxito y 0 en caso de fallo.

EVP_DigestVerifyFinal() y EVP_DigestVerify() devuelven 1 en caso de éxito; cualquier otro valor indica un fallo. Un valor de retorno de 0 indica que la firma no se verificó correctamente (es decir, la firma no coincidía con los datos originales o la firma tenía un formato inválido), mientras que otros valores indican un error más grave (y a veces también indican un formato de firma inválido).

Los códigos de error se pueden obtener de ERR_get_error(3).

VER TAMBIÉN

evp(3), EVP_DigestInit(3), EVP_DigestSignInit(3)

HISTORIA

EVP_DigestVerifyInit(), EVP_DigestVerifyUpdate(), y EVP_DigestVerifyFinal() aparecieron por primera vez en OpenSSL 1.0.0 y han estado disponibles desde OpenBSD 4.9.

EVP_DigestVerify() apareció por primera vez en OpenSSL 1.1.1 y ha estado disponible desde OpenBSD 7.0.
