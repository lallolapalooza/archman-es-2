DESCRIPCIÓN

UI significa Interfaz de Usuario (User Interface), y es un conjunto de rutinas de propósito general para solicitar al usuario información en texto. A través de métodos escritos por el usuario (ver UI_create_method(3)), la solicitud se puede hacer de cualquier manera imaginable, ya sea mediante solicitudes de texto plano, a través de cuadros de diálogo o desde un teléfono móvil.

Todas las funciones operan a través de un contexto de tipo UI. Este contexto contiene toda la información necesaria para solicitar correctamente, así como una referencia a un UI_METHOD, que es un vector ordenado de funciones que llevan a cabo la solicitud real.

Lo primero que hay que hacer es crear un UI con UI_new() o UI_new_method(), luego añadirle información con las funciones UI_add_*() o UI_dup_*(). Además, los datos aleatorios definidos por el usuario se pueden pasar al método subyacente a través de llamadas a UI_add_user_data(). El método UI por defecto no se ocupa de estos datos, pero otros métodos sí podrían hacerlo. Finalmente, usa UI_process() para realizar realmente la solicitud y UI_get0_result() para encontrar el resultado de la solicitud.

Una UI puede contener más de una solicitud, que se realizan en la secuencia dada. Cada solicitud recibe un número de índice que es devuelto por las funciones UI_add_*() y UI_dup_*(), y que debe usarse para obtener el resultado correspondiente con UI_get0_result().

Las funciones son las siguientes:

UI_new() crea una nueva UI utilizando el método UI por defecto. Cuando se haya terminado con esta UI, debe liberarse usando UI_free().

UI_new_method() crea una nueva UI utilizando el método UI dado. Cuando se haya terminado con esta UI, debe liberarse usando UI_free().

UI_free() libera la UI ui.

UI_add_input_string() y UI_dup_input_string() añaden una solicitud de cadena de caracteres. El texto de la solicitud es prompt. El resultado se almacena en result_buf, que debe ser lo suficientemente grande para almacenar hasta maxsize caracteres (incluyendo el carácter nulo final). Si result_buf es NULL, entonces se asigna memoria para él. El tamaño mínimo aceptable es minsize y el máximo es maxsize. Si minsize es 0, no se impone un tamaño mínimo. Las banderas flags pueden ser UI_INPUT_FLAG_ECHO (ver entrada de terminal) o UI_INPUT_FLAG_DEFAULT_PWD (para preguntas de contraseña donde la contraseña se puede obtener de forma segura). Las funciones UI_dup_*() duplican las cadenas de caracteres pasadas como argumentos, mientras que las funciones UI_add_*() las utilizan directamente. Usar las funciones UI_dup_*() es generalmente más seguro.

UI_add_verify_string() y UI_dup_verify_string() son similares a las funciones UI_add_input_string() y UI_dup_input_string(), pero además requieren un argumento test_buf. El valor introducido por el usuario se compara con test_buf. Si no coinciden, se vuelve a solicitar la entrada. El valor introducido (si coincide) se almacena en result_buf.

UI_add_input_boolean() y UI_dup_input_boolean() añaden una solicitud booleana. El usuario debe responder con uno de los caracteres en ok_chars (para sí) o cancel_chars (para no). El parámetro action_desc describe la acción que se está realizando. El resultado se almacena en result_buf. El valor almacenado será 'y' o 'n', o caracteres de ok_chars o cancel_chars si estos son diferentes. Las banderas flags son las mismas que para UI_add_input_string().

UI_add_info_string() y UI_dup_info_string() añaden una cadena de información. Esto se utiliza para mostrar mensajes informativos al usuario. No requieren ninguna entrada del usuario.

UI_add_error_string() y UI_dup_error_string() añaden una cadena de error. Esto se utiliza para mostrar mensajes de error al usuario. No requieren ninguna entrada del usuario.

UI_construct_prompt() es una función de ayuda para construir cadenas de solicitud para UI_add_input_string() y funciones similares. Toma un contexto de método UI, una descripción del objeto y el nombre del objeto, y devuelve una cadena de solicitud construida. El llamador es responsable de liberar la cadena devuelta usando OPENSSL_free().

UI_add_user_data() asocia datos definidos por el usuario con la estructura UI. Estos datos se pueden recuperar más tarde usando UI_get0_user_data().

UI_get0_user_data() devuelve los datos de usuario asociados con la estructura UI.

UI_get0_result() devuelve el resultado de la solicitud con el índice i. Los resultados son cadenas de caracteres terminadas en nulo. Devuelve NULL si no hay ningún resultado para el índice dado.

UI_process() inicia el proceso de solicitud de usuario. Las solicitudes se procesan en el orden en que se añadieron. Devuelve 1 con éxito, 0 si se canceló la operación y -1 en caso de error.

UI_ctrl() es una interfaz genérica para controlar el comportamiento de la UI. Los comandos disponibles actualmente son UI_CTRL_PRINT_ERRORS y UI_CTRL_IS_REDOABLE.

UI_set_default_method() establece el método UI por defecto que se utilizará cuando se llame a UI_new().

UI_get_default_method() devuelve el método UI por defecto actual.

UI_get_method() devuelve el método UI actualmente asociado con la estructura UI. Tenga en cuenta que el puntero devuelto no debe liberarse.

UI_set_method() establece el método UI para la estructura UI. Devuelve el método UI anterior. El método UI especificado no debe liberarse; debe ser un puntero estático o uno que no sea propiedad del llamador.

UI_OpenSSL() devuelve un puntero a un método UI predefinido que proporciona una interfaz de usuario simple basada en texto.

UI_null() devuelve un puntero a un método UI que no hace nada. Se puede utilizar para desactivar las solicitudes de usuario.

VALORES DE RETORNO

UI_new() y UI_new_method() devuelven un puntero a una estructura UI en caso de éxito, o NULL en caso de error.

UI_add_*(), UI_dup_*(), UI_add_user_data(), UI_construct_prompt() y UI_process() devuelven 1 en caso de éxito, y 0 o -1 en caso de error.

UI_get0_user_data() devuelve el puntero a los datos de usuario.

UI_get0_result() devuelve un puntero a la cadena de resultado.

UI_ctrl() devuelve 1 si el comando se reconoce y se ejecuta correctamente, y 0 en caso contrario.

UI_set_method() devuelve el puntero al método UI anterior.

UI_get_default_method(), UI_get_method(), UI_set_default_method(), UI_set_method(), UI_OpenSSL() y UI_null() devuelven punteros a estructuras UI_METHOD.

VER TAMBIÉN

UI_create_method(3)

UI_free()

UI_free() libera la estructura ui de la memoria, junto con todas las demás piezas de memoria que estén conectadas a ella, como cadenas de entrada duplicadas, resultados y otros. Si ui es un puntero NULL, no se realiza ninguna acción.

UI_OpenSSL() devuelve el método de interfaz de usuario incorporado (nota: no necesariamente el predeterminado, ya que el predeterminado puede cambiarse. Ver más adelante). Este método es la parte más dependiente de la máquina/sistema operativo de OpenSSL y normalmente genera la mayoría de los problemas al portar.

UI_null() devuelve un método de interfaz de usuario que no hace nada. Su uso es evitar obtener valores predeterminados internos para punteros UI_METHOD pasados.

UI_add_input_string() y UI_add_verify_string() agregan un prompt a ui, así como flags y un buffer de resultado, y los tamaños mínimo y máximo deseados del resultado, sin contar el carácter NUL final. La información dada se utiliza para solicitar información, por ejemplo, una contraseña, y para verificar una contraseña (es decir, tener al usuario ingresarla dos veces y verificar que se ingresó la misma cadena dos veces). UI_add_verify_string() toma un argumento adicional que debe ser un puntero al buffer de resultado de la cadena de entrada que se supone que debe verificar, o la verificación fallará.

UI_add_input_boolean() agrega un prompt a ui que se supone que debe responderse de forma booleana, con un solo carácter para sí y un carácter diferente para no. También se proporciona un conjunto de caracteres que se pueden usar para cancelar el prompt. El prompt en sí está realmente dividido en dos partes, una parte es el texto descriptivo (proporcionado a través del argumento prompt) y otra que describe las respuestas posibles (proporcionada a través del argumento action_desc).

UI_add_info_string() y UI_add_error_string() agregan cadenas que se muestran al mismo tiempo que el prompt para información adicional o para mostrar una cadena de error. La diferencia entre las dos es solo conceptual. Con el método incorporado, no hay diferencia técnica entre ellas. Sin embargo, otros métodos pueden marcar una diferencia entre ellas.

Los flags compatibles actualmente son UI_INPUT_FLAG_ECHO, que es relevante para UI_add_input_string() y hará que la respuesta del usuario sea mostrada (al solicitar una contraseña, este flag obviamente no debe usarse), y UI_INPUT_FLAG_DEFAULT_PWD, lo que significa que se utilizará una contraseña predeterminada de algún tipo (dependiendo completamente de la aplicación y del método de UI).

UI_dup_input_string(), UI_dup_verify_string(), UI_dup_input_boolean(), UI_dup_info_string(), y UI_dup_error_string() son básicamente lo mismo que sus contrapartes UI_add_*(), excepto que hacen sus propias copias de todas las cadenas.

UI_construct_prompt() es una función de ayuda que se puede utilizar para crear un prompt a partir de dos piezas de información: una descripción y un nombre. El constructor predeterminado (si el método utilizado no proporciona ninguno) crea una cadena "Enter description for name:". Con la descripción "pass phrase" y el nombre de archivo "foo.key", esto se convierte en "Enter pass phrase for foo.key:". Otros métodos pueden crear cualquier cadena y pueden incluir codificaciones que serán procesadas por las otras funciones del método.

UI_add_user_data() agrega un puntero de datos de usuario para que el método lo use en cualquier momento. El método de interfaz de usuario incorporado no se preocupa por esta información. Tenga en cuenta que varias llamadas a esta función no agregan datos; el blob anterior es reemplazado por el proporcionado como argumento.

UI_get0_user_data() recupera los datos que se le proporcionaron por última vez a ui con UI_add_user_data().

UI_get0_result() devuelve un puntero al buffer de resultado asociado con la información indexada por i.

UI_process() revisa la información proporcionada hasta el momento, realiza todas las impresiones y prompts, y devuelve el estado final, que es -2 en eventos fuera de banda (Interrupción, Cancelación, ...), -1 en caso de error, o 0 en caso de éxito.

UI_ctrl() agrega control adicional para el autor de la aplicación. Por ahora, entiende dos comandos: UI_CTRL_PRINT_ERRORS, que hace que UI_process() imprima la pila de errores de OpenSSL como parte del procesamiento de ui, y UI_CTRL_IS_REDOABLE, que devuelve un flag que indica si el ui

UI_set_default_method() cambia el método de interfaz de usuario predeterminado al proporcionado. Esta función no es segura para hilos y no debe llamarse al mismo tiempo que otras funciones de OpenSSL.

UI_get_default_method() devuelve un puntero al método de interfaz de usuario predeterminado actual.

UI_get_method() devuelve el método de interfaz de usuario asociado con un ui dado.

UI_set_method() cambia el método de interfaz de usuario asociado con un ui dado.

VALORES DE RETORNO

UI_new() y UI_new_method() devuelven una estructura UI válida o NULL si ocurrió un error.

UI_add_input_string(), UI_dup_input_string(), UI_add_verify_string(), UI_dup_verify_string(), UI_add_input_boolean(), UI_dup_input_boolean(), UI_add_info_string(), UI_dup_info_string(), UI_add_error_string(), y UI_dup_error_string() devuelven un número positivo en caso de éxito o un número menor o igual a cero en caso contrario.

UI_construct_prompt() y UI_get0_result() devuelven una cadena o NULL si ocurrió un error.

UI_add_user_data() y UI_get0_user_data() devuelven un puntero a los datos de usuario que estaban contenidos en ui antes de la llamada. En particular, NULL es un valor de retorno válido.

UI_process() devuelve 0 en caso de éxito o un valor negativo en caso de error.

UI_ctrl() devuelve una máscara en caso de éxito o -1 en caso de error.

UI_get_default_method(), UI_OpenSSL() y UI_null() siempre devuelven un puntero a una estructura UI_METHOD válida.

UI_get_method() y UI_set_method() devuelven un puntero a la estructura UI_METHOD que está instalada en ui después de la llamada. La documentación de OpenSSL dice que pueden fallar y devolver NULL, pero actualmente, esto solo puede ocurrir cuando y después de que UI_set_method() se llama con un argumento explícito NULL.

DESCRIPTION

These functions provide a generic user interface mechanism. They can be used to prompt the user for various kinds of information, such as passwords, passphrases, etc. The user interface itself is implemented by a UI_METHOD structure. This allows different user interface implementations to be plugged in.

The UI_new() and UI_new_method() functions create a new UI object. The method argument specifies the UI_METHOD to be used. If method is NULL, the default UI_METHOD is used.

The UI_free() function frees the UI object.

The UI_add_user_data() function adds arbitrary user data to the UI object. This data can be retrieved later using UI_get_user_data().

The UI_add_input_string() function adds a prompt for string input to the UI object. The prompt string is displayed to the user, and the input is stored in the buffer. The echoc argument determines whether the input is echoed to the screen. The pail argument is unused.

The UI_get_input_string() function retrieves the string input from the user. The prompt, buffer, size, and echoc arguments are the same as for UI_add_input_string().

The UI_add_input_buffer() function adds a prompt for buffer input to the UI object. The buffer argument is a BUFF object that will store the input.

The UI_get_input_buffer() function retrieves the buffer input from the user.

The UI_add_error_string() function adds an error string to the UI object. This string will be displayed to the user if an error occurs.

The UI_get_error_string() function retrieves the error string from the UI object.

The UI_add_prompt() function adds a prompt to the UI object. The prompt string is displayed to the user, and the selection argument indicates the type of selection to be made.

The UI_get_prompt() function retrieves the prompt from the UI object.

The UI_get_default_method() function returns the default UI_METHOD.

The UI_set_default_method() function sets the default UI_METHOD.

The UI_load_config() function loads UI configuration from a file. The filename argument specifies the configuration file.

The UI_save_config() function saves UI configuration to a file. The filename argument specifies the configuration file.

RETURN VALUES

All functions return 1 on success and 0 on failure.
