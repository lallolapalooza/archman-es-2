DESCRIPCIÓN

OCSP_REQUEST_new() asigna e inicializa un objeto OCSP_REQUEST vacío, que representa una estructura OCSPRequest ASN.1 definida en RFC 6960. OCSP_REQUEST_free() libera req.

OCSP_SIGNATURE_new() asigna e inicializa un objeto OCSP_SIGNATURE vacío, que representa una estructura Signature ASN.1 definida en RFC 6960. Dicho objeto se utiliza dentro de OCSP_REQUEST. OCSP_SIGNATURE_free() libera signature.

OCSP_REQINFO_new() asigna e inicializa un objeto OCSP_REQINFO vacío, que representa una estructura TBSRequest ASN.1 definida en RFC 6960. Dicho objeto se utiliza dentro de OCSP_REQUEST. Pregunta sobre la validez de uno o más certificados. OCSP_REQINFO_free() libera reqinfo.

OCSP_ONEREQ_new() asigna e inicializa un objeto OCSP_ONEREQ vacío, que representa una estructura Request ASN.1 definida en RFC 6960. Dichos objetos se utilizan dentro de OCSP_REQINFO. Cada uno pregunta sobre la validez de un certificado. OCSP_ONEREQ_free() libera onereq.

OCSP_request_add0_id() añade el ID de certificado cid a req. Devuelve el objeto OCSP_ONEREQ añadido para que una aplicación pueda añadir extensiones adicionales a la solicitud. El parámetro cid no debe liberarse después de la operación.

OCSP_request_sign() firma la solicitud OCSP req utilizando el certificado signer, la clave privada key, el digest dgst y los certificados adicionales certs. Si la opción flags OCSP_NOCERTS está establecida, entonces no se incluirán certificados en la solicitud.

OCSP_request_add1_cert() añade el certificado cert a la solicitud req. La aplicación es responsable de liberar cert después de su uso.

OCSP_request_onereq_count() devuelve el número total de objetos OCSP_ONEREQ en req.

OCSP_request_onereq_get0() devuelve un puntero interno al OCSP_ONEREQ contenido en req con el índice i. El valor del índice i va de 0 a OCSP_request_onereq_count(req) - 1.

OCSP_request_onereq_count() y OCSP_request_onereq_get0() son utilizados principalmente por los respondedores OCSP.

VALORES DEVUELTOS

OCSP_REQUEST_new(), OCSP_SIGNATURE_new(), OCSP_REQINFO_new(), y OCSP_ONEREQ_new() devuelven un objeto OCSP_REQUEST, OCSP_SIGNATURE, OCSP_REQINFO, o OCSP_ONEREQ vacío, respectivamente, o NULL si ocurrió un error.

OCSP_request_add0_id() devuelve el objeto OCSP_ONEREQ que contiene cid o NULL si ocurrió un error.

OCSP_request_sign() y OCSP_request_add1_cert() devuelven 1 en caso de éxito o 0 en caso de fallo.

OCSP_request_onereq_count() devuelve el número total de objetos OCSP_ONEREQ en req.

OCSP_request_onereq_get0() devuelve un puntero a un objeto OCSP_ONEREQ o NULL si el valor del índice está fuera de rango.

EJEMPLOS

Crear un objeto OCSP_REQUEST para el certificado cert con el emisor issuer:

OCSP_REQUEST *req;

DESCRIPTION

The OCSP (Online Certificate Status Protocol) protocol is used to query the status of a certificate from a trusted certificate authority (CA). The protocol is described in RFC 6960.

OCSP requests are built using the functions described here.

The basic workflow is:

  1. Create a new OCSP request object using OCSP_REQUEST_new().
  2. For each certificate being queried, create a certificate identifier using OCSP_cert_to_id().
  3. Add the certificate identifier to the request using OCSP_REQUEST_add0_id().
  4. Optionally, add extensions to the request using OCSP_REQUEST_add1_ext() or OCSP_REQUEST_add1_ext_i2d().
  5. Send the request to an OCSP responder. This can be done using OCSP_sendreq_new() or OCSP_sendreq_nbio(). These functions handle the transport layer details and return an OCSP_RESPONSE object.
  6. Free the request object when it is no longer needed using OCSP_REQUEST_free().

OCSP_REQUEST_add0_id() adds a certificate identifier to the request. The caller should not free the cid parameter after this call. Ownership is transferred to the request.

OCSP_REQUEST_print() prints a human-readable representation of the request to the specified BIO. The flags parameter is currently unused.

OCSP_REQUEST_get0_ids() returns a stack of certificate identifiers contained within the request.

OCSP_REQUEST_get0_tbsRequest() returns a pointer to the OCSP_TBSREQUEST structure within the request. This structure contains the actual request data, including the certificate identifiers.

OCSP_basic_add1_status() adds a status entry to a basic OCSP response. The status parameter indicates the certificate status (e.g., V_OCSP_CERTSTATUS_GOOD, V_OCSP_CERTSTATUS_REVOKED, or V_OCSP_CERTSTATUS_UNKNOWN). The reason parameter specifies the reason for revocation if the status is revoked. The thisctx and peer parameters are used for context and verification, and may be NULL.

OCSP_basic_verify() verifies a basic OCSP response against a set of trusted certificates.

OCSP_sendreq_new() and OCSP_sendreq_nbio() send an OCSP request to a responder specified by host and path. The request data is provided in buf and size. OCSP_sendreq_nbio() is the non-blocking version. They return an OCSP_RESPONSE object, or NULL on error. The port and ssl_use parameters control the port and whether to use SSL/TLS.

OCSP_sendreq_free() frees the OCSP_RESPONSE object returned by OCSP_sendreq_new() or OCSP_sendreq_nbio().

OCSP_sendreq_get0_response() returns the basic response from an OCSP_RESPONSE object.

The functions starting with OCSP_REQUEST_get_ext_... and OCSP_REQUEST_add1_ext... are used to manipulate extensions within an OCSP request.

OCSP_REQUEST_get_ext_by_NID() and OCSP_REQUEST_get_ext_by_OBJ() find an extension by its NID or object identifier, respectively. lastpos can be used to iterate through multiple extensions.

OCSP_REQUEST_get_ext() retrieves an extension at a specific position.

OCSP_REQUEST_get_ext_d2i(), OCSP_REQUEST_get_ext_d2i_by_NID(), and OCSP_REQUEST_get_ext_d2i_by_OBJ() retrieve and decode an extension. If crit is non-zero, only critical extensions are searched.

OCSP_REQUEST_add1_ext() adds a new extension to the request. Ownership of value is transferred.

OCSP_REQUEST_delete_ext() deletes an extension at a specific index.

OCSP_REQUEST_add1_ext_i2d() adds a new extension, encoding the provided value.

RETURN VALUES

OCSP_REQUEST_new(), OCSP_REQUEST_add0_id(), OCSP_basic_add1_status(), OCSP_basic_verify(), OCSP_sendreq_new(), OCSP_sendreq_nbio(), OCSP_REQUEST_add1_ext(), and OCSP_REQUEST_add1_ext_i2d() return 1 on success and 0 on failure.

OCSP_REQUEST_free() and OCSP_sendreq_free() do not return a value.

OCSP_REQUEST_print() returns the number of characters written, or a negative value on error.

OCSP_REQUEST_get0_ids() returns a pointer to a stack of OCSP_CERTID objects, or NULL if no IDs are present or an error occurs.

OCSP_REQUEST_get0_tbsRequest() returns a pointer to the OCSP_TBSREQUEST structure, or NULL on error.

OCSP_sendreq_get0_response() returns a pointer to the OCSP_BASICRESP structure, or NULL on error.

The extension retrieval functions return the index of the found extension, or -1 if no matching extension is found or an error occurs.

EXAMPLES

Create a new OCSP request and add a certificate ID:

P_ID *cid;
OCSP_REQUEST *req;

req = OCSP_REQUEST_new();
if (req == NULL)
	/* error */
cid = OCSP_cert_to_id(EVP_sha1(), cert, issuer);
if (cid == NULL)
	/* error */

if (OCSP_REQUEST_add0_id(req, cid) == NULL)
	/* error */

 /* Do something with req, e.g. query responder */

OCSP_REQUEST_free(req);
