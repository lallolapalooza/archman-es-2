DESCRIPCIÓN

Las funciones de utilidad de objetos ASN.1 procesan estructuras ASN1_OBJECT, en adelante denominadas “objetos”. Un objeto representa un OBJECT IDENTIFIER (OID) de ASN.1. La biblioteca mantiene una tabla global interna de objetos. Muchos de estos objetos están integrados en la biblioteca y contenidos en la tabla global por defecto. El programa de aplicación puede añadir objetos adicionales a la tabla global utilizando las funciones documentadas en la página del manual OBJ_create(3). En consecuencia, existen tres clases de objetos: objetos de tabla integrados, objetos de tabla definidos por el usuario y objetos que no están en la tabla.

Además del OID, cada objeto puede contener un nombre largo, un nombre corto y un identificador numérico (NID). Aunque el concepto de NIDs es específico de la biblioteca y no está estandarizado, el uso del NID es a menudo la forma más conveniente para que el código fuente haga referencia a un OID específico. Los NIDs de los objetos integrados están disponibles como constantes definidas.

Los objetos de tabla integrados tienen ciertas ventajas sobre los objetos que no están en la tabla global: por ejemplo, sus NIDs se pueden usar en sentencias `switch` del lenguaje C. También se comparten: solo existe una única estructura constante estática para cada OID integrado.

Algunas funciones operan solo en objetos de tabla:

OBJ_nid2obj() recupera el objeto de tabla asociado con el nid. OBJ_nid2ln() y OBJ_nid2sn() recuperan su nombre largo y corto, respectivamente.

OBJ_obj2nid() recupera el NID asociado con el object dado, que es ya sea el NID almacenado en el propio object, si lo hubiere, o de lo contrario, el NID almacenado en un objeto de tabla que contiene el mismo OID.

OBJ_ln2nid() y OBJ_sn2nid() recuperan el NID del objeto de tabla con el nombre largo ln o el nombre corto sn, respectivamente.

OBJ_txt2nid() recupera el NID del objeto de tabla descrito por la cadena de texto s, que puede ser un nombre largo, un nombre corto o la representación numérica de un OID.

Las funciones restantes se pueden usar tanto con objetos de tabla como con objetos que no están en la tabla global:

OBJ_txt2obj() recupera o crea un objeto que coincide con la cadena de texto s. Si no_name es 1, solo se acepta la representación numérica de un OID. Si no_name es 0, también se aceptan nombres largos y nombres cortos.

OBJ_obj2txt() escribe una representación textual terminada en NULO del OID contenido en el object dado en buf. Se escriben como máximo buf_len bytes, truncando el resultado si es necesario. Se devuelve la cantidad total de espacio requerido. Si no_name es 0 y el objeto de tabla que contiene el mismo OID tiene un nombre largo, se escribe el nombre largo. De lo contrario, si no_name es 0 y el objeto de tabla que contiene el mismo OID tiene un nombre corto, se escribe el nombre corto. De lo contrario, se escribe la representación numérica del OID.

i2t_ASN1_OBJECT() es lo mismo que OBJ_obj2txt() con no_name establecido en 0.

i2a_ASN1_OBJECT() escribe una representación textual del OID contenido en el object dado a out_bio usando BIO_write(3). No escribe un byte NULO terminador. Si el argumento object es NULL o no contiene ningún OID, escribe la cadena de 4 bytes “NULL”. Si i2t_ASN1_OBJECT() falla, i2a_ASN1_OBJECT() escribe la cadena de 9 bytes “<INVALID>”. De lo contrario, escribe la cadena construida con i2t_ASN1_OBJECT().

OBJ_cmp() prueba si a y b representan el mismo OBJECT IDENTIFIER de ASN.1. Se ignoran los nombres y NIDs contenidos en ambos objetos, incluso si difieren entre los dos objetos.

OBJ_dup() devuelve una copia profunda del object dado si está marcado como asignado dinámicamente. El nuevo objeto y todos los datos contenidos en él se marcan como asignados dinámicamente. Si el object dado no está marcado como asignado dinámicamente, OBJ_dup() simplemente devuelve un puntero al propio object.

VALORES DE RETORNO

El código de la aplicación debe tratar todos los valores devueltos — objetos, nombres y NIDs — como constantes.

OBJ_nid2obj() devuelve un puntero a un objeto de tabla propiedad de la biblioteca o NULL si no se encuentra ningún objeto de tabla coincidente.

DESCRIPTION

These functions are used to encode and decode Object Identifiers (OIDs). OIDs are used in X.509 certificates and other cryptographic contexts to identify object types, algorithms, and other entities. They are represented internally as an ASN1_OBJECT structure.

OBJ_nid2obj() returns an ASN1_OBJECT pointer corresponding to the numerical identifier nid. The returned object is owned by the library and should not be freed by the caller.

OBJ_nid2ln() and OBJ_nid2sn() return the long and short printable names respectively associated with the numerical identifier nid.

OBJ_obj2nid() returns the numerical identifier associated with the ASN1_OBJECT structure object. If the object is not known or is invalid, NID_undef is returned.

OBJ_ln2nid() and OBJ_sn2nid() return the numerical identifier associated with the long (ln) or short (sn) name, respectively.

OBJ_txt2nid() returns the numerical identifier associated with the text string s. The string s can be an OID in dotted decimal notation, or a known short or long name.

OBJ_txt2obj() converts the text string s into an ASN1_OBJECT structure. If no_name is non-zero, the long and short names are not stored in the returned object. If the object is found in the library's internal tables, a pointer to the internal object is returned. Otherwise, a new object is created, and its ownership is transferred to the caller.

OBJ_obj2txt() converts the ASN1_OBJECT structure object into a text string. If buf is not NULL, the output is written to the buffer buf with a maximum length of buf_len. If buf is NULL

i2t_ASN1_OBJECT() converts the ASN1_OBJECT structure object into a text string and writes it into the buffer buf of length buf_len. It returns the number of bytes written, or 0 on error.

OBJ_cmp() compares two ASN1_OBJECT structures. It returns 0 if they are equal or both invalid, and non-zero otherwise.

OBJ_dup() creates a duplicate of the ASN1_OBJECT structure object. If the object is marked as dynamically allocated, a new object is created and its ownership is transferred to the caller. Otherwise, a pointer to the original object is returned.

i2a_ASN1_OBJECT() converts the ASN1_OBJECT structure object into a printable string and writes it to the BIO object bp. It returns the number of bytes written, or a negative value on error.

RETURN VALUES

OBJ_nid2ln() and OBJ_nid2sn() return a pointer to a string owned by a table object or NULL if no matching table object is found. For NID_undef, they return the constant static strings "undefined" and "UNDEF", respectively.

OBJ_obj2nid() returns an NID on success, or NID_undef if object is NULL, does not contain an OID, if no table object matching the OID is found, or if the matching object does not contain an NID.

OBJ_ln2nid() and OBJ_sn2nid() return an NID on success or NID_undef if no matching table object is found or if the matching object does not contain an NID.

OBJ_txt2nid() returns an NID on success or NID_undef if parsing of s or memory allocation fails, if no matching table object is found, or if the matching object does not contain an NID.

OBJ_txt2obj() returns a pointer to a table object owned by the library if lookup of s as a long or short name succeeds. Otherwise, it returns a newly created object, transferring ownership to the caller, or NULL if parsing of s or memory allocation fails.

OBJ_obj2txt() and i2t_ASN1_OBJECT() return the amount of space required in bytes, including the terminating NUL byte, or zero if an error occurs before the required space can be calculated, in particular if buf_len is negative, object is NULL or does not contain an OID, or if memory allocation fails.

OBJ_cmp() returns 0 if both objects refer to the same OID or neither of them are associated with any OID, or a non-zero value if at least one of them refers to an OID but the other one does not refer to the same OID.

OBJ_dup() returns the pointer to the original object if it is not marked as dynamically allocated. Otherwise, it returns a newly created object, transferring ownership to the caller, or NULL if object is NULL or memory allocation fails.

i2a_ASN1_OBJECT() returns the number of bytes written, even if the given object is invalid or contains invalid data, but a negative value if memory allocation or a write operation fails.

In some cases of failure of OBJ_nid2obj(), OBJ_nid2ln(), OBJ_nid2sn(), OBJ_txt2nid(), OBJ_txt2obj(), OBJ_obj2txt(), OBJ_dup(), i2t_ASN1_OBJECT(), and i2a_ASN1_OBJECT(), the reason can be determined with ERR_get_error(3).

EXAMPLES

Retrieve the object for commonName:

ASN1_OBJECT *object;
object = OBJ_nid2obj(NID_commonName);

Check whether an object contains the OID for commonName:

if (OBJ_obj2nid(object) == NID_commonName)
	/* Do something */

Create a new object directly:

object = OBJ_txt2obj("1.2.3.4", 1);

HISTORY

OBJ_nid2obj(), OBJ_nid2ln(), OBJ_nid2sn(), OBJ_obj2nid(), OBJ_ln2nid(), OBJ_sn2nid(), OBJ_txt2nid(), OBJ_cmp(), and OBJ_dup() first appeared in SSLeay 0.5.1. i2a_ASN1_OBJECT() first appeared in SSLeay 0.6.0, and i2t_ASN1_OBJECT() in SSLeay 0.9.0. All these functions have been available since OpenBSD 2.4.

OBJ_txt2obj() first appeared in OpenSSL 0.9.2b. OBJ_obj2txt() first appeared in OpenSSL 0.9.4. Both functions have been available since OpenBSD 2.6.

CAVEATS

The API contract of OBJ_txt2obj() when called with a no_name argument of 0 and of OBJ_dup() is scary in so far as the caller cannot find out from the returned object whether it is owned by the library or whether ownership was transferred to the caller. Consequently, it is best practice to assume that ownership of the object may have been transferred and call ASN1_OBJECT_free(3) on the returned object when the caller no longer needs it. In case the library retained ownership of the returned object, ASN1_OBJECT_free(3) has no effect and is harmless.

Objects returned from OBJ_txt2obj() with a no_name argument of 1 always require ASN1_OBJECT_free(3) to prevent memory leaks.

Objects returned from OBJ_nid2obj() never require ASN1_OBJECT_free(3), but calling it anyway has no effect and is harmless.

BUGS

Usually, an object is expected to contain an NID other than NID_undef if and only if it is a table object. However, this is not an invariant guaranteed by the API. In particular, ASN1_OBJECT_create(3) allows the creation of non-table objects containing bogus NIDs. OBJ_obj2nid() returns such bogus NIDs even though OBJ_nid2obj() cannot use them for retrieval. On top of that, the global table contains one built-in object with an NID of NID_undef.

OBJ_obj2txt() is awkward and messy to use: it doesn't follow the convention of other OpenSSL functions where the buffer can be set to NULL to determine the amount of data that should be written. Instead buf must point to a valid buffer and buf_len should be set to a positive value. A buffer length of 80 should be more than enough to handle any OID encountered in practice.
