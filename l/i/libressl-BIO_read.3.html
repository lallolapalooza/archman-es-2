libressl-BIO_read(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

BIO_READ(3) Manual de Funciones de Biblioteca BIO_READ(3)

NOMBRE

BIO_read, BIO_number_read, BIO_gets, BIO_write, BIO_puts, BIO_indent, BIO_number_written — Funciones de E/S de BIO

SINOPSIS

biblioteca “libcrypto”
#include <openssl/bio.h>

int
BIO_read(BIO *b, void *buf, int len);

unsigned long
BIO_number_read(BIO *b);

int
BIO_gets(BIO *b, char *buf, int size);

int
BIO_write(BIO *b, const void *buf, int len);

int
BIO_puts(BIO *b, const char *string);

int
BIO_indent(BIO *b, int indent, int max);

unsigned long
BIO_number_written(BIO *b);

DESCRIPCIÓN

BIO_read() intenta leer len bytes de b y coloca los datos en buf.

BIO_number_read() devuelve el total de bytes leídos de b usando BIO_read() hasta el momento. Los bytes leídos con BIO_gets() no se cuentan. BIO_new(3) y BIO_set(3) inicializan el contador a 0. Al leer cantidades muy grandes de datos, el contador eventualmente dará la vuelta de ULONG_MAX a 0.

BIO_gets() realiza la operación "gets" de los BIO y coloca los datos en buf. Normalmente, esta operación intentará leer una línea de datos del BIO de longitud máxima size - 1. Sin embargo, hay excepciones, por ejemplo, BIO_gets() en un BIO de digest calculará y devolverá el digest y otros BIO pueden no admitir BIO_gets() en absoluto. La cadena devuelta siempre está terminada en NUL.

BIO_write() intenta escribir len bytes de buf a b.

BIO_puts() intenta escribir la string terminada en NUL a b.

BIO_indent() intenta escribir indent caracteres de espacio a b, pero no más de max caracteres.

BIO_number_written() devuelve el total de bytes escritos a b usando BIO_write(), BIO_puts(), y BIO_indent() hasta el momento. BIO_new(3) y BIO_set(3) inicializan el contador a 0. Al escribir cantidades muy grandes de datos, el contador eventualmente dará la vuelta de ULONG_MAX a 0.

Una técnica utilizada a veces con sockets bloqueantes es usar una llamada al sistema (como select(2), poll(2) o equivalente) para determinar cuándo hay datos disponibles y luego llamar a read(2) para leer los datos. El equivalente con BIOs (es decir, llamar a select(2) en la estructura de E/S subyacente y luego llamar a BIO_read() para leer los datos) no debe usarse porque una sola llamada a BIO_read() puede provocar varias lecturas (y escrituras en el caso de BIOs SSL) en la estructura de E/S subyacente y puede bloquearse como resultado. En su lugar, se debe combinar select(2) (o equivalente) con E/S no bloqueante para que las lecturas sucesivas soliciten un reintento en lugar de bloquearse.

Ver BIO_should_retry(3) para obtener detalles sobre cómo determinar la causa de un reintento y otros problemas de E/S.

Si la función BIO_gets() no es compatible con un BIO, es posible solucionarlo añadiendo un BIO de bufferización BIO_f_buffer(3) a la cadena.

VALORES DE RETORNO

BIO_indent() devuelve 1 si tiene éxito, incluso si no se escribió nada, o 0 si la escritura falla.

BIO_number_read() y BIO_number_written() devuelven una cantidad de bytes o 0 si b es un puntero NULL.

Las otras funciones devuelven la cantidad de datos leídos o escritos exitosamente (si el valor de retorno es positivo) o que no se leyó ni escribió datos si el resultado es 0 o -1. Si el valor de retorno es -2, la operación no está implementada en el tipo de BIO específico. El NUL final no se incluye en la longitud devuelta por BIO_gets().

Un retorno de 0 o -1 no es necesariamente una indicación de un error. En particular, cuando la fuente/sumidero no está bloqueando o es de cierto tipo, puede ser simplemente una indicación de que actualmente no hay datos disponibles y que la aplicación debería reintentar la operación más tarde.

VER TAMBIÉN

BIO_meth_new(3), BIO_new(3), BIO_should_retry(3)

HISTORIAL

BIO_read(), BIO_gets(), BIO_write(), y BIO_puts() aparecieron por primera vez en SSLeay 0.6.0. BIO_number_read() y BIO_number_written() aparecieron por primera vez en SSLeay 0.6.5. Estas funciones han estado disponibles desde OpenBSD 2.4.

BIO_indent() apareció por primera vez en OpenSSL 0.9.7 y ha estado disponible desde OpenBSD 3.4.
