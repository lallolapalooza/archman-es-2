libval_async(3) Manual del programador libval_async(3)

NOMBRE

val_async_submit() - envía una solicitud para el procesamiento asíncrono de consultas DNS.

val_async_select_info() - establece los descriptores de archivo apropiados para las solicitudes asíncronas pendientes.

val_async_check_wait() - maneja tiempos de espera o procesa respuestas DNS para consultas pendientes.

val_async_cancel() - cancela una solicitud de consulta asíncrona.

val_async_cancel_all() - cancela todas las consultas asíncronas para un contexto dado.

SINOPSIS

#include <validator/validator.h>

typedef int (*val_async_event_cb)(val_async_status *async_status,
int event, val_context_t *context,
void *cb_data, val_cb_params_t *cbp);

int val_async_submit(val_context_t *context,
const char * name, int class,
int type, unsigned int flags,
val_async_event_cb callback, void *cb_data,
val_async_status **async_status);

int val_async_select_info(val_context_t *context,
fd_set *fds,
int *num_fds,
struct timeval *timeout);

int val_async_check_wait(val_context_t *context,
fd_set *pending_desc, int *nfds,
struct timeval *tv, unsigned int flags);

int val_async_cancel(val_context_t *context,
val_async_status *as,
unsigned int flags);

int val_async_cancel_all(val_context_t *context,
unsigned int flags);

DESCRIPCIÓN

La API del validador asíncrono de DNSSEC permite a una aplicación enviar múltiples solicitudes, que pueden procesarse en paralelo. En la mayoría de los casos, esto resultará en una validación más rápida que una serie de solicitudes síncronas.

El parámetro ctx en las diversas funciones a continuación especifica el contexto de validación, que puede establecerse en NULL para valores predeterminados (ver libval(3) y dnsval.conf para más detalles sobre contextos de validación y política de validación).

La función val_async_submit() envía una solicitud para el procesamiento asíncrono de consultas DNS para los datos asociados con el nombre de dominio name, class y type dados. El objeto async_status identifica de forma única una solicitud particular y proporciona un manejador para operaciones futuras en esa solicitud asíncrona, incluida su cancelación antes de que se complete la búsqueda.

El parámetro flags afecta cuándo y con qué frecuencia se llama a la función de devolución de llamada. Las siguientes banderas están definidas.

VAL_AS_IGNORE_CACHE
No utilice ninguna caché interna para las respuestas a esta consulta.
VAL_AS_NO_NEW_QUERIES
No envíe nuevas consultas. Las respuestas se devolverán de la caché interna.
VAL_AS_NO_ANSWERS
Al llamante no le importan los resultados de la respuesta. Esto se puede usar para iniciar la caché.
VAL_AS_NO_CALLBACKS
No llame a ninguna función de devolución de llamada.
VAL_AS_NO_CANCEL_CALLBACKS
Llame a las funciones de devolución de llamada con los resultados, pero no llame a ninguna función de devolución de llamada cuando se cancele la solicitud.
VAL_AS_INTERIM_CALLBACKS
Llame a la función de devolución de llamada con resultados intermedios. Si no se especifica esta bandera, la función de devolución de llamada solo se llamará cuando todos los resultados de validación estén listos.

Cuando los resultados de la llamada asíncrona estén disponibles, la función callback (si no es NULL) se llamará con el valor cb_data, originalmente proporcionado a la llamada val_async_submit(), como uno de sus argumentos. Los resultados de la búsqueda se devuelven en cb_data, que es un puntero a la estructura val_cb_params_t que se muestra a continuación.

typedef struct val_cb_params_s {
    val_status_t             val_status;
    char                    *name;
    int                      class_h;
    int                      type_h;
    int                      retval;
    struct val_result_chain *results;
    struct val_answer_chain *answers;
} val_cb_params_t;

La estructura val_cb_params_t contiene los parámetros originales de la consulta en name, class_h y type_h respectivamente, el valor de retorno de la operación de búsqueda en retval, punteros a las cadenas results y answers (ver libval(3) para más detalles), y el estado final de validación de la operación de búsqueda en val_status. La aplicación debe liberar la memoria asociada con results y answers utilizando val_free_result_chain() y val_free_answer_chain() respectivamente (ver libval(3) para más detalles).

Al completar la operación de búsqueda asíncrona, se devuelve un código de evento en event. Los siguientes tipos de eventos están definidos:

VAL_AS_EVENT_COMPLETED
La solicitud se completó.
VAL_AS_EVENT_INTERIM
La solicitud todavía se está procesando, pero hay algunos resultados intermedios disponibles.
VAL_AS_EVENT_CANCELED
La solicitud fue cancelada. Los miembros val_status, results y answers de la estructura del parámetro de devolución de llamada no están definidos.

La función val_async_select_info() examina todas las solicitudes asíncronas pendientes para el contexto dado y establece los descriptores de archivo apropiados, el valor de tiempo de espera y el valor máximo de descriptor de archivo en preparación para una llamada a select(3).

El descriptor de archivo de cada socket que espera una respuesta se establece en el parámetro fds y max_fd se establece en el número de descriptor de archivo más alto de cualquier solicitud asíncrona pendiente, a menos que ese valor sea menor que el valor actual de max_fd, en cuyo caso se deja sin cambios. El campo timeout se establece en el valor de tiempo de espera más bajo de cualquier tiempo de espera de consulta asíncrona pendiente que sea menor que el valor actual en este campo por la aplicación.

Después de que la aplicación llama a select(3), también debe llamar a val_async_check_wait() con el fd_set y el número de descriptores de archivo listos, ndfs, devueltos por select(). La función val_async_check_wait() maneja tiempos de espera o procesa respuestas DNS para consultas pendientes. También llama a las funciones de devolución de llamada para solicitudes completadas.

val_async_check_wait() proporciona dos modos de operación. El primero es para uso con una aplicación que tiene su propio bucle select(). Las aplicaciones establecen sus propios descriptores de archivo, llaman a val_async_select_info() para establecer descriptores de archivo para consultas pendientes y llaman a select(). Los parámetros fds y nfds de select se pasan a val_async_check_wait y se ignora el valor de tiempo de espera. Si se procesan respuestas para un descriptor de archivo, el descriptor de archivo apropiado en fds se borra y nfds se decrementa.

En el segundo modo de operación, la aplicación puede establecer fds y nfds en NULL y especificar un valor para timeout. Aquí, val_async_select_info() y select() se llaman internamente y se procesan las respuestas recibidas antes de que expire el valor de tiempo de espera.

La función val_async_cancel() se puede usar para cancelar la solicitud asíncrona identificada por su manejador as, mientras que val_async_cancel_all() se puede usar para cancelar todas las solicitudes asíncronas asociadas con un contexto dado. La siguiente bandera puede establecerse para la solicitud de cancelación.

VAL_AS_CANCEL_NO_CALLBACKS
No llame a las funciones de devolución de llamada completadas o canceladas.

VALORES DE RETORNO

La función val_async_submit() devuelve VAL_NO_ERROR en caso de éxito y uno de VAL_RESOURCE_UNAVAILABLE, VAL_BAD_ARGUMENT o VAL_INTERNAL_ERROR en caso de fallo.

VAL_ASYNC_SELECT_INFO() | VAL_ASYNC_CHECK_WAIT() | VAL_ASYNC_CANCEL() | VAL_ASYNC_CANCEL_ALL()

val_async_select_info() returns VAL_NO_ERROR on success and VAL_BAD_ARGUMENT if an illegal argument was passed to the function.

val_async_check_wait() returns 0 when no pending requests are found and a positive integer when requests are still pending. A value less than zero on error.

val_async_cancel() and val_async_cancel_all() return VAL_NO_ERROR on success.
