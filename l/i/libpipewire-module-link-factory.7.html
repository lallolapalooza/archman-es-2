NOMBRE

libpipewire-module-link-factory - Fábrica de enlaces

DESCRIPCIÓN

Permite a los clientes crear enlaces entre puertos.

Este módulo crea una nueva fábrica. Los clientes que puedan ver la fábrica pueden usar el nombre de la fábrica (link-factory) para crear nuevos objetos de enlace con pw_core_create_object(). También es posible crear objetos en el archivo de configuración.

Se creará un objeto del tipo PW_TYPE_INTERFACE_Link y se devolverá un proxy al mismo.

Como argumento para la llamada a create_object, un conjunto de propiedades controlará qué puertos se enlazarán.

NOMBRE DEL MÓDULO

libpipewire-module-link-factory

OPCIONES DEL MÓDULO

•
allow.link.passive: si se permite la propiedad link.passive. Por defecto, falso. Por defecto, el núcleo decidirá cuándo un enlace es pasivo basándose en las propiedades del nodo y los puertos.

  • link.output.node: El nodo de salida a usar. Puede ser el id del objeto del nodo, node.name, node.nick, node.description o object.path de un nodo. Cuando la propiedad no se proporciona o es NULL, se debe especificar el puerto de salida.
  • link.output.port: El puerto de salida a enlazar. Puede ser el id del objeto del puerto, port.name, port.alias o object.path. Si se especifica un nodo de salida, el puerto debe pertenecer al nodo. Encontrar un puerto en un nodo usando port.id está obsoleto y puede llevar a resultados inesperados cuando port.id también coincide con un object.id. Si no se proporciona puerto de salida, se debe especificar un nodo de salida y se utilizará un puerto aleatorio (no enlazado) del nodo.
  • link.input.node: El nodo de entrada a usar. Puede ser el id del objeto del nodo, node.name, node.nick, node.description o object.path de un nodo. Cuando la propiedad no se proporciona o es NULL, se debe especificar el puerto de entrada.
  • link.input.port: El puerto de entrada a enlazar. Puede ser el id del objeto del puerto, port.name, port.alias o object.path. Si se especifica un nodo de entrada, el puerto debe pertenecer al nodo. Encontrar un puerto en un nodo usando port.id está obsoleto y puede llevar a resultados inesperados cuando port.id también coincide con un object.id. Si no se proporciona puerto de entrada, se debe especificar un nodo de entrada y se utilizará un puerto aleatorio (no enlazado) del nodo.
  • object.linger: Mantener el enlace activo incluso cuando el cliente que lo creó ya no existe.
  • link.passive: El enlace es pasivo, lo que significa que no mantendrá los nodos ocupados. Por defecto, esta propiedad se ignora y las propiedades del nodo y puerto se utilizan para determinar el estado pasivo del enlace.

    • EJEMPLO DE CONFIGURACIÓN

    El módulo generalmente se agrega al archivo de configuración del demonio principal de pipewire.

    context.modules = [
{ name = libpipewire-link-factory
  args = {
      #allow.link.passive = false
  }
}
]

    SOBREESCRITURA DE CONFIGURACIÓN

    Se puede agregar una sección de configuración module.link-factory.args para anular los argumentos del módulo.

    # ~/.config/pipewire/pipewire.conf.d/my-link-factory-args.conf
module.link-factory.args = {
    #allow.link.passive = false
}

    OBJETOS DE CONFIGURACIÓN

    Para crear un objeto desde la fábrica, se puede usar el método pw_core_create_object() o crear un objeto en la sección context.objects como:

    context.objects = [
{ factory = link-factory
    args = {
        link.output.node = system
        link.output.port = capture_2
        link.input.node  = my-mic
        link.input.port  = input_FR
    }
}

    Tenga en cuenta que esto solo funciona cuando los puertos que necesitan ser enlazados están disponibles en el momento en que se analiza el archivo de configuración.
