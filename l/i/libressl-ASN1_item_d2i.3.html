DESCRIPCIÓN

Estas funciones convierten valores ASN.1 de su codificación BER a estructuras C internas («d2i») y viceversa («i2d»). A diferencia de las estructuras C que contienen punteros a sub-objetos, BER es una codificación serializada, adecuada para la transferencia a través de la red y para el almacenamiento en un archivo.

ASN1_item_d2i() interpreta *der_in como un array de bytes codificado en DER o BER y decodifica un valor de tipo it representado por hasta length bytes. Si tiene éxito, *der_in se avanza al byte siguiente a los datos analizados.

Si la decodificación tiene éxito y val_out o *val_out es NULL, se asigna un nuevo objeto.

Si la decodificación tiene éxito y *val_out no es NULL, se asume que apunta a un objeto válido y poblado y se intenta reutilizarlo. No debe ser una estructura vacía como una devuelta por ASN1_item_new(3) o por alguna de las funciones *_new() específicas de tipo. Esta capacidad de «reutilización» está presente por compatibilidad con versiones anteriores, pero su uso está fuertemente desaconsejado; consulte la sección BUGS más abajo.

ASN1_item_d2i_bio() y ASN1_item_d2i_fp() son similares a ASN1_item_d2i() excepto en que leen desde un BIO o FILE, respectivamente.

d2i_ASN1_TYPE() es similar a ASN1_item_d2i() excepto en que no requiere que el usuario especifique un tipo deseado, sino que devuelve un objeto contenedor ASN1_TYPE que contiene tanto el tipo como el valor encontrados en la entrada.

ASN1_item_i2d() codifica el objeto apuntado por val_in en formato DER.

Si *der_out no es NULL, escribe los datos codificados en DER en el búfer en *der_out y lo incrementa para que apunte después de los datos recién escritos. En este caso, es responsabilidad del usuario asegurarse de que el búfer apuntado por *der_out sea lo suficientemente largo, de modo que no se produzca ningún desbordamiento del búfer.

Si *der_out es NULL, se asigna memoria para un búfer y *der_out no se incrementa, sino que apunta al inicio de los datos recién escritos.

ASN1_item_i2d() es similar a ASN1_item_d2i() excepto en que codifica un objeto ASN.1 en DER.

Si *der_out no es NULL, escribe los datos codificados en DER en el búfer en *der_out y lo incrementa para que apunte después de los datos recién escritos. En este caso, es responsabilidad del usuario asegurarse de que el búfer apuntado por *der_out sea lo suficientemente largo, de modo que no se produzca ningún desbordamiento del búfer.

Si *der_out es NULL, se asigna memoria para un búfer y *der_out no se incrementa, sino que apunta al inicio de los datos recién escritos.

Si der_out es NULL, los bytes codificados no se escriben en ningún lado sino que se descartan. Para objetos val_in de tamaño de codificación variable, esto se usa a veces para encontrar primero el número de bytes que se escribirán. Luego, se asigna suficiente memoria antes de llamar a ASN1_item_i2d() nuevamente. Esta técnica explícita de doble llamada a menudo no es necesaria porque se puede usar la técnica de asignación automática descrita en el párrafo anterior.

ASN1_item_i2d_bio() y ASN1_item_i2d_fp() son similares a ASN1_item_i2d() excepto en que escriben en un BIO o FILE, respectivamente.

i2d_ASN1_TYPE() es similar a ASN1_item_i2d() excepto en que el tipo y el valor no se proporcionan por separado, sino en forma de un único objeto ASN1_TYPE.

ASN1_item_dup() crea una copia profunda de val_in llamando a ASN1_item_i2d() y ASN1_item_d2i().

VALORES DE RETORNO

Si tiene éxito, ASN1_item_d2i(), ASN1_item_d2i_bio(), ASN1_item_d2i_fp(), y d2i_ASN1_TYPE() devuelven un puntero al valor ASN.1 decodificado. Además, si val_out no es NULL, el puntero también se escribe en *val_out. Si ocurre un error, se devuelve NULL.

ASN1_item_i2d() y i2d_ASN1_TYPE() devuelven el número de bytes escritos o un valor negativo si ocurre un error.

ASN1_item_i2d_bio() y ASN1_item_i2d_fp() devuelven 1 para éxito o 0 para fallo.

ASN1_item_dup() devuelve el nuevo objeto ASN1_VALUE o NULL si ocurre un error.

    ASN1_VALUE **val_out);
ASN1_VALUE *ASN1_item_d2i_fp(const ASN1_ITEM *it, FILE *fp,
    ASN1_VALUE **val_out);

int ASN1_item_print(BIO *bp, const ASN1_VALUE *val, int indent,

/* Legacy functions */

ASN1_TYPE *d2i_ASN1_TYPE(ASN1_TYPE **a, const unsigned char **pp,
    long len);

DESCRIPTION

These functions convert ASN.1 encoded data between a C structure and a byte buffer in DER (Distinguished Encoding Rules) format. The functions ending in _bio and _fp operate on BIO and FILE pointers, respectively. The other functions operate on byte buffers. The ASN1_ITEM structure describes the ASN.1 structure of the object being encoded or decoded. The structure is typically obtained from an automatically generated header file, e.g. the structure for X509 is X509_ITEM.

The ASN1_item_i2d() function encodes the C structure pointed to by val_in into DER format. If out is not NULL, the DER encoding is written to the buffer pointed to by out. The pointer out is advanced to point after the encoded data. If out is NULL, then the function simply returns the length of the DER encoding without actually writing any data. The ASN.1 structure information is provided by it.

The ASN1_item_i2d_bio() and ASN1_item_i2d_fp() functions are similar but write the DER encoded data to the supplied BIO or FILE pointer.

The ASN1_item_d2i() function decodes DER encoded data from the buffer pointed to by in. The data is assumed to be len bytes long. The pointer in is advanced to point after the decoded data. If val_out is not NULL, the decoded C structure is stored in the location pointed to by val_out. If val_out is NULL, a new C structure is allocated. The ASN.1 structure information is provided by it.

The ASN1_item_d2i_bio() and ASN1_item_d2i_fp() functions are similar but read the DER encoded data from the supplied BIO or FILE pointer.

The ASN1_item_dup() function duplicates the ASN.1 object pointed to by val.

The ASN1_item_print() function prints a human-readable representation of the ASN.1 object pointed to by val to the BIO bp. The indent parameter specifies the indentation level. The ASN.1 structure information is provided by it. The cb parameter is a callback function, currently unused.

The functions d2i_ASN1_TYPE() and i2d_ASN1_TYPE() are legacy functions for handling generic ASN.1 types. They should generally not be used.

The functions that take a val_out pointer and a len or a BIO/ FILE pointer as input for decoding, e.g. ASN1_item_d2i(), can be used in two ways: If val_out is initially NULL, then a new structure is allocated and returned. If val_out points to an existing structure (which must have been initialized, e.g. using ASN1_item_new()), then this existing structure is used, and any previous content is overwritten. This is often referred to as "reusing" the structure.

The functions that take an out pointer for encoding, e.g. ASN1_item_i2d(), use the same mechanism. If out is NULL, then the length is returned. If out points to a buffer, the data is written there, and the pointer out is incremented to point to the byte after the written data. The caller is responsible for ensuring that the buffer is large enough to hold the encoded data.

RETURN VALUES

ASN1_item_i2d(), ASN1_item_i2d_bio() and ASN1_item_i2d_fp() return the number of bytes written, or a negative value on error.

ASN1_item_d2i(), ASN1_item_d2i_bio() and ASN1_item_d2i_fp() return a pointer to the decoded structure, or NULL if an error occurred. The error can be checked using ERR_get_error(3).

ASN1_item_dup() returns a pointer to the duplicated structure, or NULL if an error occurred.

ASN1_item_print() returns 1 on success, 0 on error.

d2i_ASN1_TYPE() and i2d_ASN1_TYPE() return a pointer to the decoded/encoded ASN1_TYPE structure, or NULL on error.

EXAMPLES

Encode an X509 object into a buffer:

X509		*x;
unsigned char	*buf;
int		 len;

buf = NULL;
len = i2d_X509(x, &buf);
if (len < 0)
	/* error */

Attempt to decode a buffer:

X509			*x;
unsigned char		*buf;
const unsigned char	*p;
int			 len;

/* Set up buf and len to point to the input buffer. */
p = buf;
x = d2i_X509(NULL, &p, len);
if (x == NULL)
	/* error */

Equivalent technique:

X509			*x;
unsigned char		*buf;
const unsigned char	*p;
int			 len;

/* Set up buf and len to point to the input buffer. */
p = buf;
x = NULL;

if (d2i_X509(&x, &p, len) == NULL)
	/* error */

HISTORY

d2i_ASN1_TYPE() and i2d_ASN1_TYPE() first appeared in SSLeay 0.5.1 and have been available since OpenBSD 2.4.

ASN1_item_d2i(), ASN1_item_d2i_bio(), ASN1_item_d2i_fp(), ASN1_item_i2d(), ASN1_item_i2d_bio(), ASN1_item_i2d_fp(), and ASN1_item_dup() first appeared in OpenSSL 0.9.7 and have been available since OpenBSD 3.2.

ASN1_item_print() first appeared in OpenSSL 1.0.0 and has been available since OpenBSD 4.9.

CAVEATS

If the type described by it fails to match the true type of val_in or *val_out, buffer overflows and segmentation faults are likely to occur. For more details about why the type ASN1_VALUE constitutes dangerous user interface design, see ASN1_item_new(3).

The encoded data is in binary form and may contain embedded NUL bytes. Functions such as strlen(3) will not return the correct length of the encoded data.

While the way that *der_in and *der_out are incremented after the operation supports the typical usage patterns of reading or writing one object after another, this behaviour can trap the unwary.

Using a temporary pointer into the buffer is mandatory. A common mistake is to attempt to use a buffer directly as follows:

X509		*x;
unsigned char	*buf;
int		 len;

len = i2d_X509(x, NULL);
buf = malloc(len);
i2d_X509(x, &buf);
/* do something with buf[] */
free(buf);

This code will result in buf apparently containing garbage because it was incremented during i2d_X509() to point after the data just written. Also buf will no longer contain the pointer allocated by malloc(3) and the subsequent call to free(3) is likely to crash.

Another trap to avoid is misuse of the val_out argument:

X509		*x;

if (d2i_X509(&x, &p, len) == NULL)
	/* error */

This will probably crash somewhere in d2i_X509() because x is uninitialized and an attempt will be made to interpret its invalid content as an X509 object, typically causing a segmentation violation. If x is set to NULL first, then this will not happen.

BUGS

If the “reuse” capability is used, a valid object is passed in via *val_out, and an error occurs, then the object is not freed and may be left in an invalid or inconsistent state.

In some versions of OpenSSL, the “reuse” behaviour is broken such that some parts of the reused object may persist if they are not present in the new one.

In many versions of OpenSSL, ASN1_item_i2d() will not return an error if mandatory fields are not initialized due to a programming error. In that case, the encoded structure may contain invalid data and some fields may be missing entirely, such that trying to parse it with ASN1_item_d2i() may fail.
