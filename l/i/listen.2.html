listen(2) Manual de llamadas al sistema listen(2)

NOMBRE

listen - escuchar conexiones en un socket

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/socket.h>
int listen(int sockfd, int backlog);

DESCRIPCIÓN

listen() marca el socket al que se refiere sockfd como un socket pasivo, es decir, como un socket que se utilizará para aceptar solicitudes de conexión entrantes usando accept(2).

El argumento sockfd es un descriptor de archivo que se refiere a un socket de tipo SOCK_STREAM o SOCK_SEQPACKET.

El argumento backlog define la longitud máxima que puede alcanzar la cola de conexiones pendientes para sockfd. Si llega una solicitud de conexión cuando la cola está llena, el cliente puede recibir un error con una indicación de ECONNREFUSED o, si el protocolo subyacente admite la retransmisión, la solicitud puede ser ignorada para que un intento posterior de conexión tenga éxito.

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EADDRINUSE
Otro socket ya está escuchando en el mismo puerto.
EADDRINUSE
(Sockets de dominio de Internet) El socket al que se refiere sockfd no se había enlazado previamente a una dirección y, al intentar enlazarlo a un puerto efímero, se determinó que todos los números de puerto en el rango de puertos efímeros están actualmente en uso. Consulte la discusión de /proc/sys/net/ipv4/ip_local_port_range en ip(7).
EBADF
El argumento sockfd no es un descriptor de archivo válido.
ENOTSOCK
El descriptor de archivo sockfd no se refiere a un socket.
EOPNOTSUPP
El socket no es de un tipo que admita la operación listen().

ESTÁNDARES

POSIX.1-2024.

HISTORIA

POSIX.1-2001, 4.4BSD (apareció por primera vez en 4.2BSD).

NOTAS

Para aceptar conexiones, se realizan los siguientes pasos:

(1)
Se crea un socket con socket(2).
(2)
El socket se enlaza a una dirección local usando bind(2), para que otros sockets puedan ser connect(2)ados a él.
(3)
Se especifica la voluntad de aceptar conexiones entrantes y un límite de cola para las conexiones entrantes con listen().
(4)
Se aceptan las conexiones con accept(2).

El comportamiento del argumento backlog en los sockets TCP cambió con Linux 2.2. Ahora especifica la longitud de la cola para los sockets *completamente* establecidos que esperan ser aceptados, en lugar del número de solicitudes de conexión incompletas. La longitud máxima de la cola para sockets incompletos se puede establecer usando /proc/sys/net/ipv4/tcp_max_syn_backlog. Cuando los syncookies están habilitados, no hay una longitud máxima lógica y esta configuración se ignora. Consulte tcp(7) para obtener más información.

Si el argumento backlog es mayor que el valor en /proc/sys/net/core/somaxconn, se limita silenciosamente a ese valor. Desde Linux 5.4, el valor predeterminado en este archivo es 4096; en kernels anteriores, el valor predeterminado es 128. Antes de Linux 2.4.25, este límite era un valor codificado, SOMAXCONN, con el valor 128.

EJEMPLOS

Consulte bind(2).

VER TAMBIÉN

accept(2), bind(2), connect(2), socket(2), socket(7)
