link(2) Manual de llamadas al sistema link(2)

NOMBRE

link, linkat - crear un nuevo nombre para un archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int link(const char *oldpath, const char *newpath);
#include <fcntl.h>           /* Definición de las constantes AT_* */
#include <unistd.h>
int linkat(int olddirfd, const char *oldpath,
           int newdirfd, const char *newpath, int flags);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

linkat():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _ATFILE_SOURCE

DESCRIPCIÓN

link() crea un nuevo enlace (también conocido como enlace duro) a un archivo existente.

Si newpath existe, no será sobrescrito.

Este nuevo nombre puede ser utilizado exactamente como el antiguo para cualquier operación; ambos nombres se refieren al mismo archivo (y por lo tanto tienen los mismos permisos y propietario) y es imposible decir cuál nombre era el "original".

linkat()

La llamada al sistema linkat() opera exactamente de la misma manera que link(), excepto por las diferencias que se describen aquí.

Si la ruta dada en oldpath es relativa, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo olddirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como lo hace link() para una ruta relativa).

Si oldpath es relativa y olddirfd es el valor especial AT_FDCWD, entonces oldpath se interpreta en relación con el directorio de trabajo actual del proceso que llama (como link()).

Si oldpath es absoluta, entonces olddirfd se ignora.

La interpretación de newpath es como para oldpath, excepto que una ruta relativa se interpreta en relación con el directorio al que se refiere el descriptor de archivo newdirfd.

Los siguientes valores pueden ser ORados bit a bit en flags:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si oldpath es una cadena vacía, crea un enlace al archivo al que se refiere olddirfd (que puede haber sido obtenido usando el flag open(2) O_PATH). En este caso, olddirfd puede referirse a cualquier tipo de archivo excepto un directorio. Esto generalmente no funcionará si el archivo tiene un recuento de enlaces de cero (los archivos creados con O_TMPFILE y sin O_EXCL son una excepción). El llamante debe tener la capacidad CAP_DAC_READ_SEARCH para usar este flag. Este flag es específico de Linux; define _GNU_SOURCE para obtener su definición.
AT_SYMLINK_FOLLOW (desde Linux 2.6.18)
Por defecto, linkat() no desreferencia oldpath si es un enlace simbólico (como link()). El flag AT_SYMLINK_FOLLOW puede especificarse en flags para hacer que oldpath sea desreferenciado si es un enlace simbólico. Si procfs está montado, esto puede usarse como una alternativa a AT_EMPTY_PATH, de la siguiente manera:

linkat(AT_FDCWD, "/proc/self/fd/<fd>", newdirfd,
       newname, AT_SYMLINK_FOLLOW);

Antes de Linux 2.6.18, el argumento flags no se usaba y debía especificarse como 0.

Vea openat(2) para una explicación de la necesidad de linkat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EACCES
Se niega el acceso de escritura al directorio que contiene newpath, o se niega el permiso de búsqueda para uno de los directorios en el prefijo de ruta de oldpath o newpath. (Ver también path_resolution(7)).
EDQUOT
Se ha agotado la cuota del usuario de bloques de disco en el sistema de archivos.
EEXIST
newpath ya existe.
EFAULT
oldpath o newpath apunta fuera de su espacio de direcciones accesible.
EIO
Ocurrió un error de I/O.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver oldpath o newpath.
EMLINK
El archivo al que se refiere oldpath ya tiene el número máximo de enlaces. Por ejemplo, en un sistema de archivos ext4(5) que no utiliza la característica dir_index, el límite en el número de enlaces duros a un archivo es de 65,000; en btrfs(5), el límite es de 65,535 enlaces.
ENAMETOOLONG
oldpath o newpath era demasiado largo.
ENOENT
Un componente del directorio en oldpath o newpath no existe o es un enlace simbólico colgante.
ENOMEM
No había suficiente memoria del kernel disponible.
ENOSPC
El dispositivo que contiene el archivo no tiene espacio para la nueva entrada de directorio.
ENOTDIR
Un componente utilizado como directorio en oldpath o newpath no es, de hecho, un directorio.
EPERM
oldpath es un directorio.
EPERM
El sistema de archivos que contiene oldpath y newpath no soporta la creación de enlaces duros.
EPERM (desde Linux 3.6)
El llamante no tiene permiso para crear un enlace duro a este archivo (ver la descripción de /proc/sys/fs/protected_hardlinks en proc_sys_fs(5)).
EPERM
oldpath está marcado como inmutable o de solo añadir. (Ver FS_IOC_SETFLAGS(2const).)
EROFS
El archivo está en un sistema de archivos de solo lectura.
EXDEV
oldpath y newpath no están en el mismo sistema de archivos montado. (Linux permite que un sistema de archivos se monte en varios puntos, pero link() no funciona entre diferentes montajes, incluso si el mismo sistema de archivos está montado en ambos.)

Los siguientes errores adicionales pueden ocurrir para linkat():

EBADF
oldpath (newpath) es relativo pero olddirfd (newdirfd) no es AT_FDCWD ni un descriptor de archivo válido.
EINVAL
Se especificó un valor de flag inválido en flags.
ENOENT
Se especificó AT_EMPTY_PATH en flags, pero el llamante no tenía la capacidad CAP_DAC_READ_SEARCH.
ENOENT
Se intentó

ERRORS

EACCES
Search permission denied for one of the components of oldpath or newpath, or permission denied for newpath.
EEXIST
newpath exists.
EINVAL

open(path, O_TMPFILE | O_EXCL, mode);

See open(2).
ENOENT
An attempt was made to link to a /proc/self/fd/NN file corresponding to a file that has been deleted.
ENOENT
oldpath is a relative pathname and olddirfd refers to a directory that has been deleted, or newpath is a relative pathname and newdirfd refers to a directory that has been deleted.
ENOTDIR
oldpath is relative and olddirfd is a file descriptor referring to a file other than a directory; or similar for newpath and newdirfd
EPERM
AT_EMPTY_PATH was specified in flags, oldpath is an empty string, and olddirfd refers to a directory.

VERSIONS

POSIX.1-2001 dice que link() debería desenferrar oldpath si es un enlace simbólico. Sin embargo, desde Linux 2.0, Linux no lo hace: si oldpath es un enlace simbólico, entonces newpath se crea como un enlace (duro) al mismo archivo de enlace simbólico (es decir, newpath se convierte en un enlace simbólico al mismo archivo al que se refiere oldpath). Algunas otras implementaciones se comportan de manera similar a Linux. POSIX.1-2008 cambia la especificación de link(), haciendo que dependa de la implementación si oldpath se desenferra o no si es un enlace simbólico. Para un control preciso sobre el tratamiento de los enlaces simbólicos al crear un enlace, utilice linkat().

glibc

En kernels más antiguos donde linkat() no está disponible, la función wrapper de glibc recurre al uso de link(), a menos que se especifique AT_SYMLINK_FOLLOW. Cuando oldpath y newpath son rutas relativas, glibc construye rutas basadas en los enlaces simbólicos en /proc/self/fd que corresponden a los argumentos olddirfd y newdirfd.

STANDARDS

POSIX.1-2024.

HISTORY

link()
SVr4, 4.3BSD, POSIX.1-2001 (pero ver VERSIONS).
linkat()
POSIX.1-2008. Linux 2.6.16, glibc 2.4.

NOTES

Los enlaces duros, como los creados por link(), no pueden abarcar sistemas de archivos. Utilice symlink(2) si esto es necesario.

BUGS

En sistemas de archivos NFS, el código de retorno puede ser incorrecto en caso de que el servidor NFS realice la creación del enlace y muera antes de poder decirlo. Utilice stat(2) para saber si el enlace se creó.
