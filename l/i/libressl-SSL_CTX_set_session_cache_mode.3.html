libressl-SSL_CTX_set_session_cache_mode(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_CTX_SET_SESSION_CACHE_MODE(3) Manual de funciones de biblioteca SSL_CTX_SET_SESSION_CACHE_MODE(3)

NOMBRE

SSL_CTX_set_session_cache_mode, SSL_CTX_get_session_cache_mode — activar/desactivar el almacenamiento en caché de sesiones

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

long
SSL_CTX_set_session_cache_mode(SSL_CTX ctx, long mode);

long
SSL_CTX_get_session_cache_mode(SSL_CTX ctx);

DESCRIPCIÓN

SSL_CTX_set_session_cache_mode() activa/desactiva el almacenamiento en caché de sesiones estableciendo el modo operativo para ctx a mode.

SSL_CTX_get_session_cache_mode() devuelve el modo de caché utilizado actualmente.

La biblioteca OpenSSL puede almacenar/recuperar sesiones SSL/TLS para su reutilización posterior. Las sesiones se pueden mantener en memoria para cada ctx; si se mantiene más de un objeto SSL_CTX, las sesiones son únicas para cada objeto SSL_CTX.

Para reutilizar una sesión, un cliente debe enviar el ID de la sesión al servidor. Solo puede enviar exactamente un ID. El servidor luego acepta reutilizar la sesión o inicia un handshake completo (para crear una nueva sesión).

Un servidor buscará la sesión en su almacenamiento de sesiones interno. Si la sesión no se encuentra en el almacenamiento interno o si se desactivaron las búsquedas para el almacenamiento interno (SSL_SESS_CACHE_NO_INTERNAL_LOOKUP), el servidor intentará el almacenamiento externo si está disponible.

Dado que un cliente puede intentar reutilizar una sesión destinada a usarse en un contexto diferente, el contexto del ID de sesión debe ser establecido por el servidor (consulte SSL_CTX_set_session_id_context(3)).

Los siguientes modos y modificadores de caché de sesiones están disponibles:

SSL_SESS_CACHE_OFF
No se realiza ningún almacenamiento en caché de sesiones para cliente o servidor.
SSL_SESS_CACHE_CLIENT
Las sesiones del cliente se añaden a la caché de sesiones. Como no hay forma confiable para que la biblioteca OpenSSL sepa si una sesión debe ser reutilizada o cuál elegir (debido a la capa BIO abstracta, el motor SSL no tiene detalles sobre la conexión), la aplicación debe seleccionar la sesión a reutilizar utilizando la función SSL_set_session(3). Esta opción no está activada por defecto.
SSL_SESS_CACHE_SERVER
Las sesiones del servidor se añaden a la caché de sesiones. Cuando un cliente propone una sesión para reutilizar, el servidor busca la sesión correspondiente (primero) en la caché de sesiones interna (a menos que se establezca SSL_SESS_CACHE_NO_INTERNAL_LOOKUP), luego (segundo) en la caché externa si está disponible. Si la sesión se encuentra, el servidor intentará reutilizarla. Este es el valor predeterminado.
SSL_SESS_CACHE_BOTH
Activa tanto SSL_SESS_CACHE_CLIENT como SSL_SESS_CACHE_SERVER al mismo tiempo.
SSL_SESS_CACHE_NO_AUTO_CLEAR
Normalmente, la caché de sesiones se comprueba en busca de sesiones caducadas cada 255 conexiones utilizando la función SSL_CTX_flush_sessions(3). Dado que esto puede provocar un retraso que no se puede controlar, la eliminación automática se puede desactivar y la aplicación puede llamar explícitamente a SSL_CTX_flush_sessions(3).
SSL_SESS_CACHE_NO_INTERNAL_LOOKUP
Al establecer esta bandera, las operaciones de reanudación de sesión en un servidor SSL/TLS no buscarán automáticamente las sesiones en la caché interna, incluso si las sesiones se almacenan allí automáticamente. Si se utilizan devoluciones de llamada de almacenamiento en caché de sesiones externas, esta bandera garantiza que todas las búsquedas se dirijan a la caché externa. Dado que la búsqueda automática solo se aplica a los servidores SSL/TLS, la bandera no tiene ningún efecto en los clientes.
SSL_SESS_CACHE_NO_INTERNAL_STORE
Dependiendo de la presencia de SSL_SESS_CACHE_CLIENT y/o SSL_SESS_CACHE_SERVER, las sesiones negociadas en un handshake SSL/TLS pueden almacenarse en caché para su posible reutilización. Normalmente, una nueva sesión se añade a la caché interna, así como a cualquier almacenamiento en caché de sesiones externo (devolución de llamada) que esté configurado para el SSL_CTX. Esta bandera evitará que las sesiones se almacenen en la caché interna (aunque la aplicación puede añadirlas manualmente usando SSL_CTX_add_session(3)). Nota: en cualquier servidor SSL/TLS donde esté configurado el almacenamiento en caché externo, cualquier búsqueda de sesión exitosa en la caché externa (por ejemplo, para solicitudes de reanudación de sesión) se copiaría normalmente en la caché local antes de que continúe el procesamiento; esta bandera también evita estas adiciones a la caché interna.
SSL_SESS_CACHE_NO_INTERNAL
Activa tanto SSL_SESS_CACHE_NO_INTERNAL_LOOKUP como SSL_SESS_CACHE_NO_INTERNAL_STORE al mismo tiempo.

El modo predeterminado es SSL_SESS_CACHE_SERVER.

VALORES DE RETORNO

SSL_CTX_set_session_cache_mode() devuelve el modo de caché previamente establecido.

SSL_CTX_get_session_cache_mode() devuelve el modo de caché establecido actualmente.

VER TAMBIÉN

HISTORIA

SSL_CTX_set_session_cache_mode() y SSL_CTX_get_session_cache_mode() aparecieron por primera vez en SSLeay 0.6.1 y han estado disponibles desde OpenBSD 2.4.

SSL_SESS_CACHE_NO_INTERNAL_STORE y SSL_SESS_CACHE_NO_INTERNAL se introdujeron en OpenSSL 0.9.6h.
