NOMBRE

DESCRIPCIÓN

La estructura EVP_PKEY es utilizada por varias funciones de OpenSSL que requieren una clave privada o pública general sin referencia a ningún algoritmo particular.

La función EVP_PKEY_new() asigna una estructura EVP_PKEY vacía. El contador de referencias se establece en 1. Para añadirle una clave privada o pública, utilice las funciones descritas en EVP_PKEY_set1_RSA(3).

EVP_PKEY_up_ref() incrementa el contador de referencias de pkey en 1.

EVP_PKEY_free() decrementa el contador de referencias de pkey en 1, y si el contador de referencias llega a cero, la libera. Si pkey es un puntero NULL, no se realiza ninguna acción.

EVP_PKEY_new_raw_private_key() asigna una nueva EVP_PKEY. El NID de un algoritmo de clave pública que soporta claves privadas crudas, es decir, EVP_PKEY_HMAC, EVP_PKEY_X25519, o EVP_PKEY_ED25519, se proporciona en el argumento type y rawlen bytes de datos de clave privada cruda de ese tipo en rawpriv. Los datos de la clave pública se derivan automáticamente de los datos de la clave privada proporcionada, si es apropiado para el tipo de algoritmo. El argumento ENGINE *engine siempre se ignora y se recomienda pasar NULL.

EVP_PKEY_new_raw_public_key() funciona de la misma manera que EVP_PKEY_new_raw_private_key() excepto que rawpub apunta a los datos de la clave pública cruda. Los tipos de algoritmo que soportan claves públicas crudas son EVP_PKEY_X25519 y EVP_PKEY_ED25519.

EVP_PKEY_new_mac_key() es una función obsoleta que logra el mismo efecto que EVP_PKEY_new_raw_private_key() de una manera más complicada y solo funciona con un type de EVP_PKEY_HMAC.

EVP_PKEY_get_raw_private_key() escribe hasta *rawlen bytes de datos de clave privada cruda en el buffer que comienza en rawpriv y almacena el número de bytes escritos en *rawlen. La aplicación que llama es responsable de asegurar que el buffer sea lo suficientemente grande para recibir los datos de la clave privada. Si el argumento rawpriv es NULL, el número de bytes requeridos para almacenar la clave se almacena en *rawlen. Esta función solo funciona para algoritmos que soportan claves privadas crudas. Actualmente, estos son EVP_PKEY_HMAC, EVP_PKEY_X25519, y EVP_PKEY_ED25519.

EVP_PKEY_get_raw_public_key() es similar a EVP_PKEY_get_raw_private_key() excepto que escribe datos de clave pública cruda. Esta función solo funciona para algoritmos que soportan claves públicas crudas. Actualmente, estos son EVP_PKEY_X25519 y EVP_PKEY_ED25519.

VALORES DE RETORNO

EVP_PKEY_new(), EVP_PKEY_new_raw_private_key(), EVP_PKEY_new_raw_public_key(), y EVP_PKEY_new_mac_key() devuelven la estructura EVP_PKEY recién asignada o NULL si ocurrió un error.

EVP_PKEY_up_ref(), EVP_PKEY_get_raw_private_key(), y EVP_PKEY_get_raw_public_key() devuelven 1 para éxito o 0 para fallo.

EJEMPLOS

El siguiente código digiere un mensaje con HMAC-SHA256:

/* Clave falsa: normalmente se establecería desde otra fuente */
const unsigned char *key = "key";
const size_t key_len = strlen(key);

const char *msg = "The quick brown fox jumps over the lazy dog";
const size_t msg_len = strlen(msg);

unsigned char *out_mac;
size_t out_len, i;

EVP_PKEY *pkey;
EVP_MD_CTX *md_ctx;

pkey = EVP_PKEY_new_raw_private_key(EVP_PKEY_HMAC, NULL,
    key, key_len);
if (pkey == NULL)
	err(1, "EVP_PKEY_new_raw_private_key");

md_ctx = EVP_MD_CTX_new();
if (md_ctx == NULL)
	err(1, "EVP_MD_CTX_new");

if (EVP_DigestSignInit(md_ctx, NULL, EVP_sha256(), NULL, pkey) == 0)
	err(1, "EVP_DigestSignInit");
if (EVP_DigestSign(md_ctx, NULL, &out_len, msg, msg_len) == 0)
	err(1, "EVP_DigestSign(NULL)");
if ((out_mac = calloc(1, out_len)) == NULL)
	err(1, "calloc");
if (EVP_DigestSign(md_ctx, out_mac, &out_len, msg, msg_len) == 0)
	err(1, "EVP_DigestSign(MAC)");

EVP_MD_CTX_free(md_ctx);
EVP_PKEY_free(pkey);

printf(" MAC = ");
for (i = 0; i < out_len; i++)
	printf("%02x", out_mac[i]);
printf("\n");
free(out_mac);

Aunque el nombre del tipo EVP_PKEY fue originalmente pensado para significar “clave privada” y la API EVP_DigestSignInit(3) fue diseñada para firmas digitales en el contexto de criptografía de clave pública, ambos también se utilizan aquí porque un MAC también requiere una clave, aunque sea una clave simétrica.

El mismo código puede usarse para firmar con Ed25519 haciendo que la clave sea ED25519_PRIVATE_KEY_LENGTH = 32 bytes

HISTORIA

EVP_PKEY_new() y EVP_PKEY_free() aparecieron por primera vez en SSLeay 0.6.0 y han estado disponibles desde OpenBSD 2.4.

EVP_PKEY_new_mac_key() apareció por primera vez en OpenSSL 1.0.0 y ha estado disponible desde OpenBSD 4.9.

EVP_PKEY_up_ref() apareció por primera vez en OpenSSL 1.1.0 y ha estado disponible desde OpenBSD 6.3.

EVP_PKEY_new_raw_private_key(), EVP_PKEY_new_raw_public_key(), EVP_PKEY_get_raw_private_key(), y EVP_PKEY_get_raw_public_key() aparecieron por primera vez en OpenSSL 1.1.1 y han estado disponibles desde OpenBSD 7.3.
