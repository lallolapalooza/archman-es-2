libressl-SSL_get_shared_ciphers(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_GET_SHARED_CIPHERS(3) Manual de Funciones de Biblioteca SSL_GET_SHARED_CIPHERS(3)

NOMBRE

SSL_get_shared_ciphers — cifrados compatibles tanto con cliente como con servidor

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

char *
SSL_get_shared_ciphers(const SSL *ssl, char *buf, int len);

DESCRIPCIÓN

Si ssl contiene una sesión en modo servidor, SSL_get_shared_ciphers() coloca tantos nombres de cifrados que son compatibles tanto con el cliente como con el servidor en el búfer buf como permita el tamaño del búfer. Los nombres están separados por dos puntos. Se escriben como máximo len bytes en buf, incluido el carácter NUL terminador.

VALORES DE RETORNO

SSL_get_shared_ciphers() devuelve buf en caso de éxito o NULL en caso de fallo. Las siguientes situaciones causan un fallo:

  • SSL_is_server(3) es falso, es decir, ssl no está configurado en modo servidor.
  • SSL_get_ciphers(3) es NULL o está vacío, es decir, no hay cifrados disponibles para el uso del servidor.
  • SSL_get_session(3) es NULL, es decir, ssl no contiene ninguna sesión.
  • SSL_get_client_ciphers(3) es NULL o está vacío, es decir, ssl no contiene información sobre los cifrados compatibles con el cliente, o el cliente no admite ningún cifrado.
  • El argumento len es menor que 2.

VER TAMBIÉN

ssl(3), SSL_get_ciphers(3)

HISTORIA

SSL_get_shared_ciphers() apareció por primera vez en SSLeay 0.4.5b y ha estado disponible desde OpenBSD 2.4.

ERRORES

Si la lista es demasiado larga para caber en len bytes, se trunca silenciosamente después del último nombre de cifrado que cabe, y se omiten todos los cifrados siguientes. Si el búfer es muy corto, de modo que ni siquiera el primer nombre de cifrado cabe, se devuelve una cadena vacía, incluso cuando hay cifrados compartidos disponibles.

No hay una forma fácil de averiguar cuánto espacio se requiere para buf o si el espacio proporcionado fue suficiente.
