libressl-SSL_clear(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_CLEAR(3) Manual de funciones de biblioteca SSL_CLEAR(3)

NOMBRE

SSL_clear — reinicia el objeto SSL para permitir otra conexión

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_clear(SSL *ssl);

DESCRIPCIÓN

Reinicia ssl para permitir otra conexión. Todos los ajustes (método, cifrados, BIOs) se conservan.

SSL_clear() se utiliza para preparar un objeto SSL para una nueva conexión. Si bien todos los ajustes se conservan, un efecto secundario es el manejo de la sesión SSL actual. Si una sesión aún está abierta, se considera defectuosa y se eliminará de la caché de sesiones, según lo requerido por RFC 2246. Una sesión se considera abierta si SSL_shutdown(3) no se llamó para la conexión o al menos SSL_set_shutdown(3) se utilizó para establecer el estado SSL_SENT_SHUTDOWN.

Si una sesión se cerró limpiamente, el objeto de sesión se conservará y todos los ajustes correspondientes. Esto significa explícitamente que, por ejemplo, el método especial utilizado durante la sesión se conservará para el próximo apretón de manos. Por lo tanto, si la sesión fue una sesión TLSv1, un objeto cliente SSL utilizará un método cliente TLSv1 para el próximo apretón de manos y un objeto servidor SSL utilizará un método servidor TLSv1, incluso si se eligieron método_TLS_*()s al inicio. Esto podría provocar fallos en la conexión (consulte SSL_new(3) para una descripción de las propiedades del método).

VALORES DE RETORNO

Pueden ocurrir los siguientes valores de retorno:

0
La operación SSL_clear() no se pudo realizar. Compruebe la pila de errores para averiguar el motivo.
1
La operación SSL_clear() fue exitosa.

VER TAMBIÉN

ssl(3), SSL_CTX_set_client_cert_cb(3), SSL_CTX_set_options(3), SSL_free(3), SSL_new(3), SSL_set_shutdown(3), SSL_shutdown(3)

HISTORIA

SSL_clear() apareció por primera vez en SSLeay 0.4.5b y ha estado disponible desde OpenBSD 2.4.

ADVERTENCIAS

SSL_clear() reinicia el objeto SSL para permitir otra conexión. Sin embargo, la operación de reinicio conserva varias configuraciones de las últimas sesiones (algunas de estas configuraciones se realizaron automáticamente durante el último apretón de manos). Solo tiene sentido para una nueva conexión con el mismo par que comparte estas configuraciones, y puede fallar si ese par cambia sus configuraciones entre conexiones. Utilice la secuencia SSL_get_session(3); SSL_new(3); SSL_set_session(3); SSL_free(3) en su lugar para evitar tales fallos (o simplemente SSL_free(3); SSL_new(3) si no se desea la reutilización de sesiones).
