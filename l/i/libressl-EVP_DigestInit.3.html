DESCRIPCIÓN

Las rutinas de digestión EVP son una interfaz de alto nivel para digestiones de mensajes y deben usarse en lugar de las funciones específicas de cifrado.

EVP_MD_CTX_new() asigna un nuevo contexto de digestión vacío.

EVP_MD_CTX_reset() limpia ctx y lo restablece al estado que tenía después de EVP_MD_CTX_new(), para que pueda ser reutilizado.

EVP_MD_CTX_free() limpia ctx y libera el espacio asignado.

EVP_MD_CTX_init() es una función obsoleta para limpiar un contexto de digestión en la pila antes de su uso. No la uses en un contexto de digestión devuelto por EVP_MD_CTX_new() o uno que ya se haya utilizado.

EVP_MD_CTX_create(), EVP_MD_CTX_cleanup(), y EVP_MD_CTX_destroy() son alias obsoletos para EVP_MD_CTX_new(), EVP_MD_CTX_reset(), y EVP_MD_CTX_free(), respectivamente.

EVP_DigestInit_ex() configura el contexto de digestión ctx para usar una digestión de tipo type. El type será típicamente suministrado por una función como EVP_sha512(). El argumento ENGINE *engine se ignora siempre y se recomienda pasar NULL.

EVP_DigestUpdate() calcula el hash de cnt bytes de datos en d en el contexto de digestión ctx. Esta función puede llamarse varias veces en el mismo ctx para calcular el hash de datos adicionales.

EVP_DigestFinal_ex() recupera el valor de la digestión de ctx y lo coloca en md. Si el parámetro s no es NULL, entonces el número de bytes de datos escritos (es decir, la longitud de la digestión) se escribirá en el entero en s; se escribirán como máximo EVP_MAX_MD_SIZE bytes. Después de llamar a EVP_DigestFinal_ex(), no se pueden realizar más llamadas a EVP_DigestUpdate(), pero se puede llamar a EVP_DigestInit_ex()

DESCRIPTION

EVP_MD_CTX_new() and EVP_MD_CTX_create() create and return a message digest context. This context can be reused for multiple digest operations using functions like EVP_DigestInit_ex(), EVP_DigestUpdate(), and EVP_DigestFinal_ex().

EVP_MD_CTX_reset() resets an existing EVP_MD_CTX so that it can be reused. The digest state is cleared, but the digest algorithm itself is not changed. This is useful if the digest algorithm is fixed, but the data to be hashed will change. It is more efficient than calling EVP_MD_CTX_create() followed by EVP_MD_CTX_destroy(). EVP_MD_CTX_reset() may be called even if no algorithm has been set in the context yet.

EVP_MD_CTX_init() is a deprecated function behaving like EVP_MD_CTX_create(). EVP_MD_CTX_cleanup() is a deprecated function behaving like EVP_MD_CTX_reset(). EVP_MD_CTX_destroy() is a deprecated function behaving like EVP_MD_CTX_free() (not listed here). New applications should use the EVP_MD_CTX_new(), EVP_MD_CTX_reset(), and EVP_MD_CTX_free() functions.

EVP_MD_CTX_md() returns the digest algorithm (an EVP_MD) associated with the message digest context ctx.

EVP_DigestInit_ex() initializes the digest operation with digest type. If engine is not NULL, it is used to supply the implementation. If type is NULL, the digest specified during the call to EVP_MD_CTX_new() is used.

EVP_DigestUpdate() hashes count bytes of data at data into the digest context ctx. This function may be called multiple times.

EVP_DigestFinal_ex() computes the digest value from the data in ctx and places it into md. The digest length is placed into *s. If md is not NULL, it must be large enough to hold the digest. The digest context ctx is *not* cleaned up. This allows the digest context to be reused for another digest operation by calling EVP_DigestInit_ex() or EVP_MD_CTX_reset() for example.

EVP_Digest() is a simple wrapper function to hash cnt bytes of data at d using the digest type in a one-shot operation and place the digest value into md, and, unless s is NULL, the length of the digest in bytes into *s. This wrapper uses a temporary digest context and passes its arguments to EVP_DigestInit_ex(), EVP_DigestUpdate(), and EVP_DigestFinal_ex() internally. The ENGINE *engine argument is always ignored and passing NULL is recommended.

EVP_MD_CTX_copy_ex() can be used to copy the message digest state from in to out. This is useful if large amounts of data are to be hashed which only differ in the last few bytes.

EVP_DigestInit() is a deprecated function behaving like EVP_DigestInit_ex() except that it requires EVP_MD_CTX_reset() before it can be used on a context that was already used.

EVP_DigestFinal() is a deprecated function behaving like EVP_DigestFinal_ex() except that the digest context ctx is automatically cleaned up after use by calling EVP_MD_CTX_reset() internally.

EVP_MD_CTX_copy() is a deprecated function behaving like EVP_MD_CTX_copy_ex() except that it requires EVP_MD_CTX_reset() before a context that was already used can be passed as out.

EVP_sha224(), EVP_sha256(), EVP_sha384(), EVP_sha512(), and EVP_ripemd160() return EVP_MD structures for the SHA-224, SHA-256, SHA-384, SHA-512 and RIPEMD-160 digest algorithms respectively.

EVP_sha512_224() and EVP_sha512_256() return an EVP_MD structure that provides the truncated SHA-512 variants SHA-512/224 and SHA-512/256, respectively.

EVP_md_null() is a "null" message digest that does nothing: i.e. the hash it returns is of zero length.

EVP_get_digestbyname(), EVP_get_digestbynid(), and EVP_get_digestbyobj() return an EVP_MD structure when passed a digest name, a digest NID, or an ASN1_OBJECT structure respectively.

EVP_get_digestbynid() and EVP_get_digestbyobj() are implemented as macros.

The EVP interface to message digests should almost always be used in preference to the low-level interfaces. This is because the code then becomes transparent to the digest used and much more flexible.

The ENGINE *engine argument is always ignored and passing NULL is recommended.

The functions EVP_DigestInit(), EVP_DigestFinal(), and EVP_MD_CTX_copy() are obsolete but are retained to maintain compatibility with existing code. New applications should use EVP_DigestInit_ex(), EVP_DigestFinal_ex(), and EVP_MD_CTX_copy_ex() because they can efficiently reuse a digest context instead of initializing and cleaning it up on each call.

If digest contexts are not cleaned up after use, memory leaks will occur.

RETURN VALUES

EVP_MD_CTX_new() and EVP_MD_CTX_create() return the new EVP_MD_CTX object or NULL for failure.

EVP_MD_CTX_reset(), EVP_MD_CTX_init(), and EVP_MD_CTX_cleanup() always return 1.

EVP_DigestInit_ex(), EVP_DigestUpdate(), EVP_DigestFinal_ex(), EVP_Digest(), EVP_MD_CTX_copy_ex(), EVP_DigestInit(), EVP_DigestFinal(), and EVP_MD_CTX_copy() return 1 for success or 0 for failure.

EVP_MD_CTX_md() returns the EVP_MD object used by ctx, or NULL if ctx is NULL or does not have any message digest algorithm assigned yet.

EVP_md_null(), EVP_sha224(), EVP_sha256(), EVP_sha384(), EVP_sha512(), EVP_sha512_224(), EVP_sha512_256(), and EVP_ripemd160() return pointers to constant static objects owned by the library.

EVP_get_digestbyname(), EVP_get_digestbynid(), and EVP_get_digestbyobj() return either an EVP_MD structure or NULL if an error occurs.

EXAMPLES

This example digests the data "Test Message\n" and "Hello World\n", using the digest name passed on the command line.

#include <stdio.h>
#include <string.h>
#include <openssl/evp.h>

int
main(int argc, char *argv[])
{
	EVP_MD_CTX *mdctx;
	const EVP_MD *md;
	const char mess1[] = "Test Message\n";
	const char mess2[] = "Hello World\n";
	unsigned char md_value[EVP_MAX_MD_SIZE];
	unsigned int md_len, i;

	if (argc <= 1) {
		printf("Usage: mdtest digestname\n");
		exit(1);
	}

	md = EVP_get_digestbyname(argv[1]);
	if (md == NULL) {
		printf("Unknown message digest %s\n", argv[1]);
		exit(1);
	}

	mdctx = EVP_MD_CTX_new();
	EVP_DigestInit_ex(mdctx, md, NULL);
	EVP_DigestUpdate(mdctx, mess1, strlen(mess1));
	EVP_DigestUpdate(mdctx, mess2, strlen(mess2));
	EVP_DigestFinal_ex(mdctx, md_value, &md_len);
	EVP_MD_CTX_free(mdctx); /* Use EVP_MD_CTX_free() with EVP_MD_CTX_new() */

	printf("Digest is: ");
	for(i = 0; i < md_len; i++)
		printf("%02x", md_value[i]);
	printf("\n");

	return 0;
}

HISTORY

EVP_DigestInit(), EVP_DigestUpdate(), and EVP_DigestFinal() first appeared in SSLeay 0.5.1. EVP_md_null() and EVP_get_digestbyname() first appeared in SSLeay 0.8.0. EVP_get_digestbynid() and EVP_get_digestbyobj() first appeared in SSLeay 0.8.1. EVP_ripemd160() first appeared in SSLeay 0.9.0. All these functions have been available since OpenBSD 2.4.

EVP_MD_CTX_copy() first appeared in OpenSSL 0.9.2b and has been available since OpenBSD 2.6.

EVP_MD_CTX_md() first appeared in OpenSSL 0.9.5 and has been available since OpenBSD 2.7.

EVP_MD_CTX_init(), EVP_MD_CTX_create(), EVP_MD_CTX_cleanup(), EVP_MD_CTX_destroy(), EVP_DigestInit_ex(), EVP_DigestFinal_ex(), EVP_Digest(), and EVP_MD_CTX_copy_ex() first appeared in OpenSSL 0.9.7 and have been available since OpenBSD 3.2.

y EVP_sha512() aparecieron por primera vez en OpenSSL 0.9.7h y 0.9.8a y han estado disponibles desde OpenBSD 4.0.
