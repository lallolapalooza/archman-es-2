SSL_READ_EARLY_DATA(3) Manual de funciones de la biblioteca SSL_READ_EARLY_DATA(3)

NOMBRE

SSL_CTX_set_max_early_data, SSL_set_max_early_data, SSL_SESSION_set_max_early_data, SSL_CTX_get_max_early_data, SSL_get_max_early_data, SSL_SESSION_get_max_early_data, SSL_write_early_data, SSL_read_early_data, SSL_get_early_data_status — transmitir datos de aplicación durante el handshake

uint32_t
SSL_get_max_early_data(const SSL *ssl);

uint32_t
SSL_SESSION_get_max_early_data(const SSL_SESSION *session);

int
SSL_write_early_data(SSL *ssl, const void *buf, size_t len, size_t *written);

int
SSL_read_early_data(SSL *ssl, void *buf, size_t maxlen, size_t *readbytes);

int
SSL_get_early_data_status(const SSL *ssl);

DESCRIPCIÓN

En LibreSSL, estas funciones no tienen ningún efecto. Solo se proporcionan porque algunos programas de aplicación esperan que la API esté disponible cuando se soporta TLSv1.3. Se desaconseja encarecidamente el uso de estas funciones porque, incluso cuando se implementan y utilizan según lo diseñado, proporcionan un beneficio marginal, tienen una semántica absurdamente complicada y, cuando se utilizan, los descuidos inadvertidos probablemente causen graves vulnerabilidades de seguridad.

Si se utilizan estas funciones, otras implementaciones de TLS pueden permitir la transferencia de datos de aplicación durante el handshake inicial. Incluso cuando se usan según lo diseñado, la seguridad de la conexión se ve comprometida; en particular, los datos de la aplicación se intercambian con pares no autenticados y no hay reenvío secreto. Otras desventajas incluyen un mayor riesgo de ataques de repetición.

SSL_CTX_set_max_early_data(), SSL_set_max_early_data() y SSL_SESSION_set_max_early_data() pretenden configurar el número máximo de bytes por sesión que se pueden transmitir durante el handshake. Con LibreSSL, todos los argumentos son ignorados.

Un punto final puede intentar enviar datos de aplicación con SSL_write_early_data() durante el handshake. Con LibreSSL, tales intentos siempre fallan y establecen *written en 0.

Un servidor puede intentar leer datos de aplicación del cliente usando SSL_read_early_data() durante el handshake. Con LibreSSL, no se aceptan tales datos y *readbytes siempre se establece en 0.

VALORES DE RETORNO

SSL_CTX_set_max_early_data(), SSL_set_max_early_data(), y SSL_SESSION_set_max_early_data() devuelven 1 para éxito o 0 para fallo. Con LibreSSL, siempre tienen éxito.

SSL_CTX_get_max_early_data(), SSL_get_max_early_data(), y SSL_SESSION_get_max_early_data() devuelven el número máximo de bytes de datos de aplicación que se aceptarán del par durante el handshake. Con LibreSSL, siempre devuelven 0.

SSL_write_early_data() devuelve 1 para éxito o 0 para fallo. Con LibreSSL, siempre falla.

Con LibreSSL, SSL_read_early_data() siempre devuelve SSL_READ_EARLY_DATA_FINISH en el lado del servidor y SSL_READ_EARLY_DATA_ERROR en el lado del cliente. SSL_READ_EARLY_DATA_SUCCESS puede ocurrir con otras implementaciones, pero no con LibreSSL.

Con LibreSSL, SSL_get_early_data_status() siempre devuelve SSL_EARLY_DATA_REJECTED. Con otras implementaciones, también podría devolver SSL_EARLY_DATA_NOT_SENT o SSL_EARLY_DATA_ACCEPTED.
