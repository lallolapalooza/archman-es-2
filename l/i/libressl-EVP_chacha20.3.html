EVP_CHACHA20(3) Manual de Funciones de Biblioteca EVP_CHACHA20(3)

NOMBRE

EVP_chacha20, EVP_chacha20_poly1305 — Cifrador de flujo ChaCha20 para EVP

SINOPSIS

biblioteca «libcrypto»
#include <openssl/evp.h>

const EVP_CIPHER *
EVP_chacha20(void);

const EVP_CIPHER *
EVP_chacha20_poly1305(void);

DESCRIPCIÓN

EVP_chacha20() proporciona el cifrador de flujo ChaCha20 en el marco EVP. EVP_EncryptInit_ex(3), EVP_DecryptInit_ex(3), y EVP_CipherInit_ex(3) toman un argumento key de 32 bytes = 256 bits y un argumento iv de 16 bytes = 128 bits, utilizando internamente ChaCha_set_key(3) y ChaCha_set_iv(3). Los 8 bytes inferiores = 64 bits de iv se utilizan como contador y los 8 bytes restantes se utilizan como vector de inicialización de ChaCha_set_iv(3). EVP_EncryptUpdate(3), EVP_EncryptFinal_ex(3), EVP_DecryptUpdate(3), y EVP_DecryptFinal_ex(3) utilizan internamente ChaCha(3) para realizar el cifrado y descifrado. EVP_CIPHER_CTX_ctrl(3) siempre falla para objetos ctx creados desde EVP_chacha20().

EVP_chacha20_poly1305() proporciona cifrado autenticado con ChaCha20-Poly1305. A menos que se requiera compatibilidad con otras implementaciones como OpenSSL o BoringSSL, se recomienda usar EVP_AEAD_CTX_init(3) con EVP_aead_chacha20_poly1305(3) en su lugar, ya que el código se vuelve transparente al cifrado AEAD utilizado, más flexible y menos propenso a errores.

Con EVP_chacha20_poly1305(), EVP_EncryptInit_ex(3), EVP_DecryptInit_ex(3), y EVP_CipherInit_ex(3) toman un argumento key de 32 bytes = 256 bits y un argumento iv de 12 bytes = 96 bits. Esto soporta datos autenticados adicionales (AAD) y produce una etiqueta de autenticación de 128 bits. La constante EVP_CHACHAPOLY_TLS_TAG_LEN especifica la longitud de la etiqueta de autenticación en bytes y tiene un valor de 16.

Los siguientes argumentos de type son soportados para EVP_CIPHER_CTX_ctrl(3):

EVP_CTRL_AEAD_GET_TAG
Copia el número de bytes indicados por el argumento arg de la etiqueta a la ubicación indicada por el argumento ptr; debe llamarse después de EVP_EncryptFinal_ex(3). Esta operación de control falla si el ctx no está configurado para cifrado o si arg es menor que 1 o mayor que 16.
EVP_CTRL_AEAD_SET_TAG
Copia el número de bytes indicados por el argumento arg de la ubicación indicada por el argumento ptr y los designa como la longitud y etiqueta esperada, haciendo que las llamadas posteriores a EVP_DecryptFinal_ex(3) fallen si la etiqueta calculada durante el descifrado no coincide. Se recomienda encarecidamente especificar arg como exactamente 16. De lo contrario, solo se puede comparar la parte inicial de la etiqueta y las discrepancias cerca del final de la etiqueta pueden ser ignoradas silenciosamente. Esta operación de control falla si el ctx está configurado para cifrado o si arg es menor que 1 o mayor que 16. Si el argumento ptr es un puntero NULL, esta operación de control tiene éxito sin tener ningún efecto.
EVP_CTRL_AEAD_SET_IV_FIXED
Establece el vector de inicialización leyendo los 12 bytes apuntados por el argumento ptr, independientemente de EVP_EncryptInit_ex(3), EVP_DecryptInit_ex(3), y EVP_CipherInit_ex(3). Esta operación de control falla si el argumento arg no es exactamente 12.
EVP_CTRL_AEAD_SET_IVLEN
Instruye a las siguientes llamadas a EVP_EncryptInit_ex(3), EVP_DecryptInit_ex(3), o EVP_CipherInit_ex(3) para esperar un argumento iv más corto que el valor predeterminado de 12 bytes; el argumento arg especifica el número de bytes a utilizar. Las funciones de inicialización solo leerán el número especificado de bytes más pequeño de iv y los rellenarán internamente con ceros por la izquierda. No se recomienda usar esto ya que es probablemente más frágil y menos probado que el método equivalente de simplemente proporcionar un iv de tamaño completo. Esta operación de control falla si arg es menor que 1 o mayor que 16.
EVP_CTRL_INIT
Establece la longitud del vector de inicialización al valor predeterminado de 12 bytes y borra el estado interno de Poly1305. El programa de aplicación generalmente no necesita invocar esta operación de control manualmente, ya que se llama automáticamente internamente por EVP_EncryptInit_ex(3), EVP_DecryptInit_ex(3), y EVP_CipherInit_ex(3).

VALORES DE RETORNO

EVP_chacha20() y EVP_chacha20_poly1305() devuelven punteros a objetos estáticos EVP_CIPHER que contienen las implementaciones del cifrado simétrico.

Si ctx se creó a partir de EVP_chacha20() o EVP_chacha20_poly1305(), EVP_CIPHER_CTX_ctrl(3) devuelve 1 en caso de éxito o 0 en caso de fallo.

HISTORIA

EVP_chacha20() apareció por primera vez en OpenBSD 5.6.

EVP_chacha20_poly1305() apareció por primera vez en OpenSSL 1.1.0 y ha estado disponible desde OpenBSD 7.2.

ADVERTENCIAS

Las publicaciones y el código originales de Adam Langley utilizaron una construcción AEAD modificada que es incompatible con el estilo común utilizado por AEAD en TLS y es incompatible con RFC 7905:

A. Langley y W. Chang, ChaCha20 and Poly1305 based Cipher Suites for TLS, draft-agl-tls-chacha20poly1305-04, November 2013.

Y. Nir y A. Langley, ChaCha20 and Poly1305 for IETF Protocols, RFC 8439, May 2018.

En particular, la versión original utilizaba un nonce de 8 en lugar de 12 bytes.
