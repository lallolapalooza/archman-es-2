LIBARCHIVE-FORMATS(5) Manual de formatos de archivo LIBARCHIVE-FORMATS(5)

NOMBRE

libarchive-formats — formatos de archivo soportados por la biblioteca libarchive

DESCRIPCIÓN

La biblioteca libarchive(3) lee y escribe una variedad de formatos de archivo en streaming. En general, todos estos formatos de archivo consisten en una serie de "entradas". Cada entrada almacena un único objeto del sistema de archivos, como un archivo, directorio o enlace simbólico.

Lo siguiente proporciona una breve descripción de cada formato soportado por libarchive, con información sobre extensiones reconocidas o limitaciones del soporte actual de la biblioteca. Tenga en cuenta que el hecho de que un formato sea soportado por libarchive no implica que un programa que use libarchive soportará ese formato. Las aplicaciones que usan libarchive especifican qué formatos desean soportar, aunque muchos programas utilizan las funciones de conveniencia de libarchive para habilitar todos los formatos soportados.

Formatos de Tar

La biblioteca libarchive(3) puede leer la mayoría de los archivos tar. Puede escribir los formatos "ustar" y "pax interchange" del estándar POSIX, así como el formato tar v7 y un subconjunto del formato GNU tar heredado.

Todos los formatos tar almacenan cada entrada en uno o más registros de 512 bytes. El primer registro se utiliza para metadatos del archivo, incluyendo el nombre del archivo, la marca de tiempo y la información del modo, y los datos del archivo se almacenan en registros posteriores. Variantes posteriores han ampliado esto apropiándose de áreas no definidas del registro de cabecera, extendiendo la cabecera a múltiples registros, o almacenando entradas especiales que modifican la interpretación de las entradas posteriores.

gnutar
La biblioteca libarchive(3) puede leer la mayoría de los archivos tar en formato GNU. Actualmente soporta las extensiones GNU más populares, incluyendo el soporte moderno para nombres de archivo y enlaces largos, así como datos de tiempo de acceso (atime) y tiempo de cambio de inode (ctime). La biblioteca libarchive no soporta archivos multivolumen, ni el antiguo formato GNU de nombres de archivo largos. Puede leer entradas de archivos dispersos de GNU, incluyendo los nuevos formatos basados en POSIX.

La biblioteca libarchive(3) puede escribir en formato tar GNU, incluyendo soporte para nombres de archivo y enlaces largos, así como datos de tiempo de acceso y cambio de inode.

pax
La biblioteca libarchive(3) puede leer y escribir archivos en formato de intercambio pax conforme a POSIX. Los archivos en formato de intercambio pax son una extensión del formato ustar más antiguo que añade una entrada separada con atributos adicionales almacenados como pares clave/valor inmediatamente antes de cada entrada regular. La presencia de estas entradas adicionales es la única diferencia entre el formato de intercambio pax y el formato ustar más antiguo. Los atributos extendidos tienen una longitud ilimitada y se almacenan como cadenas Unicode UTF-8. Las palabras clave definidas en el estándar están en minúsculas; los proveedores pueden definir claves personalizadas precediéndolas con el nombre del proveedor en mayúsculas. Al escribir archivos pax, libarchive utiliza muchas de las claves SCHILY definidas por el archivador "star" de Joerg Schilling y algunas claves LIBARCHIVE. La biblioteca libarchive puede leer la mayoría de las claves SCHILY y la mayoría de las claves GNU introducidas por GNU tar. Ignora silenciosamente cualquier palabra clave que no entienda.

El formato de intercambio pax convierte los nombres de archivo a Unicode y los almacena utilizando la codificación UTF-8. Antes de libarchive 3.0, libarchive asumía erróneamente que las rutinas de caracteres anchos del sistema soportaban Unicode de forma nativa. Esto hacía que manejara incorrectamente nombres de archivo no ASCII en sistemas que no cumplían esta suposición.

pax restringido
La biblioteca libarchive también puede escribir archivos pax en los que intenta suprimir la entrada de atributos extendidos siempre que sea posible. El resultado será idéntico a un archivo ustar a menos que la entrada de atributos extendidos sea necesaria para almacenar un nombre de archivo largo, un enlace largo, ACL extendidas, banderas de archivo, o si alguna de los datos estándar de ustar (nombre de usuario, nombre de grupo, UID, GID, etc.) no puede representarse completamente en la cabecera ustar. En todos los casos, el resultado puede ser desarchivado por cualquier programa que pueda leer archivos en formato de intercambio pax conforme a POSIX. Los programas que leen correctamente el formato ustar (ver más abajo) también podrán leer este formato; cualquier atributo extendido se extraerá como archivos separados almacenados en directorios PaxHeader.
ustar
La biblioteca libarchive puede leer y escribir este formato. Este formato tiene las siguientes limitaciones:
  • Los números mayores y menores de dispositivos están limitados a 21 bits. Los nodos con números mayores no se añadirán al archivo.
  • Los nombres de ruta en el archivo están limitados a 255 bytes. (Más corto si no hay un carácter / en el lugar correcto.)
  • Los enlaces simbólicos y los enlaces físicos se almacenan en el archivo con el nombre del archivo referenciado. Este nombre está limitado a 100 bytes.
  • Los atributos extendidos, las banderas de archivo y otra información de seguridad extendida no pueden almacenarse.
  • Las entradas del archivo están limitadas a 8 gigabytes de tamaño.
Tenga en cuenta que el formato de intercambio pax no tiene ninguna de estas restricciones. El formato ustar es antiguo y ampliamente soportado. Se recomienda cuando la compatibilidad es la principal preocupación.
v7
La biblioteca libarchive puede leer y escribir el formato tar heredado v7. Este formato tiene las siguientes limitaciones:
  • Solo se pueden archivar archivos regulares, directorios y enlaces simbólicos. Los nodos de dispositivo de bloque y carácter, FIFOs y sockets no pueden archivarse.
  • Los nombres de ruta en el archivo están limitados a 100 bytes.
  • Los enlaces simbólicos y los enlaces físicos se almacenan en el archivo con el nombre del archivo referenciado. Este nombre está limitado a 100 bytes.
  • La información de usuario y grupo se almacena como IDs numéricos; no hay provición para almacenar nombres de usuario o grupo.
  • Los atributos extendidos, las banderas de archivo y otra información de seguridad extendida no pueden almacenarse.
  • Las entradas del archivo están limitadas a 8 gigabytes de tamaño.
En general, los usuarios deberían preferir el formato ustar para la portabilidad, ya que el formato tar v7 es menos útil y menos portable.

La biblioteca libarchive también lee una variedad de extensiones de uso común al formato tar básico. Estas extensiones se reconocen automáticamente siempre que aparecen.

Extensiones numéricas.
Los estándares POSIX requieren que los campos numéricos de longitud fija se escriban con algún carácter reservado para terminadores. Libarchive permite que estos campos se escriban sin caracteres terminadores. Esto extiende el rango permitido; en particular, los archivos ustar con esta extensión pueden soportar entradas de hasta 64 gigabytes de tamaño. Libarchive también reconoce valores base-256 en la mayoría de los campos numéricos. Esto elimina esencialmente todas las limitaciones en el tamaño del archivo, la marca de tiempo de modificación y los números de dispositivo.
Extensiones de Solaris
Libarchive reconoce registros ACL y de atributos extendidos escritos por el tar de Solaris.

El primer programa tar apareció en Seventh Edition Unix en 1979. El primer estándar oficial para el formato de archivo tar fue el formato "ustar" (Unix Standard Tar) definido por POSIX en 1988. POSIX.1-2001 extendió el formato ustar para crear el formato "pax interchange".

Formatos de Cpio

La biblioteca libarchive puede leer y escribir varias variantes comunes de cpio. Un archivo cpio almacena cada entrada como una cabecera de tamaño fijo seguida de un nombre de archivo de longitud variable y datos de longitud variable. A diferencia del formato tar, el formato cpio solo realiza un relleno mínimo de la cabecera o de los datos del archivo. Existen varias variantes de cpio, que difieren principalmente en cómo almacenan la cabecera inicial: algunas almacenan los valores como números octales o hexadecimales en ASCII, otras como valores binarios de orden de bytes y longitud variables.

NAME

libarchive-formats

overview of archive formats supported by libarchive

DESCRIPTION

The libarchive library supports a wide range of archive formats. This document provides a brief overview of the most common formats and libarchive's support for them.

AR

Libarchive can read and write archives in the standard Unix ar format. This includes support for BSD-style and GNU-style ar archives.

CPIO

Libarchive can read and write archives in the CoSpcPIO format. It supports both the SVR4 and the BSD variants of the format, as well as various binary and ASCII encodings.

ISO9660

Libarchive can read ISO9660 CD-ROM filesystem images. This includes support for the Rock Ridge and Joliet extensions.

MTREE

Libarchive can read and write mtree directory listings. This format is often used to specify the desired state of a directory hierarchy.

TAR

Libarchive can read and write archives in the tar format. It supports various tar variants, including:

  • The original tar format.

  • The POSIX tar format (ustar).

  • The GNU tar format, including support for large files and extended attributes.

  • The pax interchange format.

Libarchive also supports common compression methods used with tar archives, such as gzip, bzip2, and xz.

ZIP

Libarchive can read and write archives in the ZIP format. It supports standard ZIP compression as well as various compression methods used by PKWARE.
