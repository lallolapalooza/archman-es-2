NOMBRE

libpipewire-module-filter-chain - Cadena de Filtros

DESCRIPCIÓN

La cadena de filtros permite crear un grafo de procesamiento arbitrario a partir de filtros LADSPA, LV2 y nativos.

Este filtro puede convertirse en un sumidero/fuente virtual o intercalado entre cualesquiera 2 nodos del grafo.

La cadena de filtros se construye con 2 flujos, un flujo de captura que proporciona la entrada a la cadena de filtros y un flujo de reproducción que envía el flujo filtrado a los siguientes nodos del grafo.

Dado que ambos extremos de la cadena de filtros se construyen con flujos, el gestor de sesiones puede gestionar la configuración y la conexión con los sumideros y fuentes automáticamente.

NOMBRE DEL MÓDULO

libpipewire-module-filter-chain

OPCIONES DEL MÓDULO

  • node.description: un nombre legible para la cadena de filtros
  • filter.graph = []: una descripción del grafo de filtros a ejecutar, véase más abajo
  • capture.props = {}: propiedades que se pasarán al flujo de entrada
  • playback.props = {}: propiedades que se pasarán al flujo de salida

DESCRIPCIÓN DEL GRAFO DE FILTROS

La estructura general de la descripción del grafo es la siguiente:

 filter.graph = {
     nodes = [
         {
             type = <ladspa | lv2 | builtin | sofa>
             name = <nombre>
             plugin = <plugin>
             label = <etiqueta>
             config = {
                 <clave_config> = <valor> ...
             }
             control = {
                 <nombre_control|índice_control> = <valor> ...
             }
         }
         ...
     ]
     links = [
         { output = <nombre_puerto> input = <nombre_puerto> }
         ...
     ]
     inputs = [ <nombre_puerto> ... ]
     outputs = [ <nombre_puerto> ... ]
     capture.volumes = [
         { control = <nombre_puerto>  min = <valor>  max = <valor>  scale = <escala> } ...
     ]
     playback.volumes = [
         { control = <nombre_puerto>  min = <valor>  max = <valor>  scale = <escala> } ...
     ]
}

Nodos

Los nodos describen los filtros de procesamiento en el grafo. Utilice una herramienta como lv2ls o listplugins para obtener una lista de los plugins, etiquetas y nombres de puertos disponibles.

  • type es uno de ladspa, lv2, builtin, sofa o ebur128.
  • name es el nombre para este nodo; es posible que lo necesite más tarde para referirse a este nodo y sus puertos al configurar controles o crear enlaces.
  • plugin es el nombre del plugin específico del tipo.
•
Para los plugins LADSPA, añadirá .so para encontrar el objeto compartido con ese nombre en la ruta de plugins de LADSPA.
•
Para LV2, esta es la URI del plugin obtenida con lv2ls.
•
Para builtin, sofa y ebur128, esto se ignora.
•
label es el filtro específico del tipo dentro del plugin.
•
Para LADSPA, esta es la etiqueta.
•
Para LV2, esto no se utiliza.
•
Para builtin, sofa y ebur128, este es el nombre del filtro a utilizar.
  • config contiene una sección de configuración específica del filtro. Algunos plugins la necesitan. (convolutor, sofa, delay, ...)
  • control contiene los valores iniciales para los puertos de control del filtro. Normalmente se proporcionan con el nombre del puerto, pero también es posible dar el índice de control como clave.

Enlaces

Se pueden crear enlaces entre puertos de nodos. El nombre del puerto se proporciona como <nombre_nodo>:<nombre_puerto>.

Puedes hacer "tee" (duplicar) la salida de los filtros a múltiples otros filtros. Necesitarás usar un mezclador si quieres que la salida de múltiples filtros vaya a un puerto de entrada de un filtro.

Los enlaces se pueden omitir cuando el grafo tiene solo 1 filtro.

Entradas y Salidas

Estos son los puertos de entrada y salida de la definición del grafo. Su número define el número de canales utilizados por la cadena de filtros.

El <nombre_puerto> puede ser nulo cuando un canal debe ser ignorado.

Cada entrada/salida en el grafo solo puede estar conectada a una entrada/salida de filtro. Necesitas usar el filtro nativo copy si la señal de entrada necesita ser enrutada a múltiples filtros. Necesitas usar el plugin nativo mixer si múltiples salidas del grafo necesitan ir a una corriente de salida.

Las entradas y salidas se pueden omitir, en cuyo caso la cadena de filtros utilizará todas las entradas del primer filtro y todas las salidas del último nodo de filtro. El grafo se duplicará entonces tantas veces como sea necesario para que coincida con el número de canales de entrada/salida de los flujos.

Volúmenes

Normalmente, el volumen del sumidero/fuente es manejado por el volumen del software del flujo. Con las propiedades capture.volumes y playback.volumes, esto puede ser manejado por un puerto de control en el grafo en su lugar. Usa capture.volumes para el volumen de la entrada del filtro (cuando, por ejemplo, se usa como sumidero). Usa playback,volumes para el volumen de la salida del filtro (cuando, por ejemplo, se usa como fuente).

Los valores min y max (predeterminados 0.0 y 1.0 respectivamente) se pueden usar para escalar y traducir los valores de volumen min y max.

Normalmente, los valores de control son lineales y se asume que el plugin no realiza ninguna escala a los valores. Esto se puede cambiar con la propiedad scale. Por defecto, es lineal, pero se puede establecer en cúbica cuando el control aplica una transformación cúbica.

FILTROS NATIVOS

Hay algunos filtros nativos útiles disponibles. Los seleccionas con la etiqueta del nodo del filtro.

Mezclador

Utiliza el plugin mezclador si tienes múltiples señales de entrada que necesitan ser mezcladas juntas.

El plugin mezclador tiene hasta 8 puertos de entrada etiquetados "In 1" a "In 8" y cada uno con un control de ganancia etiquetado "Gain 1" a "Gain 8". Hay un puerto de salida etiquetado "Out". Los puertos de entrada no utilizados se ignorarán y no causarán sobrecarga.

Copiar

Utiliza el plugin de copia si necesitas copiar una señal de entrada de flujo a múltiples filtros.

Tiene un puerto de entrada "In" y un puerto de salida "Out".

Biquads

Los biquads se pueden utilizar para realizar todo tipo de filtrado. También se utilizan al crear ecualizadores.

Todos los filtros biquad tienen un puerto de entrada "In" y un puerto de salida "Out". Tienen un control "Freq", "Q" y "Gain". Su significado depende del biquad particular que se utilice. Los biquads también tienen puertos "b0", "b1", "b2", "a0", "a1" y "a2" que son de solo lectura, excepto para el biquad bq_raw, que puede configurar valores predeterminados según la tasa del grafo y cambiarlos en tiempo de ejecución.

Nos referimos a https://arachnoid.com/BiQuadDesigner/index.html para una explicación de los controles.

Se pueden utilizar las siguientes etiquetas:

  • bq_lowpass un filtro paso bajo.
  • bq_highpass un filtro paso alto.
  • bq_bandpass un filtro paso banda.
  • bq_lowshelf un filtro estante bajo.
  • bq_highshelf un filtro estante alto.
  • bq_peaking un filtro de picos.
  • bq_notch un filtro de muesca.
  • bq_allpass un filtro paso todo.
  • bq_raw un filtro biquad crudo. Necesitas una sección config para especificar los coeficientes por tasa de muestreo. Se seleccionan los coeficientes de la tasa de muestreo más cercana a la tasa del grafo:
filter.graph = {
    nodes = [
        {
            type   = builtin
            name   = ...
            label  = bq_raw
            config = {
                coefficients = [
                    { rate =  44100, b0=.., b1=.., b2=.., a0=.., a1=.., a2=.. },
                    { rate =  48000, b0=.., b1=.., b2=.

Ecualizador Paramétrico

El ecualizador paramétrico encadena una serie de biquads. Es más eficiente que especificar un número de biquads encadenados y también puede cargar la configuración desde un archivo.

El ecualizador paramétrico admite procesamiento multicanal y tiene 8 puertos de entrada y 8 de salida que no necesitan estar todos conectados. Los puertos se denominan Entrada 1 a Entrada 8 y Salida 1 a Salida 8.

filter.graph = {
    nodes = [
        {
            type   = builtin
            name   = ...
            label  = param_eq
            config = {
                filename = "..."
                #filename1 = "...", filename2 = "...", ...
                filters = [
                    { type = ..., freq = ..., gain = ..., q = ... },
                    { type = ..., freq = ..., gain = ..., q = ... },
                    ....
                ]
                #filters1 = [ ... ], filters2 = [ ... ], ...
            }
            ...
        }
    }
    ...
}

Se puede especificar un nombre de archivo o una matriz de filtros. La configuración se utilizará para todos los canales. Alternativamente, se pueden usar filenameX o filtersX, donde X es el número de canal (entre 1 y 8), para cargar una configuración específica del canal.

El nombre del archivo debe apuntar a una configuración de ecualizador paramétrico generada a partir del proyecto AutoEQ o Squiglink. Ambos proyectos permiten ecualizar auriculares o monitores intrauditivos a una curva objetivo.

Un ejemplo popular de lo anterior es ecualizar a la curva objetivo de Harman o ecualizar un auricular/IEM a otro.

Para AutoEQ, ver https://github.com/jaakkopasanen/AutoEq. Para SquigLink, ver https://squig.link/.

La configuración del ecualizador paramétrico generada desde AutoEQ o Squiglink tiene el siguiente formato.

Preamp: -6.8 dB
Filter 1: ON PK Fc 21 Hz Gain 6.7 dB Q 1.100
Filter 2: ON PK Fc 85 Hz Gain 6.9 dB Q 3.000
Filter 3: ON PK Fc 110 Hz Gain -2.6 dB Q 2.700
Filter 4: ON PK Fc 210 Hz Gain 5.9 dB Q 2.100
Filter 5: ON PK Fc 710 Hz Gain -1.0 dB Q 0.600
Filter 6: ON PK Fc 1600 Hz Gain 2.3 dB Q 2.700

Fc, Gain y Q especifican la frecuencia, la ganancia y el factor Q respectivamente. La cuarta columna puede ser PK, LSC o HSC, especificando un filtro de picos, estantería baja o estantería alta respectivamente. La mayoría de las veces, solo intervienen filtros de picos.

Los filtros (o filtersX específicos del canal, donde X es el canal entre 1 y 8) pueden contener una matriz de objetos de especificación de filtro con las siguientes claves:

type especifica el tipo de filtro, elige uno de las etiquetas biquad disponibles. freq es la frecuencia pasada al biquad. gain es la ganancia pasada al biquad. q es el Q pasado al biquad.

Esto hace posible usar también el ecualizador paramétrico sin un archivo y con todos los biquads disponibles.

Convolucionador

El convolucionador se puede utilizar para aplicar una respuesta de impulso a una señal. Se suele utilizar para reverberaciones o sonido envolvente virtual. El convolucionador está implementado con una implementación FFT rápida.

El convolucionador tiene un puerto de entrada "In" y un puerto de salida "Out". Requiere una sección de configuración en la declaración del nodo en este formato:

filter.graph = {
    nodes = [
        {
            type   = builtin
            name   = ...
            label  = convolver
            config = {
                blocksize = ...
                tailsize = ...
                gain = ...
                delay = ...
                filename = ...
                offset = ...
                length = ...
                channel = ...
                resample_quality = ...
            }
            ...
        }
    }
    ...
}
  • blocksize especifica el tamaño de los bloques a utilizar en la FFT. Es un valor entre 64 y 256. Cuando no se especifica, este valor se calcula automáticamente a partir del número de muestras en el archivo.
  • tailsize especifica el tamaño de los bloques de cola a utilizar en la FFT.
  • gain la ganancia general a aplicar al archivo IR.
  • delay El retraso adicional a añadir al IR. Un número flotante se interpretará como segundos y un entero como muestras. Usar el retraso en segundos es independiente de la frecuencia de la gráfica y del IR, y se recomienda.
  • filename El IR a cargar o crear. Los valores posibles son:
•
/hilbert crea una función de Hilbert que se puede usar para desfasar la señal +/-90 grados. La longitud se usará como el número de coeficientes.
•
/dirac crea una función de Dirac que se puede usar como ganancia.
•
Un nombre de archivo para cargar como IR. Este debe ser un formato de archivo compatible con sndfile.
•
[ filename, ... ] una matriz de nombres de archivo. Se utilizará el archivo con la coincidencia de frecuencia de muestreo más cercana con la frecuencia de muestreo de la gráfica.
  • offset El desplazamiento de muestra en el archivo como inicio del IR.
  • length El número de muestras a utilizar como IR.
  • channel El canal a utilizar del archivo como IR.
  • resample_quality La calidad de remuestreo en caso de que el IR no coincida con la frecuencia de muestreo de la gráfica.

Retardo

El retardo se puede utilizar para retrasar una señal en el tiempo.

El retardo tiene un puerto de entrada "In" y un puerto de salida "Out". También tiene un puerto de control "Retraso (s)". Requiere una sección de configuración en la declaración del nodo en este formato:

filter.graph = {
    nodes = [
        {
            type   = builtin
            name   = ...
            label  = delay
            config = {
                "max-delay" = ...
            }
            control = {
                "Delay (s)" = ...
            }
            ...
        }
    }
    ...
}
•
max-delay el retardo máximo en segundos. El parámetro "Retraso (s)" se limitará a este valor.

Invertir

El plugin de inversión se puede utilizar para invertir la fase de la señal.

Tiene un puerto de entrada "In" y un puerto de salida "Out".

Limitar

El plugin de limitación se puede utilizar para limitar las muestras entre valores mínimos y máximos.

Tiene un puerto de entrada "In" y un puerto de salida "Out". También tiene un puerto "Control" y "Notify" para los valores de control.

El resultado final se limita a los valores de control "Min" y "Max".

Lineal

El plugin lineal se puede utilizar para aplicar una transformación lineal a las muestras o valores de control.

Tiene un puerto de entrada "In" y un puerto de salida "Out". También tiene un puerto "Control" y "Notify" para los valores de control.

Los valores de control "Mult" y "Add" se utilizan para configurar la transformación lineal. Cada muestra o valor de control se calculará como: nuevo = viejo * Mult + Add.

Recíproco

El plugin recíproco se puede utilizar para calcular el recíproco (1/x) de las muestras o valores de control.

Tiene un puerto de entrada "In" y un puerto de salida "Out". También tiene un puerto "Control" y "Notify" para los valores de control.

Abs

El plugin abs se puede utilizar para calcular el valor absoluto de las muestras.

Tiene un puerto de entrada "In" y un puerto de salida "Out".

Sqrt

El plugin sqrt se puede utilizar para calcular la raíz cuadrada de las muestras.

Tiene un puerto de entrada "In" y un puerto de salida "Out".

Exp

El plugin exp se puede utilizar para calcular la exponencial (base^x) de las muestras o valores de control.

Tiene un puerto de entrada "In" y un puerto de salida "Out". También tiene un puerto "Control" y "Notify" para los valores de control.

El valor de control "Base" se utiliza para calcular base ^ x para cada muestra.

Log

El plugin log se puede utilizar para calcular el logaritmo de las muestras o valores de control.

Tiene un puerto de entrada "In" y un puerto de salida "Out". También tiene un puerto "Control" y "Notify" para los valores de control.

Los valores de control "Base", "M1" y "M2" se utilizan para calcular out = M2 * log2f(fabsf(in * M1)) / log2f(Base) para cada muestra.

Multiplicar

El plugin mult se puede utilizar para multiplicar muestras.

Tiene 8 puertos de entrada llamados "In 1" a "In 8" y un puerto de salida "Out".

Todas las muestras de los puertos de entrada se multiplican juntas en la salida. Los puertos de entrada no utilizados se ignorarán y no causarán sobrecarga.

Seno

El plugin de seno genera una onda sinusoidal.

Tiene un puerto de salida "Out" y también un puerto de salida de control "notify".

"Freq", "Ampl", "Offset" y "Phase" se pueden utilizar para controlar la frecuencia, amplitud, desplazamiento y fase de la onda sinusoidal.

Máx

Use el plugin max si necesita seleccionar el valor máximo de dos canales.

Tiene dos puertos de entrada "In 1" e "In 2" y un puerto de salida "Out".

bloqueo dc

Use el plugin dcblock implementa un bloqueo de CC.

Tiene 8 puertos de entrada "In 1" a "In 8" y puertos de salida correspondientes "Out 1" a "Out 8". No todos los puertos necesitan estar conectados.

También tiene 1 puerto de entrada de control "R" que controla el

Bloque DC R factor.

Rampa

El plugin de rampa crea una rampa lineal desde Inicio hasta Fin.

Tiene 3 puertos de control de entrada "Inicio", "Fin" y "Duración (s)". También tiene un puerto de salida "Salida". Se creará una rampa lineal desde "Inicio" hasta "Fin" durante una duración dada por el control "Duración (s)" en segundos (fraccionales). El valor actual se almacenará en el puerto de notificación de salida "Actual".

La salida de rampa puede usarse, por ejemplo, como entrada para el plugin mult para crear una rampa de volumen ascendente o descendente. Para una rampa de volumen más gruesa, el valor "Actual" puede usarse en el plugin lineal.

FILTRO SOFA

Hay un filtro SOFA incorporado opcional disponible.

Spatializer

El spatializer se puede usar para colocar el sonido en un espacio 3D.

El spatializer tiene un puerto de entrada "Entrada" y un par estéreo de puertos de salida llamados "Salida I" y "Salida D". Requiere una sección de configuración en la declaración del nodo en este formato:

El control se puede cambiar en tiempo de ejecución para mover los sonidos en el espacio 3D.

filter.graph = {
    nodes = [
        {
            type   = sofa
            name   = ...
            label  = spatializer
            config = {
                blocksize = ...
                tailsize = ...
                filename = ...
            }
            control = {
                "Azimuth" = ...
                "Elevación" = ...
                "Radio" = ...
            }
            ...
        }
    }
    ...
}
  • blocksize especifica el tamaño de los bloques a usar en la FFT. Es un valor entre 64 y 256. Cuando no se especifica, este valor se calcula automáticamente a partir del número de muestras en el archivo.
  • tailsize especifica el tamaño de los bloques de cola a usar en la FFT.
  • filename El archivo SOFA a cargar. Los archivos SOFA suelen terminar en la extensión .sofa y contienen la HRTF para las diversas posiciones espaciales.
  • Azimuth controla el azimut, que es la dirección de la que proviene el sonido en grados entre 0 y 360. 0 es recto hacia adelante. 90 es izquierda, 180 atrás, 270 derecha.
  • Elevación controla la elevación, que es cuán alto/bajo es la señal en grados entre -90 y 90. 0 es recto hacia adelante, 90 es directamente arriba y -90 directamente abajo.
  • Radio controla la distancia de la señal como un valor entre 0 y 100. El valor predeterminado es 1.0.

FILTRO EBUR128

Hay un filtro EBU R128 incorporado opcional disponible.

ebur128

El plugin ebur128 se puede usar para medir la sonoridad de una señal.

Tiene 7 puertos de entrada "Entrada FI", "Entrada FD", "Entrada C", "Entrada SIN USO", "Entrada SI", "Entrada SD" y "Entrada DUAL MONO", correspondientes a los diferentes canales de entrada para EBUR128. No todos los puertos necesitan conectarse para este filtro.

La señal de entrada se pasa sin modificar por los puertos de salida "Salida FI", "Salida FD", "Salida C", "Salida SIN USO", "Salida SI", "Salida SD" y "Salida DUAL MONO".

Hay 7 puertos de control de salida que contienen la información de sonoridad medida y que se pueden usar para controlar el procesamiento del audio. Algunos de estos puertos contienen valores en LUFS, o "Unidades de Sonoridad relativas a la Escala Completa". Estos son valores negativos, más cercanos a 0 son más fuertes. Puedes usar el plugin lufs2gain para convertir este valor a una ganancia para ajustar un volumen (Ver abajo).

"LUFS Momentáneo" contiene la medición de sonoridad momentánea con una ventana de 400ms y un solapamiento del 75%. Funciona principalmente como un medidor R.M.S.

"LUFS a Corto Plazo" contiene la sonoridad a corto plazo en LUFS durante una ventana de 3 segundos.

"LUFS Global" contiene la sonoridad integrada global en LUFS sobre la ventana de historial máximo. "LUFS de Ventana" contiene la sonoridad integrada global en LUFS sobre la ventana de máximo.

"Rango LU" contiene el rango de sonoridad (LRA) en unidades LU.

"Pico" contiene el pico de sonoridad.

"Pico Real" contiene el pico real de sonoridad sobremuestreando la señal. Esto puede reflejar el pico con más precisión en comparación con "Pico".

El nodo también tiene una sección de configuración opcional con configuración adicional:

filter.graph = {
    nodes = [
        {
            type   = ebur128
            name   = ...
            label  = ebur128
            config = {
                max-history = ...
                max-window = ...
                use-histogram = ...
            }
            ...
        }
    ]
    ...
}
  • max-history el historial máximo a mantener en segundos (flotante). Predeterminado a 10.0
  • max-window la ventana máxima a mantener en segundos (flotante). Predeterminado a 0.0 Deberás establecer esto a algún valor para obtener valores de control de salida de "LUFS de Ventana".
  • use-histogram usa el algoritmo de histograma para calcular la sonoridad. Predeterminado a false.

lufs2gain

El plugin lufs2gain se puede usar para convertir valores de control LUFS a ganancia. Necesita una entrada de control LUFS objetivo para impulsar la conversión.

Tiene 2 puertos de control de entrada "LUFS" y "LUFS Objetivo" y producirá 1 valor de control de salida "Ganancia". Esta ganancia se puede usar como entrada para el nodo lineal incorporado, por ejemplo, para ajustar la ganancia.

OPCIONES GENERALES

Opciones con comportamiento bien conocido. La mayoría de las opciones se pueden agregar a la configuración global o a las transmisiones individuales:

  • remote.name
  • audio.rate
  • audio.channels
  • audio.position
  • media.name
  • node.latency
  • node.description
  • node.group
  • node.link.group
  • node.virtual
  • node.name : Ver notas abajo. Si no se especifica, el valor predeterminado es 'filter-chain-PID-MODULEID'.

Propiedades solo de transmisión:

  • media.class
  • node.name : si no se proporciona por transmisión, el node.name global se prefijará con 'input.' y 'output.' para generar un nombre de nodo de transmisión de captura y reproducción, respectivamente.

EJEMPLO DE CONFIGURACIÓN DE UNA FUENTE VIRTUAL

Este ejemplo utiliza el plugin LADSPA rnnoise para crear una nueva fuente virtual.

Ejecutar con pipewire -c filter-chain.conf. La configuración también se puede colocar en pipewire.conf.d/ para ejecutarla dentro del servidor PipeWire.

# ~/.config/pipewire/filter-chain.conf.d/my-filter-chain-1.conf
context.modules = [
{   name = libpipewire-module-filter-chain
    args = {
        node.description =  "Fuente con cancelación de ruido"
        media.name =  "Fuente con cancelación de ruido"
        filter.graph = {
            nodes = [
                {
                    type = ladspa
                    name = rnnoise
                    plugin = ladspa/librnnoise_ladspa
                    label = noise_suppressor_stereo
                    control = {
                        "VAD Threshold (%)" 50.0
                    }
                }
            ]
        }
        capture.props = {
            node.name =  "capture.rnnoise_source"
            node.passive = true
        }
        playback.props = {
            node.name =  "rnnoise_source"
            media.class = Audio/Source
        }
    }
}
]

EJEMPLO DE CONFIGURACIÓN DE UN SUMIDERO VIRTUAL CODIFICADOR DOLBY SURROUND

Este ejemplo utiliza el codificador surround LADSPA para codificar una señal 5.1 a una señal estéreo Dolby Surround.

# ~/.config/pipewire/filter-chain.conf.d/my-filter-chain-2.conf
context.modules = [
{   name = libpipewire-module-filter-chain
