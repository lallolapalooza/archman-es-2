DESCRIPCIÓN

Estas funciones decodifican y codifican certificados X.509 y algunas de sus subestructuras. Para detalles sobre la semántica, ejemplos, advertencias y errores, ver ASN1_item_d2i(3).

d2i_X509() y i2d_X509() decodifican y codifican una estructura de Certificado ASN.1 definida en la RFC 5280 sección 4.1.

d2i_X509_bio(), d2i_X509_fp(), i2d_X509_bio(), y i2d_X509_fp() son similares excepto que decodifican o codifican usando un puntero BIO o FILE.

d2i_X509_AUX() es similar a d2i_X509(), pero se espera que la entrada consista en un certificado X.509 seguido de información de confianza auxiliar. Esto es utilizado por las rutinas PEM para leer objetos de CERTIFICADO DE CONFIANZA. Esta función no debe ser llamada en entradas no confiables.

i2d_X509_AUX() es similar a i2d_X509(), pero la salida codificada contiene tanto el certificado como cualquier información de confianza auxiliar. Esto es utilizado por las rutinas PEM para escribir objetos de CERTIFICADO DE CONFIANZA. Nótese que este es un formato de datos específico de OpenSSL no estándar.

d2i_X509_CERT_AUX() y i2d_X509_CERT_AUX() decodifican y codifican datos auxiliares opcionales no estándar anexados a un certificado, por ejemplo, nombres alias amigables y datos de confianza.

d2i_X509_CINF() y i2d_X509_CINF() decodifican y codifican una estructura TBSCertificate ASN.1 definida en la RFC 5280 sección 4.1.

d2i_X509_VAL() y i2d_X509_VAL() decodifican y codifican una estructura Validity ASN.1 definida en la RFC 5280 sección 4.1.

i2d_re_X509_tbs() es similar a i2d_X509(), excepto que codifica solo la porción TBSCertificate del certificado. i2d_re_X509_CRL_tbs() y i2d_re_X509_REQ_tbs() son análogas para CRL y solicitud de certificado, respectivamente. El "re" en i2d_re_X509_tbs() significa "re-codificar", y asegura que se genere una codificación fresca en caso de que el objeto haya sido modificado después de su creación.

La codificación de la porción TBSCertificate de un certificado se almacena en caché en la estructura X509 internamente para mejorar el rendimiento de la codificación y para asegurar que las firmas de los certificados se verifiquen correctamente en algunos certificados con codificaciones defectuosas (no DER).

Si, después de la modificación, el objeto X509 se vuelve a firmar con X509_sign(3), la codificación se renueva automáticamente. De lo contrario, la codificación de la porción TBSCertificate del X509 puede ser renovada manualmente llamando a i2d_re_X509_tbs().

VALORES DE RETORNO

d2i_X509(), d2i_X509_bio(), d2i_X509_fp(), y d2i_X509_AUX() devuelven una estructura X509 válida o NULL si ocurre un error.

DESCRIPTION

These functions convert between ASN.1 encoded data and OpenSSL internal structures. Specifically, they handle X509 certificates, X509_AUX and X509_CERT_AUX auxiliary data, X509_CINF certificate information, and X509_VAL value structures.

The `d2i_*` functions decode ASN.1 DER encoded data from the memory pointed to by *ppb. They update *ppb to point to the next byte after the decoded structure. The len parameter is the maximum number of bytes to decode. If ppval is not NULL, a new structure is allocated and the decoded data is placed there; otherwise, the decoded data replaces the structure pointed to by *ppval.

The `i2d_*` functions encode the given structure into ASN.1 DER format. If ppb is not NULL, the encoded data is written to the memory pointed to by *ppb. *ppb is updated to point to the byte after the encoded data. If ppb is NULL, the required buffer size is returned and no data is written.

i2d_X509_bio() and i2d_X509_fp() encode the given X509 structure and write the DER encoded data to the specified BIO or FILE respectively.

i2d_re_X509_tbs(), i2d_re_X509_CRL_tbs(), and i2d_re_X509_REQ_tbs() re-encode the TBS (To Be Signed) part of the respective structures. This is useful for signing operations where only the TBS part needs to be signed.

RETURN VALUES

d2i_X509(), d2i_X509_AUX(), d2i_X509_CERT_AUX(), d2i_X509_CINF(), and d2i_X509_VAL() return an X509_CERT_AUX, X509_CINF, or X509_VAL object, respectively, or NULL if an error occurs.

i2d_X509(), i2d_X509_AUX(), i2d_X509_CERT_AUX(), i2d_X509_CINF(), and i2d_X509_VAL() return the number of bytes successfully encoded or a negative value if an error occurs.

i2d_X509_bio() and i2d_X509_fp() return 1 for success or 0 if an error occurs.

i2d_re_X509_tbs(), i2d_re_X509_CRL_tbs(), and i2d_re_X509_REQ_tbs() return the number of bytes successfully encoded or 0 if an error occurs.

For all functions, the error code can be obtained by ERR_get_error(3).

HISTORY

d2i_X509(), i2d_X509(), d2i_X509_fp(), i2d_X509_fp(), d2i_X509_CINF(), i2d_X509_CINF(), d2i_X509_VAL(), and i2d_X509_VAL() first appeared in SSLeay 0.5.1. d2i_X509_bio() and i2d_X509_bio() first appeared in SSLeay 0.6.0. These functions have been available since OpenBSD 2.4.

d2i_X509_AUX(), i2d_X509_AUX(), d2i_X509_CERT_AUX(), and i2d_X509_CERT_AUX() first appeared in OpenSSL 0.9.5 and have been available since OpenBSD 2.7.

i2d_re_X509_tbs(), i2d_re_X509_CRL_tbs(), and i2d_re_X509_REQ_tbs() first appeared in OpenSSL 1.1.0 and have been available since OpenBSD 7.1.
