BIO_S_FD(3) Manual de funciones de biblioteca BIO_S_FD(3)

NOMBRE

BIO_s_fd, BIO_set_fd, BIO_get_fd, BIO_new_fd, BIO_fd_non_fatal_error, BIO_fd_should_retry — BIO de descriptor de archivo

SINOPSIS

biblioteca “libcrypto”
#include <openssl/bio.h>

const BIO_METHOD *
BIO_s_fd(void);

long
BIO_set_fd(BIO *b, int fd, long close_flag);

long
BIO_get_fd(BIO *b, int *c);

BIO *
BIO_new_fd(int fd, int close_flag);

int
BIO_fd_non_fatal_error(int errnum);

int
BIO_fd_should_retry(int retval);

DESCRIPCIÓN

BIO_s_fd() devuelve el método BIO de descriptor de archivo. Este es un envoltorio alrededor de las rutinas de descriptor de archivo de la plataforma como read(2) y write(2).

BIO_read(3) y BIO_write(3) leen o escriben en el descriptor subyacente. BIO_puts(3) es compatible pero BIO_gets(3) no lo es.

Si el indicador de cierre está establecido, close(2) se llama en el descriptor de archivo subyacente cuando se libera el BIO.

BIO_reset(3) intenta establecer el puntero de archivo al inicio del archivo usando lseek(fd, 0, 0).

BIO_seek(3) establece el puntero de archivo a la posición ofs desde el inicio del archivo usando lseek(fd, ofs, 0).

BIO_tell(3) devuelve la posición actual del archivo llamando a lseek(fd, 0, 1).

BIO_set_fd() establece el descriptor de archivo del BIO b a fd y el indicador de cierre a close_flag.

BIO_get_fd() coloca el descriptor de archivo en c si no es NULL y también devuelve el descriptor de archivo.

BIO_new_fd() devuelve un BIO de descriptor de archivo usando fd y close_flag.

BIO_fd_non_fatal_error() determina si el código de estado de error errnum representa un error recuperable. BIO_fd_should_retry() determina si ocurrió un error recuperable inspeccionando tanto errno(2) como retval, que se supone que suele ser el valor de retorno de una función llamada previamente como BIO_read(3) o BIO_write(3). Estas dos funciones se usan principalmente internamente; en código de aplicación, suele ser más fácil y robusto usar BIO_should_retry(3), que funciona para cualquier tipo de BIO.

El comportamiento de BIO_read(3) y BIO_write(3) depende del comportamiento de las llamadas read(2) y write(2) de la plataforma en el descriptor. Si el descriptor de archivo subyacente está en modo no bloqueante, entonces el BIO se comportará de la manera descrita en las páginas del manual de BIO_read(3) y BIO_should_retry(3).

No se deben usar los BIO de descriptores de archivo para E/S de socket. Use BIOs de socket en su lugar.

BIO_ctrl(3) los argumentos de cmd corresponden a macros como sigue:

cmd constante macro correspondiente
BIO_C_FILE_SEEK BIO_seek(3)
BIO_C_FILE_TELL BIO_tell(3)
BIO_C_GET_FD BIO_get_fd()
BIO_C_SET_FD BIO_set_fd()
BIO_CTRL_GET_CLOSE BIO_get_close(3)
BIO_CTRL_RESET BIO_reset(3)
BIO_CTRL_SET_CLOSE BIO_set_close(3)

VALORES DE RETORNO

BIO_s_fd() devuelve el método BIO de descriptor de archivo.

Al ser llamado en un objeto BIO de descriptor de archivo, BIO_method_type(3) devuelve la constante BIO_TYPE_FD y BIO_method_name(3) devuelve un puntero a la cadena estática "file descriptor".

BIO_set_fd() siempre devuelve 1.

BIO_get_fd() devuelve el descriptor de archivo o -1 si el BIO no ha sido inicializado.

BIO_new_fd() devuelve el BIO recién asignado o NULL si ocurrió un error.

BIO_fd_non_fatal_error() devuelve 1 si errnum es EAGAIN, EALREADY, EINPROGRESS, EINTR, o ENOTCONN y 0 en caso contrario, incluso si errnum es 0.

BIO_fd_should_retry() devuelve 1 si BIO_fd_non_fatal_error(errno) es 1 y retval es 0 o -1, o 0 en caso contrario.

EJEMPLOS

Esta es una versión de descriptor de archivo BIO de "Hola Mundo":

BIO *out;
out = BIO_new_fd(fileno(stdout), BIO_NOCLOSE);
BIO_printf(out, "Hola Mundo\n");
BIO_free(out);
