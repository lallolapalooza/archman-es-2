libressl-EVP_VerifyInit(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

EVP_VERIFYINIT(3) Manual de funciones de biblioteca EVP_VERIFYINIT(3)

NOMBRE

EVP_VerifyInit_ex, EVP_VerifyUpdate, EVP_VerifyFinal, EVP_VerifyInit — funciones de verificación de firmas EVP

SINOPSIS

biblioteca “libcrypto”
#include <openssl/evp.h>

int
EVP_VerifyInit_ex(EVP_MD_CTX *ctx, const EVP_MD *type, ENGINE *engine);

int
EVP_VerifyUpdate(EVP_MD_CTX *ctx, const void *d, unsigned int cnt);

int
EVP_VerifyFinal(EVP_MD_CTX *ctx, unsigned char *sigbuf, unsigned int siglen, EVP_PKEY *pkey);

int
EVP_VerifyInit(EVP_MD_CTX *ctx, const EVP_MD *type);

DESCRIPCIÓN

Las rutinas de verificación de firmas EVP son una interfaz de alto nivel para firmas digitales.

EVP_VerifyInit_ex() configura el contexto de verificación ctx para usar el resumen type. Antes de llamar a esta función, obtenga ctx de EVP_MD_CTX_new(3) o llame a EVP_MD_CTX_reset(3) en él. El argumento engine se ignora siempre y se recomienda pasar NULL.

EVP_VerifyUpdate() hace un resumen de cnt bytes de datos en d en el contexto de verificación ctx. Esta función se puede llamar varias veces en el mismo ctx para incluir datos adicionales.

EVP_VerifyFinal() verifica los datos en ctx usando la clave pública pkey y contra los siglen bytes en sigbuf.

EVP_VerifyInit() inicializa un contexto de verificación ctx para usar la implementación predeterminada del resumen type.

La interfaz EVP para firmas digitales casi siempre debe usarse en preferencia a las interfaces de bajo nivel. Esto se debe a que el código se vuelve transparente al algoritmo utilizado y mucho más flexible.

La llamada a EVP_VerifyFinal() finaliza internamente una copia del contexto de resumen. Esto significa que las llamadas a EVP_VerifyUpdate() y EVP_VerifyFinal() se pueden realizar más tarde para resumir y verificar datos adicionales.

Dado que solo se finaliza una copia del contexto de resumen, el contexto debe limpiarse después de su uso llamando a EVP_MD_CTX_free(3), o se producirá una fuga de memoria.

EVP_VerifyInit_ex(), EVP_VerifyUpdate(), y EVP_VerifyInit() se implementan como macros.

VALORES DE RETORNO

EVP_VerifyInit_ex() y EVP_VerifyUpdate() devuelven 1 para éxito y 0 para fallo.

EVP_VerifyFinal() devuelve 1 para una firma correcta, 0 para fallo y -1 si ocurrió algún otro error.

Los códigos de error se pueden obtener mediante ERR_get_error(3).

VER TAMBIÉN

evp(3), EVP_DigestInit(3), EVP_SignInit(3)

HISTORIA

EVP_VerifyInit(), EVP_VerifyUpdate(), y EVP_VerifyFinal() aparecieron por primera vez en SSLeay 0.5.1 y han estado disponibles desde OpenBSD 2.4.

EVP_VerifyInit_ex() apareció por primera vez en OpenSSL 0.9.7 y ha estado disponible desde OpenBSD 3.2.

ERRORES DE PROGRAMACIÓN

Versiones anteriores de esta documentación indicaban erróneamente que las llamadas a EVP_VerifyUpdate() no podían hacerse después de llamar a EVP_VerifyFinal().

Dado que la clave pública se pasa en la llamada a EVP_SignFinal(3), cualquier error relacionado con la clave privada (por ejemplo, una combinación de clave y resumen inadecuada) no se indicará hasta después de que se hayan pasado potencialmente grandes cantidades de datos a través de EVP_SignUpdate(3).

No es posible cambiar los parámetros de firma utilizando estas funciones.

Los dos errores anteriores se corrigen en las funciones más nuevas de la familia EVP_DigestVerifyInit(3).
