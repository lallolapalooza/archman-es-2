DESCRIPCIÓN

ASRange, ASIdOrRange, y ASIdentifierChoice son bloques de construcción del tipo ASIdentifiers que representan la extensión de delegación de identificadores de sistema autónomo RFC 3779.

Todos los ASN1_INTEGER en este manual deben ser representables como enteros sin signo de 32 bits. La API no realiza comprobaciones correspondientes. Un ASN1_INTEGER se puede establecer usando ASN1_INTEGER_set_uint64(3).

El tipo ASRange definido en la sección 3.2.3.8 del RFC 3779 se implementa como

typedef struct ASRange_st {
	ASN1_INTEGER *min;
	ASN1_INTEGER *max;
} ASRange;

Representa el rango cerrado [min,max] de identificadores AS entre min y max, donde min debe ser estrictamente menor que max.

ASRange_new() asigna un nuevo objeto ASRange con min y max asignados y vacíos, representando así el rango inválido [0,0].

ASRange_free() libera asrange, incluyendo cualquier dato contenido en él. Si asrange es NULL, no se realiza ninguna acción.

El tipo ASIdOrRange definido en la sección 3.2.3.5 del RFC 3779 se implementa como

typedef struct ASIdOrRange_st {
	int type;
	union {
		ASN1_INTEGER *id;
		ASRange *range;
	} u;
} ASIdOrRange;

representando un identificador AS individual o un rango. Al poblar un objeto ASIdOrRange manualmente, su type debe establecerse en ASIdOrRange_id o ASIdOrRange_range para indicar qué miembro de la unión u es válido.

ASIdOrRange_new() devuelve un nuevo objeto ASIdOrRange con tipo inválido y miembros NULL de la unión u.

ASIdOrRange_free() libera aor, incluyendo cualquier dato contenido en él, siempre que type esté configurado correctamente. Si asrange es NULL, no se realiza ninguna acción.

Para expresar una lista de identificadores y rangos AS, la sección 3.2.3.4 del RFC 3779 utiliza una SEQUENCE ASN.1, que se implementa a través de una construcción STACK_OF(3) sobre ASIdOrRange:

typedef STACK_OF(ASIdOrRange) ASIdOrRanges;

Dado que un objeto ASIdOrRanges debe ordenarse de una manera específica (ver X509v3_asid_canonize(3)), se necesita una función de comparación para una instanciación correcta con sk_new(3). La función ASIdOrRange_cmp() no está expuesta directamente y no es fácilmente accesible desde fuera de la biblioteca, y es trivial implementarla. Por lo tanto, no se recomienda usar objetos ASIdOrRanges que no formen parte de un objeto ASIdentifiers.

El marcador de "heredar" de la sección 3.2.3.3 del RFC 3779 se implementa como ASN1_NULL. No tiene un tipo o API dedicado y se puede instanciar con ASN1_NULL_new(3).

El tipo ASIdentifierChoice definido en la sección 3.2.3.2 del RFC 3779 se implementa como

typedef struct ASIdentifierChoice_st {
	int type;
	union {
		ASN1_NULL *inherit;
		ASIdOrRanges *asIdsOrRanges;
	} u;
} ASIdentifierChoice;

donde el miembro type debe establecerse en ASIdentifierChoice_inherit o ASIdentifierChoice_asIdsOrRanges para indicar si un objeto ASIdentifierChoice dado representa una lista heredada o una lista explícita.

ASIdentifierChoice_new() devuelve un nuevo objeto ASIdentifierChoice con tipo inválido y miembros NULL de la unión u.

ASIdentifierChoice_free() libera aic, incluyendo cualquier dato contenido en él, siempre que type esté configurado correctamente.

El tipo ASIdentifiers definido en la sección 3.2.3.1 del RFC 3779 se implementa como

typedef struct ASIdentifiers_st {
	ASIdentifierChoice *asnum;
	ASIdentifierChoice *rdi;
} ASIdentifiers;

Debe instanciarse con ASIdentifiers_new(3) y poblarse con X509v3_asid_add_id_or_range(3).

DESCRIPTION

The functions ASRange_new(), ASIdOrRange_new(), and ASIdentifierChoice_new() allocate and initialize new ASRange, ASIdOrRange, and ASIdentifierChoice objects, respectively.

The functions d2i_ASRange(), d2i_ASIdOrRange(), and d2i_ASIdentifierChoice() decode DER-encoded data from the buffer pointed to by pp into a ASRange, ASIdOrRange, or ASIdentifierChoice object, respectively. The number of bytes to decode is specified by length. If a is not NULL, the decoded object is stored in a. Otherwise, a new object is allocated. The pointer pp is advanced to point to the data immediately following the decoded data.

The functions i2d_ASRange(), i2d_ASIdOrRange(), and i2d_ASIdentifierChoice() convert a ASRange, ASIdOrRange, or ASIdentifierChoice object, respectively, into DER-encoded form. If pp is not NULL, the encoded data is written to the buffer pointed to by pp, and the pointer pp is advanced accordingly. If pp is NULL, then the exact number of bytes required to encode the object is returned, and no data is written.

These functions are part of the ASN.1 item processing functions and are generally used internally by OpenSSL. The ASN.1 structures ASRange, ASIdOrRange, and ASIdentifierChoice are defined in RFC 3779.

d2i_ASRange(), i2d_ASRange(), d2i_ASIdOrRange(), i2d_ASIdOrRange(), d2i_ASIdentifierChoice(), and i2d_ASIdentifierChoice() decode and encode ASN.1 ASRange, ASIdOrRange, and ASIdentifierChoice objects. For details about the semantics, examples, caveats, and bugs, see ASN1_item_d2i(3). In order for the encoding produced by i2d_ASRange() to be correct, min must be strictly less than max. Similarly for i2d_ASIdOrRange() and an ASIdOrRange object of type ASIdOrRange_range.

RETURN VALUES

ASRange_new() returns a new ASRange object with allocated, empty members, or NULL if an error occurs.

ASIdOrRange_new() returns a new, empty ASIdOrRange object or NULL if an error occurs.

ASIdentifierChoice_new() returns a new, empty ASIdentifierChoice object or NULL if an error occurs.

The decoding functions d2i_ASRange(), d2i_ASIdOrRange(), and d2i_ASIdentifierChoice() return an ASRange, an ASIdOrRange, or an ASIdentifierChoice, object, respectively, or NULL if an error occurs.

The encoding functions i2d_ASRange(), i2d_ASIdOrRange(), and i2d_ASIdentifierChoice() return the number of bytes successfully encoded or a value <= 0 if an error occurs.

HISTORY

These functions first appeared in OpenSSL 0.9.8e and have been available since OpenBSD 7.1.

BUGS

An ASIdOrRanges_new() function that installs the correct comparison function on the stack of ASIdOrRange should have been part of the API to make it usable.

ASIdentifierChoice_new() is of very limited use because ASIdOrRanges_new() is missing.

There is no way of ensuring that an ASIdOrRanges object is in canonical form unless it is part of an ASIdentifiers object. It is therefore difficult to guarantee that the output of i2d_ASIdentifierChoice() is conformant.

RFC 3779 3.2.3.4 has “asIdsOrRanges” while its type in this implementation is ASIdOrRanges.
