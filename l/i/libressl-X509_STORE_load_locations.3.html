X509_STORE_LOAD_LOCATIONS(3) Manual de funciones de biblioteca X509_STORE_LOAD_LOCATIONS(3)

NOMBRE

X509_STORE_load_locations, X509_STORE_set_default_paths, X509_STORE_load_mem, X509_STORE_add_lookup — configurar archivos y directorios utilizados por un almacén de certificados

SINOPSIS

biblioteca “libcrypto”
#include <openssl/x509_vfy.h>

int
X509_STORE_load_locations(X509_STORE *store, const char *file, const char *dirs);

int
X509_STORE_set_default_paths(X509_STORE *store);

int
X509_STORE_load_mem(X509_STORE *store, void *buffer, int length);

X509_LOOKUP *
X509_STORE_add_lookup(X509_STORE *store, const X509_LOOKUP_METHOD *method);

DESCRIPCIÓN

X509_STORE_load_locations() indica al store que utilice el archivo PEM file y todos los archivos PEM de los directorios contenidos en la lista separada por dos puntos dirs para buscar certificados, además de los archivos y directorios que ya están configurados. Los certificados en los directorios deben estar en formato hash, como se documenta en X509_LOOKUP_hash_dir(3). Los directorios ya en uso no se añaden de nuevo. Si se pasa NULL para file o dirs, no se añade ningún archivo nuevo ni ningún directorio nuevo, respectivamente.

X509_STORE_load_locations() es idéntica a SSL_CTX_load_verify_locations(3) excepto que opera directamente sobre un objeto X509_STORE, en lugar de sobre el almacén utilizado por un contexto SSL. Consulte esa página del manual para obtener más información.

X509_STORE_set_default_paths() es similar excepto que indica al store que utilice el archivo y directorio PEM por defecto (como se documenta en ARCHIVOS) además de lo que ya está configurado. Ignora los errores que ocurren al intentar cargar el archivo o añadir el directorio, pero aún puede fallar por otras razones, por ejemplo, cuando se agota la memoria al intentar asignar los objetos X509_LOOKUP requeridos.

X509_STORE_set_default_paths() es idéntica a SSL_CTX_set_default_verify_paths(3) excepto que opera directamente sobre un objeto X509_STORE, en lugar de sobre el almacén utilizado por un contexto SSL. Consulte esa página del manual para obtener más información.

Las funciones anteriores son envoltorios de X509_LOOKUP_load_file(3) y X509_LOOKUP_add_dir(3).

X509_STORE_load_mem() indica al store que utilice los certificados contenidos en el buffer de memoria de la longitud dada para la búsqueda de certificados. Es un envoltorio de X509_LOOKUP_add_mem(3).

X509_STORE_add_lookup() comprueba si el store ya contiene un objeto X509_LOOKUP que utiliza el method dado; si lo hace, se devuelve el objeto existente y no ocurre ninguna otra acción. De lo contrario, se asigna, se añade y se devuelve un nuevo objeto X509_LOOKUP. Esta función se utiliza internamente en todas las funciones listadas anteriormente.

VALORES DE RETORNO

X509_STORE_load_locations() devuelve 1 si todos los archivos y directorios especificados se añadieron correctamente. Devuelve 0 si falla. Esto puede ocurrir si la adición del archivo falló, si la adición de alguno de los directorios falló, o si ambos argumentos fueron NULL.

X509_STORE_set_default_paths() devuelve 0 para algunas condiciones de error y 1 en caso contrario, no solo para el éxito, sino también para varios casos de fallo.

X509_STORE_load_mem() devuelve 1 si tiene éxito o 0 si falla. En particular, los errores de análisis o la falta de memoria pueden causar fallos.

X509_STORE_add_lookup() devuelve el objeto de búsqueda existente o nuevo, o NULL si falla. Este es un puntero interno que no debe liberarse. Con LibreSSL, la única razón de fallo es la falta de memoria.

ARCHIVOS

/etc/ssl/cert.pem
archivo PEM por defecto para X509_STORE_set_default_paths()
/etc/ssl/certs/
directorio por defecto para X509_STORE_set_default_paths()

VER TAMBIÉN

SSL_CTX_load_verify_locations(3), X509_load_cert_file(3), X509_LOOKUP_hash_dir(3), X509_LOOKUP_new(3), X509_STORE_new(3), X509_STORE_set1_param(3), X509_STORE_set_verify_cb(3)

HISTORIA

X509_STORE_load_locations(), X509_STORE_set_default_paths(), y X509_STORE_add_lookup() aparecieron por primera vez en SSLeay 0.8.0 y han estado disponibles desde OpenBSD 2.4.

X509_STORE_load_mem() apareció por primera vez en OpenBSD 5.7.

ERRORES

En el momento en que se detecta que la adición de un directorio ha fallado, el archivo y algunos otros directorios pueden haber sido cargados correctamente, por lo que estas funciones pueden cambiar el estado del almacén incluso cuando fallan.

X509_STORE_set_default_paths() borra la cola de errores, eliminando incluso la información de error que ya estaba presente cuando se llamó.
