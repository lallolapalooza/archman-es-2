LIBUNWIND-SETJMP(3libunwind) Biblioteca de programación LIBUNWIND-SETJMP(3libunwind)

NOMBRE

libunwind-setjmp -- saltos no locales basados en libunwind

SINOPSIS

#include <setjmp.h>

int setjmp(jmp_buf env);
void longjmp(jmp_buf env, int val);
int _setjmp(jmp_buf env);
void _longjmp(jmp_buf env, int val);
int sigsetjmp(sigjmp_buf env, int savemask);
void siglongjmp(sigjmp_buf env, int val);

DESCRIPCIÓN

La biblioteca unwind-setjmp ofrece una implementación basada en libunwind de saltos no locales. Esta implementación está pensada como un reemplazo directo para las rutinas normales del sistema con el mismo nombre. La principal ventaja de usar la biblioteca unwind-setjmp es que la configuración de un salto no local a través de una de las rutinas setjmp() es muy rápida. Típicamente, solo se necesitan 2 o 3 palabras para guardar en el buffer de salto (más una llamada a sigprocmask(2), en el caso de sigsetjmp). Por otro lado, la ejecución de un salto no local llamando a una de las rutinas longjmp() tiende a ser mucho más lenta que con las rutinas proporcionadas por el sistema. De hecho, el tiempo dedicado a un longjmp() será proporcional al número de marcos de llamada que existen entre los puntos donde se llamaron setjmp() y longjmp(). Por esta razón, la biblioteca unwind-setjmp es beneficiosa principalmente en aplicaciones que frecuentemente llaman a setjmp() pero solo raramente llaman a longjmp().

ADVERTENCIAS

*
El funcionamiento correcto de esta biblioteca depende de la presencia de información de desenrollado correcta. En plataformas más nuevas, esto rara vez es un problema. En plataformas más antiguas, se debe tener cuidado para asegurar que cada una de las funciones cuyos marcos de pila puedan tener que desenrollarse durante un longjmp() tengan información de desenrollado correcta (en esas plataformas, generalmente hay un conmutador de compilador, como -funwind-tables, para solicitar la generación de información de desenrollado).
*
El contenido de jmp_buf y sigjmp_buf, tal como lo configuran y utilizan estas rutinas, es completamente diferente de los utilizados por las rutinas proporcionadas por el sistema. Por lo tanto, un buffer de salto creado por setjmp()/_setjmp basado en libunwind solo puede usarse en una llamada a longjmp()/_longjmp() basado en libunwind. Lo análogo se aplica para sigjmp_buf con sigsetjmp() y siglongjmp().

ARCHIVOS

-lunwind-setjmp

La biblioteca contra la que una aplicación debe enlazarse para asegurar que utiliza las rutinas de salto no locales basadas en libunwind.
