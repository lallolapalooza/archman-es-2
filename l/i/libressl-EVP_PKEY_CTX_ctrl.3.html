DESCRIPCIÓN

La función EVP_PKEY_CTX_ctrl() envía una operación de control al contexto ctx. El tipo de clave utilizado debe coincidir con keytype si no es -1. El parámetro optype es una máscara que indica a qué operaciones se puede aplicar el control. El comando de control se indica en cmd y los argumentos adicionales en p1 y p2.

Las aplicaciones normalmente no llamarán a EVP_PKEY_CTX_ctrl() directamente, sino que llamarán a una de las macros específicas del algoritmo descritas a continuación y en RSA_pkey_ctx_ctrl(3).

La función EVP_PKEY_CTX_ctrl_str() permite a una aplicación enviar una operación de control específica del algoritmo a un contexto ctx en forma de cadena. Esto está diseñado para ser utilizado para opciones especificadas en la línea de comandos o en archivos de texto. Los comandos compatibles se documentan en las páginas de comandos de la utilidad openssl(1) para la opción -pkeyopt, que es compatible con los comandos pkeyutl, genpkey y req.

Todas las demás "funciones" se implementan como macros.

Las macros EVP_PKEY_CTX_set_signature_md() y EVP_PKEY_CTX_get_signature_md() establecen y obtienen el tipo de resumen de mensaje utilizado en una firma. Se pueden usar con los algoritmos RSA, DSA y ECDSA. Si la clave es del tipo EVP_PKEY_RSA_PSS y tiene restricciones de uso, se produce un error si se intenta establecer el resumen a algo diferente al valor restringido.

Estas dos macros se expanden a EVP_PKEY_CTX_ctrl() con un optype de EVP_PKEY_OP_TYPE_SIG y los siguientes argumentos de comando:

cmd constante macro correspondiente
EVP_PKEY_CTRL_MD EVP_PKEY_CTX_set_signature_md()
EVP_PKEY_CTRL_GET_MD EVP_PKEY_CTX_get_signature_md()

Para EVP_PKEY_CTX_set_signature_md(), el parámetro p2 es un puntero a un EVP_MD. Para EVP_PKEY_CTX_get_signature_md(), el parámetro p2 es un puntero a un puntero a EVP_MD en el que se almacenará el resultado.

El macro EVP_PKEY_CTX_set_dsa_paramgen_bits() establece el número de bits en la generación de parámetros DSA. Actualmente, esto solo se usa para los parámetros de generación de claves DSA.

El macro EVP_PKEY_CTX_set_dh_paramgen_prime_len() establece la longitud del primo en la generación de parámetros DH. El valor predeterminado es 1024.

El macro EVP_PKEY_CTX_set_dh_paramgen_generator() establece el generador en la generación de parámetros DH. El valor predeterminado es 2.

El macro EVP_PKEY_CTX_set_ec_paramgen_curve_nid() establece la curva utilizada en la generación de parámetros EC. El valor nid es un NID de curva estándar, por ejemplo NID_secp256k1.

El macro EVP_PKEY_CTX_set_ec_param_enc() establece el tipo de codificación de parámetros de curva utilizado para generar una clave EC. El valor param_enc es uno de los valores OPENSSL_EC_EXPLICIT_CURVE o OPENSSL_EC_NAMED_CURVE.

El macro EVP_PKEY_CTX_set_ecdh_cofactor_mode() establece el modo cofactor para ECDH. Si se establece en 1, se utiliza el cofactor de la clave pública. Si se establece en 0, se utiliza el punto base.

El macro EVP_PKEY_CTX_get_ecdh_cofactor_mode() devuelve el modo cofactor actual.

El macro EVP_PKEY_CTX_set_ecdh_kdf_type() establece el tipo de KDF (Key Derivation Function) a usar con ECDH. El valor kdf debe ser EVP_KDF_SSKDF o EVP_KDF_HKDF.

El macro EVP_PKEY_CTX_get_ecdh_kdf_type() devuelve el tipo de KDF actual.

El macro EVP_PKEY_CTX_set_ecdh_kdf_md() establece el resumen de mensaje a usar con la KDF en ECDH. Para la KDF SSKDF, este es el resumen utilizado para la derivación de clave. Para la KDF HKDF, este es el resumen utilizado en las tres etapas de la función HKDF.

El macro EVP_PKEY_CTX_get_ecdh_kdf_md() devuelve el resumen de mensaje actual.

El macro EVP_PKEY_CTX_set_ecdh_kdf_outlen() establece la longitud de salida deseada de la KDF en ECDH. El valor predeterminado es 32 bytes.

El macro EVP_PKEY_CTX_get_ecdh_kdf_outlen() devuelve la longitud de salida actual.

El macro EVP_PKEY_CTX_set0_ecdh_kdf_ukm() establece el valor de datos de usuario clave (UKM) a usar con la KDF en ECDH. La función toma posesión del puntero ukm y lo liberará cuando el contexto ctx sea liberado.

El macro EVP_PKEY_CTX_get0_ecdh_kdf_ukm() devuelve un puntero a los datos UKM actuales. La función no toma posesión del puntero y la aplicación no debe liberarlo ni modificarlo. El puntero devuelto puede ser NULL si no se han establecido datos UKM.

El macro EVP_PKEY_CTX_set1_id() establece el identificador asociado con el contexto de clave. Esto se usa para algoritmos de clave compartida como EVP_PKEY_X25519 y EVP_PKEY_ED25519. La función toma posesión del puntero id.

Los macros EVP_PKEY_CTX_get1_id() y EVP_PKEY_CTX_get1_id_len() obtienen el identificador y su longitud, respectivamente. La función EVP_PKEY_CTX_get1_id_len() debe llamarse primero para obtener la longitud, luego se puede asignar memoria y llamar a EVP_PKEY_CTX_get1_id() para obtener el identificador.

Todas las funciones devuelven 1 si la operación tiene éxito, 0 o un valor negativo en caso de error.

DESCRIPTION

The functions documented here are used to control the behaviour of an EVP_PKEY_CTX object. They are all related to specific algorithms or operations, and are therefore only relevant when the EVP_PKEY_CTX is being used for those specific purposes.

The general purpose control functions are EVP_PKEY_CTX_ctrl() and EVP_PKEY_CTX_ctrl_str(). These can be used to set or get almost any parameter associated with an EVP_PKEY_CTX. The type and cmd arguments to EVP_PKEY_CTX_ctrl() specify the operation type and command respectively. See "Control Commands" below for a list of available commands.

The EVP_PKEY_CTX_ctrl_str() function provides a more convenient way to perform control operations. The type argument specifies the category of the parameter, and the value argument is a string representing the desired value. See "Control Commands" below for a list of available types and their associated string values.

Signature parameters

The EVP_PKEY_CTX_set_signature_md() macro sets the digest md to be used for signing or verifying operations. If md is NULL then any digest associated with the signature algorithm is used.

The EVP_PKEY_CTX_get_signature_md() macro returns the digest currently set for signing or verifying operations. This is the same digest that would be used by EVP_DigestSign(3) or EVP_DigestVerify(3). Note that the returned EVP_MD object is owned by the EVP_PKEY_CTX and should not be freed.

EVP_PKEY_CTX_set_signature_md() EVP_PKEY_CTX_get_signature_md()
VP_PKEY_CTRL_GET_SIGNATURE_MD EVP_PKEY_CTX_get_signature_md()

DSA parameters

The macro EVP_PKEY_CTX_set_dsa_paramgen_bits() sets the number of bits used for DSA parameter generation to nbits. If not specified, 1024 is used.

DH parameters

The macro EVP_PKEY_CTX_set_dh_paramgen_prime_len() sets the length of the DH prime parameter len for DH parameter generation. It only accepts lengths greater than or equal to 256. If this macro is not called, then 1024 is used.

The EVP_PKEY_CTX_set_dh_paramgen_generator() macro sets DH generator to gen for DH parameter generation. If not specified, 2 is used.

EC parameters

The EVP_PKEY_CTX_set_ec_paramgen_curve_nid() macro sets the EC curve for EC parameter generation to nid. For EC parameter generation, this macro must be called or an error occurs because there is no default curve.

The EVP_PKEY_CTX_set_ec_param_enc() macro sets the EC parameter encoding to param_enc when generating EC parameters or an EC key. The encoding can be set to 0 for explicit parameters or to OPENSSL_EC_NAMED_CURVE to use named curve form.

ECDH parameters

The EVP_PKEY_CTX_setdh_cofactor_mode() macro sets the cofactor mode to cofactor_mode for ECDH key derivation. Possible values are 1 to enable cofactor key derivation, 0 to disable it, or -1 to clear the stored cofactor mode and fall back to the private key cofactor mode.

The EVP_PKEY_CTX_get_ecdh_cofactor_mode() macro returns the cofactor mode for ctx used for ECDH key derivation. Possible return values are 1 when cofactor key derivation is enabled or 0 otherwise.

ECDH key derivation function parameters

The EVP_PKEY_CTX_set_ecdh_kdf_type() macro sets the key derivation function type to kdf for ECDH key derivation. Possible values are EVP_PKEY_ECDH_KDF_NONE or EVP_PKEY_ECDH_KDF_X9_63 which uses the key derivation specified in X9.63. When using key derivation, the kdf_md and kdf_outlen parameters must also be specified.

The EVP_PKEY_CTX_get_ecdh_kdf_type() macro returns the key derivation function type for ctx used for ECDH key derivation. Possible return values are EVP_PKEY_ECDH_KDF_NONE or EVP_PKEY_ECDH_KDF_X9_63.

The EVP_PKEY_CTX_set_ecdh_kdf_md() macro sets the key derivation function message digest to md for ECDH key derivation. Note that X9.63 specifies that this digest should be SHA-1, but OpenSSL tolerates other digests.

The EVP_PKEY_CTX_get_ecdh_kdf_md() macro gets the key derivation function message digest for ctx used for ECDH key derivation.

The EVP_PKEY_CTX_set_ecdh_kdf_outlen() macro sets the key derivation function output length to len for ECDH key derivation.

The EVP_PKEY_CTX_get_ecdh_kdf_outlen() macro gets the key derivation function output length for ctx used for ECDH key derivation.

The EVP_PKEY_CTX_set0_ecdh_kdf_ukm() macro sets the user key material to ukm for ECDH key derivation. This parameter is optional and corresponds to the shared info in X9.63 terms. The library takes ownership of the user key material, so the caller should not free the original memory pointed to by ukm.

The EVP_PKEY_CTX_get0_ecdh_kdf_ukm() macro gets the user key material for ctx. The return value is the user key material length. The resulting pointer is owned by the library and should not be freed by the caller.

CMAC parameters

Application programs normally implement CMAC as described in EVP_PKEY_new_CMAC_key(3) and do not need the control commands documented here.

Alternatively, the call to EVP_PKEY_new_CMAC_key(3) can be replaced as follows, leaving the rest of the example code given there unchanged:

  1. Create an empty EVP_PKEY_CTX object by passing the EVP_PKEY_CMAC constant to EVP_PKEY_CTX_new_id(3).
  2. Initialize it with EVP_PKEY_keygen_init(3).
  3. Select the block cipher by calling EVP_PKEY_CTX_ctrl() with an optype of EVP_PKEY_OP_KEYGEN, a cmd of EVP_PKEY_CTRL_CIPHER, and p2 pointing to an EVP_CIPHER object, which can be obtained from the functions in the CIPHER LISTING in EVP_EncryptInit(3). The p1 argument is ignored; passing 0 is recommended.
  4. Call EVP_PKEY_CTX_ctrl() again with an optype of EVP_PKEY_OP_KEYGEN, a cmd of EVP_PKEY_CTRL_SET_MAC_KEY, p2 pointing to the symmetric key, and p1 specifying the length of the symmetric key in bytes.
  5. Extract the desired EVP_PKEY object using EVP_PKEY_keygen(3), making sure the ppkey argument points to a storage location containing a NULL pointer.
  6. Proceed with EVP_MD_CTX_new(3), EVP_DigestSignInit(3), and EVP_DigestSign(3) as usual.

HMAC parameters

Application programs normally implement HMAC as described in EVP_PKEY_new_raw_private_key(3). While it is possible to instead use EVP_PKEY_CTRL_SET_MAC_KEY directly, similar to the above description for CMAC, that is strongly discouraged. It's essentially what the deprecated function EVP_PKEY_new_mac_key(3) does internally, and compared to the direct approach with EVP_PKEY_new_raw_private_key(3), it requires a lot of cumbersome and unnecessary work.

Other parameters

The EVP_PKEY_CTX_set1_id(), EVP_PKEY_CTX_get1_id(), and EVP_PKEY_CTX_get1_id_len() macros manipulate a special identifier field used for some specific signature algorithms such as SM2. The EVP_PKEY_set1_id() macro sets the ID to a copy of id with the length id_len. The caller can safely free the original memory pointed to by id. The EVP_PKEY_CTX_get1_id_len() macro returns the length of the ID set via a previous call to EVP_PKEY_set1_id(). That length is typically used to allocate memory for a subsequent call to EVP_PKEY_CTX_get1_id(), which copies the previously set ID into *id. The caller is responsible for allocating sufficient memory for id before calling EVP_PKEY_CTX_get1_id().

RETURN_VALUES

The various functions return 1 on success or 0 or a negative value on error.

VALORES DE RETORNO

EVP_PKEY_CTX_ctrl() y sus macros devuelven un valor positivo en caso de éxito y 0 o un valor negativo en caso de fallo. En particular, un valor de retorno de -2 indica que la operación no es compatible con el algoritmo de clave pública.
