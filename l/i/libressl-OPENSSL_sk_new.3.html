DESCRIPCIÓN

OpenSSL introdujo un concepto idiosincrásico de arreglos de tamaño variable de punteros y lo llamó de forma un tanto engañosa una "pila". Intrínsecamente, y como se documenta en esta página del manual, las pilas de OpenSSL no son seguras en cuanto a tipos, sino que solo manejan argumentos y valores de retorno de la función void *.

OpenSSL también proporciona un sistema frágil y excesivamente complicado de envolturas generadas por macros que ofrece una seguridad de tipo superficial a expensas de una ofuscación extensiva, implementado mediante una gran cantidad de código autogenerado que involucra macros de cpp(1) extremadamente feas y anidadas; consulte la página del manual de STACK_OF(3) para obtener detalles.

El tipo de datos fundamental es la estructura _STACK. Almacena un número variable de punteros void y recuerda el número de punteros almacenados actualmente. Opcionalmente, puede contener un puntero a una función de comparación. Mientras no haya una función de comparación instalada, el orden de los punteros es significativo; tan pronto como se instala una función de comparación, se vuelve indefinido.

sk_new_null() asigna e inicializa una pila nueva y vacía. sk_new() es idéntica excepto que también instala compfunc como la función de comparación para el nuevo objeto de pila. sk_set_cmp_func() instala compfunc para la pila existente. Se permite que compfunc sea NULL, pero la pila no.

sk_dup() crea una copia superficial de la pila dada, que no debe ser un puntero NULL. No copia los objetos a los que apuntan desde la pila ni aumenta sus recuentos de referencia, sino que simplemente copia los punteros. Se debe tener extremo cuidado para evitar liberar la memoria dos veces, por ejemplo, llamando a sk_free() en una copia y llamando solo a sk_pop_free() en la otra.

sk_free() libera la pila dada. No libera ninguno de los punteros almacenados en la pila. A menos que estos punteros sean meras copias de punteros propiedad de otros objetos, deben liberarse antes de llamar a sk_free() para evitar fugas de memoria. Si pila es un puntero NULL, no se realiza ninguna acción.

sk_pop_free() tiene un nombre muy engañoso. No hace en absoluto lo que uno esperaría de una función llamada "pop". En cambio, hace lo mismo que sk_free(), excepto que también llama a la función freefunc en cada uno de los punteros contenidos en la pila. Si las llamadas a freefunc están destinadas a liberar la memoria utilizada por los objetos en la pila, asegúrese de que no queden otros punteros a los mismos objetos en otros lugares.

sk_find() busca en la pila el puntero buscado. Si la pila contiene más de una copia del puntero buscado, solo se encuentra la primera coincidencia. Si se instala una función de comparación para la pila, la pila se ordena primero con sk_sort(), y en lugar de comparar punteros, dos punteros se consideran coincidentes si la función de comparación devuelve 0.

sk_sort() ordena la pila utilizando qsort(3) y la función de comparación instalada. Si la pila es un puntero NULL o ya se considera ordenada, no ocurre nada. Esta función solo se puede llamar si está instalada una función de comparación.

DESCRIPCIÓN

sk_new_null() asigna una pila vacía. Se usa en lugar de sk_new() si se puede garantizar que nunca se llamarán funciones de comparación o de liberación para el objeto de pila o para sus elementos. Esto puede ser una optimización para evitar la sobrecarga de la comprobación de si se ha configurado una función de comparación o de liberación.

sk_new() asigna y devuelve un puntero a una nueva pila vacía. Si se instala una función de comparación con sk_set_cmp_func(), se usa para la ordenación y la búsqueda.

sk_dup() duplica la stack dada. Los punteros de la pila original se copian sin liberación. Si se debe liberar la memoria de los punteros, esto debe hacerse por separado.

sk_free() libera toda la memoria asignada para la stack. Si se instaló una función de liberación con sk_free(), esta se llama para cada puntero de la pila antes de liberar la pila.

sk_pop_free() libera la stack y la función to_free se llama para cada puntero antes de liberar la pila.

sk_set_cmp_func() instala una función de comparación para la stack. Si ya existe una función de comparación, esta se reemplaza. La función de comparación debe devolver un valor negativo si el primer argumento es menor que el segundo, cero si son iguales y un valor positivo si el primer argumento es mayor que el segundo. Si se instala una función de comparación, la pila se marca como desordenada. Si stack es un puntero NULL, no se realiza ninguna acción.

sk_num() devuelve el número de punteros actualmente almacenados en la stack.

sk_value() devuelve el puntero con el índice dado de la stack.

sk_find() devuelve el índice más bajo que coincide o -1 si no se encuentra ninguna coincidencia. Si se instala una función de comparación, se utiliza para la búsqueda. De lo contrario, solo se buscan coincidencias exactas de punteros. Si se usa una función de comparación, la pila se marca como desordenada. Si stack es un puntero NULL o si está vacía, se devuelve -1.

sk_sort() ordena la pila. Si se instala una función de comparación, se utiliza para ordenar. De lo contrario, se trata la pila como si estuviera desordenada. Después de que la llamada a sk_sort() se haya completado, la pila se considera ordenada.

sk_is_sorted() devuelve 1 si la pila se considera ordenada, o 0 en caso contrario. Si stack es un puntero NULL, se considera ordenada y devuelve 1.

sk_push() inserta new_item al final de la stack, incrementando el número de punteros en 1. Si stack es un puntero NULL, no se realiza ninguna acción.

sk_unshift() inserta new_item al principio de la stack, de modo que obtiene el índice 0. El número de punteros aumenta en 1. Si stack es un puntero NULL, no se realiza ninguna acción.

sk_insert() inserta el new_item en la stack de modo que obtenga el index dado. Si index es menor que 0 o mayor o igual que sk_num(stack), el efecto es el mismo que para sk_push(). Si stack es un puntero NULL, no se realiza ninguna acción.

sk_set() reemplaza el puntero con el index dado en la stack con el new_item. El puntero antiguo no se libera, lo que puede provocar fugas de memoria si no existe una copia en otro lugar. Si stack es un puntero NULL o si index es menor que 0 o mayor o igual que sk_num(stack), no se realiza ninguna acción.

sk_pop() y sk_shift() eliminan el puntero con el índice más alto o más bajo de la stack, respectivamente, reduciendo el número de punteros en 1. Si stack es un puntero NULL o si está vacía, no se realiza ninguna acción.

sk_delete() elimina el puntero con el index dado de la stack, reduciendo el número de punteros en 1. Si stack es un puntero NULL o el index es menor que 0 o mayor o igual que sk_num(stack), no se realiza ninguna acción.

sk_delete_ptr() elimina el puntero wanted de la stack, reduciendo el número de punteros en 1 si se encuentra. Nunca utiliza una función de comparación, sino que solo compara los punteros. El puntero stack no debe ser NULL.

sk_zero() elimina todos los punteros de la stack. No libera ninguno de los punteros. A menos que estos punteros sean meras copias de punteros propiedad de otros objetos, deben liberarse antes de llamar a sk_zero() para evitar fugas de memoria. Si stack es un puntero NULL, no se realiza ninguna acción.

VALORES DE RETORNO

sk_new_null(), sk_new() y sk_dup() devuelven un puntero al objeto de pila recién asignado o NULL si no hay suficiente memoria disponible.

sk_set_cmp_func() devuelve un puntero a la función de comparación que se instaló previamente para la stack o NULL si no se instaló ninguna.

sk_num() devuelve el número de punteros actualmente almacenados en la stack, o -1 si stack es un puntero NULL.

sk_value() devuelve el puntero con el índice dado de la stack, o NULL si stack es un puntero NULL o si el index es menor que 0 o mayor o igual que sk_num(stack).

sk_find() devuelve el índice más bajo considerado que coincide o -1 si stack es un puntero NULL o si no se encuentra ninguna coincidencia.

sk_is_sorted() devuelve 1 si la stack se considera ordenada o si es un puntero NULL, o 0 en caso contrario.

sk_push(), sk_unshift() y sk_insert() devuelven el nuevo número de punteros en la stack o 0 si stack es un puntero NULL o si falla la asignación de memoria.

sk_set() devuelve new_item o NULL si stack es un puntero NULL o si el index es menor que 0 o mayor o igual que sk_num(stack).

sk_pop() y sk_shift() devuelven el puntero eliminado o NULL si stack es un puntero NULL o si está vacía.

sk_delete() devuelve el puntero eliminado o NULL si stack es un puntero NULL o si el index es menor que 0 o mayor o igual que sk_num(stack).

sk_delete_ptr() devuelve wanted o NULL si no se encuentra.

HISTORIA

sk_new_null(), sk_new(), sk_free(), sk_pop_free(), sk_num(), sk_value(), sk_find(), sk_push(), sk_unshift(), sk_insert(), sk_pop(), sk_shift(), sk_delete() y sk_delete_ptr() aparecieron por primera vez en SSLeay 0.5.1. sk_set_cmp_func(), sk_dup() y sk_zero() aparecieron por primera vez en SSLeay 0.8.0. Estas funciones han estado disponibles desde OpenBSD 2.4.

sk_set() apareció por primera vez en OpenSSL 0.9.3. sk_sort() apareció por primera vez en OpenSSL 0.9.4. Ambas funciones han estado disponibles desde OpenBSD 2.6.

sk_is_sorted() apareció por primera vez en OpenSSL 0.9.7e y ha estado disponible desde OpenBSD 3.8.

ERRORES

Incluso si se instala una función de comparación, las pilas vacías y las pilas que contienen un solo puntero a veces se consideran ordenadas y a veces desordenadas.

Si se instala una función de comparación, el concepto de "primera coincidencia" en sk_find() está mal definido porque qsort(3) no es una función de ordenación estable. Probablemente sea mejor asumir solo que devuelven una coincidencia arbitraria.
