NAME

BIO_s_mem, BIO_set_mem_eof_return, BIO_get_mem_data, BIO_set_mem_buf, BIO_get_mem_ptr, BIO_new_mem_buf — BIO de memoria

SINOPSIS

biblioteca “libcrypto”
#include <openssl/bio.h>

const BIO_METHOD *
BIO_s_mem(void);

long
BIO_set_mem_eof_return(BIO *b, int v);

long
BIO_get_mem_data(BIO *b, char **pp);

long
BIO_set_mem_buf(BIO *b, BUF_MEM *bm, int c);

long
BIO_get_mem_ptr(BIO *b, BUF_MEM **pp);

BIO *
BIO_new_mem_buf(const void *buf, int len);

DESCRIPCIÓN

BIO_s_mem() devuelve la función del método BIO de memoria.

Un BIO de memoria es un BIO de origen/sumidero que utiliza memoria para su E/S. Los datos escritos en un BIO de memoria se almacenan en una estructura BUF_MEM que se extiende según sea necesario para acomodar los datos almacenados.

Cualquier dato escrito en un BIO de memoria puede ser recuperado leyendo desde él. A menos que el BIO de memoria sea de solo lectura, cualquier dato leído de él se elimina del BIO. Para saber si un BIO de memoria es de solo lectura, se puede llamar a BIO_test_flags(3) con un argumento de BIO_FLAGS_MEM_RDONLY.

Los BIO de memoria soportan BIO_gets(3) y BIO_puts(3).

Si la bandera BIO_CLOSE está establecida cuando se libera un BIO de memoria, la estructura subyacente BUF_MEM también se libera.

BIO_reset(3) llamado en un BIO de memoria de lectura/escritura borra cualquier dato en él. En un BIO de solo lectura, restaura el BIO a su estado original y los datos de solo lectura se pueden leer de nuevo.

BIO_eof(3) es verdadero si no hay datos en el BIO.

BIO_ctrl_pending(3) devuelve el número de bytes almacenados actualmente.

BIO_set_mem_eof_return() establece el comportamiento del BIO de memoria b cuando está vacío. Si v es cero, entonces un BIO de memoria vacío devolverá EOF: devolverá cero y BIO_should_retry() será falso. Si v es distinto de cero, entonces devolverá v cuando esté vacío y establecerá la bandera de reintento de lectura: BIO_read_retry() es verdadero. Para evitar ambigüedades con un valor de retorno positivo normal, v debe establecerse en un valor negativo, típicamente -1.

BIO_get_mem_data() establece *pp a un puntero al inicio de los datos del BIO de memoria y devuelve la cantidad total de datos disponibles.

BIO_set_mem_buf() establece la estructura interna BUF_MEM a bm y establece la bandera de cierre a c. Es decir, c debe ser BIO_CLOSE o BIO_NOCLOSE.

BIO_get_mem_ptr() coloca la estructura BUF_MEM subyacente en *pp.

BIO_new_mem_buf() crea un BIO de memoria utilizando len bytes de datos en buf. Si len es -1, entonces se asume que buf está terminado en NUL y su longitud se determina mediante strlen(3). El BIO se establece en estado de solo lectura y, como resultado, no se puede escribir en él. Esto es útil cuando se necesitan proporcionar datos desde un área de memoria estática en forma de un BIO. Los datos proporcionados se leen directamente del búfer proporcionado: no se copian primero, por lo que el área de memoria proporcionada debe permanecer sin cambios hasta que se libere el BIO.

Las escrituras en los BIO de memoria siempre tendrán éxito si hay memoria disponible: su tamaño puede crecer indefinidamente.

VALORES DE RETORNO

BIO_s_mem() devuelve un puntero a un objeto estático.

Cuando se llama en un objeto BIO de memoria, BIO_method_type(3) devuelve la constante BIO_TYPE_MEM y BIO_method_name(3) devuelve un puntero a la cadena estática "memory buffer".

BIO_set_mem_eof_return(), BIO_get_mem_data(), BIO_set_mem_buf(), y BIO_get_mem_ptr() devuelven 1 en caso de éxito o un valor menor o igual a 0 si ocurrió un error.

BIO_new_mem_buf() devuelve un objeto BIO recién asignado en caso de éxito o NULL en caso de error.

libressl(3) - BIO_s_mem

NAME

BIO_s_mem, BIO_new_mem_buf, BIO_set_mem_buf, BIO_get_mem_ptr, BIO_set_mem_eof_return, BIO_get_mem_data, BIO_ptr_mem, BIO_create_mem_buf - memory BIO

SYNOPSIS

BIO_METHOD *BIO_s_mem(void);
BIO *BIO_new_mem_buf(const void *buf, int len);
BIO *BIO_new(BIO_METHOD *type);
long BIO_set_mem_buf(BIO *bp, char *buf, int len);
long BIO_get_mem_ptr(BIO *bp, char **ptr);
long BIO_set_mem_eof_return(BIO *bp, int ret);
long BIO_get_mem_data(BIO *bp, char **ptr);
BIO *BIO_ptr_mem(BIO *bp, char **ptr);
BIO *BIO_create_mem_buf(const void *buf, int len);

DESCRIPTION

Memory BIOs are used to read from and write to memory buffers. They are convenient for applications that need to process data that is already in memory, or that need to build up data in memory before writing it out.

The memory BIO can be used in two main ways:

  • As a writable buffer: BIO_new(3) is called with BIO_s_mem() to create a new memory BIO. Data can then be written to it using standard BIO functions like BIO_puts(3). The buffer will automatically grow as needed.

  • As a read-only buffer: BIO_new_mem_buf() can be used to create a BIO from an existing memory buffer. This is useful for passing data to libraries or functions that expect a BIO interface. The len parameter specifies the number of bytes in buf. If len is set to -1, then buf must be null-terminated, and its length will be determined by the strnlen function. Note that this function makes a copy of the data in buf if len is not negative; otherwise, it uses the buffer directly. BIO_new_mem_buf() is now deprecated; use BIO_new_mem_buf_from() instead.

The following functions are related to memory BIOs:

BIO_s_mem(3)
Returns the method for memory BIOs.
BIO_new_mem_buf(3)
Creates a new memory BIO initialized with the contents of buf. If len is -1, buf is assumed to be a null-terminated string.
BIO_set_mem_buf(3)
Sets the internal buffer of a memory BIO. This function is deprecated and should not be used.
BIO_get_mem_ptr(3)
Retrieves a pointer to the internal buffer of a memory BIO. The caller is responsible for managing the memory pointed to by ptr after the BIO is freed. To prevent the BIO from freeing the buffer when BIO_free(3) is called, use BIO_set_close(3) with BIO_NOCLOSE.
BIO_set_mem_eof_return(3)
Sets the return value when end-of-file (EOF) is reached on a memory BIO. The default value is 0.
BIO_get_mem_data(3)
Retrieves a pointer to the data within a memory BIO. This is similar to BIO_get_mem_ptr() but returns the current data pointer and length. The caller should not free this pointer.
BIO_ptr_mem(3)
This function is deprecated. Use BIO_get_mem_ptr() instead.
BIO_create_mem_buf(3)
This function is deprecated. Use BIO_new_mem_buf() instead.

RETURN VALUES

All the functions described in this manual page return a pointer to a BIO on success, or NULL on failure. The return value of BIO_set_mem_buf() is 1 on success and 0 on failure.

EXAMPLES

Create a writable memory BIO and write some data to it:

BIO *mem = BIO_new(BIO_s_mem());
BIO_puts(mem, "Hello World\n");

Create a read only memory BIO:

char data[] = "Hello World";
BIO *mem;
mem = BIO_new_mem_buf(data, -1);

Extract the BUF_MEM structure from a memory BIO and then free up the BIO:

BUF_MEM *bptr;
BIO_get_mem_ptr(mem, &bptr);
/* Make sure BIO_free() leaves BUF_MEM alone. */
BIO_set_close(mem, BIO_NOCLOSE);
BIO_free(mem);

SEE ALSO

BIO_new(3), BUF_MEM_new(3)

HISTORY

BIO_s_mem() first appeared in SSLeay 0.6.0. BIO_set_mem_buf() and BIO_get_mem_ptr() first appeared in SSLeay 0.6.5. These functions have been available since OpenBSD 2.4.

BIO_set_mem_eof_return() and BIO_get_mem_data() first appeared in SSLeay 0.9.1 and have been available since OpenBSD 2.6.

BIO_new_mem_buf() first appeared in OpenSSL 0.9.5 and has been available since OpenBSD 2.7.

CAVEATS

Do not manually switch a writable memory BIO to read-only mode: calling BIO_set_flags(3) with an argument of BIO_FLAGS_MEM_RDONLY will ultimately result in a memory leak when the BIO object is finally handed to BIO_free(3). It might also cause security issues because it prevents BIO_reset(3) from clearing the data.

BUGS

There should be an option to set the maximum size of a memory BIO.

There should be a way to "rewind" a read/write BIO without destroying its contents.
