DESCRIPCIÓN

BIO_s_datagram() devuelve el método BIO de socket datagrama. La aplicación habitual es para transmitir datos utilizando el protocolo udp(4) IPv4 o IPv6.

Al ser llamado en un objeto BIO de socket datagrama, BIO_method_type(3) devuelve la constante BIO_TYPE_DGRAM y BIO_method_name(3) devuelve un puntero a la cadena estática "datagram socket".

Constructores y destructores

BIO_new(3) asigna un nuevo objeto BIO de socket datagrama e inicializa todos sus datos a cero, incluyendo el descriptor de archivo del socket datagrama, la dirección del par, el indicador de inicialización que puede ser recuperado con BIO_get_init(3), el indicador conectado, la MTU y toda la información de tiempo de espera y error. El contador de referencias y el indicador de cierre se establecen a 1.

BIO_new_dgram() asigna e inicializa un nuevo objeto BIO de socket datagrama con BIO_new(3), establece el descriptor de archivo del socket datagrama y el indicador de cierre según sus argumentos, y establece el indicador de inicialización a 1.

Si el contador de referencias llega a 0 en BIO_free(3) y los indicadores de cierre e inicialización están establecidos, se llama a shutdown(2) y close(2) en el descriptor de archivo del socket datagrama antes de liberar el almacenamiento utilizado por el objeto BIO.

Cuando una cadena que contiene un BIO de socket datagrama se copia con BIO_dup_chain(3), el descriptor de archivo del socket datagrama, el indicador de inicialización, el indicador de cierre, los indicadores accesibles con BIO_test_flags(3), y cualquier dato que se haya establecido con BIO_set_ex_data(3) se copian automáticamente del objeto BIO original al nuevo, pero la dirección del par, el indicador conectado, la MTU y toda la información de tiempo de espera y error no se copian, sino que se inicializan a cero.

Inicialización y configuración

Si el indicador de cierre está establecido en b, BIO_set_fd(3) borra todos los indicadores que están establecidos en b y si el indicador de inicialización estaba establecido, llama a shutdown(2) y close(2) en el descriptor de archivo previamente asignado. En cualquier caso, BIO_set_fd(3) establece entonces el nuevo descriptor de archivo y el nuevo indicador de cierre según sus argumentos y establece el indicador de inicialización a 1.

Si el indicador de inicialización está establecido en b, BIO_get_fd(3) devuelve su descriptor de archivo de socket datagrama y, a menos que el argumento c sea un puntero NULL, también almacena el descriptor de archivo en *c. Si el indicador de inicialización no está establecido, BIO_get_fd(3) falla y devuelve -1.

BIO_set_close(3) establece el indicador de cierre en b al argumento flag. BIO_get_close(3) devuelve el valor del indicador de cierre de b.

Para objetos BIO de socket datagrama, el indicador de apagado es el mismo indicador que el indicador de cierre. En consecuencia, BIO_set_shutdown(3) tiene el mismo efecto que BIO_set_close(3) y BIO_get_shutdown(3) tiene el mismo efecto que BIO_get_close(3).

BIO_dgram_set_peer() copia sa como la dirección del par en b.

BIO_ctrl_dgram_connect() hace exactamente lo mismo que BIO_dgram_set_peer(). Su nombre es incluso más engañoso que el nombre de BIO_ctrl_set_connected(). Además de lo dicho allí, BIO_ctrl_dgram_connect() ni siquiera establece el indicador conectado en b.

BIO_dgram_get_peer() copia la dirección del par de b a *sa. Antes de llamar a esta función, el llamante debe asegurarse de que la dirección del par esté realmente establecida en b y que haya suficiente memoria disponible a partir de sa para copiar una completa struct sockaddr, struct sockaddr_in, o struct sockaddr_in6 a ese lugar, dependiendo de qué familia de direcciones esté utilizando actualmente b.

A menos que sa sea NULL, BIO_ctrl_set_connected() establece el indicador conectado en b y copia sa como la dirección del par en b. Si sa es NULL, BIO_ctrl_set_connected() borra el indicador conectado y la dirección del par en b. Teniendo en cuenta que la comunicación utilizando un protocolo datagrama no establece conexión, el nombre de esta función es engañoso. No está estableciendo ni terminando una conexión, ni cambiando nada con respecto al estado del socket datagrama, sino simplemente modificando algunos datos puramente informativos en el objeto BIO envolvente. El argumento adicional argl se pasa a las devoluciones de llamada documentadas en BIO_set_callback(3) si hay tales devoluciones de llamada instaladas.

Indicadores y errores temporizados

El indicador de tiempo de espera de recepción en b se puede consultar y modificar con BIO_get_recv_timeout(3) y BIO_set_recv_timeout(3), respectivamente. Si la operación de recepción en curso falla por tiempo de espera, la llamada a BIO_read(3) devolverá un valor negativo, indicando un error, y la función BIO_dgram_recv_timedout() devolverá 1.

El indicador de tiempo de espera de envío en b se puede consultar y modificar con BIO_get_send_timeout(3) y BIO_set_send_timeout(3), respectivamente. Si la operación de envío en curso falla por tiempo de espera, la llamada a BIO_write(3) devolverá un valor negativo, indicando un error, y la función BIO_dgram_send_timedout() devolverá 1.

Si el indicador de tiempo de espera de recepción o envío está establecido en 0, las operaciones de recepción o envío no esperarán indefinidamente y devolverán inmediatamente un error si la operación no se puede completar en el momento.

Cuando se produce un error no fatal, como EWOULDBLOCK o EAGAIN, que no causa la terminación de la operación, pero que puede ser indicativo de una posible demora, se llama a la función BIO_dgram_non_fatal_error() para que determine si el error está configurado en un indicador no fatal.

Los errores no fatales pueden ser configurados con BIO_ctrl_set_fd(3), pasando el valor de los errores como primer argumento (argl) y el descriptor de archivo como segundo argumento (arg). Tenga en cuenta que el error EINTR no es un error no fatal en el sentido de que se espera que las operaciones se reintente automáticamente y por lo tanto no se puede configurar como un error no fatal.

MTU

La Unidad de Transmisión Máxima (MTU) puede establecerse con BIO_ctrl_set_mtu(3), y ser recuperada con BIO_get_mtu(3). Si el valor de la MTU no se establece explícitamente, se asume que es 1500.

Operaciones de lectura y escritura

La operación de lectura en un BIO de socket datagrama llama a recvfrom(2). La operación de escritura llama a sendto(2).

Si el indicador conectado está establecido, la llamada a recvfrom(2) se reemplaza por una llamada a recv(2) y la llamada a sendto(2) se reemplaza por una llamada a send(2). Es importante tener en cuenta que un socket datagrama no establece conexión y, por lo tanto, estas llamadas a recv y send funcionan de manera diferente de lo esperado. Específicamente, send intentará enviar los datos a la dirección del par predeterminada, y recv intentará leer los datos de la dirección del par predeterminada.


DESCRIPTION

Datagram sockets are connectionless. They are normally used for protocols like UDP. A datagram socket BIO is created using BIO_new_dgram(3).

The fd argument is the file descriptor of the datagram socket. The flags argument can be 0 or BIO_DGRAM_CONNECT. If BIO_DGRAM_CONNECT is set, then the socket is considered to be connected to a specific peer. This means that you don't have to specify the peer address when writing, and you will only receive datagrams from that peer. If the flag is not set, then the peer address must be specified for each write operation, and datagrams from any peer will be received. Note that the connection is not a full connection like for stream sockets; it's merely an indication that datagrams should only be sent to and received from a particular peer.

The peer address is set using BIO_ctrl(3) with the BIO_CTRL_DGRAM_SET_PEER command. The address is specified in parg as a pointer to a struct sockaddr * of length parglen.

The peer address can be retrieved using BIO_ctrl(3) with the BIO_CTRL_DGRAM_GET_PEER command. The address is returned in parg and its length in parglen.

If the socket is connected, BIO_ctrl(3) with BIO_CTRL_DGRAM_CONNECT (with larg non-zero) can be used to disconnect the socket. Similarly, BIO_CTRL_DGRAM_SET_CONNECTED can be used to set or unset the connected state.

BIO_ctrl(3) with a cmd of BIO_CTRL_DGRAM_SET_NEXT_TIMEOUT interprets the parg argument as a pointer to a struct timeval and sets the read timeout to the specified absolute UTC time.

BIO_ctrl(3) with a cmd of BIO_CTRL_DGRAM_SET_RECV_TIMEOUT, BIO_CTRL_DGRAM_GET_RECV_TIMEOUT, BIO_CTRL_DGRAM_SET_SEND_TIMEOUT, or BIO_CTRL_DGRAM_GET_SEND_TIMEOUT interprets the parg argument as a pointer to a struct timeval and calls setsockopt(2) or getsockopt(2) on the datagram socket file descriptor of b with an argument of SO_RCVTIMEO or SO_SNDTIMEO, respectively. BIO_CTRL_DGRAM_SET_RECV_TIMEOUT and BIO_CTRL_DGRAM_SET_SEND_TIMEOUT return 1 on success, BIO_CTRL_DGRAM_GET_RECV_TIMEOUT and BIO_CTRL_DGRAM_GET_SEND_TIMEOUT the number of bytes written to *parg. All four return -1 on failure. Remember that BIO_read(3) may actually use a shorter timeout when BIO_CTRL_DGRAM_SET_NEXT_TIMEOUT is in effect.

BIO_ctrl(3) with a cmd of BIO_CTRL_DGRAM_GET_FALLBACK_MTU returns 1232 if the peer address is an IPv6 address that is not IPv4 mapped or 548 otherwise. Making sure that a peer address is set before issuing this command is the responsibility of the caller.

BIO_ctrl(3) with a cmd of BIO_CTRL_DGRAM_SET_MTU sets the MTU attribute of b to the value of the larg argument and also returns that argument. BIO_ctrl(3) with a cmd of BIO_CTRL_DGRAM_GET_MTU returns the MTU attribute of b or 0 if it was not set.

BIO_ctrl(3) with a cmd of BIO_CTRL_DGRAM_MTU_EXCEEDED returns 1 if the most recent non-fatal failure of BIO_read(3) or BIO_write(3) was caused by EMSGSIZE or 0 otherwise. This command also clears the errno(2) value that was saved internally for this particular purpose, so that issuing the same command again will return 0 until the next EMSGSIZE failure occurs.

BIO_dgram_recv_timedout() and BIO_dgram_send_timedout() check whether the most recent non-fatal failure of BIO_read(3) or BIO_write(3) was caused by EAGAIN. Despite having different names, both functions do exactly the same, and both inspect the most recent non-fatal I/O failure, no matter whether it occurred during a receive or send operation. Both functions also clear the errno(2) value that was saved internally for this particular purpose, so that calling these functions again will return 0 until the next EAGAIN failure occurs.

Datagram socket BIOs do not support BIO_eof(3), BIO_get_mem_data(3), BIO_pending(3), BIO_reset(3), BIO_seek(3), BIO_tell(3), and BIO_wpending(3), and attempting any such operation results in failure and returns a value of 0.

Input and output operations

BIO_read(3) attempts to read up to len bytes into buf from the datagram socket file descriptor using recvfrom(2). If a read timeout is set, setsockopt(2) is used with an argument of SO_RCVTIMEO to temporarily shorten the timeout on the datagram socket during the recvfrom(2) call such that it returns before the read timeout expires.

If recvfrom(2) succeeds and the connected flag is not yet set, BIO_read(3) also copies the peer address received from recvfrom(2) into b.

If recvfrom(2) is attempted, BIO_read(3) clears the flags BIO_FLAGS_WRITE and BIO_FLAGS_IO_SPECIAL in b and clears or sets the flags BIO_FLAGS_READ and BIO_FLAGS_SHOULD_RETRY as appropriate.

If the connected flag is set in b, BIO_write(3) attempts to write(2) len bytes from buf to the datagram socket file descriptor. If the connected flag is not set, it attempts to transmit len bytes from buf to the peer using sendto(2).

If write(2) or sendto(2) is attempted, BIO_write(3) clears the flags BIO_FLAGS_READ and BIO_FLAGS_IO_SPECIAL in b and clears or sets the flags BIO_FLAGS_WRITE and BIO_FLAGS_SHOULD_RETRY as appropriate.

The effect of BIO_puts(3) is similar to the effect of BIO_write(3) with a len argument of strlen(string).

Datagram socket BIOs do not support BIO_gets(3). Calling this function fails and returns -2.

BIO_flush(3) has no effect on a datagram socket BIO. It always succeeds and returns 1.

RETURN VALUES

BIO_s_datagram() returns the datagram socket BIO method.

BIO_new_dgram() returns a newly allocated datagram socket BIO object or NULL on failure.

BIO_dgram_set_peer(), BIO_ctrl_dgram_connect(), and BIO_ctrl_set_connected() return 1 on success or a value less than or equal to zero on failure. They can only fail if b is not a datagram socket BIO object.

BIO_dgram_get_peer() returns the number of bytes copied to sa or a value less than or equal to zero on failure. It can only fail if b is not a datagram socket BIO object.

BIO_dgram_recv_timedout() and BIO_dgram_send_timedout() return 1 if the most recent non-fatal I/O error was caused by EAGAIN or 0 otherwise.

BIO_dgram_non_fatal_error() returns 1 if errnum is EAGAIN, EALREADY, EINPROGRESS, or EINTR or 0 otherwise, even if errnum is 0.

ERRORES

Si getsockopt(2) o setsockopt(2) falla durante BIO_read(3), la biblioteca imprime un mensaje de error en la salida de error estándar pero ignora el problema, por lo tanto, posiblemente utilizando valores de tiempo de espera no deseados.

BIO_read(3) y BIO_write(3) pueden borrar la variable global errno(2) antes de intentar la llamada al sistema recvfrom(2) o sendto(2) pero pueden no borrarla si fallan antes de llegar a este punto.
