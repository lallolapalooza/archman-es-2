SSL_GET_ERROR(3) Manual de funciones de biblioteca SSL_GET_ERROR(3)

NOMBRE

SSL_get_error — obtener el código de resultado para la operación de E/S TLS/SSL

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_get_error(const SSL *ssl, int ret);

DESCRIPCIÓN

SSL_get_error() devuelve un código de resultado (adecuado para la instrucción C “switch”) para una llamada anterior a SSL_connect(3), SSL_accept(3), SSL_do_handshake(3), SSL_read(3), SSL_peek(3), o SSL_write(3) en ssl. El valor devuelto por esa función de E/S TLS/SSL debe pasarse a SSL_get_error() en el parámetro ret.

Además de ssl y ret, SSL_get_error() inspecciona la cola de errores OpenSSL del hilo actual. Por lo tanto, SSL_get_error() debe usarse en el mismo hilo que realizó la operación de E/S TLS/SSL, y no deben aparecer otras llamadas a funciones de OpenSSL entremedias. La cola de errores del hilo actual debe estar vacía antes de intentar la operación de E/S TLS/SSL, o SSL_get_error() no funcionará de manera fiable.

VALORES DEVUELTOS

Los siguientes valores de retorno pueden ocurrir actualmente:

SSL_ERROR_NONE
La operación de E/S TLS/SSL se completó. Este código de resultado se devuelve si y solo si ret > 0.
SSL_ERROR_ZERO_RETURN
La conexión TLS/SSL se ha cerrado. Si la versión del protocolo es SSL 3.0 o TLS 1.0, este código de resultado se devuelve solo si ha ocurrido una alerta de cierre en el protocolo, es decir, si la conexión se ha cerrado limpiamente. Tenga en cuenta que en este caso SSL_ERROR_ZERO_RETURN no indica necesariamente que el transporte subyacente se haya cerrado.
SSL_ERROR_WANT_READ, SSL_ERROR_WANT_WRITE
La operación no se completó; la misma función de E/S TLS/SSL debe llamarse de nuevo más tarde. Si, para entonces, el BIO subyacente tiene datos disponibles para leer (si el código de resultado es SSL_ERROR_WANT_READ) o permite escribir datos (SSL_ERROR_WANT_WRITE), entonces se producirá un progreso en el protocolo TLS/SSL, es decir, se leerá o escribirá al menos parte de un registro TLS/SSL. Tenga en cuenta que la reintentación puede conducir nuevamente a una condición de SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE. No hay un límite superior fijo para el número de iteraciones que pueden ser necesarias hasta que el progreso sea visible a nivel del protocolo de aplicación.

Para BIOs de socket (por ejemplo, cuando se usó SSL_set_fd()), select(2) o poll(2) en el socket subyacente pueden usarse para averiguar cuándo se debe reintentar la función de E/S TLS/SSL.

Precaución: Cualquier función de E/S TLS/SSL puede generar SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE. En particular, SSL_read(3) o SSL_peek(3) pueden querer escribir datos y SSL_write(3) puede querer leer datos. Esto se debe principalmente a que los handshakes TLS/SSL pueden ocurrir en cualquier momento durante el protocolo (iniciado por el cliente o el servidor); SSL_read(3), SSL_peek(3), y SSL_write(3) manejarán cualquier handshake pendiente.

SSL_ERROR_WANT_CONNECT, SSL_ERROR_WANT_ACCEPT
La operación no se completó; la misma función de E/S TLS/SSL debe llamarse de nuevo más tarde. El BIO subyacente aún no estaba conectado al par y la llamada se bloquearía en connect(2)/accept(2). La función SSL debe llamarse de nuevo cuando la conexión se establezca. Estos mensajes solo pueden aparecer con un BIO_s_connect(3) o BIO_s_accept(3) BIO, respectivamente. Para averiguar cuándo se ha establecido la conexión correctamente, en muchas plataformas select(2) o poll(2) para escribir en el descriptor de archivo del socket pueden usarse.
SSL_ERROR_WANT_X509_LOOKUP
La operación no se completó porque una devolución de llamada de aplicación configurada por SSL_CTX_set_client_cert_cb(3) ha solicitado ser llamada de nuevo. La función de E/S TLS/SSL debe llamarse de nuevo más tarde. Los detalles dependen de la aplicación.
SSL_ERROR_SYSCALL
Ocurrió un error de E/S. La cola de errores de OpenSSL puede contener más información sobre el error. Si la cola de errores está vacía (es decir, ERR_get_error() devuelve 0), ret puede usarse para obtener más información sobre el error: Si ret == 0, se observó un EOF que viola el protocolo. Si ret == −1, el BIO subyacente informó un error de E/S (para E/S de socket en sistemas Unix, consulte errno para obtener detalles).
SSL_ERROR_SSL
Ocurrió un fallo en la biblioteca SSL, generalmente un error de protocolo. La cola de errores de OpenSSL contiene más información sobre el error.

NAME

SSL_get_error — SSL error queue management

SYNOPSIS

#include <openssl/ssl.h>

int SSL_get_error(SSL *ssl, int ret);

DESCRIPTION

SSL_get_error inspects the SSL error queue associated with the SSL object ssl. The return value ret is the value returned by a previous SSL function call (e.g., SSL_read, SSL_write, SSL_connect, SSL_accept).

The function returns an integer value indicating the cause of the error:

  • SSL_ERROR_NONE: No error occurred. This is the return value if ret was greater than zero.
  • SSL_ERROR_SSL: A failure in the SSL library occurred. Further information might be available from the OpenSSL error queue (use ERR_get_error).
  • SSL_ERROR_WANT_READ: The SSL library needs to read more data from the underlying socket before it can continue the operation. The caller should wait for the socket to become readable.
  • SSL_ERROR_WANT_WRITE: The SSL library needs to write more data to the underlying socket before it can continue the operation. The caller should wait for the socket to become writable.
  • SSL_ERROR_WANT_CONNECT: The SSL library needs to perform a socket connect operation. This is typically seen in non-blocking mode when initiating a connection.
  • SSL_ERROR_WANT_ACCEPT: The SSL library needs to perform a socket accept operation. This is typically seen in non-blocking mode when initiating an accept.
  • SSL_ERROR_SYSCALL: A system call error occurred. The OpenSSL error queue might contain further details, or the specific system error code can be obtained using errno.
  • SSL_ERROR_ZERO_RETURN: A graceful closure of the connection was detected. This usually means the peer has shut down the connection.

If SSL_ERROR_SSL or SSL_ERROR_SYSCALL is returned, the specific error can be retrieved using ERR_get_error or by checking the value of errno respectively.

RETURN VALUES

Returns an integer representing the SSL error code. See DESCRIPTION for the possible values.

SEE ALSO

ERR_get_error(3), SSL_read(3), SSL_write(3), SSL_connect(3), SSL_accept(3)

HISTORY

The SSL_get_error function first appeared in OpenSSL 0.9.3.
