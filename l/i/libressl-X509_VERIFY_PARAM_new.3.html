DESCRIPCIÓN

X509_VERIFY_PARAM_new() asigna e inicializa un objeto X509_VERIFY_PARAM vacío.

X509_VERIFY_PARAM_inherit() copia algunos datos del objeto source al objeto destination.

Las banderas de verificación establecidas con X509_VERIFY_PARAM_set_flags(3) en el objeto source siempre se combinan (mediante OR bit a bit) con las banderas de verificación del objeto destination.

Los campos que tienen su valor predeterminado en el objeto source no se copian.

Por defecto, los campos en el objeto destination que ya tienen un valor no predeterminado no se sobrescriben. Sin embargo, si uno de los objetos source o destination fue creado durante una llamada a X509_STORE_CTX_init(3) que no tenía un argumento store, y si ese objeto no se utilizó previamente como destination en una llamada anterior a X509_VERIFY_PARAM_inherit(), esta restricción se suspende e incluso los campos no predeterminados en el objeto destination se sobrescriben. Si los campos sobrescritos de esta manera contienen punteros a memoria asignada, esa memoria se libera.

En la medida permitida por las reglas anteriores, se copian los siguientes campos:

  • el identificador del propósito de verificación establecido con X509_VERIFY_PARAM_set_purpose(3)
  • la configuración de confianza establecida con X509_VERIFY_PARAM_set_trust(3)
  • la hora de verificación establecida con X509_VERIFY_PARAM_set_time(3); en este caso, la única condición es que X509_V_FLAG_USE_CHECK_TIME no esté establecida en el objeto destination, mientras que el valor de tiempo en el objeto destination no se inspecciona antes de sobrescribirlo
  • la política aceptable establecida con X509_VERIFY_PARAM_set1_policies(3)
  • la profundidad máxima de verificación establecida con X509_VERIFY_PARAM_set_depth(3)
  • las banderas que se establecieron con X509_VERIFY_PARAM_set_hostflags(3)
  • la lista de nombres de host DNS esperados creada con X509_VERIFY_PARAM_set1_host(3) y X509_VERIFY_PARAM_add1_host(3)
  • la dirección de correo electrónico RFC 822 esperada establecida con X509_VERIFY_PARAM_set1_email(3)
  • la dirección IP esperada establecida con X509_VERIFY_PARAM_set1_ip(3) o X509_VERIFY_PARAM_set1_ip_asc(3)

Algunos datos que pueden estar contenidos en el objeto source nunca se copian, por ejemplo, el nombre del sujeto del certificado del par que se puede obtener con X509_VERIFY_PARAM_get0_peername(3).

Si source es un puntero NULL, la función no tiene efecto pero devuelve éxito.

X509_VERIFY_PARAM_set1() es idéntico a X509_VERIFY_PARAM_inherit() excepto en que los campos en el objeto destination se sobrescriben incluso si no coinciden con sus valores predeterminados. Aun así, los campos que tienen su valor predeterminado en el objeto source no se copian.

Si X509_VERIFY_PARAM_inherit() o X509_VERIFY_PARAM_set1() fallan, puede haber ocurrido una copia parcial, por lo que todos los datos en el objeto destination deben considerarse inválidos.

X509_VERIFY_PARAM_inherit() es utilizada internamente por X509_STORE_CTX_init(3) y por X509_STORE_CTX_set_default(3), y X509_VERIFY_PARAM_set1() es utilizada internamente por X509_STORE_set1_param(3).

X509_VERIFY_PARAM_free() limpia todos los datos contenidos en param y libera toda la memoria utilizada por él. Si param es un puntero NULL, no se realiza ninguna acción.

X509_VERIFY_PARAM_add0_table() agrega param a una lista estática de objetos X509_VERIFY_PARAM mantenida por la biblioteca. Esta función es extremadamente peligrosa porque, contrariamente al nombre de la función, si la lista ya contiene un objeto que tiene el mismo nombre, ese objeto antiguo no solo se elimina silenciosamente de la lista, sino que también se libera silenciosamente, lo que puede invalidar silenciosamente varios punteros existentes en otras partes del programa.

X509_VERIFY_PARAM_lookup() busca en esta lista un objeto con el name dado. Si no se encuentra ninguna coincidencia, también se inspeccionan los objetos predefinidos integrados en la biblioteca.

X509_VERIFY_PARAM_get_count() devuelve la suma del número de objetos en esta lista y el número de objetos predefinidos integrados en la biblioteca.

    size_t id

DESCRIPTION

The X509_VERIFY_PARAM object is used to specify and control the certificate verification process. It contains various parameters such as the set of trusted CA certificates, certificates and CRLs to be explicitly trusted or untrusted, verification flags, purpose, depth, time, etc.

The global verification parameters are stored in a table. This table is initially populated with some predefined objects.

X509_VERIFY_PARAM_new() allocates and initialises a new X509_VERIFY_PARAM object. This object is not automatically added to any global list and must be explicitly added using X509_VERIFY_PARAM_add0_table() if it is to be accessible by name or index.

X509_VERIFY_PARAM_inherit() copies the contents of the object pointed to by from to the object pointed to by param. Any existing parameters in param are freed. The flags argument specifies which flags in from should be copied. If flags is 0, then no flags are copied. Only flags that are also set in flags are copied. If from is NULL, then param is cleared.

X509_VERIFY_PARAM_set1() copies the contents of the object pointed to by from to the object pointed to by param. Any existing parameters in param are freed. All flags from from are copied.

X509_VERIFY_PARAM_free() frees the given X509_VERIFY_PARAM object param. If the object is currently in the global table, it is removed from the table before being freed. It is dangerous to call this function on objects that are not managed by X509_VERIFY_PARAM_new() or X509_VERIFY_PARAM_add0_table().

X509_VERIFY_PARAM_add0_table() adds the given X509_VERIFY_PARAM object param to the global list of verification parameters. The object is now owned by the list and will be freed when X509_VERIFY_PARAM_table_cleanup() is called or when the library is unloaded. The object should not be freed manually after this call. If an object with the same name already exists in the list, it is replaced.

X509_VERIFY_PARAM_lookup() searches the global list for an object with the given name and returns a pointer to it. The search is case-sensitive.

X509_VERIFY_PARAM_get_count() returns the number of objects currently in the global list. Note that this is not necessarily the total number of X509_VERIFY_PARAM objects existing in the program because there may be additional such objects that were never added to the list.

X509_VERIFY_PARAM_get0() accesses predefined and user-defined objects using id as an index, useful for looping over objects without knowing their names. An argument less than the number of predefined objects selects one of the predefined objects; a higher argument selects an object from the list.

X509_VERIFY_PARAM_table_cleanup() deletes all objects from this list. It is extremely dangerous because it also invalidates all data that was contained in all objects that were on the list and because it frees all these objects, which may invalidate various pointers existing elsewhere in the program.

RETURN VALUES

X509_VERIFY_PARAM_new() returns a pointer to the new object, or NULL on allocation failure.

X509_VERIFY_PARAM_inherit(), X509_VERIFY_PARAM_set1(), and X509_VERIFY_PARAM_add0_table() return 1 for success or 0 for failure.

X509_VERIFY_PARAM_lookup() and X509_VERIFY_PARAM_get0() return a pointer to an existing built-in or user-defined object, or NULL if no object with the given name is found, or if id is at least X509_VERIFY_PARAM_get_count().

X509_VERIFY_PARAM_get_count() returns a number of objects.
