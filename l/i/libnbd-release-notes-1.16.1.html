NOMBRE

libnbd-release-notes-1.16 - notas de la versión de libnbd 1.16

DESCRIPCIÓN

Estas son las notas de la versión de la versión estable de libnbd 1.16. Describen los cambios principales desde la versión 1.14.

libnbd 1.16.0 fue lanzado el **18 de abril de 2023**.

Seguridad

No se encontraron problemas de seguridad en esta versión.

Si encuentra un problema de seguridad, por favor lea SECURITY en el código fuente (en línea aquí: https://gitlab.com/nbdkit/libnbd/blob/master/SECURITY). Para saber sobre problemas de seguridad anteriores en libnbd, consulte libnbd-security(3).

Nuevas APIs

La nueva API nbd_supports_vsock(3) puede usarse para comprobar si el cliente tiene soporte para vsock (Eric Blake).

Nueva API nbd_poll2(3) que permite pasar un descriptor de archivo adicional (Ming Lei).

Nuevas APIs nbd_stats_bytes_sent(3), nbd_stats_bytes_received(3), nbd_stats_chunks_sent(3) y nbd_stats_chunks_received(3) que exponen el número de bytes y mensajes enviados y recibidos en la conexión actual (Eric Blake).

Las nuevas APIs nbd_opt_list_meta_context_queries(3) y nbd_aio_opt_list_meta_context_queries(3) le permiten consultar los metacontextos disponibles interactivamente con el servidor durante la fase de negociación del protocolo (Eric Blake).

La nueva API nbd_set_request_meta_context(3) le permite controlar si el metacontexto se establece durante la negociación. Esto puede hacer que ciertas operaciones sean más rápidas, especialmente "nbdinfo --list". (Eric Blake)

Las nuevas APIs nbd_opt_set_meta_context(3), nbd_opt_set_meta_context_queries(3), nbd_aio_opt_set_meta_context(3) y nbd_aio_opt_set_meta_context_queries(3) le permiten solicitar metacontextos al usar nbd_set_opt_mode(3) (Eric Blake).

Las nuevas APIs nbd_opt_structured_reply(3) y nbd_aio_opt_structured_reply(3) le permiten ajustar finamente cuándo se solicitan respuestas estructuradas durante la fase de negociación (Eric Blake).

Las nuevas APIs nbd_opt_starttls(3) y nbd_aio_opt_starttls(3) le permiten ajustar finamente cuándo se negocia STARTTLS (Eric Blake).

Las nuevas APIs nbd_set_socket_activation_name(3) y nbd_get_socket_activation_name(3) que le permiten nombrar el socket utilizado para la activación de sockets. Ciertos servidores como qemu-storage-daemon usarán este nombre en la línea de comandos y en scripts. (Gracias a Laszlo Ersek).

Mejoras en APIs existentes

nbd_connect_command(3) llamado con un parámetro argv nulo anteriormente fallaba, pero ahora devuelve un error (Eric Blake).

nbd_opt_list_meta_context(3) ahora puede ser llamado sin haber negociado respuestas estructuradas (Eric Blake).

nbd_set_strict_mode(3) tiene una nueva bandera "LIBNBD_STRICT_PAYLOAD" que puede usarse para controlar si se envían mensajes de tamaño excesivo, para probar servidores (Eric Blake).

Los parámetros de puntero de la API C que no pueden ser NULL ahora están anotados con "attribute((nonnull))" (si el compilador lo soporta) para que reciba una advertencia en tiempo de compilación si se usan incorrectamente (gracias Eric Blake).

Las APIs C que asignan memoria ahora están marcadas con "attribute((malloc))" y atribuciones similares para mejorar el análisis estático de programas que utilizan libnbd (Eric Blake).

Las APIs C que expresan valores de bandera ahora usan tipos sin signo, eliminando algunos casos límite indefinidos con matemáticas bit a bit en enteros con signo. Este cambio es compatible con versiones anteriores de API y ABI. (Eric Blake)

Herramientas

Nuevo programa nbdublk(1) que se utiliza para crear un dispositivo de bloque /dev/ublkb<N> de Linux a partir de un servidor NBD (gracias a Ming Lei).

nbdinfo(1) ahora tiene salida en color (use --no-color para deshabilitar).

nbdinfo tiene nuevas opciones --is tls y --can structured-reply para permitirle probar estas características en el servidor (Eric Blake).

nbdcopy(1) ahora escribe mensajes de progreso en stderr (anteriormente se escribían en /dev/tty). Esto lo hace consistente con otras herramientas como dd. (Eric Blake).

Las opciones -c y -u de nbdsh(1) ahora pueden alternarse, lo que facilita la activación/desactivación de las características opcionales de la URI (Eric Blake).

Bindings de idioma

La documentación para los bindings de OCaml ahora incluye nombres de parámetros.

Los bindings de OCaml ahora devuelven valores de error de OCaml en excepciones en lugar de números errno de C crudos.

Los bindings de OCaml ahora soportan nbd_aio_connect(3) que utiliza directamente el tipo sockaddr.

Los bindings de Python ahora tienen un método explícito "h.close()". Dejar que el manejador salga del ámbito todavía funciona para cerrar el manejador, pero ahora tiene la opción de cerrar explícitamente el manejador antes de que salga del ámbito. Si intenta usar el manejador después de cerrarlo, se lanzará una nueva excepción "nbd.ClosedHandle".

Los bindings de Python ahora proporcionan una función decorada con contextlib, por lo que puede escribir el más natural "with nbd.nbd() as h: ..."

Pruebas

Mayor cobertura de CI (Eric Blake).

Otras mejoras y correcciones de errores

La máquina de estados ahora puede lidiar y recuperarse de algunos mensajes de respuesta estructurados incorrectos y cookies desconocidas enviadas por el servidor (Eric Blake).

La biblioteca ahora está anotada con "-z nodelete", lo que evita que se descargue "realmente" cuando llama a dlclose(3). Esta es la única forma de evitar un fallo en código multihilo. Consulte el commit 368e3d0d5a887 para obtener más detalles.

Mejora la depuración cuando el manejador entra en el estado %DEAD.

La biblioteca es ahora mucho más compatible con POSIX y más resiliente al ejecutar subcomandos, ya no depende de las peculiaridades de la implementación de glibc de execvp y otras funciones no seguras para señales asíncronas (Laszlo Ersek).

Archivos fuente reformateados para usar ≤ 80 columnas (Laszlo Ersek).

Compilación

Corrige la compilación en Alpine Linux + musl que declara "AF_VSOCK" pero no define las estructuras asociadas (Eric Blake).

Distutils de Python, obsoleto en Python ≥ 3.10, ha sido reemplazado por sysconfig (gracias a Miro Hrončok).
