PKCS7_SIGN_ADD_SIGNER(3) Manual de funciones de biblioteca PKCS7_SIGN_ADD_SIGNER(3)

NOMBRE

PKCS7_sign_add_signer — añadir un firmante a una estructura SignedData

SINOPSIS

biblioteca “libcrypto”
#include <openssl/pkcs7.h>

PKCS7_SIGNER_INFO *
PKCS7_sign_add_signer(PKCS7 *p7, X509 *signcert, EVP_PKEY *pkey, const EVP_MD *md, int flags);

DESCRIPCIÓN

PKCS7_sign_add_signer() añade un firmante con el certificado signcert y la clave privada pkey usando el digest de mensaje md a una estructura de datos firmada PKCS7 p7.

La estructura PKCS7 debe obtenerse de una llamada inicial a PKCS7_sign(3) con el flag PKCS7_PARTIAL establecido o, en el caso de volver a firmar, una estructura de datos firmada PKCS7 válida.

Si el parámetro md es NULL, entonces se usará el digest predeterminado para el algoritmo de clave pública.

A menos que el flag PKCS7_REUSE_DIGEST esté establecido, la estructura PKCS7 devuelta no está completa y debe ser finalizada ya sea por streaming (si aplica) o por una llamada a PKCS7_final(3).

El propósito principal de esta función es proporcionar un control más fino sobre una estructura de datos firmada PKCS#7 donde la función más simple PKCS7_sign(3) con valores predeterminados no es apropiada, por ejemplo si se necesitan múltiples firmantes o algoritmos de digest no predeterminados.

Cualquiera de los siguientes flags (combinados con OR) puede ser pasado en el parámetro flags.

Si PKCS7_REUSE_DIGEST está establecido, entonces se intenta copiar el valor del digest de contenido de la estructura PKCS7: para añadir un firmante a una estructura existente. Ocurre un error si no se encuentra un valor de digest coincidente para copiar. La estructura PKCS7 devuelta será válida y finalizada cuando este flag esté establecido.

Si PKCS7_PARTIAL está establecido además de PKCS7_REUSE_DIGEST, entonces la estructura PKCS7_SIGNER_INO no se finalizará, por lo que se pueden añadir atributos adicionales. En este caso, se necesita una llamada explícita a PKCS7_SIGNER_INFO_sign() para finalizarla.

Si PKCS7_NOCERTS está establecido, el certificado del firmante no se incluirá en la estructura PKCS7, aunque el certificado del firmante aún debe ser proporcionado en el parámetro signcert. Esto puede reducir el tamaño de la firma si el certificado del firmante se puede obtener por otros medios: por ejemplo, un mensaje firmado previamente.

La estructura signedData incluye varios PKCS#7 authenticatedAttributes, incluyendo la hora de firma, el tipo de contenido PKCS#7 y la lista soportada de cifradores en un atributo SMIMECapabilities. Si PKCS7_NOATTR está establecido, entonces no se usarán authenticatedAttributes. Si PKCS7_NOSMIMECAP está establecido, entonces solo se omiten los SMIMECapabilities.

Si está presente, el atributo SMIMECapabilities indica soporte para los siguientes algoritmos: triple DES, RC2 de 128 bits, RC2 de 64 bits, DES y RC2 de 40 bits. Si alguno de estos algoritmos está deshabilitado, entonces no se incluirá.

PKCS7_sign_add_signer() devuelve un puntero interno a la estructura PKCS7_SIGNER_INFO recién añadida, que puede ser utilizada para establecer atributos adicionales con las funciones descritas en PKCS7_add_attribute(3) antes de que sea finalizada.

VALORES DE RETORNO

PKCS7_sign_add_signer() devuelve un puntero interno a la estructura PKCS7_SIGNER_INFO recién añadida o NULL si ocurre un error. En algunos casos de fallo, la razón puede ser determinada con ERR_get_error(3).

VER TAMBIÉN

EVP_DigestInit(3), PKCS7_add_attribute(3), PKCS7_final(3), PKCS7_get_signer_info(3), PKCS7_new(3), PKCS7_sign(3)
