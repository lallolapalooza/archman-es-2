BIO_FIND_TYPE(3) Manual de funciones de biblioteca BIO_FIND_TYPE(3)

NOMBRE

BIO_find_type, BIO_next, BIO_method_type, BIO_method_name — recorrido de cadenas BIO

SINOPSIS

biblioteca “libcrypto”
#include <openssl/bio.h>

BIO *
BIO_find_type(BIO *bio, int type);

BIO *
BIO_next(BIO *bio);

int
BIO_method_type(const BIO *bio);

const char *
BIO_method_name(const BIO *bio);

#define BIO_TYPE_NONE 0
#define BIO_TYPE_START 128

DESCRIPCIÓN

BIO_find_type() busca un BIO que coincida con el type dado en la cadena que comienza en bio. Si el byte menos significativo del argumento type no es cero, solo se aceptan coincidencias exactas del type. De lo contrario, una coincidencia solo requiere que alguno de los bits establecidos en el argumento type también esté establecido en el BIO candidato.

Los tipos con un byte menos significativo en el rango de 0 a BIO_TYPE_START, inclusive, están reservados para tipos de BIO integrados en la biblioteca. Los tipos con un byte menos significativo mayor que BIO_TYPE_START están disponibles para tipos de BIO definidos por el usuario; ver BIO_get_new_index(3) para más detalles.

BIO_next() devuelve el siguiente BIO en la cadena después de bio. Esta función se puede usar para recorrer todos los BIOs en una cadena o en conjunción con BIO_find_type() para encontrar todos los BIOs de un tipo determinado.

BIO_method_type() devuelve el tipo del bio dado.

BIO_method_name() devuelve una cadena ASCII que representa el tipo del bio.

Los siguientes son los tipos de BIO de origen/destino integrados que operan en descriptores de archivo. Todos tienen los bits BIO_TYPE_SOURCE_SINK y BIO_TYPE_DESCRIPTOR, pero no el bit BIO_TYPE_FILTER establecidos en su constante de tipo.

tipo constante nombre cadena BIO_METHOD
BIO_TYPE_ACCEPT aceptar socket BIO_s_accept(3)
BIO_TYPE_CONNECT conectar socket BIO_s_connect(3)
BIO_TYPE_DGRAM socket datagrama BIO_s_datagram(3)
BIO_TYPE_FD descriptor de archivo BIO_s_fd(3)
BIO_TYPE_SOCKET socket BIO_s_socket(3)

Los siguientes son los tipos de BIO de origen/destino integrados que no operan directamente en descriptores de archivo. Todos tienen el bit BIO_TYPE_SOURCE_SINK pero no los bits BIO_TYPE_DESCRIPTOR y BIO_TYPE_FILTER establecidos en su constante de tipo.

tipo constante nombre cadena BIO_METHOD
BIO_TYPE_BIO par BIO BIO_s_bio(3)
BIO_TYPE_FILE puntero FILE BIO_s_file(3)
BIO_TYPE_MEM buffer de memoria BIO_s_mem(3)
BIO_TYPE_NULL NULL BIO_s_null(3)

Los siguientes son los tipos de BIO de filtro integrados. Todos tienen el bit BIO_TYPE_FILTER pero no los bits BIO_TYPE_SOURCE_SINK y BIO_TYPE_DESCRIPTOR establecidos en su constante de tipo.

tipo constante nombre cadena BIO_METHOD
BIO_TYPE_BASE64 codificación base64 BIO_f_base64(3)
BIO_TYPE_BUFFER buffer BIO_f_buffer(3)
BIO_TYPE_CIPHER cifrado BIO_f_cipher(3)
BIO_TYPE_MD resumen de mensaje BIO_f_md(3)
BIO_TYPE_NULL_FILTER filtro NULL BIO_f_null(3)
BIO_TYPE_SSL ssl BIO_f_ssl(3)

Las constantes BIO_TYPE_BER, BIO_TYPE_PROXY_CLIENT, y BIO_TYPE_PROXY_SERVER no corresponden a ningún tipo de BIO implementado por la biblioteca y tampoco están destinadas a ser utilizadas para tipos definidos por la aplicación. Las constantes BIO_TYPE_COMP, BIO_TYPE_LINEBUFFER, y BIO_TYPE_NBIO_TEST corresponden a tipos de BIO obsoletos que están intencionalmente indocumentados.

Si una variable en un programa de aplicación está destinada a almacenar un tipo de BIO pero temporalmente no se refiere a ningún BIO o se refiere a un BIO de un tipo desconocido, se recomienda establecer la variable en BIO_TYPE_NONE.

BIO_find_type() devuelve el siguiente BIO coincidente o NULL si bio es un puntero NULL o si no se encuentra ningún BIO coincidente.

libressl(3) - BIO_find_type

NAME

BIO_find_type, BIO_next, BIO_method_type, BIO_method_name — find or iterate through BIO chains

SYNOPSIS

#include <openssl/bio.h>

BIO *
BIO_find_type(BIO *bio, int type);

BIO *
BIO_next(BIO *bio);

int
BIO_method_type(BIO *bio);

const char *
BIO_method_name(BIO *bio);

DESCRIPTION

BIOs can be linked together into a chain. A BIO chain is traversed using the BIO_next() function, which returns the next BIO in the chain, or NULL if the end of the chain is reached.

The BIO_find_type() function searches the chain starting from bio for a BIO of the given type. The type must be one of the BIO_TYPE_* constants defined in <openssl/bio.h>. If a BIO of the specified type is found, it is returned. Otherwise, NULL is returned.

BIO_method_type() returns one of the BIO_TYPE_* constants.

BIO_method_name() returns an internal pointer to a string.

RETURN VALUES

BIO_find_type() returns the first BIO matching the specified type, or NULL if none is found or if the end of the chain is reached.

BIO_next() returns the next BIO in the chain, or NULL if the end of the chain is reached.

BIO_method_type() returns one of the BIO_TYPE_* constants.

BIO_method_name() returns an internal pointer to a string.

EXAMPLES

Traverse a chain looking for digest BIOs:

BIO *btmp;

btmp = in_bio;	/* in_bio is the chain to search through */
while (btmp != NULL) {
	btmp = BIO_find_type(btmp, BIO_TYPE_MD);
	if (btmp == NULL)
		break;	/* Not found */

	/* btmp is a digest BIO, do something with it ... */
	...

	btmp = BIO_next(btmp);
}

BIO_meth_new(3), BIO_new(3)

HISTORY

BIO_method_type() and BIO_method_name() first appeared in SSLeay 0.6.0. BIO_find_type() first appeared in SSLeay 0.6.6. These functions have been available since OpenBSD 2.4.

BIO_next() first appeared in OpenSSL 0.9.6 and has been available since OpenBSD 2.9.
