DESCRIPCIÓN

libinn es una biblioteca de rutinas de utilidad para manipular artículos de Usenet y datos relacionados. Toda la documentación de las rutinas de libinn se divide en varias páginas de manual específicas además de esta: libinn_clientlib(3), libinn_dbz(3), libinn_inndcomm(3), libinn_list(3), libinn_qio(3), libinn_tst(3) y libinn_uwildmat(3).

MACROS

"ISWHITE" es una macro que comprueba si su argumento de tipo char es un espacio o una tabulación.

RUTINAS RELACIONADAS CON ENCABEZADOS

GenerateMessageID utiliza la hora actual, el ID de proceso de nnrpd, un contador estático global que se incrementa en cada publicación en la misma sesión NNTP, y un nombre de dominio completamente calificado, que se pasa como argumento, para crear un campo de encabezado Message-ID que probablemente sea único. El valor devuelto apunta a un espacio estático que se reutiliza en llamadas posteriores. Si el argumento es NULL, se llama a inn_getfqdn para encontrar un FQDN adecuado (utilizando domain tal como se establece en inn.conf para calificar el nombre del host local si este no se puede resolver en DNS).

HeaderCleanFrom elimina la información superflua del valor de un campo de encabezado From o Reply-To y deja solo la dirección de correo electrónico oficial. En particular, se realizan las siguientes transformaciones al parámetro from:

  • dirección --> dirección
  • dirección (cosas) --> dirección
  • cosas <dirección> --> dirección

Las transformaciones son simples, basadas en RFC 5536, que limita el formato del campo de encabezado.

DDstart, DDcheck y DDend se utilizan para establecer el campo de encabezado Distribution; el "DD" significa Default Distribution (Distribución Predeterminada). El archivo distrib.pats se consulta para determinar el valor correcto para el campo de encabezado Distribution después de que se hayan verificado todos los grupos de noticias. DDstart inicia el análisis. Devuelve un puntero a un manejador opaco que debe usarse en llamadas posteriores. Los parámetros FromServer y ToServer deben ser "FILE"s conectados al servidor NNTP para entrada y salida, respectivamente. Si alguno de los parámetros es NULL, entonces se devolverá un valor predeterminado vacío al final si el archivo no está disponible localmente.

DDcheck debe llamarse con el manejador, h, devuelto por DDstart y un grupo de noticias, group, para comprobar. Se puede llamar tantas veces como sea necesario.

DDend libera cualquier estado mantenido en el manejador y devuelve una copia asignada del texto que debe usarse para el campo de encabezado Distribution.

BLOQUEO DE CANCELACIÓN

Estas rutinas están disponibles en libinn si INN se compiló con soporte para Cancel-Lock (de lo contrario, son funciones de marcador de posición que siempre devuelven falso). El script "configure" habilita automáticamente ese soporte si encuentra libcanlock.

gen_cancel_lock espera un Message-ID, un nombre de usuario (posiblemente NULL) y la dirección de un puntero donde escribirá elementos adecuados para el cuerpo de un campo de encabezado Cancel-Lock.

gen_cancel_key espera el cuerpo de un campo de encabezado Control (posiblemente NULL), el cuerpo de un campo de encabezado Supersedes (posiblemente NULL), un nombre de usuario (posiblemente NULL) y la dirección de un puntero donde escribirá elementos adecuados para el cuerpo de un campo de encabezado Cancel-Key. Esta función extrae el Message-ID del cuerpo del campo de encabezado Control o, si es NULL, del cuerpo del campo de encabezado Supersedes. Si el campo de encabezado utilizado para esa extracción no tiene el formato correcto, o ambos son NULL, o no se encuentra ningún Message-ID, el resultado será un error.

Estas funciones devuelven verdadero si se escribieron todos los elementos, falso en caso de error. La cadena canbuff será asignada por estas funciones, a menos que devuelvan falso. El llamador es responsable de liberarla.

Para cada secreto de administrador en el vector canlockadmin establecido en inn.conf, y para cada secreto de usuario establecido en el vector canlockuser en inn.conf si username no es NULL, gen_cancel_lock generará en canbuff hashes codificados en Base64 tanto sha1 como sha256. Con respecto a gen_cancel_key, será para cada secreto de administrador en el vector canlockadmin si username es NULL o para cada secreto de usuario en el vector canlockuser si username no es NULL.

verify_cancel_lock espera punteros a los cuerpos de los campos de encabezado Cancel-Key y Cancel-Lock. Esta función verifica que c_key_header contenga un elemento que coincida con uno de los presentes en c_lock_header. Devuelve verdadero si al menos un elemento coincide. De lo contrario, devuelve falso, es decir, la solicitud de cancelación o reemplazo no se puede autenticar.

DESCRIPCIÓN

La biblioteca libinn contiene varias funciones de utilidad que se utilizan comúnmente en la familia de programas InterNetNews. Estas funciones cubren una variedad de propósitos, que incluyen la gestión de archivos, el bloqueo de archivos, las funciones NNTP, el hashing, la obtención de nombres de host completos y varios servicios varios.

Funciones de gestión de archivos

CAopen abre el archivo de artículos activos locales y devuelve un puntero a un FILE para él. Los parámetros from, host y user se utilizan para obtener las cabeceras del artículo si no se pueden encontrar localmente. Si estas cabeceras no son NULL, CAopen las utilizará para consultar el servidor NNTP usando el comando LIST para crear una copia temporal local.

CAlistopen envía un comando LIST al servidor y devuelve un archivo temporal que contiene los resultados. El parámetro request, si no es NULL, se enviará como argumento al comando. A diferencia de CAopen, esta rutina nunca usará una copia localmente disponible del archivo de artículos activos.

CAclose cierra el archivo de artículos activos y elimina cualquier archivo temporal que pudiera haber sido creado por CAopen o CAlistopen.

BLOQUEO DE ARCHIVOS

inn_lock_file intenta bloquear el descriptor de archivo fd. Si block es verdadero, bloqueará hasta que se pueda realizar el bloqueo; de lo contrario, devolverá falso si el archivo no se puede bloquear. type es uno de "INN_LOCK_READ", "INN_LOCK_WRITE" o "INN_LOCK_UNLOCK". Devuelve falso en caso de fallo o verdadero en caso de éxito.

FUNCIONES NNTP

NNTPlocalopen abre una conexión al puerto privado de un servidor InterNetNews en ejecución en el host local, si "HAVE_UNIX_DOMAIN_SOCKETS" en include/config.h está definido. Devuelve "-1" en caso de fallo, o 0 en caso de éxito. FromServerp y ToServerp se llenarán con "FILE" que se pueden usar para comunicarse con el servidor. errbuff puede ser NULL o un puntero a un búfer de al menos 512 bytes de longitud. Si no es NULL, y el servidor rechaza la conexión, entonces se llenará con el texto de la respuesta del servidor. len debe ser la longitud del búfer errbuff. Esta rutina no es para uso general. Si "HAVE_UNIX_DOMAIN_SOCKETS" en include/config.h no está definido, esta es una rutina de marcador de posición, para compatibilidad con sistemas que tienen sockets de flujo de dominio Unix, y luego siempre devuelve "-1".

NNTPremoteopen hace lo mismo, excepto que utiliza el parámetro server configurado en inn.conf como el servidor local, y abre una conexión al port. Cualquier programa cliente puede utilizar esta rutina. Devuelve "-1" en caso de fallo, o 0 en caso de éxito.

NNTPconnect es lo mismo que NNTPremoteopen excepto que el host deseado se proporciona como parámetro host.

NNTPsendarticle escribe text en ToServer utilizando convenciones NNTP para la terminación de línea. El texto debe consistir en una o más líneas que terminen con una nueva línea. Si terminate es verdadero, la rutina también escribirá el marcador de terminación de datos NNTP en el flujo. Devuelve "-1" en caso de fallo, o 0 en caso de éxito.

NNTPsendpassword envía información de autenticación a un servidor NNTP encontrando la entrada apropiada en el archivo passwd.nntp. server contiene el nombre del host; el parámetro server en inn.conf se utilizará si server es NULL. FromServer y ToServer deberían ser "FILE" conectados al servidor. No se toma ninguna medida si el host especificado no figura en el archivo de contraseñas.

HASHES

HashMessageID devuelve el Message-ID hasheado usando MD5.

OTRAS FUNCIONES ÚTILES

inn_getfqdn devuelve el nombre de dominio completamente calificado del host local. inn_getfqdn primero intenta recuperarlo de la variable de entorno INN_HOSTNAME si está configurada, luego de las llamadas a gethostname(2) y getaddrinfo(3). La comprobación es muy simple; si el nombre de host recuperado contiene un punto, se asume que tiene el nombre de dominio completo. De lo contrario, si domain está configurado en inn.conf, se añade un punto seguido del valor de domain al nombre de host recuperado para calificar el nombre del host local. El valor devuelto apunta a memoria recién asignada que el llamador es responsable de liberar, o NULL en caso de error.

GetModeratorAddress devuelve la dirección de correo del moderador para el group especificado o NULL en caso de error. moderatormailer se utiliza como su dirección, si no hay un moderador que coincida. Consulte moderators(5) para obtener detalles sobre cómo se determina la dirección. GetModeratorAddress no realiza ninguna comprobación para ver si el grupo especificado está realmente moderado. El valor devuelto apunta a un espacio estático que se reutiliza en llamadas posteriores. Los parámetros FromServer y ToServer deben ser "FILE" conectados al servidor NNTP para entrada y salida, respectivamente. Si alguno de estos parámetros es NULL, se intenta obtener la lista de una copia local.

VARIOS

GetResourceUsage rellena los parámetros usertime y systime con el tiempo total de usuario y sistema utilizado por el proceso actual y cualquier hijo que haya generado. Si "HAVE_GETRUSAGE" en include/config.h está definido, obtiene los valores realizando una llamada al sistema getrusage(2); de lo contrario, llama a times(2). Devuelve "-1" en caso de fallo, o 0 en caso de éxito.

Radix32 convierte el número en value en una cadena radix-32 en el búfer apuntado por buff. El número se divide en trozos de cinco bits y cada trozo se convierte en un carácter usando el alfabeto "0..9a..v" para representar los números 0..32. Solo se utilizan los 32 bits más bajos de value, por lo que buff solo necesita apuntar a un búfer de ocho bytes (siete caracteres y el "\0" final).

ReadInFile lee el archivo llamado name en memoria asignada, añadiendo un byte de terminación "\0". Devuelve un puntero al espacio, o NULL en caso de error. Si Sbp no es NULL, se toma como la dirección de un lugar para almacenar los resultados de una llamada a stat(2).

ReadInDescriptor realiza la misma función que ReadInFile excepto que fd se refiere a un archivo ya abierto.

RESERVA DE DESCRIPTORES DE ARCHIVO

fdreserve permite reservar fdnum descriptores de archivo para uso futuro. En plataformas que tienen una limitación stdio, como las versiones de Solaris de 64 bits anteriores a la 11.0, todas las versiones de Solaris de 32 bits y las aplicaciones de 32 bits que se ejecutan en Solaris de 64 bits, los descriptores de archivo de bajo número pueden conservarse y reutilizarse para stdio. Sin este mecanismo, algunos archivos esenciales como el archivo de historial pueden no tener ningún descriptor de archivo disponible cuando se reabren después de un cierre para algunas operaciones, y stdio fallaría.

Todos estos descriptores de archivo leen "/dev/null", hasta que se llama a Fopen en ellos. Si fdnum es 0 o negativo, se cierran todos los descriptores de archivo reservados. De lo contrario, se reservan fdnum descriptores de archivo. Si esta función se llama de nuevo con un valor de fdnum mayor, reserva más descriptores de archivo; con un valor de fdnum menor, cierra los descriptores de archivo reservados supernumerarios. Devuelve verdadero cuando todos los descriptores de archivo se han reservado correctamente, y falso en caso contrario, en cuyo caso todos los descriptores de archivo reservados se cierran, incluso si algunos de ellos estaban previamente en uso.

Fopen abre el archivo name en el mode dado, utilizando el descriptor de archivo en la posición fdindex en los descriptores de archivo reservados. Si fdindex es menor que el número de descriptores de archivo reservados, Fopen utiliza el correspondiente. De lo contrario, simplemente llama a fopen(2) sin reutilizar un descriptor de archivo reservado. Devuelve un puntero a una estructura FILE, o NULL en caso de fallo.

Fclose cierra el descriptor de archivo utilizado para fp sin conservarlo, a menos que este descriptor de archivo fuera uno reservado, en cuyo caso se conserva (y lee "/dev/null"). Devuelve 0 en caso de éxito. Cualquier otro valor (como EOF) es un fallo.

LÍMITES DE DESCRIPTORES DE ARCHIVO

getfdlimit devuelve el límite de descriptores de archivo abiertos. Utiliza la función getrlimit(2) cuando está disponible. Si no, intenta sysconf(2), luego getdtablesize(2), luego ulimit(2), luego una posible constante codificada "NOFILE" en el encabezado del sistema sys/param.h, o luego recurre al mínimo garantizado por POSIX de 20.

setfdlimit establece el límite de descriptores de archivo abiertos al parámetro limit dado. Utiliza la función setrlimit(2) cuando está disponible. Devuelve 1 en caso de éxito, y "-1" en caso de fallo (cuando setrlimit(2) no está disponible o limit es mayor que select(2) puede manejar, comprobando contra "FD_SETSIZE").

isvalidfd devuelve verdadero si fd no es mayor que lo que el sistema soporta, y falso en caso contrario.

FLAGS DE DESCRIPTORES DE ARCHIVO

fdflag_close_exec puede hacer que un descriptor se cierre al ejecutar (close-on-exec) para que no se comparta con ningún proceso hijo. Si el flag es verdadero, el archivo se marca así; si es falso, se borra el modo close-on-exec. Devuelve falso en caso de fallo (o cuando la función no es compatible) o verdadero en caso de éxito.

fdflag_nonblocking habilita (si flag es verdadero) o deshabilita (si flag es falso) la E/S no bloqueante en el "socket_type" indicado (que puede ser un descriptor de archivo no socket en sistemas UNIX, pero se espera un "socket_type" en Windows). Devuelve falso en caso de fallo o verdadero en caso de éxito.
