NOMBRE

libcurl-env - variables de entorno que libcurl comprende

DESCRIPCIÓN

libcurl lee y comprende un conjunto de variables de entorno que, si se establecen, controlan y modifican comportamientos. Esta es la lista completa de variables para establecer y la descripción de lo que hacen. Tenga en cuenta también que curl, la herramienta de línea de comandos, admite un conjunto de variables de entorno adicionales independientemente de esta.

[scheme]_proxy
Cuando a libcurl se le da una URL para usar en una transferencia, primero extrae la parte del esquema de la URL y verifica si hay un proxy configurado para él en su variable de entorno correspondiente. Una URL como https://example.com hace que libcurl use la variable http_proxy, mientras que una URL como ftp://example.com usa la variable ftp_proxy.

Estas variables de proxy también se buscan en sus versiones en mayúsculas, excepto la de http_proxy que solo se usa en minúsculas. Tenga en cuenta también que algunos sistemas tienen un manejo insensible a mayúsculas y minúsculas de las variables de entorno y, en ese caso, HTTP_PROXY aún funciona.

Existe una excepción para los esquemas de URL WebSocket ws y wss, donde libcurl primero verifica ws_proxy o wss_proxy, pero si no están configurados, retrocede y prueba las versiones http y https si están configuradas.

ALL_PROXY
Esta es una configuración para establecer un proxy para todas las URLs, independientemente del esquema que se esté utilizando. Tenga en cuenta que las variables específicas del esquema la anulan si están configuradas.
CURL_SSL_BACKEND
Cuando libcurl está compilado para admitir múltiples backends SSL, selecciona un backend específico en el primer uso. Si el programa que usa libcurl no realiza ninguna selección, se utiliza la selección de esta variable. Establecer un nombre que no sea una alternativa integrada hace que libcurl mantenga la predeterminada.

Nombres de backend SSL (sin distinción entre mayúsculas y minúsculas): GnuTLS, mbedTLS, OpenSSL, Rustls, Schannel, wolfSSL

HOME
Cuando se utiliza la función netrc (CURLOPT_NETRC(3)), esta variable se verifica como la forma principal de encontrar el directorio "actual" en el que es probable que exista el archivo .netrc.
USERPROFILE
Cuando se utiliza la función netrc (CURLOPT_NETRC(3)), esta variable se verifica como la forma secundaria de encontrar el directorio "actual" (solo en Windows) en el que es probable que exista el archivo .netrc.
NETRC
El nombre de archivo utilizado como archivo netrc cuando CURLOPT_NETRC(3) se usa sin CURLOPT_NETRC_FILE(3). (Añadido en 8.16.0)
NO_PROXY
Esto tiene la misma funcionalidad que la opción CURLOPT_NOPROXY(3): proporciona a libcurl una lista separada por comas de patrones de nombre de host para los cuales libcurl no debe usar un proxy.
SSLKEYLOGFILE
Cuando se establece y libcurl se ejecuta con un backend SSL que admite esta función, libcurl guarda los secretos SSL en el nombre de archivo proporcionado. Utilizando esos secretos SSL, otras herramientas (como Wireshark) pueden descifrar la comunicación SSL y analizar/ver el tráfico.

Estos secretos y este archivo pueden ser sensibles. Se aconseja a los usuarios que tomen precauciones para que no sean robados o revelados inadvertidamente.

Variables de depuración

Las variables de depuración están destinadas a uso interno y se documentan en libcurl-env-dbg(3).
