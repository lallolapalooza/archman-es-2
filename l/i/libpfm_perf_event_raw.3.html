LIBPFM(3) Manual de Programador de Linux LIBPFM(3)

NOMBRE

libpfm_perf_event_raw - soporte para la sintaxis de eventos `raw` de perf_events

SINOPSIS

#include <perfmon/pfmlib.h>

Nombre de PMU: perf_raw
Descripción de PMU: Sintaxis de eventos `raw` de perf_events

DESCRIPCIÓN

La biblioteca soporta un modelo de PMU pseudo para permitir codificaciones `raw` de eventos de PMU para la interfaz del kernel perf_events de Linux.

Con esta PMU, es posible proporcionar la codificación hexadecimal `raw` de cualquier evento de hardware para cualquier modelo de PMU. La codificación `raw` se pasa tal cual al kernel. Todos los eventos se codifican como PERF_TYPE_RAW. Como tal, los eventos genéricos de perf_events, como ciclos e instrucciones, no pueden ser codificados por esta PMU.

La sintaxis es muy simple: rX. X es el valor hexadecimal de 64 bits para el evento. Puede incluir filtros de eventos en algunos modelos de PMU. El número hexadecimal se pasa sin el prefijo 0x, p. ej., r01c4.

Los atributos estándar de perf_events de la biblioteca son compatibles con este modelo de PMU. Se separan con dos puntos, como es habitual en la biblioteca.

MODIFICADORES

Los siguientes modificadores son compatibles con este modelo de PMU:

u
Medir a nivel de usuario, que incluye los niveles de privilegio 1, 2, 3. Esto corresponde a PFM_PLM3. Es un modificador booleano.
k
Medir a nivel de kernel, que incluye el nivel de privilegio 0. Esto corresponde a PFM_PLM0. Es un modificador booleano.
h
Medir a nivel de hipervisor. Esto corresponde a PFM_PLMH. Es un modificador booleano.
mg
Medir solo la ejecución del invitado. Es un modificador booleano.
mh
Medir solo la ejecución del anfitrión. Es un modificador booleano.
period
Especificar el valor del período de muestreo. El valor puede expresarse en decimal o hexadecimal. El valor es de 64 bits. Esta opción es mutuamente excluyente con freq. El período se expresa en la unidad del evento. No hay valor predeterminado.
freq
Especificar el valor de la frecuencia de muestreo. El valor puede expresarse en decimal o hexadecimal. El valor es de 64 bits. Esta opción es mutuamente excluyente con period. El valor se expresa en Hertz. Por ejemplo, freq=100, significa que el evento debe muestrearse 100 veces por segundo en promedio. No hay valor predeterminado.
excl
El evento asociado es el único evento medido en la PMU. Esto se aplica solo a eventos de hardware. Este atributo requiere privilegios de administrador. El valor predeterminado es desactivado.
precise
Habilita el modo de muestreo preciso. Esta opción solo es válida cuando se muestrea en eventos. La opción toma un argumento entero. Puede tener los siguientes valores: 1=habilitar muestreo preciso, 2=habilitar muestreo preciso y eliminar el `skid`, 3=habilitar muestreo preciso, eliminar el `skid` y el sesgo. No todos los eventos necesariamente soportan el modo preciso en todos los niveles, esto depende de la PMU subyacente. Eliminar el `skid` es una característica de mejor esfuerzo. Puede que no funcione para todas las muestras. Esta opción es mutuamente excluyente con hw_smpl. Esta opción implica el uso del mecanismo de muestreo asistido por hardware.
hw_smpl
Habilita el muestreo asistido por hardware. Es una opción booleana. Está desactivada por defecto. En algunos procesadores, es posible que el hardware registre muestras en un búfer y luego notifique al kernel cuando esté lleno. Dicha característica puede no estar disponible para todos los eventos. Usar un búfer de hardware no necesariamente elimina el `skid` y el sesgo, generalmente reduce la sobrecarga del muestreo basado en interrupciones al amortizar la interrupción en múltiples muestras. Esta opción es generalmente implícita con eventos de muestreo preciso.
cpu
Esta opción entera se usa con eventos de sistema, es decir, eventos adjuntos a una CPU en lugar de a un hilo. El valor designa la CPU a la que adjuntar el evento. Es responsabilidad del llamante de la biblioteca usar el campo `cpu` en el argumento de codificación del evento de la biblioteca para crear el evento. La biblioteca no realiza ninguna verificación sobre la validez del número de CPU. El valor predeterminado para este campo es -1.
pinned
Esta opción booleana se usa con eventos de sistema, es decir, eventos adjuntos a una CPU en lugar de a un hilo. Si está establecida, el evento se marca como `pinned` (fijado). Esto significa que debe permanecer en los contadores en todo momento, es decir, no puede ser multiplexado. Solo puede haber tantos eventos `pinned` como contadores, aunque la biblioteca no lo comprueba, el subsistema perf_event sí lo hace. El valor predeterminado para este campo es falso, es decir, el evento no está `pinned`.
