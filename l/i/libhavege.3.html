NOMBRE

libhavege, havege_create, havege_run, havege_rng, havege_destroy, havege_status, havege_status_dump, havege_version - Generador de números aleatorios de haveged

SINOPSIS

#include <havege/havege.h>
H_PARAMS params = {0};
h_status status;
char     status_buf[512];
if (NULL==havege_version(HAVEGE_PREP_VERSION)) exit(1);
H_PTR handle = havege_create(&params);
havege_status(handle, &status);
havege_run(handle);
rc = havege_rng(handle, handle->io_buf, handle->i_readSz/sizeof(H_UINT));
havege_status_dump(handle, H_SD_TOPIC_BUILD, status_buf, sizeof(status_buf));
havege_destroy(handle);

DESCRIPCIÓN

La biblioteca libhavege proporciona el generador de números aleatorios haveged y sus instalaciones asociadas de ajuste y prueba en un subpaquete de desarrollo. Se conservan todas las características de compilación condicional de haveged y están disponibles todas las opciones de haveged no relacionadas directamente con sus interfaces de demonio o de sistema de archivos. Esto significa que los mismos componentes de ajuste y prueba de haveged están presentes en la biblioteca con los controles equivalentes proporcionados por la línea de comandos de haveged.

MÉTODOS DE LA API

La biblioteca libhavege utiliza la técnica de manejador opaco para gestionar sus recursos requeridos. Los errores se devuelven en el miembro "error" del manejador. Se debe llamar al método havege_destroy() para desechar cualquier recurso reclamado por havege_create().

H_PTR havege_create(H_PARAMS *params);

Crea una ancla. La mayoría de los miembros de la entrada H_PARAMS a esta llamada corresponden estrechamente a las opciones de línea de comandos de haveged (ver haveged(8) para más detalles). El llamador debe verificar un valor de retorno no nulo con un valor de error de H_NOERR. Cualquier valor no nulo devuelto debe ser desechado mediante una llamada a havege_destroy() para liberar cualquier recurso. Valores de error posibles: H_NOERR, H_NOTESTSPEC, H_NOBUF, H_NOTESTMEM, H_NOINIT

void havege_destroy(H_PTR hptr);

Libera todos los recursos del ancla asignados. Si se utiliza la opción multinúcleo, este método debe llamarse desde un manejador de señales para evitar procesos zombis. Si lo llama el proceso que llamó a haveged_create(), hptr se liberará cuando todos los procesos hijos (si los hay) hayan terminado. Si lo llama un proceso hijo, H_EXIT se establecerá y todos los hijos serán despertados para salir.

int havege_rng(H_PTR hptr, H_UINT *buf, H_UINT sz);

Lee bytes aleatorios de un ancla activa. El RNG debe haber sido preparado previamente mediante una llamada a havege_run(). La lectura debe realizarse dentro del búfer asignado, hptr->io_buf. El rango especificado es el número de H_UINT a leer. Si se utiliza la opción multinúcleo, este búfer está mapeado en memoria entre los recolectores. Valores de error posibles: H_NOERR, H_NOTESRUN, H_NOPOST, H_NODONE, H_NORQST, H_NOCOMP, H_EXIT

int havege_run(H_PTR hptr);

Calienta el RNG y ejecuta las pruebas de inicio. La operación tuvo éxito si el miembro de error del manejador es H_NOERR. Un manejador fallido debe ser desechado mediante una llamada a havege_destroy(). Valores de error posibles: H_NOERR, H_NOCOLLECT, H_NOWALK, H_NOTESTMEM, H_NOTASK, H_NOTESTTOT, H_NOWAIT, H_NOTIMER, y cualquier error de havege_rng().

void havege_status(H_PTR hptr, H_STATUS hsts);

Rellena la estructura h_status con información de solo lectura recopilada de los componentes de compilación del paquete, ajuste en tiempo de ejecución y pruebas.

int havege_status_dump(H_PTR hptr, H_SD_TOPIC topic, char *buf, size_t len);

Llama a havege_status() y formatea presentaciones estándar del estado de havege en el búfer proporcionado. Los formatos estándar son:

H_SD_TOPIC_BUILD

ver: %s; arch: %s; vend: %s; build: (%s); collect: %dK

H_SD_TOPIC_TUNE

cpu: (%s); data: %dK (%s); inst: %dK (%s); idx: %d/%d; sz: %d/%d

H_SD_TOPIC_TEST

[tot tests(%s): A:%d/%d B: %d/%d;][continuous tests(%s): A:%d/%d B: %d/%d;][last entropy estimate %g]

H_SD_TOPIC_SUM

fills: %d, generated: %.4g %c bytes

const char *havege_version(const char *version);

Devuelve/comprueba la versión de preparación de la biblioteca. La versión de preparación es la versión del paquete utilizada para compilar la biblioteca. Un argumento nulo devuelve la versión de preparación incondicionalmente. Usar la definición de la cadena de preparación en havege.h como entrada devuelve la versión de preparación si el archivo de encabezado es compatible con la biblioteca, o NULL si no lo es. Diseñado para ser llamado antes de intentar cualquier inicialización.

NOTAS

Los tamaños de las cachés de instrucciones y datos del procesador de nivel 1 se utilizan para ajustar el algoritmo HAVEGE para una máxima sensibilidad. Si no se especifican estos tamaños, haveged intentará determinar los tamaños dinámicamente de sysfs de Linux y/o la instrucción cpuid con un respaldo a un valor predeterminado compilado si no hay información mejor disponible.

El RNG de haveged incluye una instalación de prueba en tiempo de ejecución basada en el conjunto de pruebas definido en la especificación AIS-31 de la Oficina Federal Alemana para la Seguridad de la Información (Bundesamt für Sicherheit in der Informationstechnik). El conjunto de pruebas consta de 11 pruebas estadísticas empaquetadas en dos conjuntos de pruebas ("A" y "B"). Las pruebas se pueden ejecutar en la inicialización (también conocida como prueba "tot"), o de forma continua para monitorear toda la salida. El fallo de un conjunto abortará la operación a menos que el comportamiento se omita explícitamente en las opciones de configuración de la prueba.

El procedimiento A contiene 6 procedimientos de prueba diseñados para garantizar un comportamiento estadísticamente discreto. La primera prueba, "test0", comprueba la disyunción de cadenas de 65k de seis bits. El resto del procedimiento consiste en 257 repeticiones de las pruebas FIPS140-1, "test1" a "test4", y una prueba de autocorrelação, "test5". El tamaño fijo de la entrada del Procedimiento A lo hace ideal para uso continuo, pero el procedimiento es lento y consume muchos recursos. En particular, test5 es varios órdenes de magnitud más lento que cualquier otra prueba individual de AIS. Como alternativa para aquellos que no pueden tolerar esta carga, se proporcionan variantes del procedimiento A, A<n>, que ejecutan todas las pruebas incluidas pero ejecutan test5 cada 2^n repeticiones. Incluso con esta adaptación, el procedimiento A es mucho más lento que el procedimiento B.

El procedimiento B contiene 5 pruebas, "test6a", "test6b", "test7a", "test7b" y "test8". Las primeras 4 pruebas verifican las frecuencias esperadas para muestras de 100.000 transiciones de bits de un paso, dos pasos, tres pasos y cuatro pasos. La última prueba proporciona una estimación empírica de entropía de la entrada. La entrada requerida para completar estas pruebas es variable, lo que resulta en una alineación de bits siempre cambiante que protege contra artefactos de almacenamiento en búfer.

Cada procedimiento de prueba requiere más de 1 MB de datos. La entrada de la prueba se gestiona mediante un índice de bits en el búfer de recolección. Un índice independiente gestiona dónde se toman las salidas enteras del mismo búfer. Se activa un relleno de búfer cuando el índice de salida indica que se ha extraído todos los datos del búfer. Las pruebas en línea se realizan después de que el búfer se ha rellenado, pero antes de que la actualización del índice de salida permita que la salida se reanude. Si alguna prueba en línea falla mientras se procesa el búfer, el búfer se rellenará y reprocesará hasta que se complete cualquier reintento y el búfer no contenga pruebas en línea fallidas o el procedimiento de prueba en línea haya fallado y el RNG se considere roto.

Se recomienda ejecutar ambos procedimientos de prueba AIS al arrancar para garantizar que el RNG esté inicializado correctamente. Si los recursos son escasos, omitir el procedimiento A ahorrará memoria y tiempo, con poco riesgo en circunstancias donde la salida se mezcla con otras fuentes en /dev/random u otros csprng. También se recomienda realizar pruebas continuas donde la penalización de rendimiento sea aceptable. Una evaluación reciente de los costos de rendimiento de las pruebas se muestra a continuación.

API METHODS

The following functions are exported by libhavege.

havege_create(H_PARAMS *params)
Allocates and initializes a havege state structure. If params is NULL, default parameters are used. Otherwise, the parameters specified in params are used. If allocation fails, NULL is returned and error is set to H_NOBUF or H_NOHANDLE. The error variable is part of the returned structure.
havege_destroy(H_PTR handle)
Frees the havege state structure pointed to by handle.
havege_version(const char *version)
Returns the library version string if version is NULL. If version is not NULL, it checks for compatibility with the specified version string. Returns a version string on success, or NULL on failure. Use HAVEGE_PREP_VERSION macro for library initialization check.
havege_run(H_PTR handle)
Initializes the random number generator. Returns 0 on success, otherwise returns a negative error code (see DIAGNOSTICS). A failed initialization will prevent further use of the RNG.
havege_rng(H_PTR handle, H_UINT *buf, int size)
Fills the buffer pointed to by buf with 'size' random H_UINTs. Returns the number of bytes written. The return value is size * sizeof(H_UINT). Returns a negative value on error. A retry is mandated on single individual test failures.
havege_status_dump(H_PTR handle, int topic, char *buf, int size)
Returns status information into buf. The amount of information written is returned. On error, a negative value is returned. Topic can be H_SD_TOPIC_TEST or H_SD_TOPIC_SUM.

NOTES

An ideal RNG has a 10e-4 chance of failing either test procedure. The strict retry policy of AIS-31 is designed to guarantee an ideal RNG will "almost never" fail a test procedure. A single retry is mandated only to recover from a previous attempt that experienced a single individual test failure. The haveged implementation logs all retries and terminates on test procedure failures unless the procedure has been flagged as advisory by the "w" argument (see --onlinetest in haveged(8) ). Little evidence of the retry mechanism is seen unless large data sets are processed. Procedure A is too slow to be practical in these situations, so procedure B has been the best studied. Retries are observed at the approximate rate of 0.7-0.8 failures/GB, mostly in the test7 multi-step transition checks.

The probability that procedureB will fail two times in a row (in which case the program will be terminated unless w option was specified) is 4e-7 which is expected to happen at an approximate rate of once per 3,000 TB. When producing large amounts of data in order of TBs it's recommended to use -w option to make sure that program will not prematurely terminate because of a failed retry and carefully examine the stderr output for any problems.

EXAMPLE

The following minimal program writes the contents of 16 collection buffers of random data to stdout with continuous testing.

#include <stdio.h>
#include <haveged/havege.h>
int main(void)
{
H_PTR havege_state;
H_PARAMS havege_parameters = {0};
int i, rc;
if (NULL==havege_version(HAVEGE_PREP_VERSION)) {
  fprintf(stderr, "Incompatible library %s\n", havege_version(NULL));
  return 1;
  }
havege_parameters.testSpec="ta8bcb";
havege_state = havege_create(&havege_parameters);
rc = havege_state==NULL? H_NOHANDLE : havege_state->error;
if (H_NOERR==rc) {
  if (0==havege_run(havege_state)) {
    H_UINT *buf = havege_state->io_buf;
    int size = havege_state->i_readSz /sizeof(H_UINT);
    char info[256];
    for(i=0;i<16;i++) {
        rc = havege_rng(havege_state, buf, size);
        if (rc != size) {
            fprintf(stderr, "RNG read failed %d\n", havege_state->error);
            break;
            }
        rc = fwrite(buf, 1, size*sizeof(H_UINT), stdout);
        if ( rc < size ) {
            fprintf(stderr, "Write failed\n");
            break;
            }
        }
    i = havege_status_dump(havege_state, H_SD_TOPIC_TEST, info, sizeof(info));
    info[i++] = '\n';
    havege_status_dump(havege_state, H_SD_TOPIC_SUM, info+i, sizeof(info)-i);
    fprintf(stderr, "%s\n", info);
    }
  else fprintf(stderr, "Initialize failed %d\n", havege_state->error);
  havege_destroy(havege_state);
  }
else fprintf(stderr, "Create failed %d\n", rc);
return rc;
}

Defaults are provided for all inputs to havege_create() as documented in havege.h. In this case for example, (16*4kb=65kb) will be written to stdout because the default size for i_readsz in 4kb.
