LIBARCHIVE(3) Manual de Funciones de Biblioteca LIBARCHIVE(3)

NOMBRE

libarchive — funciones para leer y escribir archivos en streaming

DESCRIPCIÓN GENERAL

La biblioteca libarchive proporciona una interfaz flexible para leer y escribir archivos en varios formatos como tar y cpio. libarchive también soporta leer y escribir archivos comprimidos usando varios filtros de compresión como gzip y bzip2. La biblioteca está orientada a flujos (streams); los lectores iteran serialmente a través del archivo, los escritores añaden cosas serialmente al archivo. En particular, tenga en cuenta que actualmente no hay soporte integrado para acceso aleatorio ni para modificación en el lugar.

Al leer un archivo, la biblioteca detecta automáticamente el formato y la compresión. La biblioteca actualmente tiene soporte de lectura para:

  • archivos tar de estilo antiguo,
  • la mayoría de las variantes del formato POSIX "ustar",
  • el formato "pax interchange" de POSIX,
  • archivos tar en formato GNU,
  • la mayoría de los formatos comunes de archivos cpio,
  • archivos 7-Zip,
  • archivos ar (incluyendo extensiones GNU/SysV y BSD),
  • archivos CAB de Microsoft,
  • imágenes de CD ISO9660 (incluyendo extensiones RockRidge y Joliet),
  • archivos LHA,
  • descripciones de árboles de archivos mtree,
  • archivos RAR y la mayoría de los archivos RAR5,
  • archivos WARC,
  • archivos XAR,
  • archivos Zip.
La biblioteca detecta automáticamente archivos comprimidos con compress(1), bzip2(1), grzip(1), gzip(1), lrzip(1), lz4(1), lzip(1), lzop(1), xz(1), o zstd(1) y los descomprime transparentemente. La descompresión de algunos formatos requiere utilidades externas de descompresión. De manera similar, puede detectar y decodificar archivos procesados con uuencode(1) o que tienen una cabecera rpm(1).

Al escribir un archivo, puede especificar la compresión a usar y el formato a utilizar. La biblioteca puede escribir

  • archivos "ustar" estándar POSIX,
  • archivos "pax interchange format" de POSIX,
  • archivos cpio,
  • archivos 7-Zip,
  • archivos ar,
  • dos variantes diferentes de archivos shar,
  • imágenes de CD ISO9660,
  • descripciones de árboles de archivos mtree,
  • archivos XAR,
  • archivos Zip.
El formato de intercambio pax es una extensión del formato de archivo tar que elimina esencialmente todas las limitaciones de los formatos tar históricos de una manera estándar que es soportada por implementaciones pax(1) compatibles con POSIX en muchos sistemas, así como varias implementaciones más nuevas de tar(1). Tenga en cuenta que el formato de escritura predeterminado suprimirá los atributos extendidos de pax para la mayoría de las entradas; solicitar explícitamente el formato pax habilitará esos atributos para todas las entradas.

Las APIs de lectura y escritura se acceden a través de las funciones archive_read_XXX() y archive_write_XXX(), respectivamente, y cualquiera de ellas puede usarse independientemente de la otra.

El resto de esta página del manual proporciona una descripción general de la operación de la biblioteca. Se puede encontrar información más detallada en las páginas del manual individuales para cada API o función de utilidad.

LECTURA DE UN ARCHIVO

Véase archive_read(3).

ESCRITURA DE UN ARCHIVO

Véase archive_write(3).

ESCRITURA DE ENTRADAS EN DISCO

La API archive_write_disk(3) permite escribir objetos archive_entry(3) en disco utilizando la misma API que usa archive_write(3). La API archive_write_disk(3) es utilizada internamente por archive_read_extract(); usarla directamente puede proporcionar un mayor control sobre cómo se escriben las entradas en disco. Esta API también hace posible compartir código entre operaciones de copia de archivo a archivo y extracción de archivo a disco.

LECTURA DE ENTRADAS DESDE DISCO

El soporte de archive_read_disk(3) para poblar objetos archive_entry(3) a partir de información en el sistema de archivos. Esto incluye la información accesible desde la llamada al sistema stat(2), así como ACLs, atributos extendidos y otros metadatos. La API archive_read_disk(3) también soporta la iteración sobre árboles de directorios, lo que permite leer directorios de archivos utilizando una API compatible con la API de archive_read(3).

DESCRIPCIÓN

Las descripciones detalladas de cada función se proporcionan en las páginas del manual correspondientes.

Todas las funciones utilizan un tipo de dato struct archive opaco que proporciona acceso a los contenidos del archivo.

La estructura struct archive_entry contiene una descripción completa de una única entrada de archivo. Utiliza una interfaz opaca que está completamente documentada en archive_entry(3).

Los usuarios familiarizados con formatos históricos deben tener en cuenta que las variantes más nuevas han eliminado la mayoría de las restricciones sobre la longitud de los campos textuales. Los clientes no deben asumir que los nombres de archivo, nombres de enlace, nombres de usuario o nombres de grupo tienen una longitud limitada. En particular, el formato de intercambio pax puede acomodar fácilmente nombres de ruta en conjuntos de caracteres arbitrarios que exceden PATH_MAX.

VALORES DE RETORNO

La mayoría de las funciones devuelven ARCHIVE_OK (cero) en caso de éxito, y un valor distinto de cero en caso de error. El valor de retorno indica la gravedad general del error, que va desde ARCHIVE_WARN, que indica un problema menor que probablemente debería informarse al usuario, hasta ARCHIVE_FATAL, que indica un problema grave que impedirá cualquier operación adicional en este archivo. En caso de error, la función archive_errno() se puede utilizar para recuperar un código de error numérico (véase errno(2)). La función archive_error_string() devuelve un mensaje de error textual adecuado para mostrar.

archive_read_new() y archive_write_new() devuelven punteros a un objeto struct archive asignado y inicializado.

archive_read_data() y archive_write_data() devuelven el recuento del número de bytes realmente leídos o escritos. Un valor de cero indica el final de los datos para esta entrada. Un valor negativo indica un error, en cuyo caso las funciones archive_errno() y archive_error_string() se pueden utilizar para obtener más información.

ENTORNO

Existen conversiones de conjuntos de caracteres dentro de las funciones de archive_entry(3) que se ven afectadas por la configuración regional (locale) seleccionada actualmente.

ERRORES

Algunos formatos de archivo admiten información que no está admitida por struct archive_entry. Dicha información no puede archivarse ni restaurarse completamente utilizando esta biblioteca. Esto incluye, por ejemplo, comentarios, conjuntos de caracteres o los pares clave/valor arbitrarios que pueden aparecer en los archivos en formato de intercambio pax.

Por el contrario, por supuesto, no toda la información que se puede almacenar en un struct archive_entry está admitida por todos los formatos. Por ejemplo, los formatos cpio no admiten marcas de tiempo en nanosegundos; los formatos tar antiguos no admiten números de dispositivo grandes.

El lector ISO9660 aún no puede leer todas las imágenes ISO9660; debería aprender a buscar.

El escritor AR requiere que el programa cliente utilice dos pasadas, a diferencia de todos los demás escritores de libarchive.
