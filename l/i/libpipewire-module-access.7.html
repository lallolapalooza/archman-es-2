NOMBRE

libpipewire-module-access - Acceso

DESCRIPCIÓN

El módulo de acceso realiza comprobaciones de acceso a los clientes.

La comprobación de acceso solo se realiza una vez por cliente; las comprobaciones posteriores devuelven la misma resolución.

Los permisos asignados a un cliente se configuran como argumentos para este módulo, véase más abajo. La gestión de permisos más allá del acceso irrestricto se delega a un agente externo, normalmente el gestor de sesiones.

Este módulo establece pipewire.access de la siguiente manera:

•
Si la opción del módulo access.legacy no está habilitada:

El valor definido para el socket en la opción del módulo access.socket, o "default" si no se define ningún valor.

•
Si access.legacy está habilitado, el valor es:
•
"flatpak": si el cliente es un cliente Flatpak
•
"unrestricted": si la propiedad del cliente pipewire.client.access está establecida en "allowed"
•
Valor de la propiedad del cliente pipewire.client.access, si está establecida
•
"unrestricted": de lo contrario

Si el valor resultante de pipewire.access es "unrestricted", este módulo otorgará al cliente todos los permisos para acceder a todos los recursos. De lo contrario, el cliente se verá obligado a esperar hasta que un actor externo, como el gestor de sesiones, actualice los permisos del cliente.

Para las conexiones de aplicaciones que se ejecutan dentro de Flatpak, y que no están mediadas por otros clientes (por ejemplo, portal o pipewire-pulse), la propiedad pipewire.access.portal.app_id se establece con el ID de la aplicación Flatpak, si se encuentra. Además, se establece pipewire.sec.flatpak en true.

NOMBRE DEL MÓDULO

libpipewire-module-access

OPCIONES DEL MÓDULO

Opciones específicas del comportamiento de este módulo

•
access.socket = { "nombre-socket" = "valor-acceso", ... }:

Permisos de acceso específicos del socket. Tiene el valor predeterminado { "CORENAME-manager": "unrestricted" } donde CORENAME es el nombre del núcleo de PipeWire, normalmente pipewire-0.

•
access.legacy = true: habilita el modo de acceso compatible con versiones anteriores. No se puede habilitar cuando se utilizan permisos basados en sockets.

Si no se especifica access.socket, el valor predeterminado es true, de lo contrario es false.

Advertencia

El modo heredado está obsoleto. El valor predeterminado está sujeto a cambios y el modo heredado puede eliminarse en futuras versiones de PipeWire.

OPCIONES GENERALES

Opciones con comportamiento conocido:

  • pipewire.access
  • pipewire.client.access

SOBREESCRITURA DE CONFIGURACIÓN

Se puede añadir una sección de configuración module.access.args para sobrescribir los argumentos del módulo.

# ~/.config/pipewire/pipewire.conf.d/my-access-args.conf
module.access.args = {
     access.socket = {
         pipewire-0 = "default",
         pipewire-0-manager = "unrestricted",
     }
}

EJEMPLO DE CONFIGURACIÓN

 context.modules = [
  {   name = libpipewire-module-access
      args = {
          # Usar socket separado para aplicaciones del gestor de sesiones,
          # y pipewire-0 para aplicaciones habituales.
          access.socket = {
              pipewire-0 = "default",
              pipewire-0-manager = "unrestricted",
          }
      }
  }
]
