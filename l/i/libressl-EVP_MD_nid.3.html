DESCRIPCIÓN

EVP_MD_nid() y EVP_MD_type() son idénticas y devuelven el identificador numérico (NID) de md. El NID es un valor interno que puede o no tener un IDENTIFICADOR DE OBJETO ASN.1 correspondiente; véase OBJ_nid2obj(3) para más detalles. Por ejemplo, EVP_MD_type(EVP_sha512()) devuelve NID_sha512. EVP_MD_CTX_type() devuelve el NID del algoritmo de resumen de mensajes que ctx está configurado para usar. Estas funciones se usan normalmente al configurar OIDs ASN.1.

EVP_MD_name() convierte el NID de md a su nombre corto con OBJ_nid2sn(3).

EVP_MD_size() devuelve el tamaño en bytes de los resúmenes de mensajes (hashes) producidos por md. EVP_MD_CTX_size() devuelve el tamaño de los hashes producidos por el algoritmo de resumen de mensajes que ctx está configurado para usar.

EVP_MD_block_size() devuelve el tamaño del bloque en bytes de md. EVP_MD_CTX_block_size() devuelve el tamaño del bloque del algoritmo de resumen de mensajes que ctx está configurado para usar.

EVP_MD_flags() devuelve las banderas del resumen de mensajes utilizadas por md. Tenga cuidado de no confundir estas banderas con las banderas no relacionadas del contexto del resumen de mensajes que se pueden inspeccionar con EVP_MD_CTX_test_flags(3). Las banderas disponibles son:

EVP_MD_FLAG_DIGALGID_NULL
Los parámetros en un DigestAlgorithmIdentifier se codifican utilizando un NULL ASN.1 explícito en lugar de omitirlos. Este es el valor predeterminado, lo que significa que entra en vigor para los objetos EVP_MD que no tienen establecida EVP_MD_FLAG_DIGALGID_ABSENT.
EVP_MD_FLAG_DIGALGID_ABSENT
Los parámetros en un DigestAlgorithmIdentifier se omiten de la codificación ASN.1. Esto es utilizado por los objetos EVP_MD documentados en la página del manual EVP_sha3_224(3) y por los objetos devueltos desde EVP_sha512(3), EVP_sha512_256(3), EVP_sha512_224(3), EVP_sha384(3), EVP_sha256(3), EVP_sha224(3), EVP_sha1(3), y EVP_sm3(3).
EVP_MD_FLAG_DIGALGID_CUSTOM
Esta bandera está reservada para objetos EVP_MD definidos por el usuario que admiten el manejo personalizado de DigestAlgorithmIdentifier a través de EVP_MD_CTX_ctrl(3), pero en realidad, es ignorada tanto por LibreSSL como por OpenSSL y dicho comportamiento definido por el usuario no está soportado por las bibliotecas.
EVP_MD_FLAG_FIPS
Marca el método de resumen como adecuado para el modo FIPS. Esta bandera es ignorada tanto por LibreSSL como por OpenSSL.
EVP_MD_FLAG_ONESHOT
Tiene la intención de indicar que el método de resumen solo puede manejar un bloque de entrada, pero en realidad, esta bandera es ignorada tanto por LibreSSL como por OpenSSL.

EVP_MD_pkey_type() devuelve el NID del algoritmo de firma de clave pública asociado con este resumen. Por ejemplo, EVP_sha512(3) está asociado con RSA, por lo que esto devuelve NID_sha512WithRSAEncryption. Dado que los resúmenes y los algoritmos de firma ya no están vinculados, esta función solo se conserva por motivos de compatibilidad.

EVP_MD_nid(), EVP_MD_CTX_type(), EVP_MD_name(), EVP_MD_CTX_size(), y EVP_MD_CTX_block_size() están implementadas como macros.

VALORES DE RETORNO

EVP_MD_nid(), EVP_MD_type(), EVP_MD_CTX_type(), y EVP_MD_pkey_type() devuelven el NID del IDENTIFICADOR DE OBJETO correspondiente o NID_undef si no existe ninguno.

EVP_MD_name() devuelve un puntero a una cadena que pertenece a un objeto interno de la biblioteca o NULL si el NID no está integrado en la biblioteca ni se ha añadido a la tabla de objetos global mediante una de las funciones documentadas en la página del manual OBJ_create(3), o si el objeto no contiene un nombre corto.

EVP_MD_size(), EVP_MD_CTX_size(), EVP_MD_block_size(), y EVP_MD_CTX_block_size() devuelven el tamaño del resumen o del bloque en bytes.

VER TAMBIÉN

functions to get information about Message Digest (EVP_MD) objects and contexts

DESCRIPTION

The EVP_MD_nid() function returns the NID (numeric identifier) for the message digest algorithm specified by md. If no NID is associated with md, 0 is returned.

The EVP_MD_name() function returns the short name of the message digest algorithm specified by md. The returned string is owned by the library and should not be freed.

The EVP_MD_type() function returns the EVP_CIPHER associated with the message digest md. This is typically used for algorithms like SM3 which have a corresponding cipher definition.

The EVP_MD_pkey_type() function returns the NID of the public key algorithm that can be used to sign digests computed using the algorithm md.

The EVP_MD_size() function returns the digest size in bytes of the message digest algorithm specified by md. For example, this would return 20 for SHA1.

The EVP_MD_block_size() function returns the block size in bytes of the message digest algorithm specified by md. For example, this would return 64 for SHA1.

The EVP_MD_flags() function returns flags associated with the message digest algorithm specified by md. See EVP_get_digest(3) for details on the flags.

The EVP_MD_CTX_size(), EVP_MD_CTX_block_size(), and EVP_MD_CTX_type() functions return the size, block size, and type NID, respectively, of the message digest algorithm associated with the context ctx.

RETURN VALUES

EVP_MD_nid(), EVP_MD_size(), EVP_MD_block_size(), EVP_MD_CTX_size(), EVP_MD_CTX_block_size(), and EVP_MD_CTX_type() return the relevant integer value. Returns 0 or -1 in case of an error, depending on the function.

EVP_MD_name() returns the name of the digest.

EVP_MD_type() returns the associated EVP_CIPHER or NULL on error.

EVP_MD_pkey_type() returns the NID of the public key algorithm or 0 if none is associated.

EVP_MD_flags() returns the flags.

HISTORY

EVP_MD_size() first appeared in SSLeay 0.6.6, EVP_MD_CTX_size() and EVP_MD_CTX_type() in SSLeay 0.8.0, EVP_MD_type() and EVP_MD_pkey_type() in SSLeay 0.8.1, and EVP_MD_block_size() and EVP_MD_CTX_block_size() in SSLeay 0.9.0. All these functions have been available since OpenBSD 2.4.

EVP_MD_nid() and EVP_MD_name() first appeared in OpenSSL 0.9.7 and have been available since OpenBSD 3.2.

EVP_MD_flags() first appeared in OpenSSL 1.0.0 and has been available since OpenBSD 4.9.

CAVEATS

The behaviour of the functions taking an EVP_MD_CTX argument is undefined if they are called on a ctx that has no message digest configured yet, for example one freshly returned from EVP_MD_CTX_new(3). In that case, the program may for example be terminated by a NULL pointer access.
