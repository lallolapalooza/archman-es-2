DESCRIPCIÓN

Esta biblioteca contiene una implementación rápida del algoritmo de cifrado DES.

Hay dos fases para el uso del cifrado DES. La primera es la generación de un DES_key_schedule a partir de una clave, y la segunda es el cifrado real. Una clave DES es de tipo DES_cblock. Este tipo consta de 8 bytes con paridad impar. El bit menos significativo de cada byte es el bit de paridad. El esquema de claves es una forma expandida de la clave; se utiliza para acelerar el proceso de cifrado.

DES_random_key() genera una clave aleatoria en paridad impar.

Antes de que una clave DES pueda ser utilizada, debe ser convertida al DES_key_schedule dependiente de la arquitectura a través de la función DES_set_key_checked() o DES_set_key_unchecked().

DES_set_key_checked() comprobará que la clave pasada sea de paridad impar y no sea una clave débil o semi-débil. Si la paridad es incorrecta, se devolverá -1. Si la clave es una clave débil, se devolverá -2. Si se devuelve un error, el esquema de claves no se genera.

DES_set_key() funciona como DES_set_key_checked() si el flag DES_check_key no es cero, de lo contrario funciona como DES_set_key_unchecked(). Estas funciones están disponibles por compatibilidad; se recomienda utilizar una función que no dependa de una variable global.

DES_set_odd_parity() establece la paridad de la key pasada a impar.

Las siguientes rutinas operan principalmente sobre un flujo de entrada y salida de DES_cblocks.

DES_ecb_encrypt() es la rutina básica de cifrado DES que cifra o descifra un único DES_cblock de 8 bytes en modo de libro de códigos electrónico (ECB). Siempre transforma los datos de entrada, apuntados por input, en los datos de salida, apuntados por el argumento output. Si el argumento enc no es cero (DES_ENCRYPT), la input (texto plano) se cifra en la output (texto cifrado) utilizando el esquema de claves especificado por el argumento schedule, previamente establecido a través de DES_set_key(). Si enc es cero (DES_DECRYPT), la input (ahora texto cifrado) se descifra en la output (ahora texto plano). La entrada y la salida pueden solaparse. DES_ecb_encrypt() no devuelve ningún valor.

DES_ecb3_encrypt() cifra/descifra el bloque de input utilizando el Triple-DES de tres claves en modo ECB. Esto implica cifrar la entrada con ks1, descifrar con el esquema de claves ks2, y luego cifrar con ks3. Esta rutina reduce en gran medida las probabilidades de romper el DES por fuerza bruta y tiene la ventaja de que si ks1, ks2 y ks3 son iguales, es equivalente a un simple cifrado utilizando ECB y ks1 como clave.

La macro DES_ecb2_encrypt() se proporciona para realizar el Triple-DES de dos claves utilizando ks1 para el cifrado final.

DES_ncbc_encrypt() cifra/descifra utilizando el modo de encadenamiento de bloques de cifrado (CBC) de DES. Si el argumento enc no es cero, la rutina cifra en cadena de bloques el texto plano apuntado por el argumento input en el texto cifrado apuntado por el argumento output, utilizando el esquema de claves proporcionado por el argumento schedule, y el vector de inicialización proporcionado por el argumento ivec. Si el argumento length no es un múltiplo integral de ocho bytes, el último bloque se copia a un área temporal y se rellena con ceros. La salida es siempre un múltiplo integral de ocho bytes.

DES_xcbc_encrypt() es el modo DES de RSA (modo DESX). Utiliza inw y outw para "blanquear" el cifrado. inw y outw son secretos (a diferencia del IV) y, como tales, forman parte de la clave. Por lo tanto, la clave es de unos 24 bytes. Esto es mucho mejor que el DES CBC.

DES_ede3_cbc_encrypt() implementa el cifrado triple DES CBC externo con tres claves. Esto significa que cada operación DES dentro del modo CBC es "C=E(ks3,D(ks2,E(ks1,M)))". Este modo es utilizado por SSL.

La macro DES_ede2_cbc_encrypt() implementa el Triple-DES de dos claves reutilizando ks1 para el cifrado final. "C=E(ks1,D(ks2,E(ks1,M)))". Esta forma de Triple-DES es utilizada por la biblioteca RSAREF.

DES_pcbc_encrypt() cifra/descifra utilizando el modo de encadenamiento de bloques de cifrado propagante utilizado por Kerberos v4. Sus parámetros son los mismos que DES_ncbc_encrypt().

DES_cfb_encrypt() cifra/descifra utilizando el modo de retroalimentación de cifrado. Este método toma un array de caracteres como entrada y produce un array de caracteres como salida. No requiere ningún relleno a grupos de 8 caracteres. Nota: la variable ivec se modifica y el nuevo valor modificado debe pasarse a la siguiente llamada a esta función. Dado que esta función ejecuta un cifrado DES ECB completo por cada numbits, solo se sugiere su uso cuando se envían un pequeño número de caracteres.

DES_cfb64_encrypt() implementa el modo CFB de DES con retroalimentación de 64 bits. ¿Por qué es útil, preguntas? Porque esta rutina te permitirá cifrar un número arbitrario de bytes, sin relleno de 8 bytes. Cada llamada a esta rutina cifrará los bytes de entrada a salida y luego actualizará ivec y num. num contiene "qué tan lejos" estamos a través de ivec. Si esto no tiene mucho sentido, lee más sobre el modo CFB de DES.

La función DES_ede3_cfb64_encrypt() y la macro DES_ede2_cfb64_encrypt() son iguales a DES_cfb64_encrypt() excepto que se utiliza Triple-DES.

DES_ofb_encrypt() cifra utilizando el modo de retroalimentación de salida. Este método toma un array de caracteres como entrada y produce un array de caracteres como salida. No requiere ningún relleno a grupos de 8 caracteres. Nota: la variable ivec se modifica y el nuevo valor modificado debe pasarse a la siguiente llamada a esta función. Dado que esta función ejecuta un cifrado DES ECB completo por cada numbits, solo se sugiere su uso cuando se envían un pequeño número de caracteres.

DES_ofb64_encrypt() es igual a DES_cfb64_encrypt() utilizando el modo de Retroalimentación de Salida.

La función DES_ede3_ofb64_encrypt() y la macro DES_ede2_ofb64_encrypt() son iguales a DES_ofb64_encrypt(), utilizando Triple-DES.

Las siguientes funciones se incluyen en la biblioteca DES por compatibilidad con la biblioteca Kerberos de MIT.

DES_cbc_cksum() produce una suma de verificación de 8 bytes basada en el flujo de entrada (mediante cifrado CBC). Los últimos 4 bytes de la suma de verificación se devuelven y los 8 bytes completos se colocan en output. Esta función es utilizada por Kerberos v4. Otras aplicaciones deberían utilizar EVP_DigestInit(3) en su lugar.

DES_quad_cksum() proporciona una suma de verificación de 64 bits utilizada por el protocolo Kerberos.

DES_string_to_key() convierte una cadena de texto ASCII en una clave DES. La clave se genera mediante el algoritmo de un solo paso utilizado por el comando crypt(1). La clave resultante es de paridad impar.

DES_string_to_2keys() convierte una cadena de texto ASCII en dos claves DES de paridad impar. Se utiliza principalmente para el cifrado Triple-DES.

DES_fcrypt() es una versión de crypt(3) que utiliza DES en lugar del algoritmo DES tradicional. Su uso es el mismo que el de crypt(3), excepto que requiere un esquema de claves DES de 16 bytes.

DES_crypt() es idéntica a DES_fcrypt() excepto que utiliza el algoritmo DES tradicional como algoritmo de cifrado subyacente. La función DES_crypt() es solo para compatibilidad y se debe utilizar DES_fcrypt() en su lugar.

NAME

DES_quad_cksum, DES_cbc_cksum, DES_fcrypt, DES_crypt - DES-based checksum and password functions

SYNOPSIS

#include <openssl/des.h>

  • unsigned long DES_quad_cksum(const unsigned char *input, unsigned char *output, unsigned long input_len, unsigned int out_count, DES_cblock *seed);
  • unsigned long DES_cbc_cksum(const unsigned char *input, unsigned char *output, unsigned long input_len, DES_cblock *seed);
  • char *DES_fcrypt(const char *key, const char *salt, char *ret);
  • char *DES_crypt(const char *key, const char *salt);

DESCRIPTION

The following functions implement DES-based checksum and password hashing algorithms. Note that DES itself is now considered insecure and should not be used for new applications.

DES_quad_cksum() is a Kerberos v4 function. It returns a 4-byte checksum from the input bytes. The algorithm can be iterated over the input, depending on out_count, 1, 2, 3 or 4 times. If output is non-NULL, the 8 bytes generated by each pass are written into output.

The following are DES-based transformations:

DES_fcrypt() is a fast version of the Unix crypt(3) function. The salt must be two ASCII characters. This version is different from the normal crypt in that the third parameter is the buffer that the return value is written into. It needs to be at least 14 bytes long. The fourteenth byte is set to NUL. This version takes only a small amount of space relative to other fast crypt implementations. It is thread safe, unlike the normal crypt.

DES_crypt() is a faster replacement for the normal system crypt(3). This function calls DES_fcrypt() with a static array passed as the third parameter. This emulates the normal non-thread safe semantics of crypt(3).

RETURN VALUES

DES_set_key(), DES_key_sched(), and DES_set_key_checked() return 0 on success or a negative value on error.

DES_is_weak_key() returns 1 if the passed key is a weak key or 0 if it is ok.

DES_cbc_cksum() and DES_quad_cksum() return a 4-byte integer representing the last 4 bytes of the checksum of the input.

DES_fcrypt() returns a pointer to the caller-provided buffer ret, and DES_crypt() returns a pointer to a static buffer. Both are allowed to return NULL to indicate failure, but currently, they cannot fail.

CAVEATS

Single-key DES is insecure due to its short key size. ECB mode is not suitable for most applications.

BUGS

DES_cbc_encrypt does not modify ivec; use DES_ncbc_encrypt() instead.

DES_cfb_encrypt() and DES_ofb_encrypt() operates on input of 8 bits. What this means is that if you set numbits to 12, and length to 2, the first 12 bits will come from the 1st input byte and the low half of the second input byte. The second 12 bits will have the low 8 bits taken from the 3rd input byte and the top 4 bits taken from the 4th input byte. The same holds for output. This function has been implemented this way because most people will be using a multiple of 8 and because once you get into pulling input bytes apart things get ugly!

DES_string_to_key() is available for backward compatibility with the MIT library. New applications should use a cryptographic hash function. The same applies for DES_string_to_2key().
