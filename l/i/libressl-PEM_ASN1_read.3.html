libressl-PEM_ASN1_read(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

PEM_ASN1_READ(3) Manual de funciones de biblioteca PEM_ASN1_READ(3)

NOMBRE

d2i_of_void, PEM_ASN1_read, PEM_ASN1_read_bio — Decodifica un valor ASN.1 arbitrario de PEM y DER

SINOPSIS

biblioteca “libcrypto”
#include <openssl/pem.h>

typedef void *
d2i_of_void(void **val_out, const unsigned char **der_in, long length);

void *
PEM_ASN1_read(d2i_of_void *d2i, const char *name, FILE *in_fp, void **val_out, pem_password_cb *cb, void *u);

void *
PEM_ASN1_read_bio(d2i_of_void *d2i, const char *name, BIO *in_bp, void **val_out, pem_password_cb *cb, void *u);

DESCRIPCIÓN

Estas funciones leen un objeto de in_fp o in_bp y realizan la decodificación tanto en PEM como en DER. Son necesarias cuando las funciones de decodificación más específicas, como las documentadas en PEM_read_bio_PrivateKey(3) y PEM_read_SSL_SESSION(3) son inadecuadas para el tipo name.

Para la decodificación PEM, PEM_bytes_read_bio(3) se llama internamente. En consecuencia, se devuelve el primer objeto de tipo name y se descartan los objetos precedentes de otros tipos. Si es necesario, los datos se descifran, utilizando cb y/o u si no son NULL, como se describe en la página del manual de pem_password_cb(3).

Para la decodificación DER posterior, pase una función de devolución de llamada d2i que sea adecuada para el tipo name, devolviendo típicamente un puntero de un tipo más específico que void *. Por ejemplo, d2i_ASN1_TYPE(3) siempre puede utilizarse y su página del manual describe el comportamiento requerido de la función de devolución de llamada a pasar. Normalmente, pasar una función más específica es más útil; las funciones candidatas se pueden encontrar con ‘man -k Nm~^d2i_’.

Para el argumento name, se pueden utilizar las constantes de cadena PEM_STRING_* definidas en <openssl/pem.h>.

El argumento val_out es inútil y sus numerosos peligros se describen en detalle en la página del manual de d2i_ASN1_TYPE(3). Para reducir el riesgo de errores, siempre se recomienda pasar NULL.

VALORES DE RETORNO

Estas funciones devuelven un puntero al objeto decodificado o NULL si ocurre un error. Fallan si PEM_bytes_read_bio(3) falla, por ejemplo, debido a sintaxis inválida en la entrada, cifrado desconocido o una contraseña inválida introducida por el usuario. También fallan si d2i devuelve NULL, por ejemplo, debido a errores de decodificación DER.

PEM_ASN1_read() también puede fallar si la memoria se agota.

EJEMPLOS

El uso típico de PEM_ASN1_read() se demuestra mediante la implementación de la función más específica para decodificar PEM y DER un certificado X.509:

X509 *
PEM_read_X509(FILE *fp, X509 **val_out, pem_password_cb *cb, void *u)
{
	return PEM_ASN1_read((d2i_of_void *)d2i_X509, PEM_STRING_X509,
	    fp, (void **)val_out, cb, u);
}

ERRORES

Los diagnósticos que se pueden recuperar con ERR_get_error(3), ERR_GET_REASON(3), y ERR_reason_error_string(3) incluyen:

ERR_R_BUF_LIB "BUF lib"
PEM_ASN1_read() falló al configurar un BIO temporal, por ejemplo, porque la memoria se agotó.
ERR_R_ASN1_LIB "ASN1 lib"
d2i devolvió NULL, por ejemplo, debido a un error de sintaxis DER.

Pueden surgir tipos de errores adicionales de PEM_bytes_read_bio(3).
