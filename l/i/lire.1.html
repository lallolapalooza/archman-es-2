LIRE.IN(1) Documentación de Lire de LogReport LIRE.IN(1)

NOMBRE

lire - Interfaz de Lire

SINOPSIS

lire

DESCRIPCIÓN

lire tiene dos propósitos: configura Lire y permite la generación automática de informes.

lire es una aplicación dirigida por menús. Debes usar la tecla TAB para navegar por los diversos elementos de la interfaz. Las teclas de flecha deben usarse para navegar por los menús. La barra de menú principal se puede acceder en todo momento usando F10. El ratón puede estar disponible dependiendo de tu terminal y de la implementación del módulo Curses::UI de tu sistema.

configurando Lire

El elemento del menú 'Preferencias' en el menú 'Lire' te dará acceso a todas las configuraciones de Lire. El comando lire edita o crea ~/.lire/config.xml.

generación automática de informes

lire permite la generación automática de informes creando y gestionando almacenes DLF. Un almacén DLF es un repositorio de registros. En un almacén DLF, puedes configurar trabajos de Importación (ImportJobs) y trabajos de Informe (ReportJobs) que se ejecutarán regularmente. La configuración del almacén se guarda en store/config.xml.

Un ImportJob es un trabajo que importará datos de registro en el almacén DLF. Estos datos se utilizarán más tarde para generar los informes.

ReportJobs deben usarse para generar informes periódicos. Los informes se generan a partir de los flujos DLF disponibles en tu almacén DLF. El informe se puede generar para diferentes programaciones. Lire admite 5 programaciones diferentes: horaria, diaria, semanal, mensual y anual.

Necesitarás seleccionar el archivo de configuración del informe a utilizar para cada programación. Los valores predeterminados se encuentran en <sysconfdir>/lire/, que deberías usar como plantillas que necesitas personalizar según tu propósito.

Los informes se pueden generar a partir de los datos de registro importados en la base de datos o a partir de informes diarios generados previamente. Esto es útil cuando tienes muchos datos de registro y no quieres mantener todos los datos sin procesar disponibles. La fuente se selecciona automáticamente según la disponibilidad de los datos. Sin embargo, debes tener en cuenta que solo los informes 'diarios' se consideran como fuente de datos para otros informes (lo que solo es posible con programaciones semanales o más largas).

Cuando se ejecuta, un ReportSchedule solo generará el informe y lo guardará en el almacén DLF. Si deseas obtener una copia formateada del informe, deberás configurar uno o más OutputJobs.

Se admiten dos tipos de OutputJob:

1- El informe se puede enviar por correo electrónico a una o más direcciones;

2- o se puede guardar en un archivo en el disco. Una configuración útil es generar informes HTML en un directorio publicado en un sitio web. Al usar un OutputJob de "archivo", probablemente querrás usar la expansión strftime(3) para que el nombre del archivo sea diferente cada vez que se genere el informe. Las expansiones más comunes son:

%Y - año de cuatro dígitos (2000);
%m - número de mes de dos dígitos (01 para enero);
%V - número de semana ISO;
%d - número del día del mes;
%H - hora del día (01-23).

Además, a diferencia del comando lr_log2report, los informes HTML se generan en un directorio (no como un archivo tar).

Para ejecutar los trabajos programados, deberás configurar trabajos cron. Usa lr_cron(1) para procesar los trabajos configurados en un almacén.
