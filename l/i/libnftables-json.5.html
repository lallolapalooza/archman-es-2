NOMBRE

libnftables-json - Esquema JSON soportado por libnftables

SINOPSIS

{ "nftables": [ OBJETOS ] }

OBJETOS := OBJETOS_LISTA | OBJETOS_CMD

OBJETOS_LISTA := OBJETO_LISTA [ , OBJETOS_LISTA ]

OBJETOS_CMD := OBJETO_CMD [ , OBJETOS_CMD ]

OBJETO_CMD := { CMD: OBJETO_LISTA } | OBJETO_METAINFO

CMD := "add" | "replace" | "create" | "insert" | "delete" | "list" | "reset" | "flush" | "rename"

OBJETO_LISTA := TABLA | CADENA | REGLA | SET | MAPA | ELEMENTO | TABLA_DE_FLUJO | CONTADOR | CUOTA | ASISTENTE_CT | LIMITE | OBJETO_METAINFO | TIEMPO_CT | ESPERA_CT

DESCRIPCIÓN

libnftables soporta entrada y salida con formato JSON. Esto se implementa como un frontend alternativo al analizador de sintaxis CLI estándar, por lo tanto, el comportamiento básico es idéntico y, para (casi) cualquier operación disponible en sintaxis estándar, debería haber un equivalente en JSON.

La entrada JSON puede proporcionarse en una cadena única como parámetro a nft_run_cmd_from_buffer() o en un archivo identificado por el parámetro filename de la función nft_run_cmd_from_filename().

La salida JSON debe habilitarse a través de la función nft_ctx_output_set_json(), que cambia la salida estándar de la biblioteca al formato JSON. La salida de errores no se ve afectada.

ESTRUCTURA GLOBAL

En general, cualquier entrada o salida JSON está encerrada en un objeto con una única propiedad llamada nftables. Su valor es una matriz que contiene comandos (para entrada) o elementos de conjunto de reglas (para salida).

Un comando es un objeto con una única propiedad cuyo nombre identifica el comando. Su valor es un elemento del conjunto de reglas, básicamente idéntico a los elementos de salida, aparte de ciertas propiedades que pueden interpretarse de manera diferente o que son requeridas cuando la salida generalmente las omite.

OBJETO METAINFO

En la salida, el primer objeto en una matriz nftables es uno especial que contiene información de la biblioteca. Su contenido es el siguiente:

{ "metainfo": {
        "version": CADENA,
        "release_name": CADENA,
        "json_schema_version": NÚMERO
}}

Los valores de las propiedades version y release_name son iguales a la versión del paquete y al nombre de la versión tal como los imprime nft -v. El valor de la propiedad json_schema_version es un entero que indica la versión del esquema.

Si se proporciona en la entrada de la biblioteca, el analizador verificará que el valor de json_schema_version no exceda el codificado internamente (para asegurarse de que el esquema dado se entienda completamente). En el futuro, un número menor que el interno puede activar el modo de compatibilidad para analizar la entrada JSON obsoleta e incompatible.

OBJETOS COMANDO

La estructura acepta una cantidad arbitraria de comandos que se interpretan en el orden de aparición. Por ejemplo, la siguiente entrada de sintaxis estándar:

flush ruleset
add table inet mytable
add chain inet mytable mychain
add rule inet mytable mychain tcp dport 22 accept

se traduce a JSON de la siguiente manera:

{ "nftables": [
        { "flush": { "ruleset": null }},
        { "add": { "table": {
                        "family": "inet",
                        "name": "mytable"
        }}},
        { "add": { "chain": {
                        "family": "inet",
                        "table": "mytable",
                        "name": "mychain"
        }}},
        { "add": { "rule": {
                        "family": "inet",
                        "table": "mytable",
                        "chain": "mychain",
                        "expr": [
                                { "match": {
                                        "op": "==",
                                        "left": { "payload": {
                                                        "protocol": "tcp",
                                                        "field": "dport"
                                        }},
                                        "right": 22
                                }},
                                { "accept": null }
                        ]
        }}}
]}

AÑADIR

{ "add": OBJETO_AÑADIR }
OBJETO_AÑADIR := TABLA | CADENA | REGLA | SET | MAPA | ELEMENTO |
                TABLA_DE_FLUJO | CONTADOR | CUOTA | ASISTENTE_CT | LIMITE |
                TIEMPO_CT | ESPERA_CT

Añade un nuevo elemento del conjunto de reglas al kernel.

REEMPLAZAR

{ "replace": REGLA }

Reemplaza una regla. En REGLA, la propiedad handle es obligatoria e identifica la regla a reemplazar.

CREAR

{ "create": OBJETO_AÑADIR }

Idéntico al comando add, pero devuelve un error si el objeto ya existe.

INSERTAR

{ "insert": REGLA }

Este comando es idéntico a add para reglas, pero en lugar de añadir la regla al final de la cadena por defecto, la inserta en la primera posición. Si se proporciona una propiedad handle o index, la regla se inserta antes de la regla identificada por esas propiedades.

BORRAR

{ "delete": OBJETO_AÑADIR }

Elimina un objeto del conjunto de reglas. Generalmente solo se necesita el número mínimo de propiedades requeridas para identificar únicamente un objeto en OBJETO_AÑADIR. Para la mayoría de los elementos del conjunto de reglas, esto es family y table más ya sea handle o name (excepto las reglas ya que no tienen nombre).

LISTAR

{ "list": OBJETO_LISTA }
OBJETO_LISTA := TABLA | TABLAS | CADENA | CADENAS | SET | SETS |
                 MAPA | MAPAS | CONTADOR | CONTADORES | CUOTA | CUOTAS |
                 ASISTENTE_CT | ASISTENTES_CT | LIMITE | LIMITES | REGLAS |
                 METRO | METROS | TABLA_DE_FLUJO | TABLAS_DE_FLUJO |
                 TIEMPO_CT | ESPERA_CT

Lista elementos del conjunto de reglas. Las formas plurales se utilizan para listar todos los objetos de ese tipo, opcionalmente filtrados por family y para algunos, también por table.

REINICIAR

{ "reset": OBJETO_REINICIO }
OBJETO_REINICIO := CONTADOR | CONTADORES | CUOTA | CUOTAS | REGLA | REGLAS | SET | MAPA | ELEMENTO

Reinicia el estado en objetos adecuados, es decir, pone a cero su contador interno.

VACIAR

{ "flush": OBJETO_VACIADO }
OBJETO_VACIADO := TABLA | CADENA | SET | MAPA | METRO | REGLA

Elimina todos los elementos de un objeto. Esto puede ser una tabla, una cadena, un conjunto, un mapa o un medidor. En el caso de una tabla, se eliminarán todas las cadenas y sus contenidos. En el caso de una cadena, se eliminarán todas sus reglas. En el caso de un conjunto, se eliminarán todos sus elementos. En el caso de un mapa, se eliminarán todas sus entradas. En el caso de un medidor, se reiniciarán sus estadísticas.

RENOMBRAR

{ "rename": RENOMBRAR_OBJETO }
RENOMBRAR_OBJETO := TABLA | CADENA | SET | MAPA

Cambia el nombre de un objeto existente. La estructura RENOMBRAR_OBJETO debe contener las propiedades que identifican el objeto a renombrar, además de la propiedad new_name.

OBJETO REGLA

Las reglas son los elementos más complejos en el conjunto de reglas de nftables. Se componen de una serie de expresiones que se evalúan en orden. La estructura JSON para una regla es la siguiente:

{
    "family": "ipv4",
    "table": "mytable",
    "chain": "mychain",
    "handle": 123,     optional
    "index": 5,       optional
    "priority": 100,   optional
    "expr": [ ... ]
}

El campo expr es una matriz de objetos de expresión. Cada objeto de expresión representa una operación o un grupo de operaciones. Los objetos de expresión más comunes son:

match
Realiza una coincidencia con un campo específico. Ejemplo: 
{ "match": {
                "op": "==",
                "left": { "payload": {
                                "protocol": "tcp",
                                "field": "dport"
                }},
                "right": 22
        }}
accept
Acepta el paquete.
drop
Descarta el paquete.
reject
Rechaza el paquete.
log
Registra el paquete.
counter
Cuenta el paquete.
quota
Aplica una cuota al paquete.
rate
Aplica una tasa al paquete.

OBJETO TABLA

Las tablas son contenedores para cadenas. La estructura JSON para una tabla es la siguiente:

{
    "family": "inet",
    "name": "mytable",
    "handle": 123      optional
}

OBJETO CADENA

Las cadenas son listas de reglas. La estructura JSON para una cadena es la siguiente:

{
    "family": "inet",
    "table": "mytable",
    "name": "mychain",
    "type": "filter",      optional
    "hook": "input",        optional
    "priority": 100,   optional
    "handle": 123      optional
}

OBJETO SET

Los conjuntos son colecciones de elementos que se pueden utilizar para hacer coincidir múltiples valores a la vez. La estructura JSON para un conjunto es la siguiente:

{
    "family": "inet",
    "table": "mytable",
    "name": "my_set",
    "key": "ip",
    "type": "ipv4_addr",  optional
    "flags": [ ... ]         optional
}

OBJETO ELEMENTO

Los elementos son entradas individuales en un conjunto o mapa. La estructura JSON para un elemento es la siguiente:

{
    "set": "my_set",
    "key": "192.168.1.1",
    "value": "..."  optional, for maps
}

OBJETO MAPA

Los mapas son colecciones de pares clave-valor que se pueden utilizar para realizar búsquedas. La estructura JSON para un mapa es la siguiente:

{
    "family": "inet",
    "table": "mytable",
    "name": "my_map",
    "key": "port",
    "value": "string",
    "type": "map"
}

OBJETO CONTADOR

Los contadores se utilizan para contar paquetes y bytes que coinciden con una regla. La estructura JSON para un contador es la siguiente:

{
    "name": "my_counter",
    "packets": 123,
    "bytes": 456
}

OBJETO CUOTA

Las cuotas se utilizan para limitar el número de paquetes o bytes que pueden pasar a través de una regla. La estructura JSON para una cuota es la siguiente:

{
    "name": "my_quota",
    "limit": 100,
    "bytes": true,      optional, default false
    "period": "60s"     optional, default null
}

OBJETO ASISTENTE CT

Los asistentes CT (Connection Tracking) se utilizan para identificar protocolos de capa de aplicación. La estructura JSON para un asistente CT es la siguiente:

{
    "name": "my_helper",
    "timeout": 300      optional
}

OBJETO TIEMPO CT

Los tiempos de espera CT (Connection Tracking) definen cuánto tiempo se mantienen las conexiones en la tabla de seguimiento de conexiones. La estructura JSON para un tiempo de espera CT es la siguiente:

{
    "name": "my_timeout",
    "timeout": 300,
    "is_dp": true       optional, default false
}

OBJETO ESPERA CT

Las esperas CT (Connection Tracking) definen cuánto tiempo se mantienen las esperas en la tabla de esperas. La estructura JSON para una espera CT es la siguiente:

{
    "key": "my_expectation",
    "timeout": 300
}

OBJETO LIMITE

Los límites se utilizan para limitar la tasa de paquetes que coinciden con una regla. La estructura JSON para un límite es la siguiente:

{
    "name": "my_limit",
    "rate": 100,
    "unit": "packets",
    "interval": "1s"
}

OBJETO TABLA DE FLUJO

Las tablas de flujo se utilizan para acelerar el reenvío de paquetes utilizando el reenvío de hardware. La estructura JSON para una tabla de flujo es la siguiente:

{
    "family": "inet",
    "name": "my_flowtable",
    "hook": "prerouting",
    "priority": 0,
    "devices": [ "eth0" ]
}

NOTAS

Tenga en cuenta que la representación JSON puede volverse bastante verbosa, especialmente para reglas complejas. Se recomienda utilizar la sintaxis estándar de nftables siempre que sea posible.

La implementación JSON está en constante desarrollo y puede haber cambios en el esquema en versiones futuras.

COMANDOS

ADD

{ "add": OBJECT }

Add a new object, e.g. a new table, a new chain, a new rule, a new set.

INSERT

{ "insert": OBJECT }

Insert a new rule into a chain. The position is specified using the handle or index property of the rule object.

REPLACE

{ "replace": OBJECT }

Replace an existing rule. The rule to be replaced is identified using the handle property of the rule object.

DELETE

{ "delete": OBJECT }

Delete an object. The object to be deleted is identified using its handle property, or, if not available, using its name property.

CREATE

{ "create": OBJECT }

Create a new object, e.g. a new table or chain. This is semantically equivalent to add for tables and chains.

FLUSH

{ "flush": OBJECT }

Empty contents in given object, e.g. remove all chains from given table or remove all elements from given set.

RENAME

{ "rename": CHAIN }

Rename a chain. The new name is expected in a dedicated property named newname.

ELEMENTOS DEL RULESET

TABLE

{ "table": {
        "family": STRING,
        "name": STRING,
        "handle": NUMBER,
        "flags": TABLE_FLAGS
}}
TABLE_FLAGS := TABLE_FLAG | [ TABLE_FLAG_LIST ]
TABLE_FLAG_LIST := TABLE_FLAG [, TABLE_FLAG_LIST ]
TABLE_FLAG := "dormant" | "owner" | "persist"

Este objeto describe una tabla.

family

La familia de la tabla, por ejemplo "ip" o "ip6".

name

El nombre de la tabla.

handle

El manejador de la tabla. En la entrada, solo se usa en el comando delete como alternativa a name.

flags

Las banderas de la tabla.

CHAIN

{ "chain": {
        "family": STRING,
        "table": STRING,
        "name": STRING,
        "newname": STRING,
        "handle": NUMBER,
        "type": STRING,
        "hook": STRING,
        "prio": NUMBER,
        "dev": STRING,
        "policy": STRING
}}

Este objeto describe una cadena.

family

La familia de la tabla.

table

El nombre de la tabla.

name

El nombre de la cadena.

handle

El manejador de la cadena. En la entrada, solo se usa en el comando delete como alternativa a name.

newname

Un nuevo nombre para la cadena, solo relevante en el comando rename.

Las siguientes propiedades son requeridas para cadenas base:

type

El tipo de la cadena.

hook

El hook de la cadena.

prio

La prioridad de la cadena.

dev

La interfaz enlazada de la cadena (si pertenece a la familia netdev).

policy

La política de la cadena.

RULE

{ "rule": {
        "family": STRING,
        "table": STRING,
        "chain": STRING,
        "expr": [ STATEMENTS ],
        "handle": NUMBER,
        "index": NUMBER,
        "comment": STRING
}}
STATEMENTS := STATEMENT [, STATEMENTS ]

Este objeto describe una regla. Los bloques de construcción básicos de las reglas son las sentencias. Cada regla consta de al menos una.

family

La familia de la tabla.

table

El nombre de la tabla.

chain

El nombre de la cadena.

expr

Un array de sentencias de las que consta esta regla. En la entrada, solo se usa en los comandos add/insert/replace.

handle

El manejador de la regla. En los comandos delete/replace, sirve como identificador de la regla a eliminar/reemplazar. En los comandos add/insert, sirve como identificador de una regla existente a la que añadir/preceder la regla.

index

La posición de la regla para los comandos add/insert. Se usa como alternativa a handle en ese caso.

comment

Comentario opcional de la regla.

SET / MAP

{ "set": {
        "family": STRING,
        "table": STRING,
        "name": STRING,
        "handle": NUMBER,
        "type": SET_TYPE,
        "policy": SET_POLICY,
        "flags": SET_FLAGS,
        "elem": SET_ELEMENTS,
        "timeout": NUMBER,
        "gc-interval": NUMBER,
        "size": NUMBER,
        "auto-merge": BOOLEAN
}}
{ "map": {
        "family": STRING,
        "table": STRING,
        "name": STRING,
        "handle": NUMBER,
        "type": SET_TYPE,
        "map": STRING,
        "policy": SET_POLICY,
        "flags": SET_FLAGS,
        "elem": SET_ELEMENTS,
        "timeout": NUMBER,
        "gc-interval": NUMBER,
        "size": NUMBER,
        "auto-merge": BOOLEAN
}}
SET_TYPE := STRING | [ SET_TYPE_LIST ] | { "typeof": EXPRESSION }
SET_TYPE_LIST := STRING [, SET_TYPE_LIST ]
SET_POLICY := "performance" | "memory"
SET_FLAGS := SET_FLAG | [ SET_FLAG_LIST ]
SET_FLAG_LIST := SET_FLAG [, SET_FLAG_LIST ]
SET_FLAG := "constant" | "interval" | "timeout"
SET_ELEMENTS := EXPRESSION | [ EXPRESSION_LIST ]
EXPRESSION_LIST := EXPRESSION [, EXPRESSION_LIST ]

Estos objetos describen un set o map con nombre. Los maps son una forma especial de sets en cuanto a que traducen una clave única a un valor.

family

La familia de la tabla.

table

El nombre de la tabla.

name

El nombre del set.

handle

El manejador del set. Para la entrada, solo se usa en el comando delete.

type

El tipo de dato del set, véase abajo.

map

El tipo de los valores a los que este set mapea (es decir, este set es un map).

policy

La política del set.

flags

Las banderas del set.

elem

Elemento(s) inicial(es) del set, véase abajo.

timeout

Timeout del elemento en segundos.

gc-interval

Intervalo del recolector de basura en segundos.

size

Número máximo de elementos soportados.

auto-merge

Fusión automática de elementos adyacentes/superpuestos en sets de intervalo.

TYPE

El tipo de set puede ser una cadena, como "ipv4_addr", un array que consiste en cadenas (para tipos concatenados) o un objeto typeof que contiene una expresión para extraer el tipo.

ELEM

Un único elemento de set puede ser dado como cadena, entero o valor booleano para casos simples. Si se requieren propiedades adicionales, se puede usar un objeto elem formal.

Se pueden dar múltiples elementos en un array.

ELEMENT

{ "element": {
        "family": STRING,
        "table": STRING,
        "name": STRING,
        "elem": SET_ELEM
}}
SET_ELEM := EXPRESSION | [ EXPRESSION_LIST ]
EXPRESSION_LIST := EXPRESSION [, EXPRESSION ]

Manipular elementos en un set con nombre.

family

La familia de la tabla.

table

El nombre de la tabla.

name

El nombre del set.

elem

Véase la propiedad elem del objeto set.

LÍMITE

{ "limit": {
        "family": CADENA,
        "table": CADENA,
        "name": CADENA,
        "handle": NÚMERO,

        "per": CADENA,
        "burst": NÚMERO,
        "unit": UNIDAD_LÍMITE,
        "inv": BOOLEANO
}}
UNIDAD_LÍMITE := "packets" | "bytes"

Este objeto representa un límite con nombre.

family

La familia de la tabla.

table

El nombre de la tabla.

name

El nombre del límite.

handle

El identificador del límite. En la entrada, solo es utilizado por el comando delete.

rate

El valor de la tasa del límite.

per

Unidad de tiempo para aplicar el límite, por ejemplo "week", "day", "hour", etc. Si se omite, el valor predeterminado es "second".

burst

El valor de ráfaga del límite. Si se omite, el valor predeterminado es 0.

unit

Unidad de los valores de tasa y ráfaga. Si se omite, el valor predeterminado es "packets".

inv

Si es verdadero, coincide si el límite fue excedido. Si se omite, el valor predeterminado es false.

COINCIDENCIA

{ "match": {
        "left": EXPRESIÓN,
        "right": EXPRESIÓN,
        "op": CADENA
}}

Esto compara la expresión del lado izquierdo (típicamente una cabecera de paquete o información meta del paquete) con la expresión del lado derecho (típicamente un valor constante). Si la declaración se evalúa como verdadera, se considera la siguiente declaración en esta regla. Si no, el procesamiento continúa con la siguiente regla en la misma cadena.

left

Lado izquierdo de esta coincidencia.

right

right

Lado derecho de esta coincidencia.

op

Operador que indica el tipo de comparación.

OPERATORS

== Igual
!= No igual
< Menor que
> Mayor que
⇐ Menor o igual que
>= Mayor o igual que
in Realizar una búsqueda, es decir, probar si los bits en el RHS están contenidos en el valor del LHS

A diferencia de la API estándar, el operador es obligatorio aquí. En la API estándar, un operador faltante puede resolverse de dos maneras, dependiendo del tipo de expresión en el RHS:

•Si el RHS es una máscara de bits o una lista de máscaras de bits, la expresión se resuelve en una operación binaria con el operador de desigualdad, de esta manera: LHS & RHS != 0.
•En cualquier otro caso, simplemente se inserta el operador de igualdad.

Para el primer caso no trivial, la API JSON soporta el operador in.
