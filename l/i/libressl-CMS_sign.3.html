Paquete: libressl

Licencias: ISC, custom:OpenSSL

CMS_SIGN(3) Manual de funciones de la biblioteca CMS_SIGN(3)

NOMBRE

CMS_sign — crear una estructura SignedData de CMS

SINOPSIS

biblioteca “libcrypto”
#include <openssl/cms.h>

CMS_ContentInfo *
CMS_sign(X509 *signcert, EVP_PKEY *pkey, STACK_OF(X509) *certs, BIO *data, unsigned int flags);

DESCRIPCIÓN

CMS_sign() crea y devuelve una estructura SignedData de CMS. signcert es el certificado con el que firmar, pkey es la clave privada correspondiente. certs es un conjunto opcional de certificados adicionales para incluir en la estructura CMS (por ejemplo, cualquier CA intermedia en la cadena). Cualquiera o todos estos parámetros pueden ser NULL.

Los datos a firmar se leen de data.

Cualquiera de las siguientes banderas (combinadas con OR) puede pasarse en el argumento flags:

CMS_TEXT
Anteponer encabezados MIME para el tipo text/plain a los datos. Muchos clientes S/MIME esperan que el contenido firmado incluya encabezados MIME válidos.
CMS_NOCERTS
No incluir el certificado del firmante en la estructura CMS_ContentInfo. Sin embargo, el certificado del firmante aún debe suministrarse en el parámetro signcert. Esto puede reducir el tamaño de la firma si el certificado del firmante se puede obtener por otros medios, por ejemplo, de un mensaje firmado previamente.
CMS_DETACHED
Omitir los datos que se firman de la estructura CMS_ContentInfo. Esto se utiliza para firmas desadjuntas de CMS_ContentInfo que se utilizan en mensajes firmados en texto plano S/MIME, por ejemplo.
CMS_BINARY
No traducir el contenido suministrado al formato canónico MIME, aunque esto lo requieran las especificaciones S/MIME. Esta opción debe utilizarse si los datos suministrados están en formato binario. De lo contrario, la traducción los corromperá.
CMS_NOATTR
No añadir ningún SignedAttributes. Por defecto, el campo signerInfos incluye varios SignedAttributes de CMS, incluido el tiempo de firma, el tipo de contenido CMS y la lista de cifradores compatibles en un atributo SMIMECapabilities.
CMS_NOSMIMECAP
Omitir solo las SMIMECapabilities. Si está presente, el atributo SMIMECapabilities indica soporte para los siguientes algoritmos en orden de preferencia: AES de 256 bits, AES de 192 bits, AES de 128 bits, triple DES, RC2 de 128 bits, RC2 de 64 bits, DES y RC2 de 40 bits. Si alguno de estos algoritmos no está disponible, no se incluirá.
CMS_USE_KEYID
Utilizar el valor del identificador de clave del sujeto para identificar los certificados de firma. Se produce un error si el certificado de firma no tiene una extensión de identificador de clave del sujeto. Por defecto, se utiliza el nombre del emisor y el número de serie en su lugar.
CMS_STREAM
Solo inicializar la estructura CMS_ContentInfo devuelta para prepararla para realizar la operación de firma. Sin embargo, la firma no se realiza y los datos a firmar no se leen del parámetro data. La firma se aplaza hasta después de que se hayan escrito los datos. De esta manera, los datos se pueden firmar en un solo pase. La estructura CMS_ContentInfo devuelta no está completa y la salida de su contenido a través de una función que no finaliza correctamente la estructura CMS_ContentInfo dará resultados impredecibles. Varias funciones, como SMIME_write_CMS(3), i2d_CMS_bio_stream(3), o PEM_write_bio_CMS_stream(3) finalizan la estructura. Alternativamente, la finalización se puede realizar obteniendo el BIO ASN1 de streaming directamente utilizando BIO_new_CMS(3).
CMS_PARTIAL
Generar una estructura CMS_ContentInfo parcial a la que se puedan añadir firmantes y capacidades adicionales antes de la finalización.

Si se especifica un firmante, utilizará el resumen predeterminado para el algoritmo de firma. Este es SHA-1 tanto para claves RSA como DSA.

Si signcert y pkey son NULL, entonces se genera una estructura CMS solo de certificados.

La función CMS_sign() es una función básica de firma de CMS cuya salida será adecuada para muchos propósitos. Para un control más fino del formato de salida, los parámetros certs, signcert y pkey pueden ser todos NULL y establecerse la bandera CMS_PARTIAL. Luego se pueden añadir uno o más firmantes utilizando la función CMS_add1_signer(3), se pueden utilizar resúmenes no predeterminados y añadir atributos personalizados. CMS_final(3) debe llamarse entonces para finalizar la estructura si no está habilitado el streaming.

VALORES DE RETORNO

CMS_sign() devuelve una estructura CMS_ContentInfo válida o NULL si ocurrió un error. El error se puede obtener de ERR_get_error(3).
