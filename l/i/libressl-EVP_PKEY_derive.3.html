libressl-EVP_PKEY_derive(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

EVP_PKEY_DERIVE(3) Manual de funciones de la biblioteca EVP_PKEY_DERIVE(3)

NOMBRE

EVP_PKEY_derive_init, EVP_PKEY_derive_set_peer, EVP_PKEY_CTX_get0_peerkey, EVP_PKEY_derive — derivar secreto compartido de algoritmo de clave pública

SINÓPSIS

biblioteca “libcrypto”
#include <openssl/evp.h>

int
EVP_PKEY_derive_init(EVP_PKEY_CTX *ctx);

int
EVP_PKEY_derive_set_peer(EVP_PKEY_CTX *ctx, EVP_PKEY *peerkey);

EVP_PKEY *
EVP_PKEY_CTX_get0_peerkey(EVP_PKEY_CTX *ctx);

int
EVP_PKEY_derive(EVP_PKEY_CTX *ctx, unsigned char *key, size_t *keylen);

DESCRIPCIÓN

EVP_PKEY_derive_init() inicializa el contexto del algoritmo de clave pública ctx para la derivación de secretos compartidos utilizando el objeto EVP_PKEY ya almacenado en ctx. La biblioteca proporciona soporte incorporado para claves con un EVP_PKEY_base_id(3) de EVP_PKEY_DH, EVP_PKEY_EC, EVP_PKEY_HKDF y EVP_PKEY_X25519.

Después de la llamada a EVP_PKEY_derive_init(), se pueden realizar opcionalmente operaciones de control específicas del algoritmo para establecer los parámetros apropiados para la operación.

EVP_PKEY_derive_set_peer() configura el ctx, que ya debe estar inicializado con EVP_PKEY_derive_init(), EVP_PKEY_encrypt_init(3), o EVP_PKEY_decrypt_init(3), para usar la peerkey, que normalmente es una clave pública. En caso de éxito, el contador de referencias de peerkey se incrementa en uno. En consecuencia, el llamador debe llamar a EVP_PKEY_free(3) en peerkey cuando el llamador ya no la necesite, incluso si todavía está en uso por ctx.

EVP_PKEY_derive() deriva un secreto compartido utilizando ctx. Si key es NULL, entonces el tamaño máximo del búfer de salida se escribe en el parámetro keylen. Si key no es NULL, entonces antes de la llamada, el parámetro keylen debe contener la longitud del búfer key. Si la llamada tiene éxito, el secreto compartido se escribe en key y la cantidad de datos escrita en keylen.

La función EVP_PKEY_derive() puede ser llamada más de una vez en el mismo contexto si se realizan varias operaciones utilizando los mismos parámetros.

VALORES DEVUELTOS

EVP_PKEY_derive_init(), EVP_PKEY_derive_set_peer(), y EVP_PKEY_derive() devuelven 1 para éxito y 0 o un valor negativo para fallo. En particular, un valor de retorno de -2 indica que la operación no es compatible con el algoritmo de clave pública.

Para EVP_PKEY_derive_set_peer(), un valor de retorno de -1 puede ocurrir, por ejemplo, si ctx no está inicializado correctamente, no contiene un EVP_PKEY que pueda ser recuperado con EVP_PKEY_CTX_get0_pkey(3), el EVP_PKEY_id(3) de ambas claves no coincide, o EVP_PKEY_cmp_parameters(3) informa de parámetros de clave que no coinciden.

EVP_PKEY_derive() falla con un valor de retorno de -1, por ejemplo, si ctx no ha sido inicializado correctamente con EVP_PKEY_derive_init().

EVP_PKEY_CTX_get0_peerkey() devuelve un puntero interno a la peerkey utilizada por ctx sin incrementar su contador de referencias.

EJEMPLOS

Derivar secreto compartido (por ejemplo, claves DH o EC):

#include <openssl/evp.h>
#include <openssl/rsa.h>

EVP_PKEY_CTX *ctx;
unsigned char *skey;
size_t skeylen;
EVP_PKEY *pkey, *peerkey;

/* Se asume que pkey y peerkey ya han sido configurados. */
ctx = EVP_PKEY_CTX_new(pkey, NULL);
if (!ctx)
	/* Ocurrió un error */
if (EVP_PKEY_derive_init(ctx) <= 0)
	/* Error */
if (EVP_PKEY_derive_set_peer(ctx, peerkey) <= 0)
	/* Error */

/* Determinar la longitud del búfer */
if (EVP_PKEY_derive(ctx, NULL, &skeylen) <= 0)
	/* Error */

skey = malloc(skeylen);

if (!skey)
	/* Fallo de malloc */

if (EVP_PKEY_derive(ctx, skey, &skeylen) <= 0)
	/* Error */

/* El secreto compartido son skey bytes escritos en el búfer skey */
