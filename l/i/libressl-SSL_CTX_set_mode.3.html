libressl-SSL_CTX_set_mode(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_CTX_SET_MODE(3) Manual de funciones de biblioteca SSL_CTX_SET_MODE(3)

NOMBRE

SSL_CTX_set_mode, SSL_set_mode, SSL_CTX_clear_mode, SSL_clear_mode, SSL_CTX_get_mode, SSL_get_mode — manipular el modo del motor SSL

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

long
SSL_CTX_set_mode(SSL_CTX *ctx, long mode);

long
SSL_set_mode(SSL *ssl, long mode);

long
SSL_CTX_clear_mode(SSL_CTX *ctx, long mode);

long
SSL_clear_mode(SSL *ssl, long mode);

long
SSL_CTX_get_mode(SSL_CTX *ctx);

long
SSL_get_mode(SSL *ssl);

DESCRIPCIÓN

SSL_CTX_set_mode() y SSL_set_mode() habilitan las opciones contenidas en la máscara de bits mode para el objeto ctx o ssl, respectivamente. Las opciones que ya estaban habilitadas antes de la llamada no se deshabilitan.

SSL_CTX_clear_mode() y SSL_clear_mode() deshabilitan las opciones contenidas en la máscara de bits mode para el objeto ctx o ssl.

SSL_CTX_get_mode() y SSL_get_mode() devuelven una máscara de bits que representa las opciones que están actualmente habilitadas para el objeto ctx o ssl.

Las siguientes opciones están disponibles:

SSL_MODE_ENABLE_PARTIAL_WRITE
Permite que SSL_write(..., n) devuelva r con 0<r<n (es decir, informar éxito cuando solo se ha escrito un registro). Cuando no está configurado (por defecto), SSL_write(3) solo informará éxito una vez que se haya escrito el bloque completo. Una vez que SSL_write(3) devuelve r, se han escrito correctamente r bytes y la próxima llamada a SSL_write(3) solo debe enviar los n − r bytes restantes, imitando el comportamiento de write(2).
SSL_MODE_ACCEPT_MOVING_WRITE_BUFFER
Hace posible reintentar SSL_write(3) con una ubicación de búfer cambiada (el contenido del búfer debe permanecer igual). Esto no es el valor predeterminado para evitar la idea errónea de que SSL_write(3) no bloqueante se comporta como write(2) no bloqueante.
SSL_MODE_AUTO_RETRY
Nunca molestar a la aplicación con reintentos si el transporte está bloqueando. Si se produce una renégociación durante la operación normal, una llamada a SSL_read(3) o SSL_write(3) devolvería −1 e indicaría la necesidad de reintentar con SSL_ERROR_WANT_READ. En un entorno no bloqueante, las aplicaciones deben estar preparadas para manejar operaciones de lectura/escritura incompletas. En un entorno bloqueante, las aplicaciones no siempre están preparadas para lidiar con operaciones de lectura/escritura que regresan sin informe de éxito. El flag SSL_MODE_AUTO_RETRY hará que las operaciones de lectura/escritura solo regresen después del handshake y la finalización exitosa.
SSL_MODE_RELEASE_BUFFERS
Cuando ya no necesitamos un búfer de lectura o un búfer de escritura para un SSL determinado, liberamos la memoria que estábamos utilizando para alojarlo. El uso de este flag puede ahorrar alrededor de 34k por conexión SSL inactiva. Este flag no tiene efecto en las conexiones SSL v2, ni en las conexiones DTLS.

VALORES DE RETORNO

SSL_CTX_set_mode(), SSL_set_mode(), SSL_CTX_clear_mode(), y SSL_clear_mode() devuelven la nueva máscara de bits del modo después de agregar o limpiar mode.

SSL_CTX_get_mode() y SSL_get_mode() devuelven la máscara de bits actual.

VER TAMBIÉN

ssl(3), SSL_CTX_ctrl(3), SSL_read(3), SSL_write(3)

HISTORIA

SSL_CTX_set_mode(), SSL_set_mode(), SSL_CTX_get_mode(), y SSL_get_mode() aparecieron por primera vez en OpenSSL 0.9.4 y han estado disponibles desde OpenBSD 2.6.

SSL_CTX_clear_mode() y SSL_clear_mode() aparecieron por primera vez en OpenSSL 0.9.8m y han estado disponibles desde OpenBSD 4.9.

SSL_MODE_AUTO_RETRY se agregó en OpenSSL 0.9.6.
