libressl-CONF_modules_load_file(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

CONF_MODULES_LOAD_FILE(3) Manual de funciones de biblioteca CONF_MODULES_LOAD_FILE(3)

NOMBRE

CONF_modules_load_file, CONF_modules_load, X509_get_default_cert_area — Funciones de configuración de OpenSSL

SINOPSIS

biblioteca “libcrypto”
#include <openssl/conf.h>

int
CONF_modules_load_file(const char *filename, const char *appname, unsigned long flags);

int
CONF_modules_load(const CONF *cnf, const char *appname, unsigned long flags);

#include <openssl/x509.h>

const char *
X509_get_default_cert_area(void);

DESCRIPCIÓN

La función CONF_modules_load_file() configura OpenSSL utilizando el archivo filename en formato openssl.cnf(5) y el nombre de aplicación appname. Si filename es NULL, se utiliza el archivo de configuración estándar de OpenSSL /etc/ssl/openssl.cnf. Si appname es NULL, se utiliza el nombre de aplicación estándar de OpenSSL "openssl_conf". El comportamiento se puede personalizar usando flags.

Consulte la sección EJEMPLOS para ver funciones adicionales que podrían necesitar ser llamadas. Llamar a las funciones de configuración en el orden correcto para el efecto deseado puede ser complicado porque muchas funciones de configuración se llaman entre sí internamente.

CONF_modules_load() es idéntica a CONF_modules_load_file() excepto que lee información de configuración de cnf.

Las siguientes flags se reconocen actualmente:

CONF_MFLAGS_IGNORE_ERRORS
Ignorar errores devueltos por módulos de configuración individuales. Por defecto, el primer error del módulo se considera fatal y no se cargan más módulos.
CONF_MFLAGS_SILENT
No añadir ninguna información de error. Por defecto, todos los errores de módulo añaden información de error a la cola de errores.
CONF_MFLAGS_NO_DSO
Deshabilitar la carga de módulos de configuración desde DSOs. Esta bandera se proporciona por compatibilidad y no tiene efecto.
CONF_MFLAGS_IGNORE_MISSING_FILE
Permitir que CONF_modules_load_file() ignore los archivos de configuración faltantes. Por defecto, un archivo de configuración faltante devuelve un error.
CONF_MFLAGS_DEFAULT_SECTION
Si appname no es NULL pero no existe, recurrir a la sección por defecto "openssl_conf".

Al usar CONF_modules_load_file() con banderas apropiadas, una aplicación puede personalizar la configuración de la aplicación para que se adapte mejor a sus necesidades. En algunos casos, el uso de un archivo de configuración es opcional y su ausencia no es un error: en este caso, se establecería CONF_MFLAGS_IGNORE_MISSING_FILE.

Los errores durante la configuración también pueden ser manejados de manera diferente por diferentes aplicaciones. Por ejemplo, en algunos casos, un error puede simplemente imprimir un mensaje de advertencia y la aplicación puede continuar. En otros casos, una aplicación podría considerar un error de archivo de configuración como fatal y salir inmediatamente.

Las aplicaciones pueden usar la función CONF_modules_load() si desean cargar un archivo de configuración ellas mismas y tener un control más fino sobre cómo se tratan los errores.

VALORES DE RETORNO

CONF_modules_load_file() y CONF_modules_load() devuelven 1 en caso de éxito y cero o un valor negativo en caso de fallo. Si los errores del módulo no se ignoran, el código de retorno reflejará el valor de retorno del módulo que falla (que siempre será cero o negativo).

X509_get_default_cert_area() devuelve un puntero a la cadena constante "/etc/ssl".

ARCHIVOS

/etc/ssl
directorio de configuración estándar
/etc/ssl/openssl.cnf
archivo de configuración estándar

EJEMPLOS

Cargar un archivo de configuración e imprimir cualquier error y salir (archivo faltante considerado fatal):

if (CONF_modules_load_file(NULL, NULL, 0) <= 0) {
	fprintf(stderr, "FATAL: error loading configuration file\n");
	ERR_print_errors_fp(stderr);
	exit(1);
}

Cargar el archivo de configuración por defecto usando la sección indicada por "myapp", tolerar archivos faltantes, pero salir en otros errores:

if (CONF_modules_load_file(NULL, "myapp",
    CONF_MFLAGS_IGNORE_MISSING_FILE) <= 0) {
	fprintf(stderr, "FATAL: error loading configuration file\n");
	ERR_print_errors_fp(stderr);
	exit(1);
}

Cargar y usar un archivo de configuración y sección personalizados en lugar del estándar, solo imprimir advertencias en caso de error, archivo de configuración faltante ignorado:

OPENSSL_no_config();
if (CONF_modules_load_file("/something/app.cnf", "myapp",
    CONF_MFLAGS_IGNORE_MISSING_FILE) <= 0) {
	fprintf(stderr, "WARNING: error loading configuration file\n");
	ERR_print_errors_fp(stderr);
}

En el ejemplo anterior, se requiere la llamada a OPENSSL_no_config(3) primero para suprimir la carga automática del archivo de configuración estándar.

Cargar y analizar el archivo de configuración manualmente, manejo de errores personalizado:

FILE	*fp;
CONF	*cnf = NULL;
long	 eline;

fp = fopen("/somepath/app.cnf", "r");
if (fp == NULL) {
	fprintf(stderr, "Error opening configuration file\n");
	/* Otro comportamiento para archivo de configuración faltante */
} else {
	cnf = NCONF_new(NULL);
	if (NCONF_load_fp(cnf, fp, &eline) == 0) {
		fprintf(stderr, "Error on line %ld of configuration file\n",
		    eline);
		ERR_print_errors_fp(stderr);
		/* Otro comportamiento para archivo de configuración mal formado */
	} else if (CONF_modules_load(cnf, "appname", 0) <= 0) {
		fprintf(stderr, "Error configuring application\n");
		ERR_print_errors_fp(stderr);
		/* Otro comportamiento para error de configuración */
	}
	fclose(fp);
	NCONF_free(cnf);
}

CONF_modules_load_file() y CONF_modules_load() aparecieron por primera vez en OpenSSL 0.9.7 y han estado disponibles desde OpenBSD 3.2.
