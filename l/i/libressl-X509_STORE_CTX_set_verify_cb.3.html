X509_STORE_CTX_SET_VERIFY_CB(3) Manual de funciones de biblioteca X509_STORE_CTX_SET_VERIFY_CB(3)

NOMBRE

X509_STORE_CTX_verify_cb, X509_STORE_CTX_set_verify_cb, X509_STORE_CTX_get_verify_cb — establecer y recuperar la función de devolución de llamada de verificación

SINOPSIS

biblioteca “libcrypto”
#include <openssl/x509_vfy.h>

typedef int (*X509_STORE_CTX_verify_cb)(int ok, X509_STORE_CTX *ctx);

void
X509_STORE_CTX_set_verify_cb(X509_STORE_CTX *ctx, X509_STORE_CTX_verify_cb verify_cb);

X509_STORE_CTX_verify_cb
X509_STORE_CTX_get_verify_cb(X509_STORE_CTX *ctx);

DESCRIPCIÓN

X509_STORE_CTX_set_verify_cb() establece la función de devolución de llamada de verificación de ctx a verify_cb, sobrescribiendo cualquier función de devolución de llamada existente.

La función de devolución de llamada de verificación puede usarse para modificar la operación de verificación de certificados, ya sea anulando condiciones de error o registrando errores con fines de depuración. El uso de una función de devolución de llamada de verificación no es esencial y no debe usarse en programas sensibles a la seguridad.

No use esta función. Es extremadamente frágil e impredecible. Esta función de devolución de llamada expone detalles de implementación de la verificación de certificados, que cambian a medida que la biblioteca evoluciona. Intentar usarla para verificaciones de seguridad puede introducir vulnerabilidades si se hacen suposiciones incorrectas sobre cuándo se llama a la función de devolución de llamada. Además, anular ok puede dejar a ctx en un estado inconsistente y romper invariantes.

En su lugar, personalice la verificación de certificados configurando opciones en la X509_STORE_CTX antes de la verificación, o aplicando verificaciones adicionales después de que X509_verify_cert(3) se complete con éxito.

El parámetro ok de la función de devolución de llamada indica el valor que la función de devolución de llamada debe devolver para conservar el comportamiento predeterminado. Si es cero, se indica una condición de error. Si es 1, no ocurrió ningún error. Dado que el comportamiento predeterminado es interno al verificador y posiblemente desconocido para el llamador, cambiar este parámetro es intrínsecamente peligroso y normalmente no debería hacerse, excepto con fines de depuración, y no se debe esperar que sea consistente si el verificador cambia. Si se establece la bandera X509_V_FLAG_NOTIFY_POLICY, entonces ok se establece en 2 para indicar que la verificación de políticas se ha completado.

El parámetro ctx de la función de devolución de llamada es la estructura X509_STORE_CTX que está realizando la operación de verificación. Una función de devolución de llamada puede examinar esta estructura y recibir información adicional sobre el error, por ejemplo, llamando a X509_STORE_CTX_get_current_cert(3). Se pueden pasar datos de aplicación adicionales a la función de devolución de llamada a través del mecanismo ex_data.

La función de devolución de llamada de verificación puede establecerse y heredarse de la estructura principal que realiza la operación. En algunos casos (como la verificación S/MIME), la estructura X509_STORE_CTX se crea y destruye internamente, y la única forma de establecer una función de devolución de llamada de verificación personalizada es heredándola de la X509_STORE asociada.

VALORES DE RETORNO

X509_STORE_CTX_get_verify_cb() devuelve un puntero a la función de devolución de llamada actual utilizada por el ctx especificado. Si no se estableció ninguna función de devolución de llamada usando X509_STORE_CTX_set_verify_cb(), es un puntero a una función estática incorporada que no hace nada más que devolver el argumento ok que se le pasó.

EJEMPLOS

Operación predeterminada de la función de devolución de llamada:

int
verify_callback(int ok, X509_STORE_CTX *ctx)
{
	return ok;
}

Esta es probablemente la única función de devolución de llamada segura para usar.

Ejemplo simple y terrible que no debe usarse. Supongamos que un certificado en la cadena ha expirado y deseamos continuar después de este error:

int
verify_callback(int ok, X509_STORE_CTX *ctx)
{
	/* Tolerar la expiración del certificado */
	if (X509_STORE_CTX_get_error(ctx) == X509_V_ERR_CERT_HAS_EXPIRED)
		return 1;
	/* De lo contrario, no anular */
	return ok;
}

Aunque este ejemplo se presenta con fines históricos, esta no es la forma correcta de lograr esto. En su lugar, se debe establecer la bandera de verificación X509_V_FLAG_NO_CHECK_TIME en la STORE_CTX usando X509_VERIFY_PARAM_set_flags(3).

Función de devolución de llamada de registro de depuración completa - tenga en cuenta que la salida y el orden en que ocurren las cosas pueden cambiar con el tiempo y no deben ser analizados ni se debe esperar que sean consistentes. En este caso, se asume que bio_err es un BIO de registro global, una alternativa sería almacenar un BIO en ctx usando ex_data.

int
verify_callback(int ok, X509_STORE_CTX *ctx)
{
	X509 *err_cert;
	int err,depth;

	err_cert = X509_STORE_CTX_get_current_cert(ctx);
	err =	X509_STORE_CTX_get_error(ctx);
	depth =	X509_STORE_CTX_get_error_depth(ctx);

	BIO_printf(bio_err,"depth=%d ",depth);
	if (err_cert) {
		X509_NAME_print_ex(bio_err,
		    X509_get_subject_name(err_cert), 0,
		    XN_FLAG_ONELINE);
		BIO_puts(bio_err, "\n");
	} else
		BIO_puts(bio_err, "<no cert>\n");
	if (!ok)
		BIO_printf(bio_err, "verify error:num=%d:%s\n",
		    err, X509_verify_cert_error_string(err));
	switch (err) {
	case X509_V_ERR_UNABLE_TO_GET_ISSUER_CERT:
		BIO_puts(bio_err, "issuer= ");
		X509_NAME_print_ex(bio_err,
		    X509_get_issuer_name(err_cert), 0,
		    XN_FLAG_ONELINE);
		BIO_puts(bio_err, "\n");
		break;
	case X509_V_ERR_CERT_NOT_YET_VALID:
	case X509_V_ERR_ERROR_IN_CERT_NOT_BEFORE_FIELD:
		BIO_printf(bio_err, "notBefore=");
		ASN1_TIME_print(bio_err,
		    X509_get_notBefore(err_cert));
		BIO_printf(bio_err, "\n");
		break;
	case X509_V_ERR_CERT_HAS_EXPIRED:
	case X509_V_ERR_ERROR_IN_CERT_NOT_AFTER_FIELD:
		BIO_printf(bio_err, "notAfter=");
		ASN1_TIME_print(bio_err, X509_get_notAfter(err_cert));
		BIO_printf(bio_err, "\n");
		break;
	case X509_V_ERR_NO_EXPLICIT_POLICY:
		policies_print(bio_err, ctx);
		break;
	}
	if (err == X509_V_OK && ok == 2)
		/* imprimir políticas */

	BIO_printf(bio_err,"verify return:%d\n",ok);
	return(ok);
}

ADVERTENCIAS

ADVERTENCIAS

En general, una devolución de llamada de verificación NO debe devolver un valor de ok modificado, ya que esto puede permitir que la verificación parezca exitosa de forma impredecible. Esto puede eliminar efectivamente toda la seguridad de la aplicación, ya que es posible que se acepten certificados no confiables o no válidos. Hacer esto puede hacer que X509_verify_cert(3) devuelva lo que parece ser una cadena de certificados validada que no ha sido validada o incluso que no se han comprobado las firmas.
