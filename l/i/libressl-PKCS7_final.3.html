PKCS7_FINAL(3) Manual de Funciones de Biblioteca PKCS7_FINAL(3)

NOMBRE

PKCS7_final — leer datos de un BIO en un objeto ContentInfo

SINOPSIS

biblioteca “libcrypto”
#include <openssl/pkcs7.h>

int
PKCS7_final(PKCS7 *p7, BIO *data, int flags);

DESCRIPCIÓN

PKCS7_final() lee data y la coloca en el campo de contenido apropiado de p7 en sí mismo o de su subestructura apropiada, que puede ser de tipo SignedData, EnvelopedData, SignedAndEnvelopedData, DigestedData, o datos arbitrarios. El manual de PKCS7_dataFinal(3) explica en qué campo exacto se colocan los datos.

Los siguientes flags son reconocidos:

PKCS7_BINARY
Copia los datos literalmente sin cambiar ningún byte. Por defecto, los finales de línea se reemplazan con secuencias de dos bytes "\r\n" (CR+LF ASCII). Si se establece este flag, PKCS7_TEXT se ignora.
PKCS7_TEXT
Antepone "Content-Type: text/plain" seguido de una línea en blanco a los datos. Este flag se ignora si PKCS7_BINARY también está establecido.

Si otros bits están establecidos en flags, por ejemplo PKCS7_STREAM o PKCS7_PARTIAL, se ignoran, permitiendo pasar el mismo argumento flags que ya se pasó a PKCS7_sign(3) o PKCS7_encrypt(3).

PKCS7_final() se usa más comúnmente para finalizar un objeto p7 devuelto por una llamada a PKCS7_sign(3) que usó flags incluyendo PKCS7_PARTIAL o PKCS7_STREAM. Con estos flags, PKCS7_sign(3) ignora su argumento data. El objeto p7 parcial devuelto puede luego ser personalizado, por ejemplo, configurando múltiples firmantes o algoritmos de hash no predeterminados con PKCS7_sign_add_signer(3), antes de llamar a PKCS7_final().

De manera similar, PKCS7_final() se puede usar para finalizar un objeto p7 devuelto por una llamada a PKCS7_encrypt(3) que usó flags incluyendo PKCS7_STREAM.

Dado que PKCS7_final() comienza llamando PKCS7_dataInit(3) internamente, usarla para finalizar un objeto p7 que contiene SignedAndEnvelopedData, DigestedData, o datos arbitrarios requiere la configuración descrita en el manual de PKCS7_dataInit(3). Para SignedData y EnvelopedData, dicha configuración manual también es factible, pero se realiza más fácilmente con PKCS7_sign(3) o PKCS7_encrypt(3), respectivamente.

PKCS7_final() es solo una entre varias funciones que se pueden usar para finalizar p7; las alternativas incluyen SMIME_write_PKCS7(3), PEM_write_bio_PKCS7_stream(3), y i2d_PKCS7_bio_stream(3).

VALORES DE RETORNO

PKCS7_final() devuelve 1 en caso de éxito o 0 en caso de error.

Las posibles razones de error incluyen:

  • p7 es NULL.
  • El campo content de p7 está vacío.
  • El contentType de p7 no es compatible.
  • Se solicita firmar o procesar con hash y p7 no está configurado para almacenar una firma separada, pero tampoco contiene el campo requerido para almacenar el contenido.
  • Al menos un firmante carece de un algoritmo de hash utilizable.
  • Se requiere un cifrador pero no está configurado ninguno.
  • Cualquier operación requerida falla, por ejemplo, firmar o procesar con hash.
  • La asignación de memoria falla.

Los firmantes que carecen de claves privadas no provocan un error, sino que se omiten silenciosamente.

VER TAMBIÉN

BIO_new(3), i2d_PKCS7_bio_stream(3), PEM_write_bio_PKCS7_stream(3), PKCS7_add_attribute(3), PKCS7_dataFinal(3), PKCS7_dataInit(3), PKCS7_encrypt(3), PKCS7_new(3), PKCS7_sign(3), SMIME_write_PKCS7(3)

HISTORIA

PKCS7_final() apareció por primera vez en OpenSSL 1.0.0 y ha estado disponible desde OpenBSD 4.9.

ADVERTENCIAS

Esta función no admite EncryptedData.
