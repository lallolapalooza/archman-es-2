SSL_DO_HANDSHAKE(3) Manual de Funciones de Librería SSL_DO_HANDSHAKE(3)

NOMBRE

SSL_do_handshake — realizar un handshake TLS/SSL

SINOPSIS

librería “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_do_handshake(SSL *ssl);

DESCRIPCIÓN

SSL_do_handshake() esperará a que tenga lugar un handshake SSL/TLS. Si la conexión está en modo cliente, se iniciará el handshake. Las rutinas de handshake pueden tener que establecerse explícitamente de antemano utilizando SSL_set_connect_state(3) o SSL_set_accept_state(3).

El comportamiento de SSL_do_handshake() depende del BIO subyacente.

Si el BIO subyacente es bloqueante, SSL_do_handshake() solo retornará una vez que el handshake se haya completado o se haya producido un error.

Si el BIO subyacente es no bloqueante, SSL_do_handshake() también retornará cuando el BIO subyacente no pudo satisfacer las necesidades de SSL_do_handshake() para continuar el handshake. En este caso, una llamada a SSL_get_error(3) con el valor de retorno de SSL_do_handshake() generará SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE. El proceso llamante debe repetir la llamada después de tomar las medidas adecuadas para satisfacer las necesidades de SSL_do_handshake(). La acción depende del BIO subyacente. Al usar un socket no bloqueante, no hay nada que hacer, pero select(2) puede usarse para verificar la condición requerida. Al usar un BIO de buffer, como un par de BIO, los datos deben escribirse en el BIO o recuperarse de él antes de poder continuar.

VALORES DE RETORNO

Los siguientes valores de retorno pueden ocurrir:

0
El handshake TLS/SSL no tuvo éxito, pero se cerró de forma controlada y según las especificaciones del protocolo TLS/SSL. Llame a SSL_get_error(3) con el valor de retorno ret para conocer la razón.
1
El handshake TLS/SSL se completó con éxito y se estableció una conexión TLS/SSL.
<0
El handshake TLS/SSL no tuvo éxito porque ocurrió un error fatal a nivel de protocolo o un fallo de conexión. El cierre no fue limpio. También puede ocurrir si se necesita acción para continuar la operación para BIOs no bloqueantes. Llame a SSL_get_error(3) con el valor de retorno ret para conocer la razón.

VER TAMBIÉN

BIO_new(3), ssl(3), SSL_accept(3), SSL_connect(3), SSL_get_error(3), SSL_set_connect_state(3)
