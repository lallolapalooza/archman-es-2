NOMBRE

X509_check_host, X509_check_email, X509_check_ip, X509_check_ip_asc — Coincidencia de certificados X.509

SINOPSIS

biblioteca “libcrypto”
#include <openssl/x509v3.h>

int
X509_check_host(X509 *x, const char *name, size_t namelen, unsigned int flags, char **peername);

int
X509_check_email(X509 *x, const char *address, size_t addresslen, unsigned int flags);

int
X509_check_ip(X509 *x, const unsigned char *address, size_t addresslen, unsigned int flags);

int
X509_check_ip_asc(X509 *x, const char *address, unsigned int flags);

DESCRIPCIÓN

Las funciones de coincidencia de certificados se utilizan para comprobar si un certificado coincide con un nombre de host, dirección de correo electrónico o dirección IP determinada. La validez del certificado y su nivel de confianza deben comprobarse por otros medios.

X509_check_host() comprueba si el Nombre Alternativo del Sujeto (SAN) o el Nombre Común (CN) del certificado coincide con el nombre de host especificado, que debe estar codificado en la sintaxis de nombre preferida descrita en la sección 3.5 de RFC 1034. Por defecto, se admiten comodines y coinciden solo en la etiqueta más a la izquierda; pueden coincidir con parte de esa etiqueta con un prefijo o sufijo explícito. Por ejemplo, por defecto, el nombre de host name "www.example.com" coincidiría con un certificado con un valor SAN o CN de "*.example.com", "w*.example.com" o "*w.example.com".

Según la sección 6.4.2 de RFC 6125, los valores de name que representan nombres de dominio internacionales deben proporcionarse en formato A-label. El argumento namelen debe ser el número de caracteres de la cadena de nombre o cero, en cuyo caso la longitud se calcula con strlen(name). Cuando name comienza con un punto (por ejemplo, ".example.com"), coincidirá con cualquier subdominio de name; véase también X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAINS más adelante.

Cuando el certificado coincide y peername no es NULL, se almacena un puntero a una copia del SAN o CN coincidente del certificado del par en la dirección pasada en peername. La aplicación es responsable de liberar peername mediante free(3) cuando ya no sea necesario.

X509_check_email() comprueba si el certificado coincide con la dirección de correo electrónico especificada. Solo se admite la sintaxis de buzón de RFC 822. Los comentarios no están permitidos y no se intenta normalizar los caracteres entre comillas. El argumento addresslen debe ser el número de caracteres de la cadena de dirección o cero, en cuyo caso la longitud se calcula con strlen(address).

X509_check_ip() comprueba si el certificado coincide con una dirección IPv4 o IPv6 especificada. La matriz address está en formato binario, en orden de bytes de red. La longitud es 4 (IPv4) o 16 (IPv6). Solo se consideran las direcciones marcadas explícitamente en los certificados; se ignoran las direcciones IP almacenadas en nombres DNS y Nombres Comunes.

X509_check_ip_asc() es similar, excepto que la cadena terminada en NUL address se convierte primero a la representación interna.

El argumento flags suele ser 0, pero puede ser el OR bit a bit de las siguientes banderas.

La bandera X509_CHECK_FLAG_ALWAYS_CHECK_SUBJECT hace que la función considere el DN del sujeto incluso si el certificado contiene al menos un nombre alternativo del sujeto del tipo correcto (nombre DNS o dirección de correo electrónico según corresponda); por defecto, se ignora el DN del sujeto cuando hay presentes nombres alternativos del sujeto correspondientes.

Las banderas restantes solo son significativas para X509_check_host().

La bandera X509_CHECK_FLAG_NO_WILDCARDS deshabilita la expansión de comodines.

La bandera X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS suprime la compatibilidad con "*" como patrón comodín en etiquetas que tienen un prefijo o sufijo, como "www*" o "*www".

La bandera X509_CHECK_FLAG_MULTI_LABEL_WILDCARDS permite que un "*" que constituya la etiqueta completa de un nombre DNS (por ejemplo, "*.example.com") coincida con más de una etiqueta en name.

La bandera X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAINS restringe los valores de name que comienzan con ".", que de lo contrario coincidirían con cualquier subdominio en el certificado del par, para que solo coincidan con subdominios hijos directos. Por lo tanto, por ejemplo, con esta bandera activada, un name de ".example.com" coincidiría con un certificado de par con un nombre DNS de "www.example.com", pero no coincidiría con un certificado de par con un nombre DNS de "www.sub.example.com".

VALORES DE RETORNO

Las funciones devuelven 1 para una coincidencia exitosa, 0 para una coincidencia fallida y -1 para un error interno: típicamente un fallo de asignación de memoria o un error de decodificación ASN.1.

Todas las funciones también pueden devolver -2 si la entrada está mal formada. Por ejemplo, X509_check_host() devuelve -2 si el name proporcionado contiene bytes NUL incrustados.

X509_check_host - Verifies that an X509 certificate's subject name matches a given hostname

SYNOPSIS

#include <openssl/x509.h>

int X509_check_host(X509 *x509, const char *name, size_t namelen, unsigned int flags, X509_CHECK_HOST *check_context);

DESCRIPTION

The X509_check_host() function checks whether the given hostname name matches the subject name in the certificate x509. The matching logic follows RFC 2818, Section 3.1, with an exception for wildcard characters. The wildcard character '*' is allowed to match only one subdomain component. For example, "*.example.com" matches "sub.example.com" but not "sub.sub.example.com".

The namelen parameter specifies the length of the hostname. If namelen is zero, then strlen(name) is used.

The flags parameter can be used to modify the behavior of the function. The following flags are supported:

  • X509_CHECK_FLAG_NO_SUBJECT_ALT_NAME: If this flag is set, the function will not check the Subject Alternative Name extension of the certificate.
  • X509_CHECK_FLAG_NO_WILDCARDS: If this flag is set, wildcard characters in the hostname will not be matched.
  • X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAIN: If this flag is set, the wildcard character '*' is allowed to match only one subdomain component. For example, "*.example.com" matches "sub.example.com" but not "sub.sub.example.com". This is the default behavior.
  • X509_CHECK_FLAG_NEVER_DIVERGE: If this flag is set, then a certificate with a wildcard in the CN matching the hostname is considered a match even if there is an SAN entry present.

The check_context parameter is an optional pointer to an X509_CHECK_HOST structure that can be used to store additional context information during the check. If check_context is NULL, no context is stored.

RETURN VALUES

X509_check_host() returns 1 if the hostname matches the certificate's subject name, and 0 otherwise.
