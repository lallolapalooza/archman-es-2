libcurl-ws(3) Manual de funciones de biblioteca libcurl-ws(3)

NOMBRE

libcurl-ws - Resumen de la interfaz WebSocket

DESCRIPCIÓN

La interfaz WebSocket proporciona funciones para recibir y enviar datos de WebSocket.

INCLUIR

Todavía solo incluye <curl/curl.h> en su código.

CONFIGURACIÓN

WebSocket también se conoce a menudo como WebSockets, en plural. Se realiza actualizando una solicitud GET HTTP(S) normal a una conexión WebSocket.

WebSocket es un protocolo de comunicación basado en mensajes, similar a TCP, realizado a través de HTTP, especificado en RFC 6455.

Para iniciar una sesión WebSocket con libcurl, configure un manejador easy para usar una URL con un esquema "WS://" o "WSS://". "WS" es para comunicación en texto plano sobre HTTP y "WSS" es para hacer WebSocket de forma segura sobre HTTPS.

Una solicitud WebSocket se realiza como una solicitud HTTP/1 GET con un campo de encabezado de solicitud "Upgrade WebSocket". Cuando la actualización es aceptada por el servidor, responde con un 101 Switching y luego el cliente puede comunicarse en WebSocket con el servidor. La comunicación puede ocurrir en ambas direcciones al mismo tiempo.

EXTENSIONES

El protocolo WebSocket permite al cliente solicitar y negociar extensiones que pueden agregar funcionalidades y restricciones adicionales al protocolo.

libcurl no admite el uso de extensiones y siempre configura una conexión sin ellas.

MENSAJES

La comunicación WebSocket se basa en mensajes. Esto significa que ambos extremos envían y reciben mensajes completos, no flujos como TCP. Un mensaje WebSocket se envía a través de la red en uno o más frames. Un mensaje que se divide en varios frames se denomina mensaje *fragmentado* y los frames individuales se denominan *fragmentos*. Cada frame (o fragmento) en un mensaje puede tener un tamaño de hasta 2^63 bytes y declara el tamaño del frame en la cabecera. El tamaño total de un mensaje que se fragmenta en múltiples frames no está limitado por el protocolo y el número de fragmentos no se conoce hasta que se recibe el último fragmento.

La transmisión de un frame no debe ser interrumpida por ninguna otra transferencia de datos y la transmisión de los diferentes fragmentos de un mensaje no debe ser interrumpida por otros frames de datos de usuario. Los frames de control - PING, PONG y CLOSE - pueden transmitirse entre dos frames cualesquiera, incluso entre dos fragmentos del mismo mensaje de datos de usuario. Por otro lado, los frames de control en sí mismos nunca deben ser fragmentados y están limitados a un tamaño de 125 bytes.

libcurl entrega datos WebSocket en fragmentos de frames. Podría entregar un frame completo como un solo fragmento, pero también podría entregarlo en varias piezas dependiendo del tamaño y los patrones de red. Consulte las documentaciones individuales de la API para obtener más información.

PING

WebSocket está diseñado para permitir sesiones de larga duración y, para mantener las conexiones activas, ambos extremos pueden enviar mensajes PING para que el otro extremo responda con un PONG. Ambos extremos también pueden enviar mensajes PONG no solicitados como latido unidireccional.

libcurl responde automáticamente a los mensajes PING del servidor con un PONG que repite la carga útil del mensaje PING. libcurl no envía mensajes PING ni mensajes PONG no solicitados automáticamente. La respuesta automática a los mensajes PING se puede deshabilitar a través de CURLOPT_WS_OPTIONS(3).

MODELOS

Debido a las muchas formas diferentes en que se puede usar WebSocket, que es mucho más flexible que limitarse a descargas o cargas simples, libcurl ofrece dos modelos de API diferentes para usarlo:

1. Modelo CURLOPT_WRITEFUNCTION/CURLOPT_READFUNCTION: Usar una función de devolución de llamada de escritura con CURLOPT_WRITEFUNCTION(3) de forma similar a otras descargas para cuando el tráfico está orientado a la descarga.

Usar una función de devolución de llamada de lectura con CURLOPT_READFUNCTION(3) de forma similar a otras cargas para enviar frames WebSocket al servidor.

2. Modelo CURLOPT_CONNECT_ONLY: Usar las funciones curl_ws_recv(3) y curl_ws_send(3).

MODELO CURLOPT_WRITEFUNCTION/CURLOPT_READFUNCTION
CURLOPT_CONNECT_ONLY(3) debe estar desactivado o ser 0L para que este modelo surta efecto.

curl_easy_perform(3) establece y configura la comunicación WebSocket y luego se bloquea durante toda la duración de la conexión. libcurl llama a la función de devolución de llamada configurada en CURLOPT_WRITEFUNCTION(3), siempre que se reciba un fragmento entrante de datos WebSocket. La función de devolución de llamada recibe un puntero a los datos de carga útil como argumento y puede llamar a curl_ws_meta(3) para obtener metadatos relevantes.

Con libcurl 8.16.0 o posterior, se admite el envío de frames WebSocket a través de una CURLOPT_READFUNCTION(3). Para usar eso en dicha conexión, registre una función de devolución de llamada a través de CURLOPT_READFUNCTION(3) y establezca también CURLOPT_UPLOAD(3). Una vez establecida la conexión WebSocket, se invoca su función de devolución de llamada para obtener datos para enviar. Esos datos se envían en un frame *CURLWS_BINARY* con una longitud igual exactamente a los datos devueltos.

Para enviar otros tipos de frames o frames más largos, use curl_ws_start_frame(3) en la función de devolución de llamada de lectura. Consulte el ejemplo *websocket-updown*.

Al usar curl_multi_perform(3) para dirigir las transferencias, existen más posibilidades. La CURLOPT_READFUNCTION(3) puede devolver *CURL_READFUNC_PAUSE* cuando no tiene más datos para enviar. Llamar a curl_easy_pause(3) después reanuda la carga y se vuelve a invocar la función de devolución de llamada de lectura.

MODELO CURLOPT_CONNECT_ONLY
CURLOPT_CONNECT_ONLY(3) debe ser 2L para que este modelo surta efecto.

curl_easy_perform(3) solo establece y configura la comunicación WebSocket y luego devuelve el control a la aplicación. La aplicación puede usar entonces curl_ws_recv(3) y curl_ws_send(3) para intercambiar mensajes WebSocket con el servidor.

MODO RAW

Se puede indicar a libcurl que hable WebSocket en "modo raw" estableciendo el bit CURLWS_RAW_MODE de la opción CURLOPT_WS_OPTIONS(3).

WebSocket en modo raw significa que libcurl pasa los datos de la red sin analizarlos, dejando eso completamente a la aplicación.

Este modo está destinado a aplicaciones que ya tienen un analizador/motor WebSocket y desean cambiarse a usar libcurl para habilitar WebSocket, y mantener partes de la arquitectura de software existente.
