SSL_ACCEPT(3) Manual de Funciones de Librería SSL_ACCEPT(3)

NOMBRE

SSL_accept — esperar a que un cliente TLS/SSL inicie un handshake TLS/SSL

SINOPSIS

librería “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_accept(SSL *ssl);

DESCRIPCIÓN

SSL_accept() espera a que un cliente TLS/SSL inicie el handshake TLS/SSL. El canal de comunicación ya debe haber sido establecido y asignado al objeto ssl mediante la configuración de un BIO subyacente.

El comportamiento de SSL_accept() depende del BIO subyacente.

Si el BIO subyacente es bloqueante, SSL_accept() solo regresará una vez que el handshake se haya completado o haya ocurrido un error.

Si el BIO subyacente es no bloqueante, SSL_accept() también regresará cuando el BIO subyacente no pudo satisfacer las necesidades de SSL_accept() para continuar el handshake, indicando el problema con el valor de retorno −1. En este caso, una llamada a SSL_get_error(3) con el valor de retorno de SSL_accept() arrojará SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE. El proceso llamador debe entonces repetir la llamada después de tomar las acciones apropiadas para satisfacer las necesidades de SSL_accept(). La acción depende del BIO subyacente. Al usar un socket no bloqueante, no hay nada que hacer, pero select(2) puede ser utilizado para verificar la condición requerida. Al usar un BIO de almacenamiento en búfer, como un par de BIO, los datos deben ser escritos o recuperados del BIO antes de poder continuar.

VALORES DE RETORNO

Los siguientes valores de retorno pueden ocurrir:

0
El handshake TLS/SSL no fue exitoso pero fue cerrado de forma controlada y de acuerdo con las especificaciones del protocolo TLS/SSL. Llame a SSL_get_error(3) con el valor de retorno ret para averiguar el motivo.
1
El handshake TLS/SSL se completó exitosamente y se estableció una conexión TLS/SSL.
<0
El handshake TLS/SSL no fue exitoso debido a un error fatal ocurrido a nivel de protocolo o a un fallo de conexión. El cierre no fue limpio. También puede ocurrir si se necesita una acción para continuar la operación para BIOs no bloqueantes. Llame a SSL_get_error(3) con el valor de retorno ret para averiguar el motivo.
