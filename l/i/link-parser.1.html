LINK-PARSER(1) Manual de comandos generales LINK-PARSER(1)

NOMBRE

link-parser - analizar oraciones en lenguaje natural usando Link Grammar

SINOPSIS

link-parser --help
link-parser --version 

link-parser [idioma|ubicación_dict] [--quiet] [-<comando_especial_"!">_comando>...]

DESCRIPCIÓN

link-parser es el envoltorio de línea de comandos para la biblioteca de análisis de lenguaje natural link-grammar. Esta biblioteca analizará oraciones escritas en inglés, ruso y otros idiomas, generando árboles de enlace que muestran las relaciones entre el sujeto, el verbo y varios adjetivos, adverbios, etc. en la oración.

EJEMPLO

link-parser

Inicia el shell interactivo del analizador. Ingrese cualquier oración para analizar:

linkparser> Reading a man page is informative.
Found 18 linkages (18 had no P.P. violations)
        Linkage 1, cost vector = (UNUSED=0 DIS= 0.00 LEN=16)
    +------------------------Xp------------------------+
    +--------------->WV-------------->+                |
    |         +----------Ss*g---------+                |
    |         +--------Os-------+     |                |
    |         |     +---Ds**x---+     |                |
    +--->Wd---+     +-PHc+---A--+     +---Pa---+       |
    |         |     |    |      |     |        |       |
LEFT-WALL reading.g a man.ij page.n is.v informative.a .

ANTECEDENTES

La herramienta de línea de comandos link-parser es útil para la exploración y el uso general, aunque se presume que, para el análisis de grandes cantidades de texto, los desarrolladores crearán una aplicación personalizada, utilizando la biblioteca link-grammar. Varias de estas aplicaciones se describen en la página web de Link Grammar (ver ver también más abajo).

La teoría de Link Grammar se explica en muchos artículos académicos. En el primero de ellos, Daniel Sleator y Davy Temperley, "Parsing English with a Link Grammar" (1991), los autores definieron un nuevo sistema gramatical formal llamado "link grammar". Una secuencia de palabras está en el lenguaje de una gramática de enlaces si hay una forma de dibujar "enlaces" entre las palabras de tal manera que se cumplan los requisitos locales de cada palabra, los enlaces no se crucen y las palabras formen un grafo conectado consistente. Los autores codificaron la gramática inglesa en tal sistema y escribieron link-parser para analizar inglés usando esta gramática.

El motor que realiza el análisis está separado de los diccionarios que describen un idioma. Actualmente, los diccionarios más completos y completos son para los idiomas inglés y ruso, aunque existen diccionarios experimentales e incompletos para alemán y otros ocho idiomas.

VISIÓN GENERAL

link-parser, cuando se invoca manualmente, inicia un shell interactivo, tomando el control de la terminal. Cualquier línea que comience con un signo de exclamación se considera un "comando especial"; estos se describen a continuación. El comando !help proporcionará más información; el comando !variables imprimirá todos los comandos especiales. Estos también se llaman "variables", ya que casi todos los comandos tienen un valor asociado con ellos: el comando típicamente habilita o deshabilita alguna función, o altera alguna configuración multivaluada.

Toda la demás entrada se trata como una única oración en inglés; se analiza y se imprime el resultado del análisis. Las variables controlan lo que se imprime: por defecto, se imprime un enlace gráfico ASCII, aunque también es posible la salida post-script. La impresión del árbol de constituyentes también se puede habilitar. Otros controles de salida incluyen la impresión de disyuntos y datos de enlace completos.

Para analizar oraciones, link-parser depende de un diccionario de link-grammar. Este contiene listas de palabras y metadatos asociados sobre sus propiedades gramaticales. Se proporciona un diccionario de inglés por defecto. Si otros diccionarios de idiomas están instalados en las ubicaciones de búsqueda predeterminadas, estos pueden especificarse explícitamente por medio de un código de idioma ISO de 2 letras: por ejemplo:

link-parser de

iniciará el shell del analizador con el diccionario alemán.

Alternativamente, la ubicación del diccionario puede especificarse explícitamente con una ruta de archivo absoluta o relativa; por ejemplo:

link-parser /usr/share/link-grammar/en

ejecutará link-parser usando el diccionario inglés ubicado en el directorio de instalación típico.

link-parser también se puede usar en modo no interactivo ("modo batch") a través de la opción -batch (un comando especial, ver más abajo): por ejemplo:

cat thesis.txt | link-parser -batch

leerá líneas del archivo thesis.txt, procesando cada una como una oración completa. Para las oraciones que no tienen un análisis completo, imprimirá
+++++ error N
(N es un número) en la salida estándar.

Alternativamente, se puede especificar un archivo de entrada con el comando especial !file nombre_archivo, descrito a continuación.

Tenga en cuenta que el uso del "modo batch" deshabilita la impresión habitual de enlaces gráficos ASCII. Las oraciones de entrada tampoco aparecen por defecto en stdout. Estas características pueden ser reactivadas mediante comandos especiales; los comandos especiales pueden intercalarse con la entrada.

En lugar de especificar -batch en la línea de comandos, se puede especificar !batch en dicho archivo de entrada.

Para más detalles, use !help batch en el shell interactivo de link-parser.

OPCIONES

--help
Imprime el uso y sale.
--version
Imprime la versión del programa y los detalles de configuración, y sale.
--quiet
Suprime los mensajes de versión al inicio.

Comandos especiales !

Los comandos especiales "!" pueden especificarse como opciones de línea de comandos, o dentro del propio shell interactivo prefijándolos con "!" al inicio de la línea. No es necesario usar el nombre completo de la opción; solo se deben especificar suficientes letras para hacer que la opción sea única.

Al especificar como opción de línea de comandos, un comando especial va precedido por "-" en lugar de "!".

Las variables booleanas se pueden alternar simplemente dando !nombre_variable, por ejemplo, !batch. El establecimiento de otras variables requiere el uso de un signo igual: !nombre_variable=valor, por ejemplo, !width=100.

El comando !help imprime ayuda general. Cuando se emite desde el shell interactivo, puede recibir un argumento, generalmente un comando especial. El comando !variables imprime todas las configuraciones de variables actuales. El comando !file lee la entrada del archivo de su argumento. El comando !file no es una variable; no se puede establecer. Se puede usar repetidamente.

El comando !exit indica a link-parser que salga.

El signo de exclamación "!" es también un comando especial en sí mismo, utilizado para inspeccionar la entrada del diccionario para cualquier palabra dada (opcionalmente terminada por un subíndice). Por lo tanto, se necesitan dos signos de exclamación antes de dicha palabra al hacerlo desde el shell interactivo. El carácter comodín "*" puede especificarse como el último carácter de la palabra para encontrar múltiples coincidencias.

Los valores predeterminados de los comandos especiales a continuación se muestran entre paréntesis. La mayoría de ellos son los predeterminados de la biblioteca link-grammar.
Los valores booleanos predeterminados se muestran como encendido (1) o apagado (0).

FILES

The following files are per-language, when LL is the 2-letter ISO language code.

LL/4.0.dict
The Link Grammar dictionary.
LL/4.0.affix
Values of entities used in tokenization.
LL/4.0.regex
Regular expressions (see regex(7)) that are used to match tokens not found in the dictionary.
LL/4.0.dialect
Dialect component definitions.
LL/4.0.knowledge
Post-processing definitions.
LL/4.0.constituent-knowledge
Definitions for producing a constituent tree.
command-help-LL.txt or command-help-LL-CC.txt
Help text for the !help topic special "!" command. If several such files are provided, the desired one can be selected by e.g. the LANGUAGE environment variable if it is set to LL or LL-CC (default is en). Currently only command-help-en.txt is provided.
The directory search order for these files is:
  • ./
  • data/
  • ../
  • ../data/
  • A custom data directory, as set by the API call dictionary_set_data_dir().
  • Installation-depended system data directory (*)

    * This location is displayed as DICTIONARY_DIR when the --version argument is provided to link-parser on the command line. On windows it may be relative to the location of the link-grammar library DLL; in that case the actual location is displayed as "System data directory" when link-parser is invoked with -verbosity=4.

SEE ALSO

The link-generator command can be used to generate random sentences from a given dictionary.

Information on the link-grammar shared-library API and the link types used in the parse is available at the Link Grammar website.

Peer-reviewed papers explaining Link Grammar can be found at original CMU site.

The source code of link-parser and the link-grammar library is located at GitHub.

The mailing list for Link Grammar discussion is at link-grammar Google group.
