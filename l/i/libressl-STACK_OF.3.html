STACK_OF(3) Manual de funciones de biblioteca STACK_OF(3)

NOMBRE

STACK_OF — arreglos de tamaño variable de punteros, llamados pilas de OpenSSL

SINOPSIS

biblioteca “libcrypto”
#include <openssl/safestack.h>

STACK_OF(tipo);

DESCRIPCIÓN

La cabecera <openssl/safestack.h> proporciona un sistema frágil e inusualmente complicado de envoltorios generados por macros alrededor de las funciones descritas en la página del manual OPENSSL_sk_new(3). Está destinado a implementar arreglos de tamaño variable de punteros, superficialmente seguros en cuanto a tipos, y que OpenSSL denomina engañosamente "pilas". Debido al exceso de funciones de la API, es imposible documentar adecuadamente este sistema. En particular, llamar a man(1) para cualquiera de las funciones que operan sobre pilas no puede producir ningún resultado.

Desafortunadamente, los programas de aplicación apenas pueden evitar utilizar el concepto porque varias API importantes de OpenSSL dependen de él; véase la sección VEASE TAMBIÉN para ver ejemplos. A pesar de que ambas páginas son más complicadas de lo que debería ser cualquier página del manual, usar el concepto de forma segura requiere una comprensión completa de todos los detalles de esta página del manual y de OPENSSL_sk_new(3).

El macro STACK_OF() toma un nombre de tipo como argumento, típicamente el nombre de un tipo que ha sido definido como un alias para un tipo struct específico usando una declaración typedef. Se expande a un tipo struct incompleto que está destinado a representar una "pila" de objetos del tipo dado. Ese tipo en realidad no existe, por lo que no es posible definir, por ejemplo, una variable automática ‘STACK_OF(X509) my_certificates’; solo es posible definir punteros a pilas, por ejemplo ‘STACK_OF(X509) *my_certificates’. La única forma en que tales punteros pueden ser utilizados es mediante funciones envoltorio que los convierten al tipo _STACK * descrito en OPENSSL_sk_new(3).

Para una cantidad considerable de tipos, OpenSSL proporciona una función envoltorio para cada función descrita en OPENSSL_sk_new(3). Los nombres de estas funciones envoltorio generalmente se construyen insertando el nombre del tipo y un guion bajo después del prefijo 'sk_' del nombre de la función. Por lo general, donde las funciones reales toman argumentos void *, los envoltorios toman punteros al tipo en cuestión, y donde las funciones reales toman argumentos _STACK *, los envoltorios toman punteros a STACK_OF(tipo). Lo mismo se aplica a los valores de retorno. Existen varias excepciones a todo esto, pero lo anterior se aplica a todos los tipos enumerados a continuación.

Usar lo anterior puede tener sentido para los siguientes tipos porque existen funciones de API pública que toman pilas de estos tipos como argumentos o las devuelven: ASN1_INTEGER, ASN1_OBJECT, ASN1_UTF8STRING, CMS_RecipientInfo, CMS_SignerInfo, CONF_VALUE, GENERAL_NAMES, GENERAL_SUBTREE, OPENSSL_STRING (que es solo char *), PKCS12_SAFEBAG, PKCS7, PKCS7_RECIP_INFO, PKCS7_SIGNER_INFO, POLICYQUALINFO, SRTP_PROTECTION_PROFILE, SSL_CIPHER, SSL_COMP, X509, X509_ALGOR, X509_ATTRIBUTE, X509_CRL, X509_EXTENSION, X509_INFO, X509_NAME, X509_OBJECT, X509_POLICY_NODE, X509_REVOKED.

Además, algunas funciones de API pública utilizan los siguientes tipos que se declaran con typedef:

STACK_OF(ACCESS_DESCRIPTION) AUTHORITY_INFO_ACCESS
STACK_OF(ASN1_OBJECT) EXTENDED_KEY_USAGE
STACK_OF(ASN1_TYPE) ASN1_SEQUENCE_ANY
STACK_OF(DIST_POINT) CRL_DIST_POINTS
STACK_OF(GENERAL_NAME) GENERAL_NAMES
STACK_OF(IPAddressFamily) IPAddrBlocks
STACK_OF(POLICY_MAPPING) POLICY_MAPPINGS
STACK_OF(POLICYINFO) CERTIFICATEPOLICIES
STACK_OF(X509_ALGOR) X509_ALGORS
STACK_OF(X509_EXTENSION) X509_EXTENSIONS

Aunque las cabeceras de OpenSSL declaran funciones envoltorio para muchos más tipos e incluso aunque la documentación de OpenSSL dice que los usuarios pueden declarar sus propios tipos de pila, usar STACK_OF() con cualquier tipo no listado aquí está fuertemente desaconsejado. Para otros tipos, puede haber diferencias sutiles y no documentadas en sintaxis y semántica, y intentar declarar tipos de pila personalizados es muy propenso a errores; usar arreglos simples de C de punteros al tipo deseado es mucho más sencillo y menos peligroso.

EJEMPLOS

El siguiente programa crea un objeto certificado, coloca dos punteros a él en una pila y utiliza X509_free(3) para limpiar correctamente:

#include <err.h>
#include <stdio.h>
#include <openssl/x509.h>

int
main(void)
{
	STACK_OF(X509)	*stack;
	X509		*x;

	if ((stack = sk_X509_new_null()) == NULL)
		err(1, NULL);
	if ((x = X509_new()) == NULL)
		err(1, NULL);
	if (sk_X509_push(stack, x) == 0)
		err(1, NULL);
	if (X509_up_ref(x) == 0)
		errx(1, "X509_up_ref failed");
	if (sk_X509_push(stack, x) == 0)
		err(1, NULL);
	printf("%d pointers: %p, %p\n", sk_X509_num(stack),
	    sk_X509_value(stack, 0), sk_X509_value(stack, 1));
	sk_X509_pop_free(stack, X509_free);

	return 0;
}

La salida se parece a:

2 punteros: 0x4693ff24c00, 0x4693ff24c00
