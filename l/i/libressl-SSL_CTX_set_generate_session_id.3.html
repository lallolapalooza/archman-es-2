NOMBRE

SSL_CTX_set_generate_session_id, SSL_set_generate_session_id, SSL_has_matching_session_id, GEN_SESSION_CB — manipular la generación de IDs de sesión SSL (solo servidor)

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

typedef int
(*GEN_SESSION_CB)(const SSL *ssl, unsigned char *id, unsigned int *id_len);

int
SSL_CTX_set_generate_session_id(SSL_CTX *ctx, GEN_SESSION_CB cb);

int
SSL_set_generate_session_id(SSL *ssl, GEN_SESSION_CB cb);

int
SSL_has_matching_session_id(const SSL *ssl, const unsigned char *id, unsigned int id_len);

DESCRIPCIÓN

SSL_CTX_set_generate_session_id() establece la función de callback para generar nuevos IDs de sesión para sesiones SSL/TLS para ctx a cb.

SSL_set_generate_session_id() establece la función de callback para generar nuevos IDs de sesión para sesiones SSL/TLS para ssl a cb.

SSL_has_matching_session_id() comprueba si una sesión con el ID id (de longitud id_len) ya está contenida en la caché de sesiones interna del contexto padre de ssl.

Cuando se establece una nueva sesión entre cliente y servidor, el servidor genera un ID de sesión. El ID de sesión es una secuencia arbitraria de bytes. La longitud del ID de sesión está entre 1 y 32 bytes. El ID de sesión no es crítico para la seguridad, pero debe ser único para el servidor. Además, el ID de sesión se transmite en claro al reutilizar la sesión, por lo que no debe contener información sensible.

Sin una función de callback configurada, un servidor OpenSSL generará un ID de sesión único a partir de números pseudoaleatorios de la longitud máxima posible. Usando la función de callback, el ID de sesión se puede cambiar para contener información adicional como, por ejemplo, un ID de host para mejorar el balanceo de carga o técnicas de caché externas.

La función de callback recibe un puntero a la ubicación de memoria donde poner id y un puntero a la longitud máxima permitida id_len. El búfer en la ubicación id solo se garantiza que tenga el tamaño de id_len. La función de callback solo tiene permitido generar un ID más corto y reducir id_len; la función de callback nunca debe aumentar id_len ni escribir en la ubicación id superando el límite dado.

La ubicación id se rellena con 0x00 antes de que se llame a la función de callback, por lo que la función de callback solo puede rellenar parte de la longitud posible y dejar id_len intacto manteniendo la reproducibilidad.

Dado que las sesiones deben distinguirse, los IDs de sesión deben ser únicos. Sin la función de callback, se utiliza un número aleatorio, por lo que la probabilidad de generar el mismo ID de sesión es extremadamente pequeña (2^256 para TLSv1). Para garantizar la unicidad del ID de sesión generado, la función de callback debe llamar a SSL_has_matching_session_id() y generar otro ID si ocurre un conflicto. Si no se resuelve un conflicto de ID, la negociación fallará. Si la aplicación codifica, por ejemplo, un ID de host único, un número de proceso único y un número de secuencia único en el ID de sesión, la unicidad se podría lograr fácilmente sin añadir aleatoriedad (sin embargo, se debe tener cuidado de no filtrar información confidencial de esta manera). Si la aplicación no puede garantizar la unicidad, se recomienda utilizar la longitud máxima id_len y rellenar los bytes no utilizados para codificar información especial con datos aleatorios para evitar colisiones.

SSL_has_matching_session_id() solo consultará la caché de sesiones interna, no la externa. Dado que el ID de sesión se genera antes de que se complete la negociación, no se añade inmediatamente a la caché. Si otro hilo está utilizando la misma caché de sesiones interna, puede ocurrir una condición de carrera en la que otro hilo genere el mismo ID de sesión. También pueden ocurrir colisiones al utilizar una caché de sesiones externa, ya que la caché externa no se prueba con SSL_has_matching_session_id() y se aplica la misma condición de carrera.

La función de callback debe devolver 0 si no puede generar un ID de sesión por cualquier motivo y devolver 1 en caso de éxito.

VALORES DE RETORNO

SSL_CTX_set_generate_session_id() y SSL_set_generate_session_id() siempre devuelven 1.

SSL_has_matching_session_id() devuelve 1 si otra sesión con el mismo ID ya está en la caché.

EJEMPLOS

La función de callback que se muestra generará un ID de sesión con el ID de servidor dado y rellenará el resto con bytes pseudoaleatorios:

const char session_id_prefix = "www-18";

#define MAX_SESSION_ID_ATTEMPTS 10
static int
generate_session_id(const SSL *ssl, unsigned char *id,
    unsigned int *id_len)
{
	unsigned int count = 0;

	do {
		RAND_pseudo_bytes(id, *id_len);
		/*
		 * Prefija el session_id con el prefijo requerido. Nota: Si
		 * nuestro prefijo es demasiado largo, recórtalo — pero
		 * habrá efectos peores de todos modos, por ejemplo, el servidor
		 * solo podría crear un ID de sesión (¡el prefijo!) así que todas
		 * las negociaciones de sesión futuras fallarán debido a conflictos.
		 */
		memcpy(id, session_id_prefix,
		    (strlen(session_id_prefix) < *id_len) ?
		    strlen(session_id_prefix) : *id_len);
	} while (SSL_has_matching_session_id(ssl, id, *id_len) &&
	    (++count < MAX_SESSION_ID_ATTEMPTS));

	if (count >= MAX_SESSION_ID_ATTEMPTS)
		return 0;
	return 1;
}

NAME

SSL_CTX_set_generate_session_id, SSL_CTX_set_session_id_context - set session ID context

SYNOPSIS

#include <openssl/ssl.h>

int SSL_CTX_set_generate_session_id(SSL_CTX *ctx, SSL_CTX_generate_session_id_cb *callback);

int SSL_CTX_set_session_id_context(SSL_CTX *ctx, const unsigned char *sid_ctx, unsigned int sid_ctx_len);

DESCRIPTION

SSL_CTX_set_generate_session_id() sets a callback function to be used to generate a session ID.

SSL_CTX_set_session_id_context() is used to set a context string for the session IDs.

When a new session is created, it is associated with a session ID context. This context is a byte string of a specified length. It is intended to be used to prevent session resumption attacks. For example, if the server is running multiple virtual hosts, it can use the virtual host name as the context string. This way, a session established for one virtual host cannot be resumed for another virtual host.

The session ID context is copied from the application to the SSL structure. It is then used by the session ID generation callback.

The maximum length of the session ID context is defined by SSL_MAX_SSL_SESSION_ID_LENGTH.

The callback function callback will be called when a new session ID needs to be generated. The callback should fill the buffer pointed to by id with the new session ID. The length of the session ID should be len. The callback should return 1 on success and 0 on failure.

RETURN VALUES

SSL_CTX_set_generate_session_id() and SSL_CTX_set_session_id_context() return 1 on success, and 0 on failure.

EXAMPLES

/* Set a session ID context */
unsigned char sid_ctx[16];
if (SSL_CTX_set_session_id_context(ctx, sid_ctx, sizeof(sid_ctx)) <= 0) {
    /* handle error */
}
