INTRODUCCIÓN

Tcl incluye una biblioteca de procedimientos Tcl para funciones de uso común. Los procedimientos definidos en la biblioteca Tcl son genéricos y adecuados para su uso por diferentes aplicaciones. La ubicación de la biblioteca Tcl se devuelve con el comando info library. Además de la biblioteca Tcl, cada aplicación normalmente tendrá su propia biblioteca de procedimientos de soporte; la ubicación de esta biblioteca normalmente se indica mediante el valor de la variable global $app_library, donde app es el nombre de la aplicación. Por ejemplo, la ubicación de la biblioteca Tk se guarda en la variable tk_library.

Para acceder a los procedimientos de la biblioteca Tcl, una aplicación debe 'source' el archivo init.tcl en la biblioteca, por ejemplo con el comando Tcl

source [file join [info library] init.tcl]

Si el procedimiento de la biblioteca Tcl_Init se invoca desde el procedimiento Tcl_AppInit de una aplicación, esto ocurre automáticamente. El código en init.tcl definirá el procedimiento unknown y organizará que los otros procedimientos se carguen bajo demanda utilizando el mecanismo de carga automática definido a continuación.

PROCEDIMIENTOS DE COMANDO

La biblioteca Tcl proporciona los siguientes procedimientos:

auto_execok cmd
Determina si existe un archivo ejecutable o una utilidad integrada del shell con el nombre cmd. Si es así, devuelve una lista de argumentos para pasar a exec para ejecutar el archivo ejecutable o la utilidad integrada del shell denominada cmd. Si no, devuelve una cadena vacía. Este comando examina los directorios en la ruta de búsqueda actual (proporcionada por la variable de entorno PATH) en su búsqueda de un archivo ejecutable llamado cmd. En plataformas Windows, la búsqueda se expande con los mismos directorios y extensiones de archivo que se utilizan por exec. Auto_execok recuerda información sobre búsquedas anteriores en una matriz llamada auto_execs; esto evita la búsqueda de ruta en llamadas futuras para el mismo cmd. El comando auto_reset puede usarse para forzar a auto_execok a olvidar su información en caché.
auto_import patrón
Auto_import se invoca durante namespace import para ver si los comandos importados especificados por patrón residen en una biblioteca de carga automática. Si es así, los comandos se cargan para que estén disponibles para el intérprete para crear los enlaces de importación. Si los comandos no residen en una biblioteca de carga automática, auto_import no hace nada. La coincidencia de patrones se realiza de acuerdo con las reglas de coincidencia de namespace import.
auto_load cmd
Este comando intenta cargar la definición de un comando Tcl llamado cmd. Para hacer esto, busca en una ruta de carga automática, que es una lista de uno o más directorios. La ruta de carga automática se proporciona mediante la variable global auto_path si existe. Si no existe la variable auto_path, entonces se usa la variable de entorno TCLLIBPATH, si existe. De lo contrario, la ruta de carga automática consiste solo en el directorio de la biblioteca Tcl. Dentro de cada directorio en la ruta de carga automática debe haber un archivo tclIndex que describe uno o más comandos definidos en ese directorio y un script para evaluar para cargar cada uno de los comandos. El archivo tclIndex debe ser generado con el comando auto_mkindex. Si se encuentra cmd en un archivo de índice, se evalúa el script apropiado para crear el comando. El comando auto_load devuelve 1 si cmd se creó exitosamente. El comando devuelve 0 si no había ninguna entrada de índice para cmd o si el script no definió realmente cmd (por ejemplo, debido a que la información del índice está desactualizada). Si ocurre un error al procesar el script, ese error se devuelve. Auto_load solo lee la información del índice una vez y la guarda en la matriz auto_index; las llamadas futuras a auto_load buscan cmd en la matriz en lugar de volver a leer los archivos de índice. La información del índice en caché puede eliminarse con el comando auto_reset. Esto forzará al próximo comando auto_load a recargar la base de datos de índices desde el disco.
auto_mkindex dir patrón patrón ...
Genera un índice adecuado para su uso por auto_load. El comando busca en dir todos los archivos cuyos nombres coinciden con cualquiera de los argumentos de patrón (la coincidencia se realiza con el comando glob), genera un índice de todos los procedimientos de comandos Tcl definidos en todos los archivos coincidentes y almacena la información del índice en un archivo llamado tclIndex en dir. Si no se proporciona ningún patrón, se asumirá el patrón *.tcl. Por ejemplo, el comando
auto_mkindex foo *.tcl

leerá todos los archivos .tcl en el subdirectorio foo y generará un nuevo archivo de índice foo/tclIndex.

Auto_mkindex analiza los scripts Tcl evaluándolos en un intérprete hijo y monitoreando los comandos proc y namespace que se ejecutan. Las extensiones pueden usar el paquete (no documentado) auto_mkindex_parser para registrar otros comandos que pueden contribuir al índice de carga automática. Tendrás que leer auto.tcl para ver cómo funciona esto.

Auto_mkindex_old (que tiene la misma sintaxis que auto_mkindex) analiza los scripts Tcl de una manera relativamente poco sofisticada: si alguna línea contiene la palabra “proc” como sus primeros caracteres, entonces se asume que es una definición de procedimiento y la siguiente palabra de la línea se toma como el nombre del procedimiento. Las definiciones de procedimientos que no aparecen de esta manera (por ejemplo, tienen espacios antes de proc) no se indexarán. Si tu script contiene código “peligroso”, como código de inicialización global o nombres de procedimientos con caracteres especiales como $, *, [ o ], es más seguro usar auto_mkindex_old.

auto_reset
Destruye toda la información almacenada en caché por auto_execok y auto_load. Esta información se volverá a leer del disco la próxima vez que se necesite. Auto_reset también elimina cualquier procedimiento listado en el índice de carga automática, para que se carguen copias nuevas de ellos la próxima vez que se utilicen.
auto_qualify comando namespace
Calcula una lista de nombres completamente calificados para comando. Esta lista refleja la ruta que sigue un intérprete Tcl estándar para la búsqueda de comandos: primero busca el comando en el espacio de nombres actual y luego en el espacio de nombres global. En consecuencia, si comando es relativo y namespace no es ::, la lista devuelta tiene dos elementos: comando con ámbito de namespace, como si fuera un comando en el espacio de nombres namespace; y comando como si fuera un comando en el espacio de nombres global. De lo contrario, si comando es absoluto (comienza con ::), o si namespace es ::, la lista contiene solo comando como si fuera un comando en el espacio de nombres global.

Auto_qualify es utilizada por las instalaciones de carga automática en Tcl, tanto para producir índices de carga automática como pkgIndex.tcl, como para realizar la carga automática real de funciones en tiempo de ejecución.

NOMBRE

library - directorio de scripts de Tcl

SINOPSIS

procedure name ?arg ...?

DESCRIPCIÓN

El nombre del directorio de la biblioteca de Tcl se determina de varias maneras. La variable global tcl_library contiene la ruta al directorio de la biblioteca de Tcl. Si la variable de entorno TCL_LIBRARY está definida, su valor se utiliza como valor de tcl_library. De lo contrario, se utiliza un valor predeterminado. Este valor predeterminado generalmente se calcula en tiempo de compilación y puede basarse en la ubicación del archivo ejecutable de Tcl. El comando info library devuelve el valor de la variable tcl_library.

El procedimiento source y los procedimientos de carga automática buscan scripts Tcl en varios directorios, incluido el directorio especificado por tcl_library. El procedimiento find_library se utiliza para la búsqueda de scripts.

find_library varName initScript ?baseName?
Este es un procedimiento de búsqueda estándar para que las extensiones lo utilicen durante su inicialización. Llaman a este procedimiento para buscar su biblioteca de scripts en varios directorios estándar. El último componente del nombre del directorio de la biblioteca es normalmente basenameversion (por ejemplo, tk8.0), pero puede ser “library” cuando se encuentra en jerarquías de compilación. El archivo initScript se incluirá en el intérprete una vez que se encuentre. El directorio en el que se encuentra este archivo se almacena en la variable global varName. Si esta variable ya está definida (por ejemplo, por código C durante la inicialización de la aplicación), entonces no se realiza ninguna búsqueda. De lo contrario, la búsqueda se realiza en estos directorios: el directorio nombrado por la variable de entorno enVarName; relativo al directorio de la biblioteca Tcl; relativo al archivo ejecutable en el directorio estándar de instalación bin o bin/arch; relativo al archivo ejecutable en el árbol de compilación actual; relativo al archivo ejecutable en un árbol de compilación paralelo.
parray nombreArray ?patrón?
Imprime en la salida estándar los nombres y valores de todos los elementos en el array nombreArray, o solo los nombres que coinciden con patrón (utilizando las reglas de coincidencia de string match) y sus valores si se proporciona patrón. nombreArray debe ser un array accesible para el llamador de parray. Puede ser local o global.

AYUDANTES DE LÍMITE DE PALABRA

Estos procedimientos se utilizan principalmente internamente por Tk.

tcl_endOfWord cadena inicio
Devuelve el índice de la primera ubicación de fin de palabra que ocurre después de un índice de inicio inicio en la cadena cadena. Una ubicación de fin de palabra se define como el primer carácter que no es de palabra que sigue al primer carácter de palabra después del punto de partida. Devuelve -1 si no hay más ubicaciones de fin de palabra después del punto de partida. Consulte la descripción de tcl_wordchars y tcl_nonwordchars a continuación para obtener más detalles sobre cómo Tcl determina qué caracteres son de palabra.
tcl_startOfNextWord cadena inicio
Devuelve el índice de la primera ubicación de inicio de palabra que ocurre después de un índice de inicio inicio en la cadena cadena. Una ubicación de inicio de palabra se define como el primer carácter de palabra que sigue a un carácter que no es de palabra. Devuelve -1 si no hay más ubicaciones de inicio de palabra después del punto de partida.
tcl_startOfPreviousWord cadena inicio
Devuelve el índice de la primera ubicación de inicio de palabra que ocurre antes de un índice de inicio inicio en la cadena cadena. Devuelve -1 si no hay más ubicaciones de inicio de palabra antes del punto de partida.
tcl_wordBreakAfter cadena inicio
Devuelve el índice del primer límite de palabra después del índice de inicio inicio en la cadena cadena. Devuelve -1 si no hay más límites después del punto de partida en la cadena dada. El índice devuelto se refiere al segundo carácter del par que comprende un límite.
tcl_wordBreakBefore cadena inicio
Devuelve el índice del primer límite de palabra antes del índice de inicio inicio en la cadena cadena. Devuelve -1 si no hay más límites antes del punto de partida en la cadena dada. El índice devuelto se refiere al segundo carácter del par que comprende un límite.

VARIABLES

Las siguientes variables globales son definidas o utilizadas por los procedimientos de la biblioteca Tcl. Se dividen en dos clases amplias, que manejan comandos y paquetes desconocidos, y determinan cuáles son las palabras.

VARIABLES DE CARGA AUTOMÁTICA Y GESTIÓN DE PAQUETES

auto_execs
Utilizado por auto_execok para registrar información sobre si comandos particulares existen como archivos ejecutables.
auto_index
Utilizado por auto_load para guardar la información del índice leída del disco.
auto_noexec
Si se establece en cualquier valor, entonces unknown no intentará ejecutar automáticamente ningún comando.
auto_noload
Si se establece en cualquier valor, entonces unknown no intentará cargar automáticamente ningún comando.
auto_path
Si se establece, entonces debe contener una lista Tcl válida que proporcione directorios para buscar durante las operaciones de carga automática (incluidos los archivos de índice de paquetes al usar el manejador predeterminado de package unknown). Esta variable se inicializa durante el inicio para contener, en orden: los directorios listados en la variable de entorno TCLLIBPATH, el directorio nombrado por la variable global tcl_library, el directorio padre de tcl_library, los directorios listados en la variable tcl_pkgPath. Las ubicaciones adicionales para buscar archivos e índices de paquetes normalmente deben agregarse a esta variable usando lappend.
env(TCL_LIBRARY)
Si se establece, entonces especifica la ubicación del directorio que contiene los scripts de la biblioteca (el valor de esta variable se asignará a la variable tcl_library y, por lo tanto, será devuelto por el comando info library). Si esta variable no está establecida, se utiliza un valor predeterminado.
env(TCLLIBPATH)
Si se establece, entonces debe contener una lista Tcl válida que proporcione directorios para buscar durante las operaciones de carga automática. Los directorios deben especificarse en formato Tcl, usando “/” como separador de ruta, independientemente de la plataforma. Esta variable solo se utiliza al inicializar la variable auto_path.

VARIABLES DE DETERMINACIÓN DE LÍMITES DE PALABRA

Estas variables solo se utilizan en los comandos tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter y tcl_wordBreakBefore.

tcl_nonwordchars
Esta variable contiene una expresión regular que utilizan rutinas como tcl_endOfWord para identificar si un carácter es parte de una palabra o no. Si el patrón coincide con un carácter, el carácter se considera un carácter que no es de palabra. En plataformas Windows, los espacios, tabulaciones y saltos de línea se consideran caracteres que no son de palabra. En Unix, todo lo que no sean números, letras y guiones bajos se considera un carácter que no es de palabra.
tcl_wordchars
Esta variable contiene una expresión regular que utilizan rutinas como tcl_endOfWord para identificar si un carácter es parte de una palabra o no. Si el patrón coincide con un carácter, el carácter se considera un carácter de palabra. En plataformas Windows, las palabras están compuestas por cualquier carácter que no sea un espacio, tabulación o salto de línea. En Unix, las palabras están compuestas por números, letras o guiones bajos.
