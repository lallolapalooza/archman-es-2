OPENSSL.CNF(5) File Formats Manual OPENSSL.CNF(5)

NOMBRE

openssl.cnf — Archivos de configuración de OpenSSL

DESCRIPCIÓN

La biblioteca CONF de OpenSSL puede usarse para leer archivos de configuración; véase CONF_modules_load_file(3). Se usa para el archivo de configuración maestro de OpenSSL /etc/ssl/openssl.cnf y en otros lugares como archivos de extensiones de certificados para la utilidad openssl(1) x509. Las aplicaciones OpenSSL también pueden usar la biblioteca CONF para sus propios propósitos.

Un archivo de configuración se divide en varias secciones. Cada sección comienza con una línea [nombre_seccion] y termina cuando se inicia una nueva sección o se llega al final del archivo. Un nombre de sección puede consistir en caracteres alfanuméricos y guiones bajos.

La primera sección de un archivo de configuración es especial y se denomina la "sección por defecto". Generalmente no tiene nombre y se extiende desde el inicio del archivo hasta la primera sección con nombre. Cuando se busca un nombre, primero se busca en una sección con nombre (si existe) y luego en la sección por defecto.

El entorno se mapea a una sección llamada ENV.

Los comentarios se pueden incluir precediéndolos con el carácter ‘#’.

Cada sección en un archivo de configuración consiste en un número de pares nombre y valor de la forma nombre=valor.

El nombre de la cadena puede contener cualquier carácter alfanumérico, así como algunos símbolos de puntuación como ‘.’, ‘,’, ‘;’ y ‘_’.

El valor de la cadena consiste en la cadena que sigue al carácter ‘=’ hasta el final de la línea, eliminando cualquier espacio en blanco al principio y al final.

La cadena de valor se somete a expansión de variables. Esto se puede hacer incluyendo subcadenas de la forma $nombre o ${nombre}: esto sustituirá el valor de la variable nombrada en la sección actual. También es posible sustituir un valor de otra sección usando la sintaxis $seccion::nombre o ${seccion::nombre}. Usando la forma $ENV::nombre, se pueden sustituir variables de entorno. También es posible asignar valores a variables de entorno usando el nombre ENV::nombre. Esto funcionará si el programa busca variables de entorno usando la biblioteca CONF en lugar de llamar directamente a getenv(3). La cadena de valor no debe superar los 64k después de la expansión de variables o se producirá un error.

Es posible escapar ciertos caracteres usando cualquier tipo de comilla o el carácter ‘\’. Al hacer que el último carácter de una línea sea un ‘\’, una cadena de valor se puede extender a varias líneas. Además, se reconocen las secuencias ‘\n’, ‘\r’, ‘\b’, y ‘\t’.

CONFIGURACIÓN DE LA BIBLIOTECA OPENSSL

Las aplicaciones pueden configurar automáticamente ciertos aspectos de OpenSSL usando el archivo de configuración maestro de OpenSSL, o opcionalmente un archivo de configuración alternativo. La utilidad openssl(1) incluye esta funcionalidad: cualquier subcomando usa el archivo de configuración maestro de OpenSSL a menos que se utilice una opción en el subcomando para usar un archivo de configuración alternativo.

Para habilitar la configuración de la biblioteca, la sección por defecto debe contener una línea apropiada que apunte a la sección de configuración principal. El nombre por defecto es openssl_conf, que es utilizado por la utilidad openssl(1). Otras aplicaciones pueden usar un nombre alternativo como myapplication_conf. Todas las líneas de configuración de la biblioteca aparecen en la sección por defecto al inicio del archivo de configuración.

La sección de configuración debe consistir en un conjunto de pares nombre-valor que contienen información de configuración de módulo específica. El nombre representa el nombre del módulo de configuración. El significado del valor es específico del módulo: puede, por ejemplo, representar una sección de configuración adicional que contenga información específica del módulo de configuración. Por ejemplo:

# La siguiente línea debe estar en la sección por defecto.
openssl_conf = openssl_init

[openssl_init]
oid_section = new_oids

[new_oids]
... nuevos OIDs aquí ...

Las características de cada módulo de configuración se describen a continuación.

Módulo de Configuración de Objetos ASN1

Este módulo tiene el nombre oid_section. El valor de esta variable apunta a una sección que contiene pares nombre-valor de OIDs: el nombre es el nombre corto y largo del OID, y el valor es la forma numérica del OID. Aunque algunos de los subcomandos de la utilidad openssl(1) ya tienen su propia funcionalidad de sección de OBJETOS ASN1, no todos lo hacen. Al usar el módulo de configuración de OBJETOS ASN1, todos los subcomandos de la utilidad openssl(1) pueden ver los nuevos objetos, así como cualquier aplicación compatible. Por ejemplo:

[new_oids]
some_new_oid = 1.2.3.4
some_other_oid = 1.2.3.5

También es posible establecer el valor al nombre largo seguido de una coma y la forma numérica del OID. Por ejemplo:

shortName = some object long name, 1.2.3.4

EJEMPLOS

Aquí hay un archivo de configuración de ejemplo que utiliza algunas de las características mencionadas anteriormente:

# Esta es la sección por defecto.
HOME=/temp
RANDFILE= ${ENV::HOME}/.rnd
configdir=$ENV::HOME/config

[ section_one ]
# Ahora estamos en la sección uno.

# Las comillas permiten espacios en blanco al principio y al final
any = " any variable name "

other = A string that can \
cover several lines \
by including \\ characters

message = Hello World\n

[ section_two ]
greeting = $section_one::message

El siguiente ejemplo muestra cómo expandir variables de entorno de forma segura.

Supongamos que desea que una variable llamada tmpfile se refiera a un nombre de archivo temporal. El directorio en el que se coloca puede ser determinado por las variables de entorno TEMP o TMP, pero es posible que no tengan ningún valor asignado. Si simplemente incluye los nombres de las variables de entorno y la variable no existe, esto causará un error cuando se intente cargar el archivo de configuración. Al hacer uso de la sección por defecto, ambos valores se pueden buscar, con TEMP teniendo prioridad y /tmp usándose si ninguno está definido:

TMP=/tmp
# El valor anterior se usa si TMP no está en el entorno
TEMP=$ENV::TMP
# El valor anterior se usa si TEMP no está en el entorno
tmpfile=${ENV::TEMP}/tmp.filename

Configuración de biblioteca OpenSSL más compleja. Añadir OID:

# Nombre de aplicación por defecto: debe coincidir con el parámetro "appname" (si existe)
# suministrado a CONF_modules_load_file et al.
openssl_conf = openssl_conf_section

[openssl_conf_section]
# Lista de módulos de configuración
oid_section = new_oids

[new_oids]
# Nuevo OID, solo nombre corto
newoid1 = 1.2.3.4.1
# Nuevo OID, nombre corto y nombre largo
newoid2 = New OID 2 long name, 1.2.3.4.2

Los ejemplos anteriores pueden ser utilizados con cualquier aplicación que soporte la configuración de biblioteca si "openssl_conf" se modifica para que coincida con el "appname" apropiado.

openssl.cnf(5) — LibreSSL — The OpenBSD Project

NAME

openssl.cnf, config — OpenSSL configuration file syntax

DESCRIPTION

The OpenSSL suite of programs uses configuration files to control its behaviour. These files are primarily used for setting up certificate authorities (CAs), configuring certificate extensions, and managing various cryptographic parameters. The main configuration file is usually named openssl.cnf, but any file can be used.

Configuration files use a simple text-based format organised into sections. Each section starts with a name enclosed in square brackets, e.g. [ section_name ]. Within each section, configuration parameters are specified as name=value pairs. Values can be strings, numbers, filenames, or references to other configuration parameters.

The format is similar to the older .ini file format used on Windows, with sections and key-value pairs. However, it supports more advanced features such as variable expansion, command execution, and inclusion of other files.

OPENSSL LIBRARY CONFIGURATION

The OpenSSL library searches for a configuration file in the following locations:

  1. The file specified by the OPENSSL_CONF environment variable.
  2. The file specified by the openssl.cnf configuration option in the OpenSSL configuration file itself.
  3. The file /etc/ssl/openssl.cnf.
  4. The file /etc/pki/tls/openssl.cnf.

If multiple configuration files are found, they are processed in the order they are found. Later files override settings in earlier files.

FILES

openssl.cnf: The default OpenSSL configuration file.

EXAMPLES

This example shows how to define a new Object Identifier (OID) in a configuration file.

Create a file named example.cnf with the following content:

oid_section = new_oids

[ new_oids ]
newoid1 = 1.2.3.4.1

For example if the second sample file above is saved to "example.cnf" then the command line:

OPENSSL_CONF=example.cnf openssl asn1parse -genstr OID:1.2.3.4.1

will output:

0:d=0 hl=2 l= 4 prim: OBJECT :newoid1

showing that the OID "newoid1" has been added as "1.2.3.4.1".

SEE ALSO

openssl(1), CONF_modules_load_file(3), OPENSSL_config(3), x509v3.cnf(5)

CAVEATS

If a configuration file attempts to expand a variable that doesn't exist, then an error is flagged and the file will not load. This can also happen if an attempt is made to expand an environment variable that doesn't exist. For example, in a previous version of OpenSSL the default OpenSSL master configuration file used the value of HOME which may not be defined on non Unix systems and would cause an error.

This can be worked around by including a default section to provide a default value: then if the environment lookup fails, the default value will be used instead. For this to work properly, the default value must be defined earlier in the configuration file than the expansion. See the EXAMPLES section for an example of how to do this.

If the same variable is defined more than once in the same section, then all but the last value will be silently ignored. In certain circumstances such as with DNs, the same field may occur multiple times. This is usually worked around by ignoring any characters before an initial ‘.’, for example:

1.OU="My first OU"
2.OU="My Second OU"

BUGS

Currently there is no way to include characters using the octal \nnn form. Strings are all NUL terminated, so NUL bytes cannot form part of the value.

The escaping isn't quite right: if you want to use sequences like ‘\n’, you can't use any quote escaping on the same line.

Files are loaded in a single pass. This means that a variable expansion will only work if the variables referenced are defined earlier in the file.
