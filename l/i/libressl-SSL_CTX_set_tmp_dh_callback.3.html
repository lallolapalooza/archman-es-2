Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_CTX_SET_TMP_DH_CALLBACK(3) Manual de funciones de biblioteca SSL_CTX_SET_TMP_DH_CALLBACK(3)

NOMBRE

SSL_CTX_set_tmp_dh_callback, SSL_CTX_set_tmp_dh, SSL_set_tmp_dh_callback, SSL_set_tmp_dh — manejar claves DH para intercambio de claves efímero

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

void
SSL_CTX_set_tmp_dh_callback(SSL_CTX *ctx, DH *(*tmp_dh_callback)(SSL *ssl, int is_export, int keylength));

long
SSL_CTX_set_tmp_dh(SSL_CTX *ctx, DH *dh);

void
SSL_set_tmp_dh_callback(SSL *ssl, DH *(*tmp_dh_callback)(SSL *ssl, int is_export, int keylength);

long
SSL_set_tmp_dh(SSL *ssl, DH *dh);

DESCRIPCIÓN

SSL_CTX_set_tmp_dh_callback() establece la función de devolución de llamada para ctx que se utilizará cuando se requieran parámetros DH a tmp_dh_callback. La devolución de llamada es heredada por todos los objetos ssl creados a partir de ctx.

SSL_CTX_set_tmp_dh() establece los parámetros DH que se utilizarán por ctx. La clave es heredada por todos los objetos ssl creados a partir de ctx.

SSL_set_tmp_dh_callback() establece la devolución de llamada solo para ssl.

SSL_set_tmp_dh() establece los parámetros solo para ssl.

Estas funciones se aplican solo a servidores SSL/TLS.

Al utilizar una combinación de cifrado con autenticación RSA, se puede realizar un intercambio de claves DH efímero. En estos casos, los datos de la sesión se negocian utilizando la clave DH efímera/temporal y la clave suministrada y certificada por la cadena de certificados solo se utiliza para firmar. Las combinaciones de cifrado anónimas (sin una clave de servidor permanente) también utilizan claves DH efímeras.

El uso del intercambio de claves DH efímero proporciona secreto adelante (forward secrecy), ya que la conexión solo puede descifrarse cuando se conoce la clave DH. Al generar una clave DH temporal dentro de la aplicación del servidor que se pierde al salir de la aplicación, se hace imposible para los atacantes descifrar sesiones pasadas, incluso si obtienen la clave normal (certificada), ya que esta clave solo se utilizó para firmar.

Para realizar un intercambio de claves DH, el servidor debe usar un grupo DH (parámetros DH) y generar una clave DH. El servidor siempre generará una nueva clave DH durante la negociación.

Dado que la generación de parámetros DH consume mucho tiempo, una aplicación no debería generar los parámetros sobre la marcha, sino suministrarlos. Los parámetros DH se pueden reutilizar, ya que la clave real se genera de nuevo durante la negociación. El riesgo de reutilizar parámetros DH es que un atacante pueda especializarse en un grupo DH muy utilizado. Por lo tanto, las aplicaciones deberían generar sus propios parámetros DH durante el proceso de instalación utilizando la aplicación dhparam de openssl(1). Esta aplicación garantiza que se utilicen primos "fuertes".

Los archivos dh2048.pem y dh4096.pem en el directorio apps de la versión actual de la distribución OpenSSL contienen los parámetros DH 'SKIP', que utilizan primos seguros y se generaron de forma verificable pseudo-aleatoria. Estos archivos se pueden convertir a código C utilizando la opción -C de la aplicación dhparam de openssl(1). La generación de parámetros DH personalizados durante la instalación aún debería preferirse para evitar que un atacante se especialice en un grupo comúnmente utilizado. El archivo dh1024.pem contiene parámetros antiguos que no deben ser utilizados por las aplicaciones.

Una aplicación puede especificar directamente los parámetros DH o suministrarlos a través de una función de devolución de llamada.

Las versiones anteriores de la devolución de llamada utilizaban parámetros is_export y keylength para controlar la generación de parámetros para combinaciones de cifrado de exportación y no de exportación. Se recomienda a los servidores modernos que no admiten combinaciones de cifrado de exportación que utilicen SSL_CTX_set_tmp_dh() o, alternativamente, que utilicen la devolución de llamada pero ignoren keylength y is_export y simplemente suministren parámetros de al menos 2048 bits en la devolución de llamada.

VALORES DE RETORNO

SSL_CTX_set_tmp_dh() y SSL_set_tmp_dh() devuelven 1 en caso de éxito y 0 en caso de error. Consulte la cola de errores para averiguar el motivo del fallo.

EJEMPLOS

Configurar parámetros DH con una longitud de clave de 2048 bits. El manejo de errores se deja parcialmente fuera.

Generación de parámetros por línea de comandos:

openssl dhparam -out dh_param_2048.pem 2048

Código para configurar parámetros durante la inicialización del servidor:

SSL_CTX ctx = SSL_CTX_new();
...

/* Configurar parámetros DH efímeros. */
DH *dh_2048 = NULL;
FILE *paramfile;
paramfile = fopen("dh_param_2048.pem", "r");
if (paramfile) {
	dh_2048 = PEM_read_DHparams(paramfile, NULL, NULL, NULL);
	fclose(paramfile);
} else {
	/* Error. */
}
if (dh_2048 == NULL) {
	/* Error. */
}
if (SSL_CTX_set_tmp_dh(ctx, dh_2048) != 1) {
	/* Error. */
}

NOMBRE

SSL_CTX_set_tmp_dh_callback - Establecer una función de devolución de llamada para la generación de parámetros DH temporales

SINOPSIS

#include <openssl/ssl.h>

void SSL_CTX_set_tmp_dh_callback(SSL_CTX *ctx, SSL_TMP_DH_CB *callback);

DESCRIPCIÓN

La función SSL_CTX_set_tmp_dh_callback establece la función de devolución de llamada callback que se invocará cuando se necesiten parámetros DH temporales. Esto suele ocurrir durante el establecimiento de la conexión SSL/TLS cuando se utilizan suites de cifrado que requieren parámetros DH efímeros (DHE).

El argumento ctx es el contexto SSL para el que se establece la devolución de llamada.

La función callback debe tener la siguiente firma:

int callback(SSL *ssl, int is_export, int keylength);

  • ssl: El objeto SSL para el cual se necesitan los parámetros DH.
  • is_export: Un indicador que especifica si se trata de una exportación de cifrado (generalmente 0).
  • keylength: La longitud deseada en bits para la clave DH.

La función de devolución de llamada debe generar y devolver parámetros DH de la longitud especificada. El resultado se puede establecer utilizando la macro SSL_set_tmp_dh dentro de la devolución de llamada.

Si la función de devolución de llamada devuelve 0, se consideran como un éxito. Si devuelve un valor distinto de cero, indica un error.

Si se establece callback en NULL, se eliminará cualquier devolución de llamada de parámetros DH temporal configurada previamente.

VALORES DE RETORNO

La función SSL_CTX_set_tmp_dh_callback no devuelve ningún valor.

EJEMPLOS

No se proporcionan ejemplos específicos en esta página del manual. Consulta la documentación de OpenSSL para ver ejemplos de uso.

VER TAMBIÉN

SSL_CTX(3), SSL_set_tmp_dh(3), SSL_set_tmp_rsa(3)
