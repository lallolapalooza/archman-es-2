NOMBRE

libcurl-env-dbg - variables de entorno que libcurl DEBUGBUILD entiende

DESCRIPCIÓN

Este es un conjunto de variables solo reconocidas y utilizadas si libcurl se compiló con "depuración habilitada", lo que nunca debería ser cierto para una biblioteca utilizada en producción. Estas variables están destinadas solo para uso interno, sujetas a cambios y tienen muchos efectos en el comportamiento de libcurl. Consulte el código fuente para determinar exactamente cómo se están utilizando.

CURL_ALTSVC_HTTP
Ignora la restricción del protocolo HTTPS de AltSvc si esta variable existe.
CURL_DBG_SOCK_RBLOCK
El porcentaje de llamadas recv() que deben responderse con un EAGAIN al azar. Para sockets TCP/UNIX.
CURL_DBG_SOCK_RMAX
La cantidad máxima de datos que se recibirán de la red en una sola llamada recv(). Para sockets TCP/UNIX. Esto se aplica a cada recv.

Ejemplo: CURL_DBG_SOCK_RMAX=400 significa que el tamaño del búfer de recepción está limitado a un máximo de 400 bytes.

CURL_DBG_SOCK_WBLOCK
El porcentaje de llamadas send() que deben responderse con un EAGAIN al azar. Para sockets TCP/UNIX.
CURL_DBG_SOCK_WPARTIAL
El porcentaje de datos que se escribirán en la red. Para sockets TCP/UNIX. Esto se aplica a cada send.

Ejemplo: CURL_DBG_SOCK_WPARTIAL=80 significa que un envío de 1000 bytes solo enviará 800.

CURL_DBG_QUIC_WBLOCK
El porcentaje de llamadas send() que deben responderse con EAGAIN al azar. Solo QUIC.
CURL_DEBUG
El comportamiento de registro de rastreo como alternativa a llamar a curl_global_trace(3).

Ejemplo: CURL_DEBUG=http/2 significa rastrear detalles sobre el manejo de HTTP/2.

En la herramienta de línea de comandos curl, compilada con --enable-debug, esta variable de entorno se suma a argumentos como --verbose, -vvv. Se necesita al menos un -v para que la ejecución emita la salida de rastreo, pero cuando lo hace, se añaden los contenidos de CURL_DEBUG y pueden anular las opciones existentes.

Ejemplo: CURL_DEBUG=tcp,-http/2 curl -vv url significa rastrear detalles del protocolo, activado por -vv, añadir rastreo de TCP además y eliminar el rastreo de HTTP/2.

CURL_DEBUG_SIZE
Falsifica el tamaño devuelto por CURLINFO_HEADER_SIZE y CURLINFO_REQUEST_SIZE.
CURL_DNS_SERVER
Cuando se compila con c-ares para la resolución de nombres, establecer esta variable de entorno a [IP:puerto] hace que libcurl use ese servidor DNS en lugar del predeterminado del sistema. Esto es utilizado por la suite de pruebas de curl.
CURL_FTP_PWD_STOP
Cuando se establece, la primera transferencia - al usar ftp: - se detiene antes de enviar el comando PWD y detiene cualquier progreso adicional. Esto se usa para probar un caso límite.
CURL_GETHOSTNAME
Falsifica el nombre de host no calificado de la máquina local para NTLM y SMTP.
CURL_HSTS_HTTP
Ignora la restricción del protocolo HTTPS de HSTS si esta variable existe.
CURL_FORCETIME
Se utiliza un tiempo de 0 para las firmas de AWS y NTLM si esta variable existe.
CURL_ENTROPY
Un valor fijo falsificado para usar en lugar de un número aleatorio, de modo que las funciones en libcurl que de otra manera obtendrían salidas aleatorias puedan ser probadas para lo que generan.
CURL_SMALLREQSEND
Un tamaño alternativo de datos HTTP para enviar a la vez solo si es menor que el actual.
CURL_SMALLSENDS
Un tamaño alternativo de datos de socket para enviar a la vez solo si es menor que el actual.
CURL_TIME
Marca de tiempo Unix falsificada para usar en AltSvc, HSTS y variables CURLINFO relacionadas con el tiempo.

Esta variable también puede usarse para falsificar los datos devueltos por algunas variables CURLINFO que no están relacionadas con el tiempo (como CURLINFO_LOCAL_PORT), y en ese caso el valor no es una marca de tiempo.

CURL_TRACE
El rastreo LDAP se habilita si esta variable existe y su valor es 1 o mayor.

El rastreo de OpenLDAP es independiente. Consulte CURL_OPENLDAP_TRACE.

CURL_OPENLDAP_TRACE
El rastreo de OpenLDAP se habilita si esta variable existe y su valor es 1 o mayor. Hay un número de niveles de depuración, consulte los comentarios de openldap.c.
CURL_WS_CHUNK_SIZE
Se utiliza para influir en el tamaño del bloque del búfer utilizado para la codificación y decodificación de WebSocket.
CURL_WS_CHUNK_EAGAIN
Se utiliza para simular envíos bloqueantes después de este tamaño de bloque para conexiones WebSocket.
CURL_WS_FORCE_ZERO_MASK
Se utiliza para establecer la máscara de bits de todos los fotogramas de WebSocket enviados a cero. El valor de la variable de entorno no importa.
CURL_FORBID_REUSE
Se utiliza para establecer el indicador CURLOPT_FORBID_REUSE en cada transferencia iniciada por la herramienta de línea de comandos curl. El valor de la variable de entorno no importa.
CURL_GRACEFUL_SHUTDOWN
Realiza un cierre de sesión bloqueante y ordenado de todas las conexiones restantes cuando se destruye un manejador multi. Esto se activa implícitamente para manejadores fáciles que se ejecutan a través de easy_perform. El valor de la variable de entorno da el tiempo de espera de cierre de sesión en milisegundos.
CURL_H2_STREAM_WIN_MAX
Se establece en un número de 32 bits positivo para anular los 10 MB por defecto de la ventana de transmisión HTTP/2. Se utiliza en pruebas para verificar el manejo correcto de las actualizaciones de ventana.
