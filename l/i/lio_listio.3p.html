LIO_LISTIO(3P) Manual del Programador POSIX LIO_LISTIO(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de Linux de esta interfaz puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

lio_listio — E/S dirigida en lista

SINOPSIS

#include <aio.h>
int lio_listio(int mode, struct aiocb *restrict const list[restrict],
    int nent, struct sigevent *restrict sig);

DESCRIPCIÓN

La función lio_listio() inicia una lista de solicitudes de E/S con una única llamada a función.

El argumento mode toma uno de los valores LIO_WAIT o LIO_NOWAIT declarados en <aio.h> y determina si la función retorna cuando las operaciones de E/S se han completado, o tan pronto como las operaciones se han puesto en cola. Si el argumento mode es LIO_WAIT, la función esperará hasta que toda la E/S esté completa y el argumento sig se ignorará.

Si el argumento mode es LIO_NOWAIT, la función retornará inmediatamente, y la notificación asíncrona ocurrirá, de acuerdo con el argumento sig, cuando todas las operaciones de E/S se completen. Si sig es NULL, entonces no ocurrirá ninguna notificación asíncrona. Si sig no es NULL, la notificación asíncrona ocurrirá como se especifica en la Sección 2.4.1, Generación y Entrega de Señales, cuando todas las solicitudes en list se hayan completado.

Las solicitudes de E/S enumeradas por list se envían en un orden no especificado.

El argumento list es un array de punteros a estructuras aiocb. El array contiene nent elementos. El array puede contener elementos NULL, que serán ignorados.

Si el buffer apuntado por list o las estructuras aiocb apuntadas por los elementos del array list se vuelven direcciones ilegales antes de que toda la E/S asíncrona se complete y, si es necesario, se envíe la notificación, entonces el comportamiento es indefinido. Si los buffers apuntados por el miembro aio_buf de la estructura aiocb apuntada por los elementos del array list se vuelven direcciones ilegales antes de que la E/S asíncrona asociada con esa estructura aiocb se complete, el comportamiento es indefinido.

El campo aio_lio_opcode de cada estructura aiocb especifica la operación a realizar. Las operaciones soportadas son LIO_READ, LIO_WRITE y LIO_NOP; estos símbolos están definidos en <aio.h>. La operación LIO_NOP hace que la entrada de la lista sea ignorada. Si el miembro aio_lio_opcode es igual a LIO_READ, entonces se envía una operación de E/S como si fuera mediante una llamada a aio_read() con el aiocbp igual a la dirección de la estructura aiocb. Si el miembro aio_lio_opcode es igual a LIO_WRITE, entonces se envía una operación de E/S como si fuera mediante una llamada a aio_write() con el aiocbp igual a la dirección de la estructura aiocb.

El miembro aio_fildes especifica el descriptor de archivo en el que se debe realizar la operación.

El miembro aio_buf especifica la dirección del buffer hacia o desde el cual se transfiere los datos.

El miembro aio_nbytes especifica el número de bytes de datos a transferir.

Los miembros de la estructura aiocb describen además la operación de E/S a realizar, de una manera idéntica a la de la estructura aiocb correspondiente cuando es utilizada por las funciones aio_read() y aio_write().

El argumento nent especifica cuántos elementos son miembros de la lista; es decir, la longitud del array.

El comportamiento de esta función se modifica de acuerdo con las definiciones de finalización de integridad de datos de E/S sincronizada y finalización de integridad de archivos de E/S sincronizada si la E/S sincronizada está habilitada en el archivo asociado con aio_fildes.

Para archivos regulares, no se realizará ninguna transferencia de datos más allá del offset máximo establecido en la descripción del archivo abierto asociado con aiocbp->aio_fildes.

Si sig->sigev_notify es SIGEV_THREAD y sig->sigev_notify_attributes es un puntero no nulo y el bloque apuntado por este puntero se convierte en una dirección ilegal antes de que toda la E/S asíncrona se complete, entonces el comportamiento es indefinido.

VALOR DE RETORNO

Si el argumento mode tiene el valor LIO_NOWAIT, la función lio_listio() retornará el valor cero si las operaciones de E/S se encolan con éxito; de lo contrario, la función retornará el valor -1 y establecerá errno para indicar el error.

Si el argumento mode tiene el valor LIO_WAIT, la función lio_listio() retornará el valor cero cuando toda la E/S indicada se haya completado con éxito. De lo contrario, lio_listio() retornará un valor de -1 y establecerá errno para indicar el error.

En cualquier caso, el valor de retorno solo indica el éxito o el fallo de la llamada lio_listio() en sí, no el estado de las solicitudes de E/S individuales. En algunos casos, una o más de las solicitudes de E/S pueden fallar. El fallo de una solicitud individual no impide la finalización de ninguna otra solicitud individual. Para determinar el resultado de cada solicitud de E/S, la aplicación deberá examinar el estado de error asociado con cada bloque de control aiocb. Los estados de error devueltos son idénticos a los devueltos como resultado de una función aio_read() o aio_write().

ERRORES

La función lio_listio() fallará si:

EAGAIN
No se dispuso de los recursos necesarios para encolar todas las solicitudes de E/S. La aplicación puede verificar el estado de error de cada aiocb para determinar la(s) solicitud(es) individual(es) que fallaron.
EAGAIN
El número de entradas indicado por nent excedería el límite del sistema {AIO_MAX}.
EINVAL
El argumento mode no es un valor adecuado, o el valor de nent era mayor que {AIO_LISTIO_MAX}.
EINTR
Se entregó una señal mientras se esperaba la finalización de todas las solicitudes de E/S durante una operación LIO_WAIT. Tenga en cuenta que, dado que cada operación de E/S invocada por lio_listio() puede provocar una señal cuando se completa, este retorno de error puede ser causado por la finalización de una (o más) de las propias operaciones de E/S que se están esperando. Las solicitudes de E/S pendientes no se cancelan, y la aplicación debe examinar cada elemento de la lista para determinar si la solicitud se inició, se canceló o se completó.
EIO
Una o más de las operaciones de E/S individuales fallaron. La aplicación puede verificar el estado de error de cada estructura aiocb para determinar la(s) solicitud(es) individual(es) que fallaron.

Además de los errores devueltos por la función lio_listio(), si la función lio_listio() tiene éxito o falla con errores de [EAGAIN], [EINTR] o [EIO], entonces es posible que se hayan iniciado algunas de las E/S especificadas en la lista. Si la función lio_listio() falla con un código de error distinto de [EAGAIN], [EINTR] o [EIO], no se habrá iniciado ninguna operación de la lista. La operación de E/S indicada por cada elemento de la lista puede encontrar errores específicos de la función de lectura o escritura individual que se esté realizando. En este caso, el estado de error de cada bloque de control aiocb contiene el código de error asociado. Los códigos de error que se pueden establecer son los mismos que se establecerían mediante una función read() o write(), con los siguientes códigos de error adicionales posibles:

EAGAIN
La operación de E/S solicitada no se encoló debido a limitaciones de recursos.
ECANCELED
La E/S solicitada se canceló antes de que la E/S se completara debido a una solicitud explícita de aio_cancel().
EFBIG

NAME

lio_listio - read or write a list of I/O requests

SYNOPSIS

#include <aio.h>

int lio_listio(int mode, struct aiocb *restrict const aiocb[], int numevents, struct sigevent *restrict sev);

DESCRIPTION

The lio_listio() function initiates a list of asynchronous I/O operations. The mode argument specifies whether to perform read or write operations. It shall be either LIO_READ or LIO_WRITE.

The aiocb argument is an array of pointers to aiocb structures, each describing an asynchronous I/O operation to be initiated. The array shall contain numevents elements.

The sev argument is used for requesting asynchronous notification when all operations in the list have completed. If sev is not NULL, it describes the notification mechanism to be employed. See aio_read(3p) for a description of the sigevent structure. If sev is NULL, no notification is requested.

For each element aiocb[i] in the aiocb array:

If the file descriptor in aiocb[i]->aio_fildes is associated with a synchronous read operation (LIO_READ specified in mode), then the operation performed is a read. Otherwise, if the file descriptor is associated with a synchronous write operation (LIO_WRITE specified in mode), then the operation performed is a write.

The buffer address is aiocb[i]->aio_buf, the number of bytes to transfer is aiocb[i]->aio_nbytes, and the offset into the file is aiocb[i]->aio_offset.

The operation is synchronized with the file offset in the open file description associated with the file descriptor.

The behavior is as if each aiocb structure in the list pointed to an operation that was initiated using aio_read(3p) if LIO_READ was specified, or aio_write(3p) if LIO_WRITE was specified.

All operations in the list are initiated atomically. If any operation fails to initiate, all operations that have already been initiated by this call shall be cancelled. The state of the aiocb structures remains valid until the operation completes.

When an operation completes, the return status of the operation can be retrieved by calling aio_error(3p) . The value returned by aio_error() is the error status of the individual operation. If the operation completed successfully, aio_error() returns 0. If the operation was cancelled by aio_cancel(3p) , aio_error() returns ECANCELED. Otherwise, it returns the error code associated with the failed operation. The return status of the operation itself (the return value of the underlying read() or write() call) can be retrieved by calling aio_return(3p) .

RETURN VALUE

Upon successful initiation of all requested operations, lio_listio() returns 0. Otherwise, it returns a positive error number.

ERRORS

The lio_listio() function may fail for any of the following reasons:

[EINVAL]
The value of mode is invalid, or numevents is less than or equal to 0, or any of the aiocb structures are invalid (for example, aio_lio_opcode is not LIO_READ or LIO_WRITE, or aio_fildes is not a valid file descriptor, or aio_buf is NULL, or aio_nbytes is not positive).
[EAGAIN]
Resource temporarily unavailable.
[ENOMEM]
Insufficient memory resources are available to initiate the request.
[EBADF]
One of the file descriptors in the aiocb array is invalid. This may also occur if the file descriptor was closed before the operation was initiated.
[EFBIG]
The file is a regular file, and aiocbp-> aio_nbytes is greater than 0, and aiocbp-> aio_offset is greater than or equal to the offset maximum in the open file description associated with aiocbp-> aio_fildes.
[EINPROGRESS]
The requested I/O is in progress.
[EOVERFLOW]
The aiocbp-> aio_lio_opcode is LIO_READ, the file is a regular file, aiocbp-> aio_nbytes is greater than 0, and the aiocbp-> aio_offset is before the end-of-file and is greater than or equal to the offset maximum in the open file description associated with aiocbp-> aio_fildes.

The following sections are informative.

EXAMPLES

None.

APPLICATION USAGE

None.

RATIONALE

Although it may appear that there are inconsistencies in the specified circumstances for error codes, the [EIO] error condition applies when any circumstance relating to an individual operation makes that operation fail. This might be due to a badly formulated request (for example, the aio_lio_opcode field is invalid, and aio_error() returns [EINVAL]) or might arise from application behavior (for example, the file descriptor is closed before the operation is initiated, and aio_error() returns [EBADF]).

The limitation on the set of error codes returned when operations from the list shall have been initiated enables applications to know when operations have been started and whether aio_error() is valid for a specific operation.
