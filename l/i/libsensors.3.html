NOMBRE

libsensors - funciones públicamente accesibles proporcionadas por la biblioteca sensors

SINOPSIS

#include <sensors/sensors.h>
/* Inicialización y limpieza de la biblioteca */
int sensors_init(FILE *input);
void sensors_cleanup(void);
const char *libsensors_version;
/* Manejo de nombres de chips */
int sensors_parse_chip_name(const char *orig_name,
                            sensors_chip_name *res);
void sensors_free_chip_name(sensors_chip_name *chip);
int sensors_snprintf_chip_name(char *str, size_t size,
                               const sensors_chip_name *chip);
const char *sensors_get_adapter_name(const sensors_bus_id *bus);
/* Enumeración de chips y características */
const sensors_chip_name *
sensors_get_detected_chips(const sensors_chip_name *match,
                           int *nr);
const sensors_feature *
sensors_get_features(const sensors_chip_name *name,
                     int *nr);
const sensors_subfeature *
sensors_get_all_subfeatures(const sensors_chip_name *name,
                            const sensors_feature *feature,
                            int *nr);
const sensors_subfeature *
sensors_get_subfeature(const sensors_chip_name *name,
                       const sensors_feature *feature,
                       sensors_subfeature_type type);
/* Acceso a características */
char *sensors_get_label(const sensors_chip_name *name,
                        const sensors_feature *feature);
int sensors_get_value(const sensors_chip_name *name, int subfeat_nr,
                      double *value);
int sensors_set_value(const sensors_chip_name *name, int subfeat_nr,
                      double value);
int sensors_do_chip_sets(const sensors_chip_name *name);
#include <sensors/error.h>
/* Decodificación de errores */
const char *sensors_strerror(int errnum);
/* Manejadores de errores */
void (*sensors_parse_error) (const char *err, int lineno);
void (*sensors_parse_error_wfn) (const char *err,
                                 const char *filename, int lineno);
void (*sensors_fatal_error) (const char *proc, const char *err);

DESCRIPCIÓN

sensors_init() carga el archivo de configuración y la lista de chips detectados. Si esto devuelve un valor distinto de cero, estás en problemas; no puedes asumir que nada se inicializará correctamente. Si deseas recargar el archivo de configuración, o cargar un archivo de configuración diferente, llama a sensors_cleanup() a continuación antes de llamar a sensors_init() de nuevo. Esto significa que no puedes cargar varios archivos de configuración a la vez llamando a sensors_init() varias veces.

El formato del archivo de configuración se describe en sensors.conf(5).

Si FILE es NULL, se utilizan los archivos de configuración predeterminados (ver la sección ARCHIVOS a continuación). La mayoría de las aplicaciones querrán hacer esto.

sensors_cleanup() limpia todo: no puedes acceder a nada después de esto, ¡hasta la próxima llamada a sensors_init()!

libsensors_version es una cadena que representa la versión de libsensors.

sensors_parse_chip_name() analiza un nombre de chip a su representación interna. Devuelve 0 si tiene éxito, <0 si hay un error. Asegúrate de llamar a sensors_free_chip_name() cuando hayas terminado con los datos.

sensors_free_chip_name() libera la memoria que se haya podido asignar para la representación interna de un nombre de chip. Solo tienes que llamar a esto para los nombres de chip que no provienen de libsensors (es decir, nombres de chip que fueron generados por sensors_parse_chip_name()).

sensors_snprintf_chip_name() imprime un nombre de chip a partir de su representación interna. ¡Ten en cuenta que chip no debe contener valores comodín! Devuelve el número de caracteres impresos si tiene éxito (igual que snprintf), <0 si hay un error.

sensors_get_adapter_name() devuelve el nombre del adaptador de un tipo de bus, par de números, como se usa dentro de la estructura sensors_chip_name. Si no se pudo encontrar, devuelve NULL.

Los adaptadores describen cómo está conectado un chip de monitoreo al sistema. Esto es particularmente relevante para los chips de sensores I2C/SMBus (tipo de bus "i2c"), a los que se debe acceder a través de un controlador I2C/SMBus. Cada uno de estos controladores tiene un número diferente, asignado por el sistema en tiempo de inicialización, para que puedan ser referenciados individualmente.

Los sensores Super-I/O o integrados en la CPU, por otro lado, se pueden acceder directamente y técnicamente no utilizan ningún adaptador. Solo tienen un tipo de bus pero sin número de bus, y sensors_get_adapter_name() devolverá un nombre de adaptador genérico para ellos.

sensors_get_detected_chips() devuelve todos los chips detectados que coinciden con un nombre de chip dado, uno por uno. Si no se proporciona ningún nombre de chip, se devuelven todos los chips detectados. Para empezar por el principio de la lista, usa 0 para nr; se devuelve NULL si estamos al final de la lista. ¡No intentes cambiar estos nombres de chip, ya que apuntan a estructuras internas!

sensors_get_features() devuelve todas las características principales de un chip específico. nr es una variable utilizada internamente. Establécela a cero para comenzar al principio de la lista. Si no se encuentran más características, se devuelve NULL. ¡No intentes cambiar la estructura devuelta; corromperás las estructuras de datos internas!

sensors_get_all_subfeatures() devuelve todas las subcaracterísticas de una característica principal dada. nr es una variable utilizada internamente. Establécela a cero para comenzar al principio de la lista. Si no se encuentran más subcaracterísticas, se devuelve NULL. ¡No intentes cambiar la estructura devuelta; corromperás las estructuras de datos internas!

sensors_get_subfeature() devuelve la subcaracterística del tipo dado para una característica principal dada, si existe, de lo contrario devuelve NULL. ¡No intentes cambiar la estructura devuelta; corromperás las estructuras de datos internas!

sensors_get_label() busca la etiqueta que pertenece a este chip. ¡Ten en cuenta que chip no debe contener valores comodín! La cadena devuelta se asigna de nuevo (libérala tú mismo). En caso de fallo, se devuelve NULL. Si no existe ninguna etiqueta para esta característica, se devuelve su propio nombre.

sensors_get_value() Lee el valor de una subcaracterística de un chip determinado. ¡Ten en cuenta que chip no debe contener valores comodín! Esta función devolverá 0 si tiene éxito y <0 si hay un error.

sensors_set_value() establece el valor de una subcaracterística de un chip determinado. ¡Ten en cuenta que chip no debe contener valores comodín! Esta función devolverá 0 si tiene éxito y <0 si hay un error.

sensors_do_chip_sets() ejecuta todas las declaraciones set para este chip en particular. ¡El chip puede contener comodines! Esta función devolverá 0 si tiene éxito y <0 si hay un error.

sensors_strerror() devuelve un puntero a una cadena que describe el error. errnum puede ser negativo (se devuelve el error positivo correspondiente). ¡No debes modificar el resultado!

sensors_parse_error() y sensors_parse_error_wfn() son funciones que se llaman cuando se detecta un error de análisis. Dales nuevos valores, y tus propias funciones serán llamadas en lugar de las predeterminadas (que imprimen en stderr). Estas funciones pueden terminar el programa, pero generalmente generan un error y devuelven. La primera función es la original, la segunda se agregó más tarde cuando se agregó soporte para múltiples archivos de configuración. El código de la biblioteca ahora solo llama a la segunda función. Sin embargo, para compatibilidad con versiones anteriores, si una aplicación proporciona una función de manejo personalizada para la primera función pero no para la segunda, entonces todos los errores de análisis se informarán utilizando la primera función (es decir, el nombre del archivo nunca se informa). Ten en cuenta que el nombre del archivo puede ser NULL (si no se conoce el nombre del archivo) y el número de línea puede ser 0 (si el error ocurre antes de que comience el análisis real).

sensors_fatal_error() es una función que se llama cuando se detecta un error inmediatamente fatal (como falta de memoria). Dales un nuevo valor, y tu propia función será llamada en lugar de la predeterminada (que imprime en stderr y finaliza el programa). ¡Nunca dejes que devuelva!

NOMBRE

libsensors - biblioteca de monitorización de hardware

SINOPSIS

#include <sensors/sensors.h>

int sensors_init(sensors_chip_name **awarns);

int sensors_get_detected_chips(sensors_chip_name ***achips, int *acount);

int sensors_get_features(const sensors_chip_name *cn, sensors_feature **afeatures, int *acount);

int sensors_get_subfeatures(const sensors_feature *feature, sensors_subfeature **asubfeatures, int *acount);

int sensors_get_value(const sensors_chip_name *cn, int number, long *value);

int sensors_set_value(const sensors_chip_name *cn, int number, long value);

int sensors_get_label(const sensors_chip_name *cn, const sensors_feature *feature, const sensors_subfeature *subfeature, char *label, int size);

int sensors_get_adapter_name(const sensors_chip_name *cn, char *name, int size);

void sensors_cleanup(void);

DESCRIPCIÓN

La biblioteca libsensors(3) proporciona una interfaz para obtener información sobre el hardware de monitorización del sistema, como temperaturas, voltajes y velocidades de ventilador.

Las funciones principales para interactuar con la biblioteca son:

  • sensors_init(): Inicializa la biblioteca. Debe llamarse antes que cualquier otra función de la biblioteca.
  • sensors_get_detected_chips(): Obtiene una lista de todos los chips de monitorización detectados en el sistema.
  • sensors_get_features(): Obtiene una lista de todas las características (temperaturas, voltajes, etc.) disponibles para un chip específico.
  • sensors_get_subfeatures(): Obtiene una lista de todas las subcaracterísticas (por ejemplo, diferentes sensores de temperatura dentro de un solo chip de temperatura) para una característica dada.
  • sensors_get_value(): Obtiene el valor numérico de una subcaracterística específica.
  • sensors_set_value(): Establece el valor de una subcaracterística específica (si es escribible).
  • sensors_get_label(): Obtiene una etiqueta legible por humanos para una subcaracterística específica.
  • sensors_get_adapter_name(): Obtiene el nombre del adaptador de hardware para un chip específico.
  • sensors_cleanup(): Libera los recursos utilizados por la biblioteca. Debe llamarse cuando ya no se necesite la biblioteca.

ESTRUCTURAS DE DATOS

Estructura sensors_chip_name contiene información relacionada con un chip de monitorización específico:

typedef struct sensors_chip_name {
const char *prefix;
const char *name;
const char *path;
} sensors_chip_name;

Existen otros miembros no documentados aquí, que son solo para uso interno de libsensors.

Estructura sensors_feature contiene información relacionada con una característica dada de un chip específico:

typedef struct sensors_feature {
const char *name;
int number;
sensors_feature_type type;
} sensors_feature;

Existen otros miembros no documentados aquí, que son solo para uso interno de libsensors.

Estructura sensors_subfeature contiene información relacionada con una subcaracterística dada de una característica de chip específica:

typedef struct sensors_subfeature {
const char *name;
int number;
sensors_subfeature_type type;
int mapping;
unsigned int flags;
} sensors_subfeature;

El campo flags es un campo de bits, su valor es una combinación de SENSORS_MODE_R (legible), SENSORS_MODE_W (escribible) y SENSORS_COMPUTE_MAPPING (afectado por las reglas de cálculo de la característica principal).

ARCHIVOS

/etc/sensors3.conf
/etc/sensors.conf

El archivo de configuración de libsensors(3) a nivel de sistema. Se intenta primero con /etc/sensors3.conf y, si no existe, se usa /etc/sensors.conf en su lugar.

/etc/sensors.d

Un directorio donde puede colocar archivos de configuración adicionales de libsensors. Los archivos que se encuentren en este directorio se procesarán en orden alfabético después del archivo de configuración predeterminado. Se ignoran los archivos cuyos nombres comiencen con un punto.
