DESCRIPCIÓN

libnids proporciona la funcionalidad de un componente E-box del sistema de detección de intrusiones en red (NIDS). Actualmente realiza:

1. Desfragmentación IP
2. Reensamblaje de flujos TCP
3. Detección de escaneo de puertos TCP

libnids realiza el reensamblaje TCP/IP de la misma manera que los kernels de Linux 2.0.36, y maneja correctamente todos los ataques implementados en fragrouter(8) (además de muchos otros ataques).

RUTINAS

nids_init() inicializa la aplicación para el sniffing, basado en los valores establecidos en la variable global nids_params, declarada como sigue:

struct nids_prm {
	int	n_tcp_streams;
	int	n_hosts;
	char	*device;
	char	*filename;
	int	sk_buff_size;
	int	dev_addon;
	void	(*syslog)(int type, int err, struct ip *iph, void *data);
	int	syslog_level;
	int	scan_num_hosts;
	int	scan_num_ports;
	int	scan_delay;
	void	(*no_mem)(void);
	int	(*ip_filter)(struct ip *iph);
	char	*pcap_filter;
	int	promisc;
	int	one_loop_less;
	int	pcap_timeout;
	int	multiproc;
	int	queue_limit;
	int	tcp_workarounds;
	pcap_t	*pcap_desc;
} nids_params;

Los miembros de esta estructura son:

n_tcp_streams
Tamaño de la tabla hash utilizada para almacenar información de conexión TCP (se seguirán simultáneamente un máximo de 3/4 * n_tcp_streams conexiones TCP). Valor predeterminado: 1024
n_hosts
Tamaño de la tabla hash utilizada para almacenar información de desfragmentación IP. Valor predeterminado: 256
filename
Si esta variable está establecida, libnids llamará a pcap_open_offline con esta variable como argumento (en lugar de pcap_open_live()). Valor predeterminado: NULL
device
Interfaz a monitorizar. Valor predeterminado: NULL (en cuyo caso se determina automáticamente un dispositivo apropiado). Si esta variable se asigna el valor all, libnids intentará capturar paquetes en todas las interfaces (lo cual solo funciona en Linux)
sk_buff_size
Tamaño de struct sk_buff (utilizado para poner en cola paquetes), que debe coincidir con el valor en los hosts que se están monitorizando. Valor predeterminado: 168
dev_addon
Número de bytes en struct sk_buff reservados para información de la capa de enlace. Valor predeterminado: -1 (en cuyo caso se determina automáticamente un desplazamiento apropiado basado en el tipo de capa de enlace)
syslog
Función de devolución de llamada de syslog, utilizada para informar de condiciones inusuales, como intentos de escaneo de puertos, banderas de cabecera TCP inválidas, etc. Valor predeterminado: nids_syslog (que registra mensajes a través de syslog(3) sin tener en cuenta la tasa de mensajes por segundo ni el espacio libre en disco)
syslog_level
Nivel de registro utilizado por nids_syslog para informar de eventos a través de syslog(3). Valor predeterminado: LOG_ALERT
scan_num_hosts
Tamaño de la tabla hash utilizada para almacenar información de escaneo de puertos (el número máximo de escaneos de puertos que se detectarán simultáneamente). Si se establece en 0, la detección de escaneo de puertos se deshabilitará. Valor predeterminado: 256
scan_num_ports
Número mínimo de puertos que deben ser escaneados desde el mismo host de origen antes de que se identifique como un escaneo de puertos. Valor predeterminado: 10
scan_delay
Retraso máximo (en milisegundos) entre conexiones a diferentes puertos para que se identifiquen como parte de un escaneo de puertos. Valor predeterminado: 3000
no_mem
Función de devolución de llamada de falta de memoria, utilizada para terminar el proceso llamante de forma elegante.
ip_filter
Función de devolución de llamada de filtrado IP, utilizada para descartar selectivamente paquetes IP, inspeccionados después del reensamblaje. Si la función devuelve un valor distinto de cero, el paquete se procesa; de lo contrario, se descarta. Valor predeterminado: nids_ip_filter (que siempre devuelve 1)
pcap_filter
Cadena de filtro pcap(3) aplicada a la capa de enlace (paquetes crudos, no reasemblados). Nota: filtros como ``tcp dst port 23'' NO manejarán correctamente el tráfico fragmentado adecuadamente, por ejemplo, fragmentos IP de 8 bytes; se debe agregar "or (ip[6:2] & 0x1fff != 0)" al final del filtro para procesar paquetes reensamblados. Valor predeterminado: NULL
promisc
Si es distinto de cero, libnids pondrá las interfaces en las que escucha en modo promiscuo. Valor predeterminado: 1
one_loop_less
Deshabilitado por defecto; ver comentarios en el archivo API.html
pcap_timeout
Establece el tiempo de espera de lectura de pcap, que puede ser o no soportado por tu plataforma. Valor predeterminado: 1024.
multiproc
Si es distinto de cero, crea un hilo separado para el procesamiento de paquetes. Ver API.html. Valor predeterminado: 0.
queue_limit
Si multiproc es distinto de cero, este es el número máximo de paquetes en cola en el hilo que lee paquetes de libpcap. Valor predeterminado: 20000
tcp_workarounds
Habilita verificaciones adicionales para implementaciones defectuosas de TCP, como las que permiten cerrar conexiones a pesar de que primero deberían haber retransmisiones para paquetes perdidos (como se indica en RFC 793, sección 3.5). Si es distinto de cero, libnids establecerá el estado NIDS_TIMED_OUT para conexiones cerradas bruscamente. Valor predeterminado: 0
pcap_desc
Si esta variable está establecida, libnids no llamará ni a pcap_open_live ni a pcap_open_offline, sino que utilizará un descriptor PCAP pre-abierto; úsalo con nids_pcap_handler() para alimentar interactivamente paquetes a libnids. Valor predeterminado: NULL

Devuelve 1 si tiene éxito, 0 si falla (en cuyo caso nids_errbuf contiene un mensaje de error apropiado).

nids_register_ip_frag() registra una función de devolución de llamada definida por el usuario para procesar todos los paquetes IP entrantes (incluidos fragmentos IP, paquetes con sumas de verificación inválidas, etc.).

nids_unregister_ip_frag() anula el registro de una función de devolución de llamada definida por el usuario para procesar todos los paquetes IP.

nids_register_ip() registra una función de devolución de llamada definida por el usuario para procesar paquetes IP validados y reasemblados por libnids.

nids_unregister_ip() anula el registro de una función de devolución de llamada definida por el usuario para procesar paquetes IP.

nids_register_udp() registra una función de devolución de llamada definida por el usuario para procesar paquetes UDP validados y reasemblados por libnids.

nids_unregister_udp() anula el registro de una función de devolución de llamada definida por el usuario para procesar paquetes UDP.

nids_register_tcp() registra una función de devolución de llamada definida por el usuario para procesar flujos TCP validados y reasemblados por libnids. Se llama a esta función cada vez que se recibe un paquete TCP para un flujo dado, y el miembro ts->data siempre contendrá el puntero al último paquete recibido.

nids_unregister_tcp() anula el registro de una función de devolución de llamada definida por el usuario para procesar flujos TCP.

nids_killtcp() marca el flujo TCP especificado para ser eliminado después de que la función de devolución de llamada actual regrese. Esto es útil cuando se detecta un evento de finalización de flujo malicioso (por ejemplo, un SYN flood).

nids_discard() marca el flujo TCP especificado para que los próximos numbytes no se procesen. Útil para evitar procesar paquetes después de detectar un SYN flood.

nids_run() inicia el bucle de sniffing. Esta función nunca regresa.

nids_dispatch(cnt) lee y procesa hasta cnt paquetes de la interfaz de red y luego regresa. Devuelve el número de paquetes procesados, o -1 si ocurrió un error.

nids_next() procesa un solo paquete de la interfaz de red y luego regresa. Devuelve 1 si se procesó un paquete, o 0 si no había paquetes disponibles (solo tiene sentido si se usa en modo no bloqueante con un tiempo de espera de pcap de 0).

nids_getfd() devuelve el descriptor de archivo utilizado por libpcap. Se puede utilizar para hacer que el bucle principal de la aplicación espere paquetes de red usando select(2) o poll(2).

nids_register_chksum_ctl() registra una lista de estructuras de nids_chksum_ctl para el control de la suma de verificación. El segundo argumento es el número de elementos en la matriz.

struct nids_chksum_ctl {
        struct tuple4       ip_src;
        struct tuple4       ip_dst;
        struct tcphdr       *tcp_hdr;
        struct udphdr       *udp_hdr;
        char                *data;
        int                 len;
        int                 *chksum_valid;
};

nids_pcap_handler() es la rutina de devolución de llamada de pcap. Se debe usar con nids_params.pcap_desc para alimentar interactivamente paquetes a libnids.

nids_find_tcp_stream() busca un flujo TCP existente basado en los campos de tupla de 4 bytes.

ERRORES

Los errores se informan a través de la variable global nids_errbuf, que contendrá una cadena descriptiva del error.

BUG

En la actualidad, libnids realiza el reensamblaje de IP y TCP solo para las redes IPv4.

NAME

libnids - network intrusion detection system library

SYNOPSIS

#include <sys/types.h>
#include <netinet/in.h>
#include <pcap.h>

#include <nids.h>

int nids_init(char *errbuf);

int nids_register_udp(void (*callback)(struct ip *, void *));
int nids_register_tcp(int (*callback)(struct tcp_stream *, void *));
int nids_unregister_udp(void (*callback)(struct ip *, void *));
int nids_unregister_tcp(int (*callback)(struct tcp_stream *, void *));
void nids_killtcp(struct tcp_stream *stream);
void nids_discard(struct tcp_stream *stream, int howmuch);
int nids_run(void);
int nids_dispatch(int cnt);
int nids_next(void);
int nids_getfd(void);
int nids_register_chksum_ctl(struct nids_chksum_ctl *ctl, int nctl);
void nids_pcap_handler(u_char *user, const struct pcap_pkthdr *pkthdr, const u_char *
    packet);
struct tcp_stream *nids_find_tcp_stream(struct tuple4 *tuple);
void nids_free_tcp_stream(struct tcp_stream *stream);

DESCRIPTION

libnids is a library designed to help programmers develop network-related applications, such as intrusion detection systems, network event trackers, and protocol analyzers. It provides a convenient interface to raw packet access, TCP stream reconstruction, and protocol validation. The library is written in C and can be used with programming languages that support C bindings.

The main features of libnids include:

Raw Packet Access:
The library allows direct access to raw network packets captured from an interface using libpcap.
TCP Stream Reconstruction:
It reconstructs TCP streams from individual packets, handling issues like packet reordering, retransmissions, and out-of-window data. This provides a coherent stream of data for analysis.
UDP and TCP Protocol Handling:
libnids can identify and track UDP and TCP connections. It allows user-defined callback functions to process packets and streams.
IP Fragment Reassembly:
The library handles IP fragmentation, reassembling fragmented IP datagrams before processing.
Checksum Handling:
libnids can perform checksum calculations for network packets, which is crucial for protocol validation and security analysis.

The library needs to be initialized using nids_init() before any other functions are called. It should be deinitialized using nids_exit() when the application terminates.

User-defined callback functions can be registered to handle specific types of network traffic. These callbacks receive processed data and can perform actions based on the content and context of the packets or streams.

ROUTINES

nids_init() initializes the libnids library. It takes an error buffer errbuf as an argument, which will be filled with a descriptive error message if initialization fails. It returns 1 on success and 0 on failure.

nids_exit() cleans up the libnids library resources. It should be called before the application exits.

nids_register_udp() registers a user-defined callback function to process UDP packets.

nids_register_tcp() registers a user-defined callback function to process TCP streams validated and reassembled by libnids. The tcp_stream structure is defined as follows:

struct tcp_stream {
	struct tuple4 {
		u_short source;
		u_short	dest;
		u_int	saddr;
		u_int	daddr;
	} addr;
	char			nids_state;
	struct half_stream {
		char	state;
		char	collect;
		char	collect_urg;
		char	*data;
		u_char	urgdata;
		int	count;
		int	offset;
		int	count_new;
		char	count_new_urg;
		...
	} client;
	struct half_stream	server;
	...
	void			*user;
};

The members of the tuple4 structure identify a unique TCP connection:

source, dest
Client and server port numbers
saddr, daddr
Client and server IP addresses

The members of the half_stream structure describe each half of a TCP connection (client and server):

state
Socket state (e.g. TCP_ESTABLISHED).
collect
A boolean which specifies whether to collect data for this half of the connection in the data buffer.
collect_urg
A boolean which specifies whether to collect urgent data pointed to by the TCP urgent pointer for this half of the connection in the urgdata buffer.
data
Buffer for normal data.
urgdata
One-byte buffer for urgent data.
count
The number of bytes appended to data since the creation of the connection.
offset
The current offset from the first byte stored in the data buffer, identifying the start of newly received data.
count_new
The number of bytes appended to data since the last invocation of the TCP callback function (if 0, no new data arrived).
count_new_urg
The number of bytes appended to urgdata since the last invocation of the TCP callback function (if 0, no new urgent data arrived).

The value of the nids_state field provides information about the state of the TCP connection, to be used by the TCP callback function:

NIDS_JUST_EST
Connection just established. Connection parameters in the addr structure are available for inspection. If the connection is interesting, the TCP callback function may specify which data it wishes to receive in the future by setting non-zero values for the collect or collect_urg variables in the appropriate client or server half_stream structure members.
NIDS_DATA
New data has arrived on a connection. The half_stream structures contain buffers of data.
NIDS_CLOSE, NIDS_RESET, NIDS_TIMED_OUT
Connection has closed. The TCP callback function should free any resources it may have allocated for this connection.

The param pointer passed by libnids as argument to the TCP callback function may be set to save a pointer to user-defined connection-specific data to pass to subsequent invocations of the TCP callback function (ex. the current working directory for an FTP control connection, etc.).

The user pointer in the tcp_stream structure has the same purpose except it is global to the stream, whereas the param pointer is different from one callback function to the other even though they were called for the same stream.

nids_unregister_tcp() unregisters a user-defined callback function to process TCP streams.

nids_killtcp() tears down the specified TCP connection with symmetric RST packets between client and server.

nids_discard() may be called from the TCP callback function to specify the number of bytes to discard from the beginning of the data buffer (updating the offset value accordingly) after the TCP callback function exits. Otherwise, the new data (totalling count_new bytes) will be discarded by default.

nids_run() starts the packet-driven application, reading packets in an endless loop, and invoking registered callback functions to handle new data as it arrives. This function does not return.

nids_dispatch() attempts to process cnt packets before returning, with a cnt of -1 understood as all packets available in one pcap buffer, or all packets in a file when reading offline. On success, returns the count of packets processed, which may be zero upon EOF (offline read) or upon hitting pcap_timeout (if supported by your platform). On failure, returns -1, putting an appropriate error message in nids_errbuf.

nids_next() process the next available packet before returning. Returns 1 on success, 0 if no packet was processed, setting nids_effbuf appropriately if an error prevented packet processing.

nids_getfd() may be used by an application sleeping in select(2) to snoop for a socket file descriptor present in the read fd_set. Returns the file descriptor on success, -1 on failure (in which case nids_errbuf contains an appropriate error message).

nids_register_chksum_ctl() takes as arguments an array of struct nids_chksum_ctl elements and the number of elements in the array. A nids_chksum_ctl element is defined as follows:

struct nids_chksum_ctl {
	u_int netaddr;
	u_int mask;
	u_int action;
	/* private members */
};

Internal checksumming functions will first check elements of this array one by one, and if the source ip SRCIP of the current packet satisfies condition


(SRCIP&chksum_ctl_array[i].mask)==chksum_ctl_array[i].netaddr

then if the action field is NIDS_DO_CHKSUM, the packet will be checksummed; if the action field is NIDS_DONT_CHKSUM, the packet will not be checksummed. If the packet matches none of the array elements, the default action is to perform checksumming.

nids_pcap_handler() may be used by an application already running a capture with libpcap, in order to pass frames to libnids interactively (frame per frame) instead of having libnids itself do the capture.

nids_find_tcp_stream() returns a pointer to the tcp_stream structure corresponding to the tuple passed as argument if libnids knows about this TCP connection already, otherwise it returns NULL.

nids_free_tcp_stream() removes the given tcp_stream from the list of streams tracked by libnids. Warning: its usage can result in crashes! See comments in the API.html file.
