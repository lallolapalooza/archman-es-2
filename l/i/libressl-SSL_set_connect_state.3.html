libressl-SSL_set_connect_state(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_SET_CONNECT_STATE(3) Manual de Funciones de Librería SSL_SET_CONNECT_STATE(3)

NOMBRE

SSL_set_connect_state, SSL_set_accept_state, SSL_is_server — prepara el objeto SSL para operar en modo cliente o servidor

SINOPSIS

librería “libssl” libcrypto
#include <openssl/ssl.h>

void
SSL_set_connect_state(SSL *ssl);

void
SSL_set_accept_state(SSL *ssl);

int
SSL_is_server(const SSL *ssl);

DESCRIPCIÓN

SSL_set_connect_state() configura ssl para operar en modo cliente.

SSL_set_accept_state() configura ssl para operar en modo servidor.

SSL_is_server() comprueba si ssl está configurado en modo servidor.

Cuando el objeto SSL_CTX fue creado con SSL_CTX_new(3), se le asignó un método dedicado para cliente, un método dedicado para servidor, o un método genérico que puede ser utilizado tanto para conexiones de cliente como de servidor. (El método podría haber sido cambiado con SSL_CTX_set_ssl_version(3) o SSL_set_ssl_method(3).)

Al iniciar una nueva negociación (handshake), el motor SSL debe saber si debe llamar a las rutinas de conexión (cliente) o aceptación (servidor). Aunque pueda estar claro por el método elegido si se solicitó el modo cliente o servidor, las rutinas de negociación deben ser configuradas explícitamente.

Al usar las rutinas SSL_connect(3) o SSL_accept(3), las rutinas de negociación correctas se configuran automáticamente. Al realizar una negociación transparente usando SSL_write(3) o SSL_read(3), las rutinas de negociación deben ser configuradas explícitamente de antemano usando SSL_set_connect_state() o SSL_set_accept_state().

Si SSL_is_server() se llama antes de que SSL_set_connect_state() o SSL_set_accept_state() fueran llamadas automática o explícitamente, el resultado depende del método utilizado al crear el SSL_CTX. Si se pasó un método genérico o un método dedicado para servidor a SSL_CTX_new(3), SSL_is_server() devuelve 1; de lo contrario, devuelve 0.

VALORES DE RETORNO

SSL_is_server() devuelve 1 si ssl está configurado en modo servidor o 0 si está configurado en modo cliente.

VER TAMBIÉN

ssl(3), SSL_accept(3), SSL_connect(3), SSL_CTX_new(3), SSL_CTX_set_ssl_version(3), SSL_do_handshake(3), SSL_new(3), SSL_read(3), SSL_write(3)

HISTORIA

SSL_set_connect_state() y SSL_set_accept_state() aparecieron por primera vez en SSLeay 0.6.0 y han estado disponibles desde OpenBSD 2.4.

SSL_is_server() apareció por primera vez en OpenSSL 1.0.2 y ha estado disponible desde OpenBSD 6.3.
