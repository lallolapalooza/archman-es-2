Nombre

libvirtd - demonio de gestión de libvirt

SINOPSIS

libvirtd [OPCIÓN]...

DESCRIPCIÓN

El programa libvirtd es el componente demonio del lado del servidor del sistema de gestión de virtualización libvirt.

Este demonio se ejecuta en los servidores anfitriones y realiza las tareas de gestión necesarias para los invitados virtualizados. Esto incluye actividades como iniciar, detener y migrar invitados entre servidores anfitriones, configurar y manipular la red, y gestionar el almacenamiento para su uso por parte de los invitados.

Las bibliotecas cliente y las utilidades de libvirt se conectan a este demonio para emitir tareas y recopilar información sobre la configuración y los recursos del sistema anfitrión y de los invitados.

Por defecto, el demonio libvirtd escucha las solicitudes en un socket de dominio Unix local. Utilizando la opción de línea de comandos -l | --listen, se puede instruir al demonio libvirtd para que escuche adicionalmente en un socket TCP/IP. El socket TCP/IP a usar se define en el archivo de configuración de libvirtd.

Reiniciar libvirtd no afecta a los invitados en ejecución. Los invitados continúan operando y serán recuperados automáticamente si su configuración XML ha sido definida. Cualquier invitado cuya configuración XML no haya sido definida se perderá de la configuración.

ACTIVACIÓN POR SOCKET DEL SISTEMA

El demonio libvirtd es capaz de iniciarse en dos modos.

En el modo tradicional, creará y escuchará en sockets UNIX él mismo. Si se proporciona el parámetro --listen, también escuchará en socket(s) TCP/IP, de acuerdo con las opciones listen_tcp y listen_tls en /etc/libvirt/libvirtd.conf

En modo de activación por socket, dependerá de systemd para crear y escuchar en los sockets UNIX, y opcionalmente TCP/IP, y pasarlos como descriptores de archivo pre-abiertos. En este modo, no está permitido pasar el parámetro --listen, y la mayoría de las opciones de configuración relacionadas con el socket en /etc/libvirt/libvirtd.conf ya no tendrán ningún efecto. Para habilitar sockets TCP o TLS, use:

$ systemctl start libvirtd-tls.socket

O

$ systemctl start libvirtd-tcp.socket

El modo de activación por socket es generalmente el predeterminado cuando se ejecuta en un sistema operativo anfitrión que utiliza systemd. Para volver al modo tradicional, todos los archivos de unidad de socket deben ser enmascarados:

$ systemctl mask libvirtd.socket libvirtd-ro.socket \
   libvirtd-admin.socket libvirtd-tls.socket libvirtd-tcp.socket

Además de eso, asegúrese de que el argumento --timeout no se utilice para el demonio, ya que no se iniciaría ante ninguna conexión posterior.

Si se utiliza el servicio libvirt-guests, el ordenamiento para ese servicio debe adaptarse para que se ordene después de la unidad de servicio en lugar de la unidad de socket. Dado que las dependencias y el ordenamiento no pueden modificarse con sobrescrituras de caída, se debe cambiar el archivo de unidad completo de libvirt-guests. Para conservar dicho cambio, copie el archivo instalado /usr/lib/systemd/system/libvirt-guests.service a /etc/systemd/system/libvirt-guests.service y realice el cambio allí, específicamente asegúrese de que el ordenamiento After= mencione libvirtd.service y no libvirtd.socket:

[Unit]
After=libvirtd.service

OPCIONES

-h, --help

Muestra la ayuda de uso de la línea de comandos y sale.

-d, --daemon

Ejecutar como demonio y escribir archivo PID.

-f, --config *ARCHIVO*

Usar este archivo de configuración, anulando el valor predeterminado.

-l, --listen

Escuchar conexiones TCP/IP. Esto no debe configurarse si se utiliza la activación por socket de systemd. En su lugar, active los archivos de unidad libvirtd-tls.socket o libvirtd-tcp.socket.

-p, --pid-file *ARCHIVO*

Usar este nombre para el archivo PID, anulando el valor predeterminado.

-t, --timeout *SEGUNDOS*

Salir después de un período de tiempo de espera (en segundos), siempre que no haya conexiones de cliente ni dominios en ejecución.

-v, --verbose

Habilitar la salida de mensajes detallados.

--version

Mostrar información de versión y salir.

SEÑALES

Al recibir SIGHUP, libvirtd recargará su configuración.

ARCHIVOS

Cuando se ejecuta como root

•
/etc/libvirt/libvirtd.conf

El archivo de configuración predeterminado utilizado por libvirtd, a menos que se anule en la línea de comandos utilizando la opción -f | --config.

Dependiendo del controlador instalado, también se leen los siguientes archivos:

  • /etc/libvirt/qemu.conf para el controlador QEMU
  • /etc/libvirt/lxc.conf para el controlador LXC
  • /etc/libvirt/libxl.conf para el controlador libxl

Estos archivos contienen varias configuraciones y valores predeterminados para las máquinas virtuales creadas dentro de sus respectivos controladores, y ofrecen una forma de anular los valores predeterminados integrados, por ejemplo (pero sin limitarse a): rutas a varios binarios suplementarios, ubicación de certificados TLS, configuración de consolas gráficas y otros. La ubicación de ninguno de estos archivos puede ser anulada por ninguna opción de línea de comandos.

  • /run/libvirt/libvirt-sock
  • /run/libvirt/libvirt-sock-ro

Los sockets que usará libvirtd.

•
/etc/pki/CA/cacert.pem

El certificado de la Autoridad de Certificación TLS que usará libvirtd.

•
/etc/pki/libvirt/servercert.pem

El certificado de Servidor TLS que usará libvirtd.

•
/etc/pki/libvirt/private/serverkey.pem

La clave privada del Servidor TLS que usará libvirtd.

•
/run/libvirtd.pid

El archivo PID a usar, a menos que se anule con la opción -p | --pid-file.

Cuando se ejecuta como no root

•
$XDG_CONFIG_HOME/libvirt/libvirtd.conf

El archivo de configuración predeterminado utilizado por libvirtd, a menos que se anule en la línea de comandos utilizando la opción -f``|--config``.

Si se instala el controlador QEMU, también se lee el siguiente archivo:

•
$XDG_CONFIG_HOME/libvirt/qemu.conf

Si el archivo existe, puede contener varias configuraciones y valores predeterminados para las máquinas virtuales creadas dentro del controlador QEMU, y ofrece una forma de anular los valores predeterminados integrados, por ejemplo (pero sin limitarse a): rutas a varios binarios suplementarios, ubicación de certificados TLS, configuración de consolas gráficas y otros. La ubicación de este archivo no puede ser anulada por ninguna opción de línea de comandos.

•
$XDG_RUNTIME_DIR/libvirt/libvirt-sock

El socket que usará libvirtd.

•
$HOME/.pki/libvirt/cacert.pem

El certificado de la Autoridad de Certificación TLS que usará libvirtd.

•
$HOME/.pki/libvirt/servercert.pem

El certificado de Servidor TLS que usará libvirtd.

•
$HOME/.pki/libvirt/serverkey.pem

La clave privada del Servidor TLS que usará libvirtd.

&#x

FILES

$XDG_RUNTIME_DIR/libvirt/libvirtd.pid

El archivo PID a utilizar, a menos que sea anulado por la opción -p``|--pid-file``.

Si $XDG_CONFIG_HOME no está configurado en su entorno, libvirtd usará $HOME/.config

Si $XDG_RUNTIME_DIR no está configurado en su entorno, libvirtd usará $HOME/.cache

EJEMPLOS

Para obtener la versión de libvirtd:

# libvirtd --version
libvirtd (libvirt) 11.10.0

Para iniciar libvirtd, indicándole que se desvincule y cree un archivo PID:

# libvirtd -d
# ls -la /run/libvirtd.pid
-rw-r--r-- 1 root root 6 Jul  9 02:40 /run/libvirtd.pid
