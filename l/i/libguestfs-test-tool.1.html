NOMBRE

libguestfs-test-tool - Diagnóstico para libguestfs

SINOPSIS

libguestfs-test-tool [--options]

DESCRIPCIÓN

libguestfs-test-tool es un programa de prueba incluido con libguestfs para permitirle verificar que la funcionalidad básica de libguestfs está funcionando. Esto es necesario porque libguestfs ocasionalmente se rompe por razones fuera de nuestro control: generalmente debido a cambios en los paquetes subyacentes de qemu o del kernel, o en el entorno del host.

Si sospecha un problema en libguestfs, simplemente ejecute:

libguestfs-test-tool

Imprimirá muchos mensajes de diagnóstico.

Si se ejecuta hasta completarse con éxito, verá esto cerca del final:

===== TEST FINISHED OK =====

y la herramienta de prueba saldrá con el código 0.

Si falla (y/o sale con un código de error distinto de cero), por favor, pegue la salida *completa y sin editar* de la herramienta de prueba en un informe de error. Puede encontrar más información sobre cómo informar de errores en el sitio web http://libguestfs.org/.

OPCIONES

--help
Muestra información de uso breve y sale.
--qemu qemu_binary
Si ha descargado otro binario de qemu, apunte esta opción a la ruta completa del binario para probarlo.
--qemudir qemu_source_dir
Si ha compilado qemu desde el código fuente, apunte esta opción al directorio fuente para probarlo.
-t N
--timeout N
Establece el tiempo de espera de lanzamiento a "N" segundos. El valor predeterminado es 600 segundos (10 minutos), que normalmente no necesita ajustarse.
-V
--version
Muestra el número de versión de libguestfs y sale.

PROBANDO UNA VERSIÓN DIFERENTE DE QEMU

Si ha compilado otra versión de qemu desde el código fuente y desea probarla, puede usar la opción --qemudir para apuntar al directorio fuente de qemu.

Si ha descargado un binario de qemu de algún lugar, use la opción --qemu para apuntar al binario.

Tenga en cuenta que al usar estas opciones, puede ignorar el asunto de los scripts de envoltura de qemu ("QEMU WRAPPERS" en guestfs(3)), ya que libguestfs-test-tool escribe un script de envoltura para usted si es necesario.

PROBANDO UN NÚCLEO DIFERENTE

Puede indicar a supermin que intente usar un núcleo diferente. Haga esto estableciendo las variables de entorno "SUPERMIN_KERNEL", "SUPERMIN_KERNEL_VERSION" y/o "SUPERMIN_MODULES".

Consulte "ENVIRONMENT VARIABLES" en supermin(1) para obtener más información.

PROBANDO UNA VERSIÓN DIFERENTE DE LIBVIRT

Para averiguar qué backend es el predeterminado en su paquete libguestfs, haga:

unset LIBGUESTFS_BACKEND
guestfish get-backend

Si está utilizando el backend libvirt, puede probar una versión diferente (por ejemplo, upstream) de libvirt ejecutando estos comandos ( *no* como root):

killall libvirtd lt-libvirtd
~/path/to/libvirt/run libguestfs-test-tool

El primer comando mata cualquier proceso "libvirtd" de sesión que pueda estar en ejecución en la máquina. El segundo comando utiliza el script "run" de libvirt (en el directorio de compilación de nivel superior de libvirt) para establecer algunas variables de entorno de modo que se utilice la versión alternativa de libvirt para ejecutar el programa.

PROBANDO CON / SIN LIBVIRT

Para averiguar qué backend es el predeterminado en su paquete libguestfs, haga:

unset LIBGUESTFS_BACKEND
guestfish get-backend

Si está utilizando el backend libvirt, puede probar sin él (es decir, libguestfs lanzando qemu directamente) haciendo:

export LIBGUESTFS_BACKEND=direct

O si está utilizando el backend predeterminado (directo), puede probar libvirt:

export LIBGUESTFS_BACKEND=libvirt

o con libvirt y una URI de libvirt específica:

export LIBGUESTFS_BACKEND=libvirt:qemu:///session

PROBANDO CON AJUSTES DIFERENTES DE SELINUX

Para averiguar qué backend es el predeterminado en su paquete libguestfs, haga:

unset LIBGUESTFS_BACKEND
guestfish get-backend

Para averiguar si SELinux se está utilizando, haga:

getenforce

Si está utilizando libvirt, SELinux y sVirt, puede intentar ver si cambiar SELinux a modo "permisivo" marca alguna diferencia. Use este comando como root:

setenforce Permissive

Si esto marca una diferencia, busque en los registros de auditoría fallos recientes ("AVC"):

ausearch -m avc -ts recent

Puede convertir los AVCs en reglas de política SELinux sugeridas utilizando herramientas como audit2allow(1). Para más información, consulte la "Security Enhanced Linux User Guide".

Para volver a habilitar SELinux y sVirt, haga:

setenforce Enforcing

AUTO-DIAGNÓSTICO

Consulte "APPLIANCE BOOT PROCESS" en guestfs(3) para comprender los mensajes producidos por libguestfs-test-tool y/o posibles errores.

ESTADO DE SALIDA

libguestfs-test-tool devuelve 0 si las pruebas se completaron sin errores, o 1 si hubo un error.

VARIABLES DE ENTORNO

Para obtener la lista completa de variables de entorno que pueden afectar a libguestfs, consulte la página del manual de guestfs(3).

VER TAMBIÉN
