libressl-RC2_encrypt(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

RC2_ENCRYPT(3) Manual de funciones de biblioteca RC2_ENCRYPT(3)

NOMBRE

RC2_set_key, RC2_encrypt, RC2_decrypt, RC2_cbc_encrypt, RC2_ecb_encrypt, RC2_cfb64_encrypt, RC2_ofb64_encrypt — funciones de bajo nivel para Rivest Cipher 2

SINOPSIS

biblioteca “libcrypto”
#include <openssl/rc2.h>

void
RC2_set_key(RC2_KEY *expanded_key, int len, const unsigned char *user_key, int effective_bits);

void
RC2_encrypt(unsigned long *data, RC2_KEY *expanded_key);

void
RC2_decrypt(unsigned long *data, RC2_KEY *expanded_key);

void
RC2_cbc_encrypt(const unsigned char *in, unsigned char *out, long length, RC2_KEY *expanded_key, unsigned char *iv, int encrypt);

void
RC2_ecb_encrypt(const unsigned char *in, unsigned char *out, RC2_KEY *expanded_key, int encrypt);

void
RC2_cfb64_encrypt(const unsigned char *in, unsigned char *out, long length, RC2_KEY *expanded_key, unsigned char *iv, int *num, int encrypt);

void
RC2_ofb64_encrypt(const unsigned char *in, unsigned char *out, long length, RC2_KEY *expanded_key, unsigned char *iv, int *num);

DESCRIPCIÓN

RC2 es un cifrado de bloque que opera sobre bloques de RC2_BLOCK = 8 bytes, equivalente a 64 bits, utilizando una longitud de clave variable con un parámetro adicional llamado “bits efectivos de clave” o “longitud efectiva de clave”. La longitud efectiva máxima de clave es 1024 bits.

Si no se puede evitar el uso de RC2, se recomienda que los programas de aplicación utilicen la familia de funciones EVP_rc2_cbc(3) en lugar de las funciones documentadas en esta página del manual, para facilitar la migración posterior a algoritmos de cifrado menos obsoletos.

RC2_set_key() expande los primeros len bytes de user_key en la estructura RC2_KEY *expanded_key. El almacenamiento para la clave expandida debe ser proporcionado por el código de llamada. Si el argumento len excede 128, solo se utilizan los primeros 128 bytes.

Opcionalmente, si el argumento effective_bits es positivo y menor que 1024, la longitud efectiva de clave de *expanded_key se reduce a effective_bits. Reducir la longitud efectiva de clave no es criptográficamente útil. Esta opción fue diseñada originalmente para cumplir con las regulaciones de exportación de EE. UU. vigentes en ese momento, que estaban diseñadas para permitir al gobierno de EE. UU. espiar comunicaciones cifradas extranjeras. A menos que la interoperabilidad lo requiera, se recomienda establecer effective_bits en 1024.

RC2_encrypt() y RC2_decrypt() interpretan data como un arreglo de dos enteros de 32 bits y cifran o descifran ese único bloque en el lugar, respectivamente, usando la expanded_key.

Las funciones restantes codifican o decodifican length bytes comenzando en in a length bytes comenzando en out en varios modos de operación utilizando la expanded_key. Ambos arreglos deben ser lo suficientemente largos para contener length bytes redondeados al siguiente múltiplo de 8. El argumento iv apunta a un arreglo de 8 bytes utilizado como vector de inicialización. Si el argumento encrypt es RC2_ENCRYPT o cualquier otro valor distinto de cero, se realiza el cifrado; si es RC2_DECRYPT = 0, se realiza el descifrado.

RC2_cbc_encrypt() opera en modo de encadenamiento de bloques de cifrado.

RC2_ecb_encrypt() codifica o decodifica ocho bytes en in a ocho bytes en out en modo de libro de códigos electrónico.

RC2_cfb64_encrypt() y RC2_ofb64_encrypt() operan en modo de retroalimentación de cifrado y modo de retroalimentación de salida, respectivamente, con bloques de 64 bits. El número de bytes utilizados del último bloque de 8 bytes se rastrea en *num.

VER TAMBIÉN

crypto(3), EVP_EncryptInit(3), EVP_rc2_cbc(3)

HISTORIA

RC2_set_key(), RC2_encrypt(), RC2_cbc_encrypt(), RC2_ecb_encrypt(), RC2_cfb64_encrypt(), y RC2_ofb64_encrypt() aparecieron por primera vez en SSLeay 0.5.2. RC2_decrypt() apareció por primera vez en SSLeay 0.9.0. Todas estas funciones han estado disponibles desde OpenBSD 2.4.
