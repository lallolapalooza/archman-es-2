NOMBRE

libunwind-coredump -- soporte coredump() en libunwind

SINOPSIS

#include <libunwind-coredump.h>

unw_accessors_t _UCD_accessors;

struct UCD_info *_UCD_create(char const *);
void _UCD_destroy(struct UCD_info *);

int _UCD_get_num_threads(struct UCD_info *);
void _UCD_select_thread(struct UCD_info *, int);
void _UCD_get_pid(struct UCD_info *);
void _UCD_get_cursig(struct UCD_info *);

int _UCD_find_proc_info(unw_addr_space_t, unw_word_t, unw_proc_info_t *, int, void *);
void _UCD_put_unwind_info(unw_addr_space_t, unw_proc_info_t *, void *);
int _UCD_get_dyn_info_list_addr(unw_addr_space_t, unw_word_t *, void *);
int _UCD_access_mem(unw_addr_space_t, unw_word_t, unw_word_t *, int, void *);
int _UCD_access_reg(unw_addr_space_t, unw_regnum_t, unw_word_t *, int, void *);
int _UCD_access_fpreg(unw_addr_space_t, unw_regnum_t, unw_fpreg_t *, int, void *);
int _UCD_get_proc_name(unw_addr_space_t, unw_word_t, char *, size_t, unw_word_t *, void *);
int _UCD_resume(unw_addr_space_t, unw_cursor_t *, void *);

DESCRIPCIÓN

Es posible generar una instantánea del estado de un proceso en un momento específico y guardarla en un archivo formateado especialmente llamado coredump. Esto a menudo ocurre automáticamente cuando un proceso encuentra un error irrecuperable y el propio sistema operativo captura el estado del proceso cuando ocurrió el error. libunwind proporciona una biblioteca que puede usarse como parte de una herramienta ligera para generar información útil sobre por qué el proceso terminó de forma anormal (como un rastreo de pila de todos los hilos de ejecución). Las rutinas y variables que implementan esta funcionalidad usan el prefijo _UCD, que significa ``unwind-via-coredump''.

Una aplicación que quiera usar el acceso remoto a coredump primero debe crear un nuevo espacio de direcciones libunwind que represente al proceso objetivo. Esto se hace llamando a unw_create_addr_space(). En muchos casos, la aplicación simplemente querrá pasar la dirección de _UCD_accessors como primer argumento a esta rutina. Hacerlo asegurará que libunwind pueda desenrollar correctamente el proceso objetivo. Sin embargo, en circunstancias especiales, una aplicación puede preferir usar solo porciones de la instalación _UCD. Por esta razón, las rutinas de devolución de llamada individuales (_UCD_find_proc_info(), _UCD_put_unwind_info(), etc.) también están disponibles para uso directo. Por supuesto, las direcciones de estas rutinas también podrían obtenerse de _UCD_accessors, pero hacerlo evitaría la inicialización estática. Además, al usar _UCD_accessors, *todas* las rutinas de devolución de llamada se vincularán a la aplicación, incluso si nunca se llaman.

A continuación, la aplicación necesita cargar el archivo core para su análisis y crear una estructura UCD_info (opaca) llamando a _UCD_create(), pasando el nombre del archivo core. El puntero opaco devuelto luego debe pasarse como el puntero de ``argumento'' (tercer argumento) a unw_init_remote().

Cuando la aplicación haya terminado de usar libunwind en el archivo core, se debe llamar a _UCD_destroy(), pasándole el puntero que fue devuelto por la llamada correspondiente a _UCD_create(). Esto asegura que se liberen toda la memoria y otros recursos.

_UCD_get_num_threads()

Obtiene el número de hilos en el archivo core.
_UCD_get_pid()

Obtiene el ID del proceso asociado con el archivo core.
_UCD_get_cursig()

Obtiene la señal actual recibida por el proceso asociado con el archivo core (si la hay).
_UCD_select_thread()

Selecciona el hilo actual para desenrollar.

SEGURIDAD DE HILOS

El acceso remoto coredump asume que una única estructura _UCD_info nunca se comparte entre hilos. Debido a esto, no se usa bloqueo explícito. Mientras solo un hilo use una estructura _UCD_info en un momento dado, esta funcionalidad es segura para hilos.

VALOR DE RETORNO

_UCD_create() puede devolver un puntero nulo si falla al crear el UCD_info por cualquier motivo.
