DESCRIPCIÓN

CMS_get0_RecipientInfos() devuelve todas las estructuras RecipientInfo asociadas con la estructura EnvelopedData cms.

CMS_RecipientInfo_type() devuelve el tipo de ri:

CMS_RECIPINFO_TRANS para KeyTransRecipientInfo,
CMS_RECIPINFO_AGREE para KeyAgreeRecipientInfo,
CMS_RECIPINFO_KEK para KEKRecipientInfo,
CMS_RECIPINFO_PASS para PasswordRecipientinfo, o
CMS_RECIPINFO_OTHER para OtherRecipientInfo.

CMS_RecipientInfo_ktri_get0_signer_id() recupera el identificador de certificado RecipientIdentifier asociado con la estructura KeyTransRecipientInfo ri. O bien se establece el SubjectKeyIdentifier en keyid o el nombre del emisor y el número de serie en issuer y sno.

CMS_RecipientInfo_ktri_cert_cmp() compara el certificate con la estructura KeyTransRecipientInfo ri.

CMS_RecipientInfo_set0_pkey() asocia la clave privada pkey con la estructura KeyTransRecipientInfo ri.

CMS_RecipientInfo_kekri_get0_id() recupera la información de clave de la estructura KEKRecipientInfo ri. Los campos se copian de la siguiente manera:

keyEncryptionAlgorithm a *palg,
keyIdentifier a *pid,
date a *pdate (opcional),
other.keyAttrId a *potherid (opcional),
other.keyAttr a *pothertype (opcional).
Donde un campo es opcional y está ausente, se escribe NULL en el parámetro correspondiente. Los parámetros que no interesan a la aplicación pueden establecerse en NULL.

CMS_RecipientInfo_kekri_id_cmp() compara el identificador en los parámetros id y idlen con el campo keyIdentifier de la estructura KEKRecipientInfo ri.

CMS_RecipientInfo_set0_key() asocia la clave simétrica key de longitud keylen con la estructura KEKRecipientInfo ri.

CMS_RecipientInfo_decrypt() intenta descifrar la estructura RecipientInfo ri en cms. Primero se debe haber asociado una clave con ri.

CMS_RecipientInfo_encrypt() intenta cifrar la estructura RecipientInfo ri en cms. Primero se debe haber asociado una clave con ri y la clave de cifrado de contenido debe estar disponible, por ejemplo, mediante una llamada anterior a CMS_RecipientInfo_decrypt().

El propósito principal de estas funciones es permitir a una aplicación buscar claves de destinatario utilizando cualquier técnica apropiada cuando el método más simple de CMS_decrypt(3) no sea adecuado.

En el uso típico, una aplicación recupera todas las estructuras CMS_RecipientInfo usando CMS_get0_Recipien

DESCRIPTION

The CMS_get0_RecipientInfos() function retrieves a pointer to the stack of CMS_RecipientInfo structures within the supplied cms structure.

The CMS_RecipientInfo_type() function returns the type of the recipient information. This will be one of the following constants:

CMS_RECIPIENTINFO_KEYTRANS
Key Transport type.
CMS_RECIPIENTINFO_KEYAGREE
Key Agreement type.
CMS_RECIPIENTINFO_KEK
Key Encryption Key type.
CMS_RECIPIENTINFO_PASSWD
Password based type.

For a CMS_RecipientInfo structure of type CMS_RECIPIENTINFO_KEYTRANS, CMS_RecipientInfo_ktri_get0_signer_id() retrieves the issuer name, subject key identifier (SKI) and any attributes in iattrs, and optionally the associated certificate in icert.

Compares the key transport recipient info ri with certificate cert. Returns 0 if they match, non-zero otherwise.

For a CMS_RecipientInfo structure of type CMS_RECIPIENTINFO_KEYTRANS, associates the private key pkey with the recipient info. The private key is not copied and its lifetime is managed by the caller.

For a CMS_RecipientInfo structure of type CMS_RECIPIENTINFO_KEK, retrieves the key identifier in id, the originator identifier, and the KEKRecipientInfo structure itself in kekri.

Compares the key encryption key recipient info riid. Returns 0 if they match, non-zero otherwise.

Associates the secret key key of length keylen with the recipient info. The key is not copied and its lifetime is managed by the caller.

Decrypts the content-encryption key using the recipient information ri. The cms parameter must contain the enveloped-data. This function is typically called after retrieving recipient info using CMS_get0_RecipientInfos() and checking the type of each using CMS_RecipientInfo_type(). Depending on the type, the CMS_RecipientInfo structure can be ignored or its key identifier data retrieved using an appropriate function. If the corresponding secret or private key can be obtained by any appropriate means, it can then be associated with the structure and CMS_RecipientInfo_decrypt() called. If successful, CMS_decrypt(3) can be called with a NULL key to decrypt the enveloped content.

The function CMS_RecipientInfo_encrypt() can be used to add a new recipient to an existing enveloped data structure. Typically an application will first decrypt an appropriate CMS_RecipientInfo structure to make the content encrypt key available. It will then add a new recipient using a function such as CMS_add1_recipient_cert(3) and finally encrypt the content encryption key using CMS_RecipientInfo_encrypt().

RETURN VALUES

CMS_get0_RecipientInfos() returns an internal pointer to all the CMS_RecipientInfo structures, or NULL if an error occurs.

CMS_RecipientInfo_type() returns an integer constant.

CMS_RecipientInfo_ktri_get0_signer_id(), CMS_RecipientInfo_set0_pkey(), CMS_RecipientInfo_kekri_get0_id(), CMS_RecipientInfo_set0_key(), CMS_RecipientInfo_decrypt(), and CMS_RecipientInfo_encrypt() return 1 for success or 0 if an error occurs.

CMS_RecipientInfo_ktri_cert_cmp() and CMS_RecipientInfo_kekri_id_cmp() return 0 when ri matches or non-zero otherwise.

Any error can be obtained from ERR_get_error(3).
