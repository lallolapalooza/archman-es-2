SSL_WRITE(3) Manual de funciones de la biblioteca SSL_WRITE(3)

NOMBRE

SSL_write_ex, SSL_write — escribir bytes en una conexión TLS

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_write_ex(SSL *ssl, const void *buf, size_t num, size_t *written);

int
SSL_write(SSL *ssl, const void *buf, int num);

DESCRIPCIÓN

SSL_write_ex() y SSL_write() escriben num bytes del búfer buf en la conexión ssl especificada. En caso de éxito, SSL_write_ex() almacena el número de bytes escritos en *written.

En adelante, SSL_write_ex() y SSL_write() se denominan “funciones de escritura”.

Si es necesario, una función de escritura negocia una sesión TLS, si no se ha realizado explícitamente mediante SSL_connect(3) o SSL_accept(3). Si el par solicita una renegociación, se realizará de forma transparente durante la operación de la función de escritura. El comportamiento de las funciones de escritura depende del BIO subyacente.

Para que la negociación transparente tenga éxito, ssl debe haber sido inicializado en modo cliente o servidor. Esto se hace llamando a SSL_set_connect_state(3) o SSL_set_accept_state(3) antes de la primera llamada a una función de escritura.

Si el BIO subyacente está en modo bloqueante, la función de escritura solo devolverá una vez que la operación de escritura se haya completado o se haya producido un error, excepto cuando tiene lugar una renégociación, en cuyo caso puede producirse una SSL_ERROR_WANT_READ. Este comportamiento puede controlarse con la bandera SSL_MODE_AUTO_RETRY de la llamada SSL_CTX_set_mode(3).

Si el BIO subyacente es no bloqueante, la función de escritura también devolverá cuando el BIO subyacente no pueda satisfacer las necesidades de la función para continuar la operación. En este caso, una llamada a SSL_get_error(3) con el valor de retorno de la función de escritura devolverá SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE. Dado que en cualquier momento es posible una renégociación, una llamada a una función de escritura también puede provocar operaciones de lectura. El proceso que llama debe repetir la llamada después de tomar las medidas adecuadas para satisfacer las necesidades de la función de escritura. La acción depende del BIO subyacente. Al usar un socket no bloqueante, no hay nada que hacer, pero se puede usar select(2) para comprobar la condición requerida. Al usar un BIO de almacenamiento en búfer, como un par de BIO, los datos deben escribirse en o recuperarse del BIO antes de poder continuar.

Las funciones de escritura solo devolverán éxito cuando se hayan escrito los contenidos completos de buf con longitud num. Este comportamiento predeterminado puede cambiarse con la opción SSL_MODE_ENABLE_PARTIAL_WRITE de SSL_CTX_set_mode(3). Cuando esta bandera está establecida, las funciones de escritura también devolverán éxito cuando se haya completado con éxito una escritura parcial. En este caso, la operación de la función de escritura se considera completada. Los bytes se envían y se debe iniciar una nueva llamada de escritura con un nuevo búfer (con los bytes ya enviados eliminados). Se realiza una escritura parcial con el tamaño de un bloque de mensaje, que es de 16 KB.

Cuando una llamada a una función de escritura debe repetirse porque SSL_get_error(3) devolvió SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE, debe repetirse con los mismos argumentos.

Al llamar a SSL_write() con num=0 bytes para enviar, el comportamiento no está definido. Se puede llamar a SSL_write_ex() con num=0, pero no enviará datos de aplicación al par.

VALORES DE RETORNO

SSL_write_ex() devuelve 1 para éxito o 0 para fallo. El éxito significa que todos los bytes de datos de aplicación solicitados se han escrito en la conexión TLS o, si SSL_MODE_ENABLE_PARTIAL_WRITE está en uso, se ha escrito al menos un byte de datos de aplicación en la conexión TLS. El fallo significa que aún no se han escrito todos los bytes solicitados (si SSL_MODE_ENABLE_PARTIAL_WRITE no está en uso) o que no se ha podido escribir ningún byte en la conexión TLS (si SSL_MODE_ENABLE_PARTIAL_WRITE está en uso). Los fallos pueden ser reintentables (por ejemplo, el búfer de escritura de red se ha llenado temporalmente) o no reintentables (por ejemplo, un error de red fatal). En caso de fallo, llame a SSL_get_error(3) para averiguar la razón, que indicará si la llamada es reintentable o no.

Para SSL_write(), pueden producirse los siguientes valores de retorno:

>0
La operación de escritura fue exitosa. El valor de retorno es el número de bytes realmente escritos en la conexión TLS.
0
La operación de escritura no fue exitosa. Probablemente la conexión subyacente se cerró. Llame a SSL_get_error(3) con el valor de retorno para averiguar si se produjo un error o si la conexión se cerró limpiamente (SSL_ERROR_ZERO_RETURN).
<0
La operación de escritura no fue exitosa, ya sea porque ocurrió un error o porque el proceso que llama debe tomar alguna acción. Llame a SSL_get_error(3) con el valor de retorno para averiguar la razón.

HISTORIA

SSL_write() apareció en SSLeay 0.4 o anterior y ha estado disponible desde OpenBSD 2.4.

SSL_write_ex() apareció por primera vez en OpenSSL 1.1.1 y ha estado disponible desde OpenBSD 7.1.
