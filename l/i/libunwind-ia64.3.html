LIBUNWIND-IA64(3libunwind) Programming Library LIBUNWIND-IA64(3libunwind)

NOMBRE

libunwind-ia64 -- Soporte específico de IA-64 en libunwind

INTRODUCCIÓN

La versión IA-64 de libunwind utiliza una cadena de plataforma "ia64" y, al menos en teoría, debería poder soportar todos los sistemas operativos que cumplan con la ABI específica del procesador definida para la Itanium Processor Family. Esto incluye tanto Linux de endianness pequeño como HP-UX de endianness grande. Además, para hacer posible que una única biblioteca desenrolle objetivos de 32 y 64 bits, el tipo `unw_word_t` siempre se define como de 64 bits de ancho (independientemente del tamaño de palabra natural del host). Dicho esto, la implementación actual solo ha sido probada con IA-64 Linux.

Al dirigirse a IA-64, el archivo de cabecera de libunwind define la macro `UNW_TARGET_IA64` como 1 y la macro `UNW_TARGET` como "ia64" (sin las comillas). La primera hace posible que el código de desenrollado dependiente de la plataforma utilice compilación condicional para seleccionar una implementación adecuada. La segunda es útil para fines de ``stringification'' y para construir símbolos específicos de la plataforma objetivo.

Una característica especial de IA-64 es el uso de bits NaT para soportar la ejecución especulativa. A menudo, los bits NaT se consideran el "sexto-primer bit" de un registro general. Sin embargo, para que todo quepa en valores `unw_word_t` de 64 bits, libunwind trata los bits NaT como registros booleanos separados, cuyo valor de 64 bits es VERDADERO (no cero) o FALSO (cero).

ESTADO DE LA MÁQUINA

El estado de la máquina (conjunto de registros) al que se puede acceder a través de libunwind depende del tipo de marco de pila al que apunta un cursor. Para marcos normales, todos los registros "preservados" (guardados por el callee) son accesibles. Para marcos de "trampolín" de señal, todos los registros (incluidos los registros "scratch" (guardados por el caller)) son accesibles. La mayoría de las aplicaciones no tienen que preocuparse a priori sobre qué registros son accesibles en cada momento. En caso de duda, siempre es seguro *intentar* acceder a un registro (a través de `unw_get_reg()` o `unw_get_fpreg()`) y si el registro no es accesible, la llamada fallará con un valor de retorno de -UNW_EBADREG.

Como una excepción especial a la regla general anterior, los registros scratch r15-r18 siempre son accesibles, incluso en marcos normales. Esto hace posible pasar argumentos, por ejemplo, a manejadores de excepciones.

Para una descripción detallada de la convención de uso de registros IA-64, consulte la ``Itanium Software Conventions and Runtime Architecture Guide'', disponible en:
http://www.intel.com/design/itanium/downloads/245358.htm

NOMBRES DE REGISTROS

La versión IA-64 de libunwind define tres tipos de macros de nombres de registro: macros de registro de marco, macros de registro normal y macros de conveniencia. A continuación, describimos cada tipo en su orden:

MACROS DE REGISTRO DE MARCO

Los registros de marco son registros especiales (pseudo) porque siempre tienen un valor válido, aunque a veces no se guardan explícitamente (por ejemplo, si un marco de pila de memoria tiene 16 bytes de tamaño, el valor anterior del puntero de pila se puede calcular simplemente como sp+16, por lo que no es necesario guardar explícitamente el puntero de pila). Además, el conjunto de valores de registro de marco identifica de forma única un marco de pila. La arquitectura IA-64 define dos pilas (una de memoria y una de registros). Incluyendo el puntero de instrucción (IP), esto significa que hay tres registros de marco:

UNW_IA64_IP:

Contiene el puntero de instrucción (IP, o "contador de programa") del marco de pila actual. Dado este valor, el estado de la máquina restante corresponde a los valores de registro que estaban presentes en la CPU cuando estaba a punto de ejecutar la instrucción apuntada por UNW_IA64_IP. Los bits 0 y 1 de este registro de marco codifican el número de ranura de la instrucción. Nota: Debido a la forma en que funciona la instrucción de llamada en IA-64, el número de ranura suele ser cero, pero puede ser distinto de cero, por ejemplo, en el marco de pila de un "trampolín" de manejador de señales.
UNW_IA64_SP:

Contiene el valor del puntero de pila (de memoria) (SP).
UNW_IA64_BSP:

Contiene el puntero de respaldo de registros (BSP). Nota: el valor en este registro es igual al contenido del registro ar.bsp en el momento en que la instrucción en UNW_IA64_IP estaba a punto de comenzar a ejecutarse.

MACROS DE REGISTRO NORMAL

Las siguientes macros de registro normal están disponibles:

UNW_IA64_GR:

El índice base para los registros generales (enteros). Añada un índice en el rango de 0..127 para obtener un registro general particular. Por ejemplo, para acceder a r4, se debe usar el índice UNW_IA64_GR+4. Los registros r0 y r1 (gp) son de solo lectura, y cualquier intento de escribirlos resultará en un error (-UNW_EREADONLYREG). Aunque r1 es de solo lectura, libunwind ajustará automáticamente su valor si se modifica el puntero de instrucción (UNW_IA64_IP). Por ejemplo, si UNW_IA64_IP se establece en un valor dentro de la función `func()`, entonces leer UNW_IA64_GR+1 devolverá el valor del puntero global para esta función.
UNW_IA64_NAT:

El índice base para los bits NaT de los registros generales (enteros). Un valor no cero en estos registros corresponde a un bit NaT establecido. Añada un índice en el rango de 0..127 para obtener un registro de bit NaT particular. Por ejemplo, para acceder al bit NaT de r4, se debe usar el índice UNW_IA64_NAT+4.
UNW_IA64_FR:

El índice base para los registros de punto flotante. Añada un índice en el rango de 0..127 para obtener un registro de punto flotante particular. Por ejemplo, para acceder a f2, se debe usar el índice UNW_IA64_FR+2. Los registros f0 y f1 son de solo lectura, y cualquier intento de escribir en los índices UNW_IA64_FR+0 o UNW_IA64_FR+1 resultará en un error (-UNW_EREADONLYREG).
UNW_IA64_AR:

El índice base para los registros de aplicación. Añada un índice en el rango de 0..127 para obtener un registro de aplicación particular. Por ejemplo, para acceder a ar40, se debe usar el índice UNW_IA64_AR+40. La arquitectura IA-64 define varios registros de aplicación como "reservados para uso futuro". Intentar acceder a dichos registros resulta en un error (-UNW_EBADREG).
UNW_IA64_BR:

El índice base para los registros de rama. Añada un índice en el rango de 0..7 para obtener un registro de rama particular. Por ejemplo, para acceder a b6, se debe usar el índice UNW_IA64_BR+6.
UNW_IA64_PR:

Contiene el conjunto de registros de predicado. Este registro de 64 bits de ancho contiene los registros p0 a p63 en el formato de "lado ancho". Al igual que con la instrucción "move predicates", los registros se mapean como si CFM.rrb.pr estuviera establecido en 0. Por lo tanto, en general, el valor del registro de predicado pN con N>=16 se encuentra en el bit 16 + ((N-16)+CFM.rrb.pr) % 48.
UNW_IA64_CFM:

Contiene el registro de máscara de marco actual.

Alias para UNW_IA64_GR+1, el registro de puntero global.

IA-64-specific libunwind information

NAME

libunwind-ia64 — IA-64-specific libunwind information

INTRODUCTION

This man page details the IA-64-specific details of the libunwind library. Specifically, it describes the register names that are specific to the IA-64 architecture.

MACHINE-STATE

The unw_context_t type on IA-64 is defined to be identical to the ucontext_t type (as defined by the Single UNIX Specification). libunwind uses this structure to hold the state of the machine. This structure is accessible via the unw_context() method. The structure contains IA-64-specific register information in the uc_mcontext field. This field is of type unw_word_t, which is an alias for unw_ucontext_t structure. The unw_ucontext_t structure, in turn, contains a structure of type unw_ia64_context_t, which is defined as follows:

typedef struct unw_ia64_context {
    unw_word_t		gr[128]; /* General purpose registers */
    unw_word_t		pr;	 /* Predicate registers */
    unw_word_t		ar[128]; /* Application registers */
    unw_word_t		cr;	 /* Control registers */
    unw_word_t		fr[128]; /* Floating-point registers */
    unw_word_t		ar_bsp;	 /* Backing store pointer */
    unw_word_t		ar_bspstore; /* Backing store write pointer */
    unw_word_t		ar_rnat; /* NaT collection register */
    unw_word_t		ar_ccv;	 /* Compare-and-swap value register */
    unw_word_t		ar_csd;	 /* Compare-and-swap-data register */
    unw_word_t		ar_unat; /* User NaT collection register */
    unw_word_t		ar_fpsr; /* Floating-point status register */
    unw_word_t		ar_pfs;	 /* Previous frame pointer */
    unw_word_t		ar_lc;	 /* Loop count register */
    unw_word_t		ar_ec;	 /* Epilogue count register */
} unw_ia64_context_t;

REGISTER NAMES

libunwind defines the following register names for IA-64:

UNW_IA64_GR:
General purpose registers. These are referred to by their number, i.e., UNW_IA64_GR+0 for r0, UNW_IA64_GR+1 for r1, etc.
UNW_IA64_AR:
Application registers. These are referred to by their number, i.e., UNW_IA64_AR+0 for ar0, UNW_IA64_AR+1 for ar1, etc.
UNW_IA64_FR:
Floating-point registers. These are referred to by their number, i.e., UNW_IA64_FR+0 for f0, UNW_IA64_FR+1 for f1, etc.
UNW_IA64_AR_BSP:
Alias for UNW_IA64_GR+17, the register-backing store pointer.
UNW_IA64_AR_BSPSTORE:

Alias for UNW_IA64_GR+18, the register-backing store write pointer.
UNW_IA64_AR_RNAT:

Alias for UNW_IA64_GR+19, the register-backing store NaT-collection register.
UNW_IA64_AR_CCV:

Alias for UNW_IA64_GR+32, the compare-and-swap value register.
UNW_IA64_AR_CSD:

Alias for UNW_IA64_GR+25, the compare-and-swap-data register (used by 16-byte atomic operations).
UNW_IA64_AR_UNAT:

Alias for UNW_IA64_GR+36, the user NaT-collection register.
UNW_IA64_AR_FPSR:

Alias for UNW_IA64_GR+40, the floating-point status (and control) register.
UNW_IA64_AR_PFS:

Alias for UNW_IA64_GR+64, the previous frame-state register.
UNW_IA64_AR_LC:

Alias for UNW_IA64_GR+65 the loop-count register.
UNW_IA64_AR_EC:

Alias for UNW_IA64_GR+66, the epilogue-count register.

THE UNWIND-CONTEXT TYPE

On IA-64, unw_context_t is simply an alias for ucontext_t (as defined by the Single UNIX Spec). This implies that it is possible to initialize a value of this type not just with unw_getcontext(), but also with getcontext(), for example. However, since this is an IA-64-specific extension to libunwind, portable code should not rely on this equivalence.
