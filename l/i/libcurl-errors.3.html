NOMBRE

libcurl-errors - códigos de error en libcurl

DESCRIPCIÓN

Esta página del manual incluye la mayoría, si no todos, los códigos de error disponibles en libcurl. También se incluyen las razones por las que ocurren y, posiblemente, qué se puede hacer para solucionar el problema.

CURLcode

Casi todas las funciones de la interfaz "easy" devuelven un código de error CURLcode. Sin embargo, usar la opción curl_easy_setopt(3) CURLOPT_ERRORBUFFER(3) es una buena idea, ya que te proporciona una cadena de error legible por humanos que puede ofrecer más detalles sobre la causa del error que solo el código de error. Se puede llamar a curl_easy_strerror(3) para obtener una cadena de error a partir de un número CURLcode dado.

CURLcode es uno de los siguientes:

CURLE_OK (0)
Todo bien. Continúa como de costumbre.
CURLE_UNSUPPORTED_PROTOCOL (1)
La URL que pasaste a libcurl usaba un protocolo que esta libcurl no soporta. El soporte puede ser una opción de compilación que no usaste, puede ser una cadena de protocolo mal escrita o simplemente un protocolo para el cual libcurl no tiene código.
CURLE_FAILED_INIT (2)
El código de inicialización temprano falló. Es probable que sea un error o problema interno, o un problema de recursos donde algo fundamental no pudo realizarse en el momento de la inicialización.
CURLE_URL_MALFORMAT (3)
La URL no estaba formateada correctamente.
CURLE_NOT_BUILT_IN (4)
Una característica, protocolo u opción solicitada no se encontró compilada en esta libcurl debido a una decisión en tiempo de compilación. Esto significa que una característica u opción no se habilitó o se deshabilitó explícitamente cuando se compiló libcurl y, para que funcione, debes obtener una libcurl recompilada.
CURLE_COULDNT_RESOLVE_PROXY (5)
No se pudo resolver el proxy. El host proxy proporcionado no se pudo resolver.
CURLE_COULDNT_RESOLVE_HOST (6)
No se pudo resolver el host. El host remoto proporcionado no se resolvió.
CURLE_COULDNT_CONNECT (7)
Falló la conexión() al host o proxy.
CURLE_WEIRD_SERVER_REPLY (8)
El servidor envió datos que libcurl no pudo analizar. Este código de error se conocía como CURLE_FTP_WEIRD_SERVER_REPLY antes de la versión 7.51.0.
CURLE_REMOTE_ACCESS_DENIED (9)
Se nos negó el acceso al recurso dado en la URL. Para FTP, esto ocurre al intentar cambiar al directorio remoto.
CURLE_FTP_ACCEPT_FAILED (10)
Mientras se esperaba que el servidor se conectara de vuelta en una sesión FTP activa, se envió un código de error a través de la conexión de control o similar.
CURLE_FTP_WEIRD_PASS_REPLY (11)
Después de haber enviado la contraseña FTP al servidor, libcurl espera una respuesta adecuada. Este código de error indica que se devolvió un código inesperado.
CURLE_FTP_ACCEPT_TIMEOUT (12)
Durante una sesión FTP activa mientras se esperaba que el servidor se conectara, expiró el tiempo de espera de CURLOPT_ACCEPTTIMEOUT_MS(3) (o el predeterminado interno).
CURLE_FTP_WEIRD_PASV_REPLY (13)
libcurl no pudo obtener un resultado coherente del servidor como respuesta a un comando PASV o EPSV. El servidor es defectuoso.
CURLE_FTP_WEIRD_227_FORMAT (14)
Los servidores FTP devuelven una línea 227 como respuesta a un comando PASV. Si libcurl no puede analizar esa línea, se devuelve este código de retorno.
CURLE_FTP_CANT_GET_HOST (15)
Un error interno al buscar el host utilizado para la nueva conexión.
CURLE_HTTP2 (16)
Se detectó un problema en la capa de señalización HTTP2. Esto es algo genérico y puede ser uno de varios problemas, consulta el buffer de errores para obtener detalles.
CURLE_FTP_COULDNT_SET_TYPE (17)
Se recibió un error al intentar establecer el modo de transferencia a binario o ASCII.
CURLE_PARTIAL_FILE (18)
La transferencia de un archivo fue más corta o más larga de lo esperado. Esto ocurre cuando el servidor informa primero un tamaño de transferencia esperado y luego entrega datos que no coinciden con el tamaño dado previamente.
CURLE_FTP_COULDNT_RETR_FILE (19)
Fue una respuesta extraña al comando 'RETR' o una transferencia de cero bytes completada.
Error obsoleto (20)
No se utiliza en versiones modernas.
CURLE_QUOTE_ERROR (21)
Al enviar comandos "QUOTE" personalizados al servidor remoto, uno de los comandos devolvió un código de error de 400 o superior (para FTP) o indicó de otra manera la finalización insatisfactoria del comando.
CURLE_HTTP_RETURNED_ERROR (22)
Esto se devuelve si CURLOPT_FAILONERROR(3) está configurado como TRUE y el servidor HTTP devuelve un código de error >= 400.
CURLE_WRITE_ERROR (23)
Se produjo un error al escribir los datos recibidos en un archivo local, o un error devuelto a libcurl desde una función de devolución de llamada de escritura.
Error obsoleto (24)
No se utiliza en versiones modernas.
CURLE_UPLOAD_FAILED (25)
Falló al iniciar la carga. Para FTP, el servidor generalmente denegó el comando STOR. El buffer de errores suele contener la explicación del servidor para esto.
CURLE_READ_ERROR (26)
Hubo un problema al leer un archivo local o un error devuelto por la función de devolución de llamada de lectura.
CURLE_OUT_OF_MEMORY (27)
Falló una solicitud de asignación de memoria. Esto es muy grave y las cosas están severamente complicadas si esto ocurre alguna vez.
CURLE_OPERATION_TIMEDOUT (28)
Tiempo de espera de la operación agotado. Se alcanzó el período de tiempo de espera especificado según las condiciones.
Error obsoleto (29)
No se utiliza en versiones modernas.
CURLE_FTP_PORT_FAILED (30)
El comando FTP PORT devolvió un error. Esto ocurre principalmente cuando no has especificado una dirección lo suficientemente buena para que la use libcurl. Consulta CURLOPT_FTPPORT(3).
CURLE_FTP_COULDNT_USE_REST (31)
El comando FTP REST devolvió un error. Esto nunca debería suceder si el servidor es coherente.
Error obsoleto (32)
No se utiliza en versiones modernas.
CURLE_RANGE_ERROR (33)
El servidor no soporta o no acepta rangos.
Error obsoleto (34)
No se utiliza desde la versión 7.56.0.

This is not really an error. It means you should call curl_multi_perform(3) again without doing select() or similar in between. Before version 7.20.0 (released on February 9 2010) this could be returned by curl_multi_perform(3), but in later versions this return code is never used.
CURLM_CALL_MULTI_SOCKET (-1)
