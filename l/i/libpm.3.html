Tabla De Contenidos

Estas funciones de biblioteca forman parte de Netpbm(1)

Esta página documenta las funciones de la biblioteca de subrutinas Netpbm que no están directamente relacionadas con los datos de imagen.

Para obtener información introductoria y general sobre el uso de libnetpbm, consulte la Guía del Usuario de Libnetpbm(3)

Las funciones de libnetpbm más utilizadas son las que leen, escriben y procesan imágenes Netpbm. Estas se documentan en el Manual de Procesamiento de Imágenes Netpbm de Libnetpbm (3)

Para utilizar estos servicios, incluya pam.h.

Funciones

Inicialización

Visión general

void pm_init( const char * progname, unsigned int flags );

void pm_proginit( int * argcP, char * argv[] );

Descripción

Todos los programas Netpbm deben llamar a pm_proginit() justo después de arrancar, antes de procesar sus argumentos. pm_proginit(), entre otras cosas, procesa los argumentos universales de Netpbm y los elimina de la lista de argumentos.

Un programa que no es un programa Netpbm, sino que solo utiliza los servicios de libnetpbm, no necesita invocar pm_proginit. Pero un programa así debe invocar pm_init().

Por "programa Netpbm", nos referimos a un programa que forma parte del paquete Netpbm o que está destinado a actuar como tal. pm_proginit() realiza acciones que todos los programas Netpbm hacen por convención. Por ejemplo, escanea la lista de argumentos en busca de
opciones comunes , las maneja y las elimina de la lista de argumentos. Por lo tanto, si desea que su programa tenga las mismas opciones comunes que las del paquete Netpbm, podría usar pm_proginit(), y si no, no debe hacerlo.

pm_proginit() está destinado principalmente a los desarrolladores de Netpbm, por lo que no debe esperar que tenga una función estable entre versiones, y debe consultar los comentarios en el código fuente para ver exactamente lo que hace.

Cualquier programa que utilice libnetpbm pero no llame a pm_proginit (es decir, no sea un programa Netpbm) debe llamar a pm_init(). El lugar convencional para hacerlo es al principio del programa. Esto configura algunas variables globales del programa para su uso por las funciones de libnetpbm.

El argumento progname es el nombre del programa que las funciones de libnetpbm utilizarán en los mensajes que emitan. Normalmente, usaría argv[0] para esto.

flags no tiene significado, pero para compatibilidad futura, debe establecerlo en cero.

pm_init() y pm_proginit() existen desde Netpbm 9.25 (marzo de 2002) al menos. Otra función llamada pm_init() existe en versiones anteriores de Netpbm, pero era para uso interno. Los programas Netpbm de esa época utilizan pbm_init(), etc. para hacer lo que pm_proginit() hace hoy. Hoy en día, pbm_init(), etc. existen por compatibilidad retroactiva y son idénticos a pm_proginit().

Acceso a Archivos o Flujos de Imagen

Visión general

FILE *pm_openr( char * name );

FILE *pm_openw( char * name );

FILE *pm_openr_seekable( const char * name );

FILE *pm_close( FILE * fp );

void pm_tell2( FILE * fileP, pm_filepos * fileposP, unsigned int fileposSize );

unsigned int pm_tell( FILE * fileP );

void pm_seek2( FILE * fileP, const pm_filepos * fileposP, unsigned int fileposSize );

void pm_seek( FILE * fileP, unsigned long filepos );

char *pm_read_unknown_size( FILE * fp, long * nread );

Descripción

Un flujo de imagen es simplemente un flujo de archivo (representado en la biblioteca estándar de C como tipo FILE *).

Estas rutinas funcionan en archivos de más de 2 GiB si el sistema subyacente lo hace, utilizando la interfaz estándar de archivos grandes. Sin embargo, antes de Netpbm 10.15 (abril de 2003), fallaban al abrir cualquier archivo de ese tamaño o al procesar cualquier desplazamiento en un archivo que no pudiera representarse en 32 bits.

pm_openr() abre el archivo dado para lectura, con la comprobación de errores adecuada. Un nombre de archivo de - se interpreta como Entrada Estándar. pm_openw() abre el archivo dado para escritura, con la comprobación de errores adecuada. pm_close() cierra el descriptor de archivo, con la comprobación de errores adecuada.

pm_openr_seekable() parece abrir el archivo igual que pm_openr(), pero el archivo así abierto tiene garantizado que es buscable (puede usar ftell() y fseek() en él). pm_openr_seekable() logra esto copiando todo el archivo a un archivo temporal y dándole el manejador del archivo temporal, si es necesario. Si el archivo que nombra es un archivo regular, ya es buscable, por lo que pm_openr_seekable() hace lo mismo que pm_openr().

Pero si es, digamos, una tubería, no es buscable. Así que pm_openr_seekable() lee la tubería hasta EOF a un archivo temporal, luego abre ese archivo temporal y devuelve el manejador del archivo temporal. El archivo temporal es buscable.


El archivo que crea pm_openr_seekable() es uno que el sistema operativo reconoce como temporal, por lo que cuando cierre el archivo, por cualquier medio, se eliminará.

Necesita un archivo buscable si pretende realizar varios pasos a través del archivo. La única alternativa es leer toda la imagen en memoria y trabajar a partir de esa copia. Eso podría usar demasiada memoria. Tenga en cuenta que la imagen ocupa menos espacio en la caché de archivos que en un búfer en memoria. ¡Hasta 96 veces menos espacio! Cada muestra es un entero en el búfer, que suele tener 96 bits. En el archivo, una muestra puede tener tan solo 1 bit y raramente más de 8 bits.

pm_tell2() devuelve un manejador para la posición actual del flujo de imagen (archivo), ya sea la cabecera o una fila del mapa de bits. Utilice el manejador como argumento para pm_seek2() para reposicionar el archivo allí más tarde. El archivo debe ser buscable (lo que puede asegurar abriéndolo con pm_openr_seekable()) o esto puede fallar.

El manejador de posición de archivo es de tipo pm_filepos, que está destinado a ser opaco, es decir, utilizado solo con estas dos funciones. En la práctica, es un desplazamiento de archivo y tiene 32 o 64 bits dependiendo de la capacidad del sistema subyacente. Para máxima compatibilidad retroactiva y futura, las funciones que toman o devuelven un pm_filepos tienen un argumento fileposSize para el tamaño de la estructura de datos. En C, simplemente codifique sizeof(pm_filepos) para ello.

pm_tell2() y pm_seek2() reemplazaron a pm_tell() y pm_seek() en Netpbm 10.15 (abril de 2003).

pm_read_unknown_size() lee un archivo completo o un flujo de entrada de tamaño desconocido a un búfer. Asigna más memoria según sea necesario. La rutina que llama tiene que liberar el búfer asignado con free().

pm_read_unknown_size() devuelve un puntero al búfer asignado. El argumento nread devuelve el número de bytes leídos.

Description

pm_readchar(), pm_writechar(), pm_readbigshort(), pm_writebigshort(), pm_readbiglong(), pm_writebiglong(), pm_readlittleshort(), pm_writelittleshort(), pm_readlittlelong(), and pm_writelittlelong() are routines to read and write 1-byte, 2-byte, and 4-byte pure binary integers in either big- or little-endian byte order. Note that a 'long int' C type might be wider than 4 bytes, but the 'long' routines still read and write 4 bytes.

pm_readbiglongu(), etc. (names ending in u) are the same except they work on unsigned versions of the type.

The routines with declared return values always return 0. Before Netpbm 10.27 (March 2005), they returned -1 on failure, including EOF. Now, they issue an error message to Standard Error and abort the program if the I/O fails or encounters EOF.

The 1-byte routines were new in Netpbm 10.27 (March 2005). The unsigned versions were new somewhere around Netpbm 10.21 (2004).

Maxval Arithmetic

Entry Points

int pm_maxvaltobits( int maxval );

int pm_bitstomaxval( int bits );

unsigned int pm_lcm( unsigned int x, unsigned int y, unsigned int z, unsigned int limit );

Description

pm_maxvaltobits() and pm_bitstomaxval() convert between a maxval and the minimum number of bits required to hold it.

pm_lcm() computes the least common multiple of 3 integers. You also specify a limit and if the LCM would be higher than that limit, pm_lcm() just returns that limit.

Gamma Arithmetic

Entry Points

float pm_gamma709( float intensity );

float pm_ungamma709( float brightness );

Description

In graphics processing, there are two common ways of representing numerically the intensity of a pixel, or a component of a pixel.

The obvious way is with a number that is directly proportional to the light intensity (e.g. 10 means twice as many milliwatts per square centimeter as 5). There are two problems with this:

  • To the human eye, a 1 milliwatt per square centimeter difference
    in a bright image is much less apparent than a 1 milliwatt per
    square centimeter difference in a dark image. So if you have
    a fixed number of bits in which to store the intensity value,
    you're wasting resolution at the bright end and skimping on it at
    the dark end.
  • Monitor inputs and camera outputs aren't directly proportional to
    the light intensity they project or detect.

For these reasons, light intensities are often represented in graphics processing by an exponential scale. The transfer function is called a gamma function and the resulting numbers are called gamma-corrected or gamma-adjusted. There are various gamma functions. The Netpbm formats specify that intensities are represented by gamma-adjusted numbers of a particular gamma transfer function.

These functions let you convert back and forth between these two scales, using the same gamma transfer function that is specified in the Netpbm format specifications.

pm_gamma709 converts from an intensity-proportional intensity value to a gamma-adjusted intensity value (roughly proportional to brightness, which is the human subjective perception of intensity), using the ITU-R Recommendation BT.709 gamma transfer function.

pm_ungamma709 is the inverse of pm_gamma709.

Messages

Overview

void pm_message( char * fmt, ... );

void pm_setusermessagefn(pm_usermessagefn * function);

Description

pm_message() is a printf() style routine to write an informational message to the Standard Error file stream. pm_message() suppresses the message, however, if the user specified the -quiet common option on the command line. Note that Netpbm programs are often used interactively, but also often used by programs. In the interactive case, it is nice to issue messages about what the program is doing, but in the program case, such messages are usually undesirable. By using pm_message() for all your messages, you make your program usable in both cases. Without any effort on your part, program users of your program can avoid the messages by specifying the -quiet option.

Netpbm distinguishes between error messages and information messages; pm_message() is just for informational messages. To issue an error message, see pm_errormsg() .

pm_setusermessagefn registers a handler for informational messages, called a user message routine. Any library function (including pm_message()) that wants to issue an informational message in the future will call that function with the message as an argument instead of writing the message to Standard Error.

The argument the user message routine gets is English text designed for human reading. It is just the text of the message; there is no attempt at formatting in it (so you won't see any newline or tab characters).

To capture error messages in addition to informational messages, see pm_setusererrormsgfn() .

You can remove the user message routine, so that the library issues future informational messages in its default way (write to Standard Error) by specifying a null pointer for function.

Example:


    static pm_usermessagefn logfilewrite;
    static void
    logfilewrite(const char * const msg) {
        fprintf(mymsglog, 'Netpbm message: %s', msg);
    }
    pm_setusermessagefn(&logfilewrite);
    
    pm_message('Message for the message log');

Keyword Matching

Entry Points

void pm_keymatch();

Description

This subroutine is obsolete. It used to be used for command line option processing. Today, you can do better option processing more easily with the shhopt facility. See any recent program in the Netpbm package for an example.

pm_keymatch() does a case-insensitive match of str against keyword. str can be a leading substring of keyword, but at least minchars must be present.
