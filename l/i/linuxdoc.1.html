LINUXDOC(1) Manual de Comandos Generales LINUXDOC(1)

NOMBRE

linuxdoc - Convertidor de SGML DTD LinuxDoc a otros formatos de salida

SINOPSIS

linuxdoc --backend=formato
[--papersize=tamaño] [--language=idioma] [--charset=char] [--style=archivo] [--debug] [--define atributo=valor] [--include entidad] [opciones-de-backend...] archivo(.sgml)

o (Uso antiguo, obsoleto)
sgmlxxxx [opciones-generales...] [opciones-de-backend...]   archivo(.sgml)

DESCRIPCIÓN

La suite linuxdoc es una colección de formateadores de texto que entienden un archivo fuente SGML DTD LinuxDoc. Cada formateador (o "backend") representa el archivo fuente en una variedad de formatos de salida, incluyendo HTML, TeX, DVI, PostScript, texto plano y groff(1) fuente en formato de página de manual. La suite linuxdoc se proporciona por compatibilidad hacia atrás, ya que todavía hay muchos documentos útiles escritos en fuente sgml DTD LinuxDoc.

Los lenguajes de marcado aceptados por estos formateadores se describen en la Guía del usuario de Linuxdoc-Tools. Son variantes de una definición de tipo de documento SGML diseñada originalmente por Matt Welsh para la documentación de Linux.

OPCIONES GENERALES

La mayoría de las opciones de línea de comandos son aceptadas por todos los backends. Algunos backends tienen opciones específicas adicionales para controlar la representación en su formato de salida particular. Aquí están las opciones comunes:

--backend=formato, -B
Establece el backend para el formato especificado. El valor predeterminado es ninguno de los formatos reales, sino solo la salida de uso de esta suite. Los formatos disponibles son: html, info, latex, lyx, rtf, txt, check.
--papersize=tamaño, -p
Establece el tamaño del papel. El valor predeterminado es "a4" (papel europeo de 297x210 mm). También puede especificar el tamaño "letter".
--language=idioma, -l
Especifica el idioma del documento (esto puede cambiar los archivos de estilo que se utilizan para formatear un backend). El idioma predeterminado es Inglés. Ejecute un comando de LinuxDoc-tools sin argumentos para ver la lista de códigos de idioma válidos.
--charset=char, -c
Especifica la codificación de caracteres de salida. El valor predeterminado es "ascii", que selecciona el conjunto ASCII; puede especificar "latin" para especificar el conjunto de caracteres ISO 8859-1 (Latin-1). Además, "nippon" y "euc-kr" son necesarios para manejar el archivo sgml codificado en euc-jp y euc-kr. "utf-8" también es aceptado, aunque solo se admite parcialmente.
--style=archivo, -S
Incluye una DTD auxiliar (Definición de Tipo de Documento) de /usr/share/linuxdoc-tools/dtd.
--tabsize=n, -t
Establece el espaciado de tabulación asumido para generar el documento de salida. El espaciado de tabulación predeterminado es 8.
--debug, -d
No elimine los archivos intermedios (como los archivos .TeX generados en el camino hacia un .dvi, o los archivos .man eliminados en el camino hacia texto plano).
--define, -D
Pasa pares de atributo/valor para que coincidan con condicionales "if" y "unless". Consulte la Guía del usuario para una discusión extendida de esta característica. Esta condicionalización es manejada por el comando sgmlpre. Consulte sgmlpre(1) así como la Guía del usuario.
--include, -i
Pasa una opción -i a nsgmls(1). Esto puede usarse para inclusión condicional. Consulte la página del manual de nsgmls(1) para obtener detalles.
--pass, -P
Pasa una cadena de opciones al backend. La semántica exacta de esta opción depende del backend y debe explicarse en las páginas del manual individuales para cada uno.
archivo
El archivo fuente SGML con extensión .sgml, llamado archivo o archivo.sgml. Debe usar la DTD de linuxdoc. Otras DTD no son soportadas.

Ejecutar un backend sin argumentos hará que liste todas sus opciones (El mensaje de error sobre "no se dieron nombres de archivo" se puede ignorar de forma segura en este caso). Los backends disponibles incluyen (los nombres entre corchetes son la forma antigua y obsoleta):

linuxdoc -B html (sgml2html)
traducir a HTML
linuxdoc -B info (sgml2info)
traducir a info de GNU
linuxdoc -B lyx (sgml2lyx)
traducir a macros de Lyx
linuxdoc -B latex (sgml2latex)
traducir a LaTeX 2e
linuxdoc -B rtf (sgml2rtf)
traducir a formato de texto enriquecido de Microsoft
linuxdoc -B txt (sgml2txt)
traducir a texto plano o marcado de página de manual de Unix

También hay una herramienta linuxdoc-Bcheck
(sgmlcheck) disponible para verificar la sintaxis SGML de la DTD de Linuxdoc de los fuentes del documento sin generar realmente una versión traducida.

CONTROLADORES DE BACKEND

Aquí están las descripciones para cada controlador de backend:


****************************************************

linuxdoc -B html (sgml2html) convierte un archivo fuente SGML DTD LinuxDoc a salida HTML. La salida aparecerá en el archivo de nivel superior archivo.html y archivo-n.html para cada sección (acción predeterminada, pero puede cambiarse con una opción), donde archivo es el nombre del archivo fuente SGML y n es el nombre de la sección.

El par atributo/valor "output=html" se establece para condicionales.

linuxdoc -B html acepta las siguientes opciones: [--split 0|1|2 ] [--dosnames] [--imagebuttons] [--toc 0|1|2 ]

Los significados de ellas son:

--split, -s
Nivel en el que dividir los documentos fuente. 0 = no dividir, 1 = dividir por secciones principales, 2 = dividir por subsecciones.
--toc, -T
Nivel en el que generar la tabla de contenidos.
0 = no generar tabla de contenidos en absoluto,
1 = incluye secciones principales (/capítulos/partes),
2 = incluye subsecciones.
--dosnames, -h
Usar ".htm" en lugar de ".html" como extensión de los archivos html.
--imagebuttons, -I
Usar los iconos de flecha de imagen "siguiente", "anterior" y "contenido" incluidos en /usr/share/linuxdoc-tools como botones de navegación.
--footer, -F
Usar el archivo especificado como pie de página en cada archivo html resultante. El pie de página predeterminado es simplemente texto plano 
 </BODY>\n </HTML>\n
--header, -H
Usar el archivo especificado como la parte superior del encabezado en cada archivo html resultante. Tenga en cuenta que esta no es la parte completa del encabezado, es decir, el título y los enlaces (siguiente, anterior, contenido) en el encabezado predeterminado se conservan. El predeterminado es 
 <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 3.2 Final//EN">\n
 <HTML>\n <HEAD>\n
--rtldirection, -r
Establecer la dirección de derecha a izquierda en el archivo html.


****************************************************

linuxdoc -B info (sgml2info) convierte un archivo fuente SGML DTD LinuxDoc a formato GNU info. La salida aparecerá en archivo.info donde archivo es el nombre del archivo fuente SGML.

El par atributo/valor "output=info" se establece para condicionales.

linuxdoc -B info no tiene opciones específicas del backend.


****************************************************

linuxdoc -B latex (sgml2latex) convierte un archivo fuente SGML DTD LinuxDoc a salida LaTeX, usando el nsgmls(1) o onsgmls(1) parser, y el sgmlsasp(1) translator. Usando la salida LaTeX, y el latex(1) formatter de texto, puedes crear entonces salida DVI, y salida PostScript usando el dvips(1) converter. La salida aparecerá en archivo.tex para la salida LaTeX, archivo.dvi para la salida DVI, o archivo.ps para la salida PostScript, donde archivo es el nombre del archivo fuente SGML.

Usando la salida LaTeX, y el pdflatex(1) formatter de texto, puedes crear entonces una bonita salida PDF, adecuada para ver con visores PDF como xpdf(1), acroread(1) o ghostview(1).

El par atributo/valor "output=latex2e" se establece para condicionales.

linuxdoc -B latex acepta las siguientes opciones específicas del backend: [--output=tex|dvi|ps|pdf] [--bibtex] [--makeindex] [--pagenumber=n] --quick [--latex=latex|hlatexp|platex|jlatex] [--dvips=dvips|dvi2ps] [--verbosity=n]

Los significados de estas son:

--output=fmt, -o
Especifica el formato de salida deseado. El especificador fmt puede ser ``tex'', ``dvi'', ``ps'', o ``pdf''.

Nota: Esta versión no sobrescribe/elimina los archivos intermedios: archivo tex para la salida dvi, o archivos tex/dvi para la salida ps. Esto es un comportamiento diferente del SGML-Tools 1.0.9 original, así que se le advierte aquí.

--bibtex, -b
Procesa el TeX generado con bibtex(1).
--makeindex, -m
Genera un archivo de índice TeX adecuado para procesar con makeindex(1) a partir de etiquetas <idx> y <cdx> presentes en el fuente SGML.
--pagenumber, -n
Establece el número de página de inicio en el archivo DVI o PS de salida.
--quick, -q
Realiza solo una pasada de formato LaTeX. Esto a menudo no es suficiente para producir la salida final (debido a referencias, etc.) pero es útil para detectar errores de TeX y problemas de justificación.
--pass, -P
El argumento de la opción pass se inserta justo después del preámbulo de LaTeX generado por la etiqueta del tipo de documento. Especifica el formato de salida deseado. El especificador fmt puede ser ``tex'', ``dvi'', ``ps'', o ``pdf''.
--latex=comando_latex_alternativo, -x
Esta opción es actualmente para coreano y japonés. El comando_latex_alternativo puede ser ``latex'' (por defecto), ``hlatexp'' (para coreano), ``platex'' o ``jlatex'' (para japonés). Esta opción se puede usar para renderizar documentos en coreano usando HLaTeXp, o para renderizar documentos en japonés usando pLaTeX/jLaTeX. Si no, HLaTeX debe estar instalado para renderizar documentos en coreano. Por otro lado, los documentos en japonés se pueden renderizar con jLaTeX
(que es el valor por defecto cuando se especifica ``-c nippon''), así que si ya tienes jLaTeX, puede que no necesites instalar pLaTeX.
--dvips=comando_dvips_alternativo, -s
Esta opción es actualmente para japonés. El comando_dvips_alternativo puede ser ``dvips'' o ``dvi2ps''. Si no sabes esto, entonces puede que no lo necesites.
--verbosity, -V
Establece la verbosidad. '0' (por defecto) mostrará información sobre la ejecución de LaTeX solo en caso de errores. '1' siempre mostrará información de la última ejecución. '2' mostrará información de todas las ejecuciones.


****************************************************

linuxdoc -B lyx (sgml2lyx) convierte un archivo fuente SGML DTD LinuxDoc a salida LyX. La salida aparecerá en archivo.lyx donde archivo es el nombre del archivo fuente SGML.

El par atributo/valor "output=lyx" se establece para condicionales.

linuxdoc -B lyx no tiene opciones específicas del backend.


****************************************************

linuxdoc -B rtf (sgml2rtf) convierte un archivo fuente SGML DTD LinuxDoc a RTF, el Formato de Texto Enriquecido usado por el sistema de ayuda de Microsoft Windows. La salida aparecerá en el archivo de nivel superior archivo.rtf y archivo-n.rtf para cada sección, donde archivo es el nombre del archivo fuente SGML. La salida RTF está adaptada para su compilación por el Compilador de Ayuda de Windows (hc31.exe).

El par atributo/valor "output=rtf" se establece para condicionales.

linuxdoc -B rtf acepta [--twosplit] como una opción específica del backend. A continuación se muestra el significado de esta opción:

--twosplit, -2
Divide los archivos tanto en secciones n. como en subsecciones n.m.


****************************************************

linuxdoc -B txt (sgml2txt) convierte un archivo fuente SGML DTD LinuxDoc a salida ASCII, ISO-8859-1, o EUC-JP. La salida aparecerá en archivo.txt donde archivo es el nombre del archivo fuente SGML.

El par atributo/valor "output=txt" se establece para condicionales.

linuxdoc -B txt acepta las siguientes opciones de backend: [--manpage] [--filter] [--blanks=n]

El significado de estas opciones es:

--manpage, -m
Genera un archivo fuente groff, adecuado para formatear con groff -man para páginas man.
--filter, -f
Elimina los retrocesos de sobrescritura de la forma intermedia generada por groff(1).
--pass, -P
El argumento de la opción pass se añade a las opciones de línea de comandos que se pasan a groff(1).
--blanks=n, -b
Establece el límite de líneas en blanco continuas para generar el documento de salida. El límite por defecto es 3. Si se especifica 0 (cero), el resultado tendrá muchas líneas en blanco continuas.


****************************************************

linuxdoc -B check (sgmlcheck) ejecuta un análisis SGML en el fuente del documento especificado. Cualquier error se informa a la salida estándar. No se produce ninguna versión formateada del fuente.

Tenga en cuenta que linuxdoc -B check preprocesa el fuente SGML DTD LinuxDoc, realizando la condicionalización descrita por las etiquetas <#if></#if> y <#unless></#unless>. Los fuentes de documentos que contengan estas etiquetas confundirán a un analizador SGML independiente. linuxdoc -B check no tiene opciones específicas del backend.
