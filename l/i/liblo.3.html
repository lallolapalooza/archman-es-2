Descripción detallada

Define las funciones de API de alto nivel necesarias para implementar soporte OSC. Debería ser suficiente para la mayoría de las aplicaciones, pero si requiere un control de nivel más bajo, puede usar las funciones definidas en lo_lowlevel.h

lo_address lo_address_new (const char * host, const char * port)

Declara un destino OSC, dada la dirección IP y el número de puerto. Igual que lo_address_new_with_proto(), pero usando UDP.

Parámetros

host Una dirección IP o número, o NULL para la máquina local.
port un número de puerto decimal o nombre de servicio.

El objeto lo_address puede ser utilizado como destino de mensajes OSC.

Nota: si deseas recibir respuestas del destino de esta dirección, debes proporcionar un lo_server usando lo_send_from() o lo_send_message_from() para enviar tu mensaje, de lo contrario se utilizará el último lo_server o lo_server_thread que se creó como socket de respuesta. El receptor remoto puede obtener la dirección de respuesta llamando a lo_message_get_source() en el manejador del mensaje. Ver example_tcp_echo_server.c para un ejemplo de cómo establecer comunicación bidireccional.

lo_address lo_address_new_from_url (const char * url)

Crea un objeto lo_address a partir de una URL OSC. Ejemplo: "osc.udp://localhost:4444/my/path/"

lo_address lo_address_new_with_proto (int proto, const char * host, const char * port)

Declara un destino OSC, dada la dirección IP y el número de puerto, especificando el protocolo.

Parámetros

proto El protocolo a utilizar, debe ser uno de LO_UDP, LO_TCP o LO_UNIX.
host Una dirección IP o número, o NULL para la máquina local.
port un número de puerto decimal o nombre de servicio.

El objeto lo_address puede ser utilizado como destino de mensajes OSC.

Nota: si deseas recibir respuestas del destino de esta dirección, primero debes crear un objeto lo_server_thread o lo_server que reciba las respuestas. El último objeto lo_server(_thread) creado será el receptor.

void lo_address_set_ttl (lo_address t, int ttl)

Establece el valor Time-to-Live para una dirección de destino dada. Esto es necesario para enviar mensajes UDP multidifusión. Un valor de 1 (el caso habitual) mantiene el mensaje dentro de la subred, mientras que 255 significa un alcance global y sin restricciones.

Parámetros

t Una dirección OSC.
ttl Un entero que especifica el alcance de un mensaje UDP multidifusión.

int lo_send (lo_address targ, const char * path, const char * type, ...)

Envía un mensaje con formato OSC a la dirección especificada.

Parámetros

targ La dirección OSC de destino
path La ruta OSC a la que se entregará el mensaje
type Los tipos de los elementos de datos en el mensaje, los tipos se definen en lo_osc_types.h
... Los valores de datos a transmitir. Los tipos de los argumentos pasados aquí deben coincidir con los tipos especificados en el parámetro de tipo.

Ejemplo:

lo_send(t, "/foo/bar", "ff", 0.1f, 23.0f);

Devuelve

-1 en caso de fallo.

int lo_send_from (lo_address targ, lo_server from, lo_timetag ts, const char * path, const char * type, ...)

Envía un mensaje con formato OSC a la dirección especificada, desde el mismo socket que el servidor especificado. Si un servidor liblo está recibiendo este mensaje, puede responder obteniendo la dirección del servidor llamando a lo_message_get_source() en el manejador del mensaje, pasando el lo_message proporcionado como argumento al lo_method_handler. Mediante este mecanismo se puede establecer comunicación bidireccional configurando un lo_server o lo_server_thread en ambos lados.

Parámetros

targ La dirección OSC de destino
from El servidor desde el cual enviar el mensaje (puede ser NULL para usar un nuevo socket)
ts La etiqueta de tiempo OSC a la que se procesará el mensaje (puede ser LO_TT_IMMEDIATE si no quieres adjuntar una etiqueta de tiempo)
path La ruta OSC a la que se entregará el mensaje
type Los tipos de los elementos de datos en el mensaje, los tipos se definen en lo_osc_types.h
... Los valores de datos a transmitir. Los tipos de los argumentos pasados aquí deben coincidir con los tipos especificados en el parámetro de tipo.

Ejemplo:

serv = lo_server_new(NULL, err);
lo_server_add_method(serv, "/reply", "ss", reply_handler, NULL);
lo_send_from(t, serv, LO_TT_IMMEDIATE, "/foo/bar", "ff", 0.1f, 23.0f);

Ver example_tcp_echo_server.c para un ejemplo de cómo usar lo_message_get_source() como se describe.

Devuelve

en caso de éxito, el número de bytes enviados, o -1 en caso de fallo.

int lo_send_timestamped (lo_address targ, lo_timetag ts, const char * path, const char * type, ...)

Envía un mensaje con formato OSC a la dirección especificada, programado para ser procesado en algún momento futuro.

Parámetros

targ La dirección OSC de destino
ts La etiqueta de tiempo OSC a la que se procesará el mensaje
path La ruta OSC a la que se entregará el mensaje
type Los tipos de los elementos de datos en el mensaje, los tipos se definen en lo_osc_types.h
... Los valores de datos a transmitir. Los tipos de los argumentos pasados aquí deben coincidir con los tipos especificados en el parámetro de tipo.

Ejemplo:

lo_timetag now;<br>
lo_timetag_now(&now);<br>
lo_send_timestamped(t, now, "/foo/bar", "ff", 0.1f, 23.0f);

Devuelve

en caso de éxito, el número de bytes enviados, o -1 en caso de fallo.

void lo_version (char * verstr, int verstr_size, int * major, int * minor, char * extra, int extra_size, int * lt_major, int * lt_minor, int * lt_bug)

Obtiene información sobre la versión de liblo actualmente en uso. Todos los parámetros son opcionales y se les puede dar el valor 0 si no se desea esa información. Por ejemplo, para obtener solo la versión como una cadena, llama a lo_version(str, size, 0, 0, 0, 0, 0, 0, 0);

Los campos "lt", llamados versión ABI, corresponden al sistema de versionado de libtool para la compatibilidad de la interfaz binaria, y no están relacionados con el número de versión de la biblioteca. Esta información se codifica normalmente en el nombre de archivo de la biblioteca compartida.

Normalmente, la cadena devuelta en 'verstr' debe corresponder con $major.$minor$extra, por ejemplo, "0.28rc". Si no hay información 'extra', por ejemplo, "0.28", 'extra' contendrá la cadena nula.

Parámetros

verstr Un búfer para recibir una cadena que describe la versión de la biblioteca.
verstr_size Tamaño del búfer apuntado por la cadena.
major Ubicación para recibir la versión principal de la biblioteca.
minor Ubicación para recibir la versión secundaria de la biblioteca.
extra Ubicación para recibir la cadena extra de la versión de la biblioteca.
extra_size Tamaño del búfer apuntado por 'extra'.
lt_major Ubicación para recibir la versión principal ABI.
lt_minor Ubicación para recibir la versión secundaria ABI.
lt_bug Ubicación para recibir la versión de 'corrección de errores' ABI.

Referenciado por lo::version().
