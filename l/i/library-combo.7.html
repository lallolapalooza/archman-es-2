NOMBRE

library-combo - Soporte de GNUstep Make para compilación cruzada.

DESCRIPCIÓN

Esta página del manual trata sobre compilación cruzada y binarios "fat" (gordos). Los binarios "fat" son paquetes que puedes suministrar y que contienen más de una versión binaria de tu programa (por ejemplo, tu aplicación). De este modo, puedes dar soporte a múltiples plataformas con un solo paquete.

Para soportar esto, tu sistema debe estar construido de una manera no aplanada. Esto significa que durante la instalación de gnustep-make deberías haber seleccionado --disable-flattened y los tipos de combinaciones de bibliotecas que quieres soportar, a través de la opción --with-library-combo. Con combinaciones de bibliotecas nos referimos al runtime de Objective-C, la biblioteca Foundation y la biblioteca de Aplicación. Para más detalles sobre esto, consulta la sección LIBRARY-COMBO.

Si instalaste tu sistema GNUstep de una manera no aplanada, todos los binarios dependientes del sistema se instalan en subdirectorios con información de cpu/os/library-combo. Eso significa, por ejemplo, que la biblioteca gnustep-base se instalará en Library/Libraries/ix86/linux/gnu-gnu-gnu/ cuando estés en un sistema Intel x86, ejecutando Linux con el runtime GNU para Objective-C y hayas instalado GNUstep.

Para cada combinación de bibliotecas que quieras soportar, debes crear el entorno a través de gnustep-make, ya que este instala un config.make diferente para soportar sus propias banderas CC, OPTFLAGS, etc.

COMBINACIÓN DE BIBLIOTECAS

Un tema importante es dar a un paquete la capacidad de manejar diversas bibliotecas y configuraciones disponibles actualmente:

Runtimes de Objective-C
En el mundo de Objective-C existen tres runtimes principales: el runtime de GNUstep, el runtime de Apple y el runtime de GNU. Son diferentes en varios aspectos y un programa o biblioteca que funcione a nivel de runtime debe ser consciente de ellos.
Bibliotecas Foundation
Existen diferentes bibliotecas Foundation sobre las cuales una aplicación o herramienta puede estar escrita: gnustep-base, libFoundation y el sistema Cocoa de Apple.
Interfaces gráficas
Hasta ahora, tres bibliotecas proporcionan o intentan proporcionar sistemas compatibles con OpenStep: AppKit de NeXT, gnustep-gui y Cocoa de Apple.

Si un programa quiere funcionar con todas las combinaciones posibles, tendrá que proporcionar diferentes binarios para cada combinación, ya que no es posible tener una herramienta compilada para NeXT Foundation que funcione con gnustep-base o viceversa. En resumen, un programa puede ser compilado para estas combinaciones:

Runtime de Objective-C
ng (para GNUstep Next Generation con API no frágil y soporte ARC, etc.), gnu (para GNU, o para GNUstep sin las últimas características del lenguaje), apple (para Apple), nx (para NeXT)
Biblioteca Foundation
gnu (para gnustep-base), fd (para libFoundation), apple (para Apple Cocoa), nx (para NeXT Foundation)
Biblioteca GUI
gnu (para gnustep-gui), apple (para Apple Cocoa), nx (para NeXT GUI)

Denotaremos el hecho de que una aplicación fue compilada para una cierta combinación de los valores anteriores usando las abreviaturas de los diferentes subsistemas y colocando guiones entre ellos. Por ejemplo, una aplicación compilada para NeXT Foundation usando NeXT AppKit tendrá el atributo de compilación nx-nx-nx. Una aplicación compilada para Apple Cocoa con el compilador GNU para Objective-C gnu-apple-apple y otra compilada para gnustep-base usando gnustep-gui en Unix se denotará como gnu-gnu-gnu. Aquí hay una lista de algunas de las combinaciones posibles:


Runtime Foundation GUI

nx nx nx

nx fd gnu

gnu gnu gnu

ng gnu gnu

gnu fd gnu

apple apple apple

apple gnu gnu

Tenga en cuenta que uno puede elegir sus propios paquetes para construir; no es obligatorio tener todos los paquetes instalados en el sistema. No tenerlos todos instalados solo limita la capacidad de construir y distribuir binarios para esas combinaciones faltantes.

ESTRUCTURA DE DIRECTORIOS

Para la compilación cruzada, se recomienda una estructura de directorios no aplanada, para que puedas almacenar binarios para diferentes máquinas en la misma estructura de directorios. El diseño estándar del sistema de archivos de GNUstep se usa normalmente cuando se utiliza una estructura de directorios no aplanada; esto se obtiene con la opción --with-layout=gnustep al configurar gnustep-make. Toda la instalación de GNUstep se crea dentro de /usr/GNUstep (o en otro directorio si utilizas la opción --prefix=... al configurar gnustep-make). Los directorios que contienen binarios (como el directorio Libraries) dentro de /usr/GNUstep están configurados para soportar binarios "fat" de la siguiente manera:

Libraries/

ix86/

linux-gnu/

gnu-gnu-gnu/
libgnustep-base.so
libgnustep-gui.so

gnu-fd-gnu/
libFoundation.so
libgnustep-gui.so

Para permitir que se encuentren las bibliotecas correctas, debes ejecutar GNUstep.sh antes de usar GNUstep, y debes iniciar tu aplicación usando openapp, que localizará el binario correcto para tu combinación de bibliotecas.

COMPILACIÓN PARA UNA COMBINACIÓN DE BIBLIOTECAS

El paquete de makefiles permitirá al usuario elegir entre diferentes combinaciones de bibliotecas. Para especificar una combinación para la que quieres compilar, simplemente escribe:


$ make library_combo=combinacion-biblioteca

Por ejemplo, si quieres elegir compilar usando la implementación Foundation de GNUstep y usar la biblioteca GNUstep GUI en una máquina GNU/Linux, puedes hacerlo así:


$ make library_combo=gnu-gnu-gnu

Si tu proyecto requiere ejecutar configure antes de compilar, hay dos cuestiones que debes tener en cuenta. 'configure' se utiliza para determinar la existencia de archivos de encabezado particulares y/o de alguna funcionalidad específica en los archivos de encabezado del sistema. Esto generalmente se hace creando un archivo config.h que contiene un par de definiciones como HAVE_... que indican si la funcionalidad comprobada está presente o no.

Otro uso de configure es determinar bibliotecas específicas para enlazar y/o herramientas específicas. No se requiere que un programa típico de GNUstep compruebe bibliotecas adicionales porque este paso se realiza en el momento en que se instala el paquete de makefiles. Si el proyecto aún necesita comprobar bibliotecas y/o herramientas adicionales, la forma recomendada es generar un archivo config.mak que es incluido por el GNUmakefile principal, en lugar de usar archivos Makefile.in que son modificados por configure. La razón para no hacer esto es evitar que los makefiles contengan dependencias de destino como las anteriores, manteniendo así un solo makefile en lugar de varios para cada máquina de destino.

El paquete de makefiles está escrito para GNU make porque proporciona características muy potentes que ahorran tiempo tanto al escribir el paquete como en tiempo de ejecución, al compilar un proyecto.

COMPILACIÓN PARA UNA ARQUITECTURA

Para compilar un proyecto para múltiples arquitecturas, necesitarás el entorno de desarrollo para la máquina de destino instalado en tu máquina. Esto incluye un compilador cruzado junto con todas las herramientas adicionales como el ensamblador y el enlazador, los archivos de encabezado de destino y todas las bibliotecas que necesites.

El paquete de makefiles de GNUstep debería ser capaz de compilar y enlazar una aplicación para otra máquina simplemente escribiendo


$ make ARCH=architecture

donde 'architecture' es un nombre para la arquitectura que quieres compilar. Por ejemplo:


$ make ARCH=ppc

USANDO UNA BIBLIOTECA-COMBO

Cuando uses combinaciones de bibliotecas, debes siempre extraer GNUstep.sh. Eso te permite cambiar las rutas de las bibliotecas sobre la marcha. Si quieres cambiar a una combinación de bibliotecas diferente en tu shell, y si estás usando bash, es común primero extraer GNUstep-reset.sh para reiniciar todas las variables de shell, y luego extraer GNUstep.sh de nuevo. Asumamos que usamos gnu-gnu-gnu como nuestra LIBRARY_COMBO actual y queremos cambiar a ng-gnu-gnu, entonces usaríamos:


. /usr/GNUstep/System/Library/Makefiles/GNUstep-reset.sh

export LIBRARY_COMBO=ng-gnu-gnu

. /usr/GNUstep/System/Library/Makefiles/GNUstep.sh
