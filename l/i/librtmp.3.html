LIBRTMP(3) Manual de Funciones de Biblioteca LIBRTMP(3)

NOMBRE

librtmp - API del protocolo RTMPDump de mensajería en tiempo real

BIBLIOTECA

RTMPDump RTMP (librtmp, -lrtmp)

SINOPSIS

#include <librtmp/rtmp.h>

DESCRIPCIÓN

El Protocolo de Mensajería en Tiempo Real (RTMP) se utiliza para transmitir contenido multimedia a través de una red TCP/IP. Esta API proporciona la mayoría de las funciones del cliente y algunas funciones del servidor necesarias para soportar RTMP, RTMP encapsulado en HTTP (RTMPT), RTMP encriptado (RTMPE), RTMP sobre SSL/TLS (RTMPS) y variantes encapsuladas de estos tipos encriptados (RTMPTE, RTMPTS). La especificación básica de RTMP ha sido publicada por Adobe, pero esta API fue ingenierizada inversamente sin usar la especificación de Adobe. Como tal, puede desviarse de cualquier especificación publicada, pero generalmente duplica el comportamiento real de los clientes originales de Adobe.

El paquete de software RTMPDump incluye un programa de utilidad cliente básico en rtmpdump(1), algunos servidores de ejemplo y una biblioteca utilizada para proporcionar acceso programático al protocolo RTMP. Esta página de manual ofrece una visión general de las rutinas de la biblioteca RTMP. Estas rutinas se encuentran en la biblioteca -lrtmp. Muchas otras rutinas también están disponibles, pero aún no están documentadas.

La interacción básica es la siguiente. Se asigna un manejador de sesión usando RTMP_Alloc() y se inicializa usando RTMP_Init(). Todos los parámetros de la sesión se proporcionan usando RTMP_SetupURL(). La conexión de red se establece usando RTMP_Connect(), y luego la sesión RTMP se establece usando RTMP_ConnectStream(). El stream se lee usando RTMP_Read(). Un cliente puede publicar un stream llamando a RTMP_EnableWrite() antes de la llamada RTMP_Connect(), y luego usando RTMP_Write() después de que se establezca la sesión. Mientras se reproduce un stream, puede pausarse y reanudarse usando RTMP_Pause(). La posición de reproducción del stream se puede mover usando RTMP_Seek(). Cuando RTMP_Read() devuelve 0 bytes, el stream está completo y puede cerrarse usando RTMP_Close(). El manejador de sesión se libera usando RTMP_Free().

Todos los datos se transfieren en formato FLV. La sesión básica requiere una URL RTMP. El formato de la URL RTMP es de la forma

  rtmp[t][e|s]://hostname[:port][/app[/playpath]]

Se admiten rtmp plano, así como sesiones encapsuladas y encriptadas.

Se pueden especificar opciones adicionales agregando pares clave=valor separados por espacios a la URL. Los caracteres especiales en los valores pueden necesitar ser escapados para evitar interpretaciones erróneas por parte del analizador de opciones. La codificación de escape utiliza una barra invertida seguida de dos dígitos hexadecimales que representan el valor ASCII del carácter. Por ejemplo, los espacios deben escaparse como \20 y las barras invertidas como \5c.

OPCIONES

Parámetros de red

Estas opciones definen cómo conectarse al servidor multimedia.

socks=host:puerto
Utiliza el proxy SOCKS4 especificado.

Parámetros de conexión

Estas opciones definen el contenido del paquete de solicitud de conexión RTMP. Si no se proporcionan los valores correctos, el servidor multimedia rechazará el intento de conexión.

app=nombre
Nombre de la aplicación a la que conectarse en el servidor RTMP. Anula la aplicación en la URL RTMP. A veces, el analizador de URL de librtmp no puede determinar el nombre de la aplicación automáticamente, por lo que debe especificarse explícitamente usando esta opción.
tcUrl=url
URL del stream de destino. Por defecto es rtmp[t][e|s]://host[:port]/app.
pageUrl=url
URL de la página web en la que se incrustó el contenido multimedia. Por defecto no se enviará ningún valor.
swfUrl=url
URL del reproductor SWF para el contenido multimedia. Por defecto no se enviará ningún valor.
flashVer=versión
Versión del plugin Flash utilizada para ejecutar el reproductor SWF. El valor predeterminado es "LNX 10,0,32,18".
conn=tipo:datos
Agrega datos AMF arbitrarios al mensaje Connect. El tipo debe ser B para Booleano, N para número, S para cadena, O para objeto o Z para nulo. Para booleanos, los datos deben ser 0 o 1 para FALSO o VERDADERO, respectivamente. Igualmente para los objetos, los datos deben ser 0 o 1 para finalizar o iniciar un objeto, respectivamente. Los elementos de datos en subobjetos pueden tener nombre, prefijando el tipo con 'N' y especificando el nombre antes del valor, por ejemplo, NB:miBandera:1. Esta opción se puede usar varias veces para construir secuencias AMF arbitrarias. Por ejemplo: 
  conn=B:1 conn=S:autenticarMe conn=O:1 conn=NN:codigo:1.23 conn=NS:bandera:ok conn=O:0

Parámetros de sesión

Estas opciones surten efecto después de que la solicitud Connect haya tenido éxito.

playpath=ruta
Anula el playpath analizado de la URL RTMP. A veces, el analizador de URL de rtmpdump no puede determinar el playpath correcto automáticamente, por lo que debe especificarse explícitamente usando esta opción.
playlist=0|1
Si el valor es 1 o VERDADERO, emite un comando set_playlist antes de enviar el comando play. La lista de reproducción contendrá solo el playpath actual. Si el valor es 0 o FALSO, no se enviará el comando set_playlist. El valor predeterminado es FALSO.
live=0|1
Especifica que el contenido multimedia es un stream en vivo. No es posible reanudar ni buscar en streams en vivo.
subscribe=ruta
Nombre del stream en vivo al que suscribirse. Por defecto es playpath.
start=num
Comienza en el segundo num del stream. No es válido para streams en vivo.
stop=num
Detiene en el segundo num del stream.
buffer=num
Establece el tiempo de búfer en num milisegundos. El valor predeterminado es 30000.
timeout=num
Finaliza la sesión después de num segundos sin recibir ningún dato del servidor. El valor predeterminado es 120.

Parámetros de seguridad

Estas opciones manejan solicitudes de autenticación adicionales del servidor.

token=clave
Clave para la respuesta SecureToken, utilizada si el servidor requiere autenticación SecureToken.
jtv=JSON
Token JSON utilizado por los servidores heredados de Justin.tv. Invoca NetStream.Authenticate.UsherToken
swfVfy=0|1
Si el valor es 1 o VERDADERO, se recupera el reproductor SWF de la swfUrl especificada para realizar la Verificación SWF. El hash SWF y el tamaño (utilizados en el paso de verificación) se calculan automáticamente. Además, la información SWF se almacena en caché en un archivo .swfinfo en el directorio principal del usuario, de modo que no necesite ser recuperada y recalculada cada vez. El archivo .swfinfo registra la URL SWF, la hora en que se recuperó, la marca de tiempo de modificación del archivo SWF, su tamaño y su hash. Por defecto, la información en caché se utilizará durante 30 días antes de volver a verificar.
swfAge=días
Especifica cuántos días se utilizará la información SWF en caché antes de volver a verificar. Utilice 0 para verificar siempre la URL SWF. Tenga en cuenta que si la verificación muestra que el archivo SWF tiene la misma marca de tiempo de modificación que antes, no se recuperará de nuevo.

AMBIENTE

HOME
El valor de $HOME se utiliza como la ubicación del archivo .swfinfo.

ARCHIVOS

Caché de información de verificación SWF
