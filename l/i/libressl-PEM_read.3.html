NOMBRE

PEM_write, PEM_write_bio, PEM_read, PEM_read_bio, PEM_get_EVP_CIPHER_INFO, PEM_do_header, PEM_def_callback, pem_password_cb — Rutinas de codificación PEM

SINOPSIS

biblioteca “libcrypto”
#include <openssl/pem.h>

int
PEM_write(FILE *fp, const char *name, const char *header, const unsigned char *data, long len);

int
PEM_write_bio(BIO *bp, const char *name, const char *header, const unsigned char *data, long len);

int
PEM_read(FILE *fp, char **name, char **header, unsigned char **data, long *len);

int
PEM_read_bio(BIO *bp, char **name, char **header, unsigned char **data, long *len);

int
PEM_get_EVP_CIPHER_INFO(char *header, EVP_CIPHER_INFO *cinfo);

int
PEM_do_header(EVP_CIPHER_INFO *cinfo, unsigned char *data, long *len, pem_password_cb *cb, void *userdata);

int
PEM_def_callback(char *password, int size, int verify, void *userdata);

typedef int
pem_password_cb(char *password, int size, int verify, void *userdata);

DESCRIPCIÓN

Estas funciones leen y escriben objetos codificados en PEM, utilizando el tipo PEM name, cualquier información de header adicional y los datos sin procesar data de longitud len.

PEM es la codificación de contenido binario definida por primera vez en la RFC 1421 de IETF. El contenido es una serie de líneas codificadas en base64, rodeadas de marcadores de inicio/fin cada uno en su propia línea. Por ejemplo:

-----BEGIN PRIVATE KEY-----
MIICdg....
... bhTQ==
-----END PRIVATE KEY-----

Las líneas de encabezado opcionales pueden aparecer después de la línea de inicio, y su existencia depende del tipo de objeto que se esté escribiendo o leyendo.

PEM_write() escribe en el archivo fp, mientras que PEM_write_bio() escribe en el BIO bp. El name es el nombre a usar en el marcador, el header es el valor del encabezado o NULL, y data y len especifican los datos y su longitud.

El buffer de data final es típicamente un objeto ASN.1 que puede ser decodificado con la función d2i_*() apropiada para el tipo name; consulte d2i_X509(3) para ver ejemplos.

PEM_read() lee del archivo fp, mientras que PEM_read_bio() lee del BIO bp. Ambas funciones omiten cualquier dato no-PEM que preceda al inicio del siguiente objeto PEM. Cuando se recupera exitosamente un objeto, el nombre del tipo de "----BEGIN <type>-----" se devuelve a través del argumento name, cualquier encabezado de encapsulación se devuelve en header, y el contenido decodificado de base64 y su longitud se devuelven a través de data y len, respectivamente. Los punteros name, header y data deben ser liberados por el llamador cuando ya no sean necesarios.

Las funciones restantes están obsoletas porque el formato de cifrado PEM subyacente está obsoleto y debe evitarse. Utiliza un formato de cifrado con una función de derivación de claves específica de OpenSSL, que emplea MD5 con un recuento de iteraciones de 1. En su lugar, las claves privadas deben almacenarse en formato PKCS#8, con una PBE fuerte PKCS#5 v2.0; consulte PEM_write_PrivateKey(3) y d2i_PKCS8PrivateKey_bio(3).

PEM_get_EVP_CIPHER_INFO() se puede utilizar para determinar si los data devueltos por PEM_read() o PEM_read_bio() están cifrados y para recuperar el cifrado y el IV asociados. El llamador pasa un puntero a una estructura de tipo EVP_CIPHER_INFO a través del argumento cinfo y el header devuelto por PEM_read() o PEM_read_bio(). Si la llamada es exitosa, se devuelve 1 y el cifrado y el IV se almacenan en la dirección apuntada por cinfo. Cuando el encabezado está mal formado o no se soporta, o cuando el cifrado es desconocido o ocurre algún error interno, se devuelve 0.

PEM_do_header() se puede utilizar para descifrar los datos si el encabezado indica cifrado. El argumento cinfo es un puntero a la estructura inicializada por una llamada anterior a PEM_get_EVP_CIPHER_INFO(). Si esa estructura indica la ausencia de cifrado, PEM_do_header() se ejecuta correctamente sin realizar ninguna acción. Los argumentos data y len se utilizan tanto para pasar los datos cifrados que se devolvieron en los mismos argumentos de la llamada anterior a PEM_read() o PEM_read_bio() como para pasar los datos descifrados.

La función de devolución de llamada cb se utiliza para obtener la password de cifrado; si cb es NULL, se utiliza en su lugar PEM_def_callback(). El buffer password debe tener al menos size bytes de longitud. A menos que userdata sea NULL, PEM_def_callback() ignora el argumento verify y copia la cadena de bytes terminada en NUL userdata a password sin un byte NUL terminador, truncando silenciosamente la copia a como máximo size bytes. Si userdata es NULL, PEM_def_callback() en su lugar solicita al usuario la contraseña sin mostrarla llamando internamente a EVP_read_pw_string_min(3). En este caso, size se reduce silenciosamente a como máximo BUFSIZ y se aceptan como máximo size - 1 bytes del usuario y se copian en el buffer de cadena de bytes password. Una función de devolución de llamada cb proporcionada por la aplicación puede usar userdata para un propósito diferente al de PEM_def_callback(), por ejemplo, como datos auxiliares para usar mientras se adquiere la contraseña. Por ejemplo, una aplicación gráfica podría pasar un identificador de ventana. Si el indicador verify no es cero, se le pide al usuario dos veces la contraseña para detectar errores tipográficos

VALORES DE RETORNO

PEM_read() y PEM_read_bio() devuelven 1 en caso de éxito o 0 en caso de fallo. Esto último incluye el caso en que no queden más objetos PEM en el archivo de entrada. Para distinguir el fin del archivo de errores más graves, el llamador debe examinar la pila de errores y verificar si PEM_R_NO_START_LINE está presente, lo que indica que no se encontraron más objetos PEM. Ver ERR_peek_last_error(3) y ERR_GET_REASON(3).

PEM_get_EVP_CIPHER_INFO() y PEM_do_header() devuelven 1 en caso de éxito o 0 en caso de fallo. Los datos son probablemente irrelevantes si estas funciones fallan.

PEM_def_callback() devuelve el número de bytes almacenados en buf o un valor negativo en caso de fallo, y se espera que cb se comporte de manera similar. Si userdata es NULL, PEM_def_callback() falla si num es menor que 5 o si ocurre un error al intentar solicitar la contraseña al usuario. De lo contrario, falla cuando num es negativo. Los detalles de las circunstancias que causan el fallo de cb pueden variar.

HISTORIAL

PEM_write(), PEM_read(), y PEM_do_header() aparecieron en SSLeay 0.4 o anterior. PEM_get_EVP_CIPHER_INFO() apareció por primera vez en SSLeay 0.5.1. PEM_write_bio() y PEM_read_bio() aparecieron por primera vez en SSLeay 0.6.0. Estas funciones han estado disponibles desde OpenBSD 2.4.

PEM_def_callback() apareció por primera vez en OpenSSL 0.9.7 y ha estado disponible desde OpenBSD 3.2.
