DESCRIPCIÓN

Las funciones PEM leen o escriben estructuras en formato PEM. En este sentido, el formato PEM es simplemente datos codificados en base64 rodeados de líneas de cabecera; consulte PEM_read(3) para más detalles.

Para más detalles sobre el significado de los argumentos, consulte la sección Argumentos de las funciones PEM.

Cada operación tiene cuatro funciones asociadas. Por brevedad, el término “funciones TIPO ” se usará para referirse colectivamente a las funciones PEM_read_bio_TYPE(), PEM_read_TYPE(), PEM_write_bio_TYPE(), y PEM_write_TYPE(). Si no existe un conjunto de funciones específicas para un tipo dado, se puede usar PEM_ASN1_read(3) en su lugar.

Las funciones PrivateKey leen o escriben una clave privada en formato PEM usando una estructura EVP_PKEY. Las rutinas de escritura usan el formato de clave privada "tradicional" y pueden manejar tanto claves privadas RSA como DSA. Las funciones de lectura pueden además manejar de forma transparente claves cifradas y no cifradas en formato PKCS#8.

PEM_write_bio_PKCS8PrivateKey() y PEM_write_PKCS8PrivateKey() escriben una clave privada en una estructura EVP_PKEY en formato PKCS#8 EncryptedPrivateKeyInfo usando algoritmos de cifrado basados en contraseña PKCS#5 v2.0. El argumento enc especifica el algoritmo de cifrado a usar: a diferencia de todas las demás rutinas PEM, el cifrado se aplica a nivel de PKCS#8 y no en las cabeceras PEM. Si enc es NULL, entonces no se usa cifrado y se usa en su lugar una estructura PKCS#8 PrivateKeyInfo.

PEM_write_bio_PKCS8PrivateKey_nid() y PEM_write_PKCS8PrivateKey_nid() también escriben una clave privada como un PKCS#8 EncryptedPrivateKeyInfo. Sin embargo, usan en su lugar algoritmos de cifrado PKCS#5 v1.5 o PKCS#12. El algoritmo a usar se especifica en el parámetro nid y debe ser el NID del OBJECT IDENTIFIER correspondiente.

Las funciones PKCS8 procesan una clave privada cifrada usando una estructura X509_SIG y la función d2i_X509_SIG(3).

Las funciones PKCS8_PRIV_KEY_INFO procesan una clave privada usando una estructura PKCS8_PRIV_KEY_INFO.

Las funciones PUBKEY procesan una clave pública usando una estructura EVP_PKEY. La clave pública se codifica como una estructura ASN.1 SubjectPublicKeyInfo.

Las funciones RSAPrivateKey procesan una clave privada RSA usando una estructura RSA. Manejan los mismos formatos que las funciones PrivateKey, pero se produce un error si la clave privada no es RSA.

Las funciones RSAPublicKey procesan una clave pública RSA usando una estructura RSA. La clave pública se codifica usando una estructura PKCS#1 RSAPublicKey.

Las funciones RSA_PUBKEY también procesan una clave pública RSA usando una estructura RSA. Sin embargo, la clave pública se codifica usando una estructura ASN.1 SubjectPublicKeyInfo y se produce un error si la clave pública no es RSA.

Las funciones DSAPrivateKey procesan una clave privada DSA usando una estructura DSA. Manejan los mismos formatos que las funciones PrivateKey pero se produce un error si la clave privada no es DSA.

Las funciones DSA_PUBKEY procesan una clave pública DSA usando una estructura DSA. La clave pública se codifica usando una estructura ASN.1 SubjectPublicKeyInfo y se produce un error si la clave pública no es DSA.

Las funciones DSAparams procesan parámetros DSA usando una estructura DSA. Los parámetros se codifican usando una estructura Dss-Parms según se define en RFC 2459.

Las funciones DHparams procesan parámetros DH usando una estructura DH. Los parámetros se codifican usando una estructura DHparameter de PKCS#3.

Las funciones ECPKParameters procesan parámetros EC usando una estructura EC_GROUP y la función d2i_ECPKParameters(3).

Las funciones ECPrivateKey procesan una clave privada EC usando una estructura EC_KEY.

Las funciones EC_PUBKEY procesan una clave pública EC usando una estructura EC_KEY.

Las funciones X509 procesan un certificado X509 usando una estructura X509. También procesarán un certificado X509 de confianza, pero cualquier configuración de confianza se descarta.

Las funciones X509_AUX procesan un certificado X509 de confianza usando una estructura X509.

Las funciones X509_REQ y X509_REQ_NEW procesan una solicitud de certificado PKCS#10 usando una estructura X509_REQ. Las funciones de escritura X509_REQ usan CERTIFICATE REQUEST en la cabecera, mientras que las funciones X509_REQ_NEW usan NEW CERTIFICATE REQUEST (como requieren algunas CAs). Las funciones de lectura X509_REQ manejarán cualquiera de las dos formas, por lo que no hay funciones de lectura X509_REQ_NEW.

Las funciones X509_CRL procesan una CRL X509 usando una estructura X509_CRL.

Las funciones PKCS7 procesan un ContentInfo PKCS#7 usando una estructura PKCS7.

Las funciones CMS procesan una estructura CMS_ContentInfo.

Las antiguas rutinas de escritura de PrivateKey se conservan por compatibilidad. Las nuevas aplicaciones deberían escribir claves privadas usando las rutinas PEM_write_bio_PKCS8PrivateKey() o PEM_write_PKCS8PrivateKey() porque son más seguras (usan un recuento de iteraciones de 2048 mientras que las rutinas tradicionales usan un recuento de 1) a menos que la compatibilidad con versiones anteriores de OpenSSL sea importante.

Las rutinas de lectura de PrivateKey pueden usarse en todas las aplicaciones porque manejan todos los formatos de forma transparente.

Argumentos de las funciones PEM

Las funciones PEM tienen muchos argumentos comunes.

El parámetro bp especifica el BIO desde el que leer o al que escribir.

El parámetro fp especifica el puntero FILE desde el que leer o al que escribir.

Todas las funciones de lectura PEM toman un argumento de puntero a puntero x y devuelven un puntero del mismo tipo. Si x es NULL, entonces el parámetro se ignora. Si x no es NULL pero *x es NULL, entonces la estructura devuelta se escribirá en *x. Si ni x ni *x son NULL, entonces se intenta reutilizar la estructura en *x, pero véanse las secciones BUGS y EXAMPLES. Independientemente del valor de x, siempre se devuelve un puntero a la estructura, o NULL si ocurrió un error.

Las funciones PEM que escriben claves privadas toman un parámetro enc, que especifica el algoritmo de cifrado a usar. El cifrado se realiza a nivel de PEM. Si este parámetro se establece en NULL, entonces la clave privada se escribe en forma no cifrada.

Los argumentos opcionales u y cb son una frase de contraseña usada para cifrar una estructura PEM o una función de retorno para obtener la frase de contraseña; véase pem_password_cb(3) para más detalles.

Para las rutinas de escritura PEM, si el parámetro kstr no es NULL, entonces klen bytes en kstr se usan como la frase de contraseña y cb se ignora.

Formato de cifrado PEM

Estas antiguas rutinas de PrivateKey usan una técnica no estándar para el cifrado.

La clave privada (u otros datos) adopta la siguiente forma:

-----BEGIN RSA PRIVATE KEY-----
Proc-Type: 4,ENCRYPTED
DEK-Info: DES-EDE3-CBC,3F17F5316E2BAC89

...datos codificados en base64...
-----END RSA PRIVATE KEY-----

La línea que comienza con “DEK-Info” contiene dos piezas de información separadas por comas: el nombre del algoritmo de cifrado tal como lo usa EVP_get_cipherbyname(3) y una sal de 8 bytes codificada como un conjunto de dígitos hexadecimales.

Después de esto están los datos cifrados codificados en base64.

La clave de cifrado se determina usando EVP_BytesToKey(3), usando la sal y un recuento de iteraciones de 1. El IV usado es el valor de la sal y *no* el IV devuelto por EVP_BytesToKey(3).

VALORES DE RETORNO

Las rutinas de lectura devuelven un puntero a la estructura leída o NULL si se produjo un error.

Las rutinas de escritura devuelven 1 en caso de éxito o 0 en caso de fallo.

EJEMPLOS

Aunque las rutinas PEM toman varios argumentos, en casi todas las aplicaciones la mayoría de ellos se establecen en 0 o NULL.

Leer un certificado en formato PEM desde un BIO:

X509 *x;
x = PEM_read_bio_X509(bp, NULL, 0, NULL);
if (x == NULL) {
	/* Error */
}

Método alternativo:

X509 *x = NULL;
if (!PEM_read_bio_X509(bp, &x, 0, NULL)) {
	/* Error */
}

Escribir un certificado en un BIO:

if (!PEM_write_bio_X509(bp, x)) {
	/* Error */
}

Escribir una clave privada sin cifrar en un FILE:

if (!PEM_write_PrivateKey(fp, key, NULL, NULL, 0, 0, NULL)) {
	/* Error */
}

Escribir una clave privada (usando el formato tradicional) en un BIO usando cifrado triple DES; se solicita la frase de contraseña:

if (!PEM_write_bio_PrivateKey(bp, key, EVP_des_ede3_cbc(),
    NULL, 0, 0, NULL)) {
	/* Error */
}

Escribir una clave privada (usando el formato PKCS#8) en un BIO usando cifrado triple DES, usando la frase de contraseña "hello":

if (!PEM_write_bio_PKCS8PrivateKey(bp, key, EVP_des_ede3_cbc(),
    NULL, 0, 0, "hello")) {
	/* Error */
}

Leer una clave privada desde un BIO usando la frase de contraseña "hello":

key = PEM_read_bio_PrivateKey(bp, NULL, 0, "hello");
if (key == NULL) {
	/* Error */
}

Leer una clave privada desde un BIO usando una función de devolución de llamada para la frase de contraseña:

key = PEM_read_bio_PrivateKey(bp, NULL, pass_cb, "My Private Key");
if (key == NULL) {
	/* Error */
}

Esqueleto de la función de devolución de llamada para la frase de contraseña:

int
pass_cb(char *buf, int size, int rwflag, void *u)
{
	char	*tmp;
	size_t	 len;

	/* Probablemente haríamos algo diferente si 'rwflag' es 1 */
	printf("Enter pass phrase for \"%s\"\n", u);

	/*
	 * En lugar de la siguiente línea, obtenga la frase de contraseña
	 * del usuario de alguna manera.
	 */
	tmp = "hello";
	if (tmp == NULL) /* Ocurrió un error. */
		return -1;

	len = strlen(tmp);
	if (len == 0) /* Tratar una frase de contraseña vacía como un error también. */
		return -1;

	/* si es demasiado larga, truncar */
	if (len > size)
		len = size;
	memcpy(buf, tmp, len);
	return len;
}

ADVERTENCIAS

Una causa frecuente de problemas es intentar usar las rutinas PEM de esta manera:

X509 *x;
PEM_read_bio_X509(bp, &x, 0, NULL);

Esto es un error porque se intentará reutilizar los datos en x, que es un puntero no inicializado.

Estas funciones no hacen ninguna suposición con respecto a la frase de contraseña recibida desde la función de devolución de llamada de contraseña. Simplemente se tratará como una secuencia de bytes.

ERRORES

Las rutinas de lectura PEM en algunas versiones de OpenSSL no reutilizarán correctamente una estructura existente. Por lo tanto

PEM_read_bio_X509(bp, &x, 0, NULL);

donde x ya contiene un certificado válido puede no funcionar, mientras que

X509_free(x);
x = PEM_read_bio_X509(bp, NULL, 0, NULL);

está garantizado que funciona.
