DESCRIPCIÓN

Estas rutinas manejan la lectura y escritura de varios objetos criptográficos en y desde el formato PEM. El formato PEM es simplemente un medio de codificación de datos binarios en texto plano usando codificación Base64 y añadiendo cabeceras y pies de línea específicos, típicamente -----BEGIN <type>----- y -----END <type>-----. Para las operaciones de escritura, los objetos pueden ser encriptados.

PEM_read_bio_…() y PEM_read_…() leen un objeto del formato PEM del BIO o FILE respectivamente. Si x no es NULL, el objeto leído es almacenado en la dirección apuntada por x. Si x es NULL, entonces se asigna nueva memoria para el objeto. Si un objeto PEM está encriptado, se le solicita una contraseña usando la rutina de callback cb con el argumento de usuario u.

PEM_write_bio_…() y PEM_write_…() escriben un objeto en el formato PEM al BIO o FILE respectivamente. Si el objeto está encriptado (es decir, enc no es NULL), entonces se usa la contraseña proporcionada por cb (o kstr y klen si cb es NULL) para encriptar el objeto. El argumento u es un argumento de usuario pasado a la rutina de callback de contraseña.

La mayoría de estas funciones son nombres de alias para la rutina genérica PEM_read_bio, PEM_write_bio, PEM_read y PEM_write. Sin embargo, algunas de ellas, como PEM_write_bio_PKCS8PrivateKey_nid, llaman a PEM_write_bio_PKCS8PrivateKey con un cifrado derivado del nid proporcionado. Véase PEM_write_PKCS8PrivateKey(3) para más detalles sobre estas rutinas.

Los objetos que pueden ser manejados son:

EVP_PKEY private key

El formato PEM para claves privadas es un tipo de datos definido por RFC 7468. Históricamente, se usaban varios formatos de claves privadas no estandarizados. Las funciones PEM_read_bio_PrivateKey y PEM_read_PrivateKey pueden leer la mayoría de estos formatos, incluyendo el formato de clave privada PKCS#1 (como se usa en OpenSSH), y también las claves RSA, DSA, DH y ECDSA directamente. El tipo de clave privada se determina automáticamente al leerla.

PEM_write_bio_PrivateKey y PEM_write_PrivateKey escriben una clave privada en el formato PEM de texto plano. Por defecto, la clave privada se escribe como una clave privada PKCS#8 encriptada con el cifrado AES-256-CBC.

Si se requiere un formato diferente, se puede usar PEM_write_bio_PKCS8PrivateKey o PEM_write_bio_PKCS8PrivateKey_nid. PEM_write_bio_PKCS8PrivateKey_nid usa el NID proporcionado para seleccionar el algoritmo de encriptación.

EVP_PKEY public key

Las funciones PEM_read_bio_PUBKEY, PEM_read_PUBKEY, PEM_write_bio_PUBKEY y PEM_write_PUBKEY manejan claves públicas en el formato PEM. Estas funciones son similares a las de clave privada, pero no requieren contraseña para la lectura ni encriptación para la escritura.

RSA private key

Estas funciones manejan claves privadas RSA en formato PEM. Son sinónimo de las funciones EVP_PKEY correspondientes pero operan directamente sobre estructuras RSA.

RSA public key

Estas funciones manejan claves públicas RSA en formato PEM. Son sinónimo de las funciones EVP_PKEY correspondientes pero operan directamente sobre estructuras RSA.

DSA private key

Estas funciones manejan claves privadas DSA en formato PEM. Son sinónimo de las funciones EVP_PKEY correspondientes pero operan directamente sobre estructuras DSA.

DSA public key

Estas funciones manejan claves públicas DSA en formato PEM. Son sinónimo de las funciones EVP_PKEY correspondientes pero operan directamente sobre estructuras DSA.

DSA parameters

Estas funciones manejan parámetros DSA en formato PEM.

DH parameters

Estas funciones manejan parámetros DH en formato PEM.

ECPKParameters

Estas funciones manejan parámetros de curva elíptica en formato PEM.

EC private key

Estas funciones manejan claves privadas de curva elíptica en formato PEM. Son sinónimo de las funciones EVP_PKEY correspondientes pero operan directamente sobre estructuras EC_KEY.

EC public key

Estas funciones manejan claves públicas de curva elíptica en formato PEM. Son sinónimo de las funciones EVP_PKEY correspondientes pero operan directamente sobre estructuras EC_KEY.

X509 certificate

Estas funciones manejan certificados X.509 en formato PEM.

X509 certificate with auxiliary data

Estas funciones manejan certificados X.509 que pueden contener datos auxiliares (por ejemplo, información de clave privada o extensiones).

X509 request

Estas funciones manejan solicitudes de firma de certificados X.509 (CSRs) en formato PEM.

X509 CRL

Estas funciones manejan listas de revocación de certificados X.509 (CRLs) en formato PEM.

PKCS7 data

Estas funciones manejan datos PKCS#7 en formato PEM.

CMS data

Estas funciones manejan datos CMS (Cryptographic Message Syntax) en formato PEM.

Los argumentos cb y u permiten la implementación de una gestión de contraseñas personalizada, por ejemplo, para solicitarla al usuario o leerla de un archivo.

Las rutinas de escritura de claves privadas (y también las de PKCS#8) que toman el parámetro enc permitirán que la clave se escriba en un formato no encriptado si enc es NULL.

Si la escritura de una clave privada o PKCS#8 encriptada se realiza sin usar una rutina de callback (es decir, cb es NULL), y los argumentos kstr y klen son proporcionados, entonces estos se usarán como contraseña. Si también son NULL o cero, se usará una contraseña predeterminada, generalmente una cadena vacía.

Las rutinas que leen claves privadas (por ejemplo, PEM_read_bio_PrivateKey) pueden leer claves privadas en diferentes formatos (PEM, DER). Sin embargo, la escritura solo admite el formato PEM.

PEM_read_bio_PKCS8 y PEM_read_PKCS8 leen una estructura PKCS8 encriptada. La contraseña se requiere para desencriptarla. El resultado es una estructura X509_SIG que contiene la clave privada y los certificados (si los hubiere).

PEM_write_bio_PKCS8 y PEM_write_PKCS8 escriben una estructura X509_SIG en formato PKCS8 encriptado. No es posible escribir una estructura X509_SIG en formato PEM no encriptado, ni tampoco escribir solo la clave privada sin certificados.

PEM_read_bio_PKCS8_PRIV_KEY_INFO y PEM_read_PKCS8_PRIV_KEY_INFO leen una clave privada PKCS#8 no encriptada. La contraseña no es necesaria para leerla.

PEM_write_bio_PKCS8_PRIV_KEY_INFO y PEM_write_PKCS8_PRIV_KEY_INFO escriben una clave privada PKCS#8 no encriptada. No es posible escribir una clave privada en formato encriptado con estas funciones.

La función PEM_write_bio_X509_REQ_NEW y PEM_write_X509_REQ_NEW escriben una solicitud de certificado X.509 en el formato más nuevo y recomendado, que incluye la clave privada.

VALORES DE RETORNO

Las funciones de lectura devuelven un puntero al objeto leído, o NULL en caso de error. Las funciones de escritura devuelven 1 en caso de éxito, o 0 en caso de error.

Si x es NULL, las funciones de lectura asignan memoria para el objeto devuelto. El llamador es responsable de liberarla con la función apropiada (por ejemplo, EVP_PKEY_free, RSA_free, etc.). Si x no es NULL, las funciones de lectura escriben el resultado en la dirección apuntada por x, y el llamador no debe liberar el objeto si ya existía. Si la lectura falla y x no era NULL, el valor al que apunta x no se modifica.

En caso de error, la causa se puede encontrar en ERR_get_error(3).

EJEMPLO

Ejemplo de lectura de clave privada encriptada:

#include <stdio.h>
#include <openssl/pem.h>
#include <openssl/err.h>
#include <openssl/evp.h>
#include <openssl/bio.h>

static int password_callback(char *buf, int size, int rwflag, void *userdata) {
    // Aquí puedes solicitar la contraseña al usuario, leerla de un archivo, etc.
    // En este ejemplo, usamos una contraseña fija.
    const char *password = "mysecretpassword";
    int len = strlen(password);
    if (len > size) {
        len = size;
    }
    memcpy(buf, password, len);
    return len;
}

int main(int argc, char **argv) {
    FILE *fp;
    EVP_PKEY *pkey;
    BIO *bio;

    if (argc != 2) {
        fprintf(stderr, "Usage: %s <keyfile>\n", argv[0]);
        return 1;
    }

    fp = fopen(argv[1], "r");
    if (!fp) {
        perror("Error opening file");
        return 1;
    }

    // Convertir FILE* a BIO*
    bio = BIO_new_fp(fp, BIO_NOCLOSE);
    if (!bio) {
        fprintf(stderr, "Error creating BIO from file\n");
        fclose(fp);
        return 1;
    }

    // Leer la clave privada encriptada
    pkey = PEM_read_bio_PrivateKey(bio, NULL, password_callback, NULL);
    BIO_free(bio); // BIO_free(bio) con BIO_NOCLOSE no cierra el archivo.
    fclose(fp);    // Cerramos el archivo explícitamente.

    if (!pkey) {
        fprintf(stderr, "Error reading private key\n");
        ERR_print_errors_fp(stderr);
        return 1;
    }

    printf("Private key read successfully.\n");

    // Hacer algo con la clave privada...

    EVP_PKEY_free(pkey);
    return 0;
}

Ejemplo de escritura de clave privada encriptada:

#include <stdio.h>
#include <openssl/pem.h>
#include <openssl/err.h>
#include <openssl/evp.h>
#include <openssl/rsa.h>
#include <openssl/bio.h>

static int password_callback(char *buf, int size, int rwflag, void *userdata) {
    // Similar al ejemplo anterior
    const char *password = "mysecretpassword";
    int len = strlen(password);
    if (len > size) {
        len = size;
    }
    memcpy(buf, password, len);
    return len;
}

int main(int argc, char **argv) {
    FILE *fp;
    EVP_PKEY *pkey = NULL;
    RSA *rsa_key = NULL;
    BIO *bio;

    // Generar una clave RSA de ejemplo
    rsa_key = RSA_new();
    if (!rsa_key) {
        fprintf(stderr, "Error creating RSA key\n");
        return 1;
    }
    if (!RSA_generate_key_ex(rsa_key, 2048, NULL, NULL)) {
        fprintf(stderr, "Error generating RSA key\n");
        RSA_free(rsa_key);
        return 1;
    }

    pkey = EVP_PKEY_new();
    if (!pkey) {
        fprintf(stderr, "Error creating EVP_PKEY\n");
        RSA_free(rsa_key);
        return 1;
    }
    if (!EVP_PKEY_assign_RSA(pkey, rsa_key)) {
        fprintf(stderr, "Error assigning RSA key to EVP_PKEY\n");
        EVP_PKEY_free(pkey);
        RSA_free(rsa_key); // EVP_PKEY_assign_RSA no toma posesión si falla
        return 1;
    }
    // Ahora pkey tiene posesión de rsa_key, no necesitamos liberarlo por separado

    fp = fopen("private_key.pem", "w");
    if (!fp) {
        perror("Error opening file for writing");
        EVP_PKEY_free(pkey);
        return 1;
    }

    bio = BIO_new_fp(fp, BIO_NOCLOSE);
    if (!bio) {
        fprintf(stderr, "Error creating BIO from file\n");
        fclose(fp);
        EVP_PKEY_free(pkey);
        return 1;
    }

    // Escribir la clave privada encriptada (AES-256-CBC por defecto)
    // PEM_write_bio_PrivateKey(bio, pkey, EVP_aes_256_cbc(), NULL, 0, password_callback, NULL);
    // O usa la versión PKCS8 que es más común

DESCRIPTION

Las funciones PEM leen o escriben estructuras en formato PEM. En este sentido, el formato PEM es simplemente datos codificados en base64 rodeados por líneas de encabezado; véase PEM_read(3) para más detalles.

Para más detalles sobre el significado de los argumentos, consulte la sección Argumentos de la función PEM.

Cada operación tiene cuatro funciones asociadas con ella. Por brevedad, el término “funciones de TIPO” se usará para referirse colectivamente a las funciones PEM_read_bio_TYPE(), PEM_read_TYPE(), PEM_write_bio_TYPE(), y PEM_write_TYPE(). Si no existe un conjunto de funciones específicas para un tipo dado, se puede usar PEM_ASN1_read(3) en su lugar.

Las funciones PrivateKey leen o escriben una clave privada en formato PEM utilizando una estructura EVP_PKEY. Las rutinas de escritura utilizan el formato de clave privada "tradicional" y pueden manejar claves privadas tanto RSA como DSA. Las funciones de lectura también pueden manejar de forma transparente claves cifradas y no cifradas en formato PKCS#8.

PEM_write_bio_PKCS8PrivateKey() y PEM_write_PKCS8PrivateKey() escriben una clave privada en una estructura EVP_PKEY en formato PKCS#8 EncryptedPrivateKeyInfo utilizando algoritmos de cifrado basados en contraseña PKCS#5 v2.0. El argumento enc especifica el algoritmo de cifrado a utilizar: a diferencia de todas las demás rutinas PEM, el cifrado se aplica a nivel de PKCS#8 y no en los encabezados PEM. Si enc es NULL, entonces no se utiliza ningún cifrado y se utiliza una estructura PKCS#8 PrivateKeyInfo en su lugar.

PEM_write_bio_PKCS8PrivateKey_nid() y PEM_write_PKCS8PrivateKey_nid() también escriben una clave privada como una EncryptedPrivateKeyInfo de PKCS#8. Sin embargo, utilizan algoritmos de cifrado PKCS#5 v1.5 o PKCS#12 en su lugar. El algoritmo a utilizar se especifica en el parámetro nid y debe ser el NID del OBJECT IDENTIFIER correspondiente.

Las funciones PKCS8 procesan una clave privada cifrada utilizando una estructura X509_SIG y la función d2i_X509_SIG(3).

Las funciones PKCS8_PRIV_KEY_INFO procesan una clave privada utilizando una estructura PKCS8_PRIV_KEY_INFO.

Las funciones PUBKEY procesan una clave pública utilizando una estructura EVP_PKEY. La clave pública se codifica como una estructura ASN.1 SubjectPublicKeyInfo.

Las funciones RSAPrivateKey procesan una clave privada RSA utilizando una estructura RSA. Manejan los mismos formatos que las funciones PrivateKey, pero se produce un error si la clave privada no es RSA.

Las funciones RSAPublicKey procesan una clave pública RSA utilizando una estructura RSA. La clave pública se codifica utilizando una estructura PKCS#1 RSAPublicKey.

Las funciones RSA_PUBKEY también procesan una clave pública RSA utilizando una estructura RSA. Sin embargo, la clave pública se codifica utilizando una estructura ASN.1 SubjectPublicKeyInfo y se produce un error si la clave pública no es RSA.

Las funciones DSAPrivateKey procesan una clave privada DSA utilizando una estructura DSA. Manejan los mismos formatos que las funciones PrivateKey, pero se produce un error si la clave privada no es DSA.

Las funciones DSA_PUBKEY procesan una clave pública DSA utilizando una estructura DSA. La clave pública se codifica utilizando una estructura ASN.1 SubjectPublicKeyInfo y se produce un error si la clave pública no es DSA.

Las funciones DSAparams procesan parámetros DSA utilizando una estructura DSA. Los parámetros se codifican utilizando una estructura Dss-Parms tal como se define en RFC 2459.

Las funciones DHparams procesan parámetros DH utilizando una estructura DH. Los parámetros se codifican utilizando una estructura PKCS#3 DHparameter.

Las funciones ECPKParameters procesan parámetros EC utilizando una estructura EC_GROUP y la función d2i_ECPKParameters(3).

Las funciones ECPrivateKey procesan una clave privada EC utilizando una estructura EC_KEY.

Las funciones EC_PUBKEY procesan una clave pública EC utilizando una estructura EC_KEY.

Las funciones X509 procesan un certificado X509 utilizando una estructura X509. También procesarán un certificado X509 de confianza, pero se descartarán cualquier configuración de confianza.

Las funciones X509_AUX procesan un certificado X509 de confianza utilizando una estructura X509.

Las funciones X509_REQ y X509_REQ_NEW procesan una solicitud de certificado PKCS#10 utilizando una estructura X509_REQ. Las funciones de escritura X509_REQ usan CERTIFICATE REQUEST en el encabezado, mientras que las funciones X509_REQ_NEW usan NEW CERTIFICATE REQUEST (como requieren algunas CA). Las funciones de lectura X509_REQ manejarán cualquiera de las dos formas, por lo que no hay funciones de lectura X509_REQ_NEW.

Las funciones X509_CRL procesan una CRL X509 utilizando una estructura X509_CRL.

Las funciones PKCS7 procesan un objeto PKCS#7 utilizando una estructura PKCS7.

Las funciones CMS procesan un objeto CMS (Cryptographic Message Syntax) utilizando una estructura CMS_ContentInfo.

Los argumentos son los siguientes:

bp
Un puntero a un BIO (Buffer I/O) de donde leer, o a donde escribir.
fp
Un puntero a un FILE (stream C) de donde leer, o a donde escribir.
x
Un puntero a un puntero a la estructura que se va a leer o escribir. Si no es NULL, el puntero será actualizado para apuntar a la estructura recién asignada o liberada después de la operación.
cb
Una función de devolución de llamada de contraseña opcional que se utiliza para obtener contraseñas para descifrar datos PEM. Si es NULL, entonces se usa una función de contraseña predeterminada que solicita la contraseña desde la terminal (si está disponible).
u
Un puntero a datos definidos por el usuario que se pasan a la función de devolución de llamada cb.

Las funciones de lectura devuelven un puntero a la estructura solicitada, o NULL si falla. Las funciones de escritura devuelven 1 si tienen éxito, o 0 si falla.

La función PEM_read_bio_X509_REQ lee datos de una solicitud de certificado X509 de un BIO. La función PEM_read_X509_REQ lee de un FILE stream. La función PEM_write_bio_X509_REQ escribe una solicitud de certificado X509 en un BIO. La función PEM_write_X509_REQ escribe en un FILE stream. Las funciones PEM_write_bio_X509_REQ_NEW y PEM_write_X509_REQ_NEW escriben una solicitud de certificado X509 en formato PEM. La diferencia es que usan el encabezado “NEW CERTIFICATE REQUEST” en lugar de “CERTIFICATE REQUEST”. Esto es necesario para algunas autoridades de certificación (CA).

Las funciones PEM_read_bio_X509_CRL y PEM_read_X509_CRL leen una Lista de Revocación de Certificados (CRL) X509 de un BIO o FILE respectivamente. Las funciones PEM_write_bio_X509_CRL y PEM_write_X509_CRL escriben una CRL X509 en un BIO o FILE respectivamente.

Las funciones PEM_read_bio_PKCS7 y PEM_read_PKCS7 leen un objeto PKCS#7 de un BIO o FILE respectivamente. Las funciones PEM_write_bio_PKCS7 y PEM_write_PKCS7 escriben un objeto PKCS#7 en un BIO o FILE respectivamente.

Las funciones PEM_read_CMS y PEM_read_bio_CMS leen un objeto CMS (Cryptographic Message Syntax) de un FILE o BIO respectivamente. Las funciones PEM_write_CMS y PEM_write_bio_CMS escriben un objeto CMS en un FILE o BIO respectivamente.

La función de devolución de llamada de contraseña cb toma tres argumentos: un puntero a la estructura que se está procesando, un entero que indica si la operación es de lectura o escritura, y el puntero de datos de usuario u. Devuelve la longitud de la contraseña, o 0 si se produce un error. La contraseña se coloca en el búfer apuntado por el primer argumento (el puntero a la estructura).

El contenido se escribe en un formato ContentInfo usando una estructura PKCS7.

Las funciones CMS procesan una estructura CMS_ContentInfo.

Las rutinas antiguas de escritura de PrivateKey se conservan por compatibilidad. Las nuevas aplicaciones deben escribir claves privadas usando las rutinas PEM_write_bio_PKCS8PrivateKey() o PEM_write_PKCS8PrivateKey() porque son más seguras (usan un recuento de iteraciones de 2048, mientras que las rutinas tradicionales usan un recuento de 1) a menos que la compatibilidad con versiones anteriores de OpenSSL sea importante.

Las rutinas de lectura de PrivateKey se pueden usar en todas las aplicaciones porque manejan todos los formatos de forma transparente.

Argumentos de funciones PEM

Las funciones PEM tienen muchos argumentos comunes.

El parámetro bp especifica el BIO del que leer o escribir.

El parámetro fp especifica el puntero FILE del que leer o escribir.

Las funciones de lectura PEM toman un argumento de puntero a puntero x y devuelven un puntero del mismo tipo. Si x es NULL, el parámetro se ignora. Si x no es NULL pero *x es NULL, la estructura devuelta se escribirá en *x. Si ni x ni *x son NULL, se intenta reutilizar la estructura en *x, pero consulte las secciones de BUGS y EJEMPLOS. Independientemente del valor de x, siempre se devuelve un puntero a la estructura, o NULL si ocurrió un error.

Las funciones PEM que escriben claves privadas toman un parámetro enc, que especifica el algoritmo de cifrado a usar. El cifrado se realiza a nivel PEM. Si este parámetro se establece en NULL, la clave privada se escribe sin cifrar.

Los argumentos opcionales u y cb son una contraseña utilizada para cifrar una estructura PEM o una función de devolución de llamada para obtener la contraseña; consulte pem_password_cb(3) para obtener más detalles.

Para las rutinas de escritura PEM, si el parámetro kstr no es NULL, entonces klen bytes en kstr se usan como contraseña y cb se ignora.

Formato de cifrado PEM

Estas antiguas rutinas de PrivateKey utilizan una técnica no estándar para el cifrado.

La clave privada (u otros datos) tiene el siguiente formato:

-----BEGIN RSA PRIVATE KEY-----
Proc-Type: 4,ENCRYPTED
DEK-Info: DES-EDE3-CBC,3F17F5316E2BAC89

...datos codificados en base64...
-----END RSA PRIVATE KEY-----

La línea que comienza con “DEK-Info” contiene dos piezas de información separadas por comas: el nombre del algoritmo de cifrado tal como lo utiliza EVP_get_cipherbyname(3) y una sal de 8 bytes codificada como un conjunto de dígitos hexadecimales.

Después de esto, están los datos cifrados codificados en base64.

La clave de cifrado se determina usando EVP_BytesToKey(3), usando la sal y un recuento de iteraciones de 1. El IV utilizado es el valor de la sal y *no* el IV devuelto por EVP_BytesToKey(3).

VALORES DE RETORNO

Las rutinas de lectura devuelven un puntero a la estructura leída o NULL si ocurrió un error.

Las rutinas de escritura devuelven 1 para el éxito o 0 para el fallo.

EJEMPLOS

Aunque las funciones PEM toman varios argumentos, en casi todas las aplicaciones la mayoría de ellos se establecen en 0 o NULL.

Leer un certificado en formato PEM de un BIO:

X509 *x;
x = PEM_read_bio_X509(bp, NULL, 0, NULL);
if (x == NULL) {
	/* Error */
}

Método alternativo:

X509 *x = NULL;
if (!PEM_read_bio_X509(bp, &x, 0, NULL)) {
	/* Error */
}

Escribir un certificado en un BIO:

if (!PEM_write_bio_X509(bp, x)) {
	/* Error */
}

Escribir una clave privada sin cifrar en un FILE:

if (!PEM_write_PrivateKey(fp, key, NULL, NULL, 0, 0, NULL)) {
	/* Error */
}

Escribir una clave privada (usando formato tradicional) en un BIO usando cifrado triple DES; se solicita la frase contraseña:

if (!PEM_write_bio_PrivateKey(bp, key, EVP_des_ede3_cbc(),
    NULL, 0, 0, NULL)) {
	/* Error */
}

Escribir una clave privada (usando formato PKCS#8) en un BIO usando cifrado triple DES, usando la frase contraseña “hello”:

if (!PEM_write_bio_PKCS8PrivateKey(bp, key, EVP_des_ede3_cbc(),
    NULL, 0, 0, "hello")) {
	/* Error */
}

Leer una clave privada de un BIO usando la frase contraseña “hello”:

key = PEM_read_bio_PrivateKey(bp, NULL, 0, "hello");
if (key == NULL) {
	/* Error */
}

Leer una clave privada de un BIO usando una función de devolución de llamada para la frase contraseña:

key = PEM_read_bio_PrivateKey(bp, NULL, pass_cb, "My Private Key");
if (key == NULL) {
	/* Error */
}

Función de devolución de llamada de frase contraseña esqueleto:

int
pass_cb(char *buf, int size, int rwflag, void *u)
{
	char	*tmp;
	size_t	 len;

	/* Probablemente haríamos algo más si 'rwflag' es 1 */
	printf("Enter pass phrase for \"%s\"\n", u);

	/*
	 * En lugar de la siguiente línea, obtenga la frase
	 * contraseña del usuario de alguna manera.
	 */
	tmp = "hello";
	if (tmp == NULL) /* Ocurrió un error. */
		return -1;

	len = strlen(tmp);
	if (len == 0) /* Tratar una frase contraseña vacía como un error también. */
		return -1;

	/* si es demasiado larga, truncar */
	if (len > size)
		len = size;
	memcpy(buf, tmp, len);
	return len;
}

ADVERTENCIAS

Una causa frecuente de problemas es intentar usar las rutinas PEM de esta manera:

X509 *x;
PEM_read_bio_X509(bp, &x, 0, NULL);

Esto es un error porque se intentará reutilizar los datos en x, que es un puntero no inicializado.

Estas funciones no hacen ninguna suposición sobre la frase de contraseña recibida del callback de contraseña. Simplemente se tratará como una secuencia de bytes.

ERRORES

Las rutinas de lectura PEM en algunas versiones de OpenSSL no reutilizarán correctamente una estructura existente. Por lo tanto

PEM_read_bio_X509(bp, &x, 0, NULL);

donde x ya contiene un certificado válido puede no funcionar, mientras que

X509_free(x);
x = PEM_read_bio_X509(bp, NULL, 0, NULL);

se garantiza que funcionará.
