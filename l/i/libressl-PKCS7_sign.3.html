PKCS7_SIGN(3) Manual de funciones de la biblioteca PKCS7_SIGN(3)

NOMBRE

PKCS7_sign — crear una estructura signedData PKCS#7

SINOPSIS

biblioteca «libcrypto»
#include <openssl/pkcs7.h>

PKCS7 *
PKCS7_sign(X509 *signcert, EVP_PKEY *pkey, STACK_OF(X509) *certs, BIO *data, int flags);

DESCRIPCIÓN

PKCS7_sign() crea y devuelve una estructura signedData PKCS#7. signcert es el certificado con el que firmar, pkey es la clave privada correspondiente. certs es un conjunto opcional de certificados adicionales para incluir en la estructura PKCS#7 (por ejemplo, cualquier CA intermedia en la cadena).

Los datos a firmar se leen del BIO data.

flags es un conjunto opcional de indicadores.

Cualquiera de los siguientes indicadores (combinados con OR) se puede pasar en el parámetro flags.

Muchos clientes S/MIME esperan que el contenido firmado incluya encabezados MIME válidos. Si el indicador PKCS7_TEXT está establecido, se anteponen encabezados MIME del tipo text/plain a los datos.

Si se establece PKCS7_NOCERTS, el certificado del firmante no se incluirá en la estructura PKCS7, aunque el certificado del firmante aún debe proporcionarse en el parámetro signcert. Esto puede reducir el tamaño de la firma si el certificado del firmante se puede obtener por otros medios: por ejemplo, un mensaje firmado previamente.

Los datos que se están firmando se incluyen en la estructura PKCS7, a menos que se establezca PKCS7_DETACHED, en cuyo caso se omite. Esto se utiliza para firmas PKCS7 separadas que se utilizan en mensajes firmados en texto plano S/MIME, por ejemplo.

Normalmente, el contenido proporcionado se traduce al formato canónico MIME (según lo exigen las especificaciones S/MIME). Si se establece PKCS7_BINARY, no se produce ninguna traducción. Esta opción debe usarse si los datos proporcionados están en formato binario; de lo contrario, la traducción los corromperá.

La estructura signedData incluye varios authenticatedAttributes PKCS#7, incluido el tiempo de firma, el tipo de contenido PKCS#7 y la lista de cifradores compatibles en un atributo SMIMECapabilities. Si se establece PKCS7_NOATTR, no se utilizarán authenticatedAttributes. Si se establece PKCS7_NOSMIMECAP, solo se omiten las SMIMECapabilities.

Si están presentes, el atributo SMIMECapabilities indica compatibilidad con los siguientes algoritmos: triple DES, RC2 de 128 bits, RC2 de 64 bits, DES y RC2 de 40 bits. Si alguno de estos algoritmos está deshabilitado, no se incluirá.

Si se establece el indicador PKCS7_STREAM, la estructura PKCS7 devuelta solo se inicializa lista para realizar la operación de firma. Sin embargo, la firma no se realiza y los datos a firmar no se leen del parámetro data. La firma se pospone hasta después de que se hayan escrito los datos. De esta manera, los datos se pueden firmar en un solo paso.

Si se establece el indicador PKCS7_PARTIAL, se genera una estructura PKCS7 parcial a la que se pueden agregar firmantes y capacidades adicionales antes de la finalización.

Si se establece el indicador PKCS7_STREAM, la estructura PKCS7 devuelta no está completa y la salida de sus contenidos a través de una función que no finaliza correctamente la estructura PKCS7 dará resultados impredecibles.

Varias funciones, incluidas PKCS7_final(3), SMIME_write_PKCS7(3), PEM_write_bio_PKCS7_stream(3), y i2d_PKCS7_bio_stream(3) finalizan la estructura. Alternativamente, la finalización se puede realizar obteniendo directamente el BIO ASN.1 en streaming usando BIO_new_PKCS7().

Si se especifica un firmante, se utilizará el digest por defecto para el algoritmo de firma. Este es SHA1 para claves RSA y DSA.

En OpenSSL 1.0.0, los parámetros certs, signcert, y pkey pueden ser todos NULL si se establece el indicador PKCS7_PARTIAL. Se pueden agregar uno o más firmantes usando la función PKCS7_sign_add_signer(3) y se pueden agregar atributos usando las funciones descritas en PKCS7_add_attribute(3). También se debe llamar a PKCS7_final(3) para finalizar la estructura si el streaming no está habilitado. Los digests de firma alternativos también se pueden especificar utilizando este método.

En OpenSSL 1.0.0, si signcert y pkey son NULL, se genera una estructura PKCS#7 solo de certificado.

En versiones de OpenSSL anteriores a 1.0.0, los parámetros signcert y pkey NO deben ser NULL.

VALORES DE RETORNO

PKCS7_sign() devuelve una estructura PKCS7 válida o NULL si ocurrió un error. El error se puede obtener de ERR_get_error(3).

VER TAMBIÉN

PKCS7_add_attribute(3), PKCS7_encrypt(3), PKCS7_final(3), PKCS7_get_signer_info(3), PKCS7_new(3), PKCS7_sign_add_signer(3), PKCS7_verify(3)

HISTORIA

PKCS7_sign() apareció por primera vez en OpenSSL 0.9.5 y ha estado disponible desde OpenBSD 2.7.

Los indicadores PKCS7_PARTIAL y PKCS7_STREAM se agregaron en OpenSSL 1.0.0.

ERRORES

LibreSSL 3.9.1 PKCS7_sign(3)

NAME

PKCS7_sign, PKCS7_verify — create and verify PKCS#7 signed-data structures

SYNOPSIS

#include <openssl/pkcs7.h>

PKCS7 *PKCS7_sign(STACK_OF(X509) *certs, EVP_PKEY *privkey, STACK_OF(X509_ATTRIBUTE) *attrs, BIO *data, int flags);

int PKCS7_verify(PKCS7 *p7, STACK_OF(X509) *certs, X509_STORE *store, BIO *data, int flags);

DESCRIPTION

The PKCS7_sign() function creates a PKCS#7 signed-data structure. The structure is populated with the supplied certificates (certs), the signer's private key (privkey), and attributes (attrs).

The signed data is read from the BIO data and included in the PKCS#7 structure. If data is NULL, the PKCS#7 structure will contain no signed data.

The PKCS7_verify() function verifies a PKCS#7 signed-data structure. The certificates of the signers are taken from the certs argument. If certs is NULL, the certificates are taken from the PKCS#7 structure itself.

The store argument is an X509_STORE structure used to verify the signer's certificates. If store is NULL, the default store is used.

If data is not NULL, the signed data is read from data and compared with the signed data in the PKCS#7 structure.

The flags argument can be used to control the behavior of the functions. The following flags are supported:

PKCS7_DETACHED
Create or verify a detached signature. In this case, the signed data is not included in the PKCS#7 structure.
PKCS7_TEXT
Include text attributes in the signature.

RETURN VALUES

The PKCS7_sign() function returns a pointer to the created PKCS7 structure on success, or NULL on failure.

The PKCS7_verify() function returns 1 on success, or 0 on failure.

SEE ALSO

PKCS7_dataInit(3), PKCS7_final(3), X509_STORE_new(3)

HISTORY

The PKCS7_sign() and PKCS7_verify() functions first appeared in OpenSSL 0.9.0.
