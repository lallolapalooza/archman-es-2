SSL_CTX_SET_ALPN_SELECT_CB(3) Manual de funciones de biblioteca SSL_CTX_SET_ALPN_SELECT_CB(3)

NOMBRE

SSL_CTX_set_alpn_protos, SSL_set_alpn_protos, SSL_CTX_set_alpn_select_cb, SSL_select_next_proto, SSL_get0_alpn_selected — manejar la negociación de protocolos de capa de aplicación (ALPN)

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_CTX_set_alpn_protos(SSL_CTX *ctx, const unsigned char *protos, unsigned int protos_len);

int
SSL_set_alpn_protos(SSL *ssl, const unsigned char *protos, unsigned int protos_len);

void
SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx, int (*cb)(SSL *ssl, const unsigned char **out, unsigned char *outlen, const unsigned char *in, unsigned int inlen, void *arg), void *arg);

int
SSL_select_next_proto(unsigned char **out, unsigned char *outlen, const unsigned char *peer_list, unsigned int peer_list_len, const unsigned char *supported_list, unsigned int supported_list_len);

void
SSL_get0_alpn_selected(const SSL *ssl, const unsigned char **data, unsigned int *len);

DESCRIPCIÓN

SSL_CTX_set_alpn_protos() y SSL_set_alpn_protos() son utilizadas por el cliente para establecer la lista de protocolos disponibles para negociar. Los protos deben estar en formato de lista de protocolos, descrito a continuación. La longitud de protos se especifica en protos_len.

SSL_CTX_set_alpn_select_cb() establece la devolución de llamada de aplicación cb utilizada por un servidor para seleccionar qué protocolo usar para la conexión entrante. Cuando cb es NULL, ALPN no se usa. El valor arg es un puntero que se pasa a la devolución de llamada de la aplicación.

cb es la devolución de llamada definida por la aplicación. Los parámetros in, inlen son un vector en formato de lista de protocolos. El valor del vector out, outlen debe establecerse en el valor de un solo protocolo seleccionado del vector in, inlen. El buffer out puede apuntar directamente a in, o a un buffer que persista después del handshake. El parámetro arg es el puntero establecido a través de SSL_CTX_set_alpn_select_cb().

SSL_select_next_proto() es una función auxiliar utilizada para seleccionar protocolos. Se espera que esta función sea llamada desde la devolución de llamada de la aplicación cb. Si SSL_select_next_proto() devuelve OPENSSL_NPN_NO_OVERLAP, cb debe ignorar out y fallar devolviendo SSL_TLSEXT_ERR_ALERT_FATAL. Los datos del protocolo en peer_list, peer_list_len y supported_list, supported_list_len deben ser dos listas no vacías, codificadas válidamente en el formato de lista de protocolos descrito a continuación. El primer elemento en peer_list que coincide con un elemento en supported_list se selecciona y se devuelve en out, outlen. El valor out apuntará a peer_list o supported_list, por lo que no debe modificarse y debe copiarse inmediatamente. Si no se encuentra ninguna coincidencia, se devuelve el primer elemento en supported_list en out, outlen.

SSL_get0_alpn_selected() devuelve un puntero al protocolo seleccionado en data con longitud len. No está terminado en NUL. data se establece en NULL y len se establece en 0 si no se ha seleccionado ningún protocolo. data no debe liberarse.

Las listas de protocolos deben estar en formato de transmisión (wire-format), que se define como un vector de cadenas de bytes no vacías y con prefijo de longitud de 8 bits. El byte de prefijo de longitud no se incluye en la longitud. Cada cadena está limitada a 255 bytes. Una longitud de cadena de bytes de 0 no es válida. La longitud del vector no está en el vector mismo, sino en una variable separada.

Por ejemplo:

const unsigned char *vector = "\x06" "spdy/1" "\x08" "http/1.1";
unsigned int length = strlen(vector);

La devolución de llamada ALPN se ejecuta después de la devolución de llamada de nombre de servidor; ya que esa devolución de llamada de nombre de servidor puede actualizar el SSL_CTX, y posteriormente, la devolución de llamada ALPN.

Si no hay ninguna propuesta ALPN en el ClientHello, la devolución de llamada ALPN no se invoca.

VALORES DE RETORNO

SSL_CTX_set_alpn_protos() y SSL_set_alpn_protos() devuelven 0 en caso de éxito o un valor distinto de cero en caso de error. ADVERTENCIA: estas funciones invierten la convención del valor de retorno.

SSL_select_next_proto() devuelve uno de los siguientes:

OPENSSL_NPN_NEGOTIATED
Se encontró una coincidencia y se devuelve en out, outlen.
OPENSSL_NPN_NO_OVERLAP
No se encontró ninguna coincidencia. Se devuelve el primer elemento en supported_list, supported_list_len en out, outlen.

La devolución de llamada de selección ALPN cb debe devolver uno de los siguientes:

SSL_TLSEXT_ERR_OK
Protocolo ALPN seleccionado.
SSL_TLSEXT_ERR_ALERT_FATAL
No hubo superposición entre la lista proporcionada por el cliente y la configuración del servidor.
SSL_TLSEXT_ERR_NOACK
Protocolo ALPN no seleccionado, por ejemplo, porque no hay protocolos ALPN configurados para esta conexión.

libressl-SSL_CTX_set_alpn_select_cb(3) — LibreSSL 4.2.1

NAME

SSL_CTX_set_alpn_select_cb, SSL_CTX_set_alpn_protos, SSL_provide_server_selected_alpn_token, SSL_select_next_proto — application-level protocol negotiation

SYNOPSIS

#include <openssl/ssl.h>
int
SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx,
    int (*cb)(SSL *ssl, const unsigned char **out, unsigned char *outlen,
    const unsigned char *in, unsigned int inlen, void *arg), void *arg);
int
SSL_CTX_set_alpn_protos(SSL_CTX *ctx,
    const unsigned char *protos, unsigned int protoslen);
int
SSL_provide_server_selected_alpn_token(SSL *ssl,
    const unsigned char *token, unsigned int tokenlen);
int
SSL_select_next_proto(unsigned char **out, unsigned char *outlen,
    const unsigned char *me, unsigned int mellen,
    const unsigned char *peer, unsigned int peerlen);

DESCRIPTION

The Application-Level Protocol Negotiation (ALPN) extension (RFC 7469) allows an application to negotiate a protocol over TLS. This is used for protocols like HTTP/2.

SSL_CTX_set_alpn_select_cb() sets a callback function cb to be used by ctx to select the protocol to be offered by the server.

The callback is called with ssl the SSL object, out and outlen pointers to be filled with the negotiated protocol, in and inlen which is the list of protocols offered by the client, and arg which is the arbitrary argument passed to SSL_CTX_set_alpn_select_cb().

The callback should iterate through the client's offered protocols in in and inlen. If it finds a protocol that it also supports, it should set out to point to the start of the protocol in in, set outlen to the length of the protocol, and return SSL_ERROR_NONE. If no common protocol is found, the callback should return SSL_ERROR_SYSCALL.

SSL_CTX_set_alpn_protos() registers a list of protocols supported by the server in protos and protoslen. This function is intended to be called by clients. The protocols are represented as a sequence of 8-bit length-prefixed strings, e.g. "\x02h2\x08http/1.1".

SSL_provide_server_selected_alpn_token() is intended to be called by servers. It provides the selected protocol token to be sent to the client. It should be called after a successful handshake. The token should be one of the protocols previously registered using SSL_CTX_set_alpn_protos() or returned by the ALPN callback.

SSL_select_next_proto() is a helper function. me and mellen are the protocols supported by the current side, and peer and peerlen are the protocols offered by the other side. It returns the negotiated protocol via out and outlen. The return value is 0 on success, or a non-zero error code otherwise.

The protocols are encoded as length-prefixed byte strings. The function finds the first protocol in peer that is also present in me. If found, it copies the protocol to out and returns 0. If no common protocol is found, it returns 1.

RETURN VALUES

SSL_CTX_set_alpn_select_cb(), SSL_CTX_set_alpn_protos(), and SSL_provide_server_selected_alpn_token() return 1 on success, and 0 on failure.

SSL_select_next_proto() returns 0 on success, and 1 if no common protocol is found.

SEE ALSO

SSL_CTX(3), SSL_set_alpn_protos(3), SSL_get_negotiated_alpn_protocol(3)

STANDARDS

RFC 7469: Application-Layer Protocol Negotiation (ALPN)

HISTORY

The ALPN support was added in OpenSSL 1.0.2. The SSL_select_next_proto() function was added in OpenSSL 1.0.2 and has been available since OpenBSD 5.7.

CAVEATS

The fallback to the first supported protocol in SSL_select_next_proto() comes from the opportunistic fallback mechanism in the NPN extension. This behavior does not make sense for ALPN, where missing protocol overlap should result in a handshake failure. To avoid accidental selection of a protocol that the server does not support, it is recommended to pass the locally configured protocols as second pair of protocols in the ALPN callback.

BUGS

The out argument of SSL_select_next_proto() should have been const.
