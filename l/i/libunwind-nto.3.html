LIBUNWIND-NTO(3libunwind) Biblioteca de programación LIBUNWIND-NTO(3libunwind)

NOMBRE

libunwind-nto -- Soporte para QNX Neutrino en libunwind

SINOPSIS

#include <libunwind-nto.h>

unw_accessors_t unw_nto_accessors;

void *unw_nto_create(pid_t, pthread_t);
void unw_nto_destroy(void *);

int unw_nto_find_proc_info(unw_addr_space_t, unw_word_t, unw_proc_info_t *, int, void *);
void unw_nto_put_unwind_info(unw_addr_space_t, unw_proc_info_t *, void *);
int unw_nto_get_dyn_info_list_addr(unw_addr_space_t, unw_word_t *, void *);
int unw_nto_access_mem(unw_addr_space_t, unw_word_t, unw_word_t *, int, void *);
int unw_nto_access_reg(unw_addr_space_t, unw_regnum_t, unw_word_t *, int, void *);
int unw_nto_access_fpreg(unw_addr_space_t, unw_regnum_t, unw_fpreg_t *, int, void *);
int unw_nto_get_proc_name(unw_addr_space_t, unw_word_t, char *, size_t, unw_word_t *, void *);
int unw_nto_resume(unw_addr_space_t, unw_cursor_t *, void *);

DESCRIPCIÓN

El sistema operativo QNX permite que un proceso obtenga acceso al estado de la máquina y a la memoria virtual de otro proceso, o a un hilo diferente dentro del mismo proceso. Es posible conectar libunwind a otro proceso. Aunque no es muy difícil hacerlo directamente, libunwind facilita aún más esta tarea al proporcionar callbacks listos para usar con este propósito. Las rutinas y variables que implementan esta funcionalidad usan un prefijo de nombre unw_nto, que significa "unwind-via-nto".

Una aplicación que quiera usar el remoto NTO de libunwind debe seguir los siguientes pasos.

1.
Cree un nuevo espacio de direcciones de libunwind que represente el proceso y hilo de destino. Esto se hace llamando a unw_create_addr_space(). En muchos casos, la aplicación simplemente querrá pasar la dirección de unw_nto_accessors como primer argumento a esta rutina. Hacerlo asegurará que libunwind pueda desenrollar correctamente el proceso de destino.
2.
Cree una estructura de información NTO llamando a unw_nto_create(), pasando el pid y tid del hilo de proceso de destino como argumentos. Esto detendrá el hilo de destino. Se debe conocer el ID del proceso (pid) del proceso de destino, y solo se puede desenrollar un hilo a la vez, por lo que también se debe especificar el ID del hilo (tid).
3.
El puntero opaco devuelto debe pasarse como el puntero del "argumento" (tercer argumento) a unw_init_remote().

Cuando la aplicación termine de usar libunwind en el proceso de destino, se debe llamar a unw_nto_destroy(), pasándole el puntero opaco que fue devuelto por la llamada a unw_nto_create(). Esto asegura que se liberen toda la memoria y otros recursos.

La función unw_nto_resume() no es compatible con el remoto NTO.

En circunstancias especiales, una aplicación puede preferir usar solo partes del remoto NTO de libunwind. Por esta razón, las rutinas de callback individuales (unw_nto_find_proc_info(), unw_nto_put_unwind_info(), etc.) también están disponibles para uso directo. Por supuesto, las direcciones de estas rutinas también se podrían obtener de unw_nto_accessors, pero hacer eso impediría la inicialización estática. Además, al usar unw_nto_accessors, *todas* las rutinas de callback se vincularán a la aplicación, incluso si nunca se llaman.

SEGURIDAD DE HILOS

El remoto NTO de libunwind asume que una única estructura unw_nto-info nunca se comparte entre hilos del programa que desenrolla. Debido a esto, no se utiliza ningún bloqueo explícito. Siempre que solo un hilo use una estructura de información NTO en un momento dado, esta funcionalidad es segura para hilos.

VALOR DE RETORNO

unw_nto_create() puede devolver NULL si falla al crear la estructura de información NTO por alguna razón.

ARCHIVOS

EJEMPLO

    #include <libunwind-nto.h>
    #include <stdio.h>
    #include <stdlib.h>
    int
    main (int argc, char **argv)
    {
      if (argc != 2) {
        fprintf (stderr, "uso: %s PID\n", argv[0]);
        exit (EXIT_FAILURE);
      }
      char *endptr;
      pid_t target_pid = strtoul (argv[1], &endptr, 10);
      if (target_pid == 0 && argv[1] == endptr) {
        fprintf (stderr, "uso: %s PID\n", argv[0]);
        exit (EXIT_FAILURE);
      }
      unw_addr_space_t as = unw_create_addr_space (&unw_nto_accessors, 0);
      if (!as) {
        fprintf (stderr, "falló unw_create_addr_space()");
        exit (EXIT_FAILURE);
      }
      void *ui = unw_nto_create (target_pid, (thread_t)1);
      if (!ui) {
        fprintf (stderr, "falló unw_nto_create()");
        exit (EXIT_FAILURE);
      }
      unw_cursor_t cursor;
      int ret = unw_init_remote (&cursor, as, ui);
      if (ret < 0) {
        fprintf (stderr, "falló unw_init_remote(): ret=%d\n", ret);
        exit (EXIT_FAILURE);
      }
      do {
        unw_proc_info_t pi;
        ret = unw_get_proc_info (&cursor, &pi);
        if (ret == -UNW_ENOINFO) {
          fprintf (stdout, "sin información\n");
        } else if (ret >= 0) {
          printf ("\tproc=%#016lx-%#016lx\thandler=%#016lx lsda=%#016lx",
                  (long) pi.start_ip, (long) pi.end_ip,
                  (long) pi.handler, (long) pi.lsda);
        }
        ret = unw_step (&cursor);
      } while (ret > 0);
      if (ret < 0) {
        fprintf (stderr, "falló el desenrollado con ret=%d\n", ret);
        exit (EXIT_FAILURE);
      }
      unw_nto_destroy (ui);
      unw_destroy_addr_space (as);
      exit (EXIT_SUCCESS);
    }
