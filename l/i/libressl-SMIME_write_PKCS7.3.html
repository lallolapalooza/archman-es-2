SMIME_WRITE_PKCS7(3) Manual de funciones de biblioteca SMIME_WRITE_PKCS7(3)

NOMBRE

SMIME_write_PKCS7 — convertir la estructura PKCS#7 al formato S/MIME

SINOPSIS

biblioteca “libcrypto”
#include <openssl/pkcs7.h>

int
SMIME_write_PKCS7(BIO *out, PKCS7 *p7, BIO *data, int flags);

DESCRIPCIÓN

SMIME_write_PKCS7() genera un mensaje S/MIME en out escribiendo encabezados MIME 1.0 seguidos de una serialización codificada en BER y base64 de p7. La codificación BER utiliza el formato DER, excepto como se describe para PKCS7_STREAM a continuación. Si se habilita el streaming, el contenido debe proporcionarse en el argumento data.

Las flags pueden ser la OR lógica de cero o más de los siguientes bits:

PKCS7_DETACHED
Utiliza firma de texto plano y genera un mensaje S/MIME "multipart/signed". El contenido se lee de data. Si data es un puntero NULL, esta bandera se ignora.

Esta bandera solo se admite para signedData donde PKCS7_DETACHED también se establece al llamar a PKCS7_sign(3).

Si PKCS7_STREAM no está establecido, los datos deben leerse dos veces: una para calcular la firma en PKCS7_sign(3) y otra para escribir el mensaje S/MIME.

Si se ignora PKCS7_DETACHED o no se especifica, el tipo de smime se elige según el tipo de p7:

NID_pkcs7_enveloped
"enveloped-data"
NID_pkcs7_signed
"signed-data"
si p7 especifica algún algoritmo de resumen
"certs-only"
en caso contrario
NID_id_smime_ct_compressedData
"compressed-data"
PKCS7_REUSE_DIGEST
Omite las llamadas a PKCS7_dataInit(3) y PKCS7_dataFinal(3). Esta bandera no tiene ningún efecto a menos que PKCS7_DETACHED también esté establecida.
PKCS7_STREAM
Realiza streaming leyendo el contenido de data. Esto solo funciona si PKCS7_DETACHED no está especificado.

Esta bandera solo debe establecerse si PKCS7_STREAM también se estableció en la llamada anterior a PKCS7_sign(3) o PKCS7_encrypt(3).

El contenido se escribe en formato BER utilizando codificación construida de longitud indefinida, excepto en el caso de datos firmados con contenido separado, donde el contenido está ausente y se utiliza el formato DER.

PKCS7_TEXT
Antepone la línea "Content-Type: text/plain" al contenido. Esto solo tiene sentido si PKCS7_DETACHED también está establecido. Se ignora si la bandera SMIME_BINARY también está establecida.
SMIME_BINARY
Si se especifica, esta bandera se pasa a SMIME_crlf_copy(3).
SMIME_CRLFEOL
Finaliza las líneas de encabezado MIME con pares de caracteres de retorno de carro y nueva línea. Por defecto, no se escriben caracteres de retorno de carro y las líneas de encabezado se finalizan solo con caracteres de nueva línea.
SMIME_OLDMIME
Si este bit está establecido en el argumento flags, se utiliza "application/pkcs7-mime" o "application/pkcs7-signature" en los encabezados Content-Type. De lo contrario, se utiliza "application/x-pkcs7-mime" o "application/x-pkcs7-signature".

VALORES DE RETORNO

SMIME_write_PKCS7() pretende devolver 1 si tiene éxito o 0 si falla.

VER TAMBIÉN

BIO_f_base64(3), BIO_new(3), i2d_PKCS7_bio_stream(3), PEM_write_bio_PKCS7_stream(3), PEM_write_PKCS7(3), PKCS7_final(3), PKCS7_new(3), SMIME_crlf_copy(3), SMIME_read_PKCS7(3), SMIME_write_CMS(3)

HISTORIA

SMIME_write_PKCS7() apareció por primera vez en OpenSSL 0.9.5 y ha estado disponible desde OpenBSD 2.7.

ERRORES

SMIME_write_PKCS7() ignora la mayoría de los errores y es probable que devuelva 1 incluso después de producir una salida corrupta o incompleta.

SMIME_write_PKCS7() siempre codifica en base64 las estructuras PKCS#7. Debería haber una opción para deshabilitar esto.
