NOMBRE

libppl - la interfaz C++ de la Parma Polyhedra Library

SINOPSIS

#include <ppl.hh>

c++ file.cc -lppl

DESCRIPCIÓN

Este es un breve resumen sobre cómo usar la Parma Polyhedra Library (PPL) en tus programas C++ en sistemas tipo Unix. Ten en cuenta que la PPL también tiene interfaces para C, Java, OCaml y varios sistemas Prolog: busca en otra parte la documentación sobre ellos. Ten en cuenta también que este documento no describe la funcionalidad de la biblioteca, sus clases o sus métodos y funciones: consulta The Parma Polyhedra Library User's Manual (version 1.2) para este tipo de información.

INCLUYENDO EL ARCHIVO DE CABECERA

La interfaz C++ de la PPL tiene un solo archivo de cabecera, llamado ppl.hh. Así que tu programa debe contener una directiva del tipo

#include <ppl.hh>

Por supuesto, debes asegurarte de haber instalado la PPL en un lugar donde el compilador pueda encontrarla, ya sea por sí mismo o con la ayuda de una opción de línea de comandos adecuada -Idir (consulta el archivo INSTALL para obtener información sobre cómo configurar la biblioteca para que se instale en el lugar de tu elección).

INICIALIZANDO Y FINALIZANDO LA BIBLIOTECA

La mera inclusión de ppl.hh en al menos un archivo de tu proyecto provocará la inicialización y finalización automática de la biblioteca. Sin embargo, hay situaciones en las que la inicialización y finalización automática no son deseables (por ejemplo, si la aplicación manipula las funciones de asignación de memoria de GMP). En esos casos, cada inclusión de ppl.hh debe tener la forma

#define PPL_NO_AUTOMATIC_INITIALIZATION
#include <ppl.hh>

Cuando la inicialización y finalización automática está deshabilitada, debes llamar absolutamente a la función

void Parma_Polyhedra_Library::initialize()

antes de usar la biblioteca. También es buena norma llamar a la función

void Parma_Polyhedra_Library::finalize()

cuando hayas terminado con la biblioteca.

USANDO LA BIBLIOTECA

Teniendo en cuenta que no hay sustituto para una lectura cuidadosa de The Parma Polyhedra Library User's Manual (version 1.2), puedes encontrar muchos ejemplos de uso en los directorios tests (ver el archivo README en ese directorio) y demos/ppl_lcdd de la distribución fuente.

ENLAZANDO CON LA BIBLIOTECA

El enlazado con la interfaz C++ de la Parma Polyhedra Library se hace mejor usando el propio compilador C++: normalmente, especificar la opción de línea de comandos -lppl es suficiente. De hecho, si usas una versión compartida de la biblioteca, esto registra automáticamente la dependencia de la biblioteca GMP, algo que el enlazador debería manejar sin problemas. De lo contrario, tendrás que añadir -lgmpxx -lgmp a la línea de comandos. Las cosas son más complejas si instalaste la PPL en algún lugar no estándar. En este caso, tendrás que usar la opción -Ldir y, si usas una versión compartida de la biblioteca, posiblemente tomar medidas adicionales: consulta la documentación de tu sistema para obtener más información sobre este tema (el Program Library HOWTO es especialmente valioso para los usuarios de GNU/Linux).

IMPLEMENTANDO CÁLCULOS PROTEGIDOS POR MEMORIA

Una de las características interesantes de la Parma Polyhedra Library es la posibilidad de implementar cálculos protegidos por memoria. La idea es que puedes limitar la cantidad de memoria virtual disponible para el proceso, lanzar un cálculo de PPL y estar preparado para capturar una excepción std::bad_alloc. Dado que la biblioteca es segura ante excepciones, puedes tomar las medidas correctivas apropiadas (por ejemplo, simplificar los poliedros y/o seleccionar algoritmos menos precisos aunque menos complejos), y reiniciar el cálculo. Para ello, debes definir funciones alternativas de asignación de memoria para GMP que lancen std::bad_alloc ante el agotamiento de memoria. Por ejemplo:

#include <new>
#include <cstdlib>
extern "C" void*
cxx_malloc(size_t size) {
  void* p = malloc(size);
  if (p != 0 || size == 0)
    return p;
  throw std::bad_alloc();
}
extern "C" void*
cxx_realloc(void* q, size_t, size_t new_size) {
  void* p = realloc(q, new_size);
  if (p != 0 || new_size == 0)
    return p;
  throw std::bad_alloc();
}
extern "C" void
cxx_free(void* p, size_t) {
  free(p);
}

Luego debes instalar estas funciones y esto se puede hacer de dos maneras diferentes:

(1)
Si tu compilador C++ soporta __attribute__ ((weak)) y no tienes ninguna otra necesidad especial, entonces simplemente puedes enlazar a tu aplicación una función C ppl_set_GMP_memory_allocation_functions(void) tal como 
extern "C" void
ppl_set_GMP_memory_allocation_functions(void) {
  mp_set_memory_functions(cxx_malloc, cxx_realloc, cxx_free);
}

Esto es todo lo que tienes que hacer, ya sea que uses o no la característica de inicialización automática de la biblioteca (ver arriba): en cualquier caso, el procedimiento de inicialización llamará automáticamente a ppl_set_GMP_memory_allocation_functions(void).

(2)
Si tu compilador C++ no soporta __attribute__ ((weak)) entonces no puedes usar la característica de inicialización automática de la biblioteca (ver arriba) y deberías escribir un programa principal del tipo 
int main() {
  // El orden de las siguientes llamadas a funciones es importante.
  mp_set_memory_functions(cxx_malloc, cxx_realloc, cxx_free);
  Parma_Polyhedra_Library::initialize();
  ...

USANDO NÚMEROS DE COMA FLOTANTE NATIVOS

En el momento de la inicialización, la Parma Polyhedra Library configura el modo de redondeo de la FPU de manera que permite que sus cálculos basados en coma flotante sean conservadores (es decir, posiblemente aproximados pero correctos) y razonablemente eficientes. En caso de que tu aplicación utilice números de coma flotante nativos y dependa de un modo de redondeo particular (si tienes dudas, asume que depende del redondeo al más cercano para que se aplique), deberías usar la función

void Parma_Polyhedra_Library::restore_pre_PPL_rounding()

después de la inicialización de PPL y antes de usar números de coma flotante nativos en la aplicación. Si tu aplicación no utiliza ninguna abstracción de PPL basada en coma flotante, no se deben tomar más medidas. De lo contrario, es imperativo llamar a la función

void Parma_Polyhedra_Library::set_rounding_for_PPL()

antes de invocar cualquier interfaz de PPL relacionada con dichas abstracciones.
