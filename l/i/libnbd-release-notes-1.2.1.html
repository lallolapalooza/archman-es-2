NOMBRE

libnbd-release-notes-1.2 - notas de la versión para libnbd 1.2

DESCRIPCIÓN

Estas son las notas de la versión para la versión estable de libnbd 1.2. Describen los cambios principales desde la 1.0.

libnbd 1.2.0 fue lanzado el 14 de noviembre de 2019.

Seguridad

Se encontraron dos problemas de seguridad durante el desarrollo de libnbd 1.2. Ambos fueron retroportados a la rama estable 1.0. Se recomienda encarecidamente la actualización.

Ataque de degradación de protocolo CVE-2019-14842 al usar "LIBNBD_TLS_REQUIRE"

Vea el anuncio completo y los enlaces a mitigación, pruebas y correcciones aquí: https://www.redhat.com/archives/libguestfs/2019-September/msg00128.html

vulnerabilidad de ejecución remota de código

Vea el anuncio completo aquí: https://www.redhat.com/archives/libguestfs/2019-October/msg00060.html

Nuevas APIs

nbd_can_fast_zero(3)
Prueba el soporte del servidor para ceros rápidos (Eric Blake).
nbd_connect_socket(3)
nbd_aio_connect_socket(3)
Conéctate a un socket local conectado que crees en tu programa principal utilizando tu propio método elegido.
nbd_connect_systemd_socket_activation(3)
nbd_aio_connect_systemd_socket_activation(3)
Conéctate a procesos locales que soporten la activación de sockets de systemd.
nbd_connect_vsock(3)
nbd_aio_connect_vsock(3)
Se utiliza para conectarse a servidores a través de "AF_VSOCK".
nbd_get_handshake_flags(3)
nbd_set_handshake_flags(3)
nbd_get_request_structured_replies(3)
nbd_set_request_structured_replies(3)
nbd_get_structured_replies_negotiated(3)
Se puede utilizar al probar servidores NBD para evitar varias características de NBD (Eric Blake).
nbd_get_protocol(3)
Obtiene la variante del protocolo NBD que soporta el servidor.
nbd_get_tls_negotiated(3)
¿Negociamos realmente una conexión TLS?
nbd_set_uri_allow_local_file(3)
nbd_set_uri_allow_tls(3)
nbd_set_uri_allow_transports(3)
Estos se pueden utilizar para filtrar URIs NBD antes de llamar a nbd_connect_uri(3).

Nuevas características

La nueva herramienta nbdfuse(1) permite crear un archivo montado en bucle respaldado por un servidor NBD sin necesidad de ser root.

"AF_VSOCK" es ahora un protocolo soportado (gracias Stefan Hajnoczi y Stefano Garzarella).

Soporte para la bandera "FAST_ZERO" (Eric Blake).

Permite deshabilitar ciertas características del protocolo, para facilitar la prueba de servidores (Eric Blake).

Los Arrays de Longitud Variable (VLA) apilados ahora están prohibidos en toda la biblioteca, lo que facilita su uso desde hilos y otras situaciones de pila pequeña.

Construcciones reproducibles (Chris Lamb).

Soporte para filtrar características de URI NBD potencialmente peligrosas o indeseables.

Documentación

Muchas mejoras en las páginas del manual generadas, incluyendo:

  • Secciones separadas de "VALOR DE RETORNO" y "ERRORES" para cada función de API.
  • Código de ejemplo.
  • Se pueden añadir enlaces relevantes a la sección "VER TAMBIÉN".
  • Enlace a la especificación de URI NBD donde sea relevante, y mejora de la documentación sobre qué URIs soporta libnbd.
  • Documentación del esquema de numeración de versiones de libnbd.
  • Documentación de los límites en la longitud del nombre de exportación, codificación, etc.

La nueva página del manual libnbd-security(3) lista problemas de seguridad pasados y sus remedios (Eric Blake).

Herramientas

nbdsh(1) tiene una nueva opción --base-allocation que se puede usar para solicitar el contexto de metadatos "base:allocation".

Nueva opción --uri (-u) de nbdsh(1) para conectarse a URIs.

Pruebas

Ahora puedes hacer fuzzing de libnbd usando American Fuzzy Lop o libFuzzer de clang.

Añadidas pruebas unitarias para nbdsh(1) (Eric Blake).

Mejora de las pruebas de interoperabilidad con varios servidores y características NBD.

Otras mejoras y correcciones de errores

nbd_connect_tcp(3) ahora intenta devolver el errno(3) correcto de la llamada subyacente connect(2) cuando esta falla.

El archivo de cabecera nbd-protocol.h ahora se comparte entre libnbd y nbdkit.

Mejor seguridad contra fork en las APIs "nbd_connect_*".

El código fue analizado con Coverity y se identificaron y corrigieron varios problemas.
