link(2) Manual de llamadas al sistema link(2)

NOMBRE

link, linkat - crear un nuevo nombre para un archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int link(const char *oldpath, const char *newpath);
#include <fcntl.h>           /* Definición de las constantes AT_* */
#include <unistd.h>
int linkat(int olddirfd, const char *oldpath,
           int newdirfd, const char *newpath, int flags);
Requisitos de Macro de Prueba de Funcionalidad para glibc (ver feature_test_macros(7)):

linkat():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _ATFILE_SOURCE

DESCRIPCIÓN

link() crea un nuevo enlace (también conocido como enlace duro) a un archivo existente.

Si newpath existe, no se sobrescribirá.

Este nuevo nombre puede ser utilizado exactamente como el antiguo para cualquier operación; ambos nombres se refieren al mismo archivo (y por lo tanto tienen los mismos permisos y propiedad) y es imposible decir cuál nombre fue el "original".

linkat()

La llamada al sistema linkat() opera exactamente de la misma manera que link(), excepto por las diferencias descritas aquí.

Si la ruta de acceso dada en oldpath es relativa, entonces se interpreta relativa al directorio al que se refiere el descriptor de archivo olddirfd (en lugar de ser relativa al directorio de trabajo actual del proceso que llama, como hace link() para una ruta de acceso relativa).

Si oldpath es relativa y olddirfd es el valor especial AT_FDCWD, entonces oldpath se interpreta relativa al directorio de trabajo actual del proceso que llama (como link()).

Si oldpath es absoluta, entonces olddirfd se ignora.

La interpretación de newpath es como para oldpath, excepto que una ruta de acceso relativa se interpreta relativa al directorio al que se refiere el descriptor de archivo newdirfd.

Los siguientes valores pueden ser combinados mediante una operación OR bit a bit en flags:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si oldpath es una cadena vacía, crea un enlace al archivo referenciado por olddirfd (que puede haber sido obtenido usando la bandera open(2) O_PATH). En este caso, olddirfd puede referirse a cualquier tipo de archivo excepto un directorio. Generalmente, esto no funcionará si el archivo tiene un recuento de enlaces de cero (los archivos creados con O_TMPFILE y sin O_EXCL son una excepción). El llamador debe tener la capacidad CAP_DAC_READ_SEARCH para poder usar esta bandera. Esta bandera es específica de Linux; define _GNU_SOURCE para obtener su definición.
AT_SYMLINK_FOLLOW (desde Linux 2.6.18)
Por defecto, linkat() no desreferencia oldpath si es un enlace simbólico (como link()). La bandera AT_SYMLINK_FOLLOW puede especificarse en flags para hacer que oldpath sea desreferenciado si es un enlace simbólico. Si procfs está montado, esto puede ser utilizado como una alternativa a AT_EMPTY_PATH, de la siguiente manera:

linkat(AT_FDCWD, "/proc/self/fd/<fd>", newdirfd,
       newname, AT_SYMLINK_FOLLOW);

Antes de Linux 2.6.18, el argumento flags no se usaba, y debía especificarse como 0.

Ver openat(2) para una explicación de la necesidad de linkat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1, y errno se establece para indicar el error.

ERRORES

EACCES
Se deniega el acceso de escritura al directorio que contiene newpath, o se deniega el permiso de búsqueda para alguno de los directorios en el prefijo de ruta de oldpath o newpath. (Ver también path_resolution(7)).
EDQUOT
La cuota del usuario de bloques de disco en el sistema de archivos se ha agotado.
EEXIST
newpath ya existe.
EFAULT
oldpath o newpath apunta fuera de su espacio de direcciones accesible.
EIO
Ocurrió un error de E/S.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver oldpath o newpath.
EMLINK
El archivo al que se refiere oldpath ya tiene el número máximo de enlaces. Por ejemplo, en un sistema de archivos ext4(5) que no utiliza la característica dir_index, el límite en el número de enlaces duros a un archivo es 65,000; en btrfs(5), el límite es 65,535 enlaces.
ENAMETOOLONG
oldpath o newpath era demasiado largo.
ENOENT
Un componente del directorio en oldpath o newpath no existe o es un enlace simbólico colgante.
ENOMEM
No había suficiente memoria del kernel disponible.
ENOSPC
El dispositivo que contiene el archivo no tiene espacio para la nueva entrada de directorio.
ENOTDIR
Un componente utilizado como directorio en oldpath o newpath no es, de hecho, un directorio.
EPERM
oldpath es un directorio.
EPERM
El sistema de archivos que contiene oldpath y newpath no soporta la creación de enlaces duros.
EPERM (desde Linux 3.6)
El llamador no tiene permiso para crear un enlace duro a este archivo (ver la descripción de /proc/sys/fs/protected_hardlinks en proc_sys_fs(5)).
EPERM
oldpath está marcado como inmutable o de solo adición. (Ver FS_IOC_SETFLAGS(2const).)
EROFS
El archivo está en un sistema de archivos de solo lectura.
EXDEV
oldpath y newpath no están en el mismo sistema de archivos montado. (Linux permite que un sistema de archivos se monte en múltiples puntos, pero link() no funciona entre montajes diferentes, incluso si el mismo sistema de archivos está montado en ambos.)

Los siguientes errores adicionales pueden ocurrir para linkat():

EBADF
oldpath (newpath) es relativo pero olddirfd (newdirfd) no es AT_FDCWD ni un descriptor de archivo válido.
EINVAL
Se especificó un valor de bandera inválido en flags.
ENOENT
Se especificó AT_EMPTY_PATH en flags, pero el llamador no tenía la capacidad CAP_DAC_READ_SEARCH.
ENOENT
Se intentó enlazar al archivo /proc/self/fd/NN correspondiente a un descriptor de archivo creado con

open(path, O_TMPFILE | O_EXCL, mode);

Ver open(2).
ENOENT
Se intentó enlazar a un archivo /proc/self/fd/NN correspondiente a un archivo que ha sido eliminado.
ENOENT
oldpath es una ruta relativa y olddirfd se refiere a un directorio que ha sido eliminado, o newpath es una ruta relativa y newdirfd se refiere a un directorio que ha sido eliminado.
ENOTDIR
oldpath es relativo y olddirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio; o similar para newpath y newdirfd
EPERM
Se especificó AT_EMPTY_PATH en flags, oldpath es una cadena vacía y olddirfd se refiere a un directorio.

VERSIONES

POSIX.1-2001 dice que link() debería desreferenciar oldpath si es un enlace simbólico. Sin embargo, desde Linux 2.0, Linux no lo hace: si oldpath es un enlace simbólico, entonces newpath se crea como un enlace (duro) al mismo archivo de enlace simbólico (es decir, newpath se convierte en un enlace simbólico al mismo archivo al que apunta oldpath). Algunas otras implementaciones se comportan de la misma manera que Linux. POSIX.1-2008 cambia la especificación de link(), haciendo que sea independiente de la implementación si oldpath se desreferencia o no si es un enlace simbólico. Para un control preciso sobre el tratamiento de los enlaces simbólicos al crear un enlace, use linkat().

glibc

En kernels más antiguos donde linkat() no está disponible, la función envoltorio de glibc recurre al uso de link(), a menos que se especifique AT_SYMLINK_FOLLOW. Cuando oldpath y newpath son rutas relativas, glibc construye rutas basadas en los enlaces simbólicos en /proc/self/fd que corresponden a los argumentos olddirfd y newdirfd.

ESTÁNDARES

POSIX.1-2024.

HISTORIA

link()
SVr4, 4.3BSD, POSIX.1-2001 (pero ver VERSIONS).
linkat()
POSIX.1-2008. Linux 2.6.16, glibc 2.4.

NOTAS

Los enlaces duros, como los creados por link(), no pueden cruzar sistemas de archivos. Utilice symlink(2) si esto es necesario.

ERRORES

En sistemas de archivos NFS, el código de retorno puede ser incorrecto en caso de que el servidor NFS realice la creación del enlace y muera antes de poder comunicarlo. Utilice stat(2) para averiguar si el enlace se creó.

VER TAMBIÉN
