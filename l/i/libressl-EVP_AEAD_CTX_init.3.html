DESCRIPCIÓN

AEAD (Authenticated Encryption with Additional Data) acopla la confidencialidad y la integridad en una única primitiva. Los algoritmos AEAD toman una clave y pueden entonces sellar y abrir mensajes individuales. Cada mensaje tiene un nonce único por mensaje y, opcionalmente, datos adicionales que se autentican pero no se incluyen en la salida.

EVP_AEAD_CTX_new() asigna un nuevo contexto para usarlo con EVP_AEAD_CTX_init(). Puede ser limpiado para su reutilización con EVP_AEAD_CTX_cleanup() y debe ser liberado con EVP_AEAD_CTX_free().

EVP_AEAD_CTX_free() limpia ctx y libera el espacio asignado a él.

EVP_AEAD_CTX_init() inicializa el contexto ctx para el algoritmo AEAD especificado aead. El argumento engine debe ser NULL para la implementación predeterminada; otros valores no son compatibles. Las etiquetas de autenticación pueden ser truncadas pasando una longitud de etiqueta. Un argumento tag_len de EVP_AEAD_DEFAULT_TAG_LENGTH, que tiene el valor 0, hace que se use la longitud de etiqueta predeterminada.

EVP_AEAD_CTX_cleanup() libera cualquier dato asignado para el contexto ctx. Después de EVP_AEAD_CTX_cleanup(), ctx está en el mismo estado que después de EVP_AEAD_CTX_new().

EVP_AEAD_CTX_open() autentica la entrada in y los datos adicionales opcionales ad, descifra la entrada y la escribe como salida out. Esta función puede ser llamada (con el mismo EVP_AEAD_CTX) concurrentemente consigo misma o con EVP_AEAD_CTX_seal(). Se escriben como salida como máximo el número de bytes de entrada. Para asegurar el éxito, max_out_len debe ser al menos igual a la longitud de entrada in_len. En un retorno exitoso, out_len se establece al número real de bytes escritos. La longitud del nonce especificado con nonce_len debe ser igual al resultado de EVP_AEAD_nonce_length para este AEAD. EVP_AEAD_CTX_open() nunca resulta en una salida parcial. Si max_out_len es insuficiente, se devolverá cero y out_len se establecerá a cero. Si la entrada y la salida están solapadas, entonces out debe ser <= in.

EVP_AEAD_CTX_seal() cifra y autentica la entrada, y autentica cualquier dato adicional proporcionado en ad, escribiendo la entrada cifrada y la etiqueta de autenticación como salida out. Esta función puede ser llamada (con el mismo EVP_AEAD_CTX) concurrentemente consigo misma o con EVP_AEAD_CTX_open(). Se escriben como máximo max_out_len bytes como salida y, para asegurar el éxito, este valor debe ser la in_len más el resultado de EVP_AEAD_max_overhead(). En un retorno exitoso, out_len se establece al número real de bytes escritos. La longitud del nonce especificado con nonce_len debe ser igual al resultado de EVP_AEAD_nonce_length() para este AEAD. EVP_AEAD_CTX_seal() nunca resulta en una salida parcial. Si max_out_len es insuficiente, se devolverá cero y out_len se establecerá a cero. Si la entrada y la salida están solapadas, entonces out debe ser <= in.

EVP_AEAD_key_length(), EVP_AEAD_max_overhead(), EVP_AEAD_max_tag_len(), y EVP_AEAD_nonce_length() proporcionan información sobre el algoritmo AEAD aead.

Todos los algoritmos de cifrado tienen una longitud de clave fija a menos que se indique lo contrario. Los siguientes cifrados están disponibles:

EVP_aead_aes_128_gcm()
AES-128 en modo Galois/Contador (GCM), utilizando una key_len de 16 bytes y una nonce_len de 12 bytes.
EVP_aead_aes_256_gcm()
AES-256 en modo Galois/Contador (GCM), utilizando una key_len de 32 bytes y una nonce_len de 12 bytes.
EVP_aead_chacha20_poly1305()
ChaCha20 con un autenticador Poly1305, utilizando una key_len de 32 bytes y una nonce_len de 12 bytes. La constante EVP_CHACHAPOLY_TLS_TAG_LEN especifica la longitud de la etiqueta de autenticación en bytes y tiene un valor de 16.
EVP_aead_xchacha20_poly1305()
XChaCha20 con un autenticador Poly1305, utilizando una key_len de 32 bytes y una nonce_len de 24 bytes.

A menos que se requiera compatibilidad con otras implementaciones como OpenSSL o BoringSSL, se recomienda usar la interfaz EVP_AEAD para cifrados AEAD en lugar de las funciones documentadas en las páginas del manual EVP_EncryptInit(3), EVP_aes_256_gcm(3) y EVP_chacha20_poly1305(3). El código entonces se vuelve transparente al cifrado AEAD utilizado y mucho más flexible. También es más seguro de usar, ya que previene errores comunes con las API de EVP.

VALORES DE RETORNO

EVP_AEAD_CTX_new() devuelve el nuevo objeto EVP_AEAD_CTX en caso de éxito; de lo contrario, se devuelve NULL y se establece errno en ENOMEM.

EVP_AEAD_CTX_init(), EVP_AEAD_CTX_open() y EVP_AEAD_CTX_seal() devuelven 1 en caso de éxito o cero en caso de fallo.

EVP_AEAD_key_length() devuelve la longitud de la clave utilizada para este AEAD.

EVP_AEAD_max_overhead() devuelve el número máximo de bytes adicionales añadidos por el acto de sellar datos con el AEAD.

EVP_AEAD_max_tag_len() devuelve la longitud máxima de la etiqueta al usar este AEAD.

EVP_AEAD_nonce_length() devuelve la longitud del nonce por mensaje.

EJEMPLOS

Cifrar una cadena usando ChaCha20-Poly1305:

const EVP_AEAD *aead = EVP_aead_chacha20_poly1305();
static const unsigned char nonce[32] = {0};
size_t buf_len, nonce_len;
EVP_AEAD_CTX *ctx;

ctx = EVP_AEAD_CTX_new();
EVP_AEAD_CTX_init(ctx, aead, key32, EVP_AEAD_key_length(aead),
    EVP_AEAD_DEFAULT_TAG_LENGTH, NULL);
nonce_len = EVP_AEAD_nonce_length(aead);

EVP_AEAD_CTX_seal(ctx, out, &out_len, BUFSIZE, nonce,
    nonce_len, in, in_len, NULL, 0);

EVP_AEAD_CTX_free(ctx);

HISTORIAL

AEAD se basa en la implementación de Adam Langley para Chromium/BoringSSL y apareció por primera vez en OpenBSD 5.6.

EVP_AEAD_CTX_new() y EVP_AEAD_CTX_free() aparecieron por primera vez en OpenBSD 7.1.

ADVERTENCIAS

Las publicaciones y el código originales de Adam Langley utilizaron una construcción AEAD modificada que es incompatible con el estilo común utilizado por AEAD en TLS e incompatible con RFC 7905:

A. Langley y W. Chang, ChaCha20 y Poly1305 basados en Cipher Suites para TLS, draft-agl-tls-chacha20poly1305-04, noviembre de 2013.

Y. Nir y A. Langley, ChaCha20 y Poly1305 para Protocolos IETF, RFC 8439, junio de 2018.

En particular, la versión original utilizaba una nonce_len de 8 bytes.
