DESCRIPCIÓN

Estas funciones primarias operan sobre un estado de capacidades mantenido en memoria de trabajo e intentan completar la API del espacio de usuario (borrador) de POSIX.1e para privilegios basados en capacidades.

Un cap_t contiene información sobre las capacidades en cada uno de los tres conjuntos, Permitted (Permitido), Inheritable (Heredable) y Effective (Efectivo). Cada capacidad en un conjunto puede estar limpia (desactivada, 0) o establecida (activada, 1).

Estas funciones trabajan con los siguientes tipos de datos:

cap_value_t
identifica una capacidad, como CAP_CHOWN.
cap_flag_t
identifica uno de los tres indicadores asociados con una capacidad (es decir, identifica uno de los tres conjuntos de capacidades). Los valores válidos para este tipo son CAP_EFFECTIVE, CAP_INHERITABLE o CAP_PERMITTED.
cap_flag_value_t
identifica la configuración de un indicador de capacidad particular (es decir, el valor de una capacidad en un conjunto). Los valores válidos para este tipo son CAP_CLEAR(0) o CAP_SET(1).

VALOR DE RETORNO

El valor de retorno es generalmente específico de la función individual llamada. En caso de error, errno se establece apropiadamente.

CONFORME A

Estas funciones son según la especificación del borrador POSIX.1e retirada. Las siguientes funciones son extensiones de Linux: cap_clear_flag(), cap_drop_bound(), cap_fill(), cap_fill_flag(), cap_from_name(), cap_get_ambient(), cap_get_bound(), cap_get_mode(), cap_get_nsowner(), cap_get_secbits(), cap_mode_name(), cap_proc_root(), cap_prctl(), cap_prctlw(), cap_reset_ambient(), cap_setgroups(), cap_setuid(), cap_set_ambient(), cap_set_mode(), cap_set_nsowner(), cap_set_secbits(), cap_to_name() y cap_compare().

En Linux, la extensión IAB de los vectores de capacidades Heredable, Limitante (Bounding) y Ambiental también es compatible con libcap. Estas funciones se describen en una página de manual complementaria: cap_iab(3). Además, para gestionar la complejidad de lanzar un subproceso, libcap admite la abstracción: cap_launch(3).

Además de la API de libcap con prefijo cap_, la biblioteca también proporciona prototipos para las llamadas al sistema de Linux que proporcionan la API nativa para las capacidades de proceso. Estos prototipos son:

int capget(cap_user_header_t header, cap_user_data_t data);
int capset(cap_user_header_t header, const cap_user_data_t data);

Además, libcap proporciona una función de configuración,

void cap_set_syscall(
        long int (*new_syscall)(long int, long int, long int, long int),
        long int (*new_syscall6)(long int,
                                 long int, long int, long int,
                                 long int, long int, long int));

que se puede utilizar para redirigir su uso de las llamadas al sistema capset() y otras que escriben estado administrado por el kernel. Esto es especialmente útil al admitir semántica POSIX para el estado de seguridad. Cuando un programa se vincula con libpsx(3) como se describe en esa página de manual, esta función se utiliza para conectar libcap con las llamadas al sistema de semántica POSIX.

DESCRIPCIÓN

La biblioteca libcap proporciona una interfaz para obtener y establecer las capacidades de un proceso o de un archivo. Las capacidades son una característica del kernel de Linux que permite dividir los privilegios de superusuario (root) en unidades más pequeñas e independientes. Cada capacidad se puede habilitar o deshabilitar de forma independiente para un proceso. Esto permite conceder solo los privilegios necesarios a un programa, reduciendo así la superficie de ataque potencial.

Las funciones proporcionadas por libcap permiten:

  • Obtener las capacidades actuales de un proceso (cap_get_proc()) o de un proceso específico (cap_get_pid()).
  • Establecer las capacidades de un proceso (cap_set_proc()) o de un archivo abierto (cap_set_fd()).
  • Inicializar y liberar estructuras de capacidades (cap_init(), cap_free()).
  • Copiar y manipular conjuntos de capacidades (cap_copy_ext(), cap_copy_int(), cap_set_flag(), cap_get_flag()).
  • Serializar y deserializar conjuntos de capacidades a/desde formato de texto (cap_to_text(), cap_from_text()).
  • Obtener y establecer capacidades específicas como la ambiental, heredable, permitida y efectiva (cap_get_ambient(), cap_set_ambient(), etc.).
  • Manejar la raíz de un proceso (cap_get_root_dir(), cap_set_root_dir()).
  • Acceder a la base de datos de capacidades (cap_get_database(), cap_set_database()).

Las capacidades se representan como un conjunto de pares (capacidad, bandera). Las banderas comunes son:

  • CAP_EFFECTIVE: La bandera efectiva determina si el proceso realmente tiene el privilegio de la capacidad.
  • CAP_PERMITTED: La bandera permitida es un conjunto de capacidades que un proceso puede tener activas en su conjunto efectivo.
  • CAP_INHERITABLE: La bandera heredable es un conjunto de capacidades que pueden ser heredadas por un proceso hijo.
  • CAP_AMBIENT: La bandera ambiental permite que ciertas capacidades persistentes se establezcan en un proceso sin necesidad de ejecutarlo con privilegios elevados.

Las capacidades individuales se identifican por valores como CAP_CHOWN, CAP_DAC_OVERRIDE, etc.

VALOR DE RETORNO

Las funciones de libcap devuelven un valor de retorno que indica éxito o error. Generalmente, un valor de 0 o un puntero válido indica éxito, mientras que un valor de -1 o NULL indica un error. En caso de error, la variable global errno se establece para indicar la naturaleza del error.

CONFORME A

libcap implementa el sistema de capacidades de Linux, que no es parte de los estándares POSIX pero es una característica específica de Linux.

REPORTAR ERRORES

Los errores en libcap deben ser reportados al sistema de seguimiento de errores de Arch Linux (BTS) o a la lista de correo de desarrollo de libcap.
