libressl-RSA_public_encrypt(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

RSA_PUBLIC_ENCRYPT(3) Manual de funciones de biblioteca RSA_PUBLIC_ENCRYPT(3)

NOMBRE

RSA_public_encrypt, RSA_private_decrypt, EVP_PKEY_encrypt_old, EVP_PKEY_decrypt_old — criptografía de clave pública RSA

SINOPSIS

biblioteca “libcrypto”
#include <openssl/rsa.h>

int
RSA_public_encrypt(int flen, const unsigned char *from, unsigned char *to, RSA *rsa, int padding);

int
RSA_private_decrypt(int flen, const unsigned char *from, unsigned char *to, RSA *rsa, int padding);

#include <openssl/evp.h>

int
EVP_PKEY_encrypt_old(unsigned char *to, const unsigned char *from, int flen, EVP_PKEY *pkey);

int
EVP_PKEY_decrypt_old(unsigned char *to, const unsigned char *from, int flen, EVP_PKEY *pkey);

DESCRIPCIÓN

RSA_public_encrypt() cifra los flen bytes en from (normalmente una clave de sesión) utilizando la clave pública rsa y almacena el texto cifrado en to. to debe apuntar a RSA_size(rsa) bytes de memoria.

padding denota uno de los siguientes modos:

RSA_PKCS1_PADDING
Relleno PKCS #1 v1.5. Actualmente es el modo más utilizado.
RSA_PKCS1_OAEP_PADDING
EME-OAEP tal como se define en PKCS #1 v2.0 con SHA-1, MGF1 y un parámetro de codificación vacío. Este modo se recomienda para todas las aplicaciones nuevas.
RSA_NO_PADDING
Cifrado RSA en bruto. Este modo solo debe utilizarse para implementar modos de relleno criptográficamente seguros en el código de la aplicación. Cifrar datos de usuario directamente con RSA no es seguro.

flen debe ser menor que RSA_size(rsa) - 11 para los modos de relleno basados en PKCS #1 v1.5, menor que RSA_size(rsa) - 41 para RSA_PKCS1_OAEP_PADDING y exactamente RSA_size(rsa) para RSA_NO_PADDING.

RSA_private_decrypt() descifra los flen bytes en from utilizando la clave privada rsa y almacena el texto plano en to. to debe apuntar a una sección de memoria lo suficientemente grande como para contener los datos descifrados (que es menor que RSA_size(rsa)). padding es el modo de relleno que se utilizó para cifrar los datos.

EVP_PKEY_encrypt_old() es un envoltorio obsoleto para RSA_public_encrypt() que utiliza la clave pública RSA almacenada en pkey y RSA_PKCS1_PADDING.

EVP_PKEY_decrypt_old() es un envoltorio obsoleto para RSA_private_decrypt() que utiliza la clave privada RSA almacenada en pkey y RSA_PKCS1_PADDING.

VALORES DE RETORNO

RSA_public_encrypt() y EVP_PKEY_encrypt_old() devuelven el tamaño de los datos cifrados (es decir, RSA_size(rsa)). RSA_private_decrypt() y EVP_PKEY_decrypt_old() devuelven el tamaño del texto plano recuperado. En caso de error, se devuelve -1; los códigos de error se pueden obtener mediante ERR_get_error(3).

Además de los valores de retorno documentados anteriormente, EVP_PKEY_encrypt_old() puede devolver 0 si el EVP_PKEY_id(3) de pkey no es EVP_PKEY_RSA.

VER TAMBIÉN

EVP_PKEY_decrypt(3), EVP_PKEY_encrypt(3), RSA_meth_set_priv_dec(3), RSA_new(3), RSA_size(3)

ESTÁNDARES

SSL, PKCS #1 v2.0

HISTORIAL

RSA_public_encrypt() y RSA_private_decrypt() aparecieron en SSLeay 0.4 o anterior y han estado disponibles desde OpenBSD 2.4.

EVP_PKEY_encrypt() y EVP_PKEY_decrypt() aparecieron por primera vez en SSLeay 0.9.0 y han estado disponibles desde OpenBSD 2.4. Fueron renombrados a EVP_PKEY_encrypt_old() y EVP_PKEY_decrypt_old() en OpenSSL 1.0.0 y OpenBSD 4.9.

RSA_NO_PADDING está disponible desde SSLeay 0.9.0. OAEP se añadió en OpenSSL 0.9.2b.

ERRORES

Los fallos de descifrado en el modo RSA_PKCS1_PADDING filtran información que potencialmente puede ser utilizada para montar un ataque de oráculo de relleno de Bleichenbacher. Esta es una debilidad inherente en el diseño del relleno PKCS #1 v1.5. Prefiera RSA_PKCS1_OAEP_PADDING.
