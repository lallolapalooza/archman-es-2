libssh2_sftp_write(3)

Paquete: libssh2

Licencias: BSD

libssh2_sftp_write(3) libssh2 libssh2_sftp_write(3)

NOMBRE

libssh2_sftp_write - escribir datos SFTP

SINOPSIS

#include <libssh2.h>
#include <libssh2_sftp.h>
ssize_t
libssh2_sftp_write(LIBSSH2_SFTP_HANDLE *handle,
                   const char *buffer,
                   size_t count);

DESCRIPCIÓN

libssh2_sftp_write(3) escribe un bloque de datos al servidor SFTP. Este método está modelado según la función POSIX write() y utiliza las mismas semánticas de llamada.

handle - Identificador de archivo SFTP devuelto por libssh2_sftp_open_ex(3).

buffer - apunta a los datos a enviar.

count - Número de bytes de 'buffer' a escribir. Tenga en cuenta que puede no ser posible escribir todos los bytes solicitados.

libssh2_sftp_handle(3) utilizará la mayor parte posible del búfer y lo colocará en un único paquete del protocolo SFTP. Esto significa que para obtener el máximo rendimiento al enviar archivos grandes, debe intentar pasar siempre al menos 32K de datos a esta función.

ESCRITURA ANTICIPADA

A partir de la versión 1.2.8 de libssh2, el comportamiento predeterminado de libssh2 es crear varios paquetes salientes más pequeños para todos los datos que pase a esta función, y devolverá un número positivo tan pronto como el primer paquete sea reconocido por el servidor.

Esto tiene el efecto de que a veces se han enviado más datos pero aún no han sido reconocidos cuando esta función devuelve, y cuando esta función se llama posteriormente de nuevo para escribir más datos, libssh2 determinará inmediatamente que los datos ya han sido recibidos remotamente.

En la mayoría de las situaciones normales, esto no debería causar ningún problema, pero debe tenerse en cuenta que si una vez llamó a libssh2_sftp_write() con datos y devuelve un valor corto, DEBE asumir que el resto de los datos pueden haber sido almacenados en caché, por lo que debe asegurarse de no alterar esos datos y pensar que la versión que tiene en su próxima invocación de función será detectada o utilizada.

La razón de este comportamiento peculiar es que SFTP solo puede enviar 32K de datos en cada paquete y todos los paquetes son reconocidos individualmente. Esto significa que no podemos usar un enfoque serial simple si queremos alcanzar un alto rendimiento incluso en conexiones de alta latencia. Y queremos eso.

VALOR DE RETORNO

Número real de bytes escritos o un valor negativo en caso de fallo.

Si se utiliza en modo no bloqueante, devuelve LIBSSH2_ERROR_EAGAIN cuando de lo contrario se bloquearía. Si bien LIBSSH2_ERROR_EAGAIN es un número negativo, no es realmente un fallo en sí mismo.

Si esta función devuelve 0 (cero), no debe considerarse un error, sino que no hubo error, pero aún así no se enviaron datos útiles al otro extremo.

ERRORES

LIBSSH2_ERROR_ALLOC - Una llamada interna de asignación de memoria falló.

LIBSSH2_ERROR_SOCKET_SEND - No se pudieron enviar datos por el socket.

LIBSSH2_ERROR_SOCKET_TIMEOUT -

LIBSSH2_ERROR_SFTP_PROTOCOL - Se recibió una respuesta de protocolo SFTP inválida en el socket, o una operación SFTP provocó que el servidor devolviera un código de error.
