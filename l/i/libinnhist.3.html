NOMBRE

his - rutinas para la gestión del historial de INN

SINOPSIS

#include <inn/history.h>
struct history;
struct token;
struct histstats {
    int hitpos;
    int hitneg;
    int misses;
    int dne;
};
#define HIS_RDONLY ...
#define HIS_RDWR ...
#define HIS_CREAT ...
#define HIS_ONDISK ...
#define HIS_INCORE ...
#define HIS_MMAP ...
enum {
    HISCTLG_PATH,
    HISCTLS_PATH,
    HISCTLS_SYNCCOUNT,
    HISCTLS_NPAIRS,
    HISCTLS_IGNOREOLD,
    HISCTLS_STATINTERVAL
};
struct history *HISopen(const char *path, const char *method,
                        int flags);
bool HISclose(struct history *history);
bool HISsync(struct history *history);
void HISsetcache(struct history *history, size_t size);
bool HISlookup(struct history *history, const char *key,
               time_t *arrived, time_t *posted, time_t *expires,
               TOKEN *token);
bool HIScheck(struct history *history, const char *key);
bool HISwrite(struct history *history, const char *key,
              time_t arrived, time_t posted, time_t expires,
              const TOKEN *token);
bool HISremember(struct history *history, const char *key,
                 time_t arrived, time_t posted);
bool HISreplace(struct history *history, const char *key,
                time_t arrived, time_t posted, time_t expires,
                const TOKEN *token);
bool HISexpire(struct history *history, const char *path,
               const char *reason, bool writing, void *cookie,
               time_t threshold,
               bool (*exists)(void *cookie, time_t arrived,
                              time_t posted, time_t expires,
                              const TOKEN *token));
bool HISwalk(struct history *history, const char *reason,
             void *cookie,
             bool (*callback)(void *cookie, time_t arrived,
                              time_t posted, time_t expires,
                              const TOKEN *token));
struct histstats HISstats(struct history *history);
const char *HISerror(struct history *history);
bool HISctl(struct history *history, int request, void *val);

DESCRIPCIÓN

Estas funciones proporcionan acceso a la base de datos de historial de INN. Mantienen pares clave/valor en una base de datos opaca, al tiempo que proporcionan caducidad de la información obsoleta.

La estructura de historial es un manejador opaco devuelto por HISopen.

La función HISopen abre el archivo de historial designado por path utilizando el modo flags y el método especificado method. flags puede ser HIS_RDONLY para indicar que se desea acceso de solo lectura a la base de datos de historial, o HIS_RDWR para acceso de lectura/escritura. Los métodos de historial se definen en el momento de la compilación; el método de historial actualmente disponible es "hisv6". En caso de éxito, se devuelve un manejador de historial recién inicializado, o NULL en caso de fallo.

HIS_ONDISK, HIS_INCORE y HIS_MMAP se pueden combinar lógicamente mediante OR (`|`) en flags para proporcionar una pista al gestor de historial subyacente sobre cómo debe manejar sus archivos de datos; HIS_ONDISK indica que el llamador desea que la mayor parte de los datos se mantengan en disco (y fuera de la memoria), HIS_INCORE indica que los archivos de datos deben mantenerse en memoria principal siempre que sea posible y HIS_MMAP que los archivos deben ser mapeados ("mmap()") en el espacio de direcciones del proceso. HIS_INCORE se usa típicamente donde se está realizando una reconstrucción masiva de la base de datos de historial; el gestor de historial subyacente puede asumir que el llamador invocará HISsync() para sincronizar los archivos de datos con el disco.

El flag HIS_CREAT indica que la base de datos de historial debe ser inicializada como nueva; si se necesitan establecer opciones que afecten la creación de la base de datos, se debe crear un manejador de historial anónimo llamando a HISopen con path establecido a NULL, cualquier opción establecida usando HISctl, y luego abrir la base de datos llamando a HISctl con HISCTLS_PATH.

La función HISclose cierra el manejador history y desasigna cualquier recurso asociado a él. Devuelve false en caso de fallo o true en caso de éxito.

La función HISsync sincroniza cualquier transacción pendiente asociada con history al disco.

HISsetcache asocia una caché utilizada para acelerar HIScheck con history. La caché ocupará aproximadamente size bytes.

HISlookup recupera un token del historial history basado en la key proporcionada (normalmente el Message-ID). Si no se encuentra ninguna entrada con un token asociado, HISlookup devolverá false. Si se encuentra un token, se rellenan arrived, expires y posted con las horas de llegada, caducidad y envío del mensaje respectivamente (o cero, si el componente temporal no está disponible), además de que token se establece al token recuperado y el valor de retorno de la función es true. Cualquiera de arrived, expires, posted o token puede ser NULL, en cuyo caso ese componente no se devuelve al llamador, sin afectar el valor de retorno.

HIScheck verifica la base de datos history para la key (normalmente el Message-ID); si key ha sido previamente establecida mediante HISwrite, HIScheck devuelve true, de lo contrario devuelve false.

HISwrite escribe una nueva entrada en la base de datos history asociada con key. arrived, posted y expired especifican las horas de llegada, envío y caducidad respectivamente; posted y expired pueden especificarse como <= 0, en cuyo caso ese componente se tratará como ausente en la base de datos. token se asocia con la key especificada. HISwrite devuelve true en caso de éxito, o false en caso de fallo. El comportamiento cuando key no es única con respecto a las entradas existentes en history no está especificado.

HISremember escribe una nueva entrada en la base de datos history asociada con key, simplemente recordando que esta key ha sido vista, junto con su hora de llegada arrived y también su hora de envío posted, si se conoce. (De lo contrario, su hora de envío puede especificarse como <= 0 en caso de que esté ausente.) HISremember devuelve true en caso de éxito, o false en caso de fallo. El comportamiento cuando key no es única con respecto a las entradas existentes en history no está especificado.

HISreplace reemplaza una entrada existente en la base de datos history, asociada con key. arrived, posted, expired especifican las horas de llegada, envío y caducidad respectivamente; posted y expired pueden especificarse como <= 0, en cuyo caso ese componente se tratará como ausente en la base de datos. token se asocia con la key especificada; si es NULL, la base de datos de historial simplemente recuerda que esta key ha sido vista, junto con su hora de llegada. HISreplace devuelve true en caso de éxito, o false en caso de fallo.

HISexpire caduca la base de datos de historial asociada con history, creando una nueva base de datos de reemplazo en la misma ubicación si path es NULL, o en path si no es NULL; si path no es NULL, se asume que el llamador realizará la sustitución de la antigua base de datos de historial por la nueva fuera de banda. El flag writing se pasa normalmente como true; si desea inhibir la escritura de la nueva base de datos (y solo ver las devoluciones de llamada), writing puede establecerse en false.

Si el mecanismo de historial subyacente necesita pausar el servidor, la cadena reason se utiliza como argumento para el comando `ctlinnd pause`, y como tal, el servidor debe ser reservado por el llamador antes de llamar a HISexpire; si el llamador desea inhibir la pausa del servidor, pasar NULL logrará esto. Si reason no es NULL, entonces tras el retorno exitoso de HISexpire, el servidor permanecerá pausado y el llamador deberá reanudarlo.

Se escanea la base de datos de historial y las entradas con un token de almacenamiento asociado se pasan a la función de discriminación exists.

Si exists() devuelve false, indica que la entidad almacenada asociada con el token ya no está disponible (o ya no se requiere), y por lo tanto la entrada de historial asociada puede caducar una vez que cumpla la restricción de threshold. Si exists() devuelve true, la entrada se mantiene tal cual en la base de datos de historial recién caducada.

La función exists recibe las horas de llegada, envío y caducidad, además del token asociado con la entrada. Tenga en cuenta que el envío y/o la caducidad pueden ser cero, pero el token nunca será NULL (dichas entradas se manejan únicamente a través del mecanismo de umbral). El token de almacenamiento pasado a la función de discriminación puede actualizarse si es necesario (por ejemplo, como podría ser necesario por una implementación de gestión jerárquica de almacenamiento).

La función HISwalk recorre la base de datos de historial y llama a la función callback para cada entrada, pasando cookie para su uso posterior. Si callback devuelve false, el recorrido se detiene.

HISstats devuelve un struct histstats que contiene las estadísticas de la operación de historial actual; hitpos es el número de veces que se encontró una entrada con un token positivo, hitneg es el número de veces que se encontró una entrada con un token negativo, misses es el número de veces que no se encontró una entrada pero el token era válido y dne es el número de veces que no se encontró una entrada y el token no era válido.

HISerror devuelve una cadena de texto que describe el último error ocurrido en la operación de historial. Si no ha ocurrido ningún error, devuelve NULL.

HISctl se utiliza para consultar o establecer parámetros relacionados con el manejador de historial history. Los valores para request incluyen:

  • HISCTLG_PATH: devuelve la ruta actual del archivo de historial (el valor devuelto debe ser liberado por free(3)).
  • HISCTLS_PATH: establece la ruta del archivo de historial (el valor pasado en val es una cadena de caracteres que no debe ser liberada).
  • HISCTLS_SYNCCOUNT: establece el número de escrituras en disco antes de realizar una sincronización.
  • HISCTLS_NPAIRS: establece el número de pares clave/valor que se almacenarán.
  • HISCTLS_IGNOREOLD: establece un flag que indica si las entradas antiguas deben ser ignoradas durante la lectura.
  • HISCTLS_STATINTERVAL: establece el intervalo en segundos para la recolección de estadísticas.

NAME

libinnhist – history cache management library

SYNOPSIS

#include <inn/libinnhist.h>

void HISclose(HIST *)

HIST *HISopen(const char *path, char *(*discriminator)(void *, const char *), void *cookie)

bool HIScheck(HIST *, const char *token)

bool HISremember(HIST *, const char *token, time_t arrival, time_t posting, time_t expiry)

bool HISreplace(HIST *, const char *token, time_t arrival, time_t posting, time_t expiry)

bool HIScancel(HIST *, const char *token)

bool HISexpire(HIST *, time_t threshold, char *(*discriminator)(void *, const char *), void *cookie)

bool HISwalk(HIST *, bool (*callback)(void *, const char *, time_t, time_t, time_t, const char *), void *cookie, const char *reason)

struct histstats HISstats(HIST *)

const char *HISerror(HIST *)

bool HISctl(HIST *, int request, void *val)

DESCRIPTION

The history cache is used to track articles that have been processed by the server, and therefore do not need to be re-processed if they are received again. The history cache is managed by a history manager, and the library provides an interface to it.

HISopen opens a history cache associated with the given path. If path is NULL, an anonymous history cache is opened. The discriminator function is a callback used by the history manager to determine if an article is to be considered expired or not. It is passed the cookie supplied to HISopen, and the token of the article being considered. If the token is considered expired, the function should return true, otherwise false. If the discriminator is NULL, then no articles are considered expired.

HISclose closes a history cache, freeing any associated resources.

HIScheck checks if an article with the given token is present in the history cache. It returns true if the article is present, and false otherwise.

HISremember adds an article with the given token to the history cache. The arrival, posting, and expiry times are stored along with the token. The times are in seconds since the epoch.

HISreplace is similar to HISremember, but if an article with the given token already exists in the history cache, its times are updated.

HIScancel removes an article with the given token from the history cache.

HISexpire iterates through the history cache and removes any entries whose posting time is less than threshold and which are not considered to exist by the discriminator function. If the posting time is unknown, the arrival time is used instead. The cookie is passed to the discriminator function.

Entries in the database with a posting time less than threshold with no token associated with them are deleted from the database. In case the posting time is unknown, the arrival time is used instead.

The parameter cookie is passed to the discrimination function, and may be used for any purpose required by the caller.

If the discrimination function attempts to access the underlying database (for read or write) during the callback, the behaviour is unspecified.

HISwalk provides an iteration function for the specified history database. For every entry in the history database, callback is invoked, passing the cookie, arrival, posting, and expiry times, in addition to the token associated with the entry. If the callback() returns false the iteration is aborted and HISwalk returns false to the caller.

To process the entire database in the presence of a running server, reason may be passed; if this argument is not NULL, it is used as an an argument to the `ctlinnd (reserve|pause|go)' commands. If reason is NULL and the server is running, the behaviour of HISwalk is undefined.

If the callback function attempts to access the underlying database during the callback, the behaviour is unspecified.

HISstats returns statistics on the history cache mechanism; given a handle history, the return value is a struct histstats detailing:

"hitpos"
The number of times an item was found directly in the cache and known to exist in the underlying history manager.
"hitneg"
The number of times an item was found directly in the cache and known not to exist in the underlying history manager.
"misses"
The number of times an item was not found directly in the cache, but on retrieval from the underlying history manager was found to exist.
"dne"
The number of times an item was not found directly in the cache, but on retrieval from the underlying history manager was found not to exist.

Note that the history cache is only checked by HIScheck and only affected by HIScheck, HISwrite, HISremember and HISreplace. Following a call to HISstats the history statistics associated with history are cleared.

HISerror returns a string describing the most recent error associated with history; the format and content of these strings is history manager dependent. Note that on setting an error, the history API will call the warn function from libinn(3).

HISctl provides a control interface to the underlying history manager. The request argument determines the type of the request and the meaning of the val argument. The values for request are:

"HISCTLG_PATH" (const char **)
Get the base file path which the history handle represents. val should be a pointer to a location of type const char *. The result must not later be passed to free(3).
"HISCTLS_PATH" (const char *)
Set the base file path which this history handle should use; typically this is used after an anonymous handle has been created using HISopen(NULL, ...). val should be a value of type const char * and will be copied before being stored internally.
"HISCTLS_SYNCCOUNT" (size_t *)
Set an upper bound on how many history operations may be pending in core before being synced to permanent storage; 0 indicates unlimited. val should be a pointer to a value of type size_t and will not be modified by the call.
"HISCTLS_NPAIRS" (size_t *)
Set a hint to the to the underlying history manager as to how many entries there are expected to be in the history database; 0 indicates that an automatic or default sizing should be made. val should be a pointer to a value of type size_t and will not be modified by the call.
"HISCTLS_IGNOREOLD" (bool *)
Instruct the underlying history manager to ignore existing database when creating new ones; typically this option may be set to true if the administrator believes that the existing history database is corrupt and that ignoring it may help. val should be a pointer to a value of type bool and will not be modified by the call.
"HISCTLS_STATINTERVAL" (time_t *)
For the history v6 and tagged hash managers, set the interval, in seconds, between stat(2)s of the history files checking for replaced files (as happens during expire); this option is typically used by nnrpd(8) like applications. val should be a pointer to a value of type time_t and will not be modified by the call.
