libressl-SSL_CTX_set_tlsext_servername_callback(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_CTX_SET_TLSEXT_SERVERNAME_CALLBACK(3) Manual de funciones de la biblioteca SSL_CTX_SET_TLSEXT_SERVERNAME_CALLBACK(3)

NOMBRE

SSL_CTX_set_tlsext_servername_callback, SSL_CTX_set_tlsext_servername_arg, SSL_get_servername_type, SSL_get_servername, SSL_set_tlsext_host_name — manejar la indicación del nombre del servidor (SNI)

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

long
SSL_CTX_set_tlsext_servername_callback(SSL_CTX *ctx, int (*cb)(SSL *ssl, int *alert, void *arg));

long
SSL_CTX_set_tlsext_servername_arg(SSL_CTX *ctx, void *arg);

const char *
SSL_get_servername(const SSL *ssl, const int type);

int
SSL_get_servername_type(const SSL *ssl);

int
SSL_set_tlsext_host_name(SSL *ssl, const char *name);

DESCRIPCIÓN

SSL_CTX_set_tlsext_servername_callback() establece la devolución de llamada de aplicación cb que utiliza un servidor para realizar cualquier acción o configuración requerida basada en la extensión servername recibida en la conexión entrante. Al igual que la devolución de llamada ALPN, se ejecuta durante el procesamiento de Client Hello. Cuando cb es NULL, SNI no se utiliza.

La devolución de llamada de servername debe devolver uno de los siguientes valores:

SSL_TLSEXT_ERR_OK
Esto se usa para indicar que el nombre del servidor solicitado por el cliente ha sido aceptado. Típicamente, un servidor llamará a SSL_set_SSL_CTX(3) en la devolución de llamada para configurar una configuración diferente para el nombre del servidor seleccionado en este caso.
SSL_TLSEXT_ERR_ALERT_FATAL
En este caso, el nombre del servidor solicitado por el cliente no es aceptado y el handshake será abortado. El valor de la alerta a usar debe almacenarse en la ubicación apuntada por el parámetro alert para la devolución de llamada. Por defecto, este valor se inicializa a SSL_AD_UNRECOGNIZED_NAME.
SSL_TLSEXT_ERR_ALERT_WARNING
Si se devuelve este valor, el nombre del servidor no es aceptado por el servidor. Sin embargo, el handshake continuará y enviará una alerta de advertencia en su lugar. El valor de la alerta debe almacenarse en la ubicación apuntada por el parámetro alert como para SSL_TLSEXT_ERR_ALERT_FATAL arriba. Tenga en cuenta que TLSv1.3 no admite alertas de advertencia, por lo que si se ha negociado TLSv1.3, este valor de retorno se trata de la misma manera que SSL_TLSEXT_ERR_NOACK.
SSL_TLSEXT_ERR_NOACK
Este valor de retorno indica que el nombre del servidor no es aceptado por el servidor. No se envían alertas y el servidor no reconocerá el nombre del servidor solicitado.

SSL_CTX_set_tlsext_servername_arg() establece un argumento específico del contexto que se pasará a la devolución de llamada a través del parámetro arg para ctx.

SSL_set_tlsext_host_name() establece la extensión Client Hello de indicación del nombre del servidor para que contenga el valor name, o la borra si name es NULL. El tipo de extensión de indicación del nombre del servidor se establece en TLSEXT_NAMETYPE_host_name según se define en RFC 3546.

Las tres funciones se implementan como macros.

VALORES DE RETORNO

SSL_CTX_set_tlsext_servername_callback() y SSL_CTX_set_tlsext_servername_arg() siempre devuelven 1 indicando éxito.

SSL_get_servername() devuelve un valor de extensión de servername del tipo especificado si se proporciona en el Client Hello, o NULL en caso contrario.

SSL_get_servername_type() devuelve el tipo de servername o -1 si no hay ningún servername presente. Actualmente, el único tipo admitido (definido en RFC 3546) es TLSEXT_NAMETYPE_host_name.

SSL_set_tlsext_host_name() devuelve 1 en caso de éxito o 0 en caso de error.

VER TAMBIÉN

ssl(3), SSL_CTX_callback_ctrl(3), SSL_CTX_set_alpn_select_cb(3)
