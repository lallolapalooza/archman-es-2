NOMBRE

libpfm_intel_skl - soporte para PMU de núcleo Intel SkyLake

SINOPSIS

#include <perfmon/pfmlib.h>

Nombre PMU: skl
Descripción PMU: Núcleo Intel SkyLake

DESCRIPCIÓN

La biblioteca soporta la PMU de núcleo Intel SkyLake. Cabe señalar que este modelo de PMU solo cubre la PMU de cada núcleo y no la PMU a nivel de socket.

En SkyLake, el número de contadores genéricos depende del modo Hyperthreading (HT).

Los contadores están disponibles. La función pfm_get_pmu_info() devuelve el número máximo de contadores genéricos en num_cntrs.

MODIFICADORES

Los siguientes modificadores son compatibles con los procesadores Intel SkyLake:

u
Medir a nivel de usuario, que incluye los niveles de privilegio 1, 2, 3. Esto corresponde a PFM_PLM3. Este es un modificador booleano.
k
Medir a nivel de kernel, que incluye el nivel de privilegio 0. Esto corresponde a PFM_PLM0. Este es un modificador booleano.
i
Invertir el significado del evento. El contador ahora contará los ciclos en los que el evento no está ocurriendo. Este es un modificador booleano.
e
Habilitar detección de borde, es decir, contar solo cuando hay una transición de estado de no ocurrencia del evento a al menos una ocurrencia. Este modificador debe combinarse con un modificador de máscara de contador (m) con un valor mayor o igual a uno. Este es un modificador booleano.
c
Establecer el valor de la máscara del contador. La máscara actúa como un umbral. El contador contará el número de ciclos en los que el número de ocurrencias del evento es mayor o igual al umbral. Este es un modificador entero con valores en el rango [0:255].
t
Medir en ambos hilos al mismo tiempo, asumiendo que hyper-threading está habilitado. Este es un modificador booleano.
ldlat
Pasar un umbral de latencia al evento MEM_TRANS_RETIRED:LOAD_LATENCY. Este es un atributo entero que debe estar en el rango [1:65535]. Es requerido para este evento. Tenga en cuenta que el evento debe usarse con muestreo preciso (PEBS).
intx
Monitorizar el evento solo cuando se ejecuta dentro de una región de memoria transaccional (en tx). El evento no cuenta de lo contrario. Este es un modificador booleano. El valor predeterminado es 0.
intxcp
No contar las ocurrencias del evento cuando están dentro de una región de memoria transaccional abortada. Este es un modificador booleano. El valor predeterminado es 0.
fe_thres
Este modificador es solo para el evento FRONTEND_RETIRED. Define el período en ciclos de núcleo después del cual se cuentan las máscaras de bits IDQ_*_BUBBLES. Actúa como un umbral, es decir, al menos un período de N ciclos de núcleo donde el frontend no entregó X uops. Solo se puede usar con las máscaras de bits IDQ_*_BUBBLES. Si no se especifica, el valor del umbral predeterminado es 1 ciclo. Los valores válidos están en [1-4095].

Eventos OFFCORE_RESPONSE

Intel SkyLake proporciona dos eventos offcore_response. Se denominan OFFCORE_RESPONSE_0 y OFFCORE_RESPONSE_1.

Estos eventos requieren un tratamiento especial en la infraestructura de monitorización de rendimiento porque cada evento utiliza un registro adicional para almacenar algunas configuraciones. Por lo tanto, en caso de que se monitoricen varios eventos offcore_response simultáneamente, el kernel necesita gestionar el uso compartido de ese registro adicional.

La biblioteca expone los eventos offcore_response como eventos normales. La configuración adicional se expone como máscaras de bits regulares. La biblioteca se encarga de codificar los eventos de acuerdo con la interfaz del kernel subyacente.

En Intel SkyLake, las máscaras de bits se dividen en tres categorías: solicitud, proveedor y snoop. El usuario debe proporcionar al menos una máscara de bits para cada categoría. Las categorías se muestran en las descripciones de las máscaras de bits.

También existe la máscara de bits de respuesta especial llamada ANY_RESPONSE. Cuando se utiliza esta máscara de bits, anula todas las máscaras de bits de proveedor y snoop. En otras palabras, los usuarios pueden especificar ANY_RESPONSE O cualquier combinación de proveedor + snoop.

En caso de que no se especifique ningún proveedor ni snoop, la biblioteca utiliza de forma predeterminada ANY_RESPONSE.

Por ejemplo, las siguientes son selecciones de eventos válidas:

OFFCORE_RESPONSE_0:DMND_DATA_RD:ANY_RESPONSE
OFFCORE_RESPONSE_0:ANY_REQUEST
OFFCORE_RESPONSE_0:ANY_RFO:LLC_HITM:SNOOP_ANY

Pero las siguientes son ilegales:

OFFCORE_RESPONSE_0:ANY_RFO:LLC_HITM:ANY_RESPONSE
OFFCORE_RESPONSE_0:ANY_RFO:LLC_HITM:SNOOP_ANY:ANY_RESPONSE
