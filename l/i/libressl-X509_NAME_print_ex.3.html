Paquete: libressl

X509_NAME_PRINT_EX(3) Manual de funciones de biblioteca X509_NAME_PRINT_EX(3)

NOMBRE

X509_NAME_print_ex, X509_NAME_print_ex_fp, X509_NAME_oneline — Rutinas de impresión de X509_NAME

SINOPSIS

biblioteca “libcrypto”
#include <openssl/x509.h>

int
X509_NAME_print_ex(BIO *out, const X509_NAME *nm, int indent, unsigned long flags);

int
X509_NAME_print_ex_fp(FILE *fp, const X509_NAME *nm, int indent, unsigned long flags);

char *
X509_NAME_oneline(const X509_NAME *a, char *buf, int size);

DESCRIPCIÓN

X509_NAME_print_ex() imprime una versión legible por humanos de nm en BIO out. Cada línea (para formatos multilínea) está indentada por indent espacios. El formato de salida puede personalizarse extensamente mediante el uso del parámetro flags.

X509_NAME_print_ex_fp() es idéntico a X509_NAME_print_ex() excepto que la salida se escribe en el puntero FILE fp.

X509_NAME_oneline() imprime una versión ASCII de a en buf. Si buf es NULL, entonces se asigna dinámicamente un búfer y se devuelve, y size se ignora. De lo contrario, se escribirán como máximo size bytes, incluido el NUL final, y se devolverá buf.

X509_NAME_oneline() es una función heredada que produce una forma de salida no estándar. No maneja campos de varios caracteres y tiene varias peculiaridades e inconsistencias. Su uso se desaconseja enérgicamente en aplicaciones nuevas.

Aunque hay un gran número de indicadores posibles, para la mayoría de los propósitos bastarán XN_FLAG_ONELINE, XN_FLAG_MULTILINE o XN_FLAG_RFC2253. Como se indica en la página del manual de ASN1_STRING_print_ex(3), para terminales UTF-8, el ASN1_STRFLGS_ESC_MSB debe estar desestablecido: así, por ejemplo, se usaría XN_FLAG_ONELINE & ~ASN1_STRFLGS_ESC_MSB.

El conjunto completo de indicadores admitidos por X509_NAME_print_ex se enumera a continuación.

Se pueden combinar varias opciones mediante OR.

Las opciones XN_FLAG_SEP_COMMA_PLUS, XN_FLAG_SEP_CPLUS_SPC, XN_FLAG_SEP_SPLUS_SPC y XN_FLAG_SEP_MULTILINE determinan los separadores de campos que se utilizarán. Se utilizan dos separadores distintos entre componentes RelativeDistinguishedName distintos y entre valores en el mismo RDN para un RDN multivaluado. Los RDN multivaluados son actualmente muy raros, por lo que el segundo separador rara vez se utilizará.

XN_FLAG_SEP_COMMA_PLUS utiliza comas y signos más como separadores. XN_FLAG_SEP_CPLUS_SPC utiliza comas y signos más con espacios: esto es más legible que comas y signos más simples. XN_FLAG_SEP_SPLUS_SPC utiliza punto y coma espaciado y signo más. XN_FLAG_SEP_MULTILINE utiliza saltos de línea espaciados y signos más, respectivamente. XN_FLAG_SEP_MASK contiene los bits utilizados para representar estas cuatro opciones.

Si XN_FLAG_DN_REV está establecido, todo el DN se imprime en orden inverso.

Los campos XN_FLAG_FN_SN, XN_FLAG_FN_LN, XN_FLAG_FN_OID y XN_FLAG_FN_NONE determinan cómo se muestra un nombre de campo. Utilizará el nombre corto (p. ej., CN), el nombre largo (p. ej., commonName), siempre utilizará la forma numérica del OID (normalmente los OID solo se utilizan si el nombre del campo no se reconoce) y ningún nombre de campo, respectivamente. XN_FLAG_FN_MASK contiene los bits utilizados para representar estas cuatro opciones.

Si XN_FLAG_SPC_EQ está establecido, se colocarán espacios alrededor del carácter ‘=’ que separa los nombres de campo y los valores.

Si XN_FLAG_DUMP_UNKNOWN_FIELDS está establecido, se imprimirá la codificación de los campos desconocidos en lugar de los valores.

Si XN_FLAG_FN_ALIGN está establecido, los nombres de campo se rellenarán hasta 20 caracteres: esto solo es útil en formato multilínea.

Además, se pueden utilizar todas las opciones admitidas por ASN1_STRING_print_ex(3) para controlar cómo se muestra cada valor de campo.

Además, se pueden establecer varias opciones para formatos comunes.

XN_FLAG_RFC2253 establece opciones que producen una salida compatible con RFC 2253. Equivale a ASN1_STRFLGS_RFC2253 | XN_FLAG_SEP_COMMA_PLUS | XN_FLAG_DN_REV | XN_FLAG_FN_SN | XN_FLAG_DUMP_UNKNOWN_FIELDS.

XN_FLAG_ONELINE es un formato de una sola línea más legible, que es lo mismo que: ASN1_STRFLGS_RFC2253 | ASN1_STRFLGS_ESC_QUOTE | XN_FLAG_SEP_CPLUS_SPC | XN_FLAG_SPC_EQ | XN_FLAG_FN_SN.

XN_FLAG_MULTILINE es un formato multilínea que es lo mismo que: ASN1_STRFLGS_ESC_CTRL | ASN1_STRFLGS_ESC_MSB | XN_FLAG_SEP_MULTILINE | XN_FLAG_SPC_EQ | XN_FLAG_FN_LN | XN_FLAG_FN_ALIGN.

XN_FLAG_COMPAT utiliza el formato tradicional no estándar de SSLeay.

VALORES DE RETORNO

X509_NAME_print_ex() y X509_NAME_print_ex_fp() devuelven 1 en caso de éxito o 0 en caso de error si XN_FLAG_COMPAT está establecido en flags. De lo contrario, devuelven el número de bytes impresos, incluida la indentación, o -1 en caso de error.

X509_NAME_oneline() devuelve una cadena válida en caso de éxito o NULL en caso de error.

VER TAMBIÉN

ASN1_STRING_print_ex(3), d2i_X509_NAME(3), X509_NAME_get_index_by_NID(3), X509_NAME_new(3)

HISTORIA

X509_NAME_print_ex() y X509_NAME_print_ex_fp() aparecieron por primera vez en OpenSSL 0.9.6 y han estado disponibles desde OpenBSD 2.9.
