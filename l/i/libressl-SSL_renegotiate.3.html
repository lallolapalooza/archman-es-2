libressl-SSL_renegotiate(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_RENEGOTIATE(3) Manual de funciones de la biblioteca SSL_RENEGOTIATE(3)

NOMBRE

SSL_renegotiate, SSL_renegotiate_abbreviated, SSL_renegotiate_pending — iniciar una nueva negociación TLS

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_renegotiate(SSL *ssl);

int
SSL_renegotiate_abbreviated(SSL *ssl);

int
SSL_renegotiate_pending(SSL *ssl);

DESCRIPCIÓN

Cuando se llama desde el lado del cliente, SSL_renegotiate() programa una negociación completamente nueva sobre una conexión TLS existente. La próxima vez que una operación de E/S como SSL_read() o SSL_write() tenga lugar en la conexión, se realizará una verificación para confirmar que es un momento adecuado para iniciar una renegociación. Si es así, se iniciará una nueva negociación inmediatamente. No se reanudará ninguna sesión existente asociada con la conexión.

Esta función es llamada automáticamente por SSL_read(3) y SSL_write(3) siempre que se exceda el recuento de bytes de renegociación establecido por BIO_set_ssl_renegotiate_bytes(3) o el tiempo de espera establecido por BIO_set_ssl_renegotiate_timeout(3).

Cuando se llama desde el lado del cliente, SSL_renegotiate_abbreviated() es similar a SSL_renegotiate() excepto que se intenta reanudar la sesión asociada con la conexión actual en la nueva negociación.

Cuando se llama desde el lado del servidor, SSL_renegotiate() y SSL_renegotiate_abbreviated() se comportan idénticamente. Ambas programan una solicitud para enviar una nueva negociación al cliente. La próxima vez que se realice una operación de E/S, se realizarán las mismas verificaciones que en el lado del cliente y luego, si es apropiado, se enviará la solicitud. El cliente puede o no responder con una nueva negociación y puede o no intentar reanudar una sesión existente. Si se inicia una nueva negociación, se maneja de forma transparente durante cualquier función de E/S.

Si un cliente LibreSSL recibe una solicitud de renegociación de un servidor, también se maneja de forma transparente durante cualquier función de E/S. El cliente intenta reanudar la sesión actual en la nueva negociación. Por razones históricas, los clientes DTLS no intentan reanudar la sesión en la nueva negociación.

VALORES DE RETORNO

SSL_renegotiate() y SSL_renegotiate_abbreviated() devuelven 1 en caso de éxito o 0 en caso de error.

SSL_renegotiate_pending() devuelve 1 si se ha programado una renegociación o una solicitud de renegociación que aún no se ha llevado a cabo, o 0 en caso contrario.

VER TAMBIÉN

ssl(3), SSL_do_handshake(3), SSL_num_renegotiations(3), SSL_read(3), SSL_write(3)

HISTORIA

SSL_renegotiate() apareció por primera vez en SSLeay 0.8.0 y ha estado disponible desde OpenBSD 2.4.

SSL_renegotiate_pending() apareció por primera vez en OpenSSL 0.9.7 y ha estado disponible desde OpenBSD 3.2.

SSL_renegotiate_abbreviated() apareció por primera vez en OpenSSL 1.0.1 y ha estado disponible desde OpenBSD 5.3.
