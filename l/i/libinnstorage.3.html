DESCRIPCIÓN

libinnstorage es una biblioteca de rutinas comunes (el gestor de almacenamiento) para acceder a artículos de Usenet y datos relacionados independientemente de un método de almacenamiento particular; esto se conoce como la API de almacenamiento.

La función del gestor de almacenamiento es aislar las aplicaciones de los métodos individuales y tomar las decisiones de política sobre qué método de almacenamiento se debe llamar para almacenar un artículo. Uno de los conceptos centrales en la API de almacenamiento es que los artículos no se manipulan usando el message-ID o el número de artículo, sino un token que identifica de forma única el artículo al método que lo almacenó. Esto puede parecer redundante ya que el message-ID ya es un identificador único para el artículo; sin embargo, dado que el método de almacenamiento genera el token, puede codificar toda la información que necesita para localizar el artículo en el token.

OV son rutinas de utilidad comunes para acceder a newsgroups y datos de vista general independientemente del método de vista general particular.

La función OV es aislar las aplicaciones de los métodos individuales. Se asume que todos los artículos pasados a través de la API de almacenamiento están en formato de cable. Formato de cable significa que las líneas terminan en "\r\n", las líneas con puntos (es decir, "." al principio de líneas que ya empiezan con "."), y ".\r\n" al final del artículo en el stream NNTP no se eliminan. Esto tiene una ventaja de rendimiento al transferir artículos. Tenga en cuenta que para el método tradspool, el formato de cable puede deshabilitarse. Esto es solo por compatibilidad que necesitan algunas herramientas antiguas escritas para spool tradicional.

La función IsToken comprueba si el texto está formateado como una cadena de token de texto. Devuelve verdadero si está formateado correctamente o falso si no.

La función TokenToText convierte un token en una cadena de texto para su salida.

La función TextToToken convierte una cadena de texto en un token.

La función SMsetup configura algunos parámetros para su uso por el gestor de almacenamiento. type es uno de los siguientes:

"SM_RDWR"
Permitir apertura de lectura/escritura para archivos de almacenamiento (el valor predeterminado es falso).
"SM_PREOPEN"
Abrir todos los archivos de almacenamiento al inicio y mantenerlos (el valor predeterminado es falso).

value es el puntero que indica el valor de cada tipo. Devuelve verdadero si la configuración es exitosa, o falso si no.

La función SMinit llama a la función de configuración para todos los métodos configurados basándose en SMsetup. Esta función debe llamarse antes que todas las demás funciones de la API de almacenamiento que comienzan con "SM", excepto SMsetup. Devuelve verdadero si la inicialización es exitosa o falso si no. SMinit devuelve verdadero, a menos que todos los métodos de almacenamiento fallen la inicialización.

La función SMstore almacena un artículo especificado con article. Las cabeceras y el cuerpo del artículo se proporcionan a SMstore usando los miembros iov e iovcnt de ARTHANDLE. (data y private son ignorados por SMstore.) Si se especifica arrived, SMstore usa su valor como la hora de llegada del artículo; de lo contrario, SMstore usa la hora actual para ello. SMstore devuelve el tipo de token o devuelve TOKEN_EMPTY si el artículo no se almacena debido a algún error o simplemente no coincide con ninguna expresión uwildmat en storage.conf. SMstore falla si SM_RDWR no se ha establecido como verdadero con SMsetup.

La función SMretrieve recupera un artículo especificado con token. amount es uno de los siguientes que especifica el tipo de recuperación:

"RETR_ALL"
Recuperar el artículo completo.
"RETR_HEAD"
Recuperar las cabeceras del artículo.
"RETR_BODY"
Recuperar el cuerpo del artículo.
"RETR_STAT"
Solo comprobar si el artículo existe.

SMretrieve proporciona los datos del artículo a través de los miembros data y len de ARTHANDLE. (iov no es establecido por SMretrieve.) El área de datos indicada por ARTHANDLE no debe modificarse.

La función SMnext es similar en función a SMretrieve excepto que está destinada a recorrer la tienda de artículos del método secuencialmente. Para iniciar una consulta, se debe llamar a SMnext con un puntero ARTHANDLE NULL. Entonces SMnext devuelve un ARTHANDLE que debe usarse para la siguiente consulta. Si se devuelve un puntero ARTHANDLE NULL, no quedan artículos para consultar. Si data de ARTHANDLE es un puntero NULL o len de ARTHANDLE es 0, indica que el artículo puede estar corrupto y debe ser cancelado por SMcancel. El área de datos indicada por ARTHANDLE no debe modificarse.

La función SMfreearticle libera toda la memoria asignada utilizada por SMretrieve y SMnext. Si se llamará a SMnext con un ARTHANDLE devuelto previamente, no se debe llamar a SMfreearticle ya que SMnext libera la memoria asignada internamente.

La función SMcancel elimina el artículo especificado con token. Devuelve verdadero si la cancelación es exitosa o falso si no. SMcancel falla si SM_RDWR no se ha establecido como verdadero con SMsetup.

La función SMprobe comprueba el token en PROBETYPE. type es uno de los siguientes:

"SELFEXPIRE"
Comprobar si el método del token tiene funcionalidad de auto-expiración.
"SMARTNGNUM"
Obtener el nombre del newsgroup y el número de artículo del token.
"EXPENSIVESTAT"

libinnstorage - storage API for overview management

DESCRIPTION

The storage API provides the common interface to multiple storage methods. The overview API is the common interface to multiple overview methods.

The SMopen function calls the setup function for the configured storage method. The storage method is specified by storagehash in inn.conf(5). This function should be called prior to all other SM functions.

The SMclose function calls the teardown function for the configured storage method.

The SMstore function stores the overview data specified with the token.

The SMfetch function retrieves the overview data specified with the token.

The SMcancel function requests the storage method delete overview data specified with token.

The SMcanceltoken function requests the storage method delete overview data specified with token. It should be called when the article is not present in the storage.

The SMchecktoken function checks the existence of an article. It returns SM_OK if the article exists, and SM_NOTFOUND if the article does not exist. If the existence of an article is expensive to check, it returns SM_ERR.

The SMprintfiles function shows file name or token usable by fastrm(1).

The SMflushcacheddata function flushes cached data on each storage method. type is one of following:

"SM_HEAD"
Flush cached header.
"SM_CANCELLEDART"
Flush the articles which should be cancelled.
"SM_ALL"
Flush all cached data.

The SMexplaintoken function returns a human-readable text string with a clear, decoded form of the storage API token.

The SMshutdown function calls the shutdown for each configured storage method and then frees any resources it has allocated for itself.

SMerrno and SMerrorstr indicate the reason of the last error concerning storage manager.

OVopen calls the setup function for configured method which is specified as ovmethod in inn.conf(5). mode is constructed from following:

"OV_READ"
Allow read open for the overview method.
"OV_WRITE"
Allow write open for the overview method.

This function should be called prior to all other OV functions which begin with "OV".

The OVctl function probes or sets some parameters for the overview method. type is one of following:

"OVGROUPBASEDEXPIRE"
Setup how group-based expiry is done.
"OVCUTOFFLOW"
Do not add overview data if the data is under the lowest article.
"OVSORT"
Probe which key is suitable for the overview method.
"OVSPACE"
Probe the overview space usage.
"OVSTATALL"
Stat all the articles when OVexpiregroup is called.
"OVSTATICSEARCH"
Setup if results of OVsearch are stored in a static buffer and must be copied before the next call to OVsearch.
"OVCACHEKEEP"
Setup whether the cache should be kept.
"OVCACHEFREE"
Free the cache.

The OVgroupstats function retrieves the specified newsgroup information from the overview method.

The OVgroupadd function informs the overview method that the specified newsgroup is being added.

The OVgroupdel function informs the overview method that the specified newsgroup is being removed.

The OVadd function stores an overview data.

The OVcancel function requests the overview method delete overview data specified with token.

The OVopensearch function requests the overview method prepare overview data retrieval. The request range is determined by low and high. The setting of OVSTATICSEARCH determines how search result data must be handled. (Note that with some storage methods, each call to OVopensearch may cause internal storage to be remapped. Therefore, multiple simultaneous searches may require data to be copied in between OVsearch calls even if OVSTATICSEARCH is false.)

The OVsearch function retrieves information, article number, overview data, or arrival time. It should be called with NULL handle when it is the first time; subsequent OVsearch calls should use the handle returned by the previous call to OVsearch. OVsearch returns true, unless it reaches high, which is specified by OVopensearch. Retrieved overview data are sorted by article number, and len is 0 if there is no overview data for the article. Note that the retrieved data is not necessarily null-terminated; you should only rely on len octets of overview data being present.

The OVclosesearch function frees all resources which have been allocated by OVopensearch.

The OVgetartinfo function retrieves the overview data and the token specified with artnum.

The OVexpiregroup function expires the overview data for the newsgroup. It checks the existence of the article and purges the overview data if the article no longer exists. If groupbaseexpiry in inn.conf is true, OVexpiregroup also expires articles.

The OVclose function frees all resources which are used by the overview method.
