NOMBRE

OCSP_sendreq_new, OCSP_sendreq_nbio, OCSP_REQ_CTX_free, OCSP_REQ_CTX_add1_header, OCSP_REQ_CTX_set1_req, OCSP_parse_url, OCSP_sendreq_bio — funciones de consulta de respuesta OCSP

SINOPSIS

biblioteca “libcrypto”
#include <openssl/ocsp.h>

OCSP_REQ_CTX *
OCSP_sendreq_new(BIO *io, const char *path, OCSP_REQUEST *req, int maxline);

int
OCSP_sendreq_nbio(OCSP_RESPONSE **presp, OCSP_REQ_CTX *rctx);

void
OCSP_REQ_CTX_free(OCSP_REQ_CTX *rctx);

int
OCSP_REQ_CTX_add1_header(OCSP_REQ_CTX *rctx, const char *name, const char *value);

int
OCSP_REQ_CTX_set1_req(OCSP_REQ_CTX *rctx, OCSP_REQUEST *req);

int
OCSP_parse_url(const char *url, char **phost, char **pport, char **ppath, int *pssl);

OCSP_RESPONSE *
OCSP_sendreq_bio(BIO *io, const char *path, OCSP_REQUEST *req);

DESCRIPCIÓN

La función OCSP_sendreq_new() devuelve una estructura OCSP_REQ_CTX utilizando la respuesta io, la ruta URI path, la solicitud OCSP req y con una longitud máxima de línea de respuesta de maxline. Si maxline es cero, se utiliza un valor predeterminado de 4k. La solicitud OCSP req puede establecerse a NULL y proporcionarse más tarde si es necesario.

Los argumentos para OCSP_sendreq_new() corresponden a los componentes de la URI. Por ejemplo, si la URI de respuesta es http://ocsp.com/ocspreq, el BIO io debe conectarse al host ocsp.com en el puerto 80 y path debe establecerse en "/ocspreq".

OCSP_sendreq_nbio() realiza operaciones de E/S no bloqueantes en el contexto de solicitud OCSP rctx. Cuando la operación se completa, devuelve la respuesta en *presp. Si OCSP_sendreq_nbio() indica que se debe reintentar una operación, el BIO correspondiente puede ser examinado para determinar qué operación (lectura o escritura) debe ser reintentada y se pueden tomar las acciones apropiadas, por ejemplo, una llamada a select(2) en el socket subyacente.

OCSP_REQ_CTX_free() libera el contexto OCSP rctx.

OCSP_REQ_CTX_add1_header() agrega la cabecera name con valor value al contexto rctx. Las cabeceras añadidas tienen el formato "name: value" o simplemente "name" si value es NULL. OCSP_REQ_CTX_add1_header() puede llamarse más de una vez para añadir múltiples cabeceras. Debe llamarse antes de cualquier llamada a OCSP_sendreq_nbio(). El parámetro req en la llamada inicial a OCSP_sendreq_new() debe establecerse a NULL si se establecen cabeceras adicionales.

OCSP_REQ_CTX_set1_req() establece la solicitud OCSP en rctx a req. Esta función debe llamarse después de cualquier llamada a OCSP_REQ_CTX_add1_header().

OCSP_parse_url() es una función de utilidad para analizar una url del tipo http[s]://host[:port][/path] y almacenar punteros a copias recién asignadas de las cadenas host, port, y path en *phost, *pport, y *ppath, respectivamente. Por defecto, *ppath se establece a "/" y *pport a "443" para https o "80" para http. Para https, *pssl se establece a 1; de lo contrario, a 0.

OCSP_sendreq_bio() realiza una solicitud OCSP utilizando la respuesta io, la ruta URI path, la solicitud OCSP req. No admite reintentos y, por lo tanto, no puede manejar E/S no bloqueantes de manera eficiente. Se conserva por compatibilidad y no se recomienda su uso en aplicaciones nuevas.

VALORES DE RETORNO

OCSP_sendreq_new() devuelve una estructura OCSP_REQ_CTX válida o NULL si ocurrió un error.

OCSP_sendreq_nbio() devuelve 1 si la operación se completó con éxito, -1 si la operación debe ser reintentada, o 0 si ocurrió un error.

OCSP_REQ_CTX_add1_header(), OCSP_REQ_CTX_set1_req(), y OCSP_parse_url() devuelven 1 para éxito o 0 para fallo.

OCSP_sendreq_bio() devuelve la estructura OCSP_RESPONSE enviada por la respuesta o NULL si ocurrió un error.

EJEMPLOS

Añadir una cabecera Host para ocsp.com:

OCSP_REQ_CTX_add1_header(ctx, Host, ocsp.com );

NAME

OCSP_sendreq_new, OCSP_sendreq_ctx, OCSP_sendreq_free - OCSP request functions

SYNOPSIS

```c

 #include <openssl/ocsp.h>

 OCSP_REQUEST *OCSP_sendreq_new(const char *host, const char *path,
     OCSP_REQ_CTX *rctx, BIO *thermi);
 OCSP_REQ_CTX *OCSP_sendreq_ctx(const char *host, const char *path,
     OCSP_REQ_CTX *rctx, BIO *thermi);
 void OCSP_sendreq_free(OCSP_REQUEST *req);

DESCRIPTION

These functions are used to construct and send an OCSP request.

OCSP_sendreq_new() constructs and sends an OCSP request to the specified host and path. The rctx parameter is an OCSP_REQ_CTX structure that contains the OCSP request details. The thermi parameter is a BIO that can be used for sending and receiving data. If thermi is NULL, a new BIO will be created internally.

OCSP_sendreq_ctx() is similar to OCSP_sendreq_new(), but it returns the OCSP_REQ_CTX structure instead of the OCSP_REQUEST structure.

OCSP_sendreq_free() frees the memory allocated for the OCSP_REQUEST structure.

RETURN VALUES

OCSP_sendreq_new() returns a pointer to an OCSP_REQUEST structure if successful, and NULL otherwise.

OCSP_sendreq_ctx() returns a pointer to an OCSP_REQ_CTX structure if successful, and NULL otherwise.

EXAMPLES

The following example shows how to use OCSP_sendreq_new() to send an OCSP request:

```c

 OCSP_REQ_CTX *rctx = NULL;
 OCSP_REQUEST *req = NULL;
 BIO *bio = NULL;

 /* Create a new OCSP_REQ_CTX structure */
 rctx = OCSP_sendreq_ctx("ocsp.example.com", "/ocsp", NULL, NULL);
 if (rctx == NULL) {
     /* Handle error */
     goto err;
 }

 /* Add a certificate to the request */
 OCSP_REQ_CTX_add_cert(rctx, cert);

 /* Send the OCSP request */
 req = OCSP_sendreq_new("ocsp.example.com", "/ocsp", rctx, bio);
 if (req == NULL) {
     /* Handle error */
     goto err;
 }

 /* Process the OCSP response */
 /* ... */

err:
 OCSP_sendreq_free(req);
 OCSP_REQ_CTX_free(rctx);
 BIO_free(bio);

SEE ALSO

OCSP_REQ_CTX_new(3), OCSP_REQ_CTX_add_cert(3), OCSP_REQ_CTX_free(3)

HISTORY

These functions were added in OpenSSL 1.1.0.

CAVEATS

These functions are intended for simple use cases. For more advanced features, an application should use an alternative, more complete, HTTP library.

Currently only HTTP POST queries to responders are supported.
