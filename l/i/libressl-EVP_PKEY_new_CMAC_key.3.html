EVP_PKEY_NEW_CMAC_KEY(3) Manual de Funciones de Librería EVP_PKEY_NEW_CMAC_KEY(3)

NOMBRE

EVP_PKEY_new_CMAC_key — CMAC en el framework EVP

SINOPSIS

librería “libcrypto”
#include <openssl/evp.h>

EVP_PKEY *
EVP_PKEY_new_CMAC_key(ENGINE *engine, const unsigned char *key, size_t key_len, const EVP_CIPHER *cipher);

DESCRIPCIÓN

EVP_PKEY_new_CMAC_key() asigna un nuevo objeto EVP_PKEY, establece su tipo a EVP_PKEY_CMAC, y lo configura como un envoltorio alrededor de las funciones de bajo nivel documentadas en CMAC_Init(3) utilizando el cifrado de bloque cipher con la key simétrica que tiene key_len bytes de longitud.

Las funciones para obtener objetos EVP_CIPHER adecuados se enumeran en la sección LISTA DE CIFRADOS del manual de EVP_EncryptInit(3). Utilice siempre un objeto que implemente el modo de operación CBC. Al igual que en CMAC_Init(3), esta implementación solo admite cifrados con un tamaño de bloque de 64 o 128 bits.

El argumento engine se ignora; se recomienda pasar NULL.

VALORES DEVUELTOS

EVP_PKEY_new_CMAC_key() devuelve la estructura EVP_PKEY recién asignada o NULL si ocurrió un error.

EJEMPLOS

El siguiente código calcula el resumen de un mensaje con AES-CMAC utilizando la longitud de clave de 128 bits especificada en RFC 4493.

/* Clave ficticia: normalmente se establecería desde otra fuente. */
const unsigned char key[] = "symmetric secret";
const size_t key_len = strlen(key);  /* 16 = 128/8 */

const char *msg = "Hello World!";
const size_t msg_len = strlen(msg);

unsigned char out_mac[16];
size_t out_len = sizeof(out_mac);
size_t i;

EVP_PKEY *pkey;
EVP_MD_CTX *md_ctx;

pkey = EVP_PKEY_new_CMAC_key(NULL, key, key_len, EVP_aes_128_cbc());
if (pkey == NULL)
	err(1, "EVP_PKEY_new_CMAC_key");
md_ctx = EVP_MD_CTX_new();
if (md_ctx == NULL)
	err(1, "EVP_MD_CTX_new");

if (EVP_DigestSignInit(md_ctx, NULL, NULL, NULL, pkey) == 0)
	err(1, "EVP_DigestSignInit");
if (EVP_DigestSign(md_ctx, out_mac, &out_len, msg, msg_len) == 0)
	err(1, "EVP_DigestSign");
EVP_MD_CTX_free(md_ctx);
EVP_PKEY_free(pkey);

printf(" MAC = ");
for (i = 0; i < out_len; i++)
	printf("%02x:", out_mac[i]);
printf("\n");

Considere los siguientes detalles:

  • Aunque el nombre del tipo EVP_PKEY originalmente pretendía significar "clave privada" y la API EVP_DigestSignInit(3) fue diseñada para firmas digitales en el contexto de la criptografía de clave pública, ambos se usan aquí también porque un MAC también requiere una clave, aunque sea una clave simétrica.
  • En contraste con la firma digital que requiere tanto un algoritmo de resumen como una clave privada, el algoritmo CMAC solo requiere un cifrado de bloque y una clave compartida, ambos almacenados en el objeto EVP_PKEY algo mal utilizado. Consecuentemente, el argumento EVP_MD *type de EVP_DigestSignInit(3) debe establecerse en NULL.
  • El tamaño del resumen del mensaje resultante es igual al tamaño del bloque del cifrado utilizado.
  • La función EVP_DigestSignInit(3) no transfiere la propiedad del objeto pkey a md_ctx sino que simplemente incrementa el contador de referencias. En consecuencia, el llamador es responsable de liberar el objeto EVP_PKEY cuando ya no se necesite.
