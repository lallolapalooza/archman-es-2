DESCRIPCIÓN

BIO_s_accept() devuelve el método BIO de aceptación. Esto es un envoltorio alrededor de las rutinas accept(2) del socket TCP/IP de la plataforma.

Usando BIOs de aceptación, se pueden aceptar conexiones TCP/IP y transferir datos usando solo rutinas BIO. De esta manera, las operaciones específicas de cada plataforma están ocultas por la abstracción BIO.

Las operaciones de lectura y escritura en un BIO de aceptación realizarán E/S en la conexión subyacente. Si no hay ninguna conexión establecida y el puerto (ver abajo) está configurado correctamente, el BIO espera una conexión entrante.

Los BIOs de aceptación soportan BIO_puts(3) pero no BIO_gets(3).

Si el indicador de cierre está activado en un BIO de aceptación, cualquier conexión activa en esa cadena se cerrará y el socket se cerrará cuando el BIO se libere.

Llamar a BIO_reset(3) en un BIO de aceptación cerrará cualquier conexión activa y reiniciará el BIO a un estado donde espera otra conexión entrante.

BIO_get_fd(3) y BIO_set_fd(3) pueden ser llamados para recuperar o establecer el socket de aceptación. Ver BIO_s_fd(3).

BIO_set_accept_port() usa la cadena name para establecer el puerto de aceptación. El puerto se representa como una cadena de la forma host:puerto, donde host es la interfaz a usar y puerto es el puerto. El host puede ser "*", que se interpreta como cualquier interfaz; puerto tiene la misma sintaxis que el puerto especificado en BIO_set_conn_port(3) para los BIOs de conexión. Puede ser una cadena de puerto numérica o una cadena a buscar usando getservbyname(3) y una tabla de servicios.

BIO_new_accept() combina BIO_new(3) y BIO_set_accept_port() en una sola llamada. Crea un nuevo BIO de aceptación con el puerto host_port.

BIO_set_nbio_accept() establece el socket de aceptación en modo bloqueante (el predeterminado) si n es 0 o en modo no bloqueante si n es 1.

BIO_set_accept_bios() puede usarse para establecer una cadena de BIOs que se duplicarán y se insertarán al principio de la cadena cuando se reciba una conexión entrante. Esto es útil si, por ejemplo, se requiere un BIO de almacenamiento en búfer o SSL para cada conexión. La cadena de BIOs no debe liberarse después de esta llamada; se liberarán automáticamente cuando se libere el BIO de aceptación.

BIO_set_bind_mode() y BIO_get_bind_mode() establecen y recuperan el modo de enlace actual. Si se establece BIO_BIND_NORMAL (el predeterminado), entonces otro socket no puede enlazarse al mismo puerto. Si se establece BIO_BIND_REUSEADDR, entonces otros sockets pueden enlazarse al mismo puerto. Si se establece BIO_BIND_REUSEADDR_IF_UNUSED, primero se intenta usar BIO_BIN_NORMAL; si esto falla y el puerto no está en uso, se intenta un segundo intento usando BIO_BIND_REUSEADDR.

BIO_do_accept() cumple dos propósitos. Cuando se llama por primera vez, después de que el BIO de aceptación ha sido configurado, intentará crear el socket de aceptación y enlazarle una dirección. Las llamadas segunda y posteriores a BIO_do_accept() esperarán una conexión entrante o solicitarán un reintento en modo no bloqueante.

NOTAS

Cuando un BIO de aceptación está al final de una cadena, esperará una conexión entrante antes de procesar las llamadas de E/S. Cuando un BIO de aceptación no está al final de una cadena, pasa las llamadas de E/S al siguiente BIO de la cadena.

Cuando se establece una conexión, se crea un nuevo BIO de socket para la conexión y se añade a la cadena. Es decir, la cadena es ahora aceptación->socket. Esto significa efectivamente que intentar E/S en un socket de aceptación inicial esperará una conexión entrante y luego realizará E/S en ella.

Si se han establecido BIOs adicionales usando BIO_set_accept_bios(), entonces se colocan entre el socket y el BIO de aceptación; es decir, la cadena será aceptación->otrosbios->socket.

Si un servidor desea procesar múltiples conexiones (como suele ser el caso), entonces el BIO de aceptación debe estar disponible para conexiones entrantes adicionales. Esto se puede hacer esperando una conexión y luego llamando:

connection = BIO_pop(accept);

Después de esta llamada, connection contendrá un BIO para la conexión establecida recientemente y accept será nuevamente un solo BIO que puede usarse para esperar conexiones entrantes adicionales. Si no se aceptarán más conexiones, accept puede liberarse usando BIO_free(3).

Si solo se procesará una conexión, es posible realizar E/S usando el propio BIO de aceptación. Sin embargo, esto a menudo no es deseable porque el BIO de aceptación seguirá aceptando conexiones entrantes adicionales. Esto se puede resolver usando BIO_pop(3) (ver arriba) y liberando el BIO de aceptación después de la conexión inicial.

DESCRIPTION

The accept BIO is a convenience BIO that wraps a socket BIO and provides an interface for accepting incoming socket connections. It is typically used in server applications.

BIO_s_accept() returns the accept BIO method structure.

BIO_new_accept() creates and returns a new accept BIO. The port argument is a string representing the port number or service name to listen on. If port is NULL, then a default port (usually 0, meaning any available port) is used.

BIO_set_accept_port() sets the port on an existing accept BIO sbio. The port argument is the port number or service name string.

BIO_get_accept_port() retrieves the port number or service name string that the accept BIO is listening on. The returned string should be freed by the caller using OPENSSL_free().

BIO_set_nbio_accept() sets the accept BIO to operate in non-blocking mode if nbio is true, or blocking mode if nbio is false. By default, accept BIOs are blocking.

BIO_do_accept() performs the actual accepting of a connection. It should be called repeatedly until a connection is successfully accepted or an error occurs. On success, it returns 1. If the accept operation would block (i.e., in non-blocking mode when no connection is pending), it returns 0. On error, it returns -1.

BIO_set_accept_bios() sets the BIOs to be used for the accepted connection. If accept_bio is NULL, then a new socket BIO is created automatically. Otherwise, the provided accept_bio is used. The accept_bio should be a socket BIO or a BIO that can handle socket operations.

BIO_set_bind_mode() sets the binding mode for the socket. The mode argument can be a bitmask of BIO_BIND_AS_PTR or BIO_BIND_ABOVE_ADDR. If BIO_BIND_AS_PTR is set, the socket will be bound to the address of the peer. If BIO_BIND_ABOVE_ADDR is set, the socket will be bound to an address above the peer's address. This is useful for certain NAT scenarios.

BIO_get_bind_mode() retrieves the current binding mode.

NOTES

The accept BIO simplifies the process of setting up a listening socket and accepting incoming connections. It handles the underlying socket creation, binding, and listening operations.

When BIO_do_accept() returns 0, it means that the accept() system call would block. In a non-blocking context, the application should wait for the socket to become ready for reading (e.g., using select(2) or poll(2)) and then retry the call to BIO_do_accept().

The BIO_ctrl() function can be used to perform various control operations on the accept BIO. The cmd and larg arguments correspond to macros as follows:

RETURN VALUES

When called on an accept BIO object, BIO_method_type(3) returns the constant BIO_TYPE_ACCEPT and BIO_method_name(3) returns a pointer to the static string "socket accept".

BIO_do_accept(), BIO_set_accept_port(), BIO_set_nbio_accept(), BIO_set_accept_bios(), and BIO_set_bind_mode() return 1 for success or 0 or -1 for failure.

BIO_get_accept_port() returns the port as a string or NULL on error.

BIO_get_bind_mode() returns the set of BIO_BIND flags or -1 on failure.

BIO_new_accept() returns a BIO or NULL on error.

EXAMPLES

This example accepts two connections on port 4444, sends messages down each and finally closes both down.

BIO *abio, *cbio, *cbio2;
ERR_load_crypto_strings();
abio = BIO_new_accept("4444");

/* First call to BIO_accept() sets up accept BIO */
if (BIO_do_accept(abio) <= 0) {
	fprintf(stderr, "Error setting up accept\n");
	ERR_print_errors_fp(stderr);
	exit(0);
}

/* Wait for incoming connection */
if (BIO_do_accept(abio) <= 0) {
	fprintf(stderr, "Error accepting connection\n");
	ERR_print_errors_fp(stderr);
	exit(0);
}
fprintf(stderr, "Connection 1 established\n");

/* Retrieve BIO for connection */
cbio = BIO_pop(abio);

BIO_puts(cbio, "Connection 1: Sending out Data on initial connection\n");
fprintf(stderr, "Sent out data on connection 1\n");

/* Wait for another connection */
if (BIO_do_accept(abio) <= 0) {
	fprintf(stderr, "Error accepting connection\n");
	ERR_print_errors_fp(stderr);
	exit(0);
}
fprintf(stderr, "Connection 2 established\n");

/* Close accept BIO to refuse further connections */
cbio2 = BIO_pop(abio);
BIO_free(abio);

BIO_puts(cbio2, "Connection 2: Sending out Data on second\n");
fprintf(stderr, "Sent out data on connection 2\n");
BIO_puts(cbio, "Connection 1: Second connection established\n");

/* Close the two established connections */
BIO_free(cbio);
BIO_free(cbio2);
