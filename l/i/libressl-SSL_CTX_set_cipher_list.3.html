Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_CTX_SET_CIPHER_LIST(3) Manual de Funciones de Biblioteca SSL_CTX_SET_CIPHER_LIST(3)

NOMBRE

SSL_CTX_set_cipher_list, SSL_set_cipher_list — elegir lista de SSL_CIPHERs disponibles

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_CTX_set_cipher_list(SSL_CTX *ctx, const char *control);

int
SSL_set_cipher_list(SSL *ssl, const char *control);

DESCRIPCIÓN

SSL_CTX_set_cipher_list() establece la lista de suites de cifrado disponibles para ctx usando la cadena control. La lista de suites de cifrado es heredada por todos los objetos ssl creados desde ctx.

SSL_set_cipher_list() establece la lista de suites de cifrado solo para ssl.

La cadena de control consiste en una o más palabras de control separadas por caracteres de dos puntos (‘:’). Los caracteres de espacio (&#x2018; ’), punto y coma (&#x2018;;’) y coma (&#x2018;,’) también se pueden usar como separadores. Cada palabra de control selecciona un conjunto de suites de cifrado y puede tener uno de los siguientes caracteres de prefijo opcionales:

Sin prefijo:
Las suites de cifrado seleccionadas que aún no se han puesto a disposición se agregan al final de la lista de suites de cifrado disponibles, conservando su orden.
Signo menos con prefijo (‘-’):
Las suites de cifrado seleccionadas que se pusieron a disposición anteriormente se mueven de la lista de suites de cifrado disponibles al principio de la lista de suites de cifrado no disponibles, conservando también su orden.
Signo más con prefijo (‘+’):
Las suites de cifrado seleccionadas que se pusieron a disposición anteriormente se mueven al final de la lista de suites de cifrado disponibles, reduciendo su prioridad, pero conservando el orden entre ellas.
Signo de exclamación con prefijo (&#x2018;!’):
Las suites de cifrado seleccionadas se eliminan permanentemente, sin importar si se habían puesto a disposición anteriormente o no, y ya no se podrán agregar ni re-agregar mediante palabras posteriores.

Las siguientes palabras especiales solo se pueden usar sin prefijo:

PREDETERMINADO
Un alias para TODOS:!aNULL:!eNULL. Solo se puede usar como la primera palabra. La lista de cifrado PREDETERMINADO se puede mostrar con el comando openssl(1) ciphers.
@NIVEL_SEGURIDAD=n
Establece el nivel de seguridad en n, que debe ser un número entre cero y cinco. Consulte SSL_CTX_set_security_level(3) para obtener más detalles.
@FUERZA
Ordena la lista por fuerza de cifrado decreciente, conservando el orden de las suites de cifrado que tienen la misma fuerza. Generalmente se da como la última palabra.

Las siguientes palabras se pueden usar para seleccionar grupos de suites de cifrado, con o sin un carácter de prefijo. Si dos o más de estas palabras se unen con signos más (‘+’) para formar una palabra más larga, solo se selecciona la intersección de los conjuntos especificados.

ADH
Suites de cifrado que utilizan DH efímero para el intercambio de claves sin realizar ninguna autenticación del servidor. Equivalente a DH+aNULL.
AEAD
Suites de cifrado que utilizan Cifrado Autenticado con Datos Adicionales.
AECDH
Suites de cifrado que utilizan ECDH efímero para el intercambio de claves sin realizar ninguna autenticación del servidor. Equivalente a ECDH+aNULL.
aECDSA
Suites de cifrado que utilizan autenticación de servidor ECDSA.
AES
Suites de cifrado que utilizan AES o AESGCM para cifrado simétrico.
AES128
Suites de cifrado que utilizan AES(128) o AESGCM(128) para cifrado simétrico.
AES256
Suites de cifrado que utilizan AES(256) o AESGCM(256) para cifrado simétrico.
AESGCM
Suites de cifrado que utilizan AESGCM para cifrado simétrico.
aGOST
Un alias para aGOST01.
aGOST01
Suites de cifrado que utilizan autenticación de servidor GOST R 34.10-2001.
TODOS
Todas las suites de cifrado excepto las seleccionadas por eNULL.
aNULL
Suites de cifrado que no realizan ninguna autenticación del servidor. No habilitadas por PREDETERMINADO. Tenga cuidado con los ataques man-in-the-middle.
aRSA
Suites de cifrado que utilizan autenticación de servidor RSA.
CAMELLIA
Suites de cifrado que utilizan Camellia para cifrado simétrico.
CAMELLIA128
Suites de cifrado que utilizan Camellia(128) para cifrado simétrico.
CAMELLIA256
Suites de cifrado que utilizan Camellia(256) para cifrado simétrico.
CHACHA20
Suites de cifrado que utilizan ChaCha20-Poly1305 para cifrado simétrico.
COMPLEMENTODETODOS
Suites de cifrado que no están incluidas en TODOS. Actualmente un alias para eNULL.
COMPLEMENTODEDEFECTO
Suites de cifrado que están incluidas en TODOS, pero no incluidas en PREDETERMINADO. Actualmente similar a aNULL:!eNULL excepto por el orden de las suites de cifrado que *no* están seleccionadas.
3DES
Suites de cifrado que utilizan triple DES para cifrado simétrico.
DH
Suites de cifrado que utilizan DH efímero para el intercambio de claves.
DHE
Suites de cifrado que utilizan DH efímero para el intercambio de claves, pero excluyendo aquellas que no realizan autenticación del servidor. Similar a DH:!aNULL excepto por el orden de las suites de cifrado que *no* están seleccionadas.
ECDH
Suites de cifrado que utilizan ECDH efímero para el intercambio de claves.
ECDHE
Suites de cifrado que utilizan ECDH efímero para el intercambio de claves, pero excluyendo aquellas que no realizan autenticación del servidor. Similar a libressl(3) — Arch Linux man pages

NAME

SSL_CTX_set_cipher_list, SSL_set_cipher_list - configure cipher suites

SYNOPSIS

#include <openssl/ssl.h>

int SSL_CTX_set_cipher_list(SSL_CTX *ctx, const char *str);
int SSL_set_cipher_list(SSL *ssl, const char *str);

DESCRIPTION

The SSL_CTX_set_cipher_list() function sets the list of cipher suites that are available for the context ctx to be the string str.

The SSL_set_cipher_list() function sets the list of cipher suites that are available for the SSL object ssl to be the string str.

The string str is a colon-separated list of cipher suite names or keywords. The order in the list determines the priority. The first cipher suite in the list that is supported by both client and server will be used.

The following keywords are supported:

aNULL
Cipher suites that do not use any authentication. Not enabled by DEFAULT.
aECDH
Cipher suites that use ECDH for key agreement and an ECDSA signature for authentication.
aGOST01
Cipher suites using GOST R 34.10-2001 signature algorithm for authentication.
aGOST94
Cipher suites using GOST R 34.10-94 signature algorithm for authentication.
aKRB5
Cipher suites using Kerberos V5 for authentication.
aPSK
Cipher suites using Pre-Shared Keys (PSK) for authentication.
aRSA
Cipher suites using RSA for authentication.
ALL
All cipher suites, except for those using anonymous authentication or NULL encryption.
CHACHA20
Cipher suites using ChaCha20 for symmetric encryption.
CAMELLIA
Cipher suites using Camellia for symmetric encryption.
DES
Cipher suites using DES for symmetric encryption.
DHE
Cipher suites using Diffie-Hellman key exchange and an ephemeral Diffie-Hellman key.
DH
Cipher suites using Diffie-Hellman key exchange.
DHE_EXPORT
Cipher suites using an export-capable Diffie-Hellman key exchange.
DHE_DSS
Cipher suites using Diffie-Hellman key exchange and DSS authentication.
DHE_RSA
Cipher suites using Diffie-Hellman key exchange and RSA authentication.
DHE_PSK
Cipher suites using Diffie-Hellman key exchange and PSK authentication.
ECC
Cipher suites using Elliptic Curve Cryptography (ECC).
ECDH
Cipher suites using Elliptic Curve Diffie-Hellman key exchange.
ECDSA
Cipher suites using Elliptic Curve Digital Signature Algorithm for authentication.
eNULL
Cipher suites that do not use any encryption. Not enabled by DEFAULT, and not even included in ALL.
GOST89MAC
Cipher suites using GOST 28147-89 for message authentication instead of HMAC.
GOST94
Cipher suites using HMAC based on GOST R 34.11-94 for message authentication.
HIGH
Cipher suites of high strength.
kGOST
Cipher suites using VKO 34.10 key exchange, specified in RFC 4357.
kRSA
Cipher suites using RSA key exchange.
LOW
Cipher suites of low strength.
MD5
Cipher suites using MD5 for message authentication.
MEDIUM
Cipher suites of medium strength.
NULL
An alias for eNULL.
RC4
Cipher suites using RC4 for symmetric encryption.
RSA
Cipher suites using RSA for both key exchange and server authentication. Equivalent to kRSA+aRSA.
SHA
An alias for SHA1.
SHA1
Cipher suites using SHA1 for message authentication.
SHA256
Cipher suites using SHA256 for message authentication.
SHA384
Cipher suites using SHA384 for message authentication.
SSLv3
An alias for TLSv1.
STREEBOG256
Cipher suites using STREEBOG256 for message authentication.
TLSv1
Cipher suites usable with the TLSv1.0, TLSv1.1, and TLSv1.2 protocols.
TLSv1.2
Cipher suites for the TLSv1.2 protocol.
TLSv1.3
Cipher suites for the TLSv1.3 protocol. If the control string selects at least one cipher suite but neither contains the word TLSv1.3 nor specifically includes nor excludes any TLSv1.3 cipher suites, all the TLSv1.3 cipher suites are made available, too.

The full words returned by the openssl(1) ciphers command can be used to select individual cipher suites.

The following are deprecated aliases:

avoid: use:
EDH DHE
EECDH ECDHE
kEDH DH
kEECDH ECDH

Unknown words are silently ignored, selecting no cipher suites. Failure is only flagged if the control string contains invalid bytes or if no matching cipher suites are available at all.

On the client side, including a cipher suite into the list of available cipher suites is sufficient for using it. On the server side, all cipher suites have additional requirements. ADH ciphers don't need a certificate, but DH-parameters must have been set. All other cipher suites need a corresponding certificate and key.

A RSA cipher can only be chosen when an RSA certificate is available. RSA ciphers using DHE need a certificate and key and additional DH-parameters (see SSL_CTX_set_tmp_dh_callback(3)).

When these conditions are not met for any cipher suite in the list (for example, a client only supports export RSA ciphers with an asymmetric key length of 512 bits and the server is not configured to use temporary RSA keys), the “no shared cipher” (SSL_R_NO_SHARED_CIPHER) error is generated and the handshake will fail.

RETURN VALUES

SSL_CTX_set_cipher_list() and SSL_set_cipher_list() return 1 if any cipher suite could be selected and 0 on complete failure.

SEE ALSO

ssl(3), SSL_CTX_set1_groups(3), SSL_CTX_set_tmp_dh_callback(3), SSL_CTX_use_certificate(3), SSL_get_ciphers(3)

HISTORY

SSL_CTX_set_cipher_list() and SSL_set_cipher_list() first appeared in SSLeay 0.5.2 and have been available since OpenBSD 2.4.

CAVEATS

In LibreSSL, SSL_CTX_set_cipher_list() and SSL_set_cipher_list() can be used to configure the list of available cipher suites for all versions of the TLS protocol, whereas in OpenSSL, they only control cipher suites for protocols up to TLSv1.2. If compatibility with OpenSSL is required, the list of available TLSv1.3 cipher suites can only be changed with SSL_set_ciphersuites().
