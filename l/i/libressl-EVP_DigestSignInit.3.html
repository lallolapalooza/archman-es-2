Paquete: libressl

Licencias: ISC, custom:OpenSSL

EVP_DIGESTSIGNINIT(3) Manual de funciones de biblioteca EVP_DIGESTSIGNINIT(3)

NOMBRE

EVP_DigestSignInit, EVP_DigestSignUpdate, EVP_DigestSignFinal, EVP_DigestSign — funciones de firma EVP

SINOPSIS

biblioteca “libcrypto”
#include <openssl/evp.h>

int
EVP_DigestSignInit(EVP_MD_CTX *ctx, EVP_PKEY_CTX **pctx, const EVP_MD *type, ENGINE *engine, EVP_PKEY *pkey);

int
EVP_DigestSignUpdate(EVP_MD_CTX *ctx, const void *d, size_t cnt);

int
EVP_DigestSignFinal(EVP_MD_CTX *ctx, unsigned char *sig, size_t *siglen);

int
EVP_DigestSign(EVP_MD_CTX *ctx, unsigned char *sigret, size_t *siglen, const unsigned char *tbs, size_t tbslen);

DESCRIPCIÓN

Las rutinas de firma EVP son una interfaz de alto nivel para firmas digitales.

EVP_DigestSignInit() configura el contexto de firma ctx para usar el digest type y la clave privada pkey. Antes de llamar a esta función, obtenga ctx de EVP_MD_CTX_new(3) o llame a EVP_MD_CTX_reset(3) sobre él. El argumento engine siempre se ignora y se recomienda pasar NULL.

Si pctx no es NULL, cualquier puntero pasado como *pctx se ignora y se sobrescribe con un puntero interno al EVP_PKEY_CTX utilizado por la operación de firma: esto se puede usar para establecer opciones de firma alternativas. El EVP_PKEY_CTX devuelto no debe ser liberado por la aplicación. Se libera automáticamente cuando se libera el EVP_MD_CTX.

EVP_DigestSignUpdate() calcula el hash de cnt bytes de datos en d en el contexto de firma ctx. Esta función se puede llamar varias veces en el mismo ctx para incluir datos adicionales. Actualmente, esta función está implementada mediante una macro.

EVP_DigestSignFinal() firma los datos en ctx y coloca la firma en sig. Si sig es NULL, entonces el tamaño máximo del búfer de salida se escribe en *siglen. Si sig no es NULL, entonces antes de la llamada siglen debe contener la longitud del búfer sig. Si la llamada es exitosa, la firma se escribe en sig y la cantidad de datos escritos en siglen.

EVP_DigestSign() firma tbslen bytes de datos en tbs y coloca la firma en sigret y su longitud en siglen de manera similar a EVP_DigestSignFinal(). EVP_DigestSign() es una operación de un solo uso que firma un único bloque de datos con una sola llamada a la función. Para algoritmos que admiten transmisión en tiempo real, es equivalente a llamar a EVP_DigestSignUpdate() y EVP_DigestSignFinal().

La interfaz EVP para firmas digitales casi siempre debería usarse en lugar de las interfaces de bajo nivel. Esto se debe a que el código entonces se vuelve transparente al algoritmo utilizado y mucho más flexible.

La llamada a EVP_DigestSignFinal() finaliza internamente una copia del contexto de digest. Esto significa que EVP_DigestSignUpdate() y EVP_DigestSignFinal() se pueden llamar más tarde para calcular el hash y firmar datos adicionales.

Dado que solo se finaliza una copia del contexto de digest, el contexto debe limpiarse después de su uso llamando a EVP_MD_CTX_free(3), o se producirá una fuga de memoria.

Se desaconseja el uso de EVP_PKEY_size(3) con estas funciones porque algunas operaciones de firma pueden tener una longitud de firma que depende de los parámetros establecidos. Como resultado, EVP_PKEY_size(3) tendría que devolver un valor que indique la firma máxima posible para cualquier conjunto de parámetros.

VALORES DE RETORNO

EVP_DigestSignInit(), EVP_DigestSignUpdate(), EVP_DigestSignFinal(), y EVP_DigestSign() devuelven 1 si el éxito y 0 si falla.

Los códigos de error se pueden obtener de ERR_get_error(3).

VER TAMBIÉN

evp(3), EVP_DigestInit(3), EVP_DigestVerifyInit(3)

HISTORIA

EVP_DigestSignInit(), EVP_DigestSignUpdate(), y EVP_DigestSignFinal() aparecieron por primera vez en OpenSSL 1.0.0 y han estado disponibles desde OpenBSD 4.9.

EVP_DigestSign() apareció por primera vez en OpenSSL 1.1.1 y ha estado disponible desde OpenBSD 7.0.
