NOMBRE

libnbd-release-notes-1.18 - notas de la versión de libnbd 1.18

DESCRIPCIÓN

Estas son las notas de la versión de la versión estable 1.18 de libnbd. Describe los principales cambios desde la 1.16.

libnbd 1.18.0 fue lanzada el 27 de septiembre de 2023.

Seguridad

Eric Blake encontró un caso en el que un servidor podía hacer que libnbd se colgara, aunque no en la configuración normal de libnbd. Para más información, véase el anuncio aquí: https://listman.redhat.com/archives/libguestfs/2023-July/032035.html

Eric Blake encontró un problema con nbd_get_size(3) en el que un servidor que devuelve un tamaño > (uint64_t)INT64_MAX y < (uint64_t)-1 haría que nbd_get_size devolviera un número negativo (que no es -1 y, por lo tanto, los llamadores pueden o no tratarlo como un error). Aunque ningún código cliente en libnbd se ve afectado por esto, podría afectar a clientes externos. libnbd ≥ 1.16.5 ahora devuelve un error (-1) y establece nbd_get_errno a "EOVERFLOW" en este caso. Esto fue asignado a CVE-2023-5215 (baja severidad). Véase el anuncio aquí: https://listman.redhat.com/archives/libguestfs/2023-September/032711.html

Durante las pruebas de fuzzing de rutina, encontramos varios problemas de seguridad que se introdujeron durante este ciclo de desarrollo y que posteriormente se han corregido. Las versiones estables (con números pares) de libnbd no deberían ser vulnerables; no utilice las versiones de desarrollo (con números impares) en producción.

Si encuentra un problema de seguridad, lea SECURITY en el código fuente (en línea aquí: https://gitlab.com/nbdkit/libnbd/blob/master/SECURITY). Para saber sobre problemas de seguridad anteriores en libnbd, consulte libnbd-security(3).

Nuevas APIs

nbd_block_status_64(3)
nbd_aio_block_status_64(3)
Realiza una solicitud de estado de bloque de 64 bits, véase "Protocolo" más abajo (Eric Blake).
nbd_block_status_filter(3)
nbd_aio_block_status_filter(3)
Envía un comando de estado de bloque filtrado, véase "Protocolo" más abajo (Eric Blake).
nbd_can_block_status_payload(3)
Averigua si el servidor admite el comando de estado de bloque filtrado (Eric Blake).
nbd_set_request_extended_headers(3)
nbd_get_request_extended_headers(3)
nbd_get_extended_headers_negotiated(3)
nbd_opt_extended_headers(3)
nbd_aio_opt_extended_headers(3)
Establece/obtiene si solicitamos encabezados extendidos del servidor, y averigua si negociamos encabezados extendidos, véase "Protocolo" más abajo (Eric Blake).

Mejoras en las APIs existentes

Las constantes de meta-contexto "qemu:" (p. ej. "qemu:dirty-bitmap" como "LIBNBD_CONTEXT_QEMU_DIRTY_BITMAP") están ahora disponibles a través de los enlaces de los lenguajes C, Golang, OCaml y Python (Eric Blake).

nbd_shutdown(3) ahora funciona correctamente en modo opt (Eric Blake).

nbd_set_strict_mode(3) añade "LIBNBD_STRICT_AUTO_FLAG", que permite al cliente probar cómo se comportan los servidores cuando se ajusta la bandera de longitud de carga útil (Eric Blake).

Protocolo

libnbd ahora admite encabezados extendidos de 64 bits de NBD y tamaños de extensión. En la práctica, esto permite implementar de forma mucho más eficiente ciertas solicitudes, como el borrado de secciones muy grandes del disco, con servidores que lo admiten (Eric Blake).

libnbd ahora admite solicitudes de estado de bloque filtradas (Eric Blake).

Herramientas

nbdcopy(1), nbdinfo(1) y nbddump(1) se han ampliado para utilizar e informar sobre el soporte de encabezados extendidos / 64 bits de NBD cuando el servidor lo admite (Eric Blake).

nbdinfo --has puede usarse como alias de --can, p. ej. "nbdinfo --has structured-reply URI" (Eric Blake).

nbdinfo hace que la salida del tamaño de la exportación sea opcional, para servidores que envían una que excede el tamaño (Eric Blake).

nbdcopy ahora admite "tamaños legibles" para algunos parámetros, p. ej. "nbdcopy --request-size=1M ...".

Enlaces de lenguajes

Nuevos enlaces en Rust. Hay una API básica para uso general y una API asíncrona implementada usando Tokio. Se requiere Rust ≥ 1.69. (Tage Johansson, con el apoyo de patrocinio de Google Summer of Code 2023, revisiones y correcciones adicionales de Eric Blake).

Se admite OCaml 5.

Se admite Golang 1.21. La versión mínima es ahora 1.17 (Eric Blake).

Utilice "gofmt" para formatear los enlaces de Golang (Eric Blake).

Utilice "unsafe.Slice" al convertir matrices C a slices de Golang (Eric Blake).

Todos los enlaces de lenguajes admiten encabezados extendidos / 64 bits de NBD, y hay ejemplos de cómo usar esta característica disponibles (Eric Blake).

Pruebas

Se corrigieron un par de condiciones de carrera en las pruebas en las que no consumimos completamente la entrada estándar en el método pwrite de nbdkit-sh-plugin(3) (Eric Blake).

El fuzzing ahora deshabilita las comprobaciones de estrictez del lado del cliente, lo que permite probar una gama más amplia de entradas (Eric Blake).

Otras mejoras y correcciones de errores

Se ajusta consistentemente el código fuente a 80 columnas (Laszlo Ersek).

Los mensajes de depuración ya no imprimen las transiciones de estado muy verbosas dentro de la máquina de estados, ya que normalmente no son útiles. Puede volver a habilitar esto definiendo "-DLIBNBD_STATE_VERBOSE=1" en el momento de la compilación.

Los métodos de "completion" ".callback" ahora se llaman siempre exactamente una vez, y la documentación es más clara sobre cuándo ocurre esto (Eric Blake).

Documentación

"podwrapper" tiene un nuevo parámetro --replace que facilita el uso de sustituciones "AC_SUBST" en la documentación.

Compilación

Se corrigió una regresión en las compilaciones de MinGW (Eric Blake).
