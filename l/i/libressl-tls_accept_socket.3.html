libressl-tls_accept_socket(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

TLS_ACCEPT_SOCKET(3) Manual de funciones de la biblioteca TLS_ACCEPT_SOCKET(3)

NOMBRE

tls_accept_socket, tls_accept_fds, tls_accept_cbs — aceptar una conexión de cliente entrante en un servidor TLS

SINOPSIS

biblioteca “libtls” libssl libcrypto
#include <tls.h>

int
tls_accept_socket(struct tls *tls, struct tls **cctx, int socket);

int
tls_accept_fds(struct tls *tls, struct tls **cctx, int fd_read, int fd_write);

int
tls_accept_cbs(struct tls *tls, struct tls **cctx, ssize_t (*tls_read_cb)(struct tls *ctx, void *buf, size_t buflen, void *cb_arg), ssize_t (*tls_write_cb)(struct tls *ctx, const void *buf, size_t buflen, void *cb_arg), void *cb_arg);

DESCRIPCIÓN

Después de crear un contexto de servidor TLS tls con tls_server(3) y configurarlo con tls_configure(3), un servidor puede aceptar una nueva conexión de cliente llamando a tls_accept_socket() en una conexión de socket ya establecida.

Alternativamente, se puede aceptar una nueva conexión de cliente a través de un par de descriptores de archivo existentes llamando a tls_accept_fds().

Llamar a tls_accept_cbs() permite que las funciones de devolución de llamada de lectura y escritura manejen las transferencias de datos. El parámetro cb_arg especificado se devuelve a las funciones y puede contener un puntero a cualquier dato especificado por el llamante.

Todas estas funciones crean un nuevo contexto adecuado para leer y escribir y lo devuelven en *cctx.

VALORES DE RETORNO

Estas funciones devuelven 0 si tienen éxito o -1 si hay un error.

VEA TAMBIÉN

tls_close(3), tls_config_set_session_id(3), tls_configure(3), tls_connect(3), tls_init(3), tls_server(3)

HISTORIA

tls_accept_socket() apareció en OpenBSD 5.6 y recibió su nombre final en OpenBSD 5.7.

tls_accept_fds() apareció en OpenBSD 5.8 y tls_accept_cbs() en OpenBSD 6.1.
