DESCRIPCIÓN

Estas funciones configuran un objeto X509_STORE_CTX para su uso posterior por X509_verify_cert(3).

X509_STORE_CTX_new() asigna un objeto X509_STORE_CTX vacío que aún no contiene los subobjetos necesarios para el funcionamiento normal.

X509_STORE_CTX_init() debe llamarse en cada ctx nuevo antes de que las otras funciones sean útiles. Prepara ctx para una única operación de verificación utilizando X509_verify_cert(3). Se pueden proporcionar el certificado de confianza store a utilizar, el certificado de entidad final x a verificar y un conjunto de certificados adicionales untrusted para construir la cadena, o cualquiera o todos ellos pueden establecerse en NULL. Los tres punteros pasados se almacenan internamente, los tres objetos a los que apuntan no se copian, su recuento de referencia no se incrementa y el llamador sigue siendo responsable de gestionar su almacenamiento y de no liberarlos antes de que se llame a X509_STORE_CTX_free() en ctx. Si se proporciona una store, los parámetros de verificación contenidos en ella se copian utilizando X509_VERIFY_PARAM_inherit(3).

X509_STORE_CTX_cleanup() limpia internamente ctx, devolviéndolo a un estado vacío similar al posterior a X509_STORE_CTX_new(). Luego puede reutilizarse con una nueva llamada a X509_STORE_CTX_init().

X509_STORE_CTX_free() llama a X509_STORE_CTX_cleanup() y libera el almacenamiento al que apunta ctx. Si ctx es un puntero NULL, no ocurre ninguna acción.

X509_STORE_CTX_get0_store() devuelve el puntero interno al store de certificados de confianza que se estableció con X509_STORE_CTX_init().

X509_STORE_CTX_set0_trusted_stack() establece el conjunto de certificados trusted utilizados por ctx. Esta es una forma alternativa de especificar certificados de confianza en lugar de utilizar el store. X509_STORE_CTX_trusted_stack() es un alias obsoleto para X509_STORE_CTX_set0_trusted_stack().

X509_STORE_CTX_set_cert() establece el certificado a verificar en ctx a x, anulando el certificado que se estableció con X509_STORE_CTX_init(). De nuevo, el certificado no se copia y su recuento de referencia no se incrementa.

X509_STORE_CTX_get0_cert() recupera el puntero interno al certificado que se está verificando por ctx, es decir, el último establecido mediante X509_STORE_CTX_init() o X509_STORE_CTX_set_cert().

X509_STORE_CTX_set_chain() y X509_STORE_CTX_set0_untrusted() son idénticas y establecen los certificados adicionales y no confiables untrusted utilizados por ctx, anulando el conjunto de certificados adicionales y no confiables que se estableció con X509_STORE_CTX_init(). De nuevo, el conjunto y los certificados contenidos en él no se copian y sus recuentos de referencia no se incrementan.

X509_STORE_CTX_get0_untrusted() recupera el puntero interno al conjunto de certificados adicionales y no confiables asociados con ctx, es decir, el último establecido mediante X509_STORE_CTX_init(), X509_STORE_CTX_set_chain(), o X509_STORE_CTX_set0_untrusted().

X509_STORE_CTX_set0_crls() establece un conjunto de crls para usar durante la verificación del certificado. Estas CRL solo se utilizarán si la verificación de CRL está habilitada en la estructura X509_VERIFY_PARAM asociada. Esto podría utilizarse donde se proporcionan CRL "útiles" adicionales como parte de un protocolo, por ejemplo, en una estructura PKCS#7.

DESCRIPTION

The function X509_STORE_CTX_new() crea y devuelve un nuevo X509_STORE_CTX. Este contexto se utiliza para almacenar la información necesaria para verificar una cadena de certificados X.509. La memoria asociada con el contexto debe ser liberada usando X509_STORE_CTX_free().

La función X509_STORE_CTX_init() inicializa un X509_STORE_CTX. Los argumentos son:

  • ctx: el contexto a inicializar.
  • store: el almacén de certificados de confianza. Este argumento puede ser NULL.
  • cert: el certificado que se va a verificar. Este argumento puede ser NULL.
  • chain: una pila de certificados intermedios que forman la cadena de certificados. Este argumento puede ser NULL.

Después de usar el contexto, se debe llamar a X509_STORE_CTX_cleanup() para liberar cualquier recurso asociado, pero no la propia estructura X509_STORE_CTX. Si se creó el contexto con X509_STORE_CTX_new(), debe ser liberado con X509_STORE_CTX_free().

Este es el modo de uso antiguo:

X509_STORE_CTX ctx;
X509_STORE_CTX_init(&ctx, store, cert, chain);

Esto no se recomienda en nuevas aplicaciones. En su lugar, deberían hacer:

X509_STORE_CTX *ctx;
ctx = X509_STORE_CTX_new();
if (ctx == NULL)
	/* Error grave */
X509_STORE_CTX_init(ctx, store, cert, chain);

RETURN VALUES

X509_STORE_CTX_new() devuelve un contexto recién asignado o NULL si ocurrió un error.

X509_STORE_CTX_init() devuelve 1 si tiene éxito o 0 si ocurrió un error.

X509_STORE_CTX_get0_store() devuelve el puntero interno al almacén de certificados de confianza o NULL si no se estableció ninguno.

X509_STORE_CTX_get0_cert() devuelve el puntero interno al certificado que se va a verificar o NULL si no se estableció ningún certificado de este tipo.

X509_STORE_CTX_get0_untrusted() devuelve el puntero interno al conjunto de certificados adicionales no confiables o NULL si no se proporcionó ningún conjunto de certificados adicionales.
