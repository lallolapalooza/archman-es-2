PKCS7_VERIFY(3) Manual de Funciones de Biblioteca PKCS7_VERIFY(3)

NOMBRE

PKCS7_verify, PKCS7_get0_signers — verificar una estructura PKCS#7 signedData

SINOPSIS

biblioteca “libcrypto”
#include <openssl/pkcs7.h>

int
PKCS7_verify(PKCS7 *p7, STACK_OF(X509) *certs, X509_STORE *store, BIO *indata, BIO *out, int flags);

STACK_OF(X509) *
PKCS7_get0_signers(PKCS7 *p7, STACK_OF(X509) *certs, int flags);

DESCRIPCIÓN

PKCS7_verify() verifica una estructura PKCS#7 signedData. p7 es la estructura PKCS7 a verificar. certs es un conjunto de certificados en el cual buscar el certificado del firmante. store es un almacén de certificados confiables (utilizado para la verificación de la cadena). indata son los datos firmados si el contenido no está presente en p7, es decir, si está separado. El contenido se escribe en out si no es NULL.

flags es un conjunto opcional de flags, que pueden ser utilizados para modificar la operación de verificación.

PKCS7_get0_signers() recupera los certificados de los firmantes de p7. Los firmantes deben ser liberados con sk_X509_free(). No verifica su validez o si alguna firma es válida. Los parámetros certs y flags tienen los mismos significados que en PKCS7_verify().

Normalmente el proceso de verificación procede de la siguiente manera.

Inicialmente se realizan algunas comprobaciones de cordura en p7. El tipo de p7 debe ser signedData. Debe haber al menos una firma en los datos y si el contenido está separado, indata no puede ser NULL.

Se intenta localizar todos los certificados de los firmantes, buscando primero en el parámetro certs (si no es NULL) y luego buscando en cualquier certificado contenido en la propia estructura p7. Si no se pueden localizar los certificados de algún firmante, la operación falla.

Cada certificado de firmante se verifica mediante la cadena utilizando el propósito smimesign y el almacén de certificados confiables proporcionado. Cualquier certificado interno en el mensaje se utiliza como CA no confiable. Si falla alguna verificación de cadena, se devuelve un código de error.

Finalmente, se lee el contenido firmado (y se escribe en out si no es NULL) y se comprueban las firmas.

Si todas las firmas se verifican correctamente, la función es exitosa.

Cualquiera de los siguientes flags (OR'ed juntos) se puede pasar en el parámetro flags para cambiar el comportamiento de verificación predeterminado. Solo el flag PKCS7_NOINTERN es significativo para PKCS7_get0_signers().

Si se establece PKCS7_NOINTERN, no se buscan los certificados en el propio mensaje al localizar el certificado del firmante. Esto significa que todos los certificados del firmante deben estar en el parámetro certs.

Si se establece el flag PKCS7_TEXT, se eliminan las cabeceras MIME para el tipo text/plain del contenido. Si el contenido no es de tipo text/plain, se devuelve un error.

Si se establece PKCS7_NOVERIFY, los certificados del firmante no se verifican mediante la cadena.

Si se establece PKCS7_NOCHAIN, entonces los certificados contenidos en el mensaje no se utilizan como CA no confiables. Esto significa que toda la cadena de verificación (aparte del certificado del firmante) debe estar contenida en el almacén confiable.

Si se establece PKCS7_NOSIGS, entonces las firmas en los datos no se verifican.

Una aplicación de PKCS7_NOINTERN es aceptar solo mensajes firmados por un pequeño número de certificados. Los certificados aceptables se pasarían en el parámetro certs. En este caso, si el firmante no es uno de los certificados proporcionados en certs, la verificación fallará porque el firmante no puede ser encontrado.

Se debe tener cuidado al modificar el comportamiento de verificación predeterminado, por ejemplo, establecer PKCS7_NOVERIFY | PKCS7_NOSIGS deshabilitará completamente toda la verificación y cualquier mensaje firmado se considerará válido. Sin embargo, esta combinación es útil si uno simplemente desea escribir el contenido en out y su validez no es importante.

Se argumentaría que la verificación de la cadena debería realizarse utilizando la hora de la firma en lugar de la hora actual. Sin embargo, dado que la hora de la firma es proporcionada por el firmante, no se puede confiar en ella sin evidencia adicional (como una marca de tiempo confiable).

VALORES DE RETORNO

PKCS7_verify() devuelve 1 para una verificación exitosa y 0 o un valor negativo si ocurre un error.

PKCS7_get0_signers() devuelve todos los firmantes o NULL si ocurrió un error. Los firmantes deben ser liberados con sk_X509_free().

El error se puede obtener de ERR_get_error(3).

VER TAMBIÉN

PKCS7_decrypt(3), PKCS7_new(3), PKCS7_sign(3), X509_STORE_new(3)

HISTORIA

PKCS7_verify() y PKCS7_get0_signers() aparecieron por primera vez en OpenSSL 0.9.5 y han estado disponibles desde OpenBSD 2.7.

ERRORES

El almacén de certificados confiables no se busca para el certificado del firmante. Esto se debe principalmente a las deficiencias de la funcionalidad actual de X509_STORE.

La falta de procesamiento de una sola pasada y la necesidad de mantener todos los datos en memoria como se menciona en PKCS7_sign(3) también se aplica a PKCS7_verify().

NAME

PKCS7_verify - PKCS#7 data verification

SYNOPSIS

#include <openssl/pkcs7.h>
                int PKCS7_verify(PKCS7 *p7, STACK_OF(X509) *certs, X509_STORE *store,
                BIO *in, BIO *out, int flags);

DESCRIPTION

The PKCS7_verify() function verifies a PKCS#7 signed-data structure. It checks the signatures and certificates in the structure. The certs parameter is a stack of certificates to be used for verification. The store parameter is an X509_STORE to be used for certificate chain validation. The in parameter is a BIO for the signed data. The out parameter is a BIO to write the verified data to. The flags parameter can be used to control the verification process.

RETURN VALUES

The function returns 1 on success, and 0 or a negative value on failure.

SEE ALSO

PKCS7_sign(3), X509_STORE_new(3), BIO_new_file(3)

HISTORY

This function first appeared in OpenSSL 0.9.3.
