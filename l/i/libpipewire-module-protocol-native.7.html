NOMBRE

libpipewire-module-protocol-native - Protocolo Nativo

DESCRIPCIÓN

El módulo de protocolo nativo implementa la comunicación PipeWire entre un cliente y un servidor utilizando sockets locales de Unix.

Normalmente, este módulo se carga en los archivos de configuración del cliente y del servidor para que puedan comunicarse.

NOMBRE DEL MÓDULO

libpipewire-module-protocol-native

OPCIONES DEL MÓDULO

El módulo admite los siguientes argumentos:

•
sockets: [ { name = "nombre-socket", owner = "propietario", group = "grupo", mode = "modo", selinux.context = "contexto" }, props = { ... }, ... ]

Matriz de nombres de sockets de Unix y (opcionalmente) propietario/permisos a servir, si el contexto es un servidor. Si no son rutas absolutas, los sockets se crean en el directorio de ejecución predeterminado.

Las props se copian directamente a cualquier cliente que se conecte a través de este socket del servidor y se pueden usar para configurar permisos especiales.

Tiene el valor predeterminado [ { name = "CORENAME" }, { name = "CORENAME-manager" } ], donde CORENAME es el nombre del núcleo PipeWire, generalmente pipewire-0.

Los permisos no tienen ningún efecto para los sockets de activación de socket de Systemd. Estos deben configurarse a través del mecanismo systemd.socket(5).

OPCIONES GENERALES

El nombre del núcleo se obtiene de la siguiente manera:

  • PIPEWIRE_CORE : la variable de entorno con el nombre del núcleo
  • core.name : en las propiedades del contexto
  • un nombre basado en el ID del proceso

El contexto también se convertirá en un servidor si:

  • PIPEWIRE_DAEMON : la variable de entorno es true
  • core.daemon : en las propiedades del contexto es true

El socket se ubicará en el directorio obtenido buscando en las siguientes variables de entorno:

  • PIPEWIRE_RUNTIME_DIR
  • XDG_RUNTIME_DIR
  • USERPROFILE

La dirección del socket se escribirá en el descriptor de archivo de notificación si se establece la siguiente variable de entorno:

•
PIPEWIRE_NOTIFICATION_FD

Cuando un cliente se conecte, la conexión se realizará a:

  • PIPEWIRE_REMOTE : la variable de entorno con el nombre remoto
  • remote.name : la propiedad en el contexto.
  • El nombre remoto predeterminado "pipewire-0"

Se puede utilizar un nombre remoto especial "internal" para establecer una conexión con el contexto local. Esto se puede hacer incluso cuando el servidor no es un demonio. Se puede usar para tratar un contexto local como si fuera un servidor.

SOBREESCRITURA DE CONFIGURACIÓN

Se puede añadir una sección de configuración module.protocol-native.args para anular los argumentos del módulo.

# ~/.config/pipewire/pipewire.conf.d/my-protocol-native-args.conf
module.protocol-native.args = {
       sockets = [
           { name = "pipewire-0" }
           { name = "pipewire-0-manager" }
       ]
}

EJEMPLO DE CONFIGURACIÓN

context.modules = [
{ name = libpipewire-module-protocol-native }
]
context.modules = [
 { name = libpipewire-module-protocol-native,
   args = {
       sockets = [
           { name = "pipewire-0" }
           { name = "pipewire-0-manager" }
           { name = "pipewire-1"
             props = { my.connection = "la otra" }
           }
       ]
   }
 }
]
