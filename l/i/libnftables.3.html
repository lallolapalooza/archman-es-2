NOMBRE

libnftables - biblioteca de interfaz de nftables

SINOPSIS

#include <nftables/libnftables.h>

unsigned int nft_ctx_input_get_flags(struct nft_ctx *ctx);
unsigned int nft_ctx_input_set_flags(struct nft_ctx *ctx, unsigned int flags);
unsigned int nft_ctx_output_get_flags(struct nft_ctx *ctx);
void nft_ctx_output_set_flags(struct nft_ctx *ctx, unsigned int flags);

Enlazar con -lnftables.

DESCRIPCIÓN

Esta biblioteca fue diseñada pensando en la integración de nftables en aplicaciones. Su API se mantiene lo más simple posible, lo que limita algo su flexibilidad. Sin embargo, debido al soporte para marcado JSON de entrada y salida, se puede lograr comodidad en la construcción y análisis de datos de entrada y salida utilizando una biblioteca de terceros como libjansson.

En el nivel más básico, es necesario asignar un nuevo objeto de tipo struct nft_ctx utilizando la función nft_ctx_new(), luego pasar comandos a través de las funciones nft_run_cmd_from_buffer() o nft_run_cmd_from_filename(). Por defecto, cualquier salida se escribe en stdout (o stderr para mensajes de error). Estos punteros de archivo pueden modificarse utilizando las funciones nft_ctx_set_output() y nft_ctx_set_error(). Además, es posible que la salida sea almacenada en búfer por la biblioteca para su posterior recuperación como un búfer estático. Consulte las funciones nft_ctx_buffer_output() y nft_ctx_buffer_error() para más detalles.

nft_ctx_new() y nft_ctx_free()

Estas funciones ayudan en la gestión del contexto de nft. Para hacer uso de la biblioteca, se debe asignar al menos un objeto de contexto. El contexto contiene datos temporales como cachés, configuración de la biblioteca y (si está habilitado) búferes de salida y error.

La función nft_ctx_new() asigna y devuelve un nuevo objeto de contexto. El parámetro flags no se utiliza en este momento y debe establecerse a cero. Para mayor comodidad, se define la macro NFT_CTX_DEFAULT con ese valor.

La función nft_ctx_free() libera el objeto de contexto apuntado por ctx, incluyendo cualquier caché o búfer que pueda contener.

nft_ctx_get_dry_run() y nft_ctx_set_dry_run()

La configuración de ejecución en seco (dry-run) controla si los cambios en el conjunto de reglas se aplican realmente en el lado del kernel o no. Permite verificar si una operación dada tendría éxito sin realizar cambios reales en el conjunto de reglas. La configuración predeterminada es false.

La función nft_ctx_get_dry_run() devuelve el valor de la configuración de ejecución en seco contenido en ctx.

La función nft_ctx_set_dry_run() establece la configuración de ejecución en seco en ctx al valor de dry.

nft_ctx_input_get_flags() y nft_ctx_input_set_flags()

La configuración de banderas controla el formato de entrada.

enum {
        NFT_CTX_INPUT_NO_DNS = (1 << 0),
        NFT_CTX_INPUT_JSON   = (1 << 1),
};

NFT_CTX_INPUT_NO_DNS

Evita resolver direcciones IP con una llamada bloqueante a getaddrinfo(). En ese caso, solo se aceptan direcciones IP simples.

NFT_CTX_INPUT_JSON: Al analizar la entrada, primero intente interpretar la entrada como JSON antes de recurrir al formato nftables. Este comportamiento se implica al establecer la bandera NFT_CTX_OUTPUT_JSON.

La función nft_ctx_input_get_flags() devuelve el valor de la configuración de banderas de entrada en ctx.

La función nft_ctx_input_set_flags() establece la configuración de banderas de entrada en ctx al valor de val y devuelve las banderas anteriores.

nft_ctx_output_get_flags() y nft_ctx_output_set_flags()

La configuración de banderas controla el formato de salida.

enum {
        NFT_CTX_OUTPUT_REVERSEDNS     = (1 << 0),
        NFT_CTX_OUTPUT_SERVICE        = (1 << 1),
        NFT_CTX_OUTPUT_STATELESS      = (1 << 2),
        NFT_CTX_OUTPUT_HANDLE         = (1 << 3),
        NFT_CTX_OUTPUT_JSON           = (1 << 4),
        NFT_CTX_OUTPUT_ECHO           = (1 << 5),
        NFT_CTX_OUTPUT_GUID           = (1 << 6),
        NFT_CTX_OUTPUT_NUMERIC_PROTO  = (1 << 7),
        NFT_CTX_OUTPUT_NUMERIC_PRIO   = (1 << 8),
        NFT_CTX_OUTPUT_NUMERIC_SYMBOL = (1 << 9),
        NFT_CTX_OUTPUT_NUMERIC_TIME   = (1 << 10),
        NFT_CTX_OUTPUT_NUMERIC_ALL    = (NFT_CTX_OUTPUT_NUMERIC_PROTO |
                                         NFT_CTX_OUTPUT_NUMERIC_PRIO  |
                                         NFT_CTX_OUTPUT_NUMERIC_SYMBOL |
                                         NFT_CTX_OUTPUT_NUMERIC_TIME),
        NFT_CTX_OUTPUT_TERSE          = (1 << 11),
};

NFT_CTX_OUTPUT_REVERSEDNS

Se realizan búsquedas inversas de DNS para direcciones IP al imprimir. Tenga en cuenta que esto puede agregar un retraso significativo a los comandos list dependiendo de la velocidad del resolvedor DNS.

NFT_CTX_OUTPUT_SERVICE

Imprime números de puerto como servicios según se describe en el archivo /etc/services.

NFT_CTX_OUTPUT_STATELESS

Si se ha solicitado salida sin estado (stateless), los datos con estado (stateful) no se imprimirán. Los datos con estado se refieren a aquellos objetos que transportan datos en tiempo de ejecución, por ejemplo, la sentencia counter contiene valores de contador de paquetes y bytes, lo que la hace con estado.

NFT_CTX_OUTPUT_HANDLE

Al insertar en el conjunto de reglas, a algunos elementos se les asigna un identificador único para fines de identificación. Por ejemplo, al eliminar una tabla o cadena, puede identificarse por nombre o por su identificador. Las reglas deben eliminarse por identificador, ya que no hay otra manera de identificarlas de forma única. Esta bandera hace que las listas del conjunto de reglas incluyan los valores de identificador.

NFT_CTX_OUTPUT_JSON

Si está habilitado en tiempo de compilación, libnftables acepta entrada en formato JSON y también puede imprimir salida en formato JSON. Consulte libnftables-json(5) para una descripción del esquema soportado. Esta bandera habilita el formato de salida JSON. Si la bandera está establecida, primero se intentará analizar la entrada como formato JSON, antes de recurrir al formato nftables. Esta bandera implica NFT_CTX_INPUT_JSON.

NFT_CTX_OUTPUT_ECHO

La configuración de eco hace que libnftables imprima los cambios una vez que se aplican al kernel, al igual que lo haría una instancia en ejecución de nft monitor. Entre otras cosas, esto permite recuperar el identificador de una regla añadida de forma atómica.

NFT_CTX_OUTPUT_GUID

Muestra UID y GID como se describe en los archivos /etc/passwd y /etc/group.

NFT_CTX_OUTPUT_NUMERIC_PR

OTO

Muestra el protocolo de capa 4 numéricamente.

NFT_CTX_OUTPUT_NUMERIC_PRIO

Muestra la prioridad de la cadena base numéricamente.

NFT_CTX_OUTPUT_NUMERIC_SYMBOL

Muestra el tipo de dato de la expresión como valor numérico.

NFT_CTX_OUTPUT_NUMERIC_TIME

Muestra los valores de hora, día y hora en formato numérico.

NFT_CTX_OUTPUT_NUMERIC_ALL

Muestra todo numéricamente.

NFT_CTX_OUTPUT_TERSE

Si se solicitó una salida concisa, entonces no se imprimen los contenidos de los conjuntos.

La función nft_ctx_output_get_flags() devuelve el valor de la configuración de las banderas de salida en ctx.

La función nft_ctx_output_set_flags() establece la configuración de las banderas de salida en ctx al valor de val.

nft_ctx_output_get_debug() y nft_ctx_output_set_debug()

Libnftables soporta la depuración separada de diferentes partes de su funcionamiento interno. Para facilitar esto, la salida de depuración se controla mediante una máscara de bits. Los bits se definen de la siguiente manera:

enum nft_debug_level {
        NFT_DEBUG_SCANNER               = 0x1,
        NFT_DEBUG_PARSER                = 0x2,
        NFT_DEBUG_EVALUATION            = 0x4,
        NFT_DEBUG_NETLINK               = 0x8,
        NFT_DEBUG_MNL                   = 0x10,
        NFT_DEBUG_PROTO_CTX             = 0x20,
        NFT_DEBUG_SEGTREE               = 0x40,
};

NFT_DEBUG_SCANNER

Imprime la salida de depuración LEX.

NFT_DEBUG_PARSER

Imprime la salida de depuración YACC.

NFT_DEBUG_EVALUATION

Imprime información de depuración sobre la fase de evaluación.

NFT_DEBUG_NETLINK

Imprime la salida de depuración netlink.

NFT_DEBUG_MNL

Imprime la salida de depuración libmnl.

NFT_DEBUG_PROTO_CTX

Imprime la salida de depuración del contexto del protocolo.

NFT_DEBUG_SEGTREE

Imprime la salida de depuración segtree (es decir, conjuntos de intervalos).

La función nft_ctx_output_get_debug() devuelve el valor de la configuración de salida de depuración en ctx.

La función nft_ctx_output_set_debug() establece la configuración de salida de depuración en ctx al valor de mask.

Control de la salida estándar y de errores de la biblioteca

Por defecto, cualquier salida de la biblioteca (por ejemplo, después de un comando list) se escribe en stdout y cualquier mensaje de error se escribe en stderr. Para dar a las aplicaciones control sobre ellos, existen funciones para asignar punteros de archivo personalizados, así como para que la biblioteca almacene en búfer lo que se escribiría para su posterior recuperación en un búfer estático. Se garantiza que este búfer termina en nulo y no debe liberarse. Tenga en cuenta que las funciones de recuperación rebobinan el indicador de posición del búfer. La salida adicional de la biblioteca probablemente sobrescribirá el contenido del búfer y potencialmente lo invalidará (debido a la realocación).

Las funciones nft_ctx_set_output() y nft_ctx_set_error() establecen el puntero de archivo de salida o error en ctx al valor de fp. Devuelven el valor anterior para ayudar en las anulaciones temporales del puntero de archivo. En caso de error, estas funciones devuelven NULL. Esto solo ocurre si fp es NULL o inválido (probado con la función ferror()).

Las funciones nft_ctx_buffer_output() y nft_ctx_buffer_error() habilitan el almacenamiento en búfer de la salida estándar o de errores de la biblioteca. Las funciones devuelven cero si tienen éxito, y un valor distinto de cero en caso contrario. Esto puede ocurrir si la llamada interna a fopencookie() falló.

Las funciones nft_ctx_unbuffer_output() y nft_ctx_unbuffer_error() deshabilitan el almacenamiento en búfer de la salida estándar o de errores de la biblioteca. En caso de fallo, las funciones devuelven un valor distinto de cero, lo que solo puede ocurrir si el almacenamiento en búfer no estaba habilitado en el momento en que se llamó a la función.

Las funciones nft_ctx_get_output_buffer() y nft_ctx_get_error_buffer() devuelven un puntero a la salida almacenada en búfer (que puede estar vacía).

nft_ctx_add_include_path() y nft_ctx_clear_include_path()

El comando include en las reglas de nftables permite externalizar partes del conjunto de reglas en un archivo diferente. La ruta de inclusión define dónde se buscan estos archivos. Libnftables permite tener una lista de estas rutas que se buscan en orden. La lista de rutas de inclusión predeterminada contiene una única entrada definida en tiempo de compilación (típicamente /etc/).

La función nft_ctx_add_include_path() extiende la lista de rutas de inclusión en ctx con la proporcionada en path. La función devuelve cero si tiene éxito o un valor distinto de cero si la asignación de memoria falló.

La función nft_ctx_clear_include_paths() elimina todas las rutas de inclusión, incluso la predeterminada incorporada.

nft_ctx_add_var() y nft_ctx_clear_vars()

El comando define en el conjunto de reglas de nftables permite definir variables.

La función nft_ctx_add_var() extiende la lista de variables en ctx. La variable debe proporcionarse en el formato clave=valor. La función devuelve cero si tiene éxito o un valor distinto de cero si la variable está mal formada.

La función nft_ctx_clear_vars() elimina todas las variables.

nft_run_cmd_from_buffer() y nft_run_cmd_from_filename()

Estas funciones realizan el trabajo real de analizar la entrada del usuario en comandos de nftables y ejecutarlos.

La función nft_run_cmd_from_buffer() pasa el comando o comandos contenidos en buf (que debe terminar en nulo) a la biblioteca, respetando la configuración y el estado en nft.

La función nft_run_cmd_from_filename() pasa el contenido de filename a la biblioteca, respetando la configuración y el estado en nft.

Ambas funciones devuelven cero si tienen éxito. Un código de retorno distinto de cero indica un error durante el análisis o la ejecución del comando. Este evento debe ir acompañado de un mensaje de error escrito en la salida de error de la biblioteca.

EJEMPLO

#include <stdio.h>
#include <string.h>
#include <nftables/libnftables.h>
int main(void)
{
        char *list_cmd = "list ruleset";
        struct nft_ctx *nft;
        const char *output, *p;
        char buf[256];
        int rc = 0;
        nft = nft_ctx_new(NFT_CTX_DEFAULT);
        if (!nft)
                return 1;
        while (1) {
                if (nft_ctx_buffer_output(nft) ||
                    nft_run_cmd_from_buffer(nft, list_cmd)) {
                        rc = 1;
                        break;
                }
                output = nft_ctx_get_output_buffer(nft);
                if (strlen(output)) {
                        printf("\nEste es el conjunto de reglas actual:\n| ");
                        for (p = output; *(p + 1); p++) {
                                if (*p == '\n')
                                        printf("\n| ");
                                else
                                        putchar(*p);
                        }
                        putchar('\n');
                } else {
                        printf("\nEl conjunto de reglas actual está vacío.\n");
                }
                nft_ctx_unbuffer_output(nft);
                printf("\nIntroduce comando ('q' para salir): ");
                fflush(stdout);
                fgets(buf, 256, stdin);
                if (strlen(buf))
                        buf[strlen(buf) - 1] = '\0';
                if (buf[0] == 'q' && buf[1] == '\0')
                        break;
                if (nft_run_cmd_from_buffer(nft, buf)) {
                        rc = 1;
                        break;
                }
        }
        nft_ctx_free(nft);
        return rc;
}
