Nombre

libvirt-guests - suspender/reanudar invitados libvirt en ejecución

SINOPSIS

libvirt-guests COMANDO

DESCRIPCIÓN

libvirt-guests es un servicio que se puede utilizar para coordinar acciones del ciclo de vida del invitado y del host. Por defecto, libvirt-guests suspenderá los invitados en ejecución cuando el host se apague, y los restaurará a su estado previo al apagado cuando el host se reinicie.

libvirt-guests suele estar bajo el control de systemd. Cuando libvirt-guests.service está habilitado, systemd llamará a libvirt-guests con el COMANDO start al arrancar el host. A la inversa, systemd llamará a libvirt-guests con el COMANDO stop al apagar el host.

libvirt-guests se puede usar directamente. Además de los COMANDOS start y stop, también soporta los comandos status, restart, condrestart, try-restart, reload, force-reload, gueststatus y shutdown.

ARCHIVOS

libvirt-guests define varias variables para controlar el comportamiento del servicio. El valor por defecto de estas variables se puede sobrescribir en:

•
/etc/conf.d/libvirt-guests

Las siguientes variables son compatibles:

  • URIS=default

    URIs para comprobar si hay invitados en ejecución. Ejemplo: URIS='default xen:///system xen+tcp://host/system lxc:///system'

  • ON_BOOT=start

    Acción que se toma al arrancar el host

  • start

    Todos los invitados que estaban en ejecución al apagar se inician al arrancar, independientemente de su configuración de inicio automático.

  • ignore

    libvirt-guests no iniciará ningún invitado al arrancar, sin embargo, los invitados marcados para inicio automático seguirán siendo iniciados automáticamente por libvirtd.

  • START_DELAY=0

    Número de segundos de espera entre el inicio de cada invitado. Establecer a 0 para permitir el inicio paralelo.

  • ON_SHUTDOWN=suspend

    Acción que se toma al apagar el host

  • suspend

    Todos los invitados en ejecución se suspenden usando virsh managedsave.

  • shutdown

    Se solicita a todos los invitados en ejecución que se apaguen. Tenga cuidado con esta configuración, ya que no hay forma de distinguir entre un invitado que está atascado o ignora las solicitudes de apagado y un invitado que simplemente necesita mucho tiempo para apagarse. Al configurar ON_SHUTDOWN=shutdown, también debe configurar SHUTDOWN_TIMEOUT a un valor adecuado para sus invitados.

  • PARALLEL_SHUTDOWN=0

    Número de invitados que se apagarán simultáneamente, surtiendo efecto cuando "ON_SHUTDOWN" se establece en "shutdown". Si se establece en 0, los invitados se apagarán uno tras otro. El número de invitados que se apagarán en cualquier momento no excederá el número establecido en esta variable.

  • SHUTDOWN_TIMEOUT=300

    Número de segundos que estamos dispuestos a esperar a que un invitado se apague. Si el apagado paralelo está habilitado, este tiempo de espera se aplica como un tiempo de espera para apagar todos los invitados en una URI definida en la variable URIS. Si esto es 0, entonces no hay tiempo de espera (use con precaución, ya que los invitados podrían no responder a una solicitud de apagado). El valor por defecto es 300 segundos (5 minutos).

  • BYPASS_CACHE=0

    Si es distinto de cero, intente omitir la caché del sistema de archivos al guardar y restaurar invitados, aunque esto puede dar como resultado una operación más lenta para algunos sistemas de archivos.

  • SYNC_TIME=0

    Si es distinto de cero, intente sincronizar la hora del invitado al reanudar el dominio. Tenga en cuenta que esto requiere un agente de invitado con soporte para la sincronización de hora en ejecución dentro del invitado. Por defecto, esta funcionalidad está desactivada.

  • PERSISTENT_ONLY=default

    Define a qué tipo de máquina virtual invitada se aplica la acción ON_SHUTDOWN.

  • default

    Esto implementa el comportamiento por defecto ya existente. Si la acción ON_SHUTDOWN es shutdown, se solicita a las máquinas virtuales invitadas transitorias y persistentes que se apaguen. Si la acción ON_SHUTDOWN es suspend, solo se solicita a las máquinas virtuales invitadas persistentes que se suspendan.

  • true

    La acción ON_SHUTDOWN se ejecuta solo en máquinas virtuales invitadas persistentes. Las máquinas virtuales invitadas transitorias no se ven afectadas.

  • false

    La acción ON_SHUTDOWN se ejecuta en máquinas virtuales invitadas persistentes y transitorias.
