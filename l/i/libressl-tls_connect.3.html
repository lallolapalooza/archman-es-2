libressl-tls_connect(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

TLS_CONNECT(3) Manual de Funciones de Biblioteca TLS_CONNECT(3)

NOMBRE

tls_connect, tls_connect_fds, tls_connect_servername, tls_connect_socket, tls_connect_cbs — instruye a un cliente TLS para que establezca una conexión

SINOPSIS

biblioteca “libtls” libssl libcrypto
#include <tls.h>

int
tls_connect(struct tls *ctx, const char *host, const char *port);

int
tls_connect_fds(struct tls *ctx, int fd_read, int fd_write, const char *servername);

int
tls_connect_servername(struct tls *ctx, const char *host, const char *port, const char *servername);

int
tls_connect_socket(struct tls *ctx, int s, const char *servername);

int
tls_connect_cbs(struct tls *ctx, ssize_t (*tls_read_cb)(struct tls *ctx, void *buf, size_t buflen, void *cb_arg), ssize_t (*tls_write_cb)(struct tls *ctx, const void *buf, size_t buflen, void *cb_arg), void *cb_arg, const char *servername);

DESCRIPCIÓN

Después de crear un contexto de cliente TLS con tls_client(3) y configurarlo con tls_configure(3), se inicia una conexión de cliente llamando a tls_connect(). Esta función creará un nuevo socket, se conectará al host y puerto especificados, y luego establecerá una conexión segura. El puerto puede ser numérico o un nombre de servicio. Si es NULL, se permite un host con el formato "nombrehost:puerto". El nombre a usar para la verificación se infiere del valor de host.

La función tls_connect_servername() tiene el mismo comportamiento, sin embargo, el nombre a usar para la verificación se proporciona explícitamente, para el caso en que el nombre del servidor TLS difiera del nombre DNS.

Se puede actualizar un socket ya existente a una conexión segura llamando a tls_connect_socket().

Alternativamente, se puede establecer una conexión segura sobre un par de descriptores de archivo existentes llamando a tls_connect_fds().

Llamar a tls_connect_cbs() permite que las funciones de devolución de llamada de lectura y escritura gestionen las transferencias de datos. El parámetro cb_arg especificado se vuelve a pasar a las funciones y puede contener un puntero a cualquier dato especificado por el llamante.

VALORES DE RETORNO

Estas funciones devuelven 0 en caso de éxito o -1 en caso de error.

VER TAMBIÉN

tls_accept_socket(3), tls_client(3), tls_close(3), tls_config_ocsp_require_stapling(3), tls_configure(3), tls_handshake(3), tls_init(3)

HISTORIA

tls_connect() y tls_connect_socket() aparecieron en OpenBSD 5.6 y recibieron sus nombres finales en OpenBSD 5.7.

tls_connect_fds() y tls_connect_servername() aparecieron en OpenBSD 5.7 y tls_connect_cbs() en OpenBSD 6.1.
