libressl-SSL_CTX_set_security_level(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_CTX_SET_SECURITY_LEVEL(3) Manual de funciones de biblioteca SSL_CTX_SET_SECURITY_LEVEL(3)

NOMBRE

SSL_CTX_set_security_level, SSL_set_security_level, SSL_CTX_get_security_level, SSL_get_security_level — cambiar el nivel de seguridad para TLS

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

void
SSL_CTX_set_security_level(SSL_CTX *ctx, int level);

void
SSL_set_security_level(SSL *s, int level);

int
SSL_CTX_get_security_level(const SSL_CTX *ctx);

int
SSL_get_security_level(const SSL *s);

DESCRIPCIÓN

Un nivel de seguridad es un conjunto de restricciones sobre algoritmos, longitudes de clave, versiones de protocolo y otras características en conexiones TLS. Estas restricciones se aplican además de las que existen al seleccionar individualmente características compatibles, por ejemplo, cifrados, curvas o algoritmos.

La siguiente tabla muestra las propiedades de los diversos niveles de seguridad:

# sec   RSA ECC TLS MAC
0   0     0   0 1.0 MD5
1  80  1024 160 1.0 RC4
2 112  2048 224 1.0
3 128  3072 256 1.1 SHA1
4 192  7680 384 1.2
5 256 15360 512 1.2

El significado de las columnas es el siguiente:

#
El número del nivel.
sec
La fuerza de seguridad mínima medida en bits, que es aproximadamente el logaritmo binario del número de operaciones que un atacante debe realizar para romper una clave criptográfica. Esta fuerza mínima se aplica a todos los parámetros relevantes, incluyendo algoritmos de cifrado de suites de cifrado, curvas ECC, algoritmos de firma, tamaños de parámetros DH y algoritmos y tamaños de clave de certificado. Véase SP800-57 más abajo VER TAMBIÉN para más detalles sobre algoritmos individuales.
RSA
La longitud de clave mínima en bits para los algoritmos RSA y DH.
ECC
La longitud de clave mínima en bits para los algoritmos ECC.
TLS
La versión mínima del protocolo TLS.
MAC
Las suites de cifrado que utilizan los MAC dados están permitidas en este nivel y en niveles inferiores, pero no en niveles superiores.

El nivel 0 es solo para compatibilidad hacia atrás y permite todo.

El nivel 3 y superiores deshabilitan el soporte para tickets de sesión y solo aceptan suites de cifrado que proporcionan secreto directo.

Las funciones SSL_CTX_set_security_level() y SSL_set_security_level() seleccionan el nivel de seguridad para ctx o s, respectivamente. Si no se establece, se utiliza el nivel de seguridad 1.

SSL_CTX_new(3) inicializa el nivel de seguridad del nuevo objeto a 1.

SSL_new(3) y SSL_set_SSL_CTX(3) copian el nivel de seguridad del contexto al objeto SSL.

SSL_dup(3) copia el nivel de seguridad del objeto antiguo al nuevo.

VALORES DE RETORNO

SSL_CTX_get_security_level() y SSL_get_security_level() devuelven el nivel de seguridad configurado en ctx o s, respectivamente.

VER TAMBIÉN

EVP_PKEY_security_bits(3), RSA_security_bits(3), ssl(3), SSL_CTX_new(3), SSL_new(3)

Elaine Barker, Recomendación para la gestión de claves, Instituto Nacional de Estándares y Tecnología de EE. UU., Publicación Especial NIST 800-57 Parte 1 Revisión 5, https://doi.org/10.6028/NIST.SP.800-57pt1r5, Gaithersburg, MD, Mayo 2020.

HISTORIA

Estas funciones aparecieron por primera vez en OpenSSL 1.1.0 y han estado disponibles desde OpenBSD 7.2.

ADVERTENCIAS

Las aplicaciones que no comprueban los valores de retorno de las funciones de configuración se comportarán de forma incorrecta. Por ejemplo, si una aplicación no comprueba el valor de retorno después de intentar establecer un certificado y el certificado es rechazado debido al nivel de seguridad, la aplicación puede comportarse como si no se hubiera proporcionado ningún certificado.

Si bien algunas restricciones pueden ser manejadas de forma efectiva mediante negociaciones entre el cliente y el servidor, otras restricciones pueden ser fatales y abortar el handshake TLS. Por ejemplo, esto puede ocurrir si el certificado del par contiene una clave demasiado corta o si el tamaño del parámetro DH es demasiado pequeño.
