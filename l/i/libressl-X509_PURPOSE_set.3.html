DESCRIPCIÓN

Los propósitos para los que se pretende utilizar un certificado X.509 pueden identificarse de tres maneras equivalentes:

  1. Mediante identificadores de propósito, que son constantes enteras positivas. Los identificadores de propósito estándar se encuentran en el rango de X509_PURPOSE_MIN a X509_PURPOSE_MAX, ambos inclusive, y se enumeran en la página del manual de X509_check_purpose(3). Los identificadores de propósito definidos por el usuario son mayores que X509_PURPOSE_MAX.
  2. Mediante índices de propósito, que son constantes enteras no negativas pero diferentes de los identificadores de propósito para el mismo propósito. Los índices de propósito estándar son menores que X509_PURPOSE_MAX. Los índices de propósito definidos por el usuario son mayores o iguales que X509_PURPOSE_MAX.
  3. Mediante objetos de propósito de tipo X509_PURPOSE. Los objetos de propósito estándar están disponibles en almacenamiento estático. Los objetos de propósito definidos por el usuario pueden crearse con X509_PURPOSE_add().

Los programadores de aplicaciones no pueden elegir la forma de identificar los propósitos que prefieren; dependiendo de las circunstancias, se necesitan las tres formas. Tenga en cuenta que los nombres de la mayoría de las funciones son engañosos.

La mayoría de las funciones de la API documentadas fuera de la presente página del manual utilizan identificadores de propósito en lugar de índices de propósito.

Uso de identificadores de propósito

X509_PURPOSE_set() valida el identificador de propósito id_in. Si es válido, se copia en *id_out. De lo contrario, *id_out permanece sin cambios.

X509_PURPOSE_get_by_id() convierte el identificador de propósito al índice de propósito correspondiente. Para encontrar el objeto de propósito correspondiente, pase el resultado a X509_PURPOSE_get0().

X509_PURPOSE_add() define un propósito con el identificador dado o modifica sus propiedades si ya existe. El identificador del propósito, el identificador trust, las flags, la función check_purpose, el name, el nombre corto sname y el puntero usr_data se copian en el objeto X509_PURPOSE. Al modificar un objeto de propósito existente, los valores anteriores de los campos se sobrescriben y las cadenas anteriores de name y sname se liberan si se asignaron dinámicamente. Al crear un nuevo objeto de propósito, se añade al array global de objetos de propósito definidos por el usuario.

X509_PURPOSE_DYNAMIC y X509_PURPOSE_DYNAMIC_NAME siempre se ignoran en el argumento flags. X509_PURPOSE_DYNAMIC se establece automáticamente si el objeto fue creado por el usuario. Nunca se establece para objetos estándar, ni siquiera si fueron modificados por el usuario. X509_PURPOSE_DYNAMIC_NAME se establece automáticamente si el objeto fue creado o modificado por el usuario. Solo se desactiva para objetos estándar no modificados. La biblioteca no parece definir ninguna otra bandera, por lo que el argumento flags es probablemente inútil a menos que los usuarios definan sus propias banderas y las usen en la función check_purpose.

El tercer y último argumento de la función check_purpose es el argumento ca documentado en X509_check_purpose(3).

X509_PURPOSE_get_count() devuelve el número total de propósitos actualmente definidos, incluyendo propósitos estándar y definidos por el usuario. Si no existen propósitos definidos por el usuario, el valor devuelto es X509_PURPOSE_MAX.

X509_PURPOSE_cleanup() elimina todos los objetos de propósito definidos por el usuario e invalida sus identificadores de propósito e índices de propósito. Si alguno de los objetos de propósito estándar fue modificado por el usuario, esos cambios no se revierten.

Uso de índices de propósito

X509_PURPOSE_get0() convierte un puntero a un índice de propósito al puntero al objeto de propósito correspondiente. Para encontrar el identificador de propósito correspondiente, pase el resultado a X509_PURPOSE_get_id().

X509_PURPOSE_get_by_sname() devuelve el índice más bajo de un propósito con el nombre corto dado.

DESCRIPTION

These functions are used to manage and query the list of certificate purposes that can be used during certificate verification. A certificate purpose defines a particular use for a certificate. For example, a certificate might be intended for signing other certificates, or for authenticating a client, or for authenticating a server.

Each purpose is associated with a numeric identifier and one or more human-readable names. It is also associated with a numeric trust value. The trust value is a bitmask specifying the level of trust for that purpose. The higher the value, the more trusted the purpose.

The following standard purposes are defined:

  • X509_PURPOSE_SSL_SERVER: Server authentication for SSL/TLS.
  • X509_PURPOSE_SSL_CLIENT: Client authentication for SSL/TLS.
  • X509_PURPOSE_EMAIL: Email signing or encryption.
  • X509_PURPOSE_CODE_SIGNING: Code signing.
  • X509_PURPOSE_OCSP_SIGN: Signing OCSP requests.
  • X509_PURPOSE_TIMESTAMP_SIGN: Timestamp signing.

The functions X509_PURPOSE_set(), X509_PURPOSE_get_id(), X509_PURPOSE_get_count(), X509_PURPOSE_get0(), X509_PURPOSE_add(), X509_PURPOSE_get_by_id(), and X509_PURPOSE_get_by_sname() manage the list of purposes.

X509_PURPOSE_set() associates the purpose identified by purpose with the trust value trust. The identifier id_in is used internally by OpenSSL, and should not be modified unless you know what you are doing.

X509_PURPOSE_get_id() returns the numeric identifier for the given purpose purpose.

X509_PURPOSE_get_count() returns the total number of purposes currently defined.

X509_PURPOSE_get0() returns a pointer to the purpose object at the given index. The index ranges from 0 to X509_PURPOSE_get_count() - 1.

X509_PURPOSE_add() adds a new purpose to the list. The id is the numeric identifier for the new purpose. id_in should be set to the same value as id. The name argument is a human-readable name for the purpose, and sname is a short, human-readable name. The trust argument is the trust value associated with the purpose. The flags and usr_data arguments are reserved for future use.

X509_PURPOSE_get_by_id() returns a pointer to the purpose object with the given numeric identifier id. This function can be used to look up the purpose object corresponding to a given identifier.

X509_PURPOSE_get_by_sname() returns a pointer to the purpose object with the given short name sname. This function can be used to look up the purpose object corresponding to a given short name.

The functions X509_PURPOSE_get0_name(), X509_PURPOSE_get0_sname(), and X509_PURPOSE_get_trust() retrieve the name, short name, and trust identifier from the object, respectively.

RETURN VALUES

X509_PURPOSE_set() returns 1 if id_in is valid or 0 otherwise.

X509_PURPOSE_get_by_id() and X509_PURPOSE_get_by_sname() return the corresponding purpose index or -1 if no matching purpose is found.

X509_PURPOSE_add() returns 1 for success or 0 for failure.

X509_PURPOSE_get_count() returns the total number of purposes currently defined.

X509_PURPOSE_get0() returns a standard or user-defined purpose object or NULL if the index is invalid.

X509_PURPOSE_get_id() always returns a valid purpose identifier.

X509_PURPOSE_get0_name() and X509_PURPOSE_get0_sname() return pointers to storage owned by the object.

X509_PURPOSE_get_trust() returns the trust identifier associated with the object.

ERRORS

The following diagnostics can be retrieved with ERR_get_error(3), ERR_GET_REASON(3), and ERR_reason_error_string(3):

X509V3_R_INVALID_PURPOSE "invalid purpose"
X509_PURPOSE_set() was called with an invalid id_in argument.
X509V3_R_INVALID_NULL_ARGUMENT "invalid null argument"
X509_PURPOSE_add() was called with a name or sname argument of NULL.
ERR_R_MALLOC_FAILURE "malloc failure"
X509_PURPOSE_add() failed to allocate memory.

The other functions provide no diagnostics.

HISTORY

X509_PURPOSE_set() first appeared in OpenSSL 0.9.7 and has been available since OpenBSD 3.2.

The other functions first appeared in OpenSSL 0.9.5 and have been available since OpenBSD 2.7.

CAVEATS

The difference between purpose identifiers and purpose indices provides an ideal breeding ground for off-by-one bugs.
