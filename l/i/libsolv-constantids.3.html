NOMBRE

libsolv-constantids - IDs fijos para cadenas de uso frecuente

DESCRIPCIÓN

Los IDs constantes son IDs de cadenas que se necesitan con frecuencia. Se definen para facilitar la programación y reducir el número de llamadas a `pool_str2id`. Los IDs constantes forman parte de la ABI binaria de libsolv; una actualización menor solo agregará nuevas constantes y no cambiará las existentes para mantener la compatibilidad. El formato solv en disco no usa los IDs fijos, sino que hace referencia a las cadenas, por lo que los archivos solv aún se pueden leer cuando la ABI se rompe.

CADENAS ESPECIALES

ID_EMPTY ""

La cadena vacía. Siempre tendrá el ID 1.

SYSTEM_SYSTEM "system:system"

El nombre del solvable "system" siempre instalado.

ATRIBUTOS DE SOLVABLE

Estos son los IDs para los nombres de clave de atributos. Se pueden usar en las funciones de búsqueda y almacenamiento para seleccionar el atributo correcto en el solvable. Las descripciones a continuación describen la semántica prevista de los valores almacenados en el atributo con el nombre de clave.

SOLVABLE_NAME "solvable:name"

El nombre del paquete.

SOLVABLE_ARCH "solvable:arch"

La arquitectura del paquete. Consulte la sección Arquitectura de Solvable para ver los valores de ID de arquitectura predefinidos.

SOLVABLE_EVR "solvable:evr"

La versión del paquete. Normalmente consta de una combinación del Epoch, la Versión y el Release del solvable.

SOLVABLE_VENDOR "solvable:vendor"

Una cadena de proveedor. Normalmente la empresa o grupo que creó el paquete binario.

SOLVABLE_PROVIDES "solvable:provides"

Almacena una matriz de IDs de dependencia que describen las capacidades que proporciona el paquete.

SOLVABLE_OBSOLETES "solvable:obsoletes"

Almacena una matriz de IDs de dependencia que describen los paquetes que este paquete reemplaza.

SOLVABLE_CONFLICTS "solvable:conflicts"

Almacena una matriz de IDs de dependencia que describen las capacidades con las que este paquete entra en conflicto, es decir, que no se pueden instalar junto con este paquete.

SOLVABLE_REQUIRES "solvable:requires"

Almacena una matriz de IDs de dependencia que describen las capacidades que también deben instalarse cuando se instala este paquete.

SOLVABLE_RECOMMENDS "solvable:recommends"

Almacena una matriz de IDs de dependencia que describen las capacidades que también deberían instalarse cuando se instala este paquete. No es un error si no se pueden cumplir todas las capacidades.

SOLVABLE_SUGGESTS "solvable:suggests"

Almacena una matriz de IDs de dependencia que describen las capacidades que también son útiles de tener instaladas cuando se instala este paquete. Esto está destinado a proporcionar una pista al usuario sobre otros paquetes.

SOLVABLE_SUPPLEMENTS "solvable:supplements"

Almacena una matriz de IDs de dependencia que definen que este paquete debe instalarse si se cumple una de las capacidades. Esto es similar al atributo recommends, pero funciona de manera inversa.

SOLVABLE_ENHANCES "solvable:enhances"

Almacena una matriz de IDs de dependencia que definen que este paquete es útil de tener instalado si se cumple una de las capacidades. Esto es similar al atributo suggests, pero funciona de manera inversa.

SOLVABLE_SUMMARY "solvable:summary"

El resumen debe ser una cadena corta sin saltos de línea que describa lo que hace un paquete.

SOLVABLE_DESCRIPTION "solvable:description"

La descripción debe ser una descripción más detallada de lo que hace un paquete. Puede constar de varias líneas.

SOLVABLE_DISTRIBUTION "solvable:distribution"

La distribución es una cadena corta que describe el sistema operativo y la versión del SO para los que se compila este paquete.

SOLVABLE_AUTHORS "solvable:authors"

Una lista de autores de este paquete. Este atributo se usó en los paquetes de SUSE.

SOLVABLE_PACKAGER "solvable:packager"

La persona que creó el paquete binario; consulte también el atributo vendor.

SOLVABLE_GROUP "solvable:group"

El grupo de paquetes al que pertenece este paquete. Consulte también el atributo keywords.

SOLVABLE_URL "solvable:url"

Una URL que apunta a más información sobre el paquete.

SOLVABLE_KEYWORDS "solvable:keywords"

Lista de IDs de cadenas clave utilizadas para etiquetar este paquete.

SOLVABLE_LICENSE "solvable:license"

La(s) licencia(s) de este paquete.

SOLVABLE_BUILDTIME "solvable:buildtime"

Los segundos transcurridos desde la época Unix en que se creó el paquete binario.

SOLVABLE_BUILDHOST "solvable:buildhost"

El nombre del host en el que se creó el paquete binario.

SOLVABLE_EULA "solvable:eula"

Si este atributo está presente, se debe pedir al usuario que acepte el acuerdo de licencia de usuario final antes de instalar el paquete.

SOLVABLE_CPEID "solvable:cpeid"

Una cadena de Common Platform Enumeration describe la plataforma para la que está destinado este paquete. Consulte también el atributo distribution.

SOLVABLE_MESSAGEINS "solvable:messageins"

Un mensaje que debe mostrarse al usuario cuando se instale el paquete.

SOLVABLE_FILELIST "solvable:filelist"

SOLVABLE_INSTALLTIME "solvable:installtime"

Los segundos transcurridos desde la época Unix en que se instaló el paquete binario en el sistema.

SOLVABLE_MEDIADIR "solvable:mediadir"

El directorio en el repositorio que contiene el paquete. Si este atributo se establece en void, se utiliza la arquitectura del paquete como directorio.

SOLVABLE_SOURCEARCH "solvable:sourcearch"

La arquitectura del paquete fuente al que pertenece este paquete.

SOLVABLE_SOURCENAME "solvable:sourcename"

El nombre del paquete fuente al que pertenece este paquete. Si se establece en void, se utiliza el atributo del nombre del paquete en su lugar.

SOLVABLE_SOURCEEVR "solvable:sourceevr"

La versión del paquete fuente al que pertenece este paquete. Si se establece en void, se utiliza el atributo de la versión del paquete en su lugar.

Una lista de disparadores de paquetes para este paquete. Se utiliza en el código de ordenación de transacciones.

IDS DE DEPENDENCIAS

Los espacios de nombres son modificadores especiales que cambian el significado de una dependencia. Las dependencias de espacios de nombres se crean con la bandera REL_NAMESPACE. Para que funcionen los espacios de nombres personalizados, debe implementar una función de devolución de llamada de espacio de nombres.

Los marcadores de dependencia dividen la matriz de dependencias en dos partes con semántica diferente.

NAMESPACE_MODALIAS "namespace:modalias"

La dependencia es una dependencia especial de modalias que coincide con el hardware instalado.

NAMESPACE_SPLITPROVIDES "namespace:splitprovides"

La dependencia es una dependencia especial de splitprovides utilizada para implementar actualizaciones que incluyen una división de paquetes. Una dependencia de splitprovides contiene un nombre de archivo y un nombre de paquete; se considera una coincidencia si se instala un paquete con el nombre de paquete proporcionado que contiene el nombre de archivo. Este espacio de nombres está implementado en libsolv, por lo que no necesita una devolución de llamada.

NAMESPACE_LANGUAGE "namespace:language"

La dependencia describe un idioma. La devolución de llamada debe devolver verdadero si el usuario seleccionó el idioma.

NAMESPACE_FILESYSTEM "namespace:filesystem"

La dependencia describe un sistema de archivos. La devolución de llamada debe devolver verdadero si se necesita el sistema de archivos.

NAMESPACE_OTHERPROVIDERS "namespace:otherproviders"

Esto es un hack para permitir paquetes que se autoconflictan. No es necesario con la versión actual de rpm, así que no use este espacio de nombres.

SOLVABLE_PREREQMARKER "solvable:prereqmarker"

Este marcador divide las dependencias normales de requisito de los requisitos previos. No es necesario para la resolución de dependencias, pero es utilizado por el algoritmo de ordenación de transacciones cuando un ciclo de dependencia n
e necesita romper (las dependencias que no son prerrequisitos se rompen primero).

SOLVABLE_FILEMARKER "solvable:filemarker"

Este marcador particiona las dependencias que proporciona el paquete de las dependencias sintéticas de archivo que se añaden mediante pool_addfileprovides().

TIPOS DE DATOS

Cada dato de atributo se almacena con un tipo, para que las funciones de búsqueda sepan cómo interpretar los datos. Los siguientes tipos están disponibles:

REPOKEY_TYPE_VOID "repokey:type:void"

No se almacenan datos con este atributo. Por lo tanto, solo se puede comprobar si el atributo existe o no. Útil para almacenar valores booleanos.

REPOKEY_TYPE_CONSTANT "repokey:type:constant"

Los datos son un número constante de 32 bits. El número se almacena en el área de claves, por lo que su uso no consume espacio de almacenamiento adicional (pero se necesita el espacio de claves adicional).

REPOKEY_TYPE_CONSTANTID "repokey:type:constantid"

Los datos son un Id constante. El Id se almacena en el área de claves, por lo que su uso no consume espacio de almacenamiento adicional (pero se necesita el espacio de claves adicional).

REPOKEY_TYPE_ID "repokey:type:id"

Los datos son un Id.

REPOKEY_TYPE_NUM "repokey:type:num"

Los datos son un número sin signo de 64 bits.

REPOKEY_TYPE_U32 "repokey:type:num32"

Los datos son un número sin signo de 32 bits. Obsoleto, no usar.

REPOKEY_TYPE_DIR "repokey:type:dir"

Los datos son un Id de un directorio.

REPOKEY_TYPE_STR "repokey:type:str"

Los datos son una cadena de texto normal.

REPOKEY_TYPE_BINARY "repokey:type:binary"

Los datos son un bloque binario.

REPOKEY_TYPE_IDARRAY "repokey:type:idarray"

Los datos son un array de Ids distintos de cero.

REPOKEY_TYPE_REL_IDARRAY "repokey:type:relidarray"

Los datos son un array de Ids distintos de cero ordenados para que necesiten menos espacio.

REPOKEY_TYPE_DIRSTRARRAY "repokey:type:dirstrarray"

Los datos son una tupla que consta de un Id de directorio y un nombre base. Se utiliza para almacenar nombres de archivo.

REPOKEY_TYPE_DIRNUMNUMARRAY "repokey:type:dirnumnumarray"

Los datos son un triple que consta de un Id de directorio y dos enteros sin signo de 32 bits. Se utiliza para almacenar información de uso del disco.

REPOKEY_TYPE_MD5 "repokey:type:md5"

Los datos son un md5sum binario.

REPOKEY_TYPE_SHA1 "repokey:type:sha1"

Los datos son un sha1sum binario.

REPOKEY_TYPE_SHA256 "repokey:type:sha256"

Los datos son un sha256sum binario.

REPOKEY_TYPE_FIXARRAY "repokey:type:fixarray"

Los datos son un array de estructuras que tienen todas la misma disposición (es decir, los mismos nombres y tipos de clave en el mismo orden).

REPOKEY_TYPE_FLEXARRAY "repokey:type:flexarray"

Los datos son un array de estructuras que tienen una disposición diferente.

REPOKEY_TYPE_DELETED "repokey:type:deleted"

Los datos no existen. Se utiliza para marcar un atributo que ha sido eliminado.

METADATOS DEL REPOSITORIO

Estos atributos contienen metainformación sobre el repositorio.

REPOSITORY_SOLVABLES "repository:solvables"

Este atributo contiene el array que incluye todos los solvables. Solo se utiliza en los archivos solv en disco; internamente, los solvables se almacenan en el array de solvables del pool para un acceso rápido.

REPOSITORY_DELTAINFO "repository:deltainfo"

Este atributo contiene el array que incluye todos los paquetes delta.

REPOSITORY_EXTERNAL "repository:external"

Este atributo contiene el array que incluye todos los datos para construir áreas de metadatos stub para admitir la carga de metadatos bajo demanda.

REPOSITORY_KEYS "repository:keys"

En realidad, esto debería llamarse "repository:external:keys", contiene un array de Ids que consiste en pares (nombre de clave, tipo de clave) que describen los nombres de las claves del stub.

REPOSITORY_LOCATION "repository:location"

Esto se utiliza para proporcionar un nombre de archivo en el stub.

REPOSITORY_ADDEDFILEPROVIDES "repository:addedfileprovides"

Este atributo contiene un array de Ids de nombres de archivo, que indican a la biblioteca que todos los Ids ya se añadieron a las dependencias del solvable.

REPOSITORY_RPMDBCOOKIE "repository:rpmdbcookie"

Un atributo que almacena un sha256sum sobre las estadísticas de archivos de la base de datos de Paquetes. Se utiliza para detectar reconstrucciones de la base de datos, ya que en ese caso los Ids de base de datos de cada paquete se redistribuyen.

REPOSITORY_TIMESTAMP "repository:timestamp"

Los segundos transcurridos desde la época de Unix cuando se creó el repositorio.

REPOSITORY_EXPIRE "repository:expire"

Los segundos después de la marca de tiempo cuando el repositorio expirará.

REPOSITORY_UPDATES "repository:updates"

Un array de estructuras que describen qué actualiza este repositorio.

REPOSITORY_DISTROS "repository:distros"

También un array de estructuras que describen qué actualiza este repositorio. Parece ser el nombre más reciente de REPOSITORY_UPDATES.

REPOSITORY_PRODUCT_LABEL "repository:product:label"

En realidad, debería llamarse "repository:updates:label". Qué distribución se actualiza con este repositorio.

REPOSITORY_PRODUCT_CPEID "repository:product:cpeid"

El cpeid de la plataforma actualizada por este repositorio. Se utiliza tanto en REPOSITORY_UPDATES como en REPOSITORY_DISTROS para maximizar la confusión.

REPOSITORY_REPOID "repository:repoid"

Un array de cadenas de Id que describen palabras clave/etiquetas sobre el propio repositorio.

REPOSITORY_KEYWORDS "repository:keywords"

Un array de cadenas de Id que describen palabras clave/etiquetas sobre el contenido del repositorio.

REPOSITORY_REVISION "repository:revision"

Una cadena de texto arbitraria que describe la revisión del repositorio.

REPOSITORY_TOOLVERSION "repository:toolversion"

Alguna cadena de texto que describe la versión de libsolv utilizada para crear el archivo solv.
