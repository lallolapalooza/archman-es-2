NAME

libcpuid - CPU identification library

DESCRIPTION

The libcpuid library is intended to provide CPU identification functionality. It covers CPU features, vendor, model, stepping, and other related information.

It defines several enums for different types of CPU information:

enum cpu_feature_t
CPU feature identifiers.
enum cpu_hint_t
CPU detection hints identifiers.
enum cpu_sgx_feature_t
SGX features flags.
enum cpu_error_t
Describes common library error codes.
enum cpu_msrinfo_request_t
Requests for Model Specific Register (MSR) information.

libcpuid - CPU identification library

DESCRIPTION

The libcpuid library is used to retrieve information about the CPU. It can retrieve vendor string, CPU model, stepping, features, and more.

The MSR functions are used to access Model-Specific Registers which often contain detailed information about the CPU's configuration and capabilities. This usually requires root privileges.

The following functions are exported:

  • struct cpu_list_t * cpuid_get_cpu_list (enum cpu_vendor_t vendor)

    Gets a list of all known CPU names from a specific vendor.

  • void cpuid_free_cpu_list (struct cpu_list_t *list)

    Frees a CPU list.

  • void cpuid_free_raw_data_array (struct cpu_raw_data_array_t *raw_array)

    Frees a raw array.

  • void cpuid_free_system_id (struct system_id_t *system)

    Frees a system ID type.

  • struct msr_driver_t * cpu_msr_driver_open (void)

    Starts/opens a driver, needed to read MSRs (Model Specific Registers).

  • struct msr_driver_t * cpu_msr_driver_open_core (unsigned core_num)

    Similar to cpu_msr_driver_open, but accepts one parameter.

  • int cpu_rdmsr (struct msr_driver_t *handle, uint32_t msr_index, uint64_t *result)

    Reads a Model-Specific Register (MSR).

  • int cpu_rdmsr_range (struct msr_driver_t *handle, uint32_t msr_index, uint8_t highbit, uint8_t lowbit, uint64_t *result)

    Similar to cpu_rdmsr, but extracts a range of bits.

  • int cpu_msrinfo (struct msr_driver_t *handle, enum cpu_msrinfo_request_t which)

    Reads extended CPU information from Model-Specific Registers.

  • int msr_serialize_raw_data (struct msr_driver_t *handle, const char *filename)

    Writes the raw MSR data to a text file.

  • int cpu_msr_driver_close (struct msr_driver_t *handle)

    Closes an open MSR driver.

int cpu_clock_by_ic (int millis, int runs)

Measure the CPU clock frequency using instruction-counting.

Parameters

millis - how much time to allocate for each run, in milliseconds
runs - how many runs to perform

The function performs a busy-wait cycle using a known number of "heavy" (SSE) instructions. These instructions run at (more or less guaranteed) 1 IPC rate, so by running a busy loop for a fixed amount of time, and measuring the amount of instructions done, the CPU clock is accurately measured.

Of course, this function is still affected by the power-saving schemes, so the warnings as of cpu_clock_measure() still apply. However, this function is immune to problems with detection, related to the Intel Nehalem's "Turbo" mode, where the internal clock is raised, but the RDTSC rate is unaffected.

The function will run for about (millis * runs) milliseconds. You can make only a single busy-wait run (runs == 1); however, this can be affected by task scheduling (which will break the counting), so allowing more than one run is recommended. As run length is not imperative for accurate readings (e.g., 50ms is sufficient), you can afford a lot of short runs, e.g. 10 runs of 50ms or 20 runs of 25ms.

Recommended values - millis = 50, runs = 4. For more robustness, increase the number of runs.

NOTE: on Bulldozer and later CPUs, the busy-wait cycle runs at 1.4 IPC, thus the results are skewed. This is corrected internally by dividing the resulting value by 1.4. However, this only occurs if the thread is executed on a single CMT module - if there are other threads competing for resources, the results are unpredictable. Make sure you run cpu_clock_by_ic() on a CPU that is free from competing threads, or if there are such threads, they shouldn't exceed the number of modules. On a Bulldozer X8, that means 4 threads.

Returns

the CPU clock frequency in MHz (within some measurement error margin). If SSE is not supported, the result is -1. If the input parameters are incorrect, or some other internal fault is detected, the result is -2.

int cpu_clock_measure (int millis, int quad_check)

Measure the CPU clock frequency using RDTSC instruction.

Parameters

millis - how much time to spend on measurement, in milliseconds.
quad_check - if non-zero, the measurement is repeated 4 times to check for measurement inconsistencies.

This function is generally used when no other method is available. It relies on the Time Stamp Counter (RDTSC) instruction to measure the processor frequency. However, RDTSC has certain pitfalls:

1. On CPUs that support frequency scaling (like Intel SpeedStep or AMD Cool'n'Quiet), the measured frequency can vary depending on the current CPU load and power-saving state. The function tries to mitigate this by running the measurement for a longer duration (specified by `millis`) and, optionally, by checking the consistency of multiple measurements (`quad_check`). However, it cannot guarantee an accurate reading under dynamic frequency scaling.

2. On some older processors, RDTSC might not be a monotonic counter, meaning it could jump forwards or backwards, leading to incorrect measurements. This function assumes a reasonably modern CPU where RDTSC is reliable.

3. Context switches or system interrupts during the measurement period can disrupt the timing, leading to inaccurate results. Running this function with `quad_check` set to 1 helps detect such disruptions, but it's not foolproof.

Recommended values: `millis` = 200, `quad_check` = 1 for a balance between accuracy and performance.

Returns

the measured CPU clock frequency in MHz. Returns -1 if RDTSC is not supported or if measurements are deemed too inconsistent (e.g., due to excessive frequency scaling or interrupts).

int cpu_clock_measure (int millis, int quad_check)

Mide la frecuencia del reloj de la CPU.

Parámetros

millis - Tiempo a desperdiciar en el ciclo de espera activa. En milisegundos. Valores útiles: 10 - 1000
quad_check - Realiza una medición más exhaustiva si es distinto de cero (ver explicación).

La función realiza un ciclo de espera activa durante el tiempo dado y calcula la frecuencia de la CPU por la diferencia de los valores TSC. La precisión del cálculo depende de la duración del ciclo de espera activa: cuanto más, mejor, pero 100ms deberían ser suficientes para la mayoría de los propósitos.

Si bien esto calculará la frecuencia de la CPU correctamente en la mayoría de los casos, existen varias razones por las que podría ser incorrecto:

i) RDTSC no garantiza que se ejecutará al mismo reloj que la CPU. Aparentemente no hay CPUs en este momento, pero aún así, no hay garantía.
ii) La CPU podría estar en un modo de ahorro de energía de baja frecuencia, y la CPU podría cambiar a una frecuencia más alta en cualquier momento. Si esto sucede durante la medición, el resultado puede estar en cualquier lugar entre las frecuencias baja y alta. Además, si solo te interesa el valor de alta frecuencia, esta función podría devolver uno bajo en su lugar.
iii) En sistemas SMP que presentan deriva de TSC (ver cpu_rdtsc)

la opción quad_check ejecutará cuatro mediciones consecutivas y luego devolverá el promedio de los dos resultados más consistentes. El tiempo total de ejecución de la función seguirá siendo `millis' - considera usar un poco más de tiempo para el intervalo de tiempo.

Finalmente, para aplicaciones de benchmarking / intensivas en CPU, la mejor estrategia es usar el método cpu_tsc_mark() / cpu_tsc_unmark() / cpu_clock_by_mark(). Comienza marcando aproximadamente un segundo después del inicio de la aplicación (permitiendo que el administrador de ahorro de energía se active y aumente la frecuencia durante ese tiempo), luego desmarca justo antes de que la aplicación finalice. El resultado representará con mayor precisión a qué frecuencia se estaba ejecutando tu aplicación.

Devuelve

la frecuencia del reloj de la CPU en MHz (dentro de un margen de error de medición). Si RDTSC no es compatible, el resultado es -1.

void cpu_rdtsc (uint64_t * result)

Ejecuta RDTSC. La instrucción RDTSC (ReaD Time-Stamp Counter) proporciona acceso a un contador interno de 64 bits, que normalmente se incrementa en cada ciclo de reloj. Esto se puede utilizar para diversas rutinas de temporización y como una fuente de reloj muy precisa. Se establece a cero al inicio del sistema. Tenga en cuenta que puede no incrementarse a la misma frecuencia que la CPU. Sin embargo, se garantiza que las llamadas consecutivas a RDTSC devuelven valores monótonamente crecientes.

Parámetros

result: un puntero a un entero sin signo de 64 bits, donde se almacenará el valor del TSC.

Nota

Si la compatibilidad al 100% es una preocupación, debe verificar primero si la instrucción RDTSC está presente (si no lo está, su programa fallará con una excepción de "opcode inválido"). Solo algunos procesadores muy antiguos (i486, primeros AMD K5 y algunas CPUs Cyrix) carecen de esa instrucción; deberían ser extremadamente raros hoy en día. Para verificar la presencia de RDTSC, ejecute `cpu_identify()` y verifique `flags[CPU_FEATURE_TSC]`.

La naturaleza monótonamente creciente del TSC puede verse violada en sistemas SMP, si los relojes de sus TSC funcionan a diferentes velocidades. Si el sistema operativo no tiene en cuenta esto, la deriva del TSC puede volverse arbitrariamente grande.

int cpuid_serialize_raw_data (struct cpu_raw_data_t * data, const char * filename)

Writes the raw CPUID data to a text file.

Parameters

data - a pointer to cpu_raw_data_t structure
filename - the path of the file, where the serialized data should be written. If empty, stdout will be used.

Note

This is intended primarily for debugging. On some processor, which is not currently supported or not completely recognized by cpu_identify, one can still successfully get the raw data and write it to a file. libcpuid developers can later import this file and debug the detection code as if running on the actual hardware. The file is simple text format of "something=value" pairs. Version info is also written, but the format is not intended to be neither backward- nor forward compatible.

Returns

zero if successful, and some negative number on error. The error message can be obtained by calling cpuid_error.
