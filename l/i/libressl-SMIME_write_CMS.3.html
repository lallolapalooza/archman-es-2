SMIME_WRITE_CMS(3) Manual de funciones de biblioteca SMIME_WRITE_CMS(3)

NOMBRE

SMIME_write_CMS — convierte la estructura CMS al formato S/MIME

SINOPSIS

biblioteca “libcrypto”
#include <openssl/cms.h>

int
SMIME_write_CMS(BIO *out, CMS_ContentInfo *cms, BIO *data, int flags);

DESCRIPCIÓN

SMIME_write_CMS() genera un mensaje S/MIME en out escribiendo cabeceras MIME 1.0 seguidas de una serialización codificada en BER y base64 de cms. La codificación BER utiliza el formato DER excepto como se describe para CMS_STREAM a continuación. Si la transmisión está habilitada, el contenido debe proporcionarse en el argumento data.

Los flags pueden ser el OR lógico de cero o más de los siguientes bits:

CMS_DETACHED
Utiliza la firma de texto claro y genera un mensaje S/MIME "multipart/signed". El contenido se lee de data. Si data es un puntero NULL, esta bandera se ignora.

Esta bandera solo se admite si cms es del tipo SignedData y CMS_DETACHED también se estableció al crearlo con CMS_sign(3).

Si CMS_STREAM no está configurado, los datos deben leerse dos veces: una para calcular la firma en CMS_sign(3) y otra para generar el mensaje S/MIME.

Si CMS_DETACHED se ignora o no se especifica, el tipo de smime se elige según CMS_get0_type(3):

NID_pkcs7_enveloped
"enveloped-data"
NID_pkcs7_signed
"signed-receipt"
si CMS_get0_eContentType(3) es NID_id_smime_ct_receipt
"signed-data"
si cms especifica algún algoritmo de resumen
"certs-only"
de lo contrario
NID_id_smime_ct_compressedData
"compressed-data"
CMS_REUSE_DIGEST
Omitir las llamadas a CMS_dataInit(3) y CMS_dataFinal(3). Esta bandera no tiene ningún efecto a menos que CMS_DETACHED también esté configurado.
CMS_STREAM
Realiza la transmisión leyendo el contenido de data. Esto solo funciona si CMS_DETACHED no está especificado.

Esta bandera solo debe establecerse si CMS_STREAM también se pasó a la función que creó cms.

El contenido se genera en formato BER utilizando codificación construida de longitud indefinida, excepto en el caso de SignedData con contenido separado donde el contenido está ausente y se utiliza el formato DER.

CMS_TEXT
Antepone la línea "Content-Type: text/plain" al contenido. Esto solo tiene sentido si CMS_DETACHED también está configurado. Se ignora si también está configurada la bandera SMIME_BINARY.
SMIME_BINARY
Si se especifica, esta bandera se pasa a SMIME_crlf_copy(3).
SMIME_CRLFEOL
Termina las líneas de cabecera MIME con pares de caracteres de retorno de carro y salto de línea. Por defecto, no se escriben caracteres de retorno de carro y las líneas de cabecera terminan solo con saltos de línea.

VALORES DE RETORNO

SMIME_write_CMS() tiene la intención de devolver 1 en caso de éxito o 0 en caso de fallo.

VEA TAMBIÉN

BIO_f_base64(3), BIO_new(3), CMS_ContentInfo_new(3), CMS_encrypt(3), CMS_sign(3), d2i_CMS_ContentInfo(3), ERR_get_error(3), SMIME_crlf_copy(3), SMIME_read_CMS(3), SMIME_write_PKCS7(3)

HISTORIAL

SMIME_write_CMS() apareció por primera vez en OpenSSL 0.9.8h y ha estado disponible desde OpenBSD 6.7.

ERRORES

SMIME_write_CMS() ignora la mayoría de los errores y es probable que devuelva 1 incluso después de producir una salida corrupta o incompleta.

SMIME_write_CMS() siempre codifica en base64 las estructuras CMS. Debería haber una opción para deshabilitar esto.
