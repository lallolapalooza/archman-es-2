LIMITS.CONF(5) Manual de Linux-PAM LIMITS.CONF(5)

NOMBRE

limits.conf - archivo de configuración para el módulo pam_limits

DESCRIPCIÓN

El módulo pam_limits.so aplica límites de ulimit, prioridad nice y límite de sesiones de inicio de sesión simultáneas a las sesiones de inicio de sesión del usuario. Esta descripción de la sintaxis del archivo de configuración se aplica al archivo /etc/security/limits.conf y a los archivos *.conf en el directorio /etc/security/limits.d.

La sintaxis de las líneas es la siguiente:

<dominio> <tipo> <ítem> <valor>

Los campos enumerados anteriormente deben rellenarse de la siguiente manera:

<dominio>

•un nombre de usuario
•un nombre de grupo, con sintaxis @grupo. Esto no debe confundirse con los netgroups.
•el comodín *, para la entrada predeterminada.
•el comodín %, solo para el límite maxlogins, también se puede usar con sintaxis %grupo. Si el comodín % se usa solo, es idéntico a usar * con el límite maxsyslogins. Con un grupo especificado después de %, limita el número total de inicios de sesión de todos los usuarios que son miembros del grupo.
•un rango de uid especificado como <min_uid>:<max_uid>. Si se omite min_uid, la coincidencia es exacta para max_uid. Si se omite max_uid, coinciden todas las uids mayores o iguales a min_uid.
•un rango de gid especificado como @<min_gid>:<max_gid>. Si se omite min_gid, la coincidencia es exacta para max_gid. Si se omite max_gid, coinciden todos los gids mayores o iguales a min_gid. Para la coincidencia exacta, se examinan todos los grupos, incluidos los grupos suplementarios del usuario. Para las coincidencias de rango, solo se examina el grupo primario del usuario.
•un gid especificado como %:<gid> aplicable solo al límite maxlogins. Limita el número total de inicios de sesión de todos los usuarios que son miembros del grupo con el gid especificado.

<tipo>

hard

para aplicar límites de recursos hard (duros). Estos límites son establecidos por el superusuario y aplicados por el Kernel. Los usuarios no pueden aumentar sus propios requisitos de recursos del sistema por encima de dichos valores.

soft

para aplicar límites de recursos soft (blandos). Estos límites son aquellos que el usuario puede mover hacia arriba o hacia abajo dentro del rango permitido por cualquier límite hard preexistente. Los valores especificados con este token pueden considerarse como valores predeterminados, para el uso normal del sistema.

-

para aplicar los límites de recursos soft y hard juntos.

Nota: si especifica un tipo de '-' pero omite los campos de elemento y valor, el módulo nunca aplicará ningún límite al usuario/grupo especificado, etc.

<ítem>

core

limita el tamaño del archivo core (KB)

data

tamaño máximo de datos (KB)

fsize

tamaño máximo de archivo (KB)

memlock

dirección máxima de memoria bloqueada en memoria (KB)

nofile

número máximo de descriptores de archivo abiertos

rss

tamaño máximo del conjunto residente (KB) (Ignorado en Linux 2.4.30 y posteriores)

stack

tamaño máximo de la pila (KB)

cpu

tiempo máximo de CPU (minutos)

nproc

número máximo de procesos

as

límite de espacio de direcciones (KB)

maxlogins

número máximo de inicios de sesión para este usuario (este límite no se aplica a los usuarios con uid=0)

maxsyslogins

número máximo de todos los inicios de sesión en el sistema; el usuario no tiene permitido iniciar sesión si el número total de todos los inicios de sesión de usuarios es mayor que el número especificado (este límite no se aplica a los usuarios con uid=0)

nonewprivs

valor de 0 o 1; si se establece en 1, deshabilita la adquisición de nuevos privilegios invocando prctl(PR_SET_NO_NEW_PRIVS)

priority

la prioridad con la que se ejecuta el proceso del usuario (valores negativos aumentan la prioridad del proceso)

locks

archivos bloqueados máximos (Linux 2.4 y posteriores)

sigpending

número máximo de señales pendientes (Linux 2.6 y posteriores)

msgqueue

memoria máxima utilizada por colas de mensajes POSIX (bytes) (Linux 2.6 y posteriores)

nice

prioridad nice máxima permitida para aumentar (Linux 2.6.12 y posteriores) valores: [-20,19]

rtprio

prioridad de tiempo real máxima permitida para procesos no privilegiados (Linux 2.6.12 y posteriores)

rttime

Tiempo de espera para tareas de tiempo real en microsegundos (Linux 2.6.25 y posteriores)

Todos los elementos admiten los valores -1, unlimited o infinity indicando que no hay límite, excepto para priority, nice y nonewprivs. Si nofile se establece en uno de estos valores, se establecerá en el contenido de /proc/sys/fs/nr_open en su lugar (consulte setrlimit(3)).

Si un límite duro o blando de un recurso se establece en un valor válido, pero fuera del rango admitido por el sistema local, el sistema puede rechazar el nuevo límite o pueden ocurrir comportamientos inesperados. Si se utiliza el valor de control required, el módulo rechazará el inicio de sesión si no se puede establecer un límite.

En general, los límites individuales tienen prioridad sobre los límites de grupo, por lo que si no impone límites para el grupo admin, pero uno de los miembros de este grupo tiene una línea de límites, el usuario tendrá sus límites establecidos de acuerdo con esa línea.

Además, tenga en cuenta que todas las configuraciones de límites se establecen por inicio de sesión. No son globales ni permanentes; existen solo durante la duración de la sesión. Una excepción es la opción maxlogin, esta es para todo el sistema. Pero hay una condición de carrera, los inicios de sesión concurrentes al mismo tiempo no siempre se detectarán como tales, sino que solo se contarán como uno.

En el archivo de configuración limits, el carácter '#' introduce un comentario; después de él, el resto de la línea se ignora.

El módulo pam_limits informa sobre problemas de configuración encontrados en su archivo de configuración y errores a través de syslog(3).

EJEMPLOS

Estas son algunas líneas de ejemplo que podrían especificarse en /etc/security/limits.conf.

*               soft    core            0
*               hard    nofile          512
@student        hard    nproc           20
@faculty        soft    nproc           20
@faculty        hard    nproc           50
ftp             hard    nproc           0
@student        -       maxlogins       4
@student        -       nonewprivs      1
:123            hard    cpu             5000
@500:           soft    cpu             10000
600:700         hard    locks           10
