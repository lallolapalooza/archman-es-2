Paquete: dnssec-tools

libsres(3) Manual del programador libsres(3)

NOMBRE

query_send(), response_rcv(), get() - enviar consultas y recibir respuestas de un servidor de nombres DNS.

clone_ns(), clone_ns_list(), free_name_server(), free_name_servers() - gestionar listas de servidores de nombres

print_response() - mostrar las respuestas devueltas por el servidor de nombres

SINOPSIS

#include <resolver.h>
int query_send(const char    *name,
          const unsigned short type,
          const unsigned short class,
          struct name_server  *nslist,
          int                 edns0_size,
          int                 *trans_id);
int response_recv(int         *trans_id,
          fd_set              *pending_desc,
          struct timeval      *closest_event,
          struct name_server  **respondent,
          unsigned char       **response,
          size_t              *response_length);
int get(const char          *name_n,
        const unsigned short type_h,
        const unsigned short class_h,
        struct name_server  *nslist,
        struct name_server  **respondent,
        unsigned char       **response,
        size_t              *response_length);
int clone_ns(struct name_server **cloned_ns, 
        struct name_server *ns);
int clone_ns_list(struct name_server **ns_list,
                  struct name_server *orig_ns_list);
void free_name_server(struct name_server **ns);
void free_name_servers(struct name_server **ns);
void print_response(unsigned char *response, 
          size_t response_length);

DESCRIPCIÓN

La función query_send() envía una consulta a los servidores de nombres especificados en nslist. La consulta se compone de la tupla <nombre, clase, tipo> y trans_id proporciona un identificador para esta transacción dentro de la biblioteca libsres. El tamaño del búfer anunciado en la opción EDNS0 se puede establecer usando el argumento ends0_size.

La función response_recv() devuelve las respuestas, si están disponibles, del servidor de nombres que responde a la consulta identificada por trans_id. La respuesta está disponible en response y el servidor de nombres que responde se devuelve en respondent. La longitud de la respuesta en bytes se devuelve en response_length.

La función get() proporciona un envoltorio alrededor de las funciones query_send() y response_recv(). Después de enviar una solicitud, se bloquea hasta que se recibe una respuesta de algún servidor de nombres o hasta que la solicitud expira. La biblioteca libsres no sigue automáticamente las referencias; las respuestas que contienen referencias se tratan como respuestas válidas.

La memoria apuntada por *respondent es asignada internamente por la biblioteca libsres y debe ser liberada por el invocador usando free_name_server(). Una lista completa de servidores de nombres se puede liberar usando free_name_servers(). Se puede crear una copia del servidor de nombres usando clone_ns() y una copia de una lista de servidores de nombres se puede hacer usando clone_ns_list().

print_response() proporciona una forma conveniente de mostrar las respuestas devueltas en response por el servidor de nombres.

La estructura name_server se define en resolver.h como sigue:

#define NS_MAXCDNAME    255
struct name_server
{
    unsigned char ns_name_n[NS_MAXCDNAME];
    void *ns_tsig;
    unsigned int ns_security_options;
    unsigned int ns_status;
    unsigned long ns_options;
    int ns_retry;
    int ns_retrans;
    struct name_server *ns_next;
    int ns_number_of_addresses;
    struct sockaddr_storage **ns_address;
};
ns_name_n
El nombre de la zona para la cual este servidor de nombres es autoritativo.
ns_tsig
La clave tsig que debe usarse para proteger los mensajes enviados a este servidor de nombres. Este campo actualmente no se utiliza y debe establecerse en NULL.
ns_security_options
Las opciones de seguridad para la zona. Este campo actualmente no se utiliza y debe establecerse en ZONE_USE_NOTHING.
ns_status
El estado de la zona. Este campo indica cómo se obtuvo la información de la zona. El invocador debe establecer este valor en SR_ZI_STATUS_UNSET. La información de la zona obtenida a través de referencias tiene un valor de SR_ZI_STATUS_LEARNED para este campo.
ns_options
Especifica indicadores adicionales del resolvedor. Los indicadores definidos actualmente son SR_QUERY_RECURSE, que establece el bit "Recursion Desired"; SR_QUERY_SET_DO, que establece el bit "DNSSEC OK" en la cabecera EDNS0; SR_QUERY_SET_CD, que establece el bit "DNSSEC CD" en la cabecera EDNS0; y SR_QUERY_DEBUG, que habilita la depuración. SR_QUERY_VALIDATING_STUB_FLAGS establece tanto SR_QUERY_SET_DO como SR_QUERY_SET_CD.
ns_retry
Especifica el número máximo de intentos que deben realizarse para obtener un nombre de un servidor de nombres no receptivo antes de rendirse.
ns_retrans
Especifica el intervalo de retransmisión en segundos para las consultas enviadas a servidores de nombres no receptivos.
ns_next
La dirección del siguiente servidor de nombres en la lista.
ns_number_of_addresses
El número de elementos en el array ns_addresses. Este campo actualmente no se utiliza.
ns_addresses
La dirección IP del servidor de nombres.

OTROS SÍMBOLOS EXPORTADOS

La biblioteca libsres también exporta las siguientes funciones de BIND, cuya documentación se puede encontrar en las fuentes y manuales de documentación de BIND:

res_nametoclass
res_nametotype
ns_name_ntop
ns_name_pton
ns_name_unpack
ns_parse_ttl
p_class
p_section
p_type

La función p_type() exportada desde libsres ha sido aumentada para reconocer los diversos códigos de tipo DNSSEC como DNSKEY, RRSIG, NSEC, NSEC3 y DLV.

VALORES DE RETORNO

SR_UNSET
Sin error.
SR_CALL_ERROR
Se pasó un parámetro inválido a get(), query_send() o response_recv().
SR_INTERNAL_ERROR
El resolvedor encontró algún error interno.
SR_TSIG_ERROR
El resolvedor encontró algún error relacionado con TSIG. Esto actualmente no está implementado.
SR_NO_ANSWER
No se recibieron respuestas de ningún servidor de nombres.
SR_NO_ANSWER_YET
Todavía no hay respuesta disponible; la consulta sigue activa.
SR_HEADER_ERROR
La longitud y el recuento de registros en la cabecera eran incorrectos.
SR_NXDOMAIN
El nombre consultado no existía.
SR_FORMERR
El servidor de nombres no pudo analizar el mensaje de consulta.
SR_SERVFAIL
No se pudo contactar con el servidor de nombres.
SR_NOTIMPL
Alguna funcionalidad no está implementada todavía.
SR_REFUSED
El servidor de nombres se negó a responder a esta consulta.
SR_DNS_GENERIC_FAILURE
Otro fallo devuelto por el servidor de nombres y reflejado en el mensaje devuelto RCODE.
SR_EDNS_VERSION_ERROR

Páginas del manual de Arch Linux. Bajo licencia MIT.

La versión EDNS no fue reconocida
SR_NAME_EXPANSION_FAILURE
Se encontró un error al intentar expandir un nombre de dominio comprimido.

ESTADO ACTUAL

Actualmente no hay soporte para IPv6.

Hay un soporte limitado para especificar la política del resolutor; los miembros de la struct name_server aún están sujetos a cambios.
