NOMBRE

libpipewire-module-protocol-pulse - Protocolo Pulse

DESCRIPCIÓN

Este módulo implementa un servidor PulseAudio completo sobre PipeWire.

Esta es solo la implementación del servidor; se espera que los clientes utilicen la biblioteca cliente original de PulseAudio. Esto proporciona un alto nivel de compatibilidad con las aplicaciones existentes; de hecho, todas las herramientas habituales de PulseAudio como pavucontrol, pactl, pamon, paplay deberían seguir funcionando como lo hacían antes.

Este módulo normalmente se carga como parte de un proceso pipewire independiente, llamado pipewire-pulse, con el archivo de configuración pipewire-pulse.conf.

El servidor pulse implementa una caché de muestras que de otro modo no estaría disponible en PipeWire.

NOMBRE DEL MÓDULO

libpipewire-module-protocol-pulse

OPCIONES DEL MÓDULO

Los argumentos del módulo pueden ser el contenido de las pulse.properties, pero se recomienda crear una sección separada de pulse.properties en el archivo de configuración para poder realizar anulaciones.

PROPIEDADES_PULSE

Se puede proporcionar una sección de configuración con propiedades del servidor.

# ~/.config/pipewire/pipewire-pulse.conf.d/custom.conf
pulse.properties = {
    # las direcciones en las que este servidor escucha
    server.address = [
        "unix:native"
        #"unix:/tmp/algo"              # se pueden usar rutas absolutas
        #"tcp:4713"                         # IPv4 e IPv6 en todas las direcciones
        #"tcp:[::]:9999"                    # IPv6 en todas las direcciones
        #"tcp:127.0.0.1:8888"               # IPv4 en una única dirección
        #
        #{ address = "tcp:4713"             # dirección
        #  max-clients = 64                 # número máximo de clientes
        #  listen-backlog = 32              # cola de escucha del servidor
        #  client.access = "restricted"     # permisos para clientes
        #}
    ]
    #server.dbus-name       = "org.pulseaudio.Server"
    #pulse.allow-module-loading = true
    #pulse.min.req          = 128/48000     # 2.7ms
    #pulse.default.req      = 960/48000     # 20 milisegundos
    #pulse.min.frag         = 128/48000     # 2.7ms
    #pulse.default.frag     = 96000/48000   # 2 segundos
    #pulse.default.tlength  = 96000/48000   # 2 segundos
    #pulse.min.quantum      = 128/48000     # 2.7ms
    #pulse.default.format   = F32
    #pulse.default.position = [ FL FR ]
    #pulse.idle.timeout     = 0
}
pulse.properties.rules = [
    {   matches = [ { cpu.vm.name = !null } ]
        actions = {
            update-props = {
                # Estas anulaciones solo se aplican cuando se ejecuta en una vm.
                pulse.min.quantum = 1024/48000      # 22ms
            }
        }
    }
]

Opciones de conexión

...
server.address = [
    "unix:native"
    # "tcp:4713"
]
...

Las direcciones en las que el servidor escucha al iniciarse. Descomente la entrada tcp:4713 para que el servidor también escuche en un socket tcp. Esto es equivalente a cargar libpipewire-module-native-protocol-tcp.

También hay una sintaxis ligeramente más detallada con más opciones:

....
server.address = [
  {  address = "tcp:4713"             # dirección
     max-clients = 64                 # número máximo de clientes
     listen-backlog = 32              # cola de escucha del servidor
     client.access = "restricted"     # permisos para clientes
  }
....

Utilice client.access para usar uno de los métodos de acceso para restringir los permisos otorgados a los clientes conectados a través de esta dirección.

Por defecto, el acceso a la red tiene los permisos "restringidos". El gestor de sesión es responsable de asignar permisos a los clientes con permisos restringidos (normalmente permisos de solo lectura).

server.dbus-name       = "org.pulseaudio.Server"

El nombre de DBus a reservar para el servidor. Si tiene varios servidores, es posible que desee cambiar el nombre.

pulse.allow-module-loading = true

Por defecto, se permite a los clientes cargar y descargar módulos. Puede deshabilitar esta función con esta opción.

Opciones de búfer de reproducción

pulse.min.req = 128/48000              # 2.7ms

La cantidad mínima de datos a solicitar para los clientes. Los valores solicitados por el cliente se limitarán a este valor. Reducir este valor junto con tlength puede disminuir la latencia si el cliente lo desea, pero aumenta la carga de la CPU.

pulse.default.req = 960/48000          # 20 milisegundos

La cantidad predeterminada de datos a solicitar para los clientes. Si el cliente no especifica ningún valor en particular, se utilizará este valor predeterminado. Reducir este valor junto con tlength puede disminuir la latencia pero aumentar la carga de la CPU.

pulse.default.tlength = 96000/48000    # 2 segundos

La cantidad objetivo de datos a almacenar en búfer en el lado del servidor. Si el cliente no especificó ningún valor, se utilizará este valor predeterminado. Valores más bajos pueden disminuir la latencia.

Opciones de búfer de grabación

pulse.min.frag = 128/48000             # 2.7ms

El tamaño mínimo permitido del búfer de captura antes de enviarlo a un cliente. El valor solicitado por el cliente se limitará a este. Reducir este valor puede reducir la latencia a expensas de un mayor uso de la CPU.

pulse.default.frag = 96000/48000       # 2 segundos

El tamaño predeterminado del búfer de captura antes de enviarlo a un cliente. Si el cliente no especificó ningún valor, se utilizará este valor predeterminado. Reducir este valor puede reducir la latencia a expensas de un mayor uso de la CPU.

Opciones de planificación

pulse.min.quantum = 128/48000          # 2.7ms

El quantum mínimo (tamaño del búfer en muestras) a utilizar para los clientes de pulseaudio. Este valor se calcula en función de frag y req/tlength para flujos de grabación y reproducción respectivamente, y luego se limita a este valor para garantizar que ningún cliente de pulseaudio solicite quantums demasiado pequeños. Reducir este valor podría disminuir la latencia a expensas de un mayor uso de la CPU.

Opciones de formato

pulse.default.format = F32

Algunos módulos usarán este formato por defecto cuando no se haya especificado ningún otro formato. Esto es equivalente a la opción pulseAudio default-sample-format en /etc/pulse/daemon.conf.

pulse.default.position = [ FL FR ]

Algunos módulos usarán este mapa de canales (con su número de canales) por defecto. Esto es equivalente a las opciones de pulseaudio default-sample-channels y default-channel-map en /etc/pulse/daemon.conf.

Opciones de corrección

pulse.fix.format = "S16LE"

Cuando un flujo utiliza la bandera FIX_FORMAT, fija el formato a este valor. Normalmente, el formato se fijaría al sink/source al que se conecta el flujo. Cuando se establece un formato inválido (nulo o vacío), se ignora la bandera FIX_FORMAT.

pulse.fix.rate = 48000

Cuando un flujo utiliza la bandera FIX_RATE, fija la frecuencia de muestreo a este valor. Normalmente, la frecuencia se fijaría al sink/source al que se conecta el flujo. Cuando se establece una frecuencia de 0, se ignora la bandera FIX_RATE.

pulse.fix.position = "[ FL FR ]"

Cuando un flujo utiliza la bandera FIX_CHANNELS, fija los canales a este valor. Normalmente, los canales se fijarían al sink/source al que se conecta el flujo. Cuando se establece una posición inválida (nula o vacía), se ignora la bandera FIX_CHANNELS.

pulse.idle.timeout = 0

Algunos clientes no envían datos cuando deberían y causan interrupciones. Al configurar esta opción, dichos clientes se pausarán si se interrumpen durante la cantidad de segundos especificada. Esto asegura que los sinks puedan suspenderse y ahorrar energía. Cuando el cliente se reanuda, se reanudará de nuevo. Un valor de 0 deshabilita esta función.

NAME

libpipewire-module-protocol-pulse - PipeWire PulseAudio API module

DESCRIPTION

This module implements the PulseAudio server API, allowing PulseAudio clients to connect to PipeWire.

It is loaded by default by the PipeWire session manager. The module can be configured in /etc/pipewire/pipewire-pulse.conf or ~/.config/pipewire/pipewire-pulse.conf.

# Configuration is read from /usr/share/pipewire/pipewire-pulse.conf,
# /usr/share/pipewire/pipewire-pulse.conf.d/ and
# ~/.config/pipewire/pipewire-pulse.conf.d/.
#
# PipeWire is a JACK and ALSA API replacement.
#
# Check the PipeWire documentation for details on the configuration options:
# https://pipewire.org/documentation

MODULE NAME

The module name is libpipewire-module-protocol-pulse.

MODULE OPTIONS

The module takes the following options:

• session.suspend-timeout-seconds
The time in seconds to suspend an idle sink or source. When this timeout is reached, the sink or source is suspended. If new clients connect, it is resumed.
• session.max-length
The maximum length in frames of a fragment. Defaults to 4096.
• pulse.min.quantum
The minimum quantum size. Defaults to 1024.
• pulse.min.req
The minimum requested quantum size. Defaults to 512.
• pulse.default.channel-map
The default channel map. For example: stereo.
• pulse.default.force-sample-format
The default sample format to force. For example: S16.
• pulse.idle.timeout
The time in seconds to suspend an idle client. Defaults to 300.
• pulse.rule.enable
Enable rules. Defaults to true.
• pulse.restore.session
Restore the previous session. Defaults to true.
• pulse.default.sink.name
The default sink name. For example: alsa_output.pci-0000_00_1f.3.analog-stereo.
• pulse.default.source.name
The default source name. For example: alsa_input.pci-0000_00_1f.3.analog-stereo.
• pulse.server.address
The address of the PulseAudio server. For example: unix:native.

PULSE.PROPERTIES

This section allows setting properties for the PulseAudio server. These properties are mostly equivalent to the module options.

pulse.properties = {
    # Use the native server address
    server.address = [ "unix:native" ]
    # Default sink name
    default.clock.rate = 48000
    # Default sink name
    default.audio.sink = "alsa_output.pci-0000_00_1f.3.analog-stereo"
    # Default source name
    default.audio.source = "alsa_input.pci-0000_00_1f.3.analog-stereo"
    # Suspend sinks/sources when idle
    session.suspend-timeout-seconds = 5
    # Minimum quantum size
    pulse.min.quantum = 2048
    # Minimum requested quantum size
    pulse.min.req = 1024
}

DYNAMIC PROPERTIES

The pulse.properties can be dynamically updated with rules. It supports an update-props action. The matches will be performed on the values in context.properties.

pulse.properties.rules = [
    {   matches = [ { cpu.vm.name = !null } ]
        actions = {
            update-props = {
                # These overrides are only applied when running in a vm.
                pulse.min.quantum = 1024/48000      # 22ms
            }
        }
    }
]

In the above example, when running in a VM, the rule will override the properties in pulse.properties with the given values. This might be interesting because VMs usually can't support the low latency settings that are possible on real hardware.

STREAM SETTINGS AND RULES

Streams created by module-protocol-pulse will use the stream.properties section and stream.rules sections as usual.

APPLICATION SETTINGS (RULES)

The pulse protocol module supports generic config rules. It supports a pulse.rules section with a quirks and an update-props action. These rules operate on the client properties (not the stream properties, see above).

# ~/.config/pipewire/pipewire-pulse.conf.d/custom.conf
pulse.rules = [
    {
        # skype does not want to use devices that don't have an S16 sample format.
        matches = [
             { application.process.binary = "teams" }
             { application.process.binary = "teams-insiders" }
             { application.process.binary = "skypeforlinux" }
        ]
        actions = { quirks = [ force-s16-info ] }
    }
    {
        # speech dispatcher asks for too small latency and then underruns.
        matches = [ { application.name = "~speech-dispatcher*" } ]
        actions = {
            update-props = {
                pulse.min.req          = 1024/48000     # 21ms
                pulse.min.quantum      = 1024/48000     # 21ms
                pulse.idle.timeout     = 5              # pause after 5 seconds of underrun
            }
        }
    }
]

Quirks

The quirks action takes an array of quirks to apply for the client.

  • force-s16-info makes the sink and source introspect code pretend that the sample format is S16 (16 bits) samples. Some application refuse the sink/source if this is not the case.
  • remove-capture-dont-move Removes the DONT_MOVE flag on capture streams. Some applications set this flag so that the stream can't be moved anymore with tools such as pavucontrol.
  • block-source-volume blocks the client from updating any source volumes. This can be used to disable things like automatic gain control.
  • block-sink-volume blocks the client from updating any sink volumes.
  • block-record-stream blocks the client from creating any record stream.
  • block-playback-stream blocks the client from creating any playback stream.

update-props

Takes an object with the properties to update on the client. Common actions are to tweak the quantum values. You can use the stream specific keys in pulse.properties.

startup notification

A newline will be written into the notification file descriptor when the server has started if the following environment variable is set:

•
PIPEWIRE_PULSE_NOTIFICATION_FD

EXAMPLE CONFIGURATION

   }
   {

           update-props = {

               pulse.min.quantum      = 1024/48000     # 21ms
               pulse.idle.timeout     = 5              # pause after 5 seconds of underrun
           }
       }
   }
]
