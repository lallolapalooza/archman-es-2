NOMBRE

libtiff - Introducción a libtiff, una biblioteca para leer y escribir archivos TIFF

SINOPSIS

#include <tiffio.h>
cc file.c -ltiff

DESCRIPCIÓN

libtiff es una biblioteca para leer y escribir archivos de datos codificados con el formato “Tag Image File”, Revisión 6.0 (o revisión 5.0 o revisión 4.0). Este formato de archivo es adecuado para archivar datos de imágenes multicolores y monocromáticas.

La biblioteca soporta varios algoritmos de compresión, como se indica en el campo Compression, incluyendo: sin compresión (1), compresión Huffman 1D CCITT (2), compresión de facsímil de Grupo 3 CCITT (3), compresión de facsímil de Grupo 4 CCITT (4), compresión Lempel-Ziv & Welch (5), compresión JPEG de línea base (7), compresión Huffman 1D alineada por palabra (32771), compresión PackBits (32773). Además, se soportan varios algoritmos de compresión no estándar: el algoritmo de compresión de 4 bits utilizado por el programa ThunderScan (32809) (solo descompresión), el algoritmo de compresión de 2 bits de NeXT (32766) (solo descompresión), un algoritmo experimental estilo LZ conocido como Deflate (32946), y un esquema experimental de compresión CIE LogLuv diseñado para imágenes con alto rango dinámico (32845 para LogL y 32845 para LogLuv). La información del directorio puede estar en orden de bytes little-endian o big-endian; el intercambio de bytes se realiza automáticamente por la biblioteca. El orden de bits de los datos puede ser de Bit Más Significativo (MSB) a Bit Menos Significativo (LSB) o de LSB a MSB. Finalmente, la biblioteca no soporta archivos en los que los campos BitsPerSample, Compression, MinSampleValue o MaxSampleValue se definen de manera diferente por muestra (en la Rev. 6.0, la etiqueta Compression no se define por muestra, por lo que esto es irrelevante).

TIPOS DE DATOS

La biblioteca utiliza ampliamente typedefs de C para promover la portabilidad. Se utilizan dos conjuntos de typedefs, uno para la comunicación con los clientes de la biblioteca y otro para las estructuras de datos internas y el análisis del formato TIFF. Los siguientes typedefs se exponen a los usuarios ya sea a través de definiciones de funciones o a través de parámetros pasados a través de interfaces varargs.

typedef uint32_t ttag_t;    // etiqueta de directorio
typedef uint32_t tdir_t;    // índice de directorio
typedef uint16_t tsample_t; // número de muestra
typedef uint32_t tstrip_t;  // número de tira
typedef uint32_t ttile_t;   // número de mosaico
typedef int64_t tmsize_t;   // tipo de tamaño con signo (int32_t en plataformas de 32 bits)
typedef tmsize_t tsize_t;   // tamaño de E/S en bytes
typedef void* tdata_t;      // referencia a datos de imagen
typedef void* thandle_t;    // manejador de datos del cliente
typedef uint64_t toff_t;    // desplazamiento de archivo

Tenga en cuenta que tstrip_t, ttile_t y tsize_t están limitados a no más de 32 bits debido a los campos de 32 bits en los que se almacenan en la imagen TIFF. Del mismo modo, tsample_t está limitado por el campo de 16 bits utilizado para almacenar la etiqueta SamplesPerPixel.

tdir_t limita el número máximo de IFD que pueden aparecer en una imagen y puede ser de tamaño arbitrario (sin penalización). A partir de libtiff 4.5.0, tdir_t es un entero sin signo de 32 bits. Anteriormente, era un entero sin signo de 16 bits.

ttag_t debe ser int, unsigned int, puntero o double porque la biblioteca utiliza una interfaz varargs y C restringe el tipo del parámetro antes de una elipsis a un tipo promocionado. toff_t se define como uint64_t porque los desplazamientos de archivo TIFF son cantidades de 32 bits (sin signo), y los desplazamientos de archivo BigTIFF son cantidades de 64 bits sin signo. Se utiliza un valor con signo porque algunas interfaces devuelven -1 en caso de error. Finalmente, tenga en cuenta que las referencias de datos especificadas por el usuario se pasan como manejadores opacos y solo se convierten en las capas más bajas donde se presume su tipo.

_TIFFmemcmp() compara el contenido de los búferes de memoria
_TIFFmemcpy() copia el contenido de un búfer a otro
_TIFFmemset() rellena el búfer de memoria con un byte constante
_TIFFMultiply32() verifica el desbordamiento de enteros del resultado de la multiplicación de uint32_t y devuelve el resultado de la multiplicación o 0 si ocurriera un desbordamiento
_TIFFMultiply64() verifica el desbordamiento de enteros del resultado de la multiplicación de uint64_t y devuelve el resultado de la multiplicación o 0 si ocurriera un desbordamiento

USO DE ETIQUETAS

Para obtener una tabla de etiquetas TIFF reconocidas por la biblioteca, consulte Cobertura de LibTIFF de la Especificación TIFF 6.0.

“ETIQUETAS PSEUDO”

Además de las etiquetas TIFF normales, la biblioteca admite una colección de etiquetas cuyos valores se encuentran fuera del rango válido de etiquetas TIFF. Estas etiquetas se denominan etiquetas pseudo y se utilizan para controlar varias funciones específicas del codec dentro de la biblioteca. La siguiente tabla

resume las pseudo-etiquetas definidas.

LIBTIFF ETIQUETAS SOPORTADAS

Nombre de etiqueta Códec L/E Uso/Notas de la biblioteca
TIFFTAG_FAXMODE G3 L/E operación general del códec
TIFFTAG_FAXFILLFUNC G3/G4 L/E función de relleno de mapa de bits
TIFFTAG_JPEGQUALITY JPEG L/E control de calidad de compresión
TIFFTAG_JPEGCOLORMODE JPEG L/E control de conversiones de espacio de color
TIFFTAG_JPEGTABLESMODE JPEG L/E control del contenido de la etiqueta JPEGTables
TIFFTAG_ZIPQUALITY Deflate L/E nivel de calidad de compresión
TIFFTAG_PIXARLOGDATAFMT PixarLog L/E formato de datos del usuario
TIFFTAG_PIXARLOGQUALITY PixarLog L/E nivel de calidad de compresión
TIFFTAG_SGILOGDATAFMT SGILog L/E formato de datos del usuario

TIFFTAG_FAXMODE:

Controla la operación del códec Grupo 3. Los valores posibles (bits independientes que se pueden combinar mediante un OR bit a bit) son:

FAXMODE_CLASSIC:

(habilita el formato antiguo en el que se escribe el RTC al final de la última tira),

FAXMODE_NORTC:

(opuesto a FAXMODE_CLASSIC; también llamado FAXMODE_CLASSF),

FAXMODE_NOEOL:

(no escribe códigos EOL al inicio de cada fila de datos),

FAXMODE_BYTEALIGN:

(alinea cada fila codificada a un límite de 8 bits),

FAXMODE_WORDALIGN:

(alinea cada fila codificada a un límite de 16 bits),

El valor predeterminado depende del esquema de compresión; esta pseudo-etiqueta es utilizada por los diversos códecs G3 y G4 para compartir código.

TIFFTAG_FAXFILLFUNC:

Controla la función utilizada para convertir arrays de tiras negras y blancas en arrays de bits empaquetados. Este gancho se puede utilizar para crear imágenes de líneas de escaneo decodificadas en rásteres de profundidad multicanal (por ejemplo, para visualización en modo de mapa de colores) o para otros propósitos. El valor predeterminado es un puntero a una función incorporada que crea imágenes de datos bívalentes empaquetados.

TIFFTAG_IPTCNEWSPHOTO:

La etiqueta contiene metadatos de imagen según la especificación IPTC newsphoto: titular, subtitulado, crédito, etc. Utilizada por la mayoría de los servicios de noticias.

TIFFTAG_PHOTOSHOP:

La etiqueta contiene información de subtitulado y metadatos de Photoshop. Photoshop la usa en paralelo y de forma redundante junto con la información IPTCNEWSPHOTO.

TIFFTAG_JPEGQUALITY:

Controla el nivel de calidad de compresión utilizado en el algoritmo base. Tenga en cuenta que los niveles de calidad están en el rango 0-100 con un valor predeterminado de 75.

TIFFTAG_JPEGCOLORMODE:

Controla si se realiza o no la conversión entre los espacios de color RGB y YCbCr. Los valores posibles son:

JPEGCOLORMODE_RAW:

(no convertir), y

JPEGCOLORMODE_RGB:

(convertir a/desde RGB)

El valor predeterminado es JPEGCOLORMODE_RAW.

TIFFTAG_JPEGTABLESMODE:

Controla la información escrita en la etiqueta JPEGTables. Los valores posibles (bits independientes que se pueden combinar mediante un OR bit a bit) son:

JPEGTABLESMODE_QUANT:

(incluir tablas de cuantización), y

JPEGTABLESMODE_HUFF:

(incluir tablas de codificación Huffman).

El valor predeterminado es JPEGTABLESMODE_QUANT | JPEGTABLESMODE_HUFF.

TIFFTAG_ZIPQUALITY:

Controla la técnica de compresión utilizada por el códec Deflate. Los niveles de calidad están en el rango de 1 a 9, donde números más altos producen mejor compresión a costa de más cálculo. El nivel de calidad predeterminado es 6, lo que proporciona un buen equilibrio entre tiempo y espacio.

TIFFTAG_PIXARLOGDATAFMT:

Controla el formato de los datos del usuario que se pasan *a* el códec PixarLog al codificar y que se pasan *desde* al decodificar. Los valores posibles son:

PIXARLOGDATAFMT_8BIT:

para píxeles sin signo de 8 bits,

PIXARLOGDATAFMT_8BITABGR:

para píxeles sin signo de 8 bits con orden ABGR,

PIXARLOGDATAFMT_11BITLOG:

para datos sin procesar codificados en logaritmo de 11 bits,

PIXARLOGDATAFMT_12BITPICIO:

para datos compatibles con PICIO de 12 bits,

PIXARLOGDATAFMT_16BIT:

para muestras con signo de 16 bits, y

PIXARLOGDATAFMT_FLOAT:

para muestras de punto flotante IEEE de 32 bits.

TIFFTAG_PIXARLOGQUALITY:

Controla la técnica de compresión utilizada por el códec PixarLog. Este valor se trata de manera idéntica a TIFFTAG_ZIPQUALITY; consulte la descripción anterior.

TIFFTAG_SGILOGDATAFMT:

Controla el formato de los datos del cliente que se pasan *a* el códec SGILog al codificar y que se pasan *desde* al decodificar. Los valores posibles son:

SGILOGDATAFMT_FLTXYZ:

para convertir entre píxeles LogLuv y XYZ de punto flotante IEEE de 32 bits,

SGILOGDATAFMT_16BITLUV:

para píxeles Luv codificados de 16 bits,

SGILOGDATAFMT_32BITRAW: SGILOGDATAFMT_24BITRAW:

para no convertir datos,

SGILOGDATAFMT_8BITRGB:

para devolver datos RGB de 8 bits (válido solo al decodificar datos codificados en LogLuv),

SGILOGDATAFMT_FLTY:

para convertir entre LogL y píxeles Y de punto flotante IEEE de 32 bits,

SGILOGDATAFMT_16BITL:

para píxeles L codificados de 16 bits, y

SGILOGDATAFMT_8BITGRY:

para devolver datos en escala de grises de 8 bits (válido solo al decodificar datos codificados en LogL).

DIAGNÓSTICOS

Todos los mensajes de error se dirigen a través de la rutina TIFFErrorExtR(). Por defecto, los mensajes se dirigen a stderr con el formato: módulo: mensaje\n. Los mensajes de advertencia se dirigen de manera similar a través de la rutina TIFFWarningExtR().

ERRORES
