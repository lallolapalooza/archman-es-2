NOMBRE

libnbd-release-notes-1.8 - notas de lanzamiento para libnbd 1.8

DESCRIPCIÓN

Estas son las notas de lanzamiento para la versión estable 1.8 de libnbd. Describe los principales cambios desde la 1.6.

libnbd 1.8.0 fue lanzado el 7 de junio de 2021.

libnbd ahora está alojado en gitlab: https://listman.redhat.com/archives/libguestfs/2021-February/msg00021.html

Seguridad

Si encuentras un problema de seguridad, por favor lee SECURITY en el código fuente (en línea aquí: https://gitlab.com/nbdkit/libnbd/blob/master/SECURITY). Para saber sobre problemas de seguridad anteriores en libnbd, consulta libnbd-security(3).

Se encontró un error de seguridad en libnbd durante este ciclo de lanzamiento.

CVE-2021-20286 denegación de servicio al usar nbd_set_opt_mode(3)

Consulta el anuncio completo aquí: https://listman.redhat.com/archives/libguestfs/2021-March/msg00092.html (Encontrado y corregido por Eric Blake).

Nuevas APIs

nbd_get_private_data(3)
nbd_set_private_data(3)
Estas llamadas te permiten almacenar un entero sin signo o un puntero en el manejador para que la aplicación lo use para sus propios fines.
nbd_get_uri(3)
Esta llamada construye una URI NBD que se puede usar para conectarse al mismo servidor (usando nbd_connect_uri(3) o desde otras herramientas que soporten el estándar URI NBD).

Mejoras a APIs existentes

Las URIs numéricas de IPv6 (como "nbd://[::1]/") ahora son compatibles.

libnbd proporciona un mejor mensaje de error si la cola del servidor se desborda (gracias a Xin Long, Lukas Doktor, Eric Blake, Martin Kletzander).

Nuevas características

Las pruebas de integración continua (CI) ahora se ejecutan en cada commit y solicitud de fusión al repositorio principal (Martin Kletzander).

Herramientas

Se ha realizado una gran cantidad de trabajo para mejorar el rendimiento de nbdcopy(1) (Nir Soffer, Eric Blake).

En Linux, nbdcopy ahora usa readahead al leer de archivos y toma medidas para preservar la caché de páginas del host.

La nueva opción --request-size de nbdcopy permite controlar el tamaño de las solicitudes realizadas a los servidores NBD. Ajustar esto puede afectar el rendimiento (Nir Soffer).

nbdcopy ahora admite el pseudo-objetivo "null:", donde descarta la salida. Esto es útil para la medición de rendimiento.

nbdcopy tiene una nueva bandera -v para habilitar libnbd y otras depuraciones.

--list de nbdinfo(1) (que lista todas las exportaciones de un servidor) ya no sale prematuramente si una de las exportaciones es inaccesible o hay un error recuperable (Eric Blake).

nbdinfo ahora imprime la URI de cada exportación en la salida, lo que facilita la reconexión a cada exportación.

nbdfuse(1) ahora es multihilo y admite la emisión de comandos NBD paralelos en una sola conexión, así como multi-conexión, y se han realizado otras mejoras. Esto resultó en una mejora de rendimiento de alrededor del 50% cuando se probó con fio.

nbdfuse ahora admite el estilo nbdcopy de "[ CMD ]", por ejemplo:
nbdfuse dir/ramdisk [ nbdkit memory 1G ]

nbdfuse ahora admite trimming. También admite el relleno rápido de ceros, pero esto requiere un parche de kernel próximo antes de que funcione.

nbdfuse establece los permisos de archivo virtuales apropiadamente si la exportación NBD es de solo lectura.

nbdfuse tiene una nueva bandera -v para habilitar libnbd y otras depuraciones.

Pruebas

Se añadió una prueba de interoperabilidad con qemu-storage-daemon(1). Ten en cuenta que qemu-storage-daemon estaba roto en qemu 6.0.0, por lo que esta prueba puede fallar a menos que actualices a una versión corregida (gracias Stefan Hajnoczi, Daniel Berrangé).

Se añadió una prueba de nbdcopy con TLS, que anteriormente no se había probado.

Las pruebas de estilo de código Python ahora son opcionales usando
./configure --enable-python-code-style

Más pruebas ahora deberían ejecutarse en FreeBSD y no ser omitidas.

Las pruebas de nbdfuse ahora aseguran que los errores de NBD se transmitan a través de FUSE de vuelta al cliente local.

"MALLOC_CHECK_" y "MALLOC_PERTURB_" solo se habilitan al ejecutar las pruebas, no al ejecutar programas libnbd desde el directorio de compilación. Esto facilita la realización de mediciones de rendimiento.

Otras mejoras y correcciones de errores

El compilador C mínimo ahora es ISO C99 (anteriormente ANSI C90).

Ahora se requiere FUSE 3 (en lugar de FUSE 2) para compilar nbdfuse.

La biblioteca intenta con más ahínco no filtrar memoria de almacenamiento local de hilos en dlclose o salida. (Debido al diseño de Linux, no siempre es posible evitar esto, especialmente en programas multihilo).

Corrige la barra de progreso en nbdcopy(1).

Los nombres de exportación UTF-8 ahora se procesan y muestran correctamente por nbdinfo(1).

La salida de --help de nbdcopy, nbdfuse y nbdinfo ahora muestra un breve resumen de todas las opciones y tiene algunos ejemplos.

El generador ahora solo requiere ocamlc, no ocamlfind (Abhay Raj Singh).

Las vinculaciones de Golang ahora usan y requieren módulos de golang.

Documentación

Documenta el uso de libnbd con el sistema de compilación Meson.

Se añadieron ejemplos en Python.

Añade un ejemplo de cómo integrar libnbd con libev (Nir Soffer).
