CHACHA(3) Manual de Funciones de Librería CHACHA(3)

NOMBRE

ChaCha_set_key, ChaCha_set_iv, ChaCha, CRYPTO_chacha_20, CRYPTO_hchacha_20, CRYPTO_xchacha_20 — Cifrador de flujo ChaCha20

SINOPSIS

librería “libcrypto”
#include <openssl/chacha.h>

void
ChaCha_set_key(ChaCha_ctx *ctx, const unsigned char *key, unsigned int keybits);

void
ChaCha_set_iv(ChaCha_ctx *ctx, const unsigned char *iv, const unsigned char *counter);

void
ChaCha(ChaCha_ctx *ctx, unsigned char *out, const unsigned char *in, size_t len);

void
CRYPTO_chacha_20(unsigned char *out, const unsigned char *in, size_t len, const unsigned char key[32], const unsigned char iv[8], uint64_t counter);

void
CRYPTO_hchacha_20(unsigned char out[32], const unsigned char key[32], const unsigned char iv[16]);

void
CRYPTO_xchacha_20(unsigned char *out, const unsigned char *in, size_t len, const unsigned char key[32], const unsigned char iv[24]);

DESCRIPCIÓN

Estas funciones proporcionan una implementación de bajo nivel del cifrador de flujo ChaCha20 con claves de 256 y 128 bits. El número de rondas está codificado en 20; las variantes con 8 o 12 rondas no son soportadas.

En lugar de usar estas funciones directamente, los programas de aplicación normalmente utilizan la interfaz de alto nivel más portable EVP_chacha20(3).

El estado de ChaCha se contiene en la estructura ChaCha_ctx y consta de dieciséis enteros sin signo de 32 bits.

Para el valor recomendado de keybits de 256, ChaCha_set_key() copia 32 bytes (256 bits) de key a los ocho enteros centrales del estado ChaCha, usando orden little endian para cada entero. Para el valor alternativo de 128 keybits, solo se copian 16 bytes (128 bits) de key al estado ChaCha, pero se copian dos veces, una al segundo cuarto y otra al tercer cuarto. El primer cuarto del estado ChaCha se establece a cuatro enteros constantes; estas constantes difieren según si keybits es 128 o 256. El último cuarto del estado ChaCha permanece sin cambios.

ChaCha_set_iv() copia ocho bytes (64 bits) de counter y ocho bytes (64 bits) de iv al último cuarto del estado ChaCha, el contador a los dos primeros enteros y el vector de inicialización a los dos últimos enteros, nuevamente en orden little endian. Si counter es NULL, los dos enteros respectivos se establecen a 0 en su lugar. Los tres primeros cuartos del estado ChaCha permanecen sin cambios.

ChaCha() cifra len bytes de datos desde in a out usando el ctx que fue previamente configurado con ChaCha_set_key() y ChaCha_set_iv(). La responsabilidad del llamador es proporcionar un búfer out de al menos len bytes. Esta función puede ser llamada múltiples veces en secuencia con argumentos len variables. len no necesita ser un múltiplo de 64.

CRYPTO_chacha_20() cifra len bytes de datos desde in a out en una operación de un solo uso, utilizando la key y ivChaCha_set_key() y ChaCha_set_iv() y copiando la mitad menos significativa de counter al primer entero del contador en el estado ChaCha inicial y la mitad más significativa al segundo entero. La responsabilidad del llamador es nuevamente proporcionar un búfer out de al menos len bytes. El valor máximo soportado para len es 2^32 - 1.

XChaCha es una variante de ChaCha diseñada para soportar nonces más largos, al igual que XSalsa20 es una variante de Salsa20 que soporta nonces más largos.

CRYPTO_xchacha_20() cifra len bytes de datos desde in a out en una operación de un solo uso con el algoritmo XChaCha, utilizando la key y iv dadas. Es equivalente a CRYPTO_chacha_20() con el último tercio de iv, un counter de 0 y una clave generada con CRYPTO_hchacha_20() a partir de los dos primeros tercios de iv.

ESTÁNDARES

RFC 8439: ChaCha20 y Poly1305 para Protocolos IETF

Tenga en cuenta que el estándar especifica un contador de 32 bits y un vector de inicialización de 96 bits, mientras que esta implementación sigue la especificación original de Bernstein y utiliza un contador de 64 bits y un vector de inicialización de 64 bits.

Estas funciones son específicas de LibreSSL y no las proporciona OpenSSL. BoringSSL sí proporciona CRYPTO_chacha_20(), pero con una interfaz incompatible, que toma un iv de 96 bits y un counter de 32 bits.

HISTORIA

ChaCha_set_key(), ChaCha_set_iv(), ChaCha(), y CRYPTO_chacha_20() aparecieron por primera vez en OpenBSD 5.6.

CRYPTO_hchacha_20() y CRYPTO_xchacha_20() aparecieron por primera vez en OpenBSD 6.5.
