NOMBRE

libpfm_intel_icl - soporte para PMU Intel IceLake core

SINOPSIS

#include <perfmon/pfmlib.h>

Nombre PMU: icl
Descripción PMU: Intel IceLake

DESCRIPCIÓN

La biblioteca soporta el PMU del núcleo Intel IceLake. Cabe señalar que este modelo PMU solo cubre el PMU de cada núcleo y no el PMU a nivel de socket.

En IceLake, el número de contadores genéricos depende del modo Hyperthreading (HT).

La función pfm_get_pmu_info() devuelve el número máximo de contadores genéricos en num_cntrs.

MODIFICADORES

Los siguientes modificadores son compatibles con los procesadores Intel IceLake:

u
Medir a nivel de usuario, lo que incluye los niveles de privilegio 1, 2, 3. Esto corresponde a PFM_PLM3. Este es un modificador booleano.
k
Medir a nivel de kernel, lo que incluye el nivel de privilegio 0. Esto corresponde a PFM_PLM0. Este es un modificador booleano.
i
Invertir el significado del evento. El contador ahora contará los ciclos en los que el evento no ocurre. Este es un modificador booleano.
e
Habilitar la detección de flanco, es decir, contar solo cuando hay una transición de estado de no ocurrencia del evento a al menos una ocurrencia. Este modificador debe combinarse con un modificador de máscara de contador (m) con un valor mayor o igual a uno. Este es un modificador booleano.
c
Establecer el valor de la máscara del contador. La máscara actúa como un umbral. El contador contará el número de ciclos en los que el número de ocurrencias del evento es mayor o igual al umbral. Este es un modificador entero con valores en el rango [0:255].
ldlat
Pasar un umbral de latencia al evento MEM_TRANS_RETIRED:LOAD_LATENCY. Este es un atributo entero que debe estar en el rango [1:65535]. Es obligatorio para este evento. Tenga en cuenta que el evento debe usarse con muestreo preciso (PEBS).
intx
Monitorizar el evento solo cuando se ejecuta dentro de una región de memoria transaccional (en tx). El evento no cuenta de lo contrario. Este es un modificador booleano. El valor predeterminado es 0.
intxcp
No contar las ocurrencias del evento cuando están dentro de una región de memoria transaccional abortada. Este es un modificador booleano. El valor predeterminado es 0.
fe_thres
Este modificador es solo para el evento FRONTEND_RETIRED. Define el período en ciclos de núcleo después del cual se cuentan las máscaras de bits IDQ_*_BUBBLES. Actúa como un umbral, es decir, al menos un período de N ciclos de núcleo en los que el frontend no entregó X uops. Solo se puede usar con las máscaras de bits IDQ_*_BUBBLES. Si no se especifica, el valor del umbral predeterminado es 1 ciclo. Los valores válidos están en [1-4095].

eventos OFFCORE_RESPONSE

Intel IceLake soporta dos codificaciones para los eventos offcore_response. En la biblioteca, se denominan OFFCORE_RESPONSE_0 y OFFCORE_RESPONSE_1.

Estos eventos requieren un tratamiento especial en la infraestructura de monitorización de rendimiento porque cada evento utiliza un registro adicional para almacenar algunas configuraciones. Por lo tanto, en caso de que se monitoricen varios eventos offcore_response simultáneamente, el sistema operativo necesita gestionar el intercambio de ese registro adicional.

Los eventos offcore_response se exponen como eventos normales en la biblioteca. La configuración adicional se expone como máscaras de bits regulares. La biblioteca se encarga de codificar los eventos de acuerdo con la interfaz del kernel subyacente.

En Intel IceLake, a diferencia de procesadores anteriores, el evento se trata como un evento regular con un conjunto plano de máscaras de bits para elegir. No es posible combinar las diversas solicitudes, proveedor, bits de snoop. Por lo tanto, la biblioteca ofrece la lista de combinaciones validadas según la lista oficial de eventos de Intel.

Topdown vía PERF_METRICS

Intel Icelake soporta el MSR PERF_METRICS que proporciona soporte para Topdown Nivel 1 a través de un único contador PMU. Este contador especial proporciona porcentajes de ranuras para cada métrica. Esta función debe usarse junto con el contador fijo 3, que cuenta RANURAS, para funcionar correctamente. El kernel de Linux expone las métricas PERF_METRICS como eventos pseudo individuales que cuentan en unidades de ranuras, sin embargo, para operar correctamente, todos los eventos deben programarse juntos. El kernel de Linux requiere que todos los eventos PERF_METRICS se programen como un único grupo de eventos con el primer evento como RANURAS requerido. Ejemplo: '{slots,topdown-retiring,topdown-bad-spec,topdown-fe-bound,topdown-be-bound,topdown-heavy-ops,topdown-br-mispredict,topdown-fetch-lat,topdown-mem-bound}'. Libpfm4 proporciona acceso a los eventos pseudo PERF_METRICS a través de un evento dedicado llamado TOPDOWN_M. Este evento utiliza las codificaciones pseudo asignadas por el kernel de Linux a los eventos pseudo PERF_METRICS. El uso de estas codificaciones asegura que el kernel los detecte como dirigidos al MSR PERF_METRICS. Tenga en cuenta que libpfm4 solo proporciona las codificaciones y que depende del usuario en Linux agruparlos y ordenarlos adecuadamente para la interfaz perf_events. Existen codificaciones de contador genéricas para la mayoría de las métricas Topdown y libpfm4 proporciona soporte para ellas a través del evento TOPDOWN. Tenga en cuenta que todos los subeventos de TOPDOWN_M utilizan contadores fijos que, por definición, no tienen códigos de evento reales. La biblioteca utiliza los códigos de eventos pseudo de Linux para ellos, incluso cuando se compila en sistemas operativos que no son Linux. Lo mismo ocurre con cualquier evento pseudo de contador fijo exportado por libpfm4.
