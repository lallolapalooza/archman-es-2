libressl-SSL_CTX_set_tlsext_use_srtp(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_CTX_SET_TLSEXT_USE_SRTP(3) Manual de funciones de biblioteca SSL_CTX_SET_TLSEXT_USE_SRTP(3)

NOMBRE

SSL_CTX_set_tlsext_use_srtp, SSL_set_tlsext_use_srtp, SSL_get_srtp_profiles, SSL_get_selected_srtp_profile — Configurar y consultar soporte SRTP

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/srtp.h>

int
SSL_CTX_set_tlsext_use_srtp(SSL_CTX *ctx, const char *profiles);

int
SSL_set_tlsext_use_srtp(SSL *ssl, const char *profiles);

STACK_OF(SRTP_PROTECTION_PROFILE) *
SSL_get_srtp_profiles(SSL *ssl);

SRTP_PROTECTION_PROFILE *
SSL_get_selected_srtp_profile(SSL *ssl);

DESCRIPCIÓN

SRTP es el Protocolo de Transporte Seguro en Tiempo Real. OpenSSL implementa soporte para la extensión DTLS "use_srtp" definida en la RFC 5764. Esto proporciona un mecanismo para establecer material de clave SRTP, algoritmos y parámetros usando DTLS. Esta capacidad puede ser utilizada como parte de una implementación que cumpla con la RFC 5763. OpenSSL no implementa SRTP en sí mismo ni la RFC 5763. Tenga en cuenta que OpenSSL no soporta el uso de Identificadores de Clave Maestra SRTP (MKI). Tenga en cuenta también que esta extensión solo se soporta en DTLS. Cualquier configuración SRTP se ignora si se intenta una conexión TLS.

Un cliente OpenSSL que desee enviar la extensión "use_srtp" debe llamar a SSL_CTX_set_tlsext_use_srtp() para establecer su uso para todos los objetos SSL creados posteriormente a partir de ctx. Alternativamente, un cliente puede llamar a SSL_set_tlsext_use_srtp() para establecer su uso para un objeto SSL individual. El parámetro profiles debe apuntar a una lista separada por dos puntos y terminada en NUL de nombres de perfiles de protección SRTP.

Los nombres de perfiles de protección actualmente soportados son:

SRTP_AES128_CM_SHA1_80
Esto corresponde a SRTP_AES128_CM_HMAC_SHA1_80 definido en la RFC 5764.
SRTP_AES128_CM_SHA1_32
Esto corresponde a SRTP_AES128_CM_HMAC_SHA1_32 definido en la RFC 5764.
SRTP_AEAD_AES_128_GCM
Esto corresponde a SRTP_AEAD_AES_128_GCM definido en la RFC 7714.
SRTP_AEAD_AES_256_GCM
Esto corresponde a SRTP_AEAD_AES_256_GCM definido en la RFC 7714.

Proporcionar un nombre de perfil de protección no reconocido resulta en un error.

Un servidor OpenSSL que desee soportar la extensión "use_srtp" también debe llamar a SSL_CTX_set_tlsext_use_srtp() o SSL_set_tlsext_use_srtp() para indicar los perfiles de protección que está dispuesto a negociar.

La lista de perfiles de protección configurados actualmente para un cliente o un servidor puede obtenerse llamando a SSL_get_srtp_profiles(). Esto devuelve una pila de objetos SRTP_PROTECTION_PROFILE. La memoria apuntada en el valor de retorno de esta función no debe ser liberada por el llamante.

Después de que se haya completado un handshake, el perfil de protección SRTP negociado (si lo hay) puede obtenerse (en el cliente o en el servidor) llamando a SSL_get_selected_srtp_profile(). Esta función devuelve NULL si no se negoció ningún perfil de protección SRTP. La memoria devuelta por esta función no debe ser liberada por el llamante.

Si se ha negociado con éxito un perfil de protección SRTP, el material de clave SRTP (tanto en el cliente como en el servidor) debe obtenerse llamando a SSL_export_keying_material(3) con una etiqueta label de "EXTRACTOR-dtls_srtp", un contexto context de NULL, y un argumento use_context de 0. La longitud total del material de clave obtenido debe ser igual a dos veces la suma de la longitud de la clave maestra y la longitud de la sal, según se definen para el perfil de protección en uso. Esto proporciona la clave maestra de escritura del cliente, la clave maestra de escritura del servidor, la sal maestra de escritura del cliente y la sal maestra de escritura del servidor en ese orden.

VALORES DE RETORNO

Contrariamente a las convenciones de OpenSSL, SSL_CTX_set_tlsext_use_srtp() y SSL_set_tlsext_use_srtp() devuelven 0 en caso de éxito o 1 en caso de error.

SSL_get_srtp_profiles() devuelve una pila de objetos SRTP_PROTECTION_PROFILE en caso de éxito o NULL en caso de error o si no se han configurado perfiles de protección.

SSL_get_selected_srtp_profile() devuelve un puntero a un objeto SRTP_PROTECTION_PROFILE si se ha negociado uno o NULL en caso contrario.

VER TAMBIÉN

ssl(3), SSL_export_keying_material(3)
