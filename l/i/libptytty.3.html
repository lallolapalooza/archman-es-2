NOMBRE

libptytty - manejo independiente del SO y seguro de pty/tty y utmp/wtmp/lastlog

SINOPSIS

cc ... -lptytty
#include <libptytty.h>
// C++
ptytty *pty = ptytty::create ();
if (!pty->get ())
  // error al asignar pty
if (queremos utmp)
  pty->login (process_pid, 0, "remote.host");
else if (queremos utmp Y wtmp/lastlog)
  pty->login (process_pid, 1, "remote.host");
// hemos terminado con él
delete pty;
// C
PTYTTY pty = ptytty_create ();
if (!ptytty_get (pty))
  // error al asignar pty
if (queremos utmp)
  ptytty_login (pty, process_pid, 0, "remote.host");
else if (queremos utmp Y wtmp/lastlog)
  ptytty_login (pty, process_pid, 1, "remote.host");
// hemos terminado con él
ptytty_delete (pty);

Ver también el directorio eg/, que actualmente contiene el archivo c-sample.c que inicia un shell de inicio de sesión desde C usando libptytty.

DESCRIPCIÓN

Libptytty es una pequeña biblioteca que ofrece gestión de pseudo-tty de forma independiente del SO. Fue creada a partir de la frustración por las muchas diferencias en el manejo de pty/tty en diferentes sistemas operativos para su uso dentro de "rxvt-unicode".

Además de ofrecer mera gestión de pty/tty, también ofrece soporte para bases de datos de sesiones (actualizaciones de utmp y opcionalmente wtmp/lastlog para shells de inicio de sesión).

También admite la bifurcación (fork'ing) después del inicio y la reducción de privilegios en el proceso llamante, por lo que en caso de que el proceso llamante se vea comprometido por el usuario que inicia el programa, hay menos que ganar, ya que solo el proceso auxiliar se ejecuta con privilegios (por ejemplo, setuid/setgid), lo que reduce enormemente el área de ataque.

Libptytty está escrita en C++, pero también ofrece una API solo en C.

INSTALACIÓN

libptytty utiliza "CMake" como sistema de compilación. Para compilar libptytty, instala "CMake" y ejecuta los siguientes comandos desde el directorio de código fuente de libptytty o desde un directorio de compilación separado:

cmake -DCMAKE_INSTALL_PREFIX=<prefijo> -DBUILD_SHARED_LIBS=ON <ruta/a/libptytty>
cmake --build .
cmake --install .

CONSIDERACIONES DE SEGURIDAD

¡Es de suma importancia que al menos lea el siguiente párrafo!

Si escribe un programa típico similar a un terminal que solo desea una o más ptys, debe llamar al método "ptytty::init ()" (función C: "ptytty_init ()") como lo primerísimo en su programa:

int main (int argc, char *argv[])
{
   // no hacer nada aquí
   ptytty::init ();
   // en C: ptytty_init ();
   // inicializar, analizar argumentos, etc.
}

Esto comprueba si el programa se ejecuta con permisos setuid o setgid. Si es así, bifurcará un proceso auxiliar y reducirá los privilegios.

Algunos programas necesitan un control más fino sobre si y cuándo se inicia este proceso auxiliar, y si y cómo reducir privilegios. Para esos programas, los métodos "ptytty::use_helper" y "ptytty::drop_privileges" (y posiblemente "ptytty::sanitise_stdfd") son más útiles.

INTERFAZ C++: LA CLASE ptytty

MÉTODOS ESTÁTICOS

ptytty::init ()
La forma predeterminada de inicializar libptytty. Debe llamarse inmediatamente como lo primerísimo en la función "main", o antes, por ejemplo, en tiempo de construcción estática. Cuanto antes, mejor.

Este método llama a "sanitise_stdfd" y luego comprueba si el programa se ejecuta con permisos setuid/setgid y, si es así, inicia un proceso auxiliar para la gestión de pty/tty. Luego reduce completamente los privilegios, por lo que el programa real se ejecuta sin privilegios setuid/setgid.

En caso de fallo, este método lanza una excepción "ptytty_error".

ptytty::use_helper ()
Intenta iniciar un proceso auxiliar que conserve los privilegios incluso cuando el proceso llamante no lo hace. Esto se llama normalmente desde "ptytty::init" cuando detecta que el programa se ejecuta setuid o setgid, pero se puede llamar manualmente si es inconveniente reducir los privilegios al inicio, o cuando no se está ejecutando setuid/setgid pero se desea reducir privilegios (por ejemplo, cuando se ejecuta como un demonio iniciado por root).

Este método intentará no iniciar más de un proceso auxiliar. El mismo proceso auxiliar generalmente puede ser utilizado tanto por el proceso que lo inicia como por todos sus hijos bifurcados (no ejecutados).

En caso de fallo, este método lanza una excepción "ptytty_error".

ptytty::drop_privileges ()
Reduce completamente los privilegios, es decir, establece el ID de usuario real, efectivo y guardado al ID de usuario real. Útil para asegurarse de que el proceso no se ejecuta con privilegios especiales.

En caso de fallo, este método lanza una excepción "ptytty_error".

ptytty::sanitise_stdfd ()
Comprueba si los descriptores de archivo 0, 1 y 2 (stdin, stdout y stderr) son válidos (abiertos) y, si no lo son, los conecta a /dev/tty o /dev/null si es posible. Esto es necesario porque libptytty puede querer emitir mensajes de error a esos descriptores, que en el momento de emitir el mensaje de error, podrían estar conectados a algo inadecuado abierto por el programa desprevenido (esto puede ser un problema de seguridad).

En caso de fallo, este método lanza una excepción "ptytty_error".

bool éxito = ptytty::send_fd (int socket, int fd)
Método de utilidad para enviar un descriptor de archivo a través de un socket de dominio Unix. Devuelve verdadero si tiene éxito, falso en caso contrario. Este método solo se expone para su conveniencia y no es necesario para la operación normal.
int fd = ptytty::recv_fd (int socket)
Método de utilidad para recibir un descriptor de archivo a través de un socket de dominio Unix. Devuelve el fd si tiene éxito y "-1" en caso contrario. Este método solo se expone para su conveniencia y no es necesario para la operación normal.
ptytty *pty = ptytty::create ()
Crea un nuevo objeto ptytty. La creación aún no hace nada además de asignar la estructura.

Se utiliza un método estático porque la implementación real de ptytty puede diferir en tiempo de ejecución, por lo que necesita una instalación de creación de objetos dinámica.

MIEMBROS DE DATOS Y MÉTODOS DINÁMICOS/RELACIONADOS CON LA SESIÓN

int pty_fd = pty->pty
int tty_fd = pty->tty
Estos miembros contienen los descriptores de archivo pty y tty, respectivamente. Inicialmente contienen "-1" hasta una llamada exitosa a "ptytty::get".
bool éxito = pty->get ()
Intenta encontrar, asignar e inicializar un nuevo par pty/tty. Devuelve "true" cuando tiene éxito.

Si el proceso auxiliar se está ejecutando y hay un error de protocolo, este método lanza una excepción "ptytty_error".

C++ INTERFACE: THE ptytty CLASS

ptytty ()
Constructor. Creates a new PTY/tty pair. See "ptytty::create ()".
~ptytty ()
Destructor. Frees the pty/tty pair and cleans up the utmp/wtmp/lastlog databases, if initialised/used. Called automatically when the object goes out of scope.
pty ()
Returns the pty file descriptor.
tty ()
Returns the tty file descriptor.
operator bool ()
Returns true if the object is valid, false otherwise.
login (int cmd_pid, bool login_shell, const char *hostname)
Updates the utmp/wtmp/lastlog databases to record the new login.

Should be called from the child/tty process *after* forking, but *before* calling "make_controlling_tty ()".

cmd_pid is the PID of the child process, which will execute the command.

login_shell should be set to true if the child process will execute a login shell (e.g. "/bin/bash --login").

hostname is the "hostname" from which the user logs in, which is often the value of the "DISPLAY" variable or tty line in case of local logins.

Calling this method is optional. A session starts at the time of the login call and extends until the ptytty object is destroyed.

close_tty ()
Closes the tty. Useful after forking in the parent/pty process.
bool success = make_controlling_tty ()
Tries to make the pty/tty pair the controlling terminal of the current process. Useful after forking in the child/tty process.
set_utf8_mode (bool on)
On systems supporting special UTF-8 line disciplines (e.g. Linux), this tries to enable this discipline for the given pty. Can be called at any time to change the mode.
pty->close_tty ()
Closes the tty. Useful after forking in the parent/pty process.
bool success = pty->make_controlling_tty ()
Tries to make the pty/tty pair the controlling terminal of the current process. Useful after forking in the child/tty process.
pty->set_utf8_mode (bool on)
On systems supporting special UTF-8 line disciplines (e.g. Linux), this tries to enable this discipline for the given pty. Can be called at any time to change the mode.
pty->close_tty ()
Cierra el tty. Útil después de bifurcar en el proceso padre/pty.
bool success = pty->make_controlling_tty ()
Intenta hacer del par pty/tty la terminal controladora del proceso actual. Útil después de bifurcar en el proceso hijo/tty.
pty->set_utf8_mode (bool on)
En sistemas que soportan disciplinas de línea UTF-8 especiales (ej. Linux), esto intenta habilitar esta disciplina para el pty dado. Puede ser llamada en cualquier momento para cambiar el modo.

C INTERFACE: THE ptytty FAMILY OF FUNCTIONS

ptytty_init ()

PTYTTY ptytty_create ()
Crea y retorna un nuevo objeto opaco PTYTTY. No intentes acceder a él de ninguna manera excepto probándolo por su veracidad (ej. "if (pty) ...."). Ver "ptytty::create ()".
