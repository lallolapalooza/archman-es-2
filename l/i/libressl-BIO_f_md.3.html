NOMBRE

BIO_f_md, BIO_set_md, BIO_get_md, BIO_get_md_ctx, BIO_set_md_ctx — filtro BIO de resumen de mensajes

SINOPSIS

biblioteca “libcrypto”
#include <openssl/bio.h>
#include <openssl/evp.h>

const BIO_METHOD *
BIO_f_md(void);

long
BIO_set_md(BIO *b, EVP_MD *md);

long
BIO_get_md(BIO *b, EVP_MD **mdp);

long
BIO_get_md_ctx(BIO *b, EVP_MD_CTX **mdcp);

long
BIO_set_md_ctx(BIO *b, EVP_MD_CTX *mdc);

DESCRIPCIÓN

BIO_f_md() devuelve el método BIO de resumen. Este es un BIO de filtro que resume cualquier dato que se le pase. Es una envoltura BIO para las rutinas de resumen EVP_DigestInit(3), EVP_DigestUpdate(3), y EVP_DigestFinal(3).

BIO_set_md() establece el resumen de mensajes de b a md y lo inicializa usando EVP_DigestInit_ex(3). Se requiere llamar a esta función antes de que se pasen datos a través de b.

BIO_get_md() coloca un puntero al método de resumen de b en *mdp.

Cualquier dato escrito o leído a través de un BIO de resumen usando BIO_read(3) y BIO_write(3) es resumido.

BIO_gets(3), si su parámetro size es lo suficientemente grande, finaliza el cálculo del resumen y devuelve el valor del resumen. BIO_puts(3) no es compatible. Si una aplicación necesita llamar a BIO_gets(3) o BIO_puts(3) a través de una cadena que contiene BIOs de resumen, esto se puede hacer anteponiendo un BIO de búfer.

Después de que el resumen se haya recuperado de un BIO de resumen, llame a BIO_reset(3) para reinicializarlo y cualquier BIO subsiguiente en su cadena antes de pasar más datos a través de él. Si ningún BIO subsiguiente requiere reinicialización, BIO_set_md() puede usarse en lugar de BIO_reset(3).

BIO_get_md_ctx() coloca un puntero al contexto de resumen de b en *mdcp y marca el BIO como inicializado sin inicializarlo realmente. A menos que BIO_set_md() ya haya sido llamado en b, el llamador se hace responsable de inicializar el contexto de resumen con EVP_DigestInit_ex(3).

El contexto devuelto por BIO_get_md_ctx() se puede usar en llamadas a EVP_DigestFinal(3) y también en las rutinas de firma EVP_SignFinal(3) y EVP_VerifyFinal(3).

El contexto devuelto por BIO_get_md_ctx() es una estructura de contexto interna. Los cambios realizados en este contexto afectarán al propio BIO de resumen, y el puntero de contexto se invalidará cuando el BIO de resumen se libere.

BIO_set_md_ctx() reemplaza el contexto de resumen de b con mdc. La llamada a esta función generalmente no es necesaria porque la creación de un BIO de resumen con BIO_new(3) crea automáticamente un contexto de resumen y lo almacena internamente. Antes de llamar a BIO_set_md_ctx(), el llamador debe recuperar el contexto antiguo usando BIO_get_md_ctx(), y el llamador también se hace responsable de llamar a EVP_MD_CTX_free(3) en el contexto antiguo. A menos que mdc ya esté inicializado, el llamador necesita inicializarlo después de llamar a BIO_set_md_ctx() usando BIO_set_md() o EVP_DigestInit(3).

Cuando una cadena que contiene un BIO de resumen de mensajes se copia con BIO_dup_chain(3), EVP_MD_CTX_copy_ex(3) se llama internamente para copiar automáticamente el contexto de resumen de mensajes del objeto BIO existente al nuevo, y el indicador init que se puede recuperar con BIO_get_init(3) se establece en 1.

BIO_ctrl(3) los argumentos de cmd corresponden a macros como sigue:

cmd constante macro correspondiente
BIO_C_GET_MD BIO_get_md()
BIO_C_GET_MD_CTX BIO_get_md_ctx()
BIO_C_SET_MD BIO_set_md()
BIO_C_SET_MD_CTX BIO_set_md_ctx()
BIO_CTRL_RESET BIO_reset(3)

VALORES DE RETORNO

BIO_f_md() devuelve el método BIO de resumen.

Cuando se llama en un objeto BIO de resumen de mensajes, BIO_method_type(3) devuelve la constante BIO_TYPE_MD y BIO_method_name(3) devuelve un puntero a la cadena estática "message digest".

BIO_set_md() devuelve 1 en caso de éxito o 0 si EVP_DigestInit_ex(3) falla.

BIO_get_md() y BIO_set_md_ctx() devuelven 1 en caso de éxito o 0 si b no está inicializado.

BIO_get_md_ctx() devuelve 1 en caso de éxito o 0 en caso de fallo, pero la implementación actual no puede fallar realmente.

libressl(3) - BIO_f_md

NAME

BIO_f_md, BIO_new_md, BIO_set_md, BIO_get_md, BIO_get_md_ctx, BIO_set_md_ctx - message digest BIO filter

SYNOPSIS

#include <openssl/bio.h>

BIO *BIO_new_md(const EVP_MD *md);
int BIO_set_md(BIO *bio, const EVP_MD *md);
int BIO_get_md(BIO *bio, const EVP_MD **md);
EVP_MD_CTX *BIO_get_md_ctx(BIO *bio, EVP_MD_CTX **ctx);
int BIO_set_md_ctx(BIO *bio, EVP_MD_CTX *ctx);

DESCRIPTION

The digest BIOs provide digest computation services to a BIO chain. They can be inserted into a BIO chain using the BIO_push(3) function.

The digest BIO is an abstract BIO type, meaning that the underlying implementation is not directly exposed. The digest BIO can be created using BIO_new(BIO_f_md()) or more conveniently using BIO_new_md(md) which creates and initializes a digest BIO with the digest algorithm specified by md. md should be a digest algorithm obtained from EVP_get_digestbyname(3), EVP_get_digestbyobj(3), or EVP_sha1(3), etc.

The digest algorithm can be changed on an existing digest BIO using BIO_set_md(bio, md).

The digest algorithm currently configured for a digest BIO can be retrieved using BIO_get_md(bio, md), which stores a pointer to the algorithm in md. Note that the returned pointer is owned by the BIO and should not be freed.

The digest BIO uses an EVP_DigestInit(3) context internally to perform the digest operations. This context can be obtained using BIO_get_md_ctx(bio, ctx). If ctx is NULL, a new context will be allocated. If ctx is not NULL, then the context pointed to by ctx will be used. The digest algorithm and properties of the BIO will be updated to match the provided context. The context is owned by the BIO and should not be freed. Subsequent calls to BIO_get_md_ctx may return the same context pointer.

The digest context used by the BIO can be explicitly set using BIO_set_md_ctx(bio, ctx). This transfers ownership of the context to the BIO. The digest algorithm and properties of the BIO will be updated to match the provided context.

When data is written to a digest BIO, it is passed through to the next BIO in the chain and also digested. When data is read from a digest BIO, it is read from the next BIO in the chain. The digest BIO itself does not generate or buffer any data.

The digest result is retrieved by reading from the digest BIO after all the input data has been written. The read operation will return the digest result, and subsequent reads will return 0. The digest result is zero-padded if necessary.

Digests computed by a digest BIO can be retrieved using BIO_gets(3). The digest result is returned as a string of hexadecimal characters. The digest is computed after all data has been written to the BIO. A successful read returns the number of bytes read, which is the length of the digest. Subsequent reads will return 0.

The digest BIO supports the BIO_CTRL_DUP control operation, which duplicates the digest BIO and its internal digest context. This allows multiple independent digest computations to be derived from a single digest BIO chain.

RETURN VALUES

BIO_new_md, BIO_set_md, BIO_get_md_ctx, and BIO_set_md_ctx return 1 on success and 0 on failure.

BIO_get_md returns 1 on success and 0 on failure.

BIO_get_md_ctx returns the digest context on success, and NULL on failure.

EXAMPLES

The following example digests a string and prints the resulting digest:

#include <openssl/bio.h>
#include <openssl/evp.h>
#include <string.h>
#include <stdio.h>

int main() {
    BIO *bio, *mdtmp;
    const char *message = "This is a test message.";
    unsigned char mdbuf[EVP_MAX_MD_SIZE];
    int mdlen;
    int i;

    /* Use BIO_f_md() to create a digest BIO */
    mdtmp = BIO_new(BIO_f_md());
    BIO_set_md(mdtmp, EVP_sha256()); /* Set the digest algorithm */

    /* Push the digest BIO onto a memory BIO */
    bio = BIO_new_mem_buf(message, strlen(message));
    bio = BIO_push(mdtmp, bio);

    /* Read through the BIO to compute the digest */
    do {
        mdlen = BIO_read(bio, mdbuf, sizeof(mdbuf));
    } while (mdlen > 0);

    /* Retrieve the digest */
    mdlen = BIO_gets(bio, (char *)mdbuf, sizeof(mdbuf));
    printf("SHA256 digest: ");
    for(i = 0; i < mdlen; i++)
        printf("%02X", mdbuf[i]);
    printf("\n");

    /* Clean up */
    BIO_free_all(bio);

    return 0;
}

Note that BIO_write is not used in this example, as the data is provided via a memory BIO. If writing data directly, you would use BIO_write.

This next example retrieves the message digests from a BIO chain and outputs them. This could be used with the examples above.

BIO *mdtmp;
unsigned char mdbuf[EVP_MAX_MD_SIZE];
int mdlen;
int i;

/* Assume 'bio' is the head of a BIO chain containing digest BIOs */
/* mdtmp = bio; */

/* For demonstration, let's create a chain and then retrieve */
BIO *bio = BIO_new(BIO_f_null()); /* Dummy BIO to start */
BIO *digest_bio_md5 = BIO_new(BIO_f_md());
BIO_set_md(digest_bio_md5, EVP_md5());
bio = BIO_push(digest_bio_md5, bio);

BIO *digest_bio_sha1 = BIO_new(BIO_f_md());
BIO_set_md(digest_bio_sha1, EVP_sha1());
bio = BIO_push(digest_bio_sha1, bio);

/* Write some data to trigger digest computation */
BIO_write(bio, "Data for digest.", 16);

/* Now, iterate through the chain to find digest BIOs and get digests */
mdtmp = bio; /* Start from the head of the chain */
do {
	EVP_MD *md;
	/* Find the next digest BIO in the chain */
	mdtmp = BIO_find_type(mdtmp, BIO_TYPE_MD);
	if (!mdtmp)
		break;

	/* Get the digest algorithm associated with this BIO */
	BIO_get_md(mdtmp, &md);

	/* Print the digest algorithm name */
	printf("Digest: %s", OBJ_nid2sn(EVP_MD_type(md)));

	/* Retrieve the digest result */
	mdlen = BIO_gets(mdtmp, (char *)mdbuf, sizeof(mdbuf));
	if (mdlen > 0) {
		printf(" digest: ");
		for(i = 0; i < mdlen; i++)
			printf("%02X", mdbuf[i]);
		printf("\n");
	} else {
		printf(" (Could not retrieve digest)\n");
	}

	/* Move to the next BIO in the chain */
	mdtmp = BIO_next(mdtmp);
} while(mdtmp);

/* Free the entire chain */
BIO_free_all(bio);

HISTORY

BIO_f_md(), BIO_set_md(), and BIO_get_md() first appeared in SSLeay 0.6.0. BIO_get_md_ctx() first appeared in SSLeay 0.8.1. These functions have been available since OpenBSD 2.4.

BIO_set_md_ctx() first appeared in OpenSSL 0.9.7e and has been available since OpenBSD 3.8.

Before OpenSSL 1.0.0, the call to BIO_get_md_ctx() would only work if the BIO had been initialized, for example by calling BIO_set_md().

BUGS

The lack of support for BIO_puts(3) and the non-standard behaviour of BIO_gets(3) could be regarded as anomalous. It could be argued that BIO_gets(3) and BIO_puts(3) should be passed to the next BIO in the chain and digest the data passed through and that digests should be retrieved using a separate BIO_ctrl(3) call.
