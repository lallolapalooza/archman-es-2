LISP(1) Manual de Comandos Generales LISP(1)

NOMBRE

lisp - Entorno de programación CMU Common Lisp

SINOPSIS

lisp [archivos-de-entrada] [lista-de-opciones]

DESCRIPCIÓN

lisp Inicia CMU Common Lisp. Si lista-de-opciones está vacía, entonces Lisp entrará en un bucle de lectura-evaluación-impresión utilizando stdin, stdout y stderr. Los archivos-de-entrada opcionales proporcionan operandos para algunas opciones. Estas opciones están definidas:

-ayuda
Imprime las opciones de la línea de comandos y sale.
--ayuda
Igual que -ayuda.
-core nombre-archivo
Especifica la imagen Lisp suspendida (o `archivo core') para iniciar.
-lib ruta-libreria
Una lista de directorios separados por dos puntos que se utilizarán para la lista de búsqueda de la biblioteca.
-batch
Hace que Lisp se ejecute en modo batch, donde toda la entrada se dirige desde la entrada estándar. Se devuelve un código de retorno de Unix de 0 al encontrar un EOF, mientras que cualquier condición de error no manejada provocará una salida inmediata con un código de retorno de 1, en lugar de entrar en el depurador.
-quiet
Hace que Lisp se inicie silenciosamente, deshabilitando la impresión del encabezado y suprimiendo la mayor parte del ruido innecesario, como mensajes de GC, mensajes de carga, etc.
-dynamic-space-size
Requiere un argumento que debe ser el número de megabytes (1048576 bytes) que se asignarán al heap. Si no se especifica, se utiliza un valor predeterminado específico de la plataforma. El tamaño máximo real permitido del heap es específico de la plataforma.
-read-only-space-size
Requiere un argumento que debe ser el número de megabytes (1048576 bytes) que se asignarán al espacio de solo lectura. Si no se especifica, se utiliza un valor predeterminado específico de la plataforma.
-static-space-size
Requiere un argumento que debe ser el número de megabytes (1048576 bytes) que se asignarán al espacio estático. Si no se especifica, se utiliza un valor predeterminado específico de la plataforma. El tamaño máximo real permitido del heap es específico de la plataforma.
-control-stack-size
Requiere un argumento que debe ser el número de megabytes (1048576 bytes) que se asignarán a la pila de control. Si no se especifica, se utiliza un valor predeterminado específico de la plataforma. El tamaño máximo real permitido del heap es específico de la plataforma.
-binding-stack-size
Requiere un argumento que debe ser el número de megabytes (1048576 bytes) que se asignarán a la pila de enlaces. Si no se especifica, se utiliza un valor predeterminado específico de la plataforma. El tamaño máximo real permitido del heap es específico de la plataforma. -edit Hace que Lisp entre en el editor Hemlock. Se puede especificar un archivo para editar colocando el nombre del archivo entre el nombre del programa (generalmente `lisp') y la primera opción.
-eval expresión
Evalúa la expresión Lisp especificada durante la secuencia de inicio. El valor de la forma no se imprimirá a menos que esté envuelto en una forma que produzca salida.
-init nombre-archivo
Especifica el nombre de un archivo que contiene personalizaciones de usuario que se cargará cada vez que se inicie Lisp (por defecto ~/init o ~/.cmucl-init.) El cargador carga cualquier binario compilado existente, o la fuente `".lisp"' si no hay ninguno.
-hinit nombre-archivo
Similar a -init, pero especifica el nombre del archivo de inicialización de Hemlock (por defecto `~/hemlock-init' o ~/.hemlock-init), que se carga solo cuando se inicia Hemlock.
-noinit
Suprime la carga del archivo de inicialización, y también evita que -edit cargue el archivo de inicialización de Hemlock.
-nositeinit
Suprime la carga del archivo de inicialización específico del sitio site-init.
-load nombre-archivo
Carga el archivo especificado en Lisp antes de entrar en el bucle lectura-evaluación-impresión de Lisp.
-slave nombre-editor
Especifica que Lisp debe iniciarse como un Lisp esclavo e intentar conectarse a un Lisp editor. Se debe especificar el nombre del editor al que conectarse. Para encontrar el nombre del editor, use el comando de Hemlock `Aceptar Conexiones Esclavas'. nombre-editor tiene el formato `nombre-maquina:socket', donde nombre-maquina es el nombre del host de Internet para la máquina y socket es el número decimal del socket al que conectarse.
-debug-lisp-search
Habilita la impresión de mensajes que indican cómo CMUCL está buscando su archivo core. Esto es útil si CMUCL no encuentra su archivo core por alguna razón.
-fpu modo-fpu
Esta opción solo está disponible en sistemas x86. Esta opción toma los valores x87, sse2 o auto, siendo auto el valor predeterminado. Con el valor predeterminado, CMUCL comprobará si la máquina que ejecuta CMUCL soporta SSE2 o no. Si es así, se selecciona y se utiliza automáticamente el archivo core SSE2. Si no, se utiliza el archivo core x87. Con esta opción, el usuario puede anular la detección y seleccionar un core. (Tenga en cuenta que no se puede ejecutar el core SSE2 en un chip que no tenga SSE2. Pero el core x87 puede ejecutarse en cualquier máquina).
--
Si se proporciona esta opción, el procesamiento de argumentos de CMUCL se detiene y todo lo que siga a "--" se coloca en EXT:*COMMAND-LINE-APPLICATION-ARGUMENTS*. Esto permite que la aplicación realice su propio procesamiento de opciones especiales.

ENTORNO

CMUCLLIB
Esta variable apunta al directorio `lib/' que contiene `lisp.core' y otros archivos utilizados por Lisp en tiempo de ejecución. Esto se puede anular utilizando la opción de línea de comandos -lib.
CMUCLCORE
Esta variable contiene la ruta al `lisp.core' que debe usarse. Esto se puede anular utilizando la opción de línea de comandos -core.
CMUCL_EMPTYFILE
[Solo SunOS] Si `df /tmp' muestra `swap' como el sistema de archivos para el directorio `/tmp', entonces tiene un sistema de archivos "tmpfs". En este caso, debe configurar CMUCL_EMPTYFILE para que apunte a una ruta en un sistema de archivos no-TMPFS que pueda usarse en lugar de `/tmp/empty'.
XKEYSYMDB
Para poder utilizar Motif (y el depurador gráfico) con servidores X de proveedores que no son OSF (como Sun), es posible que necesite configurar la variable de entorno XKEYSYMDB para que apunte al archivo `lib/XKeysymDB'. De lo contrario, obtendrá muchos mensajes de error cada vez que se abra una nueva conexión a CMU CL motifd. Este archivo es leído por el Xt X11R5 para aumentar la base de datos de keysyms con ciertos keysyms de proveedor OSF que Motif desea utilizar.

BÚSQUEDA DE ARCHIVOS CORE

Cuando no se especifica ningún archivo core (ni por la variable de entorno CMUCLCORE ni por la opción -core), CMUCL buscará en varios lugares para encontrar un posible archivo core.

Cuando la variable de entorno CMUCLLIB está configurada o se proporciona la opción -lib, el archivo core de lisp se busca en los lugares especificados. Esta es una lista de directorios separados por dos puntos, al igual que PATH. Esta lista de directorios se busca en orden para encontrar un archivo llamado `lisp.core'. El primero que se encuentre será el core a utilizar.

Cuando CMUCLLIB no está configurada y -lib no se proporciona, se utiliza un conjunto de rutas predeterminadas para inicializar la lista de búsqueda de la biblioteca, y esta lista también se utiliza para buscar el archivo core. lisp(1) - Arch Linux Manual Pages

NAME

lisp

Common Lisp implementation

SYNOPSIS

lisp [-core corefile] [-f flag ...] [-i initfile] [-q] [-v] [-h] [-load file ...] [-e form ...] [-debug form ...] [-no-init] [-batch] [-hiccup] [args ...]

DESCRIPTION

CMU Common Lisp (CMUCL) is an implementation of the Common Lisp Object System (CLOS) specification. It is a high-performance Common Lisp compiler and runtime system.

The lisp command is the primary interface to CMUCL. It can be used to start a new Lisp image, load existing core files, and execute Lisp code.

The command line arguments are described in more detail below.

ENVIRONMENT

Several environment variables can be set to customize CMUCL's behavior:

lisp.core
Specifies the default core file to load if no -core argument is given. If not set, the default core file is searched for in the standard locations (see CORE FILE SEARCHING).
cmucl-fasl-path
A colon-separated list of directories to search for FASL files when loading. This is similar to the PERL5LIB or PythonPath environment variables.
cmucl-source-path
A colon-separated list of directories to search for source files when compiling or debugging. This is similar to the SRC path in some other Lisp implementations.
cmucl-core-path
A colon-separated list of directories to search for core files. This is used when the -core argument is not specified, or when a core file name is given without a path.

CORE FILE SEARCHING

When lisp is invoked without a -core argument, or with a -core argument that does not specify a full path, it searches for a core file in the following locations:

1.
The directory specified by the lisp.core environment variable.
2.
The directory specified by the cmucl-core-path environment variable.
3.
The current working directory.
4.
The standard installation directories, searched in the following order:

The following pathnames are specified relative to the directory where CMU CL is installed, e.g. /usr/local.

`<bin>/../lib/cmucl/lib'
`<bin>/../lib'
`/usr/local/lib/cmucl/lib'

FILES

The following pathnames are specified relative to the directory where CMU CL is installed, e.g. /usr/local.

doc/cmucl/*
Various postscript and text documentation files.
bin/lisp
The lisp startup program. This directory should be in PATH.
lib/cmucl/sample-wrapper
An example shell script that setups up the environment and run lisp. This is not normally needed unless you want some special configuration.
lib/cmucl/lib/lisp.core
The suspended Lisp image. But for x86 machines the suspended core is named lisp-x87.core or lisp-sse2.core, depending on whether the x87 or sse2 core is used.
lib/cmucl/lib/site-init.lisp,generic-site.lisp
Site specific initialization (see README file.) The generic-site.lisp file is a template that can be used to create site-init.lisp. (Note: installation of CMUCL does not create or destroy any site-init.lisp file.)
lib/cmucl/lib/lisp.a
An archive file of all of the C runtime code. This is needed when creating and executable image.
lib/cmucl/lib/linker.sh,linker-x86.sh
Shell scripts to perform the necessary linking to create an executable image.
lib/cmucl/lib/hemlock11.*,lib/cmucl/lib/mh-scan,lib/cmucl/lib/spell-dictionary.bin
Hemlock files.
lib/cmucl/lib/fonts/
X11 fonts for Hemlock.
lib/cmucl/lib/locale
This directory contains template files for CMUCL messages. Translations of the CMUCL messages are also stored here.
lib/cmucl/lib/XKeysymDB
Database of X Keysym names for Motif.
lib/cmucl/lib/load-foreign.csh
Script used by LOAD-FOREIGN to run "ld" on some platforms.
lib/cmucl/lib/contrib
This directory contains contrib modules, including asdf2 and mk-defsystem.
lib/cmucl/lib/ext-formats
This directory contains lisp files that implement the various external formats supported by CMUCL.
lib/cmucl/lib/subsystems
This directory contains the subsystems for CMUCL. The subsystems include CLX, CLM, Gray streams, Hemlock, and Simple Streams.
~/init.lisp,~/.cmucl-init.lisp
User customization files loaded at lisp startup; either name is acceptable. Init files can be compiled.
~/hemlock-init.lisp,~/.hemlock-init.lisp
Hemlock initialization file, loaded when Hemlock starts.

BUGS

Consult http://www.cons.org/cmucl/support.html for support information, including mechanisms for bug reporting. Please consult your local CMU CL maintainer or Common Lisp expert if any to verify that a problem really is a bug before reporting it.

Known problems with this version:

--
Detection of stack overflow is not very graceful. You get many "map failure" errors on stderr.
--
If file descriptors are used up, then Lisp will die.
--
Several proposed ANSI Common Lisp (CLtL II) features are not implemented: Any CLOS features not implemented by PCL, and features added since the first ANSI draft.
--
The interpreter's pre-processing freezes in the macro definitions in effect at the time an interpreted function is defined.
