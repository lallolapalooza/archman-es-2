libressl-SSL_CTX_load_verify_locations(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_CTX_LOAD_VERIFY_LOCATIONS(3) Manual de funciones de la biblioteca SSL_CTX_LOAD_VERIFY_LOCATIONS(3)

NOMBRE

SSL_CTX_load_verify_locations, SSL_CTX_set_default_verify_paths — establecer ubicaciones predeterminadas para certificados CA de confianza

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_CTX_load_verify_locations(SSL_CTX *ctx, const char *CAfile, const char *CApath);

int
SSL_CTX_set_default_verify_paths(SSL_CTX *ctx);

DESCRIPCIÓN

SSL_CTX_load_verify_locations() especifica las ubicaciones para ctx, donde se encuentran los certificados CA para fines de verificación. Los certificados disponibles a través de CAfile y CApath son de confianza.

SSL_CTX_set_default_verify_paths() especifica que se deben utilizar las ubicaciones predeterminadas desde las cuales se cargan los certificados CA. Hay un directorio predeterminado y un archivo predeterminado. El directorio de certificados CA predeterminado se llama certs en el directorio OpenSSL predeterminado. El archivo de certificados CA predeterminado se llama cert.pem en el directorio OpenSSL predeterminado.

Si CAfile no es NULL, apunta a un archivo de certificados CA en formato PEM. El archivo puede contener varios certificados CA identificados por secuencias de:

-----BEGIN CERTIFICATE-----
... (certificado CA en codificación base64) ...
-----END CERTIFICATE-----

Antes, entre y después de los certificados se permite texto arbitrario que puede usarse, por ejemplo, para descripciones de los certificados.

El CAfile se procesa al ejecutar la función SSL_CTX_load_verify_locations().

Si CApath no es NULL, apunta a un directorio que contiene certificados CA en formato PEM. Los archivos contienen cada uno un certificado CA. Los archivos se buscan por el valor hash del nombre del sujeto de la CA, que por lo tanto debe estar disponible. Si existen varios certificados CA con el mismo valor hash de nombre, la extensión debe ser diferente (por ejemplo, 9d66eef0.0, 9d66eef0.1, etc.). La búsqueda se realiza en el orden del número de extensión, independientemente de otras propiedades de los certificados.

Los certificados en CApath solo se buscan cuando son necesarios, por ejemplo, al construir la cadena de certificados o al realizar realmente la verificación de un certificado del par.

Al buscar certificados CA, la biblioteca OpenSSL primero buscará los certificados en CAfile, luego los de CApath. La coincidencia de certificados se realiza basándose en el nombre del sujeto, el identificador de clave (si está presente) y el número de serie tal como se extraen del certificado que se va a verificar. Si estos datos no coinciden, se intentará con el siguiente certificado. Si se encuentra un primer certificado que coincide con los parámetros, se realizará el proceso de verificación; no se buscarán otros certificados para los mismos parámetros en caso de fallo.

En modo servidor, al solicitar un certificado de cliente, el servidor debe enviar la lista de CA de las cuales aceptará certificados de cliente. Esta lista no está influenciada por el contenido de CAfile o CApath y debe establecerse explícitamente utilizando la familia de funciones SSL_CTX_set_client_CA_list(3).

Al construir su propia cadena de certificados, un cliente/servidor OpenSSL intentará completar los certificados faltantes de CAfile/ CApath, si la cadena de certificados no se especificó explícitamente (ver SSL_CTX_add_extra_chain_cert(3) y SSL_CTX_use_certificate(3)).

VALORES DE RETORNO

Para SSL_CTX_load_verify_locations(), pueden ocurrir los siguientes valores de retorno:

0
La operación falló porque CAfile y CApath son NULL o el procesamiento en una de las ubicaciones especificadas falló. Verifique la pila de errores para averiguar el motivo.
1
La operación tuvo éxito.

SSL_CTX_set_default_verify_paths() devuelve 1 en caso de éxito o 0 en caso de fallo. Una ubicación predeterminada faltante todavía se trata como un éxito.

EJEMPLOS

Generar un archivo de certificado CA con texto descriptivo a partir de los certificados CA ca1.pem ca2.pem ca3.pem:

#!/bin/sh
rm CAfile.pem
for i in ca1.pem ca2.pem ca3.pem; do
	openssl x509 -in $i -text >> CAfile.pem
done

Preparar el directorio /some/where/certs que contiene varios certificados CA para su uso como CApath:

$ cd /some/where/certs
$ rm -f *.[0-9]* *.r[0-9]*
$ for c in *.pem; do
>    [ "$c" = "*.pem" ] && continue
>    hash=$(openssl x509 -noout -hash -in "$c")
>    if egrep -q -- '-BEGIN( X509 | TRUSTED | )CERTIFICATE-' "$c"; then
>      suf=0
>      while [ -e $hash.$suf ]; do suf=$(( $suf + 1 )); done
>      ln -s "$c" $hash.$suf
>    fi
>    if egrep -q -- '-BEGIN X509 CRL-' "$c"; then
>      suf=0
>      while [ -e $hash.r$suf ]; do suf=$(( $suf + 1 )); done
>      ln -s "$c" $hash.r$suf
>    fi
> done

HISTORIA

SSL_CTX_load_verify_locations() y SSL_CTX_set_default_verify_paths() aparecieron por primera vez en SSLeay 0.8.0 y han estado disponibles desde OpenBSD 2.4.

ADVERTENCIAS

Si varios certificados CA que coinciden con el nombre, el identificador de clave y la condición del número de serie están disponibles, solo se examinará el primero. Esto puede llevar a resultados inesperados si el mismo certificado CA está disponible con diferentes fechas de caducidad. Si ocurre un error de verificación de “certificado caducado”, no se buscará ningún otro certificado. Asegúrese de no mezclar certificados caducados con certificados válidos.
