NOMBRE

nss-resolve, libnss_resolve.so.2 - Resolución de nombres de host a través de systemd-resolved.service

SINOPSIS

libnss_resolve.so.2

DESCRIPCIÓN

nss-resolve es un módulo plug-in para la funcionalidad del Conmutador de Servicios de Nombres GNU (NSS) de la Biblioteca C de GNU (glibc) que le permite resolver nombres de host a través del servicio local de resolución de nombres de red systemd-resolved(8). Reemplaza al módulo plug-in nss-dns que tradicionalmente resuelve nombres de host a través de DNS.

Para activar el módulo NSS, añada "resolve [!UNAVAIL=return]" a la línea que comienza con "hosts:" en /etc/nsswitch.conf. Específicamente, se recomienda colocar "resolve" al principio de la línea "hosts:" de /etc/nsswitch.conf. Debe estar antes de la entrada "files", ya que systemd-resolved soporta /etc/hosts internamente, pero con caché. Por el contrario, debe estar después de "mymachines", para dar precedencia a los nombres de host asignados a VMs y contenedores locales sobre los nombres recibidos por DNS. Finalmente, recomendamos colocar "dns" en algún lugar después de "resolve", para recurrir a nss-dns si systemd-resolved.service no está disponible.

Tenga en cuenta que systemd-resolved sintetizará registros de recursos DNS en algunos casos, por ejemplo para "localhost" y el nombre de host local actual; consulte systemd-resolved(8) para obtener la lista completa. Esto duplica la funcionalidad de nss-myhostname(8), pero todavía se recomienda (ver ejemplos a continuación) mantener nss-myhostname configurado en /etc/nsswitch.conf, para mantener esos nombres resolubles si systemd-resolved no está en ejecución.

Por favor, tenga en cuenta que nss-myhostname (y nss-resolve) también resuelven en la dirección opuesta — desde direcciones IP adjuntas localmente a nombres de host. Si depende de que esa búsqueda sea proporcionada por DNS, es posible que desee ordenar las cosas de manera diferente.

La comunicación entre nss-resolve y systemd-resolved.service tiene lugar a través del socket AF_UNIX /run/systemd/resolve/io.systemd.Resolve.

VARIABLES DE ENTORNO

$SYSTEMD_NSS_RESOLVE_VALIDATE

Acepta un argumento booleano. Cuando es falso, la validación criptográfica de los registros de recursos a través de DNSSEC se deshabilitará. Esto puede ser útil para pruebas, o cuando se sabe que la hora del sistema no es confiable.

Añadido en la versión 250.

$SYSTEMD_NSS_RESOLVE_SYNTHESIZE

Acepta un argumento booleano. Cuando es falso, no se devolverán registros sintéticos, p. ej., para el nombre de host local. Consulte la sección REGISTROS SINTÉTICOS en systemd-resolved.service(8) para más información. Esto puede ser útil para consultar los registros de recursos públicos, independientemente de la configuración de la máquina local.

Añadido en la versión 250.

$SYSTEMD_NSS_RESOLVE_CACHE

Acepta un argumento booleano. Cuando es falso, la caché de registros consultados previamente no será utilizada por systemd-resolved(8).

Añadido en la versión 250.

$SYSTEMD_NSS_RESOLVE_ZONE

Acepta un argumento booleano. Cuando es falso, no se devolverán respuestas que utilicen registros de recursos LLMNR/mDNS públicos registrados localmente.

Añadido en la versión 250.

$SYSTEMD_NSS_RESOLVE_TRUST_ANCHOR

Acepta un argumento booleano. Cuando es falso, no se utilizarán respuestas que utilicen anclajes de confianza configurados localmente.

Añadido en la versión 250.

$SYSTEMD_NSS_RESOLVE_NETWORK

Acepta un argumento booleano. Cuando es falso, se devolverán respuestas sin usar la red, es decir, de fuentes locales o de la caché en systemd-resolved(8).

Añadido en la versión 250.

EJEMPLO

Aquí hay un ejemplo de archivo /etc/nsswitch.conf que habilita nss-resolve correctamente:

passwd:         files systemd
group:          files [SUCCESS=merge] systemd
shadow:         files systemd
gshadow:        files systemd
hosts:          mymachines resolve [!UNAVAIL=return] files myhostname dns
networks:       files
protocols:      db files
services:       db files
ethers:         db files
rpc:            db files
netgroup:       nis
