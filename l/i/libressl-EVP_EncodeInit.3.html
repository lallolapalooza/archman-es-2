DESCRIPCIÓN

Las rutinas de codificación EVP proporcionan una interfaz de alto nivel para la codificación y decodificación base64. La codificación base64 convierte datos binarios en un formato imprimible que utiliza los caracteres A-Z, a-z, 0-9, "+" y "/" para representar los datos. Por cada 3 bytes de datos binarios proporcionados, se producirán 4 bytes de datos codificados en base64, además de algunas líneas nuevas ocasionales. Si la longitud de los datos de entrada no es un múltiplo de 3, los datos de salida se rellenarán al final utilizando el carácter "=".

EVP_ENCODE_CTX_new() asigna, inicializa y devuelve un contexto para ser utilizado por las funciones de codificación y decodificación.

EVP_ENCODE_CTX_free() libera ctx.

La codificación de datos binarios se realiza en bloques de 48 bytes de entrada (o menos para el bloque final). Por cada bloque de entrada de 48 bytes codificado, se generarán 64 bytes de datos base64, más un carácter de nueva línea adicional, es decir, 65 bytes en total. El bloque final, que puede ser inferior a 48 bytes, generará 4 bytes por cada 3 bytes de entrada. Si la longitud de los datos no es divisible por 3, se generará un bloque completo de 4 bytes para los 1 o 2 bytes finales de entrada. Del mismo modo, también se generará un carácter de nueva línea.

EVP_EncodeInit() inicializa ctx para el inicio de una nueva operación de codificación.

EVP_EncodeUpdate() codifica inl bytes de datos encontrados en el búfer apuntado por in. La salida se almacena en el búfer out y el número de bytes de salida se almacena en *outl. Es responsabilidad del llamante asegurarse de que el búfer en out sea lo suficientemente grande para acomodar los datos de salida. Solo los bloques completos de datos (48 bytes) serán procesados y emitidos inmediatamente por esta función. El resto se mantiene en el objeto ctx y será procesado por una llamada posterior a EVP_EncodeUpdate() o EVP_EncodeFinal(). Para calcular el tamaño requerido del búfer de salida, sume el valor de inl con la cantidad de datos no procesados que se mantienen en ctx y divida el resultado por 48 (ignore cualquier resto). Esto da el número de bloques de datos que se procesarán. Asegúrese de que el búfer de salida contenga 65 bytes de almacenamiento por cada bloque, más un byte adicional para un terminador NUL. EVP_EncodeUpdate() puede ser llamado repetidamente para procesar grandes cantidades de datos de entrada. En caso de error, EVP_EncodeUpdate() establecerá *outl a 0 y devolverá 0. En caso de éxito, se devolverá 1.

EVP_EncodeFinal() debe ser llamado al final de una operación de codificación. Procesará cualquier bloque de datos parcial restante en el objeto ctx. Los datos de salida se almacenarán en out y la longitud de los datos escritos se almacenará en *outl. Es responsabilidad del llamante asegurarse de que out sea lo suficientemente grande para acomodar los datos de salida, que nunca serán más de 65 bytes más un terminador NUL adicional, es decir, 66 bytes en total.

EVP_EncodeBlock() codifica un bloque completo de datos de entrada en f y de longitud n y lo almacena en t. Por cada 3 bytes de entrada proporcionados, se producirán 4 bytes de datos de salida. Si n no es divisible por 3, el bloque se codifica como un bloque final de datos y la salida se rellena para que sea siempre divisible por 4. Además, se añadirá un carácter terminador NUL. Por ejemplo, si se proporcionan 16 bytes de datos de entrada, se generan 24 bytes de datos codificados más 1 byte para un terminador NUL, es decir, 25 bytes en total. La longitud de los datos generados sin el terminador NUL es devuelta por la función.

EVP_DecodeInit() inicializa ctx para el inicio de una nueva operación de decodificación.

EVP_DecodeUpdate() decodifica inl caracteres de datos encontrados en el búfer apuntado por in. La salida se almacena en el búfer out y el número de bytes de salida se almacena en *outl. Es responsabilidad del llamante asegurarse de que el búfer en out sea lo suficientemente grande para acomodar los datos de salida. Esta función intentará decodificar tantos datos como sea posible en bloques de 4 bytes. Los caracteres de espacio en blanco, nueva línea o retorno de carro se ignoran. Cualquier bloque parcial de datos sin procesar (1, 2 o 3 bytes) que quede al final se mantendrá en el objeto ctx y se procesará en una llamada posterior a EVP_DecodeUpdate(). Si se encuentran caracteres base64 ilegales o si se encuentra el carácter de relleno base64 "=" en medio de los datos, la función devuelve -1 para indicar un error. Un valor de retorno de 0 o 1 indica el procesamiento exitoso de los datos. Un valor de retorno de 0 indica adicionalmente que los últimos caracteres de datos de entrada procesados incluyeron el carácter de relleno base64 "=" y, por lo tanto, no se espera procesar más datos que no sean caracteres de relleno. Por cada 4 bytes base64 válidos procesados, ignorando espacios en blanco, retornos de carro y saltos de línea, se producirán 3 bytes de datos binarios de salida, o menos al final de los datos con

EVP_DecodeFinal() debe ser llamado al final de una operación de decodificación. Procesará los datos restantes sin procesar y los escribirá en el búfer de salida out. La longitud de los datos escritos se almacenará en *outl. Es responsabilidad del llamante asegurarse de que el búfer out sea lo suficientemente grande para acomodar la salida.

EVP_DecodeBlock() decodifica un bloque completo de datos de entrada f de longitud n y almacena el resultado en t. Por cada 4 caracteres de entrada válidos, se producirán 3 bytes de salida. Los caracteres de relleno y los caracteres de espacio en blanco se ignoran. La longitud de los datos generados se devuelve desde la función. Si se encuentran caracteres base64 ilegales, la función devuelve -1. En caso de éxito, se devuelve el número de bytes de salida generados.

VALORES DEVUELTOS

EVP_ENCODE_CTX_new() devuelve un puntero a una nueva estructura EVP_ENCODE_CTX, o NULL si falla la asignación de memoria.

EVP_EncodeUpdate() devuelve 1 si la operación fue exitosa, y 0 si hubo un error (por ejemplo, datos de entrada inválidos).

EVP_DecodeUpdate() devuelve 1 si la operación fue exitosa, 0 si los datos de entrada se consumieron por completo y no quedan más datos no de relleno, y -1 si se encontró un error (por ejemplo, caracteres base64 ilegales o relleno incorrecto).

EVP_EncodeBlock() y EVP_DecodeBlock() devuelven el número de bytes generados en el búfer de salida t. Si se produce un error, por ejemplo, al encontrar caracteres ilegales en la entrada base64 para EVP_DecodeBlock(), se devuelve -1.

VER TAMBIÉN

Para obtener más información, consulte evp(7).

EVP_DecodeFinal

El carácter de relleno "" se ha utilizado.

EVP_DecodeFinal() debe llamarse al final de una operación de decodificación. Si todavía hay datos sin procesar en ctx, entonces los datos de entrada no deben haber sido un múltiplo de 4 y, por lo tanto, ha ocurrido un error. La función devolverá -1 en este caso. De lo contrario, la función devuelve 1 si tiene éxito.

EVP_DecodeBlock() decodificará el bloque de n caracteres de datos base64 contenidos en f y almacenará el resultado en t. Se eliminarán los espacios en blanco iniciales, así como los espacios en blanco finales, las nuevas líneas, los retornos de carro o los caracteres de fin de archivo. Después de dicha eliminación, la longitud de los datos en f debe ser divisible por 4. Por cada 4 bytes de entrada, se producirán exactamente 3 bytes de salida. La salida se rellenará con bits 0 si es necesario para asegurar que la salida sean siempre 3 bytes por cada 4 bytes de entrada. Esta función devolverá la longitud de los datos decodificados o -1 en caso de error.

VALORES DE RETORNO

EVP_ENCODE_CTX_new() devuelve un puntero al objeto EVP_ENCODE_CTX recién asignado o NULL en caso de error.

EVP_EncodeUpdate() devuelve 0 en caso de error o 1 si tiene éxito.

EVP_EncodeBlock() devuelve el número de bytes codificados excluyendo el terminador NUL.

EVP_DecodeUpdate() devuelve -1 en caso de error y 0 o 1 si tiene éxito. Si se devuelve 0, no se esperan más caracteres base64 que no sean de relleno.

EVP_DecodeFinal() devuelve -1 en caso de error o 1 si tiene éxito.

EVP_DecodeBlock() devuelve la longitud de los datos decodificados o -1 en caso de error.
