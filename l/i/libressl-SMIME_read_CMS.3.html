SMIME_READ_CMS(3) Manual de funciones de biblioteca SMIME_READ_CMS(3)

NOMBRE

SMIME_read_CMS — extrae el ContenidoInfo CMS de un mensaje S/MIME

SINOPSIS

biblioteca “libcrypto”
#include <openssl/cms.h>

CMS_ContentInfo *
SMIME_read_CMS(BIO *in, BIO **bcont);

DESCRIPCIÓN

SMIME_read_CMS() analiza un mensaje en formato S/MIME desde in.

Si el mensaje utiliza firma de texto claro, el contenido se guarda en un BIO de memoria que se escribe en *bcont y que puede ser pasado a CMS_verify(3) con el flag CMS_DETACHED establecido. De lo contrario, *bcont se establece a NULL y el tipo de la estructura devuelta puede determinarse usando CMS_get0_type(3).

Para soportar funcionalidad futura si bcont no es NULL, *bcont debe ser inicializado a NULL, por ejemplo:

BIO *cont = NULL;
CMS_ContentInfo *cms = SMIME_read_CMS(in, &cont);

VALORES DE RETORNO

SMIME_read_CMS() devuelve una CMS_ContentInfo válida o NULL si ocurrió un error. El error puede obtenerse de ERR_get_error(3).

VER TAMBIÉN

BIO_f_base64(3), BIO_new(3), CMS_ContentInfo_new(3), CMS_decrypt(3), CMS_get0_type(3), CMS_verify(3), d2i_CMS_ContentInfo(3), SMIME_read_PKCS7(3), SMIME_text(3), SMIME_write_CMS(3)

HISTORIA

SMIME_read_CMS() apareció por primera vez en OpenSSL 0.9.8h y ha estado disponible desde OpenBSD 6.7.

ERRORES CONOCIDOS

El analizador MIME utilizado por SMIME_read_CMS() es algo primitivo. Si bien manejará la mayoría de los mensajes S/MIME, los formatos compuestos más complejos pueden no funcionar.

El analizador asume que la estructura CMS_ContentInfo siempre está codificada en base64 y no manejará el caso en que esté en formato binario o utilice formato quoted-printable.

El uso de un BIO de memoria para mantener el contenido firmado limita el tamaño del mensaje que se puede procesar debido a restricciones de memoria: debería estar disponible una opción de procesamiento en una sola pasada.
