CRYPTO_SET_EX_DATA(3) Manual de Funciones de Biblioteca CRYPTO_SET_EX_DATA(3)

NOMBRE

CRYPTO_get_ex_new_index, CRYPTO_EX_new, CRYPTO_EX_free, CRYPTO_EX_dup, CRYPTO_new_ex_data, CRYPTO_set_ex_data, CRYPTO_get_ex_data, CRYPTO_free_ex_data — funciones de bajo nivel para datos específicos de la aplicación

SINOPSIS

biblioteca “libcrypto”
#include <openssl/crypto.h>

int
CRYPTO_get_ex_new_index(int class_index, long argl, void *argp, CRYPTO_EX_new *new_func, CRYPTO_EX_dup *dup_func, CRYPTO_EX_free *free_func);

typedef int
CRYPTO_EX_new(void *parent, void *data, CRYPTO_EX_DATA *ad, int idx, long argl, void *argp);

typedef void
CRYPTO_EX_free(void *parent, void *data, CRYPTO_EX_DATA *ad, int idx, long argl, void *argp);

typedef int
CRYPTO_EX_dup(CRYPTO_EX_DATA *to, const CRYPTO_EX_DATA *from, void *datap, int idx, long argl, void *argp);

int
CRYPTO_new_ex_data(int class_index, void *parent, CRYPTO_EX_DATA *ad);

int
CRYPTO_set_ex_data(CRYPTO_EX_DATA *ad, int idx, void *data);

void *
CRYPTO_get_ex_data(CRYPTO_EX_DATA *ad, int idx);

void
CRYPTO_free_ex_data(int class_index, void *parent, CRYPTO_EX_DATA *ad);

DESCRIPCIÓN

La biblioteca implementa las funciones documentadas en la página del manual de RSA_get_ex_new_index(3) y funciones similares para otros tipos de objetos padre utilizando las funciones documentadas en la presente página del manual. Los programas de aplicación casi nunca necesitan llamar directamente a las funciones aquí documentadas.

CRYPTO_get_ex_new_index() se comporta de la misma manera que RSA_get_ex_new_index(3) excepto que el tipo de objeto padre para el que se reserva el nuevo idx no forma parte del nombre de la función, sino que se especifica mediante el argumento adicional class_index, que recibe una de las constantes CRYPTO_EX_INDEX_* definidas en <openssl/crypto.h>. La recomendación dada en RSA_get_ex_new_index(3) de establecer el argumento argl en 0 y los cuatro últimos argumentos en NULL se aplica. La biblioteca pasa los argumentos argl y argp a las funciones de devolución de llamada para el idx respectivo, pero los ignora de lo contrario.

Si se pasa un puntero a función para el argumento new_func, esa función se llama para el idx devuelto cada vez que se asigna un nuevo objeto padre con RSA_new(3) o una función similar.

Si se pasa un puntero a función para el argumento free_func, esa función se llama para el idx devuelto cuando se libera un objeto padre con RSA_free(3) o una función similar.

Los argumentos de new_func y free_func son los siguientes:

parent
el objeto padre que contiene los data
data
los data establecidos previamente por CRYPTO_set_ex_data() en idx en parent
ad
el subobjeto CRYPTO_EX_DATA del objeto parent
idx
valor de retorno de CRYPTO_get_ex_new_index() que estableció esta devolución de llamada
argl
el argl pasado a CRYPTO_get_ex_new_index() para este idx
argp
el argp pasado a CRYPTO_get_ex_new_index() para este idx

Si se pasa un puntero a función para dup_func, esa función debe llamarse para el idx devuelto cada vez que se copia un objeto padre del tipo respectivo. En realidad, las únicas funciones que lo hacen son BIO_dup_chain(3), EC_KEY_copy(3) y SSL_dup(3), y la pila de red TLS 1.3 lo hace internamente al duplicar un objeto SSL_SESSION después de recibir un mensaje de ticket de sesión nuevo. La mayoría de los demás tipos de objetos que admiten ex_data no admiten la copia en primer lugar, mientras que DSA_dup_DH(3) y X509_dup(3) simplemente ignoran dup_func.

Los argumentos de dup_func son los siguientes:

to
el subobjeto CRYPTO_EX_DATA del nuevo objeto padre
from
el subobjeto CRYPTO_EX_DATA del objeto padre original
datap
un puntero a una copia del puntero a los ex_data originales
idx
valor de retorno de CRYPTO_get_ex_new_index() que estableció esta devolución de llamada
argl
el argl pasado a CRYPTO_get_ex_new_index() para este idx
argp
el argp pasado a CRYPTO_get_ex_new_index() para este idx

Dentro de dup_func, se puede acceder al puntero data contenido en el objeto padre original que se está copiando, convirtiendo y desreferenciando datap, por ejemplo:

char *orig_data = *(char **)datap;

Si los datos originales se copian, por ejemplo de manera similar a

char *new_data;
if ((new_data = strdup(orig_data)) == NULL)
	return 0;

entonces el puntero a la memoria recién asignada debe pasarse de vuelta al llamador en el argumento datap, por ejemplo:

*(char **)datap = new_data;
return 1;

Llamar a CRYPTO_set_ex_data(to, idx, new_data) desde dentro de dup_func no tiene ningún efecto porque el código que llama a dup_func llama incondicionalmente a CRYPTO_set_ex_data(to, idx, *datap).

CRYPTO_new_ex_data() y CRYPTO_free_ex_data() se utilizan para inicializar y liberar la estructura CRYPTO_EX_DATA que se asigna en el objeto parent. Generalmente se llama una vez, al crear el objeto padre, y luego se llama una vez más, al liberarlo. El argumento class_index tiene el mismo significado que en CRYPTO_get_ex_new_index().

CRYPTO_set_ex_data() asocia la estructura de datos especificada por data con el índice idx en la estructura CRYPTO_EX_DATA contenida en ad. Si ya había datos asociados con idx, se desechan sin llamar a la función free_func asociada (si la hubiera). Esto es generalmente incorrecto, pero se hace así para evitar que una llamada a CRYPTO_set_ex_data() falle después de que el objeto padre correspondiente ya haya sido liberado, por ejemplo, debido a un bucle de referencia. Por lo tanto, debe asegurarse de que los datos asociados se liberen adecuadamente. Tenga en cuenta que la función dup_func se puede utilizar para hacer una copia de los datos originales en lugar de la asignación descrita.

CRYPTO_get_ex_data() devuelve los datos previamente asociados con el índice idx en la estructura CRYPTO_EX_DATA contenida en ad.

CRYPTO_free_ex_data() devuelve los datos previamente asociados con el índice idx en la estructura CRYPTO_EX_DATA contenida en ad.

VALOR DE RETORNO

Las funciones CRYPTO_get_ex_new_index(), CRYPTO_new_ex_data() y CRYPTO_set_ex_data() devuelven el índice asignado (un valor no negativo) o -1 en caso de error.

Las funciones de devolución de llamada CRYPTO_EX_new() y CRYPTO_EX_dup() deben devolver 1 en caso de éxito y 0 en caso de error.

La función de devolución de llamada CRYPTO_EX_free() no tiene valor de retorno.

CRYPTO_get_ex_data() devuelve el puntero a los datos asociados o NULL si no se han asociado datos o si el índice no es válido.
