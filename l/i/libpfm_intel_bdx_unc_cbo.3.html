NOMBRE

libpfm_intel_bdx_unc_cbo - soporte para PMU sin caché C-Box de Intel Broadwell Server

SINOPSIS

#include <perfmon/pfmlib.h>

Nombre de PMU: bdx_unc_cbo[0-21]
Descripción de PMU: PMU sin caché C-Box de Intel Broadwell Server

DESCRIPCIÓN

La biblioteca soporta la PMU sin caché C-Box (mecanismo de coherencia) de Intel Broadwell Server. Este modelo de PMU existe en varios modelos de servidor Broadwell (79, 86). Hay una PMU C-Box por núcleo físico. Por lo tanto, hay hasta veintiuna instancias idénticas de PMU C-Box numeradas del 0 al 21. En sistemas de doble socket, el número se refiere a la PMU C-Box en el socket donde se ejecuta el programa. Por ejemplo, si se ejecuta en la CPU18, entonces bdx_unc_cbo0 se refiere a la C-Box para el núcleo físico 0 en el socket 1. Por el contrario, si se ejecuta en la CPU0, el mismo bdx_unc_cbo0 se refiere a la C-Box para el núcleo físico 0 pero en el socket 0.

Cada PMU C-Box implementa 4 contadores genéricos y dos registros de filtro utilizados solo con ciertos eventos y umasks.

MODIFICADORES

Los siguientes modificadores son compatibles con la PMU sin caché C-Box de Intel Broadwell:

e
Habilita la detección de flanco, es decir, cuenta solo cuando hay una transición de estado de no ocurrencia del evento a al menos una ocurrencia. Este modificador debe combinarse con un modificador de umbral (t) con un valor mayor o igual a uno. Este es un modificador booleano.
t
Establece el valor del umbral. Cuando se establece en un valor distinto de cero, el contador cuenta el número de ciclos de C-Box en los que el número de ocurrencias del evento es mayor o igual al umbral. Este es un modificador entero con valores en el rango [0:255].
nf
Filtro de nodo. Ciertos eventos, como UNC_C_LLC_LOOKUP, UNC_C_LLC_VICTIMS, proporcionan una umask NID. A veces, el NID se combina con otras capacidades de filtrado, como los opcodes. El filtro de nodo es una máscara de bits máxima de 8 bits. Un nodo corresponde a un socket del procesador. Por lo tanto, los valores legales dependen de la configuración del hardware subyacente. Para sistemas de doble socket, la máscara de bits tiene dos bits válidos [0:1].
cf
Filtro de núcleo. Este es un filtro de 5 bits que se utiliza para filtrar según el origen del núcleo físico de la solicitud C-Box. Los valores posibles son 0-63. Si no se especifica el filtro, no se realiza ningún filtrado. Los bits 0-3 indican el ID del núcleo físico y el bit 4 filtra datos no relacionados con hilos.
tf
Filtro de hilo. Este es un filtro de 1 bit que se utiliza para filtrar las solicitudes C-Box basándose en la identificación del procesador lógico (hiper-hilo). Los valores posibles son 0-1. Si no se especifica el filtro, no se realiza ningún filtrado.
nc
No Coherente. Este es un filtro de 1 bit que se utiliza para filtrar las solicitudes C-Box solo para las umasks TOR_INSERTS y TOR_OCCUPANCY utilizando el comparador OPCODE. Si no se especifica el filtro, no se realiza ningún filtrado.
isoc
Isócrono. Este es un filtro de 1 bit que se utiliza para filtrar las solicitudes C-Box solo para las umasks TOR_INSERTS y TOR_OCCUPANCY utilizando el comparador OPCODE. Si no se especifica el filtro, no se realiza ningún filtrado.

Filtrado de opciones

Ciertos eventos, como UNC_C_TOR_INSERTS, admiten la comparación de opciones en el tipo de transacción de la C-BOX. Para utilizar esta función, primero se debe seleccionar una umask de comparación de opciones, por ejemplo, MISS_OPCODE. Segundo, la opción a comparar debe seleccionarse a través de una segunda umask entre las umasks OPC_*. Por ejemplo, UNC_C_TOR_INSERTS:OPCODE:OPC_RFO, cuenta el número de inserciones de TOR para transacciones RFO.

La comparación de opciones se puede combinar con el filtrado de nodos con ciertas umasks. En general, el soporte de filtrado está codificado en el nombre de la umask, por ejemplo, NID_OPCODE admite filtrado tanto de nodo como de opción. Por ejemplo, UNC_C_TOR_INSERTS:NID_OPCODE:OPC_RFO:nf=1.
