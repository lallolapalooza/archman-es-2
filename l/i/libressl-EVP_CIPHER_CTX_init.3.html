Paquete: libressl

Licencias: ISC, custom:OpenSSL

EVP_CIPHER_CTX_INIT(3) Manual de funciones de la biblioteca EVP_CIPHER_CTX_INIT(3)

NOMBRE

EVP_CIPHER_CTX_init, EVP_CIPHER_CTX_cleanup, EVP_Cipher — funciones de cifrado EVP obsoletas

SINOPSIS

biblioteca “libcrypto”
#include <openssl/evp.h>

int
EVP_CIPHER_CTX_init(EVP_CIPHER_CTX *ctx);

int
EVP_CIPHER_CTX_cleanup(EVP_CIPHER_CTX *ctx);

int
EVP_Cipher(EVP_CIPHER_CTX *ctx, unsigned char *out, const unsigned char *in, unsigned int in_len);

DESCRIPCIÓN

EVP_CIPHER_CTX_init() es una función obsoleta que podría usarse para limpiar un contexto de cifrado en la pila antes de que EVP_CIPHER_CTX se volviera opaco. Llamarla en un contexto de cifrado recién devuelto por EVP_CIPHER_CTX_new(3) no tiene efecto. Llamarla en un contexto de cifrado que ya fue utilizado puede filtrar memoria con versiones antiguas de la biblioteca. En su lugar, use EVP_CIPHER_CTX_reset(3) o EVP_CIPHER_CTX_free(3).

EVP_CIPHER_CTX_cleanup() es un alias obsoleto para EVP_CIPHER_CTX_reset(3). Limpia toda la información de ctx y libera toda la memoria asignada asociada con él, excepto el objeto ctx en sí mismo.

EVP_Cipher() expone detalles de implementación de las funciones EVP_CipherUpdate(3) y EVP_CipherFinal(3) que nunca debieron formar parte de la API pública.

Si la bandera EVP_CIPH_FLAG_CUSTOM_CIPHER está establecida para el cifrado utilizado por ctx, el comportamiento depende de in. Si ese argumento es NULL y in_len es 0, el comportamiento es similar a EVP_CipherFinal(3); si in_len no es 0, el comportamiento es indefinido. Si in no es NULL, el comportamiento es similar a EVP_CipherUpdate(3). En ambos casos, las excepciones a la similitud son que los argumentos y los valores de retorno difieren.

Si la bandera EVP_CIPH_FLAG_CUSTOM_CIPHER no está establecida para el cifrado utilizado por ctx, cifra o descifra bloques de datos alineados cuyas longitudes coinciden con el tamaño del bloque de cifrado. Requiere que la operación de cifrado o descifrado anterior usando el mismo ctx, si hubo alguna, terminó exactamente en un límite de bloque y que in_len es un múltiplo entero del tamaño del bloque de cifrado. Si alguna de estas condiciones se viola, EVP_Cipher() produce silenciosamente resultados incorrectos. Por esa razón, se recomienda encarecidamente usar la función EVP_CipherUpdate(3) en su lugar. Esta última puede manejar bloques parciales de forma segura, e incluso si in_len es realmente un múltiplo del tamaño del bloque de cifrado para todas las llamadas, la sobrecarga incurrida por usar EVP_CipherUpdate(3) es mínima.

VALORES DE RETORNO

EVP_CIPHER_CTX_init() siempre devuelve 1.

EVP_CIPHER_CTX_cleanup() devuelve 1 para éxito o 0 para fallo.

Con EVP_CIPH_FLAG_CUSTOM_CIPHER, EVP_Cipher() devuelve el número de bytes escritos en out para éxito o -1 para fallo. Sin EVP_CIPH_FLAG_CUSTOM_CIPHER, devuelve 1 para éxito o 0 para fallo.

VER TAMBIÉN

evp(3), EVP_EncryptInit(3)

HISTORIA

EVP_Cipher() apareció por primera vez en SSLeay 0.6.5. EVP_CIPHER_CTX_cleanup() apareció por primera vez en SSLeay 0.8.0. EVP_CIPHER_CTX_init() apareció por primera vez en SSLeay 0.9.0. Todas estas funciones han estado disponibles desde OpenBSD 2.4.

ADVERTENCIAS

Comprobar el valor de retorno de EVP_Cipher() requiere una precaución inusual: cero señala éxito si EVP_CIPH_FLAG_CUSTOM_CIPHER está establecido o fallo en caso contrario.
