DESCRIPCIÓN

Estas son interfaces independientes del algoritmo para decodificar y codificar claves privadas y públicas. Para obtener detalles sobre la semántica, ejemplos, advertencias y errores, consulte ASN1_item_d2i(3).

d2i_PrivateKey() decodifica una clave privada usando el algoritmo type. Intenta usar cualquier formato específico del algoritmo o el formato PrivateKeyInfo sin cifrar de PKCS#8 definido en la RFC 5208, sección 5. El parámetro type debe ser una constante de algoritmo de clave pública como EVP_PKEY_RSA. Se produce un error si la clave decodificada no coincide con type.

d2i_AutoPrivateKey() es similar a d2i_PrivateKey() excepto que intenta detectar automáticamente el algoritmo.

d2i_PrivateKey_bio() y d2i_PrivateKey_fp() son similares a d2i_PrivateKey() excepto que leen desde un puntero BIO o FILE.

i2d_PrivateKey() codifica val_in. Utiliza un formato específico del algoritmo o, si no hay ninguno definido para ese tipo de clave, el formato PrivateKeyInfo sin cifrar de PKCS#8.

i2d_PrivateKey_bio() y i2d_PrivateKey_fp() son similares a i2d_PrivateKey() excepto que escriben en un puntero BIO o FILE y usan una convención diferente para sus valores de retorno.

i2d_PKCS8PrivateKeyInfo_bio() y i2d_PKCS8PrivateKeyInfo_fp() codifican val_in en el formato PrivateKeyInfo sin cifrar de PKCS#8. Son similares a i2d_PrivateKey() excepto que no utilizan ningún formato específico del algoritmo y que escriben en un puntero BIO o FILE en lugar de un búfer.

Todas estas funciones utilizan el formato DER y claves sin cifrar. Las aplicaciones que deseen cifrar o descifrar claves privadas deben utilizar otras funciones como d2i_PKCS8PrivateKey_bio(3) en su lugar.

Si *val_out no es NULL al llamar a d2i_PrivateKey() o d2i_AutoPrivateKey() (es decir, se reutiliza una estructura existente) y el formato de clave es PKCS#8, entonces *val_out se liberará y se reemplazará en una llamada exitosa.

d2i_PublicKey() llama a d2i_DSAPublicKey(3), o2i_ECPublicKey(3), o d2i_RSAPublicKey(3) dependiendo de type y almacena el resultado en el objeto EVP_PKEY devuelto.

i2d_PublicKey() llama a i2d_DSAPublicKey(3), i2o_ECPublicKey(3), o i2d_RSAPublicKey(3) dependiendo del algoritmo utilizado por val_in.

VALORES DE RETORNO

d2i_PrivateKey(), d2i_AutoPrivateKey(), d2i_PrivateKey_bio(), d2i_PrivateKey_fp(), y d2i_PublicKey() devuelven una estructura EVP_PKEY válida o NULL si ocurre un error.

i2d_PrivateKey() y i2d_PublicKey() devuelven el número de bytes codificados correctamente o un valor negativo si ocurre un error.

i2d_PrivateKey_bio(), i2d_PrivateKey_fp(), i2d_PKCS8PrivateKeyInfo_bio(), y i2d_PKCS8PrivateKeyInfo_fp() devuelven 1 para éxito o 0 si ocurre un error.

Para todas las funciones, el código de error se puede obtener llamando a ERR_get_error(3).

DESCRIPTION

These functions are used to encode and decode private and public keys. They can handle keys encoded in the PKCS#8 format (see STANDARDS) or the older, less flexible, traditional format (also known as PEM or RFC1421 format).

The traditional format is described in RFC1421 and consists of a header line "-----BEGIN <keytype> PRIVATE KEY-----", followed by base64 encoded data, followed by a footer line "-----END <keytype> PRIVATE KEY-----". The <keytype> is typically RSA or DSA.

The PKCS#8 format is more general and is described in PKCS#8.

The functions fall into three groups:

d2i_* functions decode keys from DER encoded binary format. The parameters in and len specify the input buffer and its length. The decoded key is returned and stored in the location pointed to by x, which can be NULL. If x is not NULL, and *x is not NULL, the existing EVP_PKEY structure is reused.

i2d_* functions encode keys to DER encoded binary format. The parameter x is the key to encode. If out is not NULL, the DER encoded key is written to the buffer pointed to by out, and the length of the encoded key is returned. The buffer must be large enough to hold the encoded key. If out is NULL, a buffer is allocated, and a pointer to it is stored in out. The caller is responsible for freeing this buffer using OPENSSL_free(). The length of the encoded key is returned.

The d2i_*_bio and i2d_*_bio functions work with BIO structures, which abstract input/output operations. They can be used to read from or write to files, sockets, or memory buffers.

The d2i_*_fp and i2d_*_fp functions work with standard C FILE pointers.

d2i_AutoPrivateKey, d2i_AutoPrivateKey_bio, and d2i_AutoPrivateKey_fp attempt to automatically detect whether the key is in PKCS#8 or traditional format, and decode it accordingly.

d2i_PrivateKey, d2i_PrivateKey_bio, and d2i_PrivateKey_fp decode a private key from PKCS#1 RSAPrivateKey or DSA/ECPrivateKey structure. They cannot handle PKCS#8 format.

i2d_PrivateKey, i2d_PrivateKey_bio, and i2d_PrivateKey_fp encode an EVP_PKEY structure into PKCS#1 RSAPrivateKey or DSA/ECPrivateKey structure.

d2i_PublicKey, d2i_PublicKey_bio, and d2i_PublicKey_fp decode a public key from PKCS#1 RSAPublicKey or SubjectPublicKeyInfo structure.

i2d_PublicKey, i2d_PublicKey_bio, and i2d_PublicKey_fp encode an EVP_PKEY structure into PKCS#1 RSAPublicKey or SubjectPublicKeyInfo structure.

d2i_PKCS8PrivateKeyInfo, d2i_PKCS8PrivateKeyInfo_bio, and d2i_PKCS8PrivateKeyInfo_fp decode a PKCS#8 PrivateKeyInfo structure.

i2d_PKCS8PrivateKeyInfo, i2d_PKCS8PrivateKeyInfo_bio, and i2d_PKCS8PrivateKeyInfo_fp encode an EVP_PKEY structure into a PKCS#8 PrivateKeyInfo structure.

RETURN VALUES

The d2i_* functions return a pointer to the decoded key structure on success, or NULL on failure. The i2d_* functions return the number of bytes written on success, or a non-positive value on failure.
