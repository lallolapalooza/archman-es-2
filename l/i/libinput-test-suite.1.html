NOMBRE

libinput-test-suite - ejecuta el conjunto de pruebas de libinput

SINOPSIS

libinput test-suite [OPCIONES]

DESCRIPCIÓN

El comando libinput test-suite ejecuta el conjunto de pruebas de libinput. Su propósito principal es verificar las compilaciones de distribución después de las actualizaciones de paquetes. Las fallas en el conjunto de pruebas generalmente indican parches faltantes y/o capas inferiores del sistema incompatibles.

El conjunto de pruebas no debe ser ejecutado por usuarios. Es posible la pérdida de datos.

El conjunto de pruebas debe ejecutarse como root. El conjunto de pruebas instala varios archivos en el sistema anfitrión (ver sección ARCHIVOS), ejecuta comandos del sistema y crea dispositivos virtuales del kernel a través de uinput. Estos dispositivos interferirán con cualquier sesión activa y pueden causar pérdida de datos.

Se recomienda que el conjunto de pruebas se ejecute en una máquina virtual y/o en un sistema que no esté en uso. No se requiere un entorno gráfico para ejecutar el conjunto de pruebas.

OPCIONES

Tenga en cuenta que las opciones pueden cambiar en futuras versiones de libinput. Los nombres de las pruebas, los nombres de los dispositivos de prueba y los nombres de los grupos de pruebas pueden cambiar en cualquier momento.

--filter-test "nombre_prueba"
Un glob que limita las pruebas a ejecutar. Especificar un filtro establece el valor predeterminado de --jobs a 1.
--filter-device "nombre_dispositivo"
Un glob que limita los dispositivos para los que se ejecutarán las pruebas. Especificar un filtro establece el valor predeterminado de --jobs a 1.
--filter-group "nombre_grupo"
Un glob que limita las pruebas a grupos (con nombres arbitrarios). Especificar un filtro establece el valor predeterminado de --jobs a 1.
--filter-deviceless
SOLO PARA USO INTERNO
-h, --help
Imprimir ayuda
-j, --jobs 8
Número de procesos paralelos a ejecutar. Predeterminado: 8.
--list
Listar todos los casos de prueba y los dispositivos para los que se ejecutan. Los nombres de las pruebas, los nombres de los dispositivos de prueba y los nombres de los grupos de pruebas pueden cambiar en cualquier momento.
--verbose
Habilitar salida detallada, incluyendo mensajes de depuración de libinput.

ARCHIVOS

Los siguientes directorios se modifican:

/usr/share/libinput
Las correcciones específicas del dispositivo de prueba se instalan en este directorio con un prefijo personalizado. Los archivos en este directorio no se tocan, pero se instalan nuevos archivos y se eliminan al salir. Los archivos existentes (por ejemplo, de una ejecución anterior abortada) con el mismo nombre se sobrescribirán y eliminarán silenciosamente.
/run/udev/rules.d
Las reglas de udev específicas de la prueba se instalan en este directorio y se eliminan al salir.

CONFIGURACIÓN DEL SISTEMA

El fragmento de xorg.conf.d(5) a continuación asegura que el servidor X ignore los dispositivos de prueba creados por este conjunto de pruebas:

Section "InputClass"
        Identifier "Ignorar dispositivos del conjunto de pruebas de libinput"
        MatchProduct "litest"
        Option "Ignore" "on"
EndSection

No se requiere configuración para los compositores de Wayland. El modo predeterminado de libinput ignorará los dispositivos de prueba de este conjunto de pruebas.

ERRORES

Algunas pruebas son sensibles al tiempo. Donde un sistema está bajo carga pesada, una prueba puede fallar. Volver a ejecutar la prueba con --filter-test puede ayudar a verificar si la falla de un caso de prueba fue una falla real.
