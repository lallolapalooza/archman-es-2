LIBPIPELINE(3) Manual de Funciones de Biblioteca LIBPIPELINE(3)

NOMBRE

libpipeline — biblioteca de manipulación de tuberías (pipelines)

SINOPSIS

#include <pipeline.h>

DESCRIPCIÓN

libpipeline es una biblioteca C para configurar y ejecutar tuberías de procesos, sin necesidad de recurrir al análisis de comandos de línea de shell, que a menudo es propenso a errores e inseguro. Esto libera a los programadores de la necesidad de construir laboriosamente tuberías utilizando primitivas de bajo nivel como fork y execve.

La forma general de usar libpipeline implica construir una estructura pipeline y añadirle una o más estructuras pipecmd. Un pipecmd representa un subproceso (o "comando"), mientras que un pipeline representa una secuencia de subprocesos cuya salida de cada uno está conectada a la entrada del siguiente, como en el ejemplo ls | grep pattern | less. El programa llamante puede ajustar ciertas propiedades de cada comando de forma independiente, como su entorno y la prioridad nice(3), así como propiedades de toda la tubería, como su entrada y salida y la forma en que se manejan las señales durante su ejecución. Luego, el programa llamante puede iniciar la tubería, leer su salida, esperar a que se complete y recopilar su estado de salida.

Las cadenas de caracteres pasadas como argumentos de función const char * serán copiadas por la biblioteca.

Funciones para construir comandos individuales

pipecmd *pipecmd_new(const char *name)

Construye un nuevo comando que representa la ejecución de un programa llamado name.

pipecmd *pipecmd_new_argv(const char *name, va_list argv)
 
pipecmd *pipecmd_new_args(const char *name, ...)

Constructores de conveniencia que envuelven pipecmd_new() y pipecmd_arg(). Construye un nuevo comando que representa la ejecución de un programa llamado name con argumentos. Termina los argumentos con nullptr (antes de C23: (void *) 0).

pipecmd *pipecmd_new_argstr(const char *argstr)

Divide argstr por espacios en blanco para construir un comando y argumentos, respetando las comillas simples y dobles de estilo shell, y las barras invertidas, pero no otras "maldades" del shell como comodines, punto y coma o comillas invertidas. Esto solo se incluye para soportar situaciones en las que los argumentos del comando se codifican en archivos de configuración y similares. Si bien es más seguro que system(3), todavía implica un análisis de cadenas significativo que es inherentemente más arriesgado que evitarlo por completo. Por favor, intente evitar usarlo en código nuevo.

Funciones para construir tuberías

pipeline *pipeline_new(void)

Construye una nueva tubería vacía.

void pipeline_free(pipeline *pipe)

Libera la memoria utilizada por la tubería.

int pipeline_run(pipeline *pipe)

Ejecuta la tubería y espera a que termine. Devuelve el estado de salida del último comando de la tubería, o -1 si ocurrió un error.

int pipeline_run_fd(pipeline *pipe, int input_fd, int output_fd)

Ejecuta la tubería y espera a que termine. La entrada del primer comando se tomará de input_fd y la salida del último comando se dirigirá a output_fd. Devuelve el estado de salida del último comando de la tubería, o -1 si ocurrió un error.

void pipeline_set_timeout(pipeline *pipe, unsigned int seconds)

Establece un tiempo de espera para la ejecución de la tubería. Si la tubería tarda más de seconds en completarse, se terminará.

int pipeline_get_stdout_pipe(pipeline *pipe)

Devuelve un descriptor de archivo de solo lectura que puede ser utilizado para leer la salida estándar de toda la tubería. Solo se puede llamar a esto una vez, y solo si la tubería aún no se ha ejecutado.

int pipeline_get_stderr_pipe(pipeline *pipe)

Devuelve un descriptor de archivo de solo lectura que puede ser utilizado para leer la salida de error estándar de toda la tubería. Solo se puede llamar a esto una vez, y solo si la tubería aún no se ha ejecutado.

int pipeline_get_return_code(pipeline *pipe)

Devuelve el código de retorno del último comando de la tubería. Solo se puede llamar a esto una vez, y solo después de que la tubería se haya ejecutado.

ENTORNO

libpipeline ignora la mayor parte del entorno del proceso llamante. Cada comando se ejecuta con un conjunto mínimo de variables de entorno. La variable PATH se establece en un valor predeterminado razonable. Se puede añadir un entorno personalizado a un comando individualmente, véase pipecmd_set_environ.

EJEMPLOS

Para ejecutar el comando ls -l | wc -l:

pipeline *pipe;
pipecmd *cmd1, *cmd2;
int ret;
pipe = pipeline_new();
cmd1 = pipecmd_new_args("ls", "-l", NULL);
cmd2 = pipecmd_new("wc");
pipecmd_arg(cmd2, "-l");
pipeline_add_command(pipe, cmd1);
pipeline_add_command(pipe, cmd2);
ret = pipeline_run(pipe);
pipeline_free(pipe);

VER TAMBIÉN

fork(2), exec(3), pipe(2), system(3)

Comandos

pipecmd *pipecmd_new(const char *name, va_list args)

Create a new command, with arguments given by args. The command name is given by name. The argument list must be terminated by NULL (before C23: (void *) 0).

For example:

pipecmd *cmd = pipecmd_new("echo", "hello", "world", NULL);

Added in libpipeline 1.1.0.

pipecmd *pipecmd_new_args(const char *name, ...)

Convenience constructor wrapping pipecmd_new().

pipecmd *pipecmd_new_str(const char *str)

Create a new command by parsing the string str. This uses the shell's parsing rules, but doesn't actually invoke the shell.

Added in libpipeline 1.4.0.

pipecmd *pipecmd_new_strv(const char *str)
 
pipecmd *pipecmd_new_shell_str(const char *str)

Create a new command by passing the string str to the system shell. This is generally a bad idea, unless you really need shell features such as pipes, redirection, globbing, variable expansion, etc.

Added in libpipeline 1.4.0.

pipecmd *pipecmd_new_shell_strv(const char *str)
 
pipecmd *pipecmd_new_seq(void)

Create a new empty sequence of commands.

Added in libpipeline 1.5.0.

void pipecmd_free(pipecmd *cmd)

Destroy a command. Safely does nothing if cmd is NULL.

int pipecmd_num_args(pipecmd *cmd)

Return the number of arguments to this command. Note that this includes the command name as the first argument, so the command ‘echo foo bar’ is counted as having three arguments.

Added in libpipeline 1.1.0.

void pipecmd_nice(pipecmd *cmd, int value)

Set the nice(3) value for this command. Defaults to 0. Errors while attempting to set the nice value are ignored, aside from emitting a debug message.

void pipecmd_discard_err(pipecmd *cmd, int discard_err)

If discard_err is non-zero, redirect this command's standard error to /dev/null. Otherwise, and by default, pass it through. This is usually a bad idea.

void pipecmd_chdir(pipecmd *cmd, const char *directory)

Change the working directory to directory while running this command.

Added in libpipeline 1.3.0.

void pipecmd_fchdir(pipecmd *cmd, int directory_fd)

Change the working directory to the directory given by the open file descriptor directory_fd while running this command.

Added in libpipeline 1.4.0.

void pipecmd_setenv(pipecmd *cmd, const char *name, const char *value)

Set environment variable name to value while running this command.

void pipecmd_unsetenv(pipecmd *cmd, const char *name)

Unset environment variable name while running this command.

void pipecmd_clearenv(pipecmd *cmd)

Clear the environment while running this command. (Note that environment operations work in sequence; pipecmd_clearenv followed by pipecmd_setenv causes the command to have just a single environment variable set.) Beware that this may cause unexpected failures, for example if some of the contents of the environment are necessary to execute programs at all (say, PATH).

Added in libpipeline 1.1.0.

void pipecmd_pre_exec(pipecmd *cmd, pipecmd_function_type *func, pipecmd_function_free_type *free_func, void *data);

Install a pre-exec handler. This will be run immediately before executing the command's payload (process or function). Pass NULL to clear any existing pre-exec handler. The data argument is passed as the function's only argument, and will be freed before returning using free_func (if non-NULL).

This is similar to pipeline_install_post_fork, except that is specific to a single command rather than installing a global handler, and it runs slightly later (immediately before exec rather than immediately after fork).

Added in libpipeline 1.5.0.

void pipecmd_sequence_command(pipecmd *cmd, pipecmd *child)

Add a command to a sequence created using pipecmd_new_sequence().

void pipecmd_dump(pipecmd *cmd, FILE *stream)

Dump a string representation of a command to stream.

char *pipecmd_tostring(pipecmd *cmd)

Return a string representation of a command. The caller should free the result.

void pipecmd_exec(pipecmd *cmd)

Execute a single command, replacing the current process. Never returns, instead exiting non-zero on failure.

Added in libpipeline 1.1.0.

Construct a new pipeline.

Constructores de conveniencia que envuelven pipeline_new() y pipeline_command(). Construye un nuevo pipeline que consiste en la lista dada de comandos. Termina los comandos con nullptr (antes de C23: (void *) 0).

Construye un nuevo pipeline y añade un solo comando a él.

pipeline *pipeline_join(pipeline *p1, pipeline *p2)

Une dos pipelines, ninguno de los cuales puede iniciarse. Descarta want_out, want_outfile, y outfd de p1, y want_in, want_infile, y infd de p2.

void pipeline_connect(pipeline *source, pipeline *sink, ...)

Conecta la entrada de uno o más pipelines receptores a la salida de un pipeline fuente. El pipeline fuente puede iniciarse, pero en ese caso se debe haber llamado a pipeline_want_out() con un fd negativo; de lo contrario, llama a pipeline_want_out(source, -1). En cualquier caso, llama a pipeline_want_in(sink, -1) en todos los receptores, ninguno de los cuales puede iniciarse. Termina los argumentos con nullptr (antes de C23: (void *) 0).

Esta es una conexión a nivel de aplicación; los datos pueden ser interceptados entre los pipelines por el programa antes de llamar a pipeline_pump(), lo que hace que los datos fluyan desde la fuente a los receptores. Es principalmente útil cuando hay más de un pipeline receptor, en cuyo caso los pipelines no se pueden simplemente concatenar en uno solo.

El resultado es similar a tee(1), excepto que la salida puede enviarse a más de dos lugares y puede enviarse fácilmente a múltiples procesos.

void pipeline_want_in(pipeline *p, int fd)

Set the input file descriptor for the pipeline to fd. If fd is negative, then the pipeline will create its own input (reading from a file, or from a pipe if this is the first stage). If fd is non-negative, then the pipeline will read from that file descriptor. This is only allowed if the pipeline has not yet been started.

void pipeline_want_infile(pipeline *p, const char *filename)

Set the input file for the pipeline to filename. This is only allowed if the pipeline has not yet been started.

void pipeline_want_out(pipeline *p, int fd)

Set the output file descriptor for the pipeline to fd. If fd is negative, then the pipeline will create its own output (writing to stdout, or to a pipe if this is the last stage). If fd is non-negative, then the pipeline will write to that file descriptor. This is only allowed if the pipeline has not yet been started.

void pipeline_want_outfile(pipeline *p, const char *filename)

Set the output file for the pipeline to filename. This is only allowed if the pipeline has not yet been started.

int pipeline_run(pipeline *p)

Run the pipeline, and wait for it to complete. Returns the exit status of the last command in the pipeline, or -1 if any command failed to start or terminated abnormally.

Added in libpipeline 1.1.0.

int pipeline_run_abort(pipeline *p)

Run the pipeline, and wait for it to complete. Returns the exit status of the last command in the pipeline, or -1 if any command failed to start or terminated abnormally. If any command exits abnormally, the pipeline is aborted.

Added in libpipeline 1.5.0.

pid_t pipeline_run_background(pipeline *p)

Run the pipeline in the background. Returns the process ID of the first process in the pipeline, or -1 if the pipeline failed to start.

Added in libpipeline 1.1.0.

void pipeline_pump(pipeline *source, pipeline *sink, ...)

Start the source pipeline, and connect its output to the input of the sink pipeline(s). Then, pump data from the source to the sinks until the source is exhausted. Then, close the source, wait for the sinks to finish, and return the exit status of the last sink.

This is primarily intended for use with pipeline_connect().

Added in libpipeline 1.3.0.

void pipeline_install_post_fork(pipeline *p, pipecmd_function_type *func, pipecmd_function_free_type *free_func, void *data);

Install a post-fork handler. This will be run immediately after forking each child process in the pipeline, but before it execs. Pass NULL to clear any existing post-fork handler. The data argument is passed as the function's only argument, and will be freed before returning using free_func (if non-NULL).

Added in libpipeline 1.5.0.

EJEMPLOS

Aquí hay un ejemplo de cómo leer la salida de ls usando libpipeline:

pipeline *p;
char *line;
p = pipeline_new (PIPELINE_SLURP,
                  pipeline_command_new ("ls", "ls", NULL),
                  NULL);
if (!p) {
        perror ("pipeline_new");
        exit (EXIT_FAILURE);
}
line = pipeline_peekline (p);
if (!strstr (line, "coding: UTF-8"))
        printf ("Unicode text follows:0);
while (line = pipeline_readline (p))
        printf ("  %s", line);
pipeline_free (p);

AUTORES

La mayor parte de libpipeline fue escrita por Colin Watson ⟨cjwatson@debian.org⟩, originalmente para su uso en man-db. La versión inicial se basó muy vagamente en la función run_pipeline() de GNU groff, escrita por James Clark ⟨jjc@jclark.com⟩. También contiene código de biblioteca de Markus Armbruster, y de varios contribuidores a Gnulib.

ERRORES CONOCIDOS

Es poco probable que el uso de esta biblioteca en un programa que ejecuta otros procesos hijos y/o instala su propio manejador SIGCHLD funcione correctamente.
