PKCS7_DATAINIT(3) Manual de funciones de biblioteca PKCS7_DATAINIT(3)

NOMBRE

PKCS7_dataInit — construye una cadena de BIO para añadir o recuperar contenido

SINOPSIS

biblioteca “libcrypto”
#include <openssl/pkcs7.h>

BIO *
PKCS7_dataInit(PKCS7 *p7, BIO *indata);

DESCRIPCIÓN

PKCS7_dataInit() construye una cadena de BIO en preparación para introducir o recuperar datos de p7. Dependiendo del contentType de p7, la cadena creada comienza con:

para SignedData:
uno o más filtros de resumen de mensaje BIO_f_md(3)
para EnvelopedData:
un filtro de cifrado BIO_f_cipher(3)
para SignedAndEnvelopedData:
uno o más filtros de resumen de mensaje BIO_f_md(3) seguidos por un filtro de cifrado BIO_f_cipher(3)
para DigestedData:
un filtro de resumen de mensaje BIO_f_md(3)
para datos arbitrarios:
sin BIO de filtro

Se añade un BIO adicional al final de la cadena, dependiendo de la primera condición que se cumpla en la siguiente lista:

indata
si el argumento indata no es NULL. Esto solo tiene sentido al verificar una firma separada, en cuyo caso se espera que indata proporcione el contenido asociado con la firma separada.
BIO_s_null(3)
si el contentType de p7 es SignedData y está configurado para contener una firma separada. Esto solo tiene sentido al crear la firma separada.
BIO_new_mem_buf(3)
al leer de un objeto SignedData o DigestedData. PKCS7_dataInit() adjunta el final de la cadena al contenido anidado de p7.
BIO_s_mem(3)
en caso contrario. Este es el caso más común al escribir datos en p7. PKCS7_dataFinal(3) puede usarse más tarde para transferir los datos del BIO de memoria a p7.

Añadir contenido

Antes de llamar a PKCS7_dataInit() para añadir contenido, generalmente se requieren PKCS7_new(3), PKCS7_set_type(3) y PKCS7_content_new(3) para crear p7, elegir su tipo deseado y asignar la estructura ContentInfo anidada. Alternativamente, para SignedData, se puede usar PKCS7_sign(3) con las banderas PKCS7_PARTIAL o PKCS7_STREAM, o para EnvelopedData, PKCS7_encrypt(3) con la bandera PKCS7_STREAM.

Después de llamar a PKCS7_dataInit(), los datos deseados se pueden escribir en el BIO devuelto, se puede llamar a BIO_flush(3) sobre él, se puede usar PKCS7_dataFinal(3) para transferir los datos procesados del BIO de memoria devuelto a la estructura p7, y la cadena puede finalmente destruirse con BIO_free_all(3).

Si bien PKCS7_dataInit() admite los tipos EnvelopedData y SignedAndEnvelopedData, su uso para estos tipos es incómodo y propenso a errores, excepto cuando se usa PKCS7_encrypt(3) para la configuración porque PKCS7_content_new(3) no admite estos dos tipos. Por lo tanto, además de crear p7 en sí y establecer su tipo, la estructura ContentInfo anidada también debe construirse con PKCS7_new(3) y PKCS7_set_type(3) e insertarse manualmente en el campo correcto de la subestructura respectiva de p7.

Recuperar contenido

PKCS7_dataInit() también se puede llamar en un objeto completamente poblado de tipo SignedData o DigestedData. Después de eso, BIO_read(3) se puede usar para recuperar datos de él. En este caso de uso, no llame a PKCS7_dataFinal(3); simplemente continúe directamente a BIO_free_all(3) después de leer los datos.

VALORES DE RETORNO

PKCS7_dataInit() devuelve una cadena de BIO en caso de éxito o NULL en caso de error. Falla si p7 es NULL, si el campo content de p7 está vacío, si el contentType de p7 no es compatible, si se requiere un cifrador pero no hay ninguno configurado, o si alguna operación requerida falla, por ejemplo, debido a falta de memoria o por varias otras razones.

VER TAMBIÉN

BIO_new(3), BIO_read(3), PKCS7_content_new(3), PKCS7_dataFinal(3), PKCS7_encrypt(3), PKCS7_final(3), PKCS7_new(3), PKCS7_set_type(3), PKCS7_sign(3)

HISTORIA

PKCS7_dataInit() apareció por primera vez en SSLeay 0.8.1 y ha estado disponible desde OpenBSD 2.4.

ADVERTENCIAS

Esta función no admite EncryptedData.

ERRORES

Si p7 es una estructura completamente poblada que contiene EnvelopedData, SignedAndEnvelopedData, o datos arbitrarios, PKCS7_dataInit() devuelve una cadena de BIO que en última instancia lee de un BIO de memoria vacío, por lo que leer de él indicará inmediatamente el fin de archivo en lugar de leer los datos reales contenidos en p7.
