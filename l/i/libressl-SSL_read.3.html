Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_READ(3) Manual de funciones de la biblioteca SSL_READ(3)

NOMBRE

SSL_read_ex, SSL_read, SSL_peek_ex, SSL_peek — leer bytes de una conexión TLS

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_read_ex(SSL *ssl, void *buf, size_t num, size_t *readbytes);

int
SSL_read(SSL *ssl, void *buf, int num);

int
SSL_peek_ex(SSL *ssl, void *buf, size_t num, size_t *readbytes);

int
SSL_peek(SSL *ssl, void *buf, int num);

DESCRIPCIÓN

SSL_read_ex() y SSL_read() intentan leer num bytes de la conexión SSL especificada (ssl) en el búfer buf. En caso de éxito, SSL_read_ex() almacena el número de bytes realmente leídos en *readbytes.

SSL_peek_ex() y SSL_peek() son idénticos a SSL_read_ex() y SSL_read() respectivamente, excepto que no se eliminan bytes del BIO subyacente durante la lectura, de modo que una llamada posterior a SSL_read_ex() o SSL_read() producirá al menos los mismos bytes una vez más.

En lo sucesivo, SSL_read_ex(), SSL_read(), SSL_peek_ex() y SSL_peek() se denominan “funciones de lectura”.

Si es necesario, una función de lectura negociará una sesión TLS, si aún no se ha realizado explícitamente mediante SSL_connect(3) o SSL_accept(3). Si el par solicita una renegociación, se realizará de forma transparente durante la operación de la función de lectura. El comportamiento de las funciones de lectura depende del BIO subyacente.

Para que la negociación transparente tenga éxito, el objeto ssl debe haber sido inicializado en modo cliente o servidor. Esto se hace llamando a SSL_set_connect_state(3) o SSL_set_accept_state(3) antes de la primera llamada a una función de lectura.

Las funciones de lectura operan basándose en los registros TLS. Los datos se reciben en registros (con un tamaño máximo de registro de 16 KB). Solo cuando se ha recibido completamente un registro, se puede procesar (descifrar y verificar la integridad). Por lo tanto, los datos que no se recuperaron en la última llamada de lectura todavía pueden estar en el búfer dentro de la capa TLS y se recuperarán en la próxima llamada de lectura. Si num es mayor que el número de bytes en el búfer, las funciones de lectura devolverán los bytes en el búfer. Si no hay más bytes en el búfer, las funciones de lectura activarán el procesamiento del siguiente registro. Solo cuando el registro se haya recibido y procesado completamente, las funciones de lectura devolverán éxito. Se devolverá como máximo el contenido del registro. Como el tamaño de un registro TLS puede superar el tamaño máximo del paquete del transporte subyacente (por ejemplo, TCP), puede ser necesario leer varios paquetes de la capa de transporte antes de que el registro esté completo y la llamada de lectura pueda tener éxito.

Si el BIO subyacente es bloqueante, una función de lectura solo devolverá una vez que la operación de lectura se haya completado o se haya producido un error, excepto cuando tenga lugar una renegociación, en cuyo caso puede ocurrir un SSL_ERROR_WANT_READ. Este comportamiento puede ser controlado con la bandera SSL_MODE_AUTO_RETRY de la llamada SSL_CTX_set_mode(3).

Si el BIO subyacente no es bloqueante, una función de lectura también devolverá cuando el BIO subyacente no haya podido satisfacer las necesidades de la función para continuar la operación. En este caso, una llamada a SSL_get_error(3) con el valor de retorno de la función de lectura dará SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE. Como en cualquier momento es posible una renegociación, una función de lectura también puede causar operaciones de escritura. El proceso que llama debe repetir la llamada después de tomar las medidas adecuadas para satisfacer las necesidades de la función de lectura. La acción depende del BIO subyacente. Al utilizar un socket no bloqueante, no hay nada que hacer, pero se puede usar select(2) para verificar la condición requerida. Al utilizar un BIO de búfer, como un par de BIO, los datos deben escribirse en el BIO o recuperarse de él antes de poder continuar.

SSL_pending(3) puede utilizarse para saber si hay bytes en el búfer disponibles para su recuperación inmediata. En este caso, se puede llamar a una función de lectura sin bloquear o sin recibir realmente nuevos datos del socket subyacente.

Cuando una operación de función de lectura debe repetirse debido a SSL_ERROR_WANT_READ o SSL_ERROR_WANT_WRITE, debe repetirse con los mismos argumentos.

VALORES DE RETORNO

SSL_read_ex() y SSL_peek_ex() devuelven 1 para éxito o 0 para fallo. El éxito significa que se han leído uno o más bytes de datos de la aplicación de la conexión SSL. El fallo significa que no se han podido leer bytes de la conexión SSL. Los fallos pueden ser reintentables (por ejemplo, estamos esperando que la red entregue más bytes) o no reintentables (por ejemplo, un error fatal de red). En caso de fallo, llame a SSL_get_error(3) para descubrir el motivo, que indicará si la llamada es reintentable o no.

Para SSL_read() y SSL_peek(), pueden ocurrir los siguientes valores de retorno:

>0
La operación de lectura fue exitosa. El valor de retorno es el número de bytes leídos realmente de la conexión TLS.
0
La operación de lectura no fue exitosa. El motivo puede ser un cierre limpio debido a una alerta de “close notify” enviada por el par (en cuyo caso se establece el indicador SSL_RECEIVED_SHUTDOWN en el estado de cierre de ssl (ver SSL_shutdown(3) y SSL_set_shutdown(3)). También es posible que el par simplemente haya cerrado el transporte subyacente y el cierre esté incompleto. Llame a SSL_get_error(3) con el valor de retorno para determinar si se produjo un error o si la conexión se cerró limpiamente (SSL_ERROR_ZERO_RETURN).
<0
La operación de lectura no fue exitosa, ya sea porque ocurrió un error o porque el proceso que llama debe tomar alguna acción. Llame a SSL_get_error(3) con el valor de retorno para averiguar el motivo.

HISTORY

SSL_read() apareció en SSLeay 0.4 o anterior. SSL_peek() apareció por primera vez en SSLeay 0.6.6. Ambas funciones han estado disponibles desde OpenBSD 2.4.

SSL_read_ex() y SSL_peek_ex() aparecieron por primera vez en OpenSSL 1.1.1 y han estado disponibles desde OpenBSD 7.1.
