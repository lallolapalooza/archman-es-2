CMS_GET0_TYPE(3) Manual de funciones de biblioteca CMS_GET0_TYPE(3)

NOMBRE

CMS_get0_type, CMS_get_version, CMS_set1_eContentType, CMS_get0_eContentType, CMS_get0_content — obtener y establecer tipos y contenido de CMS

SINOPSIS

biblioteca “libcrypto”
#include <openssl/cms.h>

const ASN1_OBJECT *
CMS_get0_type(const CMS_ContentInfo *cms);

int
CMS_get_version(const CMS_ContentInfo *cms, long *version);

int
CMS_set1_eContentType(CMS_ContentInfo *cms, const ASN1_OBJECT *oid);

const ASN1_OBJECT *
CMS_get0_eContentType(CMS_ContentInfo *cms);

ASN1_OCTET_STRING **
CMS_get0_content(CMS_ContentInfo *cms);

DESCRIPCIÓN

CMS_get0_type() devuelve el tipo de contenido de la estructura ContentInfo cms. El valor ASN1_OBJECT devuelto puede ser convertido a un valor NID entero usando OBJ_obj2nid(3). Los siguientes tipos de contenido son identificados por los siguientes NIDs:

SignedData NID_pkcs7_signed
EnvelopedData NID_pkcs7_enveloped
DigestedData NID_pkcs7_digest
EncryptedData NID_pkcs7_encrypted
AuthenticatedData NID_id_smime_ct_authData
CompressedData NID_id_smime_ct_compressedData
datos arbitrarios NID_pkcs7_data

Los tipos SignedData, DigestedData, AuthenticatedData, y CompressedData contienen un campo encapContentInfo para permitir la incrustación de contenido, y EnvelopedData y EncryptedData contienen un campo encryptedContentInfo para tal propósito. El tipo de contenido incrustado a ser almacenado en ese campo puede ser establecido con la función CMS_set1_eContentType(), para ser llamada en estructuras cms devueltas por funciones como CMS_sign(3) o CMS_encrypt(3) con el flag CMS_PARTIAL establecido y antes de que la estructura sea finalizada; de lo contrario, los resultados no están definidos. CMS_set1_eContentType() copia el oid suministrado, por lo que debe ser liberado después de su uso.

CMS_get_version() establece *version al número de versión de sintaxis de la estructura ContentInfo cms. La versión es un número entre 0 y 5 y está definido para todos los tipos de contenido anteriores excepto para datos arbitrarios. Para datos arbitrarios y tipos de contenido no soportados, CMS_get_version() falla y el contenido de *version no está especificado.

CMS_get0_eContentType() devuelve el tipo de contenido incrustado.

CMS_get0_content() devuelve un puntero a la ubicación de almacenamiento donde se almacena el puntero al contenido incrustado. Esto significa, por ejemplo, que después de

ASN1_OCTET_STRING **pconf = CMS_get0_content(cms);

*pconf podría ser NULL si no hay contenido incrustado. Las aplicaciones pueden acceder, modificar o crear el contenido incrustado en una estructura CMS_ContentInfo usando esta función. Las aplicaciones normalmente no necesitarán modificar el contenido incrustado, ya que normalmente es establecido por funciones de nivel superior.

VALORES DE RETORNO

CMS_get0_type() y CMS_get0_eContentType() devuelven punteros internos a estructuras de OBJECT IDENTIFIER.

CMS_get_version() devuelve 1 en caso de éxito y 0 en caso de fallo.

CMS_get0_content() devuelve un puntero interno a la ubicación de almacenamiento donde se almacena el puntero al contenido incrustado.

CMS_set1_eContentType() devuelve 1 para éxito o 0 si ocurrió un error. El error puede ser obtenido de ERR_get_error(3).
