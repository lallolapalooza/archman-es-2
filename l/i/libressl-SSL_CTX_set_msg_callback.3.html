SSL_CTX_SET_MSG_CALLBACK(3) Manual de funciones de biblioteca SSL_CTX_SET_MSG_CALLBACK(3)

NOMBRE

SSL_CTX_set_msg_callback, SSL_CTX_set_msg_callback_arg, SSL_set_msg_callback, SSL_set_msg_callback_arg — instalar una función de devolución de llamada para observar mensajes del protocolo

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

void
SSL_CTX_set_msg_callback(SSL_CTX *ctx, void (*cb)(int write_p, int version, int content_type, const void *buf, size_t len, SSL *ssl, void *arg));

void
SSL_CTX_set_msg_callback_arg(SSL_CTX *ctx, void *arg);

void
SSL_set_msg_callback(SSL *ssl, void (*cb)(int write_p, int version, int content_type, const void *buf, size_t len, SSL *ssl, void *arg));

void
SSL_set_msg_callback_arg(SSL *ssl, void *arg);

DESCRIPCIÓN

SSL_CTX_set_msg_callback() o SSL_set_msg_callback() pueden usarse para definir una función de devolución de llamada de mensajes cb para observar todos los mensajes del protocolo SSL/TLS (como mensajes de handshake) que se reciben o envían. SSL_CTX_set_msg_callback_arg() y SSL_set_msg_callback_arg() pueden usarse para establecer el argumento arg para la función de devolución de llamada, que está disponible para uso arbitrario de la aplicación.

SSL_CTX_set_msg_callback() y SSL_CTX_set_msg_callback_arg() especifican configuraciones predeterminadas que se copiarán a nuevos objetos SSL por SSL_new(3). SSL_set_msg_callback() y SSL_set_msg_callback_arg() modifican las configuraciones reales de un objeto SSL. El uso de un puntero NULL para cb deshabilita la devolución de llamada de mensajes.

Cuando la biblioteca SSL/TLS llama a cb para un mensaje del protocolo, los argumentos de la función tienen el siguiente significado:

write_p
Esta bandera es 0 cuando se ha recibido un mensaje del protocolo y 1 cuando se ha enviado un mensaje del protocolo.
version
La versión del protocolo según la cual la biblioteca interpreta el mensaje del protocolo, como TLS1_VERSION, TLS1_1_VERSION, TLS1_2_VERSION, DTLS1_VERSION, o DTLS1_2_VERSION.
content_type
Este es uno de los Tipos de Contenido valores definidos en la especificación del protocolo (SSL3_RT_CHANGE_CIPHER_SPEC, SSL3_RT_ALERT, SSL3_RT_HANDSHAKE, pero nunca SSL3_RT_APPLICATION_DATA porque la devolución de llamada solo se llamará para mensajes del protocolo.)
buf, len
buf apunta a un búfer que contiene el mensaje del protocolo, que consta de len bytes. El búfer ya no es válido después de que la función de devolución de llamada haya retornado.
ssl
El objeto SSL que recibió o envió el mensaje.
arg
El argumento definido por el usuario opcionalmente definido por SSL_CTX_set_msg_callback_arg() o SSL_set_msg_callback_arg().

Los mensajes del protocolo se pasan a la función de devolución de llamada después de la descifrado y la recolección de fragmentos, cuando corresponda. (Por lo tanto, los límites de registro no son visibles).

Si el procesamiento de un mensaje del protocolo recibido resulta en un error, es posible que la función de devolución de llamada no se llame. Por ejemplo, la función de devolución de llamada nunca verá mensajes que se consideren demasiado grandes para ser procesados.

Debido a la negociación automática de la versión del protocolo, version no es necesariamente la versión del protocolo utilizada por el remitente del mensaje: si un servidor solo SSL 3.0 recibe un mensaje TLS 1.0 ClientHello, version será SSL3_VERSION.

VER TAMBIÉN

ssl(3), SSL_new(3)

HISTORIA
