SSL_SET1_HOST(3) Manual de funciones de la biblioteca SSL_SET1_HOST(3)

NOMBRE

SSL_set1_host, SSL_set_hostflags, SSL_get0_peername — parámetros de verificación del servidor SSL

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

int
SSL_set1_host(SSL *ssl, const char *hostname);

void
SSL_set_hostflags(SSL *ssl, unsigned int flags);

const char *
SSL_get0_peername(SSL *ssl);

DESCRIPCIÓN

SSL_set1_host() configura una comprobación del nombre de host del servidor en el cliente ssl, estableciendo el nombre de dominio DNS esperado a hostname y borrando cualquier nombre de host especificado previamente. Si hostname es NULL o una cadena vacía, no se realizan comprobaciones de nombre en el certificado del par. Si se especifica un hostname no vacío, la verificación del certificado comprueba automáticamente el nombre de host del par mediante X509_check_host(3) con flags establecido a 0.

SSL_set_hostflags() establece las banderas que se pasarán a X509_check_host(3) cuando las comprobaciones de nombre sean aplicables; por defecto, el valor de flags es 0. Consulte X509_check_host(3) para obtener la lista de banderas disponibles y su significado.

SSL_get0_peername() devuelve el nombre de dominio DNS o el CommonName del sujeto del certificado del par que coincidió con uno de los identificadores de referencia. A menos que se deshabilite la coincidencia comodín, el nombre que coincida en el certificado del par puede ser un nombre comodín. Un identificador de referencia que comience con ‘.’ indica un prefijo de dominio padre en lugar de un nombre fijo. En este caso, el peername coincidente puede ser un subdominio del identificador de referencia. La cadena devuelta es propiedad de la biblioteca y deja de ser válida una vez que el objeto ssl asociado se borra o libera, o si se produce una renegociación. Las aplicaciones no deben liberar el valor de retorno.

Se recomienda a los clientes SSL que utilicen estas funciones en lugar de llamar explícitamente a X509_check_host(3).

VALORES DE RETORNO

SSL_set1_host() devuelve 1 para éxito o 0 para fallo.

SSL_get0_peername() devuelve el peername coincidente o NULL si la verificación del peername no es aplicable o si no se encontró ningún peername de confianza. Utilice SSL_get_verify_result(3) para determinar si la verificación tuvo éxito.

EJEMPLOS

Las siguientes llamadas comprueban el nombre de host. Se admiten comodines, pero deben coincidir con toda la etiqueta. Se recupera el nombre real coincidente en el certificado (que puede ser un comodín), y la aplicación debe copiarlo si se va a conservar más allá de la vida útil de la conexión SSL.

if (!SSL_set1_host(ssl, "smtp.example.com"))
	/* error */

/* XXX: Realizar el handshake de SSL_connect() y manejar los errores aquí */

if (SSL_get_verify_result(ssl) == X509_V_OK) {
	const char *peername = SSL_get0_peername(ssl);

	if (peername != NULL)
		/* Las comprobaciones de nombre estaban en el ámbito y coincidieron con el peername */
}

VER TAMBIÉN

ssl(3), SSL_CTX_set_verify(3), SSL_get_peer_certificate(3), SSL_get_verify_result(3), X509_check_host(3), X509_VERIFY_PARAM_set1_host(3)

HISTORIA

Las tres funciones aparecieron por primera vez en OpenSSL 1.1.0. SSL_set1_host() ha estado disponible desde OpenBSD 6.5, y SSL_set_hostflags() y SSL_get0_peername() desde OpenBSD 6.9.
