Funciones de Generación de Paquetes

El núcleo de libnet es la funcionalidad de generación de paquetes independiente de la plataforma. Estas funciones permiten a un programador de aplicaciones construir cabeceras de protocolo (y datos) de manera simple y consistente sin tener que preocuparse (demasiado) por los detalles de bajo nivel de la red. Cada función libnet_build() construye una parte de un paquete (generalmente una cabecera de protocolo). Si bien es perfectamente posible construir un paquete completo y listo para transmitir con una sola llamada a una función libnet_build(), generalmente se requieren más de una llamada a una función de la clase builder para construir un paquete completo. Un paquete completo listo para la red generalmente consta de más de una parte. Cada función que construye una cabecera de protocolo toma una serie de argumentos que corresponden aproximadamente a los valores de la cabecera tal como aparecen en la red. Este proceso es intuitivo pero a menudo resulta en funciones con prototipos enormes y marcos de pila grandes. Una cosa importante a tener en cuenta es que debes llamar a estas funciones en orden, correspondiente a cómo deben aparecer en la red (desde la capa de protocolo más alta hacia abajo). Este proceso de construcción es intuitivo; se aproxima a lo que sucede en el kernel de un sistema operativo. En otras palabras, para construir un paquete Network Time Protocol (NTP) utilizando la interfaz de capa de enlace, el programador de aplicaciones llamaría a las funciones libnet_build() en el siguiente orden:

1.
libnet_build_ntp()
2.
libnet_build_udp()
3.
libnet_build_ipv4()
4.
libnet_build_ethernet() Este orden es esencial para que libnet 1.1.x enlace correctamente el paquete internamente (versiones anteriores de libnet no tenían este requisito).

La Interfaz de Carga Útil

La interfaz de carga útil especifica una forma opcional de incluir datos directamente después de la cabecera de protocolo en cuestión. Puedes usar esta función para una variedad de propósitos, que incluyen los siguientes:

  • Incluir información de cabecera de protocolo adicional o arbitraria que no esté disponible en una interfaz libnet
  • Incluir una carga útil de paquete (segmento de datos)
  • Construir otra cabecera de protocolo que no esté disponible en una interfaz libnet Para emplear la interfaz, el programador de aplicaciones debe construir los datos de carga útil y pasar un puntero uint8_t * a estos datos y su tamaño a la función libnet_build() deseada. Libnet se encarga del resto.

Es importante tener en cuenta que algunas funciones (notablemente los constructores de IPv6) utilizan la interfaz de carga útil para especificar datos de longitud variable pero ostensiblemente no opcionales. Consulte las funciones individuales libnet_build_ipv6*() para obtener más información.

Esta información de alcanzabilidad de red incluye información sobre la lista de Sistemas Autónomos (AS) que atraviesa la información de alcanzabilidad. Esta información es suficiente para construir un grafo de conectividad de AS del cual se pueden eliminar bucles de enrutamiento y se pueden aplicar algunas decisiones de política a nivel de AS. Esta función construye la cabecera base BGP que se utiliza como preámbulo antes de cualquier otra cabecera BGP. Por ejemplo, un mensaje BGP KEEPALIVE se puede construir solo con esta función, mientras que una notificación de error requiere una llamada posterior a libnet_build_bgp4_notification.

Parámetros

marker un valor que el receptor puede predecir (si el tipo de mensaje no es BGP OPEN, o no se utiliza autenticación, estos 16 bytes suelen establecerse como todos unos)
len longitud total del mensaje BGP, incluida la cabecera
type código de tipo del mensaje (OPEN, UPDATE, NOTIFICATION o KEEPALIVE)
payload carga útil opcional o NULL
payload_s longitud de la carga útil o 0
l puntero a un contexto libnet
ptag etiqueta de protocolo para modificar una cabecera existente, 0 para construir una nueva

LIBNET_API libnet_t * libnet_init (int injection_type, const char * device, char * err_buf)

Crea el entorno libnet. Inicializa la biblioteca y devuelve un contexto libnet. Si injection_type es LIBNET_LINK o LIBNET_LINK_ADV, la función inicializa los primitivos de inyección para la interfaz de capa de enlace, lo que permite al programador de aplicaciones construir paquetes comenzando en la capa de enlace de datos (lo que también proporciona un control más granular sobre la capa IP). Si libnet utiliza la capa de enlace y el argumento device no es NULL, la función intenta usar el dispositivo de red especificado para la inyección de paquetes. Este es un nombre canónico que hace referencia al dispositivo (como 'eth0' para una tarjeta Ethernet de 100 MB en Linux o 'fxp0' para una tarjeta Ethernet de 100 MB en OpenBSD) o la representación en puntos y decimales de la dirección IP del dispositivo (192.168.0.1). Si device es NULL, libnet intenta encontrar un dispositivo adecuado para usar. Si injection_type es LIBNET_RAW4 o LIBNET_RAW4_ADV, la función inicializa los primitivos de inyección para la interfaz de socket raw IPv4. El argumento final, err_buf, debe ser un buffer de tamaño LIBNET_ERRBUF_SIZE y contendrá un mensaje de error si la función falla. Esta función requiere privilegios de root para ejecutarse correctamente. Tras el éxito, la función devuelve un contexto libnet válido para su uso en llamadas posteriores a funciones; en caso de fallo, la función devuelve NULL.

Parámetros

injection_type tipo de inyección de paquetes (LIBNET_LINK, LIBNET_LINK_ADV, LIBNET_RAW4, LIBNET_RAW4_ADV, LIBNET_RAW6, LIBNET_RAW6_ADV)
device la interfaz a usar (NULL y libnet elegirá una)
err_buf contendrá un mensaje de error en caso de fallo

Devuelve

contexto libnet listo para usar o NULL en caso de error.

NAME

libnet-functions - packet creation library functions

SYNOPSIS

libnet_toggle_checksum(libnet_t *l, int ptag, int mode)

libnet_version()

libnet_write(libnet_t *l)

Detailed Description

When the checksum field is set to
'0', by default libnet will calculate the header checksum prior to
injection. If the header is set to any other value, by default libnet will
not calculate the header checksum. To over-ride this behavior, use
libnet_toggle_checksum(). Switches auto-checksumming on or off for
the specified ptag. If mode is set to LIBNET_ON, libnet will mark the
specified ptag to calculate a checksum for the ptag prior to injection. This
assumes that the ptag refers to a protocol that has a checksum field. If
mode is set to LIBNET_OFF, libnet will clear the checksum flag and no
checksum will be computed prior to injection. This assumes that the
programmer will assign a value (zero or otherwise) to the checksum field.
Often times this is useful if a precomputed checksum or some other
predefined value is going to be used. Note that when libnet is initialized
with LIBNET_RAW4, the IPv4 header checksum will always be computed by the
kernel prior to injection, regardless of what the programmer sets.

Parameters

l pointer to a libnet context
ptag the ptag reference number
mode LIBNET_ON or LIBNET_OFF

Return values

1 on success
-1 on failure
