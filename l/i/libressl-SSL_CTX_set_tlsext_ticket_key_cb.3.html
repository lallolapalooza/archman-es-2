SSL_CTX_SET_TLSEXT_TICKET_KEY_CB(3) Manual de Funciones de Biblioteca SSL_CTX_SET_TLSEXT_TICKET_KEY_CB(3)

NOMBRE

SSL_CTX_set_tlsext_ticket_key_cb — establecer una función de devolución de llamada para el procesamiento de tickets de sesión

SINÓPSIS

biblioteca “libssl” libcrypto
#include <openssl/tls1.h>

long
SSL_CTX_set_tlsext_ticket_key_cb(SSL_CTX sslctx, int (*cb)(SSL *s, unsigned char key_name[16], unsigned char iv[EVP_MAX_IV_LENGTH], EVP_CIPHER_CTX *ctx, HMAC_CTX *hctx, int enc));

DESCRIPCIÓN

SSL_CTX_set_tlsext_ticket_key_cb() establece una función de devolución de llamada cb para manejar tickets de sesión para el contexto ssl sslctx. Los tickets de sesión, definidos en RFC 5077, proporcionan una capacidad de reanudación de sesión mejorada donde la implementación del servidor no requiere mantener el estado por sesión.

La función de devolución de llamada cb será llamada para cada sesión TLS iniciada por el cliente cuando se presente la extensión de ticket de sesión en el mensaje hello TLS. Es responsabilidad de esta función crear o recuperar los parámetros criptográficos y mantener su estado.

La biblioteca OpenSSL utiliza la función de devolución de llamada para ayudar a implementar un estado de construcción de ticket TLS común según RFC 5077 Sección 4, de modo que el estado por sesión sea innecesario y la función de devolución de llamada implementada necesite mantener un pequeño conjunto de variables criptográficas.

Para reutilizar una sesión, un cliente TLS debe enviar una extensión de ticket de sesión al servidor. El cliente solo puede enviar exactamente un ticket de sesión. El servidor, a través de la función de devolución de llamada, acepta reutilizar la información del ticket de sesión o inicia un apretón de manos TLS completo para crear un nuevo ticket de sesión.

La devolución de llamada se llama con ctx y hctx que se asignaron recientemente con EVP_CIPHER_CTX_new(3) y HMAC_CTX_new(3), respectivamente.

Para nuevos tickets de sesión, cuando el cliente no presenta un ticket de sesión, o un intento de recuperación del ticket falló, o se indicó una opción de renovación, la función de devolución de llamada se llamará con enc igual a 1. La biblioteca OpenSSL espera que la función establezca un key_name arbitrario, inicialice iv y configure el contexto de cifrado ctx y el contexto hmac hctx.

El key_name tiene 16 caracteres de longitud y se utiliza como identificador de clave.

La longitud de iv es la longitud del IV del cifrado correspondiente. La longitud máxima del IV es EVP_MAX_IV_LENGTH bytes definidos en <openssl/evp.h>.

El vector de inicialización iv debe ser un valor aleatorio. El contexto de cifrado ctx debe usar el vector de inicialización iv. El contexto de cifrado se puede configurar usando EVP_EncryptInit_ex(3). El contexto hmac se puede configurar usando HMAC_Init_ex(3).

Cuando el cliente presenta un ticket de sesión, la función de devolución de llamada se llamará con enc establecido en 0, lo que indica que la función cb debe recuperar un conjunto de parámetros. En este caso, key_name y iv ya han sido extraídos del ticket de sesión. La biblioteca OpenSSL espera que el key_name se utilice para recuperar parámetros criptográficos y que el contexto criptográfico ctx se configure con los parámetros recuperados y el vector de inicialización iv utilizando una función como EVP_DecryptInit_ex(3). El hctx debe configurarse usando HMAC_Init_ex(3).

Si el key_name sigue siendo válido pero se requiere una renovación del ticket, la función de devolución de llamada debería devolver 2. La biblioteca llamará a la devolución de llamada de nuevo con un argumento de enc igual a 1 para establecer el nuevo ticket.

El valor de retorno de la función cb es utilizado por OpenSSL para determinar qué procesamiento adicional ocurrirá. Los siguientes valores de retorno tienen significado:

2
Esto indica que ctx y hctx se han establecido y la sesión puede continuar con esos parámetros. Además, indica que el ticket de sesión está en un período de renovación y debe ser reemplazado. La biblioteca OpenSSL llamará a cb nuevamente con un argumento de enc igual a 1 para establecer el nuevo ticket (ver RFC 5077 3.3 párrafo 2).
1
Esto indica que ctx y hctx se han establecido y la sesión puede continuar con esos parámetros.
0
Esto indica que no fue posible establecer/recuperar un ticket de sesión y la sesión SSL/TLS continuará negociando un conjunto de parámetros criptográficos o utilizando el mecanismo alternativo de reanudación de SSL/TLS, los identificadores de sesión.

Si se llama con enc igual a 0, la biblioteca llamará a cb de nuevo para obtener un nuevo conjunto de parámetros.

menor que 0
Esto indica un error.

La reanudación de sesión omite el TLS para que la negociación de certificados del cliente no ocurra. Compensa esto almacenando el certificado del cliente y toda la otra información de estado negociada cifrada dentro del ticket. En una sesión reanudada, las aplicaciones tendrán toda esta información de estado disponible exactamente como si hubiera ocurrido una negociación completa.

Si un atacante puede obtener la clave utilizada para cifrar un ticket de sesión, puede obtener el secreto maestro de cualquier ticket que use esa clave y descifrar cualquier tráfico que use esa sesión: incluso si el cifrado admite la secreto directo. Como resultado, las aplicaciones pueden desear usar múltiples claves y evitar usar claves a largo plazo almacenadas en archivos.

Las aplicaciones pueden usar claves más largas para mantener un nivel de seguridad consistente. Por ejemplo, si un cifrado utiliza cifrados de 256 bits pero solo una clave de ticket de 128 bits, la seguridad general es solo de 128 bits porque romper la clave del ticket permitirá a un atacante obtener las claves de sesión.

VALORES DE RETORNO

Esta función devuelve 0 para indicar que la función de devolución de llamada se estableció correctamente.

EJEMPLOS

Implementación de referencia:

SSL_CTX_set_tlsext_ticket_key_cb(SSL, ssl_tlsext_ticket_key_cb);
....
static int ssl_tlsext_ticket_key_cb(SSL *s, unsigned char key_name[16],
    unsigned char *iv, EVP_CIPHER_CTX *ctx, HMAC_CTX *hctx, int enc)
{
	if (enc) { /* crear nueva sesión */
		if (RAND_bytes(iv, EVP_MAX_IV_LENGTH))
			return -1; /* aleatoriedad insuficiente */

		key = currentkey(); /* algo que necesitas implementar */
		if (!key) {
			/* la clave actual no existe o no es válida */
			key = createkey();
			    /* algo que necesitas implementar.
			     * createkey necesita inicializar un nombre,
			     * una clave aes, una clave hmac, y opcionalmente
			     * un tiempo de expiración. */
			if (!key) /* no se pudo crear la clave */
				return 0;
		}
		memcpy(key_name, key->name, 16);

		EVP_EncryptInit_ex(&ctx, EVP_aes_128_cbc(), NULL,
		    key->aes_key, iv);
		HMAC_Init_ex(&hctx, key->hmac_key, 16, EVP_sha256(), NULL);

		return 1;

	} else { /* recuperar sesión */
		key = findkey(name);

		if  (!key || key->expire < now())
			return 0;

		HMAC_Init_ex(&hctx, key->hmac_key, 16, EVP_sha256(), NULL);
		EVP_DecryptInit_ex(&ctx, EVP_aes_128_cbc(), NULL,
		    key->aes_key, iv );

		if (key->expire < (now() - RENEW_TIME))
		    /* esta sesión obtendrá un nuevo ticket
		     * aunque el actual todavía sea válido */
		    return 2;

		return 1;
	}
}

NAME

SSL_CTX_set_tlsext_ticket_key_cb, SSL_CTX_set_tlsext_ticket_keys, SSL_CTX_get_tlsext_ticket_keys - session ticket callback and keys

SYNOPSIS

#include <openssl/ssl.h>
typedef int (*ssl_tlsext_ticket_key_cb_func)(SSL *s, unsigned char *key,
    unsigned char *iv, EVP_CIPHER_CTX *ectx, EVP_MD_CTX *mdctx, int enc);
int SSL_CTX_set_tlsext_ticket_key_cb(SSL_CTX *ctx,
    ssl_tlsext_ticket_key_cb_func cb);
int SSL_CTX_set_tlsext_ticket_keys(SSL_CTX *ctx,
    const unsigned char *clients, size_t clientslen, const unsigned char *secrets,
    size_t secretslen);
int SSL_CTX_get_tlsext_ticket_keys(SSL_CTX *ctx,
    unsigned char *clients, size_t *clientslen, unsigned char *secrets,
    size_t *secretslen);

DESCRIPTION

The server can optionally support TLS session tickets. When session tickets are supported, the server creates an encrypted ticket for the client after a successful TLS handshake. This ticket can be used by the client to resume the session later, avoiding the need for a full handshake and saving computation on the server. The ticket is encrypted and authenticated using symmetric keys managed by the server.

Session tickets are enabled by default if SSL_CTX_set_tlsext_ticket_key_cb() is called to set a callback. Otherwise, they are disabled.

The callback function cb is invoked by OpenSSL when a session ticket needs to be generated or decrypted. The parameter enc indicates the operation to be performed. If enc is 1, the ticket needs to be encrypted and authenticated. If enc is 0, the ticket needs to be decrypted and verified.

The callback function should use the provided parameters to perform the encryption/decryption and authentication. The specific cipher and hash algorithms used depend on the configuration of the SSL_CTX and the TLS version in use. The callback should return 1 on success and 0 on failure.

SSL_CTX_set_tlsext_ticket_key_cb() sets the callback function cb for the SSL_CTX object ctx. This function enables session ticket support and allows custom key management.

SSL_CTX_set_tlsext_ticket_keys() allows setting the session ticket encryption and authentication keys directly. The clients parameter is a buffer containing the client keys, and clientslen is its length. The secrets parameter is a buffer containing the secret keys, and secretslen is its length. These keys are used to encrypt and authenticate the session tickets. This function disables any previously set callback.

SSL_CTX_get_tlsext_ticket_keys() retrieves the currently configured session ticket keys. The buffers clients and secrets are filled with the key data, and their respective lengths are updated in clientslen and secretslen. This function can only retrieve keys set directly using SSL_CTX_set_tlsext_ticket_keys(); it cannot retrieve keys managed by a callback.

RETURN VALUES

SSL_CTX_set_tlsext_ticket_key_cb() and SSL_CTX_set_tlsext_ticket_keys() return 1 on success and 0 on failure.

SSL_CTX_get_tlsext_ticket_keys() returns 1 on success and 0 on failure. If no keys were set directly (i.e., a callback is in use), it also returns 0.

EXAMPLES

/*
 * Example callback function for setting session ticket keys.
 * This is a simplified example and should not be used in production
 * without proper security considerations.
 */
static int ticket_key_callback(SSL *s, unsigned char *key, unsigned char *iv,
    EVP_CIPHER_CTX *ectx, EVP_MD_CTX *mdctx, int enc)
{
    /*
     * In a real implementation, you would use your own key management
     * mechanism to provide the encryption and authentication keys.
     * This example uses hardcoded keys for demonstration purposes.
     */
    static unsigned char master_key[32] = {
        0x01, 0x02, 0x03, 0x04, 0x05, 0x06, 0x07, 0x08,
        0x09, 0x0a, 0x0b, 0x0c, 0x0d, 0x0e, 0x0f, 0x10,
        0x11, 0x12, 0x13, 0x14, 0x15, 0x16, 0x17, 0x18,
        0x19, 0x1a, 0x1b, 0x1c, 0x1d, 0x1e, 0x1f, 0x20
    };
    static unsigned char hmac_key[32] = {
        0x20, 0x1f, 0x1e, 0x1d, 0x1c, 0x1b, 0x1a, 0x19,
        0x18, 0x17, 0x16, 0x15, 0x14, 0x13, 0x12, 0x11,
        0x10, 0x0f, 0x0e, 0x0d, 0x0c, 0x0b, 0x0a, 0x09,
        0x08, 0x07, 0x06, 0x05, 0x04, 0x03, 0x02, 0x01
    };

    if (enc) {
        /* Encrypting: provide the master key and HMAC key */
        memcpy(key, master_key, sizeof(master_key));
        /*
         * For AES-GCM, the IV is typically derived from the handshake context.
         * For simplicity, we are not setting it here. In a real scenario,
         * this would need proper handling.
         */
        /*
         * The EVP_CIPHER_CTX and EVP_MD_CTX are already initialized by OpenSSL
         * for the appropriate cipher and hash.
         */
        return 1;
    } else {
        /* Decrypting: provide the HMAC key */
        memcpy(key, hmac_key, sizeof(hmac_key));
        /*
         * The EVP_CIPHER_CTX and EVP_MD_CTX are already initialized by OpenSSL
         * for the appropriate cipher and hash.
         */
        return 1;
    }
}
