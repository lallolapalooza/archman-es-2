DESCRIPCIÓN

X509_LOOKUP_free() es una función obsoleta que libera la memoria utilizada por lookup. Se proporciona solo por compatibilidad. Si lookup es un puntero NULL, no se realiza ninguna acción.

El funcionamiento de X509_LOOKUP_ctrl() depende del X509_LOOKUP_METHOD utilizado por lookup:

X509_LOOKUP_hash_dir(3)
El command debe ser X509_L_ADD_DIR y el argumento source se interpreta como una lista de nombres de directorio separados por dos puntos y terminados en NULO. Estos directorios se añaden a una lista interna de directorios para buscar archivos de certificado del type dado.

Si type es X509_FILETYPE_DEFAULT, el argumento source se ignora y en su lugar se utilizan /etc/ssl/certs y un tipo X509_FILETYPE_PEM.

X509_LOOKUP_add_dir() es una macro que llama a X509_LOOKUP_ctrl() con un command de X509_L_ADD_DIR y ret establecido a NULL.

Este método de búsqueda es peculiar en el sentido de que llamar a X509_LOOKUP_ctrl() sobre un objeto lookup que lo utiliza aún no añade certificados al objeto X509_STORE asociado.

X509_LOOKUP_file(3)
El command debe ser X509_L_FILE_LOAD y el argumento source se interpreta como un nombre de archivo terminado en NULO. Si el type es X509_FILETYPE_PEM, el archivo se lee con BIO_new_file(3) y PEM_X509_INFO_read_bio(3) y los certificados y listas de revocación encontrados se añaden al objeto X509_STORE asociado con lookup utilizando X509_STORE_add_cert(3) y X509_STORE_add_crl(3). Si type es X509_FILETYPE_DEFAULT, el argumento source se ignora y en su lugar se utilizan /etc/ssl/certs.pem y un tipo X509_FILETYPE_PEM. Si type es X509_FILETYPE_ASN1, el archivo se lee con d2i_X509_bio(3) y el único certificado se añade al objeto X509_STORE asociado con lookup utilizando X509_STORE_add_cert(3).

X509_LOOKUP_load_file() es una macro que llama a X509_LOOKUP_ctrl() con un command de X509_L_FILE_LOAD y ret establecido a NULL.

X509_LOOKUP_mem(3)
El command y el type deben ser X509_L_MEM y X509_FILETYPE_PEM, respectivamente. El argumento source se interpreta como un puntero a una estructura iovec definida en <sys/uio.h>. El área de memoria descrita por esa estructura se lee con BIO_new_mem_buf(3) y PEM_X509_INFO_read_bio(3) y los certificados y listas de revocación encontrados se añaden al objeto X509_STORE asociado con lookup utilizando X509_STORE_add_cert(3) y X509_STORE_add_crl(3).

X509_LOOKUP_add_mem() es una macro que llama a X509_LOOKUP_ctrl() con un comando de X509_L_MEM y ret establecido a NULL.

Con LibreSSL, X509_LOOKUP_ctrl() siempre ignora el argumento ret.

Si el type es X509_LU_X509, busca en los directorios configurados archivos con ese nombre, con una extensión de nombre de archivo que es un entero decimal pequeño y no negativo que comienza en ".0". Estos archivos se leen con X509_load_cert_file(3). En cada directorio, la búsqueda termina una vez que un archivo con el nombre y extensión esperados no existe.

Si el type es X509_LU_CRL, se espera que las extensiones de nombre de archivo tengan un prefijo de "r", es decir, comienzan con ".r0", y los archivos se leen con X509_load_crl_file(3).

En caso de éxito, la primera coincidencia se devuelve en el *object proporcionado por el llamador, sobrescribiendo cualquier contenido previo.

VALOR DE RETORNO

X509_LOOKUP_ctrl(), X509_LOOKUP_add_dir(), X509_LOOKUP_load_file(), y X509_LOOKUP_add_mem() devuelven 1 en caso de éxito, o 0 en caso de error.

X509_get_default_cert_dir(), X509_get_default_cert_file(), X509_get_default_cert_dir_env(), y X509_get_default_cert_file_env() devuelven un puntero a una cadena de caracteres que contiene el nombre de directorio o archivo predeterminado.

EJEMPLO

Cargar un certificado del archivo cert.pem:

#include <openssl/x509_vfy.h>
#include <openssl/x509.h>
#include <stdio.h>
int
main(int argc, char **argv)
{
    X509_STORE *store = NULL;
    X509_LOOKUP *lookup = NULL;
    store = X509_STORE_new();
    if (store == NULL)
        /* handle error */
    lookup = X509_STORE_add_lookup(store, X509_LOOKUP_file());
    if (lookup == NULL)
        /* handle error */
    if (!X509_LOOKUP_load_file(lookup, "cert.pem", X509_FILETYPE_PEM))
        /* handle error */
    /* ... use store ... */
    X509_STORE_free(store);
    return 0;
}

VALORES DE RETORNO

X509_LOOKUP_ctrl() devuelve 1 para éxito o 0 para fallo. Con implementaciones de bibliotecas distintas a LibreSSL, también podría devolver -1 para errores internos.

X509_get_default_cert_dir() devuelve un puntero a la cadena constante "/etc/ssl/certs", X509_get_default_cert_file() a "/etc/ssl/certs.pem", X509_get_default_cert_dir_env() a "SSL_CERT_DIR", y X509_get_default_cert_file_env() a "SSL_CERT_FILE".

ENTORNO

Por razones de seguridad y simplicidad, LibreSSL ignora las variables de entorno SSL_CERT_DIR y SSL_CERT_FILE, pero otras implementaciones de bibliotecas pueden usar sus contenidos en lugar de las ubicaciones estándar para certificados de confianza, y algunos programas de aplicación de terceros también inspeccionan estas variables directamente y pueden pasar sus valores a X509_LOOKUP_add_dir() y X509_LOOKUP_load_file().

FICHEROS

/etc/ssl/certs/
directorio por defecto para almacenar certificados de confianza
/etc/ssl/certs.pem
fichero por defecto para almacenar certificados de confianza

ERRORES

Los siguientes diagnósticos se pueden recuperar con ERR_get_error(3), ERR_GET_REASON(3), y ERR_reason_error_string(3):

ERR_R_ASN1_LIB "ASN1 lib"
d2i_X509_bio(3) falló en X509_LOOKUP_ctrl().
X509_R_BAD_X509_FILETYPE "bad x509 filetype"
X509_LOOKUP_ctrl() fue llamada con un type inválido.
ERR_R_BUF_LIB "BUF lib"
Falló la asignación de memoria.
X509_R_INVALID_DIRECTORY "invalid directory"
El argumento source de X509_LOOKUP_ctrl() con X509_L_ADD_DIR o X509_LOOKUP_add_dir() era NULL o una cadena vacía.
X509_R_LOADING_CERT_DIR "loading cert dir"
X509_LOOKUP_ctrl() con X509_L_ADD_DIR o X509_LOOKUP_add_dir() fue llamada con X509_FILETYPE_DEFAULT y falló la adición de los directorios por defecto. Este error se añade después y además de un diagnóstico más específico.
X509_R_LOADING_DEFAULTS "loading defaults"
X509_LOOKUP_ctrl() con X509_L_FILE_LOAD o X509_LOOKUP_load_file() fue llamada con X509_FILETYPE_DEFAULT y falló la adición de los certificados y listas de revocación. Este error se añade después y además de un diagnóstico más específico.
ERR_R_MALLOC_FAILURE "malloc failure"
Falló la asignación de memoria.
ERR_R_PEM_LIB "PEM lib"
PEM_X509_INFO_read_bio(3), PEM_read_bio_X509_AUX(3), o PEM_read_bio_X509_CRL(3) fallaron en X509_LOOKUP_ctrl().
ERR_R_SYS_LIB "system lib"
BIO_new(3), BIO_new_file(3), o BIO_read_filename(3) fallaron en X509_LOOKUP_ctrl().
X509_R_WRONG_LOOKUP_TYPE "wrong lookup type"
X509_STORE_CTX_get_by_subject(3) fue llamada con un type inválido.

Pasar un command inválido a X509_LOOKUP_ctrl() causa un fallo pero no proporciona diagnósticos.

HISTORIA

X509_get_default_cert_dir(), X509_get_default_cert_file(), X509_get_default_cert_dir_env(), y X509_get_default_cert_file_env() aparecieron por primera vez en SSLeay 0.4.1 y han estado disponibles desde OpenBSD 2.4.

X509_LOOKUP_add_mem() apareció por primera vez en OpenBSD 5.7.

Las otras funciones aparecieron por primera vez en SSLeay 0.8.0 y han estado disponibles desde OpenBSD 2.4.

ERRORES

Si el type es X509_FILETYPE_DEFAULT o X509_FILETYPE_PEM, X509_LOOKUP_ctrl() con X509_L_FILE_LOAD y X509_LOOKUP_load_file() ignoran silenciosamente el fallo de X509_STORE_add_cert(3) y X509_STORE_add_crl(3) e indican éxito de todos modos.

El manejo de un source NULL es inconsistente para X509_LOOKUP_ctrl() con X509_L_FILE_LOAD y para X509_LOOKUP_load_file(). Con X509_FILETYPE_PEM, causa un fallo, pero con X509_FILETYPE_ASN1, no ocurre ninguna acción y se indica éxito.

Cuando se llama en un objeto lookup usando X509_LOOKUP_mem(3), X509_LOOKUP_ctrl() lanza ERR_R_PEM_LIB cuando se llama con un command o type inválido, cuando falla BIO_new_mem_buf(3), cuando source contiene cero objetos, o cuando X509_STORE_add_cert(3) falla en el primer objeto encontrado, lo cual es inconsistente con el comportamiento de los otros métodos de búsqueda.
