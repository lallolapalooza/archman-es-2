libressl-SSL_load_client_CA_file(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

SSL_LOAD_CLIENT_CA_FILE(3) Manual de funciones de la biblioteca SSL_LOAD_CLIENT_CA_FILE(3)

NOMBRE

SSL_load_client_CA_file, SSL_add_file_cert_subjects_to_stack, SSL_add_dir_cert_subjects_to_stack — carga nombres de certificados desde archivos

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

STACK_OF(X509_NAME) *
SSL_load_client_CA_file(const char *file);

int
SSL_add_file_cert_subjects_to_stack(STACK_OF(X509_NAME) *stack, const char *file);

int
SSL_add_dir_cert_subjects_to_stack(STACK_OF(X509_NAME) *stack, const char *dir);

DESCRIPCIÓN

SSL_load_client_CA_file() lee certificados en formato PEM del archivo file y devuelve una nueva STACK_OF(X509_NAME) con los nombres de sujeto encontrados. Aunque el nombre sugiere su uso específico como función de soporte para SSL_CTX_set_client_CA_list(3), no se limita a certificados CA.

SSL_add_file_cert_subjects_to_stack() es similar excepto que los nombres se añaden a la pila existente stack.

SSL_add_dir_cert_subjects_to_stack() llama a SSL_add_file_cert_subjects_to_stack() en cada archivo del directorio dir.

Si un nombre ya está en la pila, todas estas funciones lo omiten y no lo añaden de nuevo.

VALORES DE RETORNO

SSL_load_client_CA_file() devuelve un puntero a la nueva STACK_OF(X509_NAME) o NULL en caso de fallo.

SSL_add_file_cert_subjects_to_stack() y SSL_add_dir_cert_subjects_to_stack() devuelven 1 para éxito o 0 para fallo.

Todas estas funciones tratan los archivos y directorios vacíos como fallos.

En algunos casos de fallo, la razón puede determinarse con ERR_get_error(3).

EJEMPLOS

Cargar nombres de CAs desde un archivo y usarlo como lista de CAs de cliente:

SSL_CTX *ctx;
STACK_OF(X509_NAME) *cert_names;
...
cert_names = SSL_load_client_CA_file("/ruta/a/CAfile.pem");
if (cert_names != NULL)
	SSL_CTX_set_client_CA_list(ctx, cert_names);
else
	manejo_de_errores();
...

VER TAMBIÉN

PEM_read_bio_X509(3), ssl(3), SSL_CTX_set_client_CA_list(3), X509_get_subject_name(3), X509_NAME_new(3)

HISTORIA

SSL_load_client_CA_file() apareció por primera vez en SSLeay 0.8.0 y ha estado disponible desde OpenBSD 2.4.

SSL_add_file_cert_subjects_to_stack() y SSL_add_dir_cert_subjects_to_stack() aparecieron por primera vez en OpenSSL 0.9.2b y han estado disponibles desde OpenBSD 2.6.

AUTORES

SSL_add_file_cert_subjects_to_stack() y SSL_add_dir_cert_subjects_to_stack() fueron escritas por Ben Laurie <ben@openssl.org> en 1999.

ERRORES

En algunos casos de fallo, por ejemplo para archivos y directorios vacíos, estas funciones no informan de un error, en el sentido de que ERR_get_error(3) no funciona.

Incluso en caso de fallo, por ejemplo cuando falla el análisis de uno de los archivos o certificados, SSL_add_file_cert_subjects_to_stack() y SSL_add_dir_cert_subjects_to_stack() pueden haber añadido algunos certificados a la pila.

El comportamiento de SSL_add_dir_cert_subjects_to_stack() es no determinista. Si el análisis de un archivo falla, el análisis de todo el directorio se interrumpe. Los archivos del directorio no se analizan en ningún orden específico. Por ejemplo, añadir un archivo vacío a dir puede o no puede hacer que se ignoren algunos de los otros archivos.
