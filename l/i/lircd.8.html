LIRCD(8) Utilidades de Administración del Sistema LIRCD(8)

NOMBRE

lircd - Decodifica señales infrarrojas y las proporciona en un socket.

SINOPSIS

lircd [opciones] [archivo de configuración]

DESCRIPCIÓN

La tarea principal de lircd es decodificar las señales infrarrojas y proporcionar una interfaz uniforme para las aplicaciones cliente. Los clientes pueden conectarse a lircd a través de un socket de dominio Unix, por defecto /var/run/lirc/lircd. Usando este socket obtendrán los códigos infrarrojos recibidos por lircd y podrán enviar comandos a lircd.

ARGUMENTOS

archivo de configuración
El archivo de configuración, por defecto /etc/lirc/lircd.conf. Una ruta relativa se interpreta desde /etc/lirc. El archivo de configuración por defecto incluye todos los archivos en /etc/lircd.conf.d.
Cada control remoto que deba ser decodificado por lircd normalmente requiere que se use un archivo específico, por ejemplo, copiándolo a /etc/lirc/lirc.conf.d/. El formato se describe en lircd.conf(5). Los archivos de configuración se pueden encontrar usando irdb-get(1) o lirc-setup(1). También es posible generar un archivo de configuración usando irrecord(1).

OPCIONES

Opciones comunes:

-d, --device <dispositivo>
Selecciona el dispositivo de caracteres del cual lircd debe leer. Por defecto, actualmente es /dev/lirc0 en la mayoría de los sistemas.
Algunos drivers, incluyendo el driver por defecto devinput, soportan el dispositivo auto que selecciona el primer dispositivo utilizable encontrado para el driver actual.
Al usar el driver devinput, se puede usar name=STRING o phys=STRING para seleccionar el dispositivo; lircd buscará en /dev/input un dispositivo con una descripción que coincida. Esto es útil en caso de que el nombre del dispositivo no sea fijo. STRING puede contener los comodines '*' y '?' y '\' para marcarlos como literales. Usa mode2 --driver devinput --list-devices para listar los dispositivos actuales.
-H, --driver <driver>
El driver a usar. Usar --driver help lista todos los drivers disponibles, ver CARGA DE DRIVERS más abajo.
-h, --help
Muestra un mensaje de ayuda corto.

Otras opciones:

-a, --allow-simulate
Habilita el comando SIMULATE que se puede emitir usando irsend(1) o la API del cliente. Esto permitirá simular eventos IR arbitrarios desde la línea de comandos. Usa esta opción con precaución porque dará a todos los usuarios con acceso al socket de lircd un control amplio sobre el sistema. Por ejemplo, si has configurado tu sistema para que se apague con una pulsación de botón en tu control remoto, cualquiera podrá apagar tu sistema desde la línea de comandos.
-c, --connect [host[:puerto]][,[host[:puerto]]]
Se conecta a otros servidores lircd que proporcionan un socket de red en el host y puerto dados (ver --listen). El número de tales conexiones está actualmente limitado a 100. La instancia lircd que se conecta recibirá eventos IR de la instancia lircd a la que se conecta. Para conectarse a múltiples servidores, agrégalos como una lista separada por comas.
-e, --effective-user <uid>
Si se inicia como usuario root, lircd suelta sus privilegios y se ejecuta como el usuario <uid> después de abrir archivos, etc.
-i, --immediate-init
Lircd normalmente inicializa el driver cuando el primer cliente se conecta. Si se selecciona esta opción, el driver se inicializa inmediatamente al inicio.
-A, --driver-options clave:valor[|clave:valor...]
Establece una o más opciones para el driver. El argumento es una lista de pares clave:valor delimitados por '|'. La clave no puede contener espacios, pero estos están permitidos en la parte del valor. Ciertos caracteres, incluyendo '#' y ';', se usan como marcadores de comentario en el archivo de configuración y no están permitidos en ninguna parte.
-Y, --dynamic-codes [EXPERIMENTAL]
Permite el uso de códigos que han sido decodificados para un control remoto pero no están definidos en lircd.conf. Los nuevos códigos se crean dinámicamente con un nombre por defecto. Esta característica es experimental y está sujeta a todo tipo de cambios. No ha sido probada exhaustivamente.
-l, --listen [[dirección:]puerto]]
Permite a lircd escuchar conexiones de red en la dirección/puerto dados. La dirección por defecto es 0.0.0.0, lo que significa que se aceptarán conexiones en todas las interfaces de red. La dirección debe proporcionarse en formato numérico de puntos. El puerto por defecto es 8765. La instancia lircd que escucha enviará todos los eventos IR a las instancias lircd que se conecten sin ninguna verificación de seguridad.
En plataformas que no son glibc, el argumento dirección:puerto es obligatorio, pero se puede proporcionar como una cadena vacía, por ejemplo --listen= que luego por defecto será 0.0.0.0:8765.
-L, --logfile <ruta-archivo-registro>
Selecciona el archivo de registro del demonio lircd. archivo_registro es la cadena 'syslog' indicando que se debe usar syslog(1) o una ruta a un archivo de registro. Por defecto se usa syslog.
-D, --loglevel [nivel]
Determina la cantidad de información de registro. nivel puede ser un nivel simbólico de syslog: 'error', 'warning', 'info', 'notice' o 'debug'. lircd también define tres niveles adicionales 'trace', 'trace1' y 'trace2' que proporcionan aún más mensajes ('trace2' aporta la mayor cantidad). Sin embargo, en el registro, estos mensajes se marcan como 'debug'.
En plataformas que no son glibc, el argumento nivel es obligatorio, pero se puede proporcionar como una cadena vacía, por ejemplo --loglevel= que luego por defecto será debug.
El nivel también puede ser un entero en el rango de 3 (casi ningún mensaje) a 10.
-O, --options-file <ruta>
Archivo que contiene los valores por defecto para todas las opciones. Una ruta relativa se interpreta desde el directorio actual. Ver [ARCHIVOS] abajo.
-o, --output <socket-salida>
Selecciona el socket de dominio Unix, al cual lircd escribirá los códigos de tecla remotos. Por defecto, actualmente es /var/run/lirc/lircd.
-p, --permission <perm>
Otorga al socket de salida los permisos de archivo si tiene que ser creado, en representación octal. Ver chmod(1). Si no se proporciona la opción --permission cuando el socket se crea inicialmente, el valor por defecto es dar a todos los usuarios permisos de lectura y escritura (0666 en representación octal). Si el socket ya existe, esta opción no tiene efecto.
-p, --pidfile <ruta>
Selecciona el archivo PID del demonio lircd, por defecto es /var/run/lirc/lircd.pid.
-U --plugindir <ruta>
Establece el directorio desde el cual lircd carga sus drivers de espacio de usuario. Estos son archivos *.so, que por defecto se encuentran como se describe en CARGA DE DRIVERS. El argumento es una ruta de búsqueda separada por ':'.
-R, --repeat-max <límite>
Establece un límite superior al número de repeticiones al enviar una señal. El límite actual por defecto es 600. Una solicitud SEND_START repetirá la señal este número de veces. Además, si el número de repeticiones en una solicitud SEND_ONCE excede este número, será reemplazado por este número.

FORMATO DE MENSAJES DE BROADCAST DEL SOCKET

Al decodificar una pulsación de botón o recibir una señal SIGHUP, lircd.conf lircd transmite mensajes a todos los clientes conectados.

Por cada pulsación de botón decodificada, se pone un paquete a disposición en el socket. Estos son datos imprimibles formateados como:

        <código> <contador de repetición> <nombre del botón> <nombre del control remoto>

por ejemplo,

        000000
0000f40bf0 00 KEY_UP ANIMAX

Los campos son:

código
Un número de 16 dígitos hexadecimales que codifica la señal IR. Su uso en aplicaciones está obsoleto y debe ser ignorado.
contador de repetición
Muestra cuánto tiempo el usuario ha mantenido presionado un botón. El contador comenzará en 0 e se incrementará cada vez que se reciba una nueva señal IR.
nombre del botón
Es el nombre de una tecla definida en el archivo lircd.conf.
nombre del control remoto
Es el atributo obligatorio de nombre en el archivo de configuración lircd.conf.

Estos paquetes se difunden a todos los clientes. La única otra situación en la que lircd difunde a todos los clientes es cuando recibe la señal SIGHUP y vuelve a leer su archivo de configuración con éxito. Entonces enviará un paquete SIGHUP a sus clientes indicando que su configuración podría haber cambiado. El paquete sighup consta de tres líneas

        BEGIN
        SIGHUP
        END

INTERFAZ DE COMANDOS DEL SOCKET

Las aplicaciones también pueden enviar comandos a lircd a través de la interfaz del socket. La tarea más común es enviar datos, pero también hay otros comandos. Cada comando es una sola línea imprimible, terminada con un salto de línea. Para cada comando, lircd responde con un paquete de respuesta.

Comandos admitidos:

SEND_ONCE <control remoto> <nombre del botón> [repeticiones]
Indica a lircd que envíe la señal IR asociada con el control remoto y el nombre del botón dados, y luego la repita repeticiones veces. repeticiones es un número decimal entre 0 y repeat_max. Este último puede especificarse como un argumento de línea de comandos --repeat-max para lircd, y por defecto es 600. Si repeticiones no se especifica o es menor que el número mínimo de repeticiones para el control remoto seleccionado, se utilizará el valor mínimo.
SEND_START <nombre del control remoto> <nombre del botón>
Indica a lircd que comience a repetir el botón dado hasta que reciba un comando SEND_STOP. Sin embargo, el número de repeticiones está limitado a repeat_max. lircd no aceptará ningún comando de envío nuevo mientras esté repitiendo.
SEND_STOP <nombre del control remoto> <nombre del botón>
Indica a lircd que anule un comando SEND_START.
LIST [control remoto]
Sin argumentos, lircd responde con una lista de todos los controles remotos definidos. Dado un argumento de control remoto, lircd responde con una lista de todas las teclas definidas en el control remoto dado.
SET_INPUTLOG [ruta]
Dada una ruta, lircd comenzará a registrar todos los datos recibidos en ese archivo. El registro son líneas imprimibles como se definen en mode2(1) que describen las duraciones de los pulsos/espacios. Sin una ruta, se cierra el archivo de registro actual y se detiene el registro.
DRV_OPTION clave valor
Hace que lircd invoque drvctl_func(DRVCTL_SET_OPTION, opción) con la opción formada por la clave y el valor analizados. El paquete de retorno refleja el resultado de la llamada a drvctl_func.
SIMULATE clave datos
Dados los datos de la clave, instruye a lircd para que los envíe a todos los clientes, es decir, para simular que esta clave ha sido decodificada. Los datos de la clave deben tener el formato exacto del paquete descrito en [FORMATO DE MENSAJES DE BROADCAST DEL SOCKET], en particular, el número de dígitos en el código y el recuento de repetición están codificados. Este comando solo se acepta si la opción de línea de comandos --allow-simulate está activa.
SET_TRANSMITTERS máscara de transmisor
Hace que lircd invoque drvctl_func(LIRC_SET_TRANSMITTER_MASK, &canales), donde canales es el valor decodificado de la máscara de transmisor. Consulte lirc(4) para obtener más información.
VERSION
Indica a lircd que envíe una respuesta de paquete de versión.

El protocolo garantiza que los mensajes difundidos no interferirán con los paquetes de respuesta. Pero las difusiones pueden aparecer en cualquier momento entre paquetes. La única excepción son los paquetes SIGHUP. Estos pueden aparecer justo después de haber enviado un comando a lircd, por lo que debe asegurarse de no confundirlos con respuestas.

El formato del paquete de respuesta es

  BEGIN
  <comando>
  [SUCCESS|ERROR]
  [DATA
  n
  n líneas de datos]
  END

Si el comando fue exitoso, los datos solo se envían para los comandos que devuelven alguna información. Tenga en cuenta que un paquete que contiene 0 líneas de datos puede ser una respuesta válida.

EJECUCIÓN COMO USUARIO REGULAR

Tradicionalmente, lircd se ejecutaba como root, ya que el acceso a los dispositivos del kernel como /dev/lirc0 requiere privilegios de root por defecto. Sin embargo, ejecutar un servicio de larga duración como este es un problema de seguridad importante.

La distribución de lirc contiene reglas de udev de ejemplo que hacen que /dev/lirc[0-9] , los dispositivos USB y serie sean accesibles por el usuario lirc. Utilizando estas reglas, es posible ejecutar lircd como un usuario y grupo regular, como lirc.

ARCHIVOS

/etc/lirc/lircd.conf
Archivo de configuración principal, consulte lircd.conf(5).
/etc/lirc/lirc_options.conf
El archivo de opciones. lircd maneja los valores bajo la sección [lircd] en este archivo. La ubicación se puede cambiar usando la opción de línea de comandos -O/--options-file o usando la variable de entorno LIRC_OPTIONS_PATH. Los valores aquí se utilizan como valores predeterminados para cualquier opción que no esté presente en la línea de comandos.

ENTORNO

LIRC_OPTIONS_PATH
Ruta del archivo de opciones, consulte ARCHIVOS.
LIRC_PLUGINDIR
Ruta de carga de plugins, consulte CARGA DE CONTROLADORES.
LIRC_DEBUG_OPTIONS
Si está establecido, habilita la depuración en etapas tempranas cuando la opción --debug aún no se ha analizado.

CARGA DE CONTROLADORES

Los controladores se cargan dinámicamente. Esto se hace desde una ruta tradicional separada por ´:´ en la que se busca cada componente de la ruta (primero la parte inicial, la última al final).

La ruta utilizada para esto está determinada por (prioridad decreciente):

  • La opción --plugindir.
  • La entrada 'plugindir' en la sección [lircd] del archivo lirc_options.conf.
  • La variable de entorno LIRC_PLUGINDIR.
  • Un valor predeterminado codificado (/usr/lib/lirc/plugins).

SEÑALES

HUP
Al recibir SIGHUP, lircd vuelve a leer el archivo de configuración lircd.conf (pero no lirc_options.conf) y se ajusta si el archivo ha cambiado.
USR1
Al recibir SIGUSR1, lircd finaliza limpiamente.

DEMONIOS

lircd es un demonio. Debe iniciarse en algún script de arranque específico del sistema. Por defecto, lirc incluye archivos systemd que permiten al usuario controlar el servicio lircd.
