DESCRIPCIÓN

BIO_f_ssl() devuelve el método BIO de SSL. Este es un BIO de filtro que envuelve las rutinas SSL de OpenSSL, añadiendo un "sabor" BIO a la E/S SSL.

La E/S realizada en un BIO de SSL se comunica usando el protocolo SSL con los BIO de lectura y escritura del SSL. Si no se ha establecido una conexión SSL, se intentará establecer una en la primera llamada de E/S.

Si se añade un BIO a un BIO de SSL usando BIO_push(3), se utiliza automáticamente como los BIO de lectura y escritura del BIO de SSL.

Llamar a BIO_reset(3) en un BIO de SSL cierra cualquier conexión SSL actual llamando a SSL_shutdown(3). Luego se llama a BIO_reset(3) en el siguiente BIO en la cadena; esto típicamente desconectará el transporte subyacente. El BIO de SSL se restablece entonces al estado inicial de aceptación o conexión.

Si se establece la bandera de cierre cuando se libera un BIO de SSL, la estructura SSL interna también se libera usando SSL_free(3).

BIO_set_ssl() establece el puntero SSL interno del BIO b a ssl usando la bandera de cierre c.

BIO_get_ssl() recupera el puntero SSL del BIO b; luego puede ser manipulado usando las funciones estándar de la biblioteca SSL.

BIO_set_ssl_mode() establece el modo del BIO de SSL a client. Si client es 1, se establece el modo cliente. Si client es 0, se establece el modo servidor.

BIO_set_ssl_renegotiate_bytes() establece el número de bytes para renegociar a num. Cuando se establece, después de cada num bytes de E/S (lectura y escritura), la sesión SSL se renegociará automáticamente. num debe ser de al menos 512 bytes.

BIO_set_ssl_renegotiate_timeout() establece el tiempo de espera para renegociar a seconds. Cuando expira el tiempo de espera de renegociación, la sesión se renegociará automáticamente.

BIO_get_num_renegotiates() devuelve el número total de renegociaciones de sesión debido a E/S o tiempo de espera.

BIO_new_ssl() asigna un BIO de SSL usando SSL_CTX ctx y usando el modo cliente si client no es cero.

BIO_new_ssl_connect() crea una nueva cadena de BIO que consiste en un BIO de SSL (usando ctx) seguido de un BIO de conexión.

BIO_new_buffer_ssl_connect() crea una nueva cadena de BIO que consiste en un BIO con búfer, un BIO de SSL (usando ctx) y un BIO de conexión.

BIO_ssl_copy_session_id() copia una ID de sesión SSL entre las cadenas de BIO from y to. Lo hace localizando los BIO de SSL en cada cadena y llamando a SSL_copy_session_id(3) en el puntero SSL interno.

BIO_ssl_shutdown() cierra una conexión SSL en la cadena de BIO bio. Lo hace localizando el BIO de SSL en la cadena y llamando a SSL_shutdown(3) en su puntero SSL interno.

BIO_do_handshake() intenta completar un apretón de manos SSL en el BIO suministrado y establecer la conexión SSL. Devuelve 1 si la conexión se estableció correctamente. Se devuelve un valor cero o negativo si la conexión no pudo establecerse; la llamada SSL_get_error(3) puede ser usada para determinar la razón.

DESCRIPTION

The BIO_f_ssl() function returns a BIO method for SSL BIOs. It can be used with BIO_push(3) to add SSL functionality to a BIO chain.

BIO_new_ssl() creates a new SSL BIO that is associated with the provided SSL context ctx. If client is 1, it is a client-side BIO, otherwise it is a server-side BIO.

BIO_new_ssl_connect() creates a new SSL BIO chain. The chain consists of an SSL BIO and a connect BIO. The SSL BIO is associated with the provided context ctx. The connect BIO is used to establish a connection to a remote host. If the connection is established successfully, the SSL BIO is pushed onto the connect BIO.

BIO_new_buffer_ssl_connect() is similar to BIO_new_ssl_connect() but it also adds a buffering BIO to the chain, enabling efficient line-based I/O using BIO_gets(3) etc.

BIO_ssl_copy_session_id() copies the SSL session id from the from BIO to the to BIO. This is useful for resuming SSL sessions.

BIO_ssl_shutdown() performs an SSL shutdown on the given BIO.

BIO_do_handshake() performs the SSL handshake on the given BIO.

BIO_set_ssl() associates an already created SSL object with the given BIO. If close_bio is true, the underlying BIO will be freed when the SSL BIO is freed.

BIO_get_ssl() retrieves the SSL object from the given BIO.

BIO_set_ssl_mode() sets the mode for the SSL BIO. Currently, only SSL_MODE_AUTO_RETRY is supported. If this mode is set, the SSL BIO will automatically retry operations that would otherwise fail with an EAGAIN or EWOULDBLOCK error, provided the underlying transport is non-blocking. This is the default behaviour for SSL BIOs.

BIO_set_ssl_renegotiate_bytes() and BIO_set_ssl_renegotiate_timeout() can be used to control renegotiation. If a renegotiation is requested by the peer, and the data exchanged since the last renegotiation is less than BIO_set_ssl_renegotiate_bytes() bytes, then the renegotiation will be deferred until at least that many bytes have been exchanged. Similarly, if the time since the last renegotiation exceeds BIO_set_ssl_renegotiate_timeout() seconds, a renegotiation will be initiated. Setting either value to 0 disables the corresponding check. The default is 0 for both.

BIO_get_num_renegotiates() returns the number of renegotiations that have occurred on the SSL BIO.

BIO_should_retry(3) should be used for non blocking BIOs to determine if the call should be retried. If an SSL connection has already been established, this call has no effect.

When a chain containing an SSL BIO is copied with BIO_dup_chain(3), SSL_dup(3) is called internally to copy the SSL object from the existing BIO object to the new BIO object, and the internal data related to BIO_set_ssl_renegotiate_bytes() and BIO_set_ssl_renegotiate_timeout() is also copied.

SSL BIOs are exceptional in that if the underlying transport is non-blocking they can still request a retry in exceptional circumstances. Specifically this will happen if a session renegotiation takes place during a BIO_read(3) operation. One case where this happens is when step up occurs.

In OpenSSL 0.9.6 and later the SSL flag SSL_AUTO_RETRY can be set to disable this behaviour. In other words, when this flag is set an SSL BIO using a blocking transport will never request a retry.

Since unknown BIO_ctrl(3) operations are sent through filter BIOs, the server name and port can be set using BIO_set_conn_hostname(3) and BIO_set_conn_port(3) on the BIO returned by BIO_new_ssl_connect() without having to locate the connect BIO first.

Applications do not have to call BIO_do_handshake() but may wish to do so to separate the handshake process from other I/O processing.

BIO_set_ssl(), BIO_get_ssl(), BIO_set_ssl_mode(), BIO_set_ssl_renegotiate_bytes(), BIO_set_ssl_renegotiate_timeout(), BIO_get_num_renegotiates(), and BIO_do_handshake() are implemented as macros.

RETURN VALUES

BIO_f_ssl() returns a pointer to a static BIO_METHOD structure.

When called on an SSL BIO object, BIO_method_type(3) returns the constant BIO_TYPE_SSL and BIO_method_name(3) returns a pointer to the static string "ssl".

BIO_set_ssl(), BIO_get_ssl(), BIO_set_ssl_mode(), BIO_set_ssl_renegotiate_bytes(), BIO_set_ssl_renegotiate_timeout(), and BIO_get_num_renegotiates() return 1 on success or a value less than or equal to 0 if an error occurred.

BIO_new_ssl(), BIO_new_ssl_connect(), and BIO_new_buffer_ssl_connect() returns a pointer to a newly allocated BIO chain or NULL if an error occurred.

BIO_ssl_copy_session_id() returns 1 on success or 0 on error.

BIO_do_handshake() returns 1 if the connection was established successfully or a value less than or equal to 0 otherwise.

EXAMPLES

This SSL/TLS client example attempts to retrieve a page from an SSL/TLS web server. The I/O routines are identical to those of the unencrypted example in BIO_s_connect(3).

BIO *sbio, *out;
int len;
char tmpbuf[1024];
SSL_CTX *ctx;
SSL *ssl;

ERR_load_crypto_strings();
ERR_load_SSL_strings();
OpenSSL_add_all_algorithms();

/*
 * We would seed the PRNG here if the platform didn't do it automatically
 */

ctx = SSL_CTX_new(SSLv23_client_method());

/*
 * We'd normally set some stuff like the verify paths and mode here because
 * as things stand this will connect to any server whose certificate is
 * signed by any CA.
 */

sbio = BIO_new_ssl_connect(ctx);

BIO_get_ssl(sbio, &ssl);

if (!ssl) {
	fprintf(stderr, "Can't locate SSL pointer\n");
	/* whatever ... */
}

/* Don't want any retries */
SSL_set_mode(ssl, SSL_MODE_AUTO_RETRY);

/* We might want to do other things with ssl here */

BIO_set_conn_hostname(sbio, "localhost:https");

out = BIO_new_fp(stdout, BIO_NOCLOSE);
if (BIO_do_connect(sbio) <= 0) {
	fprintf(stderr, "Error connecting to server\n");
	ERR_print_errors_fp(stderr);
	/* whatever ... */
}

if (BIO_do_handshake(sbio) <= 0) {
	fprintf(stderr, "Error establishing SSL connection\n");
	ERR_print_errors_fp(stderr);
	/* whatever ... */
}

/* Could examine ssl here to get connection info */

BIO_puts(sbio, "GET / HTTP/1.0\n\n");
for (;;) {
	len = BIO_read(sbio, tmpbuf, 1024);
	if(len <= 0) break;
	BIO_write(out, tmpbuf, len);
}
BIO_free_all(sbio);
BIO_free(out);

Here is a simple server example. It makes use of a buffering BIO to allow lines to be read from the SSL BIO using BIO_gets(3). It creates a pseudo web page containing the actual request from a client and also echoes the request to standard output.

BIO *sbio, *bbio, *acpt, *out;
int len;
char tmpbuf[1024];
SSL_CTX *ctx;
SSL *ssl;

ctx = SSL_CTX_new(SSLv23_server_method());

if (!SSL_CTX_use_certificate_file(ctx,"server.pem",SSL_FILETYPE_PEM)
    || !SSL_CTX_use_PrivateKey_file(ctx,"server.pem",SSL_FILETYPE_PEM)
    || !SSL_CTX_check_private_key(ctx)) {
	fprintf(stderr, "Error setting up SSL_CTX\n");
	ERR_print_errors_fp(stderr);
	return 0;
}

/*
 * Might do other things here like setting verify locations and DH and/or
 * RSA temporary key callbacks
 */

/* New SSL BIO setup as server */
sbio = BIO_new_ssl(ctx,0);

BIO_get_ssl(sbio, &ssl);

if (!ssl) {
	fprintf(stderr, "Can't locate SSL pointer\n");
	/* whatever ... */
}

/* Don't want any retries */
SSL_set_mode(ssl, SSL_MODE_AUTO_RETRY);

/* Create the buffering BIO */

bbio = BIO_new(BIO_f_buffer());

/* Add to chain */
sbio = BIO_push(bbio, sbio);

acpt = BIO_new_accept("4433");

/*
 * By doing this when a new connection is established we automatically
 * have sbio inserted into it. The BIO chain is now 'swallowed' by the
 * accept BIO and will be freed when the accept BIO is freed.
 */

BIO_set_accept_bios(acpt,sbio);

out = BIO_new_fp(stdout, BIO_NOCLOSE);

/* Wait for incoming connection */
if (BIO_do_accept(acpt) <= 0) {
	fprintf(stderr, "Error setting up accept BIO\n");
	ERR_print_errors_fp(stderr);
	return 0;
}

/* We only want one connection so remove and free accept BIO */

sbio = BIO_pop(acpt);

BIO_free_all(acpt);

if (BIO_do_handshake(sbio) <= 0) {
	fprintf(stderr, "Error in SSL handshake\n");
	ERR_print_errors_fp(stderr);
	return 0;
}

BIO_puts(sbio, "HTTP/1.0 200 OK\r\nContent-type: text/plain\r\n\r\n");
BIO_puts(sbio, "\r\nConnection Established\r\nRequest headers:\r\n");
BIO_puts(sbio, "--------------------------------------------------\r\n");

for (;;) {
	len = BIO_gets(sbio, tmpbuf, 1024);
	if (len <= 0)
		break;
	BIO_write(sbio, tmpbuf, len);
	BIO_write(out, tmpbuf, len);
	/* Look for blank line signifying end of headers */
	if ((tmpbuf[0] == '\r') || (tmpbuf[0] == '\n'))
		break;
}

BIO_puts(sbio, "--------------------------------------------------\r\n");
BIO_puts(sbio, "\r\n");

/* Since there is a buffering BIO present we had better flush it */
BIO_flush(sbio);

BIO_free_all(sbio);
