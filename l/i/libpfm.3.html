LIBPFM(3) Manual del programador de Linux LIBPFM(3)

NOMBRE

libpfm - una biblioteca auxiliar para desarrollar herramientas de monitoreo

SINOPSIS

#include <perfmon/pfmlib.h>

DESCRIPCIÓN

Esta es una biblioteca auxiliar utilizada por aplicaciones para programar eventos específicos de monitoreo de rendimiento. Esos eventos suelen ser proporcionados por el hardware o el kernel del sistema operativo. Los eventos de hardware más comunes son proporcionados por la Unidad de Monitoreo de Rendimiento (PMU) de los procesadores modernos. Pueden medir ciclos transcurridos o el número de fallos de caché. Los eventos de software suelen contar eventos del kernel como el número de cambios de contexto o fallos de página.

La biblioteca agrupa los eventos según la fuente que los proporciona. El término PMU se generaliza a cualquier fuente de eventos, no solo a fuentes de hardware. La biblioteca soporta eventos de rendimiento de hardware de la mayoría de los procesadores comunes, cada grupo bajo un nombre de PMU específico, como Intel Core, IBM Power 6.

La programación de eventos generalmente se realiza a través de una API del kernel, como Oprofile, perfmon, perfctr o perf_events en Linux. La biblioteca proporciona soporte para perf_events, que está disponible en el kernel de Linux a partir de la v2.6.31. Perf_events soporta modelos de PMU seleccionados y varios eventos de software.

En su núcleo, la biblioteca proporciona un servicio de traducción simple, mediante el cual un usuario especifica un evento a medir como una cadena de texto y la biblioteca devuelve los parámetros necesarios para invocar la API del kernel. Es importante darse cuenta de que la biblioteca **no** realiza la llamada al sistema para programar el evento.

Nota: Debes llamar primero a pfm_initialize() para poder usar cualquiera de las otras funciones proporcionadas en la biblioteca.

Una primera parte de la biblioteca proporciona una interfaz de listado y consulta de eventos. Esto se puede usar para descubrir los eventos disponibles en una plataforma de hardware específica.

La segunda parte de la biblioteca proporciona un conjunto de funciones para obtener codificaciones de eventos a partir de cadenas de eventos. La codificación de eventos depende principalmente del hardware subyacente, pero también de la API del kernel. La biblioteca ofrece una API genérica para abordar la primera situación, pero también proporciona puntos de entrada para APIs específicas del kernel como perf_events. En ese caso, es capaz de preparar la estructura de datos que debe pasarse al kernel para programar un evento específico.

DETECCIÓN DE EVENTOS

Cuando la biblioteca se inicializa a través de pfm_initialize(), primero detecta la configuración de hardware y software subyacente. Basándose en esta información, habilita cierto soporte de PMU. Se pueden activar múltiples tablas de eventos.

Es posible forzar la activación de una PMU específica (grupo de eventos) utilizando una variable de entorno.

CADENAS DE EVENTOS

Los eventos se expresan como cadenas de texto. Estas cadenas están estructuradas y pueden contener varios componentes según el tipo de evento y el hardware subyacente.

El análisis de cadenas siempre distingue mayúsculas y minúsculas.

La estructura de la cadena se define de la siguiente manera:


[pmu::][nombre_evento][:mascara_unidad][:modificador|:modificador=valor]

o
[pmu::][nombre_evento][.mascara_unidad][.modificador|.modificador=valor]

Los componentes se definen de la siguiente manera:

pmu
Nombre opcional de la PMU (grupo de eventos) a la que pertenece el evento. Esto es útil para desambiguar eventos en caso de que eventos de diferentes fuentes tengan el mismo nombre. Si no se especifica, se utiliza la primera coincidencia.
nombre_evento
El nombre del evento. Debe ser el nombre completo, las coincidencias parciales no son aceptadas. Este componente es obligatorio.
mascara_unidad
Esto designa sub-eventos opcionales. Algunos eventos pueden refinarse usando sub-eventos. Los eventos pueden tener múltiples máscaras de unidad y puede ser posible combinarlas o no. Si se necesita pasar más de una máscara de unidad, entonces el patrón [:mascara_unidad] se puede repetir.
modificador
Un modificador es un filtro opcional que modifica cómo se cuentan los eventos. Los modificadores tienen un tipo y un valor. El valor se especifica después del signo igual. No se permiten espacios. En caso de modificadores booleanos, es posible omitir el valor verdadero (1). La presencia del modificador se interpreta como verdadero. Los eventos pueden soportar múltiples modificadores, en cuyo caso el patrón [:modificador|:modificador=valor] se puede repetir. No hay restricciones de orden entre el modificador y las máscaras de unidad. Los modificadores pueden especificarse antes que las máscaras de unidad y viceversa.

VARIABLES DE ENTORNO

Es posible habilitar ciertas funciones de depuración de la biblioteca utilizando variables de entorno. Las siguientes variables están definidas:

LIBPFM_VERBOSE
Habilita la salida detallada. El valor debe ser 0 o 1.
LIBPFM_DEBUG
Habilita la salida de depuración. El valor debe ser 0 o 1.
LIBPFM_DEBUG_STDOUT
Redirige la salida detallada y de depuración al descriptor de archivo de salida estándar (stdout). Por defecto, la salida se dirige al descriptor de archivo de error estándar (stderr).
LIBPFM_FORCE_PMU
Fuerza la activación de un modelo de PMU específico. En este modo, solo se activa ese modelo. El valor de la variable debe ser el nombre de la PMU tal como lo devuelve la función pfm_get_pmu_name(). Tenga en cuenta que para algunos modelos de PMU, es posible especificar opciones adicionales, como modelos de procesador específicos o stepping. Los parámetros adicionales aparecen necesariamente después de una coma. Por ejemplo, LIBPFM_FORCE_PMU=amd64,16,2,1.
LIBPFM_ENCODE_INACTIVE
Establece esta variable en 1 para habilitar la codificación de eventos para modelos de PMU no detectados, pero soportados.
LIBPFM_DISABLED_PMUS
Proporciona una lista de modelos de PMU a deshabilitar. Es una lista separada por comas de modelos de PMU. El modelo de PMU es la cadena en el campo name de la estructura pfm_pmu_info_t. Por ejemplo: LIBPFM_DISABLE_PMUS=core,snb, deshabilitará tanto el soporte de PMU del núcleo Intel Core como del núcleo SandyBridge.

libpfm — Performance Monitoring Event Library

SYNOPSIS

void pfmlib_exit(void);

int pfmlib_get_version(void);

int pfmlib_get_intel_event_info(pfmlib_event_code_t event_code, pfmlib_intel_event_info_t *event_info);

int pfmlib_get_amd_event_info(pfmlib_event_code_t event_code, pfmlib_amd_event_info_t *event_info);

DESCRIPTION

The libpfm library provides an interface to the performance monitoring capabilities of various CPU architectures. It allows applications to query available performance monitoring events, configure counters, and parse event descriptions.

INITIALIZATION AND EXIT

pfmlib_init(unsigned int flags): Initializes the library. The flags argument can be used to control library behavior (e.g., PFMLIB_NO_GROUP_BY_CORE). Returns 0 on success, or a negative error code on failure.

pfmlib_exit(void): Cleans up library resources. This should be called before the application exits.

INFORMATION RETRIEVAL

pfmlib_get_version(void): Returns the library version number.

pfmlib_get_description(void): Returns a human-readable string describing the library and the detected CPU architecture.

pfmlib_get_event_code(const char *event_name, pfmlib_event_code_t *event_code): Retrieves the internal event code for a given event name string. The event name can include modifiers (e.g., CPU_CLK_UNHALTED.THRU_HITS:G).

pfmlib_get_event_name(pfmlib_event_code_t event_code, char *event_name): Retrieves the string name for a given event code.

pfmlib_get_event_mask(pfmlib_event_code_t event_code, pfmlib_event_mask_t *event_mask): Retrieves the event mask associated with an event code. The mask specifies which counters can be used for this event.

pfmlib_get_event_info(pfmlib_event_code_t event_code, pfmlib_event_info_t *event_info): Retrieves general information about an event, such as its name, description, and supported flags.

pfmlib_get_intel_event_info(...), pfmlib_get_amd_event_info(...), pfmlib_get_spx_event_info(...), pfmlib_get_arm_event_info(...), pfmlib_get_sgi_event_info(...): Retrieve architecture-specific event information.

pfmlib_get_pmd_info(pfmlib_event_code_t event_code, pfmlib_pmd_info_t *pmd_info): Retrieves information about the Performance Monitoring Data (PMD) for an event.

pfmlib_get_event_counter_mask(pfmlib_event_code_t event_code, pfmlib_counter_mask_t *counter_mask): Retrieves a bitmask indicating which hardware counter units can be used for a given event.

pfmlib_get_event_max_period(...), pfmlib_get_event_default_period(...), pfmlib_get_event_granularity(...): Retrieve information about the sampling period and granularity of an event.

pfmlib_get_event_perf_config(...): Translates a libpfm event into the corresponding perf_event_open(2) parameters (type and config).

EVENT PARSING AND FORMATTING

pfmlib_parse_event_modifiers(...): Parses an event string that may include modifiers (e.g., event_name:modifier1:modifier2) and extracts the event code, event mask, and optionally the CPU affinity.

pfmlib_format_event_mask(...): Formats an event mask into a human-readable string.

pfmlib_parse_cpu_description(...): Parses a CPU description string (e.g., "core X", "all") into an integer CPU identifier.

pfmlib_format_cpu_description(...): Formats an integer CPU identifier into a human-readable string.

EVENT AVAILABILITY AND CONSTRAINTS

pfmlib_get_event_support_flags(...): Retrieves flags indicating general support for an event (e.g., edge detection, overflow notification).

pfmlib_get_event_constraints(...): Retrieves hardware constraints associated with an event, such as which counters it can run on or which specific CPU cores it is available on.

pfmlib_validate_event(...): Validates if a given event configuration is valid for the current CPU.

EVENT SELECTION AND INSERTION

pfmlib_select_event(...): Selects an appropriate event configuration from a list of desired events for a given CPU.

pfmlib_insert_event(...): Inserts an event into a configuration structure, checking for conflicts and constraints.

SUPPORTED EVENTS

pfmlib_get_supported_events(...): Retrieves a list of all supported event codes for the current CPU.

pfmlib_free_supported_events(...): Frees the memory allocated by pfmlib_get_supported_events().

pfmlib_get_event_availability(...): Checks the availability of a specific event on a given CPU, taking into account hardware constraints.

ENVIRONMENT VARIABLES

None.
