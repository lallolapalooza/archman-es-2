CMS_ADD1_SIGNER(3) Manual de funciones de biblioteca CMS_ADD1_SIGNER(3)

NOMBRE

CMS_add1_signer, CMS_SignerInfo_sign — agregar un firmante a una estructura CMS SignedData

SINOPSIS

biblioteca “libcrypto”
#include <openssl/cms.h>

CMS_SignerInfo *
CMS_add1_signer(CMS_ContentInfo *cms, X509 *signcert, EVP_PKEY *pkey, const EVP_MD *md, unsigned int flags);

int
CMS_SignerInfo_sign(CMS_SignerInfo *si);

DESCRIPCIÓN

CMS_add1_signer() agrega un firmante con certificado signcert y clave privada pkey usando el digest del mensaje md al campo signerInfos de la estructura SignedData cms, que debería haberse obtenido de una llamada inicial a CMS_sign(3) con la bandera CMS_PARTIAL establecida, o que puede ser una estructura SignedData válida en caso de re-firma.

Si md es NULL, se usa el digest predeterminado para el algoritmo de clave pública de pkey.

A menos que se establezca la bandera CMS_REUSE_DIGEST, la estructura cms permanece incompleta y debe ser finalizada, ya sea por streaming (si es aplicable) o mediante una llamada a CMS_final(3).

El propósito principal de CMS_add1_signer() es proporcionar un control más fino sobre una estructura CMS SignedData donde la función más simple CMS_sign(3) no es apropiada, por ejemplo, si se necesitan múltiples firmantes o algoritmos de digest no predeterminados. También se pueden agregar nuevos atributos usando la estructura CMS_SignerInfo devuelta y las funciones de utilidad de atributos CMS o las funciones de solicitud de recibo firmado CMS.

Cualquiera de las siguientes banderas (combinadas con OR) se puede pasar en el parámetro flags:

CMS_REUSE_DIGEST
Intenta copiar el valor del digest del contenido de una de las estructuras CMS_SignerInfo existentes en cms al agregar otro firmante. Se produce un error si no se encuentra un valor de digest coincidente para copiar. La estructura cms será válida y estará finalizada cuando se establezca esta bandera.
CMS_PARTIAL
Si esta bandera se establece además de CMS_REUSE_DIGEST, la estructura CMS_SignerInfo devuelta no se finalizará, por lo que se pueden agregar atributos adicionales. En este caso, se necesita una llamada explícita a CMS_SignerInfo_sign() para finalizarla.
CMS_NOCERTS
No agregue el certificado del firmante al campo certificates de cms. Sin embargo, el certificado del firmante aún debe suministrarse en el parámetro signcert. Esta bandera puede reducir el tamaño de la firma si el certificado del firmante se puede obtener por otros medios, por ejemplo, de un mensaje firmado previamente.
CMS_NOATTR
Deje el campo signedAttrs de la estructura CMS_SignedData devuelta vacío. Por defecto, se agregan varios SignedAttributes de CMS, incluido el tiempo de firma, el tipo de contenido CMS y la lista de cifradores admitidos en un atributo SMIMECapabilities.
CMS_NOSMIMECAP
Omite solo el atributo SMIMECapabilities.
CMS_USE_KEYID
Utiliza el identificador de clave del sujeto para identificar los certificados de firma. Se produce un error si el certificado de firma no tiene una extensión de identificador de clave del sujeto. Por defecto, se utiliza el nombre del emisor y el número de serie en su lugar.

Si está presente, el atributo SMIMECapabilities indica soporte para los siguientes algoritmos en orden de preferencia: AES de 256 bits, AES de 192 bits, AES de 128 bits, triple DES, RC2 de 128 bits, RC2 de 64 bits, DES y RC2 de 40 bits. Si alguno de estos algoritmos no está disponible, no se incluirá.

La función CMS_SignerInfo_sign() firma explícitamente si. Su uso principal es cuando las banderas CMS_REUSE_DIGEST y CMS_PARTIAL se establecieron en la llamada a CMS_add1_signer() que creó si.

VALORES DEVUELTOS

CMS_add1_signer() devuelve un puntero interno a la nueva estructura CMS_SignerInfo recién agregada o NULL si ocurre un error.

NOMBRE

CMS_add1_signer, CMS_add_cert, CMS_add_conf

SINOPSIS

#include <openssl/cms.h>

int CMS_add1_signer(CMS_ContentInfo *cms, X509 *cert, EVP_PKEY *key,
                    const EVP_MD *digest, unsigned int flags);
int CMS_add_cert(CMS_ContentInfo *cms, X509 *cert, unsigned int flags);
int CMS_add_conf(CMS_ContentInfo *cms, STACK_OF(X509_INFO) *certs,
                 unsigned int flags);

DESCRIPCIÓN

Estas funciones añaden información adicional a un contenido CMS (Cryptographic Message Syntax).

La función CMS_add1_signer añade un firmante al contenido CMS. El parámetro cms es el puntero al contenido CMS. El parámetro cert es el certificado del firmante. El parámetro key es la clave privada del firmante. El parámetro digest es el algoritmo de hash a utilizar. El parámetro flags se puede utilizar para especificar opciones adicionales.

La función CMS_add_cert añade un certificado adicional a la sección de certificados del contenido CMS. Esto es útil para incluir certificados intermedios o de confianza.

La función CMS_add_conf añade una pila de X509_INFO (que puede contener certificados y CRLs) a la sección de certificados del contenido CMS.

VALORES DE RETORNO

Todas estas funciones devuelven 1 en caso de éxito, y 0 en caso de error.

VER TAMBIÉN

CMS_ContentInfo(3), EVP_Digest(3), X509(3)

HISTORIA

Estas funciones fueron introducidas en OpenSSL 0.9.7.
