LIBIPQ(3) Manual del Programador de Linux LIBIPQ(3)

NOMBRE

libipq — biblioteca de colas de paquetes en el espacio de usuario de iptables.

SINOPSIS

#include <linux/netfilter.h>
#include <libipq.h>

DESCRIPCIÓN

libipq es una biblioteca de desarrollo para la cola de paquetes en el espacio de usuario de iptables.

Colas de paquetes en el espacio de usuario

Netfilter proporciona un mecanismo para pasar paquetes fuera de la pila para su puesta en cola en el espacio de usuario, y luego recibir estos paquetes de vuelta en el kernel con un veredicto que especifica qué hacer con los paquetes (como ACCEPT o DROP). Estos paquetes también pueden ser modificados en el espacio de usuario antes de ser reinyectados de nuevo en el kernel.

Para cada protocolo soportado, un módulo del kernel llamado gestor de colas puede registrarse con Netfilter para realizar las operaciones de paso de paquetes hacia y desde el espacio de usuario.

El gestor de colas estándar para IPv4 es ip_queue. Se proporciona como un módulo experimental con los kernels 2.4 y utiliza un socket Netlink para la comunicación kernel/espacio de usuario.

Una vez que ip_queue está cargado, los paquetes IP pueden ser seleccionados con iptables y puestos en cola para su procesamiento en el espacio de usuario a través del objetivo QUEUE. Por ejemplo, ejecutando los siguientes comandos:

# modprobe iptable_filter
# modprobe ip_queue
# iptables -A OUTPUT -p icmp -j QUEUE

hará que cualquier paquete ICMP generado localmente (por ejemplo, salida de ping) se envíe al módulo ip_queue, que intentará entregar los paquetes a una aplicación de espacio de usuario. Si ninguna aplicación de espacio de usuario está esperando, los paquetes serán descartados.

Una aplicación puede recibir y procesar estos paquetes a través de libipq.

Resumen de Libipq

Libipq proporciona una API para comunicarse con ip_queue. Lo siguiente es una descripción general del uso de la API, consulte las páginas de manual individuales para obtener más detalles sobre cada función.

Inicialización
Para inicializar la biblioteca, llame a ipq_create_handle(3). Esto intentará vincularse al socket Netlink utilizado por ip_queue y devolverá un manejador de contexto opaco para las llamadas posteriores a la biblioteca.

Establecer el modo de cola
ipq_set_mode(3) permite a la aplicación especificar si los metadatos del paquete, o las cargas útiles del paquete además de los metadatos, se copian al espacio de usuario. También se utiliza para notificar inicialmente a ip_queue que una aplicación está lista para recibir mensajes de cola.

Recibir paquetes de la cola
ipq_read(3) espera a que lleguen mensajes de cola desde ip_queue y los copia a un buffer proporcionado. Los mensajes de cola pueden ser mensajes de paquete o mensajes de error.

El tipo de paquete se puede determinar con ipq_message_type(3).

Si es un mensaje de paquete, los metadatos y la carga útil opcional se pueden recuperar con ipq_get_packet(3).

Para recuperar el valor de un mensaje de error, use ipq_get_msgerr(3).

Emitir veredictos sobre paquetes
Para emitir un veredicto sobre un paquete, y opcionalmente devolver una versión modificada del paquete al kernel, llame a ipq_set_verdict(3).

Manejo de errores
Una cadena de error correspondiente al valor actual de la variable interna de error ipq_errno puede obtenerse con ipq_errstr(3).

Para aplicaciones sencillas, llamar a ipq_perror(3) imprimirá el mismo mensaje que ipq_errstr(3), así como la cadena correspondiente al valor global errno (si está establecido) en stderr.

Limpieza
Para liberar el socket Netlink y destruir los recursos asociados con el manejador de contexto, llame a ipq_destroy_handle(3).

Función auxiliar para imprimir mensajes de error en stderr.

EJEMPLO

El siguiente es un ejemplo de una aplicación sencilla que recibe paquetes y emite veredictos NF_ACCEPT en cada paquete.

/*
 * Este código es GPL.
 */
#include <linux/netfilter.h>
#include <libipq.h>
#include <stdio.h>
#define BUFSIZE 2048 
static void die(struct ipq_handle *h)
{
	ipq_perror("passer");
	ipq_destroy_handle(h);
	exit(1);
}
int main(int argc, char **argv)
{
	int status;
	unsigned char buf[BUFSIZE];
	struct ipq_handle *h;

	h = ipq_create_handle(0, NFPROTO_IPV4);
	if (!h)
		die(h);

	status = ipq_set_mode(h, IPQ_COPY_PACKET, BUFSIZE);
	if (status < 0)
		die(h);

	do{
		status = ipq_read(h, buf, BUFSIZE, 0);
		if (status < 0)
			die(h);

		switch (ipq_message_type(buf)) {
			case NLMSG_ERROR:
				fprintf(stderr, "Received error message %d\n",
				        ipq_get_msgerr(buf));
				break;

			case IPQM_PACKET: {
				ipq_packet_msg_t *m = ipq_get_packet(buf);

				status = ipq_set_verdict(h, m->packet_id,
				                         NF_ACCEPT, 0, NULL);
				if (status < 0)
					die(h);
				break;
			}

			default:
				fprintf(stderr, "Unknown message type!\n");
				break;
		}
	} while (1);

	ipq_destroy_handle(h);
	return 0;
}

DIAGNÓSTICOS

Para obtener información sobre la monitorización y el ajuste de ip_queue, consulte la HOWTO de filtrado de paquetes de Linux 2.4.

Si una aplicación modifica un paquete, también debe actualizar las sumas de verificación del paquete. Típicamente, el kernel descartará silenciosamente los paquetes modificados con sumas de verificación inválidas.

SEGURIDAD

Los procesos requieren la capacidad CAP_NET_ADMIN para acceder al módulo ip_queue del kernel. Dichos procesos pueden potencialmente acceder y modificar cualquier paquete IP recibido, generado o reenviado por el kernel.
