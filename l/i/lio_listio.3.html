lio_listio(3) Manual de funciones de biblioteca lio_listio(3)

NOMBRE

lio_listio - iniciar una lista de solicitudes de E/S

BIBLIOTECA

Biblioteca de tiempo real (librt, -lrt)

SINOPSIS

#include <aio.h>
int lio_listio(int n;
               int mode,
               struct aiocb *restrict const aiocb_list[restrict n],
               int n, struct sigevent *restrict sevp);

DESCRIPCIÓN

La función lio_listio() inicia la lista de operaciones de E/S descritas por la matriz aiocb_list.

La operación mode tiene uno de los siguientes valores:

LIO_WAIT
La llamada se bloquea hasta que todas las operaciones se completen. El argumento sevp se ignora.
LIO_NOWAIT
Las operaciones de E/S se ponen en cola para su procesamiento y la llamada devuelve inmediatamente. Cuando todas las operaciones de E/S se completen, se produce una notificación asíncrona, según lo especificado por el argumento sevp; consulte sigevent(3type) para obtener detalles. Si sevp es NULL, no se produce ninguna notificación asíncrona.

El argumento aiocb_list es una matriz de punteros a estructuras aiocb que describen operaciones de E/S. Estas operaciones se ejecutan en un orden no especificado. El argumento n especifica el tamaño de la matriz aiocb_list. Los punteros NULL en aiocb_list se ignoran.

En cada bloque de control en aiocb_list, el campo aio_lio_opcode especifica la operación de E/S a iniciar, como sigue:

LIO_READ
Inicia una operación de lectura. La operación se pone en cola como para una llamada a aio_read(3) especificando este bloque de control.
LIO_WRITE
Inicia una operación de escritura. La operación se pone en cola como para una llamada a aio_write(3) especificando este bloque de control.
LIO_NOP
Ignora este bloque de control.

Los campos restantes en cada bloque de control tienen los mismos significados que para aio_read(3) y aio_write(3). Los campos aio_sigevent de cada bloque de control se pueden usar para especificar notificaciones para las operaciones de E/S individuales (consulte sigevent(7)).

VALOR DE RETORNO

Si mode es LIO_NOWAIT, lio_listio() devuelve 0 si todas las operaciones de E/S se ponen en cola correctamente. De lo contrario, devuelve -1 y errno se establece para indicar el error.

Si mode es LIO_WAIT, lio_listio() devuelve 0 cuando todas las operaciones de E/S se han completado correctamente. De lo contrario, devuelve -1 y errno se establece para indicar el error.

El estado de retorno de lio_listio() solo proporciona información sobre la propia llamada, no sobre las operaciones de E/S individuales. Una o más de las operaciones de E/S pueden fallar, pero esto no impide que otras operaciones se completen. El estado de las operaciones de E/S individuales en aiocb_list se puede determinar usando aio_error(3). Cuando una operación se ha completado, su estado de retorno se puede obtener usando aio_return(3). Las operaciones de E/S individuales pueden fallar por las razones descritas en aio_read(3) y aio_write(3).

ERRORES

La función lio_listio() puede fallar por las siguientes razones:

EAGAIN
Recursos insuficientes.
EAGAIN
El número de operaciones de E/S especificado por n excedería el límite AIO_MAX.
EINTR
mode era LIO_WAIT y se capturó una señal antes de que se completaran todas las operaciones de E/S; consulte signal(7). (Esto puede incluso ser una de las señales utilizadas para la notificación de finalización de E/S asíncrona).
EINVAL
mode es inválido, o n excede el límite AIO_LISTIO_MAX.
EIO
Una o más de las operaciones especificadas por aiocb_list fallaron. La aplicación puede verificar el estado de cada operación usando aio_return(3).

Si lio_listio() falla con el error EAGAIN, EINTR o EIO, entonces algunas de las operaciones en aiocb_list pueden haber sido iniciadas. Si lio_listio() falla por cualquier otro motivo, ninguna de las operaciones de E/S se ha iniciado.

ATRIBUTOS

Para una explicación de los términos utilizados en esta sección, consulte attributes(7).

Interfaz Atributo Valor
lio_listio () Seguridad de hilos MT-Safe

ESTÁNDARES

POSIX.1-2008.

HISTORIA

glibc 2.1. POSIX.1-2001.

NOTAS

Es una buena idea poner a cero los bloques de control antes de usarlos. Los bloques de control no deben modificarse mientras las operaciones de E/S estén en curso. Las áreas de búfer de las que se lee o hacia las que se escribe no deben accederse durante las operaciones o pueden producirse resultados indefinidos. Las áreas de memoria involucradas deben permanecer válidas.

Las operaciones de E/S simultáneas que especifican la misma estructura aiocb producen resultados indefinidos.

lio_listio(3)

NAME

lio_listio - Asynchronous I/O list submission

SYNOPSIS

#include <aio.h>

int lio_listio(int mode, struct aiocb *restrict list[], int nent, struct sigevent *restrict sig);

DESCRIPTION

The lio_listio() function is used to submit a list of asynchronous I/O requests (specified by the members of the list array) for processing. The mode argument specifies whether all operations in the list should be submitted, or if they should be submitted individually. The nent argument specifies the number of elements in the list array. The sig argument is a pointer to a structure that specifies how the calling thread should be notified upon completion of the I/O operations.

The mode argument can be one of the following values:

LIO_READ
All operations in the list are read operations.
LIO_WRITE
All operations in the list are write operations.
LIO_LASYN
The operations are submitted as described in the aiocb structures. This mode combines read and write operations. For each operation in the list, the aio_lio_opcode field of the corresponding aiocb structure must be set to either LIO_READ or LIO_WRITE.

Each element of the list array is a pointer to an aiocb structure. This structure contains all the information necessary to perform an asynchronous I/O operation, including the file descriptor, the buffer to be used, the number of bytes to transfer, the offset, and the notification method.

The sig argument is a pointer to a sigevent structure. This structure specifies how the calling thread should be notified when all the I/O operations in the list have completed. If sig is NULL, no notification is made.

RETURN VALUE

On success, lio_listio() returns 0. On failure, it returns -1 and sets errno to indicate the error.

ERRORS

EAGAIN
All available asynchronous I/O resources are currently in use.
EBADF
An invalid file descriptor was specified in one of the aiocb structures.
EINVAL
An invalid value was specified for mode, or an invalid value was specified in one of the aiocb structures.
ENOMEM
Not enough memory was available to allocate resources for the I/O requests.
ENOSYS
Asynchronous I/O is not supported on the system.

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

Interface Attribute Value
lio_listio() Thread safety MT-Safe
Async signal safety AS-Safe

STANDARDS

POSIX.1-2008.

HISTORY

POSIX.1-2001.

NOTES

The lio_listio() function is part of the POSIX Realtime Extensions.

The aiocb structure is defined in <aio.h> and contains the following fields:

struct aiocb {
    int             aio_fildes;     // File descriptor
    off_t           aio_offset;     // Offset in the file
    volatile void  *aio_buf;        // Buffer for data transfer
    size_t          aio_nbytes;     // Number of bytes to transfer
    struct sigevent aio_sigevent;   // Notification mechanism
    int             aio_lio_opcode; // Operation code for lio_listio()
    // ... other fields ...
};
