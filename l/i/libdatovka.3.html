LIBDATOVKA(3) Manual for Libdatovka LIBDATOVKA(3)


.SH "NOMBRE" libdatovka - Biblioteca cliente ISDS


.SH "SINOPSIS"

#include <libdatovka/isds.h>
#include <stdio.h>
isds_error err;
struct isds_ctx *ctx;
err = isds_init();
ctx = isds_ctx_create();
err = isds_login(ctx, NULL, "username", "password", NULL, NULL);
if (err) {
    printf("isds_login() failed: %s: %s\n",
        isds_strerror(err), isds_long_message(ctx));
} else {
    printf("Logged in.\n");
}
err = isds_ctx_free(&ctx);
err = isds_cleanup();


.SH "DESCRIPCIÓN"


.PP Esta es una biblioteca cliente para acceder a los servicios SOAP de ISDS (Informační systém datových schránek / Sistema de Información de Buzones de Datos) según se define en la Ley Checa ISDS (300/2008 Coll.)[1] y documentos implícitos. Los detalles de la implementación actual se describen en el Provoznní řád que se puede descargar de la sección Dokumenty ke stažení del Portal de Información de ISDS[2].


.PP La biblioteca proporciona una interfaz en lenguaje C con llamadas bloqueantes síncronas no reentrantes. La notificación del progreso de la comunicación de red, el registro de operaciones y la depuración de la biblioteca se implementan llamando a funciones proporcionadas por la aplicación. Las operaciones de red se pueden cancelar desde la devolución de llamada de notificación de red.


.SH "INICIALIZACIÓN Y DESINICIALIZACIÓN DE LA BIBLIOTECA"


.PP Una aplicación libdatovka debe incluir el archivo de cabecera libdatovka/isds.h. La aplicación debe llamar a la función isds_init para inicializar la biblioteca antes de llamar a cualquier otra función de la biblioteca. Después de la última llamada a libdatovka, se debe llamar a la función isds_cleanup para limpiar algunos recursos globales y desinicializar las bibliotecas dependientes.


.SH "CONTEXTOS"


.PP La mayoría de las funciones operan sobre una conexión establecida con el servidor ISDS. Esto se llama un contexto y está representado por un puntero a una estructura opaca isds_ctx. La estructura mantiene el estado de la conexión de red, la autorización o los errores de la última llamada al contexto.


.PP El contexto se asigna mediante la función isds_ctx_create y se libera mediante la función isds_ctx_free.


.PP Hay más subtipos de contexto. Se asigna un subtipo específico al contexto cuando se pasa un contexto nuevo a una de las pocas funciones de estratificación (isds_login, czp_convert_document, isds_request_new_testing_box). Una vez que el contexto se especializa, solo se puede usar con funciones que entiendan el subtipo. Esto no lo impone la biblioteca ahora, pero no importa mucho porque todas las demás funciones asumen que se llamó a isds_login en el contexto. En otras palabras, no comparta el contexto entre las tres funciones de estratificación.


.PP Por ejemplo, cree un contexto con isds_ctx_create, luego llame a isds_login, luego trabaje con el buzón, luego llame a isds_logout. Aquí puede reutilizar el contexto e iniciar sesión como otro usuario llamando a isds_login nuevamente o destruir el contexto con isds_ctx_free si ya no lo necesita.


.PP O cree un contexto con isds_ctx_create, envíe un documento para conversión autorizada usando czp_convert_document, luego puede enviar más documentos para la conversión autorizada llamando nuevamente a czp_convert_document en el mismo contexto y finalmente destruya el contexto con isds_ctx_free.


.SH "ERRORES"


.PP La mayoría de las funciones devuelven un código de error de tipo isds_error. El valor IE_SUCCESS denota una llamada exitosa. Otros valores representan algún tipo de fallo.


.PP Puede usar la función isds_strerror para obtener una representación de cadena legible por humanos del código de error.


.PP Si falló una función con un argumento de contexto, puede usar la función isds_long_message para obtener un mensaje de error detallado. Tenga en cuenta que el valor devuelto solo dura hasta la próxima llamada al contexto.


.SH "CODIFICACIÓN DE CARACTERES"


.PP Todas las cadenas intercambiadas entre la biblioteca y la aplicación están codificadas en UTF-8. Aunque hay algunas excepciones:

•
Las funciones isds_strerror y isds_long_message devuelven una cadena codificada en la configuración regional.


.RE

•
isds_version devuelve una cadena codificada en la configuración regional.


.RE

•
La función de devolución de llamada de registro establecida por la función isds_set_log_callback se llama con un flujo de bytes sin procesar.


.RE

•
Los miembros de cadena de la estructura isds_pki_credentials tienen una codificación específica de la biblioteca criptográfica vinculada a la biblioteca cURL.


.RE


.SH "CONFIGURACIONES GLOBALES"


.PP Algunas funciones influyen en el comportamiento de la biblioteca globalmente. Estas son:

•
isds_init e isds_cleanup se utilizan para inicializar y desinicializar la biblioteca.


.RE

•
isds_set_logging y isds_set_log_callback para configurar el registro.


.RE


.SH "REGISTRO Y DEPURACIÓN"


.PP El registro es global para todas las llamadas a libdatovka. El nivel y la instalación del registro se pueden configurar con la función isds_set_logging.


.PP El registro se imprime en la salida de error estándar por defecto. La aplicación puede redirigir los mensajes a una función de devolución de llamada registrando la función de devolución de llamada con isds_set_log_callback.


.SH "ENTRADA/SALIDA DE RED"


.PP Algunas funciones que operan en un contexto crean sockets de red y realizan entrada y salida de red.


.PP El tiempo de espera de la red se puede establecer con la función isds_set_timeout. Las llamadas a funciones abortadas debido al tiempo de espera devolverán IE_TIMED_OUT.


.PP El progreso de la operación de red se puede monitorear mediante una función de devolución de llamada. La función de devolución de llamada se puede registrar usando la función isds_set_xferinfo_callback. La función de devolución de llamada registrada se llamará periódicamente con argumentos que declaran la cantidad de datos transferidos. El valor de retorno de la devolución de llamada determina si continuar la operación de red o cancelarla. Las funciones que fallan debido a la cancelación de la operación de red devolverán IE_ABORTED. La función de devolución de llamada ahora obsoleta isds_set_progress_callback se comporta de manera similar pero usa valores de punto flotante para pasar las cantidades de datos transferidos. Se desaconseja el uso de isds_set_progress_callback en código nuevo.


.SH "GESTIÓN DE MEMORIA"


.PP La biblioteca proporciona destructores para todas las estructuras de datos de libdatovka. Por ejemplo, la función isds_ctx_free acepta un puntero a un puntero a la estructura isds_ctx, libera la estructura de doble referencia (de forma recursiva), escribe NULL en el puntero al que se apunta (lo que invalida efectivamente el puntero) y no devuelve nada.


.PP Al realizar una llamada a una función, todos los argumentos de salida se reubican automáticamente al tamaño deseado. En caso de fallo de la función, todos los argumentos de salida se desasignan automáticamente y sus punteros se establecen en NULL. Las excepciones se documentan en las funciones correspondientes.


.PP Las cadenas de salida se asignan utilizando la llamada estándar malloc. La aplicación es responsable de su desasignación (en caso de no fallo y si no se especifica lo contrario). Use la llamada estándar free para las cadenas, use los destructores de libdatovka para las estructuras de libdatovka.


.SH "FUNCIONES, TIPOS Y CONSTANTES DISPONIBLES"


.PP Consulte el archivo de cabecera libdatovka/isds.h.
