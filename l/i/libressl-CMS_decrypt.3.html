libressl-CMS_decrypt(3)

Paquete: libressl

Licencias: ISC, custom:OpenSSL

CMS_DECRYPT(3) Manual de funciones de la biblioteca CMS_DECRYPT(3)

NOMBRE

CMS_decrypt, CMS_decrypt_set1_pkey, CMS_decrypt_set1_key — descifrar contenido de una estructura CMS EnvelopedData

SINOPSIS

biblioteca “libcrypto”
#include <openssl/cms.h>

int
CMS_decrypt(CMS_ContentInfo *cms, EVP_PKEY *private_key, X509 *certificate, BIO *dcont, BIO *out, unsigned int flags);

int
CMS_decrypt_set1_pkey(CMS_ContentInfo *cms, EVP_PKEY *private_key, X509 *certificate);

int
CMS_decrypt_set1_key(CMS_ContentInfo *cms, unsigned char *symmetric_key, size_t keylen, const unsigned char *id, size_t idlen);

DESCRIPCIÓN

CMS_decrypt() extrae y descifra el contenido de la estructura CMS EnvelopedData cms utilizando la private_key y el certificate del destinatario. Escribe el contenido descifrado en out.

En el raro caso de que el contenido comprimido esté separado, pásalo a través de dcont. Para uso normal, establezca dcont a NULL.

Aunque el certificate del destinatario no es necesario para descifrar los datos, sí lo es para localizar al destinatario apropiado (de entre posiblemente varios) en la estructura CMS.

Si el certificate se establece a NULL, se intentan todos los destinatarios posibles. Sin embargo, este caso es problemático. Para evitar el ataque MMA (ataque de Bleichenbacher contra el relleno RSA PKCS #1 v1.5), se intentan todos los destinatarios, tanto si tienen éxito como si no. Si ningún destinatario tiene éxito, se utiliza una clave simétrica aleatoria para descifrar el contenido: esto típicamente generará basura y puede (pero no se garantiza) devolver únicamente un error de relleno. Si CMS_decrypt() simplemente devolviera un error cuando todas las claves de destinatario cifradas fallaran al descifrarse, un atacante podría usar esto en un ataque de temporización. Si se establece la bandera especial CMS_DEBUG_DECRYPT, el comportamiento anterior se modifica y se devuelve un error si ninguna clave de destinatario cifrada puede descifrarse sin generar una clave de cifrado de contenido aleatoria. Las aplicaciones deben utilizar esta bandera con extrema precaución, especialmente en pasarelas automatizadas, ya que pueden quedar expuestas a ataques.

Es posible determinar la clave de destinatario correcta por otros medios (por ejemplo, buscándola en una base de datos) y establecerla en la estructura cms de antemano utilizando funciones de utilidad CMS como CMS_decrypt_set1_pkey(). En este caso, tanto certificate como private_key deben establecerse a NULL al llamar a CMS_decrypt() posteriormente.

Para procesar los tipos KEKRecipientInfo, se deben llamar a CMS_decrypt_set1_key() o a CMS_RecipientInfo_set0_key(3) y CMS_RecipientInfo_decrypt(3) antes de llamar a CMS_decrypt(), y certificate y private_key deben establecerse a NULL al llamar a CMS_decrypt() posteriormente.

Si el bit CMS_TEXT está establecido en flags, las cabeceras MIME para el tipo text/plain se eliminan del contenido. Si el contenido no es de tipo text/plain, se produce un error.

VALORES DE RETORNO

CMS_decrypt(), CMS_decrypt_set1_pkey(), y CMS_decrypt_set1_key() devuelven 1 en caso de éxito o 0 en caso de fallo. El error se puede obtener de ERR_get_error(3).

VER TAMBIÉN

CMS_ContentInfo_new(3), CMS_encrypt(3), CMS_get0_RecipientInfos(3)

ESTÁNDARES

RFC 5652: Cryptographic Message Syntax (CMS)

  • sección 6.1: Tipo EnvelopedData
  • sección 6.2.3: Tipo KEKRecipientInfo

HISTORIA

CMS_decrypt(), CMS_decrypt_set1_pkey(), y CMS_decrypt_set1_key() aparecieron por primera vez en OpenSSL 0.9.8h y han estado disponibles desde OpenBSD 6.7.

ERRORES

La falta de procesamiento en una sola pasada y la necesidad de mantener todos los datos en memoria, como se menciona en CMS_verify(3), también se aplican a CMS_decrypt().
