NOMBRE

libOpenCL, libOpenCL.so - Implementación OCL-ICD del cargador ICD de OpenCL

DESCRIPCIÓN

libOpenCL.so es la biblioteca enlazada por los programas OpenCL. No contiene ninguna implementación OpenCL en sí misma, sino que actúa como un despachador hacia implementaciones OpenCL reales proporcionadas como Controladores de Cliente Instalables de OpenCL (ICD). Un cargador ICD debería ser capaz de cargar ICDs proporcionados por cualquier proveedor.

Según las especificaciones OpenCL de Khronos (ver [Khronos]), el Cargador ICD busca archivos en el directorio /etc/OpenCL/vendors y, para cada archivo cuyo nombre termina en .icd, el Cargador ICD carga con dlopen(3) la biblioteca compartida cuyo nombre está en la primera línea del archivo .icd.

Cada nombre de biblioteca compartida en los archivos ".icd" puede tener su ruta, o puede ser un nombre de archivo simple. En este último caso, la biblioteca compartida ICD se buscará en las rutas estándar del cargador de bibliotecas dinámicas.

ENTORNO

Algunas variables de entorno pueden usarse para modificar el comportamiento predeterminado de libOpenCL.

OPENCL_VENDOR_PATH

Esta variable permite modificar la ruta predeterminada /etc/OpenCL/vendors. Es compatible con algunos otros cargadores ICD (pero no con todos, ya que la variable no es parte del estándar). Tenga en cuenta que $OCL_ICD_VENDORS (ver abajo) se usa con prioridad si está definido y no está vacío.

OCL_ICD_VENDORS

Esta variable permite cambiar la forma en que se buscan los ICD en el sistema. Se consideran varios casos:
1. Si $OCL_ICD_VENDORS es una ruta de directorio, entonces esta ruta reemplaza la ruta "/etc/OpenCL/vendors" en el comportamiento estándar: el cargador usará los archivos .icd en este directorio;
2. De lo contrario, si $OCL_ICD_VENDORS termina en .icd, libOpenCL.so solo cargará el ICD cuyo nombre de biblioteca compartida está escrito en el archivo ".icd" especificado;

Si no hay barras en $OCL_ICD_VENDORS, libOpenCL.so primero intentará usar /etc/OpenCL/vendors/$OCL_ICD_VENDORS (o $OPENCL_VENDOR_PATH/$OCL_ICD_VENDORS si OPENCL_VENDOR_PATH está definido). Si esto falla o si hay barras, utiliza $OCL_ICD_VENDORS (como una ruta de nombre de archivo relativa o absoluta).

3. De lo contrario, libOpenCL.so intentará cargar $OCL_ICD_VENDORS como la propia biblioteca compartida ICD (es decir, cargarlo directamente con dlopen(3)).

OPENCL_LAYERS

Esta variable permite especificar una lista de capas separadas por dos puntos para cargar, especificando sus rutas.

OPENCL_LAYER_PATH

Esta variable permite anular la ruta de búsqueda de capas del sistema predeterminada (/etc/OpenCL/layers).

OCL_ICD_ASSUME_ICD_EXTENSION

Si se establece en un valor no vacío, en contra de la especificación de Khronos, el cargador no verificará que los ICD cargados declaren la extensión cl_khr_icd. También utilizará clGetPlatformInfo de la tabla de despacho si no hay una función de este tipo disponible globalmente. Es posible que deba definir esta variable de entorno si está utilizando ICD no (completamente) compatibles, o si está utilizando el ICD de Intel junto con optirun(1). En este último caso, un error en el ICD de Intel hará que la aplicación falle.

Si se establece en el valor debug, se imprimirán mensajes adicionales en modo de depuración (ver OCL_ICD_DEBUG a continuación).

OCL_ICD_PLATFORM_SORT

Permite elegir la forma en que se ordenan las plataformas cuando se presentan a los programas a través de clGetPlatformIDs(3). Los algoritmos actualmente proporcionados son:
•devices: primero, lista las plataformas que admiten más GPU, luego más CPU y luego más aceleradores. Si OCL_ICD_PLATFORM_SORT no está configurado o está configurado con un valor desconocido, se utiliza este algoritmo.
•none: no se realiza ningún ordenamiento y el orden puede cambiar en cada ejecución.

OCL_ICD_DEFAULT_PLATFORM

Número de la plataforma a elegir como plataforma predeterminada. Tenga en cuenta que el uso de esta variable de entorno sin garantizar el uso de un algoritmo de ordenamiento para las plataformas no es realmente útil.

OCL_ICD_DEBUG

Si ocl-icd se ha compilado con soporte de depuración, puede establecer esta variable de entorno a un valor donde cada bit muestre algún tipo de información. Los valores definidos son:
•1: advertencias (habilitadas por defecto si el soporte de depuración está presente y OCL_ICD_DEBUG no está configurado)
•2: mensajes informativos
•4: entrada/salida para algunas funciones OpenCL
•8: volcado de la estructura interna de los ICD cargados

OCL_ICD_DEBUG es principalmente útil para el desarrollo de ocl-icd y/o para el desarrollo de ICD.
