NOMBRE

SSL_alert_type_string, SSL_alert_type_string_long, SSL_alert_desc_string, SSL_alert_desc_string_long — obtener descripción textual de la información de alerta

SINÓPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

const char *
SSL_alert_type_string(int valor);

const char *
SSL_alert_type_string_long(int valor);

const char *
SSL_alert_desc_string(int valor);

const char *
SSL_alert_desc_string_long(int valor);

DESCRIPCIÓN

SSL_alert_type_string() devuelve una cadena de una letra que indica el tipo de alerta especificada por valor.

SSL_alert_type_string_long() devuelve una cadena que indica el tipo de alerta especificada por valor.

SSL_alert_desc_string() devuelve una cadena de dos letras como forma corta que describe la razón de la alerta especificada por valor.

SSL_alert_desc_string_long() devuelve una cadena que describe la razón de la alerta especificada por valor.

Cuando un lado de una comunicación SSL/TLS quiere informar al par sobre una situación especial, envía una alerta. La alerta se envía como un mensaje especial y no influye en el flujo de datos normal (a menos que su contenido resulte en la cancelación de la comunicación).

Se envía una alerta de advertencia cuando ocurre una condición de error no fatal. La alerta "close notify" se envía como una alerta de advertencia. Otros ejemplos de errores no fatales son errores de certificado ("certificate expired", "unsupported certificate"), para los cuales se puede enviar una alerta de advertencia. (Sin embargo, la parte que envía puede decidir enviar un error fatal). El lado receptor puede cancelar la conexión al recibir una alerta de advertencia a su discreción.

Varios mensajes de alerta deben enviarse como mensajes de alerta fatales según lo especificado por las RFC de TLS. Una alerta fatal siempre conduce a un aborto de la conexión.

VALORES DE RETORNO

Las siguientes cadenas pueden ocurrir para SSL_alert_type_string() o SSL_alert_type_string_long():

"W"/"warning"
 
"F"/"fatal"
 
"U"/"unknown"
Esto indica que no hay soporte disponible para este tipo de alerta. Probablemente valor no contiene un mensaje de alerta correcto.

Las siguientes cadenas pueden ocurrir para SSL_alert_desc_string() o SSL_alert_desc_string_long():

"CN"/"close notify"
La conexión debe cerrarse. Esta es una alerta de advertencia.
"UM"/"unexpected message"
Se recibió un mensaje inapropiado. Esta alerta es siempre fatal y nunca debería observarse en la comunicación entre implementaciones correctas.
"BM"/"bad record mac"
Esta alerta se devuelve si se recibe un registro con un MAC incorrecto. Este mensaje es siempre fatal.
"DF"/"decompression failure"
La función de descompresión recibió una entrada incorrecta (por ejemplo, datos que se expandirían a una longitud excesiva). Este mensaje es siempre fatal.
"HF"/"handshake failure"
La recepción de un mensaje de alerta handshake_failure indica que el remitente no pudo negociar un conjunto aceptable de parámetros de seguridad dadas las opciones disponibles. Este es un error fatal.
"NC"/"no certificate"
Un cliente, al que se le pidió que enviara un certificado, no envía un certificado (solo SSLv3).
"BC"/"bad certificate"
Un certificado estaba corrupto, contenía firmas que no verificaron correctamente, etc.
"UC"/"unsupported certificate"
Un certificado era de un tipo no soportado.
"CR"/"certificate revoked"
Un certificado fue revocado por su firmante.
"CE"/"certificate expired"
Un certificado ha expirado o no es válido actualmente.
"CU"/"certificate unknown"
Surgió algún otro problema (no especificado) al procesar el certificado, haciéndolo inaceptable.
"IP"/"illegal parameter"
Un campo en el handshake estaba fuera de rango o inconsistente con otros campos. Esto es siempre fatal.
"DC"/"decryption failed"
Un TLSCiphertext se descifró de forma inválida: o no era un múltiplo par de la longitud del bloque o sus valores de relleno, cuando se verificaron, no eran correctos. Este mensaje es siempre fatal.
"RO"/"record overflow"
Se recibió un registro TLSCiphertext que tenía una longitud mayor que 2^14+2048 bytes, o un registro descifrado a un registro TLSCompressed con más de 2^14+1024 bytes. Este mensaje es siempre fatal.
"CA"/"unknown CA"
Se recibió una cadena de certificado válida o parcial, pero el certificado no fue aceptado porque no se pudo localizar el certificado CA o no se pudo corresponder con una CA conocida y confiable. Este mensaje es siempre fatal.
"AD"/"access denied"
Se recibió un certificado válido, pero cuando se aplicó el control de acceso, el remitente decidió no continuar con la negociación. Este mensaje es siempre fatal.
"DE"/"decode error"
Un mensaje no pudo ser decodificado porque algún campo estaba fuera del rango especificado o la longitud del mensaje era incorrecta. Este mensaje es siempre fatal.
"CY"/"decrypt error"
Una operación criptográfica de handshake falló, incluyendo la incapacidad de verificar correctamente una firma, descifrar un intercambio de claves o validar un mensaje final.
"ER"/"export restriction"
Se detectó una negociación que no cumplía con las restricciones de exportación; por ejemplo, intentar transferir una clave RSA efímera de 1024 bits para el método de handshake RSA_EXPORT. Este mensaje es siempre fatal.
"PV"/"protocol version"
La versión del protocolo que el cliente ha intentado negociar es reconocida, pero no soportada. (Por ejemplo, las versiones antiguas del protocolo pueden evitarse por razones de seguridad). Este mensaje es siempre fatal.
"IS"/"insufficient security"
Devuelto en lugar de handshake_failure cuando una negociación ha fallado específicamente porque el servidor requiere cifrados más seguros que los soportados por el cliente. Este mensaje es siempre fatal.
"IE"/"internal error"
Un error interno no relacionado con el par o la corrección del protocolo hace imposible continuar (como una falla en la asignación de memoria). Este mensaje es siempre fatal.
"IF"/"inappropriate fallback"
Enviado por un servidor en respuesta a un intento de reintento de conexión inválido por parte de un cliente (ver RFC 7507).
"US"/"user canceled"
Este handshake se está cancelando por alguna razón no relacionada con una falla del protocolo. Si el usuario cancela una operación después de que el handshake se ha completado, es más apropiado simplemente cerrar la conexión enviando un close_notify. A esta alerta debería seguirle un close_notify. Este mensaje es generalmente una advertencia.
"NR"/"no renegotiation"
Enviado por el cliente en respuesta a una solicitud de saludo o por el servidor en respuesta a un saludo de cliente después del handshake inicial. Cualquiera de estas opciones normalmente

NAME

SSL_alert_type_string, SSL_alert_desc_string - get string representation of SSL alert message type and description

SYNOPSIS

char *SSL_alert_type_string(int value);
char *SSL_alert_desc_string(int value);

DESCRIPTION

These functions are used to obtain a human readable string representation of the alert message type and description, respectively. The value argument is the numerical value of the alert message, which consists of two bytes: the first byte specifies the alert type (warning or fatal), and the second byte specifies the alert description.

The functions return a string literal. Do not modify the returned string.

The following alert types and descriptions are recognized:

"WR"/"warning"
The alert is a warning alert. This level of alert does not necessarily mean that the connection must be terminated. A renegotiation might be appropriate; when that is not appropriate, the recipient should respond with this alert; at that point, the original requester can decide whether to proceed with the connection. One case where this would be appropriate would be where a server has spawned a process to satisfy a request; the process might receive security parameters (key length, authentication, etc.) at startup and it might be difficult to communicate changes to these parameters after that point. This message is always a warning.
"FT"/"fatal"
The alert is a fatal alert. A fatal alert terminates the connection.
"RE"/"close notify"
Sent by either party to indicate that no more messages will be sent. This is a warning alert.
"BA"/"bad certificate"
A certificate is rejected due to the signature being invalid or the issuing CA being unknown.
"BE"/"bad certificate entity"
Indicates that a certificate has been rejected, but not necessarily because of its signature or issuer. This can be used for malformed certificates or certificates that are otherwise unusable.
"BP"/"bad certificate process"
A certificate could not be processed because of an unexpected internal error.
"CA"/"certificate expired"
A certificate has expired.
"CI"/"certificate is not yet valid"
A certificate is not yet valid.
"CM"/"certificate mismatch"
The certificate signing chain could not be verified because it contained references to certificate authorities that were not included in the trusted CA list.
"CN"/"common name mismatch"
The certificate presented by the peer does not match the name expected by the client or server.
"DE"/"decryption error"
A record was received that could not be decrypted.
"DI"/"decryption failed"
A record was received that could not be decrypted, and decryption failed.
"EC"/"export restriction"
An export restriction prohibited further use of a key.
"HA"/"handshake failure"
The handshake failed for an unspecified reason.
"ID"/"illegal parameter"
An inappropriate value was received in one of the TLS/SSL protocol messages.
"IP"/"internal error"
An internal error occurred.
"NA"/"no cert"
No certificate was presented by the peer.
"PE"/"peer error"
An error occurred on the peer.
"PL"/"protocol violation"
A protocol violation occurred.
"PN"/"peer not trusted"
The peer is not trusted.
"PO"/"post-handshake authentication failure"
An error occurred during post-handshake authentication.
"RA"/"ready for renegotiation"
The peer is ready for renegotiation. This is a warning alert.
"RA"/"request renegotiation"
Sent by a client to request renegotiation. This is a warning alert.
"RO"/"record overflow"
A record was received with a length greater than allowed by the protocol.
"SC"/"session cached"
The session was resumed successfully. This is a warning alert.
"SH"/"shutdown alert"
Received shutdown alert.
"SU"/"unsupported certificate"
An unsupported certificate type was received.
"UR"/"unrecognized name"
A certificate name was not recognized.
"UA"/"unsupported alert"
An unrecognized alert message was received.
"UP"/"unknown PSK identity"
Sent by the server to indicate that it does not recognize a PSK identity or an SRP identity.
"CQ"/"certificate required"
Sent by servers when a client certificate is desired but none was provided by the client.
"AP"/"no application protocol"
Sent by servers when a client ALPN extension advertises only protocols that the server does not support (see RFC 7301).
"UK"/"unknown"
This indicates that no description is available for this alert type. Probably value does not contain a correct alert message.
