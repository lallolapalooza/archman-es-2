LIBZIP(3) Manual de Funciones de Biblioteca LIBZIP(3)

NOMBRE

libzip — biblioteca para manipular archivos zip

BIBLIOTECA

libzip (-lzip)

SINOPSIS

#include <zip.h>

DESCRIPCIÓN

libzip es una biblioteca para leer, crear y modificar archivos zip.

Los principales criterios de diseño para libzip fueron:

  • Mantener una API estable sin romper la compatibilidad con versiones anteriores.
  • No crear archivos corruptos, incluso en caso de errores.
  • No eliminar datos.
  • Ser eficiente.

Por esta razón, al modificar archivos zip, libzip escribe en un archivo temporal y reemplaza el archivo zip original de forma atómica.

NOTAS GENERALES

Al agregar archivos a un archivo, los datos del archivo solo se leen cuando se escribe el nuevo archivo. Por lo tanto, todos los archivos agregados deben permanecer válidos hasta que el archivo se cierre con zip_close(3) o zip_discard(3).

A menos que se documente explícitamente, no se deben pasar punteros NULL como argumentos a las funciones.

TIPOS DE DATOS

Estos tipos de datos corresponden a conceptos centrales en libzip. La mayoría de ellos son privados, lo que significa que no puedes asignarlos ni acceder directamente a sus miembros. Esto permite extender las estructuras en el futuro sin romper la compatibilidad.

zip_t

Este tipo representa un archivo abierto. Ver zip(5).

zip_file_t

Este tipo representa un archivo de un archivo que se ha abierto para lectura. Ver zip_file(5).

zip_source_t

Este tipo representa una fuente (o destino) de datos. Se utiliza en libzip para proporcionar datos al agregar o reemplazar archivos, acceder a datos de un archivo dentro de un archivo y a los datos del archivo en su conjunto. Ver zip_source(5).

zip_error_t

Este tipo representa información sobre un error. Su tipo puede verificarse con constantes predefinidas y puede convertirse en una cadena legible por humanos. Ver zip_error(5).

NOMBRES DE ARCHIVO

Codificación

Se espera que los nombres de archivo en el sistema de archivos anfitrión estén en codificación UTF-8. En Windows, también hay variantes disponibles para ASCII y UTF-16.

Por defecto, se espera que los nombres de archivo dentro de los archivos estén en codificación UTF-8. Se pueden solicitar otras codificaciones utilizando las banderas ZIP_FL_ENC_CP437 y ZIP_FL_ENC_RAW.

Para más detalles, consulta las páginas de manual relevantes.

Separador de Directorio

El formato zip requiere el uso de la barra inclinada ( ‘/’) como separador de directorio. Dado que la barra invertida (‘\’) puede ser parte de un nombre de archivo válido en sistemas Unix, libzip no las convierte automáticamente, incluso en Windows. Es responsabilidad del programador asegurarse de que todos los separadores de directorio se pasen como barras inclinadas a libzip.

SEGURIDAD DE HILOS

En general, los diferentes archivos zip abiertos por libzip son independientes entre sí y pueden ser utilizados por hilos que se ejecutan en paralelo sin necesidad de bloqueo. Si quieres usar un archivo desde múltiples hilos, debes sincronizar el acceso a él tú mismo. Si utilizas un archivo como fuente para zip_file_add(3) o zip_file_replace(3), el acceso al archivo de destino también debe sincronizarse con el acceso al archivo de origen.
