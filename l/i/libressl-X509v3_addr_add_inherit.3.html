NOMBRE

X509v3_addr_add_inherit, X509v3_addr_add_prefix, X509v3_addr_add_range, X509v3_addr_canonize, X509v3_addr_is_canonical — Extensiones de delegación de direcciones IP RFC 3779

SINOPSIS

int

int
X509v3_addr_add_prefix(IPAddrBlocks *addrblocks, const unsigned afi, const unsigned *safi, unsigned char *prefix, const int prefixlen);

int
X509v3_addr_add_range(IPAddrBlocks *addrblocks, const unsigned afi, const unsigned *safi, unsigned char *min, unsigned char *max);

int
X509v3_addr_canonize(IPAddrBlocks *addrblocks);

int
X509v3_addr_is_canonical(IPAddrBlocks *addrblocks);

DESCRIPCIÓN

Un objeto IPAddrBlocks representa el contenido de una extensión de delegación de direcciones IP tal como se define en RFC 3779, sección 2.2.3.1. Contiene listas de prefijos de direcciones IP y rangos de direcciones IP delegados por el emisor al sujeto del certificado. Puede ser instanciado como se explica en la sección EJEMPLOS y sus internos se documentan en IPAddressRange_new(3).

Cada lista en un objeto IPAddrBlocks bien formado se identifica de forma única por un identificador de familia de direcciones (AFI) y un identificador opcional de familia de direcciones subordinada (SAFI). Las listas pueden estar ausentes o pueden contener un marcador de “heredar” para indicar que los recursos deben ser heredados de la lista correspondiente del certificado emisor.

Según la especificación, un AFI es un entero sin signo de 16 bits y un SAFI es un entero sin signo de 8 bits. Para IPv4 e IPv6 existen las constantes predefinidas IANA_AFI_IPV4 y IANA_AFI_IPV6, que deben ser los únicos valores utilizados para afi en esta API. En la práctica, safi es siempre NULL. afi se trunca silenciosamente a sus 16 bits inferiores y, si safi no es NULL, solo se utilizan los 8 bits inferiores del valor apuntado.

X509v3_addr_add_inherit() añade una lista con un marcador de “heredar” a addrblocks. Si ya existe una lista que corresponde a afi y safi, no ocurre ninguna acción si está marcada como “heredar”, de lo contrario, la llamada falla.

X509v3_addr_add_prefix() añade una representación interna recién asignada del prefijo de longitud prefixlen a la lista correspondiente a afi y el opcional safi en addrblocks. Si no existe dicha lista, se crea primero. Si la lista existe y está marcada como “heredar”, la llamada falla. Se espera que prefix sea un array de bytes en orden de red (network byte order). Debe apuntar a suficiente memoria para acomodar prefixlen bits y se recomienda que todos los bits no cubiertos por prefixlen estén establecidos en 0. Es responsabilidad del llamante asegurar que el prefijo no tenga ninguna dirección en común con ninguno de los prefijos o rangos ya presentes en la lista. Si afi es IANA_AFI_IPV4, prefixlen debe estar entre 0 y 32 (inclusive) y si afi es IANA_AFI_IPV6, prefixlen debe estar entre 0 y 128 (inclusive).

X509v3_addr_add_range() es similar a X509v3_addr_add_prefix() para el intervalo cerrado de direcciones IP entre min y max en presentación de red. Si afi es IANA_AFI_IPV4, min y max deben apuntar a 4 bytes de memoria y si afi es IANA_AFI_IPV6, min y max deben apuntar a 16 bytes de memoria. En caso de que el rango de direcciones IP entre min y max sea un prefijo, se añadirá un prefijo en lugar de un rango. Es responsabilidad del llamante asegurar que min sea menor o igual que max y que no contenga ninguna dirección ya presente en la lista. Si no se hace esto, se producirá un fallo posterior de X509v3_addr_canonize().

X509v3_addr_canonize() intenta poner el objeto no nulo addrblocks en forma canónica. Se dice que un objeto IPAddrBlocks está en forma canónica si se ajusta al orden especificado en RFC 3779: la sección 2.2.3.3 requiere que la lista de listas se ordene primero por AFI creciente y luego por SAFI creciente, donde NULL es el SAFI mínimo; la sección 2.2.3.6 requiere que cada lista esté en forma mínima y ordenada. El requisito de minimidad es que todos los prefijos y rangos adyacentes deben fusionarse en un único rango y que cada rango debe expresarse como un prefijo, si es posible. En particular, cada dirección dada puede estar en como máximo una entrada de lista. El orden es por dirección IP mínima creciente en orden de bytes de red.

X509v3_addr_is_canonical() indica si addrblocks está en forma canónica.

VALORES DE RETORNO

Todas estas funciones devuelven 1 en caso de éxito y 0 en caso de fallo. El fallo en la asignación de memoria es una razón posible para todas ellas. A veces, se puede obtener un código de error mediante ERR_get_error(3).

X509v3_addr_add_inherit() falla si la lista correspondiente a afi y el opcional safi ya existe y no está marcada como “heredar”.

X509v3_addr_add_prefix() y X509v3_addr_add_range() fallan si una lista correspondiente a afi y el opcional safi ya existe y está marcada como “heredar”, o si prefixlen está fuera del intervalo [0,32] para direcciones IPv4 o [0,128] para direcciones IPv6.

X509v3_addr_canonize() falla si una de las listas en addrblocks está mal formada, en particular si contiene entradas corruptas, superpuestas o duplicadas. La corrupción incluye rangos donde max es estrictamente menor que min. Las condiciones de error son generalmente indistinguibles.

X509v3_addr_is_canonical() devuelve 1 si addrblocks está en forma canónica. Un valor de retorno de 0 puede indicar forma no canónica o una lista corrupta.

Implementar la API pública faltante d2i_IPAddrBlocks() y i2d_IPAddrBlocks() usando ASN1_item_d2i(3):

IPAddrBlocks *
d2i_IPAddrBlocks(IPAddrBlocks **addrblocks, const unsigned char **in,
    long len)
{
	const X509V3_EXT_METHOD *v3_addr;

	if ((v3_addr = X509V3_EXT_get_nid(NID_sbgp_ipAddrBlock)) == NULL)
		return NULL;
	return (IPAddrBlocks *)ASN1_item_d2i((ASN1_VALUE **)addrblocks,
	    in, len, ASN1_ITEM_ptr(v3_addr->it));
}

int
i2d_IPAddrBlocks(IPAddrBlocks *addrblocks, unsigned char **out)
{
	const X509V3_EXT_METHOD *v3_addr;

	if ((v3_addr = X509V3_EXT_get_nid(NID_sbgp_ipAddrBlock)) == NULL)
		return -1;
	return ASN1_item_i2d((ASN1_VALUE *)addrblocks, out,
	    ASN1_ITEM_ptr(v3_addr->it));
}

El uso de la macro no documentada ASN1_ITEM_ptr() es necesario si se desea compatibilidad con versiones modernas de otras implementaciones.

HISTORIAL

Estas funciones aparecieron por primera vez en OpenSSL 0.9.8e y han estado disponibles desde OpenBSD 7.1.

ERRORES

IPAddrBlocks_new(), IPAddrBlocks_free(), d2i_IPAddrBlocks() y i2d_IPAddrBlocks() no existen y IPAddrBlocks_it no es público. Los ejemplos anteriores muestran cómo implementar las cuatro funciones faltantes con la API pública.

X509v3_addr_add_range() debería verificar los límites del rango invertidos y las superposiciones al insertar y fallar en lugar de crear un addrblocks sin sentido que no pueda ser canonizado por X509v3_addr_canonize().

Si se pasa NULL a X509v3_asid_canonize(3), se ejecuta correctamente. X509v3_addr_is_canonical() considera NULL como un IPAddrBlocks canónico. En contraste, X509v3_addr_canonize() falla con una desreferencia de NULL.

El código solo soporta los AFI IPv4 e IPv6. Esto no se aplica de manera consistente en todas las implementaciones.

X509v3_addr_add_range() no logra borrar los bits no utilizados establecidos en 1 en el último octeto de la representación ASN1_BIT_STRING de max. Esto confunde a algunos programas.
