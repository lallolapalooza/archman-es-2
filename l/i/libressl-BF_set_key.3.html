BF_SET_KEY(3) Manual de Funciones de Librería BF_SET_KEY(3)

NOMBRE

BF_set_key, BF_encrypt, BF_decrypt, BF_ecb_encrypt, BF_cbc_encrypt, BF_cfb64_encrypt, BF_ofb64_encrypt — cifrado Blowfish

SINOPSIS

librería “libcrypto”
#include <openssl/blowfish.h>

void
BF_set_key(BF_KEY *key, int len, const unsigned char *data);

void
BF_encrypt(BF_LONG *data, const BF_KEY *key);

void
BF_decrypt(BF_LONG *data, const BF_KEY *key);

void
BF_ecb_encrypt(const unsigned char *in, unsigned char *out, BF_KEY *key, int enc);

void
BF_cbc_encrypt(const unsigned char *in, unsigned char *out, long length, BF_KEY *schedule, unsigned char *ivec, int enc);

void
BF_cfb64_encrypt(const unsigned char *in, unsigned char *out, long length, BF_KEY *schedule, unsigned char *ivec, int *num, int enc);

void
BF_ofb64_encrypt(const unsigned char *in, unsigned char *out, long length, BF_KEY *schedule, unsigned char *ivec, int *num);

DESCRIPCIÓN

Esta librería implementa el cifrado Blowfish, que fue inventado y definido por Counterpane. Nótese que las aplicaciones deberían usar funciones de alto nivel como EVP_EncryptInit(3) en lugar de llamar directamente a las funciones Blowfish.

Blowfish es un cifrado de bloque que opera sobre bloques de datos de 64 bits (8 bytes). Usa una clave de tamaño variable, pero típicamente, las claves de 128 bits (16 bytes) se consideran buenas para un cifrado fuerte. Blowfish puede usarse en los mismos modos que DES y actualmente es uno de los cifrados de bloque más rápidos. Es bastante más rápido que DES, y mucho más rápido que IDEA o RC2.

Blowfish consta de una fase de configuración de clave y la fase de cifrado o descifrado real.

BF_set_key() configura la BF_KEY key usando los len bytes de longitud de la clave en data.

BF_ecb_encrypt() es la función básica de cifrado y descifrado de Blowfish. Cifra o descifra los primeros 64 bits de in usando la clave key, colocando el resultado en out. enc decide si se debe realizar cifrado (BF_ENCRYPT) o descifrado (BF_DECRYPT). El vector apuntado por in y out debe tener una longitud de 64 bits, no menos. Si son más grandes, se ignora todo lo que esté después de los primeros 64 bits.

Las funciones de modo BF_cbc_encrypt(), BF_cfb64_encrypt(), y BF_ofb64_encrypt() operan sobre datos de longitud variable. Todas toman un vector de inicialización ivec que debe pasarse en la siguiente llamada de la misma función para el mismo mensaje. ivec puede inicializarse con cualquier cosa, pero el destinatario necesita saber con qué se inicializó, o no podrá descifrar. Algunos programas y protocolos lo simplifican, como SSH, donde ivec simplemente se inicializa a cero. BF_cbc_encrypt() opera sobre datos que son un múltiplo de 8 bytes de longitud, mientras que BF_cfb64_encrypt() y BF_ofb64_encrypt() se usan para cifrar un número variable de bytes (la cantidad no tiene que ser un múltiplo exacto de 8). El propósito de los dos últimos es simular cifrados de flujo y, por lo tanto, necesitan el parámetro num, que es un puntero a un entero donde se almacena el desplazamiento actual en ivec entre llamadas. Este entero debe inicializarse a cero cuando se inicializa ivec.

BF_cbc_encrypt() es la función Cipher Block Chaining para Blowfish. Cifra o descifra los fragmentos de 64 bits de in usando la clave schedule, colocando el resultado en out. enc decide si se debe realizar cifrado (BF_ENCRYPT) o descifrado (BF_DECRYPT). ivec debe apuntar a un vector de inicialización de 8 bytes.

BF_cfb64_encrypt() es el modo CFB para Blowfish con retroalimentación de 64 bits. Cifra o descifra los bytes en in usando la clave schedule, colocando el resultado en out. enc decide si se debe realizar cifrado (BF_ENCRYPT) o descifrado (BF_DECRYPT). ivec debe apuntar a un vector de inicialización de 8 bytes. num debe apuntar a un entero que debe inicializarse a cero.

BF_ofb64_encrypt() es el modo OFB para Blowfish con retroalimentación de 64 bits. Usa los mismos parámetros que BF_cfb64_encrypt(), que deben inicializarse de la misma manera.

BF_encrypt() y BF_decrypt() son las funciones de nivel más bajo para el cifrado Blowfish. Cifran/descifran los primeros 64 bits del vector apuntado por data, usando la clave key. Estas funciones no deben usarse a menos que se implementen `modos' de Blowfish. La alternativa es usar BF_ecb_encrypt(). Tenga en cuenta que estas funciones toman cada fragmento de 32 bits en orden de bytes del host, que es little-endian en plataformas little-endian y big-endian en plataformas big-endian.

HISTORIA

BF_set_key(), BF_encrypt(), BF_ecb_encrypt(), BF_cbc_encrypt(), BF_cfb64_encrypt(), y BF_ofb64_encrypt() aparecieron por primera vez en SSLeay 0.6.6. BF_decrypt() apareció por primera vez en SSLeay 0.9.0. Todas estas funciones han estado disponibles desde OpenBSD 2.4.
