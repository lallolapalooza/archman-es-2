DESCRIPCIÓN

La mayoría de estas funciones se llaman típicamente después de X509_verify_cert(3) para inspeccionar la información de estado relacionada con la verificación de certificados. Algunas también pueden ser llamadas en una función de devolución de llamada de verificación para determinar la naturaleza de un error.

X509_STORE_CTX_get_error() devuelve el código de error de ctx. Consulte la sección CÓDIGOS DE ERROR para obtener una descripción completa de todos los códigos de error.

X509_STORE_CTX_set_error() establece el código de error de ctx a s. Por ejemplo, podría usarse en una función de devolución de llamada de verificación para establecer un error basado en verificaciones adicionales.

X509_STORE_CTX_get_error_depth() devuelve la profundidad del error. Este es un entero no negativo que representa dónde ocurrió el error en la cadena de certificados. Si es cero, ocurrió en el certificado de entidad final, uno si es el certificado que firmó el certificado de entidad final, y así sucesivamente.

X509_STORE_CTX_set_error_depth() establece la profundidad del error. Esto se puede usar en combinación con X509_STORE_CTX_set_error() para establecer la profundidad a la que se detectó una condición de error.

X509_STORE_CTX_get_current_cert() devuelve el certificado en ctx que causó el error o NULL si no hay ningún certificado relevante.

X509_STORE_CTX_set_current_cert() establece el certificado que causó el error en ctx al cert dado. Este valor no está destinado a permanecer válido durante mucho tiempo y sigue siendo propiedad del llamador. Puede ser examinado por una función de devolución de llamada de verificación invocada para manejar cada error encontrado durante la verificación de la cadena y ya no se requiere después de dicha devolución de llamada. Si una devolución de llamada desea guardar el certificado para usarlo después de que regrese, necesita incrementar su recuento de referencias mediante X509_up_ref(3). Una vez que dicho certificado guardado ya no sea necesario, se puede liberar con X509_free(3).

X509_STORE_CTX_get0_current_issuer() devuelve el certificado que causó que la validación del emisor fallara o NULL si no hay un certificado de CA relevante.

X509_STORE_CTX_get0_current_crl() devuelve la lista de revocación de certificados que causó que la verificación de CRL fallara o NULL si no hay una CRL relevante.

Cuando, durante la validación de la ruta de certificación, surge la necesidad de verificar la validez de la ruta de certificación de un certificado emisor de CRL, la biblioteca crea un nuevo objeto X509_STORE_CTX temporal. Si se llama a X509_STORE_CTX_get0_parent_ctx() en ese objeto temporal, se devuelve un puntero al contexto de validación de ruta de certificación original. Esto puede ser útil en funciones de devolución de llamada invocadas desde X509_verify_cert(3) o desde sus subrutinas para averiguar si la devolución de llamada se llama desde la validación de ruta del certificado de destino o desde la validación de ruta de un certificado emisor de CRL relacionado, y si es lo último, cuál es el certificado de destino.

X509_STORE_CTX_get0_chain() devuelve un puntero interno a una cadena de validación completa si una llamada anterior a X509_verify_cert(3) fue exitosa. Si la llamada a X509_verify_cert(3) no fue exitosa, la cadena devuelta puede estar incompleta o ser inválida. X509_STORE_CTX_get_chain() es un alias obsoleto de X509_STORE_CTX_get0_chain(). X509_STORE_CTX_get1_chain() devuelve una copia profunda de la misma cadena que persiste incluso después de que se libera la estructura ctx. Cuando ya no se necesite, debe liberarse usando sk_X509_pop_free(3).

X509_STORE_CTX_set0_verified_chain() establece la cadena de verificación para ctx al chain dado. La propiedad de la cadena se transfiere a ctx, y ctx ahora es responsable de liberarla. Esta función puede ser útil para reemplazar la cadena calculada por X509_verify_cert(3) con una cadena calculada externamente que el llamador desea que se considere como el resultado de la verificación.

X509_verify_cert_error_string() devuelve una cadena legible por humanos que describe el código de error n. Los códigos de error son los definidos en el archivo de inclusión <openssl/x509_vfy.h>.

VALORES DEVUELTOS

X509_STORE_CTX_get_error(), X509_STORE_CTX_get_error_depth(), y X509_STORE_CTX_get_num_untrusted() devuelven los valores correspondientes.

X509_STORE_CTX_get_current_cert(), X509_STORE_CTX_get0_current_issuer(), y X509_STORE_CTX_get0_current_crl() devuelven punteros a objetos X509 o X509_CRL, o NULL.

X509_STORE_CTX_get0_parent_ctx() devuelve un puntero a un X509_STORE_CTX, o NULL.

X509_STORE_CTX_get0_chain() y X509_STORE_CTX_get_chain() devuelven un puntero a un STACK_OF(X509). No se debe modificar la cadena devuelta.

X509_STORE_CTX_get1_chain() devuelve un puntero a un STACK_OF(X509) que es una copia de la cadena de verificación. El llamador es responsable de liberar la cadena devuelta usando sk_X509_pop_free(3).

X509_verify_cert_error_string() devuelve un puntero a una cadena de caracteres constante que describe el error.

DESCRIPTION

The certificate verification functions are used to verify a certificate chain against a set of trusted certificates. The structure X509_STORE_CTX holds the context for the verification process. The functions described here provide access to various aspects of the verification context.

X509_STORE_CTX_set0_verified_chain() frees the verified chain generated by a previous call to X509_verify_cert(3), if any, and replaces it with the given chain. Ownership of the chain is transferred to the ctx, so it should not be freed by the caller.

X509_STORE_CTX_get0_verified_chain() returns the verified chain that was set using X509_STORE_CTX_set0_verified_chain().

X509_STORE_CTX_get0_chain() returns the chain of certificates being verified. This is the chain that was passed into X509_verify_cert(3).

X509_STORE_CTX_get_chain() is similar to X509_STORE_CTX_get0_chain() but returns a non-const pointer. This can be used to modify the chain, for example, by sorting it. However, note that modifying the chain may invalidate the verification results.

X509_STORE_CTX_get1_chain() returns a duplicate of the chain of certificates being verified. The caller is responsible for freeing the returned stack using sk_free(3).

X509_STORE_CTX_set_verify_depth() sets the maximum verification depth for the context ctx to depth.

X509_STORE_CTX_get_verify_depth() returns the maximum verification depth for the context ctx.

X509_STORE_CTX_set_depth() sets the current verification depth for the context ctx to depth. This is typically used internally by the verification functions.

X509_STORE_CTX_get_depth() returns the current verification depth for the context ctx.

X509_STORE_CTX_get_error() returns the current verification error code.

X509_STORE_CTX_get_error_depth() returns the depth of the certificate in the chain that caused the current error.

X509_STORE_CTX_set_error() sets the current verification error code.

X509_STORE_CTX_set_error_depth() sets the current verification error depth.

X509_STORE_CTX_get_current_cert() returns the certificate currently being processed during verification. This can be NULL if no certificate is currently being processed (e.g., at the beginning of verification).

X509_STORE_CTX_set0_current_cert() sets the current certificate being processed. Ownership of the certificate is transferred to the context.

X509_STORE_CTX_get0_current_issuer() returns the issuer certificate of the current certificate being processed. This is the certificate that is being used to verify the signature of the current certificate.

X509_STORE_CTX_get0_parent_ctx() returns the parent verification context. This is used when verifying a CRL issuer certificate. In this case, a child context is created for verifying the CRL issuer, and this function returns the context for verifying the main certificate chain.

X509_STORE_CTX_get0_policy_tree() returns the policy tree used during verification. The second argument i will be set to the number of policy levels.

X509_STORE_CTX_get0_CRL() returns the CRL that is currently being processed.

X509_STORE_CTX_get0_trusted_obj() returns the trusted object (e.g. certificate or CRL) that caused the current error.

X509_STORE_CTX_get0_untrusted() returns the stack of untrusted certificates that were used in building the chain.

X509_STORE_CTX_get_num_untrusted() returns the number of untrusted certificates that were used in building the chain during a call to X509_verify_cert(3).

X509_STORE_CTX_get0_check_issued() returns the parameters used for checking if a certificate was issued by another certificate.

X509_STORE_CTX_get0_check_policy() returns the parameters used for checking certificate policies.

X509_STORE_CTX_verify_cert() performs the actual certificate chain verification. It uses the settings within the ctx to perform the verification.

X509_STORE_CTX_verify_cert_chain() is similar to X509_STORE_CTX_verify_cert() but is intended for use when building the chain is handled separately. It verifies the chain passed into the context.

X509_verify_cert() is a convenience function that creates a new verification context, sets it up with the provided parameters, performs the verification, and then frees the context. It is equivalent to calling X509_STORE_CTX_new(3), setting the parameters using the various X509_STORE_CTX_set...() functions, calling X509_STORE_CTX_verify_cert(), and then calling X509_STORE_CTX_free(3).

X509_STORE_CTX_free() frees the verification context ctx. Any certificates or other objects contained within the context that were allocated by the context itself will also be freed. Note that objects passed into the context via functions like X509_STORE_CTX_set0_verified_chain(3) are not freed unless ownership is explicitly transferred.

sk_X509_pop_free(chain, X509_free).

X509_STORE_CTX_set0_verified_chain() frees the validate chain generated by if a previous call to X509_verify_cert(3), if any, and replaces it with the given chain. Ownership of the chain is transferred to the ctx, so it should not be freed by the caller.

X509_verify_cert_error_string() returns a human readable error string for verification error n.

X509_VERIFY_CTX The above functions should be used instead of directly referencing the fields in the X509_VERIFY_CTX structure.

In versions of OpenSSL before 1.0, the current certificate returned by X509_STORE_CTX_get_current_cert() was never NULL. Applications should check the return value before printing out any debugging information relating to the current certificate.

If an unrecognised error code is passed to X509_verify_cert_error_string(), "Unknown certificate verification error" is returned. This should never happen unless an invalid code is passed.

RETURN VALUES

X509_STORE_CTX_get_error() returns X509_V_OK or an error code.

X509_STORE_CTX_get_error_depth() returns a non-negative error depth.

X509_STORE_CTX_get_current_cert(), X509_STORE_CTX_get0_current_issuer(), and X509_STORE_CTX_get0_CRL() return the object which caused the error or NULL if no object of the requested kind is relevant to the error.

X509_STORE_CTX_get0_parent_ctx() returns the parent context or NULL if ctx is not a temporary child context used for path validation of a CRL issuer certificate.

X509_STORE_CTX_get_num_untrusted() returns the number of untrusted certificates that were used in building the chain during a call to X509_verify_cert(3).

X509_STORE_CTX_get0_chain(), X509_STORE_CTX_get_chain(), and X509_STORE_CTX_get1_chain() return a pointer to a stack of certificates or NULL if an error occurs.

X509_verify_cert_error_string() returns a human readable error string for verification error n.

ERROR CODES

A list of error codes and messages is shown below. Some of the error codes are defined but currently never returned: these are described as "unused".

X509_V_OK: ok
The operation was successful.
X509_V_ERR_UNSPECIFIED: Unspecified certificate verification error
An error was encountered during certificate verification and the internal routines failed to set a more specific error.
X509_V_ERR_UNABLE_TO_GET_ISSUER_CERT: unable to get issuer certificate
The issuer certificate of a locally looked up certificate could not be found. This normally means the list of trusted certificates is not complete.
X509_V_ERR_UNABLE_TO_GET_CRL: unable to get certificate CRL
The CRL of a certificate could not be found.
X509_V_ERR_UNABLE_TO_DECRYPT_CERT_SIGNATURE: unable to decrypt certificate's signature
The certificate signature could not be decrypted. This means that the actual signature value could not be determined rather than it not matching the expected value. This is only meaningful for RSA keys.
X509_V_ERR_UNABLE_TO_DECRYPT_CRL_SIGNATURE: unable to decrypt CRL's signature
The CRL signature could not be decrypted: this means that the actual signature value could not be determined rather than it not matching the expected value. Unused.

X509_V_ERR_CERT_SIGNATURE_FAILURE: certificate signature failure

NAME

X509_STORE_CTX_get_error, X509_STORE_CTX_set_error, X509_STORE_CTX_get_error_depth, X509_STORE_CTX_set_depth, X509_STORE_CTX_get_current_cert, X509_STORE_CTX_set_current_cert, X509_STORE_CTX_get_num_untrusted, X509_STORE_CTX_set0_verified_chain — get and set certificate verification context error information

SYNOPSIS

#include <openssl/x509_vfy.h>

int X509_STORE_CTX_get_error(X509_STORE_CTX *ctx);
void X509_STORE_CTX_set_error(X509_STORE_CTX *ctx, int error);
int X509_STORE_CTX_get_error_depth(X509_STORE_CTX *ctx);
void X509_STORE_CTX_set_depth(X509_STORE_CTX *ctx, int depth);
X509 *X509_STORE_CTX_get_current_cert(X509_STORE_CTX *ctx);
void X509_STORE_CTX_set_current_cert(X509_STORE_CTX *ctx, X509 *cert);
int X509_STORE_CTX_get_num_untrusted(X509_STORE_CTX *ctx);
int X509_STORE_CTX_set0_verified_chain(X509_STORE_CTX *ctx, STACK_OF(X509) *chain);

DESCRIPTION

The verification process, performed by X509_verify_cert(), uses an X509_STORE_CTX structure to hold all the state. The functions described here allow access to and modification of some of this state.

X509_STORE_CTX_get_error() returns the error code from the last verification operation. This is usually an error code from the ERR_R_NESTED_ASN1_ERROR list, or a specific certificate verification error code defined in <openssl/x509.h>.

X509_STORE_CTX_set_error() sets the error code in the context. This function is mainly intended for internal use by OpenSSL, but could be used by callbacks.

X509_STORE_CTX_get_error_depth() returns the current depth in the certificate chain being verified. The depth of the end-entity certificate is 0. The depth of the issuer of the end-entity certificate is 1, and so on.

X509_STORE_CTX_set_depth() sets the maximum depth allowed for verification. The default is usually 5.

X509_STORE_CTX_get_current_cert() returns the certificate currently being verified.

X509_STORE_CTX_set_current_cert() sets the certificate currently being verified. This is mostly for internal use.

X509_STORE_CTX_get_num_untrusted() returns the number of untrusted certificates in the chain. These are certificates that were not found in the trust store, but are otherwise valid. This is typically the end-entity certificate and any intermediate certificates.

X509_STORE_CTX_set0_verified_chain() sets the chain of verified certificates in the context. The passed chain becomes owned by the context. This function is typically used internally by OpenSSL after a successful verification.

RETURN VALUES

X509_STORE_CTX_get_error() returns an integer representing the error code. A return value of 0 usually indicates success.

X509_STORE_CTX_get_error_depth() returns the current depth.

X509_STORE_CTX_get_current_cert() returns a pointer to the current certificate, or NULL if none is set.

X509_STORE_CTX_get_num_untrusted() returns the number of untrusted certificates.

X509_STORE_CTX_set0_verified_chain() returns 1 on success and 0 on failure.
