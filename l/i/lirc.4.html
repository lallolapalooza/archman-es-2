lirc(4) Manual de Controladores de Dispositivos lirc(4)

NOMBRE

lirc - dispositivos lirc

DESCRIPCIÓN

Los dispositivos de caracteres /dev/lirc* proporcionan una interfaz bidireccional de bajo nivel para controles remotos de infrarrojos (IR). La mayoría de estos dispositivos pueden recibir y algunos pueden enviar. Al recibir o enviar datos, el controlador funciona en dos modos diferentes dependiendo del hardware subyacente.

Algunos hardware (típicamente tarjetas de TV) decodifican la señal IR internamente y proporcionan pulsaciones de botones decodificadas como valores de códigos de escaneo. Los controladores para este tipo de hardware funcionan en modo LIRC_MODE_SCANCODE. Dicho hardware generalmente no soporta el envío de señales IR. Además, dicho hardware solo puede decodificar un conjunto limitado de protocolos IR, generalmente solo el protocolo del control remoto específico que se incluye con, por ejemplo, una tarjeta de TV.

Otro hardware proporciona un flujo de duraciones de pulso/espacio. Dichos controladores funcionan en modo LIRC_MODE_MODE2. Dicho hardware se puede utilizar con (casi) cualquier tipo de control remoto. Este tipo de hardware también se puede usar en modo LIRC_MODE_SCANCODE, en cuyo caso los decodificadores IR del kernel decodificarán el IR. Estos decodificadores se pueden escribir en BPF extendido (ver bpf(2)) y conectarse al dispositivo lirc. A veces, este tipo de hardware también soporta el envío de datos IR.

La llamada a ioctl LIRC_GET_FEATURES (ver más abajo) permite sondear si la recepción y el envío son compatibles, y en qué modos, entre otras características.

Lectura de entrada en modo LIRC_MODE_MODE2

En el modo LIRC_MODE_MODE2, los datos devueltos por read(2) proporcionan valores de 32 bits que representan una duración de espacio o pulso. El tiempo de la duración (microsegundos) está codificado en los 24 bits inferiores. Pulso (también conocido como destello) indica una duración de luz infrarroja detectada, y espacio (también conocido como brecha) indica una duración sin infrarrojos. Si la duración del espacio excede el tiempo de inactividad, se entrega un paquete especial de tiempo de espera, que marca el final de un mensaje. Los 8 bits superiores indican el tipo de paquete:

LIRC_MODE2_SPACE
El valor refleja una duración de espacio (microsegundos).
LIRC_MODE2_PULSE
El valor refleja una duración de pulso (microsegundos).
LIRC_MODE2_FREQUENCY
El valor refleja una frecuencia (Hz); ver la llamada a ioctl LIRC_SET_MEASURE_CARRIER_MODE.
LIRC_MODE2_TIMEOUT
El valor refleja una duración de espacio (microsegundos). El paquete refleja un tiempo de espera; ver la llamada a ioctl LIRC_SET_REC_TIMEOUT_REPORTS.
LIRC_MODE2_OVERFLOW
El receptor IR encontró un desbordamiento y, como resultado, faltan datos (desde Linux 5.18).

Lectura de entrada en modo LIRC_MODE_SCANCODE

En el modo LIRC_MODE_SCANCODE, los datos devueltos por read(2) reflejan pulsaciones de botones decodificadas, en la estructura lirc_scancode. El código de escaneo se almacena en el campo scancode, y el protocolo IR se almacena en rc_proto. Este campo tiene uno de los valores de la enumeración rc_proto.

Escritura de salida en modo LIRC_MODE_PULSE

Los datos escritos en el dispositivo de caracteres usando write(2) son una secuencia de pulsos/espacios de valores enteros. Los pulsos y espacios solo se marcan implícitamente por su posición. Los datos deben comenzar y terminar con un pulso, por lo tanto, siempre deben incluir un número impar de muestras. La función write(2) se bloquea hasta que los datos han sido transmitidos por el hardware. Si se proporcionan más datos de los que el hardware puede enviar, la llamada write(2) falla con el error EINVAL.

Escritura de salida en modo LIRC_MODE_SCANCODE

Los datos escritos en los dispositivos de caracteres deben ser una única estructura lirc_scancode. Los campos scancode y rc_proto deben estar rellenados; todos los demás campos deben ser 0. Los codificadores IR del kernel convertirán el código de escaneo en pulsos y espacios. El protocolo o el código de escaneo no son válidos, o el dispositivo lirc no puede transmitir.

COMANDOS IOCTL

#include <linux/lirc.h>    /* Pero ver BUGS */
int ioctl(int fd, int cmd, int *val);

Las siguientes operaciones ioctl(2) son proporcionadas por el dispositivo de caracteres lirc para sondear o cambiar la configuración específica del hardware lirc.

Comandos Siempre Soportados

Los dispositivos /dev/lirc* siempre soportan los siguientes comandos:

LIRC_GET_FEATURES (void)
Devuelve una máscara de bits de características combinadas; ver FEATURES.

Si un dispositivo devuelve un código de error para LIRC_GET_FEATURES, es seguro asumir que no es un dispositivo lirc.

Comandos Opcionales

Algunos dispositivos lirc soportan los comandos listados a continuación. A menos que se indique lo contrario, estos fallan con el error ENOTTY si la operación no es compatible, o con el error EINVAL si la operación falló o se proporcionaron argumentos inválidos. Si un controlador no anuncia soporte para ciertas características, la invocación de los ioctls correspondientes fallará con el error ENOTTY.

LIRC_GET_REC_MODE (void)
Si el dispositivo lirc no tiene receptor, esta operación falla con el error ENOTTY. De lo contrario, devuelve el modo de recepción, que será uno de:
LIRC_MODE_MODE2
El controlador devuelve una secuencia de duraciones de pulso/espacio.
LIRC_MODE_SCANCODE
El controlador devuelve valores de la estructura lirc_scancode, cada uno de los cuales representa una pulsación de botón decodificada.
LIRC_SET_REC_MODE (int)
Establece el modo de recepción. val es LIRC_MODE_SCANCODE o LIRC_MODE_MODE2. Si el dispositivo lirc no tiene receptor, esta operación falla con el error ENOTTY.
LIRC_GET_SEND_MODE (void)
Devuelve el modo de envío. Se soporta LIRC_MODE_PULSE o LIRC_MODE_SCANCODE. Si el dispositivo lirc no puede enviar, esta operación falla con el error ENOTTY.
LIRC_SET_SEND_MODE (int)
Establece el modo de envío. val es LIRC_MODE_SCANCODE o LIRC_MODE_PULSE. Si el dispositivo lirc no puede enviar, esta operación falla con el error ENOTTY.
LIRC_SET_SEND_CARRIER (int)
Establece la frecuencia de modulación. El argumento es la frecuencia (Hz).
LIRC_SET_SEND_DUTY_CYCLE (int)
Establece el ciclo de trabajo del portador. val es un número en el rango [0,100] que describe el ancho del pulso como un porcentaje del ciclo total. Actualmente, no se define ningún significado especial para 0 o 100, pero los valores están reservados para uso futuro.
