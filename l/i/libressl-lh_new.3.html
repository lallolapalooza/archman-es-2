DESCRIPCIÓN

Esta biblioteca implementa tablas hash dinámicas con tipos verificados. Las entradas de la tabla hash pueden ser estructuras arbitrarias. Normalmente consisten en campos de clave y valor.

lh_<tipo>_new() crea una nueva estructura LHASH_OF(<tipo>) para almacenar entradas de datos arbitrarias, y proporciona las funciones de devolución de llamada hash y comparación que se utilizarán en la organización de las entradas de la tabla. La función de devolución de llamada hash toma un puntero a una entrada de tabla como argumento y devuelve un valor hash de 32 bits sin signo para su campo de clave. El valor hash normalmente se trunca a una potencia de 2, así que asegúrese de que su función hash devuelva bits de orden inferior bien mezclados. La función de devolución de llamada de comparación toma dos argumentos (punteros a dos entradas de tabla hash) y devuelve 0 si sus claves son iguales, y distinto de cero en caso contrario. Si su tabla hash contendrá elementos de algún tipo particular y las funciones de devolución de llamada hash y comparación para estos tipos, entonces las macros DECLARE_LHASH_HASH_FN() y IMPLEMENT_LHASH_COMP_FN() pueden usarse para crear envoltorios de función de los prototipos requeridos por lh_<tipo>_new(). Estos proporcionan conversiones de tipo por variable antes de llamar a las funciones de devolución de llamada específicas del tipo escritas por el autor de la aplicación. Estas macros, así como las utilizadas para las funciones de devolución de llamada doall, se definen como:

#define	DECLARE_LHASH_HASH_FN(name, o_type) \
	unsigned long name##_LHASH_HASH(const void *);
#define	IMPLEMENT_LHASH_HASH_FN(name, o_type) \
	unsigned long name##_LHASH_HASH(const void *arg) { \
		const o_type *a = arg; \
		return name##_hash(a); }
#define	LHASH_HASH_FN(name) name##_LHASH_HASH

#define	DECLARE_LHASH_COMP_FN(name, o_type) \
	int name##_LHASH_COMP(const void *, const void *);
#define	IMPLEMENT_LHASH_COMP_FN(name, o_type) \
	int name##_LHASH_COMP(const void *arg1, const void *arg2) { \
		const o_type *a = arg1;		    \
		const o_type *b = arg2; \
		return name##_cmp(a,b); }
#define	LHASH_COMP_FN(name) name##_LHASH_COMP

#define	DECLARE_LHASH_DOALL_FN(name, o_type) \
	void name##_LHASH_DOALL(void *);
#define	IMPLEMENT_LHASH_DOALL_FN(name, o_type) \
	void name##_LHASH_DOALL(void *arg) { \
		o_type *a = arg; \
		name##_doall(a); }
#define	LHASH_DOALL_FN(name) name##_LHASH_DOALL

#define	DECLARE_LHASH_DOALL_ARG_FN(name, o_type, a_type) \
	void name##_LHASH_DOALL_ARG(void *, void *);
#define	IMPLEMENT_LHASH_DOALL_ARG_FN(name, o_type, a_type) \
	void name##_LHASH_DOALL_ARG(void *arg1, void *arg2) { \
		o_type *a = arg1; \
		a_type *b = arg2; \
		name##_doall_arg(a, b); }
#define	LHASH_DOALL_ARG_FN(name) name##_LHASH_DOALL_ARG

Un ejemplo de una tabla hash que almacena (punteros a) estructuras de tipo 'STUFF' podría definirse de la siguiente manera:

/* Ordenar 'arg1' y 'arg2' (implementado en otro lugar) */

/* Crear funciones envoltorio seguras para tipos para su uso en los internos de LHASH */

static IMPLEMENT_LHASH_COMP_FN(stuff, STUFF);

int main(int argc, char *argv[]) {

lh_<tipo>_insert() inserta la estructura apuntada por datos en tabla. Si ya existe una entrada con la misma clave, se reemplaza el valor antiguo. Tenga en cuenta que lh_<tipo>_insert() almacena punteros, los datos no se copian.

lh_<tipo>_delete() elimina una entrada de tabla.

lh_<tipo>_retrieve() busca una entrada en tabla. Normalmente, datos es una estructura con los campos de clave establecidos; la función devolverá un puntero a una estructura completamente poblada.

lh_<tipo>_doall() llamará, para cada entrada en la tabla hash, a func con el elemento de datos como su parámetro. NAME

lhash - linked hash table

SYNOPSIS

#include <openssl/lhash.h>

LHASH * lh_new(int size, int (*cmp)(char *, char *)); int lh_insert(LHASH *lh, char *data); char * lh_retrieve(LHASH *lh, char *data); int lh_delete(LHASH *lh, char *data); void lh_doall(LHASH *lh, void (*func)(char *, char *)); void lh_doall_arg(LHASH *lh, void (*func)(char *, char *, char *), char *arg); void lh_free(LHASH *lh);

Using the type-specific wrappers:

/* Example using STUFF type */
typedef struct stuff_st STUFF;

LHASH *lh_STUFF_new(int size);
int lh_STUFF_insert(LHASH *lh, STUFF *data);
STUFF *lh_STUFF_retrieve(LHASH *lh, STUFF *data);
int lh_STUFF_delete(LHASH *lh, STUFF *data);
void lh_STUFF_free(LHASH *lh);

/* For type-specific callbacks */
typedef int STUFF_cmp_fn(STUFF *a, STUFF *b);
typedef unsigned long STUFF_hash_fn(STUFF *a);
typedef void STUFF_doall_fn(STUFF *a, STUFF *b);
typedef void STUFF_doall_arg_fn(STUFF *a, STUFF *b, char *arg);

/* Declare a type-specific callback and implement it */
DECLARE_LHASH_COMP(STUFF, STUFF);
IMPLEMENT_LHASH_COMP(STUFF, STUFF);

DECLARE_LHASH_HASH(STUFF, STUFF);
IMPLEMENT_LHASH_HASH(STUFF, STUFF);

DECLARE_LHASH_DOALL(STUFF, STUFF);
IMPLEMENT_LHASH_DOALL(STUFF, STUFF);

DECLARE_LHASH_DOALL_ARG(STUFF, STUFF, BIO);
IMPLEMENT_LHASH_DOALL_ARG(STUFF, STUFF, BIO);

/* And for the generic C functions */
DECLARE_LHASH_FN(STUFF);
IMPLEMENT_LHASH_FN(STUFF, STUFF, STUFF, STUFF);

DESCRIPTION

The lhash library provides a generic hash table implementation. It is used internally by various parts of OpenSSL, for example, to store X509 certificates and other objects.

The hash table uses a technique called dynamic resizing which involves expanding and contracting the table size as items are added or removed. This avoids the performance penalty associated with completely recalculating all hash values when the table size changes.

The basic functions are:

lh_new()
Creates a new hash table. size is the initial number of buckets. cmp is a comparison function that takes two pointers to data items and returns 0 if they are equal, negative if the first is less than the second, and positive if the first is greater than the second. Note that the comparison function will receive pointers to the stored items, not the data being looked up.
lh_insert()
lh_retrieve()
lh_delete()
These are the standard insert, retrieve, and delete functions. They take a pointer to the data item. The hash table uses the same pointer for hashing and comparison purposes. This means that the data item passed to lh_insert() is the item that will be used for hashing and comparison. If you want to insert an item into the hash table, you must first hash it using a suitable hash function and then compare it using a suitable comparison function. If these functions are not provided using the type-specific wrappers, the caller must ensure that the data item provided is suitable for hashing and comparison.
lh_doall()
Iterates through all items in the hash table, calling the function func for each item. The function func is called with two arguments: a pointer to the hash table item and a pointer to the data item being looked up (which is NULL in this case).
lh_doall_arg()
Similar to lh_doall(), but the function func is also passed an additional argument arg. The function func should have the prototype void (*)(char *data, char *unused, char *arg).
lh_free()
Frees the hash table and all its contents. The caller is responsible for freeing the actual data items if they were dynamically allocated.

lh_<type>_new(), lh_<type>_insert(), lh_<type>_retrieve(), lh_<type>_delete(), lh_<type>_free(), lh_<type>_doall(), and lh_<type>_doall_arg() are type-specific versions of the generic functions described above. They use the macros DECLARE_LHASH_FN and IMPLEMENT_LHASH_FN to provide type safety. The type-specific versions take arguments of the specified type instead of char *, and the callback functions also operate on pointers to the specified type.

When using the type-specific wrappers, you still need to provide a hash function and a comparison function. These can be declared using DECLARE_LHASH_HASH and DECLARE_LHASH_COMP, and implemented using IMPLEMENT_LHASH_HASH and IMPLEMENT_LHASH_COMP. The hash function should return an unsigned long, and the comparison function should take two pointers to the specified type and return an integer value as described for lh_new().

The macros DECLARE_LHASH_DOALL_FN and IMPLEMENT_LHASH_DOALL_FN allow you to create type-specific versions of the lh_<type>_doall() function. The callback function should have a prototype of the form void (*)(TYPE *data, TYPE *unused), where TYPE is the type of the items stored in the hash table. The second argument is unused and is always passed as NULL.

The macros DECLARE_LHASH_DOALL_ARG_FN and IMPLEMENT_LHASH_DOALL_ARG_FN are similar, but the callback function is also passed an additional argument. The callback prototype is of the form void (*)(TYPE *data, TYPE *unused, ARG_TYPE *arg), where TYPE is the type of the items stored in the hash table and ARG_TYPE is the type of the additional argument.

Here is an example of using the type-specific wrappers to manage a hash table of STUFF objects:

/* Define the STUFF type and its hash and comparison functions */
typedef struct stuff_st {
    int id;
    char *name;
} STUFF;

static unsigned long
st_hash(STUFF *st)
{
    /* A simple hash function based on the id */
    return (unsigned long)st->id;
}

static int
st_cmp(STUFF *st1, STUFF *st2)
{
    /* Compare based on the id */
    if (st1->id < st2->id)
        return -1;
    else if (st1->id > st2->id)
        return 1;
    else
        return 0;
}

/* Declare the type-specific functions and implement them */
DECLARE_LHASH_FN(STUFF);
IMPLEMENT_LHASH_FN(STUFF, STUFF, STUFF, STUFF);

/* Then later in the code ... */

/* Create a new hash table for STUFF objects */
LHASH *hashtable = lh_STUFF_new(100); /* Initial size 100 */

/* Insert some STUFF objects */
STUFF *s1 = malloc(sizeof(STUFF));
s1->id = 1;
s1->name = "Item 1";
lh_STUFF_insert(hashtable, s1);

STUFF *s2 = malloc(sizeof(STUFF));
s2->id = 2;
s2->name = "Item 2";
lh_STUFF_insert(hashtable, s2);

/* Retrieve an item */
STUFF *lookup = malloc(sizeof(STUFF));
lookup->id = 1;
STUFF *found = lh_STUFF_retrieve(hashtable, lookup);
free(lookup);

/* Delete an item */
STUFF *delete_target = malloc(sizeof(STUFF));
delete_target->id = 2;
lh_STUFF_delete(hashtable, delete_target);
free(delete_target); /* The item itself is not freed by lh_delete */

/* Free the hash table and its contents */
/* Note: This only frees the LHASH structure, not the data items themselves. */
/* You need to iterate and free them separately if dynamically allocated. */
lh_STUFF_free(hashtable);

The lh_<type>_doall() and lh_<type>_doall_arg() functions are useful for performing operations on all items in the hash table, such as freeing them. For example, to free all items in a hash table:

/* Callback function to free a STUFF item */
static void
STUFF_cleanup(STUFF *st, STUFF *unused) /* unused is always NULL */
{
    free(st);
}

/* Implement the type-specific doall function */
IMPLEMENT_LHASH_DOALL_FN(STUFF_cleanup, STUFF)

/* ... then later in the code ... */

/* So to run "STUFF_cleanup" against all items in a hash table ... */
lh_STUFF_doall(hashtable, LHASH_DOALL_FN(STUFF_cleanup));

/* Then the hash table itself can be deallocated */
lh_STUFF_free(hashtable);

A callback may delete entries from the hash table, however, it is not safe to insert new entries.

lh_<type>_doall_arg() is the same as lh_<type>_doall() except that func will be called with arg as the second argument and func should be of type LHASH_DOALL_ARG_FN_TYPE (a callback prototype that is passed both the table entry and an extra argument). As with lh_<type>_doall(), you can instead choose to declare your callback with a prototype matching the types you are dealing with and use the declare/implement macros to create compatible wrappers that cast variables before calling your type-specific callbacks. An example of this is demonstrated here (printing all hash table entries to a BIO that is provided by the caller):

/* Print item 'a' to 'output_bio' (this is implemented elsewhere) */
void STUFF_print_doall_arg(const STUFF *a, BIO *output_bio);

/* Implement a prototype-compatible wrapper for "STUFF_print" */
static IMPLEMENT_LHASH_DOALL_ARG_FN(STUFF, const STUFF, BIO)
    /* ... then later in the code ... */

/* Print out the entire hashtable to a particular BIO */
lh_STUFF_doall_arg(hashtable, LHASH_DOALL_ARG_FN(STUFF_print), BIO,
    logging_bio);

lh_<type>_error() can be used to determine if an error occurred in the last operation.

RETURN VALUES

lh_<type>_new() returns NULL on error, otherwise a pointer to the new LHASH structure.

When a hash table entry is replaced, lh_<type>_insert() returns the value being replaced. NULL is returned on normal operation and on error.

lh_<type>_delete() returns the entry being deleted. NULL is returned if there is no such value in the hash table.

lh_<type>_retrieve() returns the hash table entry if it has been found, or NULL otherwise.

lh_<type>_error() returns 1 if an error occurred in the last operation, or 0 otherwise.

NOTES

The various LHASH macros and callback types exist to make it possible to write type-checked code without resorting to function-prototype casting — an evil that makes application code much harder to audit/verify and also opens the window of opportunity for stack corruption and other hard-to-find bugs. It also, apparently, violates ANSI-C.

The LHASH code regards table entries as constant data. As such, it internally represents lh_<type>_insert()'ed items with a const void * pointer type. This is why callbacks such as those used by lh_<type>_doall() and lh_<type>_doall_arg() declare their prototypes with "const", even for the parameters that pass back the table items' data pointers — for consistency, user-provided data is "const" at all times as far as the LHASH code is concerned. However, as callers are themselves providing these pointers, they can choose whether they too should be treating all such parameters as constant.

As an example, a hash table may be maintained by code that, for reasons of encapsulation, has only "const" access to the data being indexed in the hash table (i.e. it is returned as "const" from elsewhere in their code) — in this case the LHASH prototypes are appropriate as-is. Conversely, if the caller is responsible for the life-time of the data in question, then they may well wish to make modifications to table item passed back in the lh_<type>_doall() or lh_<type>_doall_arg() callbacks (see the "STUFF_cleanup" example above). If so, the caller can either cast the "const" away (if they're providing the raw callbacks themselves) or use the macros to declare/implement the wrapper functions without "const" types.

Callers that only have "const" access to data they are indexing in a table, yet declare callbacks without constant types (or cast the "const" away themselves), are therefore creating their own risks/bugs without being encouraged to do so by the API. On a related note, those auditing code should pay special attention to any instances of DECLARE/IMPLEMENT_LHASH_DOALL_[ARG_]_FN macros that provide types without any "const" qualifiers.

INTERNALS

The following description is based on the SSLeay documentation:

The lhash library implements a hash table described in the Communications of the ACM in 1991. What makes this hash table different is that as the table fills, the hash table is increased (or decreased) in size via reallocarray(3). When a 'resize' is done, instead of all hashes being redistributed over twice as many 'buckets', one bucket is split. So when an 'expand' is done, there is only a minimal cost to redistribute some values. Subsequent inserts will cause more single 'bucket' redistributions but there will never be a sudden large cost due to redistributing all the 'buckets'.

The state for a particular hash table is kept in the LHASH structure. The decision to increase or decrease the hash table size is made depending on the 'load' of the hash table. The load is the number of items in the hash table divided by the size of the hash table. The default values are as follows. If (hash->up_load < load) => expand. If (hash->down_load > load) => contract. The up_load has a default value of 1 and down_load has a default value of 2. These numbers can be modified by the application by just playing with the up_load and down_load variables. The 'load' is kept in a form which is multiplied by 256. So hash->up_load=8*256 will cause a load of 8 to be set.

If you are interested in performance, the field to watch is num_comp_calls. The hash library keeps track of the 'hash' value for each item so when a lookup is done, the 'hashes' are compared, if there is a match, then a full compare is done, and hash->num_comp_calls is incremented. If num_comp_calls is not equal to num_delete plus num_retrieve, it means that your hash function is generating hashes that are the same for different values. It is probably worth changing your hash function if this is the case because even if your hash table has 10 items in a 'bucket', it can be searched with 10 unsigned long compares and 10 linked list traverses. This will be much less expensive that 10 calls to your compare function.

lh_strhash() is a demo string hashing function. Since the LHASH routines would normally be passed structures, this routine would not normally be passed to lh_<type>_new(), rather it would be used in the function passed to lh_<type>_new().

HISTORY

lh_new(), lh_free(), lh_insert(), lh_delete(), lh_retrieve(), lh_doall(), and lh_strhash() appeared in SSLeay 0.4 or earlier. lh_doall_arg() first appeared in SSLeay 0.5.1. These functions have been available since OpenBSD 2.4.

lh_<type>_error() was added in SSLeay 0.9.1b.

In OpenSSL 0.9.7, all lhash functions that were passed function pointers were changed for better type safety, and the function types LHASH_COMP_FN_TYPE, LHASH_HASH_FN_TYPE, LHASH_DOALL_FN_TYPE, and LHASH_DOALL_ARG_FN_TYPE became available.

In OpenSSL 1.0.0, the lhash interface was revamped for even better type checking.

BUGS

lh_<type>_insert() returns NULL both for success and error.

NAME

libressl-lh_new — Create a new LHash hash table

SYNOPSIS

LHASH_OF(3) macros return a pointer to a LHASH structure. 

#include <openssl/lhash.h>

LHASH_OF(type) *LHASH_new(unsigned long flags, LHASH_COMP *comp,
    LHASH_HASH *hash, LHASH_FREE *free_fn, LHASH_STORE *store_fn,
    LHASH_DOALL *doall_fn, LHASH_DOALL_ARG *doall_arg_fn);

DESCRIPTION

The LHASH_new function creates and returns a pointer to a new LHash hash table structure. The structure is dynamically allocated and its size is determined by the LHASH_OF(type) macro, which takes the type of the elements stored in the hash table as an argument. The type can be any valid C type, including structures and pointers.

The following arguments are used to configure the new hash table:

flags
A bitmask of flags to control the behavior of the hash table. Currently, the following flags are defined:
LH_GROWTH_FLAG_NO_RESIZE
Disables automatic resizing of the hash table. The table will remain at its initial size.
LH_GROWTH_FLAG_NO_AUTO_FREE
Disables automatic freeing of elements when they are replaced or deleted. The caller is responsible for freeing elements manually.
comp
A pointer to a comparison function that takes two arguments of the element type and returns an integer less than, equal to, or greater than zero if the first argument is less than, equal to, or greater than the second, respectively.
hash
A pointer to a hash function that takes a pointer to an element and returns an unsigned long hash value for that element.
free_fn
A pointer to a function that takes a pointer to an element and frees its memory. This function is called when an element is removed from the hash table or when the hash table is destroyed. If this is NULL, no memory will be freed.
store_fn
A pointer to a function that takes a pointer to an element and returns a pointer to a copy of that element. This function is used to store elements in the hash table. If this is NULL, elements are stored by reference.
doall_fn
A pointer to a function that takes a pointer to an element and performs some operation on it. This function is used in conjunction with lh_doall and lh_doall_arg.
doall_arg_fn
A pointer to a function that takes a pointer to an element and a generic argument, and performs some operation on the element using the argument. This function is used in conjunction with lh_doall_arg.

RETURN VALUES

The LHASH_new function returns a pointer to the newly created LHash hash table structure on success, or NULL on failure.

NOTES

The LHASH_OF(type) macro is a convenient way to declare and use LHash hash tables with specific element types. It simplifies the process of managing memory and type safety.

The comparison, hash, and free functions are crucial for the correct operation of the hash table. Ensure that these functions are implemented correctly and handle all possible cases.

INTERNALS

The LHash implementation uses a technique called open hashing to resolve collisions. Each bucket in the hash table can store multiple elements using a linked list. The load factor of the hash table is automatically adjusted to maintain performance.
