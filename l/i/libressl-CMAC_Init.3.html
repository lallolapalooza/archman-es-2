DESCRIPCIÓN

CMAC es un algoritmo de código de autenticación de mensajes que puede emplear un cifrado de bloque arbitrario utilizando una clave simétrica.

La presente página del manual describe las funciones de bajo nivel que implementan CMAC. En lugar de utilizar estas funciones directamente, los programas de aplicación suelen llamar a EVP_PKEY_new_CMAC_key(3) y luego pasan el objeto EVP_PKEY resultante a EVP_DigestSignInit(3).

La API de CMAC está orientada a objetos. Calcular un código de autenticación de mensajes requiere un objeto CMAC_CTX. Generalmente, las funciones CMAC_CTX_new(), CMAC_Init(), CMAC_Update(), CMAC_Final() y CMAC_CTX_free() deben llamarse en este orden.

CMAC_CTX_new() asigna un nuevo objeto CMAC_CTX, inicializa el objeto EVP_CIPHER_CTX incrustado y marca el objeto en sí como no inicializado.

CMAC_Init() selecciona el cifrado de bloque dado para su uso por ctx. Las funciones para obtener objetos EVP_CIPHER adecuados se enumeran en la sección CIPHER LISTING de la página del manual de EVP_EncryptInit(3). A menos que key sea NULL, CMAC_Init() también inicializa ctx para su uso con la clave simétrica dada, que tiene una longitud de key_len bytes. En particular, calcula y almacena internamente las dos subclaves e inicializa ctx para alimentar posteriormente datos con CMAC_Update(). El argumento engine se ignora; se recomienda pasar NULL.

Si ctx ya está inicializado, se puede volver a llamar a CMAC_Init() con key y cipher establecidos ambos a NULL y key_len establecido a 0. En ese caso, cualquier dato ya procesado se descarta y ctx se reinicializa para comenzar a leer datos de nuevo.

CMAC_Update() procesa in_len bytes de datos de entrada apuntados por in_data. Dependiendo del número de bytes de entrada ya almacenados en caché en ctx, en in_len, y en el tamaño del bloque, esto puede cifrar cero o más bloques. A menos que in_len sea cero, esta función deja al menos un byte y como máximo un bloque de entrada almacenados en caché pero no procesados dentro del objeto ctx. Se puede llamar a CMAC_Update() varias veces para concatenar varios trozos de datos de entrada de tamaños variables.

CMAC_Final() almacena la longitud del código de autenticación de mensajes en bytes, que es igual al tamaño del bloque del cifrado, en *out_len. A menos que out_mac sea NULL, cifra el último bloque, rellenándolo si es necesario, y copia el código de autenticación de mensajes resultante a out_mac. El llamante es responsable de proporcionar un búfer de tamaño suficiente.

CMAC_CTX_copy() realiza una copia profunda del in_ctx ya inicializado en out_ctx.

CMAC_CTX_cleanup() pone a cero ambas subclaves y todos los datos temporales en ctx y en el objeto EVP_CIPHER_CTX incrustado, libera toda la memoria asignada asociada a él, excepto el propio ctx, y lo marca como no inicializado, de modo que pueda reutilizarse para posteriores CMAC_Init().

CMAC_CTX_free() llama a CMAC_CTX_cleanup(), luego libera el propio ctx. Si ctx es NULL, no se realiza ninguna acción.

VALORES DE RETORNO

CMAC_CTX_new() devuelve el nuevo objeto de contexto o NULL en caso de fallo. Tiene éxito a menos que la memoria se agote.

CMAC_Init(), CMAC_Update(), CMAC_Final() y CMAC_CTX_copy() devuelven 1 en caso de éxito o 0 en caso de fallo. CMAC_Init() falla si la inicialización del objeto EVP_CIPHER_CTX incrustado falla. Los otros fallan si in_ctx no está inicializado. CMAC_Update() y CMAC_Final() también fallan si el cifrado de un bloque falla, y CMAC_CTX_copy() si la copia del objeto EVP_CIPHER_CTX incrustado falla, lo que puede ocurrir por ejemplo cuando la memoria se agota.

CMAC_CTX_get0_cipher_ctx() devuelve un puntero interno al objeto EVP_CIPHER_CTX que está incrustado en ctx.

ERRORES

El propio código CMAC no utiliza el framework de <openssl/err.h>, por lo que, en general, las razones del fallo no se pueden averiguar con ERR_get_error(3). Sin embargo, dado que las funciones de EVP_EncryptInit(3) se utilizan internamente, es posible que se añadan entradas a la pila de errores en algunos casos de fallo.
