NOMBRE

EVP_aes_128_ccm, EVP_aes_192_ccm, EVP_aes_256_ccm — Cifra AES de EVP en modo Counter with CBC-MAC (CCM)

SINOPSIS

biblioteca “libcrypto”
#include <openssl/evp.h>

const EVP_CIPHER *
EVP_aes_128_ccm(void);

const EVP_CIPHER *
EVP_aes_192_ccm(void);

const EVP_CIPHER *
EVP_aes_256_ccm(void);

DESCRIPCIÓN

EVP_aes_128_ccm(), EVP_aes_192_ccm(), y EVP_aes_256_ccm() proporcionan el algoritmo Advanced Encryption Standard para claves de 128, 192 y 256 bits en modo Counter with CBC-MAC (CCM) dentro del framework de evp(3). Este modo soporta Cifrado Autenticado con Datos Adicionales (AEAD) y puede ser utilizado en una variedad de protocolos de comunicación. Claves más largas dificultan los ataques de precomputación a costa de un rendimiento menor.

Para las cifras del modo CCM, el comportamiento de la interfaz EVP se altera sutilmente y se requieren varias operaciones adicionales de EVP_CIPHER_CTX_ctrl(3) para funcionar correctamente. Algunos de los comandos de control EVP_CTRL_CCM_* son alias más antiguos para las constantes correspondientes de EVP_CTRL_AEAD_*, como se indica a continuación.

La API EVP_AEAD_CTX_new(3), menos engorrosa y propensa a errores, no proporciona modos CCM. Algunos protocolos de comunicación soportan alternativas al CCM, que a veces pueden permitir elegir la mejor API al evitar el CCM.

Controles de configuración

Los siguientes dos comandos de control se pueden emitir tan pronto como se haya llamado a EVP_EncryptInit(3) con un tipo CCM y punteros NULL para key y iv. Ambos comandos son opcionales y se anulan entre sí. Si se emiten cuando ya se ha establecido una nonce, causan silenciosamente corrupción de datos. El argumento ptr es ignorado por ambos; se recomienda pasar NULL.

EVP_CTRL_CCM_SET_L
Establece el tamaño L del campo de longitud a arg bytes y el tamaño de la nonce a 15 - arg bytes. Por defecto, se utilizan 8 bytes para el campo de longitud y 7 para la nonce. Seleccionar un tamaño L más pequeño para el campo de longitud reduce el tamaño máximo de los mensajes que se pueden enviar, pero a cambio permite transmitir más mensajes con la misma clave. Es un error pasar menos de 2 o más del valor por defecto de 8 para arg.
EVP_CTRL_AEAD_SET_IVLEN (== EVP_CTRL_CCM_SET_IVLEN)
Establece el tamaño de la nonce a arg bytes y el tamaño L del campo de longitud a 15 - arg bytes. Por defecto, se utilizan 7 bytes para la nonce y 8 para el campo de longitud. Seleccionar un tamaño de nonce más grande permite transmitir más mensajes con la misma clave a expensas de reducir el tamaño máximo para cada mensaje. Es un error pasar más de 13 o menos del valor por defecto de 7 para arg.

Después de emitir opcionalmente uno de los comandos de control anteriores, se puede llamar a EVP_EncryptInit(3) por segunda vez, pasando esta vez NULL para el argumento type, con los otros dos argumentos apuntando a la clave AES deseada y a la nonce deseada.

Controles de cifrado

EVP_CTRL_AEAD_SET_TAG (== EVP_CTRL_CCM_SET_TAG)
Si el argumento ptr es NULL, establece la longitud de la etiqueta M a arg bytes. El valor por defecto es 12. Seleccionar un valor más grande hace que la manipulación sea más difícil para un atacante, con un pequeño coste de hacer los mensajes ligeramente más largos. No se recomienda seleccionar un valor más pequeño. Es un error pasar un número impar para arg, o un número menor que 4 o mayor que 16, o pasar NULL a ptr cuando ctx no está configurado para cifrar. Emitir este comando de control cuando ya está configurada una clave de cifrado causa silenciosamente corrupción de datos.
EVP_CTRL_AEAD_GET_TAG (== EVP_CTRL_CCM_GET_TAG)
Almacena los arg bytes de la etiqueta en la memoria proporcionada por el llamante a partir de ptr. Es un error emitir este comando de control cuando ctx no está configurado para cifrar, cuando aún no se han cifrado datos, con un arg que no coincide con la longitud de etiqueta configurada M, o cuando la etiqueta ya se ha recuperado anteriormente.

Antes de pasar cualquier dato de texto plano a EVP_EncryptUpdate(3), llame a EVP_EncryptUpdate(3) con in y out establecidos a NULL, pasando la longitud total del texto plano en bytes como in_len. Esto construye el primer bloque para ser digerido con CBC-MAC y copia la longitud del texto a *out_len. No comprueba si in_len excede el límite de 256^L; los bytes más significativos de valores excesivos se descartan silenciosamente.

Es un error si el argumento in_len de la llamada a EVP_EncryptUpdate(3) que pasa los datos de texto plano no coincide con la longitud total especificada anteriormente. Dividir el texto en más de un bloque para pasarlo en múltiples llamadas a EVP_EncryptUpdate(3) no es compatible con CCM.

Para especificar cualquier dato autenticado adicional (AAD), llame a EVP_EncryptUpdate(3) con el argumento out establecido a NULL.

Controles de descifrado

EVP_CTRL_AEAD_SET_TAG (== EVP_CTRL_CCM_SET_TAG)
Si el argumento ptr no es NULL, copia arg bytes comenzando en ptr al valor de etiqueta esperado de CCM. Es un error pasar un número impar para arg, o un número menor que 4 o mayor que 16. Pasar un número que no corresponde a la longitud de etiqueta M que se utilizó para el cifrado no genera un error inmediato, pero da como resultado un comportamiento indefinido y típicamente causa un fallo de autenticación posterior. También es un error pasar un ptr no NULL cuando ctx está configurado para cifrar.
