SSL_CTX_SET_OPTIONS(3) Manual de Funciones de Biblioteca SSL_CTX_SET_OPTIONS(3)

NOMBRE

SSL_CTX_set_options, SSL_set_options, SSL_CTX_clear_options, SSL_clear_options, SSL_CTX_get_options, SSL_get_options, SSL_get_secure_renegotiation_support — manipular opciones SSL

SINOPSIS

biblioteca “libssl” libcrypto
#include <openssl/ssl.h>

long
SSL_CTX_set_options(SSL_CTX *ctx, long options);

long
SSL_set_options(SSL *ssl, long options);

long
SSL_CTX_clear_options(SSL_CTX *ctx, long options);

long
SSL_clear_options(SSL *ssl, long options);

long
SSL_CTX_get_options(SSL_CTX *ctx);

long
SSL_get_options(SSL *ssl);

long
SSL_get_secure_renegotiation_support(SSL *ssl);

DESCRIPCIÓN

SSL_CTX_set_options() añade las opciones establecidas mediante la máscara de bits en options a ctx. ¡Las opciones ya establecidas previamente no se borran!

SSL_set_options() añade las opciones establecidas mediante la máscara de bits en options a ssl. ¡Las opciones ya establecidas previamente no se borran!

SSL_CTX_clear_options() borra las opciones establecidas mediante la máscara de bits en options de ctx.

SSL_clear_options() borra las opciones establecidas mediante la máscara de bits en options de ssl.

SSL_CTX_get_options() devuelve las opciones establecidas para ctx.

SSL_get_options() devuelve las opciones establecidas para ssl.

SSL_get_secure_renegotiation_support() indica si el par soporta la renegociación segura.

Todas estas funciones se implementan usando macros.

El comportamiento de la biblioteca SSL puede modificarse estableciendo varias opciones. Las opciones se codifican como máscaras de bits y pueden combinarse mediante una operación OR a nivel de bits (|).

SSL_CTX_set_options() y SSL_set_options() afectan al comportamiento del protocolo (externo) de la biblioteca SSL. El comportamiento (interno) de la API puede modificarse utilizando las funciones similares SSL_CTX_set_mode(3) y SSL_set_mode(3).

Durante un handshake, se utilizan los ajustes de opciones del objeto SSL. Cuando se crea un nuevo objeto SSL a partir de un contexto usando SSL_new(3), se copia la configuración de opciones actual. Los cambios en ctx no afectan a los objetos SSL ya creados. SSL_clear() no afecta a la configuración.

Las siguientes opciones de solución de errores están disponibles:

SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS
Deshabilita una contramedida contra una vulnerabilidad del protocolo TLS 1.0 que afecta a los cifrados CBC, que algunas implementaciones SSL defectuosas no pueden manejar. Esta opción no tiene efecto para conexiones que usan otros cifrados.
SSL_OP_ALL
Actualmente es un alias para SSL_OP_LEGACY_SERVER_CONNECT.

Normalmente es seguro usar SSL_OP_ALL para habilitar las opciones de solución de errores si se desea compatibilidad con implementaciones algo defectuosas.

Las siguientes opciones de modificación están disponibles:

SSL_OP_CIPHER_SERVER_PREFERENCE
Al elegir un cifrado, usa las preferencias del servidor en lugar de las del cliente. Cuando no está establecida, el servidor siempre seguirá las preferencias del cliente. Cuando está establecida, el servidor elegirá siguiendo sus propias preferencias.
SSL_OP_COOKIE_EXCHANGE
Activa el intercambio de cookies como se describe en la RFC 4347 Sección 4.2.1. Solo afecta a las conexiones DTLS.
SSL_OP_LEGACY_SERVER_CONNECT
Permite la renegociación insegura heredada entre OpenSSL y servidores sin parche solamente: esta opción está establecida por defecto actualmente. Ver la sección RENEGOCIACIÓN SEGURA para más detalles.
SSL_OP_NO_DTLSv1
No usar el protocolo DTLSv1. Obsoleto; usar SSL_CTX_set_min_proto_version(3) en su lugar.
SSL_OP_NO_DTLSv1_2
No usar el protocolo DTLSv1.2. Obsoleto; usar SSL_CTX_set_min_proto_version(3) en su lugar.
SSL_OP_NO_QUERY_MTU
No consultar la MTU. Solo afecta a las conexiones DTLS.
SSL_OP_NO_SESSION_RESUMPTION_ON_RENEGOTIATION
Al realizar la renegociación como servidor, iniciar siempre una nueva sesión (es decir, las solicitudes de reanudación de sesión solo se aceptan en el handshake inicial). Esta opción no es necesaria para clientes.
SSL_OP_NO_TICKET
Normalmente, los clientes y servidores que usan TLSv1.2 y anteriores, donde sea posible, utilizan de forma transparente los tickets RFC 5077 para la reanudación de sesiones sin estado.

Si se establece esta opción, esta funcionalidad se deshabilita y los tickets no serán utilizados por clientes ni servidores.

SSL_OP_NO_TLSv1
No usar el protocolo TLSv1.0. Obsoleto; usar SSL_CTX_set_min_proto_version(3) en su lugar.
SSL_OP_NO_TLSv1_1
No usar el protocolo TLSv1.1. Obsoleto; usar SSL_CTX_set_min_proto_version(3) en su lugar.
SSL_OP_NO_TLSv1_2
No usar el protocolo TLSv1.2. Obsoleto; usar SSL_CTX_set_min_proto_version(3) en su lugar.
SSL_OP_NO_TLSv1_3
No usar el protocolo TLSv1.3. Obsoleto; usar SSL_CTX_set_min_proto_version(3) en su lugar.
SSL_OP_PKCS1_CHECK_1_2
Comprueba si el certificado del servidor se puede utilizar para un intercambio de claves RSA seguro. Consulte el algoritmo de cifrado de clave RSA para obtener más información.
SSL_OP_PKCS1_CHECK_2
Comprueba si el certificado del servidor se puede utilizar para un intercambio de claves RSA seguro. Consulte el algoritmo de cifrado de clave RSA para obtener más información.
SSL_OP_PREFER_ECDH_CHALLENGE
Elige ECDH sobre DH en el handshake.
SSL_OP_RAW_SOCKET
Permite que las conexiones SSL/TLS se utilicen sobre sockets que no sean de red (por ejemplo, sockets IPC). Esto solo se aplica a las conexiones DTLS.
SSL_OP_REUSE_CERT_AREA_DATA
Se utiliza para el rendimiento, pero puede ser inseguro en algunos contextos.
SSL_OP_SSLEAY_080_CLIENT_DH_BUG
Habilita una solución de problemas para un error en la versión 0.9.8 de OpenSSL.
SSL_OP_TLS_BLOCK_ALL_SERVERS
Deshabilita la compatibilidad con todas las versiones de TLS.
SSL_OP_TLS_ROLLBACK_SEVERITY
Evita el ataque de reversión de TLS. Si se establece, el cliente intentará continuar la conexión aunque el servidor envíe una alerta de reversión.

SSL_set_verify_depth(3) puede ser llamado para ajustar la profundidad máxima de la cadena de certificados que se considera válida.

El valor de retorno de las funciones SSL_CTX_set_options(), SSL_set_options(), SSL_CTX_clear_options() y SSL_clear_options() es el valor de las opciones después de la operación.

SECURE RENEGOTIATION

La renegociación segura TLS es un mecanismo que permite a un cliente o servidor iniciar una nueva negociación SSL/TLS sin terminar la conexión existente. Se introdujo para solucionar una vulnerabilidad de seguridad en la renegociación SSL/TLS original. La renegociación segura TLS se describe en RFC 5746.

El cliente y el servidor deben acordar usar la renegociación segura TLS durante el handshake SSL/TLS.

OpenSSL intenta negociar la renegociación segura TLS de forma predeterminada. Sin embargo, algunas implementaciones SSL/TLS antiguas o defectuosas no soportan la renegociación segura TLS. Para garantizar la compatibilidad con tales implementaciones, OpenSSL permite la renegociación insegura heredada si se establece la opción SSL_OP_LEGACY_SERVER_CONNECT. ¡El uso de esta opción puede exponer la conexión a ataques de intermediario (man-in-the-middle)! Se recomienda encarecidamente evitar su uso y actualizar las implementaciones antiguas.

SSL_get_secure_renegotiation_support() devuelve 1 si el par soporta la renegociación segura TLS, y 0 en caso contrario.

VER TAMBIÉN

SSL_CTX_new(3), SSL_new(3), SSL_set_mode(3), SSL_set_verify(3).

BUGS

La opción SSL_OP_ALL habilita varias soluciones de problemas para implementaciones antiguas o defectuosas. Si no se necesita compatibilidad con ellas, debería evitarse usar SSL_OP_ALL y habilitar solo las opciones de solución de problemas necesarias explícitamente.

La opción SSL_OP_LEGACY_SERVER_CONNECT se establece por defecto. Esto puede ser una sorpresa, ya que habilita la renegociación insegura. Se recomienda encarecidamente deshabilitarla estableciendo explícitamente la opción SSL_OP_NO_LEGACY_SERVER_CONNECT y actualizar las implementaciones antiguas o defectuosas.

NAME

SSL_CTX_set_options, SSL_CTX_clear_options, SSL_CTX_get_options, SSL_set_options, SSL_clear_options, SSL_get_options, SSL_get_secure_renegotiation_support – set or retrieve SSL options

SYNOPSIS

 #include <openssl/ssl.h>

 unsigned long
 SSL_CTX_set_options(SSL_CTX *ctx, unsigned long ops);

 unsigned long
 SSL_CTX_clear_options(SSL_CTX *ctx, unsigned long ops);

 unsigned long
 SSL_CTX_get_options(const SSL_CTX *ctx);

 unsigned long
 SSL_set_options(SSL *ssl, unsigned long ops);

 unsigned long
 SSL_clear_options(SSL *ssl, unsigned long ops);

 unsigned long
 SSL_get_options(const SSL *ssl);

 int
 SSL_get_secure_renegotiation_support(SSL *ssl);

DESCRIPTION

The SSL_CTX_set_options() function sets the SSL options specified by ops for the given context ctx. The options are turned on in the existing options.

The SSL_CTX_clear_options() function clears the SSL options specified by ops for the given context ctx. The options are turned off in the existing options.

The SSL_CTX_get_options() function returns the current options bitmask for the context ctx.

The SSL_set_options() function sets the SSL options specified by ops for the given SSL structure ssl. The options are turned on in the existing options.

The SSL_clear_options() function clears the SSL options specified by ops for the given SSL structure ssl. The options are turned off in the existing options.

The SSL_get_options() function returns the current options bitmask for the SSL structure ssl.

The following options are currently supported:

SSL_OP_ALL
This sets all of the other SSL options. It is not recommended to use this option.
SSL_OP_ALLOW_NO_REVOKED
When checking CRLs, allow certificates that are not listed in the CRL to be considered valid. This is the default behaviour. This option can be used to select behaviour where certificates not listed in the CRL are considered revoked.
SSL_OP_CIPHER_SERVER_PREFERENCE
On the server side, use the server's preference for cipher ordering rather than the client's preference. For example, when both client and server support the same set of ciphers, the server prefers its own list of ciphers. This is the default behaviour.
SSL_OP_COOKIE_EXCHANGE
Use the cookie exchange mechanism for DTLS connections. This is the default behaviour for DTLS.
SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS
Do not insert empty fragments to try to "hide" the record layer padding if it is needed for protocol compliance. This is the default behaviour.
SSL_OP_LEGACY_SERVER_CONNECT
This option is relevant for renegotiation. See the SECURE RENEGOTIATION section.
SSL_OP_NO_QUERY_MTU
Do not query the MTU. This is the default behaviour.
SSL_OP_NO_SESSION_CACHE
Disable session caching. By default, sessions are cached.
SSL_OP_NO_SSLv2
Do not use the SSLv2 protocol. This is the default behaviour.
SSL_OP_NO_SSLv3
Do not use the SSLv3 protocol. This is the default behaviour.
SSL_OP_NO_TLSv1
Do not use the TLSv1.0 protocol. Deprecated; use SSL_CTX_set_min_proto_version(3) instead.
SSL_OP_NO_TLSv1_1
Do not use the TLSv1.1 protocol. Deprecated; use SSL_CTX_set_max_proto_version(3) instead.
SSL_OP_NO_TLSv1_2
Do not use the TLSv1.2 protocol. Deprecated; use SSL_CTX_set_max_proto_version(3) instead.

The following options used to be supported at some point in the past and no longer have any effect: SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION, SSL_OP_EPHEMERAL_RSA, SSL_OP_MICROSOFT_BIG_SSLV3_BUFFER, SSL_OP_MICROSOFT_SESS_ID_BUG, SSL_OP_NETSCAPE_CA_DN_BUG, SSL_OP_NETSCAPE_CHALLENGE_BUG, SSL_OP_NETSCAPE_DEMO_CIPHER_CHANGE_BUG, SSL_OP_NETSCAPE_REUSE_CIPHER_CHANGE_BUG, SSL_OP_NO_COMPRESSION, SSL_OP_NO_SSLv2, SSL_OP_NO_SSLv3, SSL_OP_PKCS1_CHECK_1, SSL_OP_PKCS1_CHECK_2, SSL_OP_SAFARI_ECDHE_ECDSA_BUG, SSL_OP_SINGLE_DH_USE, SSL_OP_SINGLE_ECDH_USE, SSL_OP_SSLEAY_080_CLIENT_DH_BUG, SSL_OP_SSLREF2_REUSE_CERT_TYPE_BUG, SSL_OP_TLS_BLOCK_PADDING_BUG, SSL_OP_TLS_D5_BUG, SSL_OP_TLS_ROLLBACK_BUG, SSL_OP_TLSEXT_PADDING.

SECURE RENEGOTIATION

OpenSSL 0.9.8m and later always attempts to use secure renegotiation as described in RFC 5746. This counters the prefix attack described in CVE-2009-3555 and elsewhere.

This attack has far-reaching consequences which application writers should be aware of. In the description below an implementation supporting secure renegotiation is referred to as “patched”. A server not supporting secure renegotiation is referred to as “unpatched”.

The following sections describe the operations permitted by OpenSSL's secure renegotiation implementation.

Patched client and server

Connections and renegotiation are always permitted by OpenSSL implementations.

Unpatched client and patched OpenSSL server

The initial connection succeeds but client renegotiation is denied by the server with a no_renegotiation warning alert.

If the patched OpenSSL server attempts to renegotiate, a fatal handshake_failure alert is sent. This is because the server code may be unaware of the unpatched nature of the client.

Note that a bug in OpenSSL clients earlier than 0.9.8m (all of which are unpatched) will result in the connection hanging if it receives a no_renegotiation alert. OpenSSL versions 0.9.8m and later will regard a no_renegotiation alert as fatal and respond with a fatal handshake_failure alert. This is because the OpenSSL API currently has no provision to indicate to an application that a renegotiation attempt was refused.

Patched OpenSSL client and unpatched server

If the option SSL_OP_LEGACY_SERVER_CONNECT is set then initial connections and renegotiation between patched OpenSSL clients and unpatched servers succeeds. If neither option is set then initial connections to unpatched servers will fail.

The option SSL_OP_LEGACY_SERVER_CONNECT is currently set by default even though it has security implications: otherwise it would be impossible to connect to unpatched servers (i.e., all of them initially) and this is clearly not acceptable. Renegotiation is permitted because this does not add any additional security issues: during an attack clients do not see any renegotiations anyway.

As more servers become patched, the option SSL_OP_LEGACY_SERVER_CONNECT will not be set by default in a future version of OpenSSL.

OpenSSL client applications wishing to ensure they can connect to unpatched servers should always set SSL_OP_LEGACY_SERVER_CONNECT.

OpenSSL client applications that want to ensure they can not connect to unpatched servers (and thus avoid any security issues) should always clear SSL_OP_LEGACY_SERVER_CONNECT using SSL_CTX_clear_options() or SSL_clear_options().

RETURN VALUES

SSL_CTX_set_options() and SSL_set_options() return the new options bitmask after adding options.

SSL_CTX_clear_options() and SSL_clear_options() return the new options bitmask after clearing options.

SSL_CTX_get_options() and SSL_get_options() return the current bitmask.

SSL_get_secure_renegotiation_support() returns 1 is the peer supports secure renegotiation and 0 if it does not.
