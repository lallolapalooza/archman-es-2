landlock_restrict_self(2) Manual de llamadas al sistema landlock_restrict_self(2)

NOMBRE

landlock_restrict_self - aplicar un conjunto de reglas de Landlock

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/landlock.h>  /* Definición de constantes LANDLOCK_* */
#include <sys/syscall.h>     /* Definición de constantes SYS_* */
int syscall(SYS_landlock_restrict_self, int ruleset_fd,
            uint32_t flags);

DESCRIPCIÓN

Una vez que un conjunto de reglas de Landlock se ha poblado con las reglas deseadas, la llamada al sistema landlock_restrict_self() aplica este conjunto de reglas al hilo que la llama. Vea landlock(7) para una visión general.

Un hilo puede ser restringido con múltiples conjuntos de reglas que se componen para formar el dominio de Landlock del hilo. Esto puede verse como una pila de conjuntos de reglas, pero se implementa de una manera más eficiente. Un dominio solo puede actualizarse de tal manera que las restricciones de cada conjunto de reglas pasado y futuro restringirán al hilo y a sus futuros hijos durante toda su vida. Por lo tanto, es posible aplicar gradualmente políticas de control de acceso personalizadas con múltiples conjuntos de reglas independientes provenientes de diferentes fuentes (por ejemplo, configuración del sistema init, política de sesión de usuario, política de aplicación integrada). Sin embargo, la mayoría de las aplicaciones solo necesitarán una llamada a landlock_restrict_self() y deberían evitar números arbitrarios de tales llamadas debido al límite de conjuntos de reglas compuestos. En su lugar, se alienta a los desarrolladores a construir un único conjunto de reglas personalizado con múltiples llamadas a landlock_add_rule(2).

Para aplicar un conjunto de reglas, el llamador debe tener la capacidad CAP_SYS_ADMIN en su espacio de nombres de usuario, o el hilo debe tener ya el bit no_new_privs establecido. Al igual que con seccomp(2), esto evita escenarios en los que procesos no privilegiados puedan afectar el comportamiento de sus hijos privilegiados (por ejemplo, debido a binarios set-user-ID). Si ese bit no fue establecido previamente por un ancestro de este hilo, el hilo debe realizar la siguiente llamada:

prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);

ruleset_fd es un descriptor de archivo de conjunto de reglas de Landlock obtenido con landlock_create_ruleset(2) y completamente poblado con un conjunto de llamadas a landlock_add_rule(2).

flags debe ser 0.

VALOR DE RETORNO

En caso de éxito, landlock_restrict_self() devuelve 0. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

landlock_restrict_self() puede fallar por las siguientes razones:

EOPNOTSUPP
Landlock es compatible con el kernel pero está deshabilitado en el momento del arranque.
EINVAL
flags no es 0.
EBADF
ruleset_fd no es un descriptor de archivo para el hilo actual.
EBADFD
ruleset_fd no es un descriptor de archivo de conjunto de reglas.
EPERM
ruleset_fd no tiene acceso de lectura al conjunto de reglas subyacente, o el hilo que llama no se está ejecutando con no_new_privs, o no tiene la capacidad CAP_SYS_ADMIN en su espacio de nombres de usuario.
E2BIG
Se ha alcanzado el número máximo de conjuntos de reglas compuestos para el hilo que llama. Este límite es actualmente 64.

ESTANDARES

Linux.

HISTORIA

Linux 5.13.

EJEMPLOS

Vea landlock(7).

VER TAMBIÉN

landlock_create_ruleset(2), landlock_add_rule(2), landlock(7)
