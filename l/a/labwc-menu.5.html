labwc-menu(5) Formatos de archivo Manual labwc-menu(5)

NOMBRE

labwc - archivo de menú

DESCRIPCIÓN

Los menús estáticos se construyen basándose en el archivo menu.xml ubicado en "~/.config/labwc" y en los Directorios Base XDG equivalentes.

SINTAXIS

El archivo de menú debe estar completamente encerrado entre las etiquetas <openbox_menu> y </openbox_menu>. Dentro de estas etiquetas, los menús se especifican de la siguiente manera:

<!-- Un menú de nivel superior -->
<menu id="external_menu_settings" label="External Settings" icon="preferences-other">
  <item label="Display setting">
    <action name="Execute" command="wdisplays" />
  </item>
</menu>
<!-- Otro menú de nivel superior -->
<menu id="">
  <!-- Una entrada de menú con una acción, por ejemplo, para ejecutar una aplicación -->
  <item label="" icon="">
    <action></action>
  </item>
  <!-- Un submenú definido en otro lugar, utiliza los atributos label e icon externos -->
  <menu id="external_menu_settings" />
  <!-- Línea horizontal -->
  <separator />
  <!-- Un submenú en línea -->
  <menu id="" label="" icon="">
    ...algún contenido...
  </menu>
  <!-- Título -->
  <separator label="" />
  <!-- Pipemenu -->
  <menu id="" label="" icon="" execute="COMANDO" />
</menu>

menu.id (cuando está en el nivel superior)

Define un árbol de menús. A cada menú se le debe dar un id, que es un identificador único del menú. Este id se utiliza para referirse al menú en una acción ShowMenu. Los identificadores por defecto son
  • "root-menu" para el menú contextual de la ventana raíz
  • "client-menu" para el menú contextual de la barra de título de una ventana
  • "client-list-combined-menu" para una lista de todas las ventanas en todos los espacios de trabajo. Cambiará el foco a la aplicación que se seleccione o irá al espacio de trabajo sin activar ninguna aplicación si se selecciona "Go there".
  • "client-send-to-menu" muestra todos los espacios de trabajo y envía la ventana actual a ese espacio de trabajo cuando se selecciona.

menu.id (cuando está anidado bajo otro elemento <menu>)

Enlace a un submenú definido en otro lugar (por un <menu id=""> en el nivel superior).

menu.label

El título del menú, mostrado en su padre. Se debe dar una etiqueta al definir un menú a menos que sea el elemento de menú más alto.

Tenga en cuenta que Openbox requiere una etiqueta label="" definida también para los elementos de nivel superior, pero para simplificar, labwc los maneja con o sin el atributo label.

menu.icon

Un icono a renderizar, mostrado en su padre. Este argumento es opcional. Consulte menu.item.icon para más detalles.

menu.item.label

El nombre visible del elemento del menú.

menu.item.icon

El nombre de un icono a renderizar delante de la entrada del menú. Este atributo es opcional. El nombre sigue las convenciones de nomenclatura de las entradas "Icon=" en los archivos .desktop. Si se utiliza, se recomienda usar solo el nombre del icono en lugar de una ruta completa. Esto asegura que el icono se buscará en la escala de la salida donde se renderiza el menú. Por ejemplo, se sugiere el uso de icon="vlc" en lugar de icon="/usr/share/icons/hicolor/16x16/apps/vlc.png".

menu.item.action

Consulte labwc-actions(5). Nota: Se admite XML CDATA para este nodo con el fin de mantener la compatibilidad con obmenu-generator.

menu.separator

Línea horizontal.

menu.separator.label

En un elemento "separator", el atributo label transforma el separador de una línea horizontal a un título de menú (encabezado) con el texto especificado por label en él.

menu.execute

Comando a ejecutar para el menú de tubería (pipe menu). Consulte los detalles a continuación.

MENÚS DE TUBERÍA (PIPE MENUS)

Los menús de tubería son menús generados dinámicamente basándose en la salida de scripts o binarios. Se llaman así porque la salida del ejecutable se canaliza al menú de labwc.

Para cualquier entrada <menu id="" label="" execute="COMANDO"/> en menu.xml, el COMANDO se ejecutará la primera vez que se seleccione el elemento (por ejemplo, con el cursor o la entrada del teclado). La salida XML del comando se analizará y se mostrará como un submenú. El contenido de los pipemenus se almacena en caché hasta que se cierra todo el menú (no solo el pipemenu).

El contenido de la salida debe estar completamente encerrado dentro de las etiquetas <openbox_pipe_menu>. Dentro de ellas, los menús se especifican de la misma manera que los menús estáticos (normales), por ejemplo:

<openbox_pipe_menu>
  <item label="Terminal">
    <action name="Execute" command="xterm"/>
  </item>
</openbox_pipe_menu>

Se admiten submenús en línea y pipemenus anidados.

Tenga en cuenta que es responsabilidad del ejecutable del pipemenu asegurar que los atributos ID sean únicos. Los duplicados se ignoran.

Al escribir scripts de pipemenu, asegúrese de escapar los caracteres especiales de XML como "&" ("&amp;"), "<" ("&lt;") y ">" ("&gt;").

Un pipemenu también se puede utilizar para definir el elemento de nivel superior <menu>. En este caso, todo el archivo menu.xml se reduciría a algo como esto (reemplazando obmenu-generator con el generador de menús de su elección):

<?xml version="1.0"?>
<openbox_menu>
  <menu id="root-menu" label="" execute="obmenu-generator"/>
</openbox_menu>

LOCALIZACIÓN

La localización disponible para el "client-menu" por defecto solo se muestra si no hay un "client-menu" presente en menu.xml. Cualquier definición de menú en menu.xml se interpreta como una anulación por parte del usuario.
