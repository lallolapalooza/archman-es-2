subrutina dlasv2 (doble precisión f, doble precisión g, doble precisión h, doble precisión ssmin, doble precisión ssmax, doble precisión snr, doble precisión csr, doble precisión snl, doble precisión csl)

DLASV2 calcula la descomposición de valores singulares de una matriz triangular de 2x2.

Propósito:

!>
!> DLASV2 calcula la descomposición de valores singulares de una matriz
!> triangular de 2x2
!>    [  F   G  ]
!>    [  0   H  ].
!> Al regresar, abs(SSMAX) es el valor singular mayor, abs(SSMIN) es el
!> valor singular menor, y (CSL,SNL) y (CSR,SNR) son los vectores
!> singulares izquierdo y derecho para abs(SSMAX), dando la descomposición
!>
!>    [ CSL  SNL ] [  F   G  ] [ CSR -SNR ]  =  [ SSMAX   0   ]
!>    [-SNL  CSL ] [  0   H  ] [ SNR  CSR ]     [  0    SSMIN ].
!>

Parámetros

F 
!>          F es DOBLE PRECISIÓN
!>          El elemento (1,1) de la matriz de 2x2.
!>

G

!>          G es DOBLE PRECISIÓN
!>          El elemento (1,2) de la matriz de 2x2.
!>

H

!>          H es DOBLE PRECISIÓN
!>          El elemento (2,2) de la matriz de 2x2.
!>

SSMIN

!>          SSMIN es DOBLE PRECISIÓN
!>          abs(SSMIN) es el valor singular menor.
!>

SSMAX

!>          SSMAX es DOBLE PRECISIÓN
!>          abs(SSMAX) es el valor singular mayor.
!>

SNL

!>          SNL es DOBLE PRECISIÓN
!>

CSL

!>          CSL es DOBLE PRECISIÓN
!>          El vector (CSL, SNL) es un vector singular izquierdo unitario
!>          para el valor singular abs(SSMAX).
!>

SNR

!>          SNR es DOBLE PRECISIÓN
!>

CSR

!>          CSR es DOBLE PRECISIÓN
!>          El vector (CSR, SNR) es un vector singular derecho unitario
!>          para el valor singular abs(SSMAX).
!>

Detalles Adicionales:

!>
!>  Cualquier parámetro de entrada puede ser aliased con cualquier
!>  parámetro de salida.
!>
!>  Aparte de los desbordamientos/subdesbordamientos y asumiendo un dígito
!>  de guarda en la resta, todas las cantidades de salida son correctas
!>  dentro de unas pocas unidades en el último lugar (ulps).
!>
!>  En aritmética IEEE, el código funciona correctamente si un elemento de
!>  la matriz es infinito.
!>
!>  El desbordamiento no ocurrirá a menos que el valor singular más grande
!>  en sí mismo se desborde o esté a unas pocas ulps del desbordamiento.
!>
!>  El subdesbordamiento es inofensivo si es gradual. De lo contrario, los
!>  resultados pueden corresponder a una matriz modificada por
!>  perturbaciones de tamaño cercano al umbral de subdesbordamiento.
!>

lasv(3) - LinuX Assumed State Vector

2 de febrero de 2023

NOMBRE

lasv - Vector de Estado Asumido de LinuX

DESCRIPCIÓN

lasv es una estructura de datos definida en el kernel de Linux para almacenar el estado de un hilo de usuario. Contiene información sobre el estado de ejecución del hilo, como sus registros, puntero de pila, etc.

La estructura lasv se utiliza principalmente en el contexto de la depuración y la manipulación de hilos en tiempo de ejecución. Permite a las herramientas de depuración inspeccionar y modificar el estado de un hilo.

ESTRUCTURA

La estructura lasv se define en el archivo de cabecera /usr/include/asm/lasv.h y tiene el siguiente aspecto (la definición exacta puede variar entre versiones del kernel):

struct lasv {
    unsigned long   regs[32];       /* Registros de propósito general */
    unsigned long   pc;             /* Contador de programa */
    unsigned long   sp;             /* Puntero de pila */
    unsigned long   flags;          /* Indicadores de estado del procesador */
    /* ... otros campos relevantes ... */
};

CAMPOS

regs
Un array que almacena los 32 registros de propósito general del procesador.
pc
El valor del contador de programa (Program Counter), que indica la dirección de la próxima instrucción a ejecutar.
sp
El valor del puntero de pila (Stack Pointer), que apunta a la cima de la pila del hilo.
flags
Indicadores del estado del procesador (por ejemplo, indicadores de cero, acarreo, etc.).

USO

La estructura lasv no se utiliza directamente por las aplicaciones de usuario en la mayoría de los casos. Su acceso y manipulación se realizan principalmente a través de llamadas al sistema o interfaces de depuración proporcionadas por el kernel, como:

  • ptrace(PTRACE_GETREGSET, pid, NT_LASCV, &lasv): Para obtener el vector de estado asumido de un hilo.
  • ptrace(PTRACE_SETREGSET, pid, NT_LASCV, &lasv): Para establecer el vector de estado asumido de un hilo.

Estas llamadas al sistema permiten a los depuradores (como GDB) examinar y controlar la ejecución de otros procesos/hilos.

VER TAMBIÉN

ptrace(2)
