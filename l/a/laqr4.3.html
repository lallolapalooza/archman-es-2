subrutina claqr4 (logical wantt, logical wantz, integer n, integer ilo, integer ihi, complex, dimension( ldh, * ) h, integer ldh, complex, dimension( * ) w, integer iloz, integer ihiz, complex, dimension( ldz, * ) z, integer ldz, complex, dimension( * ) work, integer lwork, integer info)

CLAQR4 calcula los valores propios de una matriz de Hessenberg, y opcionalmente las matrices de la descomposición de Schur.

Propósito:

!>
!>    CLAQR4 implementa un nivel de recursión para CLAQR0.
!>    Es una implementación completa del algoritmo QR multi-paso de Hessenberg
!>    con "bulos" múltiples. Puede ser llamada por CLAQR0 y, para un tamaño de
!>    ventana de deflación suficientemente grande, puede ser llamada por CLAQR3.
!>    Esta subrutina es idéntica a CLAQR0 excepto en que llama a CLAQR2
!>    en lugar de CLAQR3.
!>
!>    CLAQR4 calcula los valores propios de una matriz de Hessenberg H
!>    y, opcionalmente, las matrices T y Z de la descomposición de Schur
!!>    H = Z T Z**H, donde T es una matriz triangular superior (la
!>    forma de Schur), y Z es la matriz unitaria de los vectores de Schur.
!>
!>    Opcionalmente, Z puede ser post-multiplicada en una matriz unitaria
!>    de entrada Q de modo que esta rutina pueda dar la factorización de Schur
!>    de una matriz A que ha sido reducida a la forma de Hessenberg H
!>    por la matriz unitaria Q:  A = Q*H*Q**H = (QZ)*H*(QZ)**H.
!>

Parámetros

WANTT 
!>          WANTT es LOGICAL
!>          = .TRUE. : se requiere la forma de Schur completa T;
!>          = .FALSE.: sólo se requieren los valores propios.
!>

WANTZ

!>          WANTZ es LOGICAL
!>          = .TRUE. : se requiere la matriz de vectores de Schur Z;
!>          = .FALSE.: no se requieren vectores de Schur.
!>

N

!>          N es INTEGER
!>           El orden de la matriz H.  N >= 0.
!>

ILO

!>          ILO es INTEGER
!>

IHI

!>          IHI es INTEGER
!>           Se asume que H ya es triangular superior en las filas
!>           y columnas 1:ILO-1 y IHI+1:N y, si ILO > 1,
!>           H(ILO,ILO-1) es cero. ILO e IHI normalmente son establecidos por una
!>           llamada previa a CGEBAL, y luego pasados a CGEHRD cuando la
!>           matriz de salida de CGEBAL se reduce a la forma de Hessenberg.
!>           De lo contrario, ILO e IHI deberían ser establecidos a 1 y N,
!>           respectivamente.  Si N > 0, entonces 1 <= ILO <= IHI <= N.
!>           Si N = 0, entonces ILO = 1 e IHI = 0.
!>

H

!>          H es array COMPLEX, dimension (LDH,N)
!>           En la entrada, la matriz de Hessenberg superior H.
!>           En la salida, si INFO = 0 y WANTT es .TRUE., entonces H
!>           contiene la matriz triangular superior T de la descomposición
!>           de Schur (la forma de Schur). Si INFO = 0 y WANT es
!>           .FALSE., entonces el contenido de H no está especificado en la salida.
!>           (El valor de salida de H cuando INFO > 0 se da bajo la
!>           descripción de INFO a continuación.)
!>
!>           Esta subrutina puede establecer explícitamente H(i,j) = 0 para i > j y
!>           j = 1, 2, ... ILO-1 o j = IHI+1, IHI+2, ... N.
!>

LDH

!>          LDH es INTEGER
!>           La dimensión principal del array H. LDH >= max(1,N).
!>

W

!>          W es array COMPLEX, dimension (N)
!>           Los valores propios calculados de H(ILO:IHI,ILO:IHI) se almacenan
!>           en W(ILO:IHI). Si WANTT es .TRUE., entonces los valores propios se
!>           almacenan en el mismo orden que en la diagonal de la forma
!>           de Schur devuelta en H, con W(i) = H(i,i).
!>

ILOZ

!>          ILOZ es INTEGER
!>

IHIZ

!>          IHIZ es INTEGER
!>           Especifican las filas de Z a las que se deben aplicar las
!>           transformaciones si WANTZ es .TRUE..
!>           1 <= ILOZ <= ILO; IHI <= IHIZ <= N.
!>

Z

!>          Z es array COMPLEX, dimension (LDZ,IHI)
!>           Si WANTZ es .FALSE., entonces Z no se referencia.
!>           Si WANTZ es .TRUE., entonces Z(ILO:IHI,ILOZ:IHIZ) es
!>           reemplazado por Z(ILO:IHI,ILOZ:IHIZ)*U donde U es el
!>           factor de Schur ortogonal de H(ILO:IHI,ILO:IHI).
!>           (El valor de salida de Z cuando INFO > 0 se da bajo
!>           la descripción de INFO a continuación.)
!>

LDZ

!>          LDZ es INTEGER
!>           La dimensión principal del array Z.  si WANTZ es .TRUE.
!>           entonces LDZ >= MAX(1,IHIZ).  De lo contrario, LDZ >= 1.
!>

WORK

!>          WORK es array COMPLEX, dimension LWORK
!>           En la salida, si LWORK = -1, WORK(1) devuelve una estimación de
!>           el valor óptimo para LWORK.
!>

LWORK

!>          LWORK es INTEGER
!>           La dimensión del array WORK.  LWORK >= max(1,N)
!>           es suficiente, pero típicamente LWORK de hasta 6*N puede
!>           ser requerido para un rendimiento óptimo.  Se recomienda una
!>           consulta de espacio de trabajo para determinar el tamaño óptimo del
!>           espacio de trabajo.
!>
!>           Si LWORK = -1, entonces CLAQR4 realiza una consulta de espacio de
!>           trabajo.
!>           En este caso, CLAQR4 verifica los parámetros de entrada y
!>           estima el tamaño óptimo del espacio de trabajo para los
!>           valores dados de N, ILO e IHI.  La estimación se devuelve
!>           en WORK(1).  XERBLA no emite ningún mensaje de error relacionado
!>           con LWORK.  Ni H ni Z son accedidos.
!>

INFO

!>          INFO es INTEGER
!>             = 0:  salida exitosa
!>             > 0:  si INFO = i, CLAQR4 falló al calcular todos los
!>                valores propios.  Los elementos 1:ilo-1 y i+1:n de WR
!>                y WI contienen aquellos valores propios que se han
!>                calculado con éxito.  (Los fallos son raros.)
!>
!>                Si INFO > 0 y WANT es .FALSE., entonces en la salida,
!>                los valores propios no convergidos restantes son los valores
!>                propios de la matriz de Hessenberg superior de las filas
!>                y columnas ILO a INFO del valor final de H.
!>
!>                Si INFO > 0 y WANTT es .TRUE., entonces en la salida
!>
!>           (*)  (H inicial)*U  = U*(H final)
!>
!>                donde U es una matriz unitaria.  La H final
!>                es de Hessenberg superior y triangular en
!>                las filas y columnas INFO+1 a IHI.
!>
!>                Si INFO > 0 y WANTZ es .TRUE., entonces en la salida
!>
!>                  (Z final(ILO:IHI,ILOZ:IHIZ)
!>                   =  (Z inicial(ILO:IHI,ILOZ:IHIZ)*U
!>
!>                donde U es la matriz unitaria en (*) (independientemente
!>                del valor de WANTT.)
!>
!>                Si INFO > 0 y WANTZ es .FALSE., entonces Z no se
!>                accede.
!>

NAME

zlaqr4 - The complex16 version of the implicit double shift QR algorithm in matrix form.

SYNOPSIS

subroutine zlaqr4(WANTT, WANTZ, N, ILO, IHI, H, LDH, W, ILOZ, IHIZ, Z, LDZ, WORK, LWORK, INFO)
    logical :: WANTT, WANTZ
    integer :: N, ILO, IHI, LDH, ILOZ, IHIZ, LWORK, INFO
    complex*16 :: H(LDH, N), W(N), Z(LDZ, *), WORK(LWORK)

Detailed Description

This subroutine computes the eigenvalues and Schur factorization of a complex upper Hessenberg matrix H. This routine is the fourth of five routines that implement the complex double shift QR algorithm in matrix form.

The algorithm is based on the QR algorithm described in:

K.
Braman, R. Byers, and R. Mathias, "The Multi-Shift QR Algorithm Part I: Maintaining Well Focused Shifts, and Level 3 Performance," SIAM Journal of Matrix Analysis, volume 23, pages 929--947, 2002.
K.
Braman, R. Byers, and R. Mathias, "The Multi-Shift QR Algorithm Part II: Aggressive Early Deflation," SIAM Journal of Matrix Analysis, volume 23, pages 948--973, 2002.

The purpose of the routines is to provide a robust and efficient implementation of the Schur decomposition for matrices that arise from random matrix theory or other applications.

The algorithm is described in detail in the above-referenced papers. The main features of the algorithm are:

- Aggressive early deflation:
The algorithm attempts to deflate the matrix H by finding blocks of eigenvalues and transforming them into diagonal blocks. This process is performed aggressively, meaning that it is attempted at every step of the algorithm.
- Multi-shift QR algorithm:
The algorithm uses a multi-shift QR algorithm to compute the Schur decomposition. This algorithm uses multiple shifts simultaneously, which can significantly improve the convergence of the algorithm.
- Level 3 BLAS:
The algorithm is implemented using Level 3 BLAS routines, which can significantly improve performance on modern hardware.
