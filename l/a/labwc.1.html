labwc(1) Manual de Comandos Generales labwc(1)

NOMBRE

labwc - un compositor de apilamiento para Wayland

SINOPSIS

labwc [opciones...]

DESCRIPCIÓN

Labwc es un compositor de apilamiento basado en wlroots para Wayland.

Es ligero e independiente, centrándose en apilar ventanas de forma eficiente y renderizar algunas decoraciones de ventanas. Cuando sea factible, utiliza clientes para el fondo de pantalla, paneles, capturas de pantalla, etc.

SEÑALES

El compositor saldrá o recargará su configuración al recibir SIGTERM y SIGHUP respectivamente. Por ejemplo:

kill -s <señal> $LABWC_PID
killall -s <señal> labwc

Cada instancia en ejecución de labwc establece la variable de entorno `LABWC_PID` a su PID. Esto es útil para enviar señales a una instancia específica y es lo que usan las opciones `--exit` y `--reconfigure`.

OPCIONES

-c, --config <archivo-config>

Especifica un archivo de configuración con la ruta

-C, --config-dir <directorio-config>

Especifica un directorio de configuración

-d, --debug

Habilita el registro completo, incluida la información de depuración. Consulte la sección VARIABLES DE ENTORNO para ver más opciones.

-e, --exit

Sale del compositor enviando SIGTERM a `$LABWC_PID`

-h, --help

Muestra el mensaje de ayuda y sale

-m, --merge-config

Fusiona los archivos de configuración/tema del usuario en todos los Directorios Base XDG

-r, --reconfigure

Recarga la configuración del compositor enviando SIGHUP a `$LABWC_PID`

-s, --startup <comando>

Ejecuta un comando al inicio

-S, --session <comando>

Ejecuta un comando al inicio y termina el compositor al salir. Esto es útil para la gestión de sesiones, ya que permite que el cliente de sesión termine labwc al salir. Este es un caso de uso específico de Wayland porque en X, xinit inicia el servidor y lo mantiene activo mientras dure el cliente de sesión. Por lo tanto, o bien el cliente de sesión inicia el Gestor de Ventanas, o bien el Gestor de Ventanas puede iniciarse independientemente primero. En Wayland, el Compositor es tanto el Servidor de Pantalla como el Gestor de Ventanas, por lo que los mecanismos de gestión de sesiones descritos no funcionan porque el Compositor debe estar en ejecución antes de que la sesión pueda funcionar. Como algunos clientes de sesión son compatibles tanto con X11 como con Wayland, esta opción de línea de comandos evita reescrituras y fragmentación.

-v, --version

Muestra el número de versión y sale

-V, --verbose

Habilita un registro más detallado

GESTIÓN DE SESIÓN

Para habilitar el uso de clientes gráficos lanzados a través de D-Bus o activación de servicios systemd, labwc puede actualizar ambos entornos de activación al iniciarse. Siempre que labwc sea consciente de una sesión de usuario D-Bus activa (es decir, la variable de entorno `DBUS_SESSION_BUS_ADDRESS` esté definida), el compositor invocará los comandos

dbus-update-activation-environment
systemctl --user import-environment

(cuando estén disponibles) para notificar a D-Bus y systemd con los valores de las siguientes variables de entorno:

WAYLAND_DISPLAY
DISPLAY
XDG_CURRENT_DESKTOP
XDG_SESSION_TYPE
XCURSOR_SIZE
XCURSOR_THEME
LABWC_PID

Este comportamiento está habilitado por defecto siempre que labwc utilice el backend wlroots "DRM" (lo que implica que labwc es el compositor principal en la consola). Cuando se utilizan otros backends (por ejemplo, cuando labwc se ejecuta anidado en otro compositor Wayland o en un servidor X11), las actualizaciones del entorno de activación están deshabilitadas por defecto. Las actualizaciones del entorno de activación se pueden forzar estableciendo la variable de entorno `LABWC_UPDATE_ACTIVATION_ENV` a uno de los valores verdaderos `1`, `true`, `yes` o `on`; o suprimir estableciendo la variable a uno de los valores falsos `0`, `false`, `no` u `off`.

Siempre que labwc actualice el entorno de activación al iniciarse, también intentará limpiar el entorno de activación al salir. Para D-Bus, que no proporciona un medio para desestablecer correctamente las variables en el entorno de activación, esto se logra estableciendo las variables de sesión a cadenas vacías. Para systemd, se invocará el comando `systemctl --user unset-environment` para eliminar realmente las variables del entorno de activación.

VARIABLES DE ENTORNO

Establezca las variables de entorno que se enumeran a continuación para habilitar opciones de depuración específicas. Esto se puede hacer en el archivo environment o en la línea de comandos, por ejemplo: LABWC_DEBUG_FOO=1 labwc.

LABWC_DEBUG_LIBSFDO

Habilita el registro de depuración e información para libsfdo, por ejemplo, para analizar archivos de escritorio y buscar iconos. Tenga en cuenta que el registro de errores de libsfdo siempre está habilitado independientemente de esta variable de entorno, pero solo se mostrará con la opción -V|--version.

LABWC_DEBUG_DIR_CONFIG_AND_THEME

Aumenta el registro de rutas para archivos de configuración (por ejemplo, rc.xml, autostart, environment y menu.xml) así como botones de la barra de título.

LABWC_DEBUG_CONFIG_NODENAMES

Habilita el registro de todos los nombres de nodos (por ejemplo, policy.placement: Cascade para <placement><policy>Cascade</policy></placement>) para los archivos de configuración y menú respectivamente.

LABWC_DEBUG_KEY_STATE

Habilita el registro de eventos de pulsación y liberación para teclas enlazadas (generalmente combinaciones de teclas como Ctrl-Alt-t)
