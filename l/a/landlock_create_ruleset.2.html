landlock_create_ruleset(2) Manual de llamadas al sistema landlock_create_ruleset(2)

NOMBRE

landlock_create_ruleset - crear un nuevo conjunto de reglas de Landlock

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/landlock.h>  /* Definición de constantes LANDLOCK_* */
#include <sys/syscall.h>     /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_landlock_create_ruleset,
            const struct landlock_ruleset_attr *attr,
            size_t size , uint32_t flags);

DESCRIPCIÓN

Un conjunto de reglas de Landlock identifica un conjunto de reglas (es decir, acciones sobre objetos). Esta llamada al sistema landlock_create_ruleset() crea un nuevo descriptor de archivo que identifica un conjunto de reglas. Este descriptor de archivo puede ser usado luego por landlock_add_rule(2) y landlock_restrict_self(2). Ver landlock(7) para una visión general.

attr especifica las propiedades del nuevo conjunto de reglas. Apunta a la siguiente estructura:


struct landlock_ruleset_attr {
    __u64 handled_access_fs;
    __u64 handled_access_net;
};

handled_access_fs es una máscara de bits de las acciones del sistema de archivos manejadas (ver Acciones del sistema de archivos en landlock(7)).
handled_access_net es una máscara de bits de las acciones de red manejadas (ver Acciones de red en landlock(7)).
Esta estructura define un conjunto de derechos de acceso manejados, un conjunto de acciones sobre diferentes tipos de objetos, que deben ser denegados por defecto cuando se activa el conjunto de reglas. A la inversa, los derechos de acceso que no están listados específicamente aquí no serán denegados por este conjunto de reglas cuando se active.
Por razones históricas, el derecho LANDLOCK_ACCESS_FS_REFER siempre se deniega por defecto, incluso cuando su bit no está activado en handled_access_fs. Para poder añadir nuevas reglas con este derecho de acceso, el bit aún debe ser activado explícitamente (ver Acciones del sistema de archivos en landlock(7)).
La lista explícita de derechos de acceso manejados es necesaria por razones de retrocompatibilidad. En la mayoría de los casos de uso, los procesos que utilizan Landlock manejarán una amplia gama o todos los derechos de acceso que conozcan en tiempo de compilación (y que hayan probado con un kernel que los soportara todos).
Esta estructura puede crecer en futuras versiones de Landlock.

size debe especificarse como sizeof(struct landlock_ruleset_attr) por razones de compatibilidad.

flags debe ser 0 si se utiliza attr. De lo contrario, flags puede establecerse a:

LANDLOCK_CREATE_RULESET_VERSION
Si attr es NULL y size es 0, entonces el valor devuelto es la versión más alta de la ABI de Landlock soportada (comenzando en 1). Esta versión puede ser utilizada para un enfoque de seguridad de mejor esfuerzo, lo cual es alentado cuando el espacio de usuario no está fijado a una versión de kernel específica. Todas las características documentadas en estas páginas de manual están disponibles con la versión 1.

VALOR DE RETORNO

En caso de éxito, landlock_create_ruleset() devuelve un nuevo descriptor de archivo de conjunto de reglas de Landlock, o una versión de la ABI de Landlock, de acuerdo con flags. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

landlock_create_ruleset() puede fallar por las siguientes razones:

EOPNOTSUPP
Landlock es soportado por el kernel pero está deshabilitado en el arranque.
EINVAL
flags desconocidos, o acceso desconocido, o size demasiado pequeño.
E2BIG
size es demasiado grande.
EFAULT
attr no era una dirección válida.
ENOMSG
Accesos vacíos (es decir, attr no especificó ningún derecho de acceso para restringir).

ESTÁNDARES

Linux.

HISTORIA

Linux 5.13.
