landlock_add_rule(2) Manual de llamadas al sistema landlock_add_rule(2)

NOMBRE

landlock_add_rule - añadir una nueva regla de Landlock a un conjunto de reglas

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <linux/landlock.h>  /* Definición de constantes LANDLOCK_* */
#include <sys/syscall.h>     /* Definición de constantes SYS_* */
int syscall(SYS_landlock_add_rule, int ruleset_fd,
            enum landlock_rule_type rule_type,
            const void *rule_attr, uint32_t flags);

DESCRIPCIÓN

Una regla de Landlock describe una acción sobre un objeto que el proceso pretende realizar. Un conjunto de reglas se agrega en un conjunto de reglas (ruleset), que luego puede restringir el hilo que lo aplica y sus futuros hijos.

La llamada al sistema landlock_add_rule() añade una nueva regla de Landlock a un conjunto de reglas existente. Ver landlock(7) para una visión general.

ruleset_fd es un descriptor de archivo de conjunto de reglas de Landlock obtenido con landlock_create_ruleset(2).

rule_type identifica el tipo de estructura al que apunta rule_attr. Actualmente, Linux soporta los siguientes valores de rule_type:

LANDLOCK_RULE_PATH_BENEATH
Para estas reglas, el objeto es una jerarquía de archivos y las acciones relacionadas en el sistema de archivos se definen con derechos de acceso al sistema de archivos.
En este caso, rule_attr apunta a la siguiente estructura:

struct landlock_path_beneath_attr {
    __u64 allowed_access;
    __s32 parent_fd;
} __attribute__((packed));

allowed_access contiene una máscara de bits de las acciones permitidas en el sistema de archivos, que pueden aplicarse en el parent_fd dado (ver Acciones del sistema de archivos en landlock(7)).
parent_fd es un descriptor de archivo abierto, preferiblemente con la bandera O_PATH, que identifica el directorio padre de la jerarquía de archivos o simplemente un archivo.
LANDLOCK_RULE_NET_PORT
Para estas reglas, el objeto es un puerto TCP y las acciones relacionadas se definen con derechos de acceso a la red.
En este caso, rule_attr apunta a la siguiente estructura:

struct landlock_net_port_attr {
    __u64 allowed_access;
    __u64 port;
};

allowed_access contiene una máscara de bits de las acciones de red permitidas, que pueden aplicarse en el puerto dado.
port es el puerto de red en orden de bytes del host.
Cabe señalar que el puerto 0 pasado a bind(2) se vinculará a un puerto disponible del rango de puertos efímeros. Esto se puede configurar en el sysctl /proc/sys/net/ipv4/ip_local_port_range (también utilizado para IPv6).
Una regla de Landlock con puerto 0 y el derecho LANDLOCK_ACCESS_NET_BIND_TCP significa que se permite solicitar la vinculación al puerto 0 y se traducirá automáticamente a la vinculación al rango de puertos relacionado.

flags debe ser 0.

VALOR DEVUELTO

En caso de éxito, landlock_add_rule() devuelve 0. En caso de error, devuelve -1 y se establece errno para indicar el error.

ERRORES

landlock_add_rule() puede fallar por las siguientes razones:

EAFNOSUPPORT
rule_type es LANDLOCK_RULE_NET_PORT, pero TCP no es soportado por el kernel en ejecución.
EOPNOTSUPP
Landlock es soportado por el kernel pero deshabilitado en el tiempo de arranque.
EINVAL
flags no es 0.
EINVAL
Los accesos de la regla son inconsistentes (es decir, rule_attr->allowed_access no es un subconjunto de los accesos manejados por el conjunto de reglas).
EINVAL
En struct landlock_path_beneath_attr, los accesos de la regla no son aplicables al archivo (es decir, algunos derechos de acceso en rule_attr->allowed_access solo son aplicables a directorios, pero rule_attr->parent_fd no se refiere a un directorio).
EINVAL
En struct landlock_net_port_attr, el número de puerto es mayor que 65535.
ENOMSG
Accesos vacíos (es decir, rule_attr->allowed_access es 0).
EBADF
ruleset_fd no es un descriptor de archivo para el hilo actual, o un miembro de rule_attr no es un descriptor de archivo como se esperaba.
EBADFD
ruleset_fd no es un descriptor de archivo de conjunto de reglas, o un miembro de rule_attr no es del tipo de descriptor de archivo esperado.
EPERM
ruleset_fd no tiene acceso de escritura al conjunto de reglas subyacente.
EFAULT
rule_attr no era una dirección válida.

ESTÁNDARES

Linux.

HISTORIA

landlock_add_rule.2.es

landlock_add_rule(2)

NOMBRE

landlock_add_rule - añadir una regla al sandbox de Landlock

SINOPSIS

#include <linux/landlock.h>

int landlock_add_rule(struct landlock_context *ctx, uint64_t flags, const struct attr_area *area, const struct attr_fs_ops *fs_ops, const struct attr_net_ops *net_ops, const struct attr_process_ops *process_ops);

DESCRIPCIÓN

La llamada al sistema landlock_add_rule añade una regla al contexto de sandbox de Landlock especificado por ctx.

ctx es un puntero a un struct landlock_context obtenido de una llamada anterior a landlock_create_ruleset.

flags es un campo de bits de banderas que modifican el comportamiento de la regla. Actualmente, no hay banderas definidas para flags y debe ser 0.

area es un puntero a un struct attr_area que especifica el área del sistema de archivos a la que se aplica la regla.

fs_ops es un puntero a un struct attr_fs_ops que especifica las operaciones del sistema de archivos permitidas o denegadas.

net_ops es un puntero a un struct attr_net_ops que especifica las operaciones de red permitidas o denegadas.

process_ops es un puntero a un struct attr_process_ops que especifica las operaciones de proceso permitidas o denegadas.

Los argumentos area, fs_ops, net_ops y process_ops solo deben especificarse si la regla se aplica a la categoría correspondiente. Por ejemplo, si la regla se aplica a operaciones de sistema de archivos, area y fs_ops deben especificarse, y net_ops y process_ops deben ser NULL.

La regla se aplica a todos los procesos que se ejecutan dentro del sandbox asociado con ctx. Si un proceso intenta realizar una operación que está restringida por la regla, la operación será denegada.

DEVOLUCIONES

En caso de éxito, landlock_add_rule devuelve 0. En caso de error, devuelve -1 y errno se establece apropiadamente.

ERRORES

EBADF
ctx no es un descriptor de archivo válido.
EINVAL
Se especificó un argumento inválido, o no se especificó ningún argumento de operación.
ENOMEM
No hay suficiente memoria para añadir la regla.
EPERM
El proceso actual no tiene permiso para añadir la regla.

VERSIÓN

La llamada al sistema landlock_add_rule está disponible desde el kernel de Linux 5.13.

CONFORME A

landlock_add_rule es una llamada al sistema específica de Linux y no forma parte de ningún estándar.

VER TAMBIÉN

landlock_create_ruleset(2), landlock_restrict_self(2), landlock_remove_rule(2)
