NOMBRE

latexdiff - determinar y marcar diferencias entre dos archivos latex

SINOPSIS

latexdiff [ OPCIONES ] antiguo.tex nuevo.tex > diff.tex

DESCRIPCIÓN

Brevemente, latexdiff es un programa de utilidad para ayudar en la gestión de revisiones de documentos latex. Compara dos archivos latex válidos, aquí llamados "antiguo.tex" y "nuevo.tex", encuentra diferencias significativas entre ellos (es decir, ignorando el número de espacios en blanco y la posición de los saltos de línea), y añade comandos especiales para resaltar las diferencias. Donde el resaltado visual no es posible, p. ej., para cambios en el formato, las diferencias se marcan de todos modos en el código fuente. Tenga en cuenta que antiguo.tex y nuevo.tex deben ser archivos reales (no pipes o similares) ya que se abren dos veces (a menos que se utilice la opción "--encoding")

El programa trata el preámbulo de manera diferente al documento principal. Las diferencias entre los preámbulos se encuentran utilizando la diferencia basada en líneas (similar al comando diff de Unix, pero ignorando los espacios en blanco). Un comentario, ""%DIF >"", se añade a cada línea agregada, es decir, una línea presente en "nuevo.tex" pero no en "antiguo.tex". Las líneas descartadas
se desactivan anteponiendo ""%DIF <"". Los bloques cambiados van precedidos por líneas de comentario que dan información sobre los números de línea en los archivos originales. Donde hay diferencias insignificativas, el archivo resultante "diff.tex" será similar a "nuevo.tex". Al final del preámbulo, se insertan las definiciones para los comandos de marcado de latexdiff. Al comparar el cuerpo principal del texto, latexdiff intenta satisfacer las siguientes directrices (en orden de prioridad):

1.
Si tanto "antiguo.tex" como "nuevo.tex" son LaTeX válidos, entonces el resultado "diff.tex" también debería ser LateX válido. (NB Si se utilizan algunos comandos TeX planos dentro de "antiguo.tex" o "nuevo.tex", entonces no se garantiza que "diff.tex" funcione, pero generalmente lo hará).
2.
Las diferencias significativas se determinan a nivel de palabras individuales. Todas las diferencias significativas, incluidas las diferencias entre comentarios, deben marcarse claramente en el código fuente resultante "diff.tex".
3.
Si un pasaje modificado contiene texto o comandos que producen texto, entonces la ejecución de "diff.tex" a través de LateX debería producir una salida donde los pasajes añadidos y descartados estén resaltados.
4.
Donde haya diferencias insignificativas, p. ej., en la posición de los saltos de línea, "diff.tex" debería seguir el formato de "nuevo.tex"

Para comparar, se utiliza el mismo algoritmo que diff, pero se comparan palabras en lugar de líneas. Se intenta reconocer bloques que se modifican completamente para que puedan marcarse como una unidad. Los comentarios se comparan línea por línea, pero se ignora el número de espacios dentro de los comentarios. Los comandos, incluidos todos sus argumentos, se comparan generalmente como una unidad, es decir, no se inserta ningún marcado en los argumentos de los comandos. Sin embargo, para un número seleccionado de comandos (por ejemplo, "\caption" y todos los comandos de sección) se sabe que el último argumento es texto. Este texto se divide en palabras y se compara como texto ordinario (use las opciones para mostrar y cambiar la lista de comandos de texto, véase más abajo). Dado que el algoritmo no tiene un conocimiento detallado de LaTeX, asume que todos los pares de llaves que siguen inmediatamente a un comando (es decir, una secuencia de letras que comienza con una barra invertida) son argumentos para ese comando. Como restricción a la condición 1 anterior, es necesario rodear todos los argumentos con llaves y no insertar espacios extraños. Por ejemplo, escriba

\section{\textem{Este es un título de sección enfatizado}}

y no

\section {\textem{Este es un título de sección enfatizado}}

o

\section\textem{Este es un título de sección enfatizado}

aunque todas las variedades son lo mismo para LaTeX (pero vea la opción --allow-spaces que permite la segunda variedad).

Para entornos cuyo contenido no se ajusta al LaTeX estándar o donde el marcado gráfico no tiene sentido, todos los comandos de marcado se pueden eliminar estableciendo la variable de configuración PICTUREENV, establecida por defecto a "picture" y los entornos "DIFnomarkup"; vea la opción --config). El último entorno ("DIFnomarkup") se puede usar para proteger partes del archivo latex donde el marcado resulta en un marcado ilegal. Debe rodear el pasaje infractor tanto en el archivo antiguo como en el nuevo con "\begin{DIFnomarkup}" y "\end{DIFnomarkup}". Debe definir el entorno en los preámbulos de ambos documentos, el antiguo y el nuevo. Yo prefiero definirlo como un entorno nulo,

"\newenvironment{DIFnomarkup}{}{}"

pero la elección es suya. Cualquier marcado dentro del entorno se eliminará, y en general todo dentro del entorno se tomará del nuevo archivo.

También es posible comparar archivos que no tienen preámbulo.
En este caso, el archivo se procesa en modo de documento principal, pero las definiciones de los comandos de marcado no se insertan.

Todos los comandos de marcado insertados por latexdiff comienzan con ""\DIF"". Los bloques añadidos que contienen palabras, comandos o comentarios que están en "nuevo.tex" pero no en "antiguo.tex" se marcan con "\DIFaddbegin" y "\DIFaddend". Los bloques descartados se marcan con "\DIFdelbegin" y "\DIFdelend". Dentro de los bloques añadidos, todo el texto se resalta con "\DIFadd" así: "\DIFadd{Bloque de texto añadido}". Se pueden incluir comandos 'seguros' seleccionados en estos bloques de texto (use las opciones para mostrar y cambiar la lista de comandos seguros, véase más abajo). Todos los demás comandos, así como las llaves "{" y "}", nunca se colocan dentro del alcance de "\DIFadd". Los comentarios añadidos se marcan anteponiendo ""%DIF > "".

Dentro de los bloques eliminados, el texto se resalta con "\DIFdel". Los comentarios eliminados se marcan anteponiendo ""%DIF < "". Los comandos no seguros y las llaves dentro de los bloques eliminados se comentan con ""%DIFDELCMD < "".

--packages=pkg1,pkg2,..
Indica a latexdiff que el archivo .tex se procesa con los paquetes de la lista cargados. Esto normalmente no es necesario si el archivo .tex incluye el preámbulo, ya que el preámbulo se escanea automáticamente en busca de comandos "\usepackage". El uso de la opción --packages deshabilita el escaneo automático, por lo que si por alguna razón el análisis específico del paquete necesita ser desactivado, use --packages=none. "endfloat"
Asegura que "\begin{figure}" y "\end{figure}" siempre aparezcan solos en una línea.
"hyperref"
Cambia el nombre de los comandos "\DIFadd" y "\DIFdel" a "\DIFaddtex" y "\DIFdeltex" y define nuevos comandos "\DIFadd" y "\DIFdel", que proporcionan un envoltorio para estos comandos, usándolos para el texto pero no para el comando de definición de enlace (donde cualquier metamaquetado causaría errores).
"apacite", "biblatex"
Redefine los comandos reconocidos como comandos de cita.
"siunitx"
Trata "\SI" como equivalente a comandos de cita (es decir, protégelo con si el estilo de metamaquetado usa el paquete ulem.
"cleveref"
Trata "\cref,\Cref", etc. como equivalentes a comandos de cita (es decir, protégelos con si el estilo de metamaquetado usa el paquete ulem.
"glossaries"
Define la mayoría de los comandos de glosarios como seguros, protegiéndolos con \mbox donde sea necesario
"mhchem"
Trata "\ce" como un comando seguro, es decir, será resaltado (tenga en cuenta que no será resaltado en ecuaciones ya que esto conduce a errores de procesamiento)
"chemformula" o "chemmacros"
Trata "\ch" como un comando seguro fuera de las ecuaciones, es decir, será resaltado (tenga en cuenta que no será resaltado en ecuaciones ya que esto conduce a errores de procesamiento)

Tipos principales

El tipo principal determina el marcado de texto plano y algunos comandos latex seleccionados fuera de los floats definiendo los comandos de marcado "\DIFadd{...}" y "\DIFdel{...}".

"UNDERLINE"
El texto añadido se subraya onduladamente y en azul, el texto descartado se tacha y en rojo (Requiere los paquetes color y ulem). El tachado no funciona en ecuaciones matemáticas mostradas, por lo que las partes eliminadas de una ecuación se subrayan, no se tachan (esto es una limitación inherente al paquete ulem).
"LUAUNDERLINE"
El texto añadido se subraya y en azul, el texto descartado se tacha y en rojo (Requiere el paquete lua-ul + LuaLaTeX).
"CTRADITIONAL"
El texto añadido es azul y en sans-serif, y se crea una nota al pie en rojo para cada fragmento de texto descartado. (Requiere el paquete color)
"TRADITIONAL"
Similar a "CTRADITIONAL" pero sin usar color.
"CFONT"
El texto añadido es azul y en sans-serif, y el texto descartado es rojo y de tamaño muy pequeño.
"FONTSTRIKE"
El texto añadido está en sans-serif, el texto descartado es pequeño y tachado.
"CCHANGEBAR"
El texto añadido es azul y el texto descartado es rojo. Además, el texto cambiado se marca con una barra en el margen (Requiere los paquetes color y changebar).
"CFONTCHBAR"
Similar a "CFONT" pero con barras de cambio adicionales (Requiere los paquetes color y changebar).
"CULINECHBAR"
Similar a "UNDERLINE" pero con barras de cambio adicionales (Requiere los paquetes color, ulem y changebar).
"CHANGEBAR"
Sin marcado de texto, pero marcando los márgenes con barras de cambio (Requiere el paquete changebar).
"INVISIBLE"
Sin marcado visible (pero se seguirán insertando comandos de marcado genéricos).
"BOLD"
El texto añadido está en negrita, el descartado no se muestra. (ver también la opción --no-del para otra posibilidad de ocultar texto eliminado)
"PDFCOMMENT"
Se utiliza el paquete pdfcomment para subrayar texto nuevo y marcar eliminaciones con un comentario PDF. Tenga en cuenta que este marcado puede aparecer de forma diferente o no aparecer en absoluto dependiendo del visor de PDF utilizado. El visor con mejor soporte para marcado PDF es probablemente acroread. Este estilo solo se recomienda si el número de diferencias es pequeño.

Subtipos

El subtipo define los comandos que se insertan al principio y al final de los bloques añadidos o descartados, independientemente de si estos bloques contienen texto o comandos (Comandos definidos: "\DIFaddbegin, \DIFaddend, \DIFdelbegin, \DIFdelend")

"SAFE"
Sin marcado adicional (Elección recomendada)
"MARGIN"
Marca el principio y el final de los bloques cambiados con símbolos en el margen cercano (usando el comando estándar "\marginpar" - tenga en cuenta que a veces se mueve de su posición prevista).
"COLOR"
Una forma alternativa de marcar los pasajes añadidos en azul y los eliminados en rojo. (Se recomienda usar los tipos principales para obtener un marcado coloreado, aunque en algunos casos colorear con dvipscol puede ser más completo, por ejemplo con comandos de cita).
"DVIPSCOL"
Una forma alternativa de marcar los pasajes añadidos en azul y los eliminados en rojo. Tenga en cuenta que "DVIPSCOL" solo funciona con el conversor dvips, por ejemplo, no con pdflatex. (Se recomienda usar los tipos principales para obtener un marcado coloreado, aunque en algunos casos colorear con dvipscol puede ser más completo).
"ZLABEL"
Se puede usar para resaltar solo páginas cambiadas, pero requiere post-procesamiento. Se recomienda no llamar a esta opción manualmente sino usar "latexdiff-vc" con la opción "--only-changes". Alternativamente, use el script dado dentro del preámbulo de los archivos diff hechos usando este estilo.
"ONLYCHANGEDPAGE"
También resalta páginas cambiadas, sin necesidad de post-procesamiento, pero puede que no funcione de manera fiable si hay material flotante (figuras, tablas).
"LABEL"
Es similar a "ZLABEL", pero no necesita el paquete zref y funciona de forma menos fiable (obsoleto).

Tipos de Floats

Algunos de los marcados utilizados en el texto principal pueden causar problemas cuando se utilizan dentro de floats (por ejemplo, figuras o tablas). Por esta razón, se utilizan versiones alternativas de todos los comandos de marcado dentro de los floats. El tipo de float define estos comandos alternativos.

"FLOATSAFE"
Utiliza el mismo marcado para el texto que en el cuerpo principal, pero establece todos los comandos que marcan el principio y el final de los bloques cambiados como comandos nulos. Debe elegir este tipo de float si su subtipo es "MARGIN", ya que "\marginpar" no funciona correctamente dentro de los floats.
"TRADITIONALSAFE"
Marca las adiciones de la misma manera que en el texto principal. Los entornos eliminados se marcan con corchetes angulares \[ y \] y el texto eliminado se establece en tamaño scriptscript. Este tipo de float debe usarse siempre con los tipos de marcado "TRADITIONAL" y "CTRADITIONAL", ya que el comando \footnote no funciona correctamente en entornos flotantes.
"IDENTICAL"
No hace diferencia entre el texto principal y los floats.

NAME

latexdiff

compares two LaTeX files and highlights the differences.

SYNOPSIS

latexdiff [OPTION]... file1 file2

latexdiff-vc [OPTION]... file1 file2

latexdiff-vc [OPTION]... --git --tag=OLD

latexdiff-vc [OPTION]... --git --rev=OLD..NEW

latexdiff-vc [OPTION]... --svn --rev=OLD

latexdiff-vc [OPTION]... --hg --rev=OLD

DESCRIPTION

This manual page documents the latexdiff and latexdiff-vc programs. latexdiff is a script that generates a LaTeX file highlighting the differences between two other LaTeX files. latexdiff-vc is a wrapper around latexdiff that supports version control systems like Git, Subversion, and Mercurial.

The diff is generated using the Perl module "Algorithm::Diff". The output is a LaTeX file that can be processed by tex(1), latex(1), pdflatex(1), etc. The changes are marked using commands defined in the "ulem" LaTeX package for underlining and striking out text, or alternatively using other methods specified via command-line options.

By default, deleted text is struck out and new text is underlined. This behaviour can be modified using options described below.

The program can be run in two basic modes:

  • Document mode: latexdiff compares two complete LaTeX documents. It automatically tries to detect the document class and preamble to ensure correct diffing.
  • Version control mode: latexdiff-vc uses version control system commands to determine the revisions to compare. It can compare the current working copy against a specific revision, or between two arbitrary revisions.

OPTIONS

The options can be divided into several groups:

--version
Print version information and exit.
--help
Print a help message and exit.
--print-logfile
Print the name of the log file and exit.

Markup options:

-t, --type=MARKUP
Specify the markup style for differences. The following styles are supported:
COLOUR
Uses colors to mark additions and deletions. This is the default if the "color" package is found or specified via "--packages". Added text is typeset in red, deleted text in blue. Requires the "color" package.
CFONT
Uses font changes to mark differences. Added text is typeset in red, deleted text in blue. Requires the "color" package.
UNDERLINE
Uses underlining for additions and strike-out for deletions. This is the default if the "ulem" package is found or specified. Requires the "ulem" package.
RAWBODY
Does not mark up changes. Useful for comparing files without generating LaTeX output.
OLD
Uses the old diff format, with additions marked with "\ins" and deletions with "\del".
NONE
No markup is used. This is equivalent to "RAWBODY".

[ Default: "UNDERLINE" or "COLOUR" depending on available packages ]

--active-linenumbers
Use line numbers for comparison. This option is useful for comparing code snippets or other files where line numbers are significant.

[ Default: 0.0 ]

--allow-spaces
Treat sequences of whitespace characters as equivalent. This option is useful for comparing code where indentation or spacing differences should be ignored.

[ Default: 0.0 ]

--append-mboxsafecmd=CMD
Append command "CMD" to the list of commands that are safe to be enclosed in "\mbox". See also "--excludemboxsafecmd".
--change-env=ENV
Treats environment "ENV" as a changed environment. The contents of this environment are compared, and differences are marked. This option can be specified multiple times.

[ Default: "verbatim\*|lstlisting" ]

--comment-lines=REGEX
Treat lines matching the regular expression "REGEX" as comments. Comments are ignored during comparison. This option can be specified multiple times.

[ Default: "^\\s*\\\\(comment|\%|#)" ]

--context-lines=N
Number of context lines to show around differences.

[ Default: 0 ]

--cvs
Use CVS commands to compare revisions. Implies "latexdiff-vc --cvs".
--delete-comments
Remove comments from the files before comparison. Comments are lines starting with % or #, or environments like comment.

[ Default: 0.0 ]

--diff-prog=PROG
Use external diff program "PROG" instead of the Perl module "Algorithm::Diff". "PROG" must accept diff command line arguments and produce output in unified diff format.
--disable-citation-markup
Do not markup citations. Deleted citations are no longer shown, and added citations are shown without markup.

[ Default: 0.0 ]

--exclude=FILE
Exclude file "FILE" from comparison. This option can be specified multiple times.
--excludemboxsafecmd=CMD
Exclude command "CMD" from being enclosed in "\mbox". See also "--append-mboxsafecmd".
--filter=FILTER
Apply a filter to the diff output. Supported filters are:
basic
Removes all diff-related markup, leaving only the content.
stripper
Strips all LaTeX commands, leaving only plain text.

[ Default: "none" ]

--git
Use Git commands to compare revisions. Implies "latexdiff-vc --git".
--hg
Use Mercurial commands to compare revisions. Implies "latexdiff-vc --hg".
--ignore-case
Ignore case during comparison.

[ Default: 0.0 ]

--ignore-math
Ignore differences within math environments.

[ Default: 0.0 ]

--listings
Use the "listings" package for markup of verbatim environments. Requires the "listings" package.
--long-lines=N
Consider lines longer than "N" characters as potential differences.

[ Default: 1000 ]

--lua-underline
Use the lua-ul package for underlining. This is an experimental feature that may resolve issues with line breaking. Requires luatex >= 1.12.0.
--math-markup=MODE
Controls how mathematical expressions are compared. Possible values for "MODE" are:
diff
Compares mathematical expressions part by part.
whole
Compares entire mathematical expressions as single units.
off
Disables markup for mathematical expressions.

[ Default: "diff" ]

--packages=PACKAGE[,PACKAGE]...
List of packages that should be loaded by the LaTeX compiler. This is useful if latexdiff cannot automatically detect the presence of certain packages, like "amsmath" or "color".
--postproc=PROG
Run the specified postprocessing program on the generated LaTeX file. Useful for further modifications or checks.
--ps
Generate PostScript output. This option is deprecated and may be removed in future versions.
--ps-links
Generate hyperlinks in the PostScript output. Requires the "hyperref" package.
--show-copy
Show copied sections as additions. By default, copied sections are not marked.

[ Default: 0.0 ]

--show-diff
Show differences. This is the default behavior. Opposite of "--show-copy".
--size=N
Sets the size of elements in the diff. For example, when using the "COLOUR" style, this option controls the font size of added/deleted text (if they are shown at half linear size).

[ Default: 0.5 ]

--svn
Use Subversion commands to compare revisions. Implies "latexdiff-vc --svn".
--verbose
Enable verbose output. This is useful for debugging.

[ Default: 0.0 ]

--verbatim-env=REGEX
Regular expression describing environments whose contents should be taken verbatim. The content of these environments will not be processed in any way: deleted content is commented out, new content is not marked up.

[ Default: "comment" ]

--verbatim-line-env=REGEX
Regular expression describing environments whose contents should be taken verbatim. The content of environments described by "VERBATIMLINEENV" are compared in line mode, and changes are marked up using the listings package. The markup style is set based on the chosen mains markup type (Option -t), or on an analysis of the preamble. Note that "listings.sty" must be installed. If this file is not found the fallback solution is to treat "VERBATIMLINEENV" environments treated exactly the same way as "VERBATIMENV" environments.

[ Default: "(?:verbatim[*]?|lstlisting)" ]

PROBLEMAS COMUNES Y PREGUNTAS FRECUENTES

Las citas modificadas resultan en cuadros desbordados
Existe una incompatibilidad entre el paquete "ulem", que "latexdiff" utiliza para subrayar y tachar en el estilo UNDERLINE, el estilo por defecto, y la forma en que se generan las citas. Para poder marcar las citas correctamente, se envuelven con un comando "\mbox". Como las mboxes no se pueden dividir entre líneas, este procedimiento frecuentemente resulta en cuadros desbordados, posiblemente oscureciendo el contenido al extenderse más allá del margen derecho. Lo mismo ocurre con algunos otros paquetes (por ejemplo, siunitx). Si esto es un problema, tiene varias posibilidades.

1. Use el tipo de marcado "CFONT" (opción "-t CFONT"): Si se elige este marcado, las citas modificadas ya no se marcarán con la línea ondulada (adiciones) o tachadas (eliminaciones), sino que seguirán destacándose en el color apropiado, y el texto eliminado se mostrará con una fuente diferente. Otros estilos que no usan el paquete "ulem" también funcionarán.

2. Elija la opción "--disable-citation-markup", que desactiva el marcado de las citas: las citas eliminadas ya no se mostrarán, y las citas añadidas se mostrarán sin marcado. (Este era el comportamiento por defecto de latexdiff en las versiones 0.6 y anteriores). Para paquetes personalizados, puede definir los comandos que necesitan ser protegidos por "\mbox" con las opciones "--append-mboxsafecmd" y "--excludemboxsafecmd" (envíe sus listas de comandos como solicitud de característica en la página de github para establecer el comportamiento por defecto de versiones futuras, ver sección 6)

3. Si está usando luatex >= 1.12.0 puede usar la opción LUAUNDERLINE que usa lua-ul en lugar de ulem para subrayar, lo cual no tiene este problema (característica experimental).

Los cambios en ecuaciones matemáticas complicadas resultan en errores de procesamiento de LaTeX.
Intente la opción "--math-markup=whole". Si incluso eso falla, puede desactivar el marcado para las ecuaciones con "--math-markup=off".
Las partes eliminadas en las ecuaciones no se tachan sino que se subrayan.
Esta es una limitación del paquete ulem que implementa el tachado. Si usa el paquete amsmath, entonces el comando de tachado se redefine de tal manera que los pasajes eliminados se envuelven con el comando "\text"; añadir "\usepackage{amsmath}" a su preámbulo activará este comportamiento. (Si amsmath no se incluye directamente, sino que es importado por otro paquete, latexdiff no podrá detectar su disponibilidad; en este caso puede dar una pista a latexdiff con la opción "--packages=amsmath").
¿Cómo puedo mostrar solo las páginas donde se hicieron cambios?
Use las opciones "--s ZLABEL" (se requiere algún postprocesamiento) o "-s ONLYCHANGEDPAGE". "latexdiff-vc --ps|--pdf" con la opción "--only-changes" se encarga del postprocesamiento por usted (requiere el paquete zref instalado).
La codificación de caracteres falla al ejecutar latexdiff desde powershell.
Este problema no se limita a "latexdiff" y tiene que ver con la configuración por defecto de "powershell" en Windows. Se recomienda usar "cmd" en su lugar.

ERRORES

La opción allow-spaces no está implementada de forma totalmente consistente. Rompe las reglas de que el número y tipo de espacios en blanco no importan, ya que se tratan como significativos diferentes números de espacios interargumentos.

Por favor, envíe informes de errores utilizando el rastreador de problemas de la página del repositorio de github https://github.com/ftilmann/latexdiff.git, o envíelos a tilmann -- AT -- gfz-potsdam.de. Incluya el número de versión de latexdiff (de los comentarios en la parte superior del código fuente o use --version). Si encuentra archivos LaTeX que están libres de errores y se ajustan a las especificaciones establecidas anteriormente, y cuya diferenciación aún no produce un LaTeX libre de errores, por favor envíeme esos archivos, idealmente editados para contener solo el pasaje ofensivo siempre que eso siga reproduciendo el problema. Si su archivo depende de archivos de clase no estándar, debe incluirlos. No miraré ejemplos donde tenga problemas para compilar los archivos originales con LaTeX.

VER TAMBIÉN

latexrevise, latexdiff-vc

PORTABILIDAD

latexdiff no utiliza comandos externos y, por lo tanto, debería ejecutarse en cualquier plataforma que soporte Perl 5.6 o superior. Si se procesan archivos con codificaciones distintas de ASCII o UTF-8, se requiere Perl 5.8 o superior.

La versión estándar de latexdiff requiere la instalación del paquete Perl "Algorithm::Diff" (disponible en www.cpan.org - http://search.cpan.org/~nedkonz/Algorithm-Diff-1.15) pero una versión independiente, latexdiff-so, que tiene este paquete en línea, también está disponible. latexdiff-fast requiere que el comando diff esté presente.
