NOMBRE

lavpipe - crea flujos YUV crudos a partir de scripts de listas de tuberías

SINOPSIS

lavpipe [-o num] [-n num] lista-tuberias

DESCRIPCIÓN

lavpipe lee un archivo de script llamado 'lista de tuberías' que tiene una estructura similar a las listas de edición que se pueden alimentar a lav2yuv. Para obtener información sobre el formato de la lista de tuberías, véase más abajo.

La lista de tuberías define varias fuentes y filtros de vídeo que son combinados por lavpipe para producir un único flujo de salida YUV en la salida estándar (que, por ejemplo, puede ser comprimido y almacenado en disco mediante mpeg2enc(1) o yuv2lav(1)).

OPCIONES

Las opciones de línea de comandos se utilizan para generar una parte específica del flujo de vídeo resultante. Esto significa que puede indicar a lavpipe cuántos fotogramas omitir y cuántos fotogramas entregar a partir de ese punto.

-o num
Este es el desplazamiento de fotogramas de la salida de vídeo. Los primeros num fotogramas del vídeo resultante simplemente no se calculan ni se escriben en la salida estándar. Este valor por defecto es 0.
-n num
Este es el recuento de fotogramas. Si los archivos de entrada o flujos definidos en el script de la lista de tuberías son lo suficientemente largos, la salida tendrá exactamente num fotogramas de longitud. Un valor de 0 significa que se escribirán todos los fotogramas hasta el último, tal como se definen en la lista de tuberías, siempre que haya alguna entrada (0 es el valor por defecto).
lista-tuberias
Este es el nombre del archivo de la lista de tuberías que lavpipe 'ejecutará'. Para obtener información sobre el formato de este archivo, véase más abajo.
-?
Muestra una sinopsis de la sintaxis del comando.

EJEMPLOS

lavpipe -o 100 -n 25 film.pli
calcularía y generaría en la salida estándar los fotogramas 100 a 124 definidos en film.pli (en PAL, este sería el quinto segundo de la película).
lavpipe input.pli | yuv2lav -q80 output.avi
guardaría la película ensamblada por lavpipe como un único archivo AVI.

USO

En esta sección se explica el formato de los archivos de entrada de lavpipe, los scripts de la lista de tuberías. Si necesita algunos ejemplos o un tutorial más detallado, por favor, lea la sección CREACIÓN DE TRANSICIONES DE PELÍCULAS de la página del manual de mjpegtools(1). y el archivo README.lavpipe que debería incluirse en la distribución. También no dude en ponerse en contacto con nosotros a través de la lista de correo (véase más abajo).

Una lista de tuberías consta de dos partes: la lista de fuentes YUV y, después de esta, tantas descripciones de secuencias como se desee. Siempre comienza con las siguientes dos líneas:

LAV Pipe List
Esta es la primera línea en cada script de lista de tuberías. Se utiliza como una simple prueba para ver si lavpipe realmente recibió un script de lista de tuberías y no su tesis doctoral como entrada.
NTSC|PAL
Esta es la segunda línea en cada lista de tuberías y puede ser PAL o NTSC, dependiendo del estándar de vídeo que utilice. No recuerdo si se utiliza en este momento.

Ahora sigue la lista de fuentes:

num
Este es el número de comandos de entrada. lavpipe leerá las siguientes num líneas y las interpretará como comandos de flujo de entrada.
comando (num veces)
Esta es una línea de comando válida con dos variables $o y $n que serán reemplazadas por lavpipe con el desplazamiento y el número de fotogramas que el programa debe generar. Ejemplo:
lav2yuv -o $o -f $n input.avi

Por lo tanto, una lista de fuentes de ejemplo podría parecerse a esto:
2
lav2yuv -o $o -f $n scene1.avi
lav2yuv -o $o -f $n scene2.avi

después de esto puede añadir tantas descripciones de secuencias como necesite. Cada una de ellas se construye de la siguiente manera:

num
El número de fotogramas que durará esta secuencia.
num
El número de entradas que se utilizarán en esta secuencia. Este número debe, por supuesto, ser menor o igual al número de entradas que se definen anteriormente.
idx [ofs] (num veces)
Estos son los índices de las fuentes que se definen al principio del archivo (la primera fuente es 0) con un desplazamiento de fotogramas opcional (es decir, la secuencia comienza con el fotograma número ofs de esta entrada). - este valor por defecto es 0. Ejemplo:
0 150
comando
Esta es una línea de comando válida para una herramienta de filtro YUV que lee num flujos de entrada y escribe un flujo de salida, combinando sus entradas. Opcionalmente, a la herramienta de filtro se le pueden dar las dos variables $o y $n que serán reemplazadas por lavpipe como en los comandos de fuente (ver arriba). Para más información, lea README.lavpipe o la documentación de los programas de filtro (si están disponibles). Un filtro de ejemplo podría parecerse a esto:
transist.flt -o 0 -O 255 -s $o -n $n -d 50
Y si la secuencia solo tiene una entrada que simplemente debe copiarse a la salida, puede usar un guion en lugar de una línea de comando:
-

Y aquí tienes un ejemplo de una lista de tuberías completa que implementa una transición de scene1.avi a scene2.avi

ELIMINE LOS COMENTARIOS DESPUÉS DEL #

LAV Pipe List
PAL
2
lav2yuv -o $o -f $n scene1.avi
lav2yuv -o $o -f $n scene2.avi
50 # primera secuencia: 50 fotogramas
1 # contiene una entrada:
0 0 # scene1.avi, desplazamiento 0
- # salida simple
25 # segunda secuencia: 25 fotogramas
2 # contiene dos entradas:
0 50 # scene1.avi, desplazamiento 50
1 # scene2.avi, desplazamiento 0
transist.flt -o 0 -O 255 -s $o -n $n -d 50 # transición
50 # tercera secuencia: 50 fotogramas
1 # contiene una entrada:
1 25 # scene2.avi, desplazamiento 25
- # salida simple

ERRORES

Estoy seguro de que hay suficientes. lavpipe a menudo acepta listas de tuberías mal formadas y luego genera un vídeo que no era el deseado, sin previo aviso.

La mención de $n anterior es incorrecta. En un momento hubo dos parámetros, pero ahora se permite que un programa produzca tantos fotogramas como quiera. El autor del programa codificó, por razones desconocidas, $n a 0.

NOTAS

También hay algunas limitaciones serias en el sistema, como el procesamiento fotograma a fotograma. Pero como el objetivo al escribir lavpipe era la simplicidad del pipeline, se tendrán que escribir otras herramientas para realizar tareas más interesantes.
Pero quiero señalar que es muy posible escribir una lista de tuberías que combine varios archivos, y luego usar esa lista de tuberías como entrada para otra lista de tuberías simplemente usando el comando lavpipe en la lista de fuentes (ver arriba) - esto ya se puede utilizar para hacer cosas interesantes, si se tienen buenos filtros.

Los comentarios NO están permitidos en los archivos de lista de tuberías. Los comentarios (texto después de #) de arriba son solo para ilustración.
