lame(1) Compresor de audio LAME lame(1)

NOMBRE

lame - crear archivos de audio mp3

SINOPSIS

lame [opciones] <archivo_entrada> <archivo_salida>

DESCRIPCIÓN

LAME es un programa que se puede usar para crear archivos de audio comprimidos. (Lame no es un codificador MP3). Estos archivos de audio pueden ser reproducidos por reproductores MP3 populares como mpg123 o madplay. Para leer desde la entrada estándar, use "-" para <archivo_entrada>. Para escribir en la salida estándar, use "-" para <archivo_salida>.

OPCIONES

Opciones de entrada:

-r
Asume que el archivo de entrada es PCM crudo. La frecuencia de muestreo y mono/estéreo/jstereo deben especificarse en la línea de comandos. Para cada muestra estéreo, LAME espera que los datos de entrada estén ordenados con el canal izquierdo primero, luego el canal derecho. Por defecto, LAME espera que sean enteros con signo con un ancho de bits de 16 y almacenados en little-endian. Sin -r, LAME realizará varias fseek()'s en el archivo de entrada buscando encabezados WAV y AIFF.
Puede que no esté disponible en su versión.
-x
Intercambia bytes en el archivo de entrada (o archivo de salida cuando se usa --decode).
Para solucionar problemas de little-endian/big-endian. Si sus codificaciones suenan como estática, intente esto primero.
Sin usar -x, LAME tratará el archivo de entrada como endian nativo.
-s freq_muestreo
freq_muestreo = 8/11.025/12/16/22.05/24/32/44.1/48

Solo requerido para archivos de entrada PCM crudos. De lo contrario, se determinará a partir del encabezado del archivo de entrada.

LAME remuestreará automáticamente el archivo de entrada a una de las frecuencias de muestreo MP3 compatibles si es necesario.

--ancho-de-bits n
Ancho de bits de entrada por muestra.
n = 8, 16, 24, 32 (por defecto 16)

Solo requerido para archivos de entrada PCM crudos. De lo contrario, se determinará a partir del encabezado del archivo de entrada.

--con-signo
Indica a LAME que las muestras de la entrada son con signo (el valor predeterminado para datos PCM crudos de 16, 24 y 32 bits).

Solo requerido para archivos de entrada PCM crudos.

--sin-signo
Indica a LAME que las muestras de la entrada no tienen signo (el valor predeterminado para datos PCM crudos de 8 bits, donde 0x80 es cero).

Solo requerido para archivos de entrada PCM crudos y solo disponible con ancho de bits de 8.

--little-endian
Indica a LAME que las muestras de la entrada están en formato little-endian.

Solo requerido para archivos de entrada PCM crudos.

--big-endian
Indica a LAME que las muestras de la entrada están en formato big-endian.

Solo requerido para archivos de entrada PCM crudos.

--entrada-mp1
Asume que el archivo de entrada es un archivo MPEG Layer I (es decir, MP1).
Si el nombre del archivo termina en ".mp1", LAME asumirá que es MPEG Layer I. Para la entrada estándar o archivos Layer I que no terminan en .mp1, necesita usar este modificador.
--entrada-mp2
Asume que el archivo de entrada es un archivo MPEG Layer II (es decir, MP2).
Si el nombre del archivo termina en ".mp2", LAME asumirá que es MPEG Layer II. Para la entrada estándar o archivos Layer II que no terminan en .mp2, necesita usar este modificador.
--entrada-mp3
Asume que el archivo de entrada es un archivo MP3.
Útil para reducir la tasa de muestreo de un mp3 a otro. Por ejemplo, puede ser útil para transmitir a través de un servidor IceCast.
Si el nombre del archivo termina en ".mp3", LAME asumirá que es MP3. Para la entrada estándar o archivos MP3 que no terminan en .mp3, necesita usar este modificador.
--sin-silencios archivo1 archivo2 ...
codificación sin silencios para un conjunto de archivos contiguos
--salida-sin-silencios dir
directorio de salida para codificación sin silencios (debe preceder a --sin-silencios)
--dir-salida dir
Si no se especifica un archivo de salida explícito, se escribirá un archivo en la ruta dada. Ignorado al usar entrada canalizada/transmitida.

Opciones operativas:

-m modo
modo = s, j, f, d, m, l, r

El estéreo combinado (joint-stereo) es el modo predeterminado para archivos estéreo.

Estéreo (s)imple (LR forzado)
En este modo, el codificador no utiliza las correlaciones potencialmente existentes entre los dos canales de entrada. Sin embargo, puede negociar la demanda de bits entre ambos canales, es decir, dar a un canal más bits si el otro contiene silencio o necesita menos bits debido a una menor complejidad.

Estéreo (j)oint
En este modo, el codificador puede usar (basándose en cada fotograma) estéreo L/R o estéreo medio/lado. En estéreo medio/lado, se codifican los canales medio (L+R) y lado (L-R), y se asignan más bits al canal medio que al canal lado. Cuando no hay demasiada separación estéreo, esto aumenta efectivamente el ancho de banda, proporcionando mayor calidad con la misma cantidad de bits.

El uso inapropiado del estéreo medio/lado puede resultar en artefactos de compresión audibles. Demasiados cambios entre estéreo medio/lado y estéreo regular también pueden sonar mal. Para determinar cuándo cambiar a estéreo medio/lado, LAME utiliza un algoritmo mucho más sofisticado que el descrito en la documentación ISO.

Estéreo MS (f)orzado
Fuerza que todos los fotogramas se codifiquen con estéreo medio/lado. Solo debería usarse si está seguro de que cada fotograma del archivo de entrada tiene muy poca separación estéreo.

Canal (d)ual
En este modo, los 2 canales se codificarán de forma totalmente independiente. Cada canal tendrá exactamente la mitad de la tasa de bits. Este modo está diseñado para aplicaciones como codificación de doble idioma (por ejemplo: inglés en un canal y francés en el otro). Usar este modo de codificación para archivos estéreo regulares resultará en una codificación de menor calidad.

(m)ono
La entrada se codificará como una señal mono. Si era una señal estéreo, se reducirá a mono. La mezcla se calcula como la suma de los canales izquierdo y derecho, atenuada en 6 dB. Tenga en cuenta que, si utiliza una transmisión PCM estéreo CRUDA, debe usar el parámetro -a.

Solo canal (l)quierdo
La entrada se codificará como una señal mono. Si era una señal estéreo, solo se codificará el canal izquierdo.

Solo canal (r)derecho
La entrada se codificará como una señal mono. Si era una señal estéreo, solo se codificará el canal derecho.

-a
Mezcla el archivo de entrada estéreo a mono y lo codifica como mono.
La mezcla se calcula como la suma de los canales izquierdo y derecho, atenuada en 6 dB.

Esta opción solo es necesaria en el caso de entrada PCM estéreo CRUDA (porque LAME no puede determinar el número de canales en el archivo de entrada). Para codificar un archivo de entrada PCM estéreo CRUDO como mono, use lame -a -m m

Para archivos de entrada WAV y AIFF, usar -m m siempre producirá un archivo .mp3 mono a partir de entradas tanto mono como estéreo.

--formato-libre
Produce un flujo de bits de formato libre. Con esta opción, puede usar -b con cualquier tasa de bits superior a 8 kbps.

Sin embargo, aunque se requiere que un decodificador mp3 admita tasas de bits libres hasta al menos 320 kbps, muchos reproductores no pueden manejarlo.

Las pruebas han demostrado que los siguientes decodificadores soportan formato libre:
in_mpg123 hasta 560 kbps
l3dec hasta 310 kbps
LAME hasta 640 kbps
MAD hasta 640 kbps

--decodificar
Usa LAME para decodificar a un archivo wav. El archivo de entrada puede ser de cualquier tipo soportado por la codificación, incluidos los archivos layer II. LAME utiliza una bifurcación de
mpglib conocido como HIP para la decodificación.

Si se usa -t (deshabilitar cabecera wav), LAME generará pcm crudo en formato nativo de endianidad. Puedes usar -x para intercambiar el orden de los bytes.

Esta opción no se puede usar si el decodificador MP3 fue explícitamente deshabilitado en la compilación de LAME.

-t
Deshabilita la escritura de la Etiqueta INFO en la codificación.
Esta etiqueta se incrusta en el frame 0 del archivo MP3. Incluye información sobre las opciones de codificación del archivo y, en VBR, permite a los reproductores conscientes de VBR buscar y calcular correctamente los tiempos de reproducción de archivos VBR.

Cuando se especifica --decode (decodificar a WAV), este flag deshabilitará la escritura de la cabecera WAV. La salida será pcm crudo, en formato nativo de endianidad. Usa -x para intercambiar bytes.

--comp arg
En lugar de elegir la tasa de bits, usando esta opción, el usuario puede elegir la relación de compresión a alcanzar.
--scale n
--scale-l n
--scale-r n
Escala la entrada (todos los canales, solo canal izquierdo o solo canal derecho) por n. Esto simplemente multiplica los datos PCM (después de haber sido convertidos a punto flotante) por n.

n > 1: aumentar volumen
n = 1: sin efecto
n < 1: reducir volumen

Úsalo con cuidado, ya que la mayoría de los decodificadores MP3 truncarán los datos que se decodifiquen a valores mayores que 32768.

--replaygain-fast
Calcula ReplayGain rápidamente pero con una ligera imprecisión.

Esto calcula ReplayGain "Radio" en el flujo de datos de entrada después de la escala de volumen y/o el remuestreo especificados por el usuario.

El análisis ReplayGain *no* afecta el contenido de un flujo de datos comprimido en sí mismo, es un valor almacenado en la cabecera de un archivo de sonido. La información sobre el propósito de ReplayGain y los algoritmos utilizados está disponible en http://www.replaygain.org/.

Solo se calcula el valor ReplayGain "RadioGain", se almacena en la etiqueta LAME. El análisis se realiza con un volumen de referencia igual a 89dB. Nota: el volumen de referencia ha sido cambiado de 83dB en la transición de la versión 3.95 a la 3.95.1.

Este interruptor está habilitado por defecto.

Ver también: --replaygain-accurate, --noreplaygain

--replaygain-accurate
Calcula ReplayGain con mayor precisión y encuentra la muestra pico.

Esto calcula ReplayGain "Radio" en el flujo de datos decodificado, encuentra la muestra pico decodificando sobre la marcha el flujo de datos codificado y lo almacena en el archivo.

El análisis ReplayGain *no* afecta el contenido de un flujo de datos comprimido en sí mismo, es un valor almacenado en la cabecera de un archivo de sonido. La información sobre el propósito de ReplayGain y los algoritmos utilizados está disponible en http://www.replaygain.org/.

Por defecto, LAME realiza el análisis ReplayGain sobre los datos de entrada (después de la escala de volumen especificada por el usuario). Este comportamiento podría dar resultados ligeramente imprecisos porque los datos en la salida de una secuencia de compresión/descompresión con pérdida difieren de los datos de entrada iniciales. Cuando se especifica --replaygain-accurate, el flujo mp3 se decodifica sobre la marcha y el análisis se realiza sobre el flujo de datos decodificado. Aunque teóricamente este método da resultados más precisos, tiene varias desventajas:

  • las pruebas han demostrado que la diferencia entre los valores ReplayGain calculados en los datos de entrada y los datos decodificados generalmente no es mayor de 0.5dB, aunque la diferencia mínima de volumen que el oído humano puede percibir es de aproximadamente 1.0dB
  • la decodificación sobre la marcha ralentiza significativamente el proceso de codificación

La ventaja aparente es que:

*
con --replaygain-accurate se determina y almacena en el archivo la muestra pico real. El conocimiento de la muestra pico puede ser útil para los decodificadores (reproductores) para prevenir un efecto negativo llamado "clipping" que introduce distorsión en el sonido.

Solo se calcula el valor ReplayGain "RadioGain", se almacena en la etiqueta LAME. El análisis se realiza con un volumen de referencia igual a 89dB. Nota: el volumen de referencia ha sido cambiado de 83dB en la transición de la versión 3.95 a la 3.95.1.

Esta opción no se puede usar si el decodificador MP3 fue explícitamente deshabilitado en la compilación de LAME. (Nota: si LAME se compila sin el decodificador MP3, el análisis ReplayGain se realiza sobre los datos de entrada después de la escala de volumen especificada por el usuario).

Ver también: --replaygain-fast, --noreplaygain --clipdetect

--noreplaygain
Deshabilita el análisis ReplayGain.

Por defecto, el análisis ReplayGain está habilitado. Este interruptor lo deshabilita.

Ver también: --replaygain-fast, --replaygain-accurate

--clipdetect
Detección de clipping.

Habilita --replaygain-accurate e imprime un mensaje indicando si ocurre clipping y a cuántos dB está la forma de onda de la escala completa.

Esta opción no se puede usar si el decodificador MP3 fue explícitamente deshabilitado en la compilación de LAME.

Ver también: --replaygain-accurate

--preset type | [cbr] kbps
Usa uno de los presets integrados.

Echa un vistazo a la sección PRESETS más abajo.

--preset help ofrece más información sobre las opciones utilizadas en estos presets.

--noasm type
Deshabilita optimizaciones específicas de ensamblador ( mmx / 3dnow / sse ). La calidad no aumentará, solo la velocidad se reducirá. Si tienes problemas para ejecutar Lame en un procesador Cyrix/Via, deshabilitar las optimizaciones de MMX podría resolver tu problema.

Algoritmos de modelado de ruido y psicoacústicos:

-q qual
0 <= qual <= 9

La tasa de bits es, por supuesto, la principal influencia en la calidad. Cuanto mayor sea la tasa de bits, mayor será la calidad. Pero para una tasa de bits dada, tenemos una elección de algoritmos para determinar los mejores factores de escala y la codificación Huffman (noise shaping).

Para CBR y ABR, la siguiente tabla se aplica:

-q 0:
Utiliza los mejores algoritmos (mejor búsqueda de codificación Huffman, bucle externo completo y la mayor precisión de varios parámetros).

-q 1 a q 4:
Similar a -q 0 sin el bucle externo completo y precisión decreciente de los parámetros cuanto más lejos de q0. -q 3 es el valor por defecto.

-q 5 y -q 6:
Igual que -q 7, pero habilita el modelado de ruido y aumenta la ganancia de subbloques

-q 7 a -q 9:
Igual que -f. Muy rápido, calidad OK. Se usa psicoacústica para pre-eco y estéreo mid/side, pero no se hace noise-shaping.

Para el modo VBR predeterminado desde LAME 3.98, la siguiente tabla se aplica:

-q 0 a -q 4:
incluyen todas las características de los otros modos y además utilizan la mejor búsqueda al aplicar la codificación Huffman.

-q 5 y -q 6:
incluyen todas las características de -q7, calculan y consideran el ruido de cuantificación real, y además habilitan la ganancia de subbloques.

-q 7 a -q 9
Este nivel utiliza un modelo psicoacústico pero no calcula el ruido de cuantificación al codificar: hace una suposición rápida.

-h
Alias de -q 2
-f
Alias de -q 7

Opciones de CBR (tasa de bits constante, la predeterminada):

-b n
Para MPEG-1 (frecuencias de muestreo de 32, 44.1 y 48 kHz)
n = 32, 40, 48, 56, 64, 80, 96, 112, 128, 160, 192, 224, 256, 320

Para MPEG-2 (frecuencias de muestreo de 16, 22.05 y 24 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64, 80, 96, 112, 128, 144, 160

Para MPEG-2.5 (frecuencias de muestreo de 8, 11.025 y 12 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64

El valor por defecto es 128 para MPEG1 y 64 para MPEG2 y 32 para MPEG2.5
(64, 32 y 16 respectivamente en caso de mono).

--cbr
Forzar el uso de tasa de bits constante. Se utilizaba para deshabilitar la codificación VBR o ABR aunque estuvieran habilitados sus ajustes.

Opciones de ABR (tasa de bits promedio):

--abr n
Activa la codificación con una tasa de bits promedio objetivo de n kbits, permitiendo el uso de frames de diferentes tamaños. El rango permitido de n es 8 - 310, puedes usar cualquier valor entero dentro de ese rango.

Se puede combinar con los flags -b y -B como: lame --abr 123 -b 64 -B 192 a.wav a.mp3 lo que limitaría los tamaños de frame permitidos entre 64 y 192 kbits.

El uso de -B NO RECOMENDADO. Un bitstream CBR de 128 kbps, debido a la reserva de bits, puede tener cuadros que usan tantos bits como un cuadro de 320 kbps. Los modos VBR minimizan el uso de la reserva de bits, y por lo tanto necesitan permitir cuadros de 320 kbps para obtener la misma flexibilidad que las transmisiones CBR.

Opciones VBR (bitrate variable):

-v
usar bitrate variable (--vbr-new)
--vbr-old
Invoca el algoritmo VBR más antiguo y probado. Produce archivos de muy buena calidad, aunque no es muy rápido. Hasta la versión 3.89, se ha considerado el algoritmo VBR de "caballo de batalla".
--vbr-new
Invoca el algoritmo VBR más nuevo. Durante el desarrollo de la versión 3.90, se realizaron ajustes considerables en este algoritmo, y ahora se considera a la par con el --vbr-old original. Tiene la ventaja adicional de ser muy rápido (más del doble de rápido que --vbr-old). Este es el predeterminado desde la versión 3.98.
-V n
0 <= n <= 9.999
Habilita VBR (Bitrate Variable) y especifica el valor de calidad VBR (predeterminado = 4). Se pueden especificar valores decimales, como 4.51.
0 = la calidad más alta.

Opciones ABR y VBR:

-b bitrate
Para MPEG-1 (frecuencias de muestreo de 32, 44.1 y 48 kHz)
n = 32, 40, 48, 56, 64, 80, 96, 112, 128, 160, 192, 224, 256, 320

Para MPEG-2 (frecuencias de muestreo de 16, 22.05 y 24 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64, 80, 96, 112, 128, 144, 160

Para MPEG-2.5 (frecuencias de muestreo de 8, 11.025 y 12 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64

Especifica el bitrate mínimo a utilizar. Sin embargo, para evitar espacio desperdiciado, se utilizará el tamaño de cuadro más pequeño disponible durante los silencios.

-B bitrate
Para MPEG-1 (frecuencias de muestreo de 32, 44.1 y 48 kHz)
n = 32, 40, 48, 56, 64, 80, 96, 112, 128, 160, 192, 224, 256, 320

Para MPEG-2 (frecuencias de muestreo de 16, 22.05 y 24 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64, 80, 96, 112, 128, 144, 160

Para MPEG-2.5 (frecuencias de muestreo de 8, 11.025 y 12 kHz)
n = 8, 16, 24, 32, 40, 48, 56, 64

Especifica el bitrate máximo permitido.

Nota: Si posees un reproductor de hardware mp3 construido sobre un chip MAS 3503, debes establecer el bitrate máximo en no más de 224 kbps.

-F
Forzar la aplicación estricta de la opción -b.
Esto es principalmente para usar con reproductores de hardware que no soportan mp3 de bajo bitrate.

Sin esta opción, el bitrate mínimo se ignorará para pasajes de silencio analógico, es decir, cuando el nivel de música está por debajo del umbral absoluto de audición humana (ATH).

Opciones experimentales:

-X n
0 <= n <= 7

Cuando LAME busca una cuantificación "buena", tiene que comparar la actual con la mejor encontrada hasta ahora. La comparación dice cuál es mejor, la mejor hasta ahora o la actual. El parámetro -X selecciona entre diferentes enfoques para tomar esta decisión, siendo -X0 el modo predeterminado:

-X0
Los criterios son (en orden de importancia):
* menos bandas de factor de escala distorsionadas
* la suma de ruido por encima de los umbrales es menor
* el ruido total es menor

-X1
La actual es mejor si el ruido máximo sobre todas las bandas de factor de escala es menor que la mejor hasta ahora.

-X2
La actual es mejor si la suma total de ruido es menor que la mejor hasta ahora.

-X3
La actual es mejor si la suma total de ruido es menor que la mejor hasta ahora y el ruido máximo sobre todas las bandas de factor de escala es menor que la mejor hasta ahora más 2dB.

-X4
Aún no documentado.

-X5
Los criterios son (en orden de importancia):
* la suma de ruido por encima de los umbrales es menor
* la suma total de ruido es menor

-X6
Los criterios son (en orden de importancia):
* la suma de ruido por encima de los umbrales es menor
* el ruido máximo sobre todas las bandas de factor de escala es menor
* la suma total de ruido es menor

-X7
Los criterios son:
* menos bandas de factor de escala distorsionadas
o
* la suma de ruido por encima de los umbrales es menor

-Y
permite a LAME ignorar el ruido en sfb21, como en CBR

Opciones de cabecera/stream MP3:

-e emp
emp = n, 5, c

n = (ninguno, predeterminado)
5 = 0/15 microsegundos
c = citt j.17

Todo esto hace es establecer una bandera en el bitstream. Si tienes un archivo de entrada PCM al que se le ha aplicado alguno de los tipos anteriores de énfasis (obsoleto), puedes establecer esta bandera en LAME. Entonces el decodificador mp3 debería de-enfatizar la salida durante la reproducción, aunque la mayoría de los decodificadores ignoran esta bandera.

Una mejor solución sería aplicar la de-enfatización con una utilidad independiente antes de codificar, y luego codificar sin -e.

-c
Marcar el archivo codificado como protegido por derechos de autor.
-o
Marcar el archivo codificado como una copia.
-p
Activar protección contra errores CRC.
Añadirá un código de verificación de redundancia cíclica (CRC) en cada cuadro, permitiendo detectar errores de transmisión que podrían ocurrir en el stream MP3. Sin embargo, utiliza 16 bits por cuadro que de otro modo se usarían para codificar, y por lo tanto reducirá ligeramente la calidad del sonido.
--nores
Desactivar la reserva de bits. Cada cuadro se volverá independiente de los anteriores, pero la calidad será menor.
--strictly-enforce-ISO
Con esta opción, LAME aplicará la limitación de 7680 bits al tamaño total del cuadro.
Esto resulta en muchos bits desperdiciados para codificaciones de alto bitrate, pero garantizará la compatibilidad estricta con ISO. Esta compatibilidad podría ser importante para reproductores de hardware.

Opciones de filtro:

--lowpass freq
Establecer una frecuencia de filtrado de paso bajo en kHz. Las frecuencias por encima de la especificada se cortarán.
--lowpass-width freq
Establecer el ancho del filtro de paso bajo. El valor predeterminado es el 15% de la frecuencia de paso bajo.
--highpass freq
Establecer una frecuencia de filtrado de paso alto en kHz. Las frecuencias por debajo de la especificada se cortarán.
--highpass-width freq
Establecer el ancho del filtro de paso alto en kHz. El valor predeterminado es el 15% de la frecuencia de paso alto.
--resample sfreq
sfreq = 8, 11.025, 12, 16, 22.05, 24, 32, 44.1, 48
Selecciona la frecuencia de muestreo de salida (solo soportado para codificación).
Si no se especifica, LAME remuestreará automáticamente la entrada cuando se usen altas relaciones de compresión.

NOMBRE

lame - codificador MPEG Audio Layer III (MP3)

SINOPSIS

lame [options] [infile] [outfile]

lame [options] [infile] -

cat infile | lame [options] - [outfile]

DESCRIPCIÓN

LAME es un codificador de código abierto para el formato de audio MPEG Audio Layer III (MP3). Es ampliamente considerado como uno de los codificadores de MP3 de mayor calidad disponibles.

Este manual describe las opciones comunes disponibles con el comando lame.

OPCIONES

-a
Codifica en modo 'all channels' (estéreo si la entrada es estéreo, mono si la entrada es mono).
-f
Codifica en modo 'fast' (estéreo forzado). Esto utiliza codificación estéreo implícita incluso si la entrada es mono. Puede ser más rápido pero podría degradar la calidad.
-m m
Codifica en modo mono. Fuerza la salida a ser mono.
-g
ejecuta análisis gráfico en <infile>. <infile> también puede ser un archivo .mp3. (Esta característica es una opción de compilación. Su binario puede haber sido compilado sin ella por razones de velocidad.)

Opciones de control de calidad:

-q n
Establece la calidad de codificación. n puede ser un número del 0 al 9. Cuanto menor sea el número, mayor será la calidad y el tamaño del archivo. Un valor de 0 suele ser la calidad más alta y lenta. Un valor de 9 es la calidad más baja y rápida. Los valores por defecto son 2.
-b k
Establece la tasa de bits constante (CBR) deseada en kilobits por segundo (kbps). Los valores válidos son de 8 a 320 kbps. Si se establece una tasa de bits, ésta se utilizará para toda la codificación.
-B k
Establece la tasa de bits promedio (ABR) deseada en kilobits por segundo (kbps). Los valores válidos son de 8 a 320 kbps. A diferencia de CBR, ABR permite que la tasa de bits varíe para lograr una calidad más constante.
-V n
Establece la calidad de tasa de bits variable (VBR). n puede ser un número del 0 al 9, donde 0 es la mayor calidad y 9 es la menor calidad. La tasa de bits resultante variará según la complejidad del audio.

Opciones de metadatos:

-t
Incluye etiquetas ID3v1.0.
-T
Incluye etiquetas ID3v2.
-v
Incluye etiquetas ID3v1.1.
-p
Reemplaza etiquetas existentes en caso de errores en los valores pasados para las etiquetas, utiliza los valores predeterminados en caso de que ocurra un error.

Opciones de análisis:

-g
ejecuta análisis gráfico en <infile>. <infile> puede ser también un archivo .mp3. (Esta función es una opción de compilación. Es posible que su binario se haya compilado sin esta opción por motivos de velocidad.)

ETIQUETAS ID3

LAME es capaz de incrustar etiquetas ID3 v1, v1.1 o v2 dentro del archivo MP3 codificado. Esto permite tener información útil sobre la pista de música incluida dentro del archivo. La mayoría de los reproductores de MP3 pueden leer estos datos.

Lame elegirá inteligentemente qué etiquetas usar. Añadirá etiquetas ID3 v2 solo si los comentarios de entrada no caben en las etiquetas v1 o v1.1, es decir, si tienen más de 30 caracteres. En este caso, se añadirán etiquetas v1 y v2, para garantizar la lectura de etiquetas por reproductores MP3 que no son capaces de leer etiquetas ID3 v2.

MODOS DE CODIFICACIÓN

LAME es capaz de codificar su música utilizando uno de sus 3 modos de codificación: tasa de bits constante (CBR), tasa de bits promedio (ABR) y tasa de bits variable (VBR).

Tasa de Bits Constante (CBR)
Este es el modo de codificación predeterminado, y también el más básico. En este modo, la tasa de bits será la misma para todo el archivo. Esto significa que cada parte de su archivo mp3 utilizará el mismo número de bits. Si el pasaje musical es difícil o fácil de codificar, el codificador utilizará la misma tasa de bits, por lo que la calidad de su mp3 es variable. Las partes complejas serán de menor calidad que las más fáciles. La principal ventaja es que el tamaño final del archivo no cambiará y se puede predecir con precisión.
Tasa de Bits Promedio (ABR)
En este modo, usted elige que el codificador mantenga una tasa de bits promedio mientras utiliza tasas de bits más altas para las partes de su música que necesitan más bits. El resultado será de mayor calidad que la codificación CBR, pero el tamaño promedio del archivo seguirá siendo predecible, por lo que este modo es muy recomendable sobre CBR. Este modo de codificación es similar a lo que se denomina vbr en AAC o Liquid Audio (otras 2 tecnologías de compresión).
Tasa de Bits Variable (VBR)
En este modo, usted elige la calidad deseada en una escala de 9 (menor calidad/mayor distorsión) a 0 (mayor calidad/menor distorsión). Luego, el codificador intenta mantener la calidad dada en todo el archivo eligiendo el número óptimo de bits a gastar para cada parte de su música. La principal ventaja es que puede especificar el nivel de calidad que desea alcanzar, pero el inconveniente es que el tamaño final del archivo es totalmente impredecible.

PREAJUSTES

Los interruptores --preset son alias de la configuración de LAME.

Para activar estos preajustes:

Para modos VBR (generalmente la mayor calidad):

--preset medium
Este preajuste debería proporcionar una transparencia casi total a la mayoría de las personas en la mayoría de la música.
--preset standard
Este preajuste generalmente debería ser transparente para la mayoría de las personas en la mayoría de la música y ya tiene una calidad bastante alta.
--preset extreme
Si tiene un oído extremadamente bueno y un equipo similar, este preajuste generalmente proporcionará una calidad ligeramente superior al modo standard.

Para CBR 320kbps (la mayor calidad posible de los interruptores --preset):

--preset insane
Este preajuste suele ser excesivo para la mayoría de las personas y la mayoría de las situaciones, pero si necesita la máxima calidad absoluta sin importar el tamaño del archivo, esta es la forma de hacerlo.

Para modos ABR (alta calidad por tasa de bits dada pero no tan alta como VBR):

--preset kbps
Usar este preajuste generalmente le dará una buena calidad a una tasa de bits especificada. Dependiendo de la tasa de bits introducida, este preajuste determinará la configuración óptima para esa situación particular. Si bien este enfoque funciona, no es tan flexible como VBR y, por lo general, no alcanzará el mismo nivel de calidad que VBR a tasas de bits más altas.
cbr
Si utiliza el modo ABR (leer arriba) con una tasa de bits significativa como 80, 96, 112, 128, 160, 192, 224, 256, 320, puede usar la opción --preset cbr kbps para forzar la codificación en modo CBR en lugar del modo ABR estándar. ABR proporciona una mayor calidad, pero CBR puede ser útil en situaciones como cuando la transmisión de un MP3 a través de Internet es importante.

EJEMPLOS

Codificación estéreo jstereo de tasa de bits fija de 128 kbps:

lame -b 128 sample.wav sample.mp3

Codificación estéreo jstereo de tasa de bits fija de 128 kbps, mayor calidad:

lame -q 0 -b 128 sample.wav sample.mp3

Para deshabilitar la codificación estéreo jstereo (ligeramente más rápido, pero menor calidad a tasas de bits <= 128 kbps):

lame -m s sample.wav sample.mp3

Tasa de bits variable (use -V n para ajustar la calidad/tamaño del archivo):

lame -V 2 sample.wav sample.mp3

Transmisión mono pcm crudo de 22.05 kHz, salida de 24 kbps:

cat inputfile | lame -r -m m -b 24 -s 22.05 - - > output

Transmisión mono pcm crudo de 44.1 kHz, con reducción de frecuencia de muestreo a 22.05 kHz:

cat inputfile | lame -r -m m -b 24 --resample 22.05 - - > output

Codificar con el preajuste standard:

lame --preset standard sample.wav sample.mp3
