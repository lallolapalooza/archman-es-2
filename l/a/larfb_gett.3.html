CLARFB_GETT

Propósito:

!>
!> CLARFB_GETT aplica un bloque reflector de Householder complejo H desde la
!> izquierda a una matriz compleja de (K+M)-por-N
!> compuesta por dos matrices de bloque: una matriz K-por-N trapezoidal superior A
!> almacenada en el array A, y una matriz rectangular M-por-(N-K) B, almacenada
!> en el array B. El bloque reflector H se almacena en una representación
!> WY compacta, donde los reflectores elementales están en los
!> arrays A, B y T. Ver la sección Detalles Adicionales.
!>

Parámetros

IDENT 
!>          IDENT es CHARACTER*1
!>          Si IDENT = no 'I', o no 'i', entonces V1 es unitaria
!>             triangular inferior y se almacena en el bloque K-por-K izquierdo
!>             de la matriz de entrada A,
!>          Si IDENT = 'I' o 'i', entonces V1 es una matriz identidad y
!>             no se almacena.
!>          Ver la sección Detalles Adicionales.
!>

M

!>          M es INTEGER
!>          El número de filas de la matriz B.
!>          M >= 0.
!>

N

!>          N es INTEGER
!>          El número de columnas de las matrices A y B.
!>          N >= 0.
!>

K

!>          K es INTEGER
!>          El número o filas de la matriz A.
!>          K es también el orden de la matriz T, es decir, el número de
!>          reflectores elementales cuyo producto define el bloque
!>          reflector. 0 <= K <= N.
!>

T

!>          T es un array COMPLEX, dimensión (LDT,K)
!>          La matriz T triangular superior K-por-K en la representación
!>          del bloque reflector.
!>

LDT

!>          LDT es INTEGER
!>          La dimensión principal del array T. LDT >= K.
!>

A

!>          A es un array COMPLEX, dimensión (LDA,N)
!>
!>          En la entrada:
!>           a) En la parte K-por-N trapezoidal superior A: matriz de entrada A.
!>           b) En las columnas debajo de la diagonal: columnas de V1
!>              (los unos no se almacenan en la diagonal).
!>
!>          En la salida:
!>            A se sobrescribe con el producto rectangular K-por-N H*A.
!>
!>          Ver la sección Detalles Adicionales.
!>

LDA

!>          LDB es INTEGER
!>          La dimensión principal del array A. LDA >= max(1,K).
!>

B

!>          B es un array COMPLEX, dimensión (LDB,N)
!>
!>          En la entrada:
!>            a) En el bloque derecho M-por-(N-K): matriz de entrada B.
!>            b) En el bloque izquierdo M-por-N: columnas de V2.
!>
!>          En la salida:
!>            B se sobrescribe con el producto rectangular M-por-N H*B.
!>
!>          Ver la sección Detalles Adicionales.
!>

LDB

!>          LDB es INTEGER
!>          La dimensión principal del array B. LDB >= max(1,M).
!>

WORK

!>          WORK es un array COMPLEX,
!>          dimensión (LDWORK,max(K,N-K))
!>

LDWORK

!>          LDWORK es INTEGER
!>          La dimensión principal del array WORK. LDWORK>=max(1,K).
!>

Descripción


SLARFB_GETT y DLARFB_GETT aplican un reflector de bloque de Householder
  real H desde la izquierda a una matriz real (K+M)-por-N compuesta por dos
  matrices de bloque: una matriz A K-por-N de forma trapezoidal superior almacenada
  en el array A, y una matriz B rectangular M-por-(N-K) almacenada en el array
  B. El reflector de bloque H se almacena en una representación WY compacta,
  donde los reflectores elementales están en los arrays A, B y T.




Operación


La matriz A es una matriz K-por-N compuesta por dos matrices de
  bloque de columnas, A1 (K-por-K) y A2 (K-por-(N-K)):


A = ( A1, A2 ).



La matriz B es una matriz M-por-N compuesta por dos matrices de
  bloque de columnas, B1 (M-por-K) y B2 (M-por-(N-K)):


B = ( B1, B2 ).

( A_out ) := H * ( A_in ) = ( I - V * T * V**T ) * ( A_in )

Function Documentation

zlarfb_gett computes the matrices C and WORK.

This routine is part of the LAPACK routines for computing the inverse of a general matrix.

Arguments:

matrix_layout
Specifies the storage format for the matrices V, TAU and C:
  • LAPACK_ROW_MAJOR: Row major storage
  • LAPACK_COL_MAJOR: Column major storage
trans
Specifies the operation to be performed:
  • 'N': C = Q * C
  • 'C': C = QH * C
side
Specifies whether V and TAU define Q or QH.
  • 'L': C = Q * C
  • 'R': C = C * Q
direct
Indicates what form the matrix V has:
  • 'F': V is formed with elementary relectors in a left looking manner.
  • 'B': V is formed with elementary relectors in a right looking manner.
storev
Indicates what form the matrix V has:
  • 'N': V is stored by columns.
  • 'C': V is stored by rows.
m
The number of rows of the matrix C.
n
The number of columns of the matrix C.
k
The number of elementary relectors whose product defines Q. With side = 'L', the number of columns of V is k and the number of rows is m. With side = 'R', the number of columns of V is k and the number of rows is n. With direct = 'F', k must be greater than or equal to min(m, n).
v
Details of the local relectors.
ldv
The leading dimension of the array V.
tau
The coefficients of the elementary relectors.
ntau
The number of entries in tau. This is k.
c
On entry, the matrix to be operated on. On exit, C is replaced by the matrix operated on.
ldc
The leading dimension of the array C.
work
A workspace matrix. work is not used when storev = 'N'.
lwork
The dimension of the array work. If lwork = 0, then lwork is determined implicitly by the routine.

The structure of V and TAU depends on the values of side, direct and storev.

The algorithm first computes the product T of elementary relectors.

If direct = 'F', T is computed as follows. If storev = 'C', the relectors are stored by rows and T is computed by calling zlarf_. If storev = 'N', the relectors are stored by columns and T is computed by calling zlarfb_.

If direct = 'B', T is computed as follows. If storev = 'C', the relectors are stored by rows and T is computed by calling zlarfb_. If storev = 'N', the relectors are stored by columns and T is computed by calling zlarf_.

The matrix C is then updated by multiplying it with T.

The matrix WORK is computed by calling zlarfb_.

This routine is used to compute the inverse of a general matrix and its transpose.

It is intended to be used after the LU or QR decomposition of the matrix.

The detailed description is as follows:

The operation is:

H * ( A_in ) = ( I - V * T * V**H ) * ( A_in ) = ( A_out )
    ( B_in )                        ( B_in )   ( B_out )

Where:

( A_in ) consists of two block columns:
( B_in )

   ( B_in )   (( B1_in ) ( B2_in ))   ((     0 ) ( B2_in )),
where the column blocks are:
A1_in is a K-by-K upper-triangular matrix stored in the upper triangular part of the array A(1:K,1:K).
B1_in is an M-by-K rectangular ZERO matrix and not stored.
A2_in is a K-by-(N-K) rectangular matrix stored in the array A(1:K,K+1:N).
B2_in is an M-by-(N-K) rectangular matrix stored in the array B(1:M,K+1:N).

and V2 is an M-by-K rectangular stored the array B(1:M,1:K) (because on input B1_in is a rectangular zero matrix that is not stored and the space is used to store V2).

T is a K-by-K upper-triangular matrix stored in the array T(1:K,1:K).
On output:
A_out consists of two block columns:
( B_out )

   ( B_out )   (( B1_out ) ( B2_out )),

A1_out is a K-by-K square matrix, or a K-by-K upper-triangular matrix, if V1 is an identity matrix. AiOut is stored in the array A(1:K,1:K).

B2_out is an M-by-(N-K) rectangular matrix stored in the array B(1:M,K+1:N).

   ( B1_out )        (     0 )                          (     0 )

   ( B2_out )        ( B2_in )                          ( B2_in )
