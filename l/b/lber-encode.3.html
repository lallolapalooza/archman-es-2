LBER_ENCODE(3) Manual de funciones de biblioteca LBER_ENCODE(3)

NOMBRE

ber_alloc_t, ber_flush, ber_flush2, ber_printf, ber_put_int, ber_put_enum, ber_put_ostring, ber_put_string, ber_put_null, ber_put_boolean, ber_put_bitstring, ber_start_seq, ber_start_set, ber_put_seq, ber_put_set - Rutinas de biblioteca OpenLDAP LBER simplificadas de Reglas de Codificación Básicas para la codificación

BIBLIOTECA

OpenLDAP LBER (liblber, -llber)

SINOPSIS

#include <lber.h>

BerElement *ber_alloc_t(int options);

int ber_flush(Sockbuf *sb, BerElement *ber, int freeit);

int ber_flush2(Sockbuf *sb, BerElement *ber, int freeit);

int ber_printf(BerElement *ber, const char *fmt, ...);

int ber_put_int(BerElement *ber, ber_int_t num, ber_tag_t tag);

int ber_put_enum(BerElement *ber, ber_int_t num, ber_tag_t tag);

int ber_put_ostring(BerElement *ber, const char *str, ber_len_t len, ber_tag_t tag);

int ber_put_string(BerElement *ber, const char *str, ber_tag_t tag);

int ber_put_null(BerElement *ber, ber_tag_t tag);

int ber_put_boolean(BerElement *ber, ber_int_t bool, ber_tag_t tag);

int ber_put_bitstring(BerElement *ber, const char *str, ber_len_t blen, ber_tag_t tag);

int ber_start_seq(BerElement *ber, ber_tag_t tag);

int ber_start_set(BerElement *ber, ber_tag_t tag);

int ber_put_seq(BerElement *ber);

int ber_put_set(BerElement *ber);

DESCRIPCIÓN

Estas rutinas proporcionan una interfaz de subrutina a una implementación simplificada de las Reglas de Codificación Básicas (BER) de ASN.1. La versión de BER que soportan estas rutinas es la definida para el protocolo LDAP. Las reglas de codificación son las mismas que las de BER, excepto que solo se utilizan longitudes de forma definida, y los bitstrings y octetstrings siempre se codifican en forma primitiva. Esta página del manual describe las rutinas de codificación de la biblioteca lber. Consulte lber-decode(3) para obtener detalles sobre las rutinas de decodificación correspondientes. Consulte lber-types(3) para obtener información sobre tipos, asignadores y desasignadores.

Normalmente, las únicas rutinas que necesitan ser llamadas por una aplicación son ber_alloc_t() para asignar un elemento BER para la codificación, ber_printf() para realizar la codificación real y ber_flush2() para escribir realmente el elemento. Las otras rutinas se proporcionan para aquellas aplicaciones que necesitan más control del que proporciona ber_printf(). En general, estas rutinas devuelven la longitud del elemento codificado, o -1 si ocurrió un error.

La rutina ber_alloc_t() se utiliza para asignar un nuevo elemento BER. Debe llamarse con un argumento de LBER_USE_DER.

La rutina ber_flush2() se utiliza para escribir realmente el elemento en un socket (o descriptor de archivo), una vez que se ha codificado completamente (usando ber_printf() y similares). Consulte lber-sockbuf(3) para obtener más detalles sobre la implementación de Sockbuf del parámetro sb. Si el parámetro freeit no es cero, el ber suministrado se liberará. Si se usa LBER_FLUSH_FREE_ON_SUCCESS, el ber solo se libera cuando se envía correctamente, de lo contrario, se deja intacto; si se usa LBER_FLUSH_FREE_ON_ERROR, el ber solo se libera cuando ocurre un error, de lo contrario, se deja intacto; si se usa LBER_FLUSH_FREE_ALWAYS, el ber se libera de todos modos. Esta función difiere de la función original ber_flush(3), cuyo comportamiento corresponde al indicado para LBER_FLUSH_FREE_ON_SUCCESS. Tenga en cuenta que en el futuro, el comportamiento de ber_flush(3) con freeit distinto de cero podría cambiar al de ber_flush2(3) con freeit establecido en LBER_FLUSH_FREE_ALWAYS.

La rutina ber_printf() se utiliza para codificar un elemento BER de manera muy similar a como funciona sprintf(3). Sin embargo, una diferencia importante es que se mantiene información de estado con el parámetro ber para que se puedan realizar múltiples llamadas a ber_printf() para agregar cosas al final del elemento BER. Ber_printf() escribe en ber, un puntero a un BerElement como el devuelto por ber_alloc_t(). Interpreta y formatea sus argumentos según la cadena de formato fmt. La cadena de formato puede contener los siguientes caracteres:

b
Booleano. Se debe proporcionar un parámetro ber_int_t. Se genera un elemento booleano.
e
Enumeración. Se debe proporcionar un parámetro ber_int_t. Se genera un elemento de enumeración.
i
Entero. Se debe proporcionar un parámetro ber_int_t. Se genera un elemento entero.
B
Bitstring. Se proporciona un puntero char * al inicio del bitstring, seguido del número de bits en el bitstring. Se genera un elemento bitstring.
n
Nulo. No se requiere ningún parámetro. Se genera un elemento nulo.
o
Octet string. Se proporciona un char *, seguido de la longitud de la cadena apuntada. Se genera un elemento octet string.
O
Octet string. Se proporciona un struct berval *. Se genera un elemento octet string.
s
Octet string. Se proporciona una cadena terminada en nulo. Se genera un elemento octet string, sin incluir el octeto NULO final.
t
Etiqueta. Se proporciona un ber_tag_t que especifica la etiqueta para dar al siguiente elemento. Esto funciona entre llamadas.
v
Varias cadenas de octetos. Se proporciona un array terminado en nulo de char *. Tenga en cuenta que se requiere una construcción como '{v}' para obtener una secuencia real de cadenas de octetos.
V
Varias cadenas de octetos. Se proporciona un array terminado en nulo de struct berval *. Tenga en cuenta que se requiere una construcción como '{V}' para obtener una secuencia real de cadenas de octetos.
W
Varias cadenas de octetos. Se proporciona un array de struct berval. El array se termina con un struct berval con un bv_val NULO. Tenga en cuenta que se requiere una construcción como '{W}' para obtener una secuencia real de cadenas de octetos.
{
Iniciar secuencia. No se requiere ningún parámetro.
}
Fin de secuencia. No se requiere ningún parámetro.
[
Iniciar conjunto. No se requiere ningún parámetro.
]
Fin de conjunto. No se requiere ningún parámetro.

La rutina ber_put_int() escribe el elemento entero num en el elemento BER ber.

La rutina ber_put_enum() escribe el elemento de enumeración num en el elemento BER ber.

La rutina ber_put_boolean() escribe el valor booleano dado por bool en el elemento BER.

La rutina ber_put_bitstring() escribe blen bits comenzando en str como un valor de bitstring en el elemento BER dado. Tenga en cuenta que blen es la longitud *en bits* del bitstring.

La rutina ber_put_ostring() escribe len bytes comenzando en str en el elemento BER como una cadena de octetos.

La rutina ber_put_string() escribe la cadena terminada en nulo (menos el ' ' final) en el elemento BER como una cadena de octetos.

La rutina ber_put_null() escribe un elemento NULO en el elemento BER.

La rutina ber_start_seq() se utiliza para iniciar una secuencia en el elemento BER. La rutina ber_start_set() funciona de manera similar. El final de la secuencia o conjunto se marca con la llamada coincidente más cercana a ber_put_

NOMBRE

ber_printf, ber_scanf, ber_bvprintf, ber_bvscanf - Escribir y leer datos BER

BIBLIOTECA

Libldap

SINOPSIS

#include <lber.h>

int ber_printf(BerElement *ber, const char *fmt, ...)

int ber_scanf(BerElement *ber, const char *fmt, ...)

int ber_bvprintf(BerBuf *bv, const char *fmt, ...)

int ber_bvscanf(BerBuf *bv, const char *fmt, ...)

DESCRIPCIÓN

Estas funciones proporcionan una forma conveniente de codificar y decodificar datos en el formato Basic Encoding Rules (BER). El formato BER se utiliza para representar estructuras de datos ASN.1. La biblioteca libldap utiliza este formato para la comunicación con servidores LDAP.

La función ber_printf se utiliza para codificar datos en una estructura BerElement. El argumento fmt es una cadena de formato que especifica el tipo de datos a codificar, y los argumentos subsiguientes son los valores a codificar. La función ber_scanf se utiliza para decodificar datos de una estructura BerElement. El argumento fmt especifica el formato esperado de los datos, y los argumentos subsiguientes son punteros a las variables donde se almacenarán los valores decodificados.

Las funciones ber_bvprintf y ber_bvscanf son similares a ber_printf y ber_scanf, respectivamente, pero operan sobre una estructura BerBuf, que representa un búfer de bytes. Esto es útil para codificar o decodificar datos que se enviarán o recibirán a través de una red.

Los siguientes especificadores de formato son compatibles:

  • b: Booleano.
  • d: Entero con signo.
  • i: Entero con signo (sinónimo de d).
  • o: Entero sin signo.
  • s: Cadena de caracteres (terminada en nulo).
  • B: OID (Object Identifier).
  • v: Secuencia de cadenas de caracteres (terminadas en nulo).
  • O: Secuencia de OID.
  • E: Enumeración.
  • I: Cadena octal (representación hexadecimal de una cadena de bytes).
  • T: Marca de tiempo.
  • {: Inicio de una secuencia o conjunto.
  • }: Fin de una secuencia o conjunto.
  • @: Cualquier tipo de dato (útil para leer estructuras anidadas sin conocer su contenido).

Los especificadores de formato pueden anidarse para representar estructuras de datos complejas. Por ejemplo, una secuencia de enteros se representaría como i{i}}.

La función ber_printf codifica los datos en el BerElement especificado. Si el BerElement ya contiene datos, los nuevos datos se adjuntarán. Para iniciar una nueva codificación, se debe inicializar el BerElement con ber_alloc_t.

La función ber_scanf decodifica los datos del BerElement especificado. Avanza el puntero de lectura del BerElement a medida que se decodifican los datos. Para leer desde el principio de un BerElement, se puede usar ber_init.

Las funciones ber_bvprintf y ber_bvscanf utilizan un BerBuf para almacenar los datos codificados o leer los datos a decodificar. El BerBuf debe inicializarse adecuadamente antes de su uso, por ejemplo, con ber_alloc.

Tenga en cuenta que ber_printf y ber_scanf (y sus variantes bv) no manejan automáticamente la memoria para los argumentos. El llamante es responsable de asignar y liberar la memoria para las cadenas de caracteres y otras estructuras de datos. La función ber_memalloc y ber_memfree se pueden usar para la gestión de memoria.

EJEMPLOS

Asumiendo las siguientes declaraciones de variables, y que las variables han sido asignadas apropiadamente, una codificación lber del siguiente objeto ASN.1:

      AlmostASearchRequest := SEQUENCE {
          baseObject      DistinguishedName,
          scope           ENUMERATED {
              baseObject    (0),
              singleLevel   (1),
              wholeSubtree  (2)
          },
          derefAliases    ENUMERATED {
              neverDerefaliases   (0),
              derefInSearching    (1),
              derefFindingBaseObj (2),
              alwaysDerefAliases  (3)
          },
          sizelimit       INTEGER (0 .. 65535),
          timelimit       INTEGER (0 .. 65535),
          attrsOnly       BOOLEAN,
          attributes      SEQUENCE OF AttributeType
      }

se puede lograr de la siguiente manera:

      int rc;
      ber_int_t    scope, ali, size, time, attrsonly;
      char   *dn, **attrs;
      BerElement *ber;
      /* ... llenar los valores ... */
      ber = ber_alloc_t( LBER_USE_DER );
      if ( ber == NULL ) {
              /* error */
      }
      rc = ber_printf( ber, "{siiiib{v}}", dn, scope, ali,
          size, time, attrsonly, attrs );
      if( rc == -1 ) {
              /* error */
      } else {
              /* éxito */
      }

ERRORES

Si ocurre un error durante la codificación, generalmente estas rutinas devuelven -1.

NOTAS

Los valores de retorno de todas estas funciones se declaran en el archivo de cabecera <lber.h>.
