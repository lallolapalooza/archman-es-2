NOMBRE

lr_anonymize - anonimiza un archivo de registro

SINOPSIS

lr_anonymize prefijobasearchivo

DESCRIPCIÓN

lr_anonymize se utiliza normalmente al enviar registros a un responder. Consulte la sección "Enviar archivos de registro anonimizados a un responder" en el capítulo "Uso de un responder" del Manual del Usuario de Lire para ver ejemplos de uso.

lr_anonymize lee un archivo que contiene direcciones de correo electrónico, números IP y nombres de host (típicamente un archivo de registro de un servicio de Internet) desde la entrada estándar y imprime una versión "anonimizada" de este archivo en la salida estándar. Descarga la información para "desanonimizar" el archivo, utilizando lr_deanonymize(1), en 5 bases de datos Berkeley DB; los nombres de los archivos que contienen estas bases de datos se construyen concatenando las cadenas 'inaddr', 'maildomain', 'email', 'ip' y 'domain' a prefijobasearchivo. prefijobasearchivo puede ser, por ejemplo, /tmp/dump, ../../var/dump o dump. Los archivos db creados sobrescriben silenciosamente los obsoletos si se encuentran.

El script crea archivos temporales. Por defecto, estos se crean en /tmp. Se puede anular esto estableciendo la variable de entorno TMPDIR.

CONEXIÓN CON lr_deanonymize

Al ejecutar

$ lr_anonymize dump < log > log.anon
$ lr_deanonymize dump < log.anon > log.new

entonces log y log.new tendrán el mismo contenido (excepto por las mayúsculas/minúsculas, compruébelo con diff -i).

NOTAS

Intentamos optimizar este script para el uso de memoria. Esto tiene el inconveniente de que el script tardará bastante tiempo en anonimizar un archivo de registro grande.

Hemos ejecutado el script en un archivo de registro de sendmail de 25 M.

Los valores típicos en este caso son 2500 K para la cantidad total de memoria física utilizada, y 15m real, 8m de usuario y 22s de tiempo de sistema en un sistema de 64 MB con un procesador Pentium II de 300 MHz. La desanonimización de este archivo tardó 11m real, 8m de usuario y 17s de tiempo de sistema.

Almacenamos dominios de correo electrónico en el volcado. Estos son utilizados por lr_deanonymize(1), en caso de que las direcciones de correo electrónico en nuestro archivo de entrada reaparezcan en el archivo leído por lr_deanonymize(1) en forma dividida, es decir, joe.user@example.com aparece como joe.user@example.com y example.com en el archivo a desanonimizar.

Todos los objetos volcados se convierten a minúsculas.

EJEMPLO

Un 'archivo de registro' como, por ejemplo:

blaat fkrf 1.2.3.4.in-addr.arpa] pietje@bigcompany.com bla 1 2 3 lj;agas;gag
blaat 1.2.3.4 fkrf 3.2.3.4.in-addr.arpa] bla 1 www.hotsex.com 2 3 lj;agas;gag 
jan@blaat.frut.com agagag
blaat fkrf 4.2.3.4.in-addr.arpa] bla pietje@bigcompany.com www.hotsex.com 
234.34.2.0 jan@blaat.frut.com 4.2.3.4.in-addr.arpa1 2 3 lj;agas;gag
blaat fkrf tweede 3.2.3.4.in-addr.arpa] bla 1.2.3.4 1 blablabla.com 
2 mdcc.cx 
3 lj;agas;gag

será anonimizado a:

blaat fkrf 1.0.0.10.in-addr.arpa] john.doe.1@example.com bla 1 2 3 lj;agas;gag
blaat 10.0.0.1 fkrf 2.0.0.10.in-addr.arpa] bla 1 1.example.com 2 3 lj;agas;gag 
john.doe.2@example.com agagag
blaat fkrf 3.0.0.10.in-addr.arpa] bla john.doe.1@example.com 1.example.com 
10.0.0.2 john.doe.2@example.com 3.0.0.10.in-addr.arpa1 2 3 lj;agas;gag
blaat fkrf tweede 2.0.0.10.in-addr.arpa] bla 10.0.0.1 1 2.example.com 
2 3.example.com 
3 lj;agas;gag

Los volcados representarán algo como:

ip 234.34.2.0 10.0.0.2
ip 1.2.3.4 10.0.0.1
inaddr 3.2.3.4.in-addr.arpa 2.0.0.10.in-addr.arpa
inaddr 1.2.3.4.in-addr.arpa 1.0.0.10.in-addr.arpa
inaddr 4.2.3.4.in-addr.arpa 3.0.0.10.in-addr.arpa
domain mdcc.cx 3.example.com
domain blablabla.com 2.example.com
domain www.hotsex.com 1.example.com
email jan@blaat.frut.com john.doe.2@example.com
email pietje@bigcompany.com john.doe.1@example.com

ERRORES

No podemos manejar archivos que contengan nombres de host o direcciones de correo electrónico en el dominio example.com, nombres de usuario del tipo john.doe.<algunasletras> o números IP en la red privada rfc 1918 10.0.0.0 - 10.255.255.255 (prefijo 10/8).

No manejamos cadenas entrecomilladas en direcciones de correo electrónico. No manejamos literales de dominio en el dominio de las direcciones de correo electrónico.

Consideramos 999.999.999.999 como una dirección IP: no nos importa el límite de 255.

No tratamos las direcciones IP de red como 100.10.3 como direcciones IP. Estas *no* serán anonimizadas.

lr_anonymize(1)

NOMBRE

lr_anonymize — anonimiza el tráfico de red registrado por lr_replay

SINOPSIS

lr_anonymize [-i input] [-o output] [-n new_ip] [-m new_mac]

DESCRIPCIÓN

lr_anonymize es una utilidad que anonimiza los registros de tráfico de red creados por lr_replay. Busca y reemplaza las direcciones IP y MAC de origen y destino por valores ficticios, preservando así la estructura de la comunicación sin revelar información de identidad.

CONEXIÓN CON lr_deanonymize

Este comando se utiliza en conjunto con lr_deanonymize. Mientras que lr_anonymize oculta las direcciones originales, lr_deanonymize puede restaurarlas si se dispone de la clave de mapeo generada durante la anonimización.

NOTAS

El uso de esta herramienta requiere que el tráfico haya sido previamente registrado por lr_replay.

ANTECEDENTES

En escenarios de pruebas o demostraciones donde se utiliza tráfico de red real, a menudo es necesario anonimizar los datos para proteger la privacidad de los usuarios o las entidades involucradas. lr_anonymize proporciona una solución sencilla para este propósito.

EJEMPLO

Para anonimizar un archivo de registro llamado traffic.log y guardar el resultado en anonymized_traffic.log, asignando una nueva IP ficticia 192.168.1.1 y una MAC ficticia 00:11:22:33:44:55, se ejecutaría el siguiente comando:

lr_anonymize -i traffic.log -o anonymized_traffic.log -n 192.168.1.1 -m 00:11:22:33:44:55

ERRORES

Reportar errores a la lista de correo de Arch Linux o al bug tracker del paquete.

VER TAMBIÉN

lr_replay(1), lr_deanonymize(1)
