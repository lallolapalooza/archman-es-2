SZ(1) Manual de Comandos Generales SZ(1)

NOMBRE

sx, sb, sz - envío de archivos XMODEM, YMODEM, ZMODEM

SINOPSIS

sz [-+8abdefkLlNnopqTtuvyY] archivo ...
sb [-adfkqtuv] archivo ...
sx [-akqtuv] archivo
sz [-oqtv] -c COMANDO
sz [-oqtv] -i COMANDO
sz -TT

DESCRIPCIÓN

Sz utiliza el protocolo de corrección de errores ZMODEM, YMODEM o XMODEM para enviar uno o varios archivos a través de un puerto serie de acceso telefónico a diversos programas que se ejecutan en PC-DOS, CP/M, Unix, VMS y otros sistemas operativos.

Mientras que rz es lo suficientemente inteligente como para ser llamado desde cu(1), muy pocas versiones de cu(1) son lo suficientemente inteligentes como para que sz funcione correctamente. Hay disponibles versiones de Unix de Professional-YAM para tales aplicaciones de marcado saliente.

Sz envía uno o varios archivos con el protocolo ZMODEM.

ZMODEM simplifica enormemente las transferencias de archivos en comparación con XMODEM. Además de una interfaz de usuario amigable, ZMODEM proporciona a los usuarios de PC y otros usuarios un método de transferencia de archivos eficiente, preciso y robusto.

ZMODEM proporciona integridad de datos de **EXTREMO A EXTREMO** entre los programas de aplicación. El CRC de 32 bits de ZMODEM detecta errores que se cuelan incluso en las redes más avanzadas.

Las funciones avanzadas de gestión de archivos incluyen AutoDownload (descarga automática de archivos iniciada sin intervención del usuario), visualización de longitudes de archivos individuales y totales y estimaciones de tiempo de transmisión, recuperación de fallos, transferencias selectivas de archivos y preservación de la fecha y longitud exactas del archivo.

La salida de otro programa puede ser canalizada a sz para su transmisión, denotando la entrada estándar con "-":
ls -l | sz -
La salida del programa se transmite con el nombre de archivo sPID.sz donde PID es el ID de proceso del programa sz. Si la variable de entorno ONAME está configurada, se utiliza en su lugar. En este caso, el comando Unix:
ls -l | ONAME=con sz -ay -
enviará un "archivo" a la pantalla de la consola de PC-DOS. La opción -y indica al receptor que abra el archivo para escribir incondicionalmente. La opción -a hace que el receptor convierta los saltos de línea de Unix en retornos de carro y saltos de línea de PC-DOS.

Sb envía por lotes uno o varios archivos con el protocolo YMODEM o ZMODEM. No se envía la inicialización ZMODEM inicial. Cuando lo solicita el receptor, sb admite YMODEM-g con modo tty "cbreak", control de flujo XON/XOFF y carácter de interrupción establecido en CAN (^X). YMODEM-g (opción g de Professional-YAM) aumenta el rendimiento en canales sin errores (conexión directa, X.PC, etc.) al no reconocer cada sector transmitido.

En sistemas Unix, se transmite información adicional sobre el archivo. Si el programa receptor utiliza esta información, la longitud del archivo transmitido controla el número exacto de bytes escritos en el conjunto de datos de salida, y la hora de modificación y el modo de archivo se establecen en consecuencia.

Sx envía un único archivo con el protocolo XMODEM o XMODEM-1k (a veces incorrectamente llamado "ymodem"). El usuario debe proporcionar el nombre del archivo tanto a los programas de envío como de recepción.

Si sz se invoca con $SHELL configurada y si esa variable contiene la cadena rsh, rbash o rksh (shell restringida), sz opera en modo restringido. El modo restringido restringe los nombres de ruta al directorio actual y PUBDIR (generalmente /usr/spool/uucppublic) y/o sus subdirectorios.

La cuarta forma envía un único COMANDO a un receptor ZMODEM para su ejecución. Sz sale con el valor de retorno del COMANDO. Si el COMANDO incluye espacios o caracteres especiales para el shell, debe ser entrecomillado.

La quinta forma envía un único COMANDO a un receptor ZMODEM para su ejecución. Sz sale tan pronto como el receptor haya recibido correctamente el comando, antes de que se ejecute.

La sexta forma (sz -TT) intenta enviar todas las 256 combinaciones de códigos a la terminal. Si tiene dificultades para enviar archivos, este comando le permite ver qué códigos de caracteres están siendo consumidos por el sistema operativo.

Si sz se invoca con stdout y stderr a conjuntos de datos diferentes, Verbose se establece en 2, causando informes de progreso cuadro a cuadro a stderr. Esto puede ser deshabilitado con la opción q.

Los significados de las opciones disponibles son:

-+, --append
Instruye al receptor que añada los datos transmitidos a un archivo existente (solo ZMODEM).
-2, --twostop
usa dos bits de parada (si es posible). No use esto a menos que sepa lo que está haciendo.
-8, --try-8k
Intenta aumentar el tamaño de bloque hasta 8 KB. Esto es incompatible con el zmodem estándar, pero es una extensión común en el mundo BBS (solo ZMODEM).
--start-8k
Comienza con un tamaño de bloque de 8 KB. Como --try-8k.
-a, --ascii
Convierte los caracteres NL en el archivo transmitido a CR/LF. Esto lo realiza el emisor para XMODEM y YMODEM, y el receptor para ZMODEM.
-b, --binary
(ZMODEM) Anulación binaria: transfiere el archivo sin ninguna traducción.
-B NÚMERO, --bufsize NÚMERO
Utiliza un búfer de lectura de NÚMERO bytes. El valor predeterminado es 16384, que debería ser suficiente para la mayoría de las situaciones. Si tiene una máquina lenta, una interfaz de disco defectuosa o sufre otros problemas de hardware, puede que desee aumentar el tamaño del búfer. -1 o auto usan un búfer lo suficientemente grande como para almacenar todo el archivo en búfer. Tenga cuidado con esta opción: las cosas normalmente empeoran, no mejoran, si la máquina empieza a paginar.

El uso de esta opción desactiva el mapeo de memoria del archivo de entrada. Esto aumenta el uso de memoria y CPU.

-c COMANDO, --command COMANDO
Envía el COMANDO al receptor para su ejecución, y sale con el estado de salida del COMANDO.
-C N, --command-tries N
Reintenta enviar el comando N veces (predeterminado: 11).
-d, --dot-to-slash
Cambia todas las instancias de "." por "/" en la ruta transmitida. Por lo tanto, C.omenB0000 (que es inaceptable para MSDOS o CP/M) se transmite como C/omenB0000. Si el nombre de archivo resultante tiene más de 8 caracteres en el tallo, se inserta un "." para permitir un total de once.

Esta opción activa la opción --full-path.

--delay-startup N
Espera N segundos antes de hacer nada.
-e, --escape
Escapa todos los caracteres de control; normalmente se escapan XON, XOFF, DLE, CR-@-CR y Ctrl-X.
Obliga al emisor a renombrar el nuevo archivo si un archivo con el mismo
nombre ya existe.
-f, --full-path
Envía la ruta completa. Normalmente, los prefijos del directorio se eliminan del nombre de archivo transmitido.

Esto también se activa con la opción --dot-to-slash.

-h, --help
muestra ayuda.
-i COMANDO, --immediate-command COMANDO
Envía el COMANDO al receptor para su ejecución, y sale inmediatamente tras la recepción correcta del comando por parte del programa receptor.
-k, --1k
(XMODEM/YMODEM) Envía archivos utilizando bloques de 1024 bytes en lugar de los bloques predeterminados de 128 bytes. Los paquetes de 1024 bytes aceleran las transferencias de archivos a altas velocidades de bits (ZMODEM transmite los datos en secuencias para obtener el mejor rendimiento posible).
-L N, --packetlen N
Utiliza subpaquetes ZMODEM de longitud N. Un N mayor (32 <= N <= 1024) proporciona un rendimiento ligeramente mayor, un N menor acelera la recuperación de errores. El valor predeterminado es 128 por debajo de 300 baudios, 256 por encima de 300 baudios, o 1024 por encima de 2400 baudios.
-m N, --min-bps N
Detiene la transmisión si la Tasa BPS (Bytes Por Segundo) cae por debajo de N durante un cierto tiempo (ver la opción --min-bps-time).
-M N, --min-bps-time
Se usa junto con --min-bps. El valor predeterminado es 120 (segundos).
-l N, --framelen N
Espera a que el receptor acuse recibo de datos correctos cada N (32 <= N <= 1024) caracteres. Esto puede usarse para evitar que el búfer de captura del programa receptor se desborde, lo que podría suceder si el sistema operativo envía datos al programa a una velocidad superior a la que el programa puede procesar. Cuando se utiliza esta opción, el remitente es periódicamente notificado por el receptor de que debe enviar más datos. Esto es necesario solo cuando se transmite a través de un enlace serial y el receptor está muy sobrecargado. Cuando se usa esta opción, la interfaz serial se pone en modo de "retardo de tiempo" y se generan retornos de carro adicionales, que se ignoran en su mayoría.
-N, --newer
Solo envía archivos más nuevos que los archivos existentes en el destino. Esto solo se puede usar con ZMODEM.
-n, --names-only
Envía solo los nombres de los archivos y la información de estado, no los archivos en sí. Esto se usa para configurar los archivos en la máquina receptora y, a continuación, para ejecutar un script que genere los archivos.
-o, --overwrite
(ZMODEM/YMODEM) Sobrescribe los archivos existentes sin preguntar.
-p, --protect
Protege los archivos existentes. No sobrescribirá un archivo existente sin preguntar. Los archivos solo se enviarán si el archivo correspondiente en el sistema receptor no existe.
-q, --quiet
Suprime los informes de progreso por pantalla.
-r, --resume
(ZMODEM) Permite reanudar transferencias interrumpidas. Si la transferencia se interrumpe, el receptor le preguntará si desea reanudar la transferencia y continuar desde donde se interrumpió.
-R, --rename
Si el archivo existe, solicita al usuario que introduzca un nuevo nombre para el archivo que se va a recibir. Esto solo se puede usar con ZMODEM.
-s, --swap
Canjea las líneas de texto: los caracteres de retorno de carro se cambian por saltos de línea y viceversa. Esto se hace en el lado del receptor.
-t, --telnet-trick
Activa el "truco Telnet". Los caracteres de control de Telnet (255, 254, 253, etc.) se escapan como 255 255, 255 254, etc.
-T, --terminal-type
Establece el tipo de terminal para el receptor.
-u, --truncate
(ZMODEM) Trunca los archivos existentes a cero bytes. Esto es útil para enviar archivos vacíos o para borrar el contenido de un archivo existente antes de enviar un nuevo archivo con el mismo nombre.
-v, --verbose
Informes de progreso detallados. -v (o --verbose) muestra el nombre del archivo, el número de bytes, el porcentaje y la velocidad de transmisión. -vv (o --syslog) escribe en el registro del sistema en lugar de en la pantalla. -vvv (o --syslog-only) lo mismo, pero sin salir.
-V, --version
muestra la versión.
-w N, --window N
Establece el tamaño de la ventana de ZMODEM a N bytes. El valor predeterminado es 1024 bytes.
-x, --hexagon
(XMODEM) Transmite cada bloque de datos en formato hexadecimal de 16 bits. Esto es útil para depurar o para transferir datos que no son de texto simple.
-y, --no-prompt
No preguntar. Sobrescribe los archivos existentes sin preguntar.
-Y, --trust
Confiar en el receptor. No solicita al usuario confirmación antes de sobrescribir archivos existentes.
-Z, --nobatch
Desactiva la transferencia por lotes. Si se especifica, solo se puede enviar un archivo a la vez. Esto es útil si solo desea enviar un archivo y no quiere que el receptor intente recibir varios archivos.
-z N, -- MZN
Utiliza el protocolo ZMODEM con un tamaño de bloque de N. N puede ser hasta 1024. El valor predeterminado es 128. Un tamaño de bloque más grande aumenta la velocidad de transferencia.

DIAGNÓSTICOS

Los mensajes de error indican la causa del problema y cómo se puede resolver.

ERRORES

Aunque el protocolo ZMODEM es muy robusto, pueden ocurrir errores de transmisión. En tales casos, el programa debería informar del error y detenerse. Si esto no sucede, intente usar la opción -e para escapar todos los caracteres de control.

Los archivos binarios enviados con la opción -b (binario) deben ser recibidos con el protocolo binario para evitar la corrupción de datos.

--tcp
Intentar iniciar una conexión TCP/IP. lsz pedirá al zmodem receptor que abra una conexión TCP/IP. Todo el handshake (qué dirección / puerto usar) será manejado por los programas zmodem.

Normalmente no querrás usar esta opción ya que lrzsz es el único zmodem que entiende qué hacer (extensión privada). Podrías querer usar esta opción si los dos programas están conectados (stdin/out) a través de una conexión de red lenta o mala (no limpia de 8 bits).

--tcp-server

Normalmente no querrás usar esta opción ya que lrzsz es el único zmodem que entiende qué hacer (extensión privada). Si usas esta opción tienes que iniciar lsz con la opción --tcp-client ADDRESS:PORT. lrz imprimirá la dirección y el puerto al iniciarse.

El uso de esta opción impone un riesgo de seguridad, alguien más podría conectarse al puerto en el medio. Ver SECURITY para detalles.

SEGURIDAD

El modo restringido restringe los nombres de ruta al directorio actual y PUBDIR (generalmente /var/spool/uucppublic) y/o sus subdirectorios, y desactiva la ejecución remota de comandos.

Se entra en modo restringido si se proporciona la opción R o si lsz detecta que se está ejecutando bajo un shell restringido o si se encuentra la variable de entorno ZMODEM_RESTRICTED.

El modo restringido se puede desactivar con la opción U si no se está ejecutando bajo un shell restringido.

El uso de las
opciones --tcp-client o --tcp-server impone un riesgo de seguridad, ya que alguien más podría conectarse al puerto antes que tú, y robar tus datos. Si hay una fuerte demanda de un modo más seguro, podría introducir algún tipo de desafío de contraseña.

ENTORNO

ZNULLS
Puede usarse para especificar el número de nulos a enviar antes de un marco ZDATA.
SHELL
lsz reconoce un shell restringido si esta variable incluye rsh o rksh
ZMODEM_RESTRICTED
lrz entra en modo restringido si la variable está establecida.
TMPDIR
Si esta variable de entorno está establecida, su contenido se utiliza como directorio para colocar en el archivo de respuesta a una solicitud de timesync. TMP Se usa en lugar de TMPDIR si TMPDIR no está establecido. Si ni TMPDIR ni TMP están establecidos, se usará /tmp.

EJEMPLOS

Transferencia de archivos ZMODEM (Unix a DSZ/ZCOMM/Professional-YAM)
% sz -a *.c
Este único comando transfiere todos los archivos .c en el directorio Unix actual con conversión (-a) a las convenciones de fin de línea apropiadas para el entorno receptor. Con la descarga automática de ZMODEM activada, Professional-YAM y ZCOMM recibirán automáticamente los archivos después de realizar una verificación de seguridad.

% sz -Yan *.c *.h
Enviar solo los archivos .c y .h que existen en ambos sistemas, y son más nuevos en el sistema emisor que la versión correspondiente en el sistema receptor, convirtiendo de formato de texto Unix a DOS.
$ sz -\Yan file1.c file2.c file3.c foo.h baz.h (para VMS)

Descarga de comandos ZMODEM (Unix a Professional-YAM)
cpszall:all
sz -c "c:;cd /yam/dist"
sz -ya $(YD)/*.me
sz -yqb y*.exe
sz -c "cd /yam"
sz -i "!insms"
Este fragmento de Makefile utiliza sz para emitir comandos a Professional-YAM para cambiar el disco y el directorio actual. A continuación, sz transfiere los archivos .me del directorio $YD, ordenando al receptor que sobrescriba los archivos antiguos y que convierta de las convenciones de fin de línea de Unix a las de PC-DOS. El tercer comando transfiere algunos archivos .exe. El cuarto y quinto comando ordenan a Pro-YAM que cambie de directorio y ejecute un archivo por lotes de PC-DOS insms . Dado que el archivo por lotes lleva mucho tiempo, se utiliza la forma -i para permitir que sz salga inmediatamente.

Transferencia de archivos XMODEM (Unix a Crosstalk)
% sx -a foo.c
ESC
rx foo.c
Los tres comandos anteriores transfieren un solo archivo de Unix a una PC y a Crosstalk con sz traduciendo los saltos de línea de Unix a DOS CR/LF. Esta combinación es mucho más lenta y mucho menos confiable que ZMODEM.

PRUEBA DE FUNCIÓN

El comando "sz -T archivo" ejercita la recuperación de errores de la secuencia Attn ordenando errores con paquetes no terminados. El programa receptor debería quejarse cinco veces de que los paquetes de datos binarios son demasiado largos. Cada vez que se interrumpe sz, debería enviar una cabecera ZDATA seguida de otro paquete defectuoso. Si el receptor no detecta cinco paquetes de datos largos, la secuencia Attn no está interrumpiendo al remitente, y la cadena Myattn en sz.c debe modificarse.

Después de 5 paquetes, sz detiene la "transferencia" e imprime el número total de caracteres "enviados" (Tcount). La diferencia entre Tcount y 5120 representa el número de caracteres almacenados en varios búferes cuando se genera la secuencia Attn.

ERRORES

Llamar a sz desde la mayoría de las versiones de cu(1) no funciona porque el proceso de recepción de cu lucha contra sz por los caracteres del módem.

En al menos un sistema BSD, sz se colgaba o salía cuando llegaba a unos pocos kilobytes del final del archivo. El uso de la opción "-w 8192" solucionó el problema. La causa real es desconocida, quizás un error en las rutinas de salida TTY del kernel.

Los programas que no implementan correctamente el protocolo de transferencia de archivos especificado pueden hacer que sz "cuelgue" el puerto durante uno o dos minutos. Este problema se corrige utilizando ZCOMM, Pro-YAM u otro programa con una implementación correcta del protocolo especificado.

Muchos programas que afirman admitir YMODEM solo admiten XMODEM con bloques de 1k, y a menudo ni siquiera eso lo hacen del todo bien.

Las transferencias XMODEM añaden hasta 127 bytes basura por archivo. Las transferencias XMODEM-1k y YMODEM-1k utilizan bloques de 128 bytes para evitar relleno adicional.

Los programas YMODEM utilizan la longitud del archivo transmitida al principio de la transferencia para recortar el archivo a la longitud correcta; esto puede causar problemas con archivos fuente que crecen durante la transferencia. Este problema no se aplica a las transferencias ZMODEM, que conservan la longitud exacta del archivo incondicionalmente.

La mayoría de las opciones de ZMODEM simplemente se pasan al programa receptor; algunas no implementan todas estas opciones.

Se debe usar buffering circular y una ventana deslizante ZMODEM cuando la entrada proviene de tuberías en lugar de acuses de recibo de tramas cada 1024 bytes. Si no se pueden abrir archivos, sz envía un comando ZMODEM para hacer eco de una queja adecuada; quizás debería comprobar la presencia de al menos un archivo accesible antes de ponerse nervioso. El modo de prueba deja un archivo de longitud cero en el sistema receptor.

Algunos módems de alta velocidad tienen un error de firmware que descarta caracteres cuando se invierte la dirección de transmisión de alta velocidad. La variable de entorno ZNULLS se puede usar para especificar el número de nulos a enviar antes de una trama ZDATA. Valores de 101 para un PC de 4,77 MHz y 124 para un AT son típicos.
