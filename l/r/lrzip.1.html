NOMBRE

lrzip - un programa de compresión de archivos grandes

SINOPSIS

lrzip [OPCIONES] <archivo>
lrzip -d [OPCIONES] <archivo>
lrunzip [OPCIONES] <archivo>
lrzcat [OPCIONES] <archivo>
lrztar [opciones de lrzip] <directorio>
lrztar -d [opciones de lrzip] <directorio>
lrzuntar [opciones de lrzip] <directorio>
lrz [opciones de lrz] <directorio>
LRZIP=NOCONFIG [lrzip|lrunzip] [OPCIONES] <archivo>

DESCRIPCIÓN

LRZIP es un programa de compresión de archivos diseñado para funcionar especialmente bien con archivos muy grandes que contienen redundancia de larga distancia. lrztar es un envoltorio para LRZIP para simplificar la compresión y descompresión de directorios.

RESUMEN DE OPCIONES

Aquí hay un resumen de las opciones para lrzip.

Opciones generales:
 -c, --check             comprobar la integridad del archivo escrito al descomprimir
 -d, --decompress        descomprimir
 -e, --encrypt[=contraseña] cifrado con contraseña protegido con sha512/aes128 al comprimir
 -h, -?, --help          mostrar ayuda
 -H, --hash              mostrar información de integridad de hash md5
 -i, --info              mostrar información del archivo comprimido
 -q, --quiet             no mostrar el progreso de la compresión
 -Q, --very-quiet        no mostrar ninguna salida
 -r, --recursive         operar recursivamente en directorios
 -t, --test              probar la integridad del archivo comprimido
 -v[v], --verbose        aumentar la verbosidad
 -V, --version           mostrar versión
Opciones que afectan la salida:
 -D, --delete            eliminar archivos existentes
 -f, --force             forzar la sobrescritura de archivos existentes
 -k, --keep-broken       conservar archivos rotos o dañados
 -o, --outfile nombrearchivo  especificar el nombre y/o la ruta del archivo de salida
 -O, --outdir directorio  especificar el directorio de salida cuando no se usa -o
 -S, --suffix sufijo     especificar el sufijo comprimido (por defecto '.lrz')
Opciones que afectan la compresión:
 -b, --bzip2             compresión bzip2
 -g, --gzip              compresión gzip usando zlib
 -l, --lzo               compresión lzo (ultra rápida)
 -n, --no-compress       sin compresión de backend - preparar para otro compresor
 -z, --zpaq              compresión zpaq (mejor, compresión extrema, extremadamente lenta)
Opciones de bajo nivel:
 -L, --level nivel       establecer el nivel de compresión lzma/bzip2/gzip (1-9, por defecto 7)
 -N, --nice-level valor  Establecer el valor nice a valor (por defecto 19)
 -p, --threads valor     Establecer el número de procesadores para anular el número de hilos
 -m, --maxram tamaño     Establecer la RAM máxima disponible en cientos de MB
                         anula la cantidad detectada de RAM disponible
 -T, --threshold         Desactivar pruebas de compresibilidad LZ4
 -U, --unlimited         Usar tamaño de ventana ilimitado más allá del tamaño de la RAM (potencialmente mucho más lento)
 -w, --window tamaño     ventana máxima de compresión en cientos de MB
                         el valor por defecto es elegido por heurística dependiente de la RAM y la compresión elegida
La variable de entorno LRZIP=NOCONFIG puede usarse para omitir lrzip.conf.
La variable de entorno TMP se usará para almacenar archivos temporales cuando sea necesario.
TMPDIR también puede almacenarse en el archivo lrzip.conf.
Si no se especifican nombres de archivo o "-", se usará stdin/out.

OPCIONES

Opciones generales

-c
Esta opción habilita la verificación de la integridad del archivo escrito en disco al descomprimir. Toda la descompresión se prueba internamente en lrzip con verificación de hash crc32 o md5 dependiendo de la versión del archivo ya. Sin embargo, el archivo escrito en disco puede corromperse por otras razones relacionadas con otros problemas del espacio de usuario, como versiones de bibliotecas defectuosas, controladores, fallos de hardware, etc. Habilitar esta opción hará que lrzip realice una verificación de hash md5 en el archivo que se escribe en el disco. Cuando el archivo tiene el valor md5 almacenado en él, se compara con este. De lo contrario, se compara con el valor calculado durante la descompresión. Esto ofrece una garantía adicional de que el archivo escrito es el mismo que el archivo original.
-d
Descomprimir. Si esta opción no se usa, lrzip mira el nombre con el que se lanzó el programa. Si contiene la cadena "lrunzip", la opción -d se establece automáticamente. Si contiene la cadena "lrzcat", las opciones -d -o - se establecen automáticamente.
-e
--encrypt[=contraseña]
Cifrar. Esta opción habilita el cifrado de contraseña de alta calidad utilizando una combinación de contraseña hasheada sha512, sal aleatoria y cifrado AES128 CBC. Se admiten contraseñas de hasta 500 caracteres, y el mecanismo de cifrado utilizado garantiza virtualmente que el mismo archivo creado con la misma contraseña nunca será el mismo. Además, el hash de la contraseña aumenta según la fecha en que se cifra el archivo, aumentando el número de ciclos de CPU requeridos para cada intento de contraseña de acuerdo con la ley de Moore, lo que hace que la dificultad de intentar ataques de fuerza bruta sea proporcional a la potencia de las computadoras modernas.
-h|-?
Imprimir un resumen de opciones
-H
Esto muestra el valor del hash md5 calculado al comprimir o descomprimir un archivo lrzip. Por defecto, toda la compresión tiene el valor md5 calculado y almacenado en todos los archivos desde la versión 0.560. Al descomprimir, cuando se encuentra un valor md5, se calculará y se utilizará para la verificación de integridad. Si el valor md5 no está almacenado en el archivo, no se calculará a menos que se especifique explícitamente con esta opción, o se haya solicitado comprobar la integridad (ver más abajo).
-i
Esto muestra información sobre un archivo comprimido. Muestra el tamaño comprimido, el tamaño descomprimido, la relación de compresión, qué compresión se utilizó y qué verificación de hash se utilizará para la verificación de integridad interna. Tenga en cuenta que el modo de compresión se detecta solo del primer bloque y mostrará sin compresión si el primer bloque fue incompresible, incluso si los bloques posteriores fueron compresibles. Si se agregan opciones detalladas -v o -vv, también se mostrará un desglose de todos los bloques internos e información progresivamente más detallada relacionada con ellos.
-q
Si se especifica esta opción, lrzip no mostrará el progreso porcentual mientras comprime. Tenga en cuenta que la compresión ocurre en ráfagas con compresión lzma, que es la compresión predeterminada. Esto significa que progresará muy rápidamente durante períodos cortos y luego se detendrá durante períodos largos.
-Q
Si se especifica esta opción, lrzip no mostrará ninguna salida en la consola, excepto mensajes de error.
-r
Si se especifica esta opción, lrzip entrará recursivamente en los directorios especificados, comprimiendo o descomprimiendo cada archivo individualmente en el mismo directorio. Tenga en cuenta que para una mejor compresión, se recomienda combinar los archivos en un archivo tar en lugar de comprimirlos por separado, ya sea manualmente o con la utilidad lrztar.
-t
Esto prueba la integridad del archivo comprimido. Lo hace descomprimiéndolo en un archivo temporal y luego eliminándolo.
-v[v]
Aumenta la verbosidad. -vv imprimirá más mensajes que -v.
-V
Imprime el número de versión de lrzip

Opciones que afectan la salida

-D
Si se especifica esta opción, lrzip eliminará el archivo de origen después de la compresión o descompresión exitosa. Cuando esta opción no se especifica, los archivos de origen no se eliminan.
-f
Si esta opción no se especifica (Predeterminado), lrzip no sobrescribirá ningún archivo existente. Si establece esta opción, rzip sobrescribirá silenciosamente los archivos según sea necesario.
-k
Esta opción conservará los archivos rotos o dañados en lugar de eliminarlos. Cuando la compresión o descompresión se interrumpe por el usuario o por un error, o un archivo descomprimido falla una verificación de integridad, normalmente es eliminado por LRZIP.

NAME

lrzip

a long range file compressor

SYNOPSIS

lrzip [OPTIONS] [FILE...]
lrunzip [OPTIONS] [FILE...]
lrzcat [OPTIONS] [FILE...]
lrztar [OPTIONS] [FILE...]
lruntar [OPTIONS] [FILE...]

DESCRIPTION

Lrzip is a general purpose command line compression utility. It is intended to be a replacement for Lempel-Ziv based compressors such as gzip, bzip2 and lzma, offering better compression ratios on certain types of files. In particular, lrzip is designed to find and exploit redundancy over very long distances in the input data.

The key difference between lrzip and other well known compression algorithms is its ability to take advantage of very long distance redundancy. The well known deflate algorithm used in gzip uses a maximum history buffer of 32k. The block sorting algorithm used in bzip2 is limited to 900k of history. The history buffer in lrzip can be any size long, not even limited by available ram.

It is quite common these days to need to compress files that contain long distance redundancies. For example, when compressing a set of home directories several users might have copies of the same file, or of quite similar files. It is also common to have a single file that contains large duplicated chunks over long distances, such as pdf files containing repeated copies of the same image. Most compression programs won't be able to take advantage of this redundancy, and thus might achieve a much lower compression ratio than lrzip can achieve.

Lrzip operates in two stages. The first stage finds and encodes large chunks of duplicated data over potentially very long distances in the input file. The second stage is to use a compression algorithm to compress the output of the first stage. The compression algorithm can be chosen to be optimised for extreme size (zpaq), size (lzma - default), speed (lzo), legacy (bzip2 or gzip) or can be omitted entirely doing only the first stage. A one stage only compressed file can almost always improve both the compression size and speed done by a subsequent compression program.

The companion programs are:

lrunzip
Decompress files compressed with lrzip.
lrzcat
Decompress files compressed with lrzip to standard output.
lrztar
Compresses multiple files into a single tar archive, then compresses that archive using lrzip. This command is therefore a convenient wrapper around the tar and lrzip commands.
lruntar
Decompresses a file compressed with lrzip, then extracts the tar archive.

OPTIONS

Options are implemented by using flags as per the GNU style of implementation.

Basic operations

-d
Decompress. This is the default action of lrunzip.
-z
Compress. This is the default action of lrzip.
-t
Test the integrity of compressed files.

Output options

-o
Set the output file name. If this option is not set then the output file name is chosen based on the input name and the suffix. The -o option cannot be used if more than one file name is specified on the command line.
-O
Set the output directory for the default filename. This option cannot be combined with -o.
-S
Set the compression suffix. The default is '.lrz'.

Options affecting compression

-b
Bzip2 compression. Uses bzip2 compression for the 2nd stage, much like the original rzip does.
-g
Gzip compression. Uses gzip compression for the 2nd stage. Uses libz compress and uncompress functions.
-l
LZO Compression. If this option is set then lrzip will use the ultra fast lzo compression algorithm for the 2nd stage. This mode of compression gives bzip2 like compression at the speed it would normally take to simply copy the file, giving excellent compression/time value.
-n
No 2nd stage compression. If this option is set then lrzip will only perform the long distance redundancy 1st stage compression. While this does not compress any faster than LZO compression, it produces a smaller file that then responds better to further compression (by eg another application), also reducing the compression time substantially.
-z
ZPAQ compression. Uses ZPAQ compression which is from the PAQ family of compressors known for having some of the highest compression ratios possible but at the cost of being extremely slow on both compress and decompress (4x slower than lzma which is the default).

Low level options

-L 1..9
Set the compression level from 1 to 9. The default is to use level 7, which gives good all round compression. The compression level is also strongly related to how much memory lrzip uses. See the -w option for details.
-N value
The default nice value is 19. This option can be used to set the priority scheduling for the lrzip backup or decompression. Valid nice values are from -20 to 19. Note this does NOT speed up or slow down compression.
-p value
Set the number of processor count to determine the number of threads to run. Normally lrzip will scale according to the number of CPUs it detects. Using this will override the value in case you wish to use less CPUs to either decrease the load on your machine, or to improve compression. Setting it to 1 will maximise compression but will not attempt to use more than one CPU.
-T
Disables the LZ4 compressibility threshold testing when a slower compression back-end is used. LZ4 testing is normally performed for the slower back-end compression of LZMA and ZPAQ. The reasoning is that if it is completely incompressible by LZ4 then it will also be incompressible by them. Thus if a block fails to be compressed by the very fast LZ4, lrzip will not attempt to compress that block with the slower compressor, thereby saving time. If this option is enabled, it will bypass the LZ4 testing and attempt to compress each block regardless.
-U
Unlimited window size. If this option is set, and the file being compressed does not fit into the available ram, lrzip will use a moving second buffer as a "sliding mmap" which emulates having infinite ram. This will provide the most possible compression in the first rzip stage which can improve the compression of ultra large files when they're bigger than the available ram. However it runs progressively slower the larger the difference between ram and the file size, so is best reserved for when the smallest possible size is desired on a very large file, and the time taken is not important.
-w n
Set the maximum allowable compression window size to n in hundreds of megabytes. This is the amount of memory lrzip will search during its first stage of pre-compression and is the main thing that will determine how much benefit lrzip will provide over ordinary compression with the 2nd stage algorithm. If not set (recommended), the value chosen will be determined by an internal heuristic in lrzip which uses the most memory that is reasonable, without any hard upper limit. It is limited to 2GB on 32bit machines. lrzip will always reduce the window size to the biggest it can be without running out of memory.

INSTALLATION

"make install" or just install lrzip somewhere in your search path.

FILES

LRZIP recognises a configuration file that contains default settings. This configuration is searched for in the current directory, /etc/lrzip, and $HOME/.lrzip. The configuration filename must be lrzip.conf.

ENVIRONMENT

By default, lrzip will search for and use a configuration file, lrzip.conf. If the user wishes to bypass the file, a startup ENV variable may be set.
LRZIP = NOCONFIG [lrzip|lrunzip] [OPTIONS] <file>
which will force lrzip to ignore the configuration file.

HISTORY - Notes on rzip by Andrew Tridgell

The ideas behind rzip were first implemented in 1998 while I was working on rsync. That version was too slow to be practical, and was replaced by this version in 2003. LRZIP was created by the desire to have better compression and/or speed by Con Kolivas on blending the lzma and lzo compression algorithms with the rzip first stage, and extending the compression windows to scale with increasing ram sizes.
