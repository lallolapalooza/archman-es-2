LEI-OVERVIEW(7) manual de usuario de public-inbox LEI-OVERVIEW(7)

NOMBRE

lei - una visión general de lei

DESCRIPCIÓN

lei(1) es una interfaz de correo local para public-inbox y correo personal. Este documento proporciona algunos ejemplos básicos.

ALMACÉN DE LEI

lei tiene almacenamiento local escribible basado en el formato public-inbox-v2-format(5). Los comandos inicializarán automáticamente el almacén en segundo plano si es necesario, pero puedes llamar a lei-init(1) directamente si deseas usar una ubicación de almacén diferente a la predeterminada "$XDG_DATA_HOME/lei/store".

El comando lei-import(1) proporciona la interfaz principal para importar mensajes al almacenamiento local. Además, otros comandos, como lei-q(1) y lei-blob(1), usan el almacén local para memorizar mensajes de fuentes remotas.

EJEMPLOS

$ lei import mboxrd:t.mbox.gz
Importa los mensajes de un mboxrd comprimido con gzip al almacenamiento local.
$ lei blob 59ec517f9
Muestra el mensaje con el OID de blob de git 59ec517f9. Si no se encuentra un mensaje con ese OID, verifica si el repositorio git actual tiene el blob, intentando reconstruirlo a partir de un mensaje si es necesario.
$ lei blob 59ec517f9 | lei tag -F eml +kw:flagged +L:next
Establece la palabra clave "flagged" y la etiqueta "next" en el mensaje con el OID de blob 59ec517f9.

EXTERNALES

Además del almacén anterior, lei puede realizar consultas de solo lectura a "externales": bandejas de entrada e índices externos. Un external se puede registrar pasando una URL o una ruta local a lei-add-external(1). Para rutas locales existentes, el external debe ser indexado con public-inbox-index(1) (en el caso de una bandeja de entrada regular) o public-inbox-extindex(1) (en el caso de un índice externo).

SINCRONIZACIÓN

lei actualmente tiene capacidades primitivas de sincronización de correo; ver lei-mail-sync-overview(7) para más detalles.

EJEMPLOS

$ lei add-external https://public-inbox.org/meta/
Agrega un external remoto para la bandeja de entrada de public-inbox.
$ lei add-external --mirror https://public-inbox.org/meta/ ruta
Clona https://public-inbox.org/meta/ a "ruta", lo indexa con public-inbox-index(1) y lo agrega como un external local.

BÚSQUEDA

El comando lei-q(1) busca en el almacén local y en los external. Los prefijos de búsqueda coinciden con los disponibles a través de public-inbox-httpd(1).

EJEMPLOS

$ lei q s:lei s:skeleton
Busca mensajes cuyo asunto incluya "lei" y "skeleton".
$ lei q -t s:lei s:skeleton
Haz lo mismo, pero también informa mensajes no coincidentes que están en el mismo hilo que un mensaje coincidente.
$ lei q -t -o /tmp/mdir --mua=mutt s:lei s:skeleton
Escribe los resultados en un Maildir en "mdir". Se invocará a Mutt para abrir el mfolder ("mutt -f %f") mientras se obtienen y escriben los resultados.
$ lei q kw:flagged L:next
Busca todos los mensajes marcados como "flagged" que también tengan una etiqueta "next".
$ lei p2q HEAD | lei q -tt -o /tmp/mdir
Busca mensajes que tengan OIDs de blob de git de imagen posterior que coincidan con los del commit HEAD del repositorio actual, escribiéndolos al directorio Maildir "mdir" y marcando los mensajes que fueron una coincidencia exacta.
$ git show -s HEAD | lei lcat
Muestra un mensaje local para el enlace public-inbox contenido en un mensaje de commit.
$ lei q -f text m:MESSAGE-ID | lei rediff -U5
Alimenta un mensaje que contiene un diff a lei-rediff(1) para regenerar su diff con cinco líneas de contexto. A menos que se especifique "--git-dir", esto requiere que el directorio de trabajo actual esté dentro del repositorio de código asociado.

NOTAS DE RENDIMIENTO

Inline::C es requerido en BSDs y puede acelerar las cosas en Linux.

lei se ejecuta como un demonio en segundo plano para reducir los costos de inicio y puede proporcionar monitoreo de Maildir en tiempo real con kqueue(2)/inotify(7). Se recomienda IO::KQueue (p5-IO-KQueue en FreeBSD) y Linux::Inotify2 (liblinux-inotify2-perl y perl-Linux-Inotify2 en distribuciones basadas en .deb y .rpm, respectivamente).

Socket::MsgHdr es opcional (libsocket-msghdr-perl en Debian), y mejora aún más el rendimiento de inicio. Su efecto se nota más al usar la compleción de shell.

COMPLETADO DE BASH

El completado preliminar de Bash para lei se proporciona en "contrib/completion/". Son bienvenidas las contribuciones que agreguen soporte para otros shells, así como las mejoras al completado de Bash existente.

ACTUALIZACIÓN

Dado que lei se ejecuta como un demonio, se requiere lei-daemon-kill(1) para detener el demonio y que pueda cargar código nuevo. Se reiniciará con la próxima invocación de cualquier comando de lei.

ADVERTENCIAS

El rendimiento del cliente IMAP y NNTP es pobre en conexiones de alta latencia. Esperemos que se solucione en 2022.
