NOMBRE

lei-store-format - descripción del formato lei/store

DESCRIPCIÓN

"lei/store" es un almacén híbrido basado en public-inbox-extindex-format(5) ("extindex") combinado con public-inbox-v2-format(5) ("v2") para el almacenamiento de blobs. Mientras que v2 es ideal para archivar una única lista de correo público; nunca fue diseñado para correos personales ni para almacenar múltiples blobs del "mismo" mensaje.

Al igual que con extindex, puede indexar encabezados "List-Id" dispares que pertenecen al "mismo" mensaje con diferentes OIDs de blob de git. A diferencia de v2 y extindex, los encabezados "Message-ID" NO son requeridos; permitiendo que se almacenen y se indexen borradores de mensajes no enviados.

ESTRUCTURA DE DIRECTORIOS

El almacenamiento de blobs existe en forma de épocas al estilo v2. Estas épocas se encuentran bajo el directorio "local/" (en lugar de "git/") para evitar que se traten accidentalmente como una bandeja de entrada v2.

VISIÓN GENERAL DEL ÍNDICE Y DEFINICIONES

$EPOCH - Entero comenzando en 0 basado en el tiempo
$SCHEMA_VERSION - Versión del esquema de la DB (para Xapian)
$SHARD - Entero comenzando en 0 basado en el paralelismo
~/.local/share/lei/store
- local/$EPOCH.git                # repositorios git desnudos normales
- mail_sync.sqlite3               # estado de sincronización IMAP, Maildir, NNTP

Además, lo siguiente comparte los mismos roles que en extindex:

- ei.lock                         # archivo de bloqueo para proteger el estado global
- ALL.git                         # vacío, alternativas para local/*.git
- ei$SCHEMA_VERSION/$SHARD        # DB Xapian por shard
- ei$SCHEMA_VERSION/over.sqlite3  # DB de resumen para WWW, IMAP
- ei$SCHEMA_VERSION/misc          # DB Xapian miscelánea

DESDUPLICACIÓN XREF3

La desduplicación del índice sigue a extindex, véase "DESDUPLICACIÓN XREF3" en public-inbox-extindex-format(5) para más información.

DESDUPLICACIÓN DE BLOBS

El contenido de los repositorios "local/*.git" se desduplica por IDs de objeto blob de git (actualmente SHA-1). Esto permite almacenar múltiples copias de mensajes cruzados y personales con diferentes encabezados "Received:", "X-Spam-Status:" y similares para permitir la resolución de problemas.

METADATOS VOLÁTILES

Las palabras clave y la información de etiquetas (como se describe en RFC 8621 para JMAP) se almacenan en los shards de Xapian existentes ("ei$SCHEMA_VERSION/$SHARD"). Es posible buscar mensajes que coincidan con etiquetas y palabras clave usando "L:" y "kw:", respectivamente. Al igual que con todos los datos almacenados en los índices de Xapian, los metadatos volátiles se asocian con el documento de Xapian, por lo tanto, se comparten entre diferentes blobs del "mismo" mensaje.

mail_sync.sqlite3

Esta base de datos SQLite se mantiene para la asignación bidireccional de blobs de git a UIDs de IMAP, nombres de archivos Maildir y números de artículos NNTP.

También se utiliza para recuperar mensajes de Maildirs indexados por lei-index(1).

IPC

lei-daemon(8) se comunica con el proceso "lei/store" usando sockets "SOCK_SEQPACKET" de unix(7).

ADVERTENCIAS

La reindexación y la sincronización aún no están soportadas.
