NOMBRE

lev_comp - Compilador de niveles especiales de NetHack

SINOPSIS

lev_comp [ -w ] [ archivos ]

Si no se proporcionan argumentos, lee la entrada estándar.

DESCRIPCIÓN

Lev_comp es un compilador de niveles especiales para NetHack versión 3.2 y superior. Toma archivos de descripción como argumentos y produce archivos de nivel que pueden ser cargados por NetHack en tiempo de ejecución.

El propósito de esta herramienta es proporcionar a los administradores e implementadores de NetHack una forma conveniente de agregar niveles especiales al juego, o modificar los existentes, sin tener que recompilar el mundo entero.

La opción -w hace que lev_comp realice comprobaciones adicionales en el nivel y muestre advertencias adicionales, sin embargo, estas advertencias a veces son superfluas, por lo que normalmente no se muestran.

NOTA:
Las líneas que comienzan con '#' se consideran comentarios.

El contenido de una descripción de "MAP" de un laberinto es un rectángulo que muestra el mapa exacto del nivel que debe usarse para la parte dada de un laberinto. Cada carácter en el mapa corresponde a una ubicación en la pantalla. Se denotan diferentes tipos de ubicaciones usando diferentes caracteres ASCII. Se reconocen los siguientes caracteres. Para dar una idea de cómo se usan, consulte el EJEMPLO, a continuación. El tamaño máximo de un mapa es normalmente de 76 columnas por 21 filas.

'-'	muro horizontal
'|'	muro vertical
'+'	una puerta (el estado se especifica en una declaración DOOR)
'A'	aire libre
'B'	ubicación de sala límite (para delimitar regiones irregulares sin muros)
'C'	aire nublado
'I'	hielo
'S'	una puerta secreta
'H'	un corredor secreto
'{'	una fuente
'\'	un trono
'K'	un lavabo (si SINKS está definido, de lo contrario, una ubicación de sala)
'}'	una parte de un foso u otra agua profunda
'P'	un estanque
'L'	lava
'W'	agua (sí, diferente de un estanque)
'T'	un árbol
'F'	barrotes de hierro
'#'	un corredor
'.'	una ubicación de sala normal (sin iluminar a menos que se ilumine en una declaración REGION)
' '	piedra

NAME

lev_comp - NetHack level compiler

SYNOPSIS

lev_comp [-o] [-v] [input file]

DESCRIPTION

The NetHack level compiler, lev_comp, reads a text file describing a level, and produces a binary file that may be incorporated into the game data files.

The input file uses a simple grammar which is described below. This grammar allows for the creation of levels with varying degrees of randomness. For example, the position of monsters and objects may be chosen at random, or restricted to certain areas.

The compiler checks the input file for syntax errors, and reports any that it finds. It also performs some basic sanity checks, such as ensuring that objects are placed within the level boundaries.

The binary output file is typically named after the input file, with a suitable extension (e.g., ".NXL"). This file can then be used by NetHack.

The following command-line options are available:

-o
This option is currently unused.
-v
Verbose mode. This will cause the compiler to print additional information about the level being generated, which may be useful for debugging.

GRAMMAR

The input file consists of a series of directives, each starting with a keyword. The keywords are:

MAP
Defines the layout of the level using a grid of characters. Each character represents a tile in the level. Special characters are used for walls, floors, doors, etc.
MONSTER
Places a monster on the map. It takes the monster's character representation, its name, and its position (either specific coordinates or random).
OBJECT
Places an object on the map. Similar to MONSTER, it takes the object's character, name, and position.
CONTAINER
Places a container (like a chest or sack) on the map. Objects can be placed inside containers.
TRAP
Places a trap on the map. It can be specified with a percentage chance of appearing.
NON_DIGGABLE
Specifies areas of the map that cannot be dug through.
TELEPORT_REGION
Defines regions where level teleports can occur.

Coordinates are specified as (row, column), with (0,0) being the top-left corner.

Random placement can be indicated by the keyword random or by omitting coordinates.

Percentage chances can be specified in brackets, e.g., [75%].

EXAMPLE 

MAP
    #######
    #.....#
    #.#@#.#
    #.#...#
    #.#.#.#
    #.....#
    #######
MONSTER: 'd', "hell hound", (1,1)
OBJECT: '(', "chest", (3,3)
CONTAINER: '[', "sack", (5,5)
OBJECT: '*', "diamond", contained
OBJECT[50%]: '*', "ruby", contained
MONSTER: 'D', random, random
TRAP[75%]: random, (4,5)
MONSTER: ';', "electric eel", (2,7)
NON_DIGGABLE: (0,0,8,8)
TELEPORT_REGION: levregion(0,0,79,20), (0,0,8,8)

This example will produce a file named "fortress" that can be integrated into one of the numerous mazes of the game.

Note especially the final, TELEPORT_REGION specification. This says that level teleports or other non-stairway arrivals on this level can land anywhere on the level except the area of the map. This shows the use of the ``levregion'' prefix allowed in certain region specifications. Normally, regions apply only to the most recent MAP specification, but when prefixed with ``levregion'', one can refer to any area of the level, regardless of the placement of the current MAP in the level.
