LESSPIPE.SH(1) Comandos de usuario LESSPIPE.SH(1)

NOMBRE

lesspipe.sh - un filtro para less

SINOPSIS

lesspipe.sh [ARCHIVO[s]]...

DESCRIPCIÓN

El objetivo de lesspipe.sh es mejorar la salida de less. La elección de las reglas a aplicar para modificar la salida se basa en el contenido del archivo. La extensión del archivo solo se respeta como último recurso. Normalmente lesspipe.sh se llama como un filtro de entrada para less.

Con la ayuda de este filtro, less mostrará el contenido sin comprimir de archivos comprimidos (gzip, bzip2, compress, zstd, lz4, lzip, xz, lzma o brotli). Para archivos que contienen y directorios, se mostrará una tabla de contenidos (formatos tar, ar, zip, 7-zip, rar, jar, cpio, rpm, deb ms-cabinet, iso, appimage y snap). Muchos otros archivos se reformatearán para su visualización. Incluye formatos de suites de pdf, dvi, markdown, Office (MS y Openoffice), NetCDF, matlab, device tree blob, html, xml y medios (imagen, audio y vídeo). Esto requiere que se instalen programas auxiliares.

El filtro también se puede aplicar recursivamente para extraer y mostrar archivos en archivos sobre la marcha. Esto funciona hasta una profundidad de 6, donde la aplicación de un algoritmo de descompresión cuenta como un nivel separado.

Si la utilidad `file` informa de texto con una codificación diferente a la utilizada en la terminal, el texto se transformará usando iconv a la codificación predeterminada. Esto asume que el comando `file` acierta con la codificación del archivo, lo cual puede ser incorrecto en algunas situaciones. Un dos puntos (`:`) añadido al nombre del archivo suprime la conversión.

Al usar los programas git, vim o mutt, pueden ser habilitados para leer archivos no textuales utilizando lesspipe.sh. Esto se describe en la Wiki en https://github.com/wofr06/lesspipe/wiki.

ACTIVACIÓN DEL FILTRO

El filtro es llamado desde less siempre que la variable de entorno LESSOPEN esté configurada correctamente. Para shells tipo ksh (bash, zsh) el comando

LESSOPEN="|lesspipe.sh %s"; export LESSOPEN
activa el filtro para less. Use la ruta completa si lesspipe.sh no está en la ruta de búsqueda. El comando para configurar LESSOPEN también puede ser mostrado llamando lesspipe.sh sin argumentos. Esto incluso puede ser usado para configurar LESSOPEN directamente:
eval `lesspipe.sh` (bash) o
lesspipe.sh|source /dev/stdin (zsh)
Los comandos anteriores solo funcionan de la manera descrita si el nombre del archivo es lesspipe.sh. Si está instalado bajo un nombre diferente, entonces llamarlo sin argumento funcionará como filtro con LESSQUIET establecido y esperando entrada de STDIN.

Habiendo establecido la variable de entorno como se describió anteriormente, less mostrará información textual para una amplia gama de formatos de archivo.

El filtro normalmente no se llama si la entrada se envía a less mediante una tubería (pipe) como en

cat archivo | less
Como se describe en la página del manual de less, sin embargo, el filtrado en una tubería puede ser forzado comenzando LESSOPEN con los caracteres |-.

LESSOPEN comenzando con los dos caracteres || para manejar archivos vacíos y errores de comandos solo se implementa parcialmente, generalmente en fallos de comandos dentro de lesspipe.sh los mensajes de error se muestran.

Para suprimir mensajes informales en la primera línea de la salida del filtro, la variable de entorno LESSQUIET puede ser establecida a un valor no vacío.

Para desactivar temporalmente el filtro, se puede añadir un dos puntos (`:`) al nombre del archivo. Si el nombre del archivo contiene un dos puntos, entonces se debe usar un signo igual (`=`) en su lugar.

ARCHIVOS HTML, XML y POD de Perl

Los archivos en formato html, xml y perl pod siempre se renderizan. A veces, sin embargo, se debería ver el contenido original del archivo. Como se mencionó antes, eso se puede lograr añadiendo un dos puntos (`:`) al nombre del archivo. Si el tipo de archivo correcto (html, xml, pod) le sigue, la salida puede ser coloreada (ver también la sección a continuación).

Ejemplo: less index.html:html

Si el binario xmq está instalado, entonces xml se renderiza de manera diferente, para que la estructura xml se reconozca mejor. Una visualización similar para el contenido html usando xmq se logra añadiendo un dos puntos (`:`) al nombre del archivo. Para obtener el contenido original del archivo html, se requieren dos puntos (`:`) en este caso.

COLOREADO DE SALIDA

El filtro es capaz de hacer resaltado de sintaxis para una amplia variedad de tipos de archivo. Si está instalado, nvimpager se usa para colorear la salida. Si no, se prueban bat/batcat, pygmentize, source-highlight, vimcolor y code2color por turnos. Para bat/batcat, el tema se establece en ansi y el estilo se establece en plain, lo que se acerca más a la salida sin filtrar de less. Estas configuraciones se pueden cambiar en ~/.config/bat/config o mediante las variables de entorno BAT_STYLE y BAT_THEME.

Entre los colorizadores, se puede forzar uno preferido para el coloreado estableciendo la variable de entorno LESSCOLORIZER al nombre del colorizador. Para pygmentize y bat/batcat se permiten configuraciones de opciones restringidas de la siguiente manera:

LESSCOLORIZER='pygmentize -O style=foo' (-P también permitido)
LESSCOLORIZER='bat --style=foo --theme=bar' (por defecto es theme ansi, style plain)
El resaltado de sintaxis se activa si la variable de entorno LESS existe y contiene la opción -R o si less se llama con esta opción. Esto garantiza que las secuencias de escape se conviertan en colores y no corrompan la visualización. No se recomienda usar la opción -r, ya que el diseño de la pantalla puede ser incorrecto si hay líneas largas en la salida.

El resaltado de sintaxis se puede desactivar añadiendo un dos puntos (`:`) después del nombre del archivo, si la salida fue coloreada. Si se eligió el idioma incorrecto para el resaltado de sintaxis, entonces se puede forzar otro añadiendo un dos puntos (`:`) y una extensión al nombre del archivo.

En una tubería, ese método no se puede usar. Como solución, se puede añadir un último argumento que lesspipe.sh inspecciona. Un solo dos puntos (`:`) (desactivar filtro) o :extensión (forzar idioma) son posibles, como por ejemplo con

comando que genera código c | less - :c
Cuando se cumplen las condiciones para el resaltado de sintaxis, los listados de directorios y los listados de contenido de archivos tar también se colorearán.

Dado que less se usa como navegador predeterminado en otros programas (por ejemplo, man, git y perldoc), lesspipe.sh puede ser activado y alterar la salida de esos programas.

VER ARCHIVOS CRECIENTES

Tan pronto como lesspipe.sh llama a un programa para convertir la entrada, se pierde la capacidad de ver archivos crecientes (usando el comando F dentro de less). Esto generalmente se desea para archivos de registro como syslog. Para desactivar temporalmente lesspipe.sh, se necesita añadir un dos puntos (`:`) como último argumento para less, como por ejemplo en

less /var/log/syslog :
o less puede ser llamado con el argumento +F, que es equivalente a F dentro del paginador:
less +F /var/log/syslog
Añadir un dos puntos (`:`) al nombre del archivo no funciona, ya que entonces el filtro tiene que ser activado al menos para eliminar ese dos puntos y usar cat para el archivo original. Por otro lado, los archivos de registro no crecientes pueden colorearse usando ccze. Su reconocimiento como archivo de registro es difícil si no termina en .log, pero se puede forzar añadiendo :.log al nombre del archivo, como por ejemplo en
less /var/log/syslog:.log

USO AVANZADO

Esta versión de lesspipe.sh le permite ver archivos individuales contenidos en un archivo, que a su vez puede estar contenido en otro archivo.

La notación para ver archivos en archivos múltiples es

less archivo

USO AVANZADO

Este método para extraer y mostrar archivos también se puede usar con archivos anidados. Para acceder a un archivo contenido dentro de otro archivo, se usa la siguiente sintaxis:

less super_archive:archive_file:contained_file

O incluso

less super_archive:archive_file:contained_file

Para mostrar el último archivo en la cadena en formato crudo, se debe añadir dos puntos (:) al nombre del archivo. Si este contiene dos puntos, entonces se debe usar el carácter separador alternativo, el signo igual (=).

Nuevamente, este método de extraer y mostrar archivos no funciona si less se llama en una tubería de salida y LESSOPEN comienza con los caracteres |-. Como ya se mencionó para el resaltado de sintaxis, la solución es usar un segundo argumento que comience con dos puntos. Entonces, el comando anterior se escribiría como

cat super_archive | less - :archive:contained_file

MECANISMO DE COMPLETADO PARA CONTENIDOS DE ARCHIVOS

Con los archivos lesscomplete (para zsh y bash), _less (para zsh) y less_completion (para bash) proporcionados, se puede lograr el completado de tabulación para archivos dentro de archivos. Ingresar dos puntos (:) o un signo igual (=) después del nombre de un archivo de archivo y presionar la tecla de tabulación activa el mecanismo de completado. Esto también funciona en archivos anidados. Los archivos lesscomplete y less_completion deben estar en uno de los directorios listados en $PATH y la función _less para zsh en un directorio listado por $fpath. El script less_completion debe ser cargado (sourced) dentro de un script de inicialización de bash, por ejemplo, en ~/.bashrc. Nuevos directorios como ~/scripts y ~/.fpath se pueden añadir usando los comandos

PATH=~/scripts:$PATH y fpath=(~/.fpath $fpath)

FILTRADO DEFINIDO POR EL USUARIO

El filtrado de lesspipe.sh puede ser reemplazado o mejorado por un programa definido por el usuario. Dicho programa debe llamarse .lessfilter (y colocarse en el directorio principal del usuario), o lessfilter (y ser accesible desde un directorio mencionado en $PATH). Debe ser ejecutable y debe terminar con un código de salida 0, si el filtrado se realizó dentro de ese script. De lo contrario, un código de salida distinto de cero significa que el filtrado se deja a lesspipe.sh.

Este mecanismo puede ser usado para añadir filtrado para nuevos formatos o, por ejemplo, para inhibir el filtrado para ciertos tipos de archivos.
