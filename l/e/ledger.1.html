LEDGER(1) Manual de comandos generales LEDGER(1)

NOMBRE

ledger — Herramienta de contabilidad de doble entrada, para informes desde línea de comandos.

SINOPSIS

ledger [opciones] [comando] [argumentos]

DESCRIPCIÓN

ledger es una herramienta de contabilidad desde línea de comandos basada en la potencia y la completitud de la contabilidad de doble entrada. Es solo una herramienta de informes, lo que significa que nunca modifica sus archivos de datos, pero ofrece una gran selección de informes y diferentes formas de personalizarlos según sus necesidades.

COMANDOS

ledger acepta varios comandos de nivel superior, cada uno de los cuales genera un tipo diferente de informe básico. La mayoría de ellos aceptan un argumento consulta-informe, para determinar qué se debe informar. Para comprender la sintaxis de una consulta-informe, consulte la sección CONSULTAS. En su forma más básica, simplemente especificar una o más cadenas produce un informe para todas las cuentas que contienen esas cadenas.

Si no se proporciona ningún comando, ledger entra en un REPL (bucle interactivo de comandos), permitiendo ejecutar varios comandos sobre el mismo conjunto de datos sin volver a parsear.

La siguiente es una lista completa de los comandos de informes aceptados:

cuentas [consulta-informe]
Lista todas las cuentas para las anotaciones que coinciden con la consulta-informe.
saldo [consulta-informe]
Imprime un informe de saldos que muestra los totales de las anotaciones que coinciden con la consulta-informe, y los totales agregados de los padres de esas cuentas. Las opciones que se usan con más frecuencia con este comando son:
--base (-B)
Informe en términos de base de costo, no de monto o valor. Esta es la única forma de informe que se garantiza que siempre cuadrará a cero, cuando no se especifica ninguna consulta-informe. Solo muestra totales para las cuentas de nivel más alto.
--vacio (-E)
Mostrar cuentas cuyo total es cero.
--plano
En lugar de mostrar un árbol jerárquico, aplana el informe para mostrar subtotales solo para las cuentas que coinciden con la consulta-informe.
--sin-total
Suprime el total general que se muestra al final del informe.

Los sinónimos bal y b también se aceptan.

presupuesto [consulta-informe]
Un informe de saldos especial que incluye tres columnas adicionales: el monto presupuestado durante el período del informe, la diferencia entre el gasto y el presupuesto, y el porcentaje del presupuesto gastado (supera el 100% si excede el presupuesto). Tenga en cuenta que la presupuestación requiere una o más "transacciones periódicas" definidas en sus archivos de datos. Consulte el manual para obtener más información.
conciliado [consulta-informe]
Un informe de saldos especial que agrega dos columnas adicionales: el saldo conciliado para cada cuenta y la fecha de la anotación conciliada más reciente en esa cuenta. Para que esta contabilidad sea significativa, la marca de conciliación debe estar configurada en al menos una anotación. Consulte el manual para obtener más información.
mercancias [consulta-informe]
Lista todas las mercancías para las anotaciones que coinciden con la consulta-informe.
convertir
Lee datos de un archivo CSV (valores separados por comas) y genera transacciones de ledger.
csv [consulta-informe]
Informe de anotaciones que coinciden con la consulta-informe en formato CSV (valores separados por comas). Útil para exportar datos a una hoja de cálculo para análisis o gráficos adicionales.
entrada [plantilla-entrada]
Genera y muestra una nueva transacción de ledger con formato correcto, comparando la plantilla-entrada con las transacciones en sus archivos de datos. Para obtener más información sobre las plantillas de borrador y cómo usar este comando para crear rápidamente nuevas transacciones, consulte la sección ENTRADAS.

El sinónimo xact también se acepta.

emacs [consulta]
Genera datos de anotaciones y transacciones en un formato que puede ser consumido fácilmente por el editor Emacs, en una serie de formas Lisp. Esto es utilizado por el modo ledger-mode de Emacs para procesar datos de informes desde ledger.
patrimonio [consulta-informe]
Imprime una transacción con una serie de anotaciones que equilibran los saldos actuales para las cuentas que coinciden con la consulta-informe en una cuenta especial llamada Patrimonio:Saldos Iniciales. El propósito de este informe es cerrar los libros de un año anterior, utilizando estas anotaciones de patrimonio para trasladar esos saldos.
beneficiarios [consulta-informe]
Lista todos los beneficiarios de las anotaciones que coinciden con la consulta-informe.
mapa-precios
Produce un archivo que se puede utilizar para generar un gráfico con graphviz que muestre la relación de las mercancías en el archivo ledger.
precios [consulta-informe]
Informa los precios de todas las mercancías en las anotaciones que coinciden con la consulta-informe. Los precios se informan con la granularidad de un solo día.
db-precios [consulta-informe]
Informa los precios de todas las mercancías en las anotaciones que coinciden con la consulta-informe. Los precios se informan hasta el segundo, utilizando el mismo formato que el archivo ~/.pricedb.
imprimir [consulta-informe]
Imprime las transacciones completas de cualquier anotación coincidente utilizando el mismo formato que tendrían en un archivo de datos. Esto se puede usar para extraer subconjuntos de un archivo de ledger para transferirlos a otros archivos.
empujar [opciones]
En el REPL, empuja un conjunto de opciones de línea de comandos, para que se apliquen a todos los informes subsiguientes.
sacar
En el REPL, saca cualquier configuración de opción que haya sido empujada.
registro [consulta-informe]
Lista todas las anotaciones que coinciden con la consulta-informe. Este es uno de los comandos más comunes y se puede usar para proporcionar una variedad de informes útiles. Las opciones que se usan con más frecuencia con este comando son:
--promedio (-A)
Muestra el promedio acumulado, en lugar de un total acumulado.

COMMANDS

balance [--effective] [--flat] [--locale STR] [--market STR] [--monthly] [--monthly-starting INT] [--nearest-period STR] [--no-totals] [--period STR] [--quarterly] [--relative STR] [--round STR] [--sort STR] [--spread] [--start-of-week STR] [--total STR] [--weekly] [--year-sep STR] [--yearly] [account-expression ...]
Generate a balance sheet, which lists the current balance of every account in the ledger. The total is displayed at the bottom of each account's entries. The balance report is the same as the register report but displays totals for each account and truncates the display of transactions. In addition to the options listed for the register report, the balance report accepts the following options:
--effective (-e)
Show effective dates for all postings. This is the date on which the posting should be taken into account in the report.
--flat (-f)
Produce a flattened output of accounts. With this option, all hierarchies are removed, and all accounts are listed in a flat fashion.
--locale STR
Use the given STR as the locale for output formatting. For example, setting --locale en_US.UTF-8 will use United States conventions for formatting numbers and dates.
--market STR (-V)
Show current market values for all accounts. The value of STR is the commodity for which the market value is to be displayed. Currently, this is only implemented for “US dollars”.

The balance report is a snapshot of your finances. It is a summary report showing the current balance of all accounts. For a report showing historical values, use the register report.

--monthly (-M)
Print a monthly balance sheet.
--monthly-starting INT
Set the start of each month to the given day of the month.
--nearest-period STR
Use the beginning of the period nearest to the specified date. The supported periods are: week, month, quarter, and year.
--no-totals
Do not print totals for accounts. This will disable the printing of totals for the current report, and also disable the printing of totals for the whole report. See also --total.
--period STR (-p)
Print a balance sheet for the given time period.
--quarterly
Print a quarterly balance sheet.
--relative STR
Show balances relative to a given date. The value of STR is a date. The report will show the balance of each account as it was on the specified date.
--round STR
Print balances rounded to the nearest STR. Currently, the only supported value for STR is cent.
--sort value-expression (-S)
Sort postings by evaluating the given value-expression. Note that a comma-separated list of expressions is allowed, in which case each sorting term is used in order to determine the final ordering. For example, to search by date and then amount, one would use:
ledger bal --sort 'date, amount'
The sort order may be controlled with the '-' sign. For example, to sort in reverse chronological order:
ledger bal --sort '-date'
--spread
Print all postings in a spread fashion. This option is only useful when used with the balance report.
--start-of-week day
Set the start of each report grouped by week to the given day.
--total EXPR
Instead of printing totals for the current report, print the result of EXPR. The expression EXPR is evaluated in the context of the current report, and the result is printed as the total.
--weekly (-W)
Print a weekly balance sheet.
--year-sep STR
Use STR as the separator between the year and the rest of the account name in the output of the balance report.
--yearly (-Y)
Print a yearly balance sheet.
betwixt [--base STR] [account-expression ...]
This is a report for generating the dates of transactions that span between the beginning of a period and the end of that period. For example, this report can be used to find all postings that span across a fiscal year-end. The report only shows postings that span across the beginning and ending date of the specified period.
budget [--effective] [--flat] [--locale STR] [--monthly] [--monthly-starting INT] [--nearest-period STR] [--no-totals] [--period STR] [--quarterly] [--relative STR] [--round STR] [--sort STR] [--spread] [--start-of-week STR] [--total STR] [--weekly] [--year-sep STR] [--yearly] [account-expression ...]
This report generates a budget by comparing the actual amounts posted to accounts with the budgeted amounts for those accounts. The output of the budget report is identical to that of the balance report, except that the budgeted amounts are also displayed. This report accepts all of the options available to the balance report.
check [--effective] [account-expression ...]
The check report prints a list of all postings that are posted to the given accounts. The purpose of this report is to aid in performing a bank reconciliation.
--effective (-e)
Show effective dates for all postings. This is the date on which the posting should be taken into account in the report.

The check report is similar to the register report, but it is intended for use during bank reconciliation. It is often used to display the entire history of postings to a given account, so that the user may compare the postings in the ledger with the postings on a bank statement.

convert [--assume STR] [--csv] [--input STR] [--output STR] [--paste] [--pedantic] [--price STR] [--template STR] [account-expression ...]
Convert transactions from one format to another. This command is primarily used to import transactions from CSV files. It can also be used to generate transactions from arbitrary data.
--assume STR
When converting from a CSV file, use STR as the default account for postings which do not have an account specified in the CSV file. This option is only useful when converting from a CSV file.
--csv
Assume the input is in CSV format. This is the default behavior of the convert command.
--input STR
Read input from the file named STR. By default, input is read from standard input.
--output STR
Write output to the file named STR. By default, output is written to standard output.
--paste
When converting from a CSV file, use the contents of the clipboard as input. This option is only useful when converting from a CSV file.
--pedantic
When converting from a CSV file, the convert command will complain if there are any postings which do not have an account specified in the CSV file. This option is only useful when converting from a CSV file.
--price STR
When converting from a CSV file, use STR as the default price for postings which do not have a price specified in the CSV file. This option is only useful when converting from a CSV file.
--template STR
Use the template file STR for converting the input. This option is only useful when converting from a CSV file.
register [--effective] [--exchange STR] [--gain] [--head INT] [--historical] [--invert] [--market] [--period STR] [--related] [--sort STR] [--tail INT] [--uncleared] [account-expression ...]
Generate a register report, which lists all postings that affect the specified accounts. The register report is a comprehensive report showing all postings that affect the specified accounts.
--effective (-e)
Show effective dates for all postings. This is the date on which the posting should be taken into account in the report.
--exchange "COMMODITY [, COMMODITY, ...]" (-X)
Render all values in the given commodity, if a price conversion rate can be determined. If multiple commodities are given, values in a listed commodity will remain as-is, and others will be displayed in the first listed commodity they can be converted to. Rates are always displayed relative to the date of the posting they are calculated for. This means a register report is a historical value report. For current values, it may be preferable to use the balance report.
--gain (-G)
Show any gains (or losses) in commodity values over time.
--head number
Only show the top number postings.
--historical (-H)
Value commodities at the time of their acquisition.
--invert
Invert the value of amounts shown.
--market (-V)
Show current market values for all amounts. This is determined in a somewhat magical fashion. It is probably more straightforward to use the --exchange option.
--period time-period (-p)
Show postings only for the given time-period.
--related (-r)
Show postings that are related to those that would have been shown. It has the effect of displaying the "other side" of the postings.
--sort value-expression (-S)
Sort postings by evaluating the given value-expression. Note that a comma-separated list of expressions is allowed, in which case each sorting term is used in order to determine the final ordering. For example, to search by date and then amount, one would use:
ledger reg --sort 'date, amount'
The sort order may be controlled with the '-' sign. For example, to sort in reverse chronological order:
ledger reg --sort '-date'
--tail number
Only show the last number postings.
--uncleared (-U)
Only show uncleared (i.e., recent) postings.

There are also several grouping options that can be useful:

--by-payee (-P)
Group postings by common payee names.
--daily (-D)
Group postings by day.
--weekly (-W)
Group postings by week (starting on Sundays).
--start-of-week day
Set the start of each report grouped by week to the given day.
--monthly (-M)
Group postings by month.
--quarterly
Group postings by fiscal quarter.
--yearly (-Y)
Group postings by year.
--days-of-week
Group postings by the day of the week on which they took place.
--subtotal (-s)
Group all postings together. This is very similar to the totals shown by the balance report.

The synonyms reg and r are also accepted.

select [sql-query]
List all postings matching the sql-query. This command allows to generate SQL-like queries, e.g.:
ledger select date,amount from posts where account=~/Income/
source
Parse a journal file and checks it for errors. ledger will return success if no errors are found.
stats [report-query]
Provide summary information about all the postings matching report-query. It provides information such as:
  • Time range of all matching postings
  • Unique payees
  • Unique accounts
  • Postings total
  • Uncleared postings
  • Days since last posting
  • Posts in the last 7 days
  • Posts in the last 30 days
  • Posts this month
xml [report-query]
Output data relating to the current report in XML format. It includes all accounts and commodities involved in the report, plus the postings and the transactions they are contained in. See the manual for more information.

OPTIONS

Set the minimum length an account can be abbreviated to if it doesn't fit inside the account-width. If INT is zero, then the account name will be truncated on the right. --hashes ALGO
Record the hash of each transaction in a Hash metadata value, according to the hashing algorithm given by the ALGO argument. Supported algorithms are sha512 or sha512_half where both use SHA512, but the latter only stores the first half of the hash value.

If a Hash metadata value is explicitly provided and does not match what would have been generated, an error is reported. Hashes depend on previous entries, such that setting a single hash value is sufficient to guarantee the shape of the entire history leading up to that entry.

CONSULTAS

La sintaxis para las consultas de informes puede volverse algo compleja. Es una serie de términos de consulta con un operador OR implícito entre ellos. Se aceptan los siguientes términos:

regex
Una cadena desnuda se toma como una expresión regular (PCRE) que coincide con el nombre completo de la cuenta. Por lo tanto, para informar el saldo actual de todos los activos y pasivos, usaría:
ledger bal asset liab
payee regex (@regex)
Consulta sobre el pagador, en lugar de la cuenta.
tag regex (%regex)
Consulta sobre etiquetas.
note regex (=regex)
Consulta sobre cualquier cosa encontrada en la nota de un elemento.
code regex (#regex)
Consulta sobre el código opcional de la transacción (que puede ser cualquier cadena que el usuario desee).
term and term
Los términos de consulta se unen mediante un operador OR implícito. Puede cambiar esto a AND usando la palabra clave and. Por ejemplo, para mostrar gastos de comida ocurridos en Shakee's Pizza, podría decir:
ledger reg food and @Shakee
term or term
Cuando desee ser más explícito, use el operador OR.
show
 
not term
Invierta el significado lógico del término siguiente. Esto se puede usar con paréntesis de gran efecto:
ledger reg food and @Shakee and not dining
( term )
Si desea mezclar operadores OR y AND, a menudo es útil rodear las unidades lógicas con paréntesis. NOTA: Debido a la forma en que algunos shells interpretan los paréntesis, siempre debe escaparlos:
ledger bal \( assets or liab \) and not food

EXPRESSIONS

Many of the commands in ledger accept a value expression, which is a string that ledger parses and evaluates. When an expression is used in place of an argument that is not a report-query, it is referred to as a value expression. Otherwise, it is referred to as a report query.

Here is a list of all functions available within a value expression:

The account function takes a regular expression that names the account to be returned. For example, account("Expenses:Food") will return the account named Expenses:Food.

Causes the posting to be rejected if the expression evaluates to false. Returns true.
avg(value-expression)
Computes the average of the given value-expression over all postings that match the report query.
balance(account-regex)
Returns the balance of the account named by the given regular expression.
current(value-expression)
Returns the value of the expression for the current posting.
date(date-expression)

current
The date of the current posting.
effective
The effective date of the current posting.
posted
The date the current posting was posted.
first
The first date in the report.
last
The last date in the report.
display(value-expression)
Returns the value of the expression as it will be displayed.
display_total(value-expression)
Return the displayed total of the expression.
dsubtotal(value-expression)
Return the displayed subtotal of the expression.
eval(value-expression)
This function returns the value of the given expression. It is used for debugging and for creating new functions.
exists(value-expression)

ENTORNO

Todas las opciones de ledger se pueden configurar mediante una variable de entorno si la opción tiene un nombre largo. Por ejemplo, establecer la variable de entorno LEDGER_DATE_FORMAT="%d.%m.%Y" tendrá el mismo efecto que especificar --date-format '%d.%m.%Y' en la línea de comandos. Sin embargo, las opciones en la línea de comandos siempre tienen prioridad sobre la configuración de las variables de entorno.
