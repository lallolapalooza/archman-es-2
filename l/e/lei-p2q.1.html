LEI-P2Q(1) Manual de usuario de public-inbox LEI-P2Q(1)

NOMBRE

lei-p2q - usar un parche para generar una consulta lei-q

SINOPSIS

lei p2q [OPCIONES] (ARCHIVO|COMMIT)

lei p2q [OPCIONES] (--stdin|-)

DESCRIPCIÓN

Dado un parche, crea una consulta que puede ser alimentada a la entrada estándar de lei-q(1). Esto es útil para mapear el parche a mensajes asociados de una bandeja de entrada.

El parche puede ser proporcionado en la entrada estándar o como un archivo. Alternativamente, cuando se proporciona un argumento que no apunta a un archivo existente, se toma como una referencia a un commit en el repositorio git actual, y git-format-patch(1) se utiliza para generar el parche.

OPCIONES

-w PREFIJO[,PREFIJO]
--want=PREFIJO[,PREFIJO]
Prefijos de búsqueda a utilizar. "dfpost" (ID de blob de git post-imagen) y "dfn" (nombres de archivo del diff) son los más útiles. Otros valores disponibles son "dfa", "dfb", "dfctx", "dfhh" y "dfpre".

Añadir un entero a "dfpost" o "dfpre" indica una longitud mínima del ID, y la consulta generada será para ese valor hasta la longitud de abreviatura predeterminada. Por ejemplo, si la configuración "core.abbrev" del repositorio está establecida a "auto" y git calcula la longitud de abreviatura predeterminada como 7, "dfpost6" expandirá un ID de blob post-imagen de e7b4b32 (siete caracteres) en "dfpost:e7b4b32 OR dfpost:e7b4b3".

Esta opción puede darse varias veces.

Predeterminado: "dfpost7"

--stdin
Leer mensaje de la entrada estándar. Esto es implícito si no se dan argumentos y la entrada estándar es una tubería o un archivo regular.
--debug
Mostrar la salida que presenta la información recopilada para cada prefijo. Esta información puede ser útil para ver cómo se procesa un parche, pero el formato no debe considerarse estable.
--uri
Escapar la salida para interactuar con instancias de public-inbox HTTP(S).
-q
--quiet
Suprimir mensajes de retroalimentación.

EJEMPLOS

# para buscar todos los hilos que tocan un hilo dado:
lei p2q $COMMIT_OID | lei q -t -o /tmp/resultados
# para ver resultados en una instancia remota de public-inbox HTTP(S)
$BROWSER https://ejemplo.com/pub-inbox/?q=$(lei p2q --uri $COMMIT_OID)
# para ver parches no aplicados para un $FILE dado del último año:
echo \( rt:last.year.. AND dfn:$FILE \) AND NOT \( \
      $(git log -p --pretty=mboxrd --since=last.year $FILE |
              lei p2q -F mboxrd )
      \) | lei q -o /tmp/noaplicados
