NOMBRE

lei-q - busca mensajes que coincidan con términos

SINOPSIS

lei q [OPCIONES] TERMINO [TERMINO...]

lei q [OPCIONES] (--stdin|-)

DESCRIPCIÓN

Busca mensajes en el store de lei y en los externos.

OPCIONES

--stdin
Lee los términos de búsqueda desde stdin.
--no-save
No guarda la búsqueda para lei-up(1).
--output=MFOLDER
-o MFOLDER
--mfolder=MFOLDER
Advertencia: esto sobrescribe el destino de salida a menos que se especifique "--augment".

Destino para los resultados (por ejemplo, "/tmp/results-Maildir", "imaps://usuario@mail.example.com/INBOX.test", o "mboxcl2:/tmp/results-mboxcl2"). El prefijo puede ser un protocolo soportado: "imap://" o "imaps://". Las URLs que requieren autenticación usan git-credential(1) para completar el nombre de usuario y la contraseña.

Un prefijo puede especificar el formato de la salida: "maildir", "mboxrd", "mboxcl2", "mboxcl", "mboxo". Para una descripción de los formatos de correo, consulta lei-mail-formats(5).

"v2:/ruta/a/inbox" puede ser usado para crear un nuevo inbox con el formato public-inbox-v2-format(5). El nuevo inbox no se configurará en el archivo public-inbox-config(5).

"maildir" es el predeterminado para un directorio existente o una ruta no existente.

Predeterminado: "-" (salida estándar)

--format=FORMAT
-f FORMAT
Formato de los resultados a la salida estándar. Esta opción existe como una forma conveniente de especificar el formato para el destino predeterminado de salida estándar. "reply", "text", "json", "jsonl", o "concatjson" son soportados, al igual que las diversas variantes de mbox descritas en "--output".

Cuando no se especifica un formato, se elige en función del destino o prefijo de "--output". "json" se usa para el destino predeterminado (salida estándar).

Se prefiere usar un prefijo de "format:" con el destino "--output" cuando no se escribe a la salida estándar.

--no-color
Desactiva el color (para "-f reply" y "-f text").
--pretty
Formatea la salida "json" o "concatjson". Si la salida estándar se abre a una tty y se usa como destino de "--output", "--pretty" se activa por predeterminado.
--mua=COMMAND
Un comando para ejecutar en el Maildir o mbox de "--output" (por ejemplo, "mutt -f %f"). Para un subconjunto de MUAs conocidos por aceptar un buzón a través de "-f", COMMAND puede abreviarse al nombre del programa: "mutt", "mailx", "mail", o "neomutt".
--alert=COMMAND[,COMMAND...]
Ejecuta "COMMAND" después de escribir en la salida. ":WINCH" indica enviar "SIGWINCH" al proceso de "--mua". ":bell" indica imprimir un código de campana. Cualquier otro valor se interpreta como un comando para ejecutar tal cual.

Esta opción puede darse múltiples veces.

Predeterminado: ":WINCH,:bell" cuando "--mua" está especificado y "--output" no apunta a la salida estándar, nada en caso contrario.

--augment
-a
Aumenta el destino de salida en lugar de sobrescribirlo.
--no-import-before
No importa mensajes antes de escribir a un destino de salida existente. Asegúrate de que no necesitas datos existentes en tu salida antes de usar esto, ya que borra permanentemente los datos a menos que se use "--augment".
--threads
-t
Devuelve todos los mensajes del mismo hilo que la coincidencia real(es).

Usar esto dos veces ("-tt") establece la marca "flagged" (también conocida como "importante") en los mensajes que fueron coincidencias reales. Esto es útil para distinguir los mensajes que fueron coincidencias directas de los mensajes que solo eran parte del mismo hilo.

TODO: Advertencia: ¡esta bandera puede volverse persistente y guardarse en lei/store a menos que un MUA la desmarque! (Comportamiento no decidido)

Advertencia: "-tt" solo funciona con mensajes indexados localmente en este momento, y no con endpoints remotos (HTTP(S)).

--thread-id=MSGID
-T MSGID
Busca solo mensajes en el mismo hilo que el Message-ID dado.

Para externos HTTP(S), esto solo funciona en instancias que ejecutan public-inbox 2.0+ (SIN PUBLICAR).

--jobs=QUERY_WORKERS[,WRITE_WORKERS]
--jobs=,WRITE_WORKERS
-j QUERY_WORKERS[,WRITE_WORKERS]
-j ,WRITE_WORKERS
Establece el número de procesos de trabajo de consulta y escritura para paralelismo.

"QUERY_WORKERS" por predeterminado es el número de CPUs disponibles, pero 4 por host remoto (HTTP/HTTPS).

"WRITE_WORKERS" por predeterminado es el 75% del número de CPUs disponibles para destinos Maildir y mbox*, pero 4 por host IMAP/IMAPS.

Omitir "QUERY_WORKERS" pero dejar la coma (",") permite establecer solo "WRITE_WORKERS"

--dedupe=STRATEGY
-d STRATEGY
Estrategia para la deduplicación de mensajes: "content", "oid", "mid", o "none".

Predeterminado: "content"

--[no-]remote
Si se deben incluir resultados que requieren acceso a la red. Cuando se configuran externos locales, se debe pasar explícitamente "--remote" para habilitar la notificación de resultados de externos remotos.
--no-local
Limita las operaciones a aquellas que requieren

NAME

lei-q — Search a public-inbox mailbox

SYNOPSIS

lei q [OPTION...] [SEARCH TERM...]

DESCRIPTION

Search for messages matching the given criteria. Results are ordered by received time, descending by default.

The "lei q" command uses Xapian for indexing and searching. The search syntax is the same as that used by public-inbox instances for their web interface.

OPTIONS

--no-data
Don't search for data in the mailbox.
--threads
Also search for messages that are part of a thread, but not directly matching the search terms.
--no-threads
Do not search for thread-related messages.
--show=WHAT
Only show WHAT from search results. See lei-show(1) for a full list of WHATs.
-h
Same as "--show=body".
-e
Same as "--show=subject".
-a
Same as "--show=all".
--no-body
Do not show the body of the messages.
--no-subject
Do not show the subject of the messages.
--no-data
Do not show any data from the messages.
--no-external
Don't include results from externals.
--include=LOCATION
-I LOCATION
Include specified external in search. This option may be given multiple times.
--exclude=LOCATION
Exclude specified external from search. This option may be given multiple times.
--only=LOCATION
-O LOCATION
Use only the specified external for search. This option may be given multiple times, in which case the search uses only the specified set.
--globoff
-g
Do not match locations using "*?" wildcards and "[]" ranges. This option applies to "--include", "--exclude", and "--only".
--no-import-remote
Disable the default behavior of memoizing remote messages into the local store.
--lock=METHOD
mbox(5) locking method(s) to use: "dotlock", "fcntl", "flock" or "none".

Default: fcntl,dotlock

--limit=NUMBER
-NUMBER
-n NUMBER
Fuzzy-limit the number of matches per local external and lei/store. Messages added by the --threads switch do not count towards this limit, and there is no limit on remote externals.

Default: 10000

--offset=NUMBER
Shift start of search results.

Default: 0

--reverse
-r
Reverse the results. Note that this applies before "--limit".
--sort=KEY
-s KEY
Order the results by KEY. Valid keys are "received", "relevance", and "docid".

Default: "received"

--verbose
-v
Provide more feedback on stderr.
--quiet
-q
Suppress feedback messages.
--torsocks=auto|no|yes
--no-torsocks
Whether to wrap git(1) and curl(1) commands with torsocks(1).

Default: "auto"

--proxy=PROTOCOL://HOST[:PORT]

SEARCH TERMS

"lei q" supports the same search prefixes used by HTTP(S) public-inbox instances:

s:        match within Subject  e.g. s:"a quick brown fox"
d:        match date-time range, git "approxidate" formats supported
          Open-ended ranges such as `d:last.week..' and
          `d:..2.days.ago' are supported
b:        match within message body, including text attachments
nq:       match non-quoted text within message body
q:        match quoted text within message body
n:        match filename of attachment(s)
t:        match within the To header
c:        match within the Cc header
f:        match within the From header
a:        match within the To, Cc, and From headers
tc:       match within the To and Cc headers
l:        match contents of the List-Id header
bs:       match within the Subject and body
dfn:      match filename from diff
dfa:      match diff removed (-) lines
dfb:      match diff added (+) lines
dfhh:     match diff hunk header context (usually a function name)
dfctx:    match diff context lines
dfpre:    match pre-image git blob ID
dfpost:   match post-image git blob ID
dfblob:   match either pre or post-image git blob ID
patchid:  match `git patch-id --stable' output
rt:       match received time, like `d:' if sender's clock was correct

Additional search prefixes which only affect the local lei/store:

L:       match the given label
kw:      match the given keywords

See lei-tag(1) for more info on labels and keywords.

Most prefixes are probabilistic, meaning they support stemming and wildcards ("*"). Ranges (such as "d:") and boolean prefixes do not support stemming or wildcards. The upstream Xapian query parser documentation fully explains the query syntax: https://xapian.org/docs/queryparser.html

TIPS

"-f reply" is intended to aid in turning a cover letter into a reply (since using "git format-patch --in-reply-to=..." is tedious). Results (including "From " lines) should be edited and trimmed in your favorite $EDITOR before sending.
