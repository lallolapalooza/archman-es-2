load(n)

Paquete: tcl

Licencias: TCL

load(n) Comandos integrados de Tcl load(n)

NOMBRE

load - Cargar código máquina e inicializar nuevos comandos

SINOPSIS

load ?-global? ?-lazy? ?--? fileName
load ?-global? ?-lazy? ?--? fileName prefix
load ?-global? ?-lazy? ?--? fileName prefix interp

DESCRIPCIÓN

Este comando carga código binario de un archivo en el espacio de direcciones de la aplicación y llama a un procedimiento de inicialización en la biblioteca para incorporarlo a un intérprete. fileName es el nombre del archivo que contiene el código; su formato exacto varía según el sistema, pero en la mayoría de los sistemas es una biblioteca compartida, como un archivo .so en Solaris o una DLL en Windows. prefix se utiliza para calcular el nombre de un procedimiento de inicialización. interp es el nombre de ruta del intérprete en el que cargar la biblioteca (ver la entrada del manual interp para más detalles); si interp se omite, se utiliza por defecto el intérprete en el que se invocó el comando load.

Una vez que el archivo se ha cargado en el espacio de direcciones de la aplicación, se invocará uno de los dos procedimientos de inicialización en el nuevo código. Típicamente, el procedimiento de inicialización agregará nuevos comandos a un intérprete Tcl. El nombre del procedimiento de inicialización se determina mediante prefix y si el intérprete de destino es seguro o no. Para intérpretes normales, el nombre del procedimiento de inicialización tendrá el formato pfx_Init, donde pfx es el mismo que prefix excepto que la primera letra se convierte a mayúscula y todas las demás letras a minúscula. Por ejemplo, si prefix es foo o FOo, el nombre del procedimiento de inicialización será Foo_Init.

Si el intérprete de destino es un intérprete seguro, entonces el nombre del procedimiento de inicialización será pfx_SafeInit en lugar de pfx_Init. La función pfx_SafeInit debe escribirse cuidadosamente, de modo que inicialice el intérprete seguro solo con funcionalidad parcial proporcionada por la biblioteca que sea segura para su uso por código no confiable. Para más información sobre Safe-Tcl, ver la entrada del manual safe.

El procedimiento de inicialización debe coincidir con el siguiente prototipo:

typedef int Tcl_PackageInitProc(
        Tcl_Interp *interp);

El argumento interp identifica el intérprete en el que se debe cargar la biblioteca. El procedimiento de inicialización debe devolver TCL_OK o TCL_ERROR para indicar si completó con éxito o no; en caso de error, debe establecer el resultado del intérprete para que apunte a un mensaje de error. El resultado del comando load será el resultado devuelto por el procedimiento de inicialización.

La carga real de un archivo solo se realizará una vez por cada fileName en una aplicación. Si un fileName dado se carga en múltiples intérpretes, el primer load cargará el código y llamará al procedimiento de inicialización; los loads subsiguientes llamarán al procedimiento de inicialización sin cargar el código de nuevo. Para versiones de Tcl anteriores a la 8.5, no es posible descargar o recargar una biblioteca. A partir de la versión 8.5, sin embargo, el comando unload permite la descarga de bibliotecas cargadas con load, para bibliotecas que son conscientes del mecanismo de descarga de Tcl.

El comando load también admite bibliotecas que están enlazadas estáticamente con la aplicación, si esas bibliotecas han sido registradas llamando al procedimiento Tcl_StaticPackage. Si fileName es una cadena vacía, entonces se debe especificar prefix.

Si se omite prefix o se especifica como una cadena vacía, Tcl intenta adivinar el prefijo. Esto puede hacerse de manera diferente en diferentes plataformas. La suposición por defecto, que se utiliza en la mayoría de las plataformas UNIX, es tomar el último elemento de fileName, quitar los tres primeros caracteres si son lib, y usar cualquier carácter alfabético y de subrayado subsiguiente, convertido a mayúscula inicial como prefijo. Por ejemplo, el comando load libxyz4.2.so utiliza el prefijo Xyz y el comando load bin/last.so {} utiliza el prefijo Last.

Si fileName es una cadena vacía, entonces se debe especificar prefix. El comando load primero busca una biblioteca cargada estáticamente (una que ha sido registrada llamando al procedimiento Tcl_StaticPackage) con ese nombre; si se encuentra una, se utiliza. De lo contrario, el comando load busca una biblioteca cargada dinámicamente con ese nombre, y la utiliza si se encuentra. Si varios archivos diferentes se han cargado con diferentes versiones de la biblioteca, Tcl elige el archivo que se cargó primero.

Si se especifica -global antes del nombre de archivo, todos los símbolos encontrados en la biblioteca compartida se exportan para uso global por otras bibliotecas. La opción -lazy retrasa la carga real de los símbolos hasta su primer uso. Las opciones pueden abreviarse. La opción -- indica el final de las opciones, y debe usarse si desea usar un nombre de archivo que comience con - y proporciona un prefijo al comando load.

En plataformas que no soportan las opciones -global o -lazy, las opciones todavía existen pero no tienen ningún efecto. Tenga en cuenta que el uso de la opción -global o -lazy puede provocar fallos en su aplicación más adelante (en caso de conflictos de símbolos o símbolos faltantes), que no pueden detectarse durante la carga. Por lo tanto, úselo solo cuando sepa lo que está haciendo, no obtendrá un mensaje de error agradable cuando algo esté mal con la biblioteca cargada.

PROBLEMAS DE PORTABILIDAD

Windows     
Cuando una carga falla con el error "biblioteca no encontrada", también es posible que no se haya encontrado una biblioteca dependiente. Para ver las bibliotecas dependientes, escriba "dumpbin -imports <dllname>" en una consola DOS para ver qué debe importar la biblioteca. Al cargar una DLL en el directorio actual, Windows ignorará "./" como especificador de ruta y utilizará una heurística de búsqueda para encontrar la DLL en su lugar. Para evitar esto, cargue la DLL con:
load [file join [pwd] mylib.DLL]

ERRORES

Si el mismo archivo se carga con diferentes fileNames, se cargará en el espacio de direcciones del proceso varias veces. El comportamiento de esto varía según el sistema (algunos sistemas pueden detectar las cargas redundantes, otros no).

EJEMPLO

La siguiente es una extensión mínima:

#include <tcl.h>
#include <stdio.h>
static int fooCmd(void *clientData,
        Tcl_Interp *interp, int objc, Tcl_Obj *const objv[]) {
    printf("llamado con %d argumentos\n", objc);
    return TCL_OK;
}
int Foo_Init(Tcl_Interp *interp) {
    if (Tcl_InitStubs(interp, "8.1", 0) == NULL) {
	return TCL_ERROR;
    }
    printf("creando comando foo");
    Tcl_CreateObjCommand(interp, "foo", fooCmd, NULL, NULL);
    return TCL_OK;
}

Cuando se compila en una biblioteca compartida/dinámica con un nombre adecuado (por ejemplo, foo.dll en Windows, libfoo.so en Solaris y Linux), se puede cargar en Tcl con lo siguiente:

# Cargar la extensión
switch $tcl_platform(platform) {
    windows {
        load [file join [pwd] foo.dll]
    }
    unix {
        load [file join [pwd] libfoo[info sharedlibextension]]
    }
}
# Ahora ejecutar el comando definido por la extensión
foo
