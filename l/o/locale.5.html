locale(5) Manual de formatos de archivo locale(5)

NOMBRE

locale - describe un archivo de definición de localización

DESCRIPCIÓN

El archivo de definición de locale contiene toda la información que el comando localedef(1) necesita para convertirlo en la base de datos binaria de localizaciones.

Los archivos de definición consisten en secciones que describen cada categoría de localización en detalle. Ver locale(7) para detalles adicionales sobre estas categorías.

Sintaxis

El archivo de definición de localización comienza con una cabecera que puede consistir en las siguientes palabras clave:

caracter_escape
va seguido de un carácter que se usará como carácter de escape para el resto del archivo para marcar caracteres que deben interpretarse de forma especial. Por defecto es la barra invertida (\).
caracter_comentario
va seguido de un carácter que se usará como carácter de comentario para el resto del archivo. Por defecto es el signo de almohadilla (#).

La definición de localización tiene una parte para cada categoría de localización. Cada parte puede ser copiada de otra localización existente o puede definirse desde cero. Si la categoría debe ser copiada, la única palabra clave válida en la definición es copiar seguida del nombre de la localización entre comillas dobles que debe ser copiada. Las excepciones a esta regla son LC_COLLATE y LC_CTYPE donde una declaración de copiar puede ser seguida por reglas específicas de la localización y sustituciones seleccionadas.

Al definir una localización o una categoría desde cero, se debe usar un archivo de definición de localización proporcionado por el sistema como referencia para seguir las convenciones comunes de glibc.

Secciones de categoría de localización

Las siguientes secciones de categoría están definidas por POSIX:

LC_ADDRESS

La definición comienza con la cadena LC_ADDRESS en la primera columna.

Las siguientes palabras clave están permitidas:

postal_fmt
seguido de una cadena que contiene descriptores de campo que definen el formato utilizado para las direcciones postales en la localización. Los siguientes descriptores de campo se reconocen:
%n
Nombre de la persona, posiblemente construido con la palabra clave name_fmt de LC_NAME (desde glibc 2.24).
%a
A la atención de persona u organización.
%f
Nombre de la empresa.
%d
Nombre del departamento.
%b
Nombre del edificio.
%s
Nombre de la calle o bloque (por ejemplo, japonés).
%h
Número o designación de la casa.
%N
Inserta un fin de línea si el valor del descriptor anterior no era una cadena vacía; de lo contrario, ignora.
%t
Inserta un espacio si el valor del descriptor anterior no era una cadena vacía; de lo contrario, ignora.
%r
Número de habitación, designación de puerta.
%e
Número de piso.
%C
Designación del país, de la palabra clave country_post.
%l
Municipio local dentro de la ciudad (desde glibc 2.24).
%z
Número de código postal.
%T
Pueblo, ciudad.
%S
Estado, provincia o prefectura.
%c
País, tal como se toma del registro de datos.

Cada descriptor de campo puede tener una 'R' después del '%' para especificar que la información se toma de una cadena de versión romanizada de la entidad.

country_name
seguido del nombre del país en el idioma del documento actual (por ejemplo, "Deutschland" para la localización de_DE).
country_post
seguido de la abreviatura del país (por ejemplo, códigos CEPT-MAILCODE).
country_ab2
seguido de la abreviatura de dos letras del país (ISO 3166).
country_ab3
seguido de la abreviatura de tres letras del país (ISO 3166).
country_num
seguido del código numérico del país (ISO 3166).
country_car
seguido del código de país de matrícula internacional.
country_isbn
seguido del código ISBN (para libros).
lang_name
seguido del nombre del idioma en el idioma del documento actual.
lang_ab
seguido de la abreviatura de dos letras del idioma (ISO 639).
lang_term
seguido de la abreviatura de tres letras del idioma (ISO 639-2/T).
lang_lib
seguido de la abreviatura de tres letras del idioma para uso en bibliotecas (ISO 639-2/B). Las aplicaciones generalmente deben preferir lang_term sobre lang_lib.

La definición de LC_ADDRESS termina con la cadena END LC_ADDRESS.

space
seguido de una lista de caracteres definidos como caracteres de espacio en blanco. No se permiten caracteres especificados también como upper, lower, alpha, d

LC_CTYPE

La definición comienza con la cadena LC_CTYPE en la primera columna.

Las siguientes palabras clave están permitidas:

upper
seguida de una lista de caracteres en mayúsculas. Los caracteres también especificados como lower, alpha, digit, punct, graph, print o xdigit no están permitidos.
lower
seguida de una lista de caracteres en minúsculas. Los caracteres también especificados como upper, alpha, digit, punct, graph, print o xdigit no están permitidos.
alpha
seguida de una lista de caracteres alfabéticos. Los caracteres también especificados como upper, lower, digit, punct, graph, print o xdigit no están permitidos.
digit
seguida de una lista de caracteres dígitos decimales. Los caracteres tambín especificados como upper, lower, alpha, punct, graph, print o xdigit no están permitidos. Los caracteres <espacio>, <salto de página>, <nueva línea>, <retorno de carro>, <tabulador> y <tabulador vertical> se incluyen automáticamente.
cntrl
seguida de una lista de caracteres de control. Los caracteres también especificados como upper, lower, alpha, digit, punct, graph, print o xdigit no están permitidos.
punct
seguida de una lista de caracteres de puntuación. Los caracteres también especificados como upper, lower, alpha, digit, cntrl, xdigit o el carácter <espacio> no están permitidos.
graph
seguida de una lista de caracteres imprimibles, sin incluir el carácter <espacio>. Los caracteres definidos como upper, lower, alpha, digit, xdigit y punct se incluyen automáticamente. Los caracteres también especificados como cntrl no están permitidos.
print
seguida de una lista de caracteres imprimibles, incluyendo el carácter <espacio>. Los caracteres definidos como upper, lower, alpha, digit, xdigit, punct y el carácter <espacio> se incluyen automáticamente. Los caracteres también especificados como cntrl no están permitidos.
xdigit
seguida de una lista de caracteres clasificados como dígitos hexadecimales. Los dígitos decimales deben incluirse seguidos de uno o más conjuntos de seis caracteres en orden ascendente. Los siguientes caracteres se incluyen por defecto: 0 a 9, a a f, A a F.
blank
seguida de una lista de caracteres clasificados como blank. Los caracteres <espacio> y <tabulador> se incluyen automáticamente.
charclass
seguida de una lista de nombres de clases de caracteres específicos de la localización que luego se definirán en la localización.
toupper
seguida de una lista de mapeos de letras minúsculas a mayúsculas. Cada mapeo es un par de una letra minúscula y una mayúscula separadas por una , y encerradas entre paréntesis.
tolower
seguida de una lista de mapeos de letras mayúsculas a minúsculas. Si la palabra clave tolower no está presente, se utiliza la inversa de la lista toupper.
map totitle
seguida de una lista de pares de mapeo de caracteres y letras a usar en títulos (encabezados).
class
seguida de una definición de clase de caracteres específica de la localización, comenzando con el nombre de la clase seguido de los caracteres que pertenecen a la clase.
charconv
seguida de una lista de nombres de mapeo de caracteres específicos de la localización que luego se definirán en la localización.
outdigit
seguida de una lista de dígitos de salida alternativos para la localización.
map to_inpunct
seguida de una lista de pares de mapeo de dígitos y separadores alternativos para los dígitos de entrada para la localización.
map to_outpunct
seguida de una lista de pares de mapeo de separadores alternativos para la salida para la localización.
translit_start
marca el inicio de la sección de reglas de transliteración. La sección puede contener la palabra clave include al principio seguida de reglas específicas de la localización y sobrescrituras. Cualquier regla especificada en el archivo de localización sobrescribirá cualquier regla copiada o incluida de otros archivos. En caso de definiciones de reglas duplicadas en el archivo de localización, solo se utiliza la primera regla.
Una regla de transliteración consiste en un carácter a transliterar seguido de una lista de destinos de transliteración separados por punto y coma. Se utiliza el primer destino que se puede presentar en el conjunto de caracteres de destino; si ninguno de ellos se puede utilizar, se utilizará el carácter default_missing en su lugar.
include
en la sección de reglas de transliteración incluye un archivo de reglas de transliteración (y opcionalmente un archivo de mapa de repertorio).
default_missing
en la sección de reglas de transliteración define el carácter predeterminado a usar para la transliteración donde ninguno de los destinos se puede presentar en el conjunto de caracteres de destino.
translit_end
marca el final de las reglas de transliteración.

La definición de LC_CTYPE finaliza con la cadena END LC_CTYPE.

NAME

locale, setlocale, uselocale, newlocale, duplocale, freelocale, lctrans, localetrans, localeconv — locale—setting and operations

SYNOPSIS

#include <locale.h>

char *setlocale(int category, const char *locale);

locale_t uselocale(locale_t domain);

locale_t newlocale(int category_mask, const char *locale, locale_t domain);

locale_t duplocale(locale_t loc);

void freelocale(locale_t loc);

char *lctrans(const char *string, const char *locale);

char *localetrans(const char *string);

struct lconv *localeconv(void);

DESCRIPTION

The setlocale function selects the locale that determines the conventions for categories specified by category. The uselocale, newlocale, duplocale, and freelocale functions provide a more fine-grained control over locales.

The localeconv function returns a pointer to a structure containing locale-specific information on numeric and monetary formats.

The localetrans and lctrans functions are used for translating strings.

Categories

The category argument is a non-negative integer which determines which of the following categories is affected by the locale setting:

LC_ALL
All of the following categories.
LC_ADDRESS
Address formatting.
LC_COLLATE
Collation (string sort order).
LC_CTYPE
Character classification and conversion functions.
LC_IDENTIFICATION
Identification of the locale itself (name, etc.).
LC_MEASUREMENT
Measurement units (metric vs. US units).
LC_MESSAGES
Formats for diagnostic and informative messages.
LC_MONETARY
Monetary formatting.
LC_NAME
Name formatting.
LC_NUMERIC
Numeric formatting.
LC_PAPER
Paper size.
LC_TELEPHONE
Telephone number formatting.
LC_TIME
Time formatting.

The value LC_ALL refers to all of the above categories. Categories can be combined using the bitwise OR operator |. For example, LC_COLLATE | LC_CTYPE.

Locale Syntax

The locale argument to setlocale and newlocale is a string which specifies the locale to use. It can be:

  • A null pointer: Use the value of the corresponding environment variable.
  • An empty string: Use the user's default locale settings.
  • A string starting with a colon (`::`): Append the specified string to the current locale setting for the category.
  • A string starting with a plus sign (`+`): Use the first line of the specified file as the locale setting.
  • A string starting with a minus sign (`-`): Use the specified string as the locale name.
  • A string starting with a slash (`/`): Use the contents of the specified file as the locale setting.

If locale is a null pointer, setlocale returns the current setting for the category without changing it.

A locale definition file is a text file with the following structure:

  • Blank lines and lines starting with the number sign (`#`) are ignored.
  • A locale definition consists of one or more category definitions.
  • Each category definition starts with the category name in uppercase (e.g., LC_TIME) in the first column, followed by whitespace.
  • The category definition consists of a set of keywords and their values.
  • Each keyword and its value are on a separate line.
  • The definition of a category ends with the string END followed by the category name (e.g., END LC_TIME).

The following sections describe the keywords for each category.

LC_IDENTIFICATION

The definition starts with the string LC_IDENTIFICATION in the first column.

The following keywords are allowed:

title
followed by a string that identifies the locale.
source

STANDARDS

The setlocale function conforms to XPG4, SUSv2, and POSIX.1-2001. The localeconv function conforms to XPG4, SUSv2, and POSIX.1-2001. The uselocale, newlocale, duplocale, and freelocale functions conform to POSIX.1-2008.

NOTES

The behavior of setlocale regarding the locale argument depends on the implementation. On some systems, if locale is a string, it is interpreted as the name of the locale to load.

The uselocale function allows the user to create and manage multiple locale environments. The newlocale function creates a new locale environment, while duplocale duplicates an existing one, and freelocale frees it.

The lctrans and localetrans functions are used for string translation. localetrans uses the current locale settings, while lctrans allows explicitly specifying a locale.

The localeconv function returns a pointer to a static structure, which may be overwritten by subsequent calls to localeconv. The contents of this structure are locale-dependent.

The interpretation of the week and first_weekday keywords can be subtle. The second argument to week specifies the first day of the week. If it is 19971130, then Sunday is the first day of the week. If it is 19971201, then Monday is the first day of the week. The first_weekday keyword explicitly sets the first day of the week for calendar applications, overriding the setting from the week keyword if necessary. The value for first_weekday is an index into the day list, starting from 1.

The first_workday keyword specifies the first working day of the week. The value is an index into the day list, starting from 1.

The cal_direction keyword specifies the direction in which calendar dates are displayed. This affects how days are arranged on the screen.

The lctrans function is used for dynamic string translation based on a specified locale. The localetrans function uses the current locale. Both functions search for translations in the message catalog associated with the locale.

ERRORS

setlocale, newlocale, and duplocale return NULL on error and set errno to indicate the error. Possible values of errno include:

EINVAL
Invalid category or locale name.
ENOMEM
Insufficient memory to allocate locale data.
ENOENT
The locale directory or file could not be found.

uselocale returns the special locale value LC_GLOBAL_LOCALE on error and sets errno to indicate the error. Possible values of errno include:

EINVAL
Invalid locale domain.

freelocale returns on error and sets errno to indicate the error. Possible values of errno include:

EINVAL
Invalid locale.

EXAMPLES

To set the locale for all categories to the user's default:

#include <locale.h>
#include <stdio.h>

int main(void) {
    if (setlocale(LC_ALL, "") == NULL) {
        fprintf(stderr, "Could not set locale\n");
        return 1;
    }
    // ... rest of the program ...
    return 0;
}

To create a new locale object:

#include <locale.h>
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    locale_t loc;
    // Create a new locale object for the C category
    loc = newlocale(LC_CTYPE, "en_US.UTF-8", (locale_t)0);
    if (loc == (locale_t)-1) {
        perror("newlocale");
        return 1;
    }
    // Use the new locale
    if (uselocale(loc) == (locale_t)-1) {
        perror("uselocale");
        return 1;
    }
    // ... rest of the program ...
    // Free the locale object when done
    freelocale(loc);
    return 0;
}

•
