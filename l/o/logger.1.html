LOGGER(1) Comandos de usuario LOGGER(1)

NOMBRE

logger - introducir mensajes en el registro del sistema

SINOPSIS

logger [opciones] mensaje

DESCRIPCIÓN

logger crea entradas en el registro del sistema.

Cuando el argumento opcional mensaje está presente, se escribe en el registro. Si no está presente, y tampoco se da la opción -f, entonces se registra la entrada estándar.

OPCIONES

-d, --udp

Usar solo datagramas (UDP). Por defecto, se intenta la conexión al puerto syslog definido en /etc/services, que a menudo es 514.

Ver también --server y --socket para especificar dónde conectarse.

-e, --skip-empty

Ignorar líneas vacías al procesar archivos. Una línea vacía se define como una línea sin ningún carácter. Por lo tanto, una línea que consiste solo en espacios en blanco NO se considera vacía. Tenga en cuenta que cuando se especifica la opción --prio-prefix, la prioridad no forma parte de la línea. Por lo tanto, una línea vacía en este modo es una línea que no tiene ningún carácter después del prefijo de prioridad (por ejemplo, <13>).

-f, --file archivo

Registrar el contenido del archivo especificado. Esta opción no se puede combinar con un mensaje de línea de comandos.

-i

Registrar el PID del proceso logger con cada línea.

--id[=id]

Registrar el PID del proceso logger con cada línea. Cuando se especifica el argumento opcional id, este se utiliza en lugar del PID del comando logger. Se recomienda el uso de --id=$$ (PPID) en scripts que envían varios mensajes.

Tenga en cuenta que la infraestructura de registro del sistema (por ejemplo, systemd cuando escucha en /dev/log) puede seguir las credenciales del socket local para sobrescribir el PID especificado en el mensaje. logger(1) puede establecer esas credenciales de socket en el id dado, pero solo si tiene permisos de root y existe un proceso con el PID especificado, de lo contrario, las credenciales del socket no se modifican y el problema se ignora silenciosamente.

--journald[=archivo]

Escribe una entrada del registro de systemd. La entrada se lee del archivo dado, cuando se especifica, de lo contrario, desde la entrada estándar. Cada línea debe comenzar con un campo que sea aceptado por journald; consulte systemd.journal-fields(7) para obtener detalles. Generalmente es una buena idea usar un campo MESSAGE_ID, ya que facilita la búsqueda de entradas. Ejemplos: 
logger --journald <<end
MESSAGE_ID=67feb6ffbaf24c5cbec13c008dd72309
MESSAGE=Los perros ladran, pero la caravana sigue.
DOGS=ladran
CARAVAN=sigue
end
logger --journald=entrada.txt

Observe que --journald ignorará los valores de otras opciones, como la prioridad. Si se necesita prioridad, debe estar dentro de la entrada y usar el campo PRIORITY. La simple ejecución de journalctl(1) mostrará el campo MESSAGE. Use journalctl --output json-pretty para ver el resto de los campos.

Para incluir saltos de línea en MESSAGE, especifique MESSAGE varias veces. Esto se maneja como un caso especial; otros campos se almacenarán como una matriz en el registro si aparecen varias veces.

--msgid msgid

Establece el campo MSGID de RFC 5424 https://tools.ietf.org/html/rfc5424. Tenga en cuenta que el carácter de espacio no está permitido dentro de msgid. Esta opción solo se utiliza si también se especifica --rfc5424; de lo contrario, se ignora silenciosamente.

-n, --server servidor

Escribe en el servidor syslog remoto especificado en lugar de en el socket de registro del sistema. A menos que se especifique --udp o --tcp, logger primero intentará usar UDP, pero si esto falla, se intentará una conexión TCP.

--no-act

Hace que se realice todo, excepto escribir el mensaje de registro en el registro del sistema y eliminar la conexión con el registro. Esta opción se puede usar junto con --stderr para fines de prueba.

--octet-count

Utiliza el método de encapsulación de conteo de octetos de RFC 6587 https://tools.ietf.org/html/rfc6587 para enviar mensajes. Cuando esta opción no se utiliza, el valor predeterminado es sin encapsulación en UDP y con encapsulación no transparente RFC6587 (también conocida como relleno de octetos) en TCP.

-P, --port puerto

Utiliza el puerto especificado. Cuando esta opción no se especifica, el puerto por defecto es syslog para udp y syslog-conn para conexiones tcp.

-p, --priority prioridad

Introduce el mensaje en el registro con la prioridad especificada. La prioridad puede especificarse numéricamente o como un par facility.level. Por ejemplo, -p local3.info registra el mensaje como informativo en la facility local3. El valor predeterminado es user.notice.

--prio-prefix

Busca un prefijo syslog en cada línea leída de la entrada estándar. Este prefijo es un número decimal entre corchetes que codifica tanto la facility como el nivel. El número se construye multiplicando la facility por 8 y luego sumando el nivel. Por ejemplo, local0.info, que significa facility=16 y level=6, se convierte en <134>.

Si el prefijo no contiene facility, esta se establece por defecto en la especificada por la opción -p. Del mismo modo, si no se proporciona ningún prefijo, la línea se registra utilizando la prioridad dada con -p.

Esta opción no afecta a un mensaje de línea de comandos.

--rfc3164

Utiliza el protocolo syslog BSD RFC 3164 https://tools.ietf.org/html/rfc3164 para enviar mensajes a un servidor remoto.

--rfc5424[=sin]

Utiliza el protocolo syslog RFC 5424 https://tools.ietf.org/html/rfc5424 para enviar mensajes a un servidor remoto. El argumento opcional sin puede ser una lista separada por comas de los siguientes valores: notq, notime, nohost.

El valor notq suprime los datos estructurados de calidad temporal del mensaje enviado. La información de calidad temporal muestra si el reloj local estaba sincronizado más el número máximo de microsegundos que la marca de tiempo podría estar desfasada. La calidad temporal también se suprime automáticamente cuando se especifica --sd-id timeQuality.

El valor notime (que implica notq) suprime la marca de tiempo completa del remitente que está en formato ISO-8601, incluidos los microsegundos y la zona horaria.

El valor nohost suprime la información de gethostname(2) de la cabecera del mensaje.

El protocolo RFC 5424 ha sido el valor predeterminado para logger desde la versión 2.26.

-s, --stderr

Salida del mensaje a la salida de error estándar, así como al registro del sistema.

--sd-id nombre[@dígitos]

Especifica un ID de elemento de datos estructurados para una cabecera de mensaje RFC 5424. La opción debe usarse antes de --sd-param para introducir un nuevo elemento. El número de elementos de datos estructurados es ilimitado. El ID (nombre más posiblemente @dígitos) distingue entre mayúsculas y minúsculas e identifica de forma única el tipo y propósito del elemento. El mismo ID no debe existir más de una vez en un mensaje. La parte @dígitos es necesaria para IDs no estandarizados definidos por el usuario.

logger actualmente genera solo el elemento estandarizado timeQuality. RFC 5424 también describe los elementos origin (con parámetros ip, enterpriseId, software y swVersion) y meta (con parámetros sequenceId, sysUpTime y language). Estos IDs de elemento se pueden especificar sin el sufijo @dígitos.

--sd-param nombre=valor

Especifica un parámetro de datos estructurados. La opción debe usarse después de --sd-id y debe repetirse para cada parámetro dentro del mismo elemento de datos estructurados. El valor de los parámetros se puede codificar de forma segura como se describe en la sección 6.4 de RFC 5424.

Tenga en cuenta que los valores de parámetros que contienen espacios o comillas dobles deben codificarse. Por ejemplo, para establecer el parámetro ip en 192.168.0.1, se debe usar --sd-param ip=192.168.0.1. Para establecer el parámetro enterpriseId en 9876, se debe usar --sd-param enterpriseId=9876. Para establecer el parámetro swVersion en 1.2.3, se debe usar --sd-param swVersion="1.2.3". Para establecer el parámetro MESSAGE en Un mensaje con "comillas", se debe usar --sd-param MESSAGE=\"Un mensaje con \\\"comillas\\\"\". Consulte también la sección 6.4.1 de RFC 5424 para ver un ejemplo de uso de parámetros.

--socket archivo

Escribe en el socket de dominio Unix especificado en archivo. Por defecto, se utiliza el socket de registro del sistema /dev/log.

--tcp

Usar TCP. Por defecto, se intenta la conexión al puerto syslog definido en /etc/services, que a menudo es 514.

Ver también --server y --socket para especificar dónde conectarse.

-t, --tag tag

Este es el tag que se adjuntará a cada línea de registro. El valor predeterminado es el nombre del programa que ha generado el mensaje.

-u, --unix

Usar sockets de dominio Unix. Por defecto, se intenta la conexión al puerto syslog definido en /etc/services, que a menudo es 514.

Ver también --server y --socket para especificar dónde conectarse.

-V, --version

Muestra información sobre la versión y sale.

-h, --help

Muestra un mensaje de ayuda y sale.

EJEMPLOS

Registrar un mensaje simple:

logger This is a test message.

Registrar un mensaje con una prioridad y tag específicos:

logger -p local0.info -t MYAPP This is a test message.

Registrar la salida de un comando:

ls -l | logger -t MYLS

Registrar un mensaje en un servidor syslog remoto en el puerto 1234 usando TCP:

logger -n syslog.example.com -P 1234 --tcp This is a test message.

Registrar un mensaje usando el protocolo RFC 5424 sin información de host:

logger --rfc5424=nohost --sd-id origin@9876 --sd-param ip=192.168.0.1 --sd-param enterpriseId=9876 Hello world.

VER TAMBIÉN

syslog(3), syslog.conf(5), journalctl(1), systemd.journal-fields(7)

logger(1) — Arch manual pages

NAME

logger — make logging messages system logger

SYNOPSIS

logger [-i] [-f file] [-n host] [-P port] [-p priority] [-s] [-T] [-u socket] [-m max-len] [-S | --size size] [--sd-id SD-ID [--sd-param name=value]…] [--socket-errors mode] [-t tag] [-V | --version] [-h | --help] [message ...]

DESCRIPTION

The logger utility provides a simple way to create logging messages from the command line. It accepts zero or more message arguments, concatenates them with spaces in between, appends a newline, and passes the result to the system logger.

If no message arguments are specified, logger reads standard input until an end-of-file is encountered.

The logging is done using the syslog(3) subsystem.

OPTIONS

-i
Log the current process ID. This is the default behavior for older versions of logger, but it is deprecated for RFC 5424 messages.
-f, --file file
Read messages from the specified file instead of the standard input. When this option is used, the default tag is the basename of the file.
-n, --server host
Use this option to send the log messages to a remote syslog server at host. By default, logger uses the standard Unix domain socket.
-P, --port port
Use this option to specify the port on the remote syslog server to send the log messages to. By default, this is the value of the syslog service from /etc/services, which is typically port 514.
-p, --priority priority
Enter the priority for the message. The priority is a number or a textual name like daemon.info (interface level). The list of valid facility names is defined in syslog(3). The default is user.notice.
-s, --stderr
Log the message to standard error as well as to the system log. This is the default behavior when logger is run without RFC 5424 options.
--sd-id SD-ID
Add a structured data ID. SD-ID is a string which identifies the origin of the structured data (e.g. local0, com-example-myapp). This option must be followed by one or more --sd-param options.
--sd-param name=value
Add a structured data parameter. This option takes a name and value pair. The option must be used after --sd-id and may be specified more than once for the same element. Note that the quotation marks around value are required and must be escaped on the command line.
    logger --rfc5424 --sd-id zoo@123             \
                     --sd-param tiger="hungry"   \
                     --sd-param zebra="running"  \
                     --sd-id manager@123         \
                     --sd-param onMeeting="yes"  \
                     "this is message"

produces:

<13>1 2015-10-01T14:07:59.168662+02:00 ws kzak - - [timeQuality tzKnown="1" isSynced="1" syncAccuracy="218616"][zoo@123 tiger="hungry" zebra="running"][manager@123 onMeeting="yes"] this is message

-S, --size size

Sets the maximum permitted message size to size. The default is 1KiB characters, which is the limit traditionally used and specified in RFC 3164. With RFC 5424, this limit has become flexible. A good assumption is that RFC 5424 receivers can at least process 4KiB messages.

Most receivers accept messages larger than 1KiB over any type of syslog protocol. As such, the --size option affects logger in all cases (not only when --rfc5424 was used).

Note: the message-size limit limits the overall message size, including the syslog header. Header sizes vary depending on the selected options and the hostname length. As a rule of thumb, headers are usually not longer than 50 to 80 characters. When selecting a maximum message size, it is important to ensure that the receiver supports the max size as well, otherwise messages may become truncated. Again, as a rule of thumb two to four KiB message size should generally be OK, whereas anything larger should be verified to work.

--socket-errors mode

Print errors about Unix socket connections. The mode can be on, off, or auto. When the mode is auto (the default), then logger will detect if the init process is systemd(1), and if so, the assumption is made that /dev/log can be used early at boot. The lack of /dev/log on other init systems will not cause errors, just as when using the openlog(3) system call. The logger(1) before version 2.26 used openlog(3), and thus was unable to detect the loss of messages sent to Unix sockets.

When errors are not enabled, lost messages are not communicated and will result in a successful exit status of logger(1).

-T, --tcp

Use stream (TCP) only. By default the connection is tried to the syslog-conn port defined in /etc/services, which is often 601.

See also --server and --socket to specify where to connect.

-t, --tag tag

Mark every line to be logged with the specified tag. The default tag is the name of the user logged in on the terminal (or a user name based on effective user ID).

-u, --socket socket

Write to the specified socket instead of to the system log socket.

--

End the argument list. This allows the message to start with a hyphen (-).

-h, --help

Display help text and exit.

-V, --version

Display version and exit.

EXIT STATUS

The logger utility exits 0 on success, and >0 if an error occurs.

FACILITIES AND LEVELS

Valid facility names are:

auth
authpriv for security information of a sensitive nature
cron

daemon
ftp
kern cannot be generated from userspace process, automatically converted to user

lpr
mail
news
syslog
user
uucp
local0
to
local7
security deprecated synonym for auth

Valid level names are:

emerg
alert
crit
err
warning
notice
info
debug
panic deprecated synonym for emerg
error deprecated synonym for err
warn deprecated synonym for warning

For the priority order and intended purposes of these facilities and levels, see syslog(3).

CONFORMING TO

The logger command is expected to be IEEE Std 1003.2 ("POSIX.2") compatible.

EXAMPLES

logger System rebooted

logger -p local0.notice -t HOSTIDM -f /dev/idmc

logger -n loghost.example.com System rebooted
