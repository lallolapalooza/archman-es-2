LONGJMP(3P) Manual de Programador POSIX LONGJMP(3P)

PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para obtener detalles sobre el comportamiento en Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

longjmp — salto no local

SINOPSIS

#include <setjmp.h>
void longjmp(jmp_buf env, int val);

DESCRIPCION

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es involuntario. Este volumen de POSIX.1‐2017 remite al estándar ISO C.

La función longjmp() restaurará el entorno guardado por la invocación más reciente de setjmp() en el mismo proceso, con el argumento jmp_buf correspondiente. Si la invocación más reciente de setjmp() con el jmp_buf correspondiente ocurrió en otro hilo, o si no existe tal invocación, o si la función que contiene la invocación de setjmp() ha terminado su ejecución en el ínterin, o si la invocación de setjmp() estaba dentro del alcance de un identificador de tipo modificado por variables y la ejecución ha abandonado ese alcance en el ínterin, el comportamiento es indefinido. No está especificado si longjmp() restaura la máscara de señales, deja la máscara de señales sin cambios, o la restaura a su valor en el momento en que se llamó a setjmp().

Todos los objetos accesibles tienen valores, y todos los demás componentes de la máquina abstracta tienen estado (por ejemplo, indicadores de estado de punto flotante y archivos abiertos), tal como estaban en el momento en que se llamó a longjmp(), excepto que los valores de los objetos de duración de almacenamiento automático no están especificados si cumplen todas las siguientes condiciones:

*
Son locales a la función que contiene la invocación correspondiente de setjmp().
*
No tienen tipo calificado como volatile.
*
Se modifican entre la invocación de setjmp() y la llamada a longjmp().

Aunque longjmp() es una función segura para señales asíncronas, si se invoca desde un manejador de señales que interrumpió una función no segura para señales asíncronas o su equivalente (como el procesamiento equivalente a exit() realizado después de un retorno de la llamada inicial a main()), el comportamiento de cualquier llamada posterior a una función no segura para señales asíncronas o su equivalente es indefinido.

El efecto de una llamada a longjmp() donde la inicialización de la estructura jmp_buf no se realizó en el hilo que llama es indefinido.

VALOR DE RETORNO

Después de que se completa longjmp(), la ejecución del programa continúa como si la invocación correspondiente de setjmp() acabara de devolver el valor especificado por val. La función longjmp() no hará que setjmp() devuelva 0; si val es 0, setjmp() devolverá 1.

ERRORES

No se definen errores.

Las siguientes secciones son informativas.

EJEMPLOS

Ninguno.

USO DE APLICACIONES

Las aplicaciones cuyo comportamiento depende del valor de la máscara de señales no deben usar longjmp() y setjmp(), ya que su efecto en la máscara de señales no está especificado, sino que deben usar las funciones siglongjmp() y sigsetjmp() (que pueden guardar y restaurar la máscara de señales bajo control de la aplicación).

Se recomienda que las aplicaciones no llamen a longjmp() o siglongjmp() desde manejadores de señales. Para evitar un comportamiento indefinido al llamar a estas funciones desde un manejador de señales, la aplicación debe asegurarse de una de las siguientes dos cosas:

1.
Después de la llamada a longjmp() o siglongjmp(), el proceso solo llama a funciones seguras para señales asíncronas y no retorna de la llamada inicial a main().
2.
Cualquier señal cuyo manejador llame a longjmp() o siglongjmp() está bloqueada durante *cada* llamada a una función no segura para señales asíncronas, y no se realizan tales llamadas después de retornar de la llamada inicial a main().

longjmp(3p)

longjmp — invoke a non-local goto

SYNOPSIS 

#include <setjmp.h>
void longjmp(jmp_buf env, int val);

DESCRIPTION

The longjmp function restores (reverses the effect of) a direct call to setjmp.

All variables with automatic storage duration that are local to the functions between the calling point of setjmp and the call to longjmp have their values restored to the values they had at the time of the setjmp call.

Note: It is undefined behavior to call longjmp from a context that is not derived from the corresponding setjmp call, or to restore a jmp_buf that has been corrupted.

The val argument is used as the return value from the corresponding setjmp call. If val is zero, setjmp will return 1. Otherwise, setjmp will return val.

The jmp_buf argument is a buffer previously populated by a call to setjmp.

RETURN VALUE

The longjmp function does not return. Control is transferred to the setjmp call corresponding to the jmp_buf specified.

ERRORS

None.
