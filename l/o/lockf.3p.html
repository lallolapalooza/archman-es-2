LOCKF(3P) Manual del programador POSIX LOCKF(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

lockf — bloqueo de registros en archivos

SINOPSIS

#include <unistd.h>
int lockf(int fildes, int function, off_t size);

DESCRIPCIÓN

La función lockf() bloquea secciones de un archivo con bloqueos en modo consultivo. Las llamadas a lockf() desde hilos en otros procesos que intentan bloquear la sección de archivo bloqueada o bien devuelven un valor de error o se bloquean hasta que la sección se desbloquea. Todos los bloqueos de un proceso se eliminan cuando el proceso termina. El bloqueo de registros con lockf() se soportará para archivos regulares y puede que se soporte para otros archivos.

El argumento fildes es un descriptor de archivo abierto. Para establecer un bloqueo con esta función, el descriptor de archivo debe haberse abierto con permiso de solo escritura (O_WRONLY) o con permiso de lectura/escritura (O_RDWR).

El argumento function es un valor de control que especifica la acción a realizar. Los valores permitidos para function se definen en <unistd.h> de la siguiente manera:

Función Descripción
F_ULOCK Desbloquear secciones bloqueadas.
F_LOCK Bloquear una sección para uso exclusivo.
F_TLOCK Probar y bloquear una sección para uso exclusivo.
F_TEST Probar una sección para bloqueos por otros procesos.

F_TEST detectará si un bloqueo de otro proceso está presente en la sección especificada.

F_LOCK y F_TLOCK bloquearán una sección de un archivo si la sección está disponible.

F_ULOCK eliminará bloqueos de una sección del archivo.

El argumento size es el número de bytes contiguos a bloquear o desbloquear. La sección a bloquear o desbloquear comienza en el desplazamiento actual del archivo y se extiende hacia adelante para un tamaño positivo o hacia atrás para un tamaño negativo (los bytes anteriores hasta, pero sin incluir, el desplazamiento actual). Si size es 0, la sección desde el desplazamiento actual hasta el desplazamiento de archivo más grande posible se bloqueará (es decir, desde el desplazamiento actual hasta el final del archivo presente o futuro). No es necesario que un área esté asignada al archivo para ser bloqueada, ya que los bloqueos pueden existir más allá del final del archivo.

Las secciones bloqueadas con F_LOCK o F_TLOCK pueden, en su totalidad o en parte, contener o estar contenidas en una sección previamente bloqueada para el mismo proceso. Cuando esto ocurre, o si se producen secciones bloqueadas adyacentes, las secciones se combinarán en una única sección bloqueada. Si la solicitud hiciera que el número de bloqueos exceda un límite impuesto por el sistema, la solicitud fallará.

Las solicitudes F_LOCK y F_TLOCK solo difieren en la acción que se toma si la sección no está disponible. F_LOCK bloqueará el hilo llamante hasta que la sección esté disponible. F_TLOCK hará que la función falle si la sección ya está bloqueada por otro proceso.

Los bloqueos de archivos se liberarán en el primer cierre por parte del proceso que bloquea de cualquier descriptor de archivo para el archivo.

Las solicitudes F_ULOCK pueden liberar (total o parcialmente) una o más secciones bloqueadas controladas por el proceso. Las secciones bloqueadas se desbloquearán comenzando en el desplazamiento actual del archivo a través de size bytes o hasta el final del archivo si size es (off_t)0. Cuando no se libera la totalidad de una sección bloqueada (es decir, cuando el principio o el final del área a desbloquear cae dentro de una sección bloqueada), las porciones restantes de esa sección permanecerán bloqueadas por el proceso. La liberación de la porción central de una sección bloqueada hará que las porciones finales restantes, bloqueadas, se conviertan en dos secciones bloqueadas separadas. Si la solicitud hiciera que el número de bloqueos en el sistema exceda un límite impuesto por el sistema, la solicitud fallará.

Existe una posibilidad de interbloqueo si los hilos de un proceso que controla una sección bloqueada están bloqueados al acceder a una sección bloqueada de otro proceso. Si el sistema detecta que se produciría un interbloqueo, lockf() fallará con un error [EDEADLK].

La interacción entre los bloqueos de fcntl() y lockf() no está especificada.

El bloqueo en una sección será interrumpido por cualquier señal.

Una solicitud F_ULOCK en la que size no es cero y el desplazamiento del último byte de la sección solicitada es el valor máximo para un objeto de tipo off_t, cuando el proceso tiene un bloqueo existente en el que size es 0 y que incluye el último byte de la sección solicitada, se tratará como una solicitud para desbloquear desde el principio de la sección solicitada con un tamaño igual a 0. De lo contrario, una solicitud F_ULOCK intentará desbloquear solo la sección solicitada.

Intentar bloquear una sección de un archivo asociado a un stream con búfer produce resultados no especificados.

VALOR DE RETORNO

Tras una finalización exitosa, lockf() devolverá 0. De lo contrario, devolverá -1, establecerá errno para indicar un error, y los bloqueos existentes no se modificarán.

ERRORES

La función lockf() fallará si:

EBADF
El argumento fildes no es un descriptor de archivo válido y abierto; o function es F_LOCK o F_TLOCK y fildes no es un descriptor de archivo válido abierto para escritura.
EACCES o EAGAIN

El argumento function es F_TLOCK o F_TEST y la sección ya está bloqueada por otro proceso.
EDEADLK
El argumento function es F_LOCK y se detecta un interbloqueo.
EINTR
Se capturó una señal durante la ejecución de la función.
EINVAL
El argumento function no es F_LOCK, F_TLOCK, F_TEST o F_ULOCK; o size más el desplazamiento actual del archivo es menor que 0.
EOVERFLOW
El desplazamiento del primer byte, o si size no es 0, entonces el último byte de la sección solicitada no se puede representar correctamente en un objeto de tipo off_t.

La función lockf() puede fallar si:

EAGAIN
El argumento function es F_LOCK o F_TLOCK y el archivo está mapeado con mmap().
EDEADLK o ENOLCK

El argumento function es F_LOCK, F_TLOCK o F_ULOCK, y la solicitud haría que el número de bloqueos excediera un límite impuesto por el sistema.
EOPNOTSUPP o EINVAL

La implementación no soporta el bloqueo de archivos del tipo indicado por el argumento fildes.

EJEMPLOS

Bloqueo de una Porción de un Archivo

En el siguiente ejemplo, se está modificando un archivo llamado /home/cnd/mod1. A otros procesos que utilizan bloqueo se les impide modificarlo durante este proceso. Solo se bloquean los primeros 10000 bytes, y la llamada de bloqueo falla si otro proceso tiene alguna parte de esta área bloqueada previamente.

#include <fcntl.h>
#include <unistd.h>
int fildes;
int status;
...
fildes = open("/home/cnd/mod1", O_RDWR);
status = lockf(fildes, F_TLOCK, (off_t)10000);

USO DE LA APLICACIÓN

Si un proceso que utiliza lockf() es terminado, todos los bloqueos de registro mantenidos por ese proceso serán liberados.

Como los bloqueos son consultivos, otros procesos deben cooperar y utilizar explícitamente lockf() para poder detectar los bloqueos. Los sistemas de archivos que no soportan bloqueos (por ejemplo, sistemas de archivos de red que no tienen mecanismos de bloqueo apropiados) pueden permitir que múltiples procesos escriban en las mismas áreas del archivo, lo que puede provocar la corrupción de datos. Se recomienda utilizar la función fcntl() para un control más flexible del bloqueo de registros.

HISTORIA

La función lockf() apareció en la versión AT&T System V Release 2.

USO DE LA APLICACIÓN

El bloqueo de registros no debe usarse en combinación con las funciones fopen(), fread(), fwrite() y otras funciones stdio. En su lugar, deben utilizarse las funciones más primitivas y no almacenadas en búfer (como open()). Pueden ocurrir resultados inesperados en procesos que almacenan en búfer en el espacio de direcciones del usuario. El proceso puede leer/escribir posteriormente datos que están/estaban bloqueados. Las funciones stdio son la fuente más común de almacenamiento en búfer inesperado.

La función alarm() puede utilizarse para proporcionar una función de tiempo de espera en las aplicaciones que la requieran.
