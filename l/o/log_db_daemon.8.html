NOMBRE

log_db_daemon - Demonio de registro en base de datos para Squid

Versión 0.5.

SINOPSIS

log_db_daemon DSN [opciones]

DESCRIPCIÓN

Este programa escribe las entradas de access.log de Squid en una base de datos. Actualmente solo acepta el formato de registro nativo de squid.

El script ha sido desarrollado y probado en el siguiente entorno:

squid-2.7 Squid-3.2
mysql 5.0.26 y 5.1
perl 5.8.8
OpenSUSE 10.2

OPCIONES

DSN
DSN de la base de datos codificado como una ruta. Esto se envía como la ruta del archivo access_log.

Ejemplo de configuración:
access_log daemon:/host/database/table/username/password squid

para dejar un parámetro sin especificar use una doble barra:
access_log daemon://database/table/username/password squid

Por defecto "DBI:mysql:database=squid"

--debug
Escribe información de depuración en stderr.

CONFIGURACIÓN

Configuración de Squid

Directiva access_log

La ruta al archivo access.log se utiliza para proporcionar los parámetros de conexión a la base de datos.

access_log daemon:/mysql_host:puerto/base_de_datos/tabla/usuario/contraseña squid

El prefijo 'daemon' es obligatorio e indica a squid que el ayudante logfile_daemon debe usarse en lugar del registro normal en archivo.

El último parámetro le dice a squid qué formato de registro usar al escribir líneas al demonio de registro. Actualmente se admite el formato squid.

mysql_host:puerto
Host donde se está ejecutando el servidor mysql. Si se deja vacío, se asume 'localhost'.
base_de_datos
Nombre de la base de datos a la que conectarse. Si se deja vacío, se asume 'squid_log'.
tabla
Nombre de la tabla de la base de datos donde se almacenan las líneas de registro. Si se deja vacío, se asume 'access_log'.
usuario
Nombre de usuario a utilizar al conectarse a la base de datos. Si se deja vacío, se asume 'squid'.
contraseña
Contraseña a utilizar al conectarse a la base de datos. Si se deja vacío, no se usa contraseña.

Para dejar todos los campos con sus valores predeterminados, puede usar una sola barra:

access_log daemon:/ squid

Para especificar solo la contraseña de la base de datos, que por defecto está vacía, debe dejar sin especificar todos los demás parámetros usando cadenas nulas:

access_log daemon://///contraseña squid

Directiva logfile_daemon

Esta es la forma actual de indicarle a squid dónde reside el demonio logfile.

logfile_daemon /ruta/a/squid/libexec/logfile-daemon_mysql.pl

El script debe copiarse en la ubicación especificada en la directiva.

Configuración de la base de datos

Llamemos a la base de datos 'squid_log' y a la tabla de registro 'access_log'. El nombre de usuario y la contraseña para la conexión de la bd serán ambos 'squid'.

Base de datos

Crea la base de datos:

CREATE DATABASE squid_log;

Usuario

Crea el usuario:

GRANT INSERT,SELECT,CREATE ON squid_log.* TO 'squid'@'localhost' IDENTIFIED BY 'squid';
FLUSH PRIVILEGES;

Tenga en cuenta que solo se otorgan privilegios CREATE, INSERT y SELECT al usuario 'squid'. Esto asegura que el script del demonio de registro no pueda cambiar o modificar las entradas de registro.

Tabla

El demonio intentará inicializar esta tabla si no existe ninguna al iniciarse.

La tabla creada debería verse así:

CREATE TABLE access_log (
  id                   INTEGER NOT NULL AUTO_INCREMENT PRIMARY KEY,
  time_since_epoch     DECIMAL(15,3),
  time_response        INTEGER,
  ip_client            CHAR(15),
  ip_server            CHAR(15),
  http_status_code     VARCHAR(10),
  http_reply_size      INTEGER,
  http_method          VARCHAR(20),
  http_url             TEXT,
  http_username        VARCHAR(20),
  http_mime_type       VARCHAR(50),
  squid_hier_status    VARCHAR(20),
  squid_request_status VARCHAR(20)
);

EXTRACCIÓN DE DATOS

Ejemplo de consultas.

Clientes que acceden a la caché
SELECT DISTINCT ip_client FROM access_log;
Número de solicitudes por día
SELECT
  DATE(FROM_UNIXTIME(time_since_epoch)) AS date_day,
  COUNT(*) AS num_of_requests
FROM access_log
GROUP BY 1
ORDER BY 1;
Conteo de estado de la solicitud
Para obtener el recuento bruto de cada estado de solicitud: 
SELECT squid_request_status, COUNT(*) AS n
FROM access_log
GROUP BY squid_request_status
ORDER BY 2 DESC;

Para calcular el porcentaje de cada estado de solicitud:

SELECT
  squid_request_status,
  (COUNT(*)/(SELECT COUNT(*) FROM access_log)*100) AS percentage
FROM access_log
GROUP BY squid_request_status
ORDER BY 2 DESC;

Para distinguir solo entre HIT y MISS:

SELECT
  'hits',
  (SELECT COUNT(*)
  FROM access_log
  WHERE squid_request_status LIKE '%HIT%')
  /
  (SELECT COUNT(*) FROM access_log)*100
  AS percentage
UNION
SELECT
  'misses',
  (SELECT COUNT(*)
  FROM access_log
  WHERE squid_request_status LIKE '%MISS%')
  /
  (SELECT COUNT(*) FROM access_log)*100
  AS percentage;
Rangos de tiempo de respuesta
SELECT
  '0..500',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 0 AND time_response < 500
UNION
SELECT
  '500..1000',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 500 AND time_response < 1000
UNION
SELECT
  '1000..2000',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 1000 AND time_response < 2000
UNION
SELECT
  '>= 2000',
  COUNT(*)/(SELECT COUNT(*) FROM access_log)*100 AS percentage
FROM access_log
WHERE time_response >= 2000;
Tráfico por tipo de mime
SELECT
  http_mime_type,
  SUM(http_reply_size) as total_bytes
FROM access_log
GROUP BY http_mime_type
ORDER BY 2 DESC;
Tráfico por cliente
SELECT
  ip_client,
  SUM(http_reply_size) AS total_bytes
FROM access_log
GROUP BY 1
ORDER BY 2 DESC;

PROBLEMAS CONOCIDOS

Problemas de velocidad

Se sabe que el motor de almacenamiento MyISAM es más rápido que InnoDB, por lo que aunque no admite transacciones ni integridad referencial, podría ser más apropiado en este escenario. Es posible que desee agregar "ENGINE=MYISAM" al final del código de creación de la tabla en el script SQL anterior.

Se deben crear índices de acuerdo con las consultas que se ejecutan con más frecuencia. El script DDL solo crea un índice implícito para la columna de clave primaria.

Limpieza de tabla

log_db_daemon(8) — Arch Linux

NAME

log_db_daemon - Squid log database daemon

SYNOPSIS

log_db_daemon [-d] [-f config-file]

DESCRIPTION

The log_db_daemon is a helper program for Squid’s cache log aggregation. It is designed to parse and process Squid access log entries, extracting relevant information and storing it in a database. This allows for more efficient querying and analysis of Squid cache activity.

OPTIONS

-d
Enable debugging output. This option is useful for troubleshooting and monitoring the daemon’s operation.
-f config-file
Specify an alternative configuration file. If not provided, the daemon will look for a default configuration file (usually in /etc/squid/log_db_daemon.conf).

CONFIGURATION

The configuration file allows customization of various aspects of the daemon’s behavior, including:

  • Database connection settings (type, host, port, username, password).
  • Log file paths to monitor.
  • Log format parsing rules.
  • Data aggregation and summarization options.
  • Security settings and access controls.

Refer to the example configuration file provided with the distribution for detailed options and syntax.

DATA EXTRACTION

The daemon parses Squid access log entries, extracting fields such as timestamp, client IP address, requested URL, status code, bytes transferred, and client identity. The exact fields extracted depend on the configured log format and parsing rules.

This extracted data is then processed and stored in the configured database. The daemon can be configured to store raw log entries, summarized data, or both.

For performance reasons, particularly in high-volume environments, consider implementing log rotation and summarization strategies. Instead of storing every single log entry indefinitely, you could periodically aggregate older data into summary tables. This approach can help manage database size and improve query performance.

One solution would be to implement e.g. the "rotate log" command in a way that would calculate some summary values, put them in a "summary table" and then delete the lines used to calculate those values.

Similar cleanup code could be implemented in an external script and run periodically independently from squid log commands.

Testing

This script has only been tested in low-volume scenarios (single client, less than 10 req/s). Tests in high volume environments could reveal performance bottlenecks and bugs.
