LOCALE(1P) Manual del Programador POSIX LOCALE(1P)

PROLOGO

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

locale — obtener información específica de la configuración regional

SINOPSIS

locale [-a|-m]
locale [-ck] nombre...

DESCRIPCIÓN

La utilidad locale escribirá información sobre el entorno de configuración regional actual, o sobre todas las configuraciones regionales públicas, en la salida estándar. Para los fines de esta sección, una configuración regional pública es una proporcionada por la implementación que es accesible para la aplicación.

Cuando locale se invoca sin argumentos, resumirá el entorno de configuración regional actual para cada categoría de configuración regional, según lo determinado por la configuración de las variables de entorno definidas en el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 7, Configuración regional.

Cuando se invoca con operandos, escribirá los valores que se han asignado a las palabras clave en las categorías de configuración regional, de la siguiente manera:

*
Especificar un nombre de palabra clave seleccionará la palabra clave nombrada y la categoría que contiene esa palabra clave.
*
Especificar un nombre de categoría seleccionará la categoría nombrada y todas las palabras clave de esa categoría.

OPCIONES

La utilidad locale cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Pautas de sintaxis de utilidades.

Se admitirán las siguientes opciones:

-a
Escribir información sobre todas las configuraciones regionales públicas disponibles. Las configuraciones regionales disponibles incluirán POSIX, que representa la configuración regional POSIX. La forma en que la implementación determina qué otras configuraciones regionales están disponibles es definida por la implementación.
-c
Escribir los nombres de las categorías de configuración regional seleccionadas; véase la sección SALIDA ESTÁNDAR. La opción -c aumenta la legibilidad cuando se selecciona más de una categoría (por ejemplo, a través de más de un nombre de palabra clave o a través de un nombre de categoría). Es válida tanto con como sin la opción -k.
-k
Escribir los nombres y valores de las palabras clave seleccionadas. La implementación puede omitir valores para algunas palabras clave; véase la sección OPERANDOS.
-m
Escribir los nombres de los charmaps disponibles; véase el volumen de Definiciones Base de POSIX.1‐2017, Sección 6.1, Conjunto de caracteres portable.

OPERANDOS

Se admitirá el siguiente operando:

nombre
El nombre de una categoría de configuración regional según se define en el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 7, Configuración regional, el nombre de una palabra clave en una categoría de configuración regional, o el nombre reservado charmap. Se seleccionará la categoría o palabra clave nombrada para la salida. Si un solo nombre representa tanto un nombre de categoría de configuración regional como un nombre de palabra clave en la configuración regional actual, los resultados no están especificados. De lo contrario, los nombres de categorías y palabras clave pueden especificarse como operandos nombre, en cualquier secuencia. Es definido por la implementación si se escribirán valores de palabras clave para las categorías LC_CTYPE y LC_COLLATE.

ENTRADA ESTÁNDAR

No se utiliza.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán la ejecución de locale:

LANG
Proporcionar un valor predeterminado para las variables de internacionalización que no estén establecidas o estén vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de configuración regional).
LC_ALL
Si se establece en una cadena de valor no vacía, anulará los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determinar la configuración regional para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a multibyte en argumentos y archivos de entrada).
LC_MESSAGES

Determinar la configuración regional que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.
NLSPATH
Determinar la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

La aplicación garantizará que las variables de entorno LANG, LC_* y NLSPATH especifiquen el entorno de configuración regional actual que se escribirá; se utilizarán si no se especifica la opción -a.

EVENTOS ASINCRONOS

Predeterminado.

SALIDA ESTÁNDAR

La variable LANG se escribirá primero utilizando el siguiente formato:

"LANG=%s\n", <valor>

Si LANG no está establecida o es una cadena vacía, el valor es la cadena vacía.

Si locale se invoca sin opciones ni operandos, los nombres y valores de las variables de entorno LC_* descritas en este volumen de POSIX.1‐2017 se escribirán en la salida estándar, una variable por línea, y cada línea utilizará el siguiente formato. Solo se escribirán en este formato aquellas variables que estén establecidas en el entorno y no sean anuladas por LC_ALL:

"%s=%s\n", <nombre_variable>, <valor>

Los nombres de aquellas variables LC_* asociadas con categorías de configuración regional definidas en este volumen de POSIX.1‐2017 que no estén establecidas en el entorno o sean anuladas por LC_ALL se escribirán en el siguiente formato:

"%s=\"%s\"\n", <nombre_variable>, <valor_implícito>

El <valor_implícito> será el nombre de la configuración regional que ha sido seleccionada para esa categoría por la implementación, basándose en los valores de LANG y LC_ALL, como se describe en el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 8, Variables de entorno.

El <valor> y el <valor_implícito> que se muestran anteriormente se citarán correctamente para una posible reentrada posterior al shell. El <valor> no se citará con comillas dobles (para que el usuario pueda distinguirlo del caso de <valor_implícito>, que siempre requiere comillas dobles).

La variable LC_ALL se escribirá al final, utilizando el primer formato que se muestra. Si no está establecida, se escribirá como:

"LC_ALL=\n"

Si se especifican argumentos:

1.
Si se especifica la opción -a, se escribirán los nombres de todas las configuraciones regionales públicas, cada una en el siguiente formato:
"%s\n", <nombre_configuracion_regional>
2.
Si se especifica la opción -c, se escribirán los nombres de todas las categorías seleccionadas, cada una en el siguiente formato:
"%s\n", <nombre_categoria>

Si también se seleccionan palabras clave para escribir (véanse los siguientes puntos), la salida del nombre de la categoría precederá a la salida de la palabra clave para esa categoría.

DESCRIPCIÓN

El comando locale invoca la configuración regional seleccionada por las variables de entorno LC_ALL, LC_CTYPE, LC_COLLATE, LC_TIME, LC_NUMERIC, LC_MONETARY y LANG, en ese orden. La configuración regional seleccionada para cada categoría de la tabla se utiliza para determinar el comportamiento del comando.

Las siguientes opciones están disponibles:

-a
Enumera todos los nombres de configuración regional disponibles en el sistema.
-c
Si las opciones -k o -m no están especificadas, los nombres de las categorías se escribirán en la salida estándar. Si se especifica la opción -k, los nombres de las categorías y las palabras clave seleccionadas se escribirán.
-k
Si no se especifica la opción -c, los nombres de las categorías no se escribirán; solo se escribirán las palabras clave, según lo seleccionado por el operando <nombre>.
3.
Si se especifica la opción -k, se escribirán los nombres y valores de las palabras clave seleccionadas. Si un valor no es numérico y no es un valor de palabra clave compuesto, se escribirá en el siguiente formato:
"%s=\"%s\"\n", <nombre de palabra clave>, <valor de palabra clave>

Si un valor es un valor de palabra clave compuesto no numérico, se escribirá en el formato:

"%s=\"%s\"\n", <nombre de palabra clave>, <valor de palabra clave>

donde el <valor de palabra clave> es una cadena única de valores separados por caracteres <punto y coma>, o se escribirá en el formato:

"%s=%s\n", <nombre de palabra clave>, <valor de palabra clave>

donde el <valor de palabra clave> está codificado como un conjunto de cadenas, cada una entre comillas dobles, separadas por caracteres <punto y coma>.

Si la palabra clave era charmap, se escribirá el nombre del charmap (si lo hay) que se especificó a través de la opción -f de localedef al crear la configuración regional, con la palabra charmap como <nombre de palabra clave>.

Si un valor es numérico, se escribirá en uno de los siguientes formatos:

"%s=%d\n", <nombre de palabra clave>, <valor de palabra clave>
"%s=%c%o\n", <nombre de palabra clave>, <carácter de escape>, <valor de palabra clave>
"%s=%cx%x\n", <nombre de palabra clave>, <carácter de escape>, <valor de palabra clave>

donde el <carácter de escape> es el identificado por la palabra clave escape_char en la configuración regional actual; consulte el volumen de Definiciones Base de POSIX.1-2017, Sección 7.3, Definición de Configuración Regional.

Los valores de palabras clave compuestos (entradas de lista) se separarán en la salida con caracteres <punto y coma>. Cuando se incluyan en los valores de las palabras clave, el <punto y coma>, la <barra invertida>, la comilla doble y cualquier carácter de control irán precedidos (escapados) por el carácter de escape.

4.
Si la opción -k no está especificada, se escribirán los valores de palabras clave seleccionadas, cada una en el siguiente formato:
"%s\n", <valor de palabra clave>

Si la palabra clave era charmap, se escribirá el nombre del charmap (si lo hay) que se especificó a través de la opción -f de localedef al crear la configuración regional.

5.
Si se especifica la opción -m, se escribirá una lista de todos los charmaps disponibles, cada uno en el formato:
"%s\n", <charmap>

donde <charmap> está en un formato adecuado para ser utilizado como operando de opción para la opción -f de localedef.

STDERR

El error estándar solo se utilizará para mensajes de diagnóstico.

USO DE APLICACIONES

Si la variable de entorno LANG no está establecida o está establecida en un valor vacío, o si alguna de las variables de entorno LC_* está establecida en un valor no reconocido, las configuraciones regionales reales asumidas (si las hay) son definidas por la implementación como se describe en el volumen de Definiciones Base de POSIX.1-2017, Capítulo 8, Variables de Entorno.

Las implementaciones no están obligadas a escribir los valores reales de las palabras clave en las categorías LC_CTYPE y LC_COLLATE; sin embargo, deben escribir las categorías (permitiendo a una aplicación determinar, por ejemplo, qué clases de caracteres están disponibles).

EJEMPLOS

En los siguientes ejemplos, se asume que las variables de entorno de configuración regional están establecidas de la siguiente manera:

LANG=locale_x
LC_COLLATE=locale_y

El comando locale resultaría en la siguiente salida:

LANG=locale_x
LC_CTYPE="locale_x"
LC_COLLATE=locale_y
LC_TIME="locale_x"
LC_NUMERIC="locale_x"
LC_MONETARY="locale_x"
LC_MESSAGES="locale_x"
LC_ALL=

El orden de presentación de las categorías no está especificado por este volumen de POSIX.1-2017.

El comando:

LC_ALL=POSIX locale -ck decimal_point

produciría:

LC_NUMERIC
decimal_point="."

El siguiente comando muestra una aplicación de locale para determinar si una respuesta proporcionada por el usuario es afirmativa:

printf 'Prompt for response: '
read response
if printf "%s\n$response" | grep -Eq "$(locale yesexpr)"
then
    affirmative processing goes here
else
    non-affirmative processing goes here
fi

FUNDAMENTO RACIONAL

La salida para las categorías LC_CTYPE y LC_COLLATE se ha hecho dependiente de la implementación, ya que hay un valor cuestionable en tener un script de shell recibiendo un array completo de caracteres. También es difícil devolver una descripción de ordenación lógica, a menos que se devuelva un código fuente localedef completo.

La opción -m se incluyó para permitir que las aplicaciones consulten la existencia de charmaps. La salida es una lista de los charmaps (suministrados por la implementación y por el usuario, si los hay) en el sistema.

La opción -c se incluyó para mejorar la legibilidad cuando se selecciona más de una categoría (por ejemplo, a través de más de un nombre de palabra clave o a través del nombre de una categoría). Es válida tanto con como sin la opción -k.

La palabra clave charmap, que devuelve el nombre del charmap (si lo hay) que se utilizó al crear la configuración regional actual, se incluyó para permitir que las aplicaciones que necesitan la información la recuperen.

Según el volumen de Definiciones Base de POSIX.1-2017, Sección 6.1, Conjunto de Caracteres Portátiles, el estándar requiere que todas las configuraciones regionales compatibles tengan la misma codificación para <punto> y <barra diagonal>, ya que estos dos caracteres se utilizan en la secuencia de resolución de nombres de ruta independiente de la configuración regional. Por lo tanto, sería un error si locale -a listara configuraciones regionales basadas en ASCII y EBCDIC, ya que esas dos codificaciones no comparten la misma representación para <punto> ni para <barra diagonal>. Se esperaría que cualquier sistema que admita ambos entornos proporcione dos configuraciones regionales POSIX, una en cada código, donde solo las configuraciones regionales apropiadas para el entorno actual sean visibles a la vez. En una implementación compatible con XSI, la utilidad dd es el único medio portátil para realizar conversiones entre los dos conjuntos de caracteres.
