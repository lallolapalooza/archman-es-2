local::lib(3) Documentación de Perl aportada por el usuario local::lib(3)

NOMBRE

local::lib - crea y usa una librería local/ para módulos Perl con PERL5LIB

SINOPSIS

En código -

use local::lib; # configura una librería local en ~/perl5
use local::lib '~/foo'; # igual, pero en ~/foo
# O...
use FindBin;
use local::lib "$FindBin::Bin/../support";  # librería de soporte local de la aplicación

Desde la consola -

# Instala LWP y sus dependencias faltantes en el directorio '~/perl5'
perl -MCPAN -Mlocal::lib -e 'CPAN::install(LWP)'
# Simplemente imprime comandos útiles para la consola
$ perl -Mlocal::lib
PERL_MB_OPT='--install_base /home/username/perl5'; export PERL_MB_OPT;
PERL_MM_OPT='INSTALL_BASE=/home/username/perl5'; export PERL_MM_OPT;
PERL5LIB="/home/username/perl5/lib/perl5"; export PERL5LIB;
PATH="/home/username/perl5/bin:$PATH"; export PATH;
PERL_LOCAL_LIB_ROOT="/home/usename/perl5:$PERL_LOCAL_LIB_ROOT"; export PERL_LOCAL_LIB_ROOT;

Desde un archivo .bash_profile o .bashrc -

eval "$(perl -I$HOME/perl5/lib/perl5 -Mlocal::lib)"

La técnica de arranque

Una forma típica de instalar local::lib es mediante lo que se conoce como la técnica de "arranque". Deberías hacer esto si tu administrador del sistema no ha instalado local::lib previamente. En este caso, necesitarás instalar local::lib en tu directorio personal.

Incluso si tienes privilegios administrativos, seguirás queriendo configurar tus variables de entorno, como se discute en el paso 4. Sin esto, seguirías instalando los módulos en la instalación de CPAN del sistema y tus scripts de Perl tampoco usarán la ruta lib/ con la que arrancaste con local::lib.

Por defecto, local::lib se instala a sí mismo y los módulos de CPAN en ~/perl5.

Los usuarios de Windows también deben ver "Diferencias al usar este módulo en Win32".

1.
Descarga y descomprime el archivo tar de local::lib desde CPAN (busca "Download" en la página de CPAN sobre local::lib). Haz esto como un usuario normal, no como root o administrador. Descomprime el archivo en tu directorio personal o en cualquier otra ubicación conveniente.
2.
Ejecuta esto: 
perl Makefile.PL --bootstrap

Si el sistema te pregunta si debe configurar automáticamente tanto como sea posible, normalmente responderías sí.

3.
Ejecuta esto: (local::lib asume que tienes make instalado en tu sistema) 
make test && make install
4.
Ahora necesitamos configurar las variables de entorno apropiadas, para que Perl comience a usar nuestro directorio lib/ recién generado. Si estás usando bash o cualquier otro shell de Bourne, puedes añadir esto a tu script de inicio de shell de esta manera: 
echo 'eval "$(perl -I$HOME/perl5/lib/perl5 -Mlocal::lib)"' >>~/.bashrc

Si estás usando C shell, puedes hacerlo de la siguiente manera:

% echo $SHELL
/bin/csh
$ echo 'eval `perl -I$HOME/perl5/lib/perl5 -Mlocal::lib`' >> ~/.cshrc

Después de escribir tu archivo de configuración de shell, asegúrate de volver a leerlo para que los ajustes cambiados se apliquen al entorno de tu shell actual. Los shells de Bourne usan ". ~/.bashrc" para esto, mientras que los shells C usan "source ~/.cshrc".

Arranque en un directorio alternativo

Para instalar local::lib en un directorio que no sea el predeterminado, necesitas especificar el nombre del directorio al llamar a bootstrap. Luego, al configurar las variables de entorno, tanto perl como local::lib deben ser informados de la ubicación del directorio de arranque. El proceso de configuración se vería así:

perl Makefile.PL --bootstrap=~/foo
make test && make install
echo 'eval "$(perl -I$HOME/foo/lib/perl5 -Mlocal::lib=$HOME/foo)"' >>~/.bashrc
. ~/.bashrc

Otras opciones de arranque

Si estás en una máquina lenta, o operando bajo limitaciones drásticas de espacio en disco, puedes deshabilitar la generación automática de páginas de manual a partir de POD al instalar módulos usando el argumento "--no-manpages" durante el arranque:

perl Makefile.PL --bootstrap --no-manpages

Para evitar hacer varios arranques para varios entornos de módulos Perl en la misma cuenta, por ejemplo, si lo usas para varias aplicaciones desplegadas de forma independiente, puedes usar una instalación de local::lib arrancada para instalar módulos en diferentes directorios directamente de esta manera:

cd ~/mydir1
perl -Mlocal::lib=./
eval $(perl -Mlocal::lib=./)  ### Para configurar el entorno solo para esta consola
printenv                      ### Verás que ~/mydir1 está en PERL5LIB
perl -MCPAN -e install ...    ### cualquier módulo que desees
cd ../mydir2
... REPETIR ...

Si usas .bashrc para activar local::lib automáticamente, local::lib se volverá a habilitar en cualquier sub-shell utilizada, ignorando los ajustes que hayas podido hacer en la consola padre. Para evitar esto, puedes inicializar local::lib en .bash_profile en lugar de .bashrc, o proteger la invocación de local::lib con una verificación de $SHLVL:

[ $SHLVL -eq 1 ] && eval "$(perl -I$HOME/perl5/lib/perl5 -Mlocal::lib)"

Si estás trabajando con varios entornos "local::lib", puede que quieras eliminar algunos de ellos del entorno actual sin alterar los otros. Puedes desactivar un entorno así (usando bourne sh):

eval $(perl -Mlocal::lib=--deactivate,~/path)

lo que generará y ejecutará los comandos necesarios para eliminar "~/path" de tus diversas rutas de búsqueda. Cualquiera que haya sido el entorno **activado más recientemente** seguirá siendo el objetivo para la instalación de módulos. Es decir, si activas "~/path_A" y luego activas "~/path_B", los nuevos módulos que instales irán a "~/path_B". Si desactivas "~/path_B", los módulos se instalarán en "~/pathA" -- pero si desactivas "~/path_A", todavía se instalarán en "~/pathB" porque pathB fue activado más tarde.

También puedes pedirle a "local::lib" que se elimine completamente del entorno de la consola actual con la opción "--deactivate-all". Para múltiples entornos para múltiples aplicaciones, puede que necesites incluir una versión modificada de las instrucciones "use FindBin" en la muestra "En código" anterior. Si hiciste algo como lo anterior, tienes un conjunto de módulos Perl en "~/mydir1/lib". Si tienes un script en "~/mydir1/scripts/myscript.pl", necesitas indicarle dónde encontrar los módulos que instalaste para él en "~/mydir1/lib".

En "~/mydir1/scripts/myscript.pl":

use strict;
use warnings;
use local::lib "$FindBin::Bin/..";  ### apunta a ~/mydir1 y local::lib encuentra lib
use lib "$FindBin::Bin/../lib";     ### apunta a ~/mydir1/lib

Pon esto antes de cualquier bloque BEGIN { ... } que requiera los módulos que instalaste.

Diferencias al usar este módulo en Win32

Para configurar las variables de entorno adecuadas para tu sesión actual de "CMD.exe", puedes usar esto:

C:\>perl -Mlocal::lib
set PERL_MB_OPT=--install_base C:\DOCUME~1\ADMINI~1\perl5
set PERL_MM_OPT=INSTALL_BASE=C:\DOCUME~1\ADMINI~1\perl5
set PERL5LIB=C:\DOCUME~1\ADMINI~1\perl5\lib\perl5
set PATH=C:\DOCUME~1\ADMINI~1\perl5\bin;%PATH%
### Para configurar el entorno solo para esta consola
C:\>perl -Mlocal::lib > %TEMP%\tmp.bat && %TEMP%\tmp.bat && del %TEMP%\tmp.bat
### en lugar de $(perl -Mlocal::lib=./)

Si quieres que las entradas del entorno persistan, necesitarás añadirlas tú mismo al applet de Sistema del Panel de Control o usar App::local::lib::Win32Helper.

El "~" se traduce al directorio del perfil del usuario (el directorio con el nombre del usuario bajo "Documentos y Configuraciones" (Windows XP o anterior) o "Usuarios" (Windows Vista o posterior)) a menos que exista $ENV{HOME}. Después de eso, el directorio personal se traduce a un nombre corto (lo que significa que el directorio debe existir) y se crean los subdirectorios.

NAME

local::lib - Create and use a local Perl library

SYNOPSIS

  use local::lib;
  # OR
  use local::lib '/path/to/my/perl/lib';
  # OR use options
  use local::lib '-DEACTIVATE', '/path/to/my/perl/lib';
  # OR
  perl -Mlocal::lib script.pl
  # OR
  perl -Mlocal::lib='/path/to/my/perl/lib' script.pl
  # OR
  perl -Mlocal::lib=--deactivate,/path/to/my/perl/lib script.pl
  # OR
  use local::lib '-DEACTIVATE-ALL';
  # OR
  perl -Mlocal::lib=-DEACTIVATE-ALL
  # OR
  perl -Mlocal::lib=--quiet --always /path/to/my/perl/lib
  # OR
  perl -Mlocal::lib=--shelltype=powershell --always /path/to/my/perl/lib
  # OR
  perl -Mlocal::lib --no-create /path/to/my/perl/lib

WINDOWS POWERSHELL

local::lib also supports PowerShell, and can be used with the "Invoke-Expression" cmdlet.

Invoke-Expression "$(perl -Mlocal::lib)"

RATIONALE

The version of a Perl package on your machine is not always the version you need. Obviously, the best thing to do would be to update to the version you need. However, you might be in a situation where you're prevented from doing this. Perhaps you don't have system administrator privileges; or perhaps you are using a package management system such as Debian, and nobody has yet gotten around to packaging up the version you need.

local::lib solves this problem by allowing you to create your own directory of Perl packages downloaded from CPAN (in a multi-user system, this would typically be within your own home directory). The existing system Perl installation is not affected; you simply invoke Perl with special options so that Perl uses the packages in your own local package directory rather than the system packages. local::lib arranges things so that your locally installed version of the Perl packages takes precedence over the system installation.

If you are using a package management system (such as Debian), you don't need to worry about Debian and CPAN stepping on each other's toes. Your local version of the packages will be written to an entirely separate directory from those installed by Debian.

DESCRIPTION

This module provides a quick, convenient way of bootstrapping a user-local Perl module library located within the user's home directory. It also constructs and prints out for the user the list of environment variables using the syntax appropriate for the user's current shell (as specified by the "SHELL" environment variable), suitable for directly adding to one's shell configuration file.

More generally, local::lib allows for the bootstrapping and usage of a directory containing Perl modules outside of Perl's @INC. This makes it easier to ship an application with an app-specific copy of a Perl module, or collection of modules. Useful in cases like when an upstream maintainer hasn't applied a patch to a module of theirs that you need for your application.

On import, local::lib sets the following environment variables to appropriate values:

PERL_MB_OPT
PERL_MM_OPT
PERL5LIB
PATH
PERL_LOCAL_LIB_ROOT

When possible, these will be appended to instead of overwritten entirely.

These values are then available for reference by any code after import.

CREATING A SELF-CONTAINED SET OF MODULES

See lib::core::only for one way to do this - but note that there are a number of caveats, and the best approach is always to perform a build against a clean perl (i.e. site and vendor as close to empty as possible).

IMPORT OPTIONS

Options are values that can be passed to the "local::lib" import besides the directory to use. They are specified as "use local::lib '--option'[, path];" or "perl -Mlocal::lib=--option[,path]".

--deactivate

Remove the chosen path (or the default path) from the module search paths if it was added by "local::lib", instead of adding it.

--deactivate-all

Remove all directories that were added to search paths by "local::lib" from the search paths.

--quiet

Don't output any messages about directories being created.

--always

Always add directories to environment variables, ignoring if they are already included.

--shelltype

Specify the shell type to use for output. By default, the shell will be detected based on the environment. Should be one of: "bourne", "csh", "cmd", or "powershell".

--no-create

Prevents "local::lib" from creating directories when activating dirs. This is likely to cause issues on Win32 systems.

CLASS METHODS

ensure_dir_structure_for

Arguments: $path
Return value: None

Attempts to create a local::lib directory, including subdirectories and all required parent directories. Throws an exception on failure.

print_environment_vars_for

Arguments: $path
Return value: None

Prints to standard output the variables listed above, properly set to use the given path as the base directory.

build_environment_vars_for

Arguments: $path
Return value: %environment_vars

Returns a hash with the variables listed above, properly set to use the given path as the base directory.

setup_env_hash_for

Arguments: $path
Return value: None

Constructs the %ENV keys for the given path, by calling "build_environment_vars_for".

active_paths

Arguments: None
Return value: @paths

Returns a list of active "local::lib" paths, according to the "PERL_LOCAL_LIB_ROOT" environment variable and verified against what is really in @INC.

install_base_perl_path

Arguments: $path
Return value: $install_base_perl_path

Returns a path describing where to install the Perl modules for this local library installation. Appends the directories "lib" and "perl5" to the given path.

lib_paths_for

Arguments: $path
Return value: @lib_paths

Returns the list of paths perl will search for libraries, given a base path. This includes the base path itself, the architecture specific subdirectory, and perl version specific subdirectories. These paths may not all exist.

install_base_bin_path

Arguments: $path
Return value: $install_base_bin_path

Returns a path describing where to install the executable programs for this local library installation. Appends the directory "bin" to the given path.

installer_options_for

Arguments: $path
Return value: %installer_env_vars

Returns a hash of environment variables that should be set to cause installation into the given path.

resolve_empty_path

Arguments: $path
Return value: $base_path

Builds and returns the base path into which to set up the local module installation. Defaults to "~/perl5".

resolve_home_path

Argumentos: $ruta
Valor de retorno: $ruta_home

Intenta encontrar el directorio home del usuario. Si no se dispone de una respuesta definitiva, lanza una excepción.

resolve_relative_path

Argumentos: $ruta
Valor de retorno: $ruta_absoluta

Traduce la ruta dada a una ruta absoluta.

resolve_path

Argumentos: $ruta
Valor de retorno: $ruta_absoluta

Llama a lo siguiente en una canalización, pasando el resultado del anterior al siguiente, en un intento de encontrar dónde configurar el entorno para la instalación de una biblioteca local: "resolve_empty_path", "resolve_home_path", "resolve_relative_path". Pasa el argumento de ruta dado a "resolve_empty_path" que luego devuelve un resultado que se pasa a "resolve_home_path", que luego tiene su resultado pasado a "resolve_relative_path". El resultado de esta llamada final se devuelve de "resolve_path".

INTERFAZ DEL OBJETO

new

Argumentos: %atributos
Valor de retorno: $local_lib

Construye un nuevo objeto "local::lib", representando el estado actual de @INC y las variables de entorno relevantes.

ATRIBUTOS

roots

Una referencia a un array que representa directorios activos de "local::lib".

inc

Una referencia a un array que representa @INC.

libs

Una referencia a un array que representa la variable de entorno PERL5LIB.

bins

Una referencia a un array que representa la variable de entorno PATH.

extra

Una referencia a un hash de variables de entorno adicionales (por ejemplo, "PERL_MM_OPT" y "PERL_MB_OPT").

no_create

Si se establece, "local::lib" no intentará crear directorios al activarlos.

MÉTODOS DEL OBJETO

clone

Construye un nuevo objeto "local::lib" basado en el existente, anulando los atributos especificados.

activate

Argumentos: $ruta
Valor de retorno: $nuevo_local_lib

Construye una nueva instancia con la ruta especificada activa.

deactivate

Argumentos: $ruta
Valor de retorno: $nuevo_local_lib

deactivate_all

Argumentos: Ninguno

environment_vars_string

Argumentos: [ $tipo_shell ]
Valor de retorno: $cadena_entorno_shell

build_environment_vars

Argumentos: Ninguno
Valor de retorno: %variables_entorno

Devuelve un hash con las variables listadas anteriormente, correctamente configuradas para usar la ruta dada como directorio base.

setup_env_hash

Argumentos: Ninguno
Valor de retorno: Ninguno

Construye las claves %ENV para la ruta dada, llamando a "build_environment_vars".

setup_local_lib

Construye el hash %ENV usando "setup_env_hash", y configura @INC.

UNA ADVERTENCIA SOBRE UNINST=1

Tenga cuidado al usar local::lib en combinación con "make install UNINST=1". La idea de esta característica es que desinstalará una versión antigua de un módulo antes de instalar una nueva. Sin embargo, carece de una verificación de seguridad de que la versión antigua y la nueva irán al mismo directorio. Usado en combinación con local::lib, puede eliminar potencialmente una versión de un módulo accesible globalmente mientras instala la nueva versión en un lugar local. Solo combine "make install UNINST=1" y local::lib si comprende estas posibles consecuencias.

LIMITACIONES

  • Los nombres de directorios con espacios no son bien soportados por la cadena de herramientas de perl y los programas que utiliza. Las distribuciones puramente de perl deberían soportar espacios, pero los problemas son más probables con las distribuciones que requieren compilación. Una solución que puede hacer es mover su local::lib a un directorio con espacios después de haber instalado todos los módulos dentro del arranque de su local::lib. Pero tenga en cuenta que no podrá actualizar ni instalar módulos de CPAN después de la mudanza.
  • Detección de shell bastante básica. Actualmente, todo lo que tenga csh en su nombre se asume que es un shell C o algo compatible, y todo lo demás se asume que es Bourne, excepto en sistemas Win32. Si la variable de entorno "SHELL" no está establecida, se asume un shell compatible con Bourne.
  • Elimina cualquier PERL_MM_OPT o PERL_MB_OPT existente.
  • Probablemente debería arreglar automáticamente la configuración de CPAN si aún no se ha hecho.
  • En VMS y MacOS Classic (pre-OS X), local::lib carga File::Spec. Esto significa que cualquier versión de File::Spec instalada en local::lib será ignorada por los scripts que utilizan local::lib. Una solución para esto es usar "use lib "$local_lib/lib/perl5";" en lugar de usar "local::lib" directamente.
  • Entra en conflicto con la opción "PREFIX" de ExtUtils::MakeMaker. "local::lib" usa la opción "INSTALL_BASE", ya que tiene un comportamiento más predecible y sensato. Si algo intenta usar la opción "PREFIX" al ejecutar un Makefile.PL, ExtUtils::MakeMaker se negará a ejecutarse, ya que las dos opciones entran en conflicto. Esto se puede solucionar desactivando temporalmente la variable de entorno "PERL_MM_OPT".
  • Entra en conflicto con la opción "--prefix" de Module::Build. Similar a la limitación anterior, pero cualquier opción "--prefix" especificada será ignorada. Esto se puede solucionar desactivando temporalmente la variable de entorno "PERL_MB_OPT".

Se aceptan parches para cualquiera de los puntos anteriores.

•
En sistemas Win32, no hay forma de escribir las variables de entorno creadas en el registro, para que puedan persistir a través de un reinicio.

SOLUCIÓN DE PROBLEMAS
