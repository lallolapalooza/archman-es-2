lo_method lo_server_thread_add_method (lo_server_thread st, const char * path, const char * typespec, lo_method_handler h, const void * user_data)

Agrega un método OSC al hilo de servidor especificado.

Parámetros

st El hilo de servidor al que se va a agregar el método.
path La ruta OSC a la que registrar el método. Si se pasa NULL, el método coincidirá con todas las rutas.
typespec El typespec que acepta el método. Los mensajes entrantes con typespecs similares (p. ej., aquellos con tipos numéricos en la misma posición) serán forzados al typespec dado aquí.
h La función de devolución de llamada del manejador del método que se llamará si se recibe un mensaje coincidente.
user_data Un valor que se pasará a la función de devolución de llamada, h, cuando se invoque y coincida con este método.

int lo_server_thread_del_lo_method (lo_server_thread st, lo_method m)

Elimina un método OSC del hilo de servidor especificado.

Parámetros

st El hilo de servidor del que se va a eliminar el método.
m El identificador lo_method devuelto por lo_server_add_method para el método a eliminar del servidor.

Devoluciones

Distinto de cero si no se encontró en la lista de métodos para el servidor.

void lo_server_thread_del_method (lo_server_thread st, const char * path, const char * typespec)

Elimina un método OSC del hilo de servidor especificado.

Parámetros

st El hilo de servidor del que se va a eliminar el método.
path La ruta OSC del método a eliminar. Si se pasa NULL, el método coincidirá con el manejador genérico.
typespec El typespec que acepta el método.

int lo_server_thread_events_pending (lo_server_thread st)

Devuelve verdadero si hay eventos programados (p. ej., de paquetes) esperando ser distribuidos por el hilo.

void lo_server_thread_free (lo_server_thread st)

Libera la memoria ocupada por un hilo de servidor. Libera la memoria y, si se está ejecutando actualmente, detendrá el hilo asociado.

int lo_server_thread_get_port (lo_server_thread st)

Devuelve el número de puerto al que se ha enlazado el hilo del servidor.

lo_server lo_server_thread_get_server (lo_server_thread st)

Devuelve el lo_server de un lo_server_thread. Esta función es útil para pasar el lo_server de un hilo a lo_send_from().

char * lo_server_thread_get_url (lo_server_thread st)

Devuelve una URL que describe la dirección del hilo del servidor. El valor devuelto debe ser liberado con free() para recuperar memoria.

lo_server_thread lo_server_thread_new (const char * port, lo_err_handler err_h)

Crea un nuevo hilo de servidor para manejar mensajes OSC entrantes. Los hilos de servidor se encargan de la recepción y distribución de mensajes creando transparentemente un hilo del sistema para manejar los mensajes entrantes. Usa esto si no deseas manejar el threading tú mismo.

Parámetros

port Si se pasa NULL, el sistema elegirá un puerto no utilizado; su número puede recuperarse con lo_server_thread_get_port() para pasarlo a los clientes. De lo contrario, se puede pasar un número de puerto decimal, un nombre de servicio o la ruta de un socket de dominio UNIX.
err_h Una función que se llamará en caso de que se produzca un error. La prototipo de la función se define en lo_types.h

lo_server_thread lo_server_thread_new_multicast_iface (const char * group, const char * port, const char * iface, const char * ip, lo_err_handler err_h)

Crea una nueva instancia de hilo de servidor, y se une a un grupo multicast UDP, especificando opcionalmente qué interfaz de red usar. Nota que usualmente solo uno de iface o ip son especificados.

Parámetros

group El grupo multicast al que unirse.
port El puerto en el que escuchar.
iface La interfaz de red a usar (p. ej., eth0).
ip La dirección IP de la interfaz de red a usar.
err_h La función de manejo de errores.

lo_server_thread lo_server_thread_new_from_url (const char * url, lo_err_handler err_h)

Crea un nuevo hilo de servidor, tomando el puerto y la IP del grupo multicast opcional de una cadena URL.

Parámetros

url La URL de la que extraer la información del puerto y el grupo multicast. Formatos soportados:
  • osc.tcp://host:port/
  • osc.udp://host:port/
  • osc.udp://port/
  • osc.tcp://port/

err_h La función de manejo de errores.

lo_server_thread lo_server_thread_new_from_url (const char * url, lo_err_handler err_h)

Crea un nuevo hilo de servidor, obteniendo el puerto y el grupo IP de multidifusión opcional de una cadena de URL.

err_h Una función de devolución de llamada de errores que se llamará si hay un error en la recepción de mensajes o en la creación del servidor. Pase NULL si no desea el manejo de errores.

Una nueva instancia de lo_server_thread.

lo_server_thread lo_server_thread_new_multicast (const char * group, const char * port, lo_err_handler err_h)

Crea un nuevo hilo de servidor para manejar mensajes OSC entrantes y unirse a un grupo de multidifusión UDP. Los hilos de servidor se encargan de la recepción y el envío de mensajes creando de forma transparente un hilo del sistema para manejar los mensajes entrantes. Utilice esto si no desea manejar los hilos usted mismo.

Parámetros

group El grupo de multidifusión al que unirse. Consulte la documentación sobre multidifusión IP para el rango de direcciones aceptable; por ejemplo, http://tldp.org/HOWTO/Multicast-HOWTO-2.html
port Si se pasa NULL, el sistema elegirá un puerto no utilizado, su número puede recuperarse con lo_server_thread_get_port() para que pueda pasarse a los clientes. De lo contrario, se puede pasar un número de puerto decimal, un nombre de servicio o una ruta de socket de dominio UNIX.
err_h Una función que se llamará en caso de que se produzca un error. El prototipo de la función se define en lo_types.h

lo_server_thread lo_server_thread_new_multicast_iface (const char * group, const char * port, const char * iface, const char * ip, lo_err_handler err_h)

Crea una nueva instancia de hilo de servidor y se une a un grupo de multidifusión UDP, especificando opcionalmente qué interfaz de red utilizar. Tenga en cuenta que normalmente solo se especifica una de las opciones `iface` o `ip`.

Parámetros

group El grupo de multidifusión al que unirse. Consulte la documentación sobre multidifusión IP para el rango de direcciones aceptable; por ejemplo, http://tldp.org/HOWTO/Multicast-HOWTO-2.html
port Si se utiliza UDP, se puede pasar NULL para encontrar un puerto no utilizado. De lo contrario, se puede pasar un número de puerto decimal o un nombre de servicio. Si se utilizan sockets de dominio UNIX, se debe pasar una ruta de socket aquí.
iface Una cadena que especifica el nombre de una interfaz de red a utilizar, o cero si no se especifica.
ip Una cadena que especifica la dirección IP de una interfaz de red a utilizar, o cero si no se especifica.
err_h Una función de devolución de llamada de errores que se llamará si hay un error en la recepción de mensajes o en la creación del servidor. Pase NULL si no desea el manejo de errores.

lo_server_thread lo_server_thread_new_with_proto (const char * port, int proto, lo_err_handler err_h)

Crea un nuevo hilo de servidor para manejar mensajes OSC entrantes, especificando el protocolo. Los hilos de servidor se encargan de la recepción y el envío de mensajes creando de forma transparente un hilo del sistema para manejar los mensajes entrantes. Utilice esto si no desea manejar los hilos usted mismo.

Parámetros

port Si se pasa NULL, el sistema elegirá un puerto no utilizado, su número puede recuperarse con lo_server_thread_get_port() para que pueda pasarse a los clientes. De lo contrario, se puede pasar un número de puerto decimal, un nombre de servicio o una ruta de socket de dominio UNIX.
proto El protocolo a utilizar, debe ser uno de LO_UDP, LO_TCP o LO_UNIX.
err_h Una función que se llamará en caso de que se produzca un error. El prototipo de la función se define en lo_types.h

Establece una función de inicialización y/o una función de limpieza para el hilo de servidor especificado. Para que tenga algún efecto, debe llamarse antes de que se inicie el hilo del servidor.
