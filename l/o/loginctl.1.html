NOMBRE

loginctl - Controlar el gestor de inicios de sesión de systemd

SINOPSIS

loginctl [OPCIONES...] {COMANDO} [NOMBRE...]

DESCRIPCIÓN

loginctl puede ser utilizado para introspeccionar y controlar el estado del gestor de inicios de sesión de systemd(1), systemd-logind.service(8).

COMANDOS

Se entienden los siguientes comandos:

Comandos de sesión

list-sessions

Lista las sesiones actuales. La salida en formato JSON puede ser activada/desactivada usando la opción --json= o -j.

session-status [ID...]

Muestra información concisa del estado en tiempo de ejecución sobre una o más sesiones, seguida por los datos de registro más recientes del journal. Acepta uno o más identificadores de sesión como parámetros. Si no se pasan identificadores de sesión, se muestra el estado de la sesión del llamador. Esta función está destinada a generar una salida legible por humanos. Si busca una salida que pueda ser analizada por máquinas, use show-session en su lugar.

Añadido en la versión 233.

show-session [ID...]

Muestra las propiedades de una o más sesiones o del propio gestor. Si no se especifica ningún argumento, se mostrarán las propiedades del gestor. Si se especifica un ID de sesión, se mostrarán las propiedades de la sesión. Especialmente, si el ID dado es "self", se utilizará la sesión a la que pertenece el proceso de loginctl. Si es "auto", se utilizará la sesión actual como con "self" si existe, y se recurrirá a la sesión gráfica del usuario actual. Por defecto, se suprimen las propiedades vacías. Utilice --all para mostrarlas también. Para seleccionar propiedades específicas a mostrar, utilice --property=. Este comando está destinado a ser utilizado siempre que se requiera una salida analizable por máquinas. Utilice session-status si busca una salida formateada y legible por humanos.

Añadido en la versión 233.

activate [ID]

Activa una sesión. Esto trae una sesión al primer plano si otra sesión está actualmente en primer plano en el asiento respectivo. Acepta un identificador de sesión como argumento. Si no se especifica ningún argumento, la sesión del llamador se pone en primer plano.

Añadido en la versión 219.

lock-session [ID...], unlock-session [ID...]

Activa/desactiva el bloqueo de pantalla en una o más sesiones, si la sesión lo soporta. Acepta uno o más identificadores de sesión como argumentos. Si no se especifica ningún argumento, la sesión del llamador se bloquea/desbloquea.

Añadido en la versión 233.

lock-sessions, unlock-sessions

Activa/desactiva el bloqueo de pantalla en todas las sesiones actuales que lo soporten.

Añadido en la versión 188.

terminate-session ID...

Termina una sesión. Esto mata todos los procesos de la sesión y desasigna todos los recursos adjuntos a la sesión. Si el argumento se especifica como una cadena vacía, se termina la sesión que invoca el comando.

Añadido en la versión 233.

kill-session ID...

Envía una señal a uno o más procesos de la sesión. Utilice --kill-whom= para seleccionar el proceso a matar. Utilice --signal= para seleccionar la señal a enviar. Si el argumento se especifica como una cadena vacía, la señal se envía a la sesión que invoca el comando.

Añadido en la versión 233.

Comandos de usuario

list-users

Lista los usuarios actualmente conectados. La salida en formato JSON puede ser activada/desactivada usando la opción --json= o -j.

user-status [USUARIO...]

Muestra información concisa del estado en tiempo de ejecución sobre uno o más usuarios conectados, seguida por los datos de registro más recientes del journal. Acepta uno o más nombres de usuario o IDs numéricos de usuario como parámetros. Si no se pasan parámetros, se muestra el estado del usuario de la sesión del llamador. Esta función está destinada a generar una salida legible por humanos. Si busca una salida que pueda ser analizada por máquinas, use show-user en su lugar.

Añadido en la versión 233.

show-user [USUARIO...]

Muestra las propiedades de uno o más usuarios o del propio gestor. Si no se especifica ningún argumento, se mostrarán las propiedades del gestor. Si se especifica un usuario, se mostrarán las propiedades del usuario. Por defecto, se suprimen las propiedades vacías. Utilice --all para mostrarlas también. Para seleccionar propiedades específicas a mostrar, utilice --property=. Este comando está destinado a ser utilizado siempre que se requiera una salida analizable por máquinas. Utilice user-status si busca una salida formateada y legible por humanos.

Añadido en la versión 233.

enable-linger [USUARIO...], disable-linger [USUARIO...]

Habilita/deshabilita la persistencia de usuario para uno o más usuarios. Si está habilitada para un usuario específico, se inicia un gestor de usuario para el usuario al arrancar y se mantiene activo después de los cierres de sesión. Esto permite a los usuarios que no están conectados ejecutar servicios de larga duración. Acepta uno o más nombres de usuario o UIDs numéricos como argumento. Si no se especifica ningún argumento, habilita/deshabilita la persistencia para el usuario de la sesión del llamador.

Véase también el ajuste KillUserProcesses= en logind.conf(5).

Añadido en la versión 233.

terminate-user USUARIO...

Termina todas las sesiones de un usuario. Esto mata todos los procesos de todas las sesiones del usuario y desasigna todos los recursos en tiempo de ejecución adjuntos al usuario. Si el argumento se especifica como una cadena vacía, se terminan las sesiones del usuario que invoca el comando.

Añadido en la versión 233.

kill-user USUARIO...

Envía una señal a todos los procesos de un usuario. Utilice --signal= para seleccionar la señal a enviar. Si el argumento se especifica como una cadena vacía, la señal se envía a las sesiones del usuario que invoca el comando.

Añadido en la versión 233.

Comandos de asiento

list-seats

Lista los asientos actualmente disponibles en el sistema local. La salida en formato JSON puede ser activada/desactivada usando la opción --json= o -j.

seat-status [NOMBRE...]

Muestra información concisa del estado en tiempo de ejecución sobre uno o más asientos. Acepta uno o más nombres de asiento como parámetros. Si no se pasan nombres de asiento, se muestra el estado del asiento de la sesión del llamador. Esta función está destinada a generar una salida legible por humanos. Si busca una salida que pueda ser analizada por máquinas, use show-seat en su lugar.

Añadido en la versión 233.

show-seat [NOMBRE...]

Muestra las propiedades de uno o más asientos o del propio gestor. Si no se especifica ningún argumento, se mostrarán las propiedades del gestor. Si se especifica un asiento, se mostrarán las propiedades del asiento. Por defecto, se suprimen las propiedades vacías. Utilice --all para mostrarlas también. Para seleccionar propiedades específicas a mostrar, utilice --property=. Este comando está destinado a ser utilizado siempre que se requiera una salida analizable por máquinas. Utilice seat-status si busca una salida formateada y legible por humanos.

Añadido en la versión 233.

attach NOMBRE DISPOSITIVO...

Adjunta persistentemente uno o más dispositivos a un asiento. Los dispositivos deben especificarse mediante rutas de dispositivo en el sistema de archivos /sys/. Para crear un nuevo asiento, adjunte al menos una tarjeta gráfica a un nombre de asiento previamente no utilizado. Los nombres de asiento solo pueden constar de a–z, A–Z, 0–9, "-" y "_" y deben ir precedidos por "seat". Para eliminar la asignación de un dispositivo a un asiento específico, simplemente reasígnelo a otro asiento o utilice flush-devices.

Añadido en la versión 233.

flush-devices

Elimina todas las asignaciones de dispositivos creadas previamente con attach. Después de esta llamada, solo permanecerán los asientos generados automáticamente y todo el hardware del asiento se les asignará.

terminate-seat NOMBRE...

Termina una sesion. Esto mata todos los procesos de la sesion y desasigna todos los recursos adjuntos a la sesion. Si el argumento se especifica como una cadena vacía, se termina la sesion que invoca el comando.

Añadido en la versión 233.

OPCIONES

Las siguientes opciones están disponibles:

--json=

Generar salida en formato JSON. Las opciones válidas son never, auto, always. El valor predeterminado es auto, que genera JSON solo cuando la salida va a una terminal.

Añadido en la versión 233.

--property=

Selecciona propiedades específicas a mostrar. Si no se especifica, se muestran todas las propiedades. Las propiedades válidas para las sesiones son: State=, Timestamp=, TTY=, Service=, UID=, User=, Seat=, Desktop=, Display=, RemoteHost=, RemoteAddress=, AuthUserID=, IconName=, ProductName=, KeyboardLayout=, IdleHint=, InactiveHint=, StoppingHint=, ServiceMode=, Scope=, Slice=, CIAS=, CID=, Listener=. Las propiedades válidas para los usuarios son: UID=, GID=, Name=, Timestamp=, Seat=, TTY=, Display=, Service=, Desktop=, State=, IdleHint=, InactiveHint=, StoppingHint=, ServiceMode=, Scope=, Slice=, CIAS=, CID=, Listener=. Las propiedades válidas para los asientos son: SeatID=, Active=, Sessions=, DefaultSession=, IdleHint=, InactiveHint=, StoppingHint=, ServiceMode=, Scope=, Slice=, CIAS=, CID=, Listener=.

Añadido en la versión 233.

--all

Muestra todas las propiedades, incluidas las vacías. Esto es útil para la introspección programática.

Añadido en la versión 233.

--kill-whom=

Selecciona qué proceso(s) de la sesión deben ser matados. Las opciones válidas son all, main, user. Predeterminado es all.

Añadido en la versión 233.

--signal=

Selecciona qué señal se debe enviar. La señal se puede especificar por nombre o por número. La señal predeterminada es SIGTERM.

Añadido en la versión 233.

-H, --host

Opera en un host remoto.

-M, --machine

Opera en una máquina local con un ID de máquina especificado.

-q, --quiet

Suprime la información de salida. Útil para la comprobación de errores. Los códigos de salida indican el éxito (0) o el fallo (un valor distinto de cero).

--no-pager

No se utiliza ningún paginador. Por defecto, la salida se pagina si se envía a una terminal.

Añadido en la versión 233.

-h, --help

Muestra un mensaje de ayuda y sale.

--version

Muestra la información de la versión y sale.

--user

Operar como un usuario especificado. Permite al usuario llamar a las operaciones de loginctl sin privilegios de root, siempre que la operación esté permitida para ese usuario y que el usuario pueda acceder a la comunicación de dbus de systemd-logind.

Añadido en la versión 244.

--global

Conmutar el ajuste global del gestor de inactividad. Las operaciones que solo afectan al gestor de inactividad global (por ejemplo, lock-sessions, unlock-sessions, flush-devices) pueden ser invocadas sin argumentos de sesión/usuario/asiento.

Añadido en la versión 246.

EJEMPLOS

Mostrar todas las sesiones actuales:

$ loginctl list-sessions

$ loginctl list-users

$ loginctl list-seats

Mostrar información detallada sobre la sesión 0:

$ loginctl show-session 0

$ loginctl show-user root

$ loginctl show-seat seat0

Terminar la sesión del usuario actual:

$ loginctl terminate-session self

$ loginctl terminate-user

$ loginctl terminate-seat seat0

Bloquear todas las sesiones en ejecución:

$ loginctl lock-sessions

Habilitar la persistencia para el usuario auxiliar:

$ loginctl enable-linger auxuser

Adjuntar un dispositivo a un asiento específico:

$ loginctl attach seat1 /sys/bus/pci/devices/0000:01:00.0

$SYSTEMD_PAGERSECURE

Los comandos de paginación comunes como less(1), además de la "paginación", es decir, el desplazamiento a través de la salida, admiten la apertura o escritura en otros archivos y la ejecución de comandos arbitrarios de shell. Cuando los comandos se invocan con privilegios elevados, por ejemplo bajo sudo(8) o pkexec(1), el paginador se convierte en un límite de seguridad. Se debe tener cuidado de que solo se utilicen programas con funcionalidad estrictamente limitada como paginadores, y no se permitan características interactivas no deseadas como la apertura o creación de nuevos archivos o el inicio de subprocesos. El "modo seguro" para el paginador puede habilitarse como se describe a continuación, si el paginador lo admite (la mayoría de los paginadores no están escritos de manera que tengan esto en cuenta). Se recomienda habilitar explícitamente el "modo seguro" o deshabilitar completamente el paginador usando --no-pager o PAGER=cat al permitir que usuarios no confiables ejecuten comandos con privilegios elevados.

Esta opción toma un argumento booleano. Cuando se establece en true, el "modo seguro" del paginador está habilitado. En "modo seguro", se establecerá LESSSECURE=1 al invocar el paginador, lo que indica al paginador que deshabilite los comandos que abren o crean nuevos archivos o inician nuevos subprocesos. Actualmente, solo less(1) entiende esta variable e implementa el "modo seguro".

Cuando se establece en false, no se aplica ninguna limitación al paginador. Establecer SYSTEMD_PAGERSECURE=0 o no eliminarlo del entorno heredado puede permitir al usuario invocar comandos arbitrarios.

Cuando no se establece $SYSTEMD_PAGERSECURE, las herramientas de systemd intentan determinar automáticamente si se debe habilitar el "modo seguro" y si el paginador lo admite. El "modo seguro" se habilita si el UID efectivo no es el mismo que el propietario de la sesión de inicio de sesión, consulte geteuid(2) y sd_pid_get_owner_uid(3), o cuando se ejecuta bajo sudo(8) o herramientas similares (se establece $SUDO_UID [1]). En esos casos, se establecerá SYSTEMD_PAGERSECURE=1 y no se utilizarán en absoluto los paginadores que no se sepa que implementan el "modo seguro". Tenga en cuenta que esta autodetección solo cubre los mecanismos más comunes para elevar privilegios y está destinada a ser una conveniencia. Se recomienda establecer explícitamente $SYSTEMD_PAGERSECURE o deshabilitar el paginador.

Tenga en cuenta que si las variables $SYSTEMD_PAGER o $PAGER van a ser tenidas en cuenta, aparte de para deshabilitar el paginador, también debe establecerse $SYSTEMD_PAGERSECURE.

$SYSTEMD_COLORS

Toma un argumento booleano. Cuando es true, systemd y las utilidades relacionadas usarán colores en su salida, de lo contrario, la salida será monocromática. Adicionalmente, la variable puede tomar uno de los siguientes valores especiales: "16", "256" para restringir el uso de colores a los 16 o 256 colores ANSI base, respectivamente. Esto puede especificarse para anular la decisión automática basada en $TERM y a qué está conectada la consola.

$SYSTEMD_URLIFY

El valor debe ser booleano. Controla si se deben generar enlaces clickables en la salida para los emuladores de terminal que lo admitan. Esto puede especificarse para anular la decisión que systemd toma basándose en $TERM y otras condiciones.
