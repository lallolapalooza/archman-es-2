LOGIN(1) Comandos de usuario LOGIN(1)

NOMBRE

login - iniciar sesión en el sistema

SINOPSIS

login [-p] [-h host] [-H] [-f nombredeusuario|nombredeusuario]

DESCRIPCIÓN

login se utiliza al iniciar sesión en un sistema. Si no se proporciona ningún argumento, login solicita el nombre de usuario.

Luego, se le solicita al usuario una contraseña, cuando sea apropiado. El eco se desactiva para evitar revelar la contraseña. Solo se permite un número de fallos de contraseña antes de que login salga y se cierre el enlace de comunicación. Consulte LOGIN_RETRIES en la sección ELEMENTOS DEL ARCHIVO DE CONFIGURACIÓN.

Si el envejecimiento de contraseñas se ha habilitado para la cuenta, es posible que se le solicite al usuario una nueva contraseña antes de continuar. En ese caso, se debe proporcionar la contraseña anterior y introducir la nueva contraseña antes de continuar. Consulte passwd(1) para más información.

Los ID de usuario y grupo se establecerán según sus valores en el archivo /etc/passwd. Hay una excepción si el ID de usuario es cero. En ese caso, solo se establece el ID de grupo principal de la cuenta. Esto debería permitir que el administrador del sistema inicie sesión incluso en caso de problemas de red. Los valores de las variables de entorno para $HOME, $USER, $SHELL, $PATH, $LOGNAME y $MAIL se establecen según los campos correspondientes en la entrada de contraseña. $PATH por defecto es /usr/local/bin:/bin:/usr/bin para usuarios normales, y /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin para root, si no está configurado de otra manera.

La variable de entorno $TERM se conservará si existe, de lo contrario se inicializará al tipo de terminal en su tty. Otras variables de entorno se conservan si se proporciona la opción -p.

Las variables de entorno definidas por PAM siempre se conservan.

Luego se inicia el shell del usuario. Si no se especifica ningún shell para el usuario en /etc/passwd, se utiliza /bin/sh. Si el shell especificado contiene un espacio, se trata como un script de shell. Si no hay un directorio de inicio especificado en /etc/passwd, se utiliza /, seguido de la verificación de .hushlogin como se describe a continuación.

Si el archivo .hushlogin existe, se realiza un inicio de sesión "silencioso". Esto deshabilita la verificación del correo y la impresión de la hora del último inicio de sesión y el mensaje del día. De lo contrario, si existe /var/log/lastlog, se imprime la hora del último inicio de sesión y se registra el inicio de sesión actual.

OPCIONES

-p

Utilizado por getty(8) para indicar a login que conserve el entorno. Consulte también el elemento de archivo de configuración LOGIN_ENV_SAFELIST.

-f

Se utiliza para omitir la autenticación de inicio de sesión. Esta opción generalmente la utiliza la función de inicio de sesión automático de getty(8).

-h

Utilizado por otros servidores (como telnetd(8)) para pasar el nombre del host remoto a login para que pueda colocarse en utmp y wtmp. Solo al superusuario se le permite usar esta opción.

Tenga en cuenta que la opción -h tiene un impacto en el nombre del servicio PAM. El nombre de servicio estándar es login, pero con la opción -h, el nombre es remote. Es necesario crear los archivos de configuración PAM adecuados (por ejemplo, /etc/pam.d/login y /etc/pam.d/remote).

-H

Utilizado por otros servidores (por ejemplo, telnetd(8)) para indicar a login que se suprima la impresión del nombre de host en el mensaje de inicio de sesión. Consulte también LOGIN_PLAIN_PROMPT a continuación.

-h, --help

Muestra el texto de ayuda y sale.

-V, --version

Muestra la versión y sale.

ELEMENTOS DEL ARCHIVO DE CONFIGURACIÓN

login lee el archivo de configuración /etc/login.defs (consulte login.defs(5)). Tenga en cuenta que el archivo de configuración podría distribuirse con otro paquete (generalmente shadow-utils). Los siguientes elementos de configuración son relevantes para login:

MOTD_FILE (cadena)

Especifica una lista delimitada por ":" de archivos y directorios de "mensaje del día" que se mostrarán al iniciar sesión. Si la ruta especificada es un directorio, muestra todos los archivos con la extensión de archivo .motd en orden de versión desde el directorio.

El valor por defecto es /usr/share/misc/motd:/run/motd:/etc/motd. Si el elemento MOTD_FILE está vacío o si se habilita un inicio de sesión silencioso, no se mostrará el mensaje del día. Tenga en cuenta que la misma funcionalidad también la proporciona el módulo PAM pam_motd(8).

Los directorios en MOTD_FILE son compatibles desde la versión 2.36.

Tenga en cuenta que login no implementa ningún comportamiento de anulación de nombres de archivo como pam_motd (consulte también MOTD_FIRSTONLY), pero se muestra todo el contenido de todos los archivos. Se recomienda mantener la lógica adicional en los generadores de contenido y usar /run/motd.d en lugar de depender del comportamiento de anulación codificado en herramientas del sistema.

MOTD_FIRSTONLY (booleano)

Obliga a login a detener la visualización del contenido especificado por MOTD_FILE después del primer elemento accesible de la lista. Tenga en cuenta que un directorio es un elemento en este caso. Esta opción permite configurar la semántica de login para que sea más compatible con pam_motd. El valor por defecto es no.

LOGIN_ENV_SAFELIST (cadena)

Obliga a login a proteger las variables de entorno especificadas si no se usa -p. El valor de cadena es una lista de nombres de variables separadas por comas. Por ejemplo: "LANG,LC_MESSAGES,LC_COLLATE". La lista segura se ignora para las variables de entorno HOME, SHELL y USER.

LOGIN_PLAIN_PROMPT (booleano)

Indica a login que se suprima la impresión del nombre de host en el mensaje de inicio de sesión. Esta es una alternativa a la opción de línea de comandos -H. El valor por defecto es no.

LOGIN_TIMEOUT (número)

Tiempo máximo en segundos para el inicio de sesión. El valor por defecto es 60.

LOGIN_RETRIES (número)

Número máximo de reintentos de inicio de sesión en caso de contraseña incorrecta. El valor por defecto es 3.

LOGIN_KEEP_USERNAME (booleano)

Indica a login que solo vuelva a solicitar la contraseña si la autenticación falló, pero el nombre de usuario es válido. El valor por defecto es no.

FAIL_DELAY (número)

Retraso en segundos antes de permitir otros tres intentos después de un fallo de inicio de sesión. El valor por defecto es 5.

TTYPERM (cadena)

Los permisos del terminal. El valor por defecto es 0600 o 0620 si se utiliza el grupo tty. Consulte también mesg(1).

TTYGROUP (cadena)

El tty de inicio de sesión pertenecerá al TTYGROUP. El valor por defecto es tty. Si TTYGROUP no existe, la propiedad del terminal se establece en el grupo principal del usuario.

TTYGROUP puede ser el nombre de un grupo o un identificador numérico de grupo. Consulte también mesg(1).

HUSHLOGIN_FILE (cadena)

Si se define, este archivo puede inhibir todo el parloteo habitual durante la secuencia de inicio de sesión. Si se especifica una ruta absoluta (por ejemplo, /etc/hushlogins), el modo silencioso se habilitará si el nombre o el shell del usuario se encuentran en el archivo. Si este archivo global de inicio de sesión silencioso está vacío, el modo silencioso se habilitará para todos los usuarios.

Si no se especifica una ruta absoluta, el modo silencioso se habilitará si el archivo existe en el directorio de inicio del usuario.

El valor por defecto es verificar /etc/hushlogins y si no existe, luego ~/.hushlogin.

Si el elemento HUSHLOGIN_FILE está vacío, todas las verificaciones se deshabilitan.

DEFAULT_HOME (booleano)

CONFIG FILE ITEMS

The login utility supports configuration via items in the login.defs(5) configuration file. The known items are:

ALWAYS_இருID (boolean)

If set to yes, the user will be able to login even if the UID is unknown to the system. The default value is no.

CHDIR_SU_USER (boolean)

Indicate if login is allowed if we cannot change directory to the home directory. If set to yes, the user will login in the root (/) directory if it is not possible to change directory to their home. The default value is yes.

LASTLOG_UID_MAX (unsigned number)

Highest user ID number for which the lastlog entries should be updated. As higher user IDs are usually tracked by remote user identity and authentication services there is no need to create a huge sparse lastlog file for them. No LASTLOG_UID_MAX option present in the configuration means that there is no user ID limit for writing lastlog entries. The default value is ULONG_MAX.

LOG_UNKFAIL_ENAB (boolean)

Enable display of unknown usernames when login failures are recorded. The default value is no.

Note that logging unknown usernames may be a security issue if a user enters their password instead of their login name.

ENV_PATH (string)

If set, it will be used to define the PATH environment variable when a regular user logs in. The default value is /usr/local/bin:/bin:/usr/bin.

ENV_ROOTPATH (string), ENV_SUPATH (string)

If set, it will be used to define the PATH environment variable when the superuser logs in. ENV_ROOTPATH takes precedence. The default value is /usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin.

Archivos

/var/run/utmp, /var/log/wtmp, /var/log/lastlog, /var/spool/mail/*, /etc/motd, /etc/passwd, /etc/nologin, /etc/pam.d/login, /etc/pam.d/remote, /etc/hushlogins, $HOME/.hushlogin

CREDENTIALS

login supports configuration via systemd credentials (see https://systemd.io/CREDENTIALS/). login reads the following systemd credentials:

login.noauth (boolean)

If set, configures login to skip login authentication, similarly to the -f option.

BUGS

The undocumented BSD -r option is not supported. This may be required by some rlogind(8) programs.

A recursive login, as used to be possible in the good old days, no longer works; for most purposes su(1) is a satisfactory substitute. Indeed, for security reasons, login does a vhangup(2) system call to remove any possible listening processes on the tty. This is to avoid password sniffing. If one uses the command login, then the surrounding shell gets killed by vhangup(2) because it’s no longer the true owner of the tty. This can be avoided by using exec login in a top-level shell or xterm.
