NOMBRE

localectl - Controla la configuración de la localización y el diseño del teclado del sistema

SINOPSIS

localectl [OPCIONES...] {COMANDO}

DESCRIPCIÓN

localectl se puede usar para consultar y cambiar la configuración de la localización y el diseño del teclado del sistema. Se comunica con systemd-localed(8) para modificar archivos como /etc/locale.conf y /etc/vconsole.conf.

La localización del sistema controla la configuración del idioma de los servicios del sistema y de la interfaz de usuario antes de que el usuario inicie sesión, como el gestor de pantalla, así como el valor predeterminado para los usuarios después de iniciar sesión.

La configuración del teclado controla el diseño del teclado utilizado en la consola de texto y en la interfaz de usuario gráfica antes de que el usuario inicie sesión, como el gestor de pantalla, así como el valor predeterminado para los usuarios después de iniciar sesión.

Tenga en cuenta que los cambios realizados con esta herramienta podrían requerir la reconstrucción del initrd para que surtan efecto durante el arranque temprano del sistema. localectl no reconstruye el initrd automáticamente, esta tarea debe realizarse manualmente, generalmente reinstalando el paquete del kernel de la distribución.

Tenga en cuenta que systemd-firstboot(1) puede usarse para inicializar la localización del sistema para imágenes de sistema montadas (pero no arrancadas).

COMANDOS

Se entienden los siguientes comandos:

status

Muestra la configuración actual de la localización y el mapa del teclado del sistema. Si no se especifica ningún comando, este es el predeterminado implícito.

Añadido en la versión 195.

set-locale LOCALE, set-locale VARIABLE=LOCALE...

Establece la localización del sistema. Acepta una localización como "en_US.UTF-8", o una o más asignaciones de localización como "LANG=de_DE.utf8", "LC_MESSAGES=en_GB.utf8", y así sucesivamente. Si se proporciona una localización sin nombre de variable, entonces se establecerá la variable de localización "LANG=". Consulte locale(7) para obtener detalles sobre la configuración disponible y sus significados. Use list-locales para obtener una lista de las localizaciones disponibles (ver más abajo).

Añadido en la versión 195.

list-locales

Lista las localizaciones disponibles útiles para la configuración con set-locale.

Añadido en la versión 195.

set-keymap MAP [TOGGLEMAP]

Establece el mapa del teclado del sistema para la consola y X11. Acepta un nombre de mapa (como "de" o "us"), y posiblemente un segundo para definir un mapa de teclado de alternancia. A menos que se pase --no-convert, la configuración seleccionada también se aplicará como el mapa del teclado predeterminado de X11 del sistema, después de convertirlo al mapa del teclado de X11 que más se acerque. Use list-keymaps para obtener una lista de los mapas de teclado disponibles (ver más abajo).

Añadido en la versión 195.

list-keymaps

Lista los mapas de teclado disponibles para la consola, útiles para la configuración con set-keymap.

Añadido en la versión 195.

set-x11-keymap LAYOUT [MODEL [VARIANT [OPTIONS]]]

Establece el mapa del teclado predeterminado del sistema para X11 y la consola virtual. Acepta un nombre de mapa de teclado (como "de" o "us"), y posiblemente un modelo, variante y opciones, consulte kbd(4) para obtener detalles. A menos que se pase --no-convert, la configuración seleccionada también se aplicará como el mapa del teclado de la consola del sistema, después de convertirlo al mapa del teclado de la consola que más se acerque.

Añadido en la versión 195.

list-x11-keymap-models, list-x11-keymap-layouts, list-x11-keymap-variants [LAYOUT], list-x11-keymap-options

Lista los modelos, diseños, variantes y opciones de mapa de teclado de X11 disponibles, útiles para la configuración con set-keymap. El comando list-x11-keymap-variants toma opcionalmente un parámetro de diseño para limitar la salida a las variantes adecuadas para el diseño específico.

Añadido en la versión 201.

OPCIONES

Se entienden las siguientes opciones:

-l, --full

No trunca la salida.

Añadido en la versión 257.

--no-convert

Si se invoca set-keymap o set-x11-keymap y se pasa esta opción, el mapa de teclado no se convertirá de la consola a X11, o de X11 a la consola, respectivamente.

Añadido en la versión 195.

-H, --host=

Ejecuta la operación de forma remota. Especifique un nombre de host, o un nombre de usuario y un nombre de host separados por "@", para conectarse. El nombre de host puede ir opcionalmente seguido de un puerto en el que SSH esté escuchando, separado por ":", y luego un nombre de contenedor, separado por "/", lo que se conecta directamente a un contenedor específico en el host especificado. Esto utilizará SSH para hablar con la instancia remota del gestor de máquinas. Los nombres de contenedores se pueden enumerar con machinectl -H HOST. Ponga las direcciones IPv6 entre corchetes.

-M, --machine=

Ejecuta la operación en un contenedor local. Especifique un nombre de contenedor al que conectarse, opcionalmente precedido por un nombre de usuario para conectarse y un carácter separador "@". Si se utiliza la cadena especial ".host" en lugar del nombre del contenedor, se establece una conexión con el sistema local (lo que es útil para conectarse al bus de usuario de un usuario específico: "--user --machine=lennart@.host"). Si no se utiliza la sintaxis "@", la conexión se realiza como usuario root. Si se utiliza la sintaxis "@", se puede omitir el lado izquierdo o el derecho (pero no ambos) en cuyo caso se implican el nombre de usuario local y ".host".

--no-ask-password

No consulte al usuario para autenticación para operaciones privilegiadas.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una cadena corta de versión y sale.

--no-pager

No redirigir la salida a un paginador.

CÓDIGO DE SALIDA

En caso de éxito, se devuelve 0, en caso contrario, un código de error distinto de cero.

ENTORNO

$SYSTEMD_LOG_LEVEL

El nivel máximo de registro de los mensajes emitidos (los mensajes con un nivel de registro más alto, es decir, menos importantes, se suprimirán). Acepta una lista separada por comas de valores. Un valor puede ser uno de (en orden de importancia decreciente) emerg, alert, crit, err, warning, notice, info, debug, o un entero en el rango 0...7. Consulte syslog(3) para obtener más información. Cada valor puede ir opcionalmente prefijado por uno de console, syslog, kmsg o journal seguido de dos puntos para establecer el nivel máximo de registro para ese destino de registro específico (por ejemplo, SYSTEMD_LOG_LEVEL=debug,console:info especifica registrar en nivel debug excepto cuando se registra en la consola, que debería ser en nivel info). Tenga en cuenta que el nivel máximo de registro global tiene prioridad sobre cualquier nivel máximo de registro por destino.

$SYSTEMD_LOG_COLOR

Un booleano. Si es verdadero, los mensajes escritos en el tty se colorearán según la prioridad.

Esta configuración solo es útil cuando los mensajes se escriben directamente en la terminal, porque journalctl(1) y otras herramientas que muestran registros colorearán los mensajes basándose en el nivel de registro por sí mismas.

$SYSTEMD_LOG_TIME

Un booleano. Si es verdadero, los mensajes de registro de la consola irán precedidos de una marca de tiempo.

Esta configuración solo es útil cuando los mensajes se escriben directamente en la terminal o en un archivo, porque journalctl(1) y otras herramientas que muestran registros adjuntarán marcas de tiempo basándose en los metadatos de la entrada por sí mismas.

ENTORNO

$SYSTEMD_LOG_LEVEL

El nivel mínimo de registro para mostrar. Los niveles válidos son debug, info, notice, warning, err, crit, alert, emerg. Si no está configurado, se usa el nivel predeterminado 'notice'.

$SYSTEMD_LOG_COLOR

Un booleano. Si es verdadero, los mensajes se colorearán en la terminal.

$SYSTEMD_LOG_LOCATION

Un booleano. Si es verdadero, los mensajes se antepondrán con el nombre de archivo y el número de línea en el código fuente de donde se origina el mensaje.

Tenga en cuenta que la ubicación del registro a menudo se adjunta como metadatos a las entradas del diario de todos modos. Incluirlo directamente en el texto del mensaje puede ser conveniente al depurar programas.

$SYSTEMD_LOG_TID

Un booleano. Si es verdadero, los mensajes se antepondrán con el ID de hilo (TID) numérico actual.

Tenga en cuenta que esta información se adjunta como metadatos a las entradas del diario de todos modos. Incluirlo directamente en el texto del mensaje puede ser conveniente al depurar programas.

$SYSTEMD_LOG_TARGET

El destino de los mensajes de registro. Uno de console (registra en el tty adjunto), console-prefixed (registra en el tty adjunto pero con prefijos que codifican el nivel de registro y la "instalación", ver syslog(3), kmsg (registra en el búfer de registro circular del kernel), journal (registra en el diario), journal-or-kmsg (registra en el diario si está disponible, y en kmsg de lo contrario), auto (determina el destino de registro apropiado automáticamente, el predeterminado), null (deshabilita la salida de registro).

$SYSTEMD_LOG_RATELIMIT_KMSG

Si se debe limitar la tasa de kmsg o no. Toma un booleano. El valor predeterminado es "true". Si está deshabilitado, systemd no limitará la tasa de mensajes escritos en kmsg.

$SYSTEMD_PAGER, $PAGER

Paginador a usar cuando no se proporciona --no-pager. $SYSTEMD_PAGER se usa si está configurado; de lo contrario, se usa $PAGER. Si no están configurados ni $SYSTEMD_PAGER ni $PAGER, se prueban una serie de implementaciones de paginadores conocidas en orden, incluyendo less(1) y more(1), hasta que se encuentra uno. Si no se descubre ninguna implementación de paginador, no se invoca ningún paginador. Configurar estas variables de entorno a una cadena vacía o al valor "cat" es equivalente a pasar --no-pager.

Nota: si $SYSTEMD_PAGERSECURE no está configurado, $SYSTEMD_PAGER y $PAGER solo se pueden usar para deshabilitar el paginador (con "cat" o ""), y de lo contrario se ignoran.

$SYSTEMD_LESS

Anula las opciones pasadas a less (por defecto "FRSXMK").

Los usuarios pueden querer cambiar dos opciones en particular:

K

Esta opción instruye al paginador a salir inmediatamente cuando se presiona Ctrl+C. Para permitir que less maneje Ctrl+C por sí mismo para volver al prompt del comando del paginador, desconfigure esta opción.

Si el valor de $SYSTEMD_LESS no incluye "K", y el paginador que se invoca es less, Ctrl+C será ignorado por el ejecutable y deberá ser manejado por el paginador.

X

Esta opción instruye al paginador a no enviar cadenas de inicialización y desinicialización de termcap al terminal. Está configurada por defecto para permitir que la salida del comando permanezca visible en el terminal incluso después de que el paginador salga. Sin embargo, esto evita que funcione cierta funcionalidad del paginador, en particular, la salida paginada no se puede desplazar con el ratón.

Tenga en cuenta que la configuración de la variable de entorno regular $LESS no tiene efecto para las invocaciones de less por parte de las herramientas de systemd.

Ver less(1) para más discusión.

$SYSTEMD_LESSCHARSET

Anula el conjunto de caracteres pasado a less (por defecto "utf-8", si se determina que la terminal que llama es compatible con UTF-8).

Tenga en cuenta que la configuración de la variable de entorno regular $LESSCHARSET no tiene efecto para las invocaciones de less por parte de las herramientas de systemd.

$SYSTEMD_PAGERSECURE

Los comandos de paginador comunes como less(1), además de la "paginación", es decir, desplazarse por la salida, soportan la apertura o escritura de otros archivos y la ejecución de comandos arbitrarios del shell. Cuando los comandos se invocan con privilegios elevados, por ejemplo, bajo sudo(8) o pkexec(1), el paginador se convierte en un límite de seguridad. Se debe tener cuidado de que solo se utilicen programas con funcionalidad estrictamente limitada como paginadores, y no se permitan funciones interactivas no deseadas como la apertura o creación de nuevos archivos o el inicio de subprocesos. El "modo seguro" para el paginador puede habilitarse como se describe a continuación, si el paginador lo soporta (la mayoría de los paginadores no están escritos de manera que tengan esto en cuenta). Se recomienda explicitamente habilitar el "modo seguro" o deshabilitar completamente el paginador usando --no-pager o PAGER=cat cuando se permite a usuarios no confiables ejecutar comandos con privilegios elevados.

Esta opción toma un argumento booleano. Cuando se configura en verdadero, se habilita el "modo seguro" del paginador. En "modo seguro", se establecerá LESSSECURE=1 al invocar el paginador, lo que instruye al paginador a deshabilitar comandos que abran o creen nuevos archivos o inicien nuevos subprocesos. Actualmente, solo se sabe que less(1) entiende esta variable e implementa el "modo seguro".

Cuando se configura en falso, no se impone ninguna limitación al paginador. Establecer SYSTEMD_PAGERSECURE=0 o no eliminarlo del entorno heredado puede permitir al usuario invocar comandos arbitrarios.

Cuando $SYSTEMD_PAGERSECURE no está configurado, las herramientas de systemd intentan determinar automáticamente si se debe habilitar el "modo seguro" y si el paginador lo soporta. El "modo seguro" se habilita si el UID efectivo no es el mismo que el propietario de la sesión de inicio de sesión, ver geteuid(2) y sd_pid_get_owner_uid(3), o cuando se ejecuta bajo sudo(8) o herramientas similares ($SUDO_UID está configurado [1]). En esos casos, se establecerá SYSTEMD_PAGERSECURE=1 y los paginadores que no se sabe que implementan el "modo seguro" no se utilizarán en absoluto. Tenga en cuenta que esta autodetección solo cubre los mecanismos más comunes para elevar privilegios y está destinada a ser una conveniencia. Se recomienda configurar explícitamente $SYSTEMD_PAGERSECURE o deshabilitar el paginador.

Tenga en cuenta que si las variables $SYSTEMD_PAGER o $PAGER deben ser honradas, aparte de deshabilitar el paginador, también debe estar configurado $SYSTEMD_PAGERSECURE.

$SYSTEMD_COLORS

Toma un argumento booleano. Cuando es verdadero, systemd y las utilidades relacionadas usarán colores en su salida, de lo contrario, la salida será monocromática. Además, la variable puede tomar uno de los siguientes valores especiales: "16", "256" para restringir el uso de colores a los 16 o 256 colores ANSI base, respectivamente. Esto se puede especificar para anular la decisión automática basada en $TERM y a qué está conectada la consola.

$SYSTEMD_URLIFY

El valor debe ser un booleano. Controla si se deben generar enlaces clickables en la salida para los emuladores de terminal que soportan esto. Esto se puede especificar para anular la decisión que toma systemd basada en $TERM y otras condiciones.
