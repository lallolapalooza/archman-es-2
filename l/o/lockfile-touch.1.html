lockfile-progs(1) Programas de lockfile lockfile-progs(1)

NOMBRE

lockfile-progs - programas de línea de comandos para bloquear y desbloquear archivos y buzones de correo de forma segura (a través de liblockfile).

SINOPSIS

mail-lock [--use-pid] [--retry retry-count]
mail-unlock
mail-touchlock [--oneshot]
lockfile-create [--use-pid] [--retry retry-count] [--lock-name] nombre_archivo
lockfile-remove [--lock-name] nombre_archivo
lockfile-touch [--oneshot] [--lock-name] nombre_archivo
lockfile-check [--use-pid] [--lock-name] nombre_archivo

DESCRIPCIÓN

Lockfile-progs proporciona un conjunto de programas que se pueden utilizar para bloquear y desbloquear buzones de correo y archivos de forma segura (a través de liblockfile):

mail-lock - bloquea el buzón del usuario actual
mail-unlock - desbloquea el buzón del usuario actual
mail-touchlock - actualiza el bloqueo en el buzón del usuario actual
lockfile-create - bloquea un archivo dado
lockfile-remove - elimina el bloqueo de un archivo dado
lockfile-touch - actualiza el bloqueo de un archivo dado
lockfile-check - verifica el bloqueo de un archivo dado

Por defecto, el argumento nombre_archivo se refiere al nombre del archivo que se va a bloquear, y el nombre del archivo de bloqueo será nombre_archivo.lock. Sin embargo, si se especifica el argumento --lock-name, entonces nombre_archivo se tomará como el nombre del propio archivo de bloqueo.

Cada uno de los comandos de bloqueo de correo intenta bloquear /var/spool/mail/<usuario>, donde <usuario> es el nombre asociado con el ID de usuario efectivo, según lo determinado por geteuid(2).

Una vez que un archivo está bloqueado, el bloqueo debe ser actualizado al menos una vez cada cinco minutos o el bloqueo se considerará obsoleto, y los intentos de bloqueo posteriores tendrán éxito. Consulte también la opción --use-pid y la página del manual de lockfile_create(3).

El comando lockfile-check comprueba si ya existe un bloqueo válido.

OPCIONES

-q, --quiet

Suprime cualquier salida. El éxito o el fracaso solo se indicarán mediante el estado de salida.

-v, --verbose

Habilita la salida de diagnóstico.

-l, --lock-name

No añada .lock al nombre_archivo. Esta opción se aplica a lockfile-create, lockfile-remove, lockfile-touch o lockfile-check.

-p, --use-pid

Escribe el ID del proceso padre (PPID) en el archivo de bloqueo cada vez que se crea un archivo de bloqueo, y utiliza ese PID al verificar la validez de un bloqueo. Consulte la página del manual de lockfile_create(3) para más información. Esta opción se aplica a lockfile-create y lockfile-check. NOTA: esta opción no funcionará correctamente entre máquinas que comparten un sistema de archivos.

-o, --oneshot

Actualiza el bloqueo y sale inmediatamente. Esta opción se aplica a lockfile-touch y mail-touchlock. Cuando no se proporciona, estos comandos se ejecutarán de forma continua, actualizando el bloqueo una vez por minuto hasta que se detengan.

-r num_intentos, --retry num_intentos

Intenta bloquear nombre_archivo num_intentos veces antes de rendirse. Cada intento se retrasará un poco más que el anterior (en incrementos de 5 segundos) hasta alcanzar un retraso máximo de un minuto entre reintentos. Si num_intentos no se especifica, el valor predeterminado es 9, lo que dará como resultado un abandono después de 225 segundos si fallan los 9 intentos de bloqueo.

EJEMPLOS

Bloqueo de un archivo durante un proceso largo:


lockfile-create /algún/archivo
lockfile-touch /algún/archivo &
# Guarda el PID del proceso lockfile-touch
BADGER="$!"
hace-algo-importante-con /algún/archivo
kill "${BADGER}"
lockfile-remove /algún/archivo

ESTADO DE SALIDA

0

Para lockfile-check, esto indica que existe un bloqueo válido, de lo contrario, simplemente indica una ejecución exitosa del programa.

No es 0

Para lockfile-check, un estado de salida distinto de cero indica que el bloqueo especificado no existe o no es válido. Para otros programas, indica que se encontró algún problema.
