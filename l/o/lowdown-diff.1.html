LOWDOWN-DIFF(1) Manual general de comandos LOWDOWN-DIFF(1)

NOMBRE

lowdown-diff — ver diferencias en archivos markdown

SINOPSIS

lowdown-diff [opciones_entrada] [opciones_salida] [-s] [-M metadatos] [-m metadatos] [-o archivo] [-t modo] archivo_antiguo [archivo_nuevo]

DESCRIPCIÓN

Muestra las diferencias entre documentos lowdown(5) como salida formateada. Los resultados se escriben en la salida estándar.

Los argumentos cortos son los siguientes:

-s
Produce un documento independiente (por ejemplo, un documento HTML válido que incluye tipo de documento, cabecera, etc.) alrededor del contenido formateado. Consulte Documentos independientes para obtener detalles.
-M metadatos
Proporciona un par clave-valor de metadatos. Esto puede estar en la sintaxis normal o como pares separados por un signo igual, dependiendo de qué carácter (dos puntos o signo igual) aparezca primero. Sale con un error si no se proporciona ninguno. Esto anula -m y lo que se analiza desde el documento. Consulte Metadatos.
-m metadatos
Similar a -M, pero anulado por lo que se analiza del documento, luego por -M.
-o archivo
Envía la salida al archivo a menos que sea “-”, en cuyo caso vuelve a la salida estándar por defecto.
-t modo, -T modo
El modo de salida. Puede ser html para salida HTML5, latex para LaTeX, gemini para el formato "gemtext" de Gemini, ms para salida roff usando el paquete clásico (es decir, sin extensión) -ms y necesitando soporte de tablas, term para salida de terminal compatible con ANSI UTF-8, man para salida roff usando el paquete clásico -man, tree, para mostrar el árbol de análisis del documento de entrada, y null para analizar el documento pero no renderizar nada. Consulte Medios de salida. La forma -T modo se mantiene por compatibilidad con versiones anteriores.
archivo_antiguo, archivo_nuevo
Documentos Markdown utilizados para la comparación. Si archivo_nuevo no se proporciona o es “-”, se lee de la entrada estándar.

Las siguientes son opciones largas para el análisis de entrada. Estas afectan al árbol de análisis que se pasa a todas las salidas.

--parse-hilite
Habilita el soporte para resaltado de tramos. Estos están deshabilitados por defecto porque pueden ser interpretados erróneamente como encabezados de sección.
--parse-math
Reconoce ecuaciones matemáticas.
--parse-maxdepth=depth
La profundidad máxima de elementos anidados. Por defecto es 128, lo que probablemente sea más que suficiente para cualquier documento del mundo real. Si se alcanza el máximo, el sistema sale como si la memoria se hubiera agotado. Establecer a cero para no tener máximo.
--parse-no-autolink
No analiza enlaces o fragmentos de enlaces http, https, ftp, mailto, ni relativos.
--parse-no-cmark
No analiza con las restricciones de CommonMark. Esto también deshabilita el uso del primer valor de la lista ordenada en lugar de empezar todas las listas en uno.
--parse-no-codeindent
No analiza contenido indentado como bloques de código.
--parse-no-callouts
No analiza indicadores (“admoniciones”) GFM/MDN.
--parse-no-deflists
No analiza listas de definición extendidas de PHP.
--parse-no-ext-attrs
No analiza atributos extendidos extendidos de PHP.
--parse-no-fenced
No analiza bloques de código cercados (específicos del lenguaje) de GFM.
--parse-no-footnotes
No analiza notas al pie de página MMD.
--parse-no-img-ext
Obsoleto. Consulte --parse-no-ext-attrs.
--parse-no-intraemph
No analiza énfasis dentro de palabras y enlaces.
--parse-no-mantitle
No analiza el título, sección, fuente y volumen de la página de manual a partir de los metadatos de título de Pandoc. Los títulos de las páginas de manual se indican con un título seguido de un paréntesis abierto, un dígito seguido de caracteres opcionales, y luego un paréntesis cerrado.
--parse-no-metadata
No analiza metadatos. Esto no afecta a los metadatos proporcionados en -m o -M.
--parse-no-strike
No analiza tachados.
--parse-no-super
No analiza superíndices ni subíndices en absoluto.
--parse-no-tables
No analiza tablas GFM.
--parse-no-tasklists
No analiza listas de tareas GFM.
--parse-super-short
Si el análisis de superíndices está habilitado, utiliza la sintaxis tradicional "corta" no GFM.

Hay muchas opciones largas de salida. Las siguientes son compartidas por todos los medios de salida:

--out-standalone
Alias de -s.
--out-no-smarty
No utiliza el filtro de tipografía inteligente. Por defecto, ciertas secuencias de caracteres se traducen a glifos específicos de la salida.
--template plantilla
Al producir salida independiente -s, utiliza un archivo de plantilla. Consulte Plantillas. Actualmente solo para -tgemini, -thtml, -tlatex, -tman, -tms, y -ttree.

Lo que sigue son opciones largas por salida. Para HTML con -thtml, estas son las siguientes:

--html-callout-mdn
Utiliza el modo de indicadores MDN para Indicadores.
--html-callout-github
Utiliza el modo de indicadores GitHub para Indicadores.
--html-data-markup
Incluye atributos data- con las etiquetas de las estructuras de los documentos.
--html-escape-only
Solo escapa caracteres de HTML. No genera etiquetas HTML.
--html-no-attributes
No genera atributos de las etiquetas HTML.
--html-no-styles
No incluye estilos CSS en la salida.
--html-skip-html
Omite bloques de código HTML/XML.
--html-skip-images
Omite imágenes.
--html-skip-links
Omite enlaces.
--html-toc
Genera una tabla de contenidos.

Para LaTeX con -tlatex:

--latex-no-header
No incluye el comando documentclass.
--latex-no-metadata
No incluye los comandos title, date, y author.
--latex-no-title
No incluye el comando title.

Para roff con -tman o -tms:

--roff-no-header
No incluye los encabezados TH, TL, o AU.
--roff-no-metadata
No incluye los metadatos del documento como argumentos para TH, TL, y AU.
--roff-no-title
No incluye el título del documento como argumento para TH.

Documentos independientes

Cuando se le solicita un documento independiente con -s, lowdown-diff envuelve la salida en un documento HTML, LaTeX o Gemini válido. Esto se hace para facilitar su uso en los flujos de trabajo de documentación. Los documentos independientes están construidos alrededor de una plantilla.

La plantilla se puede proporcionar con la opción --template.

El comportamiento exacto es dependiente del medio de salida, pero generalmente se incluyen las siguientes secciones:

Preamble
Esto incluye la declaración DOCTYPE para HTML, el comando documentclass para LaTeX, o el encabezado de nivel 1 de Gemini.
Head
Para HTML, esto incluye la etiqueta <head>. La información de metadatos del documento se utiliza para las etiquetas <title> y <meta>. Para Gemini, esto incluye el título y la descripción.
Body
El contenido real del documento formateado.
Foot
Para HTML, esto incluye el cierre de la etiqueta <body> y </html>. Para Gemini, esto incluye un enlace de retorno.

Metadatos

Los metadatos son pares clave-valor que proporcionan información sobre el documento. Estos pueden ser colocados en la cabecera del documento markdown en forma de bloques de código YAML, o pueden ser proporcionados en la línea de comandos con las opciones -m o -M.

Los metadatos proporcionados en la línea de comandos anulan los metadatos del documento.

Las claves de metadatos comunes incluyen:

title
El título del documento.
author
El autor del documento.
date
La fecha de publicación del documento.

Algunos formatos de salida utilizan metadatos específicos. Por ejemplo, la salida man utiliza los metadatos man-name, man-section, man-source, y man-volume para generar los encabezados de la página de manual.

Medios de salida

El argumento -t o -T especifica el medio de salida:

html
Salida HTML5.
latex
Salida LaTeX.
gemini
Salida Gemini (gemtext).
ms
Salida roff usando el paquete -ms.
term
Salida de terminal compatible con ANSI UTF-8.
man
Salida roff usando el paquete -man.
tree
Muestra el árbol de análisis del documento de entrada.
null
Analiza el documento pero no genera ninguna salida.

Plantillas

Las plantillas se utilizan para generar documentos independientes. Permiten personalizar la estructura y el estilo de la salida.

Actualmente, las plantillas son compatibles con los medios de salida html, latex, gemini, man, ms, y tree.

La sintaxis de las plantillas es específica del medio de salida. Consulte la documentación de lowdown para obtener más detalles.

Indicadores

Los indicadores, también conocidos como admoniciones, se utilizan para resaltar bloques de texto importantes, como notas, advertencias o consejos. lowdown-diff admite dos estilos de indicadores:

mdn
Este estilo se basa en la documentación de MDN Web Docs y utiliza la sintaxis de bloques de código cercados con un prefijo de indicador (por ejemplo, !!! note).
github
Este estilo es similar al utilizado en GitHub y también se basa en bloques de código cercados con un prefijo de indicador (por ejemplo, !!! note).

Puede especificar el estilo de indicador deseado utilizando las opciones de línea de comandos --html-callout-mdn o --html-callout-github cuando la salida es HTML.

EJEMPLOS

Mostrar diferencias HTML entre doc1.md y doc2.md:

lowdown-diff -t html doc1.md doc2.md

Mostrar diferencias en la terminal, produciendo un documento independiente:

lowdown-diff -s -t term doc1.md doc2.md

Analizar un documento pero no generar salida, usando CommonMark y soportando tablas:

lowdown-diff -t null --parse-cmark --parse-tables doc.md

SYNOPSIS

mandoc -L language -O output-option ... -f file ... -I path ... -m input ... -M input ... -o output -p phase -s -t output-type -U output-option ...

DESCRIPTION

The mandoc utility reads input files, parses them using mdoc(7) conventions, and formats them using one of several output types. It can also be used to convert between different formats.

The utility is designed to be used as a front-end to the groff(1) typesetting system, but is extensible to other formats. Unless the -s flag is used, the output is always a fragment, to be included in a larger document.

The command line arguments are parsed according to the following order: -L, -O, -f, -I, -m, -M, -o, -p, -s, and finally -U.

The -f, -I, -m, -M, -o, -p, and -U flags may appear more than once, with subsequent occurrences overriding earlier ones. The -L and -O flags may also appear more than once, with subsequent occurrences adding to the list of language and output options, respectively.

Input files are read in the order specified. If no input files are given, standard input is read.

The -o and -O flags take arguments that are processed in the order supplied. The -m and -M flags take arguments that are processed in the order supplied.

The -U flag is processed last. This allows it to override settings made by earlier flags.

The -t flag determines the output type. The following output types are supported:

-tascii
Plain ASCII output. Does not support equations or images. Uses basic formatting.
-tcss
CSS. This is not really a standalone document type but rather a format for customising the appearance of HTML output. The CSS code is output as is, enclosed in <style> </style> tags.
-tdoc
A dialect of SGML used for documenting the Linux kernel. Only basic formatting and structure are supported.
-tdzr
The dzr format, used by the troff compiler dznroff(1). This format is mostly equivalent to the -tps output, but it is not processed by PostScript processors.
-thtml
HTML output. This is the default output type. UTF-8 encoding is used. Images are inlined using base64 encoding. Equations are rendered using mathjax.
-tjson
JSON output. This is a plain JSON representation of the parsed document. It is not syntax-checked in any way.
-tlatex
LaTeX output. This format requires the amsmath, graphicx, and inputenc (with utf8 option) packages for full functionality. Images are handled using the graphicx package.
-tman
The standard Unix manual page format, suitable for processing by groff(1), mandoc(1), or other troff(1) implementations. This is the default format for manual pages. Table support is provided by tbl(1). Does not support equations or images.
-tms
The ms macro package, also suitable for processing by groff(1) or troff(1). This format has limited support for images (encapsulated PostScript only) and does not support equations. Table support is provided by tbl(1).
-tps
PostScript output, suitable for printing or viewing with a PostScript viewer. This is the default format for PostScript output. Images are included directly. Equations are rendered using groff's built-in math macros.
-txml
XML output. This is a generic XML representation of the document, using the <mandoc-output> root element. It is not syntax-checked in any way.

The -o and -O flags take arguments that specify output options. The available options are dependant on the output type. Common options include:

-oindent=N
Set the indentation level for the specified output type. This is only meaningful for output types that support indentation, such as -txml.
-Ofragment
Output a fragment of a document, not a complete, self-contained document.
-Oencoding=encoding
Specify the output encoding. Default is UTF-8.
-Olanguage=language
Specify the language for the document. This affects things like date formats and plurals.
-Ooutput=file
Write the output to the specified file instead of standard output.
-Opage-margin=N
Set the page margin to N points. Only applicable to PostScript and LaTeX output.
-Osection-margin=N
Set the section margin to N points. Only applicable to PostScript and LaTeX output.
-Oshort-desc
Include a short description of the command in the output. Only relevant for manual page output.

The -f flag allows specifying custom CSS files for HTML output. The files are processed in the order given.

The -I flag adds directories to the search path for input files, such as included man pages.

The -m and -M flags allow specifying input metadata. Metadata is merged, with -M taking precedence over document content and -m.

The -p flag specifies a phase of processing to stop at. This is mainly useful for debugging.

The -s flag formats the output as a standalone document, including necessary boilerplate and headers.

The -U flag allows specifying output options that override earlier settings. This is useful for fine-tuning the output format.

The -L flag specifies the language of the document, which affects localization and formatting of certain elements.

The --help and --version flags display help information and version details, respectively.

OPTIONS

-f file
Use file as an input file. If no input files are specified, mandoc reads from the standard input.
-I path
Add path to the search path for included files. This is used for finding manual pages and other documentation files.
-L language
Use language as the document language. This affects localization and formatting of certain elements.
-m input
Prepend input to the list of input files. This can be used to provide metadata or other configuration information.
-M input
Prepend input to the list of input files, with higher precedence than -m. This is useful for overriding default metadata.
-o output-option
Specify an output option. The available options depend on the output type selected with -t.
-O output-option
Specify an output option that overrides earlier settings. The available options depend on the output type selected with -t.
-p phase
Stop processing after the specified phase. This is useful for debugging.
-s
Format the output as a standalone document. This includes necessary boilerplate, headers, and footers.
-t output-type
Specify the output type. Supported types include ascii, css, doc, dzr, html, json, latex, man, ms, ps, and xml. Defaults to html.
-U output-option
Specify an output option that overrides all previous settings. This provides the highest level of control over the output format.

EXAMPLES

Format a man page as HTML:

mandoc -t html myfile.man

Format a man page as PostScript:

mandoc -t ps myfile.man

Format a man page as a standalone HTML document:

mandoc -s -t html myfile.man

Format a man page as standalone HTML with a custom CSS file:

mandoc -s -t html -f style.css myfile.man

Format a man page as XML:

mandoc -t xml myfile.man

Format a man page as XML with indentation:

mandoc -t xml -o indent=2 myfile.man

STANDALONE DOCUMENTS

When the -s flag is specified, mandoc generates a complete, self-contained document. The exact content of the boilerplate varies depending on the output type.

For -thtml, this includes a DOCTYPE declaration, the <html> tag, a <head> section containing meta tags for character set and viewport, and optional meta tags for author, copyright, date, CSS files, and JavaScript files. The document title is taken from the first .TH macro's first argument.

For -tlatex, this includes a \documentclass command, \usepackage commands for required packages, and \begin{document} and \end{document} commands. Metadata like author, date, and title are used to populate corresponding LaTeX commands.

For -tman and -tms, this includes the necessary prologue macros for the respective formatting systems.

For -txml, the standalone document includes the <mandoc-output> root element and optionally XML declaration and DTD.

For -tjson, the entire output is enclosed in a JSON object, typically with a single key representing the document content.

The content of the standalone document can be influenced by metadata specified using the -m and -M flags, as well as metadata embedded within the input files themselves (e.g., using .meta directives).

Differences

The utility can be used to compare two versions of a document and highlight the differences. When comparing documents, the following output types are supported:

-tfodt
“Flat” Differences are rendered using document tracking.
-tgemini
Differences are not rendered.
-thtml
Differences are rendered using HTML. Insertions are typically shown in green and deletions in red. This format is not fixed.
-tlatex
Differences are rendered by colouring in blue (insert) and red (delete) (this format is not fixed).
-tman
Differences are rendered by colouring in blue (insert) and red (delete) (this format is not fixed).
-tms
Differences are rendered by colouring in blue (insert) and red (delete) (this format is not fixed).
-tterm
Differences are rendered by background-colouring in blue (insert) and red (delete) (this format is not fixed).
-ttree
Differences are manually in the tree output.

Differences in content metadata use the following rule: deleted metadata key-value pairs are not processed in the output, so only inserted or retained metadata are processed.

Metadata

Metadata keys are canonicalised and de-deduplicated in the following order: -m (overridden by document content and -M), the prologue of the document itself, then -M (overriding document content and -m).

After de-duplication, metadata is serialised into document variables and/or standalone -s output.

When not using --template, the following metadata keys are used in the default -s template:

affiliation
Author affiliation (organisation or institution). Multiple affiliations may be separated by two or more spaces (including newlines). Used in -thtml, -tlatex, and -tms.
author
Document author. Multiple authors may be separated by two or more spaces (including newlines). Overridden by rcsauthor. Used in -tfodt, -thtml, -tlatex, -tms, and -tterm.
baseheaderlevel
Added to each header level. Deprecated in favour of shiftheadinglevelby.
copyright

NAME

lowdown-diff – Compare differences between Markdown documents

SYNOPSIS

lowdown-diff [-ccolour] [-oout] [-ttype] [-dfile] [-s] [file ...]

DESCRIPTION

The lowdown-diff utility accepts two Markdown files, old.md and new.md, and compares them for differences. It accepts the same output formatting lowdown(1) options as the -ttype, -s, and -o options. The differences are rendered in the specified type of output. The default type is term, for colourised terminal output.

The following formatting directives may be applied after the files are specified. Note that these are applied in the order listed, and the list is reset for each new file specified. If no directives are given, then no processing is done to the files.

bold
Bold all list items.
italic
Italicise all list items.
escaped
Escape initial roff delimiters and those after newlines. This is used for the -tman output type.
escaperoff
Escape all roff delimiters. This is used for the -tman output type. The option -e is a synonym.
join
Join a list into a singleton list using two spaces as a join delimiter.
lowercase
Lowercase all list items.
split
Split list items on sequences of two or more white-space tokens (space, newline, tab). This is usually invoked on a singleton, but may be repeatedly invoked on a pre-split list. Invokes trim prior to the first split. The resulting list has no items that are only white-space.
trim
Trim white-space from the beginning and end of all list items. If an item has no non-white-space, it is discarded.
uppercase
Uppercase all list items.

ENVIRONMENT

NO_COLOR
Do not emit colours when in -tterm mode. Synonym for NO_COLOUR. Same as --term-nocolour.

FILES

share/html/default.html
The default template used if --template is not provided to -thtml.
share/latex/default.latex
The default template used if --template is not provided to -tlatex.
share/man/default.man
The default template used if --template is not provided to -tman.
share/man/default.ms
The default template used if --template is not provided to -tms.
share/odt/styles.xml
Default styles used when generating standalone -tfodt documents. Template for --odt-style styles.

EXIT STATUS

The lowdown-diff utility exits 0 on success, and >0 if an error occurs.

EXAMPLES

To view Markdown differences on an ANSI-compatible, UTF-8 terminal:

lowdown-diff -tterm old.md new.md | less -R

The terminal may also be used with groff(1) rendering:

lowdown-diff -stms old.md new.md | \
  groff -itk -mspdf -Tutf8 | less -R
lowdown-diff -stman old.md new.md | \
  groff -itk -man -Tutf8 | less -R

To emit a standalone HTML5 document:

lowdown-diff -s old.md new.md > foo.html

To use groff(1) to format as a PS file:

lowdown-diff -stms old.md new.md | \
  groff -itk -mspdf > foo.ps

Or with LaTeX:

lowdown-diff -stlatex old.md new.md > foo.latex
pslatex foo.latex

PDF generation follows similar logic:

lowdown-diff -stms old.md new.md | \
  pdfroff -itk -mspdf > foo.pdf
lowdown-diff -stlatex old.md new.md > foo.latex
pdflatex foo.latex

UTF-8 support for groff(1) PDF or PS output requires appropriate fonts, such as the Unicode Times font. This and other Unicode fonts are not always installed by default. They may be found, for PDF output, in the devpdf set of the groff(1) font directory and are prefixed with ‘U’.

lowdown-diff -stms old.md new.md | \
  pdfroff -itk -mspdf -FU-T > foo.pdf

CAVEATS

When viewing -tman differences with mandoc(1), the marker colours are not rendered. The -tgemini output also currently has no way of encoding differences.
