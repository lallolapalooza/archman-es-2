LOGGER(1P) Manual del programador POSIX LOGGER(1P)

PROLOG

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

logger — registra mensajes

SINOPSIS

logger cadena...

DESCRIPCIÓN

La utilidad logger guarda un mensaje, de una manera y formato no especificados, que contiene los operandos cadena proporcionados por el usuario. Se espera que los mensajes sean evaluados posteriormente por el personal que realiza tareas de administración del sistema.

Se definirá por la implementación si los mensajes escritos en locales distintos del locale POSIX son efectivos.

OPCIONES

Ninguna.

OPERANDOS

Se admitirá el siguiente operando:

cadena
Uno de los argumentos de cadena cuyos contenidos se concatenan, en el orden especificado, separados por caracteres <espacio> individuales.

STDIN

No utilizado.

ARCHIVOS DE ENTRADA

Ninguno.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán a la ejecución de logger:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están definidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de locale.)
LC_ALL
Si se establece en un valor de cadena no vacío, anula los valores de todas las demás variables de internacionalización.
LC_CTYPE
Determina el locale para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en los argumentos).
LC_MESSAGES

Determina el locale que debe utilizarse para afectar al formato y contenido de los mensajes de diagnóstico escritos en la salida de error estándar. (Esto significa diagnósticos de logger al usuario o aplicación, no mensajes de diagnóstico que el usuario está enviando al administrador del sistema.)
NLSPATH
Determina la ubicación de los catálogos de mensajes para el procesamiento de LC_MESSAGES.

EVENTOS ASÍNCRONOS

Predeterminado.

STDOUT

No utilizado.

STDERR

La salida de error estándar se utilizará solo para mensajes de diagnóstico.

ARCHIVOS DE SALIDA

No especificado.

DESCRIPCIÓN EXTENDIDA

Ninguna.

ESTADO DE SALIDA

Se devolverán los siguientes valores de salida:

 0
Finalización exitosa.
>0

Las siguientes secciones son informativas.

USO DE LA APLICACIÓN

Esta utilidad permite registrar información para su uso posterior por un administrador del sistema o programador para determinar por qué han fallado las utilidades no interactivas. Las ubicaciones de los mensajes guardados, su formato y el período de retención no están especificados. No existe un método para que una aplicación que cumpla con el estándar lea los mensajes una vez escritos.

EJEMPLOS

Una aplicación por lotes, que se ejecuta de forma no interactiva, intenta leer un archivo de configuración y falla; puede intentar notificar al administrador del sistema con:

logger mi_nombre: no se puede leer el archivo foo. [timestamp]

JUSTIFICACIÓN

Los desarrolladores del estándar creían firmemente que era necesario algún método para alertar a los administradores sobre los errores. El ejemplo obvio es una utilidad por lotes, que se ejecuta de forma no interactiva, que no puede leer sus archivos de configuración o que no puede crear o escribir su archivo de resultados. Sin embargo, los desarrolladores del estándar no querían definir el formato o los mecanismos de entrega, ya que históricamente han sido (y probablemente seguirán siendo) muy específicos del sistema, además de involucrar funcionalidades claramente fuera del alcance de este volumen de POSIX.1‐2017.

El texto con LC_MESSAGES sobre mensajes de diagnóstico se refiere a diagnósticos de logger al usuario o aplicación, no a mensajes de diagnóstico que el usuario está enviando al administrador del sistema.

Se permiten múltiples argumentos cadena, similar a echo, para facilitar su uso.

Al igual que las utilidades mailx y lp, se admite que logger es difícil de probar. Esto no se consideró una justificación suficiente para excluir estas utilidades de este volumen de POSIX.1‐2017. También se puede argumentar que, de hecho, son probables, pero que las pruebas en sí mismas no son portátiles.
