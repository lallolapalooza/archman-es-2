LOWDOWN(1) Manual de Comandos Generales LOWDOWN(1)

NOMBRE

lowdown — traductor simple de markdown

SINOPSIS

lowdown [opciones_entrada] [opciones_salida] [-Ls] [-M metadatos] [-m metadatos] [-o archivo] [-t modo] [-X palabra_clave] [archivo]

DESCRIPCIÓN

Traduce desde lowdown(5) a diversos formatos de salida. Los resultados se escriben en la salida estándar.

Los argumentos cortos son los siguientes:

-L
Lista las claves de metadatos, una clave por línea. El modo -t se ignora. Los metadatos se habilitan automáticamente. Anula -X.
-s
Produce un documento autónomo (por ejemplo, un documento HTML válido que incluya tipo de documento, cabecera, etc.) alrededor del contenido formateado. Ver Documentos autónomos para más detalles.
-M metadatos
Proporciona un par clave-valor de metadatos individual. Esto puede estar en la sintaxis normal o como pares separados por un signo de igual, dependiendo de qué carácter (dos puntos o signo de igual) aparezca primero. Sale con error si no se proporciona ninguno. Esto anula -m y lo que se analiza del documento. Ver Metadatos.
-m metadatos
Similar a -M, pero anulado por lo que se analiza del documento, luego por -M.
-o archivo
Envía la salida al archivo a menos que sea “-”, en cuyo caso vuelve al valor predeterminado de salida estándar.
-t modo, -T modo
El modo de salida. Puede ser html para salida HTML5, latex para LaTeX, gemini para el formato “gemtext” de Gemini, ms para salida roff usando el paquete clásico (es decir, sin extensión) -ms y que necesita soporte de tablas, term para salida de terminal compatible con ANSI y UTF-8, man para salida roff usando el paquete clásico -man, tree, para mostrar el árbol de análisis del documento de entrada, y null para analizar el documento pero sin renderizarlo. Ver Medios de salida. La forma -T modo se mantiene por compatibilidad hacia atrás.
-X palabra_clave
Imprime el valor de metadatos de palabra_clave o una cadena vacía si no se encuentra. El modo -t se ignora. Los metadatos se habilitan automáticamente. Anula -L.
archivo
Documento Markdown de entrada. Si no se proporciona o si archivo es “-”, se lee de la entrada estándar.

Las siguientes son opciones largas para el análisis de entrada. Estas afectan al árbol de análisis que se pasa a todas las salidas.

--parse-hilite
Habilita el soporte de spans de resaltado. Estos están deshabilitados por defecto ya que pueden ser interpretados erróneamente como encabezados de sección.
--parse-math
Reconoce ecuaciones matemáticas.
--parse-maxdepth=depth
La profundidad máxima de elementos anidados. Por defecto es 128, lo cual es probablemente más que suficiente para cualquier documento del mundo real. Si se alcanza el máximo, el sistema sale como si la memoria estuviera agotada. Configurar a cero para no tener máximo.
--parse-no-autolink
No analiza enlaces http, https, ftp, mailto, ni enlaces o fragmentos de enlace relativos.
--parse-no-cmark
No analiza con restricciones de CommonMark. Esto también deshabilita el uso del primer valor de lista ordenada en lugar de empezar todas las listas en uno.
--parse-no-codeindent
No analiza contenido indentado como bloques de código.
--parse-no-callouts
No analiza llamadas de atención (GFA/MDN) (“admoniciones”).
--parse-no-deflists
No analiza listas de definición extendidas de PHP.
--parse-no-ext-attrs
No analiza atributos extendidos de PHP.
--parse-no-fenced
No analiza bloques de código delimitados (específicos del lenguaje) de GFM.
--parse-no-footnotes
No analiza notas al pie de MMD.
--parse-no-img-ext
Obsoleto. Ver --parse-no-ext-attrs.
--parse-no-intraemph
No analiza el énfasis dentro de palabras y enlaces.
--parse-no-mantitle
No analiza el título, sección, fuente y volumen de la página man de los metadatos de Pandoc. Los títulos de las páginas man se indican con un título seguido de un paréntesis abierto, un dígito seguido de caracteres opcionales, y luego un paréntesis cerrado.
--parse-no-metadata
No analiza metadatos. Esto no afecta a los metadatos proporcionados en -m o -M.
--parse-no-strike
No analiza tachados.
--parse-no-super
No analiza superíndices ni subíndices en absoluto.
--parse-no-tables
No analiza tablas de GFM.
--parse-no-tasklists
No analiza listas de tareas de GFM.
--parse-super-short
Si el análisis de superíndices está habilitado, usa la sintaxis “corta” tradicional no GFM.

Lo que sigue son opciones largas por salida. Para HTML con -thtml, estas son las siguientes:

--html-callout-mdn, --html-callout-gfm
Genera sintaxis de llamada (callout) MDN o GFM.
--html-hardwrap
Ajusta forzadamente el contenido de los párrafos generando saltos de línea donde sea aplicable.
--html-no-escapehtml
Si se ha especificado --html-no-skiphtml, esto provoca que el HTML incrustado no se escape, sino que se genere tal cual. Esto no tiene efecto si no se ha especificado --html-no-skiphtml.
--html-no-head-ids
No genera atributos id para los encabezados.
--html-no-num-ent
No normaliza las entidades HTML (cuando es posible) como numéricas y en su lugar utiliza las entidades tal como se proporcionan en la entrada.
--html-no-owasp
No sigue las recomendaciones OWASP para escapar texto, y solo realiza el escape mínimo necesario para asegurar que el contenido regular no se interprete como HTML.
--html-no-skiphtml
Genera HTML incrustado. Por defecto, el HTML incrustado no se genera en absoluto. Ver --html-no-escapehtml.
--html-titleblock
Si se parseó alguna información de título (título, autor, fecha), la formatea en un elemento de encabezado que aparece al principio del documento.

Para ambos formatos roff, -tman y -tms (a menos que se indique lo contrario), se aplican los siguientes:

--roff-code-font=fuentes
Anula las fuentes predeterminadas de ancho fijo con una tupla de variantes normal, negrita, cursiva y negrita cursiva en ese orden. Por ejemplo, B,B,BI,BI utiliza negrita (“B”) en lugar de ancho fijo. No especificar una fuente utilizará la predeterminada, al igual que especificar un nombre de fuente de longitud cero. Los alias none, bold y code no establecen fuentes especiales, negrita y ancho fijo predeterminado.
--roff-endnotes
Retrasa la impresión de notas al pie hasta el final del documento. Solo se aplica a -tms, ya que -tman solo admite notas finales.
--roff-no-numbered
No genera encabezados numerados (.NH NN). Solo se aplica a -tms.
--roff-no-skiphtml
Genera HTML incrustado. Esto normalmente no tiene sentido porque el lector de salida no interpretará el HTML. Por defecto, el HTML se omite.
--roff-no-links
No muestra URLs para imágenes y enlaces (los enlaces automáticos todavía se muestran). (El contenido del enlace todavía se muestra). Anula --roff-short-links para imágenes y enlaces. Solo se aplica cuando se especifica --roff-traditional.
--roff-short-links
Acorta las URLs para imágenes, enlaces y enlaces automáticos solo al nombre de dominio y la ruta final. Solo se aplica cuando se especifica --roff-traditional.
--roff-traditional
No utiliza macros de hipervínculos (.pdfhref, .UR, .MT), tablas multipágina (.TS H, .TH), sintaxis de secuencia Unicode (\[uNNNN]), macros de bloque de ejemplo (.EX), encabezados de sección modernos (.NH NN, .SH NN, .pdfhref O NN), ni enlaces intra-documento (.pdfhref L). La salida es compatible con el troff(1) tradicional.

El prefijo de argumento --nroff, como en --nroff-traditional, está obsoleto en favor de --roff.

La salida -tterm tiene lo siguiente:

--term-all-metadata
Si se especifica -s, genera todos los metadatos en lugar de solo el título, autor y fecha.
--term-columns=columnas
El número de columnas en la terminal. Útil para cuando se ejecuta en una tubería (pipe). Por defecto, lo que informa la terminal o 72 si no se está en una terminal.
--term-hmargin=margen
El número de caracteres de margen izquierdo. Por defecto es cero. También puede ser auto para establecer el margen izquierdo en la mitad de las --term-columns restantes después de restar --term-width.
--term-hpadding=relleno
El número de caracteres de relleno izquierdo. Por defecto es cuatro. El relleno consume espacio de --term-width.
--term-no-ansi
No muestra estilos ANSI en absoluto. Esto implica --term-no-colour.
--term-no-colour
No muestra colores ANSI. Esto aún decorará el texto con subrayados, negritas y cursivas, pero no emitirá códigos de color.
--term-no-links
No muestra URLs para imágenes y enlaces (los enlaces automáticos todavía se muestran). (El contenido del enlace todavía se muestra). Anula --term-short-links y --term-no-rellinks.
--term-no-rellinks
No muestra URLs para enlaces relativos. (El contenido del enlace todavía se muestra). Anula --term-short-links.
--term-short-links
Acorta las URLs para imágenes, enlaces y enlaces automáticos solo al nombre de dominio y la ruta final.
--term-vmargin=margen
El número de saltos de línea de margen superior e inferior. Por defecto es cero.
--term-width=ancho
Límite blando en el número de caracteres por línea, incluyendo (--term-hpadding). Esto puede ser excedido por texto literal. Si es cero o no está establecido, por defecto es --term-columns o 80 como máximo. Trunca a --term-columns.

La salida -tgemini tiene varias banderas que controlan la colocación de los enlaces. Por defecto, los enlaces (imágenes, enlaces automáticos y enlaces) se ponen en cola cuando se especifican en línea y luego se generan en una secuencia de bloques después del elemento de bloque más cercano.

--gemini-link-end
Genera la cola de enlaces al final del documento en lugar de después del elemento de bloque más cercano.
--gemini-link-inline
Renderiza todos los enlaces dentro del flujo del texto. Esto causará problemas cuando haya enlaces anidados, como imágenes dentro de enlaces, enlaces en citas de bloque, etc. No debe usarse a menos que sea en documentos cuidadosamente elaborados.
--gemini-link-noref
No formatea las etiquetas de los enlaces. Tiene prioridad sobre --gemini-link-roman.
--gemini-link-roman
Al formatear etiquetas de enlaces, utiliza números romanos en minúscula en lugar del sistema hexadecimalvigesimal en minúscula predeterminado (es decir, “a”, “b”, ..., “aa”, “ab”, ...).
--gemini-metadata
Imprime los metadatos como la clave canonizada seguida de dos puntos y luego el valor, cada uno en una línea (los saltos de línea se reemplazan por espacios). El bloque de metadatos se termina con un doble salto de línea. Si no hay metadatos, esto no hace nada.

La salida -tlatex tiene las siguientes opciones:

--latex-no-numbered
No numera las secciones (y subsecciones, etc.).
--latex-no-skiphtml
Genera HTML incrustado. Esto normalmente no tiene sentido porque el lector de salida no interpretará el HTML. Por defecto, el HTML se omite.

La salida -tfodt tiene las siguientes opciones:

--odt-no-ski
phtml
Salida HTML incrustada. Esto normalmente no tiene sentido porque el HTML no será interpretado por el lector de salida. Por defecto, el HTML es omitido.
--odt-style=archivo
Especificar un archivo de estilo OpenDocument, que debe consistir al menos en los elementos XML <office:font-face-decls>, <office:scripts> y <office:styles> en la raíz del documento. Esto no se verifica sintácticamente de ninguna manera.

Medios de salida

Los medios de salida se especifican mediante -t, que por defecto es -thtml.

-tfodt
Salida OpenDocument "plana". Los estilos automáticos (aquellos condicionales al estado del documento) se generan con la salida. Las clases especificadas por atributos extendidos de PHP no se verifican en busca de existencia.
-tgemini
Formato "gemtext" de Gemini.
-thtml
Salida HTML5 con codificación UTF-8.
-tlatex
Salida LaTeX simple. Se requieren los siguientes paquetes: amsmath y amssymb para matemáticas, graphicx para imágenes, inputenc (utf8) para entrada UTF-8, frontend (T1) y textcomp para glifos de salida, lmodern para la fuente Latin Modern, xcolor para la salida del motor de diferencias y hyperref para enlaces.
-tman
El paquete de macros man adecuado para ser leído por groff(1), mandoc(1), Heirloom troff, o el tradicional troff(1). No soporta ecuaciones ni imágenes. El soporte de tablas se proporciona mediante tbl(1). Dado que UTF-8 puede pasarse como valores de entrada, puede ser necesario utilizar preconv(1).
-tms
El paquete de macros ms adecuado para ser leído por groff(1) o el tradicional troff(1). No soporta ecuaciones y tiene soporte limitado para imágenes en postscript encapsulado (sufijos PS y EPS). Las imágenes se formatean siempre como bloques. Las dimensiones de las imágenes y los atributos extendidos se ignoran, aunque las imágenes se reducen si son más grandes que el ancho de texto actual. El soporte de tablas se proporciona mediante tbl(1). Dado que UTF-8 puede pasarse como valores de entrada, puede ser necesario utilizar preconv(1).
-tterm
Salida UTF-8 con escapes ANSI adecuada para leer en la terminal. Imágenes y ecuaciones no soportadas.
-ttree
Salida de depuración. No para uso programático, ya que el formato puede cambiar entre versiones.

Documentos independientes

Cuando se especifica -s, el contenido formateado se serializa en una plantilla de documento autocontenida según lo definido por el tipo de salida.

Si no se establece explícitamente con --template, se produce una plantilla predeterminada de la siguiente manera:

-tfodt
Envoltura <office:document> y prólogo <office:automatic-styles>, <office:master-styles>, y <office:body>.
-thtml
Declaración doctype HTML5 seguida de la envoltura <html> con idioma opcional, luego <head>. En orden, el <head> consta de elementos <meta> de codificación de caracteres y viewport; elementos <meta> opcionales de afiliación de metadatos (creador), autor, derechos de autor y fecha; fuentes CSS opcionales de metadatos; fuentes JavaScript opcionales de metadatos; el <title> posiblemente vacío; luego contenido arbitrario opcional de la cabecera HTML de metadatos.
-tlatex
Declaraciones de prólogo documentclass y usepackage, contenido arbitrario opcional de la cabecera LaTeX de metadatos, luego las declaraciones envolventes begin{document}.
-tman, -tms
Macros de prólogo.
-tterm
Líneas de prólogo.
-ttree
Metadatos y plantilla analizada.

Consulte Metadatos para ver los valores de metadatos utilizados por la plantilla por defecto.

Metadatos

Las claves de metadatos se canonizan y se desduplican en el siguiente orden: -m (anulado por el contenido del documento y -M), el prólogo del propio documento, luego -M (anulando el contenido del documento y -m).

Después de la desduplicación, los metadatos se acceden directamente utilizando -X o -L, o se serializan en variables de documento y/o en la salida independiente -s.

Cuando no se utiliza --template, las siguientes claves de metadatos se utilizan en la plantilla por defecto -s:

affiliation
Afiliación del autor (organización o institución). Múltiples afiliaciones pueden separarse por dos o más espacios (incluyendo saltos de línea). Se utiliza en -thtml, -tlatex, y -tms.
author
Autor del documento. Múltiples autores pueden separarse por dos o más espacios (incluyendo saltos de línea). Anulado por rcsauthor. Se utiliza en -tfodt, -thtml, -tlatex, -tms, y -tterm.
baseheaderlevel
Se añade a cada nivel de encabezado. Obsoleto en favor de shiftheadinglevelby.
copyright
Un derecho de autor del documento (sin la palabra "Copyright"), por ejemplo, "2017, Kristaps Dzonsons". Se utiliza en -tms y -thtml.
css
Un archivo CSS que se emite en la cabecera del documento HTML como una declaración <link rel="stylesheet" href="..." />. Múltiples archivos CSS (en orden) pueden separarse por dos o más espacios (incluyendo saltos de línea) y se emiten en el orden dado. Solo se utiliza en -thtml.
date
Fecha del documento en formato ISO-8601 YYYY-MM-DD. Anulado por rcsdate. Se utiliza en -tfodt, -thtml, -tlatex, -tman, -tms, y -tterm.
htmlheader
Contenido HTML arbitrario emitido en la cabecera del documento HTML inmediatamente antes de cerrar el elemento de cabecera. Solo se utiliza en -thtml y con -s. Estos metadatos no se procesan: se pasan sin cambios a la salida.
javascript
Un archivo JavaScript que se emite en la cabecera del documento HTML como una declaración <script src="..."></script>. Múltiples archivos de script (en orden) pueden separarse por dos o más espacios (incluyendo saltos de línea) y se emiten en el orden dado. Solo se utiliza en -thtml.
lang
Idioma del documento en formato RFC 5646. Solo se utiliza en -thtml.
latexheader
Contenido LaTeX arbitrario emitido en el prólogo del documento inmediatamente antes de begin{document}. Solo se utiliza en -tlatex y con -s. Estos metadatos no se procesan: se pasan sin cambios a la salida.
manheader
Contenido roff arbitrario emitido inmediatamente antes de la macro .TH. Solo

msheader
Contenido arbitrario de roff que se emite inmediatamente antes de la macro .TL. Solo se usa en -tms y con -s. Estos metadatos no se procesan: se pasan sin cambios a la salida.
rcsauthor
Similar a author, pero en formato de autor RCS. Anula author.
rcsdate
Similar a date, pero en formato de fecha RCS. Anula date.
section
Sección de la página man, por defecto “7”. Solo se usa en -tman.
shiftheadinglevelby
Desplaza todos los encabezados por el número dado. Por ejemplo, un valor de 1 hace que los encabezados originalmente en el nivel 1 (“<h1>”) sean de nivel 2 (“<h2>”), mientras que un valor de -1 mueve el nivel 2 al 1. Los niveles no se moverán a menos de 1. Tiene precedencia sobre baseheaderlevel. Si no está configurado o no es un número válido, por defecto es cero. Se usa en -tfodt, -thtml, -tlatex, -tman, y -tms.
source
Origen de la página man (organización que proporciona el manual). Solo se usa en -tman.
volume
Volumen de la página man (describe la sección de la página del manual). Solo se usa en -tman.
title
Título del documento. Se usa en -tfodt, -thtml, -tlatex, -tman, -tms, y -tterm.

Los valores predeterminados, como “7” para la section, no se establecen como valores de metadatos y no aparecerán si la clave de metadatos se utiliza como variable.

Plantillas

Algunos medios de salida aceptan una plantilla (--template) para personalizar la salida independiente (-s). El contenido de entrada analizado se introduce en las plantillas a través de declaraciones de control que admiten condicionales, bucles y secuencias de transformación de variables.

Las declaraciones de control se delimitan como $statement$ o ${statement}. Se puede colocar espacio en blanco arbitrario alrededor de la declaración, que no distingue entre mayúsculas y minúsculas, entre delimitadores coincidentes. Las declaraciones sin un delimitador de cierre se consideran texto opaco.

Las siguientes declaraciones están disponibles:

$$, ${}
Emite un $ literal. Esto puede contener espacio en blanco arbitrario.
$ifdef(expression)$
Declaración condicional. No puede haber espacio en blanco entre ifdef y el paréntesis de apertura. Comienza un bloque que se cierra con else, endif, o el final del archivo. Su contenido se emite solo si expression se evalúa como una cadena no vacía.
$else$
Comienza un bloque que se cierra con endif o el final del archivo. Su contenido se emite solo si la condición de un ifdef anterior se evalúa como una cadena vacía. Un else sin un ifdef anterior no se emite.
$endif$
Cierra un bloque iniciado con ifdef o else. Si no va precedido por una de esas declaraciones, se ignora silenciosamente.
$for(expression)$
Declaración de bucle. No puede haber espacio en blanco entre for y el paréntesis de apertura. Comienza un bloque que se cierra con endfor o el final del archivo. El contenido del bloque se emite repetidamente para cada elemento de lista evaluado a partir de expression. La palabra clave anafórica this se puede usar para acceder a la expresión del bucle actual dentro del bloque.
$expression$
Se reemplaza por el resultado de la evaluación de una expresión de plantilla.

Si una declaración de control termina con dos guiones consecutivos antes del delimitador de cierre, se consume la entrada hasta e incluyendo la siguiente nueva línea o hasta el final del archivo. Esto permite que los medios de salida sensibles a las líneas utilicen declaraciones de control sin líneas en blanco superfluas.

Las expresiones consisten en

initial[([arg]*)]?[.transform[([arg]*)]?]*
,

o un valor inicial que acepta argumentos opcionales seguidos de una serie opcional de transformaciones que aceptan argumentos opcionales. Si una lista de argumentos está vacía o no se proporciona, se evalúa como una lista vacía.

El valor initial es uno de los siguientes:

and(expression[,expression]*)
Una lista no vacía que contiene el valor true si todas las expresiones se evalúan como listas no vacías, de lo contrario, una lista vacía. Una expresión vacía se evalúa como una lista vacía.
"literal string"
Se evalúa como una lista singleton que contiene la cadena. Una cadena vacía se evalúa como una lista vacía. El carácter de comillas dobles puede escaparse, como "foo\"bar".
body
El cuerpo del documento de entrada analizado.
clave de metadatos canonizada
El valor para la clave de metadatos dada, si se encuentra, de lo contrario una lista vacía.
body
El cuerpo del documento de entrada analizado.
meta(key)
Produce el valor de los metadatos para la clave de metadatos canonizada key. Permite claves que también son palabras clave como body o endif.
not(expression)
Una lista no vacía que contiene el valor true si la expresión se evalúa como una lista vacía, de lo contrario, una lista vacía.
or(expression[,expression]*)
Una lista no vacía que contiene el valor true si una expresión se evalúa como listas no vacías, de lo contrario, una lista vacía. Una expresión vacía se evalúa como una lista vacía.
this
El valor del contexto de bucle actual o una lista vacía.

Si una clave de metadatos no se especifica en la entrada, o si el this anafórico no ha sido inicializado por un contexto de bucle, el valor inicial se evalúa como una lista vacía. De lo contrario, el valor es una lista singleton.

Si las transformaciones no son válidas, se transformarán en una lista vacía.

Las siguientes transformaciones están disponibles:

escapegemini, escapegeminiline
Escapa los elementos de la lista para gemini (-tgemini), ya sea para múltiples líneas o comprimidas en una sola línea.
escapehtml, escapehtmlattr, escapehtmlurl
Escapa los elementos de la lista para el contenido del cuerpo de HTML (-thtml), atributos y atributos de URL, respectivamente.
escapelatex
Escapa los elementos de la lista para el contenido del cuerpo de LaTeX (-tlatex).
escaperoff, escaperoffline
Escapa los elementos de la lista para roff (-tms, -tman), ya sea para múltiples líneas o comprimidas en una sola línea. escaperoff también escapa los delimitadores roff iniciales y los que están después de las nuevas líneas.
join
Une una lista en una lista singleton usando dos espacios como delimitador de unión.
lowercase
Convierte todos los elementos de la lista a minúsculas.
split
Divide los elementos de la lista en secuencias de dos o más tokens de espacio en blanco (espacio, nueva línea, tabulación). Esto generalmente se invoca en un singleton, pero puede invocarse repetidamente en una lista pre-dividida. Invoca trim antes de la primera división. La lista resultante no tiene elementos que sean solo espacio en blanco.
trim
Recorta el espacio en blanco del principio y el final de todos los elementos de la lista. Si un elemento no tiene caracteres que no sean de espacio en blanco, se descarta.

NAME

lowdown

a Markdown translator

SYNOPSIS

lowdown

[-CdeFghHIjLMpPQrSstXxZ] [-A string] [-B string] [-H string] [-O string] [-T string] [-b string] [-i file] [-o file] [-r char] [-W flag] [-w level] [file...]

DESCRIPTION

The lowdown utility is a command-line translator for the Markdown document format. It translates the input Markdown files, or standard input if none are specified, to the specified output format. By default, it outputs to standard output.

The output format is specified with the -t flag. The available formats are:

code
Code block.
html
HTML5.
html5
HTML5.
fodt
Flat OpenDocument Text.
latex
LaTeX document.
man
Nroff man(7) macros.
ms
Nroff ms(7) macros.
term
ANSI coloured terminal output.
term5
ANSI coloured terminal output, using the first 16 ANSI colours.
xml
XML.
xhtml
XHTML.
xhtml5
XHTML5.

The -t flag may be followed by a comma-separated list of modifiers:

s
Standalone document. Includes preamble and postamble for self-contained documents (e.g. a full HTML file, not a fragment).
uppercase
Uppercase all list items.

ENVIRONMENT

NO_COLOR
Do not emit colours when in -tterm mode. Synonym for NO_COLOUR. Same as --term-nocolour.

FILES

share/html/default.html
The default template used if --template is not provided to -thtml.
share/latex/default.latex
The default template used if --template is not provided to -tlatex.
share/man/default.man
The default template used if --template is not provided to -tman.
share/man/default.ms
The default template used if --template is not provided to -tms.
share/odt/styles.xml
Default styles used when generating standalone -tfodt documents. Template for --odt-style styles.

EXIT STATUS

The lowdown utility exits 0 on success, and >0 if an error occurs.

If the -X flag is used, lowdown exits with an error if the given keyword is not found.

EXAMPLES

To view a Markdown file on an ANSI-compatible, UTF-8 terminal:

lowdown -tterm foo.md | less -R

The terminal may also be used with groff(1) or mandoc(1) rendering:

lowdown -stms foo.md | groff -itk -mspdf -Tutf8 | less -R
lowdown -stman foo.md | groff -itk -man -Tutf8 | less -R
lowdown -stman foo.md | mandoc | less

To emit a standalone HTML5 document:

lowdown -s foo.md > foo.html

To use groff(1) or mandoc(1) to format as a PS file:

lowdown -stms foo.md | groff -itk -mspdf > foo.ps
lowdown -stman foo.md | mandoc -Tps > foo.ps

Or with LaTeX:

lowdown -stlatex foo.md > foo.latex
pslatex foo.latex

PDF generation follows similar logic:

lowdown -stms foo.md | pdfroff -itk -mspdf > foo.pdf
lowdown -stman foo.md | mandoc -Tpdf > foo.pdf
lowdown -stlatex foo.md > foo.latex
pdflatex foo.latex

UTF-8 support for groff(1) PDF or PS output requires appropriate fonts, such as the Unicode Times font. This and other Unicode fonts are not always installed by default. They may be found, for PDF output, in the devpdf set of the groff(1) font directory and are prefixed with ‘U’.

lowdown -stms foo.md | pdfroff -itk -mspdf -FU-T > foo.pdf

To list all metadata keys, then to extract the “title” metadata value from foo.md:

lowdown -L foo.md
lowdown -X title foo.md
