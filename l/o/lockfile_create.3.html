LOCKFILE_CREATE(3) Manual del programador de Linux LOCKFILE_CREATE(3)

NOMBRE

lockfile_create, lockfile_remove, lockfile_touch, lockfile_check - gestionar archivos de bloqueo

SINOPSIS

#include <lockfile.h>

cc [ flag ... ] archivo ... -llockfile [ biblioteca ]

int lockfile_create( const char *archivo_bloqueo, int intentos_reintento, int flags [, struct lockargs args ] );
int lockfile_remove( const char *archivo_bloqueo );
int lockfile_touch( const char *archivo_bloqueo );
int lockfile_check( const char *archivo_bloqueo, int flags );

DESCRIPCIÓN

Funciones para manejar archivos de bloqueo de forma segura con NFS.

lockfile_create

La función lockfile_create crea un archivo de bloqueo de forma segura con NFS.

Si `flags` se establece en L_PID o L_PPID, `lockfile_create` no solo verificará la existencia de un archivo de bloqueo, sino que también leerá su contenido para ver si contiene un ID de proceso en formato ASCII. Si es así, el archivo de bloqueo solo es válido si ese proceso todavía existe. De lo contrario, un archivo de bloqueo más antiguo que 5 minutos se considera obsoleto.

Al crear un archivo de bloqueo, si L_PID está establecido en `flags`, se escribirá el PID del proceso actual en el archivo de bloqueo. A veces puede ser útil usar el PID del proceso padre en su lugar (por ejemplo, el comando dotlockfile lo usa). En tales casos, puede usar la bandera L_PPID en su lugar.

lockfile_touch

Si el archivo de bloqueo está en un sistema de archivos compartido, podría haber sido creado por un proceso en un host remoto. Por lo tanto, el método L_PID o L_PPID para decidir si un archivo de bloqueo sigue siendo válido u obsoleto es incorrecto y no debe usarse. Si está manteniendo un bloqueo durante más de 5 minutos, una llamada a lockfile_create por otro proceso considerará el bloqueo obsoleto y lo eliminará. Para evitar esto, llame a lockfile_touch para actualizar el archivo de bloqueo a intervalos regulares (cada minuto aproximadamente).

lockfile_check

Esta función verifica si ya existe un archivo de bloqueo válido sin intentar crear uno nuevo.

lockfile_remove

Elimina el archivo de bloqueo.

VALORES DE RETORNO

lockfile_create devuelve uno de los siguientes códigos de estado:

   #define L_SUCCESS   0    /* Archivo de bloqueo creado                      */
   #define L_TMPLOCK   2    /* Error al crear archivo de bloqueo temporal     */
   #define L_TMPWRITE  3    /* No se puede escribir el PID en archivo de bloqueo temporal */
   #define L_MAXTRYS   4    /* Falló después del número máximo de intentos   */
   #define L_ERROR     5    /* Error desconocido; comprueba errno             */
   #define L_ORPHANED  7    /* Llamado con L_PPID pero el padre ya no existe */
   #define L_RMSTALE   8    /* Falló al eliminar el archivo de bloqueo obsoleto */

lockfile_check devuelve 0 si está presente un archivo de bloqueo válido. Si no hay ningún archivo de bloqueo o ninguno válido, se devuelve -1.

lockfile_touch y lockfile_remove devuelven 0 si tienen éxito. En caso de error, se devuelve -1 y se establece `errno` adecuadamente. No es un error llamar a `lockfile_remove()` en un archivo de bloqueo inexistente.

ALGORITMO

El algoritmo que se utiliza para crear un archivo de bloqueo de forma atómica, incluso sobre NFS, es el siguiente:

1
Se crea un archivo único. En formato printf, el nombre del archivo es .lk%05d%x%s. El primer argumento (%05d) es el ID del proceso actual. El segundo argumento (%x) consta de los 4 bits menores del valor devuelto por time(2). El último argumento es el nombre de host del sistema.
2
Luego, el archivo de bloqueo se crea usando link(2). El valor de retorno de link se ignora.
3
Ahora se realiza un `stat` del archivo de bloqueo. Si `stat` falla, se pasa al paso 6.
4
El valor de `stat` del archivo de bloqueo se compara con el del archivo temporal. Si son iguales, hemos obtenido el bloqueo. Se elimina el archivo temporal y se devuelve un valor de 0 (éxito) al llamador.
5
Se verifica si el archivo de bloqueo existente es válido. Si no lo es, se elimina el archivo de bloqueo obsoleto.
6
Antes de reintentar, se duerme durante n segundos. n es inicialmente de 5 segundos, pero después de cada reintento se agregan 5 segundos adicionales hasta un máximo de 60 segundos (un retroceso incremental). Luego se vuelve al paso 2 hasta intentos_reintento veces.

SISTEMAS DE ARCHIVOS REMOTO Y LA CACHÉ DE ATRIBUTOS DEL NÚCLEO

Estas funciones no bloquean un archivo, sino que *generan* un *archivo de bloqueo*. Sin embargo, en muchos casos, como los buzones de correo de Unix, todos los programas involucrados que acceden a los buzones coinciden en que la presencia de <nombre_archivo>.lock significa que <nombre_archivo> está bloqueado.

Si está utilizando lockfile_create para crear un bloqueo en un archivo que reside en un servidor remoto y ya tiene ese archivo abierto, debe vaciar la caché de atributos de NFS después de bloquear. Esto es necesario para evitar el siguiente escenario:

o
abrir /var/mail/USERNAME
o
¡los atributos, como tamaño, inode, etc., ahora están en caché en el núcleo!
o
mientras tanto, otra aplicación remota añade datos a /var/mail/USERNAME
o
obtener bloqueo usando lockfile_create()
o
buscar hasta el final del archivo
o
escribir datos

Ahora, el final del archivo realmente no es el final del archivo: el núcleo almacenó en caché los atributos al abrir, y `st_size` ya no es el final del archivo. Por lo tanto, después de bloquear el archivo, necesita indicarle al núcleo que vacíe la caché de atributos de archivos NFS.

La única forma *portable* de hacer esto son las primitivas de bloqueo de archivos fcntl() de POSIX: bloquear un archivo usando fcntl() tiene el efecto secundario afortunado de invalidar la caché de atributos de archivos NFS del núcleo.

lockfile_create() no puede hacer esto por usted por dos razones. Una, solo crea un archivo de bloqueo, ¡no sabe qué archivo está realmente intentando bloquear! Dos, incluso si pudiera deducir el archivo que está bloqueando a partir del nombre de archivo, al simplemente abrirlo y cerrarlo, invalidaría cualquier bloqueo POSIX existente que el programa ya pudiera tener sobre ese archivo (sí, las semánticas de bloqueo POSIX son una locura!).

Así que, básicamente, lo que necesita hacer es algo como esto:

  fd = open("/var/mail/USUARIO");
  .. código del programa ..
  lockfile_create("/var/mail/USUARIO.lock", x, y);
  /* Invalidar caché de atributos NFS usando bloqueos POSIX */
  if (lockf(fd, F_TLOCK, 0) == 0) lockf(fd, F_ULOCK, 0);

Debe tener cuidado con esto si lo está incluyendo en un programa existente que podría estar utilizando ya bloqueos fcntl(), flock() o lockf()- podría invalidar bloqueos existentes.

También hay una forma no portable. Muchas operaciones NFS devuelven los atributos actualizados y el núcleo de Linux realmente los utiliza para actualizar la caché de atributos. Una de estas operaciones es chmod(2).

Así que, hacer un `stat()` a un archivo y luego un `chmod()` a `st.st_mode` no cambiará realmente el archivo, ni interferirá con ningún bloqueo sobre el archivo, pero invalidará la caché de atributos. El equivalente para usar desde un script de shell sería

  chmod u=u /var/mail/USUARIO

PERMISOS

Si se encuentra en un sistema que tiene un directorio de cola de correo que solo es escribible por un grupo especial (generalmente "mail"), no podrá crear un archivo de bloqueo directamente en el directorio de cola de correo sin permisos especiales.

`lockfile_create` y `lockfile_remove` verifican si el archivo de bloqueo termina en $USERNAME.lock, y si el directorio donde se encuentra el archivo de bloqueo es escribible por grupo
