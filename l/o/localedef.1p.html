LOCALEDEF(1P) Manual del programador POSIX LOCALEDEF(1P)

PROLOGO

Esta página del manual forma parte del Manual del programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual de Linux correspondiente para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

localedef — definir entorno de localización

SINOPSIS

localedef [-c] [-f mapa_caracteres] [-i archivo_fuente] [-u nombre_conjunto_codigos] nombre

DESCRIPCION

La utilidad localedef convertirá las definiciones de origen para categorías de localización en un formato utilizable por las funciones y utilidades cuyo comportamiento operativo está determinado por la configuración de las variables de entorno de localización definidas en el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 7, Localización. Si los usuarios tienen la capacidad de crear nuevas localizaciones, además de las proporcionadas por la implementación, es una decisión de la implementación. Si la constante simbólica POSIX2_LOCALEDEF está definida, el sistema admite la creación de nuevas localizaciones. En los sistemas que cumplen con XSI, la constante simbólica POSIX2_LOCALEDEF estará definida.

La utilidad leerá las definiciones de origen para una o más categorías de localización pertenecientes a la misma localización desde el archivo nombrado en la opción -i (si se especifica) o desde la entrada estándar.

El operando nombre identifica la localización de destino. La utilidad admitirá la creación de localizaciones públicas o de acceso general, así como localizaciones privadas o de acceso restringido. Las implementaciones pueden restringir la capacidad de crear o modificar localizaciones públicas a usuarios con privilegios apropiados.

Cada definición de origen de categoría se identificará por el nombre de la variable de entorno correspondiente y terminará con una declaración END nombre_categoria. Se admitirán las siguientes categorías. Además, la entrada puede contener origen para categorías no definidas por la implementación.

LC_CTYPE
Define la clasificación de caracteres y la conversión de mayúsculas/minúsculas.
LC_COLLATE

Define las reglas de ordenación.
LC_MONETARY

Define el formato y los símbolos utilizados en el formato de la información monetaria.
LC_NUMERIC

Define el delimitador decimal, la agrupación y el símbolo de agrupación para la edición numérica no monetaria.
LC_TIME
Define el formato y el contenido de la información de fecha y hora.
LC_MESSAGES

Define el formato y los valores de las respuestas afirmativas y negativas.

OPCIONES

La utilidad localedef cumplirá con el volumen de Definiciones Base de POSIX.1‐2017, Sección 12.2, Directrices de sintaxis de utilidad.

Se admitirán las siguientes opciones:

-c
Crea una salida permanente incluso si se han emitido mensajes de advertencia.
-f mapa_caracteres
Especifica la ruta de un archivo que contiene un mapeo de símbolos de caracteres y símbolos de elementos de ordenación a codificaciones de caracteres reales. El formato del mapa_caracteres se describe en el volumen de Definiciones Base de POSIX.1‐2017, Sección 6.4, Archivo de descripción del conjunto de caracteres. La aplicación se asegurará de que esta opción se especifique si se utilizan nombres simbólicos (que no sean símbolos de ordenación definidos en una palabra clave collating-symbol). Si la opción -f no está presente, se utilizará un mapeo de caracteres definido por la implementación.
-i archivo_entrada
La ruta de un archivo que contiene las definiciones de origen. Si esta opción no está presente, las definiciones de origen se leerán de la entrada estándar. El formato del archivo_entrada se describe en el volumen de Definiciones Base de POSIX.1‐2017, Sección 7.3, Definición de localización.
-u nombre_conjunto_codigos

Especifica el nombre de un conjunto de códigos utilizado como mapeo de destino de símbolos de caracteres y símbolos de elementos de ordenación cuyos valores de codificación se definen en términos de los valores de constantes de posición del estándar ISO/IEC 10646‐1:2000.

OPERANDOS

Se admitirá el siguiente operando:

nombre
Identifica la localización; consulte el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 7, Localización para obtener una descripción del uso de este nombre. Si el nombre contiene uno o más caracteres <barra>, nombre se interpretará como una ruta donde se almacenarán las definiciones de localización creadas. Si nombre no contiene ninguna <barra>, la interpretación del nombre es una decisión de la implementación y la localización será pública. La capacidad de crear localizaciones públicas de esta manera puede estar restringida a usuarios con privilegios apropiados. (Como consecuencia de especificar un nombre, aunque se pueden procesar varias categorías en una ejecución, solo se pueden procesar las categorías que pertenecen a la misma localización).

ENTRADA ESTÁNDAR

A menos que se especifique la opción -i, la entrada estándar será un archivo de texto que contiene una o más definiciones de origen de categorías de localización, como se describe en el volumen de Definiciones Base de POSIX.1‐2017, Sección 7.3, Definición de localización. Cuando las líneas se continúan usando el mecanismo de carácter de escape, no hay límite para la longitud de la línea continuada acumulada.

ARCHIVOS DE ENTRADA

El archivo de mapeo del conjunto de caracteres especificado como argumento de la opción charmap se describe en el volumen de Definiciones Base de POSIX.1‐2017, Sección 6.4, Archivo de descripción del conjunto de caracteres. Si una definición de origen de categoría de localización contiene una declaración copy, como se define en el volumen de Definiciones Base de POSIX.1‐2017, Capítulo 7, Localización, y la declaración copy nombra una localización válida y existente, entonces localedef se comportará como si la definición de origen hubiera contenido una definición de categoría válida para la localización nombrada.

VARIABLES DE ENTORNO

Las siguientes variables de entorno afectarán a la ejecución de localedef:

LANG
Proporciona un valor predeterminado para las variables de internacionalización que no están establecidas o están vacías. (Consulte el volumen de Definiciones Base de POSIX.1‐2017, Sección 8.2, Variables de internacionalización para conocer la precedencia de las variables de internacionalización utilizadas para determinar los valores de las categorías de localización).
LC_ALL
Si se establece en un valor de cadena no vacío, anulará los valores de todas las demás variables de internacionalización.
LC_COLLATE

(Esta variable no tiene ningún efecto en localedef; la localización POSIX se utiliza para esta categoría).
LC_CTYPE
Determina la localización para la interpretación de secuencias de bytes de datos de texto como caracteres (por ejemplo, caracteres de un solo byte frente a caracteres multibyte en argumentos y archivos de entrada). Esta variable no tiene ningún efecto en el procesamiento de los datos de entrada de localedef; la localización POSIX se utiliza para este propósito, independientemente del valor de esta variable.

Determina la localización que debe utilizarse para afectar el formato y el contenido de los mensajes de diagnóstico escritos en la salida de error estándar.

PROLOG

This section describes the extensions to the localedef utility for the creation of locales.

NAME

localedef - create locale modules

SYNOPSIS

localedef [-c] [-f charmap] [-i locale] [-u code_set_name] name

DESCRIPTION

The localedef utility shall create locale-specific information based on the source files specified by the -f and -i options and the name operand. The name operand specifies the name of the locale to be created.

The source files are processed in the following order:

  1. The file specified by the -f option, if present.

  2. The file specified by the -i option, if present.

  3. The standard input, if neither -f nor -i was specified.

OPTIONS

The following options shall be supported:

-c
Do not create the locale if warnings occurred. This option shall cause the utility to exit with a non-zero status if any warnings were issued during the locale creation process. If this option is not specified, the utility shall create the locale even if warnings occurred.
-f charmap
Specify the pathname of the file containing the character set description. If this option is not specified, the implementation shall use a default character set description file.
-i locale
Specify the pathname of the file containing the locale definition. If this option is not specified, the implementation shall use a default locale definition file.
-u code_set_name
Specify the name of the coded character set to be used for the locale. This option allows the creation of locales for coded character sets not explicitly named in the charmap file.

OPERANDS

The following operand shall be supported:

name
The name of the locale to be created. The format of the name is implementation-defined, but it shall be a valid path name, consisting of only the locale name, or the locale name prefixed by the directory path. If the name contains a <slash>, the implementation shall interpret it as a path name; otherwise, the implementation shall interpret it as a locale name and determine where to install the locale information.

STDIN

The standard input shall be used as the locale definition file if neither the -f nor -i options are specified.

INPUT FILES

The files specified by the -f and -i options are interpreted according to the format described in the Base Definitions volume of POSIX.1‐2017, Section 6.4, Character Set Description File and Section 7.2, Locale Definition Files, respectively.

ENVIRONMENT VARIABLES

The following environment variables shall affect the execution of localedef:

LANG
Provide a default value for the LC_ALL category in order to determine the locale that is used to process the locale definition files when the locale category is not specified.
LC_ALL
Determine the locale that is used to process the locale definition files when the locale category is not specified.
LC_COLLATE
Determine the locale that is used to process the LC_COLLATE category information.
LC_CTYPE
Determine the locale that is used to process the LC_CTYPE category information.
LC_MESSAGES
Determine the locale that is used to process the locale-specific messages.
NLSPATH
Determine the search path for locale-specific message catalog files that are used during the processing of LC_MESSAGES.

ASYNCHRONOUS EVENTS

Default.

STDOUT

The utility shall report all categories successfully processed, in an unspecified format.

STDERR

The standard error shall be used only for diagnostic messages.

OUTPUT FILES

The format of the created output is unspecified. If the name operand does not contain a <slash>, the existence of an output file for the locale is unspecified.

EXTENDED DESCRIPTION

When the -u option is used, the code_set_name option-argument shall be interpreted as an implementation-defined name of a codeset to which the ISO/IEC 10646‐1:2000 standard position constant values shall be converted via an implementation-defined method. Both the ISO/IEC 10646‐1:2000 standard position constant values and other formats (decimal, hexadecimal, or octal) shall be valid as encoding values within the charmap file. The codeset represented by the implementation-defined name can be any codeset that is supported by the implementation.

When conflicts occur between the charmap specification of <code_set_name>, <mb_cur_max>, or <mb_cur_min> and the implementation-defined interpretation of these respective items for the codeset represented by the -u option-argument code_set_name, the result is unspecified.

When conflicts occur between the charmap encoding values specified for symbolic names of characters of the portable character set and the implementation-defined assignment of character encoding values, the result is unspecified.

If a non-printable character in the charmap has a width specified that is not -1, the result will be undefined.

EXIT STATUS

The following exit values shall be returned:

 0
No errors occurred and the locales were successfully created.
 1
Warnings occurred and the locales were successfully created.
 2
The locale specification exceeded implementation limits or the coded character set or sets used were not supported by the implementation, and no locale was created.
 3
The capability to create new locales is not supported by the implementation.
>3
Warnings or errors occurred and no output was created.

CONSEQUENCES OF ERRORS

If an error is detected, no permanent output shall be created.

If warnings occur, permanent output shall be created if the -c option was specified. The following conditions shall cause warning messages to be issued:

*
If a symbolic name not found in the charmap file is used for the descriptions of the LC_CTYPE or LC_COLLATE categories (for other categories, this shall be an error condition).
*
If the number of operands to the order keyword exceeds the {COLL_WEIGHTS_MAX} limit.
*
If optional keywords not supported by the implementation are present in the source.

Other implementation-defined conditions may also cause warnings.

The following sections are informative.

APPLICATION USAGE

The charmap definition is optional, and is contained outside the locale definition. This allows both completely self-defined source files, and generic sources (applicable to more than one codeset). To aid portability, all charmap definitions must use the same symbolic names for the portable character set. As explained in the Base Definitions volume of POSIX.1‐2017, Section 6.4, Character Set Description File, it is implementation-defined whether or not users or applications can provide additional character set description files. Therefore, the -f option might be operable only when an implementation-defined charmap is named.

EXAMPLES

None.

RATIONALE

The output produced by the localedef utility is implementation-defined. The name operand is used to identify the specific locale. (As a consequence, although several categories can be processed in one execution, only categories belonging to the same locale can be processed.)
