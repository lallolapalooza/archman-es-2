loop(4) Manual de Controladores de Dispositivos loop(4)

NOMBRE

loop, loop-control - dispositivos loop

SINOPSIS

#include <linux/loop.h>

DESCRIPCIÓN

El dispositivo loop es un dispositivo de bloque que mapea sus bloques de datos no a un dispositivo físico como un disco duro o una unidad de disco óptico, sino a los bloques de un archivo regular en un sistema de archivos o a otro dispositivo de bloque. Esto puede ser útil, por ejemplo, para proporcionar un dispositivo de bloque para una imagen de sistema de archivos almacenada en un archivo, de modo que pueda ser montado con el comando mount(8). Podrías hacer:


$ dd if=/dev/zero of=file.img bs=1MiB count=10;
$ sudo losetup /dev/loop4 file.img;
$ sudo mkfs -t ext4 /dev/loop4;
$ sudo mkdir /myloopdev;
$ sudo mount /dev/loop4 /myloopdev;

Ver losetup(8) para otro ejemplo.

Se puede especificar una función de transferencia para cada dispositivo loop con fines de cifrado y descifrado.

Las siguientes operaciones de ioctl(2) son proporcionadas por el dispositivo de bloque loop:

LOOP_SET_FD
Asocia el dispositivo loop con el archivo abierto cuyo descriptor de archivo se pasa como el (tercer) argumento de ioctl(2).
LOOP_CLR_FD
Desasocia el dispositivo loop de cualquier descriptor de archivo.
LOOP_SET_STATUS
Establece el estado del dispositivo loop usando el (tercer) argumento de ioctl(2). Este argumento es un puntero a una estructura loop_info, definida en <linux/loop.h> como:

struct loop_info {
    int           lo_number;      /* ioctl r/o */
    dev_t         lo_device;      /* ioctl r/o */
    unsigned long lo_inode;       /* ioctl r/o */
    dev_t         lo_rdevice;     /* ioctl r/o */
    int           lo_offset;
    int           lo_encrypt_type;
    int           lo_encrypt_key_size;  /* ioctl w/o */
    int           lo_flags;       /* ioctl r/w (r/o antes
                                     Linux 2.6.25) */
    char          lo_name[LO_NAME_SIZE];
    unsigned char lo_encrypt_key[LO_KEY_SIZE];
                                  /* ioctl w/o */
    unsigned long lo_init[2];
    char          reserved[4];
};

El tipo de cifrado (lo_encrypt_type) debe ser uno de LO_CRYPT_NONE, LO_CRYPT_XOR, LO_CRYPT_DES, LO_CRYPT_FISH2, LO_CRYPT_BLOW, LO_CRYPT_CAST128, LO_CRYPT_IDEA, LO_CRYPT_DUMMY, LO_CRYPT_SKIPJACK, o (desde Linux 2.6.0) LO_CRYPT_CRYPTOAPI.
El campo lo_flags es una máscara de bits que puede incluir cero o más de los siguientes:
LO_FLAGS_READ_ONLY
El dispositivo loopback es de solo lectura.
LO_FLAGS_AUTOCLEAR (desde Linux 2.6.25)
El dispositivo loopback se autodestruirá al cerrarse por última vez.
LO_FLAGS_PARTSCAN (desde Linux 3.2)
Permite el escaneo automático de particiones.
LO_FLAGS_DIRECT_IO (desde Linux 4.10)
Utiliza el modo de E/S directa para acceder al archivo de respaldo.
Los únicos lo_flags que pueden ser modificados por LOOP_SET_STATUS son LO_FLAGS_AUTOCLEAR y LO_FLAGS_PARTSCAN.
LOOP_GET_STATUS
Obtiene el estado del dispositivo loop. El (tercer) argumento de ioctl(2) debe ser un puntero a una struct loop_info.
LOOP_CHANGE_FD (desde Linux 2.6.5)
Cambia el almacenamiento de respaldo del dispositivo loop al nuevo archivo identificado por el descriptor de archivo proporcionado en el (tercer) argumento de ioctl(2), que es un entero. Esta operación solo es posible si el dispositivo loop es de solo lectura y el nuevo almacenamiento de respaldo tiene el mismo tamaño y tipo que el almacenamiento de respaldo anterior.
LOOP_SET_CAPACITY (desde Linux 2.6.30)
Redimensiona un dispositivo loop activo. Se puede cambiar el tamaño del almacenamiento de respaldo subyacente y luego usar esta operación para que el controlador loop se entere del nuevo tamaño. Esta operación no toma argumentos.
LOOP_SET_DIRECT_IO (desde Linux 4.10)
Establece el modo de E/S directa en el dispositivo loop, para que pueda ser utilizado para abrir el archivo de respaldo. El (tercer) argumento de ioctl(2) es un valor sin signo largo. Un valor distinto de cero representa el modo de E/S directa.
LOOP_SET_BLOCK_SIZE (desde Linux 4.14)
Establece el tamaño del bloque del dispositivo loop. El (tercer) argumento de ioctl(2) es un valor sin signo largo. Este valor debe ser una potencia de dos en el rango [512,pagesize]; de lo contrario, se produce un error EINVAL.
LOOP_CONFIGURE (desde Linux 5.8)
Configura y establece todos los parámetros del dispositivo loop en un solo paso utilizando el (tercer) argumento de ioctl(2). Este argumento es un puntero a una estructura loop_config, definida en <linux/loop.h> como:

struct loop_config {
    __u32               fd;
    __u32               block_size;
    struct loop_info64  info;
    __u64               __reserved[8];
};

Además de hacer lo que LOOP_SET_STATUS puede hacer, LOOP_CONFIGURE también se puede utilizar para lo siguiente:
•
establecer el tamaño de bloque correcto inmediatamente estableciendo loop_config.block_size;
•
solicitar explícitamente el modo de E/S directa estableciendo LO_FLAGS_DIRECT_IO en loop_config.info.lo_flags; y
•
solicitar explícitamente el modo de solo lectura estableciendo LO_FLAGS_READ_ONLY en loop_config.info.lo_flags.

Desde Linux 2.6, existen dos nuevas operaciones de ioctl(2):

LOOP_SET_STATUS64
LOOP_GET_STATUS64
Estas son similares a LOOP_SET_STATUS y LOOP_GET_STATUS descritas anteriormente, pero utilizan la estructura loop_info64, que tiene algunos campos adicionales y un rango mayor para otros campos:

struct loop_info64 {
    uint64_t lo_device;           /* ioctl r/o */
    uint64_t lo_inode;            /* ioctl r/o */
    uint64_t lo_rdevice;          /* ioctl r/o */
    uint64_t lo_offset;
    uint64_t lo_sizelimit;  /* bytes, 0 == max available */
    uint32_t lo_number;           /* ioctl r/o */
    uint32_t lo_encrypt_type;
    uint32_t lo_encrypt_key_size; /* ioctl w/o */
    uint32_t lo_flags; i          /* ioctl r/w (r/o antes
                                     Linux 2.6.25) */
    uint8_t  lo_file_name[LO_NAME_SIZE];
    uint8_t  lo_crypt_name[LO_NAME_SIZE];
    uint8_t  lo_encrypt_key[LO_KEY_SIZE]; /* ioctl w/o */
    uint64_t lo_init[2];
};

/dev/loop-control

Desde Linux 3.1, el kernel proporciona el dispositivo /dev/loop-control, que permite a una aplicación encontrar dinámicamente un dispositivo libre y agregar y eliminar dispositivos loop del sistema. Para realizar estas operaciones, primero se abre /dev/loop-control y luego se utiliza una de las siguientes operaciones de ioctl(2):

LOOP_CTL_GET_FREE
Asigna o encuentra un dispositivo loop libre para usar. En caso de éxito, el número del dispositivo se devuelve como el resultado

loop(4) - Páginas del manual de Linux

NOMBRE

loop - dispositivos de bloque de bucle

DESCRIPCIÓN

Los dispositivos de bucle permiten que un archivo normal se trate como un dispositivo de bloque.

Por ejemplo, puede usar un dispositivo de bucle para montar un archivo de imagen de disco. El archivo de imagen se convierte en el "almacenamiento de respaldo" para el dispositivo de bucle.

El kernel de Linux admite hasta 8 dispositivos de bucle por defecto. Consulte losetup(8) para obtener información sobre cómo aumentar este número.

El dispositivo de control /dev/loop-control permite gestionar dispositivos de bucle.

ioctl

La siguiente operación ioctl(2) se admite en los dispositivos de bucle y en el dispositivo de control /dev/loop-control.

LOOP_CTL_GET_FREE
Devuelve el número de índice del primer dispositivo de bucle libre. Esta operación no requiere ningún argumento para la llamada. En caso de éxito, se devuelve el número de índice como resultado de la llamada.
LOOP_CTL_ADD
Añade un nuevo dispositivo de bucle cuyo número de dispositivo se especifica como un entero largo en el tercer argumento de ioctl(2). En caso de éxito, se devuelve el índice del dispositivo como resultado de la llamada. Si el dispositivo ya está asignado, la llamada falla con el error EEXIST.
LOOP_CTL_REMOVE
Elimina el dispositivo de bucle cuyo número de dispositivo se especifica como un entero largo en el tercer argumento de ioctl(2). En caso de éxito, se devuelve el número de dispositivo como resultado de la llamada. Si el dispositivo está en uso, la llamada falla con el error EBUSY.

ARCHIVOS

/dev/loop*
Los archivos de dispositivo especiales de bloque de bucle.

EJEMPLOS

El siguiente programa utiliza el dispositivo /dev/loop-control para encontrar un dispositivo de bucle libre, abre el dispositivo de bucle, abre un archivo para ser utilizado como almacenamiento subyacente para el dispositivo y luego asocia el dispositivo de bucle con el almacenamiento de respaldo. La siguiente sesión de shell demuestra el uso del programa:


$ dd if=/dev/zero of=file.img bs=1MiB count=10;
10+0 records in
10+0 records out
10485760 bytes (10 MB) copied, 0.00609385 s, 1.7 GB/s
$ sudo ./mnt_loop file.img;
loopname = /dev/loop5

Código fuente del programa

#include <err.h>
#include <fcntl.h>
#include <linux/loop.h>
#include <sys/ioctl.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int loopctlfd, loopfd, backingfile;
    long devnr;
    char loopname[4096];
    if (argc != 2) {
        fprintf(stderr, "Usage: %s backing-file\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    loopctlfd = open("/dev/loop-control", O_RDWR);
    if (loopctlfd == -1)
        err(EXIT_FAILURE, "open: /dev/loop-control");
    devnr = ioctl(loopctlfd, LOOP_CTL_GET_FREE);
    if (devnr == -1)
        err(EXIT_FAILURE, "ioctl-LOOP_CTL_GET_FREE");
    sprintf(loopname, "/dev/loop%ld", devnr);
    printf("loopname = %s\n", loopname);
    loopfd = open(loopname, O_RDWR);
    if (loopfd == -1)
        err(EXIT_FAILURE, "open: loopname");
    backingfile = open(argv[1], O_RDWR);
    if (backingfile == -1)
        err(EXIT_FAILURE, "open: backing-file");
    if (ioctl(loopfd, LOOP_SET_FD, backingfile) == -1)
        err(EXIT_FAILURE, "ioctl-LOOP_SET_FD");
    exit(EXIT_SUCCESS);
}
