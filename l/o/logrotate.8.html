LOGROTATE(8) Manual del Administrador del Sistema LOGROTATE(8)

NOMBRE

logrotate ‐ rota, comprime y envía por correo los registros del sistema

SINOPSIS

logrotate [--force] [--debug] [--state archivo] [--skip-state-lock] [--wait-for-state-lock] [--verbose] [--log archivo] [--mail comando] archivo_config [archivo_config2 ...]

DESCRIPCIÓN

logrotate está diseñado para facilitar la administración de sistemas que generan un gran número de archivos de registro. Permite la rotación, compresión, eliminación y envío por correo automáticos de los archivos de registro. Cada archivo de registro puede ser manejado diaria, semanal, mensual o cuando su tamaño sea demasiado grande.

Normalmente, logrotate se ejecuta como una tarea cron diaria. No modificará un registro más de una vez al día, a menos que el criterio para ese registro se base en el tamaño del registro y logrotate se ejecute más de una vez al día, o a menos que se utilice la opción -f o --force.

Se puede proporcionar cualquier número de archivos de configuración en la línea de comandos. Los archivos de configuración posteriores pueden anular las opciones dadas en archivos anteriores, por lo que el orden en que se listen los archivos de configuración de logrotate es importante. Normalmente, se debe utilizar un único archivo de configuración que incluya cualquier otro archivo de configuración necesario. Consulte a continuación para obtener más información sobre cómo utilizar la directiva include para lograr esto. Si se proporciona un directorio en la línea de comandos, cada archivo de ese directorio se utiliza como archivo de configuración.

Si no se proporcionan argumentos en la línea de comandos, logrotate imprimirá información de versión y derechos de autor, junto con un resumen de uso breve. Si ocurre algún error al rotar los registros, logrotate saldrá con un estado distinto de cero, aunque el archivo de estado se actualizará.

OPCIONES

-f, --force
Indica a logrotate que fuerce la rotación, incluso si no cree que sea necesario. A veces esto es útil después de agregar nuevas entradas a un archivo de configuración de logrotate, o si los archivos de registro antiguos han sido eliminados manualmente, ya que los nuevos archivos se crearán y el registro continuará correctamente.
-d, --debug
Activa el modo de depuración, lo que significa que no se realizan cambios en los registros y el archivo de estado de logrotate no se actualiza. Solo se imprimen mensajes de depuración.
-s, --state archivo_estado
Indica a logrotate que utilice un archivo de estado alternativo. Esto es útil si logrotate se ejecuta como un usuario diferente para varios conjuntos de archivos de registro. Para evitar la ejecución paralela, logrotate por defecto adquiere un bloqueo en el archivo de estado, si no se puede adquirir logrotate saldrá con el valor 3. El archivo de estado por defecto es /var/lib/logrotate.status. Si se proporciona /dev/null como archivo de estado, entonces logrotate no intentará bloquear ni escribir en el archivo de estado.
--skip-state-lock
No bloquear el archivo de estado, por ejemplo, si el bloqueo no es compatible o está prohibido.
--wait-for-state-lock
Espera hasta que el bloqueo en el archivo de estado sea liberado por otro proceso de logrotate. Esta opción puede hacer que logrotate espere indefinidamente. Úselo con precaución.
-v, --verbose
Activa el modo detallado, por ejemplo, para mostrar mensajes durante la rotación.
-l, --log archivo
Indica a logrotate que registre la salida detallada en el archivo de registro. La salida detallada registrada en ese archivo es la misma que al ejecutar logrotate con el interruptor -v. El archivo de registro se sobrescribe en cada ejecución de logrotate.
-m, --mail comando
Indica a logrotate qué comando utilizar al enviar registros por correo. Este comando debe aceptar los siguientes argumentos:
1) el asunto del mensaje dado con '-s subject'
2) el destinatario.
El comando debe leer un mensaje en la entrada estándar y enviarlo por correo al destinatario. El comando de correo por defecto es /usr/bin/mail.
--usage
Imprime un resumen de uso breve.
-?, --help
Imprime el mensaje de ayuda.
--version
Muestra información de la versión.

ARCHIVO DE CONFIGURACIÓN

logrotate lee todo sobre los archivos de registro que debe manejar de la serie de archivos de configuración especificados en la línea de comandos. Cada archivo de configuración puede establecer opciones globales (las definiciones locales anulan las globales y las definiciones posteriores anulan las anteriores) y especificar los archivos de registro a rotar. Las opciones globales no afectan a las directivas de inclusión precedentes. Un archivo de configuración simple se ve así:

# archivo de configuración de ejemplo de logrotate
compress
/var/log/messages {
    rotate 5
    weekly
    postrotate
        /usr/bin/killall -HUP syslogd
    endscript
}
"/var/log/httpd/access.log" /var/log/httpd/error.log {
    rotate 5
    mail recipient@example.org
    size 100k
    sharedscripts
    postrotate
        /usr/bin/killall -HUP httpd
    endscript
}
/var/log/news/* {
    monthly
    rotate 2
    olddir /var/log/news/old
    missingok
    sharedscripts
    postrotate
        kill -HUP $(cat /var/run/inn.pid)
    endscript
    nocompress
}
~/log/*.log {}

Las primeras líneas establecen opciones globales; en el ejemplo, los registros se comprimen después de rotar. Tenga en cuenta que los comentarios pueden aparecer en cualquier lugar del archivo de configuración siempre que el primer carácter que no sea espacio en blanco en la línea sea un #.

Los valores se separan de las directivas por espacios en blanco y/o un signo = opcional. Los números deben especificarse en un formato que strtoul(3) pueda entender.

La siguiente sección del archivo de configuración define cómo manejar el archivo de registro /var/log/messages. El registro pasará por cinco rotaciones semanales antes de ser eliminado. Después de que el archivo de registro se haya rotado (pero antes de que la versión antigua del registro se haya comprimido), se ejecutará el comando /usr/bin/killall -HUP syslogd.

La siguiente sección define los parámetros tanto para /var/log/httpd/access.log como para /var/log/httpd/error.log. Cada uno se rota cada vez que supera los 100 kilobytes de tamaño, y los archivos de registro antiguos se envían por correo (sin comprimir) a recipient@example.org después de pasar por 5 rotaciones, en lugar de ser eliminados. sharedscripts significa que el script postrotate solo se ejecutará una vez para esta sección, no una vez por cada registro que se rote. Tenga en cuenta que los nombres de los archivos de registro pueden ir entre comillas (y que las comillas son necesarias si el nombre contiene espacios). Se aplican las reglas normales de comillas del shell, con los caracteres ', " y \ soportados.

La siguiente sección define los parámetros para todos los archivos en /var/log/news. Cada archivo se rota mensualmente.

La última sección utiliza la expansión de tilde para rotar los archivos de registro en el directorio de inicio del usuario actual. Esto solo está disponible si su biblioteca glob soporta la expansión de tilde. GNU glob soporta esto.

Utilice comodines con precaución. Si especifica *, logrotate rotará todos los archivos, incluidos los rotados anteriormente. Una forma de evitar esto es usar la directiva olddir o un comodín más exacto (como *.log).

Tenga en cuenta que, por defecto, al usar systemd(1), la opción ProtectSystem=full está establecida en el archivo logrotate.service. Esto evita que logrotate modifique los registros en /etc y /usr.

Rotación

rotate contador
Los archivos de registro se rotan contador veces antes de ser eliminados o enviados por correo a la dirección especificada en una directiva mail. Si contador es 0, las versiones antiguas se eliminan en lugar de rotarse. Si contador es -1, los registros antiguos no se eliminan en absoluto, excepto que se ven afectados por maxage (use con precaución, puede desperdiciar rendimiento y espacio en disco). El valor predeterminado es 0.
olddir directorio
Los registros se mueven a directorio para la rotación. El directorio debe estar en el mismo dispositivo físico que el archivo de registro que se está rotando, a menos que se utilice la opción copy, copytruncate o renamecopy. Se asume que el directorio es relativo al directorio que contiene el archivo de registro, a menos que se especifique un nombre de ruta absoluto. Cuando se utiliza esta opción, todas las versiones antiguas del registro terminan en directorio. Esta opción puede ser anulada por la opción noolddir.
noolddir
Los registros se rotan en el directorio donde residen normalmente (esto anula la opción olddir).
su usuario grupo
Rota los archivos de registro configurados bajo este usuario y grupo en lugar de usar el usuario/grupo predeterminado (generalmente root). usuario especifica el usuario utilizado para la rotación y grupo especifica el grupo utilizado para la rotación (ver la sección USUARIO Y GRUPO para detalles). Si el usuario/grupo que especifica aquí no tiene privilegios suficientes para crear archivos con la propiedad que ha especificado en una directiva create, causará un error. Si logrotate se ejecuta con privilegios de root, se recomienda utilizar la directiva su para rotar archivos en directorios que están directa o indirectamente bajo el control de usuarios no privilegiados.

Frecuencia

hourly
Los archivos de registro se rotan cada hora. Tenga en cuenta que generalmente logrotate está configurado para ser ejecutado por cron diariamente (o por logrotate.timer cuando se usa systemd(1)). Debe cambiar esta configuración y ejecutar logrotate cada hora para poder rotar realmente los registros cada hora.
daily
Los archivos de registro se rotan todos los días.
weekly [dia_semana]
Los archivos de registro se rotan una vez cada dia_semana, o si la fecha ha avanzado al menos 7 días desde la última rotación (ignorando la hora exacta). La interpretación de dia_semana es la siguiente: 0 significa domingo, 1 significa lunes, ..., 6 significa sábado; el valor especial 7 significa cada 7 días, independientemente del día de la semana. El valor predeterminado es 0 si se omite el argumento dia_semana.
monthly
Los archivos de registro se rotan la primera vez que se ejecuta logrotate en un mes (normalmente el primer día del mes).
yearly
Los archivos de registro se rotan si el año actual no es el mismo que la última rotación.
size tamaño
Los archivos de registro se rotan solo si crecen más allá de tamaño bytes. Si tamaño va seguido de k, el tamaño se asume en kilobytes. Si se usa M, el tamaño está en megabytes y si se usa G, el tamaño está en gigabytes. Por lo tanto, size 100, size 100k, size 100M y size 100G son válidos. Esta opción es mutuamente excluyente con las opciones de intervalo de tiempo y hace que los archivos de registro se roten sin tener en cuenta el tiempo de la última rotación, si se especifica después de los criterios de tiempo (la última opción especificada tiene precedencia).

Selección de archivos

missingok
Si el archivo de registro falta, continúe con el siguiente sin emitir un mensaje de error. Ver también nomissingok.
nomissingok
Si un archivo de registro no existe, emita un error. Este es el valor predeterminado.
ignoreduplicates
Ignora cualquier coincidencia posterior de un archivo de registro.
ifempty
Rota el archivo de registro incluso si está vacío, anulando la opción notifempty (ifempty es el valor predeterminado).
notifempty
No rote el registro si está vacío (esto anula la opción ifempty).
minage contador
No rote los registros que tengan menos de <contador> días de antigüedad.
maxage contador
Elimina los registros rotados con más de <contador> días de antigüedad. La antigüedad solo se verifica si el archivo de registro va a ser rotado. rotate -1 no impide la eliminación. Los archivos se envían por correo a la dirección configurada si maillast y mail están configurados.
minsize tamaño
Los archivos de registro se rotan cuando crecen más allá de tamaño bytes, pero no antes del intervalo de tiempo adicionalmente especificado (daily, weekly, monthly o yearly). La opción relacionada size es similar, excepto que es mutuamente excluyente con las opciones de intervalo de tiempo y hace que los archivos de registro se roten sin tener en cuenta el tiempo de la última rotación, si se especifica después de los criterios de tiempo (la última opción especificada tiene precedencia). Cuando se usa minsize, se consideran tanto el tamaño como la marca de tiempo de un archivo de registro.
maxsize tamaño
Los archivos de registro se rotan cuando crecen más allá de tamaño bytes, incluso antes del intervalo de tiempo adicionalmente especificado (daily, weekly, monthly o yearly). La opción relacionada size es similar, excepto que es mutuamente excluyente con las opciones de intervalo de tiempo y hace que los archivos de registro se roten sin tener en cuenta el tiempo de la última rotación, si se especifica después de los criterios de tiempo (la última opción especificada tiene precedencia). Cuando se usa maxsize, se consideran tanto el tamaño como la marca de tiempo de un archivo de registro.
tabooext [+] lista
La lista actual de extensiones tabú se cambia (ver la directiva include para información sobre las extensiones tabú). Si un + precede a la lista de extensiones, la lista actual de extensiones tabú se aumenta, de lo contrario se reemplaza. Al inicio, la lista de extensiones tabú es ,v, .bak, .cfsaved, .disabled, .dpkg-bak, .dpkg-del, .dpkg-dist, .dpkg-new, .dpkg-old, .dpkg-tmp, .new, .old, .orig, .rhn-cfg-tmp-*, .rpmnew, .rpmorig, .rpmsave, .swp, .ucf-dist, .ucf-new, .ucf-old, ~
taboopat [+] lista
La lista actual de patrones glob tabú se cambia (ver la directiva include para información sobre las extensiones y patrones tabú). Si un + precede a la lista de patrones, la lista actual de patrones tabú se aumenta, de lo contrario se reemplaza. Al inicio, la lista de patrones tabú está vacía.

Archivos y Carpetas

create modo propietario grupo, create propietario grupo
Inmediatamente después de la rotación (antes de que se ejecute el script postrotate), se crea el archivo de registro (con el mismo nombre que el archivo de registro recién rotado). modo especifica el modo para el archivo de registro en octal (el mismo que chmod(2)), propietario especifica el usuario que será propietario del archivo de registro y grupo especifica el grupo al que pertenecerá el archivo de registro (ver la sección USUARIO Y GRUPO para detalles). Cualquiera de los atributos del archivo de registro puede omitirse; en ese caso, los atributos para el nuevo archivo usarán los mismos valores que el archivo de registro original para los atributos omitidos. Esta opción se puede deshabilitar usando la opción nocreate.
nocreate
Los nuevos archivos de registro no se crean (esto anula la opción create).
createolddir modo [propietario [grupo]], createolddir [propietario [grupo]]
Si el directorio especificado por la directiva olddir no existe, se crea. modo especifica el modo para el directorio olddir en octal (el mismo que chmod(2)), propietario especifica el usuario que será propietario del directorio olddir y grupo especifica el grupo al que pertenecerá el directorio olddir (ver la sección USUARIO Y GRUPO para detalles). Si no se especifica modo, se asume 0755. Esta opción se puede deshabilitar usando la opción nocreateolddir.
nocreateolddir
El directorio olddir no es creado por logrotate cuando no existe.
copy
Crea una copia del archivo de registro, pero no modifica el original en absoluto. Esta opción se puede usar, por ejemplo, para crear una instantánea del archivo de registro actual, o cuando alguna otra utilidad necesita truncar o analizar el archivo. Cuando se utiliza esta opción, la opción create no tendrá ningún efecto, ya que el archivo de registro antiguo permanecerá en su lugar. La opción copy permite almacenar archivos de registro rotados en diferentes dispositivos utilizando la directiva olddir.
nocopy
No copia el archivo de registro original y lo deja en su lugar. (esto anula la opción copy).
copytruncate
Trunca el archivo de registro original a cero tamaño en su lugar después de crear .
copytruncate
Trunca el archivo de registro original en su lugar después de crear una copia. Esto puede ser útil cuando un programa no puede ser instruido para cerrar su archivo de registro y, por lo tanto, podría seguir escribiendo (anexando) al archivo de registro anterior para siempre. Tenga en cuenta que existe una franja de tiempo muy pequeña entre la copia del archivo y su truncamiento, por lo que es posible que se pierdan algunos datos de registro. Cuando esta opción se utiliza, la opción create no tendrá ningún efecto, ya que el archivo de registro antiguo permanece en su lugar. La opción copytruncate permite almacenar los archivos de registro rotados en dispositivos diferentes utilizando la directiva olddir. La opción copytruncate implica norenamecopy.
nocopytruncate
No trunque el archivo de registro original en su lugar después de crear una copia (esto anula la opción copytruncate).
renamecopy
El archivo de registro se renombra a un nombre de archivo temporal en el mismo directorio añadiendo la extensión ".tmp". Después de eso, se ejecuta el script postrotate y el archivo de registro se copia del nombre de archivo temporal al nombre de archivo final. Al final, se elimina el nombre de archivo temporal. La opción renamecopy permite almacenar los archivos de registro rotados en dispositivos diferentes utilizando la directiva olddir. La opción renamecopy implica nocopytruncate.
norenamecopy
No renombre ni copie el archivo de registro original (esto anula la opción renamecopy).
shred
Elimine los archivos de registro utilizando shred -u en lugar de unlink(). Esto debería garantizar que los registros no sean legibles después de su eliminación programada; esto está desactivado por defecto. Véase también noshred.
noshred
No utilice shred al eliminar archivos de registro antiguos. Véase también shred.
shredcycles count
Solicita a GNU shred(1) que sobrescriba los archivos de registro count veces antes de su eliminación. Sin esta opción, se utilizará el valor predeterminado de shred.
allowhardlink
Rotar archivos con múltiples enlaces duros; esto está desactivado por defecto. El archivo de destino podría quedar vacío, por ejemplo, con shred o copytruncate. Úselo con precaución, especialmente cuando los archivos de registro se rotan como root.
noallowhardlink
No rotar archivos con múltiples enlaces duros. Véase también allowhardlink.

Compresión

compress
Las versiones antiguas de los archivos de registro se comprimen con gzip(1) por defecto. Véase también nocompress.
nocompress
Las versiones antiguas de los archivos de registro no se comprimen. Véase también compress.
compresscmd
Especifica qué comando se utilizará para comprimir los archivos de registro. El valor predeterminado es gzip(1). Véase también compress.
uncompresscmd
Especifica qué comando se utilizará para descomprimir los archivos de registro. El valor predeterminado es gunzip(1).
compressext
Especifica qué extensión se utilizará en los archivos de registro comprimidos, si la compresión está activada. El valor predeterminado sigue al del comando de compresión configurado.
compressoptions
Se pueden pasar opciones de línea de comandos al programa de compresión, si se está utilizando uno. El valor predeterminado, para gzip(1), es "-6" (sesgado hacia alta compresión a expensas de la velocidad). Si utiliza un comando de compresión diferente, es posible que necesite cambiar compressoptions para que coincida.
delaycompress
Aplazar la compresión del archivo de registro anterior al próximo ciclo de rotación. Esto solo tiene efecto cuando se utiliza en combinación con compress. Puede utilizarse cuando no se puede indicar a un programa que cierre su archivo de registro y, por lo tanto, podría seguir escribiendo en el archivo de registro anterior durante algún tiempo.
nodelaycompress
No posponer la compresión del archivo de registro anterior al próximo ciclo de rotación (esto anula la opción delaycompress).

Nombres de archivo

extension ext
Los archivos de registro con la extensión ext pueden conservarla después de la rotación. Si se utiliza compresión, la extensión de compresión (normalmente .gz) aparece después de ext. Por ejemplo, si tiene un archivo de registro llamado mylog.foo y desea rotarlo a mylog.1.foo.gz en lugar de mylog.foo.1.gz.
addextension ext
Los archivos de registro reciben la extensión final ext después de la rotación. Si el archivo original ya termina con ext, la extensión no se duplica, sino que simplemente se mueve al final, es decir, tanto filename como filenameext se rotarían a filename.1ext. Si se utiliza compresión, la extensión de compresión (normalmente .gz) aparece después de ext.
start count
Este es el número que se utilizará como base para la rotación. Por ejemplo, si especifica 0, los registros se crearán con una extensión .0 a medida que se roten desde los archivos de registro originales. Si especifica 9, los archivos de registro se crearán con un .9, omitiendo 0-8. Los archivos seguirán rotando el número de veces especificado con la directiva rotate.
dateext
Archive las versiones antiguas de los archivos de registro añadiendo una extensión de fecha como YYYYMMDD en lugar de simplemente añadir un número. La extensión se puede configurar utilizando las opciones dateformat y dateyesterday.
nodateext
No archive versiones antiguas de los archivos de registro con extensión de fecha (esto anula la opción dateext).
dateformat format_string
Especifique la extensión para dateext utilizando una notación similar a la función strftime(3). Solo se permiten los especificadores %Y %m %d %H %M %S %V %s y %z. El valor predeterminado es -%Y%m%d, excepto para la rotación horaria, que utiliza -%Y%m%d%H como valor predeterminado. Tenga en cuenta que el carácter que separa el nombre del registro de la extensión forma parte de la cadena dateformat. El reloj del sistema debe estar configurado más allá del 9 de septiembre de 2001 para que %s funcione correctamente. Tenga en cuenta que las marcas de fecha generadas por este formato deben ser lexicográficamente ordenables (es decir, primero el año, luego el mes y luego el día. Por ejemplo, 2001/12/01 está bien, pero 01/12/2001 no lo está, ya que 01/11/2002 se ordenaría más bajo aunque sea posterior). Esto se debe a que, al utilizar la opción rotate, logrotate ordena todos los nombres de archivo rotados para determinar cuáles son más antiguos y deben eliminarse.
dateyesterday
Utilice la fecha de ayer en lugar de la de hoy para crear la extensión dateext, de modo que el archivo de registro rotado tenga una fecha en su nombre que sea la misma que las marcas de tiempo que contiene.
datehourago
Utilice la hora de hace una hora en lugar de la fecha actual para crear la extensión dateext, de modo que el archivo de registro rotado tenga una hora en su nombre que sea la misma que las marcas de tiempo que contiene. Útil con la rotación hourly.

Correo

mail address
Cuando un registro se rota y se elimina, se envía por correo a address. Si no se debe generar ningún correo para un registro determinado, se puede utilizar la directiva nomail.
nomail
No enviar por correo los archivos de registro antiguos a ninguna dirección.
mailfirst
Al utilizar el comando mail, enviar el archivo recién rotado, en lugar del archivo que está a punto de expirar.
maillast
Al utilizar el comando mail, enviar el archivo que está a punto de expirar, en lugar del archivo recién rotado (este es el valor predeterminado).

Archivos de configuración adicionales

include file_or_directory
Lee el archivo proporcionado como argumento como si se incluyera en línea donde aparece la directiva include. Si se proporciona un directorio, la mayoría de los archivos de ese directorio se leen en orden alfabético antes de que continúe el procesamiento del archivo que incluye. Los únicos archivos que se ignoran son los que no son archivos regulares (como directorios y tuberías con nombre) y los archivos cuyos nombres terminan con una de las extensiones o patrones prohibidos, según lo especificado por las directivas tabooext o taboopat, respectivamente. La ruta dada puede comenzar con ~/ para hacerla relativa al directorio personal del usuario que la ejecuta. Por razones de seguridad, los archivos de configuración no deben ser escribibles por el grupo ni por el mundo.

Scripts

sharedscripts
Normalmente, los scripts prerotate y postrotate se ejecutan para cada registro que se rota y la ruta absoluta al archivo de registro se pasa como primer argumento al script. Eso significa que un solo script puede ejecutarse varias veces para entradas de archivos de registro que coinciden con varios archivos (como el ejemplo /var/log/news/*). Si se especifica sharedscripts, los scripts solo se ejecutan una vez, sin importar cuántos registros coincidan con el patrón comodín,

sharedscripts

Run prerotate and postrotate scripts only once for each set of log files which match the wildcarded pattern (rather than once for every log file), unless the nosharedscripts option is specified. The script is executed just once in this case, with the whole pattern passed to it as the first argument. The entire pattern is passed to them. However, if none of the logs in the pattern require rotating, the scripts will not be run at all. If the scripts exit with error (or any log fails to rotate), the remaining actions will not be executed for any logs. This option overrides the nosharedscripts option.

nosharedscripts

Run prerotate and postrotate scripts for every log file which is rotated (this is the default, and overrides the sharedscripts option). The absolute path to the log file is passed as first argument to the script. The absolute path to the final rotated log file is passed as the second argument to the postrotate script. If the scripts exit with error, the remaining actions will not be executed for the affected log only.

firstaction

script

endscript

The script is executed once before all log files that match the wildcarded pattern are rotated, before the prerotate script is run and only if at least one log will actually be rotated. SCRIPTS

The lines between the starting keyword (e.g. prerotate) and endscript (both of which must appear on lines by themselves) are executed (using /bin/sh). The script inherits some traits from the logrotate process, including stderr, stdout, the current directory, the environment, and the umask. Scripts are run as the invoking user and group, irrespective of any su directive. If the --log flag was specified, file descriptor 3 is the log file. The current working directory is unspecified.

USER AND GROUP

User and group identifiers are resolved first by trying the textual representation and, in case it fails, afterwards by the numeric value.
