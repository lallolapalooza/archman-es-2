locale(7) Manual de información miscelánea locale(7)

NOMBRE

locale - descripción del soporte multilingüe

SINOPSIS

#include <locale.h>

DESCRIPCIÓN

Una configuración regional (locale) es un conjunto de reglas lingüísticas y culturales. Estas cubren aspectos como el idioma de los mensajes, diferentes conjuntos de caracteres, convenciones lexicográficas, etc. Un programa necesita poder determinar su configuración regional y actuar en consecuencia para ser portable a diferentes culturas.

La cabecera <locale.h> declara tipos de datos, funciones y macros que son útiles en esta tarea.

Las funciones que declara son setlocale(3) para establecer la configuración regional actual y localeconv(3) para obtener información sobre el formato de los números.

Hay diferentes categorías de información de configuración regional que un programa podría necesitar; se declaran como macros. Utilizándolas como primer argumento de setlocale(3), es posible establecer una de estas a la configuración regional deseada:

LC_ADDRESS (Extensión GNU, desde glibc 2.2)
Cambia las configuraciones que describen los formatos (p.ej., direcciones postales) utilizados para describir ubicaciones y elementos relacionados con la geografía. Las aplicaciones que necesitan esta información pueden usar nl_langinfo(3) para recuperar elementos no estándar, como _NL_ADDRESS_COUNTRY_NAME (nombre del país, en el idioma de la configuración regional) y _NL_ADDRESS_LANG_NAME (nombre del idioma, en el idioma de la configuración regional), que devuelven cadenas como "Deutschland" y "Deutsch" (para configuraciones regionales en alemán). (Otros nombres de elementos se listan en <langinfo.h>.)
LC_COLLATE
Esta categoría rige las reglas de ordenación utilizadas para la clasificación y expresiones regulares, incluyendo clases de equivalencia de caracteres y elementos de ordenación de varios caracteres. Esta categoría de configuración regional cambia el comportamiento de las funciones strcoll(3) y strxfrm(3), que se utilizan para comparar cadenas en el alfabeto local. Por ejemplo, la 'ß' alemana se clasifica como "ss".
LC_CTYPE
Esta categoría determina la interpretación de secuencias de bytes como caracteres (p.ej., caracteres de uno o varios bytes), clasificaciones de caracteres (p.ej., alfabético o dígito) y el comportamiento de las clases de caracteres. En sistemas glibc, esta categoría también determina las reglas de transliteración de caracteres para iconv(1) y iconv(3). Cambia el comportamiento de las funciones de manejo y clasificación de caracteres, como isupper(3) y toupper(3), y las funciones de caracteres multibyte como mblen(3) o wctomb(3).
LC_IDENTIFICATION (Extensión GNU, desde glibc 2.2)
Cambia las configuraciones relacionadas con los metadatos de la configuración regional. Las aplicaciones que necesitan esta información pueden usar nl_langinfo(3) para recuperar elementos no estándar, como _NL_IDENTIFICATION_TITLE (título de este documento de configuración regional) y _NL_IDENTIFICATION_TERRITORY (territorio geográfico al que se aplica este documento de configuración regional), que podrían devolver cadenas como "English locale for the USA" y "USA". (Otros nombres de elementos se listan en <langinfo.h>.)
LC_MONETARY
Esta categoría determina el formato utilizado para los valores numéricos relacionados con la moneda. Cambia la información devuelta por localeconv(3), que describe la forma en que se imprimen normalmente los números, con detalles como el punto decimal o la coma decimal. Esta información es utilizada internamente por la función strfmon(3).
LC_MESSAGES
Esta categoría afecta el idioma en que se muestran los mensajes y cómo se ve una respuesta afirmativa o negativa. La biblioteca C de GNU contiene las funciones gettext(3), ngettext(3) y rpmatch(3) para facilitar el uso de esta información. La familia de funciones GNU gettext también obedece la variable de entorno LANGUAGE (que contiene una lista de configuraciones regionales separadas por dos puntos) si la categoría se establece a una configuración regional válida distinta de "C". Esta categoría también afecta el comportamiento de catopen(3).
LC_MEASUREMENT (Extensión GNU, desde glibc 2.2)
Cambia las configuraciones relacionadas con el sistema de medición de la configuración regional (es decir, unidades métricas o unidades consuetudinarias de EE. UU.). Las aplicaciones pueden usar nl_langinfo(3) para recuperar el elemento no estándar _NL_MEASUREMENT_MEASUREMENT, que devuelve un puntero a un carácter que tiene el valor 1 (métrico) o 2 (unidades consuetudinarias de EE. UU.).
LC_NAME (Extensión GNU, desde glibc 2.2)
Cambia las configuraciones que describen los formatos utilizados para dirigirse a las personas. Las aplicaciones que necesitan esta información pueden usar nl_langinfo(3) para recuperar elementos no estándar, como los elementos _NL_NAME_NAME_MR (saludo general para hombres) y _NL_NAME_NAME_MS (saludo general para mujeres), que devuelven cadenas como "Herr" y "Frau" (para configuraciones regionales en alemán). (Otros nombres de elementos se listan en <langinfo.h>.)
LC_NUMERIC
Esta categoría determina las reglas de formato utilizadas para los valores numéricos no monetarios; por ejemplo, el separador de miles y el carácter radix (un punto en la mayoría de los países de habla inglesa, pero una coma en muchas otras regiones). Afecta a funciones como printf(3), scanf(3) y strtod(3). Esta información también puede ser leída con la función localeconv(3).
LC_PAPER (Extensión GNU, desde glibc 2.2)
Cambia las configuraciones relacionadas con las dimensiones del tamaño de papel estándar (p.ej., carta de EE. UU. frente a A4). Las aplicaciones que necesitan las dimensiones pueden obtenerlas utilizando nl_langinfo(3) para recuperar los elementos no estándar _NL_PAPER_WIDTH y _NL_PAPER_HEIGHT, que devuelven valores int que especifican las dimensiones en milímetros.
LC_TELEPHONE (Extensión GNU, desde glibc 2.2)
Cambia las configuraciones que describen los formatos a utilizar con los servicios telefónicos. Las aplicaciones que necesitan esta información pueden usar nl_langinfo(3) para recuperar elementos no estándar, como _NL_TELEPHONE_INT_PREFIX (prefijo internacional utilizado para llamar a números en esta configuración regional), que devuelve una cadena como "49" (para Alemania). (Otros nombres de elementos se listan en <langinfo.h>.)
LC_TIME
Esta categoría rige el formato utilizado para los valores de fecha y hora. Por ejemplo, la mayor parte de Europa utiliza un reloj de 24 horas frente al reloj de 12 horas utilizado en los Estados Unidos. La configuración de esta categoría afecta el comportamiento de funciones como strftime(3) y strptime(3).
LC_ALL
Todas las anteriores.

Si el segundo argumento de setlocale(3) es una cadena vacía, "", para la configuración regional predeterminada

, se determina usando los siguientes pasos:

(1)
Si existe una variable de entorno LC_ALL no nula, se usa su valor.
(2)
Si existe una variable de entorno con el mismo nombre que alguna de las categorías anteriores y no es nula, se usa su valor para esa categoría.
(3)
Si existe una variable de entorno LANG no nula, se usa su valor.

Los valores sobre el formato numérico local están disponibles en una estructura lconv devuelta por la función localeconv(3), que tiene la siguiente declaración:


struct lconv {
    /* Información numérica (no monetaria) */
    char *decimal_point;     /* Carácter del separador decimal */
    char *thousands_sep;     /* Separador de grupos de dígitos a la
                                izquierda del carácter decimal */
    char *grouping;     /* Cada elemento es el número de dígitos en
                           un grupo; los elementos con índices
                           mayores están más a la izquierda. Un
                           elemento con valor CHAR_MAX significa que
                           no se realiza más agrupamiento. Un
                           elemento con valor 0 significa que el
                           elemento anterior se usa para todos los
                           grupos más a la izquierda. */
    /* Los campos restantes son para información monetaria */
    char *int_curr_symbol;   /* Los tres primeros caracteres son un símbolo
                                de moneda de ISO 4217. El cuarto carácter
                                es el separador. El quinto carácter es
                                '\0'. */
    char *currency_symbol;   /* Símbolo de moneda local */
    char *mon_decimal_point; /* Carácter del separador decimal */
    char *mon_thousands_sep; /* Similar a thousands_sep arriba */
    char *mon_grouping;      /* Similar a grouping arriba */
    char *positive_sign;     /* Signo para valores positivos */
    char *negative_sign;     /* Signo para valores negativos */
    char  int_frac_digits;   /* Dígitos fraccionarios internacionales */
    char  frac_digits;       /* Dígitos fraccionarios locales */
    char  p_cs_precedes;     /* 1 si currency_symbol precede a un
                                valor positivo, 0 si lo sucede */
    char  p_sep_by_space;    /* 1 si un espacio separa
                                currency_symbol de un valor positivo */
    char  n_cs_precedes;     /* 1 si currency_symbol precede a un
                                valor negativo, 0 si lo sucede */
    char  n_sep_by_space;    /* 1 si un espacio separa
                                currency_symbol de un valor negativo */
    /* Posiciones de los signos positivos y negativos:
       0 Los paréntesis rodean la cantidad y currency_symbol.
       1 La cadena de signo precede a la cantidad y currency_symbol.
       2 La cadena de signo sucede a la cantidad y currency_symbol.
       3 La cadena de signo precede inmediatamente a currency_symbol.
       4 La cadena de signo sucede inmediatamente a currency_symbol. */
    char  p_sign_posn;
    char  n_sign_posn;
};

Extensiones de POSIX.1-2008 a la API de locale

POSIX.1-2008 estandarizó una serie de extensiones a la API de locale, basadas en implementaciones que aparecieron por primera vez en glibc 2.3. Estas extensiones están diseñadas para abordar el problema de que las APIs de locale tradicionales no se integran bien con aplicaciones multihilo ni con aplicaciones que deben manejar múltiples locales.

Las extensiones toman la forma de nuevas funciones para crear y manipular objetos de locale (newlocale(3), freelocale(3), duplocale(3) y uselocale(3)) y varias nuevas funciones de biblioteca con el sufijo "_l" (por ejemplo, toupper_l(3)) que extienden las APIs tradicionales dependientes del locale (por ejemplo, toupper(3)) para permitir la especificación de un objeto de locale que debe aplicarse al ejecutar la función.

ENTORNO

La siguiente variable de entorno es utilizada por newlocale(3) y setlocale(3), y por lo tanto afecta a todos los programas localizados no privilegiados:

LOCPATH
Una lista de nombres de ruta, separados por dos puntos (':'), que deben ser usados para encontrar datos de locale. Si esta variable está establecida, solo se usan los archivos individuales de datos de locale compilados de LOCPATH y la ruta de datos de locale predeterminada del sistema; no se usan los archivos de archivo de locale disponibles (ver localedef(1)). Los archivos individuales de datos de locale compilados se buscan bajo subdirectorios que dependen del locale actualmente utilizado. Por ejemplo, cuando se usa en_GB.UTF-8 para una categoría, se buscan los siguientes subdirectorios, en este orden: en_GB.UTF-8, en_GB.utf8, en_GB, en.UTF-8, en.utf8 y en.

ARCHIVOS

/usr/lib/locale/locale-archive
Ubicación habitual del archivo de locale predeterminado.
/usr/lib/locale
Ruta habitual predeterminada para archivos de locale individuales compilados.

ESTÁNDARES

POSIX.1-2001.
