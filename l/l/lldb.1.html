NOMBRE

lldb - Documentación de LLDB

SINOPSIS

lldb [opciones] ejecutable

DESCRIPCIÓN

lldb es un depurador de alto rendimiento de próxima generación. Está construido como un conjunto de componentes reutilizables que aprovechan en gran medida las bibliotecas existentes en el proyecto LLVM más grande, como el analizador de expresiones Clang y el desensamblador LLVM.

lldb es el depurador predeterminado en Xcode en macOS y admite la depuración de C, Objective-C y C++ en el escritorio y en dispositivos y simuladores de iOS.

Todo el código del proyecto LLDB está disponible bajo la Licencia Apache 2.0 con excepciones de LLVM.

ESTADO DE SALIDA

Normalmente, el estado de salida es 0 si el depurador ha finalizado sin errores. Un estado de salida distinto de cero indica un error.

NOMBRE

lldb - El depurador del proyecto LLVM

SINOPSIS

lldb [opciones] [ejecutable [argumentos del programa ...]]

lldb [opciones] --core archivo-core

lldb [opciones] --attach <pid> | --attach-name <nombre-proceso>

DESCRIPCIÓN

lldb es un depurador de alto rendimiento, extensible y con características propias, que forma parte del proyecto LLVM. Se puede usar como una herramienta independiente o integrado en un entorno de desarrollo como Xcode.

lldb puede usarse para depurar un ejecutable proporcionado como argumento posicional, para adjuntarse a un proceso en ejecución, para depurar un archivo core o para ejecutarse en modo REPL (Read-Eval-Print Loop).

ARGUMENTOS

ejecutable
La ruta al archivo ejecutable que se va a depurar.
argumentos del programa
Los argumentos que se pasarán al programa depurado. Deben ir después de un doble guion (--) para separarlos de las opciones de lldb.
archivo-core
La ruta al archivo core dump que se va a analizar.
pid
El ID del proceso al que se va a adjuntar el depurador.
nombre-proceso
El nombre del proceso al que se va a adjuntar el depurador.

ADJUNTANDO

--attach <pid>
Adjunta el depurador al proceso con el ID especificado.
--attach-name <nombre-proceso>
Adjunta el depurador al primer proceso encontrado con el nombre especificado.
-p <pid>
Alias para --attach.
-n <nombre-proceso>
Alias para --attach-name.

COMANDOS

-c <archivo-core>
Depura un archivo core dump.
--core <archivo-core>
Alias para -c.
-k <comando>
Ejecuta el comando especificado después de que el proceso depurado se crashee.
--keep-crash <comando>
Alias para -k.
-o <comando>
Ejecuta el comando especificado después de que el ejecutable se cargue.
--once-crash <comando>
Alias para -k.
-s <comando>
Ejecuta el comando especificado después de que el ejecutable se cargue.
--script <archivo-script>
Ejecuta el archivo de script especificado antes de que el ejecutable se cargue.
-S <archivo-script>
Alias para --script.
--signal <señal>
Envía la señal especificada al proceso depurado cuando este se detiene.
-K <señal>
Alias para --signal.

OPCIONES

--arch <arquitectura>
Establece la arquitectura del ejecutable a depurar. Si no se especifica, se infiere del ejecutable.
-a <arquitectura>
Alias para --arch.
--no-use-color
Desactiva el resaltado de sintaxis y el uso de colores en la salida.
-x
Alias para --no-use-color.
--no-use-color
Alias para -x.
--run <comando>
Ejecuta el comando especificado una vez que el programa se inicia.
-r <comando>
Alias para --run.
-l <filename>
Indica al depurador que reproduzca un reproductor desde <filename>.
--version
Muestra el número de versión actual del depurador LLDB.
-v
Alias para --version.
-X
Alias para --no-use-color.

REPL

-r=<flags>
Alias para --repl=<flags>.
--repl-language <language>
Elige el lenguaje para el REPL.
--repl=<flags>
Ejecuta lldb en modo REPL con un proceso stub con las banderas dadas.
-R <value>
Alias para --repl-language.

SCRIPTING

-l <value>
Alias para --script-language.
--print-script-interpreter-info
Imprime un diccionario JSON con información sobre el intérprete del lenguaje de scripting.
--python-path
Imprime la ruta al archivo lldb.py para esta versión de lldb.
-P
Alias para --python-path.
--script-language <language>
Indica al depurador que use el lenguaje de scripting especificado para scripts definidos por el usuario.

EJEMPLOS

El depurador se puede iniciar en varios modos.

Pasar un ejecutable como argumento posicional prepara lldb para depurar el ejecutable dado. Para desambiguar entre argumentos pasados a lldb y argumentos pasados al ejecutable depurado, los argumentos que comienzan con un guion deben pasarse después de --.

lldb --arch x86_64 /ruta/a/programa argumento-programa -- --arch armv7

Para mayor comodidad, también se admite pasar el ejecutable después de --.

lldb --arch x86_64 -- /ruta/a/programa argumento-programa --arch armv7

Pasar una de las opciones de adjuntar hace que lldb se adjunte inmediatamente al proceso dado.

lldb -p <pid> lldb -n <nombre-proceso>

Pasar --repl inicia lldb en modo REPL.

lldb -r

Pasar --core hace que lldb depure el archivo core.

lldb -c /ruta/a/core

Las opciones de comando se pueden combinar con estos modos y hacen que lldb ejecute los comandos especificados antes o después de eventos, como cargar el archivo o fallar, en el orden proporcionado en la línea de comandos.

lldb -O 'settings set stop-disassembly-count 20' -o 'run' -o 'bt' lldb -S /fuente/antes/archivo -s /fuente/despues/archivo lldb -K /fuente/antes/crash -k /fuente/despues/crash

Nota: En modo REPL no se carga ningún archivo, por lo que se ignoran los comandos especificados para ejecutarse después de cargar el archivo (a través de -o o -s).

USANDO LLDB

En lldb hay un comando de ayuda (`help`) que se puede usar para encontrar descripciones y ejemplos de todos los comandos de lldb. Para obtener ayuda sobre `breakpoint set`, escribirías `help breakpoint set`.

También hay un comando `apropos` que buscará en el texto de ayuda de todos los comandos un término dado; esto es útil para localizar un comando por tema. Por ejemplo, `apropos breakpoint` listará cualquier comando que tenga la palabra "breakpoint" en su texto de ayuda.

ARCHIVOS DE CONFIGURACIÓN

lldb lee configuraciones, alias y comandos del archivo .lldbinit.

Primero, lldb intentará leer el archivo de inicialización específico de la aplicación cuyo nombre es ~/.lldbinit seguido de un "-" y el nombre del programa actual. Sería ~/.lldbinit-lldb para el lldb de línea de comandos y ~/.lldbinit-Xcode para Xcode. Si no hay un archivo de inicialización específico de la aplicación, lldb buscará un archivo de inicialización en el directorio de inicio. Si se inicia con una opción REPL, primero buscará un archivo de configuración REPL, específico para el lenguaje REPL. El archivo de inicialización debe llamarse: .lldbinit-<language>-repl (por ejemplo, .lldbinit-swift-repl). Si este archivo no existe, o si lldb no se inició con REPL, lo que significa que no hay ni un archivo de inicialización REPL ni un archivo de inicialización específico de la aplicación, lldb recurrirá al global ~/.lldbinit.

En segundo lugar, buscará un archivo .lldbinit en el directorio de trabajo actual. Por razones de seguridad, lldb mostrará una advertencia y no cargará este archivo por defecto. Este comportamiento se puede cambiar modificando la configuración target.load-cwd-lldbinit.

Para cargar siempre el archivo .lldbinit en el directorio de trabajo actual, agregue el siguiente comando a ~/.lldbinit:

settings set target.load-cwd-lldbinit true

Para no cargar nunca el archivo .lldbinit en el directorio de trabajo actual y silenciar la advertencia, agregue el siguiente comando a ~/.lldbinit:

settings set target.load-cwd-lldbinit false
