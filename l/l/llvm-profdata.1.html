NOMBRE

llvm-profdata - Herramienta de datos de perfil

SINOPSIS

llvm-profdata comando [args...]

DESCRIPCIÓN

La utilidad llvm-profdata es una pequeña herramienta para trabajar con archivos de datos de perfil.

COMANDOS

  • merge
  • show
  • overlap
  • order

MERGE

SINOPSIS

llvm-profdata merge [opciones] [archivo...]

DESCRIPCIÓN

llvm-profdata merge toma varios archivos de datos de perfil generados por instrumentación PGO y los fusiona en un único archivo de datos de perfil indexado.

Por defecto, los datos del perfil se fusionan sin modificaciones. Esto significa que la importancia relativa de cada archivo de entrada es proporcional al número de muestras o recuentos que contiene. En general, la entrada de una ejecución de entrenamiento más larga se interpretará como relativamente más importante que una ejecución más corta. Dependiendo de la naturaleza de las ejecuciones de entrenamiento, puede ser útil ajustar el peso asignado a cada archivo de entrada utilizando la opción -weighted-input.

Los perfiles pasados a través de -weighted-input, -input-files, o a través de argumentos posicionales se procesan una vez por cada vez que se ven.

OPCIONES

--help
Imprime un resumen de las opciones de línea de comandos.
--output=<salida>, -o
Especifica el nombre del archivo de salida. Salida no puede ser - ya que los datos de perfil indexados resultantes no se pueden escribir en la salida estándar.
--weighted-input=<peso,archivo>
Especifica un archivo de entrada junto con un peso. Los recuentos del perfil del archivo proporcionado se escalarán (multiplicarán) por el peso proporcionado, donde peso es un entero decimal >= 1. A los archivos de entrada especificados sin usar esta opción se les asigna un peso predeterminado de 1. A continuación se muestran ejemplos.
--input-files=<ruta>, -f
Especifica un archivo que contiene una lista de archivos para fusionar. Las entradas de este archivo están separadas por saltos de línea. Las líneas que comienzan con '#' se omiten. Las entradas pueden ser del formato <nombre_archivo> o <peso>,<nombre_archivo>.
--remapping-file=<ruta>, -r
Especifica un archivo que contiene un reempaquetado de nombres de símbolos en el perfil de entrada a los nombres de símbolos que se deben utilizar en el perfil de salida. El archivo debe consistir en líneas del formato <simbolo-entrada> <simbolo-salida>. Se omiten las líneas en blanco y las líneas que comienzan con #.

La utilidad llvm-cxxmap <> puede usarse para generar el archivo de reempaquetado de símbolos.

--instr (predeterminado)
Especifica que el perfil de entrada es un perfil basado en instrumentación.
--sample
Especifica que el perfil de entrada es un perfil basado en muestras.

El formato del archivo generado puede generarse de tres maneras:

--binary (predeterminado)

Emite el perfil utilizando una codificación binaria. Para perfiles basados en instrumentación, el formato de salida es el formato binario indexado.

--extbinary

Emite el perfil utilizando una codificación binaria extensible. Esta opción solo se puede usar con perfiles basados en muestras. La codificación binaria extensible puede ser más compacta con la compresión habilitada y puede cargarse más rápido que la codificación binaria predeterminada.

--text

Emite el perfil en modo texto. Esta opción también puede usarse con perfiles basados en muestras y en instrumentación. Cuando se usa esta opción, el perfil se volcará en el formato de texto que puede ser analizado por el lector de perfiles.

--gcc

Emite el perfil utilizando el formato gcov de GCC (aún no soportado).

--sparse[=true|false]
No emite registros de funciones con recuento de ejecución 0. Solo puede usarse en conjunción con -instr. Por defecto es falso, ya que puede inhibir la optimización del compilador durante PGO.
--num-threads=<N>, -j
Usa N hilos para realizar la fusión de perfiles. Cuando N=0, llvm-profdata auto-detecta un número apropiado de hilos a usar. Este es el valor predeterminado.
--failure-mode=[any|all]
Establece el modo de fallo. Hay dos opciones: 'any' hace que el comando de fusión falle si algún perfil es inválido, y 'all' hace que el comando de fusión falle solo si todos los perfiles son inválidos. Si se establece 'all', la información de los perfiles inválidos se excluye del producto fusionado final. El modo de fallo predeterminado es 'any'.
--prof-sym-list=<ruta>
Especifica un archivo que contiene una lista de símbolos para generar la lista de símbolos de perfil en el perfil. Esta opción solo se puede usar con perfiles basados en muestras en formato extbinary. Las entradas de este archivo están separadas por saltos de línea.
--compress-all-sections=[true|false]
Comprime todas las secciones al escribir el perfil. Esta opción solo se puede usar con perfiles basados en muestras en formato extbinary.
--use-md5=[true|false]
Usa MD5 para representar cadenas en la tabla de nombres al escribir el perfil. Esta opción solo se puede usar con perfiles basados en muestras en formato extbinary.
--gen-partial-profile=[true|false]
Marca el perfil para que sea un perfil parcial que solo proporciona una cobertura de perfil parcial para el objetivo optimizado. Esta opción solo se puede usar con perfiles basados en muestras en formato extbinary.
--split-layout=[true|false]
Divide la sección de datos del perfil en dos, una que contiene perfiles de muestras con funciones insertadas y otra que no. Esta opción solo se puede usar con perfiles basados en muestras en formato extbinary.
--convert-sample-profile-layout=[nest|flat]
Convierte el perfil fusionado en un perfil con un nuevo diseño. Los diseños soportados son nest (perfil anidado, la entrada debe ser un perfil CS plano) y flat (perfil con funciones insertadas aplanadas).
--supplement-instr-with-sample=<archivo>
Suplementa un perfil de instrumentación con un perfil de muestras. El perfil de muestras es la entrada del indicador. La salida será en formato de instrumentación.

instrumentation format (solo funciona con -instr).
--zero-counter-threshold=<float>
Para la función que es fría en el perfil de instrumentación pero caliente en el perfil de muestreo, si la relación entre el número de contadores cero y el número total de contadores supera el umbral, el perfil de la función se considerará perjudicial para el rendimiento y se descartará.
--instr-prof-cold-threshold=<int>
Umbral de frío especificado por el usuario para el perfil de instrumentación, que anulará el umbral de frío obtenido del resumen del perfil.
--suppl-min-size-threshold=<int>
Si el tamaño de una función es menor que el umbral, se asume que puede ser inlineada por el inlineador temprano de PGO y no se ajustará según el perfil de muestreo.
--debug-info=<path>
Especifica el ejecutable o .dSYM que contiene la información de depuración para el perfil bruto. Cuando se utilizó --debug-info-correlate o --profile-correlate=debug-info para la instrumentación, utiliza esta opción para correlacionar el perfil bruto.
--binary-file=<path>
Especifica el ejecutable que contiene los datos del perfil y las secciones de nombres del perfil para el perfil bruto. Cuando se utilizó -profile-correlate=binary para la instrumentación, utiliza esta opción para correlacionar el perfil bruto.
--debuginfod
Utiliza debuginfod para encontrar los ejecutables asociados que contienen los datos del perfil y las secciones de nombres para los perfiles brutos para correlacionarlos. Cuando se utilizó -profile-correlate=binary para la instrumentación, esta opción puede usarse para la correlación.
--debug-file-directory=<dir>
Utiliza los directorios locales proporcionados para buscar ejecutables que contengan datos del perfil y secciones de nombres para los perfiles brutos para correlacionarlos. Cuando se utilizó -profile-correlate=binary para la instrumentación, esta opción puede usarse para la correlación.
--correlate=<kind>
Especifica el tipo de correlación (debug_info o binary) a utilizar cuando se proporciona la opción -debuginfod o -debug-file-directory=<dir>.
--temporal-profile-trace-reservoir-size
El número máximo de trazas de perfil temporal a almacenar en el perfil de salida. Si se añaden más trazas, utilizaremos muestreo por reservorio para seleccionar qué trazas conservar. Tenga en cuenta que cambiar este valor entre diferentes invocaciones de fusión en el mismo perfil indexado podría resultar en un sesgo de muestra. El valor predeterminado es 100.
--temporal-profile-max-trace-length
El número máximo de funciones en una única traza de perfil temporal. Las trazas más largas se truncarán. El valor predeterminado es 1000.
--function=<string>
Solo conservar las funciones que coincidan con la expresión regular en la salida, todas las demás se borrarán del perfil.
--no-function=<string>
Eliminar las funciones que coincidan con la expresión regular del perfil. Si se especifican tanto --function como --no-function y una función coincide con ambas, se elimina.

EJEMPLOS

Uso Básico

Fusionar tres perfiles:

llvm-profdata merge foo.profdata bar.profdata baz.profdata -output merged.profdata

Entrada Ponderada

El archivo de entrada foo.profdata es especialmente importante, multiplicar sus recuentos por 10:

llvm-profdata merge --weighted-input=10,foo.profdata bar.profdata baz.profdata --output merged.profdata

Exactamente equivalente a la invocación anterior (forma explícita; útil para invocación programática):

llvm-profdata merge --weighted-input=10,foo.profdata --weighted-input=1,bar.profdata --weighted-input=1,baz.profdata --output merged.profdata

SHOW

SINOPSIS

llvm-profdata show [opciones] [nombrearchivo]

DESCRIPCIÓN

llvm-profdata show toma un archivo de datos de perfil y muestra la información sobre los contadores de perfil para este archivo y para cualquiera de las funciones especificadas.

Si se omite nombrearchivo o es -, entonces llvm-profdata show lee su entrada de la entrada estándar.

OPCIONES

--all-functions
Imprime detalles para cada función.
--binary-ids
Imprime los IDs binarios incrustados en un perfil.
--counts
Imprime los valores de los contadores para las funciones mostradas.
--show-format=<text|json|yaml>
Emite la salida en el formato seleccionado si es compatible con el tipo de perfil proporcionado.
--function=<string>
Imprime detalles para una función si el nombre de la función contiene la cadena dada.
--help
Imprime un resumen de las opciones de la línea de comandos.
--output=<output>, -o
Especifica el nombre del archivo de salida. Si output es - o no se especifica, la salida se envía a la salida estándar.
--instr (predeterminado)
Especifica que el perfil de entrada es un perfil basado en instrumentación.
--text
Indica al volcado de perfil que muestre los recuentos del perfil en el formato de texto de la representación de datos del perfil basado en instrumentación. Por defecto, la información del perfil se vuelca en una forma más legible por humanos (también en texto) con anotaciones.
--topn=<n>
Indica al volcado de perfil que muestre las n funciones principales con los bloques básicos más activos en la sección de resumen. Por defecto, no se vuelcan las funciones principales.
--sample
Especifica que el perfil de entrada es un perfil basado en muestreo.
--memop-sizes
Muestra los tamaños perfilados de las llamadas intrínsecas de memoria para las funciones mostradas.
--value-cutoff=<n>
Muestra solo aquellas funciones cuyos valores de recuento máximo sean mayores o iguales a n. Por defecto, el valor de corte se establece en 0.
--list-below-cutoff
Solo muestra los nombres de las funciones cuyos valores de recuento máximo estén por debajo del valor de corte.
--profile-version
Imprime la versión del perfil.
--showcs
Solo muestra los recuentos de perfil sensibles al contexto. Por defecto, se filtran todos los recuentos de perfil sensibles al contexto.
--show-prof-sym-list=[true|false]
Muestra la lista de símbolos del perfil si existe en el perfil. Esta opción solo es significativa para perfiles basados en muestreo en formato extbinary.
--show-sec-info-only=[true|false]
Muestra información básica sobre cada sección en el perfil. Esta opción solo es significativa para perfiles basados en muestreo en formato extbinary.
--debug-info=<path>
Especifica el ejecutable o .dSYM que contiene la información de depuración para el perfil bruto. Cuando se utilizó --debug-info-correlate o --profile-correlate=debug-info para la instrumentación, utiliza esta opción para mostrar las funciones correlacionadas del perfil bruto.
--covered
Muestra solo las funciones que han sido ejecutadas, es decir, funciones con recuentos distintos de cero.

SUPERPOSICIÓN

SINÓPSIS

llvm-profdata overlap [opciones] [archivo de perfil base] [archivo de perfil de prueba]

DESCRIPCIÓN

llvm-profdata overlap toma dos archivos de datos de perfil y muestra la superposición de la distribución de contadores entre los archivos completos y entre cualquiera de las funciones especificadas.

En este comando, la superposición se define de la siguiente manera: Supongamos que el archivo de perfil base tiene los siguientes recuentos: {c1_1, c1_2, ..., c1_n, c1_u_1, c2_u_2, ..., c2_u_s}, y el archivo de perfil de prueba tiene {c2_1, c2_2, ..., c2_n, c2_v_1, c2_v_2, ..., c2_v_t}. Aquí, c{1|2}_i (i = 1 .. n) son contadores emparejados y c1_u_i (i = 1 .. s) y c2_v_i (i = 1 .. v) son contadores no emparejados (o contadores que solo existen en) el archivo de perfil base y el archivo de perfil de prueba, respectivamente. Sea sum_1 = c1_1 + c1_2 + ... + c1_n + c1_u_1 + c2_u_2 + ... + c2_u_s, y sum_2 = c2_1 + c2_2 + ... + c2_n + c2_v_1 + c2_v_2 + ... + c2_v_t. Superposición = min(c1_1/sum_1, c2_1/sum_2) + min(c1_2/sum_1, c2_2/sum_2) + ... + min(c1_n/sum_1, c2_n/sum_2).

La distribución de superposición resultante es un porcentaje, que varía del 0.0% al 100.0%, donde 0.0% significa que no hay superposición y 100.0% significa una superposición perfecta.

Aquí hay un ejemplo: si el archivo de perfil base tiene recuentos de {400, 600}, y el archivo de perfil de prueba tiene recuentos emparejados de {60000, 40000}. La superposición es del 80%.

OPCIONES

--function=<cadena>
Muestra detalles de una función si el nombre de la función contiene la cadena dada.
--help
Muestra un resumen de las opciones de línea de comandos.
--output=<salida>, -o
Especifica el nombre del archivo de salida. Si salida es - o no se especifica, la salida se envía a la salida estándar.
--value-cutoff=<n>
Muestra solo aquellas funciones cuyos valores de recuento máximo sean mayores o iguales a n. Por defecto, el corte de valor se establece en el máximo de unsigned long long.
--cs
Solo muestra la superposición para los recuentos de perfil sensibles al contexto. Por defecto, se muestran los recuentos de perfil no sensibles al contexto.

ORDEN

SINÓPSIS

llvm-profdata order [opciones] [nombre de archivo]

DESCRIPCIÓN

llvm-profdata order utiliza trazas de perfilado temporal de un perfil y encuentra un orden de funciones que reduce el número de fallos de página para esas trazas. Esta salida se puede pasar directamente a lld a través de --symbol-ordering-file= para ELF o -order-file para Mach-O. Si las trazas encontradas en el perfil son representativas del mundo real, entonces este orden debería mejorar el rendimiento de inicio.

OPCIONES

--help
Muestra un resumen de las opciones de línea de comandos.
--output=<salida>, -o
Especifica el nombre del archivo de salida. Si salida es - o no se especifica, la salida se envía a la salida estándar.

ESTADO DE SALIDA

llvm-profdata devuelve 1 si se omite o es inválido el comando, si no puede leer los archivos de entrada, o si hay una discrepancia entre sus datos.
