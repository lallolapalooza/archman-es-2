NOMBRE

lli - ejecuta directamente programas desde el bitcode de LLVM

SINOPSIS

lli [opciones] [nombre_archivo] [argumentos_programa]

DESCRIPCIÓN

lli ejecuta directamente programas en formato de bitcode de LLVM. Toma un programa en formato de bitcode de LLVM y lo ejecuta usando un compilador just-in-time (JIT) o un intérprete.

lli no es un emulador. No ejecutará IR de diferentes arquitecturas y solo puede interpretar (o compilar JIT) para la arquitectura del host.

El compilador JIT toma los mismos argumentos que otras herramientas, como llc, pero estos no necesariamente funcionan para el intérprete.

Si no se especifica nombre_archivo, entonces lli lee el bitcode de LLVM para el programa desde la entrada estándar.

Los argumentos_programa opcionales especificados en la línea de comandos se pasan al programa como argumentos.

OPCIONES GENERALES

-fake-argv0=ejecutable
Sobrescribe el valor de argv[0] pasado al programa en ejecución.
-force-interpreter={false,true}
Si se establece en true, usa el intérprete incluso si hay un compilador just-in-time disponible para esta arquitectura. El valor predeterminado es false.
-help
Imprime un resumen de las opciones de la línea de comandos.
-load=nombre_archivo_plugin
Hace que lli cargue el plugin (objeto compartido) llamado nombre_archivo_plugin y lo use para la optimización.
-stats
Imprime estadísticas de los pases de generación de código. Esto solo tiene sentido para el compilador just-in-time, por ahora.
-time-passes
Registra la cantidad de tiempo necesaria para cada pase de generación de código y lo imprime en la salida de error estándar.
-version
Imprime la versión de lli y sale sin hacer nada más.

OPCIONES DE OBJETIVO

-mtriple=triple_objetivo
Sobrescribe el triple del objetivo especificado en el archivo de bitcode de entrada con la cadena especificada. Esto puede resultar en un bloqueo si se elige una arquitectura que no sea compatible con el sistema actual.
-march=arch
Especifica la arquitectura para la cual generar ensamblaje, sobrescribiendo el objetivo codificado en el archivo de bitcode. Consulte la salida de llc -help para obtener una lista de arquitecturas válidas. Por predeterminado, esto se infiere del triple del objetivo o se autodetecta a la arquitectura actual.
-mcpu=nombre_cpu
Especifica un chip específico en la arquitectura actual para generar código. Por predeterminado, esto se infiere del triple del objetivo y se autodetecta a la arquitectura actual. Para obtener una lista de CPUs disponibles, use: llvm-as < /dev/null | llc -march=xyz -mcpu=help
-mattr=a1,+a2,-a3,...
Sobrescribe o controla atributos específicos del objetivo, como si las operaciones SIMD están habilitadas o no. El conjunto predeterminado de atributos lo establece la CPU actual. Para obtener una lista de atributos disponibles, use: llvm-as < /dev/null | llc -march=xyz -mattr=help

OPCIONES DE PUNTO FLOTANTE

-disable-excess-fp-precision
Deshabilita optimizaciones que pueden aumentar la precisión del punto flotante.
-enable-no-infs-fp-math
Habilita optimizaciones que asumen que no hay valores Inf.
-enable-no-nans-fp-math
Habilita optimizaciones que asumen que no hay valores NAN.
-enable-unsafe-fp-math
Hace que lli habilite optimizaciones que pueden disminuir la precisión del punto flotante.
-soft-float
Hace que lli genere llamadas a la biblioteca de punto flotante por software en lugar de instrucciones de hardware equivalentes.

OPCIONES DE GENERACIÓN DE CÓDIGO

-code-model=modelo
Elige el modelo de código de:
default: Modelo de código predeterminado del objetivo
tiny: Modelo de código "tiny"
small: Modelo de código "small"
kernel: Modelo de código de "kernel"
medium: Modelo de código "medium"
large: Modelo de código "large"
-disable-post-RA-scheduler
Deshabilita la planificación después de la asignación de registros.
-disable-spill-fusing
Deshabilita la fusión de código de "spill" en instrucciones.
-jit-enable-eh
El manejo de excepciones debe estar habilitado en el compilador just-in-time.
-join-liveintervals
Coalesce copias (predeterminado=true)
-nozero-initialized-in-bss
No colocar símbolos inicializados a cero en la sección BSS.
-pre-RA-sched=planificador
Planificadores de instrucciones disponibles (antes de la asignación de registros):
=default: Mejor planificador para el objetivo
=none: Sin planificación: secuenciación en orden de amplitud
=simple: Planificación simple de dos pases: minimizar la ruta crítica y maximizar la utilización del procesador
=simple-noitin: Planificación simple de dos pases: igual que simple excepto que usa latencia genérica
=list-burr: Planificación de lista de reducción de registros de abajo hacia arriba
=list-tdrr: Planificación de lista de reducción de registros de arriba hacia abajo
=list-td: Planificador de lista de arriba hacia abajo
-regalloc=asignador
Asignador de registros a usar (predeterminado=linearscan)
=bigblock: Asignador de registros de bloques grandes
=linearscan: Asignador de registros de escaneo lineal
=local: Asignador de registros local
=simple: Asignador de registros simple
-relocation-model=modelo
Elige el modelo de reubicación de:
=default: Modelo de reubicación predeterminado del objetivo
=static: Código no reubicable
=pic: Código completamente reubicable e independiente de la posición
=dynamic-no-pic: Referencias externas reubicables, código no reubicable
-spiller
"Spiller" a usar (predeterminado=local)

GENERAL OPTIONS

The following options are available for the lli command:

-help
Print a summary of options.
-version
Print the version of this program.

TARGET OPTIONS

The following options are available for the lli command:

=simple: simple spiller
=local: local spiller

FLOATING POINT OPTIONS

-float-abi=abi

Select the floating-point ABI to be used:

32
Emit code that uses the 32-bit floating-point ABI.
64
Emit code that uses the 64-bit floating-point ABI.
soft
Emit code that uses software floating-point operations.
-fp-model=fpmodel

Selects the floating-point emission model:

strict

This is the default. It preserves the maximal precision available on the floating-point registers and performs operations as described in the specification. This is the slowest setting.

safe

This is a faster setting that preserves the precision of the mathematical operations as much as possible, but it may not perform operations in the exact order specified by the source code. It still guarantees that the results will be bitwise identical across different executions and different optimization levels.

tm

This is similar to safe, but it may break down larger computations into smaller ones that fit into registers. This is useful for transactional memory code.

fast

This is the fastest setting. It allows for aggressive optimizations that may reduce precision. It does not guarantee bitwise identical results across different executions or hardware.

CODE GENERATION OPTIONS

-x86-asm-syntax=syntax
Choose style of code to emit from X86 backend:
=att: Emit AT&T-style assembly
=intel: Emit Intel-style assembly

EXIT STATUS

If lli fails to load the program, it will exit with an exit code of 1. Otherwise, it will return the exit code of the program it executes.
