NOMBRE

lloadd - Demonio de balanceador de carga LDAP

SINOPSIS

/usr/lib/lloadd [-4|-6] [-d nivel-depuracion] [-f archivo-config-lloadd] [-h URLs] [-n nombre-servicio] [-s nivel-syslog] [-l usuario-local-syslog] [-o opcion[=valor]] [-r directorio] [-u usuario] [-g grupo]

DESCRIPCIÓN

Lloadd es el demonio LDAP independiente. Escucha conexiones LDAP en cualquier número de puertos (por defecto 389), reenviando las operaciones LDAP que recibe a través de estas conexiones para que sean manejadas por los backends configurados. lloadd normalmente se invoca al arrancar el sistema, usualmente desde /etc/rc.local. Al iniciar, lloadd normalmente se bifurca y se disocia del tty invocador. Si está configurado en el archivo de configuración, el proceso lloadd imprimirá su ID de proceso (ver getpid(2)) a un archivo .pid, así como las opciones de línea de comandos durante la invocación a un archivo .args (ver lloadd.conf(5)). Si se proporciona la bandera -d, incluso con un argumento cero, lloadd no se bifurcará ni se disociará del tty invocador.

Ver la "Guía del Administrador de OpenLDAP" para más detalles sobre lloadd.

OPCIONES

-4
Escuchar solo en direcciones IPv4.
-6
Escuchar solo en direcciones IPv6.
-d nivel-depuracion
Activar la depuración según lo definido por nivel-depuracion. Si se especifica esta opción, incluso con un argumento cero, lloadd no se bifurcará ni se disociará de la terminal invocadora. Algunos mensajes generales de operación y estado se imprimen para cualquier valor de nivel-depuracion. nivel-depuracion se toma como una cadena de bits, donde cada bit corresponde a un tipo diferente de información de depuración. Ver <ldap_log.h> para detalles. Se pueden especificar arreglos separados por comas de nombres amigables para seleccionar la salida de depuración de la información de depuración correspondiente. Todos los nombres reconocidos por la directiva loglevel descrita en lloadd.conf(5) son compatibles. Si nivel-depuracion es ?, se imprime una lista de los niveles de depuración instalados y lloadd sale.

Recuerde que si activa el registro de paquetes, se emitirán paquetes que contengan contraseñas de enlace, por lo que si redirige el registro a un archivo de registro, ese archivo debe tener protección de lectura.

-s nivel-syslog
Esta opción le indica a lloadd a qué nivel de depuración se deben registrar las sentencias de depuración en el sistema de registro syslog(8). El valor nivel-syslog puede establecerse en cualquier valor o combinación permitida por el interruptor -d. Lloadd registra todos los mensajes seleccionados por nivel-syslog en el nivel de severidad de depuración DEBUG de syslog(3), en la unidad especificada con -l.
-n nombre-servicio
Especifica el nombre del servicio para el registro y otros propósitos. Por defecto es el nombre base de argv[0], es decir: "lloadd".
-l usuario-local-syslog
Selecciona el usuario local del sistema de registro syslog(8). El valor puede ser LOCAL0, hasta LOCAL7, así como USER y DAEMON. Por defecto es LOCAL4. Sin embargo, esta opción solo está permitida en sistemas que admiten usuarios locales con el sistema de registro syslog(8). El registro en syslog(8) se realiza en el nivel de depuración de severidad "DEBUG".
-f archivo-config-lloadd
Especifica el archivo de configuración de lloadd. Por defecto es /etc/openldap/lloadd.conf.
-h lista-URLs
lloadd servirá por defecto ldap:/// (LDAP sobre TCP en todas las interfaces en el puerto LDAP por defecto). Es decir, se enlazará usando INADDR_ANY y el puerto 389. La opción -h se puede usar para especificar URLs LDAP (y de otros esquemas) para servir. Por ejemplo, si lloadd recibe -h "ldap://127.0.0.1:9009/ ldaps:/// ldapi:///", escuchará en 127.0.0.1:9009 para LDAP, 0.0.0.0:636 para LDAP sobre TLS, y LDAP sobre IPC (sockets de dominio Unix). El host 0.0.0.0 representa INADDR_ANY (cualquier interfaz). Se espera una lista de URLs separadas por espacios. Las URLs deben ser de los esquemas LDAP, PLDAP, LDAPS, PLDAPS o LDAPI, y generalmente sin un DN u otros parámetros opcionales (excepto como se discute a continuación). El soporte para los últimos tres esquemas depende de las opciones de configuración seleccionadas. Los hosts pueden especificarse por nombre o por formatos de dirección IPv4 e IPv6. Los puertos, si se especifican, deben ser numéricos. El puerto por defecto de ldap:// es 389 y el puerto por defecto de ldaps:// es 636, lo mismo para las variantes con proxy habilitado.

Los esquemas de URL PLDAP y PLDAPS proporcionan soporte para el protocolo proxy HAProxy versión 2, que permite a un balanceador de carga o servidor proxy proporcionar la dirección IP del cliente remoto a slapd para su uso en control de acceso o registro. Los puertos configurados para PLDAP o PLDAPS solo aceptarán conexiones que incluyan la cabecera del protocolo proxy necesaria. Las conexiones a estos puertos deben restringirse a nivel de red solo a balanceadores de carga o proxies de confianza para evitar la suplantación de direcciones IP de clientes por parte de terceros.

Por el momento, el balanceador de carga no actúa sobre la dirección registrada de ninguna manera.

Para LDAP sobre IPC, nombre es el nombre del socket, y no se requiere ni se permite ningún puerto; tenga en cuenta que los separadores de directorio deben codificarse en URL, al igual que cualquier otro carácter que sea especial para las URL; por lo tanto, el socket


/usr/local/var/ldapi

debe especificarse como


ldapi://%2Fusr%2Flocal%2Fvar%2Fldapi

La ubicación por defecto para el socket IPC es /var/lib/openldap/run/ldapi

-r directorio
Especifica un directorio para convertirlo en el directorio raíz. lloadd cambiará el directorio de trabajo actual a este directorio y luego realizará un chroot(2) a este directorio. Esto se hace después de abrir los oyentes pero antes de leer cualquier archivo de configuración o inicializar cualquier backend. Cuando se usa como mecanismo de seguridad, debe usarse junto con las opciones -u y -g.
-u usuario
lloadd ejecutará lloadd con el nombre de usuario o ID especificado, y la lista de acceso a grupos suplementarios de ese usuario según lo establecido con initgroups(3). El ID de grupo también se cambia al gid de este usuario, a menos que se use la opción -g para anularlo. Tenga en cuenta que cuando se usa con -r, lloadd usará la base de datos de usuarios en el entorno de cambio de raíz.
-g grupo
lloadd se ejecutará con el nombre de grupo o ID especificado. Tenga en cuenta que cuando se usa con -r, lloadd usará la base de datos de grupos en el entorno de cambio de raíz.
-o opcion[=valor]
Esta opción proporciona un medio genérico para especificar opciones sin la necesidad de reservar una letra separada para ellas.

Admite las siguientes opciones:

slp={on|off|attrs-slp}
Cuando el soporte SLP está compilado en lloadd, desactívalo (off),
actívalo registrándote en los DA de SLP sin atributos SLP específicos (on), o con atributos SLP específicos attrs-slp que deben ser una definición de lista de atributos SLP según el estándar SLP.

Por ejemplo, "slp=(tree=production),(server-type=OpenLDAP),(server-version=2.4.15)" se registra en los DA de SLP con los tres atributos SLP tree, server-type y server-version que tienen los valores dados anteriormente. Esto permite consultar específicamente los DA de SLP para servidores LDAP que albergan el árbol production en caso de que haya varios árboles disponibles.

OpenLDAP 2.6.10.0

NAME

lloadd - OpenLDAP load balancer daemon

SYNOPSIS

/usr/lib/lloadd [options]

DESCRIPTION

The lloadd utility implements a load balancer daemon. It is designed to distribute LDAP client connections across a pool of backend LDAP servers. The configuration of the backend servers and load balancing algorithm is specified in the lloadd.conf(5) configuration file.

OPTIONS

-f conffile
Use the specified configuration file instead of the default one. The default configuration file is typically /etc/openldap/lloadd.conf.
-l logfile
Log to the specified log file instead of standard error.
-d level
Enable debugging messages specified by level. The level is a bitmask. See lloadd.conf(5) for details.
-h
Display usage information and exit.
-n
Check configuration only, do not start the daemon.
-V
Print the version and exit.

RELATION TO SLAPD(8)

The lloadd daemon can also be compiled as a slapd loadable module. In that case, it can be loaded as such:

    moduleload path/to/lloadd.la
    backend lload
    listen "listening URLs"

This enables lloadd to provide additional features through the host slapd process like access to run-time statistics in cn=monitor and dynamic configuration from cn=config.

The listening sockets specified will be under direct control of lloadd and need to be different from the sockets slapd is configured to listen on. Clients connecting to these are completely separate from regular LDAP clients connecting to the usual slapd sockets - lloadd clients have no access to slapd databases, similarly, slapd client traffic does not propagate to the lloadd backend servers in any way.

CN=MONITOR INTERFACE

As part of lloadd's cn=monitor interface it is possible to close a client connection it manages by writing to the corresponding entry, replacing the olmConnectionState attribute with the value closing. This is subject to ACLs configured on the monitor database. The server will send a Notice of Disconnection to the client, refuse any new operations and once all pending operations have finished, close the connection.

For example, to close connection number 42:

    dn: cn=connection 42,cn=incoming connections,cn=load balancer,cn=backends,cn=monitor
    changetype: modify
    replace: olmConnectionState
    olmConnectionState: closing

EXAMPLES

To start lloadd and have it fork and detach from the terminal and start load-balancing the LDAP servers defined in the default config file, just type:

/usr/lib/lloadd

To start lloadd with an alternate configuration file, and turn on voluminous debugging which will be printed on standard error, type:

/usr/lib/lloadd -f /var/tmp/lloadd.conf -d 255

To start lloadd as a module inside a slapd process listening on ldap://:1389 and ldaps://, put the following in your slapd.conf (or its equivalent in cn=config):

    moduleload lloadd.la
    backend lload
    listen "ldap://:1389 ldaps://"
