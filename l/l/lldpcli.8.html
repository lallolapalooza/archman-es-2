LLDPCLI(8) Manual del Administrador del Sistema LLDPCLI(8)

NOMBRE

lldpcli, lldpctl — controla el demonio LLDP

SINOPSIS

lldpcli [-dv] [-u socket] [-f formato] [-c archivo] [comando ...]

lldpctl [-dv] [-u socket] [-f formato] [interfaces ...]

DESCRIPCIÓN

El programa lldpcli controla el demonio lldpd(8).

Cuando no se especifica ningún comando, lldpcli iniciará un shell interactivo que se puede usar para introducir comandos arbitrarios como si se hubieran especificado en la línea de comandos. Este shell interactivo debería proporcionar soporte de completado e historial.

Las opciones son las siguientes:

-d
Habilita más información de depuración. Esta bandera se puede repetir.
-u socket
Especifica el socket de dominio Unix utilizado para la comunicación con lldpd(8).
-v
Muestra la versión de lldpcli. Cuando se repite, muestra más información de compilación.
-f formato
Elige el formato de salida. Actualmente están disponibles los formatos plain, xml, json, json0 y keyvalue. El valor predeterminado es plain. json0 es más detallado que json, pero la estructura del objeto JSON no se ve afectada por el número de interfaces o el número de vecinos. Por lo tanto, es más fácil de analizar.
-c archivo
Lee el archivo de configuración dado. Esta opción se puede repetir varias veces. Si se proporciona un directorio, se leerá cada archivo dentro de él con el sufijo .conf. El orden es alfabético.

Cuando se invoca como lldpctl, lldpcli mostrará información detallada sobre cada vecino en las interfaces especificadas o en todas las interfaces si no se especifica ninguna. Este comando se mantiene principalmente por compatibilidad con versiones anteriores.

Los siguientes comandos son compatibles con lldpcli. Cuando no hay ambigüedad, las palabras clave se pueden abreviar. Por ejemplo, show neighbors ports eth0 summary y sh neigh p eth0 sum son el mismo comando.

exit
Salir de lldpcli.

help [...]

Muestra ayuda general o ayuda sobre un comando. Además, puedes obtener ayuda usando el completado o presionando la tecla ?. El completado y la ayuda en línea pueden no estar disponibles, sin embargo, si lldpcli se compiló sin soporte de lectura, pero el comando help siempre está disponible.

show neighbors [ports ethX [,...]] [details | summary] [hidden]

Muestra información sobre cada vecino conocido por el demonio lldpd(8). Con summary, solo se mostrará el nombre y la descripción del puerto de cada host remoto. Por otro lado, con details, se mostrará toda la información disponible, ofreciendo una vista detallada. Al usar hidden, también se muestran los puertos remotos ocultos por el filtro inteligente. Al especificar uno o varios puertos, la información mostrada se limita a la lista de puertos dada.

show interfaces [ports ethX [,...]] [details | summary] [hidden]

Muestra información sobre cada interfaz local conocida por el demonio lldpd(8). Con summary, solo se mostrará el nombre y la descripción del puerto de cada interfaz local. Por otro lado, con details, se mostrará toda la información disponible, ofreciendo una vista detallada. Al usar hidden, también se muestran los puertos locales ocultos por el filtro inteligente. Al especificar uno o varios puertos, la información mostrada se limita a la lista de puertos dada.

show chassis [details | summary]

Muestra información sobre el chasis local. Con summary, se omiten la mayoría de los detalles. Por otro lado, con details, se mostrará toda la información disponible, ofreciendo una vista detallada.

watch [ports ethX [,...]] [details | summary] [hidden] [limit X]

Observa cualquier cambio en los vecinos y repórtalos tan pronto como ocurran. Al especificar puertos, los cambios solo se informan cuando ocurren en los puertos dados. hidden, summary y details tienen el mismo significado que se describió anteriormente. Si se especifica limit, lldpcli saldrá después de recibir el número especificado de eventos.

show configuration

Muestra la configuración global del demonio lldpd(8).

show statistics [ports ethX [,...]] [summary]

Reporta estadísticas relacionadas con LLDP, como el número de LLDPDU transmitidos, recibidos, descartados o no reconocidos. Al especificar puertos, solo se reportan las estadísticas del puerto dado. Con summary, las estadísticas de cada puerto se suman.

update

Hace que lldpd(8) actualice su información y envíe nuevos PDU LLDP en todas las interfaces.

configure system hostname nombre

Sobrescribe el nombre de host del sistema con el valor proporcionado. Por defecto, el nombre del sistema es el FQDN que se obtiene del valor resuelto de uname -n. Como valor especial, usa "." (punto) para usar el nombre de host corto en lugar de un FQDN.

unconfigure system hostname

No sobrescribe el nombre de host del sistema y restaura el uso del nombre del nodo.

configure system description descripción

Sobrescribe la descripción del chasis con el valor proporcionado en lugar de usar el nombre del kernel, el nombre del nodo, la versión del kernel, la fecha de compilación y la arquitectura.

unconfigure system description

No sobrescribe la descripción del chasis y usa un valor calculado a partir del nombre del nodo, el nombre del kernel, la versión del kernel, la fecha de compilación y la arquitectura en su lugar.

configure system chassisid descripción

Sobrescribe el ID del chasis con el valor proporcionado en lugar de usar la dirección MAC de una interfaz o el nombre del host.

unconfigure system chassisid

No sobrescribe el ID del chasis, sino que usa un valor calculado a partir de una de las direcciones MAC de la interfaz (o el nombre del host si no se encuentra ninguna).

configure system platform descripción

Anula la descripción de la plataforma con el valor proporcionado en lugar de usar el nombre del kernel. Este valor se utiliza actualmente solo para CDP.

unconfigure system platform

No anules la descripción de la plataforma y utiliza el nombre del kernel. Esta opción deshace la anterior.

configure system capabilities enabled capabilities

Anula las capacidades del sistema con el valor proporcionado en lugar de utilizar la información del kernel. Se pueden especificar varias capacidades, separadas por comas. Solo se pueden habilitar las capacidades disponibles. Las capacidades válidas son:
bridge
 
docsis
 
other
 
repeater
 
router
 
station
 
telephone
 
wlan
 
Aquí tienes un ejemplo de uso:
configure system capabilities enabled bridge,router

unconfigure system capabilities enabled

No anules las capacidades, sino que utiliza la información del kernel. Esta opción deshace la anterior.

configure system interface pattern pattern

Especifica como valores separados por comas (CSV) en qué interfaces escuchar y enviar LLDPDU. Sin esta opción, lldpd utilizará todas las interfaces físicas disponibles. Esta opción puede usar comodines. Se pueden especificar varias interfaces separadas por comas. También es posible eliminar una interfaz prefijándola con un signo de exclamación. Es posible permitir una interfaz prefijándola con dos signos de exclamación. Una interfaz permitida prevalece sobre una interfaz prohibida, que a su vez prevalece sobre una interfaz simplemente coincidente. Por ejemplo, con eth*,!eth1,!eth2 lldpd solo usará las interfaces que comiencen con eth, con la excepción de eth1 y eth2. Mientras que con *,!eth*,!!eth1 lldpcli usará todas las interfaces, excepto las interfaces que comiencen con eth, con la excepción de eth1. Cuando se encuentra una coincidencia exacta, se omiten algunas pruebas. Por ejemplo, si eth0.12 se especifica, será aceptada incluso si se trata de una interfaz VLAN.

unconfigure system interface pattern

Elimina cualquier patrón de interfaz configurado previamente y utiliza todas las interfaces físicas. Esta opción deshace la anterior.

configure system interface permanent pattern

Especifica las interfaces cuya configuración se mantiene de forma permanente por lldpd. Por defecto, lldpd ignora cualquier dato sobre las interfaces cuando se eliminan del sistema (estadísticas, configuración personalizada). Esta opción permite especificar un patrón similar al patrón de interfaz. Si una interfaz desaparece pero coincide con el patrón, sus datos se conservan en memoria y se reutilizan si la interfaz reaparece en algún momento. Por ejemplo, en Linux, se podría usar el patrón eth*,eno*,enp*, que debería coincidir con interfaces fijas en la mayoría de los sistemas.

unconfigure system interface permanent

Elimina cualquier patrón de interfaz permanente configurado previamente. Cualquier interfaz eliminada del sistema será olvidada. Esta opción deshace la anterior.

configure system interface description

Algunos sistemas operativos permiten al usuario establecer una descripción para una interfaz. La configuración de esta opción permitirá a lldpd anular esta descripción con el nombre del vecino o con el número de vecinos encontrados.

unconfigure system interface description

No actualices la descripción de la interfaz con el nombre del vecino. Esta opción deshace la anterior.

configure system interface promiscuous

Habilita el modo promiscuo en las interfaces administradas.

Cuando la interfaz ya no se administra (o al salir de lldpd), la interfaz se deja en modo promiscuo, ya que es difícil saber si alguien más también la puso en modo promiscuo.

Se sabe que esta opción es útil cuando el switch remoto es un Cisco 2960 y la tarjeta de red local tiene aceleración de hardware VLAN. En este caso, es posible que no recibas tramas LLDP del switch remoto. La explicación más plausible es que la trama está etiquetada con alguna VLAN (generalmente VLAN 1) y tu tarjeta de red filtra VLANs. Esta no es la única solución disponible para solucionar este problema. Si te preocupan los problemas de rendimiento, también puedes etiquetar la VLAN 1 en cada interfaz en su lugar.

Actualmente, esta opción no tiene ningún efecto en nada que no sea Linux. En otros sistemas operativos, deshabilita la aceleración de VLAN, etiqueta la VLAN 1 o habilita manualmente el modo promiscuo en la interfaz.

unconfigure system interface promiscuous

No configures el modo promiscuo en las interfaces administradas. Esta opción no deshabilita el modo promiscuo en las interfaces que ya lo utilizan.

configure system ip management pattern pattern

Especifica las direcciones de gestión de este sistema como valores separados por comas (CSV). Al igual que con las interfaces (descritas anteriormente), esta opción puede usar comodines e inversiones. Sin esta opción, se utilizan la primera IPv4 y la primera IPv6. Si se proporciona una dirección IP exacta, se utiliza como dirección de gestión sin ninguna comprobación. Si solo se proporcionan patrones negativos, se elige una dirección IPv4 y una IPv6. De lo contrario, se pueden seleccionar muchas de ellas. Para eliminar direcciones IPv6, utiliza !*:*. Si una interfaz coincide, se elegirá la primera dirección IPv4 y la primera dirección IPv6 asociadas a esa interfaz.

unconfigure system ip management pattern

Anula cualquier patrón específico para la coincidencia de direcciones de gestión. Esta opción deshace la anterior.

configure system bond-slave-src-mac-type value

Establece el tipo de MAC de origen en los frames LLDP enviados en los esclavos de bond.

Los tipos válidos son:

real
MAC real del esclavo
zero
MAC con todos los ceros
fixed
Un valor fijo arbitrario (00:60:08:69:97:ef)
local
MAC real con el bit de administración local establecido. Si la MAC real ya tiene el bit de administración local establecido, se recurre al valor fijo.

El valor predeterminado para bond-slave-src-mac-type es local. Algunos switches pueden quejarse al usar uno de los otros dos valores posibles (ya sea porque 00:00:00:00:00:00 no es una MAC válida o porque la dirección MAC está fluctuando de un puerto a otro). Usar local podría llevar a una dirección MAC duplicada en la red (pero esto es bastante improbable).

configure system max-neighbors neighbors

Cambia el número máximo de vecinos aceptados (para cada protocolo) en una interfaz. Este es un valor global. El valor predeterminado es 32. Esta configuración solo se aplica a los vecinos futuros.

configure lldp agent-type nearest-bridge | nearest-non-tpmr-bridge | nearest-customer-bridge

La dirección MAC de destino utilizada para enviar LLDPDU permite a un agente controlar la propagación de LLDPDU. Por defecto, se utiliza la dirección MAC 01:80:c2:00:00:0e y limita la propagación de LLDPDU al puente más cercano (nearest-bridge). Para indicar a lldpd que utilice en su lugar la dirección MAC 01:80:c2:00:00:03, usa nearest-non-tpmr-bridge. Para utilizar en su lugar la dirección MAC 01:80:c2:00:00:00, usa nearest-customer-bridge.

configure lldp capabilities-advertisements

Habilita la publicidad del TLV de capacidades del chasis. Actualmente es el valor predeterminado.

unconfigure lldp capabilities-advertisements

Deshabilita la publicidad del TLV de capacidades del chasis.

configure lldp management-addresses-advertisements

Habilita la publicidad del TLV de direcciones de gestión. Actualmente es el valor predeterminado.

unconfigure lldp management-addresses-advertisements

Deshabilita la publicidad del TLV de direcciones de gestión.

El indicador unknown indica que la política de red para el tipo de aplicación especificado es requerida por el dispositivo pero es actualmente desconocida. Esto es usado por los Dispositivos de Endpoint, no por los Dispositivos de Conectividad de Red. Si no se especifica, la política de red para el tipo de aplicación dado está definida.

Una VLAN especificada con vlan indica qué ID de VLAN 802.1q debe ser anunciado para la política de red. Un valor válido está entre 1 y 4094. tagged indica que la VLAN debe ser etiquetada para el tipo de aplicación especificado.

priority permite especificar la Prioridad de Capa 2 IEEE 802.1d / IEEE 802.1p, también conocida como Clase de Servicio (CoS), que se utilizará para el tipo de aplicación especificado. Este campo generalmente se ignora si no se especifica ninguna VLAN. Los nombres coinciden con el estándar 802.1D-2004 (tabla G-2). Algunos estándares más recientes pueden usar etiquetas diferentes. Solo se deben confiar en los valores numéricos. Las etiquetas aceptadas son:

1
background
0
best-effort
2
excellent-effort
3
critical-applications
4
video
5
voice
6
internetwork-control
7
network-control

dscp representa el valor DSCP que se anunciará para la política de red dada. Valor de DiffServ/Differentiated Services Code Point (DSCP) según se define en la RFC 2474 de IETF para el tipo de aplicación especificado. Valor: 0 (predeterminado por RFC 2475) a 63. Nota: Los valores DSCP de selector de clase son retrocompatibles para dispositivos que solo admiten el formato antiguo de Tipo de Servicio (ToS) de precedencia IP. (Consulte las RFC para ver el significado de estos valores)

Un uso válido de este comando es:

configure med policy application voice vlan 500 priority voice dscp 46

configure [ports ethX [,...]] med power pse | pd source source priority priority value value

Anuncia el TLV LLDP-MED POE-MDI para los puertos dados o para todas las interfaces si no se proporciona ningún puerto. Se puede actuar como PD (consumidor de energía) o PSE (proveedor de energía). No se realiza ninguna verificación sobre la validez de los parámetros, aunque LLDP-MED requiere algunas restricciones:
  • PD nunca debe solicitar más energía que la clase física 802.3af.
  • PD nunca debe consumir más de la potencia máxima anunciada por el PSE.
  • PSE no debe reducir la potencia asignada a PD cuando esta potencia está en uso.
  • PSE puede solicitar potencia reducida usando el modo de conservación.
  • Ser PSE o PD es un parámetro global, no un parámetro por puerto. lldpcli no impone esto: un puerto puede ser configurado como PD o PSE. LLDP-MED también requiere que un PSE tenga una sola fuente de alimentación (primaria o de respaldo). De nuevo, lldpcli no impone esto. Cada puerto puede tener su propia fuente de alimentación. Lo mismo se aplica a PD y a la prioridad de energía. La MIB de LLDP-MED no permite este tipo de representación.

Los tipos válidos son:

pse
Entidad de Suministro de Energía (proveedor de energía)
pd
Dispositivo de Energía (consumidor de energía)

Las fuentes válidas son:

unknown
Desconocido
primary
Para PSE, la fuente de alimentación es la fuente de alimentación primaria.
backup
Para PSE, la fuente de alimentación es la fuente de alimentación de respaldo, o se solicita un modo de conservación de energía (el PSE puede estar funcionando con un SAI, por ejemplo).
pse
Para PD, la fuente de alimentación es el PSE.
local
Para PD, la fuente de alimentación es una fuente local.
both
Para PD, la fuente de alimentación es tanto el PSE como una fuente local.

Las prioridades válidas son:

unknown
Prioridad desconocida
critical
Crítica
high
Alta
low
Baja

value debe ser la potencia total en milivatios requerida por el dispositivo PD o disponible por el dispositivo PSE.

Aquí hay un ejemplo de uso:

configure med power pd source pse priority high value 5000

configure [ports ethX [,...]] dot3 power pse | pd [supported] [enabled] [paircontrol] powerpairs powerpairs [class class] [type type source source priority priority requested requested allocated allocated]

Anuncia el TLV Dot3 POE-MDI para el puerto dado o para todos los puertos si no se proporcionó ninguno. Se puede actuar como PD (consumidor de energía) o PSE (proveedor de energía). Esta configuración es distinta de la configuración de la transmisión del TLV LLDP-MED POE-MDI, pero el usuario debe asegurar la coherencia de estas dos configuraciones si se usan juntas.

supported significa que la alimentación MDI es compatible en el puerto dado, mientras que enabled significa que la alimentación MDI está habilitada. paircontrol se utiliza para indicar si el control de la selección de pares puede ser controlado. Los valores válidos para powerpairs son:

signal
Solo se utilizan los pares de señal.
spare
Solo se utilizan los pares de repuesto.

Cuando se especifica, class es class-, seguido de un número del 0 al 4. Por ejemplo: class-0, class-1, class-2, class-3, clase-4.

Para 802.3at, las clases son las siguientes:

0
Predeterminado (No especificado), PD 0.44-12.95 W, PSE 15.4 W
1
Dispositivo de muy baja potencia, PD 0.44-3.84 W, PSE 4.0 W
2
Dispositivo de baja potencia, PD 3.84-6.49 W, PSE 7.0 W
3
Dispositivo de potencia media, PD 6.49-12.95 W, PSE 15.4 W
4
Dispositivo de alta potencia (PoE+), PD 12.95-25.5 W, PSE 30.0 W

Los parámetros restantes cumplen con 802.3at y son opcionales. type debe ser 1 o 2, indicando si el dispositivo cumple con el tipo 1 de 802.3at o el tipo 2 de 802.3at. Los valores de source y priority son los mismos que para el TLV de LLDP-MED POE-MDI. requested y allocated se expresan en milivatios.

Aquí hay dos usos válidos de este comando:

configure ports eth3 dot3 power pse supported enabled paircontrol powerpairs spare class class-3
configure dot3 power pd supported enabled powerpairs spare class class-3 type 1 source pse priority low requested 10000 allocated 15000

pause

Pausa las operaciones de lldpd. lldpd no enviará ni recibirá más tramas. Esto se puede deshacer con el comando resume. Esto solo funciona interactivamente, ya que lldpd le pide a lldpcli que reanude después de leer el archivo de configuración.

resume

Reanuda las operaciones de lldpd. lldpd comenzará a enviar y recibir tramas. Este comando se emite internamente después de procesar la configuración, pero se puede usar en cualquier momento si se emite un comando manual de pause.
