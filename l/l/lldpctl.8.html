LLDPCLI(8) Manual del Administrador del Sistema LLDPCLI(8)

NOMBRE

lldpcli, lldpctl — controlar el demonio LLDP

SINOPSIS

lldpcli [-dv] [-u socket] [-f formato] [-c archivo] [comando ...]

lldpctl [-dv] [-u socket] [-f formato] [interfaces ...]

DESCRIPCIÓN

El programa lldpcli controla el demonio lldpd(8).

Cuando no se especifica ningún comando, lldpcli iniciará un shell interactivo que se puede usar para ingresar comandos arbitrarios como si se hubieran especificado en la línea de comandos. Este shell interactivo debería proporcionar soporte de completado e historial.

Las opciones son las siguientes:

-d
Habilita más información de depuración. Esta bandera se puede repetir.
-u socket
Especifica el socket de dominio Unix utilizado para la comunicación con lldpd(8).
-v
Muestra la versión de lldpcli. Cuando se repite, muestra más información de compilación.
-f formato
Elige el formato de salida. Actualmente están disponibles los formatos plain, xml, json, json0 y keyvalue. El predeterminado es plain. json0 es más detallado que json pero la estructura del objeto JSON no se ve afectada por el número de interfaces o el número de vecinos. Por lo lo tanto, es más fácil de analizar.
-c archivo
Lee el archivo de configuración dado. Esta opción se puede repetir varias veces. Si se proporciona un directorio, se leerá cada archivo allí con sufijo .conf. El orden es alfabético.

Cuando se invoca como lldpctl, lldpcli mostrará información detallada sobre cada vecino en las interfaces especificadas o en todas las interfaces si no se especifica ninguna. Este comando se mantiene principalmente por compatibilidad con versiones anteriores.

Los siguientes comandos son compatibles con lldpcli. Cuando no hay ambigüedad, las palabras clave pueden abreviarse. Por ejemplo, show neighbors ports eth0 summary y sh neigh p eth0 sum son el mismo comando.

exit
Salir de lldpcli.

help [...]

Muestra ayuda general o ayuda sobre un comando. También puedes obtener ayuda usando el completado o presionando la tecla ?. El completado y la ayuda en línea pueden no estar disponibles, sin embargo, si lldpcli se compiló sin soporte de readline, pero el comando help siempre está disponible.

show neighbors [ports ethX [,...]] [details | summary] [hidden]

Muestra información sobre cada vecino conocido por el demonio lldpd(8). Con summary, solo se mostrarán el nombre y la descripción del puerto de cada host remoto. Por otro lado, con details, se mostrará toda la información disponible, dando una vista detallada. Al usar hidden, también muestra los puertos remotos ocultos por el filtro inteligente. Al especificar uno o varios puertos, la información mostrada se limita a la lista de puertos dada.

show interfaces [ports ethX [,...]] [details | summary] [hidden]

Muestra información sobre cada interfaz local conocida por el demonio lldpd(8). Con summary, solo se mostrarán el nombre y la descripción del puerto de cada interfaz local. Por otro lado, con details, se mostrará toda la información disponible, dando una vista detallada. Al usar hidden, también muestra los puertos locales ocultos por el filtro inteligente. Al especificar uno o varios puertos, la información mostrada se limita a la lista de puertos dada.

show chassis [details | summary]

Muestra información sobre el chasis local. Con summary, se omiten la mayoría de los detalles. Por otro lado, con details, se mostrará toda la información disponible, dando una vista detallada.

watch [ports ethX [,...]] [details | summary] [hidden] [limit X]

Observa cualquier cambio en los vecinos y repórtalos tan pronto como ocurran. Al especificar puertos, los cambios solo se informan cuando ocurren en los puertos dados. hidden, summary y details tienen el mismo significado que se describió anteriormente. Si se especifica limit, lldpcli saldrá después de recibir el número especificado de eventos.

show configuration

Muestra la configuración global del demonio lldpd(8).

show statistics [ports ethX [,...]] [summary]

Informa estadísticas relacionadas con LLDP, como el número de LLDPDU transmitidos, recibidos, descartados o no reconocidos. Al especificar puertos, solo se informan las estadísticas del puerto dado. Con summary, las estadísticas de cada puerto se suman.

update

Hace que lldpd(8) actualice su información y envíe nuevas PDU LLDP en todas las interfaces.

configure system hostname nombre

Sobrescribe el nombre del host del sistema con el valor proporcionado. Por defecto, el nombre del sistema es el FQDN encontrado a partir del valor resuelto de uname -n. Como valor especial, usa "." (punto) para usar el nombre de host corto en lugar de un FQDN.

unconfigure system hostname

No sobrescribe el nombre del host del sistema y restaura el uso del nombre del nodo.

configure system description descripción

Sobrescribe la descripción del chasis con el valor proporcionado en lugar de usar el nombre del kernel, el nombre del nodo, la versión del kernel, la fecha de compilación y la arquitectura.

unconfigure system description

No sobrescribe la descripción del chasis y usa un valor calculado a partir del nombre del nodo, el nombre del kernel, la versión del kernel, la fecha de compilación y la arquitectura en su lugar.

configure system chassisid descripción

Sobrescribe el ID del chasis con el valor proporcionado en lugar de usar la dirección MAC de una interfaz o el nombre del host.

unconfigure system chassisid

No sobrescribe el ID del chasis, sino que usa un valor calculado a partir de una de las direcciones MAC de la interfaz (o el nombre del host si no se encuentra ninguna) en su lugar.

configure system platform descripción

Anula la descripción de la plataforma con el valor proporcionado en lugar de usar el nombre del kernel. Este valor se utiliza actualmente solo para CDP.

unconfigure system platform

No anules la descripción de la plataforma y utiliza el nombre del kernel. Esta opción deshace la anterior.

configure system capabilities enabled capabilities

Anula las capacidades del sistema con el valor proporcionado en lugar de utilizar la información del kernel. Se pueden especificar varias capacidades, separadas por comas. Solo se pueden habilitar las capacidades disponibles. Las capacidades válidas son:
bridge
 
docsis
 
other
 
repeater
 
router
 
station
 
telephone
 
wlan
 
Aquí tienes un ejemplo de uso:
configure system capabilities enabled bridge,router

unconfigure system capabilities enabled

No anules las capacidades, sino que utiliza la información del kernel. Esta opción deshace la anterior.

configure system interface pattern pattern

Especifica como valores separados por comas (CSV) qué interfaces escuchar y enviar LLDPDU desde ellas. Sin esta opción, lldpd utilizará todas las interfaces físicas disponibles. Esta opción puede usar comodines. Se pueden especificar varias interfaces separadas por comas. También es posible eliminar una interfaz prefijándola con un signo de exclamación. Es posible permitir una interfaz prefijándola con dos signos de exclamación. Una interfaz permitida supera a una interfaz prohibida, que a su vez supera a una interfaz que coincide simplemente. Por ejemplo, con eth*,!eth1,!eth2 lldpd solo usará interfaces que comiencen con eth, con la excepción de eth1 y eth2. Mientras que con *,!eth*,!!eth1 lldpcli utilizará todas las interfaces, excepto las interfaces que comiencen con eth, con la excepción de eth1. Cuando se encuentra una coincidencia exacta, se omiten algunas pruebas. Por ejemplo, si se especifica eth0.12, se aceptará aunque sea una interfaz VLAN.

unconfigure system interface pattern

Elimina cualquier patrón de interfaz configurado previamente y utiliza todas las interfaces físicas. Esta opción deshace la anterior.

configure system interface permanent pattern

Especifica las interfaces cuya configuración se mantiene de forma permanente por lldpd. Por defecto, lldpd ignora cualquier dato sobre las interfaces cuando se eliminan del sistema (estadísticas, configuración personalizada). Esta opción permite especificar un patrón similar al patrón de interfaz. Si una interfaz desaparece pero coincide con el patrón, sus datos se conservan en memoria y se reutilizan si la interfaz reaparece en algún momento. Por ejemplo, en Linux, se podría usar el patrón eth*,eno*,enp*, que debería coincidir con las interfaces fijas en la mayoría de los sistemas.

unconfigure system interface permanent

Elimina cualquier patrón de interfaz permanente configurado previamente. Se olvidará cualquier interfaz eliminada del sistema. Esta opción deshace la anterior.

configure system interface description

Algunos sistemas operativos permiten al usuario establecer una descripción para una interfaz. Al habilitar esta opción, lldpd podrá sobrescribir esta descripción con el nombre del vecino o con el número de vecinos encontrados.

unconfigure system interface description

No actualices la descripción de la interfaz con el nombre del vecino. Esta opción deshace la anterior.

configure system interface promiscuous

Habilita el modo promiscuo en las interfaces gestionadas.

Cuando la interfaz ya no es gestionada (o al salir de lldpd), la interfaz se deja en modo promiscuo, ya que es difícil saber si alguien más también la puso en modo promiscuo.

Se sabe que esta opción es útil cuando el switch remoto es un Cisco 2960 y la tarjeta de red local tiene aceleración de hardware VLAN. En este caso, es posible que no reciba tramas LLDP del switch remoto. La explicación más plausible es que la trama está etiquetada con alguna VLAN (normalmente VLAN 1) y la tarjeta de red filtra las VLAN. Esta no es la única solución disponible para solucionar este problema. Si le preocupan los problemas de rendimiento, también puede etiquetar la VLAN 1 en cada interfaz en su lugar.

Actualmente, esta opción no tiene ningún efecto en nada más que en Linux. En otros sistemas operativos, deshabilite la aceleración VLAN, etiquete la VLAN 1 o habilite el modo promiscuo manualmente en la interfaz.

unconfigure system interface promiscuous

No configures el modo promiscuo en las interfaces gestionadas. Esta opción no deshabilita el modo promiscuo en las interfaces que ya lo utilizan.

configure system ip management pattern pattern

Especifica las direcciones de gestión de este sistema como valores separados por comas (CSV). Al igual que con las interfaces (descritas anteriormente), esta opción puede usar comodines e inversiones. Sin esta opción, se utilizan la primera IPv4 y la primera IPv6. Si se proporciona una dirección IP exacta, se utiliza como dirección de gestión sin ninguna comprobación. Si solo se proporcionan patrones negativos, se elige una dirección IPv4 y una IPv6. De lo contrario, se pueden seleccionar muchas de ellas. Para eliminar direcciones IPv6, use !*:*. Si coincide un nombre de interfaz, se elegirá la primera dirección IPv4 y la primera dirección IPv6 asociadas a esa interfaz.

unconfigure system ip management pattern

Anula cualquier patrón específico para hacer coincidir las direcciones de gestión. Esta opción deshace la anterior.

configure system bond-slave-src-mac-type value

Establece el tipo de MAC de origen en los frames LLDP enviados en slaves de bond.

Los tipos válidos son:

real
MAC real del slave
zero
MAC de ceros
fixed
Un valor fijo arbitrario (00:60:08:69:97:ef)
local
MAC real con el bit de administración local establecido. Si la MAC real ya tiene el bit de administración local establecido, recurre al valor fijo.

El valor por defecto para bond-slave-src-mac-type es local. Algunos switches pueden quejarse al usar uno de los otros dos valores posibles (ya sea porque 00:00:00:00:00:00 no es una MAC válida o porque la dirección MAC está fluctuando de un puerto a otro). Usar local podría llevar a una dirección MAC duplicada en la red (pero esto es bastante improbable).

configure system max-neighbors neighbors

Cambia el número máximo de vecinos aceptados (para cada protocolo) en una interfaz. Este es un valor global. El valor por defecto es 32. Esta configuración solo se aplica a futuros vecinos.

configure lldp agent-type nearest-bridge | nearest-non-tpmr-bridge | nearest-customer-bridge

La dirección MAC de destino utilizada para enviar LLDPDU permite a un agente controlar la propagación de LLDPDU. Por defecto, se utiliza la dirección MAC 01:80:c2:00:00:0e y limita la propagación de LLDPDU al puente más cercano (nearest-bridge). Para indicar a lldpd que utilice en su lugar la dirección MAC 01:80:c2:00:00:03, use nearest-nontpmr-bridge en su lugar. Para utilizar en su lugar la dirección MAC 01:80:c2:00:00:00, use nearest-customer-bridge en su lugar.

configure lldp capabilities-advertisements

Habilita la publicidad del TLV de capacidades del chasis. Actualmente, es el valor por defecto.

unconfigure lldp capabilities-advertisements

Deshabilita la publicidad del TLV de capacidades del chasis.

configure lldp management-addresses-advertisements

Habilita la publicidad del TLV de direcciones de gestión. Actualmente, es el valor por defecto.

unconfigure lldp management-addresses-advertisements

Deshabilita la publicidad del TLV de direcciones de gestión.

configure lldp portidsubtype ifname | macaddress

configure [puertos ethX [,...]] lldp portidsubtype local valor

Fuerza el tipo de subtipo del ID del puerto. Por defecto, lldpd usará la dirección MAC como identificador del puerto y el nombre de la interfaz como descripción del puerto, a menos que la interfaz tenga un alias. En ese caso, el nombre de la interfaz se usará como identificador del puerto y la descripción será el alias de la interfaz. Con este comando, puedes forzar el identificador del puerto para que sea el nombre de la interfaz (con ifname), la dirección MAC (con macaddress) o un valor local (con local). En este último caso, se debe proporcionar el valor local.

configure [puertos ethX [,...]] lldp portdescription descripcion

Fuerza la descripción del puerto a la cadena proporcionada.

configure lldp tx-interval intervalo

Cambia el retardo de transmisión al valor especificado en segundos. El retardo de transmisión es el retardo entre dos transmisiones de PDU LLDP. El rango válido es de 1 a 3600 segundos. El valor por defecto es 30 segundos. Nota: lldpd también inicia otro temporizador de refresco del sistema en cada puerto para detectar cambios como el nombre de host. Este es el valor del intervalo de transmisión multiplicado por 20.

Puedes especificar un valor de intervalo en milisegundos añadiendo el sufijo "ms" a la cifra (por ejemplo, "configure lldp tx-interval 1500ms" son 1.5s, no 1500s). En este caso, el TTL para tramas LLDP recibidas y enviadas se redondea al segundo siguiente. Nota: el intervalo efectivo puede estar limitado por las capacidades del sistema operativo y la velocidad de la CPU.

configure lldp tx-hold retencion

Cambia el valor de retención de transmisión al valor especificado. Este valor se utiliza para calcular el TTL de los paquetes transmitidos, que es el producto de este valor y del retardo de transmisión. El rango válido es de 1 a 100. El valor por defecto es 4, por lo tanto, el TTL por defecto es de 120 segundos.

configure [puertos ethX [,...]] lldp status rx-and-tx | rx-only | tx-only | disabled

Configura el estado administrativo del puerto dado. Por defecto, todos los puertos se configuran en modo rx-and-tx. Esto significa que pueden recibir y transmitir tramas LLDP (así como otros protocolos si es necesario). En modo rx-only, no emitirán ninguna trama y en modo tx-only, no recibirán ninguna trama. En modo disabled, no se enviará ninguna trama y se descartará cualquier trama entrante. Esta configuración no anula el modo operativo del demonio principal. Si está configurado en modo solo de recepción (con la bandera -r), la configuración de cualquier modo de transmisión no tendrá ningún efecto.

configure [puertos ethX [,...]] lldp vlan-tx vlan_id [prio prioridad [dei dei]]

Configura el puerto dado para enviar tramas LLDP a través de una VLAN especificada. Con el Identificador de VLAN (VID) como vlan_id, el Punto de Código de Prioridad (PCP) como prioridad y el Indicador Elegible para Descarte (DEI) como dei. lldpd acepta tramas LLDP en todas las VLAN.

configure [puertos ethX [,...]] lldp custom-tlv [add | replace] oui oui subtype subtipo [oui-info contenido]

Emite un TLV personalizado para OUI oui, con subtipo subtipo y opcionalmente con los bytes especificados en contenido. Tanto oui como contenido deben ser una lista separada por comas de bytes en formato hexadecimal. oui debe tener exactamente 3 bytes de longitud. Si se especifica add, el TLV se añadirá. Esta es la acción por defecto. Si se especifica replace, se reemplazarán todos los TLVs con el mismo oui y subtipo.

unconfigure [puertos ethX [,...]] lldp custom-tlv [oui oui] [subtype subtipo]

Cuando no se especifica oui, elimina todos los TLVs personalizados configurados previamente. Cuando se especifica OUI oui y subtipo subtipo, elimina instancias específicas del TLV personalizado.

configure [puertos ethX [,...]] lldp vlan-advertisements pattern patron

Configura los anuncios de VLAN para el puerto dado como valores separados por comas (CSV). Al igual que para las interfaces (descritas anteriormente), esta opción puede usar comodines e inversiones. Sin esta opción, lldpd anunciará todas las VLAN.

unconfigure [puertos ethX [,...]] lldp vlan-advertisements pattern

Elimina cualquier patrón de anuncios de VLAN configurado previamente para el puerto dado.

configure lldp fast-start enable | tx-interval intervalo

Configura el mecanismo de inicio rápido de LLDP. Cuando se detecta un nuevo vecino LLDP, el inicio rápido permite a lldpd acortar el intervalo entre dos LLDPDU. enable debería habilitar el inicio rápido de LLDP mientras que tx-interval especifica el intervalo entre dos LLDPDU en segundos. El rango de intervalo válido es de 1 a 3600 segundos. El intervalo por defecto es 1 segundo. Una vez que se han enviado 4 LLDPDU, el mecanismo de inicio rápido se deshabilita hasta que se detecta un nuevo vecino.

unconfigure lldp fast-start

Deshabilita el mecanismo de inicio rápido de LLDP.

configure [puertos ethX [,...]] med location coordinate latitude latitud longitude longitud altitude altitud unidad datum datum

Anuncia una ubicación basada en coordenadas en los puertos dados (o en todos los puertos si no se especifica ninguno). El formato de latitud es un número decimal flotante seguido de N o S. El formato de longitud es un número decimal flotante seguido de E o O. altitud es un número decimal flotante seguido de m (cuando se expresa en metros) o f (cuando se expresa en pisos). Se espera un espacio entre el número flotante y la unidad. datum es uno de los siguientes valores:
  • WGS84
  • NAD83
  • NAD83/MLLW

Un uso válido de este comando es:

configure ports eth0 med location coordinate latitude 48.85667N longitude 2.2014E altitude 117.47 m datum WGS84

configure [puertos ethX [,...]] med location address country pais [tipo valor [...]]

Anuncia una dirección cívica en los puertos dados (o en todos los puertos si no se especifica ninguno). pais es el código de dos letras que representa el país. Los argumentos restantes deben emparejarse para formar la dirección. El primer miembro de cada par indica el tipo del segundo miembro, que es texto libre. Aquí está la lista de tipos válidos:
  • language
  • country-subdivision
  • county
  • city
  • city-division
  • block
  • street
  • direction
  • trailing-street-suffix
  • street-suffix
  • number
  • number-suffix
  • landmark
  • additional
  • name
  • zip
  • building
  • unit
  • floor
  • room
  • place-type
  • script

Un uso válido de este comando es:

configure ports eth1 med location address country US street "Commercial Road" city "Roseville"

configure [puertos ethX [,...]] med location elin numero

Anuncia la disponibilidad de un número ELIN. Esto se utiliza para configurar llamadas de emergencia. Si el número proporcionado es demasiado pequeño, se rellenará con 0. Aquí tienes un ejemplo de uso:
configure ports eth2 med location elin 911

configure [puertos ethX [,...]] med policy application aplicacion [unknown] [tagged] [vlan vlan] [priority prioridad] [dscp dscp]

Anuncia una política de red específica para los puertos dados (o para todos los puertos si no se proporcionó ninguno). Solo el tipo de aplicación es obligatorio. aplicacion debe ser uno de los siguientes valores:
  • voice
  • voice-signaling
  • guest-voice
  • guest-voice-signaling
  • softphone-voice
  • video-conferencing
  • st
list: - item: med subitems: - item: policy subitems: - item: application subitems: - item: unknown - item: video-streaming - item: video-signaling

The unknown flag indica que la política de red para el tipo de aplicación especificado es requerida por el dispositivo pero actualmente es desconocida. Esto es utilizado por los Dispositivos de Punto Final, no por los Dispositivos de Conectividad de Red. Si no se especifica, la política de red para el tipo de aplicación dado está definida.

Un VLAN especificado con vlan indica qué ID de VLAN 802.1q debe anunciarse para la política de red. Un valor válido está entre 1 y 4094. tagged indica que el VLAN debe ser etiquetado para el tipo de aplicación especificado.

priority permite especificar la Prioridad de Capa 2 IEEE 802.1d / IEEE 802.1p, también conocida como Clase de Servicio (CoS), que debe usarse para el tipo de aplicación especificado. Este campo generalmente se ignora si no se especifica ningún VLAN. Los nombres coinciden con el estándar 802.1D-2004 (tabla G-2). Algunos estándares más recientes pueden usar etiquetas diferentes. Solo los valores numéricos deben ser confiables. Las etiquetas aceptadas son:

1
background
0
best-effort
2
excellent-effort
3
critical-applications
4
video
5
voice
6
internetwork-control
7
network-control

dscp representa el valor DSCP que debe anunciarse para la política de red dada. Punto de Código de Servicios Diferenciados/DiffServ (DSCP) como se define en la RFC 2474 de IETF para el tipo de aplicación especificado. Valor: 0 (predeterminado por RFC 2475) a 63. Nota: Los valores DSCP del selector de clase son retrocompatibles para dispositivos que solo admiten el formato antiguo de Tipo de Servicio (ToS) de precedencia IP. (Consulte las RFC para ver qué significan estos valores)

Un uso válido de este comando es:

configure med policy application voice vlan 500 priority voice dscp 46

configure [ports ethX [,...]] med power pse | pd source source priority priority value value

Anuncia el TLV LLDP-MED POE-MDI para los puertos dados o para todas las interfaces si no se proporciona ningún puerto. Se puede actuar como un PD (consumidor de energía) o un PSE (proveedor de energía). No se realiza ninguna verificación sobre la validez de los parámetros, aunque LLDP-MED requiere algunas restricciones:
  • El PD nunca debe solicitar más energía que la clase física 802.3af.
  • El PD nunca debe consumir más de la potencia máxima anunciada por el PSE.
  • El PSE no debe reducir la potencia asignada al PD cuando esta potencia está en uso.
  • El PSE puede solicitar una potencia reducida utilizando el modo de conservación.
  • Ser PSE o PD es un parámetro global, no un parámetro por puerto. lldpcli no impone esto: un puerto puede configurarse como PD o PSE. LLDP-MED también requiere que un PSE tenga una sola fuente de alimentación (primaria o de respaldo). Nuevamente, lldpcli no impone esto. Cada puerto puede tener su propia fuente de alimentación. Lo mismo se aplica para PD y prioridad de energía. La MIB de LLDP-MED no permite este tipo de representación.

Los tipos válidos son:

pse
Entidad de Suministro de Energía (proveedor de energía)
pd
Dispositivo de Energía (consumidor de energía)

Las fuentes válidas son:

unknown
Desconocida
primary
Para PSE, la fuente de alimentación es la fuente de alimentación primaria.
backup
Para PSE, la fuente de alimentación es la fuente de alimentación de respaldo, o se solicita un modo de conservación de energía (el PSE puede estar funcionando con UPS, por ejemplo).
pse
Para PD, la fuente de alimentación es el PSE.
local
Para PD, la fuente de alimentación es una fuente local.
both
Para PD, la fuente de alimentación es tanto el PSE como una fuente local.

Las prioridades válidas son:

unknown
Prioridad desconocida
critical
Crítica
high
Alta
low
Baja

value debe ser la potencia total en milivatios requerida por el dispositivo PD o disponible por el dispositivo PSE.

Aquí hay un ejemplo de uso:

configure med power pd source pse priority high value 5000

configure [ports ethX [,...]] dot3 power pse | pd [supported] [enabled] [paircontrol] powerpairs powerpairs [class class] [type type source source priority priority requested requested allocated allocated]

Anuncia el TLV Dot3 POE-MDI para el puerto dado o para todos los puertos si no se proporcionó ninguno. Se puede actuar como un PD (consumidor de energía) o un PSE (proveedor de energía). Esta configuración es distinta de la configuración de la transmisión del TLV LLDP-MED POE-MDI, pero el usuario debe asegurar la coherencia de estas dos configuraciones si se usan juntas.

supported significa que la alimentación MDI es compatible en el puerto dado, mientras que enabled significa que la alimentación MDI está habilitada. paircontrol se utiliza para indicar si el control de la selección de pares está disponible. Los valores válidos para powerpairs son:

signal
Solo los pares de señal están en uso.
spare
Solo los pares de repuesto están en uso.

Cuando se especifica, class es class-, sufijado con un número del 0 al 4. Ej. class-0, class-1, class-2, class-3, class

dot3 power pse class

This command is only available when lldpd is compiled with the -DENABLE_LLDPMED option.

Define the class of power to be supplied by the PSE port port. The class is used to indicate the maximum power that the PSE port is able to supply. The default value is 4 for 802.3at. The class class is a number between 0 and 4. See the IEEE 802.3at standard for more information.

For 802.3at, the classes are as follows:

0
Default (Unspecified), PD 0.44-12.95 W, PSE 15.4 W
1
Very Low Power Device, PD 0.44-3.84 W, PSE 4.0 W
2
Low Power Device, PD 3.84-6.49 W, PSE 7.0 W
3
Mid Power Device, PD 6.49-12.95 W, PSE 15.4 W
4
High Power Device (PoE+), PD 12.95-25.5 W, PSE 30.0 W

The remaining parameters are in conformance with 802.3at and are optional. type should be either 1 or 2, indicating whether the device conforms to 802.3at type 1 or 802.3at type 2. Values of source and priority are the same as for LLDP-MED POE-MDI TLV. requested and allocated are expressed in milliwats.

Here are two valid uses of this command:

configure ports eth3 dot3 power pse supported enabled paircontrol powerpairs spare class class-3
configure dot3 power pd supported enabled powerpairs spare class class-3 type 1 source pse priority low requested 10000 allocated 15000

pause

Pause lldpd operations. lldpd will not send or receive any more frames. This can be undone with resume command. This only works interactively as lldpd asks lldpcli to unpause after reading the configuration file.

resume

Resume lldpd operations. lldpd will start to send and receive frames. This command is issued internally after processing the configuration but can be used at any time if a manual pause command is issued.
