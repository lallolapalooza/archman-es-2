Paquete: llvm

Licencias: Apache-2.0 WITH LLVM-exception

LLVM-SYMBOLIZER(1) LLVM LLVM-SYMBOLIZER(1)

NOMBRE

llvm-symbolizer - convierte direcciones en ubicaciones de código fuente

SINOPSIS

llvm-symbolizer [opciones] [direcciones...]

DESCRIPCIÓN

llvm-symbolizer lee nombres y direcciones de entrada desde la línea de comandos e imprime las ubicaciones de código fuente correspondientes en la salida estándar. También puede simbolizar registros que contienen Marcado de Simbolizador <> a través de --filter-markup. Las direcciones pueden especificarse como números o nombres de símbolos.

Si no se especifica ninguna dirección en la línea de comandos, lee las direcciones de la entrada estándar. Si no se especifica ningún nombre de entrada en la línea de comandos, pero sí direcciones, el primer valor de dirección se trata como un nombre de entrada. Si un valor de entrada no se reconoce, informa que no se encontró información de origen.

Los nombres de entrada se pueden especificar junto con las direcciones, ya sea en la entrada estándar o como argumentos posicionales en la línea de comandos. Por defecto, los nombres de entrada se interpretan como rutas de archivos objeto. Sin embargo, prefijar un nombre con BUILDID: indica que es un ID de compilación hexadecimal en lugar de una ruta. Esto buscará el binario de depuración correspondiente. Para consistencia, prefijar un nombre con FILE: indica explícitamente que es una ruta de archivo objeto (el valor predeterminado).

Un argumento posicional o un valor de entrada estándar puede ir precedido por "DATA" o "CODE" para indicar que la dirección debe ser simbolizada como datos o código ejecutable respectivamente. Si no se especifica ninguno, se asume "CODE". Los datos se simbolizan como dirección y tamaño de símbolo en lugar de número de línea.

llvm-symbolizer analiza las opciones de la variable de entorno LLVM_SYMBOLIZER_OPTS después de analizar las opciones de la línea de comandos. LLVM_SYMBOLIZER_OPTS es útil principalmente para complementar las opciones de la línea de comandos cuando llvm-symbolizer es invocado por otro programa o tiempo de ejecución.

EJEMPLOS

Todos los siguientes ejemplos utilizan los dos siguientes archivos fuente como entrada. Utilizan una mezcla de enlace estilo C y estilo C++ para ilustrar cómo se imprimen estos nombres de manera diferente (ver --demangle).

// test.h
extern "C" inline int foz() {
  return 1234;
}
// test.cpp
#include "test.h"
int bar=42;
int foo() {
  return bar;
}
int baz() {
  volatile int k = 42;
  return foz() + k;
}
int main() {
  return foo() + baz();
}

Estos archivos se compilan de la siguiente manera:

$ clang -g test.cpp -o test.elf
$ clang -g -O2 test.cpp -o inlined.elf

Ejemplo 1 - direcciones y objeto en la línea de comandos:

$ llvm-symbolizer --obj=test.elf 0x4004d0 0x400490
foz
/tmp/test.h:1:0
baz()
/tmp/test.cpp:11:0

Ejemplo 2 - direcciones en la entrada estándar:

$ cat addr.txt
0x4004a0
0x400490
0x4004d0
$ llvm-symbolizer --obj=test.elf < addr.txt
main
/tmp/test.cpp:15:0
baz()
/tmp/test.cpp:11:0
foz
/tmp/./test.h:1:0

Ejemplo 3 - objeto especificado con dirección:

$ llvm-symbolizer "test.elf 0x400490" "FILE:inlined.elf 0x400480"
baz()
/tmp/test.cpp:11:0
foo()
/tmp/test.cpp:8:10
$ cat addr2.txt
FILE:test.elf 0x4004a0
inlined.elf 0x400480
$ llvm-symbolizer < addr2.txt
main
/tmp/test.cpp:15:0
foo()
/tmp/test.cpp:8:10

Ejemplo 4 - prefijos BUILDID y FILE:

$ llvm-symbolizer "FILE:test.elf 0x400490" "DATA BUILDID:123456789abcdef 0x601028"
baz()
/tmp/test.cpp:11:0
bar
6295592 4
$ cat addr3.txt
FILE:test.elf 0x400490
DATA BUILDID:123456789abcdef 0x601028
$ llvm-symbolizer < addr3.txt
baz()
/tmp/test.cpp:11:0
bar
6295592 4

Ejemplo 5 - prefijos CODE y DATA:

$ llvm-symbolizer --obj=test.elf "CODE 0x400490" "DATA 0x601028"
baz()
/tmp/test.cpp:11:0
bar
6295592 4
$ cat addr4.txt
CODE test.elf 0x4004a0
DATA inlined.elf 0x601028
$ llvm-symbolizer < addr4.txt
main
/tmp/test.cpp:15:0
bar
6295592 4

Ejemplo 6 - opciones de estilo de ruta:

Este ejemplo utiliza el mismo archivo fuente que el anterior, pero la ruta completa del archivo fuente es /tmp/foo/test.cpp y se compila de la siguiente manera. El primer caso muestra la ruta absoluta predeterminada, el segundo --basenames, y el tercero muestra --relativenames.

$ pwd
/tmp
$ clang -g foo/test.cpp -o test.elf
$ llvm-symbolizer --obj=test.elf 0x4004a0
main
/tmp/foo/test.cpp:15:0
$ llvm-symbolizer --obj=test.elf 0x4004a0 --basenames
main
test.cpp:15:0
$ llvm-symbolizer --obj=test.elf 0x4004a0 --relativenames
main
foo/test.cpp:15:0

Ejemplo 7 - Direcciones como nombres de símbolos:

$ llvm-symbolizer --obj=test.elf main
main
/tmp/test.cpp:14:0
$ llvm-symbolizer --obj=test.elf "CODE foz"
foz
/tmp/test.h:1:0

Ejemplo 8 - salida de --skip-line-zero para una dirección sin correspondencia de línea (una dirección asociada con la línea cero):

// test.c
int foo = 0;
int x = 1234;
int main() {
  if (x)
    return foo;
  else
    return x;
}

Estos archivos se compilan de la siguiente manera:

$ clang -g -O2 -S test.c -o test.s
$ llvm-mc -filetype=obj -triple=x86_64-unknown-linux  test.s -o test.o
$ llvm-symbolizer --obj=test.o --skip-line-zero 0xa
main
/tmp/test.c:5:7 (aproximado)

OPCIONES

--adjust-vma <offset>
Suma el desplazamiento especificado a las direcciones del archivo objeto al realizar búsquedas. Esto se puede usar para realizar búsquedas como si el objeto hubiera sido reubicado por el desplazamiento.
--skip-line-zero
Si una dirección no tiene un número de línea asociado, utiliza el último número de línea de la secuencia actual en la tabla de líneas. Dichas líneas se etiquetan como "aproximadas" en la salida, ya que pueden ser engañosas.
--basenames, -s
Imprime solo el nombre del archivo sin directorios, en lugar de la ruta absoluta.
--build-id
Busca el objeto utilizando el ID de compilación dado, especificado como una cadena hexadecimal. Mutuamente excluyente con --obj.
--color [=<siempre|auto|nunca>]
Especifica si se debe usar color en el modo --filter-markup. El valor predeterminado es auto, que detecta si la salida estándar admite color. Especificar --color solo es equivalente a --color=siempre.
--debug-file-directory <ruta>
Proporciona una ruta a un directorio con un subdirectorio .build-id para buscar información de depuración para binarios eliminados. Se buscan múltiples instancias de este argumento en el orden dado.
--debuginfod, --no-debuginfod
Si se deben o no intentar búsquedas de debuginfod para binarios de depuración. A menos que se especifique, debuginfod solo se habilita si libcurl se compiló (LLVM_ENABLE_CURL) y al menos una URL de servidor fue proporcionada por la variable de entorno DEBUGINFOD_URLS.
--demangle, -C
Imprime nombres de funciones desenmascarados, si los nombres están enmascarados (por ejemplo, el nombre enmascarado _Z3bazv se convierte en baz(), mientras que el nombre no enmascarado foz se imprime tal cual). El valor predeterminado es verdadero.
--dwp <ruta>

NAME

llvm-symbolizer — a utility to convert raw addresses into human-readable code locations

SYNOPSIS

llvm-symbolizer [-h | --help] [-v | --version] [--output-style <LLVM|GNU|JSON>] [-f [=short|linkage]] [-i | --inlining] [--no-inlines] [--no-demangle] [-e <objfile>] [--obj <objfile>] [--build-id <build-id>] [--default-arch <arch>] [--dsym-hint <path/to/file.dSYM>] [--fallback-debug-path <path>] [--filter-markup] [-p | --pretty-print] [-a | --print-address] [--print-source-context-lines <N>] [--relativenames] [--verbose] [--dia] [<addresses> ...]

DESCRIPTION

The llvm-symbolizer utility is a tool that reads addresses from standard input or from the command line and converts them into human-readable code locations (file name, function name, and line number). It uses debug information (like DWARF or Mach-O) embedded in object files to perform this translation. The tool is often used in conjunction with crash reporting or debugging tools to diagnose issues by translating raw memory addresses found in stack traces into meaningful source code locations.

OPTIONS

--build-id <build-id>
Specify the build ID of the object file to symbolize. This is useful when the object file itself is not available, but its build ID is known. Mutually exclusive with --obj.
--compile-dir <path>
If the debug information contains relative paths, use the specified path as the base directory to reconstruct the absolute path to the source file. Defaults to the current directory.
--debug-file <path>
Path to the separate debug file (e.g. a file with a -dbg suffix). When a separate file contains debug data, and is referenced by a GNU debug link section, use the specified file as the debug data. If the file is not found, it is assumed to be relative to the specified DWP file at <path> for any CUs that have split DWARF debug data.
--fallback-debug-path <path>
When a separate file contains debug data, and is referenced by a GNU debug link section, use the specified path as a basis for locating the debug data if it cannot be found relative to the object.
--filter-markup
Reads from standard input, converts contained Symbolizer Markup <> into human-readable form, and prints the results to standard output. The following markup elements are not yet supported:
  • {{{hexdict}}}
  • {{{dumpfile}}}

The {{{bt}}} backtrace element reports frames using the following syntax:

#<number>[.<inline>] <address> <function> <file>:<line>:<col> (<module>+<relative address>)

<inline> provides frame numbers for calls inlined into the caller corresponding to <number>. The inlined call numbers start at 1 and increase from callee to caller.

<address> is an address inside the call instruction to the function. The address may not be the start of the instruction. <relative address> is the corresponding virtual offset in the <module> loaded at that address.

--functions [=<none|short|linkage>], -f
Specify the way function names are printed (omit function name, print short function name, or print full linkage name, respectively). Defaults to linkage.
--help, -h
Show help and usage for this command.
--inlining, --inlines, -i
If a source code location is in an inlined function, prints all the inlined frames. This is the default.
--no-inlines
Don't print inlined frames.
--no-demangle
Don't print demangled function names.
--obj <path>, --exe, -e
Path to object file to be symbolized. If - is specified, read the object directly from the standard input stream. Mutually exclusive with --build-id.
--output-style <LLVM|GNU|JSON>
Specify the preferred output style. Defaults to LLVM. When the output style is set to GNU, the tool follows the style of GNU's addr2line. The differences from the LLVM style are:
  • Does not print the column of a source code location.
  • Does not add an empty line after the report for an address.
  • Does not replace the name of an inlined function with the name of the topmost caller when inlined frames are not shown.
  • Prints an address's debug-data discriminator when it is non-zero. One way to produce discriminators is to compile with clang's -fdebug-info-for-profiling.
JSON style provides a machine readable output in JSON. If addresses are
supplied via stdin, the output JSON will be a series of individual objects. Otherwise, all results will be contained in a single array.
$ llvm-symbolizer --obj=inlined.elf 0x4004be 0x400486 -p
baz() at /tmp/test.cpp:11:18
 (inlined by) main at /tmp/test.cpp:15:0
foo() at /tmp/test.cpp:6:3
$ llvm-symbolizer --output-style=LLVM --obj=inlined.elf 0x4004be 0x400486 -p --no-inlines
main at /tmp/test.cpp:11:18
foo() at /tmp/test.cpp:6:3
$ llvm-symbolizer --output-style=GNU --obj=inlined.elf 0x4004be 0x400486 -p --no-inlines
baz() at /tmp/test.cpp:11
foo() at /tmp/test.cpp:6
$ clang -g -fdebug-info-for-profiling test.cpp -o profiling.elf
$ llvm-symbolizer --output-style=GNU --obj=profiling.elf 0x401167 -p --no-inlines
main at /tmp/test.cpp:15 (discriminator 2)
$ llvm-symbolizer --output-style=JSON --obj=inlined.elf 0x4004be 0x400486 -p

--pretty-print, -p
Print human readable output. If --inlining is specified, the enclosing scope is prefixed by (inlined by). For JSON output, the option will cause JSON to be indented and split over new lines. Otherwise, the JSON output will be printed in a compact form.
$ llvm-symbolizer --obj=inlined.elf 0x4004be --inlining --pretty-print
baz() at /tmp/test.cpp:11:18
 (inlined by) main at /tmp/test.cpp:15:0
--print-address, --addresses, -a
Print address before the source code location. Defaults to false.
$ llvm-symbolizer --obj=inlined.elf --print-address 0x4004be
0x4004be
baz()
/tmp/test.cpp:11:18
main
/tmp/test.cpp:15:0
$ llvm-symbolizer --obj=inlined.elf 0x4004be --pretty-print --print-address
0x4004be: baz() at /tmp/test.cpp:11:18
 (inlined by) main at /tmp/test.cpp:15:0
--print-source-context-lines <N>
Print N lines of source context for each symbolized address.
$ llvm-symbolizer --obj=test.elf 0x400490 --print-source-context-lines=3
baz()
/tmp/test.cpp:11:0
10  :   volatile int k = 42;
11 >:   return foz() + k;
12  : }
--relativenames
Print the file's path relative to the compilation directory, instead of the absolute path. If the command-line to the compiler included the full path, this will be the same as the default.
--verbose
Print verbose address, line and column information.
$ llvm-symbolizer --obj=inlined.elf --verbose 0x4004be
baz()
  Filename: /tmp/test.cpp
  Function start filename: /tmp/test.cpp
  Function start line: 9
  Function start address: 0x4004b6
  Line: 11
  Column: 18
main
  Filename: /tmp/test.cpp
  Function start filename: /tmp/test.cpp
  Function start line: 14
  Function start address: 0x4004b0
  Line: 15
  Column: 18
--version, -v
Print version information for the tool.
@<FILE>
Read command-line options from response file <FILE>.

WINDOWS/PDB SPECIFIC OPTIONS

--dia
Use the Windows DIA SDK for symbolization. If the DIA SDK is not found, llvm-symbolizer will fall back to the native implementation.

MACH-O SPECIFIC OPTIONS

--default-arch <arch>
If a binary contains object files for multiple architectures (e.g. it is a Mach-O universal binary), symbolize the object file for a given architecture. You can also specify the architecture by writing binary_name:arch_name in the input (see example below). If the architecture is not specified in either way, the address will not be symbolized. Defaults to empty string.
$ cat addr.txt
/tmp/mach_universal_binary:i386 0x1f84
/tmp/mach_universal_binary:x86_64 0x100000f24
$ llvm-symbolizer < addr.txt
_main
/tmp/source_i386.cc:8
_main
/tmp/source_x86_64.cc:8
--dsym-hint <path/to/file.dSYM>
If the debug info for a binary isn't present in the default location, look for the debug info at the .dSYM path provided via this option. This flag can be used multiple times.

EXIT STATUS

llvm-symbolizer returns 0. Other exit codes imply an internal program error.
