SINOPSIS

llvm-debuginfo-analyzer [opciones] [nombre_archivo ...]

DESCRIPCIÓN

llvm-debuginfo-analyzer analiza las secciones de depuración y texto en archivos objeto binarios e imprime su contenido en una vista lógica, que es una representación legible por humanos que se asemeja mucho a la estructura del código fuente original del usuario. Los formatos de archivo objeto compatibles incluyen ELF, Mach-O, WebAssembly, PDB y COFF.

La vista lógica abstrae la complejidad asociada con las diferentes representaciones de bajo nivel de la información de depuración que está incrustada en el archivo objeto. llvm-debuginfo-analyzer produce una vista canónica de la información de depuración independientemente de cómo esté formateada. Se verá la misma vista lógica independientemente del formato del archivo objeto, asumiendo que la información de depuración representa correctamente el mismo código fuente original.

La vista lógica incluye los siguientes elementos lógicos: tipo, ámbito, símbolo y línea, que son los elementos básicos de software utilizados en el lenguaje de programación C/C++. Cada elemento lógico tiene un conjunto de atributos, como tipos, clases, funciones, variables, parámetros, etc. La opción --attribute se puede utilizar para especificar qué atributos incluir al imprimir un elemento lógico. Un elemento lógico puede tener un tipo (kind) que describe tipos específicos de elementos. Por ejemplo, un ámbito podría tener un valor de tipo (kind) de función, clase, espacio de nombres.

llvm-debuginfo-analyzer imprime por defecto un diseño predefinido de elementos lógicos y atributos. Las opciones de línea de comandos se pueden usar para controlar los elementos impresos (--print), usar un diseño específico (--report), coincidir con un patrón dado (--select, --select-offsets). Además, la salida se puede limitar a elementos lógicos especificados usando (--select-lines, --select-scopes, --select-symbols, --select-types).

llvm-debuginfo-analyzer también puede comparar un conjunto de vistas lógicas (--compare), para encontrar diferencias e identificar posibles problemas de sintaxis en la información de depuración (--warning) en cualquier archivo objeto.

OPCIONES

Las opciones de llvm-debuginfo-analyzer se dividen en varias categorías, cada una adaptada a un propósito diferente:

  • GENERAL - Opciones estándar de LLVM para mostrar ayuda, versión, etc.
  • ATRIBUTOS - Describe cómo incluir diferentes detalles al imprimir un elemento.
  • IMPRIMIR - Especifica qué elementos se incluirán al imprimir la vista.
  • SALIDA - Describe los formatos compatibles al imprimir la vista.
  • INFORME - Describe los diseños de formato para la impresión de la vista.
  • SELECCIÓN - Permite usar criterios o condiciones específicas para seleccionar qué elementos imprimir.
  • COMPARAR - Compara vistas lógicas e imprime elementos faltantes y/o añadidos.
  • ADVERTENCIA - Imprime las advertencias detectadas durante la creación de la vista.
  • INTERNO - Análisis interno de la vista lógica.

PRELIMINARIES

The llvm-debuginfo-analyzer utility displays the debug information included in the given binary files. The information is presented as a logical view of the different entities that are represented in the debug information.

The utility can be invoked in two different modes:

1.
The default mode analyzes and prints a logical view of the debug information. The view is determined by the options that are selected. See the PRELIMINARIES, SELECTION, ELEMENTS, LINES, SCOPES, SYMBOLS and TYPES sections.
2.
The comparison mode always uses the view layout.

SELECTION

When printing an element, different data can be included and it varies (--attribute) from data directly associated with the binary file (offset) to high level details such as coverage, lexical scope level, location. As the printed output can reach a considerable size, several selection options, enable printing of specific elements.

The pattern matching can ignore the case (--select-nocase) and be extended to use regular expressions (--select-regex).

ELEMENTS

The following options allow printing of elements that match the given <pattern>, offset <value> or an element <condition>.

--select=<pattern>
Print all elements whose name or line number matches the given <pattern>.
--select-offsets=<value[,value,...]>
Print all elements whose offset matches the given values. See --attribute option.
--select-elements=<condition[,condition,...]>
Print all elements that satisfy the given <condition>. With condition being one of the options in the following list.
=discarded: Discarded elements by the linker.
=global: Element referenced across Compile Units.
=optimized: Optimized inlined abstract references.
--select-nocase
Pattern matching is case-insensitive when using --select.
--select-regex
Treat any <pattern> strings as regular expressions when selecting with --select option. If --select-nocase is specified, the regular expression becomes case-insensitive.

If the <pattern> criteria is too general, a more selective option can be specified to target a particular category of elements: lines (--select-lines), scopes (--select-scopes), symbols (--select-symbols) and types (--select-types).

These options require knowledge of the debug information format (DWARF, CodeView), as the given kind describes a very specific type of element.

LINES

The following options allow printing of lines that match the given <kind>. The given criteria describes the debug line state machine registers.

--select-lines=<kind[,kind,...]>
With kind being one of the options in the following list.

=BasicBlock: Marks a new basic block.
=Discriminator: Line that has a discriminator.
=EndSequence: Marks the end in the sequence of lines.
=EpilogueBegin: Marks the start of a function epilogue.
=LineAssembler: Lines that correspond to disassembly text.
=LineDebug: Lines that correspond to debug lines.
=NeverStepInto: marks a never step into.
=NewStatement: Marks a new statement.
=PrologueEnd: Marks the end of a function prologue.

COMPARE

When dealing with debug information, there are situations when the printing of the elements is not the correct approach. That is the case, when we are interested in the effects caused by different versions of the same toolchain, or the impact of specific compiler optimizations.

For those cases, we are looking to see which elements have been added or removed. Due to the complicated debug information format, it is very difficult to use a regular diff tool to find those elements; even impossible when dealing with different debug formats.

llvm-debuginfo-analyzer supports a logical element comparison, allowing to find semantic differences between logical views, produced by different toolchain versions or even debug information formats.

When comparing logical views created from different debug formats, its accuracy depends on how close the debug information represents the user code. For instance, a logical view created from a binary file with DWARF debug information may include more detailed data than a logical view created from a binary file with CodeView debug information.

The following options describe the elements to compare.

--compare=<value[,value,...]>
With value being one of the options in the following list.
=all: Include all the below elements.
=lines: Include lines.
=scopes: Include scopes.
=symbols: Include symbols.
=types: Include types.

llvm-debuginfo-analyzer takes the first binary file on the command line as the reference and the second one as the target. To get a more descriptive report, the comparison is done twice. The reference and target views are swapped, in order to produce those missing elements from the target view and those added elements to the reference view.

See --report options on how to describe the comparison reports.

WARNING

When reading the input object files, llvm-debuginfo-analyzer can detect issues in the raw debug information. These may not be considered fatal to the purpose of printing a logical view but they can give an indication about the quality and potentially expose issues with the generated debug information.

The following options describe the warnings to be recorded for later printing, if they are requested by --print.

--warning=<value[,value,...]>
With value being one of the options in the following list.
=all: Include all the below warnings.

The following options collect additional information during the creation of the logical view, to include invalid coverage values and locations for symbols; invalid code ranges; lines that are zero.

=coverages: Invalid symbol coverages values.
=lines: Debug lines that are zero.
=locations: Invalid symbol locations.
=ranges: Invalid code ranges.

INTERNAL

For a better understanding of the logical view, access to more detailed internal information could be needed. Such data would help to identify debug information processed or incorrect logical element management. Typically these kind of options are available only in debug builds.

llvm-debuginfo-analyzer supports these advanced options in both release and debug builds.

--internal=<valor[,valor,...]>
Siendo valor una de las opciones de la siguiente lista.
=all: Incluye todas las opciones de abajo.

Las siguientes opciones permiten verificar la integridad de la vista lógica; recopilar las etiquetas de depuración que se procesan o no se implementan; ignorar el número de línea del elemento lógico, para facilitar la comparación de la vista lógica al usar herramientas de comparación externas; imprimir las opciones de la línea de comandos utilizadas para invocar llvm-debuginfo-analyzer.

=id: Imprime el ID único del elemento.
=cmdline: Imprime la línea de comandos.
=integrity: Verifica la integridad de los elementos.
=none: Ignora el número de línea del elemento.
=tag: Etiquetas de información de depuración.

Nota: Para el formato ELF, las etiquetas recopiladas representan las etiquetas de depuración que no se procesan. Para el formato PE/COFF, representan las etiquetas que se procesan.

MODO DE COMPARACIÓN

En este modo, llvm-debuginfo-analyzer compara vistas lógicas para producir un informe con los elementos lógicos que faltan o se agregaron. Esta es una ayuda muy poderosa para encontrar diferencias semánticas en la información de depuración producida por diferentes versiones de la cadena de herramientas o incluso por cadenas de herramientas completamente diferentes (Por ejemplo, un compilador que produce DWARF se puede comparar directamente con un compilador completamente diferente que produce CodeView).

Dado el ejemplo anterior, encontramos el problema de información de depuración anterior (relacionado con la ubicación de ámbito incorrecta anterior para el 'typedef int INTEGER') comparando con otro compilador.

Usando GCC para generar test-dwarf-gcc.o, podemos aplicar un patrón de selección con el modo de impresión para obtener la siguiente salida de vista lógica.

llvm-debuginfo-analyzer --attribute=level
                        --select-regex --select-nocase --select=INTe
                        --report=list
                        --print=symbols,types
                        test-dwarf-clang.o test-dwarf-gcc.o
Vista Lógica:
[000]           {File} 'test-dwarf-clang.o'
[001]           {CompileUnit} 'test.cpp'
[003]     4     {TypeAlias} 'INTEGER' -> 'int'
[004]     5     {Variable} 'CONSTANT' -> 'const INTEGER'
Vista Lógica:
[000]           {File} 'test-dwarf-gcc.o'
[001]           {CompileUnit} 'test.cpp'
[004]     4     {TypeAlias} 'INTEGER' -> 'int'
[004]     5     {Variable} 'CONSTANT' -> 'const INTEGER'

La salida muestra que ambos objetos contienen los mismos elementos. Pero el objeto generado por GCC muestra '4', que es el valor correcto, mientras que el 'typedef INTEGER' se encuentra en un nivel de ámbito diferente.

Tenga en cuenta que no hay ningún requisito de que GCC deba producir DWARF idéntico o similar a Clang para permitir la comparación. Solo estamos comparando la semántica. El mismo caso al comparar la información de depuración de CodeView generada por MSVC y Clang.

Hay 2 métodos de comparación: vista lógica y elementos lógicos.

VISTA LÓGICA

Compara la vista lógica como una unidad completa; para que coincida, cada elemento lógico comparado debe tener los mismos padres e hijos.

Usando la funcionalidad de comparación de llvm-debuginfo-analyzer, ese problema se puede ver en un contexto más global, que puede incluir la vista lógica.

La salida muestra en formato de vista los elementos faltantes (-) y agregados (+), brindando más contexto al intercambiar los archivos de objeto de referencia y destino.

llvm-debuginfo-analyzer --attribute=level
                        --compare=types
                        --report=view
                        --print=symbols,types
                        test-dwarf-clang.o test-dwarf-gcc.o
Referencia: 'test-dwarf-clang.o'
Destino:    'test-dwarf-gcc.o'
Vista Lógica:
 [000]           {File} 'test-dwarf-clang.o'
 [001]             {CompileUnit} 'test.cpp'
 [002]     1         {TypeAlias} 'INTPTR' -> '* const int'
 [002]     2         {Function} extern not_inlined 'foo' -> 'int'
 [003]                 {Block}
 [004]     5             {Variable} 'CONSTANT' -> 'const INTEGER'
+[004]     4             {TypeAlias} 'INTEGER' -> 'int'
 [003]     2           {Parameter} 'ParamBool' -> 'bool'
 [003]     2           {Parameter} 'ParamPtr' -> 'INTPTR'
 [003]     2           {Parameter} 'ParamUnsigned' -> 'unsigned int'
-[003]     4           {TypeAlias} 'INTEGER' -> 'int'

La salida muestra la ruta de vista combinada (referencia y destino) con los elementos faltantes y agregados.

ELEMENTOS LÓGICOS

Compara elementos lógicos individuales sin considerar si sus padres son los mismos. Para ambos métodos de comparación, el criterio de igualdad incluye el nombre, la ubicación en el código fuente, el tipo y el nivel del ámbito léxico.

llvm-debuginfo-analyzer --attribute=level
                        --compare=types
                        --report=list
                   




LLVM-DEBUGINFO-ANALYZER


An LLVM tool to analyze and compare DWARF debug information.




DESCRIPTION


The llvm-debuginfo-analyzer utility is used to inspect
    and compare the DWARF debug information emitted by compilers. It allows
    users to visualize the structure of the debug information in a logical
    manner, identify discrepancies between different compilation units or
    compilers, and diagnose potential issues with debug symbol generation.






OPTIONS


The options can be divided into several categories:


    
    
  • Comparison Options: These options control how the analyzer
        compares multiple input files.
    • 
    
  • Output Control Options: These options define what information is
        printed and how it is formatted.
    • 
    
  • General Options: Standard options like help and version.
    • 





COMPARISON OPTIONS



    
--attribute=list

    
Specifies a comma-separated list of attributes to compare when
        determining if two DWARF entities are equivalent. Valid attributes
        include:
        

            
level

            
Compares the DWARF level (e.g., Compile Unit, Function,
                Variable). This is the default comparison attribute.

            
format

            
Compares the target format (e.g., ELF, COFF).

            
producer

            
Compares the producer string (compiler name and version).

            
architecture

            
Compares the target architecture.

            
flags

            
Compares compiler flags.

            
options

            
Compares compiler options.

            
all

            
Compares all available attributes.

        

    

    
--compare=list

    
Specifies a comma-separated list of DWARF entity types to compare.
        Valid types include:
        

            
types

            
Compares type information (e.g., struct, enum, basic types).

            
symbols

            
Compares symbol information (e.g., functions, variables).

            
lines

            
Compares line number information.

            
scopes

            
Compares lexical scopes.

            
instructions

            
Compares inline assembler instructions.

            
all

            
Compares all DWARF entity types.

        

    








OUTPUT CONTROL OPTIONS



    
--print=list

    
Specifies a comma-separated list of DWARF entity types to print in the
        logical view. This is useful for focusing the output on specific
        aspects of the debug information. Valid types are the same as for
        --compare, plus:
        

            
summary

            
Prints a summary of the analysis results.

        

    

    
--report=list

    
Specifies a comma-separated list of report types to generate. Valid
        types include:
        

            
list

            
Generates a detailed list of differences.

            
summary

            
Generates a summary report of differences.

        

    

    
--output-sort=kind

    
Sorts the output based on the specified kind. Valid kinds include
        kind, name, and offset.








GENERAL OPTIONS



    
-h, --help

    
Print a help message and exit.

    
-v, --version

    
Print the version of llvm-debuginfo-analyzer and exit.

## CASO DE PRUEBA 5 - ÁMBITO LÉXICO INCORRECTO PARA VARIABLE

El siguiente ejemplo se utiliza para mostrar una salida diferente generada por llvm-debuginfo-analyzer. Hemos compilado el ejemplo para objetivos Codeview X86 y ELF con versiones recientes de Clang, GCC y MSVC (-O0 -g).

```cpp
// definitions.h
#ifdef _MSC_VER
  #define forceinline __forceinline
#elif defined(__clang__)
  #if __has_attribute(__always_inline__)
    #define forceinline inline __attribute__((__always_inline__))
  #else
    #define forceinline inline
  #endif
#elif defined(__GNUC__)
  #define forceinline inline __attribute__((__always_inline__))
#else
  #define forceinline inline
  #error
#endif
```

Dado que la prueba depende de las opciones del compilador para la inserción en línea, el archivo de encabezado anterior define forceinline.

```cpp
#include "definitions.h"
```

```cpp
 1  #include "definitions.h"
 2  forceinline int InlineFunction(int Param) {
 3    int Var_1 = Param;
 4    {
 5      int Var_2 = Param + Var_1;
 6      Var_1 = Var_2;
 7    }
 8    return Var_1;

10
11  int test(int Param_1, int Param_2) {
12    int A = Param_1;
13    A += InlineFunction(Param_2);

15  }
```

llvm-debuginfo-analyzer(1) — Arch Linux man pages

NAME

llvm-debuginfo-analyzer — Analyze and compare DWARF debug information in object files.

SYNOPSIS

llvm-debuginfo-analyzer [options] [input files...]

DESCRIPTION

The llvm-debuginfo-analyzer is a tool to analyze and compare DWARF debug information. It can print the parsed DWARF information in a structured way, and also compare two object files to highlight differences in their debug information.

OPTIONS

--attribute=level
This option controls the reporting of scope level attributes. When set to 'level', it will display the scope level for each debug information entry.
--compare=types
Specifies that the comparison should focus on type information. This option is used in conjunction with comparison modes to analyze differences in type definitions between object files.
--print=symbols,types
This option controls what information is printed. Here, it's set to print both symbols and types. Other possible values include `all`, `functions`, `variables`, `types`, `lines`, `scopes`, and `constants`.
--select-regex
Enables regular expression matching for selection criteria.
--select-nocase
Performs case-insensitive matching for selection criteria.
--select=INTe
Selects debug information entries whose names match the given pattern. In this case, it selects entries starting with 'INTe'.
--report=list
Sets the report format to 'list'. This typically provides a detailed, itemized list of the analyzed or compared debug information.
--report=view
Sets the report format to 'view'. This often presents a more hierarchical or visual representation of the debug information, useful for understanding structure and relationships.
--report=summary
Sets the report format to 'summary'. This provides a concise overview of the analysis or comparison results, often including counts of different types of debug information entries.
--compare=types
Specifies that the comparison should focus on type information. This option is used in conjunction with comparison modes to analyze differences in type definitions between object files.
--print=symbols,types,summary
This option controls what information is printed. Here, it's set to print symbols, types, and a summary. Other possible values include `all`, `functions`, `variables`, `types`, `lines`, `scopes`, and `constants`.
--reference
In comparison mode, designates the first file as the reference.
--target
In comparison mode, designates the second file as the target.
