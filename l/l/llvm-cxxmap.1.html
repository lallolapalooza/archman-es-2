NOMBRE

llvm-cxxmap - Herramienta de remapeo de nombres con adornos

SINOPSIS

llvm-cxxmap [opciones] archivo-simbolos-1 archivo-simbolos-2

DESCRIPCIÓN

La herramienta llvm-cxxmap realiza una coincidencia difusa de nombres de C++ con adornos, basándose en un archivo que describe componentes de nombres que deben considerarse equivalentes.

Los archivos de símbolos deben contener una lista de nombres de C++ con adornos (uno por línea). Las líneas en blanco y las líneas que comienzan con # se ignoran. La salida es una lista de pares de símbolos equivalentes, uno por línea, del formato

<simbolo-1> <simbolo-2>

donde <simbolo-1> es un símbolo de archivo-simbolos-1 y <simbolo-2> es un símbolo de archivo-simbolos-2. Se omiten las correspondencias para las cuales los dos símbolos son idénticos.

OPCIONES

-remapping-file=archivo, -r=archivo
Especifica un archivo que contiene una lista de reglas de equivalencia que deben usarse para determinar si dos símbolos son equivalentes. Obligatorio. Ver ARCHIVO DE REMAPEO.
-output=archivo, -o=archivo
Especifica un archivo para escribir la lista de nombres coincidentes. Si no se especifica, la lista se escribirá en la salida estándar.
-Wambiguous
Produce una advertencia si hay múltiples símbolos equivalentes (pero distintos) en archivo-simbolos-2.
-Wincomplete
Produce una advertencia si archivo-simbolos-1 contiene un símbolo para el cual no hay un símbolo equivalente en archivo-simbolos-2.

ARCHIVO DE REMAPEO

El archivo de remapeo es un archivo de texto que contiene líneas del formato

tipof ragment fragment1 fragment2

donde tiporfragment es uno de name, type o encoding, que indica si los siguientes fragmentos de nombres con adornos son nombres <name http://itanium-cxx-abi.github.io/cxx-abi/abi.html#mangle.name>, tipos <type http://itanium-cxx-abi.github.io/cxx-abi/abi.html#mangle.type> o codificaciones <encoding http://itanium-cxx-abi.github.io/cxx-abi/abi.html#mangle.encoding>, respectivamente. Las líneas en blanco y las líneas que comienzan con # se ignoran.

Los nombres C sin adornos se pueden expresar como una codificación que es un nombre de origen <source-name http://itanium-cxx-abi.github.io/cxx-abi/abi.html#mangle.source-name> (con prefijo de longitud):

# La función C "void foo_bar()" se remapea a la función C++ "void foo::bar()".
encoding 7foo_bar _Z3foo3barv

Para mayor comodidad, se aceptan <sustitución>s incorporados como St y Ss como <name>s (aunque técnicamente no son <name>s).

Por ejemplo, para especificar que absl::string_view y std::string_view deben tratarse como equivalentes, se podría usar el siguiente archivo de remapeo:

# absl::string_view se considera equivalente a std::string_view
type N4absl11string_viewE St17basic_string_viewIcSt11char_traitsIcEE
# std:: podría ser std::__1:: en libc++ o std::__cxx11:: en libstdc++
name St St3__1
name St St7__cxx11

Nota:

El remapeo de símbolos actualmente solo se admite para nombres de C++ con adornos que siguen el esquema de adornos de la ABI de C++ de Itanium. Esto cubre todos los destinos de C++ compatibles con Clang, excepto los destinos de Windows.
