NOMBRE

llvm-cov - emitir información de cobertura

SINOPSIS

llvm-cov comando [args...]

DESCRIPCIÓN

La herramienta llvm-cov muestra información de cobertura de código para programas que están instrumentados para emitir datos de perfil. Se puede utilizar para trabajar con la cobertura de estilo gcov o con el perfilado basado en instrumentación de clang.

Si el programa se invoca con un nombre base de gcov, se comportará como si se hubiera llamado al comando llvm-cov gcov. De lo contrario, se debe proporcionar un comando.

COMANDOS

  • gcov
  • show
  • report
  • export

COMANDO GCOV

SINOPSIS

llvm-cov gcov [opciones] FICHERO_DE_CÓDIGO_FUENTE

DESCRIPCIÓN

La herramienta llvm-cov gcov lee archivos de datos de cobertura de código y muestra la información de cobertura para un archivo fuente especificado. Es compatible con la herramienta gcov de la versión 4.2 de GCC y también puede ser compatible con algunas versiones posteriores de gcov.

Para usar llvm-cov gcov, primero debes compilar una versión instrumentada de tu aplicación que recopile datos de cobertura mientras se ejecuta. Compila con las opciones -fprofile-arcs y -ftest-coverage para agregar la instrumentación. (Alternativamente, puedes usar la opción --coverage, que incluye ambas opciones anteriores).

En el momento en que compiles el código instrumentado, se generará un archivo de datos .gcno por cada archivo objeto. Estos archivos .gcno contienen la mitad de los datos de cobertura. La otra mitad de los datos proviene de los archivos .gcda que se generan cuando ejecutas el programa instrumentado, con un archivo .gcda separado para cada archivo objeto. Cada vez que ejecutas el programa, los recuentos de ejecución se suman a cualquier archivo .gcda existente, así que asegúrate de eliminar los archivos antiguos si no deseas que su contenido se incluya.

Por defecto, los archivos .gcda se escriben en el mismo directorio que los archivos objeto, pero puedes anular esto estableciendo las variables de entorno GCOV_PREFIX y GCOV_PREFIX_STRIP. La variable GCOV_PREFIX_STRIP especifica el número de componentes de directorio que se eliminarán del inicio de la ruta absoluta al directorio del archivo objeto. Después de eliminar esos directorios, se agrega el prefijo de la variable GCOV_PREFIX. Estas variables de entorno te permiten ejecutar el programa instrumentado en una máquina donde los directorios originales de los archivos objeto no son accesibles, pero entonces necesitarás copiar los archivos .gcda de vuelta a los directorios de los archivos objeto donde llvm-cov gcov espera encontrarlos.

Una vez que hayas generado los archivos de datos de cobertura, ejecuta llvm-cov gcov para cada archivo fuente principal donde desees examinar los resultados de la cobertura. Esto debe ejecutarse desde el mismo directorio donde ejecutaste previamente el compilador. Los resultados para el archivo fuente especificado se escriben en un archivo llamado añadiendo el sufijo .gcov. También se crea un archivo de salida separado para cada archivo incluido por el archivo fuente principal, también con un sufijo .gcov añadido.

El contenido básico de un archivo de salida .gcov es una copia del archivo fuente con un recuento de ejecución y un número de línea precediendo a cada línea. El recuento de ejecución se muestra como - si una línea no contiene código ejecutable. Si una línea contiene código pero ese código nunca se ejecutó, el recuento se muestra como #####.

OPCIONES

-a, --all-blocks
Mostrar todos los bloques básicos. Si hay varios bloques para una sola línea de código fuente, esta opción hace que llvm-cov muestre el recuento para cada bloque en lugar de un solo recuento para toda la línea.
-b, --branch-probabilities
Mostrar las probabilidades de ramas condicionales y un resumen de la información de ramas.
-c, --branch-counts
Mostrar recuentos de ramas en lugar de probabilidades (requiere -b).
-m, --demangled-names
Desmanglear nombres de funciones.
-f, --function-summaries
Mostrar un resumen de cobertura para cada función en lugar de un solo resumen para todo un archivo fuente.
--help
Mostrar las opciones disponibles (--help-hidden para más).
-l, --long-file-names
Para la salida de cobertura de archivos incluidos desde el archivo fuente principal, agregar el nombre del archivo principal seguido de ## como prefijo a los nombres de los archivos de salida. Esto se puede combinar con la opción --preserve-paths para usar rutas completas tanto para el archivo principal como para el archivo incluido.
-n, --no-output
No generar archivos .gcov. La información resumida todavía se muestra.
-o <DIR|FILE>, --object-directory=<DIR>, --object-file=<FILE>
Buscar objetos en DIR o basándose en la ruta de FILE. Si especificas un archivo objeto particular, se espera que los archivos de datos de cobertura tengan el mismo nombre base con extensiones .gcno y .gcda. Si especificas un directorio, los archivos se esperan en ese directorio con el mismo nombre base que el archivo fuente.
-p, --preserve-paths
Preservar los componentes de la ruta al nombrar los archivos de salida de cobertura. Además del nombre del archivo fuente, incluir los directorios de la ruta a ese archivo. Los directorios están separados por caracteres #, eliminando directorios . y reemplazando directorios .. por caracteres ^. Cuando se usa con la opción --long-file-names, esto se aplica tanto al nombre del archivo principal como al nombre del archivo incluido.
-r
Solo volcar archivos con rutas relativas o rutas absolutas con el prefijo especificado por -s.
-s <string>
Prefijo de origen a elidir.
-t, --stdout
Imprimir a la salida estándar en lugar de producir archivos .gcov.
-u, --unconditional-branches
Incluir ramas incondicionales en la salida para la opción --branch-probabilities.
-version
Mostrar la versión de llvm-cov.
-x, --hash-filenames
Usar el hash md5 del nombre del archivo al nombrar los archivos de salida de cobertura. El nombre del archivo fuente se sufijará con ## seguido del hash MD5 calculado para él.

ESTADO DE SALIDA

llvm-cov gcov retorna 1 si no puede leer los archivos de entrada. De lo contrario, sale con cero.

COMANDO SHOW

SINOPSIS

llvm-cov show [opciones] -instr-profile PERFIL [BIN] [-object BI

--num-lines-per-function
Establece el número máximo de líneas de función a mostrar por función, cuando se usa la opción -function.
-o
Especificar la ruta a un archivo de objeto (por ejemplo, `-o test.o`). Si no se especifica, se espera encontrar los archivos de objeto en el directorio actual.
--object-directory
Especificar un directorio donde buscar los archivos de objeto.
--path-equivalence
Considerar que las rutas son equivalentes si tienen el mismo nombre de archivo. Útil para que el perfilado funcione independientemente de si los archivos se compilaron en un directorio diferente.
--region-coverage
Mostrar cobertura de región para las funciones.
--skip-expansions
No mostrar el código generado por expansiones de macros.
--show-expansions
Mostrar el código generado por expansiones de macros.
--summary-only
Mostrar solo la información resumida, sin detalles línea por línea.
--use-color
Usar colores para resaltar las líneas con y sin cobertura. Solo disponible en terminales que admiten colores.
-version
Mostrar la versión de llvm-cov.
-X:
Opciones pasadas a gcov.

EJEMPLO

Generar un informe de cobertura para el programa `a.out` con los datos del perfil `a.profdata`:

llvm-cov show -instr-profile=a.profdata ./a.out

SHOW COMMAND

SYNOPSIS

llvm-cov show [options] -instr-profile PROFILE [BIN] [-object BIN]... [-sources] [SOURCE]...

DESCRIPTION

The llvm-cov show command displays the coverage of the binaries BIN... using the profile data PROFILE. It can optionally be filtered to only show the coverage for the files listed in SOURCE....

BIN may be an executable, object file, dynamic library, or archive (thin or otherwise).

For information on compiling programs for coverage and generating profile data, see llvm-cov(1).

OPTIONS

-use-color[=VALUE]
Enable or disable color output. By default this is autodetected.
-arch=<name>
If the covered binary is a universal binary, select the architecture to use. It is an error to specify an architecture that is not included in the universal binary or to use an architecture that does not match a non-universal binary.
-show-region-summary
Show statistics for all regions. Defaults to true.
-show-branch-summary
Show statistics for all branch conditions. Defaults to true.
-show-mcdc-summary
Show MC/DC statistics. Defaults to false.
-show-functions
Show coverage summaries for each function. Defaults to false.
-show-instantiation-summary
Show statistics for all function instantiations. Defaults to false.
-ignore-filename-regex=<PATTERN>
Skip source code files with file paths that match the given regular expression.
-compilation-dir=<dir>
Directory used as a base for relative coverage mapping paths. Only applicable when binaries have been compiled with one of -fcoverage-prefix-map -fcoverage-compilation-dir, or -ffile-compilation-dir.
-debuginfod
Attempt to look up coverage mapping from objects using debuginfod. This is attempted by default for binary IDs present in the profile but not provided on the command line, so long as debuginfod is compiled in and configured via DEBUGINFOD_URLS.
-debug-file-directory=<dir>
Provides a directory to search for objects corresponding to binary IDs in the profile.
-check-binary-ids
Fail if an object file cannot be found for a binary ID present in the profile, neither on the command line nor via binary ID lookup.
-empty-profile
Display the baseline coverage of the binaries with all zero execution counts. Mutually exclusive with -instr-profile.

DIFF COMMAND

SYNOPSIS

llvm-cov diff [options] -instr-profile PROFILE1 [-instr-profile PROFILE2] [BIN] [-object BIN]... [-sources] [SOURCE]...

DESCRIPTION

The llvm-cov diff command displays the differences in coverage between two sets of profile data. The first profile PROFILE1 is treated as the baseline, and the second profile PROFILE2 is compared against it. If PROFILE2 is omitted, it defaults to an empty profile, meaning the diff will show the coverage of the first profile.

The diff can be optionally filtered to only show differences for the files listed in SOURCE....

For information on compiling programs for coverage and generating profile data, see llvm-cov(1).

OPTIONS

Show statistics for all regions. Defaults to true.
-show-branch-summary
Show statistics for all branch conditions. Defaults to true.
-show-mcdc-summary
Show MC/DC statistics. Defaults to false.
-show-functions
Show coverage summaries for each function. Defaults to false.
-show-instantiation-summary
Show statistics for all function instantiations. Defaults to false.
-ignore-filename-regex=<PATTERN>
Skip source code files with file paths that match the given regular expression.
-compilation-dir=<dir>
Directory used as a base for relative coverage mapping paths. Only applicable when binaries have been compiled with one of -fcoverage-prefix-map -fcoverage-compilation-dir, or -ffile-compilation-dir.
-debuginfod
Attempt to look up coverage mapping from objects using debuginfod. This is attempted by default for binary IDs present in the profile but not provided on the command line, so long as debuginfod is compiled in and configured via DEBUGINFOD_URLS.
-debug-file-directory=<dir>
Provides a directory to search for objects corresponding to binary IDs in the profile.
-check-binary-ids
Fail if an object file cannot be found for a binary ID present in the profile, neither on the command line nor via binary ID lookup.
-empty-profile
Use an empty profile as the baseline. Mutually exclusive with -instr-profile.

EXPORT COMMAND

SYNOPSIS

llvm-cov export [options] -instr-profile PROFILE [BIN] [-object BIN]... [-sources] [SOURCE]...

DESCRIPTION

The llvm-cov export command exports coverage data of the binaries BIN... using the profile data PROFILE in either JSON or lcov trace file format.

When exporting JSON, the regions, functions, branches, expansions, and summaries of the coverage data will be exported. When exporting an lcov trace file, the line-based coverage, branch coverage, and summaries will be exported.

The exported data can optionally be filtered to only export the coverage for the files listed in SOURCE....

For information on compiling programs for coverage and generating profile data, see SHOW COMMAND.

-summary-only

CONVERT-FOR-TESTING COMMAND

Warning:

This command is for the LLVM developers who are working on llvm-cov only.

SYNOPSIS

llvm-cov convert-for-testing BIN -o OUT

DESCRIPTION

The llvm-cov convert-for-testing command serves the purpose of testing llvm-cov itself. It can extract all code coverage data from the binary BIN to the file OUT, thereby reducing the size of test files. The output file typically bears the .covmapping extension.

The .covmapping files can be read back by llvm-cov just as ordinary binary files.

llvm-cov(1) — Arch Linux

NAME

llvm-cov — display coverage information

SYNOPSIS

llvm-cov COMMAND [ OPTIONS ] profile-data [ object-files... ]

DESCRIPTION

The llvm-cov tool is a frontend for a code coverage analysis tool. It allows you to display, export, and convert coverage data generated by the compiler. The coverage data is generated when the program is compiled with the -fprofile-instr-generate and -fcoverage-mapping flags and run with the LLVM_PROFILE_FILE environment variable set. The tool can then use the generated profile data along with the compiled object files to display coverage information.

COMMANDS

The following commands are supported:

gcov
Displays coverage data in a format compatible with gcov.
show
Displays coverage data for each source file.
report
Displays a summary of coverage data for each source file.
export
Exports coverage data in JSON format.
convert-for-testing
Converts profile data for use with other tools.

GCOV COMMAND

The gcov command displays coverage data in a format compatible with gcov. This can be useful for comparing the output of llvm-cov with gcov or for using other tools that expect gcov-formatted output.

Usage:

llvm-cov gcov [ OPTIONS ] profile-data [ object-files... ]

Options:

-branch
Enable branch coverage.
-all-funcs
Show coverage for all functions, not just those that were called.
-skip-expansions
Skip coverage for macro expansions.

SHOW COMMAND

The show command displays coverage data for each source file. It shows which lines were executed, how many times they were executed, and whether they were fully covered. It can also show branch coverage information.

Usage:

llvm-cov show [ OPTIONS ] profile-data [ object-files... ]

Options:

-branch
Enable branch coverage.
-all-funcs
Show coverage for all functions, not just those that were called.
-skip-expansions
Skip coverage for macro expansions.
-sources=file1,file2...
Only show coverage for the specified source files.
-functions=function1,function2...
Only show coverage for the specified functions.

REPORT COMMAND

The report command displays a summary of coverage data for each source file. It shows the percentage of lines executed, the number of lines executed, and the number of lines not executed.

Usage:

llvm-cov report [ OPTIONS ] profile-data [ object-files... ]

Options:

-all-funcs
Show coverage for all functions, not just those that were called.
-skip-expansions
Skip coverage for macro expansions.
-sources=file1,file2...
Only show coverage for the specified source files.
-functions=function1,function2...
Only show coverage for the specified functions.

EXPORT COMMAND

The export command exports coverage data in JSON format. This can be useful for integrating with other tools or for custom analysis.

Usage:

llvm-cov export [ OPTIONS ] profile-data [ object-files... ]

Options:

-format=format
The output format. Currently, only json is supported.
-output-dir=dir
The directory to write the exported files to.

CONVERT-FOR-TESTING COMMAND

The convert-for-testing command converts profile data for use with other tools. This command is intended for use by tools that need to consume profile data in a specific format.

Usage:

llvm-cov convert-for-testing [ OPTIONS ] profile-data [ object-files... ]

Options:

-output-dir=dir
The directory to write the converted files to.
