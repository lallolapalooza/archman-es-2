NOMBRE

llc - Compilador estático de LLVM

SINOPSIS

llc [opciones] [nombre_archivo]

DESCRIPCIÓN

El comando llc compila entradas de código fuente LLVM a lenguaje ensamblador para una arquitectura especificada. El código ensamblador resultante puede ser procesado por un ensamblador nativo y un enlazador para generar un ejecutable nativo.

La arquitectura para el código ensamblador de salida se determina automáticamente a partir del archivo de entrada, a menos que se utilice la opción -march para anular la predeterminada.

OPCIONES

Si nombre_archivo es "-" u omitido, llc lee de la entrada estándar. De lo contrario, leerá de nombre_archivo. Las entradas pueden estar en formato de lenguaje ensamblador LLVM (.ll) o formato de código de bits LLVM (.bc).

Si se omite la opción -o, llc enviará su salida a la salida estándar si la entrada proviene de la entrada estándar. Si la opción -o especifica "-", la salida también se enviará a la salida estándar.

Si no se especifica ninguna opción -o y se especifica un archivo de entrada distinto de "-", entonces llc creará el nombre de archivo de salida tomando el nombre del archivo de entrada, eliminando cualquier extensión .bc existente y agregando el sufijo .s.

Otras opciones de llc se describen a continuación.

Opciones para el usuario final

-help
Imprime un resumen de las opciones de la línea de comandos.
-M
Pasa opciones de InstPrinter específicas del destino. Consulte la opción -M de llvm-objdump(1) <llvm-objdump.html>.
-o <nombre_archivo>
Usa <nombre_archivo> como el nombre del archivo de salida. Vea el resumen anterior para más detalles.
-O=uint
Genera código en diferentes niveles de optimización. Estos corresponden a los niveles de optimización -O0, -O1, -O2 y -O3 utilizados por clang.
-mtriple=<triple_destino>
Anula la triple del destino especificada en el archivo de entrada con la cadena especificada.
-march=<arquitectura>
Especifica la arquitectura para la que generar el ensamblaje, anulando el destino codificado en el archivo de entrada. Consulte la salida de llc -help para ver una lista de arquitecturas válidas. Por defecto, esto se infiere de la triple del destino o se autodetecta a la arquitectura actual.
-mcpu=<nombre_cpu>
Especifica un chip concreto de la arquitectura actual para generar código. Por defecto, esto se infiere de la triple del destino y se autodetecta a la arquitectura actual. Para ver una lista de CPUs disponibles, use:
llvm-as < /dev/null | llc -march=xyz -mcpu=help
-filetype=<tipo_archivo_salida>
Especifica qué tipo de salida debe generar llc. Las opciones son: asm para ensamblaje textual ('.s'), obj para archivos objeto nativos ('.o') y null para no emitir nada (para pruebas de rendimiento).

Tenga en cuenta que no todos los destinos soportan todas las opciones.

-mattr=a1,+a2,-a3,...
Anula o controla atributos específicos del destino, como si las operaciones SIMD están habilitadas o no. El conjunto predeterminado de atributos lo establece la CPU actual. Para ver una lista de atributos disponibles, use:
llvm-as < /dev/null | llc -march=xyz -mattr=help
--frame-pointer
Especifica el efecto de la optimización de eliminación del puntero de marco (all,non-leaf,none).
--disable-excess-fp-precision
Deshabilita optimizaciones que pueden producir precisión excesiva para punto flotante. Tenga en cuenta que esta opción puede ralentizar drásticamente el código en algunos sistemas (por ejemplo, X86).
--enable-no-infs-fp-math
Habilita optimizaciones que asumen que no hay valores Inf.
--enable-no-nans-fp-math
Habilita optimizaciones que asumen que no hay valores NAN.
--enable-no-signed-zeros-fp-math
Habilita optimizaciones de matemáticas FP que asumen que el signo de 0 es insignificante.
--enable-no-trapping-fp-math
Habilita el establecimiento del atributo de compilación de excepciones FP a no usar excepciones.
--enable-unsafe-fp-math
Habilita optimizaciones que hacen suposiciones inseguras sobre matemáticas IEEE (por ejemplo, que la suma es asociativa) o que pueden no funcionar para todos los rangos de entrada. Estas optimizaciones permiten al generador de código utilizar algunas instrucciones que de otro modo no serían utilizables (como fsin en X86).
--stats
Imprime estadísticas registradas por los pases de generación de código.
--time-passes
Registra la cantidad de tiempo necesaria para cada pase e imprime un informe a la salida estándar de error.
--load=<ruta_dso>
Carga dinámicamente ruta_dso (una ruta a un objeto compartido dinámico) que implementa un destino LLVM. Esto permitirá que el nombre del destino se utilice con la opción -march para que se pueda generar código para ese destino.
-meabi=[default|gnu|4|5]
Especifica qué versión de EABI debe cumplir. Las versiones de EABI válidas son gnu, 4 y 5. El valor predeterminado (default) depende de la triple.
-stack-size-section
Emite la sección .stack_sizes que contiene metadatos del tamaño de la pila. La sección contiene una matriz de pares de valores de símbolos de función (tamaño de puntero) y tamaños de pila (LEB128 sin signo). Los valores de tamaño de pila solo incluyen el espacio asignado en el prólogo de la función. Las funciones con asignaciones de pila dinámicas no están incluidas.
-remarks-section
Emite la sección __remarks (MachO) que contiene metadatos sobre diagnósticos de remark.

Opciones de Ajuste/Configuración

--print-after-isel
Imprime el código de máquina generado después de la selección de instrucciones (útil para depuración).
--regalloc=<allocator>

OPTIONS

--regalloc=<allocator>
Especifica el asignador de registros a usar. Los asignadores de registros válidos son:

basic

Asignador de registros básico.

fast

Asignador de registros rápido. Es el predeterminado para código no optimizado.

greedy

Asignador de registros voraz (greedy). Es el predeterminado para código optimizado.

pbqp

Asignador de registros basado en 'Programación Cuadrática Booleana Particionada'.
--spiller=<spiller>
Especifica el "spiller" a usar para asignadores de registros que lo soportan. Actualmente, esta opción solo es utilizada por el asignador de registros de escaneo lineal. El "spiller" predeterminado es local. Los "spillers" válidos son:

simple

Spiller simple.

local

Spiller local.

Opciones específicas de Intel IA-32

--x86-asm-syntax=[att|intel]
Especifica si se debe emitir código ensamblador en sintaxis AT&T (la predeterminada) o en sintaxis Intel.

ESTADO DE SALIDA

Si llc tiene éxito, saldrá con 0. De lo contrario, si ocurre un error, saldrá con un valor distinto de cero.
