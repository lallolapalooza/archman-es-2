NOMBRE

llvm-ifs - herramienta de creación de stubs de objetos compartidos

SINOPSIS

llvm-ifs [opciones] entradas

DESCRIPCIÓN

llvm-ifs es una herramienta que produce conjuntamente stubs de objetos compartidos legibles por humanos en formato de texto (.ifs) y stubs de objetos compartidos enlazables (.so) a partir de objetos compartidos ELF o de stubs en formato de texto. Los stubs en formato de texto son útiles para monitorizar cambios en la ABI del objeto compartido. Los stubs de objetos compartidos enlazables se pueden utilizar para evitar relinks innecesarios cuando la ABI de las bibliotecas compartidas no cambia.

FORMATOS IFS

Aquí hay un ejemplo de la representación de texto (IFS) de un objeto compartido producido por llvm-ifs:

--- !ifs-v1
IFSVersion: 3.0
SoName: libtest.so /* Opcional */
Target: x86_64-unknown-linux-gnu   /* Opcional, formato 1, mismo formato que el triple de destino de llvm */
Target: { Arch: x86_64, Endianness: little, Bitwidth: 64 } /* Opcional, formato 2 */
NeededLibs:
  - libc.so.6
Symbols:
  - { Name: sym0, Type: Notype }
  - { Name: sym1, Type: Object, Size: 0 }
  - { Name: sym2, Type: Func, Weak: false }
  - { Name: sym3, Type: TLS }
  - { Name: sym4, Type: Unknown, Warning: foo }
...
  • IFSVersion: Versión del archivo IFS para compatibilidad con el lector.
  • SoName (opcional): Nombre del archivo de objeto compartido que se está stubbando.
  • Target (opcional): La arquitectura, endianness y bitwidth del objeto compartido. Puede estar en formato explícito o en formato de triple LLVM implícito. Puede ser opcional y puede ser anulado mediante opciones de línea de comandos.
  • NeededLibs: La lista de los objetos compartidos externos de los que depende esta biblioteca.
  • Symbols: Una colección de todos los datos necesarios para enlazar objetos para cada símbolo, ordenados por nombre en orden ascendente.
  • Name: Nombre del símbolo.
  • Type: Si el símbolo es un objeto, función, sin tipo, almacenamiento de hilo local (TLS) o desconocido. Los tipos de símbolos no soportados explícitamente se mapean como desconocidos para mejorar la relación señal-ruido.
  • Size: El tamaño del símbolo en cuestión, no aplicable a funciones, y es opcional para símbolos sin tipo.
  • Undefined: Si el símbolo está definido o no en este archivo de objeto compartido.
  • Weak: Si el símbolo debe tratarse como débil o no.
  • Warning (opcional): Texto de advertencia a mostrar cuando se enlaza contra este símbolo.

Este formato de texto basado en YAML contiene todo lo necesario para generar un objeto compartido ELF enlazable y un archivo TAPI de Apple. El orden de los símbolos está ordenado, por lo que estos archivos se pueden comparar fácilmente utilizando herramientas diff. Si el contenido del archivo cambia, indica un cambio potencialmente incompatible con la ABI.

FORMATO STUB ELF

Un archivo ELF mínimo que puede ser utilizado por el enlazador debe tener las siguientes secciones correctamente pobladas:

  • Encabezado ELF.
  • Encabezados de sección.
  • Tabla de símbolos dinámicos (sección .dynsym).
  • Tabla de cadenas dinámicas (sección .dynstr).
  • Tabla dinámica (sección .dynamic).
  • Entrada DT_SYMTAB.
  • Entrada DT_STRTAB.
  • Entrada DT_STRSZ.
  • Entradas DT_NEEDED. (opcional)
  • Entrada DT_SONAME. (opcional)
•
Tabla de cadenas de encabezado de sección (sección .shstrtab)

Este archivo ELF puede tener problemas de compatibilidad con herramientas de análisis ELF que dependen de los encabezados del programa. Los enlazadores como LLD funcionan bien con un archivo ELF mínimo de este tipo sin errores.

OPCIONES

--input-format=[IFS|ELF|OtrosFormatosDeArchivoObjeto]
Especifica el formato del archivo de entrada. Actualmente, solo se admiten archivos IFS de texto y archivos de objeto compartido ELF. Esta bandera es opcional ya que el formato de entrada se puede inferir.
--output-elf=<nombre-archivo-salida>
Especifica el archivo de salida para el stub del objeto compartido ELF.
--output-ifs=<nombre-archivo-salida>
Especifica el archivo de salida para el IFS de texto.
--output-tbd=<nombre-archivo-salida>
Especifica el archivo de salida para el tbd de formato Apple TAPI.
--arch=[x86_64|AArch64|...]
Esta bandera es opcional y solo debe usarse al leer un archivo IFS que no define la Arch (arquitectura). Esta bandera define la arquitectura del archivo de salida, y puede ser cualquier cadena soportada por el campo 'e_machine' de ELF. Si el valor entra en conflicto con el archivo IFS, se informará un error y el programa se detendrá.
--endianness=[little|big]
Esta bandera es opcional y solo debe usarse al leer un archivo IFS que no define el Endianness. Esta bandera define el endianness del archivo de salida. Si el valor entra en conflicto con el archivo IFS, se informará un error y el programa se detendrá.
--bitwidth=[32|64]
Esta bandera es opcional y solo debe usarse al leer un archivo IFS que no define el BitWidth. Esta bandera define el ancho de bits del archivo de salida. Si el valor entra en conflicto con el archivo IFS de entrada, se informará un error y el programa se detendrá.
--target=<triple de destino>
Esta bandera es opcional y solo debe usarse al leer un archivo IFS que no define ninguna información de destino. Esta bandera define la arquitectura, el endianness y el ancho de bits del archivo de salida utilizando el triple de destino de llvm. Esta bandera no se puede usar simultáneamente con otras banderas relacionadas con el destino.
--hint-ifs-target=<triple de destino>
Esta bandera es opcional y solo debe usarse al leer un objeto compartido ELF y generar un archivo IFS. Por defecto, llvm-ifs utilizará los campos 'Arch, Endianness y BitWidth' para reflejar la información del destino del archivo de objeto de entrada. Usar esta bandera le indicará a llvm-ifs el triple de destino esperado en el archivo IFS de salida. Si el valor coincide con la información de destino del archivo de objeto, este valor se utilizará en el campo 'Target:' del IFS generado. Si entra en conflicto con el archivo de objeto de entrada, se informará un error y el programa se detendrá.
--hint-ifs-target
Esta bandera es opcional y solo debe usarse al generar un archivo IFS. Esta bandera elimina el campo Arch del archivo IFS para que pueda ser anulado posteriormente.
--strip-ifs-endianness
Esta bandera es opcional y solo debe usarse al generar un archivo IFS. Esta bandera elimina el campo Endianness del archivo IFS para que pueda ser anulado posteriormente.
--strip-ifs-bitwidth
Esta bandera es opcional y solo debe usarse al generar un archivo IFS. Esta bandera elimina el campo BitWidth del archivo IFS para que pueda ser anulado posteriormente.
--strip-ifs-target
Esta bandera es opcional y solo debe usarse al generar un archivo IFS. Esta bandera elimina el campo

OPCIONES

-c
Esto genera un archivo ELF stub para el archivo de entrada dado. El formato de salida es el formato ELF stub estándar (como lo describe el archivo especificado por la opción --output).
--emit-symbol-table
Cuando esta opción está activada, llvm-ifs generará una tabla de símbolos para el archivo de salida. Por defecto, no se genera ninguna tabla de símbolos. Esto es útil para fines de depuración o si el archivo de salida será procesado posteriormente por otra herramienta que requiera una tabla de símbolos.
-help
Muestra un resumen de las opciones de la línea de comandos.
-o archivo
Especifica el nombre del archivo de salida. Si no se especifica, se utilizará la salida estándar.
--output archivo
Esto especifica el archivo de entrada para llvm-ifs. Si no se especifica, se utilizará la entrada estándar. El archivo de entrada debe estar en el formato especificado por la opción --input-format.
--input-format formato
Especifica el formato del archivo de entrada. Los formatos válidos son "elf" y "text". El valor predeterminado es "elf".
--output-format formato
Especifica el formato del archivo de salida. Los formatos válidos son "elf-stub" y "ifs". El valor predeterminado es "ifs".
--parse-dfs
Cuando esta opción está activada, llvm-ifs intentará analizar el campo "Target" del archivo IFS de entrada. Esto es útil para permitir que el campo "Target" sea sobrescrito posteriormente.
--write-if-changed
Cuando esta opción está activada, llvm-ifs solo escribirá el archivo de salida si no existe previamente o si el contenido es diferente del archivo existente.
--strip-size
Cuando esta opción está activada, llvm-ifs eliminará el campo de tamaño del archivo ifs de salida. Esto es útil para objetos compartidos que solo pretenden enlazarse con código independiente de posición que no necesita relocalizaciones de copia, o donde el tamaño de un objeto no es una parte útil de la abi que rastrear.

ESTADO DE SALIDA

Si llvm-ifs tiene éxito, saldrá con 0. De lo contrario, si ocurre un error, saldrá con un valor distinto de cero.
