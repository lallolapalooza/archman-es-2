LLROUND(3P) Manual del programador POSIX LLROUND(3P)

PROLOG

Esta página del manual forma parte del Manual del Programador POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual correspondiente de Linux para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

llround, llroundf, llroundl — redondear al valor entero más cercano

SINOPSIS

#include <math.h>
long long llround(double x);
long long llroundf(float x);
long long llroundl(long double x);

DESCRIPCIÓN

La funcionalidad descrita en esta página de referencia está alineada con el estándar ISO C. Cualquier conflicto entre los requisitos descritos aquí y el estándar ISO C es no intencional. Este volumen de POSIX.1‐2017 remite al estándar ISO C.

Estas funciones redondearán su argumento al valor entero más cercano, redondeando los casos intermedios (punto medio) alejándose de cero, independientemente de la dirección de redondeo actual.

Una aplicación que desee comprobar situaciones de error debe establecer errno a cero y llamar a feclearexcept(FE_ALL_EXCEPT) antes de llamar a estas funciones. Al regresar, si errno no es cero o fetestexcept(FE_INVALID | FE_DIVBYZERO | FE_OVERFLOW | FE_UNDERFLOW) no es cero, ha ocurrido un error.

VALOR DE RETORNO

Al completarse con éxito, estas funciones devolverán el valor entero redondeado.

Si x es NaN, ocurrirá un error de dominio y se devolverá un valor no especificado.

Si x es +Inf, ocurrirá un error de dominio y se devolverá un valor no especificado.

Si x es -Inf, ocurrirá un error de dominio y se devolverá un valor no especificado.

Si el valor correcto es positivo y demasiado grande para representarlo como un long long, se devolverá un valor no especificado. En sistemas que admiten la opción de punto flotante IEC 60559, ocurrirá un error de dominio; de lo contrario, puede ocurrir un error de dominio.

Si el valor correcto es negativo y demasiado grande para representarlo como un long long, se devolverá un valor no especificado. En sistemas que admiten la opción de punto flotante IEC 60559, ocurrirá un error de dominio; de lo contrario, puede ocurrir un error de dominio.

ERRORES

Estas funciones fallarán si:

Error de Dominio
El argumento x es NaN o ±Inf, o el valor correcto no es representable como un entero.

Si la expresión entera (math_errhandling & MATH_ERRNO) no es cero, entonces errno se establecerá en [EDOM]. Si la expresión entera (math_errhandling & MATH_ERREXCEPT) no es cero, entonces se generará la excepción de punto flotante inválida.

Estas funciones pueden fallar si:

Error de Dominio
El valor correcto no es representable como un entero.

Si la expresión entera (math_errhandling & MATH_ERRNO) no es cero, entonces errno se establecerá en [EDOM]. Si la expresión entera (math_errhandling & MATH_ERREXCEPT) no es cero, entonces se generará la excepción de punto flotante inválida.

Las siguientes secciones son informativas.

EJEMPLOS

Ninguno.

USO DE LA APLICACIÓN

En caso de error, las expresiones (math_errhandling & MATH_ERRNO) y (math_errhandling & MATH_ERREXCEPT) son independientes entre sí, pero al menos una de ellas debe ser distinta de cero.

FUNDAMENTO

Estas funciones difieren de las funciones llrint() en que la dirección de redondeo predeterminada para las funciones llround() redondea los casos intermedios alejándose de cero y no es necesario que generen la excepción de punto flotante inexacto para argumentos no enteros que se redondean dentro del rango del tipo de retorno.
