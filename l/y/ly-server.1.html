NOMBRE

ly-server - Manipular archivos de entrada LilyPond vía HTTP

Uso:

ly-server [opciones]

Un servidor HTTP para manipular código de entrada LilyPond

OPCIONES DEL SERVIDOR

-v, --version
mostrar número de versión y salir
-h, --help
mostrar este texto de ayuda y salir
-p,--port PUERTO
puerto en el que escucha el servidor (por defecto 5432)
-t,--timeout TIEMPO
Si se establece, el servidor se apaga automáticamente después de -t segundos de inactividad ¡AÚN NO IMPLEMENTADO!

OPCIONES DE COMANDO

-e,--encoding ENC
codificación (de entrada) (por defecto UTF-8)
--output-encoding ENC
codificación de salida (por defecto la codificación de entrada)
-l,--language NOMBRE
idioma por defecto de los nombres de notas (por defecto "nederlands")
-d <variable=valor>
establecer una variable (ver abajo)

Las opciones de comando definen los valores predeterminados para la ejecución de comandos activados por solicitudes HTTP. Estas opciones pueden ser anuladas por la solicitud HTTP individual.

SOLICITUDES HTTP

Solicitudes GET

Algunas solicitudes GET se implementarán más adelante para recuperar valores o cambiar la configuración del servidor basándose en la ruta de la URL.

Solicitudes POST

El servidor acepta solicitudes POST sin utilizar (actualmente) la ruta de la URL. Como cuerpo de la solicitud, espera una única cadena JSON con los siguientes elementos:

commands (obligatorio)
Una matriz con uno o más comandos para ejecutar posteriormente. Cada entrada contiene:
command (obligatorio):
Un nombre para el comando. Debe ser uno de la lista de comandos disponibles a continuación.
args (opcional):
Si un comando requiere argumentos (por ejemplo, el comando transpose) se proporcionan como un único valor de cadena.
variables (opcional):
Un diccionario de asignaciones de variables. Las claves deben ser de la lista a continuación, y se verifican los tipos de valor correctos. Si se proporciona una o más variables, se establecerán antes de que se ejecute el comando. Una variable puede modificarse nuevamente antes de la ejecución del siguiente comando, pero no se restablece automáticamente. Proporcionar una variable con un valor de '' anula la variable.
options (opcional)
Un diccionario de asignaciones de opciones. Las claves deben ser de la lista anterior de Opciones de Comando, tomando el nombre largo sin los guiones iniciales, por ejemplo, { "encoding": "UTF-16" }. Si se proporciona una opción aquí, anula la opción predeterminada proporcionada en la línea de comandos, pero solo para el comando actual.
data (obligatorio)
Una única cadena que contiene el documento de entrada LilyPond.

El servidor intentará construir una serie de comandos a partir de la solicitud y, si algo sale mal, enviará un mensaje de "Solicitud incorrecta" con el código de respuesta HTTP 400.

Objeto de Respuesta

Si los comandos se ejecutan correctamente, el cuerpo de la respuesta contendrá un objeto serializado JSON con los siguientes elementos:

info
Una matriz de entradas con el resultado de los comandos "info" (ver abajo). Cada entrada tiene un campo command y un campo info.
doc
Un objeto con dos campos:
content
Una cadena con el contenido del documento con todos los comandos "edit" aplicados consecutivamente. (Si no se especificaron comandos de edición, este contendrá la entrada original).
commands
Una matriz con los nombres de los comandos que se han aplicado.
exports
Una matriz con entradas para cada comando "export" aplicado. Cada entrada tiene los siguientes campos:
doc
Una cadena con el contenido del documento convertido/exportado
command
El nombre del comando aplicado

Comandos

Hay tres tipos de comandos cuyos resultados se manejan de forma independiente:

  • Los comandos "info" recuperan metadatos del documento de entrada
  • Los comandos "edit" modifican el documento, los comandos de edición subsiguientes propagan las modificaciones
  • Los comandos "export" que convierten la entrada a otro formato. Los comandos subsiguientes no se ven afectados por el resultado de los comandos de exportación.

Comandos informativos que devuelven información y no cambian el archivo:

mode
imprimir el modo (adivinando si no se proporciona) del documento
version
imprimir la versión de LilyPond, si está configurada en el documento
language
imprimir el idioma de los nombres de notas, si está configurado en el documento

Comandos que modifican la entrada:

indent
reindentar el archivo
reformat
reformatear el archivo
translate <idioma>
traducir los nombres de notas al idioma
transpose <desde> <hasta>
transportar el archivo como lo haría LilyPond, las notas se dan en el idioma 'nederlands'
abs2rel
convertir música absoluta a relativa
rel2abs
convertir música relativa a absoluta

Comandos que convierten la entrada a otro formato:

musicxml
convertir a MusicXML (en desarrollo, lejos de estar completo)

NAME

ly-server - a HTTP server for lilypond processing

SERVER OPTIONS

The ly-server can be invoked with the following options:

-h, --help
Show help message and exit.
-v, --version
Show program's version number and exit.
-p, --port
Port to listen on. Default is 5432.
-H, --host
Host to bind to. Default is localhost.
-t, --timeout
Timeout for requests in seconds. Default is 30.
-d, --debug
Show debug messages.

COMMAND OPTIONS

These are the options that can be passed to the commands. They can be passed in the JSON request under the key options.

language
language to use. Currently only supports nederlands and deutsch.
port
port to listen on (see SERVER OPTIONS).
host
host to bind to (see SERVER OPTIONS).
timeout
timeout for requests in seconds (see SERVER OPTIONS).
debug
show debug messages (see SERVER OPTIONS).

HTTP REQUESTS

The server listens for POST requests on /request.

The request body should be a JSON object with the following keys:

data
The input data (e.g. lilypond code).
commands
A list of commands to execute. Each command is an object with a command key and optional args and variables keys.
options
A dictionary of options to pass to the commands (see COMMAND OPTIONS).

The response will be a JSON object with the results of the commands.

Example request:

{
    'data': "\\relative c' { c4 d e }",
    'commands': [
        { 'command': 'indent' },
        { 'command': 'highlight', 'variables': { 'full-html': 'false' } },
        { 'command': 'mode' }
    ]
}

Example response:

{
    'doc': {
        'content': "\\relative c' { \\indent \\relative c' { c4 d e } }"
    },
    'exports': [
        {
            'doc': {
                'content': "<span class=\\"lilypond text_color=\\"red">\\relative c' { \\indent \\relative c' { c4 d e } }</span>",
                'content_type': 'text/html'
            }
        }
    ],
    'info': {
        'command': 'mode',
        'info': 'lilypond',
        'status': 'ok'
    }
}

Command reference

The following commands are available:

indent
indent the document
info
retrieve document information (e.g. document type, pitches)
transpose
transpose the document by a given interval.
musicxml
export the document as MusicXML
highlight
export the document as syntax colored HTML

Variables

The following variables can be set to influence the behaviour of commands. If there is a default value, it is written between brackets:

mode
mode of the input to read (default automatic) can be one of: lilypond, scheme, latex, html, docbook, texinfo.
encoding [UTF-8]
encoding to read (also set by -e argument)
default-language [nederlands]
the pitch names language to use by default, when not specified otherwise in the document
output-encoding
encoding to write (defaults to encoding, also set by the --output-encoding argument)
indent-tabs [false]
whether to use tabs for indent
indent-width [2]
how many spaces for each indent level (if not using tabs)
full-html [True]
if set to True a full document with syntax-highlighted HTML will be exported, otherwise only the bare content wrapped in an element configured by the wrapper- variables.
stylesheet
filename to reference as an external stylesheet for syntax-highlighted HTML. This filename is literally used in the <link rel="stylesheet"> tag.
inline-style [false]
whether to use inline style attributes for syntax-highlighted HTML. By default a css stylesheet is embedded.
number-lines [false]
whether to add line numbers when creating syntax-highlighted HTML.
wrapper-tag [pre]
which tag syntax highlighted HTML will be wrapped in. Possible values: div, pre, id and code
wrapper-attribute [class]
attribute used for the wrapper tag. Possible values: id and class.
document-id [lilypond]
name applied to the wrapper-attribute. If the three last options use their default settings the highlighted HTML elements are wrapped in an element <pre class="lilypond"></pre>
linenumbers-id [linenumbers]
if linenumbers are exported this is the name used for the <td> elements

EXAMPLES

Here is the basic invocation, listening on port 5432:

ly-server

Specifying port and a timeout:

ly-server -p 4000 -t 5000

Sample Requests

The simplest request, just applying one edit command. In this case the result will be in result['doc']['content']:

{
    'commands': [
        {
            'command': 'indent'
        }
    ],
    'data' : "\relative c' { c ( d e f ) }"
}

Another simple request, this time applying an "info" command. The result will be in result['info'], containing lilypond in the info field and mode in the command field:

{
    'commands': [
        {
            'command': 'mode'
        }
    ],
    'data' : "\relative c' { c ( d e f ) }"
}

And a more complex example. This will first transpose the document and then convert the transposed version independently to highlighted HTML and MusicXML. Additionally it will retrieve the mode. This time the result will be in all three places: the transposed document in doc.content, the mode in info.info, and HTML and MusicXML in exports[0].doc and exports[1].doc.:

{
    'commands': [
        {
            'command': 'transpose',
            'args': 'c d'
        },
        {
            'command': 'highlight',
            'variables': { 'full-html': 'false' }
        },
        { 'command': 'musicxml' },
        { 'command': 'mode' },
    ],
    'options': {
        'language': "deutsch"
    },
    'data': "\relative c' { c4 ( d e ) }"
}
