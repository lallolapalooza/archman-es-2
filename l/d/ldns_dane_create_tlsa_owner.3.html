NOMBRE

ldns_dane_create_tlsa_rr, ldns_dane_create_tlsa_owner, ldns_dane_cert2rdf, ldns_dane_select_certificate - Funciones de creación de registros RR TLSA

SINAPSIS

#include <stdint.h>
#include <stdbool.h>

#include <ldns/ldns.h>

ldns_status ldns_dane_create_tlsa_rr(ldns_rr** tlsa, ldns_tlsa_certificate_usage certificate_usage, ldns_tlsa_selector selector, ldns_tlsa_matching_type matching_type, X509* cert);

ldns_status ldns_dane_create_tlsa_owner(ldns_rdf** tlsa_owner, const ldns_rdf* name, uint16_t port, ldns_dane_transport transport);

ldns_status ldns_dane_cert2rdf(ldns_rdf** rdf, X509* cert, ldns_tlsa_selector selector, ldns_tlsa_matching_type matching_type);

ldns_status ldns_dane_select_certificate(X509** selected_cert, X509* cert, STACK_OF(X509)* extra_certs, X509_STORE* pkix_validation_store, ldns_tlsa_certificate_usage cert_usage, int index);

DESCRIPCIÓN

ldns_dane_create_tlsa_rr() Crea un registro RR TLSA a partir del certificado. ¡No se realiza ninguna validación PKIX! El certificado proporcionado se utiliza como datos independientemente del valor de certificate_usage.

tlsa: El registro RR TLSA creado.
certificate_usage: El valor para el campo Uso del Certificado
selector: El valor para el campo Selector
matching_type: El valor para el tipo de coincidencia
cert: El certificado cuyos datos se representarán

Devuelve LDNS_STATUS_OK en caso de éxito o un código de error en caso contrario.

ldns_dane_create_tlsa_owner() Crea un dname que consta del nombre dado, prefijado por el puerto del servicio y el tipo de transporte: _<EM>puerto</EM>._<EM>transporte</EM>.<EM>nombre</EM>.

tlsa_owner: El dname creado.
name: El dname que debe prefijarse.
port: El número de puerto del servicio para el cual se debe crear el nombre.
transport: El transporte para el cual se debe crear el nombre.
Devuelve LDNS_STATUS_OK en caso de éxito o un código de error en caso contrario.

ldns_dane_cert2rdf() Crea un rdf de tipo LDNS_RDF_TYPE_HEX basado en los datos binarios elegidos por el selector y codificados utilizando matching_type.

rdf: El rdf creado de tipo LDNS_RDF_TYPE_HEX.
cert: El certificado del cual se seleccionan los datos
selector: El certificado completo o la clave pública
matching_type: Los datos completos o el hash SHA256 o SHA512 de los datos seleccionados
Devuelve LDNS_STATUS_OK en caso de éxito o un código de error en caso contrario.

ldns_dane_select_certificate() Selecciona el certificado de cert, extra_certs o pkix_validation_store basándose en el valor de cert_usage e index.

selected_cert: El certificado seleccionado.
cert: El certificado a validar (o no).
extra_certs: Certificados intermedios que pueden ser necesarios durante la validación. Puede ser NULL, excepto cuando el uso del certificado es "Aseveración de Ancla de Confianza" porque se debe proporcionar el ancla de confianza. (de lo contrario, elija un "Certificado emitido por el dominio")
pkix_validation_store: Se utiliza cuando el uso del certificado es "Restricción de CA" o "Restricción de Certificado de Servicio" para validar el certificado y, en caso de "Restricción de CA", seleccionar la CA. Cuando pkix_validation_store es NULL, la validación se desactiva explícitamente y el comportamiento es el mismo que para "Aseveración de Ancla de Confianza" y "Certificado emitido por el dominio", respectivamente.
cert_usage: Qué certificado usar y cómo validar.
index: Se utiliza para seleccionar el ancla de confianza cuando el uso del certificado es "Aseveración de Ancla de Confianza". 0 es el último certificado en la cadena de validación. 1 el penúltimo, etc. Cuando index es -1, se utiliza el último certificado que DEBE ser autofirmado. Esto puede ayudar a asegurar que el ancla de confianza (autofirmada) prevista esté realmente presente en extra_certs (que es un requisito de DANE).

Devuelve LDNS_STATUS_OK en caso de éxito o un código de error en caso contrario.
