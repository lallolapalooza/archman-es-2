LD.LLD(1) Manual de Comandos Generales LD.LLD(1)

NOMBRE

ld.lld — enlazador ELF del proyecto LLVM

SINOPSIS

ld.lld [opciones] archivo_objeto ...

DESCRIPCIÓN

Un enlazador toma uno o más archivos objeto, de biblioteca y de archivo, y los combina en un archivo de salida (un ejecutable, una biblioteca compartida u otro archivo objeto). Reubica código y datos de los archivos de entrada y resuelve las referencias de símbolos entre ellos.

ld.lld es un reemplazo directo para los enlazadores GNU BFD y gold. Acepta la mayoría de los mismos argumentos de línea de comandos y scripts de enlazador que los enlazadores GNU.

ld.lld actualmente soporta objetivos i386, x86-64, ARM, AArch64, LoongArch, PowerPC32, PowerPC64, MIPS32, MIPS64, RISC-V, AMDGPU, Hexagon y SPARC V9. ld.lld actúa como un enlazador compatible con Microsoft link.exe si se invoca como lld-link y como ld de macOS si se invoca como ld.ld64. Todos estos objetivos siempre son compatibles, sin importar cómo se compiló ld.lld, por lo que siempre puede usar ld.lld como un enlazador nativo así como un enlazador cruzado.

OPCIONES

Muchas opciones tienen una forma de una sola letra y una forma larga. Al usar las formas largas de las opciones, que no comienzan con la letra o, se pueden especificar usando uno o dos guiones precediendo el nombre de la opción. Las opciones largas que comienzan con o requieren dos guiones para evitar confusión con la opción -o ruta.

--allow-multiple-definition
No genere un error si un símbolo se define varias veces. Se usará la primera definición.
--allow-shlib-undefined
Permitir referencias no resueltas en bibliotecas compartidas. Esta opción está habilitada por defecto al enlazar una biblioteca compartida.

Aplicar valores de tiempo de enlace para reubicaciones dinámicas.

Solo establecer DT_NEEDED para bibliotecas compartidas si se usan.
--auxiliary=valor
Establecer el campo DT_AUXILIARY al nombre especificado.
--Bdynamic, --dy
Enlazar contra bibliotecas compartidas.
--Bstatic, --static, --dn
No enlazar contra bibliotecas compartidas.
-Bno-symbolic
No vincular símbolos definidos con visibilidad predeterminada localmente para -shared (predeterminado).
-Bsymbolic
Vincular símbolos definidos con visibilidad predeterminada localmente para -shared. También establecer la bandera DF_SYMBOLIC.
-Bsymbolic-non-weak
Vincular símbolos STB_GLOBAL definidos con visibilidad predeterminada localmente para -shared.
-Bsymbolic-functions
Vincular símbolos de función definidos con visibilidad predeterminada localmente para -shared.
-Bsymbolic-non-weak-functions
Vincular símbolos de función STB_GLOBAL definidos con visibilidad predeterminada localmente para -shared.
--be8
Escribir un archivo ELF Big Endian usando el formato BE8 (solo AArch32)
--branch-to-branch
Habilitar las optimizaciones de rama a rama: una rama cuyo destino es otra instrucción de rama se reescribe para apuntar al destino de esta última rama (solo AArch64 y X86_64). Habilitado por defecto en -O2.
--build-id=valor
Generar una nota de ID de compilación. valor puede ser uno de fast, md5, sha1, tree, uuid, 0xcadena-hexadecimal, y none. tree es un alias para sha1. Los IDs de compilación de tipo fast, md5, sha1 y tree se calculan a partir del contenido del objeto. fast no está destinado a ser criptográficamente seguro.
--build-id
Sinónimo de --build-id=sha1.
--call-graph-profile-sort=algoritmo
algoritmo puede ser:
none
Ignorar perfil de gráfico de llamadas.
hfsort
Usar hfsort.
cdsort
Usar cdsort (predeterminado).
--color-diagnostics=valor
Usar colores en los diagnósticos. valor puede ser uno de always, auto, y never. auto habilita el color si y solo si la salida es a una terminal.
--color-diagnostics
Alias para --color-diagnostics=auto.
--compress-debug-sections=valor
Comprimir secciones de depuración DWARF. Las secciones permanecen sin comprimir si el contenido comprimido fuera más grande. valor puede ser
none
Sin compresión.
zlib
El nivel de compresión predeterminado es 1 (más rápido) ya que la información de depuración generalmente se comprime bien en ese nivel.
zstd
Usar el nivel de compresión predeterminado en zstd.
--compress-sections=glob-seccion={none,zlib,zstd}[:nivel]
Comprimir secciones de salida que coincidan con el glob y no tengan el flag SHF_ALLOC. Las secciones coincidentes permanecen sin comprimir si el contenido comprimido fuera más grande. El nivel de compresión es nivel (si se especifica) o un nivel predeterminado enfocado en la velocidad. Esto es como un --compress-debug-sections generalizado.
--cref
Generar tabla de referencias cruzadas. Si se especifica -Map, imprimir en el archivo de mapa.
--debug-names
Generar una sección .debug_names fusionada.

--warn-ifunc-textrel
Advierte sobre el uso de símbolos ifunc junto con reubicaciones de texto. Versiones anteriores de la biblioteca glibc (2.28 y anteriores) tienen un error que hace que el segmento que incluye símbolos ifunc se marque como no ejecutable cuando se reubican. Como resultado, aunque el programa se compila y enlaza correctamente, genera un error de segmentación cuando el puntero de instrucción alcanza un símbolo ifunc. Utilice -warn-ifunc-textrel para que lld emita una advertencia, si el código puede incluir símbolos ifunc, puede realizar reubicaciones de texto y ser enlazado con una versión anterior de glibc. De lo contrario, no es necesario utilizarlo, ya que el valor predeterminado no emite una advertencia. Esta bandera se introdujo a finales de 2018, no tiene un equivalente en los enlazadores ld y gold, y puede ser eliminada en el futuro.

Crea un archivo tarro reproducido con el nombre de archivo especificado. Si se especifica --reproduce, --reproduce tiene prioridad.

ld.lld crea una sección llamada .comment que contiene la cadena de versión de LLD. La cadena de versión puede ser anulada por esta variable de entorno, lo que es útil para eliminar diferencias en el binario causadas por diferencias en el número de versión de LLD.

NOTAS DE IMPLEMENTACIÓN

ld.lld's manejo de archivos de archivo (aquellos con una extensión de archivo .a) es diferente de los enlazadores tradicionales utilizados en sistemas tipo Unix.

Los enlazadores tradicionales mantienen un conjunto de símbolos indefinidos durante el enlazado. El enlazador procesa cada archivo en el orden en que aparece en la línea de comandos, hasta que el conjunto de símbolos indefinidos se vacía. Un archivo objeto se enlaza en el objeto de salida cuando se encuentra, y sus símbolos indefinidos se añaden al conjunto. Al encontrar un archivo de archivo, un enlazador tradicional busca los objetos contenidos en él y procesa aquellos que satisfacen los símbolos en el conjunto no resuelto.

El manejo de archivos de archivo mutuamente dependientes puede ser torpe al usar un enlazador tradicional. Los archivos de archivo pueden tener que especificarse varias veces, o se pueden usar las opciones de línea de comandos especiales --start-group y --end-group para que el enlazador itere sobre los archivos del grupo hasta que no se añadan nuevos símbolos al conjunto.

ld.lld registra todos los símbolos encontrados en objetos y archivos a medida que itera sobre los argumentos de la línea de comandos. Cuando ld.lld encuentra un símbolo indefinido que puede ser resuelto por un archivo objeto contenido en un archivo de archivo procesado previamente, lo extrae y lo enlaza inmediatamente en el objeto de salida.

Con ciertas entradas de archivo, ld.lld puede producir resultados diferentes en comparación con los enlazadores tradicionales. En la práctica, grandes cuerpos de software de terceros se han enlazado con ld.lld sin problemas materiales.

La opción --warn-backrefs puede usarse para identificar una invocación del enlazador que puede ser incompatible con el comportamiento del enlazador tradicional de tipo Unix.
