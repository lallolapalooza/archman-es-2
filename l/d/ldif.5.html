LDIF(5) Manual de Formatos de Archivo LDIF(5)

NOMBRE

ldif - Formato de Intercambio de Datos LDAP

DESCRIPCIÓN

El Formato de Intercambio de Datos LDAP (LDIF) se utiliza para representar entradas LDAP y registros de cambios en formato de texto. Herramientas LDAP, como ldapadd(1) y ldapsearch(1), leen y escriben registros de entrada LDIF. ldapmodify(1) lee registros de cambios LDIF.

Esta página del manual proporciona una descripción básica de LDIF. Una especificación formal de LDIF se publica en RFC 2849.

REGISTROS DE ENTRADA

Los registros de entrada LDIF se utilizan para representar entradas de directorio. La forma básica de un registro de entrada es:

dn: <nombre distinguido>
<descripción atributo>: <valor atributo>
<descripción atributo>: <valor atributo>
<descripción atributo>:: <valor codificado en base64>
<descripción atributo>:< <URL>
...

El valor puede especificarse como texto UTF-8 o como datos codificados en base64, o se puede proporcionar una URI para la ubicación del valor del atributo.

Una línea puede continuarse comenzando la siguiente línea con un solo espacio o tabulador, por ejemplo:

dn: cn=Barbara J Jensen,dc=exam
 ple,dc=com

Las líneas que comienzan con un signo de almohadilla ('#') se ignoran.

Se especifican múltiples valores de atributo en líneas separadas, por ejemplo:

cn: Barbara J Jensen
cn: Babs Jensen

Si un valor contiene un carácter no imprimible, o comienza con un espacio o un dos puntos ':', el <tipo atributo> va seguido de dos puntos y el valor se codifica en notación base 64. Por ejemplo, el valor " comienza con un espacio" se codificaría así:

cn:: IGJlZ2lucyB3aXRoIGEgc3BhY2U=

Si el valor del atributo se encuentra en un archivo, el <tipo atributo> va seguido de ':<' y una URI de archivo. Por ejemplo, el valor contenido en el archivo /tmp/value se listaría así:

cn:< file:///tmp/value
Otros esquemas de URI (ftp, http) también pueden ser compatibles.

Las entradas múltiples dentro del mismo archivo LDIF están separadas por líneas en blanco.

EJEMPLO DE REGISTRO DE ENTRADA

Aquí hay un ejemplo de un archivo LDIF que contiene tres entradas.

dn: cn=Barbara J Jensen,dc=example,dc=com
cn: Barbara J Jensen
cn: Babs Jensen
objectclass: person
description:< file:///tmp/babs
sn: Jensen
dn: cn=Bjorn J Jensen,dc=example,dc=com
cn: Bjorn J Jensen
cn: Bjorn Jensen
objectclass: person
sn: Jensen
dn: cn=Jennifer J Jensen,dc=example,dc=com
cn: Jennifer J Jensen
cn: Jennifer Jensen
objectclass: person
sn: Jensen
jpegPhoto:: /9j/4AAQSkZJRgABAAAAAQABAAD/2wBDABALD
 A4MChAODQ4SERATGCgaGBYWGDEjJR0oOjM9PDkzODdASFxOQ
 ERXRTc4UG1RV19iZ2hnPk1xeXBkeFxlZ2P/2wBDARESEhgVG
...

Tenga en cuenta que la descripción en la entrada de Barbara Jensen se lee de file:///tmp/babs y jpegPhoto en la entrada de Jennifer Jensen está codificada usando base 64.

REGISTROS DE CAMBIO

Los registros de cambio LDIF se utilizan para representar solicitudes de cambio de directorio. Cada registro de cambio comienza con una línea que indica el nombre distinguido de la entrada que se está cambiando:

dn: <nombre distinguido>
changetype: <[modify|add|delete|modrdn]>

Finalmente, se presenta la información del cambio, cuyo formato depende de qué tipo de cambio se especificó anteriormente. Para un changetype de modify, el formato es uno o más de los siguientes:

add: <tipo atributo>
<descripción atributo>: <valor1>
<descripción atributo>: <valor2>
...
-

O, para una modificación de reemplazo:

replace: <tipo atributo>
<descripción atributo>: <valor1>
<descripción atributo>: <valor2>
...
-

Si no se proporcionan líneas de tipo atributo para reemplazar, se eliminará todo el atributo (si está presente).

O, para una modificación de eliminación:

delete: <tipo atributo>
<descripción atributo>: <valor1>
<descripción atributo>: <valor2>
...
-

Si no se proporcionan líneas de tipo atributo para eliminar, se eliminará todo el atributo.

Para un changetype de add, el formato es:

<descripción atributo1>: <valor1>
<descripción atributo1>: <valor2>
...
<descripción atributoN>: <valor1>
<descripción atributoN>: <valor2>

Para un changetype de modrdn o moddn, el formato es:

newrdn: <nuevo rdn>
deleteoldrdn: 0 | 1
newsuperior: <DN>

donde un valor de 1 para deleteoldrdn significa eliminar los valores que forman el rdn antiguo de la entrada, y un valor de 0 significa dejar los valores como atributos no distinguido en la entrada. La línea newsuperior es opcional y, si está presente, especifica el nuevo superior al que mover la entrada.

Para un changetype de delete, no se necesita información adicional en el registro.

Tenga en cuenta que los valores de los atributos pueden presentarse utilizando base64 o en archivos como se describe para los registros de entrada. Las líneas en los registros de cambio también pueden continuarse de la manera descrita para los registros de entrada.

EJEMPLO DE REGISTRO DE CAMBIO

El siguiente archivo LDIF de ejemplo contiene un registro de cambio de cada tipo de cambio.

dn: cn=Babs Jensen,dc=example,dc=com
changetype: add
objectclass: person
objectclass: extensibleObject
cn: babs
cn: babs jensen
sn: jensen
dn: cn=Babs Jensen,dc=example,dc=com
changetype: modify
add: givenName
givenName: Barbara
givenName: babs
-
replace: description
description: the fabulous babs
-
delete: sn
sn: jensen
-
dn: cn=Babs Jensen,dc=example,dc=com
changetype: modrdn
newrdn: cn=Barbara J Jensen
deleteoldrdn: 0
newsuperior: ou=People,dc=example,dc=com
dn: cn=Barbara J Jensen,ou=People,dc=example,dc=com
changetype: delete

DECLARACIÓN INCLUDE

El analizador LDIF ha sido ampliado para admitir una declaración include para referenciar otros archivos LDIF. La declaración include debe estar separada de otros registros por una línea en blanco. El archivo referenciado se especifica mediante una URI de archivo y todo su contenido se incorpora como si fuera parte del archivo LDIF original. Como se mencionó anteriormente, otros esquemas de URI pueden ser compatibles. Por ejemplo:

dn: dc=example,dc=com
objectclass: domain
dc: example
include: file:///tmp/example.com.ldif
dn: dc=example,dc=org
objectclass: domain
dc: example
Esta característica no forma parte de la especificación LDIF en RFC 2849, pero se espera que aparezca en una futura revisión de esta especificación. Es compatible con los comandos ldapadd(1), ldapmodify(1) y slapadd(8).
