DESCRIPCIÓN

Estas rutinas se utilizan para analizar las definiciones de esquema en la sintaxis definida en RFC 4512 en estructuras y para manejar dichas estructuras. Estas rutinas manejan cuatro tipos de definiciones: sintaxis, reglas de coincidencia, tipos de atributos y clases de objetos. Para cada tipo de definición, se proporcionan cuatro rutinas.

ldap_str2xxx() toma una definición en formato RFC 4512 en el argumento s como una cadena terminada en NUL y devuelve, si es posible, un puntero a una estructura recién asignada del tipo apropiado. El llamador es responsable de liberar la estructura llamando a ldap_xxx_free() cuando ya no sea necesaria. La rutina devuelve NULL si ocurrió algún problema. En este caso, el entero al que apunta el argumento code recibirá un código de error (consulte más abajo la descripción de ldap_scherr2str() para obtener una explicación de los valores) y se colocará un puntero a una cadena terminada en NUL donde lo solicite el argumento errp, indicando dónde en el argumento s ocurrió el error, por lo que el llamador no debe liberarlo. El argumento flags es una máscara de bits de opciones de análisis que controlan la relajación de la sintaxis reconocida. Se definen los siguientes valores:

LDAP_SCHEMA_ALLOW_NONE
análisis estricto según RFC 4512.
LDAP_SCHEMA_ALLOW_NO_OID
permite definiciones que no contienen un OID inicial.
LDAP_SCHEMA_ALLOW_QUOTED
permite comillas alrededor de algunos elementos que no deberían tenerlas.
LDAP_SCHEMA_ALLOW_DESCR
permite una descr en lugar de un OID numérico en lugares donde la sintaxis espera lo segundo.
LDAP_SCHEMA_ALLOW_DESCR_PREFIX
permite que el OID numérico inicial contenga un prefijo en formato descr.
LDAP_SCHEMA_ALLOW_ALL
ser muy liberal, incluir todas las opciones.

Las estructuras devueltas son las siguientes:

typedef struct ldap_schema_extension_item {
	char *lsei_name;	/* Nombre de la extensión */
	char **lsei_values;	/* Valores de la extensión */
} LDAPSchemaExtensionItem;
typedef struct ldap_syntax {
	char *syn_oid;		/* OID */
	char **syn_names;	/* Nombres */
	char *syn_desc;		/* Descripción */
	LDAPSchemaExtensionItem **syn_extensions; /* Extensión */
} LDAPSyntax;
typedef struct ldap_matchingrule {
	char *mr_oid;		/* OID */
	char **mr_names;	/* Nombres */
	char *mr_desc;		/* Descripción */
	int  mr_obsolete;	/* ¿Es obsoleto? */
	char *mr_syntax_oid;	/* OID de la sintaxis de los valores asegurados */
	LDAPSchemaExtensionItem **mr_extensions; /* Extensiones */
} LDAPMatchingRule;
typedef struct ldap_attributetype {
	char *at_oid;		/* OID */
	char **at_names;	/* Nombres */
	char *at_desc;		/* Descripción */
	int  at_obsolete;	/* ¿Es obsoleto? */
	char *at_sup_oid;	/* OID del tipo superior */
	char *at_equality_oid;	/* OID de la regla de coincidencia de igualdad */
	char *at_ordering_oid;	/* OID de la regla de coincidencia de ordenación */
	char *at_substr_oid;	/* OID de la regla de coincidencia de subcadenas */
	char *at_syntax_oid;	/* OID de la sintaxis de los valores */
	int  at_syntax_len;	/* Longitud máxima mínima sugerida */
	int  at_single_value;	/* ¿Es de valor único? */
	int  at_collective;	/* ¿Es colectivo? */
	int  at_no_user_mod;	/* ¿Están prohibidos los cambios a través de LDAP? */
	int  at_usage;		/* Uso, ver más abajo */
	LDAPSchemaExtensionItem **at_extensions; /* Extensiones */
} LDAPAttributeType;
typedef struct ldap_objectclass {
	char *oc_oid;		/* OID */
	char **oc_names;	/* Nombres */
	char *oc_desc;		/* Descripción */
	int  oc_obsolete;	/* ¿Es obsoleto? */
	char **oc_sup_oids;	/* OIDs de las clases superiores */
	int  oc_kind;		/* Tipo, ver más abajo */
	char **oc_at_oids_must;	/* OIDs de los tipos de atributos requeridos */
	char **oc_at_oids_may;	/* OIDs de los tipos de atributos opcionales */
	LDAPSchemaExtensionItem **oc_extensions; /* Extensiones */
} LDAPObjectClass;

Algunos campos enteros (los descritos con un signo de interrogación) tienen un valor de verdad, para estos campos los valores posibles son:

LDAP_SCHEMA_NO
La respuesta a la pregunta es no.
LDAP_SCHEMA_YES
La respuesta a la pregunta es sí.

Para los tipos de atributos, los siguientes usos son posibles:

LDAP_SCHEMA_USER_APPLICATIONS
el tipo de atributo no es operacional.
LDAP_SCHEMA_DIRECTORY_OPERATION
el tipo de atributo es operacional y es pertinente al directorio mismo, es decir, tiene el mismo valor en todos los servidores que proporcionan la entrada que contiene este tipo de atributo.
LDAP_SCHEMA_DISTRIBUTED_OPERATION
el tipo de atributo es operacional y es pertinente a la replicación, shadowing u otros aspectos del directorio distribuido. TBC.
LDAP_SCHEMA_DSA_OPERATION
el tipo de atributo es operacional y es pertinente al servidor de directorio mismo, es decir, puede tener valores diferentes para la misma entrada cuando se recupera de diferentes servidores que proporcionan la entrada.

Las clases de objetos pueden ser de tres tipos:

LDAP_SCHEMA_ABSTRACT
la clase de objeto es abstracta, es decir, no puede haber entradas de esta clase por sí solas.
LDAP_SCHEMA_STRUCTURAL
la clase de objeto es estructural, es decir, describe el rol principal de la entrada. En algunos servidores, una vez creada la entrada, el conjunto de clases de objetos estructurales asignadas no se puede cambiar: ninguna de las presentes se puede eliminar y no se puede añadir ninguna otra.
LDAP_SCHEMA_AUXILIARY
la clase de objeto es auxiliar, es decir, está pensada
