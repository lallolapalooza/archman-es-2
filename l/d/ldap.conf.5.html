LDAP.CONF(5) Manual de Formatos de Archivo LDAP.CONF(5)

NOMBRE

ldap.conf, .ldaprc - Archivo de configuración LDAP/variables de entorno

SINOPSIS

ETCDIR/ldap.conf, ldaprc, .ldaprc, $LDAP<nombre-opcion>

DESCRIPCIÓN

Si la variable de entorno LDAPNOINIT está definida, se deshabilita toda la configuración por defecto.

El archivo de configuración ldap.conf se utiliza para establecer valores predeterminados a nivel de sistema que se aplicarán al ejecutar clientes ldap.

Los usuarios pueden crear un archivo de configuración opcional, ldaprc o .ldaprc, en su directorio personal que se utilizará para anular el archivo de valores predeterminados a nivel de sistema. El archivo ldaprc en el directorio de trabajo actual también se utiliza.

Se pueden especificar archivos de configuración adicionales usando las variables de entorno LDAPCONF y LDAPRC. LDAPCONF puede establecerse a la ruta de un archivo de configuración. Esta ruta puede ser absoluta o relativa al directorio de trabajo actual. LDAPRC, si está definido, debe ser el nombre base de un archivo en el directorio de trabajo actual o en el directorio personal del usuario.

Las variables de entorno también pueden usarse para aumentar los valores predeterminados basados en archivos. El nombre de la variable es el nombre de la opción con un prefijo añadido de LDAP. Por ejemplo, para definir BASE a través del entorno, establezca la variable LDAPBASE al valor deseado.

Algunas opciones son solo para el usuario. Dichas opciones se ignoran si están presentes en ldap.conf (o en el archivo especificado por LDAPCONF).

Por lo tanto, los siguientes archivos y variables se leen, en orden:

    variable     $LDAPNOINIT, y si ese no está establecido:
    archivo de sistema  ETCDIR/ldap.conf,
    archivos de usuario  $HOME/ldaprc,  $HOME/.ldaprc,  ./ldaprc,
    archivo de sistema  $LDAPCONF,
    archivos de usuario  $HOME/$LDAPRC, $HOME/.$LDAPRC, ./$LDAPRC,
    variables    $LDAP<nombre de opción en mayúsculas>.
Los ajustes posteriores en la lista anulan los anteriores.

SINTAXIS

Las opciones de configuración no distinguen entre mayúsculas y minúsculas; su valor, caso por caso, puede ser sensible a mayúsculas y minúsculas.

Las líneas en blanco se ignoran.
Las líneas que comienzan con una almohadilla (`#') son comentarios y se ignoran.

Las líneas válidas consisten en el nombre de una opción (una secuencia de caracteres no en blanco, convencionalmente escritos en mayúsculas, aunque no sea obligatorio), seguido de un valor. El valor comienza con el primer carácter no en blanco después del nombre de la opción y termina al final de la línea, o en la última secuencia de espacios en blanco antes del final de la línea. La tokenización del valor, si la hay, se delega a los manejadores para esa opción, si los hay. Citar valores que contienen espacios en blanco puede ser incorrecto, ya que las comillas se convertirían en parte del valor. Por ejemplo,

# Incorrecto - comillas erróneas:
URI     "ldap:// ldaps://"
# Correcto - lista de URIs separadas por espacios, sin comillas:
URI     ldap:// ldaps://
# Correcto - la sintaxis DN requiere comillas para Example, Inc:
BASE    ou=IT staff,o="Example, Inc",c=US
# o:
BASE    ou=IT staff,o=Example\2C Inc,c=US
# Incorrecto - comentario en la misma línea que la opción:
DEREF   never           # Nunca seguir alias

Una línea no puede tener más de LINE_MAX de longitud, que debería ser superior a 2000 bytes en todas las plataformas. No existe un mecanismo para dividir una línea larga en varias líneas, ya sea para embellecimiento o para superar el límite anterior.

OPCIONES

Las diferentes opciones de configuración son:

URI <ldap[si]://[nombre[:puerto]] ...>
Especifica la(s) URI(s) del(los) servidor(es) LDAP al(los) que debe conectarse la biblioteca LDAP. El esquema URI puede ser cualquiera de ldap, ldaps o ldapi, que se refieren a LDAP sobre TCP, LDAP sobre SSL (TLS) y LDAP sobre IPC (sockets de dominio UNIX), respectivamente. El nombre de cada servidor puede especificarse como un nombre de estilo de dominio o una literal de dirección IP. Opcionalmente, el nombre del servidor puede ir seguido de ':' y el número de puerto en el que está escuchando el servidor LDAP. Si no se proporciona número de puerto, se utiliza el puerto predeterminado para el esquema (389 para ldap://, 636 para ldaps://). Para LDAP sobre IPC, nombre es el nombre del socket, y no se requiere ni se permite

puerto; tenga en cuenta que los separadores de directorio deben codificarse en URL, al igual que cualquier otro carácter especial para las URL; por lo tanto, el socket

/usr/local/var/ldapi

debe especificarse como

ldapi://%2Fusr%2Flocal%2Fvar%2Fldapi

Puede proporcionarse una lista de URIs separadas por espacios.

BASE <base>
Especifica el DN base predeterminado que se utilizará al realizar operaciones ldap. El base debe especificarse como un Distinguished Name (DN) en formato LDAP.
BINDDN <dn>
Especifica el DN de enlace predeterminado que se utilizará al realizar operaciones ldap. El DN de enlace debe especificarse como un Distinguished Name (DN) en formato LDAP. Esta es una opción solo para el usuario.
DEREF <cuándo>
Especifica cómo se realiza la desreferencia de alias al realizar una búsqueda. <cuándo> puede especificarse como una de las siguientes palabras clave:
nunca
Los alias nunca se desreferencian. Este es el valor predeterminado.
buscando
Los alias se desreferencian en los subordinados del objeto base, pero no al localizar el objeto base de la búsqueda.
encontrando
Los alias solo se desreferencian al localizar el objeto base de la búsqueda.
siempre
Los alias se desreferencian tanto al buscar como al localizar el objeto base de la búsqueda.
HOST <nombre[:puerto] ...>
Especifica el(los) nombre(s) del(los) servidor(es) LDAP al(los) que debe conectarse la biblioteca LDAP. El nombre de cada servidor puede especificarse como un nombre de estilo de dominio o una dirección IP y opcionalmente seguido de ':' y el número de puerto en el que está escuchando el servidor ldap. Se puede proporcionar una lista de hosts separada por espacios. HOST está obsoleto en favor de URI.
KEEPALIVE_IDLE
Establece/obtiene el número de segundos que una conexión debe permanecer inactiva antes de que TCP comience a enviar sondeos de mantenimiento. Solo Linux.
KEEPALIVE_PROBES
Establece/obtiene el número máximo de sondeos de mantenimiento que TCP debe enviar antes de desconectar la conexión. Solo Linux.
KEEPALIVE_INTERVAL
Establece/obtiene el intervalo en segundos entre sondeos de mantenimiento individuales. Solo Linux.
NETWORK_TIMEOUT <entero>
Especifica el tiempo de espera (en segundos) después del cual poll(2)/select(2) después de un connect(2) retorna en caso de no actividad.
PORT <puerto>
Especifica el puerto predeterminado que se utiliza al conectarse a servidores LDAP. El puerto puede especificarse como un número. PORT está obsoleto en favor de URI.
REFERRALS <activado/verdadero/sí/desactivado/falso/no>
Especifica si el cliente debe seguir automáticamente las referencias devueltas por los servidores LDAP. El valor predeterminado es activado. Tenga en cuenta que las herramientas de línea de comandos como ldapsearch(1) y otras siempre anulan esta opción.
SIZELIMIT <entero>
Especifica un límite de tamaño (número de entradas) que se utilizará al realizar búsquedas. El número debe ser un entero no negativo. SIZELIMIT de cero (0) especifica una solicitud de tamaño de búsqueda ilimitado. Tenga en cuenta que el servidor aún puede aplicar cualquier límite del lado del servidor en la cantidad de entradas que puede devolver una operación de búsqueda.
SOCKET_BIND_ADDRESSES <IP>
Especifica la IP de enlace de origen que se utilizará para conectarse al servidor LDAP de destino. Se deben separar varias direcciones IP por espacios. Solo se permite una dirección IPv4 válida y/o una dirección IPv6 válida en la lista.

never
The client will not request or check any server certificate's SAN extensions.
allow
The server certificate's SAN extensions are checked. If they are present and do not match the hostname, the certificate is ignored and the session proceeds normally.
try
The server certificate's SAN extensions are checked. If they are present and do not match the hostname, the session is immediately terminated.
demand | hard
These keywords are equivalent and the same as try. This is the default setting.

Note that the TLS_REQCERT directive is still honored, regardless of the TLS_REQSAN settings.

TLS_VERIFYCLIENTCERT <level>
Specifies what checks to perform on client certificates in a TLS session. This option is applicable only when the server requests a client certificate during the TLS handshake. The <level> can be specified as one of the following keywords:
never
The client will not present a certificate, nor check the server's request.
allow
The client will present a certificate if available. If the certificate is invalid or unavailable, the session proceeds normally.
try
The client will present a certificate if available. If the certificate is invalid or unavailable, the session is immediately terminated.
demand | hard
These keywords are equivalent and the same as try. This is the default setting.

OTHER OPTIONS

ASYNCIO <on|off>
Enables or disables asynchronous I/O. When enabled, I/O operations are performed asynchronously. The default is off.
ASYNCVALUE <value>
Specifies the asynchronous I/O value. This option is only effective when ASYNCIO is enabled.
CONNPOOL <on|off>
Enables or disables connection pooling. When enabled, the client reuses existing connections to the LDAP server. The default is off.
DEBUG <level>
Specifies the debug level for the LDAP client. The <level> is an integer from 0 to 65535. Higher levels produce more detailed debug output.
HOST <hostname>
Specifies the hostname or IP address of the LDAP server to connect to. This option is typically used when a URI is not provided or when overriding a URI.
PORT <port>
Specifies the port number of the LDAP server to connect to. The default LDAP port is 389. The default LDAPS port is 636.
REFERRALS <on|off|search|limit>
Controls whether the client should follow referrals. The default is 'search'. 'on' means always follow referrals. 'off' means never follow referrals. 'search' means follow referrals during search operations only. 'limit' means follow referrals up to a certain limit.
 
Sets the maximum number of rebind attempts. This is used in conjunction with connection pooling.
 
Sets the minimum number of rebind attempts. This is used in conjunction with connection pooling.
 
Sets the increment for rebind attempts. This is used in conjunction with connection pooling.
REQUEST_LIMIT <integer>
Specifies the maximum number of entries to return for a search request. A value of 0 means no limit. Please note that the server may still impose its own limit.
ROOTPREF <on|off>
When enabled, the client will attempt to bind using anonymous credentials to the root of the DIT before attempting to bind with other credentials. The default is off.
SIZELIMIT <integer>
Specifies a size limit (maximum number of entries) to return from a search. A value of zero (0) means unlimited. Please note that the server may still apply any server-side limit on the number of entries returned.
SOCKETPRECACHE <on|off>
When enabled, the client pre-caches socket information. This can improve performance in some environments. The default is off.
SSLUSEVERIFYCERT <on|off>
Enables or disables certificate verification for SSL/TLS connections. When enabled, the client verifies the server's certificate. The default is on.
URICACHE <on|off>
Enables or disables URI caching. When enabled, the client caches URIs to avoid redundant lookups. The default is off.

EXAMPLES

Connect to a local LDAP server and perform a search:

ldapsearch -H ldap://localhost -b "dc=example,dc=com" "cn=*"

Connect to a remote LDAP server using LDAPS and authenticate with SASL/EXTERNAL:

ldapsearch -H ldaps://ldap.example.com -Y EXTERNAL -X "dn=<<"

Bind to a server with a specific version of the LDAP protocol and a time limit:

ldapsearch -H ldap://ldap.example.com -V 3 -L 5

Connect to a server using TLS and client certificate authentication:

ldapsearch -H ldaps://ldap.example.com --TLS_CERT /path/to/client.crt \
    --TLS_KEY /path/to/client.key -b "cn=users,dc=example,dc=com" "(uid=jdoe)"

never
El cliente no verificará ningún SAN en el certificado.
allow
Se verifica el SAN contra el nombre de host especificado. Si hay un SAN presente pero ninguno coincide con el nombre de host especificado, los SAN se ignoran y se utiliza la verificación habitual contra el DN del certificado. Esta es la configuración predeterminada.
try
Se verifica el SAN contra el nombre de host especificado. Si no hay ningún SAN presente en el certificado del servidor, se utiliza la verificación habitual contra el DN del certificado. Si hay un SAN presente pero no coincide con el nombre de host especificado, la sesión se termina inmediatamente. Esta configuración puede ser preferible cuando se utiliza una mezcla de certificados con y sin SAN.
demand | hard
Estas palabras clave son equivalentes. Se verifica el SAN contra el nombre de host especificado. Si no hay ningún SAN presente en el certificado del servidor, o si ningún SAN coincide, la sesión se termina inmediatamente. Esta configuración debe utilizarse cuando solo se utilizan certificados con SAN.
TLS_CRLCHECK <level>
Especifica si la Lista de Revocación de Certificados (CRL) de la CA debe utilizarse para verificar si los certificados del servidor no han sido revocados. Esto requiere que el parámetro TLS_CACERTDIR esté configurado. Este parámetro se ignora con GnuTLS. <level> se puede especificar como una de las siguientes palabras clave:
none
No se realiza ninguna verificación de CRL
peer
Verifica la CRL del certificado del par
all
Verifica la CRL para toda la cadena de certificados
TLS_CRLFILE <filename>
Especifica el archivo que contiene una Lista de Revocación de Certificados para ser utilizada para verificar si los certificados del servidor no han sido revocados. Este parámetro solo es compatible con GnuTLS.
