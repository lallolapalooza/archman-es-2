LDAP_SEARCH(3) Manual de funciones de biblioteca LDAP_SEARCH(3)

NOMBRE

ldap_search, ldap_search_s, ldap_search_st, ldap_search_ext, ldap_search_ext_s - Realizar una operación de búsqueda LDAP

BIBLIOTECA

OpenLDAP LDAP (libldap, -lldap)

SINOPSIS

#include <sys/types.h>
#include <ldap.h>
int ldap_search_ext(
LDAP *ld,
char *base,
int scope,
char *filter,
char *attrs[],
int attrsonly,
LDAPControl **serverctrls,
LDAPControl **clientctrls,
struct timeval *timeout,
int sizelimit,
int *msgidp );
int ldap_search_ext_s(
LDAP *ld,
char *base,
int scope,
char *filter,
char *attrs[],
int attrsonly,
LDAPControl **serverctrls,
LDAPControl **clientctrls,
struct timeval *timeout,
int sizelimit,
LDAPMessage **res );

DESCRIPCIÓN

Estas rutinas se utilizan para realizar operaciones de búsqueda LDAP. La rutina ldap_search_ext_s() realiza la búsqueda de forma síncrona (es decir, no regresa hasta que la operación se completa), proporcionando un puntero a los mensajes LDAP resultantes en la ubicación apuntada por el parámetro res.

La rutina ldap_search_ext() es la versión asíncrona, que inicia la búsqueda y devuelve el ID del mensaje de la operación que inició en el entero apuntado por el parámetro msgidp.

El parámetro base es el DN de la entrada en la que se iniciará la búsqueda.

El parámetro scope es el alcance de la búsqueda y debe ser uno de LDAP_SCOPE_BASE, para buscar el objeto en sí, LDAP_SCOPE_ONELEVEL, para buscar los hijos inmediatos del objeto, LDAP_SCOPE_SUBTREE, para buscar el objeto y todos sus descendientes, o LDAP_SCOPE_CHILDREN, para buscar todos los descendientes. Tenga en cuenta que este último requiere que el servidor soporte la extensión de Ámbito de Búsqueda de Subordinados LDAP.

El filter es una representación en cadena del filtro que se aplicará en la búsqueda. La cadena debe cumplir con el formato especificado en RFC 4515, extendido por RFC 4526. Por ejemplo, "(cn=Jane Doe)". Tenga en cuenta que el uso de la extensión requiere que el servidor soporte la extensión de Filtro Absoluto Verdadero/Falso LDAP. Se puede especificar NULL para indicar que la biblioteca debe enviar el filtro (objectClass=*).

El parámetro attrs es un array terminado en nulo de descripciones de atributos a devolver de las entradas coincidentes. Si se especifica NULL, se solicita la devolución de todos los atributos de usuario. La descripción "*" (LDAP_ALL_USER_ATTRIBUTES) se puede utilizar para solicitar que se devuelvan todos los atributos de usuario. La descripción "+" (LDAP_ALL_OPERATIONAL_ATTRIBUTES) se puede utilizar para solicitar que se devuelvan todos los atributos operativos. Tenga en cuenta que esto requiere que el servidor soporte la extensión de Atributos Operativos Completos de LDAP. Para solicitar ningún atributo, se debe listar la descripción "1.1" (LDAP_NO_ATTRS) por sí sola.

El parámetro attrsonly debe establecerse en un valor no cero si solo se desean descripciones de atributos. Debe establecerse en cero (0) si se desean tanto descripciones de atributos como valores de atributos.

Los parámetros serverctrls y clientctrls se pueden utilizar para especificar controles del servidor y del cliente, respectivamente.

La rutina ldap_search_ext_s() es la versión síncrona de ldap_search_ext().

También devuelve un código que indica éxito o, en caso de fallo, que indica la naturaleza del fallo de la operación. Consulte ldap_error(3) para obtener detalles.

NOTAS

Tenga en cuenta que tanto la funcionalidad de lectura como la de listado están subsumidas por estas rutinas, al utilizar un filtro como "(objectclass=*)" y un ámbito de LDAP_SCOPE_BASE (para emular lectura) o LDAP_SCOPE_ONELEVEL (para emular listado).

Estas rutinas pueden asignar memoria dinámicamente. El llamador es responsable de liberar dicha memoria utilizando las rutinas de desasignación proporcionadas. Los valores de retorno se contienen en <ldap.h>.

Tenga en cuenta que el parámetro res de ldap_search_ext_s() y ldap_search_s() debe liberarse con ldap_msgfree() independientemente del valor de retorno de estas funciones.

INTERFACES OBSOLETAS

La rutina ldap_search() está obsoleta en favor de la rutina ldap_search_ext(). Las rutinas ldap_search_s() y ldap_search_st() están obsoletas en favor de la rutina ldap_search_ext_s().

Las interfaces obsoletas generalmente permanecen en la biblioteca. La macro LDAP_DEPRECATED se puede definir a un valor distinto de cero (por ejemplo, -DLDAP_DEPRECATED=1) al compilar programas diseñados para usar interfaces obsoletas. Se recomienda que los desarrolladores que escriban programas nuevos, o actualicen programas antiguos, eviten el uso de interfaces obsoletas. Con el tiempo, se espera que la documentación (y, eventualmente, el soporte) para interfaces obsoletas se elimine.
