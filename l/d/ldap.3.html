LDAP(3) Manual de funciones de biblioteca LDAP(3)

NOMBRE

ldap - API del Protocolo de Acceso Ligero a Directorios de OpenLDAP

BIBLIOTECA

OpenLDAP LDAP (libldap, -lldap)

SINOPSIS

#include <ldap.h>

DESCRIPCIÓN

El Protocolo Ligero de Acceso a Directorios (LDAP) (RFC 4510) proporciona acceso a servicios de directorio X.500. Estos servicios pueden ser autónomos o formar parte de un servicio de directorio distribuido. Esta API cliente soporta LDAP sobre TCP (RFC 4511), LDAP sobre TLS/SSL, y LDAP sobre IPC (sockets de dominio UNIX). Esta API soporta SASL (RFC 4513) y Start TLS (RFC 4513) así como una serie de extensiones de protocolo. Esta API se basa vagamente en la especificación de la API C LDAP del borrador IETF/LDAPEXT, un trabajo en progreso (huérfano).

El paquete de software OpenLDAP incluye un servidor autónomo en slapd(8), varios clientes LDAP, y una biblioteca cliente LDAP utilizada para proporcionar acceso programático al protocolo LDAP. Esta página del manual ofrece una visión general de las rutinas de la biblioteca LDAP.

Se proporcionan API síncronas y asíncronas. También se incluyen varias rutinas para analizar los resultados devueltos por estas rutinas. Estas rutinas se encuentran en la biblioteca -lldap.

La interacción básica es la siguiente. Se crea un manejador de sesión utilizando ldap_initialize(3) y se establece la versión del protocolo a 3 llamando a ldap_set_option(3). La sesión subyacente se establece en la primera operación que se emite. Esta sería generalmente una operación Start TLS o Bind, o una operación Search para leer atributos del Root DSE. Una operación Start TLS se realiza llamando a ldap_start_tls_s(3). Una operación Bind LDAP se realiza llamando a ldap_sasl_bind(3) o a una de sus funciones relacionadas. Una operación Search se realiza llamando a ldap_search_ext_s(3) o a una de sus funciones relacionadas.

Posteriormente, se realizan operaciones adicionales llamando a una de las rutinas síncronas o asíncronas (por ejemplo, ldap_compare_ext_s(3) o ldap_compare_ext(3) seguido de ldap_result(3)). Los resultados devueltos por estas rutinas se interpretan llamando a las rutinas de análisis LDAP como ldap_parse_result(3). La asociación LDAP y la conexión subyacente se terminan llamando a ldap_unbind_ext(3). Los errores se pueden interpretar llamando a ldap_err2string(3).

VERSIONES LDAP

Esta biblioteca soporta la versión 3 del Protocolo Ligero de Acceso a Directorios (LDAPv3) tal como se define en la RFC 4510. También soporta una variante de la versión 2 de LDAP tal como se define por U-Mich LDAP y, hasta cierto punto, la RFC 1777. La versión 2 (todas las variantes) se considera obsoleta. Se debe usar la versión 3 en su lugar.

Por razones de compatibilidad hacia atrás, la biblioteca utiliza por defecto la versión 2. Por lo tanto, todas las aplicaciones nuevas (y todas las aplicaciones activamente mantenidas) deben utilizar ldap_set_option(3) para seleccionar la versión 3. Las páginas del manual de la biblioteca asumen que la versión 3 ha sido seleccionada.

PARÁMETROS DE ENTRADA Y SALIDA

Se espera que todas las cadenas de entrada/salida sean/estén codificadas en UTF-8 Unicode (versión 3.2).

Los nombres distinguidos (DN) (y los nombres distinguidos relativos (RDN) que se pasen a las rutinas LDAP deben cumplir con la representación de cadena UTF-8 de la RFC 4514.

Los filtros de búsqueda que se pasen a las rutinas de búsqueda deben construirse manualmente y deben cumplir con la representación de cadena UTF-8 de la RFC 4515.

Las URL s LDAP que se pasen a las rutinas deben cumplir con el formato de la RFC 4516. Las rutinas de ldap_url(3) se pueden utilizar para trabajar con URL s LDAP.

Los controles LDAP que se pasen a las rutinas se pueden manipular utilizando las rutinas de ldap_controls(3).

MOSTRAR RESULTADOS

Los resultados obtenidos de las rutinas de búsqueda se pueden mostrar manualmente, llamando a ldap_first_entry(3) y ldap_next_entry(3) para avanzar por las entradas devueltas, ldap_first_attribute(3) y ldap_next_attribute(3) para avanzar por los atributos de una entrada, y ldap_get_values(3) para recuperar los valores de un atributo dado. Los valores de los atributos pueden ser o no visualizables.

RUTINAS DE UTILIDAD

También se proporcionan varias rutinas de utilidad. Las rutinas de ldap_sort(3) se utilizan para ordenar las entradas y los valores devueltos a través de las rutinas de búsqueda de ldap.

INTERFACES OBSOLETAS

Una serie de interfaces se consideran ahora obsoletas. Por ejemplo, ldap_add(3) está obsoleta en favor de ldap_add_ext(3). Las interfaces obsoletas generalmente permanecen en la biblioteca. La macro LDAP_DEPRECATED puede definirse a un valor distinto de cero (por ejemplo, -DLDAP_DEPRECATED=1) al compilar programas diseñados para utilizar interfaces obsoletas. Se recomienda que los desarrolladores que escriban programas nuevos, o actualicen programas antiguos, eviten el uso de interfaces obsoletas. Con el tiempo, se espera que la documentación (y, finalmente, el soporte) para interfaces obsoletas se elimine.

BIBLIOTECA BER

También se incluye en la distribución un conjunto de rutinas ligeras de Reglas de Codificación Básicas. Estas rutinas son utilizadas por las rutinas de la biblioteca LDAP para codificar y decodificar elementos del protocolo LDAP utilizando las Reglas de Codificación Básicas (ligeramente simplificadas) definidas por LDAP. Normalmente no son utilizadas directamente por un programa de aplicación LDAP, excepto en el manejo de controles y operaciones extendidas. Las rutinas proporcionan una interfaz similar a printf y scanf, así como acceso de nivel inferior. Estas rutinas se discuten en lber-decode(3), lber-encode(3), lber-memory(3), y lber-types(3).
