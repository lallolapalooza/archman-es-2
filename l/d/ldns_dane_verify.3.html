ldns_dane_verify(3)

Paquete: ldns

Licencias: custom:BSD

ldns(3) Manual de funciones de biblioteca ldns(3)

NOMBRE

ldns_dane_verify, ldns_dane_verify_rr - Funciones de verificación de RR TLSA

SINOPSIS

#include <stdint.h>
#include <stdbool.h>

#include <ldns/ldns.h>

ldns_status ldns_dane_verify(const ldns_rr_list* tlsas, X509* cert, STACK_OF(X509)* extra_certs, X509_STORE* pkix_validation_store);

ldns_status ldns_dane_verify_rr(const ldns_rr* tlsa_rr, X509* cert, STACK_OF(X509)* extra_certs, X509_STORE* pkix_validation_store);

DESCRIPCIÓN

ldns_dane_verify() ¡CUIDADO! Recomendamos encarecidamente utilizar las funciones de verificación DANE de OpenSSL 1.1.0 en lugar de las proporcionadas por ldns. Cuando OpenSSL 1.1.0 estuvo disponible, ldns utilizará las funciones de verificación DANE de OpenSSL 1.1.0 internamente. Cuando ldns se vinculó con OpenSSL < 1.1.0, esta función no podrá verificar registros TLSA con tipos de uso DANE-TA.

¡CUIDADO! Las funciones de verificación DANE de ldns *no* realizan comprobaciones de nombre de servidor. ¡El usuario debe realizar comprobaciones adicionales de nombre de servidor por sí mismo!

Verifica si alguno de los registros de recursos TLSA dados coincide con el certificado dado.

tlsas: Los registros de recursos que especifican qué y cómo hacer coincidir el certificado. Uno debe coincidir para que esta función tenga éxito. Con tlsas == NULL o el número de registros TLSA en tlsas == 0, se realiza la validación PKIX regular.
cert: El certificado para hacer coincidir (y validar)
extra_certs: Certificados intermedios que pueden ser necesarios para crear la cadena de validación.
pkix_validation_store: Se utiliza cuando el uso del certificado es "Restricción de CA" o "Restricción de Certificado de Servicio" para validar el certificado.

Devuelve LDNS_STATUS_OK en caso de éxito, LDNS_STATUS_DANE_NEED_OPENSSL_GE_1_1_FOR_DANE_TA cuando al menos uno de los TLSA tenía el tipo de uso DANE-TA y ninguno de los TLSA coincidió o validó PKIX, LDNS_STATUS_DANE_PKIX_DID_NOT_VALIDATE cuando uno de los TLSA coincidió pero la validación PKIX falló, LDNS_STATUS_DANE_TLSA_DID_NOT_MATCH cuando ninguno de los TLSA coincidió, u otros errores de ldns_status.

ldns_dane_verify_rr() ¡CUIDADO! Recomendamos encarecidamente utilizar las funciones de verificación DANE de OpenSSL 1.1.0 en lugar de las proporcionadas por ldns. Cuando OpenSSL 1.1.0 estuvo disponible, ldns utilizará las funciones de verificación DANE de OpenSSL 1.1.0 internamente. Cuando ldns se vinculó con OpenSSL < 1.1.0, esta función no podrá verificar registros TLSA con tipos de uso DANE-TA.

¡CUIDADO! Las funciones de verificación DANE de ldns *no* realizan comprobaciones de nombre de servidor. ¡El usuario debe realizar comprobaciones adicionales de nombre de servidor por sí mismo!

Verifica si el registro de recursos TLSA dado coincide con el certificado dado. Se prefiere informar sobre una no coincidencia de RR TLSA (LDNS_STATUS_DANE_TLSA_DID_NOT_MATCH) sobre un fallo PKIX (LDNS_STATUS_DANE_PKIX_DID_NOT_VALIDATE). Por lo tanto, cuando la validación PKIX es requerida por el uso del Certificado TLSA, pero los datos TLSA no coinciden, se devuelve LDNS_STATUS_DANE_TLSA_DID_NOT_MATCH independientemente de si PKIX validó o no.

Cuando ldns se vincula con OpenSSL < 1.1.0 y esta función está disponible, entonces el tipo de uso DANE-TA no se verificará y, en un tlsa_rr con este tipo de uso, se devolverá LDNS_STATUS_DANE_NEED_OPENSSL_GE_1_1_FOR_DANE_TA.

tlsa_rr: El registro de recursos que especifica qué y cómo hacer coincidir el certificado. Con tlsa_rr == NULL, se realiza la validación PKIX regular.
cert: El certificado para hacer coincidir (y validar)
extra_certs: Certificados intermedios que pueden ser necesarios para crear la cadena de validación.
pkix_validation_store: Se utiliza cuando el uso del certificado es "Restricción de CA" o "Restricción de Certificado de Servicio" para validar el certificado.

Devuelve LDNS_STATUS_OK en caso de éxito, LDNS_STATUS_DANE_NEED_OPENSSL_GE_1_1_FOR_DANE_TA cuando el TLSA proporcionado tenía el tipo de uso DANE-TA, LDNS_STATUS_DANE_TLSA_DID_NOT_MATCH en caso de no coincidencia de datos TLSA, LDNS_STATUS_DANE_PKIX_DID_NOT_VALIDATE cuando TLSA coincidió, pero la validación PKIX falló, u otros errores de ldns_status.
