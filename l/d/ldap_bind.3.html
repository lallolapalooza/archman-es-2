DESCRIPCIÓN

Estas rutinas proporcionan varias interfaces para la operación de enlace LDAP. Después de establecer una asociación con un servidor LDAP utilizando ldap_init(3), se debe realizar una operación de enlace LDAP antes de intentar otras operaciones a través de la conexión. Se requiere un enlace LDAP al usar la Versión 2 del protocolo LDAP; es opcional para la Versión 3 pero generalmente se necesita debido a consideraciones de seguridad.

Hay tres tipos de llamadas de enlace: las que proporcionan autenticación simple, las que proporcionan autenticación SASL y rutinas generales capaces de realizar autenticación simple o SASL.

SASL (Simple Authentication and Security Layer) puede negociar uno de muchos tipos diferentes de autenticación. Se proporcionan versiones síncronas y asíncronas de cada variante de la llamada de enlace. Todas las rutinas toman ld como su primer parámetro, como lo devuelve ldap_init(3).

AUTENTICACIÓN SIMPLE

La forma más simple de la llamada de enlace es ldap_simple_bind_s(). Toma el DN para enlazar como who, y la contraseña de usuario (userPassword) asociada con la entrada en passwd. Devuelve una indicación de error de LDAP (ver ldap_error(3)). La llamada ldap_simple_bind() es asíncrona, tomando los mismos parámetros pero solo iniciando la operación de enlace y devolviendo el ID del mensaje de la solicitud que envió. El resultado de la operación se puede obtener mediante una llamada posterior a ldap_result(3). Las funciones ldap_sasl_bind_s() y la asíncrona ldap_sasl_bind() también se pueden usar para realizar un enlace simple utilizando LDAP_SASL_SIMPLE como mecanismo SASL.

AUTENTICACIÓN GENERAL

Las rutinas ldap_bind() y ldap_bind_s() se pueden usar cuando el método de autenticación a utilizar necesita ser seleccionado en tiempo de ejecución. Ambas toman un parámetro adicional method que selecciona el método de autenticación a utilizar. Debe establecerse en LDAP_AUTH_SIMPLE para seleccionar la autenticación simple. ldap_bind() devuelve el ID del mensaje de la solicitud que inicia. ldap_bind_s() devuelve una indicación de error de LDAP.

AUTENTICACIÓN SASL

Para los enlaces SASL, el servidor siempre ignora cualquier DN proporcionado, por lo que el parámetro dn siempre debe ser NULL. ldap_sasl_bind_s() envía una única solicitud de enlace SASL con el mecanismo SASL mechanism y las credenciales dadas en el parámetro cred. El formato de las credenciales depende del mecanismo SASL particular en uso. Para los mecanismos que proporcionan autenticación mutua, las credenciales del servidor se devolverán en el parámetro servercredp. La rutina devuelve una indicación de error de LDAP (ver ldap_error(3)). La llamada ldap_sasl_bind() es asíncrona, tomando los mismos parámetros pero solo enviando la solicitud y devolviendo el ID del mensaje de la solicitud que envió. El resultado de la operación se puede obtener mediante una llamada posterior a ldap_result(3). El resultado debe ser analizado adicionalmente por ldap_parse_sasl_bind_result() para obtener cualquier credencial del servidor enviada desde el servidor.

Cualquier credencial de servidor devuelta debe liberarse usando ber_bvfree().

Muchos mecanismos SASL requieren múltiples intercambios de mensajes para realizar una autenticación completa. Las aplicaciones generalmente deberían usar ldap_sasl_interactive_bind_s() en lugar de llamar directamente a las funciones básicas de ldap_sasl_bind(). El parámetro mechs debe contener una lista separada por espacios de mecanismos candidatos para usar. Si este parámetro es NULL o vacío, la biblioteca consultará el atributo supportedSASLMechanisms del rootDSE del servidor para la lista de mecanismos SASL que el servidor soporta. El parámetro flags controla la interacción utilizada para recuperar cualquier parámetro de autenticación SASL necesario y debe ser uno de:

LDAP_SASL_AUTOMATIC
usar valores predeterminados si están disponibles, solicitar de lo contrario
LDAP_SASL_INTERACTIVE
solicitar siempre
LDAP_SASL_QUIET
nunca solicitar

La función interact utiliza la información de defaults proporcionada para manejar las solicitudes de la biblioteca SASL de parámetros de autenticación particulares. No hay un formato definido para la información de defaults; depende del llamante utilizar el formato que sea apropiado para la función interact suministrada. El parámetro sasl_interact proviene de la biblioteca SASL subyacente. Cuando se usa con Cyrus SASL, esta es una matriz de estructuras sasl_interact_t. NAME

ldap_bind, ldap_sasl_bind, ldap_sasl_bind_s, ldap_bind_s, ldap_unbind, ldap_unbind_s, ldap_unbind_ext, ldap_unbind_ext_s, ldap_set_rebind_proc, ldap_bind_init, ldap_sasl_bind_alloc - bind to an LDAP server

LIBRARY

libldap - LDAP client library

SYNOPSIS

ldap_bind(LDAP *ld, const char *dn, const char *cred, LDAPControl *sctrl[], LDAPControl *cctrl[], int method);
ldap_sasl_bind(LDAP *ld, const char *dn, const char *mechanism, struct berval *cred, LDAPControl *sctrl[], LDAPControl *cctrl[], int method);
ldap_sasl_bind_s(LDAP *ld, const char *dn, const char *mechanism, struct berval *cred, LDAPControl *sctrl[], LDAPControl *cctrl[], int method);
ldap_bind_s(LDAP *ld, const char *dn, const char *cred, LDAPControl *sctrl[], LDAPControl *cctrl[], int method);
ldap_unbind(LDAP *ld);
ldap_unbind_s(LDAP *ld);
ldap_unbind_ext(LDAP *ld, LDAPControl *sctrl[], LDAPControl *cctrl[]);
ldap_unbind_ext_s(LDAP *ld, LDAPControl *sctrl[], LDAPControl *cctrl[]);
ldap_set_rebind_proc(LDAP *ld, LDAPRebindProc *rebind, void *params);
ldap_bind_init(LDAP *ld, const char *dn, const char *cred, int method);
ldap_sasl_bind_alloc(LDAP *ld, const char *dn, const char *mechanism, struct berval *cred, LDAPControl *sctrl[], LDAPControl *cctrl[], int method, char **rmechp);

DESCRIPTION

The ldap_bind() function attempts to bind to an LDAP server using the supplied credentials. The connection to the server must have already been established using ldap_open(3).

The ldap_bind_s() call is the synchronous version of the ldap_bind() call. It performs the bind operation and does not return until the operation has completed.

The ldap_sasl_bind() and ldap_sasl_bind_s() functions perform a SASL bind. They take the SASL mechanism name and credentials as arguments.

The ldap_bind_init() function is used to initialize the bind operation. It may be used to set up a bind operation that will be performed later. The actual bind is performed when the first operation is attempted on the connection.

The ldap_sasl_bind_alloc() function is used to perform an interactive SASL bind. The mechanism parameter specifies the SASL mechanism to use. The cred parameter contains the credentials for the mechanism, if any. The function will prompt the user for any additional information needed to complete the bind. The mechanism that was actually used will be returned in rmechp.

The ldap_unbind() and ldap_unbind_ext() calls are used to unbind from the directory. They terminate the current association and free the resources contained in the LDAP structure. Once called, the connection to the LDAP server is closed and the LDAP structure is invalid. The ldap_unbind_s() and ldap_unbind_ext_s() calls are synchronous versions of the unbind calls.

The ldap_set_rebind_proc() function is used to set a callback function that will be called when the client needs to rebind to a different server, for example, when following a referral.

SIMPLE AUTHENTICATION

To perform simple authentication, set the method parameter to LDAP_AUTH_SIMPLE. The dn parameter should contain the distinguished name of the entry to bind as, and the cred parameter should contain the password for that entry. If the dn parameter is NULL, an anonymous bind is attempted.

GENERAL AUTHENTICATION

For other authentication methods, set the method parameter to LDAP_AUTH_OTHER. The dn and cred parameters are used as specified by the authentication method.

SASL AUTHENTICATION

To perform SASL authentication, set the method parameter to LDAP_AUTH_SASL. The mechanism parameter specifies the SASL mechanism to use, e.g. "PLAIN", "GSSAPI", "DIGEST-MD5". The cred parameter contains the credentials for the mechanism. The format of the credentials depends on the mechanism.

When using ldap_sasl_bind() or ldap_sasl_bind_s(), the credentials should be provided as a struct berval. If the mechanism does not require credentials, the cred parameter can be NULL.

The ldap_sasl_interactive_bind() function can be used to perform an interactive SASL bind. The function takes a pointer to a NULL-terminated array of LDAPBindPluginResult structures as the last parameter. Each structure specifies a SASL mechanism and a prompt string for obtaining credentials. The function will prompt the user for credentials and then perform the SASL bind using the provided information.

SASL_CB_REALM
the realm for the authentication attempt
SASL_CB_AUTHNAME
the username to authenticate
SASL_CB_PASS
the password for the provided username
SASL_CB_USER
the username to use for proxy authorization
SASL_CB_NOECHOPROMPT
generic prompt for input with input echoing disabled
SASL_CB_ECHOPROMPT
generic prompt for input with input echoing enabled
SASL_CB_LIST_END
indicates the end of the array of prompts

See the Cyrus SASL documentation for more details.

Applications which need to manage connections asynchronously may use ldap_sasl_interactive_bind() instead of the synchronous version. A valid mechs parameter must be supplied, otherwise the library will be forced to query the server for a list of supported mechanisms, and this query will be performed synchronously. The other parameters are the same as for the synchronous function, with three additional parameters. The actual SASL mechanism that was used, and the message ID for use with ldap_result() will be returned in rmechp and msgidp, respectively. The value in rmechp must not be modified by the caller and must be passed back on each subsequent call. The message obtained from ldap_result() must be passed in the result parameter. This parameter must be NULL when initiating a new Bind. The caller must free the result message after each call using ldap_msgfree(). The ldap_sasl_interactive_bind() function returns an LDAP result code. If the code is LDAP_SASL_BIND_IN_PROGRESS then the Bind is not complete yet, and this function must be called again with the next result from the server.

REBINDING

The ldap_set_rebind_proc function() sets the process to use for binding when an operation returns a referral. This function is used when an application needs to bind to another server in order to follow a referral or search continuation reference.

The function takes ld, the rebind function, and the params, the arbitrary data like state information which the client might need to properly rebind. The LDAP_OPT_REFERRALS option in the ld must be set to ON for the libraries to use the rebind function. Use the ldap_set_option function to set the value.

The rebind function parameters are as follows:

The ld parameter must be used by the application when binding to the referred server if the application wants the libraries to follow the referral.

The url parameter points to the URL referral string received from the LDAP server. The LDAP application can use the ldap_url_parse(3) function to parse the string into its components.

The request parameter specifies the type of request that generated the referral.

The msgid parameter specifies the message ID of the request generating the referral.

The params parameter is the same value as passed originally to the ldap_set_rebind_proc() function.

The LDAP libraries set all the parameters when they call the rebind function. The application should not attempt to free either the ld or the url structures in the rebind function.

The application must supply to the rebind function the required authentication information such as, user name, password, and certificates. The rebind function must use a synchronous bind method.

UNBINDING

The ldap_unbind() call is used to unbind from the directory, terminate the current association, and free the resources contained in the ld structure. Once it is called, the connection to the LDAP server is closed, and the ld structure is invalid. The ldap_unbind_s() call is just another name for ldap_unbind(); both of these calls are synchronous in nature.

The ldap_unbind_ext() and ldap_unbind_ext_s() allows the operations to specify controls.

ERRORS

Asynchronous routines will return -1 in case of error, setting the ld_errno parameter of the ld structure. Synchronous routines return whatever ld_errno is set to. See ldap_error(3) for more information.

NOTES

If an anonymous bind is sufficient for the application, the rebind process need not be provided. The LDAP libraries with the LDAP_OPT_REFERRALS option set to ON (default value) will automatically follow referrals using an anonymous bind.

If the application needs stronger authentication than an anonymous bind, you need to provide a rebind process for that authentication method. The bind method must be synchronous.
