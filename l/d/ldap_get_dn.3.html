ldap_get_dn(3)

Paquete: libldap

Licencias: custom

LDAP_GET_DN(3) Manual de funciones de biblioteca LDAP_GET_DN(3)

NOMBRE

ldap_get_dn, ldap_explode_dn, ldap_explode_rdn, ldap_dn2ufn - Rutinas de manejo de DN de LDAP

BIBLIOTECA

OpenLDAP LDAP (libldap, -lldap)

SINOPSIS

#include <ldap.h>
char *ldap_get_dn( LDAP *ld, LDAPMessage *entry )
int ldap_str2dn( const char *str, LDAPDN *dn, unsigned flags )
void ldap_dnfree( LDAPDN dn )
int ldap_dn2str( LDAPDN dn, char **str, unsigned flags )
char **ldap_explode_dn( const char *dn, int notypes )
char **ldap_explode_rdn( const char *rdn, int notypes )
char *ldap_dn2ufn( const char * dn )
char *ldap_dn2dcedn( const char * dn )
char *ldap_dcedn2dn( const char * dn )
char *ldap_dn2ad_canonical( const char * dn )

DESCRIPCIÓN

Estas rutinas permiten obtener, analizar, convertir a una forma fácil de usar y probar los nombres de entrada de LDAP (Nombres Distinguidos, o DN). Un DN tiene el formato descrito en RFC 4414 "Lightweight Directory Access Protocol (LDAP): String Representation of Distinguished Names".

La rutina ldap_get_dn() toma una entry como la devuelta por ldap_first_entry(3) o ldap_next_entry(3) y devuelve una copia del DN de la entrada. El espacio para el DN se obtendrá dinámicamente y debe ser liberado por el llamante usando ldap_memfree(3).

ldap_str2dn() analiza una representación en cadena de un nombre distinguido contenido en str en sus componentes, que se almacenan en dn como estructuras ldap_ava, organizadas en términos de LDAPAVA, LDAPRDN y LDAPDN. El espacio para dn se obtendrá dinámicamente y debe ser liberado por el llamante usando ldap_dnfree(3). El LDAPDN se define como:

typedef struct ldap_ava {
    struct berval la_attr;
    struct berval la_value;
    unsigned la_flags;
} LDAPAVA;
typedef LDAPAVA** LDAPRDN;
typedef LDAPRDN* LDAPDN;
Los tipos de atributos y los valores de los atributos no están normalizados. la_flags puede ser LDAP_AVA_STRING o LDAP_AVA_BINARY, el último significa que el valor está codificado en BER/DER y por lo tanto debe representarse como, citando RFC 4514, "... un carácter octothorpe ('#' ASCII 35) seguido de la representación hexadecimal de cada uno de los bytes de la codificación BER del Valor de Atributo X.500." El parámetro flags para ldap_str2dn() puede ser 
LDAP_DN_FORMAT_LDAPV3
LDAP_DN_FORMAT_LDAPV2
LDAP_DN_FORMAT_DCE
que define qué sintaxis de DN se espera (según RFC 4514, RFC 1779 y DCE, respectivamente). El formato puede ser *O*rado a las banderas 
LDAP_DN_P_NO_SPACES
LDAP_DN_P_NO_SPACE_AFTER_RDN
...
LDAP_DN_PEDANTIC
Este último es un atajo para todas las limitaciones anteriores.

LDAP_DN_P_NO_SPACES no permite espacios adicionales en el dn; el valor predeterminado es eliminar silenciosamente los espacios alrededor de los separadores AVA ('='), los separadores de componentes RDN ('+' para LDAPv3/LDAPv2 o ',' para DCE) y los separadores RDN (',' LDAPv3/LDAPv2 o '/' para DCE).

LDAP_DN_P_NO_SPACE_AFTER_RDN no permite un solo espacio después de los separadores RDN.

ldap_dn2str() realiza la operación inversa, generando en str una representación en cadena de dn. Permite los mismos valores para flags que ldap_str2dn(), más

LDAP_DN_FORMAT_UFN
LDAP_DN_FORMAT_AD_CANONICAL
para un nombre fácil de usar (RFC 1781) y el formato canónico de AD.

Las siguientes rutinas se consideran obsoletas en favor de ldap_str2dn() y ldap_dn2str(). Se proporcionan para dar soporte a aplicaciones heredadas.

La rutina ldap_explode_dn() toma un DN como el devuelto por ldap_get_dn() y lo divide en sus partes componentes. Cada parte se conoce como un Nombre Distinguido Relativo, o RDN. ldap_explode_dn() devuelve una matriz terminada en NULL, cada componente de la cual contiene un RDN del DN. El parámetro notypes se usa para solicitar que solo se devuelvan los valores RDN, no sus tipos. Por ejemplo, el DN "cn=Bob, c=US" se devolvería como { "cn=Bob", "c=US", NULL } o { "Bob", "US", NULL }, dependiendo de si notypes era 0 o 1, respectivamente. Los valores de aserción en las cadenas RDN pueden incluir caracteres escapados. El resultado puede liberarse llamando a ldap_value_free(3).

De manera similar, la rutina ldap_explode_rdn() toma un RDN como el devuelto por ldap_explode_dn(dn,0) y lo divide en sus partes componentes "tipo=valor" (o solo "valor", si el parámetro notypes está establecido). Tenga en cuenta que el valor no se desempaqueta. El resultado puede liberarse llamando a ldap_value_free(3).

ldap_dn2ufn() se utiliza para convertir un DN como el devuelto por ldap_get_dn(3) a una forma más fácil de usar, eliminando todos los nombres de tipo. Consulte "Using the Directory to Achieve User Friendly Naming" (RFC 1781) para obtener más detalles sobre el formato UFN. Debido a la naturaleza ambigua del formato, generalmente solo se utiliza para fines de visualización. El espacio para el UFN devuelto se obtiene dinámicamente y el usuario es responsable de liberarlo mediante una llamada a ldap_memfree(3).

ldap_dn2dcedn() se utiliza para convertir un DN como el devuelto por ldap_get_dn(3) a un DN estilo DCE, por ejemplo, una cadena con RDNs más significativos a menos significativos separados por barras ('/'); los componentes RDN se separan por comas (','). Solo se permiten caracteres imprimibles (por ejemplo, cadena imprimible LDAPv2), al menos en esta implementación. ldap_dcedn2dn() realiza la operación opuesta. ldap_dn2ad_canonical() convierte un DN en un nombre canónico de AD, que es básicamente un DN de DCE sin tipos de atributos. El dominio final, si está presente, se convierte en un dominio similar a DNS. El espacio para el valor devuelto se obtiene dinámicamente y el usuario es responsable de liberarlo mediante una llamada a ldap_memfree(3).

ERRORES

Si ocurre un error en ldap_get_dn(), se devuelve NULL y el campo ld_errno en el parámetro ld se establece para indicar el error. Consulte ldap_error(3) para una descripción de los posibles códigos de error. ldap_explode_dn(), ldap_explode_rdn(), ldap_dn2ufn(), ldap_dn2dcedn(), ldap_dcedn2dn() y ldap_dn2ad_canonical() devolverán NULL con errno(3) establecido adecuadamente en caso de problemas.

NOTAS

Estas rutinas asignan dinámicamente memoria que el llamante debe liberar.

VER TAMBIÉN

ldap(3), ldap_error(3), ldap_first_entry(3), ldap_memfree(3), ldap_value_free(3)

NOMBRE

ldap_get_dn, ldap_get_rdn - obtener el nombre distinguido o el nombre RDN de una entrada LDAP

BIBLIOTECA

Librería de cliente LDAP (libldap), parte de OpenLDAP (http://www.openldap.org)

SINOPSIS

#include <ldap.h>

char *ldap_get_dn( LDAP *ld, LDAPMessage *entry );

char *ldap_get_rdn( LDAP *ld, LDAPMessage *entry, char **dn_ref, int ref_type );

DESCRIPCIÓN

La función ldap_get_dn() recupera el nombre distinguido (DN) de una entrada LDAP dada. El DN se devuelve como una cadena de caracteres asignada por la biblioteca.

La función ldap_get_rdn() recupera el nombre RDN (Relative Distinguished Name) de una entrada LDAP dada. El RDN se devuelve como una cadena de caracteres asignada por la biblioteca. El parámetro dn_ref se utiliza para devolver el resto del DN (el DN superior). El parámetro ref_type controla el formato de la cadena devuelta en dn_ref . Si ref_type es LDAP_DN_FORMAT_UFDA , entonces dn_ref se establecerá en la cadena de DN superior en formato de notación estándar de tuplas (por ejemplo, "ou=People,dc=example,dc=com"). Si ref_type es LDAP_DN_FORMAT_LDAP , entonces dn_ref se establecerá en la cadena de DN superior en formato de notación estándar de LDAP (por ejemplo, "dc=example,dc=com").

Es responsabilidad del llamador liberar la memoria asignada para las cadenas devueltas utilizando ldap_memfree() .

ERRORES

Si ocurre un error, ldap_get_dn() y ldap_get_rdn() devuelven NULL . La función ldap_get_errno() se puede usar para recuperar el código de error LDAP. El estado de la conexión puede ser consultado con ldap_get_error() .

NOTAS

Estas funciones son útiles para procesar los resultados de una operación de búsqueda LDAP.

VER TAMBIÉN

ldap_first_entry(3) , ldap_next_entry(3) , ldap_memfree(3)
