ldns-testns(1) Manual de Comandos Generales ldns-testns(1)

NOMBRE

ldns-testns - herramienta simple de servidor de nombres falso

SINOPSIS

ldns-testns [ OPCION ] archivo_de_datos

DESCRIPCIÓN

ldns-testns se puede usar para proporcionar respuestas a consultas DNS para pruebas. Las respuestas están predefinidas y se pueden adaptar a las necesidades de prueba. Las respuestas pueden ser salvajemente inválidas o no analizables.

Este programa es una ayuda para la depuración. No es eficiente, especialmente con un archivo de configuración largo, pero puede dar cualquier respuesta a cualquier consulta. Esto puede ayudar al desarrollador a preescribir respuestas para las consultas.

Escucha en IP4 UDP y TCP por defecto. Puede especificar un paquete RR por RR con indicadores de encabezado para devolver.

ldns-testns no está destinado a uso en producción.

OPCIONES

-r
Escucha en un puerto aleatorio. El número de puerto se imprime en stdout.
-p puerto
Escucha en el puerto especificado.
-f num
Crea un número de instancias adicionales que sirven los mismos puertos y el mismo archivo de datos. No se cierran; se imprime 'forked pid: <num>' y tiene que matarlas usted mismo.
-v
Muestra más información de depuración. Es posible dar esta opción múltiples veces para aumentar el nivel de verbosidad.
-6
Enlaza a la dirección IP6 en lugar de IP4. Usar junto con -p.
archivo_de_datos
El archivo de datos se lee al inicio. Contiene consultas y los paquetes que deben enviarse en respuesta a esas consultas. El formato del archivo de datos se explica a continuación.

FORMATO DEL ARCHIVO DE DATOS

El formato del archivo de datos utiliza ';' para denotar comentarios. Se procesa un número de entradas de principio a fin. Se utiliza la primera entrada coincidente para responder a la consulta. Este es un formato basado en líneas. Los registros de recursos DNS se introducen en formato de archivo de zona.

Puede usar las directivas $ORIGIN y $TTL. Los paréntesis y la combinación de líneas de los archivos de zona no están permitidos.

$ORIGIN origen $TTL ttl_por_defecto

INICIO_ENTRADA

; primero proporcione líneas MATCH, que dicen qué consultas se coinciden ; con esta entrada. ; 'opcode' hace que la consulta coincida con el opcode de la respuesta ; si lo omite, cualquier opcode coincide con esta entrada. ; 'qtype' hace que la consulta coincida con el qtype de la respuesta ; 'qname' hace que la consulta coincida con el qname de la respuesta ; 'serial=1023' hace que la consulta coincida si el serial ixfr es 1023.

MATCH [opcode] [qtype] [qname] [serial=<valor>] MATCH [UDP|TCP] MATCH ...

; Luego se especifica el encabezado de REPLY.

REPLY opcode, rcode o flags.
(opcode) QUERY IQUERY STATUS NOTIFY UPDATE
(rcode) NOERROR FORMERR SERVFAIL NXDOMAIN NOTIMPL YXDOMAIN
YXRRSET NXRRSET NOTAUTH NOTZONE
(flags) QR AA TC RD CD RA AD

REPLY ...

; cualquier acción adicional a realizar.

ADJUST copy_id ; 'copy_id' copia el ID de la consulta a la respuesta.

; 'sleep=10' duerme durante 10 segundos antes de dar la respuesta (TCP está abierto)

ADJUST [sleep=<num>] ; duerme antes de dar cualquier respuesta ADJUST [packet_sleep=<num>] ; duerme antes de este paquete en secuencia

SECCION QUESTION <RR, uno por línea> ; el recuento de RR se determina automáticamente.

SECCION ANSWER <RR, uno por línea>

SECCION AUTHORITY <RR, uno por línea>

SECCION ADDITIONAL <RR, uno por línea>

HEX_EDNSDATA_BEGIN <Datos Hex de una opción EDNS> HEX_EDNSDATA_END

EXTRA_PACKET ; seguido de SECCION, REPLY para más paquetes. HEX_ANSWER_BEGIN ; seguido de datos hex
; esto reemplaza cualquier paquete de respuesta construido
; con las palabras clave SECCION (solo SECCION QUESTION
; se usa para coincidir con consultas). Si los datos no se
; pueden analizar, se ignoran las reglas ADJUST para el paquete de
; respuesta

HEX_ANSWER_END

FIN_ENTRADA
