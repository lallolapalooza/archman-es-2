ldap_dup(3)

Paquete: libldap

Licencias: personalizada

LDAP_OPEN(3) Manual de funciones de biblioteca LDAP_OPEN(3)

NOMBRE

ldap_dup, ldap_destroy, - Duplicar y destruir identificadores de sesión LDAP

BIBLIOTECA

OpenLDAP LDAP (libldap, -lldap)

SINOPSIS

#include <ldap.h>
LDAP *ldap_dup(
LDAP *old );
int ldap_destroy(
LDAP *old );

DESCRIPCIÓN

ldap_dup() duplica un identificador de sesión LDAP (LDAP *) existente. El nuevo identificador de sesión puede usarse concurrentemente con el identificador de sesión original. En un entorno con hilos, diferentes hilos pueden ejecutar solicitudes concurrentes en la misma conexión/sesión sin temor a contaminación. Cada identificador de sesión gestiona sus propios resultados de error privados.

ldap_destroy() destruye un identificador de sesión existente.

Las funciones ldap_dup() y ldap_destroy() se utilizan en conjunto con una versión "segura para hilos" de libldap para permitir llamadas a la API seguras para hilos, de modo que una sola sesión pueda ser utilizada simultáneamente en múltiples hilos con un manejo de errores consistente.

Cuando una sesión se crea a través de una de las funciones de creación de sesiones, incluidas ldap_open(3), ldap_init(3), ldap_initialize(3) o ldap_init_fd(3), se devuelve un identificador de sesión LDAP * a la aplicación. El identificador de sesión puede ser compartido entre hilos, sin embargo, los códigos de error son exclusivos de un identificador de sesión. Múltiples hilos que realizan diferentes operaciones utilizando el mismo identificador de sesión resultarán en códigos de error y valores de retorno inconsistentes.

Para evitar esta confusión, ldap_dup() se utiliza para duplicar un identificador de sesión existente, de modo que múltiples hilos puedan compartir la sesión y mantener información de error y resultados consistentes.

Las colas de mensajes para una sesión se comparten entre los identificadores de sesión hermanos. Los resultados de las operaciones en los identificadores de sesión hermanos son accesibles para todos los identificadores de sesión hermanos. Las aplicaciones que deseen resultados asociados con una operación específica deben proporcionar el msgid apropiado a ldap_result(). Las aplicaciones deben evitar llamar a ldap_result() con LDAP_RES_ANY, ya que esto puede "robar" y devolver resultados al hilo que llama que otra operación en un hilo diferente, utilizando un identificador de sesión diferente, puede requerir para completarse.

Cuando se llama a ldap_unbind() en un identificador de sesión con hermanos, todos los hermanos quedan invalidos.

Los hermanos deben destruirse utilizando ldap_destroy(). Los recursos del identificador de sesión asociados con el original (LDAP *) se liberarán cuando se destruya el último identificador de sesión o cuando se llame a ldap_unbind(), si no existen otros identificadores de sesión actualmente.

ERRORES

Si ocurre un error, ldap_dup() devolverá NULL y errno debería establecerse apropiadamente. ldap_destroy() devolverá directamente el código LDAP asociado al error (o LDAP_SUCCESS en caso de éxito); errno también debería establecerse siempre que sea apropiado.

VER TAMBIÉN

ldap_open(3), ldap_init(3), ldap_initialize(3), ldap_init_fd(3), errno(3)
