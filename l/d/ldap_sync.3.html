NOMBRE

ldap_sync_init, ldap_sync_init_refresh_only, ldap_sync_init_refresh_and_persist, ldap_sync_poll - Rutinas de sincronización LDAP

BIBLIOTECA

OpenLDAP LDAP (libldap, -lldap)

SINOPSIS

#include <ldap.h>
int ldap_sync_init(ldap_sync_t *ls, int mode);
int ldap_sync_init_refresh_only(ldap_sync_t *ls);
int ldap_sync_init_refresh_and_persist(ldap_sync_t *ls);
int ldap_sync_poll(ldap_sync_t *ls);
ldap_sync_t * ldap_sync_initialize(ldap_sync_t *ls);
void ldap_sync_destroy(ldap_sync_t *ls, int freeit);
typedef int (*ldap_sync_search_entry_f)(ldap_sync_t *ls,
LDAPMessage *msg, struct berval *entryUUID,
ldap_sync_refresh_t phase);
typedef int (*ldap_sync_search_reference_f)(ldap_sync_t *ls,
LDAPMessage *msg);
typedef int (*ldap_sync_intermediate_f)(ldap_sync_t *ls,
LDAPMessage *msg, BerVarray syncUUIDs,
ldap_sync_refresh_t phase);
typedef int (*ldap_sync_search_result_f)(ldap_sync_t *ls,
LDAPMessage *msg, int refreshDeletes);

DESCRIPCIÓN

Estas rutinas proporcionan una interfaz para la operación de Sincronización de Contenido LDAP (RFC 4533). Requieren una estructura ldap_sync_t configurada con los parámetros necesarios para las diversas fases de la operación; esto incluye la configuración de algunos manejadores para eventos especiales. Todos los manejadores toman un puntero a la estructura ldap_sync_t como primer argumento, y un puntero a la estructura LDAPMessage tal como la recibe el servidor de la biblioteca cliente, además, ocasionalmente, de otros argumentos específicos.

Los miembros de la estructura ldap_sync_t son:

char *ls_base
La base de búsqueda; por defecto, la opción BASE en ldap.conf(5).
int ls_scope
El ámbito de búsqueda (uno de LDAP_SCOPE_BASE, LDAP_SCOPE_ONELEVEL, LDAP_SCOPE_SUBORDINATE o LDAP_SCOPE_SUBTREE; ver ldap.h para detalles).
char *ls_filter
El filtro (RFC 4515); por defecto, (objectClass=*).
char **ls_attrs
Los atributos solicitados; por defecto NULL, lo que indica todos los atributos de usuario.
int ls_timelimit
El límite de tiempo solicitado (en segundos); por defecto 0, para indicar sin límite.
int ls_sizelimit
El límite de tamaño solicitado (en entradas); por defecto 0, para indicar sin límite.
int ls_timeout
El tiempo de espera deseado durante la consulta con ldap_sync_poll(3). Un valor de -1 significa que la consulta es bloqueante, por lo que ldap_sync_poll(3) no devolverá hasta que se reciba un mensaje; un valor de 0 significa que la consulta devuelve inmediatamente, sin importar si hay alguna respuesta disponible o no; un valor positivo representa el tiempo de espera que la función ldap_sync_poll(3) esperará una respuesta antes de devolver, a menos que se reciba un mensaje; en ese caso, ldap_sync_poll(3) devuelve tan pronto como el mensaje esté disponible.
ldap_sync_search_entry_f ls_search_entry
Una función que se llama cada vez que se devuelve una entrada. El argumento msg es el LDAPMessage que contiene la entrada searchResultEntry; puede ser analizado usando las rutinas de la API del cliente habituales, como ldap_get_dn(3), ldap_first_attribute(3), y así sucesivamente. El argumento entryUUID contiene el entryUUID de la entrada. El argumento phase indica el tipo de operación: uno de LDAP_SYNC_CAPI_PRESENT, LDAP_SYNC_CAPI_ADD, LDAP_SYNC_CAPI_MODIFY, LDAP_SYNC_CAPI_DELETE; en caso de LDAP_SYNC_CAPI_PRESENT o LDAP_SYNC_CAPI_DELETE, solo el DN está contenido en el LDAPMessage; en caso de LDAP_SYNC_CAPI_MODIFY, la entrada completa está contenida en el LDAPMessage, y la aplicación es responsable de determinar las diferencias entre la nueva vista de la entrada proporcionada por el llamante y los datos ya conocidos.
ldap_sync_search_reference_f ls_search_reference
Una función que se llama cada vez que se devuelve una referencia de búsqueda. El argumento msg es el LDAPMessage que contiene la searchResultReference; puede ser analizado usando las rutinas de la API del cliente habituales, como ldap_parse_reference(3).
ldap_sync_intermediate_f ls_intermediate
Una función que se llama cada vez que ocurre algo relevante durante la fase de actualización (refresh) de la búsqueda, marcada por un tipo de mensaje intermediateResponse. El argumento msg es el LDAPMessage que contiene la respuesta intermedia; puede ser analizado usando las rutinas de la API del cliente habituales, como ldap_parse_intermediate(3). El argumento syncUUIDs contiene un array de UUIDs de las entradas que depende del valor del argumento phase. En caso de LDAP_SYNC_CAPI_PRESENTS, se está entrando en la fase "present"; esto significa que la siguiente secuencia de resultados consistirá en entradas en estado de sincronización "present". En caso de LDAP_SYNC_CAPI_DELETES, se está entrando en la fase "deletes"; esto significa que la siguiente secuencia de resultados consistirá en entradas en estado de sincronización "delete". En caso de LDAP_SYNC_CAPI_PRESENTS_IDSET, el mensaje contiene un conjunto de UUIDs de entradas que están presentes; reemplaza una fase "presents". En caso de LDAP_SYNC_CAPI_DELETES_IDSET, el mensaje contiene un conjunto de UUIDs de entradas que han sido eliminadas; reemplaza una fase "deletes". En caso de LDAP_SYNC_CAPI_DONE, se ha devuelto una fase "presents" con "refreshDone" establecido en "TRUE" para indicar que la fase de actualización de refreshAndPersist ha terminado, y el cliente debe comenzar a consultar. Excepto en los casos LDAP_SYNC_CAPI_PRESENTS_IDSET y LDAP_SYNC_CAPI_DELETES_IDSET, syncUUIDs es NULL.
ldap_sync_search_result_f ls_search_result
Una función que se llama cada vez que se devuelve un searchResultDone. En refreshAndPersist esto solo puede ocurrir cuando el servidor decide que la búsqueda debe interrumpirse. El argumento msg es el LDAPMessage que contiene la respuesta; puede ser analizado usando las rutinas de la API del cliente habituales, como ldap_parse_result(3). El argumento refreshDeletes no es relevante en este caso; siempre debe ser -1.
void *ls_private
Un puntero a datos privados. El cliente puede registrar aquí un puntero a datos que los manejadores anteriores puedan necesitar.
LDAP *ls_ld
Un puntero a una estructura LDAP que se utiliza para conectarse al servidor. Es responsabilidad del cliente inicializar la estructura y proporcionar la autenticación y seguridad apropiadas en su lugar.

DESCRIPTION

The ldap_sync_init() function initializes an existing ldap_sync_t structure, populating it with values for the sync operations. The user is responsible for initializing the connection (member ls_ld), setting up transport security (TLS), binding, and any other necessary initialization. The user must also fill in all documented search-related fields of the ldap_sync_t structure.

At the end of a session, the structure can be cleaned up by calling ldap_sync_destroy(3), which handles freeing all data allocated by ldap_mem*(3) routines. Otherwise, the user should take care of destroying and zeroing out the documented search-related fields and then call ldap_sync_destroy(3) to free undocumented members set by the API.

REFRESH ONLY

The refreshOnly functionality is achieved by periodically calling ldap_sync_init(3) with the mode set to LDAP_SYNC_REFRESH_ONLY, or equivalently, by directly calling ldap_sync_init_refresh_only(3). The state of the search and the consistency of the search parameters are preserved across calls by passing the ldap_sync_t structure as left by the previous call.

REFRESH AND PERSIST

The refreshAndPersist functionality is obtained by calling ldap_sync_init(3) with the mode set to LDAP_SYNC_REFRESH_AND_PERSIST, or equivalently, by directly calling ldap_sync_init_refresh_and_persist(3) and, after a successful return, by repeatedly polling with ldap_sync_poll(3) according to the desired pattern.

A client may insert a call to ldap_sync_poll(3) into an external loop to check if any modification was returned; in this case, it might be appropriate to set ls_timeout to 0, or to set it to a finite, small value. Otherwise, if the client's main purpose consists in waiting for responses, a timeout of -1 is most suitable, so that the function only returns after some data has been received and handled.

ERRORS

All routines return any LDAP error resulting from a lower-level error in the API calls they are based on, or LDAP_SUCCESS in case of success. ldap_sync_poll(3) may return LDAP_SYNC_REFRESH_REQUIRED if a full refresh is requested by the server. In this case, it is appropriate to call ldap_sync_init(3) again, passing the same ldap_sync_t structure as resulted from any previous call.
