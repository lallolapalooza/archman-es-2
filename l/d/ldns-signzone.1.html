NOMBRE

ldns-signzone - firma un archivo de zona con datos DNSSEC

SINOPSIS

ldns-signzone [ OPCIONES ] ARCHIVO_DE_ZONA CLAVE [CLAVE [CLAVE] ...]

DESCRIPCIÓN

ldns-signzone se utiliza para generar una zona firmada con DNSSEC. Al ejecutarse, creará un nuevo archivo de zona que contiene registros de recursos RRSIG y NSEC, según lo especificado en RFC 4033, RFC 4034 y RFC 4035.

Las claves deben especificarse por su nombre base (es decir, sin .private). Si la DNSKEY que pertenece a la clave en el archivo .private no está presente en la zona, se leerá del archivo <nombre base>.key. Si ese archivo no existe, el valor DNSKEY se generará a partir de la clave privada.

Se pueden especificar varias claves. Las claves de firma de claves (Key Signing Keys) se utilizan como tales cuando ya están presentes en la zona o se especifican en un archivo .key, y tienen el bit KSK activado.

OPCIONES

-b
Aumenta la zona y los RR con textos de comentarios adicionales para un diseño más legible y fácil de depurar. Los registros DS tendrán una versión de burbuja de los datos en el texto del comentario, los registros NSEC3 tendrán los nombres de propietario sin cifrar en el texto del comentario.

Sin esta opción, solo las RR DNSKEY tendrán su Etiqueta de Clave anotada en el texto del comentario.

-d
Normalmente, si la RR DNSKEY para una clave utilizada para firmar la zona no se encuentra en el archivo de zona, se leerá de .key o se derivará de la clave privada (en ese orden). Esta opción desactiva esa función, de modo que solo se añaden las firmas a la zona.
-e fecha
Establece la fecha de expiración de las firmas en esta fecha, el formato puede ser AAAA MM DD [HHMMSS] o una marca de tiempo.
-f archivo
Utiliza este archivo para almacenar la zona firmada (por defecto <archivo original>.signed)
-i fecha
Establece la fecha de inicio de las firmas en esta fecha, el formato puede ser AAAA MM DD [HHMMSS] o una marca de tiempo.
-o origen
Utiliza esto como el origen de la zona.
-u
establece el serial SOA al número de segundos desde el 01/01/1970.
-v
Imprime la versión y sale.
-z [esquema:]hash
Calcula el resumen de la zona y los añade como RR ZONEMD. El `esquema' (opcional) debe ser `simple` (o 1) y `hash` debe ser `sha384` (o 1) o `sha512` (o 2). Esta opción se puede dar más de una vez.
-Z
Permite que se añadan ZONEMDs sin firmar.
-A
Firma el registro DNSKEY con todas las claves. Por defecto, se firma con un número mínimo de claves para mantener pequeño el tamaño de la respuesta para la consulta DNSKEY, y solo se utilizan las claves SEP que se pasan. Si no hay claves SEP, el conjunto RR DNSKEY se firma con las claves no SEP. Esta opción desactiva el valor predeterminado y se utilizan todas las claves para firmar el conjunto RR DNSKEY.
-U
Firma con cada algoritmo único en las claves proporcionadas. El conjunto DNSKEY se firma con todas las claves SEP, más todas las claves no SEP que tienen un algoritmo que no estaba presente en el conjunto de claves SEP.
-E nombre
Utiliza el motor criptográfico EVP con el nombre dado para firmar. Esto puede tener algunas opciones adicionales; consulte OPCIONES DE MOTOR para más información.
-K id_algoritmo,id_clave

Utiliza la clave `id_clave' como clave de firma para el algoritmo `id_algoritmo' como Clave de Firma de Claves (KSK). Esta opción se utiliza cuando se utiliza un motor OpenSSL, consulte OPCIONES DE MOTOR para más información.

-k id_algoritmo,id_clave
Utiliza la clave `id_clave' como clave de firma para el algoritmo `id_algoritmo' como Clave de Firma de Zona (ZSK). Esta opción se utiliza cuando se utiliza un motor OpenSSL, consulte OPCIONES DE MOTOR para más información.
-n
Utiliza NSEC3 en lugar de NSEC.
Si utiliza NSEC3, puede especificar las siguientes opciones adicionales:
-a algoritmo
Algoritmo utilizado para crear los nombres de propietario de NSEC3 cifrados.
-p
Exclusión. Todos los registros NSEC3 en la zona tendrán el indicador de exclusión activado. Después de firmar, puede añadir delegaciones inseguras a la zona firmada.
-s cadena
Sal.
-t número
Número de iteraciones de hash.

OPCIONES DE MOTOR

Puede modificar los motores posibles, si son compatibles, estableciendo un archivo de configuración de OpenSSL. Esto se hace a través de la variable de entorno OPENSSL_CONF.

Las opciones de clave (-k y -K) funcionan de la siguiente manera: especifica un algoritmo DNSSEC (utilizando su nombre simbólico, por ejemplo, RSASHA256 o su identificador numérico, por ejemplo, 8), seguido de una coma y un identificador de clave (no se permite espacio en blanco entre el algoritmo y la coma, ni entre la coma y el identificador de clave).

El identificador de clave puede ser cualquiera de los siguientes:


<id>
<ranura>:<id>
id_<id>
slot_<ranura>-id_<id>
label_<etiqueta>
slot_<ranura>-label_<etiqueta>

Donde '<id>' es el identificador de clave PKCS #11 en notación hexadecimal, '<etiqueta>' es la etiqueta legible por humanos de PKCS #11, y '<ranura>' es el número de ranura donde se encuentra el token.

Las versiones más recientes de los motores OpenSSL pueden admitir el esquema URI PKCS #11 (RFC 7512), consulte la documentación de su motor.

Si aún no está presente, se generará una RR DNSKEY a partir de los datos de la clave y se añadirá a la zona.

EJEMPLOS

ldns-signzone nlnetlabs.nl Knlnetlabs.nl.+005+12273
Firma la zona en el archivo 'nlnetlabs.nl' con la clave en los archivos 'Knlnetlabs.nl.+005+12273.private'. Si la DNSKEY no está presente en la zona, utiliza la clave en el archivo 'Knlnetlabs.nl.+005+12273.key'. Si ese no está presente, genera uno con valores predeterminados a partir de 'Knlnetlabs.nl.+005+12273.private'.
