ldap_modify(3)

Paquete: libldap

Licencias: custom

LDAP_MODIFY(3) Manual de funciones de biblioteca LDAP_MODIFY(3)

NOMBRE

ldap_modify_ext, ldap_modify_ext_s - Realizar una operación de modificación LDAP

BIBLIOTECA

OpenLDAP LDAP (libldap, -lldap)

SINOPSIS

#include <ldap.h>
int ldap_modify_ext(
LDAP *ld,
char *dn,
LDAPMod *mods[],
LDAPControl **sctrls,
LDAPControl **cctrls,
int *msgidp );
int ldap_modify_ext_s(
LDAP *ld,
char *dn,
LDAPMod *mods[],
LDAPControl **sctrls,
LDAPControl **cctrls );
void ldap_mods_free(
LDAPMod **mods,
int freemods );

DESCRIPCIÓN

La rutina ldap_modify_ext_s() se utiliza para realizar una operación de modificación LDAP. dn es el DN de la entrada a modificar, y mods es un array terminado en nulo de modificaciones a realizar en la entrada. Cada elemento del array mods es un puntero a una estructura LDAPMod, que se define a continuación.

typedef struct ldapmod {
    int mod_op;
    char *mod_type;
    union {
        char **modv_strvals;
        struct berval **modv_bvals;
    } mod_vals;
} LDAPMod;
#define mod_values mod_vals.modv_strvals
#define mod_bvalues mod_vals.modv_bvals

El campo mod_op se utiliza para especificar el tipo de modificación a realizar y debe ser uno de LDAP_MOD_ADD, LDAP_MOD_DELETE o LDAP_MOD_REPLACE. Los campos mod_type y mod_values especifican el tipo de atributo a modificar y un array terminado en nulo de valores a añadir, eliminar o reemplazar respectivamente.

Si necesita especificar un valor no-cadena (por ejemplo, para añadir un valor de atributo de foto o audio), debe establecer mod_op al OR lógico de la operación como se indica arriba (por ejemplo, LDAP_MOD_REPLACE) y la constante LDAP_MOD_BVALUES. En este caso, se debe usar mod_bvalues en lugar de mod_values, y debe apuntar a un array terminado en nulo de estructuras berval, como se define en <lber.h>.

Para modificaciones LDAP_MOD_ADD, los valores dados se añaden a la entrada, creando el atributo si es necesario. Para modificaciones LDAP_MOD_DELETE, los valores dados se eliminan de la entrada, eliminando el atributo si no quedan valores. Si se va a eliminar el atributo completo, el campo mod_values debe establecerse a NULL. Para modificaciones LDAP_MOD_REPLACE, el atributo tendrá los valores listados después de la modificación, habiendo sido creado si es necesario. Todas las modificaciones se realizan en el orden en que están listadas.

ldap_mods_free() puede usarse para liberar cada elemento de un array de estructuras mod terminado en nulo. Si freemods es distinto de cero, el propio puntero mods también se libera.

ldap_modify_ext_s() devuelve un código que indica el éxito o, en caso de fallo, indicando la naturaleza del fallo. Véase ldap_error(3) para más detalles.

La operación ldap_modify_ext() funciona de la misma manera que ldap_modify_ext_s(), excepto que es asíncrona. El entero al que apunta msgidp se establece al ID del mensaje de la solicitud de modificación. El resultado de la operación se puede obtener llamando a ldap_result(3).

Tanto ldap_modify_ext() como ldap_modify_ext_s() permiten pasar controles de servidor y cliente a través de los parámetros sctrls y cctrls, respectivamente.

INTERFACES OBSOLETAS

Las rutinas ldap_modify() y ldap_modify_s() están obsoletas en favor de las rutinas ldap_modify_ext() y ldap_modify_ext_s(), respectivamente.

Las interfaces obsoletas generalmente permanecen en la biblioteca. La macro LDAP_DEPRECATED se puede definir a un valor distinto de cero (por ejemplo, -DLDAP_DEPRECATED=1) al compilar programas diseñados para usar interfaces obsoletas. Se recomienda que los desarrolladores que escriban programas nuevos, o actualicen programas antiguos, eviten el uso de interfaces obsoletas. Con el tiempo, se espera que la documentación (y, finalmente, el soporte) para las interfaces obsoletas se elimine.
