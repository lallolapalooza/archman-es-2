ldap_open(3)

Paquete: libldap

Licencias: custom

LDAP_OPEN(3) Manual de funciones de la biblioteca LDAP_OPEN(3)

NOMBRE

ldap_init, ldap_initialize, ldap_open - Inicializa la biblioteca LDAP y abre una conexión a un servidor LDAP

BIBLIOTECA

OpenLDAP LDAP (libldap, -lldap)

SINOPSIS

#include <ldap.h>
LDAP *ldap_open(host, port)
char *host;
int port;
LDAP *ldap_init(host, port)
char *host;
int port;
int ldap_initialize(ldp, uri)
LDAP **ldp;
char *uri;
int ldap_connect(ldp)
LDAP *ldp;
int ldap_set_urllist_proc(ld, proc, params)
LDAP *ld;
LDAP_URLLIST_PROC *proc;
void *params;
int (LDAP_URLLIST_PROC)(ld, urllist, url, params);
LDAP *ld;
LDAPURLDesc **urllist;
LDAPURLDesc **url;
void *params;
#include <openldap.h>
int ldap_init_fd(fd, proto, uri, ldp)
ber_socket_t fd;
int proto;
char *uri;
LDAP **ldp;

DESCRIPCIÓN

ldap_open() abre una conexión a un servidor LDAP y asigna una estructura LDAP que se utiliza para identificar la conexión y mantener información por conexión. ldap_init() asigna una estructura LDAP pero no abre una conexión inicial. ldap_initialize() asigna una estructura LDAP pero no abre una conexión inicial. ldap_init_fd() asigna una estructura LDAP utilizando una conexión existente en el socket proporcionado. Una de estas rutinas debe ser llamada antes de intentar cualquier operación.

ldap_open() toma host, el nombre de host en el que se está ejecutando el servidor LDAP, y port, el número de puerto al que conectarse. Si se desea el puerto predeterminado asignado por IANA, 389, se debe especificar LDAP_PORT para port. El parámetro host puede contener una lista de hosts separados por espacios para intentar conectarse, y cada host puede ser opcionalmente de la forma host:puerto. Si está presente, el :puerto anula el parámetro puerto a ldap_open(). Al conectarse exitosamente a un servidor LDAP, ldap_open() devuelve un puntero a una estructura LDAP opaca, que debe pasarse a llamadas posteriores a ldap_bind(), ldap_search(), etc. Ciertos campos de la estructura LDAP se pueden establecer para indicar el límite de tamaño, el límite de tiempo y cómo se manejan los alias durante las operaciones; el acceso de lectura y escritura a esos campos debe realizarse llamando a ldap_get_option(3) y ldap_set_option(3) respectivamente, siempre que sea posible.

ldap_init() actúa como ldap_open(), pero no abre una conexión al servidor LDAP. La apertura real de la conexión ocurrirá cuando se intente la primera operación.

ldap_initialize() actúa como ldap_init(), pero devuelve un entero que indica éxito o la razón del fallo, y permite especificar detalles para la conexión en la parte del esquema del URI. El parámetro uri puede ser una lista de URIs separados por comas o espacios en blanco que contenga solo los campos esquema, host y puerto. Además de ldap, otros valores reconocidos (no estándar) del campo esquema son ldaps (LDAP sobre TLS), ldapi (LDAP sobre IPC) y cldap (LDAP sin conexión). Si hay otros campos presentes, el comportamiento es indefinido.

En este momento, ldap_open() y ldap_init() están obsoletos en favor de ldap_initialize(), esencialmente porque el primero permite especificar un esquema en el URI y devuelve explícitamente un código de error.

ldap_connect() hace que un manejador creado por ldap_initialize() se conecte al servidor. Esto es útil en situaciones donde se requiere un descriptor de archivo antes de realizar una solicitud.

ldap_init_fd() permite inicializar una estructura LDAP utilizando una conexión ya abierta. El parámetro proto debe ser uno de LDAP_PROTO_TCP, LDAP_PROTO_UDP o LDAP_PROTO_IPC para una conexión que utilice TCP, UDP o IPC, respectivamente. El valor LDAP_PROTO_EXT también puede especificarse si se van a utilizar manejadores de sockbuf proporcionados por el usuario. Tenga en cuenta que el soporte para UDP no está implementado a menos que libldap se haya compilado con LDAP_CONNECTIONLESS definido. El parámetro uri puede proporcionarse opcionalmente con fines informativos.

ldap_set_urllist_proc() permite establecer una función proc de tipo LDAP_URLLIST_PROC que se llama cuando se puede establecer una conexión exitosa. Esta función recibe la lista de URIs analizada de la cadena uri pasada originalmente a ldap_initialize(), y el que se conectó exitosamente. La función puede manipular la lista de URIs; el uso típico consiste en mover el URI exitoso al principio de la lista, de modo que los intentos posteriores de conectarse a uno de los URIs utilizando el mismo manejador LDAP lo intenten primero. Si ld es nulo, proc se establece como un parámetro global que es heredado por todos los manejadores dentro del proceso que se crean después de la llamada a ldap_set_urllist_proc(). Por defecto, no se establece ningún LDAP_URLLIST_PROC. En un entorno multihilo, ldap_set_urllist_proc() debe llamarse antes de que se inicie cualquier operación concurrente que utilice el manejador LDAP.

Nota: la primera llamada a la biblioteca LDAP también inicializa las opciones globales de la biblioteca. Por lo tanto, la primera llamada debe ser monohilo o estar protegida de alguna manera para asegurar que solo una llamada esté activa. Se recomienda que se utilice ldap_get_option() o ldap_set_option() en el hilo principal del programa antes de que se creen hilos adicionales. Consulte ldap_get_option(3).

ERRORES

Si ocurre un error, ldap_open() y ldap_init() devolverán NULL y errno debería establecerse adecuadamente. ldap_initialize() y ldap_init_fd() devolverán directamente el código LDAP asociado al error (o LDAP_SUCCESS en caso de éxito); errno también debería establecerse siempre que sea apropiado. ldap_set_urllist_proc() devuelve LDAP_OPT_ERROR en caso de error, y LDAP_OPT_SUCCESS en caso de éxito.

VER TAMBIÉN
