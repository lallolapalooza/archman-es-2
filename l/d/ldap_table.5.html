NOMBRE

ldap_table - Configuración del cliente LDAP de Postfix

SINOPSIS

postmap -q "cadena" ldap:/etc/postfix/nombre_archivo
postmap -q - ldap:/etc/postfix/nombre_archivo <archivo_entrada

DESCRIPCIÓN


El sistema de correo Postfix utiliza tablas opcionales para la reescritura de direcciones o el enrutamiento de correo. Estas tablas suelen estar en formato dbm o db.

Alternativamente, las tablas de consulta pueden especificarse como bases de datos LDAP.

Para usar consultas LDAP, define una fuente LDAP como tabla de consulta en main.cf, por ejemplo:

    alias_maps = ldap:/etc/postfix/ldap-aliases.cf

El archivo /etc/postfix/ldap-aliases.cf tiene el mismo formato que el archivo main.cf de Postfix y puede especificar los parámetros descritos a continuación. Al final de este manual se incluye un ejemplo.

Esta método de configuración está disponible con Postfix versión 2.1 y posteriores. Consulta la sección "PARÁMETROS OBSOLETOS DE MAIN.CF" más abajo para ver las versiones anteriores de Postfix.

Para obtener detalles sobre SSL y STARTTLS de LDAP, consulta la sección sobre SSL y STARTTLS más abajo.

PERTENENCIA A LISTAS

Al usar LDAP para almacenar listas como $mynetworks, $mydestination, $relay_domains, $local_recipient_maps, etc., es importante entender que la tabla debe almacenar cada miembro de la lista como una clave separada. La consulta de la tabla verifica la *existencia* de la clave. Consulta "Listas de Postfix versus tablas" en el documento DATABASE_README para una discusión.

NO crees tablas que devuelvan la lista completa de dominios en $mydestination o $relay_domains, etc., o direcciones IP en $mynetworks.

SÍ crea tablas con cada elemento coincidente como clave y con un valor arbitrario. Con las bases de datos LDAP, no es raro devolver la propia clave.

Por ejemplo, NUNCA hagas esto en un mapa que defina $mydestination:

    query_filter = domain=*
    result_attribute = domain

Haz esto en su lugar:

    query_filter = domain=%s
    result_attribute = domain

PARÁMETROS LDAP GENERALES

En el texto siguiente, los valores predeterminados se dan entre paréntesis. Nota: no uses comillas en estas variables; al menos, no hasta que las rutinas de configuración de Postfix comprendan cómo tratar las cadenas entre comillas.

server_host (predeterminado: localhost)
El nombre del host que ejecuta el servidor LDAP, por ejemplo, 
    server_host = ldap.example.com

Dependiendo de la biblioteca cliente LDAP que estés utilizando, debería ser posible especificar varios servidores aquí, con la biblioteca intentándolos en orden si el primero falla. También debería ser posible dar a cada servidor de la lista un puerto diferente (que anula server_port más abajo), nombrando los servidores como

    server_host = ldap.example.com:1444

NOTA: este cliente se reconectará inmediatamente después de un único fallo, y fallará una solicitud de consulta después de que un segundo intento también falle.

Con OpenLDAP, se puede utilizar una (lista de) URL LDAP para especificar tanto los nombres de host como los puertos:

    server_host = ldap://ldap.example.com:1444
                ldap://ldap2.example.com:1444

Se admiten todas las URL LDAP aceptadas por la biblioteca OpenLDAP, incluidas las conexiones a través de sockets de dominio UNIX y LDAP SSL (este último siempre que OpenLDAP se haya compilado con soporte para SSL):

    server_host = ldapi://%2Fsome%2Fpath
                ldaps://ldap.example.com:636
server_port (predeterminado: 389)
El puerto en el que escucha el servidor LDAP, por ejemplo, 
    server_port = 778
timeout (predeterminado: 10 segundos)
El número de segundos que una búsqueda puede tardar antes de que caduque, por ejemplo,



timeout = 5

search_base (Sin valor predeterminado; debes configurarlo)
El DN base RFC2253 en el que realizar la búsqueda, por ejemplo, 
    search_base = dc=tu, dc=com
Con Postfix 2.2 y posteriores, este parámetro admite las siguientes expansiones '%':
%%
Se reemplaza por un carácter '%' literal.
%s
Se reemplaza por la clave de entrada. Se utiliza el citado RFC 2253 para asegurar que la clave de entrada no añada metacaracteres inesperados.
%u
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección (citada según RFC 2253). En caso contrario, %u se reemplaza por la cadena de búsqueda completa. Si la parte local está vacía, la búsqueda se suprime y no devuelve resultados.
%d
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio de la dirección (citada según RFC 2253). En caso contrario, la búsqueda se suprime y no devuelve resultados.
%[SUD]
Para el parámetro search_base, las versiones en mayúsculas de las expansiones anteriores se comportan de forma idéntica a sus contrapartes en minúsculas. Con el parámetro result_format (anteriormente llamado result_filter, consulta la sección SOBRE OTRAS CARACTERÍSTICAS OBSOLETAS y más abajo), se expanden a los componentes correspondientes de la clave de entrada en lugar del valor del resultado.
%[1-9]
Los patrones %1, %2, ... %9 se reemplazan por el componente más significativo correspondiente del dominio de la clave de entrada. Si la clave de entrada es usuario@correo.ejemplo.com, entonces %1 es com, %2 es ejemplo y %3 es correo. Si la clave de entrada no está cualificada o no tiene suficientes componentes de dominio para satisfacer todos los patrones especificados, la búsqueda se suprime y no devuelve resultados.
query_filter (predeterminado: mailacceptinggeneralid=%s)
El filtro RFC2254 utilizado para buscar en el directorio, donde %s es un sustituto de la dirección que Postfix intenta resolver, por ejemplo, 
    query_filter = (&(mail=%s)(paid_up=true))

Este parámetro admite las siguientes expansiones '%':

%%
Se reemplaza por un carácter '%' literal. (Postfix 2.2 y posteriores).
%s
Se reemplaza por la clave de entrada. Se utiliza el citado RFC 2254 para asegurar que la clave de entrada no añada metacaracteres inesperados.
%u
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección (citada según RFC 2254). En caso contrario, %u se reemplaza por la cadena de búsqueda completa. Si la parte local está vacía, la búsqueda se suprime y no devuelve resultados.
%d
Cuando la clave de entrada es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio de la dirección (citada según RFC 2254). En caso contrario, la búsqueda se suprime y no devuelve resultados.
%[SUD]
Las versiones en mayúsculas de las expansiones anteriores se comportan en el parámetro query_filter de forma idéntica a sus contrapartes en minúsculas. Con el parámetro result_format (anteriormente llamado result_filter, consulta la sección SOBRE OTRAS CARACTERÍSTICAS OBSOLETAS y más abajo), se expanden a los componentes correspondientes de la clave de entrada en lugar del valor del resultado.
Las expansiones %S, %U y %D anteriores están disponibles con Postfix 2.2 y posteriores.
%[1-9]
Los patrones %1, %2, ... %9 se reemplazan por el componente más significativo correspondiente del dominio de la clave de entrada. Si la clave de entrada es usuario@correo.ejemplo.com, entonces %1 es com, %2 es ejemplo y %3 es correo. Si la clave de entrada no está cualificada o no tiene suficientes componentes de dominio para satisfacer todos los patrones especificados, la búsqueda se suprime y no devuelve resultados.
Las expansiones %1, ..., %9 anteriores están disponibles con Postfix 2.2 y posteriores.
El parámetro "domain" descrito más abajo limita las claves de entrada a las direcciones en dominios coincidentes. Cuando el parámetro "domain" no está vacío, las consultas LDAP para direcciones no cualificadas o direcciones en dominios no coincidentes se suprimen y no devuelven resultados.

NOTA: NO pongas comillas alrededor de la

b>filtro_consulta parámetro.

formato_resultado (por defecto: %s)
Llamado filtro_resultado en las versiones de Postfix anteriores a la 2.2. Plantilla de formato aplicada a los atributos de resultado. Se usa más comúnmente para añadir (o anteponer) texto al resultado. Este parámetro admite las siguientes expansiones de '%':
%%
Se reemplaza por un carácter '%' literal. (Postfix 2.2 y posterior).
%s
Se reemplaza por el valor del atributo de resultado. Cuando el resultado está vacío, se omite.
%u
Cuando el valor del atributo de resultado es una dirección del tipo usuario@dominio, %u se reemplaza por la parte local de la dirección. Cuando la parte local del resultado está vacía, se omite.
%d
Cuando el valor de un atributo de resultado es una dirección del tipo usuario@dominio, %d se reemplaza por la parte del dominio del valor del atributo. Cuando el resultado no está cualificado, se omite.
%[SUD1-9]
Las expansiones de letras mayúsculas y dígitos decimales interpolan las partes de la clave de entrada en lugar del resultado. Su comportamiento es idéntico al descrito con filtro_consulta, y de hecho, dado que la clave de entrada se conoce de antemano, las búsquedas cuya clave no contenga toda la información especificada en la plantilla de resultado se suprimen y no devuelven ningún resultado.
Las expansiones %S, %U, %D y %1, ..., %9 anteriores están disponibles con Postfix 2.2 y posterior.
Por ejemplo, usar "formato_resultado = smtp:[%s]" permite utilizar un atributo mailHost como base de una tabla transport(5). Después de aplicar el formato de resultado, los valores múltiples se concatenan como cadenas separadas por comas. Los parámetros expansion_limit y size_limit explicados a continuación permiten restringir el número de valores en el resultado, lo que es especialmente útil para mapas que deberían devolver un único valor.

El valor por defecto %s especifica que cada valor de atributo debe usarse tal cual.

Este parámetro se llamaba filtro_resultado en las versiones de Postfix anteriores a la 2.2. Si no se especifica ningún "formato_resultado", se utilizará el valor de "filtro_resultado" en su lugar antes de recurrir al valor por defecto. Esto proporciona compatibilidad con archivos de configuración antiguos.

NOTA: ¡NO ponga comillas alrededor del formato de resultado!

dominio (por defecto: sin lista de dominios)
Esta es una lista de nombres de dominio, rutas a archivos o bases de datos de "tipo:tabla". Cuando se especifica, solo las claves de búsqueda completamente cualificadas con una parte local *no vacía* y un dominio coincidente son elegibles para la búsqueda: las búsquedas de 'usuario', las búsquedas de dominio desnudo y las búsquedas "@dominio" no se realizan. Esto puede reducir significativamente la carga de consulta en el servidor LDAP. 
    dominio = postfix.org, hash:/etc/postfix/searchdomains

Es mejor no utilizar LDAP para almacenar los dominios elegibles para búsquedas LDAP.

NOTA: ¡NO defina este parámetro para alias locales(8)!

Esta característica está disponible en Postfix 1.0 y posterior.

atributo_resultado (por defecto: maildrop)
El/los atributo(s) que Postfix leerá de cualquier entrada de directorio devuelta por la búsqueda, para resolverla a una dirección de correo electrónico. 
    atributo_resultado = mailbox, maildrop

No confíe en el valor por defecto ("maildrop"). Establezca explícitamente el atributo_resultado en todos los archivos de configuración de tablas ldap. Esto es particularmente relevante cuando no hay un atributo_resultado aplicable, por ejemplo, en casos en los que se utilizan leaf_result_attribute y/o terminal_result_attribute en su lugar. El valor por defecto es inofensivo si "maildrop" también se enumera como un atributo de resultado hoja o terminal, pero es mejor no dejar esto al azar.

atributo_resultado_especial (por defecto: vacío)
El/los atributo(s) de las entradas de directorio que pueden contener DNs o URLs LDAP RFC 2255. Si se encuentran, se realiza una búsqueda recursiva para recuperar la entrada referenciada por el DN, o las entradas que coinciden con la consulta de la URL. 
    atributo_resultado_especial = memberdn

La recursión de DN recupera los mismos atributos de resultado que la consulta principal, incluidos los atributos especiales para una mayor recursión.

El procesamiento de URL recupera solo aquellos atributos que están incluidos tanto en la definición de la URL como en los atributos de resultado (ordinarios, especiales, hoja o terminal) en la definición de la tabla Postfix. Si la URL enumera alguno de los atributos de resultado especiales de la tabla, estos se recuperan y se utilizan de forma recursiva. Una URL que no especifica ninguna selección de atributos, es equivalente (RFC 2255) a una URL que selecciona todos los atributos, en cuyo caso los atributos seleccionados serán el conjunto completo de atributos de resultado en la tabla Postfix.

Si un descriptor de atributo de URL LDAP o el atributo de resultado de tabla LDAP de Postfix correspondiente (pero no ambos) utiliza opciones de subtipo RFC 2255 ("attr;option"), el atributo solicitado al servidor LDAP incluirá la opción de subtipo. En todos los demás casos, la URL del atributo y el atributo de la tabla deben coincidir exactamente. Los atributos con opciones tanto en la URL como en la tabla Postfix se solicitan solo cuando las opciones son idénticas. Las opciones de descriptor de atributo LDAP se utilizan muy raramente, la mayoría de los usuarios de LDAP no necesitarán preocuparse por este nivel de detalle matizado.

atributo_resultado_terminal (por defecto: vacío)
Cuando se encuentran uno o más atributos de resultado terminal en una entrada LDAP, todos los demás atributos de resultado se ignoran y solo se devuelven los atributos de resultado terminal. Esto es útil para delegar la expansión de miembros de grupos a un host particular, utilizando un atributo opcional "maildrop" en grupos seleccionados para dirigir el grupo a un host específico, donde el grupo se expande, posiblemente a través de un gestor de listas de correo u otro procesamiento especial. 
    atributo_resultado =
    atributo_resultado_terminal = maildrop

Al utilizar atributos de resultado terminales y/o hoja, es mejor establecer el atributo_resultado a un valor vacío cuando no se utiliza, o establecerlo explícitamente al valor deseado, incluso si es el valor por defecto "maildrop".

Esta característica está disponible con Postfix 2.4 o posterior.

atributo_resultado_hoja (por defecto: vacío)
Cuando se encuentran uno o más atributos de resultado especiales en una entrada LDAP no terminal (ver arriba), los atributos de resultado hoja se excluyen de la expansión de esa entrada. Esto es útil al expandir grupos y los atributos de dirección de correo electrónico deseados de los objetos miembro obtenidos a través de la recursión DN o URI también están presentes en el objeto del grupo. Para devolver solo los valores de atributo de los objetos hoja y no del grupo contenedor, agregue el atributo a la lista leaf_result_attribute, y no a la lista result_attribute, que siempre se expande. Tenga en cuenta que el valor por defecto de "atributo_resultado" no está vacío; es posible que desee establecerlo explícitamente vacío cuando utilice "atributo_resultado_hoja" para expandir el grupo a una lista de direcciones DN de miembros. Si los grupos tienen referencias a DN de miembros Y atributos que contienen direcciones rfc822 de múltiples valores, entonces los atributos de cadena van en "atributo_resultado". Los atributos que representan las direcciones de correo electrónico de los objetos referenciados a través de un DN (o URI LDAP) van en "atributo_resultado_hoja". 
    atributo_resultado = memberaddr
    atributo_resultado_especial = memberdn
    atributo_resultado_terminal = maildrop
    atributo_resultado_hoja = mail

Al utilizar atributos de resultado terminales y/o hoja, es mejor establecer el atributo_resultado a un valor vacío cuando no se utiliza, o establecerlo explícitamente al valor deseado, incluso si es el valor por defecto "maildrop".

Esta característica está disponible con Postfix 2.4 o posterior.

ambito (por defecto: sub)
El ámbito de búsqueda LDAP: sub, base o one. Estos se traducen en LDAP_SCOPE_SUBTREE, LDAP_SCOPE_BASE y LDAP_SCOPE_ONELEVEL.
enlazar (por defecto: sí)
Si enlazar al servidor LDAP y cómo hacerlo. Las implementaciones LDAP más nuevas no requieren que los clientes enlacen, lo que ahorra tiempo. Ejemplo: 
    # No enlazar
    enlazar = no
    # Usar enlace SIMPLE
    enlazar = sí
    # Usar enlace SASL
    enlazar = sasl

Las versiones de Postfix anteriores a la 2.8 solo admiten "enlazar = no", lo que significa no enlazar, y "enlazar = sí", lo que significa realizar un enlace SIMPLE. Postfix 2.8 y posteriores también admiten "enlazar = SASL" cuando se compila con soporte SASL LDAP como se describe en LDAP_README, también añade los sinónimos "enlazar = none" y "enlazar = simple" para "enlazar = no" y "enlazar = sí" respectivamente. Consulte la sección SASL a continuación para ver parámetros adicionales disponibles con "enlazar = sasl".

Si necesita enlazar, puede considerar configurar Postfix para conectarse a la máquina local en un puerto que sea un túnel SSL a su servidor LDAP. Si su servidor LDAP no admite SSL de forma nativa, coloque también un túnel (wrapper, proxy, como quiera llamarlo) en ese sistema. Esto debería evitar que la contraseña atraviese la red en texto plano.

dn_enlazar (por defecto: vacío)
Si tiene que enlazar, hágalo con este nombre distinguido. Ejemplo: 
    dn_enlazar = uid=postfix, dc=your, dc=com
Con "enlazar = sasl" (ver arriba), el DN puede ser opcional para algunos mecanismos SASL, no especifique un DN si no es necesario.
pw_enlazar (por defecto: vacío)
La contraseña para el nombre distinguido anterior. Si tiene que usar esto, probablemente querrá hacer que el archivo de configuración del mapa solo sea legible por el usuario de Postfix. Al usar la sintaxis obsoleta ldap:ldapsource, con parámetros de mapa en main.cf, no es posible almacenar de forma segura la contraseña de enlace. Esto se debe a que main.cf debe ser legible por todos para permitir que las cuentas locales envíen correo a través del comando sendmail. Ejemplo: 
    pw_enlazar = postfixpw
Con "enlazar = sasl" (ver arriba), la contraseña puede ser opcional para algunos mecanismos SASL, no especifique una contraseña si no es necesaria.
cache (IGNORADO con una advertencia)
cache_expiry (IGNORADO con advertencia)
cache_size (IGNORADO con advertencia)
Los parámetros anteriores YA NO SON SOPORTADOS por Postfix. El soporte de caché se ha eliminado de OpenLDAP a partir de la versión 2.1.13.
recursion_limit (por defecto: 1000)
Un límite en la profundidad de anidación de la evaluación especial de atributos de resultado DN y URL. El límite debe ser un número entero positivo no nulo.
expansion_limit (por defecto: 0)
Un límite en el número total de elementos de resultado devueltos (como una lista separada por comas) por una búsqueda en el mapa. Un valor de cero deshabilita el límite. Las búsquedas fallan con un error temporal si se supera el límite. Establecer el límite a 1 asegura que las búsquedas no devuelvan múltiples valores.
size_limit (por defecto: $expansion_limit)
Un límite en el número de entradas LDAP devueltas por una única búsqueda LDAP realizada como parte de la búsqueda. Un valor de 0 deshabilita el límite. La expansión de referencias DN y URL implica consultas LDAP anidadas, cada una de las cuales está sujeta por separado a este límite.

Nota: incluso una sola entrada LDAP puede generar múltiples resultados de búsqueda, a través de múltiples atributos de resultado y/o atributos de resultado multivalor. Este límite limita la utilización de recursos por búsqueda en el servidor LDAP, no la multiplicidad final del resultado de la búsqueda. Es análogo a la opción "-z" de "ldapsearch".

dereference (por defecto: 0)
Cuándo seguir las alias de LDAP. (Nota: esto no tiene nada que ver con las alias de Postfix.) Los valores permitidos son los legales para las implementaciones LDAP de OpenLDAP/UM:
0
nunca
1
al buscar
2
al localizar el objeto base para la búsqueda
3
siempre
Consulte ldap.h o las páginas man de ldap_open(3) o ldapsearch(1) para más información. Y si está utilizando un paquete LDAP que tenga otros valores posibles, por favor, llévelo a la atención de la lista de correo postfix-users@postfix.org.
chase_referrals (por defecto: 0)
Establece (o borra) LDAP_OPT_REFERRALS (requiere soporte de LDAP versión 3).
version (por defecto: 2)
Especifica la versión del protocolo LDAP a utilizar.
debuglevel (por defecto: 0)
Nivel a establecer para la depuración en las bibliotecas de OpenLDAP.

PARÁMETROS LDAP SASL

Si está utilizando las bibliotecas de OpenLDAP compiladas con soporte SASL, Postfix 2.8 y posteriores compilados con soporte SASL LDAP según se describe en LDAP_README pueden autenticarse en servidores LDAP a través de SASL.

Esto permite la autenticación en el servidor LDAP a través de mecanismos distintos de una contraseña simple. La flexibilidad añadida tiene un coste: ya no es práctico establecer un tiempo de espera explícito en la duración de una operación de enlace LDAP. Bajo condiciones adversas, si un enlace SASL caduca, o si lo hace, la duración del tiempo de espera está determinada por las bibliotecas LDAP y SASL.

Es mejor utilizar tablas que utilicen enlaces SASL a través de proxymap(8), de esta manera el proceso solicitante puede establecer un tiempo de espera para la solicitud de proxymap. Esto también le permite ajustar el entorno del proceso anulando la configuración de import_environment de proxymap(8) en master.cf(5). Pueden ser necesarios ajustes de entorno especiales para configurar cachés de credenciales GSSAPI u otras opciones específicas del mecanismo SASL. Las credenciales GSSAPI utilizadas para las búsquedas LDAP pueden necesitar ser diferentes a, por ejemplo, las utilizadas por el cliente SMTP de Postfix para autenticarse en servidores remotos.

El uso de mecanismos SASL requiere la versión 3 del protocolo LDAP, la versión de protocolo por defecto es la 2 para compatibilidad retroactiva. Debe establecer "version = 3" además de "bind = sasl".

Los siguientes parámetros son relevantes para usar LDAP con SASL

sasl_mechs (por defecto: vacío)
Lista de mecanismos SASL separados por espacios a intentar.
sasl_realm (por defecto: vacío)
Dominio SASL a utilizar, si es aplicable.
sasl_authz_id (por defecto: vacío)
La identidad de autorización SASL a afirmar, si es aplicable.
sasl_minssf (por defecto: 0)
El factor de seguridad sasl mínimo requerido para establecer una conexión.

PARÁMETROS LDAP SSL Y STARTTLS

Si está utilizando las bibliotecas de OpenLDAP compiladas con soporte SSL, Postfix puede conectarse a servidores LDAP SSL y puede emitir el comando STARTTLS.

Se puede solicitar el servicio LDAP SSL utilizando una URL LDAP SSL en el parámetro server_host:

    server_host = ldaps://ldap.example.com:636

STARTTLS se puede activar con el parámetro start_tls:

    start_tls = yes

Ambas formas requieren la versión 3 del protocolo LDAP, que debe ser establecida explícitamente con:

    version = 3

Si alguno de los programas de Postfix que consultan el mapa está configurado en master.cf para ejecutarse en chroot, todos los certificados y claves involucradas deben copiarse a la cárcel chroot. Por supuesto, las claves privadas solo deben ser legibles por el usuario "postfix".

Los siguientes parámetros son relevantes para LDAP SSL y STARTTLS:

start_tls (por defecto: no)
Si se debe emitir o no STARTTLS al conectarse al servidor. No establezca esto con LDAP SSL (la sesión SSL se configura automáticamente cuando se abre la conexión TCP).
tls_ca_cert_dir (Sin valor por defecto; establezca este o tls_ca_cert_file)
Directorio que contiene certificados de Autoridad de Certificación X509 en formato PEM que deben ser reconocidos por el cliente en conexiones SSL/TLS. Los archivos contienen cada uno un certificado de CA. Los archivos se buscan por el valor hash del nombre del sujeto de la CA, que por lo tanto debe estar disponible. Si existen varios certificados de CA con el mismo valor hash de nombre, la extensión debe ser diferente (por ejemplo, 9d66eef0.0, 9d66eef0.1, etc.). La búsqueda se realiza en el orden del número de extensión, independientemente de otras propiedades de los certificados. Utilice la utilidad c_rehash (de la distribución OpenSSL) para crear los enlaces necesarios.
tls_ca_cert_file (Sin valor por defecto; establezca este o tls_ca_cert_dir)
Archivo que contiene los certificados de Autoridad de Certificación X509 en formato PEM que deben ser reconocidos por el cliente en conexiones SSL/TLS. Esta configuración tiene prioridad sobre tls_ca_cert_dir.
tls_cert (Sin valor por defecto; debe establecerlo)
Archivo que contiene el certificado X509 del cliente a ser utilizado por el cliente en conexiones SSL/TLS.
tls_key (Sin valor por defecto; debe establecerlo)
Archivo que contiene la clave privada correspondiente al tls_cert anterior.
tls_require_cert (por defecto: no)
Si se debe solicitar o no el certificado X509 del servidor y verificar su validez al establecer conexiones SSL/TLS. Los valores soportados son no y sí.

Con no, la cadena de confianza del certificado del servidor no se verifica, pero con OpenLDAP anterior a 2.1.13, el nombre en el certificado del servidor aún debe coincidir con el nombre del servidor LDAP. Con OpenLDAP 2.0.0 a 2.0.11 el nombre del servidor no es necesariamente lo que especificó, sino que se determina (por búsqueda inversa) a partir de la dirección IP de la conexión del servidor LDAP. Con OpenLDAP anterior a 2.0.13, las extensiones subjectAlternativeName en el certificado del servidor LDAP se ignoran: el nombre del servidor debe coincidir con el CommonName del sujeto. La configuración no corresponde al valor never de TLS_REQCERT en los archivos de configuración del cliente LDAP.

No utilice TLS con OpenLDAP 2.0.x (y especialmente con x <= 11) si puede evitarlo.

Con sí, el certificado del servidor debe haber sido emitido por una CA de confianza y no estar caducado. El nombre del servidor LDAP debe coincidir con uno de los nombres encontrados en el certificado (ver arriba para el comportamiento dependiente de la versión de la biblioteca OpenLDAP). La configuración sí corresponde al valor demand de TLS_REQCERT en los archivos de configuración del cliente LDAP.

Los valores "try" y "allow" de TLS_REQCERT no tienen equivalentes aquí. No están disponibles con OpenLDAP 2.0 y, en cualquier caso, tienen propiedades de seguridad cuestionables. O quiere conexiones LDAP verificadas con TLS, o no las quiere.

El valor "yes" solo funciona correctamente con Postfix 2.5 y posteriores, o con OpenLDAP 2.0. Versiones anteriores de Postfix o versiones posteriores de OpenLDAP no funcionan juntas con esta configuración. El soporte para LDAP sobre TLS se añadió a Postfix basándose en la API OpenLDAP 2.0.

tls_random_file (Sin valor por defecto)
Ruta de un archivo para obtener bits aleatorios cuando /dev/[u]random no está disponible, a ser utilizados por el cliente en conexiones SSL/TLS.
tls_cipher_suite (Sin valor por defecto)
Conjunto de cifrado a utilizar en las negociaciones SSL/TLS.

EJEMPLO

Aquí hay un ejemplo básico para usar LDAP para buscar alias locales(8). Supongamos que en main.cf, tiene:

    alias_maps = hash:/etc/aliases,
            ldap:/etc/postfix/ldap-aliases.cf

y en ldap:/etc/postfix/ldap-aliases.cf tiene:

    server_host = ldap.example.com
    search_base = dc=example, dc=com

Al recibir correo para una dirección local "ldapuser" que no se encuentra en la base de datos /etc/aliases, Postfix buscará en el servidor LDAP que escucha en el puerto 389 en ldap.example.com. Se enlazará anónimamente, buscará cualquier entrada de directorio

NOMBRE

ldap_table - Postfix LDAP lookup table client

SINOPSIS

/etc/postfix/ldap-users.cf

ldap:/etc/postfix/ldap-users.cf

DESCRIPCIÓN

El cliente LDAP de Postfix permite a Postfix consultar tablas de búsqueda almacenadas en un servidor LDAP.

Los archivos de configuración de cliente LDAP de Postfix son archivos de texto plano que especifican los parámetros necesarios para conectarse a un servidor LDAP.

La configuración de la tabla de búsqueda LDAP se realiza especificando un nombre de archivo de configuración para la directiva de tabla de búsqueda en Postfix, como se muestra en la sinopsis.

El cliente LDAP de Postfix soporta los siguientes tipos de tablas de búsqueda:

hash:, btree:, nis:, nisplus:, dbm:, sdbm:, cdb:, regexp:, pcre:, texthash:, socket:, tcp:
Estos son tipos de tabla de búsqueda estándar de Postfix y no son relevantes para el cliente LDAP.
ldap:
Este es el tipo de tabla de búsqueda para el cliente LDAP. El argumento que sigue a ldap: es el nombre de un archivo de configuración de cliente LDAP.

MEMBRESÍA DE LISTA

Este cliente LDAP soporta la búsqueda de membresía de listas RFC 822. Especifique el dominio de la lista (por ejemplo,example.com) como el valor de búsqueda. El cliente LDAP consultará el servidor LDAP para encontrar entradas de usuario cuyos atributosmailacceptinggeneralid (o un atributo configurado similarmente) coincidan con el nombre de la lista de correo. Luego, para esas entradas de usuario encontradas, leerá los atributosmaildrop (o un atributo configurado similarmente) y construirá una lista de susmaildrop, que se tratarán como direcciones RFC822 a las que se entregará el mensaje.

PARÁMETROS GENERALES LDAP

Los siguientes parámetros son utilizados por el cliente LDAP de Postfix para configurar la conexión al servidor LDAP y las búsquedas.

server_host ($tilde)
El nombre de host o la dirección IP del servidor LDAP. Se pueden especificar varios hosts separados por comas. Si el nombre de host comienza con/, se trata como un socket de dominio Unix.
server_port (389)
El número de puerto del servidor LDAP. El valor predeterminado es 389.
search_base (No predeterminado)
El DN base para las búsquedas LDAP. Este es un parámetro obligatorio.
search_filter (No predeterminado)
La plantilla de filtro de búsqueda LDAP. El nombre de host o la dirección de correo electrónico se sustituirá en esta plantilla. Por ejemplo:(mail=%s) o (uid=%s). Este es un parámetro obligatorio.
search_scope (sub)
El alcance de la búsqueda. Los valores posibles sonbase,one osub.
domain (No predeterminado)
Un nombre de dominio para añadir a los nombres de host que no tienen un componente de dominio.
size_limit (0)
El número máximo de entradas a devolver en una búsqueda. Un valor de0 significa sin límite.
time_limit (60)
El tiempo máximo en segundos permitido para una búsqueda LDAP. Un valor de0 significa sin límite.
connect_timeout (10)
El tiempo máximo en segundos permitido para establecer una conexión LDAP. Un valor de0 significa sin límite.
read_timeout (60)
El tiempo máximo en segundos permitido para leer una respuesta LDAP. Un valor de0 significa sin límite.
bind_dn (No predeterminado)
El DN utilizado para enlazar con el servidor LDAP. Si no se especifica, se realizará un enlace anónimo.
bind_pw (No predeterminado)
La contraseña utilizada para enlazar con el servidor LDAP. Si no se especifica, se realizará un enlace anónimo.
sasl_mech (No predeterminado)
El mecanismo SASL a utilizar para la autenticación. Si no se especifica, no se utilizará SASL.
sasl_realm (No predeterminado)
El reino SASL a utilizar para la autenticación.
sasl_auth_enable (yes)
Habilitar la autenticación SASL. Si se establece enno, la autenticación SASL se deshabilitará.
tls_reqcert (hard)
Especifica si se debe solicitar un certificado del servidor LDAP y cómo se debe verificar. Los valores posibles son:never,allow,try,demand,hard.
tls_cert_file (No predeterminado)
El archivo que contiene el certificado de cliente para la autenticación mutua TLS.
tls_key_file (No predeterminado)
El archivo que contiene la clave privada para la autenticación mutua TLS.
tls_cacert_file (No predeterminado)
El archivo que contiene los certificados CA para verificar el certificado del servidor LDAP.
tls_cacert_dir (No predeterminado)
El directorio que contiene los certificados CA para verificar el certificado del servidor LDAP.
tls_random_file (No predeterminado)
El archivo que contiene datos aleatorios para la inicialización de TLS.
tls_session_cache_database (No predeterminado)
El archivo de base de datos para el almacenamiento en caché de sesiones TLS.
result_format (No predeterminado)
Una cadena de formato para procesar los resultados de la búsqueda LDAP. El nombre de atributo se sustituirá en esta cadena. Por ejemplo:%u@%d. Este parámetro solo se utiliza cuando se busca información de dirección de correo electrónico.
result_filter (No predeterminado)
Para compatibilidad con versiones anteriores de clientes LDAP anteriores a la versión 2.2, result_filter se puede usar en lugar deresult_format, cuando este último parámetro tampoco se establece. El nuevo nombre refleja mejor la función del parámetro. Esta interfaz de compatibilidad puede eliminarse en una versión futura.
alias_maps (No predeterminado)
Una lista de mapas de alias para consultar para resolver alias de correo electrónico.
alias_member_limit (50)
El número máximo de miembros que se pueden devolver para una expansión de alias.
map_type (ldap)
El tipo de mapa a utilizar. Esto se establece automáticamente enldap cuando se utiliza el prefijoldap:.

Los siguientes parámetros se utilizan para configurar la autenticación SASL con el servidor LDAP.

sasl_mech_filter (No predeterminado)
Un filtro para seleccionar los mecanismos SASL disponibles.
sasl_min_layer (No predeterminado)
La capa mínima de seguridad SASL requerida.
sasl_max_layer (No predeterminado)
La capa máxima de seguridad SASL permitida.

Propiedades de seguridad SASL para negociar.

Los siguientes parámetros se utilizan para configurar el uso de SSL/TLS con el servidor LDAP.

tls_use_wrapper (no)
Usar el envoltorio openssl para la conexión TLS.

EJEMPLO

A continuación, se muestra un ejemplo de archivo de configuración de cliente LDAP:

# /etc/postfix/ldap-users.cf
server_host = ldap.example.com
search_base = ou=users,dc=example,dc=com
search_filter = (mail=%s)
result_format = %u@%d

Este archivo de configuración especificaría la consulta LDAP que se realizaría. Cuando un usuario envía un correo electrónico auser@example.com, el cliente LDAP de Postfix buscaría una entrada en el servidor LDAPldap.example.com con el filtro(mail=user@example.com). Si se encuentra una entrada, el camporesult_format se aplicaría al resultado. En este ejemplo, si la entrada LDAP tuviera un campomail deuser@example.com, el resultado seríauser@example.com.

Para buscar el atributomaildrop y construir una lista de destinatarios para la membresía de lista, el archivo de configuración se vería así:

# /etc/postfix/ldap-groups.cf
server_host = ldap.example.com
search_base = ou=groups,dc=example,dc=com
search_filter = (cn=%s)
result_format = %{maildrop}
maildrop_attribute = maildrop

Cuando un usuario envía un correo electrónico a una lista de correo definida en el LDAP (por ejemplo,mailinglist@example.com), el cliente LDAP de Postfix buscaría una entrada en el servidor LDAPldap.example.com con el filtro (cn=mailinglist@example.com). Si se encuentra una entrada, el atributo maildrop de esa entrada se leería y se trataría como una dirección RFC822 a la que se entregará el mensaje.

PARÁMETROS OBSOLETOS DE MAIN.CF

Para compatibilidad con versiones anteriores de Postfix 2.0 y anteriores, los parámetros LDAP también se pueden definir enmain.cf. Especifique como fuente LDAP un nombre que no comience con una barra o un punto. Los parámetros LDAP serán entonces accesibles como el nombre que le ha dado a la fuente en su definición, un guión bajo y el nombre del parámetro. Por ejemplo, si el mapa se especifica como"ldap:ldapsource", el parámetro "server_host" a continuación se definiría enmain.cf como"ldapsource_server_host".

Nota: con esta forma, las contraseñas para las fuentes LDAP se escriben enmain.cf, que normalmente es legible por todos. El soporte para esta forma se eliminará en una futura versión de Postfix.

OTRAS CARACTERÍSTICAS OBSOLETAS

Para compatibilidad con versiones anteriores de clientes LDAP anteriores a la versión 2.2, result_filter se puede usar en lugar deresult_format, cuando este último parámetro tampoco se establece. El nuevo nombre refleja mejor la función del parámetro. Esta interfaz de compatibilidad puede eliminarse en una versión futura.
