lcov(1) Manuales de usuario lcov(1)

NOMBRE

lcov - una interfaz gráfica para GCOV

SINOPSIS

Captura el archivo de trazado de datos de cobertura (de datos generados por el compilador).
El formato del archivo de trazado de lcov (archivo ".info") se describe en el manual de geninfo(1).

lcov -c|--capture

[-d|--directory directorio] [-k|--kernel-directory directorio]
[-o|--output-file archivo_de_trazado] [-t|--test-name nombre_de_prueba]
[-b|--base-directory directorio]
[--build-directory directorio]
[--source-directory directorio]
[-i|--initial]
[--all]]
[--gcov-tool herramienta]
[--branch-coverage]
[--mcdc-coverage]
[--demangle-cpp [parametro]]
[--checksum] [--no-checksum] [--no-recursion] [-f|--follow]
[--sort-input]
[--compat-libtool] [--no-compat-libtool]
[--msg-log [nombre_archivo_log]]
[--ignore-errors errores]
[--expect-message-count tipo_mensaje=expresion[,tipo_mensaje=expresion..]]
[--preserve] [--to-package paquete] [--from-package paquete] [--no-markers] [--external] [--no-external]
[--compat modo=on|off|auto]
[--context-script archivo_script]
[--criteria-script archivo_script]
[--resolve--script archivo_script]
[--version-script archivo_script]
[--comment cadena_comentario]
[--large-file expresion_regular]

Genera un archivo de trazado (de datos generados por el compilador) con todos los valores de contador establecidos a cero:

lcov -z|--zerocounters

[-d|--directory directorio] [--no-recursion] [-f|--follow]

Muestra los recuentos de cobertura registrados en un archivo de trazado generado previamente:

lcov -l|--list archivo_de_trazado

[--list-full-path] [--no-list-full-path]

Agrega múltiples archivos de trazado de cobertura en uno:

lcov -a|--add-tracefile patron_archivo_trazado

[-o|--output-file archivo_de_trazado]
[--prune-tests]
[--forget-test-names]
[--map-functions]
[--branch-coverage]
[--mcdc-coverage]
[--checksum] [--no-checksum]
[--sort-input]

Dependiendo de su modelo de uso, puede que no sea necesario crear archivos de datos de cobertura agregados. Por ejemplo, si sus pruebas de regresión se dividen en múltiples conjuntos, es posible que desee conservar datos de conjunto separados y comparar los resultados por conjunto y agregados con el tiempo. genhtml le permite especificar archivos de trazado a través de uno o más patrones glob, lo que permite generar informes agregados sin generar explícitamente archivos de trazado agregados. Consulte el manual de genhtml.

Genera un nuevo archivo de trazado a partir de un archivo de trazado existente, conservando solo los datos de los archivos que coinciden con el patrón:

lcov -e|--extract archivo_de_trazado patron

[-o|--output-file archivo_de_trazado] [--checksum] [--no-checksum]

Genera un nuevo archivo de trazado a partir de un archivo de trazado existente, eliminando datos de archivos que coinciden con el patrón:

lcov -r|--remove archivo_de_trazado patron

[-o|--output-file archivo_de_trazado] [--checksum] [--no-checksum]

Genera un nuevo archivo de trazado a partir de archivos de trazado existentes realizando operaciones de conjunto en los datos de cobertura:

lcov --intersect patron_glob_derecha

[-o|--output-file archivo_de_trazado]
patron_glob_izquierda

La salida reflejará

(unión de archivos que coinciden con los patrones_glob_izquierdos) intersecto (unión de archivos que coinciden con los patrones_glob_derechos)
de tal manera que los puntos de cobertura encontrados en ambos conjuntos se fusionan (suman), mientras que los puntos de cobertura que se encuentran solo en un conjunto se descartan. Tenga en cuenta que los bloques de rama se definen como idénticos si y solo si su ID de bloque y la lista de expresiones de rama asociada son idénticos. Las funciones se definen como idénticas si su nombre y ubicación son idénticos.
lcov --subtract patron_glob_derecha

[-o|--output-file archivo_de_trazado]
patron_glob_izquierda

La salida reflejará

(unión de archivos que coinciden con los patrones_glob_izquierdos) resta (unión de archivos que coinciden con los patrones_glob_derechos)
de tal manera que se conservarán los puntos de cobertura que se encuentran solo en el conjunto de la izquierda y todos los demás se descartarán.

Resume el contenido del archivo de trazado:

lcov --summary archivo_de_trazado

Imprime el mensaje de versión o ayuda y sale:

lcov [-h|--help] [--version]

Opciones comunes de lcov, compatibles con todos los casos de uso anteriores:

lcov [--keep-going]
[--filter tipo]
[-q|--quiet]
[-v|--verbose]
[--comment cadena_comentario]
[--debug]
[--parallel|-j [entero]]
[--memory num_entero_Mb]
[--tempdir nombre_directorio]
[--branch-coverage]
[--mcdc-coverage]
[--config-file archivo_config] [--rc palabra_clave=valor]
[--profile [archivo_perfil]]
[--include patron_glob]
[--exclude patron_glob]
[--erase-functions patron_expresion_regular]
[--substitute patron_expresion_regular]
[--omit-lines patron_expresion_regular]
[--fail-under-branches porcentaje]
[--fail-under-lines porcentaje]

DESCRIPCIÓN

lcov es una interfaz gráfica para la herramienta de pruebas de cobertura gcov de GCC. Recopila datos de cobertura de línea, función y rama para múltiples archivos fuente y crea páginas HTML que contienen el código fuente anotado con información de cobertura. También agrega páginas de resumen para facilitar la navegación dentro de la estructura de archivos.

Utilice lcov para recopilar datos de cobertura y genhtml para crear páginas HTML. Los datos de cobertura se pueden recopilar del kernel de Linux en ejecución actual o de una aplicación en espacio de usuario. Para hacerlo, debe completar los siguientes pasos de preparación:

Para la cobertura del kernel de Linux:

Siga las instrucciones de configuración para la infraestructura gcov-kernel: https://docs.kernel.org/dev-tools/gcov.html

Para la cobertura de aplicaciones en espacio de usuario:

Compile la aplicación con GCC utilizando las opciones "-fprofile-arcs" y "-ftest-coverage" o "--coverage".

Tenga en cuenta que esta página del manual se refiere al formato de salida de lcov como "archivo .info" o "archivo de trazado" y que la salida de GCOV se llama "archivo .da".

También tenga en cuenta que al imprimir porcentajes, 0% y 100% solo se imprimen cuando los valores son exactamente 0% y 100% respectivamente. Otros valores que convencionalmente se redondearían a 0% o 100% se imprimen como el valor no límite más cercano. Este comportamiento está de acuerdo con el de la herramienta gcov(1).

Por defecto, lcov y las herramientas relacionadas generan y recopilan datos de cobertura de línea y función. Los datos de rama no se recopilan ni se muestran por defecto; todas las herramientas admiten las opciones --branch-coverage y --mdcd-coverage para habilitar la cobertura de rama y MC/DC, respectivamente, o puede habilitar permanentemente la cobertura de rama agregando la configuración apropiada a su archivo de configuración personal, de grupo o de sitio de lcov. Consulte el manual de lcovrc(5) para obtener detalles.

OPCIONES

En general, (casi) todas las opciones de lcov también se pueden especificar en un archivo de configuración; consulte el manual de lcovrc(5) para obtener detalles.

-a patron_archivo_trazado
--add-tracefile patron_archivo_trazado

Agrega el contenido de todos los archivos que coinciden con el patrón glob
tracefile_pattern.

Especifique varios archivos de rastreo con el modificador -a para combinar los datos de cobertura contenidos en estos archivos sumando los recuentos de ejecución para combinaciones de pruebas y nombres de archivo coincidentes.

El resultado de la operación de suma se escribirá en stdout o en el archivo de rastreo especificado con -o.

Solo se puede especificar uno de los modificadores -z, -c, -a, -e, -r, -l o --summary a la vez.

-b directorio
--base-directory directorio

Utilice directorio como directorio base para rutas relativas.

Utilice esta opción para especificar el directorio base de un entorno de compilación cuando lcov produce mensajes de error como:

ERROR: no se pudo leer el archivo fuente /home/user/project/subdir1/subdir2/subdir1/subdir2/file.c

En este ejemplo, utilice /home/user/project como directorio base.

Esta opción es necesaria al usar lcov en proyectos compilados con libtool o entornos de compilación similares que funcionan con un directorio base, es decir, entornos en los que el directorio de trabajo actual al invocar el compilador no es el mismo directorio en el que se encuentra el archivo de código fuente.

Tenga en cuenta que esta opción no funcionará en entornos donde se utilizan múltiples directorios base. En ese caso, utilice la configuración del archivo de configuración geninfo_auto_base=1 (consulte man lcovrc(5) ).

--build-directory directorio_compilacion

busque archivos de datos .gcno en directorio_compilacion en lugar de junto al archivo .gcda correspondiente.

Consulte man geninfo(1)) para obtener más detalles.

--source-directory nombre_directorio
Añada 'nombre_directorio' a la lista de lugares donde buscar archivos fuente.

Para rutas de archivos fuente relativas listadas en, por ejemplo, rutas encontradas en tracefile, o encontradas en la salida de gcov durante --capture - posiblemente después de que se hayan aplicado sustituciones - lcov
primero buscará la ruta desde 'cwd' (donde se invocó genhtml) y luego desde cada nombre de directorio alternativo en el orden especificado. La primera ubicación coincidente se utilizará.

Esta opción se puede especificar varias veces, para añadir más directorios a la ruta de búsqueda de fuentes.

-c
--capture
Capturar datos de cobertura en tiempo de ejecución.

Por defecto, captura los recuentos de ejecución del kernel actual y escribe los datos de cobertura resultantes en la salida estándar. Utilice la opción --directory para capturar recuentos para un programa de espacio de usuario.

El resultado de la operación de captura se escribirá en stdout o en el archivo de rastreo especificado con -o.

Cuando se combina con el modificador --all, se extraerán datos de cobertura en tiempo de ejecución y en tiempo de compilación en un solo paso. Consulte la descripción del modificador --initial, más abajo.

Consulte man geninfo(1)) para obtener más detalles sobre el proceso de captura y las opciones y parámetros disponibles.

Solo se puede especificar uno de los modificadores -z, -c, -a, -e, -r, -l, --diff o --summary a la vez.

--branch-coverage


Recopilar y/o retener datos de cobertura de ramas.

Esto es equivalente a usar la opción "--rc branch_coverage=1"; la opción se añadió para que coincidiera mejor con la interfaz de genhml.

--mcdc-coverage


Recopilar y retener datos MC/DC.

Esto es equivalente a usar la opción "--rc mcdc_coverage=1". La cobertura MC/DC es compatible con las versiones de GCC 14.2 y posteriores, o LLVM 18.1 y posteriores.
Consulte llvm2lcov --help para obtener detalles sobre la captura de datos MC/DC en LLVM.

Consulte la sección MC/DC de man genhtml(1) para obtener más detalles

--checksum
--no-checksum

Especifique si se deben generar datos de suma de verificación al escribir archivos de rastreo y/o si se deben verificar las sumas de verificación coincidentes al combinar archivos de rastreo.

Utilice --checksum para habilitar la generación de sumas de verificación o --no-checksum para deshabilitarla. La generación de sumas de verificación está deshabilitada por defecto.

Cuando la generación de sumas de verificación está habilitada, se generará una suma de verificación para cada línea de código fuente y se almacenará junto con los datos de cobertura. Esta suma de verificación se utilizará para evitar intentos de combinar datos de cobertura de diferentes versiones de código fuente.

Si no trabaja con diferentes versiones de código fuente, deshabilite esta opción para acelerar el procesamiento de los datos de cobertura y reducir el tamaño de los archivos de rastreo.

Tenga en cuenta que esta opción está algo subsumida por la opción --version-script, que hace algo similar, pero a nivel de 'archivo completo'.

--compat modo=valor[,modo=valor,...]

Establecer modo de compatibilidad.

Utilice --compat para especificar que lcov debe habilitar uno o más modos de compatibilidad al capturar datos de cobertura. Puede proporcionar una lista separada por comas de pares modo=valor para especificar los valores para varios modos.

Los valores válidos son:

on

Habilitar modo de compatibilidad.
off
Deshabilitar modo de compatibilidad.
auto
Aplicar detección automática para determinar si el modo de compatibilidad es necesario. Tenga en cuenta que la detección automática no está disponible para todos los modos de compatibilidad.

Si no se especifica ningún valor, se asume 'on' como valor predeterminado.

Los modos válidos son:

libtool

Habilite este modo si está capturando datos de cobertura para un proyecto que se compiló utilizando el mecanismo libtool. Consulte también --compat-libtool.

El valor predeterminado para esta configuración es 'on'.

hammer
Habilite este modo si está capturando datos de cobertura para un proyecto que se compiló utilizando una versión de GCC 3.3 que contiene una modificación (parche hammer) de versiones posteriores de GCC. Puede identificar una versión modificada de GCC 3.3 verificando el directorio de compilación de su proyecto en busca de archivos que terminen con la extensión '.bbg'. Las versiones no modificadas de GCC 3.3 nombran estos archivos '.bb'.

El valor predeterminado para esta configuración es 'auto'.

split_crc
Habilite este modo si está capturando datos de cobertura para un proyecto que se compiló utilizando una versión de GCC 4.6 que contiene una modificación (sumas de verificación de funciones divididas) de versiones posteriores de GCC. Los mensajes de error típicos al ejecutar lcov en datos de cobertura producidos por tales versiones de GCC son "falta de memoria" y "fin de archivo inesperado".

El valor predeterminado para esta configuración es 'auto'

--compat-libtool
--no-compat-libtool

Especifique si se debe habilitar el modo de compatibilidad de libtool.

Utilice --compat-libtool para habilitar el modo de compatibilidad de libtool o --no-compat-libtool para deshabilitarlo. El modo de compatibilidad de libtool está habilitado por defecto.

Cuando el modo de compatibilidad de libtool está habilitado, lcov asumirá que el código fuente relacionado con un archivo .da ubicado en un directorio llamado ".libs" se puede encontrar en su directorio padre.

Si tiene directorios llamados ".libs" en su entorno de compilación pero no utiliza libtool, deshabilite esta opción para evitar problemas al capturar datos de cobertura.

--config-file archivo_config

Especifique un archivo de configuración a utilizar. Consulte man lcovrc(5) para obtener detalles sobre el formato del archivo y las opciones. Consulte también la entrada config_file en la misma página man para obtener detalles sobre cómo incluir un archivo de configuración en otro.

Cuando se especifica esta opción, no se leerá ni el archivo de configuración del sistema /etc/lcovrc, ni el archivo de configuración por usuario ~/.lcovrc.

Esta opción puede ser útil cuando hay necesidad de ejecutar varias instancias de lcov con diferentes opciones de archivo de configuración en paralelo.

Tenga en cuenta que esta opción debe especificarse por completo; no se admiten abreviaturas.

--profile [ archivo_datos_perfil ]

Indica a la herramienta que realice un seguimiento del rendimiento y otros datos de configuración. Si no se especifica el archivo_datos_perfil opcional, los datos de perfil se escribirán en un archivo con el mismo nombre base que el --output-filename, con el sufijo .json añadido.

Solo se puede especificar uno de los modificadores -z, -c, -a, -e, -r, -l, --diff o --summary a la vez.

-d directorio
--directory directorio

Utilice archivos .da en directorio en lugar del kernel.

Si desea trabajar con datos de cobertura para un programa de espacio de usuario, utilice esta opción para especificar la ubicación donde se compiló el programa (ahí es donde se almacenarán los archivos de contador que terminan en .da).

Tenga en cuenta que puede especificar esta opción más de una vez.

--exclude patron

Excluir archivos fuente que coincidan con patron.

Utilice este modificador si desea excluir datos de cobertura para un conjunto particular de archivos fuente que coincidan con cualquiera de los patrones dados. Se pueden especificar varios patrones utilizando varios modificadores de línea de comandos --exclude. Los patrones se interpretarán como patrones de comodín de shell (tenga en cuenta que pueden necesitar ser escapados adecuadamente para evitar que el shell los expanda primero).

Nota: El patrón debe especificarse para que coincida con la ruta absoluta de cada archivo fuente. Si especifica un patrón que no parece aplicarse correctamente - los archivos que esperaba que se excluyeran todavía aparecen en la salida - puede buscar mensajes de advertencia en el archivo de registro. lcov emitirá una advertencia por cada patrón que no se aplique al menos una vez.

Se puede combinar con el modificador de línea de comandos --include. Si un archivo dado coincide tanto con el patrón de inclusión como con el patrón de exclusión, el patrón de exclusión tendrá prioridad.

--erase-functions expresión_regular

Excluir datos de cobertura de líneas que caen dentro de una función cuyo nombre coincide con la expresión regular proporcionada. Tenga en cuenta que este es un nombre codificado o decodificado, dependiendo de si se usa o no la opción --demangle-cpp.

Tenga en cuenta que esta opción requiere que utilice una versión de gcc que sea lo suficientemente nueva como para admitir informes de líneas de inicio/fin de función o que configure la herramienta para derivar los datos necesarios; consulte la discusión sobre derive_function_end_line en man lcovrc(5).

--substitute patron_expresion_regular
Aplique la expresión regular de Perl patron_expresion_regular a los nombres de archivos fuente encontrados durante el procesamiento. Esto es útil, por ejemplo, cuando el nombre de la ruta informado por gcov no coincide con la disposición de su fuente y no se encuentra el archivo, o en entornos más complicados donde la estructura del directorio de compilación no coincide con la disposición de la fuente o la disposición en el sistema de control de revisiones del proyecto.

Utilice esta opción en s situaciones en las que geninfo no puede encontrar la ruta correcta a los archivos de código fuente de un proyecto. Al proporcionar un regexp_pattern en formato de expresión regular de Perl (consulte man perlre(1) ), puede indicar a geninfo que elimine o cambie partes de la ruta fuente incorrecta. Consulte también la opción --resolve-script.

Se puede especificar uno o más patrones de --substitution y/o un --resolve-script. Cuando se especifican múltiples patrones, se aplican en el orden especificado, primero los patrones de sustitución seguidos de la función de devolución de llamada de resolución. El orden de búsqueda de archivos es:

1.
Busque el nombre del archivo (sin modificar).
Si el archivo existe: devuélvalo.
2.
Aplique todos los patrones de sustitución en orden: el resultado del primer patrón se utiliza como entrada del segundo patrón, y así sucesivamente.
Si existe un archivo que corresponde al nombre resultante: devuélvalo.
3.
Aplique la función de devolución de llamada 'resolve' al resultado final de las sustituciones de patrones.
Si existe un archivo que corresponde al nombre resultante: devuélvalo.
4.
De lo contrario: devuelva el nombre de archivo original (sin modificar).
Dependiendo del contexto, el nombre de archivo no resuelto puede o no resultar en un error.

Las sustituciones se utilizan en múltiples contextos por lcov/genhtml/geninfo:

  • durante --capture, aplicado a los nombres de archivos fuente encontrados en los archivos de datos de cobertura generados por gcov (consulte man gcov(1) ).
  • durante --capture, aplicado a las rutas alternativas de --build-dir, al buscar el archivo de datos .gcno (tiempo de compilación) correspondiente a algún archivo de datos .gcda (tiempo de ejecución).
  • aplicado a los nombres de archivo encontrados en los archivos de datos de lcov (archivos ".info"): por ejemplo, durante la agregación de datos de lcov o la generación de informes HTML y de texto.
    Por ejemplo, los nombres sustituidos se utilizan para encontrar archivos fuente para el filtrado basado en texto (consulte la sección --filter, a continuación) y se pasan a las funciones de devolución de llamada --version-script, --annotate-script y -criteria-script.
  • aplicado a los nombres de archivo encontrados en el --diff-file pasado a genhtml.

Ejemplo:

1. Cuando geninfo informa que no puede encontrar el archivo fuente


/path/to/src/.libs/file.c

mientras que el archivo se encuentra en realidad en


/path/to/src/file.c

use el siguiente parámetro:


--substitute 's#/.libs##g'

Esto eliminará todas las cadenas de " /.libs" de la ruta.

2. Cuando geninfo informa que no puede encontrar el archivo fuente


/tmp/build/file.c

mientras que el archivo se encuentra en realidad en


/usr/src/file.c

use el siguiente parámetro:


--substitute 's#/tmp/build#/usr/src#g'

Esto cambiará todas las cadenas "/tmp/build" en la ruta por "/usr/src".

--omit-lines regexp

Excluir datos de cobertura de líneas cuyo contenido coincida con regexp.

Utilice este interruptor si desea excluir datos de cobertura de línea y rama para algunas construcciones particulares en su código (por ejemplo, alguna macro complicada). Se pueden especificar varios patrones utilizando varios interruptores de línea de comandos --omit-lines. El regexp se interpretará como expresiones regulares de Perl (tenga en cuenta que puede ser necesario escaparlas adecuadamente para evitar que el shell las expanda primero). Si desea que el patrón coincida explícitamente desde el principio o el final de la línea, su regexp debe comenzar y/o terminar con "^" y/o "$".

Tenga en cuenta que la configuración del archivo de configuración lcovrc lcov_excl_line = regexp es similar a --omit-lines. --omit-lines es aditivo y se puede especificar en varios archivos de configuración, mientras que cada llamada a lcov_excl_line anula el valor anterior y, por lo tanto, los equipos deben coordinarse.

--external
--no-external

Especificar si se deben capturar datos de cobertura para archivos fuente externos.

Los archivos fuente externos son archivos que no se encuentran en uno de los directorios especificados por --directory o --base-directory. Utilice --external para incluir puntos de cobertura en archivos fuente externos al capturar datos de cobertura o --no-external para excluirlos. Si su ruta --directory o --base-directory contiene un enlace simbólico, el directorio de destino real no se considera "interno" a menos que se utilice la opción --follow.

La opción --no-external es algo contundente; las opciones --exclude e --include proporcionan un control más detallado sobre qué datos de cobertura se incluyen y cuáles no si la estructura de su proyecto es compleja y/o --no-external no hace lo que desea.

Los datos de los archivos fuente externos están **incluidos** por defecto.

--forget-test-names

Si es distinto de cero, ignore los nombres de las pruebas en el archivo .info; es decir, trate todos los datos de cobertura como si provinieran del mismo caso de prueba. Esto puede mejorar el rendimiento y reducir el consumo de memoria si el usuario no necesita un resumen de cobertura por caso de prueba en los informes de cobertura.

Esta opción también se puede configurar de forma permanente utilizando la opción de archivo de configuración forget_testcase_names.

--prune-tests

Determinar la lista de archivos de rastreo únicos.

Utilice esta opción para determinar una lista de archivos de rastreo únicos a partir de la lista especificada por --add-tracefile. Un archivo de rastreo se considera único si es el único archivo de rastreo que:

1.
contiene datos para un archivo fuente específico
2.
contiene datos para un nombre de caso de prueba específico
3.
contiene datos distintos de cero para una línea, función o rama específica

Tenga en cuenta que la lista de archivos retenidos puede depender del orden en que se procesan. Por ejemplo, si A y B contienen datos de cobertura idénticos, se conservará el primero que veamos y se eliminará el segundo. El orden de procesamiento de archivos no es determinista cuando se utiliza la opción --parallel, lo que implica que el resultado podado puede diferir de una ejecución a otra en este caso.

--prune-tests **debe** especificarse **junto con** --add-tracefile. Cuando se especifica, lcov emitirá la lista de archivos únicos en lugar de los datos combinados de los archivos de rastreo.

--map-functions

Enumera los archivos de rastreo con cobertura distinta de cero para cada función.

Utilice esta opción para determinar la lista de archivos de rastreo que contienen datos de cobertura distintos de cero para cada función de la lista de archivos de rastreo especificada por --add-tracefile.

Agregue comment_string a la lista de comentarios emitidos en el archivo de resultados de salida. Esta opción se puede especificar varias veces. Los comentarios se imprimen en la parte superior del archivo, en el orden en que se especificaron.

--ignore-errors errores

Especifique una lista de errores después de los cuales continuar el procesamiento.

Use esta opción para especificar una lista de una o más clases de errores después de las cuales lcov debe continuar el procesamiento en lugar de abortar. Tenga en cuenta que la herramienta generará una advertencia (en lugar de un error fatal) a menos que ignore el error dos (o más) veces:

lcov ... --ignore-errors source,source ...

errores puede ser una lista separada por comas de las siguientes palabras clave:

branch:
el ID de rama (segundo campo en la entrada 'BRDA' del archivo .info) no sigue la secuencia de enteros esperada.
callback:
error del script de versión.
child:
el proceso hijo devolvió un código de salida distinto de cero durante la ejecución de --parallel. Esto generalmente indica que el hijo encontró un error: consulte el archivo de registro inmediatamente anterior a este mensaje. En contraste: el error parallel indica una excepción inesperada/no manejada en el proceso hijo - no un error 'típico' de lcov.
corrupt:
archivo corrupto/ilegible encontrado.
count:
se ha informado de un número excesivo de mensajes de alguna clase - se suprimirán los mensajes posteriores de ese tipo. El límite puede ser controlado por la variable 'max_message_count'. Consulte el manual lcovrc(5).
deprecated:
está utilizando una opción obsoleta. Esta opción se eliminará en una versión futura, por lo que debería cambiar sus scripts ahora.
empty:
el archivo de datos .info está vacío (por ejemplo, porque todo el código fue 'eliminado' o excluido).
excessive:
sus datos de cobertura contienen un recuento de 'aciertos' sospechosamente grande que es poco probable que sea correcto, lo que podría indicar un error en su cadena de herramientas. Consulte la sección excessive_count_threshold en el manual lcovrc(5) para obtener detalles.
fork:
No se pudo crear un proceso hijo durante la ejecución de --parallel.
Si se ignora el mensaje ( --ignore-errors fork ), genhtml esperará un breve período y luego reintentará la ejecución fallida.
Si sigue viendo errores, desactive o reduzca el paralelismo, establezca un límite de memoria o busque un servidor más grande para ejecutar la tarea.
format:
Se encontró sintaxis o valor inesperado en el archivo .info, por ejemplo, se encontró un número negativo o un número de línea cero.
gcov:
la herramienta gcov devolvió un código de retorno distinto de cero.
graph:
el archivo de gráfico no se pudo encontrar o está corrupto.
inconsistent:
sus datos de cobertura son internamente inconsistentes: hacen dos o más afirmaciones mutuamente excluyentes. Por ejemplo, alguna expresión está marcada como rama de excepción y no como rama de excepción. (Consulte el manual genhtml(1) para obtener más detalles.
internal:
se detectó un problema interno de la herramienta. Por favor, informe de este error junto con un caso de prueba.
mismatch:
Se encontraron entradas inconsistentes en el archivo de traza:
  • la expresión de rama (tercer campo en la entrada 'BRDA' del archivo .info) de los datos de fusión no coincide, o
  • recuento de ejecución de función (FNDA:...) pero sin declaración de función (FN:...).
missing:
El archivo no existe o no es legible.
negative:
se encontró un recuento de 'aciertos' negativo.

Tenga en cuenta que los recuentos negativos pueden ser causados por un error conocido de GCC; consulte


https://gcc.gnu.org/bugzilla/show_bug.cgi?id=68080

e intente compilar con "-fprofile-update=atomic". Deberá recompilar, volver a ejecutar sus pruebas y volver a capturar los datos de cobertura.

package:
un paquete perl requerido no está instalado en su sistema. En algunos casos, es posible ignorar este mensaje y continuar; sin embargo, ciertas funciones estarán deshabilitadas en ese caso.
parallel:
varios tipos de errores relacionados con el paralelismo, es decir, un proceso hijo murió debido a un error. El mensaje de error correspondiente aparece en el archivo de registro inmediatamente antes del error parallel.

Si ve un error relacionado con la ejecución paralela que parece inválido, puede ser una buena idea eliminar la bandera --parallel e intentar de nuevo. Si la eliminación de la bandera conduce a un resultado diferente, por favor informe del problema (junto con un caso de prueba) para que la herramienta pueda ser corregida.

parent:
el proceso padre salió mientras el hijo estaba activo durante la ejecución de --parallel. Esto sucede cuando el padre ha encontrado un error fatal, por ejemplo, un error en algún otro hijo que no se ignoró. Este hijo no puede continuar trabajando sin su padre, por lo que saldrá.
range:
Los datos de cobertura se refieren a un número de línea que es mayor que el número de líneas en el archivo fuente. Esto puede ser causado por una discrepancia de versión o por un problema en los datos de gcov.
source:
el archivo de código fuente para un conjunto de datos no se pudo encontrar.
unsupported:
la característica solicitada no es compatible con esta configuración de herramienta. Por ejemplo, las exclusiones de rango de inicio/fin de función utilizan algunas características de GCOV que no están disponibles en versiones anteriores de GCC.
unused:
el patrón include/exclude/erase/omit/substitute no coincidió con ninguna ruta de archivo.
usage:
se detectó un uso no admitido, por ejemplo, una combinación de opciones no admitidas.
utility:
una herramienta llamada durante el procesamiento devolvió un código de error (por ejemplo, 'find' encontró un directorio ilegible).
version:
los ID de control de versiones del archivo que estamos tratando de fusionar no son los mismos; la numeración de líneas y otra información pueden ser incorrectas.

Consulte también el manual lcovrc(5) para una discusión del parámetro 'max_message_count', que se puede utilizar para controlar el número de advertencias que se emiten antes de que se supriman todos los mensajes subsiguientes. Esto se puede usar para reducir el volumen del archivo de registro.

Proporcione a lcov una restricción sobre el número de mensajes de uno o más tipos que se espera que se produzcan durante la ejecución. Si la restricción no se cumple, genere un error de tipo count (consulte más arriba).

Consulte la página del manual genhtml(1) para obtener más detalles sobre la bandera, así como la sección expect_message_count en el manual lcovrc(5) para una descripción de la opción de archivo de configuración equivalente.

-i
--initial

Capture datos de cobertura inicial cero, es decir, de los archivos de datos '.gcno' en tiempo de compilación. Consulte también la bandera --all, que le dice a la herramienta que capture datos en tiempo de compilación ('.gcno') y en tiempo de ejecución ('.gcda') al mismo tiempo.

Ejecute lcov con -c y esta opción en los directorios que contienen archivos .bb, .bbg o .gcno antes de ejecutar cualquier caso de prueba. El resultado es un archivo de datos de cobertura "base" que contiene cero cobertura para cada línea instrumentada. Combine este archivo de datos (usando lcov -a) con la coberturage data files captured after a test run to ensure that the percentage of total lines covered is correct even when not all source code files were loaded during the test.

Procedimiento recomendado al capturar datos para un caso de prueba:

1. crear archivo de datos de cobertura base

# lcov -c -i -d appdir -o app_base.info
2. ejecutar prueba
# appdir/test
3. crear archivo de datos de cobertura de prueba
# lcov -c -d appdir -o app_test.info
4. combinar datos de cobertura base y de prueba
# lcov -a app_base.info -a app_test.info -o app_total.info

Los 4 pasos anteriores son equivalentes a

# lcov --capture --all -o app_total.info -d appdir

Los datos de compilación y ejecución combinados producirán un resultado diferente al de capturar solo los datos de ejecución si su proyecto contiene algunas unidades de compilación que no se utilizan en ninguno de sus ejecutables de casos de prueba o bibliotecas compartidas, es decir, hay algunos archivos de datos '.gcno' (tiempo de compilación) que no tienen archivos de datos '.gcda' (tiempo de ejecución) correspondientes. En ese caso, el informe solo de tiempo de ejecución no contendrá puntos de cobertura de los archivos no utilizados, mientras que esos puntos de cobertura aparecerán (con todos los recuentos de 'aciertos' en cero) en el informe combinado.

El flag --initial se ignora excepto en el modo --capture. El flag --all se ignora si se especifica el flag --initial.

--parallel [ entero ]
-j [ entero ]

Especificar el paralelismo a utilizar durante el procesamiento (número máximo de procesos hijos creados). Si el parámetro opcional de paralelismo entero es cero o falta, úselo para aprovechar el número de núcleos de la máquina. El valor predeterminado es usar un solo proceso (sin paralelismo).
Consulte también las entradas memory, memory_percentage, max_fork_fails y fork_fail_timeout en el manual lcovrc(5).
--memory entero
Especificar la cantidad máxima de memoria a utilizar durante el procesamiento paralelo, en MB. Efectivamente, el proceso no llamará a fork() si se excede este límite. El valor predeterminado es 0 (cero), lo que significa que no hay límite.

Esta opción puede ser útil si el entorno de clúster de cómputo impone límites estrictos en la utilización de recursos, de modo que el trabajo se eliminará si intenta usar demasiados hijos paralelos, pero el usuario no sabe de antemano cuál es el máximo permitido. Esta opción permite que la herramienta utilice el máximo paralelismo, hasta el límite impuesto por la restricción de memoria.

La opción memory_percentage del archivo de configuración proporcionó otra forma de establecer el consumo máximo de memoria. Consulte el manual lcovrc(5) para obtener detalles.
