chown(2) Manual de llamadas al sistema chown(2)

NOMBRE

chown, fchown, lchown, fchownat - cambiar la propiedad de un archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int chown(const char *path, uid_t owner, gid_t group);
int fchown(int fd, uid_t owner, gid_t group);
int lchown(const char *path, uid_t owner, gid_t group);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <unistd.h>
int fchownat(int dirfd, const char *path,
             uid_t owner, gid_t group, int flags);
Requisitos de macro de prueba de características para glibc (ver feature_test_macros(7)):

fchown(), lchown():

    /* Desde glibc 2.12: */ _POSIX_C_SOURCE >= 200809L
        || _XOPEN_SOURCE >= 500
        || /* glibc <= 2.19: */ _BSD_SOURCE

fchownat():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _ATFILE_SOURCE

DESCRIPCIÓN

Estas llamadas al sistema cambian el propietario y el grupo de un archivo. Las llamadas al sistema chown(), fchown() y lchown() solo difieren en cómo se especifica el archivo:

•
chown() cambia la propiedad del archivo especificado por path, el cual es desreferenciado si es un enlace simbólico.
•
fchown() cambia la propiedad del archivo al que se refiere el descriptor de archivo abierto fd.
•
lchown() es como chown(), pero no desreferencia los enlaces simbólicos.

Solo un proceso privilegiado (Linux: uno con la capacidad CAP_CHOWN) puede cambiar el propietario de un archivo. El propietario de un archivo puede cambiar el grupo del archivo a cualquier grupo del cual sea miembro ese propietario. Un proceso privilegiado (Linux: con CAP_CHOWN) puede cambiar el grupo arbitrariamente.

Si el owner o group se especifican como -1, entonces ese ID no se cambia.

Cuando el propietario o grupo de un archivo ejecutable es cambiado por un usuario no privilegiado, los bits de modo S_ISUID y S_ISGID se borran. POSIX no especifica si esto también debería suceder cuando root realiza el chown(); el comportamiento de Linux depende de la versión del kernel, y desde Linux 2.2.13, root se trata como otros usuarios. En caso de un archivo no ejecutable por grupo (es decir, uno para el cual el bit S_IXGRP no está establecido), el bit S_ISGID indica bloqueo obligatorio y no se borra por un chown().

Cuando el propietario o grupo de un archivo ejecutable se cambia (por cualquier usuario), todos los conjuntos de capacidades para el archivo se borran.

fchownat()

La llamada al sistema fchownat() opera exactamente de la misma manera que chown(), excepto por las diferencias descritas aquí.

Si path es relativo, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como se hace con chown() para un nombre de ruta relativo).

Si path es relativo y dirfd es el valor especial AT_FDCWD, entonces path se interpreta en relación con el directorio de trabajo actual del proceso que llama (como chown()).

Si path es absoluto, entonces se ignora dirfd.

El argumento flags es una máscara de bits creada combinando OR 0 o más de los siguientes valores;

AT_EMPTY_PATH (desde Linux 2.6.39)
Si path es una cadena vacía, opera sobre el archivo al que se refiere dirfd (que podría haberse obtenido usando el open(2) flag O_PATH). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio. Si dirfd es AT_FDCWD, la llamada opera sobre el directorio de trabajo actual. Esta bandera es específica de Linux; define _GNU_SOURCE para obtener su definición.
AT_SYMLINK_NOFOLLOW
Si path es un enlace simbólico, no lo desreferencies: en su lugar, opera sobre el enlace mismo, como lchown(). (Por defecto, fchownat() desreferencia los enlaces simbólicos, como chown().)

Ver openat(2) para una explicación de la necesidad de fchownat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

Dependiendo del sistema de archivos, se pueden devolver errores distintos de los enumerados a continuación.

Los errores más generales para chown() se enumeran a continuación.

EACCES
Se deniega el permiso de búsqueda en un componente del prefijo de ruta. (Ver también path_resolution(7).)
EBADF
(fchown()) fd no es un descriptor de archivo abierto válido.
EBADF
(fchownat()) path es relativo pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
path apunta fuera de su espacio de direcciones accesible.
EINVAL
(fchownat()) Bandera inválida especificada en flags.
EIO
(fchown()) Ocurrió un error de E/S de bajo nivel al modificar el inodo.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver path.
ENAMETOOLONG
path es demasiado largo.
ENOENT
El archivo no existe.
ENOMEM
Había muy poca memoria del kernel disponible.
ENOTDIR
Un componente del prefijo de ruta no es un directorio.
ENOTDIR
(fchownat()) path es relativo y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EPERM
El proceso que llama no tenía los permisos requeridos (ver arriba) para cambiar el propietario y/o el grupo.
EPERM
El archivo está marcado como inmutable o de solo añadir. (Ver FS_IOC_SETFLAGS(2const).)
EROFS
El archivo nombrado reside en un sistema de archivos de solo lectura.

VERSIÓNES

La versión 4.4BSD solo puede ser utilizada por el superusuario (es decir, los usuarios normales no pueden regalar archivos).

Propiedad de nuevos archivos

Al crear un nuevo archivo

lchown32(2) — man páginas de Linux

NOMBRE

lchown32, lchown - cambiar el propietario de un archivo

BIBLIOTECA

Biblioteca C de GNU (glibc)

SINOPSIS

#include <unistd.h>
int lchown32(const char *pathname, uid_t owner, gid_t group);
int lchown(const char *pathname, uid_t owner, gid_t group);

DESCRIPCIÓN

La llamada al sistema lchown() cambia el ID de usuario y/o el ID de grupo del archivo al que apunta el puntero pathname. Los valores de owner y group son los nuevos IDs de usuario y grupo respectivamente. Si uno de los argumentos de ID es especial (-1), entonces el ID correspondiente no se cambia.

Las llamadas al sistema lchown() y lchown32() son idénticas a chown() y chown32() respectivamente, excepto que cuando se opera sobre un enlace simbólico, lchown() actúa sobre el propio enlace simbólico, en lugar de hacerlo sobre el archivo al que apunta el enlace.

chown32() y lchown32() son versiones de 32 bits de chown() y lchown() que están disponibles en sistemas que usan IDs de usuario y de grupo de 64 bits (pero que aún usan la interfaz de 32 bits para la mayoría de las llamadas al sistema).

La propiedad de un archivo nuevo, creado por ejemplo por open(2) o mkdir(2), se establece de la siguiente manera: el propietario se establece igual al ID de usuario del sistema de archivos del proceso creador. El grupo del archivo depende de una serie de factores, incluyendo el tipo de sistema de archivos, las opciones usadas para montar el sistema de archivos y si el bit de modo set-group-ID está habilitado o no en el directorio padre. Si el sistema de archivos soporta las opciones de montaje mount(8) -o grpid (o, sinónimamente, -o bsdgroups) y -o nogrpid (o, sinónimamente, -o sysvgroups), entonces las reglas son las siguientes:

•
Si el sistema de archivos está montado con -o grpid, entonces el grupo de un archivo nuevo se establece igual al del directorio padre.
•
Si el sistema de archivos está montado con -o nogrpid y el bit set-group-ID está deshabilitado en el directorio padre, entonces el grupo de un archivo nuevo se establece igual al GID del sistema de archivos del proceso.
•
Si el sistema de archivos está montado con -o nogrpid y el bit set-group-ID está habilitado en el directorio padre, entonces el grupo de un archivo nuevo se establece igual al del directorio padre.

A partir de Linux 4.12, las opciones de montaje -o grpid y -o nogrpid son soportadas por ext2, ext3, ext4 y XFS. Los sistemas de archivos que no soportan estas opciones de montaje siguen las reglas de -o nogrpid.

Notas sobre glibc

En kernels más antiguos donde fchownat() no está disponible, la función de envoltura de glibc recurre al uso de chown() y lchown(). Cuando path es relativo, glibc construye un nombre de ruta basado en el enlace simbólico en /proc/self/fd que corresponde al argumento dirfd.

NFS

La semántica de chown() se viola deliberadamente en sistemas de archivos NFS que tienen mapeo de UID habilitado. Adicionalmente, la semántica de todas las llamadas al sistema que acceden al contenido del archivo se ve violada, ya que chown() puede causar la revocación inmediata del acceso en archivos ya abiertos. El caché del lado del cliente puede llevar a un retraso entre el momento en que la propiedad ha sido cambiada para permitir el acceso a un usuario y el momento en que el archivo puede ser accedido realmente por el usuario en otros clientes.

Detalles históricos

Las llamadas al sistema originales de Linux chown(), fchown() y lchown() solo soportaban IDs de usuario y grupo de 16 bits. Posteriormente, Linux 2.4 añadió chown32(), fchown32() y lchown32(), soportando IDs de 32 bits. Las funciones de envoltura de glibc chown(), fchown() y lchown() manejan transparente las variaciones entre versiones del kernel.

Antes de Linux 2.1.81 (excepto 2.1.46), chown() no seguía enlaces simbólicos. Desde Linux 2.1.81, chown() sigue enlaces simbólicos, y hay una nueva llamada al sistema lchown() que no sigue enlaces simbólicos. Desde Linux 2.1.86, esta nueva llamada (que tiene la misma semántica que la vieja chown()) ha obtenido el mismo número de syscall, y chown() ha obtenido el número recién introducido.

EJEMPLOS

El siguiente programa cambia la propiedad del archivo cuyo nombre se indica en su segundo argumento de línea de comandos al valor especificado en su primer argumento de línea de comandos. El nuevo propietario puede ser especificado como un ID de usuario numérico o como un nombre de usuario (que se convierte a un ID de usuario utilizando getpwnam(3) para realizar una búsqueda en el archivo de contraseñas del sistema).

Código fuente del programa

#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    char           *endptr;
    uid_t          uid;
    struct passwd  *pwd;
    if (argc != 3 || argv[1][0] == '\0') {
        fprintf(stderr, "%s <propietario> <archivo>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    uid = strtol(argv[1], &endptr, 10);  /* Permitir una cadena numérica */
    if (*endptr != '\0') {         /* No era una cadena puramente numérica */
        pwd = getpwnam(argv[1]);   /* Intentar obtener UID para el nombre de usuario */
        if (pwd == NULL) {
            perror("getpwnam");
            exit(EXIT_FAILURE);
        }
        uid = pwd->pw_uid;
    }
    if (chown(argv[2], uid, -1) == -1) {
        perror("chown");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS);
}
