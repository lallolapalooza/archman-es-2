chown(2) Manual de llamadas al sistema chown(2)

NOMBRE

chown, fchown, lchown, fchownat - cambiar la propiedad de un archivo

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <unistd.h>
int chown(const char *ruta, uid_t propietario, gid_t grupo);
int fchown(int fd, uid_t propietario, gid_t grupo);
int lchown(const char *ruta, uid_t propietario, gid_t grupo);
#include <fcntl.h>           /* Definición de constantes AT_* */
#include <unistd.h>
int fchownat(int dirfd, const char *ruta,
             uid_t propietario, gid_t grupo, int flags);
Requisitos de Macro de Prueba de Funcionalidades para glibc (ver feature_test_macros(7)):

fchown(), lchown():

    /* Desde glibc 2.12: */ _POSIX_C_SOURCE >= 200809L
        || _XOPEN_SOURCE >= 500
        || /* glibc <= 2.19: */ _BSD_SOURCE

fchownat():

    Desde glibc 2.10:
        _POSIX_C_SOURCE >= 200809L
    Antes de glibc 2.10:
        _ATFILE_SOURCE

DESCRIPCIÓN

Estas llamadas al sistema cambian el propietario y el grupo de un archivo. Las llamadas al sistema chown(), fchown() y lchown() difieren solo en cómo se especifica el archivo:

•
chown() cambia la propiedad del archivo especificado por ruta, el cual se dereferencia si es un enlace simbólico.
•
fchown() cambia la propiedad del archivo al que se refiere el descriptor de archivo abierto fd.
•
lchown() es como chown(), pero no dereferencia enlaces simbólicos.

Solo un proceso privilegiado (Linux: uno con la capacidad CAP_CHOWN) puede cambiar el propietario de un archivo. El propietario de un archivo puede cambiar el grupo del archivo a cualquier grupo del que sea miembro ese propietario. Un proceso privilegiado (Linux: con CAP_CHOWN) puede cambiar el grupo arbitrariamente.

Si el propietario o grupo se especifican como -1, entonces ese ID no se cambia.

Cuando el propietario o el grupo de un archivo ejecutable es cambiado por un usuario no privilegiado, los bits de modo S_ISUID y S_ISGID se borran. POSIX no especifica si esto también debería suceder cuando root realiza el chown(); el comportamiento de Linux depende de la versión del kernel, y desde Linux 2.2.13, root se trata como otros usuarios. En caso de un archivo no ejecutable por grupo (es decir, uno para el cual el bit S_IXGRP no está establecido) el bit S_ISGID indica bloqueo obligatorio, y no se borra por un chown().

Cuando el propietario o el grupo de un archivo ejecutable es cambiado (por cualquier usuario), todos los conjuntos de capacidades para el archivo se borran.

fchownat()

La llamada al sistema fchownat() funciona exactamente de la misma manera que chown(), excepto por las diferencias descritas aquí.

Si ruta es relativa, entonces se interpreta en relación con el directorio al que se refiere el descriptor de archivo dirfd (en lugar de en relación con el directorio de trabajo actual del proceso que llama, como hace chown() para un nombre de ruta relativo).

Si ruta es relativa y dirfd es el valor especial AT_FDCWD, entonces ruta se interpreta en relación con el directorio de trabajo actual del proceso que llama (como chown()).

Si ruta es absoluta, entonces se ignora dirfd.

El argumento flags es una máscara de bits creada combinando mediante OR 0 o más de los siguientes valores:

AT_EMPTY_PATH (desde Linux 2.6.39)
Si ruta es una cadena vacía, opera en el archivo al que se refiere dirfd (que puede haberse obtenido usando la bandera open(2) O_PATH). En este caso, dirfd puede referirse a cualquier tipo de archivo, no solo a un directorio. Si dirfd es AT_FDCWD, la llamada opera en el directorio de trabajo actual. Esta bandera es específica de Linux; define _GNU_SOURCE para obtener su definición.
AT_SYMLINK_NOFOLLOW
Si ruta es un enlace simbólico, no lo dereferencia: en su lugar, opera en el enlace mismo, como lchown(). (Por defecto, fchownat() dereferencia enlaces simbólicos, como chown().)

Consulte openat(2) para una explicación de la necesidad de fchownat().

VALOR DE RETORNO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y se establece errno para indicar el error.

ERRORES

Dependiendo del sistema de archivos, se pueden devolver errores además de los enumerados a continuación.

A continuación se enumeran los errores más generales para chown().

EACCES
Se deniega el permiso de búsqueda en un componente del prefijo de la ruta. (Ver también path_resolution(7).)
EBADF
(fchown()) fd no es un descriptor de archivo abierto válido.
EBADF
(fchownat()) ruta es relativa pero dirfd no es AT_FDCWD ni un descriptor de archivo válido.
EFAULT
ruta apunta fuera de su espacio de direcciones accesible.
EINVAL
(fchownat()) Bandera inválida especificada en flags.
EIO
(fchown()) Se produjo un error de E/S de bajo nivel al modificar el inodo.
ELOOP
Se encontraron demasiados enlaces simbólicos al resolver ruta.
ENAMETOOLONG
ruta es demasiado larga.
ENOENT
El archivo no existe.
ENOMEM
No había suficiente memoria del kernel disponible.
ENOTDIR
Un componente del prefijo de la ruta no es un directorio.
ENOTDIR
(fchownat()) ruta es relativa y dirfd es un descriptor de archivo que se refiere a un archivo que no es un directorio.
EPERM
El proceso que llama no tenía los permisos requeridos (ver arriba) para cambiar el propietario y/o grupo.
EPERM
El archivo está marcado como inmutable o de solo añadir. (Ver FS_IOC_SETFLAGS(2const).)
EROFS
El archivo nombrado reside en un sistema de archivos de solo lectura.

VERSIONES

La versión 4.4BSD solo puede ser utilizada por el superusuario (es decir, los usuarios ordinarios no pueden ceder archivos).

lchown(2) — Manual page

NAME

lchown, chown, fchown — change the owner of a file

LIBRARY

libc, -lc

SYNOPSIS

       #include <unistd.h>

       int chown(const char *pathname, uid_t owner, gid_t group);
       int lchown(const char *pathname, uid_t owner, gid_t group);
       int fchown(int fd, uid_t owner, gid_t group);
       int fchownat(int dirfd, const char *pathname, uid_t owner, gid_t group,
                    int flags);

DESCRIPTION

These system calls change the user and/or group ownership of the file referred to by the pathname or file descriptor.

Only a privileged user (root) can change the ownership of any file. A non-privileged user (i.e., the effective user ID is not the superuser) can change the ownership of a file only if the owner ID of the file is the same as the real user ID of the caller and the group ID of the file is the same as the effective group ID of the caller, and the caller has write permission on the file. The caller can also change the group ownership of the file to any group that the caller belongs to.

The owner and group are specified by the owner and group arguments, respectively. A value of -1 for either argument leaves the corresponding ID unchanged.

The behavior of chown() and lchown() differs in their handling of symbolic links:

•
chown() follows symbolic links. If pathname is a symbolic link, then the owner and group of the symbolic link itself are changed.
•
lchown() does not follow symbolic links. If pathname is a symbolic link, then the owner and group of the symbolic link itself are changed.

fchown() operates on an open file specified by the file descriptor fd. It does not operate on a symbolic link, but rather on the file that the symbolic link points to. If fd refers to a symbolic link, fchown() changes the ownership of the symbolic link itself.

fchownat() is equivalent to fchown() except that it operates on a file relative to a directory specified by dirfd (rather than always relative to the current working directory as is done when pathname is relative). The behavior of fchownat() is also affected by the value of the flags argument.

The following flags can be passed in flags to fchownat():

AT_SYMLINK_NOFOLLOW
If pathname is a symbolic link, then it affects this operation in the same way as lchown().
AT_NO_AUTOMOUNT
Do not trigger a automount. (See automount(8).)
AT_REMOVEDIR
This flag is not applicable to fchownat().

If pathname is relative and dirfd is AT_FDCWD, then pathname is interpreted relative to the current working directory (like chown() and lchown()).

If pathname is absolute, the dirfd argument is ignored.

If pathname is relative, then it is resolved relative to the directory referred to by the file descriptor dirfd. If pathname contains a trailing slash, it is ignored.

A special value for pathname is an empty string "", for which fchownat() operates on the file referred to by the open file description referred to by dirfd.

The behavior of the system calls when changing ownership of a file depends on the filesystem. On Linux, the owner of a file is set to the value of the owner argument. The group of the file is set to the value of the group argument. If either argument is -1, the corresponding file attribute is not changed.

When a file is created (by, for example, open(2) or mkdir(2)), its owner is made the same as the filesystem user ID of the creating process. The group of the file depends on a range of factors, including the type of filesystem, the options used to mount the filesystem, and whether or not the set-group-ID mode bit is enabled on the parent directory. If the filesystem supports the -o grpid (or, synonymously -o bsdgroups) and -o nogrpid (or, synonymously -o sysvgroups) mount(8) options, then the rules are as follows:

•
If the filesystem is mounted with -o grpid, then the group of a new file is made the same as that of the parent directory.
•
If the filesystem is mounted with -o nogrpid and the set-group-ID bit is disabled on the parent directory, then the group of a new file is made the same as the process's filesystem GID.
•
If the filesystem is mounted with -o nogrpid and the set-group-ID bit is enabled on the parent directory, then the group of a new file is made the same as that of the parent directory.

As at Linux 4.12, the -o grpid and -o nogrpid mount options are supported by ext2, ext3, ext4, and XFS. Filesystems that don't support these mount options follow the -o nogrpid rules.

glibc notes

On older kernels where fchownat() is unavailable, the glibc wrapper function falls back to the use of chown() and lchown(). When path is relative, glibc constructs a pathname based on the symbolic link in /proc/self/fd that corresponds to the dirfd argument.

NFS

The chown() semantics are deliberately violated on NFS filesystems which have UID mapping enabled. Additionally, the semantics of all system calls which access the file contents are violated, because chown() may cause immediate access revocation on already open files. Client side caching may lead to a delay between the time where ownership have been changed to allow access for a user and the time where the file can actually be accessed by the user on other clients.

Historical details

The original Linux chown(), fchown(), and lchown() system calls supported only 16-bit user and group IDs. Subsequently, Linux 2.4 added chown32(), fchown32(), and lchown32(), supporting 32-bit IDs. The glibc chown(), fchown(), and lchown() wrapper functions transparently deal with the variations across kernel versions.

Before Linux 2.1.81 (except 2.1.46), chown() did not follow symbolic links. Since Linux 2.1.81, chown() does follow symbolic links, and there is a new system call lchown() that does not follow symbolic links. Since Linux 2.1.86, this new call (that has the same semantics as the old chown()) has got the same syscall number, and chown() got the newly introduced number.

EXAMPLES

The following program changes the ownership of the file named in its second command-line argument to the value specified in its first command-line argument. The new owner can be specified either as a numeric user ID, or as a username (which is converted to a user ID by using getpwnam(3) to perform a lookup in the system password file).

Program source

#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    char           *endptr;
    uid_t          uid;
    struct passwd  *pwd;
    if (argc != 3 || argv[1][0] == '\0') {
        fprintf(stderr, "%s <owner> <file>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    uid = strtol(argv[1], &endptr, 10);  /* Allow a numeric string */
    if (*endptr != '\0') {         /* Was not pure numeric string */
        pwd = getpwnam(argv[1]);   /* Try getting UID for username */
        if (pwd == NULL) {
            perror("getpwnam");
            exit(EXIT_FAILURE);
        }
        uid = pwd->pw_uid;
    }
    if (chown(argv[2], uid, -1) == -1) {
        perror("chown");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS);
}
