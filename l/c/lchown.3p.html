LCHOWN(3P) Manual del programador de POSIX LCHOWN(3P)

PRÓLOGO

Esta página del manual forma parte del Manual del Programador de POSIX. La implementación de esta interfaz en Linux puede diferir (consulte la página del manual correspondiente de Linux para conocer los detalles del comportamiento de Linux), o la interfaz puede no estar implementada en Linux.

NOMBRE

lchown — cambiar el propietario y el grupo de un enlace simbólico

SINOPSIS

#include <unistd.h>
int lchown(const char *path, uid_t owner, gid_t group);

DESCRIPCIÓN

La función lchown() será equivalente a chown(), excepto en el caso de que el archivo nombrado sea un enlace simbólico. En este caso, lchown() cambiará la propiedad del propio enlace simbólico, mientras que chown() cambiará la propiedad del archivo o directorio al que se refiere el enlace simbólico.

VALOR DE RETORNO

Al completarse con éxito, lchown() devolverá 0. De lo contrario, devolverá -1 y establecerá errno para indicar un error.

ERRORES

La función lchown() fallará si:

EACCES
Se deniega el permiso de búsqueda en un componente del prefijo de ruta de path.
EINVAL
El ID de propietario o de grupo no es un valor admitido por la implementación.
ELOOP
Existe un bucle en los enlaces simbólicos encontrados durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un componente de un nombre de ruta es mayor que {NAME_MAX}.
ENOENT
Un componente de path no nombra un archivo existente o path es una cadena vacía.
ENOTDIR
Un componente del prefijo de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio, o el argumento path contiene al menos un carácter que no es <barra> y termina con uno o más caracteres de <barra> finales y el último componente del nombre de ruta nombra un archivo existente que no es ni un directorio ni un enlace simbólico a un directorio.
EPERM
El ID de usuario efectivo no coincide con el propietario del archivo y el proceso no tiene los privilegios apropiados.
EROFS
El archivo reside en un sistema de archivos de solo lectura.

La función lchown() puede fallar si:

EIO
Ocurrió un error de E/S al leer o escribir en el sistema de archivos.
EINTR
Se capturó una señal durante la ejecución de la función.
ELOOP
Se encontraron más de {SYMLOOP_MAX} enlaces simbólicos durante la resolución del argumento path.
ENAMETOOLONG

La longitud de un nombre de ruta excede {PATH_MAX}, o la resolución de un enlace simbólico produjo un resultado intermedio con una longitud que excede {PATH_MAX}.

Las siguientes secciones son informativas.

EJEMPLOS

Cambiar el propietario actual de un archivo

El siguiente ejemplo muestra cómo cambiar la propiedad del enlace simbólico llamado /modules/pass1 al ID de usuario asociado con ``jones'' y al ID de grupo asociado con ``cnd''.

El valor numérico del ID de usuario se obtiene utilizando la función getpwnam(). El valor numérico del ID de grupo se obtiene utilizando la función getgrnam().

#include <sys/types.h>
#include <unistd.h>
#include <pwd.h>
#include <grp.h>
struct passwd *pwd;
struct group  *grp;
char          *path = "/modules/pass1";
...
pwd = getpwnam("jones");
grp = getgrnam("cnd");
lchown(path, pwd->pw_uid, grp->gr_gid);

USO DE LA APLICACIÓN

En implementaciones que admiten enlaces simbólicos como entradas de directorio en lugar de archivos, lchown() puede fallar.
