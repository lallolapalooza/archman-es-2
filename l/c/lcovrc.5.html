NOMBRE

lcovrc - archivo de configuración de lcov

DESCRIPCIÓN

El archivo lcovrc contiene información de configuración para la herramienta de cobertura de código lcov (ver lcov(1)).

El archivo de configuración global del sistema se encuentra en $LCOV_HOME/etc/lcovrc. Normalmente es /etc/lcovrc o /usr/local/etc/lcovrc, pero puede estar dondequiera que hayas instalado el paquete lcov. Para cambiar la configuración para un solo usuario, coloca una copia personalizada de este archivo en la ubicación ~/.lcovrc. Donde esté disponible, las opciones de línea de comandos anulan la configuración del archivo.

Los comandos genhtml, lcov, y geninfo también soportan la opción --config-file, que puede ser usada para especificar uno o más archivos que deben ser usados en lugar de los archivos rc predeterminados del sistema o del usuario. Múltiples archivos de opciones pueden ser útiles si tienes opciones comunes específicas de proyecto y de equipo y quieres asegurar la consistencia entre múltiples usuarios. Si se aplican múltiples opciones --config-file en el orden en que aparecen. Ten en cuenta que el nombre de la opción "--config-file" debe especificarse completo y no puede abreviarse. Se producirá un error si la opción no es reconocida.

Las líneas en un archivo de configuración pueden ser:

*
líneas vacías o líneas que consisten solo en caracteres de espacio en blanco. Estas líneas se ignoran.
*
líneas de comentario que comienzan con un signo de almohadilla ('#'). Estas se tratan como líneas vacías y se ignoran.
*
declaraciones en la forma 'clave = valor'.
*
Los valores pueden tomarse de variables de entorno a través de la sintaxis

'clave = ...$ENV{NOMBRE_VAR_ENTORNO}...'.

La subcadena '$ENV{NOMBRE_VAR_ENTORNO}' se reemplaza por el valor de la variable de entorno.

Una o más variables de entorno pueden ser usadas para establecer el valor RC.

Una lista de declaraciones válidas y su descripción se puede encontrar en la sección 'OPCIONES' más abajo.
NOTA que no hay comprobación de errores para las claves en el archivo de opciones: los errores de escritura simplemente se ven como valores que no son utilizados por alguna herramienta en particular. Si no estás seguro de si tu archivo de opciones se lee o si sus valores se aplican, puedes usar la opción --verbose --verbose para habilitar la impresión de las anulaciones de valores de opción. (La opción aparece dos veces para habilitar un nivel de verbosidad más alto.)

Tanto las opciones de 'lista' como las de 'escalar' (no lista) son soportadas en el archivo lcovrc.

Para opciones escalares (no lista):

*
si se especifican en la línea de comandos y en el archivo lcovrc, el valor especificado en la línea de comandos prevalece. El valor del archivo RC se ignora.
*
Las opciones escalares incluyen: 'criteria_script = ...' , 'genhtml_annotate_script = ...' , 'version_script = ...' , etc.

Para opciones de lista:

*
la entrada del archivo RC se puede usar múltiples veces; cada uso se añade a la lista.
Por ejemplo, la entrada de abajo resultará en dos patrones 'omit' que ambos serán comprobados:
# nota marcadores explícitos de inicio/fin de línea en la expresión regular
omit_lines = ^\s+//\s*MY_EXCLUDE_MARKER\s*$
# Nota que la expresión regular de abajo coincide en cualquier parte de la línea
omit_lines = NR_CM_DBG_PRINT
*
Si se especifican entradas en la línea de comandos, entonces las entradas del archivo RC se ignoran: la línea de comandos prevalece. Si se especifican entradas en más de un archivo RC (es decir, se proporcionan múltiples argumentos --config-file), entonces los archivos RC se aplican en orden de aparición y las entradas de lista se añaden en orden. Para la mayoría de las opciones de tipo lista, el orden no es importante.
*
las opciones de lista incluyen:
filter = ...
exclude = ...
ignore = ...
substitute = ...
omit_lines = ...
erase_functions = ...
genhtml_annotate_script = ...
etc. Para un conjunto completo de opciones de lista, ver la documentación de cada opción de configuración, más abajo.

CONFIGURATION

En este archivo se pueden especificar opciones para lcov, genhtml y geninfo. Algunas opciones son para lcov, otras para genhtml y otras para geninfo. Si una opción no es válida para una herramienta, será ignorada.

Las directivas de configuración tienen la forma:

nombre_opcion = valor

Los comentarios comienzan con el carácter # y continúan hasta el final de la línea.

Las opciones pueden dividirse en varias líneas usando una barra invertida \ al final de la línea.

Algunos valores pueden ser booleanos. Estos se pueden especificar como 0, 1, sí, no, verdadero o falso (insensible a mayúsculas/minúsculas).

Las opciones que esperan un nombre de archivo pueden especificar el nombre del archivo o el nombre de un directorio. Si se especifica un directorio, se espera que contenga un archivo llamado .lcovrc.

Si se encuentra una opción varias veces, el último valor encontrado será el utilizado.

OPCIONES

config_file = nombre_archivo

Incluya otro archivo de configuración.

La inclusión es equivalente a insertar el texto de nombre_archivo en este punto del archivo actual. Como resultado, la configuración del archivo incluido se procesa después de la configuración anterior en el archivo actual, pero antes de la configuración posterior del archivo actual. Como resultado:

Las opciones escalares establecidas anteriormente en el archivo actual se anulan con la configuración del archivo incluido, y las opciones escalares del archivo incluido se anulan con la configuración posterior en el archivo actual.

Las opciones de matriz de antes en el archivo actual aparecen antes de la configuración del archivo incluido, y las opciones de matriz de después en el archivo actual aparecen después.

La inclusión de archivos de configuración es recursiva: un archivo de configuración incluido puede incluir otro archivo y así sucesivamente. Los bucles de inclusión no son compatibles y resultarán en un error de uso.

El caso de uso más común para la inclusión de archivos de configuración es que un archivo de opciones para todo el sitio o proyecto pueda incluir un archivo de opciones específico del usuario o del módulo, por ejemplo, como


...
config_file = $ENV{HOME}/.lcovrc_user
...

Adjust source paths when capturing coverage data.

Use this option in situations where geninfo cannot find the correct path to source code files of a project. By providing a pattern in Perl regular expression format (see perlre(1)) and an optional replacement string, you can instruct geninfo to remove or change parts of the incorrect source path.

Example:

/path/to/src/.libs/file.c

while the file is actually located in


/path/to/src/file.c

use the following parameter:


geninfo_adjust_src_path = /.libs

This will remove all "/.libs" strings from the path.

/tmp/build/file.c

while the file is actually located in


/usr/src/file.c

use the following parameter:


geninfo_adjust_src_path = /tmp/build => /usr/src

This will change all "/tmp/build" strings in the path to "/usr/src".

lcovrc(5) — Arch Linux manual pages

NAME

lcovrc

— lcov configuration file

DESCRIPTION

The lcovrc file is used to specify configuration parameters for lcov, geninfo and genhtml.

Parameters can be specified in the file $LCOV_HOME/etc/lcovrc or ~/.lcovrc. The latter overrides the former. Parameters specified on the command line override parameters from configuration files.

The configuration file is a plain text file which is parsed line by line. Lines starting with '#' and empty lines are ignored.

Each parameter is specified as key = value.

The following parameters are recognized:

OPTIONS

select_script = script

Specifies a script which shall be used to select source code lines for inclusion in the report. The script will be called for each source code line. If the script returns with exit code 0, the line will be selected, otherwise it will be ignored.

The script will be called with arguments:

select_script [callback_args] lineDataJson annotateDataJson fileName lineNumber

or if a perl module is used:

$selectCallback = select_module ->new([callback_args])

then

$selectCallback select (lineDataRef annotateDataRef fileName lineNumber)

Here:

  • fileName is the name of the source file.
  • lineNumber is the line number within the source file (first line is 0).
  • lineDataJson is a JSON encoded LineData structure (see source file lcovutil.pm).
  • annotateDataJson is a JSON encoded output from an --annotate-script (see man page genhtml(1)) or an empty string if no annotation data is available for this file.

Note: Lines which are not selected but are within num_context_lines of a selected line are also included in the report. See below.

Note that selection is fundamentally intended to show regions of code with some surrounding context. It might not do what you expect if there is no code - e.g., if the region of interest has been compiled out via compiler or exclusion directives. For example: when selecting based on SHA or changelist ID, an inserted comment will not be selected unless it is within num_context_lines of an inserted or changed line of code.

The select script is called as:

select_script [callback_args] lineDataJson annotateDataJson fileName lineNumber

or as:

$selectCallback = select_module ->new([callback_args])

to initialize the callback object, then as

$selectCallback select (lineDataRef annotateDataRef fileName lineNumber)

to determine selection, where
  • fileName is the name of the source file and
  • lineNumber is the source file line number, indexed from zero,
  • lineDataJson is a json-encoded LineData structure (see the lcovutil.pm source code), and
  • annotateDataJson is the json-encoded data returned by your annotate-script (see the --annotate-script parameter in man genhtml(1). ), or the empty string if there are no annotations for this file.

The module callback is similar except that is is passed objects rather than JSON encodings of the objects.

The script should return "1" or "0".

See example implementation $LCOV_HOME/share/lcov/support-scripts/select.pm.
