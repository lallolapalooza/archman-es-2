HG(IMPORT) HG(IMPORT)

NOMBRE

hg import - importar un conjunto ordenado de parches

SINOPSIS

hg import [OPCIÓN]... PARCHE...

DESCRIPCIÓN

Importa una lista de parches y los confirma individualmente (a menos que se especifique --no-commit).

Para leer un parche desde la entrada estándar (stdin), usa "-" como nombre del parche. Si se especifica una URL, el parche se descargará de allí.

Import primero aplica los cambios al directorio de trabajo (a menos que se especifique --bypass), import abortará si hay cambios pendientes.

Usa --bypass para aplicar y confirmar parches directamente en el repositorio, sin afectar el directorio de trabajo. Sin --exact, los parches se aplicarán encima de la revisión padre del directorio de trabajo.

Puedes importar un parche directamente desde un mensaje de correo. Incluso los parches adjuntos funcionan (para usar la parte del cuerpo, debe tener el tipo text/plain o text/x-patch). Las cabeceras From y Subject del mensaje de correo se usan como autor de confirmación y mensaje de confirmación predeterminados. Todas las partes del cuerpo text/plain antes del primer diff se agregan al mensaje de confirmación.

Si el parche importado fue generado por hg export, el usuario y la descripción del parche anulan los valores de las cabeceras y el cuerpo del mensaje. Los valores dados en la línea de comandos con -m/--message y -u/--user anulan estos.

Si se especifica --exact, import establecerá el directorio de trabajo en el padre de cada parche antes de aplicarlo, y abortará si el cambio resultante tiene un ID diferente al registrado en el parche. Esto protegerá contra varias formas en que los formatos de parche portátiles y los sistemas de correo puedan fallar al transferir datos o metadatos de Mercurial. Ver hg bundle para una transmisión sin pérdidas.

Usa --partial para asegurar que se creará un cambio a partir del parche incluso si algunos fragmentos fallan al aplicarse. Los fragmentos que fallan al aplicarse se escribirán en un archivo <archivo-destino>.rej. Los conflictos se pueden resolver manualmente antes de ejecutar hg commit --amend para actualizar el cambio creado. Esta bandera existe para permitir que las personas importen parches que se aplican parcialmente sin perder los metadatos asociados (autor, fecha, descripción, ...).

Nota
Cuando ningún fragmento se aplica limpiamente, hg import --partial creará un cambio vacío, importando solo los metadatos del parche.

Con -s/--similarity, hg intentará descubrir renombrados y copias en el parche de la misma manera que hg addremove.

Es posible usar programas de parches externos para realizar el parche configurando la opción de configuración ui.patch. Para la herramienta interna predeterminada, la cantidad de "fuzz" también se puede configurar mediante patch.fuzz. Ver hg help config para más información sobre los archivos de configuración y cómo usar estas opciones.

Ver hg help dates para una lista de formatos válidos para -d/--date.

Ejemplos:

  • importar un parche tradicional de un sitio web y detectar renombrados: 
    hg import -s 80 http://example.com/bugfix.patch
  • importar un cambio de un servidor hgweb: 
    hg import https://www.mercurial-scm.org/repo/hg/rev/5ca8c111e9aa
  • importar todos los parches en un mbox estilo Unix: 
    hg import incoming-patches.mbox
  • importar parches desde stdin: 
    hg import -
  • intentar restaurar exactamente un cambio exportado (no siempre es posible): 
    hg import --exact proposed-fix.patch
  • usar una herramienta externa para aplicar un parche que es demasiado difuso para la herramienta interna predeterminada.

    hg import --config ui.patch="patch --merge" fuzzy.patch

  • cambiar la cantidad de "fuzz" predeterminada de 2 a 7, menos estricta

    hg import --config ui.fuzz=7 fuzz.patch

    Retorna 0 en caso de éxito, 1 en caso de éxito parcial (ver --partial).

OPCIONES

-p,--strip <NUM>
opción de strip de directorios para el parche. Tiene el mismo significado que la opción correspondiente de patch (predeterminado: 1)
-b,--base <RUTA>
ruta base (OBSOLETO)
--secret
usar la fase secreta para confirmar
-e, --edit
invocar editor en los mensajes de confirmación
-f, --force
omitir la comprobación de cambios pendientes sin confirmar (OBSOLETO)
--no-commit
no confirmar, solo actualizar el directorio de trabajo
--bypass
aplicar parche sin tocar el directorio de trabajo
--partial
confirmar incluso si algunos fragmentos fallan
--exact
abortar si el parche se aplicara de forma imprecisa
--prefix <DIR>
aplicar parche a subdirectorio
--import-branch
usar cualquier información de rama en el parche (implicado por --exact)
-m,--message <TEXTO>
usar texto como mensaje de confirmación
-l,--logfile <ARCHIVO>
leer mensaje de confirmación desde archivo
-d,--date <FECHA>
registrar la fecha especificada como fecha de confirmación
-u,--user <USUARIO>
registrar el usuario especificado como confirmador
-s,--similarity <SIMILARIDAD>
adivinar archivos renombrados por similitud (0<=s<=100)
