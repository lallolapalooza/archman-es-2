Las opciones de configuración por repositorio solo se aplican en un repositorio particular. Este archivo no está controlado por versiones y no se transferirá durante una operación de "clone". Las opciones en este archivo anulan las opciones en todos los demás archivos de

configuración.

En Plan 9 y Unix, la mayor parte de este archivo se ignorará si no pertenece a un usuario de confianza o a un grupo de confianza. Consulta hg help config.trusted para más

detalles.

Los archivos de configuración por usuario son para el usuario que ejecuta Mercurial. Las opciones en estos archivos se aplican a todos los comandos de Mercurial ejecutados por este usuario en cualquier directorio. Las opciones en estos archivos anulan las opciones por sistema y por

instalación.

Los archivos de configuración por instalación se buscan en el directorio donde está instalado Mercurial. <raíz-de-instalación> es el directorio padre del ejecutable (o enlace simbólico) hg que se está

ejecutando.

Por ejemplo, si está instalado en /shared/tools/bin/hg, Mercurial buscará en /shared/tools/etc/mercurial/hgrc. Las opciones en estos archivos se aplican a todos los comandos de Mercurial ejecutados por cualquier usuario en cualquier

directorio.

Los archivos de configuración por instalación son para el sistema en el que se está ejecutando Mercurial. Las opciones en estos archivos se aplican a todos los comandos de Mercurial ejecutados por cualquier usuario en cualquier directorio. Las claves de registro contienen cadenas similares a PATH, cada parte de las cuales debe hacer referencia a un archivo Mercurial.ini o ser un directorio donde se leerán archivos *.rc. Mercurial comprueba cada una de estas ubicaciones en el orden especificado hasta que se detecten uno o más archivos de

configuración.

Los archivos de configuración por sistema son para el sistema en el que se está ejecutando Mercurial. Las opciones en estos archivos se aplican a todos los comandos de Mercurial ejecutados por cualquier usuario en cualquier directorio. Las opciones en estos archivos anulan las opciones por

instalación.

Mercurial viene con alguna configuración predeterminada. Los archivos de configuración predeterminados se instalan con Mercurial y se sobrescribirán en las actualizaciones. Los archivos de configuración predeterminados nunca deben ser editados por usuarios o administradores, pero pueden ser anulados en otros archivos de configuración. Hasta ahora el directorio solo contiene configuración de herramientas de fusión, pero los empaquetadores también pueden colocar otra configuración predeterminada

SINTAXI

S

Un archivo de configuración consta de secciones, encabezadas por un [sección] encabezado y seguido de entradas de nombre = valor (a veces llamadas claves de configu

ración): 
[spam]
eggs=ham
green=
eggs

Cada línea contiene una entrada. Si las líneas que siguen están indentadas, se tratan como continuaciones de esa entrada. Se elimina el espacio en blanco inicial de los valores. Se omiten las líneas vacías. Las líneas que comienzan con # o ; se ignoran y pueden usarse para proporcionar

comentarios.

Las claves de configuración pueden establecerse varias veces, en cuyo caso Mercurial utilizará el valor que se configuró por última vez. Como

ejemplo: 
[spam]
eggs=large
ham=serrano
eggs=small

Esto establecería la clave de configuración llamada eggs a small

.

También es posible definir una sección varias veces. Una sección puede redefinirse en el mismo archivo y/o en diferentes archivos de configuración. Por

ejemplo: 
[foo]
eggs=large
ham=serrano
eggs=small
[bar]
eggs=ham
green=
   eggs
[foo]
ham=prosciutto
eggs=medium
bread=toasted

Esto establecería las claves de configuración eggs, ham, y bread de la sección foo a medium, prosciutto, y toasted, respectivamente. Como puedes ver, lo único que importa es el último valor establecido para cada una de las claves de

configuración.

Si una clave de configuración se establece varias veces en diferentes archivos de configuración, el valor final dependerá del orden en el que se lean los diferentes archivos de configuración, con la configuración de las rutas anteriores anulando a las posteriores como se describe en la sección Archivos

anterior.

Una línea de la forma %include archivo incluirá archivo en el archivo de configuración actual. La inclusión es recursiva, lo que significa que los archivos incluidos pueden incluir otros archivos. Los nombres de archivo son relativos al archivo de configuración en el que %include/b> directive se encuentra. Las variables de entorno y las construcciones ~user se expanden en el archivo. Esto le permite hacer algo

como: 
%include ~/.hgrc.d/$HOST.
rc

para incluir un archivo de configuración diferente en cada computadora que

use.

Una línea con %unset nombre eliminará nombre de la sección actual, si se ha establecido

previamente.

Los valores son cadenas de texto de formato libre, listas de cadenas de texto o valores booleanos. Los valores booleanos se pueden establecer en true usando cualquiera de "1", "yes", "true" u "on" y en false usando "0", "no", "false" u "off" (todos sin distinción entre mayúsculas y minúsculas)

.

Los valores de lista se separan por espacios en blanco o comas, excepto cuando los valores se colocan entre comillas

dobles: 
allow_read = "John Doe, PhD", brian,
betty

Las comillas se pueden escapar anteponiéndoles una barra invertida. Solo las comillas al comienzo de una palabra se consideran como comillas (por ejemplo, foo"bar baz es la lista de foo"bar y ba

z)
.

Los alias le permiten definir sus propios comandos en términos de otros comandos (o alias), incluyendo opcionalmente argumentos. Los argumentos posicionales en la forma de $1, $2, etc. en la definición del alias son expandidos por Mercurial antes de la ejecución. Las definiciones de alias consisten en líneas de la

Un alias puede comenzar con un signo de exclamación (!) para hacerlo un alias de shell. Un alias de shell se ejecuta con el shell y le permitirá ejecutar comandos arbitrarios. Como

Los argumentos no coincidentes se eliminan. $0 se expande al nombre del alias y $@ se expande a todos los argumentos separados por un espacio. shell.

Se pueden ejecutar múltiples hooks para la misma acción añadiendo un sufijo a la acción. Se puede anular un hook de todo el sitio cambiando su valor o estableciéndolo en una cadena vacía. Se pueden priorizar los hooks añadiendo un prefijo de priority. al nombre del hook en una nueva línea y estableciendo la prioridad. La prioridad predeterminada es

0.

Ejemplo .hg/hg

rc: 
[hooks]
# actualizar el directorio de trabajo después de añadir cambiosets
changegroup.update = hg update
# no usar el hook de todo el sitio
incoming =
incoming.email = /my/email/hook
incoming.autobuild = /my/build/hook
# forzar que el hook autobuild se ejecute antes que otros hooks incoming
priority.incoming.autobuild = 1
###  controlar la configuración de HGPLAIN al ejecutar el hook autobuild
# HGPLAIN siempre establecido (predeterminado desde Mercurial 5.7)
incoming.autobuild:run-with-plain = yes
# HGPLAIN nunca establecido
incoming.autobuild:run-with-plain = no
# HGPLAIN heredado del entorno (predeterminado antes de Mercurial 5.7)
incoming.autobuild:run-with-plain =
auto

hostsecurity

This section allows defining security settings on a per-host basis.

ciphers

A list of allowed SSL/TLS ciphers. This is a comma-separated list of cipher names. See openssl(1) for a list of cipher names and ciphers(5) for format details.

See also: https://www.openssl.org/docs/manmaster/apps/ciphers.html#CIPHER-LIST-FORMAT.

This setting is for advanced users only. Setting to incorrect values can significantly lower connection security or decrease performance. You have been warned.

This option requires Python 2.7.

minimumprotocol

Defines the minimum channel encryption protocol to use in the client.

By default, the highest version of TLS supported by both client and server is used.

Allowed values are: tls1.0, tls1.1, tls1.2, tls1.3.

Depending on the version of Python being used, not all of these values may be available. See hg debuginstall for the values supported by the current installation.

When running a Python that supports modern TLS versions, the default is tls1.2. tls1.0 and tls1.1 can still be used to allow TLS 1.0 or TLS 1.1 respectively, if supported by Python. However, this weakens security and should only be used as a feature of last resort if a server does not support TLS 1.2+.

Options in the [hostsecurity] section can have the form hostname:setting. This allows multiple settings to be defined on a per-host basis.

The following per-host settings can be defined.

ciphers

This behaves like ciphers as described above except it only applies to the host on which it is defined.

fingerprints

A list of hashes of the DER encoded peer/remote certificate. Values have the form algorithm:fingerprint. e.g. sha256:c3ab8ff13720e8ad9047dd39466b3c8974e592c2fa383d4a3960714caef0c4f2. In addition, colons (:) can appear in the fingerprint part.

The following algorithms/prefixes are supported: sha1, sha256, sha512.

Use of sha256 or sha512 is preferred.

If a fingerprint is specified, the CA chain is not validated for this host and Mercurial will require the remote certificate to match one of the fingerprints specified. This means if the server updates its certificate, Mercurial will abort until a new fingerprint is defined. This can provide stronger security than traditional CA-based validation at the expense of convenience.

This option takes precedence over verifycertsfile.

minimumprotocol

This behaves like minimumprotocol as described above except it only applies to the host on which it is defined.

verifycertsfile

Path to file a containing a list of PEM encoded certificates used to verify the server certificate. Environment variables and ~user constructs are expanded in the filename.

The server certificate or the certificate's certificate authority (CA) must match a certificate from this file or certificate verification will fail and connections to the server will be refused.

If defined, only certificates provided by this file will be used: web.cacerts and any system/default certificates will not be used.

This option has no effect if the per-host fingerprints option is set.

The format of the file is as follows:

-----BEGIN CERTIFICATE-----
... (certificate in base64 PEM encoding) ...
-----END CERTIFICATE-----
-----BEGIN CERTIFICATE-----
... (certificate in base64 PEM encoding) ...
-----END CERTIFICATE-----

For example:

[hostsecurity]
hg.example.com:fingerprints = sha256:c3ab8ff13720e8ad9047dd39466b3c8974e592c2fa383d4a3960714caef0c4f2
hg2.example.com:fingerprints = sha1:914f1aff87249c09b6859b88b1906d30756491ca, sha1:fc:e2:8d:d9:51:cd:cb:c1:4d:18:6b:b7:44:8d:49:72:57:e6:cd:33
hg3.example.com:fingerprints = sha256:9a:b0:dc:e2:75:ad:8a:b7:84:58:e5:1f:07:32:f1:87:e6:bd:24:22:af:b7:ce:8e:9c:b4:10:cf:b9:f4:0e:d2
foo.example.com:verifycertsfile = /etc/ssl/trusted-ca-certs.pem

To change the default minimum protocol version to TLS 1.2 but to allow TLS 1.1 when connecting to hg.example.com:

[hostsecurity]
minimumprotocol = tls1.2
hg.example.com:minimumprotocol = tls1.1

Controls behavior when an ignored file on disk has the same name as a tracked file in the changeset being merged or updated to, and has different contents. Options are abort, warn and ignore. With abort, abort on such files. With warn, warn on such files and back them up as .orig. With ignore, don't print a warning and back them up as .orig. (default: abort)

checkunknown

Controls behavior when an unknown file that isn't ignored has the same name as a tracked file in the changeset being merged or updated to, and has different contents. Similar to merge.checkignored, except for files that are not ignored. (default: abort)

on-failure

When set to continue (the default), the merge process attempts to merge all unresolved files using the merge chosen tool, regardless of whether previous file merge attempts during the process succeeded or not. Setting this to prompt will prompt after any merge failure continue or halt the merge process. Setting this to halt will automatically halt the merge process on any merge tool failure. The merge process can be restarted by using the resolve command. When a merge is halted, the repository is left in a normal unresolved merge state. (default: continue)

strict-capability-check

Whether capabilities of internal merge tools are checked strictly or not, while examining rules to decide merge tool to be used. (default: False)

merge-patterns

This section specifies merge tools to associate with particular file patterns. Tools matched here will take precedence over the default merge tool. Patterns are globs by default, rooted at the repository root.

Example:

[merge-patterns]
**.c = kdiff3
**.jpg = myimgmerge

    CONFIG

    Mercurial uses a configuration file, typically located at ~/.hgrc or .hg/hgrc in the repository, to customize its behavior.

    This page describes the configuration options.

    [ui]

    Options for the user interface.

    abort-on-error

    If set to true, Mercurial will abort immediately if it encounters an error, rather than attempting to continue and potentially causing more corruption. This is enabled by default.

    changeset-sort

    Specifies the default ordering of changesets in output. Valid values are: date, reverse-date, topic, phase. The default is date.

    clone-bundle-pref

    A comma-separated list of bundle types to prefer when cloning. Mercurial will try to fetch bundles of the listed types in order. If none are found, it falls back to the default behavior.

    Example: clone-bundle-pref = zstd,lzma

    clone-bundle-pref-force

    If set to true, Mercurial will only use bundles specified in clone-bundle-pref when cloning. If no matching bundles are found, the clone will fail.

    commitsort

    Specifies the default ordering of commits in the output of commands like hg log. Valid values are: date, reverse-date, author, reverse-author, committer, reverse-committer, files, reverse-files.

    The default is date.

    datefield

    Which date field to use for sorting and display purposes. Valid values are author, committer, and date (which defaults to committer if svn is used, and author otherwise). Default is date.

    diffstat

    If set to true, the hg diff command will show a summary of changes (number of files changed, lines added/deleted) after the diff output.

    editdoespush

    If set to true, saving changes to a file in hg edit will trigger a push. This is disabled by default.

    email

    Email address to use for the author field when no email address is available. Default is empty.

    fixollis

    If set to true, Mercurial will attempt to fix "ollis" (the name for invalid revisions in the revlog) when they are encountered. This may potentially corrupt the repository, so use with caution.

    graphnodetype

    Specify the node type used for graphing. Possible values are flat, compact, and full. The default is compact.

    ignorewrap

    If set to true, Mercurial will not wrap long lines in output. This is disabled by default.

    legacy-compat

    If set to true, Mercurial will try to maintain compatibility with older versions of Mercurial. This may disable some newer features or change default behavior. Use with caution.

    logshortest

    If set to true, the output of hg log will use the shortest unique revision hashes.

    makedirs

    If set to true, Mercurial will create parent directories as needed when creating files or directories.

    mergestat

    If set to true, the hg merge command will show a summary of changes after the merge.

    mirror

    If set to true, Mercurial will operate in mirror mode. In this mode, operations that modify the repository history (like amend, rebase, etc.) are disabled.

    mirror-action

    Defines the behavior when Mercurial is asked to perform an action that would modify history in mirror mode. Possible values are abort (default) or ignore.

    mirror-push

    If set to true, Mercurial will perform a push after successful clone or pull operations in mirror mode.

    mirror-pull

    If set to true, Mercurial will perform a pull after successful clone operations in mirror mode.

    multi-line

    If set to true, Mercurial will attempt to display diffs and other multi-line output in a more readable format. This is enabled by default.

    open-browser

    If set to true, Mercurial will attempt to open a web browser to display the repository history. This is disabled by default.

    pager

    Specifies the pager command to use for displaying long output. If set to true, the system's default pager will be used. If set to false, no pager will be used. You can also specify a custom pager command, e.g., pager = less -R.

    pager-auto

    If set to true, Mercurial will automatically use a pager for commands that produce long output, unless the output is being redirected to a file or pipe. This is enabled by default.

    password-command

    A command to execute to retrieve passwords. The command should print the password to standard output. This is useful for integrating with password managers.

    pre-close-bundles

    A comma-separated list of bundle types to consider for pre-closing. This is mainly used for optimization when dealing with large repositories.

    push-after-pull

    If set to true, Mercurial will automatically perform a push after a successful pull operation. This is disabled by default.

    pushkey

    Specifies the key to use for push operations. This is useful when working with multiple remotes.

    quiet

    If set to true, Mercurial will suppress most output, only showing errors and warnings. This is equivalent to using the -q or --quiet option on the command line.

    recursive

    If set to true, Mercurial will operate recursively on subrepositories. This is enabled by default.

    report-untrusted

    If set to true, Mercurial will report untrusted extensions that are being loaded. This is disabled by default.

    show-changeset-ids

    If set to true, Mercurial will display the full changeset hash in output. This is disabled by default.

    show-graph

    If set to true, Mercurial will display a text-based graph of the repository history in commands like hg log. This is disabled by default.

    show-menu

    If set to true, Mercurial will display a menu of available commands when the help command is invoked without arguments. This is enabled by default.

    show-status

    If set to true, Mercurial will display the status of files (modified, added, removed) in the repository at the beginning of most operations. This is enabled by default.

    status-width

    The maximum width of the status indicator in the output of commands like hg status. Default is 1.

    subrepository-prefetch

    If set to true, Mercurial will prefetch changesets for subrepositories before performing an operation on the parent repository. This can speed up operations but may consume more bandwidth.

    subrepossync

    Controls the synchronization of subrepositories. Possible values are: off (do not sync), conservative (only update subrepositories that are explicitly listed in .hg/hgsubstate), and true (update all subrepositories). Default is conservative.

    text-wrap

    If set to true, Mercurial will wrap long lines of text in output to fit the terminal width. This is enabled by default.

    timeout

    The timeout in seconds for network operations. Default is no timeout.

    tinytempdir

    If set to true, Mercurial will use a more compact temporary directory structure, which can be beneficial on systems with limited disk space or slow I/O.

    traceback

    If set to true, Mercurial will display a full traceback when an error occurs. This is useful for debugging. Default is false.

    verbose

    If set to true, Mercurial will provide more detailed output. This is equivalent to using the -v or --verbose option on the command line.

    web-browser

    Specifies the command to use to open a web browser. For example, on Linux you might use `xdg-open`, and on macOS `open`.

    wrap-lines

    Deprecated. Use text-wrap instead.

    wrap-width

    Deprecated. Use textwidth instead.
