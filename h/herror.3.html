NOTA

S

Las funciones gethostbyname() y gethostbyaddr() pueden devolver punteros a datos estáticos, que pueden ser sobrescritos por llamadas posteriores. Copiar el struct hostent no es suficiente, ya que contiene punteros; se requiere una copia

profunda.

En la implementación original de BSD, el argumento size de gethostbyname() era un int. El estándar SUSv2 es defectuoso y declara que el argumento size de gethostbyaddr() es de tipo size_t. (Eso es incorrecto, porque tiene que ser int, y size_t no lo es. POSIX.1-2001 lo hace socklen_t, lo cual está bien.) Véase también accept(

2).

El prototipo de BSD para gethostbyaddr() usa const char * para el primer

argumento.

Extensión System

V/POSIX

POSIX requiere la llamada gethostent(), que debería devolver la siguiente entrada en la base de datos de hosts. Al usar DNS/BIND esto no tiene mucho sentido, pero puede ser razonable si la base de datos de hosts es un archivo que se puede leer línea por línea. En muchos sistemas, una rutina con este nombre lee del archivo /etc/hosts. Puede estar disponible solo cuando la biblioteca se compiló sin soporte de DNS. La versión de glibc ignorará las entradas ipv6. Esta función no es reentrante, y glibc añade una versión reentrante gethoste

nt_
r().

Extensiones

GNU

glibc2 también tiene un gethostbyname2() que funciona como gethostbyname(), pero permite especificar la familia de direcciones a la que debe pertenecer la

dirección.

glibc2 también tiene versiones reentrantes gethostent_r(), gethostbyaddr_r(), gethostbyname_r(), y gethostbyname2_r(). El llamante proporciona una estructura hostent ret que se rellenará en caso de éxito, y un búfer de trabajo temporal buf de tamaño bufsize. Después de la llamada, result apuntará al resultado en caso de éxito. En caso de error o si no se encuentra ninguna entrada result será NULL. Las funciones devuelven 0 en caso de éxito y un número de error distinto de cero en caso de fallo. Además de los errores devueltos por las versiones no reentrantes de estas funciones, si buf es demasiado pequeño, las funciones devolverán ERANGE, y la llamada debería reintentarse con un búfer más grande. La variable global h_errno no se modifica, pero se pasa la dirección de una variable en la que almacenar los números de error en h_er
