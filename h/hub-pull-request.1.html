NOMBRE

hub-pull-request - Crear una solicitud de extracción (Pull Request) de GitHub.

SINOPSIS

hub pull-request [-focpd] [-b BASE] [-h HEAD] [-r REVISORES ] [-a ASIGNADOS] [-M HITOS] [-l ETIQUETAS]
hub pull-request -m MENSAJE [--edit]
hub pull-request -F ARCHIVO [--edit]
hub pull-request -i INCIDENCIA

OPCIONES

-f, --force

Omite la comprobación de commits no enviados.

-m, --message MENSAJE

El texto hasta la primera línea en blanco en MENSAJE se trata como el título de la solicitud de extracción, y el resto se utiliza como descripción de la solicitud de extracción en formato Markdown.

Cuando se pasan múltiples --message, sus valores se concatenan con una línea en blanco entre ellos.

Cuando no se proporcionan ni --message ni --file, se abrirá un editor de texto para escribir el título y la descripción.

--no-edit

Usa el mensaje del primer commit de la rama como título y descripción de la solicitud de extracción sin abrir un editor de texto.

-F, --file ARCHIVO

Lee el título y la descripción de la solicitud de extracción desde ARCHIVO. Pasa "-" para leer desde la entrada estándar en su lugar. Consulta --message para ver las reglas de formato.

-e, --edit

Abre el título y la descripción de la solicitud de extracción en un editor de texto antes de enviarlo. Esto se puede usar en combinación con --message o --file.

-i, --issue INCIDENCIA

Convierte la INCIDENCIA (referenciada por su número) en una solicitud de extracción.

Solo puedes convertir incidencias escritas por ti o sobre las cuales tengas derechos de administrador. En la mayoría de los flujos de trabajo, no es necesario convertir incidencias en solicitudes de extracción; simplemente puedes referenciar la incidencia original en el cuerpo de la nueva solicitud de extracción.

-o, --browse

Abre la nueva solicitud de extracción en un navegador web.

-c, --copy

Copia la URL de la nueva solicitud de extracción al portapapeles en lugar de imprimirla.

-p, --push

Envía la rama actual a HEAD antes de crear la solicitud de extracción.

-b, --base BASE

La rama base en el formato "[PROPIETARIO:]RAMA". Por defecto, es la rama predeterminada del repositorio remoto (generalmente "master").

Consulta la sección "CONVENCIONES" de hub(1) para obtener más información sobre cómo hub selecciona los valores predeterminados en caso de múltiples remotos de git.

-h, --head HEAD

La rama principal (head) en el formato "[PROPIETARIO:]RAMA". Por defecto, es la rama actualmente seleccionada.

-r, --reviewer USUARIOS

Una lista separada por comas (sin espacios alrededor de la coma) de identificadores de GitHub para solicitar una revisión.

-a, --assign USUARIOS

Una lista separada por comas (sin espacios alrededor de la coma) de identificadores de GitHub a los que asignar esta solicitud de extracción.

-M, --milestone NOMBRE

El nombre del hito a añadir a esta solicitud de extracción. Pasar el número del hito está obsoleto.

-l, --labels ETIQUETAS

Una lista separada por comas (sin espacios alrededor de la coma) de etiquetas para añadir a esta solicitud de extracción. Las etiquetas se crearán si no existen.

-d, --draft

Crea la solicitud de extracción como un borrador.

--no-maintainer-edits

Al crear una solicitud de extracción desde un fork, esto impide que los mantenedores del proyecto puedan hacer push a la rama principal (head) de este fork. Las ediciones de mantenedores están permitidas por defecto.

EJEMPLOS

$ hub pull-request
[ abre un editor de texto para escribir título y mensaje ]
[ crea una solicitud de extracción para la rama actual ]
$ hub pull-request --base PROPIETARIO:master --head MIUSUARIO:mi-rama
[ crea una solicitud de extracción con ramas base y principal explícitas ]
$ hub pull-request --browse -m "Mi título"
[ crea una solicitud de extracción con el título dado y la abre en un navegador ]
$ hub pull-request -F - --edit < ruta/a/plantilla-mensaje.md
[ edita aún más el título y el mensaje recibido de la entrada estándar ]

CONFIGURACIÓN

HUB_RETRY_TIMEOUT

El tiempo máximo para seguir reintentando después de un HTTP 422 en --push (por defecto: 9).
