Descripción Detallada

Las plataformas con memoria heterogénea requieren formas de decidir si un búfer debe asignarse en memoria 'rápida' (como HBM), memoria 'normal' (DDR) o incluso memoria 'lenta' pero de gran capacidad (memoria no volátil). Estos nodos de memoria se denominan 'Destinos' (Targets) mientras que la CPU que accede a ellos se denomina 'Iniciador' (Initiator). El rendimiento del acceso depende de su localidad (plataformas NUMA) así como del rendimiento intrínseco de los destinos (plataformas heterogéneas).

Los siguientes atributos describen el rendimiento de los accesos a memoria desde un Iniciador a un Destino de memoria, por ejemplo, su latencia o ancho de banda. Los iniciadores que realizan estos accesos a memoria suelen ser algunas PUs o Cores (descritos como un conjunto de CPUs). Por lo tanto, un Core puede elegir dónde asignar un búfer de memoria comparando los atributos de diferentes nodos de memoria de destino cercanos.

También hay algunos atributos que son a nivel de sistema. Su valor no depende de un iniciador específico que realice un acceso. La Capacidad del nodo de memoria es un ejemplo de tal atributo sin iniciador.

Una forma de usar esta API es comenzar con un conjunto de CPUs que describa los Cores en los que está enlazado un programa. El mejor nodo NUMA de destino para asignar memoria en este programa en estos Cores se puede obtener pasando este conjunto de CPUs como iniciador a hwloc_memattr_get_best_target() con el atributo de memoria relevante. Por ejemplo, si el código está limitado por latencia, use el atributo de Latencia.

Un enfoque más flexible consiste en obtener la lista de nodos NUMA locales pasando este conjunto de CPUs a hwloc_get_local_numanode_objs(). Los valores de los atributos para estos nodos, si los hay, se pueden obtener con hwloc_memattr_get_value() y compararse manualmente con los criterios deseados.

Los atributos de memoria también se utilizan internamente para construir Niveles de Memoria (Memory Tiers) que proporcionan una forma sencilla de distinguir nodos NUMA de diferentes tipos, como se explica en Memoria Heterogénea.

Además de los niveles, hwloc define un conjunto de nodos 'predeterminados' desde donde se deben realizar las asignaciones de memoria normales (ver hwloc_topology_get_default_nodeset()). Esto también es útil para dividir la máquina en un conjunto de dominios NUMA que no se superponen, por ejemplo, para enlazar tareas por dominio.

Ver también

Un ejemplo está disponible en doc/examples/memory-attributes.c en el árbol de fuentes.

Nota

La API también admite objetos específicos como iniciadores, pero actualmente hwloc no los utiliza internamente. Los usuarios pueden, por ejemplo, utilizarlos para proporcionar valores de rendimiento personalizados para los accesos a memoria del host realizados por GPUs.

La interfaz también acepta destinos que no son nodos NUMA.

Documentación de alias de tipo

typedef unsigned hwloc_memattr_id_t

Un identificador de atributo de memoria. hwloc predefine algunos atributos de uso común en hwloc_memattr_id_e. Luego, se pueden registrar dinámicamente otros personalizados con hwloc_memattr_register(); se les asignarán identificadores inmediatamente después de los predefinidos. Consulte Gestión de atributos de memoria para obtener más información sobre los identificadores de atributos existentes.

Documentación de tipo de enumeración

enum hwloc_local_numanode_flag_e

Indicadores para seleccionar nodos NUMA de destino.

Enumerador

HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY
Selecciona nodos NUMA cuya localidad sea mayor que el conjunto de CPUs dado. Por ejemplo, si se da una única PU (o su conjunto de CPUs) en initiator, selecciona todos los nodos cercanos al paquete que contiene esta PU.
HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY
Selecciona nodos NUMA cuya localidad sea menor que el conjunto de CPUs dado. Por ejemplo, si se da un paquete (o su conjunto de CPUs) en initiator, también selecciona nodos que solo están conectados a la mitad de ese paquete.
HWLOC_LOCAL_NUMANODE_FLAG_INTERSECT_LOCALITY
Selecciona nodos NUMA cuya localidad interseca el conjunto de CPUs dado. Esto incluye localidades mayores y menores, así como localidades que están parcialmente incluidas. Por ejemplo, si la localidad es un núcleo de ambos paquetes, un nodo NUMA local a un paquete no es ni mayor ni menor que esta localidad, pero la interseca.
HWLOC_LOCAL_NUMANODE_FLAG_ALL
Selecciona todos los nodos NUMA en la topología. El iniciador initiator se ignora.

enum hwloc_memattr_id_e

IDs de atributos de memoria predefinidos. Ver hwloc_memattr_id_t para la definición genérica de IDs para atributos predefinidos o personalizados.

Enumerador

HWLOC_MEMATTR_ID_CAPACITY
La "Capacidad" se devuelve en bytes (atributo local_memory en objetos). Los mejores nodos de capacidad son nodos con mayor capacidad.

No se involucra ningún iniciador al consultar este atributo. Los flags de atributo correspondientes son HWLOC_MEMATTR_FLAG_HIGHER_FIRST.

Los valores de capacidad no pueden modificarse usando hwloc_memattr_set_value().

HWLOC_MEMATTR_ID_LOCALITY
La "Localidad" se devuelve como el número de PUs en esa localidad (p. ej. el peso de su cpuset). Los mejores nodos de localidad son nodos con menor localidad (nodos que son locales a muy pocos PUs). Los nodos con localidad pobre son nodos con mayor localidad (nodos que son locales a la máquina completa).

No se involucra ningún iniciador al consultar este atributo. Los flags de atributo correspondientes son HWLOC_MEMATTR_FLAG_HIGHER_FIRST.

Los valores de localidad no pueden modificarse usando hwloc_memattr_set_value().

HWLOC_MEMATTR_ID_BANDWIDTH
El "Ancho de banda" se devuelve en MiB/s, tal como se ve desde la ubicación del iniciador dada. Los mejores nodos de ancho de banda son nodos con mayor ancho de banda.

Los flags de atributo correspondientes son HWLOC_MEMATTR_FLAG_HIGHER_FIRST y HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

Este es el ancho de banda promedio para accesos de lectura y escritura. Si la plataforma proporciona anchos de banda individuales de lectura y escritura pero no un valor promedio explícito, hwloc calcula y devuelve el promedio.

HWLOC_MEMATTR_ID_READ_BANDWIDTH
El "Ancho de banda de lectura" se devuelve en MiB/s, tal como se ve desde la ubicación del iniciador dada. Los mejores nodos de ancho de banda son nodos con mayor ancho de banda.

Los flags de atributo correspondientes son HWLOC_MEMATTR_FLAG_HIGHER_FIRST y HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

HWLOC_MEMATTR_ID_WRITE_BANDWIDTH
El "Ancho de banda de escritura" se devuelve en MiB/s, tal como se ve desde la ubicación del iniciador dada. Los mejores nodos de ancho de banda son nodos con mayor ancho de banda.

Los flags de atributo correspondientes son HWLOC_MEMATTR_FLAG_HIGHER_FIRST y HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

HWLOC_MEMATTR_ID_LATENCY
La "Latencia" se devuelve en nanosegundos, tal como se ve desde la ubicación del iniciador dada. Los mejores nodos de latencia son nodos con menor latencia.

Los flags de atributo correspondientes son HWLOC_MEMATTR_FLAG_LOWER_FIRST y HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

Esta es la latencia promedio para accesos de lectura y escritura. Si la plataforma proporciona latencias individuales de lectura y escritura pero no un valor promedio explícito, hwloc calcula y devuelve el promedio.

HWLOC_MEMATTR_ID_READ_LATENCY
La "Latencia de lectura" se devuelve en nanosegundos, tal como se ve desde la ubicación del iniciador dada. Los mejores nodos de latencia son nodos con menor latencia.

Los flags de atributo correspondientes son HWLOC_MEMATTR_FLAG_LOWER_FIRST y HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

HWLOC_MEMATTR_ID_WRITE_LATENCY
La "Latencia de escritura" se devuelve en nanosegundos, tal como se ve desde la ubicación del iniciador dada. Los mejores nodos de latencia son nodos con menor latencia.

Los flags de atributo correspondientes son HWLOC_MEMATTR_FLAG_LOWER_FIRST y HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

int hwloc_get_local_numanode_objs (hwloc_topology_t topology, struct hwloc_location * location, unsigned * nr, hwloc_obj_t * nodes, unsigned long flags)

Devuelve un array de nodos NUMA locales. Por defecto solo selecciona los nodos NUMA cuya localidad es exactamente la ubicación dada. Se pueden seleccionar más nodos si se proporcionan flags adicionales como un conjunto unido con OR de hwloc_local_numanode_flag_e.

Si location se da como un objeto explícito, se usa su conjunto de CPU para encontrar nodos NUMA con la localidad correspondiente. Si el objeto no tiene un conjunto de CPU (p. ej. un objeto E/S), se usa el padre de CPU (donde el objeto E/S está conectado).

En la entrada, nr apunta al número de nodos que pueden almacenarse en el array nodes . En la salida, nr se cambiará al número de nodos almacenados, o al número de nodos que se habrían almacenado si hubiera espacio suficiente.

Devuelve

0 en caso de éxito o -1 en caso de error.

Nota

Algunos de estos nodos NUMA pueden no tener ningún valor de atributo de memoria y por lo tanto no ser reportados como objetivos reales en otras funciones.

El número de nodos NUMA en la topología (obtenido con hwloc_bitmap_weight() en el nodeset del objeto raíz) puede usarse para allocar el array nodes .

Cuando se da el conjunto de CPU de un objeto como localidad, por ejemplo un Paquete, y cuando los flags contienen tanto HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY como HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY, el array devuelto corresponde al nodeset de ese objeto.
