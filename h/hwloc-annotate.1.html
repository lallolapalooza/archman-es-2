DESCRIPCIÓ

N

hwloc-annotate carga una topología desde un archivo XML, añade algunas anotaciones y exporta la topología resultante a otro archivo XML. Los archivos de entrada y salida pueden ser el

mismo.

La anotación puede ser atributos de información de cadena. Esto se especifica con el modo

:
info <nombre>
<valor>
Especifica un nuevo atributo de información de cadena cuyo nombre es nombre y cuyo valor es valo
r.
subtype
<subtipo>
Especifica que el atributo de subtipo del objeto debe ser ahora subtipo. Si se proporciona una cadena vacía, el subtipo se
elimina.
size
<tamaño>
Especifica el tamaño de una caché o un nodo NUMA. El valor puede tener el sufijo kB, KiB, MB, MiB, GB, GiB,
etc.
misc
<nombre>
Especifica un nuevo nombre de objeto
Misc.
memattr <nombre>
<ﬂags>
Registrar un nuevo atributo de memoria cuyo nombre es nombre y cuyas flags son flags. La ubicación se ignora en este modo.

Las flags pueden darse como valores numéricos o como una lista separada por comas de nombres de flags que se pasan a hwloc_memattr_register(). Esos nombres pueden ser subcadenas de los nombres reales de las flags, siempre que uno solo coincida. Por ejemplo, un valor de 1 (o superior) significa que los valores más al

tos se consideran los me
jores para este atributo.
memattr <nombre> <iniciador>
<valor>
Establecer el atributo de memoria (cuyo nombre es nombre) desde el iniciador iniciador (ya sea un objeto o un conjunto de CPU) hacia el nodo NUMA de destino ubicación al valor valor.

Si este atributo no requiere iniciadores específicos, el iniciador se

ignora.

Los nombres de atributos estándar son Capacity, Locality, Bandwidth y Latency. Todos los atributos existentes en la topología de entrada pueden listarse

con


$ lstopo --memattrs -i

entrada.
xml
cpukind <cpuset> <eficiencia> <flags> [<nombreinfo> <valorinfo>
]
Especifica el tipo de CPU para las Unidades de Procesamiento (PUs) listadas en el cpuset dado. La ubicación se ignora en este modo.

La eficiencia es un valor de eficiencia abstracto que se usará para ordenar los tipos. Debe ser -1 si es

desconocido.

Las flags deben ser 0 por

ahora.

Si nombreinfo y valorinfo se proporcionan y no están vacíos, se añaden como atributos de información a este tipo de

CPU.

Consulte la función h

wloc_cpukinds_register
() para más detalles.
distances <archivo> [<flags>
]
Especifica nuevas distancias que se añadirán a la topología usando las especificaciones en <archivo>. Las flags opcionales (0 a menos que se especifique) corresponden a las flags dadas a la función hwloc_distances_set(). La ubicación se ignora en este modo.

La primera línea real del archivo apuntado debe ser un entero que represente un tipo de distancias como se define en hwloc/distances.h. La segunda línea es el número de objetos involucrados en las distancias. Las siguientes líneas contienen un objeto cada una. Las siguientes líneas contienen un valor de distancia cada una, o se puede dar una sola línea con una combinación entera de formato x*y o x*y*z. Una línea opcional antes de todas las demás puede empezar con nombre= para especificar el nombre de la estructura de distancias,

si lo
hay.
distances-transform <nombre>
links
Transformar una estructura de distancias de ancho de banda llamada <nombre> en enlaces. Consulte la documentación de HWLOC_DISTANCES_TRANSFORM_LINKS en hwloc/distances.h para más
detalles.
distances-transform <nombre> merge-switch-po
rts
Cuando los conmutadores aparecen en la matriz como puertos diferentes, fusionar todos ellos en un solo puerto para mayor claridad. Esto actualmente solo se aplica a la matriz NVLinkBandwidth entre GPUs NVIDIA. Consulte la documentación de HWLOC_DISTANCES_TRANSFORM_MERGE_SWITCH_PORTS en hwloc/distances.h para más
detalles.
distances-transform <nombre> transitive-clos
ure
Si los objetos están conectados a través de un conmutador, aplicar un cierre transitivo para informar del ancho de banda a través de ese conmutador. Esto actualmente solo se aplica a la matriz NVLinkBandwidth entre GPUs NVIDIA. El ancho de banda entre todos los pares de GPUs se expondrá en lugar de los anchos de banda entre GPUs individuales y puertos NVSwitch individuales. Consulte la documentación de HWLOC_DISTANCES_TRANSFORM_TRANSITIVE_CLOSURE en hwloc/distances.h para más
detalles.
distances-transform <nombre> remove-obj
<obj>
Eliminar el objeto dado de la estructura de distancias llamada <nombre>
.
distances-transform <nombre> replace-objs <tipoantiguo>
<tiponuevo>
Reemplazar objetos de tipo <tipoantiguo> en la estructura de distancias llamada <nombre> con objetos de tipo <tiponuevo> con la misma localidad. Si <tipoantiguo> o <tiponuevo> no son tipos de objeto, se asume que son subtipos de dispositivos del sistema operativo, p. ej. "NVML" u "OpenCL". Consulte la documentación de hwloc_get_obj_with_same_locality() en hwloc/helper.h para más detalles.

Si <tiponuevo> es "NULL", los

objetos se eliminan d
e la estructura de distancias.
no
ne
No se añade ninguna anotación
nueva. Esto es útil al borra
r atributos existentes.

Las anotaciones pueden añadirse a un objeto específico en la topología, a todos ellos, o a todos de un tipo dado. Esto se especifica con la ubicación (véase también EJEMPLOS más abajo). Pueden verse afectadas múltiples ubicaciones si se especifican entre --. Los objetos pueden especificarse como tuplas de ubicación, como se explica en hwloc(7). Sin embargo, no se aceptan máscaras de bits hexadeculares ya que pueden corresponder a múltiples

objetos.

NOTA: Las anotaciones existentes pueden listarse con

hwloc-info.

NOTA: Se recomienda encarecidamente que lea el hwloc(7) antesvea la página antes de leer esta página del manual.

EJEMPLO

S

El funcionamiento de hwloc-annotate se describe mejor mediante varios

ejemplos.

Añadir un atributo info a todos los objetos Core y

PU:


$ hwloc-annotate input.xml output.xml -- Core:all PU:all -- info infoname

infovalue

Añadir solo a todos los objetos

Core:


$ hwloc-annotate input.xml output.xml Core:all info infoname

infovalue

Añadir un atributo info a los dispositivos del SO #2 y

#3:


$ hwloc-annotate input.xml output.xml os:2-3 info infoname

infovalue

Cambiar los objetos package a verde con texto rojo en la salida gráfica de

lstopo:


$ hwloc-annotate topo.xml topo.xml package:all info lstopoStyle "Background=#00ff00;Text=#ff0000"
$ lstopo -i topo.

xml

Añadir un objeto Misc llamado "foobar" bajo el objeto raíz de la topología y modificar el XML de entrada

directamente:


$ hwloc-annotate

file.xml file.xml
root misc foobar

Ejemplos con atributos de

memoria

Establecer el atributo de memoria de latencia a 123 nanosegundos desde las PUs en el primer paquete hasta el primer nodo

NUMA:


$ hwloc-annotate topo.xml topo.xml numanode:0 memattr Latency $(hwloc-calc package:0)

123

Registrar un atributo de memoria MyApplicationPerformance (con flags que especifican que requiere un iniciador y reporta valores más altos primero) y establecer su valor para el iniciador CPU-set 0x11 al nodo NUMA #2 a

2345:


$ hwloc-annotate topo.xml topo.xml ignored memattr MyApplicationPerformance need_init,higher
$ hwloc-annotate topo.xml topo.xml numanode:2 memattr MyApplicationPerformance 0x11

2345

Para aclarar que el nodo NUMA #0 es DDR mientras que el nodo NUMA #1 es

HBM:


$ hwloc-annotate topo.xml topo.xml numa:0 subtype DDR
$ hwloc-annotate t

opo.xml topo.xml
numa:1 subtype HBM

CPU

Especificar que PU 0-3 y PU 4-7 son de diferentes tipos, y que el último es más

eficiente:


$ hwloc-annotate topo.xml topo.xml dummy cpukind 0x0f 0 0 CoreType Small
$ hwloc-annotate topo.x

distancias

$ hwloc-annotate topo.xml topo.xml -- dummy -- distances-transform NUMALatency remove-obj numa:
