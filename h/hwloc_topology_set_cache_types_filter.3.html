Descripción Detallada

Varias funciones pueden llamarse opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo debe realizarse la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

Documentación del Tipo de Enumeración

enum hwloc_topology_flags_e

Banderas que deben establecerse en un contexto de topología antes de la carga. Las banderas deben pasarse a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detectar todo el sistema, ignorar reservas, incluir objetos no permitidos. Recopilar todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignorar Cgroup/Cpusets de Linux y recopilar todos los procesadores y nodos de memoria. Sin embargo, las UPs y los nodos NUMA fuera de línea todavía son ignorados.

Cuando esta bandera no está establecida, las UPs y los nodos NUMA que no están permitidos no se añaden a la topología. Los objetos padre (paquete, núcleo, caché, etc.) se añaden solo si alguno de sus hijos está permitido. Todas las UPs y los nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al cpuset y nodeset del objeto raíz.

Cuando esta bandera está establecida, los conjuntos reales de UPs y nodos NUMA permitidos son dados por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el cpuset y nodeset del objeto raíz.

Si la topología actual se exporta a XML y se vuelve a importar más tarde, esta bandera debe establecerse de nuevo en la topología reimportada para que los recursos no permitidos también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asumir que el backend seleccionado proporciona la topología del sistema en el que nos estamos ejecutando. Esto fuerza a hwloc_topology_is_thissystem() a devolver 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología del sistema en el que nos estamos ejecutando, incluso si no es el backend específico del OS sino el backend XML, por ejemplo. Esto significa hacer que las funciones de enlace realmente llamen a las llamadas de sistema específicas del OS y realmente hagan el enlace, mientras que el backend XML de otro modo proporcionaría hooks vacíos que solo devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto puede usarse por razones de eficiencia para primero detectar la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero teniendo aún así las funciones de enlace realmente haciendo el enlace.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtener el conjunto de recursos permitidos del sistema operativo local incluso si la topología fue cargada desde XML o una descripción sintética. Si la topología fue cargada desde XML o desde una cadena sintética, restringirla aplicando las restricciones del proceso actual como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (p. ej., por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Esta bandera se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecida, ya que la topología cargada debe coincidir con la máquina subyacente de donde se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES resultaría en el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importar soporte desde la topología importada. Al importar una topología XML de una máquina remota, el enlace está deshabilitado por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Este deshabilitado también se marca poniendo ceros en los bits de características soportadas correspondientes reportados por hwloc_topology_get_support().

La bandera HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT realmente importa los bits de soporte desde la máquina remota. También establece la bandera imported_support en el array de la struct hwloc_topology_misc_support . Si el XML importado no contenía ninguna información de soporte (el hwloc exportador es demasiado antiguo), esta bandera no se establece.

Nótese que estas características soportadas solo son relevantes para la instalación de hwloc que realmente exportó la topología XML (puede variar con el sistema operativo, o con cómo se compiló hwloc).

Nótese que establecer esta bandera sin embargo no habilita el enlace para la topología de hwloc importada localmente, solo reporta lo que el hwloc remoto y la máquina soportan.

int hwloc_topology_set_cache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtro para todos los tipos de objetos de caché de CPU. Las cachés del lado de la memoria no están involucradas ya que no son cachés de CPU.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Establece los flags combinados con OR en una topología aún no cargada. Establece un conjunto de flags combinados con OR de hwloc_topology_flags_e en una topología que aún no ha sido cargada.

Si esta función se llama varias veces, la última invocación borrará y reemplazará el conjunto de flags que fue establecido previamente.

Por defecto, no se establecen flags (0).

Los flags establecidos en una topología pueden ser recuperados con hwloc_topology_get_flags().

Devuelve

0 en caso de éxito.

-1 en caso de error, por ejemplo si los flags son inválidos.

void hwloc_topology_set_userdata (hwloc_topology_t topology, const void * userdata)

Establece el puntero userdata específico de la topología. Cada topología puede almacenar un puntero de datos privados proporcionado por la aplicación. Se inicializa a NULL. hwloc nunca lo modificará.

Úselo como desee, después de hwloc_topology_init() y hasta hwloc_topolog_destroy().

Este puntero no se exporta a XML.
