DESCRIPCIÓ

N

El comando hxnormalize imprime con formato un archivo HTML o XML, y también intenta corregir pequeños errores de HTML. La salida es el

mismo archivo, pero con una longitud máxima de línea y con sang
ría opcional para indicar el nivel de anidamiento de cada línea.

OPCIONE

S

Se admiten las siguientes

opciones:
-
x
Aplica convenciones XML: los elementos vacíos se escriben con una barra al final (por ejemplo, <IMG />) y, si la entrada es HTML, cualquier ‘<’ y ‘&’ dentro de los elementos <style> y <script> se escapan como ‘&’ y ‘&’. (Se asume que la entrada es HTML a menos que la opción -X esté presente.) Implica -e
.
-
e
Siempre inserta etiquetas de cierre, incluso si HTML no las requiere (por ejemplo: </p> y </li>
).
-
X
Hace que hxnormalize asuma que la entrada es XML bien formado. No intenta inferir etiquetas HTML omitidas, no asume que elementos como <img> y <br> estén vacíos, y no trata ‘<’ y ‘&’ dentro de <style> y <script> como caracteres
normales.
-
d
Omite el DOCTYPE de la
salida.
-i sangr
ía
Establece el número de espacios para sangrar cada nivel de anidamiento. El valor predeterminado es 2. No todos los elementos causan una sangría. En general, los elementos que pueden ocurrir en un entorno de bloque se inician en una nueva línea y causan una sangría, pero los elementos en línea, como EM y SPAN, no causan una
sangría.
-l longitud-de-lí
nea
Establece la longitud máxima de las líneas. hxnormalize ajustará las líneas para que todas las líneas sean lo más largas posible, pero no más largas que esta longitud. El valor predeterminado es 72. Las palabras que sean más largas que la longitud de la línea no se dividirán, y se extenderán más allá de esta longitud. Una ‘palabra’ es una secuencia de caracteres delimitada por espacio en blanco.) El contenido de los elementos STYLE, SCRIPT y PRE no se ajustará a varias
líneas.
-
s
Omite las etiquetas <span> que no tienen ningún
atributo.
-
L
Elimina los atributos ‘lang’ y ‘xml:lang’ redundantes. (Es decir, aquellos cuyo valor es el mismo que el idioma heredado del elemento padre.
)
-c magia-de-comenta
rio
Los comentarios se colocan normalmente justo después del texto precedente. Eso es generalmente correcto para comentarios cortos, pero algunos comentarios están destinados a estar en una línea separada. magia-de-comentario es una cadena y cuando esa cadena aparece dentro de un comentario, hxnormalize emitirá una línea vacía antes de ese comentario. Por ejemplo, -c "====" se puede usar para poner todos los comentarios que contengan ‘==
==’ en una línea separada, precedida po
r una línea vacía. Por defecto, ni
ngún comentario se trata de esta manera.

ERRORE

S

La recuperación de errores para HTML incorrecto es

primitiva.

hxnormalize no omitirá una etiqueta de cierre si el espacio en blanco después de ella podría ser significativo. Por ejemplo, no eliminará el primer </p> de ‘<div><p>texto</p> <p>texto</p></div>

’.

hxnormalize actualmente solo puede recuperar archivos remotos a través de HTTP. No maneja archivos protegidos por contraseña, ni archivos cuyo contenido dependa de ‘cookies’ de

HTTP.

Al convertir de XML a HTML (opción -X sin la opción -x), cualquier par de <![CDATA[ y ‘]]>’ se elimina y las entidades de carácter & & & & y & se expanden (a ‘<’, ‘>’, ‘"’, ‘'’ y ‘&’, respectivamente), pero cualquier otra entidad de carácter no se expande. Para expandir otras entidades de carácter, canalice la entrada a través de hxunent(1)

primero.

Para limitar las líneas a un número dado de caracteres, hxnormalize rompe las líneas en espacios (o dentro de etiquetas). Algunos sistemas de escritura no usan espacios entre palabras y por lo tanto hxnormalize puede no ser capaz de romper líneas, excepto en saltos de línea ya

existentes.

Para hacer que las líneas cortas sean más largas, hxnormalize combinará las líneas y reemplazará un salto de línea por un espacio, excepto en sistemas de escritura que no pongan espacios entre palabras, donde el salto de línea se reemplaza por nada. hxnormalize actualmente solo hace esto último para japonés, chino, coreano, jemer

y tailandés. (El texto debe estar correcta
mente marcado con ‘lang’ o ‘xml:lang’.)
