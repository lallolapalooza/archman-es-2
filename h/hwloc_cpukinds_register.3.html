Descripción detallada

Las plataformas con CPUs heterogéneas pueden tener algunos núcleos con diferentes características o frecuencias. Esta API expone PUs (unidades de procesamiento) idénticas en conjuntos llamados tipos de CPU. Cada PU de la topología solo puede pertenecer a un tipo.

El número de tipos se puede obtener con hwloc_cpukinds_get_nr(). Si la plataforma es homogénea, puede haber un solo tipo con todas las PUs. Si la plataforma o el sistema operativo no exponen información sobre los núcleos de CPU, puede que no haya ningún tipo.

El índice del tipo que describe un conjunto de CPU dado (si existe, y no parcialmente) se puede obtener con hwloc_cpukinds_get_by_cpuset().

A partir del índice de un tipo, es posible recuperar información con hwloc_cpukinds_get_info(): un valor de eficiencia abstracto y una matriz de atributos de información (por ejemplo, 'CoreType' y 'FrequencyMaxMHz', véase TIPOS DE CPU).

Un valor de eficiencia mayor significa un rendimiento intrínseco mayor (y posiblemente menor eficiencia energética/de rendimiento). Los tipos con valores de eficiencia menores se clasifican primero: pasar 0 como `kind_index` a hwloc_cpukinds_get_info() devolverá información sobre el tipo de CPU con menor rendimiento pero mayor eficiencia energética. Los valores de `kind_index` más altos devolverán información sobre núcleos consumidores de energía de alto rendimiento.

Cuando están disponibles, los valores de eficiencia se recopilan del sistema operativo. Si es así, `cpukind_efficiency` se establece en la estructura `hwloc_topology_discovery_support` en la matriz. Esto está disponible actualmente en Windows 10, Mac OS X (Darwin) y en algunas plataformas Linux donde la 'capacidad' del núcleo se expone en sysfs.

Si el sistema operativo no expone las eficiencias de los núcleos nativamente, hwloc intenta calcular las eficiencias comparando los tipos de CPU utilizando frecuencias (en ARM) o tipos de núcleo y frecuencias (en otras arquitecturas). La variable de entorno HWLOC_CPUKINDS_RANKING se puede utilizar para cambiar esta heurística, véase VARIABLES DE ENTORNO.

Si hwloc no puede clasificar ningún tipo, por ejemplo, porque el sistema operativo no expone las eficiencias y las frecuencias de los núcleos, todos los tipos tendrán una eficiencia desconocida (-1) y no se indexarán/ordenarán de ninguna manera específica.

int hwloc_cpukinds_get_by_cpuset (hwloc_topology_t topology, hwloc_const_bitmap_t cpuset, unsigned long flags)

Obtiene el índice del tipo de CPU que contiene las CPUs listadas en `cpuset`. `flags` debe ser 0 por ahora.

Devuelve

El índice del tipo de CPU (entero positivo o 0) si tiene éxito.

-1 con `errno` establecido en `EXDEV` si `cpuset` solo está incluido parcialmente en algún tipo.

-1 con `errno` establecido en `ENOENT` si `cpuset` no está incluido en ningún tipo, ni siquiera parcialmente.

-1 con `errno` establecido en `EINVAL` si los parámetros no son válidos.

int hwloc_cpukinds_get_info (hwloc_topology_t topology, unsigned kind_index, hwloc_bitmap_t cpuset, int * efficiency, unsigned * nr_infos, struct hwloc_info_s ** infos, unsigned long flags)

Obtiene el conjunto de CPU e información sobre un tipo de CPU en la topología. `kind_index` identifica un tipo de CPU entre 0 y el número de tipos devuelto por hwloc_cpukinds_get_nr() menos 1.

Si no es NULL, el bitmap `cpuset` se llenará con el conjunto de PUs de este tipo.

El entero al que apunta `efficiency`, si no es NULL, se llenará con la clasificación de este tipo de CPU en términos de eficiencia (ver arriba). Varía de 0 al número de tipos (como informa hwloc_cpukinds_get_nr()) menos 1.

Los tipos con menor eficiencia se informan primero.

Si hay un solo tipo en la topología, su eficiencia es 0. Si la eficiencia de algunos tipos de núcleos es desconocida, la eficiencia de todos los tipos se establece en -1, y los tipos se informan sin ningún orden específico.

La matriz de atributos de información (por ejemplo, 'CoreType', 'FrequencyMaxMHz' o 'FrequencyBaseMHz', véase TIPOS DE CPU) y su longitud se devuelven en `infos` o `nr_infos`. La matriz pertenece a la topología, no debe liberarse ni modificarse.

Si `nr_infos` o `infos` son NULL, no se devuelve ninguna información.

`flags` debe ser 0 por ahora.

Devuelve

0 si tiene éxito.

-1 con `errno` establecido en `ENOENT` si `kind_index` no coincide con ningún tipo de CPU.

-1 con `errno` establecido en `EINVAL` si los parámetros no son válidos.

int hwloc_cpukinds_register (hwloc_topology_t topology, hwloc_bitmap_t cpuset, int forced_efficiency, unsigned nr_infos, struct hwloc_info_s * infos, unsigned long flags)

Registra un tipo de CPU en la topología. Marca las PUs listadas en `cpuset` como del mismo tipo con respecto a los atributos dados.

`forced_efficiency` debería ser -1 si es desconocido. De lo contrario, es un valor de eficiencia abstracto para forzar la clasificación de todos los tipos si todos tienen eficiencias válidas (y diferentes).

La matriz `infos` de tamaño `nr_infos` se puede utilizar para proporcionar nombres y valores de información que describen este tipo de PUs.

`flags` debe ser 0 por ahora.

Los parámetros `cpuset` e `infos` se duplicarán internamente, el llamador es responsable de liberarlos.

Si `cpuset` se superpone con algunos tipos existentes, estos podrían modificarse o dividirse.
