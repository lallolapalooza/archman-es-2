int hwloc_bitmap_compare(hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los mapas de bits bitmap1 y bitmap2 en orden lexicográfico. Comparación lexicográfica de mapas de bits, comenzando por sus índices más altos. Compara primero los índices más altos, luego los segundos, etc. El mapa de bits vacío se considera menor que cualquier otro.

Devuelve

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

0 si los mapas de bits son iguales (contrariamente a hwloc_bitmap_compare_first()).

Por ejemplo, comparar los mapas de bits binarios 0011 y 0110 devuelve -1 (por lo tanto, 0011 se considera menor que 0110). Comparar 00101 y 01010 también devuelve -1.

Nota

Esto es diferente del inexistente hwloc_bitmap_compare_last() que solo compararía el índice más alto de cada mapa de bits.

int hwloc_bitmap_compare_first(hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los mapas de bits bitmap1 y bitmap2 usando su índice más bajo. Un mapa de bits se considera menor si su bit menos significativo es menor. El mapa de bits vacío se considera mayor que cualquier otro (porque su bit menos significativo no existe).

Devuelve

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

Por ejemplo, comparar los mapas de bits binarios 0011 y 0110 devuelve -1 (por lo tanto, 0011 se considera menor que 0110) porque el bit menos significativo de 0011 (0001) es menor que el bit menos significativo de 0110 (0010). Comparar 01001 y 00110 también devolvería -1 por la misma razón.

Devuelve

0 si los mapas de bits se consideran iguales, incluso si no son estrictamente iguales. Solo necesitan tener el mismo bit menos significativo. Por ejemplo, comparar los mapas de bits binarios 0010 y 0110 devuelve 0 porque tienen el mismo bit menos significativo.

DESCRIPTION

These functions manipulate bitmaps. Bitmaps are used in hwloc to represent sets of objects, primarily CPU PUs or memory nodes, but they can be used for any object type.

Bitmaps are manipulated by index. For example, cpu PUs are indexed starting from 0. Memory nodes are also indexed starting from 0. The index of an object can be retrieved using hwloc_get_obj_index_by_type().

The functions provided here manipulate these indices. They are organized into several groups:

Bitmap creation and destruction:

See hwloc_bitmap_alloc().

Bitmap inspection:

See hwloc_bitmap_isincluded().

Bitmap modification:

See hwloc_bitmap_set().

Bitmap comparisons:

See hwloc_bitmap_cmp().

Bitmap merging and differencing:

See hwloc_bitmap_or().

Bitmap conversion to/from strings:

See hwloc_bitmap_snprintf().

Bitmap conversion to/from unsigned longs:

See hwloc_bitmap_to_ulong().

Bitmap weight:

See hwloc_bitmap_weight().

Or bitmaps bitmap1 and bitmap2 and store the result in bitmap res. res can be the same as bitmap1 or bitmap2

Add index id in bitmap bitmap.

Replace i -th subset of bitmap bitmap with unsigned long mask.

int hwloc_bitmap_set_range (hwloc_bitmap_t bitmap, unsigned begin, int end)

Add indexes from begin to end in bitmap bitmap. If end is -1, the range is infinite.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Keep a single index among those set in bitmap bitmap. May be useful before binding so that the process does not have a chance of migrating between multiple processors in the original mask. Instead of running the task on any PU inside the given CPU set, the operating system scheduler will be forced to run it on a single of these PUs. It avoids a migration overhead and cache-line ping-pongs between PUs.

Note

This function is NOT meant to distribute multiple processes within a single CPU set. It always return the same single bit when called multiple times on the same input set. hwloc_distrib() may be used for generating CPU sets to distribute multiple tasks below a single multi-PU object.

This function cannot be applied to an object set directly. It should be applied to a copy (which may be obtained with hwloc_bitmap_dup()).

int hwloc_bitmap_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Stringify a bitmap in the default hwloc format. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.

Print the bits set inside a bitmap as a comma-separated list of hexadecimal 32-bit blocks. A bitmap containing bits 1, 33, 34, and all from 64 to 95 is printed as '0xffffffff,0x00000006,0x00000002'.

Up to buflen characters may be written in buffer buf.

If buflen is 0, buf may safely be NULL.

Returns

the number of characters that were actually written if not truncating, or that would have been written (not including the ending \0).

-1 on error.

int hwloc_bitmap_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Parse a bitmap string as the default hwloc format and stores it in bitmap bitmap. Note that if the bitmap is a CPU or nodeset, the input string must contain physical indexes.

The input string should be a comma-separared list of hexadecimal 32-bit blocks. String '0xffffffff,0x6,0x2' is parsed as a bitmap containing all bits between 64 and 95, and bits 33, 34 and 1.

Returns

0 on success, -1 on error.

int hwloc_bitmap_taskset_asprintf (char ** strp, hwloc_const_bitmap_t bitmap)

Stringify a bitmap into a newly allocated taskset-specific string. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.

The taskset program manipulates bitmap strings that contain a single (possible very long) hexadecimal number starting with 0x. A bitmap containing bits 1, 33, 34, and all from 64 to 95 is printed as '0xffffffff0000000600000002'.

Returns

the number of characters that were written (not including the ending \0).

-1 on error, for instance with errno set to ENOMEM on failure to allocate the output string.

int hwloc_bitmap_taskset_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Stringify a bitmap in the taskset-specific format. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.

The taskset program manipulates bitmap strings that contain a single (possible very long) hexadecimal number starting with 0x. A bitmap containing bits 1, 33, 34, and all from 64 to 95 is printed as '0xffffffff0000000600000002'.

Up to buflen characters may be written in buffer buf.

If buflen is 0, buf may safely be NULL.

Returns

the number of characters that were actually written if not truncating, or that would have been written (not including the ending \0).

-1 on error.

int hwloc_bitmap_taskset_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Parse a taskset-specific bitmap string and stores it in bitmap bitmap. Note that if the bitmap is a CPU or nodeset, the input string must contain physical indexes.

The taskset program manipulates bitmap strings that contain a single (possible very long) hexadecimal number starting with 0x. String '0xffffffff0000000600000002' is parsed as a bitmap containing all bits between 64 and 95, and bits 33, 34 and 1.

Returns

0 on success, -1 on error.
