hsearch(3) Manual de Funciones de Biblioteca hsearch(3)

NOMBRE

hcreate, hdestroy, hsearch, hcreate_r, hdestroy_r, hsearch_r - gestión de tablas hash

BIBLIOTECA

Biblioteca C estándar (libc,-lc)

SINOPSIS

#include <search.h>
int hcreate(size_t nel);
void hdestroy(void);
ENTRY *hsearch(ENTRY item, ACTION action);
#define _GNU_SOURCE         /* Vea feature_test_macros(7) */
#include <search.h>
int hcreate_r(size_t nel, struct hsearch_data *htab);
void hdestroy_r(struct hsearch_data *htab);
int hsearch_r(ENTRY item, ACTION action, ENTRY **retval,
              struct hsearch_data *htab);

DESCRIPCIÓN

Las tres funciones hcreate(), hsearch(), y hdestroy() permiten al llamador crear y gestionar una tabla de búsqueda hash que contiene entradas que consisten en una clave (una cadena de caracteres) y los datos asociados. Usando estas funciones, solo se puede usar una tabla hash a la vez.

Las tres funciones hcreate_r(), hsearch_r(), hdestroy_r() son versiones reentrantes que permiten a un programa usar más de una tabla de búsqueda hash al mismo tiempo. El último argumento, htab, apunta a una estructura que describe la tabla sobre la cual la función debe operar. El programador debe tratar esta estructura como opaca (es decir, no intente acceder o modificar directamente los campos de esta estructura).

Primero se debe crear una tabla hash usando hcreate(). El argumento nel especifica el número máximo de entradas en la tabla. (Este máximo no puede cambiarse después, así que elígalo sabiamente.) La implementación puede ajustar este valor hacia arriba para mejorar el rendimiento de la tabla hash resultante.

La función hcreate_r() realiza la misma tarea que hcreate(), pero para la tabla descrita por la estructura *htab. La estructura a la que apunta htab debe estar a cero antes de la primera llamada a hcreate_r().

La función hdestroy() libera la memoria ocupada por la tabla hash que fue creada por hcreate(). Después de llamar a hdestroy(), se puede crear una nueva tabla hash usando hcreate(). La función hdestroy_r() realiza la tarea análoga para una tabla hash descrita por *htab, que fue creada previamente usando hcreate_r().

La función hsearch() busca en la tabla hash un elemento con la misma clave que item (donde "la misma" se determina usando strcmp(3)), y si es exitosa devuelve un puntero al mismo.

El argumento item es de tipo ENTRY, que está definido en <search.h> de la siguiente manera:


typedef struct entry {
    char *key;
    void *data;
} ENTRY;

El campo key apunta a una cadena de caracteres terminada en nulo que es la clave de búsqueda. El campo data apunta a los datos que están asociados con esa clave.

El argumento action determina lo que hace hsearch() después de una búsqueda fallida. Este argumento debe tener o bien el valor ENTER, lo que significa insertar una copia de item (y devolver un puntero a la nueva entrada de la tabla hash como resultado de la función), o el valor FIND, lo que significa que se debe devolver NULL. (Si action es FIND, entonces data se ignora.)

La función hsearch_r() es como hsearch() pero opera en la tabla hash descrita por *htab. La función hsearch_r() difiere de hsearch() en que un puntero al elemento encontrado se devuelve en *retval, en lugar de como el resultado de la función.

VALOR DE RETORNO

hcreate() y hcreate_r() devuelven un valor distinto de cero en caso de éxito. Devuelven 0 en caso de error, con errno establecido para indicar el error.

En caso de éxito, hsearch() devuelve un puntero a una entrada en la tabla hash. hsearch() devuelve NULL en caso de error, es decir, si action es ENTER y la tabla hash está llena, o action es FIND y item no se puede encontrar en la tabla hash. hsearch_r() devuelve un valor distinto de cero en caso de éxito, y 0 en caso de error. En caso de error, estas dos funciones establecen errno para indicar el error.

ERRORES

hcreate_r() y hdestroy_r() pueden fallar por las siguientes razones:

EINVAL
htab es NULL.

hsearch() y hsearch_r() pueden fallar por las siguientes razones:

ENOMEM
action era ENTER, key no se encontró en la tabla, y no había espacio en la tabla para añadir una nueva entrada.
ESRCH
action era FIND, y key no se encontró en la tabla.

POSIX.1 solo especifica el error ENOMEM .

NOTAS

Las implementaciones de tablas hash suelen ser más eficientes cuando la tabla contiene suficiente espacio libre para minimizar las colisiones. Típicamente, esto significa que nel debería ser al menos un 25% mayor que el número máximo de elementos que el llamador espera almacenar en la tabla.

Las funciones hdestroy() y hdestroy_r() no liberan los búfers a los que apuntan los elementos key y data de las entradas de la tabla hash. (No pueden hacer esto porque no saben si estos búfers fueron asignados dinámicamente.) Si estos búfers necesitan ser liberados (quizás porque el programa está creando y destruyendo tablas hash repetidamente, en lugar de crear una sola tabla cuya vida útil coincida con la del programa), entonces el programa debe mantener estructuras de datos de registro que le permitan liberarlos.

ERRORES CONOCIDOS

SVr4 y POSIX.1-2001 especifican que action es significativo solo para búsquedas fallidas, de modo que un ENTER no debería hacer nada para una búsqueda exitosa. En libc y glibc (antes de glibc 2.3), la implementación viola la especificación, actualizando data para la key dada en este caso.

Se pueden añadir entradas individuales a la tabla hash, pero no se pueden eliminar.

EJEMPLOS

El siguiente programa inserta 24 elementos en una tabla hash y luego imprime algunos de ellos.

#include <search.h>
#include <stdio.h>
#include <stdlib.h>
static char *data[] = { "alpha", "bravo", "charlie", "delta",
     "echo", "foxtrot", "golf", "hotel", "india", "juliet",
     "kilo", "lima", "mike", "november", "oscar", "papa",
     "quebec", "romeo", "sierra", "tango", "uniform",
     "victor", "whisky", "x-ray", "yankee", "zulu"
};
int
main(void)
{
    ENTRY e;
    ENTRY *ep;
    hcreate(30);
    for (size_t i = 0; i < 24; i++) {
        e.key = data[i];
        /* data is just an integer, instead of a
           pointer to something */
        e.data = (void *) i;
        ep = hsearch(e, ENTER);
        /* there should be no failures */
        if (ep == NULL) {
            fprintf(stderr, "entry failed\n");
            exit(EXIT_FAILURE);
        }
    }
    for (size_t i = 22; i < 26; i++) {
        /* print two entries from the table, and
           show that two are not in the table */
        e.key = data[i];
        ep = hsearch(e, FIND);
        printf("%9.9s -> %9.9s:%d\n", e.key,
               ep ? ep->key : "NULL", ep ? (int) ep->data : 0);
    }
    hdestroy();
    exit(EXIT_SUCCESS);
}
