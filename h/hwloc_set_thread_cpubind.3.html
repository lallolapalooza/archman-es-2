Descripción detallada

Algunos sistemas operativos solo admiten la vinculación de hilos o procesos a una única PU. Otros permiten la vinculación a conjuntos más grandes, como Núcleos o Paquetes completos, o incluso conjuntos aleatorios de PUs individuales. En tales sistemas operativos, el programador es libre de ejecutar la tarea en una de estas PUs, luego migrarla a otra PU, etc. A menudo es útil llamar a hwloc_bitmap_singlify() en el conjunto de CPU de destino antes de pasarlo a la función de vinculación para evitar estas costosas migraciones. Consulte la documentación de hwloc_bitmap_singlify() para obtener detalles.

Algunos sistemas operativos no proporcionan todos los mecanismos admitidos por hwloc para vincular procesos, hilos, etc. hwloc_topology_get_support() se puede utilizar para consultar el soporte real de vinculación de CPU en el sistema operativo actualmente en uso.

Cuando la operación de vinculación solicitada no está disponible y se pasó el indicador HWLOC_CPUBIND_STRICT, la función devuelve -1. errno se establece en ENOSYS cuando no es posible vincular el tipo de objeto solicitado (procesos/hilos). errno se establece en EXDEV cuando el cpuset solicitado no se puede aplicar (por ejemplo, algunos sistemas solo permiten una CPU y otros sistemas solo permiten un nodo NUMA).

Si HWLOC_CPUBIND_STRICT no se pasó, la función también puede fallar, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de vinculación más pequeño, etc.) cuando la operación solicitada no se admite exactamente.

La versión más portable que debe preferirse sobre las demás, siempre que sea posible, es la siguiente, que simplemente vincula el programa actual, asumiendo que es monohilo:

hwloc_set_cpubind(topology, set, 0),

Si el programa puede ser multihilo, se debe preferir la siguiente para vincular solo el hilo actual:

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Algunos códigos de ejemplo están disponibles en doc/examples/ en el árbol de fuentes.

Nota

Para desvincular, simplemente llame a la función de vinculación con un cpuset completo o un cpuset igual al cpuset del sistema.

En algunos sistemas operativos, la vinculación de CPU puede tener efectos en la vinculación de memoria, consulte HWLOC_CPUBIND_NOMEMBIND

Ejecutar lstopo --top o hwloc-ps puede ser una herramienta muy conveniente para verificar cómo ocurrió realmente la vinculación.

Documentación del tipo de enumeración

enum hwloc_cpubind_flags_t

Indicadores de vinculación de Procesos/Hilos. Estas banderas de bits se pueden usar para refinar la política de vinculación.

El valor predeterminado (0) es vincular el proceso actual, asumiendo que es monohilo, de una manera no estricta. Esta es la forma más portable de vincular, ya que todos los sistemas operativos suelen proporcionarla.

Nota

No todos los sistemas admiten todos los tipos de vinculación. Consulte la sección 'Descripción detallada' de Vinculación de CPU para obtener una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_CPUBIND_PROCESS
Vincular todos los hilos del proceso actual (posiblemente) multihilo.
HWLOC_CPUBIND_THREAD
Vincular el hilo actual del proceso actual.
HWLOC_CPUBIND_STRICT
Solicitar vinculación estricta al SO. Por defecto, cuando las CPUs designadas están ocupadas mientras otras CPUs están inactivas, los sistemas operativos pueden ejecutar el hilo/proceso en esas otras CPUs en lugar de las designadas, para que progresen de todos modos. La vinculación estricta significa que el hilo/proceso _nunca_ se ejecutará en CPUs distintas de las designadas, incluso cuando estas estén ocupadas con otras tareas y otras CPUs estén inactivas.

Nota

Dependiendo del sistema operativo, la vinculación estricta puede no ser posible (por ejemplo, el SO no la implementa) o no estar permitida (por ejemplo, por razones administrativas), y la función fallará en ese caso.

Al recuperar la vinculación de un proceso, este indicador verifica si todos sus hilos tienen realmente la misma vinculación. Si no se proporciona el indicador, se acumulará la vinculación de cada hilo.

Nota

Este indicador no tiene sentido al recuperar la vinculación de un hilo.
HWLOC_CPUBIND_NOMEMBIND
Evitar cualquier efecto en la vinculación de memoria. En algunos sistemas operativos, algunas funciones de vinculación de CPU también vincularían la memoria al nodo NUMA correspondiente. A menudo no es un problema para la aplicación, pero si lo es, establecer este indicador hará que hwloc evite utilizar funciones del SO que también vincularían memoria. Sin embargo, esto reducirá el soporte de vinculación de CPU, es decir, potencialmente devolverá -1 con errno establecido en ENOSYS en algunos casos.

Este indicador solo es significativo cuando se utiliza con funciones que establecen la vinculación de CPU. Se ignora cuando se utiliza con funciones que obtienen información de vinculación de CPU.
