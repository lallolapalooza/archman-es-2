El tipo hwloc_bitmap_trepresenta un conjunto de enteros (positivos o nulos). Un mapa de bits puede ser de tamaño infinito (todos los bits están establecidos después de algún punto). Un mapa de bits puede incluso estar completo si todos los bits están establecidos. Los mapas de bits son utilizados por hwloc para conjuntos de procesadores del SO (que pueden ser en realidad hilos de hardware) como
hwloc_cpuset_t (un typedef parahwloc_bitmap_t ), o conjuntos de nodos de memoria NUMA como
hwloc_nodeset_t (también un typedef parahwloc_bitmap_t ). Estos se utilizan para los campos cpuset y nodeset en la estructura

hwloc_ob

j

, véase Conjuntos de Objetos (hwloc_cpuset_t y hwloc_nodeset_t

)

. Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del SO. Sin embargo, los usuarios normalmente no deberían construir conjuntos de CPU y nodos manualmente (por ejemplo, con hwloc_bitmap_set() ). Deberían usar más bien conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or() , etc. Por ejemplo, vincular el hilo actual a un par de

núcleos puede realizarse con:

hwloc_obj_t core1 = ... , core2 = ... ; hwloc_bitmap_t set = hwloc_bitmap_alloc(); hwloc_bitmap_or(set, core1->cpuset, core2->cpuset); hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD); hwloc_bitmap_free(set); Nota La mayoría de las funciones siguientes devuelven 0 en caso de éxito y -1 en caso de error. El caso de error habitual sería un fallo interno al realloc/extend el almacenamiento del mapa de bits

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Mantiene un solo índice entre los establecidos en el mapa de bits bitmap. Puede ser útil antes de realizar el enlace (binding) para que el proceso no tenga la posibilidad de migrar entre múltiples procesadores en la máscara original. En lugar de ejecutar la tarea en cualquier PU dentro del conjunto de CPU dado, el planificador del sistema operativo se verá obligado a ejecutarla en una sola de estas PUs. Evita una sobrecarga por migración y los "ping-pongs" de la línea de caché entre PUs.

Nota

Esta función NO está destinada a distribuir múltiples procesos dentro de un solo conjunto de CPU. Siempre devuelve el mismo bit único cuando se llama varias veces con el mismo conjunto de entrada. hwloc_distrib() puede usarse para generar conjuntos de CPU para distribuir múltiples tareas bajo un solo objeto multi-PU.

Esta función no puede aplicarse directamente a un conjunto de objetos. Debe aplicarse a una copia (que puede obtenerse con hwloc_bitmap_dup()).

La cadena de entrada debe ser una lista separada por comas de bloques hexadecimales de 32 bits. La cadena '0xffffffff,0x6,0x2' se analiza como un mapa de bits que contiene todos los bits entre 64 y 95, y los bits 33, 34 y 1.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_bitmap_taskset_asprintf (char ** strp, hwloc_const_bitmap_t bitmap)

Convierte un mapa de bits a una cadena específica de taskset recién asignada. Tenga en cuenta que si el mapa de bits es un conjunto de CPU o de nodos, contiene índices físicos.

El programa taskset manipula cadenas de mapa de bits que contienen un único número hexadecimal (posiblemente muy largo) que comienza con 0x. Un mapa de bits que contiene los bits 1, 33, 34 y todos del 64 al 95 se imprime como '0xffffffff0000000600000002'.

Devuelve

el número de caracteres que se escribieron (sin incluir el \0 final).

-1 en caso de error, por ejemplo con errno establecido a ENOMEM en caso de fallo al asignar la cadena de salida.
