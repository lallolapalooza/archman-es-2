HG(TAG) HG(TAG)

NOMBRE

hg tag - añadir una o más etiquetas para la revisión actual o dada

SINOPSIS

hg tag [-f] [-l] [-m TEXT] [-d DATE] [-u USER] [-r REV] NOMBRE...

DESCRIPCIÓN

Nombrar una revisión particular usando <nombre>.

Las etiquetas se utilizan para nombrar revisiones particulares del repositorio y son muy útiles para comparar diferentes revisiones, para volver a versiones anteriores significativas o para marcar puntos de rama como lanzamientos, etc. Modificar una etiqueta existente normalmente no está permitido; use -f/--force para anular esto.

Si no se especifica ninguna revisión, se utiliza el padre del directorio de trabajo.

Para facilitar el control de versiones, la distribución y la fusión de etiquetas, estas se almacenan como un archivo llamado ".hgtags" que se gestiona de forma similar a otros archivos del proyecto y se puede editar manualmente si es necesario. Esto también significa que el etiquetado crea un nuevo commit. El archivo ".hg/localtags" se utiliza para etiquetas locales (no compartidas entre repositorios).

Los commits de etiquetas normalmente se realizan en la cabeza de una rama. Si el padre del directorio de trabajo no es una cabeza de rama, hg tag se aborta; use -f/--force para forzar que el commit de la etiqueta se base en un changeset que no es una cabeza.

Consulte hg help dates para obtener una lista de formatos válidos para -d/--date.

Dado que los nombres de las etiquetas tienen prioridad sobre los nombres de las ramas durante la búsqueda de revisiones, se desaconseja el uso de un nombre de rama existente como nombre de etiqueta.

Devuelve 0 si tiene éxito.

OPCIONES

-f, --force
forzar etiqueta
-l, --local
hacer la etiqueta local
-r,--rev <REV>
revisión a etiquetar
--remove
eliminar una etiqueta
-e, --edit
invocar editor en mensajes de commit
-m,--message <TEXTO>
usar texto como mensaje de commit
-d,--date <FECHA>
registrar la fecha especificada como fecha de commit
-u,--user <USUARIO>
registrar el usuario especificado como committer
