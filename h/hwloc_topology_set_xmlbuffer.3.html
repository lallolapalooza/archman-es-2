Descripción Detallada

Estas funciones deben llamarse entre hwloc_topology_init() y hwloc_topology_load(). De lo contrario, devolverán -1 con errno establecido en EBUSY.

Si no se llama a ninguna de las funciones siguientes, el valor predeterminado es detectar todos los objetos de la máquina a los que el llamante tiene permiso de acceso.

Este comportamiento predeterminado también puede modificarse mediante variables de entorno si la aplicación no lo ha modificado ya. Establecer HWLOC_XMLFILE en el entorno fuerza el descubrimiento desde un archivo XML como si se hubiera llamado a hwloc_topology_set_xml(). Establecer HWLOC_SYNTHETIC fuerza una topología sintética como si se hubiera llamado a hwloc_topology_set_synthetic().

Finalmente, HWLOC_THISSYSTEM fuerza el valor de retorno de hwloc_topology_is_thissystem().

int hwloc_topology_set_components (hwloc_topology_t restrict topology, unsigned long flags, const char *restrict name)

Evitar que se utilice un componente de descubrimiento para una topología. name es el nombre del componente de descubrimiento que no debe utilizarse al cargar la topología topology. El nombre es una cadena como 'cuda'.

Para componentes con varias fases, también puede ir seguido del nombre de una fase, por ejemplo, 'linux:io'.

flags debe ser HWLOC_TOPOLOGY_COMPONENTS_FLAG_BLACKLIST.

Esto puede usarse para evitar partes costosas del proceso de descubrimiento. Por ejemplo, el descubrimiento específico de CUDA puede ser costoso y no necesario, mientras que el descubrimiento genérico de E/S podría seguir siendo útil.

Devuelve

0 en caso de éxito.

-1 en caso de error, por ejemplo, si las banderas no son válidas.

int hwloc_topology_set_pid (hwloc_topology_t restrict topology, hwloc_pid_t pid)

Cambiar el proceso desde el que se ve la topología. En algunos sistemas, los procesos pueden tener diferentes vistas de la máquina, por ejemplo, el conjunto de CPUs permitidas. Por defecto, hwloc expone la vista desde el proceso actual. Llamar a hwloc_topology_set_pid() permite hacer que exponga la topología de la máquina desde el punto de vista de otro proceso.

Nota

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

-1 se devuelve y errno se establece en ENOSYS en plataformas que no soportan esta característica.

El PID no se utilizará realmente hasta hwloc_topology_load(). Si el proceso correspondiente sale mientras tanto, hwloc ignorará el PID. Si otro proceso reutiliza el PID, se utilizará la vista de ese proceso.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_topology_set_synthetic (hwloc_topology_t restrict topology, const char *restrict description)

Habilitar topología sintética. Recopilar información de topología desde la descripción dada, una cadena separada por espacios de <tipo:número> que describe el tipo de objeto y la aridad en cada nivel. Se pueden omitir todos los tipos (cadena separada por espacios de números) para que hwloc elija todos los tipos según las topologías habituales. Consulte también las Topologías sintéticas.

Establecer la variable de entorno HWLOC_SYNTHETIC también puede dar lugar a este comportamiento.

Si description se analizó correctamente y describe una configuración de topología válida, esta función devuelve 0. De lo contrario, devuelve -1 y errno se establece en EINVAL.

Tenga en cuenta que esta función no carga realmente la información de topología; simplemente le dice a hwloc dónde cargarla. Todavía necesitará invocar hwloc_topology_load() para cargar realmente la información de topología.

Devuelve

0 en caso de éxito.

-1 con errno establecido en EINVAL si la descripción no fue válida.

Nota

Para mayor comodidad, este backend proporciona ganchos de vinculación vacíos que simplemente devuelven éxito.

En caso de éxito, el componente sintético reemplaza al componente previamente habilitado (si lo hubiera), pero la topología no se modifica realmente hasta hwloc_topology_load().

NAME

hwloc_topology_set_xmlbuffer

SYNOPSIS

#include <hwloc.h>

int hwloc_topology_set_xmlbuffer(hwloc_topology_t restrict topology, const char *restrict buffer, int size);

DESCRIPTION

Enable XML based topology using a memory buffer (instead of a file, as with hwloc_topology_set_xml()). Gather topology information from the XML memory buffer given at buffer and of length size (including an ending \0). This buffer may have been filled earlier with hwloc_topology_export_xmlbuffer() in hwloc/export.h.

Note that this function does not actually load topology information; it just tells hwloc where to load it from. You'll still need to invoke hwloc_topology_load() to actually load the topology information.

Returns

0 on success.

-1 with errno set to EINVAL on failure to read the XML buffer.

Note

See also hwloc_topology_set_userdata_import_callback() for importing application-specific object userdata.

For convenience, this backend provides empty binding hooks which just return success. To have hwloc still actually call OS-specific hooks, the HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM has to be set to assert that the loaded file is really the underlying system.

On success, the XML component replaces the previously enabled component (if any), but the topology is not actually modified until hwloc_topology_load().

If an invalid XML input file is given, the error may be reported either here or later by hwloc_topology_load() depending on the XML library used by hwloc.
