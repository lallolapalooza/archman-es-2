Descripción Detallada

Estas funciones deben llamarse entre hwloc_topology_init() y hwloc_topology_load(). De lo contrario, devolverán -1 con errno establecido en EBUSY.

Si no se llama a ninguna de las siguientes funciones, el valor predeterminado es detectar todos los objetos de la máquina a los que el llamador tiene permiso de acceso.

Este comportamiento predeterminado también puede modificarse mediante variables de entorno si la aplicación no lo ha modificado ya. Establecer HWLOC_XMLFILE en el entorno fuerza el descubrimiento a partir de un archivo XML como si se hubiese llamado a hwloc_topology_set_xml(). Establecer HWLOC_SYNTHETIC fuerza una topología sintética como si se hubiese llamado a hwloc_topology_set_synthetic().

Finalmente, HWLOC_THISSYSTEM fuerza el valor de retorno de hwloc_topology_is_thissystem().

Documentación de la función

int hwloc_topology_set_components (hwloc_topology_t restrict topology, unsigned long flags, const char *restrict name)

Evita que se utilice un componente de descubrimiento para una topología. name es el nombre del componente de descubrimiento que no debe utilizarse al cargar la topología topology. El nombre es una cadena como 'cuda'.

Para componentes con múltiples fases, también puede ir seguido del nombre de una fase, por ejemplo 'linux:io'.

flags debe ser HWLOC_TOPOLOGY_COMPONENTS_FLAG_BLACKLIST.

Esto puede utilizarse para evitar partes costosas del proceso de descubrimiento. Por ejemplo, el descubrimiento específico de CUDA puede ser costoso y no ser necesario, mientras que el descubrimiento genérico de E/S podría seguir siendo útil.

Devuelve

0 si tiene éxito.

-1 en caso de error, por ejemplo, si las banderas no son válidas.

int hwloc_topology_set_pid (hwloc_topology_t restrict topology, hwloc_pid_t pid)

Cambia desde qué proceso se ve la topología. En algunos sistemas, los procesos pueden tener diferentes vistas de la máquina, por ejemplo, el conjunto de CPU permitidas. Por defecto, hwloc expone la vista del proceso actual. Llamar a hwloc_topology_set_pid() permite hacer que exponga la topología de la máquina desde el punto de vista de otro proceso.

Nota

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

-1 se devuelve y errno se establece en ENOSYS en plataformas que no admiten esta característica.

El PID no se utilizará realmente hasta hwloc_topology_load(). Si el proceso correspondiente sale mientras tanto, hwloc ignorará el PID. Si otro proceso reutiliza el PID, se utilizará la vista de ese proceso.

Devuelve

0 si tiene éxito, -1 en caso de error.

int hwloc_topology_set_synthetic (hwloc_topology_t restrict topology, const char *restrict description)

Habilita la topología sintética. Recopila información de topología de la descripción dada, una cadena separada por espacios de <tipo:número> que describe el tipo de objeto y la aridad en cada nivel. Se pueden omitir todos los tipos (cadena separada por espacios de números) para que hwloc elija todos los tipos según las topologías habituales. Consulte también las topologías sintéticas.

Establecer la variable de entorno HWLOC_SYNTHETIC también puede dar lugar a este comportamiento.

Si description se analizó correctamente y describe una configuración de topología válida, esta función devuelve 0. De lo contrario, se devuelve -1 y errno se establece en EINVAL.

Tenga en cuenta que esta función no carga realmente la información de la topología; solo le dice a hwloc de dónde cargarla. Todavía necesitará invocar hwloc_topology_load() para cargar la información de la topología.

Devuelve

0 si tiene éxito.

-1 con errno establecido en EINVAL si la descripción era inválida.

Nota

Para mayor comodidad, este backend proporciona ganchos de enlace vacíos que simplemente devuelven éxito.

Al tener éxito, el componente sintético reemplaza al componente previamente habilitado (si lo hay), pero la topología no se modifica realmente hasta hwloc_topology_load().

int hwloc_topology_set_xml (hwloc_topology_t restrict topology, const char *restrict xmlpath)

Habilita la topología basada en archivos XML. Recopila información de topología del archivo XML proporcionado en xmlpath. Establecer la variable de entorno HWLOC_XMLFILE también puede dar lugar a este comportamiento. Este archivo puede haber sido generado anteriormente con hwloc_topology_export_xml() en hwloc/export.h, o el archivo lstopo file.xml.

Tenga en cuenta que esta función no carga realmente la información de la topología; solo le dice a hwloc de dónde cargarla. Todavía necesitará invocar hwloc_topology_load() para cargar la información de la topología.

Devuelve

0 si tiene éxito.

-1 con errno establecido en EINVAL en caso de error al leer el archivo XML .

Nota

Consulte también hwloc_topology_set_userdata_import_callback() para importar datos de usuario de objeto específicos de la aplicación.

Para mayor comodidad, este backend proporciona ganchos de enlace vacíos que simplemente devuelven éxito. Para que hwloc aún llame a ganchos específicos del sistema operativo, se debe establecer HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM para afirmar que el archivo cargado es realmente el sistema subyacente.

Al tener éxito, el componente XML reemplaza al componente previamente habilitado (si lo hay), pero la topología no se modifica realmente hasta hwloc_topology_load().
