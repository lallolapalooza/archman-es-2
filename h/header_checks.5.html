Añade la dirección especificada como destinatario BCC e inspecciona la siguiente línea de entrada. La dirección debe tener una parte local y una parte de dominio. El número de direcciones BCC que se pueden añadir está limitado únicamente por la cantidad de espacio de almacenamiento disponible.

Nota 1: la dirección BCC se añade como si se hubiera especificado con NOTIFY=NONE. El remitente no será notificado cuando la dirección BCC no sea entregable, siempre que todo el software aguas abajo implemente RFC

3461.

Nota 2: esto ignora las direcciones duplicadas (con las mismas opciones de notificación de estado de

entrega).

Esta característica está disponible en Postfix 3.0 y versiones

posteriores.

Anula la configuración del parámetro content_filter e inspecciona la siguiente línea de entrada. Después de que el mensaje se ponga en cola, envíe el mensaje completo a través del filtro de contenido externo especificado. El nombre del transporte especifica el primer campo de una definición de agente de entrega de correo en master.cf; la sintaxis de la destination de siguiente salto se describe en la página del manual del agente de entrega correspondiente. Más información sobre los filtros de contenido externos está en el archivo FILTER_README de Postfix.

Nota 1: no use sustituciones de expresiones regulares denúmero para transport o destination a menos que sepa que la información tiene un origen de

confianza.

Nota 2: esta acción anula la configuración de content_filter de main.cf y afecta a todos los destinatarios del mensaje. En el caso de que se activen múltiples acciones FILTER, solo se ejecutará la

última.

Nota 3: el propósito del comando FILTER es anular el enrutamiento de mensajes. Para anular el transport del destinatario pero no la destination de siguiente salto, especifique un destination de filtro vacío (Postfix 2.7 y posteriores), o especifique un transport:destination que entregue a través de una instancia diferente de Postfix (Postfix 2.6 y anteriores). Otras opciones son usar las características transport_maps dependientes del destinatario o sender_dependent_default_transport_maps dependientes del

remitente.

ERRORE

S

Las líneas vacías nunca coinciden, porque algunos tipos de mapas se comportan mal cuando se les da una cadena de búsqueda de longitud cero. Esta limitación puede eliminarse para las tablas de expresiones regulares en una versión

futura.

Muchas personas pasan por alto las limitaciones principales de las reglas de header y

body_checks.
  • Estas reglas operan en una cabecera lógica de mensaje o una línea de cuerpo a la vez. Una decisión tomada para una línea no se traslada a la siguiente
    • línea.
  • Si el texto en el cuerpo del mensaje está codificado (RFC 2045), entonces las reglas deben especificarse para la forma
    • codificada.
  • Del mismo modo, cuando las cabeceras de mensaje
    • están codificadas (RFC 2047), entonces las regl
as deben especificarse para la forma codificada.

Las cabeceras de mensaje añadidas por el propio demonio cleanup(8) están excluidas de la inspección. Ejemplos de tales cabeceras de mensaje son From:, To:, Message-ID:, Date

:.

Las cabeceras de mensaje eliminadas por el demonio cleanup(8) se examinarán antes de ser eliminadas. Ejemplos son: Bcc:, Content-Length:, Return

-Pat
h:.
