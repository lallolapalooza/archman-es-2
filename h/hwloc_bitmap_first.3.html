Descripción

detallada

El tipo hwloc_bitmap_t representa un conjunto de enteros (positivos o nulos). Un mapa de bits puede ser de tamaño infinito (todos los bits están establecidos después de algún punto). Un mapa de bits incluso puede estar completo si todos los bits están

establecidos.

hwloc utiliza mapas de bits para conjuntos de procesadores del SO (que pueden ser en realidad hilos de hardware) como hwloc_cpuset_t (un typedef para hwloc_bitmap_t), o conjuntos de nodos de memoria NUMA como hwloc_nodeset_t (también un typedef para hwloc_bitmap_t). Estos se utilizan para los campos cpuset y nodeset en la estructura hwloc_obj, véase Conjuntos de objetos (hwloc_cpuset_t

y hwloc_nodeset_t).

Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del SO. Sin embargo, los usuarios normalmente no deberían construir conjuntos de CPU y de nodos manualmente (p. ej. con hwloc_bitmap_set()). Más bien se deberían usar conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or(), etc. Por ejemplo, vincular el hilo actual a un par de núcleos puede realizarse

con: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

Not

a
La mayoría de las funciones siguientes devuelven 0 en caso de éxito y -1 en caso de error. El caso de error habitual sería un fallo interno al realloc/extend el almacenamiento del mapa de bits (errno se establecería en ENOMEM). Véase también Informe de errores en la API.

Hay varios ejemplos de uso de la API de mapas de bits d

isponibles en el directorio doc/examples/ del árbol de
fuentes. Las pruebas de regresión como tests/hwloc/hwlo
c_bitmap*.c también hacen un uso intensivo de esta API.

int hwloc_bitmap_from_string (hwloc_bitmap_t bitmap, const char *restrict string)

Import a bitmap from a string. The string format is a comma-separated list of hexadecimal numbers. For example, "0x1,0x2,0x4" represents bits 0, 1, and 2. "0xffffffff" represents bits 0 to 31. A range can be specified like "0x10-0x1f" for bits 16 to 31. A bitmap containing bits 1, 33, 34, and all from 64 to 95 can be represented as "0xffffffff,0x00000006,0x00000002" or "0xffffffff,0x6,0x2".

Note that if the bitmap is a CPU or nodeset, the input string must contain physical indexes.

Returns 0 on success, -1 on error.

int hwloc_bitmap_to_string (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Export a bitmap to a string. The string format is a comma-separated list of hexadecimal numbers. For example, a bitmap containing bits 1, 33, 34, and all from 64 to 95 is printed as "0xffffffff,0x00000006,0x00000002".

Note that if the bitmap is a CPU or nodeset, it contains physical indexes.

Up to buflen characters may be written in buffer buf. If buflen is 0, buf may safely be NULL.

Returns the number of characters that were actually written if not truncating, or that would have been written (not including the ending \0). -1 on error.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Keep a single index among those set in bitmap bitmap. May be useful before binding so that the process does not have a chance of migrating between multiple processors in the original mask. Instead of running the task on any PU inside the given CPU set, the operating system scheduler will be forced to run it on a single of these PUs. It avoids a migration overhead and cache-line ping-pongs between PUs.

Note

This function is NOT meant to distribute multiple processes within a single CPU set. It always return the same single bit when called multiple times on the same input set. hwloc_distrib() may be used for generating CPU sets to distribute multiple tasks below a single multi-PU object.

This function cannot be applied to an object set directly. It should be applied to a copy (which may be obtained with hwloc_bitmap_dup()).
