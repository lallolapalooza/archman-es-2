NOMBRE

hostnamectl - Controlar el nombre de host del sistema

SINOPSIS

hostnamectl [OPCIONES...] {COMANDO}

DESCRIPCIÓN

hostnamectl puede usarse para consultar y cambiar el nombre de host del sistema y configuraciones relacionadas.

systemd-hostnamed.service(8) y esta herramienta distinguen tres nombres de host diferentes: el nombre de host "bonito" de alto nivel, que podría incluir todo tipo de caracteres especiales (por ejemplo, "El Portátil de Lennart"), el nombre de host "estático", que es el nombre de host configurado por el usuario (por ejemplo, "el-portatil-de-lennart"), y el nombre de host transitorio, que es un valor de respaldo recibido de la configuración de red (por ejemplo, "nodo12345678"). Si se establece un nombre de host estático en un valor válido, entonces no se utiliza el nombre de host transitorio.

Tenga en cuenta que el nombre de host bonito tiene pocas restricciones en cuanto a los caracteres y la longitud utilizados, mientras que los nombres de host estático y transitorio están limitados a los caracteres comúnmente aceptados de los nombres de dominio de Internet, y a un máximo de 64 caracteres (esto último es una limitación de Linux).

Utilice systemd-firstboot(1) para inicializar el nombre de host del sistema para imágenes de sistema montadas (pero no iniciadas).

COMANDOS

Se entienden los siguientes comandos:

status

Muestra el nombre de host del sistema e información relacionada. Si no se especifica ningún comando, este es el predeterminado implícito.

Añadido en la versión 195.

hostname [NOMBRE]

Si no se proporciona ningún argumento, imprime el nombre de host del sistema. Si se proporciona un argumento opcional NOMBRE, el comando cambia el nombre de host del sistema a NOMBRE. Por defecto, esto alterará el nombre de host bonito, el estático y el transitorio por igual; sin embargo, si se utilizan uno o más de --static, --transient, --pretty, solo se cambian los nombres de host seleccionados. Si se está estableciendo el nombre de host bonito, y también se están estableciendo el estático o el transitorio, el nombre de host especificado se simplificará en cuanto al conjunto de caracteres utilizado antes de que se actualicen estos últimos. Esto se hace eliminando caracteres especiales y espacios. Esto garantiza que el nombre de host bonito y el estático estén siempre estrechamente relacionados, al tiempo que siguen las reglas de validez de cada nombre. Esta simplificación de la cadena del nombre de host no se realiza si solo se establecen los nombres de host transitorio y/o estático, y el nombre de host bonito se deja sin modificar.

Los nombres de host estático y transitorio deben ser cada uno una etiqueta DNS única (una cadena compuesta por caracteres en minúsculas de ASCII de 7 bits y sin espacios ni puntos, limitada al formato permitido para las etiquetas de nombres de dominio DNS), o una secuencia de tales etiquetas separadas por puntos únicos que formen un FQDN de DNS válido. El nombre de host no debe superar los 64 caracteres, lo que es una limitación de Linux (DNS permite nombres más largos).

Si el signo de interrogación "?" aparece en el nombre de host, se sustituye automáticamente por un carácter hexadecimal derivado del machine-id(5) cuando se aplica, de forma segura y determinista mediante hash criptográfico. Ejemplo: "foobar-????-????" se expandirá automáticamente a "foobar-92a9-061c" o similar, dependiendo del ID de máquina local.

Añadido en la versión 249.

icon-name [NOMBRE]

Si no se proporciona ningún argumento, imprime el nombre del icono del sistema. Si se proporciona un argumento opcional NOMBRE, el comando cambia el nombre del icono a NOMBRE. El nombre del icono es utilizado por algunas aplicaciones gráficas para visualizar este host. El nombre del icono debe seguir la Especificación de Nombres de Iconos[1].

Añadido en la versión 249.

chassis [TIPO]

Si no se proporciona ningún argumento, imprime el tipo de chasis. Si se proporciona un argumento opcional TIPO, el comando cambia el tipo de chasis a TIPO. El tipo de chasis es utilizado por algunas aplicaciones gráficas para visualizar el host o alterar la interacción del usuario. Actualmente, los siguientes tipos de chasis están definidos: "desktop", "laptop", "convertible", "server", "tablet", "handset", "watch", "embedded", así como los tipos de chasis especiales "vm" y "container" para sistemas virtualizados que carecen de un chasis físico inmediato.

Añadido en la versión 249.

deployment [ENTORNO]

Si no se proporciona ningún argumento, imprime el entorno de despliegue. Si se proporciona un argumento opcional ENTORNO, el comando cambia el entorno de despliegue a ENTORNO. El argumento ENTORNO debe ser una sola palabra sin caracteres de control. Se sugiere uno de los siguientes: "development", "integration", "staging", "production".

Añadido en la versión 249.

location [UBICACIÓN]

Si no se proporciona ningún argumento, imprime la cadena de ubicación del sistema. Si se proporciona un argumento opcional UBICACIÓN, el comando cambia la cadena de ubicación del sistema a UBICACIÓN. El argumento UBICACIÓN debe ser una cadena fácil de leer y de formato libre que describa la ubicación física del sistema, si se conoce y es aplicable. Esto puede ser tan genérico como "Berlín, Alemania" o tan específico como "Rack Izquierdo, 2º Estante".

Añadido en la versión 249.

OPCIONES

Se entienden las siguientes opciones:

--static, --transient, --pretty

Si se invoca status (o no se proporciona ningún comando explícito) y se especifica uno de estos interruptores, hostnamectl imprimirá solo ese nombre de host seleccionado.

Si se usa con hostname, solo se actualizarán los nombres de host seleccionados. Cuando se especifican más de uno de estos interruptores, se actualizarán todos los nombres de host especificados.

Añadido en la versión 195.

-H, --host=

Ejecuta la operación de forma remota. Especifique un nombre de host, o un nombre de usuario y un nombre de host separados por "@", para conectarse. Opcionalmente, el nombre de host puede ir seguido de un puerto en el que escucha ssh, separado por ":", y luego un nombre de contenedor, separado por "/", lo que se conecta directamente a un contenedor específico en la máquina host especificada. Esto utilizará SSH para comunicarse con la instancia remota del gestor de máquinas. Los nombres de contenedores se pueden enumerar con machinectl -H HOST. Coloque las direcciones IPv6 entre corchetes.

-M, --machine=

Ejecuta la operación en un contenedor local. Especifique un nombre de contenedor al que conectarse, opcionalmente precedido por un nombre de usuario con el que conectarse y un carácter "@" separador. Si se utiliza la cadena especial ".host" en lugar del nombre del contenedor, se establece una conexión con el sistema local (lo que es útil para conectarse al bus de usuario de un usuario específico: "--user --machine=lennart@.host"). Si no se utiliza la sintaxis "@", la conexión se realiza como usuario root. Si se utiliza la sintaxis "@", se puede omitir el lado izquierdo o el derecho (pero no ambos) en cuyo caso se implican el nombre de usuario local y ".host".

--no-ask-password

No solicite al usuario autenticación para operaciones privilegiadas.

-h, --help

Imprime un breve texto de ayuda y sale.

--version

Imprime una breve cadena de versión y sale.

--json=MODO

Muestra la salida en formato JSON. Espera una de las opciones: "short" (para la salida más corta posible sin espacios en blanco redundantes ni saltos de línea), "pretty" (para una versión bonita de lo mismo, con sangría y saltos de línea) o "off" (para desactivar la salida JSON, el valor predeterminado).

-j

Equivalente a --json=pretty si se ejecuta en una terminal, y --json=short en caso contrario.

ESTADO DE SALIDA

En caso de éxito, se devuelve 0; en caso contrario, se devuelve un código de error distinto de cero.
