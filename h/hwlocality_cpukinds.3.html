Cette API expose des UP identiques dans des ensembles appelés types de CPU. Chaque UP de la topologie ne peut appartenir qu'à un seul type. Le nombre de types peut être obtenu avec hwloc_cpukinds_get_nr(). Si la

ons avec

hwloc_cpukinds_get_info() : une valeur d'efficacité abstraite et un tableau d'attributs d'informations (par exemple 'CoreType' et 'FrequencyMaxMHz', voir Types de CPU). Une valeur d'efficacité plus élevée signifie des performances intrinsèques supérieure

s (et

éventuellement une moindre efficacité performance/consommation). Les types avec des valeurs d'efficacité plus faibles sont classés en premier : passer 0 comme kind_index à hwloc_cpukinds_get_info() renverra des informations sur le type de CPU aux performances plus faibles mais à l'efficacité énergétique plus élevée. Des valeurs de kind_index plus élevées renverront plutôt des informations sur des cœurs haute performance gourmands en énergie. Lorsqu'elles

sont

disponibles, les valeurs d'efficacité sont collectées depuis le système d'exploitation. Si c'est le cas, cpukind_efficiency est défini dans le tableau hwloc_topology_discovery_support [[51]]. Cela est actuellement disponible sur Windows 10, Mac OS X (Darwin) et sur certaines plateformes Linux où la 'capacity' des cœurs est exposée

dans

sysfs. Si le système d'exploitation n'expose pas nativement les efficacités des cœurs, hwloc essaie de calculer les efficacités en comparant les types de CPU à l'aide des fréquences (sur ARM), ou des types de cœurs et des fréquences (sur d'autres architectures). La variable d'environnement HWLOC_CPUKINDS_RANKING peut être utilisée pour modifier cette heu

ristique,

voir Variables d'environnement. Si hwloc échoue à classer un type, par exemple parce que le système d'exploitation n'expose ni efficacités ni fréquences des cœurs, tous les types auront uneefficacité inconnue (
