DESCRIPCIÓN DETALLADA

Las plataformas con memoria heterogénea requieren formas de decidir si un buffer debe ser asignado en memoria 'rápida' (como HBM), memoria 'normal' (DDR) o incluso memoria 'lenta' pero de gran capacidad (memoria no volátil). Estos nodos de memoria se llaman 'Objetivos' (Targets) mientras que la CPU que accede a ellos se llama el 'Iniciador' (Initiator). El rendimiento del acceso depende de su localidad (plataformas NUMA) así como del rendimiento intrínseco de los objetivos (plataformas heterogéneas).

Los siguientes atributos describen el rendimiento de los accesos a memoria desde un Iniciador a un Objetivo de memoria, por ejemplo su latencia o ancho de banda. Los Iniciadores que realizan estos accesos a memoria suelen ser algunas PU (Unidades de Procesamiento) o Núcleos (Cores) (descritos como un conjunto de CPU). Por lo tanto, un Núcleo puede elegir dónde asignar un buffer de memoria comparando los atributos de diferentes nodos de memoria cercanos.

También existen algunos atributos que son a nivel de sistema. Su valor no depende de un iniciador específico que realice un acceso. La Capacidad del nodo de memoria es un ejemplo de tal atributo sin iniciador.

Una forma de usar esta API es comenzar con un conjunto de CPU que describa los Núcleos donde está enlazado un programa. El mejor nodo NUMA objetivo para asignar memoria en este programa en estos Núcleos se puede obtener pasando este conjunto de CPU como iniciador a hwloc_memattr_get_best_target() con el atributo de memoria relevante. Por ejemplo, si el código está limitado por latencia, use el atributo de Latencia.

Un enfoque más flexible consiste en obtener la lista de nodos NUMA locales pasando este conjunto de CPU a hwloc_get_local_numanode_objs(). Los valores de atributos para estos nodos, si los hay, se pueden obtener luego con hwloc_memattr_get_value() y compararlos manualmente con los criterios deseados.

Los atributos de memoria también se utilizan internamente para construir Niveles de Memoria (Memory Tiers) que proporcionan una forma fácil de distinguir nodos NUMA de diferentes tipos, como se explica en Memoria Heterogénea.

Además de los niveles, hwloc define un conjunto de nodos 'predeterminados' desde los cuales se deben hacer las asignaciones de memoria normales (ver hwloc_topology_get_default_nodeset()). Esto también es útil para dividir la máquina en un conjunto de dominios NUMA no superpuestos, por ejemplo, para enlazar tareas por dominio.

Ver también

Hay un ejemplo disponible en doc/examples/memory-attributes.c en el árbol de fuentes.

Nota

La API también admite objetos específicos como iniciadores, pero actualmente hwloc no los utiliza internamente. Los usuarios, por ejemplo, pueden usarlos para proporcionar valores de rendimiento personalizados para los accesos a memoria del host realizados por GPUs.

La interfaz en realidad también acepta objetivos que no son nodos NUMA.

DOCUMENTACIÓN DEL TIPO DEFINIDO

typedef unsigned hwloc_memattr_id_t

Un identificador de atributo de memoria. hwloc predefine algunos atributos de uso común en hwloc_memattr_id_e. Luego se pueden registrar dinámicamente atributos personalizados con hwloc_memattr_register(), se les asignarán IDs inmediatamente después de los predefinidos. Ver Gestión de atributos de memoria para más información sobre los IDs de atributos existentes.

DOCUMENTACIÓN DEL TIPO DE ENUMERACIÓN

enum hwloc_local_numanode_flag_e

Banderas para seleccionar nodos NUMA objetivo.

Enumerador

HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY
Selecciona nodos NUMA cuya localidad sea mayor que el conjunto de CPU dado. Por ejemplo, si se proporciona una sola PU (o su conjunto de CPU) en initiator, selecciona todos los nodos cercanos al paquete que contiene esta PU.
HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY
Selecciona nodos NUMA cuya localidad sea menor que el conjunto de CPU dado. Por ejemplo, si se proporciona un paquete (o su conjunto de CPU) en initiator, también selecciona nodos que solo están conectados a la mitad de ese paquete.
HWLOC_LOCAL_NUMANODE_FLAG_INTERSECT_LOCALITY
Selecciona nodos NUMA cuya localidad se interseca con el conjunto de CPU dado. Esto incluye localidades mayores y menores, así como localidades que están parcialmente incluidas. Por ejemplo, si la localidad es un núcleo de ambos paquetes, un nodo NUMA local a un paquete no es ni mayor ni menor que esta localidad, pero se interseca con ella.
HWLOC_LOCAL_NUMANODE_FLAG_ALL
Selecciona todos los nodos NUMA en la topología. El iniciador initiator se ignora.

int hwloc_topology_get_default_nodeset (hwloc_topology_t topology, hwloc_nodeset_t nodeset, unsigned long

flags)

Devuelve el conjunto de nodos NUMA predeterminados. En máquinas con memoria heterogénea, algunos nodos NUMA se consideran los predeterminados, es decir, donde se deben hacer las asignaciones básicas. Estos son generalmente nodos

DRAM.

Otros nodos pueden estar reservados para uso específico (memoria de dispositivos de E/S, por ejemplo, memoria de GPU), pequeños pero de alto rendimiento (HBM), memoria grande pero lenta (NVM), etc. Los búferes generalmente no deben asignarse de ahí a menos que se requiera

explícitamente.

Esta función rellena nodeset con los bits de los nodos NUMA considerados predeterminados

.

Se garantiza que estos nodos tienen conjuntos de CPU no intersectantes, es decir, los núcleos pueden no tener múltiples nodos NUMA locales. Por lo tanto, esto puede usarse para iterar sobre la plataforma dividida en localidades NUMA separadas, por ejemplo, para vincular una tarea por dominio

NUMA.

Cualquier núcleo que tuviera algún nodo(s) NUMA local en la topología inicial debería aún tener uno en el nodeset predeterminado. Los casos extremos donde esto sería incorrecto consisten en plataformas asimétricas con nodos DRAM faltantes, o topologías que ya estaban restringidas a menos nodos

NUMA.

El nodeset devuelto puede pasarse a hwloc_topology_restrict() con HWLOC_RESTRICT_FLAG_BYNODESET para eliminar todos los nodos no predeterminados de la topología. La topología resultante será más fácil de usar al iterar sobre (ahora homogéneos) nodos

NUMA.

Las heurísticas para encontrar nodos predeterminados se basan en niveles de memoria y subtipos (ver Memoria Heterogénea) así como en la suposición de que los proveedores de hardware listan los nodos predeterminados primero en las tablas de

hardware.
