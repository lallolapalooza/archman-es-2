Descripción detallada

Varias funciones pueden ser llamadas opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo se debe realizar la detección, por ejemplo, para ignorar ciertos tipos de objetos, definir una topología sintética, etc.

Documentación del tipo enumerado

enum hwloc_topology_flags_e

Banderas para establecer en un contexto de topología antes de la carga. Las banderas deben proporcionarse a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detecta todo el sistema, ignora las reservas, incluye objetos no permitidos. Recopila todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignora los Cgroup/Cpusets de Linux y recopila todos los procesadores y nodos de memoria. Sin embargo, las PU y los nodos NUMA fuera de línea todavía se ignoran.

Cuando esta bandera no está establecida, las PU y los nodos NUMA que no están permitidos no se añaden a la topología. Los objetos padres (paquete, núcleo, caché, etc.) se añaden solo si algunos de sus hijos están permitidos. Todas las PU y nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al conjunto de CPU y al conjunto de nodos del objeto raíz.

Cuando esta bandera está establecida, los conjuntos reales de PU y nodos NUMA permitidos se dan por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el conjunto de CPU y el conjunto de nodos del objeto raíz.

Si la topología actual se exporta a XML y se reimporta más tarde, esta bandera debe establecerse nuevamente en la topología reimportada para que los recursos no permitidos también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asume que el backend seleccionado proporciona la topología para el sistema en el que estamos ejecutando. Esto fuerza a que hwloc_topology_is_thissystem() devuelva 1, es decir, hace que hwloc suponga que el backend seleccionado proporciona la topología para el sistema en el que estamos ejecutando, incluso si no es el backend específico del SO sino el backend XML, por ejemplo. Esto significa hacer que las funciones de enlace llamen realmente a las llamadas del sistema específicas del SO y realmente hagan el enlace, mientras que el backend XML de lo contrario proporcionaría ganchos vacíos que solo devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto se puede usar por razones de eficiencia para detectar primero la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero aún así teniendo las funciones de enlace realmente haciendo el enlace.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtiene el conjunto de recursos permitidos del sistema operativo local, incluso si la topología se cargó desde XML o desde una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restringe la topología aplicando las restricciones del proceso actual, como Linux Cgroup/Cpuset.

Esto es útil cuando la topología no se carga directamente de la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Esta bandera se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecida, ya que la topología cargada debe coincidir con la máquina subyacente de la que se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES resultaría en el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importa el soporte de la topología importada. Al importar una topología XML de una máquina remota, el enlace está deshabilitado por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Esta deshabilitación también se marca poniendo ceros en los bits correspondientes de características soportadas reportadas por hwloc_topology_get_support().

La bandera HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT en realidad importa los bits de soporte de la máquina remota. También establece la bandera imported_support en el array struct hwloc_topology_misc_support. Si el XML importado no contenía información de soporte (el exportador hwloc es demasiado antiguo), esta bandera no se establece.

Tenga en cuenta que estas características soportadas solo son relevantes para la instalación de hwloc que realmente exportó la topología XML (puede variar según el sistema operativo, o según cómo se compiló hwloc).

Tenga en cuenta que establecer esta bandera, sin embargo, no habilita el enlace para la topología hwloc importada localmente, solo informa lo que el hwloc y la máquina remotos soportan.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
No considerar los recursos fuera del enlace de CPU del proceso. Si el enlace del proceso está limitado a un subconjunto de núcleos, ignorar los otros núcleos durante el disco

No se agregan los núcleos y unidades de procesamiento que no estén incluidos en la máscara de CPU permitida del proceso.

Esta bandera es inútil si el proceso no está enlazado a un subconjunto de CPU.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
No considerar los recursos de memoria fuera del enlace de memoria del proceso. Si el enlace de memoria del proceso está limitado a un subconjunto de nodos NUMA, ignorar los otros nodos NUMA durante la detección de topología.

No se agregan los nodos NUMA que no están incluidos en el conjunto de nodos permitido del proceso.

Esta bandera es inútil si el proceso no está enlazado a un subconjunto de nodos NUMA.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
No cambiar la afinidad de CPU del proceso actual. Las funciones de enlace de CPU (como hwloc_set_cpubind_nodeset()) no cambiarán el enlace de CPU del proceso actual.

La mayoría de las aplicaciones que utilizan hwloc no cambian su propio enlace de CPU, por lo que esta opción puede ser útil para evitar comportamientos inesperados. Sin embargo, las aplicaciones que sí necesitan cambiar el enlace de CPU (por ejemplo, para lanzar subprocesos con enlaces específicos) deben deshabilitar esta bandera.

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
No detectar ni importar distancias entre nodos de memoria.

Las distancias entre nodos de memoria se utilizan para estimar el costo de acceso a memoria de diferentes nodos NUMA. Deshabilitar su detección puede reducir el tiempo de carga de la topología en sistemas grandes y sin soporte de distancias.

HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
No detectar ni importar atributos de memoria como el tipo de memoria (DDR3, DDR4, etc.) o la velocidad.

Los atributos de memoria pueden ser útiles para optimizar la asignación de memoria, pero su detección puede ser costosa. Deshabilitar su detección puede acelerar la carga de la topología.

HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
No detectar ni importar grupos de CPU (CPU kinds).

Los grupos de CPU agrupan PUs con características similares, como el mismo modelo o la misma frecuencia. Su detección puede ser útil para optimizar la planificación de tareas, pero puede ser costosa.

enum hwloc_type_filter_e

Filtros para controlar qué tipos de objetos se incluyen en la topología.

Enumerator

HWLOC_TYPE_FILTER_KEEP_ALL
Incluir todos los objetos del tipo especificado.
HWLOC_TYPE_FILTER_KEEP_NONE
Excluir todos los objetos del tipo especificado.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Incluir solo los objetos del tipo especificado que son necesarios para representar la estructura jerárquica del sistema (por ejemplo, incluir solo los niveles de caché L1, L2, L3 si están presentes).
HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Incluir solo los objetos del tipo especificado que se consideran importantes para el rendimiento o la programación (por ejemplo, incluir solo los niveles de caché L1 y L3).

Flags

Flags that can be passed to hwloc_topology_set_flags() to modify topology discovery and manipulation.

enum hwloc_topology_flags_e

Flags to be OR'ed together to control topology discovery and manipulation.

Enumerator

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
The topology context is built using the system running this program. This is the default when no XML file or other discovery source is specified. This flag enables discovery methods and checks that are only possible when running on the actual target system.
HWLOC_TOPOLOGY_FLAG_WHOLE_SYSTEM
Discover the entire system, even if the caller is not privileged enough to access all of it. For instance, on Linux, discover all cpusets and memory nodes, even if the caller is only in a restricted cgroup. This flag is ignored if the caller has full privileges anyway.
HWLOC_TOPOLOGY_FLAG_IOAPIC_HOLES
Keep IOAPIC information and report potentially unused IO interrupts as devices.
HWLOC_TOPOLOGY_FLAG_ADD_முகம்_GROUPS
Add HWLOC_OBJ_GROUP objects that group core objects. These groups are added at the same level as HWLOC_OBJ_CORE. They are named 'Group <N>' and only contain processing units that don't belong to any other specific groups.
HWLOC_TOPOLOGY_FLAG_INSTANTIATE_HOSTSIDE_BRIDGES
Also discover and instantiate bridges that are not directly attached to any local device, e.g. host bridges that are not discovered via PCI.
HWLOC_TOPOLOGY_FLAG_IGNORE_USER_OS_ONLY_DEVICES
Ignore OS devices that are not attached to any specific PCI, USB, or other device object. These often include devices like /dev/null, /dev/zero, etc. that are not tied to hardware. This is enabled by default.
HWLOC_TOPOLOGY_FLAG_GROUP_BY_L3_CACHE
Group Core objects by L3 cache. This is enabled by default.
HWLOC_TOPOLOGY_FLAG_IGNORE_ALL_PARENTS
Ignore all parent objects above the first common level. For example, if used with HWLOC_OBJ_CORE, it will ignore all objects above HWLOC_OBJ_CORE (like HWLOC_OBJ_SOCKET and HWLOC_OBJ_MACHINE).
HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
Do not consider resources outside of the process CPU binding. If the binding of the process is limited to a subset of cores, ignore the other cores during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag especially tells the x86 backend to never temporarily rebind a thread on any excluded core. This is useful on Windows because such temporary rebinding can change the process binding. Another use-case is to avoid cores that would not be able to perform the hwloc discovery anytime soon because they are busy executing some high-priority real-time tasks.

If process CPU binding is not supported, the thread CPU binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
Do not consider resources outside of the process memory binding. If the binding of the process is limited to a subset of NUMA nodes, ignore the other NUMA nodes during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag is meant to be used together with HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING when both cores and NUMA nodes should be ignored outside of the process binding.

If process memory binding is not supported, the thread memory binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Do not ever modify the process or thread binding during discovery. This flag disables all hwloc discovery steps that require a change of the process or thread binding. This currently only affects the x86 backend which gets entirely disabled.

This is useful when hwloc_topology_load() is called while the application also creates additional threads or modifies the binding.

This flag is also a strict way to make sure the process binding will not change to due thread binding changes on Windows (see HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING).

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignore distances. Ignore distance information from the operating systems (and from XML) and hence do not use distances for grouping.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignore memory attributes and tiers. Ignore memory attribues from the operating systems (and from XML) Hence also do not try to build memory tiers.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Ignore CPU Kinds. Ignore CPU kind information from the operating systems (and from XML).

enum hwloc_type_filter_e

Type filtering flags. By default, most objects are kept (HWLOC_TYPE_FILTER_KEEP_ALL). Instruction caches, memory-side caches, I/O and Misc objects are ignored by default (HWLOC_TYPE_FILTER_KEEP_NONE). Group levels are ignored unless they bring structure (HWLOC_TYPE_FILTER_KEEP_STRUCTURE).

Note that group objects are also ignored individually (without the entire level) when they do not bring structure.

Enumerator

HWLOC_TYPE_FILTER_KEEP_ALL
Keep all objects of this type. Cannot be set for HWLOC_OBJ_GROUP (groups are designed only to add more structure to the topology).
HWLOC_TYPE_FILTER_KEEP_NONE
Ignore all objects of this type. The bottom-level type HWLOC_OBJ_PU, the HWLOC_OBJ_NUMANODE type, and the top-level type HWLOC_OBJ_MACHINE may not be ignored.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Only ignore objects if their entire level does not bring any structure. Keep the entire level of objects if at least one of these objects adds structure to the topology. An object brings structure when it has multiple children and it is not the only child of its parent.

If all objects in the level are the only child of their parent, and if none of them has multiple children, the entire level is removed.

Cannot be set for I/O and Misc objects since the topology structure does not matter there.

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Only keep likely-important objects of the given type. It is only useful for I/O object types. For HWLOC_OBJ_PCI_DEVICE and HWLOC_OBJ_OS_DEVICE, it means that only objects of major/common kinds are kept (storage, network, OpenFabrics, CUDA, OpenCL, RSMI, NVML, and displays). Also, only OS devices directly attached on PCI (e.g. no USB) are reported. For HWLOC_OBJ_BRIDGE, it means that bridges are kept only if they have children.

This flag equivalent to HWLOC_TYPE_FILTER_KEEP_ALL for Normal, Memory and Misc types since they are likely important.

const struct hwloc_topology_support * hwloc_topology_get_support (hwloc_topology_t restrict topology)

Retrieve the topology support. Each flag indicates whether a feature is supported. If set to 0, the feature is not supported. If set to 1, the feature is supported, but the corresponding call may still fail in some corner cases.

These features are also listed by hwloc-info --support

The reported features are what the current topology supports on the current machine. If the topology was exported to XML from another machine and later imported here, support still describes what is supported for this imported topology after import. By default, binding will be reported as unsupported in this case (see HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM).

Topology flag HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT may be used to report the supported features of the original remote machine instead. If it was successfully imported, imported_support will be set in the struct hwloc_topology_misc_support array.

Returns

A pointer to a support structure.

Note

The function cannot return NULL.

The returned pointer should not be freed, it belongs to the hwloc library.

This function may be called before or after hwloc_topology_load() but the support structure only contains valid information after.
