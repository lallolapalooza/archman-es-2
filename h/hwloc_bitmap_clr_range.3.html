El tipo hwloc_bitmap_trepresenta un conjunto de enteros (positivos o nulos). Un mapa de bits puede ser de tamaño infinito (todos los bits están establecidos después de cierto punto). Un mapa de bits incluso puede estar completo si todos los bits están establecidos. hwloc utiliza mapas de bits para conjuntos de procesadores del SO (que en realidad pueden ser hilos de hardware) como
hwloc_cpuset_t (un typedef parahwloc_bitmap_t ), o conjuntos de nodos de memoria NUMA como
hwloc_nodeset_t (también un typedef parahwloc_bitmap_t ). Estos se utilizan para los campos cpuset y nodeset en la estructura

hwloc_ob

j

, véase Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t

)

. Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del SO. Sin embargo, los usuarios normalmente no deberían construir conjuntos de CPU y nodos manualmente (por ejemplo, con hwloc_bitmap_set() ). Deberían usar en su lugar conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or() , etc. Por ejemplo, enlazar el hilo actual a un par de

núcleos puede realizarse con:

hwloc_obj_t core1 = ... , core2 = ... ; hwloc_bitmap_t set = hwloc_bitmap_alloc(); hwloc_bitmap_or(set, core1->cpuset, core2->cpuset); hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD); hwloc_bitmap_free(set); Nota La mayoría de las funciones siguientes devuelven 0 en caso de éxito y -1 en caso de error. El caso de error habitual sería un fallo interno al reallocar/extender el almacenamiento del mapa de bits

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los mapas de bits bitmap1 y bitmap2 en orden lexicográfico. Comparación lexicográfica de mapas de bits, empezando por sus índices más altos. Compara primero los últimos índices, luego los segundos, etc. El mapa de bits vacío se considera menor que cualquier otro.

Devuelve

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

0 si los mapas de bits son iguales (a diferencia de hwloc_bitmap_compare_first()).

Por ejemplo, comparar los mapas de bits binarios 0011 y 0110 devuelve -1 (por lo tanto, 0011 se considera menor que 0110). Comparar 00101 y 01010 también devuelve -1.

Nota

Esto es diferente del inexistente hwloc_bitmap_compare_last() que solo compararía el índice más alto de cada mapa de bits.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los mapas de bits bitmap1 y bitmap2 usando su índice más bajo. Un mapa de bits se considera menor si su bit menos significativo es menor. El mapa de bits vacío se considera mayor que cualquier otro (porque su bit menos significativo no existe).

Devuelve

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

Por ejemplo, comparar los mapas de bits binarios 0011 y 0110 devuelve -1 (por lo tanto, 0011 se considera menor que 0110) porque el bit menos significativo de 0011 (0001) es menor que el bit menos significativo de 0110 (0010). Comparar 01001 y 00110 también devolvería -1 por la misma razón.

Devuelve

0 si los mapas de bits se consideran iguales, incluso si no lo son estrictamente. Solo necesitan tener el mismo bit menos significativo. Por ejemplo, comparar los mapas de bits binarios 0010 y 0110 devuelve 0 porque tienen el mismo bit menos significativo.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Mantiene un solo índice entre los establecidos en el mapa de bits bitmap. Puede ser útil antes de realizar el enlace (binding) para que el proceso no tenga la posibilidad de migrar entre múltiples procesadores en la máscara original. En lugar de ejecutar la tarea en cualquier PU dentro del conjunto de CPU dado, el planificador del sistema operativo se verá obligado a ejecutarla en una sola de estas PUs. Esto evita la sobrecarga de migración y los "ping-pongs" de la línea de caché entre PUs.

Nota

Esta función NO está destinada a distribuir múltiples procesos dentro de un solo conjunto de CPU. Siempre devuelve el mismo bit único cuando se llama varias veces con el mismo conjunto de entrada. hwloc_distrib() puede usarse para generar conjuntos de CPU para distribuir múltiples tareas bajo un solo objeto multi-PU.

Esta función no puede aplicarse directamente a un conjunto de objetos. Debe aplicarse a una copia (que puede obtenerse con hwloc_bitmap_dup()).

Calcula el 'peso' del mapa de bits bitmap (es decir, el número de índices que están en el mapa de bits).

Devuelve

el número de índices que están en el mapa de bits.

-1 si el mapa de bits está establecido infinitamente.

int hwloc_bitmap_xor (hwloc_bitmap_t res, hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Realiza la operación XOR entre los mapas de bits bitmap1 y bitmap2 y almacena el resultado en el mapa de bits res. res puede ser el mismo que bitmap1 o bitmap2

void hwloc_bitmap_zero (hwloc_bitmap_t bitmap)

Vacía el mapa de bits bitmap.
