RESUME

N

htdbm se utiliza para manipular los archivos en formato DBM que se usan para almacenar nombres de usuario y contraseñas para la autenticación b

ásica de usuarios HTTP a través de mod_authn_dbm. Consulte la documenta
ción de dbmmanage para obtener más información sobre estos archivos DBM.

S
-
b
Usar modo por lotes; es decir, obtener la contraseña de la línea de comandos en lugar de solicitarla. Esta opción debe usarse con extrema precaución, ya que la contraseña queda claramente visible en la línea de comandos. Para uso en scripts, consulte la opción -i. -

Usar hash MD5 para las contraseñas. En Windows y Netware, esta es la opción

Usar hash bcrypt para las contraseñas. Actualmente se considera muy

Este indicador solo se permite en combinación con -B (hash bcrypt). Establece el tiempo de cálculo utilizado por el algoritmo bcrypt (un valor más alto es más seguro pero más lento, predeterminado: 5, válido: 4 a

Usar hash crypt() para las contraseñas. La opción predeterminada en todas las plataformas excepto Windows y Netware. Aunque htdbm puede soportarlo en todas las plataformas, el servidor httpd no lo soporta en Windows y Netware. Este algoritmo es inseguro según los estándares
actuales.

actuales.
-
p
Usar contraseñas en texto plano. Aunque htdbm puede soportar su creación en todas las plataformas, el demonio httpd solo aceptará contraseñas en texto plano en Windows y

ERRORE

S

Se debe tener en cuenta que existen varios formatos de archivo DBM diferentes, y es muy probable que en su sistema existan bibliotecas para más de un formato. Los tres ejemplos principales son SDBM, NDBM, GNU GDBM y Berkeley/Sleepycat DB 2/3/4. Desafortunadamente, todas estas bibliotecas usan formatos de archivo diferentes, y debe asegurarse de que el formato de archivo usado por nombrearchivo sea el mismo formato que htdbm espera ver. htdbm actualmente no tiene forma de determinar qué tipo de archivo DBM está viendo. Si se usa con el formato incorrecto, simplemente no devolverá nada, o puede crear un archivo DBM diferente con un nombre distinto, o en el peor de los casos, puede corromper el archivo DBM si estaba intentando escribir en

él.

Normalmente se puede usar el programa file que se incluye con la mayoría de los sistemas

Unix para ver en qué for
mato está un archivo DBM.

ESTADO DE

SALIDA

htdbm devuelve un estado cero ("verdadero") si el nombre de usuario y la contraseña se han añadido o actualizado correctamente en el archivo DBM. htdbm devuelve 1 si encuentra algún problema al acceder a archivos, 2 si hubo un problema de sintaxis en la línea de comandos, 3 si la contraseña se introdujo interactivamente y la entrada de verificación no coincidió, 4 si su operación fue interrumpida, 5 si un valor es demasiado largo (nombre de usuario, nombre de archivo, contraseña o registro calculado final), 6 si el nombre de usuario contiene caracteres ilegales (consulte la sección de Restricciones), y 7 si el archivo no es un archi

vo de contrase
ñas DBM válido.

EJEMPLO

S 
      htdbm /usr/local/etc/apache/.htdbm-users
jsmith

Añade o modifica la contraseña del usuario jsmith. Se solicita al usuario que introduzca la contraseña. Si se ejecuta en un sistema Windows, la contraseña se hasheará usando el algoritmo MD5 modificado de Apache; de lo contrario, se usará la rutina crypt() del sistema. Si el archivo no existe, htdbm no hará nada excepto devolver un

error. 
      htdbm -c /home/doe/public_html/.htdbm
jane

Crea un nuevo archivo y almacena en él un registro para el usuario jane. Se solicita al usuario que introduzca la contraseña. Si el archivo existe y no se puede leer, o no se puede escribir, no se modifica y htdbm mostrará un mensaje y devolverá un estado de

error. 
      htdbm -mb /usr/web/.htdbm-all jones
Pwd4Steve

Cifra la contraseña de la línea de comandos (Pwd4Steve) usando el algoritmo MD5, y

la almacena en el ar
chivo especificado.

CONSIDERACIONES DE

SEGURIDAD

Los archivos de contraseñas web, como los gestionados por htdbm, no deben encontrarse dentro del espacio URI del servidor web; es decir, no deben poder ser obtenidos con un navegador. no debe estar dentro del espacio URI del servidor Web; es decir, no deben ser accesibles mediante un

navegador.

Se desaconseja el uso de la opción -b, ya que cuando se utiliza, la contraseña en texto plano aparece en la línea de

comandos.

Al utilizar el algoritmo crypt(), tenga en cuenta que solo se utilizan los primeros 8 caracteres de la contraseña para formar la clave. Si la contraseña proporcionada es más larga, los caracteres adicionales se descartarán silenciosamente

.

La opción de hash SHA no utiliza salting: para una contraseña dada, solo existe una representación con hash. Los formatos crypt() y MD5 permutan la representación anteponiendo una cadena de sal aleatoria, para dificultar los ataques de diccionario contra las

contraseñas.

Los formatos SHA y crypt() no son seguros según

los estándares
actuales.

RESTRICCIONE

S

En la plataforma Windows, las contraseñas con hash generadas con htdbm están limitadas a un máximo de 255 caracteres de longitud. Las contraseñas más largas se truncarán a 255

caracteres.

El algoritmo MD5 utilizado por htdbm es específico del software Apache; las contraseñas con hash generadas con él no serán utilizables con otros servidores

web.

Los nombres de usuario están limitados a 255 bytes y no pueden incluir el carácter :
