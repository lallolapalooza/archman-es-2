DESCRIPCIÓ

N

hut es una utilidad complementaria de línea de comandos para interactuar con sr.

ht.

Los recursos (como trabajos de compilación, tickets de tareas, conjuntos de parches de listas, repositorios git, etc.) pueden especificarse de múltiples formas: nombre, propietario y nombre, o URL completa. Por ejemplo, el repositorio hut propiedad de ~emersion en git.sr.ht puede referenciarse

mediante:
  • "hu
    • t"
  • "~emersion/h
    • ut"
  • "https://git.sr.ht/~emersion/hu
    • t
"

Además, las listas de correo pueden referenciarse por su dirección de correo

electrónico.

Los comandos de hut que leen entrada, como hut graphql o hut builds user-webhook create, leen la entrada dependiendo de si su stdin está en un terminal o

no:
•
Si stdin no está en un terminal, por ejemplo, porque stdin está redirigido desde un archivo o desde una tubería, hut lee la entra
da desd
e stdin.
•
De lo contrario, si se especifica la opción --stdin en el comando, hut lee la entra
da desd
e stdin.
•
De lo contrario, hut asume que se está ejecutando en un terminal e inicia el comando $EDITOR proporcionado por la
variable de e
ntorno para le
er la entrada.

CONFIGURACIÓ

N

Genera un nuevo token de acceso OAuth2 en meta.sr

.ht.

Al iniciarse, hut buscará un archivo en $XDG_CONFIG_HOME/hut/config. Si no está definido, $XDG_CONFIG_HOME por defecto es ~/.conf

ig/. 
instance "sr.ht" {
	access-token "<token>"
	# Como alternativa, puedes especificar un comando cuya primera línea de salida
	# se analizará como el token
	access-token-cmd pass token
	meta {
		# Puedes establecer el origen para cada servicio. Como respaldo, hut
		# construirá el origen a partir del nombre de la instancia y el servicio.
		origin "https://meta.sr.ht"
}
}

Archivo de configuración del

proyecto

El archivo de configuración del proyecto es un archivo de nivel superior llamado .hut.scfg en un repositorio, donde se pueden especificar el tracker y la lista de correo de desarrollo asociados. Estos recursos se usarán cada vez que se llame a un comando que necesite un tracker/lista de correo y no se establezca ninguno explícitamente. Además, es posible configurar que los parches contengan el nombre del repositorio en su prefijo. El comando hut git clone configurará un repositorio recién clonado para facilitar la

contribución.
