endian(3) Manual de Funciones de Biblioteca endian(3)

NOMBRE

htobe16, htole16, be16toh, le16toh, htobe32, htole32, be32toh, le32toh, htobe64, htole64, be64toh, le64toh - convertir valores entre el orden de bytes del host y el orden big-/little-endian

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <endian.h>
uint16_t htobe16(uint16_t host_16bits);
uint16_t htole16(uint16_t host_16bits);
uint16_t be16toh(uint16_t big_endian_16bits);
uint16_t le16toh(uint16_t little_endian_16bits);
uint32_t htobe32(uint32_t host_32bits);
uint32_t htole32(uint32_t host_32bits);
uint32_t be32toh(uint32_t big_endian_32bits);
uint32_t le32toh(uint32_t little_endian_32bits);
uint64_t htobe64(uint64_t host_64bits);
uint64_t htole64(uint64_t host_64bits);
uint64_t be64toh(uint64_t big_endian_64bits);
uint64_t le64toh(uint64_t little_endian_64bits);

htobe16(), htole16(), be16toh(), le16toh(), htobe32(), htole32(), be32toh(), le32toh(), htobe64(), htole64(), be64toh(), le64toh():

    En glibc hasta e incluyendo 2.19:

DESCRIPCIÓN

Estas funciones convierten la codificación de bytes de valores enteros del orden de bytes que utiliza la CPU actual (el "host"), a y desde el orden de bytes little-endian y big-endian.

El número, nn, en el nombre de cada función indica el tamaño del entero manejado por la función, ya sea de 16, 32 o 64 bits.

Las funciones con nombres de la forma "htobenn" convierten del orden de bytes del host a orden big-endian.

Las funciones con nombres de la forma "htolenn" convierten del orden de bytes del host a orden little-endian.

Las funciones con nombres de la forma "benntoh" convierten de orden big-endian a orden del host.

Las funciones con nombres de la forma "lenntoh" convierten de orden little-endian a orden del host.

VERSIÓNES

Funciones similares están presentes en BSD, donde el archivo de cabecera requerido es <sys/endian.h> en lugar de <endian.h>. Desafortunadamente, NetBSD, FreeBSD y glibc no han seguido la convención de nombres original de OpenBSD para estas funciones, en la que el componente nn siempre aparece al final del nombre de la función (por lo tanto, por ejemplo, en NetBSD, FreeBSD y glibc, el equivalente de "betoh32" de OpenBSD es "be32toh").

ESTÁNDARES

Ninguno.

HISTORIA

glibc 2.9.

Estas funciones son similares a las funciones más antiguas de la familia byteorder(3). Por ejemplo, be32toh() es idéntica a ntohl().

La ventaja de las funciones de byteorder(3) es que son funciones estándar disponibles en todos los sistemas UNIX. Por otro lado, el hecho de que fueron diseñadas para su uso en el contexto de TCP/IP significa que carecen de las variantes de 64 bits y little-endian descritas en esta página.

EJEMPLOS

El siguiente programa muestra los resultados de convertir un entero del orden de bytes del host a orden little-endian y big-endian. Dado que el orden de bytes del host es little-endian o big-endian, solo una de estas conversiones tendrá efecto. Cuando ejecutamos este programa en un sistema little-endian como x86-32, vemos lo siguiente:


$ ./a.out;
x.u32 = 0x44332211
htole32(x.u32) = 0x44332211
htobe32(x.u32) = 0x11223344

Fuente del programa

#include <endian.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
int
main(void)
{
    union {
        uint32_t u32;
        uint8_t arr[4];
    } x;
    x.arr[0] = 0x11;	/* Byte de dirección más baja */
    x.arr[1] = 0x22;
    x.arr[2] = 0x33;
    x.arr[3] = 0x44;	/* Byte de dirección más alta */
    printf("x.u32 = %#x\n", x.u32);
    printf("htole32(x.u32) = %#x\n", htole32(x.u32));
    printf("htobe32(x.u32) = %#x\n", htobe32(x.u32));
    exit(EXIT_SUCCESS);
}
