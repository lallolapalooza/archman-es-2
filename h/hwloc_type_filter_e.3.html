Descripción detallada

Varias funciones pueden llamarse opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo se debe realizar la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

Documentación de tipos de enumeración

enum hwloc_topology_flags_e

Marcas (flags) que se deben establecer en un contexto de topología antes de la carga. Las marcas se deben pasar a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerator

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detecta todo el sistema, ignora las reservas, incluye los objetos no permitidos. Recopila todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignora Cgroup/Cpusets de Linux y recopila todos los procesadores y nodos de memoria. Sin embargo, las CPU y los nodos NUMA fuera de línea todavía se ignoran.

Cuando esta marca no está establecida, las CPU y los nodos NUMA que no están permitidos no se agregan a la topología. Los objetos padre (paquete, núcleo, caché, etc.) se agregan solo si algunos de sus hijos están permitidos. Todas las CPU y nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al conjunto de CPU y al conjunto de nodos del objeto raíz.

Cuando esta marca está establecida, los conjuntos reales de CPU y nodos NUMA permitidos se obtienen de hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el conjunto de CPU y el conjunto de nodos del objeto raíz.

Si la topología actual se exporta a XML y se reimporta más tarde, esta marca debe volver a establecerse en la topología reimportada para que los recursos no permitidos también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asume que el backend seleccionado proporciona la topología del sistema en el que se está ejecutando. Esto fuerza a que hwloc_topology_is_thissystem() devuelva 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología del sistema en el que se está ejecutando, incluso si no es el backend específico del sistema operativo sino el backend XML, por ejemplo. Esto significa hacer que las funciones de vinculación (binding) llamen realmente a las llamadas del sistema específicas del sistema operativo y realicen la vinculación, mientras que el backend XML de lo contrario proporcionaría ganchos vacíos que solo devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto se puede usar por razones de eficiencia para detectar primero la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero aún así tener funciones de vinculación que realmente realicen la vinculación.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtiene el conjunto de recursos permitidos del sistema operativo local incluso si la topología se cargó desde XML o una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restringe la aplicación de las restricciones actuales del proceso, como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Esta marca se ignora a menos que también se establezca HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM, ya que la topología cargada debe coincidir con la máquina subyacente de la que se obtendrán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES tendría el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importa el soporte de la topología importada. Al importar una topología XML de una máquina remota, la vinculación está deshabilitada por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Esta deshabilitación también se marca poniendo ceros en los bits correspondientes de las características soportadas devueltas por hwloc_topology_get_support().

La marca HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT en realidad importa los bits de soporte de la máquina remota. También establece la marca imported_support en la estructura hwloc_topology_misc_support array. Si el XML importado no contenía información de soporte (el exportador hwloc es demasiado antiguo), esta marca no se establece.

Tenga en cuenta que estas características soportadas solo son relevantes para la instalación de hwloc que exportó la topología XML (puede variar según el sistema operativo o cómo se compiló hwloc).

Tenga en cuenta que establecer esta marca, sin embargo, no habilita la vinculación para la topología hwloc importada localmente, solo informa lo que el hwloc y la máquina remotos soportan.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
No considere recursos fuera de la vinculación de CPU del proceso. Si la vinculación del proceso está limitada a un subconjunto de núcleos, ignore los núcleos restantes durante la detección.

Esto es útil para evitar que la detección de topología de hwloc requiera acceso a recursos que podrían estar bloqueados para el proceso actual. Por ejemplo, en un sistema con varias máquinas de NUMA, si el proceso solo puede acceder a una máquina de NUMA, esta bandera la hará ignorar las otras máquinas de NUMA.

No se aplica si el proceso no está actualmente vinculado a un conjunto de CPU.

Esta marca solo está disponible si el backend de descubrimiento actual es el backend del sistema operativo (por ejemplo, no el backend XML o sintético).

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
No considere recursos fuera de la vinculación de memoria del proceso. Si la vinculación de memoria del proceso está limitada a un subconjunto de nodos de memoria, ignore los nodos de memoria restantes durante la detección.

Esto es útil para evitar que la detección de topología de hwloc requiera acceso a recursos que podrían estar bloqueados para el proceso actual. Por ejemplo, en un sistema con varias máquinas de NUMA, si el proceso solo puede acceder a una máquina de NUMA, esta bandera la hará ignorar las otras máquinas de NUMA.

No se aplica si el proceso no está actualmente vinculado a un conjunto de memoria.

Esta marca solo está disponible si el backend de descubrimiento actual es el backend del sistema operativo (por ejemplo, no el backend XML o sintético).

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
No cambiar la vinculación de CPU o memoria del proceso actual. Las funciones de vinculación de procesos de hwloc pueden cambiar la vinculación del proceso actual. Por ejemplo, cuando se solicita la vinculación de todos los procesos a un nuevo subproceso, el subproceso se vincula a un nuevo conjunto de CPU y la vinculación del proceso padre no se restaura después.

Establecer esta marca evita dichos cambios. Las funciones de vinculación aún verificarán la accesibilidad de los recursos pero no los modificarán.

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
No detectar ni importar tablas de distancia entre objetos del sistema. Estas tablas de distancia son opcionales y solo se recopilan de ciertos sistemas operativos o backends (por ejemplo, Linux).

Establecer esta marca puede acelerar la detección de topología si las tablas de distancia no son necesarias y/o si se sabe que son lentas o erróneas en el sistema.

HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
No detectar ni importar atributos de memoria del sistema. Estos atributos (por ejemplo, tipo de memoria, ancho de banda) son opcionales y solo se recopilan de ciertos sistemas operativos o backends (por ejemplo, Linux con el backend `numa`, FreeBSD).

Establecer esta marca puede acelerar la detección de topología si los atributos de memoria no son necesarios.

HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
No detectar ni importar grupos de CPU. Los grupos de CPU son un concepto específico de Linux que agrupa CPU para la planificación de la migración de memoria. Son opcionales y solo se recopilan si el backend de Linux los encuentra.

Establecer esta marca puede acelerar la detección de topología si los grupos de CPU no son necesarios.

enum hwloc_type_filter_e

El modo de filtrado de tipos de objetos. Se puede pasar a hwloc_topology_set_type_filter(), hwloc_topology_set_all_types_filter(), hwloc_topology_set_cache_types_filter(), hwloc_topology_set_icache_types_filter(), hwloc_topology_set_io_types_filter().

Enumerator

HWLOC_TYPE_FILTER_KEEP_ALL
Mantener todos los objetos del tipo especificado (o todos los tipos si se usa con hwloc_topology_set_all_types_filter()).
HWLOC_TYPE_FILTER_KEEP_NONE
Eliminar todos los objetos del tipo especificado (o todos los tipos si se usa con hwloc_topology_set_all_types_filter()).
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Mantener los objetos del tipo especificado solo si se necesita para representar la estructura del sistema. Por ejemplo, mantener solo los objetos de nivel superior como las máquinas, pero no los objetos de nivel inferior como los procesadores individuales dentro de un núcleo.

Se utiliza principalmente para reducir el tamaño de la topología eliminando objetos redundantes o de bajo nivel que no son necesarios para la estructura general. Por ejemplo, con esta opción, solo se mantendrán los niveles principales de caché (probablemente L2 o L1 si solo hay uno).

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Mantener los objetos del tipo especificado solo si son "importantes". La importancia se define generalmente por tener un impacto significativo en el rendimiento o la programación. Por ejemplo, solo los niveles de caché que realmente contienen datos o instrucciones se consideran importantes.

Esto está diseñado para eliminar objetos que no suelen ser de interés para la mayoría de las aplicaciones de alto rendimiento, como cachés pequeñas o memorias intermedias de E/S.

int hwloc_topology_set_all_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtrado para todos los tipos de objetos. Si algunos tipos no admiten este filtrado, se ignoran silenciosamente.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_topology_set_cache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtrado para todos los tipos de objetos de caché de CPU. Las cachés del lado de la memoria no están involucradas ya que no son cachés de CPU.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Establece los indicadores (flags) combinados con OR en una topología aún no cargada. Establece un conjunto de indicadores combinados con OR de hwloc_topology_flags_e en una topología que aún no ha sido cargada.

Si se llama a esta función varias veces, la última invocación borrará y reemplazará el conjunto de indicadores que se estableció previamente.

De forma predeterminada, no se establece ningún indicador (0).

Los indicadores establecidos en una topología pueden recuperarse con hwloc_topology_get_flags().

Devuelve

0 en caso de éxito.

-1 en caso de error, por ejemplo si los indicadores no son válidos.

void hwloc_topology_set_userdata (hwloc_topology_t topology, const void * userdata)

Establece el puntero de datos de usuario específico de la topología. Cada topología puede almacenar un puntero de datos privados proporcionado por la aplicación. Se inicializa a NULL. hwloc nunca lo modificará.

Úselo como desee, después de hwloc_topology_init() y hasta hwloc_topolog_destroy().

Este puntero no se exporta a XML.
