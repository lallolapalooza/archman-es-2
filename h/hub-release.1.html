NOMBRE

hub-release - Gestiona las versiones de GitHub para el repositorio actual.

SINOPSIS

hub release [--include-drafts] [--exclude-prereleases] [-L LÍMITE] [-f FORMATO]
hub release show [-f FORMATO] TAG
hub release create [-dpoc] [-a ARCHIVO] [-m MENSAJE|-F ARCHIVO] [-t DESTINO] TAG
hub release edit [opciones] TAG
hub release download TAG [-i PATRÓN]
hub release delete TAG

COMANDOS

Sin argumentos, muestra una lista de las versiones existentes.

show

Muestra las notas de la versión de GitHub para TAG.

Con --show-downloads, incluye la sección "Descargas".

create

Crea una versión de GitHub para el nombre de TAG especificado. Si la etiqueta git TAG no existe, se creará en DESTINO (por defecto: rama actual).

edit

Edita la versión de GitHub para el nombre de TAG especificado. Acepta las mismas opciones que el comando create. Publica un borrador con --draft=false.

Sin --message o --file, se abrirá un editor de texto pre-rellenado con el título y el cuerpo de la versión actual. Para reutilizar el título y el cuerpo existentes sin cambios, pasa -m "".

download

Descarga los activos adjuntos a la versión para el TAG especificado.

delete

Elimina la versión y los activos asociados para el TAG especificado. Ten en cuenta que esto **no** elimina la etiqueta git TAG.

OPCIONES

-d, --include-drafts

Lista los borradores junto con las versiones publicadas.

-p, --exclude-prereleases

Excluye las pre-versiones de la lista.

-L, --limit

Muestra solo las primeras LÍMITE versiones.

-d, --draft

Crea una versión borrador.

-p, --prerelease

Crea una pre-versión.

-a, --attach ARCHIVO

Adjunta un archivo como activo para esta versión.

Si ARCHIVO tiene el formato "nombre_archivo#texto", el texto después del carácter "#" se toma como etiqueta del activo.

-m, --message MENSAJE

El texto hasta la primera línea en blanco en MENSAJE se trata como el título de la versión, y el resto se utiliza como descripción de la versión en formato Markdown.

Cuando se pasan varios --message, sus valores se concatenan con una línea en blanco entre ellos.

Cuando ni --message ni --file se proporcionaron a release create, se abrirá un editor de texto para redactar el título y la descripción.

-F, --file ARCHIVO

Lee el título y la descripción de la versión desde ARCHIVO. Pasa "-" para leer desde la entrada estándar en su lugar. Consulta --message para conocer las reglas de formato.

-e, --edit

Abre el título y la descripción de la versión en un editor de texto antes de enviarlo. Esto se puede usar en combinación con --message o --file.

-o, --browse

Abre la nueva versión en un navegador web.

-c, --copy

Coloca la URL de la nueva versión en el portapapeles en lugar de imprimirla.

-t, --commitish DESTINO

Un SHA de commit o nombre de rama al que adjuntar la versión, solo se usa si TAG aún no existe (por defecto: rama principal).

-i, --include PATRÓN

Filtra los archivos en la versión para aquellos que coincidan con el patrón glob PATRÓN.

-f, --format FORMATO

Imprime las versiones de forma bonita usando FORMATO (por defecto: "%T%n"). Consulta la sección "FORMATOS BONITOS" de git-log(1) para obtener detalles adicionales sobre cómo se utilizan los marcadores de posición en el formato. Los marcadores de posición disponibles para las versiones son:

%U: la URL de esta versión

%uT: URL del tarball

%uZ: URL del zipball

%uA: URL de carga del activo

%S: estado (es decir, "draft", "pre-release")

%sC: establece el color en amarillo o rojo, dependiendo del estado

%t: nombre de la versión

%T: etiqueta de la versión

%b: cuerpo

%as: la lista de activos adjuntos a esta versión

%cD: fecha de creación (solo fecha, sin hora)

%cr: fecha de creación, relativa

%ct: fecha de creación, marca de tiempo UNIX

%cI: fecha de creación, formato ISO 8601

%pD: fecha de publicación (solo fecha, sin hora)

%pr: fecha de publicación, relativa

%pt: fecha de publicación, marca de tiempo UNIX

%pI: fecha de publicación, formato ISO 8601

%n: nueva línea

%%: un símbolo % literal

--color[=CUÁNDO]

Habilita la salida con color incluso si la salida estándar no es una terminal. CUÁNDO puede ser uno de "always" (por defecto para --color), "never" o "auto" (por defecto).

TAG

El nombre de la etiqueta git para esta versión.
