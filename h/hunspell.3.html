DESCRIPCIÓN

Las rutinas de la biblioteca Hunspell proporcionan al usuario funciones lingüísticas a nivel de palabra: corrección ortográfica y recomendación, derivación, generación morfológica y análisis en estilo de artículo y arreglo.

La cabecera C opcional contiene la interfaz C de la biblioteca C++ con el constructor y destructor Hunspell_create y Hunspell_destroy, y un parámetro adicional HunHandle (el objeto asignado) en las funciones envoltorio (ver el archivo de cabecera C hunspell.h).

Las funciones básicas de ortografía, spell() y suggest(), pueden usarse para derivación, generación morfológica y análisis mediante textos de entrada XML (ver API XML).

Constructor y destructor

El constructor de Hunspell necesita las rutas de los archivos de afijos y diccionario. (En el entorno WIN32, use rutas codificadas en UTF-8 que comiencen con el prefijo de ruta larga \\?\ para manejar la codificación de caracteres independiente del sistema y nombres de ruta muy largos). Consulte la página del manual de hunspell(4) para conocer el formato del diccionario. El parámetro opcional key es para diccionarios cifrados por la herramienta hzip de la distribución Hunspell.

Diccionarios adicionales

La función add_dic() carga un archivo de diccionario adicional. Los diccionarios adicionales usan el archivo de afijos del objeto Hunspell asignado. El número máximo de diccionarios adicionales está limitado en el código fuente (20).

Ortografía y corrección

La función spell() devuelve un valor distinto de cero si la palabra de entrada es reconocida por el corrector ortográfico, y un valor cero si no lo es. Las variables de referencia opcionales devuelven una matriz de bits (info) y la palabra raíz de la palabra de entrada. Los bits de info, verificados con las macros SPELL_COMPOUND, SPELL_FORBIDDEN o SPELL_WARN, indican palabras compuestas, explícitamente prohibidas y probablemente erróneas. Desde la versión 1.3, el valor de retorno distinto de cero es 2 para las palabras del diccionario con la etiqueta "WARN" (probablemente erróneas).

La función suggest() tiene dos parámetros de entrada, una variable de referencia de la lista de sugerencias de salida y una palabra de entrada. La función devuelve el número de sugerencias. La variable de referencia contendrá la dirección de la lista de sugerencias recién asignada o NULL, si el valor de retorno de suggest() es cero. El número máximo de sugerencias está limitado en el código fuente.

spell() y suggest() pueden reconocer entrada XML, ver la sección API XML.

Funciones morfológicas

Las funciones sencillas stem() y analyze() son similares a suggest(), pero en lugar de sugerencias, devuelven raíces y resultados del análisis morfológico. La función generate() sencilla también espera una segunda palabra. Esta palabra adicional y su afijación serán el modelo de la generación morfológica de las formas solicitadas de la primera palabra.

Las funciones stem() y generate() extendidas utilizan los resultados de un análisis morfológico:

char ** result, result2;
int n1 = analyze(&result, "words");
int n2 = stem(&result2, result, n1);

La anotación morfológica de la biblioteca Hunspell tiene identificadores de campo fijos (de dos letras y dos puntos), consulte la página del manual de hunspell(4).

char ** result;
char * affix = "is:plural"; // la descripción también depende de los diccionarios
int n = generate(&result, "word", &affix, 1);
for (int i = 0; i < n; i++) printf("%s\n", result[i]);

Liberación de memoria

La función free_list() libera la memoria asignada por las funciones suggest(), analyze, generate y stem().

Otras funciones

add(), add_with_affix() y remove() son funciones auxiliares de una implementación de diccionario personal para agregar y eliminar palabras del diccionario base en tiempo de ejecución. add_with_affix() utiliza una segunda palabra raíz como modelo de la afijación y composición habilitadas de la nueva palabra.

get_dic_encoding() devuelve "ISO8859-1" o la codificación de caracteres definida en el archivo de afijos con la palabra clave "SET".

get_csconv() devuelve la tabla de mayúsculas/minúsculas de 8 bits de la codificación del diccionario.

get_wordchars() y get_wordchars_utf16() devuelven los caracteres de palabra adicionales definidos en el archivo de afijos para la tokenización mediante la palabra clave "WORDCHARS".

get_version() devuelve la cadena de versión de la biblioteca.

API XML

La función spell() devuelve un valor distinto de cero para la entrada "<?xml?>" que indica el soporte de la API XML.

La función suggest() deriva, analiza y genera las formas de la palabra de entrada, si se agregó mediante una de las siguientes sintaxis "SPELLML":

<?xml?>
<query type="analyze">
<word>dogs</word>
</query>
<?xml?>
<query type="stem">
<word>dogs</word>
</query>
<?xml?>
<query type="generate">
<word>dog</word>
<word>cats</word>
</query>
<?xml?>
<query type="generate">
<word>dog</word>
<code><a>is:pl</a><a>is:poss</a></code>
</query>
<?xml?>
<query type="add">
<word>word</word>
</query>
<?xml?>
<query type="add">
<word>word</word>
<word>model_word_for_affixation_and_compounding</word>
</query>

Las salidas de la consulta type="stem" y la función de biblioteca stem() son las mismas. La salida de la consulta type="analyze" es una cadena que contiene un elemento <code><a>result1</a><a>result2</a>...</code>. Este elemento puede usarse en la segunda sintaxis de la consulta type="generate".
