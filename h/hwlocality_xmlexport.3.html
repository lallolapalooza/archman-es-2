void hwloc_topology_set_userdata_export_callback (hwloc_topology_t topology, void(*)(void *reserved, hwloc_topology_t topology, hwloc_obj_t obj)

export_cb)

Establece la devolución de llamada específica de la aplicación para exportar el userdata del objeto. El puntero userdata del objeto no se exporta a XML de forma predeterminada porque hwloc no sabe qué

contiene.

Esta función permite a las aplicaciones establecer export_cb a una función de devolución de llamada que convierta este userdata opaco en una cadena

exportable.

export_cb se invoca durante la exportación XML para cada objeto cuyo puntero userdata no es NULL. La devolución de llamada debe usar hwloc_export_obj_userdata() o hwloc_export_obj_userdata_base64() para exportar realmente algo a XML (posiblemente varias veces por objeto)

.

export_cb puede establecerse en NULL si el userdata no debe exportarse a

XML.

void hwloc_topology_set_userdata_import_callback (hwloc_topology_t topology, void(*)(hwloc_topology_t topology, hwloc_obj_t obj, const char *name, const void *buffer, size_t length)

import_cb)

Establece la devolución de llamada específica de la aplicación para importar userdata. En la importación XML, el userdata se ignora de forma predeterminada porque hwloc no sabe cómo almacenarlo en

memoria.

Esta función permite a las aplicaciones establecer import_cb a una función de devolución de llamada que recibirá el userdata almacenado en XML y lo almacenará en el objeto como espera la

aplicación.

import_cb se llama durante hwloc_topology_load() tantas veces como hwloc_export_obj_userdata() fue llamado durante la exportación. La topología aún no está completamente configurada. Los atributos del objeto están listos para consultar, pero los enlaces entre objetos

no.

import_cb puede ser NULL si el userdata debe ignorarse durante la

importación.
