DESCRIPCIÓN DETALLADA

Las plataformas con memoria heterogénea requieren formas de decidir si un buffer debe ser asignado en memoria 'rápida' (como HBM), memoria 'normal' (DDR) o incluso memoria 'lenta' pero de gran capacidad (no volátil). Estos nodos de memoria se denominan 'Destinos' (Targets) mientras que la CPU que accede a ellos se denomina 'Iniciador' (Initiator). El rendimiento del acceso depende de su localidad (plataformas NUMA) así como del rendimiento intrínseco de los destinos (plataformas heterogéneas).

Los siguientes atributos describen el rendimiento de los accesos a memoria desde un Iniciador a un Destino de memoria, por ejemplo, su latencia o ancho de banda. Los iniciadores que realizan estos accesos a memoria suelen ser algunos PU o Núcleos (descritos como un conjunto de CPU). Por lo tanto, un Núcleo puede elegir dónde asignar un buffer de memoria comparando los atributos de diferentes nodos de memoria de destino cercanos.

También hay algunos atributos que son globales del sistema. Su valor no depende de un iniciador específico que realice un acceso. La Capacidad del nodo de memoria es un ejemplo de tal atributo sin iniciador.

Una forma de usar esta API es comenzar con un conjunto de CPU que describa los Núcleos donde un programa está enlazado. El mejor nodo NUMA de destino para asignar memoria en este programa en estos Núcleos puede obtenerse pasando este conjunto de CPU como iniciador a hwloc_memattr_get_best_target() con el atributo de memoria relevante. Por ejemplo, si el código está limitado por latencia, use el atributo de Latencia.

Un enfoque más flexible consiste en obtener la lista de nodos NUMA locales pasando este conjunto de CPU a hwloc_get_local_numanode_objs(). Los valores de atributo para estos nodos, si existen, se pueden obtener con hwloc_memattr_get_value() y compararlos manualmente con los criterios deseados.

Los atributos de memoria también se utilizan internamente para construir Niveles de Memoria que proporcionan una forma sencilla de distinguir nodos NUMA de diferentes tipos, como se explica en Memoria Heterogénea.

Además de los niveles, hwloc define un conjunto de nodos 'predeterminados' desde donde se deben realizar las asignaciones de memoria normal (ver hwloc_topology_get_default_nodeset()). Esto también es útil para dividir la máquina en un conjunto de dominios NUMA no superpuestos, por ejemplo, para enlazar tareas por dominio.

Ver también

Un ejemplo está disponible en doc/examples/memory-attributes.c en el árbol fuente.

Nota

La API también admite objetos específicos como iniciador, pero actualmente no es utilizada internamente por hwloc. Los usuarios pueden, por ejemplo, usarla para proporcionar valores de rendimiento personalizados para accesos a memoria del host realizados por GPUs.

La interfaz en realidad también acepta destinos que no son nodos NUMA.

Documentación del alias de tipo

typedef unsigned hwloc_memattr_id_t

Un identificador de atributo de memoria. hwloc predefine algunos atributos de uso común en hwloc_memattr_id_e. Luego se pueden registrar dinámicamente atributos personalizados con hwloc_memattr_register(), se les asignarán IDs inmediatamente después de los predefinidos. Ver Gestión de atributos de memoria para más información sobre IDs de atributos existentes.

Documentación del tipo de enumeración

enum hwloc_local_numanode_flag_e

Flags para seleccionar nodos NUMA de destino.

Enumerador

HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY
Selecciona nodos NUMA cuya localidad sea mayor que el conjunto de CPU dado. Por ejemplo, si se proporciona una sola PU (o su conjunto de CPU) en initiator, selecciona todos los nodos cercanos al paquete que contiene esta PU.
HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY
Selecciona nodos NUMA cuya localidad sea menor que el conjunto de CPU dado. Por ejemplo, si se proporciona un paquete (o su conjunto de CPU) en initiator, también selecciona nodos que solo están conectados a la mitad de ese paquete.
HWLOC_LOCAL_NUMANODE_FLAG_INTERSECT_LOCALITY
Selecciona nodos NUMA cuya localidad se interseca con el conjunto de CPU dado. Esto incluye localidades más grandes y más pequeñas, así como localidades parcialmente incluidas. Por ejemplo, si la localidad es un núcleo de ambos paquetes, un nodo NUMA local a un paquete no es ni más grande ni más pequeño que esta localidad, pero se interseca con ella.
HWLOC_LOCAL_NUMANODE_FLAG_ALL
Selecciona todos los nodos NUMA de la topología. El iniciador initiator es ignorado.

int hwloc_memattr_get_initiators (hwloc_topology_t topology, hwloc_memattr_id_t attribute, hwloc_obj_t target_node, unsigned long flags, unsigned * nr, struct hwloc_location * initiators, hwloc_uint64_t * values)

Devuelve los iniciadores que tienen valores para un atributo dado para un nodo NUMA de destino específico. Devuelve los iniciadores para el atributo dado y el nodo de destino en el array initiators . Si values no es NULL, los valores de atributo correspondientes se almacenan en el array al que apunta.

En la entrada, nr apunta al número de iniciadores que pueden ser almacenados en el array initiators (y values). En la salida, nr apunta al número de iniciadores (y valores) que fueron realmente encontrados, incluso si algunos de ellos no pudieron ser almacenados en el array. Los iniciadores que no pudieron ser almacenados son ignorados, pero la función aún devuelve éxito (0). El llamador puede averiguarlo comparando el valor al que apunta nr antes y después de la llamada a la función.

Los iniciadores devueltos no deben ser modificados ni liberados, pertenecen a la topología.

target_node no puede ser NULL.

flags debe ser 0 por ahora.

Si el atributo no se relaciona con un iniciador específico (no tiene el flag HWLOC_MEMATTR_FLAG_NEED_INITIATOR), no se devuelve ningún iniciador.

Devoluciones

0 en caso de éxito o -1 en caso de error.

Nota

Esta función está destinada a herramientas y depuración (listar información interna) en lugar de para consultas de aplicaciones. Las aplicaciones deberían en su lugar seleccionar nodos NUMA útiles con hwloc_get_local_numanode_objs() y luego mirar sus valores de atributo para algunos iniciadores relevantes.

Devuelve los nodos NUMA de destino que tienen algunos valores para un atributo dado. Devuelve los destinos para el atributo dado en el array targets (para el iniciador dado, si lo hay). Si values no es NULL, los valores de atributo correspondientes se almacenan en el array al que apunta.

En la entrada, nr apunta al número de destinos que pueden ser almacenados en el array targets (y values). En la salida, nr apunta al número de destinos (y valores) que fueron realmente encontrados, incluso si algunos de ellos no pudieron ser almacenados en el array. Los destinos que no pudieron ser almacenados son ignorados, pero la función aún devuelve éxito (0). int hwloc_topology_get_default_nodeset (hwloc_topology_t topology, hwloc_nodeset_t nodeset, unsigned long flags)

Devuelve el conjunto de nodos NUMA predeterminados. En máquinas con memoria heterogénea, algunos nodos NUMA se consideran los predeterminados, es decir, donde se deben realizar las asignaciones básicas. Estos son generalmente nodos DRAM.

Otros nodos pueden estar reservados para un uso específico (memoria de dispositivos de E/S, p. ej. memoria de GPU), pequeños pero de alto rendimiento (HBM), memoria grande pero lenta (NVM), etc. Los búferes generalmente no deben asignarse de allí a menos que se requiera explícitamente.

Esta función rellena nodeset con los bits de los nodos NUMA considerados predeterminados.

Se garantiza que estos nodos tienen conjuntos de CPUs no intersectantes, es decir, los núcleos pueden no tener múltiples nodos NUMA locales. Por lo tanto, esto puede usarse para iterar sobre la plataforma dividida en localidades NUMA separadas, por ejemplo para vincular una tarea por dominio NUMA.

Cualquier núcleo que tuviera algún nodo(s) NUMA local en la topología inicial todavía debería tener uno en el nodeset predeterminado. Los casos extremos donde esto sería incorrecto consisten en plataformas asimétricas con nodos DRAM faltantes, o topologías que ya estaban restringidas a menos nodos NUMA.

El nodeset devuelto puede pasarse a hwloc_topology_restrict() con HWLOC_RESTRICT_FLAG_BYNODESET para eliminar todos los nodos no predeterminados de la topología. La topología resultante será más fácil de usar al iterar sobre (ahora homogéneos) nodos NUMA.

Las heurísticas para encontrar nodos predeterminados se basan en los niveles de memoria y subtipos (ver Memoria Heterogénea) así como en la suposición de que los proveedores de hardware listan los nodos predeterminados primero en las tablas de hardware.

flags debe ser 0 por ahora.

Devoluciones

0 en caso de éxito.

-1 en caso de error.

Nota

El nodeset devuelto generalmente contiene todos los nodos de un solo nivel de memoria, probablemente el DRAM.

El nodeset devuelto está incluido en la lista de nodos disponibles devuelta por hwloc_topology_get_topology_nodeset(). Es estrictamente más pequeño si la máquina tiene memoria heterogénea.

Las heurísticas pueden devolver un conjunto subóptimo de nodos si hwloc no pudo adivinar los tipos de memoria y/o si algunos nodos predeterminados fueron eliminados previamente de la topología (p. ej. con hwloc_topology_restrict()).
