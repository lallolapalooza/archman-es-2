Descripción

detallada

Estas funciones deben llamarse entre hwloc_topology_init() y hwloc_topology_load(). De lo contrario, devolverán -1 con errno establecido a EBUSY

.

Si no se llama a ninguna de las funciones siguientes, el comportamiento por defecto es detectar todos los objetos de la máquina a los que el llamador tiene permitido

acceder.

Este comportamiento por defecto también puede modificarse mediante variables de entorno si la aplicación no lo ha modificado ya. Establecer HWLOC_XMLFILE en el entorno fuerza el descubrimiento desde un archivo XML como si se hubiera llamado a hwloc_topology_set_xml(). Establecer HWLOC_SYNTHETIC fuerza una topología sintética como si se hubiera llamado a hwloc_topology_set_sy

nthetic().

Finalmente, HWLOC_THISSYSTEM fuerza el valor de retorno de hwloc_topology_i

ystem().

int hwloc_topology_set_components (hwloc_topology_t restrict topology, unsigned long flags, const char *restrict

name)

Impide que un componente de descubrimiento sea utilizado para una topología. name es el nombre del componente de descubrimiento que no debe usarse al cargar la topología topology. El nombre es una cadena como

'cuda'.

Para componentes con múltiples fases, también puede ir sufijado con el nombre de una fase, por ejemplo 'linux:

io'.

flags debe ser HWLOC_TOPOLOGY_COMPONENTS_FLAG_BLACKLIST

.

Esto puede usarse para evitar partes costosas del proceso de descubrimiento. Por ejemplo, el descubrimiento específico de CUDA puede ser costoso e innecesario mientras que el descubrimiento genérico de E/S podría seguir siendo

útil.

int hwloc_topology_set_pid (hwloc_topology_t restrict topology, hwloc_pid_t

pid)

Cambia desde qué proceso se ve la topología. En algunos sistemas, los procesos pueden tener vistas diferentes de la máquina, por ejemplo el conjunto de CPUs permitidas. De forma predeterminada, hwloc expone la vista desde el proceso actual. Llamar a hwloc_topology_set_pid() permite hacer que exponga la topología de la máquina desde el punto de vista de otro

proceso.

Not

a
hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

Se devuelve -1 y errno se establece a ENOSYS en plataformas que no soportan esta

característica.

El PID no se usará realmente hasta hwloc_topology_load(). Si el proceso correspondiente termina en el ínterim, hwloc i

gnorará el PID. Si otro proceso reutiliza
el PID, se usará la vista de ese proceso.

int hwloc_topology_set_synthetic (hwloc_topology_t restrict topology, const char *restrict

description)

Habilita la topología sintética. Recopila información de topología de la descripción dada, una cadena separada por espacios de <tipo:número> que describe el tipo de objeto y la aridad en cada nivel. Todos los tipos pueden omitirse (cadena de números separados por espacios) para que hwloc elija todos los tipos según las topologías habituales. Véase también Topologías sintéticas

.

Establecer la variable de entorno HWLOC_SYNTHETIC también puede resultar en este

comportamiento.

Si description se analizó correctamente y describe una configuración de topología válida, esta función devuelve 0. De lo co

ntrario, se devuelve -1 y errno se establece a EINVAL.

Ten en cuenta que esta función no carga realmente la información de topología; solo le dice a hwloc desde dónde cargarla. Aún necesitarás invocar hwloc_topology_load() para cargar realmente la información de

topología.
