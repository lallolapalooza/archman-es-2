Descripción Detallada

Las plataformas con memoria heterogénea requieren formas de decidir si un buffer debe ser asignado en memoria 'rápida' (como HBM), memoria 'normal' (DDR) o incluso memoria 'lenta' pero de gran capacidad (memoria no volátil). Estos nodos de memoria se denominan 'Targets' (objetivos), mientras que la CPU que accede a ellos se denomina 'Initiator' (iniciador). El rendimiento del acceso depende de su localidad (plataformas NUMA), así como del rendimiento intrínseco de los objetivos (plataformas heterogéneas).

Los siguientes atributos describen el rendimiento de los accesos a memoria desde un Iniciador a un Nodo de Memoria Objetivo, por ejemplo su latencia o ancho de banda. Los iniciadores que realizan estos accesos a memoria suelen ser algunas PUs o Cores (descritos como un conjunto de CPUs). Por lo tanto, un Core puede elegir dónde asignar un buffer de memoria comparando los atributos de diferentes nodos de memoria objetivo cercanos.

También hay algunos atributos que son de sistema completo. Su valor no depende de un iniciador específico que realice un acceso. La Capacidad del nodo de memoria es un ejemplo de tal atributo sin iniciador.

Una forma de usar esta API es comenzar con un conjunto de CPUs que describe los Cores a los que está enlazado un programa. El mejor nodo NUMA objetivo para asignar memoria en este programa en estos Cores se puede obtener pasando este conjunto de CPUs como iniciador a hwloc_memattr_get_best_target() con el atributo de memoria relevante. Por ejemplo, si el código está limitado por la latencia, use el atributo Latencia.

Un enfoque más flexible consiste en obtener la lista de nodos NUMA locales pasando este conjunto de CPUs a hwloc_get_local_numanode_objs(). Los valores de atributos para estos nodos, si los hay, se pueden obtener luego con hwloc_memattr_get_value() y compararlos manualmente con los criterios deseados.

Los atributos de memoria también se utilizan internamente para construir Niveles de Memoria que proporcionan una forma fácil de distinguir los nodos NUMA de diferentes tipos, como se explica en Memoria Heterogénea.

Además de los niveles, hwloc define un conjunto de nodos 'predeterminados' de los cuales se deben realizar las asignaciones de memoria normales (ver hwloc_topology_get_default_nodeset()). Esto también es útil para dividir la máquina en un conjunto de dominios NUMA no superpuestos, por ejemplo, para enlazar tareas por dominio.

Ver también

Un ejemplo está disponible en doc/examples/memory-attributes.c en el árbol de fuentes.

Nota

La API también soporta objetos específicos como iniciador, pero actualmente no es utilizada internamente por hwloc. Los usuarios pueden, por ejemplo, usarla para proporcionar valores de rendimiento personalizados para accesos a memoria del host realizados por GPUs.

La interfaz en realidad también acepta objetivos que no son nodos NUMA.

Documentación del tipo enumeración

enum hwloc_local_numanode_flag_e

Banderas para seleccionar nodos NUMA de destino.

Enumerator

HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY
Selecciona nodos NUMA cuya localidad es mayor que el conjunto de CPUs dado. Por ejemplo, si se proporciona una sola PU (o su conjunto de CPUs) en initiator, selecciona todos los nodos cercanos al paquete que contiene esta PU.
HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY
Selecciona nodos NUMA cuya localidad es menor que el conjunto de CPUs dado. Por ejemplo, si se proporciona un paquete (o su conjunto de CPUs) en initiator, también selecciona nodos que están conectados solo a la mitad de ese paquete.
HWLOC_LOCAL_NUMANODE_FLAG_INTERSECT_LOCALITY
Selecciona nodos NUMA cuya localidad intersecta el conjunto de CPUs dado. Esto incluye localidades más grandes y más pequeñas, así como localidades que están parcialmente incluidas. Por ejemplo, si la localidad es un core de ambos paquetes, un nodo NUMA local a un paquete no es ni más grande ni más pequeño que esta localidad, pero la intersecta.
HWLOC_LOCAL_NUMANODE_FLAG_ALL
Selecciona todos los nodos NUMA en la topología. El iniciador initiator es ignorado.

enum hwloc_memattr_id_e

IDs de atributos de memoria predefinidos.

Enumerator

HWLOC_MEMATTR_ID_CAPACITY
La capacidad total del nodo de memoria (en bytes). Esto solo tiene sentido para nodos de memoria que contienen memoria (como nodos NUMA o memoria de GPU), no para nodos CPU. El valor de capacidad es siempre un entero de 64 bits sin signo. Las capacidades de memoria son siempre positivas o cero. Esta es una propiedad de solo lectura del nodo de memoria.
HWLOC_MEMATTR_ID_LOCALITY
La localidad del nodo de memoria con respecto a un iniciador. Esto se mide con un entero de 64 bits sin signo, donde un valor más alto significa una mejor localidad. La localidad de 0 se utiliza para la memoria que no es local. Un valor de 1 se utiliza para la memoria local en sistemas con solo un nivel de localidad (como los sistemas NUMA de varios sockets). En sistemas con múltiples niveles de localidad (como nodos NUMA dentro de un paquete), la localidad podría ser mayor que 1. Los valores exactos no se especifican y dependen de la plataforma. Por ejemplo, el acceso a la memoria del nodo NUMA 0 desde el core 0 podría tener una localidad de 20, mientras que el acceso desde el core 1 (en el mismo paquete) podría tener una localidad de 10, y el acceso desde el core 10 (en un paquete diferente) podría tener una localidad de 1. Esta es una propiedad de solo lectura del nodo de memoria y del iniciador.
HWLOC_MEMATTR_ID_BANDWIDTH
El ancho de banda total (en bytes por segundo) entre un iniciador y un nodo de memoria. Este es un atributo de solo lectura del nodo de memoria y del iniciador. El valor es un entero de 64 bits sin signo. Un valor más alto significa un mejor ancho de banda.
HWLOC_MEMATTR_ID_READ_BANDWIDTH
El ancho de banda de lectura (en bytes por segundo) entre un iniciador y un nodo de memoria. Ver HWLOC_MEMATTR_ID_BANDWIDTH.
HWLOC_MEMATTR_ID_WRITE_BANDWIDTH
El ancho de banda de escritura (en bytes por segundo) entre un iniciador y un nodo de memoria. Ver HWLOC_MEMATTR_ID_BANDWIDTH.
HWLOC_MEMATTR_ID_LATENCY
La latencia total (en nanosegundos) entre un iniciador y un nodo de memoria. Este es un atributo de solo lectura del nodo de memoria y del iniciador. El valor es un entero de 64 bits sin signo. Un valor más bajo significa una mejor latencia.
HWLOC_MEMATTR_ID_READ_LATENCY
La latencia de lectura (en nanosegundos) entre un iniciador y un nodo de memoria. Ver HWLOC_MEMATTR_ID_LATENCY.
HWLOC_MEMATTR_ID_WRITE_LATENCY
La latencia de escritura (en nanosegundos) entre un iniciador y un nodo de memoria. Ver HWLOC_MEMATTR_ID_LATENCY.
HWLOC_MEMATTR_ID_MAX
Este es el valor máximo para los IDs de atributos de memoria predefinidos. Los IDs de atributos de memoria registrados dinámicamente se añadirán después de este valor.

Hardware Locality (hwloc)

Version 2.12.2

hwloc_memattr

Memory attributes are an abstract concept that may provide additional information about memory. For example, memory capacity, locality, or tier information.

The memory attribute subsystem is designed to be extensible. New attributes can be added to the topology even after its creation. The core hwloc library provides a few standard attributes, such as capacity and locality.

All memory attributes must have a unique identifier (hwloc_memattr_id_t) and an optional name (string). They are associated with objects in the topology. Currently, they are only associated with NUMA nodes (HWLOC_OBJ_NUMANODE) and with specific initiators (e.g. CPU cores).

Memory attributes may have flags indicating their specific usage. The only flag defined currently is HWLOC_MEMATTR_FLAG_NEED_INITIATOR. If set, this flag means the attribute value depends on the initiator of the memory access. It is then mandatory to provide the initiator information when querying the attribute value.

Memory attributes values are arbitrary unsigned 64-bit integers (hwloc_uint64_t). Interpreting these values requires additional information specific to each attribute.

For instance, memory capacity attributes typically return the capacity in bytes. Locality attributes may return a score indicating how close the memory is to the initiator. The interpretation of other attributes may require specific knowledge about the underlying hardware.

Some memory attributes may be specific to certain hardware or system configurations. hwloc provides standard attributes that are likely to be found on most systems, but custom attributes can also be added.

Note

The memory attribute subsystem is an evolving feature. New attributes and functionalities may be added in future versions of hwloc. Always check the documentation for the latest information.

See Also

hwloc(7)](hwloc.html)

int hwloc_memattr_add (hwloc_topology_t topology, const char * name, hwloc_uint64_t flags, hwloc_memattr_id_t * id)

Add a new memory attribute to the topology.

This function is intended for use by backend components that need to register custom memory attributes. Applications should generally not need to call this function directly.

The attribute is identified by its `name`. If `name` is already registered, the existing attribute's `id` is returned. Otherwise, a new attribute is created and its identifier is returned in `id`.

`flags` are currently unused and must be 0.

Returns

0 on success.

-1 on error, for instance with errno set to EINVAL if flags are invalid or if the name is invalid.

int hwloc_memattr_get (hwloc_topology_t topology, hwloc_memattr_id_t attribute, hwloc_obj_t obj, struct hwloc_location * initiator, unsigned long flags, hwloc_uint64_t * value)

Get the value of a memory attribute for a given object and initiator.

`obj` is the object for which the attribute value is queried. This is typically a NUMA node object.

`initiator` specifies the initiator of the memory access. If the attribute does not require an initiator (i.e., it does not have the flag `HWLOC_MEMATTR_FLAG_NEED_INITIATOR`), then `initiator` can be NULL.

`flags` must be 0 for now.

On success, the attribute value is stored in `value`.

Returns

0 on success.

-1 on error, for instance with errno set to EINVAL if the attribute does not exist, if the object is not suitable for the attribute, or if flags are invalid.

Note

The initiator initiator should be of type HWLOC_LOCATION_TYPE_CPUSET when refering to accesses performed by CPU cores. HWLOC_LOCATION_TYPE_OBJECT is currently unused internally by hwloc, but users may for instance use it to provide custom information about host memory accesses performed by GPUs.

Return the identifier of the memory attribute with the given name.

Returns

0 on success.

int hwloc_memattr_get_initiators (hwloc_topology_t topology, hwloc_memattr_id_t attribute, hwloc_obj_t target_node, unsigned long flags, unsigned * nr, struct hwloc_location * initiators, hwloc_uint64_t * values)

Return the initiators that have values for a given attribute for a specific target NUMA node. Return initiators for the given attribute and target node in the initiators array. If values is not NULL, the corresponding attribute values are stored in the array it points to.

On input, nr points to the number of initiators that may be stored in the array initiators (and values). On output, nr points to the number of initiators (and values) that were actually found, even if some of them couldn't be stored in the array. Initiators that couldn't be stored are ignored, but the function still returns success (0). The caller may find out by comparing the value pointed by nr before and after the function call.

The returned initiators should not be modified or freed, they belong to the topology.

target_node cannot be NULL.

flags must be 0 for now.

If the attribute does not relate to a specific initiator (it does not have the flag HWLOC_MEMATTR_FLAG_NEED_INITIATOR), no initiator is returned.

Returns

0 on success or -1 on error.

Note

This function is meant for tools and debugging (listing internal information) rather than for application queries. Applications should rather select useful NUMA nodes with hwloc_get_local_numanode_objs() and then look at their attribute values for some relevant initiators.

int hwloc_memattr_get_targets (hwloc_topology_t topology, hwloc_memattr_id_t attribute, struct hwloc_location * initiator, unsigned long flags, unsigned * nr, hwloc_obj_t * targets, hwloc_uint64_t * values)

Return the target NUMA nodes that have some values for a given attribute. Return targets for the given attribute in the targets array (for the given initiator if any). If values is not NULL, the corresponding attribute values are stored in the array it points to.

On input, nr points to the number of targets that may be stored in the array targets (and values). On output, nr points to the number of targets (and values) that were actually found, even if some of them couldn't be stored in the array. Targets that couldn't be stored are ignored, but the function still returns success (0). The caller may find out by comparing the value pointed by nr before and after the function call.

The returned targets should not be modified or freed, they belong to the topology.

Argument initiator is ignored if the attribute does not relate to a specific initiator (it does not have the flag HWLOC_MEMATTR_FLAG_NEED_INITIATOR). Otherwise initiator may be non NULL to report only targets that have a value for that initiator.

flags must be 0 for now.

Note

This function is meant for tools and debugging (listing internal information) rather than for application queries. Applications should rather select useful NUMA nodes with hwloc_get_local_numanode_objs() and then look at their attribute values.

Returns

0 on success or -1 on error.

Note

The initiator initiator should be of type HWLOC_LOCATION_TYPE_CPUSET when referring to accesses performed by CPU cores. HWLOC_LOCATION_TYPE_OBJECT is currently unused internally by hwloc, but users may for instance use it to provide custom information about host memory accesses performed by GPUs.

int hwloc_memattr_get_value (hwloc_topology_t topology, hwloc_memattr_id_t attribute, hwloc_obj_t target_node, struct hwloc_location * initiator, unsigned long flags, hwloc_uint64_t * value)

Return an attribute value for a specific target NUMA node. If the attribute does not relate to a specific initiator (it does not have the flag HWLOC_MEMATTR_FLAG_NEED_INITIATOR), location initiator is ignored and may be NULL.

target_node cannot be NULL. If attribute is HWLOC_MEMATTR_ID_CAPACITY, target_node must be a NUMA node. If it is HWLOC_MEMATTR_ID_LOCALITY, target_node must have a CPU set.

flags must be 0 for now.

Returns

0 on success.

-1 on error, for instance with errno set to EINVAL if flags are invalid or no such attribute exists.

Note

The initiator initiator should be of type HWLOC_LOCATION_TYPE_CPUSET when refering to accesses performed by CPU cores. HWLOC_LOCATION_TYPE_OBJECT is currently unused internally by hwloc, but users may for instance use it to provide custom information about host memory accesses performed by GPUs.

int hwloc_topology_get_default_nodeset (hwloc_topology_t topology, hwloc_nodeset_t nodeset, unsigned long flags)

Return the set of default NUMA nodes. In machines with heterogeneous memory, some NUMA nodes are considered the default ones, i.e. where basic allocations should be made from. These are usually DRAM nodes.

Other nodes may be reserved for specific use (I/O device memory, e.g. GPU memory), small but high performance (HBM), large but slow memory (NVM), etc. Buffers should usually not be allocated from there unless explicitly required.

This function fills nodeset with the bits of NUMA nodes considered default.

It is guaranteed that these nodes have non-intersecting CPU sets, i.e. cores may not have multiple local NUMA nodes anymore. Hence this may be used to iterate over the platform divided into separate NUMA localities, for instance for binding one task per NUMA domain.

Any core that had some local NUMA node(s) in the initial topology should still have one in the default nodeset. Corner cases where this would be wrong consist in asymmetric platforms with missing DRAM nodes, or topologies that were already restricted to less NUMA nodes.

The returned nodeset may be passed to hwloc_topology_restrict() with HWLOC_RESTRICT_FLAG_BYNODESET to remove all non-default nodes from the topology. The resulting topology will be easier to use when iterating over (now homogeneous) NUMA nodes.

The heuristics for finding default nodes relies on memory tiers and subtypes (see Heterogeneous Memory) as well as the assumption that hardware vendors list default nodes first in hardware tables.

flags must be 0 for now.

Returns

0 on success.

-1 on error.

Note

The returned nodeset usually contains all nodes from a single memory tier, likely the DRAM one.

The returned nodeset is included in the list of available nodes returned by hwloc_topology_get_topology_nodeset(). It is strictly smaller if the machine has heterogeneous memory.

The heuristics may return a suboptimal set of nodes if hwloc could not guess memory types and/or if some default nodes were removed earlier from the topology (e.g. with hwloc_topology_restrict()).
