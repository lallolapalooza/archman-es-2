NOMBRE

hub-api - Interfaz de solicitud de API de GitHub de bajo nivel.

SINOPSIS

hub api [-it] [-X METODO] [-H CABECERA] [--cache TTL] ENDPOINT [-F CAMPO|--input ARCHIVO]

OPCIONES

-X, --method METODO

El método HTTP a usar para la solicitud (por defecto: "GET"). El método se establece automáticamente a "POST" si se utilizan --field, --raw-field o --input.

Usa -XGET para forzar la serialización de campos en la cadena de consulta para la solicitud GET en lugar del cuerpo JSON de la solicitud POST.

-F, --field CLAVE=VALOR

Datos para serializar con la solicitud. VALOR tiene un manejo mágico; usa --raw-field para enviar valores de cadena arbitrarios.

Si VALOR comienza con "@", el resto del valor se interpreta como un nombre de archivo del que leer el valor. Usa "@-" para leer desde la entrada estándar.

Si VALOR es "true", "false", "null" o parece un número, se usa un tipo JSON apropiado en lugar de una cadena.

No es posible serializar VALOR como una matriz o un hash JSON anidado. En su lugar, construye la carga útil de la solicitud externamente y pásala a través de --input.

A menos que se usara -XGET, todos los campos se envían serializados como JSON dentro del cuerpo de la solicitud. Cuando ENDPOINT es "graphql", todos los campos que no sean "query" se agrupan bajo "variables". Ver ⟨https://graphql.org/learn/queries/#variables⟩

-f, --raw-field CLAVE=VALOR

Igual que --field, excepto que permite valores que comienzan con "@", cadenas literales "true", "false" y "null", así como cadenas que parecen números.

--input ARCHIVO

El nombre del archivo del que leer el cuerpo de la solicitud sin procesar. Usa "-" para leer desde la entrada estándar. Usa esto cuando quieras construir manualmente la carga útil de la solicitud.

-H, --header CLAVE:VALOR

Establecer una cabecera de solicitud HTTP.

-i, --include

Incluir cabeceras de respuesta HTTP en la salida.

-t, --flat

Analiza la respuesta JSON y produce los datos en un formato de clave-valor basado en líneas adecuado para su uso en scripts de shell.

--paginate

Solicita y produce automáticamente la siguiente página de resultados hasta que todos los recursos se hayan listado. Para solicitudes GET, esto sigue el recurso <next> como se indica en la cabecera de respuesta "Link". Para consultas GraphQL, esto utiliza pageInfo que debe estar presente en la consulta; ver EJEMPLOS.

Tenga en cuenta que se producirán varios documentos JSON como resultado. Si se ha alcanzado el límite de tasa de la API, el último documento que se produzca será el aviso HTTP 403, y el proceso saldrá con un estado distinto de cero. Una forma de evitar esto es habilitando --obey-ratelimit.

--color[=CUANDO]

Habilitar salida en color incluso si la salida estándar no es una terminal. CUANDO puede ser "always" (por defecto para --color), "never" o "auto" (por defecto).

--cache TTL

Almacena en caché respuestas válidas a solicitudes GET durante TTL segundos.

Al usar "graphql" como ENDPOINT, el almacenamiento en caché también se aplicará a las respuestas a solicitudes POST. Simplemente asegúrate de no usar --cache para ninguna mutación de GraphQL.

--obey-ratelimit

Después de exceder el límite de tasa de la API, pausa el proceso hasta el tiempo de reinicio de la ventana actual del límite de tasa y reintenta la solicitud. Tenga en cuenta que esto puede hacer que el proceso se cuelgue durante mucho tiempo (un máximo de 1 hora).

ENDPOINT

El punto final de la API de GitHub al que enviar la solicitud HTTP (por defecto: "/").

Para obtener información sobre los puntos finales disponibles, ver ⟨https://developer.github.com/v3/⟩. Para hacer consultas GraphQL, usa "graphql" como ENDPOINT y pasa -F query=CONSULTA.

Si las cadenas literales "{owner}" o "{repo}" aparecen en ENDPOINT o en el campo "query" de GraphQL, rellena esos marcadores de posición con valores leídos de la configuración remota de git del repositorio git actual.

EJEMPLOS

# obtener información sobre el usuario autenticado actualmente como JSON
$ hub api user
# listar repositorios del usuario con salida basada en líneas
$ hub api --flat users/octocat/repos
# publicar un comentario en el issue #23 del repositorio actual
$ hub api repos/{owner}/{repo}/issues/23/comments --raw-field ´body=¡Buen trabajo!´
# realizar una consulta GraphQL leída de un archivo
$ hub api graphql -F query=@ruta/a/miquery.graphql
# realizar paginación con GraphQL
$ hub api --paginate graphql -f query=´
  query($endCursor: String) {
    repositoryOwner(login: "USUARIO") {
      repositories(first: 100, after: $endCursor) {
        nodes {
          nameWithOwner
        }
        pageInfo {
          hasNextPage
          endCursor
        }
      }
    }
  }
´
