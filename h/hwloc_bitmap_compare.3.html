Descripción

Detallada

El tipo hwloc_bitmap_t representa un conjunto de enteros (positivos o nulos). Un mapa de bits puede ser de tamaño infinito (todos los bits están establecidos después de algún punto). Un mapa de bits puede incluso estar completo si todos los bits están

establecidos.

Los mapas de bits son utilizados por hwloc para conjuntos de procesadores del SO (que pueden ser en realidad hilos de hardware) como hwloc_cpuset_t (un typedef para hwloc_bitmap_t), o conjuntos de nodos de memoria NUMA como hwloc_nodeset_t (también un typedef para hwloc_bitmap_t). Estos son utilizados para los campos cpuset y nodeset en la estructura hwloc_obj, ver Conjuntos de Objetos (hwloc_cpuset_t

y hwloc_nodeset_t).

Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del SO. Sin embargo, los usuarios normalmente no deberían construir conjuntos de CPU y de nodos manualmente (por ejemplo, con hwloc_bitmap_set()). En su lugar, uno debería usar conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or(), etc. Por ejemplo, vincular el hilo actual a un par de núcleos puede realizarse

con: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

Not

a
La mayoría de las funciones siguientes devuelven 0 en caso de éxito y -1 en caso de error. El caso de error habitual sería un fallo interno al realloc/extend the almacenamiento del mapa de bits (errno se establecería en ENOMEM). Ver también Informe de Errores en la API.

Varios ejemplos de uso de la API de mapas de bits están d

isponibles en el directorio doc/examples/ del árbol d
e fuentes. Las pruebas de regresión como tests/hwloc
/hwloc_bitmap*.c también hacen uso intensivo de esta API.

int hwloc_bitmap_compare(hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los mapas de bits bitmap1 y bitmap2 en orden lexicográfico. Comparación lexicográfica de mapas de bits, comenzando por sus índices más altos. Compara los últimos índices primero, luego los segundos, etc. El mapa de bits vacío se considera menor que cualquier otro.

Retorna

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

0 si los mapas de bits son iguales (a diferencia de hwloc_bitmap_compare_first()).

Por ejemplo, comparar los mapas de bits binarios 0011 y 0110 retorna -1 (por lo tanto, 0011 se considera menor que 0110). Comparar 00101 y 01010 también retorna -1.

Nota

Esto es diferente del inexistente hwloc_bitmap_compare_last() que solo compararía el índice más alto de cada mapa de bits.

int hwloc_bitmap_compare_first(hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los mapas de bits bitmap1 y bitmap2 usando su índice más bajo. Se considera que un mapa de bits es menor si su bit menos significativo es menor. El mapa de bits vacío se considera mayor que cualquier otro (porque su bit menos significativo no existe).

Retorna

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

Por ejemplo, comparar los mapas de bits binarios 0011 y 0110 retorna -1 (por lo tanto, 0011 se considera menor que 0110) porque el bit menos significativo de 0011 (0001) es menor que el bit menos significativo de 0110 (0010). Comparar 01001 y 00110 también retornaría -1 por la misma razón.

Retorna

0 si los mapas de bits se consideran iguales, incluso si no son estrictamente iguales. Solo necesitan tener el mismo bit menos significativo. Por ejemplo, comparar los mapas de bits binarios 0010 y 0110 retorna 0 porque tienen el mismo bit menos significativo.

int hwloc_bitmap_singlify (hwloc_bitmap_t

bitmap)

Mantiene un solo índice entre los establecidos en el mapa de bits bitmap. Puede ser útil antes de la vinculación para que el proceso no tenga la posibilidad de migrar entre múltiples procesadores en la máscara original. En lugar de ejecutar la tarea en cualquier PU dentro del conjunto de CPU dado, el programador del sistema operativo se verá obligado a ejecutarla en una sola de estas PUs. Evita una sobrecarga de migración y los "ping-pongs" de la línea de caché entre

PUs.

Not

a
Esta función NO está destinada a distribuir múltiples procesos dentro de un solo conjunto de CPU. Siempre devuelve el mismo bit único cuando se llama varias veces con el mismo conjunto de entrada. hwloc_distrib() puede usarse para generar conjuntos de CPU para distribuir múltiples tareas bajo un solo objeto multi-PU.

Esta función no puede aplicarse directamente a un conjunto de objetos. Debe aplicarse a una copia (que puede obtenerse con hwloc_bi
