Descripción detallada

Varias funciones pueden llamarse opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo debe realizarse la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

Documentación del tipo enumeración

enum hwloc_topology_flags_e

Banderas que deben establecerse en un contexto de topología antes de la carga. Las banderas deben proporcionarse a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detectar todo el sistema, ignorar las reservas, incluir objetos no permitidos. Recopilar todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignorar Cgroup/Cpusets de Linux y recopilar todos los procesadores y nodos de memoria. Sin embargo, las UPs y los nodos NUMA fuera de línea todavía se ignoran.

Cuando esta bandera no está establecida, las UPs y los nodos NUMA que no están permitidos no se añaden a la topología. Los objetos padre (paquete, núcleo, caché, etc.) se añaden solo si algunos de sus hijos están permitidos. Todas las UPs y los nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al cpuset y nodeset del objeto raíz.

Cuando esta bandera está establecida, los conjuntos reales de UPs y nodos NUMA permitidos se proporcionan mediante hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el cpuset y el nodeset del objeto raíz.

Si la topología actual se exporta a XML y se vuelve a importar más tarde, esta bandera debe establecerse de nuevo en la topología reimportada para que los recursos no permitidos también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asumir que el backend seleccionado proporciona la topología del sistema en el que nos encontramos. Esto fuerza a hwloc_topology_is_thissystem() a devolver 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología del sistema en el que nos encontramos, incluso si no es el backend específico del OS sino el backend XML, por ejemplo. Esto significa hacer que las funciones de enlace realmente llamen a las llamadas al sistema específicas del OS y realmente realicen el enlace, mientras que el backend XML de otro modo proporcionaría ganchos vacíos que solo devolverían éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto puede usarse por razones de eficiencia para primero detectar la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero teniendo aún así las funciones de enlace que realmente realicen el enlace.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtener el conjunto de recursos permitidos del sistema operativo local incluso si la topología se cargó desde XML o una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restringirla aplicando las restricciones del proceso actual como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido solo a partes de la máquina.

Esta bandera se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecida, ya que la topología cargada debe coincidir con la máquina subyacente de donde se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES resultaría en el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importar soporte desde la topología importada. Al importar una topología XML desde una máquina remota, el enlace está deshabilitado por defecto (véase HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Este deshabilitado también se marca poniendo ceros en los bits de características soportadas correspondientes reportados por hwloc_topology_get_support().

La bandera HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT realmente importa los bits de soporte desde la máquina remota. También establece la bandera imported_support en el array de la struct hwloc_topology_misc_support . Si el XML importado no contenía ninguna información de soporte (el hwloc exportador es demasiado antiguo), esta bandera no se establece.

Nótese que estas características soportadas solo son relevantes para la instalación de hwloc que realmente exportó la topología XML (puede variar con el sistema operativo, o con cómo se compiló hwloc).

Nótese que establecer esta bandera sin embargo no habilita el enlace para la topología de hwloc importada localmente, solo reporta lo que el hwloc remoto y la máquina soportan.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
No considerar recursos fuera del enlace de CPU del proceso. Si el enlace del proceso está limitado a un subconjunto de núcleos, ignorar los otros núcleos durante ladescubrimiento.

La topología resultante es idéntica a la que generaría una llamada a hwloc_topology_restrict(), pero esta bandera también impide que hwloc toque otros recursos durante el descubrimiento.

Esta bandera indica especialmente al backend x86 que nunca realinee temporalmente un hilo en cualquier núcleo excluido. Esto es útil en Windows porque tal realineación temporal puede cambiar la vinculación del proceso. Otro caso de uso es evitar núcleos que no podrían realizar el descubrimiento de hwloc pronto porque están ocupados ejecutando tareas de tiempo real de alta prioridad.

Si no se soporta la vinculación de CPU del proceso, se considera la vinculación de CPU del hilo si está disponible, o se ignora la bandera.

Esta bandera requiere HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM además, ya que se requiere soporte de vinculación.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
No considerar recursos fuera de la vinculación de memoria del proceso. Si la vinculación del proceso está limitada a un subconjunto de nodos NUMA, ignorar los otros nodos NUMA durante el descubrimiento.

La topología resultante es idéntica a la que generaría una llamada a hwloc_topology_restrict(), pero esta bandera también impide que hwloc toque otros recursos durante el descubrimiento.

Esta bandera está destinada a usarse junto con HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING cuando se deben ignorar tanto núcleos como nodos NUMA fuera de la vinculación del proceso.

Si no se soporta la vinculación de memoria del proceso, se considera la vinculación de memoria del hilo si está disponible, o se ignora la bandera.

Esta bandera requiere HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM además, ya que se requiere soporte de vinculación.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Nunca modificar la vinculación del proceso o del hilo durante el descubrimiento. Esta bandera deshabilita todos los pasos de descubrimiento de hwloc que requieren un cambio de la vinculación del proceso o del hilo. Esto afecta actualmente solo al backend x86, que queda completamente deshabilitado.

Esto es útil cuando se llama a hwloc_topology_load() mientras la aplicación crea hilos adicionales o modifica la vinculación.

Esta bandera también es una forma estricta de asegurarse de que la vinculación del proceso no cambie debido a cambios de vinculación de hilos en Windows (ver HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING).

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignorar las distancias. Ignorar la información de distancia de los sistemas operativos (y de XML) y, por lo tanto, no usar las distancias para agrupar.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignorar los atributos de memoria y las jerarquías. Ignorar los atributos de memoria de los sistemas operativos (y de XML). Por lo tanto, tampoco intentar construir jerarquías de memoria.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Ignorar los tipos de CPU. Ignorar la información de tipo de CPU de los sistemas operativos (y de XML).

enum hwloc_type_filter_e

Banderas de filtrado de tipos. Por defecto, la mayoría de los objetos se mantienen (HWLOC_TYPE_FILTER_KEEP_ALL). Las cachés de instrucciones, las cachés de memoria, los objetos de entrada/salida y Misc se ignoran por defecto (HWLOC_TYPE_FILTER_KEEP_NONE). Los niveles de grupo se ignoran a menos que aporten estructura (HWLOC_TYPE_FILTER_KEEP_STRUCTURE).

Tenga en cuenta que los objetos de grupo también se ignoran individualmente (sin todo el nivel) cuando no aportan estructura.

Enumerador

HWLOC_TYPE_FILTER_KEEP_ALL
Mantener todos los objetos de este tipo. No se puede establecer para HWLOC_OBJ_GROUP (los grupos están diseñados solo para añadir más estructura a la topología).
HWLOC_TYPE_FILTER_KEEP_NONE
Ignorar todos los objetos de este tipo. El tipo de nivel inferior HWLOC_OBJ_PU, el tipo HWLOC_OBJ_NUMANODE y el tipo de nivel superior HWLOC_OBJ_MACHINE no pueden ser ignorados.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Ignorar solo los objetos si todo su nivel no aporta ninguna estructura. Mantener todo el nivel de objetos si al menos uno de estos objetos añade estructura a la topología. Un objeto aporta estructura cuando tiene múltiples hijos y no es el único hijo de su padre.

Si todos los objetos en el nivel son el único hijo de su padre, y si ninguno de ellos tiene múltiples hijos, se elimina todo el nivel.

No se puede establecer para objetos de entrada/salida y Misc, ya que la estructura de la topología no importa allí.

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Mantener solo los objetos probablemente importantes del tipo dado. Solo es útil para tipos de objetos de entrada/salida. Para HWLOC_OBJ_PCI_DEVICE y HWLOC_OBJ_OS_DEVICE, significa que solo se mantienen objetos de clases principales/comunes (almacenamiento, red, OpenFabrics, CUDA, OpenCL, RSMI, NVML y pantallas). Además, solo se reportan dispositivos OS conectados directamente a PCI (por ejemplo, no USB). Para HWLOC_OBJ_BRIDGE, significa que se mantienen los puentes solo si tienen hijos.

Esta bandera es equivalente a HWLOC_TYPE_FILTER_KEEP_ALL para tipos Normales, Memoria y Misc, ya que probablemente son importantes.

Documentación de Funciones

unsigned long hwloc_topology_get_flags (hwloc_topology_t topology)

Obtener las banderas OR'adas de una topología. Obtener el conjunto OR'ado de hwloc_topology_flags_e de una topología.

Si no se llamó a hwloc_topology_set_flags() previamente, no hay banderas establecidas (se devuelve 0).

Retorna

las banderas previamente establecidas con hwloc_topology_set_flags().

Nota

Esta función también puede llamarse después de hwloc_topology_load().

const struct hwloc_topology_support * hwloc_topology_get_support (hwloc_topology_t restrict topology)

Obtener el soporte de la topología. Cada bandera indica si una característica está soportada. Si está establecida en 0, la característica no está soportada. Si está establecida en 1, la característica está soportada, pero la llamada correspondiente aún puede fallar en algunos casos límite.

Estas características también se listan con hwloc-info --support

Las características reportadas son las que la topología actual soporta en la máquina actual. Si la topología se exportó a XML desde otra máquina y luego se importó aquí, el soporte sigue describiendo lo que está soportado para esta topología importada después de la importación. Por defecto, la vinculación se reportará como no soportada en este caso (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM).

La bandera de topología HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT puede usarse para reportar las características soportadas de la máquina remota original en lugar de las actuales. Si se importó con éxito, imported_support se establecerá en el struct hwloc_topology_misc_support array.

Retorna

Un puntero a una estructura de soporte.

Nota

La función no puede devolver NULL.

El puntero devuelto no debe liberarse, pertenece a la biblioteca hwloc.

Esta función puede llamarse antes o después de hwloc_topology_load(), pero la estructura de soporte solo contiene información válida después.

int hwloc_topology_get_type_filter (hwloc_topology_t topology, hwloc_obj_type_t type, enum hwloc_type_filter_e * filter)

Obtener el filtrado actual para el tipo de objeto dado.

Retorna

0 en caso de éxito, -1 en caso de error.

void * hwloc_topology_get_userdata (hwloc_topology_t topology)

Obtener el puntero de datos de usuario específicos de la topología. Obtener el puntero de datos privados dados por la aplicación que se estableció previamente con hwloc_topology_set_userdata().

Retorna

Un puntero a los datos privados si los hay.

NULL si no se establecieron previamente datos privados.

int hwloc_topology_is_thissystem (hwloc_topology_t restrict topology)

¿Proviene el contexto de la topología de este sistema?

Retorna

1 si este contexto de topología se construyó usando el sistema que ejecuta este programa.

0 en su lugar (por ejemplo, si se usa otra raíz de sistema de archivos, un archivo de topología XML o una topología sintética).

Nota

Esta función también puede llamarse después de hwloc_topology_load().

int hwloc_topology_set_all_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtrado para todos los tipos de objetos. Si algunos tipos no soportan este filtrado, se ignoran silenciosamente.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_topology_set_cache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtrado para todos los tipos de objetos de caché de CPU. Las cachés del lado de la memoria no están involucradas ya que no son cachés de CPU.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Establece los flags unidos con OR en una topología aún no cargada. Establece un conjunto de flags unidos con OR de hwloc_topology_flags_e en una topología que aún no ha sido cargada.

Si esta función se llama varias veces, la última invocación borrará y reemplazará el conjunto de flags que fue establecido previamente.

Por defecto, no se establecen flags (0).

Los flags establecidos en una topología pueden ser obtenidos con hwloc_topology_get_flags().

Devuelve

0 en caso de éxito.

-1 en caso de error, por ejemplo si los flags son inválidos.

int hwloc_topology_set_icache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtrado para todos los tipos de objetos de caché de instrucciones de CPU. Las cachés del lado de la memoria no están involucradas ya que no son cachés de CPU.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_topology_set_io_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Establece el filtrado para todos los tipos de objetos de E/S.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_topology_set_type_filter (hwloc_topology_t topology, hwloc_obj_type_t type, enum hwloc_type_filter_e filter)

Establece el filtrado para el tipo de objeto dado.

Devuelve

0 en caso de éxito, -1 en caso de error.

void hwloc_topology_set_userdata (hwloc_topology_t topology, const void * userdata)

Establece el puntero de datos privados específico de la topología. Cada topología puede almacenar un puntero de datos privados proporcionado por la aplicación. Se inicializa a NULL. hwloc nunca lo modificará.

Úselo como desee, después de hwloc_topology_init() y hasta hwloc_topolog_destroy().

Este puntero no se exporta a XML.
