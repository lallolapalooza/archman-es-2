hg-clone(1)

Paquete: mercurial

Licencias: GPL

HG(CLONE) HG(CLONE)

NOMBRE

hg clone - crea una copia de un repositorio existente

SINOPSIS

hg clone [OPCIÓN]... ORIGEN [DESTINO]

DESCRIPCIÓN

Crea una copia de un repositorio existente en un nuevo directorio.

Si no se especifica un nombre de directorio de destino, por defecto se usa el nombre base del origen.

La ubicación del origen se añade al archivo .hg/hgrc del nuevo repositorio, como el predeterminado para futuras operaciones de extracción (pull).

Solo se admiten rutas locales y ssh:// URLs como destinos. Para destinos ssh:// , no se creará un directorio de trabajo ni un archivo .hg/hgrc en el lado remoto.

Si el repositorio de origen tiene un marcador (bookmark) llamado '@' establecido, esa revisión se seleccionará por defecto en el nuevo repositorio.

Para seleccionar una versión particular, usa -u/--update, o -U/--noupdate para crear un clon sin directorio de trabajo.

Para extraer solo un subconjunto de cambiosets, especifica una o más identificadores de revisión con -r/--rev o ramas con -b/--branch. El clon resultante contendrá solo los cambiosets especificados y sus ancestros. Estas opciones (o 'clone src#rev dest') implican --pull, incluso para repositorios de origen locales.

En el modo de clonado normal, el lado remoto normaliza los datos del repositorio en un formato de intercambio común y el lado receptor traduce estos datos a su formato de almacenamiento local. --stream activa un modo de clonado diferente que esencialmente copia los archivos del repositorio desde el remoto con un procesamiento mínimo de datos. Esto reduce significativamente el costo de CPU de un clon tanto en remoto como en local. Sin embargo, a menudo aumenta el tamaño de los datos transferidos en un 30-40%. Esto puede resultar en clonados sustancialmente más rápidos donde el rendimiento de E/S es abundante, especialmente para repositorios más grandes. Un efecto secundario de los clonados con --stream es que la configuración y los requisitos de almacenamiento del remoto se aplican localmente: un cliente moderno puede heredar almacenamiento heredado o ineficiente usado por el remoto, o un cliente Mercurial heredado puede no poder clonar desde un remoto Mercurial moderno.

Nota
Especificar una etiqueta incluirá el changeset etiquetado pero no el changeset que contiene la etiqueta.

Por eficiencia, se usan enlaces duros para clonar siempre que el origen y el destino estén en el mismo sistema de archivos (ten en cuenta que esto aplica solo a los datos del repositorio, no al directorio de trabajo). Algunos sistemas de archivos, como AFS, implementan los enlaces duros de forma incorrecta, pero no reportan errores. En estos casos, usa la opción --pull para evitar el enlazado duro.

Mercurial actualizará el directorio de trabajo a la primera revisión aplicable de esta lista:

a.
null si se usa -U o el repositorio de origen no tiene cambiosets
b.
si se usa -u . y el repositorio de origen es local, el primer padre del directorio de trabajo del repositorio de origen
c.
el changeset especificado con -u (si es un nombre de rama, esto significa la última cabeza de esa rama)
d.
el changeset especificado con -r
e.
la cabeza más reciente especificada con -b
f.
la cabeza más reciente especificada con la sintaxis de origen url#branch
g.
la revisión marcada con el marcador '@', si está presente
h.
la cabeza más reciente de la rama por defecto
i.
tip

Al clonar desde servidores que lo admiten, Mercurial puede obtener datos pregenerados desde una URL anunciada por el servidor o en línea desde el mismo flujo. Cuando esto ocurre, los ganchos (hooks) que operan sobre los cambiosets entrantes y los grupos de cambios (changegroups) pueden dispararse más de una vez, una vez por cada paquete pregenerado y también por cualquier dato adicional restante. Además, si ocurre un error, el repositorio puede retrocederse a un clon parcial. Este comportamiento puede cambiar en versiones futuras. Ver hg help -e clonebundles para más información.

Ejemplos:

  • clonar un repositorio remoto a un nuevo directorio llamado hg/: 
    hg clone https://www.mercurial-scm.org/repo/hg/
  • crear un clon local ligero: 
    hg clone project/ project-feature/
  • clonar desde una ruta absoluta en un servidor ssh (nota la barra doble): 
    hg clone ssh://user@server//home/projects/alpha/
  • hacer un clon en streaming mientras se selecciona una versión especificada: 
    hg clone --stream http://server/repo -u 1.5
  • crear un repositorio sin cambiosets después de una revisión particular: 
    hg clone -r 04e544 experimental/ good/
  • clonar (y rastrear) una rama con nombre particular: 
    hg clone https://www.mercurial-scm.org/repo/hg/#stable

    Ver hg help urls para detalles sobre cómo especificar URLs.

    Devuelve 0 en caso de éxito.

OPCIONES

-U, --noupdate
el clon incluirá un directorio de trabajo vacío (solo un repositorio)
-u,--updaterev<REV>
revisión, etiqueta o rama para seleccionar
-r,--rev<REV[+]>
no clonar todo, sino incluir este changeset y sus ancestros
-b,--branch<BRANCH[+]>
no clonar todo, sino incluir los cambiosets de esta rama y sus ancestros
--pull
usar el protocolo de extracción (pull) para copiar metadatos
--uncompressed
un alias para --stream (OBSOLETO)
--stream
clonar con procesamiento mínimo de datos
-e,--ssh<CMD>
especificar el comando ssh a usar
--remotecmd<CMD>
especificar el comando hg a ejecutar en el lado remoto
--insecure
no verificar el certificado del servidor (ignorando la configuración web.cacerts)

[+] la opción marcada puede especificarse varias veces
