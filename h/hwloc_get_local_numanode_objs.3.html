Descripción Detallada

Las plataformas con memoria heterogénea requieren formas de decidir si un búfer debe asignarse en memoria 'rápida' (como HBM), memoria 'normal' (DDR) o incluso memoria 'lenta' pero de gran capacidad (memoria no volátil). Estos nodos de memoria se denominan 'Destinos' mientras que la CPU que accede a ellos se denomina el 'Iniciador'. El rendimiento del acceso depende de su localidad (plataformas NUMA) así como del rendimiento intrínseco de los destinos (plataformas heterogéneas).

Los siguientes atributos describen el rendimiento de los accesos a memoria desde un Iniciador a un Destino de memoria, por ejemplo su latencia o ancho de banda. Los Iniciadores que realizan estos accesos a memoria son generalmente algunas UPs o Núcleos (descritos como un conjunto de CPU). Por lo tanto, un Núcleo puede elegir dónde asignar un búfer de memoria comparando los atributos de diferentes nodos de memoria de destino cercanos.

También hay algunos atributos que son de todo el sistema. Su valor no depende de un iniciador específico que realice un acceso. La capacidad del nodo de memoria es un ejemplo de tal atributo sin iniciador.

Una forma de usar esta API es comenzar con un cpuset que describa los Núcleos a los que está vinculado un programa. El mejor nodo NUMA de destino para asignar memoria en este programa en estos Núcleos puede obtenerse pasando este cpuset como un iniciador a hwloc_memattr_get_best_target() con el atributo de memoria relevante. Por ejemplo, si el código está limitado por la latencia, use el atributo Latencia.

Un enfoque más flexible consiste en obtener la lista de los nodos NUMA locales pasando este cpuset a hwloc_get_local_numanode_objs(). Los valores de los atributos para estos nodos, si los hay, pueden obtenerse con hwloc_memattr_get_value() y compararse manualmente con los criterios deseados.

Los atributos de memoria también se usan internamente para construir Niveles de Memoria que proporcionan una forma fácil de distinguir nodos NUMA de diferentes tipos, como se explica en Memoria Heterogénea.

Además de los niveles, hwloc define un conjunto de nodos 'predeterminados' donde se deben realizar las asignaciones normales de memoria (véase hwloc_topology_get_default_nodeset()). Esto también es útil para dividir la máquina en un conjunto de dominios NUMA no superpuestos, por ejemplo, para vincular tareas por dominio.

Véase también

Un ejemplo está disponible en doc/examples/memory-attributes.c en el árbol de fuentes.

Nota

La API también admite objetos específicos como iniciador, pero actualmente no se usa internamente por hwloc. Los usuarios pueden, por ejemplo, usarlo para proporcionar valores de rendimiento personalizados para accesos a memoria de host realizados por GPUs.

La interfaz también acepta destinos que no son nodos NUMA.

Documentación de Tipos de Enumeración

enum hwloc_local_numanode_flag_e

Banderas para seleccionar nodos NUMA de destino.

Enumerador

HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY
Selecciona nodos NUMA cuya localidad es mayor que el cpuset dado. Por ejemplo, si se da una sola UP (o su cpuset) en el iniciador, selecciona todos los nodos cercanos al paquete que contiene esta UP.
HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY
Selecciona nodos NUMA cuya localidad es menor que el cpuset dado. Por ejemplo, si se da un paquete (o su cpuset) en el iniciador, también selecciona nodos que están unidos solo a la mitad de ese paquete.
HWLOC_LOCAL_NUMANODE_FLAG_INTERSECT_LOCALITY
Selecciona nodos NUMA cuya localidad intersecta el cpuset dado. Esto incluye localidades más grandes y más pequeñas, así como localidades que están parcialmente incluidas. Por ejemplo, si la localidad es un núcleo de ambos paquetes, un nodo NUMA local a un paquete no es ni más grande ni más pequeño que esta localidad, pero la intersecta.
HWLOC_LOCAL_NUMANODE_FLAG_ALL
Selecciona todos los nodos NUMA en la topología. El iniciador initiator se ignora.

enum hwloc_memattr_id_e

Predefined memory attribute IDs. See hwloc_memattr_id_t for the generic definition of IDs for predefined or custom attributes.

Enumerator

HWLOC_MEMATTR_ID_CAPACITY
The "Capacity" is returned in bytes (local_memory attribute in objects). Best capacity nodes are nodes with higher capacity.

No initiator is involved when looking at this attribute. The corresponding attribute flags are HWLOC_MEMATTR_FLAG_HIGHER_FIRST.

Capacity values may not be modified using hwloc_memattr_set_value().

HWLOC_MEMATTR_ID_LOCALITY
The "Locality" is returned as the number of PUs in that locality (e.g. the weight of its cpuset). Best locality nodes are nodes with smaller locality (nodes that are local to very few PUs). Poor locality nodes are nodes with larger locality (nodes that are local to the entire machine).

No initiator is involved when looking at this attribute. The corresponding attribute flags are HWLOC_MEMATTR_FLAG_HIGHER_FIRST.

Locality values may not be modified using hwloc_memattr_set_value().

HWLOC_MEMATTR_ID_BANDWIDTH
The "Bandwidth" is returned in MiB/s, as seen from the given initiator location. Best bandwidth nodes are nodes with higher bandwidth.

The corresponding attribute flags are HWLOC_MEMATTR_FLAG_HIGHER_FIRST and HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

This is the average bandwidth for read and write accesses. If the platform provides individual read and write bandwidths but no explicit average value, hwloc computes and returns the average.

HWLOC_MEMATTR_ID_READ_BANDWIDTH
The "ReadBandwidth" is returned in MiB/s, as seen from the given initiator location. Best bandwidth nodes are nodes with higher bandwidth.

The corresponding attribute flags are HWLOC_MEMATTR_FLAG_HIGHER_FIRST and HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

HWLOC_MEMATTR_ID_WRITE_BANDWIDTH
The "WriteBandwidth" is returned in MiB/s, as seen from the given initiator location. Best bandwidth nodes are nodes with higher bandwidth.

The corresponding attribute flags are HWLOC_MEMATTR_FLAG_HIGHER_FIRST and HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

HWLOC_MEMATTR_ID_LATENCY
The "Latency" is returned as nanoseconds, as seen from the given initiator location. Best latency nodes are nodes with smaller latency.

The corresponding attribute flags are HWLOC_MEMATTR_FLAG_LOWER_FIRST and HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

This is the average latency for read and write accesses. If the platform provides individual read and write latencies but no explicit average value, hwloc computes and returns the average.

HWLOC_MEMATTR_ID_READ_LATENCY
The "ReadLatency" is returned as nanoseconds, as seen from the given initiator location. Best latency nodes are nodes with smaller latency.

The corresponding attribute flags are HWLOC_MEMATTR_FLAG_LOWER_FIRST and HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

HWLOC_MEMATTR_ID_WRITE_LATENCY
The "WriteLatency" is returned as nanoseconds, as seen from the given initiator location. Best latency nodes are nodes with smaller latency.

The corresponding attribute flags are HWLOC_MEMATTR_FLAG_LOWER_FIRST and HWLOC_MEMATTR_FLAG_NEED_INITIATOR.

Function Documentation

int hwloc_get_local_numanode_objs(hwloc_topology_t topology, struct hwloc_location *location, unsigned *nr, hwloc_obj_t *nodes, unsigned long flags)

Return an array of local NUMA nodes. By default only select the NUMA nodes whose locality is exactly the given location. More nodes may be selected if additional flags are given as a OR'ed set of hwloc_local_numanode_flag_e.

If location is given as an explicit object, its CPU set is used to find NUMA nodes with the corresponding locality. If the object does not have a CPU set (e.g. I/O object), the CPU parent (where the I/O object is attached) is used.

On input, nr points to the number of nodes that may be stored in the nodes array. On output, nr will be changed to the number of stored nodes, or the number of nodes that would have been stored if there were enough room.

Returns

0 on success or -1 on error.

Note

Some of these NUMA nodes may not have any memory attribute values and hence not be reported as actual targets in other functions.

The number of NUMA nodes in the topology (obtained by hwloc_bitmap_weight() on the root object nodeset) may be used to allocate the nodes array.

When an object CPU set is given as locality, for instance a Package, and when flags contain both HWLOC_LOCAL_NUMANODE_FLAG_LARGER_LOCALITY and HWLOC_LOCAL_NUMANODE_FLAG_SMALLER_LOCALITY, the returned array corresponds to the nodeset of that object.

int hwloc_memattr_get_best_initiator(hwloc_topology_t topology, hwloc_memattr_id_t attribute, hwloc_obj_t target_node, unsigned long flags, struct hwloc_location *best_initiator, hwloc_uint64_t *value)

Return the best initiator for the given attribute and target NUMA node. If value is non NULL, the corresponding value is returned there.

If multiple initiators have the same attribute values, only one is returned (and there is no way to clarify how that one is chosen). Applications that want to detect initiators with identical/similar values, or that want to look at values for multiple attributes, should rather get all values using hwloc_memattr_get_value() and manually select the initiator they consider the best.

The returned initiator should not be modified or freed, it belongs to the topology.

target_node cannot be NULL.

flags must be 0 for now.

Returns

0 on success.

-1 with errno set to ENOENT if there are no matching initiators.

-1 with errno set to EINVAL if the attribute does not relate to a specific initiator (it does not have the flag HWLOC_MEMATTR_FLAG_NEED_INITIATOR).

int hwloc_memattr_get_best_target(hwloc_topology_t topology, hwloc_memattr_id_t attribute, struct hwloc_location *initiator, unsigned long flags, hwloc_obj_t *best_target, hwloc_uint64_t *value)

Return the best target NUMA node for the given attribute and initiator. If the attribute does not relate to a specific initiator (it does not have the flag HWLOC_MEMATTR_FLAG_NEED_INITIATOR), location initiator is ignored and may be NULL.

If value is non NULL, the corresponding value is returned there.

If multiple targets have the same attribute values, only one is returned (and there is no way to clarify how that one is chosen). Applications that want to detect targets with identical/similar values, or that want to look at values for multiple attributes, should rather get all values using hwloc_memattr_get_value() and manually select the target they consider the best.

flags must be 0 for now.

Returns

0 on success.

-1 with errno set to ENOENT if there are no matching targets.

-1 with errno set to EINVAL if flags are invalid, or no such attribute

existe.

Nota

El iniciador initiator debe ser de tipo HWLOC_LOCATION_TYPE_CPUSET al referirse a accesos realizados por núcleos de CPU. HWLOC_LOCATION_TYPE_OBJECT actualmente no es utilizado internamente por hwloc, pero los usuarios pueden, por ejemplo, usarlo para proporcionar información personalizada sobre accesos a memoria del host realizados por GPUs.

int hwloc_memattr_get_initiators (hwloc_topology_t topology, hwloc_memattr_id_t attribute, hwloc_obj_t target_node, unsigned long flags, unsigned * nr, struct hwloc_location * initiators, hwloc_uint64_t * values)

Devuelve los iniciadores que tienen valores para un atributo dado para un nodo NUMA de destino específico. Devuelve los iniciadores para el atributo y nodo de destino dados en el array initiators. Si values no es NULL, los valores de atributo correspondientes se almacenan en el array al que apunta.

En la entrada, nr apunta al número de iniciadores que pueden almacenarse en el array initiators (y values). En la salida, nr apunta al número de iniciadores (y valores) que se encontraron realmente, incluso si algunos de ellos no pudieron almacenarse en el array. Los iniciadores que no pudieron almacenarse se ignoran, pero la función aún devuelve éxito (0). El llamador puede averiguarlo comparando el valor apuntado por nr antes y después de la llamada a la función.

Los iniciadores devueltos no deben modificarse ni liberarse, pertenecen a la topología.

target_node no puede ser NULL.

flags debe ser 0 por ahora.

Si el atributo no está relacionado con un iniciador específico (no tiene la bandera HWLOC_MEMATTR_FLAG_NEED_INITIATOR), no se devuelve ningún iniciador.

Devuelve

0 si tiene éxito o -1 si hay un error.

Nota

Esta función está destinada a herramientas y depuración (listado de información interna) en lugar de a consultas de aplicaciones. Las aplicaciones deberían seleccionar más bien nodos NUMA útiles con hwloc_get_local_numanode_objs() y luego examinar sus valores de atributo para algunos iniciadores relevantes.

int hwloc_topology_get_default_nodeset (hwloc_topology_t topology, hwloc_nodeset_t nodeset, unsigned long flags)

Devuelve el conjunto de nodos NUMA predeterminados. En máquinas con memoria heterogénea, algunos nodos NUMA se consideran predeterminados, es decir, de dónde deben realizarse las asignaciones básicas. Estos suelen ser nodos DRAM.

Otros nodos pueden reservarse para usos específicos (memoria de dispositivos de E/S, por ejemplo, memoria de GPU), memoria pequeña pero de alto rendimiento (HBM), memoria grande pero lenta (NVM), etc. Normalmente no se deben asignar búferes desde allí a menos que se requiera explícitamente.

Esta función llena nodeset con los bits de los nodos NUMA considerados predeterminados.

Se garantiza que estos nodos tienen conjuntos de CPU que no se intersecan, es decir, los núcleos ya no pueden tener múltiples nodos NUMA locales. Por lo tanto, esto puede usarse para iterar sobre la plataforma dividida en localidades NUMA separadas, por ejemplo, para vincular una tarea por dominio NUMA.

Cualquier núcleo que tuviera algún nodo NUMA local en la topología inicial todavía debería tener uno en el conjunto de nodos predeterminados. Los casos extremos en los que esto sería incorrecto consisten en plataformas asimétricas con nodos DRAM faltantes, o topologías que ya se restringieron a menos nodos NUMA.

El conjunto de nodos devuelto puede pasarse a hwloc_topology_restrict() con HWLOC_RESTRICT_FLAG_BYNODESET para eliminar todos los nodos no predeterminados de la topología. La topología resultante será más fácil de usar al iterar sobre nodos NUMA (ahora homogéneos).

Las heurísticas para encontrar nodos predeterminados se basan en los niveles y subtipos de memoria (ver Memoria Heterogénea) así como la suposición de que los proveedores de hardware listan los nodos predeterminados primero en las tablas de hardware.

flags debe ser 0 por ahora.

Devuelve

0 si tiene éxito.

-1 en caso de error.

Nota

El conjunto de nodos devuelto generalmente contiene todos los nodos de un solo nivel de memoria, probablemente el de DRAM.

El conjunto de nodos devuelto está incluido en la lista de nodos disponibles devuelta por hwloc_topology_get_topology_nodeset(). Es estrictamente más pequeño si la máquina tiene memoria heterogénea.

Las heurísticas pueden devolver un conjunto subóptimo de nodos si hwloc no pudo adivinar los tipos de memoria y/o si algunos nodos predeterminados se eliminaron anteriormente de la topología (por ejemplo, con hwloc_topology_restrict()).
