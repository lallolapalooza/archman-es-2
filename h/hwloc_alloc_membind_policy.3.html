Descripción

Detallada

El enlazado de memoria se puede realizar de tres

maneras:
  • asignación de memoria explícita gracias a hwloc_alloc_membind() y relacionadas: el enlazado tendrá efecto sobre la memoria asignada por estas
    • funciones.
  • enlazamiento de memoria implícito a través de la política de enlazamiento: hwloc_set_membind() y relacionadas solo definen la política actual del proceso, que se aplicará a las llamadas subsecuentes a malloc() y
    • relacionadas.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y relacionada
    • s, que mueven datos
ya asignados.

No todos los sistemas operativos soportan las tres formas. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlazamiento de memoria en el sistema operativo actualmente en

uso.

Cuando la operación de enlazamiento solicitada no está disponible y se pasó el flag HWLOC_MEMBIND_STRICT, la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema no soporte la acción o política especificada (por ejemplo, algunos sistemas solo permiten enlazar memoria de forma por-hilo, mientras que otros sistemas solo permiten enlazar memoria para todos los hilos de un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no pueda aplicarse (por ejemplo, algunos sistemas solo permiten enlazar memoria a un solo nodo NUMA)

.

Si no se pasó HWLOC_MEMBIND_STRICT, la función también puede fallar, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, un conjunto de enlazamiento más pequeño, etc.) cuando la operación solicitada no esté exactamente

soportada.

La forma más portable, que debería preferirse sobre las demás siempre que sea posible, es la siguiente. Asigna algo de memoria que se espera esté enlazada al conjunto especificado. Para hacerlo, hwloc posiblemente tendrá que cambiar la política de enlazamiento de memoria actual para realmente obtener la memoria enlazada, si el SO no proporciona ninguna otra manera de asignar simplemente memoria enlazada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), que nunca cambiará la política de enlazamiento de memoria

actual. 
hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0)
;

Cada función de enlazamiento de memoria de hwloc toma un argumento de mapa de bits que es un conjunto de CPU por defecto, o un conjunto de nodos de memoria NUMA si se especifica el flag HWLOC_MEMBIND_BYNODESET. Ver Conjuntos de Objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API de mapas de bits para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_n

odeset().

El enlazamiento de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, el enlazamiento por conjunto de nodos debería preferirse siempre que sea

posible.

enum hwloc_membind_flags_

t

Flags de enlazamiento de memoria. Estos flags pueden usarse para refinar la política de enlazamiento. Todos los flags pueden combinarse lógicamente con OR, con la excepción de HWLOC_MEMBIND_PROCESS y HWLOC_MEMBIND_THREAD; estos dos flags son mutuamente

excluyentes.

No todos los sistemas soportan todos los tipos de enlazamiento. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlazamiento de memoria en el sistema operativo actualmente en uso. Ver la sección 'Descripción Detallada' de Enlazamiento de memoria para una descripción de los errores que pueden

ocurrir.

Enumerador

HWLOC_MEMBIND_PROCESS
Establece la política para todos los hilos del proceso especificado (posiblemente multihilo). Este flag es mutuamente excluyente con HWLOC_MEMBIND_
THREAD.
HWLOC_MEMBIND_THREAD
Establece la política para un hilo específico del proceso actual. Este flag es mutuamente excluyente con HWLOC_MEMBIND_PROCE
SS.
HWLOC_MEMBIND_STRICT
Solicita enlazamiento estricto al SO. La fun
ción fallará si el enlazamiento no pue
de ser garantizado / completamente aplicado.

Este flag tiene significados ligeramente diferentes dependiendo con qué función se

use.
HWLOC_MEMBIND_MIGRATE
Migra memoria ya asignada. Si la memoria no puede ser migrada y se pasó el flag HWLOC_MEMBIND_STRICT, se devolverá un
error.
HWLOC_MEMBIND_NOCPUBIND
Evita cualquier efecto sobre el enlazamiento de CPU. En algunos sistemas operativos, algunas funciones subyacentes de enlazamiento de memoria también enlazan la aplicación a el/los CPU correspondiente(s). Usar este flag hará que hwloc evite usar funciones del SO que podrían potencialmente afectar los enlazamientos de CPU. Nótese, sin embargo, que usar NOCPUBIND puede reducir el soporte general de enlazamiento de memoria de hwloc. Específicamente: algunas de las funciones de enlazamiento de memoria de hwloc pueden fallar con errno establecido a ENOSYS cuando se usan con
NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considera el argumento de mapa de bits como un conjunto de nodos. El
argumento de mapa de bits es considerado un conjunto de nodos si
se da este flag, o un conjunto de CPU por defecto en caso contrario.

El enlazamiento de memoria por conjunto de CPU no puede funcionar pa

ra nodos de memoria NUMA sin CPU. Por lo tanto, el enlazamiento
por conjunto de nodos debería preferirse siempre que sea posible.

enum hwloc_membind_policy_

t

Política de asignación de memoria. Estas constantes se pueden utilizar para elegir la política de asignación. Solo se puede usar una política a la vez (es decir, los valores no se pueden combinar con la operación OR)

.

No todos los sistemas soportan todos los tipos de asignación. hwloc_topology_get_support() puede usarse para consultar el soporte real de la política de asignación de memoria en el sistema operativo actualmente en uso. Véase la sección 'Descripción Detallada' de Asignación de memoria para una descripción de los errores que pueden

ocurrir.

Enumerador

HWLOC_MEMBIND_DEFAULT
Restablece la política de asignación de memoria a la predeterminada del sistema. Dependiendo del sistema operativo, esto puede corresponder a HWLOC_MEMBIND_FIRSTTOUCH (Linux, FreeBSD), o HWLOC_MEMBIND_BIND (AIX, HP-UX, Solaris, Windows). Esta política nunca es devuelta por las funciones de obtención de membind. El argumento nodeset es
ignorado.
HWLOC_MEMBIND_FIRSTTOUCH
Asigna cada página de memoria individualmente en el nodo NUMA local del hilo que la toca. El nodeset dado debería ser habitualmente hwloc_topology_get_topology_nodeset() para que el hilo que la t
oca pueda ejecutarse y asignars
e en cualquier nodo del sistema.

En AIX, si el nodeset es más pequeño, las páginas se asignan localmente (si el nodo local está en el nodeset) o desde un nodo no local aleatorio (en caso contrario)

.
HWLOC_MEMBIND_BIND
Asigna memoria en los nodos especificados. El comportamiento real puede variar ligeramente entre sistemas operativos, especialmente cuando (algunos de) los nodos solicitados están llenos. En Linux, por defecto, se usa la política MPOL_PREFERRED_MANY (o MPOL_PREFERRED). Sin embargo, si también se indica el flag de estricto de hwloc, se usa en su lugar la política MPOL_BIND de
Linux.
HWLOC_MEMBIND_INTERLEAVE
Asigna memoria en los nodos dados de manera entrelazada / round-robin. La disposición precisa de la memoria a través de múltiples nodos NUMA depende del sistema operativo/sistema. El entrelazado puede ser útil cuando los hilos distribuidos a través de los nodos NUMA especificados accederán todos al rango completo de memoria simultáneamente, ya que el entrelazado equilibrará entonces las referencias de
memoria.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
Asigna memoria en los nodos dados de manera entrelazada / ponderada. La disposición precisa de la memoria a través de múltiples nodos NUMA depende del sistema operativo/sistema. El entrelazado ponderado puede ser útil cuando los hilos distribuidos a través de los nodos NUMA especificados con diferentes capacidades de ancho de banda accederán todos al rango completo de memoria simultáneamente, ya que el entrelazado equilibrará entonces las referencias de
memoria.
HWLOC_MEMBIND_NEXTTOUCH
Para cada página vinculada con esta política, la próxima vez que sea tocada (y solo la próxima vez), se mueve desde su ubicación actual al nodo NUMA local del hilo donde ocurrió la referencia de memoria (si necesita ser movida en absoluto)
.
HWLOC_MEMBIND_MIXED
Devuelta por las funciones get_membind() cuando múltiples hilos
o partes de un área de memoria tienen políticas de asignación
de memoria diferentes. También se devuelve cuando la asignación
es desconocida porque los hooks de asignación están vacíos cuan
do la topología se carga desde XML sin HWLOC_THISSYSTEM=1, etc.

int hwloc_get_area_membind (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int

flags)

Consulta las CPUs cercanas al(los) nodo(s) NUMA físicos y la política de asignación de la memoria identificada por (addr, len ). El bitmap set (previamente asignado por el llamante) se rellena con la asignación del área de

memoria.

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de los flags pasados como de las políticas de asignación de memoria y los nodesets de las páginas en el rango de

direcciones.

Si HWLOC_MEMBIND_STRICT está especificado, las páginas de destino se comprueban primero para ver si todas tienen la misma política de asignación de memoria y nodeset. Si no lo tienen, se devuelve -1 y errno se establece a EXDEV. Si son idénticas en todas las páginas, el set y la política se devuelven en set y policy, respectivamente

Si HWLOC_MEMBIND_STRICT no está especificado, se calcula la unión de todos los nodos NUMA que contienen páginas en el rango de direcciones. Si todas las páginas en el destino tienen la misma política, se devuelve en policy. De lo contrario, policy se establece a HWLOC_MEMBIND_MIXED

.

Si HWLOC_MEMBIND_BYNODESET está especificado, set se considera un nodeset. De lo contrario, es un

cpuset.

Si se especifican cualquier otro flags, se devuelve -1 y errno se establece a EINVAL

int hwloc_get_membind (hwloc_topology_t topology, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int

flags)

Consulta la política de enlace de memoria predeterminada y la localidad física del proceso o hilo actual. El mapa de bits set (previamente asignado por el llamante) se rellena con el enlace de memoria del proceso o

hilo.

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de los flags pasados como de las políticas de enlace de memoria y nodesets actuales en el objetivo

consultado.

Pasar el flag HWLOC_MEMBIND_PROCESS especifica que el objetivo de la consulta son las políticas y nodesets actuales para todos los hilos en el proceso actual. Pasar HWLOC_MEMBIND_THREAD especifica que el objetivo de la consulta es la política y nodeset actuales solo para el hilo que invoca esta

función.

Si no se pasa ninguno de estos flags (que es el método más portable), se asume que el proceso es de un solo hilo. Esto permite que hwloc use funciones del SO basadas en el proceso o funciones del SO basadas en el hilo, dependiendo de cuáles estén

disponibles.

HWLOC_MEMBIND_STRICT solo tiene significado cuando HWLOC_MEMBIND_PROCESS también está especificado. En este caso, hwloc comprobará las políticas de memoria predeterminadas y los nodesets para todos los hilos en el proceso. Si no son idénticos, se devuelve -1 y se establece errno en EXDEV. Si son idénticos, los valores se devuelven en set y policy

.

De lo contrario, si HWLOC_MEMBIND_PROCESS está especificado (y HWLOC_MEMBIND_STRICT no está especificado), el conjunto predeterminado de cada hilo se combina lógicamente con OR. Si las políticas predeterminadas de todos los hilos son las mismas, policy se establece en esa política. Si son diferentes, policy se establece en HWLOC_MEMBIND_MIXED

.

En el caso HWLOC_MEMBIND_THREAD (o cuando ni HWLOC_MEMBIND_PROCESS ni HWLOC_MEMBIND_THREAD está especificado), hay solo un conjunto y una política; se devuelven en set y policy, respectivamente

.

Si HWLOC_MEMBIND_BYNODESET está especificado, set se considera un nodeset. De lo contrario, es un

cpuset.

Si se especifican otros flags, se devuelve -1 y se establece errno en EINVAL

.
