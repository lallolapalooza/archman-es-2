NOMBRE

hg graft - copiar cambios de otras ramas a la rama actual

SINOPSIS

hg graft [OPCIÓN]... [-rREV]... REV...

DESCRIPCIÓN

Este comando utiliza la lógica de fusión de Mercurial para copiar cambios individuales de otras ramas sin fusionar ramas en el grafo de historial. Esto se conoce a veces como 'backporting' o 'cherry-picking'. Por defecto, graft copiará el usuario, la fecha y la descripción de los conjuntos de cambios de origen.

Los conjuntos de cambios que son ancestros de la revisión actual, que ya han sido injertados, o que son fusiones, se omitirán.

Si se especifica --log, los mensajes de registro tendrán un comentario añadido del tipo:

(grafted from CHANGESETHASH)

Si se especifica --force, las revisiones se injertarán incluso si ya son ancestros de, o han sido injertadas en, el destino. Esto es útil cuando las revisiones han sido revertidas desde entonces.

Si una fusión de injerto resulta en conflictos, el proceso de injerto se interrumpe para que la fusión actual pueda resolverse manualmente. Una vez resueltos todos los conflictos, el proceso de injerto puede continuarse con la opción -c/--continue.

La opción -c/--continue vuelve a aplicar todas las opciones anteriores.

La opción --base expone más cómo graft utiliza internamente la fusión con una revisión base personalizada. --base se puede usar para especificar un ancestro diferente al primer y único padre.

El comando:

hg graft -r 345 --base 234

es, por lo tanto, prácticamente lo mismo que:

hg diff --from 234 --to 345 | hg import

pero utilizando la fusión para resolver conflictos y rastrear archivos movidos.

El resultado de una fusión puede, por lo tanto, ser retroportado como un solo commit especificando uno de los padres de la fusión como base, y así injertando efectivamente los cambios del otro lado.

También es posible colapsar múltiples conjuntos de cambios y limpiar el historial especificando otro ancestro como base, muy parecido a rebase --collapse --keep.

El mensaje de commit se puede ajustar después de los hechos usando commit --amend.

Para usar ancestros no existentes como base para revertir cambios, consulte el comando backout y la opción oculta --parent.

La opción experimental --to permite injertar una revisión en memoria, independientemente de la copia de trabajo. Actualmente no se admiten conflictos de fusión, y la operación se abortará si la herramienta configurada no puede manejar los conflictos que puedan encontrarse.

Dado que la operación se realiza en memoria, los archivos en disco no se modificarán y es posible que algunos hooks no se ejecuten.

Ejemplos:

  • copiar un solo cambio a la rama estable y editar su descripción: 
    hg update stable
hg graft --edit 9393
  • injertar un rango de conjuntos de cambios con una excepción, actualizando fechas: 
    hg graft -D "2085::2093 and not 2091"
  • continuar un injerto después de resolver conflictos: 
    hg graft -c
  • mostrar el origen de un conjunto de cambios injertado: 
    hg log --debug -r .
  • mostrar revisiones ordenadas por fecha: 
    hg log -r "sort(all(), date)"
  • retroportar el resultado de una fusión como un solo commit: 
    hg graft -r 123 --base 123^
  • incorporar una rama de características como un solo conjunto de cambios: 
    hg up -cr default
hg graft -r featureX --base "ancestor('featureX', 'default')"

    Consulte hg help revisions para más información sobre cómo especificar revisiones.

    Devuelve 0 si la operación se completa con éxito, 1 si hay archivos sin resolver.

OPCIONES

-r,--rev <REV[+]>
revisiones a injertar
--base <REV>
revisión base al realizar la fusión de injerto (AVANZADO)
--to <VALOR>
injertar a este destino, en memoria (EXPERIMENTAL)
-c, --continue
reanudar injerto interrumpido
--stop
detener injerto interrumpido
--abort
abortar injerto interrumpido
-e, --edit
invocar editor en los mensajes de commit
--log
añadir información del injerto al mensaje de registro
--no-commit
no hacer commit, solo aplicar los cambios en el directorio de trabajo
-f, --force
forzar injerto
-D, --currentdate
registrar la fecha actual como fecha de commit
-U, --currentuser
registrar el usuario actual como committer
-d,--date <FECHA>
registrar la fecha especificada como fecha de commit
-u,--user <USUARIO>
registrar el usuario especificado como committer
-t,--tool <HERRAMIENTA>
especificar herramienta de fusión
-n, --dry-run
no realizar acciones, solo imprimir salida

[+] la opción marcada se puede especificar varias veces
