DESCRIPCIÓN

Las funciones gethostbyname*(), gethostbyaddr*(), herror() y hstrerror() están obsoletas. Las aplicaciones deberían usar getaddrinfo(3), getnameinfo(3)y gai_strerror(3) en su lugar.

La función sethostent() especifica, si stayopen es verdadero (1), que se debe usar un socket TCP conectado para las consultas al servidor de nombres y que la conexión debe permanecer abierta durante consultas sucesivas. De lo contrario, las consultas al servidor de nombres usarán datagramas UDP.

La función endhostent() finaliza el uso de una conexión TCP para consultas al servidor de nombres.

La función gethostbyname() devuelve una estructura de tipo hostent para el host dado name. Aquí name es un nombre de host o una dirección IPv4 en notación estándar con puntos (como en inet_addr(3)). Si name es una dirección IPv4, no se realiza ninguna búsqueda y gethostbyname() simplemente copia name en el campo h_name y su equivalente struct in_addr en el campo h_addr_list[0] de la estructura hostent devuelta. Si name no termina en un punto y la variable de entorno HOSTALIASES está definida, primero se buscará name en el archivo de alias al que apunta HOSTALIASES (véase hostname(7) para el formato del archivo). Se buscan el dominio actual y sus padres a menos que name termine en un punto.

La función gethostbyaddr() devuelve una estructura de tipo hostent para la dirección de host dada addr de tamaño size y tipo de dirección type. Los tipos de dirección válidos son AF_INET y AF_INET6 (definidos en <sys/socket.h>). El argumento de dirección de host es un puntero a una estructura de un tipo que depende del tipo de dirección, por ejemplo un struct in_addr * (probablemente obtenido mediante una llamada a inet_addr(3)) para el tipo de dirección AF_INET.

La función (obsoleta) herror() imprime el mensaje de error asociado con el valor actual de h_errno en stderr.

La función (obsoleta) hstrerror() toma un número de error (típicamente h_errno) y devuelve la cadena de mensaje correspondiente.

Las consultas de nombres de dominio realizadas por gethostbyname() y gethostbyaddr() dependen de las fuentes configuradas por el Interruptor de Servicio de Nombres (nsswitch.conf(5)) o de un servidor de nombres local (named(8)). La acción por defecto es consultar las fuentes configuradas por el Interruptor de Servicio de Nombres (nsswitch.conf(5)), y en caso de fallo, un servidor de nombres local (named(8)).

Histórico

El archivo nsswitch.conf(5) es la forma moderna de controlar el orden de las búsquedas de hosts.

En glibc 2.4 y versiones anteriores, la palabra clave order se usaba para controlar el orden de las búsquedas de hosts tal como se definía en /etc/host.conf (host.conf(5)).

La estructura hostent está definida en <netdb.h> como sigue:


struct hostent {
    char  *h_name;            /* nombre oficial del host */
    char **h_aliases;         /* lista de alias */
    int    h_addrtype;        /* tipo de dirección del host */
    int    h_length;          /* tamaño de la dirección */
    char **h_addr_list;       /* lista de direcciones */
}
#define h_addr h_addr_list[0] /* para compatibilidad hacia atrás */

Los miembros de la estructura hostent son:

h_name
El nombre oficial del host.
h_aliases
Un array de nombres alternativos para el host, terminado por un puntero nulo.
h_addrtype
El tipo de dirección; siempre AF_INET o AF_INET6 en la actualidad.
h_length
El tamaño de la dirección en bytes.
h_addr_list
Un array de punteros a direcciones de red del host (en orden de bytes de red), terminado por un puntero nulo.
h_addr
La primera dirección en h_addr_list para compatibilidad hacia atrás.
