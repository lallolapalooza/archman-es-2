NOMBRE

hier - descripción de la jerarquía del sistema de archivos

DESCRIPCIÓN

Un sistema Linux típico tiene, entre otros, los siguientes directorios:

/
Este es el directorio raíz. Aquí es donde comienza todo el árbol.
/bin
Este directorio contiene programas ejecutables que son necesarios en modo de usuario único y para arrancar o reparar el sistema.
/boot
Contiene archivos estáticos para el cargador de arranque. Este directorio solo contiene los archivos que son necesarios durante el proceso de arranque. El instalador de mapas y los archivos de configuración deben ir en /sbin y /etc. El kernel del sistema operativo (initrd, por ejemplo) debe ubicarse en / o /boot.
/dev
Archivos especiales o de dispositivos, que se refieren a dispositivos físicos. Ver mknod(1).
/etc
Contiene archivos de configuración que son locales de la máquina. Algunos paquetes de software más grandes, como X11, pueden tener sus propios subdirectorios debajo de /etc. Los archivos de configuración de todo el sitio pueden colocarse aquí o en /usr/etc. Sin embargo, los programas siempre deben buscar estos archivos en /etc y usted puede tener enlaces para estos archivos en /usr/etc.
/etc/opt
Archivos de configuración específicos del host para aplicaciones complementarias instaladas en /opt.
/etc/sgml
Este directorio contiene los archivos de configuración para SGML (opcional).
/etc/skel
Cuando se crea una nueva cuenta de usuario, los archivos de este directorio generalmente se copian al directorio personal del usuario.
/etc/X11
Archivos de configuración para el sistema de ventanas X11 (opcional).
/etc/xml
Este directorio contiene los archivos de configuración para XML (opcional).
/home
En máquinas con directorios personales para usuarios, estos suelen estar debajo de este directorio, directa o indirectamente. La estructura de este directorio depende de las decisiones de administración local (opcional).
/lib
Este directorio debe contener las bibliotecas compartidas que son necesarias para arrancar el sistema y ejecutar los comandos en el sistema de archivos raíz.
/lib<qual>
Estos directorios son variantes de /lib en sistemas que soportan más de un formato binario que requiere bibliotecas separadas (opcional).
/lib/modules
Módulos del kernel cargables (opcional).
/lost+found
Este directorio contiene elementos perdidos en el sistema de archivos. Estos elementos suelen ser fragmentos de archivos dañados como consecuencia de un disco defectuoso o una caída del sistema.
/media
Este directorio contiene puntos de montaje para medios extraíbles, como discos CD y DVD o unidades USB. En sistemas donde existe más de un dispositivo para montar un cierto tipo de medio, se pueden crear directorios de montaje añadiendo un dígito al nombre de los disponibles arriba, comenzando por '0', pero el nombre sin calificar también debe existir.
/media/floppy[1-9]
Unidad de disquete (opcional).
/media/cdrom[1-9]
Unidad de CD-ROM (opcional).
/media/cdrecorder[1-9]
Grabadora de CD (opcional).
/media/zip[1-9]
Unidad Zip (opcional).
/media/usb[1-9]
Unidad USB (opcional).
/mnt
Este directorio es un punto de montaje para un sistema de archivos montado temporalmente. En algunas distribuciones, /mnt contiene subdirectorios destinados a ser utilizados como puntos de montaje para varios sistemas de archivos temporales.
/opt
Este directorio debe contener paquetes complementarios que contengan archivos estáticos.
/proc
Este es un punto de montaje para el sistema de archivos proc, que proporciona información sobre los procesos en ejecución y el kernel. Este pseudo-sistema de archivos se describe con más detalle en proc(5).
/root
Este directorio suele ser el directorio personal del usuario root (opcional).
/run
Este directorio contiene información que describe el sistema desde que se inició. En el pasado, /var/run cumplía esta función y los programas pueden seguir utilizándolo.
/sbin
Al igual que /bin, este directorio contiene comandos necesarios para arrancar el sistema, pero que normalmente no son ejecutados por usuarios normales.
/srv
Este directorio contiene datos específicos del sitio que son servidos por este sistema.
/sys
Este es un punto de montaje para el sistema de archivos sysfs, que proporciona información sobre el kernel como /proc, pero mejor estructurada, siguiendo el formalismo de la infraestructura de kobject.
/tmp
Este directorio contiene archivos temporales que pueden ser eliminados sin aviso, como por un trabajo regular o al arrancar el sistema.
/usr
Este directorio generalmente se monta desde una partición separada. Debe contener solo datos compartibles y de solo lectura, de modo que pueda ser montado por varias máquinas que ejecutan Linux.
/usr/X11R6
El sistema X-Window, versión 11 release 6 (presente en FHS 2.3, eliminado en FHS 3.0).
/usr/X11R6/bin
Binarios que pertenecen al sistema X-Window; a menudo, hay un enlace simbólico desde el más tradicional /usr/bin/X11 aquí.
/usr/X11R6/lib
Archivos de datos asociados con el sistema X-Window.
/usr/X11R6/lib/X11
Estos contienen archivos diversos necesarios para ejecutar X. A menudo, hay un enlace simbólico desde /usr/lib/X11 a este directorio.
/usr/X11R6/include/X11
Contiene archivos de cabecera necesarios para compilar programas que utilizan el sistema de ventanas X11. A menudo, hay un enlace simbólico desde /usr/include/X11 a este directorio.
/usr/bin
Este es el directorio principal para los programas ejecutables. La mayoría de los programas ejecutados por usuarios normales que no son necesarios para arrancar o reparar el sistema y que no están instalados localmente deben colocarse en este directorio.
/usr/bin/mh
Comandos para el sistema de gestión de correo MH (opcional).
/usr/bin/X11
Este es el lugar tradicional para buscar ejecutables de X11; en Linux, normalmente es un enlace simbólico a /usr/X11R6/bin.
/usr/dict
Reemplazado por /usr/share/dict.
/usr/doc
Reemplazado por /usr/share/doc.
/usr/etc
Los archivos de configuración de todo el sitio que se compartirán entre varias máquinas se pueden almacenar en este directorio. Sin embargo, los comandos siempre deben hacer referencia a esos archivos usando el directorio /etc. Los enlaces de los archivos en /etc deben apuntar a los archivos apropiados en /usr/etc.
/usr/games
Binarios para juegos y programas educativos (opcional).
/usr/include
Archivos de inclusión para el compilador C.
/usr/include/bsd
Archivos de inclusión de compatibilidad BSD (opcional).
/usr/include/X11
Archivos de inclusión para el compilador C y el sistema de ventanas X. Este suele ser un enlace simbólico a /usr/X11R6/include/X11.
/usr/include/asm
Archivos de inclusión que declaran algunas funciones de ensamblador. Este solía ser un enlace simbólico a /usr/src/linux/include/asm.
/usr/include/linux
Esto contiene información que puede cambiar de una versión del sistema a otra y solía ser un enlace simbólico a /usr/src/linux/include/linux para acceder a información específica del sistema operativo.
(Tenga en cuenta que debería haber archivos de inclusión allí que funcionen correctamente con la libc actual y en el espacio de usuario. Sin embargo, el código fuente del kernel de Linux no está diseñado para ser utilizado con programas de usuario y no sabe nada sobre la libc que está utilizando. Es muy probable que las cosas fallen si deja que /usr/include/asm y /usr/include/linux apunten a un árbol de kernel aleatorio. Los sistemas Debian no hacen esto y utilizan cabeceras de una versión de kernel conocida y buena, proporcionada en el paquete libc*-dev.)
/usr/include/g++
Archivos de inclusión para usar con el compilador GNU C++

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.
