Descripción detallada

El tipo hwloc_bitmap_t representa un conjunto de enteros (positivos o nulos). Un bitmap puede ser de tamaño infinito (todos los bits están establecidos después de cierto punto). Un bitmap puede incluso estar lleno si todos los bits están establecidos.

Los bitmaps son utilizados por hwloc para conjuntos de procesadores del sistema operativo (que pueden ser en realidad hilos de hardware) como hwloc_cpuset_t (un typedef para hwloc_bitmap_t), o conjuntos de nodos de memoria NUMA como hwloc_nodeset_t (también un typedef para hwloc_bitmap_t). Estos se usan para los campos cpuset y nodeset en la estructura hwloc_obj, ver Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t).

Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del sistema operativo. Sin embargo, los usuarios generalmente no deberían construir conjuntos de CPU y nodos manualmente (por ejemplo, con hwloc_bitmap_set()). En su lugar, se deberían usar los conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or(), etc. Por ejemplo, enlazar el hilo actual a un par de núcleos puede realizarse con:

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

Nota

La mayoría de las funciones a continuación devuelven 0 en caso de éxito y -1 en caso de error. El caso de error habitual sería un fallo interno al reasignar/extender el almacenamiento del bitmap (errno se establecería a ENOMEM). Ver también Informes de error en la API.

Varios ejemplos de uso de la API de bitmap están disponibles en el directorio doc/examples/ en el árbol de fuentes. Las pruebas de regresión, como tests/hwloc/hwloc_bitmap*.c, también hacen un uso intensivo de esta API.

Documentación de definiciones de macros

#define hwloc_bitmap_foreach_begin(id, bitmap)

Macro de bucle que itera sobre el bitmap bitmap. El bucle debe comenzar con hwloc_bitmap_foreach_begin() y terminar con hwloc_bitmap_foreach_end() seguido de un punto y coma terminal.

id es la variable del bucle; debe ser un unsigned int. La primera iteración establecerá id al índice más bajo en el bitmap. Las iteraciones sucesivas recorrerán, en orden, todos los índices restantes establecidos en el bitmap. Para ser específico: cada iteración devolverá un valor para id tal que hwloc_bitmap_isset(bitmap, id) sea verdadero.

La aserción previene que el bucle sea infinito si el bitmap está infinitamente establecido.

#define hwloc_bitmap_foreach_end()

Fin del macro de bucle que itera sobre un bitmap. Necesita un punto y coma terminal.

int hwloc_bitmap_singlify (hwloc_bitmap_t

bitmap)

Mantiene un solo índice entre los establecidos en el mapa de bits bitmap. Puede ser útil antes de la vinculación para que el proceso no tenga la posibilidad de migrar entre múltiples procesadores en la máscara original. En lugar de ejecutar la tarea en cualquier PU dentro del conjunto de CPU dado, el planificador del sistema operativo se verá obligado a ejecutarla en una sola de estas PUs. Evita una sobrecarga de migración y los "ping-pongs" de línea de caché entre

PUs.

Not

Siempre devuelve el mismo bit único cuando se llama varias veces con el mismo conjunto de entrada. hwloc_distrib() puede usarse para generar conjuntos de CPU para distribuir múltiples tareas bajo un solo objeto multi-PU.
