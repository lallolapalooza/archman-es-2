Documentación de Tipos de Enumeración

enum hwloc_topology_export_xml_flags_e

Flags para exportar topologías XML. Flags a ser proporcionados como un conjunto OR'ado a hwloc_topology_export_xml().

Enumerador

HWLOC_TOPOLOGY_EXPORT_XML_FLAG_V1
Exporta XML que puede ser cargado por hwloc v1.x. Sin embargo, la exportación puede perder algunos detalles sobre la topología.

Documentación de Funciones

int hwloc_export_obj_userdata (void * reserved, hwloc_topology_t topology, hwloc_obj_t obj, const char * name, const void * buffer, size_t length)

Exporta datos de usuario de objetos a XML. Esta función solo puede ser llamada desde dentro de la callback export() pasada a hwloc_topology_set_userdata_export_callback(). Puede ser invocada una o múltiples veces para exportar datos de usuario a XML. El contenido del buffer de longitud length se almacena con el nombre opcional name.

Al importar este archivo XML, la callback de importación (si se establece) se llamará exactamente tantas veces como se llamó a hwloc_export_obj_userdata() durante la exportación. Recibirá los argumentos name, buffer y length correspondientes.

reserved, topology y obj deben ser los primeros tres parámetros que se dieron a la callback de exportación.

Solo se pueden exportar caracteres imprimibles a los atributos de cadena XML.

Si se exportan datos binarios, la aplicación primero debe codificarlos en caracteres imprimibles (o usar hwloc_export_obj_userdata_base64()). También debe tener cuidado con los problemas de portabilidad si la exportación puede ser reimportada en una arquitectura diferente.

Retorna

0 en caso de éxito.

-1 con errno establecido en EINVAL si se pasa un carácter no imprimible en name o buffer.

int hwloc_export_obj_userdata_base64 (void * reserved, hwloc_topology_t topology, hwloc_obj_t obj, const char * name, const void * buffer, size_t length)

Codifica y exporta datos de usuario de objetos a XML. Esta función es similar a hwloc_export_obj_userdata() pero codifica el buffer de entrada en caracteres imprimibles antes de exportar. Al importar, la decodificación se realiza automáticamente antes de que los datos se pasen a la callback de importación (si la hay).

Esta función solo puede ser llamada desde dentro de la callback export() pasada a hwloc_topology_set_userdata_export_callback().

El nombre debe estar compuesto de caracteres imprimibles para la exportación a atributos de cadena XML.

La función no se ocupa de los problemas de portabilidad si la exportación puede ser reimportada en una arquitectura diferente.

Retorna

0 en caso de éxito.

-1 con errno establecido en EINVAL si se pasa un carácter no imprimible en name.

int hwloc_topology_export_xml (hwloc_topology_t topology, const char * xmlpath, unsigned long flags)

Exporta la topología a un archivo XML. Este archivo puede ser cargado más tarde a través de hwloc_topology_set_xml().

Por defecto, se utiliza el último formato de exportación, lo que significa que las versiones anteriores de hwloc (por ejemplo, v1.x) no podrán importarlo. La exportación al formato XML específico de v1.x es posible usando el flag HWLOC_TOPOLOGY_EXPORT_XML_FLAG_V1, pero puede perder algunos detalles sobre la topología. Si existe alguna posibilidad de que el archivo exportado pueda ser importado nuevamente por un proceso que use hwloc 1.x, se debería considerar detectarlo en tiempo de ejecución y usar el formato de exportación correspondiente.

flags es un conjunto OR'ado de hwloc_topology_export_xml_flags_e.

Retorna

0 en caso de éxito, o -1 en caso de error.

Nota

Ver también hwloc_topology_set_userdata_export_callback() para exportar datos de usuario de objetos específicos de la aplicación.

El puntero de datos de usuario específico de la topología se ignora al exportar a XML.

Solo se pueden exportar caracteres imprimibles a los atributos de cadena XML. Cualquier otro carácter, especialmente cualquier carácter no ASCII, se omitirá silenciosamente.

Si name es '-', la salida XML se envía a la salida estándar.

void hwloc_topology_set_userdata_export_callback (hwloc_topology_t topology, void(*)(void *reserved, hwloc_topology_t topology, hwloc_obj_t obj)

export_cb)

Establece la devolución de llamada específica de la aplicación para exportar el userdata de los objetos. El puntero userdata del objeto no se exporta a XML por defecto porque hwloc no sabe qué

contiene.

Esta función permite a las aplicaciones establecer export_cb a una función de devolución de llamada que convierta este userdata opaco en una cadena

exportable.

export_cb se invoca durante la exportación XML para cada objeto cuyo puntero userdata no es NULL. La devolución de llamada debe usar hwloc_export_obj_userdata() o hwloc_export_obj_userdata_base64() para exportar realmente algo a XML (posiblemente varias veces por objeto)

.

export_cb puede establecerse en NULL si el userdata no debe ser exportado a

XML.

void hwloc_topology_set_userdata_import_callback (hwloc_topology_t topology, void(*)(hwloc_topology_t topology, hwloc_obj_t obj, const char *name, const void *buffer, size_t length)

import_cb)

Establece la devolución de llamada específica de la aplicación para importar userdata. En la importación XML, el userdata se ignora por defecto porque hwloc no sabe cómo almacenarlo en

memoria.

Esta función permite a las aplicaciones establecer import_cb a una función de devolución de llamada que recibirá el userdata almacenado en XML y lo almacenará en el objeto como lo espera la

aplicación.

import_cb se llama durante hwloc_topology_load() tantas veces como hwloc_export_obj_userdata() fue llamado durante la exportación. La topología aún no está completamente configurada. Los atributos del objeto están listos para consultar, pero los enlaces entre objetos no lo

están.

import_cb puede ser NULL si el userdata debe ser ignorado durante la

importación.
