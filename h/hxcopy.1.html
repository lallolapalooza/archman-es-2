NOMBRE

hxcopy - copia un archivo HTML y actualiza sus enlaces relativos

SINOPSIS

hxcopy [ -i URL-antigua ] [ -o URL-nueva ] [ -s ] [ -v ] [ archivo-o-URL [ archivo-o-URL ] ]

DESCRIPCIÓN

El comando hxcopy copia su primer argumento a su segundo argumento, actualizando los enlaces relativos. Se asume que la entrada es HTML o XHTML y puede ser ligeramente reformateada en el proceso.

Si se omite el segundo argumento, hxcopy escribe en la salida estándar. En este caso, se requiere la opción -o. Si también se omite el primer argumento, hxcopy lee de la entrada estándar. En este caso, se requiere la opción -i.

OPCIONES

Se admiten las siguientes opciones:

-i URL-antigua
A efectos de actualizar enlaces relativos, actúa como si URL-antigua fuera la ubicación desde la que se copia la entrada. Si se omite esta opción, se utiliza la ubicación real del primer argumento para calcular los enlaces relativos.
-o URL-nueva
A efectos de actualizar enlaces relativos, actúa como si URL-nueva fuera la ubicación a la que se copia la entrada. Si se omite esta opción, se utiliza la ubicación real del segundo argumento para calcular los enlaces relativos.
-s
También reemplaza los enlaces a sí mismo. Esto afecta al tratamiento de las URL vacías, es decir, los enlaces al propio documento que no lo nombran explícitamente. Sin -s, los enlaces implícitos al propio documento (href=""), a un fragmento del propio documento (href="#foo") o a una consulta sobre el propio documento (href="?query") no se modifican y, por lo tanto, se referirán a (un fragmento de) el nuevo documento. Con -s, estos enlaces se reescriben para referirse a (un fragmento de) el antiguo documento en su lugar.
-v
Muestra el número de versión y sale inmediatamente.

AMBIENTE

Para usar un proxy para recuperar archivos remotos, establezca las variables de entorno http_proxy y ftp_proxy. Por ejemplo, http_proxy="http://localhost:8080/"

ERRORES

A diferencia del último argumento de cp(1), el último argumento de hxcopy debe ser un archivo, no un directorio.

El segundo argumento debe ser un archivo local. La escritura en una URL aún no está implementada. Para solucionar esto, reemplace hxcopy archivo.html http://example.org/archivo.html por hxcopy -o http://example.org/archivo.html archivo.html tmp.html y luego suba tmp.html a la URL dada con algún otro comando, como curl(1). Sin embargo, el primer argumento puede ser una URL. hxcopy descargará el archivo dado. (Actualmente solo se admite HTTP.)

EJEMPLO

Suponga que el archivo HTML foo.html contiene un enlace relativo a "../bar.html". Aquí hay algunos ejemplos de comandos:

hxcopy foo.html bar/foo.html
El archivo foo.html se copia a ../bar/foo.html y el enlace relativo a "../bar.html" se convierte en "../../bar.html".
hxcopy foo.html ../foo.html
El archivo foo.html se copia a ../foo.html y el enlace relativo a "../bar.html" se reescribe como "bar.html".
hxcopy -i http://mi.org/dir1/foo.html -o http://mi.org/foo.html archivo1.html archivo2.html
El archivo archivo1.html se copia a archivo2.html y el enlace relativo a "../bar.html" se reescribe como "bar.html". Un comando como este puede ser útil para actualizar archivos que luego se suben a un servidor.

VéASE TAMBIÉN

cp(1), curl(1), hxwls(1)
