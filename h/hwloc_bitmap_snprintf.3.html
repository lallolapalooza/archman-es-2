Descripción Detallada

El tipo hwloc_bitmap_t representa un conjunto de enteros (positivos o nulos). Un bitmap puede ser de tamaño infinito (todos los bits están definidos después de algún punto). Un bitmap puede incluso estar lleno si todos los bits están definidos.

Los bitmaps son utilizados por hwloc para conjuntos de procesadores del sistema operativo (que pueden ser en realidad hilos de hardware) como hwloc_cpuset_t (un typedef para hwloc_bitmap_t), o conjuntos de nodos de memoria NUMA como hwloc_nodeset_t (también un typedef para hwloc_bitmap_t). Estos se usan para los campos cpuset y nodeset en la estructura hwloc_obj, ver Conjuntos de Objetos (hwloc_cpuset_t y hwloc_nodeset_t).

Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del sistema operativo. Sin embargo, los usuarios generalmente no deberían construir conjuntos de CPU y nodos manualmente (por ejemplo, con hwloc_bitmap_set()). En su lugar, deberían usar los conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or(), etc. Por ejemplo, vincular el hilo actual a un par de núcleos puede realizarse con:

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

Nota

La mayoría de las funciones a continuación devuelven 0 si tienen éxito y -1 si hay un error. El caso de error usual sería una falla interna para reasignar/extender el almacenamiento del bitmap (errno se establecería a ENOMEM). Ver también Reporte de errores en la API.

Varios ejemplos de uso de la API de bitmap están disponibles en el directorio doc/examples/ del árbol de fuentes. Las pruebas de regresión como tests/hwloc/hwloc_bitmap*.c también hacen un uso intensivo de esta API.

Documentación de Definiciones de Macros

#define hwloc_bitmap_foreach_begin(id, bitmap)

Macro de bucle que itera sobre el bitmap bitmap. El bucle debe comenzar con hwloc_bitmap_foreach_begin() y terminar con hwloc_bitmap_foreach_end() seguido de un punto y coma terminador.

id es la variable del bucle; debe ser un unsigned int. La primera iteración establecerá id al índice más bajo en el bitmap. Las iteraciones sucesivas recorrerán, en orden, todos los índices restantes definidos en el bitmap. Para ser específico: cada iteración devolverá un valor para id tal que hwloc_bitmap_isset(bitmap, id) sea verdadero.

La aserción previene que el bucle sea infinito si el bitmap está infinitamente definido.

#define hwloc_bitmap_foreach_end()

Fin de la macro de bucle que itera sobre un bitmap. Necesita un punto y coma terminador.

Documentación de Funciones

hwloc_bitmap_alloc

Reserva y devuelve un nuevo bitmap vacío.

El bitmap debe ser liberado con hwloc_bitmap_free().

Devuelve el nuevo bitmap en caso de éxito, o NULL en caso de error (por ejemplo, si la memoria no pudo ser asignada).

hwloc_bitmap_alloc_full

Reserva y devuelve un nuevo bitmap lleno.

El bitmap debe ser liberado con hwloc_bitmap_free().

Devuelve el nuevo bitmap en caso de éxito, o NULL en caso de error (por ejemplo, si la memoria no pudo ser asignada).

hwloc_bitmap_free

Libera la memoria del bitmap.

hwloc_bitmap_alloc() y hwloc_bitmap_dup() devuelven bitmaps que deben ser liberados con esta función.

hwloc_bitmap_dup

Duplica el bitmap.

El bitmap devuelto debe ser liberado con hwloc_bitmap_free().

Devuelve el bitmap duplicado en caso de éxito, o NULL en caso de error.

hwloc_bitmap_copy

Copia el contenido de src en dst.

dst debe haber sido asignado previamente con hwloc_bitmap_alloc() o hwloc_bitmap_alloc_full().

Devuelve 0 en caso de éxito, o -1 en caso de error (por ejemplo, si dst es NULL).

hwloc_bitmap_snprintf

Escribe la representación de cadena del bitmap en buf.

La cadena de salida tiene el mismo formato que la entrada de hwloc_bitmap_sscanf().

buflen es el tamaño del buffer de salida. El buffer no debe ser inferior a 1 byte. Si el buffer es demasiado pequeño, la cadena no se escribirá y se devolverá el número de caracteres que se habrían escrito (sin incluir el terminador nulo).

Si el bitmap está vacío, se escribe una cadena vacía.

Devuelve el número de caracteres escritos (sin incluir el terminador nulo) en caso de éxito, o un valor negativo en caso de error (por ejemplo, si buf es NULL o buflen es 0).

hwloc_bitmap_sscanf

Analiza la cadena string y establece el bitmap bitmap en consecuencia.

La cadena de entrada puede contener:

* números individuales (por ejemplo, "2", "10")
* rangos de números separados por guiones (por ejemplo, "2-4", "10-12")
* listas de números y rangos separados por comas (por ejemplo, "2,10-12")
* notación de dos puntos para rangos y listas (por ejemplo, "2:4:10" es lo mismo que "2,3,4,10")
* asteriscos para indicar un rango infinito (por ejemplo, "2-*" significa todos los enteros mayores o iguales a 2)
* el símbolo de asterisco solo significa un conjunto infinito (todos los enteros mayores o iguales a 0)
* la cadena vacía significa un conjunto vacío (todos los enteros no están establecidos)

Los números y rangos se aplican al bitmap. Si el bitmap no estaba vacío, se preservan los índices que no se mencionan explícitamente en la cadena. Usar hwloc_bitmap_zero() antes de llamar a esta función si se desea reemplazar el contenido del bitmap.

Devuelve 0 en caso de éxito, o -1 en caso de error (por ejemplo, si la cadena contiene caracteres inválidos o si hay un error de asignación de memoria).

hwloc_bitmap_or

Calcula la unión de bitmap1 y bitmap2 y almacena el resultado en res.

res puede ser igual a bitmap1 o bitmap2.

Devuelve 0 en caso de éxito, o -1 en caso de error.

Calcula la intersección de bitmap1 y bitmap2 y almacena el resultado en res.

res puede ser igual a bitmap1 o bitmap2.

Devuelve 0 en caso de éxito, o -1 en caso de error.

Calcula la diferencia de bitmap1 y bitmap2 (es decir, los elementos que están en bitmap1 pero no en bitmap2) y almacena el resultado en res.

res puede ser igual a bitmap1 o bitmap2.

Devuelve 0 en caso de éxito, o -1 en caso de error.

hwloc_bitmap_xor

Calcula la diferencia simétrica de bitmap1 y bitmap2 (es decir, los elementos que están en uno u otro, pero no en ambos) y almacena el resultado en res.

res puede ser igual a bitmap1 o bitmap2.

Devuelve 0 en caso de éxito, o -1 en caso de error.

hwloc_bitmap_not

Calcula el complemento de bitmap y almacena el resultado en res.

res puede ser igual a bitmap.

Devuelve 0 en caso de éxito, o -1 en caso de error.

hwloc_bitmap_intersects

Comprueba si bitmap1 y bitmap2 tienen al menos un elemento en común.

Devuelve 1 si se intersectan, 0 si no, y -1 en caso de error.

hwloc_bitmap_isincluded

Comprueba si sub_bitmap está completamente incluido en super_bitmap.

Devuelve 1 si está incluido, 0 si no, y -1 en caso de error.

hwloc_bitmap_isequal

Comprueba si bitmap1 y bitmap2 son iguales (contienen exactamente los mismos elementos).

Devuelve 1 si son iguales, 0 si no, y -1 en caso de error.

hwloc_bitmap_compare_first

Compara los elementos más bajos de bitmap1 y bitmap2.

Devuelve:

* -1 si el primer elemento de bitmap1 es menor que el de bitmap2
*  0 si el primer elemento de bitmap1 es igual al de bitmap2
*  1 si el primer elemento de bitmap1 es mayor que el de bitmap2

Si uno de los bitmaps está vacío, se considera que su primer elemento es infinito.

Devuelve -1, 0 o 1 en caso de éxito, o -2 en caso de error.

hwloc_bitmap_compare

Compara los bitmaps bitmap1 y bitmap2.

Devuelve:

* -1 si bitmap1 es lexicográficamente menor que bitmap2
*  0 si bitmap1 es igual a bitmap2
*  1 si bitmap1 es lexicográficamente mayor que bitmap2

Devuelve -1, 0 o 1 en caso de éxito, o -2 en caso de error.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Mantiene un único índice entre los establecidos en el bitmap bitmap. Puede ser útil antes de enlazar para que el proceso no tenga oportunidad de migrar entre múltiples procesadores en la máscara original. En lugar de ejecutar la tarea en cualquier PU dentro del conjunto de CPU dado, el planificador del sistema operativo se verá obligado a ejecutarla en una única de estas PUs. Esto evita una sobrecarga de migración y ping-pong de líneas de caché entre PUs.

Nota

Esta función NO está destinada a distribuir múltiples procesos dentro de un solo conjunto de CPU. Siempre devuelve el mismo bit único cuando se llama varias veces en el mismo conjunto de entrada. hwloc_distrib() puede usarse para generar conjuntos de CPU para distribuir múltiples tareas debajo de un solo objeto multipuerto.

Esta función no se puede aplicar directamente a un conjunto de objetos. Debe aplicarse a una copia (que puede obtenerse con hwloc_bitmap_dup()).
