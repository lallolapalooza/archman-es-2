Descripción detallada

El enlace de memoria se puede realizar de tres maneras:

  • asignación de memoria explícita gracias a hwloc_alloc_membind() y funciones relacionadas: el enlace tendrá efecto sobre la memoria asignada por estas funciones.
  • enlace de memoria implícito a través de la política de enlace: hwloc_set_membind() y funciones relacionadas solo definen la política actual del proceso, que será aplicada a las llamadas posteriores a malloc() y funciones relacionadas.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y funciones relacionadas, que mueven datos ya asignados.

No todos los sistemas operativos soportan las tres formas. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente en uso.

Cuando la operación de enlace solicitada no está disponible y se pasó el indicador HWLOC_MEMBIND_STRICT , la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema no soporte la acción o política especificada (por ejemplo, algunos sistemas solo permiten enlazar memoria por hilo, mientras que otros sistemas solo permiten enlazar memoria para todos los hilos en un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no pueda aplicarse (por ejemplo, algunos sistemas solo permiten enlazar memoria a un solo nodo NUMA).

Si HWLOC_MEMBIND_STRICT no se pasó, la función puede fallar también, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de enlace más pequeño, etc.) cuando la operación solicitada no esté exactamente soportada.

La forma más portable que debería preferirse sobre las demás siempre que sea posible es la siguiente. Asigna algo de memoria que se espera esté enlazada al conjunto especificado. Para hacerlo, hwloc posiblemente tendrá que cambiar la política de enlace de memoria actual para realmente obtener la memoria enlazada, si el SO no proporciona ninguna otra manera de asignar simplemente memoria enlazada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), que nunca cambiará la política de enlace de memoria actual.

hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0);

Cada función de enlace de memoria de hwloc toma un argumento de mapa de bits que es un conjunto de CPU por defecto, o un conjunto de nodos de memoria NUMA si se especifica el indicador HWLOC_MEMBIND_BYNODESET . Ver Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API de mapas de bits para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_nodeset().

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por conjunto de nodos debería preferirse siempre que sea posible.

Documentación del tipo enumeración

enum hwloc_membind_flags_t

Indicadores de enlace de memoria. Estos indicadores pueden usarse para refinar la política de enlace. Todos los indicadores pueden combinarse lógicamente con OR, con la excepción de HWLOC_MEMBIND_PROCESS y HWLOC_MEMBIND_THREAD; estos dos indicadores son mutuamente excluyentes.

No todos los sistemas soportan todos los tipos de enlace. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente en uso. Ver la sección 'Descripción detallada' de Enlace de memoria para una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_MEMBIND_PROCESS
Establece la política para todos los hilos del proceso especificado (posiblemente multihilo). Este indicador es mutuamente excluyente con HWLOC_MEMBIND_THREAD.
HWLOC_MEMBIND_THREAD
Establece la política para un hilo específico del proceso actual. Este indicador es mutuamente excluyente con HWLOC_MEMBIND_PROCESS.
HWLOC_MEMBIND_STRICT
Solicita enlace estricto del sistema operativo. La función fallará si el enlace no puede garantizarse / aplicarse completamente.

Este indicador tiene significados ligeramente diferentes dependiendo con qué función se use.

HWLOC_MEMBIND_MIGRATE
Migra memoria ya asignada. Si la memoria no puede migrarse y se pasó el indicador HWLOC_MEMBIND_STRICT , se devolverá un error.
HWLOC_MEMBIND_NOCPUBIND
Evita cualquier efecto sobre el enlace de CPU. En algunos sistemas operativos, algunas funciones subyacentes de enlace de memoria también enlazan la aplicación a la(s) CPU correspondiente(s). Usar este indicador hará que hwloc evite usar funciones del SO que podrían afectar a los enlaces de CPU. Sin embargo, ten en cuenta que usar NOCPUBIND puede reducir el soporte general de enlace de memoria de hwloc. Específicamente: algunas de las funciones de enlace de memoria de hwloc pueden fallar con errno establecido en ENOSYS cuando se usan con NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considera el argumento de mapa de bits como un conjunto de nodos. El argumento de mapa de bits se considera un conjunto de nodos si se da este indicador, o un conjunto de CPU por defecto en caso contrario.

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por conjunto de nodos debería preferirse siempre que sea posible.

void * hwloc_alloc (hwloc_topology_t topology, size_t len)

Alloue une zone mémoire. Ceci est équivalent à malloc(), à la différence qu'il essaie d'allouer une mémoire alignée sur des pages auprès du système d'exploitation.

Retourne

Un pointeur vers la zone allouée, ou NULL en cas d'erreur.

Note

La mémoire allouée doit être libérée avec hwloc_free().

void * hwloc_alloc_membind (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Alloue une zone mémoire sur les nœuds mémoire NUMA spécifiés par set.

Retourne

Un pointeur vers la zone allouée.

NULL avec errno défini à ENOSYS si l'action n'est pas supportée et que HWLOC_MEMBIND_STRICT est donné.

NULL avec errno défini à EXDEV si la contrainte ne peut être appliquée et que HWLOC_MEMBIND_STRICT est donné.

NULL avec errno défini à ENOMEM si l'allocation mémoire a échoué avant même d'essayer de contraindre.

Si HWLOC_MEMBIND_BYNODESET est spécifié, set est considéré comme un ensemble de nœuds. Sinon, c'est un ensemble de CPU.

Note

La mémoire allouée doit être libérée avec hwloc_free().

void * hwloc_alloc_membind_policy (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags) [inline]

Alloue une zone mémoire sur les nœuds mémoire NUMA spécifiés par set. D'abord, essaie d'allouer correctement avec hwloc_alloc_membind(). En cas d'échec, la politique de contrainte mémoire du processus ou du thread courant est modifiée avec hwloc_set_membind() avant d'allouer la mémoire. Ainsi, cette fonction fonctionne dans plus de cas, au prix de la modification de l'état courant (affectant potentiellement les futures allocations qui ne spécifieraient aucune politique).

Si HWLOC_MEMBIND_BYNODESET est spécifié, set est considéré comme un ensemble de nœuds. Sinon, c'est un ensemble de CPU.

Retourne

Un pointeur vers la zone allouée, ou NULL en cas d'erreur.

int hwloc_free (hwloc_topology_t topology, void * addr, size_t len)

Libère la mémoire précédemment allouée par hwloc_alloc() ou hwloc_alloc_membind().

Retourne

0 en cas de succès, -1 en cas d'erreur.

int hwloc_get_area_membind (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Interroge les CPU proches des nœuds NUMA physiques et la politique de contrainte de la mémoire identifiée par (addr, len ). Le bitmap set (préalablement alloué par l'appelant) est rempli avec la contrainte de la zone mémoire.

Cette fonction possède deux paramètres de sortie : set et policy. Les valeurs retournées dans ces paramètres dépendent à la fois des flags passés et des politiques de contrainte mémoire et des ensembles de nœuds des pages dans la plage d'adresses.

Si HWLOC_MEMBIND_STRICT est spécifié, les pages cibles sont d'abord vérifiées pour voir si elles ont toutes la même politique de contrainte mémoire et le même ensemble de nœuds. Si ce n'est pas le cas, -1 est retourné et errno est défini à EXDEV. Si elles sont identiques sur toutes les pages, l'ensemble et la politique sont retournés dans set et policy, respectivement.

Si HWLOC_MEMBIND_STRICT n'est pas spécifié, l'union de tous les nœuds NUMA contenant des pages dans la plage d'adresses est calculée. Si toutes les pages cibles ont la même politique, elle est retournée dans policy. Sinon, policy est défini à HWLOC_MEMBIND_MIXED.

Si HWLOC_MEMBIND_BYNODESET est spécifié, set est considéré comme un ensemble de nœuds. Sinon, c'est un ensemble de CPU.

Si d'autres flags sont spécifiés, -1 est retourné et errno est défini à EINVAL.

Retourne

0 en cas de succès.

-1 avec errno défini à EINVAL si len est 0.

int hwloc_get_area_memlocation (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, int flags)

Obtient les nœuds NUMA où la mémoire identifiée par (addr, len ) est physiquement allouée. Le bitmap set (préalablement alloué par l'appelant) est rempli selon les nœuds NUMA où les pages de la zone mémoire sont physiquement allouées. Si aucune page n'est encore réellement allouée, set peut être vide.

Si les pages sont réparties sur plusieurs nœuds, il n'est pas spécifié si elles le sont équitablement, ou si la plupart d'entre elles se trouvent sur un seul nœud, etc.

Le système d'exploitation peut déplacer les pages mémoire d'un processeur à un autre à tout moment en fonction de leur contrainte, donc cette fonction peut retourner quelque chose qui est déjà obsolète.
