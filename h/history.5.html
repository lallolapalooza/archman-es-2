NOMBRE

history - Registro de artículos de Usenet actuales y recientemente expirados

DESCRIPCIÓN

El archivo pathdb/history mantiene un registro de todos los artículos almacenados actualmente en el sistema de noticias, así como aquellos que han sido recibidos pero ya expiraron. En un entorno de producción típico, este archivo tendrá muchos megabytes.

El archivo consta de líneas de texto. Cada línea corresponde a un artículo. Normalmente, el archivo se mantiene ordenado según el orden en que se reciben los artículos, aunque esto no es un requisito. innd añade una nueva línea cada vez que archiva un artículo, y expire construye una nueva versión del archivo eliminando artículos antiguos y purgando entradas antiguas.

Cada línea consta de dos o tres campos separados por una tabulación, mostrados a continuación como " \t ":

[hash] \t fecha
[hash] \t fecha \t @token@

El campo hash es la representación ASCII del hash del Message-ID. Se utiliza directamente como clave para el dbz.

El campo fecha consta de tres subcampos separados por una tilde. Todos los subcampos son la representación textual del número de segundos desde la época, es decir, un time_t como en gettimeofday(2). El primer subcampo es la fecha de recepción del artículo. Si todavía hay copias del artículo presentes, el segundo subcampo será el valor del campo de cabecera Expires del artículo, o un guion si no se especificó fecha de expiración. Si un artículo ha expirado, el segundo subcampo será un guion. El tercer subcampo es el valor del campo de cabecera Date del artículo, que registra cuándo se publicó el artículo.

El campo token es un token del artículo. Este campo está vacío si el artículo ha expirado.

Por ejemplo, un artículo cuyo Message-ID era <7q2saq$sal$1@isrv4.pa.vix.com>, publicado el 26 de agosto de 1999 a las 08:02:34 GMT y recibido el 26 de agosto de 1999 a las 08:06:54 GMT, podría tener una línea de historial (dividida en tres líneas para su visualización) como la siguiente:

[E6184A5BC2898A35A3140B149DE91D5C] \t
    935678987~-~935678821 \t
    @030154574F00000000000007CE3B000004BA@

Además del archivo de texto, existe una base de datos dbz asociada al archivo que utiliza el campo Message-ID como clave para determinar el desplazamiento en el archivo de texto donde comienza la línea asociada. Por razones históricas, la clave incluye el byte "\0" final (que no se almacena en el archivo de texto).
