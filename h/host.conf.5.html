host.conf(5) Manual de Formatos de Archivo host.conf(5)

NOMBRE

host.conf - archivo de configuración del resolvedor

DESCRIPCIÓN

El archivo /etc/host.conf contiene información de configuración específica de la biblioteca del resolvedor. Debería contener una palabra clave de configuración por línea, seguida de la información de configuración apropiada. Se reconocen las siguientes palabras clave:

trim
Esta palabra clave puede aparecer más de una vez. Cada vez debe ir seguida de una lista de dominios, separados por dos puntos (:), punto y coma (;) o comas (,); con el punto inicial. Cuando se establece, la biblioteca del resolvedor eliminará automáticamente el nombre de dominio dado del final de cualquier nombre de host resuelto a través de DNS. Esto está diseñado para su uso con hosts y dominios locales. (Nota relacionada: trim no afectará a los nombres de host obtenidos a través de NIS o del archivo hosts(5). Se debe tener cuidado para asegurar que el primer nombre de host para cada entrada en el archivo hosts esté completamente calificado o no calificado, según corresponda a la instalación local.)
multi
Los valores válidos son on y off. Si se establece en on, la biblioteca del resolvedor devolverá todas las direcciones válidas para un host que aparece en el archivo /etc/hosts, en lugar de solo la primera. Esto está off por defecto, ya que puede causar una pérdida de rendimiento sustancial en sitios con archivos hosts grandes.
reorder
Los valores válidos son on y off. Si se establece en on, la biblioteca del resolvedor intentará reordenar las direcciones de host para que las direcciones locales (es decir, en la misma subred) aparezcan primero cuando se realiza una llamada a gethostbyname(3). La reordenación se realiza para todos los métodos de búsqueda. El valor predeterminado es off.

AMBIENTE

Las siguientes variables de entorno se pueden usar para permitir que los usuarios anulen el comportamiento configurado en /etc/host.conf:

RESOLV_HOST_CONF
Si está establecida, esta variable apunta a un archivo que debe leerse en lugar de /etc/host.conf.
RESOLV_MULTI
Anula el comando multi.
RESOLV_REORDER
Anula el comando reorder.
RESOLV_ADD_TRIM_DOMAINS
Una lista de dominios, separados por dos puntos (:), punto y coma (;), o comas (,), con el punto inicial, que se añadirán a la lista de dominios que deben ser recortados.
RESOLV_OVERRIDE_TRIM_DOMAINS
Una lista de dominios, separados por dos puntos (:), punto y coma (;), o comas (,), con el punto inicial, que reemplazarán la lista de dominios que deben ser recortados. Anula el comando trim.

ARCHIVOS

/etc/host.conf
Archivo de configuración del resolvedor
/etc/resolv.conf
Archivo de configuración del resolvedor
/etc/hosts
Base de datos de hosts locales

NOTAS

Existen las siguientes diferencias en comparación con la implementación original. Un nuevo comando spoof y una nueva variable de entorno RESOLV_SPOOF_CHECK pueden aceptar argumentos como off, nowarn y warn. Los comentarios de línea pueden aparecer en cualquier lugar y no solo al principio de una línea.

Histórico

El archivo nsswitch.conf(5) es la forma moderna de controlar el orden de las búsquedas de hosts.

En glibc 2.4 y versiones anteriores, se reconocía la siguiente palabra clave:

order
Esta palabra clave especifica cómo se deben realizar las búsquedas de hosts. Debe ir seguida de uno o más métodos de búsqueda, separados por comas. Los métodos válidos son bind, hosts y nis.
RESOLV_SERV_ORDER
Anula el comando order.

Desde glibc 2.0.7, hasta glibc 2.24, se reconocieron las siguientes palabras clave y variables de entorno pero nunca se implementaron:

nospoof
Los valores válidos son on y off. Si se establece en on, la biblioteca del resolvedor intentará prevenir el spoofing de nombres de host para mejorar la seguridad de rlogin y rsh. Funciona de la siguiente manera: después de realizar una búsqueda de direcciones de host, la biblioteca del resolvedor realizará una búsqueda de nombres de host para esa dirección. Si los dos nombres de host no coinciden, la consulta falla. El valor predeterminado es off.
spoofalert
Los valores válidos son on y off. Si esta opción se establece en on y la opción nospoof también está establecida, la biblioteca del resolvedor registrará una advertencia del error a través de la instalación de syslog. El valor predeterminado es off.
spoof
Los valores válidos son off, nowarn y warn. Si esta opción se establece en off, se permiten direcciones falsificadas y no se emitirán advertencias a través de la instalación de syslog. Si esta opción se establece en warn, la biblioteca del resolvedor intentará prevenir el spoofing de nombres de host para mejorar la seguridad y registrará una advertencia del error a través de la instalación de syslog. Si esta opción se establece en nowarn, la biblioteca del resolvedor intentará prevenir el spoofing de nombres de host para mejorar la seguridad pero no emitirá advertencias a través de la instalación de syslog. Establecer esta opción en cualquier otro valor es igual a establecerla en nowarn.
RESOLV_SPOOF_CHECK
Anula los comandos nospoof, spoofalert y spoof de la misma manera que se analiza el comando spoof. Los valores válidos son off, nowarn y warn.

VER TAMBIÉN

gethostbyname(3), hosts(5), nsswitch.conf(5), resolv.conf(5), hostname(7), named(8)
