Descripción detallada

El enlace de memoria se puede realizar de tres maneras:

  • asignación de memoria explícita gracias a hwloc_alloc_membind() y relacionadas: el enlace tendrá efecto sobre la memoria asignada por estas funciones.
  • enlace de memoria implícito a través de la política de enlace: hwloc_set_membind() y relacionadas solo definen la política actual del proceso, que se aplicará a las llamadas posteriores a malloc() y relacionadas.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y relacionadas, que mueven datos ya asignados.

No todos los sistemas operativos admiten las tres formas. hwloc_topology_get_support() se puede usar para consultar el soporte real de enlace de memoria en el sistema operativo utilizado actualmente.

Cuando la operación de enlace solicitada no está disponible y se HWLOC_MEMBIND_STRICT se pasó la bandera, la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema no admita la acción o política especificada (por ejemplo, algunos sistemas solo permiten enlazar memoria por hilo, mientras que otros sistemas solo permiten enlazar memoria para todos los hilos de un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no se pueda imponer (por ejemplo, algunos sistemas solo permiten enlazar memoria a un solo nodo NUMA).

Si HWLOC_MEMBIND_STRICT no se pasó, la función puede fallar también, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de enlace más pequeño, etc.) cuando la operación solicitada no se admite exactamente.

La forma más portable que se debe preferir sobre las demás siempre que sea posible es la siguiente. Asigna algo de memoria que se espera esté enlazada al conjunto especificado. Para ello, hwloc posiblemente tendrá que cambiar la política de enlace de memoria actual para realmente obtener la memoria enlazada, si el SO no proporciona ninguna otra manera de asignar simplemente memoria enlazada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), que nunca cambiará la política de enlace de memoria actual.

hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0);

Cada función de enlace de memoria de hwloc toma un argumento de mapa de bits que es un conjunto de CPU de manera predeterminada, o un conjunto de nodos de memoria NUMA si se especifica la bandera HWLOC_MEMBIND_BYNODESET . Ver Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API de mapas de bits para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_nodeset().

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, se debe preferir el enlace por conjunto de nodos siempre que sea posible.

Nota

En algunos sistemas operativos, el enlace de memoria afecta el enlace de CPU; ver HWLOC_MEMBIND_NOCPUBIND

Documentación del tipo de enumeración

enum hwloc_membind_flags_t

Banderas de enlace de memoria. Estas banderas se pueden usar para refinar la política de enlace. Todas las banderas se pueden combinar lógicamente con OR con la excepción de HWLOC_MEMBIND_PROCESS y HWLOC_MEMBIND_THREAD; estas dos banderas son mutuamente excluyentes.

No todos los sistemas admiten todos los tipos de enlace. hwloc_topology_get_support() se puede usar para consultar el soporte real de enlace de memoria en el sistema operativo utilizado actualmente. Ver la sección 'Descripción detallada' de Enlace de memoria para una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_MEMBIND_PROCESS
Establecer la política para todos los hilos del proceso especificado (posiblemente multihilo). Esta bandera es mutuamente excluyente con HWLOC_MEMBIND_THREAD.
HWLOC_MEMBIND_THREAD
Establecer la política para un hilo específico del proceso actual. Esta bandera es mutuamente excluyente con HWLOC_MEMBIND_PROCESS.
HWLOC_MEMBIND_STRICT
Solicitar enlace estricto del SO. La función fallará si el enlace no se puede garantizar / imponer completamente.

Esta bandera tiene significados ligeramente diferentes dependiendo con qué función se use.

HWLOC_MEMBIND_MIGRATE
Migrar memoria asignada existente. Si la memoria no se puede migrar y se pasó la bandera HWLOC_MEMBIND_STRICT , se devolverá un error.
HWLOC_MEMBIND_NOCPUBIND
Evitar cualquier efecto sobre el enlace de CPU. En algunos sistemas operativos, algunas funciones subyacentes de enlace de memoria también enlazan la aplicación al/los CPU correspondiente(s). Usar esta bandera hará que hwloc evite usar funciones del SO que podrían afectar los enlaces de CPU. Sin embargo, ten en cuenta que usar NOCPUBIND puede reducir el soporte general de enlace de memoria de hwloc. Específicamente: algunas de las funciones de enlace de memoria de hwloc pueden fallar con errno establecido en ENOSYS cuando se usan con NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considerar el argumento de mapa de bits como un conjunto de nodos. El argumento de mapa de bits se considera un conjunto de nodos si se da esta bandera, o un conjunto de CPU de manera predeterminada en caso contrario.

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, se debe preferir el enlace por conjunto de nodos siempre que sea posible.

enum hwloc_membind_policy_t

Política de asignación de memoria. Estas constantes pueden usarse para elegir la política de asignación. Solo se puede usar una política a la vez (es decir, los valores no pueden combinarse con OR).

No todos los sistemas soportan todos los tipos de asignación. hwloc_topology_get_support() puede usarse para consultar el soporte real de la política de asignación de memoria en el sistema operativo actualmente en uso. Véase la sección 'Descripción Detallada' de Asignación de memoria para una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_MEMBIND_DEFAULT
Restablece la política de asignación de memoria a la predeterminada del sistema. Dependiendo del sistema operativo, esto puede corresponder a HWLOC_MEMBIND_FIRSTTOUCH (Linux, FreeBSD), o HWLOC_MEMBIND_BIND (AIX, HP-UX, Solaris, Windows). Esta política nunca es devuelta por las funciones de obtención de membind. El argumento nodeset es ignorado.
HWLOC_MEMBIND_FIRSTTOUCH
Asigna cada página de memoria individualmente en el nodo NUMA local del hilo que la toca. El nodeset dado debería ser normalmente hwloc_topology_get_topology_nodeset() para que el hilo que la toca pueda ejecutarse y asignarse en cualquier nodo del sistema.

En AIX, si el nodeset es más pequeño, las páginas se asignan localmente (si el nodo local está en el nodeset) o desde un nodo no local aleatorio (en caso contrario).

HWLOC_MEMBIND_BIND
Asigna memoria en los nodos especificados. El comportamiento real puede variar ligeramente entre sistemas operativos, especialmente cuando (algunos de) los nodos solicitados están llenos. En Linux, por defecto, se usa la política MPOL_PREFERRED_MANY (o MPOL_PREFERRED). Sin embargo, si también se proporciona el flag estricto de hwloc, se usa en su lugar la política MPOL_BIND de Linux.
HWLOC_MEMBIND_INTERLEAVE
Asigna memoria en los nodos dados de manera intercalada / round-robin. La disposición precisa de la memoria a través de múltiples nodos NUMA es específica del SO/sistema. El intercalado puede ser útil cuando los hilos distribuidos a través de los nodos NUMA especificados accederán todos al rango completo de memoria simultáneamente, ya que el intercalado equilibrará entonces las referencias de memoria.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
Asigna memoria en los nodos dados de manera intercalada / ponderada. La disposición precisa de la memoria a través de múltiples nodos NUMA es específica del SO/sistema. El intercalado ponderado puede ser útil cuando los hilos distribuidos a través de los nodos NUMA especificados con diferentes capacidades de ancho de banda accederán todos al rango completo de memoria simultáneamente, ya que el intercalado equilibrará entonces las referencias de memoria.
HWLOC_MEMBIND_NEXTTOUCH
Para cada página vinculada con esta política, la próxima vez que sea tocada (y solo la próxima vez), se moverá de su ubicación actual al nodo NUMA local del hilo donde ocurrió la referencia de memoria (si necesita ser movida en absoluto).
HWLOC_MEMBIND_MIXED
Devuelto por las funciones get_membind() cuando múltiples hilos o partes de un área de memoria tienen políticas de asignación de memoria diferentes. También se devuelve cuando la asignación es desconocida porque los ganchos de asignación están vacíos cuando la topología se carga desde XML sin HWLOC_THISSYSTEM=1, etc.

Función Documentación

void * hwloc_alloc (hwloc_topology_t topology, size_t len)

Asigna algo de memoria. Esto es equivalente a malloc(), excepto que intenta asignar memoria alineada a páginas desde el SO.

Devuelve

un puntero al área asignada, o NULL en caso de error.

Nota

La memoria asignada debería liberarse con hwloc_free().

void * hwloc_alloc_membind (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Asigna algo de memoria en los nodos de memoria NUMA especificados por set.

Devuelve

un puntero al área asignada.

NULL con errno establecido a ENOSYS si la acción no está soportada y HWLOC_MEMBIND_STRICT está especificado.

NULL con errno establecido a EXDEV si la asignación no puede ser aplicada y HWLOC_MEMBIND_STRICT está especificado.

NULL con errno establecido a ENOMEM si la asignación de memoria falló incluso antes de intentar la asignación.

Si HWLOC_MEMBIND_BYNODESET está especificado, set se considera un nodeset. De lo contrario, es un cpuset.

Nota

La memoria asignada debería liberarse con hwloc_free().

void * hwloc_alloc_membind_policy (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags) [inline]

Asigna algo de memoria en los nodos de memoria NUMA especificados por set. Primero, intenta asignar correctamente con hwloc_alloc_membind(). En caso de fallo, la política de asignación de memoria del proceso o hilo actual se cambia con hwloc_set_membind() antes de asignar memoria. Así, esta función funciona en más casos, a costa de cambiar el estado actual (posiblemente afectando asignaciones futuras que no especifiquen ninguna política).

Si HWLOC_MEMBIND_BYNODESET está especificado, set se considera un nodeset. De lo contrario, es un cpuset.

Devuelve

un puntero al área asignada, o NULL en caso de error.

int hwloc_free (hwloc_topology_t topology, void * addr, size_t len)

Libera memoria que fue previamente asignada por hwloc_alloc() o hwloc_alloc_membind().

Devuelve

0 en éxito, -1 en error.

int hwloc_get_area_membind (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Consulta las CPUs cerca del(los) nodo(s) NUMA físicos y la política de asignación de la memoria identificada por (addr, len ). El bitmap set (previamente asignado por el llamante) se rellena con la asignación del área de memoria.

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de los flags pasados como de las políticas de asignación de memoria y los nodesets de las páginas en el rango de dirección.

Si HWLOC_MEMBIND_STRICT está especificado, primero se comprueban las páginas de destino para ver si todas tienen la misma política de asignación de memoria y nodeset. Si no es así, se devuelve -1 y errno se establece a EXDEV. Si son idénticas en todas las páginas, el set y la política se devuelven en set y policy, respectivamente.

Si HWLOC_MEMBIND_STRICT no está especificado, se calcula la unión de todos los nodos NUMA que contienen páginas en el rango de dirección. Si todas las páginas en el destino tienen la misma política, se devuelve en policy. De lo contrario, policy se establece a HWLOC_MEMBIND_MIXED.

Si HWLOC_MEMBIND_BYNODESET está especificado, set se considera un nodeset. De lo contrario, es un cpuset.

Si se especifican cualquier otro flags, se devuelve -1 y errno se establece a EINVAL.

Devuelve

0 en éxito.

-1 con errno establecido a EINVAL si len es 0.

int hwloc_get_area_memlocation (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, int flags)

Obtiene los nodos NUMA donde la memoria identificada por (addr, len ) está físicamente asignada. El bitmap set (previamente asignado por el llamante) se rellena de acuerdo con los nodos NUMA donde las páginas del área de memoria están físicamente asignadas. Si ninguna página está realmente asignada todavía, set puede estar vacío.

Si las páginas se extienden a múltiples nodos, no se especifica si se extienden equitativamente, o si la mayoría de ellas están en un solo nodo, etc.

El sistema operativo puede mover páginas de memoria de un procesador a otro en cualquier momento de acuerdo con su asignación, por lo que esta función puede devolver algo que ya está obsoleto.
