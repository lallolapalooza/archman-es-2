DESCRIPCIÓ

N

hdparm proporciona una interfaz de línea de comandos para varias interfaces del kernel soportadas por el subsistema "libata" de Linux SATA/PATA/SAS y el subsistema de controlador IDE más antiguo. Muchas carcasas de unidades USB más nuevas (2008 y posteriores) ahora tambi

én soportan "SAT" (Traducción de Comandos SCSI-ATA) y por lo tanto también pueden funcionar con hdparm. Por ejemplo, modelos recientes
de WD "Passport" y carcasas NexStar-3 recientes. Algunas opciones pueden funcionar correctamente solo con los kernels más recientes.

OPCIONE

S

Cuando no se proporcionan opciones, se asume -acdgkmur. Para las opciones "Obtener/establecer", una consulta sin el parámetro opcional (por ejemplo, -d) consultará (obtendrá) el estado del dispositivo, y con un parámetro (por ejemplo, -d0) establecerá el estado del

dispositivo.
-
a
Obtener/establecer el recuento de sectores para la lectura anticipada (por software) del sistema de archivos. Esto se usa para mejorar el rendimiento en lecturas secuenciales de archivos grandes, al pre-cargar bloques adicionales en anticipación de que sean necesarios por la tarea en ejecución. Muchas unidades IDE también tienen una función de lectura anticipada incorporada separada, que aumenta esta función de lectura anticipada (por software) del sistema de
archivos.
-
A
Obtener/establecer la función de lectura anticipada de la unidad IDE (generalmente ACTIVADA por defecto). Uso: -A0 (deshabilitar) o -A1 (habilitar)
.
-
b
Obtener/establecer el estado del
bus.
-
B
Obtener/establecer la función de Gestión Avanzada de Energía, si la unidad lo soporta. Un valor bajo significa una gestión de energía agresiva y un valor alto significa mejor rendimiento. Los ajustes posibles van desde los valores 1 a 127 (que permiten el apagado del motor), y los valores 128 a 254 (que no permiten el apagado del motor). El mayor grado de gestión de energía se alcanza con un ajuste de 1, y el mayor rendimiento de E/S con un ajuste de 254. Un valor de 255 le indica a hdparm que deshabilite la Gestión Avanzada de Energía por completo en la unidad (no todas las unidades soportan deshabilitarla, pero la mayoría
sí).
-
c
Obtener/establecer soporte de E/S de 32 bits de (E)IDE. Se puede usar un parámetro numérico para habilitar/deshabilitar el soporte de E/S de 32 bits. Los valores soportados actualmente incluyen 0 para deshabilitar el soporte de E/S de 32 bits, 1 para habilitar transferencias de datos de 32 bits, y 3 para habilitar transferencias de datos de 32 bits con una secuencia especial de sincronización requerida por muchos chipsets. El valor 3 funciona con casi todos los chipsets IDE de 32 bits, pero incura en un poco más de sobrecarga. Tenga en cuenta que "32 bits" se refiere solo a transferencias de datos a través de un bus PCI o VLB hacia la tarjeta de interfaz; todas las unidades (E)IDE todavía tienen solo una conexión de 16 bits sobre el cable de cinta desde la tarjeta de
interfaz.
-
C
Verificar el estado actual del modo de energía IDE, que siempre será uno de desconocido (la unidad no soporta este comando), activo/inactivo (operación normal), en espera (modo de baja energía, la unidad ha detenido su motor), o dormido (modo de energía más bajo, la unidad está completamente apagada). Las opciones -S, -y, -Y, y -Z se pueden usar para manipular los modos de energía
IDE.
-
d
Obtener/establecer el indicador "using_dma" para esta unidad. Esta opción ahora funciona con la mayoría de las combinaciones de unidades e interfaces PCI que soportan DMA y que son conocidas por el controlador IDE del kernel. También es una buena idea usar la opción -X apropiada en combinación con -d1 para asegurarse de que la unidad misma esté programada para el modo DMA correcto, aunque la mayoría de las BIOS deberían hacer esto por usted en el arranque. Usar DMA casi siempre da el mejor rendimiento, con un alto rendimiento de E/S y bajo uso de la CPU. Pero hay al menos algunas configuraciones de chipsets y unidades para las que DMA no hace mucha diferencia, o incluso puede ralentizar las cosas (¡en hardware realmente descompuesto!). Sus resultados pueden
variar.
--dco-free
ze
DCO significa Superposición de Configuración del Dispositivo (Device Configuration Overlay), una forma para que los proveedores deshabiliten selectivamente ciertas características de una unidad. La opción --dco-freeze congelará/bloqueará la configuración actual de la unidad, previniendo así que el software (o malware) cambie cualquier configuración de DCO hasta después del reinicio por encendido (power-on reset)
siguiente.
--dco-identi
fy
Consultar y volcar información sobre la configuración de la unidad que puede ser deshabilitada por el proveedor o instalador OEM. Estas configuraciones muestran capacidades de la unidad que podrían ser deshabilitadas por el proveedor para una "compatibilidad mejorada". Cuando están deshabilitadas, de lo contrario están ocultas y no se mostrarán en la salida de -I identify. Por ejemplo, los proveedores de sistemas a veces deshabilitan el direccionamiento 48_bit en unidades grandes, para compatibilidad (y pérdida de capacidad) con una BIOS específica. En tales casos, --dco-identify mostrará que la unidad es capaz de 48_bit, pero -I no lo mostrará, y la unidad tampoco aceptará comandos
48_bit.
--dco-resto
re
Restablecer todos los ajustes, características y capacidades accesibles de la unidad a los valores predeterminados de fábrica y a las capacidades completas. Este comando fallará si DCO está congelado/bloqueado, o si también se ha establecido una restricción de tamaño máximo -Np. Esto es EXTREMADAMENTE PELIGROSO y muy probablemente causará una pérdida masiva de datos. NO USE ESTE
COMANDO.
--dire
ct
Usar el indicador "O_DIRECT" del kernel al realizar una prueba de tiempo -t. Esto evita la caché de páginas, haciendo que las lecturas vayan directamente desde la unidad a los búferes de hdparm, usando la llamada E/S "raw". En muchos casos, esto puede producir resultados que parecen mucho más rápidos que el método usual de caché de páginas, dando una mejor indicación del rendimiento del dispositivo y controlador en
bruto.
--drq-hsm-er
ror
MUY PELIGROSO, NI SIQUIERA PIENSE EN USARLO. Esta opción hace que hdparm emita un comando IDENTIFY al kernel, pero incorrectamente marcado como un comando "sin datos". Esto resulta en que la unidad queda con su línea DataReQust(DRQ) "atascada" en alto. Esto confunde a los controladores del kernel, y puede bloquear el sistema inmediatamente con una pérdida masiva de datos. La opción existe para ayudar en la prueba y fortalecimiento del kernel contra fallos similares de unidades en el mundo real. MUY PELIGROSO, ¡NO USE!
!
-
D
Habilitar/deshabilitar la función de gestión de defectos en la unidad, mediante la cual el firmware de la unidad intenta gestionar automáticamente los sectores defectuosos reubicándolos en sectores "de repuesto" reservados por la fábrica para tal fin. El control de esta función a través de la opción -D no está soportado para la mayoría de las unidades modernas desde ATA-4; por lo tanto, este comando puede
fallar.
-
E
Establecer la velocidad de la unidad cd/dvd. Esto NO es necesario para la operación regular, ya que la unidad cambiará de velocidad automáticamente. Pero si quiere jugar con ello, simplemente proporcione un número de velocidad después de la opción, generalmente un número como 2 o 4. Esto puede ser útil en algunos casos, sin embargo, para suavizar la reproducción de video
DVD.
-
f
Sincronizar y vaciar la caché de búfer para el dispositivo al salir. Esta operación también se realiza internamente como parte de los tiempos -t y -T y otras
opciones.
--falloca
te
Esta opción actualmente solo funciona en los tipos de sistema de archivos ext4 y xfs. Cuando se usa, esta debe ser la única opción proporcionada. Requiere dos parámetros: el
tamaño de archivo deseado en kilobytes (recuento de bytes dividido por 1024), seguido de la ruta de acceso para el nuevo archivo. Creará un nuevo archivo del tamaño espe
cificado, pero sin tener que escribir realmente ningún dato en el archivo. Esto normalmente se completará muy rápidamente, y sin agotar la unidad de almacenamiento.
Por ejemplo, crear un archivo de 10KByte: hdparm --f
allocate 10
temp_file
--fibm
ap
Cuando se usa, esta debe ser la única opción proporcionada. Requiere una ruta de archivo como parámetro, e imprimirá una lista de las extensiones de bloques (rangos de sectores) que ocupa ese archivo en el disc
o. Los números de sector se dan como números LBA absolutos, referenciados desde el sector 0 del dispositivo físico en lugar de desde la partición o el sistema de archivos. Esta información puede usarse para una
variedad de propósitos, como examinar el grado de fragmentación de archivos más grandes, o determinar sectores apropiados para corromper deliberadamente durante procedimientos de pruebas de inyección de fallos.
Esta opción usa el nuevo ioctl() FIEMAP (file extent map) cuando está disponible, y recurre al ioctl() FIBMAP (file block map) más antiguo de lo contrario. T
enga en cuenta que FIBMAP sufre de una interfaz de número de bloque de 32 bits, y por lo tanto no funciona más allá de 8TB o 16TB. FIBMAP también es muy lent
o, y no maneja bien las extensiones preasignadas sin confirmar en los sistemas de archivos ext4/xfs, a menos que se haga un sync() antes de usar esta opción.
--fwdownlo
ad
Cuando se usa, esta debería ser la única opción proporcionada. Requiere una ruta de archivo inmediatamente después de la opción, indicando desde dónde debe leerse el nuevo firmware del disco. El contenido de este archivo se enviará al disco usando el (S)ATA comando DOWNLOAD MICROCODE, usando el protocolo de transferencia 7 (archivo completo de una vez), o, si el disco lo soporta, el protocolo de transferencia 3 (descarga segmentada). Este comando es EXTREMADAMENTE PELIGROSO y podría destruir tanto el disco como todos los datos en él. NO USE ESTE COMANDO. Las --fwdownload-mode3 , --fwdownload-mode3-max , y --fwdownload-mode7 variaciones sobre el --fwdownload básico permiten anular la detección automática de protocolo a favor de forzar a hdparm a usar un protocolo de transferencia específico, solo con fines de
prueba.
-
F
Vacía el búfer de caché de escritura en el disco (los discos más antiguos pueden no implementar
esto).
-
g
Muestra la geometría del disco (cilindros, cabezas, sectores), el tamaño (en sectores) del dispositivo, y el desplazamiento inicial (en sectores) del dispositivo desde el principio del
disco.
-
h
Muestra información de uso concisa (ayuda)
.
-
H
Lee la temperatura de algunos discos (mayoritariamente Hitachi). También informa si la temperatura está dentro del rango de condiciones de operación (esto puede no ser confiable). No hace que el disco gire si está
inactivo.
-
i
Muestra la información de identificación que los controladores del kernel (IDE, libata) han almacenado desde el arranque/configuración. Esto puede diferir de la información actual obtenible directamente del disco con la -I opción. Los datos devueltos pueden o no ser actuales, dependiendo de la actividad desde el arranque del sistema. Para una interpretación más detallada de la información de identificación, refiérase a AT Attachment Interface for Disk Drives, ANSI ASC X3T9.2 working draft, revision 4a, April 19/93, y ediciones
posteriores.
--idle-immedi
ate
Emite un comando ATA IDLE_IMMEDIATE, para poner el disco en un estado de menor consumo de energía. Usualmente el dispositivo permanece
girando.
--idle-unlo
ad
Emite un comando ATA IDLE_IMMEDIATE_WITH_UNLOAD, para descargar o estacionar los cabezales y poner el disco en un estado de menor consumo de energía. Usualmente el dispositivo permanece
girando.
-
I
Solicita información de identificación directamente del disco, la cual se muestra en un nuevo formato expandido con considerablemente más detalle que con la opción -i más
antigua.
--Iraw
<ruta_del_archivo>
Esta opción vuelca los datos de identificación del disco en binario crudo al archivo
especificado.
--Istd
in
Esta es una variación especial de la -I opción, que acepta un bloque de identificación del disco como entrada estándar en lugar de usar un parámetro /dev/hd* . El formato de este bloque debe ser exactamente igual al que se encuentra en los "archivos" /proc/ide/*/hd*/identify, o al producido por la --Istdout opción descrita a continuación. Esta variación está diseñada para usarse con "bibliotecas" recopiladas de información de identificación de discos, y también puede usarse en discos ATAPI que pueden dar errores de medio con el mecanismo estándar. Cuando --Istdin se usa, debe ser el *único* parámetro proporcionado. Tenga en cuenta que alguna información estará incompleta, ya que las LOG PAGES del disco no están disponibles cuando --Istdin se
usa.
--Istdo
ut
Esta opción vuelca los datos de identificación del disco en hexadecimal a stdout, en un formato similar al de /proc/ide/*/identify, y adecuado para uso posterior con la --Istdin op
ción.
-
J
Obtener/establecer el valor de tiempo de espera "idle3" del disco Western Digital (WD) Green. Este tiempo de espera controla con qué frecuencia el disco estaciona sus cabezales y entra en un estado de bajo consumo de energía. El valor predeterminado de fá
brica es ocho (8) segundos, lo cual es una muy mala elección para su uso con Linux. Dejarlo en el valor predeterminado resultará en cientos de miles de ciclos de carga/descarga de cabezales en un período de tiempo muy corto. El mecanismo del disco solo e
stá calificado para 300,000 a 1,000,000 de ciclos, por lo que dejarlo en el valor predeterminado podría resultar en un fallo prematuro, sin mencionar el impacto en el rendimiento del disco al tener que despertarse a menudo antes de realizar E/S de rutina.
WD proporciona una utilidad DOS WDIDLE3.EXE para ajustar esta configuración, y debería usar ese programa en lugar de hdparm si es posible. La implementación de ingeniería inversa en hdparm no es tan completa como el programa oficial original, aunque parece funcionar en al menos algunos discos. Se requiere un ciclo de encendido completo para que cualquier cambio en la configuración surta efecto, independientemente de qué programa se use para ajustar las
cosas.
Se recomienda una configuración de 30 segundos para uso en Linux. Los valores permitidos son de 8 a 12 segundos, y de 30 a 300 segundos en incrementos de 30 segundos. Especifique un valor de cero (0) para deshabilitar completamente el temporizador WD idle3 (¡NO RECOMENDADO!
)
.
-
k
Obtener/establecer la bandera "keep_settings_over_reset" del disco. Cuando esta bandera está establecida, el disco preservará los -dmu ajustes a través de un reinicio suave, (como se hace durante la secuencia de recuperación de errores). Esta opción está deshabilitada por defecto, para prevenir bucles de reinicio del disco que podrían ser causados por combinaciones de -dmu ajustes. La -k opción por lo tanto solo debería establecerse después de que uno haya alcanzado confianza en el funcionamiento correcto del sistema con un conjunto elegido de ajustes de configuración. En la práctica, todo lo que normalmente es necesario para probar una configuración (antes de usar -k) es verificar que el disco puede ser leído/escrito, y que no se generan registros de errores (mensajes del kernel) en el proceso (busque en /var/log/messages en la mayoría de los sistemas)
.
-
K
Establece la bandera "keep_features_over_reset" del disco. Establecer esto permite al disco retener los ajustes para -APSWXZ a través de un reinicio suave (como se hace durante la secuencia de recuperación de errores). No todos los discos soportan esta
característica.
-
L
Establece la bandera de bloqueo de puerta del disco. Establecer esto a 1 bloqueará el mecanismo de puerta de algunos discos duros extraíbles (ej. Syquest, ZIP, Jazz..), y establecerlo a 0 desbloqueará el mecanismo de puerta. Normalmente, Linux mantiene el mecanismo de bloqueo de puerta automáticamente, dependiendo del uso del disco (bloqueado siempre que un sistema de archivos está montado). Pero en el apagado del sistema, esto puede ser una molestia si la partición raíz está en un disco extraíble, ya que la partición raíz queda montada (solo lectura) después del apagado. Así, usando este comando para desbloquear la puerta después de que el sistema de archivos raíz sea remontado solo lectura, uno puede entonces remover el cartucho del disco después del
apagado.
-
m
Obtener/establecer el conteo de sectores para E/S de múltiples sectores en el disco. Una configuración de 0 deshabilita esta característica. El modo de múltiples sectores (también conocido como IDE Block Mode), es una característica de la mayoría de los discos duros IDE modernos, permitiendo la transferencia de múltiples sectores por interrupción de E/S, en lugar del usual un sector por interrupción. Cuando esta característica está habilitada, típicamente reduce la sobrecarga del sistema operativo para E/S de disco en un 30-50%. En muchos sistemas, también proporciona un aumento en el rendimiento de datos de cualquier cosa desde un 5% hasta un 50%. Algunos discos, sin embargo (notablemente la serie WD Caviar), parecen funcionar más lento con el modo múltiple habilitado. Su experiencia puede variar. La mayoría de los discos soportan las configuraciones mínimas de 2, 4, 8, o 16 (sectores). Configuraciones más grandes también pueden ser posibles, dependiendo del disco. Una configuración de 16 o 32 parece óptima en muchos sistemas. Western Digital recomienda configuraciones más bajas de 4 a 8 en muchos de sus discos, debido a pequeños (32kB) búferes de disco y algoritmos de búfer no optimizados. La -i opción puede usarse para encontrar la configuración máxima soportada por un disco instalado (busque MaxMultSect en la salida). Algunos discos afirman soportar el modo múltiple, pero pierden datos en algunas configuraciones. En circunstancias raras, estos fallos pueden resultar en masiva corrupción del sistema de
archivos.
--make-bad-sec
tor
Crea deliberadamente un sector defectuoso (también conocido como "error de medio") en el disco. EXCEPCIONALMENTE PELIGROSO. ¡¡NO USE ESTA OPCIÓN!! Esto puede ser útil para pruebas de mecanismos de recuperación de errores de dispositivo/RAID. El número de sector se da como un parámetro (base10) después de la opción. Dependiendo del dispositivo, hdparm elegirá uno de dos comandos ATA posibles para corromper el sector. El WRITE_LONG funciona en la mayoría de los discos, pero solo hasta el límite de sector de 28 bits. Algunos discos muy recientes (2008) pueden soportar el nuevo comando WRITE_UNCORRECTABLE_EXT, que funciona para cualquier sector LBA48. Si está disponible, hdparm usará ese en preferencia a WRITE_LONG. El comando WRITE_UNCORRECTABLE_EXT en sí presenta una elección de cómo debe comportarse el nuevo sector defectuoso. Por defecto, se verá como cualquier otro sector defectuoso, y el disco puede tomar algún tiempo en reintentar y fallar en subsecuentes LECTURAs del sector. Sin embargo, si una sola letra f se antepone inmediatamente frente al primer dígito del parámetro del número de sector, entonces hdparm emitirá un WRITE_UNCORRECTABLE_EXT "marcado", lo que hace que el disco simplemente marque el sector como defectuoso (en lugar de corromperlo genuinamente), y las subsecuentes LECTURAs del sector fallarán inmediatamente (en lugar than after several retries). Note also that the --repair-sector option can be used to restore (any) bad sectors when they are no longer needed, including sectors that were genuinely bad (the drive will likely remap those to a fresh area on the media).
-M
Obtiene/establece la configuración de Gestión Acústica Automática (AAM). La mayoría de las unidades de disco duro modernas tienen la capacidad de reducir la velocidad de los movimientos de la cabeza para reducir su ruido. Los valores posibles están entre 0 y 254. 128 es la configuración más silenciosa (y, por lo tanto, más lenta) y 254 la más rápida (y ruidosa). Algunas unidades solo tienen dos niveles (silencioso / rápido), mientras que otras pueden tener diferentes niveles entre 128 y 254. En este momento, la mayoría de las unidades solo admiten 3 opciones: apagado, silencioso y rápido. Estos se han asignado los valores 0, 128 y 254 respectivamente, pero se ha incorporado espacio entero para futuras expansiones, si esto cambia.
-n
Obtiene o establece la bandera "ignore_write_errors" en el controlador. NO juegues con esto sin antes entender el código fuente del controlador.
-N
Obtiene/establece el número máximo de sectores visibles, también conocido como la configuración del Área Protegida por Host. Sin un parámetro, -N muestra la configuración actual, que se informa como dos valores: el primero proporciona la configuración actual del número máximo de sectores, y el segundo muestra el límite de hardware nativo (real) del disco. La diferencia entre estos dos valores indica cuántos sectores del disco están actualmente ocultos del sistema operativo, en forma de un Área Protegida por Host (HPA). Esta área a menudo es utilizada por los fabricantes de computadoras para almacenar software de diagnóstico y/o una copia del sistema operativo proporcionado originalmente para fines de recuperación. Otro uso posible es ocultar la capacidad real de un disco muy grande a una BIOS/sistema que normalmente no puede manejar unidades de ese tamaño (por ejemplo, la mayoría de las BIOS actuales {2010} no pueden manejar unidades mayores a 2TB, por lo que se podría usar una HPA para que una unidad de 3TB se informe a sí misma como una unidad de 2TB). Para cambiar el máximo actual (MUY PELIGROSO, LA PÉRDIDA DE DATOS ES EXTREMADAMENTE PROBABLE), se debe proporcionar un nuevo valor (en base 10) inmediatamente después de la opción -N. Este valor se especifica como un recuento de sectores, en lugar de la "dirección máxima del sector" de la unidad. Las unidades tienen el concepto de una configuración temporal (volátil) que se pierde en el próximo reinicio de hardware, así como un valor más permanente (no volátil) que sobrevive a reinicios y ciclos de energía. Por defecto, -N afecta solo a la configuración temporal (volátil). Para cambiar el valor permanente (no volátil), anteponga un carácter p inmediatamente antes del primer dígito del valor. Las unidades se supone que solo permiten un cambio permanente por sesión. Se requiere un reinicio de hardware (o ciclo de energía) antes de que otra operación permanente de -N pueda tener éxito. Tenga en cuenta que cualquier intento de establecer este valor puede fallar si el disco está siendo accedido por otro software al mismo tiempo. Esto se debe a que establecer el valor requiere un par de comandos de unidad consecutivos, pero no hay forma de evitar que algún otro comando sea insertado entre ellos por el kernel. Por lo tanto, si falla inicialmente, simplemente inténtelo de nuevo. El soporte del kernel para -N es defectuoso para muchos tipos de adaptadores en muchas versiones del kernel, en el sentido de que a veces se informa un valor de tamaño máximo incorrecto (demasiado pequeño). A partir del kernel 2.6.27, esto parece estar funcionando en la mayoría del hardware.
--offset
Desplazamientos al número dado de GiB (1024*1024*1024) al realizar las mediciones de tiempo de lectura del dispositivo -t. Cambios de velocidad (aproximadamente el doble) en muchas unidades mecánicas. Por lo general, el máximo está al principio, pero no siempre. Las unidades de estado sólido (SSD) deberían mostrar tiempos similares independientemente del desplazamiento.
-p
Intenta reprogramar el chipset de la interfaz IDE para el modo PIO especificado, o intenta sintonizar automáticamente el "mejor" modo PIO compatible con la unidad. Esta característica es compatible en el kernel solo para algunos chipsets "conocidos", e incluso entonces el soporte es dudoso en el mejor de los casos. Algunos chipsets IDE no pueden alterar el modo PIO para una sola unidad, en cuyo caso esta opción puede hacer que se establezca el modo PIO para *ambas* unidades. Muchos chipsets IDE admiten menos o más de los seis modos PIO estándar (0 a 5), por lo que la configuración de velocidad exacta que se implementa variará según la sofisticación del chipset/controlador. *¡Úselo con extrema precaución!* ¡Esta característica no incluye protección para los descuidados, y un resultado insatisfactorio puede resultar en una *severa corrupción del sistema de archivos*!
-P
Establece el número máximo de sectores para el mecanismo de prelectura interno de la unidad. No todas las unidades admiten esta característica, y se eliminó de la especificación oficial a partir de ATA-4.
--prefer-ata12
Al usar el protocolo SAT (SCSI ATA Translation), hdparm normalmente prefiere usar el formato de comando de 16 bytes siempre que sea posible. Pero algunas carcasas de unidades USB no funcionan correctamente con comandos de 16 bytes. Esta opción se puede usar para forzar el uso del formato de comando más pequeño de 12 bytes con dichas unidades. hdparm seguirá recurriendo a comandos de 16 bytes para cosas que no se pueden hacer con el formato de 12 bytes (por ejemplo, accesos a sectores más allá de 28 bits).
-q
Maneja la siguiente opción silenciosamente, suprimiendo la salida normal (pero no los mensajes de error). Esto es útil para reducir el desorden en la pantalla cuando se ejecuta desde scripts de inicio del sistema. No aplicable a las opciones -i, -v, -t o -T.
-Q
Obtiene o establece la profundidad de cola de comandos del dispositivo, si es compatible con el hardware. Esto solo funciona con kernels 2.6.xx (o posteriores), y solo con combinaciones de dispositivos y controladores que admitan el cambio de la profundidad de cola. Para discos SATA, esta es la profundidad de cola de Native Command Queuing (NCQ).
-r
Obtiene/establece la bandera de solo lectura para el dispositivo. Cuando se establece, Linux prohíbe las operaciones de escritura en el dispositivo.
-R
Obtiene/establece la característica Write-Read-Verify, si la unidad la admite. Uso: -R0 (deshabilitar) o -R1 (habilitar). Esta característica está destinada a hacer que el firmware de la unidad lea de nuevo cualquier dato que se escriba por software, para verificar que los datos se escribieron correctamente. Esto es generalmente excesivo y puede ralentizar las escrituras en disco hasta en un factor de dos (o más).
--read-sector
Lee del número de sector especificado y vuelca el contenido en hexadecimal a la salida estándar. El número de sector debe proporcionarse (base 10) después de esta opción. hdparm emitirá una lectura de bajo nivel (saltándose completamente los mecanismos habituales de lectura/escritura de capas de bloques) para el sector especificado. Esto se puede usar para verificar de manera definitiva si un sector dado está defectuoso (error de medio) o no (hacerlo a través de los mecanismos habituales a veces puede dar falsos positivos).
--repair-sector
Este es un alias para la opción --write-sector. MUY PELIGROSO.
-s
Habilita/deshabilita la característica de encendido en espera, si es compatible con la unidad. *¡MUY PELIGROSO!* No lo use a menos que esté absolutamente seguro de que tanto la BIOS (o firmware) del sistema como el kernel del sistema operativo (Linux >= 2.6.22) admiten la detección de unidades que usan esta característica. Cuando está habilitada, la unidad se enciende en modo de espera para permitir que el controlador secuencie el arranque de los dispositivos, reduciendo la carga de corriente instantánea cuando muchas unidades comparten una fuente de alimentación. Principalmente para uso en configuraciones RAID grandes. Esta característica generalmente está deshabilitada y la unidad se enciende en modo activo (ver -C arriba). Tenga en cuenta que una unidad también puede permitir habilitar esta característica mediante un jumper. Algunas unidades SATA admiten el control de esta característica a través del pin 11 del conector de alimentación SATA. En estos casos, este comando puede no ser compatible o no tener ningún efecto.
-S
Pone la unidad en modo inactivo (bajo consumo) y también establece el tiempo de espera de espera (apagado) para la unidad. Este valor de tiempo de espera es utilizado por la unidad para determinar cuánto tiempo esperar (sin actividad de disco) antes de apagar el motor del husillo para ahorrar energía. En tales circunstancias, la unidad puede tardar hasta 30 segundos en responder a un acceso posterior al disco, aunque la mayoría de las unidades son mucho más rápidas. La codificación del valor de tiempo de espera es algo peculiar. Un valor de cero significa "tiempos de espera deshabilitados": el dispositivo no entrará automáticamente en modo de espera. Los valores del 1 al 240 especifican múltiplos de 5 segundos, lo que produce tiempos de espera de 5 segundos a 20 minutos. Los valores del 241 al 251 especifican de 1 a 11 unidades de 30 minutos, lo que produce tiempos de espera de 30 minutos a 5,5 horas. Un valor de 252 significa un tiempo de espera de 21 minutos. Un valor de 253 establece un período de tiempo de espera definido por el fabricante entre 8 y 12 horas, y el valor 254 está reservado. 255 se interpreta como 21 minutos y 15 segundos. Tenga en cuenta que algunas unidades más antiguas pueden tener interpretaciones muy diferentes de estos valores.
--set-sector-size
Para unidades que admiten la reconfiguración del Tamaño de Sector Lógico, esta bandera se puede usar para especificar el nuevo tamaño de sector deseado en bytes. *¡MUY PELIGROSO. ¡Lo más probable es que esto mezcle todos los datos en la unidad!* El tamaño especificado debe ser uno de 512, 520, 528, 4096, 4160 o 4224. Muy pocas unidades admiten valores distintos de 512 y 4096. Por ejemplo: hdparm --set-sector-size 4096 /dev/sdb
-t
Realiza mediciones de tiempo de las lecturas del dispositivo con fines de referencia y comparación. Para obtener resultados significativos, esta operación debe repetirse 2-3 veces en un sistema inactivo (sin otros procesos activos) con al menos un par de megabytes de memoria libre. Esto muestra la velocidad de lectura a través de la caché del búfer hacia el disco sin ningún tipo de caché de datos previo. Esta medición es una indicación de la rapidez con la que la unidad puede mantener lecturas de datos secuenciales en Linux, sin ninguna sobrecarga del sistema de archivos. Para garantizar mediciones precisas, la caché del búfer se vacía durante el procesamiento de -t utilizando el ioctl BLKFLSBUF.
-T
Realiza mediciones de tiempo de las lecturas de caché con fines de referencia y comparación. Para obtener resultados significativos, esta operación debe repetirse 2-3 veces en un sistema inactivo (sin otros procesos activos) con al menos un par de megabytes de memoria libre. Esto muestra la velocidad de lectura directamente desde la caché del búfer de Linux sin acceso al disco. T
su medición es esencialmente una indicación del rendimiento del procesador, la caché y la memoria del sistema bajo prueba.

BUGS

Some older IDE drives do not properly support the default values for the I/O-IF timing (PIO mode) values. For these drives, the values given by the kernel are not correct and it is necessary to specify these values using hdparm.

The IDE drives of the Seagate Barracuda 133 revision BIOS/Firmware <12/30/2001 10:44:17> have a bug in their auto-powersaving mode. It is possible that hdparm does not detect this bug and therefore doesn´t report it. If the drive powers down unexpectedly it is recommended to disable the auto-powersaving mode by setting the value to 0. If this does not help, the drive may have to be replaced.

The IDE drives of the Maxtor DiamondMax Plus 8 (DMA33) have a bug in their auto-powersaving mode. It is possible that hdparm does not detect this bug and therefore doesn´t report it. If the drive powers down unexpectedly it is recommended to disable the auto-powersaving mode by setting the value to 0. If this does not help, the drive may have to be replaced.

The Western Digital WD1200JB drive has a bug where it will not report its geometry correctly. This bug can be worked around by specifying the correct geometry using the -g option.

The Linux kernel up until 2.6.12 (and probably later) doesn´t handle the security unlock and disable commands gracefully and will segfault and in some cases even panic. The security commands however might indeed have been executed by the drive. This poor kernel behaviour makes the PIO data security commands rather useless at the moment.

Note that the "security erase" and "security disable" commands have been implemented as two consecutive PIO data commands and will not succeed on a locked drive because the second command will not be issued after the segfault. See the code for hints how patch it to work around this problem. Despite the segfault it is often still possible to run two instances of hdparm consecutively and issue the two necessary commands that way.

Necessary ioctl()s were not supported.
