Descripción Detallada

Algunos sistemas operativos solo admiten el enlazado de hilos o procesos a una sola PU. Otros permiten el enlazado a conjuntos más grandes como Núcleos completos o Paquetes o incluso conjuntos aleatorios de PUs individuales. En tales sistemas operativos, el planificador es libre de ejecutar la tarea en una de estas PU, luego migrarla a otra PU, etc. A menudo es útil llamar a hwloc_bitmap_singlify() en el conjunto de CPU de destino antes de pasarlo a la función de enlazado para evitar estas migraciones costosas. Véase la documentación de hwloc_bitmap_singlify() para más detalles.

Algunos sistemas operativos no proporcionan todos los mecanismos admitidos por hwloc para enlazar procesos, hilos, etc. hwloc_topology_get_support() puede usarse para consultar sobre el soporte real de enlazado de CPU en el sistema operativo actualmente utilizado.

Cuando la operación de enlazado solicitada no está disponible y se pasó el HWLOC_CPUBIND_STRICT indicador, la función devuelve -1. errno se establece a ENOSYS cuando no es posible enlazar el tipo solicitado de objetos procesos/hilos. errno se establece a EXDEV cuando el conjunto de CPU solicitado no puede aplicarse (por ejemplo, algunos sistemas solo permiten una CPU, y algunos otros sistemas solo permiten un nodo NUMA).

Si HWLOC_CPUBIND_STRICT no se pasó, la función puede fallar también, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de enlazado más pequeño, etc.) cuando la operación solicitada no es exactamente admitida.

La versión más portable que debería preferirse sobre las demás, siempre que sea posible, es la siguiente que simplemente enlaza el programa actual, asumiendo que es de un solo hilo:

hwloc_set_cpubind(topology, set, 0),

Si el programa puede ser multihilo, la siguiente debería preferirse para enlazar solo el hilo actual:

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Véase también

Algunos códigos de ejemplo están disponibles bajo doc/examples/ en el árbol de fuentes.

Nota

Para desenlazar, simplemente llame a la función de enlazado con un conjunto de CPU completo o un conjunto de CPU igual al conjunto de CPU del sistema.

En algunos sistemas operativos, el enlazado de CPU puede tener efectos en el enlazado de memoria, véase HWLOC_CPUBIND_NOMEMBIND

Ejecutar lstopo --top o hwloc-ps puede ser una herramienta muy conveniente para verificar cómo ocurrió realmente el enlazado.

Documentación del Tipo de Enumeración

enum hwloc_cpubind_flags_t

Indicadores de enlazado de Proceso/Hilo. Estos indicadores de bits pueden usarse para refinar la política de enlazado.

El valor predeterminado (0) es enlazar el proceso actual, asumido como de un solo hilo, de una manera no estricta. Esta es la forma más portable de enlazar ya que todos los sistemas operativos suelen proporcionarla.

Nota

No todos los sistemas admiten todos los tipos de enlazado. Véase la sección 'Descripción Detallada' de Enlazado de CPU para una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_CPUBIND_PROCESS
Enlazar todos los hilos del proceso actual (posiblemente) multihilo.
HWLOC_CPUBIND_THREAD
Enlazar el hilo actual del proceso actual.
HWLOC_CPUBIND_STRICT
Solicitar enlazado estricto del SO. Por defecto, cuando las CPUs designadas están todas ocupadas mientras otras CPUs están inactivas, los sistemas operativos pueden ejecutar el hilo/proceso en esas otras CPUs en lugar de las CPUs designadas, para dejarlas avanzar de todos modos. El enlazado estricto significa que el hilo/proceso _nunca_ se ejecutará en otras CPUs que las designadas, incluso cuando estén ocupadas con otras tareas y otras CPUs estén inactivas.

Nota

Dependiendo del sistema operativo, el enlazado estricto puede no ser posible (por ejemplo, el SO no lo implementa) o no permitido (por ejemplo, por razones administrativas), y la función fallará en ese caso.

Al recuperar el enlazado de un proceso, este indicador verifica si todos sus hilos realmente tienen el mismo enlazado. Si el indicador no se da, el enlazado de cada hilo se acumulará.

Nota

Este indicador es sin sentido al recuperar el enlazado de un hilo.
HWLOC_CPUBIND_NOMEMBIND
Evitar cualquier efecto en el enlazado de memoria. En algunos sistemas operativos, algunas funciones de enlazado de CPU también enlazarían la memoria en el nodo NUMA correspondiente. A menudo no es un problema para la aplicación, pero si lo es, establecer este indicador hará que hwloc evite usar funciones del SO que también enlazarían memoria. Esto sin embargo reducirá el soporte de enlazados de CPU, es decir, potencialmente devolver -1 con errno establecido a ENOSYS en algunos casos.

Este indicador solo tiene sentido cuando se usa con funciones que establecen el enlazado de CPU. Se ignora cuando se usa con funciones que obtienen información de enlazado de CPU.

Documentación de Funciones

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtener el enlazado actual del proceso o hilo. El conjunto de CPU set (previamente asignado por el llamador) se llena con la lista de PUs a las que el proceso o hilo (según flags) fue enlazado por última vez.

Devuelve

0 en éxito, -1 en error.

int hwloc_get_last_cpu_location (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtener la última CPU física donde se ejecutó el proceso o hilo actual. El conjunto de CPU set (previamente asignado por el llamador) se llena con la lista de PUs donde el proceso o hilo (según flags) se ejecutó por última vez.

El sistema operativo puede mover algunas tareas de un procesador a otro en cualquier momento según su enlazado, por lo que esta función puede devolver algo que ya obsoleto.

flags puede incluir HWLOC_CPUBIND_PROCESS o HWLOC_CPUBIND_THREAD para especificar si la consulta debe ser para todo el proceso (unión de todos los CPU en los que se ejecutan todos los hilos), o solo para el hilo actual. Si el proceso es de un solo hilo, flags puede establecerse en cero para que hwloc use cualquier método disponible en el sistema operativo subyacente.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_get_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Obtiene el enlace físico actual del proceso pid. El conjunto de CPU set (previamente asignado por el llamante) se rellena con la lista de PUs a los que el proceso fue enlazado por última vez.

Devuelve

0 en caso de éxito, -1 en caso de error.

Nota

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

Como caso especial en Linux, si se proporciona un tid (ID de hilo) en lugar de un pid (ID de proceso) y se pasa HWLOC_CPUBIND_THREAD en flags, se devuelve el enlace de ese hilo específico.

En sistemas que no son Linux, HWLOC_CPUBIND_THREAD no puede usarse en flags.

int hwloc_get_proc_last_cpu_location (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Obtiene la última CPU física en la que se ejecutó un proceso. El conjunto de CPU set (previamente asignado por el llamante) se rellena con la lista de PUs en los que el proceso se ejecutó por última vez.

El sistema operativo puede mover algunas tareas de un procesador a otro en cualquier momento según su enlace, por lo que esta función puede devolver algo que ya está obsoleto.

Devuelve

0 en caso de éxito, -1 en caso de error.

Nota

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

Como caso especial en Linux, si se proporciona un tid (ID de hilo) en lugar de un pid (ID de proceso) y HWLOC_CPUBIND_THREAD se pasa en flags, se devuelve la última ubicación de CPU de ese hilo específico.

En sistemas que no son Linux, HWLOC_CPUBIND_THREAD no puede usarse en flags.

int hwloc_get_thread_cpubind (hwloc_topology_t topology, hwloc_thread_t thread, hwloc_cpuset_t set, int flags)

Obtiene el enlace físico actual del hilo tid. El conjunto de CPU set (previamente asignado por el llamante) se rellena con la lista de PUs a los que el hilo fue enlazado por última vez.

Devuelve

0 en caso de éxito, -1 en caso de error.

Nota

hwloc_thread_t es pthread_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

HWLOC_CPUBIND_PROCESS no puede usarse en flags.

int hwloc_set_cpubind (hwloc_topology_t topology, hwloc_const_cpuset_t set, int flags)

Enlaza el proceso o hilo actual a los CPU dados en el mapa de bits físico set.

Devuelve

0 en caso de éxito.

-1 con errno establecido a ENOSYS si la acción no es soportada.

-1 con errno establecido a EXDEV si el enlace no puede ser aplicado.

int hwloc_set_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_const_cpuset_t set, int flags)

Enlaza un proceso pid a los CPU dados en el mapa de bits físico set.

Devuelve

0 en caso de éxito, -1 en caso de error.

Nota

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

Como caso especial en Linux, si se proporciona un tid (ID de hilo) en lugar de un pid (ID de proceso) y HWLOC_CPUBIND_THREAD se pasa en flags, el enlace se aplica a ese hilo específico.

En sistemas que no son Linux, HWLOC_CPUBIND_THREAD no puede usarse en flags.

int hwloc_set_thread_cpubind (hwloc_topology_t topology, hwloc_thread_t thread, hwloc_const_cpuset_t set, int flags)

Enlaza un hilo thread a los CPU dados en el mapa de bits físico set.

Devuelve

0 en caso de éxito, -1 en caso de error.

Nota

HWLOC_CPUBIND_PROCESS no puede usarse en flags.
