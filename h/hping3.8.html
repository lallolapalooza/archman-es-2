DESCRIPCIÓ

N

hping2 es una herramienta de red capaz de enviar paquetes TCP/IP personalizados y de mostrar las respuestas del objetivo como hace el programa ping con las respuestas ICMP. hping2 maneja la fragmentación, el cuerpo y el tamaño arbitrarios de los paquetes y puede usarse para transferir archivos encapsulados bajo protocolos soportados. Usando hping2 puedes realizar al menos lo

siguiente:


- Probar reglas de firewall
- Escaneo de puertos avanzado
- Probar el rendimiento de la red usando diferentes protocolos,
tamaño de paquete, TOS (tipo de servicio) y fragmentación.
- Descubrimiento de MTU de la ruta
- Transferir archivos incluso entre reglas de firewall realmente fascistas.
reglas.
- Traceroute bajo diferentes protocolos.
- Uso tipo Firewalk.
- Identificación remota del sistema operativo.
- Auditoría de la pila TCP/IP.
- Muchas otras

cosas.

También es una buena herramienta didáctica para aprender TCP/IP. hping2 es desarrollado y mantenido por antirez@invece.org y está li

cenciado bajo la GPL versión 2. El desarrollo es abierto, así que
puedes enviarme parches, sugerencias e insultos sin inhibiciones.

SELECCIÓN DE

PROTOCOLO

El protocolo por defecto es TCP, por defecto hping2 enviará cabeceras TCP al puerto 0 del host objetivo con una ventana de 64 sin ningún flag TCP activado. A menudo esta es la mejor manera de hacer un 'ping oculto', útil cuando el objetivo está detrás de un firewall que descarta ICMP. Además, un TCP con flags nulos al puerto 0 tiene una buena probabilidad de no ser

registrado.
-0
--rawip
Modo IP RAW, en este modo hping2 enviará una cabecera IP con datos añadidos con --signature y/o --file, ver también --ipproto que te permite establecer el campo de protocolo
ip.
-1
--icmp
Modo ICMP, por defecto hping2 enviará un echo-request ICMP, puedes establecer otro tipo/código ICMP usando las opciones --icmptype
--icmpcode.
-2
--udp
Modo UDP, por defecto hping2 enviará udp al puerto 0 del host objetivo. Las opciones configurables de la cabecera UDP son las siguientes: --baseport,
--destport,
--kee
p.
-8 --scan Modo de escaneo, la opción espera un argumento que describe grupos de puertos a escanear. Los grupos de puertos están separados por comas: un número describe un solo puerto, así que 1,2,3 significa el puerto 1, 2 y 3. Los rangos se especifican usando una notación inicio-fin, como 1-1000, que le indica a hping que escanee los puertos entre 1 y 1000 (incluidos). La palabra especial all es un alias para 0-65535, mientras que la palabra especial
known incluye todos los puertos listados en /etc/services. Los grupos se pueden combinar, así que la siguiente línea de comando escaneará los puertos entre 1 y 1000 Y el puerto 8888 Y los puertos listados en /etc/services:
hping --scan 1-1000,8888,known -S target.host.com Los grupos se pueden negar (restar) usando un carácter ! como prefijo, así que la siguiente línea de comando escaneará todos los puertos NO listados en /etc/services en el rango 1-1024:
hping --scan '1-1024,!known' -S target.host.com Ten en cuenta que aunque hping parece mucho más como un escáner de puertos en este modo, la mayoría de las opciones de hping siguen siendo respetadas, así que por ejemplo para realizar un escaneo SYN necesitas especificar la opción -S, puedes cambiar el tamaño de la ventana TCP, el TTL, controlar la fragmentación IP como de costumbre, y así sucesivamente. La única diferencia real es que laLos comportamientos de hping se encapsulan en un algoritmo de escaneo.
Nota técnica: El modo de escaneo utiliza un diseño de dos procesos, con memoria compartida para la sincronización. El algoritmo de escaneo aún no es óptimo, pero ya es bastante rápido.
Pista: A diferencia de la mayoría de los escáneres, hping muestra información interesante sobre los paquetes recibidos, como el ID de IP, la ventana de TCP, el TTL, etc. No olvides mirar esta información adicional cuando realices un escaneo. A veces muestran detalles
interesantes.

Modo de escucha de HPING2, con esta opción hping2 espera paquetes que contengan una firma y muestra desde el final de la firma hasta el final del paquete. Por ejemplo, si hping2 --listen TEST lee un paquete que contiene 234-09sdflkjs45-TESThello_world mostrará hello
_w
orl

FORMATO DE SALIDA

TCP

El formato de salida estándar de TCP es el

siguiente:

len=46 ip=192.168.1.1 flags=RA DF seq=0 ttl=255 id=0 win=0 rtt=0.4

ms

len es el tamaño, en bytes, de los datos capturados desde la capa de enlace de datos excluyendo el tamaño de la cabecera de la capa de enlace de datos. Esto puede no coincidir con el tamaño del datagrama IP debido al relleno de la capa de transporte de bajo

nivel.

ip es la dirección ip de

origen.

flags son los flags de TCP, R para RESET, S para SYN, A para ACK, F para FIN, P para PUSH, U para URGENT, X para el no estándar 0x40, Y para el no estándar

0x80.

Si la respuesta contiene DF la cabecera IP tiene el bit de no fragmentar

establecido.

seq es el número de secuencia del paquete, obtenido usando el puerto de origen para paquetes TCP/UDP, el campo de secuencia para paquetes

ICMP.

id es el campo IP

ID.

win es el tamaño de la ventana de

TCP.

rtt es el tiempo de ida y vuelta en

milisegundos.

IP.

sum es el valor de la suma de comprobación de la cabecera

ICMP

Un ejemplo de salida ICMP

Es muy simple de entender. Comienza con la cadena "ICMP" seguida de la descripción del error ICMP, Port Unreachable en el ejemplo. El campo ip es la dirección IP de origen del datagrama IP que contiene el error ICMP, el campo name es simplemente la dirección numérica resuelta a un nombre (una petición dns PTR) o UNKNOWN si la resolución

falló.

diferente:

net

name=UNKNOWN

La única diferencia es l

a descripción del error,
comienza con TTL 0.
