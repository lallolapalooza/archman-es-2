DESCRIPCIÓ

N

HAProxy es un proxy inverso TCP/HTTP que es particularmente adecuado para entornos de alta disponibilidad. De hecho, puede:
- enrutar peticiones HTTP dependiendo de cookies asignadas estáticamente ;
- distribuir la carga entre varios servidores asegurando la
persistencia del servidor mediante el uso de cookies HTTP ;
- cambiar a servidores de respaldo en caso de fallo de uno principal ;
- aceptar conexiones a puertos especiales dedicados al
monitoreo de servicios ;
- dejar de aceptar conexiones sin romper las existentes ;
- añadir/modificar/eliminar cabeceras HTTP en ambos sentidos ;
- bloquear peticiones que coincidan con un patrón particular ;
- mantener a los clientes en el servidor de aplicación correcto dependiendo de
cookies de la aplicación
- informar el estado detallado como páginas HTML a usuarios autenticados desde una
URI interceptada de la

aplicación.

Necesita muy pocos recursos. Su arquitectura basada en eventos

le permite manejar fácilmente miles de conexiones simultáneas en c
ientos de instancias sin arriesgar la estabilidad del sistema.

OPCIONE

S
-f <archivo_de_configuración
|dir>
Especifica la ruta del archivo de configuración o directorio. Si el argumento es un directorio, los archivos (y solo archivos) que contiene se añaden en orden léxico (usando LC_COLLATE=C) ; solo se añaden los archivos no ocultos con extensión ".
cfg".
-L
<nombre>
Establece el nombre del par de la instancia local. Los pares se definen en la sección de configuración peers y se usan para sincronizar tablas de adherencia (stick tables) entre diferentes instancias. Si esta opción no se especifica, se usa el nombre de host local como nombre del par. Este nombre se exporta en la variable de entorno $HAPROXY_LOCALPEER y puede usarse en el archivo de
configuración.
-n
<maxconn>
Establece el límite superior para el número total de conexiones
simultáneas.
-N
<maxconn>
Establece el límite superior para el número de conexiones simultáneas por
listener.
-C
<dir>
Cambia el directorio a <dir> antes de cargar cualquier
archivo.
-
v
Muestra la versión de
HAProxy.
-v
v
Muestra la versión de HAProxy y todas las opciones de
compilación.
-
d
Inicia en primer plano con el modo de depuración habilitado. Cuando el proxy se ejecuta en este modo, vuelca todas las conexiones, desconexiones, marcas de tiempo y cabeceras HTTP a stdout. Esto NUNCA debe usarse en un script de init ya que evitará que el sistema
arranque.
-
D
Inicia en modo
daemon.
-
W
Inicia en modo master-worker. Puede usarse tanto con el modo de primer plano como con el modo
daemon.
-W
s
Inicia en modo master-worker con soporte de notificación de systemd. Le indica a systemd cuando el proceso está listo. Este modo fuerza el primer
plano.
-
q
Deshabilita los mensajes en la
salida.
-
V
Muestra mensajes en la salida incluso cuando se especifica -q o 'quiet'. Alguna información sobre los pollers y el archivo de configuración se muestra durante el
arranque.
-
c
Solo verifica el archivo de configuración y sale con el código 0 si no se encontró ningún error, o sale con el código 1 si se encontró un error de
sintaxis.
-p
<pidfile>
Pide al proceso que escriba cada uno de los pids de sus hijos en este archivo en modo daemon o pide al proceso que escriba el pid de su master en este archivo en modo
master-worker.
-d
k
Deshabilita el uso de kqueue(2). kqueue(2) solo está disponible en sistemas
BSD.
-d
v
Deshabilita el uso de puertos de eventos. Los puertos de eventos solo están disponibles en sistemas SunOS derivados de Solaris 10 y posteriores (incluyendo sistemas illumos)
.
-d
s
Deshabilita el uso de epoll(7) especulativo. epoll(7) solo está disponible en Linux 2.6 y algunos sistemas Linux 2.4
personalizados.
-d
e
Deshabilita el uso de epoll(7). epoll(7) solo está disponible en Linux 2.6 y algunos sistemas Linux 2.4
personalizados.
-d
p
Deshabilita el uso de poll(2). select(2) podría usarse en su
lugar.
-d
S
Deshabilita el uso de splice(2), que está roto en kernels
antiguos.
-d
b
Deshabilita el modo en segundo plano (permanece en primer plano, útil para depurar). Para depurar, la opción '-db' es muy útil ya que deshabilita temporalmente el modo daemon y el modo multiproceso. El servicio puede entonces detenerse simplemente presionando Ctrl-C, sin tener que editar la configuración ni ejecutar una depuración
completa.
-dM[<byte>
]
Inicializa todas las áreas de memoria asignadas con el <byte> dado. Esto facilita la detección de errores resultantes de accesos a memoria no inicializada, a costa de tocar toda la memoria asignada una vez. Si no se especifica <byte>, el valor predeterminado es 0x50 (ASCII 'P')
.
-m
<megs>
Impone un límite de uso de memoria a un máximo de <megs>
megabytes.
-sf
<pidlist>
Envía la señal FINISH a los pids en pidlist después del arranque. Los procesos que reciben esta señal esperarán a que todas las sesiones terminen antes de salir. Esta opción debe especificarse al final, seguida de cualquier número de PIDs. Técnicamente hablando, se envían SIGTTOU y SIGUSR1
.
-st
<pidlist>
Envía la señal TERMINATE a los pids en pidlist después del arranque. Los procesos que reciben esta señal terminarán inmediatamente, cerrando todas las sesiones activas. Esta opción debe especificarse al final, seguida de cualquier número de PIDs. Técnicamente hablando, se envían SIGTTOU y SIGTERM
.
-x <unix_socket>
Intenta conectarse al socket unix y recuperar todos los sockets de escucha del proceso antiguo. Estos sockets se usarán entonces si es posible en lugar de vincular
nuevos.
-S <bind>[,<bind options>.
..]
En modo master-worker, crea un CLI master. Est
e CLI permitirá el acceso al CLI de cada
worker. Útil para depurar, es una forma conve
niente de acceder a un proceso saliente.

REGISTRO

(LOGGING)

Dado que HAProxy puede ejecutarse dentro de un chroot, no puede acceder de forma fiable a /dev/log. Por esta razón, usa el protocolo UDP para enviar sus registros al servidor, incluso si es el servidor local. Las personas que tengan problemas para recibir registros deben asegurarse de que su demonio syslog escuche en el socket UDP. Varias distribuciones de Linux que incluyen syslogd del paquete sysklogd tienen UDP deshabilitado por defecto. La opción -r debe pasarse a

l demonio para
habilitar UDP.

SEÑALE

S

Algunas señales tienen un significado especial para el demonio haproxy. Generalmente, sonse usa entre demonios y no necesita ser utilizado por el

administrador.
- SIGUS
R1
Le indica al demonio que detenga todos los proxys y salga una vez que todas las sesiones hayan sido cerradas. A menudo se le conoce como la señal de "parada
suave".
- SIGUS
R2
En modo maestro-trabajador, recarga la configuración y envía una señal de parada suave a los procesos
antiguos.
- SIGTT
OU
Le indica al demonio que deje de escuchar en todos los sockets. Utilizado internamente por -sf y -st
.
- SIGTT
IN
Le indica al demonio que reinicie la escucha en todos los sockets después de un SIGTTOU. Se utiliza internamente cuando hubo un problema durante la reconfiguración en
caliente.
- SIGINT y SIGTE
RM
Ambas señales se pueden utilizar para detener rápidamente el
demonio.
- SIGH
UP
Vuelca el estado de todos los proxys y servidores en los registros. Se usa principalmente con fines de resolución de
problemas.
- SIGQU
IT
Vuelca información sobre los grupos de memoria en stderr. Se usa principalmente con fines de
depuración.
- SIGPI
PE
Esta señal se intercepta y se ignora en sistemas sin MSG_N
OSI
GN
AL.
