Documentación del Tipo de Enumeración

enum hwloc_allow_flags_e

Banderas que deben darse a hwloc_topology_allow().

Enumerador

HWLOC_ALLOW_FLAG_ALL
Marca todos los objetos como permitidos en la topología. El cpuset y el nodeset dados a hwloc_topology_allow() deben ser NULL.
HWLOC_ALLOW_FLAG_LOCAL_RESTRICTIONS
Solo permite objetos que están disponibles para el proceso actual. La topología debe tener HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM para que el conjunto de recursos disponibles pueda ser realmente recuperado del sistema operativo.

El cpuset y el nodeset dados a hwloc_topology_allow() deben ser NULL.

HWLOC_ALLOW_FLAG_CUSTOM
Permite un conjunto personalizado de objetos, dados a hwloc_topology_allow() como los parámetros cpuset y/o nodeset .

enum hwloc_restrict_flags_e

Banderas que deben darse a hwloc_topology_restrict().

Enumerador

HWLOC_RESTRICT_FLAG_REMOVE_CPULESS
Elimina todos los objetos que se quedaron sin CPU. Por defecto, solo se eliminan los objetos que no contienen ninguna PU ni memoria. Esta bandera no puede usarse con HWLOC_RESTRICT_FLAG_BYNODESET.
HWLOC_RESTRICT_FLAG_BYNODESET
Restringe por nodeset en lugar de por conjunto de CPU. Solo conserva los objetos cuyo nodeset está incluido o parcialmente incluido en el conjunto dado. Esta bandera no puede usarse con HWLOC_RESTRICT_FLAG_REMOVE_CPULESS.
HWLOC_RESTRICT_FLAG_REMOVE_MEMLESS
Elimina todos los objetos que se quedaron sin memoria. Por defecto, solo se eliminan los objetos que no contienen ninguna PU ni memoria. Esta bandera solo puede usarse con HWLOC_RESTRICT_FLAG_BYNODESET.
HWLOC_RESTRICT_FLAG_ADAPT_MISC
Mueve los objetos Misc a sus ancestros si sus padres son eliminados durante la restricción. Si esta bandera no está establecida, los objetos Misc se eliminan cuando sus padres son eliminados.
HWLOC_RESTRICT_FLAG_ADAPT_IO
Mueve los objetos de E/S a sus ancestros si sus padres son eliminados durante la restricción. Si esta bandera no está establecida, los dispositivos y puentes de E/S se eliminan cuando sus padres son eliminados.

Documentación de Funciones

int hwloc_obj_add_other_obj_sets (hwloc_obj_t dst, hwloc_obj_t src)

Configura los cpusets/nodesets del objeto haciendo OR con los conjuntos de otro objeto. Para cada cpuset o nodeset definido en src, se asigna el conjunto correspondiente en dst y se añade src a él haciendo OR de los conjuntos.

Esta función es conveniente entre hwloc_topology_alloc_group_object() y hwloc_topology_insert_group_object(). Construye los conjuntos del nuevo Grupo que será insertado como un nuevo padre intermedio de varios objetos.

Devuelve

0 en caso de éxito.

-1 con errno establecido a ENOMEM si alguna realocación interna falló.

hwloc_obj_t hwloc_topology_alloc_group_object (hwloc_topology_t topology)

Asigna un objeto Grupo para insertarlo más tarde con hwloc_topology_insert_group_object(). Esta función devuelve un nuevo objeto Grupo.

El llamador debe (al menos) inicializar sus conjuntos antes de insertar el objeto en la topología, ver hwloc_topology_insert_group_object(). O puede decidir no insertarlo y simplemente liberar el objeto grupo llamando a hwloc_topology_free_group_object().

Devuelve

El objeto asignado en caso de éxito.

NULL en caso de error.

Nota

Si se inserta correctamente con hwloc_topology_insert_group_object(), el objeto será liberado cuando se libere toda la topología. Si la inserción falló (por ejemplo, conjuntos de CPU y de nodos NULL o vacíos), se libera antes de devolver el error.

int hwloc_topology_allow (hwloc_topology_t restrict topology, hwloc_const_cpuset_t cpuset, hwloc_const_nodeset_t nodeset, unsigned long flags)

Cambia los conjuntos de PUs y nodos NUMA permitidos en la topología. Esta función solo funciona si HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED estaba establecido en la topología. No modifica ningún objeto, solo cambia los conjuntos devueltos por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset().

Es particularmente útil al importar una topología de otro proceso que se ejecuta en un Cgroup de Linux diferente.

flags debe establecerse a una bandera de entre hwloc_allow_flags_e.

Devuelve

0 en caso de éxito, -1 en caso de error.

Nota

La eliminación de objetos de una topología debería realizarse mejor con hwloc_topology_restrict().

int hwloc_topology_free_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Liberar un objeto de grupo asignado con hwloc_topology_alloc_group_object(). Esta función sólo es útil si el objeto de grupo no se entregó a hwloc_topology_insert_group_object() según lo previsto.

Nota

topology debe ser el mismo que se pasó previamente a hwloc_topology_alloc_group_object().

Devoluciones

0 en caso de éxito.

-1 en caso de error, por ejemplo si se proporciona una topología inválida.

hwloc_obj_t hwloc_topology_insert_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Añadir más estructura a la topología insertando un Grupo intermedio. El llamante debe primero asignar un nuevo objeto Grupo con hwloc_topology_alloc_group_object(). Luego debe configurar al menos uno de sus conjuntos de CPU o nodos para especificar la ubicación final del Grupo en la topología. Luego, el objeto puede pasarse a esta función para su inserción real en la topología.

El caso de uso principal de esta función es agrupar un subconjunto de hermanos de la lista de hijos bajo un único padre. Por ejemplo, si se agrupan 4 núcleos de un socket de 8 núcleos, la lista lógica de núcleos se reordenará para que los 4 agrupados sean consecutivos. Luego, si es necesario, se añade una nueva profundidad entre el padre y esos hijos, y el Grupo se inserta allí. Al final, los 4 núcleos agrupados son ahora hijos del Grupo, que los reemplaza como hijo del padre original.

En la práctica, los objetos agrupados se especifican a través de conjuntos de CPU y/o conjuntos de nodos, por ejemplo, utilizando hwloc_obj_add_other_obj_sets() iterativamente. Por lo tanto, es posible agrupar objetos que no son hijos del mismo padre, por ejemplo, algunos PU por debajo de los 4 núcleos en el ejemplo anterior. Sin embargo, este caso general puede fallar si el Grupo esperado entra en conflicto con la jerarquía existente. Por ejemplo, si cada núcleo tiene dos PU, no es posible insertar un Grupo que contenga una sola PU de cada núcleo.

Para especificar los objetos a agrupar, el campo cpuset o nodeset (o ambos, si son compatibles) debe establecerse en un mapa de bits no vacío. El complete_cpuset o complete_nodeset pueden establecerse en su lugar si se inserta con respecto a la topología completa (incluidos objetos no permitidos, fuera de línea o desconocidos). Estos conjuntos no pueden ser más grandes que la topología actual, o se restringirán silenciosamente. El núcleo configurará los otros conjuntos después de la inserción real.

El atributo subtype del objeto puede definirse con hwloc_obj_set_subtype() para mostrar algo diferente de 'Group' como nombre de tipo para este objeto en lstopo. Se pueden añadir pares de información personalizados de nombre-valor con hwloc_obj_add_info() después de la inserción.

El atributo dont_merge del grupo puede establecerse en 1 para evitar que el núcleo de hwloc fusione este objeto con otro objeto jerárquicamente idéntico. Esto es útil cuando el Grupo en sí describe una característica importante que no se puede exponer en ningún otro lugar de la jerarquía.

El atributo kind del grupo puede establecerse en un valor alto como 0xffffffff para indicar a hwloc que este nuevo Grupo debe ser descartado siempre en favor de cualquier Grupo existente con la misma localidad.

Nota

La inserción de un grupo añade información de localidad a la topología, por lo tanto, los objetos existentes pueden ser reordenados (incluyendo PUs y nodos NUMA), y sus índices lógicos pueden cambiar.

Si la inserción falla, el objeto de grupo de entrada se libera.

Si el objeto de grupo debe ser descartado en lugar de insertado, puede pasarse a hwloc_topology_free_group_object() en su lugar.

topology debe ser el mismo que se pasó previamente a hwloc_topology_alloc_group_object().

Devoluciones

El objeto insertado si se insertó correctamente.

Un objeto existente si el Grupo se fusionó o descartó porque la topología ya contenía un objeto en la misma ubicación (el Grupo no añadió ninguna información de jerarquía).

NULL si la inserción falló debido a conflictos de conjuntos en el árbol de topología.

NULL si los objetos de Grupo se filtran de la topología (HWLOC_TYPE_FILTER_KEEP_NONE).

NULL si el objeto se descartó porque no se inicializó ningún conjunto en el Grupo antes de la inserción, o todos estaban vacíos.

hwloc_obj_t hwloc_topology_insert_misc_object (hwloc_topology_t topology, hwloc_obj_t parent, const char * name)

Añadir un objeto MISC como hoja de la topología. Se creará un nuevo objeto MISC y se insertará en la topología en la posición dada por parent. Se añade a la lista de hijos Misc existentes, sin añadir nunca ningún nivel jerárquico intermedio. Esto es útil para anotar la topología sin cambiar realmente la jerarquía.

name se supone que es único entre todos los objetos Misc en la topología. Se duplicará para configurar los atributos del nuevo objeto.

El nuevo objeto hoja no tendrá ningún cpuset.

El atributo subtype del objeto puede definirse con hwloc_obj_set_subtype() después de una inserción exitosa.

Devoluciones

el objeto recién creado

NULL en caso de error.

NULL si los objetos Misc se filtran de la topología (HWLOC_TYPE_FILTER_KEEP_NONE).

Nota

Si name contiene caracteres no imprimibles, se eliminarán al exportar a XML, véase hwloc_topology_export_xml() en hwloc/export.h.

int hwloc_topology_refresh (hwloc_topology_t topology)

Actualizar las estructuras internas después de la modificación de la topología. Modificar la topología (restringiendo, añadiendo objetos, modificando estructuras como distancias o atributos de memoria, etc.) puede hacer que algunas cachés internas queden inválidas. Estas cachés se actualizan automáticamente cuando se accede a ellas, pero esta actualización no es segura para subprocesos.

Esta función tampoco es segura para subprocesos, pero es una buena manera de finalizar una fase de modificación de la topología no segura para subprocesos. Una vez realizada esta actualización, múltiples subprocesos pueden consultar la topología, objetos, distancias, atributos, etc., de forma concurrente.

Véase también Seguridad de Subprocesos

Devoluciones

0 en caso de éxito.

-1 en caso de error, por ejemplo si falló alguna reasignación interna.

int hwloc_topology_restrict (hwloc_topology_t restrict topology, hwloc_const_bitmap_t set, unsigned long flags)

Restringir la topología al conjunto de CPU o nodo dado. La topología topology se modifica para eliminar todos los objetos que no están incluidos (o parcialmente incluidos) en el conjunto de CPU set. Todos los conjuntos de CPU y nodos de los objetos se restringen en consecuencia.

Por defecto, set es un conjunto de CPU. Significa que el conjunto de PUs en la topología se restringe. Una vez eliminadas algunas PUs, sus padres también pueden eliminarse recursivamente si se quedan sin hijos.

Si HWLOC_RESTRICT_FLAG_BYNODESET se pasa en flags, set se considera un conjunto de nodos en lugar de un conjunto de CPU. Significa que el conjunto de nodos NUMA en la topología se restringe (en lugar de PUs). Una vez eliminados algunos nodos NUMA, sus padres también pueden eliminarse recursivamente si se quedan sin hijos.

flags es un conjunto OR de hwloc_restrict_flags_e.

Nota

Restringir la topología elimina información de localidad, por lo tanto, los objetos restantes pueden ser reordenados (incluyendo PUs y nodos NUMA), y sus índices lógicos pueden cambiar.

Esta llamada no se puede revertir restringiendo de nuevo a un conjunto más grande. Una vez eliminados durante la restricción, los objetos no pueden recuperarse, excepto cargando otra topología con hwloc_topology_load().

Devoluciones

0 en caso de éxito.

-1 con errno establecido en EINVAL si el conjunto de entrada es inválido. La topología no se modifica en este caso.

-1 con errno establecido en ENOMEM si falla la asignación de datos internos. La topología se reinicializa en este caso. Debe ser destruida con hwloc_topology_destroy() o configurada y cargada de nuevo.

hwloc_topology_insert_group_object

Insertar un objeto de grupo en la topología.

Declaración

int hwloc_topology_insert_group_object(hwloc_topology_t topology, hwloc_obj_t parent, hwloc_obj_t group);

Descripción

La función hwloc_topology_insert_group_object inserta el objeto de grupo proporcionado (group) como hijo del objeto parent dado dentro de la topología topology.

Los objetos de grupo son una forma de agrupar lógicamente otros objetos. Se utilizan a menudo para representar construcciones de nivel superior que no son directamente visibles en la jerarquía de hardware física.

El objeto group debe haber sido previamente asignado, por ejemplo, usando hwloc_topology_alloc_group_object.

Parámetros

topology
El manejador de la topología.
parent
El objeto padre al que se añadirá el grupo. Puede ser NULL para añadir el grupo a la raíz de la topología.
group
El objeto de grupo a insertar.

Valor de retorno

Devuelve 0 en caso de éxito y -1 en caso de error.

Ejemplo

#include <stdio.h>
#include <stdlib.h>
#include <hwloc.h>

int main(int argc, char **argv) {
    hwloc_topology_t topology;
    hwloc_obj_t root, group_obj, core_obj;

    /* Inicializar la topología */
    if (hwloc_topology_init(&topology) < 0) {
        fprintf(stderr, "Error al inicializar la topología.\n");
        return 1;
    }
    if (hwloc_topology_load(topology) < 0) {
        fprintf(stderr, "Error al cargar la topología.\n");
        hwloc_topology_free(topology);
        return 1;
    }

    /* Obtener el objeto raíz */
    root = hwloc_topology_get_root_obj(topology);

    /* Asignar un nuevo objeto de grupo */
    group_obj = hwloc_topology_alloc_group_object(topology);
    if (!group_obj) {
        fprintf(stderr, "Error al asignar el objeto de grupo.\n");
        hwloc_topology_free(topology);
        return 1;
    }
    group_obj->attr->group.name = "MiGrupoPersonalizado";

    /* Obtener un objeto de núcleo para añadir al grupo (ejemplo) */
    core_obj = hwloc_topology_get_obj_by_type(topology, HWLOC_OBJ_CORE, 0);
    if (!core_obj) {
        fprintf(stderr, "No se pudo encontrar un objeto de núcleo.\n");
        hwloc_topology_free(topology);
        return 1;
    }

    /* Insertar el objeto de grupo como hijo de la raíz */
    if (hwloc_topology_insert_group_object(topology, root, group_obj) < 0) {
        fprintf(stderr, "Error al insertar el objeto de grupo.\n");
        hwloc_topology_free(topology);
        return 1;
    }

    /* Añadir el objeto de núcleo como hijo del objeto de grupo */
    if (hwloc_obj_add_child(group_obj, core_obj) < 0) {
        fprintf(stderr, "Error al añadir el núcleo al grupo.\n");
        hwloc_topology_free(topology);
        return 1;
    }

    printf("Objeto de grupo insertado con éxito.\n");

    /* Liberar la topología */
    hwloc_topology_free(topology);

    return 0;
}
