DESCRIPCIÓN DETALLADA

Varias funciones pueden ser llamadas opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo se debe realizar la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

DOCUMENTACIÓN DEL TIPO DE ENUMERACIÓN

enum hwloc_topology_flags_e

Marcas (flags) a establecer en un contexto de topología antes de la carga. Las marcas deben ser pasadas a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detecta todo el sistema, ignora reservas, incluye objetos no permitidos. Recopila todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignora cgroups/Cpusets de Linux y recopila todos los procesadores y nodos de memoria. Sin embargo, las PU y los nodos NUMA que estén fuera de línea todavía se ignoran.

Cuando esta marca no está establecida, las PU y los nodos NUMA que no están permitidos no se agregan a la topología. Los objetos padre (paquete, núcleo, caché, etc.) se agregan solo si algunos de sus hijos están permitidos. Todas las PU y nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al cpuset y nodeset del objeto raíz.

Cuando esta marca está establecida, los conjuntos reales de PU y nodos NUMA permitidos se obtienen de hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el cpuset y nodeset del objeto raíz.

Si la topología actual se exporta a XML y se reimporta más tarde, esta marca debe establecerse nuevamente en la topología reimportada para que los recursos no permitidos también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asume que el backend seleccionado proporciona la topología para el sistema en el que estamos ejecutando. Esto fuerza a que hwloc_topology_is_thissystem() devuelva 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología para el sistema en el que estamos ejecutando, incluso si no es el backend específico del SO sino el backend XML, por ejemplo. Esto significa hacer que las funciones de enlace (binding) llamen realmente a las llamadas del sistema específicas del SO y realmente realicen el enlace, mientras que el backend XML de lo contrario proporcionaría ganchos vacíos que simplemente devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto se puede usar por razones de eficiencia para detectar primero la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero aún teniendo funciones de enlace que realmente realicen el enlace.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtiene el conjunto de recursos permitidos del sistema operativo local, incluso si la topología se cargó desde XML o desde una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restriñela aplicando las restricciones del proceso actual, como cgroups/Cpusets de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está limitado a solo partes de la máquina.

Esta marca se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecida, ya que la topología cargada debe coincidir con la máquina subyacente desde la cual se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES resultaría en el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importa el soporte del la topología importada. Al importar una topología XML de una máquina remota, el enlace está deshabilitado por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Esta deshabilitación también se marca poniendo ceros en los bits correspondientes de características soportadas informados por hwloc_topology_get_support().

La marca HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT en realidad importa los bits de soporte de la máquina remota. También establece la marca imported_support en la estructura hwloc_topology_misc_support. Si el XML importado no contenía información de soporte (el exportador de hwloc es demasiado antiguo), esta marca no se establece.

Tenga en cuenta que estas características soportadas solo son relevantes para la instalación de hwloc que exportó la topología XML (puede variar según el sistema operativo o según cómo se compiló hwloc).

Tenga en cuenta que establecer esta marca, sin embargo, no habilita el enlace para la topología hwloc importada localmente, solo informa lo que el hwloc remoto y la máquina soportan.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
No considere los recursos fuera del enlace de CPU del proceso. Si el enlace del proceso se limita a un subconjunto de núcleos, ignore los otros núcleos
s durante el descubrimiento.

La topología resultante es idéntica a la que generaría una llamada a hwloc_topology_restrict(), pero esta bandera también evita que hwloc toque otros recursos durante el

descubrimiento.

Esta bandera le indica específicamente al backend x86 que nunca reenlace temporalmente un hilo en ningún núcleo excluido. Esto es útil en Windows porque dicho reenlace temporal puede cambiar el enlace del proceso. Otro caso de uso es evitar núcleos que no podrían realizar el descubrimiento de hwloc en un futuro próximo porque están ocupados ejecutando algunas tareas de tiempo real de alta

prioridad.

Si el enlace de CPU del proceso no está soportado, se considera el enlace de CPU del hilo si está soportado, o la bandera se

ignora.

Esta bandera requiere HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también, ya que se requiere soporte de

enlace.
HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
No considerar recursos fuera del enlace de memoria del proceso. Si
el enlace del proceso está limitado a un subconjunto de nodos
NUMA, ignorar los otros nodos NUMA durante el descubrimiento.

La topología resultante es idéntica a la que generaría una llamada a hwloc_topology_restrict(), pero esta bandera también evita que hwloc toque otros recursos durante el

descubrimiento.

Esta bandera está destinada a usarse junto con HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING cuando tanto los núcleos como los nodos NUMA deban ignorarse fuera del enlace del

proceso.

Si el enlace de memoria del proceso no está soportado, se considera el enlace de memoria del hilo si está soportado, o la bandera se

ignora.

Esta bandera requiere HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también, ya que se requiere soporte de

enlace.
HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Nunca modificar el enlace del proceso o del hilo durante el descubrimiento. Esta bandera deshabi
lita todos los pasos de descubrimiento de hwloc que requieren un cambio en el enlace del proces
o o del hilo. Actualmente esto solo afecta al backend x86 que queda completamente deshabilitado.

Esto es útil cuando hwloc_topology_load() se llama mientras la aplicación también crea hilos adicionales o modifica el

enlace.

Esta bandera también es una forma estricta de asegurar que el enlace del proceso no cambiará debido a cambios en el enlace de hilos en Windows (ver HWLOC_TOPOLOGY_FLAG_RESTRICT_

TO_CPUBINDING).
HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignorar distancias. Ignorar la información de distancias de los sistemas operativos (y de XML) y por lo tanto no usar distancias para
agrupar.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignorar atributos y niveles de memoria. Ignorar los atributos de memoria de los sistemas operativos (y de XML). Por lo tanto tampoco intentar construir niveles de
memoria.
