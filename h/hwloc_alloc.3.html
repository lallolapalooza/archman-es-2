Descripción

detallada

El enlace de memoria se puede realizar de tres

maneras:
  • asignación de memoria explícita gracias a hwloc_alloc_membind() y relacionadas: el enlace tendrá efecto sobre la memoria asignada por estas
    • funciones.
  • enlace de memoria implícito a través de la política de enlace: hwloc_set_membind() y relacionadas solo definen la política actual del proceso, que se aplicará a las llamadas posteriores a malloc() y
    • relacionadas.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y relacionada
    • s, que mueven datos
ya asignados.

No todos los sistemas operativos soportan las tres formas. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente

utilizado.

Cuando la operación de enlace solicitada no está disponible y se pasó el indicador HWLOC_MEMBIND_STRICT, la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema no soporte la acción o política especificada (por ejemplo, algunos sistemas solo permiten enlazar memoria a nivel de hilo, mientras que otros sistemas solo permiten enlazar memoria para todos los hilos de un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no pueda aplicarse (por ejemplo, algunos sistemas solo permiten enlazar memoria a un solo nodo NUMA)

.

Si no se pasó HWLOC_MEMBIND_STRICT, la función también puede fallar, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de enlace más pequeño, etc.) cuando la operación solicitada no esté exactamente

soportada.

La forma más portable que debería preferirse sobre las demás siempre que sea posible es la siguiente. Asigna algo de memoria que se espera esté enlazada al conjunto especificado. Para hacerlo, hwloc posiblemente tendrá que cambiar la política actual de enlace de memoria para realmente obtener la memoria enlazada, si el SO no proporciona ninguna otra manera de asignar simplemente memoria enlazada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), que nunca cambiará la política actual de enlace de

memoria. 
hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0)
;

Cada función de enlace de memoria de hwloc toma un argumento bitmap que es un conjunto de CPU por defecto, o un conjunto de nodos de memoria NUMA si se especifica el indicador HWLOC_MEMBIND_BYNODESET. Ver Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API de bitmap para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_n

odeset().

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por conjunto de nodos debería preferirse siempre que sea

posible.

Detailed Description

These functions manipulate the memory binding of processes, threads, or memory areas.

Memory binding allows applications to influence where their memory is allocated. This can be useful for NUMA-aware applications aiming to keep data close to the processing units that will use it.

The binding is described by a policy and a set of NUMA nodes. The policy indicates how the NUMA nodes should be used, and the set indicates which NUMA nodes are allowed.

Policies

The possible policies are:

HWLOC_MEMBIND_FIRSTTOUCH
Memory is allocated on the NUMA node closest to the first access, within the allowed set.
HWLOC_MEMBIND_NEXTTOUCH
Memory is allocated on the NUMA node closest to the first access, within the allowed set. It can be migrated later by the OS.
HWLOC_MEMBIND_BIND
Memory is allocated strictly on one of the NUMA nodes specified in the set. If multiple nodes are specified, one is chosen arbitrarily.
HWLOC_MEMBIND_INTERLEAVE
Memory is interleaved across all NUMA nodes specified in the set.
HWLOC_MEMBIND_MIXED
This policy value is only returned by hwloc_get_membind() and hwloc_get_proc_membind(). It indicates that the underlying threads have different policies.
HWLOC_MEMBIND_DEFAULT
Use the system default policy.

Flags

The flags argument can be used to refine the behavior of these functions. The following flags are recognized:

HWLOC_MEMBIND_PROCESS
Apply the operation to the entire process (all its threads).
HWLOC_MEMBIND_THREAD
Apply the operation to only the calling thread.
HWLOC_MEMBIND_STRICT
When getting the memory binding, check if all underlying entities (threads or memory areas) have the exact same binding. If not, return -1 with errno=EXDEV.
HWLOC_MEMBIND_BYNODESET
The set argument is a set of NUMA nodes. This is the default behavior when binding memory areas or setting the default memory policy.
HWLOC_MEMBIND_BYsubheader
The set argument is a set of memory sub-objects (like Memory Devices or NUMA nodes).
HWLOC_MEMBIND_NOMEMPOLICY
Ignore the memory policy, only care about the locality set. This is mostly useful when querying the memory binding of a specific memory area.
HWLOC_MEMBIND_FROM_OS
Force the use of OS-provided memory binding information, even if hwloc thinks it can do better using its internal structures. This is mostly useful when querying the memory binding of a specific memory area.

int hwloc_get_membind (hwloc_topology_t topology, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Query the default memory binding policy and physical locality of the current process or thread. The bitmap set (previously allocated by the caller) is filled with the process or thread memory binding.

This function has two output parameters: set and policy. The values returned in these parameters depend on both the flags passed in and the current memory binding policies and nodesets in the queried target.

Passing the HWLOC_MEMBIND_PROCESS flag specifies that the query target is the current policies and nodesets for all the threads in the current process. Passing HWLOC_MEMBIND_THREAD specifies that the query target is the current policy and nodeset for only the thread invoking this function.

If neither of these flags are passed (which is the most portable method), the process is assumed to be single threaded. This allows hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

HWLOC_MEMBIND_STRICT is only meaningful when HWLOC_MEMBIND_PROCESS is also specified. In this case, hwloc will check the default memory policies and nodesets for all threads in the process. If they are not identical, -1 is returned and errno is set to EXDEV. If they are identical, the values are returned in set and policy.

Otherwise, if HWLOC_MEMBIND_PROCESS is specified (and HWLOC_MEMBIND_STRICT is not specified), the default set from each thread is logically OR'ed together. If all threads' default policies are the same, policy is set to that policy. If they are different, policy is set to HWLOC_MEMBIND_MIXED.

In the HWLOC_MEMBIND_THREAD case (or when neither HWLOC_MEMBIND_PROCESS or HWLOC_MEMBIND_THREAD is specified), there is only one set and policy; they are returned in set and policy, respectively.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

If any other flags are specified, -1 is returned and errno is set to EINVAL.

Returns

0 on success, -1 on error.

int hwloc_get_proc_membind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Query the default memory binding policy and physical locality of the specified process. The bitmap set (previously allocated by the caller) is filled with the process memory binding.

This function has two output parameters: set and policy. The values returned in these parameters depend on both the flags passed in and the current memory binding policies and nodesets in the queried target.

Passing the HWLOC_MEMBIND_PROCESS flag specifies that the query target is the current policies and nodesets for all the threads in the specified process. If HWLOC_MEMBIND_PROCESS is not specified (which is the most portable method), the process is assumed to be single threaded. This allows hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

Note that it does not make sense to pass HWLOC_MEMBIND_THREAD to this function.

If HWLOC_MEMBIND_STRICT is specified, hwloc will check the default memory policies and nodesets for all threads in the specified process. If they are not identical, -1 is returned and errno is set to EXDEV. If they are identical, the values are returned in set and policy.

Otherwise, set is set to the logical OR of all threads' default set. If all threads' default policies are the same, policy is set to that policy. If they are different, policy is set to HWLOC_MEMBIND_MIXED.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

If any other flags are specified, -1 is returned and errno is set to EINVAL.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

int hwloc_set_proc_membind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Set the default memory binding policy of the specified process to prefer the NUMA node(s) specified by set. If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

Returns

0 on success.

-1 with errno set to ENOSYS if the action is not supported.

-1 with errno set to EXDEV if the binding cannot be enforced.

Note
