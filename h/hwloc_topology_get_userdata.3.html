DESCRIPCION DETALLADA

Varias funciones se pueden llamar opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo se debe realizar la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

DOCUMENTACION DE TIPO ENUMERADO

enum hwloc_topology_flags_e

Banderas para ser establecidas en un contexto de topología antes de cargar. Las banderas deben ser pasadas a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detecta el sistema completo, ignora las reservas, incluye objetos disallowed. Recopila todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignora Cgroup/Cpusets de Linux y recopila todos los procesadores y nodos de memoria. Sin embargo, las PU y los nodos NUMA que están offline todavía se ignoran.

Cuando esta bandera no está establecida, las PU y los nodos NUMA que no están permitidos no se añaden a la topología. Los objetos padres (paquete, núcleo, caché, etc.) se añaden solo si algunos de sus hijos están permitidos. Todas las PU y nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al conjunto de CPU y conjunto de nodos del objeto raíz.

Cuando esta bandera está establecida, los conjuntos reales de PU y nodos NUMA permitidos son dados por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que los conjuntos de CPU y nodos del objeto raíz.

Si la topología actual se exporta a XML y se reimporta más tarde, esta bandera debe ser establecida de nuevo en la topología reimportada para que los recursos disallowed también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asume que el backend seleccionado proporciona la topología para el sistema en el que se está ejecutando. Esto fuerza a hwloc_topology_is_thissystem() a devolver 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología para el sistema en el que se está ejecutando, incluso si no es el backend específico del sistema operativo sino el backend XML, por ejemplo. Esto significa hacer que las funciones de vinculación realmente llamen a las llamadas del sistema específicas del sistema operativo y realmente hagan la vinculación, mientras que el backend XML de lo contrario proporcionaría ganchos vacíos que solo devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto se puede usar por razones de eficiencia para detectar primero la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero aún así teniendo funciones de vinculación que realmente vinculen.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtiene el conjunto de recursos permitidos del sistema operativo local incluso si la topología se cargó desde XML o desde una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restringe aplicando las restricciones actuales del proceso, como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Esta bandera se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecida, ya que la topología cargada debe coincidir con la máquina subyacente desde la cual se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES resultaría en el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importa el soporte desde la topología importada. Al importar una topología XML de una máquina remota, la vinculación está deshabilitada por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Esta deshabilitación también se marca poniendo ceros en los bits correspondientes de las características soportadas informadas por hwloc_topology_get_support().

La bandera HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT realmente importa los bits de soporte de la máquina remota. También establece la bandera imported_support en el array de la struct hwloc_topology_misc_support. Si el XML importado no contenía ninguna información de soporte (el exportador hwloc es demasiado antiguo), esta bandera no se establece.

Tenga en cuenta que estas características soportadas solo son relevantes para la instalación de hwloc que realmente exportó la topología XML (puede variar según el sistema operativo, o según cómo se compiló hwloc).

Tenga en cuenta que establecer esta bandera sin embargo no habilita la vinculación para la topología hwloc importada localmente, solo informa lo que el hwloc y la máquina remota soportan.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
No considerar recursos fuera de la vinculación de CPU del proceso. Si la vinculación del proceso está limitada a un subconjunto de núcleos, ignorar los otros núcleos durante la detección.

Esto puede ser útil para reducir la complejidad de la topología devuelta cuando el proceso actual está restringido a solo algunas CPU.

Esta bandera solo tiene efecto si la detección de la topología se realiza de forma nativa en el sistema (no a través del backend XML o sintético).

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
No considerar recursos fuera de la vinculación de memoria del proceso. Si la vinculación de memoria del proceso está limitada a un subconjunto de nodos de memoria, ignorar los otros nodos de memoria durante la detección.

Esto puede ser útil para reducir la complejidad de la topología devuelta cuando el proceso actual está restringido a solo algunos nodos de memoria.

Esta bandera solo tiene efecto si la detección de la topología se realiza de forma nativa en el sistema (no a través del backend XML o sintético).

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Evitar que las funciones de vinculación de hwloc cambien la vinculación del proceso actual. Si la vinculación actual ya está establecida, no se modificará. Si no está establecida, se dejará sin establecer (lo que a menudo significa heredar la vinculación del padre).

Por defecto, las funciones de vinculación de hwloc (por ejemplo, hwloc_set_cpubind) intentarán establecer la vinculación deseada en el proceso actual si no está ya establecida y permitirán que el sistema operativo la modifique si es necesario.

Esto puede ser útil para evitar efectos secundarios inesperados en la vinculación del proceso actual cuando se llama a funciones de vinculación de hwloc desde otros contextos.

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Evitar que hwloc detecte y reporte las distancias entre diferentes tipos de objetos (por ejemplo, latencias de acceso a memoria entre nodos NUMA).

Esto puede ser útil para reducir la sobrecarga de detección, ya que la recopilación de información de distancia puede ser costosa.

HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Evitar que hwloc detecte y reporte atributos de memoria como el tipo de memoria (por ejemplo, DDR, HBM) o las velocidades.

Esto puede ser útil para reducir la sobrecarga de detección o si esta información no es necesaria para la aplicación.

HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Evitar que hwloc agrupe objetos de CPU similares en "tipos de CPU" (por ejemplo, todos los núcleos de 2GHz como un único grupo).

Esto puede ser útil para simplificar la topología cuando no se requiere esta información de agrupación.

enum hwloc_type_filter_e

Filtros para tipos de objetos. Estos filtros se pueden aplicar a tipos específicos usando hwloc_topology_set_type_filter() o a grupos de tipos usando hwloc_topology_set_cache_types_filter(), hwloc_topology_set_icache_types_filter(), hwloc_topology_set_io_types_filter(), o a todos los tipos usando hwloc_topology_set_all_types_filter().

Valores

HWLOC_TYPE_FILTER_KEEP_ALL
Mantener todas las instancias del tipo de objeto dado.
HWLOC_TYPE_FILTER_KEEP_NONE
Ignorar todas las instancias del tipo de objeto dado.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Mantener solo las instancias del tipo de objeto dado que son necesarias para la estructura de la topología (por ejemplo, objetos de nivel superior como nodos NUMA o procesadores).
HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Mantener solo las instancias del tipo de objeto dado que se consideran importantes (por ejemplo, procesadores, nodos de memoria, cachés L1/L2/L3, dispositivos I/O importantes).

El valor predeterminado para la mayoría de los tipos es HWLOC_TYPE_FILTER_KEEP_ALL, pero se pueden aplicar filtros más estrictos a los tipos de caché, I/O y similares por defecto para mantener la topología más limpia y pequeña.
