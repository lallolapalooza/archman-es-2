HBF2GF(1) Manual de Comandos Generales HBF2GF(1)

NOMBRE

hbf2gf - convierte una fuente bitmap CJK en subfuentes utilizables por TeX y Omega.

SINOPSIS

hbf2gf [-q] archivo-configuracion[.cfg]
hbf2gf
[-q] [-p] [-g] [-n] nombre-subfuente resolucion-x [escala-y | resolucion-y]

hbf2gf -t [-q] nombre-subfuente
hbf2gf --version | --help

DESCRIPCIÓN

Las fuentes bitmap CJK no pueden ser utilizadas directamente con TeX porque el número de caracteres en tales fuentes excede los 256, el límite de una fuente TeX. Por lo tanto, es necesario dividir estas fuentes en subfuentes, y esto es exactamente lo que hace hbf2gf.

Como su nombre indica, hbf2gf utiliza fuentes CJK en un formato determinado llamado formato Hanzi Bitmap Font (HBF). Simplemente consiste en los archivos bitmap CJK y un archivo de texto en un formato muy similar al formato BDF del Sistema de Ventanas X, que describe los archivos de fuentes bitmap: la codificación, el tamaño, etc. Los archivos GF producidos pueden ser convertidos con gftopk a archivos PK estándar.

hbf2gf puede ser llamado en tres modos:


hbf2gf [-q] archivo-configuracion[.cfg]


Esta llamada normalmente crea un conjunto de archivos GF, un archivo PL y un archivo batch que debe ser ejecutado después de que hbf2gf haya terminado. Este script llamará entonces a gftopk para convertir todos los archivos GF en archivos PK, y llamará a pltotf para convertir el archivo PL en un archivo TFM. Finalmente copiará el archivo TFM para que cada archivo PK tenga su archivo TFM (que son todos idénticos).


Si ofm_file está configurado como 'yes' en el archivo de configuración, también se crearán archivos OFM y OVF.


-q hace que hbf2gf sea silencioso.


hbf2gf
[-q] [-p] [-g] [-n] nombre-subfuente resolucion-x [escala-y | resolucion-y]


Este modo está pensado para ser utilizado con mktexpk y sus derivados. Solo se calculará un archivo GF junto con un archivo PL para la subfuente dada, tomando la resolución horizontal y un factor de escala vertical (si el valor es menor que 10) o la resolución vertical (en caso contrario) desde la línea de comandos, ignorando el parámetro nmb_fonts del archivo de configuración. Los dos últimos caracteres (que se interpretan como el número de subfuente) se eliminan para obtener el nombre del archivo de configuración (que debe terminar en '.cfg'). No se creará ningún archivo de trabajo. Si se establece la opción -p, no se crea ningún archivo PL. Si se establece -g, no se crea ningún archivo GF. La extensión puede ser controlada con -n; si se establece, la extensión es '.gf', de lo contrario '.<resolucion>gf'. -q hace que hbf2gf sea silencioso.


hbf2gf
-t [-q] nombre-subfuente


Este modo está pensado para ser utilizado con scripts como mktexpk; prueba si el nombre de subfuente especificado conduce a un archivo de configuración hbf2gf. Devuelve 0 en caso de éxito e imprime el nombre de ese archivo de configuración (si la opción -q no está establecida). Esta prueba no es exhaustiva; solo elimina los dos últimos caracteres y comprueba si existe un archivo de configuración con ese nombre.

Consulte la siguiente sección para obtener más detalles sobre los archivos de configuración.

La especificación de la opción --version devuelve la versión actual de hbf2gf y la biblioteca de búsqueda de archivos utilizada (por ejemplo, kpathsea). La información de uso se muestra con el parámetro --help.

ARCHIVO DE CONFIGURACIÓN

Aquí hay un archivo de configuración de ejemplo (gsfs14.cfg) para una fuente china de 56x56 en codificación GB; tenga en cuenta que toda la información sobre la fuente está en el archivo jfs56.hbf. Vea la sección BÚSQUEDA DE ARCHIVOS sobre cómo se encuentran las fuentes HBF y los archivos de configuración hbf2gf. Vea la sección DISPONIBILIDAD dónde obtener fuentes CJK junto con sus archivos HBF:

  hbf_header     jfs56.hbf
  mag_x          1
  threshold      128
  comment        jianti fansongti 56x56 pixel font
  design_size    14.4
  y_offset       -13
  nmb_files      -1
  output_name    gsfs14
  checksum       123456789
  dpi_x          300
  pk_files       no
  tfm_files      yes
  coding         codingscheme GuoBiao encoded TeX text
  pk_directory   $HBF_TARGET/pk/modeless/gb2312/gsfs14/
  tfm_directory  $HBF_TARGET/tfm/gb2312/gsfs14/

Un archivo de configuración es un archivo de texto plano que consiste en palabras clave y sus argumentos. Una palabra clave debe comenzar una línea, de lo contrario, toda la línea será ignorada. Si la palabra que comienza una línea no es una palabra clave, la línea también será ignorada. Las líneas vacías también se omitirán. La búsqueda de palabras clave no distingue entre mayúsculas y minúsculas; por el contrario, los argumentos se tomarán exactamente como se proporcionan (excepto 'yes' y 'no' que pueden escribirse con mayúsculas o minúsculas). Cada palabra clave tiene un argumento que debe estar separado por espacios en blanco (espacios o tabulaciones) de la palabra clave y debe estar en la misma línea. Cada línea no debe tener más de 256 caracteres.

Puede utilizar variables de entorno en el archivo de configuración. El carácter de escape que inicia una variable de entorno en el archivo de configuración es siempre '$', incluso para sistemas operativos como DOS que tienen otras convenciones. hbf2gf reconoce solo nombres de variables de entorno que comienzan con una letra o un guion bajo, seguidos de caracteres alfanuméricos o guiones bajos. Puede rodear la variable con llaves para indicar dónde termina el nombre de la variable, por ejemplo ${FOO}. Para obtener un signo de dólar, debe escribir '$$'. La expansión de variables de entorno en hbf2gf mismo (sin la ayuda de las rutinas de búsqueda de kpathsea, emtexdir o MiKTeX) es muy limitada; esta característica se ha transferido de versiones anteriores. No puede expandir variables establecidas en texmf.cnf; tampoco puede manejar más de un directorio como valor de la variable. ¡NO LO USE EXCEPTO PARA LOS PARÁMETROS 'pk_directory' y 'tfm_directory'!

Esta es la lista de todas las palabras clave necesarias:

hbf_header
El nombre del archivo de cabecera HBF de las fuentes de entrada. hbf2gf utiliza el mecanismo de búsqueda dado (kpathsea, emtexdir o MiKTeX) para localizar este archivo.
output_name
El prefijo del nombre de los archivos de salida. Se añadirá un número decimal decimal de dos dígitos en ejecución comenzando con '01'. Para fuentes Unicode, vea la palabra clave unicode abajo. Este valor es en casi todos los casos idéntico al nombre del archivo de configuración.

Y ahora todas las palabras clave opcionales:

x_offset
Aumenta el ancho del carácter. Se aplicará en ambos lados; el valor predeterminado para glifos no rotados es el valor dado en la cabecera HBF (HBF_BITMAP_BOUNDING_BOX) escalado a design_size (en píxeles).
y_offset
Desplaza todos los caracteres hacia arriba o hacia abajo; el valor predeterminado para glifos no rotados es el valor dado en la cabecera HBF (HBF_BITMAP_BOUNDING_BOX) escalado a design_size (en píxeles).
design_size
El tamaño de diseño (en puntos) de la fuente. x_offset y y_offset se refieren a este tamaño. El valor predeterminado es 10.0.
slant
La inclinación de la fuente (dada como Delta_x / Delta_y). Solo se permiten valores en el rango 0 <= slant <= 1. El valor predeterminado es 0.0.
rotation
Si se establece en 'yes', todos los glifos se rotarán 90 grados en sentido antihorario. Los desplazamientos predeterminados dados en la cabecera HBF se ignorarán (y se establecerán en 0). El valor predeterminado es 'no'.
mag_x

mag_y
Valores de escala de los caracteres para alcanzar el tamaño de diseño. Si solo se da una magnificación, los valores x e y se asumen iguales. El valor predeterminado es mag_x = mag_y = 1.0.
