OPCIONES DE TOPOLOGÍA

Estas opciones permiten filtrar los objetos de la topología y modificar la forma en que se calcula el conjunto de CPU o nodo de salida.

--pu <obj>
Reportar el conjunto de CPU de las unidades de procesamiento (PU) que contienen el objeto dado. Por ejemplo, --pu package:0 reportará el conjunto de CPU de todas las PUs dentro del primer paquete. Este objeto es un alias para -I pu.
--core <obj>
Reportar el conjunto de CPU de los núcleos que contienen el objeto dado. Por ejemplo, --core package:0 reportará el conjunto de CPU de todos los núcleos dentro del primer paquete. Este objeto es un alias para -I core.
--cache <obj>
Reportar el conjunto de CPU de las cachés que contienen el objeto dado. Por ejemplo, --cache core:0 reportará el conjunto de CPU de todas las cachés dentro del primer núcleo. Este objeto es un alias para -I cache.
--memcache <obj>
Reportar el conjunto de CPU de las cachés de memoria que contienen el objeto dado. Por ejemplo, --memcache core:0 reportará el conjunto de CPU de todas las cachés de memoria dentro del primer núcleo. Este objeto es un alias para -I memcache.
--group <obj>
Reportar el conjunto de CPU de los grupos que contienen el objeto dado. Por ejemplo, --group machine:0 reportará el conjunto de CPU de todos los grupos dentro de la máquina. Este objeto es un alias para -I group.
--numanode <obj>
Reportar el conjunto de nodos que contienen el objeto dado. Por ejemplo, --numanode package:0 reportará el conjunto de nodos de todos los nodos NUMA dentro del primer paquete. Este objeto es un alias para -I numanode.
--package <obj>
Reportar el conjunto de CPU de los paquetes que contienen el objeto dado. Por ejemplo, --package machine:0 reportará el conjunto de CPU de todos los paquetes dentro de la máquina. Este objeto es un alias para -I package.
--die <obj>
Reportar el conjunto de CPU de los dies que contienen el objeto dado. Por ejemplo, --die package:0 reportará el conjunto de CPU de todos los dies dentro del primer paquete. Este objeto es un alias para -I die.
--machine <obj>
Reportar el conjunto de CPU de las máquinas que contienen el objeto dado. Por ejemplo, --machine numanode:0 reportará el conjunto de CPU de todas las máquinas dentro del primer nodo NUMA. Este objeto es un alias para -I machine.
--all
Reportar el conjunto de CPU de todos los objetos de la topología. Este objeto es un alias para -I all.
--intersect
Intersecar los conjuntos de CPU de todos los objetos dados en la entrada. Por ejemplo, --intersect package:1 package:2 devolverá los núcleos que pertenecen tanto al paquete 1 como al paquete 2. El conjunto de CPU de salida solo contendrá los CPU pertenecientes a todos los objetos de entrada.
--union
Unir los conjuntos de CPU de todos los objetos dados en la entrada. Por ejemplo, --union package:1 package:2 devolverá todos los núcleos que pertenecen al paquete 1 o al paquete 2 (o ambos). Este es el comportamiento por defecto si no se especifica ninguna opción de operación.
--difference
Calcular la diferencia de los conjuntos de CPU. Por ejemplo, --difference package:1 package:2 devolverá los núcleos que pertenecen al paquete 1 pero no al paquete 2. El conjunto de CPU de salida contendrá los CPU que pertenecen al primer objeto de entrada pero no a ninguno de los otros objetos de entrada.
--symmetric-difference
Calcular la diferencia simétrica de los conjuntos de CPU. Por ejemplo, --symmetric-difference package:1 package:2 devolverá los núcleos que pertenecen al paquete 1 o al paquete 2, pero no a ambos. El conjunto de CPU de salida contendrá los CPU que pertenecen a un número impar de los objetos de entrada.
--specific
Reportar el conjunto de CPU específico de los objetos dados en la entrada. Por ejemplo, --specific package:0 package:1 devolverá los núcleos que pertenecen únicamente al paquete 0 o únicamente al paquete 1.
--merge
Fusionar los objetos de entrada en objetos más grandes. Por ejemplo, --merge Core:1 package:2 fusionará el primer núcleo y el segundo paquete en un único objeto. No se puede fusionar el mismo objeto varias veces.
--largest
Reportar (en un formato legible por humanos) la lista de los objetos más grandes que incluyen exactamente todos los objetos de entrada (mirando sus conjuntos de CPU). Ninguno de estos objetos de salida se cruza entre sí, y la suma de ellos es exactamente equivalente a la entrada. Ningún objeto más grande está incluido en la entrada.
--local-memory
Reportar la lista de nodos NUMA que son locales a los objetos de entrada. Esta opción es similar a -I numa pero la forma en que se seleccionan los nodos es diferente: La selección realizada por --local-memory puede configurarse con precisión con --local-memory-flags, mientras que -I numa simplemente selecciona todos los nodos que son de alguna manera locales a cualquiera de los objetos de entrada.
--local-memory-flags
Cambiar las banderas utilizadas para seleccionar nodos NUMA locales. Las banderas pueden darse como valores numéricos o como una lista separada por comas de nombres de banderas que se pasan a hwloc_get_local_numanode_objs(). Esos nombres pueden ser subcadenas de los nombres de banderas reales siempre que coincida uno solo. El valor por defecto es xb (o smaller,larger,intersects) que significa que los nodos NUMA se muestran si su localidad contiene, está contenida o se interseca con la localidad del objeto dado.
--best-memattr <nombre>
Habilitar la lista de nodos de memoria locales con --local-memory, pero solo mostrar los nodos locales que tienen el mejor valor para el atributo de memoria dado por <nombre> (o como un índice).

OPCIONES DE ENTRADA / SALIDA DE CONJUNTOS Y OBJETOS

Estas opciones configuran cómo se analizan los objetos y conjuntos de CPU/nodo en la entrada y cómo se formatean en la salida.

Todas estas opciones deben darse después de todas las opciones de topología anteriores.

-p --physical
Usar índices de SO/físicos en lugar de índices lógicos para entrada y salida.
-l --logical
Usar índices lógicos en lugar de índices físicos/de SO para entrada y salida (por defecto).
--pi --physical-input
Usar índices de SO/físicos en lugar de índices lógicos para la entrada.
--li --logical-input
Usar índices lógicos en lugar de índices físicos/de SO para la entrada (por defecto).
--po --physical-output
Usar índices de SO/físicos en lugar de índices lógicos para la salida.
--lo --logical-output
Usar índices lógicos en lugar de índices físicos/de SO para la salida (por defecto, excepto para los conjuntos de CPU que son siempre físicos).
-n --nodeset
Interpretar los conjuntos de entrada y salida como conjuntos de nodos en lugar de conjuntos de CPU. Ver --nodeset-output y --nodeset-input abajo para más detalles.
--no --nodeset-output
Reportar conjuntos de nodos en lugar de conjuntos de CPU. Esta salida es más precisa que la salida por defecto de conjuntos de CPU cuando la localidad de memoria es importante porque describe correctamente los nodos NUMA sin CPU, así como los nodos NUMA que son locales a múltiples CPU.
--ni --nodeset-input
Interpretar los conjuntos de entrada como conjuntos de nodos en lugar de conjuntos de CPU.

OPCIONES DE FORMATEO

Todas estas opciones deben darse después de todas las opciones de topología anteriores.

--oo --object-output
Al reportar índices de objetos (por ejemplo, con -I o --local-memory), esta opción antepone a estos índices los tipos (por ejemplo, Core:0 en lugar de 0).
--sep <sep>
Cambiar el separador de campos en la salida. Por defecto, se usa un espacio para separar los objetos de salida (por ejemplo, cuando se da --hierarchical o --largest) mientras que se usa una coma para separar los índices (por ejemplo, cuando se da --intersect).
--single
Simplificar la salida a una sola CPU.
--cpuset-output-format <hwloc|list|taskset|systemd-dbus-api> --cof <hwloc|list|taskset|systemd-dbus-api>
Cambiar el formato de las cadenas de mapas de bits mostradas (conjunto de CPU o conjunto de nodos). Por defecto, se usa el formato específico de hwloc. Si se da list, la salida es una lista separada por comas de números o rangos, por ejemplo, 2,4-5,8. Si se da taskset, la salida es compatible con el programa taskset (reemplaza la antigua opción --taskset). Si se da systemd-dbus-api, la salida es compatible con la API de D-Bus de systemd, por ejemplo, "ay 0x0002 0x78 0x04" para la lista de conjuntos de CPU "3-6,10".
--cpuset-input-format <hwloc|list|taskset> --cif <hwloc|list|taskset>
Cambiar el formato de las cadenas de mapas de bits de entrada (conjunto de CPU o conjunto de nodos). Por defecto, la herramienta intenta adivinar el tipo automáticamente entre los formatos hwloc, list o taskset. Esta opción fuerza el formato de análisis para evitar ambigüedades, por ejemplo, cuando "1,3,5" puede analizarse como un conjunto de CPU hwloc "0x1,0x00000003,0x00000005" o como una lista "1-1,3-3,5-5".
-q --quiet
Ocultar mensajes de error no fatales. Incluye principalmente ubicaciones que apuntan a objetos inexistentes.
-v --verbose
Salida detallada.
--version
Informar la versión y salir.
-h --help
Mostrar mensaje de ayuda y salir.

DESCRIPCIÓN

hwloc-calc genera y manipula cadenas de máscaras de CPU u objetos. Tanto la entrada como la salida pueden ser objetos (con índices físicos o lógicos), listas de CPU (con índices físicos o lógicos) o cadenas de máscaras de CPU (siempre indexadas físicamente). La especificación de la ubicación de entrada se describe en hwloc(7).

Si se proporcionan objetos o cadenas de máscaras de CPU en la línea de comandos, se combinan y se imprime una única salida. Si no se proporcionan objetos o cadenas de máscaras de CPU en la línea de comandos, el programa leerá la entrada estándar. Combinará varios objetos o cadenas de máscaras de CPU que se proporcionan en la misma línea de la línea de entrada estándar con espacios como separadores. Las diferentes líneas de entrada se procesarán por separado.

Los argumentos y opciones de la línea de comandos se procesan en orden. Primero deben darse las opciones de configuración de topología. Luego, por ejemplo, cambiar el tipo de índices de entrada con --li o cambiar la topología de entrada con -i solo afectará al procesamiento de los argumentos siguientes.

NOTA: Se recomienda encarecidamente leer la página de descripción general hwloc(7) antes de leer esta página de manual. La mayoría de los conceptos descritos en hwloc(7) se aplican directamente a la utilidad hwloc-calc.

La operación de hwloc-calc se describe mejor a través de varios ejemplos.

$ hwloc-calc all ~package:3

Ejemplo de uso del formato de salida cpuset y nodeset de systemd-dbus-ap

i

hwloc-calc permite generar las cadenas muy crípticas AllowedCPUs y AllowedMemoryNodes, que espera la API D-Bus de systemd, a partir de otras representaciones de hwloc. Esto es especialmente útil cuando el comando systemd-run, que entiende listas numéricas, no se puede

usar.

Primero, cree una porción (slice) de

systemd: 
    $ busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager StartUnit ss my_slice.slice
fail

Luego, configure los conjuntos de CPU y de nodos de la porción, usando hwloc-calc para traducir la

sintaxis: 
    $ busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager SetUnitProperties 'sba(sv)' my_slice.slice 1 1 AllowedCPUs $(hwloc-calc pu:0 pu:31 pu:32 pu:63 pu:64 pu:77 --cpuset-output-format systemd-dbus-api)
    $ busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager SetUnitProperties 'sba(sv)' my_slice.slice 1 1 AllowedMemoryNodes $(hwloc-calc pu:0 pu:31 pu:32 pu:63 pu:64 pu:77 --nodeset-output-format systemd-dbus-api
)

Finalmente, agregue el proceso actual a la

porción: 
    $ busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager StartTransientUnit 'ssa(sv)a(sa(sv))' my_scope.scope fail 3 Delegate b 1 PIDs au 1 $$ Slice s my_slice.slice
0
