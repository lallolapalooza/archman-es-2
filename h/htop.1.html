DESCRIPCIÓ

N

htop es un visor de procesos basado en ncurses y multiplataforma

.

Es similar a top, pero permite desplazarse vertical y horizontalmente, e interactuar usando un dispositivo apuntador (ratón). Puedes observar todos los procesos que se ejecutan en el sistema, junto con sus argumentos de línea de comandos, así como verlos en formato de árbol, seleccionar múltiples procesos y actuar sobre todos ellos a la

vez.

Las tareas relacionadas con los procesos (matar, cambiar el nice) se pueden realizar sin introducir sus

PIDs.

pcp-htop es una versión de htop construida usando la API de métricas Performance Co-Pilot (PCP) (ver PCPIntro(1), PMAPI(3)), que permite extender htop para mostrar valores de métricas arbitrarias. Ver la sección más abajo titulada ARCHIVOS DE CONFIGURACIÓN para más detalles.

BIBLIOTECAS

EXTERNAS

Mientras que htop depende de la mayoría de las bibliotecas que usa en tiempo de compilación, hay dos excepciones notables a esta regla. Estas excepciones se relacionan ambas con los datos mostrados en los medidores mostrados en el encabezado de htop y fueron creadas intencionalmente como dependencias opcionales en tiempo de ejecución. Estas excepciones se describen a

continuación:
libsyste
md
Los enlaces para libsystemd se utilizan en el medidor SystemD para determinar el número de servicios activos y el estado general del sistema. Buscar las funciones para determinar esta información en tiempo de ejecución permite que las compilaciones soporten estos medidores sin forzar al gestor de paquetes a instalar estas bibliotecas en sistemas que de otro modo no usan systemd.

Resumen: sin dependencia en tiempo de compilación, dependencia opcional en tiempo de ejecución en libsystemd a través de carga dinámica, con systemctl(1)

como
respaldo.
libsenso
rs
Los enlaces para libsensors se utilizan para las lecturas de temperatura de la CPU en los medidores de uso de CPU si la visualización de la temperatura está habilitada a través de la pantalla de configuración. Para que htop muestre estas temperaturas correctamente, se asume una configuración adecuada de libsensors a través de sus archivos de configuración habituales y que todos los núcleos de la CPU corresponden a sensores de temperatura del controlador coretemp con el núcleo 0 correspondiente a un sensor etiquetado "Core 0". La temperatura del paquete puede darse como "Package id 0". Si falta, se infiere como el valor máximo de las lecturas por núcleo disponibles.

Resumen: dependencia en tiempo de compilación en libsensors(3) archivos de cabecera C, dependencia opcional en tiempo de ejecución en libsensors(3) a

través d
e
carga d
inámica.

ARCHIVOS DE

CONFIGURACIÓN

Por defecto htop lee su configuración desde la ruta compatible con XDG ~/.config/htop/htoprc. El archivo de configuración se sobrescribe al salir limpiamente por la configuración del programa de Configuración de htop, por lo que no se debe editar manualmente. Si no existe una configuración de usuario htop intenta leer la configuración de todo el sistema desde /etc/htoprc y como último recurso, recurre a sus valores predeterminados

codificados.

Puede anular la ubicación del archivo de configuración usando la variable de entorno $HTOPRC (para que pueda tener múltiples configuraciones para diferentes máquinas que comparten el mismo directorio de inicio, por ejemplo)

.

La utilidad pcp-htop hace uso de htoprc de una manera similar. Sin embargo, pcp-htop lee su configuración desde una ruta más convencionalmente usada por las herramientas de Performance Co-Pilot, ~/.pcp/htop/htoprc, para proporcionar una configuración separada cuando tanto htop como pcp-htop están instalados y en uso. pcp-htop soporta archivos de configuración adicionales debajo del mismo directorio que permiten añadir nuevos medidores, columnas y pestañas de pantalla a través de la pantalla de Configuración (F2). Esto muestra Medidores Disponibles adicionales, Columna Disponible y Pestañas de Pantalla para cada archivo de configuración de medidor, columna o

pantalla.

Estos archivos de configuración de pcp-htop se leen una vez al inicio. El formato de estos archivos se describe en detalle en la página de manual pcp-htop(5)

.

Esta funcionalidad pone a disposición muchos miles de métricas de Performance Co-Pilot para su visualización por pcp-htop, así como la capacidad de mostrar métricas personalizadas añadidas en sitios individuales. Las aplicaciones y servicios instrumentados usando el formato OpenMetrics https://openmetrics.io también pueden ser mostrados por pcp-htop si el componente pmdaopenmetrics(1) está

configurado.

La configuración para htop y pcp-htop solo se guarda cuando se realiza una salida limpia. Enviar cualquier señal hará que todos los cam

bios de configur
ación se pierdan.
