HAMLIB-UTILITIES(7) Manual de Información de Hamlib HAMLIB-UTILITIES(7)

NOMBRE

hamlib-utilidades - utilidades de control de radio y rotador de Hamlib

DESCRIPCIÓN

Incluidos con la distribución Hamlib hay varios programas de utilidad. Además de proporcionar una forma para que los desarrolladores prueben nuevo código y correcciones de errores, los programas también ofrecen una implementación de referencia para interactuar con las funciones de la biblioteca Hamlib tanto a través de la API de C (Interfaz de Programación de Aplicaciones) como ofreciendo una API accesible por red.

Esta página resume los tres programas de prueba, ampctl(1) para probar backends de amplificador, rigctl(1) para probar backends de radio, y rotctl(1) para probar backends de rotador y los tres demonios de red, ampctld(1), rigctld(1), y rotcltd(1) para el acceso a amplificadores, radios y rotadores a través de sockets de red. También se incluyen tres utilidades de demostración, rigmem(1), rigsmtr(1), y rigswr(1) que proporcionan ejemplos funcionales de cómo Hamlib puede ser utilizado para lograr varias tareas.

rigctl

rigctl(1) es la utilidad Hamlib de uso más frecuente. Como las otras utilidades ctl comparten muchas de las mismas características, gran parte de la información introductoria presentada en esta sección es aplicable a los otros programas de utilidad.

Introducción a rigctl

Lo más probable es que el primer programa de utilidad de Hamlib que se usa sea rigctl(1). rigctl es un programa interactivo basado en caracteres y un programa de línea de comandos capaz de establecer o consultar el valor de una radio con un solo comando. rigctl se invoca desde el prompt de comandos de la shell con varias opciones y comandos adicionales.

En su uso más simple como programa de línea de comandos, rigctl se utiliza para establecer la frecuencia y el modo escribiendo comandos después de cualquier opción de rigctl:


rigctl F 14205000
rigctl M USB 2400

y luego consultar esos valores:


rigctl f
rigctl m

Entrar en modo interactivo es una simple cuestión de no colocar ningún comando después de ninguna opción de rigctl:


rigctl

Entrar en modo interactivo permite ingresar comandos sucesivos sin salir de rigctl. Las adiciones recientes a rigctl permiten la edición de comandos y la recuperación del historial mediante el uso de la biblioteca Readline.

El modo interactivo se indica con el prompt espartano:


Comando de radio:

Los comandos se dan en el prompt y siguen la regla general de que las letras mayúsculas establecen un valor y las letras minúsculas consultan un valor:


Comando de radio: M
Modo: USB
Banda lateral: 2500
Comando de radio: m
Modo: USB
Banda lateral: 2500
Comando de radio:

Se imprime un prompt adicional cuando el comando requiere más información. Para M arriba, rigctl solicitó los valores de Modo y Banda lateral. Para m arriba, rigctl devolvió los valores de Modo y Banda lateral sin solicitudes adicionales. El prompt del comando se devuelve después de cada invocación de comando.

Los ejemplos anteriores invocaron rigctl sin especificar un modelo de radio. Esta es una característica donde se utiliza el modelo de radio interno 1 dummy de Hamlib. La radio dummy proporciona una forma de probar las funciones de Hamlib sin necesidad de hardware de radio real. Sin embargo, para desarrollar la capacidad de backend de Hamlib para una radio dada, es necesario tener la radio real conectada a la computadora para depurar.

Por ejemplo, para establecer rápidamente la frecuencia en un Elecraft K3:


rigctl -m 2029 -r /dev/rig F 3900000

y para consultar la frecuencia y luego el modo:


rigctl -m 2029 -r /dev/rig f
3900000
rigctl -m 2029 -r /dev/rig m
LSB
2000
Nota: los valores devueltos no tienen las cadenas de prompt asociadas con el modo interactivo como se muestra arriba.

La opción -m toma un valor numérico que corresponde a un backend de modelo de radio dado. La opción -r toma la ruta al dispositivo de puerto en POSIX y el nombre del dispositivo en Microsoft Windows.

Nota: una lista completa de modelos de radio compatibles se puede ver usando la opción -l:

rotctl

Idéntico en función a rigctl(1), rotctl(1) proporciona un medio para probar funciones de Hamlib útiles para el control de rotadores y cálculos de localizador QTH (sistema de cuadrícula de Maidenhead, ver Sistema Localizador de Maidenhead). Como los rotadores tienen un alcance mucho más limitado que las radios, hay menos opciones de línea de comandos y comandos para rotctl.

Introducción a rotctl

rotctl(1) es un programa interactivo basado en caracteres y un programa de línea de comandos capaz de establecer o consultar el valor de un rotador con un solo comando. rotctl se invoca desde el prompt de comandos de la shell con varias opciones y comandos adicionales.

En su uso más simple como programa de línea de comandos, rotctl se utiliza para establecer la posición de acimut y (opcionalmente) la elevación escribiendo comandos después de cualquier opción de rotctl:


rotctl P 145.0 23.0
rotctl M 8 25

y luego consultar esos valores:


rotctl p

Entrar en modo interactivo es una simple cuestión de no colocar ningún comando después de ninguna opción de rotctl:


rotctl

Entrar en modo interactivo permite ingresar comandos sucesivos sin salir de rotctl. El modo interactivo permite la edición de comandos y la recuperación del historial mediante el uso de la biblioteca Readline.

El modo interactivo se indica con el prompt espartano:


Comando de rotador:

Los comandos se dan en el prompt:


Comando de rotador: M
Dirección: 16
Velocidad: 60
Comando de rotador: p
Acimut: 11.352000
Elevación: 0.000000
Comando de rotador: p
Acimut: 27.594000
Elevación: 0.000000
Comando de rotador:

Se imprime un prompt adicional cuando el comando requiere más información. Para M arriba, rotctl solicitó los valores de Dirección y Velocidad. Para p arriba, rotctl devolvió los valores de Acimut y Elevación.

rigctld

El programa rigctld(1) es un servidor de red que acepta los comandos familiares de rigctl(1) y proporciona los datos de respuesta a una aplicación a través de un socket de red TCP/IP . De esta manera, una aplicación puede acceder a una instancia de rigctld desde casi cualquier lugar (advertencia, actualmente rigctld no proporciona seguridad). Las aplicaciones que usan rigctld no se enlazan directamente a Hamlib ni usan su API de C.

Introducción a rigctld

rigctld(1) se comunica con un cliente a través de un socket de red TCP usando comandos de texto compartidos con rigctl(1). El protocolo es simple; los comandos se envían a rigctld en una línea y rigctld responde a los comandos get con los valores solicitados, uno por línea, cuando es exitoso; de lo contrario, responde con una línea RPRT x, donde x es un número negativo que indica el código de error de Hamlib. Los comandos que no devuelven valores responden con la línea RPRT x, donde x es cero cuando es exitoso, de lo contrario un número negativo que indica el código de error de Hamlib. Cada línea termina con el carácter de nueva línea, \n. Este protocolo es principalmente para uso por el backend NET rigctl (modelo de radio 2).

Un protocolo separado de Respuesta Extendida extiende el comportamiento anterior haciendo eco de la cadena de comando recibida como encabezado, cualquier valor devuelto como un par clave: valor, y la cadena RPRT x como marcador de fin de respuesta que incluye el valor de éxito o fallo de Hamlib. Considere usar este protocolo para clientes que interactuarán con rigctld directamente a través de un socket de red TCP.

Se pueden controlar múltiples radios en diferentes puertos TCP mediante el uso de múltiples procesos de rigctld, cada uno escuchando en un puerto TCP único. Se espera que rigctld sea especialmente útil para autores de clientes que usan lenguajes como Perl, Python, PHP, Ruby, TCL, y otros.

rigmem

rigmem puede usarse para hacer una copia de seguridad y restaurar la memoria de transceptores y receptores de radio.

Introducción a rigmem

Copia de seguridad y restauración de la memoria de transceptores y receptores de radio. rigmem acepta commands solo desde la línea de comandos.

referencia de rigmem

La referencia completa para rigmem se puede encontrar en la página del manual rigmem(1) .

rigsmtr

rigsmtr usa Hamlib para controlar una radio y medir el valor del S-Meter versus el azimut de la antena.

Introducción a rigsmtr

rigsmtr rota la antena desde el azimut mínimo hasta el azimut máximo. Cada segundo, o time_step si se especifica en segundos, recupera la intensidad de la señal. Luego se imprimen en stdoutel azimut en grados y el nivel correspondiente del S-Meter en dB relativos a S9.

Para funcionar correctamente, rigsmtr necesita una radio que pueda medir el S-Meter y un backend de Hamlib que sea capaz de recuperarlo, conectado a un rotador soportado por Hamlib.

referencia de rigsmtr

La referencia completa para rigsmtr se puede encontrar en la página del manual rigsmtr(1) .

rigswr

rigswr puede usarse para medir el VSWR versus la frecuencia.

Introducción a rigswr

rigswr usa Hamlib para controlar una radio para medir el VSWR (Relación de Onda Estacionaria de Voltaje) sobre un rango de frecuencia.

Escanea frecuencias desde start_freq hasta stop_freq con un incremento opcional de freq_step (el paso predeterminado es 100 kHz). Todos los valores deben ingresarse como un entero en Hertz (ciclos por segundo).

Nota: rigswr asume que start_freq es menor o igual a stop_freq. Si es mayor, rigswr saldrá sin hacer nada.

Para cada frecuencia, rigswr transmite al 25% de la potencia total durante 0.5 segundo en modo CW y lee el VSWR.

La frecuencia y el VSWR correspondiente se imprimen entonces en stdout.

Para funcionar correctamente, rigswr necesita una radio que pueda medir VSWR y un backend de Hamlib que soporte la lectura del VSWR desde la radio.

referencia de rigswr

La referencia completa para rigswr se puede encontrar en la página del manual rigswr(1) .
