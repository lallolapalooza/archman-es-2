Descripción Detallada

Varias funciones pueden ser llamadas opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo debe realizarse la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

Documentación de Tipos de Enumeración

enum hwloc_topology_flags_e

Banderas a establecer en un contexto de topología antes de la carga. Las banderas deben ser pasadas a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detectar el sistema completo, ignorar reservas, incluir objetos desautorizados. Recopilar todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignorar Cgroup/Cpusets de Linux y recopilar todos los procesadores y nodos de memoria. Sin embargo, las PU (Unidades de Procesamiento) y nodos NUMA fuera de línea todavía se ignoran.

Cuando esta bandera no está establecida, las PU y los nodos NUMA que están desautorizados no se añaden a la topología. Los objetos padres (paquete, núcleo, caché, etc.) se añaden solo si algunos de sus hijos están autorizados. Todas las PU y nodos NUMA existentes en la topología están autorizados. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al conjunto de CPU y conjunto de nodos del objeto raíz.

Cuando esta bandera está establecida, los conjuntos reales de PU y nodos NUMA autorizados son dados por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el conjunto de CPU y conjunto de nodos del objeto raíz.

Si la topología actual se exporta a XML y se reimporta más tarde, esta bandera debe establecerse nuevamente en la topología reimportada para que los recursos desautorizados también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asumir que el backend seleccionado proporciona la topología para el sistema en el que estamos ejecutando. Esto fuerza a hwloc_topology_is_thissystem() a devolver 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología para el sistema en el que estamos ejecutando, incluso si no es el backend específico del SO sino el backend XML, por ejemplo. Esto significa hacer que las funciones de enlace llamen realmente a las llamadas del sistema específicas del SO y realmente realicen el enlace, mientras que el backend XML de lo contrario proporcionaría ganchos vacíos que simplemente devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto se puede usar por razones de eficiencia para detectar primero la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero aún teniendo funciones de enlace que realmente enlazan.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtener el conjunto de recursos permitidos del sistema operativo local, incluso si la topología se cargó desde XML o desde una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restringe la topología aplicando las restricciones del proceso actual, como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Esta bandera se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecida, ya que la topología cargada debe coincidir con la máquina subyacente desde la cual se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES daría como resultado el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importar soporte desde la topología importada. Al importar una topología XML de una máquina remota, el enlace se deshabilita por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Esta deshabilitación también se marca poniendo ceros en los bits correspondientes de las características soportadas informadas por hwloc_topology_get_support().

La bandera HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT en realidad importa bits de soporte de la máquina remota. También establece la bandera imported_support en el array de la struct hwloc_topology_misc_support. Si el XML importado no contenía ninguna información de soporte (el exportador hwloc es demasiado antiguo), esta bandera no se establece.

Tenga en cuenta que estas características soportadas solo son relevantes para la instalación de hwloc que exportó la topología XML (puede variar según el sistema operativo o cómo se compiló hwloc).

Tenga en cuenta que establecer esta bandera, sin embargo, no habilita el enlace para la topología hwloc importada localmente, solo informa lo que el hwloc remoto y la máquina soportan.

No considerar recursos fuera del enlace CPU del proceso. Si el enlace del proceso está limitado a un subconjunto de núcleos, ignorar los otros núcleos durante el descubrimiento

Establece el filtrado para todos los tipos de objetos de caché de CPU. Las cachés del lado de la memoria no están involucradas ya que no son cachés de CPU.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Establece los flags combinados con OR en una topología aún no cargada. Establece un conjunto de flags combinados con OR de hwloc_topology_flags_e en una topología que aún no ha sido cargada.

Si esta función se llama varias veces, la última invocación borrará y reemplazará el conjunto de flags que se estableció previamente.

De forma predeterminada, no se establecen flags (0).

Los flags establecidos en una topología pueden recuperarse con hwloc_topology_get_flags().

Devuelve

0 en caso de éxito.

-1 en caso de error, por ejemplo si los flags no son válidos.

void hwloc_topology_set_userdata (hwloc_topology_t topology, const void * userdata)

Establece el puntero userdata específico de la topología. Cada topología puede almacenar un puntero a datos privados proporcionados por la aplicación. Se inicializa a NULL. hwloc nunca lo modificará.

Úselo como desee, después de hwloc_topology_init() y hasta hwloc_topolog_destroy().

Este puntero no se exporta a XML.
