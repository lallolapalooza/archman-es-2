Descripción

detallada

El tipo hwloc_bitmap_t representa un conjunto de enteros (positivos o nulos). Un mapa de bits puede ser de tamaño infinito (todos los bits están establecidos después de algún punto). Un mapa de bits incluso puede estar completo si todos los bits están

establecidos.

hwloc utiliza mapas de bits para conjuntos de procesadores del SO (que pueden ser en realidad hilos de hardware) como hwloc_cpuset_t (un typedef para hwloc_bitmap_t), o conjuntos de nodos de memoria NUMA como hwloc_nodeset_t (también un typedef para hwloc_bitmap_t). Estos se utilizan para los campos cpuset y nodeset en la estructura hwloc_obj, ver Conjuntos de objetos (hwloc_cpuset_t

y hwloc_nodeset_t).

Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del SO. Sin embargo, los usuarios normalmente no deberían construir conjuntos de CPU y de nodos manualmente (por ejemplo, con hwloc_bitmap_set()). Deberían usar más bien conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or(), etc. Por ejemplo, vincular el hilo actual a un par de núcleos puede realizarse

con: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

Not

a
La mayoría de las funciones siguientes devuelven 0 en caso de éxito y -1 en caso de error. El caso de error habitual sería un fallo interno al realloc/extend el almacenamiento del mapa de bits (errno se establecería en ENOMEM). Ver también Informe de errores en la API.

Varios ejemplos de uso de la API de mapas de bits están d

isponibles en el directorio doc/examples/ del árbol d
e fuentes. Las pruebas de regresión como tests/hwloc
/hwloc_bitmap*.c también hacen uso intensivo de esta API.

#define hwloc_bitmap_foreach_begin(id,

bitmap)

Macro de bucle que itera sobre el mapa de bits bitmap. El bucle debe comenzar con hwloc_bitmap_foreach_begin() y terminar con hwloc_bitmap_foreach_end() seguido de un ';

'.

id es la variable del bucle; debería ser un unsigned int. La primera iteración establecerá id en el índice más bajo del mapa de bits. Las iteraciones sucesivas recorrerán, en orden, todos los índices restantes establecidos en el mapa de bits. Para ser específico: cada iteración devolverá un valor para id tal que hwloc_bitmap_isset(bitmap, id) es

verdadero.

a infinito si el mapa de bits es

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los bitmaps bitmap1 y bitmap2 en orden lexicográfico. Comparación lexicográfica de bitmaps, comenzando por sus índices más altos. Compara los últimos índices primero, luego los penúltimos, etc. El bitmap vacío se considera menor que cualquier otro.

Devuelve

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

0 si los bitmaps son iguales (contrario a hwloc_bitmap_compare_first()).

Por ejemplo, comparar los bitmaps binarios 0011 y 0110 devuelve -1 (por lo tanto, 0011 se considera menor que 0110). Comparar 00101 y 01010 también devuelve -1.

Nota

Esto es diferente del inexistente hwloc_bitmap_compare_last() que solo compararía el índice más alto de cada bitmap.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los bitmaps bitmap1 y bitmap2 usando su índice más bajo. Un bitmap se considera menor si su bit menos significativo es menor. El bitmap vacío se considera mayor que cualquier otro (porque su bit menos significativo no existe).

Devuelve

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

Por ejemplo, comparar los bitmaps binarios 0011 y 0110 devuelve -1 (por lo tanto, 0011 se considera menor que 0110) porque el bit menos significativo de 0011 (0001) es menor que el bit menos significativo de 0110 (0010). Comparar 01001 y 00110 también devolvería -1 por la misma razón.

Devuelve

0 si los bitmaps se consideran iguales, aunque no sean estrictamente iguales. Solo necesitan tener el mismo bit menos significativo. Por ejemplo, comparar los bitmaps binarios 0010 y 0110 devuelve 0 porque tienen el mismo bit menos significativo.
