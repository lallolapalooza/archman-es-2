DESCRIPCIÓ

N

Este manual es para la interfaz web de hledger, versión 1.51. Consulte también el manual de hledger para conceptos comunes y formatos de

archivo.

hledger es un conjunto de programas robusto, fácil de usar y multiplataforma para rastrear dinero, tiempo o cualquier otra mercancía, utilizando contabilidad de partida doble y un formato de archivo simple y editable. hledger está inspirado en y es en gran medida compatible con ledger(1), y en gran medida interconvertible con beancount(1)

.

hledger-web es una aplicación web simple para navegar y añadir transacciones. Proporciona una interfaz de usuario más amigable que la CLI de hledger o la TUI de hledger-ui, mostrando más a la vez (cuentas, el registro de cuenta actual, gráficos de balance) y permitiendo la entrada de datos con historial, búsqueda interactiva y

marcadores.

hledger-web también le permite compartir un diario con múltiples usuarios, o incluso con la web pública. No hay control de acceso, así que si necesita eso debería ponerlo detrás de un proxy web adecuado. Como pequeña protección contra la pérdida de datos al ejecutar una instancia no protegida, escribe una copia de seguridad numerada del archivo de diario principal (solo) en cada

edición.

Al igual que hledger, lee de (y añade a) un archivo de diario especificado por la variable de entorno LEDGER_FILE (por defecto $HOME/.hledger.journal); o puede especificar archivos con opciones -f. También puede leer archivos timeclock, archivos timedot, o cualquier archivo CSV/SSV/TSV con un campo de fecha. (Consulte hledger(1) -> Entrada para más detalles.

)

hledger-web se puede ejecutar en tres

modos:
•
modo --serve-browse (el por defecto): la aplicación sirve la interfaz web y la API JSON, y abre su navegador web predeterminado para mostrar la aplicación si es posible, y sale automáticamente después de dos minutos de inactividad (sin recibir solicitudes y sin ventanas de navegador abiertas que la visualicen)
.
•
--serve: la aplicación solo sirve la interfaz web y la API
JSON.
•
--serve-api: la aplicación
solo sirve la
API JSON.

En todos los casos hledger-web se ejecu

ta como un proceso en primer plano, reg
istrando las solicitudes en stdout.

Por defecto hledger-web escucha solo en la dirección IP 127.0.0.1, que solo puede ser accesada desde la máquina

local.

Para permitir el acceso desde otro lugar, use --host para especificar una dirección accesible externamente configurada en esta máquina. La dirección especial 0.0.0.0 hace que escuche en todas las direcciones de esta

máquina.

De manera similar, puede usar --port para escuchar en un puerto TCP distinto de 5000. Esto es útil si desea ejecutar múltiples instancias de hledger-web en una

máquina.

Cuando se usa --socket, hledger-web crea y se comunica a través de un archivo de socket en lugar de un puerto TCP. Esto puede ser más seguro, respeta los permisos de archivos unix y hace ciertos casos de uso más fáciles, como ejecutar instancias por usuario detrás de un proxy inverso nginx. (Ej: proxy_pass http://unix:/tmp/hledger/${remote_use

r}.socket;.)

Puede usar --base-url para cambiar el protocolo, nombre de host, puerto y ruta que aparecen en los hipervínculos de hledger-web. Esto es útil, por ejemplo, al integrar hledger-web dentro de un sitio web más grande. El valor por defecto es http://HOST:PORT/ usando la dirección de host configurada del servidor y el puerto TCP (o http://HOST si PORT es 80). Tenga en cuenta que esto afecta a la generación de urls pero no al análisis de

rutas.

Por defecto, hledger-web permite a cualquiera que pueda alcanzarlo ver el diario y añadir nuevas transacciones, pero no modificar los datos

existentes.

Puedes restringir quién puede alcanzarlo,

mediante

ponerlo detrás de un proxy de autenticación, como caddy o

ponerlo det

Y puedes restringir lo que los usuarios que lo alcanzan pueden hacer, mediante la especificación de la opción --allow=ACCESSLEVEL al inicio. ACCESSLEVEL es uno

•

El nivel de acceso predeterminado es ad

EDICIÓN, SUBIDA,

DESCARGA

Si habilitas la capacidad de gestión mencionada anteriormente, verás un nuevo botón de "llave inglesa" a la derecha de el formulario de búsqueda. Al hacer clic en él podrás editar, subir o descargar el archivo del diario o cualquier archivo que

incluya.

Ten en cuenta que, a diferencia de cualquier otro comando de hledger, en este modo tú (o cualquier visitante) puedes alterar o borrar los archivos de

datos.

Normalmente, cada vez que un archivo se cambia de esta manera, hledger-web guarda una copia de seguridad numerada (suponiendo que los permisos del archivo lo permitan, que el disco no esté lleno, etc.). hledger-web no es consciente de los sistemas de control de versiones, actualmente; si usas uno, tendrás que organizar tú mismo la confirmación de los cambios (ej con un trabajo cron o un observador de archivos como entr)

.

Se impiden los cambios que dejarían el(los) archivo(s) del diari

o sin poder analizar o no válido (ej con aserciones de saldo
que fallan). (Probablemente. Esto necesita ser reevaluado.)

RECARG

A

hledger-web detecta cambios realizados en los archivos por otros medios (ej si lo editas directamente, fuera de hledger-web), y mostrará los nuevos datos cuando recargues la página o navegues a una nueva página. Si un cambio hace que un archivo no se pueda analizar, hledger-web mostrará un mensaje de error hasta que el archivo haya sido

corregido.

(Nota: si estás viendo archivos montados desde otr

a máquina, asegúrate de que los relojes de am
bas máquinas estén aproximadamente sincronizados.)

Salida de

depuración

Puede agregar --debug[=N] a la línea de comando para registrar la salida de depuración. N varía desde 1 (menor salida, el valor predeterminado) hasta 9 (salida máxima). Normalmente comenzaría con 1 e incrementaría hasta que vea lo suficiente. La salida de depuración va a stderr, intercalada con las solicitudes registradas en stdout. Para capturar la salida de depuración en un archivo de registro en su lugar, generalmente puede redirigir stderr, por

ejemplo:
