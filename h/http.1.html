http(1) Manual de HTTPie http(1)

NOMBRE

http

SINOPSIS

http [METHOD] URL [REQUEST_ITEM ...]

DESCRIPCIÓN

HTTPie: cliente HTTP moderno y fácil de usar desde la línea de comandos para la era de las API. https://httpie.io

Argumentos posicionales

Estos argumentos vienen después de cualquier bandera y en el orden en que se enumeran aquí. Solo la URL es obligatoria.

MÉTODO

El método HTTP que se utilizará para la solicitud (GET, POST, PUT, DELETE, ...).

Este argumento puede omitirse, en cuyo caso HTTPie utilizará POST si hay algunos datos para enviar, de lo contrario, GET:


$ http example.org # => GET
$ http example.org hello=world # => POST

URL

La URL de la solicitud. El esquema por defecto es 'http://' si la URL no lo incluye. (Puedes anular esto con: --default-scheme=http/https)

También puedes usar una forma abreviada para localhost


$ http :3000 # => http://localhost:3000
$ http :/foo # => http://localhost/foo

ITEM_SOLICITUD

Pares clave-valor opcionales para incluir en la solicitud. El separador utilizado determina el tipo:

':' Encabezados HTTP:


Referer:https://httpie.io Cookie:foo=bar User-Agent:bacon/1.0

'==' Parámetros de URL para agregar a la URI de la solicitud:


search==httpie

'=' Campos de datos para serializar en un objeto JSON (con --json, -j)
o datos de formulario (con --form, -f):


name=HTTPie language=Python description='CLI HTTP client'

':=' Campos JSON de datos no string (solo con --json, -j):


awesome:=true amount:=42 colors:='["red", "green", "blue"]'

'@' Campos de archivo de formulario (solo con --form o --multipart):


cv@~/Documents/CV.pdf
cv@'~/Documents/CV.pdf;type=application/pdf'

"=@" Un campo de datos como '=', pero toma una ruta de archivo e incrusta su contenido:


essay=@Documents/essay.txt

":=@" Un campo JSON en bruto como ':=', pero toma una ruta de archivo e incrusta su contenido:


package:=@./package.json

Puedes usar una barra invertida para escapar un separador que colisiona en el nombre del campo:


field-name-with\:colon=value

Tipos de contenido predefinidos

--json, -j

(por defecto) Los elementos de datos de la línea de comandos se serializan como un objeto JSON. Los encabezados Content-Type y Accept se establecen en application/json (si no se especifican).

--form, -f

Los elementos de datos de la línea de comandos se serializan como campos de formulario.

El Content-Type se establece en application/x-www-form-urlencoded (si no se especifica). La presencia de cualquier campo de archivo da como resultado una solicitud multipart/form-data.

--multipart

Similar a --form, pero siempre envía una solicitud multipart/form-data (es decir, incluso sin archivos).

--boundary

Especifica una cadena límite personalizada para solicitudes multipart/form-data. Solo tiene efecto junto con --form.

--raw

Esta opción te permite pasar datos de solicitud sin procesar y sin procesamiento adicional (a diferencia de la sintaxis de elementos de solicitud estructurada):


$ http --raw='data' pie.dev/post

Puedes lograr lo mismo canalizando los datos a través de stdin:


$ echo data | http pie.dev/post

O hacer que HTTPie cargue los datos sin procesar de un archivo:


$ http pie.dev/post @data.txt

Opciones de procesamiento de contenido

--compress, -x

Contenido comprimido (codificado) con el algoritmo Deflate. El encabezado Content-Encoding se establece en deflate.

La compresión se omite si parece que la relación de compresión es negativa. La compresión se puede forzar repitiendo el argumento.

Procesamiento de salida

--pretty

Controla el procesamiento de la salida. El valor puede ser "none" para no embellecer la salida (por defecto para salida redirigida), "all" para aplicar tanto colores como formato (por defecto para salida de terminal), "colors", o "format".

--style, -s ESTILO

Estilo de color de salida (por defecto es "auto"). Puede ser uno de:


auto, pie, pie-dark, pie-light, solarized

Para encontrar todos los estilos disponibles en tu sistema, prueba:

$ http --style

El estilo "auto" sigue los estilos de color ANSI de tu terminal. Para que los estilos no automáticos funcionen correctamente, asegúrate de que la variable de entorno $TERM esté configurada como "xterm-256color" o similar (por ejemplo, mediante `export TERM=xterm-256color' en tu ~/.bashrc).

--unsorted

Deshabilita toda la ordenación al formatear la salida. Es un atajo para:


--format-options=headers.sort:false,json.sort_keys:false

--sorted

Vuelve a habilitar todas las opciones de ordenación al formatear la salida. Es un atajo para:


--format-options=headers.sort:true,json.sort_keys:true

--response-charset CODIFICACIÓN

Anula la codificación de respuesta para fines de visualización en terminal, por ejemplo:


--response-charset=utf8
--response-charset=big5

--response-mime TIPO_MIME

Anula el tipo MIME de respuesta para colorear y formatear la terminal, por ejemplo:


--response-mime=application/json
--response-mime=text/xml

--format-options

Controla el formato de salida. Solo es relevante cuando el formato está habilitado a través de (implícito o explícito) --pretty=all o --pretty=format. Las siguientes son las opciones predeterminadas:


headers.sort:true
json.format:true
json.indent:4
json.sort_keys:true
xml.format:true
xml.indent:2
