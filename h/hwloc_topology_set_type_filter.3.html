DESCRIPCIÓN DETALLADA

Varias funciones se pueden llamar opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo se debe realizar la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

DOCUMENTACIÓN DE TIPO ENUMERADO

enum hwloc_topology_flags_e

Marcas que se establecerán en un contexto de topología antes de la carga. Las marcas deben proporcionarse a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detectar todo el sistema, ignorar reservas, incluir objetos desautorizados. Recopilar todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignorar cgroups/Cpusets de Linux y recopilar todos los procesadores y nodos de memoria. Sin embargo, las PU y los nodos NUMA fuera de línea todavía se ignoran.

Cuando esta marca no está establecida, las PU y los nodos NUMA que están desautorizados no se agregan a la topología. Los objetos padre (paquete, núcleo, caché, etc.) se agregan solo si algunos de sus hijos están permitidos. Todas las PU y nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al conjunto de CPU y al conjunto de nodos del objeto raíz.

Cuando esta marca está establecida, los conjuntos reales de PU y nodos NUMA permitidos se proporcionan en hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el conjunto de CPU y el conjunto de nodos del objeto raíz.

Si la topología actual se exporta a XML y se reimporta más tarde, esta marca debe establecerse nuevamente en la topología reimportada para que los recursos desautorizados también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asumir que el backend seleccionado proporciona la topología para el sistema en el que se está ejecutando. Esto fuerza a hwloc_topology_is_thissystem() a devolver 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología para el sistema en el que se está ejecutando, incluso si no es el backend específico del sistema operativo, sino el backend XML, por ejemplo. Esto significa hacer que las funciones de vinculación realmente llamen a las llamadas del sistema específicas del sistema operativo y realmente hagan la vinculación, mientras que el backend XML de lo contrario proporcionaría ganchos vacíos que simplemente devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto se puede usar por razones de eficiencia para detectar primero la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero aún así teniendo funciones de vinculación que realmente vinculan.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtener el conjunto de recursos permitidos del sistema operativo local, incluso si la topología se cargó desde XML o desde una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restríngela aplicando las restricciones del proceso actual, como el cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Esta marca se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecida, ya que la topología cargada debe coincidir con la máquina subyacente de la que se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES daría como resultado el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importar soporte desde la topología importada. Al importar una topología XML de una máquina remota, la vinculación está deshabilitada por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Esta deshabilitación también se marca poniendo ceros en los bits correspondientes de las características soportadas informadas por hwloc_topology_get_support().

La marca HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT realmente importa los bits de soporte de la máquina remota. También establece la marca imported_support en la matriz struct hwloc_topology_misc_support. Si el XML importado no contenía ninguna información de soporte (el exportador hwloc es demasiado antiguo), esta marca no se establece.

Tenga en cuenta que estas características soportadas solo son relevantes para la instalación de hwloc que realmente exportó la topología XML (puede variar según el sistema operativo o cómo se compiló hwloc).

Tenga en cuenta que establecer esta marca, sin embargo, no habilita la vinculación para la topología hwloc importada localmente; solo informa lo que el hwloc y la máquina remotos soportan.
