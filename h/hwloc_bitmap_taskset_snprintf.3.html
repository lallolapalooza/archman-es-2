Descripción

detallada

El tipo hwloc_bitmap_t representa un conjunto de enteros (positivos o nulos). Un mapa de bits puede ser de tamaño infinito (todos los bits están establecidos después de algún punto). Un mapa de bits incluso puede estar completo si todos los bits están

establecidos.

hwloc utiliza mapas de bits para conjuntos de procesadores del SO (que pueden ser en realidad hilos de hardware) como hwloc_cpuset_t (un typedef para hwloc_bitmap_t), o conjuntos de nodos de memoria NUMA como hwloc_nodeset_t (también un typedef para hwloc_bitmap_t). Estos se utilizan para los campos cpuset y nodeset en la estructura hwloc_obj, ver Conjuntos de objetos (hwloc_cpuset_t

y hwloc_nodeset_t).

Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del SO. Sin embargo, los usuarios normalmente no deberían construir conjuntos de CPU y de nodos manualmente (por ejemplo, con hwloc_bitmap_set()). Deberían usar más bien conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or(), etc. Por ejemplo, enlazar el hilo actual a un par de núcleos puede realizarse

con: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

Not

a
La mayoría de las funciones siguientes devuelven 0 en caso de éxito y -1 en caso de error. El caso de error habitual sería un fallo interno al reallocar/extender el almacenamiento del mapa de bits (errno se establecería en ENOMEM). Ver también Informe de errores en la API.

Hay varios ejemplos de uso de la API de mapas de bits dis

ponibles en el directorio doc/examples/ del árbol de
fuentes. Las pruebas de regresión como tests/hwloc/hw
loc_bitmap*.c también hacen un uso intensivo de esta API.

#define hwloc_bitmap_foreach_begin(id,

bitmap)

Macro de bucle que itera sobre el mapa de bits bitmap. El bucle debe comenzar con hwloc_bitmap_foreach_begin() y terminar con hwloc_bitmap_foreach_end() seguido de un ';

'.

id es la variable del bucle; debería ser un unsigned int. La primera iteración establecerá id en el índice más bajo del mapa de bits. Las iteraciones sucesivas recorrerán, en orden, todos los índices restantes establecidos en el mapa de bits. Para ser específico: cada iteración devolverá un valor para id tal que hwloc_bitmap_isset(bitmap, id) sea

verdadero.

La aserción evita que el bucle se

a infinito si el mapa de bits es
tá infinitamente establecido.

int hwloc_bitmap_list_asprintf (char ** strp, hwloc_const_bitmap_t bitmap)

Stringify a bitmap into a newly allocated list string. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.

Lists are comma-separated indexes or ranges. Ranges are dash separated indexes. A bitmap containing bits 1, 33, 34, and all from 64 to 95 is printed as '1,33-34,64-95'. The last range may not have an ending index if the bitmap is infinitely set.

Returns

the number of characters that were written (not including the ending \0).

-1 on error, for instance with errno set to ENOMEM on failure to allocate the output string.

int hwloc_bitmap_list_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Stringify a bitmap in the list format. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.

Lists are comma-separated indexes or ranges. Ranges are dash separated indexes. A bitmap containing bits 1, 33, 34, and all from 64 to 95 is printed as '1,33-34,64-95'. The last range may not have an ending index if the bitmap is infinitely set.

Up to buflen characters may be written in buffer buf.

If buflen is 0, buf may safely be NULL.

Returns

the number of characters that were actually written if not truncating, or that would have been written (not including the ending \0).

-1 on error.

int hwloc_bitmap_list_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Parse a list string and stores it in bitmap bitmap. Note that if the bitmap is a CPU or nodeset, the input string must contain physical indexes.

Lists are comma-separated indexes or ranges. Ranges are dash separated indexes. String '1,33-34,64-95' is parsed as a bitmap containing bits 1, 33, 34, and all from 64 to 95. The last range may not have an ending index if the bitmap is infinitely set.

Returns

0 on success, -1 on error.

int hwloc_bitmap_nr_ulongs (hwloc_const_bitmap_t bitmap)

Return the number of unsigned longs required for storing bitmap bitmap entirely. This is the number of contiguous unsigned longs from the very first bit of the bitmap (even if unset) up to the last set bit. This is useful for knowing the nr parameter to pass to hwloc_bitmap_to_ulongs() (or which calls to hwloc_bitmap_to_ith_ulong() are needed) to entirely convert a bitmap into multiple unsigned longs.

When called on the output of hwloc_topology_get_topology_cpuset(), the returned number is large enough for all cpusets of the topology.

Returns

the number of unsigned longs required.

-1 if bitmap is infinite.

int hwloc_bitmap_singlify (hwloc_bitmap_t

bitmap)

Mantiene un solo índice entre los establecidos en el mapa de bits bitmap. Puede ser útil antes de la vinculación para que el proceso no tenga la oportunidad de migrar entre múltiples procesadores en la máscara original. En lugar de ejecutar la tarea en cualquier PU dentro del conjunto de CPU dado, el planificador del sistema operativo se verá obligado a ejecutarla en uno solo de estos PUs. Evita una sobrecarga de migración y los "ping-pongs" de la línea de caché entre

PUs.

Not

a
Esta función NO está destinada a distribuir múltiples procesos dentro de un solo conjunto de CPU. Siempre devuelve el mismo bit único cuando se llama varias veces en el mismo conjunto de entrada. hwloc_distrib() puede usarse para generar conjuntos de CPU para distribuir múltiples tareas debajo de un solo objeto multi-PU.

Esta función no puede aplicarse directamente a un conjunto de objetos. Debe aplicarse a una copia (que puede obtenerse con hwloc_bi

tmap
