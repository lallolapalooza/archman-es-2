El tipo hwloc_bitmap_trepresenta un conjunto de enteros (positivos o nulos). Un mapa de bits puede ser de tamaño infinito (todos los bits están establecidos después de algún punto). Un mapa de bits incluso puede estar completo si todos los bits están establecidos. hwloc utiliza mapas de bits para conjuntos de procesadores del SO (que pueden ser en realidad hilos de hardware) como
hwloc_cpuset_t (un typedef parahwloc_bitmap_t ), o conjuntos de nodos de memoria NUMA como
hwloc_nodeset_t (también un typedef parahwloc_bitmap_t ). Estos se utilizan para los campos cpuset y nodeset en la estructura

hwloc_ob

j

, véase Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t

)

. Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del SO. Sin embargo, los usuarios normalmente no deberían construir conjuntos de CPU y de nodos manualmente (por ejemplo, con hwloc_bitmap_set() ). Es preferible usar conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or() , etc. Por ejemplo, enlazar el hilo actual a un par de

núcleos puede realizarse con:

hwloc_obj_t core1 = ... , core2 = ... ; hwloc_bitmap_t set = hwloc_bitmap_alloc(); hwloc_bitmap_or(set, core1->cpuset, core2->cpuset); hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD); hwloc_bitmap_free(set); Nota La mayoría de las funciones siguientes devuelven 0 en caso de éxito y -1 en caso de error. El caso de error habitual sería un fallo interno al reallocar/extender el almacenamiento del mapa de bits

(errno

ENOMEM

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los mapas de bits bitmap1 y bitmap2 en orden lexicográfico. Comparación lexicográfica de mapas de bits, empezando por sus índices más altos. Compara los últimos índices primero, luego los segundos, etc. El mapa de bits vacío se considera menor que cualquier otro.

Devuelve

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

0 si los mapas de bits son iguales (a diferencia de hwloc_bitmap_compare_first()).

Por ejemplo, comparar los mapas de bits binarios 0011 y 0110 devuelve -1 (por lo tanto, 0011 se considera menor que 0110). Comparar 00101 y 01010 también devuelve -1.

Nota

Esto es diferente del inexistente hwloc_bitmap_compare_last() que solo compararía el índice más alto de cada mapa de bits.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los mapas de bits bitmap1 y bitmap2 usando su índice más bajo. Un mapa de bits se considera menor si su bit menos significativo es menor. El mapa de bits vacío se considera mayor que cualquier otro (porque su bit menos significativo no existe).

Devuelve

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

Por ejemplo, comparar los mapas de bits binarios 0011 y 0110 devuelve -1 (por lo tanto, 0011 se considera menor que 0110) porque el bit menos significativo de 0011 (0001) es menor que el bit menos significativo de 0110 (0010). Comparar 01001 y 00110 también devolvería -1 por la misma razón.

Devuelve

0 si los mapas de bits se consideran iguales, incluso si no lo son estrictamente. Solo necesitan tener el mismo bit menos significativo. Por ejemplo, comparar los mapas de bits binarios 0010 y 0110 devuelve 0 porque tienen el mismo bit menos significativo.

DESCRIPTION

These functions manipulate sets of hardware locality objects, also called bitmaps. These bitmaps are used to represent sets of PUs, nodes, NUMA nodes, devices, etc.

They are opaque structures.

Functions manipulating bitmaps are often named like hwloc_bitmap_*.

It is possible to pass hwloc_bitmap_alloc() as one of the arguments to functions that take hwloc_bitmap_t or hwloc_const_bitmap_t, if it is not used.

If a function takes both hwloc_bitmap_t and hwloc_const_bitmap_t arguments, the result argument (hwloc_bitmap_t) may be the same as one of the input arguments (hwloc_const_bitmap_t).

The following functions are available:

hwloc_bitmap_or()
Or bitmaps bitmap1 and bitmap2 and store the result in bitmap res. res can be the same as bitmap1 or bitmap2
hwloc_bitmap_set()
Add index id in bitmap bitmap.
hwloc_bitmap_set_ith_ulong()
Replace i -th subset of bitmap bitmap with unsigned long mask.
hwloc_bitmap_set_range()
Add indexes from begin to end in bitmap bitmap. If end is -1, the range is infinite.
hwloc_bitmap_singlify()
Keep a single index among those set in bitmap bitmap. May be useful before binding so that the process does not have a chance of migrating between multiple processors in the original mask. Instead of running the task on any PU inside the given CPU set, the operating system scheduler will be forced to run it on a single of these PUs. It avoids a migration overhead and cache-line ping-pongs between PUs.

Note

This function is NOT meant to distribute multiple processes within a single CPU set. It always return the same single bit when called multiple times on the same input set. hwloc_distrib() may be used for generating CPU sets to distribute multiple tasks below a single multi-PU object.

This function cannot be applied to an object set directly. It should be applied to a copy (which may be obtained with hwloc_bitmap_dup()).

hwloc_bitmap_snprintf()
Stringify a bitmap in the default hwloc format. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.
hwloc_bitmap_sscanf()
Parse a bitmap string as the default hwloc format and stores it in bitmap bitmap. Note that if the bitmap is a CPU or nodeset, the input string must contain physical indexes.
hwloc_bitmap_taskset_asprintf()
Stringify a bitmap into a newly allocated taskset-specific string. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.
hwloc_bitmap_taskset_snprintf()
Stringify a bitmap in the taskset-specific format. Note that if the bitmap is a CPU or nodeset, it contains physical indexes.
hwloc_bitmap_taskset_sscanf()
Parse a taskset-specific bitmap string and stores it in bitmap bitmap. Note that if the bitmap is a CPU or nodeset, the input string must contain physical indexes.
hwloc_bitmap_to_ith_ulong()
Convert the i -th subset of bitmap bitmap into unsigned long mask.
hwloc_bitmap_to_ulong()
Convert the beginning part of bitmap bitmap into unsigned long mask.
hwloc_bitmap_to_ulongs()
Convert the first nr subsets of bitmap bitmap into the array of nr unsigned long masks. nr may be determined earlier with hwloc_bitmap_nr_ulongs().

Returns

0
hwloc_bitmap_weight()
Compute the 'weight' of bitmap bitmap (i.e., number of indexes that are in the bitmap).

Returns

the number of indexes that are in the bitmap.

-1 if bitmap is infinitely set.

hwloc_bitmap_xor()
Xor bitmaps bitmap1 and bitmap2 and store the result in bitmap res. res can be the same as bitmap1 or bitmap2
hwloc_bitmap_zero()
Empty the bitmap bitmap.
