hash(3) Manual de funciones de biblioteca hash(3)

NOMBRE

hash - método de acceso a bases de datos hash

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/types.h>
#include <db.h>

DESCRIPCIÓN

Nota importante: Esta página documenta las interfaces que se proporcionaron hasta glibc 2.1. Desde glibc 2.2, glibc ya no proporciona estas interfaces. Probablemente, esté buscando las API proporcionadas por la biblioteca libdb en su lugar.

La rutina dbopen(3) es la interfaz de la biblioteca para los archivos de base de datos. Uno de los formatos de archivo soportados son los archivos hash. La descripción general de los métodos de acceso a bases de datos se encuentra en dbopen(3), esta página del manual describe solo la información específica de hash.

La estructura de datos hash es un esquema de hash dinámico y extensible.

La estructura de datos específica del método de acceso proporcionada a dbopen(3) se define en el archivo de inclusión <db.h> de la siguiente manera:


typedef struct {
    unsigned int       bsize;
    unsigned int       ffactor;
    unsigned int       nelem;
    unsigned int       cachesize;
    uint32_t         (*hash)(const void *, size_t);
    int         lorder;
} HASHINFO;

Los elementos de esta estructura son los siguientes:

bsize
define el tamaño del cubo de la tabla hash y, por defecto, es de 256 bytes. Puede ser preferible aumentar el tamaño de página para tablas residentes en disco y tablas con elementos de datos grandes.
ffactor
indica una densidad deseada dentro de la tabla hash. Es una aproximación del número de claves que se permite que se acumulen en cualquier cubo, determinando cuándo la tabla hash crece o se encoge. El valor por defecto es 8.
nelem
es una estimación del tamaño final de la tabla hash. Si no se establece o se establece demasiado bajo, las tablas hash se expandirán gradualmente a medida que se ingresan las claves, aunque se puede notar una ligera degradación del rendimiento. El valor por defecto es 1.
cachesize
es el tamaño máximo sugerido, en bytes, de la caché de memoria. Este valor es solo una recomendación, y el método de acceso asignará más memoria en lugar de fallar.
hash
es una función hash definida por el usuario. Dado que ninguna función hash funciona igual de bien en todos los datos posibles, el usuario puede descubrir que la función hash incorporada funciona mal en un conjunto de datos particular. Las funciones hash especificadas por el usuario deben tomar dos argumentos (un puntero a una cadena de bytes y una longitud) y devolver una cantidad de 32 bits que se utilizará como valor hash.
lorder
es el orden de bytes para los enteros en los metadatos de la base de datos almacenada. El número debe representar el orden como un entero; por ejemplo, el orden big endian sería el número 4,321. Si lorder es 0 (no se especifica orden), se utiliza el orden del host actual. Si el archivo ya existe, se ignora el valor especificado y se utiliza el valor especificado cuando se creó el árbol.

Si el archivo ya existe (y no se especifica la bandera O_TRUNC), se ignoran los valores especificados para bsize, ffactor, lorder y nelem y se utilizan los valores especificados cuando se creó el árbol.

Si se especifica una función hash, hash_open intenta determinar si la función hash especificada es la misma que con la que se creó la base de datos, y falla si no lo es.

Se proporcionan interfaces compatibles con versiones anteriores para las rutinas descritas en dbm(3) y ndbm(3), sin embargo, estas interfaces no son compatibles con formatos de archivo anteriores.

ERRORES

Las rutinas del método de acceso hash pueden fallar y establecer errno para cualquiera de los errores especificados para la rutina de biblioteca dbopen(3).

ERRORES DE PROGRAMACIÓN

Solo se admiten los órdenes de bytes big-endian y little-endian.
