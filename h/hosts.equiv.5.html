hosts.equiv(5) Manual de formatos de archivo hosts.equiv(5)

NOMBRE

hosts.equiv - lista de hosts y usuarios a los que se les concede acceso a los comandos r de "confianza" a su sistema

DESCRIPCIÓN

El archivo /etc/hosts.equiv permite o deniega el acceso de hosts y usuarios a los comandos r (por ejemplo, rlogin, rsh o rcp) sin necesidad de proporcionar una contraseña.

El archivo utiliza el siguiente formato:

+|[-]hostname|+@netgroup|-@netgroup [+|[-]username|+@netgroup|-@netgroup]

El hostname es el nombre de un host que es lógicamente equivalente al host local. Los usuarios conectados a ese host tienen permitido acceder a cuentas de usuario con el mismo nombre en el host local sin proporcionar una contraseña. El hostname puede ir precedido (opcionalmente) por un signo más (+). Si el signo más se usa solo, permite que cualquier host acceda a su sistema. Puede denegar explícitamente el acceso a un host precediendo el hostname con un signo menos (-). Los usuarios de ese host siempre deben proporcionar credenciales adicionales, incluyendo posiblemente una contraseña. Por razones de seguridad, siempre debe usar el FQDN del hostname y no el hostname corto.

La entrada username otorga a un usuario específico acceso a todas las cuentas de usuario (excepto root) sin necesidad de proporcionar una contraseña. Esto significa que el usuario NO está restringido a cuentas con el mismo nombre. El username puede ir precedido (opcionalmente) por un signo más (+). También puede denegar explícitamente el acceso a un usuario específico precediendo el username con un signo menos (-). Esto indica que el usuario no es de confianza independientemente de otras entradas para ese host.

Los netgroups se pueden especificar precediendo el netgroup con un signo @.

Tenga mucho cuidado al usar el signo más (+). Un simple error tipográfico podría resultar en un signo más independiente. Un signo más independiente es un comodín que significa "cualquier host".

ARCHIVOS

/etc/hosts.equiv

NOTAS

Algunos sistemas solo honran el contenido de este archivo cuando es propiedad de root y no tiene permisos de escritura para nadie más. Algunos sistemas excepcionalmente paranoicos incluso requieren que no haya otros enlaces físicos al archivo.

Los sistemas modernos utilizan la biblioteca de Módulos de Autenticación Conectables (PAM). Con PAM, un signo más independiente se considera un carácter comodín que significa "cualquier host" solo cuando la palabra promiscuous se agrega a la línea del componente auth en su archivo PAM para el servicio particular (por ejemplo, rlogin).

EJEMPLOS

A continuación, se muestran algunos ejemplos de archivos /etc/host.equiv o ~/.rhosts.

Permitir que cualquier usuario inicie sesión desde cualquier host:


+

Permitir que cualquier usuario de host con una cuenta local coincidente inicie sesión:


host

Nota: el uso de +host nunca es una sintaxis válida, ni siquiera al intentar especificar que cualquier usuario del host está permitido.

Permitir que cualquier usuario de host inicie sesión:


host +

Nota: esto es distinto del ejemplo anterior ya que no requiere una cuenta local coincidente.

Permitir que user desde host inicie sesión como cualquier usuario no root:


host user

Permitir que todos los usuarios de host con cuentas locales coincidentes inicien sesión, excepto baduser:


host -baduser
host

Denegar a todos los usuarios de host:


-host

Nota: el uso de -host -user nunca es una sintaxis válida, ni siquiera al intentar especificar que un usuario particular del host no es de confianza.

Permitir que todos los usuarios de un netgroup inicien sesión desde cualquier host con cuentas locales coincidentes:


+@netgroup

Denegar a todos los usuarios de un netgroup:


-@netgroup

Permitir que todos los usuarios de un netgroup inicien sesión desde host como cualquier usuario no root:


host +@netgroup

Permitir que todos los usuarios con cuentas locales coincidentes en todos los hosts de un netgroup, excepto baduser:


+@netgroup -baduser
+@netgroup

Nota: las sentencias de denegación siempre deben preceder a las sentencias de permiso porque el archivo se procesa secuencialmente hasta que se encuentra la primera regla coincidente.
