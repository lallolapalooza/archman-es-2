Descripción Detallada

El enlace de memoria se puede realizar de tres maneras:

  • asignación de memoria explícita gracias a hwloc_alloc_membind() y sus funciones relacionadas: el enlace tendrá efecto sobre la memoria asignada por estas funciones.
  • enlace de memoria implícito a través de la política de enlace: hwloc_set_membind() y sus funciones relacionadas solo definen la política actual del proceso, la cual se aplicará a las llamadas subsecuentes a malloc() y sus funciones relacionadas.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y sus funciones relacionadas, las cuales mueven datos ya asignados.

No todos los sistemas operativos soportan las tres formas. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente utilizado.

Cuando la operación de enlace solicitada no está disponible y se HWLOC_MEMBIND_STRICT fue pasado, la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema no soporte la acción o política especificada (por ejemplo, algunos sistemas solo permiten enlazar memoria por hilo, mientras que otros sistemas solo permiten enlazar memoria para todos los hilos en un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no pueda ser aplicado (por ejemplo, algunos sistemas solo permiten enlazar memoria a un solo nodo NUMA).

Si HWLOC_MEMBIND_STRICT no fue pasado, la función puede fallar también, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, un conjunto de enlace más pequeño, etc.) cuando la operación solicitada no esté exactamente soportada.

La forma más portable que debería preferirse sobre las demás siempre que sea posible es la siguiente. Asigna algo de memoria que se espera esté enlazada al conjunto especificado. Para hacerlo, hwloc posiblemente tendrá que cambiar la política de enlace de memoria actual para realmente obtener la memoria enlazada, si el SO no proporciona ninguna otra manera de asignar simplemente memoria enlazada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), la cual nunca cambiará la política de enlace de memoria actual.

hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0);

Cada función de enlace de memoria de hwloc toma un argumento bitmap que es un conjunto de CPU por defecto, o un conjunto de nodos de memoria NUMA si el flag HWLOC_MEMBIND_BYNODESET es especificado. Ver Conjuntos de Objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API de bitmap para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_nodeset().

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por conjunto de nodos debería preferirse siempre que sea posible.

Nota

En algunos sistemas operativos, el enlace de memoria afecta el enlace de CPU; ver HWLOC_MEMBIND_NOCPUBIND

Documentación del Tipo de Enumeración

enum hwloc_membind_flags_t

Flags de enlace de memoria. Estos flags pueden usarse para refinar la política de enlace. Todos los flags pueden combinarse lógicamente con OR con la excepción de HWLOC_MEMBIND_PROCESS y HWLOC_MEMBIND_THREAD; estos dos flags son mutuamente excluyentes.

No todos los sistemas soportan todos los tipos de enlace. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente utilizado. Ver la sección 'Descripción Detallada' de Enlace de memoria para una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_MEMBIND_PROCESS
Establece la política para todos los hilos del proceso especificado (posiblemente multihilo). Este flag es mutuamente excluyente con HWLOC_MEMBIND_THREAD.
HWLOC_MEMBIND_THREAD
Establece la política para un hilo específico del proceso actual. Este flag es mutuamente excluyente con HWLOC_MEMBIND_PROCESS.
HWLOC_MEMBIND_STRICT
Solicita enlace estricto del SO. La función fallará si el enlace no puede ser garantizado / completamente aplicado.

Este flag tiene significados ligeramente diferentes dependiendo con qué función se use.

HWLOC_MEMBIND_MIGRATE
Migra memoria ya asignada. Si la memoria no puede ser migrada y el HWLOC_MEMBIND_STRICT flag es pasado, se devolverá un error.
HWLOC_MEMBIND_NOCPUBIND
Evita cualquier efecto sobre el enlace de CPU. En algunos sistemas operativos, algunas funciones subyacentes de enlace de memoria también enlazan la aplicación a la(s) CPU correspondiente(s). Usar este flag hará que hwloc evite usar funciones del SO que podrían potencialmente afectar los enlaces de CPU. Nótese, sin embargo, que usar NOCPUBIND puede reducir el soporte general de enlace de memoria de hwloc. Específicamente: algunas de las funciones de enlace de memoria de hwloc pueden fallar con errno establecido en ENOSYS cuando se usan con NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considera el argumento bitmap como un conjunto de nodos. El argumento bitmap se considera un conjunto de nodos si este flag es dado, o un conjunto de CPU por defecto en caso contrario.

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. Por lo tanto, el enlace por conjunto de nodos debería preferirse siempre que sea posible.

enum hwloc_membind_policy_t

Política de enlace de memoria. Estas constantes se pueden utilizar para elegir la política de enlace. Solo se puede usar una política a la vez (es decir, los valores no se pueden combinar con OR).

No todos los sistemas soportan todos los tipos de enlace. hwloc_topology_get_support() puede usarse para consultar el soporte real de la política de enlace de memoria en el sistema operativo actualmente en uso. Vea la sección 'Descripción Detallada' de Enlace de memoria para una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_MEMBIND_DEFAULT
Restablece la política de asignación de memoria a la predeterminada del sistema. Dependiendo del sistema operativo, esto puede corresponder a HWLOC_MEMBIND_FIRSTTOUCH (Linux, FreeBSD), o HWLOC_MEMBIND_BIND (AIX, HP-UX, Solaris, Windows). Esta política nunca es devuelta por las funciones de obtención de membind. El argumento nodeset es ignorado.
HWLOC_MEMBIND_FIRSTTOUCH
Asigna cada página de memoria individualmente en el nodo NUMA local del hilo que la toca. El nodeset dado debería ser usualmente hwloc_topology_get_topology_nodeset() para que el hilo que la toca pueda ejecutarse y asignar en cualquier nodo del sistema.

En AIX, si el nodeset es más pequeño, las páginas se asignan localmente (si el nodo local está en el nodeset) o desde un nodo no local aleatorio (en caso contrario).

HWLOC_MEMBIND_BIND
Asigna memoria en los nodos especificados. El comportamiento real puede variar ligeramente entre sistemas operativos, especialmente cuando (algunos de) los nodos solicitados están llenos. En Linux, por defecto, se usa la política MPOL_PREFERRED_MANY (o MPOL_PREFERRED). Sin embargo, si también se proporciona el flag estricto de hwloc, se usa en su lugar la política MPOL_BIND de Linux.
HWLOC_MEMBIND_INTERLEAVE
Asigna memoria en los nodos dados de manera entrelazada / round-robin. El diseño preciso de la memoria a través de múltiples nodos NUMA es específico del sistema operativo/sistema. El entrelazado puede ser útil cuando hilos distribuidos a través de los nodos NUMA especificados accedan todos al rango completo de memoria simultáneamente, ya que el entrelazado equilibrará entonces las referencias de memoria.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
Asigna memoria en los nodos dados de manera entrelazada / ponderada. El diseño preciso de la memoria a través de múltiples nodos NUMA es específico del sistema operativo/sistema. El entrelazado ponderado puede ser útil cuando hilos distribuidos a través de los nodos NUMA especificados con diferentes capacidades de ancho de banda accedan todos al rango completo de memoria simultáneamente, ya que el entrelazado equilibrará entonces las referencias de memoria.
HWLOC_MEMBIND_NEXTTOUCH
Para cada página vinculada con esta política, la próxima vez que sea tocada (y solo la próxima vez), se mueve desde su ubicación actual al nodo NUMA local del hilo donde ocurrió la referencia de memoria (si necesita ser movida en absoluto).
HWLOC_MEMBIND_MIXED
Devuelta por las funciones get_membind() cuando múltiples hilos o partes de un área de memoria tienen políticas de enlace de memoria diferentes. También devuelta cuando el enlace es desconocido porque los hooks de enlace están vacíos cuando la topología se carga desde XML sin HWLOC_THISSYSTEM=1, etc.

Función Documentación

void * hwloc_alloc (hwloc_topology_t topology, size_t len)

Asigna algo de memoria. Esto es equivalente a malloc(), excepto que intenta asignar memoria alineada a páginas desde el sistema operativo.

Devuelve

un puntero al área asignada, o NULL en caso de error.

Nota

La memoria asignada debería liberarse con hwloc_free().

void * hwloc_alloc_membind (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Asigna algo de memoria en los nodos de memoria NUMA especificados por set.

Devuelve

un puntero al área asignada.

NULL con errno establecido a ENOSYS si la acción no es soportada y HWLOC_MEMBIND_STRICT es proporcionado.

NULL con errno establecido a EXDEV si el enlace no puede ser aplicado y HWLOC_MEMBIND_STRICT es proporcionado.

NULL con errno establecido a ENOMEM si la asignación de memoria falló incluso antes de intentar el enlace.

Si HWLOC_MEMBIND_BYNODESET es especificado, set se considera un nodeset. De lo contrario, es un cpuset.

Nota

La memoria asignada debería liberarse con hwloc_free().

void * hwloc_alloc_membind_policy (hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags) [inline]

Asigna algo de memoria en los nodos de memoria NUMA especificados por set. Primero, intenta asignar correctamente con hwloc_alloc_membind(). En caso de fallo, la política de enlace de memoria del proceso o hilo actual se cambia con hwloc_set_membind() antes de asignar memoria. Así, esta función funciona en más casos, a costa de cambiar el estado actual (posiblemente afectando asignaciones futuras que no especifiquen ninguna política).

Si HWLOC_MEMBIND_BYNODESET es especificado, set se considera un nodeset. De lo contrario, es un cpuset.

Devuelve

un puntero al área asignada, o NULL en caso de error.

int hwloc_free (hwloc_topology_t topology, void * addr, size_t len)

Libera memoria que fue previamente asignada por hwloc_alloc() o hwloc_alloc_membind().

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_get_area_membind (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Consulta las CPUs cerca del(los) nodo(s) NUMA físico(s) y la política de enlace de la memoria identificada por (addr, len ). El bitmap set (previamente asignado por el llamante) se rellena con el enlace del área de memoria.

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de los flags proporcionados como de las políticas de enlace de memoria y los nodesets de las páginas en el rango de direcciones.

Si HWLOC_MEMBIND_STRICT es especificado, las páginas objetivo se verifican primero para ver si todas tienen la misma política de enlace de memoria y nodeset. Si no es así, se devuelve -1 y errno se establece a EXDEV. Si son idénticas en todas las páginas, el set y la política se devuelven en set y policy, respectivamente.

Si HWLOC_MEMBIND_STRICT no es especificado, se calcula la unión de todos los nodo(s) NUMA que contienen páginas en el rango de direcciones. Si todas las páginas en el objetivo tienen la misma política, se devuelve en policy. De lo contrario, policy se establece a HWLOC_MEMBIND_MIXED.

Si HWLOC_MEMBIND_BYNODESET es especificado, set se considera un nodeset. De lo contrario, es un cpuset.

Si se especifican otros flags, se devuelve -1 y errno se establece a EINVAL.

Devuelve

0 en caso de éxito.

-1 con errno establecido a EINVAL si len es 0.

int hwloc_get_area_memlocation (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, int flags)

Obtiene los nodos NUMA donde la memoria identificada por (addr, len ) está asignada físicamente. El bitmap set (previamente asignado por el llamante) se rellena de acuerdo con los nodos NUMA donde las páginas del área de memoria están asignadas físicamente. Si ninguna página está realmente asignada todavía, set puede estar vacío.

Si las páginas se distribuyen en múltiples nodos, no se especifica si se distribuyen equitativamente, o si la mayoría de ellas están en un solo nodo, etc.

El sistema operativo puede mover páginas de memoria de un procesador a otro en cualquier momento de acuerdo con su enlace, por lo que esta función puede devolver algo que ya está obsoleto.

Si HWLOC_MEMBIND_BYNODESET se especifica en flags, el conjunto se considera un nodeset. De lo contrario, es un cpuset.

Si len es 0, el conjunto se vacía.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_get_membind (hwloc_topology_t topology, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Consulta la política de enlace de memoria predeterminada y la localización física del proceso o hilo actual. El mapa de bits set (previamente asignado por el llamante) se rellena con el enlace de memoria del proceso o hilo.

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de los flags pasados como de las políticas de enlace de memoria y los nodesets actuales en el objetivo consultado.

Pasar el flag HWLOC_MEMBIND_PROCESS especifica que el objetivo de la consulta son las políticas y nodesets actuales para todos los hilos del proceso actual. Pasar HWLOC_MEMBIND_THREAD especifica que el objetivo de la consulta es la política y el nodeset actuales solo para el hilo que invoca esta función.

Si no se pasa ninguno de estos flags (que es el método más portátil), se asume que el proceso es de un solo hilo. Esto permite que hwloc use funciones del SO basadas en el proceso o funciones del SO basadas en el hilo, dependiendo de cuáles estén disponibles.

HWLOC_MEMBIND_STRICT solo tiene sentido cuando HWLOC_MEMBIND_PROCESS también se especifica. En este caso, hwloc comprobará las políticas de memoria predeterminadas y los nodesets para todos los hilos del proceso. Si no son idénticos, se devuelve -1 y errno se establece a EXDEV. Si son idénticos, los valores se devuelven en set y policy.

De lo contrario, si HWLOC_MEMBIND_PROCESS se especifica (y HWLOC_MEMBIND_STRICT no se especifica), el conjunto predeterminado de cada hilo se combina lógicamente con una operación OR. Si todas las políticas predeterminadas de los hilos son la misma, policy se establece a esa política. Si son diferentes, policy se establece a HWLOC_MEMBIND_MIXED.

En el caso HWLOC_MEMBIND_THREAD (o cuando ni HWLOC_MEMBIND_PROCESS ni HWLOC_MEMBIND_THREAD se especifican), solo hay un conjunto y una política; se devuelven en set y policy, respectivamente.

Si HWLOC_MEMBIND_BYNODESET se especifica, set se considera un nodeset. De lo contrario, es un cpuset.

Si se especifican otros flags, se devuelve -1 y errno se establece a EINVAL.

Devuelve

0 en caso de éxito, -1 en caso de error.

int hwloc_get_proc_membind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Consulta la política de enlace de memoria predeterminada y la localización física del proceso especificado. El mapa de bits set (previamente asignado por el llamante) se rellena con el enlace de memoria del proceso.

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de los flags pasados como de las políticas de enlace de memoria y los nodesets actuales en el objetivo consultado.

Pasar el flag HWLOC_MEMBIND_PROCESS especifica que el objetivo de la consulta son las políticas y nodesets actuales para todos los hilos del proceso especificado. Si HWLOC_MEMBIND_PROCESS no se especifica (que es el método más portátil), se asume que el proceso es de un solo hilo. Esto permite que hwloc use funciones del SO basadas en el proceso o funciones del SO basadas en el hilo, dependiendo de cuáles estén disponibles.

Tenga en cuenta que no tiene sentido pasar HWLOC_MEMBIND_THREAD a esta función.

Si HWLOC_MEMBIND_STRICT se especifica, hwloc comprobará las políticas de memoria predeterminadas y los nodesets para todos los hilos del proceso especificado. Si no son idénticos, se devuelve -1 y errno se establece a EXDEV. Si son idénticos, los valores se devuelven en set y policy.

De lo contrario, set se establece al OR lógico de los conjuntos predeterminados de todos los hilos. Si todas las políticas predeterminadas de los hilos son la misma, policy se establece a esa política. Si son diferentes, policy se establece a HWLOC_MEMBIND_MIXED.

Si HWLOC_MEMBIND_BYNODESET se especifica, set se considera un nodeset. De lo contrario, es un cpuset.

Si se especifican otros flags, se devuelve -1 y errno se establece a EINVAL.

Devuelve

0 en caso de éxito, -1 en caso de error.

Nota

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

int hwloc_set_area_membind (hwloc_topology_t topology, const void * addr, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Enlaza la memoria ya asignada identificada por (addr, len) a los nodo(s) NUMA especificados por set. Si HWLOC_MEMBIND_BYNODESET se especifica, set se considera un nodeset. De lo contrario, es un cpuset.

Devuelve

0 en caso de éxito o si len es 0.

-1 con errno establecido a ENOSYS si la acción no está soportada.

-1 con errno establecido a EXDEV si el enlace no puede ser aplicado.

int hwloc_set_membind (hwloc_topology_t topology, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Establece la política de enlace de memoria predeterminada del proceso o hilo actual para preferir el(los) nodo(s) NUMA especificados por set. Si ni HWLOC_MEMBIND_PROCESS ni HWLOC_MEMBIND_THREAD se especifican, se asume que el proceso actual es de un solo hilo. Esta es la forma más portátil, ya que permite que hwloc use funciones del SO basadas en el proceso o funciones del SO basadas en el hilo, dependiendo de cuáles estén disponibles.

Si HWLOC_MEMBIND_BYNODESET se especifica, set se considera un nodeset. De lo contrario, es un cpuset.

Devuelve

0 en caso de éxito.

-1 con errno establecido a ENOSYS si la acción no está soportada.

-1 con errno establecido a EXDEV si el enlace no puede ser aplicado.

int hwloc_set_proc_membind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Establece la política de enlace de memoria predeterminada del proceso especificado para preferir el(los) nodo(s) NUMA especificados por set. Si HWLOC_MEMBIND_BYNODESET se especifica, set se considera un nodeset. De lo contrario, es un cpuset.

Devuelve

0 en caso de éxito.

-1 con errno establecido a ENOSYS si la acción no está soportada.

-1 con errno establecido a EXDEV si el enlace no puede ser aplicado.

Nota

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.
