void hwloc_topology_set_userdata_export_callback (hwloc_topology_t topology, void(*)(void *reserved, hwloc_topology_t topology, hwloc_obj_t obj)

export_cb)

Establece la función de retorno (callback) específica de la aplicación para exportar los datos específicos (userdata) de los objetos. El puntero de datos específicos del objeto no se exporta a XML de forma predeterminada porque hwloc no sabe qué

contiene.

Esta función permite a las aplicaciones establecer export_cb como una función de retorno que convierta estos datos opacos en una cadena

exportable.

export_cb se invoca durante la exportación XML para cada objeto cuyo puntero de datos específicos no es NULL. La función de retorno debe usar hwloc_export_obj_userdata() o hwloc_export_obj_userdata_base64() para exportar realmente algo a XML (posiblemente varias veces por objeto)

.

export_cb puede establecerse en NULL si los datos específicos no deben ser exportados a

XML.

void hwloc_topology_set_userdata_import_callback (hwloc_topology_t topology, void(*)(hwloc_topology_t topology, hwloc_obj_t obj, const char *name, const void *buffer, size_t length)

import_cb)

Establece la función de retorno (callback) específica de la aplicación para importar datos específicos (userdata). En la importación XML, los datos específicos se ignoran de forma predeterminada porque hwloc no sabe cómo almacenarlos en

memoria.

Esta función permite a las aplicaciones establecer import_cb como una función de retorno que recibirá los datos específicos almacenados en XML y los almacenará en el objeto como espera la

aplicación.

import_cb se llama durante hwloc_topology_load() tantas veces como hwloc_export_obj_userdata() fue llamada durante la exportación. La topología aún no está completamente configurada. Los atributos del objeto están listos para ser consultados, pero los enlaces entre objetos no lo

están.

import_cb puede ser NULL si los datos específicos deben ser ignorados durante la

importación.
