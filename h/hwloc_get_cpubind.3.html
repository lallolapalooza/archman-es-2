Descripción

detallada

Algunos sistemas operativos solo admiten el enlace de hilos o procesos a una sola PU. Otros permiten el enlace a conjuntos más grandes como Núcleos completos o Paquetes o incluso conjuntos aleatorios de PUs individuales. En tales sistemas operativos, el planificador es libre de ejecutar la tarea en una de estas PU, luego migrarla a otra PU, etc. A menudo es útil llamar a hwloc_bitmap_singlify() en el conjunto de CPU de destino antes de pasarlo a la función de enlace para evitar estas migraciones costosas. Consulte la documentación de hwloc_bitmap_singlify() para más

detalles.

Algunos sistemas operativos no proporcionan todos los mecanismos admitidos por hwloc para enlazar procesos, hilos, etc. hwloc_topology_get_support() puede usarse para consultar sobre el soporte real de enlace de CPU en el sistema operativo utilizado

actualmente.

Cuando la operación de enlace solicitada no está disponible y se pasó el indicador HWLOC_CPUBIND_STRICT, la función devuelve -1. errno se establece en ENOSYS cuando no es posible enlazar el tipo solicitado de objeto procesos/hilos. errno se establece en EXDEV cuando el conjunto de cpuset solicitado no puede aplicarse (p. ej., algunos sistemas solo permiten una CPU, y algunos otros sistemas solo permiten un nodo NUMA)

.

Si no se pasó HWLOC_CPUBIND_STRICT, la función puede fallar también, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de enlace más pequeño, etc.) cuando la operación solicitada no es exactamente

compatible.

La versión más portable que debería preferirse sobre las demás, siempre que sea posible, es la siguiente que solo enlaza el programa actual, asumiendo que es de un solo

hilo: 
hwloc_set_cpubind(topology, set, 0)
,

Si el programa puede ser multihilo, debería preferirse la siguiente para enlazar solo el hilo

actual: 
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD)
,

Documentación del tipo de

enumeración

enum hwloc_cpubind_flags_

t

Indicadores de enlace de proceso/hilo. Estos indicadores de bits pueden usarse para refinar la política de

enlace.

El valor predeterminado (0) es enlazar el proceso actual, asumiendo que es de un solo hilo, de manera no estricta. Esta es la forma más portable de enlazar ya que todos los sistemas operativos suelen

proporcionarla.

Not

a
No todos los sistemas admiten todos los tipos de enlace. Vea la sección 'Descripción detallada' de Enlace de CPU para una descripción de los errores que pueden
ocurrir.

Enumerador

HWLOC_CPUBIND_PROCESS
Enlazar todos los hilos del proceso actual (posiblemente)
multihilo.
HWLOC_CPUBIND_THREAD
Enlazar el hilo actual del proceso
actual.
HWLOC_CPUBIND_STRICT
Solicitar enlace estricto del SO. De forma predeterminada, cuando las CPU designadas están todas ocupadas mientras otras CPU están inactivas, los sistemas oper
ativos pueden ejecutar el hilo/proceso en esas otras CPU en lugar de las CPU designadas, para dejarlos avanzar de todos modos. El enlace estricto signif
ica que el hilo/proceso _nunca_ se ejecutará en otras CPU que las designadas, incluso cuando estén ocupadas con otras tareas y otras CPU estén inactivas.

Not

a
Dependiendo del sistema operativo, el enlace estricto puede no ser posible (p. ej., el SO no lo implementa) o no permitido (p. ej., por razones administrativas), y la función fallará en ese
caso.

Al recuperar el enlace de un proceso, este indicador verifica si todos sus hilos realmente tienen el mismo enlace. Si no se proporciona el indicador, el enlace de cada hilo se

acumulará.

Not

a
Este indicador es inútil al recuperar el enlace de un
hilo.
HWLOC_CPUBIND_NOMEMBIND
Evitar cualquier efecto en el enlace de memoria. En algunos sistemas operativos, algunas funciones de enlace de CPU también enlazarían la memoria en el nodo NUMA correspondiente. A menudo no es un problema para la aplicación, pero si lo es, establecer este indicador hará que hwloc evite usar funciones del SO que también enlazarían la memoria. Esto sin embargo reducirá el soporte de enlaces de CPU, es decir, potencialmente devolver -1 con errno establecido en ENOSYS en alg
