Descripción Detallada

Varias funciones pueden llamarse opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo debe realizarse la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

Documentación del Tipo de Enumeración

enum hwloc_topology_flags_e

Banderas que deben establecerse en un contexto de topología antes de la carga. Las banderas deben pasarse a hwloc_topology_set_flags(). También pueden ser devueltas por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detectar todo el sistema, ignorar reservas, incluir objetos no permitidos. Recopilar todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignorar Cgroup/Cpusets de Linux y recopilar todos los procesadores y nodos de memoria. Sin embargo, las UPs y nodos NUMA fuera de línea todavía son ignorados.

Cuando esta bandera no está establecida, las UPs y nodos NUMA que no están permitidos no se añaden a la topología. Los objetos padre (paquete, núcleo, caché, etc.) se añaden solo si algunos de sus hijos están permitidos. Todas las UPs y nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al cpuset y nodeset del objeto raíz.

Cuando esta bandera está establecida, los conjuntos reales de UPs y nodos NUMA permitidos son dados por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el cpuset y nodeset del objeto raíz.

Si la topología actual se exporta a XML y se vuelve a importar más tarde, esta bandera debe establecerse de nuevo en la topología reimportada para que los recursos no permitidos también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asumir que el backend seleccionado proporciona la topología del sistema en el que nos encontramos. Esto fuerza a hwloc_topology_is_thissystem() a devolver 1, es decir, hace que hwloc asuma que el backend seleccionado proporciona la topología del sistema en el que nos encontramos, incluso si no es el backend específico del OS, sino el backend XML, por ejemplo. Esto significa que las funciones de enlace realmente llaman a las llamadas al sistema específicas del OS y realmente realizan el enlace, mientras que el backend XML de otro modo proporcionaría hooks vacíos que solo devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto puede usarse por razones de eficiencia para detectar la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero teniendo aún así las funciones de enlace que realmente realicen el enlace.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtener el conjunto de recursos permitidos del sistema operativo local incluso si la topología se cargó desde XML o una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restringirla aplicando las restricciones del proceso actual como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente desde la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Esta bandera se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también esté establecida, ya que la topología cargada debe coincidir con la máquina subyacente de donde se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES resultaría en el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importar soporte desde la topología importada. Al importar una topología XML de una máquina remota, el enlace está deshabilitado por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Este deshabilitado también se marca poniendo ceros en los bits de características soportadas correspondientes reportados por hwloc_topology_get_support().

La bandera HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT realmente importa los bits de soporte de la máquina remota. También establece la bandera imported_support en el array de la struct hwloc_topology_misc_support . Si el XML importado no contenía información de soporte (el hwloc exportador es demasiado antiguo), esta bandera no se establece.

Tenga en cuenta que estas características soportadas solo son relevantes para la instalación de hwloc que realmente exportó la topología XML (puede variar con el sistema operativo, o con cómo se compiló hwloc).

Tenga en cuenta que establecer esta bandera sin embargo no habilita el enlace para la topología de hwloc importada localmente, solo reporta lo que el hwloc remoto y la máquina soportan.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
No considerar recursos fuera del enlace de CPU del proceso. Si el enlace del proceso está limitado a un subconjunto de núcleos, ignorar los otros núcleos

Flags

enum hwloc_topology_flags_e

Flags to be set by the user on topology_init() or topology_set_flags().

These flags modify the behavior of the topology discovery and loading process.

Enumerator

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
The topology is being discovered on the system where the program is currently running. This is the default.

This flag is implied by most options that require access to the system during discovery. It should not be set explicitly when using hwloc_topology_set_flags() unless the caller really wants to override the default behavior in combination with other flags.

HWLOC_TOPOLOGY_FLAG_WHOLE_SYSTEM
Discover the whole system topology, even if not all components are accessible to the current user. This requires root privileges on some systems.

This flag implies HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM.

HWLOC_TOPOLOGY_FLAG_SYNTHETIC
The topology is synthetic and should not be discovered by probing the system. The topology is defined by the user through the hwloc synthetic topology format.

This flag implies HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM.

HWLOC_TOPOLOGY_FLAG_ASSUME_LOCALITY
Assume that the system is local. This is useful for the NUMA memory policy discovery. If the system is not NUMA, the default policy will be returned for all memory.

This flag implies HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
When importing a topology from XML, also import the support information from the remote machine. If this flag is not set, the support information will reflect what is supported by the current system (i.e. by hwloc itself), not by the machine described in the XML file.

This flag implies HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING
Do not consider resources outside of the process CPU binding. If the binding of the process is limited to a subset of cores, ignore the other cores during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag especially tells the x86 backend to never temporarily rebind a thread on any excluded core. This is useful on Windows because such temporary rebinding can change the process binding. Another use-case is to avoid cores that would not be able to perform the hwloc discovery anytime soon because they are busy executing some high-priority real-time tasks.

If process CPU binding is not supported, the thread CPU binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_MEMBINDING
Do not consider resources outside of the process memory binding. If the binding of the process is limited to a subset of NUMA nodes, ignore the other NUMA nodes during discovery.

The resulting topology is identical to what a call to hwloc_topology_restrict() would generate, but this flag also prevents hwloc from ever touching other resources during the discovery.

This flag is meant to be used together with HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING when both cores and NUMA nodes should be ignored outside of the process binding.

If process memory binding is not supported, the thread memory binding is considered instead if supported, or the flag is ignored.

This flag requires HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM as well since binding support is required.

HWLOC_TOPOLOGY_FLAG_DONT_CHANGE_BINDING
Do not ever modify the process or thread binding during discovery. This flag disables all hwloc discovery steps that require a change of the process or thread binding. This currently only affects the x86 backend which gets entirely disabled.

This is useful when hwloc_topology_load() is called while the application also creates additional threads or modifies the binding.

This flag is also a strict way to make sure the process binding will not change to due thread binding changes on Windows (see HWLOC_TOPOLOGY_FLAG_RESTRICT_TO_CPUBINDING).

HWLOC_TOPOLOGY_FLAG_NO_DISTANCES
Ignore distances. Ignore distance information from the operating systems (and from XML) and hence do not use distances for grouping.
HWLOC_TOPOLOGY_FLAG_NO_MEMATTRS
Ignore memory attributes and tiers. Ignore memory attribues from the operating systems (and from XML) Hence also do not try to build memory tiers.
HWLOC_TOPOLOGY_FLAG_NO_CPUKINDS
Ignore CPU Kinds. Ignore CPU kind information from the operating systems (and from XML).

enum hwloc_type_filter_e

Type filtering flags. By default, most objects are kept (HWLOC_TYPE_FILTER_KEEP_ALL). Instruction caches, memory-side caches, I/O and Misc objects are ignored by default (HWLOC_TYPE_FILTER_KEEP_NONE). Group levels are ignored unless they bring structure (HWLOC_TYPE_FILTER_KEEP_STRUCTURE).

Note that group objects are also ignored individually (without the entire level) when they do not bring structure.

Enumerator

HWLOC_TYPE_FILTER_KEEP_ALL
Keep all objects of this type. Cannot be set for HWLOC_OBJ_GROUP (groups are designed only to add more structure to the topology).
HWLOC_TYPE_FILTER_KEEP_NONE
Ignore all objects of this type. The bottom-level type HWLOC_OBJ_PU, the HWLOC_OBJ_NUMANODE type, and the top-level type HWLOC_OBJ_MACHINE may not be ignored.
HWLOC_TYPE_FILTER_KEEP_STRUCTURE
Only ignore objects if their entire level does not bring any structure. Keep the entire level of objects if at least one of these objects adds structure to the topology. An object brings structure when it has multiple children and it is not the only child of its parent.

If all objects in the level are the only child of their parent, and if none of them has multiple children, the entire level is removed.

Cannot be set for I/O and Misc objects since the topology structure does not matter there.

HWLOC_TYPE_FILTER_KEEP_IMPORTANT
Only keep likely-important objects of the given type. It is only useful for I/O object types. For HWLOC_OBJ_PCI_DEVICE and HWLOC_OBJ_OS_DEVICE, it means that only objects of major/common kinds are kept (storage, network, OpenFabrics, CUDA, OpenCL, RSMI, NVML, and displays). Also, only OS devices directly attached on PCI (e.g. no USB) are reported. For HWLOC_OBJ_BRIDGE, it means that bridges are kept only if they have children.

This flag equivalent to HWLOC_TYPE_FILTER_KEEP_ALL for Normal, Memory and Misc types since they are likely important.

Get OR'ed flags of a topology. Get the OR'ed set of hwloc_topology_flags_e of a topology.

Note

const struct hwloc_topology_support * hwloc_topology_get_support (hwloc_topology_t restrict topology)

Retrieve the topology support. Each flag indicates whether a feature is supported. If set to 0, the feature is not supported. If set to 1, the feature is supported, but the corresponding call may still fail in some corner cases.

These features are also listed by hwloc-info --support

The reported features are what the current topology supports on the current machine. If the topology was exported to XML from another machine and later imported here, support still describes what is supported for this imported topology after import. By default, binding will be reported as unsupported in this case (see HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM).

Topology flag HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT may be used to report the supported features of the original remote machine instead. If it was successfully imported, imported_support will be set in the struct hwloc_topology_misc_support array.

Returns

A pointer to a support structure.

Note

The function cannot return NULL.

The returned pointer should not be freed, it belongs to the hwloc library.

This function may be called before or after hwloc_topology_load() but the support structure only contains valid information after.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Establece banderas OR'ed en la topología aún no cargada. Establece un conjunto de banderas OR'ed de hwloc_topology_flags_e en una topología que aún no se ha cargado.

Si esta función se llama varias veces, la última invocación borrará y reemplazará el conjunto de banderas que se estableció previamente.

Por defecto, no se establecen banderas (0).

Las banderas establecidas en una topología se pueden recuperar con hwloc_topology_get_flags().

Retorna

0 en caso de éxito.

-1 en caso de error, por ejemplo, si las banderas no son válidas.
