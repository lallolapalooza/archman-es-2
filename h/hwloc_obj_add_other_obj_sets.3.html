Documentación del Tipo de Enumeración

enum hwloc_allow_flags_e

Banderas a proporcionar a hwloc_topology_allow().

Enumerador

HWLOC_ALLOW_FLAG_ALL
Marcar todos los objetos como permitidos en la topología. cpuset y nođeset proporcionados a hwloc_topology_allow() deben ser NULL.
HWLOC_ALLOW_FLAG_LOCAL_RESTRICTIONS
Solo permitir objetos que estén disponibles para el proceso actual. La topología debe tener HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM para que el conjunto de recursos disponibles pueda obtenerse realmente del sistema operativo.

cpuset y nođeset proporcionados a hwloc_topology_allow() deben ser NULL.

HWLOC_ALLOW_FLAG_CUSTOM
Permitir un conjunto personalizado de objetos, proporcionado a hwloc_topology_allow() como cpuset y/o nodeset.

enum hwloc_restrict_flags_e

Banderas a proporcionar a hwloc_topology_restrict().

Enumerador

HWLOC_RESTRICT_FLAG_REMOVE_CPULESS
Eliminar todos los objetos que se convirtieron en sin CPU. Por defecto, solo se eliminan los objetos que no contienen ni PU ni memoria. Esta bandera no puede usarse con HWLOC_RESTRICT_FLAG_BYNODESET.
HWLOC_RESTRICT_FLAG_BYNODESET
Restringir por nodeset en lugar de conjunto de CPU. Solo mantener objetos cuyo nodeset esté incluido o parcialmente incluido en el conjunto dado. Esta bandera no puede usarse con HWLOC_RESTRICT_FLAG_REMOVE_CPULESS.
HWLOC_RESTRICT_FLAG_REMOVE_MEMLESS
Eliminar todos los objetos que se convirtieron en sin memoria. Por defecto, solo se eliminan los objetos que no contienen ni PU ni memoria. Esta bandera solo puede usarse con HWLOC_RESTRICT_FLAG_BYNODESET.
HWLOC_RESTRICT_FLAG_ADAPT_MISC
Mover objetos Misc a sus ancestros si sus padres se eliminan durante la restricción. Si esta bandera no está establecida, los objetos Misc se eliminan cuando sus padres se eliminan.
HWLOC_RESTRICT_FLAG_ADAPT_IO
Mover objetos de I/O a sus ancestros si sus padres se eliminan durante la restricción. Si esta bandera no está establecida, los dispositivos de I/O y los puentes se eliminan cuando sus padres se eliminan.

int hwloc_obj_add_other_obj_sets (hwloc_obj_t dst, hwloc_obj_t src)

Configurar los conjuntos de CPUs/nodos de un objeto mediante la operación OR con los conjuntos de otro objeto. Para cada conjunto de CPU o nodeset definido en src, asignar el conjunto correspondiente en dst y añadir src a él mediante la operación OR con los conjuntos.

Esta función es conveniente entre hwloc_topology_alloc_group_object() y hwloc_topology_insert_group_object(). Construye los conjuntos del nuevo Grupo que se insertará como un nuevo padre intermedio de varios objetos.

Retorna

0 en caso de éxito.

-1 con errno establecido en ENOMEM si alguna reasignación interna falló.

hwloc_obj_t hwloc_topology_alloc_group_object (hwloc_topology_t topology)

Asignar un objeto Grupo para insertar posteriormente con hwloc_topology_insert_group_object(). Esta función devuelve un nuevo objeto Grupo.

El llamador debe (al menos) inicializar sus conjuntos antes de insertar el objeto en la topología, vea hwloc_topology_insert_group_object(). O puede decidir no insertar y simplemente liberar el objeto grupo llamando hwloc_topology_free_group_object().

Retorna

El objeto asignado en caso de éxito.

NULL en caso de error.

Nota

Si se inserta exitosamente por hwloc_topology_insert_group_object(), el objeto se liberará cuando toda la topología se libere. Si la inserción falló (por ejemplo, NULL o conjuntos de CPU y nodos vacíos), se libera antes de devolver el error.

int hwloc_topology_allow (hwloc_topology_t restrict topology, hwloc_const_cpuset_t cpuset, hwloc_const_nodeset_t nodeset, unsigned long flags)

Cambiar los conjuntos de PUs y nodos NUMA permitidos en la topología. Esta función solo funciona si el HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED se estableció en la topología. No modifica ningún objeto, solo cambia los conjuntos devueltos por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset().

Es especialmente útil cuando se importa una topología desde otro proceso ejecutándose en un Linux Cgroup diferente.

flags debe establecerse en una de las banderas de hwloc_allow_flags_e.

Retorna

0 en caso de éxito, -1 en caso de error.

Nota

Eliminar objetos de una topología debería realizarse preferiblemente con hwloc_topology_restrict().

int hwloc_topology_free_group_object (hwloc_topology_t restrict topology, hwloc_obj_t group)

Liberar un objeto Grupo previamente asignado con hwloc_topology_alloc_group_object(). Esta función devuelve 0 en caso de éxito, o -1 con errno establecido en ENOMEM en caso de error.

Retorna

0 en caso de éxito, -1 con errno establecido en ENOMEM en caso de error.

int hwloc_topology_insert_group_object (hwloc_topology_t restrict topology, hwloc_obj_t group)

Insertar un objeto Grupo previamente asignado con hwloc_topology_alloc_group_object() en la topología. Esta función devuelve 0 en caso de éxito, o -1 con errno establecido en ENOMEM en caso de error.

Retorna

0 en caso de éxito, -1 con errno establecido en ENOMEM en caso de error.

int hwloc_topology_refresh (hwloc_topology_t restrict topology)

Recargar la topología para obtener información actualizada sobre los recursos disponibles. Esta función devuelve 0 en caso de éxito, o -1 con errno establecido en ENOMEM en caso de error.

Retorna

0 en caso de éxito, -1 con errno establecido en ENOMEM en caso de error.

hwloc_obj_t hwloc_topology_insert_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Añade más estructura a la topología añadiendo un grupo intermedio. El llamante debe primero asignar un nuevo objeto de Grupo con hwloc_topology_alloc_group_object(). Luego, debe configurar al menos uno de sus conjuntos de CPUs o nodos para especificar la ubicación final del Grupo en la topología. Luego, el objeto puede pasar a esta función para su inserción real en la topología.

El principal caso de uso para esta función es agrupar un subconjunto de hermanos entre la lista de hijos debajo de un único padre. Por ejemplo, si se agrupan 4 núcleos de un socket de 8 núcleos, la lista lógica de núcleos se reordenará para que los 4 agrupados sean consecutivos. Luego, si es necesario, se añade una nueva profundidad entre el padre y esos hijos, y se inserta el Grupo allí. Al final, los 4 núcleos agrupados ahora son hijos del Grupo, que los reemplaza como hijo del padre original.

En la práctica, los objetos agrupados se especifican mediante cpuset y/o nodeset, por ejemplo usando hwloc_obj_add_other_obj_sets() iterativamente. Por lo tanto, es posible agrupar objetos que no son hijos del mismo padre, por ejemplo algunos PUs debajo de los 4 núcleos del ejemplo anterior. Sin embargo, este caso general puede fallar si el Grupo esperado entra en conflicto con la jerarquía existente. Por ejemplo, si cada núcleo tiene dos PUs, no es posible insertar un Grupo que contenga un solo PU de cada núcleo.

Para especificar los objetos a agrupar, el campo cpuset o nodeset (o ambos, si son compatibles) debe establecerse en un bitmap no vacío. El complete_cpuset o complete_nodeset puede establecerse en su lugar si se inserta con respecto a la topología completa (incluyendo objetos prohibidos, desconectados o desconocidos). Estos conjuntos no pueden ser más grandes que la topología actual, o se restringirán silenciosamente. El núcleo configurará los otros conjuntos después de la inserción real.

El atributo de tipo de objeto subtype puede definirse con hwloc_obj_set_subtype() para mostrar algo distinto de 'Group' como el nombre de tipo para este objeto en lstopo. Pueden añadirse pares de información nombre-valor personalizados con hwloc_obj_add_info() después de la inserción.

El atributo group dont_merge puede establecerse en 1 para prevenir que el núcleo hwloc fusioné este objeto con otro objeto jerárquicamente idéntico. Esto es útil cuando el Grupo en sí describe una característica importante que no puede exponerse en ninguna otra parte de la jerarquía.

El atributo group kind puede establecerse en un valor alto, tal como 0xffffffff, para indicar a hwloc que este nuevo Grupo siempre debe ser descartado a favor de cualquier Grupo existente con la misma localidad.

Nota

Insertar un grupo añade cierta información de localidad a la topología, por lo que los objetos existentes pueden reordenarse (incluyendo PUs y nodos NUMA), y sus índices lógicos pueden cambiar.

Si la inserción falla, el objeto de grupo de entrada se libera.

Si el objeto de grupo debe descartarse en lugar de insertarse, puede pasarse a hwloc_topology_free_group_object() en su lugar.

topology debe ser el mismo que el que previamente se pasó a hwloc_topology_alloc_group_object().

Retorna

El objeto insertado si se insertó correctamente.

Un objeto existente si el Grupo se fusionó o descartó porque la topología ya contenía un objeto en la misma ubicación (el Grupo no añadió ninguna información jerárquica).

NULL si la inserción falló debido a conjuntos conflictivos en el árbol de topología.

NULL si los objetos de Grupo se filtran de la topología (HWLOC_TYPE_FILTER_KEEP_NONE).

NULL si el objeto se descartó porque no se inicializó ningún conjunto en el Grupo antes de la inserción, o todos estaban vacíos.

hwloc_obj_t hwloc_topology_insert_misc_object (hwloc_topology_t topology, hwloc_obj_t parent, const char * name)

Añade un objeto MISC como hoja de la topología. Se creará un nuevo objeto MISC y se insertará en la topología en la posición dada por parent. Se añade a la lista de hijos Misc existentes, sin añadir nunca ningún nivel intermedio de jerarquía. Esto es útil para anotar la topología sin cambiar realmente la jerarquía.

name se supone que es único entre todos los objetos Misc en la topología. Se duplicará para configurar los atributos del nuevo objeto.

El nuevo objeto hoja no tendrá ningún cpuset.

El atributo de tipo de objeto subtype puede definirse con hwloc_obj_set_subtype() después de la inserción exitosa.

Retorna

el objeto recién creado

NULL en caso de error.

NULL si los objetos Misc se filtran de la topología (HWLOC_TYPE_FILTER_KEEP_NONE).

Nota

Si name contiene algunos caracteres no imprimibles, se eliminarán al exportar a XML, véase hwloc_topology_export_xml() en hwloc/export.h.

int hwloc_topology_refresh (hwloc_topology_t topology)

Actualiza las estructuras internas después de modificar la topología. Modificar la topología (restringiendo, añadiendo objetos, modificando estructuras como distancias o atributos de memoria, etc.) puede hacer que algunas cachés internas se vuelvan inválidas. Estas cachés se actualizan automáticamente al acceder a ellas, pero esta actualización no es segura para hilos.

Esta función tampoco es segura para hilos, pero es una buena manera de terminar una fase no segura de modificación de topología. Una vez que se realiza esta actualización, múltiples hilos pueden consultar simultáneamente la topología, objetos, distancias, atributos, etc.

Retorna

0 en caso de éxito.

-1 en caso de error, por ejemplo si alguna realocación interna falló.

int hwloc_topology_restrict (hwloc_topology_t restrict topology, hwloc_const_bitmap_t set, unsigned long flags)

Restringe la topología al conjunto de CPUs o nodos dado. La topología topology se modifica para eliminar todos los objetos que no están incluidos (o parcialmente incluidos) en el conjunto de CPUs set. Todos los objetos de CPU y nodos se restringen en consecuencia.

Por defecto, set es un conjunto de CPUs. Esto significa que el conjunto de PUs en la topología se restringe. Una vez que algunos PUs se eliminan, sus padres también pueden eliminarse recursivamente si se vuelven sin hijos.

Si se pasa HWLOC_RESTRICT_FLAG_BYNODESET en flags, set se considera un nodeset en lugar de un conjunto de CPUs. Esto significa que el conjunto de nodos NUMA en la topología se restringe (en lugar de PUs). Una vez que algunos nodos NUMA se eliminan, sus padres también pueden eliminarse recursivamente si se vuelven sin hijos.

flags es un conjunto OR'ado de hwloc_restrict_flags_e.

Nota

Restringir la topología elimina cierta información de localidad, por lo que los objetos restantes pueden reordenarse (incluyendo PUs y nodos NUMA), y sus índices lógicos pueden cambiar.

Esta llamada no puede revertirse restringiendo de nuevo a un conjunto más grande. Una vez eliminados durante la restricción, los objetos pueden no ser recuperados, excepto cargando otra topología con hwloc_topology_load().

Retorna

0 en caso de éxito.

-1 con errno establecido en EINVAL si el conjunto de entrada es inválido. La topología no se modifica en este caso.

-1 con errno establecido en ENOMEM al fallar en asignar datos internos. La topología se reinicializa en este caso. Debe destruirse con hwloc_topology_destroy() o configurarse y cargarse de nuevo.
