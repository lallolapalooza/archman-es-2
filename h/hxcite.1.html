NOMBRE

hxcite - reemplaza referencias bibliográficas por hipervínculos

SINOPSIS

hxcite [ -b base ] [ -p patrón ] [ -a archivoaux ] [ -m marcador ] [ -c ] archivobib [ archivo ]

DESCRIPCIÓN

El comando hxcite copia el archivo a la salida estándar, buscando cadenas de la forma [[etiqueta]]. La etiqueta no puede incluir espacios en blanco y el doble par de corchetes debe encerrar la etiqueta sin espacios entre ellos. Si hxcite encuentra la etiqueta en el archivobib, la cadena se reemplaza por el patrón. El patrón puede incluir ciertas variables. Si la etiqueta no se encuentra en archivobib, se deja sin cambios.

El patrón predeterminado reemplaza la cadena con un hipervínculo, pero si se usa la opción -p, el reemplazo puede ser cualquier patrón. La entrada ni siquiera tiene que ser HTML.

Si la etiqueta está encerrada en {{...}} en lugar de [[...]], se copia a la salida sin cambios y no se reemplaza por el patrón, pero la etiqueta todavía se busca en el archivobib.

OPCIONES

Se admiten las siguientes opciones:

-p patrón
Especifica el patrón por el cual se reemplaza la cadena [[etiqueta]]. El patrón puede incluir las variables %b (que se reemplaza por el valor de la opción -b), %m (que se reemplaza por el valor de la opción -m) y %L (que se reemplaza por la etiqueta). El patrón predeterminado es 


<a href="%b#%L" rel="biblioentry">[%L]<!--{{%m%L}}--></a>
-b base
Establece el valor de la variable %b en el patrón. Típicamente, este valor es una URL relativa o absoluta. Por defecto, este valor es una cadena vacía.
-a archivoaux
Todas las etiquetas que se han encontrado y reemplazado también se escriben en un archivo. Esto es para que hxmkbib(1) pueda encontrarlas y crear una bibliografía. El archivoaux predeterminado se construye a partir del nombre del archivo, eliminando la última extensión (si la hay) y reemplazándola por ".aux". Si no se proporciona archivo, el nombre predeterminado es "aux.aux".
-m marcador
Por defecto, el programa busca "[[nombre]]", pero se puede hacer que busque "[[#nombre]]" donde # es alguna cadena, usualmente un símbolo como '!' o '='. Esto permite clasificar las referencias, por ejemplo, "[[!nombre]]" para referencias normativas y "[[nombre]]" para referencias no normativas.
-c
Hace que "[[nombre]]" se ignore cuando ocurre dentro de comentarios XML ("<!--...-->"). Esto es útil para archivos donde tales etiquetas ocurren en comentarios, para evitar que se expandan y posiblemente conduzcan a una salida inválida; también es útil si hxcite se utiliza para archivos que no son HTML y que pueden contener "<!--" que no son comentarios. Las ocurrencias de "{{nombre}}" no se ven afectadas por -c. (Pero véase la advertencia en BUGS a continuación).

OPERANDOS

Se admiten los siguientes operandos:

archivobib
Se debe proporcionar el nombre de una base de datos bibliográfica. Debe ser un archivo en formato refer(1) y cada entrada debe tener al menos un campo %L, que se utiliza como etiqueta. (Las entradas sin dicho campo serán ignoradas.) Las entradas pueden tener opcionalmente una línea %K, que debe contener palabras clave separadas por espacios. Esas palabras clave se pueden usar para referirse a la entrada en lugar de la etiqueta. Por lo tanto, el foo en [[foo]] puede ser la etiqueta de una entrada (línea %L) o una de las palabras clave de la línea %K de la entrada.
archivo
El nombre del archivo de entrada es opcional. Si está ausente, hxcite leerá desde la entrada estándar. El archivo no tiene que ser un archivo HTML, pero el patrón predeterminado (ver la opción -p) asume HTML.

ESTADO DE SALIDA

Se devuelven los siguientes valores de salida:

0
Finalización exitosa.
> 0
Ocurrió un error. Por lo general, esto se debe a que no se pudo abrir un archivo. Muy raramente, también puede ser un error de falta de memoria.

ERRORES

hxcite en realidad no analiza la entrada HTML o XML y la opción -c simplemente trata cada ocurrencia de "<!--" como el inicio de un comentario XML, incluso si ocurre dentro de un valor de atributo o una sección CDATA. Lo mismo ocurre con "-->" para el final de un comentario.

Actualmente no hay forma de utilizar números para las referencias (por ejemplo, "[1]", "[2]") en lugar de las etiquetas ("[Lie1996]", "[UTN22]").

hxcite requiere que el campo %L (etiqueta) esté presente en cada entrada de archivobib, lo cual no es el caso para refer(1). hxcite no implementa la búsqueda de palabras clave de refer.

EJEMPLO

Lo siguiente busca referencias de la forma "[[!etiqueta]]" en "myfile.html", omitiendo las referencias que ocurren dentro de comentarios HTML, y busca las etiquetas en "biblio.ref". La salida se escribe en "new.html" y la lista de etiquetas reconocidas en "myfile.aux".


hxcite -c -m '!' biblio.ref myfile.html > new.html
