Descripción Detallada

Estas funciones se utilizan para compartir una topología entre procesos duplicándola en un búfer de memoria compartida respaldado por un archivo.

El proceso maestro debe primero obtener el tamaño de memoria compartida requerido para almacenar esta topología con hwloc_shmem_topology_get_length().

Luego debe encontrar un área de memoria virtual de ese tamaño que esté disponible en todos los procesos (direcciones virtuales idénticas en todos los procesos). En Linux, esto se puede hacer comparando los huecos encontrados en /proc/<pid>/maps para cada proceso.

Una vez encontrado, debe abrir un archivo de destino para almacenar el búfer y pasarlo a hwloc_shmem_topology_write() junto con la dirección de memoria virtual y la longitud obtenidas anteriormente.

Otros procesos pueden entonces adoptar esta topología compartida abriendo el mismo archivo y pasándolo a hwloc_shmem_topology_adopt() con la dirección de memoria virtual y la longitud exactas.

int hwloc_shmem_topology_adopt (hwloc_topology_t * topologyp, int fd, hwloc_uint64_t fileoffset, void * mmap_address, size_t length, unsigned long flags)

Adoptar una topología de memoria compartida almacenada en un archivo. Mapear un archivo en memoria virtual y adoptar la topología que se almacenó previamente allí con hwloc_shmem_topology_write().

La topología adoptada devuelta en topologyp se puede usar como cualquier topología. Y debe destruirse conhwloc_topology_destroy() como siempre.

Sin embargo, la topología es de solo lectura. Por ejemplo, no se puede modificar con hwloc_topology_restrict() y los punteros de datos de usuario de objetos no se pueden cambiar.

El segmento del archivo señalado por el descriptor fd, comenzando en el desplazamiento fileoffset, y de longitud length (en bytes), se mapeará en la dirección virtual mmap_address.

El archivo señalado por el descriptor fd, el desplazamiento fileoffset, la dirección de memoria virtual solicitada mmap_address y la longitud length deben ser idénticos a lo que se dio a hwloc_shmem_topology_write() anteriormente.

Nota

Los flags flags actualmente no se utilizan, deben ser 0.

El puntero de datos de usuario del objeto no debe usarse a menos que el proceso que creó la topología compartida también haya colocado búferes apuntados por datos de usuario en memoria compartida.

Esta función se encarga de llamar a hwloc_topology_abi_check().

Devuelve

0 si tiene éxito.

-1 con errno establecido en EBUSY si el mapeo de memoria virtual definido por mmap_address y length no está disponible en el proceso.

-1 con errno establecido en EINVAL si fileoffset, mmap_address o length no están alineados en páginas, o no coinciden con lo que se dio a hwloc_shmem_topology_write() anteriormente.

-1 con errno establecido en EINVAL si el diseño de la estructura de topología es diferente entre el proceso escritor y el proceso adoptador.

int hwloc_shmem_topology_get_length (hwloc_topology_t topology, size_t * lengthp, unsigned long flags)

Obtener la longitud requerida de memoria compartida para almacenar una topología. Esta longitud (en bytes) debe usarse en hwloc_shmem_topology_write() y hwloc_shmem_topology_adopt() más adelante.

Devuelve

la longitud, o -1 si hay un error, por ejemplo, si los flags no son válidos.

Nota

Los flags flags actualmente no se utilizan, deben ser 0.

int hwloc_shmem_topology_write (hwloc_topology_t topology, int fd, hwloc_uint64_t fileoffset, void * mmap_address, size_t length, unsigned long flags)

Duplicar una topología a un archivo de memoria compartida. Mapear temporalmente un archivo en memoria virtual y duplicar la topología topology asignando duplicados allí.

El segmento del archivo señalado por el descriptor fd, comenzando en el desplazamiento fileoffset, y de longitud length (en bytes), se mapeará temporalmente en la dirección virtual mmap_address durante la duplicación.

La longitud del mapeo length debe haber sido obtenida previamente con hwloc_shmem_topology_get_length() y la topología no debe haber sido modificada mientras tanto.

Nota

Los flags flags actualmente no se utilizan, deben ser 0.

El puntero de datos de usuario del objeto se duplica pero el búfer apuntado no. Sin embargo, el llamador también puede asignarlo manualmente en memoria compartida para compartirlo también.

Devuelve

0 si tiene éxito.

-1 con errno establecido en EBUSY si el mapeo de memoria virtual definido por mmap_address y length no está disponible en el proceso.

-1 con errno establecido en EINVAL si fileoffset, mmap_address o length no están alineados en páginas.
