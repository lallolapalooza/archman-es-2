DESCRIPCIÓN

Hivex es una biblioteca para extraer el contenido de los archivos "hive" del Registro de Windows. Está diseñada para ser segura contra archivos de registro erróneos o maliciosos.

A diferencia de otras herramientas en esta área, no utiliza el formato textual .REG, porque analizarlo es tan problemático como analizar el formato binario original. En su lugar, hace que el archivo esté disponible a través de una API C, y luego envuelve esta API en herramientas de scripting y GUI de nivel superior.

Hay un programa separado para exportar el hive como XML (ver hivexml(1)), o para navegar por el archivo (ver hivexsh(1)). También hay un script de Perl para exportar y fusionar el archivo como un archivo .REG (regedit) textual, ver hivexregedit(1).

Si solo quieres exportar o modificar el Registro de una máquina virtual de Windows, deberías mirar virt-win-reg(1).

Hivex también viene con enlaces de idioma para OCaml, Perl, Python y Ruby.

TIPOS

"hive_h *"

Este manejador describe un archivo hive abierto.

"hive_node_h"

Este es un manejador de nodo, un entero pero opaco fuera de la biblioteca. Los manejadores de nodo válidos no pueden ser 0. La biblioteca devuelve 0 en algunas situaciones para indicar un error.

"hive_type"

El siguiente enum describe los tipos posibles para los valores almacenados en cada nodo. Nota: no debes confiar en el campo de tipo en un Registro de Windows, ya que muy a menudo no tiene relación con la realidad. Algunas aplicaciones utilizan sus propios tipos. La codificación de cadenas no está especificada. Algunos programas almacenan todo (incluidas las cadenas) en blobs binarios.

 enum hive_type {
   /* Solo una clave sin valor */
   hive_t_REG_NONE = 0,
   /* Una cadena de Windows (codificación desconocida, pero a menudo UTF16-LE) */
   hive_t_REG_SZ = 1,
   /* Una cadena de Windows que contiene %env% (expansión de variable de entorno) */
   hive_t_REG_EXPAND_SZ = 2,
   /* Un blob binario */
   hive_t_REG_BINARY = 3,
   /* DWORD (entero de 32 bits), little-endian */
   hive_t_REG_DWORD = 4,
   /* DWORD (entero de 32 bits), big-endian */
   hive_t_REG_DWORD_BIG_ENDIAN = 5,
   /* Enlace simbólico a otra parte del árbol del registro */
   hive_t_REG_LINK = 6,
   /* Múltiples cadenas de Windows. Ver http://blogs.msdn.com/oldnewthing/archive/2009/10/08/9904646.aspx */
   hive_t_REG_MULTI_SZ = 7,
   /* Lista de recursos */
   hive_t_REG_RESOURCE_LIST = 8,
   /* Descriptor de recursos */
   hive_t_REG_FULL_RESOURCE_DESCRIPTOR = 9,
   /* Lista de requisitos de recursos */
   hive_t_REG_RESOURCE_REQUIREMENTS_LIST = 10,
   /* QWORD (entero de 64 bits), endianness no especificada pero generalmente little-endian */
   hive_t_REG_QWORD = 11,
};

"hive_value_h"

Este es un manejador de valor, un entero pero opaco fuera de la biblioteca. Los manejadores de valor válidos no pueden ser 0. La biblioteca devuelve 0 en algunas situaciones para indicar un error.

"hive_set_value"

El typedef "hive_set_value" se usa junto con la llamada "hivex_node_set_values" descrita a continuación.

struct hive_set_value {
  char *key;     /* clave - una cadena ASCIIZ codificada en UTF-8 */
  hive_type t;   /* tipo del campo de valor */
  size_t len;    /* longitud del campo de valor en bytes */
  char *value;   /* campo de valor */
};
typedef struct hive_set_value hive_set_value;

Para establecer el valor predeterminado de un nodo, tienes que pasar "key = """.

Nota que el campo "value" se trata simplemente como una lista de bytes y se almacena directamente en el hive. El llamador debe asegurar la codificación y el endianness correctos, por ejemplo, convirtiendo dwords a little-endian.

El tipo y la codificación correctos para los valores dependen del nodo y la clave en el registro, la versión de Windows y, a veces, incluso cambian entre versiones de Windows para la misma clave. No lo documentamos aquí. A menudo no se documenta en absoluto.

FUNCIONES

hivex_open

hive_h *hivex_open (const char *filename, int flags);

Abre el hive llamado "filename" para lectura.

Flags es una lista ORed de las banderas de apertura (o 0 si no quieres pasar ninguna bandera). Estas banderas se definen:

HIVEX_OPEN_VERBOSE
Mensajes detallados.
HIVEX_OPEN_DEBUG
Mensajes muy detallados, adecuados para depurar problemas en la propia biblioteca.

Esto también se selecciona si la variable de entorno "HIVEX_DEBUG" está establecida a 1.

HIVEX_OPEN_WRITE
Abre el hive para escritura. Si se omite, el hive es de solo lectura.

Ver "ESCRIBIR EN ARCHIVOS HIVE" en hivex(3).

HIVEX_OPEN_UNSAFE
Abre el hive en modo inseguro que habilita heurísticas para manejar hives corruptos.

Esto puede permitir leer o escribir claves/valores del registro que parezcan intactos en un hive corrupto. Úsalo bajo tu propio riesgo.

Devuelve un nuevo manejador de hive. En caso de error devuelve NULL y establece errno.

hivex_close

int hivex_close (hive_h *h);

Cierra un manejador de hive y libera todos los recursos asociados.

Nota que cualquier escritura no confirmada *no* se confirma con esta llamada, sino que se pierde. Ver "ESCRIBIR EN ARCHIVOS HIVE" en hivex(3).

Devuelve 0 en caso de éxito. En caso de error devuelve -1 y establece errno.

Esta functi

on libera el manejador del hive (incluso si devuelve un error). El manejador del hive no debe ser utilizado de nuevo después de llamar a esta función.

hivex_node_name

char *hivex_node_name (hive_h *h, hive_node_h node);

Devuelve el nombre del nodo.

Tenga en cuenta que el nombre del nodo raíz es un marcador de posición, como "$$$PROTO.HIV" (son posibles otros nombres: parece depender de la herramienta o programa que creó el hive en primer lugar). Solo puede conocer el nombre "real" del nodo raíz sabiendo de qué archivo de registro proviene originalmente este hive, lo cual es un conocimiento que está fuera del alcance de esta biblioteca.

El nombre se recodifica a UTF-8 y puede contener caracteres NUL incrustados.

Devuelve una cadena. La cadena debe ser liberada por el llamador cuando ya no sea necesaria. En caso de error, devuelve NULL y establece errno.

hivex_value_key_len

size_t hivex_value_key_len (hive_h *h, hive_value_h val);

Devuelve la longitud de la clave (nombre) de un par (clave, valor) tal como lo produce "hivex_value_key". La longitud puede ser legítimamente 0, por lo que errno es el mecanismo necesario para comprobar errores.

WRITING TO HIVE FILES

The hivex library supports making limited modifications to hive files. We have tried to implement this very conservatively in order to reduce the chance of corrupting your registry. However you should be careful and take back-ups, since Microsoft has never documented the hive format, and so it is possible there are nuances in the reverse-engineered format that we do not understand.

To be able to modify a hive, you must pass the "HIVEX_OPEN_WRITE" flag to "hivex_open", otherwise any write operation will return with errno "EROFS".

The write operations shown below do not modify the on-disk file immediately. You must call "hivex_commit" in order to write the changes to disk. If you call "hivex_close" without committing then any writes are discarded.

Hive files internally consist of a "memory dump" of binary blocks (like the C heap), and some of these blocks can be unused. The hivex library never reuses these unused blocks. Instead, to ensure robustness in the face of the partially understood on-disk format, hivex only allocates new blocks after the end of the file, and makes minimal modifications to existing structures in the file to point to these new blocks. This makes hivex slightly less disk-efficient than it could be, but disk is cheap, and registry modifications tend to be very small.

When deleting nodes, it is possible that this library may leave unreachable live blocks in the hive. This is because certain parts of the hive disk format such as security (sk) records and big data (db) records and classname fields are not well understood (and not documented at all) and we play it safe by not attempting to modify them. Apart from wasting a little bit of disk space, it is not thought that unreachable blocks are a problem.

WRITE OPERATIONS WHICH ARE NOT SUPPORTED

  • Changing the root node.
  • Creating a new hive file from scratch. This is impossible at present because not all fields in the header are understood. In the hivex source tree is a file called "images/minimal" which could be used as the basis for a new hive (but caveat emptor).
  • Modifying or deleting single values at a node.
  • Modifying security key (sk) records or classnames. Previously we did not understand these records. However now they are well-understood and we could add support if it was required (but nothing much really uses them).

VISITING ALL NODES

The visitor pattern is useful if you want to visit all nodes in the tree or all nodes below a certain point in the tree.

First you set up your own "struct hivex_visitor" with your callback functions.

Each of these callback functions should return 0 on success or -1 on error. If any callback returns -1, then the entire visit terminates immediately. If you don't need a callback function at all, set the function pointer to NULL.

struct hivex_visitor {
  int (*node_start) (hive_h *, void *opaque, hive_node_h, const char *name);
  int (*node_end) (hive_h *, void *opaque, hive_node_h, const char *name);
  int (*value_string) (hive_h *, void *opaque, hive_node_h, hive_value_h,
        hive_type t, size_t len, const char *key, const char *str);
  int (*value_multiple_strings) (hive_h *, void *opaque, hive_node_h,
        hive_value_h, hive_type t, size_t len, const char *key, char **argv);
  int (*value_string_invalid_utf16) (hive_h *, void *opaque, hive_node_h,
        hive_value_h, hive_type t, size_t len, const char *key,
        const char *str);
  int (*value_dword) (hive_h *, void *opaque, hive_node_h, hive_value_h,
        hive_type t, size_t len, const char *key, int32_t);
  int (*value_qword) (hive_h *, void *opaque, hive_node_h, hive_value_h,
        hive_type t, size_t len, const char *key, int64_t);
  int (*value_binary) (hive_h *, void *opaque, hive_node_h, hive_value_h,
        hive_type t, size_t len, const char *key, const char *value);
  int (*value_none) (hive_h *, void *opaque, hive_node_h, hive_value_h,
        hive_type t, size_t len, const char *key, const char *value);
  int (*value_other) (hive_h *, void *opaque, hive_node_h, hive_value_h,
        hive_type t, size_t len, const char *key, const char *value);
  int (*value_any) (hive_h *, void *opaque, hive_node_h, hive_value_h,
        hive_type t, size_t len, const char *key, const char *value);
};
hivex_visit
int hivex_visit (hive_h *h, const struct hivex_visitor *visitor, size_t len, void *opaque, int flags);

Visit all the nodes recursively in

la colmena "h".

"visitante" debe ser una "hivex_visitor" estructura con campos de devolución de llamada completados según sea necesario (las devoluciones de llamada no deseadas pueden establecerse en NULL). "len" debe ser la longitud de la estructura 'visitor' (debería pasar "sizeof (struct hivex_visitor)" para esto).

Esto devuelve 0 si toda la visita recursiva se completó correctamente. En caso de error devuelve -1. Si una de las funciones de devolución de llamada devolvió un error, no tocamos errno. Si el error se generó internamente, entonces establecemos errno.

Puede omitir entradas de registro defectuosas estableciendo "flag" en "HIVEX_VISIT_SKIP_BAD". Si esta bandera no está establecida, entonces un registro defectuoso hace que la función devuelva un error inmediatamente.

Esta función es robusta si el registro contiene ciclos o punteros que son inválidos o están fuera del registro. Detecta estos casos y devuelve un error.

LA ESTRUCTURA DEL REGISTRO DE WINDOWS

Nota: Para entender la relación entre las colmenas y las claves comunes del Registro de Windows (como "HKEY_LOCAL_MACHINE") por favor consulte la página de Wikipedia sobre el Registro de Windows.

El Registro de Windows está dividido en varios archivos binarios, cada archivo siendo conocido como una "colmena". Esta biblioteca solo maneja un único archivo de colmena a la vez.

Las colmenas son árboles n-arios con una única raíz. Cada nodo en el árbol tiene un nombre.

Cada nodo en el árbol (incluyendo nodos que no son hojas) puede tener una lista arbitraria de pares (clave, valor) adjunta a él. Puede ser el caso que uno de estos pares tenga una clave vacía. Esto se conoce como la clave predeterminada para el nodo.

Los pares (clave, valor) son el lugar donde se almacenan los datos útiles en el registro. La clave es siempre una cadena de texto (posiblemente la cadena vacía para la clave predeterminada). El valor es un objeto con tipo (por ejemplo, cadena, int32, binario, etc.).

RELACIÓN CON LOS ARCHIVOS .REG

La biblioteca C de hivex no se preocupa ni trata con los archivos .REG de Windows. En su lugar, empujamos esta complejidad hacia arriba a la biblioteca Perl Win::Hivex(3) y los programas Perl hivexregedit(1) y virt-win-reg(1). Sin embargo, es útil ver la relación entre el Registro y los archivos .REG porque son tan comunes.

Un archivo .REG es una representación textual del registro, o parte del registro. Las colmenas de registro reales que usa Windows son archivos binarios. Hay un número de herramientas de Windows y Linux que le permiten generar archivos .REG, o fusionar archivos .REG de vuelta en las colmenas de registro. Destacando entre ellas está el programa REGEDIT de Microsoft (anteriormente conocido como REGEDT32).

Un archivo .REG típico contendrá muchas secciones que se ven así:

[HKEY_LOCAL_MACHINE\SOFTWARE\Classes\Stack]
"@"="Generic Stack"
"TileInfo"="prop:System.FileCount"
"TilePath"=str(2):"%systemroot%\\system32"
"ThumbnailCutoff"=dword:00000000
"FriendlyTypeName"=hex(2):40,00,25,00,53,00,79,00,73,00,74,00,65,00,6d,00,52,00,6f,00,\
 6f,00,74,00,25,00,5c,00,53,00,79,00,73,00,74,00,65,00,6d,00,\
 33,00,32,00,5c,00,73,00,65,00,61,00,72,00,63,00,68,00,66,00,\
 6f,00,6c,00,64,00,65,00,72,00,2e,00,64,00,6c,00,6c,00,2c,00,\
 2d,00,39,00,30,00,32,00,38,00,00,00,d8

Tomando esta pieza una a la vez:

[HKEY_LOCAL_MACHINE\SOFTWARE\Classes\Stack]

Esta es la ruta hacia este nodo en el árbol del registro. La primera parte, "HKEY_LOCAL_MACHINE\SOFTWARE" significa que esto proviene de un archivo de colmena llamado "C:\WINDOWS\SYSTEM32\CONFIG\SOFTWARE". "\Classes\Stack" es la parte de la ruta real, comenzando en el nodo raíz de la "SOFTWARE" colmena.

Debajo del nombre del nodo hay una lista de cero o más pares clave-valor. Cualquier nodo interior o hoja en el registro puede tener pares clave-valor adjuntos.

"@"="Generic Stack"

Esta es la "clave predeterminada". En realidad (es decir, dentro de la colmena binaria) la cadena de clave es la cadena vacía. En los archivos .REG esto se escribe como "@" pero esto no tiene significado ni en las colmenas mismas ni en esta biblioteca. El valor es una cadena de texto (tipo 1 - ver "enum hive_type" arriba).

"TileInfo"="prop:System.FileCount"

Este es un par (clave, valor) regular, con el valor siendo una cadena de tipo 1. Note que dentro del archivo binario la cadena probablemente está codificada en UTF-16LE. Esta biblioteca convierte a y desde cadenas UTF-8 de manera transparente en algunos casos.

"TilePath"=str(2):"%systemroot%\\system32"

El valor en este caso tiene tipo 2 (cadena expandida) lo que significa que algunas variables %...% son expandidas por Windows. (Esta biblioteca no conoce ni se preocupa por la expansión de variables).

"ThumbnailCutoff"=dword:00000000

El valor en este caso es un dword (tipo 4).

"FriendlyTypeName"=hex(2):40,00,....

Este valor es una cadena expandida (tipo 2) representada en el archivo .REG como una serie de bytes hexadecimales. En este caso la cadena parece ser una cadena UTF-16LE.

NOTA SOBRE EL USO DE ERRNO

Muchas funciones en esta biblioteca establecen errno para indicar errores. Estos son los valores de errno que puede encontrar (esta lista no es exhaustiva):

ENOTSUP
Formato de archivo de Registro corrupto o no soportado.
HIVEX_NO_KEY
Falta la clave raíz.
EINVAL
Se pasó un argumento inválido a la función.
EFAULT
Se siguió un puntero de Registro que va fuera del registro o fuera de un bloque de registro.
ELOOP
El registro contiene ciclos.
ERANGE
Campo en el registro fuera de rango.
EEXIST
La clave de registro ya existe.
EROFS
Se intentó escribir en un registro que no está abierto para escritura.
