Documentación de Tipos

This section provides details on the different hardware object types that hwloc can represent.

HWLOC_OBJ_MACHINE
The machine object. Represents the entire machine, which is the root of the topology tree. It is the only object that is guaranteed to exist and that has no parent.
HWLOC_OBJ_NODE
A NUMA node. This object represents a group of processors and memory that are close to each other. This object is often used to represent the processor and memory locality within a machine.
HWLOC_OBJ_SOCKET
A physical package or socket. This object represents a physical package on the motherboard, which may contain one or more processor cores.
HWLOC_OBJ_CORE
A processor core. This object represents a single core within a physical package. A core may be capable of executing multiple threads simultaneously (e.g., through SMT/Hyper-Threading).
HWLOC_OBJ_PU
A Processing Unit (PU). This object represents a single thread of execution within a core. If a core supports SMT/Hyper-Threading, it will have multiple PUs.
HWLOC_OBJ_GROUP
Group objects. Objects that do not fit into the above categories but are detected by hwloc and are useful for affinity. For example, some operating systems expose their arbitrary processor aggregations this way. hwloc may also insert these objects to group NUMA nodes according to their distances. See also What are these Group objects in my topology?. These objects are removed when they do not provide any structure (see HWLOC_TYPE_FILTER_KEEP_STRUCTURE).
HWLOC_OBJ_cache
Generic cache object. This is a generic type for any cache, regardless of its level.
HWLOC_OBJ_L1CACHE
Level 1 data Cache.
HWLOC_OBJ_L2CACHE
Level 2 data Cache.
HWLOC_OBJ_L3CACHE
Level 3 data Cache.
HWLOC_OBJ_L4CACHE
Level 4 data Cache.
HWLOC_OBJ_L5CACHE
Level 5 data (or Unified) Cache.
HWLOC_OBJ_L1ICACHE
Level 1 instruction Cache (filtrado por defecto).
HWLOC_OBJ_L2ICACHE
Level 2 instruction Cache (filtrado por defecto).
HWLOC_OBJ_L3ICACHE
Level 3 instruction Cache (filtrado por defecto).
HWLOC_OBJ_NUMANODE
Nodo NUMA. Un objeto que contiene memoria que es directamente accesible por bytes para los procesadores del host. Usualmente está cerca de algunos núcleos (los objetos correspondientes son descendientes del objeto de nodo NUMA en el árbol de hwloc). Este es el objeto más pequeño que representa recursos de memoria, no puede tener hijos excepto objetos Misc. Sin embargo, puede tener padres de caché del lado de la memoria.

Los nodos NUMA pueden corresponder a diferentes tipos de memoria (DRAM, HBM, CXL-DRAM, etc.). Cuando hwloc puede adivinar ese tipo, se especifica en el campo subtype del objeto. Ver también Atributos normales en la documentación principal.

Siempre existe al menos un objeto de este tipo en la topología, incluso si la máquina no es NUMA.

Los objetos de memoria no se listan en la lista principal de hijos, sino en la lista dedicada de hijos de memoria.

Los nodos NUMA tienen una profundidad especial HWLOC_TYPE_DEPTH_NUMANODE en lugar de una profundidad normal, al igual que otros objetos en el árbol principal.

HWLOC_OBJ_BRIDGE
Puente (filtrado por defecto). Cualquier puente (o switch PCI) que conecta el host o un bus de E/S a otro bus de E/S. Los puentes no se añaden a la topología a menos que se cambie su filtrado (ver hwloc_topology_set_type_filter() y hwloc_topology_set_io_types_filter()).

Los objetos de E/S no se listan en la lista principal de hijos, sino en la lista dedicada de hijos de E/S. Los objetos de E/S tienen conjuntos de CPU y nodos NULL.

HWLOC_OBJ_PCI_DEVICE
Dispositivo PCI (filtrado por defecto). Los dispositivos PCI no se añaden a la topología a menos que se cambie su filtrado (ver hwloc_topology_set_type_filter() y hwloc_topology_set_io_types_filter()).

Los objetos de E/S no se listan en la lista principal de hijos, sino en la lista dedicada de hijos de E/S. Los objetos de E/S tienen conjuntos de CPU y nodos NULL.

HWLOC_OBJ_OS_DEVICE
Dispositivo del sistema operativo (filtrado por defecto). Los dispositivos del SO no se añaden a la topología a menos que se cambie su filtrado (ver hwloc_topology_set_type_filter() y hwloc_topology_set_io_types_filter()).

Los objetos de E/S no se listan en la lista principal de hijos, sino en la lista dedicada de hijos de E/S. Los objetos de E/S tienen conjuntos de CPU y nodos NULL.

HWLOC_OBJ_MISC
Objetos varios (filtrado por defecto). Objetos sin significado particular, que pueden ser añadidos por la aplicación para su propio uso, o por hwloc para objetos varios como Módulos de Memoria (DIMMs). No se añaden a la topología a menos que se cambie su filtrado (ver hwloc_topology_set_type_filter()).

Estos objetos no se listan en la lista principal de hijos, sino en la lista dedicada de hijos varios. Los objetos varios solo pueden tener objetos varios como hijos, y estos también están en la lista dedicada de hijos varios. Los objetos varios tienen conjuntos de CPU y nodos NULL.

HWLOC_OBJ_MEMCACHE
Caché del lado de la memoria (filtrado por defecto). Una caché delante de un nodo NUMA específico. Este objeto siempre tiene al menos un nodo NUMA como hijo de memoria.

Los objetos de memoria no se listan en la lista principal de hijos, sino en la lista dedicada de hijos de memoria.

Las cachés del lado de la memoria tienen una profundidad especial HWLOC_TYPE_DEPTH_MEMCACHE en lugar de una profundidad normal, al igual que otros objetos en el árbol principal.

HWLOC_OBJ_DIE
Die dentro de un paquete físico. Una subparte del paquete físico, que contiene múltiples núcleos. Algunos sistemas operativos (por ejemplo, Linux) pueden exponer un solo die por paquete incluso si el hardware no soporta dies en absoluto. Para evitar mostrar tales dies inexistentes, hwloc los filtrará si todos son idénticos a los paquetes. Esto es funcionalmente equivalente a forzar HWLOC_TYPE_FILTER_KEEP_STRUCTURE para Dies frente a Paquetes.

Documentación de Funciones

int hwloc_compare_types (hwloc_obj_type_t type1, hwloc_obj_type_t type2)

Compara la profundidad de dos tipos de objetos. Los tipos no deben compararse como están, ya que pueden añadirse otros nuevos en el futuro.

Devuelve

Un entero negativo si los objetos de type1 usualmente incluyen los objetos de type2.

Un entero positivo si los objetos de type1 usualmente están incluidos en los objetos de type2.

0 si los objetos de type1 y type2 son los mismos.

HWLOC_TYPE_UNORDERED si los objetos no pueden compararse (porque ninguno está usualmente contenido en el otro).

Nota

Los tipos de objetos que contienen CPUs siempre pueden compararse (usualmente, una máquina contiene paquetes, que contienen cachés, que contienen núcleos, que contienen PUs).

HWLOC_OBJ_PU siempre será el más profundo, mientras que HWLOC_OBJ_MACHINE es siempre el más alto.

Esto no significa que la topología real respete ese orden: por ejemplo, hoy en día los núcleos también pueden contener cachés, y los paquetes también pueden contener nodos. Por lo tanto, esto solo debe verse como un método de comparación de respaldo.
