El formato de archivo HINT basado en ASCII - también llamado formato `largo' - está optimizado para la legibilidad. Puede editarse con un editor de texto. Por lo tanto, permite modificaciones simples que serían difíciles de lograr usando el formato binario. También

es conveniente para la depuración.

El formato de archivo HINT binario - también llamado formato `corto' - está optimizado para la visualización de archivos HINT. Puede analizarse igualmente bien en dirección hacia adelante y hacia atrás para permitir una navegación rápida hacia adelante o hacia atrás en el archivo.El formato de archivo HINT binario está diseñado para la lectura en pantalla de documentos. Al usar un visor HINT para mostrar un archivo HINT, su contenido se adaptará dinámicamente al área de visualización disponible. Imprimir información de versión y salir. ARCHIVOS Los archivos HINT binarios deben contener todos los recursos necesarios para mostrar el archivo, por ejemplo fuentes e imágenes. Estos archivos se llaman archivos auxiliares. Los archivos HINT ASCII contienen solo los nombres de ruta de estos archivos. Al crear un archivo HINT binario a partir de un archivo HINT ASCII, es necesario encontrar estos archivos, leerlos e incluirlos en el archivo binario de salida. Al crear un archivo HINT ASCII a partir de un archivo HINT binario, es conveniente si estos archivos pueden extraerse y escribirse en el sistema de archivos. Para evitar sobrescribir directorios arbitrarios con archivos al extraer archivos auxiliares, es posible mapear los nombres de ruta
almacenados en el archivo HINT a
nombres de ruta localizados antes de escribir o leer archivos
auxiliares. [[99]]
Al calcular un nombre de ruta localizado a partir de un nombre de ruta dado, se hace una distinción entre recursos globales, como fuentes, que son referenciados por un nombre de ruta absoluto, y recursos locales, por ejemplo una imagen, que es referenciada por un nombre de ruta relativo. El directorio que comienza el nombre de ruta localizado
del primero
tiene la
extensión

.

abs

y para el segundo se usa la

extensión

.rel . Para mantener los archivos auxiliares en estos subdirectorios incluso si su ruta contiene enlaces a un directorio padre, los enlaces padre

`

.. ' son reemplazados por enlaces ` __ ' a subdirectorios. Por ejemplo, dado un archivo de entradapaper.hint,los recursos globales se almacenan en el

directorio

paper.abs y los recursos locales se almacenan en paper.rel . Una ruta absoluta como /usr/share/fonts/ se mapeará entonces a la ruta localizada paper.abs/usr/share/fonts/ y una ruta relativa como ../image/img1.jpg se mapeará entonces a la ruta localizada paper.rel/__/image/img1.jpg . NO
