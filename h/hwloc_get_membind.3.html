Descripción detallada

El enlace de memoria se puede realizar de tres maneras:

  • asignación de memoria explícita gracias a hwloc_alloc_membind() y funciones relacionadas: el enlace tendrá efecto sobre la memoria asignada por estas funciones.
  • enlace de memoria implícito a través de una política de enlace: hwloc_set_membind() y funciones relacionadas solo definen la política actual del proceso, que será aplicada a las llamadas posteriores a malloc() y funciones relacionadas.
  • migración de rangos de memoria existentes, gracias a hwloc_set_area_membind() y funciones relacionadas, que mueven datos ya asignados.

No todos los sistemas operativos soportan las tres formas. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente utilizado.

Cuando la operación de enlace solicitada no está disponible y se pasó el indicador HWLOC_MEMBIND_STRICT , la función devuelve -1. errno se establecerá en ENOSYS cuando el sistema no soporte la acción o política especificada (por ejemplo, algunos sistemas solo permiten enlazar memoria por hilo, mientras que otros sistemas solo permiten enlazar memoria para todos los hilos de un proceso). errno se establecerá en EXDEV cuando el conjunto solicitado no pueda aplicarse (por ejemplo, algunos sistemas solo permiten enlazar memoria a un solo nodo NUMA).

Si HWLOC_MEMBIND_STRICT no se pasó, la función puede fallar también, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, un conjunto de enlace más pequeño, etc.) cuando la operación solicitada no esté exactamente soportada.

La forma más portable, que debería preferirse sobre las demás siempre que sea posible, es la siguiente. Asigna algo de memoria que se espera esté enlazada al conjunto especificado. Para hacerlo, hwloc posiblemente tendrá que cambiar la política actual de enlace de memoria para realmente obtener la memoria enlazada, si el SO no proporciona ninguna otra manera de asignar simplemente memoria enlazada sin cambiar la política para todas las asignaciones. Esa es la diferencia con hwloc_alloc_membind(), que nunca cambiará la política actual de enlace de memoria.

hwloc_alloc_membind_policy(topology, size, set,
                           HWLOC_MEMBIND_BIND, 0);

Cada función de enlace de memoria de hwloc toma un argumento bitmap que es un conjunto de CPU por defecto, o un conjunto de nodos de memoria NUMA si se especifica el indicador HWLOC_MEMBIND_BYNODESET . Ver Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t) y La API de bitmap para una discusión sobre conjuntos de CPU y conjuntos de nodos de memoria NUMA. También es posible convertir entre conjunto de CPU y conjunto de nodos usando hwloc_cpuset_to_nodeset() o hwloc_cpuset_from_nodeset().

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. El enlace por conjunto de nodos debería preferirse siempre que sea posible.

Documentación del tipo enumeración

enum hwloc_membind_flags_t

Indicadores de enlace de memoria. Estos indicadores pueden usarse para refinar la política de enlace. Todos los indicadores pueden combinarse lógicamente con OR, con la excepción de HWLOC_MEMBIND_PROCESS y HWLOC_MEMBIND_THREAD; estos dos indicadores son mutuamente excluyentes.

No todos los sistemas soportan todos los tipos de enlace. hwloc_topology_get_support() puede usarse para consultar el soporte real de enlace de memoria en el sistema operativo actualmente utilizado. Ver la sección 'Descripción detallada' de Enlace de memoria para una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_MEMBIND_PROCESS
Establece la política para todos los hilos del proceso especificado (posiblemente multihilo). Este indicador es mutuamente excluyente con HWLOC_MEMBIND_THREAD.
HWLOC_MEMBIND_THREAD
Establece la política para un hilo específico del proceso actual. Este indicador es mutuamente excluyente con HWLOC_MEMBIND_PROCESS.
HWLOC_MEMBIND_STRICT
Solicita enlace estricto al SO. La función fallará si el enlace no puede garantizarse / aplicarse completamente.

Este indicador tiene significados ligeramente diferentes dependiendo con qué función se use.

HWLOC_MEMBIND_MIGRATE
Migra memoria ya asignada. Si la memoria no puede migrarse y se pasó el indicador HWLOC_MEMBIND_STRICT , se devolverá un error.
HWLOC_MEMBIND_NOCPUBIND
Evita cualquier efecto sobre el enlace de CPU. En algunos sistemas operativos, algunas funciones subyacentes de enlace de memoria también enlazan la aplicación a la(s) CPU(s) correspondiente(s). Usar este indicador hará que hwloc evite usar funciones del SO que podrían afectar a los enlaces de CPU. Nótese, sin embargo, que usar NOCPUBIND puede reducir el soporte general de enlace de memoria de hwloc. Específicamente: algunas de las funciones de enlace de memoria de hwloc pueden fallar con errno establecido en ENOSYS cuando se usan con NOCPUBIND.
HWLOC_MEMBIND_BYNODESET
Considera el argumento bitmap como un conjunto de nodos. El argumento bitmap se considera un conjunto de nodos si se da este indicador, o un conjunto de CPU por defecto en caso contrario.

El enlace de memoria por conjunto de CPU no puede funcionar para nodos de memoria NUMA sin CPU. El enlace por conjunto de nodos debería preferirse siempre que sea posible.

enum hwloc_membi

Políticas de Vinculación de Memoria

nd_policy_t
Política de vinculación de memoria. Estas constantes se pueden usar para elegir la política de vinculación. Solo se puede usar una política a la vez (es decir, los valores no se pueden combinar con OR).

No todos los sistemas admiten todos los tipos de vinculación. hwloc_topology_get_support() se puede utilizar para consultar el soporte real de la política de vinculación de memoria en el sistema operativo actualmente en uso. Consulte la sección 'Descripción detallada' de Vinculación de memoria para obtener una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_MEMBIND_DEFAULT
Restablece la política de asignación de memoria a la predeterminada del sistema. Dependiendo del sistema operativo, esto puede corresponder a HWLOC_MEMBIND_FIRSTTOUCH (Linux, FreeBSD) o HWLOC_MEMBIND_BIND (AIX, HP-UX, Solaris, Windows). Esta política nunca es devuelta por las funciones get membind. El argumento nodeset se ignora.
HWLOC_MEMBIND_FIRSTTOUCH
Asigna cada página de memoria individualmente en el nodo NUMA local del hilo que la toca. El nodeset dado generalmente debería ser hwloc_topology_get_topology_nodeset() para que el hilo que toca pueda ejecutarse y asignar en cualquier nodo del sistema.

En AIX, si el nodeset es más pequeño, las páginas se asignan localmente (si el nodo local está en el nodeset) o desde un nodo no local aleatorio (de lo contrario).

HWLOC_MEMBIND_BIND
Asigna memoria en los nodos especificados. El comportamiento real puede variar ligeramente entre los sistemas operativos, especialmente cuando los nodos solicitados (o algunos de ellos) están llenos. En Linux, por defecto, se utiliza la política MPOL_PREFERRED_MANY (o MPOL_PREFERRED). Sin embargo, si también se proporciona la bandera estricta de hwloc, se utiliza la política MPOL_BIND de Linux.
HWLOC_MEMBIND_INTERLEAVE
Asigna memoria en los nodos dados de manera intercalada / round-robin. La disposición precisa de la memoria en múltiples nodos NUMA es específica del SO/sistema. La intercalación puede ser útil cuando los hilos distribuidos en los nodos NUMA especificados accederán a todo el rango de memoria concurrentemente, ya que la intercalación equilibrará las referencias de memoria.
HWLOC_MEMBIND_WEIGHTED_INTERLEAVE
Asigna memoria en los nodos dados de manera intercalada / ponderada. La disposición precisa de la memoria en múltiples nodos NUMA es específica del SO/sistema. La intercalación ponderada puede ser útil cuando los hilos distribuidos en los nodos NUMA especificados con diferentes capacidades de ancho de banda accederán a todo el rango de memoria concurrentemente, ya que la intercalación equilibrará las referencias de memoria.
HWLOC_MEMBIND_NEXTTOUCH
Para cada página vinculada con esta política, la próxima vez que se toque (y solo la próxima vez), se moverá de su ubicación actual al nodo NUMA local del hilo donde ocurrió la referencia de memoria (si necesita moverse).
HWLOC_MEMBIND_MIXED
Devuelto por las funciones get_membind() cuando múltiples hilos o partes de un área de memoria tienen políticas de vinculación de memoria diferentes. También devuelto cuando la vinculación es desconocida porque los ganchos de vinculación están vacíos cuando la topología se carga desde XML sin HWLOC_THISSYSTEM=1, etc.

void * hwloc_alloc(hwloc_topology_t topology, size_t len)

Asigna algo de memoria. Esto es equivalente a malloc(), excepto que intenta asignar memoria alineada por página del sistema operativo.

Retorna

Un puntero al área asignada, o NULL en caso de error.

Nota

La memoria asignada debe liberarse con hwloc_free().

void * hwloc_alloc_membind(hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Asigna algo de memoria en los nodos de memoria NUMA especificados por set.

Retorna

Un puntero al área asignada.

NULL con errno establecido en ENOSYS si la acción no es compatible y se proporciona HWLOC_MEMBIND_STRICT.

NULL con errno establecido en EXDEV si la vinculación no se puede forzar y se proporciona HWLOC_MEMBIND_STRICT.

NULL con errno establecido en ENOMEM si la asignación de memoria falló incluso antes de intentar vincular.

Si se especifica HWLOC_MEMBIND_BYNODESET, set se considera un nodeset. De lo contrario, es un cpuset.

Nota

La memoria asignada debe liberarse con hwloc_free().

void * hwloc_alloc_membind_policy(hwloc_topology_t topology, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags) [inline]

Asigna algo de memoria en los nodos de memoria NUMA especificados por set. Primero, intenta asignar correctamente con hwloc_alloc_membind(). En caso de fallo, la política de vinculación de memoria del proceso o hilo actual se cambia con hwloc_set_membind() antes de asignar memoria. Por lo tanto, esta función funciona en más casos, a costa de cambiar el estado actual (lo que podría afectar las asignaciones futuras que no especificaran ninguna política).

Si se especifica HWLOC_MEMBIND_BYNODESET, set se considera un nodeset. De lo contrario, es un cpuset.

Retorna

Un puntero al área asignada, o NULL en caso de error.

int hwloc_free(hwloc_topology_t topology, void *addr, size_t len)

Libera memoria que fue previamente asignada por hwloc_alloc() o hwloc_alloc_membind().

Retorna

0 en caso de éxito, -1 en caso de error.

int hwloc_get_area_membind(hwloc_topology_t topology, const void *addr, size_t len, hwloc_bitmap_t set, hwloc_membind_policy_t *policy, int flags)

Consulta las CPUs cercanas a los nodos NUMA físicos y la política de vinculación de la memoria identificada por (addr, len ). El bitmap set (previamente asignado por el llamador) se llena con la vinculación del área de memoria.

Esta función tiene dos parámetros de salida: set y policy. Los valores devueltos en estos parámetros dependen tanto de las flags pasadas como de las políticas de vinculación de memoria y los nodesets de las páginas en el rango de direcciones.

Si se especifica HWLOC_MEMBIND_STRICT, primero se verifica si todas las páginas objetivo tienen la misma política de vinculación de memoria y nodeset. Si no es así, se devuelve -1 y errno se establece en EXDEV. Si son idénticas en todas las páginas, set y policy se devuelven en set y policy, respectivamente.

Si no se especifica HWLOC_MEMBIND_STRICT, se calcula la unión de todos los nodos NUMA que contienen páginas en el rango de direcciones. Si todas las páginas en el objetivo tienen la misma política, se devuelve en policy. De lo contrario, policy se establece en HWLOC_MEMBIND_MIXED.

Si se especifica HWLOC_MEMBIND_BYNODESET, set se considera un nodeset. De lo contrario, es un cpuset.

Si se especifican otras flags, se devuelve -1 y errno se establece en EINVAL.

Retorna

0 en caso de éxito.

-1 con errno establecido en EINVAL si len es 0.

int hwloc_get_area_memlocation(hwloc_topology_t topology, const void *addr, size_t len, hwloc_bitmap_t set, int flags)

Obtiene los nodos NUMA donde la memoria identificada por (addr, len ) está físicamente asignada. El bitmap set (previamente asignado por el llamador) se llena según los nodos NUMA donde se asignan físicamente las páginas del área de memoria. Si aún no se ha asignado ninguna página, set puede estar vacío.

Si las páginas se extienden a múltiples nodos, no se especifica si se extienden equitativamente, o si la mayoría de ellas están en un solo nodo, etc.

El sistema operativo puede mover páginas de memoria de un procesador a otro en cualquier momento según su vinculación, por lo que esta función puede devolver algo que ya está desactualizado.

Detailed Description

int hwloc_get_area_membind (hwloc_topology_t topology, const void * addr, size_t len, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Retrieve the memory binding policy and physical locality of the already-allocated memory identified by (addr, len). The bitmap set (previously allocated by the caller) is filled with the memory binding.

This function has two output parameters: set and policy. The values returned in these parameters depend on both the flags passed in and the current memory binding policies and nodesets in the queried target.

HWLOC_MEMBIND_STRICT is only meaningful if the memory region is composed of multiple distinct memory bindings. In this case, hwloc will check if all memory bindings are identical. If they are not identical, -1 is returned and errno is set to EXDEV. If they are identical, the values are returned in set and policy.

Otherwise, if HWLOC_MEMBIND_STRICT is not specified, set is set to the logical OR of all memory bindings, and policy is set to the logical OR of all policies.

If HWLOC_MEMBIND_BYNODESET is specified in flags, set is considered a nodeset. Otherwise it's a cpuset.

If len is 0, set is emptied.

Returns

0 on success, -1 on error.

int hwloc_get_membind (hwloc_topology_t topology, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Query the default memory binding policy and physical locality of the current process or thread. The bitmap set (previously allocated by the caller) is filled with the process or thread memory binding.

This function has two output parameters: set and policy. The values returned in these parameters depend on both the flags passed in and the current memory binding policies and nodesets in the queried target.

Passing the HWLOC_MEMBIND_PROCESS flag specifies that the query target is the current policies and nodesets for all the threads in the current process. Passing HWLOC_MEMBIND_THREAD specifies that the query target is the current policy and nodeset for only the thread invoking this function.

If neither of these flags are passed (which is the most portable method), the process is assumed to be single threaded. This allows hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

HWLOC_MEMBIND_STRICT is only meaningful when HWLOC_MEMBIND_PROCESS is also specified. In this case, hwloc will check the default memory policies and nodesets for all threads in the process. If they are not identical, -1 is returned and errno is set to EXDEV. If they are identical, the values are returned in set and policy.

Otherwise, if HWLOC_MEMBIND_PROCESS is specified (and HWLOC_MEMBIND_STRICT is not specified), the default set from each thread is logically OR'ed together. If all threads' default policies are the same, policy is set to that policy. If they are different, policy is set to HWLOC_MEMBIND_MIXED.

In the HWLOC_MEMBIND_THREAD case (or when neither HWLOC_MEMBIND_PROCESS or HWLOC_MEMBIND_THREAD is specified), there is only one set and policy; they are returned in set and policy, respectively.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

If any other flags are specified, -1 is returned and errno is set to EINVAL.

Returns

0 on success, -1 on error.

int hwloc_get_proc_membind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_bitmap_t set, hwloc_membind_policy_t * policy, int flags)

Query the default memory binding policy and physical locality of the specified process. The bitmap set (previously allocated by the caller) is filled with the process memory binding.

This function has two output parameters: set and policy. The values returned in these parameters depend on both the flags passed in and the current memory binding policies and nodesets in the queried target.

Passing the HWLOC_MEMBIND_PROCESS flag specifies that the query target is the current policies and nodesets for all the threads in the specified process. If HWLOC_MEMBIND_PROCESS is not specified (which is the most portable method), the process is assumed to be single threaded. This allows hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

Note that it does not make sense to pass HWLOC_MEMBIND_THREAD to this function.

If HWLOC_MEMBIND_STRICT is specified, hwloc will check the default memory policies and nodesets for all threads in the specified process. If they are not identical, -1 is returned and errno is set to EXDEV. If they are identical, the values are returned in set and policy.

Otherwise, set is set to the logical OR of all threads' default set. If all threads' default policies are the same, policy is set to that policy. If they are different, policy is set to HWLOC_MEMBIND_MIXED.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

If any other flags are specified, -1 is returned and errno is set to EINVAL.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

int hwloc_set_area_membind (hwloc_topology_t topology, const void * addr, size_t len, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Bind the already-allocated memory identified by (addr, len) to the NUMA node(s) specified by set. If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

Returns

int hwloc_set_membind (hwloc_topology_t topology, hwloc_const_bitmap_t set, hwloc_membind_policy_t policy, int flags)

Set the default memory binding policy of the current process or thread to prefer the NUMA node(s) specified by set. If neither HWLOC_MEMBIND_PROCESS nor HWLOC_MEMBIND_THREAD is specified, the current process is assumed to be single-threaded. This is the most portable form as it permits hwloc to use either process-based OS functions or thread-based OS functions, depending on which are available.

If HWLOC_MEMBIND_BYNODESET is specified, set is considered a nodeset. Otherwise it's a cpuset.

Returns

0 on success.

-1 with errno set to ENOSYS if the action is not supported.

-1 with errno set to EXDEV if the binding cannot be enforced.
