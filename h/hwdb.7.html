NOMBRE

hwdb - Base de datos de Hardware

DESCRIPCIÓN

La base de datos de hardware es un almacén de clave-valor para asociar claves similares a modalias con valores similares a udev-property. Se utiliza principalmente por udev para añadir las propiedades relevantes a los dispositivos coincidentes, pero también puede ser consultada directamente.

ARCHIVOS DE BASE DE DATOS DE HARDWARE

Los archivos de hwdb se leen de los archivos ubicados en el directorio del sistema hwdb /usr/lib/udev/hwdb.d y el directorio de administración local /etc/udev/hwdb.d. Todos los archivos de hwdb se ordenan y procesan colectivamente en orden lexicográfico, independientemente de los directorios en los que residan. Sin embargo, los archivos con nombres idénticos se reemplazan mutuamente. Los archivos en /etc/ tienen la máxima prioridad y prevalecen sobre los archivos con el mismo nombre en /usr/lib/. Esto se puede usar para anular un archivo hwdb suministrado por el sistema con un archivo local si es necesario; un enlace simbólico en /etc/ con el mismo nombre que un archivo hwdb en /usr/lib/, apuntando a /dev/null, deshabilita completamente ese archivo hwdb. Los archivos hwdb deben tener la extensión .hwdb; otras extensiones se ignoran.

Cada archivo hwdb contiene registros de datos que consisten en coincidencias y pares clave-valor asociados. Cada registro en el hwdb comienza con una o más cadenas de coincidencia, especificando un glob de shell para comparar la cadena de búsqueda. Múltiples líneas de coincidencia se especifican en líneas consecutivas. Cada línea de coincidencia se compara individualmente y se combinan mediante OR. Cada línea de coincidencia debe comenzar en el primer carácter de la línea.

Los patrones de coincidencia consisten en caracteres literales y comodines de estilo shell:

•El asterisco "*" coincide con cualquier número de caracteres
•El signo de interrogación "?" coincide con un solo carácter
•La lista de caracteres "[chars]" coincide con uno de los caracteres chars listados entre "[" y "]". Un rango puede especificarse como con un guion como "[first-last]". La coincidencia puede invertirse con un circunflejo "[^...]".

Las líneas de coincidencia van seguidas de una o más líneas de pares clave-valor, que se reconocen por un carácter de espacio inicial. El nombre de la clave y el valor están separados por "=". Una línea vacía significa el final de un registro. Las líneas que comienzan con "#" se ignoran.

En caso de que múltiples registros coincidan con una cadena de búsqueda dada, los pares clave-valor de todos los registros se combinan. Si una clave se especifica varias veces, se utiliza el valor del registro con la mayor prioridad (cada clave solo puede tener un valor). La prioridad es mayor cuando el registro se encuentra en un archivo que se ordena lexicográficamente más tarde y, en caso de registros en el mismo archivo, los registros posteriores tienen mayor prioridad.

El contenido de todos los archivos hwdb es leído por systemd-hwdb(8) y compilado a una base de datos binaria ubicada en /etc/udev/hwdb.bin, o alternativamente /usr/lib/udev/hwdb.bin si desea empaquetar la base de datos compilada en una imagen inmutable. Durante el tiempo de ejecución, solo se utiliza la base de datos binaria.

EJEMPLOS

Ejemplo 1. Sintaxis general de los archivos hwdb

# /usr/lib/udev/hwdb.d/example.hwdb
# Los comentarios se pueden colocar antes de cualquier registro. Este es un buen lugar
# para describir para qué se utiliza ese archivo, qué tipo de propiedades
# define y la convención de ordenación.
# Un registro con tres coincidencias y una propiedad
mouse:*:name:*Trackball*:*
mouse:*:name:*trackball*:*
mouse:*:name:*TrackBall*:*
 ID_INPUT_TRACKBALL=1
# La regla anterior también podría escribirse en una forma que
# coincida con Tb, tb, TB, tB:
mouse:*:name:*[tT]rack[bB]all*:*
 ID_INPUT_TRACKBALL=1
# Un registro con una sola coincidencia y cinco propiedades
mouse:usb:v046dp4041:name:Logitech MX Master:*
 MOUSE_DPI=1000@166
 MOUSE_WHEEL_CLICK_ANGLE=15
 MOUSE_WHEEL_CLICK_ANGLE_HORIZONTAL=26
 MOUSE_WHEEL_CLICK_COUNT=24
 MOUSE_WHEEL_CLICK_COUNT_HORIZONTAL=14

Ejemplo 2. Anulación de propiedades

# /usr/lib/udev/hwdb.d/60-keyboard.hwdb
evdev:atkbd:dmi:bvn*:bvr*:bd*:svnAcer*:pn*:*
 KEYBOARD_KEY_a1=help
 KEYBOARD_KEY_a2=setup
 KEYBOARD_KEY_a3=battery
# Coincide con el nombre del proveedor "Acer" y cualquier nombre de producto que comience con "X123"
evdev:atkbd:dmi:bvn*:bvr*:bd*:svnAcer:pnX123*:*
 KEYBOARD_KEY_a2=wlan
# /etc/udev/hwdb.d/70-keyboard.hwdb
# deshabilita la tecla wlan en todos los teclados at
evdev:atkbd:*
 KEYBOARD_KEY_a2=reserved
 PROPERTY_WITH_SPACES=some string

Si el hwdb consiste en esos dos archivos, un teclado con la cadena de búsqueda "evdev:atkbd:dmi:bvnAcer:bvr:bdXXXXX:bd08/05/2010:svnAcer:pnX123:" coincidirá con los tres registros y terminará con las siguientes propiedades:

KEYBOARD_KEY_a1=help
KEYBOARD_KEY_a2=reserved
KEYBOARD_KEY_a3=battery
PROPERTY_WITH_SPACES=some string
