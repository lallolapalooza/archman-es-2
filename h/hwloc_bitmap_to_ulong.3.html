Descripción Detallada

El tipo hwloc_bitmap_t representa un conjunto de enteros (positivos o nulos). Un mapa de bits puede ser de tamaño infinito (todos los bits están establecidos después de un cierto punto). Un mapa de bits puede incluso estar completo si todos los bits están establecidos.

Los mapas de bits son utilizados por hwloc para conjuntos de procesadores del sistema (que en realidad pueden ser hilos de hardware) como hwloc_cpuset_t (un typedef para hwloc_bitmap_t), o conjuntos de nodos de memoria NUMA como hwloc_nodeset_t (también un typedef para hwloc_bitmap_t). Estos se utilizan para los campos cpuset y nodeset en la estructura hwloc_obj, ver Conjuntos de Objetos (hwloc_cpuset_t y hwloc_nodeset_t).

Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del sistema operativo. Sin embargo, los usuarios generalmente no deberían construir conjuntos de CPU y nodos manualmente (por ejemplo, con hwloc_bitmap_set()). En su lugar, deberían usar los conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or(), etc. Por ejemplo, vincular el hilo actual a un par de núcleos puede realizarse con:

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

Nota

La mayoría de las funciones a continuación devuelven 0 en caso de éxito y -1 en caso de error. El caso de error habitual sería un fallo interno al reasignar/extender el almacenamiento del mapa de bits (errno se establecería como ENOMEM). Ver también Informes de errores en la API.

Varios ejemplos de uso de la API de mapas de bits están disponibles en el directorio doc/examples/ en el árbol de fuentes. Las pruebas de regresión como tests/hwloc/hwloc_bitmap*.c también hacen un uso intensivo de esta API.

Documentación de Definición de Macros

#define hwloc_bitmap_foreach_begin(id, bitmap)

Macro de bucle que itera sobre el mapa de bits bitmap. El bucle debe comenzar con hwloc_bitmap_foreach_begin() y terminar con hwloc_bitmap_foreach_end() seguido de un ';'.

id es la variable del bucle; debe ser un unsigned int. La primera iteración establecerá id al índice más bajo en el mapa de bits. Las iteraciones sucesivas recorrerán, en orden, todos los índices restantes establecidos en el mapa de bits. Para ser específicos: cada iteración devolverá un valor para id tal que hwloc_bitmap_isset(bitmap, id) sea verdadero.

La aserción previene que el bucle sea infinito si el mapa de bits está infinitamente establecido.

#define hwloc_bitmap_foreach_end()

Fin de la macro de bucle que itera sobre un mapa de bits. Necesita un ';' terminador.

int hwloc_bitmap_snprintf (char *restrict buf, size_t buflen, hwloc_const_bitmap_t bitmap)

Escribe una representación textual del mapa de bits bitmap en el buffer buf de longitud buflen. La representación es una lista separada por comas de enteros o rangos de enteros, como la esperada por hwloc_bitmap_sscanf(). Por ejemplo: "0,3,5-7,10".

Si el mapa de bits es demasiado grande para caber en buf, el resultado será truncado y se devolverá el número de caracteres que se habrían escrito (sin contar el terminador nulo). Si no hay error, se devolverá el número de caracteres escritos (sin contar el terminador nulo).

La salida siempre está terminada por un carácter nulo.

Ver también

hwloc_bitmap_asprintf(), hwloc_bitmap_sscanf()

int hwloc_bitmap_asprintf (char **strp, hwloc_const_bitmap_t bitmap)

Convierte el mapa de bits bitmap en una cadena de caracteres y devuelve un puntero a ella en *strp. La memoria de la cadena es asignada por esta función y el llamante debe liberarla con free(3). La representación es la misma que la esperada por hwloc_bitmap_sscanf(). Devuelve 0 en caso de éxito, -1 en caso de error (por ejemplo, si la asignación de memoria falla).

Si bitmap es NULL, *strp será NULL y se devolverá 0.

Ver también

hwloc_bitmap_snprintf()

int hwloc_bitmap_sscanf (hwloc_bitmap_t bitmap, const char *restrict string)

Analiza la cadena de caracteres string y actualiza el mapa de bits bitmap en consecuencia. La cadena debe contener una lista separada por comas de enteros o rangos de enteros, como "0,3,5-7,10". Los enteros no deben ser negativos. Si la cadena está vacía o contiene solo espacios en blanco, el mapa de bits resultante estará vacío. Si la cadena está mal formateada, el mapa de bits contendrá los elementos analizados antes del punto de fallo.

Los mapas de bits extendidos (que pueden tener índices muy altos) se admiten de forma transparente.

Devuelve 0 en caso de éxito, -1 si el mapa de bits bitmap es NULL o si la cadena de entrada no contiene ningún entero válido.

Bitmap Operations

The following functions manipulate the hwloc_bitmap_t opaque type, used to represent sets of objects.

hwloc_bitmap_t is an abstract type representing a set of indices. It is used internally by hwloc to represent sets of PUs, NUMA nodes, or other objects.

Functions are provided to create, destroy, copy, set, unset, and test bits in these bitmaps. Operations like union, intersection, and difference are also available. The format is inspired by the taskset command line utility. For instance, a bitmap containing PUs 0, 1, 4, 5, 6, 7 and 10 is represented by the string "0x3a". The general format is a comma-separated list of hexadecimal blocks. Each block is 64 bits large. The first block contains the least significant bits. For example, "0xffffffff,0x00000006,0x00000002" represents the set {0, 1, 33, 34, 64, 65, ..., 95}.

Some functions accept a CPU-specific or NUMA-node-specific format. In this case, the indices in the string represent physical PUs or NUMA node IDs respectively.

int hwloc_bitmap_singlify (hwloc_bitmap_t bitmap)

Keep a single index among those set in bitmap bitmap. May be useful before binding so that the process does not have a chance of migrating between multiple processors in the original mask. Instead of running the task on any PU inside the given CPU set, the operating system scheduler will be forced to run it on a single of these PUs. It avoids a migration overhead and cache-line ping-pongs between PUs.

Note

This function is NOT meant to distribute multiple processes within a single CPU set. It always return the same single bit when called multiple times on the same input set. hwloc_distrib() may be used for generating CPU sets to distribute multiple tasks below a single multi-PU object.

This function cannot be applied to an object set directly. It should be applied to a copy (which may be obtained with hwloc_bitmap_dup()).
