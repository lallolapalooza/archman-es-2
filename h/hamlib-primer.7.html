HAMLIB-PRIMER(7) Manual de Información de Hamlib HAMLIB-PRIMER(7)

NOMBRE

hamlib-primer - compilar y usar la biblioteca de control de radio y rotadores

DESCRIPCIÓN

Existen varias formas de obtener una instalación funcional de Hamlib. Las siguientes secciones discuten la instalación desde un gestor de paquetes, la compilación desde el código fuente y la instalación de binarios suministrados por el proyecto Hamlib en Microsoft Windows®.

Instalación de paquetes binarios en Linux y BSD

La forma más sencilla de instalar una versión publicada de Hamlib en una distribución basada en Linux o una variante de BSD es a través del gestor de paquetes proporcionado. Aunque los gestores de paquetes varían según la distribución (es fácil incluir las variantes de BSD en este grupo también) su objetivo final es proporcionar paquetes de software listos para usar. Dado que existe una gran variedad de gestores de paquetes, es mejor recomendar que la documentación de su distribución elegida sea su guía.

Una variedad de fuentes de Hamlib

Los paquetes de distribución suelen ser versiones oficiales de Hamlib y, en algunos casos, podrían estar desactualizados y carecer de soporte para radios o rotadores más nuevos. En algunos casos, el soporte mejora en los backend existentes de radio o rotador y se corrigen errores en versiones más recientes. A menudo, para obtener el soporte/correcciones de errores mejorados, será necesario compilar desde el código fuente. Relájese, no es difícil. :-)

El código fuente está disponible como versiones oficiales, instantáneas de prueba, instantáneas de desarrollo diarias y lo último en desarrollo directamente desde el repositorio Git. Por regla general, incluso las instantáneas más recientes deberían configurarse y compilarse sin errores, aunque es posible que el trabajo de implementación esté en progreso y pueda estar incompleto o tener errores.

Obtener código fuente publicado

Las versiones oficiales del código fuente de Hamlib, comúnmente llamadas tarballs, se pueden encontrar en la página web de Archivos de Hamlib de SourceForge.net. La versión más reciente aparece primero.

Obtener instantáneas de código fuente

Los candidatos a prueba de lanzamiento (RC) se publican durante el período (a menudo unas pocas semanas) antes de un lanzamiento planificado. A partir de la versión 4.0, los RC se alojan en la página web de Archivos de Hamlib de SourceForge.net. Los RC se identifican por tener el sufijo ~rcX, donde X se reemplaza por un número para los candidatos a lanzamiento sucesivos.

Las instantáneas diarias del repositorio de desarrollo están disponibles a través de la World Wide Web desde Instantáneas diarias de Git de Hamlib. Estas no son versiones oficiales, pero se proporcionan para probar nuevas funciones y correcciones de errores.

La instantánea de desarrollo diaria se crea y se publica todos los días alrededor de las 10:30 UTC. Las instantáneas diarias deberían compilarse, pero a veces surge un error que impide la compilación. Si eso sucede, por favor, informe al lista de correo de hamlib-developer.

Repositorio Git

El repositorio de código fuente se puede clonar, lo que copia el repositorio a su computadora, incluido todo su historial, ramas e información de etiquetas de lanzamiento. En otras palabras, una vez que el comando git(1) clone finaliza, una copia completa del desarrollo de Hamlib estará en su computadora. Puede hacer bastante con esto, ya que nada está oculto a la vista, ya que todo el historial de Hamlib está ahí desde el primer commit hasta el presente. Ninguno de los metadatos está oculto en algún servidor central.

Para clonar el repositorio, use el siguiente comando:


git clone https://git.code.sf.net/p/hamlib/code hamlib

o:


git clone https://github.com/Hamlib/Hamlib.git

Lo más probable es que desee ejecutar el comando anterior en un subdirectorio de su directorio de inicio. Git creará el directorio hamlib y le seleccionará la rama master como copia de trabajo. La rama master es una de las varias ramas utilizadas en el desarrollo de Hamlib. Es la rama principal de nuevas funciones y correcciones de errores. La copia de trabajo será la última revisión de cada archivo en el momento de la clonación. Las actualizaciones posteriores de los desarrolladores requerirán el uso de otro comando Git para actualizar su repositorio local.

Compilación desde fuente

Se requerirá la compilación desde la fuente por diversas razones. Quizás su distribución solo proporcione una versión anterior, o le gustaría probar cambios recientes en Hamlib —ya sea un backend específico o cambios en la API— y ofrecer un informe a los desarrolladores, o le gustaría participar en el desarrollo y ofrecer su contribución al proyecto, o simplemente le gustaría aprender a compilar un paquete relativamente completo desde la fuente. Cualquiera es una buena razón para compilar desde el archivo de código fuente.

Antes de continuar, es esencial leer la información de los archivos README.md, INSTALL y README.betatester suministrados en el directorio principal de Hamlib, que se llamará algo como hamlib-3.3~git, donde la última parte es la versión de lanzamiento. En este caso, 3.3~git indica que se trata de una instantánea de desarrollo de la rama maestra de Git. Estos archivos proporcionan información detallada para compilar Hamlib y variarán un poco de una versión a otra.

La compilación desde un archivo de código fuente, ya sea una versión oficial o una instantánea de prueba o de desarrollo diario, sigue el mismo conjunto de comandos, conocido como los tres pasos, que se ejecutan desde el directorio principal:


./configure
make
sudo make install

configure

El comando ./configure examina su sistema y verifica si hay paquetes requeridos o deseables para compilar Hamlib. El prefijo ./ le dice al shell que solo ejecute el comando configure que se encuentra en el directorio actual. Siempre es posible que un comando configure esté oculto en otro lugar y ¡no queremos ejecutarlo!

Ejecute:


./configure

desde el directorio principal.

Nota: Algunas distribuciones están configuradas para que los comandos solo se puedan ejecutar desde directorios listados en la variable de entorno PATH. El ./ es necesario o el comando configure no se ejecutará ya que el directorio actual (definido como .) no está en el PATH. Esto se considera una característica de seguridad predeterminada para que solo se ejecuten los programas proporcionados por la distribución. El PATH se puede modificar
