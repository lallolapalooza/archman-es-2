Descripción

Detallada

El tipo hwloc_bitmap_t representa un conjunto de enteros (positivos o nulos). Un mapa de bits puede ser de tamaño infinito (todos los bits se establecen después de algún punto). Un mapa de bits incluso puede estar completo si todos los bits están

establecidos.

Los mapas de bits son utilizados por hwloc para conjuntos de procesadores del SO (que pueden ser en realidad hilos de hardware) como por hwloc_cpuset_t (un typedef para hwloc_bitmap_t), o conjuntos de nodos de memoria NUMA como hwloc_nodeset_t (también un typedef para hwloc_bitmap_t). Estos se utilizan para los campos cpuset y nodeset en la estructura hwloc_obj, ver Conjuntos de Objetos (hwloc_cpuset_t

y hwloc_nodeset_t).

Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del SO. Sin embargo, los usuarios normalmente no deberían construir conjuntos de CPU y nodos manualmente (por ejemplo, con hwloc_bitmap_set()). Más bien se deben usar conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or(), etc. Por ejemplo, vincular el hilo actual a un par de núcleos puede realizarse

con: 
hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set)
;

int hwloc_bitmap_list_asprintf (char ** strp, hwloc_const_bitmap_t bitmap)

Convierte un mapa de bits a una cadena de lista recién asignada. Tenga en cuenta que si el mapa de bits es un conjunto de CPU o nodos, contiene índices físicos.

Las listas son índices o rangos separados por comas. Los rangos son índices separados por guiones. Un mapa de bits que contiene los bits 1, 33, 34 y todos los de 64 a 95 se imprime como '1,33-34,64-95'. El último rango puede no tener un índice final si el mapa de bits está infinitamente establecido.

Retorna

el número de caracteres que se escribieron (sin incluir el \0 final).

-1 en caso de error, por ejemplo, con errno establecido a ENOMEM en caso de fallo al asignar la cadena de salida.

Devuelve el número de unsigned longs necesarios para almacenar completamente el mapa de bits bitmap. Este es el número de unsigned longs contiguos desde el primer bit del mapa de bits (incluso si no está establecido) hasta el último bit establecido. Esto es útil para conocer el nr a pasar a hwloc_bitmap_to_ulongs() (o qué llamadas a hwloc_bitmap_to_ith_ulong() son necesarias) para convertir completamente un mapa de bits en múltiples unsigned longs.

Cuando se llama en la salida de hwloc_topology_get_topology_cpuset(), el número devuelto es suficiente para todos los conjuntos de CPU de la topología.

Retorna

el número de unsigned longs necesarios.

-1 si el mapa de bits es infinito.

int hwloc_bitmap_singlify (hwloc_bitmap_t

bitmap)

Mantiene un solo índice entre los establecidos en el mapa de bits bitmap. Puede ser útil antes de la vinculación para que el proceso no tenga la oportunidad de migrar entre múltiples procesadores en la máscara original. En lugar de ejecutar la tarea en cualquier PU dentro del conjunto de CPU dado, el programador del sistema operativo se verá obligado a ejecutarla en una sola de estas PUs. Evita una sobrecarga de migración y los "ping-pongs" de líneas de caché entre

PUs.

Siempre devuelve el mismo bit único cuando se llama varias veces con el mismo conjunto de entrada. hwloc_distrib() puede usarse para generar conjuntos de CPU para distribuir múltiples tareas bajo un solo objeto multi-PU.
