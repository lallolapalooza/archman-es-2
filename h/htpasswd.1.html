NOMBRE

htpasswd - Gestiona archivos de usuario para autenticación básica

SINOPSIS

htpasswd [ -c ] [ -i ] [ -m | -B | -2 | -5 | -d | -s | -p ] [ -r rondas ] [ -C costo ] [ -D ] [ -v ] archivo_contraseñas nombre_usuario

htpasswd -b [ -c ] [ -m | -B | -2 | -5 | -d | -s | -p ] [ -r rondas ] [ -C costo ] [ -D ] [ -v ] archivo_contraseñas nombre_usuario contraseña

htpasswd -n [ -i ] [ -m | -B | -2 | -5 | -d | -s | -p ] [ -r rondas ] [ -C costo ] nombre_usuario

htpasswd -nb [ -m | -B | -2 | -5 | -d | -s | -p ] [ -r rondas ] [ -C costo ] nombre_usuario contraseña

RESUMEN

htpasswd se utiliza para crear y actualizar los archivos planos que almacenan nombres de usuario y contraseñas para la autenticación básica de usuarios HTTP. Si htpasswd no puede acceder a un archivo, como no poder escribir en el archivo de salida o no poder leer el archivo para actualizarlo, devuelve un estado de error y no realiza ningún cambio.

Los recursos disponibles desde el servidor HTTP Apache pueden restringirse solo a los usuarios listados en los archivos creados por htpasswd. Este programa solo puede gestionar nombres de usuario y contraseñas almacenados en un archivo plano. Sin embargo, puede hashear y mostrar información de contraseñas para su uso en otros tipos de almacenes de datos. Para usar una base de datos DBM, consulta dbmmanage o htdbm.

htpasswd hashea contraseñas utilizando bcrypt, una versión de MD5 modificada para Apache, SHA-1, o la rutina crypt() del sistema. Se admiten hashes basados en SHA-2 (SHA-256 y SHA-512) para crypt(). Los archivos gestionados por htpasswd pueden contener una mezcla de diferentes tipos de codificación de contraseñas; algunos registros de usuario pueden tener contraseñas hasheadas con bcrypt o MD5, mientras que otros en el mismo archivo pueden tener contraseñas hasheadas con crypt().

Esta página del manual solo enumera los argumentos de la línea de comandos. Para obtener detalles sobre las directivas necesarias para configurar la autenticación de usuarios en httpd, consulta el manual de Apache, que forma parte de la distribución de Apache o se puede encontrar en http://httpd.apache.org/.

OPCIONES

-b
Utiliza el modo por lotes; es decir, obtén la contraseña de la línea de comandos en lugar de solicitarla. Esta opción debe usarse con extremo cuidado, ya que la contraseña es claramente visible en la línea de comandos. Para uso en scripts, consulta la opción -i. Disponible en la versión 2.4.4 y posteriores.
-i
Lee la contraseña desde stdin sin verificación (para uso en scripts).
-c
Crea el archivo_contraseñas. Si archivo_contraseñas ya existe, se reescribe y se trunca. Esta opción no se puede combinar con la opción -n.
-n
Muestra los resultados en la salida estándar en lugar de actualizar un archivo. Esto es útil para generar registros de contraseñas aceptables para Apache para incluirlos en almacenes de datos no textuales. Esta opción cambia la sintaxis de la línea de comandos, ya que se omite el argumento archivo_contraseñas (generalmente el primero). No se puede combinar con la opción -c.
-m
Utiliza el hasheo MD5 para las contraseñas. Este es el valor predeterminado (desde la versión 2.2.18).
-2
Utiliza hashes basados en crypt() SHA-256 para las contraseñas. Esto es compatible con la mayoría de las plataformas Unix.
-5
Utiliza hashes basados en crypt() SHA-512 para las contraseñas. Esto es compatible con la mayoría de las plataformas Unix.
-B
Utiliza el hasheo bcrypt para las contraseñas. Actualmente se considera muy seguro.
-C
Esta bandera solo está permitida en combinación con -B (hasheo bcrypt). Establece el tiempo de cómputo utilizado para el algoritmo bcrypt (más alto es más seguro pero más lento, predeterminado: 5, válido: 4 a 17).
-r
Esta bandera solo está permitida en combinación con -2 o -5. Establece el número de rondas de hash utilizadas para los algoritmos SHA-2 (más alto es más seguro pero más lento; el valor predeterminado es 5.000).
-d
Utiliza el hasheo crypt() para las contraseñas. No es compatible con el servidor httpd en Windows y Netware. Este algoritmo limita la longitud de la contraseña a 8 caracteres. Este algoritmo es inseguro según los estándares actuales. Solía ser el algoritmo predeterminado hasta la versión 2.2.17.
-s
Utiliza el hasheo SHA-1 (160 bits) para las contraseñas. Facilita la migración desde/hacia servidores Netscape que utilizan el formato de intercambio de directorios LDAP (ldif). Este algoritmo es inseguro según los estándares actuales.
-p
Utiliza contraseñas en texto plano. Aunque htpasswd admitirá la creación en todas las plataformas, el demonio httpd solo aceptará contraseñas en texto plano en Windows y Netware.
-D
Elimina al usuario. Si el nombre de usuario existe en el archivo htpasswd especificado, se eliminará.
-v
Verifica la contraseña. Verifica que la contraseña proporcionada coincide con la contraseña del usuario almacenada en el archivo htpasswd especificado. Disponible en la versión 2.4.5 y posteriores.
archivo_contraseñas
Nombre del archivo que contendrá el nombre de usuario y la contraseña. Si se proporciona -c, este archivo se creará si no existe, o se reescribirá y truncará si ya existe.
nombre_usuario
El nombre de usuario a crear o actualizar en archivo_contraseñas. Si nombre_usuario no existe en este archivo, se añadirá una entrada. Si ya existe, se cambiará la contraseña.
contraseña
La contraseña en texto plano que se hasheará y almacenará en el archivo. Solo se utiliza con la bandera -b.

ESTADO DE SALIDA

htpasswd devuelve un estado cero ("verdadero") si el nombre de usuario y la contraseña se han añadido o actualizado correctamente en el archivo_contraseñas. htpasswd devuelve 1 si encuentra algún problema al acceder a los archivos, 2 si hubo un problema de sintaxis en la línea de comandos, 3 si la contraseña se introdujo interactivamente y la entrada de verificación no coincidió, 4 si la operación fue interrumpida, 5 si un valor es demasiado largo (nombre de usuario, nombre de archivo, contraseña o registro calculado final), 6 si el nombre de usuario contiene caracteres ilegales (ver la sección Restricciones), y 7 si el archivo no es un archivo de contraseñas válido.

EJEMPLOS

      htpasswd /usr/local/etc/apache/.htpasswd-users jsmith

Añade o modifica la contraseña del usuario jsmith. Se le pedirá al usuario la contraseña. La contraseña se hasheará utilizando el algoritmo MD5 modificado de Apache. Si el archivo no existe, htpasswd no hará nada excepto devolver un error.

      htpasswd -c /home/doe/public_html/.htpasswd jane

Crea un archivo nuevo y almacena un registro en él para el usuario jane. Se le pedirá al usuario la contraseña. Si el archivo existe y no se puede leer, o no se puede escribir, no se modificará y htpasswd mostrará un mensaje y devolverá un estado de error.

      htpasswd -db /usr/web/.htpasswd-all jones Pwd4Steve

Cifra la contraseña de la línea de comandos (Pwd4Steve) utilizando el algoritmo crypt(), y la almacena en el archivo especificado.

CONSIDERACIONES DE SEGURIDAD

Los archivos de contraseñas web, como los gestionados por htpasswd, no deben estar dentro del espacio URI del servidor Web; es decir, no deben ser accesibles desde un navegador.

Este programa no es seguro como ejecutable setuid. No lo hagas setuid.

Al utilizar el algoritmo crypt(), tenga en cuenta que solo se utilizan los primeros 8 caracteres de la contraseña para formar la clave. Si la contraseña proporcionada es más larga, los caracteres adicionales se descartarán silenciosamente

El formato de hash SHA-1 no utiliza salting: para una contraseña determinada, solo existe una representación con hash. Los formatos crypt() y MD5 permutan la representación anteponiendo una cadena de sal aleatoria, para dificultar los ataques de diccionario contra las

Los formatos SHA-1 y crypt() no son seguros según los estándares

actuales.

Los formatos crypt() basados en SHA-2 (SHA-256 y SHA-512) son compatibles con la mayoría de los sistemas Unix modernos y siguen la especificación en https://www.akkadia.org

/drepper/SHA-crypt.txt.
