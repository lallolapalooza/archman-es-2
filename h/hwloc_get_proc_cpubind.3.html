Descripción Detallada

Algunos sistemas operativos solo admiten la vinculación de hilos o procesos a una única PU. Otros permiten la vinculación a conjuntos más grandes, como núcleos o paquetes completos, o incluso conjuntos aleatorios de PUs individuales. En tales sistemas operativos, el planificador es libre de ejecutar la tarea en una de estas PUs, luego migrarla a otra PU, etc. A menudo es útil llamar a hwloc_bitmap_singlify() en el conjunto de CPU de destino antes de pasarlo a la función de vinculación para evitar estas migraciones costosas. Consulte la documentación de hwloc_bitmap_singlify() para obtener más detalles.

Algunos sistemas operativos no proporcionan todos los mecanismos soportados por hwloc para vincular procesos, hilos, etc. hwloc_topology_get_support() puede ser utilizado para consultar sobre el soporte real de vinculación de CPU en el sistema operativo actualmente en uso.

Cuando la operación de vinculación solicitada no está disponible y se pasó la bandera HWLOC_CPUBIND_STRICT, la función devuelve -1. errno se establece en ENOSYS cuando no es posible vincular el tipo solicitado de procesos/hilos. errno se establece en EXDEV cuando el conjunto de CPU solicitado no se puede aplicar (por ejemplo, algunos sistemas solo permiten una CPU, y algunos otros sistemas solo permiten un nodo NUMA).

Si no se pasó HWLOC_CPUBIND_STRICT, la función también puede fallar, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de vinculación más pequeño, etc.) cuando la operación solicitada no se admite exactamente.

La versión más portable que debe preferirse sobre las otras, siempre que sea posible, es la siguiente que solo vincula el programa actual, asumiendo que es de un solo hilo:

hwloc_set_cpubind(topology, set, 0),

Si el programa puede ser multihilo, se debe preferir la siguiente para vincular solo el hilo actual:

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Ver también

Algunos códigos de ejemplo están disponibles en doc/examples/ en el árbol de fuentes.

Nota

Para desvincular, simplemente llame a la función de vinculación con un conjunto de CPU completo o un conjunto de CPU igual al conjunto de CPU del sistema.

En algunos sistemas operativos, la vinculación de CPU puede tener efectos en la vinculación de memoria, ver HWLOC_CPUBIND_NOMEMBIND

Ejecutar lstopo --top o hwloc-ps puede ser una herramienta muy conveniente para verificar cómo ocurrió realmente la vinculación.

Documentación del Tipo Enumerado

enum hwloc_cpubind_flags_t

Marcas de vinculación de proceso/hilo. Estas marcas de bits pueden ser utilizadas para refinar la política de vinculación.

El valor predeterminado (0) es vincular el proceso actual, asumido como de un solo hilo, de forma no estricta. Esta es la forma más portable de vincular, ya que todos los sistemas operativos suelen proporcionarla.

Nota

No todos los sistemas admiten todos los tipos de vinculación. Consulte la sección 'Descripción Detallada' de Vinculación de CPU para ver una descripción de los errores que pueden ocurrir.

Enumeradores

HWLOC_CPUBIND_PROCESS
Vincular todos los hilos del proceso actual (posiblemente) multihilo.
HWLOC_CPUBIND_THREAD
Vincular el hilo actual del proceso actual.
HWLOC_CPUBIND_STRICT
Solicitar vinculación estricta al SO. Por defecto, cuando las CPUs designadas están todas ocupadas mientras otras CPUs están inactivas, los sistemas operativos pueden ejecutar el hilo/proceso en esas otras CPUs en lugar de las designadas, para permitir que progresen de todos modos. La vinculación estricta significa que el hilo/proceso NUNCA se ejecutará en otras CPUs que las designadas, incluso cuando estas estén ocupadas con otras tareas y otras CPUs estén inactivas.

Nota

Dependiendo del sistema operativo, la vinculación estricta puede no ser posible (por ejemplo, el SO no la implementa) o no estar permitida (por ejemplo, por razones administrativas), y la función fallará en ese caso.

Al recuperar la vinculación de un proceso, esta marca comprueba si todos sus hilos tienen realmente la misma vinculación. Si no se proporciona la marca, se acumulará la vinculación de cada hilo.

Nota

Esta marca no tiene significado al recuperar la vinculación de un hilo.
HWLOC_CPUBIND_NOMEMBIND
Evitar cualquier efecto en la vinculación de memoria. En algunos sistemas operativos, algunas funciones de vinculación de CPU también vincularían la memoria al nodo NUMA correspondiente. A menudo esto no es un problema para la aplicación, pero si lo es, establecer esta marca hará que hwloc evite usar funciones del SO que también vincularían memoria. Sin embargo, esto reducirá el soporte de vinculaciones de CPU, es decir, potencialmente devolverá -1 con errno establecido en ENOSYS en algunos casos.

Esta marca solo es significativa cuando se usa con funciones que establecen la vinculación de CPU. Se ignora cuando se usa con funciones que obtienen información de vinculación de CPU.

Documentación de Funciones

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtener la vinculación actual del proceso o hilo. El conjunto de CPU set (previamente asignado por el llamante) se llena con la lista de PUs a las que el proceso o hilo (según flags) fue vinculado por última vez.

Retorna

0 en caso de éxito, -1 en caso de error.

int hwloc_get_last_cpu_location (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Obtener la última CPU física en la que se ejecutó el proceso o hilo actual. El conjunto de CPU set (previamente asignado por el llamante) se llena con la lista de PUs en las que el proceso o hilo (según flags) se ejecutó por última vez.

Si el proceso es de un solo hilo, flags puede establecerse en cero para que hwloc use cualquier método disponible en el sistema operativo subyacente.

int hwloc_get_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Obtiene el enlace físico actual del proceso pid. El conjunto de CPU set (previamente asignado por el llamante) se rellena con la lista de PUs a los que el proceso fue enlazado por última vez.

Devuelve

0 en caso de éxito, -1 en caso de error.

Nota

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

Como caso especial en Linux, si se proporciona un tid (identificador de hilo) en lugar de un pid (identificador de proceso) y se pasa HWLOC_CPUBIND_THREAD en flags, se devuelve el enlace de ese hilo específico.

En sistemas que no son Linux, HWLOC_CPUBIND_THREAD no puede usarse en flags.

int hwloc_get_proc_last_cpu_location (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Obtiene el último CPU físico donde se ejecutó un proceso. El conjunto de CPU set (previamente asignado por el llamante) se rellena con la lista de PUs en los que el proceso se ejecutó por última vez.

El sistema operativo puede mover algunas tareas de un procesador a otro en cualquier momento según su enlace, por lo que esta función puede devolver algo que ya está obsoleto.

Devuelve

0 en caso de éxito, -1 en caso de error.

Nota

hwloc_pid_t es pid_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

Como caso especial en Linux, si se proporciona un tid (identificador de hilo) en lugar de un pid (identificador de proceso) y HWLOC_CPUBIND_THREAD se pasa en flags, se devuelve la última ubicación de CPU de ese hilo específico.

En sistemas que no son Linux, HWLOC_CPUBIND_THREAD no puede usarse en flags.

int hwloc_get_thread_cpubind (hwloc_topology_t topology, hwloc_thread_t thread, hwloc_cpuset_t set, int flags)

Obtiene el enlace físico actual del hilo tid. El conjunto de CPU set (previamente asignado por el llamante) se rellena con la lista de PUs a los que el hilo fue enlazado por última vez.

Devuelve

0 en caso de éxito, -1 en caso de error.

Nota

hwloc_thread_t es pthread_t en plataformas Unix, y HANDLE en plataformas Windows nativas.

HWLOC_CPUBIND_PROCESS no puede usarse en flags.

int hwloc_set_cpubind (hwloc_topology_t topology, hwloc_const_cpuset_t set, int flags)

Devuelve

-1 con errno establecido a ENOSYS si la acción no es soportada.

-1 con errno establecido a EXDEV si el enlace no puede ser aplicado.
