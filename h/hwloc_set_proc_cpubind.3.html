Descripción Detallada

Algunos sistemas operativos solo admiten la vinculación de hilos o procesos a una única PU. Otros permiten la vinculación a conjuntos más grandes, como núcleos o paquetes completos, o incluso conjuntos aleatorios de PUs individuales. En tales sistemas operativos, el planificador es libre de ejecutar la tarea en una de estas PUs, luego migrarla a otra PU, etc. A menudo es útil llamar a hwloc_bitmap_singlify() en el conjunto de CPU de destino antes de pasarlo a la función de vinculación para evitar estas migraciones costosas. Consulte la documentación de hwloc_bitmap_singlify() para obtener más detalles.

Algunos sistemas operativos no proporcionan todos los mecanismos admitidos por hwloc para vincular procesos, hilos, etc. hwloc_topology_get_support() puede usarse para consultar el soporte real de vinculación de CPU en el sistema operativo actualmente en uso.

Cuando la operación de vinculación solicitada no está disponible y se pasó el flag HWLOC_CPUBIND_STRICT, la función devuelve -1. Se establece errno en ENOSYS cuando no es posible vincular el tipo de objeto solicitado (procesos/hilos). Se establece errno en EXDEV cuando el cpuset solicitado no se puede aplicar (por ejemplo, algunos sistemas solo permiten una CPU y otros solo un nodo NUMA).

Si no se pasó HWLOC_CPUBIND_STRICT, la función también puede fallar, o el sistema operativo puede usar una operación ligeramente diferente (con efectos secundarios, conjunto de vinculación más pequeño, etc.) cuando la operación solicitada no se admite exactamente.

La versión más portátil que debe preferirse sobre las demás, siempre que sea posible, es la siguiente, que simplemente vincula el programa actual, asumiendo que es de un solo hilo:

hwloc_set_cpubind(topology, set, 0),

Si el programa puede ser multihilo, se debe preferir la siguiente para vincular solo el hilo actual:

hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD),

Nota

Para desvincular, simplemente llame a la función de vinculación con un cpuset completo o un cpuset igual al cpuset del sistema.

En algunos sistemas operativos, la vinculación de CPU puede tener efectos en la vinculación de memoria, ver HWLOC_CPUBIND_NOMEMBIND

Ejecutar lstopo --top o hwloc-ps puede ser una herramienta muy conveniente para comprobar cómo ocurrió realmente la vinculación.

Documentación del tipo de enumeración

enum hwloc_cpubind_flags_t

Flags de vinculación de procesos/hilos. Estas banderas de bits se pueden usar para refinar la política de vinculación.

El valor predeterminado (0) es vincular el proceso actual, asumiendo que es de un solo hilo, de forma no estricta. Esta es la forma más portable de vincular, ya que todos los sistemas operativos suelen proporcionarla.

Nota

No todos los sistemas admiten todos los tipos de vinculación. Consulte la sección 'Descripción detallada' de VIN CULACIÓN DE CPU para obtener una descripción de los errores que pueden ocurrir.

Enumerador

HWLOC_CPUBIND_PROCESS
Vincula todos los hilos del proceso actual (posiblemente) multihilo.
HWLOC_CPUBIND_THREAD
Vincula el hilo actual del proceso actual.
HWLOC_CPUBIND_STRICT
Solicita vinculación estricta al SO. Por defecto, cuando las CPUs designadas están todas ocupadas mientras otras CPUs están inactivas, los sistemas operativos pueden ejecutar el hilo/proceso en esas otras CPUs en lugar de las designadas, para permitir que progresen de todos modos. La vinculación estricta significa que el hilo/proceso _nunca_ se ejecutará en CPUs distintas a las designadas, incluso cuando estas estén ocupadas con otras tareas y otras CPUs estén inactivas.

Nota

Dependiendo del sistema operativo, la vinculación estricta puede no ser posible (por ejemplo, el SO no la implementa) o no permitirse (por ejemplo, por razones administrativas), y la función fallará en ese caso.

Al recuperar la vinculación de un proceso, este flag comprueba si todos sus hilos tienen realmente la misma vinculación. Si el flag no se proporciona, se acumulará la vinculación de cada hilo.

Nota

Este flag no tiene sentido al recuperar la vinculación de un hilo.
HWLOC_CPUBIND_NOMEMBIND
Evita cualquier efecto en la vinculación de memoria. En algunos sistemas operativos, algunas funciones de vinculación de CPU también vincularían la memoria al nodo NUMA correspondiente. A menudo no es un problema para la aplicación, pero si lo es, establecer este flag hará que hwloc evite usar funciones del SO que también vincularían memoria. Sin embargo, esto reducirá el soporte para la vinculación de CPU, es decir, potencialmente devolverá -1 con errno establecido en ENOSYS en algunos casos.

Este flag solo es significativo cuando se usa con funciones que establecen la vinculación de CPU. Se ignora cuando se usa con funciones que obtienen información de vinculación de CPU.

Description

These functions provide ways to query and set the CPU binding of processes and threads.

The CPU binding restricts the set of logical processors on which a process or thread is allowed to execute.

int hwloc_get_cpubind (hwloc_topology_t topology, hwloc_cpuset_t set, int flags)

Get the current physical binding of the calling process or thread. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process or thread was last bound to.

The flags argument can include either HWLOC_CPUBIND_PROCESS or HWLOC_CPUBIND_THREAD to specify whether the query should be for the whole process (union of all CPUs on which all threads are running), or only the current thread. If the process is single-threaded, flags can be set to zero to let hwloc use whichever method is available on the underlying OS.

Returns

0 on success, -1 on error.

int hwloc_get_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Get the current physical binding of process pid. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process was last bound to.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

As a special case on Linux, if a tid (thread ID) is supplied instead of a pid (process ID) and HWLOC_CPUBIND_THREAD is passed in flags, the binding for that specific thread is returned.

On non-Linux systems, HWLOC_CPUBIND_THREAD can not be used in flags.

int hwloc_get_proc_last_cpu_location (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_cpuset_t set, int flags)

Get the last physical CPU where a process ran. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the process last ran on.

The operating system may move some tasks from one processor to another at any time according to their binding, so this function may return something that is already outdated.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

As a special case on Linux, if a tid (thread ID) is supplied instead of a pid (process ID) and HWLOC_CPUBIND_THREAD is passed in flags, the last CPU location of that specific thread is returned.

On non-Linux systems, HWLOC_CPUBIND_THREAD can not be used in flags.

int hwloc_get_thread_cpubind (hwloc_topology_t topology, hwloc_thread_t thread, hwloc_cpuset_t set, int flags)

Get the current physical binding of thread tid. The CPU-set set (previously allocated by the caller) is filled with the list of PUs which the thread was last bound to.

Returns

0 on success, -1 on error.

Note

hwloc_thread_t is pthread_t on Unix platforms, and HANDLE on native Windows platforms.

HWLOC_CPUBIND_PROCESS can not be used in flags.

int hwloc_set_cpubind (hwloc_topology_t topology, hwloc_const_cpuset_t set, int flags)

Bind current process or thread on CPUs given in physical bitmap set.

Returns

0 on success.

-1 with errno set to ENOSYS if the action is not supported.

-1 with errno set to EXDEV if the binding cannot be enforced.

int hwloc_set_proc_cpubind (hwloc_topology_t topology, hwloc_pid_t pid, hwloc_const_cpuset_t set, int flags)

Bind a process pid on CPUs given in physical bitmap set.

Returns

0 on success, -1 on error.

Note

hwloc_pid_t is pid_t on Unix platforms, and HANDLE on native Windows platforms.

As a special case on Linux, if a tid (thread ID) is supplied instead of a pid (process ID) and HWLOC_CPUBIND_THREAD is passed in flags, the binding is applied to that specific thread.

On non-Linux systems, HWLOC_CPUBIND_THREAD can not be used in flags.

int hwloc_set_thread_cpubind (hwloc_topology_t topology, hwloc_thread_t thread, hwloc_const_cpuset_t set, int flags)

Bind a thread thread on CPUs given in physical bitmap set.

Returns

0 on success, -1 on error.

Note

hwloc_thread_t is pthread_t on Unix platforms, and HANDLE on native Windows platforms.

HWLOC_CPUBIND_PROCESS can not be used in flags.
