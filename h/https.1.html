https(1) Manual de HTTPie https(1)

NOMBRE

https

SINOPSIS

https [MÉTODO] URL [ELEMENTO_SOLICITUD ...]

DESCRIPCIÓN

HTTPie: cliente HTTP de línea de comandos moderno y fácil de usar para la era de las API. https://httpie.io

Argumentos posicionales

Estos argumentos vienen después de cualquier indicador y en el orden en que se enumeran aquí. Solo la URL es obligatoria.

MÉTODO

El método HTTP que se utilizará para la solicitud (GET, POST, PUT, DELETE, ...).

Este argumento se puede omitir, en cuyo caso HTTPie usará POST si hay datos que enviar, de lo contrario GET:


$ http example.org # => GET
$ http example.org hola=mundo # => POST

URL

La URL de la solicitud. El esquema por defecto es 'http://' si la URL no incluye uno. (Puede anular esto con: --default-scheme=http/https)

También puede usar un atajo para localhost


$ http :3000 # => http://localhost:3000
$ http :/foo # => http://localhost/foo

ELEMENTO_SOLICITUD

Pares clave-valor opcionales para incluir en la solicitud. El separador utilizado determina el tipo:

':' Cabeceras HTTP:


Referer:https://httpie.io Cookie:foo=bar User-Agent:bacon/1.0

'==' Parámetros de URL para añadir a la URI de la solicitud:


search==httpie

'=' Campos de datos para serializar en un objeto JSON (con --json, -j)
o datos de formulario (con --form, -f):


nombre=HTTPie lenguaje=Python descripción='Cliente HTTP CLI'

':=' Campos JSON no string (solo con --json, -j):


genial:=true cantidad:=42 colores:='["rojo", "verde", "azul"]'

'@' Campos de archivo de formulario (solo con --form o --multipart):


cv@~/Documentos/CV.pdf
cv@'~/Documentos/CV.pdf;type=application/pdf'

'=@' Un campo de datos como '=', pero toma una ruta de archivo e incrusta su contenido:


ensayo=@Documentos/ensayo.txt

':=@' Un campo JSON crudo como ':=', pero toma una ruta de archivo e incrusta su contenido:


paquete:=@./paquete.json

Puede usar una barra invertida para escapar un separador que colisiona en el nombre del campo:


nombre-del-campo-con\:dos-puntos=valor

Tipos de contenido predefinidos

--json, -j

(por defecto) Los elementos de datos de la línea de comandos se serializan como un objeto JSON. Las cabeceras Content-Type y Accept se establecen a application/json (si no se especifican).

--form, -f

Los elementos de datos de la línea de comandos se serializan como campos de formulario.

Content-Type se establece a application/x-www-form-urlencoded (si no se especifica). La presencia de cualquier campo de archivo da como resultado una solicitud multipart/form-data.

--multipart

Similar a --form, pero siempre envía una solicitud multipart/form-data (es decir, incluso sin archivos).

--boundary

Especifica una cadena de límite personalizada para solicitudes multipart/form-data. Solo tiene efecto junto con --form.

--raw

Esta opción le permite pasar datos de solicitud crudos sin procesamiento adicional (en contraposición a la sintaxis estructurada de elementos de solicitud):


$ http --raw='datos' pie.dev/post

Puede lograr lo mismo canalizando los datos a través de stdin:


$ echo datos | http pie.dev/post

O hacer que HTTPie cargue los datos crudos desde un archivo:


$ http pie.dev/post @datos.txt

Opciones de procesamiento de contenido

--compress, -x

Contenido comprimido (codificado) con el algoritmo Deflate. La cabecera Content-Encoding se establece a deflate.

La compresión se omite si parece que la relación de compresión es negativa. La compresión se puede forzar repitiendo el argumento.

Procesamiento de salida

--pretty

Controla el procesamiento de la salida. El valor puede ser "none" para no embellecer la salida (por defecto para salida redirigida), "all" para aplicar tanto colores como formato (por defecto para salida de terminal), "colors", o "format".

--style, -s ESTILO

Estilo de coloración de salida (por defecto es "auto"). Puede ser uno de:


auto, pie, pie-dark, pie-light, solarized

Para descubrir todos los estilos disponibles en su sistema, pruebe:

$ http --style

El estilo "auto" sigue los estilos de color ANSI de su terminal. Para que los estilos no automáticos funcionen correctamente, asegúrese de que la variable de entorno $TERM esté establecida a "xterm-256color" o similar (por ejemplo, a través de `export TERM=xterm-256color' en su ~/.bashrc).

--unsorted

Deshabilita toda la clasificación al formatear la salida. Es un atajo para:


--format-options=headers.sort:false,json.sort_keys:false

--sorted

Vuelve a habilitar todas las opciones de clasificación al formatear la salida. Es un atajo para:


--format-options=headers.sort:true,json.sort_keys:true

--response-charset CODIFICACIÓN

Anula la codificación de respuesta para fines de visualización en terminal, por ejemplo:


--response-charset=utf8
--response-charset=big5

--response-mime TIPO_MIME

Anula el tipo MIME de respuesta para colorear y formatear para la terminal, por ejemplo:


--response-mime=application/json
--response-mime=text/xml

--format-options

Controla el formato de salida. Solo relevante cuando el formato está habilitado a través de (explícito o implícito) --pretty=all o --pretty=format. Las siguientes son las opciones por defecto:


headers.sort:true
json.format:true
json.indent:4
json.sort_keys:true
xml.format:true
xml.indent:2

Puede usar esta opción varias veces, así como especificar múltiples opciones separadas por comas
