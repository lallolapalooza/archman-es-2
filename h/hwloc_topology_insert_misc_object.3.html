Documentación del Tipo de Enumeración

enum hwloc_allow_flags_e

Banderas para pasar a hwloc_topology_allow().

Enumerator

HWLOC_ALLOW_FLAG_ALL
Marca todos los objetos como permitidos en la topología. El cpuset y nodeset pasados a hwloc_topology_allow() deben ser NULL.
HWLOC_ALLOW_FLAG_LOCAL_RESTRICTIONS
Solo permite objetos que están disponibles para el proceso actual. La topología debe tener HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM para que el conjunto de recursos disponibles pueda ser realmente recuperado del sistema operativo.

El cpuset y nodeset pasados a hwloc_topology_allow() deben ser NULL.

HWLOC_ALLOW_FLAG_CUSTOM
Permite un conjunto personalizado de objetos, pasados a hwloc_topology_allow() como parámetros cpuset y/o nodeset.

enum hwloc_restrict_flags_e

Banderas para pasar a hwloc_topology_restrict().

Enumerator

HWLOC_RESTRICT_FLAG_REMOVE_CPULESS
Elimina todos los objetos que se han quedado sin CPU. Por defecto, solo se eliminan los objetos que no contienen ninguna PU ni memoria. Esta bandera no puede usarse con HWLOC_RESTRICT_FLAG_BYNODESET.
HWLOC_RESTRICT_FLAG_BYNODESET
Restringe por nodeset en lugar de por cpuset. Solo conserva los objetos cuyo nodeset esté incluido o parcialmente incluido en el conjunto dado. Esta bandera no puede usarse con HWLOC_RESTRICT_FLAG_REMOVE_CPULESS.
HWLOC_RESTRICT_FLAG_REMOVE_MEMLESS
Elimina todos los objetos que se han quedado sin memoria. Por defecto, solo se eliminan los objetos que no contienen ninguna PU ni memoria. Esta bandera solo puede usarse con HWLOC_RESTRICT_FLAG_BYNODESET.
HWLOC_RESTRICT_FLAG_ADAPT_MISC
Mueve los objetos Misc a sus ancestros si sus padres son eliminados durante la restricción. Si esta bandera no está activada, los objetos Misc se eliminan cuando sus padres son eliminados.
HWLOC_RESTRICT_FLAG_ADAPT_IO
Mueve los objetos de E/S a sus ancestros si sus padres son eliminados durante la restricción. Si esta bandera no está activada, los dispositivos de E/S y los puentes se eliminan cuando sus padres son eliminados.

int hwloc_obj_add_other_obj_sets (hwloc_obj_t dst, hwloc_obj_t src)

Configura los cpusets/nodesets de objetos mediante la operación OR con los conjuntos de otro objeto. Para cada cpuset o nodeset definido en src, asigna el conjunto correspondiente en dst y añade src a él mediante la operación OR de conjuntos.

Esta función es útil entre hwloc_topology_alloc_group_object() y hwloc_topology_insert_group_object(). Construye los conjuntos del nuevo Grupo que se insertará como un nuevo padre intermedio de varios objetos.

Retorna

0 en caso de éxito.

-1 con errno establecido a ENOMEM si alguna reasignación interna falló.

hwloc_obj_t hwloc_topology_alloc_group_object (hwloc_topology_t topology)

Asigna un objeto Grupo para insertarlo más tarde con hwloc_topology_insert_group_object(). Esta función devuelve un nuevo objeto Grupo.

El llamador debe (al menos) inicializar sus conjuntos antes de insertar el objeto en la topología, ver hwloc_topology_insert_group_object(). O puede decidir no insertarlo y simplemente liberar el objeto grupo llamando a hwloc_topology_free_group_object().

Retorna

El objeto asignado en caso de éxito.

NULL en caso de error.

Nota

Si se inserta correctamente mediante hwloc_topology_insert_group_object(), el objeto se liberará cuando se libere toda la topología. Si la inserción falla (por ejemplo, conjuntos de CPU y nodo NULL o vacíos), se libera antes de devolver el error.

int hwloc_topology_allow (hwloc_topology_t restrict topology, hwloc_const_cpuset_t cpuset, hwloc_const_nodeset_t nodeset, unsigned long flags)

Cambia los conjuntos de PUs y nodos NUMA permitidos en la topología. Esta función solo funciona si la bandera HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED fue establecida en la topología. No modifica ningún objeto, solo cambia los conjuntos devueltos por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset().

Es particularmente útil al importar una topología desde otro proceso que se ejecuta en un Cgroup de Linux diferente.

flags debe establecerse a una bandera entre hwloc_allow_flags_e.

Retorna

0 en caso de éxito, -1 en caso de error.

Nota

La eliminación de objetos de una topología debería realizarse preferentemente con hwloc_topology_restrict().

int hwloc_topology_free_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Libera un objeto Grupo previamente asignado con hwloc_topology_alloc_group_object(). Este objeto no debe haber sido insertado en la topología aún. Si fue insertado, debe ser liberado primero con hwloc_topology_remove_object().

Retorna

0 en caso de éxito.

-1 con errno establecido a EINVAL si el objeto ya está insertado en la topología.

int hwloc_topology_insert_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Inserta un objeto Grupo en la topología. El objeto Grupo, previamente asignado con hwloc_topology_alloc_group_object(), se inserta como un nuevo padre intermedio de los objetos cuyos conjuntos están definidos en el mismo.

El objeto Grupo debe tener sus conjuntos de CPU y nodo definidos (posiblemente vacíos, pero no nulos) usando hwloc_obj_set_cpuset() y hwloc_obj_set_nodeset(). Si los conjuntos están vacíos, el objeto Grupo no se insertará y será liberado automáticamente.

Si el objeto Grupo se inserta, se convierte en propiedad de la topología y será liberado cuando la topología se libere. Si no se puede insertar, será liberado automáticamente.

Retorna

0 en caso de éxito.

-1 con errno establecido a ENOMEM si la asignación de memoria falló, o EINVAL si los conjuntos de CPU y nodo son nulos o vacíos.

hwloc_obj_t hwloc_topology_insert_misc_object (hwloc_topology_t topology, hwloc_obj_t parent, const char *name)

Inserta un nuevo objeto de tipo Misc. Este objeto no tiene conjunto de CPU ni de memoria, pero puede tener atributos arbitrarios (nombre, etc.). Se puede utilizar para anotar la topología con información arbitraria.

El nuevo objeto Misc se inserta como hijo de parent. Si parent es NULL, el objeto Misc se inserta en la raíz de la topología.

Si el objeto Misc se inserta, se convierte en propiedad de la topología y será liberado cuando la topología se libere.

Retorna

El nuevo objeto Misc en caso de éxito.

NULL en caso de error (por ejemplo, si parent no es un objeto válido o si la memoria no se pudo asignar).

int hwloc_topology_refresh (hwloc_topology_t topology)

Vuelve a descubrir la topología del sistema y actualiza el objeto de topología dado. Esto es útil si la topología del sistema ha cambiado desde que se cargó o modificó por última vez (por ejemplo, si se han conectado o desconectado dispositivos de E/S en caliente, o si se han modificado los cpusets).

Retorna

0 en caso de éxito.

-1 con errno establecido a ENOMEM si la asignación de memoria falló.

int hwloc_topology_restrict (hwloc_topology_t restrict topology, hwloc_const_bitmap_t set, unsigned long flags)

Restringe la topología visible para el proceso actual. La topología resultante solo contendrá los objetos que están completamente dentro del conjunto dado set (que es un cpuset por defecto, o un nodeset si HWLOC_RESTRICT_FLAG_BYNODESET está activado).

Los objetos que no estén completamente contenidos en el conjunto resultante serán eliminados, junto con todos sus descendientes que también quedan fuera del conjunto resultante. Los objetos parcialmente contenidos serán eliminados, a menos que se mantengan indirectamente debido a la presencia de otros objetos completamente contenidos en ellos.

0 on success, -1 on error.

int hwloc_topology_free_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Libera un objeto de grupo asignado con hwloc_topology_alloc_group_object(). Esta función solo es útil si el objeto de grupo no se le pasó a hwloc_topology_insert_group_object() según lo planeado.

hwloc_obj_t hwloc_topology_insert_group_object (hwloc_topology_t topology, hwloc_obj_t group)

Agrega más estructura a la topología agregando un Grupo intermedio. El llamador primero debe asignar un nuevo objeto de Grupo con hwloc_topology_alloc_group_object(). Luego, debe configurar al menos uno de sus conjuntos de CPU o nodos para especificar la ubicación final del Grupo en la topología. Luego, el objeto se puede pasar a esta función para su inserción real en la topología.

El caso de uso principal para esta función es agrupar un subconjunto de hermanos de la lista de hijos debajo de un solo padre. Por ejemplo, si se agrupan 4 núcleos de un socket de 8 núcleos, la lista lógica de núcleos se reordenará para que los 4 agrupados sean consecutivos. Luego, si es necesario, se agrega una nueva profundidad entre el padre y esos hijos, y el Grupo se inserta allí. Al final, los 4 núcleos agrupados ahora son hijos del Grupo, que los reemplaza como hijo del padre original.

En la práctica, los objetos agrupados se especifican a través de conjuntos de CPU (cpusets) y/o conjuntos de nodos (nodesets), por ejemplo, usando hwloc_obj_add_other_obj_sets() iterativamente. Por lo tanto, es posible agrupar objetos que no son hijos del mismo padre, por ejemplo, algunas PUs debajo de los 4 núcleos en el ejemplo anterior. Sin embargo, este caso general puede fallar si el Grupo esperado entra en conflicto con la jerarquía existente. Por ejemplo, si cada núcleo tiene dos PUs, no es posible insertar un Grupo que contenga una sola PU de cada núcleo.

Para especificar los objetos a agrupar, el campo cpuset o nodeset (o ambos, si son compatibles) debe configurarse en un mapa de bits no vacío. El complete_cpuset o complete_nodeset pueden configurarse en su lugar si se inserta con respecto a la topología completa (incluidos los objetos no permitidos, fuera de línea o desconocidos). Estos conjuntos no pueden ser más grandes que la topología actual, o se restringirán silenciosamente. El núcleo configurará los otros conjuntos después de la inserción real.

El atributo de objeto subtype puede definirse con hwloc_obj_set_subtype() para mostrar algo más que 'Group' como el nombre del tipo para este objeto en lstopo. Los pares de información personalizados de nombre-valor se pueden agregar con hwloc_obj_add_info() después de la inserción.

El atributo group dont_merge puede configurarse en 1 para evitar que el núcleo de hwloc fusione este objeto con otro objeto jerárquicamente idéntico. Esto es útil cuando el Grupo en sí describe una característica importante que no se puede exponer en ningún otro lugar de la jerarquía.

El atributo group kind puede configurarse en un valor alto como 0xffffffff para decirle a hwloc que este nuevo Grupo siempre debe descartarse en favor de cualquier Grupo existente con la misma localidad.

Nota

La inserción de un grupo agrega información de localidad a la topología, por lo tanto, los objetos existentes pueden reordenarse (incluidas las PUs y los nodos NUMA), y sus índices lógicos pueden cambiar.

Si la inserción falla, el objeto de grupo de entrada se libera.

Si el objeto de grupo debe ser descartado en lugar de insertado, puede pasarse a hwloc_topology_free_group_object() en su lugar.

topology debe ser el mismo que se pasó previamente a hwloc_topology_alloc_group_object().

Devuelve

El objeto insertado si se insertó correctamente.

Un objeto existente si el Grupo se fusionó o descartó porque la topología ya contenía un objeto en la misma ubicación (el Grupo no agregó información de jerarquía).

NULL si la inserción falló debido a conflictos en los conjuntos del árbol de topología.

NULL si los objetos de Grupo están filtrados de la topología (HWLOC_TYPE_FILTER_KEEP_NONE).

NULL si el objeto fue descartado porque no se inicializó ningún conjunto en el Grupo antes de la inserción, o todos estaban vacíos.

hwloc_obj_t hwloc_topology_insert_misc_object (hwloc_topology_t topology, hwloc_obj_t parent, const char * name)

Agrega un objeto MISC como hoja de la topología. Se creará un nuevo objeto MISC y se insertará en la topología en la posición dada por parent. Se anexa a la lista de hijos Misc existentes, sin agregar nunca un nivel de jerarquía intermedio. Esto es útil para anotar la topología sin cambiar realmente la jerarquía.

name se supone que es único entre todos los objetos Misc en la topología. Se duplicará para configurar los atributos del nuevo objeto.

El nuevo objeto hoja no tendrá ningún cpuset.

El atributo de objeto subtype puede definirse con hwloc_obj_set_subtype() después de la inserción exitosa.

Devuelve

el objeto recién creado

NULL en caso de error.

NULL si los objetos Misc están filtrados de la topología (HWLOC_TYPE_FILTER_KEEP_NONE).

Nota

Si name contiene caracteres no imprimibles, se eliminarán al exportar a XML, consulte hwloc_topology_export_xml() en hwloc/export.h.

int hwloc_topology_refresh (hwloc_topology_t topology)

Refresca las estructuras internas después de la modificación de la topología. Modificar la topología (restringiendo, agregando objetos, modificando estructuras como distancias o atributos de memoria, etc.) puede hacer que algunas cachés internas se vuelvan inválidas. Estas cachés se refrescan automáticamente cuando se accede a ellas, pero este refresco no es seguro para subprocesos.

Esta función tampoco es segura para subprocesos, pero es una buena manera de finalizar una fase de modificación de topología que no es segura para subprocesos. Una vez que se realiza este refresco, varios subprocesos pueden consultar la topología, objetos, distancias, atributos, etc., concurrentemente.

Ver también Seguridad de subprocesos

Devuelve

0 en caso de éxito.

-1 en caso de error, por ejemplo, si alguna reasignación interna falló.

int hwloc_topology_restrict (hwloc_topology_t restrict topology, hwloc_const_bitmap_t set, unsigned long flags)

Restringe la topología al conjunto de CPU o conjunto de nodos dado. La topología topology se modifica para eliminar todos los objetos que no están incluidos (o parcialmente incluidos) en el conjunto de CPU set. Todos los conjuntos de CPU y nodos de objetos se restringen en consecuencia.

Por defecto, set es un conjunto de CPU. Esto significa que el conjunto de PUs en la topología se restringe. Una vez que se eliminan algunas PUs, sus padres también pueden eliminarse recursivamente si se quedan sin hijos.

Si HWLOC_RESTRICT_FLAG_BYNODESET se pasa en flags, set se considera un conjunto de nodos en lugar de un conjunto de CPU. Esto significa que el conjunto de nodos NUMA en la topología se restringe (en lugar de las PUs). Una vez que se eliminan algunos nodos NUMA, sus padres también pueden eliminarse recursivamente si se quedan sin hijos.

flags es un conjunto OR'ed de hwloc_restrict_flags_e.

Nota

Restringir la topología elimina información de localidad, por lo tanto, los objetos restantes pueden reordenarse (incluidas las PUs y los nodos NUMA), y sus índices lógicos pueden cambiar.

Esta llamada puede no ser revertida al restringir de nuevo a un conjunto más grande. Una vez eliminados durante la restricción, los objetos no se pueden recuperar, excepto cargando otra topología con hwloc_topology_load().

Devuelve

0 en caso de éxito.

-1 con errno establecido en EINVAL si el conjunto de entrada es inválido. La topología no se modifica en este caso.

-1 con errno establecido en ENOMEM en caso de fallo al asignar datos internos. La topología se reinicializa en este caso. Debería ser destruida con hwloc_topology_destroy() o configurada y cargada nuevamente.
