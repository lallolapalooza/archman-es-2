Descripción detallada

Varias funciones se pueden llamar opcionalmente entre hwloc_topology_init() y hwloc_topology_load() para configurar cómo se debe realizar la detección, por ejemplo, para ignorar algunos tipos de objetos, definir una topología sintética, etc.

Documentación del tipo de enumeración

enum hwloc_topology_flags_e

Flags para ser establecidos en un contexto de topología antes de la carga. Los flags deben ser dados a hwloc_topology_set_flags(). También pueden ser devueltos por hwloc_topology_get_flags().

Enumerador

HWLOC_TOPOLOGY_FLAG_INCLUDE_DISALLOWED
Detecta todo el sistema, ignora las reservas, incluye objetos no permitidos. Recopila todos los recursos en línea, incluso si algunos fueron deshabilitados por el administrador. Por ejemplo, ignora Cgroup/Cpusets de Linux y recopila todos los procesadores y nodos de memoria. Sin embargo, las PU y los nodos NUMA fuera de línea todavía se ignoran.

Cuando este flag no está establecido, las PU y los nodos NUMA que no están permitidos no se agregan a la topología. Los objetos padres (paquete, núcleo, caché, etc.) se agregan solo si algunos de sus hijos están permitidos. Todas las PU y nodos NUMA existentes en la topología están permitidos. hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset() son iguales al conjunto de CPU y al conjunto de nodos del objeto raíz.

Cuando este flag está establecido, los conjuntos reales de PU y nodos NUMA permitidos se dan por hwloc_topology_get_allowed_cpuset() y hwloc_topology_get_allowed_nodeset(). Pueden ser más pequeños que el conjunto de CPU y el conjunto de nodos del objeto raíz.

Si la topología actual se exporta a XML y se reimporta más tarde, este flag debe establecerse nuevamente en la topología reimportada para que los recursos no permitidos también se reimporten.

HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM
Asume que el backend seleccionado proporciona la topología para el sistema en el que estamos ejecutando. Esto fuerza a que hwloc_topology_is_thissystem() devuelva 1, es decir, hace que hwloc suponga que el backend seleccionado proporciona la topología para el sistema en el que estamos ejecutando, incluso si no es el backend específico del SO sino el backend XML, por ejemplo. Esto significa que las funciones de vinculación llamarán realmente a las llamadas del sistema específicas del SO y realmente harán la vinculación, mientras que el backend XML de lo contrario proporcionaría ganchos vacíos que simplemente devuelven éxito.

Establecer la variable de entorno HWLOC_THISSYSTEM también puede resultar en el mismo comportamiento.

Esto se puede usar por razones de eficiencia para detectar primero la topología una vez, guardarla en un archivo XML y recargarla rápidamente más tarde a través del backend XML, pero aún así tener funciones de vinculación que realmente vinculan.

HWLOC_TOPOLOGY_FLAG_THISSYSTEM_ALLOWED_RESOURCES
Obtiene el conjunto de recursos permitidos del sistema operativo local, incluso si la topología se cargó desde XML o desde una descripción sintética. Si la topología se cargó desde XML o desde una cadena sintética, restringe aplicando las restricciones del proceso actual, como Cgroup/Cpuset de Linux.

Esto es útil cuando la topología no se carga directamente de la máquina local (por ejemplo, por razones de rendimiento) y viene con todos los recursos, mientras que el proceso en ejecución está restringido a solo partes de la máquina.

Este flag se ignora a menos que HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM también se establezca, ya que la topología cargada debe coincidir con la máquina subyacente de la que se recopilarán las restricciones.

Establecer la variable de entorno HWLOC_THISSYSTEM_ALLOWED_RESOURCES daría como resultado el mismo comportamiento.

HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT
Importa el soporte desde la topología importada. Al importar una topología XML desde una máquina remota, la vinculación está deshabilitada por defecto (ver HWLOC_TOPOLOGY_FLAG_IS_THISSYSTEM). Esta deshabilitación también se marca poniendo ceros en los bits correspondientes de características soportadas informados por hwloc_topology_get_support().

El flag HWLOC_TOPOLOGY_FLAG_IMPORT_SUPPORT en realidad importa los bits de soporte de la máquina remota. También establece el flag imported_support en la estructura hwloc_topology_misc_support. Si el XML importado no contenía información de soporte (el exportador de hwloc es demasiado antiguo), este flag no se establece.

Tenga en cuenta que estas características soportadas solo son relevantes para la instalación de hwloc que realmente exportó la topología XML (puede variar según el sistema operativo o según cómo se compiló hwloc).

Tenga en cuenta que establecer este flag, sin embargo, no habilita la vinculación para la topología local importada de hwloc, solo informa lo que el hwloc y la máquina remotos soportan.

No considerar recursos fuera de la vinculación de CPU del proceso. Si la vinculación del proceso está limitada a un subconjunto de núcleos, ignorar los otros núcleos durante

Detailed Description

These functions all modify the configuration of a topology object before it is loaded (using hwloc_topology_load(3)).

They are usually called between hwloc_topology_init(3) and hwloc_topology_load(3).

hwloc_topology_set_all_types_filter(), hwloc_topology_set_cache_types_filter(), hwloc_topology_set_icache_types_filter(), hwloc_topology_set_io_types_filter() and hwloc_topology_set_type_filter() configure filtering of objects.

hwloc_topology_set_flags() configures miscellaneous flags.

hwloc_topology_set_userdata() lets the application attach private data to the topology object.

Enumeration Type Documentation

enum hwloc_type_filter_e

This is the type of filtering value passed to the set_filter functions.

HWLOC_TYPE_FILTER_KEEP

Keep objects of the specified type.

HWLOC_TYPE_FILTER_REMOVE

Remove objects of the specified type.

HWLOC_TYPE_FILTER_SHALLOW_REMOVE

Remove objects of the specified type, but keep their children.

HWLOC_TYPE_FILTER_LAST

The number of filtering values. This is not a filtering value itself.

Function Documentation

int hwloc_topology_set_all_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all object types. If some types do not support this filtering, they are silently ignored.

Returns

0 on success, -1 on error.

int hwloc_topology_set_cache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all CPU cache object types. Memory-side caches are not involved since they are not CPU caches.

Returns

0 on success, -1 on error.

int hwloc_topology_set_flags (hwloc_topology_t topology, unsigned long flags)

Set OR'ed flags to non-yet-loaded topology. Set a OR'ed set of hwloc_topology_flags_e onto a topology that was not yet loaded.

If this function is called multiple times, the last invocation will erase and replace the set of flags that was previously set.

By default, no flags are set (0).

The flags set in a topology may be retrieved with hwloc_topology_get_flags().

Returns

0 on success.

-1 on error, for instance if flags are invalid.

int hwloc_topology_set_icache_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all CPU instruction cache object types. Memory-side caches are not involved since they are not CPU caches.

Returns

0 on success, -1 on error.

int hwloc_topology_set_io_types_filter (hwloc_topology_t topology, enum hwloc_type_filter_e filter)

Set the filtering for all I/O object types.

Returns

0 on success, -1 on error.

int hwloc_topology_set_type_filter (hwloc_topology_t topology, hwloc_obj_type_t type, enum hwloc_type_filter_e filter)

Set the filtering for the given object type.

Returns

0 on success, -1 on error.

void hwloc_topology_set_userdata (hwloc_topology_t topology, const void * userdata)

Set the topology-specific userdata pointer. Each topology may store one application-given private data pointer. It is initialized to NULL. hwloc will never modify it.

Use it as you wish, after hwloc_topology_init() and until hwloc_topolog_destroy().

This pointer is not exported to XML.
