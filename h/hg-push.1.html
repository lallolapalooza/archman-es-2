HG(PUSH) HG(PUSH)

NOMBRE

hg push - enviar cambios al destino especificado

SINOPSIS

hg push [-f] [-rREV]... [-e CMD] [--remotecmd CMD] [DEST]...

DESCRIPCIÓN

Envía los conjuntos de cambios del repositorio local al destino especificado.

Esta operación es simétrica a la de pull: es idéntica a un pull en el repositorio de destino desde el actual.

Por defecto, push no permitirá la creación de nuevas cabezas en el destino, ya que múltiples cabezas harían confuso cuál usar. En esta situación, se recomienda hacer pull y merge antes de push.

Usa --new-branch si deseas permitir que push cree una nueva rama nombrada que no esté presente en el destino. Esto te permite crear una nueva rama sin forzar otros cambios.

Nota
Se debe tener especial cuidado con la opción -f/--force, que enviará todas las nuevas cabezas en todas las ramas, una acción que casi siempre causará confusión a los colaboradores.

Si se usa -r/--rev, la revisión especificada y todos sus ancestros se enviarán al repositorio remoto.

Si se usa -B/--bookmark, la revisión marcada especificada, sus ancestros y la marca se enviarán al repositorio remoto. Especificar . es equivalente a especificar el nombre de la marca activa. Usa la opción --all-bookmarks para enviar todas las marcas actuales.

Por favor, consulta hg help urls para detalles importantes sobre las URLs ssh://. Si se omite DESTINATION, se utilizará una ruta predeterminada.

Cuando se pasan múltiples destinos, push los procesará uno tras otro, pero se detendrá si ocurre un error.

La opción --pushvars envía cadenas al servidor que se convierten en variables de entorno precedidas por HG_USERVAR_. Por ejemplo, --pushvars ENABLE_FEATURE=true, proporciona a los hooks del lado del servidor HG_USERVAR_ENABLE_FEATURE=true como parte de su entorno.

pushvars puede proporcionar hooks personalizables por el usuario, así como establecer niveles de depuración. Un ejemplo es tener un hook que bloquee commits que contengan marcadores de conflicto, pero permita al usuario anular el hook si el archivo se utiliza con marcadores de conflicto para fines de prueba o si el formato del archivo tiene cadenas que parecen marcadores de conflicto.

Por defecto, los servidores ignorarán --pushvars. Para habilitarlo, añade lo siguiente a tu archivo de configuración:

[push]
pushvars.server = true

Devuelve 0 si el push fue exitoso, 1 si no hay nada que enviar.

OPCIONES

-f, --force
forzar el envío
-r,--rev <REV[+]>
un conjunto de cambios destinado a ser incluido en el destino
-B,--bookmark <BOOKMARK[+]>
marca a enviar
--all-bookmarks
enviar todas las marcas (EXPERIMENTAL)
-b,--branch <BRANCH[+]>
una rama específica que deseas enviar
--new-branch
permitir enviar una nueva rama
--pushvars <VALUE[+]>
variables que se pueden enviar al servidor (AVANZADO)
--publish
enviar el conjunto de cambios como público (EXPERIMENTAL)
-e,--ssh <CMD>
especificar el comando ssh a usar
--remotecmd <CMD>
especificar el comando hg a ejecutar en el lado remoto
--insecure
no verificar el certificado del servidor (ignorando la configuración web.cacerts)

[+] la opción marcada se puede especificar varias veces
