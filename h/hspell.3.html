NOMBRE

hspell - Corrector ortográfico hebreo (API C)

SINOPSIS

#include <hspell.h>

int hspell_init(struct dict_radix **dictp, int flags);

void hspell_uninit(struct dict_radix *dictp);

int hspell_check_word(struct dict_radix *dict, const char *word, int *preflen);

void hspell_trycorrect(struct dict_radix *dict, const char *word, struct corlist *cl);

int corlist_init(struct corlist *cl);

int corlist_free(struct corlist *cl);

int corlist_n(struct corlist *cl);

char *corlist_str(struct corlist *cl, int i);

unsigned int hspell_is_canonic_gimatria(const char *word);

typedef int hspell_word_split_callback_func(const char *word, const char *baseword, int preflen, int prefspec);

int hspell_enum_splits(struct dict_radix *dict, const char *word, hspell_word_split_callback_func *enumf);

void hspell_set_dictionary_path(const char *path);

const char *hspell_get_dictionary_path(void);

DESCRIPCIÓN

Este manual describe la API C del corrector ortográfico hebreo Hspell. Por favor, consulte hspell(1) para una descripción del proyecto Hspell, su estándar de ortografía y cómo funciona.

La función hspell_init() debe ser llamada primero para inicializar la biblioteca Hspell. Configura algunas estructuras globales (ver sección CAVEATS) y luego lee los archivos de diccionario necesarios (cuyas ubicaciones son fijas cuando se construye la biblioteca). El parámetro 'dictp' es un puntero a un objeto struct dict_radix*, que se modifica para apuntar a un diccionario recién asignado. Por lo tanto, una llamada típica a hspell_init() se ve así:


struct dict_radix *dict;
hspell_init(&dict, flags);

Tenga en cuenta que el tipo (struct dict_radix*) es un puntero opaco: el usuario de la biblioteca no tiene acceso a los campos separados de esta estructura.

El parámetro 'flags' puede contener una combinación OR bitwise de varias banderas que modifican el comportamiento predeterminado de Hspell; activar HSPELL_OPT_HE_SHEELA permite a Hspell reconocer el prefijo interrogativo He (he ha-she'ela). HSPELL_OPT_DEFAULT es un sinónimo de no activar ninguna bandera especial, es decir, se evalúa a 0.

hspell_init() devuelve 0 en caso de éxito, o números negativos en caso de errores. Actualmente, el único error es -1, lo que significa que los archivos de diccionario no se pudieron leer.

La función hspell_uninit() deshace los efectos de hspell_init(), liberando cualquier memoria que se haya asignado durante la inicialización.

La función hspell_check_word() comprueba si una palabra determinada es una palabra hebrea correcta (posiblemente con partículas de prefijo adjuntas de manera sintácticamente correcta). Se devuelve 1 si la palabra es correcta, o 0 si es incorrecta.

El parámetro 'word' debe ser una única palabra hebrea, en la codificación iso8859-8, que posiblemente contenga los caracteres de comillas simples o dobles ASCII (que significan el geresh y gershayim utilizados en hebreo para abreviaturas, acrónimos y algunos sonidos extranjeros). Si los programas que llaman funcionan con otras codificaciones, deben convertir la palabra a iso8859-8 primero. En particular, las extensiones de cp1255 (la codificación hebrea de MS-Windows) a iso8859-8, como los caracteres niqqud, geresh o gershayim, actualmente no son reconocidas y deben eliminarse de la palabra antes de llamar a hspell_check_word().

En el parámetro 'preflen', la función devuelve el número de caracteres que reconoció como partícula de prefijo; el resto de la 'palabra' es una palabra independiente. Debido a que las palabras hebreas típicamente pueden leerse de varias maneras diferentes, esta característica (de obtener solo un prefijo de una lectura posible) generalmente no es muy útil y es probable que se elimine en una versión futura.

La función hspell_enum_splits() proporciona una forma de obtener todas las divisiones posibles de la 'palabra' dada en un prefijo opcional y una palabra independiente. Para cada división posible y legal (ya que algunas palabras no pueden aceptar ciertos prefijos), se llama a una función de devolución de llamada definida por el usuario. A esta función de devolución de llamada se le da la palabra completa, la longitud del prefijo, la palabra independiente y un campo de bits que describe qué tipos de palabras puede tener este prefijo. Tenga en cuenta que en algunos casos, una palabra que comienza con la letra waw obtiene esta waw duplicada antes de un prefijo, por lo que a veces strlen(word)!=strlen(baseword)+preflen.

La función hspell_trycorrect() intenta encontrar una lista de posibles correcciones para una palabra incorrecta. Debido a que en hebreo la densidad de palabras es alta (una cadena aleatoria de letras, especialmente si es corta, tiene una alta probabilidad de ser una palabra correcta), esta función intenta probar correcciones basadas en la suposición de un error de ortografía (reemplazo de letras que suenan similar, falta o exceso de inversión), no de error tipográfico (dedo resbalado en el teclado, etc.) - ver también CAVEATS.

hspell_trycorrect() devuelve la lista de correcciones en una estructura de tipo struct corlist. Esta estructura debe ser inicialmente asignada con una llamada a corlist_init() y posteriormente liberada con corlist_free(). La macro corlist_n() devuelve el número de palabras contenidas en una corlist asignada, y corlist_str() devuelve la i-ésima palabra. Correspondientemente, aquí hay un ejemplo de uso de hspell_trycorrect():


struct corlist cl;
printf ("Encontrada palabra mal escrita %s. Posibles correcciones:\n", w);
corlist_init (&cl);
hspell_trycorrect (dict, w, &cl);
for (i=0; i<corlist_n(&cl); i++) {
printf ("%s\n", corlist_str(&cl, i));
}

La función hspell_is_canonic_gimatria() comprueba si la palabra dada es una gimatria canónica, es decir, la forma correcta de escribir en gimatria el número que representa. El llamador puede desear aceptar gimatria canónica como palabras hebreas correctas, incluso si hspell_check_word() previamente informó que dicha palabra era una palabra inexistente. hspell_is_canonic_gimatria() devuelve el número representado como gimatria en 'word' si es de hecho gimatria correcta (en forma canónica), o 0 en caso contrario.

hspell_init() normalmente lee los archivos de diccionario desde una ruta compilada en la biblioteca. Esto tiene sentido cuando el código de la biblioteca y los diccionarios se distribuyen juntos, pero en algunos escenarios el usuario de la biblioteca podría querer usar los diccionarios Hspell que ya están presentes en el sistema en una ruta arbitraria. La función hspell_set_dictionary_path() puede usarse para establecer esta ruta, y debe usarse antes de llamar a hspell_init(). La ruta dada es la de la lista de palabras, y otros archivos de entrada tienen esa ruta con un prefijo agregado. hspell_get_dictionary_path() puede usarse para encontrar la ruta actual. En muchas instalaciones, esto por defecto es "/usr/local/share/hspell/hebrew.wgz".

ENLAZADO

En la mayoría de los sistemas, la biblioteca Hspell se compila para usar la biblioteca Zlib para leer los diccionarios comprimidos. Por lo tanto, un programa enlazado con la biblioteca Hspell también debe enlazarse con la biblioteca Zlib (generalmente, agregando "-lz" a la línea de compilación).

Los programas que usan autoconf para buscar la biblioteca Hspell deben recordar decirle a AC_CHECK_LIB que también enlace con la biblioteca -lz al verificar -lhspell.

ADVERTENCIAS

Aunque la API descrita aquí ha sido estable durante años, puede cambiar en el futuro. Se anima a los usuarios a comparar los valores de las macros enteras HSPELL_VERSION_MAJOR y HSPELL_VERSION_MINOR con los esperados por el autor del programa. Una tercera macro, HSPELL_VERSION_EXTRA, contiene una cadena que puede describir modificaciones de sub-lanzamiento (por ejemplo, versiones beta).

La API C actual de Hspell es de muy bajo nivel, en el sentido de que deja al usuario la implementación de muchas características que algunos usuarios dan por sentado que un corrector ortográfico debería proporcionar. Por ejemplo, no ofrece ninguna facilidad para un diccionario personal definido por el usuario. También tiene funciones separadas para verificar palabras hebreas válidas y gimatria válida, y ninguna función para hacer ambas cosas. Se asume que el llamador, una biblioteca de corrección ortográfica más grande o un procesador de textos (por ejemplo), ya tendrá estas facilidades. Si no es así, puede que desee consultar las fuentes de hspell(1) para ver un ejemplo de implementación.

Actualmente no existe el concepto de Hspell separado

"contextos" en una aplicación. Parte del contexto es ahora global para toda la aplicación: actualmente, se mantiene una única lista de partículas prefijas legales, y el diccionario leído por hspell_init() siempre se lee del lugar predeterminado global. Esto puede resolverse en una versión posterior, por ejemplo, cambiando a una API como:


context = hspell_new_context();
hspell_set_dictionary_path(context, "/some/path/hebrew.wgz");
hspell_init(context, flags);
...
hspell_check_word(context, word, preflenp);

Nótese que a pesar del contexto global mencionado anteriormente, después de la inicialización todas las funciones descritas aquí son seguras para hilos, porque solo leen los datos del diccionario, no escriben en ellos.

hspell_trycorrect() no es tan potente como podría serlo, con errores tipográficos o ciertos tipos de errores ortográficos que no ofrecen sugerencias de corrección útiles. Junto con más tipos de correcciones, hspell_trycorrect() necesita una mejor manera de ordenar la probabilidad de las correcciones, ya que una lista desordenada de 100 correcciones sería tan útil (o más bien, inútil) como ninguna.

En algunos casos de errores durante hspell_init(), se imprimen mensajes de advertencia en la salida de error estándar. Esto es algo malo para una biblioteca.
