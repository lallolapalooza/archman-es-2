Descripción detallada

El tipo hwloc_bitmap_t representa un conjunto de enteros (positivos o nulos). Un mapa de bits puede ser de tamaño infinito (todos los bits están activados después de algún punto). Un mapa de bits incluso puede estar completo si todos los bits están activados.

Los mapas de bits son utilizados por hwloc para conjuntos de procesadores del sistema operativo (que en realidad pueden ser hilos de hardware) como hwloc_cpuset_t (un typedef para hwloc_bitmap_t), o conjuntos de nodos de memoria NUMA como hwloc_nodeset_t (también un typedef para hwloc_bitmap_t). Estos se utilizan para los campos cpuset y nodeset en la estructura hwloc_obj, ver Conjuntos de objetos (hwloc_cpuset_t y hwloc_nodeset_t).

Tanto los conjuntos de CPU como los de nodos siempre están indexados por el número físico del sistema operativo. Sin embargo, los usuarios generalmente no deberían construir conjuntos de CPU y nodos manualmente (por ejemplo, con hwloc_bitmap_set()). En su lugar, deberían usar los conjuntos de objetos existentes y combinarlos con hwloc_bitmap_or(), etc. Por ejemplo, vincular el hilo actual a un par de núcleos puede realizarse con:

hwloc_obj_t core1 = ... , core2 = ... ;
hwloc_bitmap_t set = hwloc_bitmap_alloc();
hwloc_bitmap_or(set, core1->cpuset, core2->cpuset);
hwloc_set_cpubind(topology, set, HWLOC_CPUBIND_THREAD);
hwloc_bitmap_free(set);

Nota

La mayoría de las funciones a continuación devuelven 0 en caso de éxito y -1 en caso de error. El caso de error habitual sería un fallo interno al reasignar/extender el almacenamiento del mapa de bits (errno se establecería en ENOMEM). Ver también Informes de errores en la API.

Varios ejemplos del uso de la API de mapas de bits están disponibles en el directorio doc/examples/ en el árbol de fuentes. Las pruebas de regresión como tests/hwloc/hwloc_bitmap*.c también hacen un uso intensivo de esta API.

Documentación de definición de macro

#define hwloc_bitmap_foreach_begin(id, bitmap)

Macro de bucle que itera sobre el mapa de bits bitmap. El bucle debe comenzar con hwloc_bitmap_foreach_begin() y terminar con hwloc_bitmap_foreach_end() seguido de un punto y coma final.

id es la variable del bucle; debe ser un unsigned int. La primera iteración establecerá id al índice más bajo en el mapa de bits. Las iteraciones sucesivas recorrerán, en orden, todos los índices restantes activados en el mapa de bits. Para ser específicos: cada iteración devolverá un valor para id tal que hwloc_bitmap_isset(bitmap, id) sea verdadero.

La aserción previene que el bucle sea infinito si el mapa de bits está infinitamente activado.

#define hwloc_bitmap_foreach_end()

Fin de la macro de bucle que itera sobre un mapa de bits. Necesita un punto y coma final.

int hwloc_bitmap_compare (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los mapas de bits bitmap1 y bitmap2 en orden lexicográfico. Comparación lexicográfica de mapas de bits, comenzando por sus índices más altos. Compara primero los últimos índices, luego los penúltimos, etc. El mapa de bits vacío se considera menor que cualquier otro.

Devuelve

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

0 si los mapas de bits son iguales (contrariamente a hwloc_bitmap_compare_first()).

Por ejemplo, la comparación de los mapas de bits binarios 0011 y 0110 devuelve -1 (por lo tanto, 0011 se considera menor que 0110). La comparación de 00101 y 01010 también devuelve -1.

Nota

Esto es diferente de la inexistente hwloc_bitmap_compare_last() que solo compararía el índice más alto de cada mapa de bits.

int hwloc_bitmap_compare_first (hwloc_const_bitmap_t bitmap1, hwloc_const_bitmap_t bitmap2)

Compara los mapas de bits bitmap1 y bitmap2 usando su índice más bajo. Un mapa de bits se considera menor si su bit menos significativo es menor. El mapa de bits vacío se considera mayor que cualquier otro (porque su bit menos significativo no existe).

Devuelve

-1 si bitmap1 se considera menor que bitmap2.

1 si bitmap1 se considera mayor que bitmap2.

Por ejemplo, la comparación de los mapas de bits binarios 0011 y 0110 devuelve -1 (por lo tanto, 0011 se considera menor que 0110) porque el bit menos significativo de 0011 (0001) es menor que el bit menos significativo de 0110 (0010). La comparación de 01001 y 00110 también devolvería -1 por la misma razón.

Devuelve

0 si los mapas de bits se consideran iguales, incluso si no son estrictamente iguales. Simplemente necesitan tener el mismo bit menos significativo. Por ejemplo, la comparación de los mapas de bits binarios 0010 y 0110 devuelve 0 porque tienen el mismo bit menos significativo.
