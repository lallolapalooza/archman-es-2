NOMBRE

homed.conf, homed.conf.d - Archivos de configuración del gestor de cuentas/áreas de usuario

SINOPSIS

/etc/systemd/homed.conf
/run/systemd/homed.conf
/usr/local/lib/systemd/homed.conf
/usr/lib/systemd/homed.conf
/etc/systemd/homed.conf.d/*.conf
/run/systemd/homed.conf.d/*.conf
/usr/local/lib/systemd/homed.conf.d/*.conf
/usr/lib/systemd/homed.conf.d/*.conf

DESCRIPCIÓN

Estos archivos de configuración controlan los parámetros por defecto para las áreas de usuario/cuentas de usuario creadas y gestionadas por systemd-homed.service(8).

DIRECTORIOS DE CONFIGURACIÓN Y PREFERENCIA

La configuración por defecto se establece durante la compilación, por lo que la configuración solo es necesaria cuando es necesario desviarse de esos valores por defecto. El archivo de configuración principal se carga desde uno de los directorios listados en orden de prioridad, solo el primer archivo encontrado se utiliza: /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La versión del proveedor del archivo contiene entradas comentadas que muestran los valores por defecto como guía para el administrador. También se pueden crear anulaciones locales creando archivos de anulación, como se describe a continuación. El archivo de configuración principal también puede editarse para este propósito (o una copia en /etc/ si se distribuye bajo /usr/), sin embargo, se recomienda usar archivos de anulación para la configuración local en lugar de modificaciones en el archivo de configuración principal.

Además del archivo de configuración principal, se leen fragmentos de configuración de anulación de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, y /etc/systemd/*.conf.d/. Estos archivos de anulación tienen mayor prioridad y anulan el archivo de configuración principal. Los archivos en los subdirectorios de configuración *.conf.d/ se ordenan por su nombre de archivo en orden lexicográfico, independientemente de en cuál de los subdirectorios residan. Cuando varios archivos especifican la misma opción, para opciones que aceptan solo un valor, la entrada en el archivo ordenado último tiene prioridad, y para opciones que aceptan una lista de valores, las entradas se recopilan a medida que ocurren en los archivos ordenados.

Cuando los paquetes necesitan personalizar la configuración, pueden instalar archivos de anulación bajo /usr/. Los archivos en /etc/ están reservados para el administrador local, quien puede usar esta lógica para anular los archivos de configuración instalados por los paquetes del proveedor. Se deben usar archivos de anulación para anular los archivos de anulación de paquetes, ya que el archivo de configuración principal tiene menor prioridad. Se recomienda prefijar todos los nombres de archivo en estos subdirectorios con un número de dos dígitos y un guion, para simplificar el ordenamiento. Esto también define un concepto de prioridades de anulación para permitir a los proveedores de OS distribuir archivos de anulación dentro de un rango específico inferior al rango utilizado por los usuarios. Esto debería reducir el riesgo de que los archivos de anulación de paquetes anulen accidentalmente los archivos de anulación definidos por los usuarios. Se recomienda utilizar el rango 10-40 para los archivos de anulación en /usr/ y el rango 60-90 para los archivos de anulación en /etc/ y /run/, para asegurarse de que los archivos de anulación locales y transitorios tengan prioridad sobre los archivos de anulación distribuidos por el proveedor del sistema operativo.

Para deshabilitar un archivo de configuración proporcionado por el proveedor, la forma recomendada es colocar un enlace simbólico a /dev/null en el directorio de configuración en /etc/, con el mismo nombre de archivo que el archivo de configuración del proveedor.

OPCIONES

Las siguientes opciones están disponibles en la sección [Home]:

DefaultStorage=

El almacenamiento por defecto a utilizar para las áreas de usuario. Acepta uno de "luks", "fscrypt", "directory", "subvolume", "cifs". Para detalles sobre estas opciones, ver homectl(1). Si no está configurado o se le asigna la cadena vacía, el almacenamiento por defecto se determina automáticamente: si no se ejecuta en un entorno de contenedor y /home/ no está cifrado, por defecto es "luks". De lo contrario, por defecto es "subvolume" si /home/ está en un sistema de archivos btrfs, y "directory" en caso contrario. Tenga en cuenta que el almacenamiento seleccionado en la línea de comandos de homectl siempre tiene prioridad.

Añadido en la versión 246.

DefaultFileSystemType=

Al usar "luks" como almacenamiento (ver arriba), selecciona el sistema de archivos por defecto a utilizar dentro del volumen LUKS del usuario. Acepta uno de "btrfs", "ext4" o "xfs". Si no se especifica, por defecto es "btrfs". Esta configuración no tiene ningún efecto si se utiliza un mecanismo de almacenamiento diferente. El tipo de sistema de archivos seleccionado en la línea de comandos de homectl siempre tiene prioridad.

Añadido en la versión 246.
