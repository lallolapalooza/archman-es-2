ZHESVX calcula la solución al sistema de ecuaciones lineales A * X = B para matrices HE

Propósito:

!>
!> ZHESVX utiliza el método de pivoteo diagonal para calcular la
!> solución de un sistema complejo de ecuaciones lineales A * X = B,
!> donde A es una matriz Hermítica N por N y X y B son matrices N por NRHS.
!>
!> También se proporcionan cotas de error en la solución y una estimación
!> de la condición.
!>

Descripción:

!>
!> Se realizan los siguientes pasos:
!>
!> 1. Si FACT = 'N', se utiliza el método de pivoteo diagonal para factorizar A.
!>    La forma de la factorización es
!>       A = U * D * U**H,  si UPLO = 'U', o
!>       A = L * D * L**H,  si UPLO = 'L',
!>    donde U (o L) es un producto de matrices de permutación y triangulares unitarias
!>    superiores (inferiores), y D es Hermítica y diagonal por bloques con
!>    bloques diagonales de 1x1 y 2x2.
!>
!> 2. Si algún D(i,i)=0, de modo que D es exactamente singular, la rutina
!>    retorna con INFO = i. De lo contrario, la forma factorizada de A se usa
!>    para estimar el número de condición de la matriz A. Si el
!>    recíproco del número de condición es menor que la precisión de máquina,
!>    se retorna INFO = N+1 como advertencia, pero la rutina aún continúa
!>    para resolver X y calcular cotas de error como se describe a continuación.
!>
!> 3. El sistema de ecuaciones se resuelve para X utilizando la forma
!>    factorizada de A.
!>
!> 4. Se aplica refinamiento iterativo para mejorar la solución calculada
!>    y calcular cotas de error y estimaciones de error hacia atrás
!>    para ella.
!>

Parámetros

FACT 
!>          FACT es CHARACTER*1
!>          Especifica si la forma factorizada de A se ha suministrado
!>          en la entrada o no.
!>          = 'F':  En la entrada, AF y IPIV contienen la forma factorizada
!>                  de A.  A, AF e IPIV no se modificarán.
!>          = 'N':  La matriz A se copiará en AF y se factorizará.
!>

UPLO

!>          UPLO es CHARACTER*1
!>          = 'U':  Se almacena el triángulo superior de A;
!>          = 'L':  Se almacena el triángulo inferior de A.
!>

N

!>          N es INTEGER
!>          El número de ecuaciones lineales, es decir, el orden de
!>          la matriz A.  N >= 0.
!>

NRHS

!>          NRHS es INTEGER
!>          El número de lados derechos, es decir, el número de columnas
!>          de las matrices B y X.  NRHS >= 0.
!>

A

!>          A es un array COMPLEX*16, dimensión (LDA,N)
!>          La matriz Hermítica A.  Si UPLO = 'U', la parte triangular
!>          superior N por N líder de A contiene la parte triangular
!>          superior de la matriz A, y la parte estrictamente triangular
!>          inferior de A no se referencia.  Si UPLO = 'L', la parte triangular
!>          inferior N por N líder de A contiene la parte triangular
!>          inferior de la matriz A, y la parte estrictamente triangular
!>          superior de A no se referencia.
!>

LDA

!>          LDA es INTEGER
!>          La dimensión líder del array A.  LDA >= max(1,N).
!>

AF

!>          AF es un array COMPLEX*16, dimensión (LDAF,N)
!>          Si FACT = 'F', entonces AF es un argumento de entrada y en la
!>          entrada contiene la matriz diagonal por bloques D y los multiplicadores
!>          utilizados para obtener el factor U o L de la factorización
!>          A = U*D*U**H o A = L*D*L**H calculada por ZHETRF.
!>
!>          Si FACT = 'N', entonces AF es un argumento de salida y en la
!>          salida devuelve la matriz diagonal por bloques D y los multiplicadores
!>          utilizados para obtener el factor U o L de la factorización
!>          A = U*D*U**H o A = L*D*L**H.
!>

LDAF

!>          LDAF es INTEGER
!>          La dimensión líder del array AF.  LDAF >= max(1,N).
!>

IPIV

!>          IPIV es un array INTEGER, dimensión (N)
!>          Si FACT = 'F', entonces IPIV es un argumento de entrada y en la
!>          entrada contiene detalles de los intercambios y la estructura de bloques
!>          de D, tal como lo determina ZHETRF.
!>          Si IPIV(k) > 0, entonces las filas y columnas k e IPIV(k) fueron
!>          intercambiadas y D(k,k) es un bloque diagonal de 1x1.
!>          Si UPLO = 'U' e IPIV(k) = IPIV(k-1) < 0, entonces las filas y
!>          columnas k-1 e -IPIV(k) fueron intercambiadas y D(k-1:k,k-1:k)
!>          es un bloque diagonal de 2x2. Si UPLO = 'L' e IPIV(k) =
!>          IPIV(k+1) < 0, entonces las filas y columnas k+1 e -IPIV(k) fueron
!>          intercambiadas y D(k:k+1,k:k+1) es un bloque diagonal de 2x2.
!>
!>          Si FACT = 'N', entonces IPIV es un argumento de salida y en la
!>          salida contiene detalles de los intercambios y la estructura de bloques
!>          de D, tal como lo determina ZHETRF.
!>

B

!>          B es un array COMPLEX*16, dimensión (LDB,NRHS)
!>          La matriz del lado derecho B de N por NRHS.
!>

LDB

!>          LDB es INTEGER
!>          La dimensión líder del array B.  LDB >= max(1,N).
!>

X

!>          X es un array COMPLEX*16, dimensión (LDX,NRHS)
!>          Si INFO = 0 o INFO = N+1, la matriz solución X de N por NRHS.
!>

LDX

!>          LDX es INTEGER
!>          La dimensión líder del array X.  LDX >= max(1,N).
!>

RCOND

!>          RCOND es DOUBLE PRECISION
!>          La estimación del número de condición recíproco de la matriz
!>          A.  Si RCOND es menor que la precisión de máquina (en
!>          particular, si RCOND = 0), la matriz es singular con precisión de trabajo.
!>          Esta condición se indica mediante un código de retorno de
!>          INFO > 0.
!>

FERR

!>          FERR es un array DOUBLE PRECISION, dimensión (NRHS)
!>          La cota de error hacia adelante estimada para cada vector solución
!>          X(j) (la j-ésima columna de la matriz solución X).
!>          Si XTRUE es la solución verdadera correspondiente a X(j), FERR(j)
!>          es una cota superior estimada para la magnitud del elemento más grande
!>          en (X(j) - XTRUE) dividido por la magnitud del elemento más grande
!>          en X(j). La estimación es tan fiable como
!>          la estimación de RCOND, y es casi siempre una ligera
!>          sobreestimación del error real.
!>

BERR

!>          BERR es un array DOUBLE PRECISION, dimensión (NRHS)
!>          El error hacia atrás relativo componente a componente de cada vector
!>          solución X(j) (es decir, el menor cambio relativo en
!>          cualquier elemento de A o B que haga de X(j) una solución exacta).
!>

!>          WORK es un array de array*16, dimensión (MAX(1,LWORK))
!>          A la salida, si INFO = 0, WORK(1) devuelve el LWORK óptimo.
!>

LWORK

!>          LWORK es INTEGER
!>          La longitud de WORK. LWORK >= MAX(1,2*N), y para un mejor
!>          rendimiento, cuando FACT = 'N', LWORK >= MAX(1,2*N,N*NB), donde
!>          NB es el tamaño de bloque óptimo para ZHETRF.
!>
!>          Si LWORK = -1, entonces se asume una consulta de espacio de trabajo; la rutina
!>          solo calcula el tamaño óptimo del array WORK, devuelve
!>          este valor como la primera entrada del array WORK, y no se emite ningún mensaje
!>          de error relacionado con LWORK por XERBLA.
!>

RWORK

!>          RWORK es un array de DOUBLE PRECISION, dimensión (N)
!>

INFO

!>          INFO es INTEGER
!>          = 0: salida exitosa
!>          < 0: si INFO = -i, el i-ésimo argumento tenía un valor ilegal
!>          > 0: si INFO = i, y i es
!>                <= N: D(i,i) es exactamente cero. La factorización
!>                       se ha completado pero el factor D es exactamente
!>                       singular, por lo que la solución y los límites de error no
!>                       pudieron ser calculados. Se devuelve RCOND = 0.
!>                = N+1: D es no singular, pero RCOND es menor que la precisión de la máquina,
!>                       lo que significa que la matriz es singular
!>                       a la precisión de trabajo. Sin embargo, la
!>                       solución y los límites de error se calculan porque
!>                       hay una serie de situaciones en las que la
!>                       solución calculada puede ser más precisa que el
!>                       valor de RCOND sugeriría.
!>
