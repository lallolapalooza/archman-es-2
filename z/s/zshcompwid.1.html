NOMBRE

zshcompwid - widgets de completado de zsh

DESCRIPCIÓN

El mecanismo de completado programable del shell se puede manipular de dos maneras; aquí se definen las características de bajo nivel que admiten el mecanismo más nuevo basado en funciones. Un conjunto completo de funciones del shell basado en estas características se describe en zshcompsys(1), y los usuarios sin interés en agregar a ese sistema (o, potencialmente, escribir su propio - ver entrada de diccionario para `hubris') deben omitir la sección actual. El sistema más antiguo basado en el comando incorporado compctl se describe en zshcompctl(1).

Los widgets de completado se definen mediante la opción -C del comando incorporado zle proporcionado por el módulo zsh/zle (ver zshzle(1)). Por ejemplo,

zle -C complete expand-or-complete completer

define un widget llamado `complete'. El segundo argumento es el nombre de cualquiera de los widgets incorporados que manejan completados: complete-word, expand-or-complete, expand-or-complete-prefix, menu-complete, menu-expand-or-complete, reverse-menu-complete, list-choices o delete-char-or-list. Tenga en cuenta que esto seguirá funcionando incluso si el widget en cuestión ha sido reasignado.

Cuando este widget recién definido está vinculado a una tecla usando el comando incorporado bindkey definido en el módulo zsh/zle (ver zshzle(1)), al presionar esa tecla se llamará a la función del shell `completer'. Esta función es responsable de generar coincidencias de completado utilizando los comandos incorporados que se describen a continuación. Al igual que con otros widgets ZLE, la función se llama con su entrada estándar cerrada.

Una vez que la función regresa, el código de completado retoma el control y trata las coincidencias de la misma manera que el widget incorporado especificado, en este caso expand-or-complete.

PARÁMETROS ESPECIALES DE COMPLETADO

Los parámetros ZLE_REMOVE_SUFFIX_CHARS y ZLE_SPACE_SUFFIX_CHARS son utilizados por el mecanismo de completado, pero no son especiales. Ver Parámetros utilizados por el shell en zshparam(1).

Dentro de los widgets de completado, y cualquier función llamada desde ellos, algunos parámetros tienen un significado especial; fuera de estas funciones no son especiales para el shell de ninguna manera. Estos parámetros se utilizan para pasar información entre el código de completado y el widget de completado. Algunos de los comandos incorporados y los códigos de condición usan o cambian los valores actuales de estos parámetros. Cualquier valor existente se ocultará durante la ejecución de los widgets de completado; excepto para compstate, los parámetros se restablecen en cada salida de función (incluidas las llamadas anidadas a funciones desde dentro del widget de completado) a los valores que tenían cuando se ingresó la función.

CURRENT
Este es el número de la palabra actual, es decir, la palabra en la que el cursor se encuentra actualmente en el array words. Tenga en cuenta que este valor solo es correcto si la opción ksharrays no está establecida.
IPREFIX
Inicialmente, este se establecerá en la cadena vacía. Este parámetro funciona como PREFIX; contiene una cadena que precede a la de PREFIX y no se considera parte de la lista de coincidencias. Típicamente, una cadena se transfiere del principio de PREFIX al final de IPREFIX, por ejemplo:
IPREFIX=${PREFIX%%\=*}=
PREFIX=${PREFIX#*=}

hace que la parte del prefijo hasta el primer signo igual, incluido, no se trate como parte de una cadena coincidente. Esto se puede hacer automáticamente con el comando incorporado compset, ver abajo.

ISUFFIX
Al igual que IPREFIX, pero para un sufijo que no debe considerarse parte de las coincidencias; tenga en cuenta que la cadena ISUFFIX sigue a la cadena SUFFIX.
PREFIX
Inicialmente, este se establecerá en la parte de la palabra actual desde el principio de la palabra hasta la posición del cursor; puede ser modificado para dar un prefijo común a todas las coincidencias.
QIPREFIX
Este parámetro es de solo lectura y contiene la cadena entrecomillada hasta la palabra que se está completando. Por ejemplo, al completar `"foo', este parámetro contiene las comillas dobles. Si se usa la opción -q de compset (ver abajo), y la cadena original era `"foo bar' con el cursor en `bar', este parámetro contiene `"foo '.
QISUFFIX
Similar a QIPREFIX, pero contiene el sufijo.
SUFFIX
Inicialmente, este se establecerá en la parte de la palabra actual desde la posición del cursor hasta el final; puede ser modificado para dar un sufijo común a todas las coincidencias. Es más útil cuando la opción COMPLETE_IN_WORD está establecida, ya que de lo contrario toda la palabra en la línea de comandos se trata como un prefijo.
compstate
Este es un array asociativo con varias claves y valores que el código de completado utiliza para intercambiar información con el widget de completado. Las claves son:
all_quotes
La opción -q del comando incorporado compset (ver abajo) permite que una cadena entrecomillada se divida en palabras separadas; si el cursor está en una de esas palabras, se completará esa palabra, posiblemente invocando `compset -q' recursivamente. Con esta clave es posible probar los tipos de cadenas entrecomilladas que actualmente se dividen en partes de esta manera. Su valor contiene un carácter por cada nivel de entrecomillado. Los caracteres son una comilla simple o una comilla doble para cadenas entrecomilladas con esos caracteres, un signo de dólar para cadenas entrecomilladas con $'...' y una barra invertida para cadenas que no comienzan con un carácter de entrecomillado. El primer carácter del valor siempre corresponde al nivel de entrecomillado más interno.
context
Este será establecido por el código de completado al contexto general en el que se intenta el completado. Los valores posibles son:
array_value
al completar dentro del valor de una asignación de parámetro de array; en este caso, el array words contiene las palabras dentro de los paréntesis.
brace_parameter
al completar el nombre de un parámetro en una expansión de parámetro que comienza con ${. Este contexto también se establecerá al completar indicadores de parámetro que siguen a ${(; se presenta el argumento completo de la línea de comandos y el manejador debe probar el valor a completar para determinar que este es el caso.
assign_parameter
al completar el nombre de un parámetro en una asignación de parámetro.
command
al completar para un comando normal (ya sea en posición de comando o para un argumento del comando).
condition
al completar dentro de una expresión condicional `[[...]]'; en este caso, el array words contiene solo las palabras dentro de la expresión condicional.
math
al completar en un entorno matemático como una construcción `((...))'.
parameter
al completar el nombre de un parámetro en una expansión de parámetro que comienza con $ pero no con ${.
redirect
al completar después de un operador de redirección.
subscript
al completar dentro de un subíndice de parámetro.
value
al completar el valor de una asignación de parámetro.
exact
Controla el comportamiento cuando la opción REC_EXACT está establecida. Se establecerá en accept si una coincidencia exacta conduciría

Si se estableció cuando al menos una coincidencia igual a la cadena de la línea fue generada, la coincidencia se acepta.

exact_string
La cadena de una coincidencia exacta si se encontró alguna, de lo contrario `unset'.
ignored
El número de completados que fueron ignorados porque coincidieron con uno de los patrones dados con la opción -F al comando incorporado compadd.
insert
Esto controla la forma en que una coincidencia se inserta en la línea de comandos. Al entrar en la función del widget, si está `unset' la línea de comandos no se modificará; si se establece a unambiguous, se insertará cualquier prefijo común a todas las coincidencias; si se establece a automenu-unambiguous, se insertará el prefijo común y la siguiente invocación del código de completado puede iniciar el completado de menú (debido a que la opción AUTO_MENU está establecida); si se establece a menu o automenu se iniciará el completado de menú para las coincidencias generadas actualmente (en este último caso esto ocurrirá porque AUTO_MENU está establecido). El valor también puede contener la cadena `tab' cuando el código de completado normalmente no haría completado, sino que solo insertaría el carácter TAB.

Al salir, puede establecerse a cualquiera de los valores anteriores (donde establecerlo a la cadena vacía es lo mismo que establecerlo a `unset'), o a un número, en cuyo caso la coincidencia cuyo número se da se insertará en la línea de comandos. Los números negativos cuentan hacia atrás desde la última coincidencia (con `-1' seleccionando la última coincidencia) y los valores fuera de rango se envuelven, de modo que un valor de cero selecciona la última coincidencia y un valor uno más que el máximo selecciona la primera. A menos que el valor de esta clave termine en un espacio, la coincidencia se inserta como en un completado de menú, es decir, sin añadir automáticamente un espacio.

Tanto menu como automenu también pueden especificar el número de la coincidencia a insertar, dado después de dos puntos. Por ejemplo, `menu:2' dice que se inicie el completado de menú, comenzando con la segunda coincidencia.

Tenga en cuenta que un valor que contenga la subcadena `tab' hace que las coincidencias generadas se ignoren y solo se inserte el TAB.

Finalmente, también puede establecerse a all, lo que hace que todas las coincidencias generadas se inserten en la línea.

insert_positions
Cuando el sistema de completado inserta una cadena no ambigua en la línea, puede haber múltiples lugares donde faltan caracteres o donde el carácter insertado difiere de al menos una coincidencia. El valor de esta clave contiene una lista separada por dos puntos de todas estas posiciones, como índices en la línea de comandos.
last_prompt
Si esto se establece a una cadena no vacía para cada coincidencia añadida, el código de completado moverá el cursor hacia atrás al prompt anterior después de que se muestre la lista de completados. Inicialmente se establece o se anula según la opción ALWAYS_LAST_PROMPT.
list
Esto controla si y cómo se mostrará la lista de coincidencias. Si está `unset' o vacía, nunca se listarán; si su valor comienza con list, siempre se listarán; si comienza con autolist o ambiguous, se listarán cuando las opciones AUTO_LIST o LIST_AMBIGUOUS respectivamente normalmente lo harían.

Si la subcadena force aparece en el valor, esto hace que la lista se muestre incluso si solo hay una coincidencia. Normalmente, la lista solo se mostraría si hay al menos dos coincidencias.

El valor contiene la subcadena packed si la opción LIST_PACKED está establecida. Si esta subcadena se da para todas las coincidencias añadidas a un grupo, este grupo mostrará el comportamiento de LIST_PACKED. Lo mismo se hace para la opción LIST_ROWS_FIRST con la subcadena rows.

Finalmente, si el valor contiene la cadena explanations, solo se listarán las cadenas de explicación, si las hay, y si contiene messages, solo se listarán los mensajes (añadidos con la opción -x de compadd). Si contiene tanto explanations como messages, se listarán ambos tipos de cadenas de explicación. Se establecerá adecuadamente al entrar en un widget de completado y podrá cambiarse allí.

list_lines
Esto da el número de líneas necesarias para mostrar la lista completa de completados. Tenga en cuenta que para calcular el número total de líneas a mostrar, necesita sumar a este valor el número de líneas necesarias para la línea de comandos, que está disponible como el valor del parámetro especial BUFFERLINES.
list_max
Inicialmente esto se establece al valor del parámetro LISTMAX. Puede establecerse a cualquier otro valor; cuando el widget salga, este valor se usará de la misma manera que el valor de LISTMAX.
nmatches
El número de coincidencias añadidas por el código de completado hasta el momento.
old_insert
Al entrar en el widget, esto se establecerá al número de la coincidencia de una lista antigua de completados que está actualmente insertada en la línea de comandos. Si no se ha insertado ninguna coincidencia, esto se anula.

Al igual que con old_list, el valor de esta clave solo se usará si es la cadena keep. Si se estableció a este valor por el widget y había una coincidencia antigua insertada en la línea de comandos, esta coincidencia se mantendrá y si el valor de la clave insert especifica que se debe insertar otra coincidencia, esta se insertará después de la antigua.

old_list
Esto se establece a yes si todavía hay una lista válida de completados de una completación anterior en el momento en que se invoca el widget. Esto será generalmente el caso si y solo si la operación de edición anterior fue un widget de completado o uno de los comandos incorporados de completado. Si hay una lista válida y además se muestra actualmente en la pantalla, el valor de esta clave es shown.

Después de que el widget haya salido, el valor de esta clave solo se usa si se estableció a keep. En este caso, el código de completado continuará usando esta lista antigua. Si el widget generó nuevas coincidencias, estas no se usarán.

parameter
El nombre del parámetro al completar en un subíndice o en el valor de una asignación de parámetro.
pattern_insert
Normalmente esto se establece a menu, que especifica que el completado de menú se usará siempre que un conjunto de coincidencias se haya generado usando pattern_match (ver más abajo). Si el usuario lo establece a cualquier otra cadena no vacía y el completado de menú no se selecciona por otras configuraciones de opción, el código insertará en su lugar cualquier prefijo común para las coincidencias generadas, como en el completado normal.
pattern_match
Controla localmente el comportamiento dado por la opción GLOB_COMPLETE. Inicialmente se establece a `*' si y solo si la opción está establecida. El widget de completado puede establecerlo a este valor, a una cadena vacía (que tiene el mismo efecto que anularlo), o a cualquier otra cadena no vacía. Si no está vacío, los metacaracteres sin comillas en la línea de comandos se tratarán como patrones; si es `*', además se asume un comodín `*' en la posición del cursor; si está vacío o `unset', los metacaracteres se tratarán literalmente.

Tenga en cuenta que las especificaciones de coincidencia dadas al comando incorporado compadd no se usan si esto se establece a una cadena no vacía.

quote
Al completar dentro de comillas, esto contiene el carácter de comillas (es decir, una comilla simple, una comilla doble o una comilla invertida). De lo contrario, se anula.
quoting
Al completar dentro de comillas simples, esto se establece a la cadena single; dentro de comillas dobles, la cadena double; dentro de comillas invertidas, la cadena backtick. De lo contrario, se anula.
redirect
El operador de redirección al completar en una posición de redirección, es decir, uno de <, >, etc.
restore
Esto se establece a auto antes de entrar en una función, lo que fuerza a que los parámetros especiales mencionados anteriormente (words, CURRENT, PREFIX, IPREFIX, SUFFIX y ISUFFIX) se restauren a sus valores anteriores cuando la función salga. Si una función lo anula o lo establece a cualquier otra cadena, no se restaurarán.
to_end
Especifica las ocasiones en las que el cursor se mueve al final de una cadena cuando se inserta una coincidencia. Al entrar en una función de widget, puede ser single si esto ocurrirá cuando se insertó una única coincidencia no ambigua o match si ocurrirá cada vez que se inserte una coincidencia (por ejemplo, mediante completado de menú; es probable que este sea el efecto de la opción ALWAYS_TO_END).

Al salir, puede establecerse a single como se mencionó anteriormente. También puede establecerse a always, o a la cadena vacía o `unset'; en esos casos el cursor se moverá al final de la cadena siempre o nunca respectivamente. Cualquier otra cadena se trata como match.

unambiguous
Esta clave es de solo lectura y siempre se establecerá al prefijo común (no ambiguo) que el código de completado ha generado para todas las coincidencias añadidas hasta el momento.
unambiguous_cursor
Esto da la posición en la que se colocaría el cursor si se insertara el prefijo común en la clave unambiguous, relativo al valor de esa clave. El cursor se colocaría antes del carácter cuyo índice se da por esta clave.

Esta es otra forma de la opción -r. Cuando se ha aceptado una coincidencia y se ha insertado un sufijo, la función remove-func se llamará después de escribir el siguiente carácter. Si se proporciona esta bandera, todas las completions se añadirán al conjunto de coincidencias y el código de completado no realizará ninguna coincidencia. Normalmente, esto se utiliza en funciones que realizan las coincidencias por sí mismas.

Si se proporciona esta opción, las completions *no* se añadirán al conjunto de coincidencias. En su lugar, se realizará la coincidencia como de costumbre y todas las completions que coincidan se almacenarán en el parámetro de matriz cuyo nombre se proporciona como array.

compset -q
Este comando simplifica la modificación de los parámetros especiales, mientras que su estado de retorno permite realizar pruebas sobre ellos.

Las opciones son:

-p number
Si el valor del parámetro PREFIX tiene al menos number caracteres de longitud, se eliminan los primeros number caracteres de él y se añaden al contenido del parámetro IPREFIX.
-P [ number ] pattern
Si el valor del parámetro PREFIX comienza con algo que coincide con el pattern, la porción coincidente se elimina de PREFIX y se añade a IPREFIX.

Sin el number opcional, se toma la coincidencia más larga, pero si se proporciona number, se mueve hasta la number-ésima coincidencia. Si number es negativo, se mueve la number-ésima coincidencia más larga. Por ejemplo, si PREFIX contiene la cadena `a=b=c', entonces compset -P '*\=' moverá la cadena `a=b=' al parámetro IPREFIX, pero compset -P 1 '*\=' moverá solo la cadena `a='.

-s number
Como -p, pero transfiere los últimos number caracteres del valor de SUFFIX al principio del valor de ISUFFIX.
-S [ number ] pattern
Como -P, pero coincide con la última porción de SUFFIX y transfiere la porción coincidente al principio del valor de ISUFFIX.
-n begin [ end ]
Si la posición de palabra actual, especificada por el parámetro CURRENT, es mayor o igual a begin, se elimina todo hasta la begin-ésima palabra del array words y el valor de CURRENT se decrementa en begin.

Si se proporciona el end opcional, la modificación se realiza solo si la posición de palabra actual también es menor o igual a end. En este caso, las palabras desde la posición end en adelante también se eliminan del array words.

Tanto begin como end pueden ser negativos para contar hacia atrás desde el último elemento del array words.

-N beg-pat [ end-pat ]
Si uno de los elementos del array words anterior al que está en el índice dado por el valor del parámetro CURRENT coincide con el patrón beg-pat, se eliminan todos los elementos hasta e incluyendo el coincidente del array words y el valor de CURRENT se cambia para apuntar a la misma palabra en el array modificado.

Si también se proporciona el patrón opcional end-pat, y hay un elemento en el array words que coincide con este patrón, los parámetros se modifican solo si el índice de esta palabra es mayor que el dado por el parámetro CURRENT (por lo que la palabra coincidente debe estar después del cursor). En este caso, las palabras que comienzan con la coincidente con end-pat también se eliminan del array words. Si words no contiene ninguna palabra que coincida con end-pat, la prueba y la modificación se realizan como si no se hubiera proporcionado.

-q
La palabra que se está completando actualmente se divide en espacios en palabras separadas, respetando las convenciones de comillas habituales del shell. Las palabras resultantes se almacenan en el array words, y CURRENT, PREFIX, SUFFIX, QIPREFIX y QISUFFIX se modifican para reflejar la parte de la palabra que se completa.

En todos los casos anteriores, el estado de retorno es cero si la prueba tuvo éxito y los parámetros se modificaron, y de lo contrario, es distinto de cero. Esto permite usar esta utilidad interna en pruebas como:

if compset -P '*\='; then ...

Esto fuerza a que todo hasta e incluyendo el último signo igual sea ignorado por el código de completado.

CONTROL DE COINCIDENCIA DE COMPLETADO

Cuando el usuario invoca el completado, la palabra actual en la línea de comandos (es decir, la palabra en la que se encuentra actualmente el cursor) se utiliza para generar un patrón de coincidencia. Solo se ofrecen al usuario como coincidencias aquellos completados que coinciden con el patrón.

El patrón de coincidencia predeterminado se genera a partir de la palabra actual ya sea

•
añadiendo un `*' (que coincide con cualquier número de caracteres en un completado) o,
•
si la opción del shell COMPLETE_IN_WORD está configurada, insertando un `*' en la posición del cursor.

Este patrón estrecho se puede ampliar selectivamente pasando una especificación de coincidencia al comando builtin compadd a través de su opción -M (ver `Comandos Builtin de Completado' arriba). Una especificación de coincidencia consta de uno o más coincidentes separados por espacios en blanco. Los coincidentes en una especificación de coincidencia se aplican uno a la vez, de izquierda a derecha. Una vez que se han aplicado todos los coincidentes, los completados se comparan con el patrón de coincidencia final y se descartan los que no coinciden.

•
Tenga en cuenta que la opción -M se ignora si la palabra actual contiene un patrón glob y la opción del shell GLOB_COMPLETE está configurada o si la clave pattern_match del array asociativo especial compstate está configurada con un valor no vacío (ver `Parámetros Especiales de Completado' arriba).
•
Los usuarios del sistema de completado (ver zshcompsys(1)) generalmente no deben usar la opción -M directamente, sino usar los estilos matcher-list y matcher (ver el subapartado Estilos Estándar en la documentación para CONFIGURACIÓN DEL SISTEMA DE COMPLETADO en zshcompsys(1)).

Cada coincidente consta de

•
una letra sensible a mayúsculas/minúsculas
•
un `:',
•
uno o más patrones separados por barras (`|'),
•
un signo igual (`='), y
•
otro patrón.

Los patrones antes del `=' se utilizan para hacer coincidir subcadenas de la palabra actual. Para cada subcadena coincidente, la parte correspondiente del patrón de coincidencia se amplía con el patrón después del `=', mediante un OR lógico.

Cada patrón en un coincidente consta de

•
la cadena vacía o
•
una secuencia de
•
caracteres literales (que pueden ser citados con un `\'),
•
signos de interrogación (`?'),
•
expresiones de corchetes (`[...]'; ver el subapartado Operadores Glob en la documentación para OPERADORES GLOB en zshexpn(1)), y/o
•
expresiones de llaves (ver abajo).

Otros patrones del shell no están permitidos.

Una expresión de llaves, al igual que una expresión de corchetes, consta de una lista de

•
caracteres literales,
•
rangos (`0-9'), y/o
•
clases de caracteres (`[:nombre:]').

Sin embargo, difieren entre sí de la siguiente manera:

•
Una expresión de llaves está delimitada por un par de llaves (`{...}').
•
Las expresiones de llaves no admiten negaciones. Es decir, un '!' o '^' inicial no tiene un significado especial y se interpretará como un carácter literal.
•
Cuando un carácter de la palabra actual coincide con el n-ésimo patrón en una expresión de llaves, la parte correspondiente del patrón de coincidencia se amplía solo con el n-ésimo patrón de la expresión de llaves en el otro lado del `=', si lo hay; si no hay una expresión de llaves en el otro lado, entonces este patrón es la cadena vacía. Sin embargo, si alguna de las expresiones de llaves tiene más elementos que la otra, los elementos excedentes simplemente se ignoran. Al comparar índices, cada carácter literal o clase de caracteres cuenta como un elemento, pero cada rango se expande a la lista completa de caracteres literales que representa. Además, si en ambos lados del `=', el n-ésimo patrón es '[:upper:]' o '[:lower:]', entonces estos también se expanden como rangos.

Tenga en cuenta que, aunque el sistema de coincidencia aún no maneja caracteres multibyte, es probable que sea una extensión futura. Por lo tanto, se recomienda usar `[:upper:]' y `[:lower:]' en lugar de `A-Z' y `a-z'.

A continuación se muestran las diferentes formas de coincidentes que se admiten. Cada forma en mayúsculas se comporta exactamente igual que su contraparte en minúsculas, pero agrega un paso adicional *después* de que el patrón de coincidencia haya filtrado los completados que no coinciden: cada una de las subcadenas de una coincidencia que fue emparejada por un subpatrón de un coincidente en mayúsculas se reemplaza con la subcadena correspondiente de la palabra actual. Sin embargo, los patrones de coincidentes en *minúsculas* tienen mayor peso: si una subcadena de la palabra actual coincidió con patrones tanto de un coincidente en minúsculas como en mayúsculas, entonces el patrón del coincidente en minúsculas gana y la parte correspondiente de la coincidencia no se modifica.

A menos que se indique lo contrario, cada ejemplo listado asume que COMPLETE_IN_WORD no está configurado (como lo está por defecto).

m:pat-palabra=pat-coincidencia
M:pat-palabra=pat-coincidencia

Para cada subcadena de la palabra actual que coincide con pat-palabra, amplíe la parte correspondiente del patrón de coincidencia para que coincida adicionalmente con pat-coincidencia.

Ejemplos:

m:{[:lower:]}={[:upper:]} permite que cualquier carácter en minúscula en la palabra actual se complete a sí mismo o a su contraparte en mayúsculas. Por lo tanto, los completados `foo', `FOO' y `Foo' se considerarán coincidencias para la palabra `fo'.

M:_= inserta cada guion bajo de la palabra actual en cada coincidencia, en la misma posición relativa, determinada al hacer coincidir las subcadenas a su alrededor. Por lo tanto, dada una coincidencia `foo', la palabra `f_o' se completará a la coincidencia `f_oo', incluso si esta última no estaba presente como una coincidencia.

B:pat-palabra=pat-coincidencia
e:pat-palabra=pat-coincidencia
E:pat-palabra=pat-coincidencia

Para cada subcadena consecutiva al b:eginning (inicio) o al e:nd (final) de la palabra actual que coincide con pat-palabra, amplíe la parte correspondiente del patrón de coincidencia para que coincida adicionalmente con pat-coincidencia.

Ejemplos:

`b:-=+' permite que cualquier número de guiones al inicio de la palabra actual se complete a un guion o a un signo más.

`B:0=' agrega todos los ceros al principio de la palabra actual al principio de cada coincidencia.

R:pat-palabra|=pat-coincidencia
r:pat-palabra|=pat-coincidencia

Si hay una subcadena en el borde l:eft (izquierdo) o r:ight (derecho) de la palabra actual que coincide con pat-palabra, entonces amplíe la parte correspondiente del patrón de coincidencia para que coincida adicionalmente con pat-coincidencia.

Para cada coincidente l:, L:, r: y R: (incluidos los de abajo), el patrón pat-coincidencia también puede ser un `*'. Esto coincide con cualquier número de caracteres en un completado.

Ejemplos:

`r:|=*' agrega un `*' al patrón de coincidencia, incluso cuando COMPLETE_IN_WORD está configurado y el cursor no está al final de la palabra actual.

Si la palabra actual comienza con un guion, entonces `L:|-=' lo antepondrá a cada coincidencia.

l:ancla|pat-palabra=

CONTROL DE COINCIDENCIAS DE COMPLETADO

L:patrón-palabra=patrón-coincidencia
l:patrón-palabra=patrón-coincidencia
r:patrón-palabra=patrón-coincidencia
R:patrón-palabra=patrón-coincidencia

Para cada subcadena de la palabra actual que coincide con patrón-palabra y tiene a su izquierda o derecha otra subcadena que coincide con patrón-ancla, amplía la parte correspondiente del patrón de coincidencia para que también coincida con patrón-coincidencia.

Tenga en cuenta que estos controladores (y los siguientes) solo modifican lo que se coincide con patrón-palabra; no cambian el comportamiento de coincidencia de lo que se coincide con patrón-ancla (o co-ancla; véanse los controladores siguientes). Por lo tanto, a menos que su parte correspondiente del patrón de coincidencia se haya modificado, el ancla en la palabra actual debe coincidir literalmente en cada completado, al igual que cualquier otra subcadena de la palabra actual.

Si un controlador incluye al menos un ancla (lo que incluye los controladores con dos anclas, más abajo), entonces patrón-coincidencia también puede ser `*' o `**'. `*' puede coincidir con cualquier parte de un completado que no contenga subcadenas que coincidan con patrón-ancla, mientras que un `**' puede coincidir con cualquier parte de un completado, sin excepción. (Tenga en cuenta que esto es diferente del comportamiento de `*' en las formas sin ancla de `l:' y `r:' y también diferente de `*' y `**' en expresiones glob.)

Ejemplos:

`r:|.=*' hace que el completado `comp.sources.unix' coincida con la palabra `..u', pero no con la palabra `.u'.

Dado un completado `--foo', el controlador `L:--|no-=' completará la palabra `--no-' a la coincidencia `--no-foo'.

l:patrón-ancla||patrón-co-ancla=patrón-coincidencia
L:patrón-ancla||patrón-co-ancla=patrón-coincidencia
r:patrón-co-ancla||patrón-ancla=patrón-coincidencia
R:patrón-co-ancla||patrón-ancla=patrón-coincidencia

Para dos subcadenas consecutivas cualesquiera de la palabra actual que coincidan con patrón-ancla y patrón-co-ancla, en el orden dado, inserta el patrón patrón-coincidencia entre sus partes correspondientes en el patrón de coincidencia.

Tenga en cuenta que, a diferencia de patrón-ancla, el patrón patrón-co-ancla no cambia lo que `*' puede coincidir.

Ejemplos:

`r:?||[[:upper:]]=*' completará la palabra actual `fB' a `fooBar', pero no la completará a `fooHooBar' (porque `*' aquí no puede coincidir con nada que incluya una coincidencia para `[[:upper:]]'), ni completará `B' a `fooBar' (porque no hay ningún carácter en la palabra actual para coincidir con patrón-co-ancla).

Dada la palabra actual `pass.n' y un completado `pass.byname', el controlador `L:.||[[:alpha:]]=by' producirá la coincidencia `pass.name'.

x:

Ignora este controlador y todos los controladores a su derecha.

Este controlador se utiliza para marcar el final de una especificación de coincidencia. En una única lista independiente de controladores, esto no tiene uso, pero donde las especificaciones de coincidencia se concatenan, como suele ocurrir al usar el sistema de completado (véase zshcompsys(1)), puede permitir que una especificación de coincidencia anule a otra.

EJEMPLO DE WIDGET DE COMPLETADO

El primer paso es definir el widget:

zle -C complete complete-word complete-files

Luego, el widget se puede enlazar a una tecla usando el comando integrado bindkey:

bindkey '^X\t' complete

Después de eso, la función shell complete-files se invocará después de escribir control-X y TAB. La función debe generar entonces las coincidencias, por ejemplo:

complete-files () { compadd - * }

Esta función completará archivos en el directorio actual que coincidan con la palabra actual.
