zsyncmake(1) Transferencia de archivos zsyncmake(1)

NOMBRE

zsyncmake - Construye el archivo de control para zsync(1)

SINTAXIS

zsyncmake [ { -z | -Z } ] [ -e ] [ -C ] [ -u url ] [ -U url ] [ -b tamañobloque ] [ -o archivo_salida ] [ -f nombre_archivo_destino ] [ -v ] nombre_archivo

zsync -V

DESCRIPCIÓN

Construye un metadato para que el programa cliente zsync realice descargas parciales de archivos. nombre_archivo es el archivo que los usuarios desean descargar; zsyncmake construye el metadato apropiado y escribe nombre_archivo.zsync en el directorio actual.

zsync necesitará al menos una URL desde la cual descargar el contenido del archivo. Si el archivo .zsync estará en el mismo directorio que el archivo a descargar, puedes aceptar el valor predeterminado: zsync incluye una URL relativa en el archivo de control. Si no es así, usa la opción -u para especificar la URL. También deberías especificar una URL para el contenido descomprimido con -U si está disponible, ya que zsync puede usarla para descargas más eficientes a veces. (Puedes editar el archivo .zsync y agregar estas URLs después; tiene un formato simple de clave: valor en la cabecera, pero sugiero que solo hagas esto una vez que estés familiarizado con la herramienta).

Ten en cuenta que zsyncmake en sí mismo no verifica las URLs ni descarga ningún dato (actualmente), debes proporcionar los datos del archivo localmente y verificar las URLs tú mismo.

OPCIONES

-b tamañobloque
Especifica el tamaño del bloque para el algoritmo rsync subyacente. Un tamaño de bloque más pequeño puede ser más eficiente para archivos donde es probable que haya muchos cambios pequeños y dispersos entre descargas; un tamaño de bloque más grande es más eficiente para archivos con menos cambios o menos dispersos. Este tamaño de bloque debe ser una potencia de dos. Si no se especifica, zsyncmake elige uno que cree que es el mejor para este archivo (actualmente 2048 o 4096 dependiendo del tamaño del archivo), por lo que normalmente no deberías necesitar anular el valor predeterminado.
-C
Indica a zsyncmake que no genere ninguna instrucción en el archivo .zsync que indique al cliente que comprima los datos que recibe. Esto se implica con -z, pero esta opción está aquí en caso de que comprimes un archivo tú mismo solo para la transferencia, pero quieres que el cliente obtenga el archivo descomprimido (por ejemplo, estás transfiriendo una ISO, que se mantiene comprimida en el servidor, pero que el cliente no puede usar a menos que se descomprima). Sin -C, zsyncmake generará instrucciones para que el cliente comprima el archivo que recibe cuando sea apropiado; -C está aquí para que puedas evitar que se le indique al cliente que haga eso.
-e
Indica a zsyncmake que el cliente debe poder recibir el archivo exacto que se suministró. Sin esta opción, zsyncmake solo ofrece una garantía más débil: que el cliente recibirá los datos que contiene (por ejemplo, podría transferir la versión descomprimida de un archivo .gz al cliente). Ten en cuenta que esto aún no garantiza que el cliente lo reciba; el cliente podría ignorar las directivas en el archivo zsync, o podría ser incapaz de reproducir exactamente la compresión utilizada. Pero con -e sabes que zsyncmake ha hecho posible obtener los datos exactos; saldrá con un error si no puede.
-f nombre_archivo
Establece el nombre de archivo a incluir en el archivo de salida (este será el nombre del archivo cuando un usuario termine de descargarlo).
-o archivo_salida
Anula el nombre predeterminado del archivo de salida.
-u url
Especifica la URL desde la cual los usuarios pueden descargar el contenido del archivo suministrado. Los usuarios necesitan el archivo de control para saber qué partes del archivo ya tienen, y necesitan las URLs para recuperar las partes del archivo que aún no tienen. Puedes especificar múltiples URLs especificando -u varias veces. Si no se especifica, zsync asume que el archivo y el archivo .zsync residirán en el mismo directorio público, e incluye una única URL relativa.
-U url
Especifica una URL correspondiente al contenido descomprimido del archivo (solo aplicable si es un archivo gzip). zsync a veces puede descargar de forma más eficiente de los datos descomprimidos que de los datos comprimidos; lo aprovechará si está disponible. Si no se especifican URLs, zsync busca un archivo sin la extensión .gz y asume que estará en el mismo directorio público que el archivo .zsync, e incluye una URL relativa a él.
-v
Habilita mensajes detallados.
-V
Imprime la versión de zsync.
-z
Comprime el archivo para transferir. Ten en cuenta que esto sobrescribe cualquier archivo llamado nombre_archivo.gz sin previo aviso (si no proporcionas un nombre de archivo, por ejemplo, porque lees desde la entrada estándar, entonces zsync usará el nombre proporcionado con -f, o como último recurso, zsync-target.gz).
zsync puede funcionar con datos comprimidos y, en la mayoría de los casos en los que los datos no están ya comprimidos, es más eficiente comprimirlos primero. Si bien puedes simplemente comprimir el archivo para transferir con gzip, si usas esta opción, zsyncmake comprimirá el archivo por ti, produciendo un archivo .gz que está optimizado para zsync. Esto puede ser un 30% más eficiente en el momento de la descarga que comprimir con gzip --best, pero el archivo comprimido no será tan pequeño como el producido por gzip.
-Z
zsyncmake busca automáticamente dentro de los archivos comprimidos con gzip y exporta los datos subyacentes sin comprimir al archivo zsyncmake. En pruebas, esto ha demostrado proporcionar una mayor eficiencia de descarga. -Z anula el comportamiento predeterminado y trata los archivos gzip como datos binarios. Usa esto si es esencial que el usuario reciba los datos comprimidos (por ejemplo, porque una firma criptográfica solo está disponible para los datos comprimidos). zsync normalmente no es útil si especificas -Z, a menos que el archivo gzip se haya comprimido con la opción especial --rsync para que sea amigable con las transferencias diferenciales.

EJEMPLOS

zsyncmake -C -u http://ftp.uk.debian.org/debian/dists/sarge/main/binary-i386/Packages.gz Packages.gz

Nota el uso de -C para evitar que el cliente comprima el archivo al recibirlo; el sistema de gestión de paquetes Debian utiliza el archivo sin comprimir.

zsyncmake -z mi-volcado-subversion

En este caso, hay un archivo grande y comprimible para transferir. Esto crea una versión comprimida con gzip del archivo (optimizada para zsync) y un archivo .zsync. Se añade automáticamente una URL asumiendo que los dos archivos se servirán desde el mismo directorio en el servidor web.

zsyncmake -e -u http://www.mirrorservice.org/sites/ftp.freebsd.org/pub/FreeBSD/ports/distfiles/zsync-0.2.2.tar.gz zsync-0.2.2.tar.gz

Esto crea un archivo zsync que hace referencia al tarball fuente nombrado, el cual el cliente debería descargar de la URL dada. Este ejemplo es para descargar un tarball fuente para un puerto de FreeBSD, por lo tanto se especifica -e para que el cliente pueda coincidir con su md5sum.
