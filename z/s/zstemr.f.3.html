ZSTEMR

Propósito:

!>
!> ZSTEMR calcula valores propios seleccionados y, opcionalmente, vectores propios
!> de una matriz tridiagonal simétrica real T. Cualquier matriz irreducida de este tipo tiene
!> un conjunto bien definido de valores propios reales, todos diferentes entre sí, y los vectores propios reales correspondientes son ortogonales entre sí.
!>
!> El espectro puede calcularse de forma completa o parcial especificando
!> ya sea un intervalo (VL,VU] o un rango de índices IL:IU para los valores propios deseados.
!>
!> Dependiendo del número de valores propios deseados, estos se calculan ya sea
!> por bisección o por el algoritmo dqds. Los vectores propios ortogonales numéricamente
!> se calculan mediante el uso de varias factorizaciones L D L^T adecuadas cerca de cúmulos
!> de valores propios cercanos (denominados RRR, Representaciones Relativamente Robustas). Un esbozo informal del algoritmo sigue.
!>
!> Para cada bloque irreducido (submatriz) de T,
!>    (a) Calcular T - sigma I = L D L^T, de modo que L y D
!>        definen todos los valores propios buscados con alta precisión relativa.
!>        Esto significa que pequeños cambios relativos en las entradas de D y L
!>        causan solo pequeños cambios relativos en los valores propios y
!>        vectores propios. La representación estándar (no factorizada) de la
!>        matriz tridiagonal T no tiene esta propiedad en general.
!>    (b) Calcular los valores propios con la precisión adecuada.
!>        Si se desean los vectores propios, el algoritmo alcanza la precisión completa
!>        de los valores propios calculados solo justo antes
!>        de que los vectores correspondientes tengan que ser calculados, véanse los pasos c) y d).
!>    (c) Para cada cúmulo de valores propios cercanos, seleccionar un nuevo
!>        desplazamiento cercano al cúmulo, encontrar una nueva factorización, y refinar
!>        los valores propios desplazados con la precisión adecuada.
!>    (d) Para cada valor propio con una separación relativa suficientemente grande, calcular
!>        el vector propio correspondiente formando una factorización retorcida que revele el rango. Volver a c) para cualquier cúmulo que permanezca.
!>
!> Para más detalles, ver:
!> - Inderjit S. Dhillon y Beresford N. Parlett: 
!>   Linear Algebra and its Applications, 387(1), pp. 1-28, agosto de 2004.
!> - Inderjit Dhillon y Beresford Parlett:  SIAM Journal on Matrix Analysis and Applications, Vol. 25,
!>   2004.  También LAPACK Working Note 154.
!> - Inderjit Dhillon: ,
!>   Computer Science Division Technical Report No. UCB/CSD-97-971,
!>   UC Berkeley, mayo de 1997.
!>
!> Detalles Adicionales
!> 1.ZSTEMR solo funciona en máquinas que siguen el estándar de punto flotante IEEE-754
!> en su manejo de infinitos y NaNs.
!> Esto permite el uso de bucles internos eficientes que evitan la comprobación de
!> divisores cero.
!>
!> 2. Las rutinas LAPACK pueden usarse para reducir una matriz Hermitiana compleja a
!> forma tridiagonal simétrica real.
!>
!> (Cualquier matriz tridiagonal Hermitiana compleja tiene valores reales en su diagonal
!> y potencialmente números complejos en sus subdiagonales. Al aplicar una
!> transformación de similitud con una matriz diagonal apropiada
!> diag(1,e^{i \phy_1}, ... , e^{i \phy_{n-1}}), la matriz Hermitiana compleja
!> puede transformarse en una matriz simétrica real y la aritmética compleja
!> puede evitarse por completo.)
!>
!> Mientras que los vectores propios de la matriz tridiagonal simétrica real son reales,
!> los vectores propios de la matriz Hermitiana compleja original tienen entradas complejas
!> en general.
!> Dado que los drivers LAPACK sobrescriben los datos de la matriz con los vectores propios,
!> ZSTEMR acepta espacio de trabajo complejo para facilitar la interoperabilidad
!> con ZUNMTR o ZUPMTR.
!>

zstemr.f(3) - LAPACK

NAME

zstemr -
Performs a selective spectral transformation, and computes the eigenvectors of a real symmetric tridiagonal matrix.

SYNOPSIS

CALL ZSTEMR(
     JOBZ, RANGE, N, D, E, VL, VU, IL, IU, ABSTOL, M, NZC, Z, LDZ,
     ISUPPZ, WORK, LWORK, IWORK, LIWORK, INFO )

The subroutine uses the experimental routine ZLAHQR and the eigenvectors are computed using the ZSTEIN subroutine.

The eigenvalue computation is performed by the routine DLARRC.

Function/Subroutine Documentation

JOBZ

!>          JOBZ is CHARACTER*1
!>          = 'N':  Computes only the eigenvalues of A.
!>          = 'V':  Computes the eigenvalues and the corresponding eigenvectors
!>                  of A.
!>

RANGE

!>          RANGE is CHARACTER*1
!>          = 'A': all eigenvalues will be found.
!>          = 'V': all eigenvalues in the open interval (VL, VU) will be
!>                 found.
!>          = 'I': all eigenvalues in the open interval (IL, IU), whose
!>                 indices in the sorted list of eigenvalues are between
!>                 IL and IU, will be found.
!>

N

!>          N is INTEGER
!>          The order of the matrix A. N >= 0.
!>

D

!>          D is DOUBLE PRECISION array, dimension (N)
!>          The diagonal entries of the tridiagonal matrix A.
!>

E

!>          E is DOUBLE PRECISION array, dimension (N)
!>          The off-diagonal entries of the tridiagonal matrix A. E(1) is
!>          ignored.
!>

VL

!>          VL is DOUBLE PRECISION
!>          If RANGE = 'V', the lower bound of the eigenvalues.
!>

VU

!>          VU is DOUBLE PRECISION
!>          If RANGE = 'V', the upper bound of the eigenvalues.
!>

IL

!>          IL is INTEGER
!>          If RANGE = 'I', the lower index of the eigenvalues in the
!>          interval.
!>

IU

!>          IU is INTEGER
!>          If RANGE = 'I', the upper index of the eigenvalues in the
!>          interval.
!>

ABSTOL

!>          ABSTOL is DOUBLE PRECISION
!>          The absolute tolerance for the eigenvalues. For the cross-over
!>          point of two eigenvalues, the general formula for the tolerance is
!>          the machine precision times the interval between the specified
!>          eigenvalues, in which case the calculation of the eigenvectors
!>          might not be well-defined. ABSTOL is used to distinguish the
!>          near double eigenvalues.
!>          If ABSTOL is less than or equal to zero, then the machine epsilon
!>          is used.
!>

M

!>          M is INTEGER
!>          The total number of eigenvalues found.
!>          If RANGE = 'A', M = N.
!>          If RANGE = 'V', M = the number of eigenvalues in (VL, VU].
!>          If RANGE = 'I', M = IU - IL + 1.
!>

NZC

!>          NZC is INTEGER
!>          The number of eigenvectors stored in the array Z.
!>          If JOBZ = 'I' or JOBZ = 'N', NZC = 0.
!>          If JOBZ = 'V', NZC is the number of eigenvectors to be held in the
!>          array Z.
!>          If RANGE = 'A', then NZC >= max(1,N).
!>          If RANGE = 'V', then NZC >= the number of eigenvalues in (VL, VU].
!>          If RANGE = 'I', then NZC >= IU-IL+1.
!>          If NZC = -1, then a workspace query is assumed; the
!>          routine calculates the number of columns of the array Z that
!>          are needed to hold the eigenvectors.
!>          This value is returned as the first entry of the Z array, and
!>          no error message related to NZC is issued by XERBLA.
!>

ISUPPZ

!>          ISUPPZ is INTEGER array, dimension ( 2*max(1,M) )
!>          The support of the eigenvectors in Z, i.e., the indices
!>          indicating the nonzero elements in Z. The i-th computed eigenvector
!>          is nonzero only in elements ISUPPZ( 2*i-1 ) through
!>          ISUPPZ( 2*i ). This is relevant in the case when the matrix
!>          is split. ISUPPZ is only accessed when JOBZ is 'V' and N > 0.
!>

TRYRAC

!>          TRYRAC is LOGICAL
!>          If TRYRAC = .TRUE., indicates that the code should check whether
!>          the tridiagonal matrix defines its eigenvalues to high relative
!>          accuracy.  If so, the code uses relative-accuracy preserving
!>          algorithms that might be (a bit) slower depending on the matrix.
!>          If the matrix does not define its eigenvalues to high relative
!>          accuracy, the code can uses possibly faster algorithms.
!>          If TRYRAC = .FALSE., the code is not required to guarantee
!>          relatively accurate eigenvalues and can use the fastest possible
!>          techniques.
!>          On exit, a .TRUE. TRYRAC will be set to .FALSE. if the matrix
!>          does not define its eigenvalues to high relative accuracy.
!>

WORK

!>          WORK is DOUBLE PRECISION array, dimension (LWORK)
!>          On exit, if INFO = 0, WORK(1) returns the optimal
!>          (and minimal) LWORK.
!>

LWORK

!>          LWORK is INTEGER
!>          The dimension of the array WORK. LWORK >= max(1,18*N)
!>          if JOBZ = 'V', and LWORK >= max(1,12*N) if JOBZ = 'N'.
!>          If LWORK = -1, then a workspace query is assumed; the routine
!>          only calculates the optimal size of the WORK array, returns
!>          this value as the first entry of the WORK array, and no error
!>          message related to LWORK is issued by XERBLA.
!>

IWORK

!>          IWORK is INTEGER array, dimension (LIWORK)
!>          On exit, if INFO = 0, IWORK(1) returns the optimal LIWORK.
!>

LIWORK

!>          LIWORK is INTEGER
!>          The dimension of the array IWORK.  LIWORK >= max(1,10*N)
!>          if the eigenvectors are desired, and LIWORK >= max(1,8*N)
!>          if only the eigenvalues are to be computed.
!>          If LIWORK = -1, then a workspace query is assumed; the
!>          routine only calculates the optimal size of the IWORK array,
!>          returns this value as the first entry of the IWORK array, and
!>          no error message related to LIWORK is issued by XERBLA.
!>

INFO

!>          INFO is INTEGER
!>          On exit, INFO
!>          = 0:  successful exit
!>          < 0:  if INFO = -i, the i-th argument had an illegal value
!>          > 0:  if INFO = 1X, internal error in DLARRE,
!>                if INFO = 2X, internal error in ZLARRV.
!>                Here, the digit X = ABS( IINFO ) < 10, where IINFO is
!>                the nonzero error code returned by DLARRE or
!!>                ZLARRV, respectively.
!>
