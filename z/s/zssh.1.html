NOMBRE

zssh - envoltura interactiva para transferencia de archivos para ssh

SINOPSIS

zssh [opciones de zssh] [--] [opciones de ssh]
ztelnet [opciones de zssh] [--] [opciones de telnet]

DESCRIPCIÓN

zssh (Zmodem SSH) es un programa para transferir interactivamente archivos a una máquina remota mientras se utiliza el shell seguro ( ssh ). Está destinado a ser una alternativa conveniente a scp , permitiendo transferir archivos sin tener que abrir otra sesión y volver a autenticarse.

zssh es una envoltura interactiva para ssh utilizada para cambiar la conexión ssh entre el shell remoto y las transferencias de archivos. Esto se logra utilizando otro par tty/pty entre el usuario y el proceso ssh local para conectar el tty del usuario (modo shell remoto) o algún otro proceso (modo de transferencia de archivos) a la conexión ssh.

ztelnet se comporta de manera similar a zssh, excepto que se usa telnet en lugar de ssh. Es equivalente a 'zssh -s "telnet -8 -E"'

Los archivos se transfieren a través del protocolo zmodem, utilizando los comandos rz y sz.

zssh se comporta como una sesión ssh normal hasta que se presiona la secuencia de escape (por defecto es ^@, que se puede producir presionando C-espacio, o C-2, o C-`), lo que habilita el modo de transferencia de archivos. Luego se muestra un nuevo prompt y se pueden ejecutar comandos localmente para iniciar transferencias de archivos (entre otras cosas). Se comporta aproximadamente como un shell local con edición de línea, historial y autocompletado (gracias a libreadline), expansión de nombres y caracteres de escape ( " ' y \ ).

Los siguientes comandos internos son manejados por zssh mismo: ? , cd , disconnect , escape , exit , help , hook , quit , repeat , rz , suspend , sz , version

cd <dir>
cambiar directorio actual
disconnect
desconectar y salir
escape [^X]
Cambiar la tecla de escape a ^X. Sin argumento, imprime la tecla de escape actual.
exit
salir del modo de transferencia de archivos. ^D también puede usarse para este propósito.
help
imprimir ayuda y consejos
?
hook prg [args]
Engancha el programa 'prg' al pty. Su entrada y salida estándar pasarán por el canal ssh.
escribir 'sz'/'rz' es de hecho equivalente a 'hook sz'/'hook rz'
Una imaginación peculiar es muy útil para sacar el máximo provecho de esta característica.
quit
igual que exit.
repeat
repite el comando indefinidamente (^C para interrumpir). Útil, por ejemplo, si utilizas un script remoto que invoca "sz" y no quieres escribir "rz" cada vez... Sin embargo, recuerda que varios archivos pueden ser transferidos por un solo par sz/rz, por lo que normalmente no es necesario usar repeat.
rz
Recibir archivos de la máquina remota. Ejecuta rz y conecta el proceso al canal ssh. Se requiere ejecutar sz en la máquina REMOTA:
1)
ejecuta `sz <archivo_remoto> ...' desde el shell de la máquina remota
2)
presiona la secuencia de escape (C-espacio) para entrar en modo de transferencia de archivos
3)
ejecuta el comando interno `rz'
suspend
suspender zssh (volver al shell local)
sz <archivo> ...
Enviar archivos a la máquina remota. Ejecuta sz y conecta el proceso al canal ssh. No hay necesidad de ejecutar rz manualmente en el lado remoto.
version
imprimir información de versión

Los comandos internos rz, sz, hook y exit regresan al modo shell después de completarse.

OPCIONES

-f
--force
No hacer ninguna pregunta al usuario
-h
--help
mostrar ayuda básica
-s cmd
--shell cmd
ejecutar cmd como shell remoto en lugar del predeterminado "ssh -e none" (zssh) o "telnet -8 -E" (ztelnet)
ej: zssh -s "rsh -x"
-V
--version
mostrar versión
-z ^X
--zssh-escape ^X
establecer la secuencia de escape a ^X

-- puede ser utilizado para separar las opciones de zssh de las de ssh.
Otros argumentos se pasan literalmente a ssh/telnet/lo que sea.

ENTORNO

ZSSHESCAPE
Establecer la variable de entorno ZSSHESCAPE permite anular la secuencia de escape predeterminada. ZSSHESCAPE solo debe contener dos caracteres en el formato `^X', lo que significa que ^X será la nueva secuencia de escape.

REQUISITOS

Los siguientes binarios deben estar instalados correctamente para que zssh funcione:

ssh/telnet/...
el shell remoto a ejecutar (máquina local)
sz rz
programas de envío y recepción zmodem. Deben estar tanto en la máquina local como en la remota, y (con suerte) de versiones compatibles.

CONSEJOS

Si la transferencia de archivos se inicia pero nunca se completa
(es decir, una línea como:
Bytes Enviados: 38144/4610624 BPS:3424 ETA 22:15
o
Bytes Enviados: 0/ 513 BPS:0 ETA 00:00 Reintento 0: Recibido ZCAN
se puede ver, pero la transferencia nunca se completa
)
Lo más probable es que el pty/tty en uno de los sistemas no sea 8-bit clean. (Linux es 8-bit clean, NetBSD no lo es).
Usar la opción -e (escape) de rz debería resolver este problema.

Las transferencias se pueden interrumpir con ^C (algo experimental =)

Si te quedas atascado en rz/sz (por ejemplo, acabas de ejecutar rz, pero luego decidiste no transmitir nada), presiona una docena de ^X (Ctrl-X, no el escape de zssh!) para detenerlo

Usa `sz -y <archivos>' para sobrescribir archivos en el otro lado

BUGS / LIMITACIONES

Es posible que a veces tengas que presionar retorno 2 o 3 veces después de completar la transferencia de archivos para volver al shell. A veces se muestran algunos dígitos; no te preocupes, no te harán daño (a ti ni a tu terminal) ...

El tty puede (a veces) quedar algo alterado después de una transferencia interrumpida (usando ^C). Escribir `reset' en este caso debería ayudar.

no hay soporte para pipes, redirección (y otras cosas) en el shell... pero después de todo, ya existen shells maravillosos =)
