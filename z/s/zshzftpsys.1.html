NOMBRE

zshzftpsys - interfaz de funciones de zshftp

DESCRIPCIÓN

Esto describe el conjunto de funciones de shell suministradas con la distribución de código fuente como una interfaz al comando incorporado zftp, permitiéndote realizar operaciones FTP desde la línea de comandos del shell o dentro de funciones o scripts. La interfaz es similar a un cliente FTP tradicional (por ejemplo, el propio comando ftp, ver ftp(1)), pero como se realiza completamente dentro del shell, todas las características familiares de completado, edición y globbing, etc., están presentes, y las macros son particularmente sencillas de escribir ya que son solo funciones de shell ordinarias.

El requisito previo es que el comando zftp, como se describe en zshmodules(1), debe estar disponible en la versión de zsh instalada en tu sitio. Si el shell está configurado para cargar nuevos comandos en tiempo de ejecución, probablemente lo esté: escribir `zmodload zsh/zftp' lo asegurará (si eso se ejecuta silenciosamente, ha funcionado). Si este no es el caso, es posible que zftp haya sido enlazado al shell de todos modos: para probar esto, escribe `which zftp' y si zftp está disponible obtendrás el mensaje `zftp: shell built-in command'.

Los comandos dados directamente con el incorporado zftp pueden intercalarse entre las funciones de este conjunto; en algunos casos, usar zftp directamente puede hacer que alguna de la información de estado almacenada en parámetros del shell se vuelva inválida. Ten en cuenta en particular la descripción de las variables $ZFTP_TMOUT, $ZFTP_PREFS y $ZFTP_VERBOSE para zftp.

INSTALACIÓN

Debes asegurarte de que todas las funciones del directorio Functions/Zftp de la distribución fuente estén disponibles; todas comienzan con las dos letras `zf'. Es posible que ya se hayan instalado en tu sistema; de lo contrario, necesitarás encontrarlas y copiarlas. El directorio debería aparecer como uno de los elementos del array $fpath (esto ya debería ser el caso si se instalaron), y al menos la función zfinit debería ser cargada automáticamente; esta cargará automáticamente el resto. Finalmente, para inicializar el uso del sistema necesitas llamar a la función zfinit. El siguiente código en tu .zshrc se encargará de esto; asume que las funciones están almacenadas en el directorio ~/myfns:

fpath=(~/myfns $fpath)
autoload -U zfinit
zfinit

Nota que zfinit asume que estás usando el método zmodload para cargar el comando zftp. Si ya está incorporado en el shell, cambia zfinit por zfinit -n. Es útil (aunque no esencial) que la llamada a zfinit aparezca después de cualquier código para inicializar el nuevo sistema de completado, de lo contrario se darán comandos compctl innecesarios.

FUNCIONES

La secuencia de operaciones para realizar una transferencia de archivos es esencialmente la misma que en un cliente FTP estándar. Ten en cuenta que, debido a una peculiaridad del comando incorporado getopts del shell, para aquellas funciones que manejan opciones debes usar `--' en lugar de `-' para asegurar que los argumentos restantes se traten literalmente (un solo `-' se trata como un argumento).

Abrir una conexión

zfparams [ host [ usuario [ contraseña ... ] ] ]
Establece o muestra los parámetros para un futuro zfopen sin argumentos. Si no se dan argumentos, se muestran los parámetros actuales (la contraseña se mostrará como una línea de asteriscos). Si se da un host, y falta el usuario o la contraseña, se te pedirán; además, cualquier parámetro dado como `?' se pedirá, y si el `?' va seguido de una cadena, esa se usará como prompt. Como zfopen llama a zfparams para almacenar los parámetros, generalmente no es necesario llamarlo directamente.

Un solo argumento `-' eliminará los parámetros almacenados. Esto también causará la eliminación de la memoria del último directorio (y así sucesivamente) en el otro host.

zfopen [ -1 ] [ host [ usuario [ contraseña [ cuenta ] ] ] ]
Si está presente host, abre una conexión a ese host bajo el nombre de usuario usuario con la contraseña contraseña (y, en las raras ocasiones en que sea necesario, la cuenta cuenta). Si falta un parámetro necesario o se da como `?', se te pedirá. Si host no está presente, usa un conjunto de parámetros previamente almacenado.

Si el comando fue exitoso, y el terminal es compatible con xterm o es sun-cmd, aparecerá un resumen en la barra de título, dando el host:directorio local y el host:directorio remoto; esto lo maneja la función zftp_chpwd, descrita a continuación.

Normalmente, el host, usuario y contraseña se registran internamente para reabrir más tarde, ya sea con un zfopen sin argumentos, o automáticamente (ver abajo). Con la opción `-1', no se almacena información. Además, si un comando de apertura con argumentos falló, los parámetros no se conservarán (y cualquier parámetro anterior también se eliminará). Un zfopen por sí solo, o un zfopen -1, nunca altera los parámetros almacenados.

Tanto zfopen como zfanon (pero no zfparams) entienden URLs de la forma ftp://host/ruta... como significando conectar al host, luego cambiar de directorio a ruta (que debe ser un directorio, no un archivo). El `ftp://' puede omitirse; la `/' final es suficiente para desencadenar el reconocimiento de la ruta. Nota que no se reconocen prefijos distintos de `ftp:', y que todos los caracteres después de la primera barra más allá de host son significativos en ruta.

zfanon [ -1 ] host
Abre una conexión a host para FTP anónimo. El nombre de usuario usado es `anonymous'. La contraseña (que se informará la primera vez) se genera como usuario@host; esto se almacena entonces en el parámetro de shell $EMAIL_ADDR que alternativamente puede establecerse manualmente a una cadena adecuada.

Gestión de directorios

zfcd [ dir ]
zfcd -
zfcd viejo nuevo
Cambia el directorio actual en el servidor remoto: esto se implementa para tener muchas de las características del comando incorporado del shell cd.

En la primera forma con dir presente, cambia al directorio dir. El comando `zfcd ..' se trata especialmente, por lo que se garantiza que funcione en servidores no UNIX (ten en cuenta que esto lo maneja internamente zftp). Si dir se omite, tiene el efecto de `zfcd ~'.

La segunda forma cambia al directorio previamente actual.

La tercera forma intenta cambiar el directorio actual reemplazando la primera ocurrencia de la cadena viejo con la cadena nuevo en el directorio actual.

Ten en cuenta que en este comando, y de hecho en cualquier lugar donde se espere un nombre de archivo remoto, la cadena que en el host local corresponde a `~' se convierte de nuevo a `~' antes de pasarse a la máquina remota. Esto es conveniente debido a la forma en que se realiza la expansión en la línea de comandos antes de que zfcd reciba una cadena. Por ejemplo, supongamos que el comando es `zfcd ~/foo'. El shell lo expandirá a una ruta completa como `zfcd /home/user2/pws/foo'. En esta etapa, zfcd reconoce la ruta inicial como correspondiente a `~' y enviará el directorio a la máquina remota como ~/foo, de modo que el `~' será expandido por el servidor al directorio remoto correcto. Otros directorios con nombre de la forma `~nombre' no se tratan de esta manera.

zfhere
Cambia el directorio en el servidor remoto al que corresponde el directorio local actual, con manejo especial de `~' como en zfcd. Por ejemplo, si el directorio local actual es ~/foo/bar, entonces zfhere realiza el efecto de `zfcd ~/foo/bar'.
zfdir [ -rfd ] [ -
Lista el contenido del directorio remoto actual. La opción `-r' realiza una lista recursiva. La opción `-f' muestra los nombres de archivo como se dan en el servidor remoto, sin ninguna traducción. La opción `-d' muestra los directorios, sin sus contenidos. Si el directorio actual en el servidor remoto no se puede determinar, se dará un mensaje de error.

Ver parámetros de conexión

zfinfo
Muestra información sobre la conexión actual, incluyendo el nombre del host remoto, el usuario, el directorio actual en el host remoto y el directorio local actual.

Por ejemplo:

bash-3.2$ zfinfo
Remote host:   ftp.Funet.Fi
User:          fred
Remote dir:    /pub/Net/
Local dir:     /home/fred/

Transferencias de archivos

zfohear remoto [ local ]
Descarga el archivo remoto desde el host remoto al host local. Si local se omite, se usa el nombre del archivo remoto. Si local es un directorio, se usa el nombre del archivo remoto como nombre de archivo dentro de ese directorio. La transferencia se realiza en modo binario por defecto; para usar el modo ASCII usa `zfohear -a'.

Si el archivo remoto es un nombre de directorio, entonces zfohear actúa como zfget, y descarga recursivamente el directorio.

zfput local [ remoto ]
Sube el archivo local al host remoto. Si remoto se omite, se usa el nombre del archivo local. Si remoto es un directorio, se usa el nombre del archivo local como nombre de archivo dentro de ese directorio. La transferencia se realiza en modo binario por defecto; para usar el modo ASCII usa `zfput -a'.

Si el archivo local es un nombre de directorio, entonces zfput actúa como zfsend, y sube recursivamente el directorio.

zfsend [ -a ] directorio
Sube el directorio directorio recursivamente al host remoto. La opción `-a' fuerza el uso del modo ASCII para la transferencia. El nombre del directorio remoto se derivará del nombre del directorio local.
zfget [ -a ] directorio
Descarga el directorio directorio recursivamente desde el host remoto al host local. La opción `-a' fuerza el uso del modo ASCII para la transferencia. El nombre del directorio local se derivará del nombre del directorio remoto.
zflist [ - ]
Lista el contenido del directorio remoto actual. La opción `-' realiza una lista detallada. Es posible configurar la forma de la lista (por ejemplo, para tratar los servidores como si fueran UNIX, MVS o VM/370) mediante la variable de entorno $ZFTP_LISTFMT; de lo contrario, se intentará deducir el formato del servidor.
zfdel nombre
Elimina el archivo nombre en el servidor remoto.
zfmkd nombre
Crea el directorio nombre en el servidor remoto.
zfrmd nombre
Elimina el directorio nombre en el servidor remoto.
zfren viejo nuevo
Renombra el archivo viejo a nuevo en el servidor remoto.

Cerrar una conexión

zfclose
Cierra la conexión FTP actual.

Opciones de configuración

zfprefs [ - ]
Muestra los valores actuales de las variables de configuración. Si se da la opción `-', se restablecen a sus valores por defecto.

Las siguientes variables de configuración están disponibles:

$ZFTP_TMOUT
El tiempo de espera en segundos para las operaciones de FTP. Por defecto es 60.
$ZFTP_VERBOSE
Si se establece a un valor distinto de cero, se mostrarán todas las comunicaciones con el servidor FTP.
$ZFTP_PREFS
El nombre del archivo donde se almacenan las preferencias del usuario. Por defecto es ~/.zftp-prefs.
$ZFTP_HOST
El último host FTP conectado.
$ZFTP_USER
El último nombre de usuario FTP conectado.
$ZFTP_PASS
La última contraseña FTP conectada.
$ZFTP_ACCT
La última cuenta FTP conectada.
$ZFTP_REMOTE_DIR
El último directorio remoto en el que se estuvo.
$ZFTP_LOCAL_DIR
El último directorio local en el que se estuvo.
zftarget host
Cambia el host objetivo a host sin abrir una conexión. Esto puede ser útil para realizar operaciones locales en los parámetros de un host remoto, por ejemplo, para obtener información de su directorio actual, o para enviar comandos de lista para él.

Errores y desiderata

Notifíquese cualquier error o sugerencia al autor.

Puede haber un número de problemas debido a las diferencias entre los servidores FTP y los diversos problemas que pueden surgir. Por ejemplo, algunos servidores no tienen el comando SIZE, y por lo tanto los tiempos de transferencia no se muestran. En otros servidores, el comando SIZE devuelve el tamaño incorrecto, o los comandos MKD y RMD tienen efectos secundarios extraños.

Asegúrate de que el comando zftp está realmente compilado en tu versión de zsh. De lo contrario, la mayoría de estas funciones no funcionarán.

NAME

zftp - remote file transfer program

SYNOPSIS

zftp [ -a ] [ -c ] [ -d ] [ -h ] [ -k ] [ -l ] [ -n ] [ -p ] [ -q ] [ -r ] [ -s ] [ -t ] [ -u ] [ -v ] [ -z ] [ host [ user ] ]

DESCRIPTION

zftp is a remote file transfer program that uses compression to speed up file transfers. It supports the standard FTP protocol, and also some extensions. The command-line arguments are the same as those for ftp(1), with the exception of the -z flag, which is used to control compression.

-a
Activates automatic retrieval of files. This means that when zftp is started, it will automatically attempt to download the files specified in the configuration file.
-c
Forces compression to be turned off. This is useful when transferring files that are already compressed, or when the network speed is very high.
-d
Debug mode. This will print out more information about the connection and file transfers.
-h
Help. Prints a list of available commands.
-k
Keep. When transferring files, this option will keep the local copy of the file after the transfer is complete.
-l
List. This option will list the contents of the remote directory.
-n
No auto-login. This will prevent zftp from automatically logging in to the remote server.
-p
Passive mode. This option will force zftp to use passive FTP mode.
-q
Quiet mode. This will suppress most of the output from zftp.
-r
Recursive. This option is used when transferring directories. It will transfer the directory and all of its contents recursively.
-s
Script mode. This option is used to run zftp in script mode, where commands are read from a file.
-t
Set modification times. This option will attempt to set the modification time of the local file to match the remote file.
-u
Upload. This option is used to upload files to the remote server.
-v
Verbose mode. This will print out more information about the connection and file transfers.
-z
Compress. This option enables compression for file transfers.

The host and user arguments are optional. If they are not provided, zftp will prompt the user for them.

Commands

The following commands are available within the zftp program:

abort
Abort the current file transfer.
account [password]
Send an account command, using the supplied password if given.
append local-file [ remote-file ]
Append local-file to the remote-file on the remote machine. If remote-file is not specified, then the base name of local-file is used.
ascii
Set file transfer mode to ASCII.
bell
Ring the terminal bell after a transfer is completed.
binary
Set file transfer mode to binary.
bye
Terminate the FTP session and exit.
cd remote-directory
Change the working directory on the remote server.
close
Terminate the FTP session and return to the command interpreter.
cdup
Change the remote working directory to the parent directory.
cr
Toggle carriage-return stripping on output.
delete remote-file
Delete a file on the remote server.
debug
Toggle debug mode.
dir [ dir-options ] [ dir ]
Produce a long directory listing. The arguments dir-options and dir are passed directly to the server and their effect is implementation dependent, but specifying a particular remote directory dir is usually possible. The output is passed through a pager given by the environment variable $PAGER, or `more' if that is not set.

The directory is usually cached for re-use. In fact, two caches are maintained. One is for use when there is no dir-options or dir, i.e. a full listing of the current remote directory; it is flushed when the current remote directory changes. The other is kept for repeated use of zfdir with the same arguments; for example, repeated use of `zfdir /pub/gnu' will only require the directory to be retrieved on the first call. Alternatively, this cache can be re-viewed with the -r option. As relative directories will confuse zfdir, the -f option can be used to force the cache to be flushed before the directory is listed. The option -d will delete both caches without showing a directory listing; it will also delete the cache of file names in the current remote directory, if any.

zfls [ ls-options ] [ dir ]
List files on the remote server. With no arguments, this will produce a simple list of file names for the current remote directory. Any arguments are passed directly to the server. No pager and no caching is used.

Status commands

zftype [ type ]
With no arguments, show the type of data to be transferred, usually ASCII or binary. With an argument, change the type: the types `A' or `ASCII' for ASCII data and `B' or `BINARY', `I' or `IMAGE' for binary data are understood case-insensitively.
zfstat [ -v ]
Show the status of the current or last connection, as well as the status of some of zftp's status variables. With the -v option, a more verbose listing is produced by querying the server for its version of events, too.

Retrieving files

The commands for retrieving files all take at least two options. -G suppresses remote filename expansion which would otherwise be performed (see below for a more detailed description of that). -t attempts to set the modification time of the local file to that of the remote file: see the description of the function zfrtime below for more information.

zfget [ -Gtc ] file1 ...
Retrieve all the listed files file1 ... one at a time from the remote server. If a file contains a `/', the full name is passed to the remote server, but the file is stored locally under the name given by the part after the final `/'. The option -c (cat) forces all files to be sent as a single stream to standard output; in this case the -t option has no effect.
zfuget [ -Gvst ] file1 ...
As zfget, but only retrieve files where the version on the remote server is newer (has a later modification time), or where the local file does not exist. If the remote file is older but the files have different sizes, or if the sizes are the same but the remote file is newer, the user will usually be queried. With the option -s, the command runs silently and will always retrieve the file in either of those two cases. With the option -v, the command prints more information about the files while it is working out whether or not to transfer them.
zfcget [ -Gt ] file1 ...
As zfget, but if any of the local files exists, and is shorter than the corresponding remote file, the command assumes that it is the result of a partially completed transfer and attempts to transfer the rest of the file. This is useful on a poor connection which keeps failing.

Note that this requires a commonly implemented, but non-standard, version of the FTP protocol, so is not guaranteed to work on all servers.

zfgcp [ -Gt ] remote-file local-file
zfgcp [ -Gt ] rfile1 ... ldir
This retrieves files from the remote server with arguments behaving similarly to the cp command.

In the first form, copy remote-file from the server to the local file local-file.

In the second form, copy all the remote files rfile1 ... into the local directory ldir retaining the same basenames. This assumes UNIX directory semantics.

Sending files

zfput [ -r ] file1 ...
Send all the file1 ... given separately to the remote server. If a filename contains a `/', the full filename is used locally to find the file, but only the basename is used for the remote file name.

With the option -r, if any of the files are directories they are sent recursively with all their subdirectories, including files beginning with `.'. This requires that the remote machine understand UNIX file semantics, since `/' is used as a directory separator.

zfuput [ -vs ] file1 ...
As zfput, but only send files which are newer than their remote equivalents, or if the remote file does not exist. The logic is the same as for zfuget, but reversed between local and remote files.
zfcput file1 ...
As zfput, but if any remote file already exists and is shorter than the local equivalent, assume it is the result of an incomplete transfer and send the rest of the file to append to the existing part. As the FTP append command is part of the standard set, this is in principle more likely to work than zfcget.
zfpcp local-file remote-file
zfpcp lfile1 ... rdir
This sends files to the remote server with arguments behaving similarly to the cp command.

With two arguments, copy local-file to the server as remote-file.

With more than two arguments, copy all the local files lfile1 ... into the existing remote directory rdir retaining the same basenames. This assumes UNIX directory semantics.

A problem arises if you attempt to use zfpcp lfile1 rdir, i.e. the second form of copying but with two arguments, as the command has no simple way of knowing if rdir corresponds to a directory or a filename. It attempts to resolve this in various ways. First, if the rdir argument is `.' or `..' or ends in a slash, it is assumed to be a directory. Secondly, if the operation of copying to a remote file in the first form failed, and the remote server sends back the expected failure code 553 and a reply including the string `Is a directory', then zfpcp will retry using the second form.

Closing the connection

zfclose
Close the connection.

Session management

zfsession [ -lvod ] [ sessname ]
Allows you to manage multiple FTP sessions at once. By default, connections take place in a session called `default'; by giving the command `zfsession sessname' you can change to a new or existing session with a name of your choice. The new session remembers its own connection, as well as associated shell parameters, and also the host/user parameters set by zfparams. Hence you can have different sessions set up to connect to different hosts, each remembering the appropriate host, user and password.

With no arguments, zfsession prints the name of the current session; with the option -l it lists all sessions which currently exist, and with the option -v it gives a verbose list showing the host and directory for each session, where the current session is marked with an asterisk. With -o, it will switch to the most recent previous session.

With -d, the given session (or else the current one) is removed; everything to do with it is completely forgotten. If it was the only session, a new session called `default' is created and made current. It is safest not to delete sessions while background commands using zftp are active.

zftransfer sess1:file1 sess2:file2
Transfer files between two sessions; no local copy is made. The file is read from the session sess1 as file1 and written to session sess2 as file file2; file1 and file2 may be relative to the current directories of the session. Either sess1 or sess2 may be omitted (though the colon should be retained if there is a possibility of a colon appearing in the file name) and defaults to the current session; file2 may be omitted or may end with a slash, in which case the basename of file1 will be added. The sessions sess1 and sess2 must be distinct.

The operation is performed using pipes, so it is required that the connections still be valid in a subshell, which is not the case under versions of some operating systems, presumably due to a system bug.

Bookmarks

The two functions zfmark and zfgoto allow you to `bookmark' the present location (host, user and directory) of the current FTP connection for later use. The file to be used for storing and retrieving bookmarks is given by the parameter $ZFTP_BMFIL

E; si no se establece cuando se llama a una de las dos funciones, se establecerá en el archivo .zfbkmarks en el directorio donde residen tus archivos de inicio de zsh (normalmente ~).

zfmark [ marcador ]
Si se le pasa un argumento, marca el host, usuario y directorio actual bajo el nombre marcador para su uso posterior por zfgoto. Si no hay ninguna conexión abierta, utiliza los valores de la última conexión inmediatamente antes de que se cerrara; es un error si no hubo ninguna. Cualquier marcador existente con el mismo nombre será reemplazado silenciosamente.

Si no se le pasa ningún argumento, lista los marcadores existentes y los puntos a los que se refieren en el formato usuario@host:directorio; este es el formato en el que se almacenan y el archivo puede editarse directamente.

zfgoto [ -n ] marcador
Regresa a la ubicación dada por marcador, como se estableció previamente con zfmark. Si la ubicación tiene el usuario `ftp' o `anonymous', abre la conexión con zfanon, de modo que no se requiere contraseña. Si los parámetros de usuario y host coinciden con los almacenados para la sesión actual, si los hay, se utilizarán esos, y de nuevo no se requerirá contraseña. De lo contrario, se le pedirá una contraseña.

Con la opción -n, el marcador se considera un apodo almacenado por el programa ncftp en su archivo de marcadores, que se asume que es ~/.ncftp/bookmarks. La función funciona de manera idéntica en otros aspectos. Tenga en cuenta que no existe ningún mecanismo para añadir o modificar marcadores de ncftp desde las funciones de zftp.

Otras funciones

En su mayor parte, estas funciones no se llamarán directamente (aparte de zfinit), pero se describen aquí por completitud. Es posible que desees modificar zftp_chpwd y zftp_progress, en particular.

zfinit [ -n ]
Como se describió anteriormente, esto se utiliza para inicializar el sistema de funciones de zftp. La opción -n debe usarse si el comando zftp ya está integrado en el shell.
zfautocheck [ -dn ]
Esta función se llama para implementar el comportamiento de reapertura automática, como se describe con más detalle a continuación. Las opciones deben aparecer en el primer argumento; -n evita que el comando cambie al directorio anterior, mientras que -d evita que establezca la variable do_close, lo que de lo contrario hace como indicador para cerrar automáticamente la conexión después de una transferencia. El host y el directorio de la última sesión se almacenan en la variable $zflastsession, pero los parámetros internos de host/usuario/contraseña también deben estar configurados correctamente.
zfcd_match prefijo sufijo
Esto realiza la coincidencia para completar nombres de directorios remotos. Si el servidor remoto es UNIX, intentará persuadir al servidor para que liste el directorio remoto con subdirectorios marcados, lo que normalmente funciona pero no está garantizado. En otros hosts, simplemente llama a zfget_match y, por lo tanto, completa todos los archivos, no solo los directorios. En algunos sistemas, los directorios pueden no parecer ni siquiera nombres de archivo.
zfget_match prefijo sufijo
Esto realiza la coincidencia para completar nombres de archivo remotos. Almacena en caché los archivos del directorio actual (solo) en el parámetro del shell $zftp_fcache. Tiene el formato para ser llamado por la opción -K de compctl, pero también funciona cuando se llama desde una función de completado de estilo de widget con prefijo y sufijo establecidos adecuadamente.
zfrglob nombrevar
Realiza globbing remoto, como se describe con más detalle a continuación. nombrevar es el nombre de una variable que contiene el patrón a expandir; si hubo alguna coincidencia, la misma variable se establecerá con el conjunto expandido de nombres de archivo al regresar.
zfrtime archivo_local archivo_remoto [ hora ]
Establece el archivo local archivo_local para que tenga la misma hora de modificación que el archivo remoto archivo_remoto, o la hora explícita hora en formato FTP CCYYMMDDhhmmSS para la zona horaria GMT. Esto utiliza el módulo zsh/datetime del shell para realizar la conversión de GMT a hora local.
zftp_chpwd
Esta función se llama cada vez que se abre o cierra una conexión, o cambia el directorio remoto. Esta versión modifica la barra de título de un emulador de terminal compatible con xterm o sun-cmd para reflejar los nombres de host locales y remotos y los directorios actuales. Funciona mejor cuando se combina con la función chpwd. En particular, una función de la forma
chpwd() {
  if [[ -n $ZFTP_USER ]]; then
    zftp_chpwd
  else
    # chpwd habitual, por ejemplo, poner host:directorio en la barra de título
  fi
}

encaja bien.

zftp_progress
Esta función muestra el estado de la transferencia. No escribirá nada a menos que la salida vaya a un terminal; sin embargo, si transfieres archivos en segundo plano, deberías desactivar los informes de progreso manualmente usando `zstyle ':zftp:*' progress none'. Ten en cuenta también que si la modificas, cualquier salida *debe* ser a la salida de error estándar, ya que la salida estándar puede ser un archivo que se está recibiendo. El formato del medidor de progreso, o si se utiliza o no, se puede configurar sin modificar la función, como se describe en la siguiente sección.
zffcache
Esto se utiliza para implementar el almacenamiento en caché de archivos en el directorio actual para cada sesión por separado. Lo utilizan zfget_match y zfrglob.

CARACTERISTICAS VARIAS

Configuración

Varios estilos están disponibles utilizando el mecanismo de estilo estándar del shell, descrito en zshmodules(1). Brevemente, el comando `zstyle ':zftp:*' estilo valor ...'. define el estilo con el valor valor; se puede dar más de un valor, aunque eso no es útil en los casos descritos aquí. Estos valores se utilizarán en todo el sistema de funciones de zftp. Para un control más preciso, el primer argumento, que da un patrón que coincide con los *contextos* en los que se aplica el estilo, se puede modificar para incluir una función particular, como por ejemplo `:zftp:zfget': el estilo tendrá entonces el valor dado solo en la función zfget, y anulará los estilos establecidos en `:zftp:*'. Tenga en cuenta que solo se utiliza el nombre de la función de nivel superior, tal como lo llama el usuario; la llamada a funciones de nivel inferior es transparente para el usuario. Por lo tanto, las modificaciones a la barra de título en zftp_chpwd utilizan los contextos :zftp:zfopen, :zftp:zfcd, etc., dependiendo de dónde se llamó. Los siguientes estilos son entendidos:

progress
Controla la forma en que zftp_progress informa sobre el progreso de una transferencia. Si está vacío, sin definir o es `none', no se realiza ningún informe de progreso; si es `bar', se muestra una barra creciente de video inverso; si es `percent' (o cualquier otra cadena, aunque esto puede cambiar en el futuro), se muestra el porcentaje del archivo transferido. El medidor de barra requiere que el ancho del terminal esté disponible a través del parámetro $COLUMNS (normalmente esto se establece automáticamente). Si no se dispone del tamaño del archivo que se está transfiriendo, los medidores bar y percent simplemente mostrarán el número de bytes transferidos hasta el momento.

Cuando se ejecuta zfinit, si este estilo no está definido para el contexto :zftp:*, se establecerá en `bar'.

update
Especifica el intervalo de tiempo mínimo entre actualizaciones del medidor de progreso en segundos. No se realiza ninguna actualización a menos que se hayan recibido nuevos datos, por lo que el intervalo de tiempo real está limitado solo por $ZFTP_TIMEOUT.

Como se describe para progress, zfinit forzará que esto tenga el valor predeterminado de 1.

remote-glob
Si se establece en `1', `yes' o `true', la generación de nombres de archivo (globbing) se realiza en la máquina remota en lugar de por zsh; consulte más abajo.
titlebar
Si se establece en `1', `yes' o `true', zftp_chpwd pondrá el host remoto y el directorio remoto en la barra de título de emuladores de terminal como xterm o sun-cmd que lo permitan.

Como se describe para progress, zfinit forzará que esto tenga el valor predeterminado de 1.

chpwd
Si se establece en `1' `yes' o `true', zftp_chpwd llamará a la función chpwd cuando se cierre una conexión. Esto es útil si los detalles del host remoto fueron colocados en la barra de título del terminal por zftp_chpwd y tu chpwd habitual también modifica la barra de título.

Cuando se ejecuta zfinit, determinará si chpwd existe y, si es así, establecerá el valor predeterminado para el estilo en 1 si aún no existe ninguno.

Tenga en cuenta que también existe un array asociativo zfconfig que contiene los valores utilizados por el sistema de funciones. No debe modificarse ni sobrescribirse.

Globbing remoto

Los comandos para recuperar archivos suelen realizar la generación de nombres de archivo (globbing) en sus argumentos; esto se puede desactivar pasando la opción -G a cada uno de los comandos. MISCELLANEOUS FEATURES

Some miscellaneous features of the zsh FTP system include:

Globbing

Globbing is supported in the same way as in the shell. If the style remote-glob is not set (the default), then globbing is performed locally. This means that the server is asked for a list of all files in the current directory, and then the shell filters this list for matches. This may be slow if the current directory on the server contains a lot of files. Furthermore, since it is difficult to port the UNIX directory semantics, directory handling is problematic and it is recommended that globbing only be used within the current directory. The list of files in the current directory, if retrieved, will be cached, so that subsequent globs in the same directory without an intervening zfcd are much faster.

If the remote-glob style (see above) is set, globbing is instead performed on the remote host: the server is asked for a list of matching files. This is highly dependent on how the server is implemented, though typically UNIX servers will provide support for basic glob patterns. This may in some cases be faster, as it avoids retrieving the entire list of directory contents.

Reapertura automática y temporal

Como se describe para el comando zfopen, un posterior zfopen sin parámetros reabrirá la conexión al último host (esto incluye las conexiones realizadas con el comando zfanon). Abierta de esta manera, la conexión comienza en el directorio remoto predeterminado y permanecerá abierta hasta que se cierre explícitamente.

La reapertura automática también está disponible. Si actualmente no hay una conexión abierta y se da un comando que requiere una conexión, la última conexión se reabrirá implícitamente. En este caso, el directorio que era actual cuando se cerró la conexión volverá a ser el directorio actual (a menos que, por supuesto, el comando dado lo cambie). La reapertura automática también se producirá si la conexión fue cerrada por el servidor remoto por cualquier motivo (por ejemplo, un tiempo de espera). No está disponible si se utilizó la opción -1 para zfopen o zfanon.

Además, si el comando emitido es una transferencia de archivos, la conexión se cerrará después de que la transferencia haya finalizado, proporcionando así un modo de un solo uso para las transferencias. Esto no se aplica a los comandos de cambio o listado de directorios; por ejemplo, un zfdir puede reabrir una conexión pero la dejará abierta. Además, el cierre automático solo ocurrirá en el mismo comando que la apertura automática, es decir, un zfdir seguido directamente por un zfget nunca cerrará la conexión automáticamente.

La información sobre la conexión anterior se proporciona mediante la función zfstat. Por lo tanto, por ejemplo, si informa:

Sesión:        predeterminada
No conectado.
Última sesión:   ftp.bar.com:/pub/textfiles

entonces el comando zfget file.txt intentará reabrir una conexión a ftp.bar.com, recuperar el archivo /pub/textfiles/file.txt y cerrar la conexión inmediatamente. Por otro lado, zfcd .. abrirá la conexión en el directorio /pub y la dejará abierta.

Tenga en cuenta que todo lo anterior es local para cada sesión; si vuelve a una sesión anterior, la conexión para esa sesión es la que se reabrirá.

Completado

Se admite el completado de archivos, directorios, sesiones y marcadores locales y remotos. El completado de estilo antiguo, compctl, se define cuando se llama a zfinit; la compatibilidad con el nuevo sistema de completado basado en widgets se proporciona en la función Completion/Zsh/Command/_zftp, que debe instalarse con las demás funciones del sistema de completado y, por lo tanto, debería estar automáticamente disponible.
