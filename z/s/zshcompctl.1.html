ZSHCOMPCTL(1) Manual de Comandos Generales ZSHCOMPCTL(1)

NOMBRE

zshcompctl - completado programable de zsh

DESCRIPCIÓN

Esta versión de zsh tiene dos formas de completar palabras en la línea de comandos. Los nuevos usuarios del shell pueden preferir usar el sistema más nuevo y potente basado en funciones de shell; esto se describe en zshcompsys(1), y los mecanismos básicos del shell que lo soportan se describen en zshcompwid(1). Esta entrada del manual describe el comando más antiguo compctl.

compctl [ -CDT ] opciones [ comando ... ]
compctl [ -CDT ] opciones [ -x patrón opciones - ... -- ]
[ + opciones [ -x ... -- ] ... [+] ] [ comando ... ]
compctl -M especificaciones-de-coincidencia ...
compctl -L [ -CDTM ] [ comando ... ]
compctl + comando ...

Controla el comportamiento de completado del editor de acuerdo con el conjunto de opciones proporcionado. Varios comandos de edición, en particular expand-or-complete-word, normalmente enlazado a tab, intentarán completar una palabra escrita por el usuario, mientras que otros, en particular delete-char-or-list, normalmente enlazado a ^D en modo de edición EMACS, listan las posibilidades; compctl controla cuáles son esas posibilidades. Pueden ser, por ejemplo, nombres de archivo (el caso más común, y por lo tanto el predeterminado), variables de shell o palabras de una lista especificada por el usuario.

BANDERA DE COMANDO

El completado de los argumentos de un comando puede ser diferente para cada comando o puede usar el predeterminado. El comportamiento al completar la palabra del comando en sí también puede especificarse por separado. Estos corresponden a las siguientes banderas y argumentos, todos los cuales (excepto -L) pueden combinarse con cualquier combinación de las opciones descritas posteriormente en la sección `Option Flags':

comando ...
controla el completado para los comandos nombrados, que deben listarse al final de la línea de comandos. Si se intenta un completado para un comando con una ruta que contiene barras y no se encuentra ninguna definición de completado, la búsqueda se reintenta con el último componente de la ruta. Si el comando comienza con un =, se intenta el completado con la ruta del comando.

Cualquiera de las cadenas de comando pueden ser patrones del tipo normalmente usado para la generación de nombres de archivo. Estos deben estar entre comillas para protegerlos de la expansión inmediata; por ejemplo, la cadena de comando 'foo*' organiza el completado de las palabras de cualquier comando que comience con foo. Cuando se intenta un completado, todos los completados de patrones se intentan en el orden inverso a su definición hasta que uno coincida. Por defecto, el completado continúa normalmente, es decir, el shell intentará generar más coincidencias para el comando específico en la línea de comandos; esto puede ser anulado incluyendo -tn en las banderas para el completado de patrones.

Tenga en cuenta que los alias se expanden antes de que se determine el nombre del comando, a menos que se establezca la opción COMPLETE_ALIASES. Los comandos no pueden combinarse con las banderas -C, -D o -T.

-C
controla el completado cuando se está completando la palabra del comando en sí. Si no se ha emitido ningún comando compctl -C, se completan los nombres de cualquier comando ejecutable (ya sea en la ruta o específico del shell, como alias o funciones).
-D
controla el comportamiento de completado predeterminado para los argumentos de los comandos a los que no se les ha asignado ningún comportamiento especial. Si no se ha emitido ningún comando compctl -D, se completan los nombres de archivo.
-T
proporciona banderas de completado que se utilizarán antes de cualquier otro procesamiento, incluso antes de procesar los compctl definidos para comandos específicos. Esto es especialmente útil cuando se combina con el completado extendido (la bandera -x, ver la sección `Extended Completion' más abajo). Usando esta bandera puedes definir un comportamiento predeterminado que se aplicará a todos los comandos sin excepción, o puedes alterar el comportamiento estándar para todos los comandos. Por ejemplo, si tu acceso a la base de datos de usuarios es demasiado lento y/o contiene demasiados usuarios (por lo que el completado después de `~' es demasiado lento para ser utilizable), puedes usar
compctl -T -x 's[~] C[0,[^/]#]' -k friends -S/ -tn

para completar las cadenas en el array friends después de un `~'. El argumento C[...] es necesario para que esta forma de completado de ~ no se intente después de que el nombre del directorio se haya completado.

-L
lista el comportamiento de completado existente de una manera adecuada para colocarla en un script de inicio; el comportamiento existente no se cambia. Se puede especificar cualquier combinación de las formas anteriores, o la bandera -M (que debe seguir a la bandera -L), de lo contrario se listarán todos los completados definidos. Se ignoran las demás banderas proporcionadas.
sin argumento
Si no se proporciona ningún argumento, compctl lista todos los completados definidos en forma abreviada; con una lista de opciones, se listan todos los completados con esas banderas establecidas (sin contar el completado extendido).

Si la bandera + está sola y seguida inmediatamente por la lista de comandos, el comportamiento de completado para todos los comandos de la lista se restablece al predeterminado. En otras palabras, el completado utilizará posteriormente las opciones especificadas por la bandera -D.

La forma con -M como primera y única opción define especificaciones de coincidencia globales (ver zshcompwid). Las especificaciones de coincidencia proporcionadas se utilizarán para cada intento de completado (solo al usar compctl, no con el nuevo sistema de completado) y se intentan en el orden en que se definen hasta que una genera al menos una coincidencia. Por ejemplo:

compctl -M '' 'm:{a-zA-Z}={A-Za-z}'

Esto primero intentará el completado sin ninguna especificación de coincidencia global (la cadena vacía) y, si eso no genera coincidencias, intentará el completado insensible a mayúsculas y minúsculas.

BANDERA DE OPCIÓN

[ -fcFBdeaRGovNAIOPZEnbjrzu/12 ]
[ -k array ] [ -g cadena-glob ] [ -s cadena-sust ]
[ -K función ]
[ -Q ] [ -P prefijo ] [ -S sufijo ]
[ -W prefijo-archivo ] [ -H num patrón ]
[ -q ] [ -X explicación ] [ -Y explicación ]
[ -y func-o-var ] [ -l cmd ] [ -h cmd ] [ -U ]
[ -t continuar ] [ -J nombre ] [ -V nombre ]

Las opciones restantes especifican el tipo de argumentos de comando a buscar durante el completado. Se puede especificar cualquier combinación de estas banderas; el resultado es una lista ordenada de todas las posibilidades. Las opciones son las siguientes.

Bandera Sencilla

Estas producen listas de completado creadas por el propio shell:

-f
Nombres de archivo y rutas del sistema de archivos.
-/
Solo rutas del sistema de archivos.
-c
Nombres de comandos, incluyendo alias, funciones del shell, comandos internos y palabras reservadas.
-F
Nombres de funciones.
-B
Nombres de comandos internos.
-m
Nombres de comandos externos.
-w
Palabras reservadas.
-a
Nombres de alias.

Types of Names

-R
Nombres de alias regulares (no globales).
-G
Nombres de alias globales.
-d
Esto se puede combinar con -F, -B, -w, -a, -R y -G para obtener los nombres de funciones deshabilitadas, comandos internos, palabras reservadas o alias.
-e
Esta opción (para mostrar comandos habilitados) está activa por defecto, pero puede combinarse con -d; -de en combinación con -F, -B, -w, -a, -R y -G completará nombres de funciones, comandos internos, palabras reservadas o alias, independientemente de si están deshabilitados o no.
-o
Nombres de opciones del shell (ver zshoptions(1)).
-v
Nombres de cualquier variable definida en el shell.
-N
Nombres de parámetros escalares (no de arreglos).
-A
Nombres de arreglos.
-I
Nombres de variables enteras.
-O
Nombres de variables de solo lectura.
-p
Nombres de parámetros utilizados por el shell (incluyendo parámetros especiales).
-Z
Nombres de parámetros especiales del shell.
-E
Nombres de variables de entorno.
-n
Directorios nombrados.
-b
Nombres de enlaces de teclas.
-j
Nombres de trabajos: la primera palabra de la línea de comandos del líder del trabajo. Esto es útil con el comando interno kill.
-r
Nombres de trabajos en ejecución.
-z
Nombres de trabajos suspendidos.
-u
Nombres de usuarios.

Flags con Argumentos

Estos tienen argumentos proporcionados por el usuario para determinar cómo se construye la lista de completados:

-k arreglo
Nombres tomados de los elementos de $arreglo (tenga en cuenta que el `$' no aparece en la línea de comandos). Alternativamente, el argumento arreglo en sí mismo puede ser un conjunto de valores separados por espacios o comas entre paréntesis, en cuyo caso cualquier delimitador puede ser escapado con una barra invertida; en este caso, el argumento debe ser citado. Por ejemplo,
compctl -k "(cputime filesize datasize stacksize
	       coredumpsize resident descriptors)" limit
-g cadena_glob
La cadena_glob se expande utilizando globbing de nombres de archivos; debe ser citada para protegerla de la expansión inmediata. Los nombres de archivos resultantes se toman como posibles completados. Use `*(/)' en lugar de `*/' para directorios. El parámetro especial fignore no se aplica a los archivos resultantes. Se pueden dar varios patrones separados por espacios. (Tenga en cuenta que la expansión de llaves *no* forma parte del globbing. Use la sintaxis `(uno|otro)' para coincidir con alternativas.)
-s cadena_sust
La cadena_sust se divide en palabras y estas palabras luego se expanden utilizando todos los mecanismos de expansión del shell (ver zshexpn(1)). Las palabras resultantes se toman como posibles completados. El parámetro especial fignore no se aplica a los archivos resultantes. Tenga en cuenta que -g es más rápido para nombres de archivos.
-K funcion
Llama a la función dada para obtener los completados. A menos que el nombre comience con un guion bajo, la función recibe dos argumentos: el prefijo y el sufijo de la palabra sobre la que se debe intentar la completación, en otras palabras, aquellos caracteres antes de la posición del cursor, y aquellos desde la posición del cursor en adelante. La línea de comandos completa se puede acceder con las banderas -c y -l del comando interno read. La función debe establecer la variable reply a un arreglo que contenga los completados (un completado por elemento); tenga en cuenta que reply no debe ser local a la función. Desde una función así, la línea de comandos se puede acceder con las banderas -c y -l para el comando interno read. Por ejemplo,
function whoson { reply=(`users`); }
compctl -K whoson talk

completa solo usuarios conectados después de `talk'. Tenga en cuenta que `whoson' debe devolver un arreglo, por lo que `reply=`users`' sería incorrecto.

-H num patrón
Los posibles completados se toman de las últimas num líneas del historial. Solo se toman las palabras que coinciden con patrón. Si num es cero o negativo, se busca en todo el historial y si patrón es una cadena vacía, se toman todas las palabras (como con `*'). Un uso típico es
compctl -D -f + -H 0 ''

lo que obliga a la completación a buscar en la lista de historial una palabra si no se encuentra ninguna coincidencia de archivo.

Flags de Control

Estos no especifican directamente tipos de nombres a completar, sino que manipulan las opciones que lo hacen:

-Q
Esto instruye al shell a no citar ningún metacaracter en los posibles completados. Normalmente, los resultados de una completación se insertan en la línea de comandos con los metacaracteres citados para que se interpreten como caracteres normales. Esto es apropiado para nombres de archivos y cadenas ordinarias. Sin embargo, para efectos especiales, como insertar una expresión entre comillas invertidas de un arreglo de completados (-k) para que la expresión no se evalúe hasta que se ejecute la línea completa, debe usarse esta opción.
-P prefijo
El prefijo se inserta justo antes de la cadena completada; cualquier parte inicial ya escrita se completará y todo el prefijo se ignorará a efectos de completado. Por ejemplo,
compctl -j -P "%" kill

inserta un `%' después del comando kill y luego completa nombres de trabajos.

-S sufijo
Cuando se encuentra una completación, el sufijo se inserta después de la cadena completada. En el caso de completado por menú, el sufijo se inserta inmediatamente, pero aún es posible recorrer la lista de completados presionando repetidamente la misma tecla.
-W prefijo-archivo
Con el prefijo-archivo del directorio: para la completación de comandos, archivos, directorios y globbing (opciones -c, -f, -/, -g), el prefijo del archivo se añade implícitamente delante del completado. Por ejemplo,
compctl -/ -W ~/Mail maildirs

completa cualquier subdirectorio a cualquier profundidad debajo del directorio ~/Mail, aunque ese prefijo no aparezca en la línea de comandos. El prefijo-archivo también puede ser del tipo aceptado por la bandera -k, es decir, el nombre de un arreglo o una lista literal entre paréntesis. En este caso, se buscarán todos los directorios de la lista en busca de posibles completados.

-q
Si se usa con un sufijo como el especificado por la opción -S, esto provoca que el sufijo se elimine si el siguiente carácter escrito es un espacio en blanco o no inserta nada, o si el sufijo consta de un solo carácter y el siguiente carácter escrito es el mismo; esta es la misma regla que se utiliza para la opción AUTO_REMOVE_SLASH. La opción es más útil para separadores de listas (coma, dos puntos, etc.).
-l cmd
Esta opción restringe el rango de palabras de la línea de comandos que se consideran argumentos. Si se combina con uno de los patrones de completado extendido `p[...]', `r[...]', o `R[...]' (ver la sección `Completado Extendido' más abajo) el rango se restringe al rango de argumentos especificado entre corchetes. La completación se realiza entonces como si estos se hubieran proporcionado como argumentos al cmd proporcionado con la opción. Si la cadena cmd está vacía, la primera palabra del rango se toma en su lugar como nombre de comando, y se realiza la completación de nombres de comando en la primera palabra del rango. Por ejemplo,
compctl -x 'r[-exec,;]' -l '' -- find

completa argumentos entre `-exec' y el siguiente `;` (o el final de la línea de comandos si no hay tal cadena) como si fueran una línea de comandos separada.

-h cmd
Normalmente zsh completa las cadenas entre comillas como un todo. Con esta opción, la completación se puede realizar por separado en diferentes partes de dichas cadenas. Funciona como la opción -l pero hace que el código de completado trabaje en las partes de la palabra actual separadas por espacios. Estas partes se completan como si fueran argumentos del cmd dado. Si cmd es la cadena vacía, la primera parte se completa como un nombre de comando, como con -l.
-U
Utiliza toda la lista de posibles completados, independientemente de si coinciden o no con la palabra en la línea de comandos. La palabra escrita hasta ahora se eliminará. Esto es más útil con una función (dada por la opción -K) que puede examinar los componentes de la palabra que se le pasan (o a través de las banderas -c y -l del comando interno read) y usar sus propios criterios para decidir qué coincide. Si no hay completado, se conserva la palabra original. Dado que los posibles completados producidos rara vez tienen prefijos y sufijos comunes interesantes, el completado por menú se inicia inmediatamente si AUTO_MENU está configurado y se utiliza esta bandera.
-y func-o-var

N[índice,cadena]...

Similar a n, excepto que la cadena se tomará como una clase de caracteres. Todo hasta e incluyendo la índice-ésima ocurrencia de cualquiera de los caracteres en cadena no se considerará parte de la compleción.

m[min,max]...

Coincide si el número total de palabras está entre min y max inclusive.

r[str1,str2]...

Coincide si el cursor está después de una palabra con prefijo str1. Si también hay una palabra con prefijo str2 en la línea de comandos después de la que coincide con str1, solo coincide si el cursor está antes de esta palabra. Si la coma y str2 se omiten, coincide si el cursor está después de una palabra con prefijo str1.

R[str1,str2]...

Similar a r, pero usando coincidencia de patrones en su lugar.

q[cadena]...

Coincide si la palabra que se está completando actualmente está entre comillas simples y la cadena comienza con la letra `s', o si la compleción se realiza entre comillas dobles y la cadena comienza con la letra `d', o si la compleción se realiza entre comillas invertidas y la cadena comienza con `b'.

EJEMPLO

compctl -u -x 's[+] c[-1,-f],s[-f+]' \
  -g '~/Mail/*(:t)' - 's[-f],c[-1,-f]' -f -- mail

Si el comando actual es mail, entonces

si (la palabra actual comienza con + y la palabra anterior es -f)
o (la palabra actual comienza con -f+), entonces completa la
parte no directorio (el modificador de patrón `:t') de los archivos en el
directorio
~/Mail; de lo contrario,
si la palabra actual comienza con -f o la palabra anterior fue -f, entonces
completa cualquier archivo; de lo contrario,
completa nombres de usuario.
