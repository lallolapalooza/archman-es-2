NOMBRE

zshtcpsys - sistema tcp de zsh

DESCRIPCIÓN

Se proporciona un módulo zsh/net/tcp para proporcionar E/S de red a través de TCP/IP desde el shell; consulte su descripción en zshmodules(1). Esta página del manual describe un conjunto de funciones basadas en el módulo. Si el módulo está instalado, las funciones suelen instalarse al mismo tiempo, en cuyo caso estarán disponibles para carga automática en la ruta de búsqueda de funciones predeterminada. Además del módulo zsh/net/tcp, se utiliza el módulo zsh/zselect para implementar tiempos de espera en las operaciones de lectura. Para obtener consejos sobre solución de problemas, consulte los consejos correspondientes para las funciones zftp descritas en zshzftpsys(1).

Existen funciones que corresponden a las operaciones básicas de E/S: abrir, cerrar, leer y enviar, denominadas tcp_open, etc., así como una función tcp_expect para el análisis de coincidencias de patrones de los datos leídos como entrada. El sistema facilita la recepción y el envío de datos desde y hacia múltiples sesiones con nombre a la vez. Además, puede enlazarse con el editor de línea del shell de tal manera que los datos de entrada se muestren automáticamente en el terminal. Otras facilidades disponibles incluyen registro, filtrado y avisos de salida configurables.

Para utilizar el sistema donde esté disponible, debería ser suficiente con `autoload -U tcp_open' y ejecutar tcp_open como se documenta a continuación para iniciar una sesión. La función tcp_open cargará automáticamente las funciones restantes.

FUNCIONES DE USUARIO TCP

E/S Básica

tcp_open [ -qz ] host puerto [ sess ]
tcp_open [ -qz ] [ -s sess | -l sess[,...] ] ...
tcp_open [ -qz ] [ -a fd | -f fd ] [ sess ]
Abre una nueva sesión. En la primera y más simple forma, abre una conexión TCP al host host en el puerto puerto; se entienden tanto las formas numéricas como las simbólicas para ambos.

Si se proporciona sess, este se convierte en el nombre de la sesión que se puede utilizar para referirse a múltiples conexiones TCP diferentes. Si no se proporciona sess, la función inventará un valor de nombre numérico (tenga en cuenta que esto *no* es lo mismo que el descriptor de archivo al que está adjunta la sesión). Se recomienda que los nombres de sesión no incluyan caracteres "graciosos", donde los caracteres graciosos no están bien definidos pero ciertamente no incluyen alfanuméricos ni guiones bajos, y ciertamente incluyen espacios en blanco.

En el segundo caso, se proporcionan una o más sesiones a abrir por nombre. Se proporciona un solo nombre de sesión después de -s y una lista separada por comas después de -l; ambas opciones pueden repetirse tantas veces como sea necesario. Un fallo al abrir cualquier sesión hace que tcp_open se interrumpa. El host y el puerto se leen del archivo .ztcp_sessions en el mismo directorio que los archivos de inicialización de zsh del usuario, es decir, normalmente el directorio principal, pero $ZDOTDIR si está configurado. El archivo consta de líneas que proporcionan cada una un nombre de sesión y el host y puerto correspondientes, en ese orden (tenga en cuenta que el nombre de la sesión va primero, no último), separados por espacios en blanco.

La tercera forma permite conexiones TCP pasivas y falsas. Si se utiliza la opción -a, su argumento es un descriptor de archivo abierto para escuchar conexiones. No se proporciona ninguna interfaz de función para abrir dicho descriptor de archivo, pero una llamada a `ztcp -l puerto' creará uno con el descriptor de archivo almacenado en el parámetro $REPLY. El puerto de escucha se puede cerrar con `ztcp -c fd'. Una llamada a `tcp_open -a fd' se bloqueará hasta que se establezca una conexión TCP remota a puerto en la máquina local. En este punto, se crea una sesión de la manera habitual y es prácticamente indistinguible de una conexión activa creada con una de las dos primeras formas.

Si se utiliza la opción -f, su argumento es un descriptor de archivo que se utiliza directamente como si fuera una sesión TCP. El grado en que el resto del sistema de funciones TCP se las arregla con esto depende de lo que realmente subyace a este descriptor de archivo. Es probable que un archivo regular sea inútil; una FIFO (tubería) de algún tipo funcionará mejor, pero tenga en cuenta que no es una buena idea que dos sesiones diferentes intenten leer de la misma FIFO a la vez.

Si se proporciona la opción -q con cualquiera de las tres formas, tcp_open no imprimirá mensajes informativos, aunque en cualquier caso saldrá con un estado apropiado.

Si se utiliza el editor de línea (zle), lo que suele ser el caso si el shell es interactivo, tcp_open instala un manejador dentro de zle que comprobará si hay nuevos datos al mismo tiempo que comprueba la entrada del teclado. Esto es conveniente ya que el shell no consume tiempo de CPU mientras espera; la prueba la realiza el sistema operativo. Proporcionar la opción -z a cualquiera de las formas de tcp_open evita que se instale el manejador, por lo que los datos deben leerse explícitamente. Sin embargo, tenga en cuenta que esto no es necesario para ejecutar conjuntos completos de comandos de envío y lectura desde una función, ya que zle no está activo en ese momento. En general, el manejador solo está activo cuando el shell está esperando entrada en un prompt de comando o en la utilidad incorporada vared. La opción no tiene efecto si zle no está activo; `[[ -o zle]]' probará esto.

La primera sesión que se abre se convierte en la sesión actual y las llamadas posteriores a tcp_open no la cambian. La sesión actual se almacena en el parámetro $TCP_SESS; consulte a continuación para obtener más detalles sobre los parámetros utilizados por el sistema.

La función tcp_on_open, si está definida, se llama cuando se abre una sesión. Consulte la descripción a continuación.

tcp_close [ -qn ] [ -a | -l sess[,...] | sess ... ]
Cierra las sesiones con nombre, o la sesión actual si no se proporciona ninguna, o todas las sesiones abiertas si se proporciona -a. Las opciones -l y -s se manejan ambas para consistencia con tcp_open, aunque esta última es redundante.

Si la sesión que se cierra es la actual, $TCP_SESS se elimina, sin dejar ninguna sesión actual, incluso si todavía hay otras sesiones abiertas.

Si la sesión se abrió con tcp_open -f, el descriptor de archivo se cierra siempre que esté en el rango de 0 a 9 accesible directamente desde la línea de comandos. Si se proporciona la opción -n, no se intentará cerrar descriptores de archivo en este caso. La opción -n no se utiliza para sesiones ztcp genuinas; los descriptores de archivo siempre se cierran con la sesión.

Si se proporciona la opción -q, no se imprimirán mensajes informativos.

tcp_read [ -bdq ] [ -t TO ] [ -T TO ]
[ -a | -u fd[,...] | -l sess[,...] | -s sess ... ]
Realiza una operación de lectura en la sesión actual, o en una lista de sesiones si se proporcionan con -u, -l o -s, o en todas las sesiones abiertas si se proporciona la opción -a. Cualquiera de las opciones -u, -l o -s pueden repetirse o mezclarse. La opción -u especifica un descriptor de archivo directamente (solo los administrados por este sistema son útiles), las otras dos especifican sesiones como se describe para tcp_open anteriormente.

La función comprueba si hay nuevos datos disponibles en todas las sesiones especificadas. A menos que se proporcione la opción -b, no se bloqueará esperando nuevos datos. Se leerá cualquier línea de datos de cualquiera de las sesiones disponibles, se almacenará en el parámetro $TCP_LINE y se mostrará en la salida estándar a menos que $TCP_SILENT contenga una cadena no vacía. Al imprimirse en la salida estándar, la cadena $TCP_PROMPT se mostrará al principio de la línea; la forma predeterminada para esto incluye el nombre de la sesión que se está leyendo. Consulte a continuación para obtener más información sobre estos parámetros. En este modo, tcp_read se puede llamar repetidamente hasta que devuelva el estado 2, lo que indica que toda la entrada pendiente de todas las sesiones especificadas ha sido manejada.

Con la opción -b, equivalente a un tiempo de espera infinito, la función se bloqueará hasta que haya una línea disponible para leer de una de las sesiones especificadas. Sin embargo, solo se devuelve una línea.

La opción -d indica que se debe agotar toda la entrada pendiente. En este caso, tcp_read puede procesar varias líneas de la manera indicada anteriormente; solo la última se almacena en $TCP_LINE, pero el conjunto completo

se almacena en el array $tcp_lines. Esto se borra al inicio de cada llamada a tcp_read.

Las opciones -t y -T especifican un tiempo de espera en segundos, que puede ser un número de punto flotante para mayor precisión. Con -t el tiempo de espera se aplica antes de leer cada línea. Con -T, el tiempo de espera se aplica a la operación general, posiblemente incluyendo múltiples operaciones de lectura si está presente la opción -d; sin esta opción, no hay distinción entre -t y -T.

La función no imprime mensajes informativos, pero si se proporciona la opción -q, no se imprime ningún mensaje de error para una sesión inexistente.

Un estado de retorno de 2 indica un tiempo de espera agotado o que no hay datos para leer. Cualquier otro estado de retorno distinto de cero indica alguna condición de error.

Consulte tcp_log para saber cómo controlar a dónde se envían los datos por tcp_read.

tcp_send [ -cnq ] [ -s sess | -l sess[,...] ] data ...
tcp_send [ -cnq ] -a data ...
Envía las cadenas de datos proporcionadas a todas las sesiones especificadas por turnos. La operación subyacente difiere poco de un `print -r' al descriptor de archivo de la sesión, aunque intenta evitar que el shell muera debido a una SIGPIPE causada por un intento de escribir en una sesión inactiva.

La opción -c hace que tcp_send se comporte como cat. Lee líneas de la entrada estándar hasta el final de la entrada y las envía por turnos a la(s) sesión(es) especificada(s) exactamente como si se hubieran proporcionado como argumentos de data a comandos individuales de tcp_send.

La opción -n evita que tcp_send ponga una nueva línea al final de las cadenas de datos.

Las opciones restantes se comportan como en tcp_read.

Los argumentos de datos no se procesan más una vez que se han pasado a tcp_send; simplemente se pasan a print -r.

Si el parámetro $TCP_OUTPUT es una cadena no vacía y el registro está habilitado, los datos enviados a cada sesión se reflejarán en los archivos de registro con $TCP_OUTPUT delante, donde sea apropiado, de manera similar a $TCP_PROMPT.

Gestión de sesiones

tcp_alias [ -q ] alias=sess ...
tcp_alias [ -q ] [ alias ... ]
tcp_alias -d [ -q ] alias ...
Esta función no está particularmente bien probada.

La primera forma crea un alias para un nombre de sesión; alias puede ser utilizado para referirse a la sesión existente sess. Se pueden listar tantos alias como se necesite.

La segunda forma lista los alias especificados, o todos los alias si no se especifica ninguno.

La tercera forma elimina todos los alias listados. Las sesiones subyacentes no se ven afectadas.

La opción -q suprime un subconjunto inconsistente de mensajes de error.

tcp_log [ -asc ] [ -n | -N ] [ logfile ]
Con un argumento logfile, toda la entrada futura de tcp_read se registrará en el archivo con el nombre especificado. A menos que se proporcione -a (añadir), este archivo se truncará primero o se creará vacío. Sin argumentos, muestra el estado actual del registro.

Con la opción -s, se habilita el registro por sesión. La entrada de tcp_read se envía al archivo logfile.sess. Dado que la sesión se discrimina automáticamente por el nombre del archivo, el contenido es bruto (sin $TCP_PROMPT). La opción -a se aplica como se indica anteriormente. El registro por sesión y el registro de todos los datos en un solo archivo no son mutuamente excluyentes.

La opción -c cierra todo el registro, tanto los registros completos como los por sesión.

Las opciones -n y -N respectivamente desactivan o restauran la salida de los datos leídos por tcp_read a la salida estándar; por lo tanto, `tcp_log -cn' desactiva toda la salida de tcp_read.

La función es puramente un frontend conveniente para establecer los parámetros $TCP_LOG, $TCP_LOG_SESS, $TCP_SILENT, que se describen a continuación.

tcp_rename old new
Renombra la sesión old a la sesión new. El nombre antiguo queda invalidado.
tcp_sess [ sess [ command [ arg ... ] ] ]
Sin argumentos, lista todas las sesiones abiertas y sus descriptores de archivo asociados. La sesión actual se marca con un asterisco. Para su uso en funciones, el acceso directo a los parámetros $tcp_by_name, $tcp_by_fd y $TCP_SESS es probablemente más conveniente; véase más abajo.

Con un argumento sess, establece la sesión actual a sess. Esto es equivalente a cambiar directamente $TCP_SESS.

Con argumentos adicionales, establece temporalmente la sesión actual mientras se ejecuta `command arg ...'. command se reevalúa para expandir alias, etc., pero los arg restantes se pasan tal como aparecen a tcp_sess. La sesión original se restaura cuando tcp_sess sale.

E/S Avanzada

tcp_command send-option ... send-argument ...
Este es un frontend conveniente para tcp_send. Todos los argumentos se pasan a tcp_send, luego la función se detiene esperando datos. Mientras llegan datos al menos cada $TCP_TIMEOUT (predeterminado 0.3) segundos, los datos se manejan y se imprimen según la configuración actual. Siempre se devuelve el estado 0.

Esto generalmente solo es útil para uso interactivo, para evitar que la pantalla se fragmente con la salida devuelta de la conexión. Dentro de un programa o función, generalmente es mejor manejar la lectura de datos de una manera más explícita.

tcp_expect [ -q ] [ -p var | -P var ] [ -t TO | -T TO ]
[ -a | -s sess | -l sess[,...] ] pattern ...
Espera entrada que coincida con cualquiera de los patterns dados de cualquiera de las sesiones especificadas. La entrada se ignora hasta que una línea de entrada coincide con uno de los patrones dados; en ese momento se devuelve el estado cero, la línea coincidente se almacena en $TCP_LINE, y el conjunto completo de líneas leídas durante la llamada a tcp_expect se almacena en el array $tcp_expect_lines.

Las sesiones se especifican de la misma manera que en tcp_read: por defecto se utiliza la sesión actual, de lo contrario se utilizan las sesiones especificadas por -a, -s o -l.

Cada pattern es un patrón de globbing extendido estándar de zsh; tenga en cuenta que debe estar entre comillas para evitar que sea expandido inmediatamente por la generación de nombres de archivo. Debe coincidir con la línea completa, por lo que para coincidir con una subcadena debe haber un `*' al principio y al final. La línea que se compara incluye el $TCP_PROMPT añadido por tcp_read. Es posible incluir los indicadores de globbing `#b' o `#m' en los patrones para hacer que las referencias inversas estén disponibles en los parámetros $MATCH, $match, etc., como se describe en la documentación base de zsh sobre coincidencia de patrones.

A diferencia de tcp_read, el comportamiento predeterminado de tcp_expect es bloquear indefinidamente hasta que se encuentre la entrada requerida. Esto se puede modificar especificando un tiempo de espera con -t o -T; estos funcionan como en tcp_read, especificando un tiempo de espera por lectura o total, respectivamente, en segundos, como un número entero o de punto flotante. Al igual que tcp_read, la función devuelve el estado 2 si se produce un tiempo de espera agotado.

La función devuelve tan pronto como coincida cualquiera de los patrones dados. Si el llamador necesita saber cuál de los patrones coincidió, se puede usar la opción -p var; al regresar, $var se establece en el número del patrón usando indexación ordinaria de zsh, es decir, el primero es 1, y así sucesivamente. Tenga en cuenta la ausencia de un `$' delante de var. Para evitar conflictos, el parámetro no puede comenzar con `_expect'. El índice -1 se usa si hay un tiempo de espera agotado y 0 si no hay coincidencia.

La opción -P var funciona de manera similar a -p, pero en lugar de índices numéricos, los argumentos regulares deben comenzar con un prefijo seguido de dos puntos: ese prefijo se usa luego como una etiqueta a la que se establece var cuando el argumento coincide. La etiqueta timeout se usa si hay un tiempo de espera agotado y la cadena vacía si no hay coincidencia. Tenga en cuenta que es aceptable que diferentes argumentos comiencen con el mismo prefijo si las coincidencias no necesitan ser distinguidas.

La opción -q se pasa directamente a tcp_read.

Dado que toda la entrada se realiza a través de tcp_read, se aplican todas las reglas habituales sobre la salida de las líneas leídas. Una excepción es que el parámetro $tcp_lines solo reflejará la línea efectivamente coincidente por tcp_expect; use $tcp_expect_lines para el conjunto completo de líneas leídas durante la llamada a la función.

tcp_proxy
Esta es una función simple para aceptar una conexión TCP y ejecutar un comando con E/S redirigida a la conexión. Se debe tener extrema precaución ya que no hay seguridad alguna y esto puede dejar su computadora expuesta al mundo. Idealmente, solo debe usarse detrás de un firewall.

El primer argumento es un puerto TCP en el que la función escuchará.

Los argumentos restantes especifican un comando y sus argumentos para ejecutar con la entrada estándar, la salida estándar y el error estándar redirigidos al descriptor de archivo en el que se ha aceptado la sesión TCP. Si no se proporciona ningún comando, se inicia un nuevo zsh. Esto da a todos en su red acceso directo a su cuenta, lo que en muchos casos será algo malo.

El comando se ejecuta en segundo plano, por lo que tcp_proxy puede aceptar nuevas conexiones. Continúa aceptando nuevas conexiones hasta que se interrumpe.

tcp_spam [ -ertv ] [ -a | -s sess | -l sess[,...] ] cmd [ arg ... ]
Ejecuta `cmd [ arg ... ]' para cada sesión por turnos. Tenga en cuenta que esto ejecuta el comando y los argumentos; no envía la línea de comandos como datos a menos que se especifique la opción -t (transmitir
) se proporciona una opción.

Las sesiones pueden seleccionarse explícitamente con las opciones estándar -a, -s o -l, o pueden elegirse implícitamente. Si no se proporciona ninguna de las tres opciones, las reglas son: primero, si el array $tcp_spam_list está configurado, se toma como la lista de sesiones; de lo contrario, se toman todas las sesiones. Segundo, cualquier sesión dada en el array $tcp_no_spam_list se elimina de la lista de sesiones.

Normalmente, cualquier sesión añadida por el indicador `-a' o cuando todas las sesiones se eligen implícitamente se envían en orden alfabético; las sesiones dadas por el array $tcp_spam_list o en la línea de comandos se envían en el orden dado. El indicador -r invierte el orden, sin importar cómo se haya llegado a él.

El indicador -v especifica que se mostrará un $TCP_PROMPT antes de cada sesión. Esto se muestra después de cualquier modificación de TCP_SESS por la función definida por el usuario tcp_on_spam descrita a continuación. (Obviamente, esa función es capaz de generar su propia salida).

Si la opción -e está presente, la línea dada como `cmd [ arg ... ]' se ejecuta usando eval, de lo contrario se ejecuta sin ningún procesamiento adicional.

tcp_talk
Este es un intento bastante simple de forzar que la entrada del editor de línea vaya directamente a TCP_SESS por defecto.

Se utiliza una cadena de escape, $TCP_TALK_ESCAPE, por defecto `:', para permitir el acceso a la operación normal del shell. Si está sola al principio de la línea, o seguida solo por espacios en blanco, el editor de línea vuelve a la operación normal. De lo contrario, la cadena y cualquier espacio en blanco siguiente se omiten y el resto de la línea se ejecuta como entrada del shell sin ningún cambio en el modo de operación del editor de línea.

La implementación actual es algo deficiente en cuanto al uso del historial de comandos. Por esta razón, muchos usuarios preferirán usar alguna forma de enfoque alternativo para enviar datos fácilmente a la sesión actual. Un enfoque simple es aliasar algún carácter especial (como `%') a `tcp_command --'.

tcp_wait
El único argumento es un número entero o de punto flotante que indica los segundos de retraso. El shell no hará nada durante ese período, excepto esperar entrada en todas las sesiones TCP llamando a tcp_read -a. Esto es similar al comportamiento interactivo en el prompt de la línea de comandos cuando se instalan manejadores de zle.

Transferencia de archivos `de un solo uso'

tcp_point port
tcp_shoot host port
Este par de funciones proporciona una forma sencilla de transferir un archivo entre dos hosts dentro del shell. Tenga en cuenta, sin embargo, que la transferencia de datos masivos se realiza actualmente utilizando cat. tcp_point lee cualquier dato que llegue al port y lo envía a la salida estándar; tcp_shoot se conecta al port en host y envía su entrada estándar. Se puede usar cualquier port no utilizado; el mecanismo estándar para elegir un puerto es pensar en un número aleatorio de cuatro dígitos por encima de 1024 hasta que uno funcione.

Para transferir un archivo del host woodcock al host springes, en springes:

tcp_point 8091 >output_file

y en woodcock:

tcp_shoot springes 8091 <input_file

Dado que estas dos funciones no requieren tcp_open para establecer una conexión TCP primero, es posible que necesiten ser cargadas automáticamente por separado.

Funciones definidas por el usuario de TCP

Ciertas funciones, si son definidas por el usuario, serán llamadas por el sistema de funciones en ciertos contextos. Esta facilidad depende del módulo zsh/parameter, que generalmente está disponible en los shells interactivos ya que el sistema de completado depende de él. Ninguna de las funciones necesita ser definida; simplemente proporcionan puntos de enganche convenientes cuando es necesario.

Típicamente, estas se llaman después de que se ha realizado la acción solicitada, por lo que los diversos parámetros reflejarán el nuevo estado.

tcp_on_alias alias fd
Cuando se define un alias, esta función se llamará con dos argumentos: el nombre del alias y el descriptor de archivo de la sesión correspondiente.
tcp_on_awol sess fd
Si la función tcp_fd_handler está manejando la entrada del editor de línea y detecta que el descriptor de archivo ya no es reutilizable, por defecto lo elimina de la lista de descriptores de archivo manejados por este método e imprime un mensaje. Si la función tcp_on_awol está definida, se llama inmediatamente antes de este punto. Puede devolver el estado 100, lo que indica que el manejo normal aún debe realizarse; cualquier otro estado de retorno indica que no se debe tomar ninguna acción adicional y el tcp_fd_handler debe regresar inmediatamente con el estado dado. Típicamente, la acción de tcp_on_awol será cerrar la sesión.

La variable TCP_INVALIDATE_ZLE será una cadena no vacía si es necesario invalidar la pantalla del editor de línea usando `zle -I' antes de imprimir la salida de la función.

(`AWOL' es jerga militar para `ausente sin permiso' o alguna variación. No tiene un significado técnico preexistente conocido por el autor.)

tcp_on_close sess fd
Se llama con el nombre de una sesión que se está cerrando y el descriptor de archivo que correspondía a esa sesión. Ambos serán inválidos cuando se llame a la función.
tcp_on_open sess fd
Se llama después de que se ha definido una nueva sesión con el nombre de la sesión y el descriptor de archivo como argumentos. Si devuelve un estado distinto de cero, se asume que la apertura de la sesión falla y la sesión se cierra nuevamente; sin embargo, tcp_open continuará intentando abrir cualquier sesión restante dada en la línea de comandos.
tcp_on_rename oldsess fd newsess
Se llama después de que una sesión ha sido renombrada con los tres argumentos: nombre antiguo de la sesión, descriptor de archivo, nombre nuevo de la sesión.
tcp_on_spam sess command ...
Se llama una vez por cada sesión enviada, justo *antes* de que se ejecute un comando para una sesión por tcp_spam. Los argumentos son el nombre de la sesión seguido de la lista de comandos a ejecutar. Si se llamó a tcp_spam con la opción -t, el primer comando será tcp_send.

Esta función se llama después de que $TCP_SESS se establece para reflejar la sesión que se va a enviar, pero antes de que se haga uso de ella. Por lo tanto, es posible modificar el valor de $TCP_SESS dentro de esta función. Por ejemplo, los argumentos de sesión para tcp_spam podrían incluir información adicional para ser eliminada y procesada en tcp_on_spam.

Si la función establece el parámetro $REPLY a `done', la línea de comandos no se ejecuta; además, no se imprime ningún prompt para la opción -v de tcp_spam.

tcp_on_unalias alias fd
Se llama con el nombre de un alias y el descriptor de archivo de la sesión correspondiente después de que se ha eliminado un alias.

Funciones utilitarias de TCP

Las siguientes funciones son utilizadas por el sistema de funciones TCP pero rara vez, o nunca, necesitarán ser llamadas directamente.

tcp_fd_handler
Esta es la función instalada por tcp_open para manejar la entrada desde el editor de línea, si eso es necesario. Tiene el formato documentado para el comando incorporado `zle -F' en zshzle(1) .

Mientras está activa, la función establece el parámetro TCP_HANDLER_ACTIVE a 1. Esto permite que el código del shell llamado internamente (por ejemplo, al configurar tcp_on_read) sepa si se está llamando cuando el shell está de lo contrario inactivo en el prompt del editor.

tcp_output [ -q ] -P prompt -F fd -S sess
Esta función se utiliza tanto para registrar como para manejar la salida a la salida estándar, desde dentro de tcp_read y (si se establece $TCP_OUTPUT) tcp_send.

El prompt a usar se especifica con -P; por defecto es la cadena vacía. Puede contener:

%c
Se expande a 1 si la sesión es la sesión actual, de lo contrario a 0. Se usa con expresiones ternarias como `%(c.-.+)' para mostrar `+' para la sesión actual y `-' de lo contrario.
%f
Reemplazado por el descriptor de archivo de la sesión.
%s
Reemplazado por el nombre de la sesión.
%%
Reemplazado por un solo `%'.

La opción -q suprime la salida a la salida estándar, pero no a los archivos de registro que estén configurados.

Las opciones -S y -F se utilizan para pasar el nombre de la sesión y el descriptor de archivo para su posible reemplazo en el prompt.

Parámetros de usuario de TCP

Los parámetros siguen la convención habitual de que se utilizan mayúsculas para escalares y enteros, mientras que las minúsculas se utilizan para arrays normales y asociativos. Siempre es seguro para el código del usuario leer estos parámetros. Algunos parámetros también pueden ser establecidos; estos se anotan explícitamente. Otros se incluyen en este grupo ya que son establecidos por el sistema de funciones para beneficio del usuario, es decir, establecerlos normalmente no es útil pero es benigno.

A menudo también es útil hacer que los parámetros configurables sean locales a una función. Por ejemplo, `local TCP_SILENT=1' especifica que los datos leídos durante la llamada a la función no se imprimirán en la salida estándar, independientemente de la configuración exterior. NAME

zshtcpsys - A Zsh module for TCP networking.

DESCRIPTION

This module provides a set of functions and parameters for handling TCP networking within Zsh. It allows you to create TCP clients and servers, send and receive data, and manage network connections.

TCP USER FUNCTIONS

This section describes the functions that are available for general use by the user.

  • tcp_connect host port: Connects to a TCP server at the specified host and port.
  • tcp_listen port: Starts a TCP server listening on the specified port.
  • tcp_accept: Accepts an incoming connection on a listening socket.
  • tcp_send data: Sends data over the active TCP connection.
  • tcp_recv size: Receives up to size bytes of data from the TCP connection.
  • tcp_close: Closes the active TCP connection.

TCP USER-DEFINED FUNCTIONS

This section describes how to define your own functions to extend the functionality of the TCP module.

You can define your own functions to handle specific events or actions related to TCP networking. For example, you could define a function to process incoming data or to handle connection errors.

TCP UTILITY FUNCTIONS

This section describes utility functions provided by the module that may be helpful for advanced usage.

  • tcp_set_timeout seconds: Sets a timeout for read/write operations.
  • tcp_get_last_error: Returns the last error message from a TCP operation.

TCP USER PARAMETERS

This section describes parameters that can be set by the user to configure the behavior of the TCP module.

  • TCP_BUFFER_SIZE: The size of the buffer used for sending and receiving data.
  • TCP_DEFAULT_TIMEOUT: The default timeout for network operations.

TCP USER-DEFINED PARAMETERS

This section describes how to define your own parameters to customize the TCP module.

You can define your own parameters to store custom configuration values or state information related to your TCP applications.

TCP UTILITY PARAMETERS

This section describes internal parameters used by the module. Users should generally not modify these.

  • TCP_INTERNAL_STATE: Internal state variable for managing connections.

TCP EXAMPLES

Here are some basic examples of how to use the zshtcpsys module.

Example 1: Simple TCP Client

# Connect to a server
tcp_connect example.com 80
if [[ $? -eq 0 ]]; then
    # Send an HTTP GET request
    tcp_send "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n"
    # Receive up to 1024 bytes
    data=$(tcp_recv 1024)
    echo "$data"
    # Close the connection
    tcp_close
else
    echo "Failed to connect"
fi

Example 2: Simple TCP Server

# Listen on port 1234
tcp_listen 1234
if [[ $? -eq 0 ]]; then
    echo "Server listening on port 1234"
    # Accept a connection
    if tcp_accept; then
        echo "Client connected"
        # Receive data
        data=$(tcp_recv 1024)
        echo "Received: $data"
        # Send a response
        tcp_send "Hello from server!"
        tcp_close
    fi
else
    echo "Failed to start server"
fi
