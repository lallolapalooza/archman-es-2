ZSTD(1) Comandos de usuario ZSTD(1)

NOMBRE

zstd, zstdmt, unzstd, zstdcat - Comprimir o descomprimir archivos .zst

SINOPSIS

zstd [OPCIONES] [-|ARCHIVO-ENTRADA] [-o ARCHIVO-SALIDA]

zstdmt es equivalente a zstd -T0

unzstd es equivalente a zstd -d

zstdcat es equivalente a zstd -dcf

DESCRIPCIÓN

zstd es un algoritmo de compresión rápido sin pérdidas y una herramienta de compresión de datos, con una sintaxis de línea de comandos similar a gzip(1) y xz(1). Se basa en la familia LZ77, con etapas adicionales de entropía FSE y huff0. zstd ofrece una velocidad de compresión altamente configurable, desde modos rápidos a > 200 MB/s por núcleo, hasta modos potentes con una excelente relación de compresión. También cuenta con un decodificador muy rápido, con velocidades de > 500 MB/s por núcleo, que se mantiene aproximadamente estable en todas las configuraciones de compresión.

La sintaxis del comando zstd es generalmente similar a la de gzip, pero presenta las siguientes diferencias:

  • Los archivos de origen se conservan por defecto. Es posible eliminarlos automáticamente usando el comando --rm.
  • Al comprimir un solo archivo, zstd muestra notificaciones de progreso y un resumen de resultados por defecto. Use -q para desactivarlas.
  • zstd muestra una página de ayuda corta cuando la línea de comandos es errónea. Use -q para desactivarla.
  • zstd no acepta entrada desde la consola, aunque sí acepta stdin cuando no es la consola.
  • zstd no almacena el nombre de archivo ni los atributos del contenido de entrada, solo su contenido.

zstd procesa cada archivo de acuerdo con el modo de operación seleccionado. Si no se proporcionan archivos o el archivo es -, zstd lee de la entrada estándar y escribe los datos procesados en la salida estándar. zstd se negará a escribir datos comprimidos en la salida estándar si es una terminal: mostrará un mensaje de error y omitirá el archivo. De manera similar, zstd se negará a leer datos comprimidos de la entrada estándar si es una terminal.

A menos que se especifique --stdout o -o, los archivos se escriben en un nuevo archivo cuyo nombre se deriva del nombre del archivo fuente:

  • Al comprimir, se añade el sufijo .zst al nombre del archivo fuente para obtener el nombre del archivo de destino.
  • Al descomprimir, se elimina el sufijo .zst del nombre del archivo fuente para obtener el nombre del archivo de destino.

Concatenación con archivos .zst

Es posible concatenar múltiples archivos .zst. zstd descomprimirá dicho archivo aglomerado como si fuera un solo archivo .zst.

OPCIONES

Sufijos enteros y valores especiales

En la mayoría de los lugares donde se espera un argumento entero, se soporta un sufijo opcional para indicar fácilmente enteros grandes. No debe haber ningún espacio entre el entero y el sufijo.

KiB
Multiplica el entero por 1.024 (2^10). Ki, K y KB se aceptan como sinónimos de KiB.
MiB
Multiplica el entero por 1.048.576 (2^20). Mi, M y MB se aceptan como sinónimos de MiB.

Modo de operación

Si se especifican varias opciones de modo de operación, la última es la que tiene efecto.

-z, --compress
Comprimir. Este es el modo de operación por defecto cuando no se especifica ninguna opción de modo de operación y ningún otro modo de operación está implícito por el nombre del comando (por ejemplo, unzstd implica --decompress).
-d, --decompress, --uncompress
Descomprimir.
-t, --test
Probar la integridad de los archivos comprimidos. Esta opción es equivalente a --decompress --stdout > /dev/null, los datos descomprimidos se descartan y se verifica su suma de control en busca de errores. No se crean ni se eliminan archivos.
-b#
Benchmarking de archivo(s) usando el nivel de compresión #. Vea BENCHMARK abajo para una descripción de esta operación.
--train ARCHIVOS
Utilice ARCHIVOS como conjunto de entrenamiento para crear un diccionario. El conjunto de entrenamiento debe contener muchos archivos pequeños (> 100). Vea CREADOR DE DICCIONARIOS abajo para una descripción de esta operación.
-l, --list
Mostrar información relacionada con un archivo comprimido con zstd, como tamaño, ratio y suma de control. Algunos de estos campos pueden no estar disponibles. La salida de este comando puede ser aumentada con el modificador -v.

Modificadores de operación

  • -#: selecciona el nivel de compresión # [1-19] (por defecto: 3). Los niveles de compresión más altos *generalmente* producen una mayor relación de compresión a expensas de la velocidad y la memoria. Una regla general es que se espera que la velocidad de compresión se divida por 2 cada 2 niveles. Técnicamente, cada nivel se mapea a un conjunto de parámetros avanzados (que también se pueden modificar individualmente, ver abajo). Debido a que el comportamiento del compresor depende en gran medida del contenido a comprimir, no hay garantía de una progresión suave de un nivel a otro.
  • --ultra: desbloquea niveles de compresión altos 20+ (máximo 22), utilizando mucha más memoria. Tenga en cuenta que la descompresión también requerirá más memoria al usar estos niveles.
  • --fast[=#]: cambia a niveles de compresión ultrarrápidos. Si no está presente =#, por defecto es 1. Cuanto mayor sea el valor, mayor será la velocidad de compresión, a costa de cierta relación de compresión. Esta configuración anula el nivel de compresión si se estableció previamente. De manera similar, si se establece un nivel de compresión después de --fast, lo anula.
  • -T#, --threads=#: Comprime usando # hilos de trabajo (por defecto: 1). Si # es 0, intenta detectar y usar el número de núcleos de CPU físicos. En todos los casos, el número de hilos se limita a ZSTDMT_NBWORKERS_MAX, que es 64 en modo de 32 bits, o 256 para entornos de 64 bits. Este modificador no hace nada si zstd está compilado sin soporte multihilo.
  • --single-thread: Utiliza un solo hilo para I/O y compresión. Como la compresión está serializada con la I/O, esto puede ser ligeramente más lento. El modo de un solo hilo presenta un uso de memoria significativamente menor, lo que puede ser útil para sistemas con una cantidad limitada de memoria, como los sistemas de 32 bits.
Nota 1: este modo es el único disponible cuando el soporte multihilo está deshabilitado.
Nota 2: este modo es diferente de -T1, que inicia 1 hilo de compresión en paralelo con la I/O. El resultado comprimido final también es ligeramente diferente de -T1.
  • --auto-threads={physical,logical} (por defecto: physical): Al usar una cantidad por defecto de hilos a través de -T0, elige el valor por defecto basándose en el número de núcleos físicos o lógicos detectados.
  • --adapt[=min=#,max=#]: zstd adaptará dinámicamente el nivel de compresión a las condiciones de I/O percibidas. La adaptación del nivel de compresión se puede observar en vivo usando el comando -v. La adaptación se puede restringir entre los niveles min y max suministrados. La característica funciona cuando se combina con multihilo y el modo --long. No funciona con --single-thread. Establece el tamaño de la ventana en 8 MiB por defecto (se puede cambiar manualmente, ver wlog). Debido a la naturaleza caótica de la adaptación dinámica, el resultado comprimido no es reproducible.
Nota: en el momento de escribir esto, --adapt puede quedarse atascado a baja velocidad cuando se combina con múltiples hilos de trabajo (>=2).

Hay un impacto insignificante en la relación de compresión y un impacto potencial en la velocidad de compresión, perceptible a velocidades más altas, por ejemplo, al combinar --rsyncable con muchos hilos trabajadores paralelos. Esta característica no funciona con --single-thread. Probablemente no querrás usarla con el modo de largo alcance, ya que disminuirá la efectividad de los puntos de sincronización, pero tu experiencia puede variar.
  • -C, --[no-]check: agrega una verificación de integridad calculada a partir de datos descomprimidos (por defecto: habilitado).
  • --[no-]content-size: habilita / deshabilita si el tamaño original del archivo se incluye o no en la cabecera del archivo comprimido. La opción por defecto es --content-size (lo que significa que el tamaño original se incluirá en la cabecera).
  • --no-dictID: no almacena el ID del diccionario en la cabecera del marco (compresión de diccionario). El decodificador tendrá que confiar en el conocimiento implícito sobre qué diccionario usar, no podrá verificar si es correcto.
  • -M#, --memory=#: Establece un límite de uso de memoria. Por defecto, zstd utiliza 128 MiB para la descompresión como cantidad máxima de memoria que el descompresor puede utilizar, pero puedes anular esto manualmente en cualquier dirección (es decir, puedes aumentarlo o disminuirlo).
Esto también se utiliza durante la compresión cuando se usa con --patch-from=. En este caso, este parámetro anula el tamaño máximo permitido para un diccionario (128 MiB).
Además, esto se puede utilizar para limitar la memoria para el entrenamiento de diccionarios. Este parámetro anula el límite predeterminado de 2 GiB. zstd cargará muestras de entrenamiento hasta el límite de memoria e ignorará el resto.
  • --stream-size=#: Establece el tamaño de origen prometido de la entrada proveniente de un flujo. Este valor debe ser exacto, ya que se incluirá en la cabecera del marco producido. Los tamaños de flujo incorrectos causarán un error. Esta información se utilizará para optimizar mejor los parámetros de compresión, lo que resultará en una compresión mejor y potencialmente más rápida, especialmente para tamaños de origen más pequeños.
  • --size-hint=#: Al procesar entrada desde un flujo, zstd debe adivinar cuán grande será el tamaño de origen al optimizar los parámetros de compresión. Si el tamaño del flujo es relativamente pequeño, esta suposición puede ser pobre, lo que resulta en una relación de compresión más alta de lo esperado. Esta característica permite controlar la suposición cuando sea necesario. Las suposiciones exactas resultan en mejores relaciones de compresión. Las sobreestimaciones resultan en relaciones de compresión ligeramente degradadas, mientras que las subestimaciones pueden resultar en una degradación significativa.
  • --target-compressed-block-size=#: Intenta producir bloques comprimidos de aproximadamente este tamaño. Esto dividirá bloques más grandes para aproximarse a este objetivo. Esta característica es notablemente útil para mejorar la latencia, cuando el receptor puede beneficiarse de recibir datos incompletos temprano. Este parámetro define un objetivo flexible: los bloques comprimidos apuntarán a este tamaño "en promedio", pero los bloques individuales aún pueden ser más grandes o más pequeños. Habilitar esta característica puede disminuir la velocidad de compresión hasta en un ~10% en el nivel 1. Los niveles más altos verán regresiones de velocidad relativas menores, volviéndose invisibles en configuraciones más altas.
  • -f, --force: deshabilita las verificaciones de entrada y salida. Permite sobrescribir archivos existentes, entrada desde la consola, salida a stdout, operar en enlaces, dispositivos de bloque, etc. Durante la descompresión y cuando el destino de salida es stdout, pasa los formatos no reconocidos tal cual.
  • -c, --stdout: escribe a la salida estándar (incluso si es la consola); conserva los archivos originales (deshabilita --rm).
  • -o FILE: guarda el resultado en FILE. Ten en cuenta que esta operación está en conflicto con -c. Si ambas operaciones están presentes en la línea de comandos, la última expresada prevalece.
  • --[no-]sparse: habilita / deshabilita el soporte para sistemas de archivos dispersos, para hacer que los archivos con muchos ceros sean más pequeños en disco. La creación de archivos dispersos puede ahorrar espacio en disco y acelerar la descompresión al reducir la cantidad de E/S de disco. Por defecto: habilitado cuando la salida es a un archivo, y deshabilitado cuando la salida es stdout. Esta configuración anula el predeterminado y puede forzar el modo disperso sobre stdout.
  • --[no-]pass-through habilita / deshabilita el paso de archivos no comprimidos tal cual. Durante la descompresión cuando el paso está habilitado, los formatos no reconocidos se copiarán tal cual de la entrada a la salida. Por defecto, el paso ocurrirá cuando el destino de salida sea stdout y la opción force (-f) esté establecida.
  • --rm: elimina el (los) archivo(s) fuente(s) después de una compresión o descompresión exitosa. Este comando se ignora silenciosamente si la salida es stdout. Si se usa en combinación con -o, activa una solicitud de confirmación (que se puede silenciar con -f), ya que es una operación destructiva.
  • -k, --keep: conserva el (los) archivo(s) fuente(s) después de una compresión o descompresión exitosa. Este es el comportamiento predeterminado.
  • -r: opera recursivamente en directorios. Selecciona todos los archivos en el directorio nombrado y en todos sus subdirectorios. Esto puede ser útil tanto para reducir la escritura en la línea de comandos como para eludir las limitaciones de expansión del shell, cuando hay muchos archivos y la nomenclatura excede el tamaño máximo de una línea de comandos.
  • --filelist FILE lee una lista de archivos a procesar como contenido de FILE. El formato es compatible con la salida de ls, con un archivo por línea.
  • --output-dir-flat DIR: los archivos resultantes se almacenan en el directorio de destino DIR, en lugar de en el mismo directorio del archivo de origen. Ten en cuenta que este comando puede introducir problemas de colisión de nombres, si varios archivos, de diferentes directorios, terminan teniendo el mismo nombre. La resolución de colisiones asegura que el primer archivo con un nombre dado estará presente en DIR, mientras que en combinación con -f, estará presente el último archivo.
  • --output-dir-mirror DIR: similar a --output-dir-flat, los archivos de salida se almacenan debajo del directorio de destino DIR, pero esta opción replicará la jerarquía del directorio de entrada en DIR de salida.
Si el directorio de entrada contiene "..", los archivos en este directorio serán ignorados. Si el directorio de entrada es un directorio absoluto (es decir, "/var/tmp/abc"), se almacenará en "output-dir/var/tmp/abc". Si hay varios archivos o directorios de entrada, la resolución de colisión de nombres seguirá las mismas reglas que --output-dir-flat.
  • --format=FORMAT: comprime y descomprime en otros formatos. Si se compiló con soporte, zstd puede comprimir a o descomprimir desde otros formatos de algoritmo de compresión. Las opciones posiblemente disponibles son zstd, gzip, xz, lzma y lz4. Si no se proporciona ningún formato, el predeterminado es zstd.
  • -h/-H, --help: muestra la ayuda / ayuda larga y sale.
  • -V, --version: muestra el número de versión y sale inmediatamente. Ten en cuenta que, como sale, las banderas especificadas después de -V se ignoran efectivamente. Avanzado: -vV también muestra los formatos compatibles. -vvV también muestra el soporte POSIX. -qV solo mostrará el número de versión, adecuado para lectura por máquina.
  • -v, --verbose: modo detallado, muestra más información.
  • -q, --quiet: suprime advertencias, interactividad y notificaciones. especifica dos veces para suprimir también los errores.
  • --no-progress: no muestra la barra de progreso, pero mantiene todos los demás mensajes.
  • --show-default-cparams: muestra los parámetros de compresión predeterminados que se utilizarán para un archivo de entrada particular, basados en el nivel de compresión proporcionado y el tamaño de entrada. Si el archivo proporcionado no es un archivo regular (por ejemplo, una tubería), esta bandera mostrará los parámetros utilizados para entradas de tamaño desconocido.
  • --exclude-compressed: solo comprime archivos que no están ya comprimidos.
  • --: Todos los argumentos después de -- se tratan como archivos.

Modificadores de Operación de gzip

Cuando se invoca a través de un enlace simbólico de gzip, zstd admitirá opciones adicionales que pretenden imitar el comportamiento de gzip:

-n, --no-name
no almacena el nombre de archivo original ni las marcas de tiempo al comprimir un archivo. Este es el comportamiento predeterminado y, por lo tanto, una operación nula.
--best
alias de la opción -9.

--train ARCHIVOS
Utiliza ARCHIVOS como conjunto de entrenamiento para crear un diccionario. El conjunto de entrenamiento idealmente debería contener muchas muestras (> 100) y pesar típicamente 100 veces el tamaño del diccionario objetivo (por ejemplo, ~10 MB para un diccionario de 100 KB). --train se puede combinar con -r para indicar un directorio en lugar de listar todos los archivos, lo que puede ser útil para evitar los límites de expansión del shell.
Dado que la compresión de diccionario es mayormente efectiva para archivos pequeños, la expectativa es que el conjunto de entrenamiento solo contenga archivos pequeños. En caso de que algunas muestras sean grandes, solo se utilizarán los primeros 128 KiB de estas muestras para el entrenamiento.
--train soporta multihilo si zstd está compilado con soporte para hilos (por defecto). Se pueden especificar parámetros adicionales avanzados con --train-fastcover. Se puede acceder al generador de diccionarios heredado con --train-legacy. Se puede acceder al generador de diccionarios cover, más lento, con --train-cover. El valor por defecto de --train es equivalente a --train-fastcover=d=8,steps=4.
-o ARCHIVO
Diccionario guardado en ARCHIVO (nombre por defecto: dictionary).
--maxdict=#
Limita el diccionario al tamaño especificado (por defecto: 112640 bytes). Como siempre, las cantidades se expresan en bytes por defecto, y es posible emplear sufijos (como KB o MB) para especificar valores más grandes.
-#
Utiliza el nivel de compresión # durante el entrenamiento (opcional). Generará estadísticas más ajustadas para el nivel de compresión seleccionado, resultando en una *pequeña* mejora en la relación de compresión para este nivel.
-B#
Divide los archivos de entrada en bloques de tamaño # (por defecto: sin división)
-M#, --memory=#
Limita la cantidad de datos de muestra cargados para el entrenamiento (por defecto: 2 GB). Ten en cuenta que el valor por defecto (2 GB) es también el máximo. Este parámetro puede ser útil en situaciones donde el tamaño del conjunto de entrenamiento no está bien controlado y podría ser potencialmente muy grande. Dado que la velocidad del proceso de entrenamiento está directamente correlacionada con el tamaño del conjunto de muestras de entrenamiento, un conjunto de muestras más pequeño conduce a un entrenamiento más rápido.
En situaciones donde el conjunto de entrenamiento es mayor que la memoria máxima, la CLI seleccionará aleatoriamente muestras entre las disponibles, hasta el presupuesto máximo de memoria permitido. Esto tiene como objetivo mejorar la relevancia del diccionario mitigando el impacto potencial de la agrupación, como seleccionar solo archivos del principio de una lista ordenada por fecha de modificación o por orden alfabético. El proceso de aleatorización es determinista, por lo que el entrenamiento de la misma lista de archivos con los mismos parámetros conducirá a la creación del mismo diccionario.
--dictID=#
Un ID de diccionario es un ID localmente único. El decodificador usará este valor para verificar que está usando el diccionario correcto. Por defecto, zstd creará un ID numérico aleatorio de 4 bytes. Es posible proporcionar un ID numérico explícito en su lugar. Depende del administrador del diccionario no asignar dos veces el mismo ID a 2 diccionarios diferentes. Ten en cuenta que los números cortos tienen una ventaja: un ID < 256 solo necesitará 1 byte en la cabecera del frame comprimido, y un ID < 65536 solo necesitará 2 bytes. Esto se compara favorablemente con los 4 bytes por defecto.
Ten en cuenta que RFC8878 reserva IDs menores que 32768 y mayores o iguales a 2^31, por lo que no deben usarse públicamente.
--train-cover[=k#,d=#,steps=#,split=#,shrink[=#]]
Selecciona parámetros para el algoritmo generador de diccionarios por defecto llamado cover. Si d no se especifica, entonces prueba d = 6 y d = 8. Si k no se especifica, entonces prueba valores de steps en el rango [50, 2000]. Si steps no se especifica, entonces se usa el valor por defecto de 40. Si split no se especifica o split <= 0, entonces se usa el valor por defecto de 100. Requiere que d <= k. Si el flag shrink no se usa, entonces se usa el valor por defecto para shrinkDict de 0. Si shrink no se especifica, entonces se usa el valor por defecto para shrinkDictMaxRegression de 1.
Selecciona segmentos de tamaño k con la puntuación más alta para incluir en el diccionario. La puntuación de un segmento se calcula sumando las frecuencias de todos los subsegmentos de tamaño d. Generalmente d debería estar en el rango [6, 8], ocasionalmente hasta 16, pero el algoritmo se ejecutará más rápido con d <= 8. Los buenos valores para k varían ampliamente según los datos de entrada, pero un rango seguro es [2 * d, 2000]. Si split es 100, todas las muestras de entrada se utilizan tanto para entrenamiento como para prueba para encontrar los valores óptimos de d y k para construir el diccionario. Soporta multihilo si zstd está compilado con soporte para hilos. Tener shrink habilitado toma un diccionario truncado de tamaño mínimo y duplica su tamaño hasta que la relación de compresión del diccionario truncado sea como máximo un X% peor que la relación de compresión del diccionario más grande.
Ejemplos:
zstd --train-cover ARCHIVOS
zstd --train-cover=k=50,d=8 ARCHIVOS
zstd --train-cover=d=8,steps=500 ARCHIVOS
zstd --train-cover=k=50 ARCHIVOS
zstd --train-cover=k=50,split=60 ARCHIVOS
zstd --train-cover=shrink ARCHIVOS
zstd --train-cover=shrink=2 ARCHIVOS
--train-fastcover[=k#,d=#,f=#,steps=#,split=#,accel=#]
Igual que cover pero con parámetros adicionales f y accel y un valor por defecto diferente de split. Si split no se especifica, entonces prueba split = 75. Si f no se especifica, entonces prueba f = 20. Requiere que 0 < f < 32. Si accel no se especifica, entonces prueba accel = 1. Requiere que 0 < accel <= 10. Requiere que d = 6 u d = 8.
f es el logaritmo del tamaño de un array que realiza un seguimiento de la frecuencia de subsegmentos de tamaño d. El subsegmento se hasha a un índice en el rango [0,2^f - 1]. Es posible que 2 subsegmentos diferentes se hasheen al mismo índice, y se consideren como el mismo subsegmento al calcular la frecuencia. Usar un f más alto reduce las colisiones pero lleva más tiempo.
Ejemplos:
zstd --train-fastcover ARCHIVOS
zstd --train-fastcover=d=8,f=15,accel=2 ARCHIVOS
--train-legacy[=selectivity=#]
Utiliza el algoritmo generador de diccionarios heredado con la selectividad de diccionario dada (por defecto: 9). Cuanto menor sea el valor de selectividad, más denso será el diccionario, mejorando su eficiencia pero reduciendo su tamaño máximo alcanzable. También se acepta --train-legacy=s=#.
Ejemplos:
zstd --train-legacy ARCHIVOS
zstd --train-legacy=selectivity=8 ARCHIVOS

BENCHMARK

La CLI de zstd proporciona un modo de benchmarking que puede utilizarse para encontrar fácilmente parámetros de compresión adecuados, o alternativamente para evaluar el rendimiento de un ordenador. zstd -b [ARCHIVOS] evaluará zstd tanto para la compresión como para la descompresión utilizando el nivel de compresión por defecto. Ten en cuenta que los resultados dependen mucho del contenido que se comprime.

Es posible pasar varios archivos al benchmark, e incluso un directorio con -r DIRECTORIO. Cuando no se proporciona ningún ARCHIVO, el benchmark utilizará un texto lorem ipsum generado procedimentalmente.

El benchmarking empleará por defecto max(1, min(4, nbCores/4)) hilos de trabajo para que coincida con el comportamiento de la E/S normal de la CLI.

  • -b#: evalúa el/los archivo(s) usando el nivel de compresión #
  • -e#: evalúa el/los archivo(s) usando múltiples niveles de compresión, desde -b# hasta -e# (inclusive)
  • -d: evalúa solo la velocidad de descompresión (requiere proporcionar un contenido comprimido con zstd)
  • -i#: tiempo mínimo de evaluación, en segundos (por defecto: 3s), solo modo benchmark
  • -B#, --block-size=#: corta el/los archivo(s) en fragmentos independientes de tamaño # (por defecto: sin fragmentación)
  • -S: produce un resultado de benchmark por archivo de entrada (por defecto: resultado consolidado)
  • -D diccionario evalúa usando diccionario
  • --priority=rt: establece la prioridad del proceso a tiempo real (Windows)

Más allá de los niveles de compresión, el benchmarking también es compatible con otros parámetros, como el número de hilos (-T#), parámetros de compresión avanzados (--zstd=###), compresión de diccionario (-D diccionario), o incluso la desactivación de la verificación de checksum, por ejemplo.

Formato de Salida: NivelDeCompresión#NombreArchivo: TamañoEntrada -> TamañoSalida (RelaciónCompresión), VelocidadCompresión, VelocidadDescompresión

Metodología: Para la medición de velocidad, toda la entrada se comprime/descomprime en memoria para medir la velocidad. Una ejecución dura al menos 1 segundo, por lo que cuando los archivos son pequeños, se comprimen/ descomprimen varias veces por ejecución, con el fin de mejorar la precisión de la medición.
