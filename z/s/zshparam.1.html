NOMBRE

zshparam - parámetros de zsh

DESCRIPCIÓN

Un parámetro tiene un nombre, un valor y una serie de atributos. Un nombre puede ser cualquier secuencia de caracteres alfanuméricos y guiones bajos, o los caracteres individuales `*', `@', `#', `?', `-', `$', o `!'. Un parámetro cuyo nombre comienza con un alfanumérico o guion bajo también se conoce como una variable.

Los atributos de un parámetro determinan el tipo de su valor, a menudo referido como el tipo de parámetro o tipo de variable, y también controlan otro procesamiento que puede aplicarse al valor cuando se referencia. El tipo de valor puede ser un escalar (una cadena, un entero o un número de punto flotante), un array (indexado numéricamente) o un array asociativo (un conjunto no ordenado de pares nombre-valor, indexado por nombre, también conocido como un hash).

Los parámetros escalares con nombre pueden tener el atributo exportado, -x, para copiarlos en el entorno del proceso, que luego se pasa del shell a cualquier proceso nuevo que inicie. Los parámetros exportados se denominan variables de entorno. El shell también importa variables de entorno al inicio y marca automáticamente los parámetros correspondientes como exportados. Algunas variables de entorno no se importan por razones de seguridad o porque interferirían con el correcto funcionamiento de otras características del shell.

Los parámetros también pueden ser especiales, es decir, tienen un significado predeterminado para el shell. Los parámetros especiales no pueden cambiar su tipo ni desactivar su atributo de solo lectura, y si un parámetro especial se elimina y luego se recrea, las propiedades especiales se conservarán.

Para declarar el tipo de un parámetro, o para asignar un valor de cadena o numérico a un parámetro escalar, use el comando interno typeset.

El valor de un parámetro escalar también se puede asignar escribiendo:

nombre=valor

En la asignación escalar, valor se expande como una única cadena, en la que los elementos de los arrays se unen; la expansión de nombres de archivo no se realiza a menos que la opción GLOB_ASSIGN esté establecida.

Cuando el atributo de entero, -i, o un atributo de punto flotante, -E o -F, se establece para nombre, el valor se somete a evaluación aritmética. Además, al reemplazar `=' con `+=', un parámetro puede incrementarse o añadirse. Consulte la sección `Parámetros Array' y Evaluación Aritmética (en zshmisc(1)) para formas adicionales de asignación.

Tenga en cuenta que la asignación puede cambiar implícitamente los atributos de un parámetro. Por ejemplo, asignar un número a una variable en evaluación aritmética puede cambiar su tipo a entero o flotante, y con GLOB_ASSIGN, asignar un patrón a una variable puede cambiar su tipo a array.

Para referenciar el valor de un parámetro, escriba `$nombre' o `${nombre}'. Consulte Expansión de Parámetros en zshexpn(1) para obtener detalles completos. Esa sección también explica el efecto de la diferencia entre la asignación escalar y de array en la expansión de parámetros.

PARÁMETROS ARRAY

Para asignar un valor de array, escriba una de las siguientes opciones:

set -A nombre valor ...
nombre=(valor ...)
nombre=([clave]=valor ...)

Si no existe ningún parámetro nombre, se crea un parámetro de array ordinario. Si el parámetro nombre existe y es escalar, se reemplaza por un nuevo array.

En la tercera forma, clave es una expresión que se evaluará en contexto aritmético (en su forma más simple, un entero) que proporciona el índice del elemento que se asignará con valor. En esta forma, los elementos no mencionados explícitamente que preceden al índice más grande al que se asigna un valor se les asigna una cadena vacía. Los índices pueden estar en cualquier orden. Tenga en cuenta que esta sintaxis es estricta: [ y ]= no deben estar entre comillas, y clave no puede consistir en la cadena no entre comillas ]=, pero por lo demás se trata como una cadena simple. Las formas mejoradas de subíndices que se pueden usar al indexar directamente un nombre de variable, descritas en la sección `Subíndices de Array' a continuación, no están disponibles.

Las sintaxis con y sin la clave explícita se pueden mezclar. La clave implícita se deduce incrementando el índice del elemento asignado previamente. Tenga en cuenta que no se considera un error si las asignaciones posteriores en esta forma sobrescriben asignaciones anteriores.

Por ejemplo, asumiendo que la opción KSH_ARRAYS no está establecida, lo siguiente:

array=(one [3]=three four)

hace que la variable de array array contenga cuatro elementos: one, una cadena vacía, three y four, en ese orden.

En las formas en las que solo se especifica valor, se realiza una expansión completa de la línea de comandos.

En la forma [clave]=valor, tanto clave como valor se someten a todas las formas de expansión permitidas para expansiones de palabras únicas del shell (esto no incluye la generación de nombres de archivo); estas son como se realizan por el indicador de expansión de parámetros (e) como se describe en zshexpn(1). Los paréntesis anidados pueden rodear valor y se incluyen como parte del valor, que se une en una cadena simple; esto difiere de ksh, que permite que los propios valores sean arrays. Una versión futura de zsh puede admitir eso. Para hacer que los corchetes se interpreten como una clase de caracteres para la generación de nombres de archivo, y por lo tanto para tratar la lista resultante de archivos como un conjunto de valores, ponga entre comillas el signo igual usando cualquier forma de cita. Ejemplo:

nombre=([a-z]'='*)

Para añadir a un array sin cambiar los valores existentes, utilice una de las siguientes opciones:

nombre+=(valor ...)
nombre+=([clave]=valor ...)

En la segunda forma, clave puede especificar un índice existente, así como un índice fuera del final del array antiguo; cualquier valor existente se sobrescribe con valor. Además, es posible usar [clave]+=valor para añadir al valor existente en ese índice.

Dentro de los paréntesis en el lado derecho de cualquiera de las formas de asignación, los saltos de línea y los punto y coma se tratan igual que el espacio en blanco, separando valores individuales. Cualquier secuencia consecutiva de dichos caracteres tiene el mismo efecto.

Los parámetros de array ordinarios también se pueden declarar explícitamente con:

typeset -a nombre

Los arrays asociativos deben declararse antes de la asignación, utilizando:

typeset -A nombre

Cuando nombre se refiere a un array asociativo, la lista en una asignación se interpreta como claves y valores alternos:

set -A nombre clave valor ...
nombre=(clave valor ...)
nombre=([clave]=valor ...)

Tenga en cuenta que solo una de las dos sintaxis anteriores puede usarse en una asignación dada; las formas no se pueden mezclar. Esto es diferente del caso de los arrays indexados numéricamente.

Cada clave debe tener un valor en este caso. Tenga en cuenta que esto asigna a todo el array, eliminando cualquier elemento que no aparezca en la lista. La sintaxis de añadir también se puede usar con un array asociativo:

nombre+=(clave valor ...)
nombre+=([clave]=valor ...)

Esto añade un nuevo par clave/valor si la clave no está presente, y reemplaza el valor para la clave existente si lo está. En la segunda forma, también es posible usar [clave]+=valor para añadir al valor existente en esa clave. La expansión se realiza de manera idéntica a las formas correspondientes para arrays normales, como se describe anteriormente.

Para crear un array vacío (incluyendo arrays asociativos), use una de las siguientes opciones:

set -A nombre
nombre=()

Subíndices de Array

La expansión de parámetros de array puede referirse a subconjuntos específicos de elementos de un array. El comportamiento varía según que se trate de un array ordinario o de un array asociativo. Para arrays ordinarios, los subíndices son números enteros que comienzan en 0. Para arrays asociativos, los subíndices son cadenas que coinciden con las claves del array.

El subíndice puede ser una expresión aritmética simple, como se describe en Evaluación Aritmética en zshmisc(1). Los subíndices negativos se cuentan desde el final del array, de modo que -1 es el último elemento, -2 es el penúltimo, y así sucesivamente. Si el subíndice es mayor o igual al número de elementos del array, o menor o igual al negativo del número de elementos, se produce un error (a menos que se establezca la opción NOMATCH).

Además de los subíndices de cadena simples para arrays asociativos, zsh admite subíndices mejorados:

[expresión]
El valor de expresión se utiliza como subíndice. Por ejemplo, ${array[2]} hace referencia al tercer elemento del array ordinario `array', o al elemento con clave `2' en un array asociativo `array'.
[inicio,fin]
Esto hace referencia a un rango de elementos, desde el índice inicio hasta el índice fin (inclusive). Por ejemplo, ${array[1,3]} hace referencia a los elementos de índice 1, 2 y 3.
[inicio:+expresión]
Esto hace referencia a todos los elementos desde el índice inicio hasta el final del array. Por ejemplo, ${array[2,:+]} hace referencia a todos los elementos del array `array' a partir del índice 2.
[:*]
Esto hace referencia a todos los elementos del array.

Los subíndices de rango son aplicables a ambos tipos de arrays. Para arrays asociativos, los índices de rango pueden especificarse como índices de cadena para arrays asociativos: ${hash[key1,key2]}. Sin embargo, la ordenación de los elementos en un array asociativo no está garantizada, por lo que el uso de rangos de índices en arrays asociativos puede dar lugar a resultados impredecibles.

Las claves de los arrays asociativos pueden incluir cualquier carácter que sea válido en los nombres de variables de zsh, así como caracteres de espacio en blanco y la mayoría de los caracteres de puntuación. Sin embargo, si una clave contiene un carácter especial (por ejemplo, ` ` ` , `$'` o `"'` ), se deben entrecomillar. Por ejemplo, ${array["clave con espacio"]} o ${array["clave'con'cita"]}.

Si se hace referencia a un elemento de array que no existe, el valor devuelto es una cadena vacía, a menos que se establezca la opción NOMATCH, en cuyo caso se produce un error.

Para obtener el número de elementos de un array, utilice el subíndice ${#array[@]} para arrays ordinarios (que devuelve el número de elementos) y ${#hash[@]} para arrays asociativos (que devuelve el número de pares clave-valor). Para obtener el número de caracteres en la expansión de un solo elemento, utilice ${#array[i]}.

PARÁMETROS ENTEROS

Si el atributo de entero, -i, se establece para un parámetro, su valor se trata como un entero en las operaciones aritméticas y la asignación. Cuando se asigna un valor a un parámetro entero, el valor se evalúa en un contexto aritmético. Por ejemplo, si el parámetro i se declara como entero con typeset -i i, y luego se le asigna i=5+3, el valor de i será 8.

Los parámetros enteros también pueden ser de punto flotante. Para ello, utilice el atributo -E para el punto flotante de doble precisión o -F para el punto flotante de precisión simple. La asignación a un parámetro de punto flotante también se evalúa en contexto aritmético. Por ejemplo, si el parámetro f se declara como punto flotante con typeset -E f, y luego se le asigna f=1.23\*4, el valor de f será 4.92.

La operación += se puede usar para añadir a un parámetro entero o de punto flotante. Por ejemplo, si i es un entero, i+=5 añade 5 a su valor actual. Si f es de punto flotante, f+=1.5 añade 1.5 a su valor actual.

Los parámetros enteros y de punto flotante se inicializan a 0 (o 0.0) si no se les asigna un valor explícito.

PARÁMETROS LOCALES

Dentro de una función, los parámetros pueden declararse como locales utilizando el comando interno typeset o local. Las variables declaradas como locales solo existen dentro del ámbito de la función en la que se declaran y se destruyen cuando la función sale. Esto es útil para evitar la contaminación del espacio de nombres global y para mantener el estado de la función aislado.

Por ejemplo:

my_function() {
  local var1="valor local"
  typeset var2="otro valor local"
  echo "$var1"
  echo "$var2"
}

Las variables var1 y var2 solo están disponibles dentro de my_function. Intentar acceder a ellas fuera de la función resultará en un error.

El comando local es un alias de typeset con el modificador -h. El modificador -h hace que la variable sea local a la función actual.

PARÁMETROS DE SOLO LECTURA

Los parámetros pueden declararse como de solo lectura utilizando el modificador -r del comando typeset. Una vez que un parámetro se marca como de solo lectura, su valor no se puede cambiar y no se puede eliminar. Esto es útil para proteger variables importantes de modificaciones accidentales.

Por ejemplo:

typeset -r MY_CONSTANT="este valor no se puede cambiar"

Si se intenta asignar un nuevo valor a MY_CONSTANT o eliminarlo, el shell generará un error.

Los parámetros especiales creados por el shell, como $? (código de salida), también son de solo lectura.

PARÁMETROS NAMEREF

Los parámetros nameref (referencia de nombre) son un tipo especial de parámetro que actúa como un alias para otro parámetro. Cuando se accede a un parámetro nameref, en realidad se está accediendo al parámetro al que apunta. Esto se declara utilizando el modificador -n del comando typeset.

Por ejemplo:

variable="valor original"
typeset -n alias_variable=variable
echo "$alias_variable"
alias_variable="nuevo valor"
echo "$variable"

En este ejemplo, alias_variable es un nameref que apunta a variable. Cualquier cambio realizado en alias_variable afecta a variable y viceversa. La salida será:

valor original
nuevo valor

Los nameref son útiles para crear referencias a variables, especialmente dentro de funciones o al manipular estructuras de datos complejas.

PARÁMETROS ESPECIALES

El shell zsh define varios parámetros especiales que proporcionan información sobre el estado del shell, los argumentos del comando, los procesos y el entorno de ejecución. Estos parámetros tienen significados predefinidos y no pueden ser redefinidos ni eliminados por el usuario.

Algunos de los parámetros especiales más comunes incluyen:

$0
El nombre del script o shell que se está ejecutando.
$1, $2, ... ${10}, ...
Los argumentos posicionales pasados al script o shell. $@ y $* representan todos los argumentos posicionales.
$?
El código de salida del último comando ejecutado. Un valor de 0 indica éxito, mientras que un valor distinto de cero indica un error.
$$
El ID del proceso (PID) del shell actual.
$!
El ID del proceso (PID) del último comando ejecutado en segundo plano.
$-
Los indicadores de opciones actualmente establecidos para el shell.
$?
El carácter que se utiliza para separar los argumentos en la expansión de parámetros del array. El valor predeterminado es un espacio.
$UID
El ID de usuario real del usuario actual.
$EUID
El ID de usuario efectivo del usuario actual.
$GROUPS
Un array que contiene los GID de los grupos de los que forma parte el usuario actual.
$HOME
El directorio principal del usuario actual.
$PATH
La lista de directorios en los que el shell busca comandos ejecutables.
$RANDOM
Un número pseudoaleatorio entre 0 y 32767 cada vez que se accede a él.
$SECONDS
El número de segundos transcurridos desde el inicio del shell.

Estos parámetros especiales proporcionan una forma conveniente de interactuar con el entorno del shell y controlar su comportamiento.

Análisis de Subíndices

This discussion applies mainly to associative array key strings and to patterns used for reverse subscripting (the `r', `R', `i', etc. flags), but it may also affect parameter substitutions that appear as part of an arithmetic expression in an ordinary subscript.

To avoid subscript parsing limitations in assignments to associative array elements, use the append syntax:

aa+=('key with "*strange*" characters' 'value string')

The basic rule to remember when writing a subscript expression is that all text between the opening `[' and the closing `]' is interpreted as if it were in double quotes (see zshmisc(1)). However, unlike double quotes which normally cannot nest, subscript expressions may appear inside double-quoted strings or inside other subscript expressions (or both!), so the rules have two important differences.

The first difference is that brackets (`[' and `]') must appear as balanced pairs in a subscript expression unless they are preceded by a backslash (`\'). Therefore, within a subscript expression (and unlike true double-quoting) the sequence `\[' becomes `[', and similarly `\]' becomes `]'. This applies even in cases where a backslash is not normally required; for example, the pattern `[^[]' (to match any character other than an open bracket) should be written `[^\[]' in a reverse-subscript pattern. However, note that `\[^\[\]' and even `\[^[]' mean the same thing, because backslashes are always stripped when they appear before brackets!

The same rule applies to parentheses (`(' and `)') and braces (`{' and `}'): they must appear either in balanced pairs or preceded by a backslash, and backslashes that protect parentheses or braces are removed during parsing. This is because parameter expansions may be surrounded by balanced braces, and subscript flags are introduced by balanced parentheses.

The second difference is that a double-quote (`"') may appear as part of a subscript expression without being preceded by a backslash, and therefore that the two characters `\"' remain as two characters in the subscript (in true double-quoting, `\"' becomes `"'). However, because of the standard shell quoting rules, any double-quotes that appear must occur in balanced pairs unless preceded by a backslash. This makes it more difficult to write a subscript expression that contains an odd number of double-quote characters, but the reason for this difference is so that when a subscript expression appears inside true double-quotes, one can still write `\"' (rather than `\\\"') for `"'.

To use an odd number of double quotes as a key in an assignment, use the typeset builtin and an enclosing pair of double quotes; to refer to the value of that key, again use double quotes:

typeset -A aa
typeset "aa[one\"two\"three\"quotes]"=QQQ
print "$aa[one\"two\"three\"quotes]"

It is important to note that the quoting rules do not change when a parameter expansion with a subscript is nested inside another subscript expression. That is, it is not necessary to use additional backslashes within the inner subscript expression; they are removed only once, from the innermost subscript outwards. Parameters are also expanded from the innermost subscript first, as each expansion is encountered left to right in the outer expression.

A further complication arises from a way in which subscript parsing is not different from double quote parsing. As in true double-quoting, the sequences `\*', and `\@' remain as two characters when they appear in a subscript expression. To use a literal `*' or `@' as an associative array key, the `e' flag must be used:

typeset -A aa
aa[(e)*]=star
print $aa[(e)*]

A last detail must be considered when reverse subscripting is performed. Parameters appearing in the subscript expression are first expanded and then the complete expression is interpreted as a pattern. This has two effects: first, parameters behave as if GLOB_SUBST were on (and it cannot be turned off); second, backslashes are interpreted twice, once when parsing the array subscript and again when parsing the pattern. In a reverse subscript, it's necessary to use four backslashes to cause a single backslash to match literally in the pattern. For complex patterns, it is often easiest to assign the desired pattern to a parameter and then refer to that parameter in the subscript, because then the backslashes, brackets, parentheses, etc., are seen only when the complete expression is converted to a pattern. To match the value of a parameter literally in a reverse subscript, rather than as a pattern, use `${(q)name}' (see zshexpn(1)) to quote the expanded value.

Note that the `k' and `K' flags are reverse subscripting for an ordinary array, but are not reverse subscripting for an associative array! (For an associative array, the keys in the array itself are interpreted as patterns by those flags; the subscript is a plain string in that case.)

One final note, not directly related to subscripting: the numeric names of positional parameters (described below) are parsed specially, so for example `$2foo' is equivalent to `${2}foo'. Therefore, to use subscript syntax to extract a substring from a positional parameter, the expansion must be surrounded by braces; for example, `${2[3,5]}' evaluates to the third through fifth characters of the second positional parameter, but `$2[3,5]' is the entire second parameter concatenated with the filename generation pattern `[3,5]'.

PARÁMETROS POSICIONALES

The positional parameters provide access to the command-line arguments of a shell function, shell script, or the shell itself; see the section `Invocation', and also the section `Functions'. The parameter n, where n is a number, is the nth positional parameter. The parameter `$0' is a special case, see the section `Parameters Set By The Shell'.

The parameters *, @ and argv are arrays containing all the positional parameters; thus `$argv[n]', etc., is equivalent to simply `$n'. Note that the options KSH_ARRAYS or KSH_ZERO_SUBSCRIPT apply to these arrays as well, so with either of those options set, `${argv[0]}' is equivalent to `$1' and so on.

Positional parameters may be changed after the shell or function starts by using the set builtin, by assigning to the argv array, or by direct assignment of the form `n=value' where n is the number of the positional parameter to be changed. This also creates (with empty values) any of the positions from 1 to n that do not already have values. Note that, because the positional parameters form an array, an array assignment of the form `n=(value ...)' is allowed, and has the effect of shifting all the values at positions greater than n by as many positions as necessary to accommodate the new values.

PARÁMETROS LOCALES

La mayoría de los parámetros se pueden hacer locales a una función. Cuando un parámetro se declara como local en una función, su alcance se limita a esa función. Los parámetros locales de una función se eliminan al finalizar la función. Al declarar un parámetro como local a una función, la función puede tener un parámetro de igual nombre que no es local a la función; en tal caso, el parámetro local oculta al parámetro externo.

Solo los parámetros que no sean de solo lectura se pueden hacer locales. El uso de local dentro de una función crea una copia local del parámetro. Si el parámetro ya existe, su valor se guarda y se restaura cuando la función termina. Si el parámetro no existe, se crea localmente y se elimina cuando la función termina. Si se le asigna un valor al declarar un parámetro local, ese valor se usa como el valor inicial del parámetro local.

Por ejemplo:

foo() {
    local bar=1
    print $bar # imprime 1
}
bar=2
foo
print $bar # imprime 2

El uso de local sin un nombre de parámetro le permite declarar varios parámetros locales de una vez. Por ejemplo:

foo() {
    local bar baz
    bar=1
    baz=2
    print $bar $baz
}

Si se usa local con un parámetro que no existe, o si se declara un nuevo parámetro con export, este se crea en el ámbito exterior.

Los parámetros locales desaparecen cuando finaliza su ámbito. unset se puede usar para eliminar un parámetro mientras todavía está en ámbito; cualquier parámetro externo del mismo nombre permanece oculto.

Los parámetros especiales también se pueden hacer locales; conservan sus atributos especiales a menos que el parámetro existente o el recién creado tenga el atributo -h (ocultar). Esto puede tener efectos inesperados: no hay un valor predeterminado, por lo que si no hay una asignación en el punto en que la variable se hace local, se establecerá en un valor vacío (o cero en el caso de los enteros). Lo siguiente:

typeset PATH=/new/directory:$PATH

es válido para permitir temporalmente que el shell o los programas llamados desde él encuentren los programas en /new/directory dentro de una función.

Tenga en cuenta que la restricción en versiones anteriores de zsh de que los parámetros locales nunca se exportaban ha sido eliminada.

Estas variables pueden contener los conjuntos de caracteres que causarán la eliminación del sufijo. Si ZLE_REMOVE_SUFFIX_CHARS no está establecido, el comportamiento predeterminado es equivalente a:

ZLE_REMOVE_SUFFIX_CHARS=$' \t\n;&|'

Si ZLE_REMOVE_SUFFIX_CHARS está establecido pero vacío, ningún carácter tiene este comportamiento. ZLE_SPACE_SUFFIX_CHARS tiene prioridad, de modo que lo siguiente:

ZLE_SPACE_SUFFIX_CHARS=$'&|'

Para ilustrar la diferencia, supongamos que la opción AUTO_REMOVE_SLASH está en vigor y el directorio DIR acaba de completarse, con una / añadida, después de lo cual el usuario escribe `&'. El resultado predeterminado es `DIR&'. Con ZLE_REMOVE_SUFFIX_CHARS establecido pero sin incluir `&' el resultado es `DIR/&'. Con ZLE_SPACE_SUFFIX_CHARS establecido para incluir `&' el resultado es `DIR &'.

Ten en cuenta que ciertas completaciones pueden proporcionar su propio comportamiento de eliminación o reemplazo de sufijos que anula los valores descritos aquí. Ver la documentación del sistema de completado en zshcompsys(1).
