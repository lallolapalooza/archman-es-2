NOMBRE

zshroadmap - introducción informal al manual de zsh El Manual de Zsh, como el propio shell, es grande y a menudo complicado. Esta sección del manual proporciona algunas indicaciones sobre áreas del shell que probablemente serán de particular interés para los nuevos usuarios, e indica dónde en el resto del manual se encuentra la documentación.

CUANDO ARRANCA EL SHELL

Cuando arranca, el shell lee comandos de varios archivos. Estos pueden ser creados o editados para personalizar el shell. Ver la sección Archivos de inicio/cierre en zsh(1).

Si no existen archivos de inicialización personales para el usuario actual, se ejecuta una función para ayudarle a cambiar algunas de las configuraciones más comunes. No aparecerá si su administrador ha deshabilitado el módulo zsh/newuser. La función está diseñada para ser autoexplicativa. Puede ejecutarla manualmente con `autoload -Uz zsh-newuser-install; zsh-newuser-install -f'. Ver también la sección `Funciones de configuración de usuario' en zshcontrib(1).

USO INTERACTIVO

La interacción con el shell utiliza el editor de línea incorporado de Zsh, ZLE. Esto se describe en detalle en zshzle(1).

La primera decisión que un usuario debe tomar es si usar el modo de edición Emacs o Vi, ya que las teclas para editar son sustancialmente diferentes. El modo de edición Emacs es probablemente más natural para los principiantes y puede seleccionarse explícitamente con el comando bindkey -e.

Hay disponible un mecanismo de historial para recuperar líneas escritas previamente (lo más sencillo con las teclas de flecha Arriba o Abajo); tenga en cuenta que, a diferencia de otros shells, zsh no guardará estas líneas cuando el shell salga a menos que establezca las variables apropiadas, y el número de líneas de historial retenidas por defecto es bastante pequeño (30 líneas). Ver la descripción de las variables de shell (referidas en la documentación como parámetros) HISTFILE, HISTSIZE y SAVEHIST en zshparam(1). Tenga en cuenta que actualmente solo es posible leer y escribir archivos que guardan el historial cuando el shell es interactivo, es decir, no funciona desde scripts.

El shell ahora soporta el conjunto de caracteres UTF-8 (y también otros si son soportados por el sistema operativo). Esto es (en su mayor parte) manejado transparentemente por el shell, pero el grado de soporte en los emuladores de terminal es variable. Hay una discusión sobre esto en la FAQ del shell, https://www.zsh.org/FAQ/. Tenga en cuenta en particular que para que los caracteres combinados sean manejados, la opción COMBINING_CHARS debe ser establecida. Debido a que el shell es ahora más sensible a la definición del conjunto de caracteres, tenga en cuenta que si está actualizando desde una versión anterior del shell, debería asegurarse de que la variable apropiada, ya sea LANG (para afectar a todos los aspectos de la operación del shell) o LC_CTYPE (para afectar solo al manejo de conjuntos de caracteres) esté establecida a un valor apropiado. Esto es cierto incluso si está utilizando un conjunto de caracteres de un solo byte, incluidas las extensiones de ASCII como ISO-8859-1 o ISO-8859-15. Ver la descripción de LC_CTYPE en zshparam(1).

Completado

El completado es una característica presente en muchos shells. Permite al usuario escribir solo una parte (generalmente el prefijo) de una palabra y que el shell complete el resto. El sistema de completado en zsh es programable. Por ejemplo, el shell puede configurarse para completar direcciones de correo electrónico en argumentos del comando mail desde su ~/.abook/addressbook; nombres de usuario, nombres de host e incluso rutas remotas en argumentos de scp, y así sucesivamente. Cualquier cosa que pueda escribirse o unirse con zsh puede ser la fuente de lo que el editor de línea ofrece como posibles completados.

Zsh tiene dos sistemas de completado, uno antiguo, llamado `compctl' (llamado así por el comando incorporado que sirve como su interfaz completa y única), y uno nuevo, al que se hace referencia como `compsys', organizado como una biblioteca de funciones incorporadas y definidas por el usuario. Los dos sistemas difieren en su interfaz para especificar el comportamiento de completado. El nuevo sistema es más personalizable y se suministra con completados para muchos comandos de uso común; por lo tanto, es preferible.

El sistema de completado debe habilitarse explícitamente cuando el shell arranca. Para más información ver zshcompsys(1).

Extender el editor de línea

Aparte del completado, el editor de línea es altamente extensible mediante funciones de shell. Algunas funciones útiles se proporcionan con el shell; proporcionan facilidades como:

insert-composed-char
componer caracteres que no se encuentran en el teclado
match-words-by-style
configurar qué considera el editor de línea como una palabra al moverse o eliminar por palabra
history-beginning-search-backward-end, etc.
formas alternativas de buscar en el historial del shell
replace-string, replace-pattern
funciones para reemplazar cadenas o patrones globalmente en la línea de comandos
edit-command-line
editar la línea de comandos con un editor externo.

Ver la sección `Funciones ZLE' en zshcontrib(1) para descripciones de estas.

OPCIONES

El shell tiene un gran número de opciones para cambiar su comportamiento. Estas cubren todos los aspectos del shell; explorar la documentación completa es la única forma buena de familiarizarse con las muchas posibilidades. Ver zshoptions(1).

COINCIDENCIA DE PATRONES

El shell tiene un rico conjunto de patrones que están disponibles para la coincidencia de archivos (descritos en la documentación como `generación de nombres de archivo' y también conocidos por razones históricas como `globbing') y para su uso al programar. Estos se describen en la sección `Generación de nombres de archivo' en zshexpn(1).

De particular interés son los siguientes patrones que no son comúnmente soportados por otros sistemas de coincidencia de patrones:

**
para coincidir en múltiples directorios
|
para coincidir con alguna de dos alternativas
~, ^
la capacidad de excluir patrones de la coincidencia cuando la opción EXTENDED_GLOB está establecida
(...)
calificadores de glob, incluidos entre paréntesis al final del patrón, que seleccionan archivos por tipo (como directorios) o atributo (como tamaño).

COMENTARIOS GENERALES SOBRE LA SINTAXIS

Aunque la sintaxis de zsh es en algunos aspectos similar a la del shell Korn, y por lo tanto más remotamente a la del shell UNIX original, el shell Bourne, su comportamiento por defecto no corresponde totalmente a esos shells. La sintaxis general del shell se introduce en la sección `Gramática del shell' en zshmisc(1).

Una diferencia que se encuentra comúnmente es que las variables sustituidas en la línea de comandos no se dividen en palabras. Ver la descripción de la opción de shell SH_WORD_SPLIT en la sección `Expansión de parámetros' en zshexpn(1). En zsh, puede solicitar explícitamente la división (p. ej., ${=foo}) o usar un array cuando quiere que una variable se expanda a más de una palabra. Ver la sección `Parámetros de array' en zshparam(1).

PROGRAMACIÓN

La forma más conveniente de agregar mejoras al shell es típicamente escribiendo una función de shell y organizando su carga automática. Las funciones se describen en la sección `Funciones' en zshmisc(1). Los usuarios que cambian del shell C y sus relativos deberían notar que los alias se usan menos en zsh ya que no realizan sustitución de argumentos, solo reemplazo de texto simple.

Cuando se inicia el shell, se lee el archivo ~/.zshrc. Si este archivo no existe, se intenta leer el archivo /etc/zshrc. Si existe el archivo ~/.zprofile, este se lee al final de la sesión de inicio de sesión. Si ~/.zlogin existe, este se lee al final de la sesión de inicio de sesión.

Los archivos ~/.zprofile y ~/.zlogin se leen solo en las sesiones de inicio de sesión.

/etc/zprofile, /etc/zshrc y /etc/zlogin son leídos por todas las cuentas de usuario si existen.

Si el shell se inicia interactivamente, se lee el archivo ~/.zshhistory para cargar el historial de comandos, y luego se lee ~/.zshrc. Al finalizar, se escribe el historial de comandos en ~/.zshhistory.

~/.zshenv se lee cada vez que se inicia un shell, ya sea interactiva o no interactivamente.

~/.zprofile, ~/.zshrc, ~/.zlogin, ~/.zlogout, ~/.zshenv, ~/.zhistory y ~/.zprofile se pueden omitir si se les antepone un guion (por ejemplo, ~/.zprofile).

Opciones:

  • -f: Deshabilita el procesamiento de archivos .zshrc.
  • -i: Fuerza la ejecución interactiva.
  • -t: Ejecuta los comandos de un archivo y sale.
  • -v: Imprime el nombre de cada archivo mientras se lee.
  • -x: Imprime cada comando después de la expansión.

Coincidencia de patrones:

El shell admite la coincidencia de patrones para nombres de archivos. Esto incluye:

  • *: Coincide con cualquier secuencia de caracteres.
  • ?: Coincide con un solo carácter.
  • [...]: Coincide con cualquiera de los caracteres dentro de los corchetes.
  • [!...] o [^...]: Coincide con cualquier carácter que no esté dentro de los corchetes.

Comentarios generales sobre la sintaxis:

El shell utiliza la sintaxis de comandos de shell estándar. Los comandos se separan por saltos de línea o punto y coma. Los comentarios comienzan con #.

Programación:

El shell admite una variedad de características de programación, incluyendo variables, bucles, condicionales y funciones.

promptinit
un sistema de temas de prompt para cambiar prompts fácilmente, ver la sección `Temas de Prompt'
zsh-mime-setup
un sistema de manejo de MIME que envía comandos según la extensión de un archivo, como lo hacen los administradores de archivos gráficos
zcalc
una calculadora
zargs
una versión de xargs que hace que el comando find sea redundante
zmv
un comando para renombrar archivos mediante patrones de shell.
