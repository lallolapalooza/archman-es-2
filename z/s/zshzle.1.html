NOMBRE

zshzle - editor de línea de comandos de zsh

DESCRIPCIÓN

Si la opción ZLE está activada (lo cual es por defecto en los shells interactivos) y la entrada del shell está conectada al terminal, el usuario puede editar las líneas de comando.

Hay dos modos de visualización. El primero, modo multilínea, es el predeterminado. Solo funciona si el parámetro TERM está configurado a un tipo de terminal válido que pueda mover el cursor hacia arriba. El segundo, modo de una sola línea, se utiliza si TERM es inválido o incapaz de mover el cursor hacia arriba, o si la opción SINGLE_LINE_ZLE está activada. Este modo es similar a ksh y no usa secuencias termcap. Si TERM es "emacs", la opción ZLE se desactivará por defecto.

Los parámetros BAUD, COLUMNS y LINES también son utilizados por el editor de línea. Consulte Parámetros Utilizados Por El Shell en zshparam(1).

El parámetro zle_highlight también es utilizado por el editor de línea; consulte Resaltado de Caracteres más abajo. El resaltado de caracteres especiales y la región entre el cursor y la marca (como se establece con set-mark-command en modo Emacs, o con visual-mode en modo Vi) está activado por defecto; consulte esta referencia para más información. Los conservadores irascibles desearán saber que todo el resaltado puede ser desactivado con la siguiente configuración:

zle_highlight=(none)

En muchos lugares, se hacen referencias al argumento numérico. Este puede ser introducido por defecto en modo emacs manteniendo presionada la tecla alt y escribiendo un número, o presionando escape antes de cada dígito, y en modo de comando vi escribiendo el número antes de introducir un comando. Generalmente el argumento numérico hace que el siguiente comando introducido se repita el número especificado de veces, a menos que se indique lo contrario abajo; esto es implementado por el widget digit-argument. Consulte también el subapartado Argumentos de la sección Widgets para algunas otras formas en que el argumento numérico puede ser modificado.

MAPAS DE TECLADO

Un mapa de teclado en ZLE contiene un conjunto de enlaces entre secuencias de teclas y comandos ZLE. La secuencia de teclas vacía no puede ser enlazada.

Puede haber cualquier número de mapas de teclado en cualquier momento, y cada mapa de teclado tiene uno o más nombres. Si todos los nombres de un mapa de teclado son eliminados, este desaparece. bindkey puede ser utilizado para manipular nombres de mapas de teclado.

Inicialmente, hay ocho mapas de teclado:

emacs
Emulación EMACS
viins
Emulación vi - modo inserción
vicmd
Emulación vi - modo comando
viopp
Emulación vi - operador pendiente
visual
Emulación vi - selección activa
isearch
Modo de búsqueda incremental
command
Leer un nombre de comando
.safe
Mapa de teclado de respaldo

El mapa de teclado `.safe' es especial. Nunca puede ser alterado, y su nombre nunca puede ser eliminado. Sin embargo, puede ser enlazado a otros nombres, que sí pueden ser eliminados. En el futuro podrían añadirse otros mapas de teclado especiales; los usuarios deben evitar usar nombres que comiencen con `.' para sus propios mapas de teclado.

Además de estos nombres, `emacs' o `viins' (o ambos) también están enlazados al nombre `main'. Si alguna de las variables de entorno VISUAL o EDITOR contiene la cadena `vi' cuando el shell se inicia, entonces será `viins'; de lo contrario, será `emacs'. Las opciones -e y -v de bindkey proporcionan una forma conveniente de anular esta elección predeterminada.

Cuando el editor se inicia, seleccionará el mapa de teclado `main'. Si ese mapa de teclado no existe, usará `.safe' en su lugar.

En el mapa de teclado `.safe', cada tecla individual está enlazada a self-insert, excepto ^J (salto de línea) y ^M (retorno), que están enlazados a accept-line. Esto es deliberadamente desagradable de usar; si lo está utilizando, significa que ha eliminado el mapa de teclado principal, y debería restaurarlo.

Lectura de Comandos

Cuando ZLE está leyendo un comando desde el terminal, puede leer una secuencia que esté enlazada a algún comando y que también sea un prefijo de una cadena enlazada más larga. En este caso, ZLE esperará un cierto tiempo para ver si se teclean más caracteres, y si no (o si no coinciden con ninguna cadena más larga) ejecutará el enlace. Este tiempo de espera está definido por el parámetro KEYTIMEOUT; su valor predeterminado es 0.4 segundos. No hay tiempo de espera si la cadena prefijo no está enlazada a un comando.

El tiempo de espera de teclas también se aplica cuando ZLE está leyendo los bytes de una cadena multibyte cuando está en el modo apropiado. (Esto requiere que el shell haya sido compilado con el modo multibyte habilitado; típicamente la locale también tiene caracteres con la codificación UTF-8, aunque se admite cualquier codificación multibyte conocida por el sistema operativo.) Si el segundo o un byte subsiguiente no se lee dentro del período de tiempo de espera, el shell actúa como si se hubiera tecleado ? y reinicia el estado de entrada.

Además de los comandos ZLE, las secuencias de teclas pueden ser enlazadas a otras cadenas, usando `bindkey -s'. Cuando se lee una secuencia de este tipo, la cadena de reemplazo se empuja de nuevo como entrada, y el proceso de lectura de comandos comienza de nuevo usando estas pulsaciones falsas. Esta entrada puede invocar a su vez cadenas de reemplazo adicionales, pero para detectar bucles, el proceso se detendrá si hay veinte reemplazos de este tipo sin que se lea un comando real.

Una secuencia de teclas tecleada por el usuario puede ser convertida en un nombre de comando para ser usado en widgets definidos por el usuario con el widget read-command, descrito en el subapartado `Miscelánea' de la sección `Widgets Estándar' más abajo.

Mapas de Teclado Locales

Mientras que para la edición normal se usa exclusivamente un solo mapa de teclado, en muchos modos un mapa de teclado local permite personalizar algunas teclas. Por ejemplo, en un modo de búsqueda incremental, un enlace en el mapa de teclado isearch anulará un enlace en el mapa de teclado main, pero todas las teclas que no sean anuladas aún podrán ser utilizadas.

Si una secuencia de teclas está definida en un mapa de teclado local, ocultará una secuencia de teclas en el mapa de teclado global que sea un prefijo de esa secuencia. Un ejemplo de esto ocurre con el enlace de iw en viopp, ya que esto oculta el enlace de i en vicmd. Sin embargo, una secuencia más larga en el mapa de teclado global que comparte el mismo prefijo aún puede aplicarse, por lo que, por ejemplo, el enlace de ^Xa en el mapa de teclado global no se verá afectado por el enlace de ^Xb en el mapa de teclado local.

COMANDOS INTEGRADOS ZLE

El módulo ZLE contiene tres comandos integrados relacionados. El comando bindkey manipula mapas de teclado y enlaces de teclas; el comando vared invoca ZLE sobre el valor de un parámetro del shell; y el comando zle manipula widgets de edición y permite el acceso a comandos ZLE desde dentro de funciones del shell.

bindkey [ opciones ] -d
bindkey [ opciones ] -D mapa-teclado ...
bindkey [ opciones ] -A mapa-teclado-antiguo mapa-teclado-nuevo
bindkey [ opciones ] -N mapa-teclado-nuevo [ mapa-teclado-antiguo ]
bindkey [ opciones ] -m
bindkey [ opciones ] -r cadena-entrada ...
bindkey [ opciones ] -s cadena-entrada cadena-salida ...
bindkey [ opciones ] cadena-entrada comando ...
bindkey [ opciones ] [ cadena-entrada ]
Las opciones de bindkey se pueden dividir en tres categorías: selección del mapa de teclado para el comando actual, selección de operación y otras. Las opciones de selección del mapa de teclado son:
-e
Selecciona el mapa de teclado `emacs' para cualquier operación por el comando actual, y también enlaza `emacs' a `main' para que sea seleccionado por defecto la próxima vez que el editor se inicie.
-v
Selecciona el mapa de teclado `viins' de la misma manera. Si una variable de entorno `VISUAL' o `EDITOR' se establece al inicio del shell y contiene `vi', entonces se usa `viins', de lo contrario se usa `emacs'.
-a
El mapa de teclado seleccionado se utiliza como un mapa de teclado local en lugar de un mapa de teclado global.
-k
Interpreta las cadenas de entrada como secuencias de teclas especiales (escape, control, etc.).
-M modo
Especifica el modo de selección: `-M main' (por defecto) selecciona el mapa de teclado principal; `-M local' selecciona el mapa de teclado local (si existe); `-M current' usa el mapa de teclado actualmente en uso. La opción `-M global' es igual a `-M main'.
-s
Las cadenas de entrada se interpretan como secuencias de teclas que serán reemplazadas por las cadenas de salida correspondientes. Esto se usa para la sustitución de macros.
-S
Similar a -s, pero las cadenas de salida se interpretan como secuencias de comandos ZLE en lugar de cadenas de texto simples. Esto permite vincular secuencias de teclas a comandos ZLE definidos por el usuario.
-f
Las cadenas de entrada se interpretan como nombres de widgets ZLE. Se establece un enlace para que al teclear la secuencia de entrada se invoque el widget especificado. Si no se proporciona un widget, se mostrará una lista de todos los widgets disponibles.
-r
Elimina todos los enlaces para las secuencias de entrada especificadas. Si no se especifican secuencias de entrada, se eliminan todos los enlaces del mapa de teclado seleccionado.
-l
Lista todos los mapas de teclado disponibles. Si se proporcionan nombres de mapas de teclado, lista los enlaces para esos mapas. Si se usa la opción -L, lista todos los nombres de mapas de teclado disponibles, incluyendo los no definidos actualmente.
-d
Restablece el mapa de teclado principal a sus valores predeterminados. Si se proporciona un nombre de mapa de teclado, restablece ese mapa.
-D mapa-teclado ...
Elimina los mapas de teclado especificados. Solo se pueden eliminar los mapas de teclado definidos por el usuario.
-A mapa-teclado-antiguo mapa-teclado-nuevo
Renombra un mapa de teclado. El mapa de teclado antiguo se renombra al nuevo nombre.
-N mapa-teclado-nuevo [ mapa-teclado-antiguo ]
Crea un nuevo mapa de teclado. Si se especifica un mapa de teclado antiguo, el nuevo mapa de teclado se copiará del antiguo. Si no se especifica, el nuevo mapa de teclado estará vacío.
-m
Muestra todos los mapas de teclado definidos y sus enlaces actuales.

vared [ opciones ] nombre-parametro

Invoca el editor ZLE para permitir la edición del valor de un parámetro del shell. Las opciones son:

-p
El valor del parámetro se muestra como una cadena fija, sin posibilidad de modificarla.
-c
La cadena de entrada se copia en el búfer de edición, pero el valor original del parámetro no se modifica hasta que se confirma la edición.
-e
El editor se inicia en modo Emacs.
-v
El editor se inicia en modo Vi.

zle [ opciones ] [ widget ... ]

El comando zle se utiliza para manipular widgets de edición y para acceder a comandos ZLE desde dentro de funciones del shell. Las opciones son:

-l
Lista todos los widgets ZLE disponibles.
-f
Permite definir un nuevo widget o modificar uno existente. Requiere especificar un nombre de widget y una secuencia de comandos ZLE.
-c widget
Copia el widget especificado a un nuevo widget (sin nombre).
-d widget
Elimina el widget especificado.
-r widget
Restablece el widget especificado a su valor predeterminado.
-m
Muestra información sobre el widget especificado (si se proporciona), o sobre todos los widgets si no se especifica ninguno.
-e mapa-teclado
Establece el mapa de teclado especificado como el mapa de teclado actual.
-a mapa-teclado-antiguo mapa-teclado-nuevo
Renombra un mapa de teclado.
-N mapa-teclado-nuevo [ mapa-teclado-antiguo ]
Crea un nuevo mapa de teclado.

Si se proporcionan nombres de widgets sin opciones, se invocan esos widgets.

WIDGETS

Los widgets son los comandos básicos de ZLE. Hay muchos widgets predefinidos para realizar diversas tareas de edición de línea de comandos. Algunos widgets comunes incluyen:

accept-line
Acepta la línea de comando actual y la ejecuta.
beginning-of-line
Mueve el cursor al principio de la línea.
end-of-line
Mueve el cursor al final de la línea.
forward-char
Mueve el cursor un carácter hacia adelante.
backward-char
Mueve el cursor un carácter hacia atrás.
kill-line
Borra la línea desde el cursor hasta el final.
yank
Pega el texto previamente borrado (cortado).
transpose-chars
Intercambia los dos caracteres alrededor del cursor.
uppercase-word
Convierte la palabra actual a mayúsculas.
delete-word
Borra la palabra actual.
complete
Realiza la compleción automática del comando o nombre de archivo.
history-search-backward
Busca hacia atrás en el historial de comandos basándose en la entrada actual.
self-insert
Inserta el carácter tecleado en la línea de comandos.

Los widgets pueden ser invocados directamente desde la línea de comandos usando el comando zle, o pueden ser enlazados a secuencias de teclas usando el comando bindkey.

Para más información sobre widgets específicos y sus argumentos, consulte la documentación de ZLE en la wiki de Arch Linux o la documentación en línea de zsh.

CARACTERES ESPECIALES

En la configuración predeterminada, ZLE resalta ciertos caracteres y el texto entre el cursor y la marca. La personalización del resaltado se realiza a través del parámetro zle_highlight. La configuración predeterminada es la siguiente:

zle_highlight=(root 'none' \
              command‐arg 'none' \
              command‐char 'none' \
              command‐word 'none' \
              cursor 'none' \
              cursor‐word 'none' \
              history‐line 'none' \
              history‐search ‘none’ \
              line‐editing ‘none’ \
              menu‐complete ‘none’ \
              path ‘none’ \
              path‐arg ‘none’ \
              path‐paren ‘none’ \
              quoted ‘none’ \
              region ‘none’ \
              selection ‘none’ \
              space ‘none’ \
              substitution ‘none’ \
              word ‘none’)

Para desactivar todo el resaltado, establezca:

zle_highlight=(none)

Consulte la documentación de zsh para obtener una lista completa de las categorías de resaltado y sus significados.

ARGUMENTOS NUMERICOS

La mayoría de los widgets de ZLE pueden ser previsualizados con un argumento numérico. Este argumento puede ser introducido de varias maneras, dependiendo del modo del editor:

  • En modo Emacs: mantenga presionada la tecla Alt y escriba los dígitos, o presione Escape antes de cada dígito.
  • En modo Vi: en modo de comando, escriba los dígitos antes de la tecla del comando.

El argumento numérico generalmente se utiliza para repetir la acción del widget el número especificado de veces. Por ejemplo, si se introduce el argumento numérico 5 y luego se presiona la tecla de avance de carácter (normalmente Ctrl+F en modo Emacs o `l' en modo Vi), el cursor se moverá cinco caracteres hacia adelante.

Consulte la sección Argumentos de la página del manual de ZLE para obtener más detalles sobre cómo se manejan los argumentos numéricos y cómo se pueden modificar.

-m

-r cadena-entrada ...
Desvincula las cadena-entrada especificadas en el mapa de teclas seleccionado. Esto es exactamente equivalente a vincular las cadenas a undefined-key.

Cuando también se usa -R, interpreta las cadena-entrada como rangos.

Cuando también se usa -p, las cadena-entrada especifican prefijos. Se eliminará cualquier enlace que tenga la cadena-entrada dada como prefijo, sin incluir el enlace para la propia cadena-entrada, si lo hay. Por ejemplo,

bindkey -rpM viins '^['

eliminará todos los enlaces en el mapa de teclas vi-insert que comiencen con un carácter de escape (probablemente teclas de cursor), pero dejará el enlace para el propio carácter de escape (probablemente vi-cmd-mode). Esto es incompatible con la opción -R.

-s cadena-entrada cadena-salida ...
Vincula cada cadena-entrada a cada cadena-salida. Cuando se teclea cadena-entrada, cadena-salida se empujará hacia atrás y se tratará como entrada para el editor de línea. Cuando también se usa -R, interpreta las cadena-entrada como rangos.

Tenga en cuenta que tanto cadena-entrada como cadena-salida están sujetas a la misma forma de interpretación, como se describe a continuación.

[ cadena-entrada ]

De lo contrario, se muestran todos los enlaces de teclas en el mapa de teclas seleccionado. (Como caso especial, si la opción -e o -v se usa sola, el mapa de teclas no se muestra; el enlace implícito de los mapas de teclas es lo único que sucede).

El valor del parámetro nombre se carga en el búfer de edición, y se invoca el editor de línea. Cuando el editor sale, nombre se establece en el valor de cadena devuelto por el editor. Cuando se proporciona la bandera -c, el parámetro se crea si aún no existe. La bandera -a puede proporcionarse con -c para crear un parámetro de arreglo, o la bandera -A para crear un arreglo asociativo. Si el tipo de un parámetro existente no coincide con el tipo que se va a crear, el parámetro se anula y se recrea. La bandera -g puede proporcionarse para suprimir advertencias de las opciones WARN_CREATE_GLOBAL y WARN_NESTED_VAR.

Si se está editando un arreglo o una porción de arreglo, los caracteres separadores definidos en $IFS se mostrarán entre comillas invertidas, al igual que las propias barras invertidas. A la inversa, cuando el texto editado se divide en un arreglo, una barra invertida cita un carácter separador o barra invertida inmediatamente posterior; no se realiza ningún otro manejo especial de barras invertidas ni ningún manejo de comillas.

Se pueden editar elementos individuales de arreglos o arreglos asociativos existentes utilizando la sintaxis de subíndice en nombre. Los nuevos elementos se crean automáticamente, incluso sin -c.

Si se proporciona la bandera -p, la siguiente cadena se tomará como el mensaje que se mostrará a la izquierda. Si se proporciona la bandera -r, la siguiente cadena proporciona el mensaje que se mostrará a la derecha. Si se especifica la bandera -h, el historial se puede acceder desde ZLE. Si se proporciona la bandera -e, al teclear ^D (Control-D) en una línea vacía, vared sale inmediatamente con un valor de retorno distinto de cero.

La opción -M proporciona un mapa de teclas para enlazar a main durante la edición, y la opción -m proporciona un mapa de teclas para enlazar a vicmd durante la edición. Para la edición al estilo vi, esto permite que un par de mapas de teclas anulen viins y vicmd. Para la edición al estilo emacs, normalmente solo se necesita -M, pero la opción -m aún puede usarse. Al salir, se restaurarán los mapas de teclas anteriores.

Vared llama a los ganchos habituales `zle-line-init' y `zle-line-finish' antes y después de tomar el control. Utilizando las opciones -i y -f, es posible reemplazarlos por otros widgets personalizados.

Si se proporciona `-t terminal', terminal es el nombre de un dispositivo de terminal que se utilizará en lugar del predeterminado /dev/tty. Si terminal no se refiere a una terminal, se informará un error.

El comando interno zle realiza una serie de acciones diferentes relacionadas con ZLE.

Sin opciones ni argumentos, solo se establecerá el estado de retorno. Es cero si ZLE está activo actualmente y los widgets podrían invocarse utilizando este comando interno y distinto de cero en caso contrario. Tenga en cuenta que incluso si se devuelve un estado distinto de cero, zle todavía puede estar activo como parte del sistema de compleción; esto no permite llamadas directas a widgets de ZLE.

De lo contrario, la operación que realiza depende de sus opciones:

-l [ -L | -a ] [ string ]
Lista todos los widgets definidos por el usuario existentes. Si se utiliza la opción -L, se lista en forma de comandos zle para crear los widgets.

Cuando se combina con la opción -a, se enumeran todos los nombres de widgets, incluidos los integrados. En este caso, la opción -L se ignora.

Si se proporciona al menos una string y está presente -a o -L no se utiliza, no se imprimirá nada. El estado de retorno será cero si todas las strings son nombres de widgets existentes y distinto de cero si al menos una string no es el nombre de un widget definido. Si también está presente -a, se utilizan todos los nombres de widgets para la comparación, incluidos los widgets integrados; de lo contrario, solo se utilizan los widgets definidos por el usuario.

Si está presente al menos una string y se utiliza la opción -L, se enumeran los widgets definidos por el usuario que coinciden con cualquier string en forma de comandos zle para crear los widgets.

-D widget ...
Elimina los widgets con nombre.
-A old-widget new-widget
Hace que el nombre new-widget sea un alias para old-widget, de modo que ambos nombres se refieren al mismo widget. Los nombres tienen el mismo peso; si alguno se elimina, el otro permanece. Si ya existe un widget con el nombre new-widget, se elimina.
-N widget [ function ]
Crea un widget definido por el usuario. Si ya existe un widget con el nombre especificado, se sobrescribe. Cuando el nuevo widget se invoca desde el editor, se llama a la function de shell especificada. Si no se especifica ningún nombre de función, se utiliza por defecto el mismo nombre que el del widget. Para más información, véase la sección `Widgets' a continuación.
-f flag [ flag... ]
Establece varias marcas en el widget en ejecución. Los valores posibles para flag son:

yank para indicar que el widget ha copiado texto en el búfer. Si el widget envuelve un widget interno existente, no es necesaria ninguna acción adicional, pero si ha insertado el texto manualmente, también debe asegurarse de establecer YANK_START y YANK_END correctamente. yankbefore hace lo mismo pero se utiliza cuando el texto copiado aparece después del cursor.

kill para indicar que el texto ha sido cortado en el búfer de corte. Al invocar repetidamente un widget de corte, el texto se agrega al búfer de corte en lugar de reemplazarlo, pero al envolver dichos widgets, es necesario llamar a `zle -f kill' para mantener este efecto.

vichange para indicar que el widget representa un cambio vi que se puede repetir en su totalidad con `vi-repeat-change'. La marca debe establecerse al principio de la función antes de inspeccionar el valor de NUMERIC o invocar otros widgets. Esto no tiene ningún efecto para un widget invocado desde el modo de inserción. Si el modo de inserción está activo cuando finaliza el widget, el cambio se extiende hasta el próximo regreso al modo de comando.

-C widget completion-widget function
Crea un widget de compleción definido por el usuario llamado widget. El widget de compleción se comportará como el widget de compleción integrado cuyo nombre se proporciona como completion-widget. Para generar las compleciones, se llamará a la función de shell function. Para más información, véase zshcompwid(1).
-R [ -c ] [ display-string ] [ string ... ]
Vuelve a mostrar la línea de comandos. Si se proporciona una display-string y no está vacía, se mostrará en la línea de estado (inmediatamente debajo de la línea que se está editando).

Si se proporcionan las strings opcionales, se enumeran debajo del prompt de la misma manera que se imprimen las listas de compleción. Si no se proporcionan strings pero se utiliza la opción -c, se borra dicha lista.

Tenga en cuenta que inmediatamente después de regresar de ejecutar widgets, la línea de comandos se volverá a mostrar y se borrarán las cadenas mostradas. Por lo tanto, este comando solo es útil para widgets que no salen inmediatamente después de usarlo.

Este comando se puede llamar de forma segura fuera de los widgets definidos por el usuario; si zle está activo, se actualizará la pantalla, mientras que si zle no está activo, el comando no tendrá ningún efecto. En este caso, normalmente no habrá otros argumentos.

El estado es cero si zle estaba activo, de lo contrario uno.

-M string
Al igual que con la opción -R, la string se mostrará debajo de la línea de comandos; a diferencia de la opción -R, la cadena no se colocará en la línea de estado, sino que se imprimirá normalmente debajo del prompt. Esto significa que la string seguirá mostrándose después de que el widget regrese (hasta que sea sobrescrita por comandos posteriores).
-U string
Esto introduce los caracteres de la string en la pila de entrada de ZLE. Después de que el widget que se está ejecutando actualmente finalice, ZLE se comportará como si los caracteres de la string hubieran sido escritos por el usuario.

Como ZLE utiliza una pila, si esta opción se utiliza repetidamente, la última cadena introducida en la pila se procesará primero. Sin embargo, los caracteres de cada string se procesarán en el orden en que aparecen en la cadena.

-K keymap
Selecciona el mapa de teclas llamado keymap. Se mostrará un mensaje de error si no existe dicho mapa de teclas.

Esta selección de mapa de teclas afecta la interpretación de las pulsaciones de teclas siguientes dentro de esta invocación de ZLE. Cualquier invocación posterior (por ejemplo, la siguiente línea de comandos) comenzará como de costumbre con el mapa de teclas `main' seleccionado.

-F [ -L | -w ] [ fd [ handler ] ]
Solo disponible si su sistema admite una de las llamadas al sistema `poll' o `select'; la mayoría de los sistemas modernos lo hacen.

Instala handler (el nombre de una función de shell) para manejar la entrada del descriptor de archivo fd. Instalar un manejador para un fd que ya está siendo manejado reemplaza el manejador existente. Se puede instalar cualquier número de manejadores para cualquier número de descriptores de archivo legibles. Tenga en cuenta que zle no intenta verificar si este fd es realmente legible al instalar el manejador. El usuario debe hacer sus propios arreglos para manejar el descriptor de archivo cuando zle no está activo.

Cuando zle intenta leer datos, examinará tanto la terminal como la lista de fds manejados. Si hay datos disponibles en un fd manejado, zle llama a handler con el fd que está listo para leer como primer argumento. En circunstancias normales, este es el único argumento, pero si se detectó un error, un segundo argumento proporciona detalles: `hup' para una desconexión, `nval' para un descriptor cerrado o inválido, o `err' para cualquier otra condición. Los sistemas que solo admiten la llamada al sistema `select' siempre utilizan `err'.

Si también se proporciona la opción -w, el handler es en su lugar un widget de editor de líneas, típicamente una función de shell convertida en widget usando `zle -N'. En ese caso, handler puede usar todas las facilidades de zle para actualizar la línea de edición actual. Tenga en cuenta, sin embargo, que como el manejo de fd se lleva a cabo a bajo nivel, los cambios en la pantalla no aparecerán automáticamente; el widget debería llamar a `zle -R' para forzar la redisplay. En el momento de escribir esto, los manejadores de widgets solo admiten un único argumento y, por lo tanto, nunca se les pasa una cadena para el estado de error, por lo que los widgets deben estar preparados para probar el descriptor ellos mismos.

Si algún tipo de manejador produce salida a la terminal, debería llamar a `zle -I' antes de hacerlo (ver más abajo). Los manejadores no deben intentar leer de la terminal.

Si no se proporciona handler, pero se proporciona un fd, se elimina cualquier manejador para ese fd. Si no hay ninguno, se imprime un mensaje de error y se devuelve el estado 1.

Si no se proporcionan argumentos, o se suministra la opción -L, se imprime una lista de manejadores en un formato que se puede almacenar para su posterior ejecución.

Opcionalmente, se puede proporcionar un fd (pero no un handler) con la opción -L; en este caso, la función enumerará el manejador si existe, de lo contrario, devolverá silenciosamente el estado 1.

Tenga en cuenta que esta característica debe usarse con cuidado. La actividad en uno de los fds que no se maneja correctamente puede hacer que la terminal se vuelva inutilizable. Eliminar un manejador de fd dentro de una trampa de señales puede causar un comportamiento impredecible.

Un desplazamiento de inicio en las mismas unidades que CURSOR.
•
Un desplazamiento de fin en las mismas unidades que CURSOR.
•
Una especificación de resaltado en el mismo formato que se usa para los contextos en el parámetro zle_highlight, ver la sección `Resaltado de caracteres' a continuación; por ejemplo, standout o fg=red,bold.
•
Opcionalmente, una cadena de la forma `memo=token'. El token consta de todo lo que hay entre el `=' y el siguiente espacio en blanco, coma, NUL o el final de la cadena. El token se conserva textualmente pero no se analiza de ninguna manera.

Los plugins pueden usar esto para identificar los elementos del array que han añadido: por ejemplo, un plugin podría establecer token en su nombre (el del plugin) y luego usar `region_highlight=( ${region_highlight:#*memo=token} )' para eliminar los elementos del array que ha añadido.

(Este ejemplo utiliza la sintaxis de búsqueda de arrays `${nombre:#patrón}' descrita en la sección `Expansión de parámetros' en zshexpn(1).)

Por ejemplo,

region_highlight=("P0 20 bold memo=foobar")

especifica que los primeros veinte caracteres del texto, incluido cualquier cadena de previsualización, deben resaltarse en negrita.

Tenga en cuenta que el efecto de region_highlight no se guarda y desaparece tan pronto como se acepta la línea.

Tenga en cuenta que zsh 5.8 y anteriores no admiten el campo `memo=token' y pueden analizar incorrectamente el tercer campo (especificación de resaltado) cuando se proporciona una nota.

El resaltado final en la línea de comandos depende tanto de region_highlight como de zle_highlight; ver la sección RESALTADO DE CARACTERES a continuación para más detalles.

zle insert-last-word -- -1 1 -

}

zle -A accept-line caps-lock

RESALTADO DE CARACTERES

El editor de línea tiene la capacidad de resaltar caracteres o regiones de la línea que tienen un significado particular. Esto se controla mediante el parámetro de matriz zle_highlight, si ha sido establecido por el usuario.

Si el parámetro contiene la entrada única none, se desactiva todo el resaltado. Tenga en cuenta que todavía se espera que el parámetro sea una matriz.

De lo contrario, cada entrada de la matriz debe consistir en una palabra que indique un contexto para el resaltado, seguida de dos puntos, luego una lista separada por comas de los tipos de resaltado que se aplicarán en ese contexto.

Los contextos disponibles para el resaltado son los siguientes:

default
Cualquier texto dentro de la línea de comandos que no se vea afectado por ningún otro resaltado. El texto fuera del área editable de la línea de comandos no se ve afectado.
isearch
Cuando uno de los widgets de búsqueda incremental de historial está activo, el área de la línea de comandos que coincide con la cadena o el patrón de búsqueda.
region
El texto actualmente seleccionado. En terminología de emacs, esto se denomina la región y está delimitada por el cursor (punto) y la marca. La región solo se resalta si está activa, que es el caso después de modificar la marca con set-mark-command o exchange-point-and-mark. Tenga en cuenta que si la región está activa o no, no afecta su uso dentro de widgets de estilo emacs, simplemente determina si se resalta. En modo vi, la región corresponde al texto seleccionado en modo visual.
special
Caracteres individuales que no tienen una representación imprimible directa, pero que son mostrados de manera especial por el editor de línea. Estos caracteres se describen a continuación.
suffix
Este contexto se utiliza en la compleción para caracteres que se marcan como sufijos que se eliminarán si la compleción termina en ese punto, el ejemplo más obvio es una barra (/) después de un nombre de directorio. Tenga en cuenta que la eliminación de sufijos es configurable; las circunstancias bajo las cuales se eliminará el sufijo pueden diferir para diferentes compleciones.
paste
Después de un comando para pegar texto, los caracteres que se insertaron.

Cuando se establece region_highlight, primero se aplican los contextos que describen una región —isearch, region, suffix y paste—, luego se aplica region_highlight, y finalmente se aplican los contextos restantes de zle_highlight. Si un carácter particular se ve afectado por múltiples especificaciones, la última especificación prevalece.

zle_highlight puede contener campos adicionales para controlar cómo se generan las secuencias de terminal para cambiar los colores. Cada uno de los siguientes va seguido de dos puntos y una cadena en el mismo formato que para los atajos de teclado. NAME

zshzle — zsh line editor

DESCRIPTION

This manual page describes the Zsh Line Editor (ZLE) built into zsh. ZLE is a powerful line editor that is used to edit the command line when zsh is running in interactive mode.

ZLE is driven by keymaps, which are collections of key bindings. Each key binding maps a sequence of keystrokes to a ZLE widget. ZLE widgets are the commands that perform editing operations, such as inserting text, moving the cursor, deleting text, or executing shell commands.

ZLE can be configured to use different keymaps, and users can define their own keymaps and key bindings.

KEYMAPS

ZLE uses keymaps to interpret keystrokes. The most common keymaps are:

emacs
This keymap is based on the Emacs editor. It is the default keymap if zsh is started with the -e option.
vi
This keymap is based on the vi editor. It is the default keymap if zsh is started with the -v option.

The current keymap can be changed using the bindkey builtin command.

ZLE BUILTINS

ZLE provides a number of built-in commands (widgets) that can be used to perform editing operations. Some of the most common ZLE widgets include:

backward-char
Move the cursor one character backward.
forward-char
Move the cursor one character forward.
backward-word
Move the cursor one word backward.
forward-word
Move the cursor one word forward.
kill-line
Delete the characters from the cursor to the beginning of the line.
kill-word
Delete the characters from the cursor to the beginning of the word.
yank
Insert the most recently killed text at the cursor position.
accept-line
Accept the current line and execute it.
abort
Abort the current command line.

ZLE WIDGETS

ZLE widgets are functions that perform editing operations. Users can define their own ZLE widgets using the zle builtin command.

For example, the following command defines a new widget called delete-word that deletes the word at the cursor:

zle -N delete-word delete-word

This widget can then be bound to a key sequence using the bindkey builtin command.

USER-DEFINED WIDGETS

Users can define their own ZLE widgets to customize the line editor to their needs. This is done using the zle -N command, followed by the widget name and the name of the shell function that implements the widget.

The shell function should accept one argument, which is the name of the widget being called. The function can then use ZLE builtins and other shell commands to perform the desired editing operation.

STANDARD WIDGETS

ZLE provides a large number of standard widgets for common editing tasks. These widgets can be viewed using the bindkey builtin command without any arguments.

CHARACTER HIGHLIGHTING

ZLE can highlight certain characters on the command line to provide visual feedback to the user. This highlighting is controlled by the zle_highlight associative array.

The keys of the zle_highlight array specify the type of character to be highlighted, and the values specify the highlighting attributes. The following character types are supported:

region
This is used to highlight the region selected by the user, e.g. when using the mouse to select text.
special
This is used to highlight special characters, such as control characters and non-printable characters.
suffix
This is used to highlight the suffix of a word when using completion.
isearch
This is used to highlight the characters being searched for during an incremental search.
paste
This is used to highlight characters that were just pasted into the buffer.
double-width
This is used to highlight double-width characters. Double-width characters are characters that occupy two character cells on the screen, such as many CJK characters. They are presented as two hexadecimal digits between angle brackets, as distinct from the four or eight digits that are used for unprintable characters that are nonetheless valid in the current character set.

Not all systems support this: for it to work, the system's representation of wide characters must be code values from the Universal Character Set, as defined by IS0 10646 (also known as Unicode).

Wrapped double-width characters
When a double-width character appears in the final column of a line, it is instead shown on the next line. The empty space left in the original position is highlighted as a special character.

If zle_highlight is not set or no value applies to a particular context, the defaults applied are equivalent to

zle_highlight=(region:standout special:standout
suffix:bold isearch:underline paste:standout)

i.e. both the region and special characters are shown in standout mode.

Within widgets, arbitrary regions may be highlighted by setting the special array parameter region_highlight; see above.
