NOMBRE

zshmisc - todo y algo más

COMANDOS SIMPLES & TUBO

Un comando simple es una secuencia de asignaciones de parámetros opcionales seguidas de palabras separadas por espacios en blanco, con redirecciones opcionales intercaladas. Para una descripción de la asignación, véase el principio de zshparam(1).

La primera palabra es el comando que se ejecutará, y las palabras restantes, si las hay, son argumentos para el comando. Si se da un nombre de comando, las asignaciones de parámetros modifican el entorno del comando cuando se ejecuta. El valor de un comando simple es su estado de salida, o 128 más el número de señal si fue terminado por una señal. Por ejemplo,

echo foo

es un comando simple con argumentos.

Un tubo (pipeline) es un comando simple, o una secuencia de dos o más comandos simples donde cada comando está separado del siguiente por `|' o `|&'. Donde los comandos están separados por `|', la salida estándar del primer comando se conecta a la entrada estándar del siguiente. `|&' es una abreviatura de `2>&1 |', que conecta tanto la salida estándar como el error estándar del comando a la entrada estándar del siguiente. El valor de un tubo es el valor del último comando, a menos que el tubo vaya precedido por `!', en cuyo caso el valor es la inversión lógica del valor del último comando. Por ejemplo,

echo foo | sed 's/foo/bar/'

es un tubo, donde la salida (`foo' más una nueva línea) del primer comando se pasará a la entrada del segundo.

Si un tubo va precedido por `coproc', se ejecuta como un coproceso; se establece un tubo bidireccional entre él y el shell principal. El shell puede leer o escribir en el coproceso mediante los operadores de redirección `>&p' y `<&p' o con `print -p' y `read -p'. Un tubo no puede ir precedido tanto por `coproc' como por `!'. Si el control de trabajos está activo, el coproceso puede tratarse, aparte de la entrada y salida, como un trabajo de fondo ordinario.

Una sublista es un tubo individual, o una secuencia de dos o más tubos separados por `&&' o `||'. Si dos tubos están separados por `&&', el segundo tubo se ejecuta solo si el primero tiene éxito (devuelve un estado cero). Si dos tubos están separados por `||', el segundo se ejecuta solo si el primero falla (devuelve un estado distinto de cero). Ambos operadores tienen la misma precedencia y son asociativos por la izquierda. El valor de la sublista es el valor del último tubo ejecutado. Por ejemplo,

dmesg | grep panic && print yes

es una sublista que consiste en dos tubos, el segundo es solo un comando simple que se ejecutará si y solo si el comando grep devuelve un estado cero. Si no lo hace, el valor de la sublista es ese estado de retorno, de lo contrario, es el estado devuelto por print (casi seguro cero).

Una lista es una secuencia de cero o más sublistas, en la que cada sublista está terminada por `;', `&', `&|', `&!', o una nueva línea. Este terminador puede omitirse opcionalmente de la última sublista cuando la lista aparece como un comando complejo dentro de `(...)' o `{...}'. Cuando una sublista termina con `;' o nueva línea, el shell espera a que termine antes de ejecutar la siguiente sublista. Si una sublista termina con `&', `&|', o `&!', el shell ejecuta el último tubo en segundo plano y no espera a que termine (tenga en cuenta la diferencia con otros shells que ejecutan toda la sublista en segundo plano). Un tubo en segundo plano devuelve un estado cero.

Más generalmente, una lista puede verse como un conjunto de cualquier comando del shell, incluidos los comandos complejos a continuación; esto se implica dondequiera que aparezca la palabra `lista' en descripciones posteriores. Por ejemplo, los comandos en una función de shell forman un tipo especial de lista.

MODIFICADORES DE PRECOMANDO

Un comando simple puede ir precedido por un modificador de precomando, que alterará cómo se interpreta el comando. Estos modificadores son comandos incorporados del shell con la excepción de nocorrect que es una palabra reservada.

-
El comando se ejecuta con un `-' antepuesto a su cadena argv[0].
builtin
La palabra del comando se toma como el nombre de un comando incorporado, en lugar de una función del shell o un comando externo.
command [ -pvV ]
La palabra del comando se toma como el nombre de un comando externo, en lugar de una función del shell o un comando incorporado. Si la opción POSIX_BUILTINS está configurada, los comandos incorporados también se ejecutarán, pero ciertas propiedades especiales de ellos se suprimen. El flag -p hace que se busque una ruta predeterminada en lugar de la de $path. Con el flag -v, command es similar a whence y con -V, es equivalente a whence -v.
exec [ -cl ] [ -a argv0 ]
El comando siguiente junto con cualquier argumento se ejecuta en lugar del proceso actual, en lugar de como un subproceso. El shell no se bifurca y es reemplazado. El shell no invoca TRAPEXIT, ni incluye los archivos zlogout. Las opciones se proporcionan para compatibilidad con otros shells.

La opción -c limpia el entorno.

La opción -l es equivalente al modificador de precomando -, para tratar el comando de reemplazo como un shell de inicio de sesión; el comando se ejecuta con un - antepuesto a su cadena argv[0]. Este flag no tiene efecto si se usa junto con la opción -a.

La opción -a se utiliza para especificar explícitamente la cadena argv[0] (el nombre del comando tal como lo ve el propio proceso) que debe utilizar el comando de reemplazo y es directamente equivalente a establecer un valor para la variable de entorno ARGV0.

nocorrect
La corrección ortográfica no se realiza en ninguna de las palabras. Esto debe aparecer antes de cualquier otro modificador de precomando, ya que se interpreta inmediatamente, antes de que se realice cualquier análisis. No tiene efecto en shells no interactivos.
noglob
La generación de nombres de archivo (globbing) no se realiza en ninguna de las palabras.

COMANDOS COMPLEJOS

Un comando complejo en zsh es uno de los siguientes:

if lista then lista [ elif lista then lista ] ... [ else lista ] fi
Se ejecuta la lista if, y si devuelve un estado de salida cero, se ejecuta la lista then. De lo contrario, se ejecuta la lista elif y si su estado es cero, se ejecuta la lista then. Si cada lista elif devuelve un estado distinto de cero, se ejecuta la lista else.
for nombre ... [ in palabra ... ] terminador do lista done
Expande la lista de palabras, y establece el parámetro nombre a cada una de ellas en turno, ejecutando lista cada vez. Si se omite el `in palabra', se usan los parámetros posicionales en lugar de las palabras.

El terminador consiste en una o más nuevas líneas o ; que terminan las palabras, y son opcionales cuando se omite el `in palabra'.

Puede aparecer más de un parámetro nombre antes de la lista de palabras. Si se dan N nombres, entonces en cada ejecución del bucle las siguientes N palabras se asignan a los parámetros correspondientes. Si hay más nombres que palabras restantes, los parámetros restantes se establecen cada uno a la cadena vacía. La ejecución del bucle termina cuando no queda ninguna palabra para asignar al primer nombre. Solo es posible que in aparezca como el primer nombre de la lista, de lo contrario se tratará como la marca del final de la lista.

for (( expresión-inicial ; condición ; expresión-incremento )) do lista done
Ejecuta el bloque lista repetidamente mientras la condición sea verdadera. La expresión-inicial se evalúa una vez antes de comenzar el bucle. La expresión-incremento se evalúa después de cada ejecución del bloque lista. Las tres expresiones se evalúan según las reglas de la aritmética entera de zsh.

COMANDOS DE FLUJO DE CONTROL

for name [ [ in word ... ] ; ] list done
for name [ [ in word ... ] ; ] list done
El name se establece en cada uno de los words en la secuencia, y list se ejecuta. Si se omite la palabra clave in, el comando for itera sobre los parámetros posicionales. El comando for puede ser anidado. La palabra clave do puede usarse en lugar de la primera palabra clave ;.
while list do list done
Ejecuta la list do mientras la list while devuelva un estado de salida cero.
until list do list done
Ejecuta la list do mientras la list until devuelva un estado de salida distinto de cero.
repeat word do list done
word se expande y se trata como una expresión aritmética, que debe evaluarse a un número n. Luego, list se ejecuta n veces.

La sintaxis repeat está deshabilitada por defecto cuando el shell se inicia en un modo que emula otro shell. Se puede habilitar con el comando `enable -r repeat'

case word in [ [(] pattern [ | pattern ] ... ) list (;;|;&|;|) ] ... esac
Ejecuta la list asociada con el primer pattern que coincide con word, si lo hay. La forma de los patrones es la misma que se utiliza para la generación de nombres de archivo. Consulte la sección `Generación de Nombres de Archivo'.

Tenga en cuenta además que, a menos que la opción SH_GLOB esté configurada, el patrón completo con alternativas es tratado por el shell como equivalente a un grupo de patrones entre paréntesis, aunque puede aparecer espacio en blanco alrededor de los paréntesis y la barra vertical, y se eliminará del patrón en esos puntos. El espacio en blanco puede aparecer en otros lugares del patrón; esto no se elimina. Si la opción SH_GLOB está configurada, de modo que un paréntesis de apertura pueda tratarse inequívocamente como parte de la sintaxis del caso, la expresión se analiza en palabras separadas y estas se tratan como alternativas estrictas (como en otros shells).

Si la list que se ejecuta termina con ;& en lugar de ;;, la siguiente lista también se ejecuta. La regla para el terminador de la siguiente lista ;;, ;& o ;| se aplica a menos que se alcance el esac.

Si la list que se ejecuta termina con ;|, el shell continúa buscando el siguiente patrón coincidente, ejecutando la list correspondiente y aplicando la regla para el terminador correspondiente ;;, ;& o ;|. Tenga en cuenta que word no se expande de nuevo; todos los patterns aplicables se prueban con la misma word.

select name [ in word ... term ] do list done
donde term es uno o más saltos de línea o ; para terminar los words. Imprime el conjunto de words, cada uno precedido por un número. Si se omite el in word, se utilizan los parámetros posicionales. Se imprime el prompt PROMPT3 y se lee una línea del editor de línea si el shell es interactivo y este está activo, o de lo contrario, la entrada estándar. Si esta línea consta del número de uno de los words listados, entonces el parámetro name se establece en el word correspondiente a este número. Si esta línea está vacía, la lista de selección se imprime de nuevo. De lo contrario, el valor del parámetro name se establece como nulo. El contenido de la línea leída de la entrada estándar se guarda en el parámetro REPLY. list se ejecuta para cada selección hasta que se encuentre un break o fin de archivo.
( list )
Ejecuta list en un subshell. Las trampas establecidas por el builtin trap se restablecen a sus valores predeterminados mientras se ejecuta list; una excepción es que las señales ignoradas seguirán siendo ignoradas si la opción POSIXTRAPS está configurada.
{ list }
Ejecuta list.
{ try-list } always { always-list }
Primero ejecuta try-list. Independientemente de los errores, o de los comandos break o continue encontrados dentro de try-list, ejecuta always-list. La ejecución continúa a partir del resultado de la ejecución de try-list; en otras palabras, cualquier error, o comando break o continue se trata de la manera normal, como si always-list no estuviera presente. Los dos fragmentos de código se denominan `bloque try' y `bloque always'.

Pueden aparecer saltos de línea o puntos y comas opcionales después de always; tenga en cuenta, sin embargo, que *no* pueden aparecer entre el corchete de cierre anterior y always.

Un `error' en este contexto es una condición como un error de sintaxis que hace que el shell aborte la ejecución de la función actual, script o lista. Los errores de sintaxis encontrados mientras el shell está analizando el código no hacen que se ejecute always-list. Por ejemplo, un bloque if construido erróneamente en try-list haría que el shell abortara durante el análisis, por lo que always-list no se ejecutaría, mientras que una sustitución errónea como ${*foo*} causaría un error en tiempo de ejecución, después del cual se ejecutaría always-list.

Una condición de error puede probarse y restablecerse con la variable entera especial TRY_BLOCK_ERROR. Fuera de una always-list, el valor es irrelevante, pero se inicializa a -1. Dentro de always-list, el valor es 1 si ocurrió un error en try-list, de lo contrario 0. Si se establece TRY_BLOCK_ERROR en 0 durante always-list, la condición de error causada por try-list se restablece y la ejecución del shell continúa normalmente después del final de always-list. Alterar el valor durante try-list no es útil (a menos que forme parte de un bloque always envolvente).

Independientemente de TRY_BLOCK_ERROR, después del final de always-list, el estado normal del shell $? es el valor devuelto por try-list. Este será distinto de cero si hubo un error, incluso si TRY_BLOCK_ERROR se estableció en cero.

Lo siguiente ejecuta el código dado, ignorando cualquier error que cause. Esta es una alternativa a la convención habitual de proteger el código ejecutándolo en un subshell.

{
    # código que puede causar un error
  } always {
    # Este código se ejecuta independientemente del error.
    (( TRY_BLOCK_ERROR = 0 ))
}
# La condición de error se ha restablecido.

Cuando un bloque try ocurre fuera de cualquier función, un return o un exit encontrado en try-list *no* causa la ejecución de always-list. En su lugar, el shell sale inmediatamente después de que se haya ejecutado cualquier trampa de EXIT. De lo contrario, un comando return encontrado en try-list causará la ejecución de always-list, al igual que break y continue.

function [ -T ] word ... [ () ] [ term ] { list }
word ... () [ term ] { list }
word ... () [ term ] command
donde term es uno o más saltos de línea o ;. Define una función a la que se hace referencia por cualquiera de los words. Normalmente, solo se proporciona un word; múltiples words suelen ser útiles solo para establecer trampas. El cuerpo de la función es la list entre los corchetes { y }. Consulte la sección `Funciones'.

Las opciones de function tienen los siguientes significados:

-T
Habilita el trazado para esta función, como si fuera con functions -T. Consulte la documentación de la opción -f del builtin typeset, en zshbuiltins(1).

Si la opción SH_GLOB está configurada para compatibilidad con otros shells, el espacio en blanco puede aparecer entre los paréntesis izquierdo y derecho cuando hay una sola word; de lo contrario, los paréntesis se tratarán como un patrón de globbing en ese caso.

En cualquiera de las formas anteriores, una redirección puede aparecer fuera del cuerpo de la función, por ejemplo

func() { ... } 2>&1

La redirección se almacena con la función y se aplica cada vez que se ejecuta la función. Las variables en la redirección se expanden en el momento en que se ejecuta la función, pero fuera del ámbito de la función.

time [ pipeline ]
Se ejecuta la pipeline y se informan estadísticas de tiempo en el error estándar en el formato especificado por el parámetro TIMEFMT. Si se omite pipeline, se informan estadísticas sobre el proceso del shell y sus hijos.
[[ exp ]]
Evalúa la expresión condicional exp y devuelve un estado de salida cero si es verdadera. Consulte la sección `Expresiones Condicionales' para una descripción de exp.

FORMAS ALTERNATIVAS PARA COMANDOS COMPLEJOS

Muchos de los comandos complejos de zsh tienen formas alternativas. Estos no son estándar y es probable que no sean obvios incluso para programadores de shell experimentados; no deben usarse en lugares donde la portabilidad del código del shell sea una preocupación.

Las versiones cortas a continuación solo funcionan si sublist tiene la forma `{ list }' o si la opción SHORT_LOOPS está configurada. Para los comandos if, while y until, en ambos casos la parte de prueba del bucle también debe estar debidamente delimitada, como por `[[ ... ]]' o `(( ... ))', de lo contrario, el final de la prueba no se reconocerá. Para los comandos for, repeat, case y select no se necesita ninguna forma especial para los argumentos, pero la otra condición (la forma especial de sublist o el uso de la opción SHORT_LOOPS) sigue aplicándose. La opción SHORT_REPEAT está disponible para habilitar la versión corta solo para el comando repeat.

if list { list } [ elif list { list } ] ... [ else { list

Sentencias de control

if [condición] { sublist } ]
Una forma alternativa de if. Las reglas significan que
if [[ -o ignorebraces ]] {
  print yes

funciona, pero

if true {  # ¡No funciona!

no funciona, ya que la prueba no está adecuadamente delimitada.

Una forma corta de la if alternativa. Las mismas limitaciones en la forma de list se aplican como para la forma anterior.

Una forma corta de for.
for name ... [ in word ... ] term sublist
donde term es al menos un salto de línea o ;. Otra forma corta de for.
for (( [expr1] ; [expr2] ; [expr3] )) sublist
Una forma corta del comando for aritmético.

Otra forma de for.

Una forma alternativa de while. Tenga en cuenta las limitaciones en la forma de list mencionadas anteriormente.
until list { list }
Una forma alternativa de until. Tenga en cuenta las limitaciones en la forma de list mencionadas anteriormente.

Esta es una forma corta de repeat.

PALABRAS RESERVADAS

Las siguientes palabras se reconocen como palabras reservadas cuando se utilizan como la primera palabra de un comando, a menos que estén entre comillas o deshabilitadas con disable -r:

do done esac then elif else fi for case if while function repeat time until select coproc nocorrect foreach end ! [[ { } declare export float integer local readonly typeset

Adicionalmente, `}' se reconoce en cualquier posición si la opción IGNORE_BRACES ni la opción IGNORE_CLOSE_BRACES están establecidas.

ERRORES

Ciertos errores son tratados como fatales por el shell: en un shell interactivo, causan que el control regrese a la línea de comandos, y en un shell no interactivo causan que el shell sea abortado. En versiones anteriores de zsh, un shell no interactivo ejecutando un script no abortaba completamente, sino que reanudaba la ejecución en el siguiente comando a leer del script, saltándose el resto de funciones o construcciones del shell como bucles o condiciones; este comportamiento algo ilógico se puede recuperar configurando la opción CONTINUE_ON_ERROR.

Los errores fatales encontrados en shells no interactivos incluyen:

•
Fallo al analizar las opciones del shell pasadas al invocar el shell
•
Fallo al cambiar las opciones con el comando interno set
•
Errores de análisis de todo tipo, incluyendo fallos al analizar expresiones matemáticas
•
Fallos al establecer o modificar el comportamiento de variables con typeset, local, declare, export, integer, float
•
Ejecución de estructuras de control de bucle incorrectamente posicionadas (continue, break)
•
Intentos de usar expresiones regulares sin un módulo de expresiones regulares disponible
•
Operaciones no permitidas cuando la opción RESTRICTED está establecida
•
Fallo al crear una tubería necesaria para un pipeline
•
Fallo al crear un multio
•
Fallo al cargar automáticamente un módulo necesario para una característica del shell declarada
•
Errores al crear sustituciones de comando o de proceso
•
Errores de sintaxis en calificadores de globbing
•
Errores de generación de archivos donde no fueron capturados por la opción BAD_PATTERN
•
Todos los patrones erróneos utilizados para hacer coincidir dentro de sentencias case
•
Fallos de generación de archivos donde no fueron causados por NO_MATCH o opciones similares
•
Todos los errores de generación de archivos donde el patrón se utilizó para crear un multio
•
Errores de memoria donde fueron detectados por el shell
•
Subíndices inválidos para variables del shell
•
Intentos de asignar variables de solo lectura
•
Errores lógicos con variables, como asignación al tipo incorrecto
•
Uso de nombres de variables inválidos
•
Errores en la sintaxis de sustitución de variables
•
Fallo al convertir caracteres en expresiones $'...'

Si la opción POSIX_BUILTINS está establecida, más errores asociados con los comandos internos del shell se tratan como fatales, como se especifica en el estándar POSIX.

COMENTARIOS

En shells no interactivos, o en shells interactivos con la opción INTERACTIVE_COMMENTS establecida, una palabra que comienza con el tercer carácter del parámetro histchars (`#' por defecto) hace que esa palabra y todos los caracteres siguientes hasta un salto de línea se ignoren.

ALIASADO

Cada palabra elegible en la entrada del shell se verifica para ver si existe un alias definido para ella. Si es así, se reemplaza por el texto del alias si está en posición de comando (si pudiera ser la primera palabra de un comando simple), o si el alias es global. Si el texto de reemplazo termina con un espacio, la siguiente palabra en la entrada del shell es siempre elegible a efectos de expansión de alias.

Es un error que el nombre de la función, word, en la sintaxis de definición de función compatible con sh `word () ...' sea una palabra que resultó de la expansión de alias, a menos que la opción ALIAS_FUNC_DEF esté establecida.

Un alias se define usando el comando interno alias; los alias globales se pueden definir usando la opción -g de ese comando interno.

Una palabra se define como:

•
Cualquier cadena simple o patrón de globbing
•
Cualquier cadena entre comillas, usando cualquier método de comillas (tenga en cuenta que las comillas deben ser parte de la definición del alias para que sea elegible)
•
Cualquier referencia a parámetro o sustitución de comando
•
Cualquier serie de los anteriores, concatenados sin espacios en blanco u otros tokens entre ellos
•
Cualquier palabra reservada (case, do, else, etc.)
•
Con aliasing global, cualquier separador de comando, cualquier operador de redirección y `(' o `)' cuando no forma parte de un patrón de globbing

La expansión de alias se realiza en la entrada del shell antes de cualquier otra expansión, excepto la expansión de historial. Por lo tanto, si se define un alias para la palabra foo, la expansión de alias se puede evitar poniendo entre comillas parte de la palabra, por ejemplo, \foo. Cualquier forma de comillas funciona, aunque no hay nada que impida que se defina un alias para la forma entre comillas como \foo también.

En particular, tenga en cuenta que se deben usar comillas al usar unalias para eliminar alias globales:

% alias -g foo=bar
% unalias foo
unalias: no such hash table element: bar
% unalias \foo
%

Cuando se establece POSIX_ALIASES, solo las cadenas simples sin comillas son elegibles para aliasing. El comando interno alias no rechaza alias no elegibles, pero no se expanden.

Para usar con completado, que eliminaría una barra invertida inicial seguida de un carácter que no es especial, puede ser más conveniente poner entre comillas la palabra comenzando con una comilla simple, es decir, 'foo; el completado agregará automáticamente la comilla simple final.

Dificultades con los alias

Aunque los alias se pueden usar de maneras que doblan la sintaxis normal del shell, no todas las cadenas de caracteres no blancos pueden usarse como alias.

Cualquier conjunto de caracteres que no esté listado como una palabra anterior no es una palabra, por lo tanto, no se intenta expandirlo como un alias, sin importar cómo se defina (es decir, a través del comando interno o del parámetro especial aliases descrito en la sección EL MÓDULO DE PARÁMETROS DE ZSH en zshmodules(1)). Sin embargo, como se señaló en el caso de POSIX_ALIASES anteriormente, el shell no intenta deducir si la cadena corresponde a una palabra en el momento en que se crea el alias.

Por ejemplo, una expresión que contiene un = al comienzo de una línea de comando es una asignación y no puede ser expandida como un alias; un = solitario no es una asignación pero solo puede establecerse como alias usando el parámetro, ya que de lo contrario el = se toma como parte de la sintaxis del comando interno.

Actualmente no es posible poner entre alias el token `((' que introduce expresiones aritméticas, porque hasta que no se haya analizado una declaración completa, no se puede distinguir de dos tokens `(' consecutivos que introducen subshells anidados. Además, si se pone un separador como && entre alias, \&& se convierte en los dos tokens \& y &, cada uno de los cuales puede haber sido puesto entre alias por separado. Similarmente para \<<, \>|, etc.

alias echobar='echo bar'; echobar

ALIAS

Una cadena precedida por un nombre de comando que es un alias se expande a esa cadena. Por ejemplo, si se define el alias

alias echobar='print -r -- \"Hello world\"'

entonces el comando

echobar

es reemplazado por

print -r -- "Hello world"

y se ejecuta esta última forma. Una vez que se ha realizado una expansión de alias, la cadena resultante se procesa de nuevo en busca de más expansiones de alias. La expansión de alias se detiene después de que se haya expandido una cadena que contenga la misma cadena que el alias que se está expandiendo en ese momento, para evitar bucles infinitos. No se puede definir un alias para que tenga el mismo nombre que un comando incorporado existente o un nombre de comando que no sea un alias. Los alias no se expanden dentro de las cadenas de cita simple (ver cita más abajo).

Una expansión de alias puede fallar si el comando está precedido por uno de los operadores de redirección de E/S o uno de los operadores de control de trabajos.

La expansión de alias solo se realiza en la primera palabra de una línea de comando. Esto está destinado a evitar problemas con la expansión de alias y redirecciones de E/S. Sin embargo, la expansión de alias se realiza dentro de listas de comandos, subshells y subcomandos de for y while.

Una expansión de alias puede ser problemática en shell scripts, funciones y código ejecutado con source o .. Esto se debe a que los alias se expanden cuando el código se lee; toda la línea se lee de una vez, por lo que cuando se ejecuta echobar ya es demasiado tarde para expandir el alias recién definido. Este es a menudo un problema en los shell scripts, funciones y código ejecutado con source o .. Por consiguiente, se recomienda el uso de funciones en lugar de alias en código no interactivo.

CITAS

Un carácter puede ser citado (es decir, hacer que se represente a sí mismo) precediéndolo con un `\'. `\' seguido de una nueva línea se ignora.

Una cadena encerrada entre `$'' y `'' se procesa de la misma manera que los argumentos de cadena del comando incorporado print, y la cadena resultante se considera completamente citada. Un carácter `'' literal se puede incluir en la cadena utilizando la secuencia de escape `\''.

Todos los caracteres encerrados entre un par de comillas simples ('') que no están precedidos por un `$' están citados. Una comilla simple no puede aparecer dentro de comillas simples a menos que la opción RC_QUOTES esté configurada, en cuyo caso un par de comillas simples se convierte en una comilla simple. Por ejemplo,

print ''''

no produce nada aparte de una nueva línea si RC_QUOTES no está configurado, pero una comilla simple si está configurado.

Dentro de comillas dobles (""), ocurren la sustitución de parámetros y de comandos, y `\' cita los caracteres `\', ``', `"', `$', y el primer carácter de $histchars (por defecto `!').

REDirección

Si un comando va seguido de & y el control de trabajos no está activo, la entrada estándar por defecto para el comando es el archivo vacío /dev/null. De lo contrario, el entorno para la ejecución de un comando contiene los descriptores de archivo del shell invocador, modificados por las especificaciones de entrada/salida.

Lo siguiente puede aparecer en cualquier lugar de un comando simple o puede preceder o seguir a un comando complejo. La expansión ocurre antes de que se utilicen word o digit, excepto como se indica a continuación. Si el resultado de la sustitución en word produce más de un nombre de archivo, la redirección ocurre para cada nombre de archivo separado en turno.

< word
Abre el archivo word para lectura como entrada estándar. Es un error abrir un archivo de esta manera si no existe.
<> word
Abre el archivo word para lectura y escritura como entrada estándar. Si el archivo no existe, se crea.
> word
Abre el archivo word para escritura como salida estándar. Si el archivo no existe, se crea. Si el archivo existe, y la opción CLOBBER no está configurada, esto provoca un error; de lo contrario, se trunca a longitud cero.
>| word
>! word
Igual que >, excepto que el archivo se trunca a longitud cero si existe, independientemente de CLOBBER.
>> word
Abre el archivo word para escritura en modo de anexión como salida estándar. Si el archivo no existe, y las opciones CLOBBER y APPEND_CREATE no están configuradas, esto provoca un error; de lo contrario, el archivo se crea.
>>| word
>>! word
Igual que >>, excepto que el archivo se crea si no existe, independientemente de CLOBBER y APPEND_CREATE.
<<[-] word
La entrada del shell se lee hasta una línea que sea igual a word, o hasta el final del archivo. No se realiza sustitución de parámetros, sustitución de comandos ni generación de nombres de archivo en word. El documento resultante, llamado here-document, se convierte en la entrada estándar.

Si algún carácter de word está citado con comillas simples o dobles o un `\', no se realiza ninguna interpretación sobre los caracteres del documento. De lo contrario, ocurre la sustitución de parámetros y comandos, `\' seguido de una nueva línea se elimina, y `\' se debe usar para citar los caracteres `\', `$', ``' y el primer carácter de word.

Tenga en cuenta que word en sí mismo no sufre expansión del shell. Las comillas invertidas en word no tienen su efecto habitual; en su lugar, se comportan de manera similar a las comillas dobles, excepto que las propias comillas invertidas se pasan sin cambios. (Esta información se proporciona para completar y no se recomienda el uso de comillas invertidas). Las comillas en la forma $'...' tienen su efecto estándar de expandir referencias con barra invertida a caracteres especiales.

Si se utiliza <<-, se eliminan todas las tabulaciones del principio de word y del documento.

<<< word
Realiza la expansión del shell en word y pasa el resultado a la entrada estándar. Esto se conoce como here-string. Compare el uso de word en here-documents anteriores, donde word no sufre expansión del shell. El resultado tendrá una nueva línea final después de él.
<& number
>& number
La entrada/salida estándar se duplica desde el descriptor de archivo number (ver dup2(2)).
<& -
>& -
Cierra la entrada/salida estándar.
<& p
>& p
La entrada/salida desde/hacia el coproceso se mueve a la entrada/salida estándar.
>& word
&> word
(Excepto donde `>& word' coincide con una de las sintaxis anteriores; `&>' siempre se puede usar para evitar esta ambigüedad). Redirige tanto la salida estándar como el error estándar (descriptor de archivo 2) de la manera de `> word'. Tenga en cuenta que esto no tiene el mismo efecto que `> word 2>&1' en presencia de múltiples redirecciones (ver la siguiente sección).
>&| word
>&! word
&>| word
&>! word
Redirige tanto la salida estándar como el error estándar (descriptor de archivo 2) de la manera de `>| word'.
>>& word
&>> word
Redirige tanto la salida estándar como el error estándar (descriptor de archivo 2) de la manera de `>> word'.
>>&| word
>>&! word
&>>| word
&>>! word
Redirige tanto la salida estándar como el error estándar (descriptor de archivo 2) de la manera de `>>| word'.

Si uno de los anteriores está precedido por un dígito, entonces el descriptor de archivo al que se hace referencia es el especificado por el dígito en lugar del predeterminado 0 o 1. El orden en que se especifican las redirecciones es significativo. El shell evalúa cada redirección en términos de la asociación (descriptor de archivo, archivo) en el momento de la evaluación. Por ejemplo:

... 1>fname 2>&1

primero asocia el descriptor de archivo 1 con el archivo fname. Luego asocia el descriptor de archivo 2 con el archivo asociado con el descriptor de archivo 1 (es decir, fname). Si el orden de las redirecciones se invirtiera, el descriptor de archivo 2 se asociaría con la terminal (suponiendo que el descriptor de archivo 1 lo hubiera estado) y luego el descriptor de archivo 1 se asociaría con el archivo fname.

El separador de comandos `|&' descrito en Comandos Simples y Pipelines en zshmisc(1) es una abreviatura de `2>&1 |'.

Las diversas formas de sustitución de procesos, `<(list)', y `=(list)' para entrada y `>(list)' para salida, se usan a menudo junto con la redirección. Por ejemplo, si word en una redirección de salida tiene la forma `>(list)', la salida se canaliza al comando representado por list. Ver Sustitución de Procesos en zshexpn(1).

APERTURA DE DESCRIPTORES DE ARCHIVO USANDO PARÁMETROS

Cuando el shell está analizando argumentos para un comando, y la opción del shell IGNORE_BRACES no está configurada, se permite una forma diferente de redirección: en lugar de un dígito antes del operador, hay un identificador de shell válido encerrado entre llaves. El shell abrirá un nuevo descriptor de archivo que se garantiza que sea al menos 10 y establecerá el parámetro nombrado por el identificador al descriptor de archivo abierto. No se permite espacio en blanco entre la llave de cierre y el carácter de redirección. Por ejemplo:

... {myfd}>&1

Esto abre un nuevo descriptor de archivo que es un duplicado del descriptor de archivo 1 y establece el parámetro myfd al número del descriptor de archivo, que será al menos 10. Se puede escribir en el nuevo descriptor de archivo usando la sintaxis >&$myfd. El descriptor de archivo permanece abierto en subshells y ejecutables externos creados con fork.

La sintaxis {varid}>&-, por ejemplo {myfd}>&-, se puede usar para cerrar un descriptor de archivo abierto de esta manera. Tenga en cuenta que el parámetro dado por varid debe haber sido previamente establecido a un descriptor de archivo en este caso.

Es un error abrir o cerrar un descriptor de archivo de esta manera cuando el parámetro es de solo lectura. Sin embargo, no es un error leer o escribir en un descriptor de archivo usando <&$param o >&$param si param es de solo lectura.

Si la opción CLOBBER no está configurada, es un error abrir un descriptor de archivo usando un parámetro que ya está configurado con un descriptor de archivo abierto previamente asignado por este mecanismo. Desconfigurar el parámetro antes de usarlo para asignar un descriptor de archivo evita el error.

Tenga en cuenta que este mecanismo simplemente asigna o cierra un descriptor de archivo; no realiza ninguna redirección desde o hacia él. Generalmente es conveniente asignar un descriptor de archivo antes de usarlo como argumento para exec. La sintaxis en ningún caso funciona cuando se utiliza alrededor de comandos complejos como subshells entre paréntesis o bucles, donde la llave de apertura se interpreta como parte de una lista de comandos a ejecutar en el shell actual.

FUNCIONES ANÓNIMAS

Si no se da un nombre a una función, es `anónima' y se maneja especialmente. Se puede usar cualquiera de las formas de definición de función: un `()' sin nombre previo, o una `function' con una llave abierta inmediatamente después. La función se ejecuta inmediatamente en el punto de definición y no se almacena para uso futuro. El nombre de la función se establece en `(anon)'.

Los argumentos para la función pueden especificarse como palabras después de la llave de cierre que define la función, por lo tanto, si no hay ninguno, no se establecen argumentos (aparte de $0). Esta es una diferencia con la forma en que se analizan otras funciones: las definiciones de funciones normales pueden ir seguidas de ciertas palabras clave como `else' o `fi', que se tratarán como argumentos para funciones anónimas, por lo que se necesita un salto de línea o un punto y coma para forzar la interpretación de palabras clave.

Tenga en cuenta también que la lista de argumentos de cualquier script o función envolvente está oculta (como sería el caso de cualquier otra función llamada en este punto).

Las redirecciones se pueden aplicar a la función anónima de la misma manera que a una estructura de shell actual encerrada entre llaves. El uso principal de las funciones anónimas es proporcionar un ámbito para variables locales. Esto es particularmente conveniente en los archivos de inicio, ya que estos no proporcionan su propio ámbito de variables locales.

Por ejemplo,

variable=outside
function {
  local variable=inside
  print "I am $variable with arguments $*"
} this and that
print "I am $variable"

muestra lo siguiente:

I am inside with arguments this and that
I am outside

Tenga en cuenta que las definiciones de funciones con argumentos que se expanden a nada, por ejemplo `name=; function $name { ... }', no se tratan como funciones anónimas. En cambio, se tratan como definiciones de funciones normales donde la definición se descarta silenciosamente.

FUNCIONES ESPECIALES

Ciertas funciones, si se definen, tienen un significado especial para el shell.

Funciones de Gancho (Hook Functions)

Para las siguientes funciones, es posible definir un array que tenga el mismo nombre que la función con `_functions' añadido. Cada elemento en dicho array se toma como el nombre de una función a ejecutar; se ejecuta en el mismo contexto y con los mismos argumentos y el mismo valor inicial de $? que la función básica. Por ejemplo, si $chpwd_functions es un array que contiene los valores `mychpwd', `chpwd_save_dirstack', entonces el shell intenta ejecutar las funciones `chpwd', `mychpwd' y `chpwd_save_dirstack', en ese orden. Cualquier función que no exista se ignora silenciosamente. Una función encontrada por este mecanismo se denomina en otros lugares función de gancho. Un error en cualquier función hace que las funciones posteriores no se ejecuten. Tenga en cuenta además que un error en un gancho de precmd hace que una función de periodic inmediatamente posterior no se ejecute (aunque puede ejecutarse en la próxima oportunidad).

chpwd
Se ejecuta cada vez que cambia el directorio de trabajo actual.
periodic
Si el parámetro PERIOD está establecido, esta función se ejecuta cada $PERIOD segundos, justo antes de un prompt. Tenga en cuenta que si se definen varias funciones usando el array periodic_functions, solo se aplica un período al conjunto completo de funciones, y el tiempo programado no se restablece si la lista de funciones se modifica. Por lo tanto, el conjunto de funciones siempre se llama junto.
precmd
Se ejecuta antes de cada prompt. Tenga en cuenta que las funciones precmd no se reejecutan simplemente porque la línea de comandos se redibuja, como sucede, por ejemplo, cuando se muestra una notificación sobre un trabajo que está saliendo.
preexec
Se ejecuta justo después de que se ha leído un comando y está a punto de ejecutarse. FUNCIONES DE TRAMPA

Las funciones siguientes se tratan de forma especial pero no tienen arrays de gancho correspondientes.

TRAPNAL
Si se define y no es nulo, esta función se ejecutará cada vez que el shell capture una señal SIGNAL, donde NAL es un nombre de señal según lo especificado para el comando incorporado kill. El número de señal se pasará como primer parámetro a la función.

Si se define una función de esta forma y es nula, el shell y los procesos generados por él ignorarán SIGNAL.

El estado de retorno de la función se maneja de forma especial. Si es cero, se asume que la señal ha sido manejada y la ejecución continúa normalmente. De lo contrario, el shell se comportará como si se hubiera interrumpido, excepto que se conservará el estado de retorno de la trampa.

Los programas terminados por señales no capturadas normalmente devuelven el estado 128 más el número de señal. Por lo tanto, lo siguiente provoca que el manejador de SIGINT imprima un mensaje, y luego imite el efecto habitual de la señal.

TRAPINT() {
  print "Atrapada SIGINT, abortando."
  return $(( 128 + $1 ))
}

Las funciones TRAPZERR, TRAPDEBUG y TRAPEXIT nunca se ejecutan dentro de otras trampas.

TRAPDEBUG
Si la opción DEBUG_BEFORE_CMD está establecida (como lo está por defecto), se ejecuta antes de cada comando; de lo contrario, se ejecuta después de cada comando. Consulte la descripción del comando incorporado trap en zshbuiltins(1) para obtener detalles de las características adicionales proporcionadas en las trampas de depuración.
TRAPEXIT
Se ejecuta cuando el shell sale, o cuando la función actual sale si se define dentro de una función. El valor de $? al inicio de la ejecución es el estado de salida del shell o el estado de retorno de la función que está saliendo.
TRAPZERR
Se ejecuta cada vez que un comando tiene un estado de salida distinto de cero. Sin embargo, la función no se ejecuta si el comando ocurrió en una sublista seguida de `&&' o `||'; solo el último comando en una sublista de este tipo provoca que se ejecute la trampa. La función TRAPERR actúa igual que TRAPZERR en sistemas donde no hay SIGERR (este es el caso habitual).

Las funciones que comienzan con `TRAP' alternativamente pueden definirse con el comando incorporado trap: esto puede ser preferible para algunos usos. Establecer una trampa con una forma elimina cualquier trampa de la otra forma para la misma señal; eliminar una trampa en cualquiera de las formas elimina todas las trampas para la misma señal. TRABAJOS

Si la opción MONITOR está establecida, un shell interactivo asocia un trabajo con cada pipeline. Mantiene una tabla de trabajos actuales, impresa por el comando jobs, y les asigna números enteros pequeños. Cuando un trabajo se inicia de forma asíncrona con `&', el shell imprime una línea en la salida de error estándar que se ve así:

[1] 1234

indicando que el trabajo que se inició asíncronamente era el trabajo número 1 y tenía un proceso (de nivel superior), cuyo ID de proceso era 1234.

Si un trabajo se inicia con `&|' o `&!', ese trabajo se desvincula inmediatamente. Después del inicio, no tiene un lugar en la tabla de trabajos y no está sujeto a las características de control de trabajos descritas aquí.

Si está ejecutando un trabajo y desea hacer otra cosa, puede presionar la tecla ^Z (control-Z) que envía una señal TSTP al trabajo actual: esta tecla puede ser redefinida por la opción susp del comando externo stty. El shell normalmente indicará que el trabajo ha sido `suspendido', y mostrará otro prompt. Luego puede manipular el estado de este trabajo, poniéndolo en segundo plano con el comando bg, o ejecutar otros comandos y luego, eventualmente, traer el trabajo de vuelta al primer plano con el comando fg. Un ^Z tiene efecto inmediato y es como una interrupción, ya que la salida pendiente y la entrada no leída se descartan cuando se escribe.

Un trabajo que se ejecuta en segundo plano se suspenderá si intenta leer desde el terminal.

Tenga en cuenta que si el trabajo que se ejecuta en primer plano es una función de shell, suspenderla tendrá el efecto de hacer que el shell se bifurque. Esto es necesario para separar el estado de la función del shell padre que realiza el control del trabajo, para que este último pueda retornar al prompt de la línea de comandos. Como resultado, incluso si se usa fg para continuar el trabajo, la función ya no formará parte del shell padre, y cualquier variable establecida por la función no será visible en el shell padre. Por lo tanto, el comportamiento es diferente del caso en que la función nunca fue suspendida. Zsh difiere de muchos otros shells en este aspecto.

Un efecto secundario adicional es que el uso de disown con un trabajo creado al suspender código de shell de esta manera se retrasa: el trabajo solo puede ser desvinculado una vez que cualquier proceso iniciado desde el shell padre haya terminado. En ese punto, el trabajo desvinculado desaparece silenciosamente de la lista de trabajos.

El mismo comportamiento se encuentra cuando el shell está ejecutando código como el lado derecho de un pipeline o cualquier constructo de shell complejo como if, for, etc., para que todo el bloque de código pueda ser gestionado como un solo trabajo. Los trabajos en segundo plano normalmente pueden producir salida, pero esto se puede deshabilitar dando el comando `stty tostop'. Si establece esta opción de tty, los trabajos en segundo plano se suspenderán cuando intenten producir salida, al igual que cuando intentan leer entrada.

Cuando un comando se suspende y se reanuda más tarde con los comandos incorporados fg o wait, zsh restaura los modos de tty que estaban en vigor cuando se suspendió. Esto (intencionalmente) no se aplica si el comando se reanuda a través de `kill -CONT', ni cuando se reanuda con bg.

Hay varias formas de referirse a los trabajos en el shell. Un trabajo puede referirse por el ID del proceso de cualquier proceso del trabajo o por uno de los siguientes:

%número
El trabajo con el número dado.
%cadena
El último trabajo cuya línea de comando comienza con cadena.
%?cadena
El último trabajo cuya línea de comando contiene cadena.
%%
Trabajo actual.
%+
Equivalente a `%%'.
%-
Trabajo anterior.

El shell se entera inmediatamente cada vez que un proceso cambia de estado. Normalmente le informa cada vez que un trabajo se bloquea y no se puede avanzar más. Si la opción NOTIFY no está establecida, espera hasta justo antes de imprimir un prompt antes de informarle. Todas estas notificaciones se envían directamente al terminal, no a la salida estándar o al error estándar.

Cuando el modo monitor está activado, cada trabajo en segundo plano que se completa activa cualquier trampa establecida para CHLD.

Cuando intenta salir del shell mientras hay trabajos en ejecución o suspendidos, se le advertirá que `Tiene trabajos suspendidos (en ejecución)'. Puede usar el comando jobs para ver cuáles son. Si hace esto o intenta salir inmediatamente de nuevo, el shell no le advertirá por segunda vez; los trabajos suspendidos serán terminados, y a los trabajos en ejecución se les enviará una señal SIGHUP, si la opción HUP está establecida.

Para evitar que el shell termine los trabajos en ejecución, use el comando nohup(1) o el comando incorporado disown.

SEÑALES

Las señales INT y QUIT para un comando invocado se ignoran si el comando va seguido de `&' y la opción MONITOR no está activa. El propio shell siempre ignora la señal QUIT. De lo contrario, las señales tienen los valores heredados por el shell de su padre (pero vea las funciones especiales TRAPNAL en la sección `Funciones').

Ciertos trabajos son ejecutados asíncronamente por el shell, aparte de aquellos puestos explícitamente en segundo plano; incluso en casos donde el shell normalmente esperaría por tales trabajos, un comando exit explícito o una salida debido a la opción ERR_EXIT hará que el shell salga sin esperar. Ejemplos de tales trabajos asíncronos son la sustitución de procesos, véase la sección SUSTITUCIÓN DE PROCESOS en la página del manual zshxpn(1), y los procesos manejadores para múltiples salidas, véase la sección MÚLTIPLES SALIDAS en la página del manual zshmisc(1).

EVALUACIÓN ARITMÉTICA

El shell puede realizar aritmética de enteros y de punto flotante, ya sea usando el comando incorporado let, o a través de una sustitución de la forma $((...)). Para enteros, el shell generalmente se compila para usar precisión de 8 bytes donde esto está disponible, de lo contrario la precisión es de 4 bytes. Esto se puede probar, por ejemplo, dando el comando `print - $(( 12345678901 ))'; si el número aparece sin cambios, la precisión es de al menos 8 bytes. La aritmética de punto flotante siempre utiliza el tipo `double' con la precisión correspondiente que proporcione el compilador y la biblioteca.

El comando incorporado let toma expresiones aritméticas como argumentos; cada una se evalúa por separado. Dado que muchos de los operadores aritméticos, así como los espacios, requieren comillas, se proporciona una forma alternativa: para cualquier comando que comience con un `((', todos los caracteres hasta un `))' coincidente se tratan como una expresión entre comillas dobles y se realiza la expansión aritmética como para un argumento de let.

Más precisamente, `((...))' es equivalente a `let "..."'. El estado de retorno es 0 si el valor aritmético de la expresión no es cero, 1 si es cero y 2 si ocurrió un error.

Por ejemplo, la siguiente sentencia

(( val = 2 + 1 ))

es equivalente a

let "val = 2 + 1"

ambas asignando el valor 3 a la variable de shell val y devolviendo un estado cero.

Los enteros pueden estar en bases distintas de 10. Un prefijo `0x' o `0X' denota hexadecimal y un prefijo `0b' o `0B' binario. Los enteros también pueden tener la forma `base#n', donde base es un número decimal entre dos y treinta y seis que representa la base aritmética y n es un número en esa base (por ejemplo, `16#ff' es 255 en hexadecimal). El `base#' también puede omitirse, en cuyo caso se utiliza la base 10. Para compatibilidad hacia atrás, también se acepta la forma `[base]n'.

Una expresión entera o una base dada en la forma `base#n' puede contener guiones bajos (`_') después del dígito inicial para facilitar la lectura; estos se ignoran en los cálculos. Los ejemplos son 1_000_000 o 0xffff_ffff que son equivalentes a 1000000 y 0xffffffff respectivamente.

También es posible especificar una base a utilizar para la salida en la forma `[#base]', por ejemplo `[#16]'. Esto se usa al imprimir sustituciones aritméticas o al asignar a parámetros escalares, pero una variable entera o de punto flotante definida explícitamente no se verá afectada. Si una variable entera se define implícitamente por una expresión aritmética, cualquier base especificada de esta manera se establecerá como la base de salida aritmética de la variable, como si se hubiera utilizado la opción `-i base' del comando interno typeset. La expresión no tiene precedencia y si aparece más de una vez en una expresión matemática, se utiliza la última encontrada. Para mayor claridad, se recomienda que aparezca al principio de una expresión. Como ejemplo:

typeset -i 16 y
print $(( [#8] x = 32, y = 32 ))
print $x $y

imprime primero `8#40', el valor más a la derecha en la base de salida dada, y luego `8#40 16#20', porque y ha sido declarada explícitamente para tener la base de salida 16, mientras que x (asumiendo que aún no existe) se tipifica implícitamente por la evaluación aritmética, donde adquiere la base de salida 8.

La base puede ser reemplazada o seguida por un guión bajo, que a su vez puede ser seguido por un entero positivo (si falta, se usa el valor 3). Esto indica que se deben insertar guiones bajos en la cadena de salida, agrupando el número para mayor claridad visual. El siguiente entero especifica el número de dígitos a agrupar. Por ejemplo:

setopt cbases
print $(( [#16_4] 65536 ** 2 ))

imprime `0x1_0000_0000'.

La característica se puede usar con números de punto flotante, en cuyo caso se debe omitir la base; el agrupamiento se realiza a partir del punto decimal. Por ejemplo,

zmodload zsh/mathfunc
print $(( [#_] sqrt(1e7) ))

imprime `3_162.277_660_168_379_5' (el número de decimales que se muestran puede variar).

Si la opción C_BASES está configurada, los números hexadecimales se imprimen en el formato estándar de C, por ejemplo `0xFF' en lugar del habitual `16#FF'. Si también está configurada la opción OCTAL_ZEROES (no lo está por defecto), los números octales se tratarán de manera similar y, por lo tanto, aparecerán como `077' en lugar de `8#77'. Esta opción no tiene efecto en la salida de bases distintas de hexadecimal y octal, y estos formatos siempre se comprenden en la entrada.

Cuando se especifica una base de salida utilizando la sintaxis `[#base]', se añadirá un prefijo de base apropiado si es necesario, de modo que el valor impreso sea sintaxis válida para la entrada. Si el # se duplica, por ejemplo `[##16]', entonces no se imprimirá ningún prefijo de base.

Las constantes de punto flotante se reconocen por la presencia de un punto decimal o un exponente. El punto decimal puede ser el primer carácter de la constante, pero el carácter del exponente e o E no puede serlo, ya que se tomará como un nombre de parámetro. Todas las partes numéricas (antes y después del punto decimal y en el exponente) pueden contener guiones bajos después del dígito inicial para facilitar la lectura; estos se ignoran en los cálculos.

asigna el doble del valor de $val1 al parámetro llamado val2.

La representación entera interna de un parámetro con nombre se puede especificar con el comando interno integer. La evaluación aritmética se realiza sobre el valor de cada asignación a un parámetro con nombre declarado entero de esta manera. Asignar un número de punto flotante a un entero resulta en redondeo hacia cero.

Del mismo modo, los números de punto flotante se pueden declarar con el comando interno float; hay dos tipos, que difieren solo en su formato de salida, como se describe para el comando interno typeset. El formato de salida se puede omitir utilizando la sustitución aritmética en lugar de la sustitución de parámetros, es decir, `${float}' usa el formato definido, pero `$((float))' usa un formato genérico de punto flotante.

La promoción de enteros a valores de punto flotante se realiza donde sea necesario. Además, si algún operador que requiere un entero (`&', `|', `^', `<<', `>>' y sus equivalentes con asignación) recibe un argumento de punto flotante, se redondeará silenciosamente hacia cero, excepto para `~' que redondea hacia abajo.

Los usuarios deben tener en cuenta que, al igual que muchos otros lenguajes de programación pero a diferencia del software diseñado para cálculos, la evaluación de una expresión en zsh se realiza término a término y la promoción de enteros a punto flotante no ocurre en términos que solo contienen enteros. Un resultado típico de esto es que una división como 6/8 se trunca, redondeándose hacia 0. La opción de shell FORCE_FLOAT se puede utilizar en scripts o funciones donde se requiere evaluación de punto flotante en general.

EXPANSION OF PROMPT SEQUENCES

Prompt sequences undergo a special form of expansion. This type of expansion is also available using the -P option to the print builtin.

If the PROMPT_SUBST option is set, the prompt string is first subjected to parameter expansion, command substitution and arithmetic expansion. See zshexpn(1).

Certain escape sequences may be recognised in the prompt string.

If the PROMPT_BANG option is set, a `!' in the prompt is replaced by the current history event number. A literal `!' may then be represented as `!!'.

If the PROMPT_PERCENT option is set, certain escape sequences that start with `%' are expanded. Many escapes are followed by a single character, although some of these take an optional integer argument that should appear between the `%' and the next character of the sequence. More complicated escape sequences are available to provide conditional expansion.

Especifica el comportamiento de truncamiento para el resto de la cadena del prompt. La tercera forma, obsoleta, es equivalente a `%cadenadc', es decir, c puede ser `<' o `>'. La parte de la cadena del prompt que se truncará se extiende hasta el final de la cadena, o hasta el final del siguiente grupo anidado de la construcción `%(', o hasta el siguiente truncamiento encontrado en el mismo nivel de agrupación (es decir, los truncamientos dentro de un `%(' son separados), lo que ocurra primero. Sin el `%<<', esos dos caracteres se incluirían en la cadena a truncar. Tenga en cuenta que `%-0<<' no es equivalente a `%<<' sino que especifica que el prompt se trunca en el margen derecho.

Si la longitud total de cualquier línea del prompt después del truncamiento es mayor que el ancho del terminal, o si la parte a truncar contiene saltos de línea incrustados, el comportamiento de truncamiento no está definido y puede cambiar en una futura versión del shell.
