NOMBRE

zshmodules - módulos cargables de zsh

DESCRIPCIÓN

Algunas partes opcionales de zsh están en módulos, separadas del núcleo del shell. Cada uno de estos módulos puede enlazarse al shell en tiempo de compilación, o puede enlazarse dinámicamente mientras el shell está en ejecución si la instalación soporta esta característica. Los módulos se enlazan en tiempo de ejecución con el comando zmodload, véase zshbuiltins(1).

Los módulos que se incluyen con la distribución de zsh son:

zsh/attr
Comandos para manipular atributos extendidos (xattr).
zsh/cap
Comandos para manipular conjuntos de capacidades (privilegios) POSIX.1e (POSIX.6).
zsh/clone
Un comando que puede clonar un shell en ejecución a otra terminal.
zsh/compctl
El comando compctl para controlar la compleción.
zsh/complete
El código básico de compleción.
zsh/complist
Extensiones de listado de compleción.
zsh/computil
Un módulo con comandos de utilidad necesarios para el sistema de compleción basado en funciones del shell.
zsh/curses
Comandos de ventanas curses
zsh/datetime
Algunos comandos y parámetros de fecha/hora.
zsh/db/gdbm
Comandos para gestionar parámetros de arrays asociativos vinculados a bases de datos GDBM.
zsh/deltochar
Una función ZLE que duplica el zap-to-char de EMACS.
zsh/example
Un ejemplo de cómo escribir un módulo.
zsh/files
Algunos comandos básicos de manipulación de archivos como comandos internos.
zsh/langinfo
Interfaz a la información de localización (locale).
zsh/mapfile
Acceso a archivos externos a través de un array asociativo especial.
zsh/mathfunc
Funciones científicas estándar para su uso en evaluaciones matemáticas.
zsh/nearcolor
Mapea colores al color más cercano en la paleta disponible.
zsh/newuser
Organiza la instalación de archivos para nuevos usuarios.
zsh/parameter
Acceso a tablas hash internas a través de arrays asociativos especiales.
zsh/pcre
Interfaz a la biblioteca PCRE.

Comandos para gestionar parámetros de ámbito privado en contexto de función.

Interfaz a la biblioteca POSIX regex.

Manipulación de sockets de dominio Unix

Interfaz a la base de datos termcap.

zsh/zselect

zsh/zutil
Algunos comandos de utilidad, por ejemplo, el que soporta la configuración a través de estilos.

EL MÓDULO ZSH/ATTR

El módulo zsh/attr se utiliza para manipular atributos extendidos. La opción -h hace que todos los comandos operen sobre enlaces simbólicos en lugar de sus objetivos. Los comandos internos de este módulo son:

zgetattr [ -h ] nombrearchivo atributo [ parámetro ]
Obtiene el atributo extendido atributo del nombrearchivo especificado. Si se proporciona el argumento opcional parámetro, el atributo se asigna a ese parámetro en lugar de imprimirse en la salida estándar.
zsetattr [ -h ] nombrearchivo atributo valor
Establece el atributo extendido atributo en el nombrearchivo especificado a valor.
zdelattr [ -h ] nombrearchivo atributo
Elimina el atributo extendido atributo del nombrearchivo especificado.
zlistattr [ -h ] nombrearchivo [ parámetro ]
Lista los atributos extendidos actualmente establecidos en el nombrearchivo especificado. Si se proporciona el argumento opcional parámetro, la lista de atributos se asigna a ese parámetro en lugar de imprimirse en la salida estándar.

zgetattr y zlistattr asignan memoria dinámicamente. Si el atributo o la lista de atributos crece entre la asignación y la llamada para obtenerlos, retornan 2. En todos los demás errores, retornan 1. Esto permite a la función que llama comprobar este caso y reintentar.

EL MÓDULO ZSH/CAP

El módulo zsh/cap se utiliza para manipular conjuntos de capacidades POSIX.1e (POSIX.6). Si el sistema operativo no soporta esta interfaz, los comandos internos definidos por este módulo no harán nada. Los comandos internos de este módulo son:

cap [ capacidades ]
Cambia los conjuntos de capacidades del proceso del shell a las capacidades especificadas; de lo contrario, muestra las capacidades actuales del shell.
getcap nombrearchivo ...
Esta es una implementación interna de la utilidad estándar POSIX. Muestra los conjuntos de capacidades en cada nombrearchivo especificado.
setcap capacidades nombrearchivo ...
Esta es una implementación interna de la utilidad estándar POSIX. Establece los conjuntos de capacidades en cada nombrearchivo especificado a las capacidades especificadas.

EL MÓDULO ZSH/CLONE

El módulo zsh/clone pone a disposición un comando interno:

clone tty
Crea una instancia derivada del shell actual, adjunta al tty especificado.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

tty. En el nuevo shell, los parámetros especiales PID, PPID y TTY se cambian apropiadamente. $! se establece en cero en el nuevo shell, y en el PID del nuevo shell en el shell original.

El estado de retorno del comando incorporado es cero en ambos shells si tiene éxito, y distinto de cero en caso de error.

El destino de clone debe ser un terminal no utilizado, como una consola virtual no utilizada o un terminal virtual creado por

xterm -e sh -c 'trap : INT QUIT TSTP; tty;
        while :; do sleep 100000000; done'

Se requieren algunas explicaciones sobre esta larga línea de comandos de xterm: al clonar un pseudo-terminal, alguna otra sesión ("sesión" entendida como un grupo de sesión de Unix, o SID) ya está poseyendo el terminal. Por lo tanto, el zsh clonado no puede adquirir el pseudo-terminal como un tty de control. Eso significa dos cosas:

•
las señales de control de trabajos irán al grupo de procesos iniciado por sh (por eso deshabilitamos INT QUIT y TSTP con trap; de lo contrario, el bucle while podría suspenderse o matarse)
•
el shell clonado tendrá el control de trabajos deshabilitado, y las teclas de control de trabajos (control-C, control-\ y control-Z) no funcionarán.

Esto no se aplica al clonar a una vc no utilizada.

Clonar a un terminal usado (y no preparado) resultará en dos procesos leyendo simultáneamente del mismo terminal, con los bytes de entrada yendo aleatoriamente a cualquiera de los dos procesos.

clone es principalmente útil como un reemplazo de comando incorporado para openvt.

EL MÓDULO ZSH/COMPCTL

El módulo zsh/compctl pone a disposición dos comandos incorporados. compctl, es la forma antigua y obsoleta de controlar las completaciones para ZLE. Ver zshcompctl(1). El otro comando incorporado, compcall, se puede usar en widgets de completación definidos por el usuario, ver zshcompwid(1).

EL MÓDULO ZSH/COMPLETE

El módulo zsh/complete pone a disposición varios comandos incorporados que se pueden utilizar en widgets de completación definidos por el usuario, ver zshcompwid(1).

EL MÓDULO ZSH/COMPLIST

El módulo zsh/complist ofrece tres extensiones para las listas de completación: la capacidad de resaltar coincidencias en dicha lista, la capacidad de desplazarse por listas largas y un estilo diferente de completación de menú.

Listas de completación con color

Siempre que se establezca uno de los parámetros ZLS_COLORS o ZLS_COLOURS y el módulo zsh/complist se cargue o enlace en el shell, las listas de completación se colorearán. Tenga en cuenta, sin embargo, que complist no se cargará automáticamente si no está enlazado: en sistemas con carga dinámica, se requiere `zmodload zsh/complist'.

Los parámetros ZLS_COLORS y ZLS_COLOURS describen cómo se resaltan las coincidencias. Para activar el resaltado, basta con un valor vacío, en cuyo caso se utilizarán todos los valores predeterminados que se indican a continuación. El formato del valor de estos parámetros es el mismo que utiliza la versión GNU del comando ls: una lista separada por dos puntos de especificaciones de la forma `nombre=valor'. El nombre puede ser una de las siguientes cadenas, la mayoría de las cuales especifican tipos de archivo para los que se utilizará el valor. Las cadenas y sus valores predeterminados son:

no 0
para texto normal (es decir, al mostrar algo que no sea un archivo coincidente)
fi 0
para archivos regulares
di 32
para directorios
ln 36
para enlaces simbólicos. Si este tiene el valor especial target, los enlaces simbólicos se desreferenciarán y se utilizará el archivo de destino para determinar el formato de visualización.
pi 31
para tuberías con nombre (FIFOs)
so 33
para sockets
bd 44;37
para dispositivos de bloque
cd 44;37
para dispositivos de caracteres
or none
para un enlace simbólico a un archivo inexistente (el valor predeterminado es el definido para ln)
mi none
para un archivo inexistente (el valor predeterminado es el definido para fi); este código actualmente no se utiliza
su 37;41
para archivos con el bit setuid establecido
sg 30;43
para archivos con el bit setgid establecido
tw 30;42
para directorios escribibles por el mundo con el bit sticky establecido
ow 34;43
para directorios escribibles por el mundo sin el bit sticky establecido
sa none
para archivos con un alias de sufijo asociado; esto solo se prueba después de sufijos específicos, como se describe a continuación
st 37;44
para directorios con el bit sticky establecido pero no escribibles por el mundo
ex 35
para archivos ejecutables
lc \e[
para el código izquierdo (ver más abajo)
rc m
para el código derecho
tc 0
para el carácter que indica el tipo de archivo impreso después de los nombres de archivo si la opción LIST_TYPES está establecida
sp 0
para los espacios impresos después de las coincidencias para alinear la siguiente columna
ec none
para el código de fin

Aparte de estas cadenas, el nombre también puede ser un asterisco (`*') seguido de cualquier cadena. El valor dado para tal cadena se utilizará para todos los archivos cuyos nombres terminen con la cadena. El nombre también puede ser un signo igual (`=') seguido de un patrón; la opción EXTENDED_GLOB se activará para la evaluación del patrón. El valor dado para este patrón se utilizará para todas las coincidencias (no solo nombres de archivo) cuyas cadenas de visualización coincidan con el patrón. Las definiciones para la forma con el signo igual inicial tienen precedencia sobre los valores definidos para los tipos de archivo, que a su vez tienen precedencia sobre la forma con el asterisco inicial (extensiones de archivo).

La forma con el signo igual inicial también permite colorear diferentes partes de las cadenas mostradas de manera diferente. Para esto, el patrón debe usar la bandera de globbing `(#b)' y pares de paréntesis que rodeen las partes de las cadenas que se colorearán de manera diferente. En este caso, el valor puede consistir en más de un código de color separado por signos de igual. El primer código se utilizará para todas las partes para las que no se especifica ningún código explícito y los siguientes códigos se utilizarán para las partes que coincidan con los subpatrones entre paréntesis. Por ejemplo, la especificación `=(#b)(?)*(?)=0=3=7' se utilizará para todas las coincidencias que tengan al menos dos caracteres de longitud y utilizará el código `3' para el primer carácter, `7' para el último carácter y `0' para el resto.

Las tres formas de nombre pueden ir precedidas por un patrón entre paréntesis. Si se proporciona, el valor solo se utilizará para las coincidencias en grupos cuyos nombres coincidan con el patrón dado entre paréntesis. Por ejemplo, `(g*)m*=43' resalta todas las coincidencias que comienzan con `m' en grupos cuyos nombres comienzan con `g' utilizando el código de color `43'. En el caso de los códigos `lc', `rc' y `ec', se ignora el patrón de grupo.

Tenga en cuenta también que todos los patrones se prueban en el orden en que aparecen en el valor del parámetro hasta que coincida el primero, que luego se utiliza. Los patrones se pueden comparar con completaciones, descripciones (posiblemente con espacios añadidos para relleno) o líneas que consisten en una completación seguida de una descripción. Para un coloreado consistente, puede ser necesario utilizar más de un patrón o un patrón con retroreferencias.

Al imprimir una coincidencia, el código imprime el valor de lc, el valor para el tipo de archivo o la última especificación coincidente con un `*', el valor de rc, la cadena a mostrar para la coincidencia en sí, y luego el valor de ec si está definido o los valores de lc, no y rc si ec no está definido.

Los valores predeterminados cumplen con ISO 6429 (ANSI) y se pueden usar en terminales compatibles con vt100 como xterms. En terminales monocromáticos, los valores predeterminados no tendrán ningún efecto visible. La función colors de la contribución se puede utilizar para obtener arrays asociativos que contengan los códigos para terminales ANSI (ver la sección `Otras funciones' en zshcontrib(1)). Por ejemplo, después de cargar colors, se podría usar `$color[red]' para obtener el código del color rojo frontal y `$color[bg-green]' para el código del color verde de fondo.

Si se utiliza el sistema de completación invocado por compinit, estos parámetros no deben establecerse directamente, ya que el sistema los controla por sí mismo. En su lugar, se debe utilizar el estilo list-colors (ver la sección `Configuración del sistema de completación' en zshcompsys(1)).

Desplazamiento en listas de completación

Para habilitar el desplazamiento por una lista de completación, se debe establecer el parámetro LISTPROMPT. Su valor se utilizará como el prompt; si es la cadena vacía, se utilizará un prompt predeterminado. El valor puede contener escapes del tipo `%x'. Admite los escapes `%B', `%b', `%S', `%s', `%U', `%u', `%F', `%f', `%K', `%k' y `%{...%}' utilizados también en prompts de shell, así como tres pares de secuencias adicionales: `%l' o `%L' se reemplaza por el número de la última línea mostrada y el número total de líneas en el formato `número/total'; `%m' o `%M' se reemplaza con el núme

Visualización de listas

Cuando se muestra una lista de completados, se pueden utilizar varias secuencias de escape en el parámetro PROMPT para personalizar su apariencia. Estas secuencias se reemplazan con información sobre la lista de completados que se muestra:

%N
es reemplazado por el número de la última coincidencia mostrada y el número total de coincidencias.
%p o %P
se reemplaza con "Top", "Bottom" o la posición de la primera línea mostrada como un porcentaje del número total de líneas, respectivamente. En cada uno de estos casos, la forma con la letra mayúscula se reemplazará con una cadena de ancho fijo, rellenada a la derecha con espacios, mientras que la forma en minúsculas no se rellenará.

Si el parámetro LISTPROMPT está establecido, el código de completado no preguntará si se debe mostrar la lista. En cambio, comenzará inmediatamente a mostrar la lista, deteniéndose después de la primera pantalla, mostrando el prompt en la parte inferior, esperando una pulsación de tecla después de cambiar temporalmente al mapa de teclas listscroll. Algunas de las funciones zle tienen un significado especial al desplazarse por listas:

send-break
detiene la visualización de la lista descartando la tecla presionada.
accept-line, down-history, down-line-or-history
down-line-or-search, vi-down-line-or-history
desplaza hacia adelante una línea.
complete-word, menu-complete, expand-or-complete
expand-or-complete-prefix, menu-complete-or-expand
desplaza hacia adelante una pantalla completa.
accept-search
detiene la visualización de la lista pero no realiza ninguna otra acción.

Cualquier otro carácter detiene la visualización de la lista y procesa inmediatamente la tecla como de costumbre. Cualquier tecla que no esté vinculada en el mapa de teclas listscroll o que esté vinculada a undefined-key se busca en el mapa de teclas actualmente seleccionado.

En cuanto a los parámetros ZLS_COLORS y ZLS_COLOURS, LISTPROMPT no debe establecerse directamente al usar el sistema de completado basado en funciones del shell. En su lugar, se debe usar el estilo list-prompt.

Selección de menú

El módulo zsh/complist también ofrece un estilo alternativo para seleccionar coincidencias de una lista, llamado selección de menú, que se puede usar si el shell está configurado para regresar al último prompt después de mostrar una lista de completados (consulte la opción ALWAYS_LAST_PROMPT en zshoptions(1)).

La selección de menú se puede invocar directamente con el widget menu-select definido por este módulo. Este es un widget estándar de ZLE que se puede vincular a una tecla de la manera habitual, como se describe en zshzle(1).

Alternativamente, el parámetro MENUSELECT puede establecerse a un entero, que da el número mínimo de coincidencias que deben estar presentes antes de que la selección de menú se active automáticamente. Este segundo método requiere que se inicie la completación de menú, ya sea directamente desde un widget como menu-complete, o debido a que se establece una de las opciones MENU_COMPLETE o AUTO_MENU. Si MENUSELECT está establecido, pero es 0, 1 o vacío, la selección de menú siempre se iniciará durante una completación de menú ambigua.

Al usar el sistema de completado basado en funciones del shell, el parámetro MENUSELECT no debe usarse (como los parámetros ZLS_COLORS y ZLS_COLOURS descritos anteriormente). En su lugar, se debe usar el estilo menu con la palabra clave select=....

Una vez iniciada la selección de menú, se enumerarán las coincidencias. Si hay más coincidencias que caben en la pantalla, solo se mostrará la primera pantalla. Las coincidencias a insertar en la línea de comandos se pueden seleccionar de esta lista. En la lista, una coincidencia se resalta utilizando el valor de ma del parámetro ZLS_COLORS o ZLS_COLOURS. El valor predeterminado para esto es '7', que fuerza a que la coincidencia seleccionada se resalte utilizando el modo de selección (standout mode) en un terminal compatible con vt100. Si no se establece ni ZLS_COLORS ni ZLS_COLOURS, se utiliza la misma secuencia de control de terminal que para la secuencia de escape '%S' en los prompts.

Si hay más coincidencias que caben en la pantalla y el parámetro MENUPROMPT está establecido, su valor se mostrará debajo de las coincidencias. Soporta las mismas secuencias de escape que LISTPROMPT, pero el número de la coincidencia o línea mostrada será el de aquella donde se coloca la marca. Si su valor es la cadena vacía, se usará un prompt predeterminado.

El parámetro MENUSCROLL se puede usar para especificar cómo se desplaza la lista. Si el parámetro no está establecido, se hace línea por línea; si se establece en '0' (cero), la lista se desplazará la mitad del número de líneas de la pantalla. Si el valor es positivo, indica el número de líneas a desplazar y si es negativo, la lista se desplazará el número de líneas de la pantalla menos el valor (absoluto).

Al igual que con los parámetros ZLS_COLORS, ZLS_COLOURS y LISTPROMPT, ni MENUPROMPT ni MENUSCROLL deben establecerse directamente al usar el sistema de completado basado en funciones del shell. En su lugar, se deben usar los estilos select-prompt y select-scroll.

El código de completado a veces decide no mostrar todas las coincidencias en la lista. Estas coincidencias ocultas son o bien coincidencias para las cuales la función de completado que las agregó solicitó explícitamente que no aparecieran en la lista (usando la opción -n del comando incorporado compadd) o son coincidencias que duplican una cadena ya presente en la lista (porque difieren solo en cosas como prefijos o sufijos que no se muestran). Sin embargo, en la lista utilizada para la selección de menú, incluso estas coincidencias se muestran para que sea posible seleccionarlas. Para resaltar dichas coincidencias, se admiten las capacidades hi y du en los parámetros ZLS_COLORS y ZLS_COLOURS para las coincidencias ocultas del primer y segundo tipo, respectivamente.

La selección de coincidencias se realiza moviendo la marca usando las funciones de movimiento de zle. Cuando no todas las coincidencias se pueden mostrar en la pantalla al mismo tiempo, la lista se desplazará hacia arriba y hacia abajo al cruzar la línea superior o inferior. Las siguientes funciones de zle tienen un significado especial durante la selección de menú. Tenga en cuenta que las siguientes siempre realizan la misma tarea dentro del mapa de selección de menú y no pueden ser reemplazadas por widgets definidos por el usuario, ni se puede extender el conjunto de funciones:

accept-line, accept-search
acepta la coincidencia actual y sale de la selección de menú (pero no provoca que se acepte la línea de comandos).
send-break
sale de la selección de menú y restaura el contenido anterior de la línea de comandos.
redisplay, clear-screen
ejecuta su función normal sin salir de la selección de menú.
accept-and-hold, accept-and-menu-complete
acepta la coincidencia actualmente insertada y continúa la selección, permitiendo seleccionar la siguiente coincidencia a insertar en la línea.
accept-and-infer-next-history
acepta la coincidencia actual e intenta nuevamente la completación con selección de menú; en el caso de archivos, esto permite seleccionar un directorio e intentar completar archivos dentro de él inmediatamente; si no hay coincidencias, se muestra un mensaje y se puede usar undo para regresar a la completación en el nivel anterior; cualquier otra tecla sale de la selección de menú (incluidas las otras funciones de zle que son especiales durante la selección de menú).
undo
elimina las coincidencias insertadas durante la selección de menú por una de las tres funciones anteriores.
down-history, down-line-or-history
vi-down-line-or-history, down-line-or-search
mueve la marca una línea hacia abajo.
up-history, up-line-or-history
vi-up-line-or-history, up-line-or-search
mueve la marca una línea hacia arriba.
forward-char, vi-forward-char
mueve la marca una columna a la derecha.
backward-char, vi-backward-char
mueve la marca una columna a la izquierda.
forward-word, vi-forward-word
vi-forward-word-end, emacs-forward-word
mueve la marca una pantalla completa hacia abajo.
backward-word, vi-backward-word, emacs-backward-word
mueve la marca una pantalla completa hacia arriba.
vi-forward-blank-word, vi-forward-blank-word-end
mueve la marca a la primera línea del siguiente grupo de coincidencias.
vi-backward-blank-word
mueve la marca a la última línea del grupo de coincidencias anterior.
beginning-of-history
mueve la marca a la primera línea.
end-of-history
mueve la marca a la última línea.
beginning-of-buffer-or-history, beginning-of-line
beginning-of-line-hist, vi-beginning-of-line
mueve la marca a la columna más a la izquierda.
end-of-buffer-or-history, end-of-line
end-of-line-hist, vi-end-of-line
mueve la marca a la columna más a la derecha.
complete-word, menu-complete, expand-or-complete
expand-or-complete-prefix, menu-expand-or-complete
mueve la marca a la siguiente coincidencia.
reverse-menu-complete
mueve la marca a la coincidencia anterior.
vi-insert
esto alterna entre el modo normal y el interactivo; en modo interactivo, las teclas vinculadas a self-insert y self-insert-unmeta se insertan en la línea de comandos como en el modo de edición normal pero sin salir de la selección de menú; después de cada carácter, se intenta la completación nuevamente y la lista cambia para contener solo las nuevas coincidencias; los widgets de completado hacen que la cadena más larga y sin ambigüedades se inserte en la línea de comandos y undo y backward-delete-char regresan al conjunto anterior de coincidencias.
history-incremental-search-forward

MÓDULO ZSH/COMPUTIL

El módulo zsh/computil agrega varios comandos incorporados que son utilizados por algunas de las funciones de completado en el sistema de completado basado en funciones del shell (ver zshcompsys(1)). Excepto por compquote, estos comandos incorporados son muy especializados y, por lo tanto, no muy interesantes al escribir tus propias funciones de completado. En resumen, estos comandos incorporados son:

comparguments
Esto es utilizado por la función _arguments para realizar el análisis de argumentos y de la línea de comandos. Al igual que compdescribe, tiene la opción -i para realizar el análisis e inicializar un estado interno y varias opciones para acceder a la información del estado y decidir qué se debe completar.
compdescribe
Esto es utilizado por la función _describe para construir las visualizaciones de las coincidencias y obtener las cadenas para agregar como coincidencias con sus opciones. En la primera llamada, se debe proporcionar una de las opciones -i o -I como primer argumento. En el primer caso, se generarán cadenas de visualización sin las descripciones; en el segundo caso, se debe proporcionar la cadena utilizada para separar las coincidencias de sus descripciones como segundo argumento y las descripciones (si las hay) se mostrarán. Todos los demás argumentos son como los argumentos de definición para _describe.

Una vez que se ha llamado a compdescribe con la opción -i o -I, se puede llamar repetidamente con la opción -g y los nombres de cuatro parámetros como sus argumentos. Esto recorrerá los diferentes conjuntos de coincidencias y almacenará el valor de compstate[list] en el primer escalar, las opciones para compadd en el segundo array, las coincidencias en el tercer array y las cadenas que se mostrarán en la lista de completado en el cuarto array. Los arrays se pueden dar directamente a compadd para registrar las coincidencias con el código de completado.

compfiles
Utilizado por la función _path_files para optimizar la generación recursiva compleja de nombres de archivo (globbing). Hace tres cosas. Con las opciones -p y -P construye los patrones glob a utilizar, incluyendo las rutas ya manejadas y tratando de optimizar los patrones con respecto al prefijo y sufijo de la línea y la especificación de coincidencia utilizada actualmente. La opción -i realiza las pruebas de directorio para el estilo ignore-parents y la opción -r prueba si un componente para algunas de las coincidencias es igual a la cadena en la línea y elimina todas las demás coincidencias si eso es cierto.
compgroups
Utilizado por la función _tags para implementar los detalles internos del estilo group-order. Esto solo toma sus argumentos como nombres de grupos de completado y crea los grupos para él (los seis tipos: ordenados y sin ordenar, ambos sin eliminar duplicados, con eliminación de todos los duplicados y con eliminación de duplicados consecutivos).

Puede haber razones para escribir funciones de completado que tengan que agregar las coincidencias usando la opción -Q a compadd y realizar el escape ellas mismas. En lugar de interpretar el primer carácter de la clave all_quotes de la asociación especial compstate y usar el flag q para las expansiones de parámetros, se puede usar este comando incorporado. Los argumentos son los nombres de parámetros escalares o de arrays y los valores de estos parámetros se escapan según sea necesario para el nivel de escape más interno. Si se proporciona la opción -p, el escape se realiza como si hubiera algún prefijo antes de los valores de los parámetros, de modo que un signo igual inicial no se escape.

El estado de retorno es distinto de cero en caso de error y cero en caso contrario.

comptags
comptry
Estos implementan los detalles internos del mecanismo de etiquetas.
compvalues
Similar a comparguments, pero para la función _values.

EL MÓDULO ZSH/MAPFILE

El módulo zsh/mapfile proporciona un array asociativo especial del mismo nombre.

mapfile
Este array asociativo toma como claves los nombres de los archivos; el valor resultante es el contenido del archivo. El valor se trata de forma idéntica a cualquier otro texto proveniente de un parámetro. El valor también se puede asignar, en cuyo caso el archivo en cuestión se escribe (independientemente de si existía originalmente); o se puede eliminar un elemento, lo que eliminará el archivo en cuestión. Por ejemplo, `vared 'mapfile[archivo_propio]'' funciona como se espera, editando el archivo `archivo_propio'.

Cuando se accede al array en su totalidad, las claves son los nombres de los archivos en el directorio actual, y los valores están vacíos (para ahorrar una gran sobrecarga de memoria). Por lo tanto, ${(k)mapfile} tiene el mismo efecto que el operador glob *(D), ya que los archivos que comienzan con un punto no son especiales. Se debe tener cuidado con expresiones como rm ${(k)mapfile}, que eliminarán todos los archivos en el directorio actual sin la prueba habitual de `rm *'.

El parámetro mapfile puede hacerse de solo lectura; en ese caso, los archivos referenciados no se podrán escribir ni eliminar.

Un archivo se puede leer convenientemente en un array como una línea por elemento con el formato `array=("${(f@)mapfile[nombre_archivo]}")'. Las comillas dobles y el `@' son necesarios para evitar que se eliminen las líneas vacías. Tenga en cuenta que si el archivo termina con un salto de línea, el shell se dividirá en el salto de línea final, generando un campo vacío adicional; esto se puede suprimir utilizando `array=("${(f@)${mapfile[nombre_archivo]%$'\n'}}")'.

Limitaciones

Aunque la lectura y escritura del archivo en cuestión se manejan de manera eficiente, la gestión de memoria interna de zsh puede ser arbitrariamente barroca; sin embargo, mapfile suele ser mucho más eficiente que cualquier cosa que implique un bucle. Tenga en cuenta en particular que todo el contenido del archivo residirá siempre físicamente en memoria cuando se acceda a él (posiblemente varias veces, debido a las operaciones estándar de sustitución de parámetros). En particular, esto significa que el manejo de archivos suficientemente largos (mayores que el espacio de intercambio de la máquina o que el rango del tipo de puntero) será incorrecto.

No se imprimen ni se marcan errores para archivos inexistentes, ilegibles o no escribibles, ya que el mecanismo de parámetros está demasiado bajo en la jerarquía de ejecución del shell para hacerlo conveniente.

Es lamentable que el mecanismo para cargar módulos aún no permita al usuario especificar el nombre del parámetro del shell al que se le dará el comportamiento especial.

EL MÓDULO ZSH/MATHFUNC

El módulo zsh/mathfunc proporciona funciones matemáticas estándar para su uso al evaluar fórmulas matemáticas. La sintaxis concuerda con las convenciones normales de C y FORTRAN, por ejemplo,

(( f = sin(0.3) ))

asigna el seno de 0.3 al parámetro f.

La mayoría de las funciones toman argumentos de punto flotante y devuelven un valor de punto flotante. Sin embargo, cualquier conversión necesaria de o a tipo entero será realizada automáticamente por el shell. Aparte de atan con un segundo argumento y las funciones abs, int y float, todas las funciones se comportan como se indica en la página del manual de la función C correspondiente, excepto que cualquier argumento fuera de rango para la función en cuestión será detectado por el shell y se informará de un error.

Las siguientes funciones toman un solo argumento de punto flotante: acos, acosh, asin, asinh, atan, atanh, cbrt, ceil, cos, cosh, erf, erfc, exp, expm1, fabs, floor, gamma, j0, j1, lgamma, log, log10, log1p, log2, logb, sin, sinh, sqrt, tan, tanh, y0, y1. La función atan puede tomar opcionalmente un segundo argumento, en cuyo caso se comporta como la función C atan2. La función ilogb toma un solo argumento de punto flotante, pero devuelve un entero.

La función signgam no toma argumentos y devuelve un entero, que es la variable C del mismo nombre, como se describe en gamma(3). Tenga en cuenta que, por lo tanto, solo es útil inmediatamente después de una llamada a gamma o lgamma. Tenga en cuenta también que `signgam()' y `signgam' son expresiones distintas.

Las funciones min, max y sum no están definidas en este módulo, sino en la función cargable automáticamente zmathfunc, descrita en la sección `Funciones matemáticas' en zshcontrib(1).

Las siguientes funciones toman dos argumentos de punto flotante: copysign, fmod, hypot, nextafter.

Las siguientes toman un primer argumento entero y un segundo argumento de punto flotante: jn, yn.

Las siguientes toman un primer argumento de punto flotante y un segundo argumento entero: ldexp, scalb.

La función abs no convierte el tipo de su único argumento; devuelve el valor absoluto de un número de punto flotante o un entero. Las funciones float y int convierten sus argumentos en un valor de punto flotante o entero (por truncamiento), respectivamente.

Tenga en cuenta que la función C pow está disponible en la evaluación matemática ordinaria como el operador `**' y no se proporciona aquí.

La función rand48 está disponible si la biblioteca matemática de su sistema tiene la función erand48(3). Devuelve un número de punto flotante pseudoaleatorio entre 0 y 1. Toma un único argumento opcional de cadena.

Si el argumento no está presente, la semilla del número aleatorio se inicializa mediante tres llamadas a la función rand(3) --- esto produce los mismos números aleatorios que los siguientes tres valores de $RANDOM.

Si el argumento está presente, da el nombre de un parámetro escalar donde se almacenará la semilla del número aleatorio actual. En la primera llamada, el valor debe contener al menos doce dígitos hexadecimales (el resto de la cadena se ignora), o la semilla se inicializará de la misma manera que para una llamada a rand48 sin argumento. Las llamadas posteriores a rand48(param) mantendrán la semilla en el parámetro param como una cadena de doce dígitos hexadecimales, sin signo base. Las secuencias de números aleatorios para diferentes parámetros son completamente independientes, y también son independientes de la utilizada por las llamadas a rand48 sin argumento.

Por ejemplo, considere

print $(( rand48(seed) ))
print $(( rand48() ))
print $(( rand48(seed) ))

Suponiendo que $seed no existe, se inicializará en la primera llamada. En la segunda llamada, se inicializa la semilla predeterminada; tenga en cuenta, sin embargo, que debido a las propiedades de rand() existe una correlación entre las semillas utilizadas para las dos inicializaciones, por lo que para usos más seguros, debe generar su propia semilla de 12 bytes. La tercera llamada vuelve a la misma secuencia de números aleatorios utilizada en la primera llamada, no afectada por la intervención de rand48().

EL MÓDULO ZSH/NEARCOLOR

El módulo zsh/nearcolor reemplaza los colores especificados como tríos hexadecimales con el color más cercano en las paletas de 88 o 256 colores que son ampliamente utilizadas por los emuladores de terminal. Por defecto, se generan códigos de escape de color verdadero de 24 bits cuando los colores se especifican mediante tríos hexadecimales. Estos no son compatibles con todas las terminales. El propósito de este módulo es facilitar la definición de preferencias de color en un formato que pueda funcionar en una variedad de emuladores de terminal.

Aparte del color predeterminado, el estándar ANSI para códigos de escape de terminal proporciona ocho colores. El atributo brillante lleva esto a dieciséis. Estos colores básicos se utilizan comúnmente en aplicaciones de terminal debido a su amplia compatibilidad. Las paletas de colores expandidas de 88 y 256 colores también son comunes y, aunque los primeros dieciséis colores varían un poco entre terminales y configuraciones, estos agregan un conjunto de colores generalmente consistente y predecible.

Para utilizar el módulo zsh/nearcolor, solo necesita cargarse. A partir de entonces, cada vez que se especifique un color utilizando un trío hexadecimal, se comparará con cada uno de los colores disponibles y se seleccionará el más cercano. Los primeros dieciséis colores nunca se corresponden en este proceso debido a que son impredecibles.

No es posible detectar de forma fiable la compatibilidad con color verdadero en el emulador de terminal. Por lo tanto, se recomienda ser selectivo al cargar el módulo zsh/nearcolor. Por ejemplo, lo siguiente comprueba la variable de entorno COLORTERM:

[[ $COLORTERM = *(24bit|truecolor)* ]] || zmodload zsh/nearcolor

Tenga en cuenta que algunas terminales aceptan los códigos de escape de color verdadero pero los mapean internamente a una paleta más limitada de manera similar al módulo zsh/nearcolor.

EL MÓDULO ZSH/NEWUSER

El módulo zsh/newuser se carga al arrancar si está disponible, la opción RCS está establecida y la opción PRIVILEGED no está establecida (los tres son verdaderos por defecto). Esto ocurre inmediatamente después de que se ejecutan los comandos en el archivo global zshenv (típicamente /etc/zsh/zshenv), si los hay. Si el módulo no está disponible, el shell lo ignora silenciosamente; el administrador puede eliminar el módulo de $MODULE_PATH de forma segura si no se requiere.

Al cargarse, el módulo prueba si alguno de los archivos de inicio .zshenv, .zprofile, .zshrc o .zlogin existen en el directorio dado por la variable de entorno ZDOTDIR, o el directorio principal del usuario si no está establecido. La prueba no se realiza y el módulo detiene el procesamiento si el shell estaba en un modo de emulación (es decir, se había invocado como algún otro shell que no fuera zsh).

Si no se encontraron ninguno de los archivos de inicio, el módulo busca entonces el archivo newuser primero en un directorio sitewide, generalmente el directorio padre del directorio site-functions, y si no se encuentra, el módulo busca en un directorio específico de la versión, generalmente el padre del directorio functions que contiene funciones específicas de la versión. (Estos directorios se pueden configurar cuando se compila zsh utilizando las banderas --enable-site-scriptdir=dir y --enable-scriptdir=dir para configure, respectivamente; los valores predeterminados son prefix/share/zsh y prefix/share/zsh/$ZSH_VERSION donde el prefix predeterminado es /usr/local.)

Si se encuentra el archivo newuser, se fuente de la misma manera que un archivo de inicio. Se espera que el archivo contenga código para instalar archivos de inicio para el usuario, sin embargo, se ejecutará cualquier código de shell válido.

El módulo zsh/newuser se descarga incondicionalmente después.

Tenga en cuenta que es posible lograr exactamente el mismo efecto que el módulo zsh/newuser agregando código a /etc/zsh/zshenv. El módulo existe simplemente para permitir que el shell haga arreglos para nuevos usuarios sin la necesidad de intervención de los mantenedores de paquetes y administradores del sistema.

El script suministrado con el módulo invoca la función de shell zsh-newuser-install. Esta puede ser invocada directamente por el usuario incluso si el módulo zsh/newuser está deshabilitado. Tenga en cuenta, sin embargo, que si el módulo no está instalado, la función tampoco se instalará. La función está documentada en la sección `Funciones de configuración del usuario' en zshcontrib(1).

El job-state indica el estado en el que se encuentra actualmente todo el trabajo, uno de `running', `suspended', o `done'. Los pids son, por supuesto, los identificadores de proceso y el state describe el estado de ese proceso.

El manejo de las claves del array asociativo se describe como para jobdirs anteriormente.

Consulte el comando incorporado jobs para saber cómo se proporciona la información del trabajo en un subshell.

Este array asociativo mapea los nombres de directorios nombrados a las rutas que representan.

Este array asociativo mapea los nombres de usuario a las rutas de sus directorios de inicio.

Este array asociativo mapea los nombres de los grupos del sistema de los cuales el usuario actual es miembro a los identificadores de grupo correspondientes. Los contenidos son los mismos que los grupos que muestra el comando id.

Este array contiene los números de línea absolutos y los nombres de archivo correspondientes al punto donde se llamó a la función actual, el archivo fuente o el comando eval (si EVAL_LINENO está establecido). El array tiene la misma longitud que funcsourcetrace y functrace, pero difiere de funcsourcetrace en que la línea y el archivo son el punto de llamada, no el punto de definición, y difiere de functrace en que todos los valores son números de línea absolutos en archivos, en lugar de relativos al inicio de una función, si los hay.

EL MÓDULO ZSH/PCRE

El módulo zsh/pcre pone algunos comandos a disposición como incorporados:

pcre_compile [ -aimxs ] PCRE
Compila una expresión regular compatible con Perl.

La opción -a forzará a que el patrón esté anclado. La opción -i compilará un patrón insensible a mayúsculas y minúsculas. La opción -m compilará un patrón multilinea; es decir, ^ y $ coincidirán con saltos de línea dentro del patrón. La opción -x compilará un patrón extendido, en el que se ignoran los espacios en blanco y los comentarios #. La opción -s hace que el metacarácter punto coincida con todos los caracteres, incluidos los que indican salto de línea.

pcre_study
Estudia el PCRE previamente compilado, lo que puede resultar en una coincidencia más rápida.
pcre_match [ -v var ] [ -a arr ] [ -n offset ] [ -b ] string
Devuelve éxito si string coincide con el PCRE previamente compilado.

En caso de coincidencia exitosa, si la expresión captura subcadenas entre paréntesis, pcre_match establecerá el array match con esas subcadenas, a menos que se proporcione la opción -a, en cuyo caso establecerá el array arr. De manera similar, la variable MATCH se establecerá con la porción completa de la cadena que coincide, a menos que se proporcione la opción -v, en cuyo caso la variable var se establecerá. No se alteran variables si no hay una coincidencia exitosa. Una opción -n comienza la búsqueda de una coincidencia a partir de la posición de byte offset en string. Si se proporciona la opción -b, la variable ZPCRE_OP se establecerá con una cadena de pares de desplazamiento, que representa las posiciones de desplazamiento de bytes de la porción completa que coincide dentro de lai>cadena. Por ejemplo, un ZPCRE_OP establecido en "32 45" indica que la porción coincidente comenzó en el desplazamiento de bytes 32 y terminó en el desplazamiento de bytes 44. Aquí, la posición del desplazamiento de bytes 45 es la posición directamente después de la porción coincidente. Ten en cuenta que la posición del byte no es necesariamente la misma que la posición del carácter cuando intervienen caracteres UTF-8. En consecuencia, las posiciones de desplazamiento de bytes solo deben tenerse en cuenta en el contexto de utilizarlas para búsquedas posteriores en cadena, utilizando una posición de desplazamiento como argumento para la opción -n. Esto se usa principalmente para implementar la funcionalidad de "encontrar todas las coincidencias no superpuestas".

Un ejemplo simple de "encontrar todas las coincidencias no superpuestas":

cadena="Los siguientes códigos postales: 78884 90210 99513"
pcre_compile -m "\d{5}"
acumul=()
pcre_match -b -- $cadena
while [[ $? -eq 0 ]] do
    b=($=ZPCRE_OP)
    acumul+=$MATCH
    pcre_match -b -n $b[2] -- $cadena
done
print -l $acumul

El módulo zsh/pcre pone a disposición la siguiente condición de prueba:

expr -pcre-match pcre
Coincide una cadena con una expresión regular compatible con perl.

Por ejemplo,

[[ "$texto" -pcre-match ^d+$ ]] &&
print la variable texto contiene solo "d".

Si la opción REMATCH_PCRE está establecida, el operador =~ es equivalente a -pcre-match, y la opción NO_CASE_MATCH puede ser utilizada. Ten en cuenta que NO_CASE_MATCH nunca se aplica a la orden interna pcre_match, usa en su lugar el modificador -i de pcre_compile.

EL MÓDULO ZSH/PARAM/PRIVATE

El módulo zsh/param/private se utiliza para crear parámetros cuyo alcance se limita al cuerpo de la función actual, y *no* a otras funciones llamadas por la función actual.

Este módulo proporciona una única orden interna cargada automáticamente:

private [ {+|-}AHUahlmrtux ] [ {+|-}EFLRZi [ n ] ] [ nombre[=valor] ... ]
La orden interna private acepta todas las opciones y argumentos que local (zshbuiltins(1)) excepto la opción `-T'. Los parámetros enlazados no pueden ser hechos privados.

La opción `-p' es actualmente un no-op porque el estado de los parámetros privados no puede ser recargado de forma fiable. Esto también se aplica a la impresión de parámetros privados con `typeset -p'.

Si se utiliza en el nivel superior (fuera del ámbito de una función), private crea un parámetro normal de la misma manera que declare o typeset. Se imprime una advertencia sobre esto si WARN_CREATE_GLOBAL está establecido (zshoptions(1)). Usado dentro del ámbito de una función, private crea un parámetro local similar a uno declarado con local, excepto por las propiedades especiales señaladas abajo.

Los parámetros especiales que exponen o manipulan el estado interno del intérprete, como ARGC, argv, COLUMNS, LINES, UID, EUID, IFS, PROMPT, RANDOM, SECONDS, etc., no pueden ser privados a menos que se use la opción `-h' para ocultar el significado especial del parámetro. Esto puede cambiar en el futuro.

Al igual que con otros equivalentes de typeset, private es tanto una orden interna como una palabra reservada, por lo que los arrays pueden ser asignados con la sintaxis de lista de palabras entre paréntesis nombre=(valor...). Sin embargo, la palabra reservada `private' no está disponible hasta que se cargue zsh/param/private, por lo que se debe tener cuidado con el orden de ejecución y el análisis para las definiciones de funciones que usan private. Para compensar esto, el módulo también agrega la opción `-P' a la orden interna `local' para declarar parámetros privados.

Por ejemplo, esta construcción falla si zsh/param/private aún no se ha cargado cuando se define `bad_declaration':

bad_declaration() {
  zmodload zsh/param/private
  private array=( uno dos tres )
}

Esta construcción funciona porque local ya es una palabra clave, y el módulo se carga antes de que se ejecute la instrucción:

good_declaration() {
  zmodload zsh/param/private
  local -P array=( uno dos tres )
}

Lo siguiente es utilizable en scripts pero puede tener problemas con autoload:

zmodload zsh/param/private
iffy_declaration() {
  private array=( uno dos tres )
}

La orden interna private siempre puede usarse con asignaciones escalares y para declaraciones sin asignaciones.

Los parámetros declarados con private tienen las siguientes propiedades:

•
Dentro del cuerpo de la función donde se declara, el parámetro se comporta como local, excepto como se señaló anteriormente para parámetros enlazados o especiales.
•
El tipo de un parámetro declarado privado no puede cambiarse en el ámbito donde se declaró, incluso si el parámetro no está establecido. Por lo tanto, un array no puede ser asignado a un escalar privado, etc.
•
Dentro de cualquier otra función llamada por la función declarante, el parámetro privado *NO* oculta otros parámetros del mismo nombre, por lo que, por ejemplo, un parámetro global del mismo nombre es visible y puede ser asignado o eliminado. Esto incluye llamadas a funciones anónimas, aunque eso también puede cambiar en el futuro. Sin embargo, el nombre privado no puede ser creado fuera del ámbito local cuando no fue declarado previamente.
•
Un privado exportado permanece en el entorno de los ámbitos internos pero aparece como no establecido para el shell actual en esos ámbitos. En general, se debe evitar la exportación de parámetros privados.

Ten en cuenta que esto difiere del ámbito estático definido por lenguajes compilados derivados de C, en el sentido de que una nueva llamada a la misma función crea un nuevo ámbito, es decir, el parámetro todavía está asociado con la pila de llamadas en lugar de con la definición de la función. Difiere de `typeset -S' de ksh en que la sintaxis utilizada para definir la función no tiene ninguna influencia en si el ámbito del parámetro se respeta.

EL MÓDULO ZSH/REGEX

El módulo zsh/regex pone a disposición la siguiente condición de prueba:

expr -regex-match regex
Coincide una cadena con una expresión regular extendida POSIX. En una coincidencia exitosa, la porción coincidente de la cadena normalmente se colocará en la variable MATCH. Si hay paréntesis de captura dentro de la expresión regular, entonces el array match contendrá esos. Si la coincidencia no es exitosa, las variables no se alterarán.

Por ejemplo,

[[ alfabético -regex-match ^a([^a]+)a([^a]+)a ]] &&
print -l $MATCH X $match

Si la opción REMATCH_PCRE no está establecida, el operador =~ cargará automáticamente este módulo según sea necesario e invocará al operador -regex-match.

Si BASH_REMATCH está establecido, entonces el array BASH_REMATCH se establecerá en lugar de MATCH y match.

Ten en cuenta que la lógica del módulo zsh/regex depende del sistema anfitrión. El mismo par expr y regex podría producir resultados diferentes en plataformas diferentes si se proporciona una regex con sintaxis no estándar.

Por ejemplo, no hay sintaxis definida en el estándar de expresiones regulares extendidas POSIX para coincidir con un límite de palabra. Tanto libc de GNU como libc de BSD proporcionan sintaxis como extensiones (\b y [[:<:]]/[[:>:]] respectivamente), pero ninguna de estas sintaxis es compatible con ambas implementaciones.

Consulta las páginas del manual regcomp(3) y re_format(7) de tu sistema para conocer la sintaxis soportada localmente.

The zsh/net/socket module makes available one builtin command:

ZSH/STAT MODULE

The zsh/stat module makes available one builtin command under two possible names:

zstat [ -gnNolLtTrs ] [ -f fd ] [ -H hash ] [ -A array ] [ -F fmt ]
[ +element ] [ file ... ]
stat ...
The command acts as a front end to the stat system call (see stat(2)). The same command is provided with two names; as the name stat is often used by an external command it is recommended that only the zstat form of the command is used. This can be arranged by loading the module with the command `zmodload -F zsh/stat b:zstat'.

If the stat call fails, the appropriate system error message printed and status 1 is returned. The fields of struct stat give information about the files provided as arguments to the command. In addition to those available from the stat call, an extra element `link' is provided. These elements are:

device
The number of the device on which the file resides.
inode
The unique number of the file on this device (`inode' number).
mode
The mode of the file; that is, the file's type and access permissions. With the -s option, this will be returned as a string corresponding to the first column in the display of the ls -l command.
nlink
The number of hard links to the file.
uid
The user ID of the owner of the file. With the -s option, this is displayed as a user name.
gid
The group ID of the file. With the -s option, this is displayed as a group name.
rdev
The raw device number. This is only useful for special devices.
size
The size of the file in bytes.
atime
mtime
ctime
The last access, modification and inode change times of the file, respectively, as the number of seconds since midnight GMT on 1st January, 1970. With the -s option, these are printed as strings for the local time zone; the format can be altered with the -F option, and with the -g option the times are in GMT.
blksize
The number of bytes in one allocation block on the device on which the file resides.
block
The number of disk blocks used by the file.
link
If the file is a link and the -L option is in effect, this contains the name of the file linked to, otherwise it is empty. Note that if this element is selected (``zstat +link'') then the -L option is automatically used.

A particular element may be selected by including its name preceded by a `+' in the option list; only one element is allowed. The element may be shortened to any unique set of leading characters. Otherwise, all elements will be shown for all files.

Options:

-A array
Instead of displaying the results on standard output, assign them to an array, one struct stat element per array element for each file in order. In this case neither the name of the element nor the name of the files appears in array unless the -t or -n options were given, respectively. If -t is given, the element name appears as a prefix to the appropriate array element; if -n is given, the file name appears as a separate array element preceding all the others. Other formatting options are respected.
-H hash
Similar to -A, but instead assign the values to hash. The keys are the elements listed above. If the -n option is provided then the name of the file is included in the hash with key name.
-f fd
Use the file on file descriptor fd instead of named files; no list of file names is allowed in this case.
-F fmt
Supplies a strftime (see strftime(3)) string for the formatting of the time elements. The format string supports all of the zsh extensions described in the section EXPANSION OF PROMPT SEQUENCES in zshmisc(1). In particular, -F %s.%N can be used to show timestamps with nanosecond precision if supported by the system. The -s option is implied.
-g
Show the time elements in the GMT time zone. The -s option is implied.
-l
List the names of the type elements (to standard output or an array as appropriate) and return immediately; arguments, and options other than -A, are ignored.
-L
Perform an lstat (see lstat(2)) rather than a stat system call. In this case, if the file is a link, information about the link itself rather than the target file is returned. This option is required to make the link element useful. It's important to note that this is the exact opposite from ls(1), etc.
-n
Always show the names of files. Usually these are only shown when output is to standard output and there is more than one file in the list.
-N
Never show the names of files.
-o
If a raw file mode is printed, show it in octal, which is more useful for human consumption than the default of decimal. A leading zero will be printed in this case. Note that this does not affect whether a raw or formatted file mode is shown, which is controlled by the -r and -s options, nor whether a mode is shown at all.
-r
Print raw data (the default format) alongside string data (the -s format); the string data appears in parentheses after the raw data.
-s
Print mode, uid, gid and the three time elements as strings instead of numbers. In each case the format is like that of ls -l.
-t
Always show the type names for the elements of struct stat. Usually these are only shown when output is to standard output and no individual element has been selected.
-T
Never show the type names of the struct stat elements.

Este comando imprime el mensaje de error asociado con errno, un número de error del sistema, seguido de una nueva línea a la salida estándar de error.

exec {fd}>&-
sysread [ -c countvar ] [ -i infd ] [ -o outfd ]
[ -s bufsize ] [ -t timeout ] [ param ]
Realiza una única lectura del sistema desde el descriptor de archivo infd, o cero si no se proporciona. El resultado de la lectura se almacena en param o en REPLY si no se proporciona. Si se proporciona countvar, el número de bytes leídos se asigna al parámetro con el nombre countvar.

El número máximo de bytes a leer es bufsize o 8192 si no se proporciona, sin embargo, el comando regresa tan pronto como se lee cualquier cantidad de bytes con éxito.

Si se proporciona timeout, especifica un tiempo de espera en segundos, que puede ser cero para sondear el descriptor de archivo. Esto se maneja mediante la llamada al sistema poll si está disponible, de lo contrario, mediante la llamada al sistema select si está disponible.

Si se proporciona outfd, se intenta escribir todos los bytes recién leídos en el descriptor de archivo outfd. Si esto falla, debido a un error del sistema distinto de EINTR o debido a un error interno de zsh durante una interrupción, los bytes leídos pero no escritos se almacenan en el parámetro con el nombre param si se proporciona (no se usa un valor predeterminado en este caso), y el número de bytes leídos pero no escritos se almacena en el parámetro con el nombre countvar si se proporciona. Si tuvo éxito, countvar contiene el número total de bytes transferidos, como de costumbre, y param no se establece.

El error EINTR (llamada al sistema interrumpida) se maneja internamente para que las interrupciones del shell sean transparentes para el llamador. Cualquier otro error provoca un retorno.

Los posibles estados de retorno son

0
Se leyó al menos un byte de datos con éxito y, si corresponde, se escribió.
1
Hubo un error en los parámetros del comando. Este es el único error para el cual se imprime un mensaje en la salida estándar de error.
2
Hubo un error en la lectura, o en el sondeo del descriptor de archivo de entrada para un tiempo de espera. El parámetro ERRNO proporciona el error.
3
Se leyeron datos con éxito, pero hubo un error al escribirlos en outfd. El parámetro ERRNO proporciona el error.
4
El intento de lectura expiró. Tenga en cuenta que esto no establece ERRNO ya que no es un error del sistema.
5
No ocurrió ningún error del sistema, pero se leyeron cero bytes. Esto generalmente indica el final del archivo. Los parámetros se establecen según las reglas habituales; no se intenta ninguna escritura en outfd.
sysseek [ -u fd ] [ -w start|end|current ] offset
La posición actual del archivo en la que tendrán lugar las futuras lecturas y escrituras se ajusta al desplazamiento de bytes especificado. El offset se evalúa como una expresión matemática. La opción -u permite especificar el descriptor de archivo. Por defecto, el desplazamiento se especifica en relación con el inicio del archivo, pero con la opción -w, es posible especificar que el desplazamiento debe ser relativo a la posición actual o al final del archivo.
syswrite [ -c countvar ] [ -o outfd ] data
Los datos (una única cadena de bytes) se escriben en el descriptor de archivo outfd, o 1 si no se proporciona, utilizando la llamada al sistema write. Se pueden utilizar múltiples operaciones de escritura si la primera no escribe todos los datos.

Si se proporciona countvar, el número de bytes escritos se almacena en el parámetro con el nombre countvar; es posible que no sea la longitud completa de data si ocurrió un error.

El error EINTR (llamada al sistema interrumpida) se maneja internamente mediante reintentos; de lo contrario, un error provoca que el comando retorne. Por ejemplo, si el descriptor de archivo está configurado para salida no bloqueante, un error EAGAIN (en algunos sistemas, EWOULDBLOCK) puede hacer que el comando retorne prematuramente.

El estado de retorno puede ser 0 para éxito, 1 para un error en los parámetros del comando, o 2 para un error en la escritura; en este último caso, no se imprime ningún mensaje de error, pero el parámetro ERRNO reflejará el error que ocurrió.

zsystem flock [ -t timeout ] [ -i intervalo ] [ -f var ] [-er] archivo
zsystem flock -u fd_expr
El subcomando flock de zsystem realiza bloqueos de archivo consultivos (a través de la llamada al sistema fcntl(2)) sobre el contenido completo del archivo dado. Esta forma de bloqueo requiere que los procesos que acceden al archivo cooperen; su uso más obvio es entre dos instancias del propio shell.

En la primera forma, el archivo nombrado, que debe existir previamente, se bloquea abriendo un descriptor de archivo al archivo y aplicando un bloqueo al descriptor de archivo. El bloqueo termina cuando el proceso del shell que creó el bloqueo sale; por lo tanto, a menudo es conveniente crear bloqueos de archivo dentro de subshells, ya que el bloqueo se libera automáticamente cuando sale la subshell. Tenga en cuenta que el uso del comando incorporado print con la opción -u, como efecto secundario, liberará el bloqueo, al igual que la redirección al archivo en el shell que tiene el bloqueo. Para evitar esto, use una subshell, por ejemplo, `(print mensaje) >> archivo'. Se devuelve el estado 0 si el bloqueo tiene éxito, de lo contrario, el estado 1.

En la segunda forma, el descriptor de archivo dado por la expresión aritmética fd_expr se cierra, liberando un bloqueo. El descriptor de archivo se puede consultar utilizando la forma `-f var' durante el bloqueo; en un bloqueo exitoso, la variable de shell var se establece en el descriptor de archivo utilizado para el bloqueo. El bloqueo se liberará si el descriptor de archivo se cierra por cualquier otro medio, por ejemplo, usando `exec {var}>&-'; sin embargo, la forma descrita aquí realiza una verificación de seguridad de que el descriptor de archivo se está utilizando para el bloqueo de archivos.

Por defecto, el shell espera indefinidamente a que el bloqueo tenga éxito. La opción -t timeout especifica un tiempo de espera para el bloqueo en segundos; se permiten fracciones de segundo. Durante este período, el shell intentará bloquear el archivo cada intervalo segundos si se proporciona la opción -i intervalo, de lo contrario, una vez por segundo. (Este intervalo se acorta antes del último intento si es necesario, de modo que el shell espere solo hasta el timeout y no más). Si el intento se agota, se devuelve el estado 2.

(Nota: timeout está limitado a 2^30-1 segundos (aproximadamente 34 años), e intervalo a 0.999 * LONG_MAX microsegundos (solo unos 35 minutos en sistemas de 32 bits).)

Si se proporciona la opción -e, el descriptor de archivo para el bloqueo se conserva cuando el shell utiliza exec para iniciar un nuevo proceso; de lo contrario, se cierra en ese momento y se libera el bloqueo.

Si se proporciona la opción -r, el bloqueo es solo para lectura; de lo contrario, es para lectura y escritura. El descriptor de archivo se abre en consecuencia.

EL MÓDULO ZSH/NET/TCP

El módulo zsh/net/tcp pone a disposición un comando incorporado:

ztcp [ -acflLtv ] [ -d fd ] [ args ]
ztcp se implementa como un incorporado para permitir el uso completo de la edición de línea de comandos del shell, E/S de archivos y mecanismos de control de trabajos.

Si ztcp se ejecuta sin opciones, mostrará el contenido de su tabla de sesiones.

Si se ejecuta solo con la opción -L, mostrará el contenido de la tabla de sesiones en un formato adecuado para el análisis automático. La opción se ignora si se proporciona con un comando para abrir o cerrar una sesión. La salida consta de un conjunto de líneas, una por sesión, cada una que contiene los siguientes elementos separados por espacios:

Descriptor de archivo
El descriptor de archivo en uso para la conexión. Para las conexiones de entrada (I) y salida (O) normales, estas pueden ser leídas y escritas por los mecanismos habituales del shell. Sin embargo, solo deben cerrarse con `ztcp -c'.
Tipo de conexión
Una letra que indica cómo se creó la sesión:
Z
Una sesión creada con el comando zftp.
L
Una conexión abierta para escuchar con `ztcp -l'.
I
Una conexión de entrada aceptada con `ztcp -a'.
O
Una conexión de salida creada con `ztcp host ...'.
El host local
Esto generalmente se establece en una dirección IP de ceros, ya que la dirección del localhost es irrelevante.
El puerto local
Es probable que sea cero a menos que la conexión sea para escuchar.
El host remoto
Este es el nombre de dominio completo del par, si está disponible, de lo contrario, una dirección IP. Es una dirección IP de ceros para una sesión abierta para escuchar.
El puerto remoto
Esto es cero para una conexión abierta para escuchar.

Conexiones de Salida

ztcp [ -v ] [ -d fd ] host [ port ]
Abre una nueva conexión TCP a host. Si se omite el puerto, se usará el puerto 23 por defecto. La conexión se agregará a la tabla de sesiones y el parámetro del shell REPLY se establecerá en el descriptor de archivo asociado con esa conexión.

Si se especifica -d, su argumento se tomará como el descriptor de archivo de destino para la conexión.

Para obtener una salida más detallada, use -v.

Conexiones de Entrada

ztcp -l [ -v ] [ -d fd ] port
ztcp -l abrirá un socket que escucha en el puerto TCP port. El socket se agregará a la tabla de sesiones y el parámetro del shell REPLY se establecerá en el descriptor de archivo asociado con ese oyente.

Si se especifica -d, su argumento se tomará como el descriptor de archivo de destino para la conexión.

Para obtener una salida más detallada, use -v.

ztcp -a [ -tv ] [ -d targetfd ] listenfd
ztcp -a aceptará una conexión entrante al puerto asociado con listenfd. La conexión se agregará a la tabla de sesiones y el parámetro del shell REPLY se establecerá en el descriptor de archivo asociado con la conexión entrante.

Si se especifica -d, su argumento se tomará como el descriptor de archivo de destino para la conexión.

Si se especifica -t, ztcp devolverá si no hay una conexión entrante pendiente. De lo contrario, esperará una.

Para obtener una salida más detallada, use -v.

Cerrando Conexiones

ztcp -cf [ -v ] [ fd ]
ztcp -c [ -v ] [ fd ]
ztcp -c cerrará el socket asociado con fd. El socket se eliminará de la tabla de sesiones. Si no se especifica fd, ztcp cerrará todo en la tabla de sesiones.

Normalmente, los sockets registrados por zftp (consulte zshmodules(1)) no se pueden cerrar de esta manera. Para forzar el cierre de un socket de este tipo, use -f.

Para obtener una salida más detallada, use -v.

Ejemplo

Aquí se explica cómo crear una conexión TCP entre dos instancias de zsh. Necesitamos elegir un puerto no asignado; aquí usamos el puerto 5123 elegido aleatoriamente.

En host1,

zmodload zsh/net/tcp
ztcp -l 5123
listenfd=$REPLY
ztcp -a $listenfd
fd=$REPLY
El penúltimo comando se bloquea hasta que haya una conexión entrante.

Ahora cree una conexión desde host2 (que, por supuesto, puede ser la misma máquina):

zmodload zsh/net/tcp
ztcp host1 5123
fd=$REPLY

Ahora, en cada host, $fd contiene un descriptor de archivo para hablar con el otro. Por ejemplo, en host1:

print This is a message >&$fd
y en host2: 
read -r line <&$fd; print -r - $line
imprime `This is a message'.

Para limpiar, en host1:

ztcp -c $listenfd
ztcp -c $fd
y en host2 
ztcp -c $fd

El módulo zsh/watch se puede utilizar para informar cuándo los usuarios específicos inician o cierran sesión. Esto se controla a través de los siguientes parámetros.

LOGCHECK
El intervalo en segundos entre comprobaciones de actividad de inicio/cierre de sesión utilizando el parámetro watch.
watch <S> <Z> (WATCH <S>)
Un array (lista separada por dos puntos) de eventos de inicio/cierre de sesión para informar.

Si contiene la palabra única `all', se informan todos los eventos de inicio/cierre de sesión. Si contiene la palabra única `notme', se informan todos los eventos como con `all' excepto $USERNAME.

Una entrada en esta lista puede co

consta de un nombre de usuario, un `@' seguido de un nombre de host remoto, y un `%' seguido de una línea (tty). Cualquiera de estos puede ser un patrón (asegúrate de citarlos al asignarlos a watch para que no genere archivos inmediatamente); se respeta la configuración de la opción EXTENDED_GLOB. El formato de los informes de inicio/cierre de sesión si el parámetro watch está establecido. El valor predeterminado es `%n has %a %l from %m'. Reconoce las siguientes secuencias de escape:

El nombre del usuario que inició/cerró sesión.
%a
La acción observada, es decir, "logged on" o "logged off".
%l
La línea (tty) en la que el usuario ha iniciado sesión.
%M
El nombre de host completo del host remoto.
%m
El nombre de host hasta el primer `.'. Si solo está disponible la dirección IP o el campo utmp contiene el nombre de una pantalla de X-windows, se imprime el nombre completo.

%F{color} (%f)
Iniciar (detener) el uso de un color frontal diferente.
%K{color} (%k)
Iniciar (detener) el uso de un color de fondo diferente.
%S (%s)
Iniciar (detener) el modo destacado.
%U (%u)
Iniciar (detener) el modo de subrayado.
%B (%b)
Iniciar (detener) el modo negrita.
%t
%@
La hora, en formato de 12 horas, am/pm.
%T
La hora, en formato de 24 horas.
%w
La fecha en formato `día-dd'.
%W
La fecha en formato `mm/dd/yy'.
%D
La fecha en formato `yy-mm-dd'.
%D{cadena}
La fecha formateada como cadena usando la función strftime, con extensiones de zsh según se describe en la EXPANSIÓN DE SECUENCIAS DE PROMPT en zshmisc(1).
%(x:texto-verdadero:texto-falso)
Especifica una expresión ternaria. El carácter que sigue a x es arbitrario; el mismo carácter se utiliza para separar el texto del resultado "verdadero" del resultado "falso". Tanto el separador como el paréntesis derecho pueden escaparse con una barra invertida. Las expresiones ternarias pueden anidarse.

El carácter de prueba x puede ser cualquiera de `l', `n', `m' o `M', que indican un resultado 'verdadero' si la secuencia de escape correspondiente devuelve un valor no vacío; o puede ser `a', que indica un resultado 'verdadero' si el usuario vigilado ha iniciado sesión, o 'falso' si ha cerrado sesión. Otros caracteres no evalúan ni a verdadero ni a falso; la expresión completa se omite en este caso.

Si el resultado es 'verdadero', entonces el texto-verdadero se formatea de acuerdo con las reglas anteriores y se imprime, y el texto-falso se omite. Si es 'falso', se omite el texto-verdadero y se formatea e imprime el texto-falso. Una o ambas ramas pueden estar vacías, pero ambos separadores deben estar presentes en cualquier caso.

EL MÓDULO ZSH/ZFTP

El módulo zsh/zftp pone a disposición un comando incorporado:

zftp subcomando [ argumentos ]
El módulo zsh/zftp es un cliente para FTP (protocolo de transferencia de archivos). Está implementado como un comando incorporado para permitir el uso completo de la edición de línea de comandos del shell, la E/S de archivos y los mecanismos de control de trabajos. A menudo, los usuarios accederán a él a través de funciones de shell que proporcionan una interfaz más potente; se proporciona un conjunto con la distribución zsh y se describe en zshzftpsys(1). Sin embargo, el comando zftp es totalmente utilizable por sí mismo.

Todos los comandos consisten en el nombre del comando zftp seguido de el nombre de un subcomando. Estos se enumeran a continuación. Se supone que el estado de retorno de cada subcomando refleja el éxito o el fracaso de la operación remota. Consulte la descripción de la variable ZFTP_VERBOSE para obtener más información sobre cómo se pueden imprimir las respuestas del servidor.

Subcomandos

open host[:puerto] [ usuario [ contraseña [ cuenta ] ] ]
Abre una nueva sesión FTP a host, que puede ser el nombre de un host conectado por TCP/IP o un número IP en la notación de puntos estándar. Si el argumento tiene el formato host:puerto, abre una conexión al puerto TCP puerto en lugar del puerto FTP estándar 21. Este puede ser el nombre de un servicio TCP o un número: consulte la descripción de ZFTP_PORT a continuación para obtener más información.

Si se utilizan direcciones IPv6 en formato de dos puntos, el host debe estar rodeado de corchetes entrecomillados para distinguirlo del puerto, por ejemplo, '[fe80::203:baff:fe02:8b56]'. Por coherencia, esto se permite con todas las formas de host.

Los argumentos restantes se pasan al subcomando login. Tenga en cuenta que si no se proporcionan argumentos más allá de host, open *no* llamará automáticamente a login. Si no se proporcionan argumentos en absoluto, open utilizará los parámetros establecidos por el subcomando params.

Después de un open exitoso, las variables del shell ZFTP_HOST, ZFTP_PORT, ZFTP_IP y ZFTP_SYSTEM están disponibles; consulte `Variables' a continuación.

login [ nombre [ contraseña [ cuenta ] ] ]
user [ nombre [ contraseña [ cuenta ] ] ]
Inicia sesión del usuario nombre con los parámetros contraseña y cuenta. Cualquiera de los parámetros puede omitirse y se leerá de la entrada estándar si es necesario (nombre siempre es necesario). Si la entrada estándar es una terminal, se imprimirá una solicitud para cada uno en la salida de error estándar y la contraseña no se mostrará. Si no se utilizan alguno de los parámetros, se imprime un mensaje de advertencia.

Después de un inicio de sesión exitoso, las variables del shell ZFTP_USER, ZFTP_ACCOUNT y ZFTP_PWD están disponibles; consulte `Variables' a continuación.

Este comando puede volver a emitirse cuando un usuario ya ha iniciado sesión, y el servidor se reinicializará primero para un nuevo usuario.

params [ host [ usuario [ contraseña [ cuenta ] ] ] ]
params -
Almacena los parámetros dados para un posterior comando open sin argumentos. Solo los proporcionados en la línea de comandos se recordarán. Si no se proporcionan argumentos, se imprimen los parámetros actualmente establecidos, aunque la contraseña aparecerá como una línea de asteriscos; el estado de retorno es uno si no se establecieron parámetros, cero en caso contrario.

Cualquiera de los parámetros puede especificarse como un `?', que puede necesitar ser entrecomillado para protegerlo de la expansión del shell. En este caso, el parámetro apropiado se leerá de stdin como con el subcomando login, incluido el manejo especial de contraseña. Si el `?' va seguido de una cadena, esa se utiliza como indicación para leer el parámetro en lugar del mensaje predeterminado (cualquier puntuación y espacio en blanco necesarios deben incluirse al final de la indicación). La primera letra del parámetro (solo) puede entrecomillarse con una `\'; por lo tanto, un argumento "\\$word" garantiza que la cadena del parámetro del shell $word se tratará literalmente, independientemente de si comienza con un `?'.

Si en su lugar se proporciona un solo `-', los parámetros existentes, si los hay, se eliminan. En ese caso, llamar a open sin argumentos provocará un error.

La lista de parámetros no se elimina después de un close, sin embargo, se eliminará si el módulo zsh/zftp se descarga.

Por ejemplo,

zftp params ftp.elsewhere.xx juser '?Password for juser: '

almacenará el host ftp.elsewhere.xx y el usuario juser y luego pedirá al usuario la contraseña correspondiente con la indicación dada.

test
Prueba la conexión; si el servidor ha informado que ha cerrado la conexión (quizás debido a un tiempo de espera), devuelve el estado 2; si de todos modos no había ninguna conexión abierta, devuelve el estado 1; de lo contrario, devuelve el estado 0. El subcomando test es silencioso, aparte de los mensajes impresos por el mecanismo de $ZFTP_VERBOSE, o mensajes de error si la conexión se cierra. No hay sobrecarga de red para esta prueba.

La prueba solo se admite en sistemas que tengan las llamadas al sistema select(2) o poll(2); de lo contrario, se imprimirá el mensaje `no soportado en este sistema'.

El subcomando test se llamará automáticamente al inicio de cualquier otro subcomando para la sesión actual cuando haya una conexión abierta.

cd directorio
Cambia el directorio remoto a directorio. También altera la variable del shell ZFTP_PWD.
cdup
Cambia el directorio remoto al directorio superior en el árbol de directorios. Tenga en cuenta que cd .. también funcionará correctamente en sistemas no UNIX.
dir [ arg ... ]
Proporciona una lista (detallada) del directorio remoto. Los args se pasan directamente al servidor. El comportamiento del comando depende de la implementación, pero un UNIX

rename old-name new-name
Renombra el archivo old-name a new-name en el servidor.
site arg ...
Envía un comando específico del host al servidor. Probablemente solo lo necesitará si el servidor se lo indica.
quote arg ...
Envía la secuencia de comandos FTP cruda al servidor. Debe estar familiarizado con el conjunto de comandos FTP definido en RFC959 antes de hacerlo. Los comandos útiles pueden incluir STAT y HELP. Tenga en cuenta también el mecanismo para devolver mensajes como se describe para la variable ZFTP_VERBOSE a continuación, en particular que todos los mensajes de la conexión de control se envían al error estándar.
close
quit
Cierra la conexión de datos actual. Esto desactiva los parámetros del shell ZFTP_HOST, ZFTP_PORT, ZFTP_IP, ZFTP_SYSTEM, ZFTP_USER, ZFTP_ACCOUNT, ZFTP_PWD, ZFTP_TYPE y ZFTP_MODE.
session [ sessname ]
Permite usar múltiples sesiones FTP a la vez. El nombre de la sesión es una cadena arbitraria de caracteres; la sesión predeterminada se llama `default'. Si este comando se llama sin un argumento, listará todas las sesiones actuales; con un argumento, cambiará a la sesión existente llamada sessname, o creará una nueva sesión con ese nombre.

Cada sesión recuerda el estado de la conexión, el conjunto de parámetros del shell específicos de la conexión (el mismo conjunto que se desactiva cuando se cierra una conexión, como se indica en la descripción de close) y cualquier parámetro de usuario especificado con el subcomando params. Cambiar a una sesión anterior restaura esos valores; cambiar a una nueva sesión los inicializa de la misma manera que si zftp se hubiera cargado recientemente. El nombre de la sesión actual se da por el parámetro ZFTP_SESSION.

rmsession [ sessname ]
Elimina una sesión; si no se proporciona un nombre, se elimina la sesión actual. Si se elimina la sesión actual, la sesión existente más antigua se convierte en la nueva sesión actual; de lo contrario, la sesión actual no cambia. Si la sesión que se elimina es la única, se crea una nueva sesión llamada `default' y se convierte en la sesión actual; tenga en cuenta que esta es una nueva sesión, incluso si la sesión que se elimina también se llama `default'. Se recomienda no eliminar sesiones mientras los comandos en segundo plano que utilizan zftp todavía están activos.

Parámetros

Los siguientes parámetros del shell son utilizados por zftp. Actualmente ninguno de ellos es especial.

ZFTP_TMOUT
Entero. El tiempo en segundos para esperar a que una operación de red se complete antes de devolver un error. Si no se establece cuando se carga el módulo, se le asignará el valor predeterminado de 60. Un valor de cero desactiva los tiempos de espera. Si ocurre un tiempo de espera en la conexión de control, esta se cerrará. Use un valor mayor si esto ocurre con demasiada frecuencia.
ZFTP_IP
Solo lectura. La dirección IP de la conexión actual en notación de puntos.
ZFTP_HOST
Solo lectura. El nombre de host del servidor remoto actual. Si el host se abrió como un número IP, ZFTP_HOST contiene ese número en su lugar; esto ahorra la sobrecarga de una búsqueda de nombres, ya que los números IP se usan con mayor frecuencia cuando un servidor de nombres no está disponible.
ZFTP_PORT
Solo lectura. El número del puerto TCP remoto al que está abierta la conexión (incluso si el puerto se especificó originalmente como un servicio con nombre). Por lo general, este es el puerto FTP estándar, 21.

En el improbable caso de que su sistema no tenga las funciones de conversión apropiadas, esto aparece en orden de bytes de red. Si su sistema es little-endian, el puerto consta de dos bytes intercambiados y el puerto estándar se informará como 5376. En ese caso, los puertos numéricos pasados a zftp open también deberán estar en este formato.

ZFTP_SYSTEM
Solo lectura. La cadena de tipo de sistema devuelta por el servidor en respuesta a una solicitud FTP SYST. El caso más interesante es una cadena que comienza "UNIX Type: L8", que garantiza la máxima compatibilidad con un host UNIX local.
ZFTP_TYPE
Solo lectura. El tipo que se utilizará para las transferencias de datos, ya sea `A' o `I'. Utilice el subcomando type para cambiar esto.
ZFTP_USER
Solo lectura. El nombre de usuario actualmente conectado, si lo hay.
ZFTP_ACCOUNT
Solo lectura. El nombre de cuenta del usuario actual, si lo hay. La mayoría de los servidores no requieren un nombre de cuenta.
ZFTP_PWD
Solo lectura. El directorio actual en el servidor.
ZFTP_CODE
Solo lectura. El código de tres dígitos de la última respuesta FTP del servidor como una cadena. Esto aún se puede leer después de que se cierra la conexión y no cambia cuando cambia la sesión actual.
ZFTP_REPLY
Solo lectura. La última línea de la última respuesta enviada por el servidor. Esto aún se puede leer después de que se cierra la conexión y no cambia cuando cambia la sesión actual.
ZFTP_SESSION
Solo lectura. El nombre de la sesión FTP actual; consulte la descripción del subcomando session.
ZFTP_PREFS
Una cadena de preferencias para alterar aspectos del comportamiento de zftp. Cada preferencia es un solo carácter. Los siguientes están definidos:
P
Pasivo: intentar que el servidor remoto inicie transferencias de datos. Esto es ligeramente más eficiente que el modo sendport. Si la letra **S** ocurre más tarde en la cadena, **zftp** usará el modo sendport si el modo pasivo no está disponible.
S
Sendport: inicia transferencias mediante el comando FTP **PORT**. Si esto ocurre antes que cualquier **P** en la cadena, el modo pasivo nunca se intentará.
D
Dumb: usa solo el mínimo de comandos FTP. Esto evita que las variables **ZFTP_SYSTEM** y **ZFTP_PWD** se establezcan y hará que todas las conexiones tengan el tipo ASCII por defecto. Puede evitar que **ZFTP_SIZE** se establezca durante una transferencia si el servidor no lo envía de todas formas (muchos servidores lo hacen).

Si **ZFTP_PREFS** no está configurada cuando se carga **zftp**, se establecerá por defecto a `**PS**', es decir, usar el modo pasivo si está disponible, de lo contrario, volverá al modo sendport.

ZFTP_VERBOSE
Una cadena de dígitos entre 0 y 5 inclusive, que especifica qué respuestas del servidor deben imprimirse. Todas las respuestas van a la salida de error estándar. Si alguno de los números del 1 al 5 aparece en la cadena, las respuestas crudas del servidor con códigos de respuesta que comiencen con ese dígito se imprimirán en la salida de error estándar. El primer dígito del código de respuesta de tres dígitos se define según RFC959 para corresponder a:
1.
Una respuesta preliminar positiva.
2.
Una respuesta de finalización positiva.
3.
Una respuesta intermedia positiva.
4.
Una respuesta de finalización negativa transitoria.
5.
Una respuesta de finalización negativa permanente.

Cabe señalar que, por razones desconocidas, la respuesta `Servicio no disponible', que fuerza la terminación de una conexión, se clasifica como 421, es decir, `negativa transitoria', una interpretación interesante de la palabra `transitoria'.

El código 0 es especial: indica que todas las líneas excepto la última de las respuestas multilínea leídas del servidor se imprimirán en la salida de error estándar en un formato procesado. Por convención, los servidores usan este mecanismo para enviar información para que el usuario la lea. El código de respuesta apropiado, si coincide con la misma respuesta, tiene prioridad.

Si **ZFTP_VERBOSE** no está configurada cuando se carga **zftp**, se establecerá al valor predeterminado **450**, es decir, se imprimirán los mensajes destinados al usuario y todos los errores. Una cadena vacía es válida y especifica que no se deben imprimir mensajes.

Funciones

zftp_chpwd
Si el usuario configura esta función, se llama cada vez que cambia el directorio en el servidor, incluido cuando un usuario inicia sesión o cuando se cierra una conexión. En este último caso, **$ZFTP_PWD** se deshará; de lo contrario, reflejará el nuevo directorio.
zftp_progress
Si el usuario configura esta función, se llamará durante una operación de **get**, **put** o **append** cada vez que se hayan recibido suficientes datos del host. Durante un **get**, los datos se envían a la salida estándar, por lo que es vital que esta función escriba en la salida de error estándar o directamente en la terminal, *no* en la salida estándar.

Cuando se llama con una transferencia en curso, se establecen los siguientes parámetros adicionales del shell:

ZFTP_FILE
El nombre del archivo remoto que se está transfiriendo desde o hacia.
ZFTP_TRANSFER
Una **G** para una operación de **get** y una **P** para una operación de **put**.
ZFTP_SIZE
El tamaño total del archivo completo que se está transfiriendo: lo mismo que el primer valor proporcionado por los subcomandos **remote** y **local** para un archivo particular. Si el servidor no puede proporcionar este valor para un archivo remoto que se está recuperando, no se establecerá. Si la entrada proviene de una tubería, el valor puede ser incorrecto y corresponder simplemente a un búfer de tubería completo.
ZFTP_COUNT
La cantidad de datos transferidos hasta el momento; un número entre cero y **$ZFTP_SIZE**, si este está configurado. Este número siempre está disponible.

La función se llama inicialmente con **ZFTP_TRANSFER** configurada apropiadamente y **ZFTP_COUNT** configurada a cero. Después de que la transferencia finalice, la función se llamará una vez más con **ZFTP_TRANSFER** configurada a **GF** o **PF**, en caso de que desee limpiar. De lo contrario, nunca se llama dos veces con el mismo valor de **ZFTP_COUNT**.

A veces, el medidor de progreso puede causar interrupciones. Depende del usuario decidir si la función debe definirse y usar **unfunction** cuando sea necesario.

Problemas

Es posible que una conexión no se abra en el lado izquierdo de una tubería, ya que esto ocurre en un subshell y la información del archivo no se actualiza en el shell principal. En el caso de cambios de tipo o modo, o de cierre de la conexión en un subshell, la información se devuelve, pero las variables no se actualizan hasta la próxima llamada a **zftp**. Otros cambios de estado en subshells no se reflejarán con cambios en las variables (pero deberían ser inofensivos en general).

Eliminar sesiones mientras un comando **zftp** está activo en segundo plano puede tener efectos inesperados, incluso si no usa la sesión que se está eliminando. Esto se debe a que todos los subprocesos del shell comparten información sobre el estado de todas las conexiones, y la eliminación de una sesión cambia el orden de esa información.

En algunos sistemas operativos, la conexión de control no es válida después de un fork(), por lo que las operaciones en subshells, en el lado izquierdo de una tubería o en segundo plano no son posibles, como deberían ser. Esto es presumiblemente un error en el sistema operativo.

EL MÓDULO ZSH/ZPROF

Cuando se carga, **zsh/zprof** hace que las funciones del shell se perfilen. Los resultados del perfilado se pueden obtener con el comando incorporado **zprof** que pone a disposición este módulo. No hay forma de desactivar el perfilado, excepto descargando el módulo.

zprof [ -c ]
Sin la opción **-c**, **zprof** lista los resultados del perfilado en la salida estándar. El formato es comparable al de comandos como **gprof**.

En la parte superior hay un resumen que lista todas las funciones que se llamaron al menos una vez. Este resumen está ordenado en orden decreciente de la cantidad de tiempo dedicado a cada una. Las líneas contienen el número de la función en orden, que se utiliza en otras partes de la lista en sufijos del tipo `**[**num**]**', luego el número de llamadas realizadas a la función. Las siguientes tres columnas enumeran el tiempo en milisegundos dedicado a la función y sus descendientes, el tiempo promedio en milisegundos dedicado a la función y sus descendientes por llamada y el porcentaje de tiempo dedicado a todas las funciones del shell utilizadas en esta función y sus descendientes. Las siguientes tres columnas proporcionan la misma información, pero contando solo el tiempo dedicado a la función misma. La columna final muestra el nombre de la función.

Después del resumen, se presenta información detallada sobre cada función que se invocó, ordenada en orden decreciente de la cantidad de tiempo dedicado a cada función y sus descendientes. Cada una de estas entradas consiste en descripciones de las funciones que llamaron a la función descrita, la función misma y las funciones que se llamaron desde ella. La descripción de la función en sí tiene el mismo formato que en el resumen (y muestra la misma información). Las otras líneas no muestran el número de la función al principio y tienen su nombre de función indentado para facilitar la distinción de la línea que muestra la función descrita en la sección de las líneas circundantes.

La información que se muestra en este caso es casi la misma que en el resumen, pero solo se refiere a la jerarquía de llamadas que se está mostrando. Por ejemplo, para una función llamadora, la columna que muestra el tiempo total de ejecución lista el tiempo dedicado a la función descrita y sus descendientes solo por las veces que se llamó desde esa función llamadora particular. De manera similar, para una función llamada, estas columnas muestran el tiempo total dedicado a la función llamada y sus descendientes solo por las veces que se llamó desde la función descrita.

También en este caso, la columna que muestra el número de llamadas a una función también muestra una barra y luego el número total de invocaciones realizadas a la función llamada.

Mientras el módulo **zsh/zprof** esté cargado, se realizará el perfilado y múltiples invocaciones del comando incorporado **zprof** mostrarán los tiempos y números de llamadas desde que se cargó el módulo. Con la opción **-c**, el comando incorporado **zprof** reiniciará sus contadores internos y no mostrará la lista.

EL MÓDULO ZSH/ZPTY

El módulo zsh/zpty ofrece una utilidad incorporada:

zpty [ -e ] [ -b ] nombre [ arg ... ]
Los argumentos que siguen a nombre se concatenan con espacios entre ellos, y luego se ejecutan como un comando, como si se pasaran a la utilidad incorporada eval. El comando se ejecuta en una pseudo-terminal recién asignada; esto es útil para ejecutar comandos de forma no interactiva que esperan un entorno interactivo. El nombre no forma parte del comando, sino que se utiliza para referirse a este comando en llamadas posteriores a zpty.

Con la opción -e, la pseudo-terminal se configura de manera que los caracteres de entrada se reflejen.

Con la opción -b, la entrada y salida de la pseudo-terminal se vuelven no bloqueantes.

El parámetro del shell REPLY se establece en el descriptor de archivo asignado al lado maestro de la pseudo-terminal. Esto permite monitorear la terminal con manejadores de descriptores ZLE (ver zshzle(1)) o manipularla con sysread y syswrite (ver EL MÓDULO ZSH/SYSTEM en zshmodules(1)). Advertencia: El uso de sysread y syswrite no se recomienda; utilice zpty -r y zpty -w a menos que sepa exactamente lo que está haciendo.

zpty -d [ nombre ... ]
La segunda forma, con la opción -d, se utiliza para eliminar comandos iniciados previamente, proporcionando una lista de sus nombres. Si no se proporciona ningún nombre, se eliminan todos los comandos. Eliminar un comando provoca el envío de la señal HUP al proceso correspondiente.
zpty -w [ -n ] nombre [ cadena ... ]
La opción -w se puede usar para enviar a la pseudo-terminal del comando nombre las cadenas dadas como entrada (separadas por espacios). Si la opción -n no se proporciona, se añade una nueva línea al final.

Si no se proporciona ninguna cadena, la entrada estándar se copia a la pseudo-terminal; esto puede detenerse antes de copiar la entrada completa si la pseudo-terminal no está bloqueante. La entrada exacta siempre se copia: la opción -n no se aplica.

Tenga en cuenta que el comando bajo la pseudo-terminal ve esta entrada como si fuera escrita, así que tenga cuidado al enviar caracteres especiales del controlador tty como borrado de palabra, eliminación de línea y fin de archivo.

zpty -r [ -mt ] nombre [ param [ patrón ] ]
La opción -r se puede usar para leer la salida del comando nombre. Con solo un argumento nombre, la salida leída se copia a la salida estándar. A menos que la pseudo-terminal no esté bloqueante, la copia continúa hasta que el comando bajo la pseudo-terminal finaliza; cuando no está bloqueante, solo se copia la cantidad de salida que está inmediatamente disponible. El estado de retorno es cero si se copia alguna salida.

Cuando también se proporciona un argumento param, se lee como máximo una línea y se almacena en el parámetro llamado param. Se puede leer menos de una línea completa si la pseudo-terminal no está bloqueante. El estado de retorno es cero si se almacena al menos un carácter en param.

Si también se proporciona un patrón, la salida se lee hasta que toda la cadena leída coincida con el patrón, incluso en el caso no bloqueante. El estado de retorno es cero si la cadena leída coincide con el patrón, o si el comando ha finalizado pero aún se pudo leer al menos un carácter. Si la opción -m está presente, el estado de retorno es cero solo si el patrón coincide. En el momento de escribir esto, se puede consumir un máximo de un megabyte de salida de esta manera; si se lee un megabyte completo sin coincidir con el patrón, el estado de retorno es distinto de cero.

En todos los casos, el estado de retorno es distinto de cero si no se pudo leer nada, y es 2 si esto se debe a que el comando ha finalizado.

Si la opción -r se combina con la opción -t, zpty comprueba si hay salida disponible antes de intentar leer. Si no hay salida disponible, zpty devuelve inmediatamente el estado 1. Cuando se utiliza con un patrón, el comportamiento en un sondeo fallido es similar a cuando el comando ha finalizado: el valor de retorno es cero si al menos un carácter pudo ser leído incluso si el patrón no coincidió.

zpty -t nombre
La opción -t sin la opción -r se puede utilizar para comprobar si el comando nombre todavía se está ejecutando. Devuelve un estado cero si el comando se está ejecutando y un valor distinto de cero en caso contrario.
zpty [ -L ]
La última forma, sin argumentos, se utiliza para listar los comandos actualmente definidos. Si se proporciona la opción -L, esto se hace en forma de llamadas a la utilidad incorporada zpty.

EL MÓDULO ZSH/ZSELECT

El módulo zsh/zselect pone a disposición una única utilidad incorporada:

zselect [ -rwe ] [ -t tiempo_espera ] [ -a arreglo ] [ -A asociativo ] [ fd ... ]
La utilidad incorporada zselect es un front-end para la llamada al sistema `select', que bloquea hasta que un descriptor de archivo está listo para lectura o escritura, o tiene una condición de error, con un tiempo de espera opcional. Si esto no está disponible en su sistema, el comando imprime un mensaje de error y devuelve el estado 2 (los errores normales devuelven el estado 1). Para más información, consulte la documentación de su sistema para select(3). Tenga en cuenta que no hay conexión con la utilidad incorporada del shell del mismo nombre.

Los argumentos y opciones pueden entremezclarse en cualquier orden. Los argumentos que no son opciones son descriptores de archivo, que deben ser enteros decimales. Por defecto, los descriptores de archivo se prueban para lectura, es decir, zselect devolverá cuando haya datos disponibles para leer del descriptor de archivo, o más precisamente, cuando una operación de lectura desde el descriptor de archivo no se bloquee. Después de un -r, -w y -e, los descriptores de archivo dados se prueban para lectura, escritura o condiciones de error. Estas opciones y una lista arbitraria de descriptores de archivo se pueden dar en cualquier orden.

(La presencia de una "condición de error" no está bien definida en la documentación para muchas implementaciones de la llamada al sistema select. Según versiones recientes de la especificación POSIX, se trata realmente de una condición de *excepción*, cuyo único ejemplo estándar son los datos fuera de banda recibidos en un socket. Por lo tanto, es poco probable que los usuarios de zsh encuentren útil la opción -e.)

La opción `-t tiempo_espera' especifica un tiempo de espera en centésimas de segundo. Esto puede ser cero, en cuyo caso los descriptores de archivo simplemente se sondearán y zselect devolverá inmediatamente. Es posible llamar a zselect sin descriptores de archivo y con un tiempo de espera distinto de cero para usarlo como un reemplazo de mayor granularidad para `sleep'; tenga en cuenta, sin embargo, que el estado de retorno es siempre 1 para un tiempo de espera.

La opción `-a arreglo' indica que arreglo se establecerá para indicar los descriptores de archivo que están listos. Si la opción no se proporciona, el arreglo reply se usará para este propósito. El arreglo contendrá una cadena similar a los argumentos para zselect. Por ejemplo,

zselect -t 0 -r 0 -w 1

podría devolver inmediatamente con estado 0 y $reply conteniendo `-r 0 -w 1' para mostrar que ambos descriptores de archivo están listos para las operaciones solicitadas.

La opción `-A asociativo' indica que el arreglo asociativo asociativo se establecerá para indicar los descriptores de archivo que están listos. Esta opción anula la opción -a, ni se modificará reply. Las claves de assoc son los descriptores de archivo, y los valores correspondientes son cualquiera de los caracteres `rwe' para indicar la condición.

El comando devuelve el estado 0 si algunos descriptores de archivo están listos para lectura. Si la operación expiró, o se dio un tiempo de espera de 0 y no hubo descriptores de archivo listos, o hubo un error, devuelve el estado 1 y el arreglo no se establecerá (ni se modificará de ninguna manera). Si hubo un error en la operación select, se imprimirá el mensaje de error apropiado.

EL MÓDULO ZSH/ZUTIL

El módulo zsh/zutil solo agrega algunas utilidades incorporadas:

zstyle [ -L [ metapatrón [ estilo ] ] ]
zstyle [ -e | - | -- ] patrón estilo cadena ...
zstyle -d [ patrón [ estilo ... ] ]
zstyle -g nombre [ patrón [ estilo ] ]
zstyle -{a|b|s} contexto estilo nombre [ sep ]
zstyle -{T|t} contexto estilo [ cadena ... ]
zstyle -m contexto estilo patrón
Esta utilidad incorporada se utiliza para definir y buscar estilos. Los estilos son pares de nombres y valores, donde los valores consisten en cualquier número de cadenas. Se almacenan junto con patrones y la búsqueda se realiza proporcionando una cadena, llamada `contexto', que coincide con los patrones. Se devolverá la definición almacenada para el patrón más específico que coincida.

Un patrón se considera más específico que otro si contiene más componentes (subcadenas separadas por dos puntos) o si los patrones de los componentes son más específicos, donde las cadenas simples se consideran más específicas que los patrones y los patrones complejos se consideran más específicos que el patrón `*'. Un `*' en el patrón coincidirá con cero o más caracteres en el contexto; los dos puntos no se tratan de forma especial en este sentido. Si dos patrones son igualmente específicos, el desempate se resuelve a favor del patrón que se definió primero.

Ejemplo

Por ejemplo, un plugin ficticio de `weather' podría indicar en su documentación que busca el estilo preferred-precipitation bajo el contexto `:weather:continente:día-de-la-semana:fase-de-la-luna'. Según esto, podría establecer lo siguiente en su zshrc:

zstyle ':weather:europe:*' preferred-precipitation rain
zstyle ':weather:*:Sunday:*' preferred-precipitation snow

Entonces el plugin ejecutaría en segundo plano un comando s

uch as

zstyle -s ":weather:${continent}:${day_of_week}:${moon_phase}" preferred-precipitation REPLY

para recuperar tu preferencia en la variable escalar $REPLY. Los domingos $REPLY se establecería en `snow'; en Europa se establecería en `rain'; y los domingos en Europa se establecería de nuevo en `snow', porque los patrones `:weather:europe:*' y `:weather:*:Sunday:*' coinciden con el argumento context de zstyle -s, son igualmente específicos, y este último es más específico (porque tiene más componentes separados por dos puntos).

Uso

Las formas que operan sobre patrones son las siguientes.

zstyle [ -L [ metapattern [ style ] ] ]
Sin argumentos, lista las definiciones de estilo. Los estilos se muestran en orden alfabético y los patrones se muestran en el orden en que zstyle los probará.

Si se proporciona la opción -L, la lista se realiza en forma de llamadas a zstyle. El primer argumento opcional, metapattern, es un patrón que coincidirá con la cadena proporcionada como pattern cuando se definió el estilo. Nota: esto significa, por ejemplo, que `zstyle -L ":completion:*"' coincidirá con cualquier patrón suministrado que comience por `:completion:', no solo ":completion:*": use ':completion:\*' para que coincida con eso. El segundo argumento opcional limita la salida a un style específico (no a un patrón). -L no es compatible con ninguna otra opción.

zstyle [ - | -- | -e ] pattern style string ...
Define el style dado para el pattern con los strings como valor. Si se proporciona la opción -e, los strings se concatenarán (separados por espacios) y la cadena resultante se evaluará (de la misma manera que se hace con el comando incorporado eval) cuando se busque el estilo. En este caso, el parámetro `reply' debe asignarse para establecer las cadenas que se devuelven después de la evaluación. Antes de evaluar el valor, reply se desestablece y, si sigue sin establecerse después de la evaluación, el estilo se trata como si no estuviera establecido.
zstyle -d [ pattern [ style ... ] ]
Elimina definiciones de estilo. Sin argumentos, se eliminan todas las definiciones, con un pattern se eliminan todas las definiciones para ese patrón y, si se proporcionan styles, solo se eliminan esos estilos para el pattern.
zstyle -g name [ pattern [ style ] ]
Recupera una definición de estilo. El name se utiliza como nombre de un array en el que se almacenan los resultados. Sin argumentos adicionales, se devuelven todos los patrones definidos. Con un pattern, se devuelven los estilos definidos para ese patrón y, con un pattern y un style, se devuelve el valor de cadena de esa combinación.

Las otras formas se pueden utilizar para buscar o probar estilos para un contexto dado.

zstyle -s context style name [ sep ]
El parámetro name se establece con el valor del estilo interpretado como una cadena. Si el valor contiene varias cadenas, se concatenan con espacios (o con la cadena sep si se proporciona) entre ellas.

Devuelve 0 si el estilo está establecido, 1 en caso contrario.

zstyle -b context style name
El valor se almacena en name como un booleano, es decir, como la cadena `yes' si el valor tiene una sola cadena y esa cadena es igual a `yes', `true', `on' o `1'. Si el valor es cualquier otra cadena o tiene más de una cadena, el parámetro se establece en `no'.

Devuelve 0 si name se establece en `yes', 1 en caso contrario.

zstyle -a context style name
El valor se almacena en name como un array. Si name se declara como un array asociativo, las cadenas primera, tercera, etc., se utilizan como claves y las otras cadenas se utilizan como valores.

Devuelve 0 si el estilo está establecido, 1 en caso contrario.

zstyle -t context style [ string ... ]
zstyle -T context style [ string ... ]
Prueba el valor de un estilo, es decir, la opción -t solo devuelve un estado (establece $?). Sin ningún string, el estado de retorno es cero si el estilo está definido para al menos un patrón coincidente, tiene una sola cadena en su valor y esta es igual a `true', `yes', `on' o `1'. Si se proporcionan strings, el estado es cero si y solo si al menos uno de los strings es igual a al menos uno de los strings del valor. Si el estilo está definido pero no coincide, el estado de retorno es 1. Si el estilo no está definido, el estado es 2.

La opción -T prueba los valores del estilo como -t, pero devuelve el estado cero (en lugar de 2) si el estilo no está definido para ningún patrón coincidente.

zstyle -m context style pattern
Coincide un valor. Devuelve el estado cero si el pattern coincide con al menos una de las cadenas del valor.
zformat -f param format spec ...
zformat -F param format spec ...
zformat -a array sep spec ...
Este comando incorporado proporciona diferentes formas de formato. La primera forma se selecciona con la opción -f. En este caso, la cadena format se modificará reemplazando las secuencias que comienzan con un signo de porcentaje por cadenas de los specs. Cada spec debe tener el formato `char:string' lo que provocará que cada aparición de la secuencia `%char' en format se reemplace por la string. La secuencia `%' también puede contener especificaciones opcionales de ancho mínimo y máximo de campo entre el `%' y el `char' en el formato `%min.maxc', es decir, el ancho mínimo de campo se da primero y, si se utiliza el ancho máximo de campo, debe ir precedido de un punto. Especificar un ancho mínimo de campo hace que el resultado se rellene con espacios a la derecha si la string es más corta que el ancho solicitado. Se puede lograr un relleno a la izquierda dando un ancho mínimo de campo negativo. Si se especifica un ancho máximo de campo, la string se truncará después de esa cantidad de caracteres. Después de procesar todas las secuencias `%' para los specs dados, la cadena resultante se almacena en el parámetro param.

Los escapes % también entienden expresiones ternarias en el formato utilizado por los prompts. El % va seguido de un `(' y luego un carácter especificador de formato ordinario como se describe arriba. Puede haber un conjunto de dígitos antes o después del `('; estos especifican un número de prueba, que por defecto es cero. También se permiten números negativos. Un carácter delimitador arbitrario sigue al especificador de formato, que va seguido de una parte de texto 'verdadero', el carácter delimitador de nuevo, una parte de texto 'falso' y un paréntesis de cierre. La expresión completa (sin los dígitos) se ve así `%(X.text1.text2)', excepto que el carácter `.' es arbitrario. El valor dado para el especificador de formato en las expresiones char:string se evalúa como una expresión matemática y se compara con el número de prueba. Si son iguales, se genera text1, de lo contrario se genera text2. Se puede escapar un paréntesis en text2 como %). Cualquiera de los text1 o text2 puede contener escapes % anidados.

Por ejemplo:

zformat -f REPLY "The answer is '%3(c.yes.no)'." c:3

genera "The answer is 'yes'." en REPLY ya que el valor para el especificador de formato c es 3, coincidiendo con el argumento numérico de la expresión ternaria.

Con -F en lugar de -f, las expresiones ternarias eligen entre el texto 'verdadero' o 'falso' basándose en si el especificador de formato está presente y no está vacío. Un número de prueba indica un ancho mínimo para el valor dado en el especificador de formato. Los números negativos invierten esto, por lo que la prueba es si el valor excede un ancho máximo.

La forma, utilizando la opción -a, se puede usar para alinear cadenas. Aquí, los specs tienen el formato `left:right' donde `left' y `right' son cadenas arbitrarias. Estas cadenas se modifican reemplazando los dos puntos por la cadena sep y rellenando las cadenas left con espacios a la derecha para que las cadenas sep en el resultado (y, por lo tanto, las cadenas right después de ellas) estén todas alineadas si las cadenas se imprimen una debajo de la otra. Todas las cadenas sin dos puntos no se modifican y todas las cadenas con una cadena right vacía tienen los dos puntos finales eliminados. En ambos casos, las longitudes de las cadenas no se utilizan para determinar cómo se alinearán las otras cadenas. Se puede escapar un dos puntos en la cadena left con una barra invertida. Las cadenas resultantes se almacenan en el array.

zregexparse
Esto implementa algunas partes internas de la función _regex_arguments.
zparseopts [ -D -E -F -K -M ] [ -a array ] [ -A assoc ] [ - ] spec ...
Este comando incorporado simplifica el análisis de opciones en parámetros posicionales, es decir, el conjunto de argumentos dados por $*. Cada spec describe una opción y debe tener el formato `opt[=array]'. Si se encuentra una opción descrita por opt en los parámetros posicionales, se copia en el array especificado con la opción -a; si se proporciona el `=array' opcional, se copia en su lugar en ese array, que debe declararse como un array normal y nunca como un array asociativo.

Tenga en cuenta que es un error dar cualquier spec sin una `=array' a menos que se utilicen las opciones -a o -A.

A menos que se proporcione la opción -E, el análisis se detiene en la primera cadena que no está descrita por ninguna de las specs. Incluso con -E, el análisis siempre se detiene en un parámetro posicional igual a `-' o `--'. Véase también -F.

La descripción de opt debe ser una de las siguientes. Cualquiera de los caracteres especiales puede aparecer en el nombre de la opción siempre que vaya precedido de una barra invertida.

name
name+
El name es el nombre de la opción sin el `-' inicial. Para especificar una opción larga al estilo GNU, se debe incluir uno de los dos `-' iniciales habituales en name; por ejemplo, una opción `--file' se representa con un name de `-file'.

Si aparece un `+' después de name, la opción se añade a array cada vez que se encuentra en los parámetros posicionales; sin el `+', solo se conserva la última ocurrencia de la opción.

Si se utiliza alguna de estas formas, la opción no toma ningún argumento, por lo que el análisis se detiene si el siguiente parámetro posicional no empieza también con `-' (a menos que se utilice la opción -E).

name:
name:-
name::
Si se dan uno o dos puntos, la opción toma un argumento; con un punto, el argumento es obligatorio y con dos puntos es opcional. El argumento se añade a array después de la propia opción.

Un argumento opcional se coloca en el mismo elemento de array que el nombre de la opción (tenga en cuenta que esto hace que las cadenas vacías como argumentos sean indistinguibles). Un argumento obligatorio se añade como un elemento separado a menos que se utilice la forma `:-', en cuyo caso el argumento se coloca en el mismo elemento.

Un `+' como se describe anteriormente puede aparecer entre el name y el primer punto.

En todos los casos, los argumentos de opción deben aparecer inmediatamente después de la opción en el mismo parámetro posicional o en el siguiente. Incluso un argumento opcional puede aparecer en el siguiente parámetro, a menos que comience con un `-'. No hay manejo especial de `=' como con los analizadores de argumentos al estilo GNU; dado el spec `-foo:', el parámetro posicional `--foo=bar' se analiza como `--foo' con un argumento de `=bar'.

Cuando los nombres de dos opciones que no toman argumentos se solapan, gana la más larga, de modo que el análisis para los specs `-foo -foobar' (por ejemplo) no es ambiguo. Sin embargo, debido al manejo mencionado de argumentos de opción, pueden surgir ambigüedades cuando al menos un spec solapado toma un argumento, como en `-foo: -foobar'. En ese caso, gana el último spec coincidente.

Las opciones de zparseopts en sí mismas no pueden apilarse porque, por ejemplo, la pila `-DEK' es indistinguible de un spec para la opción larga al estilo GNU `--DEK'. Las opciones de zparseopts en sí mismas son:

-a array
Como se describió anteriormente, este nombra el array predeterminado en el que se almacenarán las opciones reconocidas.
-A assoc
Si se proporciona, las opciones y sus valores también se colocan en un array asociativo con los nombres de las opciones como claves y los argumentos (si los hay) como valores.
-D
Si se proporciona esta opción, todas las opciones encontradas se eliminan de los parámetros posicionales del shell o función shell de llamada, hasta pero sin incluir cualquier elemento que no esté descrito por las specs. Si el primer parámetro de este tipo es `-' o `--', también se elimina. Esto es similar a usar el builtin shift.
-E
Esto cambia las reglas de análisis para no detenerse en la primera cadena que no está descrita por ninguna de las specs. Puede usarse para probar o (si se usa junto con -D) extraer opciones y sus argumentos, ignorando todas las demás opciones y argumentos que puedan estar en los parámetros posicionales. Como se indicó anteriormente, el análisis todavía se detiene en el primer `-' o `--' no descrito por una spec, pero no se elimina cuando se usa con -D.
-F
Si se proporciona esta opción, zparseopts se detiene inmediatamente en el primer parámetro similar a una opción que no está descrito por ninguna de las specs, imprime un mensaje de error y devuelve el estado 1. La eliminación (-D) y la extracción (-E) no se realizan, y los arrays de opciones no se actualizan. Esto proporciona una validación básica para las opciones dadas.

Tenga en cuenta que la aparición en los parámetros posicionales de una opción sin su argumento requerido siempre aborta el análisis y devuelve un error como se describe anteriormente, independientemente de si se utiliza esta opción.

-K
Con esta opción, los arrays especificados con la opción -a y con las formas `=array' se mantienen sin cambios cuando ninguna de las specs para ellos se utiliza. De lo contrario, todo el array se reemplaza cuando se utiliza cualquiera de las specs. Los elementos individuales de los arrays asociativos especificados con la opción -A se conservan con -K. Esto permite la asignación de valores por defecto a los arrays antes de llamar a zparseopts.
-M
Esto cambia las reglas de asignación para implementar un mapeo entre nombres de opciones equivalentes. Si alguna spec utiliza la forma `=array', la cadena array se interpreta como el nombre de otra spec, que se utiliza para elegir dónde almacenar los valores. Si no se encuentra ninguna otra spec, los valores se almacenan como de costumbre. Esto solo cambia la forma en que se almacenan los valores, no la forma en que se analiza $*, por lo que los resultados pueden ser impredecibles si el especificador `name+' se utiliza de forma inconsistente.

Por ejemplo,

set -- -a -bx -c y -cz baz -cend
zparseopts a=foo b:=bar c+:=bar

tendrá el efecto de

foo=(-a)
bar=(-b x -c y -c z)

Los argumentos a partir de `baz' no se utilizarán.

Como ejemplo de la opción -E, considere:

set -- -a x -b y -c z arg1 arg2
zparseopts -E -D b:=bar

tendrá el efecto de

bar=(-b y)
set -- -a x -c z arg1 arg2

Es decir, la opción -b y sus argumentos se toman de los parámetros posicionales y se colocan en el array bar.

La opción -M se puede usar de la siguiente manera:

set -- -a -bx -c y -cz baz -cend
zparseopts -A bar -M a=foo b+: c:=b

para tener el efecto de

foo=(-a)
bar=(-a '' -b xyz)
