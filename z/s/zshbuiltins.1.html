zshbuiltins - comandos internos de zsh

COMANDOS INTERNOS DEL SHELL

Algunos comandos internos del shell aceptan opciones según se describe en las entradas individuales; estos a menudo se conocen en la siguiente lista como `flags' para evitar confusiones con las opciones del shell, que también pueden tener un efecto en el comportamiento de los comandos internos. En esta sección introductoria, `option' siempre tiene el significado de una opción para un comando que debería ser familiar para la mayoría de los usuarios de la línea de comandos.

Típicamente, las opciones son letras individuales precedidas por un guion (-). Las opciones que toman un argumento lo aceptan inmediatamente después de la letra de la opción o después de un espacio en blanco, por ejemplo, `print -C3 {1..9}' o `print -C 3 {1..9}' son equivalentes. Los argumentos de las opciones no son lo mismo que los argumentos del comando; la documentación indica cuál es cuál. Las opciones que no toman argumento pueden combinarse en una sola palabra, por ejemplo, `print -rca -- *' y `print -r -c -a -- *' son equivalentes.

Algunos comandos internos del shell también toman opciones que comienzan con `+' en lugar de `-'. La siguiente lista aclara qué comandos son estos.

Las opciones (junto con sus argumentos individuales, si los hay) deben aparecer en un grupo antes que cualquier argumento que no sea una opción; una vez encontrado el primer argumento que no es una opción, se termina el procesamiento de opciones.

Todos los comandos internos, excepto `echo' y los modificadores de pre-comando, incluso aquellos que no tienen opciones, pueden recibir el argumento `--' para terminar el procesamiento de opciones. Esto indica que las siguientes palabras son argumentos que no son de opción, pero por lo demás se ignora. Esto es útil en casos donde los argumentos del comando pueden comenzar con `-'. Por razones históricas, la mayoría de los comandos internos (incluido `echo') también reconocen un solo `-' en una palabra separada para este propósito; tenga en cuenta que esto es menos estándar y se recomienda el uso de `--'.

- comando simple
Ver la sección `Modificadores de pre-comando' en zshmisc(1).
. archivo [ arg ... ]
Lee comandos del archivo y los ejecuta en el entorno del shell actual.

Si archivo no contiene una barra, o si PATH_DIRS está configurado, el shell busca en los componentes de $path para encontrar el directorio que contiene archivo. Los archivos en el directorio actual no se leen a menos que `.' aparezca en algún lugar de $path. Si se encuentra un archivo llamado `archivo.zwc', es más reciente que archivo y es la forma compilada (creada con el comando interno zcompile) de archivo, entonces los comandos se leen de ese archivo en lugar de archivo.

Si se proporcionan argumentos arg, estos se convierten en los parámetros posicionales; los parámetros posicionales antiguos se restauran cuando se termina de ejecutar archivo. Sin embargo, si no se proporcionan argumentos, los parámetros posicionales siguen siendo los del contexto de llamada, y no se realiza ninguna restauración.

Si no se encontró archivo, el estado de salida es 127; si se encontró archivo pero contenía un error de sintaxis, el estado de salida es 126; de lo contrario, el estado de salida es el estado de salida del último comando ejecutado.

: [ arg ... ]
Este comando no hace nada, aunque se realizan expansiones normales de argumentos que pueden tener efectos en los parámetros del shell. Se devuelve un estado de salida cero.
alias [ {+|-}gmrsL ] [ nombre[=valor] ... ]
Para cada nombre con un valor correspondiente, define un alias con ese valor. Un espacio final en valor hace que la siguiente palabra se verifique para la expansión de alias. Si está presente el indicador -g, define un alias global; los alias globales se expanden incluso si no ocurren en la posición del comando:
% perldoc --help 2>&1 | grep 'built-in functions'
    -f   Search Perl built-in functions
% alias -g HG='--help 2>&1 | grep'
% perldoc HG 'built-in functions'
    -f   Search Perl built-in functions

Si está presente el indicador -s, define un alias de sufijo: si la palabra del comando en una línea de comandos tiene la forma `texto.nombre', donde texto es cualquier cadena no vacía, se reemplaza por el texto `valor texto.nombre'. Tenga en cuenta que nombre se trata como una cadena literal, no como un patrón. Un espacio final en valor no es especial en este caso. Por ejemplo,

alias -s ps='gv --'

hará que el comando `*.ps' se expanda a `gv -- *.ps'. Como la expansión de alias se realiza antes que la globbing, `*.ps' se expandirá entonces. Los alias de sufijo constituyen un espacio de nombres diferente al de otros alias (por lo que en el ejemplo anterior todavía es posible crear un alias para el comando ps) y los dos conjuntos nunca se enumeran juntos.

Para cada nombre sin valor, imprime el valor de nombre, si existe. Sin argumentos, imprime todos los alias actualmente definidos que no sean alias de sufijo. Si se proporciona el indicador -m, los argumentos se toman como patrones (deben entrecomillarse para evitar que se interpreten como patrones de globbing), y se imprimen los alias que coinciden con estos patrones. Al imprimir alias y si está presente uno de los indicadores -g, -r o -s, restrinja la impresión a alias globales, regulares o de sufijo, respectivamente; un alias regular es aquel que no es ni global ni de sufijo. Usar `+' en lugar de `-', o terminar la lista de opciones con un solo `+', evita que se impriman los valores de los alias.

Si está presente el indicador -L, entonces imprime cada alias de una manera adecuada para colocarlo en un script de inicio. El estado de salida es distinto de cero si se da un nombre (sin valor) para el cual no se ha definido ningún alias.

Para más información sobre alias, incluidos problemas comunes, consulte la sección ALIASING en zshmisc(1).

autoload [ {+|-}RTUXdkmrtWz ] [ -w ] [ nombre ... ]
Ver la sección `Funciones de carga automática' en zshmisc(1) para obtener detalles completos. Se buscará en el parámetro fpath para encontrar la definición de la función cuando se haga referencia a la función por primera vez.

Si nombre consta de una ruta absoluta, la función se define para cargar desde el archivo dado (buscando como de costumbre los archivos de volcado en la ubicación dada). El nombre de la función es el nombre base (parte no directorio) del archivo. Normalmente es un error si la función no se encuentra en la ubicación dada; sin embargo, si se da la opción -d, la búsqueda de la función por defecto es $fpath. Si una función se carga por ruta absoluta, cualquier función cargada de ella que esté marcada para autoload sin una ruta absoluta tiene la ruta de carga de la función padre antepuesta temporalmente a $fpath.

Si se da la opción -r o -R, la función se busca inmediatamente y la ubicación se registra internamente para su uso cuando se ejecuta la función; una ruta relativa se expande usando el valor de $PWD. Esto protege contra un cambio en $fpath después de la llamada a autoload. Con -r, si la función no se encuentra, se deja en silencio sin resolver hasta la ejecución; con -R, se imprime un mensaje de error y se aborta el procesamiento de comandos inmediatamente al fallar la búsqueda, es decir, en el comando autoload en lugar de en la ejecución de la función.

El indicador -X solo puede usarse dentro de una función del shell. Hace que la función que llama se marque para carga automática y luego se cargue y ejecute inmediatamente, con la matriz actual de parámetros posicionales como argumentos. Esto reemplaza la definición anterior de la función. Si no se encuentra ninguna definición de función, se imprime un error y la función permanece indefinida y marcada para carga automática. Si se da un argumento, se utiliza como un directorio (es decir, no incluye el nombre de la función) en el que se encontrará la función; esto se puede combinar con la opción -d para permitir que la búsqueda de la función por defecto sea $fpath si no está en la ubicación dada.

El indicador +X intenta cargar cada nombre como una función cargada automáticamente, pero *no* la ejecuta. El estado de salida es cero (éxito) si la función no estaba definida previamente *y* se encontró una definición para ella. Esto *no* reemplaza ninguna definición existente de la función. Con el indicador -t, activa el rastreo de ejecución; con -T, activa el rastreo de ejecución solo para la función actual, desactivándolo al entrar en cualquier función llamada que no tenga el rastreo habilitado.

Con el indicador -U, la expansión de alias se suprime al cargar la función.

Con el indicador -w, los nombres se toman como nombres de archivos compilados con el comando incorporado zcompile, y todas las funciones definidas en ellos se marcan para carga automática.

Los indicadores -z y -k marcan la función para ser cargada automáticamente utilizando el estilo zsh o ksh, como si la opción KSH_AUTOLOAD estuviera desestablecida o establecida, respectivamente. Los indicadores anulan la configuración de la opción en el momento en que se carga la función.

Tenga en cuenta que el comando autoload no intenta asegurar que las opciones del shell establecidas durante la carga o ejecución del archivo tengan algún valor particular. Para ello, se puede utilizar el comando emulate:

emulate zsh -c 'autoload -Uz func'

organiza que cuando se cargue func, el shell esté en emulación zsh nativa, y esta emulación también se aplique cuando se ejecute func.

Algunas de las funciones de autoload también son proporcionadas por functions -u o functions -U, pero autoload es una interfaz más completa.

cd [ -qsLP ] [ arg ]
cd [ -qsLP ] old new
cd [ -qsLP ] {+|-}n
Cambia el directorio actual. En la primera forma, cambia el directorio actual a arg, o al valor de $HOME si arg no se especifica. Si arg es `-', cambia al directorio anterior.

De lo contrario, si arg comienza con una barra, intenta cambiar al directorio dado por arg.

Si arg no comienza con una barra, el comportamiento depende de si el directorio actual `.' se encuentra en la lista de directorios contenidos en el parámetro del shell cdpath. Si no es así, primero intenta cambiar al directorio arg bajo el directorio actual y, si falla pero cdpath está establecido y contiene al menos un elemento, intenta cambiar al directorio arg bajo cada componente de cdpath en turno hasta tener éxito. Si `.' se encuentra en cdpath, entonces cdpath se busca estrictamente en orden para que `.' solo se intente en el punto apropiado.

El orden de prueba de cdpath se modifica si la opción POSIX_CD está establecida, como se describe en la documentación de la opción.

Si no se encuentra ningún directorio, la opción CDABLE_VARS está establecida y existe un parámetro llamado arg cuyo valor comienza con una barra, trata su valor como el directorio. En ese caso, el parámetro se agrega a la tabla hash de directorios nombrados.

La segunda forma de cd sustituye la cadena new por la cadena old en el nombre del directorio actual e intenta cambiar a este nuevo directorio.

La tercera forma de cd extrae una entrada de la pila de directorios y cambia a ese directorio. Un argumento de la forma `+n' identifica una entrada de pila contando desde la izquierda de la lista que muestra el comando dirs, comenzando desde cero. Un argumento de la forma `-n' cuenta desde la derecha. Si la opción PUSHD_MINUS está establecida, los significados de `+' y `-' en este contexto se intercambian. Si la opción POSIX_CD está establecida, esta forma de cd no se reconoce y se interpretará como la primera forma.

Si se especifica la opción -q (silenciosa), la función gancho chpwd y las funciones en el array chpwd_functions no se llaman. Esto es útil para llamadas a cd que no cambian el entorno visto por un usuario interactivo.

Si se especifica la opción -s, cd se niega a cambiar el directorio actual si la ruta dada contiene enlaces simbólicos. Si se proporciona la opción -P o se establece la opción CHASE_LINKS, los enlaces simbólicos se resuelven a sus valores reales. Si se proporciona la opción -L, los enlaces simbólicos se conservan en el directorio (y no se resuelven) independientemente del estado de la opción CHASE_LINKS.

Deshabilita temporalmente los elementos de tabla hash o patrones nombrados name. El valor predeterminado es deshabilitar comandos incorporados. Esto le permite usar un comando externo con el mismo nombre que un comando incorporado. El indicador -a hace que disable actúe sobre alias regulares o globales. El indicador -s hace que disable actúe sobre alias de sufijo. El indicador -f hace que disable actúe sobre funciones del shell. El indicador -r hace que disable actúe sobre palabras reservadas. Sin argumentos, se imprimen todos los elementos de tabla hash deshabilitados de la tabla hash correspondiente. Con el indicador -m, los argumentos se toman como patrones (que deben entrecomillarse para evitar que se sometan a expansión de nombres de archivo) y todos los elementos de tabla hash de la tabla hash correspondiente que coincidan con estos patrones se deshabilitan. Por lo tanto, por ejemplo, la emulación persistente es heredada por subfunciones definidas dentro de funciones con emulación persistente.
2.
No se produce ningún cambio de opciones al entrar o salir de funciones que no están marcadas para emulación persistente, aparte de los que ocurrirían normalmente, incluso si esas funciones se llaman dentro de emulación persistente.

enable [ -afmprs ] nombre ...
Habilita los elementos de la tabla hash con el nombre especificado, presumiblemente deshabilitados anteriormente con disable. Por defecto, se habilitan los comandos incorporados. La opción -a hace que enable actúe sobre alias regulares o globales. La opción -s hace que enable actúe sobre alias de sufijo. La opción -f hace que enable actúe sobre funciones del shell. La opción -r hace que enable actúe sobre palabras reservadas. Sin argumentos, se imprimen todos los elementos de la tabla hash habilitados de la tabla hash correspondiente. Con la bandera -m, los argumentos se toman como patrones (deben entrecomillarse) y se habilitan todos los elementos de la tabla hash correspondiente que coincidan con estos patrones. Los objetos habilitados pueden deshabilitarse con el comando incorporado disable.

enable -p rehabilita los patrones deshabilitados con disable -p. Tenga en cuenta que no anula las opciones de globbing; por ejemplo, `enable -p "~"' no hace que el carácter de patrón ~ esté activo a menos que la opción EXTENDED_GLOB también esté establecida. Para habilitar todos los patrones posibles (para que puedan deshabilitarse individualmente con disable -p), use `setopt EXTENDED_GLOB KSH_GLOB NO_SH_GLOB'.

eval [ arg ... ]
Lee los argumentos como entrada para el shell y ejecuta los comandos resultantes en el proceso actual del shell. El estado de retorno es el mismo que si los comandos se hubieran ejecutado directamente por el shell; si no hay args o no contienen comandos (es decir, son una cadena vacía o espacios en blanco), el estado de retorno es cero.
exec [ -cl ] [ -a argv0 ] [ comando [ arg ... ] ]
Reemplaza el shell actual con comando en lugar de crear un proceso hijo. Si comando es un comando incorporado del shell o una función del shell, el shell lo ejecuta y sale cuando el comando se completa.

Con -c borra el entorno; con -l antepone - a la cadena argv[0] del comando ejecutado (para simular un shell de inicio de sesión); con -a argv0 establece la cadena argv[0] del comando ejecutado. Consulte la sección `Modificadores de pre-comando' en zshmisc(1).

Si la opción POSIX_BUILTINS está establecida, comando nunca se interpreta como un comando incorporado del shell o una función del shell. Esto significa que los modificadores de pre-comando adicionales como builtin y noglob tampoco se interpretan dentro del shell. Por lo tanto, comando siempre se encuentra buscando en la ruta de comandos.

Si comando se omite pero se especifican redirecciones, las redirecciones tendrán efecto en el shell actual.

El comando fc controla el mecanismo de historial interactivo. Tenga en cuenta que la lectura y escritura de las opciones de historial solo se realiza si el shell es interactivo. Normalmente, esto se detecta automáticamente, pero se puede forzar estableciendo la opción interactive al iniciar el shell.

Las dos primeras formas de este comando seleccionan un rango de eventos desde primero hasta ultimo de la lista de historial. Los argumentos primero y ultimo se pueden especificar como un número o como una cadena. Un número negativo se usa como un desplazamiento del número de evento de historial actual. Una cadena especifica el evento más reciente que comienza con la cadena dada. Todas las sustituciones viejo=nuevo, si las hay, se realizan en el texto de los eventos.

El rango de eventos seleccionado por números se puede acotar aún más con las siguientes banderas.

-I
restringe solo a eventos internos (no de $HISTFILE)
-L
restringe solo a eventos locales (no de otros shells, consulte SHARE_HISTORY en zshoptions(1); tenga en cuenta que $HISTFILE se considera local al leerse al inicio)
-m
toma el primer argumento como un patrón (que debe entrecomillarse) y solo se consideran los eventos de historial que coincidan con este patrón

Si no se especifica primero, se establecerá en -1 (el evento más reciente), o en -16 si se da la bandera -l. Si no se especifica ultimo, se establecerá en primero, o en -1 si se da la bandera -l. Sin embargo, si el evento actual ha agregado entradas al historial con `print -s' o `fc -R', entonces el ultimo predeterminado para -l incluye todas las nuevas entradas del historial desde que comenzó el evento actual.

Cuando se da la bandera -l, los eventos resultantes se enumeran en la salida estándar. De lo contrario, se invoca el editor especificado por -e ename en un archivo que contiene estos eventos de historial. Si no se proporciona -e, se utiliza el valor del parámetro FCEDIT; si no está establecido, se utiliza el valor del parámetro EDITOR; si no está establecido, se utiliza un valor predeterminado incorporado, generalmente `vi'. Si ename es `-', no se invoca ningún editor. Cuando se completa la edición, se ejecuta el comando editado.

La bandera `-s' es equivalente a `-e -'. La bandera -r invierte el orden de los eventos y la bandera -n suprime los números de evento al listar.

También al listar,

-d
imprime las marcas de tiempo para cada evento
-f
imprime marcas de fecha y hora completas en el formato estadounidense `MM/DD/AA hh:mm'
-E
imprime marcas de fecha y hora completas en el formato europeo `dd.mm.aaaa hh:mm'
-i
imprime marcas de fecha y hora completas en formato ISO8601 `aaaa-mm-dd hh:mm'
-t fmt
imprime marcas de fecha y hora en el formato dado; fmt se formatea con la función strftime con las extensiones de zsh descritas para el formato de prompt %D{cadena} en la sección EXPANSIÓN DE SECUENCIAS DE PROMPT en zshmisc(1). La cadena formateada resultante no debe tener más de 256 caracteres o no se imprimirá
-D
imprime los tiempos transcurridos; se puede combinar con una de las opciones anteriores

`fc -p' empuja la lista de historial actual a una pila y cambia a una nueva lista de historial. Si también se especifica la opción -a, esta lista de historial se sacará automáticamente cuando se salga del ámbito de la función actual, lo que es una solución mucho mejor que crear una trampa para llamar `fc -P' manualmente. Si no se especifican argumentos, la lista de historial se deja vacía, se anula $HISTFILE y se establecen $HISTSIZE y $SAVEHIST en sus valores predeterminados. Si se proporciona un argumento, $HISTFILE se establece en ese nombre de archivo, $HISTSIZE y $SAVEHIST permanecen sin cambios, y se lee el archivo de historial (si existe) para inicializar la nueva lista. Si se especifica un segundo argumento, $HISTSIZE y $SAVEHIST se establecen en su lugar en el único valor numérico especificado. Finalmente, si se especifica un tercer argumento,

$SAVEHIST tiene un valor separado de $HISTSIZE. Eres libre de cambiar estos valores de entorno para la nueva lista de historial como desees para manipular la nueva lista de historial.

`fc -P' restaura la lista de historial a una lista anterior guardada por `fc -p'. La lista actual se guarda en su $HISTFILE antes de ser destruida (asumiendo que $HISTFILE y $SAVEHIST están configurados apropiadamente, por supuesto). Los valores de $HISTFILE, $HISTSIZE y $SAVEHIST se restauran a los valores que tenían cuando se llamó a `fc -p'. Ten en cuenta que esta restauración puede entrar en conflicto con la declaración de estas variables como "locales", por lo que lo mejor es evitar declaraciones locales para estas variables en funciones que usan `fc -p'. La única otra combinación garantizada de forma segura es declarar estas variables como locales al principio de tu función y usar la opción automática (-a) con `fc -p'. Finalmente, ten en cuenta que es legal restaurar manualmente un push marcado para restauración automática si necesitas hacerlo antes de que la función salga.

`fc -R' lee el historial del archivo dado, `fc -W' escribe el historial en el archivo dado y `fc -A' añade el historial al archivo dado. Si no se especifica ningún nombre de archivo, se asume $HISTFILE. Si se añade la opción -I a -R, solo se añaden aquellos eventos que aún no están contenidos en la lista de historial interna. Si se añade la opción -I a -A o -W, solo se añaden/escriben aquellos eventos que son nuevos desde la última adición/escritura incremental al archivo de historial. En cualquier caso, el archivo creado no tendrá más de $SAVEHIST entradas.

Las banderas -M y +M

El uso de la opción -M no puede combinarse con ninguna de las opciones manejadas por typeset -f.

functions -M func_matematica define func_matematica como el nombre de una función matemática reconocida en todas las formas de expresiones aritméticas; consulta la sección `Evaluación Aritmética' en zshmisc(1). Por defecto, func_matematica puede tomar cualquier número de argumentos separados por comas. Si se da min, debe tener exactamente min argumentos; si se dan min y max, debe tener al menos min y como máximo max argumentos. max puede ser -1 para indicar que no hay límite superior.

Por defecto, la función se implementa mediante una función de shell del mismo nombre; si se especifica func_shell, proporciona el nombre de la función de shell correspondiente mientras que func_matematica sigue siendo el nombre utilizado en expresiones aritméticas. El nombre de la función en $0 es func_matematica (no func_shell como sería usualmente el caso), siempre que la opción FUNCTION_ARGZERO esté en vigor. Los parámetros posicionales en la función de shell corresponden a los argumentos de la llamada a la función matemática.

El resultado de la última expresión aritmética evaluada dentro de la función de shell da el resultado de la función matemática. Esto no se limita a las sustituciones aritméticas de la forma $((...)), sino que también incluye expresiones aritméticas evaluadas de cualquier otra manera, incluyendo el comando incorporado let, las sentencias ((...)), e incluso el comando incorporado return y las subíndices de arrays. Por lo tanto, se debe tener cuidado de no usar construcciones sintácticas que realicen evaluación aritmética después de evaluar lo que será el resultado de la función. Por ejemplo:

# INCORRECTO
zmath_cube() {
  (( $1 * $1 * $1 ))
  return 0
}
functions -M cube 1 1 zmath_cube
print $(( cube(3) ))

Esto imprimirá `0' debido al return.

Comentar el return llevaría a un problema diferente: la sentencia ((...)) se convertiría en la última sentencia de la función, por lo que el *estado de retorno* ($?) de la función sería distinto de cero (indicando fallo) siempre que el *resultado* *aritmético* de la función fuera cero (numéricamente):

# INCORRECTO
zmath_cube() {
  (( $1 * $1 * $1 ))
}
functions -M cube 1 1 zmath_cube
print $(( cube(0) ))

En su lugar, se puede usar el comando incorporado true:

# CORRECTO
zmath_cube() {
  (( $1 * $1 * $1 ))
  true
}
functions -M cube 1 1 zmath_cube
print $(( cube(3) ))

Si se da la opción adicional -s a functions -M, el argumento de la función es una cadena única: todo lo que está entre el paréntesis de apertura y el de cierre correspondiente se pasa a la función como un único argumento, incluso si incluye comas o espacios en blanco. Por lo tanto, los especificadores de argumento mínimo y máximo deben ser 1 si se dan. Una lista de argumentos vacía se pasa como una cadena de longitud cero. Así, la siguiente función de cadena toma un único argumento, incluidas las comas, e imprime 11:

stringfn() { (( $#1 )); true }
functions -Ms stringfn
print $(( stringfn(foo,bar,rod) ))

functions -M sin argumentos lista todas las funciones definidas por el usuario de esta manera, con el mismo formato que una definición. Con la opción adicional -m y una lista de argumentos, se listan todas las funciones cuyos func_matematica coinciden con uno de los argumentos del patrón.

function +M elimina la lista de funciones matemáticas; con la opción adicional -m, los argumentos se tratan como patrones y se eliminan todas las funciones cuyos func_matematica coinciden con el patrón. Ten en cuenta que la función de shell que implementa el comportamiento no se elimina (independientemente de si su nombre coincide con func_matematica).

trap [ arg ] [ sig ... ]
arg es una serie de comandos (generalmente entrecomillados para protegerlos de la evaluación inmediata por el shell) que se leerán y ejecutarán cuando el shell reciba cualquiera de las señales especificadas por uno o más argumentos sig. Cada sig puede darse como un número, o como el nombre de una señal, ya sea con o sin la cadena SIG delante (por ejemplo, 1, HUP y SIGHUP son la misma señal).

Si arg es `-', entonces las señales especificadas se restauran a sus valores predeterminados o, si no hay argumentos sig, se restauran todas las trampas.

Si arg es una cadena vacía, entonces el shell (y los comandos que invoca) ignorarán las señales especificadas.

Si se omite arg pero se proporcionan uno o más argumentos sig (es decir, el primer argumento es un número o nombre de señal válido), el efecto es el mismo que si arg se hubiera especificado como `-'.

El comando trap sin argumentos imprime una lista de comandos asociados con cada señal.

Si sig es ZERR, entonces se ejecutará arg después de cada comando con un estado de salida distinto de cero. ERR es un alias para ZERR en sistemas que no tienen señal SIGERR (este es el caso habitual).

Si sig es DEBUG, entonces se ejecutará arg antes de cada comando si la opción DEBUG_BEFORE_CMD está establecida (como lo está por defecto), de lo contrario, después de cada comando. Aquí, un `comando' es lo que se describe como una `sublista' en la gramática del shell, ver la sección COMANDOS SIMPLES Y PIPELINES en zshmisc(1). Si DEBUG_BEFORE_CMD está establecido, están disponibles varias características adicionales. Primero, es posible omitir el siguiente comando estableciendo la opción ERR_EXIT; ver la descripción de la opción ERR_EXIT en zshoptions(1). Además, el parámetro del shell ZSH_DEBUG_CMD se establece en la cadena correspondiente al comando a ejecutar después de la trampa. Tenga en cuenta que esta cadena se reconstruye a partir del formato interno y puede que no esté formateada de la misma manera que el texto original. El parámetro se desestablece después de que se ejecuta la trampa.

Si sig es 0 o EXIT y la sentencia trap se ejecuta dentro del cuerpo de una función, entonces el comando arg se ejecutará después de que la función se complete. El valor de $? al inicio de la ejecución es el estado de salida del shell o el estado de retorno de la función que termina. Si sig es 0 o EXIT y la sentencia trap no se ejecuta dentro del cuerpo de una función, entonces el comando arg se ejecutará cuando el shell termine; la trampa se ejecuta antes que cualquier función de hook zshexit.

Las trampas ZERR, DEBUG y EXIT no se ejecutan dentro de otras trampas. Las trampas ZERR y DEBUG se mantienen dentro de subshells, mientras que otras trampas se restauran.

Tenga en cuenta que las trampas definidas con el comando interno trap son ligeramente diferentes de las definidas como `TRAPNAL () { ... }', ya que estas últimas tienen su propio entorno de función (números de línea, variables locales, etc.) mientras que las primeras utilizan el entorno del comando en el que se llamaron. Por ejemplo,

trap 'print $LINENO' DEBUG

imprimirá el número de línea de un comando ejecutado después de que se ejecute, mientras que

TRAPDEBUG() { print $LINENO; }

imprimirá siempre el número cero.

Se permiten nombres de señal alternativos como se describe en kill más arriba. Definir una trampa bajo cualquiera de los nombres elimina cualquier trampa bajo un nombre alternativo. Sin embargo, se recomienda que, por coherencia, los usuarios se ciñan exclusivamente a un nombre o a otro.

Ejemplos de las diferencias entre el análisis de comandos y palabras reservadas:

# Análisis de palabras reservadas
typeset svar=$(echo una palabra) avar=(varias palabras)

Lo anterior crea un parámetro escalar svar y un parámetro de matriz avar como si las asignaciones hubieran sido

svar="una palabra"
avar=(varias palabras)

Por otro lado:

# Interfaz de builtin normal
builtin typeset svar=$(echo dos palabras)

La palabra clave builtin hace que lo anterior utilice la interfaz de builtin estándar de typeset en la que el análisis de argumentos se realiza de la misma manera que para otros comandos. Este ejemplo crea un escalar svar que contiene el valor dos y otro parámetro escalar palabras sin valor. Un valor de matriz en este caso provocaría un error o se trataría como un conjunto oscuro de calificadores de globos.

Se permiten argumentos arbitrarios si tienen la forma de asignaciones después de la expansión de la línea de comandos; sin embargo, estos solo realizan asignación escalar:

var='svar=valor'
typeset $var

Lo anterior establece el parámetro escalar svar en el valor valor. Los paréntesis alrededor del valor dentro de var no causarían asignación de matriz, ya que se tratarán como caracteres ordinarios cuando se sustituya $var. Cualquier expansión no trivial en la parte del nombre de la asignación hace que el argumento se trate de esta manera:

typeset {var1,var2,var3}=nombre

La sintaxis anterior es válida y tiene el efecto esperado de establecer los tres parámetros al mismo valor, pero la línea de comandos se analiza como un conjunto de tres argumentos de línea de comandos normales para typeset después de la expansión. Por lo tanto, no es posible asignar a múltiples matrices por este medio.

Tenga en cuenta que cada interfaz de cualquiera de los comandos puede deshabilitarse por separado. Por ejemplo, `disable -r typeset' deshabilita la interfaz de palabra reservada para typeset, exponiendo la interfaz de builtin, mientras que `disable typeset' deshabilita la de builtin. Tenga en cuenta que deshabilitar la interfaz de palabra reservada para typeset puede causar problemas con la salida de `typeset -p', que asume que la interfaz de palabra reservada está disponible para restaurar valores de matriz y matriz asociativa.

A diferencia de las sentencias de asignación de parámetros, el estado de salida de typeset en una asignación que involucra una sustitución de comandos no refleja el estado de salida de la sustitución de comandos. Por lo tanto, para probar un error en una sustitución de comandos, separe la declaración del parámetro de su inicialización:

# INCORRECTO
typeset var1=$(exit 1) || echo "Problema con var1"
# CORRECTO
typeset var1 && var1=$(exit 1) || echo "Problema con var1"

Para inicializar un parámetro param a la salida de un comando y marcarlo como de solo lectura, use typeset -r param o readonly param después de la sentencia de asignación del parámetro.

Si no se dan banderas de atributo, y no hay argumentos nombre presentes o se usa la bandera +m, entonces cada nombre de parámetro impreso va precedido por una lista de los atributos de ese parámetro (array, association, exported, float, integer, readonly o undefined para parámetros autoloaded no cargados todavía). Si se usa +m con banderas de atributo, y todas esas banderas se introducen con +, se imprimen los nombres de los parámetros coincidentes pero no sus valores.

Las siguientes banderas de control cambian el comportamiento de typeset:

+
Si `+' aparece solo en una palabra separada como última opción, entonces se imprimen los nombres de todos los parámetros (funciones con -f), pero no los valores (cuerpos de función). No pueden aparecer argumentos nombre, y es un error que sigan otras opciones a `+'. El efecto de `+' es como si todas las banderas de atributo que lo preceden se dieran con un prefijo `+'. Por ejemplo, `typeset -U +' es equivalente a `typeset +U' y muestra los nombres de todas las matrices que tienen el atributo de unicidad, mientras que `typeset -f -U +' muestra los nombres de todas las funciones autoloadables. Si + es la única opción, entonces también se imprime información de tipo (matriz, solo lectura, etc.) para cada parámetro, de la misma manera que `typeset +m "*"'.
-g
El -g (global) significa que cualquier parámetro resultante no estará restringido al ámbito local. Tenga en cuenta que esto no significa necesariamente que el parámetro será global, ya que la bandera se aplicará a cualquier parámetro existente (incluso si no está establecido) de una función envolvente. Esta bandera no afecta al parámetro después de la creación, por lo tanto, no tiene ningún efecto al listar parámetros existentes, ni la bandera +g tiene ningún efecto excepto en combinación con -m (ver abajo).

BUILTIN COMMANDS typeset

Set attributes for shell variables and functions.

Synopsis typeset [] [ ] [ ] [ ] [ []] [ []] [ []] [ ] [ []] [] [ ] [] [ []] name [=value] ...

typeset is equivalent to -h, except that it is equivalent to declare.

typeset may be used to restrict the attributes and default values of shell variables.

When used with options that specify attributes, but without any name arguments, typeset lists the attributes and values of all shell variables that have any of the specified attributes. If no options are given, all shell variables are listed.

If any name is given, then the attributes are applied to each named variable. If an assignment of the form name=value is present, then the variable is set to that value.

If the shell is operating in POSIX mode (see the -o option to the shell builtin `set'), or if the POSIX_BUILTINS option is set, then typeset behaves like the POSIX shell builtin `declare'.

The following options are available:

-T [ ]
Tie the scalar parameter to the array parameter. If the array parameter is also tied, the scalar parameter must have the same separator character. If no separator character is given, it defaults to the first character of the value of the parameter `fs'. If only one of the scalar or array parameter is given a value, the other is set to the same value. If both are given values, the values must be compatible. If the array is indexed, its elements are accessed by means of the scalar parameter.

For example, if `typeset -T scalar array' is executed, then `$scalar' expands to the value of the first element of `array', and setting `scalar' sets the first element of `array'.

If the scalar parameter is assigned a value, the array is split into elements based on the separator character. The array parameter may be explicitly indexed (e.g., `array[1]'). If the array parameter is not explicitly indexed, it is assumed to be indexed starting from 1.

Assigning to an array element using explicit indexing changes the scalar parameter only if the array is tied to the scalar parameter. Assigning to an array element updates the scalar parameter if it is not assigned an explicit value.

The attribute flags described below are applied to both parameters. If the attribute flags are different, the behaviour is undefined, except for the export attribute. The export attribute of the scalar parameter is used.

There is no way to break the tie without unsetting both parameters.

The attribute flags described below are applied to both parameters. If the attribute flags are different, the behaviour is undefined, except for the export attribute. The export attribute of the scalar parameter is used.

The character set for the special characters in the characters are not yet supported.

Only one of the scalar and array parameters may be assigned an initial value (the restrictions on assignment forms described above also apply).
Both the scalar and the array may be manipulated as normal. If one is unset, the other will automatically be unset too. There is no way of untying the variables without unsetting them, nor of converting the type of one of them with another typeset command; +T does not work, assigning an array to scalar is an error, and assigning a scalar to array sets it to be a single-element array.
Note that both `typeset -xT ...' and `export -T ...' work, but only the scalar will be marked for export. Setting the value using the scalar version causes a split on all separators (which cannot be quoted). It is possible to apply -T to two previously tied variables but with a different separator character, in which case the variables remain joined as before but the separator is changed.
When an existing scalar is tied to a new array, the value of the scalar is preserved but no attribute other than export will be preserved.

Attribute flags that transform the final value (-L, -R, -Z, -l, -u) are only applied to the expanded value at the point of a parameter expansion expression using `$'. They are not applied when a parameter is retrieved internally by the shell for any purpose.

The following attribute flags may be specified:

-A
The names refer to associative array parameters; see `Array Parameters' in zshparam(1).
-L [ n ]
Left justify and remove leading blanks from the value when the parameter is expanded. If n is nonzero, it defines the width of the field. If n is zero, the width is determined by the width of the value of the first assignment. In the case of numeric parameters, the length of the complete value assigned to the parameter is used to determine the width, not the value that would be output.

The width is the count of characters, which may be multibyte characters if the MULTIBYTE option is in effect. Note that the screen width of the character is not taken into account; if this is required, use padding with parameter expansion flags ${(ml...)...} as described in `Parameter Expansion Flags' in zshexpn(1).

When the parameter is expanded, it is filled on the right with blanks or truncated if necessary to fit the field. Note truncation can lead to unexpected results with numeric parameters. Leading zeros are removed if the -Z flag is also set.

-R [ n ]
Similar to -L, except that right justification is used; when the parameter is expanded, the field is left filled with blanks or truncated from the end. May not be combined with the -Z flag.
-U
For arrays (but not for associative arrays), keep only the first occurrence of each duplicated value. This may also be set for tied parameters (see -T) or colon-separated special parameters like PATH or FIGNORE, etc. Note the flag takes effect on assignment, and the type of the variable being assigned to is determinative; for variables with shared values it is therefore recommended to set the flag for all interfaces, e.g. `typeset -U PATH path'.

This flag has a different meaning when used with -f; see below.

-Z [ n ]
Specially handled if set along with the -L flag. Otherwise, similar to -R, except that leading zeros are used for padding instead of blanks if the first non-blank character is a digit. Numeric parameters are specially handled: they are always eligible for padding with zeroes, and the zeroes are inserted at an appropriate place in the output.
-a
The names refer to array parameters. An array parameter may be created this way, but it may be assigned to in the typeset statement only if the reserved word form of typeset is enabled (as it is by default). When displaying, both normal and associative arrays are shown.
-f
The names refer to functions rather than parameters. No assignments can be made, and the only other valid flags are -t, -T, -k, -u, -U and -z. The flag -t turns on execution tracing for this function; the flag -T does the same, but turns off tracing for any named (not anonymous) function called from the present one, unless that function also has the -t or -T flag. The -u and -U flags cause the function to be marked for autoloading; -U also causes alias expansion to be suppressed when the function is loaded. See the description of the `autoload' builtin for details.

Note that the builtin functions provides the same basic capabilities as typeset -f but gives access to a few extra options; autoload gives further additional options for the case typeset -fu and typeset -fU.

-h
Hide: only useful for special parameters (those marked `<S>' in the table in zshparam(1)), and for local parameters with the same name as a special parameter, though harmless for others. A special parameter with this attribute will not retain its special effect when made local. Thus after `typeset -h PATH', a function containing `typeset PATH' will create an ordinary local parameter without the usual behaviour of PATH. Alternatively, the local parameter may itself be given this attribute; hence inside a function `typeset -h PATH' creates an ordinary local parameter and the special PATH parameter is not altered in any way. It is also possible to create a local parameter using `typeset +h special', where the local copy of special will retain its special properties regardless of having the -h attribute. Global special parameters loaded from shell modules (currently those in zsh/mapfile and zsh/parameter) are automatically given the -h attribute to avoid name clashes.
-H
Hide value: specifies that typeset will not display the value of the parameter when listing parameters; the display for such parameters is always as if the `+' flag had been given. Use of the parameter is in other respects normal, and the option does not apply if the parameter is specified by name, or by pattern with the -m option. This is on by default for the parameters in the zsh/parameter and zsh/mapfile modules. Note, however, that unlike the -h flag this is also useful for non-special parameters.
-i [ n ]
Use an internal integer representation. If n is nonzero it defines the output arithmetic base, otherwise it is determined by the first assignment. Bases from 2 to 36 inclusive are allowed.
-E [ n ]
Use an internal double-precision floating point representation. On output the variable will be converted to scientific notation. If n is nonzero it defines the number of significant figures to display; the default is ten.
-F [ n ]
Use an internal double-precision floating point representation. On output the variable will be converted to fixed-point decimal notation. If n is nonzero it defines the number of digits to display after the decimal point; the default is ten.
-l
Convert the result to lower case whenever the parameter is expanded. The value is not converted when assigned.
-r
The given names are marked readonly. Note that if name is a special parameter, the readonly attribute can be turned on, but cannot be then turned off.

If the POSIX_BUILTINS option is set, the readonly attribute is more restrictive: unset variables can be marked readonly and cannot then be set; furthermore, the readonly attribute cannot be removed from any variable.

It is still possible to change other attributes of the variable though, some of which like -U or -Z would affect the value. More generally, the readonly attribute should not be relied on as a security mechanism.

Note that in zsh (like in pdksh but unlike most other shells) it is still possible to create a local variable of the same name as this is considered a different variable (though this variable, too, can be marked readonly). Special variables that have been made readonly retain their value and readonly attribute when made local.

-t
Tags the named parameters. Tags have no special meaning to the shell. This flag has a different meaning when used with -f; see above.
-u
Convert the result to upper case whenever the parameter is expanded. The value is not converted when assigned. This flag has a different meaning when used with -f; see above.
-x
Mark for automatic export to the environment of subsequently executed commands. If the option GLOBAL_EXPORT is set, this implies the option -g, unless +g is also explicitly given; in other words the parameter is not made local to the enclosing function. This is for compatibility with previous versions of zsh.

zcompile [ -U ] [ -z | -k ] [ -R | -M ] file [ name ... ]
zcompile -ca [ -m ] [ -R | -M ] file [ name ... ]
zcompile -t file [ name ... ]
Este comando interno se puede utilizar para compilar funciones o scripts, almacenando la forma compilada en un archivo, y para examinar archivos que contienen la forma compilada. Esto permite una carga automática más rápida de funciones y la inclusión de scripts al evitar el análisis del texto cuando se leen los archivos.

La primera forma (sin las opciones -c, -a o -t) crea un archivo compilado. Si solo se proporciona el argumento file, el archivo de salida tendrá el nombre `file.zwc' y se colocará en el mismo directorio que file. El shell cargará el archivo compilado en lugar del archivo de función normal cuando la función se cargue automáticamente; consulte la sección `Autoloading Functions' en zshmisc(1) para una descripción de cómo se buscan las funciones de carga automática. La extensión .zwc significa `zsh word code'.

Si hay al menos un argumento name, todos los archivos con nombre especificado se compilan en el archivo de salida file dado como primer argumento. Si file no termina en .zwc, esta extensión se agrega automáticamente. Los archivos que contienen múltiples funciones compiladas se denominan archivos `digest' y están destinados a ser utilizados como elementos del array especial FPATH/fpath.

La segunda forma, con las opciones -c o -a, escribe las definiciones compiladas para todas las funciones nombradas en file. Para -c, los nombres deben ser funciones actualmente definidas en el shell, no aquellas marcadas para carga automática. Las funciones no definidas que están marcadas para carga automática pueden ser escritas usando la opción -a, en cuyo caso se busca en fpath y el contenido de los archivos de definición para esas funciones, si se encuentran, se compila en file. Si se dan tanto -c como -a, se pueden dar nombres de funciones definidas y funciones marcadas para carga automática. En cualquier caso, las funciones en los archivos escritos con las opciones -c o -a se cargarán automáticamente como si la opción KSH_AUTOLOAD estuviera desestablecida.

La razón para manejar funciones cargadas y no cargadas con diferentes opciones es que algunos archivos de definición para carga automática definen múltiples funciones, incluida la función con el mismo nombre que el archivo, y, al final, llaman a esa función. En tales casos, la salida de `zcompile -c' no incluye las funciones adicionales definidas en el archivo, y se pierde cualquier otro código de inicialización en el archivo. Usar `zcompile -a' captura toda esta información adicional.

Si la opción -m se combina con -c o -a, los names se utilizan como patrones y se escribirán todas las funciones cuyos nombres coincidan con uno de estos patrones. Si no se da ningún name, se escribirán las definiciones de todas las funciones actualmente definidas o marcadas como carga automática.

Tenga en cuenta que la segunda forma no se puede utilizar para compilar funciones que incluyan redirecciones como parte de la definición en lugar de dentro del cuerpo de la función; por ejemplo:

fn1() { { ... } >~/logfile }

se puede compilar, pero

fn1() { ... } >~/logfile

no. Es posible usar la primera forma de zcompile para compilar funciones cargables automáticamente que incluyan la definición completa de la función en lugar de solo el cuerpo de la función.

La tercera forma, con la opción -t, examina un archivo compilado existente. Sin argumentos adicionales, se enumeran los nombres de los archivos originales compilados en él. La primera línea de salida muestra la versión del shell que compiló el archivo y cómo se utilizará el archivo (es decir, leyéndolo directamente o mapeándolo en memoria). Con argumentos, no se produce ninguna salida y el estado de retorno se establece en cero si se encontraron definiciones para all names en el archivo compilado, y en no cero si la definición para al menos un name no se encontró.

Otras opciones:

-U
Los alias no se expanden al compilar los archivos nombrados.
-R
Cuando se lee el archivo compilado, su contenido se copia en la memoria del shell, en lugar de mapearse en memoria (ver -M). Esto sucede automáticamente en sistemas que no admiten el mapeo de memoria.

Al compilar scripts en lugar de funciones cargables automáticamente, a menudo es deseable usar esta opción; de lo contrario, todo el archivo, incluido el código para definir funciones que ya han sido definidas, permanecerá mapeado, desperdiciando en consecuencia memoria.

-M
El archivo compilado se mapea en la memoria del shell cuando se lee. Esto se hace de tal manera que múltiples instancias del shell ejecutándose en el mismo host compartirán este archivo mapeado. Si no se proporciona ni -R ni -M, el comando interno zcompile decide qué hacer basándose en el tamaño del archivo compilado.

-z
Estas opciones se utilizan cuando el archivo compilado contiene funciones que deben cargarse automáticamente. Si se proporciona -z, la función se cargará automáticamente como si la opción KSH_AUTOLOAD estuviera *no* establecida, incluso si está establecida en el momento en que se lee el archivo compilado, mientras que si se proporciona -k, la función se cargará como si KSH_AUTOLOAD *estuviera* establecida. Estas opciones también tienen precedencia sobre cualquier opción -k o -z especificada al comando interno autoload. Si ninguna de estas opciones se proporciona, la función se cargará según lo determine la configuración de la opción KSH_AUTOLOAD en el momento en que se lee el archivo compilado.

Estas opciones también pueden aparecer tantas veces como sea necesario entre los names listados para especificar el estilo de carga de todas las funciones siguientes, hasta el próximo -k o -z.

El archivo creado siempre contiene dos versiones del formato compilado, una para máquinas big-endian y otra para máquinas little-endian. La consecuencia de esto es que el archivo compilado es independiente de la máquina y si se lee o mapea, solo la mitad del archivo se utiliza realmente (y se mapea).

Realiza operaciones relacionadas con los módulos cargables de zsh. La carga de módulos mientras el shell se está ejecutando (`carga dinámica') no está disponible en todos los sistemas operativos, o en todas las instalaciones en un sistema operativo particular, aunque el comando zmodload siempre está disponible y se puede utilizar para manipular módulos integrados en versiones del ejecutable del shell sin carga dinámica.

Sin argumentos, se imprimen los nombres de todos los módulos binarios cargados actualmente. La opción -L hace que esta lista tenga el formato de una serie de comandos zmodload. Las formas con argumentos son:

zmodload [ -is ] name ...
zmodload -u [ -i ] name ...
En el caso más simple, zmodload carga un módulo binario. El módulo debe estar en un archivo con un nombre que consista en el name especificado seguido de un sufijo estándar, generalmente `.so' (`.sl' en HPUX). Si el módulo a cargar ya está cargado, el módulo duplicado se ignora. Si zmodload detecta una inconsistencia, como un nombre de módulo inválido o una lista de dependencias circulares, el bloque de código actual se aborta. Si está disponible, el módulo se carga si es necesario, mientras que si no está disponible, se devuelve silenciosamente un estado no cero. La opción -i se acepta por compatibilidad pero no tiene efecto.

El módulo name se busca de la misma manera que un comando, utilizando $module_path en lugar de $path. Sin embargo, la búsqueda en la ruta se realiza incluso cuando el nombre del módulo contiene un `/', lo cual suele ocurrir. No hay forma de evitar la búsqueda en la ruta.

Si el módulo soporta características (ver más abajo), zmodload intenta habilitar todas las características al cargar un módulo. Si el módulo se cargó correctamente pero no todas las características pudieron habilitarse, zmodload devuelve el estado 2.

Si se proporciona la opción -s, no se imprime ningún error si el módulo no estaba disponible (aunque se imprimen otros errores que indican un problema con el módulo). El estado de retorno indica si el módulo se cargó. Esto es apropiado si el llamador considera que el módulo es opcional.

Con -u, zmodload descarga módulos. Se debe dar el mismo name que se dio al cargar el módulo, pero no es necesario que el módulo exista en el sistema de archivos. La opción -i suprime el error si el módulo ya está descargado (o nunca se cargó).

Cada módulo tiene una función de arranque y una función de limpieza. El módulo no se cargará si falla su función de arranque. De manera similar, un módulo solo se puede descargar si su función de limpieza se ejecuta correctamente.

zmodload -F [ -almLe -P param ] módulo [ [+-]característica ... ]
zmodload -F permite un control más selectivo sobre las características proporcionadas por los módulos. Sin opciones aparte de -F, el módulo llamado módulo se carga, si no estaba ya cargado, y la lista de características se establece en el estado requerido. Si no se especifican características, el módulo se carga, si no estaba ya cargado, pero el estado de las características no cambia. Cada característica puede ir precedida de un + para activarla o de un - para desactivarla; se asume el + si no hay ningún carácter presente. Cualquier característica que no se mencione explícitamente se deja en su estado actual; si el módulo no se cargó previamente, esto significa que dichas características permanecerán deshabilitadas. El estado de retorno es cero si todas las características se establecieron, 1 si el módulo falló al cargarse y 2 si algunas características no pudieron establecerse (por ejemplo, no se pudo añadir un parámetro porque había otro parámetro con el mismo nombre) pero el módulo se cargó.

Las características estándar son incorporadas, condiciones, parámetros y funciones matemáticas; estas se indican con el prefijo `b:', `c:' (`C:' para una condición infija), `p:' y `f:', respectivamente, seguido del nombre que la característica correspondiente tendría en el shell. Por ejemplo, `b:strftime' indica una incorporada llamada strftime y p:EPOCHSECONDS indica un parámetro llamado EPOCHSECONDS. El módulo puede proporcionar otras características (`abstractas') propias, según se indica en su documentación; estas no tienen prefijo.

Con -l o -L, se listan las características proporcionadas por el módulo. Con -l solo, se muestra una lista de características junto con sus estados, una característica por línea. Con -L solo, se muestra un comando zmodload -F que haría que las características habilitadas del módulo se activaran. Con -lL, se muestra un comando zmodload -F que haría que todas las características se establecieran en su estado actual. Si una de estas combinaciones se da con la opción -P param, entonces el parámetro param se establece en una matriz de características, ya sean características junto con su estado o (si solo se da -L) características habilitadas.

Con la opción -L se puede omitir el nombre del módulo; entonces se imprime una lista de todas las características habilitadas para todos los módulos que proporcionan características, en forma de comandos zmodload -F. Si también se da -l, se muestra el estado de las características habilitadas y deshabilitadas en esa forma.

Se puede proporcionar un conjunto de características junto con -l o -L y un nombre de módulo; en ese caso, solo se considera el estado de esas características. Cada característica puede ir precedida de + o -, pero el carácter no tiene ningún efecto. Si no se proporciona ningún conjunto de características, se consideran todas las características.

Con -e, el comando primero prueba que el módulo esté cargado; si no lo está, se devuelve el estado 1. Si el módulo está cargado, se examina la lista de características dadas como argumento. Cualquier característica dada sin prefijo simplemente se prueba para ver si el módulo la proporciona; cualquier característica dada con un prefijo + o - se prueba para ver si se proporciona y en el estado dado. Si las pruebas en todas las características de la lista tienen éxito, se devuelve el estado 0, de lo contrario, el estado 1.

Con -m, cada entrada de la lista de características dada se toma como un patrón para hacer coincidir con la lista de características proporcionadas por el módulo. Se debe dar explícitamente un + o - inicial. Esto no se puede combinar con la opción -a ya que los cargadores automáticos deben especificarse explícitamente.

Con -a, la lista de características dada se marca para carga automática desde el módulo especificado, que puede que aún no esté cargado. Puede aparecer un + opcional antes del nombre de la característica. Si la característica va precedida de un -, se elimina cualquier carga automática existente. Las opciones -l y -L se pueden utilizar para listar las cargas automáticas. La carga automática es específica para características individuales; cuando se carga el módulo, solo se habilita la característica solicitada. Las solicitudes de carga automática se conservan si el módulo se descarga posteriormente hasta que se emite un `zmodload -Fa módulo -característica' explícito. No es un error solicitar una carga automática para una característica de un módulo que ya está cargado.

Cuando se carga el módulo, cada carga automática se comprueba con las características realmente proporcionadas por el módulo; si la característica no se proporciona, la solicitud de carga automática se elimina. Se imprime un mensaje de advertencia; si el módulo se está cargando para proporcionar una característica diferente y esa carga automática tiene éxito, no tiene ningún efecto en el estado del comando actual. Si el módulo ya está cargado cuando se ejecuta zmodload -Fa, se imprime un mensaje de error y se devuelve el estado 1.

zmodload -Fa se puede usar con las opciones -l, -L, -e y -P para listar y probar la existencia de características cargables automáticamente. En este caso, -l se ignora si se especifica -L. zmodload -FaL sin nombre de módulo lista las cargas automáticas para todos los módulos.

Tenga en cuenta que solo las características estándar descritas anteriormente se pueden cargar automáticamente; otras características requieren que el módulo se cargue antes de habilitarse.

zmodload -d [ -L ] [ name ]
zmodload -d name dep ...
zmodload -ud name [ dep ... ]
La opción -d se puede utilizar para especificar las dependencias del módulo. Los módulos nombrados en el segundo y posteriores argumentos se cargarán antes que el módulo nombrado en el primer argumento.

Con -d y un argumento, se listan todas las dependencias de ese módulo. Con -d y sin argumentos, se listan todas las dependencias del módulo. Esta lista está por defecto en un formato similar a Makefile. La opción -L cambia este formato a una lista de comandos zmodload -d.

Si se usan tanto -d como -u, se eliminan las dependencias. Si solo se da un argumento, se eliminan todas las dependencias de ese módulo.

zmodload -ab [ -L ]
zmodload -ab [ -i ] name [ builtin ... ]
zmodload -ub [ -i ] builtin ...
La opción -ab define incorporadas de carga automática. Define las builtins especificadas. Cuando se llama a cualquiera de esas incorporadas, se carga el módulo especificado en el primer argumento y se habilitan todas sus características (para control selectivo de características, use `zmodload -F -a' como se describe anteriormente). Si solo se da el name, se define una incorporada, con el mismo nombre que el módulo. -i suprime el error si la incorporada ya está definida o cargada automáticamente, pero no si otra incorporada con el mismo nombre ya está definida.

Con -ab y sin argumentos, se listan todas las incorporadas cargadas automáticamente, mostrando el nombre del módulo (si es diferente) entre paréntesis después del nombre de la incorporada. La opción -L cambia este formato a una lista de comandos zmodload -a.

Si -b se usa junto con la opción -u, elimina las incorporadas definidas previamente con -ab. Esto solo es posible si la incorporada aún no está cargada. -i suprime el error si la incorporada ya está eliminada (o nunca existió).

Las solicitudes de carga automática se conservan si el módulo se descarga posteriormente hasta que se emite un `zmodload -ub builtin' explícito.

zmodload -ac [ -IL ]
zmodload -ac [ -iI ] name [ cond ... ]
zmodload -uc [ -iI ] cond ...
La opción -ac se utiliza para definir códigos de condición de carga automática. Los strings cond dan los nombres de las condiciones definidas por el módulo. La opción opcional -I se usa para definir nombres de condiciones infijas. Sin esta opción, se definen nombres de condiciones de prefijo.

Si no se dan nombres de condición, se listan todos los nombres definidos (como una serie de comandos zmodload si se da la opción -L).

La opción -uc elimina las definiciones de condiciones de carga automática.

zmodload -A [ -L ] [ modalias[=module] ... ]
Para cada argumento, si se dan tanto modalias como module, se define modalias como un alias para el módulo module. Si el módulo modalias se solicita posteriormente, ya sea a través de una llamada a zmodload o implícitamente, el shell intentará cargar module en su lugar. Si no se proporciona module, se muestra la definición de modalias. Si no se proporcionan argumentos, se enumeran todos los alias de módulo definidos. Al listar, si también se proporcionó el indicador -L, se enumera la definición como un comando zmodload para recrear el alias.

La existencia de alias para módulos es completamente independiente de si el nombre resuelto se carga realmente como un módulo: mientras el alias exista, cargar y descargar el módulo bajo cualquier alias tiene exactamente el mismo efecto que usar el nombre resuelto, y no afecta la conexión entre el alias y el nombre resuelto que puede eliminarse ya sea por zmodload -R o redefiniendo el alias. Las cadenas de alias (es decir, donde el primer nombre resuelto es a su vez un alias) son válidas siempre que no sean circulares. Como los alias toman el mismo formato que los nombres de módulo, pueden incluir separadores de ruta: en este caso, no hay requisito de que exista ninguna parte de la ruta nombrada, ya que el alias se resolverá primero. Por ejemplo, `any/old/alias' es siempre un alias válido.

Las dependencias añadidas a los módulos aliased se añaden realmente al módulo resuelto; estas permanecen si el alias se elimina. Es válido crear un alias cuyo nombre sea uno de los módulos estándar del shell y que resuelva a un módulo diferente. Sin embargo, si un módulo tiene dependencias, no será posible usar el nombre del módulo como alias, ya que el módulo ya estará marcado como un módulo cargable por derecho propio.

Aparte de lo anterior, los alias se pueden usar en el comando zmodload donde se requieran nombres de módulo. Sin embargo, los alias no se mostrarán en las listas de módulos cargados con un `zmodload' desnudo.

zmodload -R modalias ...
Para cada argumento modalias que se definió previamente como un alias de módulo a través de zmodload -A, se elimina el alias. Si alguno no estaba definido, se produce un error y el resto de la línea se ignora.

Tenga en cuenta que zsh no distingue entre módulos que se enlazaron al shell y módulos que se cargan dinámicamente. En ambos casos, este comando incorporado debe usarse para hacer disponibles los comandos incorporados y otras cosas definidas por módulos (a menos que el módulo se cargue automáticamente en estas definiciones). Esto es cierto incluso para sistemas que no admiten la carga dinámica de módulos.
