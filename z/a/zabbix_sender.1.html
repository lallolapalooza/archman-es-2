DESCRIPCIÓN

zabbix_sender es una utilidad de línea de comandos para enviar datos de monitoreo al servidor o proxy de Zabbix. En el servidor Zabbix se debe crear un elemento de tipo Zabbix trapper con la clave correspondiente. Tenga en cuenta que los valores entrantes solo se aceptarán de los hosts especificados en el campo Hosts permitidos para este elemento.

OPCIONES

-c, --config archivo de configuración
Utiliza archivo de configuración. Zabbix sender lee los detalles del servidor del archivo de configuración de agentd. Por defecto, Zabbix sender no lee ningún archivo de configuración. Solo se admiten los parámetros Hostname, ServerActive, SourceIP, TLSConnect, TLSCAFile, TLSCRLFile, TLSServerCertIssuer, TLSServerCertSubject, TLSCertFile, TLSKeyFile, TLSPSKIdentity y TLSPSKFile. El nombre de host definido a través del parámetro HostnameItem no se obtendrá; en este caso, el nombre de host debe especificarse en la línea de comandos (ver opción -s). Todas las direcciones definidas en el parámetro de configuración ServerActive del agente se utilizan para enviar datos. Si el envío de datos por lotes falla a una dirección, los lotes siguientes no se envían a esa dirección.
-z, --zabbix-server servidor
Nombre del host o dirección IP del servidor Zabbix. Si un host es monitoreado por un proxy, se debe usar el nombre del host o la dirección IP del proxy en su lugar. Cuando se usa junto con --config, anula las entradas del parámetro ServerActive especificado en el archivo de configuración de agentd.
-p, --port puerto
Especifica el número de puerto del servicio de trapper de Zabbix que se ejecuta en el servidor. El valor predeterminado es 10051. Cuando se usa junto con --config, anula las entradas de puerto del parámetro ServerActive especificadas en el archivo de configuración de agentd.
-I, --source-address dirección-IP
Especifica la dirección IP de origen. Cuando se usa junto con --config, anula el parámetro SourceIP especificado en el archivo de configuración de agentd.
-t, --timeout segundos
Especifica el tiempo de espera. Rango válido: 1-300 segundos (predeterminado: 60)
-s, --host host
Especifica el nombre del host al que pertenece el elemento (tal como está registrado en el frontend de Zabbix). La dirección IP o el nombre DNS del host no funcionarán. Cuando se usa junto con --config, anula el parámetro Hostname especificado en el archivo de configuración de agentd.
-k, --key clave
Especifica la clave del elemento al que se enviará el valor.
-o, --value valor
Especifica el valor del elemento.
-i, --input-file archivo de entrada
Carga valores del archivo de entrada. Especifique - como <archivo de entrada> para leer valores de la entrada estándar. Cada línea del archivo contiene, separada por espacios en blanco: <nombre de host> <clave> <valor>. Cada valor debe especificarse en su propia línea. Cada línea debe contener 3 entradas separadas por espacios en blanco: <nombre de host> <clave> <valor>, donde "nombre de host" es el nombre del host monitoreado tal como está registrado en

NAME

zabbix_sender — utility to send Zabbix data to Zabbix server or Zabbix proxy.

SYNOPSIS

zabbix_sender [-c config] [-z zabbix_server[:port]]
    [-p port] [-t timeout] [-L] [-r] [-R max_retries]
    [-T] [-i input_file] [-k key] [-o value]
    [-s host] [-I source_ip]
    [--tls-connect value] [--tls-ca-file CA-file]
    [--tls-crl-file CRL-file] [--tls-server-cert-issuer cert-issuer]
    [--tls-server-cert-subject cert-subject] [--tls-cert-file cert-file]
    [--tls-key-file key-file] [--tls-psk-identity PSK-identity]
    [--tls-psk-file PSK-file] [--tls-cipher13 cipher-string]
    [--tls-cipher cipher-string] [-v] [-h] [-V]

DESCRIPTION

The zabbix_sender utility is used to send Zabbix data (trapped data) to Zabbix server or Zabbix proxy. It is a command line utility.

The values can be sent either one by one using -k and -o options or from a file using -i option.

Zabbix sender connects to Zabbix server or proxy specified using -z parameter. If this parameter is not specified, Zabbix sender will try to use Zabbix server IP address from agent configuration file zabbix_agentd.conf.

By default zabbix_sender sends values to port 10051. This can be changed using -p parameter.

When sending values, Zabbix sender may need to know the hostname of the monitored host and the item key. The hostname is used to identify the host in Zabbix frontend, and the key identifies the item. Both can be provided using -s and -k options respectively.

If -s option is not specified, Zabbix sender will use the hostname from the agent configuration file. If both -s and -k options are omitted, Zabbix sender will try to obtain hostname and key from the agent configuration file.

The value can be sent using -o option.

Values can also be sent from a file using the -i option. The file format is described below.

The -t option specifies timeout in seconds for network operations.

The -L option enables sending of values individually.

The -r option enables sending of values one by one as soon as they are received. This can be used when reading from standard input.

The -R option specifies maximum number of retries for network operations.

When sending values from a file, the input file can contain multiple entries, each on a new line. Each entry consists of three parts: hostname, key, and value. Hostname and key are quoted and separated by whitespace. The value follows the key, separated by whitespace.

The -T option allows sending timestamped values. Each line in the input file must contain four parts: hostname, key, timestamp, and value. The timestamp must be in Unix timestamp format. If the Zabbix server uses triggers that reference the item, all timestamps must be in increasing order to ensure correct event calculation.

The -N option, when used with -T, allows sending nanosecond precision timestamps. Each line in the input file must contain five parts: hostname, key, timestamp, nanoseconds, and value.

The -I option specifies the source IP address to be used for sending data.

TLS/SSL encryption can be enabled using the respective options. The --tls-connect option specifies the encryption method. Other --tls-* options specify the paths to certificate and key files, CA files, etc.

OPTIONS

-c, --config config
Use the specified configuration file. If this option is not specified, zabbix_sender will try to use zabbix_agentd.conf in the current directory or in /usr/local/etc/zabbix/, /etc/zabbix/.
-z, --server zabbix_server
Specifies the Zabbix server or proxy hostname or IP address. If this option is omitted, the hostname from the configuration file is used.
-p, --port port
Specifies the port on which Zabbix server or proxy is listening. Default is 10051.
-t, --timeout timeout
Specifies timeout in seconds for network operations. Default is 3.
-L, --send-individual-messages
Send each value in a separate message.
-r, --real-time
Send values one by one as soon as they are received. This can be used when reading from standard input.
-R, --retries max_retries
Maximum number of retries for network operations. Default is 1.
-T, --with-timestamps
This option can be only used with --input-file option.

Each line of the input file must contain 4 whitespace delimited entries: <hostname> <key> <timestamp> <value>. Timestamp should be specified in Unix timestamp format. If target item has triggers referencing it, all timestamps must be in an increasing order, otherwise event calculation will not be correct.

An example of a line of the input file:

"Linux DB3" db.connections 1429533600 43

For more details please see option --input-file.

If a timestamped value is sent for a host that is in a “no data” maintenance type then this value will be dropped; however, it is possible to send a timestamped value in for an expired maintenance period and it will be accepted.

-N, --with-ns
This option can be only used with --with-timestamps option.

Each line of the input file must contain 5 whitespace delimited entries: <hostname> <key> <timestamp> <ns> <value>.

An example of a line of the input file:

"Linux DB3" db.connections 1429533600 7402561 43

For more details please see option --input-file.

-i, --input-file input_file
Read values from the specified file. Use - for standard input.

Input file format:

Each line consists of three whitespace delimited fields:

  • <hostname> - hostname of the monitored host.
  • <key> - item key for Zabbix frontend.
  • <value> - the value to send.

If <hostname> is omitted, the value from the -s parameter will be used. If -s is also omitted, the value from the agent configuration file will be used. If <key> is omitted, the value from the -k parameter will be used. If -k is also omitted, the value from the agent configuration file will be used. If <value> is omitted, the value from the -o parameter will be used.

Specify - as <hostname> to use hostname from agent configuration file or from --host argument. The value is sent to Zabbix server or proxy defined in Zabbix sender configuration file. If server/proxy is not defined in config file, use -z parameter.

An example of a line of an input file:

"Linux DB3" db.connections 43

The value type must be correctly set in item configuration of Zabbix frontend. Zabbix sender will send up to 250 values in one connection. Contents of the input file must be in the UTF-8 encoding. All values from the input file are sent in a sequential order top-down. Entries must be formatted using the following rules:

•
Quoted and non-quoted entries are supported.
•
Double-quote is the quoting character.
•
Entries with whitespace must be quoted.
•
Double-quote and backslash characters inside quoted entry must be escaped with a backslash.
•
Escaping is not supported in non-quoted entries.
•
Linefeed escape sequences (\n) are supported in quoted strings.
•
Linefeed escape sequences are trimmed from the end of an entry.
-T, --with-timestamps
This option can be only used with --input-file option.

Each line of the input file must contain 4 whitespace delimited entries: <hostname> <key> <timestamp> <value>. Timestamp should be specified in Unix timestamp format. If target item has triggers referencing it, all timestamps must be in an increasing order, otherwise event calculation will not be correct.

An example of a line of the input file:

"Linux DB3" db.connections 1429533600 43

For more details please see option --input-file.

If a timestamped value is sent for a host that is in a “no data” maintenance type then this value will be dropped; however, it is possible to send a timestamped value in for an expired maintenance period and it will be accepted.

-N, --with-ns
This option can be only used with --with-timestamps option.

Each line of the input file must contain 5 whitespace delimited entries: <hostname> <key> <timestamp> <ns> <value>.

An example of a line of the input file:

"Linux DB3" db.connections 1429533600 7402561 43

For more details please see option --input-file.

-k, --key key
Item key.
-o, --value value
Value to send.
-s, --host host
Monitored host name. If this parameter is omitted, the hostname from the configuration file is used.
-I, --source-ip source_ip
Source IP address to use for sending data.
--tls-connect value
How to connect to server or proxy. Values:
unencrypted
connect without encryption (default)
psk
connect using TLS and a pre-shared key
cert
connect using TLS and a certificate
--tls-ca-file CA-file
Full pathname of a file containing the top-level CA(s) certificates for peer certificate verification.
--tls-crl-file CRL-file
Full pathname of a file containing revoked certificates.
--tls-server-cert-issuer cert-issuer
Allowed server certificate issuer.
--tls-server-cert-subject cert-subject
Allowed server certificate subject.
--tls-cert-file cert-file
Full pathname of a file containing the certificate or certificate chain.
--tls-key-file key-file
Full pathname of a file containing the private key.
--tls-psk-identity PSK-identity
PSK-identity string.
--tls-psk-file PSK-file
Full pathname of a file containing the pre-shared key.
--tls-cipher13 cipher-string
Cipher string for OpenSSL 1.1.1 or newer for TLS 1.3. Override the default ciphersuite selection criteria. This option is not available if OpenSSL version is less than 1.1.1.
--tls-cipher cipher-string
GnuTLS priority string (for TLS 1.2 and up) or OpenSSL cipher string (only for TLS 1.2). Override the default ciphersuite selection criteria.
-v, --verbose
Verbose mode, -vv for more details.
-h, --help
Display this help and exit.
-V, --version
Output version information and exit.

EXIT STATUS

The exit status is 0 if the values were sent and all of them were successfully processed by server. If data was sent, but processing of at least one of the values failed, the exit status is 2. If data sending failed, the exit status is 1.

EXAMPLES

zabbix_sender -c /etc/zabbix/zabbix_agentd.conf -k mysql.queries -o 342.45

Send 342.45 as the value for mysql.queries item of monitored host. Use monitored host and Zabbix server defined in agent configuration file.

zabbix_sender -c /etc/zabbix/zabbix_agentd.conf -s "Monitored Host" -k mysql.queries -o 342.45

Send 342.45 as the value for mysql.queries item of Monitored Host host using Zabbix server defined in agent configuration file.

zabbix_sender -z 192.168.1.113 -i data_values.txt


Send values from file data_values.txt to Zabbix server with IP 192.168.1.113. Host names and keys are defined in the file.

echo "- hw.serial.number 1287872261 SQ4321ASDF" | zabbix_sender -c /usr/local/etc/zabbix_agentd.conf -T -i -

Send a timestamped value from the commandline to Zabbix server, specified in the agent configuration file. Dash in the input data indicates that hostname also should be used from the same configuration file.

echo '"Zabbix server" trapper.item ""' | zabbix_sender -z 192.168.1.113 -p 10000 -i -

Send empty value of an item to the Zabbix server with IP address 192.168.1.113 on port 10000 from the commandline. Empty values must be indicated by empty double quotes.

zabbix_sender -z 192.168.1.113 -s "Monitored Host" -k mysql.queries -o 342.45 --tls-connect cert --tls-ca-file /home/zabbix/zabbix_ca_file --tls-cert-file /home/zabbix/zabbix_agentd.crt --tls-key-file /home/zabbix/zabbix_agentd.key

Send 342.45 as the value for mysql.queries item in Monitored Host host to server with IP 192.168.1.113 using TLS with certificate.

zabbix_sender -z 192.168.1.113 -s "Monitored Host" -k mysql.queries -o 342.45 --tls-connect psk --tls-psk-identity "PSK ID Zabbix agentd" --tls-psk-file /home/zabbix/zabbix_agentd.psk

Send 342.45 as the value for mysql.queries item in Monitored Host host to server with IP 192.168.1.113 using TLS with pre-shared key (PSK).
