NOMBRE

zmap - El Escáner Rápido de Internet

SINOPSIS

zmap [ -p <puerto(s)> ] [ -o <archivo_salida> ] [ OPCIONES... ] [ ip/nombre_host/rango ]

DESCRIPCIÓN

ZMap es una herramienta de red para escanear todo el espacio de direcciones IPv4 (o grandes muestras). ZMap es capaz de escanear toda la Internet en aproximadamente 45 minutos en una conexión de red gigabit, alcanzando ~98% de la velocidad teórica de línea.

OPCIONES

OPCIONES BÁSICAS

ip/nombre_host/rango
Direcciones IP o nombres de host DNS a escanear. Acepta rangos de IP en notación de bloque CIDR. Por defecto es 0.0.0/8
-p, --puertos_objetivo=puerto(s)
Lista de puertos TCP/UDP y/o rangos de puertos a escanear (ej. 80,443,100-105). Use ' * ' para escanear todos los puertos, incluido el puerto 0.
-o, --archivo_salida=nombre
Cuando se utiliza un módulo de salida que usa un archivo, escriba los resultados en este archivo. Use - para stdout.
-b, --archivo_lista_bloqueo=ruta
Archivo de subredes a excluir, en notación CIDR, una por línea. Se recomienda usar esto para excluir direcciones RFC 1918, multicast, espacio reservado de IANA y otras direcciones de propósito especial de IANA. Un ejemplo de archivo de lista de bloqueo blocklist.conf para este propósito.
-w, --archivo_lista_permisos=ruta
Archivo de subredes a escanear, en notación CIDR, una por línea. Especificar un archivo de lista de permisos es equivalente a especificar rangos directamente en la interfaz de línea de comandos, pero permite especificar un gran número de subredes. Nota: si está especificando un gran número de direcciones IP individuales (más de 10 millones), debería usar --archivo_lista_ips en su lugar.
-I, --archivo_lista_ips=ruta
Archivo de direcciones IP individuales a escanear, una por línea. Esta característica le permite escanear un gran número de direcciones no relacionadas. Si tiene un pequeño número de IPs, es más rápido especificarlas en la línea de comandos o usando --archivo_lista_permisos. Esto solo debe usarse al escanear más de 10 millones de direcciones. Cuando se usa con --archivo_lista_permisos, solo se escanearán los hosts en la intersección de ambos conjuntos. Los hosts especificados aquí, pero incluidos en la lista de bloqueo, serán excluidos.

OPCIONES DE ESCANEO

-r, --tasa=pps
Establece la tasa de envío en paquetes/segundo. Nota: cuando se combina con --sondas, esto es el total de paquetes por segundo, no IPs por segundo. Establecer la tasa a 0 escaneará a velocidad de línea completa. Por defecto: 10000 pps.
-B, --ancho_banda=bps
Establece la tasa de envío en bits/segundo (admite sufijos G, M y K (ej. -B 10M para 10 mbps). Esto anula el indicador --tasa.
-n, --max_objetivos=n
Limita el número de objetivos a sondear. Esto puede ser un número (ej. -n 1000) o un porcentaje (ej. -n 0.1%) del espacio de direcciones escaneable (después de excluir la lista de bloqueo). Un objetivo es un par IP/puerto, si se escanean múltiples puertos, y una IP en caso contrario. En el caso de porcentajes y múltiples puertos, el porcentaje es del número total de combinaciones de pares IP/puerto.
-N, --max_resultados=n
Salir después de recibir este número de resultados
-t, --tiempo_max_ejecucion=segundos
Limita la duración del envío de paquetes
-c, --tiempo_enfriamiento=segundos
Cuánto tiempo continuar recibiendo después de que se haya completado el envío (por defecto=8)
-e, --semilla=n
Semilla utilizada para seleccionar la permutación de direcciones. Úselo si desea escanear direcciones en el mismo orden para múltiples ejecuciones de ZMap.
-P, --sondas=n
Número de sondas a enviar a cada par IP/Puerto (por defecto=1). Dado que ZMap compone tramas Ethernet directamente, las sondas pueden perderse en el camino hacia el destino. Aumentar --sondas aumenta la probabilidad de que un host en línea reciba una sonda en una red poco confiable. Esto se contrasta con --reintentos, que simplemente da el número de intentos de enviar una sola sonda en la NIC de origen.
--reintentos=n
Número de veces que se intentará reenviar un paquete si falla la llamada sendto (por defecto=10)
--lote=n
Número de paquetes a agrupar antes de llamar a la llamada del sistema apropiada para enviarlos. Se usa para aprovechar la llamada del sistema sendmmsg de Linux para enviar todo el lote a la vez. Solo disponible en Linux, otros sistemas operativos enviarán cada paquete individualmente. (por defecto=64)

FRAGMENTACIÓN DE ESCANEO

--fragmentos=N
Dividir el escaneo en N fragmentos/particiones entre diferentes instancias de zmap (por defecto=1). Al fragmentar, se requiere --semilla.
--fragmento=n
Establecer qué fragmento escanear (por defecto=0). Los fragmentos tienen índice 0 en el rango [0, N), donde N es el número total de fragmentos. Al fragmentar, se requiere --semilla.

OPCIONES DE RED

-s, --puerto_origen=puerto|rango
Puerto(s) de origen para enviar paquetes desde
--validar_puerto_origen=habilitar|deshabilitar
Se utiliza como anulación para habilitar/deshabilitar la validación del puerto de origen. La validación del puerto de origen comprobará que el puerto de origen de una respuesta de sonda recibida coincida con el puerto de destino de la sonda enviada a ese par IP/puerto. Esto garantiza que múltiples escaneos de ZMap a los mismos hosts pero a diferentes puertos no interfieran entre sí. Esto anula el comportamiento predeterminado de cada módulo sobre si validar o no los puertos de origen con respuestas de sonda.
-S, --ip_origen=ip|rango
Dirección(es) de origen para enviar paquetes desde. Ya sea una IP única o un rango (ej. 10.0.0.1-10.0.0.9)
-G, --mac_puerta_enlace=direccion
Dirección MAC de la puerta de enlace para enviar paquetes (en caso de que la autodetección falle)
--mac_origen=direccion
Dirección MAC de origen para enviar paquetes desde (en caso de que la autodetección falle)
-i, --interfaz=nombre
Interfaz de red a usar
-X, --iplayer
Enviar paquetes de capa IP en lugar de paquetes Ethernet (para interfaces no Ethernet)
(Netmap solo) Esperar a que la IP responda a la solicitud de eco ICMP antes de comenzar el escaneo. Útil si está conectado a un conmutador con STP habilitado, donde el reinicio de PHY necesario para entrar y salir del modo Netmap hará que el conmutador mute el puerto hasta que el protocolo de árbol de expansión haya determinado que el enlace debe configurarse en estado de reenvío.
--netmap-wait-ping=ip

OPCIONES DE SONDA

ZMap permite a los usuarios especificar y escribir sus propios módulos de sonda. Los módulos de sonda son responsables de generar paquetes de sonda para enviar y procesar las respuestas de los hosts.

--listar_modulos_sonda
Listar módulos de sonda disponibles (ej. tcp_synscan)
-M, --modulo_sonda=nombre
Seleccionar módulo de sonda (por defecto=tcp_synscan)
--args_sonda=args
Argumentos a pasar al módulo de sonda
--ttl_sonda=saltos
Establecer el valor TTL para los paquetes IP de sonda

NAME

zmap - internet-wide network scanner

SYNOPSIS

zmap [-b allowlist] [-B blocklist] [-p port] [-o output file] [-f fields] [-M module] [-d] [-q] [-v verbosity] [-l log file] [-m metadata file] [-w status file] [-C config file] [-T threads] [-E repeat interval] [-N target count]

DESCRIPTION

ZMap is a tool designed for the Internet-wide measurement. It is capable of scanning the entire IPv4 address space in an average of 45 minutes. ZMap is not a traditional vulnerability scanner. It is designed to send a probe packet to each IP address on the Internet (or a specified subset) and collect the response. The purpose of ZMap is to allow researchers to conduct large-scale network measurements in a timely manner.

ZMap is highly configurable. You can specify the probe module to use, the output module for results, the ports to scan, the number of threads to use, and much more. The options are broadly categorized below.

OPTIONS

TARGET SELECTION

-b, --allowlist=filename
Path to a file containing a list of IP addresses or networks to scan. Each line should contain a CIDR-formatted IP address or network. If not specified, ZMap will default to scanning the entire IPv4 address space.
-B, --blocklist=filename
Path to a file containing a list of IP addresses or networks to exclude from the scan. Each line should contain a CIDR-formatted IP address or network.
-N, --target-count=number
Scan exactly this many target IP addresses. This option overrides the allowlist/blocklist files if used. By default, ZMap scans the entire IPv4 address space.
-p, --target-port=port
Scan the specified port number. Defaults to 80.
-E, --repeat-interval=seconds
Set the time interval, in seconds, between repeated scans of the same IP address. Default is 10 seconds.
--probes-per-target=number
Number of probes to send to each target IP address. Default is 1.

PROBE MODULE OPTIONS

ZMap allows users to select different probe modules for scanning different protocols. The available probe modules and their options are listed below.

-M, --probe-module=name
Select the probe module to use for the scan. Defaults to.
--probe-args=args
Arguments to pass to the probe module. The arguments are probe-module specific. See the documentation for each probe module for available arguments.
--list-probe-modules
List available probe modules.
--list-output-fields
List the fields the selected probe module can send to the output module

OUTPUT OPTIONS

ZMap allows users to specify and write their own output modules for use with ZMap. Output modules are responsible for processing the fieldsets returned by the probe module, and outputting them to the user. Users can specify output fields, and write filters over the output fields.

--list-output-modules
List available output modules (e.g. csv)
-O, --output-module=name
Select output module (default=csv)
--output-args=args
Arguments to pass to output module
-f, --output-fields=fields
Comma-separated list of fields to output
--output-filter
Specify an output filter over the fields defined by the probe module. See the output filter section for more details.
--no-header-row
Excludes any header rows (e.g., CSV header fields) from ZMap output. This is useful if you´re piping results into another application that expects only data.

RESPONSE DEDUPLICATION

Hosts will oftentimes send multiple responses to a probe (either because the scanner doesn´t send back a RST packet or because the host has a misimplemented TCP stack. To address this, ZMap will attempt to deduplicate responsive (ip,port) targets.

--dedup-method
Specifies the method ZMap will use to deduplicate responses. Options are: full, window, and none. Full deduplication uses a 32-bit bitmap and guarantees that no duplicates will be emitted. However, full-deduplication requires around 500MB of memory for a single port. We do not support full deduplication for multiple ports. Window uses a sliding window of the last (user-defined) number of responses as set by --dedup-window-size. None will prevent any deduplication.
--dedup-window-size=targets
Specifies the size of the sliding window as the last n target responses to be used for deduplication. Only applicable if using window deduplication.

LOGGING AND METADATA OPTIONS

-q, --quiet
Do not print status updates once per second
-v, --verbosity=n
Level of log detail (0-5, default=3)
-l, --log-file=filename
Output file for log messages. By default, stderr.
-m, --metadata-file=filename
Output file for scan metadata (JSON)
-L, --log-directory
Write log entries to a timestamped file in this directory
-u, --status-updates-file
Write scan progress updates to CSV file"
--disable-syslog
Disables logging messages to syslog
--notes
Inject user-specified notes into scan metadata
--user-metadata
Inject user-specified JSON metadata into scan metadata

ADDITIONAL OPTIONS

-T, --sender-threads=n
Threads used to send packets. ZMap will attempt to detect the optimal number of send threads based on the number of processor cores. Defaults to min(4, number of processor cores on host - 1).
-C, --config=filename
Read a configuration file, which can specify any other options.
-d, --dryrun
Print out each packet to stdout instead of sending it (useful for debugging)
--fast-dryrun
Don´t actually send packets, print out a binary representation probe dst IP and dst Port. Used for faster integration tests, not for general use.
--max-sendto-failures
Maximum NIC sendto failures before scan is aborted
--min-hitrate
Minimum hitrate that scan can hit before scan is aborted
--cores
Comma-separated list of cores to pin to
--ignore-blocklist-errors
Ignore invalid, malformed, or unresolvable entries in allowlist/blocklist file. Replaces the pre-v3.x --ignore-invalid-hosts option.
-h, --help
Print help and exit
-V, --version
Print version and exit

OUTPUT FILTERS

Results generated by a probe module can be filtered before being passed to the output module. Filters are defined over the output fields of a probe module. Filters are written in a simple filtering language, similar to SQL, and are passed to ZMap using the --output-filter option. Output filters are commonly used to filter out duplicate results, or to only pass only successful responses to the output module.

Filter expressions are of the form <fieldname> <operation> <value>. The type of <value> must be either a string or unsigned integer literal, and match the type of <fieldname>. The valid operations for integer comparisons are = !=, ,, =,=. The operations for string comparisons are =, !=. The --list-output-fields flag will print what fields and types are available for the selected probe module, and then exit.

Compound filter expressions may be constructed by combining filter expressions using parenthesis to specify order of operations, the && (logical AND) and || (logical OR) operators.

For example, a filter for only successful, non-duplicate responses would be written as: --output-filter="success = 1 && repeat = 0"

UDP PROBE MODULE OPTIONS

These arguments are all passed using the --probe-args=args option. Only one argument may be passed at a time.

file:/path/to/file
Path to payload file to send to each host over UDP.
template:/path/to/template
Path to template file. For each destination host, the template file is populated, set as the UDP payload, and sent.
text:<text>
ASCII text to send to each destination host
hex:<hex>
Hex-encoded binary to send to each destination host
template-fields
Print information about the allowed template fields and exit.

MID-SCAN CHANGES

You can change the rate at which ZMap is scanning mid-scan by sending SIGUSR1 (increase) and SIGUSR2 (decrease) signals to ZMap. These will result in the scan rate increasing or decreasing by 5%.
