ZMQ_SETSOCKOPT(3) Manual de 0MQ ZMQ_SETSOCKOPT(3)

NOMBRE

zmq_setsockopt - establecer opciones de socket 0MQ

SINOPSIS

int zmq_setsockopt (void *socket, int option_name, const void *option_value, size_t option_len);

Precaución: Todas las opciones, con la excepción de ZMQ_SUBSCRIBE, ZMQ_UNSUBSCRIBE, ZMQ_LINGER, ZMQ_ROUTER_HANDOVER, ZMQ_ROUTER_MANDATORY, ZMQ_PROBE_ROUTER, ZMQ_XPUB_VERBOSE, ZMQ_XPUB_VERBOSER, ZMQ_REQ_CORRELATE, ZMQ_REQ_RELAXED, ZMQ_SNDHWM y ZMQ_RCVHWM, solo surten efecto para las siguientes conexiones/enlaces de socket.

Específicamente, las opciones de seguridad surten efecto para las llamadas posteriores de enlace/conexión, y pueden cambiarse en cualquier momento para afectar los enlaces y/o conexiones posteriores.

DESCRIPCIÓN

La función zmq_setsockopt() establecerá la opción especificada por el argumento option_name al valor apuntado por el argumento option_value para el socket 0MQ apuntado por el argumento socket. El argumento option_len es el tamaño del valor de la opción en bytes. Para opciones que toman un valor de tipo "cadena de caracteres", los datos de bytes proporcionados no deben contener bytes nulos, o deben terminar en un único byte nulo (carácter NUL ASCII terminador).

Las siguientes opciones de socket se pueden establecer con la función zmq_setsockopt():

ZMQ_AFFINITY: Establecer la afinidad de hilos I/O

La opción ZMQ_AFFINITY establecerá la afinidad de hilos I/O para las conexiones recién creadas en el socket especificado.

La afinidad determina qué hilos del grupo de hilos I/O de 0MQ asociados con el contexto del socket manejarán las conexiones recién creadas. Un valor de cero especifica ninguna afinidad, lo que significa que el trabajo se distribuirá equitativamente entre todos los hilos I/O de 0MQ en el grupo. Para valores distintos de cero, el bit de menor orden corresponde al hilo 1, el segundo bit de menor orden al hilo 2, y así sucesivamente. Por ejemplo, un valor de 3 especifica que las conexiones posteriores en el socket serán manejadas exclusivamente por los hilos I/O 1 y 2.

Ver también zmq_init(3) para detalles sobre la asignación del número de hilos I/O para un contexto específico.

Tipo de valor de opción uint64_t
Unidad de valor de opción N/A (mapa de bits)
Valor predeterminado 0
Tipos de socket aplicables N/A

ZMQ_BINDTODEVICE: Establecer el nombre del dispositivo al que se enlazará el socket

La opción ZMQ_BINDTODEVICE enlaza este socket a un dispositivo particular, por ejemplo, una interfaz o VRF. Si un socket está enlazado a una interfaz, solo los paquetes recibidos de esa interfaz particular son procesados por el socket. Si el dispositivo es un dispositivo VRF, entonces los enlaces/conexiones posteriores a ese socket utilizan direcciones en la tabla de enrutamiento VRF.

ZMQ_BUSY_POLL: Esto elimina los retrasos causados por la interrupción y el cambio de contexto resultante.

El sondeo activo (busy polling) ayuda a reducir la latencia en la ruta de recepción de red al permitir que el código de la capa de socket consulte la cola de recepción de un dispositivo de red y deshabilite las interrupciones de red. Esto elimina los retrasos causados por la interrupción y el cambio de contexto resultante. Sin embargo, también aumenta la utilización de la CPU. El sondeo activo también evita que la CPU duerma, lo que puede generar un consumo de energía adicional.

ZMQ_CONNECT_RID: Asignar el próximo ID de conexión saliente

ZMQ_CONNECT_ROUTING_ID: Asignar el próximo ID de enrutamiento saliente

La opción ZMQ_CONNECT_ROUTING_ID establece el ID del par conectado a través de la próxima llamada a zmq_connect(), de modo que esa conexión esté inmediatamente lista para la transferencia de datos con el ID de enrutamiento dado. Esta opción se aplica solo a la primera llamada subsiguiente a zmq_connect(), las llamadas posteriores a zmq_connect() usan el comportamiento de conexión predeterminado.

El uso típico es establecer esta opción de socket antes de cada llamada a zmq_connect(). Cada conexión DEBE tener asignado un ID de enrutamiento único. No se permite asignar un ID de enrutamiento que ya esté en uso.

Útil al conectar ROUTER con ROUTER, o STREAM con STREAM, ya que permite enviar inmediatamente a los pares. Se aplican los requisitos de formateo del ID de enrutamiento saliente para los sockets ROUTER y STREAM.

El ID de enrutamiento debe tener entre 1 y 255 bytes de longitud y NO PUEDE comenzar con un byte cero (dichos IDs de enrutamiento están reservados para uso interno de la infraestructura 0MQ).

ZMQ_HANDSHAKE_IVL: Establecer el intervalo máximo de handshake

La opción ZMQ_HEARTBEAT_IVL establecerá el intervalo entre el envío de latidos ZMTP para el socket especificado. Si esta opción se establece y es mayor que 0, entonces se enviará un comando ZMTP PING cada ZMQ_HEARTBEAT_IVL milisegundos.

ZMQ_HEARTBEAT_TIMEOUT: Establecer el tiempo de espera para los latidos ZMTP

La opción ZMQ_HEARTBEAT_TIMEOUT establecerá cuánto tiempo esperar antes de agotar el tiempo de espera de una conexión después de enviar un comando ZMTP PING y no recibir ningún tráfico. Esta opción solo es válida si ZMQ_HEARTBEAT_IVL también está establecido y es mayor que 0. La conexión agota el tiempo de espera si no se recibe tráfico después de enviar el comando PING, pero el tráfico recibido no tiene por qué ser un comando PONG; cualquier tráfico recibido cancelará el tiempo de espera.

La opción ZMQ_HEARTBEAT_TTL establecerá el tiempo de espera en el par remoto para los latidos ZMTP. ZMQ_IMMEDIATE: Cola mensajes solo a conexiones completadas

Por defecto, las colas se llenarán en conexiones salientes incluso si la conexión no se ha completado. Esto puede generar mensajes "perdidos" en sockets con enrutamiento round-robin (REQ, PUSH, DEALER). Si esta opción se establece en 1, los mensajes se pondrán en cola solo para conexiones completadas. Esto hará que el socket se bloquee si no hay otras conexiones, pero evitará que las colas se llenen en tuberías que esperan conexión.

Tipo de valor de opción int
Unidad de valor de opción booleano
Valor por defecto 0 (falso)
Tipos de socket aplicables todos, solo para transportes orientados a conexión.

ZMQ_INVERT_MATCHING: Invertir el filtrado de mensajes

Invierte el comportamiento de filtrado de los sockets PUB-SUB, cuando se establece en 1.

En los sockets PUB y XPUB, esto hace que los mensajes se envíen a todos los sockets conectados excepto a aquellos suscritos a un prefijo que coincide con el mensaje. En los sockets SUB, esto hace que solo se reciban por el usuario los mensajes entrantes que no coinciden con ninguna de las suscripciones del socket.

Cuando ZMQ_INVERT_MATCHING se establece en 1 en un socket PUB, todos los sockets SUB que se conecten a él también deben tener la opción establecida en 1. Si no lo hacen, los sockets SUB rechazarán todo lo que el socket PUB les envíe. Los sockets XSUB no necesitan hacer esto porque no filtran los mensajes entrantes.

Tipo de valor de opción int
Unidad de valor de opción 0,1
Valor por defecto 0
Tipos de socket aplicables ZMQ_PUB, ZMQ_XPUB, ZMQ_SUB

ZMQ_LINGER: Establecer período de espera para el cierre del socket

La opción ZMQ_LINGER establecerá el período de espera para el socket especificado. El período de espera determina cuánto tiempo los mensajes pendientes que aún no se han enviado a un par permanecerán en memoria después de que un socket se desconecte con zmq_disconnect(3) o se cierre con zmq_close(3), y afecta además a la terminación del contexto del socket con zmq_ctx_term(3). Lo siguiente describe los diferentes comportamientos:

•Un valor de -1 especifica un período de espera infinito. Los mensajes pendientes no se descartarán después de una llamada a zmq_disconnect() o zmq_close(); intentar terminar el contexto del socket con zmq_ctx_term() se bloqueará hasta que todos los mensajes pendientes se hayan enviado a un par.
•El valor de 0 especifica ningún período de espera. Los mensajes pendientes se descartarán inmediatamente después de una llamada a zmq_disconnect() o zmq_close().
•Los valores positivos especifican un límite superior para el período de espera en milisegundos. Los mensajes pendientes no se descartarán después de una llamada a zmq_disconnect() o zmq_close(); intentar terminar el contexto del socket con zmq_ctx_term() se bloqueará hasta que todos los mensajes pendientes se hayan enviado a un par, o hasta que expire el período de espera, después de lo cual se descartarán los mensajes pendientes.
Tipo de valor de opción int
Unidad de valor de opción milisegundos
Valor por defecto -1 (infinito)
Tipos de socket aplicables todos

ZMQ_METADATA: Añadir propiedades de metadatos de aplicación a un socket

La opción ZMQ_METADATA añadirá metadatos de aplicación al socket especificado; los metadatos se intercambian con los pares durante la configuración de la conexión. Una propiedad de metadatos se especifica como una cadena, delimitada por dos puntos, comenzando con la propiedad de metadatos seguida del valor de los metadatos, por ejemplo, "X-key:value". Los nombres de las propiedades están restringidos a un máximo de 255 caracteres y deben ir precedidos de "X-". Se pueden añadir múltiples propiedades de metadatos a un socket ejecutando zmq_setsockopt() varias veces. Dado que el argumento es una cadena terminada en nulo, los datos binarios deben codificarse antes de añadirse, por ejemplo, usando Z85 (zmq_z85_encode(3)).

en estado DRAFT, aún no disponible en versiones estables.

RETURN VALUE

The zmq_setsockopt() function shall return zero if successful. Otherwise it shall return -1 and set errno to one of the values defined below.

ERRORS

EINVAL

The requested option option_name is unknown, or the requested option_len or option_value is invalid.

ETERM

The 0MQ context associated with the specified socket was terminated.

ENOTSOCK

The provided socket was invalid.

EINTR

The operation was interrupted by delivery of a signal.

EXAMPLE

Subscribing to messages on a ZMQ_SUB socket.

/* Subscribe to all messages */
rc = zmq_setsockopt (socket, ZMQ_SUBSCRIBE, "", 0);
assert (rc == 0);
/* Subscribe to messages prefixed with "ANIMALS.CATS" */
rc = zmq_setsockopt (socket, ZMQ_SUBSCRIBE, "ANIMALS.CATS", 12);

Setting I/O thread affinity.

int64_t affinity;
/* Incoming connections on TCP port 5555 shall be handled by I/O thread 1 */
affinity = 1;
rc = zmq_setsockopt (socket, ZMQ_AFFINITY, &affinity, sizeof (affinity));
assert (rc);
rc = zmq_bind (socket, "tcp://lo:5555");
assert (rc);
/* Incoming connections on TCP port 5556 shall be handled by I/O thread 2 */
affinity = 2;
rc = zmq_setsockopt (socket, ZMQ_AFFINITY, &affinity, sizeof (affinity));
assert (rc);
rc = zmq_bind (socket, "tcp://lo:5556");
assert (rc);
