NOMBRE

zmq_ctx_set - establecer opciones del contexto

SINOPSIS

int zmq_ctx_set (void *context, int option_name, int option_value);

DESCRIPCIÓN

La función zmq_ctx_set() establecerá la opción especificada por el argumento option_name al valor del argumento option_value.

La función zmq_ctx_set() acepta las siguientes opciones:

ZMQ_BLOCKY: Corregir comportamiento bloqueante

Por defecto, el contexto se bloqueará, para siempre, en una llamada a zmq_ctx_term. La suposición detrás de este comportamiento es que la terminación abrupta causará pérdida de mensajes. La mayoría de las aplicaciones reales utilizan alguna forma de handshake para asegurar que las aplicaciones reciban los mensajes de terminación, y luego terminan el contexto con ZMQ_LINGER establecido en cero en todos los sockets. Esta configuración es una forma más fácil de obtener el mismo resultado. Cuando ZMQ_BLOCKY se establece en false, a todos los nuevos sockets se les da un tiempo de espera de lingering de cero. Aún debe cerrar todos los sockets antes de llamar a zmq_ctx_term.

Valor por defecto true (comportamiento anterior)

ZMQ_IO_THREADS: Establecer número de hilos de E/S

El argumento ZMQ_IO_THREADS especifica el tamaño del pool de hilos de 0MQ para manejar operaciones de E/S. Si su aplicación solo usa el transporte inproc para la mensajería, puede establecerlo en cero, de lo contrario, establézcalo en al menos uno. Esta opción solo se aplica antes de crear cualquier socket en el contexto.

Valor por defecto 1

ZMQ_THREAD_SCHED_POLICY: Establecer política de planificación para hilos de E/S

El argumento ZMQ_THREAD_SCHED_POLICY establece la política de planificación para el pool de hilos interno del contexto. Esta opción no está disponible en Windows. Los valores admitidos para esta opción se pueden encontrar en el archivo sched.h, o en http://man7.org/linux/man-pages/man2/sched_setscheduler.2.html. Esta opción solo se aplica antes de crear cualquier socket en el contexto.

Valor por defecto -1

ZMQ_THREAD_PRIORITY: Establecer prioridad de planificación para hilos de E/S

El argumento ZMQ_THREAD_PRIORITY establece la prioridad de planificación para el pool de hilos interno del contexto. Esta opción no está disponible en Windows. Los valores admitidos para esta opción dependen de la política de planificación elegida. En Linux, cuando la política de planificación es SCHED_OTHER, SCHED_IDLE o SCHED_BATCH, el planificador del SO no utilizará la prioridad del hilo sino el valor "nice" del hilo; en tales casos, si ZMQ_THREAD_PRIORITY se establece en un valor estrictamente positivo, se utilizará la llamada al sistema "nice" para establecer el valor nice en -20 (prioridad máxima) en lugar de ajustar la prioridad del hilo (que debe ser cero para esas políticas de planificación). Los detalles se pueden encontrar en el archivo sched.h, o en http://man7.org/linux/man-pages/man2/sched_setscheduler.2.html. Esta opción solo se aplica antes de crear cualquier socket en el contexto.

Valor por defecto -1

ZMQ_THREAD_AFFINITY_CPU_ADD: Añadir una CPU a la lista de afinidad para hilos de E/S

El argumento ZMQ_THREAD_AFFINITY_CPU_ADD añade una CPU específica a la lista de afinidad para el pool de hilos del contexto interno. Esta opción solo se admite en Linux. Esta opción solo se aplica antes de crear cualquier socket en el contexto. La lista de afinidad por defecto está vacía y significa que no se establecerá ninguna afinidad de CPU explícita en los hilos del contexto interno.

Valor por defecto -1

ZMQ_THREAD_AFFINITY_CPU_REMOVE: Eliminar una CPU de la lista de afinidad para hilos de E/S

El argumento ZMQ_THREAD_AFFINITY_CPU_REMOVE elimina una CPU específica de la lista de afinidad para el pool de hilos del contexto interno. Esta opción solo se admite en Linux. Esta opción solo se aplica antes de crear cualquier socket en el contexto. La lista de afinidad por defecto está vacía y significa que no se establecerá ninguna afinidad de CPU explícita en los hilos del contexto interno.

Valor por defecto -1

ZMQ_THREAD_NAME_PREFIX: Establecer prefijo de nombre para hilos de E/S

El argumento ZMQ_THREAD_NAME_PREFIX establece un prefijo numérico para cada hilo creado para el pool de hilos del contexto interno. Esta opción solo se admite en Linux. Esta opción es útil para depurar a través de "top -H" o "gdb"; en caso de que varios procesos en el sistema utilicen ZeroMQ, es útil proporcionar a través de esta opción de contexto un prefijo específico de la aplicación para distinguir los hilos de fondo de ZeroMQ que pertenecen a diferentes procesos. Esta opción solo se aplica antes de crear cualquier socket en el contexto.

Valor por defecto -1

ZMQ_MAX_MSGSZ: Establecer tamaño máximo de mensaje

El argumento ZMQ_MAX_MSGSZ establece el tamaño máximo permitido de un mensaje enviado en el contexto. Puede consultar el valor máximo permitido con zmq_ctx_get(3) utilizando la opción ZMQ_MAX_MSGSZ.

Valor por defecto INT_MAX
Valor máximo INT_MAX

ZMQ_ZERO_COPY_RECV: Especificar estrategia de decodificación de mensajes

El argumento ZMQ_ZERO_COPY_RECV especifica si el decodificador de mensajes debe utilizar una estrategia de copia cero al recibir mensajes. La estrategia de copia cero puede provocar un mayor uso de memoria en algunos casos. Esta opción le permite utilizar la estrategia de copia anterior. Puede consultar el valor de esta opción con zmq_ctx_get(3) utilizando la opción ZMQ_ZERO_COPY_RECV. NOTA: en estado DRAFT, aún no disponible en versiones estables.

Valor por defecto 1

ZMQ_MAX_SOCKETS: Establecer número máximo de sockets

El argumento ZMQ_MAX_SOCKETS establece el número máximo de sockets permitidos en el contexto. Puede consultar el valor máximo permitido con zmq_ctx_get(3) utilizando la opción ZMQ_SOCKET_LIMIT.

Valor por defecto 1023

ZMQ_IPV6: Establecer opción IPv6

El argumento ZMQ_IPV6 establece si el contexto debe usar IPv6 para todos los transports. Si esta opción está establecida en 1, el contexto usará IPv6. Si está establecida en 0, el contexto usará IPv4. Nota: Esta opción solo se puede establecer antes de crear cualquier socket en el contexto.

Valor por defecto 0

ZMQ_IPV6: Establecer opción IPv6

El argumento ZMQ_IPV6 establece el valor IPv6 para todos los sockets creados en el contexto a partir de este momento. Un valor de 1 significa que IPv6 está habilitado, mientras que 0 significa que el socket solo usará IPv4. Cuando IPv6 está habilitado, un socket se conectará a, o aceptará conexiones de, hosts tanto IPv4 como IPv6.

Valor por defecto 0

VALOR DE RETORNO

La función zmq_ctx_set() devuelve cero si tiene éxito. De lo contrario, devuelve -1 y establece errno a uno de los valores definidos a continuación.

ERRORES

EINVAL

La opción solicitada option_name es desconocida.

EJEMPLO

Establecer un límite en el número de sockets.

void *context = zmq_ctx_new ();
zmq_ctx_set (context, ZMQ_MAX_SOCKETS, 256);
int max_sockets = zmq_ctx_get (context, ZMQ_MAX_SOCKETS);
assert (max_sockets == 256);
