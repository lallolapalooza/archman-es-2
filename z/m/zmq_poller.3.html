NOMBRE

zmq_poller - multiplexación de entrada/salida

SINOPSIS

void *zmq_poller_new (void);

int zmq_poller_destroy (void **poller_p);

int zmq_poller_size (void *poller);

int zmq_poller_add (void *poller, void *socket, void *user_data, short events);

int zmq_poller_modify (void *poller, void *socket, short events);

int zmq_poller_remove (void *poller, void *socket);

int zmq_poller_add_fd (void *poller, int fd, void *user_data, short events);

int zmq_poller_modify_fd (void *poller, int fd, short events);

int zmq_poller_remove_fd (void *poller, int fd);

int zmq_poller_wait (void *poller, zmq_poller_event_t *event, long timeout);

int zmq_poller_wait_all (void *poller, zmq_poller_event_t *events, int n_events, long timeout);

int zmq_poller_fd (void *poller, zmq_fd_t *fd);

DESCRIPCIÓN

Las funciones zmq_poller_* proporcionan un mecanismo para que las aplicaciones multiplexen eventos de entrada/salida en un modo de disparo de nivel sobre un conjunto de sockets.

zmq_poller_new y zmq_poller_destroy gestionan la vida útil de una instancia del poller. zmq_poller_new crea y devuelve una nueva instancia del poller, mientras que zmq_poller_destroy la destruye. Se debe pasar un puntero a un poller válido como argumento poller_p de zmq_poller_destroy. En particular, no se puede llamar a zmq_poller_destroy varias veces para la misma instancia del poller. zmq_poller_destroy establece el puntero pasado a NULL en caso de una ejecución exitosa. zmq_poller_destroy anula el registro implícitamente de todos los sockets y descriptores de archivo registrados.

zmq_poller_size consulta el número de sockets o descriptores de archivo registrados con un poller. El tamaño inicial de un poller es 0; una operación de adición exitosa incrementa el tamaño en 1 y una operación de eliminación exitosa lo decrementa en 1. El tamaño no se ve afectado por los eventos especificados.

zmq_poller_add, zmq_poller_modify y zmq_poller_remove gestionan los sockets 0MQ registrados con un poller.

zmq_poller_add registra un nuevo socket con un poller dado. Tanto poller como socket deben apuntar a objetos 0MQ válidos. El parámetro events especifica a qué tipos de eventos desea suscribirse el cliente. Es legal especificar ningún evento (es decir, 0) y activarlos más tarde con zmq_poller_modify. Adicionalmente, se puede especificar user_data, que no es utilizado por el poller, pero se devuelve al llamador cuando se señala un evento en una llamada a zmq_poller_wait o zmq_poller_wait_all. user_data puede ser NULL. Si no es NULL, debe ser un puntero válido. De lo contrario, el comportamiento es indefinido. Solo debe añadir un socket a una única instancia de poller una vez (a menos que se haya llamado a zmq_poller_remove para ese socket antes). Puede añadir un socket a múltiples instancias de poller, si el socket en sí mismo es explícitamente thread-safe (Servidor, Cliente, ...). Si el socket no lo es, puede invocar comportamiento indefinido.

zmq_poller_modify modifica los eventos suscritos para un socket. Es legal especificar ningún evento (es decir, 0) para deshabilitar los eventos temporalmente y reactivarlos más tarde con otra llamada a zmq_poller_modify.

zmq_poller_remove elimina completamente un registro de socket. Se debe llamar a zmq_poller_remove antes de que un socket sea cerrado con zmq_close.

Tenga en cuenta que no es necesario llamar a zmq_poller_remove para ningún socket antes de llamar a zmq_poller_destroy.

También tenga en cuenta que llamar a zmq_poller_remove no es equivalente a llamar a zmq_poller_modify sin eventos. zmq_poller_modify no libera los recursos asociados con el registro del socket y requiere que el socket siga siendo válido.

zmq_poller_add_fd, zmq_poller_modify_fd y zmq_poller_remove_fd son análogos a las funciones anteriores pero gestionan descriptores de archivo regulares registrados con un poller. En Windows, estas funciones solo se pueden usar con sockets WinSock.

En lo siguiente, los sockets 0MQ añadidos con zmq_poller_add y los descriptores de archivo añadidos con zmq_poller_add_fd se denominan objetos registrados.

La estructura zmq_poller_event_t se define de la siguiente manera:

typedef struct
{
    void *socket;
    zmq_fd_t fd;
    void *user_data;
    short events;
} zmq_poller_event_t;

Para cada objeto registrado, zmq_poller_wait_all() examinará los objetos registrados en busca de los eventos actualmente registrados.

Si ninguno de los eventos registrados ha ocurrido, zmq_poller_wait_all esperará timeout milisegundos a que ocurra un evento en cualquiera de los objetos registrados. Si el valor de timeout es 0, zmq_poller_wait_all devolverá inmediatamente. Si el valor de timeout es -1, zmq_poller_wait_all se bloqueará indefinidamente hasta que ocurra un evento en cualquiera de los objetos registrados.

El argumento events de zmq_poller_wait_all debe ser un puntero a un array de al menos n_events elementos. El comportamiento es indefinido si events no apunta a un array de al menos n_events elementos.

zmq_poller_wait_all devuelve como máximo n_events eventos. Si se señalaron más de n_events eventos, solo se devuelve un subconjunto no especificado de los eventos señalados a través de events.

Se aconseja al llamador asegurarse de que n_events sea igual al número de objetos registrados. De lo contrario, puede ocurrir una situación de livelock: si más de n_events objetos registrados tienen un evento activo en cada llamada a zmq_poller_wait_all, podría suceder que siempre se devuelva el mismo subconjunto de objetos registrados, y el llamador nunca note los eventos en los otros. El número de objetos registrados se puede consultar con zmq_poller_size.

zmq_poller_wait_all devuelve el número de elementos válidos. Los elementos válidos se colocan en las posiciones 0 a n_events - 1 en el array events. Todos los miembros de un elemento válido son establecidos con valores válidos por zmq_poller_wait_all. Para eventos de socket, socket no es NULL y fd es un valor específico del sistema operativo para un socket inválido (-1 o INVALID_SOCKET). Para eventos de fd, socket es NULL y fd es un descriptor de archivo válido. Por lo tanto, el cliente no necesita inicializar el contenido del array events antes de una llamada a zmq_poller_wait_all. No está especificado si los elementos restantes de events son escritos por zmq_poller_wait_all.

zmq_poller_fd consulta el descriptor de archivo asociado con el zmq_poller y lo almacena en la dirección apuntada por fd. Solo se garantiza que el zmq_poller tenga un descriptor de archivo si hay al menos un socket thread-safe registrado actualmente.

Tenga en cuenta que cerrar un socket registrado en un poller resulta en un comportamiento indefinido. El socket debe ser desregistrado primero.

TIPOS DE EVENTOS

El parámetro events de zmq_poller_add y zmq_poller_modify, y el miembro events de la estructura zmq_poller_event_t son máscaras de bits construidas mediante OR lógico de una combinación de las siguientes banderas de eventos:

ZMQ_POLLIN

Para sockets 0MQ, se puede recibir al menos un mensaje del socket sin bloquear. Para sockets estándar, esto es equivalente al flag POLLIN de la llamada al sistema poll() y generalmente significa que se puede leer al menos un byte de datos de fd sin bloquear.

ZMQ_POLLOUT

Para sockets 0MQ, se puede enviar al menos un mensaje al socket sin bloquear. Para sockets estándar, esto es equivalente al flag POLLOUT de la llamada al sistema poll() y generalmente significa que se puede escribir al menos un byte de datos en fd sin bloquear.
zmq_poller(3)

NAME

zmq_poller - 0MQ event poller

SYNOPSIS

#include <zmq.h>
void *zmq_poller_new (void);
int zmq_poller_destroy (void **poller_p);
int zmq_poller_size (void *poller);
int zmq_poller_add (void *poller, void *socket, void *user_data, int events);
int zmq_poller_modify (void *poller, void *socket, void *user_data, int events);
int zmq_poller_remove (void *poller, void *socket);
int zmq_poller_add_fd (void *poller, int fd, void *user_data, int events);
int zmq_poller_modify_fd (void *poller, int fd, void *user_data, int events);
int zmq_poller_remove_fd (void *poller, int fd);
int zmq_poller_wait (void *poller, zmq_poller_event_t *events, size_t max_events, int timeout);
int zmq_poller_wait_all (void *poller, zmq_poller_event_t *events, size_t max_events, int timeout);
int zmq_poller_fd (void *poller);

DESCRIPTION

The 0MQ poller is an object that allows applications to monitor multiple 0MQ sockets and standard file descriptors for activity. It is implemented using the 0MQ internal mechanisms, or by using underlying operating system polling interfaces such as poll(), epoll(), kqueue(), or IOCP.

Use zmq_poller_new to create a new poller object. Use zmq_poller_destroy to destroy it. Use zmq_poller_size to retrieve the number of sockets and file descriptors currently registered with the poller.

Use zmq_poller_add to register a 0MQ socket with the poller. Use zmq_poller_add_fd to register a standard file descriptor. The events argument specifies the events to monitor. The user_data argument is an optional user-defined pointer that will be returned by zmq_poller_wait and zmq_poller_wait_all.

Use zmq_poller_modify and zmq_poller_modify_fd to change the events being monitored for a registered socket or file descriptor. Use zmq_poller_remove and zmq_poller_remove_fd to unregister a socket or file descriptor.

Use zmq_poller_wait or zmq_poller_wait_all to wait for events to occur on any of the registered sockets or file descriptors. The events argument is an array of zmq_poller_event_t structures that will be filled with information about the events that occurred. The max_events argument specifies the maximum number of events to return. The timeout argument specifies the maximum time in milliseconds to wait for events. A value of -1 will wait indefinitely.

zmq_poller_wait will return as soon as at least one event is available. zmq_poller_wait_all will return when all events that occurred within the timeout period have been retrieved. If the timeout is reached and no events are available, zmq_poller_wait_all returns EAGAIN.

The zmq_poller_event_t structure is defined as:

typedef struct {
    void *socket;       /* 0MQ socket, or NULL if it's a file descriptor */
    int fd;             /* File descriptor, or -1 if it's a 0MQ socket */
    void *user_data;    /* User data pointer */
    int events;         /* Bitmask of events for this object */
} zmq_poller_event_t;

Use zmq_poller_fd to retrieve the underlying file descriptor used by the poller itself. This can be useful for integrating with external polling mechanisms. Note that not all poller implementations expose an underlying file descriptor.

EVENT TYPES

The following event types can be specified in the events argument:

ZMQ_POLLIN

Monitors sockets and file descriptors that have data available for reading.

ZMQ_POLLOUT

Monitors sockets and file descriptors that are ready for writing.

ZMQ_POLLERR

For 0MQ sockets this flag has no effect on the zmq_poller_add and zmq_poller_modify functions, and is never set in the events member of the zmq_poller_event_t structure. For standard sockets, this flag is passed through zmq_poller_wait_all to the underlying poll() system call and generally means that some sort of error condition is present on the socket specified by fd.

ZMQ_POLLPRI

For 0MQ sockets this flag has no effect on the zmq_poller_add and zmq_poller_modify functions, and is never set in the events member of the zmq_poller_event_t structure. For standard sockets this means there is urgent data to read. Refer to the POLLPRI flag for more information. For a file descriptor, refer to your OS documentation: as an example, GPIO interrupts are signaled through a POLLPRI event. This flag has no effect on Windows.

Note

The zmq_poller*_ functions may be implemented or emulated using operating system interfaces other than poll(), and as such may be subject to the limits of those interfaces in ways not defined in this documentation.

THREAD SAFETY

Like most other 0MQ objects, a poller is not thread-safe. All operations must be called from the same thread. Otherwise, behaviour is undefined.

In addition to that, if you want to add a socket to multiple existing poller instances, the socket itself needs to be thread-safe (Server, Client, ...). Otherwise, behaviour is undefined.

RETURN VALUE

zmq_poller_new returns a valid pointer to a poller, or NULL in case of a failure.

All functions that return an int, return -1 in case of a failure. In that case, zmq_errno() can be used to query the type of the error as described below.

zmq_poller_wait_all returns the number of events signalled and returned in the events array. It never returns 0.

All other functions return 0 in case of a successful execution.

ERRORS

On zmq_poller_new:

ENOMEM

A new poller could not be allocated successfully.

On zmq_poller_destroy:

EFAULT

poller_p did not point to a valid poller. Note that passing an invalid pointer (e.g. pointer to deallocated memory) may cause undefined behaviour (e.g. an access violation).

On zmq_poller_size:

EFAULT

poller did not point to a valid poller. Note that passing an invalid pointer (e.g. pointer to deallocated memory) may cause undefined behaviour (e.g. an access violation).

On zmq_poller_add, zmq_poller_modify and zmq_poller_remove:

EFAULT

poller did not point to a valid poller. Note that passing an invalid pointer (e.g. pointer to deallocated memory) may cause undefined behaviour (e.g. an access violation).

ENOTSOCK

socket did not point to a valid socket. Note that passing an invalid pointer (e.g. pointer to deallocated memory) may cause undefined behaviour (e.g. an access violation).

On zmq_poller_add:

EMFILE

TODO

On zmq_poller_add or zmq_poller_add_fd:

ENOMEM

Necessary resources could not be allocated.

EINVAL

socket resp. fd was already registered with the poller.

On zmq_poller_modify, zmq_poller_modify_fd, zmq_poller_remove or zmq_poller_remove_fd:

EINVAL

socket resp. fd was not registered with the poller.

On zmq_poller_add_fd, zmq_poller_modify_fd and zmq_poller_remove_fd:

EBADF

The fd specified was the retired fd.

On zmq_poller_wait and zmq_poller_wait_all:

ENOMEM

Necessary resources could not be allocated.

ETERM

At least one of the registered objects is a socket whose associated 0MQ context was terminated.

EFAULT

The provided events was NULL, or poller did not point to a valid poller, or there are no registered objects or all event subscriptions are disabled and timeout was negative.

EINTR

The operation was interrupted by delivery of a signal before any events were available.

EAGAIN

No registered event was signalled before the timeout was reached.

On zmq_poller_fd:

EINVAL

The poller has no associated file descriptor.

EFAULT

The provided poller did not point to a valid poller.

EXAMPLE

Polling indefinitely for input events on both a 0MQ socket and a standard socket..

void *poller = zmq_poller_new ();
/* First item refers to 0MQ socket 'socket' */
zmq_poller_add (poller, socket, NULL, ZMQ_POLLIN);
/* Second item refers to standard socket 'fd' */
zmq_poller_add_fd (poller, fd, NULL, ZMQ_POLLIN);
zmq_poller_event_t events [2];
/* Poll for events indefinitely */
int rc = zmq_poller_wait_all (poller, events, 2, -1);
assert (rc >= 0);
/* Returned events will be stored in 'events' */
for (int i = 0; i < 2; ++i) {
    if (events[i].socket == socket && events[i].events & ZMQ_POLLIN) {
        // ...
    } else if (events[i].fd == fd && events[i].events & ZMQ_POLLIN)) {
        // ...
    }
}
zmq_poller_destroy (&poller);
