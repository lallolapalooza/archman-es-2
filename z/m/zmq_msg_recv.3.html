NOMBRE

zmq_msg_recv - recibe una parte de mensaje de un socket

SINOPSIS

int zmq_msg_recv (zmq_msg_t *msg, void *socket, int flags);

DESCRIPCIÓN

La función zmq_msg_recv() es idéntica a zmq_recvmsg(3), que será obsoleta en versiones futuras. zmq_msg_recv() es más consistente con otras funciones de manipulación de mensajes.

La función zmq_msg_recv() recibirá una parte de mensaje del socket referenciado por el argumento socket y la almacenará en el mensaje referenciado por el argumento msg. Cualquier contenido previamente almacenado en msg será desasignado correctamente. Si no hay partes de mensaje disponibles en el socket especificado, la función zmq_msg_recv() se bloqueará hasta que la solicitud pueda ser satisfecha. El argumento flags es una combinación de las banderas definidas a continuación:

ZMQ_DONTWAIT

Especifica que la operación debe realizarse en modo no bloqueante. Si no hay mensajes disponibles en el socket especificado, la función zmq_msg_recv() fallará con errno establecido en EAGAIN.

Mensajes multi-parte

Un mensaje 0MQ se compone de 1 o más partes de mensaje. Cada parte de mensaje es una zmq_msg_t independiente por derecho propio. 0MQ garantiza la entrega atómica de mensajes: los pares recibirán todas las partes del mensaje de un mensaje o ninguna. El número total de partes de mensaje es ilimitado excepto por la memoria disponible.

Una aplicación que procesa mensajes multi-parte debe usar la opción ZMQ_RCVMORE de zmq_getsockopt(3) después de llamar a zmq_msg_recv() para determinar si hay más partes que recibir.

VALOR DE RETORNO

La función zmq_msg_recv() devolverá el número de bytes en el mensaje si tiene éxito. De lo contrario, devolverá -1 y establecerá errno en uno de los valores definidos a continuación.

ERRORES

EAGAIN

Se ha alcanzado el tiempo de espera establecido a través de la opción de socket ZMQ_RCVTIMEO (ver zmq_setsockopt(3)) (sin la bandera ZMQ_DONTWAIT establecida) sin poder leer un mensaje del socket, o no hay mensajes disponibles en ese momento (bandera ZMQ_DONTWAIT establecida) y la operación bloquearía.

ENOTSUP

La operación zmq_msg_recv() no está soportada por este tipo de socket.

EFSM

La operación zmq_msg_recv() no se puede realizar en este socket en este momento debido a que el socket no se encuentra en el estado apropiado. Este error puede ocurrir con tipos de socket que cambian entre varios estados, como ZMQ_REP. Ver la sección de patrones de mensajería de zmq_socket(3) para más información.

ETERM

El contexto 0MQ asociado con el socket especificado fue terminado.

ENOTSOCK

El socket proporcionado era inválido.

EINTR

La operación fue interrumpida por la entrega de una señal antes de que un mensaje estuviera disponible.

EFAULT

El mensaje pasado a la función era inválido.

EJEMPLO

Recibir un mensaje de un socket.

/* Crear un mensaje 0MQ vacío */
zmq_msg_t msg;
int rc = zmq_msg_init (&msg);
assert (rc == 0);
/* Bloquear hasta que un mensaje esté disponible para ser recibido del socket */
rc = zmq_msg_recv (&msg, socket, 0);
assert (rc != -1);
/* Liberar mensaje */
zmq_msg_close (&msg);

Recibir un mensaje multi-parte.

int more;
size_t more_size = sizeof (more);
do {
    /* Crear un mensaje 0MQ vacío para contener la parte del mensaje */
    zmq_msg_t part;
    int rc = zmq_msg_init (&part);
    assert (rc == 0);
    /* Bloquear hasta que un mensaje esté disponible para ser recibido del socket */
    rc = zmq_msg_recv (&part, socket, 0);
    assert (rc != -1);
    /* Determinar si hay más partes de mensaje por seguir */
    rc = zmq_getsockopt (socket, ZMQ_RCVMORE, &more, &more_size);
    assert (rc == 0);
    zmq_msg_close (&part);
} while (more);
