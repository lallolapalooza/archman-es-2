NOMBRE

zmq_proxy - Inicia un proxy 0MQ incorporado

SINOPSIS

int zmq_proxy (void *frontend, void *backend, void *capture);

DESCRIPCIÓN

La función zmq_proxy() inicia el proxy 0MQ incorporado en el hilo de la aplicación actual.

El proxy conecta un socket frontend a un socket backend. Conceptualmente, los datos fluyen desde el frontend hacia el backend. Dependiendo de los tipos de socket, las respuestas pueden fluir en la dirección opuesta. La dirección es solo conceptual; el proxy es totalmente simétrico y no hay diferencia técnica entre frontend y backend.

zmq_proxy() se ejecuta en el hilo actual y solo retorna si el contexto actual se cierra, o cuando se cierra.

Si el socket de captura no es NULL, el proxy enviará todos los mensajes, recibidos tanto en el frontend como en el backend, al socket de captura. El socket de captura debe ser un socket de tipo ZMQ_PUB, ZMQ_DEALER, ZMQ_PUSH o ZMQ_PAIR.

Consulta zmq_socket(3) para obtener una descripción de los tipos de socket disponibles.

USO DE EJEMPLO

Cola Compartida

Cuando el frontend es un socket ZMQ_ROUTER y el backend es un socket ZMQ_DEALER, el proxy actuará como una cola compartida que recopila solicitudes de un conjunto de clientes y las distribuye de manera justa entre un conjunto de servicios. Las solicitudes se encolarán de forma justa desde las conexiones frontend y se distribuirán de manera uniforme entre las conexiones backend. Las respuestas volverán automáticamente al cliente que realizó la solicitud original.

Reenviador

Cuando el frontend es un socket ZMQ_XSUB y el backend es un socket ZMQ_XPUB, el proxy actuará como un reenviador de mensajes que recopila mensajes de un conjunto de publicadores y los reenvía a un conjunto de suscriptores. Esto puede usarse para conectar transportes de red, por ejemplo, leer en tcp:// y reenviar en pgm://.

Streamer

Cuando el frontend es un socket ZMQ_PULL y el backend es un socket ZMQ_PUSH, el proxy recopilará tareas de un conjunto de clientes y las reenviará a un conjunto de trabajadores utilizando el patrón de pipeline.

VALOR DE RETORNO

La función zmq_proxy() siempre devuelve -1 y errno se establece en ETERM o EINTR (el contexto 0MQ asociado con cualquiera de los sockets especificados fue terminado) o EFAULT (el frontend o backend proporcionado era inválido).

EJEMPLO

Creación de un proxy de cola compartida.

//  Crear sockets frontend y backend
void *frontend = zmq_socket (context, ZMQ_ROUTER);
assert (frontend);
void *backend = zmq_socket (context, ZMQ_DEALER);
assert (backend);
//  Enlazar ambos sockets a puertos TCP
assert (zmq_bind (frontend, "tcp://*:5555") == 0);
assert (zmq_bind (backend, "tcp://*:5556") == 0);
//  Iniciar el proxy de cola, que se ejecuta hasta ETERM
zmq_proxy (frontend, backend, NULL);
