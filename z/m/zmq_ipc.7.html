NOMBRE

zmq_ipc - transporte de comunicación entre procesos local de 0MQ

SINOPSIS

El transporte entre procesos pasa mensajes entre procesos locales utilizando un mecanismo de IPC dependiente del sistema.


Nota

El transporte entre procesos actualmente solo está implementado en sistemas operativos que proporcionan sockets de dominio UNIX.

DIRECCIONAMIENTO

Un punto final de 0MQ es una cadena que consiste en un transporte:// seguido de una dirección. El transporte especifica el protocolo subyacente a utilizar. La dirección especifica la dirección específica del transporte a la que conectarse.

Para el transporte entre procesos, el transporte es ipc, y el significado de la parte de dirección se define a continuación.

Vinculación de un socket

Al vincular un socket a una dirección local usando zmq_bind() con el transporte ipc, el punto final se interpretará como una cadena arbitraria que identifica la ruta de acceso a crear. La ruta de acceso debe ser única dentro del espacio de nombres del sistema operativo utilizado por la implementación ipc y debe cumplir cualquier restricción impuesta por el sistema operativo en el formato y la longitud de una ruta de acceso.

Cuando la dirección es un comodín *, zmq_bind() generará una ruta de acceso temporal única. El llamador debe recuperar esta ruta de acceso utilizando la opción de socket ZMQ_LAST_ENDPOINT. Consulte zmq_getsockopt(3) para obtener detalles.


Nota

cualquier enlace existente a la misma dirección final se anulará. Es decir, si un segundo proceso se vincula a una dirección final ya vinculada por un proceso, esto tendrá éxito y el primer proceso perderá su enlace. En este comportamiento, el transporte ipc no es coherente con los transportes tcp o inproc.


Nota

la ruta de acceso del punto final debe ser escribible por el proceso. Cuando el punto final comienza con /, por ejemplo, ipc:///ruta/de/acceso, esta será una ruta de acceso absoluta. Si el punto final especifica un directorio que no existe, la vinculación fallará.


Nota

solo en Linux, cuando la ruta de acceso del punto final comienza con @, se utilizará el espacio de nombres abstracto. El espacio de nombres abstracto es independiente del sistema de archivos y si un proceso intenta vincular un punto final ya vinculado por un proceso, fallará. Consulte unix(7) para obtener detalles.


Nota

las rutas de acceso IPC tienen un tamaño máximo que depende del sistema operativo. En Linux, el máximo es de 113 caracteres, incluido el prefijo "ipc://" (107 caracteres para la ruta de acceso real).

Desvinculación de dirección comodín de un socket

Cuando se utilizó el punto final comodín * en zmq_bind(), el llamador debe utilizar el punto final real obtenido de la opción de socket ZMQ_LAST_ENDPOINT para desvincular este punto final de un socket usando zmq_unbind().

Conexión de un socket

Al conectar un socket a una dirección de par usando zmq_connect() con el transporte ipc, el punto final se interpretará como una cadena arbitraria que identifica la ruta de acceso a la que conectarse. La ruta de acceso debe haber sido creada previamente en el espacio de nombres del sistema operativo asignándola a un socket con zmq_bind().

EJEMPLOS

Asignación de una dirección local a un socket.

//  Asignar la ruta de acceso "/tmp/feeds/0"
rc = zmq_bind(socket, "ipc:///tmp/feeds/0");
assert (rc == 0);

Conexión de un socket.

//  Conectar a la ruta de acceso "/tmp/feeds/0"
rc = zmq_connect(socket, "ipc:///tmp/feeds/0");
assert (rc == 0);
