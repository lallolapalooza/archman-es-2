zmq_getsockopt(3)

Paquete: zeromq

Licencias: MPL2

ZMQ_GETSOCKOPT(3) Manual de 0MQ ZMQ_GETSOCKOPT(3)

NOMBRE

zmq_getsockopt - obtener opciones del socket 0MQ

SINOPSIS

int zmq_getsockopt (void *socket, int option_name, void *option_value, size_t *option_len);

DESCRIPCIÓN

La función zmq_getsockopt() recuperará el valor de la opción especificada por el argumento option_name para el socket 0MQ apuntado por el argumento socket, y lo almacenará en el buffer apuntado por el argumento option_value. El argumento option_len es el tamaño en bytes del buffer apuntado por option_value; al completarse con éxito, zmq_getsockopt() modificará el argumento option_len para indicar el tamaño real del valor de la opción almacenado en el buffer.

Las siguientes opciones pueden recuperarse con la función zmq_getsockopt():

ZMQ_AFFINITY: Recuperar la afinidad del hilo de E/S

La opción ZMQ_AFFINITY recuperará la afinidad del hilo de E/S para las conexiones recién creadas en el socket especificado.

La afinidad determina qué hilos del pool de hilos de E/S de 0MQ asociado al context del socket manejarán las conexiones recién creadas. Un valor de cero especifica no afinidad, lo que significa que el trabajo se distribuirá de manera justa entre todos los hilos de E/S de 0MQ en el pool de hilos. Para valores distintos de cero, el bit de menor orden corresponde al hilo 1, el bit de segundo orden de menor valor al hilo 2 y así sucesivamente. Por ejemplo, un valor de 3 especifica que las conexiones posteriores en socket serán manejadas exclusivamente por los hilos de E/S 1 y 2.

Ver también zmq_init(3) para detalles sobre la asignación del número de hilos de E/S para un context específico.

Tipo de valor de opción uint64_t
Unidad de valor de opción N/A (mapa de bits)
Valor por defecto 0
Tipos de socket aplicables N/A

ZMQ_BACKLOG: Recuperar la longitud máxima de la cola de conexiones pendientes

La opción ZMQ_BACKLOG recuperará la longitud máxima de la cola de conexiones de pares pendientes para el socket especificado; esto solo se aplica a los transportes orientados a la conexión. Para más detalles, consulte la documentación de su sistema operativo para la función listen.

Tipo de valor de opción int
Unidad de valor de opción conexiones
Valor por defecto 100
Tipos de socket aplicables todos, solo para transportes orientados a la conexión

ZMQ_BINDTODEVICE: Recuperar el nombre del dispositivo al que está conectado el socket

La opción ZMQ_BINDTODEVICE recupera el nombre del dispositivo al que está conectado este socket, por ejemplo, una interfaz o VRF. Si un socket está conectado a una interfaz, solo los paquetes recibidos de esa interfaz son procesados por el socket. Si el dispositivo es un dispositivo VRF, entonces las conexiones/conexiones posteriores a ese socket utilizan direcciones en la tabla de enrutamiento VRF.

Tipo de valor de opción cadena de caracteres
Unidad de valor de opción N/A
Valor por defecto no establecido
Tipos de socket aplicables todos, al usar transportes TCP o UDP.

ZMQ_CONNECT_TIMEOUT: Recuperar el tiempo de espera de connect()

Recupera cuánto tiempo esperar antes de que la llamada al sistema connect() se agote. La llamada al sistema connect() normalmente tarda mucho tiempo antes de devolver un error de tiempo de espera. Establecer esta opción permite a la biblioteca agotar la llamada en un intervalo anterior.

Tipo de valor de opción int
Unidad de valor de opción milisegundos
Valor por defecto 0 (deshabilitado)
Tipos de socket aplicables todos, al usar transportes TCP.

ZMQ_CURVE_PUBLICKEY: Recuperar la clave pública CURVE actual

Recupera la clave pública a largo plazo actual para el socket. Puede proporcionar un buffer de 32 bytes, para recuperar el valor binario de la clave, o un buffer de 41 bytes, para recuperar la clave en un formato Z85 imprimible. NOTA: para obtener una clave imprimible, el buffer debe tener 41 bytes de tamaño para contener el valor de la clave de 40 caracteres y un byte nulo.

Tipo de valor de opción datos binarios o cadena de texto Z85
Tamaño del valor de opción 32 o 41
Valor por defecto null
Tipos de socket aplicables todos, al usar transporte TCP

ZMQ_CURVE_SECRETKEY: Recuperar la clave secreta CURVE actual

Recupera la clave secreta a largo plazo actual para el socket. Puede proporcionar un buffer de 32 bytes, para recuperar el valor binario de la clave, o un buffer de 41 bytes, para recuperar la clave en un formato Z85 imprimible. NOTA: para obtener una clave imprimible, el buffer debe tener 41 bytes de tamaño para contener el valor de la clave de 40 caracteres y un byte nulo.

Tipo de valor de opción datos binarios o cadena de texto Z85
Tamaño del valor de opción 32 o 41
Valor por defecto null

ZMQ_CURVE_SERVERKEY: Recuperar la clave del servidor CURVE actual

Recupera la clave del servidor actual para el socket cliente. Puede proporcionar un buffer de 32 bytes, para recuperar el valor binario de la clave, o un buffer de 41 bytes, para recuperar la clave en un formato Z85 imprimible. NOTA: para obtener una clave imprimible, el buffer debe tener 41 bytes de tamaño para contener el valor de la clave de 40 caracteres y un byte nulo.

Tipo de valor de opción datos binarios o cadena de texto Z85
Tamaño del valor de opción 32 o 41
Valor por defecto null
Tipos de socket aplicables all, cuando se usa transporte TCP

ZMQ_EVENTS: Obtener el estado del evento del socket

La opción ZMQ_EVENTS obtendrá el estado del evento para el socket especificado. El valor devuelto es una máscara de bits construida mediante la operación OR de una combinación de las siguientes banderas de evento:

ZMQ_POLLIN

Indica que se puede recibir al menos un mensaje del socket especificado sin bloquear.

ZMQ_POLLOUT

Indica que se puede enviar al menos un mensaje al socket especificado sin bloquear.

La combinación de un descriptor de archivo devuelto por la opción ZMQ_FD que está listo para lectura pero ningún evento real devuelto por una recuperación posterior de la opción ZMQ_EVENTS es válida; las aplicaciones simplemente deben ignorar este caso y reiniciar su operación de sondeo/bucle de eventos.

Tipo de valor de opción int
Unidad de valor de opción N/A (banderas)
Valor predeterminado N/A
Tipos de socket aplicables todos

ZMQ_FD: Obtener el descriptor de archivo asociado con el socket

La opción ZMQ_FD obtendrá el descriptor de archivo asociado con el socket especificado. El descriptor de archivo devuelto puede utilizarse para integrar el socket en un bucle de eventos existente; la biblioteca 0MQ señalará cualquier evento pendiente en el socket de forma *edge-triggered* (disparada por flanco), haciendo que el descriptor de archivo esté listo para lectura.


Nota

La capacidad de leer del descriptor de archivo devuelto no indica necesariamente que haya mensajes disponibles para leer o que se puedan escribir en el socket subyacente; las aplicaciones deben obtener el estado real del evento con una recuperación posterior de la opción ZMQ_EVENTS.


Nota

El descriptor de archivo devuelto también es utilizado internamente por las funciones zmq_send y zmq_recv. Dado que el descriptor es *edge-triggered*, las aplicaciones deben actualizar el estado de ZMQ_EVENTS después de cada invocación de zmq_send o zmq_recv. Para ser más explícito: después de llamar a zmq_send, el socket puede volverse legible (y viceversa) sin disparar un evento de lectura en el descriptor de archivo.


Precaución

El descriptor de archivo devuelto está destinado únicamente para su uso con la llamada al sistema poll o similar. Las aplicaciones nunca deben intentar leer o escribir datos en él directamente, ni deben intentar cerrarlo.

Tipo de valor de opción int en sistemas POSIX, SOCKET en Windows
Unidad de valor de opción N/A
Valor predeterminado N/A
Tipos de socket aplicables todos

Devuelve la opción ZMQ_GSSAPI_PLAINTEXT, si existe, establecida previamente en el socket. Un valor de 1 significa que las comunicaciones serán en texto plano. Un valor de 0 significa que las comunicaciones serán cifradas.

ZMQ_GSSAPI_SERVICE_PRINCIPAL_NAMETYPE: Obtener el tipo de nombre para el principal de servicio

Devuelve la opción ZMQ_GSSAPI_SERVICE_PRINCIPAL_NAMETYPE, si existe, establecida previamente en el socket. Un valor de ZMQ_GSSAPI_NT_HOSTBASED (0) significa que el nombre especificado con ZMQ_GSSAPI_SERVICE_PRINCIPAL se interpreta como un nombre basado en host. ZMQ_GSSAPI_PRINCIPAL_NAMETYPE: Obtener el tipo de nombre para el principal de servicio

Un valor de ZMQ_GSSAPI_NT_USER_NAME (1) significa que se interpreta como un nombre de usuario local. ZMQ_HANDSHAKE_IVL: Obtener el intervalo máximo de handshake

La opción ZMQ_HANDSHAKE_IVL obtendrá el intervalo máximo de handshake para el socket especificado. El handshake es el intercambio de información de configuración del socket (tipo de socket, ID de enrutamiento, seguridad) que ocurre cuando se abre una conexión por primera vez, solo para transportes orientados a la conexión. Si el handshake no se completa dentro del tiempo configurado, la conexión se cerrará. El valor 0 significa que no hay límite de tiempo para el handshake.

ZMQ_EVENT_NOTIFICATION_INTERVAL: Retrieve event notification interval

This option controls the interval in milliseconds between event notifications. If set to 0, events will be sent as soon as they occur. Otherwise, events will be bundled and sent at the specified interval.

Option value type int
Option value unit milliseconds
Default value 30000
Applicable socket types all but ZMQ_STREAM, only for connection-oriented transports

ZMQ_IDENTITY: Retrieve socket identity

This option name is now deprecated. Use ZMQ_ROUTING_ID instead. ZMQ_IDENTITY remains as an alias for now.

ZMQ_IMMEDIATE: Retrieve attach-on-connect value

Retrieve the state of the attach on connect value. If set to 1, will delay the attachment of a pipe on connect until the underlying connection has completed. This will cause the socket to block if there are no other connections, but will prevent queues from filling on pipes awaiting connection.

Option value type int
Option value unit boolean
Default value 0 (false)
Applicable socket types all, primarily when using TCP/IPC transports.

ZMQ_INVERT_MATCHING: Retrieve inverted filtering status

Returns the value of the ZMQ_INVERT_MATCHING option. A value of 1 means the socket uses inverted prefix matching.

On PUB and XPUB sockets, this causes messages to be sent to all connected sockets except those subscribed to a prefix that matches the message. On SUB sockets, this causes only incoming messages that do not match any of the socket’s subscriptions to be received by the user.

Whenever ZMQ_INVERT_MATCHING is set to 1 on a PUB socket, all SUB sockets connecting to it must also have the option set to 1. Failure to do so will have the SUB sockets reject everything the PUB socket sends them. XSUB sockets do not need to do this because they do not filter incoming messages.

Option value type int
Option value unit 0,1
Default value 0
Applicable socket types ZMQ_PUB, ZMQ_XPUB, ZMQ_SUB

ZMQ_IPV4ONLY: Retrieve IPv4-only socket override status

Retrieve the IPv4-only option for the socket. This option is deprecated. Please use the ZMQ_IPV6 option.

Option value type int
Option value unit boolean
Default value 1 (true)
Applicable socket types all, when using TCP transports.

ZMQ_IPV6: Retrieve IPv6 socket status

Retrieve the IPv6 option for the socket. A value of 1 means IPv6 is enabled on the socket, while 0 means the socket will use only IPv4. When IPv6 is enabled the socket will connect to, or accept connections from, both IPv4 and IPv6 hosts.

Option value type int
Option value unit boolean
Default value 0 (false)
Applicable socket types all, when using TCP transports.

ZMQ_LAST_ENDPOINT: Retrieve the last endpoint set

The ZMQ_LAST_ENDPOINT option shall retrieve the last endpoint bound for TCP and IPC transports. The returned value will be a string in the form of a ZMQ DSN. Note that if the TCP host is INADDR_ANY, indicated by a *, then the returned address will be 0.0.0.0 (for IPv4). Note: not supported on GNU/Hurd with IPC due to non-working getsockname().

Option value type NULL-terminated character string
Option value unit N/A
Default value NULL
Applicable socket types all, when binding TCP or IPC transports

ZMQ_LINGER: Retrieve linger period for socket shutdown

The ZMQ_LINGER option shall retrieve the linger period for the specified socket. The linger period determines how long pending messages which have yet to be sent to a peer shall linger in memory after a socket is closed with zmq_close(3), and further affects the termination of the socket’s context with zmq_ctx_term(3). The following outlines the different behaviours:

•The default value of -1 specifies an infinite linger period. Pending messages shall not be discarded after a call to zmq_close(); attempting to terminate the socket’s context with zmq_ctx_term() shall block until all pending messages have been sent to a peer.
•The value of 0 specifies no linger period. Pending messages shall be discarded immediately when the socket is closed with zmq_close().
•Positive values specify an upper bound for the linger period in milliseconds. Pending messages shall not be discarded after a call to zmq_close(); attempting to terminate the socket’s context with zmq_ctx_term() shall block until either all pending messages have been sent to a peer, or the linger period expires, after which any pending messages shall be discarded.
Option value type int
Option value unit milliseconds
Default value -1 (infinite)
Applicable socket types all

ZMQ_MAXMSGSIZE: Maximum acceptable inbound message size

The option shall retrieve limit for the inbound messages. If a peer sends a message larger than ZMQ_MAXMSGSIZE it is disconnected. Value of -1 means no limit.

Option value type int64_t
Option value unit bytes
Default value -1
Applicable socket types all

ZMQ_MECHANISM: Retrieve current security mechanism

The ZMQ_MECHANISM option shall retrieve the current security mechanism for the socket.

ZMQ_MULTICAST_HOPS: Maximum network hops for multicast packets

The option shall retrieve time-to-live used for outbound multicast packets. The default of 1 means that the multicast packets don’t leave the local network.

ZMQ_RCVHWM: Recuperar marca de agua alta para mensajes entrantes

La opción ZMQ_RCVHWM devolverá la marca de agua alta para los mensajes entrantes en el socket especificado. La marca de agua alta es un límite estricto en el número máximo de mensajes pendientes que 0MQ encolará en la memoria para cualquier par individual con el que se esté comunicando el socket especificado. Un valor de cero significa sin límite.

Si se ha alcanzado este límite, el socket entrará en un estado excepcional y, dependiendo del tipo de socket, 0MQ tomará la acción apropiada, como bloquear o descartar los mensajes enviados. Consulte las descripciones individuales de los sockets en zmq_socket(3) para obtener detalles sobre la acción exacta tomada para cada tipo de socket.

Tipo de valor de opción int
Unidad de valor de opción mensajes
Valor predeterminado 1000
Tipos de socket aplicables todos

ZMQ_RCVMORE: Quedan más partes de datos de mensaje por seguir

La opción ZMQ_RCVMORE devolverá Verdadero (1) si la parte del mensaje recibida previamente del socket era una parte de datos con más partes por seguir. Si no quedan partes de datos por seguir, esta opción devolverá Falso (0).

Consulte zmq_send(3) y zmq_recv(3) para una descripción detallada de los mensajes multipartes.

Tipo de valor de opción int
Unidad de valor de opción booleano
Valor predeterminado N/A
Tipos de socket aplicables todos

ZMQ_RCVTIMEO: Tiempo máximo antes de que una operación de socket devuelva EAGAIN

Recupera el tiempo de espera para la operación recv en el socket. Si el valor es 0, zmq_recv(3) devolverá inmediatamente, con un error EAGAIN si no hay un mensaje que recibir. Si el valor es -1, se bloqueará hasta que un mensaje esté disponible. Para todos los demás valores, esperará un mensaje durante esa cantidad de tiempo antes de devolver un error EAGAIN.

Tipo de valor de opción int
Unidad de valor de opción milisegundos
Valor predeterminado -1 (infinito)
Tipos de socket aplicables todos

ZMQ_RECONNECT_IVL: Recuperar intervalo de reconexión

La opción ZMQ_RECONNECT_IVL recuperará el intervalo de reconexión inicial para el socket especificado. El intervalo de reconexión es el período que 0MQ esperará

interválica entre intentos de reconexión de pares desconectados cuando se utilizan transportes orientados a la conexión. El valor -1 significa sin reconexión.


Nota

El intervalo de reconexión puede ser aleatorizado por 0MQ para prevenir tormentas de reconexión en topologías con un gran número de pares por socket.

Tipo de valor de opción int
Unidad de valor de opción milisegundos
Valor por defecto 100
Tipos de socket aplicables todos, solo para transportes orientados a la conexión

ZMQ_RECONNECT_IVL_MAX: Recuperar el intervalo máximo de reconexión

La opción ZMQ_RECONNECT_IVL_MAX recuperará el intervalo máximo de reconexión para el socket especificado. 0MQ esperará como máximo el intervalo configurado entre intentos de reconexión. El intervalo crece exponencialmente (es decir, se duplica) con cada intento hasta que alcanza ZMQ_RECONNECT_IVL_MAX. El valor por defecto significa que el intervalo de reconexión se basa exclusivamente en ZMQ_RECONNECT_IVL y no se realiza retroceso exponencial.


Nota

El valor tiene que ser mayor o igual que ZMQ_RECONNECT_IVL, de lo contrario será ignorado.

Tipo de valor de opción int
Unidad de valor de opción milisegundos
Valor por defecto 0 (se usará ZMQ_RECONNECT_IVL)
Tipos de socket aplicables todos, solo para transportes orientados a la conexión

ZMQ_RECONNECT_STOP: Recuperar la condición donde la reconexión se detendrá

La opción ZMQ_RECONNECT_STOP recuperará las condiciones bajo las cuales la reconexión automática se detendrá.

La opción ZMQ_RECONNECT_STOP_CONN_REFUSED detendrá la reconexión cuando 0MQ reciba el código de retorno ECONNREFUSED de la conexión. Esto indica que no hay ningún código enlazado al punto final especificado.

Tipo de valor de opción int
Unidad de valor de opción ZMQ_RECONNECT_STOP_CONN_REFUSED
Valor por defecto 0
Tipos de socket aplicables todos, solo para transportes orientados a la conexión

ZMQ_RECOVERY_IVL: Obtener el intervalo de recuperación multicast

La opción ZMQ_RECOVERY_IVL recuperará el intervalo de recuperación para transportes multicast utilizando el socket especificado. El intervalo de recuperación determina el tiempo máximo en milisegundos que un receptor puede estar ausente de un grupo multicast antes de que ocurra una pérdida de datos irrecuperable.

Tipo de valor de opción int
Unidad de valor de opción milisegundos
Valor por defecto 10000
Tipos de socket aplicables todos, al usar transportes multicast

ZMQ_ROUTING_ID: Recuperar el id de enrutamiento del socket

La opción ZMQ_ROUTING_ID recuperará el id de enrutamiento del socket especificado. Los ids de enrutamiento solo se utilizan con el patrón request/reply. Específicamente, se puede usar junto con el socket ROUTER para enrutar mensajes al par con un id de enrutamiento específico.

Un id de enrutamiento debe tener al menos un byte y como máximo 255 bytes de longitud. Las identidades que comienzan con un byte cero están reservadas para su uso por la infraestructura 0MQ.

Tipo de valor de opción datos binarios
Unidad de valor de opción N/A
Valor por defecto NULL
Tipos de socket aplicables ZMQ_REP, ZMQ_REQ, ZMQ_ROUTER, ZMQ_DEALER.

ZMQ_SNDBUF: Recuperar el tamaño del buffer de transmisión del kernel

ZMQ_SNDHWM: Recupera la marca de agua alta para mensajes de salida

La opción ZMQ_SNDHWM devolverá la marca de agua alta para mensajes de salida en el socket especificado. La marca de agua alta es un límite estricto en el número máximo de mensajes pendientes que 0MQ enviará en cola en la memoria para cualquier par individual con el que se esté comunicando el socket especificado. Un valor de cero significa sin límite.

Valor por defecto 1000
Tipos de socket aplicables todos

ZMQ_TCP_MAXRT: Recuperar el tiempo de espera máximo de retransmisión TCP

En los SO donde sea compatible, recupera cuánto tiempo antes de que una retransmisión TCP no confirmada expire. El sistema normalmente intenta muchas retransmisiones TCP siguiendo una estrategia de retroceso exponencial. NAME

zmq_getsockopt - retrieve settings from a socket

SYNOPSIS

#include <zmq.h>
int zmq_getsockopt (void *socket, int option_name, void *option_value,
                    size_t *option_len);

DESCRIPTION

The zmq_getsockopt() function shall retrieve the value for the specified socket option_name and store it in the buffer pointed to by option_value. The option_len argument should initially point to the size of the buffer pointed to by option_value, and after a successful call it will be updated to hold the actual size of the value stored.

Refer to the zmq_options(7) manual page for a complete list of the available socket options.

ZMQ_NORM_BLOCK_SIZE: Retrieve NORM block size

Gets the NORM sender block size, which is the number of segments in a NORM FEC coding block. NORM repair operations take place at block boundaries. Maximum value is 255, but parity packets (ZMQ_NORM_NUM_PARITY) are limited to a value of (255 - ZMQ_NORM_BLOCK_SIZE). Minimum value is (ZMQ_NORM_NUM_PARITY + 1). Effective value may be different based on the settings of ZMQ_NORM_NUM_PARITY and ZMQ_NORM_NUM_AUTOPARITY if invalid settings are provided.


Note

in DRAFT state, not yet available in stable releases.

Option value type int
Option value unit >0, ⟨255
Default value 16
Applicable socket types All, when using NORM transport.

ZMQ_NORM_NUM_PARITY: Retrieve NORM parity segment setting

Gets the maximum number of NORM parity symbol segments that the sender is willing to calculate per FEC coding block for the purpose of reparing lost data. Maximum value is 255, but is further limited to a value of (255 - ZMQ_NORM_BLOCK_SIZE). Minimum value is ZMQ_NORM_NUM_AUTOPARITY. Effective value may be different based on the setting of ZMQ_NORM_NUM_AUTOPARITY if invalid settings are provided.


Note

in DRAFT state, not yet available in stable releases.

Option value type int
Option value unit >0, <255
Default value 4
Applicable socket types All, when using NORM transport.

ZMQ_NORM_NUM_AUTOPARITY: Retrieve proactive NORM parity segment setting

Gets the number of NORM parity symbol segments that the sender will proactively send at the end of each FEC coding block. By default, no proactive parity segments will be sent; instead, parity segments will only be sent in response to repair requests (NACKs). Maximum value is 255, but is further limited to a maximum value of ZMQ_NORM_NUM_PARITY.


Note

in DRAFT state, not yet available in stable releases.

Option value type int
Option value unit >=0, <255
Default value 0
Applicable socket types All, when using NORM transport.

ZMQ_NORM_PUSH: Retrieve NORM push mode

Gets status of NORM stream push mode, which alters the behavior of the sender when enqueueing new data. By default, NORM will stop accepting new messages while waiting for old data to be transmitted and/or repaired. Enabling push mode discards the oldest data (which may be pending repair or may never have been transmitted) in favor of accepting new data. This may be useful in cases where it is more important to quickly deliver new data instead of reliably delivering older data.


Note

in DRAFT state, not yet available in stable releases.

Option value type int
Option value unit boolean
Default value 0 (false)
Applicable socket types All, when using NORM transport.

RETURN VALUE

The zmq_getsockopt() function shall return zero if successful. Otherwise it shall return -1 and set errno to one of the values defined below.

ERRORS

EINVAL

The requested option option_name is unknown, or the requested option_len or option_value is invalid, or the size of the buffer pointed to by option_value, as specified by option_len, is insufficient for storing the option value.

ETERM

The 0MQ context associated with the specified socket was terminated.

ENOTSOCK

The provided socket was invalid.

EINTR

The operation was interrupted by delivery of a signal.

EXAMPLE

Retrieving the high water mark for outgoing messages.

/* Retrieve high water mark into sndhwm */
int sndhwm;
size_t sndhwm_size = sizeof (sndhwm);
rc = zmq_getsockopt (socket, ZMQ_SNDHWM, &sndhwm, &sndhwm_size);
assert (rc == 0);
