NOMBRE

zmq_sendmsg - enviar una parte de mensaje a un socket

SINOPSIS

int zmq_sendmsg (void *socket, zmq_msg_t *msg, int flags);

DESCRIPCIÓN

La función zmq_sendmsg() encolará el mensaje al que hace referencia el argumento msg para ser enviado al socket al que hace referencia el argumento socket. El argumento flags es una combinación de las banderas definidas a continuación:

ZMQ_DONTWAIT

Para los tipos de socket (DEALER, PUSH) que se bloquean (ya sea con la opción ZMQ_IMMEDIATE establecida y sin par disponible, o todos los pares con la marca de alta agua llena), especifica que la operación debe realizarse en modo no bloqueante. Si el mensaje no se puede encolar en el socket, la función zmq_sendmsg() fallará con errno establecido en EAGAIN.

ZMQ_SNDMORE

Especifica que el mensaje que se está enviando es un mensaje multipart y que seguirán más partes del mensaje. Consulte la sección sobre mensajes multipart a continuación para obtener una descripción detallada.

La estructura zmq_msg_t pasada a zmq_sendmsg() se anula durante la llamada. Si desea enviar el mismo mensaje a varios sockets, debe copiarlo (por ejemplo, usando zmq_msg_copy()).


Nota

Una invocación exitosa de zmq_sendmsg() no indica que el mensaje se haya transmitido a la red, solo que se ha encolado en el socket y 0MQ ha asumido la responsabilidad del mensaje.


Nota

este método de API está obsoleto en favor de zmq_msg_send(3).

Mensajes multipart

Un mensaje 0MQ consta de 1 o más partes de mensaje. Cada parte del mensaje es una zmq_msg_t independiente por derecho propio. 0MQ garantiza la entrega atómica de los mensajes: los pares recibirán todas las partes del mensaje de un mensaje o ninguna. El número total de partes del mensaje es ilimitado, excepto por la memoria disponible.

Una aplicación que envía mensajes multipart debe usar la bandera ZMQ_SNDMORE al enviar cada parte del mensaje, excepto la final.

VALOR DE RETORNO

La función zmq_sendmsg() devolverá el número de bytes en el mensaje si tiene éxito. De lo contrario, devolverá -1 y establecerá errno en uno de los valores definidos a continuación.

ERRORES

EAGAIN

Se solicitó el modo no bloqueante y el mensaje no se puede enviar en este momento.

ENOTSUP

La operación zmq_sendmsg() no es compatible con este tipo de socket.

EINVAL

El remitente intentó enviar datos multipart, lo que el tipo de socket no permite.

EFSM

La operación zmq_sendmsg() no se puede realizar en este socket en este momento debido a que el socket no se encuentra en el estado apropiado. Este error puede ocurrir con tipos de socket que cambian entre varios estados, como ZMQ_REP. Consulte la sección de patrones de mensajería de zmq_socket(3) para obtener más información.

ETERM

El contexto 0MQ asociado con el socket especificado fue terminado.

ENOTSOCK

El socket proporcionado no era válido.

EINTR

La operación fue interrumpida por la entrega de una señal antes de que se enviara el mensaje.

EFAULT

Mensaje inválido.

EHOSTUNREACH

El mensaje no se puede enrutar.

EJEMPLO

Rellenando un mensaje y enviándolo a un socket.

/* Crear un nuevo mensaje, asignando 6 bytes para el contenido del mensaje */
zmq_msg_t msg;
int rc = zmq_msg_init_size (&msg, 6);
assert (rc == 0);
/* Rellenar el contenido del mensaje con 'AAAAAA' */
memset (zmq_msg_data (&msg), 'A', 6);
/* Enviar el mensaje al socket */
rc = zmq_sendmsg (socket, &msg, 0);
assert (rc == 6);

Enviando un mensaje multipart.

/* Enviar un mensaje multipart que consta de tres partes al socket */
rc = zmq_sendmsg (socket, &part1, ZMQ_SNDMORE);
rc = zmq_sendmsg (socket, &part2, ZMQ_SNDMORE);
/* Parte final; no hay más partes que seguir */
rc = zmq_sendmsg (socket, &part3, 0);
