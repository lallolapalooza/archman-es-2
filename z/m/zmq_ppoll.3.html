zmq_ppoll(3)

Paquete: zeromq

Licencias: MPL2

ZMQ_POLL(3) Manual de 0MQ ZMQ_POLL(3)

NOMBRE

zmq_ppoll - multiplexación de entrada/salida con máscara de señales

SINOPSIS

int zmq_ppoll (zmq_pollitem_t *items, int nitems, long timeout, const sigset_t *sigmask);

DESCRIPCIÓN

La relación entre zmq_poll() y zmq_ppoll() es análoga a la relación entre poll(2) y ppoll(2) y entre select(2) y pselect(2): zmq_ppoll() permite a una aplicación esperar de forma segura hasta que un descriptor de archivo esté listo o hasta que se capture una señal.

Cuando se utiliza zmq_ppoll() con sigmask establecido en NULL, su comportamiento es idéntico al de zmq_poll(). Consulte zmq_poll(3) para obtener más información al respecto.

Para hacer uso completo de zmq_ppoll(), se debe construir y pasar un puntero no NULL a una máscara de señales a sigmask. Consulte sigprocmask(2) para más detalles. Cuando esto se hace, dentro de la llamada real del sistema ppoll() (o pselect(), véase la nota a continuación), se realiza una operación atómica que consta de tres pasos: 1. La máscara de señales actual se reemplaza por la apuntada por sigmask. 2. Se realiza la llamada real poll(). 3. Se restaura la máscara de señales original. Dado que estas operaciones se realizan de forma atómica, no hay oportunidad de condiciones de carrera entre las llamadas que cambian la máscara de señales y la llamada al sistema poll/select. Esto significa que solo durante esta llamada (atómica), podemos desbloquear ciertas señales, de modo que puedan manejarse **en ese momento solamente**, no fuera de la llamada. Esto significa que, efectivamente, extendemos nuestro poller a una función que no solo vigila los sockets en busca de cambios, sino que también vigila el "socket de señales POSIX" en busca de señales entrantes. En otros momentos, estas señales estarán bloqueadas, y no tendremos que lidiar con interrupciones en las llamadas al sistema en esos otros momentos.


Nota

La función zmq_ppoll() puede implementarse o emularse utilizando interfaces del sistema operativo distintas de ppoll(), y como tal, puede estar sujeta a los límites de esas interfaces de formas no definidas en esta documentación.


Nota

No existe ppoll ni pselect en Windows, por lo que zmq_ppoll() no es compatible en las compilaciones de Windows. Todavía se puede llamar, pero su sigmask tiene tipo de puntero void (ya que sigset_t tampoco está disponible en Windows) y zmq_ppoll() devolverá un error (ver sección de errores a continuación).

SEGURIDAD DE HILOS

El array zmq_pollitem_t solo debe ser utilizado por el hilo que llamará/está llamando a zmq_ppoll.

Si un socket está contenido en múltiples arrays zmq_pollitem_t, cada uno propiedad de un hilo diferente, el socket en sí mismo debe ser seguro para hilos (Servidor, Cliente, ...). De lo contrario, el comportamiento no está definido.

VALOR DE RETORNO

Al completarse con éxito, la función zmq_ppoll() devolverá el número de estructuras zmq_pollitem_t con eventos señalados en revents o 0 si no se han señalado eventos. En caso de fallo, zmq_ppoll() devolverá -1 y establecerá errno a uno de los valores definidos a continuación.

ERRORES

ETERM

Al menos uno de los miembros del array items se refiere a un socket cuyo contexto 0MQ asociado fue terminado.

EFAULT

Los items proporcionados no eran válidos (NULL).

EINTR

La operación fue interrumpida por la entrega de una señal antes de que hubiera eventos disponibles.

EINTR

La operación fue interrumpida por la entrega de una señal antes de que hubiera eventos disponibles.

ENOTSUP

zmq_ppoll() no fue activado en esta compilación.

EJEMPLO

Esperando indefinidamente eventos de entrada en un socket 0MQ y un socket estándar.. Consulte la sección de ejemplo de zmq_poll(3). Solo necesita reemplazar la llamada zmq_poll con zmq_ppoll y agregar un argumento NULL para el parámetro sigmask.

Manejar SIGTERM durante zmq_ppoll (y bloquearlo de lo contrario)..

// manejador de señal global simple para SIGTERM
static bool sigterm_received = false;
void handle_sigterm (int signum) {
    sigterm_received = true;
}
// configurar máscara de señales e instalar manejador para SIGTERM
sigset_t sigmask, sigmask_without_sigterm;
sigemptyset(&sigmask);
sigaddset(&sigmask, SIGTERM);
sigprocmask(SIG_BLOCK, &sigmask, &sigmask_without_sigterm);
struct sigaction sa;
memset(&sa, '\0', sizeof(sa));
sa.sa_handler = handle_sigterm;
// sondear
zmq_pollitem_t items [1];
// Solo un elemento, que se refiere al socket 0MQ 'socket' */
items[0].socket = socket;
items[0].events = ZMQ_POLLIN;
// Sondear eventos indefinidamente, pero también salir en SIGTERM
int rc = zmq_poll (items, 2, -1, &sigmask_without_sigterm);
if (rc < 0 && errno == EINTR && sigterm_received) {
  // haz tu negocio de SIGTERM
} else {
  // haz tu manejo de errores que no sea SIGTERM
}
