NOMBRE

zmq_curve - autenticación segura y confidencialidad

SINOPSIS

El mecanismo CURVE define un mecanismo para autenticación segura y confidencialidad para las comunicaciones entre un cliente y un servidor. CURVE está pensado para su uso en redes públicas. El mecanismo CURVE está definido por este documento: http://rfc.zeromq.org/spec:25.

ROLES DE CLIENTE Y SERVIDOR

Un socket que utiliza CURVE puede ser cliente o servidor, en cualquier momento, pero no ambos. El rol es independiente de la dirección de bind/connect.

Un socket puede cambiar de rol en cualquier momento estableciendo nuevas opciones. El rol afecta a todas las llamadas a zmq_connect y zmq_bind que le siguen.

Para convertirse en un servidor CURVE, la aplicación establece la opción ZMQ_CURVE_SERVER en el socket, y luego establece la opción ZMQ_CURVE_SECRETKEY para proporcionar al socket su clave secreta a largo plazo. La aplicación no proporciona al socket su clave pública a largo plazo, que es utilizada solo por los clientes.

Para convertirse en un cliente CURVE, la aplicación establece la opción ZMQ_CURVE_SERVERKEY con la clave pública a largo plazo del servidor al que pretende conectarse, o del que pretende aceptar conexiones, a continuación. La aplicación luego establece las opciones ZMQ_CURVE_PUBLICKEY y ZMQ_CURVE_SECRETKEY con su par de claves a largo plazo de cliente.

Si el servidor realiza autenticación, esta se basará en la clave pública a largo plazo del cliente.

CODIFICACIÓN DE CLAVES

La representación estándar de las claves en el código fuente es ya sea 32 bytes de datos en base 256 (binarios), o 40 caracteres de datos en base 85 codificados usando el algoritmo base 85 definido por http://rfc.zeromq.org/spec:32.

El algoritmo base 85 está diseñado para producir cadenas de claves imprimibles para su uso en archivos de configuración, la línea de comandos y código. Hay una implementación de referencia en C en https://github.com/zeromq/rfc/tree/master/src.
