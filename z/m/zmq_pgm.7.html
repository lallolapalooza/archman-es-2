NOMBRE

zmq_pgm - transporte multicast fiable de 0MQ usando PGM

SINÓPSIS

PGM (Pragmatic General Multicast) es un protocolo para el transporte multicast fiable de datos sobre redes IP.

DESCRIPCIÓN

0MQ implementa dos variantes de PGM, el protocolo estándar donde los datagramas PGM se colocan directamente sobre datagramas IP tal como se define en RFC 3208 (el transporte pgm) y el "PGM Encapsulado" o EPGM donde los datagramas PGM se encapsulan dentro de datagramas UDP (el transporte epgm).

Los transportes pgm y epgm solo pueden usarse con los tipos de socket ZMQ_PUB y ZMQ_SUB.

Además, los sockets PGM tienen limitación de velocidad por defecto. Para más detalles, consulta las opciones ZMQ_RATE y ZMQ_RECOVERY_IVL documentadas en zmq_setsockopt(3).


Precaución

La implementación del transporte pgm requiere acceso a sockets IP crudos. Se pueden requerir privilegios adicionales en algunos sistemas operativos para esta operación. Se anima a las aplicaciones que no requieren interoperabilidad directa con otras implementaciones PGM a usar el transporte epgm en su lugar, el cual no requiere ningún privilegio especial.

DIRECCIONAMIENTO

Un punto final de 0MQ es una cadena que consiste en un transporte:// seguido de una dirección. El transporte especifica el protocolo subyacente a usar. La dirección especifica la dirección específica del transporte a la que conectarse.

Para el transporte PGM, el transporte es pgm, y para el protocolo EPGM el transporte es epgm. El significado de la parte de la dirección se define a continuación.

Conectando un socket

Al conectar un socket a una dirección de par usando zmq_connect() con el transporte pgm o epgm, el punto final se interpretará como una interfaz seguida de un punto y coma, seguido de una dirección multicast, seguido de dos puntos y un número de puerto.

Una interfaz puede especificarse mediante cualquiera de lo siguiente:

•El nombre de la interfaz tal como lo define el sistema operativo.
•La dirección IPv4 principal asignada a la interfaz, en su representación numérica.

Nota

Los nombres de interfaz no están estandarizados de ninguna manera y se debe asumir que son arbitrarios y dependientes de la plataforma. En plataformas Win32 no existen nombres cortos de interfaz, por lo que solo la dirección IPv4 principal puede usarse para especificar una interfaz. La parte de la interfaz puede omitirse; en ese caso, se seleccionará la predeterminada.

Una dirección multicast se especifica mediante una dirección multicast IPv4 en su representación numérica.

FORMATO DEL CABLEADO

Los datagramas PGM consecutivos son interpretados por 0MQ como un único flujo continuo de datos donde los mensajes 0MQ no están necesariamente alineados con los límites de los datagramas PGM y un único mensaje 0MQ puede abarcar varios datagramas PGM. Este flujo de datos consiste en mensajes 0MQ encapsulados en tramas como se describe en zmq_tcp(7).

Carga útil del datagrama PGM

La siguiente gramática ABNF representa la carga útil de un único datagrama PGM tal como lo usa 0MQ:

datagram               = (offset data)
offset                 = 2OCTET
data                   = *OCTET

Para que los consumidores que se unen tardíamente puedan identificar los límites de los mensajes, la carga útil de cada datagrama PGM comienza con un entero sin signo de 16 bits en orden de bytes de red que especifica el desplazamiento de la primera trama del mensaje en el datagrama o que contiene el valor 0xFFFF si el datagrama contiene únicamente una parte intermedia de un mensaje más grande.

Tenga en cuenta que el desplazamiento especifica dónde comienza el primer mensaje en lugar de la primera parte del mensaje. Por lo tanto, si hay partes de mensajes posteriores al principio del paquete, el desplazamiento las ignora y apunta a la primera parte inicial del mensaje en el paquete.

El siguiente diagrama ilustra la disposición de la carga útil de un único datagrama PGM:

+------------------+----------------------+
| offset (16 bits) |         data         |
+------------------+----------------------+

El siguiente diagrama ilustra además cómo tres tramas 0MQ de ejemplo se disponen en cargas útiles de datagramas PGM consecutivos:

Carga útil del primer datagrama
+--------------+-------------+---------------------+
| Frame offset |   Frame 1   |   Frame 2, part 1   |
|    0x0000    | (Message 1) | (Message 2, part 1) |
+--------------+-------------+---------------------+
Carga útil del segundo datagrama
+--------------+---------------------+
| Frame offset |   Frame 2, part 2   |
| 0xFFFF       | (Message 2, part 2) |
+--------------+---------------------+
Carga útil del tercer datagrama
+--------------+----------------------------+-------------+
| Frame offset |   Frame 2, final 8 bytes   |   Frame 3   |
| 0x0008       | (Message 2, final 8 bytes) | (Message 3) |
+--------------+----------------------------+-------------+

CONFIGURACIÓN

El protocolo PGM es capaz de transmitir datos a altas tasas (500 Mbps+) con mensajes grandes (1 MB+), sin embargo requiere la configuración de las opciones de socket ZMQ relevantes que se documentan en zmq_setsockopt(3):

•El ZMQ_RATE debe configurarse lo suficientemente alto, por ejemplo, 1 Gbps
•El ZMQ_RCVBUF debe aumentarse en el suscriptor, por ejemplo, 4 MB
•El ZMQ_SNDBUF debe aumentarse en el publicador, por ejemplo, 4 MB

Es importante tener en cuenta que las opciones ZMQ_RCVBUF y ZMQ_SNDBUF están limitadas por el tamaño del buffer de transmisión/recepción del sistema operativo subyacente. En Linux, estos pueden aumentarse para la sesión actual con los siguientes comandos:

# establecer los buffers de tx/rx a 4 MB (el valor predeterminado también se puede leer como el tamaño inicial del buffer)
sudo sysctl -w net.core.rmem_max=4194304
sudo sysctl -w net.core.wmem_max=4194304
sudo sysctl -w net.core.rmem_default=4194304
sudo sysctl -w net.core.wmem_default=4194304

EJEMPLO

Conectando un socket.

// Conectando a la dirección multicast 239.192.1.1, puerto 5555,
// usando la primera interfaz de red Ethernet en Linux
// y el protocolo PGM Encapsulado
rc = zmq_connect(socket, "epgm://eth0;239.192.1.1:5555");
assert (rc == 0);
// Conectando a la dirección multicast 239.192.1.1, puerto 5555,
// usando la interfaz de red con la dirección 192.168.1.1
// y el protocolo PGM estándar
rc = zmq_connect(socket, "pgm://192.168.1.1;239.192.1.1:5555");
assert (rc == 0);
