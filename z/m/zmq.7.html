NOMBRE

zmq - Kernel de mensajería ligera 0MQ

SINOPSIS

#include <zmq.h>

cc [opciones] archivos -lzmq [bibliotecas]

DESCRIPCIÓN

El kernel de mensajería ligera 0MQ es una biblioteca que extiende las interfaces de socket estándar con características tradicionalmente proporcionadas por productos especializados de middleware de mensajería. Los sockets 0MQ proporcionan una abstracción de colas de mensajes asíncronas, múltiples patrones de mensajería, filtrado de mensajes (suscripciones), acceso transparente a múltiples protocolos de transporte y más.

Esta documentación presenta una visión general de los conceptos de 0MQ, describe cómo 0MQ abstrae los sockets estándar y proporciona un manual de referencia para las funciones proporcionadas por la biblioteca 0MQ.

Contexto

El contexto 0MQ mantiene la lista de sockets y gestiona el hilo de E/S asíncrona y las consultas internas.

Antes de usar cualquier función de la biblioteca 0MQ, debe crear un contexto 0MQ. Cuando salga de su aplicación, debe destruir el contexto. Estas funciones le permiten trabajar con contextos:

Crear un nuevo contexto 0MQ

zmq_ctx_new(3)

Trabajar con propiedades del contexto

zmq_ctx_set(3) zmq_ctx_get(3)

Destruir un contexto 0MQ

zmq_ctx_shutdown(3) zmq_ctx_term(3)

Seguridad de hilos

Un contexto 0MQ es seguro para hilos y puede ser compartido entre tantos hilos de aplicación como sea necesario, sin ninguna sincronización adicional por parte del llamante.

Los sockets individuales 0MQ no son seguros para hilos, excepto en el caso en que se emitan barreras de memoria completas al migrar un socket de un hilo a otro. En la práctica, esto significa que las aplicaciones pueden crear un socket en un hilo con zmq_socket() y luego pasarlo a un hilo recién creado como parte de la inicialización del hilo, por ejemplo, a través de una estructura pasada como argumento a pthread_create().

Múltiples contextos

Múltiples contextos pueden coexistir dentro de una sola aplicación. Por lo tanto, una aplicación puede usar 0MQ directamente y al mismo tiempo utilizar cualquier número de bibliotecas o componentes adicionales que a su vez utilicen 0MQ, siempre que se cumplan las directrices anteriores sobre seguridad de hilos.

Mensajes

Un mensaje 0MQ es una unidad discreta de datos que se pasa entre aplicaciones o componentes de la misma aplicación. Los mensajes 0MQ no tienen estructura interna y, desde el punto de vista de 0MQ, se consideran datos binarios opacos.

Las siguientes funciones se proporcionan para trabajar con mensajes:

Inicializar un mensaje

zmq_msg_init(3) zmq_msg_init_size(3) zmq_msg_init_buffer(3) zmq_msg_init_data(3)

Enviar y recibir un mensaje

zmq_msg_send(3) zmq_msg_recv(3)

Liberar un mensaje

zmq_msg_close(3)

Acceder al contenido del mensaje

zmq_msg_data(3) zmq_msg_size(3) zmq_msg_more(3)

Trabajar con propiedades del mensaje

zmq_msg_gets(3) zmq_msg_get(3) zmq_msg_set(3)

Manipulación de mensajes

zmq_msg_copy(3) zmq_msg_move(3)

Sockets

Los sockets 0MQ presentan una abstracción de una cola de mensajes asíncrona, con la semántica exacta de cola dependiendo del tipo de socket en uso. Ver zmq_socket(3) para los tipos de socket proporcionados.

Las siguientes funciones se proporcionan para trabajar con sockets:

Crear un socket

zmq_socket(3)

Cerrar un socket

zmq_close(3)

Manipular opciones de socket

zmq_getsockopt(3) zmq_setsockopt(3)

Establecer un flujo de mensajes

zmq_bind(3) zmq_connect(3)

Enviar y recibir mensajes

zmq_msg_send(3) zmq_msg_recv(3) zmq_send(3) zmq_recv(3) zmq_send_const(3)

Monitorear eventos de socket

zmq_socket_monitor(3)

Multiplexación de entrada/salida. 0MQ proporciona un mecanismo para que las aplicaciones multiplexen eventos de entrada/salida a través de un conjunto que contiene tanto sockets 0MQ como sockets estándar. Este mecanismo refleja la llamada al sistema poll() estándar y se describe en detalle en zmq_poll(3). Sin embargo, esta API está obsoleta.

Hay una nueva API DRAFT con múltiples funciones zmq_poller_*, que se describe en zmq_poller(3).

Transportes

Un socket 0MQ puede utilizar varios mecanismos de transporte subyacentes diferentes. Cada mecanismo de transporte es adecuado para un propósito particular y tiene sus propias ventajas y desventajas.

Se proporcionan los siguientes mecanismos de transporte:

Transporte unicast usando TCP

zmq_tcp(7)

Transporte multicast fiable usando PGM

zmq_pgm(7)

Transporte de comunicación entre procesos local

zmq_ipc(7)

Transporte de comunicación local dentro del proceso (entre hilos)

zmq_inproc(7)

Transporte de la Interfaz de Comunicación de Máquina Virtual (VMC)

zmq_vmci(7)

Unicast y multicast no fiable usando UDP

zmq_udp(7)

Proxies

0MQ proporciona proxies para crear topologías de abanico y abanico inverso. Un proxy conecta un socket de frontend a un socket de backend e intercambia todos los mensajes entre los dos sockets, de forma opaca. Un proxy puede opcionalmente capturar todo el tráfico a un tercer socket. Para iniciar un proxy en un hilo de aplicación, use zmq_proxy(3).

Seguridad

Un socket 0MQ puede seleccionar un mecanismo de seguridad. Ambos extremos deben usar el mismo mecanismo de seguridad.

Se proporcionan los siguientes mecanismos de seguridad para conexiones IPC y TCP:

Seguridad nula

zmq_null(7)

Autenticación de texto plano usando nombre de usuario y contraseña

zmq_plain(7)

Autenticación y encriptación de curva elíptica

zmq_curve(7)

Generar un par de claves CURVE en formato de texto blindado

zmq_curve_keypair(3)

Derivar una clave pública CURVE de una clave secreta: zmq_curve_public(3)

Convertir claves de/a cadenas de texto blindado

zmq_z85_decode(3) zmq_z85_encode(3)

MANEJO DE ERRORES

Las funciones de la biblioteca 0MQ manejan los errores utilizando las convenciones estándar encontradas en los sistemas POSIX. Generalmente, esto significa que, en caso de fallo, una función de la biblioteca 0MQ deberá devolver un valor NULL (si devuelve un puntero) o un valor negativo (si devuelve un entero), y el código de error real se almacenará en la variable errno.

En sistemas no POSIX, algunos usuarios pueden experimentar problemas al recuperar el valor correcto de la variable errno. La función zmq_errno() se proporciona para ayudar en estos casos; para obtener más detalles, consulte zmq_errno(3).

La función zmq_strerror() se proporciona para traducir los códigos de error específicos de 0MQ a cadenas de mensajes de error; para obtener más detalles, consulte zmq_strerror(3).

BINDINGS DE LENGUAJE

La biblioteca 0MQ proporciona interfaces adecuadas para ser llamadas desde programas en cualquier idioma; esta documentación documenta esas interfaces tal como serían utilizadas por programadores de C. La intención es que los programadores que utilicen 0MQ desde otros idiomas consulten esta documentación junto con cualquier documentación proporcionada por el vendedor de su binding de idioma.

Los bindings de lenguaje (C++, Python, PHP, Ruby, Java y más) son proporcionados por miembros de la comunidad 0MQ y se pueden encontrar enlaces en el sitio web de 0MQ.
