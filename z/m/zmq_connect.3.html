NOMBRE

zmq_connect(3) - crea una conexión saliente desde un socket

SINOPSIS

int zmq_connect (void *socket, const char *endpoint);

DESCRIPCIÓN

La función zmq_connect() conecta el socket a un endpoint y luego acepta conexiones entrantes en ese endpoint.

El endpoint es una cadena que consta de un transporte:// seguido de una dirección. El transporte especifica el protocolo subyacente a utilizar. La dirección especifica la dirección específica del transporte a la que conectarse.

0MQ proporciona los siguientes transportes:

tcp

transporte de unidifusión utilizando TCP, véase zmq_tcp(7)

ipc

transporte de comunicación interproceso local, véase zmq_ipc(7)

inproc

transporte de comunicación dentro del proceso (inter-hilos) local, véase zmq_inproc(7)

pgm, epgm

transporte de multidifusión fiable utilizando PGM, véase zmq_pgm(7)

vmci

interfaz de comunicaciones de máquina virtual (VMCI), véase zmq_vmci(7)

udp

unidifusión y multidifusión no fiable utilizando UDP, véase zmq_udp(7)

Cada tipo de socket 0MQ excepto ZMQ_PAIR y ZMQ_CHANNEL soporta semántica uno a muchos y muchos a uno. Las semánticas precisas dependen del tipo de socket y se definen en zmq_socket(3).


Nota

para la mayoría de los transportes y tipos de socket, la conexión no se realiza inmediatamente sino según sea necesario por 0MQ. Por lo tanto, una llamada exitosa a zmq_connect() no significa que la conexión se haya establecido o se pueda haber establecido realmente. Debido a esto, para la mayoría de los transportes y tipos de socket, el orden en el que un socket de servidor se enlaza y un socket de cliente se conecta a él no importa. Los sockets ZMQ_PAIR y ZMQ_CHANNEL son una excepción, ya que no se reconectan automáticamente a los endpoints.


Nota

después de un zmq_connect(), para los tipos de socket excepto para ZMQ_ROUTER, el socket entra en su estado normal de preparado. Por el contrario, después de un zmq_bind() solo, el socket entra en un estado de mudo en el que el socket bloquea o descarta mensajes según el tipo de socket, como se define en zmq_socket(3). Un socket ZMQ_ROUTER entra en su estado normal de preparado para un par específico solo cuando el handshake se completa para ese par, lo que puede llevar un tiempo arbitrario.


Nota

para algunos tipos de socket, múltiples conexiones al mismo endpoint no tienen mucho sentido (véase https://github.com/zeromq/libzmq/issues/788). Para esos tipos de socket, cualquier intento de conectarse a un endpoint ya conectado se ignora silenciosamente (es decir, devuelve cero). Este comportamiento se aplica a los tipos de socket ZMQ_DEALER, ZMQ_SUB, ZMQ_PUB y ZMQ_REQ.

VALOR DE RETORNO

La función zmq_connect() devuelve cero si tiene éxito. De lo contrario, devuelve -1 y establece errno a uno de los valores definidos a continuación.

ERRORES

EINVAL

El endpoint proporcionado es inválido.

EPROTONOSUPPORT

El protocolo de transporte solicitado no está soportado.

ENOCOMPATPROTO

El protocolo de transporte solicitado no es compatible con el tipo de socket.

ETERM

El contexto 0MQ asociado con el socket especificado fue terminado.

ENOTSOCK

El socket proporcionado era inválido.

EMTHREAD

No hay ningún hilo de E/S disponible para realizar la tarea.

EJEMPLO

Conectar un socket suscriptor a un transporte en proceso y a uno TCP .

/* Crear un socket ZMQ_SUB */
void *socket = zmq_socket (context, ZMQ_SUB);
assert (socket);
/* Conectarlo a un transporte en proceso con la dirección 'my_publisher' */
int rc = zmq_connect (socket, "inproc://my_publisher");
assert (rc == 0);
/* Conectarlo al host server001, puerto 5555 utilizando un transporte TCP */
rc = zmq_connect (socket, "tcp://server001:5555");
assert (rc == 0);
