ZMQ_SOCKET_MONITOR_V(3) Manual de 0MQ ZMQ_SOCKET_MONITOR_V(3)

NOMBRE

zmq_socket_monitor_versioned - monitorizar eventos del socket

SINOPSIS

int zmq_socket_monitor_versioned (void *socket, char *endpoint, uint64_t events, int event_version, int type);

int zmq_socket_monitor_pipes_stats (void *socket);

DESCRIPCIÓN

El método zmq_socket_monitor_versioned() permite a un hilo de aplicación rastrear eventos del socket (como conexiones) en un socket ZeroMQ. Cada llamada a este método crea un socket ZMQ_PAIR y lo enlaza al endpoint inproc:// especificado. Para recopilar los eventos del socket, debes crear tu propio socket ZMQ_PAIR y conectarlo al endpoint.

El argumento events es una máscara de bits de los eventos del socket que deseas monitorizar, consulta Eventos soportados más adelante. Para monitorizar todos los eventos de una versión, usa el valor del evento ZMQ_EVENT_ALL_V<version>, por ejemplo, ZMQ_EVENT_ALL_V1. Para versiones de eventos no DRAFT, este valor no cambiará en el futuro, por lo que los nuevos tipos de eventos solo se añadirán en nuevas versiones (ten en cuenta que este es un cambio respecto a zmq_socket_monitor y al ZMQ_EVENT_ALL no versionado).

Ten en cuenta que la versión de eventos 2 está actualmente en modo DRAFT. El protocolo puede ser modificado en cualquier momento para las versiones de eventos en DRAFT.

ZMQ_CURRENT_EVENT_VERSION y ZMQ_CURRENT_EVENT_VERSION_DRAFT siempre se definen a la versión de eventos estable o DRAFT más reciente, que actualmente son 1 y 2 respectivamente.

Esta página describe el protocolo solo para la event_version 2. Para el protocolo utilizado con la event_version 1, consulta zmq_socket_monitor(3).

Cada evento se envía en múltiples tramas. La primera trama contiene un número de evento (64 bits). El número y el contenido de las tramas siguientes dependen de este número de evento.

A menos que se especifique lo contrario, la segunda trama contiene el número de tramas de valor que la seguirán como un entero de 64 bits. Las tramas tercera a N-ésima contienen un valor de evento (64 bits) que proporciona datos adicionales según el número de evento. Cada tipo de evento puede tener un número diferente de valores. Las penúltima y última tramas contienen cadenas que especifican la conexión o endpoint afectado. La primera trama contiene una cadena que denota el endpoint local, mientras que la segunda trama contiene una cadena que denota el endpoint remoto. Cualquiera de ellas puede estar vacía, dependiendo del tipo de evento y si la conexión utiliza un endpoint local enlazado o conectado.

Ten en cuenta que el formato de la segunda y siguientes tramas, así como el número de tramas, puede ser diferente para los eventos añadidos en el futuro.

El argumento type se utiliza para especificar el tipo de socket de monitorización. Los tipos soportados son ZMQ_PAIR, ZMQ_PUB y ZMQ_PUSH. Ten en cuenta que los consumidores de los eventos deben ser compatibles con el tipo de socket, por ejemplo, un socket de monitorización de tipo ZMQ_PUB requerirá consumidores de tipo ZMQ_SUB. En el caso de que el tipo de socket de monitorización sea ZMQ_PUB, el tema del mensaje multipart es el número de evento, por lo que los consumidores deben suscribirse a los eventos que desean recibir.

El método zmq_socket_monitor_pipes_stats() activa un evento de tipo ZMQ_EVENT_PIPES_STATS para cada par conectado del socket monitorizado. NOTA: zmq_socket_monitor_pipes_stats() está en estado DRAFT.

Los eventos de monitorización solo son generados por algunos transportes: Actualmente estos
son SOCKS, TCP, IPC y TIPC. Ten en cuenta que no es un error llamar
a 'zmq_socket_monitor_versioned' en un socket que está conectado o enlazado a algún
otro transporte, ya que esto puede no ser conocido en el momento en que
se llama a 'zmq_socket_monitor_versioned'. Además, un socket puede ser
conectado/enlazado a múltiples endpoints utilizando diferentes transportes.

Eventos soportados (v1)

ZMQ_EVENT_CONNECTED
~~~~~~~~~~~~~~~~~~~
El socket se ha conectado con éxito a un par remoto. El valor del evento
es el descriptor de archivo (FD) del socket de red subyacente. Advertencia:
no hay garantía de que el FD siga siendo válido cuando tu código
reciba este evento.
ZMQ_EVENT_CONNECT_DELAYED
~~~~~~~~~~~~~~~~~~~~~~~~~
Una solicitud de conexión en el socket está pendiente. El valor del evento
no está especificado.
ZMQ_EVENT_CONNECT_RETRIED
~~~~~~~~~~~~~~~~~~~~~~~~~
Una solicitud de conexión falló y ahora se está reintentando. El valor del evento es
el intervalo de reconexión en milisegundos. Ten en cuenta que el intervalo de
reconexión se recalcula para cada reintento.
ZMQ_EVENT_LISTENING
~~~~~~~~~~~~~~~~~~~
El socket se enlazó con éxito a una interfaz de red. El valor del evento
es el FD del socket de red subyacente. Advertencia: no hay garantía de que
el FD siga siendo válido cuando tu código reciba este evento.
ZMQ_EVENT_BIND_FAILED
~~~~~~~~~~~~~~~~~~~~~
El socket no pudo enlazarse a una interfaz dada. El valor del evento es el
errno generado por la llamada de sistema bind.
ZMQ_EVENT_ACCEPTED
~~~~~~~~~~~~~~~~~~
El socket aceptó una conexión de un par remoto. El valor del evento es el
FD del socket de red subyacente. Advertencia: no hay garantía de que
el FD siga siendo válido cuando tu código reciba este evento.
ZMQ_EVENT_ACCEPT_FAILED
~~~~~~~~~~~~~~~~~~~~~~~
El socket rechazó una conexión de un par remoto. El valor del evento es el
errno generado por la llamada de sistema accept.
ZMQ_EVENT_CLOSED
~~~~~~~~~~~~~~~~
El socket se cerró. El valor del evento es el FD del socket de red (ya cerrado).
ZMQ_EVENT_CLOSE_FAILED
~~~~~~~~~~~~~~~~~~~~~~
El cierre del socket falló. El valor del evento es el errno devuelto por la llamada
al sistema. Ten en cuenta que este evento solo ocurre en transportes IPC.
ZMQ_EVENT_DISCONNECTED
~~~~~~~~~~~~~~~~~~~~~~
El socket se desconectó inesperadamente. El valor del evento es el FD del
socket de red subyacente. Advertencia: este socket se cerrará.
ZMQ_EVENT_MONITOR_STOPPED
~~~~~~~~~~~~~~~~~~~~~~~~~
La monitorización en este socket finalizó.
ZMQ_EVENT_HANDSHAKE_FAILED_NO_DETAIL
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Error no especificado durante el handshake.
El valor del evento es un errno.
ZMQ_EVENT_HANDSHAKE_SUCCEEDED
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
El handshake del mecanismo de seguridad ZMTP tuvo éxito.
El valor del evento no está especificado.
ZMQ_EVENT_HANDSHAKE_FAILED_PROTOCOL
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
El handshake del mecanismo de seguridad ZMTP falló debido a algún error de protocolo
del mecanismo, ya sea entre los pares del mecanismo ZMTP, o entre el servidor
del mecanismo y el manejador ZAP. Esto indica un error de configuración o
implementación en cualquiera de los pares o en el manejador ZAP.
El valor del evento es uno de los valores ZMQ_PROTOCOL_ERROR_* :
ZMQ_PROTOCOL_ERROR_ZMTP_UNSPECIFIED
ZMQ_PROTOCOL_ERROR_ZMTP_UNEXPECTED_COMMAND
ZMQ_PROTOCOL_ERROR_ZMTP_INVALID_SEQUENCE
ZMQ_PROTOCOL_ERROR_ZMTP_KEY_EXCHANGE
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_UNSPECIFIED
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_MESSAGE
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_HELLO
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_INITIATE
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_ERROR
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_READY
ZMQ_PROTOCOL_ERROR_ZMTP_MALFORMED_COMMAND_WELCOME
ZMQ_PROTOCOL_ERROR_ZMTP_INVALID_METADATA
ZMQ_PROTOCOL_ERROR_ZMTP_CRYPTOGRAPHIC
ZMQ_PROTOCOL_ERROR_ZMTP_MECHANISM_MISMATCH
ZMQ_PROTOCOL_ERROR_ZAP_UNSPECIFIED
ZMQ_PROTOCOL_ERROR_ZAP_MALFORMED_REPLY
ZMQ_PROTOCOL_ERROR_ZAP_BAD_REQUEST_ID
ZMQ_PROTOCOL_ERROR_ZAP_BAD_VERSION
ZMQ_PROTOCOL_ERROR_ZAP_INVALID_STATUS_CODE
ZMQ_PROTOCOL_ERROR_ZAP_INVALID_METADATA
ZMQ_EVENT_HANDSHAKE_FAILED_AUTH
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
El handshake del mecanismo de seguridad ZMTP falló debido a un fallo de autenticación.
El valor del evento es el código de estado devuelto por el manejador ZAP (es decir, 300,
400 o 500).

Eventos soportados (v2)

ZMQ_EVENT_PIPES_STATS
~~~~~~~~~~~~~~~~~~~~~
Este evento proporciona dos valores, el número de mensajes en cada una de las dos
colas asociadas al endpoint devuelto (respectivamente egreso e ingreso).
Este evento solo se activa después de llamar a la función
_zmq_socket_monitor_pipes_stats()_.
NOTA: esta medición es asíncrona, por lo que en el momento en que se recibe el mensaje
el estado interno podría haber cambiado ya.
NOTA: cuando el socket monitorizado y el monitor no se utilizan en un poll, el
evento podría no ser entregado hasta que se haya llamado a una API en el socket monitorizado,
como zmq_getsockopt por ejemplo (la opción es irrelevante).
NOTA: en estado DRAFT, aún no disponible en versiones estables.
VALOR DE RETORNO

Las funciones zmq_socket_monitor() y zmq_socket_monitor_pipes_stats() devuelven un valor de 0 o mayor si tienen éxito. De lo contrario, devuelven -1 y establecen errno a uno de los valores definidos a continuación.

NAME

zmq_socket_monitor_versioned — Set up a socket monitor

SYNOPSIS

int zmq_socket_monitor_versioned (void *socket, const char *addr, int events, int version);

DESCRIPTION

The zmq_socket_monitor_versioned function shall set up a monitor on the specified socket, emitting events to the specified addr when the specified events occur. The monitor socket shall be of type ZMQ_PAIR and attached to the specified addr using zmq_bind. The addr shall be of the form inproc://.

The events parameter is a bitmask of events to monitor. The following events are available:

ZMQ_EVENT_CONNECTED
The socket successfully connected to a peer.
ZMQ_EVENT_CONNECT_DELAYED
The socket could not establish a connection to a peer within the negotiated timeout. This event is only generated for connection establishment when ZMQ_CONNECT_TIMEOUT socket option is set on the peer.
ZMQ_EVENT_CONNECT_RETried
The socket retried establishing a connection to a peer. This event is only generated for connection establishment when ZMQ_MAX_RETRIES or ZMQ_MAX_RETRY_INTERVAL socket option is set on the peer.
ZMQ_EVENT_DISCONNECTED
The socket disconnected from a peer.
ZMQ_EVENT_MONITOR_STOPPED
The monitor socket itself has been closed.
ZMQ_EVENT_LISTENING
The socket successfully started listening on an endpoint.
ZMQ_EVENT_BIND_FAILED
The socket failed to start listening on an endpoint.
ZMQ_EVENT_ACCEPTED
The socket successfully accepted a connection from a peer.
ZMQ_EVENT_ACCEPT_FAILED
The socket failed to accept a connection from a peer.
ZMQ_EVENT_CLOSE_FAILED
The socket failed to close a connection from a peer.
ZMQ_EVENT_CLOSED
The socket successfully closed a connection from a peer.

Use ZMQ_EVENT_ALL to monitor all events.

The version parameter specifies the protocol version for the monitor. If set to 2, events will be sent in the new format.

When version 2 is used, each event is sent as a multi-frame message:

  • Frame 0: Event code (uint64_t)

  • Frame 1: Number of event values (uint64_t)

  • Frame 2...N: Event values (uint64_t)

  • Frame N+1: Local address (string)

  • Frame N+2: Remote address (string)

The event values are specific to each event. For ZMQ_EVENT_CONNECTED and ZMQ_EVENT_ACCEPTED, the value is the endpoint identity. For ZMQ_EVENT_CLOSE_FAILED and ZMQ_EVENT_CLOSED, the value is the endpoint identity. For ZMQ_EVENT_LISTENING, the value is the endpoint identity. For ZMQ_EVENT_BIND_FAILED and ZMQ_EVENT_ACCEPT_FAILED, the value is an error code. For ZMQ_EVENT_CONNECT_DELAYED and ZMQ_EVENT_CONNECT_RETRIED, the value is the delay time in milliseconds.

Note that zmq_socket_monitor_versioned only supports monitoring over the inproc:// transport. Attempting to use any other transport will result in EPROTONOSUPPORT error.

The socket must be of type ZMQ_PAIR for the monitor socket. The address must be of the form inproc://<endpoint>.

The socket being monitored must have monitoring enabled by this call before the event occurs. For instance, to monitor connection events on a client socket, zmq_socket_monitor_versioned must be called before zmq_connect.

ERRORS

EPROTONOSUPPORT

The transport protocol specified in addr is not supported for socket monitoring. Only inproc:// transports are supported.

EINVAL

The addr parameter is invalid or the monitor socket type is not ZMQ_PAIR.

EFSM

The socket argument is invalid or the monitor socket is already in use.

ENOTSOCK

The socket parameter was not a valid 0MQ socket.

EAGAIN

The monitor socket could not be bound to the specified address.

ENOMEM

Out of memory.

ERRORS - ZMQ_SOCKET_MONITOR_PIPES_STATS()

ENOTSOCK

The socket parameter was not a valid 0MQ socket.

EINVAL

The socket did not have monitoring enabled.

EAGAIN

The monitored socket did not have any connections to monitor yet.

EXAMPLE

Monitoring client and server sockets.

//  Read one event off the monitor socket; return values and addresses
//  by reference, if not null, and event number by value. Returns -1
//  in case of error.
static uint64_t
get_monitor_event (void *monitor, uint64_t **value, char **local_address, char **remote_address)
{
    //  First frame in message contains event number
    zmq_msg_t msg;
    zmq_msg_init (&msg);
    if (zmq_msg_recv (&msg, monitor, 0) == -1)
        return -1;              //  Interrupted, presumably
    assert (zmq_msg_more (&msg));
    uint64_t event;
    memcpy (&event, zmq_msg_data (&msg), sizeof (event));
    zmq_msg_close (&msg);
    //  Second frame in message contains the number of values
    zmq_msg_init (&msg);
    if (zmq_msg_recv (&msg, monitor, 0) == -1)
        return -1;              //  Interrupted, presumably
    assert (zmq_msg_more (&msg));
    uint64_t value_count;
    memcpy (&value_count, zmq_msg_data (&msg), sizeof (value_count));
    zmq_msg_close (&msg);
    if (value) {
        *value = (uint64_t *) malloc (value_count * sizeof (uint64_t));
        assert (*value);
    }
    for (uint64_t i = 0; i < value_count; ++i) {
        //  Subsequent frames in message contain event values
        zmq_msg_init (&msg);
        if (zmq_msg_recv (&msg, monitor, 0) == -1)
            return -1;              //  Interrupted, presumably
        assert (zmq_msg_more (&msg));
        if (value && *value)
            memcpy (&(*value)[i], zmq_msg_data (&msg), sizeof (uint64_t));
        zmq_msg_close (&msg);
    }
    //  Second-to-last frame in message contains local address
    zmq_msg_init (&msg);
    if (zmq_msg_recv (&msg, monitor, 0) == -1)
        return -1;              //  Interrupted, presumably
    assert (zmq_msg_more (&msg));
    if (local_address_) {
        uint8_t *data = (uint8_t *) zmq_msg_data (&msg);
        size_t size = zmq_msg_size (&msg);
        *local_address_ = (char *) malloc (size + 1);
        memcpy (*local_address_, data, size);
        (*local_address_)[size] = 0;
    }
    zmq_msg_close (&msg);
    //  Last frame in message contains remote address
    zmq_msg_init (&msg);
    if (zmq_msg_recv (&msg, monitor, 0) == -1)
        return -1;              //  Interrupted, presumably
    assert (!zmq_msg_more (&msg));
    if (remote_address_) {
        uint8_t *data = (uint8_t *) zmq_msg_data (&msg);
        size_t size = zmq_msg_size (&msg);
        *remote_address_ = (char *) malloc (size + 1);
        memcpy (*remote_address_, data, size);
        (*remote_address_)[size] = 0;
    }
    zmq_msg_close (&msg);
    return event;
}
int main (void)
{
    void *ctx = zmq_ctx_new ();
    assert (ctx);
    //  We'll monitor these two sockets
    void *client = zmq_socket (ctx, ZMQ_DEALER);
    assert (client);
    void *server = zmq_socket (ctx, ZMQ_DEALER);
    assert (server);
    //  Socket monitoring only works over inproc://
    int rc = zmq_socket_monitor_versioned (client, "tcp://127.0.0.1:9999", 0, 2);
    assert (rc == -1);
    assert (zmq_errno () == EPROTONOSUPPORT);
    //  Monitor all events on client and server sockets
    rc = zmq_socket_monitor_versioned (client, "inproc://monitor-client", ZMQ_EVENT_ALL, 2);
    assert (rc == 0);
    rc = zmq_socket_monitor_versioned (server, "inproc://monitor-server", ZMQ_EVENT_ALL, 2);
    assert (rc == 0);
    //  Create two sockets for collecting monitor events
    void *client_mon = zmq_socket (ctx, ZMQ_PAIR);
    assert (client_mon);
    void *server_mon = zmq_socket (ctx, ZMQ_PAIR);
    assert (server_mon);
    //  Connect these to the inproc endpoints so they'll get events
    rc = zmq_connect (client_mon, "inproc://monitor-client");
    assert (rc == 0);
    rc = zmq_connect (server_mon, "inproc://monitor-server");
    assert (rc == 0);
    //  Now do a basic ping test
    rc = zmq_bind (server, "tcp://127.0.0.1:9998");
    assert (rc == 0);
    rc = zmq_connect (client, "tcp://127.0.0.1:9998");
    assert (rc == 0);
    bounce (client, server);
    //  Close client and server
    close_zero_linger (client);
    close_zero_linger (server);
    //  Now collect and check events from both sockets
    int event = get_monitor_event (client_mon, NULL, NULL);
    if (event == ZMQ_EVENT_CONNECT_DELAYED)
        event = get_monitor_event (client_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_CONNECTED);
    event = get_monitor_event (client_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_MONITOR_STOPPED);
    //  This is the flow of server events
    event = get_monitor_event (server_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_LISTENING);
    event = get_monitor_event (server_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_ACCEPTED);
    event = get_monitor_event (server_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_CLOSED);
    event = get_monitor_event (server_mon, NULL, NULL);
    assert (event == ZMQ_EVENT_MONITOR_STOPPED);
    //  Close down the sockets
    close_zero_linger (client_mon);
    close_zero_linger (server_mon);
    zmq_ctx_term (ctx);
    return 0 ;
}
