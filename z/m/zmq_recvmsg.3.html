NOMBRE

zmq_recvmsg - recibir una parte de mensaje de un socket

SINOPSIS

int zmq_recvmsg (void *socket, zmq_msg_t *msg, int flags);

DESCRIPCIÓN

La función zmq_recvmsg() recibirá una parte de mensaje del socket referenciado por el argumento socket y la almacenará en el mensaje referenciado por el argumento msg. Cualquier contenido almacenado previamente en msg será debidamente desasignado. Si no hay partes de mensaje disponibles en el socket especificado, la función zmq_recvmsg() se bloqueará hasta que la solicitud pueda ser satisfecha. El argumento flags es una combinación de las banderas definidas a continuación:

ZMQ_DONTWAIT

Especifica que la operación debe realizarse en modo no bloqueante. Si no hay mensajes disponibles en el socket especificado, la función zmq_recvmsg() fallará con errno establecido a EAGAIN.

Nota

este método de API está obsoleto y se prefiere zmq_msg_recv(3).

Mensajes multi-parte

Un mensaje 0MQ se compone de 1 o más partes de mensaje. Cada parte de mensaje es una zmq_msg_t independiente por derecho propio. 0MQ asegura la entrega atómica de mensajes: los pares recibirán todas las partes del mensaje de un mensaje o ninguna. El número total de partes de mensaje es ilimitado, excepto por la memoria disponible.

Una aplicación que procesa mensajes multi-parte debe usar la opción ZMQ_RCVMORE de zmq_getsockopt(3) después de llamar a zmq_recvmsg() para determinar si hay más partes que recibir.

VALOR DE RETORNO

La función zmq_recvmsg() devolverá el número de bytes en el mensaje si tiene éxito. De lo contrario, devolverá -1 y establecerá errno en uno de los valores definidos a continuación.

ERRORES

EAGAIN

O bien el tiempo de espera establecido a través de la opción de socket ZMQ_RCVTIMEO (ver zmq_setsockopt(3)) ha expirado (bandera ZMQ_DONTWAIT no establecida) sin poder leer un mensaje del socket o no hay mensajes disponibles en el momento (bandera ZMQ_DONTWAIT establecida) y la operación bloquearía.

ENOTSUP

La operación zmq_recvmsg() no es compatible con este tipo de socket.

EFSM

La operación zmq_recvmsg() no se puede realizar en este socket en este momento debido a que el socket no se encuentra en el estado apropiado. Este error puede ocurrir con tipos de socket que cambian entre varios estados, como ZMQ_REP. Ver la sección de patrones de mensajería de zmq_socket(3) para más información.

ETERM

El contexto 0MQ asociado con el socket especificado fue terminado.

ENOTSOCK

El socket proporcionado era inválido.

EINTR

La operación fue interrumpida por la entrega de una señal antes de que hubiera un mensaje disponible.

EFAULT

El mensaje pasado a la función era inválido.

EJEMPLO

Recibir un mensaje de un socket.

/* Crear un mensaje 0MQ vacío */
zmq_msg_t msg;
int rc = zmq_msg_init (&msg);
assert (rc == 0);
/* Bloquear hasta que un mensaje esté disponible para ser recibido del socket */
rc = zmq_recvmsg (socket, &msg, 0);
assert (rc != -1);
/* Liberar mensaje */
zmq_msg_close (&msg);

Recibir un mensaje multi-parte.

int more;
size_t more_size = sizeof (more);
do {
    /* Crear un mensaje 0MQ vacío para contener la parte del mensaje */
    zmq_msg_t part;
    int rc = zmq_msg_init (&part);
    assert (rc == 0);
    /* Bloquear hasta que un mensaje esté disponible para ser recibido del socket */
    rc = zmq_recvmsg (socket, &part, 0);
    assert (rc != -1);
    /* Determinar si más partes del mensaje seguirán */
    rc = zmq_getsockopt (socket, ZMQ_RCVMORE, &more, &more_size);
    assert (rc == 0);
    zmq_msg_close (&part);
} while (more);
