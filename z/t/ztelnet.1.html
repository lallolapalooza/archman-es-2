NOMBRE

zssh - wrapper interactivo de transferencia de archivos para ssh

SINOPSIS

zssh [opciones de zssh] [--] [opciones de ssh]
ztelnet [opciones de zssh] [--] [opciones de telnet]

DESCRIPCIÓN

zssh (Zmodem SSH) es un programa para transferir interactivamente archivos a una máquina remota mientras se utiliza el shell seguro ( ssh ). Está pensado para ser una alternativa conveniente a scp , permitiendo transferir archivos sin tener que abrir otra sesión y volver a autenticarse.

zssh es un wrapper interactivo para ssh utilizado para cambiar la conexión ssh entre el shell remoto y las transferencias de archivos. Esto se logra utilizando otro par de tty/pty entre el usuario y el proceso ssh local para enchufar el tty del usuario (modo shell remoto) o a otro proceso (modo de transferencia de archivos) en la conexión ssh.

ztelnet se comporta de manera similar a zssh, excepto que se usa telnet en lugar de ssh. Es equivalente a 'zssh -s "telnet -8 -E"'

Los archivos se transfieren a través del protocolo zmodem, utilizando los comandos rz y sz.

zssh se comporta como una sesión ssh normal hasta que se presiona la secuencia de escape (el valor predeterminado es ^@ que se puede producir presionando C-espacio, o C-2, o C-`), lo que habilita el modo de transferencia de archivos. Luego se muestra un nuevo prompt, y se pueden ejecutar comandos localmente para iniciar transferencias de archivos (entre otras cosas). Se comporta aproximadamente como un shell local con edición de línea, historial y autocompletado (gracias a libreadline), globbing y caracteres de escape (' y \).

Los siguientes comandos internos son manejados por zssh:

cd <dir>
cambia el directorio actual
disconnect
desconecta y sale
escape [^X]
Cambia la tecla de escape a ^X. Sin argumento, imprime la tecla de escape actual
exit
sale del modo de transferencia de archivos. ^D también se puede usar para este propósito.
help
imprime ayuda y consejos
?
hook prg [args]
Engancha el programa 'prg' en el pty. Su entrada y salida estándar irán a través del canal ssh.
escribir 'sz'/'rz' es en realidad equivalente a 'hook sz'/'hook rz'
Una imaginación peculiar es muy útil para sacar el máximo provecho de esta característica.
quit
igual que exit.
repeat
repite el comando para siempre (^C para interrumpir). Útil por ejemplo si usa un script remoto que invoca "sz" y no quiere escribir "rz" cada vez... Recuerde sin embargo que varios archivos pueden ser transferidos por un solo par sz/rz, por lo que esto normalmente no es necesario para usar repeat.
rz
Recibe archivos de la máquina remota. Ejecuta rz y conecta el proceso al canal ssh. Es necesario ejecutar sz en la máquina REMOTA:
1) Ejecute `sz <archivo_remoto> ...' desde el shell de la máquina remota
2) Presione la secuencia de escape (C-espacio) para entrar en modo de transferencia de archivos
3) Ejecute el comando interno `rz'
suspend
suspende zssh (vuelve al shell de la máquina local)
sz <archivo> ...
Envía archivos a la máquina remota. Ejecuta sz y conecta el proceso al canal ssh. No es necesario ejecutar rz manualmente en el lado remoto.
version
imprime información de la versión

Los comandos internos rz, sz, hook y exit regresan al modo de shell después de completarse.

OPCIONES

-f
--force
No pregunte nada al usuario
-h
--help
muestra ayuda básica
-s cmd
--shell cmd
ejecuta cmd como shell remoto en lugar del predeterminado "ssh -e none" (zssh) o "telnet -8 -E" (ztelnet)
ej: zssh -s "rsh -x"
-V
--version
muestra la versión
-z ^X
--zssh-escape ^X
establece la secuencia de escape a ^X

-- se puede usar para separar las opciones de zssh de las de ssh
Otros argumentos se pasan textualmente a ssh/telnet/lo que sea.

AMBIENTE

ZSSHESCAPE
Establecer la variable de entorno ZSSHESCAPE permite anular la secuencia de escape predeterminada. ZSSHESCAPE debe contener solo dos caracteres del formato `^X', lo que significa que ^X será la nueva secuencia de escape.

REQUISITOS

los siguientes binarios deben estar instalados correctamente para que zssh funcione:

ssh/telnet/...
el shell remoto a ejecutar (máquina local)
sz rz
programas de envío y recepción zmodem. Deberían estar tanto en la máquina local como en la remota, y (con suerte) de versiones compatibles.

CONSEJOS

Si la transferencia de archivos se inicia pero nunca se completa
(es decir, una línea como:
Bytes enviados: 38144/4610624 BPS:3424 ETA 22:15
o
Bytes enviados: 0/ 513 BPS:0 ETA 00:00 Reintento 0: Recibido ZCAN
se puede ver, pero la transferencia nunca se completa
)
Lo más probable es que el pty/tty en uno de los sistemas no sea 8-bit clean. (Linux es 8-bit clean, NetBSD no lo es).
Usar la opción -e (escape) de rz debería resolver este problema.

Las transferencias se pueden interrumpir con ^C (¡algo experimental =)!

Si te quedas atascado en rz/sz (por ejemplo, acabas de ejecutar rz, pero luego decidiste no transmitir nada), presiona una docena de ^X (Ctrl-X, no el escape de zssh!) para detenerlo

Usa `sz -y <archivos>' para sobrescribir archivos en el otro lado

ERRORES / LIMITACIONES

A veces, puede que tengas que presionar enter 2 o 3 veces después de que la transferencia de archivos se complete para volver al shell. Algunos dígitos se muestran normalmente; no te preocupes, no te hará daño (a ti ni a tu terminal)...

el tty puede (a veces) quedar algo afectado después de una transferencia interrumpida (usando ^C). Escribir `reset' en ese caso debería ayudar.

sin soporte para pipes, redirección (y otras cosas) en el shell... pero después de todo ya hay shells maravillosos alrededor =)
