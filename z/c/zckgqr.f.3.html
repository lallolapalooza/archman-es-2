ZCKGQR

Propósito:

!>
!> ZCKGQR prueba
!> ZGGQRF: Factorización GQR para la matriz A de N por M y la matriz B de N por P,
!> ZGGRQF: Factorización GRQ para la matriz A de M por N y la matriz B de P por N.
!>

Parámetros

NM 
!>          NM es ENTERO
!>          El número de valores de M contenidos en el vector MVAL.
!>

MVAL

!>          MVAL es un array ENTERO, dimensión (NM)
!>          Los valores de la dimensión de fila/columna de la matriz M.
!>

NP

!>          NP es ENTERO
!>          El número de valores de P contenidos en el vector PVAL.
!>

PVAL

!>          PVAL es un array ENTERO, dimensión (NP)
!>          Los valores de la dimensión de fila/columna de la matriz P.
!>

NN

!>          NN es ENTERO
!>          El número de valores de N contenidos en el vector NVAL.
!>

NVAL

!>          NVAL es un array ENTERO, dimensión (NN)
!>          Los valores de la dimensión de columna/fila de la matriz N.
!>

NMATS

!>          NMATS es ENTERO
!>          El número de tipos de matriz a probar para cada combinación
!>          de dimensiones de matriz. Si NMATS >= NTYPES (el número máximo
!>          de tipos de matriz), entonces se generan todos los tipos diferentes
!>          para la prueba. Si NMATS < NTYPES, se lee una línea de entrada adicional
!>          para obtener los números de los tipos de matriz a utilizar.
!>

ISEED

!>          ISEED es un array ENTERO, dimensión (4)
!>          En la entrada, la semilla del generador de números aleatorios. Los elementos
!>          del array deben estar entre 0 y 4095, de lo contrario se reducirán
!>          módulo 4096, y ISEED(4) debe ser impar.
!>          En la salida, la siguiente semilla en la secuencia de números aleatorios
!>          después de que se hayan generado todas las matrices de prueba.
!>

THRESH

!>          THRESH es PRECISIÓN DOBLE
!>          El valor umbral para las relaciones de prueba. Un resultado se
!>          incluye en el archivo de salida si RESULTADO >= UMBRAL. Para que
!>          se impriman todas las relaciones de prueba, use UMBRAL = 0.
!>

NMAX

!>          NMAX es ENTERO
!>          El valor máximo permitido para M o N, utilizado en la dimensionamiento
!>          de los arrays de trabajo.
!>

A

!>          A es un array COMPLEJO*16, dimensión (NMAX*NMAX)
!>

AF

!>          AF es un array COMPLEJO*16, dimensión (NMAX*NMAX)
!>

AQ

!>          AQ es un array COMPLEJO*16, dimensión (NMAX*NMAX)
!>

AR

!>          AR es un array COMPLEJO*16, dimensión (NMAX*NMAX)
!>

TAUA

!>          TAUA es un array COMPLEJO*16, dimensión (NMAX)
!>

B

!>          B es un array COMPLEJO*16, dimensión (NMAX*NMAX)
!>

BF

!>          BF es un array COMPLEJO*16, dimensión (NMAX*NMAX)
!>

BZ

!>          BZ es un array COMPLEJO*16, dimensión (NMAX*NMAX)
!>

BT

!>          BT es un array COMPLEJO*16, dimensión (NMAX*NMAX)
!>

BWK

!>          BWK es un array COMPLEJO*16, dimensión (NMAX*NMAX)
!>

TAUB

!>          TAUB es un array COMPLEJO*16, dimensión (NMAX)
!>

WORK

!>          WORK es un array COMPLEJO*16, dimensión (NMAX*NMAX)
!>

RWORK

!>          RWORK es un array de PRECISIÓN DOBLE, dimensión (NMAX)
!>

NIN

!>          NIN es ENTERO
!>          La unidad de número para entrada.
!>

NOUT

!>          NOUT es ENTERO
!>          La unidad de número para salida.
!>

INFO

!>          INFO es ENTERO
!>          = 0 : salida exitosa
!>          > 0 : Si ZLATMS devuelve un código de error, su valor absoluto
!>                 se devuelve.
!>

Sobre Nosotros

Arch Linux es una distribución de Linux independiente, orientada a x86-64, diseñada para ser ligera y flexible.

Desarrollada por desarrolladores y usuarios, Arch Linux se esfuerza por ser simple en su diseño, moderna, pragmática, centrada en el usuario y versátil.

Arch Linux sigue un modelo de lanzamiento continuo, lo que significa que no hay "versiones" fijas. El sistema se actualiza constantemente, permitiéndole tener siempre la última versión de cada paquete de software.

Filosofía

La filosofía de Arch Linux se puede resumir en:

  • Simplicidad: Se prioriza un diseño limpio y sin adornos.
  • Modernidad: Se utilizan las versiones más recientes de software.
  • Pragmatismo: Se adoptan soluciones prácticas y eficientes.
  • Centrado en el usuario: El usuario tiene control total sobre su sistema.
  • Versatilidad: El sistema está diseñado para adaptarse a diversas necesidades.
