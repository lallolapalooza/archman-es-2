ZDRVST

Propósito:

!>
!>      ZDRVST  comprueba los drivers de problemas de valores propios Hermitianos.
!>
!>              ZHEEVD calcula todos los valores propios y, opcionalmente, los
!>              vectores propios de una matriz Hermitiana compleja,
!>              usando un algoritmo de divide y vencerás.
!>
!>              ZHEEVX calcula valores propios seleccionados y, opcionalmente,
!>              vectores propios de una matriz Hermitiana compleja.
!>
!>              ZHEEVR calcula valores propios seleccionados y, opcionalmente,
!>              vectores propios de una matriz Hermitiana compleja
!>              usando la Representación Relativamente Robusta siempre que sea posible.
!>
!>              ZHPEVD calcula todos los valores propios y, opcionalmente, los
!>              vectores propios de una matriz Hermitiana compleja en almacenamiento empaquetado,
!>              usando un algoritmo de divide y vencerás.
!>
!>              ZHPEVX calcula valores propios seleccionados y, opcionalmente,
!>              vectores propios de una matriz Hermitiana compleja en almacenamiento empaquetado.
!>
!>              ZHBEVD calcula todos los valores propios y, opcionalmente, los
!>              vectores propios de una matriz banda Hermitiana compleja,
!>              usando un algoritmo de divide y vencerás.
!>
!>              ZHBEVX calcula valores propios seleccionados y, opcionalmente,
!>              vectores propios de una matriz banda Hermitiana compleja.
!>
!>              ZHEEV calcula todos los valores propios y, opcionalmente, los
!>              vectores propios de una matriz Hermitiana compleja.
!>
!>              ZHPEV calcula todos los valores propios y, opcionalmente, los
!>              vectores propios de una matriz Hermitiana compleja en almacenamiento empaquetado.
!>
!>              ZHBEV calcula todos los valores propios y, opcionalmente, los
!>              vectores propios de una matriz banda Hermitiana compleja.
!>
!>      Cuando ZDRVST es llamada, se especifican un número de tamaños de matriz () y un
!>      número de tipos de matriz. Para cada tamaño ()
!>      y cada tipo de matriz, se generará una matriz y se utilizará
!>      para probar los drivers apropiados. Para cada matriz y cada
!>      rutina de driver llamada, se realizarán las siguientes pruebas:
!>
!>      (1)     | A - Z D Z' | / ( |A| n ulp )
!>
!>      (2)     | I - Z Z' | / ( n ulp )
!>
!>      (3)     | D1 - D2 | / ( |D1| ulp )
!>
!>      donde Z es la matriz de vectores propios devuelta cuando se da la
!>      opción de vector propio y D1 y D2 son los valores propios
!>      devueltos con y sin la opción de vector propio.
!>
!>      Los tamaños () se especifican mediante un array NN(1:NSIZES); el valor de
!>      cada elemento NN(j) especifica un tamaño.
!>      Los tipos () se especifican mediante un array lógico DOTYPE( 1:NTYPES );
!>      si DOTYPE(j) es .TRUE., entonces se generará la matriz de tipo j.
!>      Actualmente, la lista de tipos posibles es:
!>
!>      (1)  La matriz cero.
!>      (2)  La matriz identidad.
!>
!>      (3)  Una matriz diagonal con entradas espaciadas uniformemente
!>           1, ..., ULP  y signos aleatorios.
!>           (ULP = (primer número mayor que 1) - 1 )
!>      (4)  Una matriz diagonal con entradas espaciadas geométricamente
!>           1, ..., ULP  y signos aleatorios.
!>      (5)  Una matriz diagonal con entradas  1, ULP, ..., ULP
!>           y signos aleatorios.
!>
!>      (6)  Igual que (4), pero multiplicada por SQRT( umbral de desbordamiento )
!>      (7)  Igual que (4), pero multiplicada por SQRT( umbral de subdesbordamiento )
!>
!>      (8)  Una matriz de la forma  U* D U, donde U es unitaria y
!>           D tiene entradas espaciadas uniformemente 1, ..., ULP con signos
!>           aleatorios en la diagonal.
!>
!>      (9)  Una matriz de la forma  U* D U, donde U es unitaria y
!>           D tiene entradas espaciadas geométricamente 1, ..., ULP con signos
!>           aleatorios en la diagonal.
!>
!>      (10) Una matriz de la forma  U* D U, donde U es unitaria y
!>           D tiene entradas  1, ULP,..., ULP con signos
!>           aleatorios en la diagonal.
!>
!>      (11) Igual que (8), pero multiplicada por SQRT( umbral de desbordamiento )
!>      (12) Igual que (8), pero multiplicada por SQRT( umbral de subdesbordamiento )
!>
!>      (13) Matriz simétrica con entradas aleatorias elegidas entre (-1,1).
!>      (14) Igual que (13), pero multiplicada por SQRT( umbral de desbordamiento )
!>      (15) Igual que (13), pero multiplicada por SQRT( umbral de subdesbordamiento )
!>      (16) Una matriz banda con ancho de banda medio elegido aleatoriamente entre
!>           0 y N-1, con valores propios espaciados uniformemente 1, ..., ULP
!>           con signos aleatorios.
!>      (17) Igual que (16), pero multiplicada por SQRT( umbral de desbordamiento )
!>      (18) Igual que (16), pero multiplicada por SQRT( umbral de subdesbordamiento )
!> 
!>  NSIZES  INTEGER
!>          El número de tamaños de matrices a utilizar. Si es cero,
!>          ZDRVST no hace nada. Debe ser mayor o igual a cero.
!>          No modificado.
!>
!>  NN      INTEGER array, dimension (NSIZES)
!>          Un array que contiene los tamaños a utilizar para las matrices.
!>          Se omitirán los valores cero. Los valores deben ser mayores o iguales a
!>          cero.
!>          No modificado.
!>
!>  NTYPES  INTEGER
!>          El número de elementos en DOTYPE. Si es cero, ZDRVST
!>          no hace nada. Debe ser mayor o igual a cero. Si es MAXTYP+1
!>          y NSIZES es 1, entonces se define un tipo adicional, MAXTYP+1,
!>          que es usar la matriz que esté en A. Esto
!>          solo es útil si DOTYPE(1:MAXTYP) es .FALSE. y
!>          DOTYPE(MAXTYP+1) es .TRUE. .
!>          No modificado.
!>
!>  DOTYPE  LOGICAL array, dimension (NTYPES)
!>          Si DOTYPE(j) es .TRUE., entonces para cada tamaño en NN se generará una
!>          matriz de ese tamaño y de tipo j.
!>          Si NTYPES es menor que el número máximo de tipos
!>          definidos (PARAMETER MAXTYP), entonces los tipos NTYPES+1 hasta
!>          MAXTYP no se generarán. Si NTYPES es mayor
!>          que MAXTYP, DOTYPE(MAXTYP+1) hasta DOTYPE(NTYPES)
!>          serán ignorados.
!>          No modificado.
!>
!>  ISEED   INTEGER array, dimension (4)
!>          En la entrada ISEED especifica la semilla del generador de números
!>          aleatorios. Los elementos del array deben estar entre 0 y 4095;
!>          si no lo están, se reducirán módulo 40

LAPACK

zdrvst(3)

Version 3.12.0

NAME

zdrvst - provides the driver routines for testing ZHEEV, ZHEGV, ZHP, ZHPX, ZGBEV, ZGBVX, ZGEEV, ZGEVX, ZSYSV, ZSYGSV, ZPOSV, ZPOSVX, ZSPSV, ZSPSVX, ZGESV, ZGESVX, ZPTTRF, ZPTTRS, ZLATME, ZLATMS, ZLATMR, ZLATMS, DLAFTS, ZDRVST

SYNOPSIS

CALL ZDRVST( NSIZES, NN, NTSTYPES, JTYPES, DOTYPE, ISEED, THRESH,
             NOUNIT, A, LDA, D1, D2, D3, WA1, WA2, WA3, U, LDU, V, TAU,
             Z, WORK, LWORK, RWORK, LRWORK, IWORK, LIWORK, RESULT, INFO )

Function/Subroutine Documentation

  NSIZES  INTEGER
          The number of sizes of matrices to be tested.

  NN      INTEGER array, dimension (NSIZES)
          The sizes of the matrices to be tested.

  NTYPES  INTEGER
          The number of matrix types to be tested.

  JTYPES  INTEGER array, dimension (NTYPES)
          The list of matrix types to be tested.

  DOTYPE  LOGICAL array, dimension (NTYPES)
          If DOTYPE(j) is true, then type JTYPE(j) will be tested.

  ISEED   INTEGER array, dimension (4)
          The random number seed used to generate random matrices.
          It must be odd. The random number generator uses a linear
          congruential sequence limited to small integers, and so
          should produce machine independent random numbers. The
          values of ISEED are changed on exit, and can be used in the
          next call to ZDRVST to continue the same random number
          sequence.
          Modified.

  THRESH  DOUBLE PRECISION
          A test will count as
          if the , computed as
          described above, exceeds THRESH. Note that the error
          is scaled to be O(1), so THRESH should be a reasonably
          small multiple of 1, e.g., 10 or 100. In particular,
          it should not depend on the precision (single vs. double)
          or the size of the matrix. It must be at least zero.
          Not modified.

  NOUNIT  INTEGER
          The FORTRAN unit number for printing out error messages
          (e.g., if a routine returns IINFO not equal to 0.)
          Not modified.

  A       COMPLEX*16 array, dimension (LDA , max(NN))
          Used to hold the matrix whose eigenvalues are to be
          computed. On exit, A contains the last matrix actually
          used.
          Modified.

  LDA     INTEGER
          The leading dimension of A. It must be at
          least 1 and at least max( NN ).
          Not modified.

  D1      DOUBLE PRECISION array, dimension (max(NN))
          The eigenvalues of A, as computed by ZSTEQR simultaneously
          with Z. On exit, the eigenvalues in D1 correspond with the
          matrix in A.
          Modified.

  D2      DOUBLE PRECISION array, dimension (max(NN))
          The eigenvalues of A, as computed by ZSTEQR if Z is not
          computed. On exit, the eigenvalues in D2 correspond with
          the matrix in A.
          Modified.

  D3      DOUBLE PRECISION array, dimension (max(NN))
          The eigenvalues of A, as computed by DSTERF. On exit, the
          eigenvalues in D3 correspond with the matrix in A.
          Modified.

  WA1     DOUBLE PRECISION array, dimension

  WA2     DOUBLE PRECISION array, dimension

  WA3     DOUBLE PRECISION array, dimension

  U       COMPLEX*16 array, dimension (LDU, max(NN))
          The unitary matrix computed by ZHETRD + ZUNGC3.
          Modified.

  LDU     INTEGER
          The leading dimension of U, Z, and V. It must be at
          least 1 and at least max( NN ).
          Not modified.

  V       COMPLEX*16 array, dimension (LDU, max(NN))
          The Housholder vectors computed by ZHETRD in reducing A to
          tridiagonal form.
          Modified.

  TAU     COMPLEX*16 array, dimension (max(NN))
          The Householder factors computed by ZHETRD in reducing A
          to tridiagonal form.
          Modified.

  Z       COMPLEX*16 array, dimension (LDU, max(NN))
          The unitary matrix of eigenvectors computed by ZHEEVD,
          ZHEEVX, ZHPEVD, CHPEVX, ZHBEVD, and CHBEVX.
          Modified.

  WORK  - COMPLEX*16 array of dimension ( LWORK )
           Workspace.
           Modified.

  LWORK - INTEGER
           The number of entries in WORK. This must be at least
           2*max( NN(j), 2 )**2.
           Not modified.

  RWORK   DOUBLE PRECISION array, dimension (3*max(NN))
           Workspace.
           Modified.

  LRWORK - INTEGER
           The number of entries in RWORK.

  IWORK   INTEGER array, dimension (6*max(NN))
          Workspace.
          Modified.

  LIWORK - INTEGER
           The number of entries in IWORK.

  RESULT  DOUBLE PRECISION array, dimension (??)
          The values computed by the tests described above.
          The values are currently limited to 1/ulp, to avoid
          overflow.
          Modified.

  INFO    INTEGER
          If 0, then everything ran OK.
           -1: NSIZES < 0
           -2: Some NN(j) < 0
           -3: NTYPES < 0
           -5: THRESH < 0
           -9: LDA < 1 or LDA < NMAX, where NMAX is max( NN(j) ).
          -16: LDU < 1 or LDU < NMAX.
          -21: LWORK too small.
          If  DLATMR, SLATMS, ZHETRD, DORGC3, ZSTEQR, DSTERF,
              or DORMC2 returns an error code, the
              absolute value of it is returned.
          Modified.

-----------------------------------------------------------------------

       Some Local Variables and Parameters:
       ---- ----- --------- --- ----------
       ZERO, ONE       Real 0 and 1.
       MAXTYP          The number of types defined.
       NTEST           The number of tests performed, or which can
                       be performed so far, for the current matrix.
       NTESTT          The total number of tests performed so far.
       NMAX            Largest value in NN.
       NMATS           The number of matrices generated so far.
       NERRS           The number of tests which have exceeded THRESH
                       so far (computed by DLAFTS).
       COND, IMODE     Values to be passed to the matrix generators.
       ANORM           Norm of A; passed to matrix generators.

       OVFL, UNFL      Overflow and underflow thresholds.
       ULP, ULPINV     Finest relative precision and its inverse.
       RTOVFL, RTUNFL  Square roots of the previous 2 values.
               The following four arrays decode JTYPE:
       KTYPE(j)        The general type (1-10) for type .
       KMODE(j)        The MODE value to be passed to the matrix
                       generator for type .
       KMAGN(j)        The order of magnitude ( O(1),
                       O(overflow^(1/2) ), O(underflow^(1/2) )
