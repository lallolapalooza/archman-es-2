NOMBRE

zonesigner - Genera claves de cifrado y firma una zona DNS

SINOPSIS

zonesigner [opciones] <archivo-zona> <archivo-zona-firmada>
# ejemplos para empezar inmediatamente:
# primera ejecución en una zona para example.com:
zonesigner -genkeys -endtime +2678400 example.com
# futuras ejecuciones antes de la hora de expiración (reutiliza las mismas claves):
zonesigner -endtime +2678400 example.com

DESCRIPCIÓN

Este script combina en un solo comando muchas acciones que son requeridas para firmar una zona DNS. Genera las claves KSK y ZSK requeridas, añade los datos de las claves a un archivo de registro de zona, firma el archivo de zona y ejecuta verificaciones para asegurar que todo funcionó correctamente. También mantiene registros sobre las claves y cómo se firmó la zona para facilitar la resigneación futura de la zona.

Los registros de firma de zona específicos de zonesigner se mantienen en archivos keyrec. Usando archivos keyrec, definidos y mantenidos por DNSSEC-Tools, zonesigner puede recopilar automáticamente muchas de las opciones utilizadas para firmar y generar una zona y sus claves previamente. Esto permite que la zona se mantenga usando las mismas longitudes de clave y tiempos de expiración, por ejemplo, sin que un administrador necesite rastrear manualmente estos campos.

INICIO RÁPIDO

Los siguientes son ejemplos que permitirán un inicio rápido en el uso de zonesigner:

primera ejecución en example.com
El siguiente comando generará claves y firmará el archivo de zona para example.com, dando una fecha de expiración de 31 días en el futuro. El archivo de zona se llama example.com y el archivo de zona firmado se llamará example.com.signed. 
zonesigner -genkeys -endtime +2678400 example.com
ejecuciones posteriores en example.com
El siguiente comando volverá a firmar el archivo de zona de example.com, pero no generará nuevas claves. Los archivos y todos los argumentos de generación de claves y firma de zona permanecerán iguales. 
zonesigner example.com

USANDO ZONESIGNER

zonesigner se usa de esta manera:

zonesigner [opciones] <archivo-zona> <archivo-zona-firmada>

El argumento archivo-zona es obligatorio.

archivo-zona es el nombre del archivo de zona desde el cual se creará un archivo de zona firmado. Si no se proporciona la opción -zone, entonces archivo-zona se usará como el nombre de la zona que se firmará. Las claves generadas toman este nombre como base.

Una vez que zonesigner ha creado un conjunto de claves para una zona y ha firmado la zona, puede ser utilizado para resigne la zona a medida que el archivo de zona cambia. Cuando se ejecuta sin ninguna opción, zonesigner consultará el keyrec de la zona para encontrar el conjunto apropiado de claves y luego firmará la zona especificada con ellas.

El archivo de zona se modifica para tener comandos include, que incluirán las claves KSK y ZSK. Estas líneas se colocan al final del archivo y no deben ser modificadas por el usuario. Si el archivo de zona ya incluye algún archivo de clave, esas inclusiones serán eliminadas. Estas líneas se distinguen por comenzar con "$INCLUDE" y terminar con ".key". Solo las líneas de inclusión reales son eliminadas; cualquier línea de comentario relacionada se deja intacta.

Se utiliza un archivo intermedio para firmar la zona. archivo-zona se copia al archivo intermedio y se modifica en preparación para firmar el archivo de zona. Varias líneas $INCLUDE se añadirán al final del archivo y el número de serie de la SOA se incrementará.

signed-zone es el nombre del archivo de zona firmado. Si no se proporciona en la línea de comandos, el nombre de archivo de zona firmado por defecto es el archivo-zona con ".signed" añadido. Por lo tanto, ejecutar zonesigner example.com resultará en que la zona firmada se almacene en example.com.signed.

A menos que se especifiquen las opciones -genkeys, -genksk, -genzsk o -newpubksk, las últimas claves generadas para una zona en particular se usarán en ejecuciones posteriores de zonesigner. Los registros DS se incluirán en las operaciones de firma a menos que se utilice la opción -nogends.

zonesigner puede usarse con un administrador de rollover, como rollerd, para proporcionar una gestión automatizada de una zona, sus claves y la firma de la zona. Si un archivo de zona administrado por rollerd cambia mientras rollerd está esperando que comience un rollover de zona o que se complete una fase de rollover, zonesigner puede usarse para firmar la zona con el conjunto de claves apropiado; rollerd no se verá afectado por esto.

ARCHIVOS KEYREC

Los archivos keyrec retienen información sobre operaciones anteriores de generación de claves y firma de zona. Si no se especifica un archivo keyrec (a través de la opción -krfile), se utilizará un archivo keyrec por defecto. Si este por defecto no está especificado en el archivo de configuración de DNSSEC-Tools del sistema, el nombre del archivo será el nombre de la zona con ".krf" añadido. Si se proporciona la opción -nokrfile, no se consultará ni se guardará ningún archivo keyrec.

Cada keyrec contiene un conjunto de entradas "clave/valor", una por línea. El ejemplo 4 a continuación contiene el contenido de un archivo keyrec de muestra.

Los archivos keyrec contienen tres tipos de entradas: keyrec de zona, keyrec de conjunto y keyrec de clave. Los keyrec de zona contienen información específica sobre la zona, como el número de ZSK utilizadas para firmar la zona, la hora de finalización de la zona y los nombres de los conjuntos de claves de firma (nombres de keyrec de conjunto). Los keyrec de conjunto contienen listas de nombres de keyrec de clave utilizados para un propósito específico, como las claves ZSK actuales o las claves ZSK publicadas. Los keyrec de clave contienen información sobre las claves generadas en sí mismas, como el algoritmo de cifrado, la longitud de la clave y la vida útil de la clave.

A medida que la zona avanza en el rollover de claves, se generarán nuevas claves criptográficas para la zona. Los diversos parámetros de clave (por ejemplo, la longitud de la clave y el algoritmo criptográfico) serán los mismos que los parámetros utilizados previamente para generar claves para esa zona. El comando keymod permite modificar estos parámetros de clave según cambien las necesidades. Si se modifica un parámetro en particular, como la longitud KSK que cambia de 1024 a 2048, entonces las claves *futuras* reflejarán ese cambio; las claves actuales y pasadas no se modificarán.

Archivos Keyrec y Revocación KSK RFC5011

Si el procesamiento RFC5011 está habilitado, hay un manejo especial del keyrec de conjunto de la zona de claves KSK revocadas. El campo "kskrev" en el keyrec de la zona apunta a un keyrec de conjunto, marcado como de tipo "kskrev". Este keyrec de conjunto, a su vez, apunta a un número de otros keyrec de conjunto, todos los cuales también están marcados como de tipo "kskrev". El grupo de todas las claves KSK revocadas se encuentra consultando ese conjunto subsidiario de keyrec de conjunto "kskrev". Cuando las edades de estas claves revocadas exceden sus períodos de revocación, se marcan como obsoletas ("kskobs"). Si esto sucede como parte de un rollover normal, estas claves revocadas y los keyrec de conjunto son eliminados de la cadena de keyrec activos y revocados. Si esto le sucede a una clave que forma parte de un conjunto más grande de claves, se elimina de ese conjunto de firma y se coloca en su propio nuevo conjunto de firma.

SYNOPSIS

zonesigner [-options] zone

DESCRIPTION

The zonesigner utility automates the process of signing DNSSEC zones. It is intended to be used in a semi-automated or fully automated fashion. It is designed to handle the complexities of key rollovers, time-based key-signing policies, and other DNSSEC-specific operational tasks.

The utility reads configuration options from a number of sources, with the command line options taking precedence, followed by the DNSSEC-Tools configuration file, followed by the keyrec file, followed by defaults. This allows for fine-grained control over the signing process.

The order of precedence for options is as follows:

  1. Command line options
  2. keyrec file
  3. DNSSEC-Tools configuration file
  4. Defaults

When zonesigner is invoked, it attempts to determine the appropriate keys to use for signing the zone. It consults the keyrec file to find the status of existing keys (e.g., current, published, obsolete). If new keys need to be generated or existing keys rolled over, zonesigner can perform these actions based on the provided options.

The process involves generating or selecting keys, signing the zone data with these keys, and updating the keyrec file to reflect the new state of the keys. Obsolete keys are typically archived to prevent them from being used in future signings.

The utility supports various rollover strategies for both Key Signing Keys (KSKs) and Zone Signing Keys (ZSKs), including pre-publish and post-publish methods. It also handles the complexities of RFC5011 KSK revocation.

The -krfile option allows specifying a custom keyrec file, overriding the default behavior of using the keyrec file located in the same directory as the zone file. The keyrec file stores metadata about the keys used for signing a zone, including their status, lifespan, and rollover information.

The precedence rules ensure that specific command-line arguments can override settings in configuration files or the keyrec file for a particular execution of zonesigner. For instance, if a specific KSK length is provided via the -ksklength command-line option, that value will be used, even if a different length is specified in the keyrec file or the DNSSEC-Tools configuration file. This value is then stored back into the keyrec file for subsequent zonesigner executions.

Example

For example, the KSK length has the following values:

-ksklength command line option:     8192
keyrec file:                        1024
DNSSEC-Tools configuration file:     512
zonesigner defaults:                2048

If all are present, then the KSK length will be 8192.

If the -ksklength command line option wasn't given, the KSK length will be 1024.

If the KSK length wasn't given in the configuration file, it will be 8192.

If the KSK length wasn't in the keyrec file or the configuration file, the KSK length will be 8192.

If the -ksklength command line option wasn't given and the KSK length wasn't in the configuration file, it'll be 1024.

If the command line option wasn't given, the KSK length wasn't in the keyrec file, and it wasn't in the configuration file, then the KSK length will be 512.

OPTIONS

Three types of options may be given, based on the command for which they are intended. These commands are dnssec-keygen, dnssec-signzone, and zonesigner.

zonesigner-specific Options

-archivedir
The key archive directory. If a key archive directory hasn't been specified (on the command line or in the DNSSEC-Tools configuration file) and the -nosave option was not given, then zonesigner will leave the keys in the current directory.

When the files are saved into the archive directory, the existing file names are prepended with a timestamp. The timestamp indicates when the files are archived.

This directory may not be the root directory.

-droprevoked
Explicitly obsolete currently revoked KSKs and remove them from the signing set before resigning. This is mutually exclusive from -nodroprevoked. If neither -droprevoked nor -nodroprevoked are given, then -droprevoked functionality is assumed..
-dsdir
Specify a directory for storing dssets. This directory will be created if it does not exist.

The directory must be writable and may not be the root directory.

-genkeys
Generate new KSKs and ZSKs for the zone.
-genksk
Generate new Current KSKs for the zone. Any existing Current KSKs will be marked as obsolete. If this option is not given, the last KSKs generated for this zone will be used.
-genzsk
Generate new ZSKs for the zone. By default, the last ZSKs generated for this zone will be used.
-help
Display a usage message.
-intermediate
Filename to use for the temporary zone file. The zone file will be copied to this file and then the key names appended.
-keydirectory
The directory in which KSK and ZSK keys will be stored. The default is to store the keys in the directory in which zonesigner is executed.

This directory may not be the root directory.

-krfile
keyrec file to use in processing options. See the man page for Net::DNS::SEC::Tools::tooloptions.pm for more details about this file.
-ksignset
The name of the KSK signing set to use. If the signing set does not exist, then this must be used in conjunction with either -genkeys or -genksk. The name may contain alphanumerics, underscores, hyphens, periods, and commas.

The name may contain alphanumerics, underscores, hyphens, periods, and commas. The default signing set name is "zone-signset-N", where zone is the zone being signed and N is a number.

If -ksignset is not specified, then zonesigner will use the default and increment the number for subsequent signing sets.

-kskcount
The number of KSK keys to generate and with which to sign the zone. The default is to use a single KSK key.
-kskdirectory
The directory in which KSK keys will be stored. The default is to store the keys in the directory in which zonesigner is executed.

This directory may not be the root directory.

-ksklife
The time between KSK rollovers. This is measured in seconds.
-newpubksk
Generate new Published KSKs for the zone. Any existing Published KSKs will be marked as obsolete.
-nodroprevoked
Explicitly turn off obsoleting currently revoked KSKs and remove them from the signing set before resigning. This is mutually exclusive from -droprevoked. If neither -droprevoked nor -nodroprevoked are given, then -droprevoked functionality is assumed..
-nokrfile
No keyrec file will be consulted or created.
-norfc5011
Disable RFC5011 KSK revocation when rolling or replacing existing KSK key sets. By default, zonesigner performs RFC5011 KSK revocation and this option supersedes this behavior and any option setting within the keyrec file.
-nosave
Do not save obsolete keys to the key archive directory. The default behavior is to save obsolete keys.
-phase
Specify an rollover option based on the rollover phase, as opposed to using the option naming the specific action to be performed. The purpose of this option is to bring clarity and greater understanding to how zonesigner is used in the rollover process.

The following are the mappings between the -phase options and the action options.

Phase Option             Action-based Option
-phase ksk2              -newpubksk
-phase ksk4              -rollksk
-phase zsk2              -usezskpub
-phase zsk4b             -rollzsk
-phase zsk4b             (no option)

Warning: The -phase option should only be used if you know what you're doing.

-rollksk
Force a rollover of the KSK keys. The Current KSK keys are marked as Obsolete and the Published KSK keys are marked as Current. The zone is then signed with the new set of Current KSK keys. If the zone's keyrec does not list a Current or Published KSK, an error message is printed and zonesigner stops execution.

The zone's keyrec file is updated to show the new key state.

The keyrecs of the KSK keys are adjusted as follows:

The Current KSK keys are marked as Obsolete.
The Published KSK keys are marked as Current.
The Obsolete KSK keys are moved to the archive directory.

If RFC5011 processing is enabled, then the KSK rollover sequence is modified as follows:

The Current KSK keys are marked as Revoked.
The Published KSK keys are marked as Current.
The Revoked KSK keys are checked to see if they are still
within their revocation period.  If not, they are marked
as Obsolete.
The Obsolete KSK keys are moved to the archive directory.

Warning: The timing of key-rolling is critical. Great care must be taken when using this option. In the future, rollerd will automate the KSK rollover process and may be used to safely take care of this aspect of DNSSEC management.

Warning: Using the -rollksk option should only be used if you know what you're doing.

Warning: This is may be a temporary method of KSK rollover. It may be changed in the future.

-rollmgr
The zone's rollover manager. This indicates that the zone is under control of a rollover manager. If a user wishes to sign a zone in the middle of a rollover wait phase, this field helps zonesigner and the rollover manager to determine how best to handle the zone-signing operation.
-rollzsk
Force a rollover of the ZSK keys using the Pre-Publish Key Rollover method. The rollover process adjusts the keys used to sign the specified zone, generates new keys, signs the zone with the appropriate keys, and updates the keyrec file. The Pre-Publish Key Rollover process is described in the DNSSEC Operational Practices document.

Three sets of ZSK keys are used in the rollover process: Current, Published, and New. Current ZSKs are those which are used to sign the zone. Published ZSKs are available in the zone data, and therefore in cached zone data, but are not yet used to sign the zone. New ZSKs are not available in zone data nor yet used to sign the zone, but are waiting in the wings for future use.

The keyrecs of the ZSK keys are adjusted as follows:

The Current ZSK keys are marked as obsolete.
The Published ZSK keys are marked as Current.
The New ZSK keys, if they exist, are marked as Published.
Another set of ZSK keys are generated, which will be
    marked as the New ZSK keys.
The Published ZSK keys' zsklife field is copied to the
    new ZSK keys' keyrecs.
The obsolete ZSK keys are moved to the archive directory.

The quick summary of proper ZSK rolling (which rollerd does for you if you use it):

- wait 2 * max(TTL in zone)
- run zonesigner using -usezskpub
- wait 2 * max(TTL in zone)
- run zonesigner using -rollzsk
- wait 2 * max(TTL in zone)

Warning: The timing of key-rolling is critical. Great

se debe tener cuidado al usar esta opción. rollerd automatiza el proceso de cambio y puede utilizarse para gestionar de forma segura este aspecto de la gestión de DNSSEC. El uso de la opción -rollzsk solo debe utilizarse si sabe lo que está haciendo.

-showkeycmd
Muestra el comando real de generación de claves (con opciones y argumentos) que se ejecuta. Este es un pequeño subconjunto de la salida del nivel 3 de verbosidad.
-showsigncmd
Muestra el comando real de firma de zona (con opciones y argumentos) que se ejecuta. Este es un pequeño subconjunto de la salida del nivel 3 de verbosidad.
-signonly
Firma la zona sin realizar ninguna operación de generación o cambio de claves. Las claves utilizadas en la firma más reciente de la zona por zonesigner serán las claves utilizadas para esta firma.
-signset
El nombre del conjunto de firma ZSK a utilizar como conjunto de firma ZSK Actual. La zona se firma y el conjunto de firma dado se convierte en el nuevo conjunto de firma ZSK Actual de la zona. Si el conjunto de firma no existe, entonces debe utilizarse junto con -genkeys o -genzsk.

El nombre puede contener alfanuméricos, guiones bajos, guiones, puntos y comas. El nombre del conjunto de firma predeterminado es "zonasignset-N", donde zona es la zona que se está firmando y N es un número.

Si no se especifica -signset, entonces zonesigner utilizará el predeterminado e incrementará el número para los conjuntos de firma posteriores.

-threshold
Firma la zona si se cumple una condición de umbral. Dependiendo de cómo se especifique el umbral, puede ser relativo a la última vez que se firmó la zona o a la fecha de caducidad de la zona.

tiempo-umbral es el valor del umbral, dado como un valor numérico, con un especificador de unidad opcional. La unidad puede ser 's', 'm', 'h' o 'd', para segundos, minutos, horas o días. Si no se proporciona la unidad, el valor está en segundos. El valor del umbral debe tener el prefijo '-' o el prefijo '+' para indicar qué umbral medir. El valor del umbral +10d se refiere a diez días antes de la fecha de caducidad de una zona.

Si se utiliza el prefijo '-', la zona se volverá a firmar si zonesigner se ejecuta no más de tiempo-umbral después de la última vez que se firmó la zona. El tiempo-umbral se determina restando el valor del umbral de la medianoche siguiente. Si esto pusiera el tiempo del umbral en el futuro, entonces se calcula a partir del momento actual.

Si se utiliza el prefijo '+', la zona se volverá a firmar si zonesigner se ejecuta no más de tiempo-umbral antes de la fecha de caducidad de la zona. El tiempo-umbral se determina restando el valor del umbral de la medianoche anterior. Si esto pusiera el tiempo-umbral en el pasado, entonces se calcula a partir del momento actual.

-useboth
Utiliza las ZSK actuales y publicadas existentes para firmar la zona.
-usezskpub
Utiliza las ZSK publicadas existentes para firmar la zona.
-Version
Muestra la información de la versión de zonesigner y del paquete DNSSEC-Tools.

-algorithm
Algoritmo criptográfico utilizado para generar las claves de la zona. El valor predeterminado es RSASHA1. El valor de la opción se pasa a dnssec-keygen como el indicador -a. Consulte la página del manual de dnssec-keygen para determinar los valores legales.
-kgopts
Se pueden especificar opciones adicionales para dnssec-keygen utilizando esta opción. Las opciones adicionales se pasan como un único valor de cadena como argumento a la opción -kgopts.
-ksklength
Longitud en bits de la clave KSK de la zona. El valor predeterminado es 2048.
-nsec3optout
Cuando se establecen este indicador y el indicador -usensec3, la zona se firmará utilizando la compatibilidad Opt-Out descrita en RFC5155. Un resumen rápido es que solo se firmarán los subdominios con DS válidos o claves públicas disponibles y el resto no. Esto reduce en gran medida los requisitos computacionales y de memoria de zonas extremadamente grandes con muchos hijos no firmados.

NAME

zonesigner

wrapper around dnssec-signzone and other tools to simplify DNSSEC zone signing

SYNOPSIS

zonesigner [-options] zonename [signedzone]
zonesigner [-options] -krfile keyrec zonename [signedzone]
zonesigner [-options] -intermediate signedzone zonename
zonesigner [-options] -krfile keyrec -intermediate signedzone zonename

DESCRIPTION

zonesigner is a wrapper around dnssec-signzone(8) and other DNSSEC-Tools utilities. Its goal is to simplify the process of signing DNSSEC zones by providing a higher-level interface. It handles the creation of necessary keys (if they don't exist), the signing of the zone, and the creation of DS records.

In addition to signing the zone, zonesigner can also handle the creation of a keyrec file. The keyrec file is a human-readable, object-oriented configuration file that stores information about the zone's keys and signing parameters. It is used by DNSSEC-Tools utilities to manage keys and signing operations.

If a keyrec file is not specified, zonesigner will create one based on the provided options and the zone name. If the signedzone argument is not provided, the signed zone file will be created in the current directory, named after the zone name with the suffix .signed.

The -intermediate option is used to sign an intermediate zone file, typically one that has already been signed by another tool or process. This is useful for scenarios where zones are signed in multiple stages.

QUICK START

To sign a zone named example.com with the signed zone file named db.example.com.signed, and to generate keys if they don't exist:

# zonesigner example.com db.example.com.signed

This command will:

  • Generate a Zone Signing Key (ZSK) and a Key Signing Key (KSK) if they don't already exist.
  • Create a keyrec file named example.com.krf.
  • Sign the zone file example.com (or db.example.com if the former doesn't exist) using the generated keys.
  • Create the signed zone file db.example.com.signed.
  • Generate DS records for the zone.

To sign a zone using an existing keyrec file:

# zonesigner -krfile example.com.krf example.com db.example.com.signed

USING ZONESIGNER

zonesigner accepts a number of options that are passed to the underlying DNSSEC-Tools utilities, such as dnssec-signzone(8), dnssec-keygen(8), and named-checkzone(8). These options allow fine-grained control over the signing process.

General Options

-d directory
Sets the directory in which keys and other signing-related files are stored. Defaults to the current directory.
-f file
Specifies the zone file to be signed. If not specified, zonesigner will look for a file named after the zonename argument.
-g
Generates DS records for the zone. This is the default behavior.
-g keytype
Generates keys of the specified keytype. Valid keytypes are all, ksk, and zsk. Defaults to all.
-i
Signs the zone using the intermediate zone file specified as the signedzone argument. This option is mutually exclusive with providing a standard signedzone argument.
-k file
Specifies the key record file (keyrec) to be used for signing. If not specified, zonesigner will attempt to create one or use default key generation parameters.
-l lifetime
Sets the default key lifetime in seconds. The default is 15768000 seconds (approximately 6 months).
-n name
Specifies the DNSSEC signing algorithm to be used. Defaults to rsasha1.
-r source
Source of randomness used to generate the zone's keys. This is assumed to be a file, for example /dev/urandom.
-u
Signs the zone using NSEC3 (see RFC5155) proof-of-non-existence records rather than NSEC records. The keys used to sign the zone must support the use of NSEC3 or else zone-signing will fail. Zonesigner will automatically generate new keys of the correct type if one of the -genkeys or similar options is used.
-z length
Bit length of the zone's ZSK key. The default is 1024.

dnssec-signzone-specific Options

-endtime
Time that the zone expires, as measured from the current time. If given as a number, it is a count of seconds. If it is given as a number followed by 's', 'm', 'h', or 'd', then it is the number of seconds, minutes, hours, or days. The default value is 2764800 seconds (32 days.)
-gends
Force dnssec-signzone to generate DS records for the zone. This option is translated into -g when passed to dnssec-signzone.

This option is obsolete. DS records are generated by default. Use the -nogends option if DS records should not be generated.

-ksdir
Specify a directory for storing keysets. This is passed to dnssec-signzone as the -d option.
-nogends
Prevent dnssec-signzone from generating DS records for the zone.
-szopts
Additional options for dnssec-signzone may be specified using this option. The additional options are passed as a single string value as an argument to the -szopts option.

The default value for this option is "-i local", set in defaults.pm. This value has been found to greatly improve the amount of time it takes named-checkzone to run.

Other Options

-zcopts
Additional options for named-checkzone may be specified using this option. The additional options are passed as a single string value as an argument to the -zcopts option.
