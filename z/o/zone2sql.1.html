ZONE2SQL(1) Servidor Autoritativo de PowerDNS ZONE2SQL(1)

NOMBRE

zone2sql - convertir zonas BIND a SQL

SINOPSIS

zone2sql {--named-conf=RUTA,--zone-file=RUTA [--zone-name=NOMBRE]} [Opciones]

DESCRIPCIÓN

zone2sql analiza los archivos de configuración named.conf y los archivos de zona de BIND y genera SQL en la salida estándar, que luego puede ser introducido en su base de datos.

zone2sql entiende la extensión de archivo maestro de BIND $GENERATE y también respetará $ORIGIN y $TTL.

Para backends que admiten operación secundaria, también existe una opción para mantener las zonas secundarias como secundarias, y no convertirlas a operación nativa.

zone2sql puede generar SQL para los backends genéricos MySQL, PostgreSQL y SQLite3.

OPCIONES

OPCIONES DE ENTRADA

--named-conf=<RUTA>
Lee RUTA para obtener la configuración de BIND
--zone-file=<RUTA>
Analiza solo el archivo de zona en RUTA. Conflicta con el parámetro --named-conf.
--zone-name=<NOMBRE>
Al analizar una única zona sin una declaración $ORIGIN, establece ZONA como el nombre de la zona.

BACKENDS

--gmysql
Genera la salida en un formato adecuado para la configuración por defecto del backend genérico MySQL.
--gpgsql
Genera la salida en un formato adecuado para la configuración por defecto del backend genérico PostgreSQL.
--gsqlite3
Genera la salida en un formato adecuado para la configuración por defecto del backend genérico SQLite3.

OPCIONES DE SALIDA

--json-comments
Analiza JSON en los comentarios de los archivos de zona para establecer los campos 'disabled' y 'comment' en la base de datos. Consulte COMENTARIOS JSON para más información.
--transactions
Si el backend SQL de destino admite transacciones, envuelve cada dominio en una transacción para garantizar la integridad y posiblemente una mayor velocidad.

OTRAS OPCIONES

--delete-matching-domains
Añade una sentencia de eliminación a la salida SQL para permitir la reimportación de zonas. Principalmente útil durante las pruebas. Dado que esto solo eliminará el dominio, pero no sus registros, debería tener la relación de clave externa opcional habilitada en su esquema para evitar dejar registros huérfanos.
--filter-duplicate-soa
Si hay más de un registro SOA en la zona (posiblemente porque fue AXFR'd), ignórelo. Si esta opción no está establecida, se emiten todos los registros SOA de la zona.
--help
Lista todas las opciones
--on-error-resume-next
Ignora los archivos de zona faltantes durante el análisis. Peligroso.
--secondary
Mantiene el estado secundario de las zonas listadas en named.conf como esclavas. El comportamiento por defecto es convertir todas las zonas a operación nativa.
--verbose
Sea detallado durante la conversión.

COMENTARIOS JSON

Los backends SQL genéricos tienen los campos 'comment' y 'disabled' en la tabla 'records'. El campo 'comment' contiene un comentario para este registro (si lo hay) y el campo 'disabled' indica a PowerDNS si el registro puede ser servido a los clientes.

Cuando un archivo de zona contiene un comentario como ; json={"comment": "Algo", "disabled": true} y se proporciona --json-comments, el campo 'comment' contendrá "Algo" y el campo 'disabled' se establecerá al valor verdadero nativo de la base de datos.

ADVERTENCIA: Usar comentarios JSON para deshabilitar registros significa que la zona en PowerDNS es diferente de la que sirve BIND, ya que BIND no maneja el estado deshabilitado en el comentario.
