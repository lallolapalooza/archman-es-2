NOMBRE

zerotier-one - Servicio de punto final de red virtual ZeroTier

SINOPSIS

zerotier-one [-opciones] [directorio de trabajo]

DESCRIPCIÓN

zerotier-one es el servicio/demonio responsable de conectar un sistema Unix (Linux/BSD/OSX) a una o más redes virtuales ZeroTier y presentar esas redes al sistema como puertos de red virtuales. Puedes pensar en él como un cliente VPN peer-to-peer.

Normalmente es ejecutado por sistemas de inicio como systemd (Linux) o launchd (Mac) en lugar de directamente por el usuario, y debe ejecutarse como root a menos que le proporciones el interruptor -U y no planees unirte a redes (por ejemplo, para ejecutar solo un microservicio de controlador de red).

El servicio zerotier-one guarda su estado y otros archivos en un directorio de trabajo. Si este directorio no se especifica al iniciar, por defecto es "/var/lib/zerotier-one" en Linux, "/Library/Application Support/ZeroTier/One" en Mac, y "/var/db/zerotier-one" en FreeBSD y otros BSD similares. El directorio de trabajo debe persistir. No debe ser limpiado automáticamente por demonios de limpieza del sistema ni almacenarse en una ubicación volátil. La pérdida de su archivo identity.secret resulta en la pérdida de la dirección ZeroTier única de 10 dígitos de este sistema y su clave.

Se pueden ejecutar múltiples instancias de zerotier-one en el mismo sistema siempre que se ejecuten con puertos primarios diferentes (ver opciones) y un directorio de trabajo diferente. Pero dado que un solo servicio puede unirse a cualquier número de redes, normalmente no tiene sentido hacer esto.

El servicio zerotier-one se controla a través de una API JSON disponible en 127.0.0.1:<puerto primario>, siendo el puerto primario por defecto 9993. El acceso a esta API requiere un token de autorización que normalmente se encuentra en el archivo authtoken.secret en el directorio de trabajo del servicio. En algunas plataformas, el acceso puede estar protegido por otras medidas como la búsqueda de UID/GID del par del socket si se habilitan opciones de seguridad adicionales (esto no es lo predeterminado).

La primera vez que se inicia el servicio en un directorio de trabajo nuevo, genera una identidad ZeroTier. En sistemas lentos, este proceso puede tardar diez segundos o más debido a una función de prueba de trabajo anti-DDOS/anti-falsificación utilizada por ZeroTier en la generación de direcciones. Esto solo ocurre una vez, y una vez generado, el resultado se guarda en identity.secret en el directorio de trabajo. Este archivo representa y define/reclama tu dirección ZeroTier y el par de claves ECC-256 asociado.

OPCIONES

  • -h: Muestra la ayuda.
  • -v: Muestra la versión de ZeroTier One.
  • -U: Omite la verificación de privilegios y permite que sea ejecutado por un usuario no privilegiado. Esto se usa típicamente cuando zerotier-one se compila con la opción del controlador de red incluida. En este caso, el servicio ZeroTier podría actuar solo como un controlador de red y podría no unirse nunca a redes, en cuyo caso no requiere permisos elevados del sistema.
  • -p<puerto>: Especifica un puerto primario diferente. Si no se proporciona, el valor predeterminado es 9993. Si se proporciona cero, se elige un puerto aleatorio cada vez.
  • -d: Crea un proceso hijo y se ejecuta como demonio.
  • -i: Invoca la personalidad de zerotier-idtool, en cuyo caso el binario se comporta como zerotier-idtool(1). Esto ocurre automáticamente si el nombre del binario (o un enlace simbólico a él) es zerotier-idtool.
  • -q: Invoca la personalidad de zerotier-cli, en cuyo caso el binario se comporta como zerotier-cli(1). Esto ocurre automáticamente si el nombre del binario (o un enlace simbólico a él) es zerotier-cli.

EJEMPLOS

Ejecutar como demonio con el directorio de trabajo predeterminado del SO y el puerto predeterminado:

$ sudo zerotier-one -d

Ejecutar como demonio con un directorio de trabajo y puerto diferentes:

$ sudo zerotier-one -d -p12345 /tmp/zerotier-working-directory-test

ARCHIVOS

Estos se encuentran en el directorio de trabajo del servicio.

  • identity.public: La parte pública de tu identidad ZeroTier, que es tu dirección hexadecimal de 10 dígitos y la clave pública asociada.
  • identity.secret: Tu identidad ZeroTier completa, incluida su clave privada. Este archivo identifica el sistema en la red, lo que significa que puedes mover una dirección ZeroTier copiando este archivo y deberías hacer una copia de seguridad de este archivo si quieres guardar la dirección ZeroTier estática de tu sistema. Este archivo debe estar protegido, ya que el robo de su clave secreta permitirá a cualquiera suplantar tu dispositivo en cualquier red y descifrar el tráfico. Para los controladores de red, este archivo es particularmente sensible ya que constituye la clave privada de una autoridad de certificación para las redes del controlador.
  • authtoken.secret: El token secreto utilizado para autenticar las solicitudes a la API JSON local del servicio. Si no existe, se genera a partir de una fuente aleatoria segura al iniciar el servicio. Para usarlo, envíalo en la cabecera "X-ZT1-Auth" con las solicitudes HTTP a 127.0.0.1:<puerto primario>.
  • devicemap: Recuerda los mapeos de los números de interfaz zt# a las redes ZeroTier para que persistan entre reinicios. En algunos sistemas que admiten nombres de interfaz más largos que pueden codificar el ID de red (como FreeBSD), este archivo puede no estar presente.
  • zerotier-one.pid: El PID de ZeroTier. Este archivo se elimina en el apagado normal.
  • zerotier-one.port: El puerto primario de ZeroTier, que también es donde se encuentra su API JSON en 127.0.0.1:<este puerto>. Este archivo se crea al iniciar y es leído por zerotier-cli(1) para determinar dónde encontrar la API de control.
  • controller.db: Si el servicio ZeroTier One se compila con el controlador de red habilitado, este archivo contiene la base de datos SQLite3 del controlador.
  • controller.db.backup: Si el servicio ZeroTier One se compila con el controlador de red habilitado, hace copias de seguridad periódicas de su base de datos controller.db en este archivo (actualmente cada 5 minutos si ha habido cambios). Dado que este archivo no es una base de datos SQLite3 en uso actualmente, es más seguro hacer una copia de seguridad sin corrupción. En las copias de seguridad nuevas, el archivo se rota en lugar de sobrescribirse en su lugar.
  • iddb.d/ (directorio): Almacena en caché la identidad pública de cada par con el que ZeroTier ha hablado en los últimos 60 días. Este directorio y su contenido pueden ser eliminados, pero esto puede resultar en inicios de conexión más lentos ya que requerirá que obtengamos y recuperemos identidades completas para los pares con los que estamos hablando.
  • networks.d (directorio): Almacena en caché configuraciones de red e información de certificados para las redes a las que perteneces. ZeroTier escanea este directorio en busca de archivos <network ID>.conf al iniciar para recordar sus redes, por lo que "tocar" un archivo <network ID>.conf vacío en este directorio es una forma de preconfigurar ZeroTier para unirse a una red específica al iniciar sin usar la API. Si el archivo de configuración está vacío, ZeroTIer simplemente lo obtendrá del controlador de la red.
