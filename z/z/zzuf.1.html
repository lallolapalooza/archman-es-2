EJEMPLOS

Fuzzing simple commands like cat:

zzuf -P '\n' -R '\x00-\x1f\x7f-\xff' cat /etc/motd

Fuzz la entrada del programa convert, usando el archivo foo.jpeg como entrada original y excluyendo archivos .xml del fuzzing (porque convert también abrirá sus propios archivos de configuración XML y no queremos que zzuf los modifique):

zzuf -E '\.xml$' convert foo.jpeg -format tga /dev/null

Fuzz la entrada de VLC, usando el archivo movie.avi como entrada original y restringiendo el fuzzing a nombres de archivo que aparecen en la línea de comandos (-c), luego genera fuzzy-movie.avi, que es un archivo que puede ser leído por VLC para reproducir el mismo comportamiento sin usar zzuf:

zzuf -c -s87423 -r0.01 vlc movie.avi
zzuf -c -s87423 -r0.01 <movie.avi >fuzzy-movie.avi
vlc fuzzy-movie.avi

Fuzz entre el 0.1% y el 2% de los bits de entrada de MPlayer (-r0.001:0.02) con semillas de 0 a 9999 (-s0:10000), preservando la cabecera de 4 bytes de AVI al restringir el fuzzing a desplazamientos posteriores a 4 (-b4-), deshabilitando sus mensajes de salida estándar (-q), lanzando hasta cinco procesos hijos simultáneos (-j5) pero esperando al menos medio segundo entre lanzamientos (-D0.5), matando MPlayer si tarda más de un minuto en leer el archivo (-T60) y deshabilitando su manejador de señal SIGSEGV (-S):

zzuf -c -r0.001:0.02 -s0:10000 -b4- -q -j5 -D0.5 -T60 -S \
mplayer -benchmark -vo null -fps 1000 movie.avi

Un ejemplo de fuzzing más avanzado para VLC, deteniéndose solo en el primer fallo:

zzuf -j4 -vqc -r0.000001:0.01 -s0: vlc -v -I dummy movie.avi \
--sout '#transcode{acodec=s16l,vcodec=I420}:dummy' vlc:quit

Crear un archivo similar a HTML que carga 200 veces la misma imagen hello.jpg y abrirlo en Firefox™ en modo de autoincremento (-A):

seq -f '<img src="hello.jpg#%g">' 1 200 > hello.html
(o: jot -w '<img src="hello.jpg#%d">' 200 1 > hello.html)
zzuf -A -I 'hello[.]jpg' -r0.001 firefox hello.html

Ejecutar un redireccionador HTTP simple en el host local usando socat y corromper cada conexión de red (-n) de una manera diferente (-A) después de que se hayan recibido un megabyte de datos en ella (-b1000000-):

zzuf -n -A -b1000000- \ socat TCP4-LISTEN:8080,reuseaddr,fork TCP4:192.168.1.42:80

Navegar por la intarweb (-n) usando Firefox™ sin modificar archivos locales (-E.) ni conexiones no HTTP (-p80,8010,8080), preservando el inicio de los datos enviados con cada respuesta HTTP (-b4000-) y usando una semilla diferente en cada conexión (-A):

zzuf -r 0.0001 -n -E. -p80,8010,8080 -b4000- -A firefox

RESTRICCIONES

Debido a que zzuf utiliza la precarga de objetos compartidos (LD_PRELOAD, _RLD_LIST, DYLD_INSERT_LIBRARIES, etc.) para ejecutar sus procesos hijos, fallará en presencia de cualquier mecanismo que deshabilite la precarga. Por ejemplo, los binarios setuid root no serán modificados cuando se ejecuten como un usuario no privilegiado.

Por las mismas razones, zzuf tampoco funcionará con binarios enlazados estáticamente. Tenga esto en cuenta al usar zzuf en la plataforma OpenBSD, donde cat, cp y dd son binarios estáticos.

Aunque se hacen grandes esfuerzos, no se garantiza un comportamiento idéntico para diferentes versiones de zzuf. La reproducibilidad para llamadas subsiguientes en diferentes sistemas operativos y con diferentes programas de destino solo está garantizada cuando se utiliza la misma versión de zzuf.

ERRORES

zzuf probablemente no se comporta correctamente con desplazamientos de 64 bits.

Aún no es posible insertar o eliminar bytes de la entrada, hacer fuzzing según el formato del archivo, intercambiar bytes, etc. Se planean métodos de fuzzing más avanzados.

Por ahora, zzuf no soporta realmente aplicaciones multihilo. El comportamiento con aplicaciones multihilo donde más de un hilo realiza operaciones de descriptor de archivo no está definido.

HISTORIA

zzuf comenzó su vida en 2002 como la herramienta streamfucker, un pequeño corruptor de flujos multimedia utilizado para encontrar errores en el reproductor de medios VLC.
