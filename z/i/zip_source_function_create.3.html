ZIP_SOURCE_FUNCTION(3) Manual de funciones de la biblioteca ZIP_SOURCE_FUNCTION(3)

NOMBRE

zip_source_function, zip_source_function_create — crear fuente de datos a partir de una función

BIBLIOTECA

libzip (-lzip)

SINOPSIS

#include <zip.h>

zip_source_t *
zip_source_function(zip_t *archive, zip_source_callback fn, void *userdata);

zip_source_t *
zip_source_function_create(zip_source_callback fn, void *userdata, zip_error_t *error);

DESCRIPCIÓN

Las funciones zip_source_function() y zip_source_function_create() crean una fuente zip a partir de la función proporcionada por el usuario fn, que debe ser del siguiente tipo:

typedef zip_int64_t (*zip_source_callback)(void *userdata, void *data, zip_uint64_t len, zip_source_cmd_t cmd);

archive o error se utilizan para informar de errores y pueden ser NULL.

Cuando es llamada por la biblioteca, el primer argumento es el argumento userdata suministrado a la función. Los dos siguientes argumentos son un buffer data de tamaño len cuando se pasan datos o se espera recibirlos, o bien NULL y 0. El último argumento, cmd, especifica qué acción debe realizar la función.

Dependiendo de los usos, existen tres conjuntos útiles de comandos que deben ser soportados por un zip_source_callback():

fuente de lectura
Proporciona datos en streaming (para datos de archivo añadidos a archivos). Debe soportar ZIP_SOURCE_OPEN, ZIP_SOURCE_READ, ZIP_SOURCE_CLOSE, ZIP_SOURCE_STAT, y ZIP_SOURCE_ERROR.

Si su fuente utiliza memoria asignada (incluido userdata), también debería implementar ZIP_SOURCE_FREE para evitar fugas de memoria.

fuente de lectura buscable
Igual que la anterior, pero desde una fuente que permite leer desde offsets arbitrarios (también para archivo zip de solo lectura). Debe además soportar ZIP_SOURCE_SEEK, ZIP_SOURCE_TELL, y ZIP_SOURCE_SUPPORTS.
fuente de lectura/escritura
Igual que la anterior, pero permitiendo además la escritura (también para archivos zip escribibles). Debe además soportar ZIP_SOURCE_BEGIN_WRITE, ZIP_SOURCE_COMMIT_WRITE, ZIP_SOURCE_ROLLBACK_WRITE, ZIP_SOURCE_SEEK_WRITE, ZIP_SOURCE_TELL_WRITE, y ZIP_SOURCE_REMOVE.

Además de lo anterior, soportar el pseudo-comando ZIP_SOURCE_SUPPORTS_REOPEN permite llamar a zip_source_open() de nuevo después de llamar a zip_source_close().

ZIP_SOURCE_ACCEPT_EMPTY

Devuelve 1 si se debe aceptar una fuente vacía como un archivo zip válido. Este es el valor predeterminado si esta función no es soportada por una fuente. Las fuentes basadas en el sistema de archivos deben devolver 0.

ZIP_SOURCE_BEGIN_WRITE

Prepara la fuente para escribir. Utilice esto para crear archivos temporales.

ZIP_SOURCE_BEGIN_WRITE_CLONING

Prepara la fuente para escribir, manteniendo los primeros len bytes del archivo original. Solo implemente esta función si es más eficiente que copiar los datos, y si no sobrescribe destructivamente el archivo original (aún debe poder ejecutar ZIP_SOURCE_ROLLBACK_WRITE).

La siguiente escritura debe ocurrir en el byte offset.

ZIP_SOURCE_CLOSE

La lectura ha finalizado.

ZIP_SOURCE_COMMIT_WRITE

Finaliza la escritura en la fuente. Reemplaza los datos originales con los datos recién escritos. Limpia archivos temporales o buffers internos. Posteriormente, abrir y leer de la fuente debería devolver los datos recién escritos.

ZIP_SOURCE_ERROR

Obtiene información de error. data apunta a un array de dos enteros, que deben ser rellenados con el código de error de libzip y el código de error del sistema correspondiente al error ocurrido. Consulte zip_errors(3) para obtener detalles sobre los códigos de error. Si la fuente almacena información de error en un zip_error_t, utilice zip_error_to_data(3) y devuelva su valor de retorno. De lo contrario, devuelva 2 * sizeof(int).

ZIP_SOURCE_FREE

Limpia y libera todos los recursos, incluido userdata. La función de callback no volverá a ser llamada.

ZIP_SOURCE_GET_FILE_ATTRIBUTES

Proporciona información sobre varios datos. Luego, los datos deben colocarse en la entrada apropiada de la estructura zip_file_attributes_t proporcionada, y el valor apropiado de ZIP_FILE_ATTRIBUTES_* debe ser aplicado mediante OR bit a bit al miembro valid para indicar que los datos correspondientes han sido proporcionados. Una estructura zip_file_attributes_t puede inicializarse usando zip_file_attributes_init(3).

Modo ASCII
Si un archivo es un archivo de texto plano en ASCII. Puede ser utilizado por herramientas de extracción para convertir automáticamente los finales de línea (parte de los atributos internos del archivo). Miembro ascii, flag ZIP_FILE_ATTRIBUTES_ASCII.
Marcas de Bits de Propósito General (limitado a Marcas de Compresión)
La marca de bits de propósito general en el encabezado de directorio local y central de zip contiene información sobre el método de compresión. Miembro general_purpose_bi

NAME

zip_source_function, zip_source_function_create — create zip source from a function

LIBRARY

libzip, -lzip

SYNOPSIS

#include <zip.h>

typedef int (*zip_source_callback_t)(zip_error_t *, void *, void *, zip_source_cmd_t);

zip_source_t *zip_source_function_create(zip_error_t *error, zip_source_callback_t callback, void *userdata);

zip_source_t *zip_source_function(zip_t *za, zip_error_t *error, zip_source_callback_t callback, void *userdata);

DESCRIPTION

The function zip_source_function_create() creates a zip source that reads data from and writes data to the given callback function. The userdata is passed to the callback for each command.

The function zip_source_function() is provided for backward compatibility. It is equivalent to calling zip_source_function_create() and then adding the returned source to the zip archive za. The error argument is used to return an error if the source cannot be added to the archive.

The callback function callback is called by libzip with different commands specified by cmd. The arguments data and len depend on the command.

The source is implemented by the callback function. See zip_source(5) for a list of commands.

Example implementations of zip sources can be found in zip_source_file(3), zip_source_buffer(3), and zip_source_iovec(3).

ZIP_SOURCE_ACCEPT_EMPTY

If the source is empty, accept it. This is for sources that support writing and will be empty after writing.

ZIP_SOURCE_BEGIN_WRITE

Prepare for writing. The source might be cloned if it's used for multiple entries.

ZIP_SOURCE_BEGIN_WRITE_CLONING

Prepare for writing and cloning. The source needs to be able to provide the same data multiple times.

ZIP_SOURCE_CLOSE

Release resources obtained by ZIP_SOURCE_OPEN.

ZIP_SOURCE_COMMIT_WRITE

Commit writing to the source. Make written data available for reading.

ZIP_SOURCE_CONCAT

Concatenate two sources. The first source is data, the second source is specified by the second argument of type zip_source_t *. The command returns the new concatenated source.

ZIP_SOURCE_ERROR

Retrieve the last error code. data points to a zip_error_t struct which will be filled.

ZIP_SOURCE_FILE_ATTRIBUTES

Fill in file attributes. data points to a struct zip_file_attributes. See zip_file_attributes_init(3).

General Purpose Bit Mask
A bit mask indicating which members of the struct zip_file_attributes have been set. Member t_flags and general_purpose_bit_mask to denote which members have been set; flag ZIP_FILE_ATTRIBUTES_GENERAL_PURPOSE_BIT_FLAGS.
External File Attributes
The external file attributes (usually operating system-specific). Member external_file_attributes, flag ZIP_FILE_ATTRIBUTES_EXTERNAL_FILE_ATTRIBUTES.
Version Needed
A minimum version needed required to unpack this entry (in the usual "major * 10 + minor" format). Member version_needed, flag ZIP_FILE_ATTRIBUTES_VERSION_NEEDED.
Operating System
One of the operating systems as defined by the ZIP_OPSYS_* variables (see zip.h). This value affects the interpretation of the external file attributes. Member host_system, flag ZIP_FILE_ATTRIBUTES_HOST_SYSTEM.

ZIP_SOURCE_OPEN

Prepare for reading.

ZIP_SOURCE_READ

Read data into the buffer data of size len. Return the number of bytes placed into data on success, and zero for end-of-file.

ZIP_SOURCE_REMOVE

Remove the underlying file. This is called if a zip archive is empty when closed.

ZIP_SOURCE_ROLLBACK_WRITE

Abort writing to the source. Discard written data. Clean up temporary files or internal buffers. Subsequently opening and reading from the source should return the original data.

ZIP_SOURCE_SEEK

Specify position to read next byte from, like fseek(3). Use ZIP_SOURCE_GET_ARGS(3) to decode the arguments into the following struct:

struct zip_source_args_seek {
    zip_int64_t offset;
    int whence;
};

If the size of the source's data is known, use zip_source_seek_compute_offset(3) to validate the arguments and compute the new offset.

ZIP_SOURCE_SEEK_WRITE

Specify position to write next byte to, like fseek(3). See ZIP_SOURCE_SEEK for details.

ZIP_SOURCE_STAT

Get meta information for the input data. data points to an allocated struct zip_stat, which should be initialized using zip_stat_init(3) and then filled in.

For uncompressed, unencrypted data, all information is optional. However, fill in as much information as is readily available.

If the data is compressed, ZIP_STAT_COMP_METHOD, ZIP_STAT_SIZE, and ZIP_STAT_CRC must be filled in.

If the data is encrypted, ZIP_STAT_ENCRYPTION_METHOD, ZIP_STAT_COMP_METHOD, ZIP_STAT_SIZE, and ZIP_STAT_CRC must be filled in.

Information only available after the source has been read (e.g., size) can be omitted in an earlier call. NOTE: zip_source_function() may be called with this argument even after being called with ZIP_SOURCE_CLOSE.

Return sizeof(struct zip_stat) on success.

ZIP_SOURCE_SUPPORTS

Return bitmap specifying which commands are supported. Use zip_source_make_command_bitmap(3). If this command is not implemented, the source is assumed to be a read source without seek support.

ZIP_SOURCE_TELL

Return the current read offset in the source, like ftell(3).

ZIP_SOURCE_TELL_WRITE

Return the current write offset in the source, like ftell(3).

ZIP_SOURCE_WRITE

Write data to the source. Return number of bytes written.

ZIP_SOURCE_SUPPORTS_REOPEN

This command is never actually invoked, support for it signals the ability to handle multiple open/read/close cycles.

Return Values

Commands should return -1 on error. ZIP_SOURCE_ERROR will be called to retrieve the error code. On success, commands return 0, unless specified otherwise in the description above.

Calling Conventions

The library will always issue ZIP_SOURCE_OPEN before issuing ZIP_SOURCE_READ, ZIP_SOURCE_SEEK, or ZIP_SOURCE_TELL. When it no longer wishes to read from this source, it will issue ZIP_SOURCE_CLOSE. If the library wishes to read the data again, it will issue ZIP_SOURCE_OPEN a second time. If the function is unable to provide the data again, it should return -1.

ZIP_SOURCE_BEGIN_WRITE or ZIP_SOURCE_BEGIN_WRITE_CLONING will be called before ZIP_SOURCE_WRITE, ZIP_SOURCE_SEEK_WRITE, or ZIP_SOURCE_TELL_WRITE. When writing is complete, either ZIP_SOURCE_COMMIT_WRITE or ZIP_SOURCE_ROLLBACK_WRITE will be called.

ZIP_SOURCE_ACCEPT_EMPTY, ZIP_SOURCE_GET_FILE_ATTRIBUTES, and ZIP_SOURCE_STAT can be issued at any time.

ZIP_SOURCE_ERROR will only be issued in response to the function returning -1.

ZIP_SOURCE_FREE will be the last command issued; if ZIP_SOURCE_OPEN was called and succeeded, ZIP_SOURCE_CLOSE will be called before ZIP_SOURCE_FREE, and similarly for ZIP_SOURCE_BEGIN_WRITE or ZIP_SOURCE_BEGIN_WRITE_CLONING and ZIP_SOURCE_COMMIT_WRITE or ZIP_SOURCE_ROLLBACK_WRITE.

RETURN VALUES

Upon successful completion, the created source is returned. Otherwise, NULL is returned and the error code in archive or error is set to indicate the error (unless it is NULL).

ERRORS

zip_source_function() fails if:

[ZIP_ER_MEMORY]
Required memory could not be allocated.
