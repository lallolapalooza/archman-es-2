ZINT(1) Manual de Comandos Generales ZINT(1)

NOMBRE

zint - codifica datos como una imagen de código de barras

SINOPSIS

zint [-h | --help]

zint [opciones]

DESCRIPCIÓN

zint toma datos de entrada desde la línea de comandos o un archivo para codificarlos en un código de barras, que luego se exporta a un archivo de imagen.

Los datos de entrada son UTF-8, a menos que se especifique --binary.

El Texto Legible por Humanos (HRT) se muestra por defecto para aquellos códigos de barras que lo soportan, a menos que se especifique --notext.

El archivo de imagen de salida (especificado con -o | --output) puede estar en uno de los siguientes formatos: Windows Bitmap (BMP), Enhanced Metafile Format (EMF), Encapsulated PostScript (EPS), Graphics Interchange Format (GIF), ZSoft Paintbrush (PCX), Portable Network Format (PNG), Scalable Vector Graphic (SVG), o Tagged Image File Format (TIF).

OPCIONES

-h, --help
Muestra información de uso resumiendo las opciones de la línea de comandos.
-b TIPO, --barcode=TIPO
Establece la simbología del código de barras que se utilizará para codificar los datos. TIPO es el número o nombre de la simbología del código de barras. Si no se especifica, la simbología por defecto es 20 (Code 128). Para ver los tipos disponibles, usa la opción -t | --types. Los nombres de tipo no distinguen mayúsculas y minúsculas, y los caracteres no alfanuméricos se ignoran.
--addongap=INTEGER
Para las simbologías EAN/UPC, establece el espacio entre los datos principales y el complemento. INTEGER se mide en múltiplos enteros de la dimensión X. El espacio máximo que se puede establecer es 12. El mínimo es 7, excepto para UPC-A, donde el mínimo es 9.
--batch
Trata cada línea de un archivo de entrada especificado con -i | --input como un conjunto de datos separado y produce una imagen de código de barras para cada uno. Las imágenes de código de barras se exportan por defecto a archivos con nombres numerados empezando por “00001.png”, “00002.png”, etc., lo cual puede cambiarse usando la opción -o | --output.
--bg=COLOUR
Especifica un color de fondo (papel) donde COLOUR está en formato hexadecimal RRGGBB o RRGGBBAA o en formato de porcentajes decimales C,M,Y,K.
--binary
Trata los datos de entrada como datos binarios brutos de 8 bits en lugar del UTF-8 por defecto. La traducción automática de la página de códigos a una página ECI se deshabilita, y no se realiza ninguna validación de la codificación de caracteres de los datos.
--bind
Añade barras de límite horizontales (también conocidas como barras portadoras) al símbolo. El ancho de las barras de límite se especifica con la opción --border. --bind también puede usarse para añadir barras separadoras de fila a símbolos apilados con múltiples entradas -d | --data, en cuyo caso el ancho de las barras separadoras se especifica con la opción --separator.
--bindtop
Añade una barra de límite horizontal a la parte superior del símbolo. El ancho de la barra de límite se especifica con la opción --border.
--bold
Usa una fuente en negrita para el Texto Legible por Humanos (HRT).
--border=INTEGER
Establece el ancho de las barras de límite (--bind o --bindtop) o los bordes de la caja (--box), donde INTEGER se mide en múltiplos enteros de la dimensión X. El valor por defecto es cero.
--box
Añade una caja alrededor del símbolo. El ancho de los bordes se especifica con la opción --border.
--cmyk
Usa el espacio de color CMYK al exportar a archivos Encapsulated PostScript (EPS) o TIF.
--cols=INTEGER
Establece el número de columnas de datos en el símbolo a INTEGER. Afecta a los símbolos Codablock-F, DotCode, GS1 DataBar Expanded Stacked (DBAR_EXPSTK), MicroPDF417 y PDF417.
--compliantheight
Advierte si la altura especificada por la opción --height no cumple con la especificación del código de barras, o si --height no se proporciona, usa por defecto la altura especificada por la especificación (si existe).
-d, --data=DATOS
Especifica los DATOS de entrada a codificar. La opción --esc puede usarse para introducir caracteres no imprimibles usando secuencias de escape. Los DATOS deben ser UTF-8, a menos que se proporcione la opción --binary, en cuyo caso pueden ser cualquier cosa.
--direct
Envía la salida a stdout, que en la mayoría de los casos debería ser redirigida a una tubería o a un archivo. Usa --filetype para especificar el formato de salida.
--dmiso144
Para los símbolos Data Matrix, usa la colocación de codewords estándar ISO/IEC para símbolos de 144 x 144 (--vers=24), en lugar de la colocación por defecto “de facto” (que rota la colocación de los codewords ECC).
--dmre
Para los símbolos Data Matrix, permite tamaños de Data Matrix Rectangular Extended (DMRE) al considerar tamaños automáticos. Ver también --square.
--dotsize=NUMBER
Establece el radio de los puntos en modo punteado (--dotty). NUMBER está en dimensiones X, y puede ser de punto flotante. El valor por defecto es 0.8.
--dotty
Usa puntos en lugar de cuadrados para los símbolos matriciales. DotCode está siempre en modo punteado.
--dump
Exporta una representación hexadecimal de la codificación del símbolo a stdout. La misma representación puede ser exportada a un archivo usando una extensión .txt con -o | --output o especificando --filetype=txt.
-e, --ecinos
Muestra la tabla de ECIs (Extended Channel Interpretations).
--eci=INTEGER
Establece el código ECI de los datos de entrada a INTEGER. Ver -e | --ecinos para una lista de los ECI disponibles. Los ECI son compatibles con Aztec Code, Code One, Data Matrix, DotCode, Grid Matrix, Han Xin Code, MaxiCode, MicroPDF417, PDF417, QR Code, rMQR y Ultracode.
--embedfont
Para la salida vectorial, incrusta la fuente en el archivo para portabilidad. Actualmente solo disponible para salida SVG.
--esc
Procesa caracteres de escape en los datos de entrada. Las secuencias de escape son:

--segN=ECI,DATOS
Establece el contenido ECI y DATOS para el segmento N, donde N es del 1 al 9. -d | --data todavía debe proporcionarse y cuenta como segmento 0, su ECI dado por --eci. Los segmentos deben ser consecutivos.
--separator=ENTEROS
Establece la altura de las barras separadoras de fila para simbologías apiladas, donde ENTEROS está en múltiplos integrales de la dimensión X. El valor predeterminado es cero.
--small
Usa una fuente más pequeña para el Texto Legible por Humanos (HRT).
--square
Para símbolos Data Matrix, excluye tamaños rectangulares al considerar tamaños automáticos. Ver también --dmre.
--structapp=I,C[,ID]
Establece la información de Structured Append, donde I es el índice basado en 1, C es el número total de símbolos en la secuencia, y ID, que es opcional, es el identificador que comparten todos los símbolos de la secuencia. Structured Append es compatible con Aztec Code, Code One, Data Matrix, DotCode, Grid Matrix, MaxiCode, MicroPDF417, PDF417 y Ultracode.
-t, --types
Muestra la tabla de tipos de códigos de barras (simbologías). Los números o nombres pueden usarse con -b | --barcode.
--textgap=NÚMERO
Ajusta el espacio entre el código de barras y el Texto Legible por Humanos (HRT). NÚMERO está en dimensiones X, y puede ser de punto flotante. El máximo es 10 y el mínimo es -5. El valor predeterminado es 1.
--vers=ENTEROS
Establece la versión del símbolo (tamaño, dígitos de control, otras opciones) a ENTEROS. El significado es específico del símbolo.

-v, --version
Muestra la versión de zint.
--vwhitesp=ENTEROS
Establece la altura del espacio en blanco vertical por encima y por debajo del código de barras, donde ENTEROS está en múltiplos integrales de la dimensión X.
-w, --whitesp=ENTEROS
Establece el ancho del espacio en blanco horizontal a cada lado del código de barras, donde ENTEROS está en múltiplos integrales de la dimensión X.
--werror
Convierte todas las advertencias en errores.

ESTADO DE SALIDA

0
Éxito (incluso cuando se proporcionan las opciones informativas -h | --help, -e | --ecinos, -t | --types, -v | --version).
-1

EJEMPLOS

Crea “out.png” (o “out.gif” si zint se compiló sin soporte PNG) en el directorio actual, como un símbolo de Código 128.

zint -d 'This Text'

Crea “qr.svg” en el directorio actual, como un símbolo de Código QR.

zint -b QRCode -d 'This Text' -o 'qr.svg'

Utiliza el modo por lotes para leer desde un archivo de entrada “ean13nos.txt” que contiene una lista de GTINs de 13 dígitos, cada uno en una línea separada, para crear una serie de códigos de barras EAN-13, formateando los nombres de archivo de salida a “ean001.gif”, “ean002.gif”, etc., utilizando el carácter especial “~”.

zint -b EANX --batch -i 'ean13nos.txt' -o 'ean~~~.gif'
