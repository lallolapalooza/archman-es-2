ZGGSVP

Propósito:

!>
!> Esta subrutina está obsoleta y ha sido reemplazada por la subrutina ZGGSVP3.
!>
!> ZGGSVP calcula matrices unitarias U, V y Q tales que
!>
!>                    N-K-L  K    L
!>  U**H*A*Q =     K ( 0    A12  A13 )  si M-K-L >= 0;
!>                 L ( 0     0   A23 )
!>             M-K-L ( 0     0    0  )
!>
!>                  N-K-L  K    L
!>         =     K ( 0    A12  A13 )  si M-K-L < 0;
!>             M-K ( 0     0   A23 )
!>
!>                  N-K-L  K    L
!>  V**H*B*Q =   L ( 0     0   B13 )
!>             P-L ( 0     0    0  )
!>
!> donde la matriz KxK A12 y la matriz LxL B13 son triangulares superiores
!> no singulares; A23 es triangular superior LxL si M-K-L >= 0,
!> de lo contrario A23 es trapezoidal superior (M-K)xL. K+L = el rango
!> numérico efectivo de la matriz (M+P)xN (A**H,B**H)**H.
!>
!> Esta descomposición es el paso de preprocesamiento para calcular la
!> Descomposición en Valores Singulares Generalizada (GSVD), ver subrutina
!> ZGGSVD.
!>

Parámetros

JOBU 
!>          JOBU es CHARACTER*1
!>          = 'U':  Se calcula la matriz unitaria U;
!>          = 'N':  U no se calcula.
!>

JOBV

!>          JOBV es CHARACTER*1
!>          = 'V':  Se calcula la matriz unitaria V;
!>          = 'N':  V no se calcula.
!>

JOBQ

!>          JOBQ es CHARACTER*1
!>          = 'Q':  Se calcula la matriz unitaria Q;
!>          = 'N':  Q no se calcula.
!>

M

!>          M es INTEGER
!>          El número de filas de la matriz A. M >= 0.
!>

P

!>          P es INTEGER
!>          El número de filas de la matriz B. P >= 0.
!>

N

!>          N es INTEGER
!>          El número de columnas de las matrices A y B. N >= 0.
!>

A

!>          A es un arreglo de tipo COMPLEX*16, dimensión (LDA,N)
!>          A la entrada, la matriz M x N A.
!>          A la salida, A contiene la matriz triangular (o trapezoidal)
!>          descrita en la sección Propósito.
!>

LDA

!>          LDA es INTEGER
!>          La dimensión principal del arreglo A. LDA >= max(1,M).
!>

B

!>          B es un arreglo de tipo COMPLEX*16, dimensión (LDB,N)
!>          A la entrada, la matriz P x N B.
!>          A la salida, B contiene la matriz triangular descrita en
!>          la sección Propósito.
!>

LDB

!>          LDB es INTEGER
!>          La dimensión principal del arreglo B. LDB >= max(1,P).
!>

TOLA

!>          TOLA es DOUBLE PRECISION
!>

TOLB

!>          TOLB es DOUBLE PRECISION
!>
!>          TOLA y TOLB son los umbrales para determinar el rango numérico
!>          efectivo de la matriz B y un subbloque de A. Generalmente,
!>          se establecen a
!>             TOLA = MAX(M,N)*norm(A)*MAZHEPS,
!>             TOLB = MAX(P,N)*norm(B)*MAZHEPS.
!>          El tamaño de TOLA y TOLB puede afectar los errores hacia atrás
!>          de la descomposición.
!>

K

!>          K es INTEGER
!>

L

!>          L es INTEGER
!>
!>          A la salida, K y L especifican la dimensión de los subbloques
!>          descritos en la sección Propósito.
!>          K + L = rango numérico efectivo de (A**H,B**H)**H.
!>

U

!>          U es un arreglo de tipo COMPLEX*16, dimensión (LDU,M)
!>          Si JOBU = 'U', U contiene la matriz unitaria U.
!>          Si JOBU = 'N', U no se utiliza.
!>

LDU

!>          LDU es INTEGER
!>          La dimensión principal del arreglo U. LDU >= max(1,M) si
!>          JOBU = 'U'; LDU >= 1 en caso contrario.
!>

V

!>          V es un arreglo de tipo COMPLEX*16, dimensión (LDV,P)
!>          Si JOBV = 'V', V contiene la matriz unitaria V.
!>          Si JOBV = 'N', V no se utiliza.
!>

LDV

!>          LDV es INTEGER
!>          La dimensión principal del arreglo V. LDV >= max(1,P) si
!>          JOBV = 'V'; LDV >= 1 en caso contrario.
!>

Q

!>          Q es un arreglo de tipo COMPLEX*16, dimensión (LDQ,N)
!>          Si JOBQ = 'Q', Q contiene la matriz unitaria Q.
!>          Si JOBQ = 'N', Q no se utiliza.
!>

LDQ

!>          LDQ es INTEGER
!>          La dimensión principal del arreglo Q. LDQ >= max(1,N) si
!>          JOBQ = 'Q'; LDQ >= 1 en caso contrario.
!>

IWORK

!>          IWORK es un arreglo de tipo INTEGER, dimensión (N)
!>

RWORK

!>          RWORK es un arreglo de tipo DOUBLE PRECISION, dimensión (2*N)
!>

TAU

!>          TAU es un arreglo de tipo COMPLEX*16, dimensión (N)
!>

WORK

!>          WORK es un arreglo de tipo COMPLEX*16, dimensión (max(3*N,M,P))
!>

INFO

!>          INFO es INTEGER
!>          = 0:  salida exitosa
!>          < 0:  si INFO = -i, el i-ésimo argumento tenía un valor ilegal.
!>

zggsvp.3 (LAPACK)

NOMBRE

zggsvp - establece la generalizada de valores singulares de dos matrices complejas.

SINÓPSIS

    subroutine zggsvp(JOBU, JOBV, JOE, M, N, K, A, LDA, B, LDB, TOL,
                      INFO, U, LDU, V, LDV, X, LDX)

    complex(8) A(LDA,*)
    complex(8) B(LDB,*)
    complex(8) U(LDU,*)
    complex(8) V(LDV,*)
    complex(8) X(LDX,*)
    integer JOBU, JOBV, JOE, M, N, K, LDA, LDB, INFO, LDU, LDV, LDX
    real(8) TOL

Documentación de Funciones/Subrutinas

Esta función/subrutina realiza la siguiente operación:

    Comprueba los parámetros de entrada:
    - JOBU: Indica si se deben calcular U.
    - JOBV: Indica si se deben calcular V.
    - JOE: Indica si se deben calcular E.
    - M, N: Dimensiones de las matrices A y B.
    - K: Subespacio restringido.
    - A, LDA: Matriz A y su tamaño de fila.
    - B, LDB: Matriz B y su tamaño de fila.
    - TOL: Tolerancia para determinar el rango numérico.
    - INFO: Variable de salida para información de error.
    - U, LDU: Matriz U y su tamaño de fila (si se calcula).
    - V, LDV: Matriz V y su tamaño de fila (si se calcula).
    - X, LDX: Matriz X y su tamaño de fila (si se calcula).

    Realiza una reducción de la matriz generalizada, estableciendo el subespacio restringido.
    La reducción se realiza de forma que A se transforma en una matriz triangular superior
    y B se transforma en una matriz diagonal superior.

    La subrutina maneja diferentes casos según los valores de JOBU, JOBV y JOE,
    determinando qué matrices (U, V, E) se calculan y qué transformaciones se aplican.

    La complejidad computacional depende de las dimensiones de las matrices y de los parámetros de entrada.
