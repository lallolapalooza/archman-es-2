zlib(n) Comandos integrados de Tcl zlib(n)

NOMBRE

zlib - operaciones de compresión y descompresión

SINOPSIS

zlib subcomando arg ...

DESCRIPCIÓN

El comando zlib proporciona acceso a las instalaciones de compresión y suma de verificación de la biblioteca Zlib de Jean-loup Gailly y Mark Adler. Tiene los siguientes subcomandos.

SUBCOMANDOS DE COMPRESIÓN

zlib compress cadena ?nivel?
Devuelve los datos binarios comprimidos en formato zlib de la cadena binaria en cadena. Si está presente, nivel especifica el nivel de compresión a utilizar (de 0, que es sin comprimir, a 9, máximamente comprimido).
zlib decompress cadena ?tamañoBuffer?
Devuelve la versión descomprimida de los datos binarios comprimidos en bruto en cadena. Si está presente, tamañoBuffer es una sugerencia sobre el tamaño del búfer que se utilizará para recibir los datos.
zlib deflate cadena ?nivel?
Devuelve los datos binarios comprimidos en bruto de la cadena binaria en cadena. Si está presente, nivel especifica el nivel de compresión a utilizar (de 0, que es sin comprimir, a 9, máximamente comprimido).
zlib gunzip cadena ?-variableEncabezado nombreVar?
Devuelve el contenido descomprimido de la cadena binaria cadena, que debe haber estado en formato gzip. Si se proporciona -variableEncabezado, almacena un diccionario que describe el contenido del encabezado gzip en la variable llamada nombreVar. Las claves del diccionario que pueden estar presentes son:
comentario
El campo de comentario del encabezado, si está presente.
crc
Un valor booleano que describe si se calcula una CRC del encabezado.
nombreArchivo
El campo nombre de archivo del encabezado, si está presente.
so
El código del tipo de sistema operativo del encabezado (si no es el valor desconocido QW). Consulte RFC 1952 para conocer el significado de estos códigos.
tamaño
El tamaño de los datos sin comprimir.
tiempo
El campo de tiempo del encabezado si no es cero, se espera que sea el tiempo en que se modificó el archivo con el nombre del campo nombreArchivo. Adecuado para su uso con clock format.
tipo
El tipo de los datos sin comprimir (binario o texto) si se conoce.
zlib gzip cadena ?-nivel nivel? ?-encabezado diccionario?
Devuelve el contenido comprimido de la cadena binaria cadena en formato gzip. Si se especifica -nivel, nivel indica el nivel de compresión a utilizar (de 0, que es sin comprimir, a 9, máximamente comprimido). Si se especifica -encabezado, diccionario es un diccionario que contiene valores utilizados para el encabezado gzip. Las siguientes claves pueden definirse:
comentario
Agrega el comentario dado al encabezado de los datos en formato gzip.
crc
Un booleano que indica si se debe calcular una CRC del encabezado. Tenga en cuenta que si los datos se van a intercambiar con el programa gzip, NO se debe calcular una CRC del encabezado.
nombreArchivo
El nombre del archivo del que provienen los datos a comprimir.
so
El código del tipo de sistema operativo, que debe ser uno de los valores descritos en RFC 1952.
tiempo
El tiempo en que se modificó por última vez el archivo nombrado en la clave nombreArchivo. Esto estará en el mismo formato que el devuelto por clock seconds o file mtime.
tipo
El tipo de los datos que se están comprimiendo, siendo binario o texto.
zlib inflate cadena ?tamañoBuffer?
Devuelve la versión descomprimida de los datos binarios comprimidos en bruto en cadena. Si está presente, tamañoBuffer es una sugerencia sobre el tamaño del búfer que se utilizará para recibir los datos.

SUBCOMANDO DE CANAL

zlib push modo canal ?opciones ...?
Empuja una transformación de compresión o descompresión sobre el canal canal. La transformación se puede eliminar de nuevo con chan pop. El argumento modo determina qué tipo de transformación se empuja; se admiten los siguientes:
compress
La transformación será una transformación de compresión que produce datos en formato zlib en canal, que debe ser escribible.
decompress
La transformación será una transformación de descompresión que lee datos en formato zlib de canal, que debe ser legible.
deflate
La transformación será una transformación de compresión que produce datos comprimidos en bruto en canal, que debe ser escribible.
gunzip
La transformación será una transformación de descompresión que lee datos en formato gzip de canal, que debe ser legible.
gzip
La transformación será una transformación de compresión que produce datos en formato gzip en canal, que debe ser escribible.
inflate
La transformación será una transformación de descompresión que lee datos comprimidos en bruto de canal, que debe ser legible.

Las siguientes opciones se pueden establecer al crear una transformación a través de las "opciones ..." del comando zlib push:

-dictionary datosBinarios
Establece el diccionario de compresión a utilizar al trabajar con la compresión o descompresión de los datos a ser datosBinarios. No es válido para transformaciones que trabajan con datos en formato gzip. El diccionario debe consistir en cadenas (secuencias de bytes) que es probable que se encuentren más adelante en los datos a comprimir, y las cadenas de uso más común preferiblemente se colocan hacia el final del diccionario. Tcl no proporciona ningún mecanismo para elegir un buen diccionario para una secuencia de datos particular.
-header diccionario
Pasa una descripción del encabezado gzip a crear, en el mismo formato que entiende zlib gzip.
-level nivelCompresion
Qué tan difícil comprimir los datos. Debe ser un entero de 0 (sin comprimir) a 9 (máximamente comprimido).
-limit limiteLecturaAnticipada
El número máximo de bytes a leer con antelación al descomprimir.

Esta opción se ha vuelto irrelevante. Se introdujo originalmente para evitar que Tcl leyera más allá del final de un flujo comprimido en canales de flujo múltiple para garantizar que los datos posteriores se dejaran intactos para lecturas posteriores, a costa de la velocidad.

Tcl ahora devuelve automáticamente cualquier byte que haya leído más allá del final de un flujo comprimido al canal, haciéndolos aparecer como no leídos para lectores posteriores.

DESCRIPTION

The compression operation from above can also be done with streams, which is especially helpful when you want to accumulate the data by stages:

set strm [zlib stream compress]
$strm put [encoding convertto utf-8 $string]
# ...
$strm finalize
set compData [$strm get]
$strm close
