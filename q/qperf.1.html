QPERF(1) Comandos de usuario QPERF(1)

NOMBRE

qperf - Mide el rendimiento de RDMA e IP

SINOPSIS

qperf
qperf NODO_SERVIDOR [OPCIONES] PRUEBAS

DESCRIPCIÓN

qperf mide el ancho de banda y la latencia entre dos nodos. Puede funcionar sobre TCP/IP, así como sobre los transportes RDMA. En uno de los nodos, qperf se suele ejecutar sin argumentos, designándolo como nodo servidor. Luego se puede ejecutar qperf en un nodo cliente para obtener mediciones como ancho de banda, latencia y utilización de la CPU.

En su forma más básica, qperf se ejecuta en un nodo en modo servidor invocándolo sin argumentos. En el otro nodo, se ejecuta con dos argumentos: el nombre del nodo servidor seguido del nombre de la prueba. Una lista de pruebas se encuentra en la sección PRUEBAS. También se puede especificar una variedad de opciones.

Se puede obtener información más detallada sobre qperf utilizando la opción --help. A continuación se muestran ejemplos de uso de la opción --help:


qperf --help examples Algunos ejemplos de uso de qperf
qperf --help opts Resumen de opciones
qperf --help options Descripción de opciones
qperf --help tests Resumen corto y descripción de las pruebas
qperf --help TESTNAME Más información sobre la prueba TESTNAME

EJEMPLOS

En estos ejemplos, primero ejecutamos qperf en un nodo llamado myserver en modo servidor invocándolo sin argumentos. En todos los ejemplos posteriores, ejecutamos qperf en otro nodo y nos conectamos al servidor, del cual asumimos que tiene el nombre de host myserver.

Para ejecutar una prueba de ancho de banda y latencia TCP:
qperf myserver tcp_bw tcp_lat
Para ejecutar una prueba de ancho de banda SDP durante 10 segundos:
qperf myserver -t 10 sdp_bw
Para ejecutar una prueba de latencia UDP y luego hacer que el servidor termine:
qperf myserver udp_lat quit
Para medir la latencia y el ancho de banda UD de RDMA:
qperf myserver ud_lat ud_bw
Para medir el ancho de banda bidireccional UC de RDMA:
qperf myserver rc_bi_bw
Para obtener un rango de latencias TCP con un tamaño de mensaje de 1 a 64K
qperf myserver -oo msg_size:1:64K:*2 -vu tcp_lat

OPCIONES

-ar, --access_recv OnOff
Si OnOff no es cero, los datos se acceden una vez recibidos. De lo contrario, los datos se ignoran. Por defecto, OnOff es 0. Esto puede ayudar a imitar algunas aplicaciones.
-ar1
Hace que los datos recibidos sean accedidos.
-ap, --alt_port Puerto
Establece el puerto de ruta alternativa. Esto habilita la conmutación por error automática de ruta.
-lap, --loc_alt_port Puerto
Establece el puerto de ruta alternativa local. Esto habilita la conmutación por error automática de ruta.
-rap, --rem_alt_port Puerto
Establece el puerto de ruta alternativa remoto. Esto habilita la conmutación por error automática de ruta.
-ca, --cpu_affinity PN
Establece la afinidad de CPU a PN. Las CPU se numeran secuencialmente a partir de 0. Si PN es "any", se permite cualquier CPU; de lo contrario, la CPU se limita a la especificada.
-lca, --loc_cpu_affinity PN
Establece la afinidad del procesador local a PN.
-rca, --rem_cpu_affinity PN
Establece la afinidad del procesador remoto a PN.
-f, --flip OnOff
Si no es cero, hace que el remitente y el receptor jueguen roles opuestos.
-f1
Hace que el remitente y el receptor jueguen roles opuestos.
-h, --help Tema
Imprime información sobre el Tema. Para ver la lista de temas, escribe qperf --help
-H, --host Host
Ejecuta la prueba entre el nodo actual y el qperf que se ejecuta en el nodo Host. Esto también se puede especificar como el primer argumento que no es una opción.
-i, --id Dispositivo:Puerto
Utiliza el Dispositivo y Puerto RDMA.
-li, --loc_id Dispositivo:Puerto
Utiliza el Dispositivo y Puerto RDMA local.
-ri, --rem_id Dispositivo:Puerto
Utiliza el Dispositivo y Puerto RDMA remoto.
-lp, --listen_port Puerto
Establece el puerto en el que escuchamos a PuertoEscucha. Esto debe establecerse en el mismo puerto en las máquinas del servidor y del cliente. El valor predeterminado es 19765.
-oo, --loop Var:Ini:Ult:Inc
Ejecuta una prueba varias veces, secuenciando a través de una serie de valores. Var es la variable de bucle; Ini es el valor inicial; Ult es el valor que no debe exceder e Inc es el incremento. Es útil establecer la opción --verbose_used (-vu) junto con esta opción.
-m, --msg_size Tamaño
Establece el tamaño del mensaje a Tamaño. El valor predeterminado varía según la prueba. Se supone que el valor se especifica en bytes; sin embargo, un sufijo kib o K, mib o M, o gib o G indica que el tamaño se especifica en kibibytes, mebibytes o gibibytes respectivamente, mientras que un sufijo kb o k, mb o m, o gb o g indica kilobytes, megabytes o gigabytes respectivamente.
-mt, --mtu_size Tamaño
Establece el tamaño de MTU. Solo relevante para las pruebas RDMA UC/RC. Las unidades se especifican de la misma manera que la opción --msg_size.
-n, --no_msgs N
Establece la duración de la prueba por número de mensajes enviados en lugar de tiempo.
-cp, --cq_poll OnOff
Activa o desactiva el modo de sondeo. Esto solo es relevante para las pruebas RDMA y determina si sondea o espera en las colas de finalización. Si OnOff es 0, esperan; de lo contrario, sondean.
-lcp, --loc_cq_poll OnOff
Activa o desactiva localmente el modo de sondeo.
-rcp, --rem_cq_poll OnOff
Activa o desactiva remotamente el modo de sondeo.
-cp1
Activa el modo de sondeo.
-lcp1
Activa el modo de sondeo local.
-rcp1
Activa el modo de sondeo remoto.
-ip, --ip_port Puerto
Utiliza Puerto para ejecutar las pruebas de socket. Esto es diferente de --listen_port, que se utiliza para la sincronización. Esto solo es relevante para las pruebas de socket y se refiere al puerto TCP/UDP/SDP/RDS/SCTP en el que se ejecuta la prueba.
-e, --precision Dígitos
Establece el número de dígitos significativos que se utilizan para informar los resultados.
-nr, --rd_atomic Max
Establece el número de operaciones en curso que pueden manejarse para una operación RDMA read o atómica en Max. Esto solo es relevante para las pruebas RDMA Read y Atomic.
-lnr, --loc_rd_atomic Max
Establece el recuento de lectura/atómico local.
-rnr, --rem_rd_atomic Max
Establece el recuento de lectura/atómico remoto.
-sl, --service_level SL
Establece el nivel de servicio RDMA en SL. Esto solo es utilizado por las pruebas RDMA. El nivel de servicio debe estar entre 0 y 15. El nivel de servicio predeterminado es 0.
-lsl, --loc_service_level SL
Establece el nivel de servicio local.

OPTIONS

-rsl, --rem_service_level SL
Establecer el nivel de servicio remoto.
-sb, --sock_buf_size Tamaño
Establecer el tamaño del búfer del socket. Esto solo es relevante para las pruebas de socket.
-lsb, --loc_sock_buf_size Tamaño
Establecer el tamaño del búfer del socket local.
-rsb, --rem_sock_buf_size Tamaño
Establecer el tamaño del búfer del socket remoto.
-sp, --src_path_bits N
Establecer los bits de la ruta de origen. Si el LMC no es cero, esto hará que la conexión use un LID con los bits LMC de orden bajo establecidos en N.
-lsp, --loc_src_path_bits N
Establecer los bits de la ruta de origen local.
-rsp, --rem_src_path_bits N
Establecer los bits de la ruta de origen remoto.
-sr, --static_rate Tasa
Forzar la tasa estática de InfiniBand. La tasa puede ser una de: 2.5, 5, 10, 20, 30, 40, 60, 80, 120, 1xSDR (2.5 Gbps), 1xDDR (5 Gbps), 1xQDR (10 Gbps), 4xSDR (2.5 Gbps), 4xDDR (5 Gbps), 4xQDR (10 Gbps), 8xSDR (2.5 Gbps), 8xDDR (5 Gbps), 8xQDR (10 Gbps).
-lsr, --loc_static_rate
Forzar la tasa estática local de InfiniBand
-rsr, --rem_static_rate
Forzar la tasa estática remota de InfiniBand
-t, --time Tiempo
Establecer la duración de la prueba en Tiempo. Especificado en segundos, sin embargo, una 'm', 'h' o 'd' al final indica que el tiempo se especifica en minutos, horas o días respectivamente.
-to, --timeout Tiempo
Establecer el tiempo de espera en Tiempo. Este es el tiempo de espera utilizado para diversas cosas, como el intercambio de mensajes. El valor predeterminado es 5 segundos.
-lto, --loc_timeout Tiempo
Establecer el tiempo de espera local en Tiempo. Esto puede ser utilizado en el servidor para establecer el tiempo de espera al intercambiar datos inicialmente con cada cliente. Sin embargo, tan pronto como recibamos los parámetros del cliente, el tiempo de espera remoto del cliente anulará este parámetro.
-rto, --rem_timeout Tiempo
Establecer el tiempo de espera remoto en Tiempo.
-un, --unify_nodes
Unificar los nodos. Describirlos en términos de local y remoto en lugar de enviar y recibir.
-uu, --unify_units
Unificar las unidades en las que se muestran los resultados. Utiliza el mínimo común denominador. Útil para scripts.
-ub, --use_bits_per_sec
Usar bits/segundo en lugar de bytes/segundo al mostrar la velocidad de red.
-cm, --use_cm OnOff
Usar el Gestor de Conexiones RDMA (CM) si OnOff es distinto de cero. Es necesario usar el CM para dispositivos iWARP. El valor predeterminado es establecer la conexión sin usar el CM. Esto solo funciona para las pruebas que usan el transporte RC.
-cm1
Usar Gestor de Conexiones RDMA.
-v, --verbose
Proporcionar salida más detallada. Activa -vc, -vs, -vt y -vu.
-vc, --verbose_conf
Proporcionar información sobre la configuración.
-vs, --verbose_stat
Proporcionar información sobre las estadísticas.
-vt, --verbose_time
Proporcionar información sobre la temporización.
-vu, --verbose_used
Proporcionar información sobre los parámetros utilizados.
-vv, --verbose_more
Proporcionar aún más detalles. Activa -vvc, -vvs, -vvt y -vvu.
-vvc, --verbose_more_conf
Proporcionar más información sobre la configuración.
-vvs, --verbose_more_stat
Proporcionar más información sobre las estadísticas.
-vvt, --verbose_more_time
Proporcionar más información sobre la temporización.
-vvu, --verbose_more_used
Proporcionar más información sobre los parámetros utilizados.
-V, --version
Se imprime la versión actual de qperf.
-ws, --wait_server Tiempo
Si el servidor no está listo, continúa intentando conectarse durante Tiempo segundos antes de rendirse. El valor predeterminado es 5 segundos.

AUTOR

ERRORES

Ninguna de las pruebas RDMA está disponible si qperf se compila sin las bibliotecas RDMA. Ninguna de las pruebas XRC está disponible si qperf se compila sin las extensiones XRC. La opción -f aún no está implementada en muchas de las pruebas.
