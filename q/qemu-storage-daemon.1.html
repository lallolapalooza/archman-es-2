NOMBRE

qemu-storage-daemon - Demonio de almacenamiento de QEMU

SINOPSIS

qemu-storage-daemon [opciones]

DESCRIPCIÓN

qemu-storage-daemon proporciona funcionalidad de imagen de disco de QEMU, qemu-img y qemu-nbd en un proceso de larga duración controlado a través de comandos QMP sin ejecutar una máquina virtual. Puede exportar imágenes de disco, ejecutar operaciones de trabajos de bloque y realizar otras operaciones relacionadas con el disco. El demonio se controla a través de un monitor QMP y una configuración inicial desde la línea de comandos.

El demonio ofrece el siguiente subconjunto de funcionalidades de QEMU:

  • Nodos de bloque
  • Trabajos de bloque
  • Exportaciones de bloque
  • Grupos de limitación de velocidad
  • Dispositivos de caracteres
  • Criptografía y secretos
  • QMP
  • IOThreads

Los comandos se pueden enviar a través de una conexión QEMU Monitor Protocol (QMP). Consulte la página del manual qemu-storage-daemon-qmp-ref(7) para obtener una descripción de los comandos.

El demonio se ejecuta hasta que se detiene utilizando el comando QMP quit o SIGINT/SIGHUP/SIGTERM.

Advertencia: Nunca modifique imágenes en uso por una máquina virtual en ejecución o cualquier otro proceso; esto puede destruir la imagen. Además, tenga en cuenta que consultar una imagen que está siendo modificada por otro proceso puede encontrar un estado inconsistente.

OPCIONES

Opciones estándar:

-h, --help
Muestra la ayuda y sale
-V, --version
Muestra información de la versión y sale
-T, --trace [[enable=]PATRON][,events=ARCHIVO][,file=ARCHIVO]
Especifica opciones de trazado.

[enable=]PATRON

Habilita inmediatamente eventos que coincidan con el PATRON (ya sea el nombre del evento o un patrón globbing). Esta opción solo está disponible si QEMU ha sido compilado con el backend de trazado simple, log o ftrace. Para especificar múltiples eventos o patrones, especifique la opción -trace varias veces.

Use -trace help para imprimir una lista de nombres de puntos de trazado.

events=ARCHIVO

Habilita inmediatamente los eventos listados en ARCHIVO. El archivo debe contener un nombre de evento (como se lista en el archivo trace-events-all) por línea; también se aceptan patrones globbing. Esta opción solo está disponible si QEMU ha sido compilado con el backend de trazado simple, log o ftrace.

file=ARCHIVO

Registra la salida de los trazados en ARCHIVO. Esta opción solo está disponible si QEMU ha sido compilado con el backend de trazado simple.
--blockdev DEFINICION_BLOQUE
es una definición de nodo de bloque. Consulte la página del manual qemu(1) para obtener una descripción de las propiedades del nodo de bloque y la página del manual qemu-block-drivers(7) para obtener una descripción de los parámetros específicos del controlador.
--chardev DEFINICION_CARACTER
es una definición de dispositivo de caracteres. Consulte la página del manual qemu(1) para obtener una descripción de las propiedades del dispositivo de caracteres. Una definición común de dispositivo de caracteres configura un socket de dominio UNIX:
--chardev socket,id=char1,path=/var/run/qsd-qmp.sock,server=on,wait=off
--export [type=]nbd,id=<id>,node-name=<nombre-nodo>[,name=<nombre-exportacion>][,writable=on|off][,bitmap=<nombre>]
--export [type=]vhost-user-blk,id=<id>,node-name=<nombre-nodo>,addr.type=unix,addr.path=<ruta-socket>[,writable=on|off][,logical-block-size=<tamaño-bloque>][,num-queues=<num-colas>]
--export [type=]vhost-user-blk,id=<id>,node-name=<nombre-nodo>,addr.type=fd,addr.str=<fd>[,writable=on|off][,logical-block-size=<tamaño-bloque>][,num-queues=<num-colas>]
--export [type=]fuse,id=<id>,node-name=<nombre-nodo>,mountpoint=<archivo>[,growable=on|off][,writable=on|off][,allow-other=on|off|auto]
--export [type=]vduse-blk,id=<id>,node-name=<nombre-nodo>,name=<nombre-vduse>[,writable=on|off][,num-queues=<num-colas>][,queue-size=<tamaño-cola>][,logical-block-size=<tamaño-bloque>][,serial=<numero-serie>]
es una definición de exportación de bloque. node-name es el nodo de bloque que debe exportarse. writable determina si la exportación permite o no solicitudes de escritura para modificar datos (el valor predeterminado es desactivado).

El tipo de exportación nbd requiere --nbd-server (ver abajo). name es el nombre de la exportación NBD (si no se especifica, se establece como el node-name dado). bitmap es el nombre de un bitmap de modificación alcanzable desde el nodo de bloque, por lo que el cliente NBD puede usar NBD_OPT_SET_META_CONTEXT con el nombre del contexto de metadatos "qemu:dirty-bitmap:BITMAP" para inspeccionar el bitmap.

El tipo de exportación vhost-user-blk toma una dirección de socket vhost-user en la que acepta conexiones entrantes. Se admiten tanto addr.type=unix,addr.path=<ruta-socket> para sockets de dominio UNIX como addr.type=fd,addr.str=<fd> para el paso de descriptores de archivo. logical-block-size establece el tamaño lógico del bloque en bytes (el valor predeterminado es 512). num-queues establece el número de colas virtuales (el valor predeterminado es 1).

El tipo de exportación fuse toma un punto de montaje, que debe ser un archivo regular, en el que exportar el nodo de bloque dado. Ese archivo no se modificará, simplemente parecerá tener el contenido del nodo de bloque mientras la exportación esté activa (muy parecido a montar un sistema de archivos en un directorio no cambia lo que contiene el directorio, solo muestra un contenido diferente mientras el sistema de archivos está montado). En consecuencia, las aplicaciones que hayan abierto el archivo dado antes de que la exportación se activara seguirán viendo su contenido original. Si se establece growable, las escrituras después del final del archivo exportado crecerán el nodo de bloque para ajustarse. La opción allow-other controla si los usuarios distintos del usuario que ejecuta el proceso podrán acceder a la exportación. Tenga en cuenta que habilitar esta opción como usuario no root requiere habilitar la opción user_allow_other en el archivo de configuración global fuse.conf. Establecer allow-other en auto (el valor predeterminado) intentará habilitar esta opción y, en caso de error, volverá a desactivarla.

El tipo de exportación vduse-blk toma un nombre (debe ser único en el host) para crear el dispositivo VDUSE. num-queues establece el número de colas virtuales (el valor predeterminado es 1). queue-size establece el tamaño de la tabla de descriptores de colas virtuales (el valor predeterminado es 256).

El dispositivo VDUSE instanciado debe agregarse al bus vDPA utilizando el comando vdpa(8) del proyecto iproute2:

# vdpa dev add name <id> mgmtdev vduse

El dispositivo se puede eliminar del bus vDPA más tarde de la siguiente manera:

# vdpa dev del <id>

Para obtener más información sobre cómo conectar dispositivos vDPA al host con virtio_vdpa.ko o conectarlos a invitados con vhost_vdpa.ko, consulte https://vdpa-dev.gitlab.io/.

Para obtener más información sobre VDUSE, consulte https://docs.kernel.org/userspace-api/vduse.html.

--monitor DEFINICION_MONITOR
es una definición de monitor QMP. Consulte la página del manual qemu(1) para obtener una descripción de las propiedades del monitor QMP. Una definición común de monitor QMP

NOMBRE

qemu-storage-daemon - Daemon para acceso a dispositivos de bloques QEMU

SINOPSIS

qemu-storage-daemon [OPCIONES]

DESCRIPCIÓN

El demonio de almacenamiento QEMU proporciona acceso a dispositivos de bloques QEMU, ya sea como exportación NBD o como un servidor de disco vhost-user en un socket de dominio UNIX.

Si se omite --daemonize, el proceso se ejecuta en primer plano.

Si se invoca el demonio sin opciones, se ejecutará en primer plano y esperará conexiones en el socket de dominio UNIX /var/run/qsd-rpc.sock.

Una vez iniciado, el demonio puede ser controlado a través de comandos QMP (QEMU Machine Protocol). La interfaz QMP se puede habilitar utilizando la opción --monitor.

OPCIONES

Hay dos tipos de opciones:

  • Las opciones que se utilizan para configurar la ejecución del demonio, como el registro, la creación de demonios o la configuración de servidores NBD. Estas opciones solo se pueden especificar una vez y deben aparecer antes que las opciones de exportación.
  • Las opciones que configuran una exportación de almacenamiento. Estas opciones se pueden especificar varias veces para configurar múltiples exportaciones.
--chardev <type>[,<param>...]
Define un dispositivo de caracteres. Consulte la página del manual qemu-options(7) para ver los tipos y parámetros disponibles. Los parámetros importantes son:
id=<id>
Identificador único para el dispositivo de caracteres. Se utiliza para referenciar este dispositivo de caracteres con la opción --monitor.
path=<path>
Ruta del socket de dominio UNIX. Para usarlo con la opción --monitor.
server=[on|off]
Indica si el dispositivo de caracteres debe escuchar conexiones entrantes (servidor).
wait=[on|off]
Si es 'on', espera a que una conexión llegue al dispositivo de caracteres antes de continuar con el inicio del demonio. Es útil para la inicialización de la consola monitor, asegurando que el monitor QMP esté disponible antes de que el demonio acepte otras conexiones (por ejemplo, NBD).
--monitor chardev=<char1>
configura un monitor en el dispositivo de caracteres char1:
--monitor chardev=char1
--nbd-server addr.type=inet,addr.host=<host>,addr.port=<port>[,tls-creds=<id>][,tls-authz=<id>][,max-connections=<n>]
--nbd-server addr.type=unix,addr.path=<path>[,tls-creds=<id>][,tls-authz=<id>][,max-connections=<n>]
--nbd-server addr.type=fd,addr.str=<fd>[,tls-creds=<id>][,tls-authz=<id>][,max-connections=<n>]
es un servidor para exportaciones NBD. Se admiten tanto TCP como sockets de dominio UNIX. Se puede proporcionar un socket de escucha a través de la transferencia de descriptores de archivo (consulte los Ejemplos a continuación). El cifrado TLS se puede configurar utilizando secretos --object tls-creds-* y authz-* (consulte más abajo).

Para configurar un servidor NBD en la ruta del socket de dominio UNIX /var/run/qsd-nbd.sock:

--nbd-server addr.type=unix,addr.path=/var/run/qsd-nbd.sock
--object help
--object <type>,help
--object <type>[,<property>=<value>...]
es una definición de objeto creable por el usuario de QEMU. Enumere los tipos de objetos con help. Enumere las propiedades de los objetos con <type>,help. Consulte la página del manual de qemu(1) para obtener una descripción de las propiedades de los objetos.
--pidfile PATH
es la ruta a un archivo donde el demonio escribe su pid. Esto permite que los scripts detengan el demonio enviando una señal:
$ kill -SIGTERM $(<path/to/qsd.pid)

Se aplica un bloqueo de archivo al archivo para que solo una instancia del demonio pueda ejecutarse con una ruta de archivo de pid dada. El demonio elimina su archivo de pid al terminar.

El archivo de pid se escribe después de que se hayan creado los chardevs, las exportaciones y los servidores NBD, pero antes de aceptar conexiones. El demonio se ha iniciado correctamente cuando se escribe el archivo de pid y los clientes pueden comenzar a conectarse.

--daemonize
Daemoniza el proceso. El proceso padre saldrá una vez que la inicialización se complete (es decir, después de que se haya escrito o se hubiera escrito el archivo de pid) o si ocurre un error. Su código de salida reflejará si el proceso hijo se ha iniciado correctamente o no.

EJEMPLOS

Inicia el demonio con el socket de monitor QMP qmp.sock para que los clientes puedan ejecutar comandos QMP:

$ qemu-storage-daemon \
    --chardev socket,path=qmp.sock,server=on,wait=off,id=char1 \
    --monitor chardev=char1

Inicia el demonio desde Python con un socket de monitor QMP usando la transferencia de descriptores de archivo para que no sea necesario esperar activamente a que el monitor QMP esté disponible:

#!/usr/bin/env python3
import subprocess
import socket
sock_path = '/var/run/qmp.sock'
with socket.socket(socket.AF_UNIX, socket.SOCK_STREAM) as listen_sock:
    listen_sock.bind(sock_path)
    listen_sock.listen()
    fd = listen_sock.fileno()
    subprocess.Popen(
        ['qemu-storage-daemon',
         '--chardev', f'socket,fd={fd},server=on,id=char1',
         '--monitor', 'chardev=char1'],
        pass_fds=[fd],
    )
# listen_sock se cerró automáticamente al salir del bloque 'with'.
# Si el proceso demonio terminó prematuramente, la siguiente conexión()
# fallará con "Connection refused" porque ningún proceso tiene el socket
# de escucha abierto. Los errores de inicio se pueden detectar de esta manera.
qmp_sock = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
qmp_sock.connect(sock_path)
...interacción QMP...

El mismo enfoque de invocación de socket también funciona con las opciones --nbd-server addr.type=fd,addr.str=<fd> y --export type=vhost-user-blk,addr.type=fd,addr.str=<fd>.

Exporta el archivo de imagen raw disk.img a través del socket de dominio UNIX NBD nbd.sock:

$ qemu-storage-daemon \
    --blockdev driver=file,node-name=disk,filename=disk.img \
    --nbd-server addr.type=unix,addr.path=nbd.sock \
    --export type=nbd,id=export,node-name=disk,writable=on

Exporta un archivo de imagen qcow2 disk.qcow2 como un dispositivo vhost-user-blk a través del socket de dominio UNIX vhost-user-blk.sock:

$ qemu-storage-daemon \
    --blockdev driver=file,node-name=file,filename=disk.qcow2 \
    --blockdev driver=qcow2,node-name=qcow2,file=file \
    --export type=vhost-user-blk,id=export,addr.type=unix,addr.path=vhost-user-blk.sock,node-name=qcow2

Exporta un archivo de imagen qcow2 disk.qcow2 a través de FUSE sobre sí mismo, de modo que el archivo de imagen del disco aparezca como una imagen raw:

$ qemu-storage-daemon \
    --blockdev driver=file,node-name=file,filename=disk.qcow2 \
    --blockdev driver=qcow2,node-name=qcow2,file=file \
    --export type=fuse,id=export,node-name=qcow2,mountpoint=disk.qcow2,writable=on
