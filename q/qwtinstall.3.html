NOMBRE

qwtinstall - Instalando Qwt

Descarga

Las versiones estables de Qwt están disponibles en la página del proyecto Qwt.

Qwt-6.2.0 consta de 4 archivos:

  • qwt-6.2.0.zip
    Archivo Zip con las fuentes de Qwt y la documentación html para Windows
  • qwt-6.2.0.tar.bz2
    Archivo tar comprimido con las fuentes de Qwt y la documentación html para sistemas UNIX ( Linux, Mac, ... )
  • qwt-6.2.0.pdf
    Documentación de Qwt en formato PDF.
  • qwt-6.2.0.qch
    Documentación de Qwt como documento Qt Compressed Help, que se puede cargar en el Qt Assistant o Creator. En Qt Creator, la ayuda sensible al contexto estará disponible como para las clases de Qt.

Plugins de diseñador de Qwt precompilados, compatibles con algunos paquetes binarios de Qt Creator:

•
qwtdesigner-6.2.0-*.zip

Instalando Qwt

Además de los encabezados, bibliotecas y la versión html de la documentación de la clase, una instalación adecuada de Qwt contiene un plugin de diseñador y un archivo de características de Qwt para construir aplicaciones que utilizan Qwt.

Todos los archivos se copiarán a un directorio de instalación, configurable editando qwtconfig.pri. Su configuración predeterminada es:

  • Windows
    C:\Qwt-6.2.0
  • Sistemas tipo Unix
    /usr/local/qwt-6.2.0

Para el resto del documento, esta ruta de instalación se escribirá como ${QWT_ROOT} y deberá reemplazarse por la ruta real en todos los comandos siguientes.

No es raro tener más de una instalación de Qwt en el mismo sistema. Por ejemplo, para usar el plugin de diseñador de Qwt en Qt Creator, se necesita una versión de Qwt con la misma combinación de Qt y compilador que se utilizó para compilar Qt Creator ( consulte 'Ayuda -> Acerca de Qt Creator ...' ).

La instalación de Qwt se realiza en 3 pasos, que son bastante comunes en los sistemas UNIX.

1.
Configuración
En el paso de configuración, se establecen todos los parámetros para controlar cómo construir e instalar Qwt
2.
Compilación
En el paso de compilación, se generan binarios a partir de los archivos fuente.
3.
Instalación
La instalación copia y reorganiza todos los archivos necesarios para construir aplicaciones Qwt en un directorio de destino.

La instalación no modifica el sistema más allá de copiar archivos a un directorio de forma adecuada. Después de eliminar los directorios de compilación e instalación, el sistema estará en el mismo estado que antes.

Configuración

La configuración de Qwt debe realizarse editando los archivos de proyecto utilizados para la compilación:

  • qwtbuild.pri
    qwtbuild.pri contiene configuraciones sobre cómo compilar Qwt. Todas las configuraciones de este archivo son solo para compilar Qwt en sí y no tienen impacto en cómo se compila una aplicación que usa Qwt. Normalmente, sus configuraciones predeterminadas no necesitan ser modificadas.
  • qwtconfig.pri
    qwtconfig.pri define qué módulos de Qwt se compilarán y dónde se instalarán. qwtconfig.pri se instala junto con el archivo de características de Qwt qwt.prf y todas sus configuraciones son conocidas por los archivos de proyecto para compilar aplicaciones Qwt.

En qwtconfig.pri, se explica detalladamente el significado de cada opción: vale la pena leerlo antes de tener problemas más adelante.

Compilación e instalación

Qt Creator es una interfaz gráfica para llamar a qmake/make y, técnicamente, podría usarse para compilar e instalar Qwt. Pero como esta forma requiere mucha más comprensión de los detalles, las siguientes instrucciones paso a paso son para la forma más fácil de usar la línea de comandos.

Sistemas tipo Unix

El primer paso antes de crear el Makefile es verificar que se está utilizando la versión correcta de qmake. Por ejemplo, en distribuciones Linux antiguas, a menudo se encuentra un qmake de Qt3 en el PATH.

La configuración predeterminada de qmake es generar un Makefile que compila Qwt para el mismo entorno para el que se compiló la versión de qmake. Por lo tanto, crear un Makefile generalmente significa algo como:

cd qwt-6.2.0
/usr/local/Qt-5.0.1/bin/qmake qwt.pro

El Makefile generado incluye todas las rutas relacionadas con la versión de Qt elegida y el siguiente paso es:

make


( En sistemas multinúcleo, puede acelerar la compilación de las bibliotecas Qwt ejecutando varios trabajos simultáneamente: por ejemplo, 'make -j4' en un doble núcleo. )

Finalmente, debe instalar todo debajo de los directorios que especificó en qwtconfig.pri. Generalmente, se trata de uno de los directorios del sistema ( /usr/local, /opt, ... ) donde no tiene permisos de escritura y, por lo tanto, la instalación debe realizarse como root:

sudo make install


( En sistemas donde sudo no es compatible, puede hacer lo mismo con: su -c 'make install' )

Windows

Los paquetes de Qt ofrecen una interfaz de línea de comandos, que se puede encontrar en el menú de aplicaciones de Qt: por ejemplo, 'Todos los programas -> Qt -> Símbolo del sistema'. No es obligatorio usarlo, pero probablemente sea la forma más fácil, ya que ofrece un entorno donde todo está inicializado para una versión de Qt (por ejemplo, qmake está en el PATH).

Crear un Makefile generalmente significa algo como:

cd qwt-6.2.0
qmake qwt.pro

El Makefile generado incluye todas las rutas relacionadas con la versión de Qt elegida.

MinGW

Para las compilaciones de MinGW, el nombre de la herramienta make es 'mingw32-make'

mingw32-make


( En sistemas multinúcleo, puede acelerar la compilación de las bibliotecas Qwt ejecutando varios trabajos simultáneamente: 'mingw32-make -j' )

Finalmente, debe instalar todo debajo de los directorios que especificó en qwtconfig.pri.

mingw32-make install

MSVC

Para las compilaciones de MSVC, el nombre de la herramienta make es 'nmake'. Alternativamente, es posible usar 'jom' ( https://wiki.qt.io/Jom ), que generalmente se incluye en un paquete de Qt Creator.

nmake

Finalmente, debe instalar todo debajo de los directorios que especificó en qwtconfig.pri.

nmake install

Qwt y la cadena de herramientas de Qt

Plugin de diseñador

El plugin de diseñador y la biblioteca Qwt correspondiente (si el plugin no se compiló de forma autónoma) deben ser compatibles con la versión de Qt de la aplicación que los carga (generalmente Qt Creator), lo que a menudo es una versión diferente de las bibliotecas de Qt con las que desea compilar su aplicación. Por ejemplo, en Windows, Qt Creator generalmente se compila con un compilador MSVC, ¡incluso si está incluido en un paquete MinGW!

Para ayudar a Qt Designer/Creator a localizar el plugin de diseñador de Qwt, debe establecer la variable de entorno QT_PLUGIN_PATH, modificar qt.conf o instalar el plugin en una de las rutas predeterminadas de la aplicación.

La documentación de Qt explica todas las opciones en detalle:

  • https://doc.qt.io/qt-5/deployment-plugins.html
  • https://doc.qt.io/qtcreator/adding-plugins.html

Por ejemplo, en un sistema Linux, podría agregar las siguientes líneas a .bashrc:

QT_PLUGIN_PATH="${QWT_ROOT}/plugins:$QT_PLUGIN_PATH"
export QT_PLUGIN_PATH

Cuando el plugin no se compiló incluyendo la biblioteca Qwt (consulte QwtDesignerSelfContained en qwtconfig.pri), Qt Designer/Creator también necesita localizar las bibliotecas Qwt. En sistemas Unix, la ruta a la biblioteca instalada se compila en el plugin (consulte rpath, ldd), pero en Windows, Qt Creator necesita ser configurado ( ( Ejecutando una aplicación Qwt ) de la misma manera que para cualquier aplicación que use Qwt.

En caso de problemas, los diagnósticos de Qt Creator y Designer son muy limitados (generalmente ninguno), pero establecer la variable de entorno QT_DEBUG_PLUGINS puede ayudar. En Qt Creator es posible verificar qué plugins fueron

qwtinstall(3)

NAME

qwtinstall - instructions for installing and using Qwt

Download

Qwt is available on the qwt.sf.net website.

Installing Qwt

The Qwt library is installed using the standard Qt build process. The following commands should be executed in the Qwt root directory.

qmake 
make
make install

To install the documentation as well, run

make install_docs

The default installation prefix is /usr/local. To change this, modify the PREFIX variable in qwtconfig.pri.

make install DESTDIR=/path/to/your/prefix

Or set the environment variable QWT_ROOT when configuring the build.

qmake "PREFIX=/path/to/your/prefix"
make
make install

When installing the library files into a directory that is not searched by the dynamic linker at runtime ( e.g. not /usr/lib or /usr/local/lib ), the installation prefix must be added to the linker configuration.

On Unix systems this can be done by adding the path to /etc/ld.so.conf or by setting the LD_LIBRARY_PATH environment variable.

On Windows, the DLLs must be found in the PATH.

Qwt and the Qt tool chain

When Qwt is installed, the plugin for Qt Designer will be installed into the Qt plugins directory, which is usually found under plugins/designer in the Qt installation directory.

In addition, the plugin is registered within the Qt application. If the plugin is loaded successfully it is listed in the qwtdesigner.pro file. For certain problems it also lists those that were recognized but failed ( Tools > Form Editor > About Qt Designer Plugins ).

Online Help

The Qwt class documentation can be loaded into the Qt Creator:

  • open the settings dialog from the Tools->Options menu
  • raise the tab 'Help->Documentation'.
  • press the Add button and select qwt-6.2.0.qch.

Now the context sensitive help ( F1 ) works for Qwt classes.

For browsing the documentation in the Qt Assistant:

  • open the settings dialog from the Edit->Preferences menu
  • raise the tab Documentation.
  • press the Add button and select qwt-6.2.0.qch.

Building a Qwt application

All flags and settings that are necessary to compile and link an application using Qwt can be found in the file ${QWT_ROOT}/features/qwt.prf.

When using qmake it can included from the application project file in 2 different ways:

•
Adding Qwt as qmake feature


When using the qmake feature mechanism you can bind a special version of qmake to a special installation of Qwt without having to add this dependency to the application project. How to add Qwt as feature is documented in the qmake docs.

After adding Qwt as a feature f.e on Linux as a persistent property ....

qmake -set QMAKEFEATURES ${QWT_ROOT}/features


.. the following line can be added to the application project file:

CONFIG += qwt
•
Including qwt.prf in the application project file


Instead of using qwt.prf as qmake feature it can be included from the application project file:

include ( ${QWT_ROOT}/features/qwt.prf )


The advantage of using a direct include is, that all settings of qwt.prf are known to the application project file ( qmake features are included after the application project file has been parsed ) and it can be implemented depending on - f.e. settings made in qwtconfig.pri.

On Unix platforms it is possible to link a runtime path into the executable, so that the location of the Qwt libraries can be found without having to configure a runtime environment:

  • QMAKE_LFLAGS_RPATH
  • QMAKE_RPATH
  • QMAKE_RPATHDIR

Running a Qwt application

When using Qwt as shared library ( DLL ) the dynamic linker has to find it according to the rules of the operating system.

Windows

The only reasonable way to configure the runtime environment - without having to copy the Qwt libraries around - is to modify the PATH variable. F.e. this could be done by adding the following line to some batch file:

set PATH=%PATH%;${QWT_ROOT}

GNU/Linux

Read the documentation about:

  • ldconfig
  • /etc/ld.so.conf
  • LD_LIBRARY_PATH

Using the ldd command a configuration can be tested.
