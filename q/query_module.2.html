query_module(2) Manual de llamadas al sistema query_module(2)

NOMBRE

query_module - consultar el kernel para obtener varios bits relacionados con módulos

SINOPSIS

#include <linux/module.h>
[[deprecated]] int query_module(size_t bufsize;
                                const char *name, int which,
                                void buf[bufsize], size_t bufsize,
                                size_t *ret);

DESCRIPCIÓN

Nota: Esta llamada al sistema solo está presente antes de Linux 2.6.

query_module() solicita información del kernel sobre módulos cargables. La información devuelta se coloca en el búfer apuntado por buf. El llamador debe especificar el tamaño de buf en bufsize. La naturaleza y el formato precisos de la información devuelta dependen de la operación especificada por which. Algunas operaciones requieren name para identificar un módulo cargado actualmente, otras permiten que name sea NULL, indicando el propio kernel.

Los siguientes valores se pueden especificar para which:

0
Devuelve éxito, si el kernel soporta query_module(). Se utiliza para sondear la disponibilidad de la llamada al sistema.
QM_MODULES
Devuelve los nombres de todos los módulos cargados. El búfer devuelto consta de una secuencia de cadenas terminadas en nulo; ret se establece en el número de módulos.
QM_DEPS
Devuelve los nombres de todos los módulos utilizados por el módulo indicado. El búfer devuelto consta de una secuencia de cadenas terminadas en nulo; ret se establece en el número de módulos.
QM_REFS
Devuelve los nombres de todos los módulos que utilizan el módulo indicado. Esta es la inversa de QM_DEPS. El búfer devuelto consta de una secuencia de cadenas terminadas en nulo; ret se establece en el número de módulos.
QM_SYMBOLS
Devuelve los símbolos y valores exportados por el kernel o el módulo indicado. El búfer devuelto es una matriz de estructuras de la siguiente forma

struct module_symbol {
    unsigned long value;
    unsigned long name;
};

seguido de cadenas terminadas en nulo. El valor de name es el desplazamiento de caracteres de la cadena en relación con el inicio de buf; ret se establece en el número de símbolos.
QM_INFO
Devuelve información diversa sobre el módulo indicado. El formato del búfer de salida es:

struct module_info {
    unsigned long address;
    unsigned long size;
    unsigned long flags;
};

donde address es la dirección del kernel en la que reside el módulo, size es el tamaño del módulo en bytes y flags es una máscara de MOD_RUNNING, MOD_AUTOCLEAN y otros, que indica el estado actual del módulo (consulte el archivo de origen del kernel de Linux include/linux/module.h). ret se establece en el tamaño de la estructura module_info.

VALOR DEVUELTO

En caso de éxito, se devuelve cero. En caso de error, se devuelve -1 y errno se establece para indicar el error.

ERRORES

EFAULT
Al menos uno de name, buf o ret estaba fuera del espacio de direcciones accesible del programa.
EINVAL
which inválido; o name es NULL (indicando "el kernel"), pero esto no está permitido con el valor especificado de which.
ENOENT
No existe ningún módulo con ese name.
ENOSPC
El tamaño del búfer proporcionado era demasiado pequeño. ret se establece en el tamaño mínimo necesario.
ENOSYS
query_module() no es compatible en esta versión del kernel (por ejemplo, Linux 2.6 o posterior).

ESTÁNDARES

Linux.

VERSIÓNES

Eliminado en Linux 2.6.

Parte de la información que antes estaba disponible a través de query_module() se puede obtener de /proc/modules, /proc/kallsyms y los archivos del directorio /sys/module.

La llamada al sistema query_module() no es compatible con glibc. No se proporciona ninguna declaración en las cabeceras de glibc, pero, debido a una peculiaridad histórica, glibc sí exporta una ABI para esta llamada al sistema. Por lo tanto, para utilizar esta llamada al sistema, es suficiente declarar manualmente la interfaz en su código; alternativamente, puede invocar la llamada al sistema usando syscall(2).

VER TAMBIÉN
