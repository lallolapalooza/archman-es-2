NOMBRE

qemu-nbd - Servidor de Dispositivos de Bloque de Red QEMU

SINOPSIS

qemu-nbd [OPCION]... archivo

qemu-nbd -L [OPCION]...

qemu-nbd -d dev

DESCRIPCIÓN

Exporta una imagen de disco QEMU utilizando el protocolo NBD.

Otros usos:

  • Vincula un dispositivo de bloque /dev/nbdX a un servidor QEMU (en Linux).
  • Como cliente para consultar las exportaciones de un servidor NBD remoto.

OPCIONES

archivo es el nombre de un archivo de imagen de disco, o un conjunto de opciones de controlador de bloque si se especifica --image-opts.

dev es un dispositivo NBD.

--object tipo,id=ID,...
Define una nueva instancia de la clase de objeto tipo identificada por ID. Consulte la página del manual de qemu(1) para obtener detalles completos de las propiedades admitidas. Los tipos de objeto comunes que tienen sentido definir son el objeto secret, que se utiliza para suministrar contraseñas y/o claves de cifrado, y el objeto tls-creds, que se utiliza para suministrar credenciales TLS para el servidor o cliente qemu-nbd.
-p, --port=PUERTO
Puerto TCP en el que escuchar como servidor, o al que conectarse como cliente (por defecto 10809).
-o, --offset=DESPLAZAMIENTO
El desplazamiento dentro de la imagen.
-b, --bind=IFACE
La interfaz en la que enlazarse como servidor, o a la que conectarse como cliente (por defecto 0.0.0.0).
-k, --socket=RUTA
Utiliza un socket Unix con la ruta RUTA.
--image-opts
Trata archivo como un conjunto de opciones de imagen, en lugar de un archivo simple. Si se especifica esta bandera, la bandera -f no debe utilizarse, sino que se debe establecer la opción format=.
-f, --format=FMT
Fuerza el uso del controlador de bloque para el formato FMT en lugar de la autodetección.
-r, --read-only
Exporta el disco como solo lectura.
-A, --allocation-depth
Expone información de profundidad de asignación a través del contexto de metadatos qemu:allocation-depth accesible mediante NBD_OPT_SET_META_CONTEXT.
-B, --bitmap=NOMBRE
Si archivo tiene un bitmap persistente qcow2 NOMBRE, expone ese bitmap a través del contexto de metadatos qemu:dirty-bitmap:NOMBRE accesible mediante NBD_OPT_SET_META_CONTEXT.
-s, --snapshot
Utiliza archivo como una instantánea externa, crea un archivo temporal con backing_file=archivo, redirige la escritura al archivo temporal.
-l, --load-snapshot=SNAPSHOT_PARAM
Carga una instantánea interna dentro de archivo y la exporta como un dispositivo de solo lectura. El formato SNAPSHOT_PARAM es snapshot.id=[ID],snapshot.name=[NOMBRE] o [ID_O_NOMBRE]
--cache=CACHE
El modo de caché que se utilizará con el archivo. Los valores válidos son: none, writeback (el predeterminado), writethrough, directsync y unsafe. Consulte la documentación de la opción del emulador -drive cache=... para obtener más información.
-n, --nocache
Equivalente a --cache=none.
--aio=AIO
Establece el modo de E/S asíncrona entre threads (el predeterminado), native (solo Linux) y io_uring (Linux 5.1+).
--discard=DISCARD
Controla si las solicitudes de discard (también conocidas como trim o unmap) se ignoran o se pasan al sistema de archivos. DISCARD es uno de ignore (o off), unmap (o on). El valor predeterminado es ignore.
--detect-zeroes=DETECT_ZEROES
Controla la conversión automática de escrituras de cero simples por parte del SO a comandos optimizados de escritura de cero específicos del controlador. DETECT_ZEROES es uno de off, on, o unmap. unmap convierte una escritura de cero en una operación de desmapeo y solo se puede utilizar si DISCARD está establecido en unmap. El valor predeterminado es off.
-c, --connect=DEV
Conecta archivo al dispositivo NBD DEV (solo Linux).
-d, --disconnect
Desconecta el dispositivo DEV (solo Linux).
-e, --shared=NUM
Permite que hasta NUM clientes compartan el dispositivo (por defecto 1), 0 para ilimitado.
-t, --persistent
No salir tras la última conexión.
-x, --export-name=NOMBRE
Establece el nombre de exportación del volumen NBD (por defecto una cadena de longitud cero).
-D, --description=DESCRIPCIÓN
Establece la descripción de la exportación del volumen NBD, como una cadena legible por humanos.
--handshake-limit=N
Establece el tiempo de espera para que un cliente complete con éxito su negociación a N segundos (por defecto 10), o 0 para sin límite.
-L, --list
Conéctate como cliente y lista todos los detalles sobre las exportaciones expuestas por un servidor NBD remoto. Esto habilita el modo de lista y es incompatible con opciones que cambian el comportamiento relacionado con una exportación específica (como --export-name, --offset, ...).
--tls-creds=ID
Habilita el cifrado TLS obligatorio para el servidor estableciendo el ID del objeto de credenciales TLS creado previamente con la opción --object; o proporciona las credenciales necesarias para conectarse como cliente en modo de lista.
--tls-hostname=nombrehost
Al validar un certificado x509 recibido a través de una conexión TLS, se comprobará el nombre del host utilizado por el cliente NBD para conectarse con la información del certificado proporcionado por el servidor. A veces, puede ser necesario anular el nombre del host utilizado para realizar esta comprobación. Por ejemplo, si el cliente NBD está utilizando un túnel desde localhost para conectarse al servidor remoto, se debe usar la opción --tls-hostname para establecer el nombre de host oficialmente esperado del servidor NBD remoto. Esto también se puede utilizar si se accede a NBD a través de un socket UNIX donde no hay un nombre de host inherente disponible. Esto solo está permitido cuando se actúa como cliente NBD con la opción --list.

NOMBRE

qemu-nbd - QEMU Network Block Device server

SINOPSIS

qemu-nbd [Options] Image

qemu-nbd [Options] -d Image

qemu-nbd [Options] -c Image

qemu-nbd [Options] -L host

DESCRIPCIÓN

qemu-nbd es un servidor de dispositivo de bloques de red para QEMU que permite que un cliente NBD se conecte a una imagen de disco. El servidor puede ser iniciado en un host o de forma remota a través de una red. El servidor puede exponer un archivo de imagen de disco como un dispositivo de bloque para que los clientes remotos puedan acceder a él.

Las siguientes opciones están disponibles:

OPCIONES

-f fmt, --format=fmt
Formato de la imagen de disco. Los formatos soportados son los soportados por qemu-img(1). El formato por defecto es qcow2.
-c host, --connect=host
Conecta el servidor NBD al host especificado. El host puede ser un nombre de dispositivo de bloque (por ejemplo, /dev/nbd0) o un nombre de host y puerto (por ejemplo, 127.0.0.1:10809). Si se especifica un nombre de dispositivo de bloque, el servidor NBD se conectará a ese dispositivo y el cliente NBD estará disponible como /dev/nbd0 (o el siguiente dispositivo NBD libre).
-d, --disconnect
Desconecta el servidor NBD del host especificado.
-L, --list
Lista los servidores NBD disponibles en el host especificado.
-p port, --port=port
Especifica el puerto en el que el servidor NBD escuchará las conexiones entrantes. El valor por defecto es 10809.
-x export, --export=export
Especifica el nombre de exportación para la imagen de disco. Si no se especifica, el nombre de exportación será una cadena vacía.
-U, --unixsocket
Escucha las conexiones entrantes en un socket Unix en lugar de un puerto TCP. El nombre del socket se especifica con la opción --socket.
--socket=path
Especifica la ruta del socket Unix en el que el servidor NBD escuchará las conexiones entrantes. Esta opción solo es válida si se utiliza la opción -U.
-r, --read-only
Abre la imagen de disco en modo de solo lectura.
-s, --shared
Permite que varios clientes se conecten a la misma imagen de disco. El argumento opcional especifica el número máximo de clientes permitidos. El valor por defecto es 1.
-P, --persistent
Mantiene el servidor NBD en ejecución incluso después de que el último cliente se desconecte. El servidor se detendrá solo cuando se reciba una señal SIGTERM o SIGINT.
--fork
Desvincula el proceso del servidor y sale del padre una vez que el servidor esté en funcionamiento.
--pid-file=PATH
Almacena el ID del proceso del servidor en el archivo dado.
--tls-authz=ID
Especifica el ID de un objeto qauthz creado previamente con la opción --object. Esto se utilizará para autorizar a los usuarios que se conectan contra su nombre distinguido x509.
-v, --verbose
Muestra información de depuración adicional. Esta opción también mantiene el flujo original de STDERR abierto si el proceso qemu-nbd se desvincula debido a otras opciones como --fork o -c.
-h, --help
Muestra esta ayuda y sale.
-V, --version
Muestra la información de la versión y sale.
-T, --trace [[enable=]PATTERN][,events=FILE][,file=FILE]
Especifica opciones de trazado.

[enable=]PATTERN

Habilita inmediatamente los eventos que coincidan con PATTERN (ya sea el nombre del evento o un patrón glob). Esta opción solo está disponible si QEMU se ha compilado con el backend de trazado simple, log o ftrace. Para especificar varios eventos o patrones, especifique la opción -trace varias veces.

Use -trace help para imprimir una lista de nombres de puntos de trazado.

events=FILE

Habilita inmediatamente los eventos listados en FILE. El archivo debe contener un nombre de evento (como se indica en el archivo trace-events-all) por línea; también se aceptan patrones glob. Esta opción solo está disponible si QEMU se ha compilado con el backend de trazado simple, log o ftrace.

file=FILE

Registra las trazas de salida en FILE. Esta opción solo está disponible si QEMU se ha compilado con el backend de trazado simple.

EJEMPLOS

Inicia un servidor que escucha en el puerto 10809 y expone solo el contenido visible para el invitado de un archivo qcow2, sin cifrado TLS y con el nombre de exportación predeterminado (una cadena vacía). El comando es de un solo uso y se bloqueará hasta que la primera desconexión exitosa del cliente:

qemu-nbd -f qcow2 file.qcow2

Inicia un servidor de ejecución prolongada escuchando con cifrado en el puerto 10810 y permite que los clientes con un certificado X.509 específico se conecten a un subconjunto de 1 megabyte de un archivo raw, utilizando el nombre de exportación 'subset':

qemu-nbd \
  --object tls-creds-x509,id=tls0,endpoint=server,dir=/path/to/qemutls \
  --object 'authz-simple,id=auth0,identity=CN=laptop.example.com,,\
            O=Example Org,,L=London,,ST=London,,C=GB' \
  --tls-creds tls0 --tls-authz auth0 \
  -t -x subset -p 10810 \
  --image-opts driver=raw,offset=1M,size=1M,file.driver=file,file.filename=file.raw

Sirve una copia de solo lectura de una imagen de invitado a través de un socket Unix con hasta 5 lectores simultáneos, con un proceso persistente desvinculado como demonio:

qemu-nbd --fork --persistent --shared=5 --socket=/path/to/sock \
  --read-only --format=qcow2 file.qcow2

Expone el contenido visible para el invitado de un archivo qcow2 a través de un dispositivo de bloque /dev/nbd0 (y posiblemente creando /dev/nbd0p1 y similares para las particiones encontradas dentro), luego desconecta el dispositivo cuando termine. El acceso para vincular qemu-nbd a un dispositivo /dev/nbd generalmente requiere privilegios de root y también puede requerir la ejecución de modprobe nbd para habilitar el módulo cliente NBD del kernel. PRECAUCIÓN: No utilice este método para montar sistemas de archivos de una imagen de invitado no confiable: un invitado malicioso puede haber preparado la imagen para intentar activar errores del kernel al explorar particiones o al montar sistemas de archivos.

qemu-nbd -c /dev/nbd0 -f qcow2 file.qcow2
qemu-nbd -d /dev/nbd0

Consulta a un servidor remoto para ver detalles sobre qué exportación(es) está sirviendo en el puerto 10809, y autenticándose a través de PSK:

qemu-nbd \
  --object tls-creds-psk,id=tls0,dir=/tmp/keys,username=eblake,endpoint=client \
  --tls-creds tls0 -L -b remote.example.com
