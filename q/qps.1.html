QPS(1) Manual de Comandos Generales QPS(1)

NOMBRE

qps - Gestor visual de procesos

SINOPSIS

qps [ opciones ]

DESCRIPCIÓN

qps es un monitor que muestra el estado de los procesos actualmente existentes, de forma similar a top(1) o ps(1). La interfaz de usuario utiliza el toolkit Qt, y la mayoría de las operaciones deberían ser bastante intuitivas.

La lista de procesos se ordena por el campo resaltado. Haz clic en otro título para cambiar; haz clic de nuevo para invertir el orden de ordenación. Reorganiza las columnas arrastrando los títulos.

Hacer clic izquierdo en un proceso lo selecciona o deselecciona. Shift-clic para seleccionar varios procesos. Las PID de los procesos seleccionados se pueden pegar en otras aplicaciones (esta opción se puede deshabilitar).

El botón derecho del ratón muestra un menú contextual, que duplica algunas funciones del menú principal para mayor comodidad. Funciona tanto en procesos como en encabezados de columna.

Control-clic en la tabla de procesos selecciona todos los procesos que tienen el mismo valor mostrado en la columna en la que se hizo clic. Por ejemplo, para seleccionar todos los procesos propiedad de "joshua", mantén presionada la tecla Control mientras haces clic en "joshua". Shift y Control juntos producen el resultado esperado.

En el modo Árbol, las relaciones padre-hijo entre los procesos se muestran de manera más obvia. Haz clic en los triángulos para mostrar u ocultar un subárbol completo. La ordenación solo afecta a los hermanos; la estructura del árbol impone el orden global.

Para cambiar la prioridad de tiempo compartido de los procesos seleccionados, escribe la nueva prioridad en el diálogo Renice.... El nuevo valor de nice debe estar en el rango de -20 a 20; 0 es el valor predeterminado. Un número mayor significa que el proceso recibe menos tiempo de CPU. Solo el superusuario puede disminuir el valor de nice.

El diálogo Cambiar Programación... permite al superusuario cambiar la política de programación de los procesos seleccionados (utilizando el control de programación Posix.1b). Los procesos normales se establecen en SCHED_OTHER y tienen una prioridad estática de 0; los procesos de tiempo real (suave) tienen la política SCHED_FIFO o SCHED_RR y una prioridad estática en el rango de 1 a 99. (Ver sched_setscheduler(2).) Solaris tiene políticas de programación adicionales, pero por ahora qps no permite configurarlas.

Por defecto, la visualización de procesos se actualiza cada 5 segundos. Para cambiarlo, escribe el nuevo período de actualización en el diálogo Período de Actualización.... Se pueden usar las unidades min, s y ms (si no se especifica ninguna, se asumen segundos). Puedes forzar una actualización presionando la barra espaciadora o haciendo clic en el botón Actualizar. qps consumirá mucho tiempo de CPU si el período de actualización es corto o cero. Sin embargo, si se minimiza, qps consumirá muy poca CPU.

El campo USER muestra el ID de usuario real. Si el ID de usuario efectivo de un proceso es diferente de su ID de usuario real, se añade un signo más (+) al nombre de usuario; si es el superusuario, se añade un asterisco (*).

Las pantallas de carga, CPU, memoria e intercambio en la barra de estado se pueden alternar entre representaciones gráficas y de texto haciendo clic en ellas, o mediante la configuración en el diálogo Preferencias.... Los números de carga mostrados son el número de trabajos en la cola de ejecución promediados durante 1, 5 y 15 minutos.

La barra de intercambio se pondrá roja si el espacio de intercambio libre cae por debajo de un cierto valor, que se puede cambiar en el diálogo Preferencias.... El número se puede introducir en K, M (megabytes) o % (porcentaje del espacio de intercambio total). El valor predeterminado es 10%.

En máquinas SMP (multiprocesador) con Solaris 2.6 o Linux 2.1.x o posterior, las estadísticas de CPU se mostrarán para cada procesador en modo vertical, y el promedio de todas las CPU en modo horizontal.

Para mostrar el campo WCHAN como símbolos, se necesita el archivo de símbolos del kernel System.map. qps lo buscará en las siguientes ubicaciones:

	/boot/System.map-
RELEASE
	/boot/System.map
	/lib/modules/
RELEASE
/System.map
	/usr/src/linux-
RELEASE
/System.map
	/usr/src/linux/System.map
	/usr/local/src/linux-
RELEASE
/System.map
	/usr/local/src/linux/System.map

donde RELEASE es el número de versión del kernel, por ejemplo "2.0.29". Si el archivo System.map no se encuentra o no se puede leer, se mostrarán direcciones hexadecimales en su lugar. Los prefijos "sys_" y "do_" se eliminan de los símbolos antes de mostrarlos. En Solaris, los nombres simbólicos no son compatibles actualmente y siempre se mostrarán direcciones hexadecimales.

El elemento de menú Ver Detalles abre una ventana que muestra diferentes aspectos de los procesos seleccionados. Hacer doble clic en un proceso tiene el mismo efecto. Toda la información solo está disponible para el propietario del proceso (y para el superusuario).

La tabla Sockets (solo Linux) muestra los sockets TCP y UDP utilizados actualmente. Si Búsqueda de Nombres de Host está marcada en el diálogo Preferencias, se realizará una búsqueda de nombres de host para cada dirección IP. Esto se hace mediante un proceso en segundo plano pero puede llevar tiempo en casos difíciles (pero una vez buscadas, las direcciones se almacenan en caché).

La tabla Mapas de Memoria muestra los mapeos de memoria del proceso. En Linux 2.0.x y Solaris, no se proporcionan los nombres de archivo. Los mapeos anónimos (memoria asignada no enlazada a un archivo o dispositivo) se marcan como (anónimo).

La tabla Archivos muestra los archivos abiertos del proceso. En Linux 2.0.x, los archivos se dan en el formato [AABB]:inodo, donde AA y BB son los números mayor/menor del dispositivo en hexadecimal.

La tabla Entorno muestra las variables de entorno del proceso. Ten en cuenta que este es el entorno con el que se inició el proceso, no necesariamente incorpora cambios posteriores. Algunos procesos que modifican su línea de comandos, en particular sendmail(8) y ftpd(8), pueden usar el espacio de entorno para esto, mostrando información sin sentido en esta tabla. Hacer clic en los encabezados de campo cambia el orden de clasificación como de costumbre. (En Solaris, solo se muestran los primeros 8 KB del entorno. Se corregirá si resulta ser una limitación).

Buscar Padre y Buscar Hijos seleccionarán el padre/hijos de los procesos seleccionados, y centrarán la tabla en el primero de ellos. Buscar Descendientes seleccionará el árbol de todos los hijos de los procesos seleccionados.

Si Incluir Tiempos de Hijos está seleccionado en el menú Opciones, el campo TIEMPO mostrará la suma de los tiempos de CPU utilizados por el proceso y todos sus hijos.

Puedes especificar comandos que se ejecutarán en los procesos seleccionados abriendo el diálogo Editar Comandos.... La "Descripción" de cada comando es lo que aparece en el menú; la "Línea de Comandos" es un comando de shell (ejecutado con /bin/sh). Antes de que el comando se pase al shell, se realizan las siguientes sustituciones:

%p
con el PID (ID de Proceso) del proceso seleccionado
%c
con el nombre corto del comando del proceso
%C
con la línea de comandos completa del proceso
%u
con el nombre del propietario (real) del proceso
%%
con un '%' literal.

Cualquier otra combinación de % + letra se elimina. La línea de comandos se ejecutará una vez por cada proceso seleccionado (en orden no especificado).

NAME

qps — process information viewer

SYNOPSIS

qps

DESCRIPTION

The qps utility provides an interactive process information display. It is intended to be a faster and less resource intensive alternative to top. It displays a list of processes sorted by CPU usage, along with system summary information.

The display is updated periodically. New processes are added to the list and terminated processes are removed. The list is sorted by CPU usage in descending order.

Summary information is displayed at the top of the screen, including:

  • CPU usage: displays the percentage of CPU time spent in user mode, system mode, nice mode, idle, etc.
  • Memory usage: displays the total amount of RAM, used memory, free memory, buffer usage, and cache usage.
  • Swap usage: displays the total amount of swap space, used swap space, and free swap space.

The process list includes the following fields:

  • PID: Process ID.
  • USER: User name of the process owner.
  • PRI: Priority of the process.
  • NI: Nice value of the process.
  • VIRT: Virtual memory size used by the process.
  • RES: Resident memory size used by the process.
  • SHR: Shared memory size used by the process.
  • %CPU: Percentage of CPU time used by the process since the last update.
  • %MEM: Percentage of physical memory used by the process.
  • WCHAN: Wait channel, the kernel function the process is sleeping in. This field is only available on Linux.
  • COMMAND: The command name and arguments of the process.

KEYBOARD ACCELERATORS

The following keys can be pressed to interact with qps:

^L
Redraw the screen.
k, j
Move the selection up or down.
g
Go to the top or bottom of the list.
n
Invert the sort order.
1
Switch between single CPU and all CPUs in the summary.
h
Display this help screen.
q
Quit qps.

OPTIONS

-version
prints the version of qps and the Qt library, and exits.
-help
prints a summary of command-line options and exits.

ENVIRONMENT

QPS_COLORS contains color specifications of comma-separated name:value pairs, where name is one of the following:

cpu-user, cpu-nice (Linux), cpu-sys, cpu-wait (Solaris), cpu-idle, mem-used, mem-buff, mem-cache, mem-free, swap-used, swap-free, swap-warn, load-bg, load-fg, load-lines, selection-bg, selection-fg

value is an X11 color name, either a symbolic name like "salmon" or an RGB color like #c5b769.

BUGS

qps is too big and too slow.

The %CPU number isn’t accurate at very short update intervals due to timer granularity.

The %WCPU field isn’t recalculated when qps is iconified, so it might take a while to readjust when the window is deiconified again.

The WCHAN field doesn’t show a function name if a process sleeps in a location outside those in System.map (for instance, in a kernel module), but a hex address instead. The function name can then be found in /proc/ksyms but has to be found by hand right now.

The CPU indicator in the status bar will display nonsense in SMP systems running Linux 2.0.x due to a kernel bug.

Adding/removing CPUs at runtime will probably confuse qps.
