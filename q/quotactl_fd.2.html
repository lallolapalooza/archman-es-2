quotactl(2) Manual de llamadas al sistema quotactl(2)

NOMBRE

quotactl, quotactl_fd — manipular cuotas de disco

BIBLIOTECA

Biblioteca C estándar (libc, -lc)

SINOPSIS

#include <sys/quota.h>
#include <xfs/xqm.h> /* Definición de constantes Q_X* y XFS_QUOTA_*
                        (o <linux/dqblk_xfs.h>; ver NOTAS) */
int quotactl(int op, const char *_Nullable special, int id,
             caddr_t addr);
#include <sys/syscall.h>    /* Definición de constantes SYS_* */
#include <unistd.h>
int syscall(SYS_quotactl_fd, int fd, int op, int id, caddr_t addr);

Nota: glibc no proporciona un envoltorio para quotactl_fd(), lo que hace necesario el uso de syscall(2).

DESCRIPCIÓN

El sistema de cuotas se puede usar para establecer límites por usuario, por grupo y por proyecto sobre la cantidad de espacio en disco utilizado en un sistema de archivos. Para cada usuario y/o grupo, se pueden establecer un límite blando y un límite duro para cada sistema de archivos. El límite duro no se puede superar. El límite blando se puede superar, pero se producirán advertencias. Además, el usuario no puede superar el límite blando durante más del período de gracia (una semana por defecto) a la vez; después de esto, el límite blando cuenta como un límite duro.

Las llamadas quotactl() y quotactl_fd() manipulan las cuotas de disco. La diferencia entre estas funciones es la forma en que se especifica el sistema de archivos que se está manipulando; ver la descripción de los argumentos a continuación. Ver NOTAS para saber por qué una variante podría ser preferible a la otra.

El argumento op indica una operación a aplicar al ID de usuario o grupo especificado en id. Para inicializar el argumento op, use la macro QCMD(subop, type). El valor type es ya sea USRQUOTA, para cuotas de usuario, GRPQUOTA, para cuotas de grupo, o (desde Linux 4.1) PRJQUOTA, para cuotas de proyecto. El valor subop se describe a continuación.

Para quotactl(), el argumento special es un puntero a una cadena terminada en nulo que contiene la ruta del dispositivo especial de bloques (montado) del sistema de archivos que se está manipulando.

Para quotactl_fd(), el argumento fd es un descriptor de archivo (que puede abrirse con la bandera O_PATH) que hace referencia a un archivo o directorio en el sistema de archivos que se está manipulando.

El argumento addr es la dirección de una estructura de datos opcional, específica de la operación, que se copia dentro o fuera del sistema. La interpretación de addr se da con cada operación a continuación.

El valor subop es una de las siguientes operaciones:

Q_QUOTAON
Activar cuotas para un sistema de archivos. El argumento id es el número de identificación del formato de cuota a utilizar. Actualmente, hay tres formatos de cuota admitidos:
QFMT_VFS_OLD
El formato de cuota original.
QFMT_VFS_V0
El formato de cuota estándar VFS v0, que puede manejar UIDs y GIDs de 32 bits y límites de cuota de hasta 2^42 bytes y 2^32 inodos.
QFMT_VFS_V1
Un formato de cuota que puede manejar UIDs y GIDs de 32 bits y límites de cuota de 2^63 - 1 bytes y 2^63 - 1 inodos.
El argumento addr apunta a la ruta de un archivo que contiene las cuotas del sistema de archivos. El archivo de cuota debe existir; normalmente se crea con el programa quotacheck(8)
La información de cuota también se puede almacenar en inodos de sistema ocultos para ext4, XFS y otros sistemas de archivos si el sistema de archivos está configurado para ello. En este caso, no hay archivos de cuota visibles y no es necesario usar quotacheck(8). El sistema de archivos mantiene la información de cuota siempre consistente y la operación Q_QUOTAON solo sirve para habilitar la aplicación de los límites de cuota. La presencia de inodos de sistema ocultos con información de cuota se indica mediante la bandera DQF_SYS_FILE en el campo dqi_flags devuelto por la operación Q_GETINFO.
La variante quotactl_fd() de esta llamada al sistema ignora los argumentos addr e id, por lo que la operación Q_QUOTAON de quotactl_fd() solo es adecuada para trabajar con inodos de sistema ocultos.
Esta operación requiere privilegios (CAP_SYS_ADMIN).
Q_QUOTAOFF
Desactivar cuotas para un sistema de archivos. Los argumentos addr e id se ignoran. Esta operación requiere privilegios (CAP_SYS_ADMIN).
Q_GETQUOTA
Obtener límites de cuota de disco y uso actual para el usuario o grupo id. El argumento addr es un puntero a una estructura dqblk definida en <sys/quota.h> de la siguiente manera:

/* uint64_t es un entero sin signo de 64 bits;
   uint32_t es un entero sin signo de 32 bits */
struct dqblk {      /* Definición desde Linux 2.4.22 */
    uint64_t dqb_bhardlimit;  /* Límite absoluto de bloques
                                 de cuota de disco asignados */
    uint64_t dqb_bsoftlimit;  /* Límite preferido de bloques
                                 de cuota de disco */
    uint64_t dqb_curspace;    /* Espacio ocupado actual
                                 (en bytes) */
    uint64_t dqb_ihardlimit;  /* Número máximo de inodos
                                 asignados */
    uint64_t dqb_isoftlimit;  /* Límite preferido de inodos */
    uint64_t dqb_curinodes;   /* Número actual de inodos
                                 asignados */
    uint64_t dqb_btime;       /* Límite de tiempo para uso
                                 excesivo de disco */
    uint64_t dqb_itime;       /* Límite de tiempo para uso
                                 excesivo de archivos */
    uint32_t dqb_valid;       /* Máscara de bits de constantes
                                 QIF_* */
};
/* Banderas en dqb_valid que indican qué campos de la
   estructura dqblk son válidos.  */
#define QIF_BLIMITS   1
#define QIF_SPACE     2
#define QIF_ILIMITS   4
#define QIF_INODES    8
#define QIF_BTIME     16
#define QIF_ITIME     32
#define QIF_LIMITS    (QIF_BLIMITS | QIF_ILIMITS)
#define QIF_USAGE     (QIF_SPACE | QIF_INODES)
#define QIF_TIMES     (QIF_BTIME | QIF_ITIME)
#define QIF_ALL       (QIF_LIMITS | QIF_USAGE | QIF_TIMES)

El campo dqb_valid es una máscara de bits que se establece para indicar las entradas en la estructura dqblk que son válidas. Actualmente, el kernel rellena todas las entradas de la estructura dqblk y las marca como válidas en el campo dqb_valid. Los usuarios sin privilegios solo pueden obtener sus propias cuotas; un usuario con privilegios (CAP_SYS_ADMIN) puede obtener las cuotas de cualquier usuario.
Q_GETNEXTQUOTA (desde Linux 4.6)
Esta operación es la misma que Q_GETQUOTA, pero devuelve información de cuota para el próximo ID mayor o igual a id que tenga una cuota establecida.
El argumento addr es un puntero a una estructura nextdqblk cuyos campos son los mismos que los de dqblk, excepto por la adición de un campo dqb_id que se utiliza para devolver el ID para el que se devuelve la información de cuota:

struct nextdqblk {
    uint64_t dqb_bhardlimit;
    uint64_t dqb_bsoftlimit;
    uint64_t dqb_curspace;
    uint64_t dqb_ihardlimit;
    uint64_t dqb_isoftlimit;
    uint64_t dqb_curinodes;
    uint64_t dqb_btime;
    uint64_t dqb_itime;
    uint32_t dqb_valid;
    uint32_t dqb_id;
};

Q_SETQUOTA
Establecer información de cuota para el usuario o grupo id, usando la información proporcionada en la estructura dqblk apuntada por addr. El campo dqb_valid de la estructura dqblk indica qué entradas de la estructura han sido establecidas por el llamador. Esta operación reemplaza las operaciones Q_SETQLIM y Q_SETUSE de las interfaces de cuota anteriores. Esta operación requiere privilegios (CAP_SYS_ADMIN).

Q_SETINFO (desde Linux 2.4.22)
Establecer información sobre el archivo de cuotas. El argumento addr debe ser un puntero a una estructura dqinfo. El campo dqi_valid de la estructura dqinfo indica las entradas de la estructura que han sido establecidas por el llamador. Esta operación reemplaza las operaciones Q_SETGRACE y Q_SETFLAGS de las interfaces de cuotas anteriores. El argumento id se ignora. Esta operación requiere privilegios (CAP_SYS_ADMIN).
Q_GETFMT (desde Linux 2.4.22)
Obtener el formato de cuota utilizado en el sistema de archivos especificado. El argumento addr debe ser un puntero a un búfer de 4 bytes donde se almacenará el número de formato.
Q_SYNC
Actualizar la copia en disco de los usos de cuota para un sistema de archivos. Para quotactl(), si special es NULL, se sincronizan todos los sistemas de archivos con cuotas activas. (quotactl_fd() siempre sincroniza solo un sistema de archivos.) En ambos casos, los argumentos addr e id se ignoran.
Q_GETSTATS (soportado hasta Linux 2.4.21)
Obtener estadísticas y otra información genérica sobre el subsistema de cuotas. El argumento addr debe ser un puntero a una estructura dqstats en la que se almacenarán los datos. Esta estructura se define en <sys/quota.h>. Los argumentos special e id se ignoran.
Esta operación es obsoleta y fue eliminada en Linux 2.4.22. Los archivos en /proc/sys/fs/quota/ contienen la información en su lugar.

Para los sistemas de archivos XFS que utilizan XFS Quota Manager (XQM), las operaciones anteriores se omiten y se utilizan las siguientes operaciones:

Q_XQUOTAON
Activar las cuotas para un sistema de archivos XFS. XFS proporciona la capacidad de activar/desactivar la aplicación de límites de cuota con contabilidad de cuotas. Por lo tanto, XFS espera que addr sea un puntero a un unsigned int que contiene una combinación a nivel de bits de las siguientes banderas (definidas en <xfs/xqm.h>):

XFS_QUOTA_UDQ_ACCT  /* Contabilidad de cuotas de usuario */
XFS_QUOTA_UDQ_ENFD  /* Aplicación de límites de cuotas de usuario */
XFS_QUOTA_GDQ_ACCT  /* Contabilidad de cuotas de grupo */
XFS_QUOTA_GDQ_ENFD  /* Aplicación de límites de cuotas de grupo */
XFS_QUOTA_PDQ_ACCT  /* Contabilidad de cuotas de proyecto */
XFS_QUOTA_PDQ_ENFD  /* Aplicación de límites de cuotas de proyecto */

Esta operación requiere privilegios (CAP_SYS_ADMIN). El argumento id se ignora.
Q_XQUOTAOFF
Desactivar las cuotas para un sistema de archivos XFS. Al igual que con Q_QUOTAON, los sistemas de archivos XFS esperan un puntero a un unsigned int que especifica si la contabilidad de cuotas y/o la aplicación de límites deben desactivarse (utilizando las mismas banderas que para la operación Q_XQUOTAON). Esta operación requiere privilegios (CAP_SYS_ADMIN). El argumento id se ignora.
Q_XGETQUOTA
Obtener los límites de cuota de disco y el uso actual para el usuario id. El argumento addr es un puntero a una estructura fs_disk_quota, que se define en <xfs/xqm.h> de la siguiente manera:

/* Todas las unidades de bloques están en BBs (Bloques Básicos) de
   512 bytes.  */
#define FS_DQUOT_VERSION  1  /* fs_disk_quota.d_version */
#define XFS_USER_QUOTA    (1<<0)  /* Tipo de cuota de usuario */
#define XFS_PROJ_QUOTA    (1<<1)  /* Tipo de cuota de proyecto */
#define XFS_GROUP_QUOTA   (1<<2)  /* Tipo de cuota de grupo */
struct fs_disk_quota {
    int8_t   d_version;   /* Versión de esta estructura */
    int8_t   d_flags;     /* XFS_{USER,PROJ,GROUP}_QUOTA */
    uint16_t d_fieldmask; /* Especificador de campo */
    uint32_t d_id;        /* ID de usuario, proyecto o grupo */
    uint64_t d_blk_hardlimit; /* Límite absoluto de
                                 bloques de disco */
    uint64_t d_blk_softlimit; /* Límite preferido de
                                 bloques de disco */
    uint64_t d_ino_hardlimit; /* Número máximo de
                                 inodos asignados */
    uint64_t d_ino_softlimit; /* Límite preferido de inodos */
    uint64_t d_bcount;    /* Número de bloques de disco propiedad
                             del usuario */
    uint64_t d_icount;    /* Número de inodos propiedad
                             del usuario */
    int32_t  d_itimer;    /* Cero si está dentro de los límites de inodos */
                          /* Si no, rechazamos el servicio */
    int32_t  d_btimer;    /* Similar a lo anterior; para
                             bloques de disco */
    uint16_t d_iwarns;    /* Número de advertencias emitidas con
                             respecto al número de inodos */
    uint16_t d_bwarns;    /* Número de advertencias emitidas con
                             respecto a los bloques de disco */
    int32_t  d_padding2;  /* Relleno - para uso futuro */
    uint64_t d_rtb_hardlimit; /* Límite absoluto de bloques de
                                 disco en tiempo real (RT) */
    uint64_t d_rtb_softlimit; /* Límite preferido de bloques
                                 de disco RT */
    uint64_t d_rtbcount;  /* Número de bloques RT propiedad */
    int32_t  d_rtbtimer;  /* Similar a lo anterior; para
                             bloques de disco RT */
    uint16_t d_rtbwarns;  /* Número de advertencias emitidas con
                             respecto a los bloques de disco RT */
    int16_t  d_padding3;  /* Relleno - para uso futuro */
    char     d_padding4[8];   /* Más relleno */
};

Los usuarios sin privilegios solo pueden recuperar sus propias cuotas; un usuario con privilegios (CAP_SYS_ADMIN) puede recuperar las cuotas de cualquier usuario.
Q_XGETNEXTQUOTA (desde Linux 4.6)
Esta operación es la misma que Q_XGETQUOTA, pero devuelve (en la estructura fs_disk_quota apuntada por addr) información de cuota para el siguiente ID mayor o igual a id que tenga una cuota establecida. Tenga en cuenta que dado que fs_disk_quota ya tiene el campo q_id, no se necesita un tipo de estructura separado (a diferencia de las operaciones Q_GETQUOTA y Q_GETNEXTQUOTA)
Q_XSETQLIM
Establecer los límites de cuota de disco para el usuario id. El argumento addr es un puntero a una estructura fs_disk_quota. Esta operación requiere privilegios (CAP_SYS_ADMIN).
Q_XGETQSTAT
Devuelve información de cuota específica del sistema de archivos XFS en la estructura fs_quota_stat apuntada por addr. Esto es útil para averiguar cuánta espacio se utiliza para almacenar información de cuotas y también para obtener el estado de activación/desactivación de cuotas de un sistema de archivos XFS local dado. La estructura fs_quota_stat en sí está definida de la siguiente manera:

#define FS_QSTAT_VERSION 1  /* fs_quota_stat.qs_version */
struct fs_qfilestat {
    uint64_t qfs_ino;       /* Número de inodo */
    uint64_t qfs_nblks;     /* Número de BBs
                               bloques de 512 bytes */
    uint32_t qfs_nextents;  /* Número de extensiones */
};
struct fs_quota_stat {
    int8_t   qs_version; /* Número de versión para
                            cambios futuros */
    uint16_t qs_flags; /* XFS_QUOTA_{U,P,G}DQ_{ACCT,ENFD} */
    int8_t   qs_pad;   /* No utilizado */
    struct fs_qfilestat qs_uquota;  /* Información de almacenamiento de
                                       cuotas de usuario */
    struct fs_qfilestat qs_gquota;  /* Información de almacenamiento de
                                       cuotas de grupo */
    uint32_t qs_incoredqs;   /* Número de dquots en memoria principal */
    int32_t  qs_btimelimit;  /* Límite para el temporizador de bloques */
    int32_t  qs_itimelimit;  /* Límite para el temporizador de inodos */
    int32_t  qs_rtbtimelimit;/* Límite para el temporizador de
                                bloques RT */
    uint16_t qs_bwarnlimit;  /* Límite para el número de advertencias */
    uint16_t qs_iwarnlimit;  /* Límite para el número de advertencias */
};

El argumento id se ignora.
Q_XGETQSTATV
Devuelve información de cuota específica del sistema de archivos XFS en la estructura fs_quota_statv apuntada por addr. Esta versión de la operación utiliza una estructura con soporte de versionado adecuado, junto con un diseño apropiado (todos los campos están alineados naturalmente) y relleno para evitar un manejo especial de compatibilidad; también proporciona la capacidad de obtener estadísticas sobre el archivo de cuotas de proyecto. La estructura fs_quota_statv en sí está definida de la siguiente manera:

#define FS_QSTATV_VERSION1 1 /* fs_quota_statv.qs_version */
struct fs_qfilestatv {
    uint64_t qfs_ino;       /* Número de inodo */
    uint64_t qfs_nblks;     /* Número de BBs
                               bloques de 512 bytes */
    uint32_t qfs_nextents;  /* Número de extensiones */
    uint32_t qfs_pad;       /* Relleno para alineación de 8 bytes */
};
struct fs_quota_statv {
    int8_t   qs_version;    /* Versión para cambios futuros */
    uint8_t  qs_pad1;       /* Relleno para alineación de 16 bits */
    uint16_t qs_flags;      /* Banderas XFS_QUOTA_.* */
    uint32_t qs_incoredqs;  /* Número de dquots en memoria principal */
    struct fs_qfilestatv qs_uquota;  /* Información de cuota
                                        de usuario */
    struct fs_qfilestatv qs_gquota;  /* Información de cuota de grupo */
    struct fs_qfilestatv qs_pquota;  /* Información de cuota de proyecto */
    int32_t  qs_btimelimit;   /* Límite para el temporizador de bloques */
    int32_t  qs_itimelimit;   /* Límite para el temporizador de inodos */
    int32_t  qs_rtbtimelimit; /* Límite para el temporizador de bloques RT */
    uint16_t qs_bwarnlimit;   /* Límite de # de advertencias */
    uint16_t qs_iwarnlimit;   /* Límite de # de advertencias */
    uint64_t qs_pad2[8];      /* Para futuras ampliaciones */
};

El campo qs_version de la estructura debe rellenarse con la versión de la estructura soportada por el llamador (por ahora, solo se soporta FS_QSTAT_VERSION1). El kernel rellenará la estructura de acuerdo con la versión proporcionada. El argumento id es ignorado.
Q_XQUOTARM (defectuoso hasta Linux 3.16)
Liberar el espacio en disco ocupado por las cuotas de disco. El argumento addr debe ser un puntero a un valor de tipo unsigned int que contenga flags (los mismos que en el campo d_flags de la estructura fs_disk_quota) que identifiquen qué tipos de cuotas deben eliminarse. (Nótese que el tipo de cuota pasado en el argumento op es ignorado, pero debe seguir siendo válido para superar las comprobaciones preliminares del manejador de llamadas al sistema quotactl.)
Las cuotas deben haber sido previamente desactivadas. El argumento id es ignorado.
Q_XQUOTASYNC (desde Linux 2.6.15; no-op desde Linux 3.4)
Esta operación era un equivalente XFS de Q_SYNC, pero es un no-op desde Linux 3.4, ya que sync(1) escribe información de cuotas en disco ahora (además de los otros metadatos del sistema de archivos que escribe). Los argumentos special, id y addr son ignorados.

VALOR DE RETORNO

En caso de éxito, quotactl() devuelve 0; en caso de error, devuelve -1, y errno se establece para indicar el error.

ERRORES

EACCES
op es Q_QUOTAON, y el archivo de cuotas apuntado por addr existe, pero no es un archivo regular o no está en el sistema de archivos apuntado por special.
EBUSY
op es Q_QUOTAON, pero ya se había realizado otro Q_QUOTAON.
EFAULT
addr o special es inválido.
EINVAL
op o type es inválido.
EINVAL
op es Q_QUOTAON, pero el archivo de cuotas especificado está corrupto.
EINVAL (desde Linux 5.5)
op es Q_XQUOTARM, pero addr no apunta a tipos de cuota válidos.
ENOENT
El archivo especificado por special o addr no existe.
ENOSYS
El kernel no se ha compilado con la opción CONFIG_QUOTA.
ENOTBLK
special no es un dispositivo de bloques.
EPERM
Al llamante le faltaba el privilegio requerido (CAP_SYS_ADMIN) para la operación especificada.
ERANGE
op es Q_SETQUOTA, pero los límites especificados están fuera del rango permitido por el formato de cuota.
ESRCH
No se encontraron cuotas de disco para el usuario indicado. Las cuotas no se han activado para este sistema de archivos.
ESRCH
op es Q_QUOTAON, pero no se encontró el formato de cuota especificado.
ESRCH
op es Q_GETNEXTQUOTA o Q_XGETNEXTQUOTA, pero no hay un ID mayor o igual a id que tenga una cuota activa.

NOTAS

Cabecera XFS alternativa

En lugar de <xfs/xqm.h> se puede usar <linux/dqblk_xfs.h>, teniendo en cuenta que hay varias discrepancias en los nombres:

•
Los flags de habilitación de cuotas (de formato XFS_QUOTA_[UGP]DQ_{ACCT,ENFD}) se definen sin una "X" inicial, como FS_QUOTA_[UGP]DQ_{ACCT,ENFD}.
•
Lo mismo ocurre con los flags de tipo de cuota XFS_{USER,GROUP,PROJ}_QUOTA, que se definen como FS_{USER,GROUP,PROJ}_QUOTA.
•
El archivo de cabecera dqblk_xfs.h define sus propias constantes XQM_USRQUOTA, XQM_GRPQUOTA y XQM_PRJQUOTA para los tipos de cuota disponibles, pero sus valores son los mismos que para las constantes sin el prefijo XQM_.

quotactl() frente a quotactl_fd()

La variante original de esta llamada al sistema, quotactl(), requiere especificar el dispositivo de bloques que contiene el sistema de archivos sobre el que operar. Esto hace imposible su uso en casos en los que el sistema de archivos no tiene un dispositivo de bloques subyacente (por ejemplo, tmpfs). Incluso cuando el dispositivo de bloques existe, puede ser difícil de localizar (requiere escanear /proc/self/mounts e incluso algún análisis específico del sistema de archivos en el caso de, por ejemplo, bcachefs). quotactl_fd() en su lugar opera sobre el punto de montaje, lo que evita esta limitación y es más fácil de usar (ya que el sistema de archivos a manipular se especifica típicamente por su punto de montaje de todos modos).
